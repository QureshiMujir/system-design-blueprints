398 — Unicode Text Shaping

Goal: Implement, from scratch in Rust, a Unicode text-layout engine that turns a string plus a font into positioned glyphs — UAX #15 normalization (NFC/NFD/NFKC/NFKD, canonical ordering, Hangul, quick-check), UAX #29 grapheme/word segmentation and UAX #14 line-break opportunities, the UAX #9 bidirectional algorithm (embedding levels, isolates, reordering, mirroring), and OpenType shaping over parsed font tables (cmap, GSUB, GPOS, GDEF) with script-specific shapers (Latin, Arabic joining, one Indic reordering shaper, and a general fallback). Output is a glyph Buffer (glyph ids + clusters + positions) consumed by the TrueType rasterizer (project #385). It is the missing layout layer between Unicode text and glyph rasterization; it does not rasterize.

1. Goal

Turn an arbitrary Unicode string plus a font file into a positioned glyph Buffer suitable for immediate rasterization by project #385.

Engineering definition: a from-scratch Unicode text-layout engine that executes four sequential transformations—(1) UAX #15 normalization, (2) UAX #29/14 segmentation, (3) UAX #9 bidirectional resolution, (4) OpenType shaping—and emits a Buffer { Vec<GlyphInfo>, Vec<GlyphPosition> } whose glyph IDs and per-glyph advances/offsets are consumed unchanged by the TrueType rasterizer (#385). No rendering, no font loading policy, no layout box model.

Explicit Non-Goals

  • Glyph rasterization / hinting / rendering — entirely #385's domain; we hand off the Buffer.
  • Full paragraph / line-wrap UI — we emit line-break opportunities (LineBreaker) and directional runs; wrapping, justification, and the box model are the caller's responsibility.
  • Font subsetting / editing — read-only parsing of sfnt bytes; no glyph rewriting, no woff2 recompression.
  • CFF / Type 2 charstring interpretation — sfnt table directory + TrueType glyf assumed; CFF (CFF , CFF2) table parsing deferred (see Deferred Features Register; FINAL_BLUEPRINT §25).
  • Every complex script — Phase 12 delivers Arabic + one Indic; Tibetan, Khmer, Myanmar, Hangul jamo shaper, etc. are PhaseDeferred (see Deferred Features Register; FINAL_BLUEPRINT §24).
  • Full UAX #14 tailoring — we implement the default algorithm; locale-specific tailoring tables deferred (see Deferred Features Register; FINAL_BLUEPRINT §17).

  • Browser-engine research (layout layer feeding a renderer)
  • Project #385 TrueType rasterizer (direct Buffer consumer)

Target users: text-stack engineers, font engineers, OS/browser subsystem authors.

2. Why Build This

The learning claim: every OS, browser, terminal, and PDF engine executes this exact pipeline; it is invisible when correct and catastrophically visible when wrong (mojibake, tofu □, inverted Arabic, split cursor in bidi text, malformed ligatures). Building it from scratch forces mastery of four distinct sub-disciplines—normalization algebra, rule-machine segmentation, the bidi algorithm, and binary font-table parsing—that are rarely taught together and never obvious.

Unique Systems Knowledge Acquired

Sub-discipline What you learn
Normalization algebra Canonical decomposition as a rewriting system; the "blocked" composition invariant; Hangul's arithmetic encoding; QuickCheck as a span-skip optimization
Rule-machine segmentation Translating UAX property tables into O(n) finite automata; handling emoji ZWJ + regional-indicator pairing as special productions
Bidirectional algorithm UAX #9 is 30+ rules across five resolution stages; isolates add a scoped stack; mirroring is post-reorder; getting cursor movement right requires the cluster map
Binary font parsing sfnt table directory; cmap format 4/12 BMP/full-range encoding; GSUB/GPOS LookupList → FeatureList → ScriptList indirection; coverage tables; anchor records; bounds-checking untrusted bytes without copying
Table generation Two-stage trie construction from UCD text files; trade-off between index-stage block size, data-stage deduplication, and lookup cost

Why It Matters Architecturally

  • Every display system needs it. The Linux text stack (Pango → HarfBuzz → FreeType), macOS CoreText, Windows DirectWrite, browser engines (Blink/WebKit), and terminal emulators all implement exactly this pipeline.
  • HarfBuzz + ICU are canonical prior art. HarfBuzz (~80 KLOC C++) implements shaping; ICU (~1 MLOC C++) implements normalization + bidi + segmentation. Understanding them at source level requires understanding exactly the algorithms we implement.
  • Correctness bugs are high-impact. Wrong normalization → storage key collisions. Wrong grapheme clusters → miscounted characters in text editors. Wrong bidi → reversed display, security-relevant (CVE-class: "Trojan Source" exploits bidi override chars). Wrong shaping → tofu or illegible text for Arabic/Indic scripts used by hundreds of millions.

Engineering Muscles

  • Spec-faithful rule machines: translating a 30-rule UAX into a state machine with no added complexity.
  • Compact table generation: a two-stage trie maps 0..=0x10FFFF to per-property bytes in < 1 MB static data.
  • Untrusted-font parsing: bounds-checked slice indexing, typed errors, no heap allocation per lookup.
  • Differential testing: normalize/segment/bidi outputs compared byte-for-byte against ICU + unicode-bidi; shaping compared against HarfBuzz fixture files.

Calibration Value

Completing this project demonstrates: (a) ability to translate multi-hundred-page Unicode specifications into correct, tested implementations; (b) safe binary parsing discipline; (c) generated-table engineering; (d) differential conformance testing against production systems. These signal competence at the level expected for a text-stack or rendering-engine role.

What Mastery Looks Like

  • Phase 1 — Table engineering: Can design a two-stage CodePointTrie from scratch, explain the block-deduplication trade-off, derive the static-data budget, and regenerate the tables from a new UCD release without consulting documentation.
  • Phase 2–3 — Normalization algebra: Can explain why the canonical-ordering step must precede composition, identify the exact conditions under which a pair is "blocked," enumerate the composition exclusion categories from memory, and debug a NormalizationTest.txt failure by tracing the decompose→order→compose pipeline step-by-step.
  • Phase 4–5 — Rule-machine segmentation: Can translate any UAX #29 or #14 rule table into an O(n) state machine, explain why GB11 and GB12/13 require explicit state (not just pair-table lookup), and verify a GraphemeBreakTest.txt failure against the spec rule number.
  • Phase 6–7 — Bidirectional algorithm: Can execute the full UAX #9 X-through-L rule sequence on a mixed Arabic/Latin paragraph by hand, explain the isolating-run-sequence construction, identify which rule governs bracket pairing, and implement reorder_line producing a correct permutation from a level array.
  • Phase 8–12 — OpenType shaping: Can parse a GSUB LookupList from raw font bytes, explain the Coverage/ClassDef/FeatureList indirection chain, write a correct cluster-merge for a ligature substitution, and debug a HarfBuzz differential failure to a specific lookup type and feature ordering issue.
  • Phase 13 — Conformance discipline: Can build a differential testing harness against a production reference (ICU/HarfBuzz), instrument a libFuzzer corpus for font parsing, and set criterion regression gates that distinguish genuine regressions from CI noise.
  • Cross-cutting — Systems thinking: Can reason about the full pipeline from a raw &str to a Buffer handed to a rasterizer, explain every data-flow contract at each stage boundary, identify which invariants (cluster monotonicity, bidi level bounds, normalization idempotence) must hold end-to-end, and diagnose a cursor-placement bug by tracing the cluster map from GSUB output back to the original byte offset.

Trust Boundary

UNTRUSTED --->  font bytes &[u8]  (ush-shape; every table access bounds-checked)
UNTRUSTED --->  text &str         (all crates; arbitrary Unicode, no assumption on normalization)
TRUSTED   --->  ush-tables data   (generated at build time from UCD; const; immutable)

Both untrusted inputs are processed with bounds-checked slice access and typed Result errors; no unsafe on the parsing hot path. Malformed font → Err(ShapeError::...) + .notdef glyph fallback; invalid UTF-8 is rejected at the &str type boundary.

Data-Flow Contracts Between Stages

Stage boundary Type crossing
normalize out String (NFC/NFD/…); same scalar values, reordered/composed combining marks
segment out Iterator of (Range<usize>, BreakClass); or Vec<Run { range, script, bidi_level }>
bidi out BidiInfo { levels: Vec<Level>, classes: Vec<BidiClass>, para_level: Level }; one entry per UTF-16 code unit (UAX #9 convention)
shape out Buffer { infos: Vec<GlyphInfo>, positions: Vec<GlyphPosition>, direction }
#385 boundary Buffer passed by reference; #385 reads glyph_id + cluster + advances + offsets; no ownership transfer of font data

No stage persists state between calls. Generated UCD tables are the single build-time artifact (const static data compiled into ush-tables).

Per-Box Responsibilities

ush-tables — CodePointTrie + property accessors

  • Owns all per-code-point Unicode properties: general_category, combining_class (ccc), decomposition (canonical + compat + CompatTag), bidi_class, grapheme_break (GCB), word_break, line_break, script.
  • Two-stage trie: 9-bit index block size → index[cp >> 9] gives a page offset; data[page + (cp & 0x1FF)] gives the value. Total size target < 1 MB for all properties combined.
  • Generated by tools/ from UCD text files; output is Rust const arrays. no_std. Invariant: property values are frozen at Unicode 15.1; any UCD bump requires regeneration + full conformance re-run.

ush-normalize — UAX #15 normalization

  • Normalizer { form: NormForm } + free fn normalize(form, &str) -> String.
  • NFD: recursive canonical decomposition via decomposition(), then canonical_order() (stable ccc sort, ccc==0 blockers prevent reordering across starters).
  • NFC: NFD then canonical composition — scan left-to-right, pair a starter with a following combining char if primary composite exists AND pair is not blocked AND composite not in composition-exclusion set.
  • NFKD/NFKC: same as NFD/NFC but also apply compat decompositions (CompatTag-tagged entries).
  • Hangul: algorithmic (SBase=0xAC00, LBase=0x1100, VBase=0x1161, TBase=0x11A7, LCount=19, VCount=21, TCount=28); no table needed.
  • quick_check(form, &str) -> QuickCheck { Yes, No, Maybe }: Yes-only spans are already normalized → skip entirely (the fast path for already-NFC text).
  • Invariant: output is idempotent (normalize(form, normalize(form, s)) == normalize(form, s)).

ush-segment — grapheme clusters, words, line-break opportunities

  • GraphemeCursor<'a> over a &str: advances one extended grapheme cluster per step using the GB1..GB999 rule state machine over GraphemeBreak properties.
  • Emoji ZWJ sequences: ZWJ (U+200D) followed by ExtPict is never a break point (GB11). Regional indicators pair: break after every second RI (GB12/GB13).
  • WordCursor applies WB rules over word_break properties; yields word/non-word spans.
  • LineBreaker applies UAX #14 LB rules via the break-class pair table; emits (offset, BreakClass { Mandatory, Allowed, No }).
  • Invariant: grapheme cluster boundaries are always valid UTF-8 byte boundaries; cursor never splits a multi-byte sequence.

ush-bidi — UAX #9 bidirectional algorithm

  • process_paragraph(text, base: Option<Level>) -> BidiInfo: assigns BidiClass per char (via ush-tables), detects paragraph base level (P2/P3; FSI heuristic), runs X1..X8 explicit-level rules via DirectionalStatusStack (push on LRE/RLE/LRO/RLO/LRI/RLI/FSI; pop on PDF/PDI; max depth 125), forms isolating run sequences, resolves weak types (W1..W7), neutral types (N0..N2), implicit levels (I1/I2).
  • reorder_line(levels, line) -> Vec<usize>: L2 rule — from highest level down to the lowest odd level, reverse each maximal run; returns visual-order index vector.
  • mirror(c) -> Option<char>: returns the bidi mirroring pair for chars at odd embedding levels (e.g. ( → ) for RTL display).
  • Invariant: Level(0) is LTR, Level(1) is RTL; even = LTR, odd = RTL; max 125.

ush-shape — OpenType font parsing: Face

  • Face<'a> holds &'a [u8] (zero-copy), the sfnt table-directory offsets, and units_per_em from head.
  • Table parsing: head/hhea/maxp/hmtx for metrics; cmap formats 4 (BMP) and 12 (full range) → nominal_glyph(char) -> Option<u32>; GDEF for glyph-class + mark-attach-class + mark-glyph-sets.
  • All table access: range-checked get(offset..offset+len)?; never panics on malformed input.

Buffer — the shaping workspace

  • Buffer { infos: Vec<GlyphInfo>, positions: Vec<GlyphPosition>, direction: Direction }.
  • GlyphInfo { glyph_id: u32, cluster: u32, flags: u16 } — cluster is monotonically non-decreasing (LTR) or non-increasing (RTL); merges on ligation, splits on multiple-substitution.
  • GlyphPosition { x_advance, y_advance, x_offset, y_offset: i32 } in font design units.
  • Invariant: infos.len() == positions.len() always; cluster values preserve input-char provenance for hit-testing.

Shaping pipeline + Shapers

  • shape(face, buf, features) orchestrates: (1) map Unicode chars → nominal glyph IDs via cmap; (2) select script/lang/features from GSUB + GPOS ScriptList; (3) dispatch to the appropriate Shaper impl; (4) run GSUB lookups; (5) run GPOS lookups.
  • ShaperLatin: applies default GSUB/GPOS features (kern, liga, calt, …); no reorder.
  • ShaperArabic: joining-type state machine → assigns isol/init/medi/fina contextual forms; applies arab/init/medi/fina/isol/liga/mset features.
  • ShaperIndic: syllable reorder (base consonant, halant, matra positions) before GSUB; applies the Indic feature set.
  • ShaperGeneral: script-agnostic fallback; applies default features only.
  • RTL Buffer: direction from bidi Level parity; RTL runs have the buffer reversed before GSUB so lookup order is correct; reversed back after GPOS.

GSUB — glyph substitution

  • Lookup types 1 (single), 2 (multiple), 3 (alternate), 4 (ligature), 5 (contextual), 6 (chaining-contextual).
  • Feature ordering: mandatory features first, then ordered user feature list, then default features.
  • Cluster merging on ligature (type 4): output glyph inherits minimum cluster of all input glyphs.

GPOS — glyph positioning

  • Lookup types 1 (single adjust), 2 (pair/kerning), 3 (cursive attach), 4 (mark-to-base), 5 (mark-to-ligature), 6 (mark-to-mark), 7/8 (contextual).
  • Value records: XPlacement, YPlacement, XAdvance, YAdvance deltas applied to GlyphPosition.
  • Anchors + device tables for mark attachment; device table delta applied at current ppem.

ush-cli — the ush binary

  • Subcommands: normalize [--form NFC|NFD|NFKC|NFKD] <text>, segment [--graphemes|--words|--lines] <text>, bidi <text>, shape --font <file> [--script] [--lang] [--features] <text>.
  • shape output: JSON or TSV of (glyph_id, cluster, x_advance, y_advance, x_offset, y_offset) per glyph; optionally pipes to #385 rasterizer stdin.
  • Depends on all five library crates; the only std-using crate in the workspace.

6. Design Principles

P1 — The annex is the oracle. UAX #9/#14/#15/#29 + the official Unicode test files (NormalizationTest.txt, BidiTest.txt, BidiCharacterTest.txt, GraphemeBreakTest.txt, WordBreakTest.txt, LineBreakTest.txt) are the normative source of truth. When ush-* and ICU/HarfBuzz disagree, first check which conforms to the annex; differential failures are filed against the crate, not the reference implementation. Tradeoff: occasionally the spec admits non-determinism or tailoring; document every tailoring decision as a deviation. Violating it breaks conformance and makes the engine untrustworthy for i18n-critical applications.

P2 — Pin the Unicode version. The workspace declares a single UCD version (currently 15.1) in tools/Cargo.toml as a const; ush-tables embeds it in a pub const UNICODE_VERSION: (u8, u8, u8) and exposes it in every crate. Updating requires a full tools/ regeneration + re-run of all conformance test files for that version. Tradeoff: no automatic "latest" tables; explicit upgrade step. Violating it causes property mismatches between table data and test expectations.

P3 — Normalize, then segment, then bidi, then shape. The pipeline order ush-normalize → ush-segment → ush-bidi → ush-shape is load-bearing, not cosmetic. Segmentation over non-normalized text can split combining sequences incorrectly; bidi over unsegmented text cannot correctly handle paragraph-scoped embedding; shaping expects canonical-ordered, direction-resolved glyph runs. Tradeoff: pipeline stages cannot be skipped or reordered by the caller without violating correctness guarantees. Violating it produces incorrect cluster boundaries, wrong embedding levels, or malformed shaped output.

P4 — Quick-check before doing work. quick_check(form, input) returns QuickCheck::Yes when every codepoint's NFC_QC/NFD_QC/NFKC_QC/NFKD_QC property is Yes; the Normalizer short-circuits and returns the input unchanged. ASCII-only strings (U+0000–U+007F) are always NFC/NFD Yes. Tradeoff: adds a linear scan; justified because most production text is already NFC, making the fast path the common case (>90% in English/CJK documents). Violating it re-normalizes already-normalized text, wasting cycles.

P5 — Rule machines mirror the spec rules 1:1. Every grapheme break rule is labeled GBn, every word-break rule WBn, every line-break rule LBn, every bidi explicit rule Xn, weak rule Wn, neutral Nn, implicit In, reorder Ln — matching the annex numbering. Code comments cite the rule number. No rule merging, reordering, or "optimization" that changes observable behavior. Tradeoff: some rules could be collapsed for speed; we defer that to a later optimization pass with a before/after differential. Violating it makes conformance failures impossible to debug against the spec.

P6 — Never trust a font. Every byte offset and length read from a font file is bounds-checked against the backing &[u8] slice before dereferencing. Malformed offsets, zero-length subtables, and cyclic lookup references (depth cap: 8 levels) never panic; they return a .notdef glyph (glyph id 0) or skip the feature. Face construction validates the sfnt table directory first. Tradeoff: some valid-but-unusual fonts may hit conservative limits; document the limits in the opentype parsing module. Violating it opens a memory-safety hole on attacker-controlled fonts.

P7 — Clusters are sacred. The cluster map in Buffer is monotonically non-decreasing (Ltr) or non-increasing (Rtl) throughout the shaping pipeline. Ligature substitution (GSUB type 4) merges component clusters to the first component's value; multiple substitution (GSUB type 2) splits one cluster into a range. No shaping operation ever assigns a glyph a cluster value outside the input's valid range. Tradeoff: prevents some otherwise-valid cross-cluster substitutions; the OpenType spec allows them only in specific contexts. Violating it breaks hit-testing, cursor placement, and selection rendering in any layout engine consuming the Buffer.

P8 — Tables are generated, not hand-typed. All property tables in ush-tables (CodePointTrie index + data arrays, break-property tables, bidi-class arrays, decomposition maps) are emitted by tools/gen_tables from official UCD files. No hand-editing of generated files; a tools/verify_tables target compares a fresh generation against the committed output and fails CI if they differ. Tradeoff: adds a code-generation dependency; justified because Unicode tables span ~100 000 entries and hand-maintenance is error-prone. Violating it introduces stale or incorrect property data.

P9 — Glyphs out, not pixels. ush-shape's output is a Buffer containing GlyphInfo (glyph_id, cluster, flags) and GlyphPosition (x_advance, y_advance, x_offset, y_offset) in font units (units_per_em from the head table). Hinting, rasterization, sub-pixel rendering, and compositing are entirely outside this project — consumed by project #385. Tradeoff: callers must scale font units to device pixels themselves; we provide units_per_em as metadata. Violating it entangles layout and rendering, making the boundary untestable independently.

P10 — Determinism. For fixed Unicode version + font file bytes + feature list, shape(face, buf, features) always produces the identical Buffer. No global mutable state, no thread-local caches, no randomization. Tradeoff: no shape-plan caching between calls (as HarfBuzz does); a future optimization may add an explicit cache parameter. Violating it makes golden-file tests non-reproducible and differential debugging against HarfBuzz impossible.

P11 — Minimal allocations on the hot path. Each pipeline stage reuses a single pre-allocated buffer per call. normalize returns a String (one allocation). The Buffer in ush-shape pre-allocates to input length and resizes only on expansion (multiple-subst). No per-glyph Box or Rc. Tradeoff: slightly more complex buffer management vs. idiomatic per-item allocation. Violating it makes the shaper too slow for real-time text layout (target: <1 µs/glyph at 1 000 glyphs/call).

P12 — no_std + alloc for all library crates. ush-tables, ush-normalize, ush-segment, ush-bidi, ush-shape: #![no_std] with extern crate alloc. Only ush-cli is std. This keeps the library embeddable in OS kernels, WASM, and embedded runtimes. Tradeoff: no std::io, no std::fs in library code; font bytes must be pre-loaded by caller. Violating it closes off embedded/WASM consumers.

P13 — Fail-safe fallback, never silent drop. Unmapped characters (no cmap entry) → glyph id 0 (.notdef); unsupported GSUB lookup types → pass-through (glyph unchanged); unassigned codepoints → processed per their Unicode properties (not silently filtered). Every fallback is logged at trace! level via a pluggable debug callback (no std::io dependency). Tradeoff: .notdef glyphs are visible to the user; callers can detect unmapped chars via GlyphInfo::flags. Violating it silently corrupts text by dropping characters.

P14 — Test-first conformance gating. Phase 13 conformance tests (NormalizationTest, GraphemeBreakTest, BidiTest, etc.) are part of the standard cargo test suite, not an optional benchmark. CI must pass them before any merge. Differential fixtures against HarfBuzz shaping output are committed as golden files. Tradeoff: ~19 000 normalization test vectors make the test suite slower; use --release mode and nextest for acceptable CI wall time. Violating it allows regressions to slip into production.

7. System Invariants

INV-1 — Normalization is idempotent.

  • Statement: normalize(form, normalize(form, x)) == normalize(form, x) for all x, all NormForm.
  • Why: Unicode defines normal forms as fixed points; double application must be a no-op.
  • Enforced: Unit tests on NormalizationTest.txt column pairs; property quick_check(form, normalize(form, x)) == QuickCheck::Yes asserted in debug builds.
  • Detection: debug_assert_eq! after normalization in test mode; Phase 13 regression harness.
  • Recovery: Not applicable (pure function); failure indicates a bug in canonical_order or the composition loop.

INV-2 — Canonical ordering is stable.

  • Statement: canonical_order is a stable sort: codepoints with equal ccc retain their relative input order.
  • Why: UAX #15 §3: canonical ordering must be stable to avoid spurious canonical-equivalence violations.
  • Enforced: Implemented via Rust's slice::sort_by_key (guaranteed stable); asserted in tests with equal-ccc pairs.
  • Detection: Differential test against ICU normalizer2 output on equal-ccc sequences.
  • Recovery: Re-sort with stability flag; no user-visible recovery needed (internal invariant).

INV-3 — NFC→NFD canonical equivalence round-trip.

  • Statement: normalize(Nfd, normalize(Nfc, x)) is canonically equivalent to normalize(Nfd, x).
  • Why: NFC and NFD represent the same canonical-equivalence class; any sequence of compose/decompose must stay in-class.
  • Enforced: NormalizationTest.txt column checks (NFD(NFC(x)) == NFD(x)); verified in Phase 13.
  • Detection: Compare NFD output after NFC round-trip in test harness.

INV-4 — Grapheme boundaries never split base+extending or emoji ZWJ sequences.

  • Statement: No boundary returned by GraphemeCursor or graphemes() falls between a base and its Extend/SpacingMark/ZWJ or inside an emoji ZWJ sequence or regional-indicator pair.
  • Why: UAX #29 GB9/GB9a/GB9b/GB11/GB12/GB13; splitting these violates extended grapheme cluster definition.
  • Enforced: State machine enforces GBn rules; GraphemeBreakTest.txt covers all rule interactions.
  • Detection: Failing GraphemeBreakTest.txt row → rule number cited in error message.
  • Recovery: No recovery; assertion failure triggers a test failure revealing the broken rule.

INV-5 — Bidi embedding levels never exceed 125.

  • Statement: All Level values in BidiInfo::levels satisfy 0 <= level.0 <= 125.
  • Why: UAX #9 §3 conformance clause BI3; the DirectionalStatusStack caps depth at 125; exceeding entries are ignored.
  • Enforced: Level::new returns Err for values > 125; the stack overflow path sets level = para_level instead of pushing.
  • Detection: debug_assert!(level.0 <= 125) at every Level construction site; BidiTest.txt exercises the cap.
  • Telemetry: trace!("bidi_stack_overflow: para={}", para_level.0) on ignored embeddings.

INV-6 — reorder_line is a permutation.

  • Statement: The Vec<usize> returned by reorder_line(levels, line) is a permutation of line.start..line.end; no index appears twice, none is absent.
  • Why: Reordering must not lose or duplicate glyphs; consumer (#385) indexes into the original buffer by these indices.
  • Enforced: debug_assert_eq!(sorted(result), line.start..line.end) in debug builds; unit tests on all-LTR, all-RTL, mixed runs.
  • Detection: Permutation check fires in test suite; fuzz target exercises random level sequences.
  • Recovery: Not applicable; the algorithm is deterministic; failure indicates a bug in the L2 level-run loop.

INV-7 — Every font table access is bounds-checked.

  • Statement: No read from a Face's backing &[u8] slice ever accesses an out-of-bounds index; all offsets are validated before dereference.
  • Why: Font files are untrusted; OOB reads are undefined behavior (precluded by Rust slice indexing) but must not panic in production.
  • Enforced: All table accessors return Option or Result; slice indexing uses .get() not []; fuzz target in Phase 13.
  • Detection: libFuzzer corpus of malformed OTF/TTF files; cargo fuzz run fuzz_face.
  • Recovery: Malformed table → return .notdef (glyph id 0) for affected glyph range; log trace!("table_parse_error: table={:?}", tag).

INV-8 — The cluster map is monotonic and covers all input.

  • Statement (Ltr): buf.infos[i].cluster <= buf.infos[i+1].cluster for all consecutive glyphs in an Ltr run. Every cluster value is in 0..input_len. Statement (Rtl): non-increasing.
  • Why: Monotonicity is required by downstream hit-testing and cursor advancement; every output glyph must reference a valid input codepoint range.
  • Enforced: debug_assert after each GSUB lookup application in the shaping pipeline; verified against HarfBuzz golden fixtures.
  • Detection: Post-shaping cluster-monotonicity check in debug builds; Phase 13 differential.
  • Recovery: If a GSUB lookup would violate monotonicity (e.g., cross-cluster substitution), the lookup is skipped for that glyph sequence.

INV-9 — GSUB/GPOS apply only over Coverage-matched glyphs.

  • Statement: A GSUB or GPOS lookup is applied to glyph g only if coverage_index(lookup, g) returns Some(_); unmatched glyphs pass through unchanged.
  • Why: OpenType spec §5.1; applying a lookup outside its Coverage produces undefined output glyphs.
  • Enforced: Every lookup application function calls coverage_index first; no fallthrough without coverage check.
  • Detection: Unit tests with glyphs deliberately outside coverage verify pass-through.
  • Telemetry: trace!("lookup_skip: type={} glyph={}", lookup_type, glyph_id) for missed matches in verbose mode.

INV-10 — Shaping preserves total advance (absent GPOS).

  • Statement: buf.positions.iter().map(|p| p.x_advance).sum::<i32>() after GSUB only equals the sum of hmtx advances for each glyph in the Buffer; GPOS may adjust individual values but the cumulative layout advance is well-defined.
  • Why: Ligatures replace N glyphs with 1 whose advance = the ligature glyph's hmtx advance (not the sum of components); callers must not assume component-sum semantics.
  • Enforced: Tested with known ligatures (fi ligature in Latin fonts); GPOS kerning delta is sign-checked against plausible kerning ranges (< ±units_per_em).
  • Detection: Golden-file advance sums in Phase 13 HarfBuzz fixtures.

INV-11 — Unassigned and noncharacter codepoints are handled per spec.

  • Statement: Codepoints with GeneralCategory::Unassigned (Cn) or noncharacters (U+FDD0–U+FDEF, U+FFFE, U+FFFF, plane-final pairs) are not silently dropped; they pass through normalization (no decomposition), receive a BidiClass from ush-tables (typically ON or BN), and map to glyph 0 (.notdef) in ush-shape.
  • Why: UAX #15 §6 (unassigned codepoints are assigned to NFD_QC=Yes); UAX #9 §3.3 (noncharacters have defined bidi class); dropping them corrupts cluster indices for subsequent characters.
  • Enforced: decomposition(c) returns None for Cn/noncharacters; cmap lookup returns glyph 0; cluster map still allocates a slot.
  • Detection: Explicit test cases for U+FFFF, U+FDD0, and a Cn scalar in each pipeline stage.

INV-12 — The pipeline is deterministic for fixed Unicode + font version.

  • Statement: For identical inputs (text bytes, font bytes, feature list, base bidi level), the sequence normalize → segment → bidi → shape produces byte-for-byte identical output on every invocation, every platform.
  • Why: Required for reproducible builds, golden-file testing, and cache-key correctness.
  • Enforced: No HashMap with non-deterministic iteration order on output paths; BTreeMap or sorted Vec for feature/lookup iteration; no thread-local state.
  • Detection: Two consecutive calls in Phase 13 fixture harness; output XORed and asserted zero.
  • Telemetry: Any non-determinism source (clock, RNG, OS randomization) is a compile-time error via #![deny(clippy::non_deterministic_ordering)] equivalent lint.

8.2 Normalization Algorithm

Step order: decompose → canonical order → compose (only for NFC/NFKC).

8.2.1 Decomposition

  • Canonical: recursively expand via decomposition(c) = Canonical(chars) until no entry; Hangul LVT -> L,V,T arithmetically.
  • Compatibility (NFKD/NFKC): expand Compat(tag, chars) as well; same recursion.
  • Hangul arithmetic (no table):
    SBase=0xAC00, LBase=0x1100, VBase=0x1161, TBase=0x11A7
LCount=19, VCount=21, TCount=28, NCount=VCount*TCount=588
LV = LBase + (cp-SBase)/NCount
V  = VBase + ((cp-SBase) % NCount) / TCount
T  = TBase + (cp-SBase) % TCount   (only if T index > 0)

8.2.2 Canonical Ordering

  • Collect (char, ccc) pairs from decomposed buffer.
  • Stable sort every maximal run of ccc > 0; ccc == 0 chars act as blockers — they terminate a run.
  • Invariant after step: any two adjacent chars with ccc(a) > ccc(b) have been swapped; starters not moved.

8.2.3 Canonical Composition (NFC / NFKC)

Current char ccc Condition Action
== 0 (starter) always record as new starter candidate
> 0 (combining) blocked(starter, i) == true append char unchanged; update max_ccc_since_starter
> 0 (combining) not blocked AND is_primary_composite(buf[starter], buf[i]) replace buf[starter] with composite; delete buf[i] from buffer; continue scan at same i (now pointing to next char)
> 0 (combining) not blocked AND no composite found append char unchanged; update max_ccc_since_starter
  • Blocked: some char at j (starter < j < i) has ccc(j) >= ccc(i); OR j is a starter itself.
  • Composition exclusions: singletons, non-starter decompositions, pre-composed chars listed in CompositionExclusions.txt; also Hangul composed algorithmically (L+V -> LV, LV+T -> LVT).

8.4.2 Paragraph Base Level (P2/P3 + FSI)

  • P2: scan left-to-right in paragraph, skipping chars inside isolates; take first strong (L/R/AL).
  • P3: if L -> level 0; if R/AL -> level 1; if no strong found -> level 0.
  • FSI: look ahead within the isolate for first strong; resolve its direction the same way.

8.4.3 Explicit Level Resolution (X Rules) — DirectionalStatusStack

struct DirectionalStatusStack {
    entries: Vec<(Level, Override, Isolate)>,  // max 125 depth
}
// X1: push paragraph level.
// X2 LRE: push(current+1 rounded even, Neutral, false)   if depth < 125
// X3 RLE: push(current+1 rounded odd,  Neutral, false)   if depth < 125
// X4 LRO: push(..., Override=L, false)
// X5 RLO: push(..., Override=R, false)
// X5a LRI: push(current+1 rounded even, Neutral, true)   isolate
// X5b RLI: push(current+1 rounded odd,  Neutral, true)   isolate
// X5c FSI: determine direction, then push as LRI or RLI
// X6: assign current level/override to every non-format char
// X6a PDI: pop top isolate entry; assign PDI level from new top
// X7 PDF: pop top non-isolate entry
// X8: reset stack to paragraph level at B
// depth > 125: ignore LRE/RLE/LRO/RLO; overflow isolate counter for LRI/RLI/FSI

Isolate example: "hello ⁦Arabic⁩ world" (LRI...PDI):

  • Before LRI: level 0. LRI pushes level 1 (even -> LTR override from isolate direction).
  • "Arabic" chars assigned level 1 inside isolate.
  • PDI pops; "world" back at level 0.
  • Isolate is treated as a unit in the enclosing level; no W/N rules cross its boundary.

8.4.4 W / N / I Rules + L2 Reorder

  • W1-W7 (weak): W1 NSM inherits preceding class; W2 EN after AL -> AN; W3 AL -> R; W4 ES/CS between EN->EN; W5 ET adjacent EN; W6 ES/ET/CS -> ON; W7 EN after L context -> L.
  • N0-N2 (neutral): N0 paired brackets (the bracket-matching algorithm); N1 sequence of neutrals between same-direction strongs -> that direction; N2 remaining neutrals -> embedding direction.
  • I1/I2 (implicit): I1 even level: L stays, R +1, AN/EN +2; I2 odd level: R stays, L/AN/EN +1.
  • L2 reorder: reverse every maximal contiguous sequence at the highest level, decrement level, repeat until all levels resolved; yields visual order.
  • L3 combining marks: (handled; marks take preceding level).
  • mirror(): at odd levels, replace bracket/quote/arrow with bidi-mirror pair (e.g., U+0028 -> U+0029) using the Bidi_Mirroring_Glyph table.

1 a L 0

3 (space) WS 0

Type Name Mechanism

3 Alternate 1 -> 1 of N alternates
4 Ligature N -> 1 (ligate)

Worked ligature (GSUB type 4): feature liga, script latn:

  • LookupList[2]: LigatureSet for glyph(f): [Ligature { components:[glyph(i)], ligGlyph:glyph(fi) }]
  • Buffer before: [GlyphInfo{id:glyph(f), cluster:0}, GlyphInfo{id:glyph(i), cluster:1}]
  • Match: current=glyph(f), next=glyph(i) -> ligature match.
  • Buffer after: [GlyphInfo{id:glyph(fi), cluster:0}] — cluster 0 covers input chars 0..1; cluster monotonic.

8.5.5 GPOS Lookup Types

Type Name Mechanism
1 Single Adjust value record per glyph
2 Pair Adjust kerning: (g1,g2) -> (ValueRecord1, ValueRecord2)
3 Cursive Attach entry/exit anchors for cursive scripts
4 Mark-to-Base mark anchor -> base anchor
5 Mark-to-Ligature mark -> ligature component anchor

Worked kerning pair (GPOS type 2):

  • PairSet for glyph(A): [PairValueRecord{ secondGlyph:glyph(V), value1:{XAdvance:-80}, value2:{} }]
  • Buffer: [GlyphInfo(A,cluster=0), GlyphInfo(V,cluster=1)]
  • Apply: positions[0].x_advance += -80; positions[1] unchanged.

Value record fields: XPlacement, YPlacement, XAdvance, YAdvance (each i16). Anchors: (x,y) in design units with optional device tables for hinting.

8.5.6 Buffer / Cluster Invariants

  • infos.len() == positions.len() always.
  • Cluster values monotonically non-decreasing (LTR) or non-increasing (RTL).
  • Ligature merge: all consumed glyphs' clusters collapse to the minimum cluster index.
  • Multiple-subst split: new glyphs inherit the source glyph's cluster value.
  • Cluster ties output glyph_id back to input char offset for hit-testing + cursor placement by caller.

Unassigned code point (e.g., U+FFFF) Valid scalar, GC=Cn, no decomp, bidi=BN Pass through as-is; no crash; cmap miss -> .notdef

cmap miss No glyph for cp in any subtable glyph_id = 0 (.notdef); cluster preserved; shaping continues

1.2 Detailed Implementation Steps

Theory anchors: two-stage trie mirrors ICU's UCPTrie (Reference Impl: ICU normalizer2impl.cpp); trie block-size/dedup trade-off is data-compression (ADR-05); UAX #44 (sec. 5.4) defines every source-file format consumed here.

2.2 Detailed Implementation Steps

Theory anchors: recursive canonical decomposition follows UAX #15 sec. 3 (P5 — rule machines mirror spec); ccc stable-sort derives from the Unicode Standard sec. 3.11 canonical ordering; blocked-pair detection is the composition invariant from UAX #15 sec. 1; Hangul arithmetic is entirely sec. 3.12 of the Unicode Standard (no table required per P8).

hangul.rs — constants + functions: S_BASE=0xAC00, L_BASE=0x1100/L_COUNT=19, V_BASE=0x1161/V_COUNT=21, T_BASE=0x11A7/T_COUNT=28, N_COUNT=V_COUNT*T_COUNT=588, S_COUNT=L_COUNT*N_COUNT=11172; decompose_hangul(s) -> Option<(char,char,Option<char>)> (LV or LVT), compose_lv_t, compose_l_v. Decompose LVT: si=s-S_BASE; T=T_BASE+si%T_COUNT; LV=S_BASE+si-si%T_COUNT. Decompose LV: L=L_BASE+si/N_COUNT; V=V_BASE+(si%N_COUNT)/T_COUNT. Compose L+V: bounds-check both, LV=S_BASE+(l-L_BASE)*N_COUNT+(v-V_BASE)*T_COUNT. Compose LV+T: require T_BASE+1≤t and (s-S_BASE)%T_COUNT==0, LVT=s+(t-T_BASE).

decompose.rs — fn decompose_char(c: char, out: &mut Vec<(char,u8)>): is_hangul(c) (0xAC00..=0xD7A3) → push L/V/T (ccc=0 each) and return; decomposition(c)==Some(Canonical(slice)) → recurse per char; None or Compat(..) → push (c, combining_class(c)) as leaf. Compat is NOT followed in NFD/NFC (only NFKD/NFKC, Phase 3) — the Compat arm behaves like None here. pub fn nfd(input: &str) -> Vec<(char,u8)> iterates input chars calling decompose_char, returns flat vec.

order.rs — pub fn canonical_order(buf: &mut Vec<(char,u8)>): scan left-to-right; runs are bounded by ccc==0 starters; within each run apply stable sort_by_key(|(_,ccc)| *ccc). Invariant: after canonical_order, for all adjacent pairs (a_ccc, b_ccc) with both > 0, a_ccc ≤ b_ccc; a ccc==0 char restarts a new run.

compose.rs — pub fn nfc_compose(buf: Vec<(char,u8)>) -> String, state = last_starter (composition candidate) + max_ccc_since_starter (blocking tracker). Scan buf left-to-right: for (ch, ccc), if ccc==0 or max_ccc_since_starter < ccc(ch) (not blocked), attempt compose_pair(last_starter, ch) via COMPOSITION; on hit (and not Full_Composition_Exclusion) replace last_starter in output, else append ch and update max_ccc_since_starter. Blocked = an intervening char with ccc ≥ ccc(c) exists (tracked via max_ccc_since_starter). compose_pair(a,b) -> Option<char> binary-searches COMPOSITION by (a as u32, b as u32), returns composite iff found and !is_full_composition_exclusion(composite).

ush-normalize/src/lib.rs public signatures (§11.2): normalize(form, input) — Nfd: nfd → canonical_order → collect; Nfc: nfd → canonical_order → nfc_compose → collect; Nfkd/Nfkc: Phase 3 (compat branch). quick_check(form, input): Phase 2 uses NFD_QC/NFC_QC bits from Phase 1 — returns Yes iff every char has QC=Yes for the given form.

3.2 Detailed Implementation Steps

Theory anchors: compatibility decomposition follows UAX #15 sec. 3 (CompatTag variants defined there); QuickCheck algorithm maps to UAX #15 sec. 10 (Davis, Whistler; §5.2); stream-safe 30-CC cap derives from UTN#27 (Davis; §5.2); incremental normalization boundary = ccc==0 starter (P5, UAX #15).

compat.rs — compat_decompose(c, buf: &mut Vec<(char,u8)>): recurse via decomposition(c) -> Compat(tag,chars) | Canonical(chars); NFKD applies both Canonical + Compat mappings recursively, NFKC same + then compose. Decomp::Compat(CompatTag, &[char]) applies regardless of tag for K-forms, skipped for non-K-forms. Recursion terminates when decomposition(c)==None (atomic). After full K-decomposition: run canonical_order + (NFKC only) canonical_compose, reusing Phase 2 code.

quickcheck.rs — quick_check(form, input) -> QuickCheck: scan, look up QC property per code point, track last_ccc; No → return No immediately; Maybe accumulates; ccc decrease → No; all-Yes + ccc non-decreasing → Yes (fully normalized, skip). QC stored in CodePointTrie as a 2-bit field per form (4 forms/u8); an all-Yes input costs zero allocations, single O(n) pass. Integrated into normalize() as the first call — Yes returns input as-is (Cow/borrow path).

incremental.rs — stream-safe + chunked processing: IncrementalNormalizer { form, pending: Vec<(char,u8)>, combining_count: u8 }; push_char(c) -> Option<String> flushes on starter or cap hit; finish() -> String; stream_safe(input) -> String inserts CGJ after the 30th combining mark in a run. Starter-boundary detection: combining_class(c)==0 flushes pending, emits, starts a new run. Stream-safe cap: count combining marks (ccc>0) per starter; at 30, insert CGJ (ccc=0 blocker), continue. push_char returns Some(flushed_chunk) when a complete normalized unit is ready; caller concatenates. normalize() for NFKD/NFKC calls compat_decompose in place of canonical_decompose before ordering/composition.

lib.rs routing: normalize(Nfkd, ..) → compat decompose → canonical order → done; normalize(Nfkc, ..) → compat decompose → canonical order → canonical compose; quick_check is the first call in normalize, Cow<str> return where possible.

18. Phase 6 — Bidi I: classes, base level, explicit levels + isolates (UAX #9)

6.1 Objectives

  • Assign BidiClass per scalar value via ush-tables::bidi_class(c); store in BidiInfo.classes.
  • Detect paragraph base level: P2/P3 (first strong type L/R/AL in paragraph, skipping isolate scopes); FSI heuristic (count enclosed strong types to determine RLI vs LRI).
  • Resolve explicit-level rules X1..X10 using DirectionalStatusStack; emit per-char Level into BidiInfo.levels.
  • Mark BN / explicit-formatting characters; match every isolate initiator (LRI/RLI/FSI) to its PDI (or end-of-paragraph) for use in Phase 7 run-sequence building.

6.2 Detailed Implementation Steps

Theory anchors: DirectionalStatusStack is a bounded pushdown automaton (Hopcroft et al.; §5.1); X rules are specified verbatim in UAX #9 sec. 4 (Davis; §5.2); isolate tracking (LRI/RLI/FSI/PDI) was introduced in Unicode 6.3 and formalized in UAX #9 sec. 3.3.2 (ADR-12); FSI heuristic is UAX #9 P2 (P5 — rule machines mirror spec 1:1).

File layout (ush-bidi/src/): lib.rs (BidiInfo, process_paragraph public API, re-exports); classes.rs (assign_classes(text) -> Vec<BidiClass>, iterates chars calling ush_tables::bidi_class); para_level.rs (detect_base_level(classes, override) -> Level, P2/P3 + FSI scan); explicit.rs (DirectionalStatusStack, resolve_explicit(classes, para_level) -> (Vec<Level>, IsolateMap)); types.rs (BidiClass enum, 23 variants; Level(u8); Direction; DirectionalStatusStack; IsolateMap).

BidiClass assignment: iterate text.char_indices(), call bidi_class(c), push to Vec<BidiClass>; surrogate ranges absent (Rust char guarantees scalars); BOM (U+FEFF) → BN.

Base-level detection: P2 scans left-to-right, skipping the interior of any isolate scope (LRI/RLI/FSI...PDI, nesting via counter); P3: first strong found L→Level(0), R/AL→Level(1), none found→Level(0); FSI scans enclosed content up to matching PDI — if R/AL count > L count, RLI semantics, else LRI.

DirectionalStatusStack: Entry{level:Level, override_status:Override, isolate:bool}; DirectionalStatusStack{stack:Vec<Entry>, overflow_isolate:u32, overflow_embedding:u32, valid_isolate:u32} — max depth 125, overflow counters track excess pushes. X1: init stack with [Entry{para_level, Neutral, false}]. X2/X3 (RLE/LRE): push Entry{next_odd/even(top.level), Neutral, false} if depth≤125 and overflow_isolate==0, else increment overflow_embedding. X4/X5 (RLO/LRO): same but override=R/L. X5a/b/c (RLI/LRI/FSI): push Entry{next_odd/even, Neutral, true}, increment valid_isolate, assign current char top.level; if overflow_isolate>0, increment it instead. X6a (PDI): if overflow_isolate>0 decrement; else if valid_isolate==0 ignore (error); else pop until stack.top().isolate==true, decrement valid_isolate, assign current char new top level. X7 (PDF): if overflow_isolate>0 ignore; else if overflow_embedding>0 decrement; else if top is non-isolate, pop. X8 (end of paragraph): reset to paragraph level. X9: mark LRE/RLE/LRO/RLO/PDF/BN with a level but flag REMOVED from the active sequence. X10: record IsolateMap: HashMap<usize,usize> mapping initiator char-index → PDI char-index. X6 (all other chars): level = top.level; if override=R/L, class = R/L.

20. Phase 8 — OpenType font parsing (sfnt, cmap, metrics, GDEF)

8.1 Objectives

  • Parse sfnt table directory from raw &[u8] font bytes; locate tables by 4-byte tag.
  • Parse head (units_per_em, indexToLocFormat), hhea/hmtx (advance widths + lsb for all glyphs), maxp (numGlyphs bound).
  • Parse cmap subtables: format 4 (BMP segmented delta/range), format 6 (trimmed array), format 12 (full Unicode groups) → char -> GlyphId nominal map.
  • Parse GDEF: GlyphClassDef (base/ligature/mark/component), MarkAttachClassDef, MarkGlyphSetsTable.
  • Every offset + length bounds-checked; malformed input → typed ParseError, never panic.
  • Deliver Face API consumed by Phase 9 shaping pipeline.

8.2 Detailed Implementation Steps

Theory anchors: sfnt table directory structure is normative in the OpenType Specification "General — Font Tables" (§5.4); cmap format 4 segment-delta arithmetic is OpenType cmap; bounds-checked zero-copy parsing with &[u8] mirrors ttf-parser idioms (Reference Impl; §5.3); ADR-13 justifies hand-rolling over library dependency; P6 — never trust a font.

File layout (ush-shape/src/): face.rs (Face<'a>, TableDirectory, sfnt_version check, table(tag) -> Option<&[u8]>); cmap.rs (Cmap, CmapSubtable{Format4,Format6,Format12}, nominal_glyph(c) -> Option<u32>); gdef.rs (Gdef, GlyphClass, glyph_class(id), mark_attach_class(id) -> u8, mark_glyph_set_contains(set, id) -> bool); parse.rs (Bytes<'a> cursor: read_u8/u16/u32/i16, slice(len), at(offset), all Result<_,ParseError>); error.rs (ParseError{UnexpectedEof,InvalidMagic,InvalidVersion,TableNotFound,InvalidFormat(u16),OutOfRange}); metrics.rs (HorizontalMetrics{advances:Vec<u16>, lsbs:Vec<i16>}, parsed from hhea+hmtx).

Face::parse(data) -> Result<Face<'a>, ParseError>: (1) check sfnt_version 0x00010000 (TT) or 0x4F54544F (OT/CFF), error on mismatch; (2) read numTables/searchRange/entrySelector/rangeShift (u16 each); (3) parse TableRecord[numTables]: tag(u32), checksum(u32), offset(u32), length(u32); (4) bounds-check offset+length ≤ data.len() for every record, else OutOfRange; (5) store sorted, binary search by tag in table().

head: magic 0x5F0F3CF5 at offset 12, version 0x00010000; units_per_em u16 at offset 18 (valid 16..=16384); indexToLocFormat i16 at offset 50 (0=short, 1=long offsets).

hhea+hmtx: hhea.numberOfHMetrics u16 at offset 34; hmtx holds that many (advanceWidth:u16, lsb:i16) records, remaining glyphs get lsb only (advance = last hMetric's); bounds numberOfHMetrics*4 + (numGlyphs-numberOfHMetrics)*2 ≤ hmtx.len().

cmap: header version(u16)=0, numTables(u16), EncodingRecord[numTables]{platformID,encodingID,offset(u32)}; subtable priority format 12 (3/10 or 0/4) > format 4 (3/1 or 0/3) > format 6. Format 4: segCount=segCountX2/2; arrays endCode[]/startCode[]/idDelta[]/idRangeOffset[]; glyph_id = ((startCode[i]+(c-startCode[i]))+idDelta[i]) & 0xFFFF, or via idRangeOffset into glyphIdArray. Format 12: numGroups groups of (startCharCode,endCharCode,startGlyphID); glyph = startGlyphID + (c-startCharCode). Format 6: firstCode+entryCount; glyphIdArray[c-firstCode]. All offset arithmetic adds offset to the cmap table base; verify offset+record_size ≤ subtable.len().

GDEF: header version 1.0/1.2/1.3; offsets to GlyphClassDef, AttachList, LigCaretList, MarkAttachClassDef, MarkGlyphSetsTable. GlyphClassDef: ClassDef format 1 (startGlyph+array) or 2 (ranges), maps glyph_id→class; GlyphClass{Base=1,Ligature=2,Mark=3,Component=4,Unclassified=0}. MarkAttachClassDef: same ClassDef format, u8 result. MarkGlyphSetsTable (v1.3): coverage array; mark_glyph_set_contains(set_index, glyph_id) -> bool via Coverage format 1/2.

Bytes cursor: wraps &'a [u8] + usize position; read_u16() checks pos+2 ≤ data.len(), reads big-endian, advances pos; at(offset) -> Bytes<'a> clones with new pos (original unaffected) — enables sub-table parsing without ownership transfer.

9.1 Objectives

9.2 Detailed Implementation Steps

Theory anchors: Buffer design and cluster semantics are derived from HarfBuzz's shaping model (Esfahbod, freedesktop.org blog; §5.2); cmap char→glyph mapping follows OpenType cmap (§5.4); P7 — clusters are sacred; P10 — determinism; ADR-14 (Buffer SoA design); default-ignorable detection uses is_default_ignorable from UAX #44 sec. 2.6.

buffer.rs: GlyphInfo{glyph_id:u32, cluster:u32, flags:u16}; GlyphPosition{x_advance:i32, y_advance:i32, x_offset:i32, y_offset:i32}; Buffer{infos:Vec<GlyphInfo>, positions:Vec<GlyphPosition>, direction:Direction}. shape.rs: pub fn shape(face: &Face, buf: &mut Buffer, features: &[(Tag,u32)]). Pipeline in order: (1) map_chars — face.cmap.map(c) -> glyph_id (0 if missing), mark default-ignorable via ush_tables::is_default_ignorable(c); (2) set_advances — face.hmtx.advance(glyph_id) -> x_advance (LTR) or y_advance (TTB), scaled to design units; (3) detect_script — scan infos[].cluster chars, call ush_tables::script(c) for dominant Script tag; (4) select_shaper — match Script → ShaperLatin|ShaperArabic|ShaperIndic|ShaperGeneral; (5) collect_features — shaper.collect_features(&face, script, lang, user_features) -> ordered Vec<(Tag,u32)>; (6) setup_masks — shaper.setup_masks(&mut buf, ...) sets GlyphInfo::flags mask bits per feature; (7) shaper.reorder — pre-GSUB reorder (Indic only; no-op for General/Latin/Arabic here); (8) GSUB (Phase 10); (9) GPOS (Phase 11); (10) remove_default_ignorables — delete glyphs flagged GLYPH_IS_DEFAULT_IGNORABLE with glyph_id 0, compact infos+positions. RTL direction: reverse infos after step 1 (cluster values become descending), unreverse after GSUB/GPOS for logical→visual output.

shapers/general.rs: ShaperGeneral implements Shaper — collect_features enables ccmp, locl, rlig, calt, clig, liga, kern, dist, mark, mkmk; setup_masks is a no-op (masks already set by default); reorder is a no-op (no script-specific reorder for general shaper). face.rs additions: Face::cmap_map(c) -> Option<u32> dispatches to parsed Cmap (Phase 8); Face::h_advance(glyph_id) -> i32 looks up hmtx, returns 0 for out-of-range (never panics); Face::units_per_em() -> u16 reads head.

10.1 Objectives

10.2 Detailed Implementation Steps

Theory anchors: ScriptList/FeatureList/LookupList indirection chain is normative in the OpenType Specification's GSUB table (§5.4); cluster-merge-on-ligation and feature-plan ordering come from HarfBuzz architectural overview (Esfahbod; §5.2); mark-skipping cursor using GDEF glyph classes follows OpenType LookupFlag; ADR-16 (direct match dispatch); P7 — clusters are sacred.

Parsing: Gsub<'a>{data:&'a [u8], script_list:ScriptList, feature_list:FeatureList, lookup_list:LookupList}; Coverage<'a> (format 1: sorted GlyphIDs; format 2: ranges), Coverage::get(glyph_id) -> Option<u16>; ClassDef<'a> (format 1: start_glyph+array; format 2: ranges+class), ClassDef::class(glyph_id) -> u16 (0=not covered). LookupList -> Vec<Lookup>; Lookup{lookup_type:u16, flag:u16, subtables:Vec<SubtableOffset>}, parsed lazily (subtables parsed on first apply() to avoid upfront allocation for unused lookups).

Lookup type dispatch: 1 Single (formats 1 delta, 2 array); 2 Multiple (format 1); 3 Alternate (format 1); 4 Ligature (format 1); 5 Context (formats 1 glyph, 2 class, 3 coverage); 6 Chaining Context (formats 1/2/3); 7 Extension (redirect — dereference the inner lookup type and re-dispatch, not a separate impl); 8 Reverse (deferred).

Apply loop: fn apply_gsub(face: &Face, buf: &mut Buffer, plan: &ShapePlan) iterates plan.features ordered by LookupList index; for each feature tag, resolves lookup_indices via ScriptList/FeatureList and calls apply_lookup(face, buf, idx, value) per index. apply_lookup iterates buffer positions with a cursor; on match, mutates in place or splices (type 2/4); advances cursor past consumed glyphs.

Cluster rules: type 4 Ligature — buf.merge_clusters(start, start+component_count-1) → all components get min(cluster[start..]); type 2 Multiple — buf.split_cluster(pos, replacement_count) → inserted glyphs keep the original cluster value (all map to same input codepoint); type 3 Alternate — single replacement, no cluster change; type 5/6 Context — applies the nested lookup, cluster changes delegated to it.

Feature ordering invariant: collect all (lookup_index, feature_tag) pairs, sort by lookup_index ascending, dedup, apply in that order — HarfBuzz calls this "feature plan ordering."

RTL buffer handling: buffer already reversed before GSUB (Phase 9); ligature matching scans in reversed direction; chaining-context backtrack/lookahead swap roles for RTL (backtrack is to the right in logical order but left in buffer). Lookup::flag & RIGHT_TO_LEFT matters for cursive attachment (GPOS), not GSUB lookup direction.

11.1 Objectives

  • Accumulate into GlyphPosition: x_advance, y_advance, x_offset, y_offset (additive; multiple lookups sum).

11.2 Detailed Implementation Steps

Theory anchors: ValueRecord format-driven field presence is normative in the OpenType Specification's GPOS table (§5.4); mark-to-base anchor resolution derives from GPOS type 4; pair-kerning class-matrix structure is GPOS type 2 format 2; accumulation into GlyphPosition follows HarfBuzz's GPOS accumulation model (Esfahbod; §5.2); ADR-16 (dispatch); P6 — never trust a font (bounds-checking ValueFormat).

Parsing: Gpos<'a>{data:&'a [u8], script_list:ScriptList, feature_list:FeatureList, lookup_list:LookupList}; ValueRecord{x_placement:i16, y_placement:i16, x_advance:i16, y_advance:i16, ..} (device offsets present only if format bits set); Anchor{x:i16, y:i16} (format 1; format 2 adds contour point; format 3 adds Device); Device<'a> (delta array: start/end ppem + delta_format + delta_values). ValueRecord format is a 16-bit ValueFormat bitmask; only present fields are serialized — the parser reads exactly the fields the bitmask indicates, critical to avoid offset corruption.

Lookup type implementations: 1 Single Adjust — apply ValueRecord to every glyph in Coverage (format 1 = same VR for all, format 2 = per-glyph array); 2 Pair Adjust — format 1 sorted PairSets by first glyph with binary-search on second, format 2 ClassDef1×ClassDef2 matrix with O(1) class lookup; 3 Cursive Attach — EntryAnchor/ExitAnchor connect exit of glyph[i] to entry of glyph[i+1], affecting the x/y offset chain; 4 Mark-to-Base — MarkArray (mark anchor + class) + BaseArray (anchor per class per base glyph), base = last non-mark before mark; 5 Mark-to-Ligature — LigatureArray → per-component anchors, component index from GlyphInfo::lig_component; 6 Mark-to-Mark — same as type 4 but base is another mark glyph (lookup_flag & IGNORE_BASE_GLYPHS governs); 7/8 Context/Chaining — same structure as GSUB 5/6, applying nested GPOS lookups at matched positions.

Anchor resolution: fn resolve_anchor(anchor: Anchor, glyph_id: u32, face: &Face) -> (i32, i32) — format 2 snaps to a contour point (requires glyf table, deferred to Phase 12 if needed); format 3 adds the Device delta for the current ppem (deferred if no ppem available). Phase 11 implements only format 1 (static x/y); format 2 contour snapping and format 3 device deltas are todo!() behind a compile-time feature flag gpos_advanced_anchors (off by default).

Accumulation into GlyphPosition: fn apply_value_record(pos: &mut GlyphPosition, vr: &ValueRecord, dir: Direction) accumulates additively, once per matching lookup per glyph — x_placement→x_offset (lateral shift from nominal pen position), y_placement→y_offset (vertical shift), x_advance→x_advance (kern delta, adjusts pen advance not visual offset), y_advance→y_advance (vertical advance delta, TTB only). Mark placement (types 4–6): x_offset = base_anchor.x - mark_anchor.x + base_pos.x_offset, y_offset = base_anchor.y - mark_anchor.y + base_pos.y_offset; never change x_advance for marks (zero advance by convention).

apply_gpos loop (called after apply_gsub in shape()): fn apply_gpos(face: &Face, buf: &mut Buffer, plan: &ShapePlan) — ensure_positions(), then iterates plan.features ordered by LookupList index, resolving lookup_indices per feature tag and calling apply_gpos_lookup(face, buf, idx). Mark-skipping cursor is the same machinery as GSUB — honors lookup_flag bits (IGNORE_BASE_GLYPHS, IGNORE_LIGATURES, IGNORE_MARKS, USE_MARK_FILTERING_SET) using GDEF glyph classes.

Threat Catalogue

T1 — Malformed / adversarial font (CRITICAL)

  • Vectors: bad sfnt table-directory offset, Coverage table with out-of-bounds glyph IDs, ClassDef with runaway ranges, LookupList offset cycle, subtable length underflow.
  • Mitigation: every Face::new() and subtable accessor validates: offset + length <= font.len() before any slice; coverage/classdef arrays capped at maxp.numGlyphs; no raw pointer arithmetic — slice indexing only.
  • Detection: Face::new() returns Err(ParseError) on first violation; all shape/GSUB/GPOS table accessors return Option/Result — no panic path.
  • Recovery: return .notdef (glyph ID 0) for any glyph that cannot be resolved; caller receives a ShapeError::FontParse variant with table tag + byte offset.
  • Recursion guard: GSUB lookup invocation depth capped at 8; loop detected = lookup skipped, error logged via hook.

T2 — Algorithmic-complexity DoS via GSUB/GPOS contextual chains

  • Vector: contextual/chaining-contextual lookup (types 5/6/7/8) with artificially large BacktrackSequence + LookaheadSequence; nested lookup references forming a fan-out tree.
  • Mitigation: lookup-application iteration cap per-buffer = 16 * buffer.len() total substitution steps; chaining context recursion depth capped at 8; GPOS value-record application capped at 4 * buffer.len().
  • Detection: cap hit → ShapeError::LookupOverflow; stage-latency hook fires if per-buffer shaping exceeds 10 ms.

T3 — Bidi nesting / stack overflow

  • Vector: deeply nested LRE/RLE/LRI/RLI push sequences; adversarial FSI in mixed text.
  • Mitigation: UAX #9 mandates max embedding depth 125; DirectionalStatusStack enforces this; overflows silently ignored per spec (entries beyond cap are treated as BN). Stack is a fixed-size array (125 entries × 8 bytes = 1 KB), not heap-recursive.
  • Detection: BidiInfo carries overflow_isolate_count + overflow_embedding_count fields for telemetry.

T4 — Memory blowup via combining-mark accumulation / huge decomposition

  • Vector: input string with thousands of combining marks (ccc > 0) between starters — forces O(n²) canonical ordering; or a pathological compatibility decomposition chain.
  • Mitigation: stream-safe normalization inserts CGJ (U+034F) after every run of 30 non-starter combining marks; decomposition recursion depth capped at 32 levels; decomposition output buffer pre-reserved but capped at 4 * input.len().
  • Detection: CGJ insertion count exposed as a metric; decomposition depth overflow → NormError::DecompDepth.

T5 — Panic-as-DoS on unexpected scalar values

  • Vector: unassigned code points, noncharacters (U+FDD0..U+FDEF, U+FFFE/FFFF, plane-end), PUA.
  • Mitigation: all property accessors (bidi_class, combining_class, grapheme_break, etc.) are total functions — unknown code points return a defined default (BidiClass::ON, ccc=0, GraphemeBreak::Other). No unwrap() / expect() on property lookups in any public path. Enforced by CI fuzzing.
  • Detection: #[deny(clippy::unwrap_used)] in ush-tables, ush-normalize, ush-segment, ush-bidi.

T6 — Cluster-map corruption enabling wrong hit-testing / cursor placement

  • Vector: GSUB ligature merge or multiple-substitution split that corrupts the monotonic cluster index — downstream #385 hit-testing returns wrong cursor positions.
  • Mitigation: Buffer enforces monotonic-cluster invariant after every GSUB lookup application: RTL buffers non-increasing, LTR non-decreasing. Assertion runs in debug builds; checked post-shape in release via a dedicated Buffer::verify_clusters() call before returning.
  • Detection: ShapeError::ClusterInvariantViolated surfaced; Buffer::verify_clusters() O(n) scan.

T7 — Confusables / visual-spoofing

  • Scope: OUT OF SCOPE for ush to mitigate (no identifier-security layer here). Documented as a downstream concern — callers performing security-sensitive rendering (URLs, usernames) MUST apply Unicode confusable detection (UTS #39) independently.
  • Note: NFC normalization does reduce some homoglyph surface area (e.g., precomposed vs decomposed forms collapse), but this is not a security guarantee.

T8 — Supply-chain: UCD table provenance

  • Vector: tampered UnicodeData.txt or auxiliary files during table generation.
  • Mitigation: deny.toml (cargo-deny) restricts dependency graph; UCD files fetched from unicode.org with SHA-256 pinned in tools/ucd/checksums.sha256; generated ush-tables/src/generated/ committed with a UCD_VERSION constant checked at crate init.
  • Detection: CI verifies sha256sum -c checksums.sha256 before any cargo build.

T9 — Unicode-version skew (tables vs runtime expectation)

  • Vector: ush-tables built against Unicode 15.1 but linked into a binary expecting 16.0 data.
  • Mitigation: ush_tables::UCD_VERSION: &str = "15.1.0" exported constant; ush-normalize/ush-bidi assert ush_tables::UCD_VERSION == their EXPECTED_UCD_VERSION at init (debug_assert in no_std, explicit check in ush-cli startup).
  • Detection: version mismatch → InitError::UcdVersionMismatch { found, expected }.

FM-1: Normalization Divergence (CRITICAL)

  • Symptoms: Output of normalize(Nfc/Nfd, s) differs from NormalizationTest.txt column 1–5.
  • Root causes: (a) wrong recursion order in canonical decomposition (subtraction formula error for Hangul); (b) ccc sort instability — stable sort required; (c) composition exclusion set wrong (singletons, non-starter decompositions, pre-composed exceptions); (d) "blocked" check error (intervening starter not detected).
  • Detection: NormalizationTest.txt harness in Phase 13; each test line exercises all five forms. CI fails on first divergence.
  • Auto-recovery: None — normalization is deterministic; wrong output is wrong.
  • Debug methodology: Stage-diff pipeline: (1) dump decomposed+ordered sequence char-by-char with ccc; (2) compare to expected; (3) isolate at the composition step by disabling compose and checking NF*D first; (4) for Hangul, test SBase/LBase/VBase/TBase arithmetic independently.
  • Forensic artifacts: failing NormalizationTest line number, input scalar, expected output form, actual output form, intermediate decomposed sequence.
  • Long-term mitigation: Pin UCD version; re-run NormalizationTest.txt on every Unicode upgrade; property-test normalize(Nfc, normalize(Nfd, s)) == normalize(Nfc, s) idempotence.

FM-2: Bidi Reorder Mismatch (CRITICAL)

  • Symptoms: reorder_line() output differs from BidiTest.txt or BidiCharacterTest.txt visual order.
  • Root causes: (a) X-rule DirectionalStatusStack push/pop logic (isolate vs embedding confusion); (b) isolating-run-sequence formation — wrong sos/eos assignment; (c) W-rule iteration order; (d) N0 bracket pairing (wrong stack or wrong strong-type scan direction); (e) L2 level-run reversal applied to wrong range.
  • Detection: BidiTest.txt (level + order columns); BidiCharacterTest.txt (explicit-bidi characters).
  • Debug methodology: Dump per-character: (code point, bidi_class, embedding level after X, after W, after N, after I); compare stage-by-stage against expected levels; narrow to the first character that diverges.
  • Forensic artifacts: paragraph text, base level, level array at each stage, isolating run sequence boundaries, bracket-pair log.
  • Long-term mitigation: Differential test vs unicode-bidi crate on the same input.

FM-3: GSUB/GPOS Misapplication (HIGH)

  • Symptoms: Wrong glyph sequence vs HarfBuzz reference (missing ligature, wrong form, extra substitution); wrong advance/offset vs HarfBuzz GPOS output.
  • Root causes: (a) wrong feature ordering (user features vs required vs default); (b) LookupFlag skip logic (mark class skipping wrong glyphs); (c) chaining-contextual backtrack/lookahead direction (RTL buffers reverse the match direction); (d) GPOS pair-lookup class vs glyph format confusion; (e) anchor coordinate parsing (format 2 contour-point vs format 1 XY).
  • Detection: HarfBuzz shaping fixtures in Phase 13; diff on (glyph_id[], cluster[], x_advance[]) arrays.
  • Debug methodology: Enable lookup-trace hook; diff ush vs HarfBuzz lookup-by-lookup; isolate to a single lookup type by disabling others via feature flags.
  • Forensic artifacts: Buffer state at each lookup application (glyph_id + cluster + flags), lookup index + type + subtable index, match result.

FM-4: Font Parse Error / Truncated Table (HIGH)

  • Symptoms: Face::new() returns Err(ParseError); shape returns no glyphs.
  • Root causes: Truncated font file; corrupt sfnt directory; unsupported cmap format.
  • Detection: ParseError { table: Tag, offset: usize, reason: &'static str } propagated to caller.
  • Auto-recovery: Shape with .notdef for all glyphs; caller receives error + full glyph-id-0 Buffer.
  • Manual recovery: Validate font file integrity; check cmap format support matrix.

FM-5: cmap Miss → Tofu (LOW / HIGH if systematic)

  • Symptoms: GlyphInfo.glyph_id == 0 (.notdef) for code points that should be in the font.
  • Root causes: (a) cmap format 4/12 parsing bug (segment boundary off-by-one); (b) font only covers BMP but input is supplementary (need format 12); (c) wrong platform/encoding-ID selected.
  • Detection: tofu-rate metric; Buffer::notdef_count() after shape.
  • Debug: Dump cmap segment table; compare expected vs resolved glyph ID per code point.

FM-6: Cluster-Map Desync (HIGH)

  • Symptoms: Hit-testing / cursor placement wrong after ligature or multiple substitution.
  • Root causes: Cluster merge on ligation not propagating min cluster value to all output glyphs; split on multiple-subst not assigning correct source cluster.
  • Detection: Buffer::verify_clusters() O(n) monotonicity check post-shape.
  • Recovery: ShapeError::ClusterInvariantViolated returned; caller falls back to character-offset = glyph-index mapping.

FM-7: Mark-Positioning Drift (MEDIUM)

  • Symptoms: Diacritics misaligned on base glyphs; visible on complex scripts with multiple marks.
  • Root causes: GPOS mark-to-base anchor format 2 (contour point) not resolved; device-table corrections ignored; mark-filtering (LookupFlag MarkAttachType) skipping wrong glyphs.
  • Detection: Visual regression fixtures; GPOS anchor dump vs HarfBuzz.
  • Long-term mitigation: Automated pixel-diff vs HarfBuzz+FreeType reference renders (Phase 13 optional).

FM-8: Wrong Script Detection (MEDIUM)

  • Symptoms: ShaperArabic or ShaperIndic not invoked for the correct run; wrong OpenType script tag selected.
  • Root causes: Script property lookup returning wrong value; script-tag mapping table missing an entry; mixed-script run splitting not isolating Arabic/Indic characters.
  • Debug: Dump (char, Script, Tag) per-run pre-shaping; compare to expected script-tag selection.

FM-9: Table-Version Skew (LOW)

  • Symptoms: InitError::UcdVersionMismatch at startup; properties inconsistent with expected Unicode version behavior.
  • Recovery: Rebuild ush-tables with the correct UCD version; bump UCD_VERSION.

Incident Runbooks

"Tofu boxes appear" (glyph_id = 0):

  1. Check StageMetrics.notdef_count / font_parse_errors.
  2. If font_parse_errors > 0: inspect ParseError.table + .offset; validate font file.
  3. If font_parse_errors == 0: dump cmap segments for affected code points; confirm format 12 for supplementary chars; verify platform/encoding-ID selection.

"Wrong cursor position after click":

  1. Call Buffer::verify_clusters() — if fails, cluster-map desync (FM-6).
  2. Dump (glyph_id, cluster) pairs; trace GSUB ligature merges; verify min-cluster propagation.

"RTL text rendered LTR / wrong visual order":

  1. Enable on_bidi_levels hook; dump level array.
  2. Compare against BidiCharacterTest expected levels.
  3. Check DirectionalStatusStack overflow flags in BidiInfo.
  4. Verify buffer Direction passed to shape() matches paragraph level parity.

"Ligature not forming":

  1. Enable on_gsub_lookup trace; confirm liga feature active for script/langsys.
  2. Check lookup type (must be 4-ligature); verify component glyph IDs match Coverage.
  3. Check LookupFlag — mark-skip may be consuming a glyph that should be skipped.

"Arabic joining wrong (isol instead of medi)":

  1. Dump joining-type per glyph pre-shaper.
  2. Verify ShaperArabic joining state machine transitions.
  3. Check init/medi/fina/isol feature application order.

Hot Paths and Cache Behavior

CodePointTrie lookup (combining_class, bidi_class, etc.):

  • Two-stage: index array (~4 KB, L1-resident) + data array (~128 KB, L2); one multiply + two indexed loads per lookup.
  • Keep index and data in separate static arrays so link order places them adjacently; 64-byte cache-line alignment.

Normalization combining-run sort (canonical_order):

  • Stable sort over a Vec<(char, u8)> run; typical run ≤ 4 elements → insertion sort faster than slice::sort_stable; switch at run-length = 8.
  • Avoid allocation: accumulate runs in a stack buffer [( char, u8); 32] (stream-safe cap = 30 + slack).

Rule-machine inner loops (segment/bidi):

  • State machine encoded as [u8; N×M] jump tables; inner loop is table[state][class] → new state, no branches.
  • Bidi W/N rules: operate on a single Vec<BidiClass> pass; avoid per-char allocation.

Coverage binary search (GSUB/GPOS):

  • Coverage::get(glyph_id) → u16 index; backed by sorted &[(u16,u16,u16)] range array; partition_point binary search; hot Coverage tables ≤ 200 ranges → fits a cache line.
  • Format-1 (individual glyphs) uses direct slice binary search; format-2 (ranges) uses the range table.

Buffer operations (ush-shape):

  • Buffer::infos + Buffer::positions are Vecs pre-allocated to estimated glyph count (= char count × 1.2 for shaping headroom).
  • Reuse Buffer across repeated shape() calls by buf.clear() without shrink_to_fit.

Quick-Check Fast Path

  • quick_check(Nfc, s) returns Yes for ≥ 95 % of real-world Latin text → zero decomposition/composition work.
  • Implementation: scan code points; if any has NFC_QC ≠ Yes → return Maybe/No; else Yes.
  • Normalization driver: find the first non-Yes position, copy-before unchanged, then run the full algorithm only on the tail. This yields the 400+ MB/s target for pre-composed input.

Profiling

  • perf record -g + cargo flamegraph on normalize + shape macrobench; annotate hot loops.
  • perf stat -e cache-misses,cache-references on trie lookups; target: < 2 % L1 miss rate for Latin text.
  • valgrind --tool=cachegrind for GSUB Coverage search miss pattern on complex-script fonts.
  • GPOS mark lookup hot path: mark-to-base resolves anchor per base glyph; cache base_anchor by (glyph_id, mark_class) in a small HashMap if the same base appears > 3× in a run.

Allocation Analysis

  • Per-call allocations bounded: normalize allocates one String (output); process_paragraph allocates Vec<Level> + Vec<BidiClass> of len = char count; shape re-uses caller-provided Buffer.
  • DirectionalStatusStack is a fixed-capacity stack [StackEntry; 128] on the call stack — no heap.
  • Stream-safe normalization buffer: [( char, u8); 32] on stack, spills to heap only if run > 30 marks (stream-safe cap; invariant prevents this in conforming text).

Tail Latency: Mark-Heavy / Complex-Script Text

  • Mark-heavy Arabic: many mark-to-base GPOS lookups; anchor table reads are random-access into font bytes; mitigate with a SmallVec<[AnchorPoint; 8]> per mark class pre-parsed at Face::new().
  • Indic reordering (ShaperIndic): O(syllable length) per syllable; syllable ≤ 15 code points → bounded; worst case is pathological virama stacks in malformed text (capped by syllable-parse depth limit = 20).
  • Very long combining runs: stream-safe cap at 30 ensures sort step O(1) bounded per run.

Scaling with Text Length

Mental Models & First Principles

MM1. A Unicode code point is not a character; a grapheme cluster is. Expert insight: "character" is ambiguous; the spec defines scalar value, grapheme cluster, word, and paragraph as distinct layers. Predicts: correct cursor-movement and selection logic requires grapheme-cluster boundaries, not code-point boundaries. Bug class without it: splitting a ZWJ emoji sequence when the user presses Backspace once. Resolving sections: Phase 4 (GraphemeCursor), §8.1 (Character Model).

MM2. Normalization is a canonical-equivalence relation, not a canonical form. Expert insight: NFC and NFD both express the same canonical-equivalence class; the form only determines which representative is chosen. Predicts: NFD(NFC(x)) == NFD(x) always holds; this is the test for correct NFC implementation. Bug class without it: treating NFC as "the one right form" and skipping the idempotence test, then shipping a non-idempotent normalizer. Resolving sections: Phase 2 (INV-1, INV-3), §2.2 Canonical Composition.

MM3. Canonical ordering is not sort-by-ccc; it is stable-sort-within-runs-bounded-by-starters. Expert insight: ccc==0 starters divide the string into independent segments; the sort does not cross segment boundaries. Predicts: a character with ccc==0 is an absolute boundary even if surrounded by high-ccc marks. Bug class without it: a global sort-by-ccc incorrectly reorders marks across a starter, breaking canonical equivalence. Resolving sections: Phase 2.2 (canonical_order), §8.2.2.

MM4. The bidi algorithm is a level-assignment problem, not a reversal problem. Expert insight: X through I rules produce a level per character; L2 reorder is only one final pass that reverses maximal level runs. The complexity is in level assignment, not the reversal itself. Predicts: most bidi bugs are in W/N/I rules (isolating run sequences, bracket pairing) not in reorder_line. Bug class without it: developers jump to debugging the reorder loop when the actual error is a wrong level from a misapplied W rule. Resolving sections: Phase 6 (X rules), Phase 7 (W/N/I rules), §8.4.

MM5. An OpenType font is a relational database; GSUB/GPOS is the query engine. Expert insight: ScriptList → FeatureList → LookupList is a three-level indirection (the "OT lookup chain"). A feature is a named set of lookup indices, not a set of rules. Predicts: feature ordering must be by LookupList index, not by feature-tag alphabetical order. Bug class without it: applying liga before ccmp, which produces wrong glyph sequences for scripts whose precomposed glyphs depend on ccmp running first. Resolving sections: Phase 10 (GSUB apply loop, feature-ordering invariant), §8.5.3.

MM6. The cluster map is the contract between shaping and hit-testing. Expert insight: GlyphInfo.cluster is a monotonic mapping from output glyph back to input byte offset; it must remain monotonic (non-decreasing LTR, non-increasing RTL) through every GSUB transformation. Predicts: any ligature or decomposition that does not update clusters correctly breaks cursor placement for every downstream consumer. Bug class without it: hit-testing returns a wrong caret position after a ligature; the user cannot click between "f" and "i" in an "fi" ligature correctly. Resolving sections: Phase 9–10 (cluster merge/split), INV-8, §8.5.6.

MM7. Quick-check is a proven span-skip, not a heuristic. Expert insight: the NFC_QC / NFD_QC properties are derived from the normalization algorithm itself — a span with all-Yes properties is mathematically guaranteed to be already normalized. Predicts: on typical ASCII/Latin text, >90% of the input is QC=Yes and the full decompose+recompose pipeline is never invoked. Bug class without it: implementing quick-check as a heuristic (e.g., checking only ASCII range) that admits false positives, silently skipping strings that need normalization. Resolving sections: Phase 3 (QuickCheck), §4 throughput targets for NFC fast path.

MM8. Font bytes are adversarial input; every offset is a potential exploit. Expert insight: a font file is a structured binary from an external source; every offset + length expression must be validated against the backing &[u8] before dereference. Rust slice indexing panics on OOB in debug, returns None with .get() — choose .get(). Predicts: a fuzz run against any font parser that uses [] instead of .get() will produce panics within minutes. Bug class without it: memory-safety violations (pre-Rust) or panics that become a denial-of-service vector in a server-side font renderer. Resolving sections: Phase 8 (Bytes cursor), P6, Threat Model T1.

MM9. Isolates change bidi from a paragraph property to a scoped property. Expert insight: before Unicode 6.3 isolates (LRI/RLI/FSI/PDI), the only way to embed a bidirectional run was with explicit overrides (LRE/RLE), which "leaked" directionality to adjacent content. Isolates create a hard scope — W/N rules cannot cross isolate boundaries. Predicts: any bidi implementation that treats LRI/RLI/FSI as equivalent to LRE/RLE will produce wrong neutral/bracket resolution for strings with embedded opposite-direction spans. Bug class without it: Arabic name inside a URL inside an English sentence has corrupted punctuation placement. Resolving sections: Phase 6 (IsolateMap), Phase 7 (isolating run sequence construction), §8.4.3.

MM10. Hangul is arithmetic, not a table. Expert insight: Hangul syllable decomposition and composition are entirely defined by six integer constants (SBase, LBase, VBase, TBase, L/V/T counts); no table lookup is ever needed. Predicts: any normalization engine that puts Hangul in the decomposition table has made an unnecessary space trade-off, and will fail to compose newly allocated syllables if the UCD table is ever regenerated without covering them. Bug class without it: off-by-one on TBase (T_BASE+0 is a sentinel, not a real T jamo) produces wrong decomposition for syllables with T index 0. Resolving sections: Phase 2 (hangul.rs), §8.2.1.

HarfBuzz made the decision to be a single-purpose shaping engine with no normalization or bidi, delegating those to ICU or FriBidi at the caller's discretion. This wins for browser engines (Chromium, Firefox) that already have ICU linked and want to use a best-in-class shaper without pulling in another normalization stack. HarfBuzz's shape-plan caching amortizes GSUB/GPOS feature resolution across thousands of calls — a win for web rendering that shapes the same script/font/features constantly.

ICU4C made the decision to be a comprehensive i18n library covering not just text shaping but collation, number formatting, locale handling, and calendar systems. Its UCPTrie is a 3-level structure trading slightly higher lookup cost for an even smaller footprint than a 2-stage trie. ICU wins for Java/.NET applications and OS-level text processing where a single integrated library is preferred over composing several. CoreText is tightly integrated with macOS/iOS rendering stack, providing GPU-accelerated text layout as a system service. It wins for native macOS/iOS applications because it uses the OS font cache, supports all system fonts including variable fonts, and offloads rendering to Core Animation. The trade-off: it is opaque, proprietary, platform-locked, and cannot be used on Linux or embedded targets.

Pango + FriBidi is the GNOME/GTK text stack; it uses HarfBuzz for shaping, FriBidi for bidi (a standalone C implementation of UAX #9), and FreeType for rendering. Pango wins for GTK applications on Linux because it integrates with Fontconfig for font discovery and supports the Pango markup language for rich text. The trade-off is a large dependency chain (GLib, HarfBuzz, FriBidi, FreeType) and no embedded/WASM support.

Back-of-Envelope Capacity Model

All values derived from System Constraints table (§4).

C1. CodePointTrie total static data. Formula: (index_entries × 2 B) + (data_entries × 4 B). BMP index: 65536 / 64 = 1024 blocks × 2 B = 2 KB. With dedup: ~600 unique blocks × 64 entries × 4 B = 154 KB data. Supplementary planes add ~50 unique blocks. Total per property ≈ 2 KB index + 160 KB data ≈ 162 KB. Eight properties at 162 KB each would be 1.3 MB; deduplication across properties (shared index) brings this to ≤ 300 KB (§4 UCD table constraint = < 2 MB; target ≈ 1 MB). Result: ≈ 300 KB static — consistent with §4.

C2. Normalization decomposition table size. Formula: entries × avg_entry_size. ~940 BMP canonical decomps + ~2300 compat decomps = ~3240 entries × 12 B/entry (cp u32 + 2 chars u32 each) = ~39 KB. Plus multi-char ext slice: ~200 entries × 3 chars × 4 B = 2.4 KB. Total: ~42 KB for decomp tables. Result: ≈ 42 KB — well inside the 300 KB target.

C3. Composition table size. Formula: composites × 12 B (starter u32 + combining u32 + composite u32). ~930 primary composites × 12 B = ~11 KB. Binary search over 930 entries = ~10 comparisons. Result: ≈ 11 KB — negligible.

C4. Per-call normalize working set. Formula: max(output_len) = 3 × input_len (worst-case compat decomposition, e.g., one CJK = three code points). For 1 KB input: max output = 3 KB. Vec pre-allocated at input.len() + 20% = 1.2 KB; realloc needed for compat expansion. Result: O(n) — ≤ 3× input size per call, consistent with §4.

C5. BidiInfo working set per call. Formula: char_count × (1 B level + 1 B class) = 2 × char_count bytes. For 1 KB UTF-8 paragraph (~500 chars avg): 500 × 2 B = 1 KB. DirectionalStatusStack: 128 entries × 8 B/entry = 1 KB stack. Total: ~2 KB per call. Result: ≈ 2 KB — O(n) as stated in §4.

C6. Buffer working set per shape call. Formula: glyph_count × (GlyphInfo 8 B + GlyphPosition 16 B) = 24 B/glyph. For 1 KB paragraph (~200 glyphs after shaping): 200 × 24 B = 4.8 KB. Pre-allocated at 1.2 × char_count: 1.2 × 500 = 600 entries × 24 B = 14.4 KB. Result: ≈ 14 KB — O(g) as stated in §4.

C7. GSUB feature lookup throughput. Formula: features_applied × avg_lookups_per_feature × coverage_binary_search_cost. Typical Latin: 10 features × 3 lookups × log₂(200 coverage entries) ≈ 10 × 3 × 8 = 240 comparisons per glyph. At 1 ns/comparison: 240 ns/glyph → ~4M glyphs/s limit from coverage search alone. Actual target: ≥ 100k glyphs/s from §4, so the budget is comfortable. Result: coverage search is not the bottleneck for ≤ 30 features; confirmed.

C8. Normalize NFC fast-path throughput. Formula: throughput = chars / (QC_lookup_ns × chars) for all-NFC input. QC lookup = 2 array reads ≈ 5 ns. 1 MB ASCII = 1M chars × 5 ns = 5 ms → 200 MB/s. §4 target is ≥ 400 MB/s → requires batch-scanning or SIMD to reach; achievable by checking 8 chars per iteration with a vectorized QC scan. Result: 200–400 MB/s — matches §4 Performance targets.

C9. cmap format-4 lookup latency. Formula: binary_search(segments) × cache_miss_cost. Typical font: ~100 BMP segments × 4 arrays = ~3.2 KB data. Fits in L1 cache (32 KB). Binary search: log₂(100) ≈ 7 steps × 2 ns/step = 14 ns. Result: ≈ 14 ns — consistent with §8.7 < 50 ns target.

C10. HarfBuzz fixture corpus size (Phase 13). Formula: entries × (text_bytes + glyph_array_bytes). 200 fixture entries × (50 B text + 50 glyphs × 12 B/glyph) = 200 × 650 B = 130 KB binary. Result: ≈ 130 KB — small enough to commit to repository.

C11. Fuzz corpus iteration rate. Formula: libfuzzer_rate × 60s. Typical libFuzzer rate on font parser: ~10k iterations/s × 60 s = 600k inputs per CI run. For fuzz_normalize (no file I/O): ~100k iterations/s × 60 s = 6M inputs. Result: 600k–6M inputs per CI run — sufficient for surface coverage.

C12. Conformance test suite wall time. Formula: test_lines × normalize_calls × normalize_time. 17,808 NormalizationTest.txt lines × 5 forms × 1 µs/call (release) = 89 ms. BidiTest.txt: 77k lines × 2 µs/call = 154 ms. Total suite: < 500 ms in release mode. Result: < 1 s — CI-feasible without special flags.

Alternative Architectures (Roads Not Taken)

Alt-1: Monolithic C Library with ICU/FriBidi/HarfBuzz linkage

+-----------------+     +-----------+     +----------+     +----------+
| ICU normalizer  | --> | FriBidi   | --> | HarfBuzz | --> | Buffer   |
| (ubidi + norm2) |     | (UAX #9)  |     | (shaping)|     | (output) |
+-----------------+     +-----------+     +----------+     +----------+
         ^                                      ^
         |                                      |
    UCD data blob                        font bytes (libfreetype)

Regime where it wins: When shipping a production browser engine or desktop application that already links ICU (for locale/collation/number formatting) and HarfBuzz (already used by GTK/Qt). The engineering investment in the component pipeline is already paid; adding ush as a competing implementation is wasteful. Pango on Linux and QTextLayout on Qt are real systems embodying this architecture.

Why this blueprint rejected it: The project's explicit goal is to learn the algorithms. Linking established libraries produces correct output but zero understanding of how it works. Additionally, no_std is incompatible with ICU/FriBidi/HarfBuzz (all require a POSIX environment), ruling out embedded/WASM targets.

Alt-2: Virtual-Machine Bytecode Interpreter (RBBI-style)

+---------------+     +-----------+     +-----------+
| Rule grammar  | --> | Bytecode  | --> | VM eval   |
| (RBBI format) |     | compiler  |     | per char  |
+---------------+     +-----------+     +-----------+
                           |
                     committed byte
                     code (icu .dat)

Regime where it wins: When break rules must be updated at runtime without recompiling the library — e.g., a deployment model where Unicode version bumps must ship as data-only patches (no binary recompile). ICU's RBBI engine embodies this: icu.dat contains compiled break-rule bytecode, and upgrading to Unicode 16.0 is a data-file swap, not a code change. This is critical for OS-level libraries (libICU on Android) updated through the OS image.

Why this blueprint rejected it: RBBI bytecode compilation is a non-trivial sub-project (lexer + parser + peephole optimizer). For the scope defined in §1 — a library with a pinned Unicode version (ADR-04) — the bytecode indirection adds complexity without benefit. Our generated pair tables (lb_table.rs) achieve the same data-driven result with simpler machinery and significantly faster interpreter throughput (table lookup vs bytecode dispatch).

Alt-3: Push-Down Transducer for Normalization

+---------------+     +-----------+     +-----------+
| Input stream  | --> | PDT rules | --> | Output    |
| char-by-char  |     | (NFD/NFC) |     | stream    |
+---------------+     +-----------+     +-----------+

Regime where it wins: For streaming normalization where output must be emitted character-by-character with minimal latency (e.g., a real-time chat application normalizing keystrokes before display). A push-down transducer can emit normalized output as soon as a starter is consumed, without buffering the entire combining-mark run. This architecture is described in the "Streaming Normalization" literature and is the basis for stream-safe text (UTN#27).

Why this blueprint rejected it: PDT normalization requires the stream-safe invariant (30-CC cap) to bound the push-down stack — otherwise correctness is not achievable for unbounded combining-mark runs. We implement stream-safe normalization as an optional IncrementalNormalizer in Phase 3, but the primary API is batch normalization (normalize(form, &str) -> String), which is simpler to test, audit, and prove correct against NormalizationTest.txt.

Alt-4: GPU-Resident Text Shaper

+-------------+     +-----------+     +-----------+     +--------+
| CPU: bidi + | --> | GPU: GSUB | --> | GPU: GPOS | --> | Pixel  |
| normalize   |     | (compute  |     | (compute  |     | output |
+-------------+     | shader)   |     | shader)   |     +--------+
                    +-----------+     +-----------+

Regime where it wins: For a GPU-resident text renderer (e.g., a game engine or a GPU-accelerated terminal emulator like WezTerm or Alacritty's proposed GPU backend) where text shaping is the performance bottleneck and thousands of glyphs must be shaped in parallel. Lookup tables (Coverage, ClassDef) map cleanly to GPU buffer reads; ligature matching can be parallelized across non-overlapping glyph runs. NVIDIA's DLSS text stack uses a variant of this approach.

Why this blueprint rejected it: The GPU shaper requires a fundamentally different programming model (WGSL/GLSL/SPIR-V), eliminates no_std compatibility, and requires the font tables to be uploaded to GPU memory as read-only buffers. The serial Rust pipeline is a prerequisite — GPU shaping requires a correct CPU reference implementation to validate correctness. Building the GPU variant is a future Phase 14+ extension, not the core scope.

Glossary

Term Definition
code point Integer U+0000–U+10FFFF; the atomic unit of the Unicode character model.
scalar value Code point excluding surrogates (U+D800–U+DFFF); Rust char models exactly this.
grapheme cluster Extended grapheme cluster per UAX #29: user-perceived character; may span multiple code points (base + combining marks + ZWJ + ExtPict). GraphemeCursor walks boundaries.
normalization form One of NFC / NFD / NFKC / NFKD (NormForm enum); determines which decomposition and whether to recompose.
canonical decomposition Replace a precomposed code point with its canonical equivalent sequence; applied recursively. Invariant: NFC/NFD round-trip under canonical equivalence.
compatibility decomposition Broader decomposition for formatting/compat variants (e.g. ﬁ → fi, ² → 2); applied in NFKD/NFKC before recomposition.
combining class (ccc) u8 value 0–254 per code point; 0 = "starter" (blocks reordering); non-zero marks sorted stably by ccc within a run between starters. combining_class(c: char) -> u8.
starter Code point with ccc == 0; acts as a hard boundary for the canonical ordering algorithm.
canonical ordering Stable sort of combining marks by ccc within maximal runs between starters; required before NFC composition; canonical_order(buf: &mut Vec<(char, u8)>).
canonical composition Attempt to merge a starter with a following combining char into a primary composite; fails if the pair is blocked or the composite is in the composition exclusion set.
composition exclusion Code points that must not be produced by canonical composition (singletons, non-starters, full composition exclusions from DerivedNormalizationProps.txt).
blocked A combining mark C is blocked from a starter L if any character between L and C has ccc ≥ ccc(C), preventing composition.
Hangul Korean syllables composed algorithmically from jamo: L (leading, base U+1100), V (vowel, U+1161), T (trailing, U+11A7+1..28); SBase U+AC00; LVT = L×(VCount×TCount) + V×TCount + T. No table required.
quick check Per-form NFC_QC / NFD_QC / NFKC_QC / NFKD_QC property → QuickCheck { Yes, No, Maybe }; a "Yes"-only span is already normalized; skip full processing on those spans.
stream-safe Normalization form variant that caps a combining-mark run to 30 non-starters; prevents unbounded lookahead in streaming contexts.
word boundary Position in text where the WB rules (WB1–WB999, UAX #29) determine a word starts or ends; WordCursor walks these; used for selection, search, and tokenization.
line-break opportunity Position where a line may be broken per UAX #14; classified as Mandatory, Allowed, or No; LineBreaker emits these alongside text runs.
mandatory / allowed break Mandatory: must break (e.g. U+000A LF, U+2028 LS). Allowed: may break subject to layout policy.
bidi class Unicode Bidi_Class property (BidiClass enum: L, R, AL, EN, AN, NSM, BN, B, S, WS, ON, plus explicit/isolate codes); drives UAX #9 resolution.
embedding level Level(u8) 0–125; even = LTR, odd = RTL; the X rules assign levels; higher levels nest inside lower.
isolate Bidi directional isolate (LRI/RLI/FSI … PDI); inner content does not affect outer bracket/neutral resolution; handled by DirectionalStatusStack.
directional status stack Stack of (level, override_status, isolate_flag) entries maintained during the X rules; max depth 125 including isolates.
isolating run sequence A maximal sequence of level runs that are connected by isolate initiators; W/N/I rules apply per sequence, not per raw level run.
weak resolution W1–W7 rules: transform EN/AN/NSM/ET/ES/CS/ON in context to reduce ambiguity before neutral resolution.
neutral resolution N0–N2 rules: assign a direction to ON/WS/BN sequences based on surrounding strong types and bracket pairing.
implicit resolution I1/I2 rules: bump odd-level chars from L/AN/EN and even-level chars from R/AL/AN to the next embedding level.
reordering L2 rule: reverse maximal level-runs from highest level downward to produce visual order; reorder_line returns a Vec<usize> of visual-order indices.
mirroring L4 rule: substitute a bidi-mirrored character (e.g. ( ↔ )) at odd levels; mirror(c: char) -> Option<char>.
sfnt The binary container format for TrueType/OpenType fonts: 4-byte magic + table-directory of (tag, checksum, offset, length) entries; Face parses this.
table directory sfnt structure listing all font tables by Tag; Face uses it to locate cmap, GDEF, GSUB, GPOS, head, hhea, hmtx, maxp.
cmap OpenType 'cmap' table: maps Unicode code points → nominal glyph IDs; ush-shape parses subtable formats 4, 6, 12.
GDEF OpenType 'GDEF' table: classifies glyphs as Base / Ligature / Mark / Component; provides mark-attachment classes + mark-glyph-sets used by GSUB/GPOS lookups.
GSUB OpenType 'GSUB' table: glyph substitution; rewrites the glyph sequence via ordered lookup types 1–8; applied after cmap mapping.
GPOS OpenType 'GPOS' table: glyph positioning; adjusts advances and offsets via lookup types 1–9 (kerning, mark attachment, cursive, contextual).
lookup A GSUB/GPOS sub-table identified by type + flags + a list of subtables; Lookup struct; applied in FeatureList order.
lookup type Integer identifying the substitution/positioning rule variant (e.g. GSUB type 4 = ligature, GPOS type 2 = pair/kerning).
feature Named OpenType tag (e.g. liga, kern, calt, mark) grouping a set of lookup indices; enabled per script/langsys + user override via (Tag, u32) pairs.
script tag 4-byte OpenType tag identifying the writing system (e.g. latn, arab, dev2); used to select the ScriptList entry in GSUB/GPOS.
langsys Language-system record within a script; selects required + optional features for a specific language (e.g. TRK for Turkish).
coverage table Per-lookup bitmap/range structure listing the glyph IDs to which the lookup applies; tested before executing a substitution/positioning rule.
class definition GDEF/GSUB/GPOS subtable mapping glyph IDs to integer class values (0 = unclassed); used by class-based contextual lookups.
value record GPOS structure: up to 4 i16 fields (XPlacement, YPlacement, XAdvance, YAdvance) plus optional device-table pointers; accumulated into GlyphPosition.
anchor GPOS attachment point (x, y) in font units; used by mark-to-base, mark-to-ligature, mark-to-mark, and cursive lookups.
mark-to-base GPOS lookup type 4: attach a mark glyph's anchor to the anchor of the preceding base glyph; produces the x_offset/y_offset in GlyphPosition.
ligature GSUB type 4 substitution: replace a sequence of glyphs with a single ligature glyph; cluster of merged input glyphs maps to the output GlyphInfo.cluster.
glyph buffer Buffer { infos: Vec<GlyphInfo>, positions: Vec<GlyphPosition>, direction }: the mutable sequence threaded through the shaping pipeline; input = code-point–mapped glyph IDs, output = shaped + positioned glyphs.
cluster GlyphInfo.cluster: u32 = byte offset into the original text; monotonically non-decreasing (LTR) or non-increasing (RTL); merges on ligation, splits on multiple-subst; enables hit-testing + cursor placement.
joining type Arabic/Syriac per-character property (Non-joining, Right, Left, Dual, Transparent, Causing); drives ShaperArabic's joining state machine to select isol/init/medi/fina forms.
nominal glyph Glyph ID returned by cmap lookup before any GSUB substitution; the starting state of the Buffer.
units per em Face.units_per_em: u16; the coordinate grid size for all font metrics; advances and anchor coordinates are in these units.
advance GlyphPosition.x_advance (LTR) / y_advance (TTB): how far the pen moves after drawing a glyph; sum of nominal advance + GPOS adjustments.
.notdef / tofu Glyph ID 0; returned when cmap has no mapping for a code point; rendered as a blank or box by the rasterizer (#385).
