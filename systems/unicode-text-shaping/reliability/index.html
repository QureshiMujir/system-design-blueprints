7. System Invariants

INV-1 — Normalization is idempotent.

  • Statement: normalize(form, normalize(form, x)) == normalize(form, x) for all x, all NormForm.
  • Why: Unicode defines normal forms as fixed points; double application must be a no-op.
  • Enforced: Unit tests on NormalizationTest.txt column pairs; property quick_check(form, normalize(form, x)) == QuickCheck::Yes asserted in debug builds.
  • Detection: debug_assert_eq! after normalization in test mode; Phase 13 regression harness.
  • Recovery: Not applicable (pure function); failure indicates a bug in canonical_order or the composition loop.

INV-2 — Canonical ordering is stable.

  • Statement: canonical_order is a stable sort: codepoints with equal ccc retain their relative input order.
  • Why: UAX #15 §3: canonical ordering must be stable to avoid spurious canonical-equivalence violations.
  • Enforced: Implemented via Rust's slice::sort_by_key (guaranteed stable); asserted in tests with equal-ccc pairs.
  • Detection: Differential test against ICU normalizer2 output on equal-ccc sequences.
  • Recovery: Re-sort with stability flag; no user-visible recovery needed (internal invariant).

INV-3 — NFC→NFD canonical equivalence round-trip.

  • Statement: normalize(Nfd, normalize(Nfc, x)) is canonically equivalent to normalize(Nfd, x).
  • Why: NFC and NFD represent the same canonical-equivalence class; any sequence of compose/decompose must stay in-class.
  • Enforced: NormalizationTest.txt column checks (NFD(NFC(x)) == NFD(x)); verified in Phase 13.
  • Detection: Compare NFD output after NFC round-trip in test harness.

INV-4 — Grapheme boundaries never split base+extending or emoji ZWJ sequences.

  • Statement: No boundary returned by GraphemeCursor or graphemes() falls between a base and its Extend/SpacingMark/ZWJ or inside an emoji ZWJ sequence or regional-indicator pair.
  • Why: UAX #29 GB9/GB9a/GB9b/GB11/GB12/GB13; splitting these violates extended grapheme cluster definition.
  • Enforced: State machine enforces GBn rules; GraphemeBreakTest.txt covers all rule interactions.
  • Detection: Failing GraphemeBreakTest.txt row → rule number cited in error message.
  • Recovery: No recovery; assertion failure triggers a test failure revealing the broken rule.

INV-5 — Bidi embedding levels never exceed 125.

  • Statement: All Level values in BidiInfo::levels satisfy 0 <= level.0 <= 125.
  • Why: UAX #9 §3 conformance clause BI3; the DirectionalStatusStack caps depth at 125; exceeding entries are ignored.
  • Enforced: Level::new returns Err for values > 125; the stack overflow path sets level = para_level instead of pushing.
  • Detection: debug_assert!(level.0 <= 125) at every Level construction site; BidiTest.txt exercises the cap.
  • Telemetry: trace!("bidi_stack_overflow: para={}", para_level.0) on ignored embeddings.

INV-6 — reorder_line is a permutation.

  • Statement: The Vec<usize> returned by reorder_line(levels, line) is a permutation of line.start..line.end; no index appears twice, none is absent.
  • Why: Reordering must not lose or duplicate glyphs; consumer (#385) indexes into the original buffer by these indices.
  • Enforced: debug_assert_eq!(sorted(result), line.start..line.end) in debug builds; unit tests on all-LTR, all-RTL, mixed runs.
  • Detection: Permutation check fires in test suite; fuzz target exercises random level sequences.
  • Recovery: Not applicable; the algorithm is deterministic; failure indicates a bug in the L2 level-run loop.

INV-7 — Every font table access is bounds-checked.

  • Statement: No read from a Face's backing &[u8] slice ever accesses an out-of-bounds index; all offsets are validated before dereference.
  • Why: Font files are untrusted; OOB reads are undefined behavior (precluded by Rust slice indexing) but must not panic in production.
  • Enforced: All table accessors return Option or Result; slice indexing uses .get() not []; fuzz target in Phase 13.
  • Detection: libFuzzer corpus of malformed OTF/TTF files; cargo fuzz run fuzz_face.
  • Recovery: Malformed table → return .notdef (glyph id 0) for affected glyph range; log trace!("table_parse_error: table={:?}", tag).

INV-8 — The cluster map is monotonic and covers all input.

  • Statement (Ltr): buf.infos[i].cluster <= buf.infos[i+1].cluster for all consecutive glyphs in an Ltr run. Every cluster value is in 0..input_len. Statement (Rtl): non-increasing.
  • Why: Monotonicity is required by downstream hit-testing and cursor advancement; every output glyph must reference a valid input codepoint range.
  • Enforced: debug_assert after each GSUB lookup application in the shaping pipeline; verified against HarfBuzz golden fixtures.
  • Detection: Post-shaping cluster-monotonicity check in debug builds; Phase 13 differential.
  • Recovery: If a GSUB lookup would violate monotonicity (e.g., cross-cluster substitution), the lookup is skipped for that glyph sequence.

INV-9 — GSUB/GPOS apply only over Coverage-matched glyphs.

  • Statement: A GSUB or GPOS lookup is applied to glyph g only if coverage_index(lookup, g) returns Some(_); unmatched glyphs pass through unchanged.
  • Why: OpenType spec §5.1; applying a lookup outside its Coverage produces undefined output glyphs.
  • Enforced: Every lookup application function calls coverage_index first; no fallthrough without coverage check.
  • Detection: Unit tests with glyphs deliberately outside coverage verify pass-through.
  • Telemetry: trace!("lookup_skip: type={} glyph={}", lookup_type, glyph_id) for missed matches in verbose mode.

INV-10 — Shaping preserves total advance (absent GPOS).

  • Statement: buf.positions.iter().map(|p| p.x_advance).sum::<i32>() after GSUB only equals the sum of hmtx advances for each glyph in the Buffer; GPOS may adjust individual values but the cumulative layout advance is well-defined.
  • Why: Ligatures replace N glyphs with 1 whose advance = the ligature glyph's hmtx advance (not the sum of components); callers must not assume component-sum semantics.
  • Enforced: Tested with known ligatures (fi ligature in Latin fonts); GPOS kerning delta is sign-checked against plausible kerning ranges (< ±units_per_em).
  • Detection: Golden-file advance sums in Phase 13 HarfBuzz fixtures.

INV-11 — Unassigned and noncharacter codepoints are handled per spec.

  • Statement: Codepoints with GeneralCategory::Unassigned (Cn) or noncharacters (U+FDD0–U+FDEF, U+FFFE, U+FFFF, plane-final pairs) are not silently dropped; they pass through normalization (no decomposition), receive a BidiClass from ush-tables (typically ON or BN), and map to glyph 0 (.notdef) in ush-shape.
  • Why: UAX #15 §6 (unassigned codepoints are assigned to NFD_QC=Yes); UAX #9 §3.3 (noncharacters have defined bidi class); dropping them corrupts cluster indices for subsequent characters.
  • Enforced: decomposition(c) returns None for Cn/noncharacters; cmap lookup returns glyph 0; cluster map still allocates a slot.
  • Detection: Explicit test cases for U+FFFF, U+FDD0, and a Cn scalar in each pipeline stage.

INV-12 — The pipeline is deterministic for fixed Unicode + font version.

  • Statement: For identical inputs (text bytes, font bytes, feature list, base bidi level), the sequence normalize → segment → bidi → shape produces byte-for-byte identical output on every invocation, every platform.
  • Why: Required for reproducible builds, golden-file testing, and cache-key correctness.
  • Enforced: No HashMap with non-deterministic iteration order on output paths; BTreeMap or sorted Vec for feature/lookup iteration; no thread-local state.
  • Detection: Two consecutive calls in Phase 13 fixture harness; output XORed and asserted zero.
  • Telemetry: Any non-determinism source (clock, RNG, OS randomization) is a compile-time error via #![deny(clippy::non_deterministic_ordering)] equivalent lint.
