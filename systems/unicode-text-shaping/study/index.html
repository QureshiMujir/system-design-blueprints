Mental Models & First Principles

MM1. A Unicode code point is not a character; a grapheme cluster is. Expert insight: "character" is ambiguous; the spec defines scalar value, grapheme cluster, word, and paragraph as distinct layers. Predicts: correct cursor-movement and selection logic requires grapheme-cluster boundaries, not code-point boundaries. Bug class without it: splitting a ZWJ emoji sequence when the user presses Backspace once. Resolving sections: Phase 4 (GraphemeCursor), §8.1 (Character Model).

MM2. Normalization is a canonical-equivalence relation, not a canonical form. Expert insight: NFC and NFD both express the same canonical-equivalence class; the form only determines which representative is chosen. Predicts: NFD(NFC(x)) == NFD(x) always holds; this is the test for correct NFC implementation. Bug class without it: treating NFC as "the one right form" and skipping the idempotence test, then shipping a non-idempotent normalizer. Resolving sections: Phase 2 (INV-1, INV-3), §2.2 Canonical Composition.

MM3. Canonical ordering is not sort-by-ccc; it is stable-sort-within-runs-bounded-by-starters. Expert insight: ccc==0 starters divide the string into independent segments; the sort does not cross segment boundaries. Predicts: a character with ccc==0 is an absolute boundary even if surrounded by high-ccc marks. Bug class without it: a global sort-by-ccc incorrectly reorders marks across a starter, breaking canonical equivalence. Resolving sections: Phase 2.2 (canonical_order), §8.2.2.

MM4. The bidi algorithm is a level-assignment problem, not a reversal problem. Expert insight: X through I rules produce a level per character; L2 reorder is only one final pass that reverses maximal level runs. The complexity is in level assignment, not the reversal itself. Predicts: most bidi bugs are in W/N/I rules (isolating run sequences, bracket pairing) not in reorder_line. Bug class without it: developers jump to debugging the reorder loop when the actual error is a wrong level from a misapplied W rule. Resolving sections: Phase 6 (X rules), Phase 7 (W/N/I rules), §8.4.

MM5. An OpenType font is a relational database; GSUB/GPOS is the query engine. Expert insight: ScriptList → FeatureList → LookupList is a three-level indirection (the "OT lookup chain"). A feature is a named set of lookup indices, not a set of rules. Predicts: feature ordering must be by LookupList index, not by feature-tag alphabetical order. Bug class without it: applying liga before ccmp, which produces wrong glyph sequences for scripts whose precomposed glyphs depend on ccmp running first. Resolving sections: Phase 10 (GSUB apply loop, feature-ordering invariant), §8.5.3.

MM6. The cluster map is the contract between shaping and hit-testing. Expert insight: GlyphInfo.cluster is a monotonic mapping from output glyph back to input byte offset; it must remain monotonic (non-decreasing LTR, non-increasing RTL) through every GSUB transformation. Predicts: any ligature or decomposition that does not update clusters correctly breaks cursor placement for every downstream consumer. Bug class without it: hit-testing returns a wrong caret position after a ligature; the user cannot click between "f" and "i" in an "fi" ligature correctly. Resolving sections: Phase 9–10 (cluster merge/split), INV-8, §8.5.6.

MM7. Quick-check is a proven span-skip, not a heuristic. Expert insight: the NFC_QC / NFD_QC properties are derived from the normalization algorithm itself — a span with all-Yes properties is mathematically guaranteed to be already normalized. Predicts: on typical ASCII/Latin text, >90% of the input is QC=Yes and the full decompose+recompose pipeline is never invoked. Bug class without it: implementing quick-check as a heuristic (e.g., checking only ASCII range) that admits false positives, silently skipping strings that need normalization. Resolving sections: Phase 3 (QuickCheck), §4 throughput targets for NFC fast path.

MM8. Font bytes are adversarial input; every offset is a potential exploit. Expert insight: a font file is a structured binary from an external source; every offset + length expression must be validated against the backing &[u8] before dereference. Rust slice indexing panics on OOB in debug, returns None with .get() — choose .get(). Predicts: a fuzz run against any font parser that uses [] instead of .get() will produce panics within minutes. Bug class without it: memory-safety violations (pre-Rust) or panics that become a denial-of-service vector in a server-side font renderer. Resolving sections: Phase 8 (Bytes cursor), P6, Threat Model T1.

MM9. Isolates change bidi from a paragraph property to a scoped property. Expert insight: before Unicode 6.3 isolates (LRI/RLI/FSI/PDI), the only way to embed a bidirectional run was with explicit overrides (LRE/RLE), which "leaked" directionality to adjacent content. Isolates create a hard scope — W/N rules cannot cross isolate boundaries. Predicts: any bidi implementation that treats LRI/RLI/FSI as equivalent to LRE/RLE will produce wrong neutral/bracket resolution for strings with embedded opposite-direction spans. Bug class without it: Arabic name inside a URL inside an English sentence has corrupted punctuation placement. Resolving sections: Phase 6 (IsolateMap), Phase 7 (isolating run sequence construction), §8.4.3.

MM10. Hangul is arithmetic, not a table. Expert insight: Hangul syllable decomposition and composition are entirely defined by six integer constants (SBase, LBase, VBase, TBase, L/V/T counts); no table lookup is ever needed. Predicts: any normalization engine that puts Hangul in the decomposition table has made an unnecessary space trade-off, and will fail to compose newly allocated syllables if the UCD table is ever regenerated without covering them. Bug class without it: off-by-one on TBase (T_BASE+0 is a sentinel, not a real T jamo) produces wrong decomposition for syllables with T index 0. Resolving sections: Phase 2 (hangul.rs), §8.2.1.

Glossary · 52 terms · site-wide glossary

code point
Integer U+0000–U+10FFFF; the atomic unit of the Unicode character model.
scalar value
Code point excluding surrogates (U+D800–U+DFFF); Rust char models exactly this.
grapheme cluster
Extended grapheme cluster per UAX #29: user-perceived character; may span multiple code points (base + combining marks + ZWJ + ExtPict). GraphemeCursor walks boundaries.
normalization form
One of NFC / NFD / NFKC / NFKD (NormForm enum); determines which decomposition and whether to recompose.
canonical decomposition
Replace a precomposed code point with its canonical equivalent sequence; applied recursively. Invariant: NFC/NFD round-trip under canonical equivalence.
compatibility decomposition
Broader decomposition for formatting/compat variants (e.g. ﬁ → fi, ² → 2); applied in NFKD/NFKC before recomposition.
combining class (ccc)
u8 value 0–254 per code point; 0 = "starter" (blocks reordering); non-zero marks sorted stably by ccc within a run between starters. combining_class(c: char) -> u8.
starter
Code point with ccc == 0; acts as a hard boundary for the canonical ordering algorithm.
canonical ordering
Stable sort of combining marks by ccc within maximal runs between starters; required before NFC composition; canonical_order(buf: &mut Vec<(char, u8)>).
canonical composition
Attempt to merge a starter with a following combining char into a primary composite; fails if the pair is blocked or the composite is in the composition exclusion set.
composition exclusion
Code points that must not be produced by canonical composition (singletons, non-starters, full composition exclusions from DerivedNormalizationProps.txt).
blocked
A combining mark C is blocked from a starter L if any character between L and C has ccc ≥ ccc(C), preventing composition.
Hangul
Korean syllables composed algorithmically from jamo: L (leading, base U+1100), V (vowel, U+1161), T (trailing, U+11A7+1..28); SBase U+AC00; LVT = L×(VCount×TCount) + V×TCount + T. No table required.
quick check
Per-form NFC_QC / NFD_QC / NFKC_QC / NFKD_QC property → QuickCheck { Yes, No, Maybe }; a "Yes"-only span is already normalized; skip full processing on those spans.
stream-safe
Normalization form variant that caps a combining-mark run to 30 non-starters; prevents unbounded lookahead in streaming contexts.
word boundary
Position in text where the WB rules (WB1–WB999, UAX #29) determine a word starts or ends; WordCursor walks these; used for selection, search, and tokenization.
line-break opportunity
Position where a line may be broken per UAX #14; classified as Mandatory, Allowed, or No; LineBreaker emits these alongside text runs.
mandatory / allowed break
Mandatory: must break (e.g. U+000A LF, U+2028 LS). Allowed: may break subject to layout policy.
bidi class
Unicode Bidi_Class property (BidiClass enum: L, R, AL, EN, AN, NSM, BN, B, S, WS, ON, plus explicit/isolate codes); drives UAX #9 resolution.
embedding level
Level(u8) 0–125; even = LTR, odd = RTL; the X rules assign levels; higher levels nest inside lower.
isolate
Bidi directional isolate (LRI/RLI/FSI … PDI); inner content does not affect outer bracket/neutral resolution; handled by DirectionalStatusStack.
directional status stack
Stack of (level, override_status, isolate_flag) entries maintained during the X rules; max depth 125 including isolates.
isolating run sequence
A maximal sequence of level runs that are connected by isolate initiators; W/N/I rules apply per sequence, not per raw level run.
weak resolution
W1–W7 rules: transform EN/AN/NSM/ET/ES/CS/ON in context to reduce ambiguity before neutral resolution.
neutral resolution
N0–N2 rules: assign a direction to ON/WS/BN sequences based on surrounding strong types and bracket pairing.
implicit resolution
I1/I2 rules: bump odd-level chars from L/AN/EN and even-level chars from R/AL/AN to the next embedding level.
reordering
L2 rule: reverse maximal level-runs from highest level downward to produce visual order; reorder_line returns a Vec<usize> of visual-order indices.
mirroring
L4 rule: substitute a bidi-mirrored character (e.g. ( ↔ )) at odd levels; mirror(c: char) -> Option<char>.
sfnt
The binary container format for TrueType/OpenType fonts: 4-byte magic + table-directory of (tag, checksum, offset, length) entries; Face parses this.
table directory
sfnt structure listing all font tables by Tag; Face uses it to locate cmap, GDEF, GSUB, GPOS, head, hhea, hmtx, maxp.
cmap
OpenType 'cmap' table: maps Unicode code points → nominal glyph IDs; ush-shape parses subtable formats 4, 6, 12.
GDEF
OpenType 'GDEF' table: classifies glyphs as Base / Ligature / Mark / Component; provides mark-attachment classes + mark-glyph-sets used by GSUB/GPOS lookups.
GSUB
OpenType 'GSUB' table: glyph substitution; rewrites the glyph sequence via ordered lookup types 1–8; applied after cmap mapping.
GPOS
OpenType 'GPOS' table: glyph positioning; adjusts advances and offsets via lookup types 1–9 (kerning, mark attachment, cursive, contextual).
lookup
A GSUB/GPOS sub-table identified by type + flags + a list of subtables; Lookup struct; applied in FeatureList order.
lookup type
Integer identifying the substitution/positioning rule variant (e.g. GSUB type 4 = ligature, GPOS type 2 = pair/kerning).
feature
Named OpenType tag (e.g. liga, kern, calt, mark) grouping a set of lookup indices; enabled per script/langsys + user override via (Tag, u32) pairs.
script tag
4-byte OpenType tag identifying the writing system (e.g. latn, arab, dev2); used to select the ScriptList entry in GSUB/GPOS.
langsys
Language-system record within a script; selects required + optional features for a specific language (e.g. TRK for Turkish).
coverage table
Per-lookup bitmap/range structure listing the glyph IDs to which the lookup applies; tested before executing a substitution/positioning rule.
class definition
GDEF/GSUB/GPOS subtable mapping glyph IDs to integer class values (0 = unclassed); used by class-based contextual lookups.
value record
GPOS structure: up to 4 i16 fields (XPlacement, YPlacement, XAdvance, YAdvance) plus optional device-table pointers; accumulated into GlyphPosition.
anchor
GPOS attachment point (x, y) in font units; used by mark-to-base, mark-to-ligature, mark-to-mark, and cursive lookups.
mark-to-base
GPOS lookup type 4: attach a mark glyph's anchor to the anchor of the preceding base glyph; produces the x_offset/y_offset in GlyphPosition.
ligature
GSUB type 4 substitution: replace a sequence of glyphs with a single ligature glyph; cluster of merged input glyphs maps to the output GlyphInfo.cluster.
glyph buffer
Buffer { infos: Vec<GlyphInfo>, positions: Vec<GlyphPosition>, direction }: the mutable sequence threaded through the shaping pipeline; input = code-point–mapped glyph IDs, output = shaped + positioned glyphs.
cluster
GlyphInfo.cluster: u32 = byte offset into the original text; monotonically non-decreasing (LTR) or non-increasing (RTL); merges on ligation, splits on multiple-subst; enables hit-testing + cursor placement.
joining type
Arabic/Syriac per-character property (Non-joining, Right, Left, Dual, Transparent, Causing); drives ShaperArabic's joining state machine to select isol/init/medi/fina forms.
nominal glyph
Glyph ID returned by cmap lookup before any GSUB substitution; the starting state of the Buffer.
units per em
Face.units_per_em: u16; the coordinate grid size for all font metrics; advances and anchor coordinates are in these units.
advance
GlyphPosition.x_advance (LTR) / y_advance (TTB): how far the pen moves after drawing a glyph; sum of nominal advance + GPOS adjustments.
.notdef / tofu
Glyph ID 0; returned when cmap has no mapping for a code point; rendered as a blank or box by the rasterizer (#385).
