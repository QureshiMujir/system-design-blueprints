3. Architectural Overview

Pipeline Diagram

Application (ush CLI / layout engine)  -- text: &str, font bytes, script/lang/dir hint
                   |
                   v
    ush-normalize : NFC/NFD/NFKC/NFKD
                   (canonical order, Hangul, quick-check fast path)
                   |  normalized &str
                   v
    ush-segment   : grapheme / word / line-break boundaries
                   (UAX #29 GB rules, UAX #29 WB rules, UAX #14 LB rules)
                   |  runs: Vec<(byte_range, script, dir)>
                   v
    ush-bidi      : process_paragraph -> BidiInfo { levels, classes, para_level }
                   reorder_line -> visual-order index vec; mirror() per glyph
                   |  directional runs: (Level, script, lang)
                   v
    ush-shape     : Face { cmap / GDEF / GSUB / GPOS }
                   -> map chars to nominal glyph ids (cmap)
                   -> Shaper { Latin | Arabic | Indic | General }
                   -> GSUB substitutions (lookup types 1–6)
                   -> GPOS positioning   (lookup types 1–8)
                   -> Buffer { Vec<GlyphInfo>, Vec<GlyphPosition>, direction }
                   |  positioned glyphs: glyph_id, cluster, x/y advance+offset
                   v
    TrueType rasterizer (project #385) — draws the glyphs

    ush-tables underlies ALL stages:
      CodePointTrie -> general_category, combining_class, decomposition,
                       bidi_class, grapheme_break, word_break, line_break, script

Trust Boundary

UNTRUSTED --->  font bytes &[u8]  (ush-shape; every table access bounds-checked)
UNTRUSTED --->  text &str         (all crates; arbitrary Unicode, no assumption on normalization)
TRUSTED   --->  ush-tables data   (generated at build time from UCD; const; immutable)

Both untrusted inputs are processed with bounds-checked slice access and typed Result errors; no unsafe on the parsing hot path. Malformed font → Err(ShapeError::...) + .notdef glyph fallback; invalid UTF-8 is rejected at the &str type boundary.

Data-Flow Contracts Between Stages

Stage boundary Type crossing
normalize out String (NFC/NFD/…); same scalar values, reordered/composed combining marks
segment out Iterator of (Range<usize>, BreakClass); or Vec<Run { range, script, bidi_level }>
bidi out BidiInfo { levels: Vec<Level>, classes: Vec<BidiClass>, para_level: Level }; one entry per UTF-16 code unit (UAX #9 convention)
shape out Buffer { infos: Vec<GlyphInfo>, positions: Vec<GlyphPosition>, direction }
#385 boundary Buffer passed by reference; #385 reads glyph_id + cluster + advances + offsets; no ownership transfer of font data

No stage persists state between calls. Generated UCD tables are the single build-time artifact (const static data compiled into ush-tables).

Per-Box Responsibilities

ush-tables — CodePointTrie + property accessors

  • Owns all per-code-point Unicode properties: general_category, combining_class (ccc), decomposition (canonical + compat + CompatTag), bidi_class, grapheme_break (GCB), word_break, line_break, script.
  • Two-stage trie: 9-bit index block size → index[cp >> 9] gives a page offset; data[page + (cp & 0x1FF)] gives the value. Total size target < 1 MB for all properties combined.
  • Generated by tools/ from UCD text files; output is Rust const arrays. no_std. Invariant: property values are frozen at Unicode 15.1; any UCD bump requires regeneration + full conformance re-run.

ush-normalize — UAX #15 normalization

  • Normalizer { form: NormForm } + free fn normalize(form, &str) -> String.
  • NFD: recursive canonical decomposition via decomposition(), then canonical_order() (stable ccc sort, ccc==0 blockers prevent reordering across starters).
  • NFC: NFD then canonical composition — scan left-to-right, pair a starter with a following combining char if primary composite exists AND pair is not blocked AND composite not in composition-exclusion set.
  • NFKD/NFKC: same as NFD/NFC but also apply compat decompositions (CompatTag-tagged entries).
  • Hangul: algorithmic (SBase=0xAC00, LBase=0x1100, VBase=0x1161, TBase=0x11A7, LCount=19, VCount=21, TCount=28); no table needed.
  • quick_check(form, &str) -> QuickCheck { Yes, No, Maybe }: Yes-only spans are already normalized → skip entirely (the fast path for already-NFC text).
  • Invariant: output is idempotent (normalize(form, normalize(form, s)) == normalize(form, s)).

ush-segment — grapheme clusters, words, line-break opportunities

  • GraphemeCursor<'a> over a &str: advances one extended grapheme cluster per step using the GB1..GB999 rule state machine over GraphemeBreak properties.
  • Emoji ZWJ sequences: ZWJ (U+200D) followed by ExtPict is never a break point (GB11). Regional indicators pair: break after every second RI (GB12/GB13).
  • WordCursor applies WB rules over word_break properties; yields word/non-word spans.
  • LineBreaker applies UAX #14 LB rules via the break-class pair table; emits (offset, BreakClass { Mandatory, Allowed, No }).
  • Invariant: grapheme cluster boundaries are always valid UTF-8 byte boundaries; cursor never splits a multi-byte sequence.

ush-bidi — UAX #9 bidirectional algorithm

  • process_paragraph(text, base: Option<Level>) -> BidiInfo: assigns BidiClass per char (via ush-tables), detects paragraph base level (P2/P3; FSI heuristic), runs X1..X8 explicit-level rules via DirectionalStatusStack (push on LRE/RLE/LRO/RLO/LRI/RLI/FSI; pop on PDF/PDI; max depth 125), forms isolating run sequences, resolves weak types (W1..W7), neutral types (N0..N2), implicit levels (I1/I2).
  • reorder_line(levels, line) -> Vec<usize>: L2 rule — from highest level down to the lowest odd level, reverse each maximal run; returns visual-order index vector.
  • mirror(c) -> Option<char>: returns the bidi mirroring pair for chars at odd embedding levels (e.g. ( → ) for RTL display).
  • Invariant: Level(0) is LTR, Level(1) is RTL; even = LTR, odd = RTL; max 125.

ush-shape — OpenType font parsing: Face

  • Face<'a> holds &'a [u8] (zero-copy), the sfnt table-directory offsets, and units_per_em from head.
  • Table parsing: head/hhea/maxp/hmtx for metrics; cmap formats 4 (BMP) and 12 (full range) → nominal_glyph(char) -> Option<u32>; GDEF for glyph-class + mark-attach-class + mark-glyph-sets.
  • All table access: range-checked get(offset..offset+len)?; never panics on malformed input.

Buffer — the shaping workspace

  • Buffer { infos: Vec<GlyphInfo>, positions: Vec<GlyphPosition>, direction: Direction }.
  • GlyphInfo { glyph_id: u32, cluster: u32, flags: u16 } — cluster is monotonically non-decreasing (LTR) or non-increasing (RTL); merges on ligation, splits on multiple-substitution.
  • GlyphPosition { x_advance, y_advance, x_offset, y_offset: i32 } in font design units.
  • Invariant: infos.len() == positions.len() always; cluster values preserve input-char provenance for hit-testing.

Shaping pipeline + Shapers

  • shape(face, buf, features) orchestrates: (1) map Unicode chars → nominal glyph IDs via cmap; (2) select script/lang/features from GSUB + GPOS ScriptList; (3) dispatch to the appropriate Shaper impl; (4) run GSUB lookups; (5) run GPOS lookups.
  • ShaperLatin: applies default GSUB/GPOS features (kern, liga, calt, …); no reorder.
  • ShaperArabic: joining-type state machine → assigns isol/init/medi/fina contextual forms; applies arab/init/medi/fina/isol/liga/mset features.
  • ShaperIndic: syllable reorder (base consonant, halant, matra positions) before GSUB; applies the Indic feature set.
  • ShaperGeneral: script-agnostic fallback; applies default features only.
  • RTL Buffer: direction from bidi Level parity; RTL runs have the buffer reversed before GSUB so lookup order is correct; reversed back after GPOS.

GSUB — glyph substitution

  • Lookup types 1 (single), 2 (multiple), 3 (alternate), 4 (ligature), 5 (contextual), 6 (chaining-contextual).
  • Feature ordering: mandatory features first, then ordered user feature list, then default features.
  • Cluster merging on ligature (type 4): output glyph inherits minimum cluster of all input glyphs.

GPOS — glyph positioning

  • Lookup types 1 (single adjust), 2 (pair/kerning), 3 (cursive attach), 4 (mark-to-base), 5 (mark-to-ligature), 6 (mark-to-mark), 7/8 (contextual).
  • Value records: XPlacement, YPlacement, XAdvance, YAdvance deltas applied to GlyphPosition.
  • Anchors + device tables for mark attachment; device table delta applied at current ppem.

ush-cli — the ush binary

  • Subcommands: normalize [--form NFC|NFD|NFKC|NFKD] <text>, segment [--graphemes|--words|--lines] <text>, bidi <text>, shape --font <file> [--script] [--lang] [--features] <text>.
  • shape output: JSON or TSV of (glyph_id, cluster, x_advance, y_advance, x_offset, y_offset) per glyph; optionally pipes to #385 rasterizer stdin.
  • Depends on all five library crates; the only std-using crate in the workspace.

8.2 Normalization Algorithm

Step order: decompose → canonical order → compose (only for NFC/NFKC).

8.2.1 Decomposition

  • Canonical: recursively expand via decomposition(c) = Canonical(chars) until no entry; Hangul LVT -> L,V,T arithmetically.
  • Compatibility (NFKD/NFKC): expand Compat(tag, chars) as well; same recursion.
  • Hangul arithmetic (no table):
    SBase=0xAC00, LBase=0x1100, VBase=0x1161, TBase=0x11A7
LCount=19, VCount=21, TCount=28, NCount=VCount*TCount=588
LV = LBase + (cp-SBase)/NCount
V  = VBase + ((cp-SBase) % NCount) / TCount
T  = TBase + (cp-SBase) % TCount   (only if T index > 0)

8.2.2 Canonical Ordering

  • Collect (char, ccc) pairs from decomposed buffer.
  • Stable sort every maximal run of ccc > 0; ccc == 0 chars act as blockers — they terminate a run.
  • Invariant after step: any two adjacent chars with ccc(a) > ccc(b) have been swapped; starters not moved.

8.2.3 Canonical Composition (NFC / NFKC)

Current char ccc Condition Action
== 0 (starter) always record as new starter candidate
> 0 (combining) blocked(starter, i) == true append char unchanged; update max_ccc_since_starter
> 0 (combining) not blocked AND is_primary_composite(buf[starter], buf[i]) replace buf[starter] with composite; delete buf[i] from buffer; continue scan at same i (now pointing to next char)
> 0 (combining) not blocked AND no composite found append char unchanged; update max_ccc_since_starter
  • Blocked: some char at j (starter < j < i) has ccc(j) >= ccc(i); OR j is a starter itself.
  • Composition exclusions: singletons, non-starter decompositions, pre-composed chars listed in CompositionExclusions.txt; also Hangul composed algorithmically (L+V -> LV, LV+T -> LVT).

8.2.4 Worked Example

Input: "q̣̇" (q + combining dot above U+0307 ccc=230 + combining dot below U+0323 ccc=220)

Step Buffer Notes
Decompose (NFD) q(0), ̣(220), ̇(230) No canonical decomps; passthrough
Canonical order q(0), ̣(220), ̇(230) 220 < 230, already in order after stable sort
NFC compose q + U+0323 + U+0307 No primary composite for q+U+0323; no composite for result+U+0307
Output NFD q̣̇ Reordered vs input

Second example: "é" (é U+00E9, precomposed):

Step Buffer Notes
Decompose NFD e(0), ́(230) U+00E9 -> U+0065 U+0301 via table
Canonical order e(0), ́(230) Single combiner, unchanged
NFC compose é e + U+0301 -> U+00E9; not excluded; not blocked

8.3 Segmentation Rule Machines

Grapheme Cluster (UAX #29 GB rules), ordered highest-priority first:

Rule Pattern Action
GB1 sot ÷ Always break at start
GB2 ÷ eot Always break at end
GB3 CR × LF No break
GB4 (Control|CR|LF) ÷ Break after
GB5 ÷ (Control|CR|LF) Break before
GB6 L × (L|V|LV|LVT) Hangul syllable
GB7 (LV|V) × (V|T) Hangul
GB8 (LVT|T) × T Hangul
GB9 × (Extend|ZWJ) Keep combiners
GB9a × SpacingMark Keep spacing marks
GB9b Prepend × Keep prepends
GB11 ExtPict Extend* ZWJ × ExtPict Emoji ZWJ sequence
GB12/13 RI × RI (first pair only) Regional indicator pair
GB999 ÷ (otherwise) Default break

Emoji ZWJ + Regional Indicator examples:

  • 👩‍🚀 = U+1F469 ZWJ U+1F680: GB11 keeps ExtPict + ZWJ + ExtPict as one cluster.
  • 🇺🇸🇬🇧: GB12/13 pairs: [U+1F1FA U+1F1F8] [U+1F1EC U+1F1E7]; each RI pair is one cluster; stateful — must track if preceding RI count is even.

Word Break (WB rules, same machine pattern): WB1/WB2 sot/eot; WB3 CR×LF; WB3a-c controls; WB4 skip Extend/Format/ZWJ; WB5 AHLetter×AHLetter; WB6/7 AHLetter×(MidLetter|MidNumLet)AHLetter; WB8-10 Numeric; WB11/12 Numeric+MidNum; WB13 Katakana; WB13a/b ExtendNumLet; WB15/16 RI pairs; WB999 break.

Line Break (LB pair table): LB rules classify each code point into an LbClass; a 50×50 pair table encodes { B(reak), N(o), ^(prohibited), _ } for (before, after) class pairs; mandatory breaks (BK, NL, CR, LF) always fire; tailoring via rule ordering for spaces + combining marks.

8.4.2 Paragraph Base Level (P2/P3 + FSI)

  • P2: scan left-to-right in paragraph, skipping chars inside isolates; take first strong (L/R/AL).
  • P3: if L -> level 0; if R/AL -> level 1; if no strong found -> level 0.
  • FSI: look ahead within the isolate for first strong; resolve its direction the same way.

8.4.3 Explicit Level Resolution (X Rules) — DirectionalStatusStack

struct DirectionalStatusStack {
    entries: Vec<(Level, Override, Isolate)>,  // max 125 depth
}
// X1: push paragraph level.
// X2 LRE: push(current+1 rounded even, Neutral, false)   if depth < 125
// X3 RLE: push(current+1 rounded odd,  Neutral, false)   if depth < 125
// X4 LRO: push(..., Override=L, false)
// X5 RLO: push(..., Override=R, false)
// X5a LRI: push(current+1 rounded even, Neutral, true)   isolate
// X5b RLI: push(current+1 rounded odd,  Neutral, true)   isolate
// X5c FSI: determine direction, then push as LRI or RLI
// X6: assign current level/override to every non-format char
// X6a PDI: pop top isolate entry; assign PDI level from new top
// X7 PDF: pop top non-isolate entry
// X8: reset stack to paragraph level at B
// depth > 125: ignore LRE/RLE/LRO/RLO; overflow isolate counter for LRI/RLI/FSI

Isolate example: "hello ⁦Arabic⁩ world" (LRI...PDI):

  • Before LRI: level 0. LRI pushes level 1 (even -> LTR override from isolate direction).
  • "Arabic" chars assigned level 1 inside isolate.
  • PDI pops; "world" back at level 0.
  • Isolate is treated as a unit in the enclosing level; no W/N rules cross its boundary.

8.4.4 W / N / I Rules + L2 Reorder

  • W1-W7 (weak): W1 NSM inherits preceding class; W2 EN after AL -> AN; W3 AL -> R; W4 ES/CS between EN->EN; W5 ET adjacent EN; W6 ES/ET/CS -> ON; W7 EN after L context -> L.
  • N0-N2 (neutral): N0 paired brackets (the bracket-matching algorithm); N1 sequence of neutrals between same-direction strongs -> that direction; N2 remaining neutrals -> embedding direction.
  • I1/I2 (implicit): I1 even level: L stays, R +1, AN/EN +2; I2 odd level: R stays, L/AN/EN +1.
  • L2 reorder: reverse every maximal contiguous sequence at the highest level, decrement level, repeat until all levels resolved; yields visual order.
  • L3 combining marks: (handled; marks take preceding level).
  • mirror(): at odd levels, replace bracket/quote/arrow with bidi-mirror pair (e.g., U+0028 -> U+0029) using the Bidi_Mirroring_Glyph table.

Worked mixed example: logical "car ב→ג" (L:"car " R:"ב→ג")

Position Char BidiClass Level (after I rules)
0 c L 0
1 a L 0
2 r L 0
3 (space) WS 0
4 ב R 1
5 → ON 1 (N1: between R,R)
6 ג R 1

L2 reorder (highest=1): reverse positions 4..6 -> visual: "car גּ←ב" (arrow mirrored at odd level).

8.5 OpenType Layout Model

8.5.1 sfnt Table Directory

sfnt header: sfVersion, numTables, searchRange, entrySelector, rangeShift
TableRecord[numTables]: tag(4B), checksum(4B), offset(4B), length(4B)
Required tables parsed: head (unitsPerEm), hhea, maxp, hmtx (advance widths),
                        cmap, GDEF, GSUB, GPOS

8.5.2 cmap Formats

Format Coverage Usage
4 (segmented delta) BMP U+0000..U+FFFF Most common; segment array
6 (trimmed array) Dense BMP range Small fonts
12 (segmented, 32-bit) Full Unicode incl. supplementary Required for emoji/CJK ext

cmap lookup: binary-search segment table -> glyph_id = (cp - startCode) + idDelta (format 4) or direct index (format 12). Miss -> glyph 0 (.notdef).

8.5.3 GSUB / GPOS Structure

ScriptList  -> Script[tag] -> LangSys[tag] -> Feature indices[]
FeatureList -> Feature[index] -> LookupList indices[]
LookupList  -> Lookup[index] -> { LookupType, LookupFlag, SubTable[] }
  • Coverage table: glyph-id set (format 1: sorted glyph array; format 2: ranges) -> coverage index.
  • ClassDef: maps glyph-id -> class integer (format 1: array from startGlyph; format 2: ranges).

8.5.4 GSUB Lookup Types

Type Name Mechanism
1 Single glyph + delta or explicit map
2 Multiple 1 -> N glyphs (decompose)
3 Alternate 1 -> 1 of N alternates
4 Ligature N -> 1 (ligate)
5 Context rule set / class / coverage-based context
6 Chaining Context backtrack + input + lookahead
7/8 Extension / Reverse Chain extension indirection; RTL single

Worked ligature (GSUB type 4): feature liga, script latn:

  • LookupList[2]: LigatureSet for glyph(f): [Ligature { components:[glyph(i)], ligGlyph:glyph(fi) }]
  • Buffer before: [GlyphInfo{id:glyph(f), cluster:0}, GlyphInfo{id:glyph(i), cluster:1}]
  • Match: current=glyph(f), next=glyph(i) -> ligature match.
  • Buffer after: [GlyphInfo{id:glyph(fi), cluster:0}] — cluster 0 covers input chars 0..1; cluster monotonic.

8.5.5 GPOS Lookup Types

Type Name Mechanism
1 Single Adjust value record per glyph
2 Pair Adjust kerning: (g1,g2) -> (ValueRecord1, ValueRecord2)
3 Cursive Attach entry/exit anchors for cursive scripts
4 Mark-to-Base mark anchor -> base anchor
5 Mark-to-Ligature mark -> ligature component anchor
6 Mark-to-Mark mark -> mark anchor
7/8 Context / Chaining contextual positioning

Worked kerning pair (GPOS type 2):

  • PairSet for glyph(A): [PairValueRecord{ secondGlyph:glyph(V), value1:{XAdvance:-80}, value2:{} }]
  • Buffer: [GlyphInfo(A,cluster=0), GlyphInfo(V,cluster=1)]
  • Apply: positions[0].x_advance += -80; positions[1] unchanged.

Value record fields: XPlacement, YPlacement, XAdvance, YAdvance (each i16). Anchors: (x,y) in design units with optional device tables for hinting.

8.5.6 Buffer / Cluster Invariants

  • infos.len() == positions.len() always.
  • Cluster values monotonically non-decreasing (LTR) or non-increasing (RTL).
  • Ligature merge: all consumed glyphs' clusters collapse to the minimum cluster index.
  • Multiple-subst split: new glyphs inherit the source glyph's cluster value.
  • Cluster ties output glyph_id back to input char offset for hit-testing + cursor placement by caller.

8.5.7 Malformed / Edge-Case Handling

Input Condition Handling
Lone surrogate (e.g., U+D800) Not a valid Rust char; can arrive via FFI/bytes Reject at API boundary; Err(InvalidScalar) before any pipeline stage
Unassigned code point (e.g., U+FFFF) Valid scalar, GC=Cn, no decomp, bidi=BN Pass through as-is; no crash; cmap miss -> .notdef
Font with truncated GSUB SubTable offset past EOF Bounds-check on every offset read; return Err(MalformedTable); skip subtable, continue
cmap miss No glyph for cp in any subtable glyph_id = 0 (.notdef); cluster preserved; shaping continues
Over-deep bidi nesting (>125) DirectionalStatusStack overflow Overflow LRE/RLE/LRO/RLO silently ignored per spec; overflow isolate counter incremented; no stack growth
ccc > 254 Not valid in Unicode Table stores u8; values clamped at table generation; flagged in tools/ validation
Empty font GPOS No GPOS table present gpos field = None in Face; positioning step is a no-op; all positions remain zero
