Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. If the dependency graph (§17, §31) has no eviction policy while the event log (§18) does, what stops a multi-hour session from exhausting target-process memory even though every other buffer is bounded — and does the 4-hour session cap (§8.6) actually save you, or just delay the failure? (§17, §31)
  2. I9 says replay never re-executes target-side code, and §19.2 says the replay projector holds no reference to the live target connection at all. When a saved view (§21) is evaluated against a historical ScrubCursor, is that a distinct query path from the live-attached one, and does §11's schema actually distinguish the two cases anywhere? (§19, §21, §11)
  3. The redaction filter (§22) runs at the backend, downstream of the target's serializer, while I13's getter-guard runs inside the serializer, upstream of redaction. Could a getter that is itself a secret accessor be materialized (T10) before the backend gets a chance to filter it — and does that mean the target-side pre-filter deferral (§37) needs un-deferring before Phase 10 ships safely? (§14, §22, §37)
  4. §15's reconnect model assumes a locally-issued resumption token is trustworthy; §22 says the remote-bridge case needs "its own credential model, not a copy-paste." Where is that boundary actually enforced — one shared SessionManager path, or two genuinely separate ones — without becoming exactly the copy-paste ADR-09 warns against? (§15, §22, ADR-09)
  5. M3 sets a 50 ns budget per signal read, and §17.7 says a single unnecessary allocation blows it. Given DependencyEdge (§11) is declared immutable, how does the tracker avoid allocating a fresh edge object per read without violating that immutability or reintroducing a mutable-shared-state hazard P2/I2 forbid elsewhere? (§11, §17, §30)
  6. §18's ring buffer preserves keyframes under eviction, but §18.8 admits a storm could make "every event a keyframe," and the fallback evicts keyframes too. What actually happens to an in-progress scrub session (§19) when the keyframe it's anchored to is evicted by that fallback mid-session? (§18, §19)
  7. ADR-04 locks runtime monkey-patching over a compiler transform partly on zero-build-step grounds. For a target whose bundler LRSI genuinely cannot hook into post-hoc, is there a real migration path to a future compiler-transform adapter that doesn't re-derive the entire InstrumentationHooks contract, or does §1's deferral quietly assume a rewrite? (ADR-04, §36, §1)
  8. §20's async tracking is opt-in due to overhead risk, but §8.4's EventRecord.kind already includes "async-boundary" with no opt-in gate mentioned in §8. Does enabling async tracking retroactively change the meaning of events already in the ring buffer, or does the event log need a per-event capability marker to avoid an inconsistent read across the toggle? (§8, §18, §20)
  9. §27 says a schema-version-mismatched saved view degrades to "no matches," and §21.8 says an eviction-spanning query degrades to "partial." If both occur at once, does the UI have one consistent way to say "incomplete and possibly stale," or do the two warning paths collide? (§21, §27)
  10. T12's mitigation is a compiled-cost estimate plus a hard evaluation cap, but §21.7 says predicate compilation must be cheap enough for a live-updating saved view evaluated on every delta. Is the cost estimate computed once at compile time (cheap, possibly wrong for data-dependent cost) or dynamically per evaluation (accurate, but reintroducing the overhead §21.7 forbids)? (§21, T12, §30)
  11. §26 says session state is "not backed up — ephemeral by design," yet §22.9's redaction-gap forensics require a "wire-capture archive... retained only as long as policy allows." Doesn't a forensic wire-capture archive directly contradict "ephemeral by design," and where is the actual retention policy specified as a real, versioned rule rather than a placeholder? (§25, §26, §29)
  12. §17.8 says a dependency edge from an aborted concurrent-render pass "must not be committed to the graph." How does the tracker know a pass was aborted before committing edges it already emitted, given onDependencyEdge (§8.2) is append-only and may interleave with onUpdate — is a transactional/rollback mechanism implied that isn't in the §11 signatures? (§8, §11, §17)
  13. §31 names the dependency graph as the top bottleneck precisely because it's uncapped, while every other buffer here has an explicit eviction policy (P2). Why doesn't Phase 5 apply the same ring-buffer discipline Phase 6 applies to events — a technical blocker, or a genuine scope gap? (§17, §18, §31)
  14. §19.6 forbids assuming deltas are invertible "unless the adapter declares them so," and no adapter through Phase 11 ever declares invertibility. Does that make every backward seek in the shipped product a forward-replay-from-an-earlier-keyframe illusion rather than true reverse playback, and is that disclosed to the user anywhere, per P11? (§13, §19)
  15. T9's mitigation for session hijack is a short token staleness window, but ADR-09's rationale is that hot reload disconnects "every few seconds." Is the staleness window actually tuned to survive a realistic hot-reload gap while staying short enough to bound the T9 window, or are these two numeric requirements never reconciled against each other? (ADR-09, T9, I12)
  16. §33 credits Redux DevTools with "full" time-travel specifically because reducers are pure, and §17/I9 build LRSI's replay model around the opposite (impure-target) assumption. Does the query engine (§21) ever offer a Redux-DevTools-equivalent full-fidelity mode for a sub-store that happens to be pure, or does the general impure-target model uniformly degrade even a pure sub-store to lossy keyframe+delta replay? (§19, §21, §33)
  17. §22.8 says a mid-session redaction rule "must not attempt retroactive redaction of already-transmitted data," yet §22.9's failure analysis calls for "an audit of any prior session's transmitted data for exposure." If retroactive redaction is architecturally impossible, what does that audit accomplish beyond confirming the exposure already happened — is there a purge mechanism elsewhere it's meant to trigger? (§22, §25, §26)
  18. MM7 frames keyframe+delta replay as a philosophical commitment (never re-execute the observed system), while §36 frames the rejection of full record/replay as an engineering-feasibility argument (can't ptrace a JS heap). If a future engine-level hook made full in-realm replay feasible, would P1 still forbid it, or was feasibility the only real blocking constraint all along? (MM7, §36, P1)

32. Mental Models & First Principles

MM1 — An inspector is a serializer with a scheduling problem. The hard part is not reading state but reading it without becoming part of it. Predicts overhead budgets dominate the design more than feature completeness. Without it: unbounded instrumentation cost creeps into the target's own timing behavior. Resolved in §4 and §14 (I13).

MM2 — A snapshot is a lossy compression of a live heap, and the loss must be declared, not discovered. Predicts every truncation needs a marker. Without it: a developer trusts a truncated view as complete and misdiagnoses a bug. Resolved in §8.1 (P3, I10).

MM3 — Causality needs its own clock, because wall time lies the moment two processes are involved. Predicts any cross-process feature needs LogicalClock discipline from day one. Without it: reordered events under clock skew produce an impossible-looking causal trace. Resolved in §15 and §22 (P7, I4).

MM4 — A cycle is not a bug in the data, it's a bug in your assumption that data is a tree. Predicts any tree-first serializer/graph model needs an expensive retrofit. Without it: a crash or infinite loop the first time a real reactive store is inspected. Resolved in §14 and §17 (I3).

MM5 — Reconnection is a protocol, not an event handler. Predicts that treating "the socket reconnected" as sufficient will silently break session continuity. Without it: duplicate or missing events after every hot reload. Resolved in §15 (I12, ADR-09).

MM6 — Query power and query cost are the same knob. Expose one without bounding the other and you've built a denial-of-service generator, not a feature. Predicts any sufficiently expressive query language needs an explicit cost model before it ships. Without it: a saved view silently hangs the backend. Resolved in §21 (T12, FM-10).

MM7 — Time travel over an impure system is a projection over recorded history, not a rewind of the system itself. Predicts any live-target callback from the replay path is architecturally wrong, not just risky. Without it: replay accidentally re-triggers real side effects. Resolved in §19 and §36 (I9).

MM8 — Redaction is a property of the pipe, not the display. Predicts any redaction implemented downstream of the trust boundary is a compliance liability waiting to be discovered. Without it: a secret "not shown in the UI" sitting in a network capture. Resolved in §22 (P9, I5).

MM9 — Every buffer is a promise about memory, and an undocumented eviction policy is a broken promise waiting for a demo. Predicts any new stateful buffer added later must declare its eviction policy at the same commit that introduces it. Without it: a slow memory leak that only surfaces after hours of live use, exactly when a demo or incident is happening. Resolved in §18 and §31 (P2).

5. Required Reading

Books

  • Designing Data-Intensive Applications, Kleppmann — ch. 5 (Replication) and ch. 11 (Stream Processing): log-based propagation and ordering guarantees. Applied in §18 (Phase 6).
  • Site Reliability Engineering, Beyer et al. — ch. on SLOs and monitoring distributed systems: budget-setting discipline for latency/error targets. Applied in §26.
  • Debugging: The 9 Indispensable Rules, Agans — systematic-debugging heuristics ("understand the system", "make it fail", "quit thinking and look"): informs the invariant-detection methodology. Applied in §7.
  • Crafting Interpreters, Nystrom — ch. 26 (Garbage Collection): mark-sweep and weak-reference reasoning informs the WeakRef/FinalizationRegistry reference model. Applied in §14 (Phase 2).
  • Effective TypeScript, Vanderkam — items on structural typing and avoiding any: informs the hook-boundary type discipline. Applied in §11.
  • Release It!, Nygard — ch. on stability patterns (circuit breaker, bulkhead, timeout): informs reconnect/backpressure design. Applied in §15 (Phase 3) and §25.
  • Database Internals, Petrov — ch. on log-structured storage and compaction: informs ring-buffer eviction and keyframe placement. Applied in §18 (Phase 6) and §19 (Phase 7).

Papers

  • Meyerovich & Bodik, 2010 — empirical analysis of reactive vs. imperative update-propagation cost; motivates edge-level dependency tracking over coarse re-render capture. Applied in §17 (Phase 5).
  • Ko & Myers, ICSE 2008 (Whyline) — structural "why/why not" causal questions over program behavior. Applied in §21 (Phase 9, query engine).
  • Sillito, Murphy, De Volder, FSE 2006 — catalog of questions programmers ask during software evolution (structure, relationships, history). Applied in §21 (Phase 9).
  • O'Callahan, Paradis, et al., USENIX ATC 2017 (rr) — low-overhead deterministic record/replay; contrasted against the keyframe+delta compromise. Applied in §19 (Phase 7) and §36.
  • Carniato — Solid.js signal/reactivity design (conference talks, design docs) and the surrounding fine-grained-reactivity literature: synchronous glitch-free dependency-edge propagation. Applied in §17 (Phase 5).
  • Czaplicki — The Elm Architecture and its time-travelling debugger (design notes): pure-model replay as a limiting case contrasted with LRSI's impure-target replay. Applied in §19 (Phase 7).
  • Microsoft Time Travel Debugging (TTD) — bit-accurate reverse debugging via full instruction trace; contrasted against LRSI's intentionally lossy snapshot model. Applied in §19 and §36.
  • Weststrate — MobX observable/reaction design (project documentation, talks): transparent proxy-based dependency tracking as an alternative model. Applied in §33 (Comparative Architecture).

Reference Implementations

  • facebook/react → packages/react-devtools-shared/src/backend/ — lesson: a stable backend/frontend bridge protocol decoupled from the framework's internal version. Pitfall: do not copy its single-global-hook coupling (__REACT_DEVTOOLS_GLOBAL_HOOK__) as the only attach mechanism — it collides with concurrent tools. Applied in §13 (Phase 1).
  • vuejs/devtools → packages/core/src/ — lesson: a plugin-based tree-walking architecture per framework. Pitfall: don't couple the UI directly to a specific reactivity-runtime version. Applied in §13.
  • reduxjs/redux-devtools → packages/redux-devtools-instrument/src/instrument.js — lesson: action-replay time-travel is safe only because reducers are pure. Pitfall: never assume replay is side-effect-free for an arbitrary runtime (I9 exists because of this). Applied in §19 (Phase 7).
  • nodejs/node → lib/async_hooks.js, lib/internal/inspector_async_hook.js — lesson: async causality via init/before/after/destroy callbacks. Pitfall: async_hooks itself has nontrivial overhead and can perturb GC timing — must be opt-in. Applied in §20 (Phase 8).
  • solidjs/solid-devtools → packages/debugger/src/ — lesson: fine-grained signal/computation graph inspection without a virtual-DOM diff. Pitfall: it couples tightly to Solid's own runtime internals — motivates LRSI's explicit adapter boundary instead. Applied in §17 (Phase 5).
  • ChromeDevTools/devtools-protocol → json/js_protocol.json, json/browser_protocol.json — lesson: domain/method/event namespacing for a session-scoped protocol. Pitfall: CDP's domain-enable statefulness is easy to leak across reconnects — reconnect must re-establish enabled state explicitly. Applied in §15 (Phase 3).

RFCs / Specifications

  • Chrome DevTools Protocol (domain/method/event model). Applied in §8 (wire protocol catalogue) and §13.
  • V8 Inspector Protocol (v8/v8 src/inspector/*.json domains), distinct from CDP proper. Applied in §13.
  • RFC 6455 (WebSocket). Applied in §15 (Phase 3).
  • RFC 8949 (CBOR). Applied in §8 and §15.
  • HTML Living Standard, structured-clone algorithm. Applied in §14 (Phase 2).
  • W3C User Timing and Performance Timeline specifications. Applied in §18 (Phase 6).
  • Debug Adapter Protocol (DAP) and Language Server Protocol (LSP), as precedents for a tool-to-tool contract. Applied in §1 (boundaries) and §27.
  • OpenTelemetry specification. Applied in §26.

Glossary (§38) · 45 terms · site-wide glossary

Adapter
a per-runtime implementation of InstrumentationHooks (e.g. @lrsi/adapter-react).
Attach
connecting a session to a running target and beginning snapshot/event capture.
AttachAck
the wire message confirming a successful attach with an initial keyframe.
Async task
a tracked unit of async work with a start/end boundary (Phase 8).
Backpressure
the mechanism bounding queue growth when producers outpace consumers.
Bridge
the remote-target relay process (@lrsi/bridge) enabling attach across a network boundary.
CBOR
Concise Binary Object Representation (RFC 8949), the wire payload encoding.
Conformance suite
the fixture-driven test corpus (@lrsi/conformance) gating releases.
CycleRef
a schema marker replacing a re-visited node reference during serialization.
Degraded
a session state indicating impaired but not lost connectivity.
Delta / DeltaOp
a single structural change applied to reconstruct a snapshot from a keyframe.
Dependency edge
a typed link (reads/writes/subscribes/triggers) in the reactive graph.
Detach
ending a session and reverting the target to its pre-attach state.
Effect
a reactive computation that re-runs when its dependencies change.
EffectRecord
the schema type tracking an effect's last-run dependencies and disposal state.
Event ring buffer
the bounded, LogicalClock-ordered store of EventRecords.
Eviction policy
the documented rule governing what a bounded buffer discards when full.
Fiber
React's internal unit of work; adapter-internal, never exposed in the wire schema.
Hot reload
a development-time module replacement that disconnects and reconnects the transport without restarting the target process.
Instrumentation hook
a call the target's own runtime makes into LRSI at a defined lifecycle point.
Keyframe
a full StateSnapshot captured periodically as a replay anchor point.
Logical clock
a monotonic, per-session ordering value independent of wall-clock time.
Node identity (NodeId)
the stable identifier assigned to a tracked live object within a session.
Observer effect
the phenomenon where the act of inspecting a system changes its behavior.
Query engine
the component compiling and evaluating QuerySpec predicates over snapshots and events.
QuerySpec
a typed predicate/projection request against nodes, edges, or events.
Redaction rule
a path-pattern rule stripping a field before it crosses the trust boundary.
Reference model
the strategy (weak vs. strong) governing how snapshots hold onto live objects.
Reconnect / resume
re-establishing a dropped transport connection under the same SessionId.
Resumption token
the credential presented to resume a session after a transport drop.
Ring buffer
a fixed-capacity, oldest-evicted-first data structure.
Saved view
a named, persisted QuerySpec recallable within a session.
Scrub cursor
the current position within a session's replay timeline.
Serializer
the component walking a live object graph into a StateSnapshot.
Session
the bounded lifetime of one attach-to-detach relationship between a target and the backend.
Session manager
the backend component owning the session lifecycle state machine.
Signal
a fine-grained reactive primitive whose reads/writes are individually tracked.
Snapshot (StateSnapshot)
a versioned, cycle-safe serialization of live target state at a point in logical time.
Structured clone
the HTML-spec algorithm for deep-copying values, whose cycle/type limitations motivate LRSI's own serializer design.
Subscription
a registered interest in future state changes matching a QuerySpec.
Time scrub
navigating to an arbitrary historical point in a session's retained data.
Transport
the WebSocket-based wire connection carrying TransportMessages.
Trust boundary
a point in the architecture across which data crosses from one security domain to another.
Truncation marker
a schema field declaring that a subtree was deliberately cut short.
Weak reference
a reference that does not prevent garbage collection of its target.
