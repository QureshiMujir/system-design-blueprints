ADR-01

Language

Chosen

TypeScript strict, end to end

Rejected

Rust/WASM hooks, Go backend, Python backend

When the rejected choice is right

a non-JS target runtime would justify a polyglot hook; out of scope here

Why: shared type surface across hook/wire/UI eliminates a translation boundary

ADR-02

Build system

Chosen

pnpm workspaces + esbuild (hooks), Vite (UI)

Rejected

Bazel, Nx, Turborepo

When the rejected choice is right

Bazel wins once the org runs >5 independently-releasing polyglot packages needing remote caching

Why: minimal config overhead for a single-org monorepo

ADR-03

Dependency policy

Chosen

zero runtime deps in @lrsi/hooks

Rejected

lodash/ramda in hook path

When the rejected choice is right

a UI-only package may take a utility dep freely — it never runs in the target process

Why: I1 forbids allocation-heavy utility deps on the hot path

ADR-04

Instrumentation strategy

Chosen

runtime monkey-patch of framework-exposed hook points

Rejected

compiler transform (Babel/SWC plugin), CDP-only introspection

When the rejected choice is right

compiler transform wins when the target's bundler cannot be hooked into post-hoc (§36 alt. A)

Why: matches the zero-build-step goal; compiler transform couples to a specific bundler

ADR-05

Snapshot serialization format

Chosen

internal SerializedValue tagged union → CBOR (RFC 8949)

Rejected

JSON, MessagePack, Protocol Buffers

When the rejected choice is right

Protocol Buffers wins with a fixed low-cardinality schema and cross-language codegen needs

Why: CBOR supports canonical encoding plus native BigInt/binary without a schema compiler

ADR-06

Cycle handling

Chosen

visited-WeakMap cycle detection emitting CycleRef

Rejected

unbounded deep clone, reference counting

When the rejected choice is right

naive structured clone wins only for a priori acyclic fixtures used in §28 differential tests

Why: structured-clone semantics throw on cycles unless handled; LRSI must never throw mid-snapshot

ADR-07

Reference model

Chosen

WeakRef-backed NodeId table, FinalizationRegistry-pruned

Rejected

strong id-table (Map)

When the rejected choice is right

a strong table wins only inside the bounded conformance harness (§28), process-scoped lifetime

Why: I2 — a snapshot must never prevent GC

ADR-08

Transport protocol

Chosen

WebSocket (RFC 6455), CBOR payload

Rejected

raw TCP socket, SSE, HTTP long-poll

When the rejected choice is right

SSE wins for a read-only, CORS-constrained embed with no query-dispatch channel

Why: bidirectional, low-latency, matches the existing devtools/remote-debug port model

ADR-09

Reconnect strategy

Chosen

exponential backoff + resumption token, hot-reload-aware buffer replay

Rejected

full session teardown/recreate per disconnect

When the rejected choice is right

teardown/recreate wins for the remote bridge (Phase 10) where a resumption token is itself untrusted

Why: hot reload disconnects every few seconds during active dev; teardown/recreate thrashes UI state

ADR-10

Event-log eviction policy

Chosen

fixed-capacity ring buffer, oldest-evicted-first, keyframe-preserving

Rejected

When the rejected choice is right

Why: I11 — the log must be bounded regardless of target event rate

ADR-11

Roads not taken (§36)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

A — Compiler-Transform Instrumentation

Source (.tsx) → [Babel/SWC LRSI Plugin] → Instrumented Bundle
                        │
                        ▼
              inserted onMount/onUpdate/onEvent
              calls at every state-touching AST node
                        │
                        ▼
              Bundle ships with hooks already baked in,
              no runtime monkey-patch needed

Winning regime: build systems where a custom bundler or non-standard component model makes runtime monkey-patching unreachable. Real embodying systems: Svelte's own compiler (rewrites reactive assignments at build time) and Solid's JSX compiler transform. Rejected because it couples LRSI to a specific build tool per target, breaking the zero-build-step deployment model (§1, ADR-04), and fails silently for any dynamically-loaded or eval'd code the transform never saw.

B — CDP-Only, No In-Process Agent

Target (V8) ⇄ [V8 Inspector Protocol] ⇄ [LRSI Backend as CDP client]
                                              │
                                              ▼
                                        UI Client
        (no @lrsi/hooks in the target realm at all)

Winning regime: introspecting engine-level primitives (heap, call stack, breakpoints) without touching the app's own code. Real embodying system: Chrome DevTools itself. Rejected because CDP exposes engine concepts (objects, scopes, heap), not framework concepts (components, signals, effects); reconstructing a dependency graph purely from CDP-level object graphs would mean re-implementing framework-internals knowledge at the protocol-consumer layer instead of inside an adapter (ADR-04) — strictly harder and less maintainable.

C — Full Deterministic Record/Replay

Target Process (recorded via OS-level trace, a la rr)
        │  full instruction/syscall trace
        ▼
  [Recording Store] ── pure viewer ──▶ [LRSI UI]
   (no live attach; replay only, bit-accurate)

Winning regime: a single, fully-controlled native process where total reversibility matters more than live interactivity. Real embodying system: rr / Pernosco (O'Callahan et al., USENIX ATC 2017) and Microsoft Time Travel Debugging. Rejected because it requires OS/kernel-level trace capture that cannot observe a JS heap from outside its own realm without unacceptable overhead and platform coupling, and it answers "what did the CPU do" rather than "what did the reactive graph do."

D — Log-Only Exporter, No Live Attach

Target → [Event Exporter] → OTel Collector → External Trace Viewer
   (fire-and-forget spans/events; no session, no attach, no scrub)

Winning regime: production observability where live attach is explicitly undesirable and historical trend analysis matters more than a single debugging session. Real embodying system: standard OpenTelemetry-instrumented production monitoring stacks. Rejected because this is precisely the production-APM non-goal from §1 — it answers "what happened in aggregate," not "why did this specific re-run happen right now," and has no notion of a live, queryable, time-scrubbing session at all.
