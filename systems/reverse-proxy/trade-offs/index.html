ADR-01

Language & runtime model

Chosen

Rust 2024, Tokio

Rejected

Go; C; C++

When the rejected choice is right

an all-Go platform already exists, hiring pool skews Go, or the latency budget is >10 ms (GC pause tolerable)

Why: no GC pause on the p99-bounded hot path (§4); borrow checker forecloses the historical CVE class in C/C++ proxies

36. Alternative Architectures (Roads Not Taken)

Alternative 1 — Thread-per-connection, blocking I/O.

  conn 1 ──► [ OS thread, blocking read()/write() ]
  conn 2 ──► [ OS thread, blocking read()/write() ]
  conn N ──► [ OS thread, blocking read()/write() ]

Regime where it wins: low concurrency (< 1,000 conns/node) or workloads where per-request CPU dominates I/O wait, and where async-runtime complexity is not worth paying for. Real system: Apache httpd's prefork/worker MPM. Why rejected: does not scale to the 500,000-connection ceiling (§4) — a thread per connection at that scale exhausts kernel scheduler capacity and per-thread stack memory far before the event-driven model's limits are reached.

Alternative 2 — Kernel-space/eBPF (XDP) accelerated pre-filter.

  NIC ──► [ eBPF/XDP: drop/allow/simple-route in-kernel ] ──► userspace L7 proxy (only survivors)

Regime where it wins: extreme throughput floors (millions of rps) where even a userspace event-loop is the bottleneck, e.g. DDoS-scrubbing edges. Real system: Cloudflare's XDP-based L4 mitigation layer, deployed in front of (not instead of) a Pingora-style L7 proxy. Why rejected: eBPF/XDP cannot run arbitrary WAF regex evaluation, Wasm sandboxing, or the RFC 9111 cache state machine — it is a complementary L4 pre-filter, never a substitute for this system's L7 request-awareness (§1 scope).

Alternative 3 — Fully declarative, control-plane-driven (xDS-native).

  Control plane (Istio-style) ──stream(xDS)──► Data plane (no local config file)

Regime where it wins: large multi-team service-mesh deployments where centralized policy must be the single source of truth and per-node config drift is itself the threat model. Real system: Envoy inside Istio. Why rejected: couples every deployment to running a control plane (§1 non-goals explicitly exclude this); this blueprint keeps xDS a Phase-11+ adapter (§9 ADR-15) so the common single-team, single-config-file case never pays that coupling cost.

Alternative 4 — Pure Layer-4 (TCP/UDP) passthrough, SNI-only routing.

  client ──TCP──► [ SNI sniff, no HTTP parse ] ──TCP──► origin (TLS terminates at origin)

Regime where it wins: extreme low-latency requirements where even microsecond-scale request parsing is unacceptable (e.g. HFT gateways), or where TLS must terminate only at the origin for compliance. Real system: LVS/IPVS, or HAProxy in mode tcp. Why rejected: forecloses every feature this system exists to provide — path/header/JWT routing, RFC 9111 caching, the WAF, transformation — this is the Load-Balancer document's domain (§1, §33), a different system by definition, not a rejected parameter of this one.
