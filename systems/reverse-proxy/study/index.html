Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does the p99 added-latency target (§4) force a lock-free connection-pool checkout (§14) rather than a mutex-guarded one, and what does §30's M6 gate actually verify about that choice?
  2. Trace how a hot reload (§23) interacts with an in-flight WebSocket connection (§22) that started under the old Config generation — which invariant (§7 I1) guarantees it never observes the new generation mid-stream, and what bounds how long the old generation can be held (§25 FM-4)?
  3. Why is power-of-two-choices (§14) the default load-balancing policy instead of least-connections, given both are sub-linear, and what real-world regime (§33) would flip that default?
  4. What chain of RFC 9111 clauses (§16) must all hold before a response carrying Authorization is shared-cached, and which invariant (§7 I5/I12) enforces the "never" half structurally rather than by convention?
  5. An edge program (§21) and the WAF (§20) are both configured on the same route — which evaluates first, why does that ordering matter for the security boundary (§7 I11), and what would break if it were reversed?
  6. Derive, from §4's constraints and §34's capacity model, whether this system's bottleneck at high average response size is CPU or network bandwidth — and which §31 lever addresses each case differently.
  7. Why does the fresh-handshake TLS p99 target (§4, §30 M9) tolerate 10× the resumed-session target (M8), and what does that asymmetry imply about the session-ticket rotation policy in §17?
  8. Walk through why a retry (§14) is only safe for idempotent methods or a strictly-pre-write failure, citing the paper (§5 Dean & Barroso) that motivates bounding retry fan-out at all.
  9. Compare this design's no-cross-node-cache-coherence decision (§31) against Envoy's and NGINX's approaches (§33) — why is this the correct choice given the non-goals in §1?
  10. Why must the ACME account key be confined to a single orchestrator node (§7 I13, §18) rather than replicated for availability, and what alternative architecture (§36) would remove that single point of coordination, at what cost?
  11. Using §9 ADR-08 (own cache implementation) and ADR-13 (xxhash-3 keying), explain why cache correctness risk and cache-key latency were treated as two separately optimized decisions rather than bundled into "use an existing crate."
  12. Which §30 M-series targets would regress if the edge-program budget defaults (§7 I7, §21) were loosened from 1 ms/2 MiB to 10 ms/20 MiB, and via §34's capacity-derivation method, how would you predict the regression's magnitude before measuring it?
  13. Why does §22's HPACK-error policy (close the connection, never attempt resync) generalize to QPACK in HTTP/3, and what mental model (§32 MM1) explains why "attempt partial recovery" is the wrong instinct for any framing-layer desync?
  14. Trace a slowloris attack (§24 T2) through the connection lifecycle state machine (§8) — at which state does the mitigation intervene, and why would moving that defense one state later (into the request pipeline instead of the listener) fail against this specific attack shape?
  15. Why is the xDS adapter in the Deferred Features Register (§37) architected as a translation layer producing the same Config type (§11) rather than a parallel code path, and what ADR (§9 ADR-15) locks that decision in?
  16. Given the bottleneck ordering in §31, which phase (§12–§23) would you build first for a green-field service-mesh-sidecar deployment instead of a public-ingress one, and why does §1's non-goals section make that a different answer than the one this blueprint locked in?
  17. Derive the minimum disk-tier size (§4) needed to keep cache-miss origin load under a target threshold, using §34's object-count derivation — what operational lever (§26) would you pull if that minimum exceeds the configured ceiling?
  18. Why does §27's compatibility policy version the disk cache-tier format independently from ConfigVersion, and what failure mode (§25 FM-10) would result if the two were conflated into a single version number?
  19. Compare the "sandbox is a budget, not a promise" mental model (§32 MM5) against Pingora's extension model (§33) — does Pingora's approach make the same guarantee, and if not, what threat (§24 T6) does this design close that Pingora's model does not?
  20. Using the worked example in §8, identify every §7 invariant that request touches on its happy path, and explain why the malformed-input example in the same section touches a strict subset of those invariants rather than all of them.

32. Mental Models & First Principles

  • MM1 — A connection is a state machine, not a byte pipe. Predicts: every protocol bug is a missed or malformed state transition. Without it: ad-hoc flag-based logic that cannot express valid transition ordering, the root shape of the smuggling and desync bug classes. Applied in §8, §12.
  • MM2 — Config is a value, not a place. A Config generation is immutable once compiled; reload produces a new value, never mutates the old one in place. Predicts: hot reload is safe exactly when no code holds a mutable reference across generations. Without it: reload races and dropped in-flight requests. Applied in §11, §23, §7 I1.
  • MM3 — The pool owns trust, not the connection. A pooled connection is guilty (untrusted) until health-checked; trust is a property the pool asserts, not one the connection carries. Predicts: errors compound only until the poisoned connection is excised, never further. Without it: error amplification across otherwise-healthy traffic sharing a bad connection. Applied in §14, §7 I3, §6 P7.
  • MM4 — Cache correctness is a freshness proof, not a TTL guess. Every serve decision must cite the RFC 9111 clause that permitted it. Predicts a cache that never "mostly" follows the spec. Without it: silent staleness or over-caching of security-sensitive responses. Applied in §16, §6 P3.
  • MM5 — A sandbox is a budget, not a promise. Safety holds even against adversarial code because the runtime enforces limits unconditionally, never because the program cooperates. Predicts a bounded blast radius regardless of program intent. Without it: the standard multi-tenant-plugin failure mode — trusting "well-behaved" code. Applied in §21, §6 P6, §7 I7.
  • MM6 — Backpressure is a design decision, not an accident. Every queue has a bounded depth and an explicit rejection policy. Predicts unbounded queues always eventually become an outage. Without it: OOM under a slow-downstream/fast-upstream (or reverse) mismatch. Applied in §6 P11, §14.
  • MM7 — Every constraints-table number is a promise the architecture keeps, derived, not asserted. Predicts a system whose §4 numbers cannot be traced to a design choice is unreviewable by definition. Without it: an architecture that "feels fast" with no basis for its SLO. Applied in §4, §34.
  • MM8 — Two truths about time: wall-clock for humans, monotonic for correctness. Predicts that an NTP jump or leap second must never perturb a timeout comparison or freshness calculation. Without it: reload/health-check flapping correlated with clock adjustments rather than real signal. Applied in §6 P12, §12.

5. Required Reading

Books

  • Grigorik, High Performance Browser Networking, O'Reilly, 2013 — ch. 11 (HTTP/1.1), ch. 12 (HTTP/2), ch. 13 (HTTP/3-adjacent transport). Applied in §22 (protocol codecs) and §5's own RFC cross-reads.
  • Kleppmann, Designing Data-Intensive Applications, O'Reilly, 2017 — ch. 5 (replication/staleness reasoning), ch. 8 (distributed-system trouble: partial failure). Applied in §16 (cache staleness model) and §7 (invariant enforcement reasoning).
  • Kerrisk, The Linux Programming Interface, No Starch Press, 2010 — ch. 63 (epoll), ch. 44 (sockets). Applied in §12 (listener accept-loop design).
  • Bos, Rust Atomics and Locks, O'Reilly, 2023 — ch. 4 (atomics), ch. 9 (building a lock-free structure). Applied in §14 (lock-free connection-pool checkout, ADR-driven).
  • Kurose & Ross, Computer Networking: A Top-Down Approach, Pearson, 8th ed. — ch. 8 (network security, TLS). Applied in §17 (TLS termination).
  • Newman, Building Microservices, O'Reilly, 2nd ed., 2021 — ch. 5 (communication styles, the reverse-proxy-as-ingress pattern). Applied in §2 and §33 (comparative architecture framing).

Papers

  • Dean & Barroso, "The Tail at Scale," Communications of the ACM 56(2), 2013 — hedged requests, tail-latency amplification under fan-out. Applied in §14 (2.2, retry budget) and §37 (hedged requests, deferred).
  • Mitzenmacher, "The Power of Two Choices in Randomized Load Balancing," IEEE Transactions on Parallel and Distributed Systems 12(10), 2001 — P2C's exponential improvement over random/RR under load imbalance. Applied in §14 (default LB policy, ADR justification).
  • Karger, Lehman, Leighton, Panigrahy, Levine, Lewin, "Consistent Hashing and Random Trees," STOC, 1997 — bounded remapping on membership change. Applied in §14 (ConsistentHash policy).
  • Fielding, "Architectural Styles and the Design of Network-based Software Architectures," PhD dissertation, UC Irvine, 2000 — the cache/proxy/layered-system constraints of REST. Applied in §3 (pipeline layering) and §16 (cache semantics framing).
  • Kegel, "The C10K Problem," kegel.com, 1999 (rev. 2006) — event-driven vs. thread-per-connection concurrency at scale. Applied in §12 (listener architecture, ADR-16/ADR-17).
  • Ousterhout, "Always Measure One Level Deeper," Communications of the ACM 61(7), 2018 — profiling methodology beyond aggregate CPU%. Applied in §30 (Performance Engineering methodology).
  • Barroso & Hölzle, "The Datacenter as a Computer," Synthesis Lectures on Computer Architecture, Morgan & Claypool, 2009 — capacity planning and tail-latency-at-scale reasoning. Applied in §31 (Scalability Analysis) and §34 (Back-of-Envelope Capacity Model).
  • Varghese & Lauck, "Hashed and Hierarchical Timing Wheels," SOSP, 1987 — O(1) amortized timer management. Applied in §12 (0.2, per-connection idle/read timeout implementation).

Reference Implementations

  • NGINX (nginx/nginx) — src/http/, src/event/. The state-machine request model (ngx_http_request.c) and upstream layer (ngx_http_upstream.c). Applied in §12 (Phase 0 codec/state-machine shape) and §13 (routing).
  • Envoy (envoyproxy/envoy) — source/common/http/, source/common/router/, source/extensions/filters/http/. The HTTP filter-chain abstraction. Applied in §13 (routing matrix ordering) and §20 (WAF as a filter stage). Pitfall: do not copy Envoy's xDS-first coupling into the native config path (§37 keeps xDS a separate adapter).
  • Pingora (cloudflare/pingora) — pingora-proxy/, pingora-core/. The closest Rust reference at Cloudflare's operating scale. Applied in §14 (connection-pool design).
  • HAProxy (haproxy/haproxy) — src/proxy.c, src/check.c. Load-balancing algorithms and health-check state machine. Applied in §14 (LB policies, health-check states).
  • Caddy (caddyserver/caddy) — modules/caddytls/. ACME-by-default certificate automation. Applied in §18 (ACME provisioning). Pitfall: Caddy's automatic HTTPS assumes a single-node ACME owner; §18 (6.6) documents the multi-node caveat explicitly rather than copying the assumption silently.

Glossary (§38) · 48 terms · site-wide glossary

ALPN
Application-Layer Protocol Negotiation; TLS extension selecting h1/h2/h3 during the handshake (§17).
SNI
Server Name Indication; the plaintext hostname sent in ClientHello, used for cert selection (§17).
HPACK
HTTP/2's header-compression format with a stateful dynamic table (§22).
QPACK
HTTP/3's header-compression format, decoupled from stream ordering (§22).
Backpressure
an explicit, bounded rejection policy applied when a queue would otherwise grow without limit (§6 P11).
Circuit breaker
a per-endpoint state machine that stops sending traffic to a failing endpoint before every request against it times out individually (§14).
Consistent hashing
a hashing scheme where membership changes remap only a bounded fraction of keys (§14, §5 Karger et al.).
Content-Length
the HTTP header declaring a fixed request/response body length in bytes.
Chunked transfer-encoding
an HTTP/1.1 body-framing mode using length-prefixed chunks terminated by a zero-length chunk (§12).
Cache stampede
a burst of simultaneous origin requests caused by many clients missing the cache for the same resource at once (§25 FM-2).
Cold handshake
a full TLS handshake with no resumed session, the more expensive of the two handshake paths (§4, §30 M9).
Session resumption
reusing a previously negotiated TLS session's keys via a ticket or ID to skip the full handshake (§17).
OCSP stapling
the server attaching a signed certificate-revocation-status response to the handshake instead of the client querying the CA directly (§17).
mTLS
mutual TLS; both peers present and verify certificates (§17, §19).
JWKS
JSON Web Key Set; the published set of public keys used to verify JWT signatures (§19).
Anomaly scoring
a WAF technique where each matched rule contributes to a cumulative score that trips a block threshold, rather than any single match blocking alone (§20).
CRS
the OWASP Core Rule Set, a portable WAF rule baseline (§5, §20).
Fuel
(Wasm) — wasmtime's instruction-metering mechanism used to bound a guest program's CPU consumption (§21).
Epoch interruption
wasmtime's mechanism for bounding a guest program's wall-clock execution time independent of fuel (§21).
Wasm Component Model
a WebAssembly extension standardizing cross-language component interfaces (WIT), used for the edge-program host ABI (§21).
WASI
the WebAssembly System Interface, a standardized set of host capabilities for Wasm guests (§21).
LuaJIT
a just-in-time compiling implementation of Lua, embedded via mlua (§21).
Token bucket
a rate-limiting algorithm allowing bursts up to a bucket capacity while enforcing a steady-state refill rate (§20, §9 ADR-11).
P2C
power-of-two-choices; sample two candidates, pick the less-loaded (§14, §5 Mitzenmacher).
Round robin
cyclic, fixed-order endpoint selection (§14).
Least connections
selecting the endpoint with the fewest in-flight requests (§14).
Active health check
a proxy-initiated periodic probe against an upstream endpoint (§14).
Passive health check
inferring endpoint health from the outcome of real proxied requests (§14).
Ejection
removing an endpoint from selection eligibility after a health-check failure threshold (§7 I10, §8).
Probation
a capped-traffic re-admission state between Ejected and Healthy (§8).
Hop-by-hop header
a header meaningful only for one transport hop, never forwarded across a proxy boundary (§6 P14, section 7.6.1 of RFC 9110).
Vary header
an HTTP response header naming request headers a cache must also key on (§16).
Surrogate key
an out-of-band cache tag enabling bulk invalidation across many cached entries at once (§16).
Stale-while-revalidate
serving a stale cached response while a background request refreshes it (§16).
RTO
Recovery Time Objective; the target maximum time to restore service after a failure (§4).
SLO
Service Level Objective; an internal target a system is held to (§26).
Trailers
headers sent after a chunked or HTTP/2 body, rather than before it (§12, §22).
Extended CONNECT
the RFC 8441 mechanism bootstrapping WebSocket over HTTP/2 (§22).
0-RTT
TLS 1.3's zero-round-trip early-data mode, replay-vulnerable and restricted to idempotent methods here (§22, §24 T12).
Slowloris
an attack sending data slowly enough to hold a connection open without triggering a byte-level timeout (§24 T2).
Request smuggling
exploiting disagreement between two HTTP parsers over where one request ends and the next begins (§8, §24 T1).
ReDoS
Regular-expression Denial of Service via catastrophic backtracking (§24 T10).
SBOM
Software Bill of Materials; a manifest of a build's dependency graph (§29).
Reproducible build
a build process guaranteed to produce bit-identical artifacts from the same source (§29).
Generation
(Config) — one immutable, atomically-swapped version of the compiled Config (§7 I1, §11, §23).
Graceful drain
completing in-flight requests before closing a connection during shutdown or reload, rather than aborting them (§6 P1, §12).
Radix tree
a compressed prefix tree used here for longest-prefix-wins path routing in sub-linear time (§13).
Timing wheel
an O(1)-amortized data structure for scheduling large numbers of timeouts (§5 Varghese & Lauck, §12).
