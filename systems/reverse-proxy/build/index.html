⬜ Phase 0 — Repo Skeleton & Correctness Kernel §12

Objectives

Stand up the Cargo workspace (§10) and land the smallest system that is a real reverse proxy: an HTTP/1.1 listener, a fixed route, a health-checked upstream pool, an access log, and a hot-reload path. This phase establishes the concurrency model (one Tokio task per connection, §3 box C) and the correctness kernel — invariants I1, I2, I3, I4, I14 must all hold by the end of this phase, not be deferred to a later one.

Deliverable

revp binary proxying HTTP/1.1 between a downstream client and a static two-endpoint upstream pool; examples/minimal-h1.yaml runs end-to-end against a mock upstream.

Acceptance

Conformance bucket h1/basic at 100% Pass against NGINX-1.27-captured golden fixtures; p99 added latency < 2 ms at 25,000 rps/core (the Phase-0 floor — §4's 100,000 rps/core target is reached at §22); zero dropped connections across 100 consecutive SIGHUP reloads under 5,000 rps background load.

Fixtures

h1/basic/keep-alive-reuse.toml — one TCP connection serves 10 sequential requests, expect a single upstream connection reused; h1/smuggling/cl-te-conflict.toml — expect 400 and immediate connection close; h1/basic/chunked-trailers.toml — expect trailers preserved end-to-end; reload/sighup-zero-drop.toml — expect 0 dropped requests across a reload at 10,000 rps.

Pitfalls

Mis-parsing the 0\r\n\r\n chunked end-marker truncates responses silently; Connection: close must be honored independently on the downstream and upstream sides (a downstream close does not imply the upstream connection should close, and vice versa); a 200 from a synthetic liveness path is not proof the service can serve the routes actually configured — the active health check must probe a real route path.

⬜ Phase 1 — Routing Matrix §13

Objectives

Replace Phase 0's single hardcoded route with a compiled, priority-ordered routing matrix: host/path/method/header/JWT-claim/query matching, longest-prefix-wins path semantics, and an admin-only debug header naming the matched route (P2).

Deliverable

A compiled routing table serving all matcher dimensions against the Phase-0 listener; x-route-id observable via the admin API stub.

Acceptance

Routing table compiles 10,000 routes in < 100 ms; route lookup is O(log n) worst case, O(1) amortized for prefix/exact paths via the radix tree; conformance bucket routing/all at 100% Pass against Envoy-v1.32-captured fixtures; a 5,000-route / 1,000,000-synthetic-request fuzz run completes with zero panics.

Fixtures

routing/host-wildcard-suffix.toml; routing/path-longest-prefix-wins.toml; routing/regex-timeout-rejected.toml — expects a pathological regex route to time out and fall through priority rather than hang the worker; routing/host-sni-vs-authority-precedence.toml.

Pitfalls

Unbounded regex routes are a denial-of-service surface — cap at 1,000 regex routes by default and reject configurations that exceed it (I9); /foo/../bar, /foo//bar, and /foo%2Fbar each need an explicit normalization policy or routes silently diverge from operator intent; the Host header, the TLS SNI, and the HTTP/2 :authority pseudo-header can disagree — canonicalize explicitly rather than picking whichever the codec happens to expose first.

⬜ Phase 2 — Upstream Pool & Load Balancing §14

Objectives

Build the full upstream layer: endpoint resolution, a lock-free connection pool with HTTP/1.1 keep-alive and HTTP/2 multiplexing, the five load-balancing policies (§8), active and passive health checking (§8 state machine), a circuit breaker, and a method-aware retry policy (P7).

Deliverable

revp-upstream sustaining multi-endpoint pools with live health-check state transitions observable via the admin status endpoint stub.

Acceptance

Pool sustains 50,000 in-flight requests across 100 upstream endpoints with no connection thrash (checkout p99 < 20 µs); P2C selection beats round-robin on tail latency by ≥ 30% in the benchmarks/routed_1k.rs harness under a synthetic heterogeneous-latency backend mix; conformance bucket upstream/all at 100% Pass.

Fixtures

upstream/ejection-and-reprobe.toml; upstream/p2c-tail-latency.toml; upstream/retry-idempotent-only.toml — expects a POST never retried after a partial write; upstream/dns-ttl-respected.toml.

Pitfalls

Connection-pool contention is the primary bug source — a single global mutex around checkout collapses throughput at the 50,000-in-flight target; DNS refreshed too aggressively burns resolver QPS, too lazily routes to dead endpoints (min(TTL, 30s) is the balance point); retries that ignore request-body replay for non-idempotent methods leak side effects (double-charge class bugs).

⬜ Phase 3 — Request/Response Transformation §15

Objectives

Implement the Transform chain (§11): header set/remove/rename, path rewrite, bounded body rewrite, redirects, request/response injection — applied per-scope, in configured order, bidirectionally around the upstream call.

Deliverable

A configurable transform chain executing around the Phase-2 upstream call, exercised by examples/edge-rewrite.yaml.

Acceptance

Transform chain executes in < 10 µs for a typical 5-rule chain (measured in benchmarks/routed_1k.rs); conformance bucket transform/all at 100% Pass; body rewrites correctly bypass and flag (x-rewrite-skipped) any payload exceeding the 1 MiB default cap.

Fixtures

transform/header-rewrite-roundtrip.toml; transform/hop-by-hop-stripped.toml; transform/body-rewrite-cap-exceeded.toml; transform/redirect-templated-location.toml.

Pitfalls

A body rewrite that must simultaneously stream, buffer, and stay within a byte bound is the primary bug source — each rule must declare which mode it runs in and document the consequence of exceeding the cap; header capitalization is preserved on the wire even though comparison is case-insensitive (some legacy clients break on case changes the proxy did not intend to make).

⬜ Phase 4 — RFC 9111 Caching Layer §16

Objectives

Implement the cache as a literal reading of RFC 9111 (P3): key construction, cacheability decision, freshness lifetime, validator-based revalidation, stale-while-revalidate/stale-if-error, surrogate-key invalidation, and a two-tier store (in-memory LRU + optional disk tier).

Deliverable

revp-cache serving as CacheStore (§11) behind the Phase-3 pipeline; examples/ cache-with-surrogates.yaml demonstrating tag-based invalidation end to end.

Acceptance

Cache passes the httpwg/9111-cache-tests suite at 100%; surrogate-key invalidation propagates across the in-process cache in < 100 ms; cache lookup p99 < 50 µs (§30 M11); conformance bucket cache/all at 100% Pass.

Fixtures

cache/vary-accept-encoding.toml (§10 example scenario); cache/set-cookie-stripped.toml; cache/stale-while-revalidate.toml; cache/surrogate-key-purge-propagation.toml.

Pitfalls

Vary cardinality explosion (I5) if not capped; caching an Authorization-bearing response without an explicit public directive leaks one user's data to another; heuristic freshness without an explicit cap surprises operators who expected a no-cache-adjacent default.

⬜ Phase 5 — TLS Termination & SNI Routing §17

Objectives

Terminate TLS 1.3 (and optional 1.2 fallback) with SNI-based certificate selection, ALPN negotiation across h1/h2/h3, OCSP stapling, optional mTLS to both client and upstream, and key-material hygiene (P4, I6).

Deliverable

TLS-terminating listener serving SNI-routed certs over the Phase-0–4 pipeline; examples/tls-acme.yaml scaffold (cert provisioning itself lands in §18).

Acceptance

10,000 distinct SNI mappings load in < 5 s and resolve in < 10 µs each; TLS handshake p99 < 5 ms resumed / < 50 ms fresh (§4, §30 M8/M9); conformance bucket tls/all at 100% Pass including the 1.2-fallback path (opt-in, default 1.3-only).

Fixtures

tls/sni-wildcard-resolution.toml; tls/ocsp-staple-fresh.toml; tls/passthrough-no-decrypt.toml — asserts the proxy process never holds a decrypted byte for a passthrough route; tls/mtls-upstream-chain-validated.toml.

Pitfalls

Session-ticket key reuse across processes silently breaks forward secrecy — each process generates and rotates its own key unless an explicit cluster-wide KMS integration is configured; a failed OCSP fetch must not block cert loading (the cert loads unstapled and an alert fires, §26); SNI is plaintext on the wire absent ECH (deferred, §37).

⬜ Phase 6 — ACME Automatic Certificate Provisioning §18

Objectives

Automate certificate issuance and renewal against an ACME v2 directory (Let's Encrypt), so operators never run a manual cert pipeline; wraps the CertResolver from §17 rather than replacing it.

Deliverable

revp obtains and auto-renews a cert against the Pebble test ACME server with zero manual steps after initial account creation.

Acceptance

Fresh install obtains a Let's Encrypt staging cert in < 30 s (§30 M10); renewal under 5,000 rps background load drops zero requests; conformance bucket acme/all at 100% Pass against Pebble.

Fixtures

acme/http01-challenge-roundtrip.toml; acme/dns01-provider-route53.toml; acme/renewal-zero-drop.toml; acme/rate-limit-batching.toml.

Pitfalls

Let's Encrypt production enforces a hard 50 certs/registered-domain/week limit — batch SAN-bundled certs or the deployment silently stalls issuance; account-key compromise is catastrophic and total, which is why I13 confines it to one orchestrator node; clustered ACME without leader election races on challenge state (documented as a single-node-ACME default, multi-node as an explicit opt-in in docs/acme.md).

⬜ Phase 7 — Authentication & Authorization §19

Objectives

Implement the four authentication schemes (Basic, JWT, OAuth introspection, mTLS) producing a Principal (§11) the router and downstream stages can act on, with auth chains (any-of/all-of/ none) and per-route failure responses.

Deliverable

revp-auth producing Principal values consumed by the router (§13 jwt_claims matcher) and the access log; examples/jwt-routing.yaml.

Acceptance

JWKS rotation completes in < 100 ms with zero failed verifications during the swap (overlap window covers both old and new keys); conformance bucket auth/all at 100% Pass.

Fixtures

auth/jwt-alg-none-rejected.toml; auth/jwks-rotation-overlap.toml; auth/oauth-introspection-cache-ttl.toml; auth/mtls-principal-from-chain.toml.

Pitfalls

Fetching JWKS on every request is the primary bug source — cache respecting the JWKS endpoint's own Cache-Control: max-age (default 1 h if absent) is mandatory; a revocation event must propagate through the introspection cache invalidation path or a revoked token stays accepted until its cached TTL expires.

⬜ Phase 8 — Web Application Firewall & Rate Limiting §20

Objectives

Implement a WAF rule engine (OWASP CRS v4.x subset, ADR-10) with anomaly scoring, detect/block modes, and integrate token-bucket rate limiting (ADR-11) per IP/JWT-subject/API-key — enforced strictly before any upstream connection opens (P5, I11).

Deliverable

revp-waf evaluated as a mandatory pre-upstream pipeline stage (§3 box C); examples/ waf-mode.yaml demonstrating detect-then-block promotion.

Acceptance

WAF processes a 1 KB request through 200 rules in < 50 µs (§30 M12); false-positive rate against a captured production-traffic sample < 0.1% at the default score threshold; conformance bucket waf/all at 100% Pass including the CRS test corpus.

Fixtures

waf/sqli-crs-corpus.toml; waf/xss-crs-corpus.toml; waf/ordering-before-upstream.toml (I11); waf/regex-timeout-bounded.toml.

Pitfalls

Regex denial-of-service is the primary bug source — every WAF regex is compiled with the same timeout/instruction budget as routing (I9); enabling body inspection without a byte cap buffers unbounded request bodies; false positives in production require rule tuning, which is why detect-only is the shipped default and block requires explicit opt-in.

⬜ Phase 9 — Edge Programs: Wasm + Lua Sandboxing §21

Objectives

Let tenants run small request/response-transforming programs (Wasm or Lua) inside the pipeline under a hard, runtime-enforced resource budget (P6) — never relying on the program's cooperation.

Deliverable

revp-edge-wasm and revp-edge-lua invoked as an optional pipeline stage (§3 box J); examples/edge-rewrite.yaml running a Rust-compiled Wasm filter.

Acceptance

Wasm filter overhead < 100 µs for a no-op program (§30 M13); Lua filter overhead < 50 µs (§30 M14 — note: table cites both under the M-series, §30); conformance bucket edge/all at 100% Pass including Rust-, TinyGo-, and AssemblyScript-compiled Wasm filters.

Fixtures

edge/wasm-fuel-exhaustion-reject.toml; edge/lua-sandbox-escape-blocked.toml; edge/proxy-wasm-abi-compat.toml; edge/host-function-allowlist-enforced.toml.

Pitfalls

Fuel exhaustion mid-request is the primary bug source — the action on exhaustion is configurable (pass-through, reject, terminate; default reject, P6); Lua sandbox escape via string.format or debug-library access is closed by removing both from the sandboxed _G; a Wasm module that calls a host function per byte of body data is pathological — a streaming on_request_body_chunk ABI amortizes the call cost.

⬜ Phase 10 — HTTP/2, gRPC, HTTP/3, WebSocket, SSE §22

Objectives

Reach full downstream/upstream protocol parity: HTTP/2 with HPACK, gRPC framing and trailers, HTTP/3 over QUIC with QPACK, WebSocket proxying, and Server-Sent Events streaming — hitting the 100,000 rps/core defining target (§4) on HTTP/1.1 and HTTP/2.

Deliverable

Full protocol parity across the listener (box B) and upstream layer (box E); conformance buckets h2, h3, grpc, ws, sse all wired into the harness.

Acceptance

HTTP/1.1 and HTTP/2 sustain 100,000 rps/core on the no-op route (§4, §30 M1/M2); HTTP/3 sustains 75,000 rps/core (the documented QUIC-overhead gap, §30 M3); WebSocket proxying holds 100,000 concurrent connections/node (§30 M15); SSE holds 50,000 concurrent connections/node with a 15 s heartbeat (§30 M16); conformance buckets h2/all, h3/all, grpc/all, ws/all, sse/all all at 100% Pass.

Fixtures

h2/hpack-error-closes-connection.toml; h3/0rtt-rejected-on-post.toml; grpc/bidi-streaming-interop.toml; ws/close-handshake-on-upstream-disconnect.toml; sse/no-buffering-flush-per-event.toml.

Pitfalls

HPACK dynamic-table desync between peers corrupts every subsequent header decode on the connection — the only correct recovery is closing the connection, never attempting to resync; gRPC trailer handling differs from generic HTTP/2 trailers in frame-ordering and status-mapping subtlety, tested against the gRPC interop suite (§5); stream-multiplexing fairness requires an explicit per-connection stream-count limit or one client starves the rest; 0-RTT replay on non-idempotent methods is a correctness and security bug, foreclosed at config-validation time, not request time.

⬜ Phase 11 — Hot Reload, Control Plane & Conformance Harness §23

Objectives

Deliver zero-downtime configuration reload (P1, I1) via a real mTLS-only control-plane API (P9, I8), and close the loop with a conformance harness that diffs behavior against NGINX, Envoy, and Caddy on the full scenario corpus.

Deliverable

Full revp binary with a live mTLS control plane and a conformance report showing 100% Pass against the scenario corpus, differences against reference proxies categorized and signed off.

Acceptance

10,000 reloads in sequence with no memory leak (heaptrack-verified, RSS delta < 1% across the run); cache-purge propagation < 100 ms (§16); reload p99 < 100 ms at 10,000 routes (§30 M17); every conformance category at 100% Pass; zero plaintext control-plane bind possible (I8, enforced at startup).

Fixtures

reload/10k-reloads-no-leak.toml; control-plane/plaintext-bind-rejected.toml; conformance/nginx-diff-categorized.toml; conformance/envoy-diff-categorized.toml.

Pitfalls

Old-Config-generation retention leaks if a request never finishes — the 10-minute force-eviction bound (with a warning) is the safety net, not the primary defense (the primary defense is bounded request timeouts, §4); validation that depends on external state (JWKS reachability, upstream DNS) must be distinguished from parse/schema errors or operators cannot tell "config is wrong" from "network is flaky right now"; NGINX and Envoy disagree on real edge cases (chunked whitespace, percent-encoded / in paths, ambiguous Vary) — each disagreement is resolved by an explicit ADR, never left silently inconsistent.
