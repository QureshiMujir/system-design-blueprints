32. Back-of-Envelope Capacity Model

  • C1 — AST Arena Footprint (typical). 10,000 patterns × 8 nodes/pattern avg × 96 B/node = 7.68 MB, × 1.8x §4 amplification ceiling = 13.8 MB, well inside the 512 MB §4 ceiling.
  • C2 — AST Arena Footprint (worst case). 64 MB max source × 1.8x §4 amplification = 115.2 MB raw arena, + 4x diagnostics/trivia overhead = 460.8 MB, inside the 512 MB §4 ceiling with 51 MB headroom.
  • C3 — Concurrent Worker Memory. 128 concurrent compilations (§4) × 7.68 MB typical AST (C1) = 983 MB, inside the 8 GB §4 per-node RAM budget with headroom for 6 more worst-case (C2) compilations.
  • C4 — Exhaustiveness Memory. 1 GB §4 ceiling ÷ 96 B/witness-node = 10.9M witness nodes addressable before Phase 6 (§18) throttling triggers.
  • C5 — Decision DAG Throughput Headroom. 50,000 nodes/sec §4 target × 0.25 s §4 p95 latency budget = 12,500 nodes producible inside the p95 window for a 10k-pattern compilation.
  • C6 — File Descriptor Headroom. 2048 §4 FD budget ÷ 128 §4 concurrent compilations = 16 FDs/compilation (source file + replay log + snapshot + fixture handles).
  • C7 — Replay Log Growth. 10,000 patterns × 5 pipeline stages (§3) × 32 B/event = 1.6 MB replay trace per compilation, × 128 concurrent (§4) = 204.8 MB/interval, inside the < 2.2x §4 storage-amplification budget.
  • C8 — Branch Depth Safety Margin. 4096 §4 branch-depth soft limit ÷ 8 avg constructor arity = 512 nesting levels before Phase 0 (§12) trampoline conversion engages.
  • C9 — Startup Warm-Up Budget. 100 ms §4 startup ceiling × 50,000 nodes/sec §4 throughput = 5,000 nodes worth of warm-up amortized before the first user compilation lands.
  • C10 — Availability-Derived Downtime Budget. (1 − 0.9995) × 525,600 min/yr = 262.8 min/yr allowed downtime against the 99.95% §4 availability target, cross-checked against the < 10 min §4 RTO.
