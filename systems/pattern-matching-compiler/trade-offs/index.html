Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — Backtracking Interpreter

scrutinee -> [try pattern 1] -fail-> [try pattern 2] -fail-> ... -fail-> [no match]
                 |match                  |match
                 v                      v
              [arm 1]                [arm 2]

Regime where it wins: prototype DSLs with fewer than ~50 patterns where implementation simplicity and compile-time cost matter more than dispatch-time cost. Real system: early Scheme syntax-rules-style tree-walking pattern interpreters. Rejected here because backtracking cost is exponential in the worst case (no shared decomposition across alternatives) and produces no artifact satisfying I6 (there is no DAG at all to validate).

Alt B — NFA/Regex-Style Automaton Compilation

[start] --char class--> [state 1] --char class--> [state 2] --> [accept]
                |already-seen-class
                v
           [shared state]

Regime where it wins: string/byte-oriented matching where the input space is characters, not typed constructors — regex/lexer-generator territory. Real system: rust-lang/regex (regex-automata), built on Thompson-construction NFA compilation. Rejected here because ADT constructor matching needs typed tuple/field decomposition (§8), not character-class transitions; forcing patterns through an automaton model would require encoding every constructor as a synthetic alphabet, discarding the type information §15 depends on.

Alt C — SAT/SMT-Backed Exhaustiveness

pattern matrix -> [encode as boolean formula] -> [SAT/SMT solver] -> SAT: witness
                                                                  -> UNSAT: exhaustive

Regime where it wins: refinement-typed or dependently-typed pattern systems where boolean guard reasoning dominates over constructor coverage — verification-oriented languages. Real system: Z3-backed verification tooling in the Prusti/Verus style for refinement-typed languages. Rejected for this system's Phase 0–9 scope because solver latency variance is incompatible with the 250 ms p95 §4 constraint; tracked instead as the deferred GADT-aware refinement-typing feature (PhaseDeferred("§18")) pending a use case that justifies the latency tradeoff.

Alt D — Interpreted Decision Table Without a Codegen Backend

[decision table row 1] -> test -> next row or arm
[decision table row 2] -> test -> next row or arm
   ... executed by a generic interpreter loop, never compiled ...

Regime where it wins: low-throughput rule engines where portability and hot-reload trump dispatch speed. Real system: interpreted-mode rule evaluation as used by Drools-style business rule engines. Rejected here because interpretive dispatch overhead cannot meet the 50,000 nodes/sec §4 M3 throughput target — this system compiles to two independent executable backends (§21) specifically to avoid paying interpretation cost on every dispatch.
