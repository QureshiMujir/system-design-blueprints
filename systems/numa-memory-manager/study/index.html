33. Hard Questions (Self-Examination)

  • Q1. If §17's policy engine is purely advisory and never allocates (P5), what prevents §14's allocation fast path from committing a placement one epoch before §17's precomputed score updates?
  • Q2. §16's hugepage manager forbids partial free of a hugepage-backed allocation — how does that interact with §19's reclaim scanner, which otherwise operates at 4 KB granularity?
  • Q3. §18's migration engine treats a 1 GB hugepage as one atomic migration unit — what does that imply for §28's migration-overhead budget once §32's hugepage reservation (C6) is fully utilized?
  • Q4. §20's replay WAL assumes a monotonic per-node sequence (I5) — how does §21's rolling-upgrade validation guarantee sequence continuity across a version boundary given §25's additive-only guarantee?
  • Q5. §4's remote-allocation-ratio ceiling (8 %) and §17's balancing-threshold hysteresis were tuned independently — what in §32's C5 derivation shows they are mutually consistent rather than coincidental?
  • Q6. §19's emergency reclaim path may never reclaim a Pinned/Migrating page — what happens when §18's migration engine and §19's emergency reclaim both target the same page under §4's pressure-collapse case?
  • Q7. §9's ADR-05 locks in a fixed-schema binary layout for size and speed on the WAL append path — does §26's differential fuzzing actually exercise the WAL versioning path from §25, or only the steady-state append path?
  • Q8. §14's lock-striping design (Calciu et al. 2013) assumes node-partitioned cohorts — how does §29's per-process horizontal-scaling model avoid recreating the same global-lock bottleneck at the process-manager level?
  • Q9. §13's degraded mode (P12) disables optimization for the process lifetime once triggered — what does §24's runbook tell an operator to do differently than just restarting?
  • Q10. §32's C1 shows page-descriptor metadata at 1.17 % of the 2.5 % ceiling — once §16's hugepage manager reduces effective page count for hugepage regions, does §4's ceiling still bind, or does §28 need an adjusted metric?
  • Q11. §22's T5 (malicious pinning) and §18's I4 (migration cannot violate pinning) together mean a caller that pins memory can defeat locality repair — what bounds the blast radius per §23, and is it enforced by a quota in §11?
  • Q12. §30's MM3 (bounded queues convert the failure mode, not eliminate it) applies to §18's migration queue — what is the reject policy when full, and does §23's FM-5 forensics separate rejected from admitted-then-failed tasks?
  • Q13. §27's release-channel gating promotes nightly → rc → stable — at which stage does §21's 72-hour soak actually run, and does §38's Phase 9 duration leave room for a soak failure to be re-run?
  • Q14. §31 shows every comparative system picked a threading model incompatible with this design's per-node arena split — what specific type in §11 is the actual reason none could be adopted wholesale?
  • Q15. §7's I7 (lock ordering never cycles) is enforced via a static lock-order table in CI — does it cover cross-crate ordering between §14's arena locks and §19's reclaim locks, or only intra-crate ordering?
  • Q16. §35 registers RDMA-aware placement deferred at §21, but §21 is Conformance/Fuzzing/Hardening, not placement logic — should the anchor instead point at §17?
  • Q17. §4's availability target and §32's C10 derive a ~52-minute annual error budget — does §23's FM-3 (RTO < 60 s) leave any budget for a second incident in the same year?

30. Mental Models & First Principles

  • MM1 — Locality Is a Correctness-Adjacent Property. Compressed insight: treat remote access like a latent bug, not a slowdown. Predicts: locality regressions surface as a remote-ratio percentage before they surface as p99. Bug class without it: silent latency creep dismissed as noise until a customer escalation. Applies in §17.
  • MM2 — Fast Paths Are Zero-Decision Paths. Compressed insight: any per-allocation branch on shared state is a scalability bet against you. Predicts: adding "just one check" measurably degrades p50. Bug class without it: cumulative small checks that each look free in isolation. Applies in §14.
  • MM3 — Bounded Queues Convert the Failure Mode, They Don't Eliminate It. Compressed insight: backpressure trades unbounded latency for bounded rejection — you still need a reject policy. Predicts: a "fixed" unbounded-growth bug that just adds a bound with no reject path silently deadlocks instead. Bug class without it: assuming a bound alone is sufficient. Applies in §18.
  • MM4 — Replay Determinism Is a Design Constraint, Not a Feature. Compressed insight: one stray non- deterministic input anywhere poisons every downstream replay. Predicts: replay divergence that "sometimes" reproduces is always a real bug, never a flake. Bug class without it: dismissing intermittent replay mismatches as noise. Applies in §20.
  • MM5 — Ownership Transfer Must Be Atomic or It's a Race. Compressed insight: any two-step handoff has a window. Predicts: double-free/double-use bugs cluster exactly at handoff boundaries (migration, reclaim). Bug class without it: "temporarily" shared ownership during a state transition. Applies in §7.
  • MM6 — Degraded Mode Beats a Guess. Compressed insight: an allocator that doesn't know the topology should say so, not guess. Predicts: a guessed placement on malformed input pins memory to the wrong socket for the process's entire life, not just once. Bug class without it: silent misplacement treated as a one-time hiccup. Applies in §13.
  • MM7 — Tail Latency Hides in Rare Code Paths. Compressed insight: p99 is dominated by paths taken under 1 % of the time. Predicts: mean-latency dashboards miss the actual regression entirely. Bug class without it: "the average looks fine" masking a rare multi-microsecond lock hold. Applies in §28.
  • MM8 — Every Capacity Number Must Trace to a Measured Constraint. Compressed insight: an unsourced number in a capacity model is a guess wearing a table's clothing. Predicts: capacity plans built on assumed rather than derived numbers fail the first time deployed hardware doesn't match the assumption. Bug class without it: sizing decisions that can't be re-derived when hardware changes. Applies in §32.

5. Required Reading

Books

  • Understanding the Linux Virtual Memory Manager — Mel Gorman (2004), ch. on Physical Page Allocation, Slab Allocator, NUMA API, Page Reclaim: buddy allocation, page lifecycle, reclaim semantics; applied in §14 and §19.
  • Systems Performance — Brendan Gregg (2nd ed., 2020), ch. Memory, ch. CPUs, ch. Methodology: USE-method bottleneck attribution, tail-latency analysis technique; applied in §28 and §24.
  • The Art of Multiprocessor Programming — Maurice Herlihy & Nir Shavit (rev. ed., 2012), ch. on lock-free queues, memory ordering: CAS semantics, ABA mitigation, queue scalability bounds; applied in §14 and §7.
  • Computer Architecture: A Quantitative Approach — John Hennessy & David Patterson (6th ed., 2017), ch. on cache coherency, memory hierarchies, interconnects: cross-node bandwidth/latency modeling; applied in §4 and §29.
  • Database Internals — Alex Petrov (2019), sections on memory management, page layout, buffer pools: node-local buffer-pool design analogues; applied in §11 and §15.
  • BPF Performance Tools — Brendan Gregg (2019): eBPF-based allocator tracing without recompilation; applied in §20 and §28.
  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. on replication and consistency: informs replay-log durability and ordering guarantees; applied in §20.
  • Linux Kernel Development — Robert Love (3rd ed., 2010), ch. on Memory Management and Page Cache: kernel-side reclaim/page-cache interaction the allocator must not fight; applied in §19.

Papers

  • "The Slab Allocator: An Object-Caching Kernel Memory Allocator" — Jeff Bonwick, 1994, USENIX Summer Technical Conference: size-classed object caching → basis of the slab size-class design; applied in §15.
  • "Magazines and Vmem: Extending the Slab Allocator to Many CPUs and Arbitrary Resources" — Jeff Bonwick & Jonathan Adams, 2001, USENIX ATC: per-CPU magazine layer over a shared slab depot → basis of per-thread cache refill; applied in §15.
  • "A Scalable Concurrent malloc(3) Implementation for FreeBSD" — Jason Evans, 2006, BSDCan: arena partitioning and extent management → informs arena per-node domain design; applied in §14.
  • "Hoard: A Scalable Memory Allocator for Multithreaded Applications" — Emery Berger, Kathryn McKinley, Robert Blumofe, Paul Wilson, 2000, ASPLOS: per-thread heaps with a global-heap fallback → informs thread-cache-to-arena fallback ordering; applied in §14.
  • "Simple, Fast, and Practical Non-Blocking and Blocking Concurrent Queue Algorithms" — Maged Michael & Michael Scott, 1996, PODC: lock-free MPMC queue design → basis of the remote-free queue; applied in §14.
  • "NUMA-Aware Reader-Writer Locks" — Irina Calciu, Dave Dice, Yossi Lev, Victor Luchangco, Virendra Marathe, Nir Shavit, 2013, PPoPP: node-partitioned lock cohorting → informs lock striping; applied in §14.
  • "Read-Copy Update: Using Execution History to Solve Concurrency Problems" — Paul McKenney & John Slingwine, 1998, PDCS: wait-free readers via deferred reclamation → informs the immutable topology-snapshot read path; applied in §13.
  • "Large Pages May Be Harmful on NUMA Systems" — Fabien Gaud, Baptiste Lepers, Jeremie Decouchant, Justin Funston, Alexandra Fedorova, Vivien Quéma, 2014, USENIX ATC: hugepages amplify remote-access penalty when placement is wrong → informs hugepage/migration interaction; applied in §16 and §18.

Reference Implementations

  • jemalloc — study src/arena.c, src/extent.c, src/pac.c: fragmentation control via extent management, per-arena scalability; pitfall: do not copy jemalloc's global mutex-guarded extent tree verbatim, it caps scalability past ~32 cores; applied in §14.
  • mimalloc — study src/segment.c, src/page.c: per-thread segment ownership, fast free path; pitfall: mimalloc's free-list sharding assumes single-threaded segment owners, which does not hold once cross-node remote free is added; applied in §15.
  • Linux mm/ — study mm/page_alloc.c, mm/memory.c, mm/huge_memory.c: buddy allocator order math, THP promotion/demotion; pitfall: do not copy the kernel's synchronous compaction-on-allocation path, it violates the bounded-lock-hold invariant; applied in §14 and §16.
  • Seastar — study core/memory.cc: per-shard exclusive memory pools eliminating cross-thread locking; pitfall: Seastar assumes one shard pins one CPU permanently, an assumption this design's thread-cache-over-arena model must approximate rather than take for granted; applied in §15.
  • tcmalloc — study the central free list and page heap components: two-level cache hierarchy mirrors the arena/slab split here; pitfall: tcmalloc's central free list uses a single spinlock per size class, a documented high-core-count contention point avoided here via per-node sharding; applied in §15.

RFCs / Specifications

  • ACPI Specification, Section 5.2.16 (SRAT) — pins down the System Resource Affinity Table layout consumed by topology discovery; applied in §13.
  • ACPI Specification, Section 5.2.17 (SLIT) — pins down the System Locality Distance Information Table used for the node distance matrix; applied in §13.
  • Linux Documentation/admin-guide/mm/numa_memory_policy.rst — pins down mbind/set_mempolicy semantics the runtime API must not contradict; applied in §17.
  • Linux Documentation/admin-guide/cgroup-v2.rst (memory controller) — pins down memory.max/memory.pressure interaction the reclaim subsystem must respect under container limits; applied in §19.

Glossary (§36) · 47 terms · site-wide glossary

Arena
NUMA-local allocation domain owning exactly one node's free lists and slab caches.
Slab
fixed-size object allocation region managed by size class.
Magazine
per-thread cache layer over a slab's shared depot (Bonwick & Adams 2001).
Size Class
a fixed allocation-size bucket used by the slab allocator's dispatch table.
Depot
the shared per-slab-class object pool magazines refill from.
Locality Score
the placement-affinity metric computed by the NUMA policy engine.
Replay WAL
the deterministic, append-only allocator event log used for reconstruction.
Remote Free
a free operation whose target arena is on a different node than the freeing thread.
Hugepage
a 2 MB or 1 GB hardware page mapping, explicitly reserved via hugetlbfs.
NUMA Distance
the relative access-cost value between two nodes from the SLIT table.
Reclaim
the memory-recovery process that returns cold pages to the free pool under pressure.
TLB Shootdown
cross-core translation-invalidation synchronization triggered by a page move.
Heatmap
sampled access-frequency metadata used to prioritize migration and reclaim targets.
Poison Pattern
a fixed fill-byte sequence written on free, used to detect use-after-free.
Generation Counter
an ABA-mitigation version field bumped on every ownership transition.
Migration Storm
an uncoordinated burst of migration tasks that collapses available bandwidth.
Pressure Signal
telemetry indicating approaching memory exhaustion, sourced from cgroup v2.
Topology Snapshot
the immutable-after-startup hardware map published by the topology layer.
Pinning
a per-page flag preventing migration or reclaim (I4, I11).
Fragmentation
the fraction of reserved capacity that is free but unusable for a given request.
Local Allocation
an allocation served from the requesting thread's own NUMA node.
Remote Allocation
an allocation served from a NUMA node other than the requester's own.
Degraded Mode
the safety-first fallback state entered when topology validation fails (P12).
Free List
an intrusive linked structure of unallocated pages or objects within an arena/slab.
Page Descriptor
the per-page metadata record tracking owner, state, checksum, and generation.
Node Descriptor
the per-NUMA-node metadata record tracking CPUs, memory ranges, and distances.
Ownership
the single-authoritative-owner relationship a page or object has at all times (I1).
Checksum
a per-descriptor integrity value validated on every metadata access (I3).
ABA Problem
a concurrency hazard where a value is read, changed, and changed back, hiding a race.
CAS (Compare-And-Swap)
the atomic primitive used for lock-free ownership transitions.
Lock Striping
partitioning a lock's protected state across shards to reduce contention (P11).
Backpressure
an explicit bounded-queue reject/delay policy applied at every subsystem boundary.
Crash-Only Semantics
the design discipline of recovering only via restart/reconstruction (P3).
Soak Test
a long-duration sustained-load test (72 h, §21) verifying zero invariant violations.
Canary Deployment
serving a small traffic percentage to a new build under full telemetry.
Rolling Upgrade
running two allocator versions simultaneously during a release rollout.
SBOM
a CycloneDX-format software bill of materials generated on every build.
Sigstore
the keyless artifact-signing infrastructure used for release provenance.
Cold Page
a page whose heatmap access frequency has fallen below the reclaim/migration threshold.
Emergency Reclaim
the bounded, synchronous last-resort reclaim path under severe pressure.
Throttling
delaying (not rejecting) new allocations proportionally to pressure severity.
RTO
recovery time objective, the maximum time to restore service after a failure.
RPO
recovery point objective, the maximum tolerable data-loss window.
SRAT / SLIT
the ACPI System Resource Affinity Table and System Locality Distance Information Table, the firmware sources of NUMA topology data.
cgroup v2
the Linux control-group hierarchy version whose memory controller drives pressure signals into the reclaim subsystem.
THP
transparent hugepages, the kernel's automatic (non-explicit) hugepage mechanism this design deliberately does not rely on (ADR-23).
Workload Classification
the policy engine's heuristic distinction between steady-state and bursty allocation patterns.
