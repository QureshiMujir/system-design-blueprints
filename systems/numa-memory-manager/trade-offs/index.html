Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — Kernel-Resident NUMA Allocator

+-------------------------------------------+
|         Every process on the host          |
+---------------------+-----------------------+
                      v
+-------------------------------------------+
|   Linux mm/ patch: SLUB + buddy + AutoNUMA  |
|   (single shared allocator, kernel-owned)   |
+-------------------------------------------+

Wins when every process on a host must benefit from NUMA-aware allocation uniformly, with no per- application embedding step. Embodied by Linux's own SLUB/buddy allocator plus AutoNUMA balancing. Rejected here because this project targets library-level control with rapid iteration for one embedding process (§1); a kernel patch has multi-year upstream review cycles incompatible with the 9–14 month full-system timeline (§1) and cannot expose the replay/observability surface (§20) this design requires.

Alt B — Share-Nothing Per-Core Runtime

Core 0 -- exclusive pool 0        Core 1 -- exclusive pool 1
   ^  no cross-core allocation       ^  no cross-core allocation
   |                                 |
Application thread pinned forever to one core, forever

Wins for async dataplane workloads that already pin exactly one thread per core for the process's lifetime. Embodied by Seastar's per-shard memory subsystem. Rejected here because §1's target operators include conventional thread-pool database and actor-runtime embedders where thread-to-core pinning is not guaranteed — forcing that assumption would break the embedding model this project promises.

Alt C — Garbage-Collected NUMA-Aware Heap

Mutator threads --> GC-managed heap regions (NUMA-tagged)
                         |
                    GC relocates objects across regions
                    during collection (stop-the-world or
                    concurrent, but always GC-driven)

Wins for managed-language workloads where the collector already owns object lifetime and can freely relocate objects during collection. Embodied by the HotSpot JVM's -XX:+UseNUMA NUMA-aware allocation for its garbage collectors. Rejected here because §1's target workloads (databases, dataplanes, OLTP engines) cannot tolerate GC pause semantics or object-relocation-during-use — P8's bounded-tail-latency principle is incompatible with a GC-driven relocation model.

Alt D — Distributed Shared Memory Across Hosts

Host A page table <--network page fault/coherence--> Host B page table
        (a single page can live on either host, migrated over the wire)

Wins for workloads whose working set genuinely exceeds one host's NUMA fabric and must span multiple machines transparently. Embodied by Li & Hudak's Ivy distributed shared memory system (1989), the foundational page-based DSM design. Rejected here because §1 explicitly excludes distributed shared memory as a non-goal — cross-host page coherence introduces network-partition failure modes entirely outside this design's single-host threat model (§22).
