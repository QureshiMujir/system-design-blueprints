⬜ Phase 0 — Skeleton, Governance, Smoke Test §12

Objectives

Stand up the repository (§10) as a single commit; land governance docs, CI workflows, and a smoke-test binary that parses and executes exactly one construct: a SimpleCommand with $USER/${USER} expansion. No lexer/parser generality yet (P3/P4 come in Phase 1–2).

Deliverable

osh -c 'echo Hello, $USER' prints the value of $USER plus newline; make bootstrap build test lint all exit 0.

Acceptance
  • make test passes with ≥1 test asserting byte-identical output of osh -c 'echo $USER' against the host $USER value.
  • ADR-01, ADR-02, ADR-03, ADR-04, ADR-11 written under docs/adr/.
  • smoke.hello conformance bucket reports Pass in conformance.report.json.
Fixtures
  • smoke.hello — osh -c 'echo $USER'; expected: $USER + \n, byte-identical.
  • smoke.cli-modes — the three entry forms (-c, script path, stdin) all execute the same one-line fixture identically.
Pitfalls
  • Shipping a "real" lexer here mis-shapes Phase 1's five-context design (P3) — keep this phase's lexer intentionally minimal.
  • Skipping CI now means the conformance harness (added incrementally from Phase 1) has no green baseline to regress against.
  • Exporting RUST_BACKTRACE=1 at binary startup changes default panic output that the test harness depends on being absent.

⬜ Phase 1 — Lexer §13

Objectives

Replace Phase 0's placeholder lexer with the full 5-context tagged state machine (P3, §8.1) producing token streams byte-identical to the reference corpus for every fixture.

Deliverable

osh::Lexer produces a token stream over any input in the conformance corpus; the fuzz target fuzz/fuzz_targets/lex.rs runs one CI minute without panicking.

Acceptance
  • lexer.posix and lexer.bash buckets: 100% byte-identical token streams (I1), ≥ 400 cases each.
  • Tokenizer throughput ≥ 200 MiB/s sustained on the 10 MiB corpus (M5, §4).
  • Zero fuzzer crashes in a 60-second cargo fuzz run lex CI run.
Fixtures
  • corpora/posix/tokens/*.in ↔ *.out (JSONL token streams).
  • corpora/bash/tokens/*.in — bash-flavored, Mode::Bash.
  • corpora/heredoc/*.in — every section 2.7.4 here-doc edge case.
  • corpora/alias/*.in — alias-expansion order fixtures.
Pitfalls
  • Here-doc bodies read before the rest of the line parses (cat <<EOF | wc is a classic naive-lexer trap) — root cause: deferred-read ordering; debug via the lexer.heredoc bucket; recover by fixing capture order (§8.1).
  • Backtick nesting escape rules differ from $(); ship $() canonical, document backtick edge cases in docs/posix-divergences.md (P1).
  • Alias expansion of a builtin already classified by the parser is an interaction trap — fixture alias if='echo if' + if true; then …; fi must not alias the keyword if.
  • Whitespace inside ${...} is a POSIX syntax error but bash-permitted — gate on Mode::Bash (P1, P2).

⬜ Phase 2 — Parser §14

Objectives

Turn the Phase 1 token stream into an arena-allocated AST (§11.3) via hand-written recursive descent (P4, ADR-02) matching POSIX section 2.10's grammar (§8.2) one production at a time.

Deliverable

osh::Parser produces an AST for any conformance-corpus input; a round-trip test (parse → pretty-print → parse) produces equal ASTs for every corpora/parser/round-trip/ fixture.

Acceptance
  • parser.posix and parser.bash buckets: 100% snapshot match against *.snap.json, ≥ 350 cases each.
  • Round-trip fixture set: 100% byte-identical re-parse (M11 analogue).
  • Parse rate: 100,000-line synthetic script in ≤ 500 ms (M1, §4).
Fixtures
  • corpora/posix/ast/*.in ↔ *.snap.json.
  • corpora/bash/ast/*.in — bash-flavored, Mode::Bash.
  • corpora/parser/round-trip/*.in.
  • corpora/parser/recovery/*.in — interactive-mode continuation/resync.
Pitfalls
  • Reserved words are reserved only at command-start (for at a list head vs. as a command name) — the parser must consult the cursor's command-start flag, not infer it lexically (P3/P4 boundary).
  • The empty brace group { ; } is a POSIX parse error but bash-accepted — gate on Mode::Bash.
  • A case pattern list's | is a pattern delimiter, not a pipeline operator — parser position state, not the lexer, disambiguates.
  • Function-definition syntax: POSIX's name() compound_command vs. bash's function name { ... } — gate the latter on Mode::Bash.

⬜ Phase 3 — Built-ins Library §15

Objectives

Ship the full built-ins surface: 15 POSIX-special (POSIX section 2.14), 19 POSIX-regular, and 22 bash-gated built-ins, each implementing the Builtin trait (§11.6).

Deliverable

Every built-in in §15.2 ships with a unit test; help (bash mode) returns text for each.

Acceptance
  • builtins.special bucket: exit + assignment-survival rules pass for all 15 (I9).
  • builtins.regular bucket: per-built-in reference behavior match, ≥ 200 cases.
  • getopts diagnostic-message fixture passes byte-identical against reference.
Fixtures
  • corpora/builtins/<name>/*.in — input, expected output, expected exit code.
  • corpora/builtins/special/*.in — set -e interaction cases.
  • corpora/builtins/getopts/*.in — "Unknown option" diagnostic case.
Pitfalls
  • set -e around special built-ins has four distinct swallow contexts (function-called, direct-if, if-test, top-level &&) — decisions belong in one table, not scattered ifs (I9, Phase 5 shares this table).
  • read -t 0 is a non-blocking poll via select with zero timeout — O_NONBLOCK permanently changes the FD's mode and is wrong.
  • trap reparses the action string, not a cached AST, on every fire.
  • kill -l signal names must match the host's signal set (Linux/macOS/FreeBSD differ).

⬜ Phase 4 — Expansion Pipeline §16

Objectives

Implement the eight-stage ordered expansion sequence (§8.3, I2, P5) as independent traits and one driver, never a merged single-pass expander.

Deliverable

Every WORD in the conformance corpus expands to a field list byte-identical to the reference shell; a property test asserts ${var:-default} of an unset var equals var=default assignment result.

Acceptance
  • expand.{param,command,arith,field,glob,brace,tilde,quote} buckets: 100% match, ≥ 500 total cases (I2).
  • Property test: 1,000 random (var, default) pairs for ${var:-word} — 100% pass.
Fixtures
  • corpora/expand/param/*.in — every parameter-expansion form.
  • corpora/expand/command/*.in — $() and backticks.
  • corpora/expand/field/*.in — IFS edge cases.
  • corpora/expand/glob/*.in — glob + extglob cases.
Pitfalls
  • The eight stages are strictly ordered — reordering breaks ${var:-$other}-class fixtures (I2, P5).
  • "$@" (no field-splitting, per-positional quoting preserved) vs. $@ (subject to splitting) is the single largest real-world bug mine (POSIX section 2.5.2).
  • nullglob is bash-only; POSIX default leaves a non-matching pattern unchanged.
  • ${var: -1} (negative-index substring) needs an explicit space in POSIX; the expander emits a clear diagnostic when missing.

⬜ Phase 5 — Executor §17

Objectives

Walk the AST into process trees: fork/execve/dup2/pipe, function-frame stack, and the set -e/-u/pipefail decision table (I3, I9, P6, P11).

Deliverable

Every AST construct executes correctly against conformance/corpora/exec/; a 100-line configure-style script (Required Reading, Cooper) runs to completion.

Acceptance
  • exec.* buckets: 100% match on exit status + stdout + stderr bytes, ≥ 300 cases.
  • exec.flags bucket covers all POSIX section 2.11 swallow contexts plus 8 documented bash deviations (I9).
  • 100-line configure-style fixture completes with exit 0.
Fixtures
  • corpora/exec/{simple,pipeline,redirect,heredoc,function}/*.in.
  • corpora/exec/flags/*.in — set -e/-u/pipefail cases.
Pitfalls
  • dup2 order is left-to-right in the redirect list — 2>&1 1>file ≠ 1>file 2>&1.
  • Large here-documents deadlock on a pipe write exceeding PIPE_BUF — materialize to a temp file above the threshold (§17.2).
  • set -e swallow rules are the most bug-prone area in any shell — consult the single decision table (I9), never re-derive ad hoc.
  • A subshell inherits parent traps set with trap 'cmd' SIG reverting to default, but traps set trap '' SIG (ignored) stay ignored — the reset happens post-fork in the child (POSIX section 2.5).

⬜ Phase 6 — Job Control & Signals §18

Objectives

Implement the terminal-arbitration state machine (§8.5, P7, I5, I6) and async-signal-safe signal delivery (P8, I7) for interactive multitasking.

Deliverable

osh runs vim interactively, suspends with Ctrl-Z, runs ls, resumes with fg, preserving editor state; a stress test of 64 background jobs cycled leaves zero orphans.

Acceptance
  • jobs.{fg,bg,suspend,kill,disown} buckets: 100% pass (PTY-driven, ≥ 40 cases).
  • 64-job stress test (§18.3): zero orphan processes, zero stuck terminals (M12).
  • signals.{sigint,sigwinch} buckets: 100% pass.
Fixtures
  • corpora/jobs/{fg,bg,disown}/*.expect — PTY-driven.
  • corpora/signals/{sigint,sigwinch}/*.expect.
Pitfalls
  • Forgetting the parent's foreground-pgid set races the child's keyboard input against the shell's — the parent's setpgid call is authoritative (I5).
  • A tcsetpgrp call from a non-foreground group sends the caller SIGTTOU — the arbiter must self-ignore first (§18.2).
  • A signal can arrive between fork and the parent's setpgid — the child's own call covers this narrow race window (I5).
  • SIGCHLD handlers must be re-entrant; the reaper loop, not the handler itself, does the real work (P8).

⬜ Phase 7 — Arithmetic Engine §19

Objectives

Implement crates/arith: a precedence-climbing recursive-descent evaluator for $((expr)), ((expr)), and [[ ]]'s arithmetic operators, deterministic per I13.

Deliverable

The arithmetic engine passes expand.arith; a property test asserts $((a+b)) == a+b (computed in i64 two's-complement) for 1,000 random (a, b) pairs (I13, M13-analog).

Acceptance
  • expand.arith bucket: 100% match against reference, ≥ 100 cases covering every operator in §19.2's precedence table.
  • Property test: 1,000/1,000 random pairs pass (I13).
Fixtures
  • corpora/expand/arith/*.in — every operator + precedence combination.
  • corpora/expand/arith/overflow/*.in — two's-complement wraparound cases.
Pitfalls
  • Octal 077 is 63, not 77 — inherited from C, rarely expected by users.
  • ** is right-associative: 2**3**2 = 512, not 64.
  • Unary -/+ must be recognized via an "at operand start" flag before binary forms.
  • Comma is lowest-precedence and discards its left operand — do not conflate with a list separator inside (( )).

⬜ Phase 8 — Line Editor §20

Objectives

Implement the interactive surface: raw-mode terminal input, a gap buffer, vi/emacs keymaps, and a minimal-diff render loop (P13, ADR-05, ADR-15).

Deliverable

The editor runs against a PTY in CI, green for both vi and emacs modes; a user can edit a 200-character line, Ctrl-R search history, and tab-complete a path.

Acceptance
  • interactive.{emacs,vi} buckets: 100% pass, ≥ 30 PTY-driven cases each.
  • 200-character-line edit + reverse-search + tab-complete fixture passes end-to-end.
Fixtures
  • corpora/interactive/{emacs,vi}/*.expect — keystroke-driven, PTY-asserted.
  • corpora/interactive/{multiline,paste}/*.expect.
Pitfalls
  • Multibyte keystrokes: a single keypress can yield up to 4 UTF-8 bytes — the input loop must read/decode accordingly (P9-adjacent).
  • Bracketed paste mode (CSI ?2004h): pasted bytes bracketed by CSI 200~/CSI 201~ must not trigger key bindings, including embedded newlines.
  • Ctrl-Z with no foreground job is delivered to the shell itself, which ignores it — it does not suspend the editor's main loop.
  • Cursor byte-position and display-column position diverge for multibyte characters — the buffer tracks both.

⬜ Phase 9 — Completion & History §21

Objectives

Implement programmable tab-completion and the append-only history store with !-style expansion and reverse incremental search.

Deliverable

Existing bash-completion scripts for git/cargo/kubectl load and complete correctly; history and fc built-ins operate on the in-memory store.

Acceptance
  • completion.{command,file,programmable} buckets: 100% candidate-set match, ≥ 60 cases.
  • history.{expansion,fc,search} buckets: 100% pass, all five !-forms covered.
  • The 3 curated real completion scripts complete correctly against ≥ 10 fixtures each.
Fixtures
  • corpora/completion/{command,file,programmable}/*.in.
  • corpora/history/{expansion,fc,search}/*.in.
Pitfalls
  • History expansion runs before quoting — a literal ! in interactive mode needs set +H, a frequent surprise (documented in docs/posix-divergences.md).
  • Concurrent shells writing history race; flock is the only portable cure (Solaris fcntl locking is finicky — tested Linux/macOS only, §5 scope note).
  • Ctrl-R in vi mode is a keymap binding, not a universal search trigger — the editor disambiguates by active mode.

⬜ Phase 10 — Restricted Shell, No-Exec Mode, Observability §22

Objectives

Implement least-privilege restricted mode (I12), static-analysis no-exec mode, opt-in OpenTelemetry tracing (ADR-19), and miette-based diagnostics (ADR-13).

Deliverable

Restricted mode passes its conformance bucket; osh -n script.sh returns 0 on syntactically valid input, 2 on invalid, and executes zero leaves; OSH_TRACE=1 emits a coherent trace to a local OTLP collector.

Acceptance
  • restricted bucket: every restricted operation emits the documented diagnostic, 100% of ≥ 20 cases (I12).
  • noexec bucket: 100% of fixtures parse without executing a single leaf.
  • A tracing smoke test confirms span nesting matches the AST's compound-command nesting.
Fixtures
  • corpora/restricted/*.in — every restricted operation + expected diagnostic.
  • corpora/noexec/*.in — parse-only fixtures, execution-count asserted zero.
Pitfalls
  • Checking restrictions only in the built-in dispatcher misses direct executor paths (e.g., a redirect on a compound command) — checks belong at every entry point (I12).
  • No-exec mode must still run the expansion pipeline (to catch $((...)) syntax errors) — stubbing the whole pipeline produces false-negative "valid" scripts.
  • OSH_TRACE spans left always-on in a hot loop defeats the zero-overhead default — gate strictly on the env var check, not a runtime feature flag with residual cost.

⬜ Phase 11 — Enhanced Mode (Opt-In, Non-Portable) §23

Objectives

Ship the Mode::Enhanced convenience surface — zsh/fish-style features explicitly marked non-portable, gated behind Mode::Enhanced (P1, P2).

Deliverable

Mode::Enhanced builds and runs against a small curated fixture set; every PhaseDeferred call site is registered in the Deferred Features Register.

Acceptance
  • Process substitution: ≥ 10 fixtures pass byte-identical against a reference zsh/ bash (with xpg_echo-equivalent) run.
  • RPROMPT renders without corrupting the primary prompt's cursor tracking in ≥ 5 terminal-width fixtures.
  • Every enhanced-mode feature not yet implemented carries a PhaseDeferred(...) call site resolving to the Deferred Features Register.
Fixtures
  • corpora/enhanced/procsub/*.in.
  • corpora/enhanced/rprompt/*.expect (PTY-driven).
Pitfalls
  • Glob qualifiers are lexically adjacent to extglob syntax — a naive implementation double-parses @(...) as both extglob and a qualifier; disambiguate by mode.
  • Process substitution FIFOs leak if the consuming command never opens them — the executor must set a reaper timeout.
  • Coprocess pipe wiring interacting with the existing pipeline pipe-count assumption (§17.2, N-1 pipes for N commands) needs an explicit extra-pipe accounting path.

⬜ Phase 12 — External Conformance & Validation §24

Objectives

Integrate the published POSIX VSC (Verification Suite for Commands) as an external, licensed-but-not-vendored validation pass, and close out the full-system validation milestones (Appendix B).

Deliverable

A signed conformance.report.json covering every bucket from Phases 1–11 plus the external VSC integration, all Pass; the 24-hour soak and 30-day fuzz artifacts archived under audits/.

Acceptance
  • VSC integration bucket: Pass on every non-Deferred case (§22.4 handling for Phase-1+ surfaces).
  • 24-hour soak: zero unhandled exceptions, zero measured memory growth (M9).
  • 30-day fuzz campaign: zero crashes across lex/parse targets (M10).
Fixtures
  • External VSC corpus (fetched, not vendored) — pass/fail per its own case IDs.
  • audits/soak/<date>/run.json, audits/fuzz/<date>/run.json.
Pitfalls
  • The VSC licence is restrictive — vendoring it violates the licence; the fetch-and- cache step must re-verify the licence terms on every CI run, not just once.
  • A 24-hour soak that silently swallows a crash-and-restart supervisor masks the very failure it's meant to catch — the soak harness must run the raw process, unsupervised.
  • Fuzz targets that only exercise ASCII input miss the UTF-8/multibyte edge cases Phase 8 documented — seed the corpus from corpora/interactive/paste/.
