Per-box:

Actor cell — the runtime's atom: a heap object holding an actor's private state, its behavior (the Actor trait object / typed handler), its mailbox, its links/monitors, and a handle to its supervisor. The cell is the only owner of the state; the scheduler grants it exclusive access for the duration of one message (invariant I1: a cell is never run on two workers at once → no concurrent handling → no data races without locks). Activation = "this cell has ≥1 message and is not currently running" → enqueued on a worker run-queue.

act-runtime (M:N scheduler) — a thread-per-core worker pool (one OS thread pinned per core for NUMA locality). Each worker owns a run-queue of ready actor cells; work-stealing balances load. A running cell processes messages until it hits a reduction budget (Erlang-style cooperative preemption: each message handled costs reductions; budget exhausted → yield, re-enqueue), guaranteeing fairness (I3: no actor starves the worker). Idle workers park (futex/condvar) to avoid busy-spin. This is the #54/#129/#131 cross-link made concrete.

act-mailbox — per-actor lock-free bounded MPSC queue (many senders, single consumer = the owning cell). Bounded → backpressure: when full, the configured policy (block sender / drop-newest / drop-oldest / fail-send) applies (I8). FIFO per sender pair (I4) — messages from sender A to actor X arrive in send order; no global ordering across senders. Enqueue transitions an idle cell to ready (notifies the scheduler).

act-supervise — supervision tree: every actor (except the root) has a parent supervisor; on child crash, the supervisor applies a strategy — one-for-one (restart only the crashed child), one-for-all (restart all children), rest-for-one (restart the crashed child + those started after it) — bounded by a restart-intensity limit (max R restarts in T seconds; exceeding it escalates the failure up the tree → "let it crash" all the way to a clean shutdown if unrecoverable). This is OTP's fault model (I9/I10).

act-addr — addressing: a Pid{ node, incarnation, local_id } uniquely names an actor across space and time (incarnation distinguishes a restarted node's reused ids). An ActorRef wraps a Pid + a resolution cache; send resolves to either a local cell (direct mailbox enqueue) or a remote target (hand the serialized Envelope to the transport). Location transparency (I11): the caller's API is identical either way — the only difference is at-most-once becomes more likely to silently drop on a partition (documented, not hidden).

act-transport — the wire protocol: one TCP connection per peer (multiplexing all actor traffic + heartbeats), length-prefixed frames, a versioned handshake (protocol version + node identity + incarnation), and message serialization (envelope header + opaque payload). Preserves per-sender FIFO over the connection (I4). Trust boundary: inbound bytes are hostile → the frame decoder must never panic (I6, fuzzed).

act-cluster (membership) — SWIM: nodes join via a seed, then maintain a member list through periodic ping + ping-req (indirect probe via k random members) + gossip of membership updates (alive/suspect/dead) piggybacked on probes. Incarnation numbers let a node refute a false suspicion. Detects and surfaces split-brain (a partition where each side thinks the other is dead) — this runtime is AP (availability + partition-tolerance), so it does not auto-resolve split-brain; it reports it (consensus/CP is #42's job).

act-detector (failure detection) — phi-accrual: instead of a binary timeout, it tracks the distribution of heartbeat inter-arrival times per peer and outputs a continuous suspicion level φ; when φ exceeds a threshold, the peer is suspected (feeds SWIM). Adaptive to network jitter (a momentary GC pause raises φ gradually, not a hard cutoff). Direct heartbeats + indirect ping-req confirm. On confirmed death, the peer's actors' remote ActorRefs are invalidated (I12: sends to them fail fast / dead-letter, monitors fire Down).

act-cli / observability — act talks to a local actd over a control socket: members (cluster view), ps (actors + mailbox depths), tree (supervision tree), send (inject a message). Metrics (mailbox depth, scheduler reductions, restarts, φ per peer, frame errors), tracing spans (send→enqueue→handle, probe→suspect→dead), structured logs.

8. Domain Model

8.1 The actor (three axioms, Hewitt 1973)

An actor, on receiving a message, may do exactly three things:

1. SEND   a finite number of messages to other actors (by ActorRef).
2. SPAWN  a finite number of new actors (it becomes their supervisor).
3. BECOME a new behavior for the *next* message (designate next state).

Everything else is built from these. An actor = { private state, current behavior, mailbox, identity (Pid), supervisor handle, links, monitors }. It is passive until a message activates it; the scheduler runs it; it processes one message; it goes idle (or is preempted).

8.2 Identity, addressing, and references

Pid        := { node: NodeId, incarnation: u32, local_id: u64 }     // unique across space + time
NodeId     := { name: String, addr: SocketAddr, uid: u64 }          // a cluster node
ActorRef   := { pid: Pid, hint: ResolveHint }                       // location-transparent handle
ResolveHint:= Local(CellPtr) | Remote(NodeId) | Unresolved          // cached resolution
DeadLetter := { from: Pid, to: Pid, payload: Bytes, reason: DeadReason }
  • local_id is unique within a node and incarnation; reuse after restart is disambiguated by incarnation (I13) — a stale ref to a pre-restart actor resolves to dead, never to a new actor that reused the id.
  • ActorRef::send resolves hint: Local → enqueue on the cell's mailbox directly; Remote → serialize Envelope, hand to transport for that NodeId; Unresolved → consult act-addr registry / cluster.

8.3 Message, Envelope, and the wire format

Logical message (application type) → wrapped in an Envelope for routing/wire.

Envelope := { to: Pid, from: Pid, kind: MsgKind, seq: u64, payload: Bytes }
MsgKind  := User | System(SystemMsg) | Monitor(MonitorMsg)
SystemMsg:= Link(Pid) | Unlink(Pid) | Exit{from:Pid, reason:ExitReason} | Stop | Restart
MonitorMsg := Down{ref:Pid, reason:ExitReason} | MonitorReq | DemonitorReq
ExitReason := Normal | Shutdown | Killed | Panic(String) | NodeDown(NodeId)

Wire frame (length-prefixed, big-endian on the TCP byte stream):

+--------+--------+----------------+-----------------+------------------+============+
| MAGIC  | VER    | FRAME_LEN(u32) | FRAME_TYPE(u8)  | HEADER (varint)  |  PAYLOAD   |
| 0xAC70 | u16    | bytes to follow| Msg|Ping|PingReq | to/from/kind/seq |  (opaque)  |
|        |        |                | Ack|Gossip|Hello | (serialized)     |            |
+--------+--------+----------------+-----------------+------------------+============+
FRAME_TYPE := Hello(0) Msg(1) Ping(2) PingReq(3) Ack(4) Gossip(5) Bye(6) ExitSig(7)
  • FRAME_LEN bounds the read (reject > 16 MiB before allocating — I6). Decoder reads header (fixed/varint), then exactly payload_len bytes; never trusts a length past the buffer.
  • Payload serialization is pluggable (ADR-005): bincode-style fixed for internal types; user payloads carry a type-tag the receiving node maps to a deserializer (or dead-letters on unknown type).
  • Handshake (Hello): { proto_ver, node_id, incarnation, capabilities } — both sides exchange before any Msg; version-mismatch → close (or negotiate down within a major, Compatibility & Versioning).

8.4 Mailbox semantics

Mailbox := bounded lock-free MPSC<Envelope>, capacity C, policy P
enqueue(env) -> Ok | Err(MailboxFull)   // many producers (any sender), wait-free fast path
dequeue()    -> Option<Envelope>        // single consumer (the owning cell), FIFO
policy P     := Block | DropNewest | DropOldest | Fail   // backpressure (I8)
  • FIFO per sender pair (I4): the queue is FIFO; combined with per-connection FIFO on the wire, A→X order is preserved. No cross-sender order guarantee.
  • System messages (Link/Exit/Stop) may use a priority lane (out-of-band) so a crash signal is not stuck behind a backlog of user messages — Erlang-style (documented in Phase 3).
  • Activation: the first enqueue onto an empty mailbox flips the cell idle→ready and notifies the scheduler (exactly once; subsequent enqueues while ready do not re-notify).

8.6 Supervision tree + strategies

Supervisor := { children: Vec<ChildSpec>, strategy: Strategy, intensity: (max_r:u32, within:Duration) }
ChildSpec  := { factory: Fn()->Actor, restart: Permanent|Transient|Temporary, id: ChildId }
Strategy   := OneForOne | OneForAll | RestForOne
Strategy On a child crash, restart…
OneForOne only the crashed child
OneForAll all children (siblings share fate)
RestForOne the crashed child + all children started after it (ordered dependency)
  • restart policy: Permanent (always restart), Transient (restart only on abnormal exit), Temporary (never restart).
  • Intensity (I9): if a child crashes > max_r times within within, the supervisor itself fails → its parent applies its strategy → escalation propagates toward the root. The root's failure = orderly node shutdown ("let it crash" to the top).

  • Membership updates (Alive/Suspect/Dead + incarnation) are gossiped piggybacked on ping/ack frames (Gossip frame type), converging in O(log N) rounds.
  • A node that hears it is Suspect/Dead but is alive bumps its incarnation and gossips Alive to refute (I13) — prevents a healthy node from being permanently evicted on a transient blip.

8.8 Worked example — local supervised counter

1. root spawns Supervisor S (OneForOne, intensity 3-in-5s).
2. S spawns child Counter C (Permanent). C.state = 0. Pid{node=N1,inc=0,id=7}.
3. clientRef.send(C, Inc) ×3  → mailbox [Inc,Inc,Inc] ; C activated, runs each (one at a time, I1): state 0→1→2→3.
4. clientRef.send(C, Crash)   → handler panics → Terminating → Exit{C, Panic("boom")} to S (I7).
5. S strategy OneForOne, intensity ok (1<3) → restart C: re-run factory → C' Pid{N1,inc=0,id=8}, state=0 (I10).
   (a stale ref to id=7 now dead-letters — I13/I14.)
6. clientRef(old, id=7).send(Inc) → resolve → dead → DeadLetter{reason: ActorGone} (at-most-once, I14).

8.9 Worked example — remote send across a partition

NodeA actor P holds remoteRef R → actor Q on NodeB. Steady state: P.send(R,msg) → Envelope over TCP A→B → Q.mailbox.
Partition A|B:
  - NodeA's detector: B's heartbeats stop → φ rises → φ>θ → B Suspect → ping-req via C fails → B Dead (I12).
  - R is invalidated: P.send(R,msg) now → DeadLetter{NodeDown(B)} fast-fail (no hang). Monitors on Q fire Down{Q, NodeDown(B)}.
  - On NodeB (other side): A is likewise declared Dead. Both sides remain AVAILABLE (AP). This is split-brain — SURFACED, not merged (principle 8).
Heal:
  - Connectivity returns; Hello re-handshake; incarnations exchanged. If B restarted, its incarnation is higher → A adopts (I13);
    old refs to pre-restart B actors stay dead (I13). No automatic state reconciliation (deferred / CRDT note, Phase 9).

8.10 Malformed / failure-path examples

  • Oversize frame: FRAME_LEN = 4 GiB → reject before alloc, close connection, frame_error (I6); peer re-handshakes.
  • Unknown payload type-tag: receiver has no deserializer → dead-letter the message (do not crash the receiving actor) — graceful degradation.
  • Truncated frame (connection drops mid-frame): decoder returns FrameError::Truncated; connection torn down; per-sender FIFO means in-flight unacked messages (ALO mode) are redelivered on reconnect (I15); default mode drops them (I14).
  • Mailbox flood: a producer outpaces a consumer → mailbox hits capacity C → policy applies (Block throttles the producer; DropNewest sheds load; Fail returns MailboxFull to sender) — never OOM (I8).
  • Crash loop: a child crashes immediately on every restart → intensity limit (R-in-T) trips → supervisor escalates (I9) rather than spinning forever.
  • False-positive death: a node GC-pauses 4 s with a 1 s heartbeat → φ rises → Suspect; if it recovers and gossips Alive with a refute before the suspicion timeout, it is reinstated (I13) — no eviction. If it stays silent past timeout → Dead (acceptable false positive, ◇P, principle 7).
  • Duplicate under ALO: at-least-once redelivers an unacked message; the receiver's dedup window suppresses the duplicate by (from, seq) (I15); outside the window (very late duplicate) the application must be idempotent (documented limit — exactly-once = dedup + idempotency, never free).
  • Self-link / monitor-of-self: rejected or no-op (an actor crashing cannot meaningfully notify itself); validated at link time.

Design principles (§6)

  • No shared mutable state across actors (the prime directive). An actor owns its state exclusively; the only inter-actor communication is by value via messages. Enforced by Rust ownership + Send bounds on messages and the cell-runs-on-one-worker rule. Tradeoff: copying/serialization cost vs. data-race freedom. Violation: sharing a &mut across actors reintroduces locks, races, and the very bugs the model abolishes — I2 breaks and the safety story collapses.
  • One message at a time, per actor. A cell handles exactly one message per activation; never two concurrently. Tradeoff: a single actor is a serialization point (not internally parallel — split work across actors). Violation: concurrent handling = data race on private state + non-determinism, breaking I1 and #344 replay.
  • Let it crash; supervise, don't defend. Actors do not litter handlers with defensive error recovery; on an unexpected fault they crash, and a supervisor restarts them to a known-good state. Tradeoff: restart cost + transient unavailability vs. simpler, more correct code. Violation: in-actor try/catch everywhere recreates fragile error spaghetti and hides faults from the supervision tree (I9).
  • Location transparency — but honest about partial failure. send is identical local or remote; however, remote sends can silently fail (at-most-once over a partition). We do not pretend remote == local (per Waldo's "Note on Distributed Computing"); monitors + dead-letters surface remote failure. Violation: assuming remote sends always arrive → lost-message bugs that only manifest under partition (I11/I12).
  • Backpressure everywhere; bounded mailboxes. Every mailbox is bounded; a slow consumer applies backpressure (block/drop/fail) rather than growing unboundedly. Tradeoff: a fast producer is throttled vs. OOM. Violation: unbounded mailbox → one slow actor OOMs the node (I8), the classic actor-system outage.
  • Crash-only / restart over repair. Components start and stop; there is no "repair in place." Restart returns to a known state (state is rebuilt, not patched). Violation: in-place mutation recovery leaves half-broken state — restart is the only trusted recovery (drives Phase 4 + #163 boundary).
  • Failure detection is a hint, not a fact (◇P). A "dead" verdict can be wrong (a slow node looks dead). The detector is eventually accurate but may false-positive; the system must tolerate a live node being declared dead (and recover when it refutes via incarnation). Tradeoff: aggressive detection (fast, false positives) vs. conservative (slow, misses). Violation: treating detection as ground truth → killing healthy nodes (split-brain amplification, I12).
  • AP, not CP — surface split-brain, don't fake consensus. Under partition we stay available on both sides and report the split; we never silently pick a winner or pretend consistency. Consensus (#42 Raft) is a deliberate non-goal. Violation: faking exactly-once / single-truth without consensus → silent data divergence (I-delivery, Phase 10).
  • Determinism per actor. Given a fixed arrival order of messages, an actor's state trajectory is reproducible (no hidden nondeterminism in the handler path beyond the inputs). Tradeoff: must thread time/randomness as explicit messages/inputs. Violation: Instant::now()/RNG inside handlers breaks #344 deterministic replay (I1).
  • The wire decoder never trusts its input. Every inbound frame is hostile: bounded sizes, no panic, no OOB, no unbounded allocation. Fuzzed + Miri-checked. Violation: a crafted frame crashes or OOMs a node = remote DoS across the cluster (I6, Threat Model).
  • Fair scheduling via reduction counting. No actor monopolizes a worker; cooperative preemption (reduction budget) bounds per-activation work, then yields. Tradeoff: preemption overhead vs. fairness. Violation: a hot actor (tight message loop) starves all others on that worker (I3), latency cliff.
  • Explicit ownership of every async resource. Each TCP connection, worker thread, timer, and mailbox has exactly one owner; shutdown is orderly (drain → close → join). Violation: leaked connections/threads on shutdown → fd exhaustion + zombie workers.
  • Per-sender FIFO, no global order. Messages from one sender to one actor arrive in send order; there is no total order across senders. Tradeoff: cheap (no global sequencer) vs. callers must not assume cross-sender ordering. Violation: assuming global order → reordering bugs that pass locally and fail under load/distribution (I4).
  • Observability is first-class. Mailbox depth, scheduler reductions/parks, restart counts, detector φ, frame errors, membership transitions are all metricized + traced from day one. Violation: an opaque async runtime is undebuggable in production (where the bugs are).
  • Stable wire + API compatibility (SemVer). The wire protocol (handshake version negotiation) and the public Actor/ActorRef/Pid API are SemVer'd; nodes of adjacent versions interoperate. Violation: an unversioned wire change splits the cluster on rolling upgrade (Compatibility & Versioning).
