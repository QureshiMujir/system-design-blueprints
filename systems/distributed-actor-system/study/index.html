How does the backpressure propagate, and what are the three levers an operator has to address it without dropping data? Mental Models & First Principles

MM1 — An actor is a unit of failure, not a unit of computation. The compressed insight: the actor boundary exists for fault isolation, not for parallelism. A supervisor tree is not an optimization structure — it is a fault-containment boundary. Predicts: a crash in one actor cannot corrupt another's state; a crash in a subtree escalates cleanly up to a bounded recovery point. Bug class without it: writing try/catch inside handlers to avoid supervision (hiding faults from the tree, defeating the reliability model). Applying §: §6 P3/P6, Phase 4 (supervision tree), §7 I9/I10.

MM2 — The mailbox is the actor's event loop; one message at a time is not a restriction, it is the contract. An actor's handle method is not "called concurrently sometimes" — it is always called one at a time, with the actor owning its state exclusively for the full duration. Predicts: no lock needed inside a handler; the actor is a single-threaded sequential processor. Bug class without it: adding a Mutex around actor state "for safety," indicating the programmer has confused actor isolation with thread safety. Applying §: §6 P2, §7 I1, Phase 0/Phase 2 (cell claim), §11 Actor trait.

MM3 — Location transparency is an API contract, not a semantics contract. ActorRef::send looks identical whether the target is on the same core or across a continent. The API is transparent; the failure semantics are not — a remote send can silently drop (at-most-once under partition) in a way a local send never does. Predicts: a slow → dead detection pipeline (phi-accrual → SWIM) is mandatory to surface remote failure; dead-letters and monitors are not optional observability, they are the only way to detect dropped remote sends. Bug class without it: treating a remote ActorRef like a local one and assuming delivery, leading to silent message loss on partition. Applying §: §6 P4, §7 I11/I14, Phase 5 (ActorRef resolution), Phase 9 (ref invalidation), Waldo 1994 paper.

MM4 — A failure detector is a hint with a confidence level, never a fact. The phi-accrual detector outputs a continuous suspicion level φ, not a binary dead/alive verdict. A node declared dead may be alive (a false positive from a GC pause). The system must accommodate false positives gracefully (incarnation refutation) and tolerate them with designed-in recovery paths. Predicts: a node recovering from a false death refutes via a higher incarnation and rejoins; no irreversible damage. Bug class without it: treating a "dead" verdict as ground truth and immediately deleting all state associated with a node, losing actors and refs that could have been recovered. Applying §: §6 P7, §7 I12/I13, Phase 9 (phi.rs, suspicion.rs, incarnation refutation).

MM5 — Exactly-once delivery does not exist; it is an alias for at-least-once + idempotency. In an asynchronous unreliable network (FLP), a sender cannot distinguish "message lost" from "message delivered but ack lost." The minimum viable exactly-once approximation is: redeliver until ack (at-least-once) + deduplicate on the receiver side (dedup window) + ensure the handler is idempotent for out-of-window duplicates. Predicts: any system claiming "exactly-once" either has a dedup window (and an idempotency requirement for late duplicates) or is lying. Bug class without it: trusting a "guaranteed delivery" abstraction, building non-idempotent handlers, and then discovering duplicate side effects (double-charges, double-commits) on reconnect. Applying §: §6 P8, §7 I14/I15, Phase 10 (dedup.rs, ALO semantics), Appendix E, Helland 2007, FLP 1985.

MM6 — SWIM gives O(1) load per node, not O(N) — that is the entire point. Naive heartbeat-based membership requires each node to heartbeat every peer: O(N) messages per period per node, O(N²) cluster-wide. SWIM's insight: ping one random peer per period, piggyback gossip on probes. Each node sends O(1) probes/period; membership changes disseminate in O(log N) gossip rounds. Predicts: SWIM membership is practical at thousands of nodes; naive all-pairs heartbeating is not. Bug class without it: implementing an O(N)-per-node heartbeat loop thinking it is equivalent to SWIM, then observing the cluster saturate its own network at N=500. Applying §: §6 P7 (hint not fact — SWIM probe is the confirmation), Phase 8 (swim.rs, gossip.rs, gossip piggybacking), Scalability Analysis.

MM7 — The M:N scheduler is an implicit message queue with fairness guarantees; reduction counting is its preemption mechanism. A thread-per-actor model gives each actor its own OS thread — correct but wasteful at millions of actors. M:N maps M actors to N OS threads; the reduction budget is the preemption point that prevents a hot actor from monopolizing a worker. Predicts: without reduction counting, a message-tight actor loop starves all other actors on that worker. Bug class without it: building a "fiber" scheduler without a fairness bound, seeing latency spikes when one actor receives a burst. Applying §: §6 P11, §7 I3, Phase 1 (reductions.rs, worker.rs), BEAM scheduler ERTS paper.

MM8 — The wire decoder is a security boundary; frame length must be validated before allocation. Every inbound byte on the TCP socket is potentially hostile. The canonical remote DoS: a crafted frame with FRAME_LEN = 4 GiB causes the receiver to allocate 4 GiB before reading any payload. The fix is to validate FRAME_LEN against the configured maximum before any allocation. Predicts: a decoder that allocates first and checks second is a remote OOM vector. Bug class without it: a Vec::with_capacity(attacker_controlled_len) crash/OOM on a single malformed packet. Applying §: §6 P10, §7 I6, Phase 6 (codec.rs, Appendix D decoder safety rules), Threat Model.

Required reading (§5)

Books

  • Armstrong, Programming Erlang (2e) — ch. on processes, message passing, links, and the "let it crash" philosophy; OTP supervisors. The canonical actor-runtime mental model; extract the process = unit of failure idea. Applied: §6 principles P2/P3/P6, Phase 0 (actor trait), Phase 3 (links/exit signals), Phase 4 (supervision strategies).
  • Armstrong, Making Reliable Distributed Systems in the Presence of Software Errors (PhD thesis, 2003) — the definitive justification for supervision trees, isolation, and "nine nines." Extract the fault-isolation + restart argument. Applied: §6 P3, Phase 4 (supervision tree + restart-intensity rationale), §7 I9/I10.
  • Cesarini & Thompson, Erlang Programming — supervision strategies, gen_server patterns, restart intensity. Extract the strategy taxonomy (one-for-one/all/rest-for-one) for act-supervise. Applied: §8.6, Phase 4 (strategy.rs, intensity.rs), Appendix F.
  • Roestenburg, Bakker & Williams, Akka in Action — ActorRef, location transparency, remoting, cluster, supervision on the JVM. Extract the same-API-local-or-remote design and cluster lifecycle. Applied: §8.2 (ActorRef design), Phase 5 (location transparency), Phase 8 (cluster lifecycle), Appendix L.
  • Vernon, Reactive Messaging Patterns with the Actor Model — message protocols, backpressure, delivery patterns. Extract mailbox + backpressure + at-least-once patterns. Applied: §8.4 (mailbox semantics), Phase 2 (backpressure policies), Phase 10 (delivery semantics).
  • Hewitt, Bishop & Steiger, A Universal Modular Actor Formalism (1973) — the original actor model. Extract the three axioms (an actor can: send messages, create actors, designate next behavior). Applied: §8.1, §6 P1/P2, Phase 0 (actor trait become_ axiom 3), §11 Context API.
  • Bos, Rust Atomics and Locks — the Rust/C++ memory model, acquire/release, building lock-free structures correctly. Extract the memory-ordering discipline for act-mailbox. Applied: Phase 2 (lock-free MPSC, ABA-free Vyukov-style ring, acquire/release annotations), §11 Core Schema types.
  • Blandy & Orendorff, Programming Rust — async, Send/Sync, ownership. Extract the static no-shared-state enforcement (I2) and the async run-loop model. Applied: §6 P1 (Send bound), §7 I2, Phase 1 (Future/Waker model), §11 Actor trait annotation.
  • Tanenbaum & Van Steen, Distributed Systems — failure models, membership, FLP, delivery semantics. Extract the at-most/at-least/exactly-once framework + the impossibility results. Applied: §6 P7/P8, Phase 10 (AMO/ALO/impossibility), Threat Model (crash-fault assumption), §7 I14/I15.
  • Kleppmann, Designing Data-Intensive Applications — ch. 8/9: faults, unreliable networks, exactly-once-as-idempotency, consensus boundary. Extract why "exactly-once" is dedup, not magic. Applied: Phase 10 (dedup.rs, exactly-once framing), §6 P8, Appendix E (delivery matrix).

Glossary · 50 terms · site-wide glossary

Actor
A unit of computation with private state, a behavior, and a mailbox; communicates only by messages.
Mailbox
A bounded queue holding an actor's incoming messages (FIFO per sender).
Message
An immutable value sent between actors (Send by value, no shared state).
Envelope
A message wrapped with routing metadata (to/from/kind/seq) for the runtime + wire.
Pid
Process identifier: {node, incarnation, local_id} — unique across space and time.
ActorRef
A location-transparent handle to an actor; send works identically local or remote.
Location transparency
The property that the send API is identical for local and remote actors (I11).
Cell
The runtime object owning an actor's state + mailbox + links; the scheduling unit.
Behavior
The function an actor uses to handle its next message (Hewitt axiom 3: become).
M:N scheduler
Maps M logical actors onto N OS threads (workers); enables millions of actors.
Worker
An OS thread (one per core) running ready cells from its run-queue.
Run-queue
A worker's queue of ready (has-messages, not-running) cells.
Work-stealing
Idle workers steal cells from busy workers' run-queues to balance load.
Reduction
A unit of work; an actor's per-activation budget bounds work for fairness (I3).
Preemption
Yielding a cell when its reduction budget is exhausted (cooperative, Erlang-style).
Parking
A worker sleeping (futex/condvar) when no cells are ready, woken on enqueue.
Backpressure
Throttling/dropping when a bounded mailbox is full (block/drop/fail) (I8).
Supervision tree
A hierarchy where each actor (except root) has a supervisor that restarts it on crash.
Supervisor
An actor that traps child exits and applies a restart strategy.
Strategy
one-for-one / one-for-all / rest-for-one — which children to restart on a crash.
Restart intensity
Max R restarts in T seconds before the supervisor escalates (I9).
Let it crash
The philosophy: don't defend in-actor; crash and let a supervisor restart to a known state.
Link
A bidirectional fate-share: a crash propagates an exit signal to linked actors (I7).
Monitor
A unidirectional watch: get a Down message when the target dies, without dying.
Exit signal
A SystemMsg::Exit{from,reason} sent to links/supervisor on termination.
Trap exits
An actor flag making exit signals arrive as normal messages (how supervisors work).
Dead letter
A message that couldn't be delivered (no such actor / node down), routed for observability.
Wire protocol
The binary frame format (magic+version+len+type+header+payload) nodes speak over TCP.
Frame
A length-prefixed unit on the wire (Hello/Msg/Ping/PingReq/Ack/Gossip/Bye/ExitSig).
Handshake
The Hello exchange (proto version + identity + incarnation) opening a connection.
Serialization
Encoding an envelope/payload to bytes for the wire (and back).
Cluster
A set of nodes (one actd each) connected pairwise, forming one actor system.
Node
An actd process; a member of the cluster; hosts many actors.
SWIM
Scalable Weakly-consistent Infection-style Membership: ping + ping-req + gossip.
Gossip
Piggybacked dissemination of membership updates (epidemic / anti-entropy).
Incarnation
A per-node monotonic counter; higher wins, used to refute false suspicion (I13).
Ping-req
An indirect probe: ask k members to ping a target you couldn't reach directly.
Failure detector
A component that suspects/declares peers dead (eventually accurate, ◇P).
phi (φ) accrual
A detector outputting a continuous suspicion level from heartbeat arrival statistics.
Heartbeat
A periodic liveness signal between nodes, feeding the φ detector.
Split-brain
A partition where each side believes the other is dead (AP: surfaced, not merged).
AP / CP
Availability+Partition-tolerance vs. Consistency+Partition-tolerance (CAP); we are AP.
At-most-once
A message is delivered 0 or 1 times (Erlang default); may be lost, never duplicated (I14).
At-least-once
A message is delivered ≥1 time (redeliver until ack); may duplicate → dedup (I15).
Exactly-once
Unachievable without dedup + idempotency; we do not claim it (principle 8).
Dedup window
A bounded per-sender seen-seq set suppressing duplicates in at-least-once mode.
Idempotency
A handler safe to run more than once with the same effect (required for effectively-once).
FIFO per sender
Messages from one sender to one actor arrive in send order (I4); no global order.
loom
A Rust tool exhaustively model-checking concurrent code interleavings.
Crash-fault
The assumed fault model: nodes crash/stop, do not lie (non-Byzantine).
