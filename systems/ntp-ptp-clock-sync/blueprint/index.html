394 — NTP/PTP Clock Synchronization from Scratch

Project Number: 394 Project Name: NTP/PTP Clock Synchronization from Scratch Owner: Mujir Qureshi Document: FINAL_BLUEPRINT.md Status: specification — locked

1. Goal

Build clock synchronization from first principles: a correct, observable, Byzantine-tolerant time daemon plus a virtual-clock library.

Deliverables (in scope):

  • NTPv4 client + server (RFC 5905): on-wire protocol, full mitigation pipeline (clock filter → selection → clustering → combining), clock discipline loop (hybrid PLL/FLL), poll scheduler, reachability, KoD.
  • SNTP mode (RFC 4330): stateless one-shot client/server; compute offset θ and delay δ from four timestamps; no discipline state machine.
  • PTP ordinary + boundary clock (IEEE 1588-2008, 1588-2019): event/general ports, delay request-response + peer-delay mechanisms, BMCA, PI servo, datasets, one-step/two-step.
  • Local clock model: oscillator (phase, frequency, drift, jitter) for deterministic simulation.
  • OS clock disciplining: clock_adjtime/adjtimex (ntp_adjtime) actuation; step vs slew; drift-file persistence.
  • NTS (RFC 8915): NTS-KE over TLS, cookies, AEAD-protected packets; symmetric-key auth (RFC 5905 Appendix).

System boundaries:

  • Inputs: UDP/123 (NTP), UDP/319-320 or raw L2 0x88F7 (PTP), NTS-KE TCP/4460 (TLS), IERS leap table, drift file.
  • Outputs: disciplined system clock (CLOCK_REALTIME) or virtual clock; served NTP/PTP; telemetry.
  • Trust boundary: every received packet is hostile until sanity-checked + (optionally) authenticated.

Explicit non-goals:

  • NOT a hardware NIC PHC driver. Use SW/kernel timestamps (SO_TIMESTAMPING); HW timestamping gated PhaseDeferred("Deferred Features Register").
  • NOT a GPS/PPS reference-clock driver beyond a stub refclock (clock/refclock_stub).
  • NOT NTP Autokey (deprecated, broken security model) — PhaseDeferred never; rejected outright.
  • NOT a full Stratum-1 appliance (no oscillator hardware, no rubidium holdover, no antenna mgmt).
  • NOT mode 6 (control) read/write beyond read-only status, mode 7 (private/monlist) forbidden (amplification).
  • NOT PTP transparent clock (TC) in Phase 0 — PhaseDeferred("Deferred Features Register").

Deployment model:

  • ntpx daemon: long-running, disciplines CLOCK_REALTIME, serves NTP/PTP, exposes metrics on /metrics.
  • libclocksync: embeddable virtual-clock library; same discipline/servo code path against an in-memory OscillatorModel (no syscalls) for tests and embedded simulation.
  • One static binary; capability-dropped (CAP_SYS_TIME only); seccomp filter post-init.

Target users: timing engineers, distributed-systems engineers needing bounded clock error (consensus, snapshotting, TrueTime-style intervals), exchange/finance ops under MiFID II / FINRA timestamp mandates.

Phase 0 deliverable — numbered modules:

  1. timestamp/ — ntp_ts (32.32 fixed), ptp_ts (48.32), fixed, timescale, leap.
  2. wire/ — ntp_packet, ptp_message, ext_fields, parse.
  3. net/ — udp, l2, timestamping.
  4. ntp/sntp — one-shot client computing θ, δ.
  5. clock/virtual_clock — deterministic oscillator-backed clock.
  6. cli/ — ntpx query (SNTP one-shot) + ntpx version.

Later phases unlock: associations + filter (P2), selection/clustering/combining (P3), discipline loop (P4), OS actuation (P5), server (P6), leap (P7), NTS (P8), PTP message/transport (P9), PTP delay mechs (P10), BMCA/state machine (P11), PTP servo + holdover + combined selection (P12), conformance + soak (P13).

Deferred features (gated):

  • HW timestamping / PHC cross-timestamp → PhaseDeferred("Deferred Features Register").
  • PTP transparent clock + management msgs → PhaseDeferred("Deferred Features Register").
  • GPS/PPS refclock → PhaseDeferred("Deferred Features Register").
  • Interleaved (xleave) NTP mode → PhaseDeferred("Deferred Features Register").
  • G.8275.1 full telecom profile certification → PhaseDeferred("Deferred Features Register").

Timeline: Phase 0 = 6–12 weeks (single engineer). Full (P0–P13) = several months. Soak/Allan (P13) adds 30+ continuous days wall-clock.

Recommended language: Rust.

  • Rationale: NO GC pauses — a stop-the-world pause mid-servo-update injects phase error directly into the loop filter; GC jitter corrupts timestamps and destabilizes the servo. Precise control of memory layout + syscalls (recvmmsg, clock_adjtime, SO_TIMESTAMPING cmsg parsing). Safe parsing of hostile packets (no buffer overruns in attacker-controlled length fields). Fearless concurrency (I/O thread feeds samples to time-critical thread via lock-free channel).
  • Reject Go: GC jitter unacceptable for sub-µs PTP servo; scheduler preemption adds timestamp noise.
  • Reject C: unsafe packet parsing (the historical source of ntpd CVEs), manual concurrency, no ownership model for clock state.

Prerequisites:

  • Control theory: PLL/FLL, PI loops, loop gain, time constant, damping, stability margins.
  • Statistics/filtering: median/min selection, RMS jitter, linear regression (chrony-style), Allan variance.
  • Time scales: UTC vs TAI, leap seconds, POSIX time, monotonic clocks, epochs/eras.
  • Fixed-point math: 32.32 and 48.32 representations, rounding, overflow, sign.
  • UDP networking + ancillary data (cmsg, SCM_TIMESTAMPING).
  • OS clock APIs: adjtimex/clock_adjtime, timex struct, STA flags.
  • IEEE-754 double (for servo math only; never on the wire).

2. Why Build This

Unique systems knowledge taught:

  • Offset/delay estimation from four timestamps under asymmetric, jittered paths.
  • Filtering + Byzantine-tolerant selection (Marzullo/intersection): a single falseticker must never win even if it lies consistently.
  • Feedback control of a physical oscillator: discrete PLL/FLL/PI design, stability, settling, overshoot.
  • Time-scale arithmetic: leap-second insertion/deletion, UTC/TAI conversion, smearing, era rollover (2036 NTP, 2038 not applicable to 64-bit NTP but relevant to OS).
  • Sub-µs PTP timestamping: hardware/kernel timestamp capture, correctionField accumulation, transparent-clock residence time.
  • Holdover modeling: honest error growth when all sources lost; drift extrapolation; uncertainty inflation.

Historical / architectural significance:

  • Mills' NTP, deployed since 1985 — one of the oldest continuously running Internet protocols; the canonical adaptive feedback system on the Internet.
  • IEEE 1588 (PTP) — backbone of telecom (5G fronthaul), finance (exchange colocation), industrial automation, power-grid synchrophasors.
  • Google TrueTime/Spanner — external consistency depends on a bounded clock-error interval [earliest, latest]; commit-wait blocks on it. This project builds the same uncertainty accounting.
  • Regulation: MiFID II RTS 25 (100 µs / 1 ms traceability to UTC), FINRA clock-sync rules — time is a compliance artifact.

Engineering muscles:

  • Control loops under noise (rare in app dev; core to robotics, RF, PLLs).
  • Numerical stability with fixed-point + IEEE-754 mixed math.
  • Adversarial-input parsing (packets are attacker-controlled).
  • Separating measurement from actuation (estimator vs controller).

Cross-links:

  • #376 Chandy-Lamport snapshots — distributed-time reasoning; consistent cuts assume bounded skew.
  • Consensus projects (Raft/Paxos) — leader leases + bounded clocks; this provides the error interval they assume.
  • Userspace networking stack — SO_TIMESTAMPING, raw L2 frames, recvmmsg.
  • Monitoring/observability stack — offset/jitter/freq gauges, histograms, Allan deviation dashboards.

Calibration value: permanently raises capability in control theory, adversarial parsing, and uncertainty-aware distributed systems. After this, "the clock is reliable" is never an unexamined assumption again.

What Mastery Looks Like

  • Design a feedback controller for a physical oscillator — after Phase 4 you can size a hybrid PLL/FLL loop filter (time constant tied to poll, damping ζ≈1, ±500 ppm clamp), predict its step response and settling time, and explain why an over-aggressive gain amplifies path-delay-variation into the clock (§8.6, P4 of §6, I4).
  • Estimate offset and bound its error from four timestamps — after Phase 1 you can derive θ and δ from T1–T4, compute the dispersion/jitter/root-distance error budget, and produce a sound [earliest, latest] interval that a TrueTime-style consumer can rely on (§8.4, I2, MM1).
  • Make source selection Byzantine-tolerant — after Phase 3 you can implement Marzullo intersection + clustering + inverse-variance combining and prove a minority of falsetickers can never walk the clock, even when they lie consistently (§8.5, P3 of §6, I3, MM3).
  • Parse hostile packets without a CVE — after Phase 1 (and hardened through Phase 8) you can write a bounded, zero-copy, no-allocation NTP/PTP parser with constant-time MAC compare and verify-before-process ordering, defeating the spoof/replay/amplification class that produced ntpd's CVE history (§8.17, I10/I11/I15, MM7).
  • Handle time-scale arithmetic correctly — after Phase 7 you can apply a leap second exactly once at the right instant (or smear it monotonically), convert UTC↔TAI↔POSIX, and survive the 2036 NTP era rollover without an off-by-one-second or off-by-136-year bug (§8.3/§8.15, I6/I8, MM5).
  • Discipline a real OS clock and run honest holdover — after Phase 5 and Phase 12 you can actuate CLOCK_REALTIME via clock_adjtime as the sole disciplinarian, persist frequency across reboots, and grow reported uncertainty honestly when all sources are lost rather than presenting drift as accuracy (§8.6, I9/I13, P9/P14 of §6, MM6).
  • Build sub-µs PTP from the wire up — after Phases 9–11 you can implement the PTP message layer, kernel timestamping, both delay mechanisms, the BMCA election, and the boundary-clock relay, and explain where path asymmetry sets the hard accuracy floor (§8.7–§8.12, I7, MM4/MM8).
  • Test a control loop deterministically — after Phase 13 you can replay a recorded sample stream through the servo for bit-identical corrections, differential-test against chrony/ntpd/ptp4l, and read an Allan-deviation plot to find slow drift invisible in short tests (P15 of §6, I1/I2/I4, MM2).

Per-box detail:

  • net/ RX+TX + timestamping: owns sockets (UDP 123/319/320, raw L2). Captures T2 (server RX) / T4 (client RX) via SO_TIMESTAMPING ancillary cmsg; SW fallback = clock_gettime immediately post-recvmmsg. TX timestamp (T3/t1) via send-side SO_TIMESTAMPING errqueue or estimate. Batches with recvmmsg/sendmmsg. Sole syscall surface for I/O.
  • wire/ parse+sanity: zero-copy bounded parse of ntp_packet/ptp_message. Rejects: short buffer, mode 7, bad version, stratum 16 source for sync, leap=alarm, negative delay, length-field overrun. Verifies MAC (symkey) / AEAD (NTS). No allocation on hot path.
  • Protocol engine (ntp/assoc, ptp/port): per-peer association FSM (NTP) / per-port BMCA + state FSM (PTP). Matches origin timestamp echo (anti-replay). Drives poll/announce cadence.
  • Offset/Delay compute: pure function of T1..T4; produces sample (θ, δ, ε, ψ_seed). Detects asymmetry hints (delay variance).
  • ntp/filter: 8-entry shift register per source; selects min-delay sample (least queueing); computes jitter ψ = RMS of offset deltas; emits dispersion ε with age growth.
  • ntp/select: builds correctness intervals [θ−δ/2−ε, θ+δ/2+ε]; Marzullo/intersection finds largest set of overlapping intervals → truechimers; falsetickers excluded.
  • ntp/cluster: iteratively culls the survivor with worst selection jitter until ≤ NMIN or jitter floor.
  • ntp/combine: weighted average of survivors (weight ∝ 1/ψ) → system offset, system jitter, root dispersion.
  • discipline/: hybrid PLL/FLL loop filter (NTP) or PI servo (PTP). Converts system offset → frequency + phase correction. Owns step/slew/panic decision.
  • clock/oscillator_model: software model/estimator of the local oscillator (phase, freq, drift, jitter); used by virtual clock and for holdover extrapolation.
  • clock/sys_clock | virtual_clock: actuator. sys_clock issues clock_adjtime (slew via freq/offset, step via ADJ_SETOFFSET). virtual_clock mutates the model in-process for deterministic tests.
  • Side: poll scheduler (exponential backoff/forward), BMCA (best master election), holdover controller (error growth when sources lost), leap handler (insert/delete at instant), security (NTS/symkey/ratelimit/KoD), telemetry.

6. Design Principles

  1. Never step time backwards once disciplined. After first sync, only slew (gradual frequency nudge) unless offset exceeds STEP (125 ms), in which case step forward/back is allowed only when no app monotonicity contract is broken — and never below PANIC handling. Tradeoff: slew is slow to converge large errors. Operational: apps relying on gettimeofday monotonicity (databases, log ordering) break on backward steps. Violation → duplicate timestamps, TLS "not yet valid", DB MVCC corruption.

  2. Bounded, expressed uncertainty. Every reported time carries Uncertainty{max_error, est_error} derived from root delay/dispersion + jitter; expose [earliest, latest] (TrueTime-style). Tradeoff: extra bookkeeping. Operational: consumers (consensus, commit-wait) need the bound, not a point. Violation → callers assume false precision; ordering guarantees collapse.

  3. Byzantine-tolerant source selection. Use Marzullo/intersection so a single (or minority) falseticker cannot win even if internally consistent. Tradeoff: needs ≥3 sources to outvote 1 liar; rejects valid-but-distant sources. Operational: never trust one server. Violation → a compromised/misconfigured server walks your clock.

  4. Servo stability over speed. Conservative loop gains; damping ζ≈1; bound frequency slew rate. Tradeoff: slower convergence. Operational: an oscillating servo is worse than a slightly slow one (it amplifies PDV into the clock). Violation → frequency runaway, clock hop, never settling.

  5. Reject before discipline. Sanity-check every sample before it can influence the clock: stratum < 16, non-zero refid/timestamp, leap ≠ alarm (11), delay ≥ 0, dispersion bounded, origin-timestamp echo matches. Tradeoff: may discard borderline-good samples. Operational: garbage-in poisons the loop filter for hours. Violation → one bad packet destabilizes the servo.

  6. Determinism of time-scale math. UTC/TAI/leap handled explicitly; never depend on ambiguous local time or localtime. All internal math in TAI or monotonic; convert at edges. Tradeoff: must carry leap table. Operational: leap second at 23:59:60 must apply exactly once. Violation → off-by-one-second for months, or double-application.

  7. Hostile-packet defensive parsing. Bounded reads, no trust in length fields, no allocation driven by attacker input, constant-time MAC compare. Tradeoff: more code than naive parse. Operational: NTP is UDP, spoofable, internet-facing. Violation → RCE/DoS (the ntpd CVE history).

  8. No amplification / abuse vectors. No mode 7 monlist (huge response to tiny request); rate-limit responses; emit KoD RATE instead of amplifying; response ≤ request size class. Tradeoff: legitimate bursty clients throttled. Operational: open NTP servers were top DDoS reflectors (2013–14). Violation → your server becomes a weapon.

  9. Holdover with honest error growth. When all sources lost, extrapolate from last frequency estimate and grow max_error at the worst-case drift rate. Tradeoff: clock keeps running but uncertainty widens. Operational: report degraded clockClass; alarm when error exceeds SLO. Violation → silent drift presented as accurate.

  10. Observability of offset/jitter/frequency. Every loop iteration emits offset, jitter, freq (ppm), root dispersion, reach, selected source, leap state, PTP port state. Tradeoff: telemetry overhead. Operational: you cannot debug a control loop you cannot see. Violation → opaque clock-hop incidents with no forensics.

  11. Separate measurement from actuation. Estimator (filter/select/combine) is pure and side-effect-free; controller (discipline) and actuator (sys_clock) are isolated. Tradeoff: more layers. Operational: enables virtual-clock testing (same estimator, fake actuator) and reasoning about each stage. Violation → untestable, tangled feedback.

  12. One actuator owns the clock. Exactly one component issues clock_adjtime; no other code touches CLOCK_REALTIME. Tradeoff: serialization. Operational: prevents fighting controllers (e.g., ntpd + systemd-timesyncd both adjusting). Violation → dueling adjustments, instability. (Mirrors NTP single-source-of-discipline and PTP single-master.)

  13. Fixed-point on the wire, float only for control. Wire timestamps are exact fixed-point (NTP 32.32, PTP 48.32); IEEE-754 f64 used only inside servo math, never serialized. Tradeoff: conversion code. Operational: f64 cannot represent NTP fraction exactly past ~µs near large seconds. Violation → silent precision loss, biased offsets.

  14. Fail toward not-stepping. On ambiguity (lost sources, suspect leap, parse doubt) prefer holdover/no-action over a risky correction. Tradeoff: may stay slightly off. Operational: a wrong step is worse than a small known error. Violation → confident wrongness.

  15. Idempotent, replayable discipline. Given the same sample stream + initial state, the loop filter produces identical corrections (deterministic). Tradeoff: must avoid wall-clock-dependent branches inside the loop. Operational: enables clknetsim replay + differential testing. Violation → non-reproducible servo bugs.

8.3 NTP timestamp format

  • 64-bit, unsigned, 32.32 fixed-point seconds since 1900-01-01 00:00:00 UTC (the prime epoch).
  • Upper 32 bits = seconds; lower 32 bits = fraction (resolution 2^-32 s ≈ 233 ps).
  • Era: seconds field wraps every 2^32 s ≈ 136 years. Era 0 ends 2036-02-07 06:28:16 UTC; era 1 begins. Comparison must be era-aware: pick the era minimizing |difference| relative to a pivot (current best time). Internal storage = 64-bit NTP value + explicit era counter (i8) ⇒ effective range > 8 billion years.
  • Short format (Root Delay/Dispersion) = UQ16.16 seconds (32-bit).
  • Conversion to/from POSIX (CLOCK_REALTIME, seconds since 1970): ntp_sec = posix_sec + 2_208_988_800 (seconds 1900→1970), fraction = nanos * 2^32 / 1e9.

8.4 Core NTP equations

Given client xmit T1, server recv T2, server xmit T3, client recv T4:

offset  θ = ( (T2 − T1) + (T3 − T4) ) / 2
delay   δ = ( T4 − T1 ) − ( T3 − T2 )
  • θ: estimated correction to add to local clock (local + θ ≈ server).
  • δ: round-trip delay; assumes symmetric path (the core assumption + its core vulnerability).
  • Dispersion ε (per sample): ε = ρ_server + ρ_local + φ·(T4 − T1) where ρ = precision, φ = max drift (15 ppm). Grows with age.
  • Peer jitter ψ: RMS of differences between the chosen offset and the other 7 filter samples: ψ = sqrt( (1/(n−1)) Σ (θ_i − θ_0)^2 ).
  • Root delay Δ = peer δ + server root delay (Root Delay field). Root dispersion E = peer ε + peer jitter + server root dispersion.
  • Maximum error (the bound, I2): Λ = E + Δ/2. True offset ∈ [θ − Λ, θ + Λ].

8.5 Mitigation pipeline (NTP)

  1. Clock filter (ntp/filter): per association, 8-sample shift register of (θ, δ, ε, t). On new sample: shift in, age all ε. Select the sample with minimum δ (least queueing delay ⇒ most accurate). Output offset = its θ; output jitter ψ = RMS over window; output dispersion = weighted by age Σ θ_i·2^-i. Discard if all samples stale (ε > MAXDISP 16 s).
  2. Selection / intersection (ntp/select): for each survivor of the filter, form correctness interval [θ−Λ, θ+Λ]. Run Marzullo/intersection: find the largest clique of overlapping intervals (≥ ⌈(n+1)/2⌉ to tolerate minority falsetickers). Members = truechimers; others = falsetickers (rejected). Compute the intersection interval [lo, hi], midpoint.
  3. Clustering (ntp/cluster): among truechimers, iteratively compute selection jitter (per-candidate distance to others) and cull the worst until survivors ≤ NMAX (10) and > NMIN (3) or jitter floor reached. Removes statistical outliers that passed intersection.
  4. Combining (ntp/combine): weighted average of survivors, weight w_i = 1/ψ_i^2 (inverse variance). System offset Θ = Σ w_i θ_i / Σ w_i. System jitter = combination of selection + peer jitter. Pick system peer (lowest stratum, then lowest root distance) for refid/stratum propagation.

8.6 Clock discipline (discipline/)

Hybrid PLL/FLL loop filter. State: phase estimate, frequency estimate (ppm), poll-derived time constant τ.

Discrete update (symbolic, not code):

PLL branch (phase-locked, dominant at short τ):
    x   = Θ                       (system offset, the phase error)
    freq_pll = (x / (τ^2)) · weight_p
PLL frequency adjustment integrates phase error over τ^2.

FLL branch (frequency-locked, dominant at long τ / large age):
    freq_fll = (Δx / Δt) · (1 / (4·τ)) · weight_f
FLL tracks the rate of change of offset directly.

combine:
    freq += freq_pll + freq_fll          (clamped to ±500 ppm)
    phase_correction = x · (1/τ)          (applied as slew or step)
    poll/τ adjustment: if offset small & stable → increase poll (×2 up to maxpoll)
                       if offset large/jumpy   → decrease poll (÷2 down to minpoll)
  • Time constant τ tied to poll interval; larger τ = stiffer loop (more averaging, slower).
  • Frequency held in a drift file (ppm) across restarts (warm start).
  • Weights blend PLL (good transient) and FLL (good steady-state at long poll), per Mills.

Step / slew / panic decision (discipline/step_slew):

|Θ| < STEP (125 ms)   → SLEW   (adjust freq/offset gradually via clock_adjtime)
STEP ≤ |Θ| < PANIC    → STEP   (clock_adjtime ADJ_SETOFFSET; allowed if not violating I1 / startup)
|Θ| ≥ PANIC (1000 s)  → PANIC  (refuse, log, exit/alarm — unless first sample with -g)

Slew rate cap: 500 ppm (so 125 ms takes ≥ 250 s to slew out) — bounds disruption.

8.9 PTP delay request-response mechanism

master                              slave
  |---- Sync (t1) ------------------>|  t2 = slave RX
  |---- Follow_Up (t1 precise) ----->|  (two-step only)
  |<--- Delay_Req -------------------|  t3 = slave TX
  |---- Delay_Resp (t4) ------------>|  t4 = master RX of Delay_Req
offsetFromMaster = ( (t2 − t1) − (t4 − t3) ) / 2 − meanPathDelay_correction
meanPathDelay    = ( (t2 − t1) + (t4 − t3) ) / 2
  • correctionField subtracted from each timestamp delta (residence time of TCs, asymmetry).
  • One-step: t1 written into Sync at egress (HW). Two-step: Sync sent, precise t1 follows in Follow_Up (SW/most flexible).
  • offsetFromMaster is the slave's correction (servo input). Sign: slave ahead ⇒ positive ⇒ slow down.

8.10 PTP peer-delay mechanism (link delay)

A ---- Pdelay_Req (t1) ----> B     t2 = B RX
A <--- Pdelay_Resp (t2,t3) - B     t3 = B TX
A ---- (t4 RX) <------------       t4 = A RX
linkDelay = ( (t4 − t1) − (t3 − t2) ) / 2

Measures per-link delay independent of master; used in P2P transparent-clock topologies (G.8275.1). Decouples path-delay measurement from the Sync flow.

8.11 PTP clock types

  • OC (ordinary clock): single PTP port; either master or slave. (Phase 11 target.)
  • BC (boundary clock): multiple ports; slave on one, master on others; isolates timing domains. (Phase 11 target.)
  • TC (transparent clock): forwards + updates correctionField with residence time; E2E or P2P. (PhaseDeferred §Phase 13.)
  • Grandmaster (GM): the BMCA-elected root of the timing tree; best clock in domain.

8.12 BMCA (Best Master Clock Algorithm)

Per-port: collect Announce → ForeignMaster records. Dataset comparison (Announce contents), in order:

1. priority1        (lower wins; operator override)
2. clockClass       (lower wins; 6=GM locked, 7=holdover, 52/187=degraded, 248=default)
3. clockAccuracy    (lower enum wins; e.g. 0x20=25ns … 0xFE=unknown)
4. offsetScaledLogVariance (lower wins; stability)
5. priority2        (lower wins; tiebreak among equals)
6. clockIdentity    (lower wins; final deterministic tiebreak)

Decision → port recommended state (MASTER / SLAVE / PASSIVE). State decision algorithm maps BMCA result + local role to port state.

PTP port state machine:

INITIALIZING ──ds_ready──► LISTENING
LISTENING ──announce_timeout & best=self──► PRE_MASTER ──qual_timeout──► MASTER
LISTENING ──better_master_seen──► UNCALIBRATED ──servo_locked──► SLAVE
MASTER ──better_master(BMCA)──► UNCALIBRATED/PASSIVE
SLAVE ──master_lost (announce_timeout)──► LISTENING (then BMCA)
any ──FAULT──► FAULTY ──reset──► INITIALIZING
PASSIVE: another master present, not selected, stays quiet

8.13 Worked example — full NTP exchange

Assume (NTP seconds, fraction shown as decimal seconds for readability; internally 32.32):

T1 = 3_927_000_000.000000   (client xmit)
T2 = 3_927_000_000.018000   (server recv)
T3 = 3_927_000_000.018500   (server xmit, 500 µs processing)
T4 = 3_927_000_000.022000   (client recv)

δ = (T4 − T1) − (T3 − T2) = 0.022000 − 0.000500 = 0.021500 s  (21.5 ms RTT)
θ = ((T2 − T1) + (T3 − T4)) / 2
  = (0.018000 + (−0.003500)) / 2 = 0.014500 / 2 = 0.007250 s   (+7.25 ms)

Client is 7.25 ms behind server; add +7.25 ms (slew, < STEP). Max error Λ = E + δ/2 ≈ ρ + 0.01075 s; reported [θ−Λ, θ+Λ].

t1 = 1000.000000000   (master Sync egress, precise via Follow_Up)

t3 = 1000.010000000   (slave Delay_Req TX)
t4 = 1000.010030000   (master RX, +30 µs path)

8.15 Worked example — leap second insertion (23:59:60)

LI bits = 01 (insert) flagged in NTP packets / PTP leap61 flag during the UTC day of insertion.
UTC sequence at insertion (end of 2016-12-31):
  23:59:59  → 23:59:60 (the leap second) → 00:00:00
POSIX time has no 23:59:60 ⇒ choices:
  (a) step: repeat 23:59:59 (POSIX clock holds/steps back 1s) — violates I1 if naive.
  (b) smear: spread −1s over a window (e.g. ±1000 s) at ~11.6 ppm — monotonic, never 23:59:60.
TAI−UTC increments 36→37. Internal TAI clock is unaffected; only UTC display + POSIX mapping change.
Handler: arm at LI=01, apply exactly once at the instant (I8), update leap table TAI offset, clear flag.

Chosen default: slew/smear to preserve monotonicity (I1); step only if configured + no monotonic consumers.

8.16 Worked example — falseticker rejected by Marzullo

Four sources, correctness intervals (ms):

S1: [ −2,  +2 ]
S2: [  −1, +3 ]
S3: [  0, +4 ]
S4: [ +40, +44 ]   ← falseticker (consistently 42 ms off)

Intersection: S1∩S2∩S3 overlap on [0, +2] (3 agree). S4 overlaps none of the majority. Largest clique = {S1,S2,S3} (size 3 ≥ ⌈(4+1)/2⌉=3). S4 = falseticker, rejected. System offset from intersection ≈ +1 ms. A naive average would have been pulled to +10.5 ms — the value of Marzullo.

ADR-02 Time-critical execution Single dedicated thread, no async, no alloc in loop tokio in hot loop Determinism + bounded latency; async scheduling adds jitter to servo (P15 of §6) async hot loop wins when the target is a pure SNTP/NTP server with no local discipline (no servo to keep jitter-free, §8.2 mode 4 only) and tens of thousands of concurrent flows where an async reactor's connection scaling beats a hand-pinned thread.
ADR-03 I/O model tokio (or mio) on a SEPARATE I/O thread, lock-free SPSC channel to time thread I/O in time thread Isolate syscall/wakeup jitter from control loop; batch via recvmmsg (I4) I/O in the time thread wins for a single-source embedded SNTP client (libclocksync one-shot, §1) polling at minutes-scale: one socket, no servo-jitter budget, and the extra thread + channel are pure complexity.
ADR-04 Wire timestamp repr NTP u64 32.32; PTP (u48,u32) fixed-point f64 on wire f64 loses precision at large seconds (>µs error); fixed-point is exact (I14) f64 seconds win on the display/export surface (ntpx status JSON, §Operational Readiness): human-readable µs precision suffices there and exactness is not a wire-interop requirement, so float is the right representation for the operator-facing boundary even though it is wrong on the wire (I14).
ADR-05 Servo math repr f64 internal only fixed-point everywhere Float fine for gains/integrator; never serialized (I14) fixed-point servo math wins when the discipline loop must itself be bit-reproducible across architectures for differential conformance (the determinism bar a sibling like #393 Congestion-Control imposes); f64 FMA/libm differences then break cross-arch trace equality.
ADR-06 RX timestamping kernel SO_TIMESTAMPING (SOFTWARE+RAW_HARDWARE), SW clock_gettime fallback userspace-only Kernel stamp removes scheduler latency; HW behind PhaseDeferred §Phase 13 (I2) userspace-only timestamping wins on platforms with no SO_TIMESTAMPING support (macOS, older/embedded kernels, containers without the socket option) where a post-recvmmsg clock_gettime is the only portable option and ms-class NTP accuracy is acceptable.
ADR-07 NTP loop filter Hybrid PLL/FLL (Mills) pure PI, pure PLL PLL good transient, FLL good steady-state long-poll; matches RFC 5905 pure PI wins for high-rate PTP discipline (ADR-08): with Sync at 16–128/s the loop runs far below its time constant and a PI servo (linuxptp) converges faster and is simpler than the FLL machinery the long NTP poll needs.
ADR-08 PTP servo PI controller (linuxptp-style) + linreg option PLL PTP high-rate Sync ⇒ PI converges fast; linreg for jittery profiles a PLL/FLL servo wins for very long PTP intervals or PDV-dominated WAN profiles (G.8275.2 over the public Internet) where averaging over many intervals (FLL behaviour) beats a fast PI that would amplify packet-delay-variation into the clock (P4 of §6).
ADR-09 Source selection Marzullo / intersection + clustering simple median, single source Byzantine tolerance (P3 of §6); median fails with ≥2 colluding liars near each other single-source (no selection) wins for a PTP ordinary clock locked to one BMCA-elected grandmaster (§8.12), where there is exactly one timing source by protocol design and intersection over a one-element set is meaningless overhead.
ADR-10 Filter window 8-sample shift register (NTP) larger window, Kalman RFC 5905 normative; bounded mem; min-delay heuristic proven a regression / Kalman filter wins on highly jittery WAN paths (chrony's sourcestats.c linear regression, §5): regression over a longer history converges faster and estimates frequency directly where the 8-sample min-delay pick leaves accuracy on the table (Veitch et al., IMC 2004).
ADR-11 OS actuation clock_adjtime/ntp_adjtime (timex) manual settimeofday Kernel does the slewing; ADJ_FREQUENCY/ADJ_OFFSET/ADJ_SETOFFSET (I1) settimeofday/step wins at first-boot cold start (-g) when the clock is wildly wrong (e.g. dead RTC battery, offset ≫ 1000 s) and a single hard set is the only sane action — slewing a 50-year error would take millennia at 500 ppm; this is exactly the bounded -g exception in §8.6.
ADR-12 Step vs slew policy slew < 125 ms, step 125 ms..1000 s, panic ≥ 1000 s always step / always slew Monotonicity (I1) vs convergence balance always-step wins for a stateless one-shot SNTP set-and-exit (ntpx query --set, §1): there is no running clock to keep monotonic and no servo, so a single immediate step is correct and slewing is pointless. always-slew wins for hosts that forbid any backward step (databases under strict MVCC) regardless of offset.
ADR-13 Leap-second source IERS leap-seconds.list (NIST mirror) + LI bits; smear optional hardcoded, OS-only Authoritative; smear preserves monotonicity (I8) OS-only (kernel STA_INS/STA_DEL) wins on an air-gapped host with no IERS feed and a trusted upstream NTP server already asserting LI bits — the kernel applies the leap from the upstream signal without a local table to maintain.
ADR-14 Test clock backend virtual_clock (oscillator model), no syscalls only integration tests Deterministic, fast, reproducible servo tests (P15 of §6) integration-only testing wins for the syscall-actuation layer itself (clock/sys_clock, Phase 5): the clock_adjtime/timex/STA_* mapping is exactly the part the virtual clock cannot exercise, so a real-kernel integration test is the only thing that catches a wrong ADJ_* flag.
ADR-15 Security: auth NTS (RFC 8915, TLS 1.3 KE + AEAD) + symmetric AES-CMAC Autokey Autokey broken/deprecated (reject outright); NTS modern, PFS (P7 of §6) symmetric-key (no NTS) wins for closed PTP/NTP fabrics with pre-shared keys and no PKI — datacenter or telecom links where a shared AES-CMAC key (RFC 5905 Appendix) is operationally simpler than running NTS-KE/TLS and certificate management. (The third rejected option, Autokey, is excluded outright as cryptographically broken — no regime, hence not locked.)
ADR-16 Abuse prevention Rate-limit + KoD RATE; no mode 7; response≤request open responder Anti-amplification (P8 of §6); CVE-2013-5211 lesson an "open responder" (no rate-limit) wins only inside a trusted, isolated network segment (lab, single-tenant fabric) with no internet exposure, where the rate-limit table is pure overhead and reflection/amplification (CVE-2013-5211) is not in the threat model.
ADR-17 Packet parser hand-written bounded zero-copy parser nom/serde on wire Full control over bounds; no alloc; constant-time MAC; fuzz-targeted (I15) nom/declarative parser wins for the non-hot-path, non-adversarial config and NTS-KE record formats (§8) where parser-combinator clarity and maintainability beat hand-rolling, and the per-packet allocation/latency cost is irrelevant (KE happens rarely, §8.7).
ADR-18 Async runtime crate tokio (I/O + timers only) async-std, smol Ecosystem, recvmmsg via socket2, mature smol/mio wins for the embeddable libclocksync (§1) where pulling in the full tokio dependency tree is unacceptable for a small static library and a minimal reactor (or raw mio) covers the one or two sockets needed.

11. Core Schema and Core Types

Normative signatures (no bodies). Names/fields are stable across all sections.

11.1 timestamp/

// NtpTimestamp: u64, 32.32 fixed seconds since 1900-01-01 UTC. + explicit era.
struct NtpTimestamp { bits: u64 }           // upper32=sec, lower32=frac
struct NtpDateTime  { era: i8, ts: NtpTimestamp }   // era-extended (range > 8e9 yr)
impl NtpTimestamp {
    fn from_posix(sec: i64, nanos: u32) -> Self;     // +2_208_988_800 epoch shift
    fn to_posix(self) -> (i64, u32);
    fn sub_signed(self, o: NtpTimestamp) -> NtpDuration;  // era-aware, signed
    fn add(self, d: NtpDuration) -> Self;
    fn frac_secs_f64(self) -> f64;                   // for servo math only
}
struct NtpDuration { ticks: i64 }            // signed 32.32 seconds
struct NtpShort { bits: u32 }                // UQ16.16 (RootDelay/RootDispersion)

// PtpTimestamp: 80-bit on wire (48 sec + 32 ns), TAI epoch (1970-01-01).
struct PtpTimestamp { secs: u64 /*48 used*/, nanos: u32 }   // secs masked to 48b on wire
struct PtpInterval { scaled_ns: i64 }        // ns × 2^16 (correctionField domain)

enum TimeScale { Utc, Tai, Monotonic }
struct LeapState { kind: LeapKind, armed: bool, applied: bool, tai_offset: i32 }
enum LeapKind { None, Insert /*+1*/, Delete /*−1*/, Alarm /*unsync*/ }
struct LeapTable { entries: Vec<(NtpTimestamp /*instant*/, i32 /*tai_offset*/)> }

Ownership: timestamp types are Copy, no heap, no interior mutability. LeapTable owned by timestamp/leap, read-shared via Arc, reloaded on file change. Mutation: timestamps immutable values; LeapState mutated only by leap handler. Concurrency: Copy types cross threads freely; LeapTable is Arc<...> (read-mostly). Persistence: LeapTable from leap-seconds.list. Serialization: wire = big-endian fixed-point (I14). Compatibility: NTP era handling stable; PTP 48-bit seconds.

15. Phase 3 — Source Selection (Intersection/Marzullo) + Clustering + Combining

15.1 Objectives

Turn per-peer filtered samples into a single trustworthy system offset via Byzantine-tolerant selection, outlier clustering, and inverse-variance combining.

15.2 Detailed Implementation Steps

Implements P3 of §6 (Byzantine-tolerant selection) and I3 via the Marzullo & Owicki (PODC 1983) intersection algorithm (§8.5 step 2, ADR-09); combining produces the I2 error interval (Spanner/TrueTime, OSDI 2012).

  • ntp/select.rs: build SelectInterval{lo,hi,mid} = [θ−Λ, θ+Λ] per survivor; intersection/Marzullo finds largest overlap clique (≥ majority) → Truechimer set; falsetickers → AssocState::FalseTick (I3).
  • ntp/cluster.rs: compute selection jitter per candidate; iteratively cull worst until ≤NMAX(10), >NMIN(3) or jitter floor.
  • ntp/combine.rs: weighted average (w=1/ψ²) → SystemState.offset/jitter; select sys_peer (min stratum, then min root distance) for refid/stratum.
  • Root distance λ = root_delay/2 + root_dispersion; tie-break.

15.3 Deliverable

Daemon computes a single system offset + jitter + dispersion from many peers, excluding falsetickers; ntpx status shows truechimers, falsetickers, sys_peer.

15.4 Acceptance Criteria

  • §8.16 falseticker scenario: S4 rejected, system offset ≈ +1 ms (not +10.5 ms average).
  • With 1 falseticker among ≥4, never selected (property test, many random configs).
  • Clustering reduces to ≤NMAX survivors.
  • Combined jitter ≤ min peer jitter is NOT required, but ≤ worst survivor jitter holds.

15.5 Conformance Fixtures

conformance/ntp_vectors/marzullo_4src.json (incl. falseticker), .../intersection_edge.json (no majority → no sync), .../cluster_outlier.json, .../combine_weights.json.

15.6 Pitfalls

  • Wrong majority threshold lets 1 liar win (violates P3/§6). - Including peer's own jitter incorrectly in Λ. - Empty intersection ⇒ must declare UNSYNC, not pick arbitrary. - Combining before clustering. - Float NaN from zero jitter weight (clamp ψ_min).

15.7 Performance Concerns

Intersection O(n log n) over interval endpoints; n small (≤64). No alloc — operate on stack arrays. Runs once per combine cycle, not per packet.

15.8 Edge Cases

Even number of sources split 2-2. All falsetickers (network attack). Single source (no Byzantine tolerance — flag low confidence). Identical intervals. Tie in root distance.

15.9 Failure Analysis

Selection accepts falseticker ⇒ clock walks → I2/I3 violation. Detection: differential vs chrony in sim; falseticker injection test (P13). Recovery: demobilize, alarm, holdover.

15.10 Operational Notes

Metrics: truechimers, falsetickers_total, selected_source, sys_jitter_s, sys_root_dispersion_s. Log selection decisions at info. Still measurement-only (no actuation) — last safe phase before disciplining.

16. Phase 4 — Clock Discipline Loop (Hybrid PLL/FLL) + Step/Slew/Panic

16.1 Objectives

Convert system offset into frequency + phase corrections via the hybrid PLL/FLL loop filter; implement step/slew/panic decision. Actuation still against virtual clock (real OS in Phase 5).

16.2 Detailed Implementation Steps

Implements P4 of §6 (servo stability over speed) and the Mills hybrid PLL/FLL (RFC 5905 §11; ADR-07); enforces I4 (freq clamp/no runaway), I9 (negative-feedback sign), and P15 of §6 (deterministic, replayable discipline).

  • discipline/pll_fll.rs: LoopFilter{phase,freq,time_const,mode}; PLL branch freq += x/τ²·wp; FLL branch freq += (Δx/Δt)/(4τ)·wf; combine + clamp ±500 ppm (§8.6, I4).
  • discipline/loop_filter.rs: poll/τ adaptation (grow poll when stable, shrink when jumpy).
  • discipline/step_slew.rs: StepDecision per §8.6 thresholds; first-sample -g allows one big step.
  • Wire combine output → loop filter → ClockAdjust{freq_ppm, offset, op} → ClockBackend (virtual in this phase).

16.3 Deliverable

Against virtual_clock with injected offset/drift, the servo converges; ntpx status shows freq (ppm), offset trending to 0, mode (PLL/FLL).

16.4 Acceptance Criteria

  • Step response: 50 ms offset → within jitter in < 10 poll intervals, no overshoot > 20% (I4).
  • Frequency clamps at ±500 ppm; never runaway.
  • Sign correct: positive offset ⇒ clock slowed (I9).
  • |offset| > 125 ms ⇒ Step; > 1000 s ⇒ Panic (refuse unless -g).
  • Deterministic: same input → same corrections (P15/§6).

16.5 Conformance Fixtures

conformance/servo/step_50ms.json (expected convergence trace), .../drift_100ppm.json, .../panic_2000s.json, .../sign_test.json, .../oscillation_regression.json (gains that must NOT oscillate).

16.6 Pitfalls

  • Positive feedback (sign flip) → runaway (I9). - Too-high gain → oscillation (I4). - Not clamping freq. - τ not tied to poll → instability at long poll. - Stepping when slew suffices (breaks I1). - Integrator windup after large offset.

16.7 Performance Concerns

Loop update is a few f64 ops, < 50 µs, no alloc. Runs once per combine. Avoid transcendental functions in hot path. Determinism: no wall-clock reads inside loop (use sample times).

16.8 Edge Cases

First sample (cold start, freq unknown). Offset exactly at STEP boundary. Sample gap (missed polls) → FLL handles via Δt. Drift file says X but reality Y (warm-start mismatch). NaN guard on zero Δt.

16.9 Failure Analysis

Runaway servo (I4) → freq pegs at ±500 ppm, offset diverges. Detection: freq_clamp_total, slope alarm. Recovery: reset FLL/integrator, holdover, re-converge. Forensics: servo trace log.

16.10 Operational Notes

Metrics: freq_ppm, offset_s, servo_mode, freq_clamp_total, step_total, panic_total. Runbook servo-oscillation.md. Tunables in ntpx.toml (gains, minpoll/maxpoll). Still virtual clock — no OS impact.

24. Phase 12 — PTP Servo (PI) + Holdover Controller + Combined NTP/PTP Selection

24.1 Objectives

Discipline the clock from PTP offsetFromMaster via a PI servo; implement holdover (honest error growth) when sources lost; unify NTP + PTP into one source-selection pipeline.

24.2 Detailed Implementation Steps

  • discipline/pi_servo.rs: Servo{kp,ki,integrator}; freq = kp·offset + ki·∫offset; anti-windup clamp; ServoState Unlocked→Locked→Holdover.

  • Combined selection: present NTP truechimers + PTP offset as unified candidates to ntp/select; choose best by root distance / PTP clockClass; single disciplinarian (I12).

24.3 Deliverable

ntpx disciplines the clock from PTP (< 100 µs SW); on source loss enters holdover with growing reported error; can prefer PTP over NTP when better.

24.4 Acceptance Criteria

  • PTP slave: |offsetFromMaster| < 100 µs steady-state (kernel ts, LAN).
  • PI servo stable (no oscillation, I4); settle < 10 s.
  • Holdover: freq held, max_error grows linearly at drift rate (I9 of §6/honest growth); clockClass degrades.
  • Combined: with both NTP+PTP, picks lower-error source; only one disciplines clock (I12/I13).
  • Recovery from holdover re-converges without step (I1).

24.5 Conformance Fixtures

24.8 Edge Cases

24.9 Failure Analysis

Performance Engineering

  • Timestamp capture latency: budget < 10 µs SW, < 1 µs kernel (M1); measure RX cmsg→sample. Pin RX thread; isolate NIC IRQs (irqaffinity); consider busy-poll (SO_BUSY_POLL) for PTP.
  • Syscall overhead: clock_adjtime ~1 µs, once/loop (not per packet), inside the < 50 µs sample-to-actuation budget (M9); recvmmsg/sendmmsg batch to amortize; count syscalls/sec.
  • Jitter minimization (servo): pin time-critical thread to an isolated core (isolcpus/cset); no allocation in hot loop (preallocated arenas); no locks (SPSC channel, seqlock for now()); no GC (Rust); avoid syscalls between sample and correction.
  • Allocation: zero per-packet heap; fixed [Option<NtpAssoc>;MAX_ASSOC], response template reuse, bounded ForeignMaster vec.
  • Cache locality: assoc arena contiguous; hot fields packed; avoid pointer chasing in filter/select.
  • Branch prediction: sanity checks ordered common-case-first; parse is straight-line.
  • Tail latency: histogram of capture→correction; p99 < 50 µs (M9); flamegraph (perf/cargo-flamegraph) on hot path.
  • Server throughput: stateless response path; target 10k req/s/core (M6); criterion + load test (scripts); measure response_bytes_total.
  • Profiling methodology: perf record for CPU, perf c2c for false sharing, heaptrack/dhat to confirm no hot-path alloc, criterion for micro, offset/jitter histograms for end-to-end.
  • Memory profiling: confirm < 16 MB RSS (M7); track arena sizes; no leak (ASAN/valgrind in CI).
  • Client CPU budget: ≤ 1% of one core at 8 sources, poll 64 s (M5); PTP servo load bounded by logSyncInterval (M10) × per-update cost (M9) — see Capacity Model C12.

Scalability Analysis

  • Client sources: O(n) over associations; n ≤ 64 typical; selection O(n log n) negligible. Ceiling: useful sources limited by diversity, not CPU.
  • Server clients/sec: stateless ⇒ scales with NIC + cores; rate-limit table bounded (fixed buckets, LRU eviction). Bottleneck = packet I/O, not state. Horizontal scale: anycast / many stateless servers (Meta ptp4u model).
  • PTP domains: per-domain isolation; multiple domains = parallel state machines; bounded foreign-master lists. BC fan-out = number of downstream ports.
  • Network fanout (broadcast/multicast): one send to many; scales well but spoofable (auth needed).
  • Fundamental ceilings: (1) timestamp accuracy — SW ~10 µs, kernel ~1 µs, HW ~ns (deferred); cannot beat the capture floor. (2) network PDV — packet sync bounded by path delay variance; physical-layer sync (DTP/White Rabbit) needed below that. (3) path asymmetry — undetectable bias; absolute accuracy floor without calibration/HW.
  • Coordination overhead: none (no cross-node consensus); each clock independent. BMCA is local per domain.
  • Storage growth: trivial (drift file + leap table, bytes). No metadata scaling.
  • Scheduler saturation: single time thread handles thousands of samples/sec easily; I/O thread batches. Risk only at extreme PTP rates (128 Sync/s × many ports) — shard ports across threads if needed (PhaseDeferred).
  • Vertical scaling: more cores help server I/O + multi-domain PTP; time-critical loop is single-core by design (determinism).

Mental Models & First Principles

The compressed intuitions an expert holds about clock synchronization. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it. Every cited § resolves.

  • MM1 — Time sync produces a bounded interval, never a point. The deliverable is [earliest, latest] (true time lies inside with high confidence), not a scalar "the time". The width is the error budget Λ = E + Δ/2; a point estimate is just the interval's midpoint with its uncertainty thrown away. Predicts: a consumer that treats the clock as exact (consensus lease, commit-wait, MVCC) will violate its safety property exactly when the interval is wide and it assumed it was narrow. Bug without it: reporting offset with no max_error, so callers assume false precision and ordering guarantees silently collapse. Applied: §8.4 (Λ), I2, P2 of §6, Phase 12; this is the Spanner/TrueTime insight (§Comparative Architecture).
  • MM2 — Sync is a feedback control loop, and the oscillator is the plant. Offset is the phase error, frequency is the integral term, and the loop filter is a controller disciplining a physical (drifting, noisy) oscillator — the same math as a PLL in an RF receiver. Predicts: gains too high → the loop amplifies measurement noise (PDV) into the clock and oscillates; gains too low → it never catches a drift. Bug without it: tuning the servo by trial-and-error rather than damping/time-constant, getting a clock that hops. Applied: §8.6, P4 of §6, I4/I9, Phase 4 & Phase 12.
  • MM3 — A single source is never trustworthy; truth is the majority intersection. One server — even one that lies consistently and internally-consistently — must never move your clock. Correctness comes from overlapping confidence intervals (Marzullo), not averaging. Predicts: a naive mean of N sources is walked by one distant liar in proportion to its distance; an intersection rejects it outright. Bug without it: trusting one NTP server, or averaging, so a compromised/misconfigured source walks the fleet. Applied: §8.5/§8.16, P3 of §6, I3, Phase 3.
  • MM4 — Offset and delay are computed from four timestamps under one load-bearing assumption: path symmetry. θ = ((T2−T1)+(T3−T4))/2 and δ = (T4−T1)−(T3−T2) are exact algebra, but θ's correctness rests entirely on the forward and reverse path delays being equal. Predicts: any asymmetry (routing, queueing, a deliberate one-way delay) injects a constant offset bias of half the asymmetry that no algorithm can detect from the timestamps alone. Bug without it: trusting a sub-ms offset over an asymmetric WAN/satellite path, or missing the delay-asymmetry attack. Applied: §8.4/§8.9, T5, Phase 1 & Phase 10, §Scalability Analysis (asymmetry floor).
  • MM5 — A min/min-delay filter extracts signal because queueing only ever adds delay. The sample with the smallest round-trip delay suffered the least queueing, so its offset is the least corrupted — the truth is at the extreme, not the average. RTprop and BtlBw analogues: the minimum delay and the cleanest offset. Predicts: averaging the 8 filter samples is worse than picking the min-delay one; a window that never expires sticks to a stale minimum after a route change. Bug without it: smoothing the filter window and degrading accuracy, or never re-learning after a path change. Applied: §8.5 step 1, I12, Phase 2, ADR-10.
  • MM6 — Slewing preserves monotonicity; stepping breaks it — so the default must be slew. Apps assume gettimeofday never goes backward (log ordering, DB MVCC, TLS validity, TOTP). A frequency nudge (slew) keeps time monotonic; a step can move it backward. Predicts: a system that steps on every correction produces duplicate timestamps, "certificate not yet valid" errors, and MVCC corruption; the worst case is a leap second naively stepped backward. Bug without it: calling settimeofday to "fix" offset, breaking every monotonic consumer. Applied: §8.6, P1 of §6, I1, Phase 5 & Phase 7; the Cloudflare 2017 leap bug (§Failure Modes) is the canonical violation.
  • MM7 — Every received packet is hostile until proven otherwise, and the loop's inputs are the attack surface. NTP is spoofable UDP; a forged reply, a replayed packet, or a length-field lie drives the control loop or the parser. Predicts: trusting pkt.org without checking it echoes your last transmit lets an off-path attacker inject offset; allocating from an attacker's length field is a DoS; a non-constant-time MAC compare is a timing oracle. Bug without it: the entire ntpd CVE class (mode-7 monlist amplification CVE-2013-5211; parser overflows). Applied: §8.17, P7/P8 of §6, I10/I11/I15, Phase 1/6/8, §Threat Model.
  • MM8 — Estimator and controller are different machines; keep measurement pure and actuation isolated. Filter→select→combine is a pure function of samples (no side effects); discipline→actuate is the only thing that touches the clock. Predicts: tangle them and you cannot test the estimator without a real clock, cannot replay a servo bug deterministically, and risk two code paths fighting over CLOCK_REALTIME. Bug without it: an untestable feedback loop and dueling disciplinarians (ntpd + systemd-timesyncd). Applied: P11/P12 of §6, I13, §3 (architecture), Phase 5 (virtual vs sys clock), §11.4 (ClockBackend).
  • MM9 — Wire time is exact fixed-point; float belongs only inside the controller. NTP 32.32 and PTP 48.32 represent sub-ns exactly; IEEE-754 f64 cannot represent the NTP fraction exactly once the seconds field is large (~µs error near 2^32 s). Predicts: serialize an f64 timestamp and you bias every offset by a sub-µs-to-µs amount that grows with the epoch; do servo math in fixed-point and you lose nothing but reproducibility risk. Bug without it: silent precision loss that looks like a stable but wrong offset. Applied: P13 of §6, I14, §8.3, ADR-04/05, Phase 0.
  • MM10 — When you lose your sources, your clock keeps running but your honesty is the deliverable. Holdover means extrapolating from the last frequency estimate while growing max_error at the worst-case drift rate — the time is no longer trustworthy at the old bound and the interval must say so. Predicts: a holdover that keeps reporting the pre-loss error bound presents drift as accuracy and a consumer trusts a clock that is silently wrong; an honest one widens the interval until a consumer can refuse it. Bug without it: false confidence after source loss (the most dangerous failure — confident wrongness). Applied: P9/P14 of §6, I2, Phase 12 (holdover/controller), §Failure Modes (holdover drift).

  • ntpd (NTP.org reference implementation) made the choice to be the protocol — it is the executable definition of RFC 5905's mitigation pipeline and discipline loop, and every other NTP implementation is judged against it. It wins as the correctness reference and on breadth of legacy features (broadcast, symmetric, refclocks, Autokey). Its documented cost is a large C attack surface (CVE-2013-5211 mode-7 amplification) and slower convergence than regression-based designs — the reasons NTPsec forked it and chrony exists. ntpx keeps its pipeline (§8.5) but rejects its unsafe-C parsing (ADR-01/17) and abuse vectors (P8 of §6).
  • chrony (chronyd) changed one thing decisively: replace the fixed 8-sample min-delay filter with linear regression over a longer source history (sourcestats.c), estimating frequency directly. That wins on jittery WAN paths and on machines that are intermittently connected or frequently suspended (laptops, VMs), converging far faster — which is why it is the default on RHEL/Fedora. Its cost is more statistics to get right. ntpx offers this as ADR-10's rejected-but-regime-bounded alternative and uses chrony as a §13 differential baseline.
  • linuxptp (ptp4l / phc2sys) is the PTP counterpart: it commits fully to IEEE 1588 with a PI servo and hardware (PHC) timestamping, reaching sub-µs to ns accuracy that NTP cannot. It wins in telecom 5G fronthaul, exchange colocation, and power-grid synchrophasors where the LAN is engineered and HW timestamping is available. Its cost is profile-configuration sprawl and hard hardware dependence. ntpx implements the same PTP semantics (§8.7–§8.12) in software/kernel-timestamp form, with HW timestamping PhaseDeferred §Phase 13.
  • Google TrueTime / Spanner (Corbett et al., OSDI 2012) made the radical choice that the time API returns an interval, TT.now() → [earliest, latest], backed by GPS and atomic clocks in every datacenter; Spanner's external consistency is achieved by commit-wait — blocking until the interval no longer overlaps a transaction's timestamp. It wins where a database needs globally-consistent ordering and can afford a few ms of commit-wait. Its cost is special hardware (GPS/atomic clocks per DC). ntpx builds the same uncertainty accounting (I2, MM1) in software so any consumer can have a bounded interval without that hardware.
  • Roughtime (Google, then Cloudflare) rejected high precision in favour of cryptographic authenticity: an Ed25519-signed response giving time to within ~a second, with a chained-proof protocol that lets a client prove a server lied. It wins for bootstrapping trust (e.g. validating TLS certificate dates on a device with no trusted clock) where authenticated coarse time beats precise unauthenticated time. Its cost is ~1 s precision — useless for finance/telecom. ntpx instead authenticates precise time via NTS (RFC 8915, Phase 8); Roughtime is the alternative for the bootstrap-trust regime (cf. T15 bootstrap, §Threat Model).

Back-of-Envelope Capacity Model

Numbers an expert computes from §4 (System Constraints) before designing. Each is derived step-by-step; the §4 input is named and the formula shown.

  • C1 — Offset error from timestamp-capture jitter. Input: §4 "Timestamp capture jitter < 10 µs SW, < 1 µs kernel" (M1). Capture jitter enters θ as ±jitter/2 per timestamp on both T2 and T4. With SW capture at 10 µs: θ_error ≈ jitter ≈ 10 µs, dominating the < 1 ms LAN budget by 100×-headroom but setting the floor — you cannot beat ~10 µs with SW stamps, the exact reason kernel (1 µs) and HW (ns, deferred) stamping exist. Confirms §4's tiered accuracy targets.
  • C2 — Asymmetry-induced offset bias. Input: §4 WAN RTT < 250 ms + MM4. A path-delay asymmetry of Δ_asym injects a constant bias = Δ_asym / 2. For a satellite/asymmetric WAN with 10 ms forward/reverse difference: bias = 10 ms / 2 = 5 ms — undetectable from timestamps, and exactly the §4 "WAN < 10 ms" target's limiting term. This is why PTP targets engineered-symmetric LANs (C1 floor) and NTP WAN accuracy is ms-class.
  • C3 — Servo slew-out time for a sub-step offset. Input: §4 "Frequency tolerance ±500 ppm" (M2) + "Step threshold 125 ms" (M3). Slewing at the 500 ppm cap, draining offset o: t = o / 500e-6. For the maximum slew-eligible offset (just under 125 ms): t = 0.125 / 5e-4 = 250 s to slew out. Confirms §8.6's "125 ms takes ≥ 250 s to slew" and bounds how slow convergence can be before a step is justified.
  • C4 — Holdover error growth rate. Input: §4 "Holdover drift budget < 1 ppm" (M4) + I2/MM10. Error grows at the residual frequency error: error(t) = freq_err × t. At 1 ppm residual: 1e-6 × t → 3.6 ms after 1 h, 86 ms after 1 day, 2.6 s after 30 days. This is the curve holdover/controller must report honestly (P9 of §6); it tells an operator a 1-day holdover blows a 1 ms SLO ~24× over and a 100 µs PTP SLO ~36× over.
  • C5 — Client steady-state CPU / packet rate. Input: §4 "CPU < 1% of one core, 8 sources, poll 64 s" (M5). At poll 64 s, 8 sources: 8 / 64 = 0.125 packets/s RX+TX. Per-packet work (parse + filter + maybe select/combine) at, say, ≤ 10 µs: 0.125 × 2 × 10 µs ≈ 2.5 µs/s of CPU = ~0.00025% — three orders under the 1% ceiling, confirming the client is I/O-trivial and the budget exists for crypto (NTS AEAD, §8).
  • C6 — Server throughput vs per-request cost. Input: §4 "scale to 10k req/s/core" (M6). Budget per request = 1 s / 10,000 = 100 µs/core. A stateless mode-4 response (precomputed template, echo origin, stamp T2/T3, sendmmsg) is ~1–5 µs of CPU, so 100 µs leaves the path I/O-bound, not CPU-bound — confirming §Scalability's "bottleneck = packet I/O" and that recvmmsg/sendmmsg batching (ADR-03) is the lever, matching Meta's stateless ptp4u model.
  • C7 — Daemon memory at max associations. Input: §4 "Memory < 16 MB RSS" (M7) "; ≥ 64 NTP assoc; ≥ 16 PTP foreign masters" (M8) + §11.3. Per NtpAssoc ≈ filter (8 × FilterSample ~48 B = 384 B) + state ~128 B ≈ 512 B. 64 × 512 B = 32 KiB for all associations; 16 × sizeof(ForeignMaster) adds a few KiB. Association state is < 0.5% of the 16 MB ceiling — the budget is dominated by buffers/runtime, confirming the fixed arena (§11.3) is cheap and "no per-packet heap alloc" is the real constraint, not arena size.
  • C8 — RX socket buffer for a server burst. Input: §4 "10k req/s/core" (M6) + a worst-case scheduling gap. If the time/IO thread is delayed g = 10 ms, inbound packets buffer: 10,000 req/s × 0.010 s × ~90 B/packet ≈ 9 KB. A default 212 KB SO_RCVBUF absorbs ~23× that, so a 10 ms stall costs zero dropped requests — but a 250 ms stall (225 KB) would overflow it, quantifying why the IO thread must not block (ADR-02/03) and why recvmmsg drains in batches.
  • C9 — NTP era lifetime and rollover horizon. Input: §4 "NTP timestamp resolution: 64-bit 32.32 since 1900-01-01" (32-bit seconds field) + §8.3 "seconds field wraps every 2^32 s". 2^32 s = 4,294,967,296 s ÷ 31,556,952 s/yr ≈ 136.1 years. Era 0 (from 1900) ends 1900 + 136 = 2036 (precisely 2036-02-07). With the explicit era: i8 (§11.1), range = 256 × 136 ≈ 34,800 years of representable eras — confirming I6's "> 8 billion years" claim is actually bounded by the i8 era count, and that 2036 is the first real rollover an implementation must test (Phase 0/7).
  • C10 — Leap-smear frequency offset. Input: §4 "Frequency tolerance ±500 ppm" (M2, the ceiling this must respect) + §8.15 "spread −1 s over a window" + I1. Smearing 1 s over a window W: freq_offset = 1 s / W. Over a ±1000 s (≈ 33 min total) window: 1 / 2000 = 500e-6 = 500 ppm — at the §4 frequency-tolerance ceiling (M2). Over Google's documented ~24 h smear: 1 / 86400 ≈ 11.6 ppm, comfortably small. This derives §8.15's "~11.6 ppm" figure and shows why a narrow smear window is dangerous (hits the M2 clamp) while a day-long one is gentle.
  • C11 — Filter staleness horizon (MAXDISP). Input: §4 "Poll interval (NTP) 2^4..2^17 s" (bounds how fast a fresh sample re-arrives) + §8.5 "discard if ε > MAXDISP 16 s" + §8.4 "φ = 15 ppm" dispersion growth. A sample's dispersion reaches MAXDISP after t = MAXDISP / φ = 16 / 15e-6 ≈ 1.07e6 s ≈ 12.3 days. So a single sample is theoretically usable for ~12 days of source outage before age alone disqualifies it — but C4's holdover error (86 ms/day at 1 ppm) makes it useless for accuracy long before that, confirming holdover, not stale filter samples, is the real outage mechanism.
  • C12 — PTP Sync-rate servo load. Input: §4 "logSyncInterval −7..+4 (1/128 s .. 16 s)" (M10) + §4 "Servo update latency < 50 µs" (M9). At the fastest rate (128 Sync/s): 128 × 50 µs = 6.4 ms/s of servo CPU = 0.64% of one core for the discipline path alone, plus message handling. Confirms a single time thread sustains max PTP rate on one core (§Scalability) with headroom, and that sharding ports across threads is only needed at many high-rate ports (deferred).

Alternative Architectures

Fundamentally different ways to synchronize clocks for the same goal. Each: ASCII sketch, the regime where it wins, the real system that embodies it, why this blueprint rejected it.

A1 — Hardware-reference time (GPS/atomic clock per node, no network sync loop). Each node (or each datacenter) carries a GPS receiver and/or atomic clock; the "sync" is local disciplining to a physical reference, and the network carries only an authenticated bound, not the time itself.

   [GPS antenna]──┐        [GPS antenna]──┐
                  ▼                        ▼
   ┌── node A: local atomic/GPS ──┐  ┌── node B: local atomic/GPS ──┐
   │  disciplines its own clock   │  │  disciplines its own clock   │
   └──────────────┬───────────────┘  └──────────────┬──────────────┘
                  └──── exchange only [earliest,latest] bounds ──────┘
  • Wins: when sub-µs absolute accuracy with a tight, trustworthy uncertainty bound is required fleet-wide and the operator can afford GPS/atomic hardware in every datacenter — network PDV and path asymmetry (MM4) are removed from the accuracy path entirely.
  • Real system: Google TrueTime / Spanner (Corbett et al., OSDI 2012) puts GPS + atomic clocks in every datacenter and exposes TT.now()→[earliest,latest]; Amazon's Time Sync Service / ClockBound is a comparable bounded-interval offering.
  • Rejected because: this blueprint's scope is explicitly software sync over commodity networks with no special hardware (§1 non-goals: "NOT a GPS/PPS reference-clock driver", "NOT a full Stratum-1 appliance"). ntpx builds the same uncertainty accounting (I2, MM1) but obtains time over the network; GPS/PPS refclock is PhaseDeferred §Phase 12.

A2 — Physical-layer / in-network synchronization (sync rides the link, not packets). Time is distributed at the physical or switch layer — every switch is timing-aware and corrects residence time in hardware, or the clock is recovered from the link's bit stream — so accuracy is bounded by hardware, not packet-delay variation.

   GM ──PHY sync──▶ [switch: HW timestamp + correctionField] ──PHY──▶ [switch] ──▶ slave
        (every hop is timing-aware; residence time removed in hardware)
  • Wins: when sub-nanosecond accuracy is required and the entire path can be specialized hardware — particle-physics timing, telecom 5G fronthaul, power-grid synchrophasors — where even kernel timestamping's µs floor (C1) is far too coarse.
  • Real system: White Rabbit (CERN) achieves sub-ns over Ethernet by combining PTP with Synchronous Ethernet and phase measurement; PTP transparent clocks (IEEE 1588) and DTP (Lee et al., SIGCOMM 2016, physical-layer sync) embody the in-network approach.
  • Rejected because: it requires timing-aware hardware on every hop — out of scope for a commodity-network daemon (§1 non-goals: "NOT a hardware NIC PHC driver", transparent clock PhaseDeferred). ntpx targets the SW/kernel-timestamp regime (ADR-06) and treats the HW/PHY floor as the documented ceiling (§Scalability Analysis).

A3 — Probe-flooding statistical estimation (many coded probes + regression/ML, not a filter pipeline). Instead of an 8-sample filter and Marzullo, blanket the network with a high rate of timestamped probes and recover offset/skew with regression or a learned model that exploits correlations across many probes and paths.

   sender ──▶▶▶▶▶▶ (burst of coded probe packets) ▶▶▶▶▶▶──▶ receiver
                       │  regression / SVM over the whole probe cloud │
                       ▼                                              ▼
                  estimate offset+skew jointly, reject PDV statistically
  • Wins: at datacenter scale with fine-grained sync requirements and spare bandwidth — exploiting the law of large numbers over thousands of probes drives the offset estimate below what a small min-delay filter achieves on a jittery path.
  • Real system: Huygens (Geng et al., NSDI 2018) uses coded probes + SVM to reach tens-of-ns sync in software; chrony's linear-regression estimator (sourcestats.c) is the lightweight, deployed cousin of the same statistical idea.
  • Rejected because: it trades bandwidth and a heavier estimator for accuracy this blueprint obtains more simply, and the probe flood is unfriendly to the WAN/general-Internet regime ntpx must serve (P8 of §6 anti-abuse). The regression variant is captured as ADR-10's regime-bounded alternative; the full probe-cloud approach is a different system class (Sundial/Huygens, §5 Papers).

Glossary

Term Definition
NTP Network Time Protocol; UDP/123 packet-based sync with mitigation + discipline (RFC 5905)
SNTP Simple NTP; stateless single-exchange subset (RFC 4330)
PTP Precision Time Protocol; IEEE 1588 sub-µs LAN sync
IEEE 1588 The PTP standard (2008, 2019 editions)
Stratum Distance from reference clock; 1=primary, 2..15 secondary, 16=unsynchronized
Offset (θ) Estimated correction local→reference = ((T2−T1)+(T3−T4))/2
Delay (δ) Round-trip delay = (T4−T1)−(T3−T2)
Dispersion (ε) Accumulated error from precision + drift + age
Jitter (ψ) RMS variation of offset samples
Root delay/dispersion Total delay/dispersion to the reference clock (propagated in header)
Max error (Λ) Bound on true offset: E + Δ/2; defines [earliest, latest]
Clock filter 8-sample shift register picking min-delay sample (NTP)
Marzullo Algorithm for the intersection of confidence intervals; Byzantine-tolerant
Truechimer A source whose interval is in the agreeing majority (accepted)
Falseticker A source outside the majority intersection (rejected)
Intersection algorithm Selection step finding the largest overlapping clique of intervals
Clustering Culling statistical outliers among truechimers by jitter
Combining Inverse-variance weighted average of survivors → system offset
PLL Phase-Locked Loop; tracks phase error
FLL Frequency-Locked Loop; tracks rate of change of offset
Loop filter The control filter converting offset → frequency/phase correction
PI servo Proportional-Integral controller (PTP discipline)
Step / slew Step = jump clock; slew = gradual frequency nudge
Panic threshold 1000 s; offset beyond ⇒ refuse + alarm
STEP threshold 125 ms; offset beyond ⇒ step instead of slew
Poll interval Time between requests; NTP 2^4..2^17 s
Reachability 8-bit register of recent successful polls
KoD Kiss-o'-Death; server rate-control/deny packet (stratum 0 + code)
RefID Reference identifier (refclock code or server IP/hash)
Leap second ±1 s UTC adjustment at 23:59:60 to track Earth rotation
Smearing Spreading a leap second over a window to preserve monotonicity
TAI / UTC International Atomic Time (no leaps) vs Coordinated Universal Time (with leaps)
Era NTP 136-year epoch (seconds-field wrap), 2036 boundary
BMCA Best Master Clock Algorithm; PTP master election
Grandmaster (GM) BMCA-elected root clock of a PTP domain
Ordinary clock (OC) Single-port PTP clock (master or slave)
Boundary clock (BC) Multi-port PTP clock isolating domains; slave up, master down
Transparent clock (TC) Forwards PTP updating correctionField with residence time
One-step / two-step t1 in Sync (one-step) vs in Follow_Up (two-step)
correctionField PTP Q48.16 ns accumulating residence + asymmetry corrections
meanPathDelay ((t2−t1)+(t4−t3))/2; assumes symmetric path
offsetFromMaster ((t2−t1)−(t4−t3))/2; slave's correction
Peer delay P2P per-link delay measurement (Pdelay mechanism)
Holdover Free-running on last frequency when sources lost; error grows
Allan variance / ADEV Stability metric of a clock vs averaging time τ
NTS Network Time Security; TLS-derived AEAD auth for NTP (RFC 8915)
NTS-KE NTS Key Establishment (TLS handshake → cookies + keys)
SO_TIMESTAMPING Kernel socket option capturing RX/TX timestamps
PHC PTP Hardware Clock (NIC clock); HW timestamping source (deferred)
Truetime Google's bounded-uncertainty time API ([earliest, latest])
