⬜ Phase 0 — Repo Skeleton + Fixed-Point Timestamps + Time-Scale Arithmetic + UDP Scaffolding §12

Objectives

Establish workspace, exact fixed-point timestamp types (NTP 32.32, PTP 48.32), time-scale conversions (UTC/TAI/Monotonic), era handling, and UDP socket scaffolding. Foundation all later phases depend on. No discipline yet.

Deliverable

cargo build produces ntpx; ntpx version prints build/version; timestamp library with round-trip POSIX↔NTP↔PTP; UDP echo loopback test.

Acceptance
  • Round-trip posix→ntp→posix exact to nanosecond for 1970..2200.
  • Era-aware sub_signed correct across 2036 boundary (unit-tested both eras).
  • NtpShort encodes/decodes RootDelay 0..65535.99998 s exact.
  • UDP loopback RTT measured; clippy + fmt clean; CI green.
Fixtures

fixtures/ts/posix_ntp_pairs.csv (known pairs incl. 2036 era boundary, 2038), fixtures/ts/short_format.csv, fixtures/ts/malformed_ntp_64.bin (era-wrap edge). Expected: exact equality; malformed → defined wrap, no panic.

Pitfalls
  • f64 used for storage instead of fixed-point → precision loss (forbidden by I14). - Forgetting era ⇒ time wrong by 136 yr after 2036. - Sign error in epoch shift. - recvmmsg partial-batch handling. - Nanos field ≥ 1e9 not normalized in PTP ts.

⬜ Phase 1 — NTP Packet Parse/Serialize + Sanity Checks + SNTP One-Shot Client §13

Objectives

Full NTPv4 packet codec (all header fields, extension fields), strict sanity validation, and a stateless SNTP client computing θ and δ from a single exchange.

Deliverable

ntpx query pool.ntp.org prints offset, delay, stratum, refid, root delay/disp, computed max error. Works against real servers (chrony/ntpd).

Acceptance
  • Decodes RFC 5905 reference packet exactly (all fields match fixture).
  • θ, δ match §8.13 worked example to 2^-32 s.
  • Rejects every §8.17 malformed case without panic; correct WireError/SanityReason.
  • Interop: offset vs sntp/chronyc within 1 ms on same network.
Fixtures

conformance/ntp_vectors/server_reply.bin (+ expected fields), .../worked_8_13.json (θ,δ), .../ext_field_nts.bin, malformed set: mode7.bin, short.bin, extlen_overrun.bin, stratum16.bin, leap_alarm.bin, neg_delay.bin.

Pitfalls
  • Treating origin/xmit endianness wrong. - T4 captured too late (after parse) inflating δ — capture at recv. - Off-by-one ext-field padding. - Accepting stratum 0 non-KoD. - Mixing seconds/fraction in θ math. - Not masking PTP-style nanos here (N/A but watch ts width).

⬜ Phase 2 — NTP Association + Poll Scheduler + Reachability + Clock Filter §14

Objectives

Stateful per-peer associations: poll scheduling (2^4..2^17 s), 8-bit reachability, and the 8-sample clock filter (min-delay selection, jitter, dispersion aging).

Deliverable

Daemon maintains N associations, polls on schedule, fills filters; ntpx status shows per-peer offset/delay/jitter/disp/reach/poll. No discipline yet (observe only).

Acceptance
  • Origin-echo mismatch ⇒ pkt_bogus_total++, sample dropped (I10 test).
  • Filter selects min-delay sample (unit test with crafted window).
  • Jitter computed = RMS reference (±1e-9 s).
  • reach register transitions correct over simulated loss pattern.
  • Poll backoff on KoD RATE observed.
Fixtures

conformance/ntp_vectors/filter_window_8.json (8 samples → expected pick+jitter), .../reach_pattern.json, .../bogus_origin.bin, .../kod_rate.bin. Replay: .../assoc_trace.pcap deterministic.

Pitfalls
  • Not aging dispersion ⇒ stale samples look fresh (I12). - Accepting reply whose origin≠last xmt (spoof). - iburst flooding a server (respect minpoll). - Reusing xmt across peers. - Filter index wraparound bug. - Treating jitter as offset.

⬜ Phase 3 — Source Selection (Intersection/Marzullo) + Clustering + Combining §15

Objectives

Turn per-peer filtered samples into a single trustworthy system offset via Byzantine-tolerant selection, outlier clustering, and inverse-variance combining.

Deliverable

Daemon computes a single system offset + jitter + dispersion from many peers, excluding falsetickers; ntpx status shows truechimers, falsetickers, sys_peer.

Acceptance
  • §8.16 falseticker scenario: S4 rejected, system offset ≈ +1 ms (not +10.5 ms average).
  • With 1 falseticker among ≥4, never selected (property test, many random configs).
  • Clustering reduces to ≤NMAX survivors.
  • Combined jitter ≤ min peer jitter is NOT required, but ≤ worst survivor jitter holds.
Fixtures

conformance/ntp_vectors/marzullo_4src.json (incl. falseticker), .../intersection_edge.json (no majority → no sync), .../cluster_outlier.json, .../combine_weights.json.

Pitfalls
  • Wrong majority threshold lets 1 liar win (violates P3/§6). - Including peer's own jitter incorrectly in Λ. - Empty intersection ⇒ must declare UNSYNC, not pick arbitrary. - Combining before clustering. - Float NaN from zero jitter weight (clamp ψ_min).

⬜ Phase 4 — Clock Discipline Loop (Hybrid PLL/FLL) + Step/Slew/Panic §16

Objectives

Convert system offset into frequency + phase corrections via the hybrid PLL/FLL loop filter; implement step/slew/panic decision. Actuation still against virtual clock (real OS in Phase 5).

Deliverable

Against virtual_clock with injected offset/drift, the servo converges; ntpx status shows freq (ppm), offset trending to 0, mode (PLL/FLL).

Acceptance
  • Step response: 50 ms offset → within jitter in < 10 poll intervals, no overshoot > 20% (I4).
  • Frequency clamps at ±500 ppm; never runaway.
  • Sign correct: positive offset ⇒ clock slowed (I9).
  • |offset| > 125 ms ⇒ Step; > 1000 s ⇒ Panic (refuse unless -g).
  • Deterministic: same input → same corrections (P15/§6).
Fixtures

conformance/servo/step_50ms.json (expected convergence trace), .../drift_100ppm.json, .../panic_2000s.json, .../sign_test.json, .../oscillation_regression.json (gains that must NOT oscillate).

Pitfalls
  • Positive feedback (sign flip) → runaway (I9). - Too-high gain → oscillation (I4). - Not clamping freq. - τ not tied to poll → instability at long poll. - Stepping when slew suffices (breaks I1). - Integrator windup after large offset.

⬜ Phase 5 — OS Clock Actuation (clock_adjtime) + Drift File + Virtual-Clock Backend §17

Objectives

Discipline the real OS clock via clock_adjtime/ntp_adjtime; persist frequency in a drift file; finalize the ClockBackend trait with both sys_clock and virtual_clock.

Deliverable

ntpx disciplines CLOCK_REALTIME on a real host; offset converges; drift file persists; reboot warm-starts frequency.

Acceptance
  • On real host, |offset| < 1 ms (LAN) within 5 min from cold start (§4 target).
  • Step only when |offset| ≥ 125 ms; slew otherwise (I1).
  • Foreign disciplinarian (systemd-timesyncd active) detected → refuse to start (I13).
  • Drift file survives restart; warm-start convergence < 1 min.
  • clock_adjtime errors surfaced, not panicked.
Fixtures

conformance/clock/drift_file_v1.txt, .../adjtimex_ops.json (op→flag mapping), .../warm_start.json. Virtual-vs-sys differential: scripts/diff_chrony.sh baseline.

Pitfalls
  • Calling settimeofday instead of slewing (jumps clock). - Not setting STA_PLL/mode flags ⇒ kernel ignores adjustments. - Fighting systemd-timesyncd/ntpd (I13). - Drift file race on concurrent write. - ppm sign convention (kernel freq is scaled). - Forgetting CAP_SYS_TIME.

⬜ Phase 6 — NTP Server Mode + Broadcast/Symmetric + KoD + Rate Limiting §18

Objectives

Serve NTP to clients (mode 4 responses), support broadcast (mode 5) and symmetric (mode 1/2) peers, propagate refid/stratum, and prevent abuse via KoD + rate limiting.

Deliverable

ntpx answers ntpdate/chronyc/sntp; stratum propagates; rate-limited clients get KoD; no mode 7 response.

Acceptance
  • External client syncs to our server within target accuracy.
  • Stratum = upstream sys_peer stratum + 1; refid correct.
  • Flood → KoD RATE after threshold; response never larger than request (I11).
  • Mode 7 request → no reply, amplification_blocked_total++.
  • Symmetric peer reaches SYNC; broadcast clients receive.
Fixtures

conformance/ntp_vectors/server_response.json, .../kod_rate_trigger.json, .../mode7_drop.json, .../symmetric_peer.pcap, .../broadcast.pcap.

Pitfalls
  • Reflecting amplification (mode 7/monlist) — never (CVE-2013-5211). - Serving while UNSYNC (must set LI=alarm/stratum 16). - Origin echo wrong → clients reject. - Rate-limit too aggressive (legit clients KoD'd). - Leaking internal refid. - Broadcast without auth (spoofable).

⬜ Phase 7 — Leap-Second Handling + Era Rollover §19

Objectives

Correctly handle leap-second insertion/deletion at the precise instant (exactly once), with optional smearing, plus NTP era rollover robustness.

Deliverable

Simulated leap second applied once at the right instant; monotonic under smear; era boundary crossing handled. ntpx status shows leap armed/applied.

Acceptance
  • Leap insertion applied exactly once (I8); TAI offset 36→37.
  • Smear: no backward step (I1); clock monotonic across event.
  • LI bits set on leap day, cleared after.
  • Era 2036 boundary: time correct ± resolution (I6 fixture).
  • Deletion scenario handled symmetrically.
Fixtures

conformance/leap/insert_2016.json (instant + expected), .../delete.json, .../smear_window.json (monotonic check), .../era_2036.json, .../double_apply_guard.json.

Pitfalls
  • Applying leap twice (no once-flag) → off by 1 s. - Applying at wrong instant (local vs UTC). - Smear + step both → 2 s error. - Trusting a single source's LI (could be spoofed leap). - Not clearing leap flag after. - Era off-by-one near 2036.

⬜ Phase 8 — NTS Security (RFC 8915) + Symmetric-Key Auth §20

Objectives

Authenticate + integrity-protect NTP without Autokey: NTS-KE over TLS 1.3 to obtain cookies + AEAD keys, then AEAD-protected NTP packets; plus legacy symmetric-key (AES-CMAC).

Deliverable

ntpx syncs to an NTS server (e.g. time.cloudflare.com) with authentication; cookies rotate; symmetric-key peering works.

Acceptance
  • NTS-KE handshake succeeds; AEAD packet verifies; offset computed only on authenticated packets.
  • Cookie rotation maintains ≥1 spare; no plaintext fallback when NTS configured.
  • Tampered packet → AEAD fail → dropped (auth_fail_total++), no clock effect (I15).
  • Symmetric MAC mismatch rejected (constant-time).
  • Downgrade attempt (strip NTS EF) rejected when NTS required.
Fixtures

conformance/nts/ke_transcript.json, .../aead_packet.bin (+ key), .../tampered.bin, .../cookie_rotation.json, .../symkey_cmac.json, .../downgrade.bin.

Pitfalls
  • Non-constant-time MAC compare → timing oracle (I15). - Reusing AEAD nonce → catastrophic. - Cookie exhaustion → fall back to unauth (forbidden when required). - Accepting unauth when NTS configured (downgrade). - TLS cert not validated. - Leaking cookie via Unique-ID correlation (rotate UID).

⬜ Phase 9 — PTP Message Layer + Event/General Ports + SW/Kernel Timestamping §21

Objectives

Implement the PTP wire layer (all message types, common header), event (319) + general (320) UDP ports and raw L2 transport, integrated with SW/kernel timestamping for sub-100 µs capture.

Deliverable

ntpx sends/receives all PTP message types on 319/320 (+ L2); timestamps captured via kernel; pktdump decodes PTP. No servo yet.

Acceptance
  • Encode/decode round-trips every PTP message type bit-exact vs fixture.
  • Event messages get RX/TX timestamps (kernel where available, SW fallback).
  • domainNumber filtering correct (ignore other domains).
  • correctionField parsed as signed Q48.16.
  • Interop: ptp4l recognizes our messages (passive capture).
Fixtures

conformance/ptp_profiles/sync.bin, .../followup.bin, .../delay_req.bin, .../delay_resp.bin, .../announce.bin (+ expected fields), .../correction_field.json, malformed: bad_msgtype.bin, short_header.bin, wrong_domain.bin.

Pitfalls
  • Confusing event vs general port (timestamping only on event). - Two-step flag handling (t1 in Follow_Up not Sync). - correctionField scale (×2^16 ns). - Ignoring transportSpecific/majorSdoId. - L2 vs UDP transport mismatch. - cmsg buffer too small (truncated timestamp).

⬜ Phase 10 — PTP Delay Request-Response + Peer-Delay; offsetFromMaster + meanPathDelay §22

Objectives

Implement both PTP path-delay mechanisms (E2E delay request-response, P2P peer-delay), computing offsetFromMaster and meanPathDelay, supporting one-step and two-step.

Deliverable

As a PTP slave to a master (ptp4l), ntpx computes offsetFromMaster + meanPathDelay continuously; both mechanisms selectable. No actuation yet (Phase 12 servo).

Acceptance
  • §8.14 worked example: offsetFromMaster=+10 µs, meanPathDelay=40 µs (exact).
  • correctionField correctly subtracted (TC residence test).
  • One-step and two-step both yield same offset (fixture).
  • Peer-delay linkDelay matches expected.
  • Interop with ptp4l master: offsetFromMaster agrees within timestamp resolution.
Fixtures

conformance/ptp_profiles/e2e_cycle.json (t1..t4 → offset/delay), .../p2p_linkdelay.json, .../onestep_vs_twostep.json, .../correction_residence.json, .../ptp4l_capture.pcap.

Pitfalls
  • Sign error in offsetFromMaster (slave ahead vs behind). - Forgetting correctionField. - Mixing E2E and P2P on same path. - Delay_Req storm (no randomization). - Asymmetry assumed zero (systematic bias — document). - Two-step Follow_Up matching by sequenceId.

⬜ Phase 11 — PTP BMCA + Port State Machine + Datasets; Ordinary + Boundary Clock §23

Objectives

Implement BMCA (best-master election), the port state machine, all datasets, and operate as an ordinary clock (OC) and boundary clock (BC).

Deliverable

ntpx participates in BMCA: becomes SLAVE to a better master, MASTER when best, PASSIVE otherwise; operates as BC relaying time; ntpx status shows port states + GM.

Acceptance
  • BMCA selects correct GM per dataset comparison (fixture with multiple masters).
  • Single active master per domain (I7); no two MASTER ports for same path.
  • announceReceiptTimeout → master loss → re-election.
  • BC: downstream sees steps_removed+1, correct GM identity.
  • Interop: ptp4l elects same GM given same Announce set.
Fixtures

conformance/ptp_profiles/bmca_3masters.json (expected GM), .../tiebreak_clockid.json, .../master_loss.json, .../bc_relay.json, .../passive.json, .../g8275_1_announce.bin.

Pitfalls
  • Wrong comparison order → wrong GM. - Flapping between MASTER/SLAVE (hysteresis needed). - Two masters (I7) from missed Announce. - steps_removed loop in BC. - Ignoring foreignMasterThreshold (need ≥2 Announces to qualify). - clockClass not reflecting holdover.

⬜ Phase 12 — PTP Servo (PI) + Holdover Controller + Combined NTP/PTP Selection §24

Objectives

Discipline the clock from PTP offsetFromMaster via a PI servo; implement holdover (honest error growth) when sources lost; unify NTP + PTP into one source-selection pipeline.

Deliverable

ntpx disciplines the clock from PTP (< 100 µs SW); on source loss enters holdover with growing reported error; can prefer PTP over NTP when better.

Acceptance
  • PTP slave: |offsetFromMaster| < 100 µs steady-state (kernel ts, LAN).
  • PI servo stable (no oscillation, I4); settle < 10 s.
  • Holdover: freq held, max_error grows linearly at drift rate (I9 of §6/honest growth); clockClass degrades.
  • Combined: with both NTP+PTP, picks lower-error source; only one disciplines clock (I12/I13).
  • Recovery from holdover re-converges without step (I1).
Fixtures

conformance/servo/pi_step.json, .../holdover_drift.json (error growth curve), .../clockclass_degrade.json, .../combined_ntp_ptp.json, .../holdover_recovery.json.

Pitfalls
  • PI gains too high → oscillation (I4). - Integrator windup during holdover. - Two disciplinarians (NTP+PTP both adjusting) → violate I12. - Holdover error not growing (false confidence, violates §6 P9). - clockClass not degraded → downstream trusts stale master. - Switching sources causes step.

⬜ Phase 13 — Conformance + Fuzzing + Long-Run Stability (Allan Deviation) §25

Objectives

Validate correctness + stability at scale: deterministic simulation (clknetsim), NTP/PTP test vectors, PTP telecom profiles (G.8275), parser fuzzing, and 30-day Allan-deviation soak. HW timestamping integration is PhaseDeferred §Phase 13 (interface ready, driver out of scope).

Deliverable

Full conformance suite green; fuzz corpus stable (no crashes); 30-day soak with ADEV plot; differential parity with reference implementations within tolerance.

Acceptance
  • 100% conformance fixtures pass; differential offset vs chrony within 1 ms (NTP) / ptp4l within timestamp resolution (PTP).
  • Fuzz: 24 h no crash/UB/leak on all targets.
  • Soak: no clock-hop, no backward step (I1), ADEV reaches < 1e-9 at τ=10^4 s (oscillator-bound).
  • Property tests pass 10^6 cases (monotonicity, error-bound).
  • G.8275 profile: time error within G.8273.2 class budget (sim).
Fixtures

All prior conformance/** replayed; conformance/sim/clknetsim_scenarios/*.conf; conformance/soak/adev_baseline.json; fuzz seed corpora fuzz/corpus/*.

Pitfalls
  • Non-deterministic sim (wall-clock leak) → flaky CI (P15). - Fuzz corpus not seeded → shallow coverage. - Soak on noisy host masks bugs (use isolated/PHC-stable host). - Differential tolerance too tight (env noise) or too loose (hides regressions). - ADEV computed wrong (overlapping vs non-overlapping).
