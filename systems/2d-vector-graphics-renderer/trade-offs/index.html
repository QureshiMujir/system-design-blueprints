Decisions (§9) · 30 ADRs

A01

Implementation language

Chosen

Rust (stable)

Rejected

C++ (Skia), C (Cairo), Zig

When the rejected choice is right

C or Zig targets embedded firmware where std Rust is unavailable or LLVM support is incomplete

Why: Memory-layout control + portable-SIMD + no GC + portfolio consistency (#385/#169/#181)

A02

Build system

Chosen

cargo + make

Rejected

CMake, Bazel

When the rejected choice is right

Bazel wins in multi-language monorepos requiring hermetic cross-language dependency graphs

Why: Standard Rust; reproducible via Cargo.lock

A03

Dependency policy

Chosen

Minimal; no heavy graphics deps; bytemuck/half/png(tool-only)

Rejected

pulling Skia/Cairo bindings

When the rejected choice is right

Heavy graphics deps (Skia bindings) win in production hosts that already ship Skia and need ABI compatibility

Why: Pedagogical from-scratch; control over hot path

A04

Coverage rasterizer algorithm

Chosen

Sparse signed-area (area,cover) cells + prefix-sum

Rejected

Active-edge-table + N× supersample; trapezoid (Cairo); GPU stencil-cover

When the rejected choice is right

Active-edge-table + supersampling wins for small fixed surfaces where memory is unconstrained and multi-sample quality is required; trapezoid raster (Cairo) wins for PostScript-compatible rendering where trapezoidal decomposition is a normative requirement

Why: One-pass exact-ish AA; O(edges+cells); no SS memory blowup (P3)

A05

Cell accumulator numeric type

Chosen

Fixed-point i32 (Q24.8)

Rejected

f32 cells, f64 cells

When the rejected choice is right

f32 cells win when operating in IEEE-exact floating-point pipelines where bit-identical results across hardware are enforced via compiler flags and no fixed-point library exists

Why: Deterministic (P1); fast integer add; bounded; matches FreeType

A06

Curve flattening

Chosen

Adaptive de Casteljau, Wang's-formula bound, device-space ε

Rejected

Uniform subdivision; analytic coverage (Manson-Schaefer)

When the rejected choice is right

Uniform subdivision wins when ε needs to be a strict upper bound on segment count for bounded real-time budgets; Manson-Schaefer analytic coverage wins for cubic curve rendering where the polynomial can be evaluated at GPU fragment rate

Why: Resolution-correct (P4); terminates; simple vs polynomial coverage

A07

Pixel format (compositing)

Chosen

Premultiplied RGBA8888; F16 for linear blend

Rejected

Straight alpha; planar

When the rejected choice is right

Straight alpha wins when the final surface is consumed by a compositing host that requires straight-alpha input and has no premul conversion step; planar layout wins for SIMD-width-16 color transforms that process each channel as a separate plane

Why: Correct AA edges (P2); SIMD-friendly interleave

A08

Blend implementation

Chosen

Op table → (Fa,Fb) + W3C blend fns; scalar ref + SIMD

Rejected

Per-op hand-written branches

When the rejected choice is right

Per-op hand-written branches win when a hardware target has no branch predictor and a fixed subset of three operators (clear/src/src-over) covers 99% of draws

Why: Maintainable; ref/SIMD parity (P14)

A09

SIMD strategy

Chosen

std::simd portable + target_feature runtime dispatch (SSE2/AVX2/NEON)

Rejected

Hand intrinsics only; autovec only

When the rejected choice is right

Hand intrinsics only win when the compiler's std::simd tier does not yet support a required ISA extension (e.g., AVX-512 gather); autovec only wins for CI targets with no vector hardware where portability matters more than throughput

Why: Portability + width control (#181 reuse)

A10

Color management

Chosen

Table-based sRGB↔linear (256-entry decode, 4096 encode); F16 linear

Rejected

On-the-fly powf per pixel

When the rejected choice is right

On-the-fly powf per pixel wins when the sRGB table would not fit in L1 cache on a very narrow embedded processor and latency-hiding pipelines amortize the transcendental cost

Why: Speed + determinism; ≤1 LSB (I6)

A11

Dithering

Chosen

Bayer 8×8 ordered matrix on 8-bit output

Rejected

Error-diffusion (Floyd-Steinberg)

When the rejected choice is right

Error-diffusion dithering (Floyd-Steinberg) wins when sequential rendering of a single image tile is acceptable and minimum visible banding is critical (print workflows); it is wrong for parallel tile rendering due to scanline state coupling

Why: Deterministic, parallel-safe, cache-free (P1)

A12

Gradient stop interpolation

Chosen

Premul-linear default; configurable sRGB/straight

Rejected

Always sRGB straight

When the rejected choice is right

Always-sRGB-straight interpolation wins when CSS/Canvas compatibility requires matching browser behavior for legacy gradients defined in sRGB straight-alpha

Why: Correctness; matches CSS option set

A13

Stroking model

Chosen

Stroke→fill outline, NonZero

Rejected

Per-segment AA stroke; GPU stroking

When the rejected choice is right

Per-segment AA stroking wins when rendering hairline strokes on GPU where stroke geometry is generated by a vertex shader and blending overlap is acceptable

Why: Avoids join double-blend (P10)

A14

Clip representation

Chosen

Rect fast path + A8 coverage mask; multiply

Rejected

Boolean bitmap; stencil

When the rejected choice is right

Boolean bitmap clip wins on hardware rasterizers (GPU stencil) where coverage-mask arithmetic is not available at the fragment level; stencil wins when clip paths are reused many times and the stencil buffer avoids per-frame mask rasterization

Why: AA clips compose by multiply (P6)

A15

Display list

Chosen

Typed DrawOp enum vector; replay through Canvas

Rejected

Bytecode VM; closure list

When the rejected choice is right

Bytecode VM wins when the display list needs to be serialized across a process boundary (e.g., Wayland protocol extensions) and a compact wire format is required; closure list wins for single-frame immediate rendering where serialization cost is zero

Why: Single render path (P13); easy bounds

A16

Memory model

Chosen

Arena/bump per-frame; pooled cell grid/masks

Rejected

malloc per draw; global GC

When the rejected choice is right

malloc per draw wins in long-lived heterogeneous allocation patterns where the system allocator's coalescing is more efficient than a fixed-size arena; global GC wins in managed-runtime hosts (JVM/CLR) where the host GC already handles graphics objects

Why: Bounded latency (P5); 0 hot-loop alloc

A17

Concurrency (raster)

Chosen

Independent tile workers; immutable scene

Rejected

Shared mutable framebuffer locks

When the rejected choice is right

Shared mutable framebuffer with locks wins on NUMA systems where tile boundary padding would exceed inter-socket cache-coherence cost; sequential rendering wins when surface dimensions are small (< 64×64) and tile overhead dominates

Why: Determinism + linear scaling; no contention

A18

Surface storage

Chosen

Rejected

When the rejected choice is right

Hidden GPU texture wins in compositing pipelines where the surface lives resident on the GPU and CPU readback is never required

Why: Embeddable; predictable layout

Scanline / Active-Edge-Table CPU Rasterization

┌────────────────────────────────────────────────────────────┐
│  Path edges sorted by y_min into Edge Table (ET)            │
│                            │                                │
│                            ▼  (per-scanline y)              │
│  ┌──────────────────────────────────────────────────────┐  │
│  │ Active Edge Table (AET) — edges crossing scanline y  │  │
│  │ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐         │  │
│  │ │edge A  │ │edge B  │ │edge C  │ │edge D  │  ...    │  │
│  │ │ x_now  │ │ x_now  │ │ x_now  │ │ x_now  │         │  │
│  │ │ 1/slope│ │ 1/slope│ │ 1/slope│ │ 1/slope│         │  │
│  │ └────────┘ └────────┘ └────────┘ └────────┘         │  │
│  └──────────────────────────────────────────────────────┘  │
│  AET sorted by x_now → fill pairs [x0,x1] → N× supersample │
│  ──────────────────────────────────────────────────────── │
│  Output: RGBA spans at full or N× resolution               │
└────────────────────────────────────────────────────────────┘

Wins when: the renderer targets a fixed small surface (e.g., ≤ 256×256 icons) where the O(N²) supersampling memory cost is bounded; or when the output is a 1-bit bitmap (font hinting, laser printing) where supersampling is free and analytic coverage is unnecessary. Embodied by: FreeType's monochrome rasterizer (ftbitmap.c), the original Macintosh QuickDraw polygon fill, classic GDI on Windows pre-Vista. Why rejected here: N× supersampling multiplies cell memory and rasterization work by N² while still aliasing at frequencies above N/2 px; does not produce exact coverage fractions, so the area-conservation invariant (I3) cannot be met; ADR-A04 explicitly records this as the primary rejected alternative.

GPU Triangle-Coverage Rasterization

┌─────────────────────────────────────────────────────────────────┐
│ CPU: Path → Triangle Fan (fill) / Quad Strip (stroke)            │
│      ┌──────────────────────────────────────────────────────┐   │
│      │ Tessellator: Béziers → triangles (lyon-style)        │   │
│      │  monotone poly decomp → triangle strips               │   │
│      └────────────────────┬─────────────────────────────────┘   │
│                           │ vertex buffer upload                  │
│ GPU: ──────────────────────────────────────────────────────────  │
│      ┌──────────────────────────────────────────────────────┐   │
│      │ Vertex Shader: affine CTM → clip space                │   │
│      │ Rasterizer: hardware coverage (MSAA 4×/8×)           │   │
│      │ Fragment Shader: Porter-Duff + blend, premul RGBA     │   │
│      │ Render Target: RGBA surface (MSAA resolve if needed)  │   │
│      └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘

Wins when: the rendered surface is already GPU-resident and read-back to CPU is never needed; GPU parallelism (thousands of fragment threads) makes this 10–100× faster than CPU cells for large scenes; required in game-engine HUD overlays, WebGPU-based UI toolkits, and any context where the display pipeline is end-to-end GPU. Embodied by: Skia Ganesh (GL/Vulkan/Metal tessellation path), Direct2D (D3D11 hardware rasterizer), NV_path_rendering (Kilgard & Bolz 2012, GPU stencil-then-cover). Why rejected here: this design targets an embeddable CPU-only renderer (no_std-friendly, single-thread per surface, §1); GPU dependency breaks the deployment model (linked library, headless render farms, deterministic pixel output); GPU raster output is driver-dependent and fails the bit-identical determinism requirement (§4, I10, P1).

Compute-Shader Tile-Based Path Rendering

┌──────────────────────────────────────────────────────────────────┐
│ CPU: Path → per-tile segment lists                                │
│ ┌───────────────────────────────────────────────────────────┐   │
│ │ Flatten curves → line segments in device space             │   │
│ │ Bin segments into 16×16 (or 32×32) tiles                   │   │
│ └────────────────┬──────────────────────────────────────────┘   │
│                  │ segment buffer per tile → GPU                  │
│ GPU compute pass: ─────────────────────────────────────────────  │
│ ┌───────────────────────────────────────────────────────────┐   │
│ │ Tile workgroup: 16×16 threads                              │   │
│ │ Per-thread lane: signed-area accumulation for its pixel    │   │
│ │ Warp reduction → coverage mask per tile                    │   │
│ │ Shade: LUT gradients / image samples                       │   │
│ │ Blend: Porter-Duff in-register                             │   │
│ │ Write tile → surface texture                               │   │
│ └───────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────┘

Wins when: the rendering target is a GPU surface and scene complexity is high (10k+ paths per frame), as in vector-heavy web browser rendering or design-tool canvases; GPU tile parallelism amortizes per-segment cost over the warp width; Vello achieves >10 Gpix/s on modern GPUs vs ~1 Gpix/s CPU ceiling. Embodied by: Vello / piet-gpu (Levien et al., linebender), Pathfinder (servo project), the Slug glyph renderer on GPU. Why rejected here: requires a GPU compute-capable runtime (wgpu, Vulkan, Metal) which is incompatible with the no_std-friendly embeddable library goal (§1); CPU flat-segment binning and GPU tile dispatch add complexity that is unnecessary when a single CPU core at 800 Mpix/s meets the §4 targets; the CPU cell approach (ADR-A04) is the reference from which this GPU design evolved.

Analytic Coverage / Signed-Distance for Glyph-Class Paths

┌─────────────────────────────────────────────────────────┐
│ Path → Implicit curve representation                     │
│ ┌─────────────────────────────────────────────────────┐ │
│ │  Cubic Bézier → Loop-Blinn (2005) classifying cubic │ │
│ │  OR                                                  │ │
│ │  Slug (Lengyel 2017): per-glyph SDF atlas            │ │
│ │  Δ = signed distance to nearest curve               │ │
│ └───────────────────┬─────────────────────────────────┘ │
│                     │ per-pixel signed distance          │
│ ┌───────────────────▼─────────────────────────────────┐ │
│ │  coverage = smoothstep( -½, +½, Δ / (√2 · ε) )     │ │
│ │  one fragment shader evaluation per pixel            │ │
│ │  resolution-independent: no pre-rasterization        │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘

Wins when: the path set consists entirely of smooth, non-self-intersecting curves (glyphs, icons) that must render correctly at arbitrary scale; signed-distance fields are stored in a compact atlas and re-evaluated per-pixel by a GPU fragment shader at any resolution without re-tessellation; excellent for text rendering at large sizes. Embodied by: Slug (Eric Lengyel, JCGT 2017) for glyph rendering; Loop & Blinn (2005 SIGGRAPH) for GPU resolution-independent curves; multi-channel SDF (MSDF) font rendering. Why rejected here: analytic SDF/implicit evaluation requires the curve to be smooth and non-self-intersecting; arbitrary user paths (self-intersecting fills, EvenOdd rule, compound paths, clipping) are not representable as a single signed-distance field; the coverage formulation loses the fill-rule generality that the signed-area cell approach provides natively (ADR-A04, ADR-A06, Phase 4).
