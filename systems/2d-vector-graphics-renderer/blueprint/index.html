415 — 2D Vector Graphics / Compositing Renderer (Skia/Cairo-like) from Scratch

Project Number: 415 Project Name: 2D Vector Graphics / Compositing Renderer (Skia/Cairo-like) from Scratch Owner: Mujir Qureshi Document: FINAL_BLUEPRINT.md Status: specification — locked

1. Goal

Build a CPU 2D vector graphics + compositing engine — peer class to Skia (SkCanvas/SkRasterPipeline) and Cairo (cairo_t). Arbitrary anti-aliased path fill + stroke, gradients, Porter-Duff compositing, blend modes, clipping, image sources, retained display lists. Software rasterizer; NO GPU backend. Correctness-first → observability → maintainability → performance.

Core capability surface:

  • Path model — PathBuilder verbs move_to / line_to / quad_to (quadratic Bézier) / cubic_to (cubic Bézier) / close; verb stream + point array; multiple subpaths; fill rules NonZero + EvenOdd.
  • Coordinate spaces — user space → device space via affine 2×3 Matrix(a,b,c,d,e,f); compose/invert/map-point; CTM stack; perspective 3×3 deferred → PhaseDeferred("Deferred Features Register").
  • Bézier flattening — adaptive de Casteljau subdivision to line segments within flatness ε (default 0.25 px device); Wang's-formula segment-count bound; cusp/near-degenerate handling.
  • Coverage rasterizer (the core) — signed-area cell accumulation (Skia / FreeType-smooth / font-rs / Raph-Levien approach): each edge walked cell-by-cell accumulating (area, cover); per-scanline prefix-sum → exact-ish AA alpha per pixel; single pass, NO supersampling.
  • Span generation — coverage SPANS per scanline (x_start, len, &[coverage]) feeding the compositor.
  • Paint / shaders — solid color; linear / radial (two-circle, focal) / conic gradients; image shaders; sorted color stops; spread modes pad/repeat/reflect; gradient transform via inverse CTM.
  • Compositor — premultiplied RGBA8888; 12 Porter-Duff operators (clear … xor, plus plus/lighter); coverage modulates source alpha; premul/unpremul round-trip.
  • Blend modes — W3C Compositing & Blending L1: 12 separable (multiply … exclusion) + 4 non-separable (hue, saturation, color, luminosity).
  • Clipping — clip-rect fast path; clip-path AA coverage mask; clip stack push/pop with monotonic intersection.
  • Color management — sRGB↔linear transfer; gamma-correct (linear-light) blending option; F16 intermediate surfaces; ordered dithering on 8-bit output.
  • Surfaces — RGBA8888-premul (+ optional F16); row stride; clip-to-bounds.
  • Display list / Picture — retained record of draw ops; bounds; replay (immediate mode also supported).

System boundaries: an embeddable rendering library (vg) + a CLI conformance/render driver (vg-tool) + a golden-image differ (vg-diff). NOT a windowing/display server (→ #384), NOT an image codec (→ #173), NOT a GPU rasterizer.

Explicit non-goals:

  • NOT GPU/Vulkan/Metal backend — CPU SIMD only; GPU shader pipeline → PhaseDeferred("Deferred Features Register").
  • NOT a font shaper/layout engine — consumes glyph outlines as paths (TrueType outline extraction = #385); text shaping → PhaseDeferred("Deferred Features Register").
  • NOT SVG/PDF document parsing — input is the programmatic path/paint API, not a markup language; SVG front-end = separate project.
  • NOT a windowing/event system — emits pixel surfaces; presentation = #384.
  • NOT image encode/decode — accepts decoded RGBA buffers; codecs = #173.
  • NOT 3D/perspective rasterization — affine only in v1; 3D triangle raster = #169.
  • NOT mipmap/anisotropic image filtering — nearest + bilinear only; mipmaps → PhaseDeferred("Deferred Features Register").

Deployment model: linked into a host process (compositor, document viewer, headless renderer); single render thread per surface; optional worker pool for tiled parallel raster. no_std-friendly core; std for file/CLI.

Target users: graphics-engine engineers, UI-toolkit authors, headless render-farm operators needing deterministic pixel-exact 2D output.

Phase 0 deliverable — numbered crates/modules:

  1. vg-geom/ — Point, Vec2, Matrix (2×3), Rect, Transform stack, affine math.
  2. vg-path/ — PathBuilder, verb/point storage, subpath iteration, bounds.
  3. vg-flatten/ — adaptive Bézier flattening, flatness tolerance, Wang's formula.
  4. vg-raster/ — signed-area coverage cells, edge builder, prefix-sum AA, span emitter.
  5. vg-color/ — Color, premul/unpremul, sRGB↔linear, F16, dithering.
  6. vg-paint/ — Paint, shaders (solid/gradient/image), spread modes, stop interpolation.
  7. vg-comp/ — Porter-Duff + blend modes; span blending; SIMD kernels.
  8. vg-surface/ — pixel surfaces (RGBA8888/F16), stride, clip-to-bounds, allocators.
  9. vg-clip/ — clip stack, clip-rect, clip-path mask, AA clip intersection.
  10. vg-record/ — display list / Picture record + replay; bounds.
  11. vg-tool/ — CLI: render scene → PNG, run conformance, dump spans.
  12. vg-diff/ — golden-image differ (per-pixel + perceptual), reference-rasterizer differential harness.

What later phases unlock: P3 unlocks AA fill; P5 unlocks visible output (paint + compositing); P6 gradients; P7 stroking; P8 clipping; P9 blend modes; P10 color-correct blending; P11 images; P12 retained replay + SIMD; P13 conformance + perf hardening.

Estimated timeline: Phase 0 (P0–P5, fill+composite to a surface) = 8–11 weeks; full P0–P13 = 6–8 months.

Prerequisites:

  • Computational geometry: affine transforms, Bézier curves, de Casteljau, line/curve intersection, winding number.
  • Rasterization: scanline conversion, coverage/anti-aliasing, signed-area method, edge sorting.
  • Color science: premultiplied alpha, sRGB transfer function, gamma, linear-light, dithering.
  • Compositing algebra: Porter-Duff operators, W3C blend formulae, separable vs non-separable blend.
  • SIMD: lane width, gather/scatter, FMA, masked stores; cache behavior of span loops.
  • Numerics: fixed-point vs float for cell accumulation, rounding, error bounds.

2. Why Build This

Unique systems knowledge taught:

  • Analytic anti-aliasing without supersampling — the signed-area coverage method computes exact pixel-coverage in one pass; understanding why (area, cover) + prefix-sum equals per-pixel alpha is the single deepest idea in 2D raster.
  • Premultiplied-alpha compositing algebra — why premul is the canonical representation, how Porter-Duff Fa/Fb factors generalize 12 operators, and the precision traps of premul/unpremul round-trips.
  • Stroke-to-fill conversion — turning a centerline + width + joins/caps into a fillable outline; the geometry of miter/round/bevel and self-intersection resolution by NonZero fill.
  • Gradient sampling under transform — projecting device pixels back through the inverse CTM into gradient parameter space; incremental evaluation to kill per-pixel sqrt.
  • Color-correct blending — sRGB is perceptual, not linear; blending in gamma space darkens edges; linear-light intermediates + dithering are how production renderers get it right.
  • Clip composition as coverage multiplication — clipping is not a boolean mask but an alpha mask multiplied into coverage; AA clips compose by multiplication.
  • Retained-mode recording — display lists decouple scene description from rasterization, enabling bounds culling, replay, and deferred SIMD batching.

Historical / architectural significance:

  • Skia — Chrome/Android/Flutter 2D engine; SkRasterPipeline (Levien-style sparse coverage) defines the modern CPU AA path.
  • Cairo — GTK/Firefox-era vector engine; cairo_t API and trapezoid rasterizer popularized the path/paint/clip model.
  • FreeType smooth rasterizer — the canonical signed-area (area, cover) cell rasterizer; #385 builds the glyph-specialized subset of this engine.
  • Porter & Duff (1984) — "Compositing Digital Images" — the algebra every alpha compositor still uses.
  • W3C Compositing & Blending L1 — standardized blend-mode formulae now ubiquitous in CSS/Canvas/SVG.

Engineering muscles: numeric-stable geometry; cache-aware span loops; SIMD kernel authoring; invariant-driven pixel correctness; differential testing against a reference rasterizer.

Cross-links:

  • #385 TrueType Font Rasterizer — fills glyph outlines: a SPECIAL CASE of this engine (path fill, no gradients/stroke/blend/clip). This project generalizes it; glyph outlines feed in as paths.
  • #169 3D Software Rasterizer — triangle raster with z-buffer + perspective; contrast: this is 2D, AA-by-coverage, no depth, affine only.
  • #384 Display Server / Compositor — consumes rendered Surfaces as window contents; this engine is the per-window drawing backend.
  • #173 Image Codec — decodes PNG/JPEG into the RGBA buffers our image shader samples.
  • #380 Video Codec — per-frame surfaces can be composited (overlays, subtitles).
  • #389 Classical CV — shares premul/linear-light color handling and convolution kernels.
  • #181 SIMD Library — span blend kernels reuse its portable-SIMD abstractions.

Calibration value: pixel-exact 2D rendering tolerates zero hand-waving — a one-LSB color error or a half-pixel coverage bug is visible and falsifiable. Permanently raises the bar for numeric rigor, color correctness, and SIMD-aware data layout.

What Mastery Looks Like — finishing this blueprint means you can:

  • Design a signed-area cell rasterizer from scratch and derive the (area, cover) + prefix-sum equivalence to analytic coverage without supersampling (Phase 3)
  • Reason about premultiplied alpha algebra end-to-end: when to multiply, when to divide, and why straight-alpha compositing produces dark fringes (Phase 5)
  • Implement all 12 Porter-Duff operators and 16 W3C blend modes correctly for both opaque and partial-alpha cases, including the unpremultiply–blend–repremultiply cycle (Phase 5, Phase 9)
  • Write adaptive Bézier flattening in device space, explain Wang's-formula segment bound, and identify the failure modes of user-space tolerance (Phase 2)
  • Author portable-SIMD span kernels with scalar-parity guarantees and runtime target_feature dispatch, diagnosing mismatches by lane/tail/rounding source (Phase 12)
  • Apply sRGB↔linear color management correctly: choose the right space for premultiplication, compositing, and 8-bit quantization with ordered dithering (Phase 10)
  • Instrument a CPU graphics pipeline for pixel-exact differential testing: golden images, scalar oracle, area-conservation invariants, and fuzz targets that explore all geometry edge cases (Phase 13)

Client / Host App — calls the Canvas immediate API (fill_path, stroke_path, clip, save/restore) or records a Picture for replay. vg-tool drives scenes from JSON and emits PNG/raw surfaces. All input is programmatic; no markup parsing.

vg-record — retained recorder; appends typed DrawOps to a DrawOpList; accumulates a conservative device-space bounding box; Replayer re-issues ops to a Canvas. Decouples scene construction from rasterization; enables culling and deferred batching.

vg::Canvas — orchestration layer holding the CTM stack and clip stack. Per draw op: maps path points through CTM, flattens curves, rasterizes to coverage spans intersected with the current clip mask, shades the spans via vg-paint, composites via vg-comp into the bound Surface. The only place rendering side effects occur.

vg-geom — Matrix (2×3 affine) compose/invert/map-point; Transform stack; Point/Vec2/Rect. All user→device mapping flows through here; perspective deferred.

vg-path — PathBuilder storing a verb stream + point array; subpath iteration; close semantics; conservative bounds. Immutable Path after build; cheaply clonable (Arc'd buffers).

vg-flatten — converts quad/cubic Béziers to polylines within flatness ε in device space (so tolerance is resolution-correct); de Casteljau subdivision bounded by Wang's formula; emits line segments to the edge builder.

vg-raster — the core. EdgeBuilder ingests polyline edges into a sparse CellGrid of (area, cover) per touched pixel; a per-scanline prefix-sum over cover produces accumulated winding, folded by FillRule into coverage ∈ [0,1]; SpanEmitter coalesces runs into Spans; clip mask multiplies coverage. Single pass, O(edges + touched cells).

vg-paint — Shader produces source premul RGBA per pixel of a span: Solid, LinearGradient, RadialGradient (two-circle/focal), ConicGradient, ImageShader (nearest/bilinear). Gradients evaluate in local space mapped through inverse CTM; spread modes pad/repeat/reflect; stop interpolation in chosen color space.

vg-color — Color, premultiply/unpremultiply, sRGB encode/decode (gamma transfer), F16 intermediate conversions, ordered dithering. Centralizes all color-space transforms so blending math is space-correct.

vg-comp — applies the Porter-Duff (Fa, Fb) factor pair, then (if a blend mode is set) B(Cs,Cd) before the over step; SIMD span kernels blend whole spans. Operates on premul RGBA (or F16 when color-correct blending is enabled).

vg-surface — owns pixel storage; formats RGBA8888-premul and F16; row stride (alignment + padding); clip-to-bounds; arena/bump allocators for transient cell grids and masks.

vg-clip — ClipStack of rectangles + coverage masks; clip-rect fast path intersects span x-ranges; clip-path rasterizes to an AA alpha mask; intersection is monotonic shrink (push narrows, restore widens).

vg-diff — offline: per-pixel + perceptual golden-image comparison; differential harness running scenes against a trusted reference rasterizer and asserting bounded coverage/color deltas.

6. Design Principles

P1 — Determinism over convenience. Identical (scene, CTM, surface fmt, ε, color cfg) MUST yield bit-identical pixels on every run/platform. Forbid FP-order nondeterminism (parallel reductions reorder sums), uninitialized padding, address-dependent hashing. Violation: golden-image tests flake; replay diverges; differential harness becomes useless.

P2 — Premultiplied alpha is the canonical pixel. All compositing math is on premul RGBA (c ≤ a per channel). Unpremultiply only at API boundaries (color readback). Violation: src-over with straight alpha produces dark fringes on AA edges; round-trip precision loss.

P3 — Coverage is the only AA mechanism. No supersampling, no MSAA. Edge coverage ∈ [0,1] from the signed-area sweep modulates source alpha. Violation: supersampling multiplies memory + time and still aliases at high frequency; abandoning analytic coverage breaks the area-conservation invariant.

P4 — Tolerance lives in device space. Flatness ε and curve subdivision are evaluated AFTER the CTM, so quality is resolution-correct at any zoom. Violation: flattening in user space under-tessellates when scaled up (visible facets) and over-tessellates when scaled down (wasted work).

P5 — Bounded, arena-based allocation. Transient cell grids, masks, and span buffers come from per-frame arenas reset between draws; zero malloc in the hot loop. Violation: per-draw heap churn causes frame-time spikes; fragmentation breaks p99.

P6 — Clip is alpha multiplication, not boolean. Clipping multiplies coverage by a clip alpha mask; nested clips intersect by multiplying masks (monotonic shrink). Violation: boolean clips alias clip edges; AA clips composed by min instead of multiply give wrong soft edges.

P7 — Color space is explicit. Every blend declares its space (sRGB-encoded vs linear-light). Linear-light blending requires linear intermediates (F16 or 16-bit). Violation: blending sRGB values as if linear darkens gradients and edge AA; gamma errors are visible and non-recoverable.

P8 — Shaders are pure functions of device coordinates. A shader maps device (x,y) → premul source color via the inverse CTM; no hidden state, no per-pixel allocation. Violation: stateful shaders break tiling/parallelism and determinism.

P9 — Spans are the universal interface. Rasterizer → shader → compositor communicate via Span{ y, x0, len, coverage }. Every stage processes whole spans. Violation: per-pixel virtual dispatch destroys throughput and SIMD batching.

P10 — Stroke is converted to a fill. Strokes become outline paths filled with NonZero; joins/caps are geometry, not raster special-cases. Violation: per-segment AA stroking double-blends overlaps and seams at joins.

P11 — Saturating/checked math in raster. Fixed-point cell accumulation and coverage clamp use checked/saturating ops; coverage clamped to [0,1]; device coords bounds-checked once per edge. Violation: integer overflow in cell area corrupts coverage silently.

P12 — Observability by default. Per draw: counts of edges, cells touched, spans, pixels blended, allocation high-water; per frame: phase timing. Violation: a coverage or perf regression is undetectable without per-stage counters.

P13 — Retained and immediate share one path. Picture replay issues the exact same DrawOps as immediate mode through the same Canvas. No second rasterizer. Violation: two code paths drift; golden images diverge between record and direct draw.

P14 — Bit-exact compositing reference. A scalar reference compositor mirrors every SIMD kernel; SIMD output MUST equal scalar output bit-for-bit. Violation: SIMD-only bugs (lane masking, rounding) ship silently.

Path Grammar (EBNF)

Path        ::= Subpath* ;
Subpath     ::= MoveTo Verb* Close? ;
Verb        ::= LineTo | QuadTo | CubicTo ;
MoveTo      ::= "M" Point ;            -- start new subpath at Point
LineTo      ::= "L" Point ;            -- straight segment to Point
QuadTo      ::= "Q" Point Point ;      -- ctrl, end (quadratic Bézier)
CubicTo     ::= "C" Point Point Point ;-- ctrl1, ctrl2, end (cubic Bézier)

Storage: parallel arrays — verbs: Vec<Verb> (u8 tag) + points: Vec<Point> (consumed positionally per verb). Implicit MoveTo if first verb is a draw verb. Close makes a subpath cyclic for fill + join continuity in stroke.

Coverage Cell Model (core)

A Cell at integer pixel (x,y) holds two signed fixed-point accumulators:

  • cover — net vertical winding crossing the LEFT edge of the cell (Σ of edge dy fractions through this x-column at this scanline).
  • area — twice the signed trapezoidal area the edge covers INSIDE this cell (sub-pixel partial coverage).

Per scanline y, sweep x ascending maintaining acc = Σ cover[0..x]. Pixel coverage:

winding(x) = acc_before_cell + area(x) * sign / (2*ONE_PIXEL)
NonZero : coverage = clamp01(|winding|)
EvenOdd : w = winding mod 2 ;  coverage = clamp01(w > 1 ? 2 - w : w)

(ONE_PIXEL = fixed-point unit, e.g. 1<<8.) Output: contiguous Spans where coverage > 0.

Degenerate / failure paths

- Empty path (no verbs): zero spans; surface unchanged.
- Subpath "M 5 5" only: no area; fill emits nothing; stroke emits a dot if round/square cap.
- Matrix det≈0 (collapsed CTM): reject map; raise MatrixSingular (I5).
- Cubic with coincident control points (cusp): flattening still terminates via Wang bound; no infinite recursion.
- NaN/Inf in points: rejected at PathBuilder (PointNotFinite); never reach raster.
- Coverage accumulator overflow (pathological huge winding): saturates to clamp01 (I2,I11).
- Gradient with 0 stops: error GradientNeedsStops; 1 stop: solid that color.

11. Core Schema and Core Types

Matrix / Point (vg-geom)

struct Point { x: f32, y: f32 }
struct Vec2  { x: f32, y: f32 }
struct Matrix { a:f32, b:f32, c:f32, d:f32, e:f32, f:f32 }  // 2x3 affine

fn Matrix::identity() -> Matrix;
fn Matrix::concat(&self, rhs: &Matrix) -> Matrix;          // self · rhs
fn Matrix::invert(&self) -> Option<Matrix>;                // None if |det|<1e-12 (I5)
fn Matrix::map_point(&self, p: Point) -> Point;
fn Matrix::det(&self) -> f32;

Ownership: Copy value types. Mutation: none (pure). Concurrency: trivially Send+Sync. Determinism: f32 ops in fixed source order (P1).

Transform stack (vg-geom)

struct Transform { stack: Vec<Matrix>, current: Matrix }
fn save(&mut self);                 // push current
fn restore(&mut self) -> bool;      // pop; false if underflow
fn concat(&mut self, m: &Matrix);   // current = current · m

Path / PathBuilder (vg-path)

enum Verb { Move=0, Line=1, Quad=2, Cubic=3, Close=4 }
struct Path { verbs: Arc<[Verb]>, points: Arc<[Point]>, bounds: Rect }
struct PathBuilder { verbs: Vec<Verb>, points: Vec<Point>, last: Point, start: Point }

fn move_to(&mut self, p: Point); fn line_to(&mut self, p: Point);
fn quad_to(&mut self, c: Point, e: Point);
fn cubic_to(&mut self, c1: Point, c2: Point, e: Point);
fn close(&mut self); fn finish(self) -> Result<Path, PathError>;  // rejects non-finite (I-edge)

Ownership: Path immutable, cheaply cloned (Arc'd buffers). Mutation: only during build. Serialization: verbs+points are POD; bytemuck-castable. Compatibility: verb tags frozen.

Cell / CellGrid / Span (vg-raster)

struct Cell { area: i32, cover: i32 }     // fixed-point Q24.8 (ADR A05)
struct CellGrid<'a> { cells: &'a mut [Cell], width: i32, x_min: i32, ... }  // arena-backed
struct Span<'c> { y: i32, x0: i32, len: u32, coverage: &'c [u8] }  // 0..=255

fn EdgeBuilder::add_line(&mut self, p0: Point, p1: Point);   // accumulate into grid
fn sweep_scanline(grid:&CellGrid, y:i32, rule:FillRule, out:&mut Vec<u8>); // prefix-sum
fn SpanEmitter::emit(coverage:&[u8], y:i32, clip:&ClipMask) -> impl Iterator<Item=Span>;
enum FillRule { NonZero, EvenOdd }

Ownership: CellGrid borrows arena memory; reset per draw. Concurrency: per-tile grid is thread-local; never shared mutably (A17). Determinism: ascending-x sweep, fixed accumulation order (I10).

    • flatness metric = max perpendicular distance of control points from the chord; if ≤ ε emit chord; else subdivide (recursive with depth cap) OR uniform-step via Wang count (choose: adaptive primary, Wang as recursion-depth guard). (ADR-A06 cusp/near-degenerate handling; I2 bounded work)

  • Max chord deviation ≤ ε for all emitted segments (measured).

  • Cusp curve (control points crossing) terminates; no stack overflow (depth cap, e.g. 24).

15. Phase 3 — Coverage Rasterizer (Signed-Area Cells + Prefix-Sum AA)

15.1 Objectives

  • Implement the CORE: EdgeBuilder → sparse CellGrid(area,cover) → per-scanline prefix-sum → coverage spans (P2, P3, A04, A05).
  • Exact-ish analytic AA in a single pass; no supersampling.
  • Fixed-point Q24.8 accumulators; coverage clamp; area-conservation invariant (I3).

15.2 Detailed Implementation Steps

  • vg-raster/cell.rs: Cell { area:i32, cover:i32 }; ONE = 1<<8 fixed-point unit. (signed-area (area,cover) cell: Levien 2020 P2; FreeType ftgrays P3; ADR-A04, ADR-A05)
  • vg-raster/grid.rs: CellGrid — arena-backed sparse storage keyed by (x,y) within device bounds; one Cell per touched pixel; add(x,y, area, cover).
  • vg-raster/edge.rs: EdgeBuilder::add_line(p0,p1) — walk the line cell-by-cell (DDA-style across pixel columns/rows): (scanline/active-edge-table contrast: ADR-A04; P3 — Coverage is the only AA mechanism)
    • split the edge at each integer y-boundary into sub-segments within one scanline.
    • for each scanline sub-segment, walk integer x cells; per cell add: cover += dy_fraction; area += dy_fraction * (1 - mid_x_fraction)*2*ONE (trapezoidal partial coverage). Sign from edge winding direction (up vs down).
  • vg-raster/sweep.rs: sweep_scanline(grid, y, rule, out) — iterate cells left→right; acc accumulates cover; per pixel coverage_raw = acc*2*ONE + area; fold by FillRule → u8 coverage. (prefix-sum AA: P2 Levien; I3 area conservation; analytic coverage P3 Catmull 1978 P8)
  • vg-raster/fillrule.rs: NonZero clamp01(|w|); EvenOdd triangle-fold (deferred wiring to P4; implement function now). (NonZero/EvenOdd fold; I4 determinism; P1 Determinism over convenience)
  • vg-raster/span.rs: SpanEmitter coalesces runs of coverage>0 into Span{y,x0,len,&coverage}.
  • Integrate: Canvas::fill_path → flatten → EdgeBuilder → sweep → spans → (debug) write coverage as A8 to surface.
  • tools/coverage_viz: render coverage grayscale for inspection.
  • Tests: filled square coverage all=255 interior; edge pixels partial; Σcoverage ≈ analytic area (I3).

15.3 Deliverable

A8 coverage of a filled path written to surface; vg-tool render --coverage scene.json out.png shows AA grayscale. Area-conservation test passes.

15.4 Acceptance Criteria

  • Interior coverage = 255; exterior = 0; edges ∈ (0,255).
  • Area conservation: |Σcoverage/255 − analytic_area| ≤ ε·perimeter (I3).
  • Single pass: no per-pixel re-rasterization; complexity O(edges + touched cells).
  • Coverage ∈ [0,255] always (I2); no overflow on a 32k-edge star polygon.
  • Rasterize ≥ 40 M edge-cells/s (criterion).

15.5 Conformance Fixtures

  • conformance/fixtures/paths/aa_square.json — interior/edge coverage golden (A8).
  • conformance/fixtures/paths/aa_triangle.json — area conservation.
  • conformance/fixtures/paths/thin_sliver.json — sub-pixel sliver coverage < 1.
  • conformance/fixtures/paths/star_32k_edges.json — overflow/perf stress.

15.6 Pitfalls

  • Sign of cover: winding direction (edge going up vs down) sets sign; flipping it inverts inside/outside.
  • Cell at scanline boundary: an edge crossing an integer y must be split exactly there; mis-split double-counts area into the wrong scanline → bright/dark seams.
  • Fixed-point overflow: area accumulation for many overlapping edges in one cell can overflow i32; use i64 accumulation per cell OR saturate (I2); document the chosen bound.
  • Pixel-center vs corner sampling: coverage is area-based, not point-sampled; do NOT also point-sample (A29 consistency).
  • Empty span suppression: coalesce only coverage>0 runs; emitting zero-coverage pixels wastes compositing.

15.7 Performance Concerns

  • Sparse cell storage: hashmap is too slow; use a per-scanline sorted cell list or a dense row buffer reset per scanline (font-rs/ftgrays approach) — choose dense-row-accumulator for cache locality.
  • Cache: process scanline-by-scanline; area/cover rows are contiguous; prefix-sum is a streaming pass.
  • Branchless coverage fold for NonZero (clamp); EvenOdd needs a mod — keep on slow path.
  • Arena reset between draws avoids alloc; high-water tracked (I12).

15.8 Edge Cases

  • Horizontal edge: contributes zero cover (dy=0); skip — but still defines fill boundary via adjacent edges.
  • Edge entirely left of device bounds: still contributes cover to the leftmost column (winding from far left); accumulate at x=x_min.
  • Edge outside top/bottom: clip to device scanline range.
  • Single-pixel-tall path: one scanline; coverage from area only.

15.9 Failure Analysis

  • Seams between scanlines: y-split error; visualize coverage; check sub-segment area distribution.
  • Inverted fill (inside/outside swapped): cover sign bug; check edge winding direction.
  • Coverage > 255 clamped frequently: overflow path; switch to i64 cell accumulation; alert raster.coverage_clamped.

15.10 Operational Notes

  • metrics::counter!("raster.edges"), counter!("raster.cells_touched"), histogram!("raster.area_error") (I3).
  • tracing::debug! per draw: edges, cells, spans.
  • Runbook: docs/runbooks/coverage-mismatch.md.

23.6 Pitfalls

  • Bilinear on straight alpha: interpolating straight-alpha texels bleeds color from transparent texels (halo); sample in premul (P2).
  • Half-texel offset: sampling at texel corner vs center; use pixel-center (UV+0.5) convention (A29); off-by-half blurs/shifts.

Mental Models & First Principles

  1. MM1 — The signed-area cell is an exact integral of edge coverage, not a sample. Predicts: why summing (area, cover) over a scanline equals the true geometric fraction of each pixel covered by the filled region. Without it: you add supersampling (4× memory, still aliased at high frequency) or misunderstand why the prefix-sum sweep works. Applied: §8 Coverage Cell Model, §3 (vg-raster), Phase 3.

  2. MM2 — Premultiplied alpha is the only representation that makes src-over a linear blend. Predicts: that compositing N transparent layers in premul gives the same result regardless of ordering (where correct), and that straight-alpha compositing introduces a nonlinear dark-fringe artifact on AA edges. Without it: you write dst = src*α + dst*(1−α) with straight values and produce visibly darkened fringe pixels at every partially-covered edge. Applied: §8 Porter-Duff, §6 (P2), Phase 5, Phase 9.

  3. MM3 — Bézier flatness error is a second-difference norm, not a chord-to-control-point distance. Predicts: Wang's formula and the correct recursion termination criterion; a control-hull check underestimates error for S-curves. Without it: you terminate subdivision too early on S-shaped cubics and produce visible facets; or you recurse forever on cusps. Applied: §6 (P4), Phase 2 (wang.rs, bezier.rs, ADR-A06).

  4. MM4 — Porter-Duff (Fa, Fb) factors are derived from the principle that no pixel is counted twice. Predicts: the full table of 12 operators from first principles by enumerating the four regions (src-only, dst-only, both, neither) and asking which survives. Without it: you memorize a table without understanding why src-in is Fa=αd, Fb=0 or how to derive a new operator. Applied: §8 Porter-Duff table, Phase 5, Phase 9 (W3C compositing equation).

  5. MM5 — sRGB is a perceptual encoding; blending in it computes the wrong midpoint. Predicts: that the 50% luminance midpoint between white and black is sRGB 188, not 128; and that AA-edge blending in sRGB-encoded space makes edges appear too dark. Without it: you blend in sRGB, gradients look muddy, and AA edges are perceptually too thin. Applied: §6 (P7), §4 (Color round-trip ≤1 LSB), Phase 10 (sRGB↔linear, F16 intermediate, ADR-A10).

  6. MM6 — Clip composition is multiplicative, not MIN. Predicts: that two 50%-transparent clip masks nested together yield 25% coverage, not 50%; and that min(a,b) is wrong for soft AA clips. Without it: you implement apply = min(draw_cov, clip_cov), overlapping soft clips are too bright, and nested clips do not correctly narrow the visible region. Applied: §6 (P6), §8 (Clipping), Phase 8 (ADR-A14, I8).

  7. MM7 — Device-space tolerance is the only resolution-correct criterion for flattening. Predicts: that flattening curves in user space under a 10× scale CTM produces visible facets (ε is 10× too large in device pixels); and that device-space ε self-corrects at all zoom levels. Without it: you flatten once in user space and get faceted curves when the canvas is scaled. Applied: §6 (P4), §4 (Flatten tolerance ε = 0.25 px device space), Phase 2.

  8. MM8 — The span is the correct SIMD granularity because it is a contiguous, homogeneous memory region. Predicts: that per-pixel virtual dispatch destroys throughput; that coalescing coverage runs into spans before blending is a strict prerequisite for SIMD efficiency; and that span length is the primary determinant of fill-rate headroom. Without it: you write a per-pixel compositor and observe 10× lower fill rate than the memory-bandwidth ceiling. Applied: §6 (P9), §4 (Fill rate ≥800 Mpix/s), Phase 12 (ADR-A09).

  9. MM9 — Stroke-to-fill conversion avoids double-blending at joins because the entire outline is one filled path. Predicts: that per-segment AA stroking darkens overlap regions at joins and caps; and that assembling the full outline and calling fill_path(NonZero) once is the only correct approach. Without it: you rasterize each segment with AA separately, overlapping strips at joins blend twice, and seam artifacts are visible at every corner. Applied: §6 (P10), §8 (Stroking), Phase 7 (ADR-A13, I7).

  10. MM10 — Determinism requires a fixed total order on every floating-point operation, not just an absence of data races. Predicts: that parallel tile reductions which sum coverage in non-deterministic order produce different output bytes across runs even with the same scene, breaking golden-image gates. Without it: you enable tile parallelism, the pixel hash varies between runs, and the CI golden gate fails spuriously. Applied: §6 (P1), §4 (Determinism: bit-identical), Phase 13 (I10, ADR-A17, ADR-A28).

Back-of-Envelope Capacity Model

  1. Solid src-over fill rate ceiling (memory-bandwidth bound). §4: target ≥ 800 Mpix/s on 1 core. DDR4-3200 ~50 GB/s peak; L2/L3 bandwidth ~200 GB/s. Per pixel in src-over: 1 read (4 B dst) + 1 write (4 B dst) = 8 B/pixel. L2 bandwidth ceiling = 200 GB/s / 8 B = 25 Gpix/s; L3 = 50 GB/s / 8 B = 6.25 Gpix/s; DRAM = 6.25 Gpix/s. AVX2 compute: 8 px/iter × 1 blend iter ≈ 1–2 ns → ~4–8 Gpix/s compute-bound. Working set for a 1280×720 span row = 1280 × 4 B = 5 KB (fits L1 per scanline). Design consequence: 800 Mpix/s target is achievable with AVX2 SIMD at L1/L2 working-set sizes; DRAM-bound scenarios (large non-sequential blits) cap at ~1–2 Gpix/s. Confirmed by §4 constraint: SIMD width 256-bit (AVX2 opt-in).

  2. Edge-cell accumulation budget. §4: target ≥ 40 M edge-cells/s. §4 reference scene: 1280×720, ~2k paths, p50 frame < 4 ms. Worst-case edges per frame: assume each path averages 50 flattened edges → 100k edges. Cell touches per edge ≈ max(Δx, Δy) device pixels; for a 1280-wide path, average edge = 50 px → 50 cells. 100k edges × 50 cells = 5 M cell-ops/frame. At 40 M/s → 5M / 40M = 0.125 ms → well inside 4 ms budget. Design consequence: the 40 M edge-cells/s target gives ≥ 32× headroom over the reference scene; the bottleneck at 2k paths is the span-blend pass, not the raster accumulation.

  3. Cell grid memory per frame (sparse). §4: ≤ 16 bytes/touched-cell; ≤ 64 MB ceiling. §4 surface max: 32 767 px/axis. Worst-case fully-opaque surface 32k×32k = 1G pixels; if every pixel is touched (dense path): 1G × 16 B = 16 GB — exceeds ceiling. But §4 arena ceiling is 64 MB: 64 MB / 16 B = 4 M cells max per draw. 4 M cells corresponds to a 2000×2000 fully-dense fill or a long thin path. §4 states arena is reset between draws. Design consequence: the 64 MB arena ceiling bounds worst-case memory but implies that very large (32k-dimension) fully-covered scenes must be tiled; the tiled parallelism model (ADR-A17) is the required escape hatch.

  4. Wang's formula segment count for a cubic Bézier at default ε. §4: ε = 0.25 px device. Wang's formula for a cubic: N ≈ ceil( sqrt( 3/4 · max(|P0 − 2P1 + P2|, |P1 − 2P2 + P3|) / (8ε) ) ). For a unit-square cubic (second-difference magnitude ~1.0 px at 1:1 CTM): N = ceil( sqrt( 0.75 · 1.0 / 2.0 ) ) = ceil( sqrt(0.375) ) ≈ 1. At 100× zoom (CTM scale 100×): device-space second difference = 100 px, ε unchanged at 0.25 px → N = ceil( sqrt( 0.75 × 100 / 2.0 ) ) = ceil( sqrt(37.5) ) ≈ 7. Design consequence: segment count scales as ~√(CTM-scale), confirming P4 (device-space ε is resolution-correct); at extreme zoom (1000×) a single cubic emits ceil(sqrt(0.75·1000/2.0)) = ceil(19.36) = 20 segments, within the cell budget.

  5. Gradient fill rate with stop-LUT (no per-pixel binary search). §4: target ≥ 200 Mpix/s for gradient. Per pixel without LUT: binary search over 256 stops = ~8 comparisons = ~8 ns → 125 Mpix/s — below target. With a precomputed 1024-entry LUT: per pixel = 1 LUT load (~1 ns L1) + 1 lerp (~0.5 ns) = 1.5 ns → 667 Mpix/s. Two LUT loads (bilinear image): 4 × 1 ns + 3 lerps ≈ 7 ns → ~140 Mpix/s scalar; SIMD ×4 → ~560 Mpix/s, confirming ≥200 Mpix/s is achievable. Design consequence: the 256-stop binary-search path (§4 Max gradient stops = 256) must be replaced by a precomputed color LUT for all performance-critical paths (§18.7, Phase 6).

  6. SIMD lane utilization for AVX2 src-over. §4: SIMD width 256-bit (AVX2). RGBA8888 = 4 bytes/pixel; AVX2 = 32 bytes = 8 pixels/iteration. At 8 px/iter × ~3 cycles/iter (load + blend + store) at 3 GHz → 8 × 10^9 / 3 = ~8 Gpix/s theoretical; cache-bound floor ~2–4 Gpix/s. §4 target 800 Mpix/s = 20% of cache-bound floor → comfortable margin; margin is consumed by scalar tails, branch overhead, and mixed-paint spans. Design consequence: span coalescing (Phase 3 SpanEmitter) must produce spans ≥ 32 pixels (4 AVX2 iterations) to amortize scalar setup cost; short spans from tiny paths are the main fill-rate killer.

  7. p99 frame budget breakdown (1280×720, 2k paths). §4: p99 < 12 ms. Stages: (a) flatten 2k paths × 50 segments avg = 100k segments; at 100 ns/segment = 10 ms — too high. At ε=0.25 px with typical paths avg ~10 segments: 20k segments × 20 ns = 0.4 ms flatten. (b) Edge accumulation: 5 M cell-ops at 40 M/s = 0.125 ms. (c) Span blend: 1280×720 = 921k pixels at 800 Mpix/s = 1.15 ms. (d) Overhead (CTM, display-list replay, arena reset): ~0.5 ms. Total ≈ 2.2 ms p50, ≈ 4× outlier budget for p99 = ~8.8 ms — inside 12 ms target. Design consequence: flatten is the stage most sensitive to path complexity; the 16M verb cap (§4) prevents degenerate scenes from exceeding the p99 budget; SIMD matters most for the span-blend stage.

  8. Clip-mask AA memory per nested clip level. §4: Clip stack depth ≤ 128; surface max 32 767 px. Worst-case clip mask = 32 767 × 32 767 × 1 B (A8) ≈ 1 GB per level × 128 = 128 GB — clearly infeasible. §4 Arena ceiling 64 MB → 64 MB / 128 levels = 512 KB/level → 720×720 px/level. Design consequence: clip masks must be sized to the intersection of the clip bounds and the current surface clip, not the full surface; the monotonic-shrink invariant (I8) ensures each nested clip is never larger than its parent, keeping mask sizes bounded in practice.

  9. Display-list replay overhead per op. §4: ≤ 4 M ops/Picture. Enum dispatch per DrawOp: ~5 ns/op (branch + pointer). 4 M ops × 5 ns = 20 ms — exceeds frame budget alone. Practical mitigation: bounds culling (Phase 12) eliminates off-screen ops; 2k paths → 2k DrawOps × 5 ns = 10 µs dispatch overhead, negligible. Design consequence: the 4 M op cap (§4) is a DoS bound, not a perf-target; real scenes are 10–100k ops; bounds culling must be applied before replay to keep dispatch overhead sub-millisecond.

Wins when: the path set consists entirely of smooth, non-self-intersecting curves (glyphs, icons) that must render correctly at arbitrary scale; signed-distance fields are stored in a compact atlas and re-evaluated per-pixel by a GPU fragment shader at any resolution without re-tessellation; excellent for text rendering at large sizes. Embodied by: Slug (Eric Lengyel, JCGT 2017) for glyph rendering; Loop & Blinn (2005 SIGGRAPH) for GPU resolution-independent curves; multi-channel SDF (MSDF) font rendering. Why rejected here: analytic SDF/implicit evaluation requires the curve to be smooth and non-self-intersecting; arbitrary user paths (self-intersecting fills, EvenOdd rule, compound paths, clipping) are not representable as a single signed-distance field; the coverage formulation loses the fill-rule generality that the signed-area cell approach provides natively (ADR-A04, ADR-A06, Phase 4).
