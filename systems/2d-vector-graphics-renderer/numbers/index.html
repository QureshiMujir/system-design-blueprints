Back-of-Envelope Capacity Model

  1. Solid src-over fill rate ceiling (memory-bandwidth bound). §4: target ≥ 800 Mpix/s on 1 core. DDR4-3200 ~50 GB/s peak; L2/L3 bandwidth ~200 GB/s. Per pixel in src-over: 1 read (4 B dst) + 1 write (4 B dst) = 8 B/pixel. L2 bandwidth ceiling = 200 GB/s / 8 B = 25 Gpix/s; L3 = 50 GB/s / 8 B = 6.25 Gpix/s; DRAM = 6.25 Gpix/s. AVX2 compute: 8 px/iter × 1 blend iter ≈ 1–2 ns → ~4–8 Gpix/s compute-bound. Working set for a 1280×720 span row = 1280 × 4 B = 5 KB (fits L1 per scanline). Design consequence: 800 Mpix/s target is achievable with AVX2 SIMD at L1/L2 working-set sizes; DRAM-bound scenarios (large non-sequential blits) cap at ~1–2 Gpix/s. Confirmed by §4 constraint: SIMD width 256-bit (AVX2 opt-in).

  2. Edge-cell accumulation budget. §4: target ≥ 40 M edge-cells/s. §4 reference scene: 1280×720, ~2k paths, p50 frame < 4 ms. Worst-case edges per frame: assume each path averages 50 flattened edges → 100k edges. Cell touches per edge ≈ max(Δx, Δy) device pixels; for a 1280-wide path, average edge = 50 px → 50 cells. 100k edges × 50 cells = 5 M cell-ops/frame. At 40 M/s → 5M / 40M = 0.125 ms → well inside 4 ms budget. Design consequence: the 40 M edge-cells/s target gives ≥ 32× headroom over the reference scene; the bottleneck at 2k paths is the span-blend pass, not the raster accumulation.

  3. Cell grid memory per frame (sparse). §4: ≤ 16 bytes/touched-cell; ≤ 64 MB ceiling. §4 surface max: 32 767 px/axis. Worst-case fully-opaque surface 32k×32k = 1G pixels; if every pixel is touched (dense path): 1G × 16 B = 16 GB — exceeds ceiling. But §4 arena ceiling is 64 MB: 64 MB / 16 B = 4 M cells max per draw. 4 M cells corresponds to a 2000×2000 fully-dense fill or a long thin path. §4 states arena is reset between draws. Design consequence: the 64 MB arena ceiling bounds worst-case memory but implies that very large (32k-dimension) fully-covered scenes must be tiled; the tiled parallelism model (ADR-A17) is the required escape hatch.

  4. Wang's formula segment count for a cubic Bézier at default ε. §4: ε = 0.25 px device. Wang's formula for a cubic: N ≈ ceil( sqrt( 3/4 · max(|P0 − 2P1 + P2|, |P1 − 2P2 + P3|) / (8ε) ) ). For a unit-square cubic (second-difference magnitude ~1.0 px at 1:1 CTM): N = ceil( sqrt( 0.75 · 1.0 / 2.0 ) ) = ceil( sqrt(0.375) ) ≈ 1. At 100× zoom (CTM scale 100×): device-space second difference = 100 px, ε unchanged at 0.25 px → N = ceil( sqrt( 0.75 × 100 / 2.0 ) ) = ceil( sqrt(37.5) ) ≈ 7. Design consequence: segment count scales as ~√(CTM-scale), confirming P4 (device-space ε is resolution-correct); at extreme zoom (1000×) a single cubic emits ceil(sqrt(0.75·1000/2.0)) = ceil(19.36) = 20 segments, within the cell budget.

  5. Gradient fill rate with stop-LUT (no per-pixel binary search). §4: target ≥ 200 Mpix/s for gradient. Per pixel without LUT: binary search over 256 stops = ~8 comparisons = ~8 ns → 125 Mpix/s — below target. With a precomputed 1024-entry LUT: per pixel = 1 LUT load (~1 ns L1) + 1 lerp (~0.5 ns) = 1.5 ns → 667 Mpix/s. Two LUT loads (bilinear image): 4 × 1 ns + 3 lerps ≈ 7 ns → ~140 Mpix/s scalar; SIMD ×4 → ~560 Mpix/s, confirming ≥200 Mpix/s is achievable. Design consequence: the 256-stop binary-search path (§4 Max gradient stops = 256) must be replaced by a precomputed color LUT for all performance-critical paths (§18.7, Phase 6).

  6. SIMD lane utilization for AVX2 src-over. §4: SIMD width 256-bit (AVX2). RGBA8888 = 4 bytes/pixel; AVX2 = 32 bytes = 8 pixels/iteration. At 8 px/iter × ~3 cycles/iter (load + blend + store) at 3 GHz → 8 × 10^9 / 3 = ~8 Gpix/s theoretical; cache-bound floor ~2–4 Gpix/s. §4 target 800 Mpix/s = 20% of cache-bound floor → comfortable margin; margin is consumed by scalar tails, branch overhead, and mixed-paint spans. Design consequence: span coalescing (Phase 3 SpanEmitter) must produce spans ≥ 32 pixels (4 AVX2 iterations) to amortize scalar setup cost; short spans from tiny paths are the main fill-rate killer.

  7. p99 frame budget breakdown (1280×720, 2k paths). §4: p99 < 12 ms. Stages: (a) flatten 2k paths × 50 segments avg = 100k segments; at 100 ns/segment = 10 ms — too high. At ε=0.25 px with typical paths avg ~10 segments: 20k segments × 20 ns = 0.4 ms flatten. (b) Edge accumulation: 5 M cell-ops at 40 M/s = 0.125 ms. (c) Span blend: 1280×720 = 921k pixels at 800 Mpix/s = 1.15 ms. (d) Overhead (CTM, display-list replay, arena reset): ~0.5 ms. Total ≈ 2.2 ms p50, ≈ 4× outlier budget for p99 = ~8.8 ms — inside 12 ms target. Design consequence: flatten is the stage most sensitive to path complexity; the 16M verb cap (§4) prevents degenerate scenes from exceeding the p99 budget; SIMD matters most for the span-blend stage.

  8. Clip-mask AA memory per nested clip level. §4: Clip stack depth ≤ 128; surface max 32 767 px. Worst-case clip mask = 32 767 × 32 767 × 1 B (A8) ≈ 1 GB per level × 128 = 128 GB — clearly infeasible. §4 Arena ceiling 64 MB → 64 MB / 128 levels = 512 KB/level → 720×720 px/level. Design consequence: clip masks must be sized to the intersection of the clip bounds and the current surface clip, not the full surface; the monotonic-shrink invariant (I8) ensures each nested clip is never larger than its parent, keeping mask sizes bounded in practice.

  9. Display-list replay overhead per op. §4: ≤ 4 M ops/Picture. Enum dispatch per DrawOp: ~5 ns/op (branch + pointer). 4 M ops × 5 ns = 20 ms — exceeds frame budget alone. Practical mitigation: bounds culling (Phase 12) eliminates off-screen ops; 2k paths → 2k DrawOps × 5 ns = 10 µs dispatch overhead, negligible. Design consequence: the 4 M op cap (§4) is a DoS bound, not a perf-target; real scenes are 10–100k ops; bounds culling must be applied before replay to keep dispatch overhead sub-millisecond.
