Hard Questions (Self-Examination)

Each question requires synthesis of at least two sections. The § references name the sections where the answer lives.

HQ1. Why does the scheduler assume the pod on a node before the CAS bind succeeds, and what prevents this from causing a double-book when the bind conflicts? Requires: §8.3 (scheduling cycle sequence) + Phase 8 (assume/forget mechanics) + Domain Deep Dive §D.4 (assume as advisory, not authoritative).

HQ2. A pod with a required inter-pod anti-affinity selector that matches its own workload (e.g., label app=X must not co-locate with app=X) passes the predicate when it is the first replica. A second replica fails. A third replica arrives and needs the same node. Walk the exact predicate evaluation, identifying which snapshot data structures are consulted, what happens in PreFilter, and why the result is deterministic. Requires: Phase 4 (pod_affinity predicate + PreFilter amortization) + Phase 1 (snapshot cache, pods-by-node index) + §6 principle P6/I10.

HQ3. Two schedulers, A and B, both read the same snapshot showing node N with 1 CPU free. A schedules pod X (1 CPU) to N; B schedules pod Y (1 CPU) to N. Both call cas_bind concurrently. Walk the exact store interaction proving that exactly one pod ends up on N and the losing scheduler does not leave a phantom capacity reservation. Requires: Phase 8 (CAS commit, conflict rollback) + Domain Deep Dive §D.6 (worked race) + Phase 1 (cache/assume.rs forget) + §9 Tech Stack ADR Table (ADR-06).

HQ4. Derive the condition under which a preempting pod X (priority 1000) targeting node N is refused despite there being lower-priority pods on N, and explain exactly which invariant it protects. Requires: Phase 7 (victim selection + PDB check) + §7 System Invariants (I7) + §8.6 (preemption with PDB worked example).

HQ5. A tenant T submits pods at 10× the rate of tenant S. After 100 scheduling decisions, what is the expected dominant-share gap between T and S, and why can T not improve its position by understating its resource requests? HQ6. Under what exact conditions does the scheduling queue's move-request mechanism fail to wake a pod that has become schedulable, and what is the operational signal that detects this failure? HQ7. A gang of 10 pods (each requesting 2 CPU) has reserved capacity and is in the Permit-wait stage on a cluster with 20 CPU free. HQ8. The percentage-to-score cap samples a fraction of feasible nodes for scoring. HQ9. A standby replica becomes leader after a lease expiry. Its informer cache was last synced 800 ms ago (inside the §4 ≤ 1 s lag target). Mental Models & First Principles

MM1. The cache is a prediction, not a promise. An expert holds: every NodeInfo.free value is what the cluster looked like at RV=R, not what it looks like now. What it predicts: bind conflicts are structurally inevitable and must be handled gracefully, never suppressed. Bug class without it: treating the cache as authoritative → binding without CAS → silent double-booking (I1). Applied in: Phase 8 (optimistic async binder), Domain Deep Dive §D.1.

MM2. CAS is the serializer, not the scheduler. An expert holds: the linearizable compare-and-swap at the store is the only component that sees all writers simultaneously; the scheduler just submits proposals. What it predicts: even a buggy scheduler that tries to over-commit cannot permanently succeed — the store rejects the stale write. Bug class without it: routing any write through a blind Put, believing the scheduler's local check is sufficient. Applied in: Phase 8 (§8.4 store protocol, I5), Domain Deep Dive §D.2–§D.6.

MM3. Filter is a proof, Score is a ranking. An expert holds: a predicate's output is a boolean fact about feasibility; a score is a preference among already-proven-feasible nodes. What it predicts: encoding a hard constraint as a low score places the pod on an infeasible node when all scores are low. Bug class without it: "soft node-fit" expressed as score = −1000 instead of a filter → placement on an over-committed node when no other node scores high. Applied in: Phase 3 (node-fit predicate), Phase 5 (scoring architecture), §6 principle P4.

MM4. Backoff and event-driven re-activation are a feedback loop, not a retry loop. An expert holds: a pod parked Unschedulable should only re-enter the pipeline when the cluster event that caused its failure could have changed. Exponential backoff governs transient failures; move-requests govern structural ones. What it predicts: waking all parked pods on every event causes a thundering herd; a fixed-timer retry on an unsatisfiable pod hot-loops the CPU. Bug class without it: either of the two extremes. Applied in: Phase 2 (scheduling queue, queue/events.rs), §6 principle P5.

MM5. DRF is max-min fairness projected onto the dominant resource axis. An expert holds: in a multi-resource cluster, a tenant's "share" is the fraction of the single resource it uses most heavily; equalizing that share across tenants implements max-min fairness in a way that is Pareto-efficient and strategy-proof. What it predicts: a tenant cannot improve its allocation by misreporting its needs; the tenant with the lowest dominant share always gets the next slot under contention. Bug class without it: using a single-resource (CPU-only) fair-share → a memory-heavy tenant receives more than its fair share of both resources. Applied in: Phase 9 (DRF allocator, fairness/drf.rs), §8.7 DRF worked example, §6 principle P7.

MM6. Gang atomicity is two-phase commit without a coordinator. An expert holds: all-or-nothing placement for N pods is structurally a 2PC problem — reserve → vote yes/wait → commit-or-abort — where the Permit extension point is the vote gate and the reservation TTL is the abort timeout. What it predicts: incremental placement (no Permit gate) deadlocks when two gangs each hold half of what the other needs. Bug class without it: binding gang members one at a time → indefinite resource deadlock between competing gangs. Applied in: Phase 9 (place/gang.rs, ADR-15), §6 principle P8, §8.3 scheduling cycle sequence.

MM7. Assume is optimistic local accounting; forget is its rollback. An expert holds: assume is a temporary local debit to prevent the next scheduling cycle from double-picking the same node slot — it is advisory (I15), not authoritative. The informer's delivery of the real pod-add is the authoritative overwrite; forget is the rollback on conflict. What it predicts: a lost forget on conflict causes a phantom capacity leak that manifests as creeping false-Unschedulable, not a double-book. Bug class without it: leaving an orphan assume after a conflict → cache under-counts free capacity → pods park Unschedulable on a node that actually has room. Applied in: Phase 1 (cache/assume.rs), Phase 8 (conflict rollback), Domain Deep Dive §D.4.

MM8. Leader election + CAS form a defense-in-depth fence, not a single line. An expert holds: the lease TTL fences the old leader at the control level (it stops scheduling); the universal CAS fences it at the data level (the store rejects its stale write). Either defense alone is sufficient for correctness; together they prevent churn. What it predicts: a scheduler that checks the lease but skips the CAS still cannot double-book (the store rejects), but it may emit a noisy conflict; a scheduler that does CAS but not lease does not double-book but allows two concurrent schedulers to compete, wasting cycles. Bug class without it: relying solely on a runtime lease check without a CAS → any code path that bypasses the check double-books. Applied in: Phase 8 (bind guard), Phase 10 (leader election, I8), §6 principle P12, Domain Deep Dive §D.6.

MM9. The scheduling queue is a policy surface, not just a data structure. An expert holds: the three-band queue (active/backoff/unschedulable) encodes three distinct scheduling policies — urgency, back-pressure, and event-responsiveness — and the move-request mapping determines which policy governs a pod's re-entry. What it predicts: the wrong band assignment (e.g. re-activating Unschedulable pods via the backoff timer instead of cluster events) causes spurious retries and CPU waste. Bug class without it: conflating the backoffQ (transient failure → timer) with the unschedulableQ (structural impossibility → event) → hot-looping on impossible pods. Applied in: Phase 2 (three-band queue, queue/events.rs), §7 System Invariants (I3), §6 principle P5.

MM10. Determinism is an invariant, not a nice-to-have. An expert holds: a scheduling decision is a pure function of (cluster state, seed, plugin config); non-determinism in any of the 32 ADR choices is a latent bug that defers to production. What it predicts: nondeterministic placement means two scheduler replicas disagree, amplifying conflicts; nondeterministic tie-breaks make incidents unreproducible and differential tests flaky. Bug class without it: using hash-map iteration order or thread-local random in tie-breaking → a bug that appears once in 10,000 cycles and is unreproducible. Applied in: ADR-21, Phase 2 (queue tie-break), Phase 6 (deterministic parallel reduction), §7 System Invariants (I10), Phase 11 (replay harness).

Glossary · 60 terms · site-wide glossary

Scheduler
the control-plane component that assigns pending workloads (pods) to nodes.
Placement engine
the optimization layer choosing where (packing, spread, fairness) among feasible nodes.
Pod
the schedulable unit (one or more co-located containers); has resource requests, priority, affinity.
Node
a machine with allocatable capacity, labels, taints, and a topology location.
Binding
the durable (pod → node) assignment the scheduler commits to the store.
Allocatable
node capacity minus system/kube reservations and eviction thresholds; what the scheduler packs against.
Request vs limit
guaranteed reservation (drives scheduling) vs enforcement ceiling (kubelet/cgroup, not scheduled).
QoS class
Guaranteed / Burstable / BestEffort, derived from requests/limits; governs eviction/preemption order.
Overcommit ratio
a multiplier on allocatable trading utilization for pressure risk.
Extended resource
an opaque integer resource (GPU, custom device) beyond CPU/memory.
Predicate / Filter
a hard feasibility check (node-fit, taints, affinity, topology-spread, volume limits).
Priority / Score
a soft preference ranking feasible nodes (least/most-allocated, balanced, spread, image-locality).
Extension point
a fixed stage in the scheduling pipeline (PreFilter..PostBind) populated by plugins.
Plugin
a policy implementation on an extension point; the unit of scheduler extensibility.
CycleState
typed per-scheduling-cycle scratch state (e.g. PreFilter→Filter handoff).
Scheduling queue
the three-band (active/backoff/unschedulable) priority queue of pending pods.
Backoff
exponentially increasing delay before retrying a failed pod (anti-hot-loop).
Unschedulable
a pod that fits nowhere now, parked until a relevant cluster event.
Move-request
a signal that a cluster event may unblock specific parked pods (re-activates them).
Cluster event
a node add/update/delete, pod delete, quota/PDB change that could change scheduling outcomes.
Snapshot cache
the read-consistent in-memory projection of cluster state the scheduler reads each cycle.
NodeInfo
per-node aggregate: allocatable − committed = free, plus pods/images/topology.
Informer
the list→watch→resync client that keeps the cache eventually-consistent with the store.
List / Watch / Resync
seed the cache / stream deltas / periodically re-list to heal misses.
ResourceVersion (RV)
the store's monotonic per-object revision; the optimistic-concurrency token.
CAS (compare-and-swap)
a store Txn that commits only if the RV is unchanged; the conflict-detection primitive.
Assume
a local optimistic capacity deduction made before a bind confirms (advisory, not authoritative).
Forget
rolling back an assume when a bind conflicts.
Bind conflict
a CAS rejected because the snapshot was stale (the node/pod RV changed); normal, not an error.
Optimistic concurrency
read a snapshot, compute a transaction, detect conflicts at commit (the Omega model).
Shared-state scheduling
schedulers operating on a shared cluster state with transactional commits (Omega).
Two-level scheduling
a resource manager offering resources to framework schedulers (Mesos; rejected here).

Leader election

Lease

Split-brain

Fencing
preventing a stale leader from acting (lease expiry + CAS rejection).
Crash-only

Sharding

the cache converges to the store over time (the scheduler's view is always slightly stale).

the store's strong-consistency guarantee that makes CAS a sound conflict detector.
