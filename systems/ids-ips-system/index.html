Packet Capture ingests raw frames from an interface (AF_PACKET) or a deterministic PCAP replay source, timestamps them, and hands them to the decoder without copying payload bytes more than once (ADR-02).

Decoder (Eth / IP / TCP / UDP) parses link, network, and transport headers into canonical, bounds-checked structures; it is the first adversarial-input boundary and never panics on malformed input (I10).

IP Defragmenter reassembles IP fragments into complete datagrams using a host-OS-profile-selectable overlap policy (ADR-05), because a fixed policy is exactly what RFC 1858's fragment-overlap attack exploits.

Flow Table tracks per-five-tuple state (I5) so the reassembler, protocol parsers, and anomaly detector all share one canonical notion of "this connection."

TCP Reassembler + Traffic Normalizer sits at the evasion-normalization boundary: it reconstructs the byte stream and actively removes the ambiguities (overlapping segments, TTL games, insertion opportunities) that Ptacek & Newsham showed let an attacker's traffic look different to the sensor than to the target (I1, I9).

Protocol Parsers extract only the detection-relevant metadata from HTTP, DNS, and TLS handshakes (ClientHello/JA3), deliberately not implementing full protocol stacks (ADR-14).

Aho-Corasick Multi-Pattern Matcher scans the normalized, reassembled byte stream against every active signature's fixed-string content simultaneously, in one linear pass (Aho & Corasick 1975).

Rule Engine evaluates full rule predicates (header match plus content/PCRE options) against matcher hits and protocol metadata, producing a MatchResult.

Anomaly Detector maintains statistical baselines and entropy estimates per flow/feature and flags deviations that no signature covers (Denning 1987, Lakhina et al. 2005).

Alert Generator + Correlator turns raw matches and anomalies into Alert records and links related alerts into incidents without discarding the underlying evidence (I11).

IPS Enforcement (inline) applies the final verdict — drop, reset, or allow — atomically to the packet in flight (I2, I3); IDS tap path instead only ever emits alerts, with zero ability to affect the wire.

The reassembly/evasion problem. IP defragmentation and TCP reassembly are both instances of the same structural problem: multiple packets claim to describe the same byte range, and the sensor must decide which claim wins. Ptacek & Newsham (1998) showed the winning claim is only correct if it matches what the destination host's own stack would choose — and an attacker who knows (or guesses) the target's OS can send packets constructed so the sensor's answer and the target's answer differ. Named cases:

  • Overlap-insertion: attacker sends an overlapping fragment/segment containing benign-looking bytes at an offset the target will discard but the sensor accepts (or vice versa) — the sensor sees benign traffic, the target executes the attack (an "insertion") or the sensor sees an attack the target never receives (an "evasion").
  • TTL-based insertion: attacker sends a packet with a TTL just large enough to reach the sensor but not the target (or a spoofed intermediate hop); the sensor processes it, the target never does, desynchronizing the sensor's reassembled stream from reality.
  • Fragment-reordering ambiguity: overlapping IP fragments arriving out of send-order resolve differently under "first fragment wins" vs "last fragment wins" policies, and different OSes pick different defaults (RFC 1858).

Defense: traffic normalization (Handley, Paxson & Kreibich 2001) — rather than trying to guess the target's interpretation, the normalizer makes the traffic unambiguous before it reaches detection: it picks one canonical policy per configured host profile and rewrites (conceptually) the stream to that canonical form, so detection and the destination host are provably looking at the same bytes.

Worked evasion + normalization: attacker sends TCP segment A covering bytes [100,150) with a fragment of shellcode, followed by segment B covering [100,200) with entirely benign bytes overlapping A's range. A sensor configured "first-received-wins" keeps A's shellcode; a Windows target configured "last-received-wins" keeps B's benign bytes — the sensor alerts on nothing (evasion) even though, in the mirror case, it would insert phantom attacks the target never runs. The normalizer, told the target profile is Windows-last-wins, discards A's overlapping range in favor of B before signature matching runs, guaranteeing the matcher only ever sees what the Windows target will actually execute.

Aho-Corasick multi-pattern matcher. A finite automaton built once from the full pattern set (goto function, failure function, output function), then traversed once per byte of input regardless of pattern count.

State machine sketch for patterns {"he", "she", "his", "hers"}: the trie has root -> h -> e (output "he") and root -> s -> h -> e (output "she"), with failure links from the "she" branch's h back to root's h and from e (end of "she") back to the e after root's h (catching "he" as a suffix). Worked match: input "ushers" — at position 2 ('s') no match; position 3 ('h') advances the s-h-e branch; position 4 ('e') emits "she" AND, via the failure link, also emits "he"; position 5 ('r') follows "she"'s goto extension toward "hers"; position 6... (end of input) — total matches found in one linear pass: {"she","he"} plus, on a longer input containing "...hers", "hers" too, all without re-scanning.

Rule language (Snort/Suricata-like) EBNF.

rule        = action, protocol, src_ip, src_port, direction,
              dst_ip, dst_port, "(", option_list, ")" ;
action      = "alert" | "drop" | "reject" | "pass" ;
protocol    = "tcp" | "udp" | "icmp" | "ip" | "http" | "dns" | "tls" ;
direction   = "->" | "<>" ;
option_list = option, { ";", option } ;
option      = msg_opt | content_opt | pcre_opt | flow_opt | sid_opt | rev_opt ;
msg_opt     = "msg", ":", string ;
content_opt = "content", ":", string, [ modifier ] ;
modifier    = "nocase" | "depth", ":", integer | "offset", ":", integer ;
pcre_opt    = "pcre", ":", regex_literal ;
flow_opt    = "flow", ":", flow_state ;
flow_state  = "established" | "to_server" | "to_client" ;
sid_opt     = "sid", ":", integer ;
rev_opt     = "rev", ":", integer ;

Worked rule: alert tcp any any -> 10.0.0.0/8 443 (msg:"Suspicious JA3 fingerprint"; tls.ja3_hash:"e7d705a3286e19ea42f587b344ee6865"; flow:established,to_server; sid:1001001; rev:1;). Worked match: a TCP flow from any source to 10.0.0.7:443, established, whose TLS ClientHello (parsed in Phase 4, fingerprinted in Phase 10) hashes to the listed JA3 value fires this rule and emits an Alert with sid=1001001.

Anomaly-detection model. Baseline: for a feature x (e.g. bytes/second per flow, distinct-destination-ports per source), maintain rolling mean μ and variance σ² over the configured window (I7); flag x where |x - μ| > k·σ for a tuned k. Entropy of a feature distribution p over n bins: H(p) = -Σ p_i · log2(p_i) for i in 1..n — a sudden entropy drop in destination-port distribution (many flows suddenly concentrating on one port) is a classic scan/flood signature (Lakhina et al. 2005); a sudden entropy rise in an otherwise-stable field can indicate randomized/obfuscated payloads. Base-rate fallacy: if true attacks are 1 in 10,000 connections and the detector is 99% accurate (1% false-positive, 1% false-negative), then out of 10,000 connections the detector flags roughly ~100 false positives against only ~1 true positive — a >99% chance any given alert is noise, which is exactly the failure mode Sommer & Paxson (2010) warn ML-IDS papers routinely ignore by reporting accuracy instead of precision at realistic base rates.

Flow/stream state machine (five-tuple flow, TCP): CLOSED -[SYN]-> SYN_SENT -[SYN/ACK]-> ESTABLISHING -[ACK]-> ESTABLISHED -[FIN]-> CLOSING -[FIN/ACK]-> CLOSED; alternate edge ESTABLISHED -[RST]-> CLOSED (abort); error edges: SYN_SENT -[timeout]-> CLOSED (half-open reaped), ESTABLISHING -[unexpected seq]-> ANOMALOUS (flagged, not silently accepted), ESTABLISHED -[data after FIN]-> ANOMALOUS (possible desync/evasion attempt, routed to the normalizer's overlap-policy logic).

IPS enforcement decision table.

Match Result Rule Action Flow State Verdict Rationale
signature hit drop established Drop known-bad payload, connection live
signature hit reject established Reset terminate cleanly, inform both ends
signature hit alert any Allow + Alert IDS-mode-equivalent action even inline
no match n/a any Allow default permit
anomaly over threshold, no signature policy-configured any Alert, Drop only if policy escalates anomalies to enforcement anomalies alone rarely warrant auto-block (P3)
parser fault / malformed packet policy-configured any Drop or Allow per fail-open/fail-closed config availability-vs-security tradeoff (P12)

Alert correlation groups alerts sharing a flow, source, or time-window and a plausible kill-chain relationship (e.g. a port-scan alert followed by an exploit-signature alert from the same source within minutes) into one Incident, always retaining links to every constituent Alert (I11).

Packet/flow lifecycle state machine with failure edges: Captured -> Decoded -[malformed]-> Rejected(counted); Decoded -> Defragmented -[buffer bound exceeded]-> Evicted(anomaly-flagged); Defragmented -> Reassembled -[normalizer policy conflict]-> Anomalous(flagged, best-effort continue); Reassembled -> Parsed -[parser fault]-> MetadataOnly(I10 fallback); Parsed -> Matched -> Verdicted -[enforcement fault]-> FailPolicy(fail-open|fail-closed, ADR-03); Verdicted -> Alerted -> Correlated.

Malformed/hard examples. (1) Fragmented-overlap evasion: shellcode split across overlapping IP fragments so no single fragment's payload matches any signature, resolved only by correct defrag policy (Phase 2, Phase 3). (2) TTL-based insertion: a phantom packet the sensor accepts but the target's router-hop-count never lets arrive, corrupting the sensor's stream view. (3) Rule false-positive: a legitimate software update matching a byte pattern coincidentally shared with a signature's content option — resolved by adding a pcre context constraint. (4) Encrypted-traffic blind spot: a TLS-wrapped exploit payload is invisible to content matching; only JA3/metadata-level detection applies (Phase 10). (5) Flow-table exhaustion attack: an attacker opens millions of half-open connections to exhaust flow-table memory, mitigated by I6's bounds and eviction. (6) Polymorphic payload defeating signatures: functionally identical shellcode re-encoded per-instance so no fixed-string signature matches — this is precisely the class of attack anomaly detection (Phase 7) exists to catch where signatures cannot.

Failure-path example: a crafted PCAP delivers overlapping TCP segments faster than the reassembly bound can flush; the reassembler hits its per-flow byte ceiling (I6), evicts the oldest incomplete stream, marks the flow Anomalous, and emits reassembly_bytes_buffered telemetry — the operator sees a spike, not a silent gap, and the evicted flow's partial data is retained for forensic review rather than discarded.
