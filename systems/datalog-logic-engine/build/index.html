✅ Phase 4 — Program Model + Stratification

Objectives
  • Classify every predicate as EDB or IDB from loaded rules and facts.
  • Build the predicate dependency graph (PDG) with labeled positive/negative/aggregate edges.
  • Compute stratification via SCC condensation; assign each predicate a stratum index.
  • Detect and reject any program with a cycle through a negative or aggregate edge (not stratifiable).
  • Expose Program with strata: Vec<Vec<PredId>> consumed by dl-eval in Phase 5.
  • Enforce I4 (stratification well-formedness): reject PDG cycles through a negative/aggregate edge.
  • Program::from_ast is the single public constructor consumed by all downstream crates.
Deliverable
  • dl-program compiles; Program::from_ast returns Ok(Program) on all valid fixtures.
  • StratificationError for non-stratifiable programs, cycle predicate names resolved via interner.
  • Program.strata ordering verified by fixture diff against hand-computed reference.
  • dl-eval consumes program.strata and program.rules_by_stratum (Phase 5).
  • dl-cli stratify <file> prints stratum assignments in human-readable form.
  • DependencyGraph accessible via program.dependency_graph() for inspection tools.
  • Post-stratification validator confirms no rule violates stratum ordering before Ok(Program).
  • All error variants have Display impls with predicate names resolved through Interner.
Acceptance
  • All 12 stratification fixtures classify/stratify correctly (see 4.5).
  • Negative-cycle fixtures rejected with StratificationError; message includes cycle predicate names.
  • Stratum count and membership match hand-computed reference per fixture (snapshot-tested).
  • cargo test -p dl-program passes; zero panics; zero unwrap calls.
  • Stratification runtime < 10 ms for 1,000-predicate / 5,000-rule synthetic program (benched).
  • ArityConflict returned for arity_mismatch.dl fixture.

✅ Phase 5 — Naive Bottom-Up Evaluation

Objectives
  • NaiveEvaluator in dl-eval: reference correctness baseline for diff-testing.
  • Per stratum (ascending), iterate all stratum rules until no new tuple is added (least-fixpoint).
  • Guarantee termination for all safe, function-symbol-free programs via the finite-domain argument.
  • Produce the complete minimal model: all IDB relations populated; EDB unchanged.
  • Oracle for diff-testing Phase 7 (semi-naive) and future Phase 11 (magic sets).
  • Validate I1 (minimal-model correctness), I2 (set semantics), I6 (termination).
Deliverable
  • NaiveEvaluator::run returns Ok(Model) for all canonical programs in fixtures.
  • Transitive closure, ancestor, same-generation, negation-filter programs produce correct models.

  • CLI: dl-cli run --naive <file> invokes this evaluator, prints derived tuples per predicate.
  • NaiveEvaluator::run_with_trace records per-rule per-round derivation counts (emitted to tracing); Model::tuple_count() accessible for benchmarks/monitoring.
  • Model implements Eq (set equality per relation) for diff-testing against semi-naive (Phase 7); dl-eval/benches/naive_eval.rs benchmarks TC/ancestor programs, baseline in benches/baselines.txt.

⬜ Phase 8 — Stratified Negation

Objectives
  • Implement negation-as-failure (NAF) in dl-negation as a closed-world check against a fully-computed lower-stratum relation.

  • Adornment explosion: a predicate with arity 4 has 16 possible adornments; worklist can grow quadratically. Cap at 64 adornments per predicate; warn and fall back.
