Decisions (§9) · 30 ADRs

ADR-01

Implementation language

Chosen

Rust (stable toolchain)

Rejected

C++, Haskell, OCaml, Java

When the rejected choice is right

C++ when compiling rules to native for maximum throughput (Soufflé-style); Haskell/OCaml for a research prototype valuing algebraic expressiveness over runtime speed

Why: Memory safety without GC; zero-cost abstractions for tight join loops; strong type system encodes invariants; no runtime overhead

ADR-02

Build system

Chosen

Cargo workspace (single workspace, 12 crates)

Rejected

Bazel, Buck, CMake

When the rejected choice is right

Bazel in a large polyglot monorepo needing remote build caching across languages

Why: Native Rust; per-crate dependency isolation; cargo test --workspace for uniform CI; no build-system integration overhead

ADR-03

Crate dependency policy

Chosen

Each crate depends only on crates listed in the spine; no transitive surprise crates; deny(warnings) in all crates

Rejected

Monolithic single crate

When the rejected choice is right

A single crate for a small tool where strict layering overhead isn't worth the friction

Why: Enforces layering; prevents dl-core from depending on I/O; enables independent testing per crate

ADR-04

External dependency policy

Chosen

Minimal pinned set: hashbrown, petgraph, logos, chumsky or pest, criterion, proptest, serde (optional CLI), clap; no ORM, no async runtime

Rejected

Pulling in large framework crates

When the rejected choice is right

A batteries-included framework when rapid prototyping outranks compile time and supply-chain surface

Why: Keeps compile times low; avoids hidden transitive CVEs; each dep serves one clear purpose

ADR-05

Symbol / interner storage

Chosen

hashbrown::HashMap<Arc<str>, Sym> + Vec<Arc<str>> (append-only)

Rejected

string-interner crate, global static interner

When the rejected choice is right

The string-interner crate when a battle-tested interner suffices and custom ownership isn't needed; a global static for a simple single-threaded tool

Why: Explicit ownership; no global mutable state; easily passed through call chain; testable in isolation

ADR-06

Relation core storage

Chosen

hashbrown::HashSet<Tuple> (set semantics, O(1) membership)

Rejected

BTreeSet (ordered), columnar storage, arena-of-sorted-vecs

When the rejected choice is right

Columnar storage when scans/aggregation over huge relations dominate (analytics); BTreeSet when ordered iteration or range scans are needed

Why: Dedup is the core invariant; hash-set membership test is the most frequent operation; ordering not required for correctness

ADR-07

Index structure

Chosen

HashMap<Vec<Sym>, Vec<Tuple>> keyed on bound-position values; built lazily per join

Rejected

B-tree range index, trie, sorted array binary search

When the rejected choice is right

A B-tree/trie when prefix or range lookups matter (datalog± with comparison/arithmetic literals)

Why: Join key lookups are equality-only (Datalog has no range-scan in base join); lazy construction avoids building unused indexes

ADR-08

Tuple representation

Chosen

Vec<Sym> (heap-allocated, variable arity)

Rejected

Fixed-size arrays, SmallVec, arena allocation

When the rejected choice is right

SmallVec/fixed arrays when arity is small and known, to eliminate per-tuple heap allocation on the hot path

Why: Simplicity; arity known only at runtime; SmallVec can be adopted later as an optimization in Phase 14

ADR-09

Parser library

Chosen

logos (lexer) + chumsky (combinator parser)

Rejected

pest (PEG grammar file), nom, hand-written recursive descent

When the rejected choice is right

pest when a declarative PEG grammar file is preferred for maintainability; hand-written RD for ultimate control over error messages

Why: logos zero-copy lexing; chumsky gives typed error recovery and good error messages; both are pure Rust with no codegen step

ADR-10

Dependency graph library

Chosen

petgraph (DiGraph, SCC via Tarjan/Kosaraju)

Rejected

Custom adjacency list, daggy

When the rejected choice is right

A custom adjacency list when you want zero deps and only need one SCC pass

Why: Provides SCC algorithm needed for stratification out of the box; well-maintained; used only in dl-program

ADR-11

Evaluation strategy

Chosen

Semi-naive bottom-up (default); naive as reference/diff-test target

Rejected

Top-down SLD resolution, tabling, magic-sets-only

When the rejected choice is right

Top-down tabling for highly selective queries that touch a small fraction of the model, where bottom-up over-derives

Why: Semi-naive is the standard efficient Datalog evaluation strategy (P5); naive retained for correctness cross-checking (I5)

ADR-12

Negation model

Chosen

Stratified negation-as-failure (closed-world)

Rejected

Well-founded semantics, stable model semantics, 3-valued logic

When the rejected choice is right

WFS/stable-model semantics when programs have negation through cycles (non-stratifiable) that must still carry a defined meaning

Why: Stratified NAF is decidable, well-understood, and sufficient for the target workloads; WFS/stable models add significant complexity

ADR-13

Aggregation model

Chosen

Stratified per-stratum grouped aggregates (count/sum/min/max)

Rejected

Recursive aggregation, bag semantics, lattice-based aggregation

When the rejected choice is right

Lattice-based aggregation (Flix) when recursive aggregation is needed — e.g. shortest-path as a fixpoint over a semiring

Why: Stratified aggregation is decidable and sound; lattice-based (Flix-style) deferred to future extension

ADR-14

Join ordering

Chosen

Cost-based: selectivity estimated from relation sizes; most-bound-first heuristic; reorder once per rule at eval start

Rejected

Exhaustive dynamic programming, query-graph min-cut, no ordering

When the rejected choice is right

Full DP join ordering when bodies are large and a bad greedy choice triggers a cartesian-product blow-up (complex analytic queries)

Why: Simple greedy heuristic avoids worst-case cartesian products; full DP deferred to Phase 14 if benchmarks show need

ADR-15

Magic-sets transform

Chosen

Optional, query-driven; applied at query time per adornment; falls back to full eval for fully-free queries

Rejected

Always-on magic sets, OLDT tabling, demand-driven tabling

When the rejected choice is right

Always-on magic-sets when every query is bound-heavy and the rewrite always pays; OLDT tabling when top-down is the base engine

Why: Layered optimization (P7); does not affect correctness (I9); adds complexity so must be optional and skippable

ADR-16

Concurrency model

Chosen

Single-threaded evaluation (no async, no rayon in Phases 1-13); Phase 14 evaluates rayon parallelism for stratum-level

Rejected

Async Tokio, actor model, parallel semi-naive from Phase 1

When the rejected choice is right

Parallel semi-naive when relations are huge and stratum-level parallelism yields near-linear speedup on multicore

Why: Correctness first; parallel semi-naive requires careful delta-merge synchronization; defer until model is validated

ADR-17

Serialization format (facts I/O)

Chosen

Tab-separated values (TSV) for .input/.output; optional JSON via serde_json behind feature flag

Rejected

CSV with quoting, Protobuf, custom binary

When the rejected choice is right

Protobuf/binary when fact volumes are huge and parse time dominates load (the §4 parse budget is the bottleneck)

Why: TSV matches Souffle's default; trivially parseable; no quoting ambiguity for simple Sym values; binary format deferred

ADR-18

Wire/IPC format (REPL)

Chosen

Line-oriented text protocol over stdin/stdout; no network socket in Phase 1-13

Rejected

gRPC, REST API, Unix socket

When the rejected choice is right

gRPC/REST when the engine is a shared service queried by many remote clients

Why: Simplest possible interface for a single-process tool; network API deferred to post-blueprint extension

ADR-19

Logging

Chosen

tracing crate with tracing-subscriber (structured, spans for stratum/round)

Rejected

log crate, slog, env_logger

When the rejected choice is right

The log facade when consumers prefer a simpler backend and per-stratum spans add no value

Why: tracing spans capture per-stratum evaluation cost automatically; structured fields enable post-hoc analysis

ADR-20

Metrics / observability

Chosen

tracing counter/gauge macros for tuple counts, round counts, join probes; no external metrics push in Phase 1-13

Rejected

Prometheus client, statsd, OpenTelemetry

When the rejected choice is right

Prometheus/OpenTelemetry when the engine runs as a long-lived service needing live dashboards

Why: Inline instrumentation sufficient; external push adds deployment complexity outside scope

ADR-21

Unit + integration testing

Chosen

cargo test (unit per crate); integration tests in dl-cli/tests/ loading .dl fixture files and comparing output

Rejected

pytest, external test harness, Bazel test

When the rejected choice is right

An external harness when conformance must run cross-language against a reference engine (e.g. comparing to Soufflé)

Why: Native Rust test framework; fixture-driven tests are easy to add and review; matches Souffle's test style

ADR-22

Property-based / fuzz testing

Chosen

proptest for semi-naive==naive equivalence on generated programs; cargo-fuzz (libFuzzer) targeting parser and join engine

Rejected

QuickCheck, AFL, Honggfuzz

When the rejected choice is right

AFL/honggfuzz for whole-binary, coverage-guided fuzzing of the CLI with complex file inputs

Why: proptest integrates with cargo test; cargo-fuzz is the standard Rust fuzzing interface; both catch distinct bug classes

ADR-23

Benchmarking

Chosen

criterion (statistical, wall-clock); benchmarks for transitive closure (10K/100K edges), join probe rate, stratification cost

Rejected

divan, manual timing, perf stat

When the rejected choice is right

divan for nanosecond micro-benchmarks where criterion's statistical machinery dominates the measurement

Why: criterion provides statistical rigor and regression detection; benchmarks run in CI on a pinned runner to catch regressions

ADR-24

CI/CD pipeline

Chosen

GitHub Actions: cargo build --workspace, cargo test --workspace, cargo clippy -- -D warnings, cargo fmt --check, fuzz for 60s, criterion smoke

Rejected

Jenkins, CircleCI, self-hosted only

When the rejected choice is right

Self-hosted CI for private repos needing custom hardware or air-gapped builds

Why: Standard open-source CI; clippy + fmt enforced; fuzz smoke catches parser regressions early

ADR-25

Packaging

Chosen

cargo install dl-cli; published crates on crates.io (dl-core through dl-cli); single binary dl

Rejected

Nix flake, Homebrew, Docker-only

When the rejected choice is right

Nix/Homebrew when targeting users who manage tooling through those package managers; Docker-only for a reproducible service deployment

Why: cargo install is the simplest distribution for a CLI tool; library crates published for downstream use (e.g., as Datalog backend)

ADR-26

Container / reproducibility

Chosen

Dockerfile (FROM rust:stable, multi-stage, final FROM debian:slim); Cargo.lock committed; --locked flag in Docker build

Rejected

Alpine (musl link issues), Nix

When the rejected choice is right

Alpine when minimal image size outweighs musl link friction; Nix for fully hermetic, bit-reproducible builds across hosts

Why: Committed Cargo.lock + --locked guarantees byte-for-byte reproducible builds; slim final image for deployment

ADR-27

License

Chosen

MIT OR Apache-2.0 (dual license, Rust ecosystem standard)

Rejected

GPL, LGPL, proprietary

When the rejected choice is right

GPL/LGPL when copyleft reciprocity is the goal (preventing closed-source forks)

Why: Maximizes downstream reuse; compatible with all dependencies used; standard for Rust infrastructure libraries

ADR-28

Error handling

Chosen

thiserror-derived error enums per crate; crate-boundary Result<T, E> with typed variants; no unwrap in library code

Rejected

anyhow (type-erased), failure, panics

When the rejected choice is right

anyhow in the binary crates where error kinds are never matched and a single error type simplifies the code

Why: Typed errors enforce that callers handle each variant explicitly; thiserror reduces boilerplate; anyhow acceptable in dl-cli / dl-repl binary crates only

ADR-29

MSRV policy

Chosen

Rust stable, current minus 2 releases; specified in rust-version field in each Cargo.toml; CI tests on MSRV and latest stable

Rejected

Nightly-only features, fixed ancient MSRV

When the rejected choice is right

Nightly when an unstable feature is essential; a fixed ancient MSRV when supporting very conservative enterprise downstreams

Why: Avoids nightly instability; -2 gives downstream time to upgrade; current stable features (TAIT, GATs) available as needed

Alternative Architectures (Roads Not Taken)

A1 — Top-down SLD resolution with tabling (memoized Prolog-style).

Show the original text diagram
query goal → resolve against rule heads → table sub-goals → reuse memoized answers

Wins for queries touching a small fraction of the model (highly selective goals) where bottom-up over-derives. Embodied by XSB / tabled Prolog. Rejected because bottom-up semi-naive is simpler to make complete and the target workloads materialize most of the IDB; magic-sets recovers demand-driven behavior without a second engine (Phase 11).

A2 — Incremental dataflow (differential dataflow).

Show the original text diagram
inputs as collections → arranged operators → only deltas propagate downstream

Wins for continuously-changing inputs where only deltas should recompute (reactive/streaming). Embodied by Differential Datalog / timely. Rejected for v1 because batch evaluation (§4) targets load-once-query workloads; full incremental view maintenance is deferred (Register).

A3 — Compile-to-native (rule program → specialized C++/LLVM).

Show the original text diagram
.dl program → codegen → specialized relation containers + loops → native binary

Wins for huge static analyses run repeatedly where compile-once amortizes. Embodied by Soufflé. Rejected because an interpreter gives REPL interactivity and faster iteration (Phase 13), and the §4 sizes (≤ 10M facts, < 2 s TC) fit an interpreter comfortably.

A4 — Worst-case-optimal join over sorted columns (Leapfrog Triejoin).

Show the original text diagram
relations as sorted tries → multi-way variable-at-a-time join → WCOJ bound

Wins for cyclic/many-way joins where binary-join plans explode (graph-pattern queries). Embodied by LogicBlox / Soufflé's Brie. Rejected for v1 simplicity; hash-join with most-bound-first ordering suffices for ≤ 12-literal bodies (§4), with WCOJ a Phase-14 option.
