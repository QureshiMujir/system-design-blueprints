33. Mental Models & First Principles

  1. MM1 — A CAS is a conversation, not a command. It says "if the world still looks like X, make it Y" — every algorithm is a sequence of such conditional conversations, not imperative steps. Predicts: why retry loops exist at all. Bug class without it: treating a CAS like an unconditional store. Applied in §8.2, §8.3.
  2. MM2 — Acquire/Release is a relay baton, not a lock. A Release store hands off a baton; an Acquire load picks it up — nothing is held in between. Predicts: why two threads can each hold "half" a synchronisation without blocking. Bug class without it: assuming Acquire/Release provides mutual exclusion. Applied in §8.1.
  3. MM3 — Reclamation is deferred destruction, not deferred allocation. The hard part was never "when to free," it's "how do I know no one is still looking." Predicts: why hazard pointers/epochs exist instead of just Arc. Bug class without it: reaching for reference counting and being surprised by its own contention (I5). Applied in §8.5, §15.
  4. MM4 — ABA is a proxy-identity bug, not a value bug. The CAS checks an address, but the programmer's mental model checks a meaning — the two diverge exactly when memory is reused. Predicts: why tagging or hazard-protection (not "checking the value again") is the fix. Bug class without it: adding a redundant re-read that doesn't actually help. Applied in §8.2, I4.
  5. MM5 — Lock-free is a system property, not a per-thread one. "Some thread progresses" says nothing about which thread — a starved thread under lock-freedom is not a bug. Predicts: why wait-freedom is a strictly stronger, separately-earned guarantee (I2, I3). Bug class without it: promising individual-thread latency bounds a lock-free design cannot give. Applied in §7, §20.
  6. MM6 — Helping is how "lock-free" survives preemption. Any thread preempted mid-operation must be completable by someone else, or the guarantee is fiction. Predicts: every lock-free algorithm with more than one CAS site needs a helping mechanism. Bug class without it: shipping an algorithm that is lock-free only when nothing gets preempted (§8.4, §8.6). Applied in §14.2, §20.2.
  7. MM7 — The memory model is the actual hardware contract; the language spec is a promise about it. x86's TSO is not "what C++ requires," it's a stronger guarantee the spec permits weakening — code correct only by TSO's extra strength is latent aarch64/ Power breakage. Predicts: why cross-architecture CI, not code review, is the real gate. Bug class without it: "it works on my machine" as a correctness argument. Applied in §8.1, §22.
  8. MM8 — Linearisability is a real-time constraint on a logical-time property. The operations can be reordered onto any legal sequential timeline, but that timeline must respect wall-clock non-overlap — it's not "eventually consistent," it's "consistent at every instant, from some valid vantage point." Predicts: why the oracle needs start/end timestamps, not just op order. Bug class without it: confusing linearisability with serialisability (no real-time constraint) or sequential consistency (no per-op real-time constraint either). Applied in §8, §21.3.

Reference Implementations

  • crossbeam-rs/crossbeam (crossbeam-epoch/, crossbeam-queue/, crossbeam-deque/) — epoch reclamation, MPMC queues, work-stealing. Lesson: the Guard-scoped pin API. Pitfall not to copy: crossbeam's global default collector complicates test isolation (ADR-22). Applied in §15, §17, §34.
  • facebook/folly (folly/concurrency/, folly/synchronization/, folly/AtomicHashMap.h) — production C++ lock-free primitives at hyperscale. Lesson: the AtomicHashMap open-addressing tradeoffs. Pitfall: unsafe-by-convention with no compiler-checked thread-safety marker (ADR-01). Applied in §34.
  • OpenJDK java.util.concurrent (ConcurrentLinkedQueue.java, ConcurrentHashMap.java, ConcurrentSkipListMap.java) — the JMM-targeted reference designs. Lesson: JMM happens-before framing maps directly to our synchronises-with proofs. Pitfall: JIT-dependent codegen defeats our assembly-diff technique (§1 language-rejection rationale). Applied in §19, §20, §34.
  • tokio-rs/loom — exhaustive interleaving model checker for Rust. Lesson: cfg(loom) parameterisation over std::sync. Pitfall: state-space explosion past TC 3 (§21.8). Applied in §21.
  • awslabs/shuttle — randomised interleaving checker (PCT scheduler). Lesson: seed-based reproducibility. Applied in §21.
  • khizmax/libcds — the C++ concurrent-data-structures library with the widest algorithm coverage (hazard pointers, multiple hash-map variants). Lesson: its reclamation-scheme-as-template-parameter design is the direct ancestor of our Guard trait (P2). Pitfall: template-based API surfaces the reclamation scheme in every type name, hurting ergonomics — we hide it behind a default type parameter instead. Applied in §11, §34.

RFCs / Specifications

  • ISO/IEC 14882:2020, clause 6.9 / [intro.races], [atomics] — the C++20 memory model our named orderings target. Applied in §8.1.
  • Linux Kernel Memory Consistency Model (LKMM), tools/memory-model/Documentation/ — the practical portable-subset model. Applied in §8.1, §22.
  • ARM — ARM Architecture Reference Manual, ARMv8-A, ch. B2. Applied in §22.
  • RISC-V Weak Memory Ordering (RVWMO) specification. Applied in §22 (forward-looking target architecture).

Glossary (§39) · 48 terms · site-wide glossary

ABA problem
A CAS succeeds because the observed value is unchanged by address, even though the underlying state changed and was recycled in between (§8.2).
Acquire
A memory ordering: no later memory access reorders before this load (§8.1).
ADR
Architectural Decision Record — a locked choice plus its rejected alternatives (§9).
AcqRel
Acquire-Release combined; used on a successful read-modify-write (§8.1).
Backoff
A progression of waits (spin → yield → sleep) used in a contended CAS loop (P9).
Bucket array
The index structure over a split-ordered list mapping hash prefixes to sentinel positions (§19.2).
CAS
Compare-and-swap — the canonical lock-free read-modify-write primitive (§8.2).
Cache-line padding
Layout technique preventing two hot fields from sharing a coherence unit (I11).
Chase–Lev deque
The 2005 growable circular-buffer work-stealing algorithm (§17).
Conformance bucket
A named pass-rate commitment (e.g. linearisability, ABA) gated in CI (§23.4).
DWCAS
Double-width CAS — CAS on 128 bits, x86-only as a single instruction (ADR-15).
EBR
Epoch-based reclamation (§15.2).
Fence
A memory barrier ordering accesses on either side of it (§8.1).
Guard
The reclamation handle returned while a thread observes shared memory (§11).
Hazard pointer
A per-thread slot announcing a pointer about to be dereferenced, preventing its reclamation while announced (§15.1).
Helping
A technique where one thread completes another's pending or partially-done operation (§8.4, §20.2).
Herd7
A memory-model litmus-test checker used for cross-architecture validation (§22.2).
Kogan–Petrank queue
The 2011 wait-free MPMC queue via announce-and-help (§20.2).
Linearisability
A correctness condition: every operation appears to take effect atomically at one point in real time (I1, Herlihy & Wing 1990).
Lock-freedom
A progress guarantee: system-wide, some thread completes in bounded steps (I2).
Loom
An exhaustive interleaving model checker for Rust concurrency (§21.2).
LL/SC
Load-linked/store-conditional — the RISC alternative CAS implementation strategy (§8.2).
Marked pointer
A pointer with a low bit repurposed to signal logical deletion (§18.2).
Michael–Scott queue
The 1996 unbounded MPMC lock-free queue (§14.2).
MPMC
Multi-producer multi-consumer.
Node
A heap-allocated element of a linked structure, retired (not freed directly) on removal (§11).
Obstruction-freedom
A progress guarantee weaker than lock-freedom: a thread running alone completes in bounded steps (referenced, §7 context).
PCT scheduler
Probabilistic Concurrency Testing — shuttle's bias toward unlikely interleavings (§21.2).
QSBR
Quiescent-state-based reclamation (§15.3).
Reclamation domain
A value-type context owning a reclamation scheme's global state (P12).
Release
A memory ordering: no earlier memory access reorders after this store (§8.1).
Retire
Marking a node as logically removed but not yet physically freed, pending reclamation-scheme clearance (§11).
SeqCst
Sequentially consistent — the strongest ordering, total order across all SeqCst operations (§8.1).
Shalev–Shavit split-ordered list
The 2006 lock-free extensible hash-table design (§19).
Shuttle
A randomised interleaving checker for Rust concurrency, using PCT/random/DFS schedulers (§21.2).
Skip list
A probabilistically-balanced multi-level ordered structure (§20.2).
Slot
A per-thread hazard-pointer announcement cell (§15.1).
Spurious failure
A compare_exchange_weak failure despite the compared value being unchanged, permitted on LL/SC architectures (§8.2, ADR-13).
SPSC
Single-producer single-consumer.
Synchronises-with
The formal relation by which a Release store's effects become visible, in order, to an Acquire load of the same location (§8.1).
Tag
A small integer packed with a pointer to defeat the ABA problem (I4).
Treiber stack
The 1986 lock-free LIFO stack (§8.3, §14.2).
TSO
Total Store Order — the x86-64 memory model (§8.1, §22.5).
Two-phase commit (Chase–Lev)
The five-step protocol resolving the owner/stealer race on the last element (§17.2).
Vyukov ring
Dmitry Vyukov's sequence-numbered bounded MPMC queue design (§16.2).
Wait-freedom
A progress guarantee: every thread completes in a bounded number of steps regardless of others (I3).
WGL (Wing–Gong–Liu)
The backtracking linearisability-checking algorithm this library's oracle implements (§21.2).
Work-stealing
A scheduling technique where idle threads pull work from busy threads' deques (§17).
