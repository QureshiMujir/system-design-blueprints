Mental Models & First Principles

The compressed models an expert holds about deterministic record/replay. Each: the insight, what it predicts, the bug class you ship without it, and the § where this blueprint applies it. All cited §/Phase references resolve.

  • MM1 — The supervisor is a state machine clocked by ptrace stops. Insight: ttdb makes no progress between waitpid returns; every stop is a transition with a defined action. Predicts: a CONT issued in the wrong state desynchronizes the whole run. Bug without it: "lost stop" hangs and free-running tracees. Applied in: §8.16 (the state-transition table), Phase 1 (§1.2, owner-thread + state machine), § Failure Modes & Recovery (Supervisor hang).
  • MM2 — A syscall's full effect is (return register + every byte the kernel wrote). Insight: replay needs not just the return value but the exact output-buffer bytes, sized by the result, not the argument. Predicts: using the arg length captures uninitialized bytes that diverge later. Bug without it: silent record-side gaps surfacing as far-downstream divergence. Applied in: §8.11 (MemWrite schema), Phase 2 (§2.2, §2.6 out-length pitfall), Phase 7 (§7.2 injection).
  • MM3 — A hardware perf counter is a logical clock; skid is its quantization error. Insight: retired conditional branches order instructions, but the overflow interrupt fires near not at the triggering instruction. Predicts: you can count to a neighborhood but must single-step the residual to land exactly. Bug without it: async events placed one branch early/late → divergence at delivery. Applied in: §6 P7 (two-stage convergence), Phase 3 (§3.2, §3.6), §4 (skid margin constraint).
  • MM4 — A crash-only log is correct iff every torn tail truncates to a valid prefix. Insight: durability is not "never lose data" but "what survives is always replayable." Predicts: with per-block CRC + length prefix, a kill -9 mid-append costs only the in-flight block. Bug without it: a half-written final record read as valid → immediate replay divergence. Applied in: §6 P5, Phase 4 (§4.2, §4.6), I9.
  • MM5 — Serialization turns a race into a recordable total order. Insight: running ≤1 tracee thread at a time makes the interleaving a sequence of Sched events instead of a non-deterministic memory race. Predicts: recorded parallel programs are slower but reproducible; true sub-quantum races are not captured. Bug without it: "it reproduced once and never again." Applied in: §6 P4, Phase 5 (§5.2, §5.7), I5, the §12.4 deferral.
  • MM6 — An async event has no natural place in a deterministic re-run; the tick coordinate is the only thing that gives it one. Insight: a signal can arrive at any instruction during record, so replay must be told the exact (Tick, IP, regs) to re-deliver it. Predicts: a coordinate missing any of the three cannot be re-found. Bug without it: the handler runs at the wrong instruction. Applied in: Phase 6 (§6.2), I10, §8.17 (signal-one-branch-late example).
  • MM7 — Replay is the same deterministic function as record, run on injected inputs; equal inputs force equal state. Insight: given identical nondeterministic inputs, the CPU is a pure function — so any observed inequality is a real missing input, never noise. Predicts: divergence is always actionable; it points at a record-side gap. Bug without it: tolerating "small" divergence and trusting corrupt state. Applied in: §6 P2/P6, Phase 7 (§7.2, §7.9), I1/I6.
  • MM8 — Random access into a deterministic stream costs (distance to the nearest snapshot). Insight: you cannot seek a replay directly; you restore a checkpoint ≤ T and replay forward. Predicts: checkpoint spacing is the single knob trading memory for seek/reverse latency; a logarithmic spread bounds any seek to one interval. Bug without it: linear replay-from-start makes reverse ops unusable. Applied in: §6 P8, Phase 8 (§8.2, §8.7), Phase 10 (§10.2), Phase 12 (§12.7), §4 (seek-latency constraint).
  • MM9 — A breakpoint is metadata over a deterministic replay, never part of the recorded execution. Insight: the 0xCC must be invisible to the tick clock — removed and the original instruction executed before any tick-affecting control flow. Predicts: a left-in trap byte changes a branch and diverges. Bug without it: breakpoints silently corrupt the replay they sit on. Applied in: Phase 9 (§9.2, §9.6), I1.
  • MM10 — "Backward" is an illusion built from a forward scan plus a select-last. Insight: reverse-continue / reverse-step / reverse-watch all = restore a prior checkpoint, replay forward collecting hits, and pick the last one before "now"; the CPU never runs in reverse. Predicts: off-by-one at the tick < now boundary returns the current position. Bug without it: the user debugs the wrong event. Applied in: Phase 10 (§10.2, §10.6), Phase 11 (§11.2), Phase 13 (§13.2 DAP bridge).

Required reading (§5)

Books

  • "The Linux Programming Interface" — Kerrisk. Ch 20–22 (signals), 24–25 (process creation/fork), 49 (mmap), 63 (alt I/O). Why: exact semantics of fork/COW, signal delivery, mmap — the kernel surface ttdb records. Applied in: Phase 6 (signal capture, §6.2), Phase 8 (COW-fork checkpoints, §8.2), Phase 2 (mmap interception, §2.6).
  • "Computer Systems: A Programmer's Perspective" — Bryant & O'Hallaron. Ch 3 (machine-level x86-64), 8 (exceptional control flow: signals, process model). Why: register file, condition codes, control flow — the substrate of the Tick clock. Applied in: Phase 3 (the Tick coordinate, §3.2), Phase 1 (RegisterFile, §1.2).
  • "What Every Programmer Should Know About Memory" — Drepper. §3–4 (caches, virtual memory). Why: COW cost, working-set sizing for checkpoint intervals. Applied in: Phase 8 (checkpoint interval sizing, §8.7), § Performance Engineering (cache analysis).
  • "Intel 64 & IA-32 Architectures Software Developer's Manual" — Vol 3B/3C. Performance Monitoring, Debug Registers (DR0–DR7), single-step (TF) chapters. Why: normative semantics of PMU counters, skid, hardware watchpoints. Applied in: Phase 3 (perf counter + skid, §3.6), Phase 9 (DRx breakpoints, §9.2), Phase 11 (DR0–DR3 watchpoints, §11.2).
  • "Linux Kernel Development" — Love. Process management, signals, system calls chapters. Why: kernel-side view of ptrace stops and signal queues. Applied in: Phase 1 (waitpid/ptrace stops, §1.2), Phase 6 (signal queueing, §6.6).
  • "Operating Systems: Three Easy Pieces" — Arpaci-Dusseau. Virtualization (process, address space), persistence basics. Why: COW fork + address-space model foundations. Applied in: Phase 8 (snapshot mechanism, §8.2), Phase 7 (address-space stability, §7.2).
  • "Advanced Programming in the UNIX Environment" — Stevens & Rago. Ch 10 (signals), 8 (process control). Why: portable signal semantics, waitpid status decoding. Applied in: Phase 1 (waitpid status decode, §1.2), Phase 6 (signal semantics, §6.2).
  • "DWARF Debugging Standard" v5 + "Engineering a Compiler" — Cooper & Torczon (codegen/debug-info adjacency). Why: line/variable lookup and frame description for state inspection. Applied in: Phase 9 (DWARF line/CFI, §9.2, §9.4 via §12.9 cross-link), Phase 12 (variable resolution, §12.2).

Papers

  • O'Callahan, Jones, Froyd, Huey, Noll, Partush — "Engineering Record And Replay For Deployability" (USENIX ATC 2017). The rr paper. Contribution: low-overhead deployable record-replay via single-core thread serialization + retired-branch counters + syscall interception. Relevance: the canonical architecture this project follows; read first, cover to cover. Applied in: Phase 3 (retired-branch Tick, §3.2), Phase 5 (single-core serialization, §5.2), Phase 14 (syscallbuf overhead win, §14.2); documented-determinism-challenges cited in § Failure Modes & Recovery.
  • Dunlap, King, Cinar, Basrai, Chen — "ReVirt: Enabling Intrusion Analysis through Virtual-Machine Logging and Replay" (OSDI 2002). Contribution: full-VM deterministic replay for security forensics. Relevance: foundational determinism-boundary framing; contrast VM-level vs process-level. Applied in: §2 (historical framing), § Alternative Architectures (the full-VM road not taken).
  • King, Dunlap, Chen — "Debugging Operating Systems with Time-Traveling Virtual Machines" (USENIX ATC 2005). Contribution: reverse debugging via checkpoint + replay over a VM. Relevance: the checkpoint+replay reverse-execution algorithm ttdb uses at process scope. Applied in: Phase 8 (checkpoint+replay seek, §8.2), Phase 10 (reverse-execution algorithm, §10.2).
  • Microsoft — "Time Travel Debugging" (TTD/WinDbg) technical notes. Contribution: production omniscient debugging on Windows via instruction emulation/instrumentation. Relevance: alternate recording mechanism (instrument vs counter); queryable trace ideas. Applied in: § Comparative Architecture Table (TTD row), § Alternative Architectures (instrumentation-emulation road).
  • Pernosco engineering notes / blog corpus. Contribution: post-hoc omniscient analysis over an rr trace (dataflow, full state DB). Relevance: state-reconstruction and the queryable-timeline north star. Applied in: Phase 12 (deep index / queryable state, §12.2), § Comparative Architecture Table (Pernosco row).
  • Lewis — "Debugging Backwards in Time" (AADEBUG 2003), Omniscient Debugging. Contribution: backward debugging concept + event-logging approach for managed runtimes. Relevance: the language-VM contrast in §2. Applied in: §2 (cross-link to managed-runtime time-travel), § Alternative Architectures (event-sourced road).
  • Bergan, Hunt, Ceze, Gribble — "Deterministic Process Groups" (OSDI 2010) / CoreDet (ASPLOS 2010). Contribution: deterministic execution of multithreaded programs. Relevance: multicore deferral rationale; why serialization is chosen instead. Applied in: Phase 5 (serialization rationale, §5.7), Phase 12 (§12.5 deferral note, §12.2).
  • Geels, Altekar, Shenker, Stoica — "Replay Debugging for Distributed Applications" (USENIX ATC 2006). Contribution: replay at application scope. Relevance: scope boundary; why ttdb stays single-process. Applied in: §1 (system boundaries / non-goals), § Scalability Analysis (no horizontal scaling within a session).
  • Saito — "Jockey: A User-Space Library for Record-Replay Debugging" (AADEBUG 2005). Contribution: in-process interposition replay. Relevance: contrast with ptrace-supervisor approach; pitfalls of LD_PRELOAD interposition. Applied in: ADR-03 rationale (§9), § Alternative Architectures (in-process interposition road).
  • Altekar, Stoica — "ODR: Output-Deterministic Replay for Multicore Debugging" (SOSP 2009). Contribution: relaxes to output-determinism for multicore. Relevance: future online-replay direction; relaxation tradeoffs. Applied in: Phase 12 (§12.5 deferral, §12.2), § Alternative Architectures (output-deterministic road).
  • Mashtizadeh, Garfinkel, Terei, Mazières, Rosenblum — "Towards Practical Default-On Multi-Core Record/Replay" (ASPLOS 2017, CASTOR). Contribution: page-ownership multicore replay. Relevance: multicore design alternatives. Applied in: Phase 12 (§12.5 deferral, §12.2), § Alternative Architectures (page-ownership multicore road), ADR-12 "When the Rejected Choice Wins".

Reference Implementations

  • mozilla/rr — study src/Task.cc (Task/tracee abstraction, register access), src/AddressSpace.cc (mapped regions, breakpoint mgmt), src/PerfCounters.cc (counter open/skid handling), src/RecordSession.cc + src/ReplaySession.cc (record/replay loops), src/Scheduler.cc (single-core thread serialization). Lessons: production blueprint for every phase. Pitfalls to avoid copying: rr's deep C++ inheritance; rr's syscallbuf optimization is a Phase 14 stretch, not a first build. Applied in: Phase 1 (Task→Tracee, §1.2), Phase 3 (PerfCounters→§3.2), Phase 5 (Scheduler→§5.2), Phase 7 (record/replay loops, §7.2).
  • gdb — gdb/record-full.c (full software record, simplest reverse-exec model), gdb/record-btrace.c (branch-trace via Intel PT/BTS), gdb/reverse.c, gdb/target.c (target vector). Lessons: clean target-vector abstraction = our Target; record-full shows minimal reverse-exec. Pitfalls: record-full keeps per-instruction undo deltas → memory blowup; avoid as the primary model (use checkpoints). Applied in: §11 (Target trait from target.c), Phase 10 (reverse-exec UX, §10.2), ADR-08 "When the Rejected Choice Wins" (undo-log regime).
  • undo/UndoDB (LiveRecorder) — closed source; study public docs/talks. Lessons: commercial COW snapshot cadence + "bookmark" UX. Pitfalls: not inspectable; rely on rr for source. Applied in: Phase 8 (snapshot cadence, §8.7), § Comparative Architecture Table (UndoDB row).
  • Pernosco (architecture talks) — lessons: separate record from analysis; build a queryable DB post-hoc rather than re-replaying for every query. Pitfalls: full-DB approach is a Phase 12 stretch, not a Phase-0 requirement. Applied in: Phase 12 (deep index, §12.2), § Comparative Architecture Table (Pernosco row).
  • strace / ltrace — strace: syscall decoding tables, process_vm_readv usage, PTRACE_SYSCALL loop. Lessons: robust syscall arg/return decoding; the trap loop. Pitfalls: strace needs no determinism; its lenient error handling is insufficient for replay. Applied in: Phase 2 (syscall arg/return decode + differential, §2.2, §2.4).
  • ptrace-based sandboxes (gVisor ptrace platform, nsjail) — lessons: seccomp-BPF + ptrace integration patterns, vDSO handling. Pitfalls: their goal is isolation not determinism; do not copy their syscall emulation wholesale. Applied in: Phase 2 (seccomp-BPF filter, §2.2), Phase 14 (vDSO handling, §14.2).

Glossary · 42 terms · site-wide glossary

Tick
retired-conditional-branch count; the monotonic logical clock over executed instructions; the temporal coordinate axis.
Coordinate
(Tick, IP, regs) triple uniquely locating an execution point for async re-delivery and seek.
Trace / EventLog
append-only, tick-indexed, on-disk record of all nondeterministic inputs.
TraceEvent
one recorded nondeterminism point: SyscallEntry/Exit, Signal, Sched, RdtscRdrandCpuid, MmapData.
MemWrite
bytes the kernel wrote into tracee memory during a syscall, captured for injection.
Checkpoint
a saved tracee state (regs + memory snapshot + fds) at a tick; the time-machine substrate.
MemSnapshot
checkpoint memory as a live COW fork (CowFork) or persisted page-diff (PageDiff).
ReplayTimeline
checkpoints indexed by tick + seek(T) (restore nearest ≤ T, replay forward).
Recorder
the record-side driver; intercepts and logs nondeterministic inputs.
Replayer
the replay-side driver; suppresses real syscalls, injects recorded results, detects divergence.
Session
top-level debug orchestrator over a ReplayTimeline (breakpoints, watchpoints, cursor).
Tracee
the process under ptrace; state machine {Running, AtSyscallEntry, AtSyscallExit, Stopped, Checkpointed, Diverged}.
Divergence
observed replay state ≠ recorded state; a fatal, first-class signal (never tolerated).
Suppress + inject
replay never runs a real syscall; it writes the recorded effects + return value instead.
Two-stage convergence
count-to-near via the perf counter, then single-step the residual to an exact instruction.
Skid
PMU counter imprecision; the overflow fires near (not exactly at) the triggering instruction.
Skid margin
calibrated safety distance before a target tick at which the PMI is programmed.
PMI
Performance Monitoring Interrupt; fires when a perf counter overflows.
Serialization (scheduling)
running ≤ 1 tracee thread at a time so the interleaving is deterministic + recordable.
Sched event
a recorded context-switch point (from_tid → to_tid).
Anchor
the recorded coordinate at which an async signal (or nondet insn) was delivered.
Reverse-continue
run backward to the most recent breakpoint hit before now (via checkpoint + forward scan).
Reverse-step
move one instruction/source-line backward.
Reverse-watch
find the last time a memory range changed before now.
Watchpoint
a data breakpoint: forward via DR0–DR3, reverse via replay scan.
Breakpoint
int3 (software) or DRx (hardware) execution stop.
int3
the 0xCC single-byte breakpoint instruction.
Debug registers (DR0–DR7)
x86 hardware breakpoint/watchpoint registers.
RFLAGS.TF
the Trap Flag enabling single-step.
seccomp-BPF
kernel syscall filter; SECCOMP_RET_TRACE traps selected syscalls cheaply.
process_vm_readv/writev
bulk tracee memory I/O syscalls.
vDSO
kernel-mapped fast-path syscall page (gettimeofday/clock_gettime) that bypasses ptrace unless patched.
COW fork
copy-on-write process duplication used for cheap memory snapshots.
soft-dirty PTE
kernel page-table bit tracking pages written since the last clear_refs, used for page-diff checkpoints.
RDTSC / RDRAND / CPUID
nondeterministic x86 instructions that must be trapped + recorded.
DAP
Debug Adapter Protocol; the editor-facing debug protocol; supportsStepBack enables reverse ops.
DWARF
debug-info format for line/variable/frame description.
CFI
Call Frame Information (DWARF) used for stack unwinding.
Hermetic replay
replay with no real I/O or host side effects.
Trace format version
MAJOR.MINOR contract governing trace readability across ttdb versions.
Divergence bisect
tooling to find the first diverging event between recorded and replayed runs.
Owner thread
the single supervisor thread permitted to issue ptrace ops on a given tracee.
