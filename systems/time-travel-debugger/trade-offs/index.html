Decisions (§9) · 30 ADRs

1

Implementation language

Chosen

Rust

Rejected

C, Python, Go

When the rejected choice is right

C wins when extending an existing C codebase (rr itself) or targeting a platform with no Rust toolchain; Python wins for a throwaway syscall-trace prototype where overhead is irrelevant

Why: Safety over raw FFI; no GC timing perturbation; ptrace owner-thread contract (§1)

2

Target ISA/OS

Chosen

Linux x86-64 only (P0–P14)

Rejected

aarch64, Windows

When the rejected choice is right

aarch64 wins on Apple-silicon / server-ARM fleets where x86 is absent; Windows wins when the bug is in a Windows-only binary (use TTD/WinDbg per § Comparative Architecture Table)

Why: PMU retired-branch + DRx + ptrace semantics differ; aarch64 → §12.3

3

Tracing mechanism

Chosen

ptrace (nix)

Rejected

LD_PRELOAD interposition, kernel module, eBPF-only

When the rejected choice is right

LD_PRELOAD wins when you only need library-call logging with near-zero overhead and the target cooperates; a kernel module wins when you control the kernel and need whole-system capture below ptrace's reach

Why: ptrace gives register/memory + signal control LD_PRELOAD can't; no kernel-module risk

4

Syscall trap path

Chosen

seccomp-BPF (SECCOMP_RET_TRACE) + PTRACE_SYSCALL fallback

Rejected

PTRACE_SYSCALL only

When the rejected choice is right

PTRACE_SYSCALL-only wins on kernels without SECCOMP_RET_TRACE (pre-4.8) or when every syscall must be intercepted anyway (no filtering benefit)

Why: seccomp filters cheap syscalls out of the trap loop → lower overhead

5

Instruction clock

Chosen

perf_event_open retired conditional branches

Rejected

retired instructions, Intel PT, software counting

When the rejected choice is right

Intel PT wins when you need a full control-flow trace (not just a counter) for omniscient analysis (Pernosco-style) and can afford the bandwidth; software counting wins on CPUs with no usable PMU (most cloud VMs, §3.5)

Why: branches most reproducible across reps; PT heavier/portability-bound (§12.3)

6

Bulk memory I/O

Chosen

process_vm_readv/writev

Rejected

per-word PTRACE_PEEK/POKE, /proc/pid/mem

When the rejected choice is right

PEEK/POKE wins for single-word pokes (breakpoint byte) where the iovec setup cost dominates; /proc/pid/mem wins when process_vm_readv is blocked by Yama and /proc is mountable

Why: one syscall per buffer vs per word → far less overhead

7

Snapshot mechanism

Chosen

COW fork (live) + page-diff (persisted)

Rejected

full memory copy, CRIU

When the rejected choice is right

full copy wins for tiny address spaces where COW page-table setup exceeds the copy; CRIU wins when you must persist a checkpoint across host reboots or migrate it to another machine

Why: COW = cheap incremental; full copy too costly; CRIU too heavy/external

8

Reverse execution model

Chosen

checkpoint + replay-forward search

Rejected

per-instruction undo log (gdb record-full)

When the rejected choice is right

a per-instruction undo log wins for very short executions (≤ a few million instructions) where exact single-instruction reverse with no replay latency matters more than memory

Why: undo log memory blows up; checkpoints bound memory (principle 8)

9

Trace storage

Chosen

append-only binary log + out-of-line blobs

Rejected

SQLite, single mmap'd file

When the rejected choice is right

SQLite wins when the trace must be queried ad-hoc with rich indexes (a post-hoc analysis DB, Phase 12); a single mmap'd file wins for a fixed-size, never-growing trace read randomly

Why: crash-only append; blobs keep event records small/cacheable

10

Serialization

Chosen

custom length-prefixed + CRC32C (fixed-size events)

Rejected

protobuf, bincode, JSON

When the rejected choice is right

protobuf wins when the trace crosses a language boundary and schema evolution must be tool-generated; JSON wins for a human-readable debug dump where size/speed are irrelevant

Why: layout/versioning control; fixed-size = fast seek; no schema runtime

11

Trace integrity

Chosen

CRC32C per block

Rejected

none, SHA-256 per block

When the rejected choice is right

SHA-256 wins when the trace is evidence in a security/forensic chain-of-custody and tamper-resistance (not just corruption detection) is required (§ Threat Model, integrity row); none wins for an in-memory-only trace never written to disk

Why: torn-tail detection cheap; crypto hash unneeded (trace not adversarial)

12

Thread scheduling (record)

Chosen

single runnable tracee thread, recorded switches

Rejected

true multicore record

When the rejected choice is right

true multicore record wins when the bug only manifests under real parallelism and serialized scheduling perturbs it away — the regime CASTOR/ODR target (§ Alternative Architectures)

Why: makes scheduling deterministic; multicore → §12.5

13

Async/runtime model

Chosen

synchronous supervisor loop, no async runtime

Rejected

tokio, thread-per-tracee

When the rejected choice is right

an async runtime wins when one supervisor process drives many independent tracees concurrently (a fleet recorder) and per-tracee owner-thread isolation is preserved

Why: ptrace is an inherently blocking waitpid loop; async adds nothing, risks owner-thread (ADR 1)

14

Concurrency primitives

Chosen

owner-thread + message channel to UI

Rejected

shared-state locks across ptrace

When the rejected choice is right

shared-state locks win when no ptrace call ever crosses a thread (e.g. a pure trace-file analyzer with no live tracee) and lock simplicity beats message plumbing

Why: one owner thread per tracee (principle 9); UI talks via channel

15

Debug info

Chosen

DWARF v5 via gimli

Rejected

custom parser, addr2line shell-out

When the rejected choice is right

a custom parser wins for a non-DWARF format (PDB on Windows, §ADR 2 cross-ref); addr2line shell-out wins for a one-shot script where link-time linking against gimli is not worth it

Why: mature read-only DWARF; no shell-out latency

Breakpoints

Chosen

Rejected

When the rejected choice is right

trap-flag-only single-stepping wins on read-only code pages where 0xCC cannot be written and no DRx slot is free (e.g. ROM/XIP firmware)

Why: software unlimited count; hardware for exec/data watch

Watchpoints

Chosen

Rejected

When the rejected choice is right

mprotect page traps win when you must watch a region larger than 4 hardware slots × 8 bytes can cover and page-granular faults are acceptable (large-array watch)

Why: debug regs precise + cheap fwd; page traps coarse/noisy

Alternative Architectures (Roads Not Taken)

Three fundamentally different architectures for the same goal (process time-travel debugging), not parameter tweaks. Each: sketch, winning regime, the real system embodying it, why rejected here.

A. Full-VM record/replay (log at the virtual-hardware boundary).

   +-----------------------------+
   |        Guest OS + app       |
   |  (the program under study)  |
   +--------------+--------------+
                  | all device I/O, interrupts, DMA
   +--------------v--------------+
   |       Hypervisor / VMM      |
   |  logs every nondeterministic|
   |  input at the HW boundary   |
   +--------------+--------------+
                  v
            VM event log  --> deterministic whole-VM replay

Winning regime: whole-system bugs — kernel, drivers, cross-process and device/DMA nondeterminism — where process scope is too narrow. Real system: ReVirt (OSDI 2002) and "Debugging OS with Time-Traveling VMs" (ATC 2005) (papers §5 #6/#7). Why rejected: heavyweight (record the whole VM), and the project's goal is the harder process-level native case at low overhead; device/DMA replay is an explicit non-goal (§1). Lifting to VM scope would discard the retired-branch-counter approach (§6 P3) that makes commodity recording cheap.

B. In-process interposition (LD_PRELOAD / library-level record).

   +-------------------------------+
   |        app process            |
   |  +-------------------------+  |
   |  | interposed libc shims   |  |  record syscall args/results
   |  | (LD_PRELOAD) + emulator |  |  into an in-process buffer
   |  +-------------------------+  |
   +-------------------------------+
        no separate supervisor; no ptrace

Winning regime: cooperative targets where you only need library-call-level record with near-zero overhead and no privilege to ptrace. Real system: Jockey (AADEBUG 2005) (papers §5 #13). Why rejected: interposition cannot see register/signal state or trap nondeterministic instructions, and a hostile/statically-linked target bypasses the shims; ptrace gives the control LD_PRELOAD cannot (§ADR-03, § Reference Implementations #9). It is listed as ADR-03's "When the Rejected Choice Wins" regime.

C. True-multicore record with page-ownership / output-determinism.

   core0   core1   core2   core3      (threads run in PARALLEL)
     |       |       |       |
     +---+---+---+---+---+---+
         | page-ownership / version log
         v
   parallel-replay log  --> reproduces a *consistent* parallel run

Winning regime: bugs that only manifest under genuine parallelism, where single-core serialization (§6 P4) perturbs the bug away. Real systems: CASTOR (ASPLOS 2017, page-ownership) and ODR (SOSP 2009, output-determinism) (papers §5 #14/#15). Why rejected (here, for now): an order of magnitude more complex (page-ownership tracking or relaxed output-determinism semantics) and not needed for the single-process scope this blueprint targets; deferred as PhaseDeferred("FINAL_BLUEPRINT §12.5") and named in ADR-12's "When the Rejected Choice Wins". The serialized design detects (never silently mis-replays) such races as divergence (§12.4).
