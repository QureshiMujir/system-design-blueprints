33. Hard Questions (Self-Examination)

  • Q1. Why must WAL fsync happen before flow-mod ack rather than after, and what invariant would break if the order were reversed? (§18, §7)
  • Q2. If the Raft lease epoch and the southbound TxnId sequence both reset independently after a crash, how do I3 and I1 interact to prevent a stale write from reaching the dataplane? (§7, §19)
  • Q3. The RCU-snapshot pattern generalizes from TopologyGraph (§11) to the flow table (§15) — why doesn't it generalize to ControllerContext itself, and what property is missing? (§11, §15)
  • Q4. Under what conditions could the reconciliation diff-engine's incremental dirty-set optimization (§16) produce a different convergence outcome than a full rescan, and why must it not? (§16, §7)
  • Q5. Discovery-storm jitter (§17) and heartbeat-storm jitter (§13) are structurally the same fix — what single design principle explains both? (§13, §17)
  • Q6. If a switch capability cache is quarantined (I9) while a reconciliation cycle is mid-flight for that switch, what ordering guarantee stops the reconciler from acting on stale capabilities? (§7, §16)
  • Q7. Why does the intent compiler's determinism requirement (§20) key off the topology snapshot generation number (§17) instead of wall-clock time? (§20, §17)
  • Q8. How does the WAL storage-amplification budget (§4, §32) bound the maximum sustainable flow-programming throughput, and what happens operationally once that throughput target (§4) is exceeded? (§4, §32)
  • Q9. Why can't the cluster simply grow quorum size to improve availability, given the write-amplification tradeoff behind ADR-05 and §19? (§9, §19)
  • Q10. What is the actual difference between "switch isolation" (FM-4) and "topology split" (FM-6), given both stem from a partition, and why do they require different recovery paths? (§23, §17)
  • Q11. Why does the northbound gateway's statelessness (§3) matter for the 99.95% availability target (§4), and what would break if the gateway held session state? (§3, §4)
  • Q12. If P1 (determinism) and P4 (observability by default) ever conflicted — e.g. a trace ID that varies run-to-run — which principle wins, and why does the design avoid the conflict entirely instead of resolving it case by case? (§6, §21)
  • Q13. Why is the single-writer invariant (P11) enforced via a lease epoch (I12) rather than via an external distributed lock service like Chubby, given Chubby is explicitly cited in required reading? (§6, §7)
  • Q14. How would the answer to Q13 change if this system needed leaderless writes, and which ADR would have to flip to support that? (§9, §19)
  • Q15. Why does rule-shadowing detection belong in the intent compiler (§20) rather than the flow-table install path (§15), given both could technically implement the check? (§20, §15)
  • Q16. What specific §4 number bounds the maximum number of concurrent in-flight reconciliation diffs the system can sustain, and how was that bound derived in §32? (§4, §32)
  • Q17. Why does the metrics-cardinality ceiling (§32) force per-flow observability into traces (§21) instead of metrics, and what tradeoff does that impose on incident response? (§32, §21)
  • Q18. The event journal (§11) and the WAL (§18) are both append-only logs — why does this system maintain them as two separate structures instead of one? (§11, §18)
  • Q19. Why does §4's controller RTT assumption (0.5-5 ms) make WAN federation (§17, §19) structurally hard rather than merely "slower," and what would have to change in the consensus design to relax it? (§4, §19)
  • Q20. If the intent compiler (§20) and the flow-table engine (§15) both enforce structural checks (cycle detection vs. group-reference validity), why is one a compile-time rejection and the other an install-time rejection rather than both being the same kind of check? (§20, §15)

30. Mental Models & First Principles

  • MM1 — Desired vs. Observed Are Two Independent Clocks. Compressed insight: version desired state and observed state independently, never collapse them into one mutable value · predicts: without this split, a retry and a stale observation become indistinguishable · bug class: reconciliation oscillation (FM-9) · applies in §16.
  • MM2 — RCU Read Paths Never Block. Insight: readers hold an immutable generation while writers publish new ones, so reads and writes never contend · predicts exactly where lock contention would appear in a naive mutable-graph design · bug class: torn reads under concurrent mutation · applies in §17.
  • MM3 — Fencing Tokens Beat Trust. Insight: a monotonically increasing epoch, checked at every write, replaces "trust the current leader" with "verify the epoch" · predicts why heartbeat-based leader trust alone is insufficient during a partition · bug class: split-brain flow-mod issuance (FM-7) · applies in §19.
  • MM4 — Durability Is a Program Order, Not a Timer. Insight: fsync-before-ack is a causal ordering constraint, not a periodic housekeeping task · predicts what breaks if ack races fsync (acknowledged-then-lost intent) · bug class: durability violation (I4/I11) · applies in §18.
  • MM5 — Replay Is a Test, Not a Feature. Insight: if a system can't replay its own history, it can only assert determinism, never prove it · predicts silent non-determinism that "usually works" until it doesn't · bug class: replay divergence (FM-3) · applies in §26.
  • MM6 — Backpressure Is a Contract, Not a Buffer Size. Insight: every queue needs a documented shed policy, not merely a capacity number · predicts cascading OOM under any sustained producer/consumer imbalance · bug class: queue saturation (FM-5) · applies in §16.
  • MM7 — Compile-Time Conflict Detection Beats Runtime Shadowing. Insight: catching rule overlap at intent-compile time is strictly cheaper than debugging a silently-shadowed rule already in production · predicts where a "why doesn't my rule fire" incident originates · bug class: rule shadowing (FM-8) · applies in §20.
  • MM8 — Observability Must Outlive What It Observes. Insight: the telemetry pipeline needs its own degraded-mode path or it vanishes exactly when it is needed most · predicts masked incidents during cluster-health outages · bug class: masked concurrent incident (§21.9) · applies in §21.

5. Required Reading

Books

  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 5-7, 11: replication, partitioning, and stream processing as the model for reconciliation and event-journal design; applied in §17 and §19.
  • Computer Networking: A Top-Down Approach — Kurose & Ross (7th ed.), ch. 4-5: Ethernet/IP forwarding and the control-plane/data-plane split that motivates the whole project; applied in §3 and §14.
  • TCP/IP Illustrated, Volume 1 — W. Richard Stevens (1994), ch. 3-9, 17-18: exact framing and header layout for Ethernet/ARP/IPv4/TCP/UDP/ICMP used by the packet parser; applied in §14.
  • Linux Kernel Networking — Rami Rosen (2014), ch. 2-3, 11: skb lifecycle, bridge subsystem, Netfilter hook points that the switch runtime's TAP/veth integration must respect; applied in §15 and §3.
  • Rust Atomics and Locks — Mara Bos (2023), ch. 2-7: memory ordering, lock-free queues, and contention analysis behind the flow-table RCU snapshot design; applied in §16 and §17.
  • Database Internals, Vol. 1 — Alex Petrov (2019), ch. 3-4, 7: WAL formats, checksum framing, and snapshot/compaction tradeoffs directly reused for the persistence layer; applied in §18.

Papers

  • "OpenFlow: Enabling Innovation in Campus Networks" — McKeown et al., 2008, SIGCOMM CCR: defined the match/action, flow-table, and controller-switch channel abstraction this project reimplements a subset of; applied in §13.
  • "Ethane: Taking Control of the Enterprise" — Casado et al., 2007, SIGCOMM: centralized policy enforcement predating OpenFlow, motivates the fail-closed gateway default; applied in §3.
  • "Onix: A Distributed Control Platform for Large-scale Production Networks" — Koponen et al., 2010, OSDI: distributed controller state as a replicated NIB, the model behind splitting authoritative from derived state; applied in §17.
  • "B4: Experience with a Globally-Deployed Software Defined WAN" — Jain et al., 2013, SIGCOMM: SDN traffic engineering at WAN scale, the reference point for why WAN federation is out of scope; applied in §20.
  • "In Search of an Understandable Consensus Algorithm" — Ongaro & Ousterhout, 2014, USENIX ATC: the Raft algorithm controller-cluster implements verbatim; applied in §19.
  • "The Chubby Lock Service for Loosely-Coupled Distributed Systems" — Burrows, 2006, OSDI: lease-based fencing to prevent two granted leases from being simultaneously valid; applied in §19.
  • "NOX: Towards an Operating System for Networks" — Gude et al., 2008, SIGCOMM CCR: an early centralized-controller-as-OS abstraction behind treating the controller as an event loop; applied in §16.
  • "P4: Programming Protocol-Independent Packet Processors" — Bosshart et al., 2014, SIGCOMM CCR: the programmable-pipeline model this project deliberately does not adopt as a target, bounding what the software pipeline must support; applied in §15.

Reference Implementations

  • openvswitch/ovs — study ofproto/, datapath/, lib/: dataplane/control-plane split and flow-cache (megaflow) behavior; pitfall: do not copy its in-kernel datapath fast path; applied in §15.
  • opennetworkinglab/onos — study core/, providers/, protocols/: the Intent Framework's compile-install-withdraw lifecycle; pitfall: ONOS's intent reconciliation is cluster-wide eventually-consistent, this project's is leader-only; applied in §20.
  • opendaylight/controller — study its MD-SAL modular data store: separating "config" desired-state trees from "operational" observed-state trees; pitfall: MD-SAL's transaction chaining adds latency this project's diff-engine avoids; applied in §16.
  • cilium/cilium — study its eBPF datapath observability (Hubble): per-flow telemetry and drop-reason tagging as the cardinality bar; pitfall: do not attempt eBPF-level per-packet tracing, out of scope; applied in §21.
  • etcd-io/etcd — study raft/, wal/, mvcc/: WAL segment rotation and snapshot boundary markers; pitfall: etcd's wal/ fsyncs every append, this project batches within RPO=1s; applied in §18 and §19.

RFCs / Specifications

  • OpenFlow Switch Specification 1.3.5 — ONF: defines the flow-mod/packet-in/stats message set and multi-table pipeline this project's southbound protocol is modeled on (subset); applied in §13.
  • RFC 791 — IPv4 header format and fragmentation semantics pinned for the packet parser's IPv4 module; applied in §14.
  • RFC 793 — TCP header/option layout and connection-state vocabulary used by the TCP field matcher; applied in §14.
  • RFC 8446 — TLS 1.3 handshake and record layer, the transport security for southbound and cluster sessions; applied in §13.
  • RFC 7047 — OVSDB management protocol semantics, the model for northbound schema versioning and idempotent configuration pushes; applied in §22.

Glossary (§36) · 45 terms · site-wide glossary

Action list
ordered set of dataplane operations (output/drop/set-field/push-vlan/ pop-vlan/goto-table/group) attached to a flow rule.
Actor (concurrency model)
one supervised async task per session/worker, isolating failure per ADR-09/P10.
Cardinality
number of distinct label-value combinations for a metric; unbounded cardinality is FM-10.
Capability bitmap
negotiated set of features a switch supports, cached and quarantined under I9.
Chaos testing
fault injection (partition, packet loss, corruption) against the full running stack, not a single crate.
Conformance fixture
a named input/expected-output pair under conformance/fixtures/ exercised by every phase's N.5.
Correlation ID
trace/log identifier threaded across an async boundary so one operation is traceable end to end (P4).
Diff engine
computes desired-vs-observed deltas per flow, the core of the reconciler (§16).
Dirty set
the incrementally-tracked set of flows needing reconciliation, avoiding full rescans (§16.7).
Drift
divergence between desired and observed state, detected by drift_detector.rs.
ECMP
equal-cost multipath routing; multiple paths of equal cost load-balanced across.
Event journal
append-only, replayable log of control-plane decisions (§11 EventRecord).
Fail closed
a security-relevant failure rejects the operation rather than degrading permissively (P9).
Fencing
epoch-based mechanism preventing a stale leader/writer from taking effect (I12).
FlowMod
the flow-programming operation (install/modify/delete) sent to a switch.
Flow rule
a match/action forwarding entry scoped to a table and priority (§8, §11).
Generation
a monotonically increasing version number on a snapshot or switch registration (I5, I6).
Goto-table
an instruction chaining evaluation from one flow table to another.
Group table
a table of shared action groups referenced by flow rules (I10).
Hard timeout
a fixed expiry independent of traffic activity, as opposed to idle timeout.
Idle timeout
expiry triggered by an absence of matching traffic for a duration.
Intent
a declarative network policy (ACL/VLAN/path) submitted via the northbound API (§11).
Lease epoch
the monotonically increasing fencing token identifying the current authoritative leader (§11 LeaseGrant, I12).
LLDP
Link Layer Discovery Protocol; the model for this project's topology-discovery probes.
Match field
one matchable packet attribute (ingress port, Ethernet/IP/TCP/UDP fields, metadata register).
mTLS
mutually authenticated TLS, used for southbound and cluster-replication channels.
Northbound
the operator/client-facing interface (REST/gRPC) into the controller.
Packet-in
an event sent from switch to controller when no installed rule matches a packet.
Quorum
the majority set of cluster nodes required to commit a Raft write.
RCU
read-copy-update; a concurrency pattern where readers hold immutable snapshots while writers publish new generations without locking readers out.
Reconciliation
the continuous desired-vs-observed convergence loop (§16).
Replay cursor
the durable bookmark tracking replay progress through the event journal.
RPO
Recovery Point Objective; maximum acceptable data loss window (§4: ≤ 1 second).
RTO
Recovery Time Objective; maximum acceptable time to restore service (§4: ≤ 5 minutes).
SBOM
Software Bill of Materials; generated per release for supply-chain verification.
Shed policy
the documented behavior a bounded queue follows once full (reject, drop-oldest, etc.) — required by P2.
Single-writer invariant
only the current leader may mutate desired state (P11, I3).
Snapshot
a compacted, versioned point-in-time copy of persistent state.
Southbound
the controller-to-switch protocol interface.
Span
a single traced unit of work within a distributed trace (OpenTelemetry, §21).
Split-brain
a state where more than one node believes it holds sole write authority.
Tail latency
high-percentile (p95/p99) latency, the metric class most §4 targets are expressed in.
Topology graph
the canonical, RCU-snapshotted network representation (§11 TopologyGraph).
TxnId
a per-switch monotonically increasing transaction identifier enforcing I1 ordering.
WAL
Write-Ahead Log; the durability primitive underlying I4/I11.
