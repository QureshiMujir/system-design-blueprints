cordrun CLI — the single trust boundary between an operator/orchestrator (root-equivalent caller) and the runtime; dispatches to the runtime core or the image puller; no network listener (P3, ADR-06).

image puller (pkg/registry + pkg/image) — resolves a reference against an OCI Distribution v2 endpoint, fetches manifest and layers concurrently, verifies each blob's SHA-256 digest against the manifest before it is trusted (I7), and hands verified blobs to the CAS.

CAS (pkg/store) — the durable, content-addressed home for every blob; a blob's filename is its digest, so two images sharing a base layer share one file (§34 dedup model).

runtime core (pkg/runtime) — the lifecycle state machine (§8.4); the only component permitted to write state.json (I1, P4); orchestrates namespace, cgroup, capability, seccomp, and overlay setup in the exact order Phase 4–7 (§16–§19) fix.

pkg/namespace — composes the seven namespaces via a single clone3 call and performs the parent/child handshake that writes uid_map/gid_map before the child proceeds (I9).

pkg/cgroup — creates the cgroup v2 subtree, enables controllers up the ancestor chain, and applies memory.max/cpu.max/pids.max/io.max before the workload execs (I4).

pkg/overlay — mounts the lower (image layers, read-only) / upper (container-writable) / work (kernel scratch) stack; the merged view is the container's /.

pkg/capability / pkg/seccomp — applied after pivot_root, before exec, in a fixed order (NO_NEW_PRIVS → seccomp load → capset) that the kernel itself enforces (I8).

cordrun-init (PID 1 in the container) — the tiniest possible init: reaps zombies, forwards signals, execs the workload as PID 2, exits with its status (P10).

pkg/network — attaches the container's fresh network namespace to a host bridge via a veth pair, installs NAT/port-map nftables rules; a CNI-exec path is available for orchestrators that require it (P9, PhaseDeferred("§21.4")).

All later sections (Domain Model §8, Core Schema §11, phases §12–§23) stay consistent with this diagram; module names here are used identically in the Repository Layout (§10) and Core Schema & Types (§11).

8. Domain Model

8.1 OCI Image & Layer Model

An image is a Merkle chain of content-addressed blobs (MM4, §32): a manifest (JSON) lists an ordered array of layer descriptors (mediaType, digest, size) plus a config descriptor; each layer is a tar+gzip (Phase-0) or tar+zstd (deferred, PhaseDeferred("§14.7")) stream. Applying layers in order onto an empty root, honoring OCI whiteouts (.wh.<name> deletes <name>; .wh..wh..opq marks a directory opaque, hiding everything beneath it from lower layers), produces the flattened rootfs.

Manifest {
  schemaVersion: 2
  mediaType:     "application/vnd.oci.image.manifest.v1+json"
  config:        Descriptor{mediaType, digest, size}
  layers:        []Descriptor{mediaType, digest, size}  // ordered, bottom to top
}
Descriptor {
  mediaType: string   // e.g. "application/vnd.oci.image.layer.v1.tar+gzip"
  digest:    string   // "sha256:<hex>" — the CAS key (I7)
  size:      int64
}

8.2 OCI Runtime Bundle & Config Model

A bundle is a directory containing config.json (the OCI Runtime Spec document, §11) and a rootfs/ directory (produced by 8.1's unpack). config.json declares: the process to run (process), the root filesystem path (root), the namespace set and resource limits (linux), and lifecycle hooks (hooks). The runtime never mutates config.json; it is read once at create and the derived, mutable view lives in state.json (I1, P4).

8.3 Namespace & Cgroup Isolation Model

Namespace Isolates Created at Joined via
pid process ID space, /proc view clone3 (Phase 4) setns for exec (Phase 10)
net interfaces, routes, ports clone3 (Phase 4) veth move (Phase 9)
mnt mount table clone3 (Phase 4) n/a — pivoted immediately (Phase 5)
uts hostname, domainname clone3 (Phase 4) n/a
ipc SysV IPC, POSIX MQ clone3 (Phase 4) n/a
user UID/GID mapping, capabilities clone3 (Phase 4) n/a (root-only Phase-0, I19)
cgroup cgroup-root view clone3 (Phase 4) n/a

Cgroup v2's unified hierarchy sits orthogonal to namespaces: the cgroup namespace changes what a container sees under /sys/fs/cgroup; the actual resource-controlling subtree (/sys/fs/cgroup/cordrun/<id>/) is created and populated by pkg/cgroup (Phase 6, §18) regardless of namespace visibility (MM2, §32).

8.4 Container Lifecycle State Machine

   none ──create──▶ created ──start──▶ running ──[workload exits]──▶ stopped
                        │                  │                             │
                        │                  └────────kill─────────────────┤
                        └──────────────────delete (from created)─────────┤
                                                                          ▼
                                                                  delete ──▶ none

Legal transitions: none→created (create), created→running (start), running→stopped (workload exit or kill), created→stopped/stopped→none (kill/delete, idempotent per P8). Illegal transitions (e.g., start on a stopped container) return CodeInvalidState (P11) without mutating state.json. Every arrow is a single state.json rewrite: read current state, validate the transition against this table, write new state, fsync, rename — never a partial update (I1, I13).

8.5 Worked Example, Malformed Input, and Failure Path

Worked example. cordrun run alpine:latest sh resolves to: pull alpine:latest (§14) → digest sha256:c5b1… → unpack 1 layer into CAS-backed rootfs (§15) → create writes state.json{status:"created"} → start signals cordrun-init to exec sh, writes status:"running", pid:<init-pid> → operator's sh session ends → workload exits 0 → state.json{status:"stopped"} → delete tears down cgroup/overlay/netns, writes status: none (removes the state file) — 8.4's full cycle, once.

Malformed input. A config.json with "linux":{"namespaces":[{"type":"pidd"}]} (typo) fails pkg/spec.Validate (Phase 1, §13) with CodeInvalidSpec, Path: "linux.namespaces[0].type", before any clone3 call — no partial container is ever created from an invalid spec (I13).

Failure path. The runtime process is SIGKILLed between state.json{status:"creating"} and the clone3 call completing (FM-1). On the next cordrun state <id> invocation, the runtime finds status:"creating" with no corresponding process, cgroup, or namespace resources; per I13 and I11, it classifies the container as failed-to-create, tears down any partial cgroup/netns that does exist (idempotent, P8), and rewrites state.json{status: none} — recoverable without operator intervention (§25, FM-1).

Design principles (§6)

  • P1 — Spec compliance is supreme. When the OCI Runtime Spec is unambiguous, do exactly what it says even if a "better" alternative exists; reserved fields stay reserved. Tradeoff: forgoes local optimization. Operational implication: conformance failures are cheap to diagnose (§28). Violating it breaks every downstream Kubernetes/CRI integration silently.
  • P2 — Default-deny everywhere. Capabilities, seccomp, mount propagation, network reachability all start closed and are opened only by explicit spec entries. Tradeoff: more spec authoring burden on the caller. Operational implication: the attack surface is auditable from the spec alone. Violating it turns every unconfigured field into a silent privilege leak.
  • P3 — Two-process model with explicit synchronization. Parent supervises; child becomes container init via clone3; synchronization is a pipe(2)-based handshake, never signals or files. Tradeoff: one extra syscall round trip at create time. Operational implication: crash of either side is unambiguous from the pipe's EOF. Violating it (e.g., signal-based sync) reintroduces the classic race between "signal sent" and "signal handled."
  • P4 — No state exists that cannot be reconstructed from disk. state.json is the truth; the runtime can be killed at any instant. Tradeoff: every transition costs an fsync. Violating it makes crash recovery (I13, FM-1) undefined behavior instead of a documented path.
  • P5 — Static linking everywhere. The runtime, the init, and any helper binaries are fully static (CGO_ENABLED=0). Tradeoff: larger binaries, vendored libseccomp bindings in pure Go. Operational implication: the runtime never depends on the target image having a libc. Violating it (dynamic linking) breaks injecting cordrun-init into arbitrary images.
  • P6 — No magic environment variables. Every behavior is governed by the spec or an explicit CLI flag; LD_PRELOAD-style hacks are forbidden. Violating it makes behavior non-reproducible from the bundle alone.
  • P7 — One transaction per container at a time. The lifecycle is a state machine (§8.4); state.json records each transition; concurrent operations on the same container ID serialize via a file lock. Violating it produces the classic double-delete race (FM-9).
  • P8 — Idempotent cleanup. delete succeeds if the container is already gone; kill succeeds if the process is already dead. Tradeoff: every teardown path must tolerate "already torn down." Violating it turns routine orchestrator retries into hard failures.
  • P9 — CNI is invokable, not embedded. Phase 9 (§21) ships a built-in bridge; a --cni flag invokes the standard CNI exec contract against /etc/cni/net.d/, deferred to a follow-on (PhaseDeferred("§21.4")). Violating it (embedding CNI logic) couples the runtime to every plugin's release cadence.
  • P10 — The init binary does exactly three things. Reap zombies, forward signals, exit when its workload exits — nothing else lives in cordrun-init. Tradeoff: any richer behavior (log multiplexing, health checks) lives outside it. Violating it turns PID 1 into an unbounded attack surface and a single point of many unrelated failures.
  • P11 — Errors are typed and spec-mapped. A cordrun.Error interface with Code(), Path(), Wrapped(); codes map onto OCI lifecycle error classes so tooling can switch on them. Violating it forces callers to string-match error messages.
  • P12 — Content-addressing is the only image identity a blob receives internally. A tag is resolved to a digest at pull time and never re-used as an identity afterward (I7, T9). Violating it reintroduces "latest drift" as an internal correctness bug, not just a UX wart.
  • P13 — Namespaces are fresh by default, never implicitly shared. Every one of the seven namespace types is created fresh unless the spec explicitly names a path to join (I3, T1). Violating it silently reduces the isolation boundary.
  • P14 — Observability is built, not bolted on. Every state transition, cgroup limit application, and namespace creation emits a structured log line and a metric at the moment it happens, not after the fact. Violating it makes production incidents (§26) undebuggable from telemetry alone.
