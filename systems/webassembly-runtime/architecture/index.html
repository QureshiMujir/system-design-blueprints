Trust and sandbox boundaries

  • Trust boundary: raw .wasm bytes arrive from an untrusted source; everything after wrt-decoder/wrt-validator operates on validated, typed data. Host panics due to guest input = a bug.
  • Sandbox boundary: a guest module's MemInst.data is its only addressable heap. No host pointers cross into the guest; bounds-checked effective-address arithmetic enforces containment. MemInst is a Vec<u8> entirely within the Store.
  • Concurrency boundary: a Store is single-threaded; ModuleInst and Engine are !Sync. Parallelism = multiple Stores in separate threads, no shared memory.
  • W^X boundary: inside wrt-jit, CodeBuffer pages transition PROT_WRITE → PROT_READ|PROT_EXEC before first call; never both simultaneously.

Component descriptions

wrt-decoder — stateless byte-stream reader; no heap beyond the output Module. Processes magic (\0asm), version (1), then sections in order. Each section: read id: u8, size: u32 ULEB, then dispatch. Type section: N FuncType entries (ULEB count, then param-vec + result-vec). Code section: N function bodies; each body has RLE locals [(count: u32, ty: ValType)] then a flat Box<[Instr]>. Memory is bounded by .wasm size. Key invariant: decoder never skips validation; it produces structural IR only — semantic checks belong to wrt-validator.

wrt-validator — single-pass abstract interpretation over Module. Builds a Context (type/func/table/mem/global/elem/data index spaces, locals, labels, return_). Per function body: iterates Instr, calls push/pop_operand and push/pop_ctrl. OperandType::Unknown handles the polymorphic stack (post-unreachable). pop_ctrl checks the operand stack height matches CtrlFrame.height + end_types. Module-level: import type matching, export resolution, start-func arity check, active-segment constant expressions. Output: ValidatedModule(Module) newtype — the only token that unlocks instantiation.

wrt-runtime Store — the sole mutable runtime state. Holds flat Vec pools: funcs, tables, mems, globals, elems, datas. Addresses are typed newtypes (FuncAddr, MemAddr, …) that index their respective vec. ModuleInst contains address vectors mapping module-local indices to store addresses + an export map. Instantiation: allocate entries in order (funcs, tables, mems, globals), evaluate constant init-exprs, populate active element/data segments, call start function.

MemInst — data: Vec<u8> whose length is always a multiple of PAGE = 65536. Effective address = base_i as u64 + memarg.offset; trap OutOfBoundsMemory if effective_addr + N > data.len() as u64. memory.grow(n): extend by n * PAGE bytes if <= max; return old size in pages or -1. Little-endian load/store; alignment is a hint (never traps). memory.fill/copy/init use ptr::copy/copy_nonoverlapping for bulk ops. data.drop clears the DataInst vec.

Engine interpreter — the correctness oracle. Three stacks: value stack Vec<Val>, frame stack Vec<Frame>, label stack Vec<Label>. Frame.locals holds arguments + declared locals (initialized to zero-for-type). Dispatch: match instr { ... } over Instr variants; validates nothing (validation already done). block/loop/if push a Label { arity, cont }; end pops and checks label arity; br(depth) unwinds to the depth-th label. Fuel: decrement per instruction; Trap::CallStackExhausted if frame_stack.len() > 1024. Host functions call out via FuncInst::Host { host }.

wrt-jit Compiler + CodeBuffer — Compiler<'a> walks ValidatedModule's Instr list once. Maintains a compile-time value-stack-state tracker (types + location: register or stack slot). Assembler encodes x86-64: REX + opcode + ModRM for common ops; push/pop/mov/add/sub/imul/cmp/jcc/call/ret; memory-access with 32-bit displacement. CodeBuffer: mmap(MAP_ANON|MAP_PRIVATE, PROT_READ|PROT_WRITE), fill, then mprotect(PROT_READ|PROT_EXEC). Unknown opcodes (SIMD, some bulk ops) → emit a call to deopt stub which re-enters the interpreter.

Trampolines — call emits a direct call to CompiledFunc.entry; call_indirect emits: load table[i] (bounds-check → trap stub), null-check (→ UninitializedElement stub), type-check (→ IndirectCallTypeMismatch stub), then call through the funcref. Host→Wasm trampoline marshals &[Val] through the SysV ABI; Wasm→host trampoline does the inverse. Trap stubs jmp to a per-Trap handler that unwinds and returns Err(Trap) to the host.

wrt-cli — thin orchestration: validate subcommand decodes + validates, prints section summary; run decodes + validates + instantiates + calls the export named main or _start; dump prints human-readable section listing (like wasm-objdump -d); jit-dump emits the emitted x86-64 bytes with pseudo-disassembly; bench runs a named export N times and reports mean/p99 latency. All subcommands share a common --fuel flag.

8. Domain Model — Wasm Binary Format, Type System, Execution

8.1 Binary Module Layout

Offset Field Value / Encoding
0–3 Magic 0x00 0x61 0x73 0x6D (\0asm)
4–7 Version 0x01 0x00 0x00 0x00 (little-endian u32 = 1)
8+ Sections Sequence of (id: u8, size: u32 uleb, payload: [u8; size])

Section IDs (ordered; custom=0 may appear anywhere, rest must be ascending):

ID Name Key Contents
0 Custom name + arbitrary bytes; passthrough
1 Type vec(FuncType) — 0x60 params results
2 Import vec(Import) — mod name ExternType
3 Function vec(TypeIdx) — one per internal func
4 Table vec(TableType)
5 Memory vec(MemType) — at most 1 in MVP
6 Global vec(GlobalType init_expr)
7 Export vec(Export) — name ExternIdx
8 Start FuncIdx — called at instantiation
9 Element vec(ElemSegment)
10 Code vec(FuncBody) — locals RLE + opcodes
11 Data vec(DataSegment)
12 DataCount u32 — required if bulk-memory used

LEB128 encoding:

  • ULEB128 u32/u64: 7-bit groups, MSB=1 means more; max 5 bytes (u32), 10 bytes (u64).
  • SLEB128 i32/i64: same framing, sign-extended from MSB group; used for i32.const, i64.const, block typeidx.
  • MemArg.align is stored as log₂ power; MemArg.offset as u32 ULEB (memory64 extension: u64 ULEB).

8.4 BlockType Encoding

BlockType ::= 0x40           -- empty (no results)
            | ValType        -- single result (byte 0x7F..0x70)
            | s33 (SLEB128)  -- typeidx into Type section (negative = above; only non-negative used)

Decoded by wrt-decoder into enum BlockType { Empty, Val(ValType), FuncType(TypeIdx) }.

8.5 Validation Algorithm

Structures:

OperandType  ::= Known(ValType) | Unknown
OperandStack ::= Vec<OperandType>
CtrlFrame    ::= { opcode: CtrlOp, start_types: [ValType], end_types: [ValType],
                   height: usize, unreachable: bool }
CtrlStack    ::= Vec<CtrlFrame>

Core operations (Wasm Core Spec Appendix B — pseudocode):

Operation Precondition / Guard Effect
push_operand(t) — Append Known(t) to operands
pop_operand(expect) If operands.len == ctrl.top().height && ctrl.top().unreachable Yield Unknown (polymorphic pass)
pop_operand(expect) t = operands.last(); t == Unknown ∥ expect == Unknown ∥ t == Known(expect) Pop and yield t
pop_operand(expect) Otherwise → ValidationError(TypeMismatch)
push_ctrl(op, in_types, out_types) — Push CtrlFrame{op, start_types, end_types, height=operands.len(), unreachable=false}; push in_types onto operands
pop_ctrl() — Pop end_types from operands; assert operands.len == frame.height; pop ctrl; yield frame
label_types(frame) — Yields frame.start_types if frame.opcode == Loop; else frame.end_types
unreachable() — Truncate operands to ctrl.top().height; set ctrl.top().unreachable = true

Polymorphic-after-unreachable invariant: once unreachable() fires, pop_operand returns Unknown for any request until the frame is popped — no validation error for any type. Nested block/loop/if each push a new frame resetting height; end uses pop_ctrl which re-checks the frame's end types.

Worked example — (func (param i32) (result i32) block (result i32) local.get 0 if (result i32) i32.const 1 else i32.const 2 end end):

Step Instruction Operand Stack Ctrl Stack top
entry — [I32] (param) func frame, end=[I32]
1 block (result i32) [] block, end=[I32], h=0
2 local.get 0 [I32] block
3 if (result i32) [] if, end=[I32], h=0
4 i32.const 1 [I32] if
5 else [] if→else (flip; check [I32])
6 i32.const 2 [I32] else
7 end (if) [I32] block
8 end (block) [I32] func
valid return [] —

Br depth resolution: br 0 branches to innermost ctrl frame; label_types returns start_types for loop (back-edge) and end_types for block/if.

Module-level validation order: types → imports (match ExternType) → functions (TypeIdx in range) → tables → memories (≤1 for MVP) → globals (init expr type) → exports (uniqueness + ExternType match) → elements (ref types, func indices declared) → data (memory existence) → start (FuncType []→[]).

8.6 Execution — Small-Step Stack Evolution

Example — loop with counter ((loop $l br_if $l)):

(func (param i32) (result i32)   ;; i32 = counter
  block $b (result i32)
    loop $l
      local.get 0       ;; push counter
      i32.const 1
      i32.sub           ;; counter - 1
      local.tee 0       ;; store + leave on stack
      br_if $l          ;; if nonzero, jump back to loop start
    end
    local.get 0         ;; = 0
  end)
Step Instr Value Stack Label Stack Frame locals[0]
enter — [] [block@end, loop@start] 3
local.get 0 — [3] same 3
i32.const 1 — [3,1] same 3
i32.sub — [2] same 3
local.tee 0 — [2] same 2
br_if $l (nonzero) — [] jump → loop@start 2
… (iter 2) — [1] → [0] — 1→0
br_if $l (zero) fall-through [0] same 0
end (loop) — [0] pop loop label 0
local.get 0 — [0,0]→ already done by loop exit pop block 0
end (block) — [0] — —
  • Label.arity = number of values the branch carries; br_if $l pops i32 cond, then if nonzero pops arity values, jumps; otherwise fall-through.
  • br to a block/if: unwinds value stack to Label.height, pops arity results, continues after end.
  • br to a loop: same unwind but continues at Label.cont = loop_start.

8.7 Malformed / Invalid — Error Taxonomy

Input Phase Exact Error
First 4 bytes ≠ 0x00 0x61 0x73 0x6D Decode DecodeError::BadMagic
Truncated ULEB128 (high bit set, no next byte) Decode DecodeError::UnexpectedEof
Section ID 3 appears after section ID 7 Decode DecodeError::SectionOutOfOrder
