396 — WebAssembly Runtime

Goal: Implement, from scratch in Rust, a complete WebAssembly runtime — a binary-format decoder, a type-checking validator built on the stack-based validation algorithm, a Store with sandboxed linear memory (64 KiB pages), tables, and globals, a tree-walking interpreter that serves as the correctness oracle, and a baseline single-pass JIT to x86-64 with W^X executable memory. Implement precise trap semantics, an embedding API with host functions and a Linker, and fuel/epoch interruption. Target the WebAssembly 2.0 core (MVP + bulk-memory + reference-types + sign-extension + non-trapping-float-to-int + multi-value), with v128 SIMD as an advanced phase. Pass the official spec testsuite and differential-test against wasmtime. It is a runtime/executor, not a Wasm producer.

1. Goal

Build a from-scratch WebAssembly 2.0 runtime in Rust: binary decode → type-validate → instantiate → interpret/JIT-execute, exposed as an embeddable library (wrt-*) and the wrtc CLI.

Engineering definition

Validate Module ValidatedModule wrt-validator
Instantiate ValidatedModule + Store ModuleInst wrt-runtime
Interpret Store, FuncAddr, &[Val] Vec<Val> or Trap wrt-runtime

Wasm 2.0 core feature set: MVP + bulk-memory + reference-types + sign-extension + non-trapping-float-to-int + multi-value. v128 SIMD decodes and validates in all phases; interpreter lowering complete by Phase 12; JIT SIMD lowering is PhaseDeferred("FINAL_BLUEPRINT §24").

  • Use cases: plugin hosts (game scripting, editor extensions), sandboxed compute pipelines, edge functions, smart-contract-style deterministic execution, teaching/research runtime.
  • Target users: runtime engineers, embedder engineers, systems programmers learning Wasm internals.

  • Stack machines + structured control flow — operand stack, label/branch semantics, block/loop/if.
  • Type systems + abstract interpretation — polymorphic stack, OperandType::Unknown, CtrlFrame.

  • Virtual memory / mmap / W^X — mmap/mprotect, executable-page lifecycle, guard pages.
  • IEEE-754 — NaN payloads, signed-zero, rounding modes, unordered comparisons.

Polymorphic-stack subtlety: after unreachable, pop_operand must return Unknown rather than fail — this is the most spec-subtle corner of validation; implementing it correctly requires reading the spec algorithm precisely, not intuiting it.

W^X management: the JIT must never hold a page PROT_WRITE|PROT_EXEC simultaneously; mprotect sequencing, cache flushing on non-x86 (future), and the SIGBUS/SIGSEGV trap handler are real systems programming.

Why Wasm matters architecturally

  • Portable safe-sandbox substrate: the only widely-deployed format that is simultaneously: safe (memory-isolated), deterministic (no UB), fast (near-native with JIT), and language-agnostic.
  • Browsers: the fourth official web language (2019 W3C standard); runs in V8, SpiderMonkey, JavaScriptCore.
  • Edge / serverless: Fastly Compute@Edge, Cloudflare Workers (via V8), Fermyon Spin, WASI-preview2.
  • Plugins: Extism, Envoy WASM filters, OPA Rego → Wasm, game-engine scripting (Unity, Godot experiments).
  • Blockchains: EWasm (Ethereum), Cosmos CosmWasm, Near Protocol, Polkadot — determinism + bounded compute (fuel) are first-class requirements matched by this design.

Understanding the Wasm runtime from the inside — not just "use wasmtime" — is the difference between an embedder and a runtime engineer.

Engineering muscles

  • Binary protocol parsing without external parser combinators (no nom/pest — raw BufReader + LEB128).
  • Type-system implementation: the validation algorithm is a textbook abstract interpretation pass.
  • Writing a JIT without an IR/SSA: single-pass baseline codegen forces tight understanding of ABI + machine encoding.
  • Differential testing discipline: the interpreter is the oracle; the JIT must agree on every input.
  • Fuzzing: structure-aware fuzzing of a binary format where malformed input must never cause UB.

Calibration value

Implementing a Wasm runtime end-to-end — decoder, validator, interpreter, JIT, embedding API — is the single project that simultaneously covers: binary format parsing, type system / abstract interpretation, sandboxed memory, machine-code generation, IEEE-754, and embedding ABI. No other portfolio project combines all six. The spec-testsuite conformance pass (Phase 13) provides a quantified correctness signal against 10k+ official test cases.

What Mastery Looks Like

  • Binary-format mastery (Phase 1–2): Given an arbitrary .wasm blob, can explain every byte — magic, version, section id, LEB128 encoding, opcode prefix dispatch — without consulting the spec; can hand-assemble a minimal valid module in a hex editor.
  • Type-system / abstract-interpretation mastery (Phase 3): Can trace the OperandStack/CtrlStack state step-by-step through any instruction sequence, predict whether it validates and explain the polymorphic-stack behavior after unreachable; can reproduce the spec §Appendix B algorithm from memory.
  • Sandboxed-memory mastery (Phase 4–5): Can derive, from first principles, why every effective address must be widened to u64, why alignment is a hint, why memory.grow returns -1 rather than trapping, and what guard-page placement is required for a JIT fast-path; can spot u32-wrap OOB bugs on code review.
  • Interpreter-oracle mastery (Phase 6–8): Can trace the Frame/Label/value stack through a multi-value multi-table module with call_indirect; can predict, for any Trap variant, exactly which invariant was violated and which component catches it.
  • JIT / machine-code mastery (Phase 9–10): Can encode any of the Assembler's x86-64 instructions by hand (REX prefix, ModRM, displacement), predict the W^X mprotect sequencing required for correct execution, and trace a deopt bailout from JIT frame state back into the interpreter.
  • Differential-testing mastery (Phase 10 + 13): Can design a corpus that triggers all known divergence classes (NaN payloads, call_indirect trap order, f32.nearest ties-to-even), run the harness, and diagnose mismatches from a (module_hash, func_idx, args, interp_result, jit_result) log entry.
  • Conformance-engineering mastery (Phase 13): Can interpret a .wast spec file, map assert_invalid/assert_trap/assert_return directives to specific ValidateError/Trap/Val variants, and write a regression test that pins an opcode edge case for all future phases.
  • Embedding-API mastery (Phase 11): Can wire a non-trivial host application (e.g., a WASI-preview1 shim with fd_write + proc_exit) using the Linker API, correctly propagate traps across the host boundary, and configure both fuel metering and epoch interruption for a multi-tenant plugin host.

Trust and sandbox boundaries

  • Trust boundary: raw .wasm bytes arrive from an untrusted source; everything after wrt-decoder/wrt-validator operates on validated, typed data. Host panics due to guest input = a bug.
  • Sandbox boundary: a guest module's MemInst.data is its only addressable heap. No host pointers cross into the guest; bounds-checked effective-address arithmetic enforces containment. MemInst is a Vec<u8> entirely within the Store.
  • Concurrency boundary: a Store is single-threaded; ModuleInst and Engine are !Sync. Parallelism = multiple Stores in separate threads, no shared memory.
  • W^X boundary: inside wrt-jit, CodeBuffer pages transition PROT_WRITE → PROT_READ|PROT_EXEC before first call; never both simultaneously.

Component descriptions

wrt-decoder — stateless byte-stream reader; no heap beyond the output Module. Processes magic (\0asm), version (1), then sections in order. Each section: read id: u8, size: u32 ULEB, then dispatch. Type section: N FuncType entries (ULEB count, then param-vec + result-vec). Code section: N function bodies; each body has RLE locals [(count: u32, ty: ValType)] then a flat Box<[Instr]>. Memory is bounded by .wasm size. Key invariant: decoder never skips validation; it produces structural IR only — semantic checks belong to wrt-validator.

wrt-validator — single-pass abstract interpretation over Module. Builds a Context (type/func/table/mem/global/elem/data index spaces, locals, labels, return_). Per function body: iterates Instr, calls push/pop_operand and push/pop_ctrl. OperandType::Unknown handles the polymorphic stack (post-unreachable). pop_ctrl checks the operand stack height matches CtrlFrame.height + end_types. Module-level: import type matching, export resolution, start-func arity check, active-segment constant expressions. Output: ValidatedModule(Module) newtype — the only token that unlocks instantiation.

wrt-runtime Store — the sole mutable runtime state. Holds flat Vec pools: funcs, tables, mems, globals, elems, datas. Addresses are typed newtypes (FuncAddr, MemAddr, …) that index their respective vec. ModuleInst contains address vectors mapping module-local indices to store addresses + an export map. Instantiation: allocate entries in order (funcs, tables, mems, globals), evaluate constant init-exprs, populate active element/data segments, call start function.

MemInst — data: Vec<u8> whose length is always a multiple of PAGE = 65536. Effective address = base_i as u64 + memarg.offset; trap OutOfBoundsMemory if effective_addr + N > data.len() as u64. memory.grow(n): extend by n * PAGE bytes if <= max; return old size in pages or -1. Little-endian load/store; alignment is a hint (never traps). memory.fill/copy/init use ptr::copy/copy_nonoverlapping for bulk ops. data.drop clears the DataInst vec.

Engine interpreter — the correctness oracle. Three stacks: value stack Vec<Val>, frame stack Vec<Frame>, label stack Vec<Label>. Frame.locals holds arguments + declared locals (initialized to zero-for-type). Dispatch: match instr { ... } over Instr variants; validates nothing (validation already done). block/loop/if push a Label { arity, cont }; end pops and checks label arity; br(depth) unwinds to the depth-th label. Fuel: decrement per instruction; Trap::CallStackExhausted if frame_stack.len() > 1024. Host functions call out via FuncInst::Host { host }.

wrt-jit Compiler + CodeBuffer — Compiler<'a> walks ValidatedModule's Instr list once. Maintains a compile-time value-stack-state tracker (types + location: register or stack slot). Assembler encodes x86-64: REX + opcode + ModRM for common ops; push/pop/mov/add/sub/imul/cmp/jcc/call/ret; memory-access with 32-bit displacement. CodeBuffer: mmap(MAP_ANON|MAP_PRIVATE, PROT_READ|PROT_WRITE), fill, then mprotect(PROT_READ|PROT_EXEC). Unknown opcodes (SIMD, some bulk ops) → emit a call to deopt stub which re-enters the interpreter.

Trampolines — call emits a direct call to CompiledFunc.entry; call_indirect emits: load table[i] (bounds-check → trap stub), null-check (→ UninitializedElement stub), type-check (→ IndirectCallTypeMismatch stub), then call through the funcref. Host→Wasm trampoline marshals &[Val] through the SysV ABI; Wasm→host trampoline does the inverse. Trap stubs jmp to a per-Trap handler that unwinds and returns Err(Trap) to the host.

wrt-cli — thin orchestration: validate subcommand decodes + validates, prints section summary; run decodes + validates + instantiates + calls the export named main or _start; dump prints human-readable section listing (like wasm-objdump -d); jit-dump emits the emitted x86-64 bytes with pseudo-disassembly; bench runs a named export N times and reports mean/p99 latency. All subcommands share a common --fuel flag.

Recovery invariants

Input condition Required behavior
Malformed .wasm (bad magic, truncated LEB128, unknown section) Err(DecodeError) — no panic, no UB
Semantically invalid module (type mismatch, undefined import) Err(ValidateError) — never reaches Store
Guest trap at runtime (OOB memory, integer divide-by-zero, unreachable) Err(Trap) returned to host — host process continues
call_indirect type mismatch Err(Trap::IndirectCallTypeMismatch) — not a validator failure
memory.grow exceeding cap Returns -1 (Wasm spec); host sees no error
Frame stack overflow Err(Trap::CallStackExhausted) — not a Rust stack overflow
JIT code fault (bad emit) Caught by trap-stub handler; Err(Trap) — never SIGSEGV the host
Fuel exhausted Err(Trap) (or a distinct OutOfFuel variant) — deterministic interruption

Concurrency constraints

  • Store: !Send, !Sync by default; a Store must not be shared across threads.
  • Multiple independent Stores may exist in separate threads with no synchronization.
  • ValidatedModule is Send + Sync (immutable after validation); multiple Engines may reference the same ValidatedModule.
  • CodeBuffer pages are !Send until PROT_READ|PROT_EXEC flip; after flip, read-only → safe to share across threads (future multi-instance JIT).

6. Design Principles

DP-1 — The Spec Is the Oracle

Statement: The WebAssembly Core Specification 2.0 is the ground truth. Any behavioral discrepancy — even a "reasonable" deviation — is a bug. Tradeoff: Spec-faithful behavior sometimes diverges from "intuitive" host semantics (e.g., NaN nondeterminism, alignment hints that never trap). Operational implication: Phase 13 runs the entire official testsuite as a CI gate; differential fuzzing against wasmtime is a continuous job. Violating it breaks: correctness claims; portability of guest modules; any downstream trust that wrtc is a spec-compliant runtime.

DP-2 — Validate Before Execute (ValidatedModule Newtype)

Statement: wrt-runtime and wrt-jit accept only ValidatedModule, never raw Module. The newtype carries the invariant "type-safe by construction." Tradeoff: Adds a mandatory validation pass at load time; no lazy/on-demand compilation skipping validation. Operational implication: Engine::invoke + compile() both take &ValidatedModule; constructors are private outside wrt-validator. The interpreter omits per-opcode type checks — it trusts the proof. Violating it breaks: the entire sandbox; a malformed Instr sequence could produce Val type confusion → UB in unsafe JIT output.

DP-3 — Traps Are Values, Not Panics

Statement: Every guest fault surfaces as Result::Err(Trap), never a Rust panic! or unwrap. Host code handles traps as normal control flow. Tradeoff: Requires explicit ?-propagation through the interpreter loop + JIT stub → trampoline path; cannot use unwrap in hot paths. Operational implication: invoke() signature: fn invoke(...) -> Result<Vec<Val>, Trap>. Host functions that trap return Err(Trap::...). Panics in wrt-* crates are bugs, not expected runtime events. Violating it breaks: embedder error handling; trap-across-host-boundary contract; assert_trap conformance tests.

DP-4 — Sandbox the Guest

Statement: The guest can only read/write its MemInst byte arrays and its TableInst element arrays. No host pointer, Rust reference, or JIT code pointer is ever placed inside guest-accessible memory. Tradeoff: No zero-copy host↔guest sharing; data must cross the boundary via explicit import/export arguments. Operational implication: MemInst::data is a plain Vec<u8>; host functions receive Val arguments (copied scalars), not raw memory slices. JIT trampolines are in host-owned CodeBuffer pages outside MemInst. Violating it breaks: the entire security model; guest-controlled out-of-bounds write could corrupt host heap or JIT code.

DP-5 — W^X Always

Statement: A CodeBuffer page is either writable (during JIT emission) or executable (during execution), never both simultaneously. Mechanism: mprotect(PROT_READ|PROT_WRITE) during Assembler emission; mprotect(PROT_READ|PROT_EXEC) before first invoke on a CompiledFunc. Re-emit requires a fresh CodeBuffer. Tradeoff: Cannot patch JIT code in place without a second mprotect cycle; acceptable for baseline (no inline caching, no deoptimization patching). Violating it breaks: W^X security guarantee; enables JIT-spraying attacks on exploitable guest modules.

DP-6 — Determinism Modulo Spec-Permitted Float Nondeterminism

Statement: Given identical inputs, Engine and wrt-jit produce identical results or the same Trap. Float nondeterminism (NaN payload bits) is the only exception, explicitly documented. Operational implication: Val::F32(u32) stores bit patterns. Arithmetic: cast to f32/f64, compute, bit-cast back. NaN payload after arithmetic is host-FPU-dependent — spec permits this. Trap conditions (div-by-zero, overflow) are deterministic. Violating it breaks: differential testing; reproducible bug reports; any embedder that needs deterministic replay.

DP-7 — Bounded Resources (Stack Cap, Memory Cap, Fuel)

Statement: Three independent resource limits: (a) call-stack depth capped at a configured limit (→ Trap::CallStackExhausted); (b) MemInst pages capped at MemType.max or a host-configured ceiling; (c) Engine fuel decrements per-instruction, returning Trap on exhaustion. Tradeoff: Fuel adds a branch per opcode in the interpreter hot path (~5% overhead); disable with fuel: None for trusted workloads. Violating it breaks: DoS protection; a guest infinite loop or unbounded recursion exhausts host stack/heap without limits.

DP-8 — Baseline Correctness Over JIT Speed

Statement: The JIT must produce results bit-identical to the interpreter for every supported opcode. When the JIT cannot guarantee this, it bails out to the interpreter (deopt). Speed is secondary to correctness. Tradeoff: Bailout for edge-case opcodes means the JIT is not a universal accelerator; a function with one unhandled opcode runs entirely interpreted. Violating it breaks: the differential invariant (DP-6 + Invariant 8); silent wrong-answer bugs in guest code.

DP-9 — Little-Endian, Explicit Widths

Statement: All MemInst loads/stores are little-endian, regardless of host endianness. Width is always explicit in LoadKind/StoreKind (i8/i16/i32/i64/f32/f64/v128). No implicit widening or narrowing. Operational implication: On big-endian hosts (unsupported build target for wrt-jit; interpreter portable), byte-swap is inserted. Alignment in MemArg.align is a log2 hint — never traps. Violating it breaks: spec-conformant load/store semantics; cross-platform guest binary compatibility.

DP-10 — Index Spaces Are Checked at Validation

Statement: All FuncIdx, TypeIdx, TableIdx, MemIdx, GlobalIdx, LabelIdx, LocalIdx references are range-checked during wrt-validator. The interpreter and JIT index directly without bounds checks. Tradeoff: Validation cost is paid once at load; runtime is faster. Skipping validation (DP-2 violation) reintroduces all index-OOB risks. Violating it breaks: memory safety in the interpreter (index into Vec without check could panic or — in unsafe JIT — access garbage).

DP-11 — No UB in the Host (Localized Unsafe)

Statement: All unsafe blocks are confined to wrt-jit (CodeBuffer mmap + function-pointer cast) and wrt-runtime (none — safe Rust only). Each unsafe block carries a // SAFETY: comment with the invariant it relies on. Tradeoff: Occasionally verbose; some low-level memory ops require wrapper functions that add a call overhead. Violating it breaks: the Rust memory-safety guarantee on the host side; Miri / cargo-audit checks.

DP-12 — Module Load Is Transactional (No Half-Mutated Store)

Statement: Instantiation either fully commits all allocations to the Store, or rolls back completely on any LinkError/Trap during the start function. The Store is never left in a partially-initialized state. Mechanism: Instantiation collects all new indices into temporaries; only on success are they pushed into Store Vecs. Start-function trap triggers rollback of the batch. Violating it breaks: Invariant 7 (trap unwind safety); embedder assumptions that a failed instantiate leaves the Store unchanged.

DP-13 — One Canonical Decoder (No Lazy Re-parsing)

Statement: wrt-decoder decodes the entire binary into Module once. No section is re-parsed at instantiation or JIT time. Instr is the single instruction IR shared by validator, interpreter, and JIT. Tradeoff: Higher peak memory at load (full Module in memory); avoids repeated parse overhead and divergence between decode paths. Violating it breaks: consistency between validation and execution; a re-parse could decode an instruction differently than the one validated.

DP-14 — Proposal Features Are Gated, Not Silent

Statement: Proposal opcodes (bulk-memory, reference-types, sign-extension, non-trapping-float-to-int, multi-value, v128) are enabled by a Features bitset passed at decode + validate time. Disabled-but-present opcodes → DecodeError::UnsupportedOpcode. Operational implication: wrtc CLI exposes --features flags. Default = all Wasm 2.0 features enabled; SIMD gated behind --features simd. Violating it breaks: spec-required rejection of modules using disabled proposals; embedder feature-negotiation contracts.

7. System Invariants

INV-1 — Only a ValidatedModule Is Instantiated

Attribute Detail
Statement Store::instantiate and compile() accept &ValidatedModule; the newtype constructor ValidatedModule(m) is pub(crate) in wrt-validator only.
Why Validation proves type-safety, index-space safety, and stack-height consistency. Without it, interpreter/JIT have undefined behavior on malformed input.
Enforced at Compile time (type system); ValidatedModule is not constructible outside wrt-validator::Validator::validate().
Detection Compile error if caller attempts ValidatedModule(raw_module).
Debugging If validate() returns Err(ValidateError::*), surface the full ValidateError with function index + instruction offset.

Attribute Detail
Statement During pop_operand, `assert!(stack.len() >= frame.height
Why Prevents cross-frame operand leakage; ensures block results are exactly the declared end_types.
Enforced at wrt-validator::Validator::pop_operand() — checked every call.
Detection ValidateError::OperandStackUnderflow { func, offset }.
Recovery Validation fails; Module is rejected; no partial ValidatedModule produced.

INV-3 — Every Memory Access Bounds-Checked in u64

Attribute Detail
Statement Effective address = (i as u64) + memarg.offset; access of N bytes traps if ea + N > mem.data.len() as u64. All arithmetic in u64 — no u32 wrap.
Why Prevents silent wrap-around on 32-bit indices + large offsets; eliminates out-of-bounds host memory access.

Attribute Detail

Enforced at MemInst::grow(n) — allocates exactly n * 65536 bytes via Vec::resize; init in Store::alloc_mem.
Detection Debug-mode assert; release: invariant maintained by construction (no external MemInst::data mutation).

Attribute Detail
Statement The Engine value stack at any instruction point holds exactly the ValType sequence that the Validator proved for that point. No runtime type tag needed.

Enforced at Engine::exec_call_indirect() and wrt-jit call_indirect trampoline (Phase 10).

INV-7 — Traps Unwind to Host Boundary; Store Not Half-Mutated

Attribute Detail
Statement A Trap propagated out of invoke() leaves the Store in the state it was in before the call, OR in a fully-committed post-side-effect state — never partially mutated in a way that violates Store structural invariants.
Why Embedder must be able to retry or continue using the same Store after a trap.

OperandType  ::= Known(ValType) | Unknown
OperandStack ::= Vec<OperandType>
CtrlFrame    ::= { opcode: CtrlOp, start_types: [ValType], end_types: [ValType],
                   height: usize, unreachable: bool }
CtrlStack    ::= Vec<CtrlFrame>

Core operations (Wasm Core Spec Appendix B — pseudocode):

Operation Precondition / Guard Effect
push_operand(t) — Append Known(t) to operands
pop_operand(expect) If operands.len == ctrl.top().height && ctrl.top().unreachable Yield Unknown (polymorphic pass)
pop_operand(expect) t = operands.last(); t == Unknown ∥ expect == Unknown ∥ t == Known(expect) Pop and yield t
pop_operand(expect) Otherwise → ValidationError(TypeMismatch)
push_ctrl(op, in_types, out_types) — Push CtrlFrame{op, start_types, end_types, height=operands.len(), unreachable=false}; push in_types onto operands
pop_ctrl() — Pop end_types from operands; assert operands.len == frame.height; pop ctrl; yield frame
label_types(frame) — Yields frame.start_types if frame.opcode == Loop; else frame.end_types
unreachable() — Truncate operands to ctrl.top().height; set ctrl.top().unreachable = true

Polymorphic-after-unreachable invariant: once unreachable() fires, pop_operand returns Unknown for any request until the frame is popped — no validation error for any type. Nested block/loop/if each push a new frame resetting height; end uses pop_ctrl which re-checks the frame's end types.

Worked example — (func (param i32) (result i32) block (result i32) local.get 0 if (result i32) i32.const 1 else i32.const 2 end end):

Step Instruction Operand Stack Ctrl Stack top
entry — [I32] (param) func frame, end=[I32]
1 block (result i32) [] block, end=[I32], h=0

3 if (result i32) [] if, end=[I32], h=0

Br depth resolution: br 0 branches to innermost ctrl frame; label_types returns start_types for loop (back-edge) and end_types for block/if.

Module-level validation order: types → imports (match ExternType) → functions (TypeIdx in range) → tables → memories (≤1 for MVP) → globals (init expr type) → exports (uniqueness + ExternType match) → elements (ref types, func indices declared) → data (memory existence) → start (FuncType []→[]).

8.6 Execution — Small-Step Stack Evolution

Example — loop with counter ((loop $l br_if $l)):

(func (param i32) (result i32)   ;; i32 = counter
  block $b (result i32)
    loop $l
      local.get 0       ;; push counter
      i32.const 1
      i32.sub           ;; counter - 1
      local.tee 0       ;; store + leave on stack
      br_if $l          ;; if nonzero, jump back to loop start
    end
    local.get 0         ;; = 0
  end)
Step Instr Value Stack Label Stack Frame locals[0]
enter — [] [block@end, loop@start] 3
local.get 0 — [3] same 3
i32.const 1 — [3,1] same 3
i32.sub — [2] same 3
local.tee 0 — [2] same 2
br_if $l (nonzero) — [] jump → loop@start 2
… (iter 2) — [1] → [0] — 1→0
br_if $l (zero) fall-through [0] same 0
end (loop) — [0] pop loop label 0

end (block) — [0] — —
  • Label.arity = number of values the branch carries; br_if $l pops i32 cond, then if nonzero pops arity values, jumps; otherwise fall-through.
  • br to a block/if: unwinds value stack to Label.height, pops arity results, continues after end.
  • br to a loop: same unwind but continues at Label.cont = loop_start.

/// Every distinct Wasm value type. V128 and Ref variants gated by feature flags decoded by wrt-decoder.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum ValType {
    I32, I64, F32, F64,
    V128,            // Phase 12; 128-bit lane vector
    Ref(RefType),    // funcref | externref
}

/// Reference sub-classification; determines null default and table element type.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum RefType { FuncRef, ExternRef }

/// Runtime value. Floats stored as bit-patterns (u32/u64) so canonical NaN payloads and
/// signaling NaN encodings survive round-trips through Val without being normalized by the
/// host FPU. Arithmetic reinterprets to f32/f64, operates, then reinterprets back.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Val {
    I32(i32),
    I64(i64),
    F32(u32),   // IEEE-754 binary32 bit-pattern; NOT f32 to preserve NaN payloads
    F64(u64),   // IEEE-754 binary64 bit-pattern; NOT f64
    V128(u128), // 128-bit opaque; lane interpretation is per-opcode
    Ref(Ref),
}

/// Reference value; null carries type for typed-select and table default.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Ref {
    Null(RefType),
    Func(FuncAddr),    // index into Store::funcs
    Extern(ExternAddr),
}

pub fn read_u32(r: &mut Reader) -> Result<u32, DecodeError>;   // ULEB128, ≤5 groups, final byte ≤0x0F
pub fn read_u64(r: &mut Reader) -> Result<u64, DecodeError>;   // ULEB128, ≤10 groups
pub fn read_i32(r: &mut Reader) -> Result<i32, DecodeError>;   // SLEB128, sign-extend from last group
pub fn read_i64(r: &mut Reader) -> Result<i64, DecodeError>;
pub fn read_s33(r: &mut Reader) -> Result<i64, DecodeError>;   // SLEB128 clamped to 33-bit range
pub fn check_magic_version(r: &mut Reader) -> Result<(), DecodeError>;
pub fn read_section_header(r: &mut Reader) -> Result<Option<(SectionId, Reader<'_>)>, DecodeError>;
  • ULEB loop: accumulate 7-bit groups; if group_count > ceil(bits/7) → DecodeError::Leb128Overflow; if final byte has set high bits beyond type width → DecodeError::Leb128NonCanonical. SLEB: same loop; sign-extend when (last_byte & 0x40) != 0.
  • Reader struct: data: &[u8], pos: usize; fn byte(&mut self)->Result<u8,DecodeError> (EOF guard); fn sub(&mut self,n:usize)->Result<Reader,DecodeError> (bounds check → slice).
  • Magic [0x00,0x61,0x73,0x6D]; version [0x01,0x00,0x00,0x00]. SectionId 0–12 exactly as §8.1 Binary Module Layout.
  • Ordering: last_non_custom_id; require id > last_non_custom_id for non-custom; else DecodeError::OutOfOrderSection. Section size: read_u32 ULEB; check pos + size <= data.len() → DecodeError::UnexpectedEof; return r.sub(size). Custom: read name (LEB length + UTF-8 bytes), store Custom{name,data:Box<[u8]>}; no ordering constraint.

Opcode dispatch (single exhaustive match u8, no _ catch-all; opcode-to-semantics categorization is §8.3's Instruction Set by Category — this decoder adds only the byte-level argument reads): 0x00–0x01/0x05/0x0B (Unreachable/Nop/Else/End) take no args, End returns None; 0x02–0x04 (Block/Loop/If) read via decode_blocktype; 0x0C–0x0D (Br/BrIf) and 0x20–0x26 (Local{Get,Set,Tee}/Global{Get,Set}/Table{Get,Set}) all read one read_u32 (label depth or index); 0x0E (BrTable) reads read_vec(read_u32) then a read_u32 default; 0x0F–0x11 (Return/Call/CallIndirect) read nothing / a FuncIdx / a TypeIdx+TableIdx pair; 0x1A–0x1C (Drop/Select) reads nothing except typed Select which reads count=1 u32 + one valtype; 0x28–0x3E (Load/Store) read via decode_memarg; 0x3F–0x40 (MemorySize/MemoryGrow) read one reserved 0x00 byte; 0x41–0x44 (Const) read i32/i64 via SLEB, f32/f64 via 4/8 raw LE bytes; 0x45–0xC4 (all numeric ops) take no args, the operation is encoded in the opcode itself; 0xD0–0xD2 (Ref ops) — RefNull reads a reftype byte; 0xFC/0xFD are prefixes that read a read_u32 sub-opcode (0xFC table below; 0xFD SIMD sub-ops unimplemented → DecodeError::UnknownSimdOpcode).

0xFC sub-op → Instr: 0–7 CvtOp saturating variants (I32TruncSatF32S..I64TruncSatF64U); 8 MemoryInit(read_u32) + reserved 0x00; 9 DataDrop(read_u32); 10 MemoryCopy + two reserved 0x00; 11 MemoryFill + reserved 0x00; 12 TableInit(elem_idx: read_u32, table_idx: read_u32); 13 ElemDrop(read_u32); 14 TableCopy(dst: read_u32, src: read_u32); 15 TableGrow(read_u32); 16 TableSize(read_u32); 17 TableFill(read_u32); anything else → DecodeError::UnknownOpcode.

decode_blocktype peeks an s33: the value -0x40 (byte 0x40) yields BlockType::Empty; any other negative value decodes a ValType from that byte (BlockType::ValType); any non-negative value is a BlockType::TypeIdx(value as u32).

decode_memarg → MemArg{align:read_u32, offset:read_u32 as u64} (offset stored as u64 for future memory64). LoadKind/StoreKind enums live in wrt-decoder (not wrt-types): 14 LoadKind variants (I32, I64, F32, F64, I32_8s/u, I32_16s/u, I64_8s/u, I64_16s/u, I64_32s/u) and 9 StoreKind variants (I32, I64, F32, F64, I32_8, I32_16, I64_8, I64_16, I64_32).

Code section (wrt-decoder/src/decode/code.rs): pub fn decode_code_section(r: &mut Reader, funcs: &mut Vec<Func>) -> Result<(), DecodeError>; — read count, assert it equals funcs.len() (else DecodeError::CodeFuncCountMismatch); per entry read body_size = read_u32, sub-reader, local groups n_groups = read_u32 then n pairs (read_u32, read_valtype) with a checked_add running sum (else DecodeError::LocalsCountOverflow), stored as Box<[(u32,ValType)]> (RLE kept, not expanded); body = decode_expr(sub_reader)?, then assert the sub-reader is fully consumed.

Element segments (wrt-decoder/src/decode/elems.rs) — 8 flag values, each decode_expr for the offset where active: flags 0/4 = active, table 0 (0: FuncIdx vec init; 4: expr vec init); flags 1/5 = passive (1: elemkind 0x00 + FuncIdx vec; 5: reftype + expr vec); flags 2/6 = active with an explicit TableIdx (2: elemkind+FuncIdx vec; 6: reftype+expr vec); flags 3/7 = declarative, no table/offset (3: elemkind+FuncIdx vec; 7: reftype+expr vec). ElemSegment{kind:ElemKind, ty:RefType, inits:ElemInits, table:Option<TableIdx>, offset:Option<Box<[Instr]>>}; ElemInits::FuncRefs(Box<[FuncIdx]>) | ElemInits::Exprs(Box<[Box<[Instr]>]>).

Data segments (wrt-decoder/src/decode/data.rs): flags=0 active, memidx=0, offset=decode_expr, bytes; flags=1 passive, bytes only; flags=2 active, explicit MemIdx, offset=decode_expr, bytes. After decode, if Module::data_count.is_some(), assert datas.len() == data_count → DecodeError::DataCountMismatch.

module.rs update: after the section loop, call decode_code_section with the stored code-section bytes + funcs, then decode_elem_section, then decode_data_section; replace Phase 1's ConstExpr(Box<[u8]>) in globals/offsets with Box<[Instr]>. Instantiation algorithm (instantiate.rs), steps in order per spec §4.5.4:

  1. Import resolution — for each Import in module.imports, look up in the provided Imports map (HashMap<(module_name, field_name), ExternVal>); match ExternType:
    • Func: FuncInst::ty must equal types[TypeIdx] (param/result exact).
    • Table: Limits of provided ≥ required; RefType exact.
    • Mem: Limits of provided ≥ required (min ≤ provided.min; provided.max ≥ required.max if required.max present).
    • Global: ValType + Mutability exact. Mismatch → LinkError::TypeMismatch.
  2. Alloc module-defined funcs — push FuncInst::Wasm { ty, module: <new ModuleAddr>, code: FuncIdx } for each func after imports.
  3. Alloc tables — TableInst { elem: vec![Ref::Null(rt); min], ty }.
  4. Alloc mems — MemInst { data: vec![0u8; min * PAGE], max }.
  5. Alloc globals — evaluate each init const-expr (const_expr.rs); GlobalInst { value, mutability }.
  6. Alloc elems — for each ElemSegment: ElemInst { refs: Vec<Ref>, dropped: false }. Active segments also schedule a table-init step.
  7. Alloc datas — DataInst { data: Bytes, dropped: false }. Active segments schedule memory-init.
  8. Build ModuleInst — assemble index→addr maps from import addrs ++ newly allocated addrs; insert into store.modules.
  9. Active element initialization — for each active elem, eval offset const-expr (I32), call table_init(store, table_addr, elem_addr, offset, 0, len); out-of-range → LinkError::ElemOutOfRange.
  10. Active data initialization — for each active data segment, eval offset const-expr (I32), mem_init(store, mem_addr, data_addr, offset, 0, len); out-of-range → LinkError::DataOutOfRange.
  11. Start function — if module.start present, call invoke(store, func_addrs[start_idx], &[]).

const_expr.rs — mini-evaluator for init expressions: allowed instructions are i32.const, i64.const, f32.const, f64.const, ref.null, ref.func, global.get (imported globals only, already in store); returns Val.

pub struct MemInst { pub data: Vec<u8>, pub max: Option<u32> }

pub fn mem_grow(m: &mut MemInst, delta: u32) -> i32;       // returns old size or -1
pub fn mem_load<const N: usize>(m: &MemInst, addr: u64) -> Result<[u8;N], Trap>;
pub fn mem_store<const N: usize>(m: &mut MemInst, addr: u64, bytes: [u8;N]) -> Result<(), Trap>;

Effective address (computed in u64, in ops_mem.rs): ea = (stack_pop_i32() as u32 as u64) + memarg.offset, where base_i32 is cast unsigned (i32 → u32 → u64, never sign-extended) before adding the u64 memarg.offset; bounds check traps Trap::OutOfBoundsMemory if ea + N as u64 > mem.data.len() as u64 (this u64 arithmetic cannot overflow for ≤4 GiB memories but stays correct for future 64-bit memories).

Load/store width dispatch (ops_mem.rs) — width N / result type / sign per LoadKind: I32Load/I64Load/F32Load/F64Load are widths 4/8/4/8, no sign; I32Load8S/U and I64Load8S/U are width 1 (signed- or zero-extend per suffix); I32Load16S/U and I64Load16S/U are width 2; I64Load32S/U is width 4. All loads read [u8; N] from mem.data[ea..ea+N] via copy_from_slice and convert with i32::from_le_bytes/u32::from_le_bytes etc.; stores to_le_bytes() then copy_from_slice back.

memory.grow (pseudocode, not compilable Rust): read old = size_pages(); delta == 0 short-circuits to old (always ok); if old + delta overflows u32 or new_size > mem.max, return -1; else data.resize(new_size * PAGE, 0) (OOM → -1) and return old as i32. Trap::MemoryGrowFailed fires only if the allocator itself panics/aborts (caught via a catch_unwind wrapper in debug) — normal limit rejection returns -1 as a value, never a trap.

memory.fill(dst,val,len): bounds-check dst as u64 + len as u64 ≤ mem.data.len(), then mem.data[dst..dst+len].fill(val). memory.copy(dst,src,len): bounds-check both [src,src+len) and [dst,dst+len) (u64), then mem.data.copy_within(src..src+len, dst) (Rust copy_within is memmove-correct for overlap). memory.init(dst,src,len,data_inst): if data_inst.dropped, len==0 is ok else Trap::OutOfBoundsMemory; else bounds-check src+len ≤ data_inst.data.len() and dst+len ≤ mem.data.len() (u64), then copy_from_slice. data.drop: DataInst{dropped:true, data:vec![]} — zeroes memory immediately. memory.size: push Val::I32(mem.size_pages() as i32) (pages ≤ 65536, always fits i32).

Theory anchors: Value-stack/Frame/Label discipline — Crafting Interpreters Part II Ch 14–20 (P6); structured control-flow semantics — Wasm Core Spec §4.4.5 (I14); label-type resolution (loop→start_types, block→end_types) — Wasm Core Spec §4.4.5.5 (I15); find_end precomputed pc-map — ADR-04/ADR-13 (one-pass decode); fuel per-instruction check — ADR-15/DP-7.

wrt-runtime/src/engine.rs — new file, implementing the canonical Engine (§11.4: values/frames/labels/fuel, cap MAX_FRAMES = 1024). This phase adds two fields to §11.4's Frame/Label: Frame.label_base: usize (indexes into the flat labels vec) and Label.stack_base: usize (operand-stack depth at entry); Label.cont: usize is the continuation instruction index.

Dispatch loop (fn run(&mut self, store: &mut Store, instrs: &[Instr], pc: usize)): loop { match instrs[pc] { … pc += 1 } } — direct pc-indexed slice dispatch, with a fuel decrement before each instruction (Trap::CallStackExhausted on fuel=0).

Control flow algorithm (per-Instr dispatch rule, label[n] = the n-th-from-top label):

Instr Rule
Block(bt) push Label { arity: bt.results.len(), cont: find_end(pc), stack_base: values.len() - bt.params.len() }
Loop(bt) push Label { arity: bt.params.len(), cont: pc (loop head), stack_base: … }
If(bt) pop i32; nonzero pushes Label(then); zero jumps to the matching Else/End
Else inside the true branch: jump to the matching End; otherwise continue
End pop Label; if it is the frame's last label, return from the function
Br(n) unwind_to(n): keep the top label[n].arity values, truncate the stack to label[n].stack_base, jump to label[n].cont, pop n+1 labels
BrIf(n) pop i32; perform Br(n) iff nonzero
BrTable(ls,def) pop i32 i; target = ls.get(i).unwrap_or(def); perform Br(target)
Return keep the top frame.arity values; pop all labels back to frame.label_base; pop Frame; restore the caller pc

find_end(pc) is computed lazily during decoding (stored on Block/Loop/If as the end_pc precomputed in a post-decode pass in wrt-decoder/src/endmap.rs).

Call(f), five steps: check frames.len() < MAX_FRAMES (else Trap::CallStackExhausted); resolve FuncInst from store.funcs[module_inst.func_addrs[f]]; pop params from the value stack into locals, padding the rest with zero values; push Frame and an entry Label for the function body; set the instrs pointer to code.body and reset pc=0. local.get/set/tee, global.get/set index directly into frame.locals / store.globals[addr].value — no bounds check needed (the validator guarantees index range). drop: values.pop(). select(ty): pop i32 cond, pop b, pop a, push if cond≠0 { a } else { b }.

wrt-runtime/src/endmap.rs — post-decode pass: a single linear scan builds HashMap<usize, usize> mapping Block/Loop/If pc → matching End/Else pc, stored in Func.end_map.

Sign-extension (i32): extend8_s = (v as i8) as i32; extend16_s = (v as i16) as i32 (i64 adds extend32_s = (v as i32) as i64). nearest (round-to-nearest-even) uses f32::round_ties_even() (stabilized Rust 1.77), fallback libm::rintf. sqrt/abs/neg/ceil/floor/trunc use Rust intrinsics directly (NaN-safe, NaN in → NaN out).

Step Action Outcome
1 Pop i32 i (table index) —
2 tbl = store.tables[module_inst.table_addrs[table_idx]] —
3 Bounds-check i against tbl.size() i >= tbl.size() → Trap::OutOfBoundsTable

Inline bounds check per load/store adds ~3 instructions, acceptable; eliminate with a guard page only in a future tier. Code buffer size is pre-allocated at max(4096, instrs * 16) bytes; realloc uses mmap+copy, never the mprotect dance.

9.8 Edge Cases

Function with 0 params + 0 results: prologue/epilogue only, must still emit valid ret. memory.grow returning -1 (cannot grow) pushes -1 as i32 0xFFFFFFFF, does NOT trap. F32 NaN operand in arithmetic: hardware propagates payload on x87/SSE, verified with an f32::NAN.to_bits() round-trip test. Very large memarg.offset (e.g. 0xFFFF_FFFF): u64 addition must not overflow to valid range.

10.2 Detailed Implementation Steps

Theory anchors: Label-backpatch for forward branches — Wazero design notes (P14), Crafting Interpreters Ch 23 (P6); RIP-relative jmp rel32 encoding — Intel SDM §2.4 (P12); thread-local trap slot — ADR-16 (Result<T,Trap> at boundary); call_indirect trap ordering — INV-6/Wasm Core Spec §4.4.7.1 (I19); deopt PC-mapping — ADR-07 (interpreter-first correctness oracle); native-stack guard page — CS:APP Ch 9 §9.7 (P10).

Control flow lowering in compiler.rs — add ctrl_stack: Vec<CtrlEntry> where CtrlEntry is Block { end_patch: Vec<usize>, arity: usize }, Loop { head_off: usize, arity: usize }, or If { else_patch: usize, end_patch: Vec<usize>, arity: usize }.

Instr Lowering
Block(bt) push CtrlEntry::Block { end_patch:[], arity }
Loop(bt) record head_off = buf.cursor(); push CtrlEntry::Loop { head_off, arity }
If(bt) pop condition → rax; cmp eax, 0; emit je rel32(0) (4-byte placeholder); push CtrlEntry::If { else_patch: cursor-4, end_patch:[], arity }
Else top is If: emit jmp rel32(0) → save in end_patch; backpatch else_patch to here
End pop CtrlEntry; for Block/If: backpatch all end_patch to cursor; for Loop: nothing (back-edge already live)
Br(d) resolve target frame at depth d; emit vstack fixup (pop/shuffle to match label arity); for Loop → jmp rel32(head_off - here - 5); for Block/If → jmp rel32(0), push to end_patch
Br_If(d) pop condition; cmp eax, 0; jne to same target resolution as Br; fall-through for 0
Br_Table(ls, def) pop index → rax; bounds-check vs ls.len(); emit jump table: lea rcx,[rip+table]; jmp [rcx + rax*8]; patch each entry once targets are known (two-pass for this instruction only)
Return vstack fixup to function arity; emit jmp epilogue_off

Vstack fixup on branch: for each label at depth d, its arity values are at known spill offsets; emit mov sequence to compact them, adjust rsp, then branch.

Trampolines — wrt-jit/src/trampoline.rs: pub fn call_wasm_func(store: &mut Store, addr: FuncAddr, args: &[Val]) -> Result<Vec<Val>, Trap> marshals args right-to-left onto the native stack (or into regs rdi/rsi/rdx/rcx/r8/r9 per SysV) then jumps to CompiledFunc.entry; on normal return it pops result slots from rax (i32/i64) or xmm0 (f32/f64) and reconstructs Vec<Val>; on Trap, JIT trap stubs store Trap in a thread-local TRAP_SLOT: Cell<Option<Trap>> then jmp trampoline_exit, and the trampoline reads it and returns Err(trap).

call lowering, in order: flush the virtual vstack to memory (all VStackSlot → rbp spill slots); marshal args by loading from spill into SysV arg regs or pushing to stack; and rsp, -16; call [compiled_func_ptr]; restore by moving return values from rax/xmm0 back to the vstack top. call_indirect lowering, in order: pop table_idx → rax and bounds-check vs table.len() → UndefinedElement; load table.elem[rax] (a Ref) and null-check → UninitializedElement; load the FuncInst, extract FuncType, compare against the static TypeIdx → IndirectCallTypeMismatch; dispatch as call above.

Stack-overflow guard — codebuf.rs: at prologue, emit cmp rsp, [STACK_LIMIT_TLS] (thread-local address of the red-zone boundary) then jb trap_stack_overflow; STACK_LIMIT_TLS is set by wrt-runtime at thread start to stackbase - max_depth * FRAME_OVERHEAD.

Deopt/bailout — compiler.rs: for any unhandled Instr, emit call deopt_entry, a shared stub that restores &mut Store/&ValidatedModule/current FuncIdx/current Wasm PC (stored in a thread-local by the compiler as an offset into Func.body), calls wrt-runtime::Engine::run_from(pc) (a new entry point starting from a given instruction index), and returns results as if the whole function completed natively; the compiler tracks wasm_pc per emitted instruction for this mapping.

Differential test harness — wrt-jit/tests/differential.rs: for every .wasm fixture, compute interp_result = Engine::invoke(store_i, f, args) and jit_result = compile(m, f) -> invoke(store_j, f, args), then assert the two are equal.

wrt-runtime/src/epoch.rs — static EPOCH: AtomicU64 (global; host increments) and EpochDeadline { deadline: u64 }. Engine holds epoch: Option<EpochDeadline>; the interpreter checks at each Loop back-edge: if EPOCH.load(Relaxed) >= deadline { return Err(Trap::CallStackExhausted) }; the JIT emits mov rax, [EPOCH_ADDR]; cmp rax, [deadline_slot]; jae trap_epoch at loop back-edges. 12.7 Performance Concerns

  • XMM spill threshold: with 8 caller-saved XMMs, depth > 8 spills to stack; code emitting deep SIMD chains should pre-lower to reduce live count.
  • VPBROADCASTB requires AVX2; SSE4.1 fallback: PINSRB + PSHUFB (2 insns) — detect at runtime via CPUID, cache flag in Compiler.
  • Interpreter SIMD throughput ~4× slower than scalar per lane; acceptable for correctness oracle, not for hot paths — JIT covers hot patterns.
  • Lane decompose/recompose in interpreter allocates no heap: use stack arrays [i32; 4] etc.

12.8 Edge Cases

  • f32x4.pmin/pmax (pseudo-min/max): pick operand2 if operand1 is NaN — opposite of fmin; both must coexist.
  • i32x4.trunc_sat_f32x4_s: input lane NaN → 0 (not trap); INT_MIN for -inf; INT_MAX for +inf — PhaseDeferred in JIT.
  • i64x2.extend_low_i32x4_s: sign-extends low 4 lanes of i32x4 — source lane count halves.
  • i8x16.shuffle with idx >= 32 is a validation error, not a runtime trap.
  • v128.load32_zero sets upper 96 bits to zero (must not leave XMM register state); Val::V128 in select requires the explicit select t form — plain select is invalid with v128.

Sandbox Boundaries (summary)

  • Guest linear memory: entirely within MemInst::data (Vec<u8>); no pointer to host heap.
  • Guest tables: Vec<Ref> inside TableInst; Ref::Func(FuncAddr) is an index, not a raw pointer.
  • JIT code pages: isolated mmap regions; base address never exposed to guest.
  • HostFunc ABI: &mut Store borrow held by the runtime call frame; guest cannot obtain it.

Failure Modes & Recovery

Severity taxonomy

Severity Class Host impact
S0 — Critical Validator false-accept; JIT miscompile; W^X violation Host memory corruption risk or silent wrong result
S1 — High Guest trap mis-surfaced as panic; decode panic on malformed input Host process crash
S2 — Medium Incorrect numeric result vs oracle; NaN divergence Silent wrong result
S3 — Low Fuel exhaustion, memory.grow -1, OOB trap Expected; Err(Trap) returned cleanly

Per-Class Detail

FM-1 Decode Error (S3)

  • Symptoms: Err(DecodeError::*) from wrt-decoder; module is None.
  • Root cause: malformed LEB128, unknown section id, truncated instruction stream, invalid magic/version.
  • Detection: typed DecodeError variant with byte-offset field; fuzz corpus in CI.
  • Auto-recovery: discard bytes; return error to embedder.
  • Forensic: DecodeError carries offset: usize + kind; embedder logs or propagates.
  • Mitigation: bounded slice reads; no unwrap; AFL/libfuzzer coverage.

FM-2 Validation Rejection (S3)

  • Symptoms: Err(ValidateError::*) from wrt-validator.
  • Root cause: type mismatch on operand stack, control stack depth error, undeclared index, etc.
  • Detection: ValidateError with function index + instruction offset.
  • Recovery: discard Module; embedder reports to operator.
  • Forensic: wrtc validate prints human-readable error with location.

FM-3 Validator False-Accept (S0 — highest severity)

  • Symptoms: type-unsafe module instantiated; interpreter exhibits wrong results or panics on operand type mismatch; fuzz differential vs wasmtime diverges.
  • Root cause: missing check in push_operand / pop_operand / CtrlFrame logic; polymorphic-stack edge case after unreachable.
  • Detection: differential fuzzer (Phase 13): every (module ...) wast snippet validated by wrt-validator AND wasmtime; any accept/reject divergence is a bug. Spec testsuite invalid/ corpus must all reject.
  • Auto-recovery: none — ValidatedModule newtype is only as strong as the validator.
  • Manual recovery: bisect failing wast; add regression fixture; fix CtrlFrame::unreachable branch; re-run spec suite.
  • Forensic: minimized .wasm; diff of CtrlStack dumps at divergence point.
  • Long-term mitigation: formal spec cross-reference comments in wrt-validator; property-based tests covering all opcode typing rules.

FM-4 Guest Trap (S3 — expected)

  • Symptoms: Err(Trap::*) from invoke.
  • Root cause: OOB memory, integer divide-by-zero, unreachable opcode, type mismatch on call_indirect, etc.
  • Detection: Trap enum variant returned; host logs or ignores.
  • Recovery: Store state after trap is UNDEFINED — discard the ModuleInst or re-instantiate.
  • Forensic: optional execution-trace hook records last N ops before trap.

FM-5 JIT Miscompile (S0)

  • Symptoms: JIT path returns different Val than interpreter for same inputs; differential gate fires.
  • Root cause: incorrect x86-64 encoding in Assembler; wrong calling-convention slot; label backpatch off-by-one; missing NaN canonicalization.
  • Detection: Phase 10 differential: every JIT-compiled function run against interpreter oracle on same inputs; fuzz + spec testsuite.
  • Manual recovery: wrtc jit-dump to inspect emitted asm; bisect offending opcode emission; add targeted fixture; deopt that opcode class until fixed.
  • Forensic: CompiledFunc::entry + len; jit-dump subcommand; lldb/objdump disassembly.
  • Long-term mitigation: per-opcode unit tests in wrt-jit; keep interpreter oracle permanently enabled for CI differential.

FM-6 W^X / Segfault in JITed Code (S0)

  • Symptoms: SIGSEGV/SIGBUS in JIT page; host process crash.
  • Root cause: mprotect to RX failed silently; code emitted after flip; codegen wrote past CodeBuffer bounds.
  • Detection: assert that mprotect(RX) succeeds before execution; buffer bounds check in Assembler::emit.
  • Recovery: mprotect failure → fall back to interpreter; buffer overrun → JitError::BufferFull → bail.
  • Forensic: dmesg / crash address vs mapped region; CodeBuffer size watermark metric.

FM-7 Stack Overflow — Native vs Guest (S1/S3)

  • Symptoms (native): SIGSEGV on host stack; interpreter recursion without frame-depth guard. Symptoms (guest): Trap::CallStackExhausted.
  • Detection: frame-depth counter in Engine; JIT guard-page probe in prologue.
  • Recovery (native): frame cap prevents reaching OS limit; guard page → Trap::CallStackExhausted not SIGSEGV.
  • Long-term: Engine iterative dispatch (no Rust recursion per wasm call); frame cap default = 1 000.

FM-8 Host-Function Panic Crossing Boundary (S1)

  • Symptoms: Rust panic unwinds through invoke → UB if invoke is called across an FFI boundary.
  • Root cause: HostFunc implementation panics.
  • Detection: std::panic::catch_unwind wrapping each HostFunc call; convert to Trap::HostPanic.
  • Recovery: surface as Err(Trap); discard ModuleInst.

FM-9 Non-Deterministic Float / NaN Divergence (S2)

  • Symptoms: interpreter vs wasmtime result differs in NaN payload bits; not a miscompile.
  • Root cause: Wasm spec allows canonical-NaN choice; hardware FPU may produce different NaN payloads.
  • Detection: differential flagged; compare with NaN-masking (check is_nan() not bit equality).
  • Recovery: document spec-permitted divergence; mask in differential oracle.

FM-10 Embedding-API Misuse — Store Aliased Across Threads (S1)

  • Symptoms: data races on Store internals (corrupted Vec lengths, torn MemInst reads) only under concurrent load; not reproducible single-threaded.
  • Root cause: Store/Engine are intentionally !Send/!Sync (§4 Concurrency constraints, DP-11); an embedder that forces a Store across threads via unsafe impl Send or FFI defeats the compile-time guarantee.
  • Detection: cargo miri + loom-style concurrency tests on the public API; code review checklist flags any unsafe impl Send/Sync on Store/Engine in downstream crates.
  • Auto-recovery: none — this is a violation of the ownership contract, not a runtime-catchable condition.
  • Manual recovery: remove the unsafe impl; switch to the intended scale-out pattern (§Scalability Analysis: one Store per thread, sharing only the immutable Send + Sync ValidatedModule).
  • Forensic: SECURITY.md documents the !Send/!Sync contract; docs/runbooks/ includes a "Store is not shareable" note pointing back to this failure class.

Incident Runbooks

"Guest appears to hang"

  1. Enable fuel limit before invoke; re-run.
  2. If fuel exhausted: Trap::FuelExhausted — identify looping function via trace hook on_call.
  3. If native hang: check epoch interrupt is wired (host thread increments epoch counter).

"Unexpected trap from a module I trust"

  1. Enable ExecutionTrace::on_instr; re-run with minimized input.
  2. Capture last-N-instructions log.
  3. Reproduce as .wast assertion; add to regression suite.

"JIT output differs from expected"

  1. Run wrtc jit-dump <func-idx> — inspect emitted asm.
  2. Run same function via interpreter (wrtc run --no-jit); compare outputs.
  3. Bisect: disable JIT for individual opcode classes via CompilerConfig::skip_opcodes.
  4. File issue with minimized .wasm + diff.

"JIT slower than interpreter"

  1. Check wrt_jit_bailouts_total per opcode — high bailout rate means JIT overhead with interpreter fallback.
  2. Add unsupported opcode class to CompilerConfig::skip_opcodes to avoid repeated deopt.
  3. Profile with wrtc bench.

Binary-Format Compatibility

  • Accept: exactly the pinned feature set above.
  • Unknown section id with high bit set → passthrough as Custom (spec §2.5.15).
  • Unknown section id without high bit set → DecodeError::UnknownSection.
  • Unknown opcode (outside pinned feature set) → DecodeError::UnknownOpcode; never silent accept.
  • data_count section required when bulk-memory data segments present; absence → DecodeError::MissingDataCount.

Embedding API Stability (semver)

  • Stable surfaces: invoke, Linker::{define, instantiate}, HostFunc type alias, Trap enum, ValType, Val, FuncType.
  • Trap is #[non_exhaustive]; new variants added in minor versions without breaking embedders.
  • Unstable / internal: Module IR (wrt-decoder output), Instr enum, ValidatedModule internals, Assembler internals — semver-minor changes allowed with deprecation notice.
  • OperandStack, CtrlStack, CtrlFrame — internal to wrt-validator; no stability promise.
  • Cross-crate: wrt-types is the only shared vocabulary; wrt-decoder / wrt-validator / wrt-runtime / wrt-jit may evolve independently within semver.

Compiled-Module Cache Format

  • v1: no persistent cache (in-process CodeBuffer only).
  • Future compiled-cache feature: versioned header [magic: 4B][wrt_version: semver: 12B][wasm_hash: sha256: 32B][isa: 1B]; rejected on version or ISA mismatch → re-compile.
  • Cache invalidated on any wrt-jit version bump (patch or above); embedder responsible for eviction.

MSRV Policy

  • MSRV: Rust 1.78, edition 2021.
  • MSRV bumps: minor-version release only; announced in CHANGELOG.md one release in advance.
  • no_std crates (wrt-types, wrt-decoder, wrt-validator): no std feature leak; tested with cargo build --target thumbv7m-none-eabi in CI.

Adding New Proposals

  1. Introduce behind feature = "proposal-name" in affected crate's Cargo.toml.
  2. New Instr variants and ValType variants under #[cfg(feature = "proposal-name")].
  3. Existing embedders with default-features = false are unaffected.
  4. Proposal graduates to default when spec status = Standardized + conformance suite passes.

Differential-Parity Guarantee

  • Pinned wasmtime version recorded in Cargo.lock under [dev-dependencies] of wrt-validator and wrt-runtime.
  • CI (Phase 13): every .wast snippet from the official spec testsuite run against both wrt and pinned wasmtime; accept/reject + result must match.
  • On wasmtime version bump: re-run differential suite; any new divergence treated as a wrt bug until confirmed spec-permitted (e.g., canonical-NaN payload choice).
  • Guarantee scope: module-level accept/reject decisions and all non-NaN numeric results must be bit-identical to pinned wasmtime for the pinned feature set.

Interpreter Dispatch Loop Design

  • match-based dispatch (Rust match Instr { ... }): compiler emits indirect branch on the discriminant; predictable on tight loops with repeated opcodes.
  • Direct-threaded alternative (unsafe computed-goto via *const fn): ~15–20 % faster on branchy code in benchmarks; gated behind #[cfg(feature = "threaded-dispatch")]; requires unsafe + nightly asm_goto or manual trampoline array. Default: match-based for safety/portability.
  • Branch-prediction cost: the match discriminant is a 1-byte tag (repr(u8) on hot variants); annotate cold variants with #[cold]; group numeric ops as first discriminant range.
  • Instruction stream layout: Box<[Instr]> stored contiguously; linear prefetch-friendly traversal on block/loop bodies.

  • Invariant: zero heap allocations between invoke entry and return on any non-growing, non-table-init call path. Verified via #[global_allocator] counting allocator in tests.

JIT Performance Model

  • Win sources: no opcode dispatch overhead (branch per opcode eliminated); integer operands in registers (rax/rcx/rdx/rsi short-lived) for arithmetic chains; tight loop bodies = hot icache.
  • Limits: no register allocator → spill-heavy on functions with many live values; no inlining across function calls (each Call emits a real call); memory bounds-check not eliminated (no guard-page model in baseline).
  • Deopt cost: fallback to interpreter for unsupported opcodes (SIMD until Phase 12, memory.init, complex ref ops) adds one indirect call overhead per deopt site; counted in JitError::Deopt metrics.

Memory Bounds-Check Cost

  • Explicit compare model: every Load/Store emits cmp [addr+offset], mem_len; jae trap_stub; ~2 instructions overhead per access.
  • Guard-page model (stretch goal, Phase 10): map 4 GiB virtual address space per MemInst; OS raises SIGSEGV on OOB → signal handler converts to Trap::OutOfBoundsMemory; eliminates explicit cmp. Requires 64-bit host, careful signal handler registration.
  • Baseline target: explicit compare; guard-page as opt-in future feature.
  • u64 effective-address arithmetic: base_i as u64 + memarg.offset — no 32-bit wrap; compare against mem.data.len() as u64; zero performance difference vs u32 on x86-64 (lea uses 64-bit regs).

Memory.grow Tail Latency

  • Vec::resize on MemInst::data may trigger mmap/mremap; latency spike ~10–100 µs on large grows.
  • Mitigation: pre-reserve max_pages * PAGE bytes on instantiation when Limits::max is known (no re-alloc on grow); documented tradeoff (peak RSS higher).
  • memory.grow never called in hot paths of benchmark modules; tail latency acceptable.

Decode + Validate Throughput

  • Linear single-pass: no backtracking; LEB128 is the bottleneck on dense operand sequences.
  • SIMD-accelerated LEB128 (stretch, Phase 13): process 16 bytes at a time; unlocks ≥ 400 MB/s decode.
  • Validation CPU-bound by push/pop_operand on large functions; OperandStack is a Vec<OperandType> with O(1) push/pop; no hash map in hot path.

Scalability Analysis

Algorithmic Complexity

Operation Complexity Notes

Validate O(N_instrs) one push/pop per instruction; CtrlStack bounded by nesting depth
JIT compile O(N_instrs) single-pass; no IR, no fixpoint
Instantiate O(N_imports + N_elem_entries + N_data_bytes) active segment memcpy is O(segment size)

memory.fill/copy/init O(N_bytes) memmove/memset delegation

Instance Count Scaling

  • Store is not Sync — designed for single-threaded use; no locking in hot path.
  • N instances on N threads: each thread owns an independent Store + ModuleInst; shares only an immutable ValidatedModule (which is Send + Sync as a read-only newtype).
  • No global mutable state; FuncAddr / MemAddr are indices into a Store-local Vec — no cross-store aliasing.
  • Scale-out pattern: spawn N OS threads or async tasks, each with its own Store; throughput scales linearly to N cores (no contention).
  • Per-instance memory cost: MemInst::data dominates (up to 4 GiB); other structures O(module_size).

Linear-Memory Scaling

  • Minimum page granularity: 64 KiB (PAGE = 65536). Max pages: 65536 → 4 GiB per memory.
  • Bounds-check: O(1) explicit compare (or guard-page signal); independent of memory size.
  • memory.grow cost: O(new_pages) if Vec::resize allocates; O(1) if pre-reserved via reserve(max_pages * PAGE).
  • Multiple memories (Wasm 2.0 multi-memory): each is an independent MemInst; MemIdx selects within ModuleInst::mem_addrs; no cross-memory interference.

Call Depth Scaling

  • Interpreter: frame stack is a Vec<Frame> on the host heap; capped at Engine::MAX_FRAMES (default 65536, configurable); exceeding → Trap::CallStackExhausted.
  • JIT: uses native x86-64 stack; native stack guard page catches overflow → SIGSEGV → converted to Trap::CallStackExhausted via signal handler (Phase 10).
  • Recursive Wasm functions with large local counts consume proportionally more frame memory.

Table Size Scaling

  • TableInst::elem is a Vec<Ref>; O(1) indexed access; O(N) table.copy/fill/init.
  • Max table size: Wasm spec limit 2^32−1 elements; practical limit host RAM.
  • call_indirect is O(1) regardless of table size.

JIT Code Cache Scaling

  • One CodeBuffer (mmap'd) per compiled function; size ≈ 3–8× the Wasm bytecode size.
  • Code cache is stored in wrt-jit::CodeCache (a HashMap<FuncIdx, CompiledFunc>); shared across invocations of the same function.
  • ValidatedModule + CodeCache together are Send + Sync; multiple Store instances on multiple threads share the code cache without locks (compiled functions are immutable after mprotect to RX).
  • Cache invalidation: not needed (Wasm modules are immutable post-validation).

Ahead-of-Time Validation as Scaling Primitive

  • ValidatedModule produced once; reused for N instantiations at O(1) per instantiation.
  • wrtc validate + serialize ValidatedModule to disk (future stretch): amortize validation cost across cold-starts.
  • Pooling allocator for MemInst: maintain a free-list of pre-mmap'd 4 GiB regions; memory.grow satisfied from pool; reduces instantiate latency from O(max_pages) to O(1) for pre-reserved pools.

Mental Models & First Principles

MM1 — A Wasm module is a proof certificate, not executable code. The ValidatedModule newtype encodes this: validation produces a type-correctness proof; instantiation and execution consume it. What it predicts: runtime type errors are structurally impossible after the validation gate; the interpreter needs no per-opcode type guards. Bug class without it: "validate-bypass" bugs where a raw Module reaches the JIT — one wrong ValType in a binary-op could produce a Val::F32 where the assembler assumes Val::I32, yielding corrupt x86-64 immediate encoding and a silent wrong result. Resolving §: §6 DP-2, §7 INV-1, §9 ADR-06, §15 Phase 3.

MM2 — The operand stack is a static proof trace, not a runtime value stack. During validation (wrt-validator) the stack holds OperandType (Known/Unknown), never Val. After unreachable, pop_operand returns Unknown for any request — this is the polymorphic-stack rule; the validator accepts any type pop in an unreachable code region. What it predicts: dead code after unreachable + br is always valid; select in polymorphic region does not require identical top-two types. Bug class without it: rejecting valid dead-code branches (false TypeMismatch), or — worse — failing to propagate unreachable through nested blocks, silently accepting a type-unsafe frame exit. Resolving §: §8.5, §15 Phase 3, §7 INV-2.

MM3 — Every effective address is u64; u32 wrap is an exploit vector. Wasm i32 indices are unsigned when used as addresses, but i32::MAX + large memarg.offset wraps in u32 arithmetic to a small positive number, bypassing the intended bounds check. The fix is: ea = (i as u64) + memarg.offset as u64; if ea + access_width > mem.data.len() as u64 { trap }. What it predicts: no attacker-controlled address can silently wrap; the worst case is an OutOfBoundsMemory trap. Bug class without it: classic "64-bit index truncation" OOB read/write where (0xFFFF_FFFF_u32 + offset) % 2^32 hits a low address in guest memory — Lehmann et al. (USENIX 2020) document this class in production runtimes. Resolving §: §7 INV-3, §17 Phase 5, §6 DP-4.

MM4 — A baseline JIT is a streaming code translator, not a compiler. Unlike an optimizing compiler with IR/SSA, a single-pass JIT visits each opcode exactly once, left-to-right, and emits machine code immediately. Forward branches require label backpatching (record the patch site; fill in the relative offset once the target is known). What it predicts: JIT compilation is O(N_instructions) with no fixpoint iteration; deopt is the only recourse for opcodes that need global analysis. Bug class without it: attempting to implement "just a bit of optimization" (e.g., constant folding) in the single pass creates correctness hazards when the fold depends on type context that appears later in the stream. Resolving §: §9 ADR-08, §21 Phase 9 (single-pass Compiler<'a>), §22 Phase 10 (backpatch CtrlEntry list).

MM5 — W^X is a memory-permission state machine, not a policy flag. CodeBuffer transitions one-way: PROT_READ|PROT_WRITE (emit) → PROT_READ|PROT_EXEC (sealed). The state machine has no reverse; re-emitting requires a new CodeBuffer. What it predicts: any attempt to "patch" a compiled function in place will fail; the Assembler panics on a Sealed buffer. Bug class without it: holding PROT_RWX maps means any guest-controlled write to the host heap that reaches the code region can redirect execution — JIT-spraying attacks (Payer et al., Oakland 2010). Resolving §: §6 DP-5, §7 INV-9, §9 ADR-11, §21 Phase 9 (CodeBuffer::seal()).

MM6 — Traps are values; panics are bugs. Result<T, Trap> is the contract. Every guest fault — OOB memory, integer divide-by-zero, stack exhaustion — must be caught in wrt-runtime or wrt-jit's trap stub and returned as Err(Trap). Any Rust panic! or unwrap that fires because of guest data is a host-level bug, not a trap. What it predicts: invoke() is safe to call in a loop; the host process never crashes on malformed guest input. Bug class without it: a guest integer divide that reaches i32::MIN / -1 triggers Rust's debug-mode overflow panic, killing the embedder process — the spec requires Trap::IntegerOverflow. Resolving §: §6 DP-3, §7 INV-7, §9 ADR-16, §8.7 error taxonomy.

MM7 — Structured control flow makes br depth-indexed, not label-addressed. Wasm has no arbitrary goto. All br/br_if/br_table take a relative depth into the ctrl stack (LabelIdx), not an absolute target address. Depth 0 = innermost enclosing block. For loop, branching to it re-enters at the top (back-edge); for block/if, branching exits to after the end. What it predicts: a single-pass JIT must maintain a CtrlEntry stack that mirrors the ctrl-frame stack; forward branches get patch sites filled on end, backward branches (loop) get the target recorded on entry. Bug class without it: confusing label_types() for loop vs block — loop branch target is start_types (back-edge carries inputs), block branch target is end_types (forward-edge carries outputs) — incorrect arity leads to value-stack corruption. Resolving §: §8.5 validation algorithm, §8.6 execution, §21 Phase 9, §22 Phase 10.

MM8 — Fuel is a monotone counter; epochs are a monotone generation. Fuel decrement per instruction is O(1) and deterministic: given the same fuel budget, the same execution always traps at the same instruction. Epochs are coarser: the host increments a shared atomic; the engine checks at function entries and loop back-edges. Both mechanisms cooperate — fuel for deterministic gas budgeting (blockchain semantics), epoch for wall-clock async interruption. What it predicts: a high-frequency call pattern cannot "bank" fuel across calls; each invoke() deducts from the shared budget. Bug class without it: a deeply-recursive guest exhausts native stack before fuel fires — the check must be a pre-push guard, not a post-call check. Resolving §: §6 DP-7, §9 ADR-15, §7 INV-12, §23 Phase 11.

Back-of-Envelope Capacity Model

All numbers derived from the System Constraints table (§4) and standard hardware constants. Formula shown for each.

C1 — Interpreter throughput ceiling (single thread): Constraint: ≥ 100 M simple integer ops/sec (§4 table). Each interpreter dispatch is: array-index on Instr slice + match arm (~5 ns on a 3 GHz OOO core at ~2 IPC for a data-dependent dispatch). Formula: 1 / 5 ns = 200 M ops/s raw; with fuel decrement branch and value-stack push/pop overhead, effective ~120–150 M ops/s. Target ≥ 100 M is achievable with no exotic optimization.

C2 — Baseline JIT speedup budget: Constraint: ≥ 5× interpreter (§4). At 150 M interp ops/s, JIT must reach ≥ 750 M ops/s. A tight JIT numeric loop on x86-64 (register-allocated ADD/IMUL with no memory traffic) runs at ~1–3 GHz / 1 op = 1–3 G ops/s. 5× is well within reach for integer-intensive loops; the bottleneck will be memory-bound loops, not compute.

C3 — Module IR size in RAM: Constraint: Module IR ≤ 4× compressed .wasm (§4). A typical real-world .wasm is 1–5 MB (e.g., sqlite3.wasm ≈ 1.3 MB, a game engine ≈ 3–5 MB). Formula: Module_RAM ≤ 4 × 5 MB = 20 MB. With Box<[Instr]> and Box<[ValType]>, each Instr costs 8–16 bytes (enum + payload). A 1 MB .wasm decodes to ~200 K instructions × 12 bytes avg = 2.4 MB — well within 4×.

C4 — Default instance peak RAM (decode + validate + 256 MiB memory): Module IR (C3): 2.4 MB. ValidatedModule = same Module re-wrapped: +0. MemInst::data: 256 MiB (§4 default cap). Frame/label/value stacks at 1024 call depth: 1024 × sizeof(Frame) ≈ 1024 × 64 bytes = 64 KB. Total peak: ~258 MB. Formula: Module_IR + MemInst_data + stacks ≈ 2.4 MB + 256 MB + 0.064 MB ≈ 259 MB.

C5 — Decode + validate throughput ceiling: Constraint: ≥ 50 MB/s (§4). A 50 MB/s decoder must process one byte in 1 / (50 × 10^6) = 20 ns. On a 3 GHz core: 20 ns × 3 GHz = 60 cycles per byte budget. LEB128 decode: ~3 branches + 2 shifts + 1 OR ≈ 10–15 cycles/byte. Section framing + instruction decode: ~20–40 cycles/instruction. Average instruction = ~1.5 bytes compressed; 40 cycles / 1.5 bytes ≈ 27 cycles/byte — within the 60-cycle budget. Validation adds ~10 cycles/instruction (push/pop on OperandStack). Total: ~50 cycles/byte → ~60 MB/s. ≥ 50 MB/s is reachable without hand-tuning.

C6 — JIT compilation throughput ceiling: Constraint: ≥ 10 MB/s of Wasm bytecode → x86-64 (§4). 10 MB/s means 1 / (10 × 10^6) = 100 ns per byte. An average Wasm instruction ≈ 1.5 bytes; 100 ns × 1.5 = 150 ns/instruction budget. x86-64 encoding of one instruction (MOV/ADD/CMP/Jcc): ~20–60 bytes emitted, ~5–10 ns per emit call (just writes to a buffer). With single-pass overhead (value-stack state tracking, patch-site recording): ~30–50 cycles/instruction → ~10–16 ns on a 3 GHz core. Budget is 150 ns — 10× headroom. Target easily met.

C7 — JIT code size: From C6: a 1 MB .wasm input → x86-64 output. Empirically, x86-64 baseline JIT produces 3–8× expansion (each Wasm instruction → 4–15 x86 bytes). Formula: JIT_code = 1 MB × 5 (median) = 5 MB. For the 5 MB .wasm case: 25 MB JIT cache. CodeBuffer uses mmap(MAP_ANONYMOUS) — this comes from virtual address space, not the heap.

C8 — call_indirect type-check cost: One call_indirect requires: table bounds check (1 compare), null check (1 compare), FuncType equality (compare two Box<[ValType]> slices). Slice compare: params.len() == other.len() (1 compare) + memcmp(params, other.params) (≤ 8 bytes for typical arities = 1–2 cache-hit word compares). Total: ~5 ns at cache-warm. Constraint: call latency < 200 ns (§4); 5 ns type check is 2.5% of budget.

C9 — Fuel decrement overhead: Constraint: ≤ 2% throughput penalty (§4). At 150 M ops/s, one op takes ~6.7 ns. 2% of 6.7 ns = 0.13 ns. The fuel path: Option<u64> check (branch predicted-taken for Some) + u64::saturating_sub(1) (1 cycle) + branch on zero (predicted not-taken). Total overhead: ~1–2 cycles ≈ 0.5 ns at 3 GHz. 0.5 ns / 6.7 ns = 7.5% — above the 2% target. Mitigation: use fuel: u64 with a sentinel u64::MAX for unlimited rather than Option<u64> — removes the None branch, reduces to 1 extra instruction per op (~0.3 ns, ~4%).

C10 — Frame stack memory at max depth: Constraint: 1024 frames cap (§4). sizeof(Frame) = sizeof(Vec<Val>) + sizeof(ModuleAddr) + sizeof(usize) = 24 + 4 + 8 = 36 bytes on x86-64. Locals Vec content: avg 8 locals × 16 bytes/Val = 128 bytes. Total per frame: ~164 bytes. At 1024 frames: 1024 × 164 bytes = 168 KB. Small: L2 cache (512 KB typical) holds the entire frame stack.

C11 — Spec-testsuite conformance run time: Official spec testsuite: ~18 000 test cases (core + proposals, as of Wasm 2.0). Each test: decode + validate + instantiate + ≤10 invoke calls. At 50 MB/s decode + 50 MB/s validate + 1 ms instantiate + 200 ns/invoke: avg test ≈ 2–5 ms. Formula: 18 000 × 3 ms = 54 s wall-clock in a single-threaded runner. With parallelism (8 cores): ~7 s. Target: CI conformance run < 5 min — met.

C12 — Differential fuzzer throughput: One differential fuzz iteration: generate via wasm-smith (~1 ms) + interpret + JIT-compare. Interpret 100 K instructions: 100 K / 150 M ops/s ≈ 0.67 ms. JIT call: ~1 µs (post-compile). Total: ~3 ms/iteration. Formula: 1000 ms / 3 ms = 333 fuzz iterations/second per core. On 8 cores: ~2 666/s. In a 5-minute fuzz CI run: 2666 × 300 s = 800 K iterations — sufficient to cover common divergence classes.

Alternative Architectures (Roads Not Taken)

Alt-A — Register-Based Bytecode VM (JVM-class)

Guest bytecode                   Host
─────────────────────────────────────────────
.wasm → [Wasm→RegBC Lowering] → .rbc
.rbc  → [RegBC Interpreter]   → Vec<Val>

          RAX/RBX/../R15 map
          to virtual regs v0..v15)

Regime where it wins: If the host ISA is register-rich (AArch64 has 31 GP registers) and the guest programs are long-lived (many calls to the same function), a register-based IR amortizes the load/store overhead vs stack-based dispatch. Spill-free small functions run faster because operands stay in registers between instructions. Used by: Dalvik VM (Android) — deliberately chose register-based bytecode over JVM stack bytecode for mobile performance.

Why this blueprint rejected it: Wasm's specification is defined in terms of a stack machine; re-encoding to register-based IR requires a lowering pass (Wasm → RegBC) that is as complex as an SSA front-end — this contradicts the single-source-of-truth principle (DP-13, ADR-04) and doubles the attack surface on untrusted input. The spec testsuite tests Wasm semantics, not RegBC semantics; conformance becomes indirect. The teaching value of this project is implementing the spec algorithm, not implementing a separate ISA.

Alt-B — Ahead-of-Time (AOT) Compilation to Native Binary

.wasm → [AoT Compiler] → .so / ELF
                          (native shared library)
         import stubs                 export stubs
         ┌──────────────────────────────────────┐
         │  native code (fully optimized)       │
         │  no interpreter; no JIT at runtime   │
         └──────────────────────────────────────┘
host ──dlopen──→ wasm_module.so ──call──→ result

Regime where it wins: Serverless platforms with cold-start SLA < 1 ms cannot afford JIT compilation at invocation time. If the .wasm is compiled to a native .so at deploy time, the cold-start is just dlopen + relocation (~100 µs). Optimizing AOT (with full LLVM pipeline) can match hand-written C. Used by: Fastly Compute@Edge (AOT with Cranelift), Cosmopolitan/WasmEdge AOT mode, wasm-opt → wasm2c pipeline.

Why this blueprint rejected it: AOT requires a persistent compiled artefact with a versioned format, cross-compilation toolchain, and a code-signing / trust chain. The resulting .so is no longer portable Wasm — it is target-CPU-specific and loses the "run anywhere" guarantee. The educational value is in the runtime pipeline (decode → validate → execute); AOT would outsource that to an LLVM backend, reducing the project to a thin wrapper. The differential-testing discipline (INV-8) also requires a live interpreter oracle during execution — incompatible with pure AOT.

Regime where it wins: The Wasm GC proposal and component model move toward capability-oriented isolation where multiple components share an address space with fine-grained access control per object — not the coarse "one flat memory per module" sandbox. If the workload is multi-tenant with many small modules sharing a GC heap, capability-based isolation reduces per-tenant overhead. Why this blueprint rejected it: The component model and GC proposal are explicit NON-GOALs (§1). Implementing this as an extension would invalidate the existing MemInst-centric bounds-check invariants (INV-3, INV-4) and require replacing the Val enum with a capability-tagged union — a complete redesign, not an extension.
