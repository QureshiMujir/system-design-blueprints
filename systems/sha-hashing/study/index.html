  3. Derive the expected throughput ratio between SHA-NI and portable-scalar SHA-256 from §4's numbers, and explain why the ratio isn't simply "clock-speed × instruction count." (§4, §32)
  4. Why must HMAC-DRBG's reseed counter be enforced by code, not left to caller discipline? (§7 I13, §23)

  9. Why does multi-buffer SHA-256 require equal-length inputs per batch, and what are the two remediation strategies when the caller's messages differ in length? (§15, §23 FM-8)

30. Mental Models & First Principles

  • MM1 — A hash function is a compression map with a random-oracle façade. Predicts: any shortcut to invert or find collisions faster than birthday-bound work means the façade cracked. Bug class without it: ad hoc digest truncation breaking the birthday-bound argument. Resolving §: §8 Domain Model, §22 T3.
  • MM2 — Merkle-Damgård chains state; sponge absorbs-and-squeezes. Predicts: SHA-2 needs a length-prepended pass and is prefix-vulnerable (I11); SHA-3 needs a capacity margin and is XOF-capable. Bug class without it: assuming SHA-3 needs HMAC's wrapper for a MAC — KMAC exists precisely because sponge MACs differ. Resolving §: §8, §17.
  • MM3 — The permutation is the primitive; mode-of-use is a policy layer on top. Predicts: Keccak-f[1600] alone has no security claim; SHA-3/SHAKE/cSHAKE/KMAC/TupleHash/ParallelHash are the same permutation under different padding/rate policies. Bug class without it: re-implementing the permutation per variant instead of sharing keccak_f1600 (P13). Resolving §: §16, §8.
  • MM4 — Constant-time is a property of the whole call path, not one function. Predicts a compiler can undo a constant-time comparison by optimizing across an inlined boundary (T11). Bug class without it: shipping subtle::ConstantTimeEq inside a function the compiler proves only ever receives matching-or-not inputs, then constant-folds the branch away. Resolving §: §21, §22 T11.
  • MM5 — A MAC is a hash plus a secret the attacker cannot simulate. Predicts that any construction letting the attacker compute new valid (tag, message) pairs without the secret (length extension) is not a MAC even if it's a fine hash (P8). Bug class without it: H(secret‖msg) MACs — the historic Flickr-API-signature bug class. Resolving §: §22 T1, §19.
  • MM6 — Throughput is a function of block size and per-block cost; §4's constants are not independent. Predicts SHA-512's larger 128-byte block amortizes per-block overhead better on 64-bit hosts than SHA-256's 64-byte block, despite more arithmetic per block. Bug class without it: assuming "more rounds always means slower" without accounting for block-size amortization. Resolving §: §4, §32.
  • MM7 — A conformance vector is a point sample; a differential fuzzer is a manifold cover. Predicts vectors catch known-shape bugs, fuzzing plus cross-validation catch unknown-shape ones (P11, P6). Bug class without it: a SIMD backend passing every CAVP vector yet diverging on an input CAVP never samples. Resolving §: §26, §15.
  • MM8 — Every deprecation is a promise kept to the next reader, not a suggestion. Predicts sha1_legacy's warning must survive every refactor or new engineers silently promote it back to first-class status (P10). Bug class without it: SHA-1 creeping back into new call sites years later because the warning was refactored away. Resolving §: §22 T4, §25.

  • Menezes, A., van Oorschot, P., Vanstone, S. — Handbook of Applied Cryptography (CRC Press, 1996). Ch. 9 (Hash Functions and Data Integrity). Extract: birthday-bound analysis, MDC constructions. Applied in §8 Domain Model, §32 Capacity Model.
  • Aumasson, J-P. — Serious Cryptography (No Starch Press, 2017). Ch. 8 (Hash Functions), Ch. 9 (SHA-2 and SHA-3). Extract: practitioner-level SHA-2 vs. SHA-3 comparison. Applied in §31 Comparative Architecture Table.

Reference Implementations

  • OpenSSL crypto/sha/ — sha256.c, sha512.c, keccak1600.c. Lesson: the AVX2/SHA-NI schedule layout most other implementations crib from. Pitfall not to copy: OpenSSL's general-purpose dispatch macro sprawl trades readability for portability across decades of CPU generations — not a trade this crate needs to make. Applied in §15 Phase 3, §26.
  • BoringSSL crypto/fipsmodule/sha/ — the constant-time-audited C reference. Lesson: FIPS-module boundary discipline (what must be constant-time vs. what may not be). Pitfall: BoringSSL's module boundary is enforced by a build-time integrity check that has no direct Rust equivalent — approximate it with cargo public-api (I14) instead. Applied in §21 Phase 9.
  • RustCrypto sha2, sha3, hmac, hkdf crates — read as reference, never copied verbatim. Lesson: generic Digest-trait layering across many hash families. Pitfall: their trait object safety trade-offs differ from this crate's no_std-first design; do not import the trait hierarchy wholesale. Applied in §11 Core Schema & Types.
  • XKCP (eXtended Keccak Code Package), the Keccak team's own reference (github.com/XKCP/XKCP) — Standalone/CompactFIPS202. Lesson: the canonical bit-exact Keccak-f[1600] reference used to validate every other implementation. Pitfall: XKCP's SIMD "SnP" backends assume a build-time-fixed target; this crate needs runtime dispatch instead (ADR-05). Applied in §16 Phase 4.
  • Linux kernel crypto/sha256_generic.c, crypto/sha3_generic.c — Lesson: constant-space, no-allocation kernel-context hashing (mirrors sha-core's no_std requirement). Pitfall: kernel code assumes a single-threaded interrupt context that does not map onto this crate's multi-buffer concurrency model (ADR-07); do not copy the locking assumptions. Applied in §12 Phase 0, §1.

Glossary (§36) · 45 terms · site-wide glossary

Merkle-Damgård construction
iterative hashing chaining a compression function over padded fixed-size blocks; collision-resistant if the compression function is (Damgård 1989).
Sponge construction
absorb-then-squeeze construction over a fixed-width permutation, providing arbitrary-length output and random-oracle indifferentiability up to the capacity.
Compression function
the fixed-input-size building block of a Merkle-Damgård hash.
Permutation (Keccak-f[1600])
the fixed, keyless bijection over the sponge's 1600-bit state; the sole primitive underlying every SHA-3/SHAKE/cSHAKE/KMAC/TupleHash/ParallelHash.
Message schedule
the expansion of a hash's input block into the full round-input word sequence.
Rate
the portion of the sponge state (bytes) exposed to absorb/squeeze.
Capacity
the portion of the sponge state never touched by input/output, setting the security margin.
Absorb
the sponge phase XOR-ing input blocks into the rate, interleaved with permutation calls.
Squeeze
the sponge phase reading rate-sized output chunks, interleaved with permutation calls.
pad10*1
the Keccak multi-rate padding rule appending 1, zero-or-more 0s, and a final 1 bit to reach a rate-aligned length.
Domain separation
distinguishing otherwise-identical constructions via a differing padding suffix byte.
IV (initialization value)
the fixed starting chaining state of a Merkle-Damgård hash.
Chaining value
the intermediate state passed between compression-function calls.
Block size
the fixed input size of one compression-function/absorb call.
Output size / digest length
the fixed length of a hash's final output.
XOF (extendable-output function)
a hash whose output length is a caller parameter.
SHAKE
the SHA-3-family XOF, a sponge with a 0x1F domain-separation pad byte.
cSHAKE
a customised SHAKE supporting function-name/customisation strings.
KMAC
a sponge-native MAC built on cSHAKE, structurally distinct from HMAC.
TupleHash
a SP 800-185 construction hashing an ordered byte-string sequence unambiguously.
ParallelHash
a SP 800-185 construction hashing large inputs in independent blocks.
HMAC
the RFC 2104/FIPS 198-1 keyed-hash MAC, generic over any underlying hash.
HKDF
the RFC 5869 two-stage (extract/expand) key-derivation function built on HMAC.
HMAC-DRBG
the SP 800-90A deterministic random-bit generator built on HMAC.
Length-extension attack
computing H(pad(m)‖pad(ext)) from H(m)/len(m) alone, inherent to bare Merkle-Damgård hashes.
Collision resistance
finding two distinct inputs with the same digest is infeasible.
Second-preimage resistance
given m, finding m' ≠ m with H(m') = H(m) is infeasible.
Preimage resistance
given a digest, finding any input producing it is infeasible.
Birthday bound
the ~√(2ⁿ) work threshold at which a collision becomes findable for an n-bit digest.
Constant-time code
code whose execution time is independent of secret data.
Side channel
any observable signal leaking information about a secret computation.
Timing attack
a side-channel attack exploiting execution-time variation.
SHA-NI
Intel's dedicated SHA-256 acceleration instruction-set extension.
SIMD
hardware parallelism executing one instruction across multiple data lanes.
Multi-buffer hashing
processing several independent messages together via SIMD lanes.
Lane (Keccak)
one of the 25 sixty-four-bit words composing the Keccak-f[1600] state.
Theta/rho/pi/chi/iota
the five round-function steps of Keccak-f[1600] (FIPS 202 Sec. 3.2).
CAVP / ACVP
NIST's Cryptographic Algorithm Validation Program (legacy / current), source of canonical hash conformance vectors.
Wycheproof
Google's cryptographic test-vector project, emphasizing edge-case and negative vectors.
Conformance vector
an (input, expected-output) pair used to validate an implementation.
Differential fuzzing
testing by comparing output against an independent implementation on the same random inputs.
Zeroization
overwriting sensitive memory with zeros in a compiler-defeating way, on drop.
Dispatch (runtime feature detection)
selecting among backends at runtime based on detected CPU capabilities.
Monomorphization
Rust's compile-time generation of a concrete function per generic type instantiation.
Reseed
supplying fresh entropy to a DRBG's internal state.
