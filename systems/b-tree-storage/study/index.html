30. Mental Models & First Principles

  1. MM1 — A B+tree is a sorted array that pays O(log n) to stay sorted under mutation. Predicts: fanout, not height, dominates capacity planning (§32 C1–C3). Bug class without it: engineers tune page size for "more levels of caching" instead of fanout, missing that a 4-level tree over 10M keys is already near-optimal (§16, §32).
  2. MM2 — The WAL is the source of truth; the data file is a cache of it. Predicts: the data file can be arbitrarily stale and recovery still works (I5). Bug class without it: writing data-file bytes before the WAL record is durable (§18.6) — the single invisible-data-loss bug.
  3. MM3 — A latch protects bytes in memory; a lock protects a logical entity across a transaction. Predicts: latches must never be held across a syscall (§20.7). Bug class without it: holding a page latch across a disk read, serializing every other descender behind a millisecond-scale I/O (§20).
  4. MM4 — Copy-on-write turns concurrency control into a garbage-collection problem. Predicts: snapshot isolation needs a reclaim policy (vacuum, I9), not a locking policy (§21). Bug class without it: reclaiming a page a live snapshot still needs (FM6, T9).
  5. MM5 — Every checksum is a bet about where corruption enters the system. Predicts: a per-page CRC catches disk-level corruption but not a logic bug that produces a well-formed wrong page (P13). Bug class without it: trusting a CRC pass as proof of correctness instead of proof of "unchanged since written" (§14, FM10).
  6. MM6 — Buffer-pool eviction is scheduling, not memory management. Predicts: eviction policy choice (CLOCK vs. LRU-K, ADR-07) is a throughput/fairness tradeoff, not a memory-safety one (memory safety comes from the pin discipline, I3). Bug class without it: conflating "which page to evict" with "is it safe to evict" — the latter is always I3, regardless of policy (§17).
  7. MM7 — Fanout is an amortization; height is a logarithm. Predicts: doubling dataset size changes tree height by roughly one level, not proportionally (§32 C3). Bug class without it: assuming a 10× larger dataset needs a 10× larger buffer pool to maintain the same hit rate — in fact only the leaf count grows linearly; internal levels barely move.
  8. MM8 — Group commit turns a per-transaction fsync cost into an amortized one. Predicts: commit throughput at high concurrency is bound by fsync rate ÷ batch size, not by transaction count (§32 C6). Bug class without it: fsync-ing on every single commit at high write concurrency, capping throughput at the raw fsync rate (~300–1,500/s, §4) instead of M4's 1.5M/s.

Reference Implementations

  • LMDB (mdb.c, mdb.h, midl.c, https://www.symas.com/lmdb). Lesson: the two-meta-page double-buffer dance for torn-write-safe root publication (§21.2). Pitfall not to copy: LMDB's single-level free-list ID list can fragment under heavy churn; document the freelist conservation invariant (I8) explicitly instead of inferring it from behavior. Applied in §21.
  • BoltDB / bbolt (db.go, bucket.go, node.go, freelist.go, tx.go, https://github.com/etcd-io/bbolt). Lesson: the smallest readable CoW B+tree; the Rust idiom here tracks bbolt's shape more than LMDB's C. Pitfall: bbolt's single-writer-blocks-on-mmap- remap behavior under file growth; this engine avoids mmap for the write path (ADR-15 discussion, §13.6). Applied in §21, §11.
  • SQLite (btree.c, pager.c, wal.c; file format at https://sqlite.org/fileformat.html). Lesson: the overflow-page chain format and the pagesize/4 inline threshold (ADR-19). Pitfall: SQLite's freelist trunk-page format optimizes for single-writer WAL-mode specifically; do not port it uncritically to a CoW-snapshot regime with concurrent live snapshots (I9). Applied in §14, §16.
  • InnoDB (storage/innobase/btr/, storage/innobase/mtr/, storage/innobase/log/, https://github.com/mysql/mysql-server). Lesson: latch-crabbing in a production concurrent B+tree, and the double-write buffer for torn-write protection (ADR-16). Pitfall: InnoDB's full MVCC/undo-log stack is far larger than this engine's redo-only Phase 0 — read it for latch protocol, not for a recovery-model template. Applied in §20, §18 (§35 row 5).
  • PostgreSQL nbtree (src/backend/access/nbtree/, https://github.com/postgres/postgres). Lesson: right-link-based concurrent descent independent of Lehman/Yao's original write-up. Pitfall: PostgreSQL's B-tree is not the primary heap storage (heap + index are separate); do not conflate its index-only concurrency model with this engine's heap-is-the-tree model. Applied in §20 (§35 row 2).
  • WiredTiger (https://github.com/wiredtiger/wiredtiger). Lesson: page-level compression and a row-store/column-store split above a common B-tree core. Pitfall: WiredTiger's eviction is driven by a dedicated eviction-server thread pool, not inline CLOCK; do not assume its threading model maps directly onto this engine's single async flusher (§17.5). Applied in §31.

RFCs / Specifications

  • SQLite File Format specification, https://sqlite.org/fileformat.html — the canonical documented on-disk page/overflow layout this engine's page codec (§14) is modeled after. Applied in §14, §11.
  • IEEE Std 1003.1 (POSIX.1-2017) / The Single UNIX Specification — fsync(), fdatasync(), pread(), pwrite() semantics; the pager's syscall contract (§13). Applied in §13, §18.

No formal RFC series governs embedded storage-engine wire formats; the two specifications above are the relevant normative references for this domain.

Glossary (§36) · 44 terms · site-wide glossary

ARIES
Algorithm for Recovery and Isolation Exploiting Semantics (Mohan et al. 1992); the canonical WAL-based recovery model this engine implements a redo-only subset of.
B+tree
a B-tree variant storing all data in leaves, linked by sibling pointers.
B-link tree
a B+tree variant adding a high-key and right-sibling pointer to every node for lock-free-ish concurrent descent (Lehman & Yao 1981).
Buffer pool
the fixed-size in-memory page cache between the tree and the pager.
Bulk load
the sorted-input, bottom-up tree-construction fast path (ADR-20).
Bw-tree
a lock-free B-tree variant using a mapping table and delta records (Levandoski et al. 2013).
Cell
the variable-length key(+value or +child-pgno) payload referenced by a slot.
Checkpoint
the operation that flushes dirty pages and advances the WAL's reclaimable boundary.
CLOCK
the one-reference-bit approximate-LRU eviction algorithm.
Copy-on-write (CoW)
never mutating a page in place; copying it and its ancestors instead.
CRC32C
the Castagnoli CRC-32 variant used for page/WAL checksums.
Dirty bit/bitmap
per-frame flag marking a page mutated since its last flush.
Double-write buffer
an InnoDB-style fixed staging region providing torn-write protection (deferred here).
Fanout
the number of children/cells a page holds.
fdatasync
a fsync variant skipping the inode metadata fence.
File header
page 0; magic, format version, page size.
Freelist
the linked list of reclaimable page numbers.
fsync
the syscall fencing a file's writes (and metadata) to durable storage.
Frame
one buffer-pool slot holding one page's bytes plus bookkeeping.
Group commit
batching multiple transactions' fsync calls into one.
Latch
an in-memory mutual-exclusion primitive scoped to one page operation.
Latch crabbing / lock coupling
holding at most two latches at a time while descending.
LSN (Log Sequence Number)
a monotonic identifier for a WAL record's position.
Meta page
the double-buffered page holding root_pgno, freelist_pgno, last_committed_lsn.
MVCC
multi-version concurrency control via version chains (deferred here).
Overflow page
a chained page holding a value too large to fit inline.
Page
the fixed-size unit of disk I/O and buffer-pool caching.
Pager
the sole file-I/O owner (pread/pwrite/fsync).
Pin/unpin
the reference-counting discipline preventing eviction of an in-use frame.
Prefix compression
storing a leaf's shared key prefix once, per page.
RTO (Recovery Time Objective)
the maximum acceptable time to reopen and recover after a crash.
Redo
reapplying a committed change during recovery.
Separator key
the internal-node key bounding a child subtree, possibly suffix-truncated.
Slot
a fixed-size array entry pointing at a cell's offset/length.
Slotted page
the header+slot-array+cell-area layout.
Snapshot
a long-lived handle pinning a tree version for repeated reads.
Suffix truncation
shortening a separator to the minimum distinguishing prefix.
Torn write
a page partially written before a crash, leaving an inconsistent byte image.
Undo
reverting an uncommitted change during recovery (deferred here, ADR-05).
Vacuum
the delayed-reclaim process freeing CoW pages no live snapshot needs.
WAL (Write-Ahead Log)
the append-only durability log written before data-file changes are made durable.
WAL segment
one fixed-size file in the WAL's rotating sequence.
Write amplification
extra bytes written per logical byte of user data (CoW ridge-copy, WAL double-write).
Write conflict
Error::WriteConflict, surfaced when a structural operation targets a still-pinned page. ---
