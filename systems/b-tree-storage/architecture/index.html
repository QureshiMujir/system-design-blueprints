Three properties hold throughout: (1) the data path is layered, not woven — the tree never touches a raw byte, the buffer pool never knows what a key is, the page codec never knows what a B+tree is, the pager never knows what a page's meaning is; (2) the WAL is the durability primitive (I5); every other component is an optimization against it — a page never written to disk is still recoverable from the WAL up to the last fsync'd record; (3) every cross-cutting concern (page size, key/value limits, error type, telemetry) is owned by btree-engine::config and threaded through — no layer reaches across another.

Boxes, one paragraph each. Public API is the only surface an embedding application sees; it never exposes a page number, a latch handle, or a buffer-pool-lifetime-bound byte slice. Engine owns the one live WriteTxn at a time and the registry of live Snapshots (I9). Tree is pure algorithm over pages fetched through the buffer pool; it holds latches, never raw file offsets. WAL is append-only bytes plus a replay function; it does not know what a page's contents mean, only that a record is (lsn, txn_id, kind, payload). Buffer Pool is a fixed-size cache with a pin discipline that makes eviction safe under concurrent access. Page Codec is a pure transform between bytes and (header, slots, cells); it never touches disk. Pager is the only file-descriptor owner in the process for a given Db.

8. Domain Model / Protocol / Data Model

8.1 On-disk page byte layout

byte 0                                                      pagesize-4  pagesize
┌────────────────┬──────────────┬───────────────┬───────────┬──────────┐
│ PageHeader(24B)│ Slot array   │  free space   │ Cell area │ CRC32C(4)│
│ pgno,kind,lsn, │ (grows right)│ (shrinks as   │(grows left│ trailer  │
│ n_cells,free_* │ sorted by key│  both grow)   │ from end) │          │
└────────────────┴──────────────┴───────────────┴───────────┴──────────┘

Cell (leaf, inline): [u32 key_len][u32 val_len][key bytes][val bytes]. Cell (leaf, overflow): [u32 key_len][u32 0][u64 first_overflow_pgno][u64 total_len][key bytes]. Cell (internal): [u32 sep_len][u32 0][u64 child_pgno][sep bytes]. All integers little-endian regardless of host (P14). File header (page 0) and the two meta pages (1, 2) use the same PageHeader + trailer layout as every other page (§12.2) — no special case.

8.2 WAL record wire format

+---------+---------+--------+---------+----------+------------+
| u64 lsn | u64 txn | u8 knd | 3B pad  | u32 plen | u32 crc32c |
+---------+---------+--------+---------+----------+------------+
| payload (plen bytes, kind-specific: Begin/PageWrite/FullPage/  |
| AllocPage/FreePage/SetMeta/Commit/Abort/Checkpoint)             |
+------------------------------------------------------------------+

CRC32C covers (lsn, txn_id, kind, plen, payload) (I12). Records never span a segment file; a record that would not fit is deferred to the next segment, padding the residual space of the current one with a kind == 0, plen == 0 sentinel.

8.3 Transaction state machine

From Event To Notes
— begin_write Active blocks if another WriteTxn is live (P3)
Active put/delete Active mutates the CoW ridge (§21.1), no disk I/O required yet
Active commit Committing WAL Commit record appended, flush_through called
Committing flush_through returns Ok Committed I1 satisfied; meta page swap follows
Committing I/O error on flush Aborted WAL Abort implied by absence of Commit durability
Active abort Aborted dirty pages discarded, no WAL record required for redo-only

8.4 Recovery state machine (redo-only, ADR-05)

From Event To
Start meta pages read, newer-valid selected (I10) Scanning
Scanning WAL walked from meta.last_committed_lsn + 1 Buffering
Buffering Commit(txn_id) seen Applying
Applying all buffered records for txn_id applied in LSN order (I14) Scanning
Buffering Abort(txn_id) seen Scanning (txn's records discarded)
Scanning bad CRC / truncated header Truncated (policy-gated, §18.7)
Truncated past last Commit Done (discard tail)

8.5 Worked example — insert causing a two-level split

Insert k=500 into a leaf at 100% fill (fanout 4, illustrative): (1) leaf full → allocate leaf R; (2) copy upper half of leaf L's cells into R; (3) R.next_sibling = L.next_sibling, L.next_sibling = R.pgno; (4) separator = R.cell(0).key; (5) insert (separator, R.pgno) into parent P; (6) if P is also full, recurse: allocate P', split, propagate (sep', P'.pgno) to grandparent; (7) if the root split, allocate a new root with two children, update meta root_pgno (§16.1, cites P2, I7, ADR-18).

8.6 Malformed-input example

A page whose header.free_off places the slot array past pagesize - 4 (the CRC trailer) is rejected at PageRef::new with Error::PageCorrupt(pgno) before any cell is dereferenced — bounds are checked against the header fields, never trusted (P13, conformance/corpora/pages/ leaf-bad-slot.bin, §14.8).

8.7 Failure-path example

kill -9 between the WAL pwrite succeeding and its fsync completing: on reopen, recovery reads the meta pages (I10), scans from last_committed_lsn + 1, and finds the un-fsync'd record either absent (if the kernel had not yet flushed the write to its page cache view — indistinguish- able from "never written") or present-but-un-committed (no matching Commit record) — either way the transaction is correctly treated as never-happened (I1, conformance/corpora/crash/ kill-after-pwrite.bin, §18.5).

Design principles (§6)

  • P1 — Crash safety is the ground truth. Every write that returns success from commit() is recoverable after kill -9 + power cut. Tradeoff: forbids any optimization that reorders the WAL-fsync-before-meta-write sequence (§18.6). Operational implication: crash-injection fixtures (§26) gate every release. Violating it: silent data loss indistinguishable from a correct system until the next crash.
  • P2 — The page is the unit of work. Buffer pool, WAL, checksum, and recovery all speak in whole pages; sub-page operations live only inside the codec. Tradeoff: some space waste on small values. Operational implication: every I/O is page-aligned, simplifying O_DIRECT (ADR-15). Violating it: partial-page writes reintroduce torn-write risk the CRC (I2) can't catch.
  • P3 — One writer, many readers. Concurrent writers are a Phase-1+ surface (§35 row 1); begin_write blocks a second caller, begin_read never blocks. Tradeoff: write throughput capped by one thread's WAL-append rate. Operational implication: no write-write conflict resolution code exists in Phase 0. Violating it (accepting concurrent writers without B-link or MVCC, §35 rows 2/4) corrupts the tree under concurrent structural mutation.
  • P4 — Snapshots are free for readers. A ReadTxn holds a root pgno + read-version; cost is one u64 + a refcount (§21.3). Tradeoff: CoW write amplification (every path from a modified leaf to the root is copied, §21.1). Operational implication: no reader-side locking at all. Violating it: a global lock for consistency defeats the entire design's read-scaling claim (M2).
  • P5 — The WAL is the durability boundary. A transaction is durable iff its commit record is fsync'd (I1). The data file may lag unboundedly. Tradeoff: recovery must replay from the last checkpoint, bounding startup time by WAL size (§32 C10). Operational implication: checkpoint cadence is an RTO lever (§24). Violating it: writing the meta page before the WAL fsync is the single bug class that loses committed data invisibly (§27 pitfall list).
  • P6 — No silent corruption. Every page and WAL record carries an independent CRC32C (I2, I12). A bad page surfaces as Error::PageCorrupt, never silently re-read or repaired. Tradeoff: a CRC-verified read costs one extra pass over the page bytes. Operational implication: repair is a separate, explicit btreectl repair subcommand. Violating it: silent auto-repair hides the operator signal that a device is failing.
  • P7 — No silent fallbacks. A requested O_DIRECT that is unavailable is a hard open error, not a silent downgrade; a short pwrite is a hard error, not a silent retry. Tradeoff: the engine refuses to "just work" on a misconfigured host. Operational implication: operators get one clear error, not a mysteriously slow or unsafe database. Violating it: silent retry under a different durability policy destroys the auditability the whole threat model (§22) depends on.
  • P8 — Latches do not nest unbounded. Lock coupling holds at most two latches at once (I6, §20.2), releasing the parent once the child is safe. Tradeoff: a split/merge that propagates to the root holds latches up the whole path — bounded but rare. Operational implication: a per-thread debug-build latch-stack assertion catches order violations before they become deadlocks. Violating it: unbounded latch nesting is the direct cause of the B-tree deadlocks that take a week to debug (§27).
  • P9 — Allocation is bounded. A WriteTxn's dirty-page budget (default 64 MiB) triggers a flush, never an OOM (§4). Tradeoff: a pathological single transaction is throttled, not allowed to run unbounded. Operational implication: budget exhaustion is a metric (btree_buffer_pool_dirty_pages), not a kernel OOM-killer event. Violating it moves the failure mode from "visible in telemetry" to "invisible until the kernel kills the process."
  • P10 — One config struct, one error enum, one telemetry trait. All knobs on DbOptions; all errors are Error variants; all metrics flow through Telemetry (§11.4). Tradeoff: no plugin runtime — new behavior ships behind a cfg(feature) flag, recompiled. Operational implication: one place to look for every tunable. Violating it (scattering config across ad hoc globals) is what makes production incidents take hours instead of minutes to diagnose.
  • P11 — Recovery is idempotent. Replaying the same WAL range N times produces the same on-disk state as replaying it once (I14): a redo record applies only if the target page's header.lsn < record.lsn. Tradeoff: every page carries its own LSN, one extra 8-byte field. Operational implication: a stuck recovery can be safely re-run without a special "already partially recovered" state. Violating it makes crash-during-recovery an unrecoverable state.
  • P12 — The buffer pool is the only path to disk. No component but the async flusher (§17.5) issues a pwrite to the data file after Phase 5 lands. Tradeoff: every read/write, even inside the tree, goes through pin/pin_mut (§11.3). Operational implication: the WAL ordering rule (I4) has exactly one enforcement point. Violating it (a component bypassing the pool) breaks I4 silently — a page can become durable before its log record.
  • P13 — Checksums are structural, not semantic. CRC32C proves "these bytes are what was written," never "these bytes are meaningful" (a well-formed-but-wrong key still passes CRC). Tradeoff: the codec still needs bounds checks (cell offsets inside the page) independent of the CRC. Operational implication: fuzzing (§26, fuzz_targets/page_codec.rs) targets logic bugs the CRC cannot catch. Violating it (treating a CRC pass as "this page is correct") lets a bounds-check bug slip past code review.
  • P14 — Every locked on-disk format is versioned. Page size, WAL record layout, and file magic are all read from the header at open (§8.1), never assumed from a compile-time constant alone. Tradeoff: one extra field (format_version) per format. Operational implication: a future format change can detect and refuse (or migrate) an old file instead of misreading it. Violating it turns every future format change into a silent misinterpretation of old files.
