Three properties, referenced throughout. First, the data path is one-way at every layer: the poller produces raw kernel events, the reactor translates them into wakeups, the executor consumes wakeups and polls futures, futures hand intent back down. The reactor never calls up into user code (I3). Second, the four poller backends present one trait (§11.3); the reactor never branches on backend type outside Builder::build() (P2, I11). Third, the completion path is structurally distinct: epoll/kqueue/IOCP-readiness answer "tell me when this is ready," io_uring answers "do this, tell me when it is done." Conflating them produces a leaky abstraction that always favours one model (ADR-06, §37 Alt 2).

Per-box responsibility. elr-net is the user-facing async I/O surface; it registers with the reactor and dispatches to the readiness or completion path per Builder configuration (§20.7). elr-runtime owns task lifecycle, scheduling, and the poll budget; it is the only crate that allocates a RawTask. elr-channel/elr-timer/elr-trace/elr-blocking are peer subsystems the executor drives every worker-park cycle. elr-reactor is the sole owner of the per-FD Source table and the only crate that calls into elr-poller. elr-poller is four independent, symmetric backend implementations behind one trait; elr-uring is a sibling, not a subtype, of that trait. elr-c-abi is the only crate exposed to non-Rust code; every other crate is an internal implementation detail from the embedder's point of view.

The elr-* crate-name convention is normative (§10); do not re-imagine it.

8. Domain Model / Protocol / Data Model

8.1 Task Lifecycle State Machine

State Trigger Next State Side Effect
Idle (allocated, not yet scheduled) spawn() returns Scheduled pushed to local deque or inject queue (§18.5)
Scheduled worker pops it Running Header::vtable.poll invoked
Running Poll::Pending returned, waker registered Idle (parked) waker stored on a Source/timer/channel slot
Running Poll::Ready(out) returned Completed output stored, JoinHandle waker fired
Idle (parked) matching waker fires Scheduled re-pushed to a deque or inject queue
any non-Completed state JoinHandle/TaskGroup dropped Cancelled (I5) cancellation bit set, task woken to observe it at next poll
Cancelled next poll observes the bit Completed (aborted) future dropped in place, all its Drop impls run

8.2 Source Readiness State Machine (per direction)

Unregistered -> Registered -> Ready -> Draining -> Registered (loop) -> Deregistered. Registered -> Ready on a kernel event matching the interest mask; Ready -> Draining when a future's poll_read/poll_write observes it; Draining -> Registered when the read/write call returns EAGAIN (I1) — the future re-registers its waker and returns Pending; any state -> Deregistered on Source::drop (I3 governs safe waker teardown here).

8.3 Timer Wheel Cascade (ASCII)

level 0 (1ms/slot, 256 slots) --cascade at wrap--> level 1 (256ms/slot)
level 1                        --cascade at wrap--> level 2 (65.5s/slot)
level 2                        --cascade at wrap--> level 3 (4.66h/slot)
level 3..7                     --cascade--------->  up to ~600y coverage
insert(deadline): pick the lowest level where (deadline - cursor) fits 8 bits, push_front
advance_to(now): drain level-0's current slot; entries due now fire; not-yet-due entries
                 re-insert (cascade); cursor += 1ms; on cursor%256==0, cascade next level

Named states: Pending (linked into a slot) → Cascading (re-inserted one level down during a wrap) → Fired (waker invoked) or Cancelled (I4, unlinked before firing).

8.4 io_uring SQE/CQE Lifecycle

State Trigger Next State Malformed-input handling
Built opcode::*::new(...).build() Submitted n/a
Submitted Submitter::submit enqueues the SQE InFlight kernel rejects malformed SQE synchronously (submit returns Err)
InFlight kernel completes the operation Completed CQE res < 0 maps to an io::Error from -res as errno (I10 keeps the buffer alive throughout)
InFlight the ring is torn down before completion Cancelled IORING_OP_ASYNC_CANCEL or ring drop; buffer released only after Cancelled is observed
Completed CQE drained and matched by SubmissionToken terminal a CQE with no matching pending token (double-completion, IORING_FEAT_NODROP bug) is logged and dropped, never dereferenced (FM5)

8.6 Worked Example — Echo Connection End to End

  1. TcpListener::accept().await registers Source (Read interest) with the reactor (§15.1).
  2. Reactor turn() blocks in poller.poll; kernel reports the listener readable.
  3. Accept future wakes, accept(2) returns a connected fd; TcpStream registers its own Source.
  4. spawn(handler) pushes a task onto the accepting worker's local deque (§18.5, wait-free, I7).
  5. Handler calls stream.read(&mut buf).await; if EAGAIN, registers a read waker (I2) and returns Pending; the task parks.
  6. Client sends bytes; kernel event delivered; reactor turn() finds the Source, wakes the handler's waker outside the source-table lock (I3); task re-scheduled.
  7. Handler drains to EAGAIN (I1), calls write_all().await, same registration dance on the write direction, then loops to step 5 or completes and drops its Source (deregister).

8.7 Malformed-Input / Failure-Path Examples

  • kqueue interleaved EV_ERROR. A single kevent() call can return error flags interleaved with real events; the consumer must check flags & EV_ERROR per event and treat data as errno rather than assuming every returned kevent is a successful readiness signal (§14.6 pitfall).
  • A task holds std::sync::Mutex across .await. Worker A acquires the mutex, yields at an .await; a different task is scheduled onto the same worker and blocks trying to acquire the same mutex — a self-deadlock, because std::sync::Mutex is not async-aware and blocks the thread, not just the task (FM4-adjacent but distinct from a missed-wakeup bug — this is a genuine correctness bug in user code that the runtime cannot detect at compile time; the idle-detector, §22.3, is the production-visible symptom).

Design principles (§6)

  • P1 — Cooperative scheduling is the contract. A future that does not yield is an application-layer bug; the idle-detector (§22.3) detects and surfaces it, never preempts it. Tradeoff: no fairness guarantee against a misbehaving task. Operational implication: one stuck task can starve a whole worker (FM1). Violated: the cost model in §35 #2 collapses — throughput becomes a function of the worst task, not the aggregate.
  • P2 — One reactor, four pollers. The reactor talks to dyn Poller (I11); the four backends live in crates/elr-poller/src/{linux,bsd,windows}/. Tradeoff: dynamic dispatch vs. monomorphisation (ADR-02). Operational implication: one code path to debug per OS regardless of platform. Violated: platform-specific bugs multiply across the reactor instead of staying contained in one backend file.
  • P3 — The completion-based path is structurally distinct. io_uring is elr-uring's Submitter, not a fifth Poller (ADR-06). Tradeoff: two trait surfaces instead of one. Operational implication: TcpStream dispatches at construction time, zero runtime branching cost. Violated: forcing completion semantics through a readiness facade caps every io_uring-only optimisation (multishot accept, fixed buffers) at the readiness model's ceiling.
  • P4 — Wakers are reference-counted, not boxed trait objects. A RawWaker vtable (clone/wake/wake_by_ref/drop) over a Header pointer; zero heap allocation in the wakeup path (ADR-21). Tradeoff: unsafe vtable plumbing vs. safe Box<dyn Wake>. Operational implication: directly gates M7 (§35 #7). Violated: every wakeup allocates and frees, and M7's ≤1µs ceiling is unreachable.
  • P5 — Cancellation is drop-cancellation. Dropping a JoinHandle (or its owning TaskGroup) is the only cancellation path (ADR-09, I5). Tradeoff: no synchronous "cancel and wait" primitive distinct from drop. Operational implication: leaks are structurally impossible inside a TaskGroup scope. Violated: two cancellation paths means two answers to "did cancellation complete," and FM8 becomes unfixable.
  • P6 — Backpressure is the user's responsibility, not the runtime's. Bounded channels only by default (ADR-10, I8); a full producer blocks, never drops silently. Tradeoff: the user must choose a capacity. Operational implication: memory growth is bounded and observable (elr_channel_capacity_gauge). Violated: an unbounded default turns every slow consumer into an unbounded-memory-growth incident (T6).
  • P7 — Time is owned by the timer wheel, not the OS. The reactor's poll timeout is always timer_wheel.next_deadline() - now, never a caller-supplied raw duration (I9). Tradeoff: an extra layer of indirection over "just call epoll_wait(timeout)". Operational implication: O(1) insert/cancel for every timer regardless of count (§17.1). Violated: the kernel's millisecond-rounding becomes the lower bound on timer accuracy and cancellation becomes O(n) (FM3).
  • P8 — Files are not async on Linux without io_uring. epoll does not deliver readiness on regular files; the offload thread pool is the honest default, io_uring is opt-in (ADR-11). Tradeoff: a thread-pool hop costs latency the completion path avoids. Operational implication: Builder::max_blocking_threads is a real capacity knob (C11–C12). Violated: pretending file I/O is uniformly async is the lie that costs a production team a week debugging a blocked worker (FM1).
  • P9 — DNS is offloaded to a thread pool. getaddrinfo blocks; there is no portable async DNS in the OS. The offload pool is the default; c-ares is deferred (PhaseDeferred("§21.2")). Tradeoff: resolution latency tail under packet loss. Operational implication: the DNS-Resolver-from-Scratch project (rank 65) is the from-scratch consumer; this runtime ships only the glue. Violated: a from-scratch async DNS stack duplicates a sibling project's entire scope.
  • P10 — Zero allocation on the hot path. Reactor turn, future poll, waker wake, channel recv must be allocation-free in steady state; each crate's CI gates this with dhat (M8). Tradeoff: fixed-capacity data structures (ring buffers, inline task storage) over dynamic ones. Operational implication: the allocator is never a suspect in a latency-tail investigation. Violated: a hot-path regression fails CI, not a customer's SLO, by design.
  • P11 — No global state. Runtime is a value from Builder::new().build() (ADR-15, I13); multiple runtimes coexist in one process. Tradeoff: every API takes or captures a Runtime handle instead of using a global spawn. Operational implication: embeddable as a library, testable in isolation. Violated: "which runtime does the C ABI use" becomes unanswerable the moment two are constructed.
  • P12 — Determinism is a stretch goal. Builder::deterministic_test_runtime() gives a single-threaded, deterministic-poll-order executor for property tests; work-stealing and OS scheduling defeat determinism everywhere else. Tradeoff: the deterministic mode cannot exercise multi-thread bugs. Operational implication: property tests are reproducible; soak tests are not. Violated: without it, every flaky property-test failure is unreproducible.
  • P13 — Observability is built in, not bolted on. Spans, metrics, and the idle-detector are Phase 10 first-class citizens, not an optional feature flag (ADR-12, ADR-18, ADR-19). Tradeoff: a small span-creation cost on every task/IO boundary in dev builds. Operational implication: tokio-console connects to any Builder::trace_console-enabled runtime with zero bespoke tooling. Violated: the first production incident becomes a redeploy-with-more- logging cycle instead of a live tokio-console session.
  • P14 — Every unsafe block is paired with a proof obligation. A // SAFETY: comment plus a miri and/or loom CI gate (ADR-17). Tradeoff: CI time (loom is exponential in atomic count; tests must stay small). Operational implication: T8 (memory corruption via unsafe) is caught before merge, not in production. Violated: an unreviewed unsafe block is undetectable until a fuzz run or a customer finds the aliasing bug; the gate exists precisely to move that discovery left of merge.
