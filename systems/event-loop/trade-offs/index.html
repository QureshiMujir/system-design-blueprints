Decisions (§9) · 22 ADRs

ADR-01

Runtime implementation language

Chosen

Rust 1.78+

Rejected

Go; C++

When the rejected choice is right

Go wins when the team wants the event loop hidden behind a compiler-integrated M:N scheduler and does not need library embeddability (§37 Alt 3)

Why: Borrow-checked Source/Waker lifetimes catch double-drop/use-after-free at compile time; Rust's zero-cost async/await fits P2's "one reactor, many backends" shape

ADR-02

Poller dispatch mechanism

Chosen

dyn Poller at runtime, T: Poller in tests

Rejected

Generic monomorphisation everywhere

When the rejected choice is right

Monomorphisation wins in a single-target embedded build where compile time is irrelevant and binary size/inlining matters more than the syscall-dominated delta

Why: <1% hot-path delta (dominated by the syscall, not the vtable) vs. materially worse compile times and codegen size with 4 monomorphised backends

ADR-03

Readiness trigger mode

Chosen

Edge-triggered EPOLLET / kqueue EV_CLEAR / IOCP completion

Rejected

Level-triggered epoll/kqueue

When the rejected choice is right

Level-triggered wins for a low-connection-count (<1K) tool where re-arm cost is irrelevant and the simpler drain-once-per-event model reduces bug surface

Why: level-triggered re-arms a thundering herd of writable events every loop turn at scale (Banga/Mogul/Druschel 1999, §5)

ADR-04

Scheduling model

Chosen

Cooperative, no preemption

Rejected

Signal-driven preemption; compiler-injected yield points (Go-style)

When the rejected choice is right

Compiler-injected preemption wins when the team owns the compiler too, as Go's does — not available to a library crate targeting stable Rust

Why: Preemption needs async-signal-safe stack rewinding or compiler+runtime co-design; disproportionate cost at this scope (P1)

ADR-05

Source registration lifetime

Chosen

Borrows &Reactor (non-'static)

Rejected

'static (mio's model)

When the rejected choice is right

'static wins when the embedding API must hand out Source handles that outlive any borrow scope the caller controls, as mio must for its C-adjacent embedding story

Why: Avoids forcing every TcpStream to be heap-allocated/pinned just to satisfy a 'static bound

ADR-06

io_uring integration shape

Chosen

Separate Submitter trait (elr-uring)

Rejected

A fifth Poller backend

When the rejected choice is right

A unified trait wins when a codebase only ever needs the lowest-common-denominator subset (plain read/write) and values one call site over peak throughput

Why: Readiness ("tell me when ready") and completion ("do this, tell me when done") are different questions; unifying them caps every completion-only optimisation at the readiness ceiling

ADR-07

Timer data structure

Chosen

Hashed Hierarchical Timer Wheel, 8 levels, 1ms slot

Rejected

Binary heap of deadlines

When the rejected choice is right

A binary heap wins at low timer counts (<1K) where its simplicity and exact-ordering iteration outweigh the wheel's cascade bookkeeping

Why: O(1) insert/cancel vs. O(log n); at 1M connections with 30s idle timers, heap fixup cost dominates the reactor turn

ADR-08

Multi-thread scheduling

Chosen

Chase-Lev work-stealing deque per worker + global inject queue

Rejected

A single shared run queue

When the rejected choice is right

A single shared queue wins on a 1–2 core target, where contention stays negligible and the extra steal-coordination code is pure overhead

Why: A shared queue is a contention point past ~4 cores; work-stealing distributes steal cost across siblings

ADR-09

Cancellation API

Chosen

Drop-cancellation only (JoinHandle::drop)

Rejected

An explicit task.cancel() method

When the rejected choice is right

An explicit cancel() wins when cancellation must be requested without giving up ownership of the handle — e.g. a supervisor that cancels but still wants to .await the JoinError afterward; that shape needs a distinct API this project deliberately omits (embedders needing it wrap JoinHandle themselves)

Why: Two cancellation paths raise "does cancel() complete synchronously?"; drop-cancellation is structurally leak-proof inside a scope

ADR-10

Channel default capacity

Chosen

Bounded by default; unbounded behind explicit opt-in + clippy lint

Rejected

Unbounded channels as the default

When the rejected choice is right

Unbounded wins for a bursty, bounded-lifetime pipeline (e.g. a one-shot batch fan-out) where the producer's total output is known in advance to be small

Why: An unbounded default is a backpressure violation and a memory leak waiting on every slow consumer

ADR-11

File/DNS async strategy

Chosen

Thread-pool offload, libuv-style, adaptive n_cpu→4×n_cpu

Rejected

POSIX aio; pretend epoll handles regular files

When the rejected choice is right

io_uring's direct file ops win once the fleet is Linux-only on kernel ≥5.6 and offload's thread-hop latency is the bottleneck (ADR-06 is the escape hatch, opt-in)

Why: epoll does not poll regular files; POSIX aio is widely considered unreliable/under-supported across platforms

ADR-12

Tracing wire protocol

Chosen

tokio-console's console-api protocol

Rejected

A bespoke tracing protocol

When the rejected choice is right

A bespoke protocol wins when the runtime's task model diverges enough from Tokio's that the console's schema cannot express it — not the case here, since the task/span model is intentionally Tokio-shaped

Why: Building a parallel ecosystem duplicates compounding upstream effort for no differentiated value

ADR-13

C ABI shape

Chosen

Custom handle-based API (libelr.so)

Rejected

A libuv-API-compatible clone

When the rejected choice is right

A libuv-clone wins when the primary goal is a drop-in replacement for an existing libuv embedder with zero source changes — exactly the deferred stretch surface (PhaseDeferred("§24.6"))

Why: libuv's API is callback-based; a handle-based API is more ergonomic from Go(cgo)/Python(cffi) callers that already have their own event loops

ADR-14

Licensing

Chosen

Apache-2.0 OR MIT dual licence on runtime crates

Rejected

Single-licence (Apache-2.0 only, or MIT only)

When the rejected choice is right

A single stricter licence (e.g. AGPL) wins for a hosted-service business model that wants to prevent unmodified redistribution — reserved instead for the ELv2-licensed hosted control plane, a Phase-2+ surface, not the runtime itself

Why: Matches the Rust ecosystem norm; maximises downstream compatibility

ADR-15

Runtime instantiation

Chosen

Value type via Builder::new().build(), no global

Rejected

A process-wide static runtime (Tokio's #[tokio::main] convenience model)

When the rejected choice is right

A global convenience runtime wins for application-level ergonomics where exactly one runtime will ever exist in the process — the common case for a top-level Tokio binary, not for an embeddable library

Why: A static runtime makes embedding ambiguous (which runtime does the C ABI use?) and complicates test isolation

ADR-16

Async DNS strategy

Chosen

Offload via getaddrinfo (default); c-ares deferred

Rejected

c-ares integration in Phase 0

When the rejected choice is right

c-ares wins once sustained resolver QPS exceeds the offload pool's thread-hop throughput (Deferred Features Register)

Why: Offload covers every scale below ~50K simultaneous resolutions/sec; building c-ares integration before the offload path ships is premature optimisation

ADR-17

Concurrency/UB verification

Chosen

loom (concurrency-model exhaustion) + miri (UB detection) in CI

Rejected

Manual code review only

When the rejected choice is right

Manual review alone is acceptable only for code with zero unsafe and zero shared mutable state — true of almost nothing in elr-runtime/elr-reactor

Why: Manual review does not exhaustively check thread interleavings or catch aliasing UB; P14

ADR-18

Distributed tracing export

Chosen

OpenTelemetry (OTLP-gRPC, OTLP-HTTP fallback), optional

Rejected

No tracing export; a bespoke exporter

When the rejected choice is right

No export wins for a single-process embedded deployment with no centralized observability stack — the feature is optional precisely for this case

Why: OTLP is the de facto standard; building a bespoke exporter duplicates effort for no gain

ADR-19

Metrics exposure

Chosen

Runtime exposes counters/gauges via Runtime::metrics() and the C ABI; embedder serves them

Rejected

The runtime serves its own Prometheus HTTP endpoint

When the rejected choice is right

The runtime serving its own endpoint wins for a zero-config standalone binary where there is no embedder to delegate to — outside this project's embeddable-library scope

Why: Serving HTTP is a policy decision (which port, which auth) that belongs to the embedder, not the runtime (P11-adjacent: no global state, no global listener either)

ADR-20

Build reproducibility

Chosen

Nix flake (pinned compiler, glibc, kernel headers)

Rejected

Plain cargo build with no pinning

When the rejected choice is right

Plain cargo build wins for a quick local iteration loop where reproducibility across machines is not yet a concern (pre-Phase-0 prototyping)

Why: io_uring feature detection and FFI ABI stability need a pinned toolchain; unpinned builds drift silently across CI runners

ADR-21

Waker representation

Chosen

RawWaker vtable over a ref-counted Header pointer, zero allocation

Rejected

Box<dyn Wake> (the ergonomic std-library-adjacent path)

When the rejected choice is right

Box<dyn Wake> wins for application code with no hot-path latency requirement, where the ergonomic std::task::Wake trait is worth the allocation — not acceptable inside the runtime itself

Why: Directly gates M7 (§35 #7); a boxed trait object allocates and frees on every wake

ADR-22

Listener fan-out

Chosen

EPOLLEXCLUSIVE (Linux) / one-shot kqueue registration per accept

Rejected

N workers each with their own independent accept() loop on a shared listener, no exclusive flag

When the rejected choice is right

Independent per-worker accept loops without the exclusive flag win only on kernels/BSDs where EPOLLEXCLUSIVE/one-shot semantics are unavailable — a compatibility fallback, not a design preference

Why: Prevents the thundering-herd wakeup where every worker wakes for one incoming connection and all but one re-park (FM6)

Roads not taken (§37)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt 1 — Thread-Per-Connection (Blocking I/O)

conn1 -> [OS thread, blocked in read()]
conn2 -> [OS thread, blocked in read()]
 ...
connN -> [OS thread, blocked in read()]     (N OS threads, N stacks)

Regime where it wins: < 10,000 connections, where simplicity of code (no async/await, no reactor) outweighs per-thread cost. Real system: classic Apache prefork/worker MPM; early Java servlet containers (Tomcat's BIO connector). Why rejected: default 8MB thread stacks × 1,000,000 connections is not feasible (§35 #6's math scales directly: 8MB × 1M = 8TB), and context-switch overhead dominates well before reaching C1's target — this is precisely the C10K problem Kegel (1999, §5) named.

Alt 2 — Pure Completion-Based, io_uring-Only (Drop Readiness Entirely)

app -> SQE -> [io_uring kernel ring] -> CQE -> app     (no epoll/kqueue/IOCP path at all)

Regime where it wins: Linux-only fleets on kernel ≥5.6 with no portability requirement. Real system: Glommio (a thread-per-core, io_uring-only Rust runtime). Why rejected: macOS/Windows/older-kernel portability is a hard requirement (§1 non-goals explicitly reject Linux-only scope for this project); MM7 names exactly why forcing every platform through one model degrades the others.

Alt 3 — Green Threads / M:N with Full Stack Switching (Goroutine-Style)

[user-space stack A] -\
[user-space stack B] --> [M:N scheduler, compiler-inserted safepoints] -> OS threads
[user-space stack C] -/

Regime where it wins: workloads that want synchronous-looking code with zero async/await function-coloring. Real system: Go's runtime (goroutines + netpoller, §5, §34). Why rejected: requires compiler-and-runtime co-design (safepoint injection, segmented/growable stacks) unavailable to a library crate targeting stable Rust — ADR-01's rejection of Go as the implementation language is this exact argument restated at the language-choice level.

Alt 4 — Shared-Nothing, Shard-Per-Core (No Work Stealing)

core0: [reactor0] <- NIC RSS queue0   (connections pinned at accept-time, never migrate)
core1: [reactor1] <- NIC RSS queue1
core2: [reactor2] <- NIC RSS queue2

Regime where it wins: extremely high single-core efficiency on NIC-receive-side-scaling- aligned workloads with even connection distribution. Real system: Seastar (ScyllaDB's C++ framework). Why rejected: accept-time pinning with no cross-core migration starves under skewed load — exactly the failure mode work-stealing (ADR-08) exists to prevent, at the accepted cost of steal-coordination overhead (§32's named bottleneck #3).
