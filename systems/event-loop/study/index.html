33. Mental Models & First Principles

Eight compressed insights, MM1–MM8. Each predicts a class of correct design and names the bug class an engineer writes without it.

  1. MM1 — A Future is a state machine; the executor is its clock. Predicts: nothing runs until polled, and progress is entirely demand-driven. Bug class without it: assuming a spawned future executes "in the background" the instant it's created, rather than at its next poll — leading to code that waits on a result that was never actually driven forward. Applies at §16 (executor), §8.1 (task lifecycle).
  2. MM2 — Edge-triggered readiness is a doorbell, not a mailbox. Predicts: a notification means "something changed," not "here is all the data" — the consumer must drain until told otherwise. Bug class without it: reading once per notification and stalling forever on buffered-but-undelivered data (I1). Applies at §14 (pollers), §21.2 (elr-net).
  3. MM3 — The reactor is a translator, never a decision-maker. Predicts: the one-way data path (poller → reactor → executor → futures) means the reactor never needs application-level context to do its job. Bug class without it: routing business logic into the reactor "for efficiency," coupling a translation layer to policy and making both harder to test in isolation. Applies at §3 (architectural overview), §15 (reactor).
  4. MM4 — Time is a first-class scheduled resource, not a syscall parameter. Predicts: O(1) timer operations regardless of count, because the wheel owns time instead of a raw kernel-timeout value per call. Bug class without it: passing a caller-derived timeout straight to epoll_wait and discovering that cancelling ten thousand of them is O(n) each (P7). Applies at §17 (timer wheel).
  5. MM5 — Cancellation is a message, not a stack unwind. Predicts: a cancelled task keeps running to its next poll point before tearing down, never mid-instruction. Bug class without it: expecting synchronous, immediate cancellation semantics (like a thread kill) and being surprised when a task's Drop runs one scheduling quantum later than requested (I5, P5). Applies at §19 (structured concurrency).
  6. MM6 — Work-stealing turns idle CPUs into a distributed load balancer. Predicts: aggregate throughput approaches the sum of per-core capacity even under uneven task arrival, because idle workers actively redistribute load rather than waiting for a central dispatcher. Bug class without it: assuming a single shared run-queue scales linearly with core count, and being surprised by contention collapse past ~4 cores (ADR-08). Applies at §18 (multi-thread executor).
  7. MM7 — A completion model and a readiness model are different questions to the kernel, not different answers to the same question. Predicts: unifying them at one abstraction layer always degrades one to match the other's shape. Bug class without it: trying to retrofit io_uring's multishot/fixed-buffer wins onto a readiness-shaped API and discovering the abstraction cannot express the optimisation at all (ADR-06, P3). Applies at §20 (io_uring), §37 (Alternative Architectures).
  8. MM8 — Backpressure is a signal that must propagate, not a queue that must grow. Predicts: a bounded system surfaces "I am overloaded" as an observable blocking condition upstream, rather than absorbing it invisibly until memory runs out. Bug class without it: an unbounded channel or connection-accept path turning a slow consumer into a silent, delayed-onset OOM incident instead of an immediate, debuggable backpressure signal (P6, I8). Applies at §19 (channels), §4 (system constraints).

5. Required Reading

Read in this order; the foundational papers first. Every entry names where its idea is applied.

Books

  • Kerrisk, M. 2010. The Linux Programming Interface. No Starch Press. Chapters 63 (epoll, poll, select), 22 (signals), 33 (threads), 61 (sockets). Applied in §14 (pollers), §21.5 (signalfd/self-pipe).
  • Stevens, W. R., Fenner, B., Rudoff, A. M. 2003. UNIX Network Programming, Volume 1: The Sockets Networking API (3rd ed.). The reference for every socket primitive. Applied in §21 (elr-net).
  • Stevens, W. R., Rago, S. A. 2013. Advanced Programming in the UNIX Environment (3rd ed.). Chapters on signals, threads, and process control. Applied in §21.5–21.6 (signals, child processes).
  • Arpaci-Dusseau, R. H., Arpaci-Dusseau, A. C. 2018 (continuously updated). Operating Systems: Three Easy Pieces. Scheduling and concurrency fundamentals. Applied in §6 (P1, cooperative scheduling) and §16 (executor).
  • Herlihy, M., Shavit, N. 2012 (rev. ed.). The Art of Multiprocessor Programming. Morgan Kaufmann. Lock-free data structures and memory-model foundations. Applied in §18 (Chase-Lev deque) and §19 (channels).
  • Gregg, B. 2020. Systems Performance (2nd ed.). Addison-Wesley. Tail-latency analysis, syscall/allocation profiling methodology. Applied in §31 (Performance Engineering).

Papers

  • Kegel, D. 1999 (rev. 2014). The C10K Problem. kegel.com/c10k.html. The option matrix (thread-per-connection, process-per-connection, multiplexed select/poll/epoll/kqueue, POSIX aio). Applied in §9 ADR table and §37 (Alternative Architectures).
  • Banga, G., Mogul, J. C., Druschel, P. 1999. A Scalable and Explicit Event Delivery Mechanism for UNIX. USENIX ATC. The API argument for kqueue/epoll: edge- vs level-triggered, separate registration. Applied in ADR-03, §14.
  • Varghese, G., Lauck, A. 1987. Hashed and Hierarchical Timing Wheels. SOSP. The data structure §17 implements; the SOSP version contains the cascade trick. Applied in §17.
  • Varghese, G., Lauck, A. 1996. Hashed and Hierarchical Timing Wheels: Efficient Data Structures for Implementing a Timer Facility. ACM ToN. The polished revision. Applied in §17.
  • Chase, D., Lev, Y. 2005. Dynamic Circular Work-Stealing Deque. SPAA. The deque §18 ports. Applied in §18.3.
  • Le, N. M., Pop, A., Cohen, A., Zappa Nardelli, F. 2013. Correct and Efficient Work-Stealing for Weak Memory Models. PPoPP. The memory-ordering proof for push/pop/steal. Applied in §18.7 (memory ordering pitfall), I7.
  • Vyukov, D. 2014. Bounded MPMC Queue and Intrusive MPSC Node-Based Queue. 1024cores.net. The reference algorithms behind the inject queue and channels. Applied in §18.4, §19.4.
  • Axboe, J. 2019 onward. io_uring kernel documentation (Documentation/io_uring.rst) and the kernel.dk engineering posts ("Efficient IO with io_uring", "Faster IO through io_uring"). Applied in §20.
  • Graham, R. 2013. The Secret to 10 Million Concurrent Connections (the "C10M manifesto"). OS-tuning angle: FD limits, ephemeral-port exhaustion, conntrack sizing. Applied in §4 (C13, C18), §35 #10.
  • Hoff, T. 2014. The WhatsApp Architecture Facebook Bought For $19 Billion. HighScalability.com. The ~2M-connections-per-host record and its socket-buffer-tuning technique. Applied in §35 #1, §32.

Reference Implementations

  • Tokio (tokio-rs/tokio) — runtime/scheduler/multi_thread/worker.rs, runtime/io/driver.rs, time/driver/wheel/mod.rs, sync/mpsc/, task/. Read as a reference, not a copy target; the work-stealing logic is the cleanest published Rust statement of the algorithm. Applied in §18, §17, §19.
  • libuv (libuv/libuv) — src/unix/core.c, src/unix/linux-core.c, src/unix/kqueue.c, src/win/core.c, src/threadpool.c, src/unix/getaddrinfo.c, include/uv.h. The offload-boundary reference. Applied in §21.7–21.8, ADR-11.
  • mio (tokio-rs/mio) — src/sys/{unix/epoll,unix/kqueue,windows/iocp}, src/poll.rs. The portable-poller reference; elr-poller diverges on Source lifetime (ADR-05). Applied in §14.
  • Boost.Asio (boostorg/asio) — boost/asio/io_context.hpp, boost/asio/detail/scheduler.ipp, boost/asio/detail/epoll_reactor.ipp. The proactor-vs-reactor reference. Applied in §34 (Comparative Architecture), ADR-06.
  • Netty (netty/netty) — io.netty.channel.nio.NioEventLoop, io.netty.channel.epoll.EpollEventLoop. The event-loop-per-thread + Channel reference. Applied in §34.
  • io-uring crate (tokio-rs/io-uring) — src/squeue.rs, src/cqueue.rs, src/types.rs. The thinnest safe SQE/CQE wrapper; elr-uring adds executor-aware machinery on top. Applied in §20.2, §20.3.
  • Go runtime netpoller (golang/go) — src/runtime/netpoll.go, src/runtime/netpoll_epoll.go, src/runtime/proc.go. The hidden-event-loop-inside-a-scheduler reference; the M:N goroutine model this project's ADR-01 explicitly rejects as our substrate. Applied in §34, §37 Alt 3.
  • Node.js (nodejs/node) — src/node.cc, lib/internal/process/per_thread.js. How a single-threaded event loop with a thread pool is exposed to an application layer; the shape elr-c-abi exposes to embedders. Applied in §24.

RFCs / Specifications

  • POSIX.1-2017 (IEEE Std 1003.1-2017) — Signal Concepts, Threads, Thread Cancellation chapters. Applied in §21.5 (signal handling), §19.1 (cancellation).
  • io_uring man pages — io_uring(7), io_uring_setup(2), io_uring_enter(2). Applied in §20.
  • console-api (Tokio console wire protocol), pinned = 0.7.x. Applied in §22.2, ADR-12.

Glossary (§39) · 47 terms · site-wide glossary

Reactor
the subsystem translating kernel readiness/completion events into task wakeups (§15).
Poller
the trait/backend abstraction over epoll/kqueue/IOCP (§11.3, §14).
Source
the per-fd registration record holding waker slots (§11.4).
Token
the non-zero identifier the reactor maps back to a Source (§11.1).
Interest
the bitset of directions (read/write) a registration cares about (§11.1).
Readiness
the bitset the kernel reports back (§11.1).
Waker
the handle a future uses to signal "poll me again" (§11.6).
RawWaker
the allocation-free vtable-based waker implementation (P4, §16.2).
Future
Rust's poll-based asynchronous computation abstraction (§8.1).
Executor
the subsystem that polls futures to completion (§16, §18).
Task
a spawned unit of scheduled work, backed by a Header (§11.6).
JoinHandle
the caller-held handle to a spawned task's result; dropping it cancels the task (§11.6, P5).
TaskGroup
the structured-concurrency scope that cascades cancellation to every child (§19.2).
Drop-cancellation
cancelling a task solely by dropping its JoinHandle (P5, ADR-09).
Structured concurrency
the discipline that every spawned task's lifetime is bounded by its parent scope (§19.2, §34).
select!
the macro that races multiple futures, returning the first ready one (§19.2).
Timer wheel
the hierarchical, slotted data structure holding scheduled wakeups (§17, ADR-07).
Timer slot
one bucket within one wheel level (§11.9).
Cascade
re-inserting a not-yet-due timer entry one wheel level down at a wrap boundary (§8.3).
Work-stealing
a scheduling discipline where idle workers pull tasks from busy siblings' queues (§18, ADR-08).
Chase-Lev deque
the wait-free-push/pop, lock-free-steal data structure behind each worker's local queue (§18.3, §5).
Inject queue
the bounded MPMC queue for spawn calls from non-worker threads (§18.2).
Steal-half
the policy of stealing up to half a victim's queue in one attempt (§18.6).
Parker / Unparker
the primitive a worker uses to block/wake when idle (§11.5, §15.2).
Two-phase park
the race-free park protocol (set a flag, re-check, then sleep) preventing missed wakeups (§18.6).
Backpressure
an explicit, propagating signal that a consumer cannot keep up (P6, MM8).
Watermark
the high/low thresholds that batch channel wakeups (§19.2, §19.5).
Bounded channel
a channel with a fixed capacity that never silently drops (I8, ADR-10).
MPSC
multi-producer, single-consumer (the default channel shape, §11.10).
Broadcast channel
a channel where every receiver observes every message, explicitly signalling lag rather than dropping silently (§19.5).
Oneshot channel
a single-value, single-use channel (§11.10).
io_uring
the Linux completion-based asynchronous I/O interface (§5, §20).
SQE
Submission Queue Entry, one requested io_uring operation (§8.4).
CQE
Completion Queue Entry, one io_uring operation's result (§8.4).
Submitter
the trait wrapping io_uring's submit/wait/drain cycle (§11.11, ADR-06).
Multishot accept
one SQE that keeps yielding CQEs as new connections arrive (§20.2).
Fixed buffer
a pre-registered, pinned buffer eliminating per-submission iovec translation (§20.2, §35 #8).
Feature probe
behaviour-testing (not version-string-trusting) detection of kernel io_uring capabilities (§11.11, §20.2).
Readiness model
"tell me when this is ready" (epoll/kqueue/IOCP-readiness, MM7).
Completion model
"do this, tell me when it's done" (io_uring, IOCP-completion, MM7).
Edge-triggered
a notification delivered exactly once per kernel-state transition, requiring drain-to-EAGAIN (I1, ADR-03).
EPOLLEXCLUSIVE
the Linux flag preventing thundering-herd wakeups on a shared listener (ADR-22, FM6).
Blocking pool
the adaptive thread pool absorbing file/DNS calls that cannot be readiness-polled (P8, ADR-11).
Idle-detector
the subsystem flagging a task that has run too long without yielding (§22.2, P1).
Poll budget
the per-task "consumes" allowance forcing a yield under a tight always-ready loop (§22.2).
tokio-console
the external tool this runtime's tracing hook is wire-compatible with (ADR-12, §22.2).
C10K/C10M
the "ten thousand"/"ten million" concurrent-connection scaling problems and their literature (§5, §37). ---
