Control-plane API: the only trust boundary allowed to mutate flag/segment/experiment state; every mutation is authenticated, authorized, and appended to the audit log before it can reach the config compiler.

Flag/experiment store: Postgres, transactional, the single source of truth for authored (not yet compiled) state; Flag, Segment, Experiment rows keyed by (environment_id, key).

Config compiler: pure transformation from authored state to an immutable ConfigDocument at a monotonically increasing ConfigVersion; never partially applies.

Delivery service (streaming + polling fallback): stateless, holds the current ConfigDocument per environment in memory, terminates the concurrency boundary between one control-plane publish and N SDK connections.

SDK local evaluator: runs inside the host application process; holds the last-known ConfigDocument; evaluates offline; is the trust boundary between untrusted request attributes and the flag decision.

Bucketing function: a pure function of (salt, unit id); no I/O, no mutable state; the one component whose output must never change silently.

Exposure-event collector: SDK-side batching and shipping of ExposureEvent records; crosses the persistence boundary into the ingestion queue.

Ingestion queue: durable, at-least-once, the concurrency boundary between many SDK producers and one stats-pipeline consumer.

Stats pipeline: reads exposure and goal events, computes StatsResult per experiment under a SequentialBoundary, runs SRM and guardrail checks.

Results store: ClickHouse, append-only, columnar, holds exposures, goal events, and computed results.

Audit log: append-only, hash-chained, the forensic trust boundary for "who changed what."

Telemetry: metrics, traces, and structured logs emitted at every tier boundary crossing above (§26 names the concrete signals).

8.2 Targeting-rule grammar (EBNF)

rule        := clause_list , priority ;
clause_list := clause , { "AND" , clause } ;
clause      := attribute , operator , value_list , [ "NEGATE" ] ;
operator    := "EQ" | "NEQ" | "IN" | "GT" | "LT" | "CONTAINS"
             | "STARTS_WITH" | "ENDS_WITH" | "MATCHES" | "SEGMENT_MATCH"
             | "SEMVER_EQ" | "SEMVER_GT" | "SEMVER_LT"
             | "DATE_BEFORE" | "DATE_AFTER" ;
attribute   := identifier ;
value_list  := value , { "," , value } ;
value       := string | number | boolean | semver | date ;

Operator / type-coercion table

Operator Valid types Coercion Missing attribute
EQ / NEQ any none false unless NEGATE
IN any none false unless NEGATE
GT / LT number, semver, date numeric compare false unless NEGATE
CONTAINS/STARTS_WITH/ENDS_WITH string none false unless NEGATE
MATCHES string (RE2-class regex) none false unless NEGATE
SEGMENT_MATCH segment key resolves to Segment evaluated against segment's own clauses
SEMVER_* string parsed as semver invalid string → non-match false unless NEGATE
DATE_* string parsed as RFC 3339 invalid string → non-match false unless NEGATE

Evaluation-order precedence: clauses within a rule are AND-combined, evaluated left-to-right with short-circuit on first false; clauses within a segment are OR-combined; rules within a flag are walked by descending priority, first full match wins (I6); an unknown operator value evaluates to non-match per P10/I7.

8.3 Deterministic bucketing model

Given salt s, unit id u, and rollout entries with weights w_1..w_k summing to W = 100000:

h(s, u)  =  MurmurHash3_32( s || "." || u )
bucket(s, u)  =  h(s, u) mod 100000

Variant assignment: accumulate weights A_i = Σ_{j≤i} w_j; assign variant i where A_{i-1} ≤ bucket(s,u) < A_i.

Worked example — stability under weight change. s = "exp-42", u = "user-777", h(s,u) mod 100000 = 61,204. Weights [50000, 50000] (50/50): A_1=50000, bucket 61204 falls in [50000, 100000) → variant 2. Weights change to [40000, 60000] (rebalance toward variant 2): A_1=40000, bucket 61204 still falls in [40000, 100000) → variant 2 — unchanged, because bucket 61204 never crossed a boundary that moved away from it. A user near the old boundary (e.g. bucket 45000) would move from variant 1 to variant 2 — this is the documented, acceptable "boundary users move" cost of weight changes, not a bug.

Worked example — reshuffle under salt change. Same u, new salt s' = "exp-42-v2": h(s', u) mod 100000 = 8,431 → a completely uncorrelated bucket, landing in variant 1 under the same [50000,50000] split. Changing the salt is the only supported way to intentionally re-randomize a population (§9 experiment lifecycle, "restart").

8.4 Config-document wire format and versioning

ConfigDocument { version: ConfigVersion(u64), environment_id, flags: [...], segments: [...], compiled_at }, Protocol-Buffers-encoded, gzip-compressed over the wire (ADR-09). ConfigVersion is a per-environment monotonic sequence assigned by the compiler under a DB-serialized transaction (I11); SDKs detect staleness via If-None-Match: <version> on polling and via a version field on every streamed delta.

8.7 Statistics model — display equations

Variance estimation (per-variant sample mean/variance for a continuous metric):

x̄_v = (1/n_v) Σ x_i,      s_v² = (1/(n_v - 1)) Σ (x_i - x̄_v)²

CUPED adjustment (Deng et al. 2013), using pre-experiment covariate Y:

X_cuped = X - θ(Y - Ȳ),     θ = Cov(X, Y) / Var(Y)

reducing post-adjustment variance to Var(X_cuped) = Var(X)(1 - ρ²) where ρ is the correlation between X and Y — the mechanism by which CUPED shortens days-to-significance without inflating Type-I error.

Sequential-test boundary (time-uniform confidence sequence, Howard et al. 2021 form, mixture-based per Johari et al. 2017):

CS_t = [ θ̂_t ± ( σ̂_t / √n_t ) · √( 2 (n_t ψ + 1) / n_t² · ln( (n_t ψ + 1) / α² ) ) ]

where θ̂_t is the running effect estimate, ψ a tuning parameter for the mixing distribution, and α the desired always-valid Type-I error rate. An experiment may be concluded the instant 0 ∉ CS_t, at any t, with the Type-I error still bounded by α — the property naive fixed-horizon t-tests do not have under repeated peeking.

8.8 Worked evaluation trace

Context {unit_id: "u-9", country: "US", plan: "pro"}; flag checkout-v2 enabled, rule R1 {country EQ "US" AND plan EQ "pro"} priority 10 → variant treatment; rule R2 {country EQ "US"} priority 5 → 50/50 rollout. Evaluation: flag enabled → walk rules descending priority → R1 (priority 10) clauses both match → return treatment, EvaluationReason::TargetMatch{rule_id: R1}. R2 never evaluated (first-match-wins, I6).

8.9 Malformed-rule examples

{attribute: "plan", operator: "SEGMENT_MATCH", values: ["nonexistent-seg"]} — segment key does not resolve → clause is non-match (P10), not an error. {operator: "FUTURE_OP_V9"} from a newer control plane read by an older SDK — unrecognized operator → non-match (I7). Rollout weights [30000, 30000] summing to 60,000 — rejected at save time (I13), never reaches an SDK.

8.10 Failure-path example

Delivery service publishes ConfigVersion(118) but the SDK's TCP write for the streaming delta times out mid-flight. SDK detects an incomplete frame (length-prefixed delta parse failure), discards the partial delta, and requests a full document resend at its last-known-good version rather than applying a corrupt partial state — preserving I3.
