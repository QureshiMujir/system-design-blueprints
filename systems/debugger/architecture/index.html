Three properties hold throughout and are referenced repeatedly. First, data flow is one-way downward for control (front end → Session → Inferior Control) and upward for queries (Inferior Control → Symbol/Debug-Info → Unwinder/Evaluator → Session → front end); debug info enters from the side via mmap of the on-disk ELF. Second, front ends are interchangeable: Session never knows whether a request came from GDB-RSP, DAP, or the CLI (Principle P7). Third, correctness ground truth lives in the Symbol/Debug-Info layer and the Unwinder; every front-end query reduces to a small set of primitives over those layers, each with a conformance fixture (Testing & Verification Strategy).

8. Domain Model / Protocol / Data Model

8.1 The Breakpoint State Machine

        ┌────────────┐  install_swbp Ok
        │  Pending   │ ─────────────────────► ┌────────────┐
        └────────────┘                        │ Installed  │
              ▲                                └─────┬──────┘
              │ disable                 hit; step-over dance (P4) │
              │                                       │ re-arm
        ┌────────────┐                                │
        │  Disabled  │ ◄──────────────────────────────┘
        └─────┬──────┘
              │ delete
              ▼
        ┌────────────┐
        │  Deleted   │ (terminal — BreakpointId never reused)
        └────────────┘

A breakpoint against a not-yet-loaded symbol starts Pending; the rendezvous mechanism (Phase 2) flips it to Installed (Invariant I9). Disabled restores the original byte if the breakpoint was Installed. Deleted is the only terminal transition. The step-over dance (Phase 5) is a self-loop on Installed — never visible to the front end as Disabled.

8.2 ASLR Slide and the Dynamic-Linker Rendezvous

At module load, aslr_slide = load_address - file_base_address (the file's lowest PT_LOAD segment vaddr), read from /proc/PID/maps. The dynamic linker exposes _r_debug with an r_brk field naming a function invoked on every dlopen/dlclose; a software breakpoint at r_brk re-walks _r_debug.r_map on every hit to refresh the ModuleSet (mirrors gdb/solib-svr4.c, Reference Implementations).

8.3 Expression Grammar (EBNF)

expr        = or_expr ;
or_expr     = and_expr , { "||" , and_expr } ;
and_expr    = equality , { "&&" , equality } ;
equality    = relational , { ("==" | "!="), relational } ;
relational  = additive , { ("<"|">"|"<="|">="), additive } ;
additive    = unary , { ("+"|"-"), unary } ;
unary       = ["*"|"&"|"-"] , postfix ;
postfix     = primary , { "." ident | "->" ident | "[" expr "]" } ;
primary     = ident | number | string | "(" expr ")" | "(" type ")" unary ;

A strict C-expression subset: no function calls (deferred — Deferred Features Register), no C++ template instantiation syntax. Field/Index/Deref resolve through the current Frame's type DIEs (Phase 7).

8.4 GDB-RSP Packet Grammar

packet     = "$" , payload , "#" , checksum ;
payload    = { escaped_byte } ;
escaped_byte = normal_byte | "}" , (byte XOR 0x20) ;
checksum   = 2 * hex_digit ;               (* sum(payload) mod 256, unsigned *)
ack        = "+" | "-" ;                   (* "-" triggers resend of last packet *)

Special bytes #, $, }, * are escape-encoded. A receiver ACKs + (checksum OK) or - (bad, resend). Phase 10 §10.1 covers the full command set.

8.6 Malformed-Input Examples

  • Truncated DWARF: .debug_abbrev ends mid-attribute-list. gimli returns Err(UnexpectedEof); dbg-dwarf maps it to DwarfError::Truncated{cu_offset}, module marked "no debug info," never a panic (Invariant I13).
  • Bad GDB-RSP checksum: server recomputes; on mismatch it does not process the packet and sends -; the last-sent reply is cached for resend (Phase 10 §10.6).
  • Malformed DAP JSON: Content-Length header present but body fails to deserialize into the expected request shape; server replies with a DAP response carrying success: false and a message, never crashes the adapter process.

8.7 Failure-Path Example: Inferior Killed Mid-Continue

Sequence: front end sends continue → supervisor issues PTRACE_CONT → before the next waitpid, the OOM killer sends SIGKILL to the inferior → the next ptrace call against that Tid returns ESRCH. The wrapper (Phase 1 §1.7 pitfall) translates ESRCH into InferiorEvent::Exited{pid, status: SIGKILL} rather than propagating a raw OS error; Session tears down its breakpoint/watchpoint tables for that inferior and the front end receives an exited/terminated event exactly once (Invariant I2 still holds — nothing is left in T-state because the kernel already reaped the state via the fatal signal).

Design principles (§6)

  • Inferior memory is untrusted (P1). Every read from /proc/PID/mem or PTRACE_PEEKDATA returns Result<Bytes, IoError>; zero unwrap()s on inferior reads, zero panics on bad DWARF. Tradeoff: more Result-threading boilerplate. Operationally: a malformed binary degrades to a typed error, never a crash. Violate it and a single corrupted inferior takes the debugger down with it.
  • The register file is ground truth (P2). Every "where am I" query resolves through PTRACE_GETREGSET(NT_PRSTATUS), never a cache. Tradeoff: one extra syscall per query. Operationally: no stale-PC display class of bug exists. Violate it and the UI can show a PC the inferior left an instruction ago.
  • One inferior, one supervisor task (P3). Per-inferior ptrace state is owned by exactly one task; cross-task access goes through a typed mailbox. Tradeoff: a serialization point per inferior. Operationally: the entire family of kernel per-thread tracer-tracee binding bugs is structurally avoided. Violate it and ptrace calls fail with ESRCH/EPERM under concurrent access from the wrong thread.
  • Software breakpoints are reversible by construction (P4). The installer saves the original byte before writing the trap; every step-over path runs uninstall → single-step → reinstall → continue with no shortcut. Tradeoff: two extra ptrace calls per step-over. Operationally: no crash-after-clear bug class. Violate it and Failure Mode FM1 (lost breakpoint byte) reproduces.
  • DWARF is parsed lazily (P5). No compilation unit loads until a query reaches it; .debug_aranges indexes address → CU without a scan; parsed CUs are LRU-cached (Invariant I6). Tradeoff: first-query-per-CU latency spike. Operationally: attach time stays sub-second even on 500 MB binaries (SC1-SC2). Violate it and attach time becomes O(binary size).
  • Symbolication is separate from unwinding (P6). The unwinder emits (pc, cfa, sp) triples and stops; symbol names/lines are resolved lazily only when the front end asks. Tradeoff: two passes over frame data when both are needed. Operationally: bt stays fast even with missing debug info (Performance Engineering M5). Violate it and a stripped frame silently drops instead of showing an address (Mental Model MM4).
  • The two protocols share one session (P7). A DAP setBreakpoints request and a GDB-RSP Z0 packet both call Session::set_breakpoint. Tradeoff: a translation layer per protocol. Operationally: GDB and DAP clients attached to the same session never disagree about state. Violate it and Failure Mode-class divergence appears (Mental Model MM7).
  • Correctness before speed in Phase 0 (P8). Phase 0 ships a working next, print, backtrace, and the GDB-RSP minimum set; speed (lazy DWARF, hardware breakpoints, indexing) and coverage (pretty-printers, inline stepping) land in later phases. Tradeoff: early phases are slower than final targets. Operationally: every phase has something runnable to gate on. Violate it and premature optimization stalls Phase 0.
  • Determinism is the default (P9). Two runs of the same script against the same binary produce bit-identical front-end output modulo PIDs/timestamps, which are documented as redacted. Tradeoff: conformance fixtures must explicitly redact nondeterministic fields. Operationally: regressions are byte-diffable. Violate it and flaky conformance fixtures erode trust in the whole suite.
  • No silent fallbacks (P10). If a hardware breakpoint cannot be set (slots exhausted), the caller gets a typed error, never a silent downgrade to software. Tradeoff: the caller must handle the error explicitly. Operationally: a user profiling cache misses on a hot loop never has their experiment silently altered. Violate it and Invariant I5 breaks.
  • The breakpoint table is indexed, never scanned (P11). BTreeMap<BreakpointId,_> and an address-sorted index, not a Vec. Tradeoff: slightly more complex insert/delete. Operationally: continue with 1,000 breakpoints stays under Performance target M7. Violate it and headcrab's documented mistake (Reference Implementations) reproduces.
  • Hardware resources are explicitly rationed (P12). DR0-DR3/BRP-WRP slots are tracked by a bijective allocator (Invariant I5); the count is read from the CPU at attach time, never assumed. Tradeoff: a fixed, small ceiling regardless of software ambition. Operationally: SlotsExhausted is a typed, expected error, not a crash. Violate it and Failure Mode FM7 (slot leak) reproduces.
  • Every supervisor task owns its ptrace state exclusively (P13). Only the task that issued PTRACE_SEIZE may issue further requests for that Tid (kernel-enforced tracer binding). Tradeoff: cross-thread requests must be proxied through the mailbox (P3). Operationally: no EPERM surprises from a second thread trying to trace the same Tid. Violate it and Failure Mode FM6 (double-trace) reproduces.
  • Observability is not an afterthought (P14). Every command, supervisor event, and breakpoint operation emits a tracing span from Phase 0 onward, not bolted on in Phase
  • Tradeoff: span overhead on the hot path (mitigated — Performance Engineering). Operationally: docs/runbooks/triage.md's first 15 minutes rely on this data existing. Violate it and every production incident starts with "let me add logging and reproduce."
