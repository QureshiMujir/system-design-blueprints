ADR-01

Core language

Chosen

Rust 1.75+

Rejected

C++17; OCaml

When the rejected choice is right

a team with an existing 500k-line C++ debugger core and no Rust bench strength

Why: ownership over inferior-memory views, gimli/object/nix maturity, safer AArch64 cross-compile

Alternative Architectures (Roads Not Taken)

ALT1 — JIT-based dynamic binary instrumentation (Pin/Valgrind-style).

[inferior code] --rewrite--> [code cache] --instrumented basic blocks--> [analysis hooks]

Regime where it wins: heavyweight whole-program analysis (memory checking, taint tracking) where per-instruction overhead is acceptable and no live gdb-style interactive session is needed. Real system: Valgrind (Nethercote & Seward 2007), Pin (Luk et al. 2005). Rejected because: a 5-100x slowdown is unacceptable for an interactive stepping debugger (violates SC9 startup and SC3 step-throughput targets), and instrumentation-based tools have no clean mapping onto hardware breakpoints/watchpoints since their mechanism is software-only.

ALT2 — Full syscall-interception record/replay first (rr-style).

[recorder: ptrace+seccomp-bpf] --trace file--> [replayer: deterministic re-execution]

Regime where it wins: bugs that must be reproduced exactly and stepped backward (races, heisenbugs). Real system: Mozilla rr. Rejected as the Phase-0 architecture because live attach-to-a-running-process — the single most common debugging entry point — is not rr's design center, and rr requires single-logical-CPU replay plus specific CPU performance- counter support not universally available (tracked as a Phase-1+ stretch, Deferred Features Register, not a Phase-0 substitute).

ALT3 — In-process debugging via self-installed signal handlers (no supervisor process).

[target binary + linked runtime] --installs own SIGTRAP/SIGSEGV handlers--> [socket to inspector]

Regime where it wins: production post-mortem/crash-reporting agents where the target must debug itself with zero external privilege (embedded crash handlers). Real system: Google Breakpad/Crashpad. Rejected because: it cannot set breakpoints before a crash happens, cannot control CPU registers/execution from outside the process, and a compromised inferior can lie to its own handler — violating Principle P1 (inferior state is untrusted) at the architectural level, not just an implementation detail.

ALT4 — Kernel-mode/hypervisor-level debugging (VM introspection) instead of ptrace.

[hypervisor/VMI] --intercepts guest traps, bypasses ptrace entirely--> [debug port outside guest]

Regime where it wins: kernel-mode debugging (kgdb/kdb), or debugging a guest OS that must not be trusted to cooperate at all. Real system: Linux's own kgdb/kdb; VMI frameworks such as LibVMI. Rejected because: this project's Phase 0-12 scope is user-space process debugging on a single Linux host — kernel/hypervisor debugging is a different trust boundary and privilege model entirely, explicitly out of scope (Deferred Features Register: kernel-mode debugging).
