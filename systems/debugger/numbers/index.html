The one defining property: every query is a read-through of live kernel state (Invariant I3) layered under a lazily-parsed, address-indexed debug-info cache (Invariant I6) — nothing here is a database with its own durability story; correctness comes from never caching what the kernel can tell you fresher.

Back-of-Envelope Capacity Model

  • BEC1 — Max resident DWARF working set. CU cache capacity (256, Invariant I6) × avg parsed CU size (≈150 KB, measured on typical -g binaries) = 256 × 150 KB ≈ 37.5 MB.
  • BEC2 — Breakpoint table memory. 10,000 (SC6) × sizeof(Breakpoint) (≈128 B incl. Option/enum overhead) = 1.28 MB.
  • BEC3 — Bulk-read time for a 1 GB region at SC11 (≥ 2 GB/s). 1 GB ÷ 2 GB/s = 0.5 s (matches Performance target M3 exactly).
  • BEC4 — Single-step time for a 100k-iteration loop at SC3 (≥ 20k steps/s). 100,000 ÷ 20,000 = 5.0 s (matches M2 exactly).
  • BEC5 — Hardware breakpoint fan-out. 4 x86-64 DR slots (SC7) × 64 max concurrent inferiors (SC5) = 256 total hardware breakpoints addressable system-wide, though any single inferior is still capped at 4 (Invariant I5).
  • BEC6 — FD budget check. 3 FDs/inferior (SC14) × 64 concurrent inferiors (SC5) = 192 FDs — 5.3x headroom inside the 1,024 default ulimit.
  • BEC7 — GDB-RSP packet-rate ceiling. 1 ÷ SC12 (1 ms median round trip) = 1,000 packets/s per connection — the rate an interactive info registers polling loop can sustain.
  • BEC8 — DAP concurrent-IDE ceiling. SC13 (5 ms/256-frame trace) × N IDEs must stay under a 100 ms human-perceptible UI-latency budget ⇒ N ≤ 20 concurrent stackTrace requests per 100 ms window before requests queue.
  • BEC9 — 30-day fuzz executions for the M12 gate. ≈10,000 exec/s per fuzz core (typical libFuzzer throughput on small DWARF inputs) × 86,400 s/day × 30 days ≈ 2.59×10^10 executions — the statistical weight behind M12's "zero crashes" claim.
  • BEC10 — Soak-test RSS ceiling (M11, ±5% over 24h). Starting RSS ≈ 50 MB (post-attach + symbolicate, SC2) × 1.05 = 52.5 MB before the soak test is considered failed.
  • BEC11 — Multi-thread register-cache worst case. SC4's 4,096-thread ceiling × per-thread Registers size (≈216 B, GPRs + FPU selector, NT_PRSTATUS+NT_PRFPREG) ≈ 885 KB resident at the pathological maximum.
