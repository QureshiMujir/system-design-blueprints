32. Mental Models & First Principles

MM1. Gas is the EVM's whole safety model — it turns the halting problem into an economic one: you cannot run forever because you cannot pay forever, so untrusted code on a shared machine becomes safe (the Yellow Paper's core design move).

MM2. The EVM is a deterministic function from (state, tx) to state, replicated across thousands of independently-operated machines that must all agree bit-for-bit — every design decision (no floats, no wall-clock, no unordered iteration) serves that agreement, and any decision that doesn't is a bug waiting to happen.

MM3. The state root is a Merkle commitment to all of world state, so "the state" is, cryptographically, a single 32-byte hash — light clients and cross-client comparisons both reduce to comparing that one hash, not the underlying gigabytes of data.

MM4. Journaling turns "revert" from a special case into the normal path — every call frame is provisional until it commits, which is what makes nested calls, reentrancy, and failed sub-calls all tractable with one mechanism instead of three.

MM5. Gas forwarding (the 63/64 rule) is a security control disguised as a resource-accounting detail — without it, an attacker could grief callers into effectively unbounded call-depth gas costs; with it, the cost of depth is geometrically bounded.

MM6. A "contract" is just an account whose code field is non-empty — the account model doesn't distinguish user wallets from smart contracts structurally, only behaviorally (whether code executes on a message call).

MM7. Determinism is the actual product being sold — throughput and features are secondary to the guarantee that this VM, run by anyone, on any input, produces the same answer as every other conforming VM.

MM8. Reentrancy is not a VM bug — it's what happens when a contract's own control flow reenters itself through an external call; the VM's contract is "execute exactly what the bytecode says," and the DAO hack is the canonical proof that faithful execution and safe contracts are two different properties.

Glossary (§38) · 50 terms · site-wide glossary

ABI
Application Binary Interface; encoding convention for contract function calls and return data.
Access list
the EIP-2929 per-transaction set of pre-touched (warm) addresses and storage keys.
Account
a world-state entry: nonce, balance, codeHash, storageRoot.
Bloom filter
a 2048-bit probabilistic structure summarizing a receipt's/block's logs for fast filtering.
Branch node
an MPT node with 16 child slots plus an optional value.
Bytecode
the executable opcode stream a contract account's code field holds.
Call frame
an isolated execution context (own stack, memory, return-data) for one CALL/CREATE-family invocation.
Checks-effects-interactions
the contract-level defensive pattern against reentrancy: validate, then mutate state, then make external calls.
Cold access
the first touch of an address/storage-key within a transaction (EIP-2929), priced higher than warm.
Consensus split
the catastrophic failure where conforming nodes disagree on the state root for identical input.
CREATE / CREATE2
opcodes deploying a new contract; CREATE2's address is deterministic from deployer+salt+init-code hash (EIP-1014).
Determinism
the property that identical (state, transaction) always yields identical output on every conforming node.
EOF (EVM Object Format)
a deferred future bytecode-container format (EIP-3540/3670).
EIP
Ethereum Improvement Proposal, the mechanism by which protocol changes are specified and numbered.
Extension node
an MPT node encoding a shared nibble-path prefix pointing to one child.
Gas
the per-opcode-priced unit of computational cost; the EVM's halting/resource-pricing mechanism.
Gas limit
the maximum gas a transaction or call is permitted to consume before halting with OutOfGas.
Gas price / base fee
the per-gas-unit fee (legacy) or protocol-set floor fee (EIP-1559) paid by the sender.
Halt
a non-successful termination of a frame (OutOfGas, InvalidJump, StackOverflow, etc.), returning a typed HaltReason.
Hardfork
a named, block/timestamp-activated set of protocol rule changes.
Hex-prefix encoding
the MPT's nibble-path encoding distinguishing leaf/extension and odd/even nibble counts.
Init code
the bytecode executed once at contract-creation time, whose RETURN output becomes the runtime code.
Journal
the append-only log of previous values recorded before every state mutation, enabling revert.
JUMPDEST
the marker opcode; the only valid target of JUMP/JUMPI.
Keccak-256
the pre-standardization SHA-3-family hash function used throughout the EVM/Ethereum protocol (distinct from NIST SHA3-256).
Leaf node
an MPT node holding the terminal nibble-path remainder and a value.
Log / event
a LOG0-LOG4-emitted record (address, topics, data) attached to a transaction's receipt.
Merkle-Patricia trie (MPT)
Ethereum's modified radix trie committing world state and per-account storage to a single root hash.
Message call
an invocation of one account's code by another (CALL/DELEGATECALL/STATICCALL/CALLCODE).
Nibble
a 4-bit value; the MPT's path unit (2 nibbles per byte).
Nonce
a monotonically incrementing per-account counter (tx count for EOAs, contracts-created count for contract accounts).
Opcode
a single EVM instruction byte plus its semantics.
Out-of-gas (OOG)
the halt condition when a gas charge cannot be satisfied by remaining gas.
Precompile
a host-native, gas-priced function invoked like a call but bypassing the interpreter (e.g. ECRECOVER).
Program counter (PC)
the current instruction-stream offset within a call frame's code.
Receipt
the per-transaction execution summary: status, gas used, logs, bloom.
Refund
a gas credit (e.g. from SSTORE clearing a slot) applied, capped, at end-of-transaction (EIP-3529).
Reentrancy
an external call re-entering the calling contract's own code before its state settles; a contract-level, not VM-level, concern.
REVERT
the opcode halting a frame, discarding its state mutations, but returning output data and refunding unused gas (EIP-140).
RLP (Recursive Length Prefix)
Ethereum's canonical binary serialization format for trie nodes, transactions, and receipts.
State root
the 32-byte Keccak256 commitment to the entire account trie at a given point.
Stack machine
a VM architecture where operations consume/produce values from a LIFO value stack rather than named registers.
STATICCALL
a read-only message call forbidding any state mutation in itself or any nested sub-call.
Storage slot
a single 256-bit key/value pair within a contract's persistent storage trie.
Storage trie
the per-account Merkle-Patricia trie committing that account's persistent storage.
Transaction
a signed, sender-originated message applying a state transition.
Warm access
a subsequent touch of an already-accessed address/storage-key within the same transaction, priced lower than cold.
Word
a 256-bit value; the EVM's native stack/memory/storage value unit.
World state
the complete mapping of all addresses to accounts at a given point in the chain.
Υ (Upsilon)
the Yellow Paper's symbol for the state-transition function: Υ(σ, T) = σ'. ---
