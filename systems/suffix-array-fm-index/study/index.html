Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why must the sentinel be both unique and the strictly-smallest symbol, and what specifically breaks in LF-mapping invertibility if either property is dropped? (§8.1, DP2, I3)
  2. Trace why SA-IS's recursion terminates in O(log n) levels, and why that specific bound — not, say, O(log log n) — is what gives O(n) total work. (§8.3, §4)
  3. Why is Kasai's total-decrement bound exactly n (not n log n), and how does that bound depend on the SA already being computed? (§8.4, I6)
  4. What would go wrong with backward-search correctness if Occ used BWT[0..=i] (inclusive) instead of BWT[0..i) (exclusive) semantics, and where is this locked down in the phase plan? (§8.8, §19 Pitfalls)
  5. Why does the r-index's O(r) space bound depend on r ≪ n holding, and what happens to its guarantees on incompressible (high-entropy) text? (§8.14, Scalability Analysis, §23)
  6. Contrast the space/time tradeoff of the SA sample rate s with the RRR block size t: both trade space for time, but along which different axes? (§8.9, §8.13, DP9)
  7. Why is the suffix automaton kept as an oracle rather than the primary count path, given it can also answer count(P) via a transition walk? (§8.15, ADR-15, Alternative Architectures)
  8. What is the precise reason wavelet-tree rank composes across levels — why can Occ be computed via a root-to-leaf walk using only the mapped index at each level, not the original index? (§8.12, §18 Pitfalls)
  9. Why does this design validate every construction against an independent oracle instead of relying on unit tests alone, and what category of bug specifically escapes unit tests but not differential testing? (DP1, DP12, Testing & Verification Strategy)
  10. Derive why the FM-index's theoretical space target is n·H_k + o(n) bits, and explain what the o(n) term must cover for the index to remain functional, not merely small. (§8.13, §4, Back-of-Envelope Capacity Model)
  11. Why can't the plain sampled-SA locate scheme be reused unmodified for the r-index's locate, and what does the toehold mechanism replace? (§8.9, §8.14, §23)
  12. What specific invariant would a tampered index need to violate to make backward search return a wrong-but-plausible count, and how is that caught before it reaches a query? (I1, I10, Threat Model, Failure Modes & Recovery)
  13. Why does the blueprint forbid dynamic/mutable indexes rather than supporting incremental FM-index updates directly, and what would have to change architecturally to support them? (§1 non-goals, DP3, Deferred Features Register)
  14. Explain why distinct_substrings has two independently-derived formulas (SA+LCP vs SAM), and under what circumstances the two could silently diverge if only one were implemented. (§8.6, §8.15, I14)
  15. Why is Rust's ownership model specifically suited to the untrusted-index-decode threat model, compared to what an equivalent C++ implementation must do manually? (§1, ADR-01, Threat Model, Comparative Architecture Table)
  16. Using the Back-of-Envelope Capacity Model, explain why a 4.29 GB genomic corpus is a reasonable single-machine target for the plain FM-index, but would strongly favor the r-index if it were a pan-genome collection instead. (Back-of-Envelope Capacity Model, §8.14, Scalability Analysis)
  17. Why does the design lock LCP[0] = 0 by convention rather than leaving it undefined, and what would break in the RMQ/LCE machinery if it weren't? (§8.4, §8.5, Phase 3 §15 Pitfalls)
  18. What is the architectural reason the succinct layer (rank/select, wavelet, RRR) is a strict prerequisite for the FM-index phase rather than being built alongside it? (§10, §17–§19 phase ordering)
  19. Why would GPU/SIMD-vectorized rank be deferred rather than built into Phase 5 from the start, and what would have to be true of the workload to justify un-deferring it? (Deferred Features Register, Performance Engineering)
  20. Compare the rejection rationale for DC3 as the primary SACA against its role as a mandatory cross-check — why is a rejected alternative still worth fully implementing? (ADR-03, §14, Alternative Architectures)

Mental Models & First Principles

Eight compressed insights an expert holds. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — A suffix array is a permutation that turns substring search into a range search. Predicts: every occurrence of P sits in one contiguous SA interval, so count/locate are interval operations, never per-position scans. Bug without it: reimplementing substring search as a linear scan even after building the SA. Applied in §8.2, §19.
  • MM2 — Induced sorting is a fixed-point relaxation seeded from a sparse subset, not a comparison sort. Predicts O(n) construction from O(log n) recursion levels on a shrinking LMS-name alphabet. Bug without it: attempting a direct comparison-based reimplementation and landing back at O(n log n). Applied in §8.3, §14.
  • MM3 — The BWT is a lossless, reversible sort — a permutation of the text is still the whole text. Predicts invertibility via a single bijective LF walk from one anchor row. Bug without it: forgetting the primary index / sentinel anchor and producing a non-terminating or wrong reconstruction. Applied in §8.7, Phase 4 (§16).
  • MM4 — Rank is the universal succinct primitive; almost everything else (Occ, select, wavelet routing) reduces to popcount. Predicts that one well-built rank structure composes into every higher structure without re-deriving bit tricks. Bug without it: reimplementing Occ from scratch per structure, multiplying the surface for bit-order bugs. Applied in §8.11, §17, §18.
  • MM5 — Backward search is binary search generalized to a whole alphabet transition at once. Predicts the half-open-interval invariant and why it narrows monotonically. Bug without it: an off-by-one at the ep boundary that double-counts or drops the last occurrence. Applied in §8.8, §19.
  • MM6 — Space is a spectrum (dense → succinct o(n) → entropy H_0/H_k → repetition-aware O(r)); pick the point matching the corpus's redundancy structure. Predicts when RRR helps (skewed entropy) vs when it doesn't (near-random text) vs when the r-index dominates (few BWT runs). Bug without it: applying RRR to incompressible data or the r-index to non-repetitive data and getting no win, or worse, wasted overhead. Applied in §22, §23, Scalability Analysis.
  • MM7 — Every structure needs an independent second oracle; correctness is proven by agreement, not by elegant construction. Predicts that a beautiful, subtly wrong implementation still ships without a second, differently-derived check. Bug without it: trusting a single SA-IS or FM-index implementation that passes small unit tests but is wrong on adversarial or large inputs. Applied in DP1, DP12, Testing & Verification Strategy.
  • MM8 — The suffix tree is a virtual structure; SA + LCP + RMQ emulate it without paying its pointer overhead. Predicts that LRS/LCS/LCE all reduce to array range-queries, no explicit tree needed. Bug without it: building an actual ~20n-byte pointer-based suffix tree when the array trio suffices at a fraction of the memory. Applied in §8.5, Phase 3 (§15).

Glossary · 48 terms · site-wide glossary

Suffix array (SA)
Array of all suffix start positions of T in ascending lexicographic order; a permutation of [0,n) (I1)
Inverse SA (ISA / rank)
ISA[SA[i]] = i; the rank of the suffix at a given text position
LCP array
LCP[i] = lcp(suffix(SA[i−1]), suffix(SA[i])); LCP[0]=0
PLCP
LCP in text order (PLCP[p]=LCP[ISA[p]]); "almost-increasing", cache-friendly
LCE
Longest common extension; lcp of two suffixes via RMQ over LCP, O(1)
RMQ
Range-minimum query; sparse table (O(n log n)) or Fischer–Heun (O(n))
Sentinel $
Unique smallest terminator (0x00) appended once; makes suffixes distinct, BWT invertible (I3)
Alphabet σ
Number of distinct symbols; byte path σ ≤ 256; remapped to dense [0,σ)
SA-IS
Linear-time suffix-array construction via induced sorting (Nong–Zhang–Chan)
L/S type
Suffix classification: S if T[i..]<T[i+1..], else L; drives induced sorting
LMS position
Leftmost-S: type=S with type[i−1]=L; seeds SA-IS
Induced sorting
Deriving all suffix order from sorted LMS suffixes via two bucket passes
DC3 / skew
Alternative linear SACA via difference cover mod 3; cross-check oracle
BWT
Burrows–Wheeler Transform; last column of sorted rotations; BWT[i]=T[(SA[i]−1) mod n]
F column
First column of the rotation matrix; sorted symbols of T
LF-mapping
LF(i)=C[BWT[i]]+Occ(BWT[i],i); a bijection (I4); inverts the BWT
Ψ (Psi)
Inverse of LF; reads T forward; basis of the CSA
Primary index
Row with SA[p]=0 (BWT of $); anchors reconstruction
C[] table
C[c] = number of symbols < c; backward-search base offset (I10)
Occ(c,i)
Number of occurrences of c in BWT[0..i); a rank query
FM-index
Self-index = BWT+C[]+Occ; backward search; stores no plaintext
Backward search
Narrows half-open [sp,ep) one pattern symbol right-to-left (I7)
count(P)
ep − sp after backward search; number of occurrences
locate(P)
Text positions of all occurrences via sampled SA + LF-walk
extract(i,j)
Recover T[i..j] from the index via sampled ISA + LF-walk
Sampled SA
SA[i] stored only at sampled rows (rate s); space/locate-latency knob
Rank/select
rank1(i)=#1s in B[0..i); select1(j)=position of the j-th 1; O(1), o(n) overhead
Superblock/block
Two-level rank structure (512-bit superblock + 64-bit block + popcount)
Wavelet tree
Balanced/Huffman tree over σ giving access/rank/select in O(log σ)
Wavelet matrix
Level-wise wavelet layout with better cache locality
RRR
Raman–Raman–Rao entropy-compressed bitvector (n·H_0+o(n), O(1) rank)
H_0 / H_k
Zeroth- / k-th-order empirical entropy; the FM-index space target
RLBWT
Run-length BWT; r runs (head,len); O(r) space
r-index
O(r)-space index over BWT runs with run-boundary SA samples + toehold
Run count r
Number of maximal equal-symbol runs in the BWT; r ≪ n on repetitive text
Toehold
One known SA value bootstrapping r-index locate
Suffix automaton (DAWG)
Minimal DFA recognizing all substrings; endpos classes; differential oracle
endpos
Set of end positions of a substring class in the SAM
Suffix link
SAM link to the next-shorter-suffix class with a different endpos
LRS
Longest repeated substring (max LCP, or deepest SAM state with endpos ≥ 2)
Distinct substrings
Count of distinct non-empty substrings; Σ(n−SA[i])−Σ LCP[i] or SAM sum
Differential oracle
An independent computation (naive SA, DC3, SAM) used to validate a structure
Half-open interval
[sp, ep); the backward-search invariant (I7)
Idx width
SA index integer width (u32 default / u64 --wide); chosen by n (I16)
DP#
Design-Principle ID token (DP1…DP13, §6); distinct from paper IDs to avoid collision
PR#
Required-Reading paper ID token (PR1…PR15, §5)
MM#
Mental-Model ID token (MM1…MM8, Mental Models & First Principles)
M#
Performance-target ID token (M1…M12, Performance Engineering)
