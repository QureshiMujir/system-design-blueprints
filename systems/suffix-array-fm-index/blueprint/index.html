417 — Suffix Array / FM-Index String-Indexing Engine from Scratch

Project Number: 417

Project Name: Suffix Array / FM-Index String-Indexing Engine from Scratch

Document: FINAL_BLUEPRINT.md

Owner: Mujir Qureshi

Status: specification — locked

1. Goal & Scope

Build a correct, embeddable substring-indexing engine: given an immutable text T of length n, precompute an index that answers, over arbitrary patterns P (m = |P|):

  • count(P) → u64 — number of occurrences of P as a substring of T.
  • locate(P) → [usize] — the exact set of start positions (text offsets) where P occurs.
  • extract(i, j) → bytes — recover the substring T[i..j] from the (possibly compressed) index without the original text.
  • lrs() — a longest repeated substring; lcs(T2) — a longest common substring of T and a second text; distinct_substrings() → u64 — count of distinct non-empty substrings.

The engine is the SA/BWT/FM-index family: a suffix array (SA), its LCP array, the Burrows–Wheeler Transform (BWT) of T, and a self-index (FM-index) layered over succinct rank/select structures and a wavelet tree, with compressed (RRR, run-length / r-index) variants for entropy- and repetition-bounded space. A suffix automaton (DAWG) is built as an alternate substring oracle for counting/distinct-substring queries and as a differential check on the SA path.

Correctness-first, observability-second, maintainability-third, performance-fourth (the fixed priority order for this blueprint). The index is build-once, query-many, immutable: construction is offline; queries never mutate.

Boundaries: a library (linkable crate) plus a query/build CLI for differential validation and corpus benchmarking. Not a service, not a network protocol, not a document store.

Explicit non-goals:

  • NOT a token/document inverted index. Word/term/document-level retrieval, postings lists, TF-IDF/BM25 ranking are project #78 (Inverted Index) → cross-linked, out of scope. This engine indexes every position of every substring, not tokens.
  • NOT a regular-expression engine. Arbitrary regex (alternation, repetition, backreferences, no precomputed index) is project #61 (Regex Engine) → cross-linked. This engine answers exact substring and exact-substring-derived queries against a precomputed index. Approximate / k-mismatch search is PhaseDeferred("Deferred Features Register") (bidirectional / seed-and-extend noted only).
  • NOT a full-text search platform. No relevance scoring, faceting, sharded distributed query, snippet highlighting beyond extract. Snippet/relevance layers belong to a search-platform project consuming this engine's locate.
  • NOT external-memory / GB-scale construction. SA-IS here is in-RAM (n plus working set must fit). Semi-external and external (eSAIS, pSAscan, DSM-based) construction is PhaseDeferred("Deferred Features Register").
  • NOT a mutable / dynamic index. Insertions/deletions, dynamic FM-index, dynamic wavelet trees are out of scope; the index is rebuilt on text change. Dynamic variants PhaseDeferred("Deferred Features Register").
  • NOT a Unicode-aware linguistic indexer. The alphabet is bytes (σ ≤ 256); normalization, casefolding, collation, grapheme clustering are the caller's preprocessing concern (cross-link #398 Unicode). General large-alphabet (σ up to 2^32) is supported via the wavelet-tree path but without locale semantics.

Deployment model:

  • no_std-capable core primitives (bit I/O, popcount rank, integer codecs, SA-IS over an integer alphabet) — zero-allocation hot query paths where feasible; usable in WASM/embedded for query-only.
  • std build/loader — file mmap, index serialization, large-corpus construction, CLI. Feature-gated.
  • CLI — sufx: build (text → index file), query count|locate|extract, lrs|lcs|distinct, inspect (dump SA/BWT/LF), verify (differential against the naive oracle).

Target users: search-infrastructure engineers, bioinformatics tool authors (read aligners over a reference genome), compression researchers, and any system needing exact substring membership/position over a large static corpus with sublinear query time.

Phase 0 deliverable — numbered modules:

  1. bits/ — bitvector, bitio (bit reader/writer), intcode (Elias/δ, vbyte), popcount.
  2. sa/ — naive (sort oracle), sais (SA-IS), lcp (Kasai + PLCP), rmq (sparse-table / Fischer–Heun).
  3. bwt/ — transform (SA→BWT), invert (LF-walk), lf (C[] + Occ).
  4. succinct/ — rank_select (two-level + popcount), select (sampling), wavelet (balanced + Huffman), rrr.
  5. fm/ — index (C[]+Occ), search (backward search), sample (sampled SA / ISA), locate, extract.
  6. sam/ — automaton (suffix automaton / DAWG, online build), queries (count/distinct via SAM).
  7. rindex/ — rlbwt (run-length BWT), r_index (runs + SA samples + toehold).
  8. cli/ — sufx.

What later phases unlock: Phase 2 unlocks linear-time construction at scale; Phases 5–7 unlock the self-index (query without the text); Phase 8 unlocks locate/extract from the compressed index; Phases 10–11 unlock entropy- and repetition-compressed indexes (genomic/versioned corpora); Phase 12 unlocks production trust via large-corpus differential conformance + fuzzing.

Deferred features (all gated PhaseDeferred("Deferred Features Register"), detailed anchors/triggers in that register): external-memory construction, approximate/k-mismatch + bidirectional search, dynamic/mutable index, generalized suffix array over a multi-document collection with document-listing, GPU/SIMD-vectorized rank, 2D / parameterized / circular suffix structures, the O(1)-workspace SACA-K variant.

Estimated timeline: Phase 0 = 6–12 weeks (one engineer, full-time) to ship Phases 0–8 + CLI (SA, BWT, FM-index, locate/extract); full Phases 0–12 incl. r-index, RRR, conformance and fuzzing = 5–7 months.

Rust chosen: it gives C++-class control over bit layout, popcount, and n-word arrays while making the dominant risk class here — out-of-bounds reads when deserializing an untrusted/truncated index or decoding a malformed succinct stream — a typed, bounded error rather than UB. The reference algorithm corpus (SDSL, divsufsort, BWA, Bowtie2) is C/C++; Rust reimplements the same data structures with the same asymptotics and competitive constants while eliminating the segfault/UB failure mode that dominates this domain.

Prerequisites:

  • String algorithms — suffixes, tries, suffix trees vs arrays, lexicographic order, lcp.
  • Algorithmic analysis — amortized analysis, induced sorting correctness, recursion-tree size bounds (T(n) = T(n/2) + O(n) → O(n)).
  • Bit manipulation / succinct data structures — popcount, broadword tricks, entropy H_0/H_k, o(n) overhead reasoning.
  • Information theory — zeroth/k-th order empirical entropy; why n·H_k + o(n) bits is the FM-index target.
  • Binary format parsing — fixed-width little/big-endian records, length-prefixed arrays, version negotiation, bounds validation.
  • Memory hierarchy — cache lines, sequential vs random access, why SA construction is memory-bound and why rank locality dominates query latency.

2. Why Build This

Unique systems knowledge taught:

  • Suffixes encode all substrings. The single idea that the sorted set of suffixes (the SA) makes every substring query a prefix query — answerable by binary search or by the BWT's backward search — is the conceptual spine of full-text indexing. Building it removes the "search = scan" intuition permanently.
  • Induced sorting (SA-IS). Linear-time suffix sorting by classifying suffixes (L/S), seeding LMS positions, and inducing the rest in two bucket passes is a non-obvious, beautiful algorithm; implementing it correctly (recursion on the reduced string, exact bucket-pointer bookkeeping) is a genuine algorithmic milestone.
  • The BWT / LF-mapping duality. That a permutation of the text (BWT) is both highly compressible and searchable via a bijective LF mapping is the trick behind both bzip2 and modern read aligners. Internalizing LF(i) = C[c] + Occ(c,i) and its inverse Ψ is the core.
  • Self-indexing. An FM-index replaces the text: it answers count/locate/extract from a compressed representation in n·H_k + o(n) bits. Building one teaches how to store strictly less than the input yet answer richer queries than a scan.
  • Succinct data structures. O(1) rank with o(n) overhead, select, RRR's entropy-compressed bitvectors, and wavelet trees are the canonical succinct toolkit; they recur in graph indexes, tries, and column stores.
  • Repetition vs entropy. The r-index exploits that a highly repetitive corpus (versioned source, pan-genomes) has few BWT runs (r ≪ n), giving O(r) space where entropy coders still pay Θ(n). Distinguishing these compressibility regimes is a deep practical lesson.

Historical / architectural significance:

  • Manber–Myers (1990) introduced suffix arrays as the space-frugal alternative to Weiner/McCreight suffix trees; the SA is the data structure that made full-text indexing practical on commodity memory.
  • Burrows–Wheeler (1994) is the transform behind bzip2; Ferragina–Manzini (2000) turned it into the FM-index, founding the field of compressed self-indexes.
  • SA-IS (Nong–Zhang–Chan, 2009) is the algorithm libdivsufsort-class libraries and most bioinformatics toolchains rely on; BWA and Bowtie made FM-index backward search the standard for aligning billions of short DNA reads to the human genome.

Engineering muscles developed: exact index arithmetic under adversarial input; differential conformance against a naive oracle and against divsufsort/zdump-class references; property-based testing of bijections (SA is a permutation, BWT inverts); cache-aware data-structure layout; bounded decoding of compressed streams; reasoning in bits, not bytes.

Production engineering concepts exercised: immutable build-once artifacts and their serialization/versioning; succinct-structure overhead budgeting; entropy accounting as an SLO; memory-mapped read-only indexes shared across query threads; supply-chain pinning of reference corpora (Pizza&Chili).

Calibration value: a substring index looks like "sort the suffixes and binary-search," and is in fact a linear-time-construction + succinct-data-structure + information-theory + adversarial-decode problem. Building it to production bar — SA-IS that is provably linear, an FM-index whose space is measured against H_k, an r-index whose space is measured against r — recalibrates an engineer's sense of what "indexing" costs and instills the habit of validating every structure against an independent oracle.

  3. Size an FM-index against H_0/H_k before writing a line of code, and predict RRR's win/lose crossover for a given corpus (Phase 6, Phase 10).
  4. Choose between a plain FM-index and an r-index for an unseen corpus purely by measuring r/n (Phase 11).
  5. Distinguish a sampling-arithmetic bug from an LF bug from a rank bug when locate returns wrong positions, using only the invariant that fails (Phase 5, Phase 8).
  6. Defend every ADR's rejected alternative with the concrete regime where it would have won instead (§9).
  7. Harden an untrusted binary-format decoder against out-of-bounds reads as a first-class design discipline, not an afterthought (Phase 8, Phase 12).
  8. Redesign the system as a pointer-based suffix tree, a hash-seed index, or an external-memory builder, and state exactly what each redesign trades away (Alternative Architectures).

Per-box detail:

  • TEXT SOURCE T — the immutable input. A unique sentinel $ (internally 0x00, defined smallest) is appended so every suffix is distinct and prefix-free; n = |T|+1. The byte alphabet is optionally remapped to a dense [0, σ) to shrink wavelet-tree depth and bucket arrays. Read-only after this point; loaded via mmap for large corpora.
  • SA CONSTRUCTION — produces SA[0..n), the lexicographic order of all suffixes. SA-IS is the locked linear-time builder (L/S typing, LMS seeding, two induced-sort passes, recursion on the reduced LMS string). The output is asserted to be a permutation of [0, n) (Invariant I1).
  • NAIVE SA ORACLE — a test-only suffix sorter (comparison sort, O(n log²n)) plus binary-search count. It is never shipped; it is the independent oracle every other construction path is differentially validated against (DP1).
  • LCP ARRAY (Kasai) — LCP[i] = lcp(suffix SA[i-1], suffix SA[i]), computed in O(n) via Kasai using SA and its inverse (rank). PLCP (text-order LCP) is derived; a sparse-table RMQ over LCP enables O(1) longest-common-extension and emulates a suffix tree.
  • LCP-DERIVED QUERIES — longest-repeated-substring (max LCP), longest-common-substring (over a concatenated T1$T2#), and distinct-substring count (Σ(n−SA[i]) − ΣLCP[i]), all read off SA+LCP without building an explicit tree.
  • BWT TRANSFORM — the last column L[i] = T[(SA[i]−1) mod n] of the sorted-rotation matrix; with the sentinel this is well-defined and invertible. The primary index p (row of the sentinel / unrotated string) and the BWT are the only structures the self-index needs from SA.
  • SUFFIX AUTOMATON — the minimal DAWG accepting all substrings of T, built online (Blumer/Crochemore) with suffix links and endpos equivalence classes. Independent of the SA path; used for distinct_substrings and as a differential oracle for count.
  • SUCCINCT LAYER — the bit-level toolkit: a plain bitvector with O(1) rank and select at o(n) overhead (two-level superblock/block + popcount), a wavelet tree giving Occ(c,i) rank over a general alphabet in O(log σ), and RRR entropy-compressed bitvectors (nH_0 + o(n)).
  • FM-INDEX — the self-index: C[c] (count of symbols < c) plus Occ(c,i) (rank of c in BWT[0..i)) drive backward search, narrowing an SA interval [sp, ep) one pattern symbol at a time. count(P) = ep − sp. Stores no plaintext.
  • LOCATE / EXTRACT — a sampled suffix array stores SA[i] only at sampled rows/positions (rate s); locate walks LF from a matched row until it lands on a sample, adding the step count. extract(i,j) uses sampled inverse-SA to find a nearby anchor row and emits characters via LF. Space/latency trade is the sample rate s.
  • r-INDEX / RLBWT — for highly repetitive T, the BWT has r ≪ n maximal equal-symbol runs; the r-index stores run heads + SA samples at run boundaries + a "toehold," achieving O(r) space and O((m+occ) log(n/r)) locate. Selected automatically when r/n is below a threshold.
  • QUERY API / serialized index — the public surface. The on-disk index is versioned, length-prefixed, bounds-validated on load, and memory-mapped; the in-memory index is immutable and shared Arc<Index> across query threads with no locking on the hot path.

6. Design Principles

Thirteen non-negotiable principles, IDs DP1…DP13 (referenced throughout this document). Each: tradeoff, operational implication, breakage-on-violation.

  1. DP1 — Correctness is validated against an independent oracle, never self-asserted. Every construction (SA-IS, BWT, FM, r-index, SAM) is differentially checked against the naive sort oracle and/or a second algorithm. Tradeoff: the oracle is O(n log²n), usable only on small/medium inputs. Operational: sufx verify runs the oracle path in CI. Violation: a subtle SA-IS bucket bug ships and silently returns wrong positions on inputs the unit tests missed.
  2. DP2 — The sentinel $ is unique and strictly smallest. A single 0x00 terminator appended once makes all suffixes distinct, prefix-free, and BWT well-defined. Tradeoff: 0x00 is reserved and must not appear in T (validated, or the alphabet is remapped). Operational: the builder rejects/escapes embedded 0x00. Violation: duplicate-suffix ties break the SA total order and the LF bijection; BWT becomes non-invertible.
  3. DP3 — The index is immutable and build-once. Construction is offline; the query API takes &self. Tradeoff: any text change forces a rebuild. Operational: indexes are content-addressed by a text hash + build params. Violation: in-place mutation corrupts rank caches and SA samples, defeating Send + Sync sharing.
  4. DP4 — SA is a permutation; BWT is invertible — asserted, not assumed. SA must be a bijection on [0,n); inverse_bwt(bwt) == T. Tradeoff: an O(n) post-build check costs build time. Operational: the check runs in debug and behind feature="invariant-checks" in release. Violation: a permutation defect makes locate return phantom or missing positions with no error.
  5. DP5 — Succinct overhead is budgeted and measured in bits. Every auxiliary structure (rank, select, samples) has a stated o(n) or O(r) bound and is reported by index.space_breakdown(). Tradeoff: engineering to a bit budget is slower to build. Operational: space is an SLO; regressions fail CI. Violation: "succinct" structures silently bloat to Θ(n log n), erasing the reason to use an FM-index over a plain SA.
  6. DP6 — Determinism + reproducibility. Identical text + build parameters ⇒ byte-identical index; no RNG, no wall-clock, no float in construction. Tradeoff: tie-breaking and bucket order are fixed by spec. Operational: index files are bit-reproducible across machines. Violation: nondeterministic builds make differential diffs and incident reproduction impossible.
  7. DP7 — Bounded, total decoding of untrusted indexes. Loading an index validates magic/version/lengths and bounds-checks every offset before use. Tradeoff: a validation pass on load. Operational: a truncated/hostile index yields a typed IndexError, never UB. Violation: an out-of-bounds read on a crafted index file is a memory-safety vulnerability in the query host.
  8. DP8 — Backward search narrows a half-open interval [sp, ep). All count/locate flows through the single invariant that [sp, ep) is the SA range of rows prefixed by the processed pattern suffix. Tradeoff: one shared code path, fewer specializations. Operational: interval width ep − sp is logged per query. Violation: off-by-one on ep (inclusive vs exclusive) double-counts or drops the boundary occurrence.
  9. DP9 — Space/latency trade is an explicit knob, not a hidden default. The SA sample rate s and the bitvector representation (plain vs RRR) are build parameters with documented effects. Tradeoff: callers must choose. Operational: s and representation are recorded in the index header. Violation: a silent s=1 (store full SA) defeats compression; a silent s=∞ makes locate O(n).
  10. DP10 — Integer-exact, overflow-checked arithmetic. Index/rank arithmetic uses sized integers with debug_assert-guarded bounds; widths (u32/u64) are chosen by n. Tradeoff: width selection at build time. Operational: a text exceeding 2^32 requires the 64-bit feature. Violation: u32 overflow on a >4 GB text wraps an SA index, returning a garbage position.
  11. DP11 — One canonical internal alphabet. The text is remapped to a dense [0, σ) once; SA-IS, buckets, wavelet shape, and C[] all use it. Tradeoff: a remap table (≤ 256 entries for bytes) travels with the index. Operational: extract un-maps on output. Violation: mixing raw bytes and remapped symbols corrupts C[] offsets and wavelet routing.
  12. DP12 — Two methods for every derived count. Distinct-substring count (SA+LCP vs SAM), count(P) (backward search vs SAM walk vs naive), and LRS (LCP-max vs SAM-longest) each have an independent second computation used as a cross-check. Tradeoff: extra code maintained as oracles. Operational: conformance compares the two. Violation: a single-method count with a sign/boundary error ships unnoticed.
  13. DP13 — Query paths never allocate unboundedly. count is O(m) time and O(1) space; locate allocates exactly occ outputs; extract allocates exactly the requested span. Tradeoff: no speculative buffering. Operational: memory per query is predictable and bounded by output size. Violation: an unbounded internal buffer turns a hostile locate of a frequent pattern into an OOM vector.

8. Domain Model

8.1 Text, alphabet, sentinel

T is a byte string of length |T|. The engine appends a unique sentinel $ (0x00, defined < all other symbols) once, giving the indexed string of length n = |T| + 1. The sentinel guarantees: (a) every suffix has a distinct length-bounded prefix, so the suffix order is a strict total order (I2); (b) SA[0] = n−1 (the sentinel-only suffix sorts first, I3); (c) the BWT is invertible without a separate primary-index hack (the sentinel row anchors the LF-walk). The alphabet Σ is optionally remapped to a dense [0, σ) via an order-preserving table map: byte → symbol; σ ≤ 256 for the byte path, larger for the general (wavelet) path.

8.2 Suffixes and the suffix array

The suffix starting at position i is T[i..n). The suffix array SA[0..n) lists the starting positions of all n suffixes in ascending lexicographic order: suffix(SA[0]) < suffix(SA[1]) < … < suffix(SA[n−1]). The inverse suffix array (rank array) is ISA[SA[i]] = i; ISA[p] is the rank of the suffix starting at text position p. Both are permutations of [0, n) (I1).

Lexicographic comparison uses the remapped symbol order with $ smallest. Because patterns occurring in T occupy a contiguous range of SA (all suffixes sharing a prefix P are adjacent in sorted order), count(P) is the width of that range and locate(P) reads the SA values in it. This contiguity is the foundational fact (DP8).

8.3.1 SA-IS — L/S type classification

Scanning T right-to-left, classify each position's suffix:

  • S-type if T[i..] < T[i+1..] lexicographically; the sentinel position is S-type by definition.
  • L-type if T[i..] > T[i+1..].
  • Rule: type[i] = S if T[i] < T[i+1], = L if T[i] > T[i+1], and = type[i+1] if T[i] == T[i+1]. Computed in one O(n) right-to-left pass.

A position i is LMS (leftmost-S) if type[i] == S and type[i−1] == L (i > 0). LMS positions partition T into LMS-substrings (each runs from one LMS position to the next, inclusive of both endpoints).

8.3.2 SA-IS — induced sorting

Bucket boundaries are the cumulative C[] counts (each symbol's slot range in SA). The three passes:

  1. Seed LMS suffixes into the ends of their symbol buckets (in arbitrary LMS text order initially).
  2. Induce L-type: left-to-right scan of SA; for each placed SA[i], if SA[i]−1 is L-type, place it at the front of its bucket (advance the bucket's front pointer).
  3. Induce S-type: right-to-left scan of SA; for each placed SA[i], if SA[i]−1 is S-type, place it at the end of its bucket (retreat the bucket's end pointer).

After the first induce, the LMS-substrings are sorted relative to each other. Each LMS-substring is assigned a name (rank); if all names are distinct, the reduced problem is solved directly, else recurse on the reduced string T1 of names. The recursion shrinks the input by at least half each level (LMS positions are non-adjacent), giving T(n) = T(≤ n/2) + O(n) = O(n). The final SA is produced by one more induced-sort pass seeded by the recursively-sorted LMS order.

8.4 LCP array and Kasai's algorithm

LCP[i] = lcp(suffix(SA[i−1]), suffix(SA[i])) for i ≥ 1, LCP[0] = 0. Kasai (PR4) computes it in O(n) using SA and ISA, one pass over TEXT positions p = 0..n carrying a running match-length h forward across iterations:

Step State Transition Emits
K0 text position p, carried h if ISA[p] = 0 (suffix is rank 0): no predecessor h ← 0; advance p
K1 p, h, predecessor q = SA[ISA[p]−1] extend h while T[p+h] = T[q+h] and both in bounds (bounded total work, the h−1 invariant, PR4) LCP[ISA[p]] ← h
K2 after recording h ← max(h−1, 0) — dropping T[p]'s first character shrinks the shared prefix with the next suffix by at most one advance p; loop K0 until p = n

Correctness rests on the h−1 invariant: the total number of decrements is bounded by the total number of extensions, so cumulative work across all p is O(n) (PR4). PLCP (permuted LCP) stores LCP in text order (PLCP[p] = LCP[ISA[p]]); it is "almost increasing" (PLCP[p+1] ≥ PLCP[p] − 1), enabling a cache-friendlier computation and compact storage. Worked (banana$): LCP = [0, 0, 1, 3, 0, 0, 2] (I6) — e.g. LCP[2] = lcp("a$","ana$") = 1; LCP[3] = lcp("ana$","anana$") = 3 ("ana", the LRS, occurring at text positions {1,3}); LCP[6] = lcp("na$","nana$") = 2.

8.5 RMQ over LCP — suffix-tree emulation

A range-minimum-query structure over LCP answers lcp(suffix(SA[i]), suffix(SA[j])) = min(LCP[i+1 .. j]) in O(1) — the longest-common-extension primitive. With SA + LCP + RMQ, the engine emulates a suffix tree (internal nodes = lcp-intervals) without the ~20n-byte tree. Implementations: a O(n log n)-space sparse table (simple, fast), or the O(n)-space Fischer–Heun structure (PR11). Applications: LRS (deepest internal node = max LCP), repeated-substring enumeration, and constant-time pattern-match extension.

8.7 BWT and LF-mapping

The Burrows–Wheeler Transform (PR5) is the last column of the matrix of n sorted rotations of T. Via the SA: BWT[i] = T[(SA[i] − 1) mod n]. The first column F is the sorted symbols of T; F[i] is the first symbol of suffix(SA[i]). The LF-mapping maps a row i to the row whose F-symbol is the same occurrence as BWT[i]: LF(i) = C[BWT[i]] + Occ(BWT[i], i), where C[c] = number of symbols in T strictly less than c (the start of c's F-block) and Occ(c, i) = number of occurrences of c in BWT[0..i) (a rank query). LF is a bijection (I4); iterating it from the sentinel row reconstructs T backward (inverse-BWT, I5). Its inverse Ψ(i) = SA^{-1}[SA[i] + 1] reads T forward and is the basis of the compressed suffix array (CSA, PR7). The primary index p is the row with BWT[p] = $ (equivalently SA[p] = 0); it anchors reconstruction when no explicit sentinel is used (the engine uses an explicit sentinel, so p is recorded but not required).

Worked (banana$, C[$]=0, C[a]=1, C[b]=4, C[n]=5, I10):

8.8 FM-index and backward search

The FM-index (PR6) stores BWT, C[], and a rank structure for Occ; it stores no plaintext. Backward search finds the SA interval of all occurrences of P by processing P right-to-left, maintaining a half-open interval [sp, ep) (I7), initialized to [0, n). At each step, reading pattern symbol c = P[k] from k = m−1 down to 0: both sp and ep are replaced by C[c] + Occ(c, sp) and C[c] + Occ(c, ep) respectively (computed from the pre-update values, §8.16 S1–S2); an interval that becomes empty (sp ≥ ep) at any step means P does not occur in T and the search terminates early. After processing all of P, count(P) = ep − sp. Each step is two rank queries; count(P) is O(m · t_rank) with t_rank = O(1) (byte alphabet, Occ table) or O(log σ) (wavelet tree). The interval [sp, ep) is exactly the SA range of rows prefixed by P (DP8).

Worked count("ana") on banana$ (P = a,n,a, right-to-left):

step symbol c sp = C[c]+Occ(c,sp) ep = C[c]+Occ(c,ep) interval

1 a 1 + Occ(a,0)=1 1 + Occ(a,7)=4 [1, 4)
2 n 5 + Occ(n,1)=5 5 + Occ(n,4)=7 [5, 7)

8.9 Locate via sampled suffix array

Storing the full SA (4n–8n bytes) defeats compression, so the FM-index stores SA[i] only at sampled rows. The standard scheme samples by text position: keep SA[i] iff SA[i] mod s == 0 (sample rate s), in a marked bitvector + packed value array. Locating an occurrence at row i is a walk:

Step State Transition Termination
L0 row i (from [sp,ep)), step count t=0 test: is row i marked sampled? yes → L2
L1 row i, t i ← LF(i) (one step left in the text); t ← t+1 loop L0 (bounded by ≤ s steps, §4)
L2 sampled row i, t pos ← SA_sample[i] + t return pos (the original text position)

Each occurrence costs ≤ s LF-steps (each O(t_rank)), so locate(P) is O(m·t_rank + occ·s·t_rank). Space for samples is ≈ (n/s)·log n bits plus the marking bitvector. s trades space against locate latency (DP9); default s = 32.

8.10 Extract via inverse-SA samples

extract(i, j) recovers T[i..j] without the text. Sample the inverse mapping (text position → row) at the same rate: keep the row for text positions ≡ 0 mod s. Extraction anchors at the nearest sampled position and walks backward:

Step State Transition Termination
E0 anchor = smallest sampled position ≥ j; row ← ISA_sample[anchor]; p ← anchor test: p = i? yes → E2
E1 row, p row ← LF(row); emit F[row] as the symbol at text position p−1; p ← p−1 loop E0 (bounded by anchor − i + s, §4)
E2 collected symbols for p = i .. anchor−1 reverse the emission order return T[i..j)

Cost O((j − i + s) · t_rank). The sentinel-anchored LF-walk is the same primitive as inverse-BWT (I5), restricted to a span.

8.11 Succinct rank/select

A bitvector B[0..n) supports rank1(i) = #1s in B[0..i) and select1(j) = position of the j-th 1. O(1) rank, o(n) overhead uses two levels: a superblock absolute count every L = 512 bits (stored u64) and a block relative count every K = 64 bits (packed, ≤ 9 bits each, relative to its superblock), with a final popcount on the partial word:

rank1(i) = superblock[i/512] + block[i/64] + popcount(word[i/64] & ((1<<(i mod 64)) − 1))

Layout: B is word-packed u64, LSB-first, 8 words (512 bits) per superblock; the superblock array holds one u64 absolute count per 512 bits (0.125n bits overhead); the block array holds 7 packed 9-bit relative counts per superblock (the 8th is implied by the next superblock, ≈0.123n bits) — total rank overhead ≈ 0.25n bits (§4), matching the budget gate succinct/overhead_budget.json. At i mod 64 == 0 the partial-word mask (1<<0)−1 = 0 contributes nothing; rank1(n) is the full popcount; shift-by-64 is avoided by the mod 64 guard (never literally 64). select1(j) samples the position of every 4096th 1-bit (≈0.20n bits overhead) and, between samples, scans blocks using rank to binary-search the target 1, finishing with a broadword select-in-word; the duality select1(rank1(i)) ≤ i < select1(rank1(i)+1) is the I9 property test. Both are derived once at build, immutable, O(1) per query.

8.12 Wavelet tree

For Occ(c, i) over a general alphabet, a wavelet tree (PR12) represents the BWT as a balanced binary tree over Σ: the root's bitvector marks, for each position, whether its symbol is in the left (0) or right (1) half of the alphabet; each child recurses on its half. access(i) (recover BWT[i]), rank(c, i) (= Occ), and select(c, j) are each O(log σ) via rank/select walks down the path of c — at every level the walk uses the parent's mapped index, not the original i, so rank composes level-to-level. A balanced tree uses n·⌈log σ⌉ + o(n log σ) bits; a Huffman-shaped tree weights depth by symbol frequency, reaching n·H_0 + o(n·H_0) bits (shorter paths for frequent symbols). The wavelet matrix is an equivalent level-wise layout with better constants. For σ ≤ 256 a direct Occ table (one rank bitvector per symbol, or a 256-way checkpointed counter) may beat the wavelet tree on constants; the build picks per σ (ADR-08).

8.13 RRR and compressed FM-index

RRR (Raman–Raman–Rao, PR8) compresses a bitvector to n·H_0 + o(n) bits while keeping O(1) rank/select. It splits B into blocks of t bits (e.g. t = 15 or 31); each block is encoded as a pair (class, offset) where class = popcount(block) (⌈log(t+1)⌉ bits) and offset is the block's index within the C(t, class) enumeration of all t-bit strings of that popcount (⌈log C(t, class)⌉ bits, variable). Superblock samples store cumulative rank + a bit-pointer into the offset stream every K blocks; decoding uses precomputed binomial and per-class offset tables (PR14). Backing the FM-index's wavelet-tree bitvectors with RRR yields an index of ≈ n·H_k + o(n) bits (PR6, PR8). The trade: RRR rank is a few table lookups slower than plain rank (constant factor), bought against substantial space on compressible text.

8.14 r-index / RLBWT for repetitive text

On highly repetitive T (versioned files, pan-genomes), the BWT consists of r maximal runs of equal symbols, with r ≪ n. The run-length BWT (RLBWT) stores only run heads + lengths (O(r) words, PR13). The r-index (Gagie–Navarro–Prezza, PR9) augments RLBWT with SA samples at run boundaries and a toehold: backward search runs on the RLBWT in O(m log(n/r)); one known SA value (the toehold, obtained when the search interval first contains a run boundary) bootstraps locate, and the run-boundary samples let each subsequent occurrence be found by LF-stepping to the next sampled boundary — O((m + occ) log(n/r)) total, O(r) space (I15). The build selects the r-index when r/n falls below a threshold (e.g. 0.3), else the sampled-SA FM-index (ADR-14).

8.15 Suffix automaton (DAWG)

The suffix automaton of T is the minimal deterministic finite automaton recognizing exactly the set of substrings of T (Blumer et al., PR10). Built online by adding one symbol at a time: each new symbol may clone a state to preserve minimality. State invariants: len[v] = length of the longest string in v's endpos-equivalence class; link[v] = suffix link to the class of the next-shorter suffix with a different endpos. Bounds: ≤ 2n − 1 states, ≤ 3n − 4 transitions (I13). Queries: count(P) = walk transitions for P; if it ends in state v, the number of occurrences is |endpos(v)| (precomputable by a reverse-topological pass over suffix links, decreasing len); distinct substrings = Σ_v (len[v] − len[link[v]]); longest-repeated-substring = the deepest state reachable by ≥ 2 endpos. The SAM is an independent oracle for count/distinct/LRS (DP12, I14) and relates to the suffix tree of reverse(T).

8.16 State / interval transition table (backward search)

Per backward-search step on interval [sp, ep) reading symbol c:

Stage Input Operation Output
S0 init — sp ← 0, ep ← n full SA interval
S1 rank-sp sp, c sp' ← C[c] + Occ(c, sp) new lower bound
S2 rank-ep ep, c ep' ← C[c] + Occ(c, ep) new upper bound
S3 test sp', ep' if sp' ≥ ep' → empty (P absent) continue or terminate
S4 advance — k ← k − 1 (next pattern symbol leftward) loop or finish
S5 result [sp, ep) count = ep − sp; for locate, iterate rows count / occurrence rows

Termination: pattern exhausted (k < 0) → report [sp, ep); or empty interval → report 0. The interval is always half-open and non-decreasing-in-correctness (I7).

sufx-bits (no_std) with packed bit access and integer codecs; workspace compiles with zero warnings; cargo test green; CI matrix green on first PR; sufx inspect --bits round-trips a bit pattern.

  • get_bits/set_bits round-trip for all widths 1..=64 and all bit offsets (incl. word-spanning).

12.5 Conformance Fixtures

  • conformance/succinct/bit_roundtrip.json — (offset,width,value) set/get triples incl. boundaries.
  • conformance/succinct/intcode_vectors.json — γ/δ/vbyte (value, encoded_bits) pairs.
  • conformance/succinct/popcount.json — random words + expected popcounts.

12.6 Pitfalls

  • Bit-order confusion (LSB-first vs MSB-first): silently corrupts every downstream structure (RRR, samples, wavelet). Fix and document one convention (LSB-first); add an explicit fixture asserting bit 0 is the LSB of word 0.
  • get_bits word-boundary off-by-one: a width spanning two u64 words must OR the high bits of word k with the low bits of word k+1; test offsets {63, 64, 127}.
  • Shift-by-64 UB: 1u64 << 64 is UB; guard every shift with % 64 or branch on w == 64.
  • vbyte continuation bit: misplacing the high continuation bit silently truncates large values; test 2^32 − 1.

12.7 Performance Concerns

  • get_bits must be branch-light and #[inline]; no per-bit loops — use shift + mask + (optional) two-word merge.
  • popcount must lower to a single instruction (x86-64 POPCNT, aarch64 CNT); the SWAR fallback is ~5× slower and used only where the intrinsic is absent.
  • No heap allocation in BitVector access; BitReader borrows, never copies.

12.8 Edge Cases

  • len == 0 (empty bitvector); reads spanning exactly two words; widths exactly 64.
  • Codec inputs 0 and 2^32 − 1; unaligned bit offsets; vbyte single-byte vs multi-byte boundary at 128.

12.9 Failure Analysis

  • A bit-order or boundary bug here is silent and corrupts SA samples and RRR globally; blast radius = the whole engine. Detection: round-trip fixtures + a proptest over random (offset, width, value). Recovery: this is pre-dependency, so the cost is contained to Phase 0 if caught here — hence the heavy property testing before any structure depends on bits.

12.10 Operational Notes

  • No runtime surface. Establish fmt/clippy/test/deny/audit CI gates and the invariant-checks + oracle features here so every later phase inherits them. CI artifacts retained 30 days.

13. Phase 1 — Naive Suffix Array + Binary-Search Count (The Oracle)

13.1 Objectives

sufx-sa::naive::SuffixArray + binary-search query; CLI sufx verify --naive builds and dumps SA for a small text.

13.4 Acceptance Criteria

  • conformance/fm/count_basic.json — (pattern, count, positions) for the canonical texts.

13.6 Pitfalls

  • Comparator not treating the sentinel as strictly smallest (I3) → wrong total order.

  • Binary-search boundary (lower- vs upper-bound) off-by-one → drops or double-counts the boundary occurrence.

  • Irrelevant to production (oracle only). Cap oracle inputs (≤ 100 KB) so CI stays fast; the comparator's worst case is O(n) per comparison on long common prefixes.

  • Empty text (SA=[0], the sentinel-only suffix); single symbol; all-equal text (worst-case comparator depth); m > n; pattern absent.

  • Ships only behind cfg(test)/feature="oracle"; documented as O(n log²n), never on a production query path. sufx verify exposes it for differential debugging only.

14. Phase 2 — SA-IS Linear-Time Construction (+ DC3 Cross-Check)

14.1 Objectives

  • Implement SA-IS (O(n), ADR-03, PR2): L/S typing, LMS identification, induced sorting, recursion on the reduced LMS string (§8.3).
  • Add DC3/skew (PR3) as a second linear-time builder for cross-validation (ADR-19).
  • This is the production SA builder; constraints: in-RAM only (external-memory PhaseDeferred("Deferred Features Register")); generalized over an integer alphabet for recursion; width-checked (I16).

14.2 Detailed Implementation Steps

  • sufx-sa/src/sais.rs (PR2, §8.3):
    • right-to-left L/S type pass (type[i] = S if T[i]<T[i+1], L if >, else type[i+1]; sentinel is S, §8.3.1).
    • LMS-position list (type[i]==S && type[i-1]==L).
    • bucket boundaries from C[] (cumulative symbol counts); separate front and end pointer arrays.
    • three induced-sort passes (§8.3.2): seed LMS at bucket ends; induce L left-to-right at bucket fronts; induce S right-to-left at bucket ends.
    • name LMS-substrings (compare full LMS-substrings incl. type transitions); recurse on the reduced string of names if names are non-unique; final induced-sort pass seeded by the recursively-sorted LMS order.
    • generic over Sym: integer so the recursive call (alphabet = LMS names) reuses the same routine.
  • sufx-sa/src/dc3.rs (PR3) — difference-cover mod 3: sort sample suffixes (positions ≢ 0 mod 3) by recursion on a radix-named triple string, then merge with non-sample suffixes via a comparison rule.
  • bucket-pointer scratch reused across recursion levels (bound working space to O(n) ints + O(σ)).
  • Idx width selected at build by n (u32 default / u64 behind feature="wide", I16); overflow → BuildError::WidthOverflow.

14.3 Deliverable

sufx-sa::sais::build(&[Sym]) → SuffixArray in linear time; sufx build uses it; sufx inspect --sa dumps it; DC3 available behind a flag for cross-check.

14.4 Acceptance Criteria

  • SA-IS output equals the naive oracle (Phase 1, §13) on all fixtures and the full Pizza & Chili corpus; equals DC3 output.
  • SA is a permutation (I1) and sorted (I2).
  • Build throughput ≥ 3 MB/s/core warm (byte input, M2); recursion depth O(log n) (instrumented).
  • Texts near 2^32 rejected without --wide (I16).

14.5 Conformance Fixtures

  • conformance/sa/banana.json, sa/mississippi.json, sa/all_equal.json, sa/fibonacci_string.json (recursion stress, deep reduction).
  • conformance/sa/corpus_sha.json (Pizza&Chili SHAs + expected SA hashes); sa/dc3_parity.json (SA-IS == DC3).

14.6 Pitfalls

  • Mis-seeding LMS at bucket ends vs fronts: the classic SA-IS bug; LMS seed at ends, L-induce at fronts, S-induce at ends.
  • Not resetting bucket pointers between the L and S induce passes → corrupted placement.
  • LMS-substring equality test during naming must compare the full substring including the type-change boundary, not just the prefix.
  • Off-by-one in reduced-string length; failing the all-equal text (single bucket, deep type runs); forgetting the sentinel is the unique smallest LMS (§8.3.3).

14.7 Performance Concerns

  • SA-IS is memory-bound: induced-sort passes are random-access scatters into buckets — cache misses dominate. Keep SA, the type bitvector, and bucket arrays contiguous; pack the type array to one bit/position.
  • C[] recomputation per recursion level is O(σ) and cheap. Avoid heap churn across levels (reuse a single scratch arena). Sequential write of SA in the final pass is cache-friendly; the scatters are not.

14.8 Edge Cases

  • Empty/one-symbol text; all-equal text (degenerate single bucket); highly periodic text (Fibonacci/Thue–Morse) stressing recursion depth; alphabet remap producing σ = 1; text near 2^32 (I16).

14.9 Failure Analysis

  • A bucket-pointer bug produces an SA that is almost sorted — passing small unit tests, failing on the corpus. Detection: I1 permutation sweep + differential vs naive/DC3 on the corpus. Blast radius: every query is wrong. Containment: I1/I2 checks behind invariant-checks block a bad build. Recovery: bisect via sufx verify on the proptest-shrunk minimal failing slice.

14.10 Operational Notes

  • build emits tracing spans: n, σ, recursion depth, bytes/sec. Metric sais_build_bytes_per_sec gates the benchmark CI (M2). Document in-RAM-only; external-memory construction PhaseDeferred("Deferred Features Register"). SACA-K (O(1) workspace) PhaseDeferred("Deferred Features Register").

15. Phase 3 — LCP Array (Kasai) + PLCP + RMQ/LCE

15.1 Objectives

  • Compute the LCP array in O(n) via Kasai (PR4, §8.4), derive PLCP (text-order), and build an RMQ over LCP for O(1) longest-common-extension (§8.5) — together emulating a suffix tree without the ~20n-byte tree.
  • Deliver the first user-facing analytics: lrs, distinct_substrings.

15.2 Detailed Implementation Steps

  • sufx-sa/src/lcp.rs (PR4, §8.4) — Kasai using SA + ISA with the h−1 decrement invariant; PLCP variant (PLCP[p] = LCP[ISA[p]], "almost-increasing") for cache locality and compact storage.
  • sufx-sa/src/rmq.rs — sparse table (O(n log n) space, O(1) query) default; Fischer–Heun O(n)-space O(1)-query structure behind feature="rmq-compact" (ADR-07, PR11).
  • LCE primitive: lce(i,j) = RMQ(LCP, ISA[i]+1 ..= ISA[j]) (assuming ISA[i] < ISA[j]; swap otherwise).
  • LCP-derived queries (§8.6): lrs = substring at argmax LCP; distinct = Σ(n−SA[i]) − Σ LCP[i].

15.3 Deliverable

LcpArray + Rmq; sufx inspect --lcp dumps LCP; sufx lrs returns the longest repeated substring; sufx distinct returns the distinct-substring count.

15.4 Acceptance Criteria

  • LCP matches a naive O(n²) reference on fixtures (I6); LCP[0]=0.
  • lrs(banana$) = "ana" (len 3); distinct_substrings(banana) = 15 (excl. sentinel) / 22 (incl.), per §8.6.
  • LCE matches naive on random pairs; Kasai's total decrement count is ≤ n (instrumented → O(n)).

15.5 Conformance Fixtures

  • conformance/lcp/banana.json (LCP=[0,0,1,3,0,0,2]), lcp/mississippi.json, lcp/lrs_distinct.json (expected values), lcp/lce_pairs.json.

15.6 Pitfalls

  • LCP[0] undefined → set 0 by convention.
  • The h−1 decrement applies only when h > 0; decrementing at h=0 underflows.
  • PLCP "almost-increasing" (PLCP[p+1] ≥ PLCP[p]−1) mis-asserted breaks the compact path.
  • Sparse-table log table off-by-one; RMQ half-open vs closed range confusion for LCE (lock to inclusive [ISA[i]+1, ISA[j]]).

15.7 Performance Concerns

  • Kasai's text-order access scatters over SA/ISA (cache-unfriendly); the PLCP variant restores locality (text-sequential).
  • Sparse table is O(n log n) memory — large on big n; switch to Fischer–Heun (O(n)) when SA memory is tight (feature="rmq-compact").

15.8 Edge Cases

  • All-equal text (LCP = [0, n−2, n−3, …, 1] shape); no repeats (all LCP=0, lrs empty); single symbol; distinct-count overflow for large n (use u64 accumulator).

15.9 Failure Analysis

  • A wrong LCP silently corrupts lrs/distinct/LCE. Detection: naive cross-check (I6) and the SA+LCP-vs-SAM distinct agreement (I14, DP12). Recovery: recompute via the PLCP path and diff against the sparse-table path.

15.10 Operational Notes

  • Document the distinct-substring formula and the with/without-sentinel convention prominently (a common user confusion). Metric lcp_kasai_decrements confirms linearity. lrs/distinct are the first user-facing analytics; expose both --method sa-lcp and (later) --method sam.

16.1 Objectives

16.5 Conformance Fixtures

16.6 Pitfalls

  • The (SA[i]−1) mod n wraparound at SA[i]=0 (yields the sentinel) — a missing mod n panics or mis-indexes.
  • Wrong anchor row for inverse-BWT (must start at the sentinel/SA=0 row).
  • C[] exclusive-vs-inclusive prefix-sum off-by-one (lock to exclusive: C[c] = #symbols < c).

16.7 Performance Concerns

  • BWT construction is a sequential scan of SA (cache-friendly) writing BWT (sequential) — fast.

16.8 Edge Cases

  • Sentinel-only text; all-equal text (BWT is one run + sentinel, r=2); interior sentinel (must not happen — I3); primary index at row 0.

16.9 Failure Analysis

17. Phase 5 — Succinct Rank/Select Bitvector

17.1 Objectives

  • Build the O(1)-rank, o(n)-overhead bitvector (two-level superblock/block + popcount, §8.11) and a sampled select (I8, I9, ADR-11/12).
  • This replaces the naive Occ and underlies the wavelet tree (Phase 6), SA-sample marking (Phase 8), and RRR (Phase 10).
  • Constraint: rank overhead ≤ 0.25 n bits, select ≤ 0.20 n bits, both measured and CI-gated (DP5, M5, M6).

17.2 Detailed Implementation Steps

  • sufx-succinct/src/rank_select.rs (§8.11, B8) — RankSupport: superblock absolute counts every L=512 bits (u64), block relative counts every K=64 bits (packed ≤ 9 bits, relative to the superblock); rank1(i) = superblock[i/512] + block[i/64] + popcount(word[i/64] & ((1<<(i%64))−1)).
  • sufx-succinct/src/select.rs — SelectSupport: store the position of every 4096th 1-bit; between samples scan blocks using rank to binary-search the target 1 (ADR-12).
  • expose rank0(i) = i − rank1(i); select0 symmetric (optional, behind a flag).
  • space_breakdown() accounts rank/select overhead bits per structure (DP5).

17.3 Deliverable

BitVector with O(1) rank1/rank0 and select1; space_breakdown reports overhead bits; sufx inspect --rank shows the structure on a sample bitvector.

17.4 Acceptance Criteria

  • rank1(i) equals brute-force popcount for all i on random + structured bitvectors (I8), incl. rank1(n).
  • select1(rank1(i)) duality holds (I9).
  • Rank overhead ≤ 0.25 n bits (M5), select ≤ 0.20 n bits (M6) (measured, CI-gated).
  • Rank is O(1) — benchmark latency is flat in i (constant instruction count).

17.5 Conformance Fixtures

  • conformance/succinct/rank_random.json, succinct/select_random.json, succinct/rank_select_duality.json, succinct/overhead_budget.json (measured overhead vs budget).

17.6 Pitfalls

  • Block count must be relative to the superblock, not absolute (else it overflows the 9-bit field).
  • rank1(n) (full count) boundary; partial-word mask at i % 64 == 0 (empty mask — must yield 0, not the full word).
  • Select sampling too sparse (slow scan) or too dense (overhead blowup); shift-by-64 UB at word edges (12.6).

17.7 Performance Concerns

  • Rank is two array loads + one masked popcount — design for one cache line per query (interleave superblock + block, SDSL rank_support_v5 style, to halve cache misses).
  • Select's between-sample scan is the latency risk; tune the sample interval against bitvector density (sparse → larger interval).

17.8 Edge Cases

  • All-zeros / all-ones bitvector; n not a multiple of 512/64 (zero-padded tail); select1(j) for j > rank1(n) → error; empty bitvector.

17.9 Failure Analysis

  • A rank bug corrupts every Occ, hence every count/locate — but produces plausible wrong answers (no crash). Detection: brute-force rank fixture (I8) + the downstream count-vs-naive differential. Recovery: rebuild the rank index from the raw bitvector (O(n), cheap, no data loss).

17.10 Operational Notes

  • space_breakdown exposes rank/select overhead as a first-class metric (DP5); a regression past budget fails CI (succinct/overhead_budget.json, M5/M6). Document the superblock/block constants and the overhead derivation in docs/adr.

18. Phase 6 — Wavelet Tree over the BWT

18.1 Objectives

  • Build a wavelet tree over the BWT giving access, rank (= Occ), select in O(log σ) over a general alphabet (PR12, §8.12); balanced and Huffman-shaped variants (ADR-09).
  • For σ ≤ 64, provide the direct Occ-table fast path (O(1), ADR-08).
  • Define the OccRank seam (§11) implemented by all three representations.

18.2 Detailed Implementation Steps

  • sufx-succinct/src/wavelet.rs (PR12, §8.12):
    • balanced tree: at each node a BitVector (with §17 rank) marks left(0)/right(1) by alphabet midpoint; access(i) walks down using bit + rank; rank(c,i) follows c's root-to-leaf path mapping i via rank at each level (using the parent's mapped index, 18.6).
    • Huffman-shaped variant (feature="wt-huff"): build by symbol frequency (canonical Huffman) so frequent symbols have short paths → n·H_0 bits; serialize the codebook.
  • direct Occ table for small σ (ADR-08): per-symbol checkpointed counters every K positions + popcount, O(1) Occ.
  • implement OccRank for all three; FmIndex<O: OccRank> is generic over it; the build picks per σ.

18.3 Deliverable

WaveletTree implementing OccRank; sufx inspect --occ c i returns Occ(c,i); space_breakdown shows wavelet bits vs n·H_0.

18.4 Acceptance Criteria

  • access(i) == BWT[i] ∀ i; rank(c,i) equals brute-force Occ ∀ (c,i) on fixtures + corpus (I8 extended).
  • Balanced size ≈ n·⌈log σ⌉ bits; Huffman ≈ n·H_0 (measured, within o(n) slack).
  • O(log σ) query (latency benchmark scales with log σ).

18.5 Conformance Fixtures

  • conformance/succinct/wavelet_access.json, succinct/wavelet_rank.json, succinct/wavelet_select.json, succinct/occ_vs_naive_corpus.json, succinct/wt_huff_entropy.json.

18.6 Pitfalls

  • Alphabet-midpoint routing must match the leaf assignment exactly (a mismatch silently misroutes rank).
  • Huffman codebook must be canonical + serialized (else load gives the wrong shape).
  • rank at a level must use the parent's mapped index, not the original i; select walks bottom-up (inverse of access).
  • Empty subtrees for absent symbols (balanced) vs omitted (Huffman) — handle both.

18.7 Performance Concerns

  • Each wavelet level is a rank query (§17) — log σ cache misses per Occ. For DNA (σ=4) the direct Occ table (2-level, or a 4-way counter) is far faster — the build picks per σ.
  • Wavelet matrix layout (level-wise) improves locality for large σ; offered behind a flag.

18.8 Edge Cases

  • σ = 1 (single leaf, Occ trivial); σ = 256 (depth 8); symbols absent from T (zero-frequency leaves balanced, omitted Huffman); the sentinel as a symbol.

18.9 Failure Analysis

  • A wavelet routing bug yields wrong Occ → wrong count that looks reasonable. Detection: Occ-vs-naive on the corpus + the count differential (§19). Recovery: rebuild; if Huffman, re-derive the canonical codebook and compare shape against the serialized one.

18.10 Operational Notes

  • space_breakdown reports wavelet bits and the H_0 ratio. Document when to prefer the direct Occ table (small σ) vs wavelet (large σ) vs RRR-backed wavelet (Phase 10, compressible). Log σ and the chosen Occ representation at build (occ_representation metric).

19. Phase 7 — FM-Index Backward Search (Count)

19.1 Objectives

  • Assemble the FM-index (BWT + C[] + Occ via wavelet/table) and implement backward search over a half-open interval [sp, ep) to answer count(P) from the self-index alone — no plaintext, no full SA (I7, DP8, PR6, §8.8).

19.2 Detailed Implementation Steps

  • sufx-fm/src/index.rs (PR6) — FmIndex{bwt, c, occ, n} constructed from Phase 4's BWT + Phase 6's OccRank.
  • sufx-fm/src/search.rs (DP8, §8.8, §8.16) — the backward-search loop: for P[k] right-to-left, sp = C[c] + Occ(c, sp), ep = C[c] + Occ(c, ep); early-exit on sp ≥ ep; both ranks computed from the pre-update sp/ep.
  • count(P) = ep − sp; return the final Interval for locate (Phase 8) to consume.

19.3 Deliverable

Index::count(P) from a serialized FM-index without the text; CLI sufx query count PATTERN.

19.4 Acceptance Criteria

  • count equals the naive oracle for thousands of patterns over the corpus (sampled substrings + random + absent).
  • count("ana", banana$) = 2 with interval trace [0,7)→[1,4)→[5,7)→[2,4) (§8.8); absent symbols → 0; m > n → 0.
  • count is O(m·t_rank): ≤ 2m rank ops (benchmarked); < 2 µs for m ≤ 64, byte alphabet, warm (§4, M1).

19.5 Conformance Fixtures

  • conformance/fm/count_banana.json (interval trace), fm/count_corpus.json (pattern→count over Pizza&Chili), fm/count_absent.json, fm/count_edge.json (empty/overlong).

19.6 Pitfalls

  • ep inclusive vs exclusive — half-open is mandatory (I7); an off-by-one drops/double-counts the boundary occurrence.
  • Occ(c, ep) must use the current ep before sp/ep are updated (compute both from old values).
  • C[c] indexing for the sentinel; empty-pattern convention locked to count = 0 (§8.17, ADR-09).

19.7 Performance Concerns

  • Each step is two Occ queries = 2 log σ (wavelet) or 2 (table) rank ops; the two ranks for the same symbol c at sp/ep share the wavelet path — fuse them to halve cache misses.
  • Pattern bytes scanned right-to-left (sequential, cache-friendly). Tail latency is the wavelet depth on large σ.

19.8 Edge Cases

  • Single-symbol pattern (count = C[c+1] − C[c]); pattern == whole text; repeated-symbol pattern on all-equal text (interval shrinks predictably); pattern with a symbol absent from T (interval empties at the first absent step, C[c]==C[c+1]).

19.9 Failure Analysis

  • An off-by-one on ep yields a ±1 count error that passes casual testing. Detection: large-scale count-vs-naive differential (I7, DP12). Blast radius: all counts + the locate interval. Recovery: replay the interval trace via sufx inspect --search.

19.10 Operational Notes

  • Per-query tracing span records m, final ep−sp, rank-op count; metrics count_total, count_empty_interval_total, count_latency_us (histogram, M1). The FM-index is now a complete membership/count index; locate/extract follow in Phase 8.

20. Phase 8 — Sampled Suffix Array → Locate + Extract + Serialization

20.1 Objectives

  • Add locate(P) (every occurrence's text position) and extract(i,j) (recover a substring) from the self-index, via a sampled SA and sampled ISA at rate s (DP9, I11, I12, §8.9–§8.10).
  • Implement versioned, bounds-checked serialization (I17, DP7). After this phase the full SA need not be stored — the headline self-index capability.

20.2 Detailed Implementation Steps

  • sufx-fm/src/sample.rs (§8.9, DP9) — mark sampled rows (SA[i] mod s == 0) in a BitVector (+ §17 rank); store their SA values packed to ⌈log n⌉ bits (SaSamples); store ISA samples for text positions ≡ 0 mod s (IsaSamples).
  • sufx-fm/src/locate.rs (§8.9, I11) — for each row in [sp, ep): LF-walk until a sampled row, pos = SA_sample + steps; a walk-step cap == s+1 guards against marking bugs.
  • sufx-fm/src/extract.rs (§8.10, I12) — anchor at the nearest sampled text position ≥ j, LF-walk backward emitting F-symbols, collect T[i..j].
  • sufx-fm/src/serialize.rs (I17, DP7, ADR-18) — versioned, length-prefixed, little-endian save/load of the whole Index; bounds-check every array length against the buffer before any access; typed IndexError on truncation/bad-magic/version/corrupt-permutation.

20.3 Deliverable

Index::locate(P) and Index::extract(i,j); full save/load; CLI sufx query locate PATTERN, sufx query extract i j; the text is no longer required at query time.

20.4 Acceptance Criteria

  • locate(P) equals the naive position set (sorted) for thousands of patterns (I11); extract(i,j) == T[i..j] ∀ valid ranges (I12).
  • load(save(idx)) round-trips structurally (I17); locate cost ≤ occ·s LF-steps (M7).
  • Truncated/tampered index files yield typed IndexError, never panic/UB (DP7); fuzz index_load zero-crash.

20.5 Conformance Fixtures

  • conformance/fm/locate_banana.json (locate("ana")={1,3}), fm/locate_corpus.json, fm/extract_corpus.json, fm/serialize_roundtrip.json, fm/malformed_index/ (truncated, bad-magic, corrupt-permutation, version-mismatch).

20.6 Pitfalls

  • LF-step arithmetic: pos = SA_sample + steps, not −.
  • Wrong anchor for extract (must be ≥ j, walk left); sample-marking bitvector rank off-by-one.
  • Sampling rate s not recorded in the header (DP9) → unreadable index.
  • locate output order is row order, not position order — sort if the contract requires.

20.7 Performance Concerns

  • locate is occ × (up to s) random-access LF-steps — the dominant query cost; tune s (small for locate-heavy, large for space). Sampled-value array packed to ⌈log n⌉ bits.
  • extract is sequential in the span but each step is a rank — batch where possible. load is mmap-lazy: header validated first, pages faulted on demand (< 50 ms for 1 GB, §4, M3).

20.8 Edge Cases

  • locate of a pattern occurring occ = n−1 times (every position; bounded output, DP13); extract(0,n) (whole text); extract spanning a sampled boundary; i == j (empty); out-of-bounds → QueryError::Range.

20.9 Failure Analysis

  • A sampling-arithmetic bug returns positions off by a constant or misses occurrences whose row never hits a sample (infinite walk if marking is wrong). Detection: locate-vs-naive (I11) + the walk-step cap assertion. Recovery: rebuild samples; sufx inspect --samples dumps marked rows and values.

20.10 Operational Notes

  • s is in the index header and reported by space_breakdown; document the locate-latency-vs-space curve. Metrics locate_total, locate_lf_steps (histogram), extract_bytes_total. This phase delivers the complete count/locate/extract triad from a compressed self-index — the headline capability. index_load is the security-critical decode path (Threat Model).

21. Phase 9 — Suffix Automaton (DAWG) + Distinct/LRS Oracle

21.1 Objectives

  • Build the suffix automaton online (Blumer/Crochemore, PR10, §8.15) with suffix links and endpos sizes; use it as an independent oracle for count, distinct_substrings, lrs (DP12, I13, I14).
  • Sets up generalized multi-document indexing context (deferred).

21.2 Detailed Implementation Steps

  • sufx-sam/src/automaton.rs (PR10, §8.15) — online construction: extend(c) per symbol, with state cloning to preserve minimality when len[q] != len[p]+1; maintain len[], link[], next[] (BTreeMap<Sym,u32> or fixed array per symbol).
  • sufx-sam/src/queries.rs (I14, DP12) — count(P) by transition walk → |endpos(v)| (precomputed via a reverse-topological pass over suffix links, decreasing len); distinct = Σ_v (len[v] − len[link[v]]); lrs = deepest state with |endpos| ≥ 2.
  • assert state/transition bounds (I13) post-build.

21.3 Deliverable

SuffixAutomaton + SAM queries; sufx inspect --sam (size, states); sufx distinct --method sam and --method sa-lcp for cross-check.

21.4 Acceptance Criteria

  • States ≤ 2n−1, transitions ≤ 3n−4 (I13).
  • SAM distinct equals the SA+LCP value on every fixture and the corpus (I14); SAM count equals the FM-index count; SAM lrs equals the LCP lrs.
  • Online build is O(n log σ) (M12).

21.5 Conformance Fixtures

  • conformance/sam/banana_size.json (states/transitions), sam/distinct_agreement.json (SAM vs SA+LCP over corpus), sam/count_agreement.json, sam/lrs_agreement.json.

21.6 Pitfalls

  • The clone step (split when len[q] != len[p]+1) is the classic SAM bug — copy link/len/next and re-point exactly.
  • endpos-size propagation must follow suffix links in reverse-topological (decreasing len) order.
  • Transition maps over large σ are memory-heavy (array vs map trade); the initial/empty state has link = −1.

21.7 Performance Concerns

  • BTreeMap transitions cost O(log σ) per step; for small σ use a fixed array per state (faster, more memory). Online build is mostly cache-unfriendly pointer chasing — acceptable as a build-time oracle. endpos topological pass is O(n).

21.8 Edge Cases

  • Empty/one-symbol text (2-state automaton); all-equal text (linear chain); the clone-vs-no-clone branch on each extend; counting occurrences of the empty pattern (convention).

21.9 Failure Analysis

  • A clone bug makes the automaton non-minimal or wrong, breaking distinct/count. Detection: the I13 size bounds (a too-large automaton signals a clone defect) + the I14 cross-method agreement. Recovery: rebuild; diff SAM distinct against SA+LCP to localize the divergence.

21.10 Operational Notes

  • The SAM is build-time/optional (BuildParams.build_sam); document its role as the differential oracle, not the primary query path. Generalized SA over a document collection (document listing) is PhaseDeferred("Deferred Features Register"). Metric sam_states, sam_transitions.

22. Phase 10 — RRR Compressed Bitvectors → Entropy-Compressed FM-Index

22.1 Objectives

  • Implement RRR bitvectors (n·H_0 + o(n) bits, O(1) rank/select, PR8, §8.13) and back the wavelet tree's bitvectors with RRR, yielding an FM-index of ≈ n·H_k + o(n) bits (PR6/PR8, ADR-10).
  • Constraint: FM-index target < 1× the text size on compressible corpora (§4, M4).

22.2 Detailed Implementation Steps

  • sufx-succinct/src/rrr.rs (PR8, PR14, §8.13) — split each bitvector into t-bit blocks (t ∈ {15,31}); encode (class = popcount, offset) where offset indexes the C(t,class) enumeration (⌈log C(t,class)⌉ variable bits); superblock samples (cumulative rank + bit-pointer into the offset stream) every K blocks; precomputed binomial + per-class decode tables (u128 intermediates).
  • rank1/select1 over RRR: locate superblock, decode blocks forward summing classes, decode the target block to a popcount-prefix.
  • make WaveletTree generic over BvKind (Plain | Rrr); BuildParams.bitvector selects.

22.3 Deliverable

RrrVector implementing rank/select; RRR-backed FM-index; space_breakdown shows n·H_0/n·H_k ratios; CLI sufx build --compress rrr.

22.4 Acceptance Criteria

  • RRR rank/select equal the plain bitvector's on all fixtures + corpus (I8 extended).
  • RRR size ≤ n·H_0 + o(n) (measured, within slack); RRR-backed FM-index count/locate/extract identical to the plain index.
  • Space on english/dna reduced toward n·H_k (M4); rank slowdown vs plain ≤ 3× (M9, documented constant factor).

22.5 Conformance Fixtures

  • conformance/succinct/rrr_rank_select.json, succinct/rrr_size_vs_h0.json, fm/rrr_query_parity.json, succinct/rrr_corpus_space.json.

22.6 Pitfalls

  • The binomial table C(t,class) must be exact (u128 intermediates).
  • Offset bit-width is variable per class (a fixed width wastes the compression).
  • Superblock bit-pointer must align with the offset stream; decoding a block requires the class table for that popcount.
  • t too large blows up table size; too small loses compression.

22.7 Performance Concerns

  • RRR rank is several table lookups + a partial decode — slower than plain rank's single popcount; the superblock interval K trades space (samples) against decode-scan length.
  • Cache behavior: the class array and offset stream are separate — co-locating samples helps. RRR shines only on compressible bitvectors (skewed alphabets).

22.8 Edge Cases

  • All-zeros/all-ones blocks (class 0 / class t, offset width 0 — store nothing); t not dividing n (pad the last block); a maximal-entropy bitvector (RRR offers no gain — document the crossover); very large σ wavelet with many tiny bitvectors.

22.9 Failure Analysis

  • An RRR decode bug yields wrong rank → wrong Occ → wrong queries, only on compressed builds. Detection: RRR-vs-plain parity (I8 extended) + the count/locate differential on both representations. Recovery: fall back to the plain build (--compress none) and diff to localize.

22.10 Operational Notes

  • space_breakdown reports per-structure bits and the H_0/H_k ratios as an SLO (DP5); document the compressibility crossover (RRR helps on english/dna/xml, not on random). Build logs the chosen t, K, achieved bits/symbol.

23. Phase 11 — r-Index / RLBWT for Highly Repetitive Text

23.1 Objectives

  • Implement the run-length BWT and the r-index (Gagie–Navarro–Prezza, PR9, §8.14): O(r) space, run-boundary SA samples, the toehold mechanism, O((m+occ)·log(n/r)) locate — for repetitive corpora where r ≪ n (I15, ADR-14).

23.2 Detailed Implementation Steps

  • sufx-rindex/src/rlbwt.rs (PR9, PR13, §8.14) — encode the BWT as r runs (head, len); rank over runs via a sparse bitvector marking run starts (§17/RRR rank, §22).
  • sufx-rindex/src/r_index.rs (PR9) — store SA values at run boundaries (first/last position of each run); backward search on the RLBWT.
  • sufx-rindex/src/toehold.rs (PR9) — when the search interval first straddles a run boundary, recover one SA value (the toehold); thereafter step to adjacent run-boundary samples to enumerate all occurrences.
  • auto-select in Index::build: compute r/n; if < repetitive_threshold (default 0.3) build the r-index, else the Phase 8 sampled-SA FM-index (ADR-14).

23.3 Deliverable

RIndex with count/locate; auto-selection in Index::build; CLI sufx build --index auto|fm|r; space_breakdown shows O(r) bits.

23.4 Acceptance Criteria

  • r-index count/locate equal the FM-index and the naive oracle on the Pizza & Chili repetitive set (I15).
  • Run count r matches a direct BWT scan; Σ run_len = n; space O(r) (≈ (2+ε)·r·(log n + log σ) bits, measured, M8).
  • Locate is O((m+occ)·log(n/r)); on non-repetitive text the FM-index is correctly chosen instead.

23.5 Conformance Fixtures

  • conformance/rindex/run_count.json (BWT run counts), rindex/repetitive_locate.json (vs naive on cere, einstein, world_leaders), rindex/space_vs_r.json, rindex/auto_select.json.

23.6 Pitfalls

  • The toehold bootstrap is subtle — recovering the first known SA value and propagating via run-boundary samples must be exact.
  • Run-boundary sampling stores two SA values per run (start/end) — getting which to use during the LF-walk.
  • log(n/r) predecessor queries over run starts need a correct sparse-bitvector rank/select; threshold mis-tuning picks the wrong index for borderline r/n.

23.7 Performance Concerns

  • On repetitive text the r-index is both smaller and often faster (fits in cache where the FM-index does not); the log(n/r) factor is a predecessor query — implement with a fast sparse rank/select.
  • The RLBWT run array is sequential (cache-friendly); SA-sample lookups are random.

23.8 Edge Cases

  • r = 1 (constant text → with sentinel r = 2); r ≈ n (incompressible — auto-select rejects r-index); a single long run vs many tiny runs; occurrences spanning many runs.

23.9 Failure Analysis

  • A toehold/sample bug returns wrong or missing positions only on the r-index path and only on repetitive inputs. Detection: r-index-vs-naive on the repetitive corpus (I15) + r-index-vs-FM parity where both are built. Recovery: force --index fm and diff; sufx inspect --runs dumps run boundaries and samples.

23.10 Operational Notes

  • space_breakdown reports r, r/n, and O(r) bits; document when the r-index wins (versioned/genomic corpora) vs the FM-index (general text). Bidirectional / approximate search over the r-index is PhaseDeferred("Deferred Features Register"). Build logs the selection decision and r/n (index_kind metric).

Threat Model

The trust boundary is the index file and the query pattern: an Index is built from trusted text offline, but load() may be handed a truncated, tampered, or hostile index file, and count/locate/extract may be handed adversarial patterns. The dominant risk class (ADR-01 rationale) is an out-of-bounds read while decoding a malformed succinct stream. Construction itself is offline and not network-facing.

Backup / Restore / Deployment

  • The index is a content-addressed immutable file (text hash + build params); "backup" = retain the file or the source text + params (deterministic rebuild, DP6).

  • New engine version must load the current index format version (Compatibility & Versioning); a format bump ships a converter or a documented rebuild.

Performance Engineering

Scalability Analysis

  • Construction ceiling: in-RAM SA-IS bounds n to what fits in O(n) ints + text + O(σ) buckets (~5n–9n bytes working set). The u32 width caps n at 2^32 − 1 ≈ 4.29 G (one Index); --wide (u64) doubles SA memory. External-memory construction (eSAIS/pSAscan) is PhaseDeferred("Deferred Features Register") — the scaling lever beyond RAM.
  • Query scaling: count is O(m·t_rank), independent of n beyond cache effects — scales to multi-GB indexes. locate scales with occ·s; a frequent pattern's cost is bounded by output size (DP13).
  • Space scaling: plain SA is Θ(n log n) bits — the limiting cost; the FM-index drops to n·H_k + o(n) (RRR, Phase 10) and the r-index to O(r) (Phase 11) on repetitive corpora (pan-genomes, versioned source) where r ≪ n — the key compressibility lever.
  • Concurrency: the index is immutable, Send + Sync, shared Arc<Index> (ADR-29, I18); query throughput scales linearly with cores on a shared read-only mmap — no locks, no coordination.
  • Sharding (out of core scope): a multi-document collection can be partitioned into per-shard indexes with a query fan-out + merge layer; generalized-SA document-listing is PhaseDeferred("Deferred Features Register"). Distributed query is a non-goal (§4).
  • Metadata scaling: C[] is O(σ); the alphabet remap is ≤ 256 entries (byte path); sample arrays scale as (n/s)·log n bits — s is the tuning knob.

Mental Models & First Principles

Eight compressed insights an expert holds. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — A suffix array is a permutation that turns substring search into a range search. Predicts: every occurrence of P sits in one contiguous SA interval, so count/locate are interval operations, never per-position scans. Bug without it: reimplementing substring search as a linear scan even after building the SA. Applied in §8.2, §19.
  • MM2 — Induced sorting is a fixed-point relaxation seeded from a sparse subset, not a comparison sort. Predicts O(n) construction from O(log n) recursion levels on a shrinking LMS-name alphabet. Bug without it: attempting a direct comparison-based reimplementation and landing back at O(n log n). Applied in §8.3, §14.
  • MM3 — The BWT is a lossless, reversible sort — a permutation of the text is still the whole text. Predicts invertibility via a single bijective LF walk from one anchor row. Bug without it: forgetting the primary index / sentinel anchor and producing a non-terminating or wrong reconstruction. Applied in §8.7, Phase 4 (§16).
  • MM4 — Rank is the universal succinct primitive; almost everything else (Occ, select, wavelet routing) reduces to popcount. Predicts that one well-built rank structure composes into every higher structure without re-deriving bit tricks. Bug without it: reimplementing Occ from scratch per structure, multiplying the surface for bit-order bugs. Applied in §8.11, §17, §18.
  • MM5 — Backward search is binary search generalized to a whole alphabet transition at once. Predicts the half-open-interval invariant and why it narrows monotonically. Bug without it: an off-by-one at the ep boundary that double-counts or drops the last occurrence. Applied in §8.8, §19.
  • MM6 — Space is a spectrum (dense → succinct o(n) → entropy H_0/H_k → repetition-aware O(r)); pick the point matching the corpus's redundancy structure. Predicts when RRR helps (skewed entropy) vs when it doesn't (near-random text) vs when the r-index dominates (few BWT runs). Bug without it: applying RRR to incompressible data or the r-index to non-repetitive data and getting no win, or worse, wasted overhead. Applied in §22, §23, Scalability Analysis.
  • MM7 — Every structure needs an independent second oracle; correctness is proven by agreement, not by elegant construction. Predicts that a beautiful, subtly wrong implementation still ships without a second, differently-derived check. Bug without it: trusting a single SA-IS or FM-index implementation that passes small unit tests but is wrong on adversarial or large inputs. Applied in DP1, DP12, Testing & Verification Strategy.
  • MM8 — The suffix tree is a virtual structure; SA + LCP + RMQ emulate it without paying its pointer overhead. Predicts that LRS/LCS/LCE all reduce to array range-queries, no explicit tree needed. Bug without it: building an actual ~20n-byte pointer-based suffix tree when the array trio suffices at a fraction of the memory. Applied in §8.5, Phase 3 (§15).

Back-of-Envelope Capacity Model

Twelve numbers, each derived step-by-step from §4's System Constraints, formula shown.

  1. Plain SA memory at n_max. SA_mem = 4n bytes (u32, §4). At n = 2^32−1 ≈ 4.29×10^9: 4 × 4.29e9 ≈ 17.18 GB.
  2. Text + BWT memory. text_mem = n bytes (byte alphabet, §4); BWT is the same size: 4.29 GB each.
  3. Raw wavelet/FM-index space (byte alphabet, before Occ overhead). WT_bits = n·⌈log2 σ⌉ = n·8 bits = n bytes ⇒ 4.29 GB.
  4. Rank/select overhead on the full wavelet tree. overhead_bits = 0.45 × (n·log2 σ) (§4: 0.25n rank + 0.20n select per bit-plane, ×log2 σ = 8 planes) = 0.45 × 4.29e9 × 8 bits ≈ 1.93 GB.
  5. RRR-compressed target at H_k ≈ 2 bits/symbol (a representative order-k entropy for natural-language/DNA-class text, §8.13). RRR_bytes = n·H_k / 8 = 4.29e9 × 2 / 8 ≈ 1.07 GB — versus item 3's 4.29 GB uncompressed.
  6. SA-sample array at rate s = 32. sample_bytes = (n/s)·⌈log2 n⌉ / 8 = (4.29e9/32) × 33 / 8 ≈ 5.53×10^8 bytes ≈ 553 MB.
  7. r-index space on a repetitive corpus (r/n = 0.01, a representative pan-genome/versioned-source ratio, §8.14). r = 0.01 × 4.29e9 = 4.29×10^7; r_bytes ≈ 2.2 × r × (log2 n + log2 σ) / 8 = 2.2 × 4.29e7 × 40 / 8 ≈ 4.72×10^8 bytes ≈ 472 MB — roughly 36× smaller than item 1's plain SA at the same n.
  8. locate() worst-case per-occurrence cost. steps_per_occ ≤ s · t_rank; wavelet path (t_rank = log2 σ = 8): ≤ 32 × 8 = 256 rank ops/occurrence; small-σ table path (t_rank = 1): ≤ 32 rank ops/occurrence.
  9. Build time for a 4.29 GB corpus. build_time = n / throughput = 4.29×10^9 / 3×10^6 ≈ 1430 s ≈ 23.8 minutes per core (§4, M2); SA-IS's sequential recursion levels limit cross-core parallelism to within-level bucket work.
  10. count() throughput ceiling. qps = 1 / latency = 1 / 2×10^-6 = 5×10^5 — ≥500,000 count queries/sec per core (§4, M1).
  11. Index load bandwidth implied by the 50 ms / 1 GB target (M3). implied_throughput = 1 GB / 0.05 s = 20 GB/s — achievable only because load is header-parse-plus-lazy-mmap, not a full read; cross-checked against typical NVMe/page-cache bandwidth, not a hard derivation.
  12. Minimum release-gate fuzz coverage (M10). 24 h × 6 targets = 144 target-hours per release cycle at minimum (sais, bwt_invert, index_load, backward_search, wavelet, rrr).

Alternative Architectures (Roads Not Taken)

AA1 — Pointer-based suffix tree (McCreight / Ukkonen)

        root
       / | \ \
      a  b  n $
     /|      |
    n a      a
    ...     (internal nodes carry suffix links;
             each edge is a (start,end) substring pointer
             into T, not a copied string)

Regime where it wins: interactive/online construction where new suffixes must be inserted one at a time with O(1) amortized work per character (Ukkonen), and where the ~20n-byte pointer overhead is acceptable because n is small (single genes, not whole genomes). Real embodying system: classic genome-alignment tools built directly on suffix trees (e.g. early REPuter/MUMmer1-generation tools before SA-based successors). Why rejected here: the ~20n-byte pointer/node overhead is 5-10× the plain SA's 4n–8n bytes at the n scales this blueprint targets (§4), and SA+LCP+RMQ (§8.5) already emulates every suffix-tree query this project needs at a fraction of the memory.

AA2 — Suffix automaton (CDAWG/SAM) as the primary index

  extend(c): last -> new state (len=len[last]+1)
  walk suffix links from last, redirect/clone as needed
  (state graph grows by <=2 states per symbol, online)

Regime where it wins: streaming/incremental corpora where the index must grow one symbol at a time without a full resort, and where the workload is dominated by LZ-factorization / dictionary-compression parsing (the suffix automaton and its compact form, the CDAWG, are the standard substrate for optimal LZ77 parsing). Real embodying system: online LZ-factorization research parsers built on suffix automata / CDAWGs. Why rejected here: this blueprint's corpus is static (build-once, DP3), so SA-IS's superior space (4n bytes vs the SAM's ≤2n-1 states each carrying a transition map) and the FM-index's compressibility make the sort-based path strictly better for the batch, queried-many-times workload this project targets; the SAM is retained only as a cross-check oracle (ADR-15).

AA3 — k-mer hash-table seed index (BLAST-style)

  hash_table[k-mer] -> list of text positions
  (fixed k, e.g. k=11; no full-text sort at all)

Regime where it wins: approximate / seed-and-extend search where exact full-text membership is not the primitive needed — only "does this k-mer appear, and roughly where" — trading exactness and worst-case guarantees for much cheaper construction and no global sort. Real embodying system: BLAST's k-mer seed-and-extend index. Why rejected here: this project's contract is exact substring count/locate/extract (§1), which a fixed-k hash table cannot answer for patterns shorter or longer than k, or with any position guarantee beyond the seed; approximate/seed-based search is explicitly out of scope and deferred (Deferred Features Register).

AA4 — External-memory / disk-backed construction (pSAscan-style)

  text (on disk, > RAM) -> disk-backed radix/induced-sort
  passes with bounded RAM buffers -> SA (on disk)

Regime where it wins: corpora that exceed available RAM (whole-genome pan-genome collections, web-scale text) where in-RAM SA-IS simply cannot run regardless of time budget. Real embodying system: pSAscan / eSAIS external-memory suffix-array construction algorithms (Kärkkäinen, Kempa, Puglisi and related work, referenced in B4). Why rejected here: Phase 0's engineering budget (§1, 6-12 weeks) targets the in-RAM regime that covers the stated n ≤ 2^32 ceiling (§4); external-memory construction is a materially larger engineering project (disk-aware buffer management, multi-pass merge) that is explicitly deferred (Deferred Features Register) rather than attempted as a half-measure.
