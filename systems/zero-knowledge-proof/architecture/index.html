Per-box summary: zkp-field/zkp-curve/zkp-pairing — the arithmetic kernel (§12 Phase 0); every other crate depends on it and never re-implements modular reduction or EC group law. zkp-poly — polynomial and FFT/NTT operations shared by QAP arithmetization and KZG. zkp-circuit/zkp-r1cs — the front-end: a computation becomes a constraint system, protocol-boundary between "what the circuit author writes" and "what the proof system consumes." zkp-sigma/zkp-transcript — the independent Sigma-protocol/Fiat–Shamir teaching track (Phases 1–3), sharing only the field kernel with the Groth16 track; illustrates interactive→non-interactive transformation before the heavier QAP/pairing machinery. zkp-qap — the arithmetization bridge (protocol boundary: R1CS satisfiability ⟺ polynomial divisibility). zkp-setup — the trust boundary: the only crate that ever touches the toxic-waste trapdoor (τ, α, β, γ, δ), destroyed on scope exit (I7, P3). zkp-kzg — an independently useful polynomial-commitment primitive, built for pedagogy alongside Groth16 (Groth16 itself does not call zkp-kzg — the arrow is a shared-lineage/teaching link, not a runtime dependency; see §8). zkp-groth16 — the SNARK: setup consumes the QAP + SRS; prove()/verify() are the concurrency boundary (each call is independent, no shared mutable state, §4). zkp-conformance — the correctness boundary: every other crate's output is differential-tested here against arkworks and bellman in-process (no subprocess/FFI boundary — all three are Rust, ADR-12).

8. Domain Model / Protocol / Data Model

Circuit DSL Grammar (EBNF)

circuit     ::= "circuit" ident "{" decl* constraint* "}" ;
decl        ::= visibility ident ("," ident)* ";" ;
visibility  ::= "public" | "witness" ;
constraint  ::= "constrain" expr "==" expr ";" ;
expr        ::= term (("+" | "-") term)* ;
term        ::= factor ("*" factor)* ;
factor      ::= ident | number | "(" expr ")" ;
ident       ::= letter (letter | digit | "_")* ;
number      ::= digit+ ;

Worked Example: x^3 + x + 5 = 35

The canonical pedagogical circuit (witness x=3, public out=35; witness vector indices [one, out, x, sym_1, y, sym_2] = [1, 35, 3, 9, 27, 30]):

Constraint A (nonzero terms) B (nonzero terms) C (nonzero terms)
1: x·x = sym_1 x=1 x=1 sym_1=1
2: sym_1·x = y sym_1=1 x=1 y=1
3: (y+x)·1 = sym_2 y=1, x=1 one=1 sym_2=1
4: (sym_2+5)·1 = out sym_2=1, one=5 one=1 out=1

R1CS satisfaction: (A·w) ⊙ (B·w) = (C·w) element-wise for the witness vector w above (I11). QAP identity (§17): interpolating each column of A, B, C as degree-3 polynomials over a size-4 evaluation domain with vanishing polynomial Z(x), satisfiability becomes A(x)·B(x) − C(x) = H(x)·Z(x) for some polynomial H(x) (I6) — this is the exact identity Groth16's pairing check (§19) verifies at a single random point, encoded in the exponent.

Fiat–Shamir Non-Interactive Transform

Prover(w) s.t. Y = g^w
  k <- random Zr
  R = g^k
  c = H(transcript || Y || R)      // I8: full-statement binding, P7
  s = k + c·w mod r
  proof = (R, s)         ──(R, s), Y──▶     Verifier
                                             c' = H(transcript || Y || R)
                                             accept iff g^s == R · Y^{c'}

Malformed-Input Example

A serialized G1Affine with the compressed-point flag bit set but coordinate bytes decoding to a value ≥ the base-field modulus, or an infinity flag combined with nonzero coordinate bytes: rejected by from_compressed() with PointError::NotOnCurve / PointError::ZeroInfinity before any subgroup check runs (I5, fixture malformed_point_overflow.bin, §21 N.5).

Failure-Path Example: Verifying-Key/Circuit Mismatch

An operator wires VerifyingKey for circuit "RangeCheck" to a verifier endpoint that actually receives proofs generated under the ProvingKey for circuit "Multiply," where both circuits happen to share the same public-input count. Without a circuit_hash binding (T11), the pairing equation may coincidentally still fail (PK/VK do not algebraically match) — but this is accidental, not structural, safety. The design fix: VerifyingKey.circuit_hash (§11) is checked at load time; the verifier refuses to initialize against a proof/VK pair whose hash doesn't match the operator-declared circuit, converting a silent-maybe-safe mismatch into a loud, structural one (§22 T11, §23 FC-9's sibling class).
