32. Back-of-Envelope Capacity Model

  1. Proof size (BLS12-381) = 2×|G1_compressed| + 1×|G2_compressed| = 2×48B + 96B = 192 bytes (M1) — chained directly from §4's field/curve sizes.
  2. Proof size (BN254) = 2×32B + 64B = 128 bytes (M2).
  3. MSM operation count, prove() ≈ 3–4 × m group scalar-mults, where m = constraint count (one term per nonzero A/B/C entry, roughly 3–4 group ops per constraint in the Groth16 A/B/C computation). At m = 2^20 (≈1,048,576): ≈ 3.1M–4.2M scalar-mults.
  4. prove() time at 2^20 constraints = MSM_ops / (cores × M8_throughput) ≈ 3.5×10^6 / (8 × 40,000) ≈ 10.9 s — under the M5 target (≤25s) with margin for FFT/serialization overhead not modeled here.
  5. FFT cost, domain 2^20 ≈ n log₂(n) field multiplications = 2^20 × 20 ≈ 21M field mults per forward/inverse pass — chained into M9's ≤400ms target at typical single-core field-mult throughput (~50–100M ops/sec for Montgomery multiplication).
  6. Proving-key size at 2^16 constraints ≈ (a_query + b_g1_query + h_query + l_query) × |G1| + b_g2_query × |G2| ≈ 4 × 2^16 × 48B + 2^16 × 96B ≈ 18.9 MB (schematic upper bound; §4's stated 9.4 MB reflects sparsity-adjusted query vector sizes in practice).
  7. Peak RSS at 2^20 constraints ≈ witness (32B × n) + 3 QAP polynomials (32B × n each) + MSM precompute table (window-factor × 32B × n) ≈ 32×2^20 + 3×32×2^20 + 16×32×2^20 ≈ 671 MB × 20/32-factor adjustment ≈ ~4–6 GB, matching M10's stated ceiling.
  8. Ceremony per-participant artifact size, 2^20 domain ≈ 2n×|G1| + n×|G2| ≈ 2×2^20×48B + 2^20×96B ≈ 201 MB per contribution — the dominant I/O cost behind M7's round-latency target.
  9. Verify cost (fixed, independent of n) = 3 Miller-loop pairings + 1 final exponentiation ≈ a small constant number of milliseconds on commodity hardware (typical software BLS12-381 pairing ≈ 1–2ms), chaining directly to M3's ≤5ms p50 target.
  10. Throughput ceiling, single 8-core prover ≈ (8 cores × 40,000 ops/sec) / (3.5×10^6 ops/proof) ≈ 0.09 proofs/sec at 2^20 constraints — i.e., ~1 proof every ~11s, matching derivation #4; horizontal scaling to k processes multiplies this linearly (§29).
