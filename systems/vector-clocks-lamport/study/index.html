Self-examination questions from the blueprint; each points at the section where the answer lives.

  7. Why must the parent-directory fsync occur after the file rename, and what specific production-incident class results from skipping it? (§18.2, §18.6, T6/FM-7)
  8. State the precise safety invariant that makes clock pruning sound, then construct a concrete scenario where a tombstone TTL shorter than the maximum message-in-flight delay violates it. (§7 I9, §20.6, T7/FM-9)
  9. Why does this project ship five clock families instead of standardizing on vector clocks alone, and under what actor-topology condition does each of the other four strictly dominate vector clocks? (§6 P1, §30)

  11. Why is Ord opt-in via TotalOrder<A> instead of implemented directly on LamportTs, and what silent failure mode does a direct Ord implementation invite? (§6 P9, §13.6)
  12. Compare DynamoDB's version-vector truncation policy with this project's DVV design — what anomaly does DynamoDB's truncation accept that DVVs avoid, and why is that an acceptable tradeoff specifically for Dynamo's deployment topology? (§5, §30, §20.6)
  13. Why can Lamport timestamps never detect concurrency, and what concrete architectural mistake results from building a CRDT directly on Lamport instead of a vector clock or DVV? (§6 P11, §21.6)
  14. Explain the difference between "the DVV causal context dominates" and "the DVV dot set is a superset," and construct an example where checking only one of the two conditions in descends produces an incorrect result. (§11.5, §15.6, §7 I8)
  15. Why does this project treat TrueTime-style bounded physical clocks as a permanent non-goal rather than a deferred feature, and what capability does a consumer lose by not having it? (§1, §30, §34)
  16. Trace the crash-mid-write failure path (§8.5) and state precisely which invariant guarantees no corruption occurs — and which guarantee is explicitly not made by the same mechanism. (§8.5, §7 I6, §18)

30. Mental Models & First Principles

  • MM1 — A clock is a compressed representation of a partial order, not a duration. Predicts: any two clock values can only answer "before / after / concurrent", never "how much later". Bug class without it: computing a "latency" from a Lamport-timestamp difference — meaningless, since ticks accrue on every local event, not on wall time. Applied in §8.1, §14.
  • MM2 — Concurrent is not conflicting. (P10, §6) Predicts an application can have concurrent writes to disjoint state that never need resolution. Bug class without it: over-eager conflict resolution that merges/rejects non-conflicting concurrent writes, silently losing data the application never needed to reconcile. Applied in §6, §21.
  • MM3 — "Missing = zero" is a chosen convention, not a law of nature; violate it once and every downstream comparison is wrong. Predicts sparse, asymmetric actor sets compare correctly if and only if every accessor goes through get() (I5). Bug class without it: comparing raw maps with == instead of the union-of-keys partial_cmp. Applied in §8.2, §14.6.
  • MM4 — Metadata size is the tax paid for exactness; approximate schemes trade exactness for boundedness. Predicts why Bloom-clocks and ITCs exist at all — vector clocks are exact but O(n); the alternatives compress at the cost of introducing false positives (Bloom) or requiring a tree structure (ITC). Bug class without it: assuming vector clocks scale to unbounded actor counts "because they're correct". Applied in §4, §29, §34.
  • MM5 — HLC is a bridge between logical and physical time, not a replacement for either. Predicts HLC gives you a total order comparable to wall-clock time but not concurrency detection — it is Lamport-with-a-physical-anchor, not a vector clock. Bug class without it: assuming an HLC comparison tells you whether two events were concurrent (it cannot; only vector/DVV/ITC can). Applied in §16, §6 P11 (by analogy).
  • MM6 — Durability is a property of the write path (fsync ordering), not the storage engine's marketing claim. Predicts that the choice of sled vs. RocksDB matters far less than whether the parent-directory fsync happens at all. Bug class without it: trusting "we use a database" as a durability argument without checking the fsync contract. Applied in §18, T6/FM-7.
  • MM7 — Pruning safety is a global invariant enforced by cheap local primitives (tombstone + epoch), never by omniscience. Predicts why GC here is opt-in with operator-supplied policy rather than an automatic language-runtime-style collector. Bug class without it: assuming clock GC "just works" like a GC'd language's heap — it cannot, because the safety invariant needs deployment-topology knowledge no local process has. Applied in §20, P4 (§6).
  • MM8 — A trait is a promise about behavioral consistency, not just a method signature; deriving concurrent_with from partial_cmp keeps that promise from drifting. Predicts any override of the derived method is a latent I3 violation waiting for a differential test to catch it. Bug class without it: two "obviously equivalent" implementations of concurrency-checking silently diverging over time as one is optimized and the other isn't. Applied in §11.1, §7.

Glossary (§36) · 44 terms · site-wide glossary

Happens-before (→)
the causal partial order generated by program order and send/receive (Lamport 1978 §2).
Concurrent (∥)
two events where neither happens-before the other.
Partial order
an order relation admitting incomparable pairs.
Total order
an order relation where every pair is comparable.
Lamport timestamp
a scalar logical clock giving a total order consistent with →.
Vector clock
a per-actor counter vector giving exact →/∥ detection (Fidge 1988, Mattern 1989).
Version vector
a vector clock applied to per-replica update tracking (Parker 1983).
Dotted Version Vector (DVV)
a version vector plus a dot set, fixing the client-server anomaly (Preguiça 2010/2012).
Dot
an (actor, counter) pair uniquely identifying one write event.
Causal context (cc)
the "observed as of this write" version vector inside a DVV.
Hybrid Logical Clock (HLC)
a (physical, logical) pair clock with bounded skew (Kulkarni et al. 2014).
Interval Tree Clock (ITC)
a fork/event/join clock for dynamic actor membership (Almeida, Baquero, Fonte 2008).
Actor
the identity unit that ticks a clock (an ActorId).
Fidge-Mattern theorem
V_a ≤ V_b entry-wise iff a → b.
Charron-Bost lower bound
any exact partial-order-detecting clock needs ≥n integers for n actors (Charron-Bost 1991).
Merge
combining two clock values (entry-wise max for VC/VV; union+compact for DVV; four-branch max for HLC; tree recombination for ITC).
Tick
advancing a clock to record a local event.
Monotonicity
a clock's per-actor value never decreases across events (I1).
Bounded skew
HLC's physical component never diverges from the local wall clock by more than max_offset (I10).
max_offset
the configurable HLC skew bound (ADR-21, default 500 ms).
Tombstone
a marker retained after pruning an actor's clock entry (§20.3).
Epoch
a per-clock counter incremented on every prune, used to reject stale clocks (§20.2).
Truncation
pruning to the k most-recent entries by counter value (Dynamo pattern, DeCandia 2007 section 6.3).
Client-server VV anomaly
a lost write under concurrent client writes through a plain version vector (Preguiça 2012 §2).
Anti-entropy
gossip-based state reconciliation requiring version vectors (Demers et al. 1987).
CRDT
Conflict-free Replicated Data Type.
LWW-register
Last-Writer-Wins register CRDT.
OR-Set
Observed-Remove Set CRDT.
RGA
Replicated Growable Array CRDT (ordered-sequence CRDT).
Snapshot isolation
an MVCC-based read-consistency model.
Exactly-once delivery
an idempotent message-processing guarantee.
Wire frame
the versioned binary envelope wrapping a serialized clock value (§11.8).
Varint
a variable-length integer encoding (LEB128).
fsync
the syscall forcing a durable write of data (and, separately, directory metadata) to disk.
Atomic write
the write-fsync-rename-fsync pattern guaranteeing no partially- written value is ever observable (I6).
Normal form (ITC)
the canonical, reduced tree representation an ITC value must be in before serialization (I11).
Bit-packed encoding
Almeida §7's compact binary ITC serialization.
Conformance suite
the paper-derived and production-differential test harness (conformance/, §10, §26).
Differential testing
cross-implementation behavioral comparison against a foreign reference implementation (§26, ADR-22).
Phi-accrual failure detector
a probabilistic liveness detector (Hayashibara et al. 2004), a layered stretch over the heartbeat-timeout primitive (ADR-19).
TrueTime
Spanner's bounded-error physical clock (Corbett et al. 2012), rejected as a permanent non-goal here (§1, §34).
NTP / PTP
Network Time Protocol (RFC 5905) / Precision Time Protocol (IEEE 1588-2019), the physical-clock synchronization sources HLC depends on.
Actor-death detection
the heartbeat-timeout mechanism marking an actor presumed dead for pruning purposes (§20.2).
Safety invariant (pruning)
the rule that no actor entry may be evicted while still reachable from a causally-prior event (I9).
