Consumer APIs box. Never touches a concrete clock type; drives everything through CausalClock (P2, §6). A CRDT does not know whether it runs over a vector clock or a DVV — this is the load-bearing decoupling boundary of the whole system.

Clock-type layer box. Five independent crates, one shared trait. Each crate owns its own partial_cmp implementation because the representation of the partial order differs (entry-wise max on a map vs. dot-set containment vs. tree dominance) even though the contract (§11.1) is identical.

Wire format box. A concurrency boundary as much as a serialization boundary: once a clock value leaves process memory it is a byte string with a version prefix (§19.1); nothing downstream may assume in-process representation.

Persistence box. The durability boundary. Everything above this line can be rebuilt from a crash by replaying from the last fsynced clock value; nothing below it (disk, kernel page cache, filesystem semantics) is this project's responsibility beyond documented assumptions (§4).

Pruning/GC box. A cross-cutting concern, not a layer: it operates on every clock type's on-disk and in-memory representation and is opt-in per deployment (P4, §6) because the safety invariant needs deployment-topology knowledge the library cannot infer.

All later sections stay consistent with this diagram; a component introduced in a later section must appear in one of these five boxes or be flagged non-goal (§1).

8. Domain Model

8.1 The causality model

The happens-before relation → (Lamport 1978 §2) is the strict partial order generated by: (a) program order within one actor; (b) send-before-receive across actors; (c) transitive closure. Two events a, b are concurrent (a ∥ b) iff neither a → b nor b → a. Every clock in this system is a finite representation of a prefix of this relation, with a scheme-specific comparison operator that must agree with →/∥ exactly (I2). The design space differs only in what is tracked: Lamport tracks a linearization consistent with → (loses ∥); vector/version clocks track exact →/∥ for a known, stable actor set; DVVs track it for a client-server topology where the writer and the replica have different identities; HLC adds an approximately-synchronized physical-time component; ITC tracks it for a dynamically changing actor set with no metadata growth.

8.2 Clock update-rule state tables

Lamport scalar (state = ts: u64):

Event Precondition Transition Postcondition
Local event none ts := ts + 1 ts strictly increases
Send none attach current ts to message unchanged
Receive (r) none ts := max(ts, r) + 1 ts > r and ts > prior ts

Vector clock (state = V: Actor ⇀ u64, missing = 0):

Event Precondition Transition Postcondition
Local event on a none V[a] := V[a] + 1 V[a] strictly increases
Send none attach V (full snapshot) unchanged
Receive (V_msg) on a none V := entrywise_max(V, V_msg); V[a] += 1 V ≥ V_msg entrywise, V[a] strictly increases

Version vector / DVV (state = cc: VV, dots: {Dot}):

Event Precondition Transition Postcondition
Client read none client receives cc (causal context) —
Server write, client context cc_r cc_r dominated by or equal to server cc new dot (server_id, cc[server_id]+1); dots += {dot} dot uniquely identifies this write
Merge two DVVs none cc := max(cc1, cc2); dots := (dots1 ∪ dots2) \ covered_by(cc) I8 holds post-merge
Compact dots non-empty drop any dot with counter ≤ cc[actor] dots minimal

Hybrid Logical Clock (state = (wall: u64, logical: u32)):

Event Precondition Transition Postcondition
Local event pt := now() if pt > wall: (wall,logical) := (pt,0); else logical += 1 I1, I10 hold
Receive (m) pt := now(); nw := max(pt, wall, m.wall) four-way branch on which of wall/m.wall/pt equals nw (§16.2) nw ≥ wall, nw ≥ m.wall, I10 holds

Interval Tree Clock (state = (id: IdTree, event: EventTree)):

Event Precondition Transition Postcondition
fork none split id into (id1, id2) sharing event both normal form (I11)
event none increment event at the leaf id owns normal form (I11)
join two ITCs to merge recombine id trees; event := entrywise_max on trees normal form (I11)

8.3 Worked example: three actors, one DVV anomaly, one resolution

Actors A, B (clients), S (server holding a key). Initial state: S.cc = {S:5}.

  1. A reads: receives context {S:5}.
  2. B reads: receives context {S:5} (concurrently with step 1).
  3. A writes back with context {S:5} → server mints dot (S,6); S.dots = {(S,6)}, S.cc = {S:6} is not yet merged — the dot is held separately until compaction.
  4. B writes back with context {S:5} (unaware of A's write) → server mints dot (S,7); S.dots = {(S,6),(S,7)}.
  5. A reader now receives both dots as sibling values — the DVV-Set (§15.4) surfaced both concurrent writes instead of the plain-VV outcome (§8.4 below) where (S,7) silently dominates and overwrites (S,6).
  6. Resolution: the consumer's LWW policy (§21.2) picks the higher dot counter, or an OR-Set-style consumer keeps both as siblings for a manual merge.

8.4 Malformed-input examples

  • Non-canonical DVV: a dots set containing (S,4) while cc = {S:6} — the dot is already covered by the causal context (I8 violated). DvvSet::compact must reject or silently drop this on ingest, logging dvv_non_canonical_input_total.
  • Corrupt wire frame: a frame with type = 0x09 (undefined clock-type tag, valid range is 0x01–0x06, §19.1) — Frame::decode returns Err(FrameError::UnknownType(0x09)), never silently defaulting to Lamport.
  • Truncated frame: length field declares 40 bytes but only 12 remain in the buffer — Frame::decode returns Err(FrameError::Truncated { expected: 40, got: 12 }); the frame-fuzz target (clocks-fuzz/fuzz_targets/frame_decode.rs) exercises this specifically and must never panic (M16, §28).
  • Un-normalized ITC on the wire: Id::Node(Leaf(0), Leaf(0)) arrives instead of the normal-form Leaf(0) — the decoder normalizes on ingest rather than trusting the wire representation, per I11.
  • Backwards-jumping physical clock (HLC): PhysicalClockSource::now_ns() returns a value 2 seconds behind the previous call (NTP step adjustment) — Hlc::tick detects pt < prior_observed_pt and returns Err(SkewError::ClockRegression) rather than silently using the stale value (I10).

8.5 Failure-path example: crash mid-write during a partition heal

Topology: replicas R1, R2 partitioned for 10 minutes, each accumulating local vector- clock ticks. Partition heals; R1 sends its accumulated clock to R2. R2 begins atomic_write of the merged clock (tmp-file write, §18.2) and the process is killed (SIGKILL) after the tmp-file fsync but before the rename. On restart: R2's persistence layer (§18.5) finds the tmp file, verifies its checksum, and — because the rename never completed — discards it and falls back to the last-fsynced prior value (the pre-merge clock). R2 correctly reports MonotonicityError is not triggered (no partial value was ever exposed, I6 holds) but the merge from R1 is lost and must be re-delivered — the anti-entropy layer (Demers et al. 1987, referenced §2) is responsible for retry, not this library. This is the documented contract: persistence guarantees no corruption, not no data loss on unacknowledged crash — delivery guarantees are the caller's layer, matching the Repository/consumer boundary in §1.

Design principles (§6)

  • P1 — Four families serve four purposes; ship all four (plus HLC and ITC). Lamport is for total-order extension on a small log. Vector clocks are for partial-order detection between processes with stable identities. Version vectors are for replicated- data conflict detection between server-side replicas. DVVs are for the same when writers are clients. HLCs add approximate physical time. ITCs handle dynamic membership. Tradeoff: five times the maintenance surface of one scheme. Operational implication: the Comparative Architecture Table (§30) is mandatory reading before picking one. Violating this (shipping only vector clocks "because it's simplest") reproduces the exact client-server VV anomaly Riak spent two years fixing (§15.2).
  • P2 — The CausalClock trait is the integration contract. Every scheme implements tick, merge, partial_cmp (§11.1), serialize/deserialize. concurrent_with is a derived default method, never independently implemented. Tradeoff: trait-object dispatch has a small vtable cost vs. monomorphized generics (mitigated: consumers are generic over C: CausalClock, ADR-13). Violating this by hand-rolling concurrent_with risks it drifting from partial_cmp — caught by I3 (§7).
  • P3 — Vector-clock size is O(n_actors); the library refuses silent unboundedness. Charron-Bost 1991 is tight on the worst case. Tradeoff: every vector-clock deployment must pair with a pruning policy (§20) or accept the 400 KB/clock ceiling documented in §4. Violating this ships the two-year-unpruned-deployment failure mode (FM-6, §23).
  • P4 — Pruning is mandatory in production; the library supplies primitives, the operator supplies policy. The safety invariant I9 (§7) requires deployment-topology knowledge the library cannot infer. Tradeoff: no "just works" default GC; every deployment must configure a tombstone TTL or truncation threshold explicitly. Operational implication: docs/runbook/pruning-incident.md (§10) is required reading for any operator running this in production. Violating I9 causes silent lost updates.
  • P5 — HLC requires a documented clock-skew bound and physical-clock source. Kulkarni 2014's monotonicity guarantee assumes bounded skew between nodes. Tradeoff: the Hlc constructor refuses to produce a value when the local clock is observed jumping backwards beyond max_offset (ADR-21). Violating this breaks the bounded-divergence guarantee silently (FM-4, §23).
  • P6 — Serialization format is part of the API contract, versioned from day one. A clock persisted by version 0.3.0 must be readable by 0.4.0. Tradeoff: a 1-byte version prefix on every frame (§19.1) costs bytes on the wire in exchange for zero flag-day migrations. Violating this (skipping the version byte "to save space") forces a coordinated fleet-wide upgrade instead of a rolling one — a Compatibility & Versioning (§25) failure.
  • P7 — Persistence is atomic at the clock-value granularity. A partial write must never be observable on recovery (I6, §7). Tradeoff: every write pays an fsync (data) + fsync (parent directory) cost (M13, §4) instead of a buffered write. Violating this on Linux specifically (skipping the parent-dir fsync) loses the rename on power-failure even though the data itself was fsynced — the single most common storage-engine bug in this domain (FM-7, §23).
  • P8 — Comparison operators are total-order-compatible with partial-order semantics. partial_cmp returns Some(Less/Equal/Greater) or None (concurrent); None is never conflated with Some(Equal). Tradeoff: callers cannot use Ord/< directly on a raw clock — they must handle None explicitly or opt into TotalOrder<A> (P9). Violating this is I3's core failure mode.
  • P9 — Ord is opt-in via a separate TotalOrder<A> wrapper. Lamport's (ts, actor) tie-break is exposed only through TotalOrder<LamportTs>; LamportTs itself implements only PartialOrd. Tradeoff: one extra type for callers who want a total order. Violating this (implementing Ord directly on LamportTs) silently hides the fact that concurrent-looking events got an arbitrary tie-break.
  • P10 — Concurrent is a clock property; conflicting is an application decision. Two writes whose clocks are concurrent are eligible to conflict; whether they do is the consumer's resolution policy (LWW / OR-Set union / manual surfacing). Tradeoff: the library never resolves conflicts itself, so every consumer must supply a policy (§21). Violating this by baking in a default resolution (e.g. "last write by wall-clock wins") silently drops correct concurrent updates for consumers that needed a different policy.
  • P11 — Lamport timestamps cannot detect concurrency, by design, not by omission. Callers that need concurrency detection are pointed to vector clocks or DVVs; the API surface does not expose a concurrent_with on LamportTs at all. Tradeoff: a caller who only needs total order pays no vector-sized metadata cost. Violating this (bolting concurrent_with onto Lamport by comparing raw scalars) produces false concurrency answers — two causally-related events can share a scalar timestamp.
  • P12 — Actor identity is a bounded type parameter, Uuid by default. ActorId: Copy + Ord + Hash + Serialize + Deserialize. Tradeoff: generic code is slightly harder to read than a hard-coded Uuid everywhere, in exchange for u8 in tests (compact output) and u64 in benchmarks (tight memory) without duplicating implementations. Violating this (hard-coding Uuid) blocks the embedded/WASM use case in §1.
  • P13 — No unsafe anywhere in the workspace. ITC bit-packing (§17.4) is pure safe Rust. Tradeoff: some hand-rollable bit tricks are left on the table; revisited only if a profiler shows a documented >20% win on a hot path unreachable safely (none found to date). Violating this reintroduces the memory-safety risk class Rust was chosen to eliminate (§1 language rationale).
  • P14 — Conformance is the contract, not a nice-to-have. Every partial-order axiom (reflexivity, antisymmetry, transitivity), merge commutativity/associativity/ idempotency, HLC bounded-skew tolerance, and ITC normal form is a property test; three differentials (Riak, CockroachDB, Almeida's ITC C reference) run in CI. Tradeoff: CI wall-clock time (M14, §28) grows with the corpus. Violating this (merging a scheme without its differential) is exactly the failure class that let the Riak VV anomaly ship for years (§2).
