Concurrency: one agent-loop instance per task; the sandbox pool and model-client connection pool are shared, bounded resources (section 26 topology, section 31 sandbox-slot limit). Persistence: trajectories and the cost ledger are append-only and durable across process restarts; the repository index is durable and incrementally rebuilt. Protocol boundaries: CLI/service to core is an in-process call or a queue message (section 26); core to provider is the ModelClient protocol (section 11); core to sandbox is the OCI runtime interface (section 17); core to Git remote is the provider's REST/GraphQL API.

Per-box description: the task spec parser turns a free-text or structured task description into a validated TaskSpec (section 11), the first and only point where a raw instruction enters the system. The repository indexer builds and incrementally maintains the lexical, structural (tree-sitter), and optional embedding index (section 14) without model involvement — purely mechanical. The context retriever & budgeter is where the untrusted boundary begins in earnest: it selects repository chunks and enforces the token- budget arithmetic of section 8 before anything reaches a prompt. The prompt assembler concatenates system prompt, task, retrieved context and (compacted) history, tagging each segment's trust level for the model and for downstream logging. The model client is the sole point of contact with the external provider, behind a versioned interface (ADR-02) that also implements the recorded-response replay transport used by every deterministic test. The response parser & tool-call validator rejects any output that does not parse to a valid, schema-conformant tool call (I3) before it can reach an effectful path. The tool registry exposes read, edit, search, shell and test tools, each with a declared effect class (section 8). The sandbox executor is the only place untrusted code or untrusted commands run (I1); it enforces filesystem, network and resource isolation (section 17). The patch applier enforces the stale-precondition check (I2) before writing any edit to disk. The verification runner invokes the repository's own tests/lints/build inside the sandbox and is the sole source of truth for task success (P1). The trajectory recorder durably logs every turn for replay and evaluation (I7). The cost/token accountant maintains an atomic ledger (I10) consulted by the budgeter before every request. The patch emitter/PR creator turns a verified PatchSet into a reviewable diff or pull request (section 21). The eval harness drives the entire stack, unmodified, over a benchmark task set (section 23).

8. Domain Model

8.1 Agent-Loop State-Transition Table

From Event To Notes
Planning Model produces a parseable next action Retrieving or Acting Planning may itself request more context
Planning Model response has no parseable action Reflecting Counts against retry budget (I5)
Planning Malformed/unschematized response repeated past retry budget Failed Terminal
Retrieving Context assembled within budget Acting Budgeter check per I4/I13
Retrieving Budget cannot be satisfied even after compaction Aborted Terminal; P6/I4
Acting Tool call validates and dispatches Observing I3 gate passed
Acting Tool call fails schema validation Reflecting Returned as tool_result error, not silently dropped
Acting Turn ceiling reached mid-action Aborted Terminal; I5
Observing Tool result received normally Planning Loop continues
Observing Tool reports nonzero exit / exception Reflecting Tool-error failure edge
Observing Sandbox command exceeds per-command timeout Reflecting (first N) / Aborted (repeated) Sandbox-timeout failure edge
Observing Model signals task believed complete Verifying Never Done directly (P11)
Verifying Tests/lints/build pass Done Terminal; P1
Verifying Tests/lints/build fail Reflecting Verification-failure edge
Verifying Verification harness itself hangs/times out Aborted Terminal; treated as infra failure, not task failure
Reflecting Retry budget available Planning Reflexion-style feedback appended (Shinn et al. 2023)
Reflecting Retry budget exhausted Failed Terminal
Any Wall-clock ceiling reached Aborted Terminal; checked on every transition (I5)
Any Cost ceiling (hard) reached Aborted Terminal; T7 guard

Done, Failed, Aborted are terminal; only Done results in patch/PR emission (section 21).

8.2 Tool-Call Contract

Tool Schema (key fields) Effect Class Idempotent Timeout Failure Mode
read_file path, line_range? read-only yes 5s path outside root → schema/precondition error
search query, mode (lexical|structural|embedding), max_results read-only yes 5s empty index → degrade to lexical only
edit path, anchor (EditOp), content_hash mutating no 5s stale precondition (I2), ambiguous anchor
shell command, cwd, timeout_sec executing no ≤120s nonzero exit, timeout, sandbox spawn failure
test command? (else auto-discovered) executing no (side effects possible) ≤600s hang → sandbox-timeout edge; flaky → ADR-17 quorum

8.3 Context-Budget Arithmetic

system_prompt + task_spec + retrieved_context + history + reserved_output ≤ context_window

Worked allocation (window = 200,000): system_prompt = 3,000; task_spec = 1,000; reserved_output = 8,000; history (compacted, cap) = 20,000; remaining for retrieved_context = 200,000 − 3,000 − 1,000 − 8,000 − 20,000 = 168,000 theoretical, policy-capped at 100,000 (section 4 per-turn input cap headroom) leaving 68,000 as safety margin for tool-result growth within a turn without re-running the budgeter mid-turn. Eviction/summarization policy: when history exceeds its 20,000-token cap, the oldest turns are collapsed into a single summary record ("earlier in this session, X was tried and failed because Y") preserving the most recent 4–8 turns verbatim and all open (unresolved) tool-call threads uncompacted.

8.4 Structured-Edit Representation Comparison

Representation Match Semantics Stale-Precondition Support Failure Mode Verdict
Whole-file rewrite Full replacement Trivial (hash whole file) Expensive; large diffs obscure intent Fallback for small/generated files (ADR-05)
Unified diff Line-number + context hunks Weak (hunk offsets drift) Model hallucinates line numbers; silent misapply Rejected as primary
Search-and-replace block Unique-anchor exact match Strong (hash the anchored region) Ambiguous/absent anchor → explicit error Locked primary (ADR-05)
AST-level edit Structural node match via tree-sitter Strong (structural equality) Requires a grammar per language; brittle on syntax errors Used for high-confidence template repairs (Getafix-style, section 18)

8.5 Retrieval Strategy Decision Table

Strategy Signal Cost Precision When Used
Lexical Token/substring match (ripgrep/BM25-style) Low High for exact identifiers Default first pass, every query
Structural tree-sitter symbol table Low–medium High for "definition of X" Symbol-shaped queries
Embedding Vector similarity Medium–high High for natural-language intent Fallback when lexical/structural yield low-confidence results

8.6 Verification-Loop Protocol (Sequence)

  1. Discover verification command (convention-based, ADR-16; manual override honored).
  2. Dispatch inside sandbox with the 600s test-suite budget (section 4).
  3. Capture stdout/stderr/exit code; classify: pass / fail / timeout / flaky-suspect.
  4. If flaky-suspect (result differs from a prior run on unchanged code), apply ADR-17 quorum (run 3×, majority rules).
  5. Emit VerificationRun record; transition per section 8.1.

8.7 Trajectory Record Schema (fields)

task_id, turn_index, state_from, state_to, model_request_ref, model_response_ref, tool_calls[], tool_results[], token_usage{input,output}, cost_delta, wall_clock_ms, trust_tags{}, timestamp. One record per turn, append-only (ADR-21).

8.8 Cost-Accounting Model

turn_cost = input_tokens × input_price + output_tokens × output_price; task_cost = Σ turn_cost over all turns; ledger entries are written atomically per turn (I10) and checked against the soft/hard ceilings (section 4) before the next request is issued (P6/P13).

8.9 Worked End-to-End Example (Four Turns)

Prices: $3 / 1M input tokens, $15 / 1M output tokens (representative frontier pricing).

Turn Action Input tok Output tok Turn cost
1 Retrieve + plan 15,000 800 $0.045 + $0.012 = $0.057
2 read_file result folded in, propose edit 22,000 600 $0.066 + $0.009 = $0.075
3 Test run result folded in, propose second edit 30,000 1,200 $0.090 + $0.018 = $0.108
4 Verification passes, summarize 34,000 400 $0.102 + $0.006 = $0.108

Task total: $0.348, well under the $2.00 soft ceiling (section 4) — an example of an easy task; section 34 shows the fleet-average 8-turn task at ≈$1.14.

8.10 Malformed-Input Examples

Example Handling
Tool call with an invalid schema (missing required field) I3 rejects pre-dispatch; returned as tool_result error; counts against turn
Edit whose anchor is absent from the current file EditPrecondition failure; explicit "anchor not found" error, no partial write (I12)
Edit whose anchor matches twice (ambiguous) Rejected with disambiguation hint (surrounding-line count) per file
Model response with no parseable action at all Planning → Reflecting failure edge (section 8.1)
Shell test command that hangs Sandbox per-command timeout fires; Observing → Reflecting (or Aborted if repeated)
Repository file containing an injected instruction (e.g., a README with "ignore previous instructions") Trust-tagged as untrusted at retrieval; system prompt instruction hierarchy (ADR-24) prevents it overriding task instructions; logged as an injection-detection hit (section 26 metric)

8.11 Failure-Path Example

Task: fix a failing test. Turn 1–3 proceed normally into Verifying. Verification fails (test still red). Reflecting: Reflexion-style feedback appended, retry budget available, back to Planning. Turns 4–7 repeat the loop with progressively refined edits. At turn 8 the model proposes an edit whose anchor is now stale (another tool call altered the file); I2 rejects it, Reflecting again. At turn 12, retry budget for this failure signature is exhausted → Failed, trajectory retained for post-mortem (section 25, FM-class review).
