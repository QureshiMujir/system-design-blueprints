⬜ Phase 0 — Repository, Governance, and Shared Primitives §12

Objectives
  • Establish workspace structure, CI, and toolchain; no format logic yet.
  • Implement shared:: crate: Thrift compact reader/writer, bit reader/writer, varint, CRC-32C.
  • Wire up GitHub Actions (fmt, clippy, test, Miri, coverage).
  • Establish fuzz harness infrastructure (cargo-fuzz + AFL).
Deliverable
  • All 6 crates compile (empty public APIs for non-shared crates).
  • shared:: has 100% unit test coverage of bit-reader/writer round-trips and varint encode/decode.
  • CI green on stable + MSRV.
  • cargo fuzz run fuzz_thrift_compact runs without panic on 10k random inputs.
Acceptance
  • cargo test -p shared passes; zero clippy warnings.
  • bit_writer → bit_reader roundtrip for bit widths 1–64: all pass.
  • Varint roundtrip for u64::MIN, u64::MAX, 0x7F, 0x80, i64::MIN, i64::MAX (zigzag): all pass.
  • CRC-32C of known vector [0x00; 32] matches RFC 3720 known answer.
  • Miri clean on shared::bit_reader + shared::thrift_compact.
Fixtures
  • conformance/fixtures/thrift_varint_vectors.json — known varint byte sequences + decoded values.
  • conformance/fixtures/bit_pack_vectors.bin — bit-packed sequences with known bit widths + expected u64 streams.
Pitfalls
  • Zigzag signed overflow: (v << 1) ^ (v >> 63) for i64::MIN must not overflow; use i64::wrapping_shl.
  • Bit reader LSB vs MSB confusion: Parquet bit-packing is LSB-first; Thrift is MSB-first for type headers; keep separate code paths, clearly labeled.
  • Thrift stop byte: field type 0x00 = STOP; must not be confused with field delta 0 (field IDs are delta-encoded); delta 0 = next field uses full 2-byte encoding.
  • CRC endianness: DataPageV2 stores CRC as int32 (Thrift i32 = big-endian zigzag); compute must match exact Parquet spec interpretation.

⬜ Phase 1 — Flat Schema, PLAIN Encoding, Uncompressed Reader/Writer §13

Objectives
  • Implement Parquet magic verification, footer parse, and FileMetaData reconstruction for flat (non-nested) schemas.
  • Implement PLAIN encoding/decoding for all physical types.
  • Implement uncompressed ColumnChunkReader + ColumnChunkWriter for flat schemas (no R/D levels, all-required fields).
  • End-to-end roundtrip: write a flat INT64 column, read it back, verify values.
Deliverable
  • write_flat_int64.rs example compiles and runs: creates test.parquet, reads it back, asserts values match.
  • pqtool schema test.parquet prints the schema tree with physical types.
  • pqtool stats test.parquet prints row count and column count.
Acceptance
  • Roundtrip: 1M INT64 values written + read back: all equal; zero errors.
  • PLAIN decode throughput ≥ 2 GB/s on 8-byte-aligned INT64 (criterion benchmark decode_plain).
  • parquet-mr CLI can read the generated file without error (conformance gate).
  • Footer parse latency for file with 1 row group, 10 columns ≤ 500 µs.
  • cargo test -p parquet_core -p parquet_encoding -p parquet_codec all pass.
Fixtures
  • flat_plain_uncompressed.parquet — generated by parquet-mr; read with our reader; assert values match reference JSON.
  • flat_int64_our_output.parquet — written by our writer; read by parquet-mr; assert no errors + value match.
Pitfalls
  • Schema element DFS vs BFS: SchemaElement list is pre-order DFS; num_children is NOT recursive count but direct children count; getting this wrong produces wrong schema tree.
  • Footer byte order: footer_len is 4-byte little-endian int32 (not uint32); negative value = corrupt file; check > 0 before use.
  • BOOLEAN PLAIN: values are LSB-packed into bytes (8 values/byte); num_values may not be multiple of 8; last byte has partial bits; do NOT read past ceil(num_values/8) bytes.
  • BYTE_ARRAY length: 4-byte LE int (NOT varint); length prefix in the value stream itself, NOT in a page header field.
  • INT96: 12 bytes little-endian; no general arithmetic needed in P1; just copy raw bytes; preserve semantics deferred to P6.

⬜ Phase 2 — Hybrid RLE/BIT_PACKED and Dictionary Encoding §14

Objectives
  • Implement hybrid RLE/BIT_PACKED encoder/decoder (used for R/D levels and dictionary indices).
  • Implement dictionary page + RLE_DICTIONARY encoding with cardinality-threshold fallback.
  • Wire dict encoding into ColumnChunkWriter; wire dict decode into ColumnChunkReader.
  • Implement encoding_selector heuristic: pick PLAIN vs RLE_DICTIONARY vs PLAIN.
Deliverable
  • Round-trip test: write 1M STRING values with 500 distinct strings; read back; all equal.
  • pqtool dump file.parquet shows correct string values (dict-decoded).
  • Dict encoding reduces file size vs PLAIN by ≥ 50% for 500-distinct/1M-values dataset.
Acceptance
  • RLE_DICTIONARY encode/decode roundtrip: 10M u32 indices (bit widths 1–32): all pass.
  • Dict lookup never out-of-range (invariant I8); property test with proptest.
  • Fallback: write 1M values exceeding MAX_DICT_SIZE; verify PLAIN fallback pages; parquet-mr reads without error.
  • decode_dict criterion benchmark ≥ 400 MB/s (indices + lookup combined).
  • cargo fuzz run fuzz_rle_bp runs 100k iterations without panic.
Fixtures
  • flat_dict_snappy.parquet — parquet-mr generated; read with our decoder; values match.
  • dict_fallback.parquet — our writer; dict fills and overflows mid-chunk; parquet-mr reads.
  • rle_bp_known_vectors.bin — hand-crafted RLE + BIT_PACKED blocks; decode + assert known output.
Pitfalls
  • Dict page encoding tag: RLE_DICTIONARY data page uses Encoding::RleDictionary (8) for data pages, but the dict page itself uses Encoding::PlainDictionary (2) (legacy tag kept for compatibility); don't use Plain (0) for dict page.
  • Bit width byte for RLE_DICTIONARY data page: the first byte of the data (after page header compressed bytes) is the bit_width byte, then the RLE/BIT_PACKED stream; forgetting this byte shifts all index reads by 1.
  • Empty runs: an RLE block with count=0 is valid (skip it); don't infinite-loop on count=0 input.
  • BIT_PACKED block padding: blocks are always 8 values even if fewer remain; last block may be padded with 0; decoder must use count to stop at correct value, not byte count.
  • HashMap non-determinism: dict index assignment depends on insertion order; HashMap random order under randomized hashing; use IndexMap or sort-then-assign for reproducible dict pages.

⬜ Phase 3 — Nested/Repeated Schema and Dremel R/D Shredding + Assembly §15

Objectives
  • Extend schema builder to support Optional and Repeated field types; compute max_rep / max_def per column.
  • Implement Dremel record shredding: values: Iterator<Item=NestedRecord> → per-column (R[], D[], values[]) streams.
  • Implement Dremel assembly FSM: per-column (R[], D[], values[]) → Iterator<Item=NestedRecord>.
  • Write + read nested schemas: LIST<STRING>, MAP<STRING,INT32>, STRUCT(a: INT64, b: optional STRING).
Deliverable
  • write_nested_list.rs example: write LIST<STRING> column with null lists, empty lists, multi-item lists; read back; values match.
  • pqtool schema nested.parquet prints nested schema with max_rep/max_def per column.
Acceptance
  • Dremel roundtrip property test: for any randomly generated nested record (depth ≤ 5, up to 3 repetitions), assemble(shred(records)) == records; 10k iterations.
  • Conformance: nested_list_map.parquet (parquet-mr generated) read by our reader; all values match.
  • Our written nested file read by parquet-mr without error.
  • Level OOB invariant (I9) tested: fuzz-generated levels outside max_rep/max_def → Error::InvalidLevel; no panic.
Fixtures
  • nested_list_map.parquet — parquet-mr generated; canonical LIST+MAP structure.
  • dremel_worked_example.parquet — hand-crafted file matching §8.5 worked example; byte-verified.
  • deeply_nested.parquet — 6-level nesting depth; max_def=6; edge case for assembly stack depth.
Pitfalls
  • DataPageV1 level boundary: rep and def level byte-lengths are NOT stored in V1 header; reader must parse RLE/BIT_PACKED stream and stop at num_values elements (not bytes); values begin at next byte boundary after def levels. Use DataPageV2 for new writes (stores explicit byte lengths).
  • NULL vs ABSENT for optional fields: Parquet does not distinguish between a JSON null value and an absent field — both map to D < max_def; assembly must not re-introduce the distinction.
  • LIST three-level vs two-level legacy: some files use legacy 2-level LIST encoding (repeated field directly, no wrapper group); detect by presence of ConvertedType::LIST on the outer group without a nested repeated group; handle both.
  • Assembly FSM partial state across pages: AssemblyFSM must be stateful across page boundaries within a column chunk; records can span page boundaries (a record's values can be split across pages).

⬜ Phase 4 — Compression Integration (Per-Page Codecs) §16

Objectives
  • Integrate the Codec trait from #397 compression project; implement codec_bridge.rs.
  • Wire per-page compression into ColumnChunkWriter and decompression into ColumnChunkReader.
  • Support SNAPPY, GZIP, ZSTD, LZ4_RAW; BROTLI optional (feature flag).
  • Enforce MAX_UNCOMPRESSED_PAGE_BYTES decompression bomb guard.
  • Benchmark: ZSTD L1 + RLE_DICTIONARY decode throughput ≥ 400 MB/s.
Deliverable
  • all_types_zstd.parquet example: write all physical types with ZSTD; read back; values match.
  • pqtool stats file.parquet shows per-column codec and compression ratio.
Acceptance
  • Roundtrip: SNAPPY + GZIP + ZSTD + LZ4_RAW, all physical types: all pass.
  • Decompression bomb guard: attempt to decompress page claiming uncompressed_size = 2 GB → Error::DecompressionBomb before any allocation.
  • DataPageV2 CRC: corrupt 1 byte in compressed payload → Error::Corruption; no partial decode.
  • decode_dict + ZSTD L1 combined: ≥ 400 MB/s on INT64 column (criterion benchmark).
  • cargo fuzz run fuzz_page_header runs 100k iterations without panic.
Fixtures
  • flat_plain_snappy.parquet, flat_plain_gzip.parquet, flat_plain_zstd.parquet, flat_plain_lz4raw.parquet — parquet-mr generated, one codec each.
  • crc_mismatch.parquet — synthetic; 1-byte corruption in DataPageV2 compressed payload.
  • bomb_claimed_size.parquet — synthetic; uncompressed_size header = 0x7FFFFFFF.
Pitfalls
  • GZIP framing vs deflate raw: CompressionCodec::Gzip in Parquet means RFC 1952 gzip (with header/trailer); not raw deflate; ensure flate2::GzEncoder is used, not DeflateEncoder.
  • LZ4_RAW vs LZ4_FRAME: Parquet uses LZ4_RAW (raw LZ4 block, no frame magic); using framed LZ4 adds 7+ bytes of header → "invalid magic" on read by parquet-mr.
  • Uncompressed page size in V2 header: includes uncompressed levels bytes (not just values); common bug: using only value uncompressed size → wrong uncompressed_page_size → decompression fails or returns wrong data.
  • Zstd decompression without declared size: if uncompressed_size from header is 0 or wrong, Zstd can still decompress (streaming) but Parquet requires pre-declaration; enforce consistency.

⬜ Phase 6 — Column Statistics and Row-Group Predicate Pushdown §18

Objectives
  • Implement per-column statistics accumulation in ColumnChunkWriter (min, max, null_count, distinct_count estimate).
  • Implement row-group predicate pushdown in ParquetReader/RowGroupReader: skip row groups where stats prove no match.
  • Expose PredicatePushdown API; evaluate against ColumnStatistics.
  • Verify: 95%+ I/O savings on 1% selectivity scan.
Deliverable
  • predicate_pushdown.rs example: 100 row groups; query col > 500; all but ~1 row group skipped; verify skipped count.
  • pqtool stats --predicate "col > 500" prints which row groups would be skipped.
Acceptance
  • Predicate skip ratio: dataset with 100 row groups, uniform distribution, 1% selectivity filter → ≥ 95 row groups skipped (no I/O).
  • IsNull pushdown: column with no nulls → null_count=0 in stats → IsNull predicate skips row group.
  • NaN values: column with NaN floats → statistics absent → predicate never skips that column's row group.
  • bloom_filter.parquet (parquet-mr generated): our reader parses statistics; skip evaluation matches parquet-mr behavior.
  • Statistics invariant (I6): property test — min ≤ v ≤ max for all non-null values in 10k random datasets.
Fixtures
  • stats_sorted_int64.parquet — sorted INT64 column; tight min/max; skip ratio = 99% for point queries.
  • stats_null_heavy.parquet — 50% null column; null_count accurate; IsNull/IsNotNull pushdown verified.
  • stats_float_nan.parquet — column with NaN values; statistics must be absent for that column.
Pitfalls
  • Statistics byte encoding endianness: min_value for INT32 is 4-byte LE (not NBO); getting this wrong makes min/max comparisons wrong → incorrect predicate skip → data loss. Cross-check with parquet-mr byte output.
  • BYTE_ARRAY min/max comparison: raw byte lexicographic order; NULL bytes sort before printable ASCII; important for STRING columns.
  • Truncated statistics: for long strings, some writers truncate max_value to a prefix (safe: widening); readers must handle max_value ≥ true max, min_value ≤ true min as acceptable.
  • All-null column statistics: null_count = num_values; min_value/max_value absent; predicates against all-null column: IsNull = MustMatch; any value comparison = MustSkip.
  • Statistics without is_min_value_exact field (old files): assume exact when field absent (Parquet spec default).

Pitfalls
  • Bloom filter spec version: Parquet uses a custom split-block Bloom (not standard Bloom or Xor filter); must use the Parquet-specified salt[] constants and block structure; different from bloom crate.
  • ColumnIndex byte encoding: min/max per page use same encoding as footer statistics (physical-type dependent); same endian rules apply.
  • null_pages flag: if null_pages[i] = true, page i is entirely null; min/max undefined; predicate for any non-null value must skip this page (MustSkip for value predicates).
  • OffsetIndex first_row_index: cumulative (not per-page delta); row 0 of the row group = 0; must track running count during write.

Fixtures

  • delta_byte_array_strings.parquet — parquet-mr generated sorted strings.

  • orc_all_types.orc — Apache ORC reference with all types.
  • orc_null_heavy.orc — PRESENT stream exercise; 70% nulls.
Pitfalls
  • ORC compression chunks vs Parquet page compression: ORC compresses per-stream in fixed-size chunks (default 256 KB); each chunk has a 3-byte header (1 bit = original/compressed, 23 bits = length); NOT per-row-group.
  • RLEv2 DIRECT bit_width encoding: stored as (bit_width - 1) in 5 bits using the ORC encoding table (not raw bit width); table: 0=1, 1=2, ..., 23=24, 24=26, 25=28, ...; must use exact table.
  • ORC type system vs Parquet: ORC types are in a flat list with parent_index links (not a tree); LIST is type list with child subtype; MAP has key + value subtypes; unlike Parquet's schema element DFS.
  • Stripe footer before file footer: each stripe has its own stripe footer immediately after the stripe data; the file footer is at the end; don't confuse the two.

⬜ Phase 10 — Vectorized Reader + Projection Pushdown + I/O Coalescing §22

Objectives
  • Implement batch-oriented ColumnChunkReader::read_batch(n) returning DecodedColumn<T> of up to n rows; amortize decode overhead over batches (default batch size 4096 rows).
  • Implement projection pushdown: ParquetReader::open_with_projection(schema_columns: &[&str]) — only read + decode the projected columns; skip all other column chunks.
  • Implement I/O coalescing: given a list of (offset, length) byte ranges required for projected columns in a row group, merge adjacent ranges (within a configurable gap threshold = 1 MB) into single reads.
  • Implement multi-row-group parallel scan interface: ParquetReader::scan_parallel(pred, proj) -> impl Iterator using caller-provided rayon::ThreadPool.
Deliverable
  • 100-column file; project 2 columns; measure I/O bytes read ≤ 3% of total file (2 columns / 100 = 2%, plus footer and coalesced overhead).
  • Vectorized decode throughput: INT64 column, 1 row group, 10M rows, batch_size=4096 → ≥ 2 GB/s.
  • pqtool dump --columns col1,col2 only reads 2 column chunks.
Acceptance
  • Projection: reading 2/100 columns reads ≤ 5% of file bytes (measured via CoalescingReader byte counter).
  • Batch decode: 10M INT64 rows in batches of 4096: total decode ≥ 2 GB/s; no correctness errors.
  • Dremel assembly for batch: nested LIST column, batch_size = 4096 → correct records per batch; no cross-batch state corruption.
  • I/O coalescing: 5 adjacent column chunks within 500 KB gap → merged into 1 read; verified by mock I/O counter.
Fixtures
  • wide_100_columns.parquet — 100-column file; projection test; generated by parquet-mr.
  • batch_nested.parquet — nested LIST column; batch reading; cross-page boundary records.
Pitfalls
  • Dremel state across batches: AssemblyFSM must be persistent across read_batch calls within a column chunk; do not reset FSM per batch; records can span batch boundaries.
  • Column chunk skip with non-seekable reader: CoalescingReader requires seekable I/O; for streaming (non-seekable) sources, skip must consume (not seek) skipped bytes; add SkippingReader fallback.
  • Batch boundary on repeated field: a record with 1000 LIST items and batch_size=4096 means a record can span multiple batches; assembly FSM must buffer partial records.
  • Type erasure overhead: Box<dyn AnyColumn> with dynamic dispatch; avoid in tight loops; concrete-typed ColumnBatch<T> is preferred for internal use; RecordBatch is for output only.

Pitfalls
  • Differential output format differences: parquet-mr prints NaN as NaN, Arrow may print NaN; normalize before diff; don't report false failures.
  • INT96 endianness in Julian day: the 12-byte INT96 layout in Parquet is [nanos_since_midnight: i64 LE][julian_day: i32 LE] (nanos first, then day); confusing field order is a known source of bugs.
  • ConvertedType vs LogicalType ordering in old files: some parquet-mr versions write only ConvertedType; ensure both code paths tested.
