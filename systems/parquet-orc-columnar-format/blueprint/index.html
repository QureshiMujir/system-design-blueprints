412 — Parquet / ORC Columnar File Format Codec from Scratch

Project Number: 412

Project Name: Parquet / ORC Columnar File Format Codec from Scratch

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal

Build a correct, production-capable bytes-on-disk codec for Apache Parquet (primary) and Apache ORC (secondary track) — a from-scratch reader + writer that operates at the file-format layer, distinct from the in-memory columnar layer (#395 Arrow) and table-format layer (#214 Iceberg/Delta). Correctness-first, observability-second, maintainability-third, performance-fourth.

Core capability surface:

  • Parquet reader — footer parse, schema reconstruction, row-group + page navigation, predicate pushdown (stats + PageIndex + Bloom filter), Dremel assembly, all encodings, all codecs.
  • Parquet writer — schema ingestion, per-column buffering, R/D level computation, encoding selection, per-page compression, row-group flush at size threshold, footer serialization.
  • ORC reader — postscript + file footer + stripe footer parse, column stream decode (PRESENT/DATA/LENGTH/DICTIONARY_DATA), integer RLEv2, row-group index.
  • ORC writer — stripe flush, column stream generation, postscript seal.
  • CLI tool (pqtool) — schema dump, row-group stats, page dump, roundtrip verify, differential compare vs reference files.

System boundaries:

  • IN scope: PAR1 magic-framed files; Thrift compact footer; all page encodings; codecs (SNAPPY, GZIP, ZSTD, LZ4_RAW); column statistics; PageIndex; Bloom filters; Dremel record shredding/assembly; ORC stripes + RLEv2.
  • OUT of scope (explicit non-goals):
    • NOT an execution engine or query planner — no SQL, no expression evaluation, no joins.
    • NOT an in-memory columnar format — Arrow IPC/Flight are #395.
    • NOT a table format (Iceberg/Delta/Hudi manifest layer) — those sit above this layer (#214).
    • NOT compression primitives — reuse codecs from #397; do not re-implement Snappy/Zstd/LZ4/Gzip internals.
    • NOT a distributed shuffle or exchange layer.
    • NOT Avro, CSV, JSON, or ORC-ACID transaction log parsing beyond basic delta detection.

Intended deployment model: linkable Rust crate (parquet_codec + orc_codec) + CLI binary; embedded in query engines, ETL pipelines, lake-house connectors.

Target users: query-engine authors, ETL pipeline engineers, data-infra platform engineers requiring byte-level Parquet/ORC fidelity (not a higher-level connector).

Phase 0 deliverable — numbered crates/modules:

  1. crates/parquet_core/ — magic, footer, schema, row_group, column_chunk, page
  2. crates/parquet_encoding/ — plain, rle_bp, dict, delta, byte_stream_split
  3. crates/parquet_codec/ — public reader + writer facade, integration with codec layer
  4. crates/orc_codec/ — postscript, footer, stripe, stream, rle_v2
  5. crates/shared/ — thrift_compact, bit_reader, bit_writer, crc32c
  6. cli/pqtool/ — schema, stats, dump, verify, diff subcommands

What later phases unlock: P3 unlocks nested/repeated data; P4 unlocks compression integration; P6 unlocks predicate pushdown; P7 unlocks page-level skipping + Bloom filters; P9 unlocks delta encodings; P10 unlocks ORC track; P11 unlocks vectorized reads.

Deferred features: non-Parquet encryption (PhaseDeferred("Deferred Features Register")); ACID delta-file merge (PhaseDeferred("Deferred Features Register")); Arrow IPC bridge (PhaseDeferred("Deferred Features Register")).

Estimated timeline: Phase 0 = 6–10 weeks (one engineer, full-time); full P0–P12 = 5–8 months.

Recommended language: Rust.

2. Why Build This

Unique systems knowledge taught:

  • Columnar layout economics — why projecting 2 of 100 columns reads 2% of bytes; cache-line density vs row-oriented layouts; compression ratio amplification from value similarity within a column.
  • Dremel record shredding — lossless encoding of arbitrary nested/repeated structure into flat R/D integer arrays; assembly FSM reconstruction of the original tree; the single most subtle algorithm in Parquet.
  • Thrift compact protocol — varint field IDs, zigzag integers, stop bytes; reading metadata without a schema (field-ID driven); writing deterministically without drift.
  • Bit-packing / hybrid RLE — encoding levels and dictionary indices into minimal bits; bit_width selection; run-vs-literal block switching.
  • Predicate pushdown at bytes level — how min/max statistics gate row-group skipping; ColumnIndex for page-level skipping; Bloom filters for equality predicates against high-cardinality columns; I/O coalescing.
  • ORC second format — stripe-based model; per-column ORC streams vs Parquet pages; integer RLEv2 (DIRECT/PATCHED_BASE/DELTA/RLE) vs Parquet's DELTA_BINARY_PACKED; ACID delta design.

Historical/architectural significance:

  • Parquet (Google Dremel → Twitter/Cloudera 2013) defined the modern open columnar format; every major OLAP system (Spark, Presto/Trino, BigQuery, DuckDB, Snowflake) reads or writes it.
  • ORC (Hortonworks/Facebook 2013) explored alternative trade-offs (stripe-based, native compression, lightweight indexing); remains dominant in Hive/ORC-first pipelines.
  • Both formats occupy the same niche: durable, self-describing, compressed columnar storage requiring no runtime schema registry.

Engineering muscles developed: adversarial binary parsing; offset arithmetic correctness; differential conformance against parquet-mr and Arrow-produced files; property-based round-trip testing; encoding-selection heuristics under real-world distribution assumptions.

Production concepts exercised: schema evolution (added/dropped/optional columns), statistics trust boundary (corrupt min/max leads to silent data loss via incorrect predicate skip), page CRC verification, dictionary fallback mid-chunk, decompression-bomb defense.

Cross-links:

  • #395 Arrow — in-memory columnar layer above this; Parquet reader feeds Arrow record batches; this project is the bytes-on-disk counterpart.
  • #397 Compression — codec implementations reused here; Snappy/Zstd/LZ4/Gzip wrapping is a dependency, not a re-implementation.
  • #214 Iceberg/Delta — table-format manifest layer that references Parquet data files; this project implements what that layer points to.
  • #394 NTP clock — timestamp physical type (INT96/TIMESTAMP micros/nanos) correctness depends on correct epoch math.

Calibration value: Parquet is a deceptively deep format — it appears to be "just a file format" and is actually a nested-data algebra + encoding pipeline + statistics index + Thrift metadata system. Building it from scratch permanently calibrates one's understanding of what query engines actually do at I/O boundaries.

What Mastery Looks Like

  • Binary format forensics (Phase 1 + Phase 5): Given a corrupt Parquet file, locate the footer by working backward from EOF, decode Thrift compact fields by hand, and identify the exact byte offset of any structural error — without a debugger or helper library.
  • Dremel shred/assemble fluency (Phase 3): Derive max_rep and max_def for any nested schema, trace through the shred and assembly FSM for a multi-level LIST-of-MAP schema by hand, and explain why a record with rep=1/def=2 means "second item in an inner list is null" vs rep=0/def=1 meaning "outer list is empty".
  • Predicate pushdown reasoning (Phase 6 + Phase 7): Given a filter predicate, a ColumnIndex, and a Bloom filter, enumerate exactly which row groups and pages are skipped and why — and identify the one class of predicate (NaN floats) that cannot use statistics-based pruning.
  • Encoding selection judgment (Phase 8 + Phase 2): For a given column's value distribution (cardinality ratio, sort order, type), choose the optimal encoding, quantify the expected compression ratio and decode throughput change, and explain the fallback condition (e.g., dict overflow) that forces a mid-chunk switch.
  • Conformance gap diagnosis (Phase 11): When a parquet-mr differential test fails, use pqtool dump --raw-pages to identify whether the divergence is in the encoding, the statistics, the footer Thrift field, or the level encoding — and distinguish a real bug from a normalization artifact (NaN formatting, ConvertedType vs LogicalType precedence).
  • ORC vs Parquet architectural trade-offs (Phase 9): Articulate why ORC's per-stream per-stripe compression differs from Parquet's per-page compression, how that affects I/O coalescing for narrow vs wide reads, and why RLEv2 PATCHED_BASE outperforms DELTA for integer columns with outliers.
  • Performance bottleneck diagnosis (Phase 10): Using flamegraph + perf stat + criterion, identify whether a decode regression is in codec decompression, bit-unpacking, dict lookup, or Dremel assembly — and determine whether a fix requires SIMD intrinsics, a buffer reuse change, or an algorithmic shift.
  • Security boundary enforcement (Phase 11 + Threat Model): After Phase 11, for any input fuzz crash you can classify it into the correct threat category (T1–T15), trace the invariant it violates (I1–I15), confirm the error type returned is the correct variant, and write a regression fixture that reproduces the crash without panicking.

pqtool CLI — thin command dispatcher; calls parquet_codec + orc_codec public APIs; no format logic here; used for manual inspection, differential testing, and operator runbooks.

parquet_codec facade — public entry point; owns ParquetReader (footer-driven navigation, predicate evaluation, page iteration) and ParquetWriter (schema ingestion, row-group lifecycle, footer serialization); enforces all invariants at the boundary.

parquet_core — file anatomy: magic verification, footer byte-range read, Thrift deserialization into FileMetaData; schema element tree into SchemaNode DAG; row-group + column-chunk descriptors; page header parsing (DataPageHeaderV1/V2, DictionaryPageHeader); PageIndex (ColumnIndex + OffsetIndex) parsing; Bloom filter block reader; Dremel R/D assembly FSM.

parquet_encoding — stateless encode/decode functions per encoding type; no I/O; operates on &[u8] / Vec<u8>; encoding-selection heuristic module inspects value distribution and picks optimal encoding.

shared — Thrift compact protocol (read/write without generated code; field-ID-driven); bit-level reader/writer (LSB-first, arbitrary widths); CRC-32C computation; varint encode/decode.

#397 codec layer — external dependency boundary; Codec trait with compress/decompress + max_compressed_len; implementation provided by the compression project; per-page instantiation.

orc_codec — independent second-format crate; ORC postscript (last byte = PS length, then PS protobuf), file footer protobuf, stripe footers, column streams, integer RLEv2 decoder/encoder; structurally parallel to parquet_core but shares only shared:: primitives.

6. Design Principles

P1 — Roundtrip Fidelity is Non-Negotiable. decode(encode(x)) == x for all values including nulls, NaN, nested structures, empty arrays. Enforced by property tests on every encoding + Dremel round-trip. Violation: data loss or silent corruption on read-back; no partial failure modes permitted.

P2 — Statistics Never Lie (Conservative Bound). Written min/max/null_count must be exact or conservative (widen, never tighten). A pruned row-group must provably contain no matching rows. Violation: predicate pushdown silently skips rows that satisfy a filter → silent data loss at query time.

P3 — Footer Offsets Are Ground Truth. Every column-chunk and page offset/length stored in the footer must match the byte position in the file. Cross-validated on write (pre-computed) and optionally on read (spot-check mode). Violation: seek to wrong offset → decode garbage → cascading errors.

P4 — Bounded Decompression. Every decompress call is bounded by a configurable MAX_UNCOMPRESSED_PAGE_BYTES. Reject before allocating. Violation: decompression bomb → OOM in reader process → DoS from adversarial or corrupted files.

P5 — Encoding Is Stateless. Each encoding module is a pure function over byte slices. No shared mutable state; no hidden caches between pages. Caller owns all buffers. Violation: encoder state bleeds across pages → corrupted output; impossible to test in isolation.

P6 — Dremel Levels Are Schema-Derived, Not Inferred. max_rep and max_def are computed from the schema tree at schema-load time and stored in the ColumnDescriptor. Every value's R/D pair is validated against these maxima on decode. Violation: out-of-range levels → assembly FSM enters undefined state → silently wrong output.

P7 — Thrift Decode Is Forward-Compatible. Unknown field IDs are skipped, not rejected. Stop byte terminates; missing optional fields are default-initialized. Violation: new Parquet spec version adds an optional field → reader crashes on valid files → forward-compat broken.

P8 — Dictionary Fallback Is Transparent to Callers. When dictionary exceeds cardinality threshold mid-chunk, the writer falls back to PLAIN silently; the caller's value stream is unaffected. The partially built dictionary page is flushed before the first plain page. Violation: caller observes encoding-dependent errors → leaky abstraction.

P9 — I/O Is Caller-Controlled. The codec layer accepts Read + Seek (reader) and Write (writer) traits; no internal file opens, no thread spawning, no async runtime. Caller controls buffering, prefetch, and concurrency. Violation: internal I/O → can't embed in async runtimes or test with in-memory buffers.

P10 — Schema Evolution Is Additive and Opt-In. Added optional columns are safe; removed columns become nulls; renamed columns break. Schema evolution is detected at open time; mismatches returned as structured errors, not panics. Violation: silent schema drift → wrong column projected → corrupted analytics.

P11 — CRC Errors Are Hard Failures. A DataPageV2 CRC mismatch is an unrecoverable error for that page. No partial read of a CRC-mismatched page. Return Error::Corruption with offset and column info. Caller decides whether to skip the row-group or abort. Violation: reading corrupt data as valid → silent wrong results.

P12 — Observability by Default. Every reader and writer emits structured trace spans (pages decoded, bytes decompressed, rows emitted, row-groups skipped, dict-hit ratio). Zero overhead when tracing is disabled via compile-time feature or runtime no-op sink. Violation: unobservable performance regressions in production pipelines.

P13 — No Allocation on the Hot Decode Path. Level arrays, value buffers, and bit-reader scratch space are pre-allocated and reused across pages within a column chunk. decode_page accepts caller-provided mutable slices. Violation: per-page heap allocation → GC pressure equivalent → latency spikes in tight scan loops.

8.5 Dremel R/D Levels — Worked Example

Schema:

message MyRecord {
  optional group a {       // optional → max_def contributes 1
    repeated group b {     // repeated → max_rep contributes 1, max_def contributes 1
      optional int32 c;    // optional → max_def contributes 1
    }
  }
}

Column a.b.c: max_rep = 1, max_def = 3.

Record a b list c R D Notes
{a: {b: [{c:1}, {c:2}]}} present 2 items 1 0 3 first value of new record
(cont.) — — 2 1 3 second item in b (rep=1 = new b item)
{a: {b: [{c:null}]}} present 1 item null 0 2 c is null → def stops at 2
{a: {b: []}} present empty — 0 1 b list is empty → def stops at 1
{a: null} null — — 0 0 a is null → def stops at 0
{} (a absent) absent — — 0 0 same encoding as null a

Assembly FSM: for each (R, D) pair — if R == 0 emit new top-level record; if D < max_def then corresponding level is null/empty; if D == max_def emit concrete value; R > 0 means repeated field repeats at level R.

8.6 Encoding Catalogue

Encoding Tag Applies To Notes
PLAIN 0 all types raw little-endian; BOOLEAN = LSB-packed
PLAIN_DICTIONARY 2 all dict-page + delta indices (legacy tag; use RLE_DICTIONARY)
RLE 3 BOOLEAN RLE-only (no bit-packing)
BIT_PACKED 4 levels only legacy; fixed 8-values-per-block
DELTA_BINARY_PACKED 5 INT32/INT64 block-delta + bit-pack; zigzag optional
DELTA_LENGTH_BYTE_ARRAY 6 BYTE_ARRAY delta-encode lengths; concatenate values
DELTA_BYTE_ARRAY 7 BYTE_ARRAY shared-prefix delta; suffix plain
RLE_DICTIONARY 8 all (dict indices) hybrid RLE/bit-pack over dict indices
BYTE_STREAM_SPLIT 9 FLOAT/DOUBLE/INT32/INT64 byte-plane interleave; improves compression ratio

Hybrid RLE/BIT_PACKED format (used for levels + dict indices):

  • 4-byte LE byte_count header (total bytes following)
  • then blocks alternating between:
    • RLE block: (count << 1 | 0) varint + 1-byte value (if bit_width ≤ 8) or ceil(bit_width/8) bytes
    • BIT_PACKED block: (block_count << 1 | 1) varint + block_count * bit_width * 8 / 8 bytes (8 values per block)

8.7 ORC File Layout

┌────────────────────────────────────────────────────────────┐
│  [stripe 0] [stripe 1] ... [stripe N-1]  [file footer]     │
│                                           [postscript]      │
│                                           [1-byte PS_len]   │
└────────────────────────────────────────────────────────────┘

Stripe:
┌──────────────┬────────────────────────────────────┐
│ index streams│ data streams  │  stripe footer      │
│ (row-group   │ (PRESENT,DATA,│  (Protobuf)         │
│  indexes)    │  LENGTH, DICT)│                     │
└──────────────┴────────────────────────────────────┘
  • Postscript (last bytes before 1-byte PS_len): Protobuf with footerLength, compression, compressionBlockSize, version.
  • File footer: Protobuf Footer with column types, stripes list, row count, statistics, metadata.
  • Stripe footer: Protobuf with stream list (column, kind, length) and column encodings.
  • Column streams: PRESENT (null bitmap, RLE), DATA (values), LENGTH (string/list/map lengths), DICTIONARY_DATA (dict strings).
  • Integer RLEv2: 4 sub-encodings — DIRECT (bit-pack), DELTA (monotone runs), RLE (short runs), PATCHED_BASE (outlier handling).

  • Zigzag signed overflow: (v << 1) ^ (v >> 63) for i64::MIN must not overflow; use i64::wrapping_shl.

  • parquet_core::magic: verify_header(buf: &[u8]) -> Result<(), Error> checks buf[0..4] == b"PAR1"; verify_footer(buf: &[u8]) -> Result<(), Error> checks last 4 bytes = b"PAR1" and preceding 4 bytes as footer_len ≤ file_len − 8. (P13 §1 file format spec; I2, I3)

14. Phase 2 — Hybrid RLE/BIT_PACKED and Dictionary Encoding

14.1 Objectives

  • Implement hybrid RLE/BIT_PACKED encoder/decoder (used for R/D levels and dictionary indices).
  • Implement dictionary page + RLE_DICTIONARY encoding with cardinality-threshold fallback.
  • Wire dict encoding into ColumnChunkWriter; wire dict decode into ColumnChunkReader.
  • Implement encoding_selector heuristic: pick PLAIN vs RLE_DICTIONARY vs PLAIN.

14.2 Detailed Implementation Steps

  • parquet_encoding::rle_bp::encode(values: &[u32], bit_width: u8, out: &mut Vec<u8>): prepend 4-byte LE byte count header; scan for runs (≥ 8 identical) → emit RLE block (count << 1 | 0) + value bytes; remaining → group into 8-value BIT_PACKED blocks (block_count << 1 | 1) + packed bytes. (P13 §6 hybrid RLE/BIT_PACKED format; P9 Lemire vectorized bit-unpack; ADR-A04)
  • parquet_encoding::rle_bp::decode(buf: &[u8], bit_width: u8, count: usize, out: &mut Vec<u32>): read 4-byte header; loop: read varint; low bit = 0 → RLE (read value bytes, repeat count times); low bit = 1 → BIT_PACKED (read block_count * 8 values via BitReader::read_bits(bit_width)). (P13 §6 hybrid RLE; I11 level-count check)
  • Bit width 0: all values are identical (known from RLE run header); bit_width=0 means value occupies 0 bits; read_bits(0) = 0 unconditionally. (P13 §6 special case; B4 Ch 11)
  • parquet_encoding::dict: DictBuilder<T> — HashMap<T, u32> index, Vec<T> values; add(v: T) -> u32 returns index; is_full() -> bool when len() > MAX_DICT_SIZE; encode_page(out: &mut Vec<u8>) — PLAIN-encode dict values. (P13 §5 RLE_DICTIONARY encoding; ADR-A17 dict-per-chunk lifecycle)
  • DictDecoder<T> — Vec<T> values preloaded from dict page; lookup(idx: u32) -> &T. (I8 dict index bounds; ADR-A17)
  • parquet_encoding::dict::encode_indices(indices: &[u32], bit_width: u8, out: &mut Vec<u8>) — RLE_DICTIONARY: first byte = bit_width, then rle_bp::encode(indices, bit_width, out). (P13 RLE_DICTIONARY data page first-byte protocol)
  • Dict fallback mid-chunk: when DictBuilder::is_full(), writer flushes current pages (dict page + dict-encoded data pages), then switches to PLAIN for remaining values in the chunk. New data pages use Encoding::Plain. Footer encodes both RleDictionary and Plain in encodings list. (P8 fallback transparency; ADR-A17; System Constraints dict cardinality constraint)
  • parquet_encoding::selector::select_encoding(sample: &[Value], desc: &ColumnDescriptor) -> Encoding: heuristic — if distinct / total < 0.5 → RleDictionary; if column is sorted int → DeltaBinaryPacked; if FLOAT/DOUBLE → ByteStreamSplit; else Plain. (P3 Abadi compression analysis; B3 Ch 2 statistical coding; ADR-A19)
  • ColumnChunkWriter: check selector::select_encoding at start; if dict, use DictBuilder; flush dict page before first data page; if fallback triggered mid-chunk, flush partial dict page + switch.

14.5 Conformance Fixtures

  • flat_dict_snappy.parquet — parquet-mr generated; read with our decoder; values match.
  • dict_fallback.parquet — our writer; dict fills and overflows mid-chunk; parquet-mr reads.
  • rle_bp_known_vectors.bin — hand-crafted RLE + BIT_PACKED blocks; decode + assert known output.

14.6 Pitfalls

  • Dict page encoding tag: RLE_DICTIONARY data page uses Encoding::RleDictionary (8) for data pages, but the dict page itself uses Encoding::PlainDictionary (2) (legacy tag kept for compatibility); don't use Plain (0) for dict page.
  • Bit width byte for RLE_DICTIONARY data page: the first byte of the data (after page header compressed bytes) is the bit_width byte, then the RLE/BIT_PACKED stream; forgetting this byte shifts all index reads by 1.
  • Empty runs: an RLE block with count=0 is valid (skip it); don't infinite-loop on count=0 input.
  • BIT_PACKED block padding: blocks are always 8 values even if fewer remain; last block may be padded with 0; decoder must use count to stop at correct value, not byte count.
  • HashMap non-determinism: dict index assignment depends on insertion order; HashMap random order under randomized hashing; use IndexMap or sort-then-assign for reproducible dict pages.

14.7 Performance Concerns

  • DictBuilder::add: hot path; HashMap<Value, u32> lookup per value; consider FxHashMap for speed.
  • RLE encode scan for runs: vectorizable if values are u8 (levels); branch-heavy if u32 (indices); profile on hot workloads.
  • Dict page PLAIN encode: memcpy for fixed-width; BYTE_ARRAY dict encode is sum_of_lengths * 4 + total_bytes output; pre-estimate capacity.

14.8 Edge Cases

  • All-same values: entire column is one RLE run; bit_width=0; dict_size=1; index = 0.
  • All-distinct values (cardinality = n): dict_size immediately hits threshold on first add; entire column written as PLAIN.
  • MAX_DICT_SIZE = 1: fallback on second distinct value; valid but unusual.
  • Empty dict (0 values written): should not produce a dict page; ColumnChunkWriter guards this.

14.9 Failure Analysis

  • Dict index OOB at decode: DictDecoder::lookup panics if unchecked; must bounds-check and return Error::DictIndexOutOfRange. Detection: every lookup in decode_indices. Blast radius: entire column chunk; fail with error, do not partially decode.
  • Bit width mismatch: stored bit_width byte ≠ expected from dict size; detect by checking ceil(log2(dict_size)) ≤ stored bit_width; if mismatch, trust stored bit_width (may be over-wide, never under-wide per spec).

14.10 Operational Notes

  • writer.dict_hit_ratio histogram: fraction of values using dict vs PLAIN across column chunks.
  • writer.dict_fallback_count counter: increments per column-chunk that triggers fallback.
  • Span: tracing::span!(Level::DEBUG, "encode_column_chunk", encoding = ?, dict_size = ?).

15. Phase 3 — Nested/Repeated Schema and Dremel R/D Shredding + Assembly

15.1 Objectives

  • Extend schema builder to support Optional and Repeated field types; compute max_rep / max_def per column.
  • Implement Dremel record shredding: values: Iterator<Item=NestedRecord> → per-column (R[], D[], values[]) streams.
  • Implement Dremel assembly FSM: per-column (R[], D[], values[]) → Iterator<Item=NestedRecord>.
  • Write + read nested schemas: LIST<STRING>, MAP<STRING,INT32>, STRUCT(a: INT64, b: optional STRING).

15.2 Detailed Implementation Steps

  • parquet_core::schema::build_schema_tree: handle Repetition::Optional (contributes 1 to max_def), Repetition::Repeated (contributes 1 to max_rep and 1 to max_def), Repetition::Required (no contribution); max_rep and max_def accumulated through recursive DFS. (P1 §3 repetition/definition level computation; ADR-A18; I9, I12)
  • parquet_core::dremel::shred: fn shred(record: &dyn DremelRecord, col: &ColumnDescriptor, rep_levels: &mut Vec<u8>, def_levels: &mut Vec<u8>, values: &mut dyn ValueSink) — recursive descent; track current_rep (reset at record boundary = 0); for each leaf: if field absent/null at depth D → push (current_rep, D−1); if field present → push (current_rep, max_def) + emit value. (P1 §4 shredding algorithm; I1 roundtrip fidelity)
  • DremelRecord trait: is_null() -> bool; is_absent() -> bool; child(name: &str) -> Option<&dyn DremelRecord>; list_items() -> &[Self]. (P1 §2 nested data model; P6 design principle null vs absent)
  • parquet_core::dremel::assemble: AssemblyFSM per column; state = (column_path_position, open_records_stack: Vec<usize>); for each (R, D) pair: if R == 0 → finalize previous record, start new; if D < max_def → appropriate nesting level is null/empty; if D == max_def → append concrete value to current path position. (P1 §5 assembly FSM algorithm; I9, I11)
  • AssemblyFSM::consume_batch(reps: &[u8], defs: &[u8], values: &[T]) -> Result<Vec<Record>, Error>: processes one decoded page; accumulates partial records; returns completed records only. (P1 §5 partial-record spanning pages; §8.5 worked example)
  • LIST standard encoding: 3-level structure optional group list { repeated group element { optional T item } } → max_rep=1, max_def=3 for non-null item; max_def=2 for null item; max_def=1 for empty list; max_def=0 for null list.
  • MAP standard encoding: 4-level optional group map { repeated group key_value { required K key; optional V value } } → max_rep=1 for repeated key_value; max_def varies per nullable.
  • ColumnChunkWriter (nested): for each value in record stream, call dremel::shred into LevelArrays; accumulate; when page size threshold reached, flush: encode rep levels with rle_bp (bit_width = ceil(log2(max_rep+1))), def levels with rle_bp (bit_width = ceil(log2(max_def+1))), then encode values.
  • DataPageV1 format for nested: rep_levels bytes (RLE/BIT_PACKED) + def_levels bytes (RLE/BIT_PACKED) + value bytes; sizes NOT stored in V1 header (reader must parse in order); DataPageV2 stores rep/def byte lengths in header — prefer V2 for new writes.

15.3 Deliverable

  • write_nested_list.rs example: write LIST<STRING> column with null lists, empty lists, multi-item lists; read back; values match.
  • pqtool schema nested.parquet prints nested schema with max_rep/max_def per column.

15.4 Acceptance Criteria

  • Dremel roundtrip property test: for any randomly generated nested record (depth ≤ 5, up to 3 repetitions), assemble(shred(records)) == records; 10k iterations.
  • Conformance: nested_list_map.parquet (parquet-mr generated) read by our reader; all values match.
  • Our written nested file read by parquet-mr without error.
  • Level OOB invariant (I9) tested: fuzz-generated levels outside max_rep/max_def → Error::InvalidLevel; no panic.

15.5 Conformance Fixtures

  • nested_list_map.parquet — parquet-mr generated; canonical LIST+MAP structure.
  • dremel_worked_example.parquet — hand-crafted file matching §8.5 worked example; byte-verified.
  • deeply_nested.parquet — 6-level nesting depth; max_def=6; edge case for assembly stack depth.

15.6 Pitfalls

  • DataPageV1 level boundary: rep and def level byte-lengths are NOT stored in V1 header; reader must parse RLE/BIT_PACKED stream and stop at num_values elements (not bytes); values begin at next byte boundary after def levels. Use DataPageV2 for new writes (stores explicit byte lengths).
  • NULL vs ABSENT for optional fields: Parquet does not distinguish between a JSON null value and an absent field — both map to D < max_def; assembly must not re-introduce the distinction.
  • LIST three-level vs two-level legacy: some files use legacy 2-level LIST encoding (repeated field directly, no wrapper group); detect by presence of ConvertedType::LIST on the outer group without a nested repeated group; handle both.
  • Assembly FSM partial state across pages: AssemblyFSM must be stateful across page boundaries within a column chunk; records can span page boundaries (a record's values can be split across pages).

15.7 Performance Concerns

  • Level decode is on the hot path for every column in every page; rle_bp::decode into u8 arrays; must be < 5% of total column decode time.
  • shred recursion: stack depth = schema depth ≤ 32; not heap-allocated; safe for deep schemas.
  • AssemblyFSM state: stack of open records is Vec<usize> (small); heap only for completed records batch.

15.8 Edge Cases

  • All-null list column: all D=0; rep = 0 for every value; assembly emits null list for every row.
  • Empty list: D=1 (list present, empty); no repeated elements; rep = 0.
  • Single-element list: D=max_def, R=0; one value per record.
  • Record boundary at exact page boundary: R=0 at first value of next page; assembly must detect new record start.
  • Schema has only REQUIRED fields: max_rep=0, max_def=0; levels have bit_width=0; no level bytes in page; special-cased in encoder/decoder.

15.9 Failure Analysis

  • Dremel assembly FSM wrong record boundary: R=0 at wrong position → records merged or split incorrectly → silent wrong output. Detection: row-count check at end of row group (assembled records = RowGroupDescriptor.num_rows); mismatch → Error::RowCountMismatch.
  • Level decode overrun: reading more levels than num_values → reading into next field's bytes → corrupt decode. Detection: strict count parameter enforcement in rle_bp::decode.

15.10 Operational Notes

  • reader.dremel_assembly_time_us histogram per row group.
  • Span: tracing::span!(Level::DEBUG, "dremel_shred", column = ?, num_records = ?).
  • pqtool dump --format=json renders nested values as JSON; uses AssemblyFSM output.

16. Phase 4 — Compression Integration (Per-Page Codecs)

16.1 Objectives

  • Integrate the Codec trait from #397 compression project; implement codec_bridge.rs.
  • Wire per-page compression into ColumnChunkWriter and decompression into ColumnChunkReader.
  • Support SNAPPY, GZIP, ZSTD, LZ4_RAW; BROTLI optional (feature flag).
  • Enforce MAX_UNCOMPRESSED_PAGE_BYTES decompression bomb guard.
  • Benchmark: ZSTD L1 + RLE_DICTIONARY decode throughput ≥ 400 MB/s.

16.2 Detailed Implementation Steps

  • parquet_codec::codec_bridge: trait Codec { fn compress(&self, input: &[u8], out: &mut Vec<u8>) -> Result<(), Error>; fn decompress(&self, input: &[u8], uncompressed_size: usize, limit: usize, out: &mut Vec<u8>) -> Result<(), Error>; } — thin wrapper delegating to #397 crate implementations. (ADR-A05; P9 I/O trait boundary)
  • codec_bridge::from_compression(codec: CompressionCodec) -> Box<dyn Codec>: factory; returns SnappyCodec, GzipCodec, ZstdCodec, Lz4RawCodec, UncompressedCodec (memcpy), or Error::UnsupportedCodec for BROTLI/LZO without feature flag. (ADR-A05; Zstd Frame Format RFC 8878; LZ4 Frame Format doc)
  • LZ4_RAW: no frame header; raw LZ4 block compression; distinct from framed LZ4; ensure the #397 project exposes a lz4_raw_compress variant. (R7 Snappy framing analogy; LZ4 Frame Format spec → applied in Phase 4)
  • SNAPPY raw: Parquet uses Snappy without the framing format; raw snappy block only; snap::raw::Encoder/Decoder. (R7; P13 CompressionCodec.SNAPPY definition)
  • ColumnChunkWriter::flush_page: after encoding, call codec.compress(encoded_bytes, &mut compressed_buf); write PageHeader with compressed_page_size + uncompressed_page_size; write compressed_buf. (P13 page layout §4; ADR-A05; B3 Ch 7 LZ block semantics)
  • ColumnChunkReader::read_page: read PageHeader (Thrift); allocate decompressed_buf only after checking uncompressed_page_size ≤ MAX_UNCOMPRESSED_PAGE_BYTES (invariant I13); call codec.decompress(compressed_bytes, uncompressed_size, limit, &mut decompressed_buf). (I13 decompression bomb guard; T3 threat model; P4 design principle)
  • DataPageV2 special case: rep+def levels are NOT compressed (written raw); only value bytes are compressed; compressed_page_size in header = uncompressed_levels_bytes + compressed_values_bytes; uncompressed_page_size = uncompressed_levels_bytes + uncompressed_values_bytes. (P13 DataPageHeaderV2 spec sec. 4.4; §8.1 page layout diagram)
  • CRC for DataPageV2: compute CRC-32C(compressed_values_bytes) after compression; store in DataPageHeaderV2.crc; verify on read before decompression. (ADR-A08; I10; T8 threat model; P11 CRC design principle)
  • WriterConfig::compression: CompressionCodec field; default = Zstd (level 1); selectable per column via ColumnConfig. (ADR-A05; System Constraints ZSTD L1 throughput target)

  • all_types_zstd.parquet example: write all physical types with ZSTD; read back; values match.
  • pqtool stats file.parquet shows per-column codec and compression ratio.

16.4 Acceptance Criteria

  • Roundtrip: SNAPPY + GZIP + ZSTD + LZ4_RAW, all physical types: all pass.
  • Decompression bomb guard: attempt to decompress page claiming uncompressed_size = 2 GB → Error::DecompressionBomb before any allocation.
  • DataPageV2 CRC: corrupt 1 byte in compressed payload → Error::Corruption; no partial decode.
  • decode_dict + ZSTD L1 combined: ≥ 400 MB/s on INT64 column (criterion benchmark).
  • cargo fuzz run fuzz_page_header runs 100k iterations without panic.

16.5 Conformance Fixtures

  • flat_plain_snappy.parquet, flat_plain_gzip.parquet, flat_plain_zstd.parquet, flat_plain_lz4raw.parquet — parquet-mr generated, one codec each.
  • crc_mismatch.parquet — synthetic; 1-byte corruption in DataPageV2 compressed payload.
  • bomb_claimed_size.parquet — synthetic; uncompressed_size header = 0x7FFFFFFF.

16.6 Pitfalls

  • GZIP framing vs deflate raw: CompressionCodec::Gzip in Parquet means RFC 1952 gzip (with header/trailer); not raw deflate; ensure flate2::GzEncoder is used, not DeflateEncoder.
  • LZ4_RAW vs LZ4_FRAME: Parquet uses LZ4_RAW (raw LZ4 block, no frame magic); using framed LZ4 adds 7+ bytes of header → "invalid magic" on read by parquet-mr.
  • Uncompressed page size in V2 header: includes uncompressed levels bytes (not just values); common bug: using only value uncompressed size → wrong uncompressed_page_size → decompression fails or returns wrong data.
  • Zstd decompression without declared size: if uncompressed_size from header is 0 or wrong, Zstd can still decompress (streaming) but Parquet requires pre-declaration; enforce consistency.

16.7 Performance Concerns

  • codec.decompress is the dominant cost for compressed files; avoid double-buffering (compress directly into page output buffer via Vec::resize + in-place).
  • ZSTD L1: ~3–5 GB/s decompression on modern x86; don't introduce copies that halve this.
  • LZ4_RAW: ~6–8 GB/s decompression; fastest codec; prefer for latency-sensitive pipelines.
  • Per-page codec object instantiation: reuse Box<dyn Codec> across pages within a column chunk (cached in ColumnChunkReader/Writer).

16.8 Edge Cases

  • Zero-length compressed page (0 values): compressed_page_size = 0; valid; decoder returns empty output; no call to decompressor.
  • Codec fallback: CompressionCodec::Uncompressed means memcpy; compressed_size == uncompressed_size.
  • Column-level codec override: one column SNAPPY, another ZSTD within same row group; valid; footer encodes per-column codec field.

16.9 Failure Analysis

  • Codec mismatch (written ZSTD, read as SNAPPY): footer codec field mismatch → Snappy decompress fails on ZSTD bytes → Error::Io or corrupt output. Detection: always read codec from ColumnChunkDescriptor, never assume. Recovery: Error::UnsupportedCodec or Error::Io with context.
  • CRC mismatch: 1-bit flip in flight → corruption detected before decompress → hard fail. No partial page. Operator runbook: pqtool verify --crc file.parquet to identify which pages are corrupt.

16.10 Operational Notes

  • reader.codec_decompress_bytes counter per codec type (tag: codec=zstd).
  • reader.page_crc_failures counter.
  • writer.compression_ratio histogram (compressed/uncompressed per page).
  • Span: tracing::span!(Level::TRACE, "decompress_page", codec = ?, compressed_bytes = ?, uncompressed_bytes = ?).

18. Phase 6 — Column Statistics and Row-Group Predicate Pushdown

18.1 Objectives

  • Implement per-column statistics accumulation in ColumnChunkWriter (min, max, null_count, distinct_count estimate).
  • Implement row-group predicate pushdown in ParquetReader/RowGroupReader: skip row groups where stats prove no match.
  • Expose PredicatePushdown API; evaluate against ColumnStatistics.
  • Verify: 95%+ I/O savings on 1% selectivity scan.

18.2 Detailed Implementation Steps

  • parquet_core::statistics: struct MinMaxStats<T: Ord+Clone> — min: T, max: T, null_count: i64, distinct_count: Option<i64>; update(v: &T): update min/max; update_null(): increment null_count. (P2 design principle; I6, I7; ADR-A19)
  • MinMaxStats::to_column_statistics() -> ColumnStatistics: serialize min/max to raw bytes per physical type spec (for binary types: raw bytes; for INT32/INT64: LE bytes; for FLOAT/DOUBLE: IEEE 754 LE). (P13 Statistics spec sec. 4.5; ADR-A19 typed generics rationale)
  • Min/max byte encoding per spec: for BYTE_ARRAY columns, min_value/max_value = raw bytes (no length prefix); for INT32 = 4-byte LE; for INT64 = 8-byte LE; for BOOLEAN = 1 byte (0x00 / 0x01). (P13 Statistics field encoding note; §18.6 pitfall on endianness)
  • NaN/Inf handling: IEEE 754 NaN is unordered → if any value is NaN, statistics are not written (set to absent); NaN in min/max would corrupt predicate skip. Inf is valid: -Inf is valid min; +Inf is valid max. (P13 statistics NaN handling rule; P2 — statistics never lie principle)
  • parquet_codec::predicate: fn evaluate_row_group(pred: &PredicatePushdown, stats: &HashMap<String,ColumnStatistics>) -> TriState where TriState = {MustSkip, MayMatch, MustMatch}; MustSkip → skip row group. (B1 Ch 14 skip index theory; P10 SIMD-Scan predicate evaluation; ADR-A21)
  • Predicate evaluation rules: Eq(v) vs [min, max] → skip if v < min || v > max; Lt(v) → skip if min >= v; Gt(v) → skip if max <= v; IsNull → skip if null_count == 0; IsNotNull → skip if null_count == num_values (all null); In(set) → skip if max < set.min() || min > set.max(). (P13 predicate pushdown spec; I6 statistics correctness invariant)
  • RowGroupReader::with_predicate(pred): stores predicate; on each row_group(idx) call, evaluate predicate against RowGroupDescriptor.columns[*].statistics; return None (skip) or Some(RowGroupReader).
  • Statistics-absent handling: if statistics is None in ColumnChunkDescriptor, MayMatch (never skip).
  • Statistics column order: predicate pushdown requires matching column path to ColumnChunkDescriptor; build HashMap<Vec<String>, usize> index at open time.
  • Writer: ColumnChunkWriter maintains MinMaxStats<T> per physical type; accumulates across all pages; serialized into ColumnMetaData.statistics on column-chunk close.

18.3 Deliverable

  • predicate_pushdown.rs example: 100 row groups; query col > 500; all but ~1 row group skipped; verify skipped count.
  • pqtool stats --predicate "col > 500" prints which row groups would be skipped.

18.4 Acceptance Criteria

  • Predicate skip ratio: dataset with 100 row groups, uniform distribution, 1% selectivity filter → ≥ 95 row groups skipped (no I/O).
  • IsNull pushdown: column with no nulls → null_count=0 in stats → IsNull predicate skips row group.
  • NaN values: column with NaN floats → statistics absent → predicate never skips that column's row group.
  • bloom_filter.parquet (parquet-mr generated): our reader parses statistics; skip evaluation matches parquet-mr behavior.
  • Statistics invariant (I6): property test — min ≤ v ≤ max for all non-null values in 10k random datasets.

18.5 Conformance Fixtures

  • stats_sorted_int64.parquet — sorted INT64 column; tight min/max; skip ratio = 99% for point queries.
  • stats_null_heavy.parquet — 50% null column; null_count accurate; IsNull/IsNotNull pushdown verified.
  • stats_float_nan.parquet — column with NaN values; statistics must be absent for that column.

18.6 Pitfalls

  • Statistics byte encoding endianness: min_value for INT32 is 4-byte LE (not NBO); getting this wrong makes min/max comparisons wrong → incorrect predicate skip → data loss. Cross-check with parquet-mr byte output.
  • BYTE_ARRAY min/max comparison: raw byte lexicographic order; NULL bytes sort before printable ASCII; important for STRING columns.
  • Truncated statistics: for long strings, some writers truncate max_value to a prefix (safe: widening); readers must handle max_value ≥ true max, min_value ≤ true min as acceptable.
  • All-null column statistics: null_count = num_values; min_value/max_value absent; predicates against all-null column: IsNull = MustMatch; any value comparison = MustSkip.
  • Statistics without is_min_value_exact field (old files): assume exact when field absent (Parquet spec default).

18.7 Performance Concerns

  • Statistics accumulation in writer: one comparison per value on the hot write path; must inline; min/max update = 2 comparisons; negligible vs encoding cost.
  • Predicate evaluation at open time: O(row_groups × columns_in_predicate); for 10k row groups and 10 predicate columns = 100k comparisons; < 1 ms; no concern.
  • Avoid deserializing statistics bytes per-evaluation: parse once at open into ColumnStatistics structs; cache in RowGroupDescriptor.

18.8 Edge Cases

  • Predicate on column not in file (schema evolution — column added later): stats absent → MayMatch → row group not skipped; column reads return all-null.
  • Predicate AND: both sub-predicates must yield MustSkip before the row group is skipped; one MayMatch is sufficient to include.
  • Predicate OR: either sub-predicate MayMatch → include; both MustSkip → skip.

18.9 Failure Analysis

  • Wrong statistics → silent data loss: a predicate skips a row group that actually matches → query returns wrong results. This is the most dangerous invariant violation. Detection: pqtool verify --statistics file.parquet scans all pages and checks min ≤ all_values ≤ max; null_count matches actual nulls. CI: nightly statistics verification on conformance corpus.
  • Statistics overflow (e.g., accumulate INT64 sum for distinct count): use Option<i64> for distinct_count; omit rather than overflow.

18.10 Operational Notes

  • reader.row_groups_skipped counter (tag: reason=stats_pushdown).
  • reader.row_groups_scanned counter.
  • reader.skip_ratio gauge = skipped / total.
  • Span: tracing::span!(Level::DEBUG, "predicate_pushdown", row_group = ?, result = ?).

(P10 SIMD-Scan; B7 Ch 12 skip-index search; System Constraints page skip ratio target ≥ 80%)
  • parquet_core::bloom_filter: Split Block Bloom filter as specified in Parquet format (Parquet Bloom filter spec §2): block size 256 bits = 8 × 32-bit words; BloomFilter { blocks: Vec<u64x4>, num_bytes: u32 }. (P6 Bloom 1970 theory; P13 Bloom filter spec; ADR-A20 XXHash)
  • Bloom hash: XXHash-64 of value bytes (raw bytes per physical type); split-block: block_index = (h >> 32) % num_blocks; within block: 8-probe SIMD-friendly mask salt[i] × (h × (2i+1)) masked to word boundary. (P7 Kirsch-Mitzenmacher double-hashing; ADR-A20; P13 Bloom §2 salt constants)
  • BloomFilter::may_contain(hash: u64) -> bool: check all 8 probes; any miss → false (definitely absent). (P6 Bloom no-false-negatives property; I14 invariant)
  • Writer: build BloomFilter during ColumnChunkWriter value accumulation; serialize as raw bytes; write after page index; record bloom_filter_offset/bloom_filter_length in ColumnChunkDescriptor. (System Constraints Bloom FPP 1% / max 128 KB; ADR-A20)
  • Predicate integration: for Eq(v) predicate, if Bloom filter present and !may_contain(hash(v)) → skip entire column chunk. (P10 predicate pushdown; I14; Failure Modes and Recovery bloom false-negative is impossible by construction)

19.3 Deliverable

  • bloom_filter.parquet example: column with 1M values; Bloom filter present; equality queries for absent values → 0 I/O (all skipped by Bloom); 1% FPP measured.
  • page_index_sorted.parquet: sorted INT64 column; page-level skips eliminate > 90% of pages for point queries.

19.4 Acceptance Criteria

  • Bloom filter false-negative rate: 0 (by construction); verified over 1M values in filter.
  • Bloom filter FPP: < 1% measured over 10M hash probes of values not in the filter.
  • PageIndex: point query on sorted 100-page column → ≤ 2 pages read (correct page + possible boundary).
  • bloom_filter.parquet (parquet-mr generated): our reader parses Bloom; may_contain matches expected.
  • OffsetIndex byte offsets: verified to match actual page positions in file.

  • bloom_filter.parquet — parquet-mr generated with Bloom filter; our reader must parse and evaluate.
  • page_index_sorted.parquet — sorted INT64; our writer writes PageIndex; parquet-mr reads PageIndex.
  • page_index_unsorted.parquet — random INT64; BoundaryOrder=Unordered; no skip possible but parse must succeed.

19.6 Pitfalls

  • Bloom filter spec version: Parquet uses a custom split-block Bloom (not standard Bloom or Xor filter); must use the Parquet-specified salt[] constants and block structure; different from bloom crate.
  • ColumnIndex byte encoding: min/max per page use same encoding as footer statistics (physical-type dependent); same endian rules apply.
  • null_pages flag: if null_pages[i] = true, page i is entirely null; min/max undefined; predicate for any non-null value must skip this page (MustSkip for value predicates).
  • OffsetIndex first_row_index: cumulative (not per-page delta); row 0 of the row group = 0; must track running count during write.

19.7 Performance Concerns

  • PageIndex load: seeks for each column chunk; for wide tables (100 columns), this is 200 seeks per row group; consider coalescing reads if column index offsets are adjacent.

19.8 Edge Cases

  • PageIndex offset/length mismatch: column_index_offset points to wrong location → Thrift decode fails → return Error::ThriftDecode; page-level skipping disabled for that column; row-group-level stats still used.

20. Phase 8 — Delta and BYTE_STREAM_SPLIT Encodings

20.1 Objectives

  • Implement DELTA_BINARY_PACKED (INT32/INT64): block-based delta + bit-pack encoding.
  • Implement DELTA_LENGTH_BYTE_ARRAY (BYTE_ARRAY): delta-encoded lengths + concatenated values.
  • Implement DELTA_BYTE_ARRAY (BYTE_ARRAY): shared-prefix delta + suffix encoding.
  • Implement BYTE_STREAM_SPLIT (FLOAT/DOUBLE/INT32/INT64): byte-plane transpose.
  • Integrate all four into encoding_selector heuristic.

20.2 Detailed Implementation Steps

  • parquet_encoding::delta_binary: DeltaBinaryPackedEncoder { block_size: usize (default 128), miniblock_count: usize (default 4) }. Format: header (block_size, miniblock_count, total_value_count, first_value as zigzag varint); then per block: min_delta (zigzag varint) + per-miniblock bit_width (1 byte each) + miniblock values (bit-packed). encode_i64(values: &[i64], out: &mut Vec<u8>). Decode: inverse; handle zigzag for signed deltas; decode_i64(buf: &[u8], count: usize) -> Vec<i64>. (P13 DELTA_BINARY_PACKED spec §7; P9 Lemire bit-unpack SIMD; B4 Ch 3 zigzag; ADR-A04)
  • parquet_encoding::delta_len_ba: separate: encode all lengths as DELTA_BINARY_PACKED i32 array first; then concatenate all value bytes. Decode: decode length array → compute prefix sums → slice value bytes. (P13 DELTA_LENGTH_BYTE_ARRAY spec §8)
  • parquet_encoding::delta_byte_arr: compute shared prefix lengths between consecutive strings (prefix of values[i] shared with values[i-1]); encode prefix lengths as DELTA_BINARY_PACKED; encode suffixes as DELTA_LENGTH_BYTE_ARRAY; decode: reconstruct strings by prepending prefix from previous. (P13 DELTA_BYTE_ARRAY spec §9; B7 Ch 12 sorted string compression)
  • parquet_encoding::byte_stream_split: for FLOAT (4 bytes) and DOUBLE (8 bytes): transpose byte planes. For n values of type T (width W): output = [v0.bytes[0], v1.bytes[0], ..., vn.bytes[0], v0.bytes[1], ...]. Decode: detranspose. For INT32/INT64: same plane transpose (spec v2.0+). (P13 BYTE_STREAM_SPLIT spec §10; B3 Ch 2 byte-plane similarity improves entropy coding; ADR-A19)
  • encoding_selector: add heuristics — DeltaBinaryPacked for sorted/nearly-sorted INT columns (detect by checking if std_dev of deltas is < mean); DeltaByteArray for sorted string columns; ByteStreamSplit for FLOAT/DOUBLE (always better for snappy-compressed float data). (P3 Abadi late materialization + compression analysis; ADR-A19 selection heuristic; System Constraints decode throughput targets)
  • All four encodings wired into ColumnChunkWriter::flush_page dispatch on selected_encoding.
  • All four encodings wired into ColumnChunkReader decode dispatch on DataPageHeader.encoding.

20.3 Deliverable

  • delta_encoded_int64.parquet + byte_stream_split_float.parquet examples roundtrip correctly.
  • pqtool stats --encoding file.parquet shows encoding per column.
  • delta_binary_packed benchmark: ≥ 600 MB/s encode, ≥ 1 GB/s decode.

20.4 Acceptance Criteria

  • DELTA_BINARY_PACKED: property test with proptest — roundtrip i64 values (min, max, sorted, random): all pass.
  • DELTA_BYTE_ARRAY: roundtrip sorted strings; common-prefix strings (e.g., UUIDs): all pass.
  • BYTE_STREAM_SPLIT FLOAT: roundtrip 1M float32 values; compare file size vs PLAIN (typically 10–20% smaller when combined with ZSTD).
  • cargo fuzz run fuzz_delta_binary 100k iterations without panic.
  • delta_encoded_int64.parquet (parquet-mr generated) read by our reader: values match.

20.5 Conformance Fixtures

  • delta_encoded_int64.parquet — parquet-mr generated.
  • delta_byte_array_strings.parquet — parquet-mr generated sorted strings.
  • byte_stream_split_float.parquet — Arrow Rust generated.

20.6 Pitfalls

  • DELTA_BINARY_PACKED block boundary: block_size must be a multiple of 8; miniblock_count must divide block_size; miniblock_size = block_size / miniblock_count must be a multiple of 8 bits. Violations → malformed output.
  • DELTA_BINARY_PACKED last block padding: last block may have fewer than block_size values; pad with zeros for bit-packing; decoder uses total_value_count to stop, not block boundaries.
  • DELTA_BYTE_ARRAY prefix length > string length: corrupt input; clamp and return error; do not truncate silently.
  • BYTE_STREAM_SPLIT for non-width-aligned types: only valid for fixed-width types (FLOAT=4, DOUBLE=8, INT32=4, INT64=8, FIXED_LEN_BYTE_ARRAY=type_length); reject for BYTE_ARRAY.

20.7 Performance Concerns

  • DELTA_BINARY_PACKED decode: inner loop is bit-unpack then zigzag; SIMD-amenable for the miniblock decode; measure vs baseline.
  • BYTE_STREAM_SPLIT transpose: O(n × W) memory accesses; non-sequential for large n; cache miss pattern; consider blocking the transpose (B values at a time where B = L1/W).

20.8 Edge Cases

  • Zero-length value list: DELTA_BINARY_PACKED header with total_value_count=0; no blocks; decode returns empty.
  • All-identical values: delta = 0 for all; bit_width=0 for all miniblocks; very compact output.
  • Negative deltas: zigzag encoded; i64::MIN - i64::MIN = 0 (first delta = 0); handle first-value-as-zigzag-varint carefully.

20.9 Failure Analysis

  • DELTA_BINARY_PACKED decode overrun: reading more miniblock bytes than available → BitReader returns None → propagate as Error::MalformedPage. Fuzz harness catches this.
  • BYTE_STREAM_SPLIT size mismatch: compressed payload length not divisible by type_width → return Error::MalformedPage{reason: "byte_stream_split_size"}.

21. Phase 9 — ORC Stripe Model: Reader and Writer

21.1 Objectives

  • Implement orc_codec crate: postscript + file footer parse, stripe navigation, column stream decode (PRESENT/DATA/LENGTH/DICTIONARY_DATA), integer RLEv2 all four sub-encodings.
  • Implement OrcWriter: stripe flush at configurable row threshold, stripe footer, file footer + postscript seal.
  • Basic type support: INT, BIGINT, STRING, BOOLEAN, FLOAT, DOUBLE, TIMESTAMP, DATE.
  • Differential test: write with our ORC writer; read with orc crate (reference); values match.

21.2 Detailed Implementation Steps

  • orc_codec::postscript: read from EOF − 1 (PS length byte), read PS length bytes, Protobuf decode PostScript {footer_length, compression, compression_block_size, version, metadata_length, magic}. (P12 ORC spec §2 postscript; ADR-A07 prost; ADR-A22 separate crate)
  • orc_codec::file_footer: seek to file_len − PS_length − 1 − footer_length; decompress (per compression codec in PS); Protobuf decode Footer {header_length, content_length, stripes, types, metadata, number_of_rows, statistics, row_index_stride}. (P12 ORC spec §3 footer; ADR-A07)
  • orc_codec::rle_v2: four sub-encodings detected by 2-bit header in first byte: 00 = SHORT_REPEAT, 01 = DIRECT, 10 = PATCHED_BASE, 11 = DELTA. (P12 ORC spec §5 RLEv2; R3 C++ reference impl)
    • SHORT_REPEAT: repeat count (3–10) of fixed-width value (1–8 bytes).
    • DIRECT: bit_width (5-bit encoded via 1-based encoding table) + length (9-bit) + bit-packed values.
    • PATCHED_BASE: bit_width + length + base value (varint) + bit-packed base-adjusted values + patch list (outliers encoded separately).
    • DELTA: base value (varint) + delta (zigzag) + fixed_delta (0=all same delta) or bit-packed delta adjustments.
  • orc_codec::stream: StreamReader { kind: OrcStreamKind, column_id: u32, compressed_data: Vec<u8>, codec: OrcCompressionCodec } — ORC compression is per-stream (not per-page); each stream has concatenated chunks of (compressed_flag: bool, length: u24) + length bytes.
  • PRESENT stream: RLEv2 decode of booleans (byte-packed: 8 bools per byte); yields null bitmap.
  • DATA stream: RLEv2 decode for INT/BIGINT; raw bytes for FLOAT/DOUBLE; RLEv2 for lengths in STRING; DICTIONARY_DATA stream for dict strings.
  • OrcReader::open: read postscript, file footer, build Vec<StripeInformation>, build type tree.
  • OrcReader::read_stripe(idx): seek to stripe offset; read row index (if present); parse stripe footer; build stream map; for each column: open PRESENT + DATA streams; decode values.
  • OrcWriter::new(schema, config): init; write_stripe(batch): buffer rows; when num_rows ≥ stripe_row_count (default 1M), flush: encode streams, write stripe data, write stripe footer (Protobuf), update StripeInformation.
  • OrcWriter::close(): write file footer (Protobuf), write postscript, write 1-byte PS length.

21.3 Deliverable

  • orc_roundtrip.rs example: write 1M INT64 rows; read back; values match.
  • pqtool schema --format=orc file.orc prints ORC type tree.
  • Our ORC writer output readable by Apache ORC C++ reader without error.

21.4 Acceptance Criteria

  • RLEv2: all four sub-encodings round-trip for INT64 (min, max, sorted, random, all-same): all pass.
  • PRESENT stream: null bitmap roundtrip for 50% null column: all pass.
  • basic_stripe.orc (Apache ORC reference) read by our reader: values match.
  • Our written ORC file read by Apache ORC orc-tools without error.
  • cargo fuzz run fuzz_orc_postscript 50k iterations without panic.

21.5 Conformance Fixtures

  • basic_stripe.orc — Apache ORC reference file.
  • orc_all_types.orc — Apache ORC reference with all types.
  • orc_null_heavy.orc — PRESENT stream exercise; 70% nulls.

21.6 Pitfalls

  • ORC compression chunks vs Parquet page compression: ORC compresses per-stream in fixed-size chunks (default 256 KB); each chunk has a 3-byte header (1 bit = original/compressed, 23 bits = length); NOT per-row-group.
  • RLEv2 DIRECT bit_width encoding: stored as (bit_width - 1) in 5 bits using the ORC encoding table (not raw bit width); table: 0=1, 1=2, ..., 23=24, 24=26, 25=28, ...; must use exact table.
  • ORC type system vs Parquet: ORC types are in a flat list with parent_index links (not a tree); LIST is type list with child subtype; MAP has key + value subtypes; unlike Parquet's schema element DFS.
  • Stripe footer before file footer: each stripe has its own stripe footer immediately after the stripe data; the file footer is at the end; don't confuse the two.

21.7 Performance Concerns

  • ORC per-stream decompression: many small streams per stripe; I/O coalescing critical; consider reading entire stripe in one seek + buffer in memory.
  • RLEv2 PATCHED_BASE: rare but complex; patch list adds random-access cost; profile separately.

21.8 Edge Cases

  • Stripe with 0 rows: valid; skip stream reads; StripeInformation.num_rows = 0.
  • Column present but all-null: PRESENT stream all zeros; DATA stream absent (ORC allows omitting DATA for all-null); reader must handle absent DATA stream.
  • Single-row stripe: num_rows = 1; valid; all sub-encodings must handle.

21.9 Failure Analysis

  • Protobuf decode failure (ORC footer): corrupted ORC file or wrong file type; prost returns error; OrcReader::open returns Error::Io with context. No recovery; file is unusable.
  • Stripe offset overflow: StripeInformation.offset + stripe_length > file_length; detect at open; return Error::OffsetOutOfBounds.

22. Phase 10 — Vectorized Reader + Projection Pushdown + I/O Coalescing

22.1 Objectives

  • Implement batch-oriented ColumnChunkReader::read_batch(n) returning DecodedColumn<T> of up to n rows; amortize decode overhead over batches (default batch size 4096 rows).
  • Implement projection pushdown: ParquetReader::open_with_projection(schema_columns: &[&str]) — only read + decode the projected columns; skip all other column chunks.
  • Implement I/O coalescing: given a list of (offset, length) byte ranges required for projected columns in a row group, merge adjacent ranges (within a configurable gap threshold = 1 MB) into single reads.
  • Implement multi-row-group parallel scan interface: ParquetReader::scan_parallel(pred, proj) -> impl Iterator using caller-provided rayon::ThreadPool.

22.2 Detailed Implementation Steps

  • ColumnChunkReader::read_batch(batch_size: usize) -> Result<Option<ColumnBatch<T>>, Error>: state machine; maintains page_iter position; decompresses + decodes pages accumulating batch_size values; if page exhausted, advance to next page; returns None when column chunk exhausted. (P5 MonetDB/X100 vectorized model; P11 Flare batched scan; ADR-A16 external parallelism)
  • ColumnBatch<T> = DecodedColumn<T> with explicit row_count: usize; Dremel assembly runs on the batch before returning. (P1 assembly FSM; System Constraints thread model single-threaded codec)
  • Projection: ProjectionPlan { columns: Vec<ColumnDescriptor> } computed from requested column names against FileMetaData.schema_root; when navigating a RowGroupDescriptor, only ColumnChunkDescriptors for projected columns are opened; byte ranges for other columns are skipped. (P4 C-Store projection pushdown; P3 Abadi late materialization; System Constraints memory per open reader ≤ 32 MB)
  • I/O coalescing: struct ReadRequest { offset: u64, length: u64 }; sort by offset; merge if next.offset - (prev.offset + prev.length) ≤ coalesce_gap_bytes; issue single read_at(offset, merged_len) then slice from buffer. Implement CoalescingReader<R: Read+Seek> wrapper. (B5 Ch 9 I/O coalescing; System Constraints 1 FD per open file; ADR-A06 sync I/O)
  • CoalescingReader API: add_range(offset, len, tag: usize); execute() -> Vec<(tag, Vec<u8>)>; reads all ranges in one or few seeks; distributes to tagged callers. (R4 DuckDB coalescing scan; ADR-A06)
  • Multi-row-group scan: ParquetReader::scan_row_groups(indices: &[usize], proj: ProjectionPlan, pred: Option<PredicatePushdown>) -> Vec<Result<RecordBatch, Error>> — returns one result per row group; caller may rayon::par_bridge().
  • RecordBatch type: struct RecordBatch { schema: Arc<SchemaNode>, columns: Vec<Box<dyn AnyColumn>>, num_rows: usize } — type-erased columnar batch; AnyColumn::downcast::<T>().
  • Projection plan caching: parse column paths once at open time; cache HashMap<Vec<String>, usize> for O(1) column lookup.
  • ReaderConfig fields: batch_size: usize (default 4096), coalesce_gap_bytes: u64 (default 1 MB), prefetch_column_count: usize (default = all projected columns).

22.3 Deliverable

  • 100-column file; project 2 columns; measure I/O bytes read ≤ 3% of total file (2 columns / 100 = 2%, plus footer and coalesced overhead).
  • Vectorized decode throughput: INT64 column, 1 row group, 10M rows, batch_size=4096 → ≥ 2 GB/s.
  • pqtool dump --columns col1,col2 only reads 2 column chunks.

22.4 Acceptance Criteria

  • Projection: reading 2/100 columns reads ≤ 5% of file bytes (measured via CoalescingReader byte counter).
  • Batch decode: 10M INT64 rows in batches of 4096: total decode ≥ 2 GB/s; no correctness errors.
  • Dremel assembly for batch: nested LIST column, batch_size = 4096 → correct records per batch; no cross-batch state corruption.
  • I/O coalescing: 5 adjacent column chunks within 500 KB gap → merged into 1 read; verified by mock I/O counter.

22.5 Conformance Fixtures

  • wide_100_columns.parquet — 100-column file; projection test; generated by parquet-mr.
  • batch_nested.parquet — nested LIST column; batch reading; cross-page boundary records.

22.6 Pitfalls

  • Dremel state across batches: AssemblyFSM must be persistent across read_batch calls within a column chunk; do not reset FSM per batch; records can span batch boundaries.
  • Column chunk skip with non-seekable reader: CoalescingReader requires seekable I/O; for streaming (non-seekable) sources, skip must consume (not seek) skipped bytes; add SkippingReader fallback.
  • Batch boundary on repeated field: a record with 1000 LIST items and batch_size=4096 means a record can span multiple batches; assembly FSM must buffer partial records.
  • Type erasure overhead: Box<dyn AnyColumn> with dynamic dispatch; avoid in tight loops; concrete-typed ColumnBatch<T> is preferred for internal use; RecordBatch is for output only.

22.7 Performance Concerns

  • read_batch inner loop: the hot path; no allocations per row (pre-allocated level arrays, pre-allocated value buffer); amortized alloc per batch only.
  • CoalescingReader sort: O(n log n) on n = projected_columns; n ≤ 100 in practice; negligible.
  • SIMD decode opportunity: with batch_size=4096, decode loops over 4096 values → auto-vectorizer can operate; do not break vectorization with conditionals in inner loop.

22.8 Edge Cases

  • Last row group has fewer rows than batch_size: partial batch returned; ColumnBatch.row_count < batch_size; valid.
  • Projected column in some row groups only (schema evolution — column added in row group 5): row groups 0–4 return all-null for that column; handled by None column chunk in those row groups.
  • Empty projection (0 columns): valid; returns RecordBatch with 0 columns but correct num_rows; used for COUNT(*) queries.

22.9 Failure Analysis

  • Batch decode count mismatch: after all batches from a column chunk, total_values_decoded must equal ColumnChunkDescriptor.num_values. Mismatch → Error::RowCountMismatch. Detection: assertion in ColumnChunkReader::close.
  • I/O coalescing reads wrong bytes: merged read at wrong offset → all projected columns in the merged range decoded incorrectly. Prevention: unit test coalescing logic with mock reader that validates requested offset/length pairs.

Mental Models & First Principles

The compressed intuitions an expert holds about columnar codecs. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — A column chunk is a sorted run in disguise. Even without explicit sort keys, values in one column in one row group cluster: low-cardinality strings collapse onto dict pages, timestamps increment monotonically, NULL/non-NULL status clusters by write time. Predicts: statistics-based pruning is highly effective even on "unsorted" files; an encoding selector should check delta variance before committing to PLAIN. Bug without it: choosing PLAIN for INT64 columns that are 80% monotone, leaving DELTA_BINARY_PACKED savings on the table. Applied: Phase 8 §20.2 (encoding_selector delta std-dev heuristic), Phase 6 §18.2 (predicate skip ratios), P3.
  • MM2 — The footer is the index; the pages are the data. FileMetaData (the Thrift footer) carries all structural metadata — schema, row-group boundaries, per-column offsets, statistics, PageIndex offsets. No byte of page data is needed to answer "can this row group be skipped?" Predicts: open-time cost is dominated by footer parse + PageIndex load; per-page cost is dominated by decompression + decode; predicate evaluation is a pure footer operation. Bug without it: eagerly reading page bytes before evaluating statistics, eliminating all I/O savings. Applied: ADR-A21 (eager PageIndex parse), Phase 6 §18.2 (predicate before seek), Phase 7 §19.2 (ColumnIndex loaded at open).
  • MM3 — Dremel levels are a lossless serialization of a tree path, not a value attribute. Repetition level R encodes "which repeated ancestor started a new instance"; definition level D encodes "how deep the path is defined". Both derive from schema structure, not from the value. Predicts: max_rep and max_def are schema constants, computable once at open time; any value with D = max_def is non-null regardless of its numeric value. Bug without it: recomputing max_rep/max_def per page (slow, drift-prone); misreading D=0 as "value is zero" instead of "outermost optional field is absent". Applied: Phase 3 §15.2 (parquet_core::dremel), ADR-A18 (precomputed levels in SchemaNode), §8.5 worked example.
  • MM4 — Compression operates on byte similarity, not semantic meaning. Column layout clusters similar bytes (all INT64 values for one column in one row group are contiguous), maximizing the run-length and entropy reduction ZSTD/Snappy exploit; BYTE_STREAM_SPLIT further raises byte-plane similarity for IEEE-754 floats by grouping exponent bytes. Predicts: a columnar file with ZSTD compresses 5–10× better than the same data row-oriented with ZSTD. Bug without it: applying BYTE_STREAM_SPLIT to BYTE_ARRAY (variable width — no byte planes) causing a decode error, or leaving PLAIN on float columns that BYTE_STREAM_SPLIT would shrink 15–20%. Applied: Phase 4 §16.2 (codec integration), Phase 8 §20.2 (BYTE_STREAM_SPLIT selector), B3.
  • MM5 — Statistics are a one-sided proof of absence. If a predicate is inconsistent with a row group's min/max/null_count, that row group provably has zero matches; if consistent, it may or may not match — statistics cannot prove presence. So false negatives (skipping a matching group) are catastrophic data loss; false positives (reading an unmatching group) are merely wasted I/O — statistics must err toward inclusion (widen, never narrow). Predicts: a writer that fails to update max after a late large value silently drops row groups at query time. Bug without it: tightening statistics below the true range → silent wrong query results. Applied: Phase 6 §18.9 (I6/I7, P2), Phase 11 §23.2 (pqtool verify --statistics).
  • MM6 — Dictionary encoding is a two-pointer structure with a fallback seam. A dict-encoded column chunk is a pair (dict_page: Vec<T>, data_pages: Vec<u32 indices>) with the invariant that every index ∈ [0, dict_size). The seam is the fallback threshold: once the dict fills, the writer flushes the partial dict, switches to PLAIN, and the reader must decode both encodings in sequence transparently. Predicts: a conformance corpus must include a file that crosses the threshold mid-chunk; a reader assuming "all dict or all plain" silently corrupts the tail. Bug without it: applying dict-index lookup to PLAIN bytes in a mixed-encoding chunk → wrong values or panics. Applied: Phase 2 §14.2 (fallback path, ADR-A17), §14.6 pitfalls, I8.
  • MM7 — Thrift compact protocol is field-ID delta-encoded, not schema-driven. Field IDs are encoded as deltas from the previous ID; a stop byte (0x00) terminates a struct; unknown IDs must be skipped, not rejected. Predicts: forward compatibility is free if you skip unknowns; backward compatibility requires treating absent optional fields as defaults. Bug without it: hard-coding field-ID arithmetic that breaks when a new optional field is inserted between two existing ones (the delta shifts for every later field), crashing on files from a newer parquet-mr. Applied: Phase 0 §12.2 (shared::thrift_compact), Phase 5 §17.2 (full FileMetaData), ADR-A03, P7.
  • MM8 — The split-block Bloom filter is a SIMD-friendly set-membership test. Parquet's filter is not a standard k-hash Bloom: the hash selects a 256-bit block, then 8 probes run within that block via a fixed salt array, all fitting one cache line so the 8 probe results AND together under SIMD. Predicts: any miss in the 8 probes is a definitive "not present" (no false negatives); FPP is set by filter size; the implementation must use Parquet's exact salt constants or be incompatible with parquet-mr. Bug without it: using a generic Bloom crate (different hash/probe pattern) → filters written by parquet-mr are meaningless and I14 is violated. Applied: Phase 7 §19.2 (parquet_core::bloom_filter), ADR-A20, P6/P7.
  • MM9 — ORC stripes and Parquet row groups solve the same problem differently. Both are horizontal partitions enabling column-parallel I/O; the difference is compression granularity — ORC compresses at the stream level (per-column byte streams in configurable chunks) while Parquet compresses at the page level (each encoded page independently). Predicts: for narrow projections Parquet's per-page layout enables tighter I/O coalescing; for wide reads ORC's stream-level layout decompresses sequentially in one pass. Bug without it: applying Parquet per-page decompress logic to ORC streams (which have no page headers — a flat compressed byte stream). Applied: Phase 9 §21.6 (ORC stripe reader, ADR-A22), Comparative Architecture.
  • MM10 — Offset arithmetic is the root of all Parquet corruption bugs. Every structural element — footer byte range, row-group extent, column-chunk start, page start — is an absolute file offset; an off-by-one seeks to the wrong location and the wrong bytes silently decode as valid Thrift or page data, producing garbage rather than an error. Predicts: offset bugs rarely crash (Thrift is lenient; random bytes often decode as valid varints) — they manifest as silent wrong values. Bug without it: recording dict_page_offset after writing the dict header rather than before → every dict decode starts on the wrong byte → silent corruption. Applied: Phase 1 §13.2 (footer offset tracking), Phase 5 §17.2 (WriteCounter<W>), I3/I4/I5, P3.

Apache Parquet (parquet-mr / Arrow): The canonical implementations establish the reference for encoding correctness and file compatibility. parquet-mr made the deliberate choice to couple encoding logic with the JVM runtime, which simplifies development but adds GC pressure in tight scan loops. Arrow's C++ Parquet reader decouples the codec from the execution engine via the Arrow memory model, winning for high-throughput OLAP where zero-copy columnar buffers can flow directly into vectorized operators. This design wins over Arrow when no_std embedding is required or when the caller must control all allocations.

Apache ORC (orc-core): ORC chose stream-level compression over page-level compression and RLEv2 over Parquet's hybrid RLE. Stream-level compression wins for wide-table sequential reads where merging many tiny page decompressions into one large stream decompression reduces overhead. RLEv2's PATCHED_BASE sub-encoding handles integer columns with outliers more efficiently than Parquet's DELTA_BINARY_PACKED. ORC wins in Hive-centric pipelines and for ACID delta-merge workloads. This design's Parquet track wins for portability and ecosystem breadth; the ORC track is the secondary format precisely because both niches are worth covering.

DuckDB Parquet Scanner: DuckDB embedded its Parquet reader directly inside a query engine, gaining deep integration with the vectorized operator pipeline (filter evaluation happens during decode, not after). It does not expose a standalone library API. DuckDB wins for single-binary analytics where the user runs SQL directly on files. This design wins when the caller needs a linkable library that integrates with its own query engine without shipping an embedded DuckDB.

Delta Lake / Iceberg (table layer): These are not file format implementations but table format layers that sit above Parquet. They add MVCC snapshots, schema evolution as first-class features, partition pruning, and file-level skip from manifests. Delta/Iceberg win when multi-writer consistency and time-travel queries are required. This design is what those layers call at the data-file layer — they depend on a Parquet codec like this one.

Back-of-Envelope Capacity Model

Numbers an expert computes from §4 (System Constraints) before designing; each is derived and names its §4 input. Variables: T = §4 decode throughput (PLAIN INT64, uncompressed) ≥ 2 GB/s/thread; T_z = §4 ZSTD L1 + RLE_DICTIONARY ≥ 400 MB/s/thread; RG = §4 row-group size = 128 MB uncompressed; P = §4 page buffer = 1 MB uncompressed; M = §4 memory per open reader ≤ 32 MB; F = §4 footer parse latency ≤ 2 ms / 1 MB footer.

  • C1 — Single-thread scan throughput (PLAIN INT64, uncompressed). Input: §4 T (≥ 2 GB/s) + INT64 width 8 B. rows/s = T / bytes_per_value = 2 GB/s ÷ 8 B = 250 M rows/s. A 1 B-row INT64 column takes ≈ 4 s on one thread; 8 threads (caller-partitioned, ADR-A16) → ≈ 0.5 s.
  • C2 — Single-thread scan throughput (ZSTD + RLE_DICTIONARY, INT64). Input: §4 T_z (≥ 400 MB/s) + 8 B width. rows/s = T_z ÷ 8 B = 400 MB/s ÷ 8 = 50 M rows/s. Compression is 5× slower per row than uncompressed → the codec, not the decode loop, is the bottleneck on compressed files.
  • C3 — Row groups per file for a 1 TB dataset. Input: §4 RG (128 MB). num_rg = file_size ÷ RG = 1 TB ÷ 128 MB = 8,192 row groups. Footer grows O(num_rg × num_columns); for 100 columns: 8,192 × 100 × ~200 B/column-chunk-metadata ≈ 164 MB (pathological — partition files first to keep the footer < 10 MB).
  • C4 — Footer parse budget for 10k row groups × 100 columns. Input: §4 F (≤ 2 ms / 1 MB). footer_bytes = 10,000 × 100 × 200 B = 200 MB; at a Thrift-compact field-ID decode rate ≈ 500 MB/s → 200 MB ÷ 500 MB/s = 400 ms, far over the 2 ms target. Conclusion: > ~500 row groups at 100 columns needs split-file partitioning; §4's 1 MB/2 ms budget is calibrated for ≤ ~50 row groups × 100 columns.
  • C5 — Memory for footer + schema at open. Input: §4 M (≤ 32 MB) + §4 max columns (1,000). schema_nodes ≈ 1,000 × 512 B = 512 KB; row_group_metadata ≈ num_rg × num_columns × 80 B; for 100 RG × 100 col = 800 KB. Total ≈ 512 KB + 800 KB + PageIndex ≈ 5 MB — well within the 32 MB M budget.
  • C6 — PageIndex memory per row group (100 columns × 128 pages). Input: §4 M + §4 page buffer P (1 MB → ~128 pages/128 MB RG). per_page_entry ≈ 2×min_max + 8 B null_count + 12 B PageLocation ≈ 60 B; 100 col × 128 pages × 60 B = 768 KB/RG; 10 row groups loaded → 7.68 MB, fits the 32 MB M budget.
  • C7 — Bloom filter memory budget. Input: §4 Bloom max size (128 KB/column chunk) + §4 FPP (1%). num_bytes = ceil(−n × ln(0.01) ÷ ln(2)²) = ceil(n × 9.585 bits ÷ 8). For n = 1 M (§4 dict cardinality threshold): ≈ 1.2 MB — exceeds the 128 KB cap, so Bloom is capped, raising FPP on high-cardinality columns; 100 columns × 128 KB = 12.8 MB worst case.
  • C8 — Effective FPP at the 128 KB cap for n = 1 M entries. Input: §4 Bloom max size (m = 128 KB × 8 = 1,048,576 bits) + 8 probes. FPP = (1 − e^(−k·n/m))^k; k·n/m = 8 × 10⁶ ÷ 1,048,576 ≈ 7.63; FPP = (1 − e^{−7.63})^8 ≈ 99.6% — near-useless. Conclusion: Bloom is effective only at ≤ ~100 K distinct values per row group; the design disables it for high-cardinality columns.
  • C9 — I/O savings from predicate pushdown at 1% selectivity. Input: §4 row-group skip ratio (≥ 95%) + §4 page skip ratio (≥ 80%). bytes_read = file_size × (1 − skip) = 1 TB × 0.05 = 50 GB (20× reduction vs full scan); add page-level skip on a sorted column: 50 GB × 0.20 = 10 GB effective I/O for a 1% point query.
  • C10 — Dict cardinality threshold vs page size. Input: §4 dict cardinality fallback (≤ 1 M or ≥ 50% of page) + §4 page buffer P (1 MB). At 1 M BYTE_ARRAY entries × (4 B length + 20 B) = 24 MB dict page — 24× over P. Conclusion: the threshold must enforce a byte cap too; the "≥ 50% of page" rule fires at P ÷ avg_value_size = 1 MB ÷ 24 B ≈ 43 K distinct 20-byte values, long before the 1 M entry count.
  • C11 — CRC-32C verification headroom. Input: §4 CRC rate (≈ 4 GB/s hardware) + §4 T (2 GB/s). crc_fraction_of_decode = T ÷ crc_rate = 2 GB/s ÷ 4 GB/s = 0.5 → CRC adds ≤ 50% to PLAIN decode time; on the ZSTD path T_z ÷ crc_rate = 400 MB/s ÷ 4 GB/s = 0.1 → ≤ 10% overhead (negligible).
  • C12 — File-descriptor pressure. Input: §4 FD usage (1 FD/open file, ADR-A06). A file-parallel scan over 1,000 Parquet files holds 1,000 FDs; Linux default ulimit -n = 1,024. Implication: operators must raise ulimit -n to ≥ 2 × num_files; no internal multi-FD pre-read is used (§4 thread model).

Alternative Architectures (Roads Not Taken)

Fundamentally different ways to build a durable columnar codec for the same goal. Each: sketch, winning regime, the real system embodying it, why this blueprint rejected it.

A1 — Row-oriented page layout with a column metadata index. Values are stored row-major in pages; a side index maps each column to its byte offsets.

┌─────────────────────────────────────────────────────────┐
│  File Header                                            │
├─────────────────────────────────────────────────────────┤
│  Row Page 0: [col0_val, col1_val, col2_val, ...]        │
│  Row Page 1: [col0_val, col1_val, col2_val, ...]        │
│  ...                                                    │
├─────────────────────────────────────────────────────────┤
│  Column Offset Index: col_id → list of page offsets     │
│  Footer: schema + page index                            │
└─────────────────────────────────────────────────────────┘
  • Wins: write-heavy workloads with high row-update frequency (OLTP-style appends where every column of a row is written together) — row layout removes the column-fan-out write amplification of flushing 100 column chunks per row group.
  • Real system: PostgreSQL heap file format (row-oriented pages) with a separate BRIN index for column min/max metadata.
  • Rejected because: analytical queries project 2–5 of 100 columns; row layout reads all 100 columns' bytes to materialize 5 → 20× I/O amplification, versus 2–5% for columnar projection. P3 (Abadi et al., Column-Stores vs Row-Stores) is the authoritative quantification; the blueprint targets an OLAP-grade format, for which row layout is the wrong physical design.

A2 — Log-structured columnar format (LSM-style). Columns are written as immutable per-column SSTables at L0 and merged into sorted, larger SSTables by background compaction.

┌─────────────────────────────────────────────────────────┐
│  L0 SSTables (recent, uncompacted, small)               │
│    col_a_0.col, col_b_0.col, col_c_0.col               │
│  L1 SSTables (compacted, sorted within column)          │
│    col_a_1.col (sorted), col_b_1.col, ...               │
│  Bloom filter per SSTable + sparse index                 │
│  Manifest JSON: active SSTables per column              │
└─────────────────────────────────────────────────────────┘
Reads: merge-scan across levels; latest version wins.
Writes: append to L0; background compaction to L1+.
  • Wins: streaming ingestion with frequent small writes (IoT, CDC) where immutable append-only row groups would produce thousands of tiny files; LSM amortizes write cost through compaction and offers point-delete/upsert without rewriting whole row groups.
  • Real system: Apache Kudu (columnar LSM storage engine); Cassandra SSTables (row-oriented LSM, same write path).
  • Rejected because: LSM requires a compaction daemon, a manifest, multi-version concurrency, and a merge-read path — all well beyond "bytes-on-disk codec," and the blueprint explicitly non-goals the table-format and compaction layers (#214 Iceberg/Delta). A Parquet file from this codec managed by Iceberg achieves the same streaming-ingest + ACID result without embedding compaction in the codec.

A3 — Arrow IPC file format as the unified columnar format. The in-memory Arrow layout is written verbatim to disk; reads memory-map and zero-copy slice into buffers with no decode step.

┌──────────────────────────────────────────────────────────┐
│  Arrow IPC Magic: ARROW1                                 │
│  Schema message (FlatBuffers): field types + metadata    │
│  RecordBatch 0: buffers (validity, offsets, data)        │
│  RecordBatch 1: ...                                      │
│  Footer (FlatBuffers): RecordBatch offsets + schema; EOS │
└──────────────────────────────────────────────────────────┘
R/W memory-mapped; in-memory layout IS the file layout.
  • Wins: in-process or same-host columnar exchange at memory speed (shuffle between co-located processes, Python↔Rust IPC, shared-memory zero-copy); throughput is bounded by memcpy (~50 GB/s), not codec speed, because there is no encode/decode.
  • Real system: Apache Arrow IPC file format (.arrow); Apache Arrow Flight (Arrow IPC over gRPC).
  • Rejected because: Arrow IPC trades compression for zero-copy — a 100 GB Parquet file with ZSTD + DELTA_BINARY_PACKED is ~10 GB on disk, the Arrow IPC equivalent ~100 GB. For durable object-store lake storage that 10× drives storage cost and transfer time directly; the blueprint targets a bytes-on-disk codec requiring compression. Arrow IPC is the complementary in-memory layer (#395), not a substitute for Parquet at rest.

A4 — Avro with column reordering (row-columnar hybrid). Avro container blocks carry rows, with fields reordered at write time so each column's values are contiguous within a block.

┌──────────────────────────────────────────────────────────┐
│  Avro file header: schema (JSON), codec, sync marker     │
│  Block 0: N rows, Avro binary                            │
│    (reordered: all col0 values first, then col1, ...)    │
│  Sync marker; Block 1: ...                               │
│  No footer; schema in header only                        │
└──────────────────────────────────────────────────────────┘
Column reordering is a write-time convention, not a spec feature.
  • Wins: schema-registry-driven pipelines (Confluent Schema Registry, event streaming) where every producer/consumer is already Avro and adding Parquet writers means a second SDK; Avro's schema-in-header simplifies streaming deserialization without a footer read, and for narrow schemas (3–5 fields) the simplicity beats Parquet's optimization overhead.
  • Real system: Apache Avro container files (heavy in Kafka pipelines); Confluent Platform Avro serializer.
  • Rejected because: Avro has no native columnar storage — reordering is an unofficial convention readers cannot exploit without custom logic — and no statistics, page index, Bloom filter, or file-level predicate pushdown, so analytics over large files degrade to full scans. The blueprint targets OLAP I/O efficiency; Avro is the right format for streaming event encoding, not analytical storage.
