ADR-01

Language

Chosen

Rust 1.78+, edition 2021

Rejected

C, C++, Go, Zig

When the rejected choice is right

a hard real-time, certified-toolchain embedded target (ASIL-D automotive) mandating a qualified C compiler

Why: memory safety, borrow-checker-enforced secret handling, audited crate ecosystem

ADR-02

Runtime model

Chosen

no_std core crates

Rejected

std-only

When the rejected choice is right

a server-only deployment where std's allocator/threading simplify async integration and no_std adds no value

Why: embeds in bootloaders/HSM firmware/WASM

ADR-03

Field representation

Chosen

Bernstein-Lange radix-2⁵¹, 5×u64

Rejected

radix-2^25.5 10-limb 32-bit-native, saturated radix-2⁶⁴

When the rejected choice is right

a 32-bit target (Cortex-M0) where 64-bit multiplies are emulated and the 10-limb layout is faster

Why: matches curve25519-dalek::FieldElement51; fewer carries per multiply on 64-bit targets

ADR-04

Curve form for signing

Chosen

Twisted Edwards (a=-1)

Rejected

Weierstrass

When the rejected choice is right

interop with a toolchain (HSM/hardware wallet) that only implements NIST P-256 Weierstrass and Ed25519 is not an option at all

Why: complete addition law, no exceptional cases (Bernstein-Lange 2007, Hisil et al. 2008)

ADR-05

Curve form for DH

Chosen

Montgomery x-only

Rejected

Edwards-direct DH

When the rejected choice is right

a protocol needing the y-coordinate mid-exchange without a birational round-trip — libsodium's optional Edwards-DH path

Why: x-only ladder skips the y-coordinate, halves field ops (Bernstein 2006)

ADR-06

Scalar-mult family

Chosen

Montgomery ladder + fixed-base comb + Straus double-scalar, all constant-time

Rejected

fixed-window non-constant-time double-and-add

When the rejected choice is right

a feature-gated, never-shipped benchmarking build measuring the raw field-op cost ceiling

Why: side-channel closure (P2, T1)

ADR-07

Verification default

Chosen

strict (RFC 8032 section 5.1.7); lax-verify feature opt-in

Rejected

lax-only

When the rejected choice is right

interop with a legacy pre-2019 verifier already accepting lax-encoded signatures on-chain, for reads only, never new signing

Why: Chalkias et al. 2020 malleability corpus

ADR-08

Cofactor handling

Chosen

cofactor-aware [8h]A+[8R]-[8s]B

Rejected

cofactor-naive hA+R-sB

When the rejected choice is right

a protocol that already rejects all eight-torsion components at decode time, making the multiply redundant — some HSM firmwares skip it there

Why: closes small-subgroup confusion (Chalkias et al. 2020, Brendel et al. 2021)

ADR-09

Nonce generation

Chosen

deterministic, SHA-512(prefix‖msg) mod L

Rejected

hedged/RFC-6979-style, pure random

When the rejected choice is right

a signer under a fault-injection threat model (smart-card glitching) where a hedged (deterministic+fresh-randomness) nonce closes fault-induced reuse pure determinism does not

Why: LadderLeak (Aranha et al. 2020) shows nonce bias is catastrophic

ADR-10

When the rejected choice is right

a code-size-constrained IoT target where the explicit table costs ~200 B of .rodata deemed unaffordable

Why: defense-in-depth, catches small-subgroup keys before the ladder

38. Alternative Architectures (Roads Not Taken)

Alt A — Formally-verified backend (HACL/Fiat-crypto-generated field arithmetic).*

Show the original text diagram
+------------------------------------------------------+
|  F* proof source --> OCaml/C extraction --> Rust FFI  |
|  shim, replacing crate `curve-field` at the boundary  |
+------------------------------------------------------+

Regime where it wins: certification-heavy deployments (browser TLS stacks, national crypto agencies) where a machine-checked proof of the field arithmetic's functional correctness and constant-time-ness outweighs the cost of a foreign toolchain and an FFI boundary. Real system: HACL* (Project Everest), integrated into Mozilla NSS and libsignal. Rejected here because it introduces an F*/OCaml build dependency this blueprint's Rust-only, cargo-only toolchain (ADR-01/02) is designed to avoid, and the proof pipeline is a multi-year investment orthogonal to shipping a correct, hand-audited implementation quickly (PhaseDeferred, §39).

Alt B — SIMD-batched vector backend as the primary (not optional) scalar-mult path.

Show the original text diagram
+------------------------------------------------------+
|  "batch of N contexts" scheduler --> N-lane vectorized|
|  field ops (AVX2/AVX-512/NEON), N independent scalar  |
|  multiplications processed in lockstep                |
+------------------------------------------------------+

Regime where it wins: a bulk-signing service (certificate-transparency log signer, a blockchain validator batch-verifying thousands of signatures per block) where aggregate throughput dominates and per-signature latency is irrelevant. Real system: the vectorized batch-verification techniques in Cloudflare's CIRCL library and BoringSSL's AVX2 curve25519 path. Rejected here because this blueprint targets a general-purpose library used inside single-signature-latency-sensitive paths (TLS handshake, SSH auth, §4's M1–M3) where per-call latency matters more than batch throughput, and mandatory SIMD would violate ADR-11's no-unsafe-in-core-crates principle.

Alt C — Cofactor-free group abstraction via Ristretto from Phase 0.

+------------------------------------------------------+
|  application code sees only RistrettoPoint/Scalar;    |
|  EdwardsPoint and the [8]-cofactor never surface       |
+------------------------------------------------------+

Regime where it wins: a protocol stack (OPAQUE, a zk-SNARK's Pedersen-commitment layer) that assumes a clean prime-order group and would otherwise re-derive cofactor-clearing logic at every call site. Real system: curve25519-dalek's ristretto module (used by opaque-ke); libsodium's crypto_core_ristretto255. Rejected here because RFC 7748/8032 (this project's chartered scope, §1) are defined directly over Edwards25519/Curve25519, not Ristretto — encoding, X25519, and Ed25519 wire formats are byte-incompatible with a Ristretto-first design, so building Ristretto-first would break RFC conformance; ADR-19 defers it instead (§39).
