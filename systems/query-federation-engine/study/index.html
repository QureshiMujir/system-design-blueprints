30. Mental Models & First Principles

  • MM1 — The Tail at Scale. Fan-out latency is bounded by the slowest participant, not the average · predicts p99 degrades disproportionately as source count grows · without it: no per-source timeout, one slow source hangs the whole query · applies in §18.
  • MM2 — Push What You Can Prove. Pushdown is only sound when declared capability matches source semantics exactly · predicts silent correctness bugs from assumed capabilities · without it: engineers push a filter a source can't actually apply correctly · applies in §14.
  • MM3 — Spill Is Steady-State, Not an Exception. Memory pressure under adversarial cardinality is expected, not rare · predicts under-invested spill/checksum code paths fail in production first · without it: spill is untested until an incident teaches the lesson · applies in §17.
  • MM4 — Leases With Fencing Beat Locks Under Partition. A time-bounded lease with a monotonic fencing epoch survives a network partition; a lock does not · predicts split-brain in any scheduler that skips the epoch · without it: two workers both believe they own a fragment · applies in §15.
  • MM5 — Determinism Must Be Structural, Not Disciplinary. Any wall-clock read anywhere eventually breaks replay · predicts intermittent, hard-to-reproduce divergence, never a clean failure · without it: "it worked in testing" nondeterminism bugs surface only in production · applies in §20.
  • MM6 — Schema IDs Are a One-Way Ratchet. Column IDs are a contract binding every in-flight and cached plan · predicts a "harmless" renumbering silently reads the wrong column · without it: schema evolution breaks consumers that never touched the migrating code path · applies in §19.
  • MM7 — Fail Closed Beats Fail Fast for Governance. An unevaluatable policy must deny, not error open · predicts a catalog outage during a security-sensitive window stays safe by default · without it: an exception handler silently becomes an authorization bypass · applies in §21.
  • MM8 — Cost Models Bound Regret, They Don't Predict Truth. Every cardinality estimate is wrong by some margin; the optimizer's job is a bounded-regret decision under a timeout · predicts any optimizer without a fallback path eventually hangs on an adversarial plan · without it: no plan B when statistics are absent or wrong · applies in §14.

5. Required Reading

Books

  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 5–12: replication, partitioning, distributed transactions; applied in §12 and §15.
  • Database System Concepts — Silberschatz, Korth & Sudarshan (2019), query-optimization chapters: relational algebra and cost estimation; applied in §14.
  • Database Internals — Alex Petrov (2019), entire: storage engine and execution internals informing statistics/catalog design; applied in §19.
  • Transaction Processing: Concepts and Techniques — Gray & Reuter (1992), concurrency-control chapters: lease/lock-based scheduling semantics; applied in §15.
  • Rust Atomics and Locks — Mara Bos (2023), entire: memory-ordering correctness for the scheduler's lock-free registry and memory tracker; applied in §15 and §16.
  • Systems Performance — Brendan Gregg (2020), observability chapters: latency analysis methodology (USE method, flamegraphs); applied in §28.
  • Site Reliability Engineering — Beyer, Jones, Petoff & Murphy (2016), incident-response chapters: availability budget and paging philosophy; applied in §24.

Papers

  • "Encapsulation of Parallelism in the Volcano Query Processing System" — Goetz Graefe, 1994, SIGMOD: the iterator (open/next/close) execution model behind the Operator trait; applied in §16.
  • "Dremel: Interactive Analysis of Web-Scale Datasets" — Melnik et al., 2010, VLDB: columnar distributed execution informing Arrow batch layout choice; applied in §16.
  • "MapReduce: Simplified Data Processing on Large Clusters" — Dean & Ghemawat, 2004, OSDI: distributed execution coordination and worker fault model informing fragment retry semantics; applied in §15.
  • "Spanner: Google's Globally-Distributed Database" — Corbett et al., 2012, OSDI: distributed coordination semantics and TrueTime informing the time-source discipline (P14); applied in §12.
  • "Presto: SQL on Everything" — Sethi et al., 2019, ICDE: the federation execution model this project's coordinator/scheduler/connector split most directly descends from; applied in §18.
  • "Efficient and Extensible Algorithms for Multi Query Optimization" — Roy, Ramamritham, Seshadri, Shenoy & Sudarshan, 2000, SIGMOD: cost-based rule application informing the optimizer's rule registry; applied in §14.
  • "Dynamo: Amazon's Highly Available Key-value Store" — DeCandia et al., 2007, SOSP: partial failure handling and retry/backoff discipline; applied in §18.
  • "The Tail at Scale" — Dean & Barroso, 2013, CACM: fan-out latency amplification motivating per-source timeouts; applied in §28.

Reference Implementations

  • trinodb/trino — study core/trino-main/src/main/java/io/trino/sql/planner: rule-based planning and connector SPI capability negotiation; pitfall: do not copy Trino's Java-object-per-row model; applied in §14 and §18.
  • apache/calcite — study core/src/main/java/org/apache/calcite/rel/rules: the rule-registry pattern for cost-based rewrites; pitfall: exhaustive RelOptRule matching can diverge, bound optimization time; applied in §14.
  • apache/arrow-datafusion — study datafusion/physical-plan/src: Arrow-native physical operator shapes; pitfall: DataFusion assumes a single-process runtime, no distributed exchange analog; applied in §16.
  • duckdb/duckdb — study src/execution/operator: vectorized pull-based operator execution; pitfall: single-node vectorization needs no network exchange operator, do not port verbatim; applied in §16.
  • apache/arrow — study cpp/src/arrow/ipc: the Arrow IPC wire format used for exchange and spill; applied in §16 and §17.
  • ClickHouse/ClickHouse — study src/Processors: distributed pipeline execution and processor-based backpressure; pitfall: MergeTree assumptions do not apply to a no-owned-storage engine; applied in §16.

RFCs / Specifications

  • Apache Arrow IPC Streaming Format — pins the record-batch framing used for exchange and spill; applied in §16 and §17.
  • Apache Parquet Format Specification — pins the columnar file format the Parquet connector reads; applied in §18.
  • OpenTelemetry Trace SDK Specification — pins the span/trace-context propagation contract; applied in §20.
  • RFC 9110 (HTTP Semantics) — pins the semantics gRPC-over-HTTP/2 (RFC 9113) builds on for the gateway's protocol translation; applied in §21.

Glossary (§36) · 49 terms · site-wide glossary

Fragment
an executable physical query unit dispatched to exactly one worker at a time (I3).
Pushdown
delegating filter/projection/aggregation/join/limit execution to a source (§8).
Spill
disk- or object-storage-backed overflow for a memory-bounded operator (§17).
Exchange
bounded inter-worker RecordBatch stream between execution fragments (§16).
Replay WAL
append-only deterministic execution log (§20, I2).
Coordinator
the query/session lifecycle authority (§12).
Connector
an isolated source-integration runtime (§18).
Operator DAG
the physical execution graph a fragment executes (§11).
Cardinality
an estimated or actual row count used by the optimizer (§14).
Admission Control
the throttling subsystem bounding concurrent query/fragment intake (§15, §21).
Stage
a grouped boundary of fragments sharing a logical pipeline step (§11).
Runtime Pool
an isolated async executor or process pool per connector type (P4).
Backpressure
bounded flow control preventing unbounded queue growth (P2).
Capability Negotiation
discovering a connector's declared pushdown capabilities (§11).
Replay Divergence
a mismatch between recorded and re-executed state during replay (§20).
Execution Lease
a time-bounded, fencing-epoch-backed worker ownership token (I7).
Trace Context
distributed observability metadata propagated with every fragment (I13).
Histogram Stats
per-column distribution statistics feeding cardinality estimation (§14).
Predicate Pushdown
remote filtering delegation to a connector (§8).
Vectorized Batch
an Arrow RecordBatch, the unit of columnar execution (§11).
ULID
a lexicographically sortable unique identifier used for query_id/fragment_id.
Fencing Epoch
a monotonically increasing token invalidating stale lease holders (§15.6).
Tenant Isolation
the guarantee that catalog/execution state never crosses tenant boundaries (I6).
RBAC
role-based access control policy evaluated by authz/metadata-catalog (§19, §21).
OIDC
OpenID Connect, the identity protocol authz validates tokens against (§21).
Checksum
a CRC32C integrity value validated before spill/WAL restore (I5, I2).
Catalog Snapshot
a versioned read-consistent view of the metadata catalog (I11).
Statistics Cache
the cached histogram/cardinality data feeding the optimizer (§19).
Join Reordering
cost-based rearrangement of join operator order (§14).
Cost Model
the function mapping a candidate plan to an estimated execution cost (§14).
Logical Plan
the pre-physical, source-agnostic operator DAG (§13).
Physical Plan
the cost-annotated, pushdown-resolved, fragment-ready plan (§14).
AST
the normalized abstract syntax tree produced by the parser (§13).
Semantic Validation
catalog-bound type and reference checking of the AST (§13).
Worker Pool
the autoscaled set of execution-engine processes running fragments (§16).
Heartbeat
the periodic worker liveness signal to the scheduler registry (§15).
Lease Expiry
the sole trigger for fragment reassignment (I7).
Retry Budget
the fixed, monotonically-consumed retry counter per fragment (I12).
Backoff Jitter
randomized retry delay preventing retry-storm synchronization (§15.6).
N-1 Compatibility
the guarantee that adjacent coordinator versions interoperate during rolling upgrades (P7).
Canary Rollout
a partial-traffic-percentage deployment stage ahead of full rollout (§21).
mTLS
mutual TLS authenticating coordinator/worker/gateway connections (ADR-17).
WAL Segment
a rotated, size/age-bounded slice of the replay WAL (§20.10).
Deterministic Replay
reconstructing an execution byte-for-byte from the WAL alone (P1).
Query Hash
a literal-independent stable hash of a normalized AST (§13).
Schema Version
the monotonically increasing catalog schema revision number (I11).
Column ID
the immutable positional identifier a plan uses to reference a column (I4).
Partition Pruning
eliminating non-matching source partitions before scan (§18).
Connection Pooling
per-connector, per-source-type reusable connection management (§18).
