Subsystem Responsibilities

sql-gateway/grpc-api (§21) — protocol translation, session multiplexing, admission control at the edge, rate limiting. Trust boundary: all external traffic terminates here; nothing downstream trusts client-supplied identity without an authz decision.

authz (§21) — OIDC token validation, RBAC policy evaluation, tenant binding. Failure mode: authentication bypass reaches the coordinator with an unauthenticated session context — P12 (fail closed) exists to prevent this.

coordinator (§12) — query lifecycle (QueryHandle, §11), session/tenant context, admission control, retry supervision, plan orchestration hand-off. Concurrency boundary: one coordinator instance owns a session's mutable state exclusively (P3); persistence boundary: execution metadata snapshots checkpoint to the metadata catalog before a query is acknowledged RUNNING.

parser+planner (§13) — SQL grammar (§5 SQL:2016 subset), AST, semantic validation against catalog, logical operator DAG.

optimizer (§14) — join reordering, cardinality estimation from the statistics service, pushdown capability negotiation against ConnectorCapability (§11), fragment parallelization hints.

scheduler (§15) — fragment placement onto workers, worker heartbeats, bounded admission queues, execution leases (I7), retry orchestration, cancellation propagation. Concurrency boundary: exactly one worker holds an active lease per fragment (I3).

execution-engine (§16) — Arrow RecordBatch operator pipeline (scan/filter/project/hash-join/ aggregate), exchange streams between fragments, memory tracking.

spill-engine (§17) — Arrow-IPC-encoded disk overflow for operators that would otherwise exceed their memory budget; checksum-validated restore (I5).

connector-sdk + connectors/* (§18) — per-source pushdown translation, protocol adaptation (wire protocol boundary — each connector process/thread pool is isolated per P4), retry policy, schema discovery.

metadata-catalog (§19) — schema registry, connector registry, capability metadata, statistics cache, governance policy metadata. Persistence boundary: PostgreSQL-backed (ADR-04), the only subsystem permitted to mutate durable schema/policy state.

telemetry + replay-engine (§20) — every box above emits traces/metrics/structured logs; replay-engine additionally taps coordinator/scheduler/execution-engine/connector-sdk event streams into an append-only WAL (I2) for deterministic reconstruction.

8. Domain Model — Query Lifecycle & Fragment Protocol

Query Lifecycle State Machine

RECEIVED -> PARSED -> OPTIMIZED -> SCHEDULED -> RUNNING -> COMPLETED
                                       |            |
                                       v            v
                                   CANCELLED     SPILLING -> RUNNING
                                       |            |
                                       v            v
                                    FAILED       FAILED
State Description Entered From Terminal?
RECEIVED accepted by sql-gateway/grpc-api, admission-controlled — no
PARSED AST built and semantically validated against catalog RECEIVED no
OPTIMIZED physical plan generated with cost annotations PARSED no
SCHEDULED fragments placed on workers, leases issued OPTIMIZED no
RUNNING active execution, streaming results SCHEDULED, SPILLING no
SPILLING memory pressure active, subset of RUNNING semantics RUNNING no
COMPLETED successful terminal state RUNNING yes
FAILED terminal failure state any non-terminal state yes
CANCELLED operator- or client-initiated cancellation any non-terminal state yes

I8 governs every arrow in this diagram: no edge exists from a terminal state, and no edge skips backward (SCHEDULED never returns to PARSED).

Connector Capability Model

Capabilities negotiated per source, declared in ConnectorCapability (§11) and enforced by I10: predicate pushdown, projection pushdown, aggregation pushdown, join pushdown, partition pruning, limit pushdown. The optimizer (§14) never emits a pushed-down operator a connector has not declared support for.

Failure Path Example — Connector Timeout

  1. connector runtime emits a timeout event on its isolated pool (P4),
  2. scheduler marks the owning fragment DEGRADED, decrements retry budget (I12),
  3. if retry budget remains, scheduler reissues a new lease (I7) and reschedules,
  4. if exhausted, coordinator transitions the query FAILED (I8) with the connector diagnostic attached,
  5. replay-engine emits a checkpoint capturing the full retry sequence for forensics (§20).
