Decisions (§9) · 30 ADRs

1

Language

Chosen

Rust (2021 edition)

Rejected

Go, C/C++, Erlang

When the rejected choice is right

Erlang wins when the goal is a clustered broker with hot-code-upgrade and per-entity supervision trees as the primary feature — RabbitMQ/EMQX/VerneMQ all chose the BEAM precisely because process isolation + distribution come free; our single-node scope (§1.2) removes that pull.

Why: Memory safety on adversarial bytes; exhaustive enums on packet/method/state; no GC tail-latency (§1.10)

2

Async runtime

Chosen

tokio (multi-thread)

Rejected

async-std, glommio, custom epoll

When the rejected choice is right

glommio (thread-per-core, io_uring) wins at the 1M-connection ceiling where a shared-nothing per-core reactor with SO_REUSEPORT sharding beats work-stealing on cache locality — the regime §Scalability Analysis and C4 reach but §4.1's 10k–100k target does not require.

Why: Mature reactor/executor, timers, channels; one task/conn (#129, #53)

3

Buffer / zero-copy

Chosen

bytes (Bytes/BytesMut)

Rejected

Vec<u8> copies, custom arena

When the rejected choice is right

A custom arena wins when message lifetimes are strictly bounded to one fan-out cycle and the atomic refcount of Bytes shows up in a profile — a bump allocator freed per-tick removes the refcount traffic, viable only when no body outlives the dispatch (durable queues, §Phase 9, break that assumption).

Why: Ref-counted slices; payloads alias the read buffer; no per-packet copy

4

TLS

Chosen

rustls + tokio-rustls

Rejected

OpenSSL/native-tls

When the rejected choice is right

OpenSSL wins when a deployment mandates FIPS-140 validated crypto or hardware-engine offload (ENGINE/PKCS#11) that rustls does not provide, or must interoperate with a legacy cipher suite rustls deliberately omits.

Why: Memory-safe, no C deps; client-cert auth (#48)

5

WebSocket (MQTT-over-WS)

Chosen

tokio-tungstenite

Rejected

hand-rolled RFC6455

When the rejected choice is right

Hand-rolling RFC 6455 wins when MQTT-over-WS is the only transport and you want a single fused decode path (WS frame + MQTT packet) with no intermediate buffering — sister project #81 does exactly this; here TCP/TLS are primary so the library is the lower-risk reuse.

Why: Vetted WS framing/upgrade; subprotocol mqtt (#81)

6

MQTT codec

Chosen

hand-built over bytes

Rejected

reuse mqttbytes/mqtt-v5 wholesale

When the rejected choice is right

Reusing mqttbytes/rumqtt wholesale wins when the deliverable is a product (ship a broker fast) rather than the pedagogy of the wire (§2) — a battle-tested codec removes an entire fuzz surface; this project's whole point (§1.1) is to build that surface.

Why: Wire control is the project; ≤2-line snippets, full control of caps (P1,P2)

7

AMQP codec

Chosen

hand-built; method tables from amqp0-9-1.xml

Rejected

depend on amq-protocol (client lib)

When the rejected choice is right

Depending on amq-protocol wins for a client or a proxy that only forwards frames it never originates — the client crate's types suffice; a broker must originate every server-side method (connection.start, basic.deliver, basic.return) which the client lib does not model.

Why: Need broker-side model; generate method arg codecs from spec XML

8

Serialization (config/snapshots)

Chosen

serde + TOML (config), bincode (snapshots)

Rejected

JSON everywhere, protobuf

When the rejected choice is right

Protobuf wins when snapshots/WAL records must evolve across many independent producers/consumers with strong forward/backward-compat guarantees and cross-language readers — overkill for one writer (the broker) reading its own bincode, but right for a shared on-disk contract.

Why: TOML human config; compact deterministic snapshots

9

Persistence / WAL

Chosen

hand-built append-only WAL + segments (#69)

Rejected

embedded KV (sled/RocksDB), SQLite

When the rejected choice is right

RocksDB wins when the durable working set exceeds RAM and you need LSM compaction, bloom filters, and range scans over millions of retained topics/queued messages — an embedded LSM is years of tuning we forgo because our durable state is small and the WAL is the lesson (§9).

Why: Durability semantics are the project; control fsync + recovery (P7)

10

Durability policy

Chosen

group-commit fsync; ack-after-fsync for durable

Rejected

fsync-per-op, no-fsync

When the rejected choice is right

no-fsync (fsync-off / O_DSYNC-less) wins for a pure QoS0 / transient-only telemetry broker where every message is replaceable and throughput dominates — durability is then pure cost; fsync-per-op wins for a single-writer audit log needing per-record durability over throughput.

Why: Bounded fsync amplification; no acked-msg loss (I11)

11

Topic index

Chosen

level-segmented trie (radix per level)

Rejected

regex, linear scan, hash of full topic

When the rejected choice is right

A flat hash of the full topic wins when no subscription uses wildcards (exact-match-only routing, e.g. a key-addressed cache-invalidation bus) — an O(1) HashMap<Topic, Subs> beats a trie walk; wildcards (+/#, the protocol mandate, §8.9) are what force the trie.

Why: O(depth×branch) deterministic match; wildcards (P8, I9)

12

QoS dedup/inflight store

Chosen

per-session ring buffer + id bitmap, WAL-backed

Rejected

global map only, in-memory only

When the rejected choice is right

In-memory-only wins when no session is persistent and clean-start=1 is enforced broker-wide (an ephemeral fan-out tier in front of a durable backend) — persistence is dead weight if exactly-once need not survive a crash, which §Phase 9's durability contract explicitly rejects for the general broker.

Why: Exactly-once across reconnect/crash (P3, I2)

13

Concurrency model

Chosen

one task/connection; routing core Arc + sharded locks

Rejected

thread-per-conn, single event loop

When the rejected choice is right

A single event loop wins at low connection counts on one core where the cross-core cache traffic of shared Arc state costs more than it saves — Mosquitto's single-threaded epoll loop (§5 ref-impl) is simpler and faster until multicore fan-out saturates one core.

Why: Scales on multicore; bounded contention (P6)

14

Shared-state locking

Chosen

parking_lot RwLock + per-shard mutexes; atomics for counters

Rejected

one global Mutex

When the rejected choice is right

One global Mutex wins when contention is provably negligible (a low-rate broker, or single-threaded runtime) — it is strictly simpler and removes the deadlock-ordering reasoning that multiple locks force; sharding only earns its complexity above a contention threshold (§Phase 4).

Why: Reduce contention on the trie/router; lock-free telemetry (P11)

15

Channels (intra-broker)

Chosen

tokio::mpsc bounded (outbound), watch (config)

Rejected

unbounded mpsc

When the rejected choice is right

Unbounded mpsc wins for a strictly internal, provably-bounded producer (e.g. a fixed-cardinality $SYS updater that emits ≤N msgs/interval) where backpressure can never trigger — the bound is then pure overhead; for any client-driven path it is a DoS vector (P4).

Why: Bounded = backpressure (P4, I16)

16

Error handling

Chosen

thiserror typed enums per crate

Rejected

anyhow only, panics

When the rejected choice is right

anyhow wins in the brkr-cli tool and test harnesses where errors are reported to a human, not matched on or mapped to a wire reason code — typed enums there are ceremony; the broker core needs them because every error becomes a reason/reply code (P10).

Why: Matchable, reason-coded failures (P10, P14)

17

Logging

Chosen

tracing + tracing-subscriber (JSON/text)

Rejected

log, println

When the rejected choice is right

Plain log wins for an embedded/edge broker (NanoMQ-class, §5 ref-impl) where binary size and zero span-overhead matter more than structured tracing — spans cost allocation and a subscriber; a tiny edge deployment may not run a log pipeline at all.

Why: Structured spans for message path; no payload logging (P11)

18

Metrics

Chosen

$SYS tree + metrics/Prometheus exporter

Rejected

ad hoc counters

When the rejected choice is right

Ad-hoc counters win for a throwaway load experiment where you instrument exactly one number and discard the binary — the $SYS tree + exporter is infrastructure that only pays off for an operated, long-lived broker.

Why: Standard MQTT $SYS + scrapeable gauges (P11)

19

Tracing context

Chosen

MQTT5 user-properties / AMQP headers carry trace-id

Rejected

none

When the rejected choice is right

No propagated context wins in a closed system where the broker is the trust + observability boundary and no downstream consumer participates in the same trace — carrying trace-ids then leaks metadata and costs bytes for no cross-service correlation.

Why: Distributed tracing across pub→sub (#132)

20

Testing

Chosen

cargo test + proptest + tokio::test

Rejected

unit-only

When the rejected choice is right

Unit-only wins for a frozen codec with a fixed, fully-enumerated input space (every packet type has one canonical encoding) where property generators add maintenance without finding new states — the QoS/trie state spaces (I2, I9) are what make property testing pay here.

Why: Property tests on topic-match + QoS state machines

21

Fuzzing

Chosen

cargo-fuzz (libFuzzer) on codec targets

Rejected

none

When the rejected choice is right

No fuzzing wins when the parser only ever sees bytes the broker itself produced on a trusted loopback (an internal bus behind a validating gateway) — fuzzing earns its CI cost precisely because this broker parses the open internet (§Threat Model).

Why: Decode robustness on adversarial bytes (P2)

Interop testing

Chosen

mosquitto, Paho (C/Py/Java), RabbitMQ client libs in CI containers

When the rejected choice is right

Self-only testing wins for a closed appliance shipping a matched client + broker pair from the same codebase, where third-party interop is a non-goal — but it cannot catch our own wire assumptions, which is why P1 demands independent clients.

Why: Real-client conformance (P1, §Phase 13)

Ad-hoc timing wins during early spike/prototyping before any performance contract exists — committed baselines + a regression gate (§Performance Engineering) only matter once you must defend a number across commits.

Alternative Architectures

Fundamentally different ways to build a message broker for the same goal. Each: sketch, winning regime, the real system embodying it, why this blueprint rejected it.

A1 — The append-only partitioned log (consumers track offsets). No per-subscriber state, no per-message ack: messages append to a partitioned, replayable log; each consumer stores its own offset and pulls.

  producers ──▶ [ topic = partition 0 | 1 | 2 ... ]  (append-only, offset-indexed)
                         │            │
                    consumer-group: each consumer owns a partition,
                    tracks its own offset, pulls and replays at will
  • Wins: high-throughput event streaming, replay/reprocessing, and stream analytics where the log is the source of truth and consumers come and go — sequential disk writes + zero per-message broker state give enormous throughput.
  • Real system: Apache Kafka (Kreps et al., NetDB 2011, §5 Papers); Apache Pulsar splits this further into broker + BookKeeper bookies.
  • Rejected because: it has no per-subscriber QoS state machine, no retained-value semantics, no topic wildcards, and no per-message acknowledgement — i.e. none of the MQTT/AMQP delivery contract (§8.6, MM2) that is this project's entire subject. The log is a different machine class (§Comparative Architecture); #27 covers it.

A2 — Erlang/OTP process-per-entity (let-it-crash supervision). Each connection, queue, and channel is a lightweight BEAM process under a supervision tree; isolation and clustering come from the runtime, not the application.

  • supervisor
    • conn_proc(client A) ── chan_proc ── chan_proc
    • conn_proc(client B)
    • queue_proc(q1) ── queue_proc(q2) (each isolated; crash → supervisor restarts)
  • (distribution: processes transparently span nodes → free clustering)
  • Wins: massive connection counts and multi-node clustering with near-free fault isolation and hot-code upgrade — the runtime gives process isolation, distribution, and supervision that an application would otherwise hand-build.
  • Real system: RabbitMQ, EMQX, and VerneMQ all embody this (§5 Reference Implementations); it is why the canonical brokers are BEAM-based.
  • Rejected because: ADR-1 chose Rust for memory safety on adversarial bytes, exhaustive enums (MM9), and no-GC tail latency; the BEAM's strengths (distribution, hot-upgrade) serve clustering, which §1.2 defers (§Phase 13). For a single-node, deterministic, fuzz-hardened broker, Rust's compile-time guarantees beat runtime supervision — at the cost of giving up free clustering.

A3 — A thread-per-core, shared-nothing reactor (io_uring). Instead of one work-stealing runtime over shared Arc state, each core runs an independent reactor owning a shard of connections with no cross-core locking; SO_REUSEPORT distributes accepts.

  core 0: reactor ── conns 0..k   (owns its shard of sessions/trie; no shared lock)
  core 1: reactor ── conns k..2k
  core 2: reactor ── conns 2k..3k   ── routing across shards via explicit message-passing
   (io_uring submission/completion queues per core; SO_REUSEPORT accept fan-in)
  • Wins: the absolute-highest connection counts and lowest tail latency, where the cross-core cache traffic of shared Arc<RoutingCore> state becomes the bottleneck — a shared-nothing design removes lock contention and cache-line bouncing entirely (the C4/§Scalability Analysis regime, ~1M connections).
  • Real system: the glommio runtime (ADR-2 rejected alternative) embodies thread-per-core io_uring in Rust; Seastar/ScyllaDB and Redis's threaded-I/O model are the same philosophy.
  • Rejected because: cross-shard routing (a publish on core 0 fanning out to subscribers on core 2) requires explicit message-passing between reactors, which complicates the fan-out path that is the broker's core operation (MM1) — a fan-out broker has inherently cross-connection routing, so shared state (ADR-13) is the simpler fit at the §4.1 10k–100k target. The shared-nothing design only pays off at the 1M-connection ceiling §Scalability Analysis defers.
