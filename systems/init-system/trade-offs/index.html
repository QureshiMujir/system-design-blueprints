Decisions (§9) · 22 ADRs

ADR-01

Implementation language

Chosen

Rust 1.78+ MSRV

Rejected

C, C++, Go

When the rejected choice is right

C wins on toolchains with no Rust support (rare embedded cross-targets); Go wins for a non-PID-1 control-plane CLI where GC pauses don't matter

Why: memory safety in PID 1; no GC pause in signal-latency paths

ADR-02

Unit-file format

Chosen

systemd-compatible key=value INI-like

Rejected

TOML, YAML, custom S-expr

When the rejected choice is right

TOML wins for a greenfield deployment with no migration burden needing native nested structures

Why: admin familiarity; migration path from systemd

ADR-03

cgroup version

Chosen

v2 only

Rejected

v1 dual-hierarchy support

When the rejected choice is right

v1 wins on kernels < 4.5 or long-support embedded distros stuck on a pre-migration LTS image

Why: single unified hierarchy (P2)

ADR-04

Activation ordering algorithm

Chosen

transaction + topological sort

Rejected

retry-until-stable (Upstart), directory-scan order (runit)

When the rejected choice is right

retry-until-stable wins when dependency declarations are inherently unreliable (udev hardware events)

Why: determinism, single-pass convergence (P4)

ADR-05

Concurrency model

Chosen

async single-threaded epoll reactor + blocking thread pool for cgroup/FS ops

Rejected

full multi-threaded work-stealing runtime, pure synchronous blocking

When the rejected choice is right

work-stealing wins for a non-PID-1, bus/API-heavy control process under heavy concurrent load

Why: PID 1 needs simple, auditable control flow; a crash in one thread must not corrupt shared state

ADR-06

Journal storage/serialization

Chosen

custom binary indexed format

Rejected

plain-text append log, SQLite

When the rejected choice is right

SQLite wins when the host already depends on it elsewhere and ad hoc SQL queries matter more than throughput

Why: queryable + compact + crash-recoverable (I9)

ADR-07

Control-bus transport

Chosen

Unix-domain socket only

Rejected

TCP loopback, named pipes

When the rejected choice is right

TCP loopback wins for a container-sidecar pattern needing cross-netns reachability without a shared mount namespace

Why: filesystem permissions double as access control; no network-stack dependency at early boot

ADR-08

Async runtime

Chosen

hand-rolled epoll reactor

Rejected

tokio, async-std

When the rejected choice is right

tokio wins for every non-PID-1 crate in the workspace (is-cli, is-bench) where ecosystem velocity outweighs the supply-chain argument

Why: PID 1 cannot depend on a general runtime's internal thread-spawn semantics this early in boot, or its dependency-supply-chain surface

ADR-09

Init's own diagnostic logging

Chosen

structured stderr + kernel console, pre-journal

Rejected

syslog(3) only

When the rejected choice is right

syslog wins once the journal/syslog bridge is confirmed running, for non-PID-1 services

Why: syslog target may not be up during early boot

ADR-10

Metrics exposition

Chosen

pull-based textfile/Prometheus exporter

Rejected

push-based StatsD

When the rejected choice is right

push-based StatsD wins in a fleet with an existing centralized StatsD pipeline and no local scraping

Why: PID 1 must not depend on a reachable network destination to emit metrics

ADR-11

Testing strategy

Chosen

property-based (proptest) + differential-vs-systemd + deterministic simulator

Rejected

unit tests only

When the rejected choice is right

unit-tests-only wins for leaf crates with trivially small state space (e.g. journal serialization helpers)

Why: dependency-graph correctness is exactly the state-space bug class unit tests miss

ADR-12

Fuzzing

Chosen

cargo-fuzz (libFuzzer) on parser + transaction engine

Rejected

AFL++ only

When the rejected choice is right

AFL++ wins fuzzing across a process boundary (the compiled is-cli binary's argv parsing)

Why: integrates directly with the Rust toolchain and corpus management

ADR-13

CI/CD

Chosen

GitHub Actions matrix, QEMU-boot smoke test

Rejected

self-hosted Jenkins

When the rejected choice is right

self-hosted Jenkins wins when QEMU images need proprietary hardware emulation unavailable on public runners

Why: disposable VM images without host maintenance burden

ADR-14

Packaging

Chosen

static musl binary + minimal initramfs

Rejected

dynamic glibc linking

When the rejected choice is right

dynamic glibc wins when a non-PID-1 unit needs NSS integration (getpwnam) — resolved via a small dynamic NSS helper, keeping PID 1 itself static

Why: PID 1 must not depend on the dynamic linker's state this early in boot

ADR-15

Container support

Chosen

cgroup delegation only, no bundled OCI runtime

Rejected

bundled container runtime (containerd-style)

When the rejected choice is right

bundling wins for an appliance image where minimizing binary count outweighs separation of concerns

Why: scope discipline — a runtime is its own multi-year project

ADR-16

Mandatory access control

Chosen

hooks to invoke external LSM tooling only

Rejected

embedded SELinux/AppArmor policy engine

When the rejected choice is right

embedding wins for a hardened-appliance vendor shipping one policy pinned 1:1 to one init version

Why: policy compilation is its own specialized toolchain, out of scope

ADR-17

Release/versioning policy

Chosen

SemVer, 2-major-version wire/format compat window

Rejected

rolling release, no version pinning

When the rejected choice is right

rolling release wins for a single-vendor fleet upgrading in lockstep with no cross-version burden

Why: operators need predictable unit-file compat upgrade paths

ADR-18

Build reproducibility

Chosen

reproducible builds (locked Cargo.lock, deterministic timestamps)

Rejected

best-effort builds

When the rejected choice is right

best-effort wins for rapid-iteration dev-only builds where the tooling overhead isn't justified

Why: PID 1 binary provenance must be independently verifiable

ADR-19

Time source

Chosen

CLOCK_MONOTONIC for scheduling/backoff/watchdog; CLOCK_REALTIME only for OnCalendar/journal timestamps

Rejected

CLOCK_REALTIME everywhere

When the rejected choice is right

CLOCK_REALTIME-everywhere wins on RTC-only hardware with no monotonic guarantee across suspend/resume

Why: monotonic clock is immune to NTP step corrupting backoff/timeout math

ADR-20

Event-loop backpressure

Chosen

bounded 256-event signalfd/epoll drain per iteration, cooperative yield

Rejected

unbounded drain-to-empty

When the rejected choice is right

unbounded drain wins for known bursty-then-idle batch workloads where full-drain latency matters more than fairness

Why: prevents event-source starvation under a SIGCHLD storm (I5)

ADR-21

Licensing

Chosen

dual MIT/Apache-2.0

Rejected

GPLv2/LGPL (matching the kernel/systemd)

When the rejected choice is right

GPLv2/LGPL wins when the project wants to guarantee downstream modifications stay open

Why: maximizes adoption in embedded/commercial contexts

ADR-22

Dependency policy

Chosen

minimized, cargo-vet-audited allow-list for the PID 1 binary

Rejected

unrestricted dependency graph

When the rejected choice is right

unrestricted deps win for peripheral crates not compiled into the PID 1 binary (is-cli, is-bench)

Why: PID 1 is the highest-value supply-chain-attack target on the host

36. Alternative Architectures (Roads Not Taken)

1. Retry-until-stable, event-driven (no static DAG).

 udev event ──▶ [job queue] ──▶ try-start job ──▶ fail? requeue with delay
                                        │
                                        └─ succeed ──▶ emit "started" event

Regime where it wins: hardware-event-driven boot (hot-plug devices arriving in unpredictable order) where a static dependency declaration is impossible to write correctly in advance. Real system: Upstart. Rejected here because a static service graph (this project's actual workload) has no such unpredictability, and retry-until-stable trades away the determinism P4/P13 depend on for no corresponding benefit in this regime.

2. Dependency-free, supervision-only.

 /service/*/  ──▶ [runsvdir scans dir] ──▶ [runsv per entry, independent]

Regime where it wins: a minimal embedded image with a handful of services and no meaningful ordering requirements. Real system: runit. Rejected here because this project's target scope (hundreds of units, complex Requires=/After= graphs) needs exactly the ordering expressiveness this model omits.

3. Continuous reconciliation loop (desired-state vs. actual-state, not one-shot activation).

 ┌────────────┐   diff    ┌───────────┐   converge   ┌──────────────┐
 │ desired-state ├────────▶│ controller ├─────────────▶│ actual state │
 │   (units)     │◀────────┤   loop     │◀─────────────┤ (processes)  │
 └────────────┘  re-diff  └───────────┘   observe     └──────────────┘

Regime where it wins: containerized/cloud-native fleets where "keep converging toward desired state forever" is the right model because the desired state itself changes continuously (a kubelet-style control loop). Real system: Kubernetes' kubelet reconciling pod specs. Rejected here because a continuous reconciliation loop's inherent latency (poll-diff-converge cycles) is unsuitable for PID 1's boot-critical path (§4's sub-2-second p95 boot target), where one-shot transactional activation (§15) is both simpler to reason about and faster.

4. Micro-kernel-style init split into cooperating minimal daemons, no single privileged supervisor.

 [tiny root task] ──spawns──▶ [name-service daemon]
        │                            │
        └──spawns──▶ [supervisor daemon] ◀──queries── [policy daemon]

Regime where it wins: high-assurance, security-certified systems where minimizing the trusted computing base of any single component is the overriding goal, even at the cost of more inter-process coordination. Real system: seL4-based deployments following the root-task minimalism pattern. Rejected here because it fragments the single coherent unit graph and control-bus UX operators expect (§3's architectural overview), trading a unified operational model for a smaller-but-more-numerous trust boundary set — the wrong tradeoff for a general-purpose Linux distribution's init.
