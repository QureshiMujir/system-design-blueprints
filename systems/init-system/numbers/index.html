34. Back-of-Envelope Capacity Model

  1. SIGCHLD-storm reactor ceiling = batch_size × loop_hz = 256 events/iteration (ADR-20) × ~5,000 Hz idle-loop rate (≈200 µs/epoll_wait cycle) ≈ 1,280,000 reaps/sec theoretical ceiling — real fork/waitpid overhead caps actual exit rate far below this, so the reactor itself is never the bottleneck (§18.7).
  2. Unit-graph RAM at max scale = 8,192 units × ~1.2 KiB per Unit+ Dependencies struct ≈ 9.8 MiB, plus 8,192 × ~200 B supervisor records ≈ 1.6 MiB — well within the 32 MiB PID 1 ceiling (§4) with headroom for journal write buffers.
  3. Socket-unit FD ceiling = hard_nofile ÷ fds_per_socket_unit = 4,096 ÷ 3 ≈ 1,365 concurrently listening socket units before FD exhaustion — below the 2,048 soft unit cap, meaning socket-heavy deployments hit the FD ceiling before the unit-count ceiling (the real practical limit for that workload shape, §31).
  4. Boot-time journal burst bandwidth = units × avg_line_bytes ÷ throughput = 2,048 × 200 B ÷ 100,000 entries/sec ≈ 4.1 ms to drain a full-boot logging burst — negligible against the 1.2 s p50 boot target (§4).
  5. Dependency-graph build time at the hard ceiling = nodes × per-node cost = 8,192 × 100 µs ≈ 819 ms — this alone would blow the 1.2 s p50 boot budget, which is exactly why §4's 500-node reference class, not 8,192, backs the p50 target; 8,192 is documented as a degraded-mode ceiling only.
  6. Journal storage growth at sustained max throughput = throughput × entry_size × amplification × seconds/day = 100,000 × 200 B × 1.3 × 86,400 ≈ 2.25 TB/day — the reason journal rotation/vacuuming policy (§26, §27) is mandatory, not optional, for any host run near this ceiling indefinitely.
  7. cgroup fan-out cost if serialized = units × per-unit cgroup latency = 8,192 × 5 ms ≈ 41 s of serialized cgroup setup — the concrete number motivating §16 Phase 4's decision to parallelize cgroup creation across a batch rather than the process-spawn step alone.
  8. Restart-storm blast-radius bound = burst × restart_latency = StartLimitBurst(5) × 80 ms p50 ≈ 400 ms of churn before a flapping unit enters Maintenance (I8) — bounding the CPU-pinning blast radius of a single bad deploy to under half a second before the circuit breaker trips.
