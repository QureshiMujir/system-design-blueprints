32. Mental Models & First Principles

MM1 — "A unit is a promise, not a process." Predicts: units can be Active with no associated PID (targets, slices, RemainAfterExit= services). Bug class without it: assuming every unit has a meaningfully-set pid field. Applies in §11 (Core Schema, UnitState) and §21 Phase 9 (Target units).

MM2 — "The graph is data, the transaction is a plan, activation is execution — three distinct phases, never conflated." Predicts: validation errors surface before any process touches the kernel. Bug class without it: parse/graph errors that only surface at runtime because validation was skipped under time pressure. Applies in §8 Domain Model and §15 Phase 3.

MM3 — "PID 1 is an event loop wearing a supervisor costume." Predicts: everything routes through one epoll reactor; a blocking call anywhere stalls every subsystem, not just its caller. Bug class without it: spawning a blocking syscall directly on the reactor thread and wondering why unrelated units stop progressing. Applies in §17 Phase 5 and §18 Phase 6.

MM4 — "A cgroup is a lease, not a label." Predicts: cgroup membership must be established atomically with process creation, never applied after the fact. Bug class without it: a TOCTOU window where the new process allocates memory before its limit lands. Applies in §19 Phase 7, I12.

MM5 — "Signals are doorbells, not messages." Predicts: SIGCHLD tells you that something happened, never what — you always re-scan with waitpid. Bug class without it: trying to correlate one specific signal delivery to one specific child, which breaks the instant two children exit close together. Applies in §18 Phase 6, I5.

MM6 — "A socket unit is a promise redeemed lazily." Predicts: connection accept can precede process existence; a socket unit is "available" before it has forked anything. Bug class without it: assuming a socket-activated, Accept=no unit behaves like a live server the instant it reports Active. Applies in §20 Phase 8.

MM7 — "Restart policy is a control loop with a spring, not a switch." Predicts: naive immediate-restart-forever policies oscillate under a persistent failure. Bug class without it: no circuit breaker, so a bad deploy pins a CPU core indefinitely. Applies in §17 Phase 5, I8.

MM8 — "Boot order is a partial order, not a sequence." Predicts: two units with no path between them in the DAG have no guaranteed relative order and must never be written to depend on one existing anyway. Bug class without it: implicit ordering assumptions inherited from directory/alphabetical scan order (sysvinit's actual, historical failure mode). Applies in §14 Phase 2 and §36 Alternative Architectures.

Reference Implementations

  • systemd (github.com/systemd/systemd) — src/core/unit.c, src/core/job.c, src/core/transaction.c. Lesson: the transaction abstraction that reconciles a requested job set before touching any process. Applied in §15 Phase 3. Pitfall not to copy: src/core/'s historical monolithic PID-1 surface area (D-Bus, logind, resolved, networkd all in one project) — this blueprint draws hard scope lines (ADR-15, ADR-16) precisely to avoid that.
  • runit (smarden.org/runit) — runsv, sv, runsvdir. Lesson: minimal supervision-only design with no dependency graph at all. Applied (as a rejected model) in §36 Alternative Architectures. Pitfall not to copy: ordering is directory-scan-order only, which does not scale past a handful of services.
  • s6 (skarnet.org/software/s6) — s6-svscan, s6-supervise. Lesson: strict separation between supervision and "everything else" (logging, activation). Applied in §17 Phase 5's supervision-first minimalism and §33 Comparative Architecture Table. Pitfall not to copy: no native dependency ordering; s6-rc is a bolt-on.
  • OpenRC (github.com/OpenRC/openrc) — rc-service, rc-depend. Lesson: runlevel-inheritance model for targets. Applied in §21 Phase 9. Pitfall not to copy: shell-script-based unit definitions reintroduce the implicit-ordering problem declarative units (P1) exist to avoid.
  • Upstart (historical; Ubuntu's event-based init, referenced via the Upstart Cookbook, above) — event-emission model. Lesson: udev-hardware-event-driven activation is a genuinely different regime from a static service graph. Applied (as a rejected model) in §36 Alternative Architectures. Pitfall not to copy: "keep retrying jobs until the system converges" is non-deterministic across reboots (rejected in ADR-04).

Glossary (§38) · 43 terms · site-wide glossary

Activation
the process of transitioning a unit from Inactive toward Active (§8.3).
After= / Before=
ordering relations between units (§8.2).
Backoff
the exponentially-increasing delay between restart attempts (§17.2).
BindsTo=
a strong requirement relation; the dependent stops if the dependency stops (§8.2).
Batch (round)
the set of units activated in parallel within one step of the topological sort (§15.2).
Bus (control bus)
the Unix-domain-socket protocol carrying operator commands (§20).
cgroup
a Linux control group; the resource-isolation and process-tracking primitive (§19).
cgroups v2
the unified single-hierarchy cgroup model (ADR-03).
Conflicts=
a negative requirement; two conflicting units are never both Active (§8.2).
Controller
(cgroup) — a resource-accounting/limiting subsystem (memory, cpu, io, pids) (§19.2).
Delegate=
a unit directive letting a service manage its own cgroup subtree (§19.2).
Drop-in
a layered unit-file config override (foo.service.d/*.conf) (§8.1).
Ephemeral (orphan)
a process reparented to PID 1 whose original parent exited (§18.2).
ExecStart=
the unit-file directive declaring the command to run (§8.1).
FD (file descriptor)
the kernel handle for an open resource; central to socket activation's FD-passing protocol (§20).
Fork+exec
the POSIX process-creation idiom clone3 (or fork) followed by execve (§17.2).
Isolate
an operation switching the active target, deactivating everything outside the new target's closure (§21.2).
Journal
the structured, crash-consistent log store (§22).
LISTEN_FDS
the environment variable protocol communicating inherited socket FD count to an activated service (§20.2).
Maintenance
the unit state entered after StartLimitBurst is exceeded, requiring operator reset (§8.3).
MemoryHigh= / MemoryMax=
the cgroup memory throttle threshold and hard limit, respectively (§19.2).
OnCalendar=
a cron-like timer specification (a Timer-unit directive, deferred detail beyond Phase 9's target scope).
Once semantics (idempotency)
the property that repeating a control-plane operation has no additional side effect (P11).
Orphan reaping
waitpid-ing a process whose original parent already exited (§18.2).
PID 1
the first userspace process; the init; the ancestor of every other userspace process (§1).
Process group / session
the POSIX grouping mechanisms setsid() establishes for signal-delivery isolation (§17.2).
Reap
calling wait/waitpid on an exited child to release its zombie slot (§18).
Requires=
a strong requirement relation; the dependent fails if the dependency fails (§8.2).
RestartPolicy
the closed enum governing post-exit restart behavior (§11).
RestartSec=
the base backoff interval before a restart attempt (§17.2).
Round
see Batch.
Signalfd
the Linux facility delivering signals as readable file descriptor events instead of interrupting execution (§18.2).
SIGCHLD
the signal delivered to a parent on a child's state change (§18).
Slice
a cgroup-grouping unit kind aggregating related units' cgroups (§10, §19.2).
Socket activation
lazily starting a service upon a connection to its pre-created listening socket (§20).
StartLimitBurst / StartLimitIntervalSec
the circuit-breaker parameters bounding restart attempts within a time window (I8).
Target
a synchronization-point unit kind with no process of its own (§21.2).
Transaction
a planned, atomic set of activation/deactivation batches (§15).
UnitConfig
the parsed, typed representation of a unit file's directives (§11).
UnitName
the (name, kind) identity pair for a unit (§8.1).
UnitState
the six-state supervision FSM (§8.3).
Watchdog (WatchdogSec=)
a per-service heartbeat timeout enforcing liveness beyond mere process existence (§17.2).
Zombie
an exited process still occupying a process-table slot pending its parent's reap (§18).
