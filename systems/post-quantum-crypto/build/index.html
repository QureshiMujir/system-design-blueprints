Pitfalls
  • Wrong domain byte: SHA-3 uses 0x06; SHAKE uses 0x1f. Mixing them produces silently wrong output that only KATs catch.
  • Endianness in lane packing: Keccak lanes are little-endian 64-bit; big-endian hosts require from_le_bytes. Missing this silently corrupts all output.
  • Off-by-one in rate boundary: absorbing exactly rate bytes without permuting before the next absorb; can trigger if block-aligned input is common in testing but the bug only surfaces on uncommon lengths.
  • Squeeze after non-finalized state: calling squeeze without finalize produces wrong output; the API must enforce ordering (boolean flag + debug-assert).
  • State aliasing on reset: reset() must zero-fill the full 200-byte state, not just set counters; partial zeroing leaves key material in memory (violates P8).
  • PRF nonce domain: FIPS 203 PRF takes a 33-byte input (32-byte key + 1-byte nonce); off-by-one in the concatenation breaks all subsequent sampling.

Pitfalls
  • CBD bit extraction off by one: extracting eta bits starting from wrong bit offset produces a shifted distribution; symptoms are subtle (mean non-zero); catch with distribution test.
  • Nonce collision in s-expansion: s1 and s2 use different nonce offsets (0..L and L..L+K); if both use offset 0, keys are correlated and security collapses silently.
  • Variable-time CBD on secret data: using a lookup table indexed by coefficient value or a conditional expression is variable-time; must be pure arithmetic (add/sub/shift).
  • Rejection loop not seeded per (i,j): reusing the same XOF instance across matrix positions produces repeated coefficients; XOF must be re-initialized per position.
  • gamma1 mask overflow in Dilithium: expand_mask output must fit in i32 after centering; if gamma1=2^17, values up to 131071; coefficient arithmetic must not overflow before reduction.
  • PRF absorb length mismatch: FIPS 203 PRF input is exactly 33 bytes; absorbing 32+1 in separate calls is fine but must finalize before squeeze; omitting finalize gives wrong output.

Pitfalls
  • Compress rounding bias: naive x * 2^d / q truncates; must use round-half-up with + q/2 before division; off-by-one causes decryption failure in ML-KEM.
  • Bit cursor alignment in bitpack: packing non-power-of-2 widths (e.g., 10 bits) across byte boundaries is error-prone; unit-test each bit-width boundary case individually.
  • t0 signed packing: t0 coefficients are signed and centered; encode as unsigned offset (+ 2^(d-1)) before packing; omitting the shift produces wrong unpacked values.
  • Hint position invariant: FIPS 204 requires hint positions within each polynomial to be strictly increasing; accepting unsorted positions in unpack opens a malleability vector.
  • PolyVec length mismatch in decode_u: if k is wrong (e.g., caller passes k=3 for a k=2 ciphertext), decode silently pads; must validate bytes.len() == k * 32 * du.
  • Integer overflow in compress: x * (1 << d) with x up to q-1=3328 and d=12: 3328 * 4096 = 13,631,488 fits in i32; for q=8380417 and d=10: 8380417 * 1024 = 8,581,547,008 — overflows i32 (max 2,147,483,647); must use i64 intermediate.

  • rho_prime width. FIPS 204 sec. 6.1: rho_prime is 64 bytes (not 32); using 32 shifts all subsequent expand_s indices. Debug: compare rho_prime hex against known vector.
  • expand_s uses SHAKE256, not SHAKE128. Matrix A uses SHAKE128 (XOF); secrets use SHAKE256 (PRF). Mixing produces wrong s1/s2. Debug: confirm hash function per FIPS 204 Table 1.
  • Power2Round sign convention. t0 = t - t1*2^d may be negative; must be stored as signed integer in range (-2^(d-1), 2^(d-1)]; treating as unsigned shifts pack_t0 encoding. Debug: unit-test with t=0, t=1, t=2^d-1, t=2^d.
  • tr length. tr = H(pk, 64) is 64 bytes (ML-DSA) vs H(pk) = 32 bytes (ML-KEM); confusion causes off-by-32 in sk layout. Debug: print sk field offsets.
  • K field placement. sk = rho || K || tr || ...; K is 32 bytes at offset 32, before tr at offset 64. Misplacing K breaks sign and verify. Debug: parse sk per-field and compare against known vector.
  • eta=4 packing width. ML-DSA-44 uses eta=4 (3 bits/coeff); ML-DSA-65/87 use eta=2 (3 bits/coeff also, but range differs). A wrong packing width silently truncates coefficients. Debug: decode packed s1 and check range.
