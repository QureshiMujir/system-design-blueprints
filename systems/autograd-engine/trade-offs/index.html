Decisions (§9) · 23 ADRs

ADR-01

Implementation language

Chosen

Rust, edition 2021, toolchain 1.75

Rejected

Python+C++ split (PyTorch shape); C++ alone; Zig

When the rejected choice is right

A team that must ship a Python-first researcher UX today and can absorb the ABI tax — Python+C++ wins

Why: One build, one memory model, no FFI/ABI tax; Weak/Arc discipline needs a real ownership model (§1)

ADR-02

Graph construction

Chosen

Dynamic, define-by-run (eager)

Rejected

Static graph (TF1-shape); hybrid trace-then-run

When the rejected choice is right

A deployment target with zero tolerance for per-step Python/Rust overhead and a fixed, unchanging graph shape — static graphs win (Alt-1, §37)

Why: Preserves imperative debugging (§2, P2); JIT capture (§23) is opt-in on top

ADR-03

Tensor layout

Chosen

Strided views over shared Arc<Storage>

Rejected

Blocked/tiled layout at the tensor level (BLIS/NVPL-native)

When the rejected choice is right

A kernel-only library with no user-facing view API — a blocked-native layout wins on raw matmul throughput

Why: Numpy/PyTorch-compatible; broadcasting and views are free (P4, §8.1)

ADR-04

Tape node ownership

Chosen

Arc<Node> on Vec, Weak parent/tensor refs

Rejected

Arena allocator with a single generation-counter free

When the rejected choice is right

A JIT-fused inner loop (Phase 11) that runs thousands of tiny steps per second — an arena's one-shot free beats Arc refcounting overhead

Why: Arena needs a per-step lifetime that matches training exactly; Arc/Weak is simpler to reason about first (§8.4)

ADR-05

Execution mode

Chosen

Eager by default; lazy mode opt-in (Phase 11)

Rejected

Tinygrad-style lazy-by-default (LazyBuffer)

When the rejected choice is right

A kernel-fusion-first framework where every op is a compile target — lazy-by-default wins (Alt-3, §37)

Why: Eager is debugging-friendly (P2); lazy conflates scheduling with autograd if made default (§5, Tinygrad ref-impl)

ADR-06

Broadcasting rules

Chosen

Numpy semantics exactly

Rejected

A custom "strict-shape" rule requiring exact match

When the rejected choice is right

A safety-critical numerical kernel where implicit broadcasting has caused real incidents — strict-shape wins

Why: PyTorch, JAX, numpy all match; departure is a bug report (P5)

ADR-07

In-place safety

Chosen

Per-Storage atomic version counter

Rejected

Copy-on-write; banning in-place entirely

When the rejected choice is right

A pure-functional engine (JAX-shape, no mutation) — banning in-place wins outright there

Why: PyTorch's proven approach; in-place ops matter for memory-bound training loops (P6, I5)

ADR-08

Gradient accumulation

Chosen

Accumulate; .grad never auto-zeroed

Rejected

Auto-zero at every backward() call

When the rejected choice is right

A single-shot inference-only engine with no training loop — auto-zero (or no .grad at all) wins

Why: Supports gradient-accumulation training loops (P7)

ADR-09

Mixed precision

Chosen

bf16 autocast region, per-op whitelist

Rejected

Full fp16 with loss scaling; full-network bf16

When the rejected choice is right

A model whose entire forward is numerically well-conditioned (e.g. small MLP on normalized inputs) — full bf16 wins on throughput

Why: bf16 has fp32's dynamic range; per-op partition protects softmax/norm (P8, §22)

ADR-10

CPU parallelism

Chosen

rayon work-stealing threadpool

Rejected

Hand-rolled work-stealing; tokio for compute

When the rejected choice is right

A workload dominated by I/O-bound async fan-out (the dataloader) — tokio wins, and is used there (ADR-11)

Why: Mature, proven, zero-cost abstraction over cores (§16.3)

ADR-11

Dataloader I/O

Chosen

tokio async runtime, bounded-channel prefetch

Rejected

Synchronous blocking reads; a second rayon pool

When the rejected choice is right

A dataset fully resident in RAM with no decode cost — synchronous blocking reads win (simpler, no runtime)

Why: Decode+prefetch is I/O-bound, not compute-bound; async fits (§20.2)

ADR-12

Graph fingerprinting (JIT cache keys)

Chosen

xxh3 non-cryptographic hash

Rejected

SHA-256

When the rejected choice is right

Model files crossing a trust boundary (untrusted download) — SHA-256 wins for integrity, not speed

Why: xxh3 is the fastest non-cryptographic hash; SHA-256 reserved for signing (§28)

ADR-13

Default dtype

Chosen

f32; f64/bf16/f16/ints/bool optional

Rejected

f64 default (numpy convention)

When the rejected choice is right

A scientific-computing workload prioritizing precision over throughput — f64-default wins

Why: f32 is the deep-learning throughput/memory default; f64 reserved for gradcheck (§4 M6)

ADR-14

conv2d strategy (CPU)

Chosen

im2col + matmul

Rejected

Direct convolution (Winograd/FFT)

When the rejected choice is right

Small 3x3 kernels at high channel count on a target with a tuned Winograd path — direct conv wins

Why: Reuses the matmul kernel (§16); direct conv is a documented Phase-extension (§38)

ADR-15

Vendor BLAS / cuBLAS

Chosen

Rejected for the default path; hand-written SIMD kernels

Rejected

FFI to OpenBLAS/cuBLAS by default

When the rejected choice is right

A production system where correctness-by-construction of the kernel is not the goal — vendor BLAS wins on raw throughput every time

Why: The point of the project is to own the kernel layer (§1); a blas feature is opt-in

ADR-16

Tracing/metrics

Chosen

OpenTelemetry (traces) + Prometheus (metrics)

Rejected

A bespoke logging format

When the rejected choice is right

A single-developer local-only workflow with no need for structured export — plain stderr logging wins

Why: Spans wrap every op/step/fetch; agctl inspect-tape emits OTLP (§27)

ADR-17

Build reproducibility

Chosen

sccache + Nix flake dev-shell

Rejected

Plain cargo build, no cache/pin

When the rejected choice is right

A single-maintainer project with one dev machine — plain cargo wins on setup simplicity

Why: Reproducible builds across maintainer machines (§28)

ADR-18

License

Chosen

Apache-2.0 (runtime crates)

Rejected

MIT-only; GPL/AGPL

When the rejected choice is right

A library targeting maximum permissiveness with zero patent concern — MIT-only wins

Why: Patent grant matters for a kernel library; dual MIT text kept for ecosystem convention

ADR-19

CUDA backend

Chosen

Raw cuda-sys-style FFI, hand-written kernels

Rejected

candle/cudarc dependency

When the rejected choice is right

A team needing GPU support in weeks, not months — candle/cudarc wins decisively

Why: Owning the kernel layer is the point (§1, mirrors ADR-15); Phase 12 (§24)

ADR-20

Metal backend

Chosen

metal-rs FFI, hand-written kernels

Rejected

MPS Graph wholesale

When the rejected choice is right

A team targeting only Apple platforms and wanting Apple-tuned kernels immediately — MPS Graph wins

Why: Same rationale as ADR-19; Phase 12 (§24)

ADR-21

Distributed training

Chosen

Ring all-reduce over tokio::net; nccl feature for GPU

Rejected

Parameter-server architecture

When the rejected choice is right

A very large (1,000+ node) heterogeneous cluster with stragglers — a parameter-server or hierarchical all-reduce wins

Why: Ring all-reduce has better bandwidth scaling at moderate node counts (§32); Phase 12 hook only

ADR-22

Gradient checkpointing

Chosen

Deferred to Phase 11 as a JIT-time transform

Rejected

A runtime opt-in recompute flag at any phase

When the rejected choice is right

A memory-constrained Phase-2..10 user training a deep MLP right now — a simple runtime opt-in wins short-term, at the cost documented in the register

Why: Adds real complexity to the backward engine (§8.4); better expressed once a graph is captured (§23, PhaseDeferred("§38"))

ADR-23

Tape scope

Chosen

Per-training-step; no global tape across steps

Rejected

A single global tape for the process lifetime

When the rejected choice is right

An offline one-shot differentiation of a single fixed expression (no training loop) — a global tape is simpler and fine

Why: A global tape leaks the first time a user forgets to reset it; per-step matches zero_grad()'s boundary (§4, §8.5)

37. Alternative Architectures (Roads Not Taken)

Alt-1 — Static graph, build-then-run (the TensorFlow 1.x shape).

   define graph (no execution)         session.run(graph, feed_dict)
   +-----------------------+            +------------------------+
   | placeholder -> op ->  |  compile   | partitioned, optimized |
   | op -> op -> output    | ---------> | executable graph runs  |
   +-----------------------+            +------------------------+

Regime where it wins: a fixed, unchanging graph shape deployed to a target with zero tolerance for per-step interpretation overhead (embedded inference, TPU pods running the same compiled program billions of times). Real system: TensorFlow 1.x (Abadi et al. 2016, §5). Rejected here (ADR-02) because it breaks the imperative debugging story (§2) that motivates this entire project — a stack trace through a graph executor is not the stack trace the user wrote.

Alt-2 — Fully functional, traced-and-compiled (the JAX shape).

   pure fn(params, x) -> loss     jax.grad traces once per shape
   +------------------------+      +--------------------------+
   | no mutation; every op  | ---> | XLA-compiled executable,  |
   | is a pure transform    |      | re-run for matching shapes|
   +------------------------+      +--------------------------+

Regime where it wins: research code that re-executes the same shape thousands of times (RL loops, scientific computing sweeps) where whole-program compilation amortizes and purity simplifies reasoning about parallelism. Real system: JAX (Bradbury et al. 2018, §5). Rejected here (ADR-08) because .grad-mutation and in-place ops (P6, P7) are load-bearing for this design's PyTorch-shaped training-loop ergonomics, and giving them up trades away exactly the imperative debuggability §2 targets.

Alt-3 — Lazy-by-default with aggressive fusion (the Tinygrad shape).

   op call -> LazyBuffer (no compute yet) -> .realize() triggers
   +------------------------+                +---------------------+
   | graph of unexecuted    |  scheduling +   | fused kernel(s)     |
   | lazy ops accumulates   |  codegen        | actually dispatched |
   +------------------------+                +---------------------+

Regime where it wins: a small, hackable framework where kernel fusion is the primary performance lever and the whole stack (tensor to codegen) must fit in one person's head. Real system: Tinygrad (Hotz et al., §5). Rejected as the default here (ADR-05) because lazy-by-default conflates scheduling with autograd (§5 ref-impl pitfall), complicating the Phase 0-2 correctness kernel this design prioritizes first (P13); Phase 11's opt-in JIT (§23) recovers most of the fusion benefit without that coupling.

Alt-4 — Source-to-source compiler-transformation AD (the Enzyme/Zygote shape).

   source fn                    compiler pass rewrites the fn's
   (Rust/LLVM IR/Julia AST)     IR/AST into an adjoint-computing fn
   +----------------------+     +-------------------------------+
   | ordinary program,     | -> | no runtime tape at all; the    |
   | no tape at runtime     |    | derivative IS compiled code   |
   +----------------------+     +-------------------------------+

Regime where it wins: differentiating existing, unmodified numerical code (legacy Fortran/C++/LLVM IR) without any operator-overloading API — Enzyme operates directly on LLVM IR; Zygote operates on Julia's IR via source-to-source transformation. Real systems: Enzyme (LLVM-level AD) and Zygote (Julia). Rejected here because it requires a compiler-pass-level integration far beyond a library's scope (§1 — this is a linked Rust library, not a compiler plugin), and it sacrifices the tape's runtime inspectability (agctl inspect-tape, §14.10) that this design's debugging story (§2) depends on.
