32. Mental Models & First Principles

  • MM1 — A series is a label set, not a name. The compressed insight: cardinality is the number of distinct label-set values, not the number of metric names. Predicts: adding one high- cardinality label multiplies cost by that label's cardinality, not by 1. Bug class without it: "we only have 50 metrics, why is memory exploding" (FM-2). Applied §16, §23.
  • MM2 — Compaction is a scheduled rewrite, not a cleanup. The insight: compaction exists to convert append-cost into read-cost amortization (Kleppmann's log-structured pattern). Predicts: a compactor falling behind degrades query latency before it degrades ingest. Bug class without it: treating compaction as optional housekeeping. Applied §18.
  • MM3 — A WAL trades latency for durability at a knob, not a binary. The insight: fsync batching is a continuous RPO/throughput tradeoff (Mohan 1992's steal/no-force framing). Predicts: the "right" fsync interval depends on the workload's tolerance for a bounded loss window. Bug class without it: assuming "WAL present" means "zero data loss." Applied §16.
  • MM4 — PromQL evaluation is a pure function of the AST and the sample set. The insight: determinism (I8) is what makes differential testing against the Prometheus reference possible at all. Predicts: any evaluator behavior depending on wall-clock time outside the query's own time parameter is a correctness bug. Bug class without it: flaky conformance tests. Applied §20, §28.
  • MM5 — Cardinality defense must happen before allocation, not after observation. The insight: a cap checked post-hoc has already paid the memory cost it was meant to prevent. Predicts: a "cardinality alert" without a pre-allocation cap is a warning, not a mitigation. Bug class without it: OOM despite dashboards showing the warning fired. Applied §14, §23.
  • MM6 — Multi-tenancy is a storage-layer property, not an API-layer filter. The insight: an API-level tenant filter can be bypassed by a bug anywhere upstream of it; a storage-layer partition cannot. Predicts: I7 violations are caught even when the API layer has a bug. Bug class without it: cross-tenant data leaks from an unrelated API regression. Applied §23, §24 (T-8).
  • MM7 — Pull inverts the trust and failure direction of push. The insight: with pull, the consumer controls load and can always inspect a producer manually; with push, the producer controls load and the consumer must defend itself. Predicts: pull systems fail closed (missing data, visible as gaps) where push systems fail open (overload) absent explicit backpressure. Bug class without it: building push-style backpressure into a pull system unnecessarily. Applied §15, §36.
  • MM8 — Compression ratio is a property of the data's temporal locality, not a fixed constant. The insight: Gorilla's ratio depends on scrape-interval regularity and value-change frequency. Predicts: nanosecond-jittered timestamps or highly volatile values degrade the ratio toward the raw floor. Bug class without it: benchmarking compression on synthetic constant data and shipping a false expectation. Applied §17.

5. Required Reading

Books

  • Brian Brazil, Prometheus: Up & Running, O'Reilly, 2018. Ch. 3 ("Metric Types"), Ch. 8 ("Alerting"). Extract: the canonical counter/gauge/histogram/summary semantics and the alerting contract. Applied in §8, §21.
  • Alex Petrov, Database Internals, O'Reilly, 2019. Part I Ch. 2–4 (storage engines, B-Trees vs LSM), Ch. 7 (write-ahead logging). Extract: WAL segmenting, checkpoint/replay discipline, compaction trade-offs. Applied in §16, §18.
  • Martin Kleppmann, Designing Data-Intensive Applications, O'Reilly, 2017. Ch. 3 ("Storage and Retrieval" — log-structured storage, compaction). Extract: the append-only-write / background-compaction pattern this TSDB reuses. Applied in §17, §18.
  • Jon Gjengset, Rust for Rustaceans, No Starch Press, 2021. Ch. 6 ("Concurrency"). Extract: atomics for lock-free Counter/Gauge, and where a lock is unavoidable (Summary quantiles). Applied in §14, §16.
  • Betsy Beyer, Chris Jones, Jennifer Petoff, Niall Murphy (eds.), Site Reliability Engineering, O'Reilly, 2016. Ch. 4 ("Service Level Objectives"), Ch. 6 ("Monitoring Distributed Systems"). Extract: the SLO/error-budget vocabulary used throughout §26/§30. Applied in §26, §30.
  • Brendan Gregg, Systems Performance, 2nd ed., Addison-Wesley, 2020. Ch. 2 ("Methodology"), Ch. 6 ("CPU"). Extract: the USE-method benchmarking discipline behind §30's hot-path breakdowns. Applied in §30.

Papers

  • Pelkonen et al. (Facebook), "Gorilla: A Fast, Scalable, In-Memory Time Series Database", VLDB 2015. Delta-of-delta timestamp + XOR value compression. Applied in §17.
  • Adams et al. (Google), "Monarch: Google's Planet-Scale In-Memory Time Series Database", VLDB 2020. Planet-scale multi-tenant sharding and query fan-out. Applied in §23, §31.
  • Fabian Reinartz, "Writing a Time Series Database from Scratch" (Prometheus team design blog, 2017). TSDB rationale: why head + WAL + immutable block. Applied in §16, §18.
  • Björn Rabenstein / Julius Volz, Prometheus TSDB design docs (prometheus/prometheus, tsdb/docs/format/). The on-disk block/chunk/index format this design mirrors. Applied in §16, §18.
  • C. Mohan et al., "ARIES: A Transaction Recovery Method", ACM TODS 1992. WAL/checkpoint correctness discipline (steal/no-force, redo-only replay). Applied in §16.
  • G. DeCandia et al. (Amazon), "Dynamo: Amazon's Highly Available Key-value Store", SOSP 2007. Consistent-hash sharding and partition tolerance. Applied in §23.
  • M. Greenwald, S. Khanna, "Space-Efficient Online Computation of Quantile Summaries", SIGMOD 2001. Streaming quantile estimation behind the Summary metric type. Applied in §14.
  • T. Dunning, O. Ertl, "Computing Extremely Accurate Quantiles Using t-Digests", arXiv 2019. t-digest structure for client-side quantile aggregation. Applied in §14.
  • Gil Tene, HdrHistogram design documentation ("How NOT to Measure Latency"). High-dynamic- range histogram bucket layout, relevant to histogram_quantile error bounds. Applied in §14, §20.
  • OpenMetrics Working Group (CNCF), "OpenMetrics Specification 1.0.0". The successor exposition format. Applied in §13.

Reference Implementations

  • Prometheus — github.com/prometheus/prometheus. Study tsdb/, promql/, scrape/, discovery/, rules/. Lesson: the head/WAL/block split. Pitfall not to copy: the Go GC pause under high cardinality (§4, ADR-01). Applied in §16–21.
  • VictoriaMetrics — github.com/VictoriaMetrics/VictoriaMetrics. Study lib/storage. Lesson: a more aggressive, MergeTree-inspired encoding trades flexibility for ratio. Pitfall: its encoding is not chunk-random-access-friendly. Applied in §17.
  • Grafana Mimir — github.com/grafana/mimir. Study pkg/ingester, pkg/distributor. Lesson: distributor-based per-tenant sharding at SaaS scale. Pitfall: the distributor is a single point of fan-out amplification if unbounded. Applied in §23.
  • Thanos — github.com/thanos-io/thanos. Study pkg/compact, pkg/store. Lesson: object- store-backed long-term blocks plus a Store API for federation. Pitfall: compactor singleton-per-tenant is a scaling bottleneck if not sharded. Applied in §18, §22.
  • M3DB — github.com/m3db/m3. Study src/dbnode/storage. Lesson: a sharded, replica-aware index design. Pitfall: its own query language forked from PromQL, causing ecosystem drift. Applied in §18, §23.
  • InfluxDB — github.com/influxdata/influxdb. Study tsdb/engine/tsm1. Lesson: the TSM alternative chunk encoding. Pitfall: TSM compaction stalls under sustained high-cardinality writes — the reason this design keeps compaction background and non-blocking (§18). Applied in §17.

RFCs / Specifications

  • OpenMetrics Specification 1.0.0 (github.com/OpenObservability/OpenMetrics). Applied in §13.
  • Prometheus Remote Write Specification (1.0 and 2.0) (prometheus.io/docs/concepts/remote_write_spec/). Applied in §22.
  • Prometheus Exposition Format (prometheus.io/docs/instrumenting/exposition_formats/). Applied in §13.

Glossary (§38) · 42 terms · site-wide glossary

Alert
A rule instance that transitions to Firing when its expression matches for its for-duration.
Alertmanager
The external component (delegated, §1) responsible for alert routing, grouping, and silencing.
Cardinality
The number of distinct label-set values for a given metric.
Checkpoint
A snapshot of the head block that lets WAL replay start from a later offset.
Chunk
An immutable, Gorilla-compressed block of samples for one series over one time window.
Cold tier
Object-store-backed long-term storage for daily-compacted chunks.
Compaction
The background process converting WAL/head data into immutable chunk files (hourly) and merging small chunks into larger ones (daily).
Counter
A monotonically non-decreasing metric type.
Delta-of-delta
The second-order difference of consecutive timestamps, the basis of Gorilla's timestamp compression.
Discovery (service discovery)
The pluggable mechanism (static/file/DNS/K8s) producing the scrape target list.
Federation
A pull query (/federate) composing the most-recent value across matching series, not a durable forward.
Gauge
A metric type whose value can move up or down arbitrarily.
Gorilla
The Facebook Pelkonen et al. 2015 in-memory time-series compression scheme (delta-of-delta timestamps + XOR values).
Head block
The in-memory, queryable, currently-being-appended-to store for the most recent time window.
Histogram
A metric type recording cumulative le-bucketed observation counts plus sum and count.
Instant vector
A PromQL result type: one value per series at a single timestamp.
Inverted index
The label-pair → series-ID-set structure enabling selective series lookup.
Label set
The canonical, sorted, deduplicated set of (name, value) pairs identifying a series.
Matcher
A label-pair predicate (=, !=, =~, !~) used in a PromQL vector selector.
Multi-tenancy
Storage-layer isolation of independent tenants' data (I7).
OpenMetrics
The CNCF successor exposition format to Prometheus text format.
PromQL
The Prometheus Query Language; this system's query language (ADR-05).
Pull (scrape)
The default ingestion model: the system fetches /metrics from targets on its own schedule.
Push (remote-write)
The secondary ingestion model: a producer sends samples to the system.
Range vector
A PromQL result type: a series of (value, timestamp) pairs over a duration, per series.
Recording rule
A periodically-evaluated rule whose result is written back to the TSDB as a new series.
Relabeling
Per-target label transformation applied before scrape (rename/drop/keep/shard).
Remote read
The protocol serving streamed sample chunks to an external reader.
Remote write
The protocol accepting pushed samples via Snappy-compressed Protobuf.
Reset detection
The rate()-time heuristic treating a counter decrease as a process restart.
Retention
The per-tenant duration after which chunks become eligible for deletion (I9).
Sample
A (series_id, timestamp_ms, value) triple.
Series
A unique time series identified by metric name + canonical label set.
Series ID
The 64-bit FNV1a hash of a canonical label set (I1).
Shard
An independent process/storage partition serving one or more tenants (never split across a single tenant, I7).
Stale marker
The reserved NaN bit-pattern signaling a series has ended (I11).
Summary
A client-aggregated quantile metric type (t-digest-backed).
Tenant
The unit of storage and query isolation (ADR-07, I7).
TSDB
Time-Series Database — this system's storage engine (head + WAL + chunks + index).
Vector matching
The PromQL rule set (one-to-one, ignoring/on, group_left/ group_right) governing how two vectors combine in a binary operation.
WAL (Write-Ahead Log)
The append-only, checksummed, segmented durability log underlying crash recovery (I2, I4).
XOR encoding
Gorilla's value-compression technique: XOR each value with its predecessor and store only the changed bit window.
