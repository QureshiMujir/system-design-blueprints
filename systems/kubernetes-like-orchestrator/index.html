Per-box.

  • apiserver — the only writer to store. Stateless, horizontally scalable. Terminates auth, runs the admission chain (mutating then validating), enforces schema + optimistic concurrency, and fans out watch streams. All other components are clients; they never touch store directly. This is the single serialization point that makes the cluster reasoned-about.
  • store — MVCC KV: every key carries a monotonically increasing global revision; watchers resume from a revision; compaction reclaims old revisions. Phase 0 embeds a single-node MVCC engine (BoltDB-style B+tree pages + in-memory watch index). Phase 12 promotes it to a Raft group.
  • registry (REST) — per-resource strategy objects implementing Create/Get/List/Update/Delete/Watch with defaulting, validation, and resourceVersion CAS. Maps REST verbs to store ops; owns the metadata lifecycle (uid, generation, creationTimestamp, deletionTimestamp, finalizers).
  • admission chain — ordered mutating plugins (defaulting, owner-ref injection, resource-quota debit) then validating plugins (schema, immutable-field, quota check). Webhook plugins deferred (Phase 9, §9.10).
  • informer caches — per-controller local replicas of a resource type, populated by an initial List then kept live by a Watch; deliver Add/Update/Delete deltas into a workqueue. The mechanism that lets dozens of controllers observe state without melting the store.
  • scheduler — watches unbound Pods (spec.nodeName==""), runs filter (feasibility: resources, taints, affinity, ports) then score (spread, least-allocated), then issues a Bind write that sets nodeName. Stateless; restart-safe (re-derives from store).
  • controller-manager — hosts reconciler loops: ReplicaSet (Pod count), Deployment (rollout/rollback over ReplicaSets), Node (heartbeat→Ready/NotReady, eviction), Endpoints (Service↔Pod IP mapping), GC (orphan deletion via owner refs). Leader-elected so exactly one instance acts.
  • kube-proxy — per-node; watches Services + Endpoints; programs the local dataplane so a Service VIP load-balances to ready backend Pod IPs. Backends: userspace (portal proxy, debuggable), iptables (DNAT chains), IPVS (hash/RR/least-conn).
  • kubelet — per-node agent; watches Pods bound to its node; drives each Pod's lifecycle through a PodWorker; runs liveness/readiness/startup probes; mounts volumes; reports Pod + Node status back to apiserver. The data-plane reconciler.
  • cri-shim — translates kubelet's CRI gRPC (RunPodSandbox, CreateContainer, StartContainer, ...) into OCI runtime calls; manages the pause/sandbox container, shared network namespace, and image unpacking.
  • dataplane (iptables/IPVS) — kernel-level packet rewriting installed by kube-proxy; the fast path that needs no control-plane round trip per packet.

Boundaries. Trust: control plane ↔ node (mTLS, node identity, node-restriction authz). Concurrency: every controller is an independent loop; the workqueue + optimistic CAS are the only synchronization. Persistence: only store persists; everything else is a cache rebuildable from store. Protocol: REST/watch (north), CRI gRPC (kubelet↔shim), CNI exec (shim↔plugin), Raft (store↔store, Phase 12).

8.4 Watch protocol

GET /api/v1/namespaces/ns/pods?watch=1&resourceVersion=V → chunked stream of {type: ADDED|MODIFIED|DELETED|BOOKMARK, object:{...}}. Client tracks last RV; on disconnect, resumes from it; on 410 Gone (RV compacted) it relists and resumes from the list's RV. BOOKMARK events advance the client RV without payload to keep resume cheap.

8.5 Reconcile sequence (Deployment rollout, worked example)

user: apply Deployment replicas=3 image=v2 (was v1, RS-A has 3 v1 pods)
 deployment-ctlr: see spec change → gen=2
   → create RS-B (v2, replicas=0), compute surge: maxSurge=1,maxUnavailable=0
   → scale RS-B→1, wait readyReplicas, scale RS-A→2  (repeat)
   → ... RS-B→3, RS-A→0
 RS-ctlr (per RS): replicas - actual = delta → create/delete Pods (owner=RS)
 scheduler: each new Pod (nodeName="") → filter→score→bind nodeName
 kubelet(N): watch Pod bound to N → CRI RunPodSandbox→pull→CreateContainer→Start
   → readiness probe pass → Pod.status Ready → endpoints-ctlr adds podIP
 deployment-ctlr: updated==available==3, observedGeneration=2 → Progressing=True,reason=NewReplicaSetAvailable

8.6 Malformed / failure-path examples

  • Apply Pod with nodeName already set to a non-existent node → admission passes (valid shape) but kubelet never claims it; node controller never reports it; Pod stuck Pending → surfaced via unschedulable/orphan metric.
  • Update with stale resourceVersion → 409 Conflict; client must GET-merge-retry (orctl does this automatically for apply).
  • Two schedulers bind same Pod → first CAS wins, second gets 409 and re-enqueues; I5 preserved.
  • Delete Namespace with live Pods → Namespace→Terminating, namespace controller deletes contained objects, finalizer removed last → gone.

Design principles (§6)

  • P1 — Declarative desired state, never imperative commands. Clients write what they want; controllers compute how. Tradeoff: indirection vs robustness. Operationally: any client can re-declare and the system converges. Violation: an imperative "create container X now" API has no truth to reconcile against after a crash — state drifts permanently.
  • P2 — Level-triggered, not edge-triggered. Reconcile against current observed state, not against the event that woke you. Tradeoff: periodic resync cost vs correctness under lost events. Violation: missing one "Pod deleted" event leaks the Pod forever; level-triggered relist heals it.
  • P3 — The store is the single source of truth. All durable state lives in store; every other component is a cache rebuildable from it. Tradeoff: store is the bottleneck + SPOF (until Phase 12). Violation: a controller caching authoritative state means a restart loses cluster truth.
  • P4 — Optimistic concurrency, no cross-object locks. Writes carry resourceVersion; conflicting writes lose and retry. Tradeoff: retry churn under contention vs no lock-ordering deadlocks. Violation: pessimistic locks across objects deadlock controllers against each other.
  • P5 — Idempotent reconciliation. Running a reconcile twice with the same input yields the same result. Tradeoff: must dedupe by identity (owner refs, names) not by "did I already act." Violation: non-idempotent create on retry spawns duplicate Pods.
  • P6 — Data plane survives control-plane outage. Running containers keep running when apiserver/scheduler/controllers are down. Tradeoff: stale node config during partitions. Violation: a kubelet that kills Pods when it loses the apiserver turns a control-plane blip into an outage.
  • P7 — Generation / observedGeneration for progress. spec bumps metadata.generation; controllers record status.observedGeneration. Tradeoff: extra status writes. Violation: clients cannot tell "applied" from "in flight," and rollouts look done before they are.
  • P8 — Owner references + finalizers for lifecycle. Children point at owners; finalizers gate deletion until cleanup runs. Tradeoff: deletion is multi-step, not instant. Violation: deleting a Deployment orphans ReplicaSets and Pods; missing finalizers leak external resources.
  • P9 — Watch over poll. Controllers consume change streams from a local informer, not periodic full lists. Tradeoff: watch-cache memory + relist-on-gap complexity. Violation: N controllers polling LIST melts the store at scale.
  • P10 — Backpressure + bounded workqueues everywhere. Rate-limited, deduped, exponential-backoff queues between watch and reconcile. Tradeoff: latency under burst. Violation: unbounded reconcile fanout OOMs the controller and stampedes the apiserver.
  • P11 — Explicit API versioning + conversion. Served versions convert to one internal version; storage version is pinned. Tradeoff: conversion code. Violation: persisting the served wire shape freezes the API forever.
  • P12 — Crash-only components. Every process can be kill -9'd and restarts clean by re-reading store. Tradeoff: no in-memory-only invariants. Violation: graceful-only shutdown logic rots and fails exactly during the incident.
  • P13 — Observable by default. Every loop emits queue depth, reconcile latency, error counters, and per-object events. Tradeoff: cardinality management. Violation: a wedged controller is invisible until users complain.
  • P14 — Least privilege between roles. Node identity ≠ admin; the node-restriction plugin limits what a kubelet can write. Tradeoff: authz complexity. Violation: a compromised node rewrites the whole cluster.
