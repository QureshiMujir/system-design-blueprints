Each card is one row of the blueprint's decision table: what was locked in, what was rejected, and — the column that matters most — the situation in which the rejected choice is the right one.

Decisions (§9) · 32 ADRs

001

Language

Chosen

Rust 1.78+ (ed. 2021), scoped unsafe

Rejected

C, C++, Go, Java

When the rejected choice is right

C wins when you must link the real DPDK/VPP codebase or target a platform with no Rust toolchain (some embedded NPUs); Go wins for a control-plane daemon where developer velocity beats the cycle budget and packets never touch it.

Why: Ownership for mbuf/DMA lifetime; Send/Sync per-core sharding at compile time; no GC p99 tax; fuzz/Miri/loom.

002

Hugepage mapping

Chosen

mmap(MAP_HUGETLB) via libc, safe wrapper HugeAlloc

Rejected

posix_memalign, transparent hugepages

When the rejected choice is right

THP wins on a host where you cannot reserve hugepages at boot (shared/cloud VM with no nr_hugepages control) and a small TLB-miss tax is acceptable; posix_memalign wins for a pure-functional unit test that never touches the device.

Why: Explicit huge TLB; contiguous; NUMA-pinnable.

003

Build

Chosen

Cargo workspace, multi-crate

Rejected

Bazel, Make

When the rejected choice is right

Bazel wins inside a large polyglot monorepo where the dataplane is one target among thousands and remote caching/hermeticity dominate; Make wins when wrapping a C FFI build that Cargo cannot drive natively.

Why: Native, reproducible (Cargo.lock).

004

Threading

Chosen

OS threads pinned (sched_setaffinity), busy-poll

Rejected

async runtime (tokio), thread pool

When the rejected choice is right

An async runtime wins for the control plane and for a low-rate edge dataplane (≤100 kpps) where burning a whole core idle is wasteful and interrupt/epoll latency is acceptable — the interrupt-mode regime DPDK itself added (rte_eth_dev_rx_intr_*).

Why: Dataplane is CPU-bound poll loops; async adds overhead + nondeterminism.

005

Atomics/ordering

Chosen

core::sync::atomic with explicit Ordering

Rejected

SeqCst everywhere, Mutex

When the rejected choice is right

SeqCst everywhere wins for a first-draft or a rarely-touched control structure where correctness-by-simplicity beats the few-cycle fence cost; a Mutex wins for a cold-path config table mutated once per minute.

Why: Acquire/release is correct + fast ring model; SeqCst over-synchronizes.

006

Cross-core queue

Chosen

custom uns-ring (SPSC+MPMC)

Rejected

crossbeam channels, std::mpsc

When the rejected choice is right

crossbeam wins when you want a growable/blocking channel with backpressure-by-blocking (not drop-on-full) off the hot path — e.g. the control→dataplane command queue, where losing a command is worse than blocking.

Why: Need rte_ring exact semantics (burst reserve, mask index, drop-on-full).

007

Fast-path backend

Chosen

AF_XDP (libc/raw XSK setup), safe wrapper

Rejected

DPDK bindings, raw PCIe

When the rejected choice is right

DPDK PMD over VFIO wins when you own the NIC exclusively and need the absolute ceiling (100/200 GbE, hardware RSS/flow-director/inline crypto) that the kernel seam cannot match; raw PCIe only inside a unikernel/bare-metal with no OS.

Why: AF_XDP is the real, portable Linux kernel-bypass fast path; no root-VFIO needed.

008

Portable backend

Chosen

AF_PACKET v3 (TPACKET_V3 mmap block ring)

Rejected

raw AF_PACKET (no mmap)

When the rejected choice is right

Raw AF_PACKET (recvmsg/sendmsg, no mmap) wins for a trivial diagnostic tap or a one-off capture tool where setup simplicity beats throughput and per-packet syscall cost is irrelevant.

Why: Works without XDP; mmap block ring batches RX.

009

Test backend

Chosen

in-memory virtual NIC (uns-vnic)

Rejected

loopback netns

When the rejected choice is right

A loopback netns wins for an integration test that must exercise the real kernel seam (AF_XDP/AF_PACKET bind, XDP attach) — the differential oracle in §Phase 12 deliberately uses it, because determinism there is a non-goal.

Why: Deterministic, no kernel, replayable.

010

mbuf/mempool

Chosen

custom (uns-mbuf/uns-mempool)

Rejected

bytes::Bytes, Vec pools

When the rejected choice is right

bytes::Bytes wins for an application-layer service (HTTP/gRPC) where refcounted slices and ergonomic ownership matter more than headroom/offload metadata and a fixed cycle budget.

Why: Need headroom/refcount/ol_flags + per-core magazine + zero-alloc.

011

LPM

Chosen

DIR-24-8 (IPv4) + 16-stride trie (IPv6)

Rejected

binary trie only, hash-LPM

When the rejected choice is right

A binary/Poptrie-style trie wins when memory is tight and the 64 MiB tbl24 is unaffordable (embedded), or for IPv6 where a 2²⁴ first level is impossible; hash-LPM wins when prefixes are few and exact-length so a hash beats a trie.

Why: O(1)/O(2) lookup at line rate (Gupta 1998).

012

Exact-match table

Chosen

cuckoo hash (uns-classify)

Rejected

open-addressing linear, chaining

When the rejected choice is right

Linear-probe open addressing wins at low load factor where one cache line holds the probe sequence (better locality than cuckoo's two random buckets); chaining wins when inserts must never fail and rehash pauses are unacceptable.

Why: Worst-case O(1) lookup, bounded probe (Pagh 2004).

013

Table concurrency

Chosen

RCU (epoch) + seqlock for small tables

Rejected

RwLock, Mutex

When the rejected choice is right

An RwLock wins when updates are frequent relative to reads and bounded reader staleness is unacceptable (a strongly-consistent config read); a Mutex wins for a tiny table touched only off the hot path.

Why: Lookup-safe, reader never blocks (I7).

014

RSS hash

Chosen

Toeplitz, fixed 40 B key

Rejected

jhash, CRC

When the rejected choice is right

CRC32 (hardware crc32 instruction) wins for software RSS where you don't need NIC-compatibility and want fewer cycles than a Toeplitz bit-walk; jhash wins inside a self-contained hash table that never has to match a NIC's distribution.

Why: MS RSS spec standard; symmetric variant; deterministic (I10).

015

Serialization (config/telemetry)

Chosen

serde + JSON; bincode for pcap index

Rejected

protobuf

When the rejected choice is right

protobuf wins when the telemetry/config schema is shared across many services and languages and needs a strict, versioned IDL with codegen — a multi-team control plane.

Why: Human-diffable config; standard.

016

pcap

Chosen

libpcap file format (writer/reader in uns-telemetry)

Rejected

custom

When the rejected choice is right

A custom format wins when you need per-packet metadata libpcap can't carry (per-core arrival TSC, drop reason, flow state) at high capture rates — pcapng or a bespoke columnar trace then beats classic pcap.

Why: Interop with tcpdump/wireshark + scapy.

017

Logging

Chosen

tracing (off hot path)

Rejected

log + env_logger

When the rejected choice is right

log + env_logger wins for a tiny tool or example binary where structured spans are overkill and a one-line logger is enough.

Why: Structured spans for control/setup; never per-packet.

018

Metrics

Chosen

per-core counters → aggregated metrics→Prometheus

Rejected

atomic global counters

When the rejected choice is right

Atomic global counters win for a cold-path event counted a few times per second (config reloads, port up/down) where the simplicity beats per-core aggregation and contention is nil.

Why: Zero false-sharing on hot path (I14).

019

Latency histograms

Chosen

HDR histogram (hdrhistogram)

Rejected

fixed buckets

When the rejected choice is right

Fixed buckets win when you only need a coarse SLO check (under/over a single threshold) and want a trivially-mergeable, fixed-memory counter array — a cheap dashboard gauge.

Why: Accurate tail (p99/p999) at low cost.

020

Testing

Chosen

cargo test, proptest, insta

Rejected

only unit

When the rejected choice is right

Unit-only wins for a stable, total function with a small finite domain (e.g. a 16-bit checksum fold) where exhaustive or table-driven unit tests already cover it and property generators add no coverage.

Why: Property tests for ring/refcount/checksum invariants.

021

Differential oracle

Chosen

scapy-generated packets + kernel stack (netns)

Rejected

none

When the rejected choice is right

No differential is acceptable only for behavior with no external reference to compare against (a bespoke QoS policy with no standard) — there the conformance golden vectors stand alone.

Why: Parse/forward/checksum cross-validation.

022

Fuzzing

Chosen

cargo fuzz (packet parser, config)

Rejected

AFL raw

When the rejected choice is right

AFL/AFL++ wins when fuzzing a binary (the sample-app process end-to-end) rather than a Rust library entry point, or when you need its CFG-aware mutators on a non-Rust component.

Why: Parser must never OOB/panic on adversarial frames.

023

Concurrency testing

Chosen

loom (rings, RCU, magazine)

Rejected

stress-only

When the rejected choice is right

Stress testing wins to surface bugs that depend on timing/scale (cache-line contention, real preemption, NUMA effects) that loom's bounded model abstracts away — the two are complementary, stress for what loom can't model.

Why: Exhaustive interleavings for I1/I3.

024

UB checking

Chosen

When the rejected choice is right

No Miri is fine for a 100%-safe crate (no unsafe) — e.g. a pure parsing crate built only on slices — where there is no UB surface for Miri to check.

Why: Catch unsafe-buffer mistakes; scoped unsafe verified.

Alternative Architectures (Roads Not Taken)

Three fundamentally different architectures for the same goal (line-rate userspace/host packet processing), each embodied by a real system, with the regime where it wins and why this blueprint rejected it.

Alt-1 — In-kernel XDP/eBPF dataplane (no userspace bypass).

   NIC ──IRQ/NAPI──▶ XDP hook (eBPF program, in driver)
                       │  verdict: XDP_DROP / XDP_TX / XDP_REDIRECT
                       ├─▶ XDP_REDIRECT ─▶ another netdev / CPU / AF_XDP socket
                       └─▶ XDP_PASS ─▶ normal kernel stack (skb)
   (program is JIT'd in-kernel; runs before skb allocation)

Regime where it wins: DDoS scrubbing, load balancing, and per-packet filtering where you want to run inside the kernel before skb allocation, share the NIC with the host stack, and deploy/upgrade a small program without a dedicated core or a separate process. Embodied by Cilium / Katran (Facebook's XDP L4 load balancer) and the XDP framework (Høiland-Jørgensen, CoNEXT 2018, paper 2). Why rejected here: the eBPF verifier bounds program complexity (no unbounded loops, limited state), so full stateful L2–L4 processing, hierarchical QoS, and conntrack/NAT at this richness do not fit the model; and the goal of this project is to teach the dataplane mechanisms themselves (mempool, rings, PMD), which XDP hides inside the kernel. We instead consume AF_XDP as a backend (§Phase 2) rather than living inside the XDP hook.

Alt-2 — Microkernel / dataplane-OS with hardware-enforced isolation.

   ┌──────────── control plane (full OS kernel) ────────────┐
   │  sets up protection domains, NIC queues, memory         │
   └───────────────────────┬─────────────────────────────────┘
                            │ (control only; off the data path)
   ┌──────────── data plane (per-app protection domain) ─────┐
   │  app owns its NIC queue directly (hardware-virtualized) │
   │  run-to-completion, zero syscalls, batched, polled       │
   └──────────────────────────────────────────────────────────┘

Regime where it wins: multi-tenant hosts that need both line rate and hardware-enforced isolation between untrusted dataplane apps — the OS sets up protected NIC queues once, then each app runs its own dataplane with the kernel fully off the path. Embodied by Arrakis (Peter et al., OSDI 2014, paper 6) and IX (Belay et al., OSDI 2014, paper 5), which split control/data planes and give apps direct, protected device access. Why rejected here: it requires SR-IOV / hardware virtual functions and a custom OS or dom0-style control plane — explicitly a non-goal of this blueprint (§1: no SR-IOV, no VF passthrough). We borrow the control/data-plane split (§3 architecture, telemetry socket) and the run-to-completion model (IX → §Phase 8) without the hardware-isolation machinery; the dataplane-OS regime wins when you must isolate mutually-distrusting tenants at line rate.

Alt-3 — Interrupt-driven, allocate-per-packet socket stack (the thing we are not building).

   NIC ──IRQ──▶ softirq/NAPI ──▶ alloc skb ──▶ protocol stack
                                      │  copy to socket buffer
                                      └─▶ recvmsg() syscall ──▶ app
   (one interrupt + one skb alloc + one copy + one syscall per packet-ish)

Regime where it wins: the overwhelming majority of applications — anything that is not bottlenecked on packet rate. At ≤1 Mpps with bursty, latency-tolerant traffic, paying the kernel tax (MM3) buys you the entire mature kernel stack (TCP, routing, netfilter, sockets) for free, with no dedicated cores burned and no special privileges. Embodied by the Linux network stack itself (Bovet & Cesati, book 9), the reference our differential oracle compares against (§Phase 12). Why rejected here: it caps at ~1 Mpps/core and adds unbounded latency jitter from interrupts and allocation (principle 1/2) — precisely the wall this entire project exists to break through; but it is the correct choice whenever the cycle budget (MM2) is not the binding constraint, which is why it remains the default for general-purpose hosts.
