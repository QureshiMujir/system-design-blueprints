⬜ Phase 0 — Repo Skeleton, EAL (hugepages + lcore pinning + per-core), mbuf + mempool, vNIC PMD, Burst RX/TX, L2-Forward

Objectives

Stand up the workspace; build the EAL (hugepage allocator, lcore launch + CPU affinity, PerCore<T>); implement Mbuf + single-core Mempool; the in-memory uns-vnic PMD; the burst rx_burst/tx_burst API; an L2-forward sample that polls, swaps MACs, transmits. Single-core only (rings + multi-core in §Phase 1).

Deliverable

uns-l2fwd --vnic --pkts 1e6 -l 0 runs single-core: polls 1M frames from vNIC, swaps MACs, TXes; prints PortStats; cargo test green; Miri clean on mbuf/mempool unsafe paths.

Acceptance
  • L2-forward correctness: every input frame egresses with MACs swapped, bytes otherwise identical (differential vs golden).
  • ≥ 10 Mpps single-core on vNIC, 64 B frames (no kernel) — first throughput gate.
  • Zero heap allocations on the forward loop (allocator hook = 0, I4).
  • Config validator rejects 4 malformed configs (non-pow2 ring, undersized mempool, bad core mask, missing huge-dir) with correct error.
  • Hugepages unmapped + mbufs accounted at exit (I13).
Fixtures
  • conformance/packets/l2_basic.pcap — input frames. golden/l2fwd_swapped.pcap — expected output. templates/cfg_1core_vnic.json — baseline config. Malformed: cfg_ring_not_pow2.json, cfg_mempool_too_small.json (I12 reject).
Pitfalls
  • Headroom/tailroom off-by-one → header rewrite corrupts adjacent bytes. Root: wrong data_off math. Debug: byte-diff vs golden (I8). Recover: bounds-checked prepend/adj.
  • Hugepage mmap fails silently (no MAP_HUGETLB reserve) → falls back to normal pages → TLB thrash. Root: nr_hugepages not set. Debug: /proc/meminfo HugePages_Free; numastat. Recover: setup-hugepages.sh, fail-fast if reserve < needed.
  • lcore not actually pinned → OS migrates thread → cache + NUMA misses. Root: affinity mask wrong. Debug: /proc/<tid>/stat CPU; taskset. Recover: assert affinity post-pin.
  • Mempool under-sized → rx_burst starves under burst. Root: sizing < in-flight. Debug: mempool_exhausted. Recover: size = §4 formula; validator check (I12).

⬜ Phase 1 — Lockless Rings (SPSC then MPMC), Per-Core Mempool Cache (Magazine), Multi-Core Run-to-Completion

Objectives

Add uns-ring (SPSC then MPMC, correct memory ordering — I1, bounded — I2); the per-core magazine cache in uns-mempool (I4); and a multi-core run-to-completion launch where each lcore owns a queue and busy-polls. No backends beyond vNIC yet.

Deliverable

Multi-core L2-forward: N lcores each own a vNIC queue, poll + forward independently; aggregate throughput scales ~linearly with cores; loom green on rings; per-core cache eliminates atomics on the common path.

Acceptance
  • loom passes on SPSC + MPMC (no torn slot, no overrun, no lost/duplicated item — I1/I2).
  • Per-core cache: ≥ 99% of get/put hit local cache (no atomic) under steady forwarding (I4).
  • Multi-core scaling efficiency ≥ 0.85× linear to 8 cores (independent queues, no shared state — I3).
  • Aggregate ≥ 8 × single-core Mpps on 8 cores (within 15%).
Fixtures
  • templates/cfg_8core_8queue.json. benchmarks/mpps/scaling_{1,2,4,8}.json. microbench/ring_spsc.rs, ring_mpmc.rs. Loom harness fixtures in uns-ring/tests/.
Pitfalls
  • Missing Release/Acquire pairing → consumer reads slot before payload visible → corruption. Root: relaxed where release needed. Debug: loom failure; ThreadSanitizer-equiv. Recover: audited ordering (I1); proof in order.rs.
  • ABA on head/tail → slot reused mid-CAS → lost/duplicated item. Root: index reuse instead of monotonic counter. Debug: loom. Recover: monotonic 32/64-bit counters, mask only for indexing (§8.3).
  • False sharing on per-core counters/cache → cross-core cache-line bouncing kills scaling. Root: unpadded PerCore. Debug: scaling < linear; perf HITM. Recover: cache-line pad (I14).
  • Magazine size mismatched to burst → frequent backing touches. Root: cache < burst. Debug: high mempool_backing_ops. Recover: CACHE_SIZE ≥ several bursts.

⬜ Phase 2 — AF_XDP Backend (UMEM, FILL/COMPLETION/RX/TX, XSK, zero-copy + copy) + AF_PACKET v3 Fallback

Objectives

Add the two real Linux backends behind PmdOps: AF_XDP (uns-afxdp — UMEM region, FILL/COMPLETION/RX/TX rings, XSK socket, zero-copy and copy modes) and AF_PACKET v3 (uns-afpacket — TPACKET_V3 mmap block ring). The vNIC stays the test backend; all three are interchangeable.

Deliverable

L2-forward and a loopback test run over AF_XDP (zero-copy on a supported NIC/veth) and AF_PACKET v3; same app code, swapped backend; near-line-rate on AF_XDP.

Acceptance
  • AF_XDP zero-copy: ≥ 90% of line rate on a 10 GbE-class path (or veth at high pps); copy-mode functional.
  • AF_PACKET v3 fallback: correct forwarding, lower pps (documented), no leaks.
  • FILL ring kept non-empty under load (refill each poll) — no RX starvation.
  • COMPLETION reclaim returns every TXed chunk exactly once (no leak, no double-use — I6).
  • Differential: frames forwarded over AF_XDP match vNIC golden output.
Fixtures
  • templates/cfg_afxdp_veth.json, cfg_afpacket.json. conformance/pcaps/loopback_in.pcap → golden/loopback_out.pcap. scripts/setup-veth-xdp.sh (CI veth + XDP attach).
Pitfalls
  • FILL ring starvation → rx_burst returns 0 even with traffic. Root: not refilling FILL after consuming RX. Debug: FILL-ring producer index stuck; rx_burst==0 + traffic present. Recover: refill FILL from freed chunks every poll (docs/runbooks/rx-zero.md).
  • UMEM chunk double-ownership → kernel and userspace both write a chunk → corruption. Root: chunk reclaimed before COMPLETION. Debug: garbled payloads; chunk-index audit. Recover: a chunk is owned by exactly one ring at a time (mirror I5 for chunks).
  • Zero-copy unsupported silently falls to copy → unexpected low pps. Root: NIC/driver lacks ZC. Debug: bind flags returned; ethtool features. Recover: detect ZC support, log mode, allow copy fallback explicitly.
  • XDP program not attached / wrong queue → packets go to kernel stack, not XSK. Root: redirect map missing. Debug: bpftool map; kernel stack counters rising. Recover: verify attach + queue binding at start.
  • TX kick missing (sendto) → TX ring fills, nothing sent. Root: forgot to notify kernel. Debug: TX producer advances, COMPLETION empty. Recover: kick after enqueue (or XDP_USE_NEED_WAKEUP).

⬜ Phase 3 — Packet Parsing (eth/VLAN/QinQ/IPv4/IPv6/TCP/UDP/ICMP), Header Rewrite, Incremental L3/L4 Checksum, Offload Flags

Objectives

Build uns-pkt: zero-copy parsing of the full L2–L4 header stack into &[u8] views + a packed Ptype; header-rewrite helpers; incremental L3/L4 checksum (RFC 1624 — I9); and offload-flag handling (RX/TX cksum, VLAN strip/insert). This is the data the forwarder/QoS/conntrack layers consume.

Deliverable

A parse+rewrite pipeline over a frame corpus: every header field correctly extracted; TTL-decrement + incremental checksum produces the same value as full recompute; VLAN push/pop round-trips.

Acceptance
  • Parse correctness vs scapy on the full corpus (eth/VLAN/QinQ/IPv4+opts/IPv6+exthdr/TCP/UDP/ICMP/ARP) — exact field match.
  • Incremental checksum == full recompute on 10⁶ randomized TTL/NAT mutations (I9).
  • Parser never panics / never OOB-reads on the malformed corpus (truncated, bad IHL, VLAN loop) — returns ParseError (I8).
  • VLAN push then pop yields byte-identical frame (round-trip).
  • cargo fuzz parser smoke (5 min): no panic/UB.
Fixtures
  • conformance/packets/{ipv4,ipv6,vlan_qinq,tcp,udp,icmp,arp}.pcap (valid). packets/malformed_{truncated,bad_ihl,vlan_loop,ipv6_exthdr_bomb}.pcap. vectors/checksum_vectors.json (input→expected cksum). golden/parse_fields.json (expected per-frame fields). fuzz/corpus/parse_frame/*.
Pitfalls
  • Trusting on-wire length fields → OOB read past data_len. Root: using IP TotLen/IHL without bounding to mbuf. Debug: fuzz crash; ASAN-equiv. Recover: every offset bounded to data() slice (I8, §Threat Model).
  • Incremental checksum wrong delta → packet silently dropped downstream / by receiver. Root: ones-complement folding error. Debug: incremental vs full mismatch (I9). Recover: RFC1624 formula + differential test.
  • VLAN/QinQ depth unbounded → parse loop / OOB on stacked tags. Root: no tag-stack limit. Debug: vlan_loop fixture. Recover: cap VLAN depth (e.g. 2), reject beyond.
  • IPv6 extension-header chain loop / bomb → CPU blowup. Root: following NextHdr without limit. Debug: ipv6_exthdr_bomb fixture; CPU spike. Recover: cap exthdr count + total length.
  • Pseudo-header checksum forgets payload length / proto → wrong L4 cksum. Root: incomplete pseudo-header. Debug: differential vs scapy. Recover: include src/dst/proto/len per RFC.

⬜ Phase 4 — RSS (Toeplitz) + Indirection Table + Multi-Queue + Flow Steering + Symmetric RSS

Objectives

Build uns-rss: Toeplitz hash over the 5-tuple (fixed 40 B key — I10), indirection table → RX queue, multi-queue RX so each lcore owns queue(s), n-tuple flow steering overrides, and symmetric RSS so a flow and its reverse land on the same queue/core (state locality for §P10 conntrack).

Deliverable

A multi-flow workload spreads across queues/cores by RSS; reverse flows co-locate (symmetric); a steered 5-tuple lands on its pinned queue; load distribution is deterministic for a fixed key.

Acceptance
  • Toeplitz hash matches MS RSS spec test vectors exactly (I10).
  • Flow distribution across 8 queues within ±10% of uniform on a uniform-flow corpus.
  • Symmetric RSS: 1000 bidirectional flows — each flow + reverse on the same queue (100%).
  • Steering: every steered 5-tuple lands on its configured queue, overriding RSS.
  • Determinism: identical queue assignment across 100 runs (fixed key — I10).
Fixtures
  • conformance/vectors/rss_toeplitz.json (MS spec vectors). packets/multiflow_uniform.pcap, bidirectional_flows.pcap. templates/cfg_rss_8q.json, cfg_steering.json. golden/rss_queue_assignment.json.
Pitfalls
  • Asymmetric serialization → flow and reverse on different cores → conntrack state split across cores (needs a lock). Root: tuple not min/max-ordered. Debug: bidirectional fixture shows split. Recover: symmetric serialization (§8.5).
  • Per-run random key → non-reproducible distribution + unreproducible incidents. Root: random key default. Debug: replay diff. Recover: fixed key in config (I10/principle 12).
  • Indirection table not pow2 → mask wrong → skewed/aliased distribution. Root: bad config. Debug: skewed queue_distribution. Recover: validator enforces pow2 (I12).
  • Hashing the wrong byte order → distribution mismatch vs hardware/spec. Root: endianness in tuple serialize. Debug: vector mismatch. Recover: serialize per RSS spec (network order).

⬜ Phase 5 — Classification: LPM (DIR-24-8 IPv4 + trie IPv6), Cuckoo Exact-Match, ACL; Update-While-Lookup Safety (RCU/Seqlock)

Objectives

Build uns-classify: LPM via DIR-24-8 (IPv4) + 16-stride trie (IPv6) for routing; cuckoo hash for exact-match (flow/MAC); ACL (tuple-space / bit-vector) for filtering. All update-while-lookup safe — the control plane mutates while the dataplane reads lock-free (I7).

Deliverable

The L3 router (§P6) resolves next-hops via LPM at line rate; exact-match flow lookups via cuckoo; ACL filters traffic; routes/rules can be added/removed live with no dataplane stall and no torn read.

Acceptance
  • LPM4 correctness vs a reference longest-prefix-match on a full BGP-table-shaped fixture (~800K prefixes) — exact next-hop.
  • LPM4 lookup ≤ 2 memory accesses; ≥ 50 Mpps lookup microbench (cache-resident tbl24 hot set).
  • Cuckoo: bounded probe (≤ configured max), no infinite insert loop; lookup O(1).
  • Update-while-lookup: 10⁶ lookups concurrent with 10⁴ updates — zero torn reads, zero reader stalls, no use-after-free of old table (I7, loom + soak).
  • ACL: rule precedence correct vs reference on overlapping rules.
Fixtures
  • conformance/vectors/lpm4_bgp_table.json (prefixes→next-hops), lpm4_lookups.json (queries→expected). vectors/cuckoo_keys.json. vectors/acl_rules.json + acl_queries.json. Concurrency fixture: lpm_update_under_load (loom + soak).
Pitfalls
  • tbl8 pool exhaustion → can't insert a long prefix. Root: pool under-sized for /25../32 count. Debug: tbl8_pool_full. Recover: size pool to prefix-length distribution; reject + alert on exhaust.
  • Cuckoo insertion loop (kick cycle) → insert never terminates. Root: load factor too high / bad hashes. Debug: kick count > threshold. Recover: cap kicks → resize/rehash (control-plane, off dataplane).
  • RCU grace period skipped → free old table while a reader still in it → use-after-free. Root: not waiting for all per-core epochs. Debug: Miri/loom; poison old table. Recover: proper grace-period wait (I7).
  • Seqlock reader infinite retry under hot writer → reader livelock. Root: writer holds odd seq too long. Debug: seqlock_retries spike. Recover: bound writer critical section; prefer RCU for hot tables.
  • LPM update not atomic (partial tbl24 write visible) → torn next-hop. Root: in-place mutation. Debug: differential during update. Recover: build-new + atomic-pointer-swap (RCU).

⬜ Phase 6 — L3 LPM Router (TTL + incremental cksum + next-hop + ARP/ND) and L2 Learning Switch (MAC table, flood/forward/age)

Objectives

Build the two flagship forwarding apps. L3 router (uns-l3fwd): LPM route → next-hop → ARP/ND neighbor resolution + cache → rewrite (MAC + TTL decrement + incremental checksum — I9). L2 learning switch (uns-l2fwd upgraded): MAC learning table → forward/flood/age. mbuf refcount (clone) lands here for flooding/broadcast (I5).

Deliverable

uns-l3fwd routes IPv4/IPv6 across ports using a loaded route table, resolving neighbors via ARP/ND; uns-l2fwd learns MACs and forwards/floods/ages. Both run multi-core at line rate.

Acceptance
  • L3 forwarding correctness vs Linux kernel routing (netns differential) on a route fixture — same next-hop port, TTL decremented, checksum valid (I9).
  • ARP/ND: unresolved next-hop triggers request, resolves on reply, then forwards; cache hit on subsequent packets.
  • L2: known dst → unicast to learned port; unknown dst → flood to all-but-ingress; src learned; entries age out.
  • mbuf clone (flood): no double-free, no leak across N egress ports (I5).
  • TTL=1 packet → dropped + ICMP time-exceeded (or counted drop) — not forwarded with TTL 0.
Fixtures
  • conformance/vectors/route_table.json, packets/l3_route_mix.pcap → golden/l3_forwarded.pcap. packets/arp_resolve.pcap, nd_resolve.pcap. packets/l2_learn_flood.pcap → golden/l2_out.pcap. packets/ttl_1.pcap (expire).
Pitfalls
  • TTL decrement without checksum update → receiver drops (bad cksum). Root: forgot incremental update. Debug: cksum_mismatch at receiver; differential. Recover: incremental update on every TTL change (I9).
  • mbuf clone double-free on flood → freed by two ports → aliased buffer. Root: refcount not incremented per clone. Debug: poison + mbuf_double_free (I5). Recover: refcnt++ per egress, free decrements.
  • ARP cache thundering herd — many packets to an unresolved next-hop all emit ARP. Root: no in-flight suppression. Debug: ARP request storm. Recover: one outstanding request per next-hop; queue packets behind it.
  • MAC table flap (same MAC seen on two ports rapidly) → forwarding oscillation. Root: loop or move. Debug: mac_move counter. Recover: rate-limit moves; alert (possible L2 loop).
  • Forwarding to ingress port (L2) → reflection. Root: flood includes ingress. Debug: packet returns. Recover: exclude ingress port from flood set.

⬜ Phase 7 — QoS: Token-Bucket Metering (srTCM/trTCM) + Hierarchical Scheduler (port/subport/pipe/tc/queue) + DRR/WRR + RED/WRED

Objectives

Build uns-qos: single token-bucket rate limiting; hierarchical scheduler (5-level: port → subport → pipe → traffic-class → queue) with DRR/WRR within a level + strict priority across traffic classes; RED/WRED active-queue-management drop; srTCM/trTCM metering (RFC 2697/2698) coloring packets for differentiated drop.

Deliverable

An egress path that rate-limits per subscriber (pipe), prioritizes traffic classes, fairly shares within a class (DRR), and drops via WRED under congestion by color — measurable shaping + fairness.

Acceptance
  • Token bucket: measured egress rate within ±2% of configured r over a window; burst b honored.
  • Hierarchical scheduler: TC0 (highest priority) starves TC3 under congestion; within a TC, DRR shares bytes fairly (±5%) across queues per quantum.
  • WRED: under sustained overload, red-colored packets dropped at a higher rate than green (per thresholds); no tail-drop cliff.
  • srTCM/trTCM coloring matches RFC reference vectors.
  • QoS adds ≤ ~30 cycles/pkt on the egress path (within budget).
Fixtures
  • conformance/vectors/srtcm_trtcm.json (RFC vectors). templates/cfg_hsched_4tc.json. packets/qos_mixed_classes.pcap. golden/qos_shaped_rates.json, golden/drr_fairness.json, golden/wred_drop_by_color.json.
Pitfalls
  • Token-bucket refill using wall-clock syscall → per-packet syscall kills throughput. Root: clock_gettime per packet. Debug: flamegraph in QoS. Recover: TSC/cycle-counter refill, batched.
  • Priority inversion / TC starvation by design but unbounded → low-priority never sent. Root: strict priority without min guarantee. Debug: TC3 throughput 0. Recover: optional min-credit per TC (configurable).
  • DRR quantum smaller than max packet → queue can't send its packet → stall. Root: quantum < MTU. Debug: queue stuck with deficit < pkt. Recover: quantum ≥ MTU.
  • RED average-queue EWMA misconfigured → either no early drop (tail-drop cliff) or over-drop (underutilization). Root: weight/thresholds wrong. Debug: drop pattern vs queue length. Recover: tune w_q, min/max thresholds per Floyd.
  • Hierarchical token accounting drift (parent credited but child not) → rate exceeds link. Root: level accounting bug. Debug: egress > link rate. Recover: credit flows top-down; child bounded by parent.

⬜ Phase 8 — Execution Models: Pipeline (stages on distinct cores via rings) vs Run-to-Completion; Load Distributor; Reorder Buffer

Objectives

Build uns-pipeline: the pipeline model (split processing into stages, each pinned to its own lcore, connected by uns-ring SPSC/MPMC) as an alternative to run-to-completion (RTC); a load distributor (one RX core fans packets to N worker cores by flow); and a reorder buffer that restores per-flow packet order after parallel processing (IX/distributor lesson).

Deliverable

The same forwarding logic runs in both RTC and pipeline modes (config-selectable); a distributor spreads a single RX queue across workers with per-flow stickiness; the reorder buffer guarantees per-flow egress order; a comparison shows the tradeoff (RTC: better cache locality, simpler; pipeline: stage specialization, but ring + cross-core cost).

Acceptance
  • RTC vs pipeline produce identical forwarding output (differential) on the same corpus.
  • Distributor: per-flow stickiness 100% (a flow's packets all to one worker); cross-flow spread within ±10% of uniform.
  • Reorder: per-flow egress order preserved 100% even with workers finishing out of order (fault-injected variable per-packet latency).
  • Pipeline backpressure: a slow stage throttles upstream via bounded ring (no unbounded growth — I2); RTC has no inter-stage ring.
  • Measured tradeoff documented: RTC cycles/pkt vs pipeline cycles/pkt (ring + cross-core overhead quantified).
Fixtures
  • templates/cfg_rtc.json, cfg_pipeline_4stage.json, cfg_distributor.json. packets/multiflow_ordered.pcap → golden/ordered_out.pcap. Reorder fixture: workers with injected latency variance; assert egress order.
Pitfalls
  • Pipeline cross-core cache bouncing → mbuf metadata written on core A, read on core B → cache miss per handoff. Root: stage split too fine. Debug: scaling worse than RTC; perf HITM. Recover: coarsen stages; prefetch on dequeue; prefer RTC when locality dominates.
  • Reorder buffer HOL stall — a lost/slow packet blocks all later in-order release. Root: no timeout. Debug: reorder-window full, egress stalls. Recover: bounded window + timeout release (skip missing, count gap).
  • Distributor not flow-sticky → same flow on two workers → conntrack state split / reordering. Root: hashing or assignment bug. Debug: flow seen on 2 cores. Recover: deterministic flow→worker (RSS hash), sticky.
  • Ring backpressure deadlock in a pipeline cycle. Root: a cyclic stage graph with bidirectional full rings. Debug: all stages blocked. Recover: keep the stage graph acyclic; never block holding the only mbuf source.
  • Sequence-number wrap in reorder → false ordering. Root: small seq width. Debug: reorder error at wrap. Recover: wide monotonic seq + windowed comparison.

⬜ Phase 9 — Performance Hardening: NUMA-Local Placement, Prefetch, Batch Everywhere, Cache-Line Alignment, False-Sharing Elimination, Write-Combining, Branch Reduction

Objectives

Drive the per-packet cost to the ≤150-cycle budget (§4): NUMA-local hugepage placement (I11), software prefetch of mbuf metadata + packet data, batching across every stage, cache-line alignment of hot structures, false-sharing elimination on per-core state (I14), write-combining for descriptor writes, and branch reduction in the hot path. This phase is measurement-driven (profile → fix → re-measure).

Deliverable

A hardened dataplane that hits the cycle budget: ≥ the §4 Mpps targets with a measured cycles/pkt breakdown; flamegraphs + perf stat (cache misses, branch misses) documented in docs/performance/.

Acceptance
  • 64 B single-core ≥ 14.88 Mpps on vNIC (≤ ~150 cycles/pkt) — the headline gate.
  • perf stat: L1/L2 miss rate on the hot path below a documented threshold; branch-miss rate reduced vs pre-hardening baseline.
  • Zero remote-NUMA accesses on the steady-state hot path (I11, numastat).
  • Zero false-sharing HITM events on per-core counters (I14, perf c2c-equiv).
  • No heap allocation on the hot path (I4, allocator hook = 0).
  • Prefetch yields a measurable cycles/pkt reduction (before/after documented).
Fixtures
  • benchmarks/mpps/64b_singlecore.json, mixed_size.json, imix.json. benchmarks/microbench/{prefetch_on_off,numa_local_remote,branch_table_vs_if}.rs. docs/performance/cycle-budget.md worksheet.
Pitfalls
  • Prefetch too late / too early → no benefit or evicts useful lines. Root: prefetch distance wrong. Debug: cycles/pkt unchanged or worse. Recover: tune prefetch distance (usually 1–2 ahead); measure.
  • Accidental remote-NUMA allocation → silent ~100 ns/access tax. Root: allocator picked the wrong node. Debug: numastat, numa_remote_access. Recover: explicit node binding (I11).
  • False sharing reintroduced by a new shared counter. Root: a metric added without padding. Debug: scaling regression; perf c2c. Recover: per-core + pad (I14); lint for shared atomics on hot path.
  • Over-batching latency → waiting to fill a burst adds latency under low load. Root: fixed burst wait. Debug: p99 latency up at low pps. Recover: adaptive burst (drain partial after a short spin).
  • Branchless code that's actually slower (extra work both sides) → regression. Root: premature branchless. Debug: microbench. Recover: measure; keep branch where predictable.

⬜ Phase 10 — Stateful Flow Table + Connection Tracking (5-tuple FSM) + Timer Wheel (#204) + Stateful NAT + Aging/Eviction

Objectives

Build uns-flow + uns-timer: a per-core stateful flow table (5-tuple keyed, cuckoo from §P5) with a connection-tracking state machine (TCP-like + UDP), a timer wheel (cross-link #204) driving aging/eviction, and a stateful NAT sample (rewrite + reverse-mapping, incremental L4 cksum — I9). Flows are per-core (symmetric RSS guarantees a flow + reverse on one core — I3, no lock).

Deliverable

A conntrack-aware dataplane: flows tracked through their lifecycle, aged out on timeout, with a working stateful NAT (forward + return path) — all per-core, lock-free, at line rate.

Acceptance
  • Conntrack FSM correctness vs a reference (e.g. simplified nf_conntrack) on a TCP+UDP flow corpus — correct state transitions.
  • NAT: bidirectional flow translated correctly (forward rewrite + return matched via reverse map); checksum valid (I9); differential vs Linux NAT (netns).
  • Aging: idle flow evicted after its state-dependent timeout (timer wheel); active flow refreshed (not evicted).
  • Timer wheel: O(1) insert/expire; 10⁶ concurrent timers, expiry within one tick of target.
  • Per-core: a flow + its reverse always on the same core (symmetric RSS) → zero cross-core flow-state access (I3).
Fixtures
  • conformance/packets/tcp_handshake.pcap, udp_flow.pcap, tcp_teardown.pcap → golden/conntrack_states.json. packets/nat_bidirectional.pcap → golden/nat_translated.pcap. vectors/timer_wheel_expiry.json. Aging fixture (idle → evict).
Pitfalls
  • Flow + reverse on different cores → state split → needs a lock (violates I3) or two half-states. Root: asymmetric RSS. Debug: flow state on 2 cores. Recover: symmetric RSS (§P4) is a hard prerequisite here.
  • Timer not cancelled on early flow close → stale timer fires on a reused entry → wrong eviction. Root: missing cancel. Debug: eviction of an active flow. Recover: cancel-on-close; generation/epoch on entries.
  • NAT port-pool exhaustion → can't translate new flows. Root: ports not freed on flow close. Debug: nat_pool_exhausted. Recover: free port on eviction; size pool; alert.
  • Conntrack table full → can't track new flows. Root: eviction slower than creation under flood. Debug: flowtable_full. Recover: LRU/timeout eviction; rate-limit new flows; counted drop.
  • Checksum not updated after NAT rewrite → receiver drops. Root: forgot incremental L4 cksum on addr/port change. Debug: cksum_mismatch. Recover: incremental update on every NAT rewrite (I9).
  • FSM state confusion under reordering/retransmit → wrong state. Root: strict FSM without retransmit tolerance. Debug: differential. Recover: tolerate retransmits; window-based validation.

⬜ Phase 11 — Observability: Per-Queue/Per-Core xstats, HDR Latency Histograms, pcap Capture/Replay, Per-Packet Trace, Drop Accounting, Telemetry Socket

Objectives

Build uns-telemetry: per-queue/per-core counters (xstats — zero-cost on hot path, I14), HDR latency histograms (p50/p99/p999), pcap capture + replay (libpcap format), a per-packet trace ring, drop accounting by reason, and a telemetry unix socket the control plane scrapes. This makes the dataplane debuggable without perturbing it.

Deliverable

A running dataplane exposes a complete counter set + latency percentiles over a unix socket; captures/replays pcaps; traces recent packets; accounts every drop by reason — with zero measurable hot-path cost from counters (I14).

Acceptance
  • xstats: all packets accounted (rx = forwarded + dropped-by-all-reasons; conservation check). Zero false-sharing from counters (I14, perf c2c).
  • Latency histogram: p50/p99/p999 reported; matches a reference timing within sampling error.
  • pcap: capture then replay reproduces the same forwarding decisions (deterministic, vNIC).
  • Per-packet trace: last K packets' decisions retrievable; dump cost off-path only.
  • Telemetry socket: control plane scrapes a full snapshot without dropping packets (no hot-path stall).
  • Hot-path counter cost: ≤ 1 cycle/pkt added (a local increment) — measured before/after.
Fixtures
  • conformance/pcaps/capture_replay.pcap (capture → replay → assert identical decisions). golden/xstats_conservation.json (rx = fwd + drops). golden/latency_percentiles.json. Telemetry-socket fixture (scrape under load).
Pitfalls
  • Atomic counter on the hot path → cross-core contention (the principle-4/14 violation). Root: shared global counter. Debug: scaling regression; perf c2c. Recover: per-core + pad; aggregate off-path.
  • Timestamping every packet → TSC read + store per packet adds cost. Root: unsampled histogram. Debug: cycles/pkt up. Recover: sample 1/N; or only on a traced subset.
  • pcap capture in the hot path → memcpy per packet stalls forwarding. Root: synchronous capture. Debug: throughput drop when capture on. Recover: capture to a per-core ring, drain off-path; or capture a sampled subset.
  • Telemetry socket scrape blocks the dataplane → poll stall. Root: control work on a data lcore. Debug: rx_burst gap during scrape. Recover: dedicated control thread; lock-free snapshot.
  • Drop reason missing → packets vanish unaccounted ("where did 2% go?"). Root: a drop path without a counter. Debug: conservation check fails. Recover: every drop path increments a reason (audit).

⬜ Phase 12 — Conformance + Differential (vs kernel / scapy), Parser Fuzzing, loom on Rings, Soak (no mbuf/FD leak), Perf Gate (Mpps)

Objectives

Lock correctness + safety + performance: full conformance suite (parse/forward/checksum/RSS/LPM/conntrack/NAT/QoS), differential vs the Linux kernel stack + scapy-generated packets, packet-parser fuzzing (cargo fuzz), loom on rings + RCU + magazine, soak (no mbuf/FD/hugepage leak), and a Mpps performance gate. Wire the CI to block on all of it.

Deliverable

make conformance + make differential + make fuzz-smoke + make loom + make soak + make bench all green; metrics endpoint live; the dataplane is production-gated.

Acceptance
  • Conformance: 100% of fixtures byte-exact (parse/forward/checksum/NAT) + correct states (conntrack/RSS/LPM).
  • Differential vs kernel: equivalent forwarding/NAT/conntrack on the corpus (documented intentional differences only).
  • Fuzz smoke (5 min/target): no panic/UB/OOB on parser, config, LPM-update.
  • loom: green on rings, RCU, magazine (I1/I2/I4/I7).
  • Soak: 1 h — zero mbuf/FD/hugepage leak (I13), no ring growth, replan/aging stable.
  • Perf gate: ≥ 14.88 Mpps 64 B single-core; scaling ≥ 0.85× linear/8 cores; no > 10% regression vs baseline.
Fixtures
  • conformance/packets/*, pcaps/*, golden/*, vectors/* (full suite). fuzz/corpus/*. benchmarks/mpps/*, latency/*. Soak harness config. Differential netns setup (scripts/setup-netns.sh).
Pitfalls
  • Differential float/normalization mismatch (e.g. timestamp, ID fields) → false failures. Root: comparing non-deterministic fields. Debug: per-field diff. Recover: normalize (ignore IP-ID/timestamp/ephemeral-port) before compare.
  • Fuzzer finds parser OOB on a crafted header → the exact memory-safety bug this phase exists to catch. Root: an unbounded offset. Debug: minimized crashing input. Recover: bound it (I8); add to corpus.
  • loom state-space explosion → tests time out. Root: too many threads/ops modeled. Debug: loom iteration count. Recover: model the minimal interleaving (2 producers/1 consumer), bound preemptions.
  • Soak leak only at scale (slow mbuf leak from an error path) → missed in short tests. Root: an untested error path frees nothing. Debug: mempool census trend over 1 h. Recover: RAII/explicit free on every error path (I5/I13).
  • Bench flakiness on shared CI → false regressions. Root: noisy host. Debug: variance. Recover: pinned isolated cores (isolcpus), relative thresholds, multiple runs (median).
