321 — Userspace Networking Stack (DPDK-style) from Scratch

Project Number: 321

Project Name: Userspace Networking Stack (DPDK-style) from Scratch

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal

Build a poll-mode, kernel-bypass userspace packet-I/O framework plus L2–L4 processing, modeled on DPDK. Packets move NIC-equivalent → userspace via a poll-mode driver (PMD) — no per-packet interrupts, no kernel network stack — are processed in run-to-completion (or pipeline) loops on cores pinned to hugepage-backed memory, then transmitted. The novelty vs a socket app: the data path owns its memory (mbufs in a lockless mempool), owns its scheduling (lcores poll RX rings in a busy loop), and owns its parallelism (per-core sharding + lockless rings cross-core), so per-packet cost drops to a fixed cycle budget independent of kernel.

System boundaries (in scope):

  • EAL (Environment Abstraction Layer): hugepage allocator via mmap(MAP_HUGETLB), lcore threads pinned to CPUs (sched_setaffinity), per-core data (PerCore<T>).
  • mempool: lockless mbuf object pool + per-core cache (magazine); mbuf: headroom/tailroom, chaining/segmentation, refcount, offload flags.
  • rte_ring-style lockless bounded rings: SPSC + MPMC, Lamport/Lynch head/tail with explicit memory ordering.
  • PMD abstraction: RX/TX descriptor rings + burst API rx_burst/tx_burst. Backends: AF_XDP (real fast path), AF_PACKET v3 (portable fallback), in-memory virtual NIC (deterministic tests).
  • RSS (Toeplitz hash) + multi-queue + flow steering (n-tuple → queue/core); symmetric RSS for bidirectional flow affinity.
  • Classification: LPM via DIR-24-8 (IPv4) + trie (IPv6), cuckoo-hash exact-match, ACL (tuple-space / bit-vector). Update-while-lookup safe (RCU/seqlock).
  • Packet processing: parse eth/VLAN/QinQ/IPv4/IPv6/TCP/UDP/ICMP; header rewrite; incremental L3/L4 checksum; offload flags.
  • QoS / rate limiting: token bucket (srTCM/trTCM), hierarchical scheduler (port/subport/pipe/tc/queue), DRR/WRR, RED/WRED.
  • Execution models: run-to-completion vs pipeline (stages on distinct cores connected by rings); load distributor; reorder buffer.
  • Stateful: flow table / connection tracking (5-tuple state machine), timer wheel (cross-link #204), stateful NAT, aging/eviction.
  • Sample apps: L2 learning switch, L3 LPM router (+ ARP/ND neighbor), userspace UDP echo.
  • Observability: per-queue/per-core xstats, HDR latency histograms, pcap capture/replay, per-packet trace, drop accounting, telemetry socket.

Explicit non-goals (deferred, each registered in Deferred Features Register with a resolving anchor):

  • Real PCIe/VFIO/UIO MMIO driver for physical NICs — model the device or use AF_XDP. PhaseDeferred("Deferred Features Register").
  • Full userspace TCP — only UDP + stateful tracking here. PhaseDeferred("Deferred Features Register") (cross-link #33 TCP/IP Stack, #224 QUIC).
  • Hardware crypto / IPsec offload. PhaseDeferred("Deferred Features Register").
  • RDMA transport — that is #322 Kernel Bypass RPC. PhaseDeferred("Deferred Features Register") (cross-link #322).
  • SR-IOV / hardware virtual functions / VF passthrough. PhaseDeferred("Deferred Features Register").
  • GPU/DPU offload — that is #324 Smart NIC Simulator. PhaseDeferred("Deferred Features Register") (cross-link #324).

Deployment model: a workspace of library crates (uns-*) plus thin sample-app binaries (uns-l2fwd, uns-l3fwd, uns-udpecho). An app declares ports/queues/lcores in a config, the EAL maps hugepages, launches lcores, the PMD polls, the app's run-to-completion function processes bursts. Runs as a dedicated, CPU-isolated process owning whole cores. Embeds as the dataplane beneath a control plane (routing daemon, ovs-style controller) over the telemetry socket.

Target users/operators/developers: dataplane engineers building NFV/router/switch fast paths; SREs debugging why a core's rx_burst returns 0 (FILL-ring starvation) at 3 a.m.; learners who want DPDK's mempool/ring/PMD/RSS/LPM/QoS core built end to end without a physical NIC.

Phase 0 deliverable (numbered crates/modules):

  1. uns-eal — hugepage allocator (HugeAlloc), lcore launch + affinity (Lcore, lcore_launch), PerCore<T>, EAL init + CLI arg parse.
  2. uns-mbuf — Mbuf (headroom/tailroom/data_off/refcnt/ol_flags), segment chaining helpers.
  3. uns-mempool — Mempool (lockless free-stack + per-core cache), bulk get/put.
  4. uns-pmd — trait EthDev / PmdOps (configure/start/rx_burst/tx_burst/stop), PortId/QueueId/LcoreId.
  5. uns-vnic — in-memory virtual NIC PMD (deterministic packet source/sink, programmable workload).
  6. uns-types — shared IDs, OffloadFlags bitflags, PortStats/XStats, error enums (thiserror).
  7. uns-l2fwd — L2-forward sample binary: EAL init → vNIC port → poll rx_burst → swap MACs → tx_burst.

What later phases unlock: lockless rings + per-core cache + multi-core RTC (§Phase 1); AF_XDP + AF_PACKET backends (§Phase 2); parsing + checksum + offload (§Phase 3); RSS + multi-queue + steering (§Phase 4); LPM/cuckoo/ACL classification (§Phase 5); L3 router + L2 switch + ARP/ND (§Phase 6); QoS hierarchical scheduler (§Phase 7); pipeline model + distributor + reorder (§Phase 8); perf hardening (§Phase 9); conntrack + timer wheel + NAT (§Phase 10); observability (§Phase 11); conformance + differential + fuzz + soak + perf gate (§Phase 12).

Timeline: Phase 0 = 6–14 weeks. Full plan = 6–10 months.

Recommended language: Rust (edition 2021, ≥1.78), with carefully scoped unsafe. Rationale (ADR-001): (a) ownership models mbuf + DMA-buffer lifetime (owned until freed to pool / handed to TX) without GC pauses that would poison p99 at 14.88 Mpps; (b) Send/Sync make per-core sharding a compile-time property — a value that is not Send cannot leak across cores except through a ring; (c) zero-cost slices give vectorized batch processing (burst=32) the autovectorization a dataplane needs; (d) unsafe is scoped to three places — hugepage mmap, ring memory-ordering, AF_XDP UMEM — each behind a safe wrapper with a stated contract; (e) cargo fuzz (packet-parser fuzz), Miri (UB on unsafe paths), loom (ring concurrency permutations) cover the testing this domain demands. Reject C (memory-unsafe at line rate — use-after-free of an mbuf is a silent corruption), Go/Java (GC tax destroys the cycle budget). Locked in ADR-001.

Prerequisites: packet formats (Ethernet/VLAN/IPv4/IPv6/TCP/UDP/ICMP, byte order); lockless data structures + the C11/Rust memory model (acquire/release, SeqCst vs Acquire); cache lines + false sharing + NUMA (Drepper); DMA/descriptor-ring mental model (even though modeled); hugepages + mmap; AF_XDP/XDP basics; Rust unsafe, Send/Sync, UnsafeCell, atomics; LPM/hashing/sketch basics; token-bucket/scheduling theory.

2. Why Build This

  • Unique systems knowledge: the data plane at line rate. Socket programming teaches the kernel's network stack; this teaches what you do when the kernel is the bottleneck — poll instead of interrupt, batch instead of per-packet, shard per-core instead of lock, own your memory instead of malloc. It is the difference between 1 Mpps and 14.88 Mpps on one core.
  • Historical/architectural significance: the industry's response to the per-packet interrupt + kernel-copy + socket-syscall tax. netmap (2012), PF_RING ZC, Intel DPDK (2010→), and later AF_XDP (2018) all kernel-bypass or fast-path the NIC. Cisco VPP, Open vSwitch-DPDK, and every NFV stack ride on this model. Building it rebuilds that core.
  • Engineering muscles: lockless ring design with correct memory ordering (the single hardest correctness problem here); per-core sharding without false sharing; zero-allocation hot paths; cycle-budget thinking (≤150 cycles/pkt); RCU/seqlock for update-while-lookup tables; batching everywhere; NUMA placement; observability that is itself zero-cost on the hot path.
  • Production concepts exercised: poll vs interrupt, burst APIs, mempool/mbuf lifecycle, RSS load distribution, LPM forwarding, QoS hierarchical scheduling, backpressure (FILL/COMPLETION ring depth), graceful drain, drop accounting, telemetry.
  • Cross-links:
    • #33 TCP/IP Stack — the L4 logic deferred here; shares packet-format + checksum vocabulary.
    • #224 QUIC — a userspace L4 that could ride this dataplane.
    • #204 Timer Wheel — reused verbatim for conntrack aging (§Phase 10).
    • #322 Kernel Bypass RPC — RDMA-style transport; this stack is its substrate.
    • #324 Smart NIC / Offload Simulator — offload model that would consume this stack's PMD.
  • Calibration value: after this you can read any DPDK app, reason about why a core is dropping packets (FILL starvation vs ring overrun vs HOL on one queue), design a lockless ring and prove its ordering, and think in cycles-per-packet rather than requests-per-second.

What Mastery Looks Like

After building this system you hold these competencies, each cemented by a named phase:

  • Prove a lockless ring correct, not just write one. You can state the acquire/release pairing on a SPSC ring, explain why a relaxed producer-tail store corrupts the consumer, and read a loom counterexample — built in §Phase 1 (rings), exercised in §Phase 8 (pipeline edges).
  • Budget a data path in cycles, not requests. You decompose 67 ns/packet into parse/lookup/rewrite/checksum/ring overhead and know which line is the cache miss — built in §Phase 9 (perf hardening), proven against the ≤150-cycle gate.
  • Design update-while-lookup data structures. You choose RCU vs seqlock vs RwLock by read/write ratio and staleness tolerance, and know why a lock on the lookup path stalls every core — built in §Phase 5 (classification).
  • Reason about per-core sharding and false sharing. You can predict from a struct layout whether two cores will bounce a cache line, and why a shared atomic counter reintroduces the contention sharding removed — built in §Phase 1 and hardened in §Phase 9.
  • Make a system deterministic on purpose. You know which knobs (RSS key, hash seeds, vNIC source) collapse a distributed dataplane to a replayable sequence, and why that is the precondition for debugging an incident — built in §Phase 4 (RSS) and §Phase 11 (replay).
  • Trace a packet's bytes end-to-end and find where they were corrupted. You can byte-diff against a golden pcap, localize an off-by-one in headroom math, and verify an incremental checksum equals a full recompute — built in §Phase 3 (parse/rewrite/checksum) and §Phase 6 (forwarding).
  • Operate a kernel-bypass dataplane in production. You can diagnose rx_burst==0 as FILL starvation vs ring overrun vs a hot flow, and read the drop-by-reason conservation check — built in §Phase 2 (AF_XDP) and §Phase 11 (observability).
  • Account a stateful flow table under flood. You size a conntrack table and NAT port pool against a creation/eviction balance, and know why symmetric RSS is the prerequisite for lock-free per-flow state — built in §Phase 4 (symmetric RSS) and §Phase 10 (conntrack/NAT).

Per-box dense notes:

  • NIC-equivalent — the device seam. In tests, uns-vnic is a deterministic frame source/sink (programmable rate, sizes, flows). In production, the seam is the kernel: AF_XDP UMEM rings or AF_PACKET v3 block ring. Trust boundary: every inbound frame is untrusted bytes (§Threat Model) — the parser is the gate.
  • Poll-mode driver (PMD) — trait EthDev/PmdOps; rx_burst/tx_burst are the only I/O entry points. No interrupts: an lcore busy-polls. Burst API amortizes per-call overhead over ≤32 mbufs. Backend is swappable behind the trait (vNIC for determinism, AF_XDP for speed). Invariant: tx_burst returns unsent count, never partially frees (I6/I10).
  • Mempool — lockless free-stack of pre-allocated mbufs in hugepages, fronted by a per-core magazine cache so the common alloc/free hits no atomics (I4). Bulk get/put amortize the rare backing-store touch.
  • RSS / multi-queue / steering — Toeplitz hash over the 5-tuple → indirection table → RX queue; spreads flows across cores. n-tuple steering overrides for specific flows. Symmetric RSS ensures a flow and its reverse land on the same queue/core (state locality). Concurrency boundary: each queue owned by one lcore → no shared state.
  • EAL: lcores + hugepages + per-core data — the substrate. Each lcore is an OS thread pinned to a CPU (sched_setaffinity), running a busy-poll loop. Hugepages back mempool + rings (TLB-friendly, contiguous). PerCore<T> shards mutable state so the hot path touches only this core's cache line (no false sharing, I14).
  • Packet processing pipeline — run-to-completion: one lcore parses → classifies → forwards → checksums → QoS → TXes a whole burst before fetching the next. Apps differ only in the per-packet function. Shared Mbuf vocabulary throughout.
  • Classify (uns-classify) — LPM (DIR-24-8 IPv4 + trie IPv6) for routing, cuckoo hash for exact-match (flow/MAC), ACL (tuple-space) for filtering. Update-while-lookup safe via RCU/seqlock (I7): the control plane swaps tables; the dataplane never blocks, never reads a torn table.
  • Conntrack (uns-flow, §P10) — 5-tuple keyed flow table with a per-flow state machine; aging/eviction via the timer wheel. Stateful NAT rides on it.
  • QoS scheduler (uns-qos, §P7) — hierarchical port/subport/pipe/tc/queue token buckets with DRR/WRR + RED/WRED drop. Meters classify to traffic classes (srTCM/trTCM).
  • Timer wheel (#204, §P10) — hashed/hierarchical timer wheel for flow aging + retransmit-style timeouts; O(1) insert/expire.
  • rte_ring (uns-ring) — lockless bounded rings: SPSC (one producer, one consumer) and MPMC (CAS head/tail). The only cross-core data path (I3). Connects pipeline stages (§P8) and PMD→worker handoffs.
  • Observability (uns-telemetry) — per-queue/per-core counters (cheap, per-core, no atomics), HDR latency histograms, pcap capture/replay, per-packet trace ring, drop accounting by reason, and a telemetry unix socket the control plane polls. Hot-path cost ≈ one increment of a per-core counter (I14).

4. System Constraints

Dimension Target
Throughput (vNIC, 64 B, 1 core, RTC) ≥ 10–20 Mpps/core (deterministic source, no kernel)
Throughput (AF_XDP, real) ≥ 90% of line rate at 10/25/100 GbE (zero-copy mode)
Per-packet cycle budget (64 B, 14.88 Mpps, 1 core @ ~2.2 GHz) ≤ ~150 cycles/pkt (≈ 67 ns)
Heap allocation on data path zero — all mbufs from mempool; no malloc/Box per packet (I4)
Burst size 32 (RX + TX); tunable power-of-two
mbuf data room 2 KiB data + 128 B headroom (default; configurable)
Ring size power-of-two (mask-indexed); default 1024 entries/queue (I12)
Mempool size ≥ 2× (n_queues × ring_size + per-core cache × n_cores) + in-flight margin
Per-core cache (magazine) 256–512 mbufs; bulk transfer 32 to/from backing store
Hugepages NUMA-local to the owning lcore; 2 MiB default, 1 GiB optional
NUMA per-node mempool + rings; lcore touches only local memory; remote access counted (I11)
FD budget ≤ 64 (XSK sockets + UMEM + pcap files); AF_XDP: 1 XSK/queue
Startup (EAL init → first poll) ≤ 500 ms (hugepage map + lcore launch + PMD configure)
Shutdown graceful drain: stop RX, flush in-flight to TX, free mbufs, unmap hugepages; ≤ 2 s (I13)
Latency (UDP echo, vNIC, p50/p99) p50 ≤ 2 µs, p99 ≤ 10 µs (no kernel, busy-poll)
Drop policy bounded rings → drops counted by reason; never unbounded buffering (I2)
Concurrency scales to physical cores; 1 lcore = 1 busy-poll loop; default = isolated cores
Cache mbuf metadata 1 cache line (64 B); per-core counters cache-line padded (no false sharing)
Recovery (FILL-ring starvation) refill from mempool each poll; detect via rx_burst==0 + empty FILL counter
Availability single process owning cores; crash = restart dataplane (control plane re-syncs tables)
Determinism vNIC backend + fixed RSS key ⇒ identical packet→queue→core→action across runs (I10)

Scaling assumptions: single node, 1–64 cores, NUMA 1–4 nodes, hugepages 1–64 GiB, NVMe for pcap. Horizontal scaling = more boxes behind an L3 ECMP/RSS hash (out of scope; the per-core shard is the unit). Vertical scaling = more lcores + more RX queues (RSS spreads load); coalescing not needed (packets are uniform-cost).

6. Design Principles

  1. Poll, never interrupt, on the data path. An lcore busy-polls its RX queue; no per-packet interrupt, no syscall per packet. Tradeoff: a core is 100% busy even when idle (burns power, needs CPU isolation). Violation: interrupt-driven RX caps you at ~1 Mpps and adds unbounded latency jitter.
  2. Zero allocation on the data path. Every mbuf comes from the mempool; nothing calls malloc/Box/Vec::new per packet (I4). Tradeoff: mempool must be pre-sized for worst-case in-flight. Violation: one allocation/packet at 14.88 Mpps = an allocator call every 67 ns → cycle budget blown, p99 destroyed.
  3. Batch everything (burst = 32). RX, TX, parse, classify, free — all operate on arrays of mbufs. Tradeoff: small added latency (wait to fill a burst) vs huge throughput win (amortized per-call cost, prefetch pipelining). Violation: per-packet calls re-pay fixed overhead 32× and defeat prefetch.
  4. Per-core sharding; cross-core only through a ring. Mutable state is PerCore<T>; the only legal cross-core data path is a lockless ring (I3). Tradeoff: no shared global tables without RCU. Violation: a shared Mutex<HashMap> on the hot path serializes all cores → throughput collapses to one core.
  5. Lockless rings with explicit memory ordering. SPSC/MPMC rings use acquire/release (not SeqCst everywhere); ordering is proven, not hoped (I1). Tradeoff: harder to reason about; needs loom. Violation: a missing Release on the producer tail → consumer reads a slot before the payload write is visible → corruption.
  6. mbuf ownership is single and explicit. An mbuf is owned by exactly one party: the pool (free), a worker (processing), or TX (in flight). Refcount governs shared/cloned mbufs (I5). Violation: double-free (freed twice to pool → later alloc returns an aliased buffer) or use-after-free (TXed mbuf still read) → silent packet corruption.
  7. Bounded rings; drops are counted, never unbounded buffering. Every queue has a power-of-two capacity; a full ring drops and increments a per-reason counter (I2). Tradeoff: drops under overload. Violation: unbounded queue → memory blow-up → OOM under a microburst, worse than a counted drop.
  8. Tables are update-while-lookup safe (RCU/seqlock). The control plane mutates LPM/flow/ACL tables; the dataplane reads without locking and never sees a torn table (I7). Tradeoff: readers may briefly see the old table (bounded staleness). Violation: a lock on lookup → control-plane update stalls every core; or a torn read → wrong next-hop.
  9. Byte-conservation through the pipeline. A packet's bytes are never silently corrupted; rewrites are explicit and checksums updated (I8, I9). Violation: an off-by-one in headroom adjust corrupts every header; a stale checksum gets the packet dropped downstream.
  10. TX burst returns the unsent count; never partial-free. tx_burst returning k < n means mbufs [k..n) are still owned by the caller (re-queue or free), [0..k) are owned by the device (I6, I10). Violation: freeing an mbuf the device still holds = use-after-free; double-counting = leak.
  11. NUMA-local memory. mempool, rings, and per-core data for an lcore live on that lcore's NUMA node (I11). Tradeoff: per-node pools. Violation: remote-node mbuf access adds ~100 ns/access → cycle budget blown on multi-socket.
  12. Deterministic where it can be. vNIC backend + fixed RSS key + fixed hash seeds ⇒ identical packet→queue→core→action sequence across runs (I10). Violation: per-run random RSS key → non-reproducible load distribution → unreproducible incidents.
  13. Graceful drain on shutdown. Stop RX, flush in-flight mbufs to TX, free all mbufs, unmap hugepages, close XSKs (I13). Violation: abrupt exit leaks hugepages (kernel reclaims slowly) + drops in-flight packets + orphans XSK FDs.
  14. Observability is zero-cost on the hot path. Counters are per-core (no atomics), histograms sampled, traces ring-buffered; the control plane aggregates off-path (I14). Tradeoff: slightly stale aggregate view. Violation: an atomic increment per packet on a shared counter reintroduces the cross-core contention principle 4 forbids.
  15. The kernel is off the data path, but trusted at the seam. AF_XDP/AF_PACKET cross the kernel once at setup; thereafter the kernel does not touch packets. Inbound frame bytes are untrusted (parser is the gate, §Threat Model). Violation: trusting frame lengths/offsets from the wire → OOB read in the parser.

8.2 mbuf layout (one cache line of metadata + data room)

┌────────────────────────────────────────────────────────────────────┐
│ mbuf metadata (≈64 B, 1 cache line)                                  │
│  buf_addr → start of data buffer | data_off (headroom, default 128)  │
│  data_len (this segment) | pkt_len (total chain) | nb_segs | next →  │
│  refcnt (u16) | ol_flags (RX/TX cksum, VLAN, ptype) | rss_hash (u32) │
│  port (PortId) | pool (Mempool back-ref)                             │
├──────────────┬───────────────────────────────────────┬──────────────┤
│ HEADROOM     │ DATA (data_off .. data_off+data_len)   │ TAILROOM     │
│ (128 B def.) │ ← prepend headers here (push)          │ ← append     │
│ encap grows  │   parse reads here                     │   payload    │
└──────────────┴───────────────────────────────────────┴──────────────┘
buf_len = headroom + data_room(2KiB) + tailroom
Chaining: next → next segment; pkt_len = Σ data_len; nb_segs = chain length (jumbo/scatter)

Operations: prepend(len) shrinks data_off (push header, e.g. VLAN/encap); adj(len) grows data_off (strip header); append(len) grows data_len into tailroom; trim(len) shrinks. Each asserts headroom/tailroom bounds (I8). Refcount: clone increments (shared, e.g. broadcast/replicate); free decrements, returns to pool at 0 (I5).

8.3 Ring semantics (lockless bounded queue)

Ring<T> { prod_head, prod_tail, cons_head, cons_tail, mask, slots[capacity] }   ; capacity = pow2
SPSC enqueue: ph = prod_head; if (ph - cons_tail) == cap → full(drop, I2);
              write slot[ph & mask] = item; Release: prod_tail = ph+1
SPSC dequeue: ct = cons_head; if prod_tail == ct → empty;
              Acquire(prod_tail); read item = slot[ct & mask]; cons_tail = ct+1
MPMC: CAS prod_head forward to reserve, write slot, then advance prod_tail in order (wait for predecessor)

Memory ordering (I1): producer publishes payload with Release on prod_tail; consumer observes with Acquire load of prod_tail before reading the slot. ABA avoided by monotonic 32/64-bit head/tail counters (not index reuse). Burst variant reserves n slots in one CAS.

8.4 Mempool + per-core cache (magazine)

Mempool { backing: lockless free-stack of mbuf ptrs (hugepage),
          per_core: [Cache; n_cores], elt_size, n_elts }
Cache   { local: [*mut Mbuf; CACHE_SIZE], len }                ; per-core, no atomics
get():  if cache.len>0 → pop local (hot, no atomic);
        else bulk-pull 32 from backing (one atomic CAS), refill cache, pop
put():  if cache.len<CACHE_SIZE → push local;
        else bulk-flush 32 to backing, push

Invariant I4: common-case get/put is a per-core array pop/push — zero atomics, zero heap. Backing touched only on cache miss (amortized 1/32).

8.5 RSS / steering (packet → queue → core)

rss_hash = toeplitz(key[40B], serialize_5tuple(src_ip,dst_ip,src_port,dst_port,proto))
queue    = indirection_table[ rss_hash & (table_size-1) ]      ; table_size pow2 (default 128)
core     = queue_to_lcore[queue]                                ; static binding
symmetric: serialize with min(src,dst) || max(src,dst) ordering → flow & reverse hash identical
steering override: if 5tuple ∈ flow_steer_table → queue = steered_queue (n-tuple exact match)

Determinism (I10): fixed 40-byte key + fixed serialization ⇒ identical hash ⇒ identical queue.

8.6 State tables

Stage / port lifecycle (PMD): Uninit → Configured(configure) → Started(start) → [rx_burst/tx_burst loop] → Stopped(stop) → Closed. Only Started ports do I/O.

mbuf lifecycle: Pooled → Allocated(get) → Owned(processing) → {Freed(put)→Pooled | TxInFlight(tx_burst accepted) → Freed-by-device}. Cloned: Owned → SharedN (refcnt=N).

Conntrack flow FSM (§P10, TCP-like): New → SynSent → Established → FinWait → Closed; UDP: New → Assured → (timeout)Closed. Transition on packet direction + flags; timeout via timer wheel.

8.7 Worked example — L3 router forwards one IPv4 packet

1. rx_burst(q0, &mut burst[32]) → returns 4 mbufs (deterministic vNIC)
2. for each mbuf: parse EthHdr → EtherType=0x0800 → IPv4 view at data_off+14
3. dst_ip = 10.2.3.4 → lpm.lookup_24_8(dst_ip) → next_hop_id = 7  (1 memory access, §8 DIR-24-8)
4. neigh = arp_cache.get(next_hop_id) → dst_mac (or queue for ARP resolve if miss)
5. rewrite: eth.dst = neigh.mac; eth.src = port.mac; ipv4.ttl -= 1
6. ipv4.hdr_cksum = incremental_update(old_ttl, new_ttl)   (RFC1624, I9 — no full recompute)
7. tx_burst(out_q, &burst[..4]) → returns 4 (all sent) → mbufs now device-owned (I6/I10)

Cycle budget check: parse(~20) + LPM(~30, 1 cache miss) + ARP(~15, hot) + rewrite(~20) + cksum(~10) + ring/burst overhead(~40 amortized) ≈ 135 cycles → within ≤150 (§4).

8.8 Malformed / failure-path examples

  • Truncated frame (data_len < 14) → parser returns ParseError::Truncated, packet dropped, parse_drops++ (I8). Never OOB-reads (slice bounds).
  • IPv4 IHL > data → ParseError::BadHeaderLen, drop. EtherType unknown → forward-to-host or drop per policy.
  • Ring full on enqueue → ring_full_drops++ (I2), packet freed to pool (not leaked).
  • mempool exhausted (rx_burst wants mbufs, none free) → rx_burst returns fewer/zero; mempool_exhausted++; RX backpressure (frames dropped at device/FILL ring).
  • LPM lookup during table swap → reader sees old epoch (RCU) — never a torn next-hop (I7).
  • TX returns k < n → caller frees [k..n) or re-queues; never frees [0..k) (I6/I10).
  • Checksum incremental update with a wrong delta → caught by cksum_mismatch differential test (I9).

Ownership / concurrency / persistence semantics:

  • Mbuf — owned by exactly one party at a time (pool / worker / TX-in-flight); refcnt permits explicit sharing (clone for broadcast). Send but !Sync for the metadata mutation path; the data buffer is hugepage memory the mbuf points into. No persistence — packets are transient.
  • Mempool / Cache — Cache is PerCore and !Sync (per-lcore); backing free-stack is the only atomic touchpoint (bulk, amortized). NUMA-local (I11).
  • Ring — Send + Sync via UnsafeCell + atomic head/tail with audited ordering (I1); the sole sanctioned cross-core channel (I3).
  • PMD / EthDev — Send; a queue is single-owner (one lcore) → its rx_burst/tx_burst need no internal lock.
  • Classify tables (Lpm4/Cuckoo/Acl) — readers lock-free (RCU epoch or seqlock retry); writers serialized in the control plane; bounded staleness (I7).
  • FlowTable — PerCore shards keyed by RSS (a flow always lands on its owning core via symmetric RSS), so per-flow state needs no lock; aging driven by per-core timer wheel.
  • Persistence: none on the data path. Config (ports/queues/lcores/routes/ACLs) is JSON-loaded at startup; pcap files are the only on-disk artifacts (capture/replay). Telemetry counters are in-memory, scraped over the socket.

Compatibility: config schema is SemVer'd (config_version); additive fields → minor, removals → major; validator rejects unknown major. pcap is standard libpcap (interop). Telemetry counter names are stable within a major (#[non_exhaustive] on public enums for additive evolution).

  • L2-forward correctness: every input frame egresses with MACs swapped, bytes otherwise identical (differential vs golden).
  • ≥ 10 Mpps single-core on vNIC, 64 B frames (no kernel) — first throughput gate.
  • Zero heap allocations on the forward loop (allocator hook = 0, I4).
  • Config validator rejects 4 malformed configs (non-pow2 ring, undersized mempool, bad core mask, missing huge-dir) with correct error.

0.5 Conformance Fixtures

  • conformance/packets/l2_basic.pcap — input frames. golden/l2fwd_swapped.pcap — expected output. templates/cfg_1core_vnic.json — baseline config. Malformed: cfg_ring_not_pow2.json, cfg_mempool_too_small.json (I12 reject).

0.6 Pitfalls

  • Headroom/tailroom off-by-one → header rewrite corrupts adjacent bytes. Root: wrong data_off math. Debug: byte-diff vs golden (I8). Recover: bounds-checked prepend/adj.
  • Hugepage mmap fails silently (no MAP_HUGETLB reserve) → falls back to normal pages → TLB thrash. Root: nr_hugepages not set. Debug: /proc/meminfo HugePages_Free; numastat. Recover: setup-hugepages.sh, fail-fast if reserve < needed.
  • lcore not actually pinned → OS migrates thread → cache + NUMA misses. Root: affinity mask wrong. Debug: /proc/<tid>/stat CPU; taskset. Recover: assert affinity post-pin.
  • Mempool under-sized → rx_burst starves under burst. Root: sizing < in-flight. Debug: mempool_exhausted. Recover: size = §4 formula; validator check (I12).

0.7 Performance Concerns

mbuf metadata in 1 cache line (avoid 2-line straddle); burst loop unrolled over 32; mempool free-stack LIFO (recently-freed = cache-hot); avoid per-frame function-call overhead (inline hot ops). vNIC source pre-builds frames (measure forwarding, not generation).

0.8 Edge Cases

Empty burst (rx_burst==0 → spin); single frame; max-size jumbo (chained mbuf); tx_burst returns < n (sink full — re-queue path); mempool exactly drained then refilled.

0.9 Failure Analysis

Hugepage map failure → EAL init fails fast (blast radius: process won't start — correct). Mempool exhaustion → RX backpressure, counted (no crash). mbuf bounds violation → debug-build assert; release-build returns ParseError (containment: that packet). No rings/multi-core yet → contention not yet possible.

0.10 Operational Notes

tracing span at EAL init + port configure (setup only, never per-packet). Counters: rx_pkts, tx_pkts, mempool_exhausted, mbufs_in_use. PortStats is the operator's first window. Runbook seed: docs/runbooks/rx-zero.md.

Phase 1 — Lockless Rings (SPSC then MPMC), Per-Core Mempool Cache (Magazine), Multi-Core Run-to-Completion

1.1 Objectives

Add uns-ring (SPSC then MPMC, correct memory ordering — I1, bounded — I2); the per-core magazine cache in uns-mempool (I4); and a multi-core run-to-completion launch where each lcore owns a queue and busy-polls. No backends beyond vNIC yet.

1.2 Detailed Implementation Steps

  • uns-ring/spsc.rs: single-producer/single-consumer ring; prod_tail published with Release, consumed with Acquire (§8.3, I1); bounded drop-on-full (I2); pow2 mask (I12).
  • uns-ring/mpmc.rs: multi-producer/multi-consumer; CAS prod_head/cons_head to reserve, then advance *_tail in arrival order (wait for predecessor). burst.rs: reserve n in one CAS (burst enqueue/dequeue). order.rs: documented ordering proof + debug fences.
  • loom model (uns-ring tests): exhaustive producer/consumer interleavings assert no torn slot, no overrun, no lost item (I1/I2).
  • uns-mempool/cache.rs: per-core magazine (CACHE_SIZE 256–512); get/put hit local array (no atomics); bulk-transfer 32 to/from backing on miss/overflow (§8.4, I4).
  • uns-eal multi-core RTC: launch runs the app's per-lcore poll loop; each lcore = one RX queue + busy-poll + RTC processing; PerCore state per lcore (I3).

1.3 Deliverable

Multi-core L2-forward: N lcores each own a vNIC queue, poll + forward independently; aggregate throughput scales ~linearly with cores; loom green on rings; per-core cache eliminates atomics on the common path.

1.4 Acceptance Criteria

  • loom passes on SPSC + MPMC (no torn slot, no overrun, no lost/duplicated item — I1/I2).
  • Per-core cache: ≥ 99% of get/put hit local cache (no atomic) under steady forwarding (I4).
  • Multi-core scaling efficiency ≥ 0.85× linear to 8 cores (independent queues, no shared state — I3).
  • Aggregate ≥ 8 × single-core Mpps on 8 cores (within 15%).

1.5 Conformance Fixtures

  • templates/cfg_8core_8queue.json. benchmarks/mpps/scaling_{1,2,4,8}.json. microbench/ring_spsc.rs, ring_mpmc.rs. Loom harness fixtures in uns-ring/tests/.

1.6 Pitfalls

  • Missing Release/Acquire pairing → consumer reads slot before payload visible → corruption. Root: relaxed where release needed. Debug: loom failure; ThreadSanitizer-equiv. Recover: audited ordering (I1); proof in order.rs.
  • ABA on head/tail → slot reused mid-CAS → lost/duplicated item. Root: index reuse instead of monotonic counter. Debug: loom. Recover: monotonic 32/64-bit counters, mask only for indexing (§8.3).
  • False sharing on per-core counters/cache → cross-core cache-line bouncing kills scaling. Root: unpadded PerCore. Debug: scaling < linear; perf HITM. Recover: cache-line pad (I14).
  • Magazine size mismatched to burst → frequent backing touches. Root: cache < burst. Debug: high mempool_backing_ops. Recover: CACHE_SIZE ≥ several bursts.

1.7 Performance Concerns

Ring slots cache-line-aware; head/tail on separate cache lines (producer line vs consumer line) to avoid bouncing; burst reserve amortizes CAS; magazine keeps the hot path atomic-free; NUMA-local ring per producer-consumer pair where possible.

1.8 Edge Cases

Ring exactly full (drop, counted); ring exactly empty (poll spins); single producer many consumers (MPMC); wrap-around at counter boundary; all cores contend one MPMC ring (worst-case CAS).

1.9 Failure Analysis

Ring overrun → counted drop, no corruption (I2). Ordering bug → caught by loom pre-merge (never ships). Cache-line bounce → scaling regression, caught by scaling bench. Blast radius of a ring bug: the connected stages; contained by loom gate.

1.10 Operational Notes

Metrics: ring_full_drops{ring}, ring_depth{ring} (gauge), mempool_backing_ops, worker_busy_ratio. Runbook: docs/runbooks/ring-overrun.md (symptom: drops on one ring → producer faster than consumer → add consumer/queue or raise capacity).

Producer/consumer index protocol (mmap'd, kernel-shared) with correct ordering (analogous to I1, same acquire/release discipline as §8.3).
  • uns-afxdp/xsk.rs: bind() XSK to (ifindex, queue); XDP_ZEROCOPY else XDP_COPY; load/attach a minimal XDP redirect program (via libbpf) or use generic XDP.
  • uns-afxdp/zerocopy.rs: rx_burst = dequeue RX ring → wrap UMEM chunks as mbufs (no copy); refill FILL ring from freed chunks. tx_burst = enqueue chunk descriptors to TX ring, kick (sendto), reclaim from COMPLETION (I6/I10). Batch the FILL refill + TX kick into one syscall per burst (principle 3; netmap's batched-syscall lesson, Rizzo ATC 2012, paper 1).
  • uns-afpacket/blockring.rs: TPACKET_V3 block ring (mmap); RX = walk filled blocks → mbuf views; TX = TPACKET ring or sendmmsg. Copy-mode (portable, slower) — the fallback when XDP unavailable.
  • Backend selection in uns-pmd config (backend: vnic|afxdp|afpacket).

2.3 Deliverable

L2-forward and a loopback test run over AF_XDP (zero-copy on a supported NIC/veth) and AF_PACKET v3; same app code, swapped backend; near-line-rate on AF_XDP.

2.4 Acceptance Criteria

  • AF_XDP zero-copy: ≥ 90% of line rate on a 10 GbE-class path (or veth at high pps); copy-mode functional.
  • AF_PACKET v3 fallback: correct forwarding, lower pps (documented), no leaks.
  • FILL ring kept non-empty under load (refill each poll) — no RX starvation.
  • COMPLETION reclaim returns every TXed chunk exactly once (no leak, no double-use — I6).
  • Differential: frames forwarded over AF_XDP match vNIC golden output.

2.5 Conformance Fixtures

  • templates/cfg_afxdp_veth.json, cfg_afpacket.json. conformance/pcaps/loopback_in.pcap → golden/loopback_out.pcap. scripts/setup-veth-xdp.sh (CI veth + XDP attach).

2.6 Pitfalls

  • FILL ring starvation → rx_burst returns 0 even with traffic. Root: not refilling FILL after consuming RX. Debug: FILL-ring producer index stuck; rx_burst==0 + traffic present. Recover: refill FILL from freed chunks every poll (docs/runbooks/rx-zero.md).
  • UMEM chunk double-ownership → kernel and userspace both write a chunk → corruption. Root: chunk reclaimed before COMPLETION. Debug: garbled payloads; chunk-index audit. Recover: a chunk is owned by exactly one ring at a time (mirror I5 for chunks).
  • Zero-copy unsupported silently falls to copy → unexpected low pps. Root: NIC/driver lacks ZC. Debug: bind flags returned; ethtool features. Recover: detect ZC support, log mode, allow copy fallback explicitly.
  • XDP program not attached / wrong queue → packets go to kernel stack, not XSK. Root: redirect map missing. Debug: bpftool map; kernel stack counters rising. Recover: verify attach + queue binding at start.
  • TX kick missing (sendto) → TX ring fills, nothing sent. Root: forgot to notify kernel. Debug: TX producer advances, COMPLETION empty. Recover: kick after enqueue (or XDP_USE_NEED_WAKEUP).

2.7 Performance Concerns

Zero-copy = no memcpy (mbuf data is the UMEM frame) — the whole point. Batch FILL refill + TX kick (one syscall per burst, not per packet — netmap lesson). XDP_USE_NEED_WAKEUP avoids unnecessary syscalls. NUMA: UMEM on the NIC's local node. Copy-mode AF_PACKET pays one memcpy/packet — documented ceiling.

2.8 Edge Cases

NIC without zero-copy (copy fallback); veth (generic XDP, copy-only); ring sizes mismatched (FILL vs RX); kernel older than AF_XDP; queue count > NIC queues; jumbo frames over UMEM chunk size (chain or reject).

2.9 Failure Analysis

XSK bind fails (perms/kernel) → backend init error, fall back to AF_PACKET or vNIC (graceful). FILL starvation → throughput collapse, not corruption (detect via rx_burst==0). UMEM corruption → packet garbling, caught by checksum/differential (§P3). Blast radius: the affected port.

2.10 Operational Notes

Metrics: afxdp_fill_refill, afxdp_completion_reclaim, afxdp_rx_ring_full, afxdp_mode{zerocopy,copy}, afpacket_blocks_processed. Runbook: docs/runbooks/afxdp-setup.md (hugepages, cap_net_raw+cap_bpf, XDP attach, ZC detection) + rx-zero.md. Deployment: needs CAP_NET_RAW/CAP_BPF (or root); container privileged.

Phase 3 — Packet Parsing (eth/VLAN/QinQ/IPv4/IPv6/TCP/UDP/ICMP), Header Rewrite, Incremental L3/L4 Checksum, Offload Flags

3.1 Objectives

Build uns-pkt: zero-copy parsing of the full L2–L4 header stack into &[u8] views + a packed Ptype; header-rewrite helpers; incremental L3/L4 checksum (RFC 1624 — I9); and offload-flag handling (RX/TX cksum, VLAN strip/insert). This is the data the forwarder/QoS/conntrack layers consume.

3.2 Detailed Implementation Steps

  • uns-pkt/eth.rs,vlan.rs: parse EthHdr, walk VLAN/QinQ stack (0x8100/0x88A8), produce inner EtherType; bounds-checked (I8).
  • uns-pkt/ipv4.rs,ipv6.rs: parse IPv4 (IHL, options) + IPv6 (extension-header walk); validate lengths against data_len (I8); never OOB.
  • uns-pkt/{tcp,udp,icmp,arp}.rs: L4 + ARP/ICMP views; data-offset/length checks.
  • uns-pkt/ptype.rs: pack L2/L3/L4 type into Ptype during parse (one pass) → downstream branches on Ptype, not re-parse.
  • uns-pkt/cksum.rs: full Internet checksum (RFC 1071) + incremental update (RFC 1141/1624) — e.g. TTL decrement updates hdr_cksum by the 16-bit delta, no full recompute (I9). UDP/TCP pseudo-header checksum.
  • uns-pkt/rewrite.rs: MAC rewrite, TTL/hop-limit decrement (+ incremental cksum), VLAN push/pop (mbuf prepend/adj), NAT address/port rewrite (+ incremental L4 cksum).
  • Offload flags: if backend reports RX cksum-good, skip verify; set TX cksum-offload flags where the (virtual) device computes.

3.3 Deliverable

A parse+rewrite pipeline over a frame corpus: every header field correctly extracted; TTL-decrement + incremental checksum produces the same value as full recompute; VLAN push/pop round-trips.

3.4 Acceptance Criteria

  • Parse correctness vs scapy on the full corpus (eth/VLAN/QinQ/IPv4+opts/IPv6+exthdr/TCP/UDP/ICMP/ARP) — exact field match.
  • Incremental checksum == full recompute on 10⁶ randomized TTL/NAT mutations (I9).
  • Parser never panics / never OOB-reads on the malformed corpus (truncated, bad IHL, VLAN loop) — returns ParseError (I8).
  • VLAN push then pop yields byte-identical frame (round-trip).
  • cargo fuzz parser smoke (5 min): no panic/UB.

3.5 Conformance Fixtures

  • conformance/packets/{ipv4,ipv6,vlan_qinq,tcp,udp,icmp,arp}.pcap (valid). packets/malformed_{truncated,bad_ihl,vlan_loop,ipv6_exthdr_bomb}.pcap. vectors/checksum_vectors.json (input→expected cksum). golden/parse_fields.json (expected per-frame fields). fuzz/corpus/parse_frame/*.

3.6 Pitfalls

  • Trusting on-wire length fields → OOB read past data_len. Root: using IP TotLen/IHL without bounding to mbuf. Debug: fuzz crash; ASAN-equiv. Recover: every offset bounded to data() slice (I8, §Threat Model).
  • Incremental checksum wrong delta → packet silently dropped downstream / by receiver. Root: ones-complement folding error. Debug: incremental vs full mismatch (I9). Recover: RFC1624 formula + differential test.
  • VLAN/QinQ depth unbounded → parse loop / OOB on stacked tags. Root: no tag-stack limit. Debug: vlan_loop fixture. Recover: cap VLAN depth (e.g. 2), reject beyond.
  • IPv6 extension-header chain loop / bomb → CPU blowup. Root: following NextHdr without limit. Debug: ipv6_exthdr_bomb fixture; CPU spike. Recover: cap exthdr count + total length.
  • Pseudo-header checksum forgets payload length / proto → wrong L4 cksum. Root: incomplete pseudo-header. Debug: differential vs scapy. Recover: include src/dst/proto/len per RFC.

3.7 Performance Concerns

Parse once → Ptype (avoid re-parsing per layer); operate on &[u8] views (zero-copy, no struct decode); incremental checksum is a few adds (vs full recompute over the header); prefetch next mbuf's data while parsing current (software pipelining, §P9). Branch on Ptype table, not chained ifs.

3.8 Edge Cases

Minimum 64 B frame (padding); IPv4 with max options (IHL=15); IPv6 with multiple extension headers; QinQ (double tag); ICMP error embedding original header; ARP request vs reply; checksum field already 0 (UDP optional cksum).

3.9 Failure Analysis

Malformed frame → ParseError, counted drop, no crash (I8) — blast radius: that packet. Checksum bug → packet dropped by receiver (silent) — caught only by differential/cksum_mismatch (I9), hence the mandatory gate. Parser OOB would be memory-unsafe — prevented by Rust slice bounds + fuzz.

3.10 Operational Notes

Metrics: parse_drops{reason}, cksum_mismatch, ptype_distribution, vlan_depth_exceeded. EXPLAIN-equivalent: per-packet trace (§P11) records parsed Ptype + offsets. Runbook note: a spike in parse_drops → upstream sending malformed or a parser regression.

Phase 4 — RSS (Toeplitz) + Indirection Table + Multi-Queue + Flow Steering + Symmetric RSS

4.1 Objectives

Build uns-rss: Toeplitz hash over the 5-tuple (fixed 40 B key — I10), indirection table → RX queue, multi-queue RX so each lcore owns queue(s), n-tuple flow steering overrides, and symmetric RSS so a flow and its reverse land on the same queue/core (state locality for §P10 conntrack).

4.2 Detailed Implementation Steps

  • uns-rss/toeplitz.rs: Toeplitz hash (bit-walk the serialized tuple against the 320-bit key) — pure function (I10, principle 12); validated against the Microsoft RSS specification test vectors (paper 10).
  • uns-rss/indirection.rs: Indirection table (pow2, default 128) maps hash & mask → QueueId; reprogrammable by control plane (RCU-swapped — I7, ADR-013).
  • uns-rss/symmetric.rs: serialize the tuple with (min(src,dst), max(src,dst)) ordering so hash(a→b) == hash(b→a) — both directions same queue (the precondition for lock-free per-core conntrack, principle 4 + I3, consumed in §Phase 10).
  • uns-rss/steer.rs: exact-match n-tuple flow-steering table (cuckoo from §P5 stub here): specific 5-tuples override RSS to a chosen queue (e.g. pin a control flow to a core).
  • Multi-queue RX: uns-vnic (and AF_XDP) configured with N RX queues; vNIC source distributes synthetic flows by RSS for deterministic tests; each lcore polls its queue(s).
  • Wire rss_hash into the mbuf at RX (set by vNIC/AF_XDP path or computed in software for AF_PACKET).

4.3 Deliverable

A multi-flow workload spreads across queues/cores by RSS; reverse flows co-locate (symmetric); a steered 5-tuple lands on its pinned queue; load distribution is deterministic for a fixed key.

4.4 Acceptance Criteria

  • Toeplitz hash matches MS RSS spec test vectors exactly (I10).
  • Flow distribution across 8 queues within ±10% of uniform on a uniform-flow corpus.
  • Symmetric RSS: 1000 bidirectional flows — each flow + reverse on the same queue (100%).
  • Steering: every steered 5-tuple lands on its configured queue, overriding RSS.
  • Determinism: identical queue assignment across 100 runs (fixed key — I10).

4.5 Conformance Fixtures

  • conformance/vectors/rss_toeplitz.json (MS spec vectors). packets/multiflow_uniform.pcap, bidirectional_flows.pcap. templates/cfg_rss_8q.json, cfg_steering.json. golden/rss_queue_assignment.json.

4.6 Pitfalls

  • Asymmetric serialization → flow and reverse on different cores → conntrack state split across cores (needs a lock). Root: tuple not min/max-ordered. Debug: bidirectional fixture shows split. Recover: symmetric serialization (§8.5).
  • Per-run random key → non-reproducible distribution + unreproducible incidents. Root: random key default. Debug: replay diff. Recover: fixed key in config (I10/principle 12).
  • Indirection table not pow2 → mask wrong → skewed/aliased distribution. Root: bad config. Debug: skewed queue_distribution. Recover: validator enforces pow2 (I12).
  • Hashing the wrong byte order → distribution mismatch vs hardware/spec. Root: endianness in tuple serialize. Debug: vector mismatch. Recover: serialize per RSS spec (network order).

4.7 Performance Concerns

Toeplitz is a bit-walk — for software RSS (AF_PACKET path) use a precomputed byte-indexed table to make it O(tuple bytes) not O(bits). On AF_XDP/vNIC the hash may come from the (modeled) NIC → free. Indirection lookup is one cache-hot array access. Per-queue ownership = zero cross-core sharing (I3) → linear scaling.

4.8 Edge Cases

Single flow (all to one queue — degenerate, no spread); all flows same 5-tuple (one queue, hot — handled by skew-like steering); steering table miss (fall back to RSS); fewer queues than cores; non-IP frame (no 5-tuple → default queue).

4.9 Failure Analysis

Skewed distribution → one core hot, others idle → throughput ceiling on the hot core (not corruption). Detect via queue_distribution variance. Recover: re-balance indirection table, or steer the heavy flow. Wrong hash → conntrack mis-routing (caught in §P10 differential).

4.10 Operational Notes

Metrics: queue_distribution{queue} (gauge), rss_hash_value (sampled), steering_hits, steering_misses. The indirection table + key are dumped in the telemetry snapshot (reproducibility). Runbook: skewed distribution → numa.md/balancing note.

Phase 5 — Classification: LPM (DIR-24-8 IPv4 + trie IPv6), Cuckoo Exact-Match, ACL; Update-While-Lookup Safety (RCU/Seqlock)

5.1 Objectives

Build uns-classify: LPM via DIR-24-8 (IPv4) + 16-stride trie (IPv6) for routing; cuckoo hash for exact-match (flow/MAC); ACL (tuple-space / bit-vector) for filtering. All update-while-lookup safe — the control plane mutates while the dataplane reads lock-free (I7).

5.2 Detailed Implementation Steps

  • uns-classify/lpm4.rs: DIR-24-8 — tbl24 (2²⁴ entries: next-hop or pointer-to-tbl8) + tbl8 pool (256-entry second levels for prefixes longer than /24). Lookup: index tbl24[ip>>8]; if it points to a tbl8, index tbl8[ip&0xFF] (Gupta 1998) — 1–2 memory accesses.
  • uns-classify/lpm6.rs: 16-stride (or 8-stride) multibit trie for IPv6 /0../128.
  • uns-classify/cuckoo.rs: 2-table cuckoo hash (bounded probe, worst-case O(1) lookup — Pagh 2004); used for exact-match flow keys, MAC table, steering table.
  • uns-classify/acl.rs: tuple-space search or bit-vector classification over 5-tuple + ranges (ports) — ordered rules → action (permit/deny/redirect).
  • uns-classify/rcu.rs: epoch-based RCU — readers enter a read-side critical section (per-core epoch), writers publish a new table version + wait for grace period before freeing the old (I7). seqlock.rs: seqlock for small tables (reader retries on odd sequence).
  • Control-plane API: add/delete/bulk_update routes/rules → build new table → atomic publish; dataplane lookups never block.

5.3 Deliverable

The L3 router (§P6) resolves next-hops via LPM at line rate; exact-match flow lookups via cuckoo; ACL filters traffic; routes/rules can be added/removed live with no dataplane stall and no torn read.

5.4 Acceptance Criteria

  • LPM4 correctness vs a reference longest-prefix-match on a full BGP-table-shaped fixture (~800K prefixes) — exact next-hop.
  • LPM4 lookup ≤ 2 memory accesses; ≥ 50 Mpps lookup microbench (cache-resident tbl24 hot set).
  • Cuckoo: bounded probe (≤ configured max), no infinite insert loop; lookup O(1).
  • Update-while-lookup: 10⁶ lookups concurrent with 10⁴ updates — zero torn reads, zero reader stalls, no use-after-free of old table (I7, loom + soak).
  • ACL: rule precedence correct vs reference on overlapping rules.

5.5 Conformance Fixtures

  • conformance/vectors/lpm4_bgp_table.json (prefixes→next-hops), lpm4_lookups.json (queries→expected). vectors/cuckoo_keys.json. vectors/acl_rules.json + acl_queries.json. Concurrency fixture: lpm_update_under_load (loom + soak).

5.6 Pitfalls

  • tbl8 pool exhaustion → can't insert a long prefix. Root: pool under-sized for /25../32 count. Debug: tbl8_pool_full. Recover: size pool to prefix-length distribution; reject + alert on exhaust.
  • Cuckoo insertion loop (kick cycle) → insert never terminates. Root: load factor too high / bad hashes. Debug: kick count > threshold. Recover: cap kicks → resize/rehash (control-plane, off dataplane).
  • RCU grace period skipped → free old table while a reader still in it → use-after-free. Root: not waiting for all per-core epochs. Debug: Miri/loom; poison old table. Recover: proper grace-period wait (I7).
  • Seqlock reader infinite retry under hot writer → reader livelock. Root: writer holds odd seq too long. Debug: seqlock_retries spike. Recover: bound writer critical section; prefer RCU for hot tables.
  • LPM update not atomic (partial tbl24 write visible) → torn next-hop. Root: in-place mutation. Debug: differential during update. Recover: build-new + atomic-pointer-swap (RCU).

5.7 Performance Concerns

DIR-24-8 trades memory (2²⁴ × entry = ~64 MiB for tbl24) for O(1) lookup — the classic space/time deal; tbl24 hot set stays in LLC. Cuckoo: 2 cache accesses worst case; prefetch both buckets. ACL tuple-space can be slower — use only where needed, else exact-match. RCU read side is near-free (per-core epoch bump). Prefetch the LPM entry for the next packet while processing current (§P9).

5.8 Edge Cases

Default route (/0); host route (/32 — needs tbl8); overlapping prefixes (longest wins); ACL no-match (default action); cuckoo at max load factor; concurrent add + delete of the same prefix; IPv6 with many specific routes.

5.9 Failure Analysis

LPM miss (no route) → drop or send-to-default, counted (lpm_miss). Torn read → wrong forwarding (caught by differential + I7 enforcement). Cuckoo loop → control-plane stall (not dataplane), bounded by kick cap. Blast radius: routing decisions; contained by RCU correctness.

5.10 Operational Notes

Metrics: lpm_lookups, lpm_miss, tbl8_pool_used, cuckoo_load_factor, cuckoo_kicks, acl_matches{action}, table_update{table}, seqlock_retries, rcu_grace_waits. Control-plane updates logged with route/rule + epoch. Runbook: route-update stall → check rcu_grace_waits (a stuck reader holds the grace period).

Phase 6 — L3 LPM Router (TTL + incremental cksum + next-hop + ARP/ND) and L2 Learning Switch (MAC table, flood/forward/age)

6.1 Objectives

Build the two flagship forwarding apps. L3 router (uns-l3fwd): LPM route → next-hop → ARP/ND neighbor resolution + cache → rewrite (MAC + TTL decrement + incremental checksum — I9). L2 learning switch (uns-l2fwd upgraded): MAC learning table → forward/flood/age. mbuf refcount (clone) lands here for flooding/broadcast (I5).

6.2 Detailed Implementation Steps

  • uns-l3fwd: per-packet — parse → lpm.lookup(dst_ip) → next_hop_id → ARP/ND cache lookup → if hit: rewrite eth.dst=neigh.mac, eth.src=port.mac, TTL−−, incremental cksum (I9), tx_burst out the next-hop port; if miss: enqueue packet, emit ARP request / ND solicitation, resolve, then forward (or drop after timeout).
  • ARP/ND cache (uns-flow neighbor sub-table, RCU — I7): ip → (mac, state); states Incomplete/Reachable/Stale; refresh via ARP/ND; age out. ARP reply / ND advertisement handling in the dataplane (slow-path, low rate).
  • L2 learning switch: mac_table (cuckoo, RCU) src_mac → port; on RX learn src→ingress port; lookup dst_mac → forward to its port; miss → flood (clone mbuf to all other ports, refcount — I5); age entries via timer wheel (§P10 stub here).
  • mbuf clone (uns-mbuf refcount, I5): flooding clones the mbuf (refcnt++) to N ports; each tx_burst consumer frees its ref; data freed at refcnt 0.

6.3 Deliverable

uns-l3fwd routes IPv4/IPv6 across ports using a loaded route table, resolving neighbors via ARP/ND; uns-l2fwd learns MACs and forwards/floods/ages. Both run multi-core at line rate.

6.4 Acceptance Criteria

  • L3 forwarding correctness vs Linux kernel routing (netns differential) on a route fixture — same next-hop port, TTL decremented, checksum valid (I9).
  • ARP/ND: unresolved next-hop triggers request, resolves on reply, then forwards; cache hit on subsequent packets.
  • L2: known dst → unicast to learned port; unknown dst → flood to all-but-ingress; src learned; entries age out.
  • mbuf clone (flood): no double-free, no leak across N egress ports (I5).
  • TTL=1 packet → dropped + ICMP time-exceeded (or counted drop) — not forwarded with TTL 0.

6.5 Conformance Fixtures

  • conformance/vectors/route_table.json, packets/l3_route_mix.pcap → golden/l3_forwarded.pcap. packets/arp_resolve.pcap, nd_resolve.pcap. packets/l2_learn_flood.pcap → golden/l2_out.pcap. packets/ttl_1.pcap (expire).

6.6 Pitfalls

  • TTL decrement without checksum update → receiver drops (bad cksum). Root: forgot incremental update. Debug: cksum_mismatch at receiver; differential. Recover: incremental update on every TTL change (I9).
  • mbuf clone double-free on flood → freed by two ports → aliased buffer. Root: refcount not incremented per clone. Debug: poison + mbuf_double_free (I5). Recover: refcnt++ per egress, free decrements.
  • ARP cache thundering herd — many packets to an unresolved next-hop all emit ARP. Root: no in-flight suppression. Debug: ARP request storm. Recover: one outstanding request per next-hop; queue packets behind it.
  • MAC table flap (same MAC seen on two ports rapidly) → forwarding oscillation. Root: loop or move. Debug: mac_move counter. Recover: rate-limit moves; alert (possible L2 loop).
  • Forwarding to ingress port (L2) → reflection. Root: flood includes ingress. Debug: packet returns. Recover: exclude ingress port from flood set.

6.7 Performance Concerns

LPM lookup is the main per-packet cost (1–2 cache accesses) — prefetch next packet's route. ARP/ND cache hit is one cuckoo lookup (hot). Flood clone is rare (only on miss) — refcount avoids copy. TTL+cksum is a few cycles (incremental). Batch egress per port (group mbufs by out-port, one tx_burst/port).

6.8 Edge Cases

Default route; directly-connected (no next-hop rewrite beyond ARP); TTL=0/1 (expire); ARP for own IP (reply); gratuitous ARP; broadcast/multicast MAC (flood); IPv6 link-local (ND); MAC table full (evict LRU).

6.9 Failure Analysis

Route miss → drop/default, counted. Neighbor unresolved past timeout → drop queued packets, counted (arp_unresolved_drops). L2 loop → broadcast storm — mitigated by move rate-limit + (out of scope) STP; detect via flood-rate spike. Blast radius: forwarding for affected destinations.

6.10 Operational Notes

Metrics: l3_forwarded{port}, lpm_miss, ttl_expired, arp_requests, arp_resolved, arp_unresolved_drops, nd_*, mac_learned, mac_moves, flood_pkts, mbuf_clones. Per-packet trace shows route decision + neighbor. Runbook: broadcast storm → check flood_pkts/mac_moves (L2 loop).

Phase 7 — QoS: Token-Bucket Metering (srTCM/trTCM) + Hierarchical Scheduler (port/subport/pipe/tc/queue) + DRR/WRR + RED/WRED

7.1 Objectives

Build uns-qos: single token-bucket rate limiting; hierarchical scheduler (5-level: port → subport → pipe → traffic-class → queue) with DRR/WRR within a level + strict priority across traffic classes; RED/WRED active-queue-management drop; srTCM/trTCM metering (RFC 2697/2698) coloring packets for differentiated drop.

7.2 Detailed Implementation Steps

  • uns-qos/token_bucket.rs: token bucket (rate r, burst b); consume(len) → bool; refill by elapsed cycles (TSC-based, no syscall). Single-rate limiter.
  • uns-qos/meter.rs: srTCM (CIR/CBS/EBS → green/yellow/red) + trTCM (CIR/PIR → green/yellow/red) per RFC 2697/2698; meter classifies each packet to a color.
  • uns-qos/hsched.rs: hierarchical scheduler — port (link rate) → subport (token bucket) → pipe (per-subscriber token bucket) → traffic class (4 TCs, strict priority) → queue (4 queues/TC). Each level a token bucket; dequeue picks highest-priority TC with credit, then drr/wrr among its queues.
  • uns-qos/drr.rs: Deficit Round Robin (Shreedhar 1995) — per-queue deficit counter + quantum; fair byte-share among queues. WRR variant (weighted).
  • uns-qos/red.rs: RED (Floyd 1993) — average queue length → drop probability; WRED (per-color thresholds — drop red before yellow before green). Enqueue-time drop decision.
  • Wire QoS as an egress stage: classify (meter) → enqueue to (subport,pipe,tc,queue) → scheduler dequeues to TX at link rate.

7.3 Deliverable

An egress path that rate-limits per subscriber (pipe), prioritizes traffic classes, fairly shares within a class (DRR), and drops via WRED under congestion by color — measurable shaping + fairness.

7.4 Acceptance Criteria

  • Token bucket: measured egress rate within ±2% of configured r over a window; burst b honored.
  • Hierarchical scheduler: TC0 (highest priority) starves TC3 under congestion; within a TC, DRR shares bytes fairly (±5%) across queues per quantum.
  • WRED: under sustained overload, red-colored packets dropped at a higher rate than green (per thresholds); no tail-drop cliff.
  • srTCM/trTCM coloring matches RFC reference vectors.
  • QoS adds ≤ ~30 cycles/pkt on the egress path (within budget).

7.5 Conformance Fixtures

  • conformance/vectors/srtcm_trtcm.json (RFC vectors). templates/cfg_hsched_4tc.json. packets/qos_mixed_classes.pcap. golden/qos_shaped_rates.json, golden/drr_fairness.json, golden/wred_drop_by_color.json.

7.6 Pitfalls

  • Token-bucket refill using wall-clock syscall → per-packet syscall kills throughput. Root: clock_gettime per packet. Debug: flamegraph in QoS. Recover: TSC/cycle-counter refill, batched.
  • Priority inversion / TC starvation by design but unbounded → low-priority never sent. Root: strict priority without min guarantee. Debug: TC3 throughput 0. Recover: optional min-credit per TC (configurable).
  • DRR quantum smaller than max packet → queue can't send its packet → stall. Root: quantum < MTU. Debug: queue stuck with deficit < pkt. Recover: quantum ≥ MTU.
  • RED average-queue EWMA misconfigured → either no early drop (tail-drop cliff) or over-drop (underutilization). Root: weight/thresholds wrong. Debug: drop pattern vs queue length. Recover: tune w_q, min/max thresholds per Floyd.
  • Hierarchical token accounting drift (parent credited but child not) → rate exceeds link. Root: level accounting bug. Debug: egress > link rate. Recover: credit flows top-down; child bounded by parent.

7.7 Performance Concerns

QoS is per-packet on egress — keep it cheap: TSC refill (no syscall), branch-light meter, precomputed quanta. Scheduler dequeue is the hot loop — prioritize TCs with a bitmask of non-empty/credited queues. Per-pipe state cache-line aligned. Batch dequeue to fill a TX burst. WRED average-queue update is a shift+add.

7.8 Edge Cases

Zero rate (drop all); rate ≥ link (no shaping); single queue (DRR trivial); all queues empty (idle); burst exactly = bucket; all packets red (WRED drops most); min-size vs max-size packet mix (DRR fairness).

7.9 Failure Analysis

Mis-configured rate → over/under shaping (not corruption) — detect via egress-rate metric vs config. Starvation → low-priority drop spike. WRED misconfig → throughput or latency regression. Blast radius: the affected pipe/subport. Recovery: re-tune config (control plane), no restart.

7.10 Operational Notes

Metrics: qos_egress_rate{port,subport,pipe}, qos_drops{tc,color,reason}, drr_deficit{queue} (sampled), wred_avg_qlen{queue}, meter_color{green,yellow,red}. Dashboard: per-TC throughput + drop-by-color. Runbook: starvation/over-drop → inspect TC priority + WRED thresholds.

Phase 8 — Execution Models: Pipeline (stages on distinct cores via rings) vs Run-to-Completion; Load Distributor; Reorder Buffer

8.1 Objectives

Build uns-pipeline: the pipeline model (split processing into stages, each pinned to its own lcore, connected by uns-ring SPSC/MPMC) as an alternative to run-to-completion (RTC); a load distributor (one RX core fans packets to N worker cores by flow); and a reorder buffer that restores per-flow packet order after parallel processing (IX/distributor lesson).

8.2 Detailed Implementation Steps

  • uns-pipeline/rtc.rs: the existing run-to-completion driver (one lcore does the whole pipeline for its queue) — formalized + comparable. RTC is the IX dataplane model (Belay, OSDI 2014, paper 5): batched, zero-copy, run-to-completion per core (principle 4 — per-core sharding).
  • uns-pipeline/stage.rs: a Stage = (input ring, function, output ring); stages connected into a graph; each stage pinned to a distinct lcore — the modular packet-module dataplane of SoftNIC/BESS (Han 2015, paper 17) and VPL's vector graph (VPP ref-impl 2).
  • uns-pipeline/pipeline.rs: build a pipeline (e.g. RX-stage → classify-stage → forward-stage → TX-stage), each on its own core, mbufs flow via rings. Backpressure = bounded rings (I2, principle 7).
  • uns-pipeline/distributor.rs: load distributor — an RX core tags each mbuf with a flow id (RSS hash) and enqueues to the worker ring for that flow's core (sticky per flow → state locality + ordering within a flow, principle 4 + I3). MPMC where workers share, SPSC where flow-pinned (the only cross-core path, ADR-006).
  • uns-pipeline/reorder.rs: reorder buffer — assign a monotonic sequence number at distribution; workers process out of order (parallel); a reorder stage releases packets to TX in sequence order per flow (bounded reorder window; timeout releases to avoid HOL stall).

8.3 Deliverable

The same forwarding logic runs in both RTC and pipeline modes (config-selectable); a distributor spreads a single RX queue across workers with per-flow stickiness; the reorder buffer guarantees per-flow egress order; a comparison shows the tradeoff (RTC: better cache locality, simpler; pipeline: stage specialization, but ring + cross-core cost).

8.4 Acceptance Criteria

  • RTC vs pipeline produce identical forwarding output (differential) on the same corpus.
  • Distributor: per-flow stickiness 100% (a flow's packets all to one worker); cross-flow spread within ±10% of uniform.
  • Reorder: per-flow egress order preserved 100% even with workers finishing out of order (fault-injected variable per-packet latency).
  • Pipeline backpressure: a slow stage throttles upstream via bounded ring (no unbounded growth — I2); RTC has no inter-stage ring.
  • Measured tradeoff documented: RTC cycles/pkt vs pipeline cycles/pkt (ring + cross-core overhead quantified).

8.5 Conformance Fixtures

  • templates/cfg_rtc.json, cfg_pipeline_4stage.json, cfg_distributor.json. packets/multiflow_ordered.pcap → golden/ordered_out.pcap. Reorder fixture: workers with injected latency variance; assert egress order.

8.6 Pitfalls

  • Pipeline cross-core cache bouncing → mbuf metadata written on core A, read on core B → cache miss per handoff. Root: stage split too fine. Debug: scaling worse than RTC; perf HITM. Recover: coarsen stages; prefetch on dequeue; prefer RTC when locality dominates.
  • Reorder buffer HOL stall — a lost/slow packet blocks all later in-order release. Root: no timeout. Debug: reorder-window full, egress stalls. Recover: bounded window + timeout release (skip missing, count gap).
  • Distributor not flow-sticky → same flow on two workers → conntrack state split / reordering. Root: hashing or assignment bug. Debug: flow seen on 2 cores. Recover: deterministic flow→worker (RSS hash), sticky.
  • Ring backpressure deadlock in a pipeline cycle. Root: a cyclic stage graph with bidirectional full rings. Debug: all stages blocked. Recover: keep the stage graph acyclic; never block holding the only mbuf source.
  • Sequence-number wrap in reorder → false ordering. Root: small seq width. Debug: reorder error at wrap. Recover: wide monotonic seq + windowed comparison.

8.7 Performance Concerns

RTC: best cache locality (one core touches the packet end-to-end), no ring cost — the default. Pipeline: pays a ring enqueue/dequeue + a cross-core cache transfer per stage boundary — worth it only when a stage is heavy/specialized (e.g. crypto, deep classify). Distributor adds one RX core's worth of fan-out. Reorder buffer is per-flow state + a small window (cache-resident). Prefetch mbuf metadata on ring dequeue.

8.8 Edge Cases

Single stage (= RTC); single flow through distributor (one worker, no spread); reorder window of 1 (strict in-order, no parallelism benefit); all packets one flow (HOL within flow is inherent); worker crash mid-pipeline (drain its ring); empty pipeline stage.

8.9 Failure Analysis

Stage core stall → upstream ring fills → backpressure → RX drops (counted, I2) — contained, no corruption. Reorder HOL → latency spike on a flow (timeout bounds it). Distributor mis-assignment → conntrack/order bug (caught in §P10 differential). Blast radius: the pipeline; recovery = restart (crash-only).

8.10 Operational Notes

Metrics: stage_ring_depth{stage}, stage_cycles{stage} (sampled), distributor_flow_spread, reorder_window_used, reorder_timeouts, reorder_gaps. Mode (rtc/pipeline) in the telemetry snapshot. Runbook: pipeline slower than RTC → check per-stage stage_cycles + cross-core misses; consider coarsening.

Phase 9 — Performance Hardening: NUMA-Local Placement, Prefetch, Batch Everywhere, Cache-Line Alignment, False-Sharing Elimination, Write-Combining, Branch Reduction

9.1 Objectives

Drive the per-packet cost to the ≤150-cycle budget (§4): NUMA-local hugepage placement (I11), software prefetch of mbuf metadata + packet data, batching across every stage, cache-line alignment of hot structures, false-sharing elimination on per-core state (I14), write-combining for descriptor writes, and branch reduction in the hot path. This phase is measurement-driven (profile → fix → re-measure).

9.2 Detailed Implementation Steps

  • NUMA placement: assert mempool/rings/per-core data + UMEM are on the owning lcore's node; add numa_remote_access detection (I11); re-pin or re-allocate on violation.
  • Prefetch: in the burst loop, while processing mbuf i, prefetch mbuf i+1's metadata (and its data for parse) and the LPM/flow entry for i+1 — software pipelining hides cache-miss latency (VPP/DPDK lesson).
  • Batch everywhere: ensure RX/parse/classify/rewrite/TX/free all operate on the burst array; eliminate any residual per-packet call/alloc (I4).
  • Cache-line alignment: #[repr(align(64))] on mbuf metadata, ring head/tail (separate lines), per-core counters; verify layout (pahole-equiv).
  • False-sharing elimination: per-core counters/cache each on their own cache line (I14); no two cores write the same line on the hot path.
  • Write-combining: where descriptor writes go to a (modeled) device region, use write-combining stores + a single fence per burst (not per descriptor).
  • Branch reduction: replace Ptype if-chains with table dispatch; branchless mask compute where possible; mark cold paths #[cold].

9.3 Deliverable

A hardened dataplane that hits the cycle budget: ≥ the §4 Mpps targets with a measured cycles/pkt breakdown; flamegraphs + perf stat (cache misses, branch misses) documented in docs/performance/.

9.4 Acceptance Criteria

  • 64 B single-core ≥ 14.88 Mpps on vNIC (≤ ~150 cycles/pkt) — the headline gate.
  • perf stat: L1/L2 miss rate on the hot path below a documented threshold; branch-miss rate reduced vs pre-hardening baseline.
  • Zero remote-NUMA accesses on the steady-state hot path (I11, numastat).
  • Zero false-sharing HITM events on per-core counters (I14, perf c2c-equiv).
  • No heap allocation on the hot path (I4, allocator hook = 0).
  • Prefetch yields a measurable cycles/pkt reduction (before/after documented).

9.5 Conformance Fixtures

  • benchmarks/mpps/64b_singlecore.json, mixed_size.json, imix.json. benchmarks/microbench/{prefetch_on_off,numa_local_remote,branch_table_vs_if}.rs. docs/performance/cycle-budget.md worksheet.

9.6 Pitfalls

  • Prefetch too late / too early → no benefit or evicts useful lines. Root: prefetch distance wrong. Debug: cycles/pkt unchanged or worse. Recover: tune prefetch distance (usually 1–2 ahead); measure.
  • Accidental remote-NUMA allocation → silent ~100 ns/access tax. Root: allocator picked the wrong node. Debug: numastat, numa_remote_access. Recover: explicit node binding (I11).
  • False sharing reintroduced by a new shared counter. Root: a metric added without padding. Debug: scaling regression; perf c2c. Recover: per-core + pad (I14); lint for shared atomics on hot path.
  • Over-batching latency → waiting to fill a burst adds latency under low load. Root: fixed burst wait. Debug: p99 latency up at low pps. Recover: adaptive burst (drain partial after a short spin).
  • Branchless code that's actually slower (extra work both sides) → regression. Root: premature branchless. Debug: microbench. Recover: measure; keep branch where predictable.

9.7 Performance Concerns

This phase is performance. Key levers: cache locality (RTC + prefetch), atomic-free hot path (per-core + magazine), syscall-free hot path (poll + TSC), batch amortization (burst=32), NUMA locality. Tail latency: bounded by burst wait + ring depth; coalescing not needed (uniform packet cost). TSC for timing (no syscall). Document cycles/pkt budget allocation per stage.

9.8 Edge Cases

Single packet (no batch amortization — worst cycles/pkt); imix (mixed sizes — cache behavior varies); max-size packet (memory-bound, not cycle-bound); cross-NUMA forwarding (deliberate remote — measure cost); cold cache (first packet of a burst).

9.9 Failure Analysis

A perf regression is a release blocker (bench gate, §P12). Remote-NUMA or false-sharing → throughput cliff, caught by scaling bench + perf. No correctness impact from this phase (pure optimization) — guarded by the differential suite (optimizations must not change output). Blast radius: throughput SLO.

9.10 Operational Notes

Metrics: cycles_per_pkt (sampled), l2_miss_rate, branch_miss_rate, numa_remote_access, false_sharing_misses. docs/performance/ holds the methodology (flamegraph workflow, perf stat counters, cycle-budget worksheet). Bench host pinned + isolated (isolcpus, nohz_full) for stable numbers.

Phase 10 — Stateful Flow Table + Connection Tracking (5-tuple FSM) + Timer Wheel (#204) + Stateful NAT + Aging/Eviction

10.1 Objectives

Build uns-flow + uns-timer: a per-core stateful flow table (5-tuple keyed, cuckoo from §P5) with a connection-tracking state machine (TCP-like + UDP), a timer wheel (cross-link #204) driving aging/eviction, and a stateful NAT sample (rewrite + reverse-mapping, incremental L4 cksum — I9). Flows are per-core (symmetric RSS guarantees a flow + reverse on one core — I3, no lock).

10.2 Detailed Implementation Steps

  • uns-flow/flowtable.rs: PerCore flow table, cuckoo-keyed by 5-tuple; entry = FlowEntry{key,state,last_seen,nat,timer}. Lookup on every packet; create on first packet of a new flow.
  • uns-flow/fsm.rs: connection-tracking FSM — TCP: New→SynSent→Established→FinWait→Closed (transitions on flags + direction); UDP: New→Assured→Closed (Assured after bidirectional traffic). Invalid transitions → counted + optional drop.
  • uns-timer/wheel.rs: hashed timer wheel (Varghese & Lauck 1987 / #204) — O(1) insert/cancel/expire; per-core (no lock). hierarchical.rs: hierarchical wheels for a wide timeout range (ms → minutes).
  • uns-flow/aging.rs: each flow has a timer (refreshed on packet via last_seen + timer reset); expiry → evict entry, free state. State-dependent timeouts (Established longer than New).
  • uns-flow/nat.rs: stateful NAT — on first packet allocate a translation (e.g. source IP:port → public IP:port), store forward + reverse mapping; rewrite + incremental L4 checksum (I9); reverse-direction packets matched by the reverse mapping. Port-pool management.

10.3 Deliverable

A conntrack-aware dataplane: flows tracked through their lifecycle, aged out on timeout, with a working stateful NAT (forward + return path) — all per-core, lock-free, at line rate.

10.4 Acceptance Criteria

  • Conntrack FSM correctness vs a reference (e.g. simplified nf_conntrack) on a TCP+UDP flow corpus — correct state transitions.
  • NAT: bidirectional flow translated correctly (forward rewrite + return matched via reverse map); checksum valid (I9); differential vs Linux NAT (netns).
  • Aging: idle flow evicted after its state-dependent timeout (timer wheel); active flow refreshed (not evicted).
  • Timer wheel: O(1) insert/expire; 10⁶ concurrent timers, expiry within one tick of target.
  • Per-core: a flow + its reverse always on the same core (symmetric RSS) → zero cross-core flow-state access (I3).

10.5 Conformance Fixtures

  • conformance/packets/tcp_handshake.pcap, udp_flow.pcap, tcp_teardown.pcap → golden/conntrack_states.json. packets/nat_bidirectional.pcap → golden/nat_translated.pcap. vectors/timer_wheel_expiry.json. Aging fixture (idle → evict).

10.6 Pitfalls

  • Flow + reverse on different cores → state split → needs a lock (violates I3) or two half-states. Root: asymmetric RSS. Debug: flow state on 2 cores. Recover: symmetric RSS (§P4) is a hard prerequisite here.
  • Timer not cancelled on early flow close → stale timer fires on a reused entry → wrong eviction. Root: missing cancel. Debug: eviction of an active flow. Recover: cancel-on-close; generation/epoch on entries.
  • NAT port-pool exhaustion → can't translate new flows. Root: ports not freed on flow close. Debug: nat_pool_exhausted. Recover: free port on eviction; size pool; alert.
  • Conntrack table full → can't track new flows. Root: eviction slower than creation under flood. Debug: flowtable_full. Recover: LRU/timeout eviction; rate-limit new flows; counted drop.
  • Checksum not updated after NAT rewrite → receiver drops. Root: forgot incremental L4 cksum on addr/port change. Debug: cksum_mismatch. Recover: incremental update on every NAT rewrite (I9).
  • FSM state confusion under reordering/retransmit → wrong state. Root: strict FSM without retransmit tolerance. Debug: differential. Recover: tolerate retransmits; window-based validation.

10.7 Performance Concerns

Flow lookup is per-packet — cuckoo O(1), prefetch the entry for the next packet. Per-core flow table = no lock (I3). Timer wheel insert/expire O(1); batch expiry per tick. last_seen update is a cheap write (cache-hot entry). NAT rewrite + incremental cksum is a few cycles. Aging runs amortized (a few timer-wheel slots per poll, not a full scan).

10.8 Edge Cases

First packet of a flow (create); flow close (TCP FIN/RST → fast timeout); idle flow (age out); flow flood (table pressure → eviction); NAT hairpinning; UDP "connection" (no handshake — Assured heuristic); reordered SYN/SYN-ACK; simultaneous open; timer wheel wrap (hierarchical promotion).

10.9 Failure Analysis

Table full → new-flow drops, counted (flowtable_full); existing flows unaffected. NAT pool exhaustion → new translations fail, counted; existing intact. Stale timer → wrong eviction (caught by generation check). Blast radius: new flows / the affected flow. Crash-only: state lost on restart (flows re-established).

10.10 Operational Notes

Metrics: flows_active, flows_created, flows_evicted{reason}, flowtable_full, conntrack_state{state} (gauge), nat_translations, nat_pool_used, nat_pool_exhausted, timer_inserts, timer_expiries. Per-packet trace shows flow state + NAT mapping. Runbook: flow-table full → check creation rate vs eviction; NAT exhaustion → port-pool size.

Phase 11 — Observability: Per-Queue/Per-Core xstats, HDR Latency Histograms, pcap Capture/Replay, Per-Packet Trace, Drop Accounting, Telemetry Socket

11.1 Objectives

Build uns-telemetry: per-queue/per-core counters (xstats — zero-cost on hot path, I14), HDR latency histograms (p50/p99/p999), pcap capture + replay (libpcap format), a per-packet trace ring, drop accounting by reason, and a telemetry unix socket the control plane scrapes. This makes the dataplane debuggable without perturbing it.

11.2 Detailed Implementation Steps

  • uns-telemetry/xstats.rs: PerCore<Counters> (cache-line padded — I14, principle 14, ADR-018); hot path bumps a local u64 (no atomic), enforcing principle 4 (no cross-core sharing) on the metrics path; an off-path aggregator sums across cores on scrape. Named counters (rx/tx/drops/parse/lpm/flow/qos/...).
  • uns-telemetry/histo.rs: HDR histogram for latency (timestamp at RX, sample at TX) — per-core, merged off-path; report p50/p99/p999 (ADR-019). Sampled (1/N packets) to bound the TSC-read cost (principle 14 — observability is zero-cost on the hot path).
  • uns-telemetry/pcap.rs: pcap writer (capture a ring of recent packets, or a filtered subset) + reader (replay a pcap through the vNIC source — deterministic test driver). libpcap format (tcpdump/wireshark/scapy interop).
  • uns-telemetry/trace.rs: per-packet trace ring (lock-free, per-core) — records (timestamp, ptype, decision: forwarded/dropped/reason, flow state) for the last K packets; dumped on demand. Off by default (cost) or sampled.
  • uns-telemetry/drops.rs: drop accounting — every drop path increments a drop{reason} counter (parse, ring-full, lpm-miss, qos, flow-full, ttl-expired, nat-fail). The single source of truth for "where did my packets go".
  • uns-telemetry/socket.rs: unix-domain telemetry socket — control plane connects, requests a snapshot (all xstats + histograms + config), receives JSON. Off the data path (a control thread).

11.3 Deliverable

A running dataplane exposes a complete counter set + latency percentiles over a unix socket; captures/replays pcaps; traces recent packets; accounts every drop by reason — with zero measurable hot-path cost from counters (I14).

11.4 Acceptance Criteria

  • xstats: all packets accounted (rx = forwarded + dropped-by-all-reasons; conservation check). Zero false-sharing from counters (I14, perf c2c).
  • Latency histogram: p50/p99/p999 reported; matches a reference timing within sampling error.
  • pcap: capture then replay reproduces the same forwarding decisions (deterministic, vNIC).
  • Per-packet trace: last K packets' decisions retrievable; dump cost off-path only.
  • Telemetry socket: control plane scrapes a full snapshot without dropping packets (no hot-path stall).
  • Hot-path counter cost: ≤ 1 cycle/pkt added (a local increment) — measured before/after.

11.5 Conformance Fixtures

  • conformance/pcaps/capture_replay.pcap (capture → replay → assert identical decisions). golden/xstats_conservation.json (rx = fwd + drops). golden/latency_percentiles.json. Telemetry-socket fixture (scrape under load).

11.6 Pitfalls

  • Atomic counter on the hot path → cross-core contention (the principle-4/14 violation). Root: shared global counter. Debug: scaling regression; perf c2c. Recover: per-core + pad; aggregate off-path.
  • Timestamping every packet → TSC read + store per packet adds cost. Root: unsampled histogram. Debug: cycles/pkt up. Recover: sample 1/N; or only on a traced subset.
  • pcap capture in the hot path → memcpy per packet stalls forwarding. Root: synchronous capture. Debug: throughput drop when capture on. Recover: capture to a per-core ring, drain off-path; or capture a sampled subset.
  • Telemetry socket scrape blocks the dataplane → poll stall. Root: control work on a data lcore. Debug: rx_burst gap during scrape. Recover: dedicated control thread; lock-free snapshot.
  • Drop reason missing → packets vanish unaccounted ("where did 2% go?"). Root: a drop path without a counter. Debug: conservation check fails. Recover: every drop path increments a reason (audit).

11.7 Performance Concerns

Counters: per-core u64 increment (1 cycle, no atomic, cache-hot — I14). Histogram: sampled (1/N) to amortize TSC read. Trace: lock-free per-core ring, off by default. pcap: off-path drain. Telemetry socket: separate thread, lock-free snapshot of per-core counters (read-mostly). The whole subsystem is designed to be invisible to the hot path.

11.8 Edge Cases

Counter overflow (u64 — unreachable at realistic rates); histogram with one sample; pcap larger than ring (oldest evicted); trace ring wrap; telemetry scrape during shutdown; all packets dropped (conservation: rx = drops).

11.9 Failure Analysis

A missing drop counter → unaccounted loss (caught by conservation check — the key invariant of this phase). Histogram sampling bias → misleading percentiles (documented sampling rate). Telemetry thread crash → no metrics (dataplane unaffected — control/data split). Blast radius: observability only; dataplane keeps forwarding.

11.10 Operational Notes

Full counter catalogue exported via the telemetry socket → Prometheus (control plane). Dashboards: throughput (per-queue/core), drop-by-reason, latency percentiles, flow/NAT/QoS panels. The per-packet trace + pcap capture are the primary deep-debug tools. This phase is what makes every prior phase operable in production.

Compatibility & Versioning

  • Config schema: SemVer (config_version). Additive fields → minor; removal/rename/semantic change → major. Validator rejects unknown major (I12).
  • PMD trait / PmdOps: stable within a major; #[non_exhaustive] on public enums (OffloadFlags, error enums) for additive evolution. New backends implement the trait without breaking apps.
  • mbuf layout: internal (not a wire format); changes are a major version (affects ABI for any C interop). Headroom/data-room are config, not ABI.
  • pcap format: standard libpcap — full interop with tcpdump/wireshark/scapy; never changes.
  • Telemetry: counter names + JSON snapshot schema stable within a major; additive counters → minor. Prometheus metric names follow the same policy.
  • RSS key + hash: the Toeplitz hash is fixed (MS spec); changing the key is a config change (alters distribution, not correctness). Symmetric serialization is stable (conntrack co-location depends on it).
  • Wire protocols: Ethernet/IP/TCP/UDP/ARP/ND/VLAN are external standards — we conform, we don't version them.
  • Semantic versioning policy: workspace crates share a major; pre-1.0 minor may break (documented). Deprecation: one minor of warning before removal.

Scalability Analysis

  • Bottlenecks: per-packet LPM/flow cache miss (mitigated by prefetch + cache-resident tables); one hot flow on one core (inherent to per-flow ordering — distributor + reorder bound it); MPMC ring CAS contention (mitigated by SPSC where flow-pinned + burst reserve); NIC/UMEM bandwidth (AF_XDP ceiling).
  • Scaling ceilings: physical cores (per-core sharding scales linearly while RSS spreads flows); NIC queue count (RSS needs ≥ cores queues); hugepage memory (mempool sizing); LLC for hot LPM/flow tables.
  • Horizontal scaling: more boxes behind L3 ECMP / a hardware RSS hash; the per-core shard is the unit; no cross-box coordination (stateless forwarding) or sticky-by-hash (stateful).
  • Vertical scaling: add lcores + RX queues; RSS spreads load; near-linear while flows are well-distributed and per-core (I3).
  • Sharding/partitioning: RSS hash partitions flows across cores; symmetric RSS keeps a flow + reverse on one core (state locality); flow-table + conntrack are per-core shards.
  • Replication pressure: L2 flood clones mbufs (refcount, bounded by port count); broadcast/multicast bounded.
  • Coordination overhead: none on the hot path (per-core + rings); control-plane table updates are RCU (readers never block); aging is per-core (timer wheel).
  • Network fanout: per-port TX batching; flood fan-out bounded by port count.
  • Scheduler saturation: an lcore is a busy-poll loop at 100% — saturation = packet drops (counted), not scheduler thrash; QoS shapes egress.
  • Storage growth: none on the data path (packets transient); pcap capture is bounded ring / sampled; counters are fixed-size.
  • Metadata scaling: flow table O(active flows) per core (eviction bounds it); LPM O(prefixes) (DIR-24-8 fixed 2²⁴ + tbl8 pool); ACL O(rules).

Domain Deep Dive — Anatomy of a Packet (RX → parse → classify → forward → QoS → TX) at line rate

A concrete trace of one 64 B IPv4 packet through the L3 router on one lcore, in the run-to-completion model, with the cycle budget accounted. Demonstrates poll, batch, zero-alloc, per-core sharding, and incremental checksum working together.

Setup: lcore 2 owns RX queue 2 (RSS-assigned), mempool + LPM + ARP cache + flow table all NUMA-local to lcore 2's node. Burst size 32. vNIC backend (deterministic).

Step table — what lcore 2 does in one poll iteration:

t Step Action Cost (cycles, approx) Invariant / note
1 Poll RX rx_burst(q2, &mut burst[32]) → 32 mbufs from mempool-backed RX ring ~40 / 32 = ~1.3/pkt no interrupt (principle 1); no alloc (mbufs pre-owned, I4)
2 Prefetch prefetch mbuf[i+1] metadata + data while processing mbuf[i] hidden (overlapped) software pipelining (§P9)
3 Parse EthHdr → EtherType 0x0800 → IPv4 view; pack Ptype; bounds-checked ~20/pkt no OOB (I8); zero-copy &[u8]
4 Classify lpm4.lookup(dst_ip) → tbl24[ip>>8] → next_hop_id=7 (1 access, prefetched) ~25/pkt RCU read (I7); DIR-24-8 (§8)
5 Neighbor arp_cache.get(7) → dst_mac (cuckoo, hot) ~15/pkt per-core, no lock (I3)
6 Rewrite eth.dst=neigh.mac; eth.src=port.mac; ipv4.ttl-- ~12/pkt byte-conservation (I8)
7 Checksum hdr_cksum = incremental(old_ttl, new_ttl) (RFC1624) ~5/pkt incremental==full (I9); no recompute
8 QoS (opt) meter → token bucket → enqueue to (pipe,tc,queue); scheduler picks ~30/pkt (if enabled) shaping (§P7); off → skip
9 TX group by out-port; tx_burst(out_q, &batch) → returns 32 (all sent) ~40 / 32 = ~1.3/pkt mbufs now device-owned (I6/I10)
10 Free unsent (none here) freed to mempool; loop ~0 no partial-free (I6); LIFO cache-hot

Cycle budget: parse 20 + LPM 25 + ARP 15 + rewrite 12 + cksum 5 + RX/TX/free amortized ~3 = ~80 cycles/pkt (QoS off) or ~110 (QoS on) — within the ≤150 budget (§4). At ~2.2 GHz, 80 cycles ≈ 36 ns/pkt → ~27 Mpps/core (comfortably above 14.88).

Why this is fast: (1) poll — no interrupt, no syscall (step 1, 9); (2) batch — RX/TX/free amortize fixed cost over 32 (steps 1, 9, 10); (3) zero-alloc — mbufs are pre-owned, freed to a per-core cache (steps 1, 10, I4); (4) per-core — LPM/ARP/flow are this core's NUMA-local, lock-free state (steps 4–5, I3/I11); (5) prefetch — the next packet's metadata + LPM entry are in flight while this one is processed (step 2); (6) incremental checksum — 5 cycles, not a full header recompute (step 7, I9).

Why this is deterministic (I10): with the vNIC backend, a fixed RSS key, and fixed table contents, this exact packet always lands on lcore 2, takes next-hop 7, egresses the same port with the same bytes — replaying the input pcap reproduces the identical egress pcap, byte for byte.

Failure-path variant (neighbor miss): suppose at step 5 the ARP cache misses (next-hop 7 unresolved). The router enqueues this mbuf behind one outstanding ARP request for next-hop 7 (no thundering herd — §P6 pitfall), emits an ARP request, and continues the burst. On the ARP reply, the cache fills and the queued packet forwards; if no reply within the timeout (timer wheel), the queued packet is dropped and arp_unresolved_drops++ . The slow path costs ~hundreds of cycles but is rare (once per neighbor) — the fast path (step 5 hit) dominates. This is the bias the whole design holds: the common case is a handful of cache-hot accesses; the rare case is contained and counted.

Mental Models & First Principles

The compressed insights an expert holds before touching the code. Each predicts behavior, names the bug class you write without it, and the § where this blueprint applies it.

  • MM1 — A NIC is a producer-consumer ring; "driving" it is just advancing two indices. RX = the device produces filled descriptors, you consume them; TX = you produce descriptors, the device consumes them. Predicts: every I/O bug reduces to "who owns this slot now, and is the index visible to the other side?". Bug class without it: treating RX/TX as function calls and missing that a descriptor not yet consumed by the device must not be reused. Applied: §8.3 (ring semantics), §Phase 0 (vNIC RX/TX), §Phase 2 (AF_XDP FILL/COMP/RX/TX).
  • MM2 — Throughput is a cycle budget, not a rate. At 14.88 Mpps on one ~2.2 GHz core you have ≈150 cycles/packet; every design choice spends from that fixed bank. Predicts: you can sum the cost of parse+lookup+rewrite+checksum and know before benchmarking whether a design fits. Bug class without it: adding a "cheap" per-packet malloc or clock_gettime that silently overruns the bank and shows up only as a throughput cliff. Applied: §4 (constraints), §8.7 (worked budget), §Phase 9, Back-of-Envelope Capacity Model.
  • MM3 — The kernel's per-packet cost is a fixed tax you pay once at the seam or never. Interrupt + softirq + skb alloc + socket copy + syscall is ~thousands of cycles/packet; AF_XDP pays it once at setup and then the kernel is off the path. Predicts: the win from kernel-bypass is bounded by how much of that tax you actually remove (copy-mode AF_PACKET keeps the copy). Bug class without it: expecting line rate from a copy-mode fallback. Applied: principle 1/15, §Phase 2, Comparative Architecture Table.
  • MM4 — Shared mutable state is the enemy; the ring is the only sanctioned sharing. A value that never leaves its core needs no lock and no atomic. Predicts: throughput scales linearly with cores exactly until two cores write the same cache line — then it collapses to one core's worth. Bug class without it: a Mutex<HashMap> flow table that serializes every core, or an unpadded shared counter that false-shares. Applied: principle 4, I3/I14, §Phase 1, §Phase 10 (per-core conntrack).
  • MM5 — A lockless ring is correct only if the payload write happens-before the index publish. The producer must Release the tail after writing the slot; the consumer must Acquire the tail before reading. Predicts: a relaxed store on the tail lets the consumer read a slot whose payload is not yet visible — intermittent corruption that no single-threaded test finds. Bug class without it: the classic "works on x86, corrupts on ARM" memory-ordering bug (x86's TSO hides the missing fence). Applied: I1, §8.3, §Phase 1, ADR-005, tested by loom in §Phase 12.
  • MM6 — Batching amortizes fixed cost and unlocks prefetch. Process 32 packets per call: the per-call overhead is paid once per 32, and while you work packet i you prefetch i+1's data and lookup entry, hiding cache-miss latency. Predicts: per-packet processing is not 1/32 the throughput of batched — it is far worse, because prefetch can no longer overlap. Bug class without it: a "simple" per-packet loop that benchmarks at a fraction of expected pps. Applied: principle 3, §Phase 9 (prefetch), §8.7.
  • MM7 — Tables must be read without locking; reclamation is deferred, not synchronous. RCU/seqlock let the dataplane read while the control plane swaps a new version; the old version is freed only after every reader has left it (grace period). Predicts: a lock on the lookup path stalls all cores during a route update; a torn in-place write yields a wrong next-hop. Bug class without it: use-after-free of the old table (freed before a reader finished) or a read of a half-updated table. Applied: I7, principle 8, §Phase 5, ADR-013.
  • MM8 — Symmetric hashing is what makes per-core flow state lock-free. If a flow and its reverse hash to the same core, all of a connection's packets — both directions — land on one core, so its conntrack/NAT state needs no lock. Predicts: asymmetric RSS splits a connection across two cores, forcing either a lock or two half-states. Bug class without it: a conntrack table that needs a per-entry lock, re-introducing the contention sharding removed. Applied: §8.5, principle 12, I3, §Phase 4 → consumed in §Phase 10.
  • MM9 — Every packet that disappears must increment a counter; "loss" with no reason is a bug, not a drop. Conservation: rx == forwarded + Σ drops{reason}. Predicts: if the conservation check fails, there is a drop path with no counter — you have lost observability, not just packets. Bug class without it: the 3 a.m. "where did 2% of traffic go?" with no telemetry to answer it. Applied: I2, §Phase 11 (drop accounting), Operational Readiness (Drop SLO).
  • MM10 — Determinism is engineered, and it is the precondition for debugging. Fix the RSS key, the hash seeds, and use the vNIC source, and the same input pcap reproduces the same packet→queue→core→action→egress, byte for byte. Predicts: with a random key you cannot reproduce an incident; with a fixed one you can replay it offline. Bug class without it: heisenbugs that vanish on the next run. Applied: I10, principle 12, §Phase 4, §Phase 11 (replay), §Phase 12 (differential).

Its one defining decision is direct device ownership via VFIO/UIO: the PMD maps the NIC's registers and DMA rings into userspace and bypasses the kernel entirely, which wins when you own the NIC and need the absolute ceiling (hardware RSS, flow director, inline crypto, 100/200 GbE). This stack instead uses the AF_XDP/AF_PACKET kernel seam (ADR-007/008), trading peak throughput for portability and not needing root-VFIO — DPDK's regime wins in a dedicated appliance, ours in a portable/learnable build.
  • Snabb — a Lua/LuaJIT dataplane whose defining decision is the app/link graph in a JIT-compiled high-level language: you wire "apps" together with "links" (rings) and LuaJIT compiles the hot loop. This wins for rapid prototyping and readability of the dataplane. We reject the managed-language hot path (ADR-001) because a JIT/GC introduces tail-latency nondeterminism the cycle budget (MM2) cannot absorb; we borrow Snabb's clean app/link separation conceptually in uns-pipeline.
  • Cisco VPP — its defining decision is vector packet processing: each graph node processes a whole vector of packets (not one), so the instruction cache stays hot for the node's code across the batch and per-packet dispatch overhead is amortized. This wins at scale with a deep, stable feature graph. We adopt the batch idea (burst=32, MM6) but reject the full graph-node DSL (ref-impl 2 pitfall) as heavier than our RTC+pipeline; VPP wins when you need a large, composable, production feature set out of the box.
  • Google Snap (SOSP 2019) — its defining decision is networking as an always-on userspace microkernel-style service ("engines") with microsecond-scale scheduling and live upgrade, decoupling NIC hardware from transport (it hosts the Pony Express transport). This wins at hyperscale where centralizing host networking, upgradability, and CPU-efficiency across many tenants matters more than a single flow's peak. We are a single-process dataplane with no live-upgrade story (crash-only, Failure Modes & Recovery); Snap's regime wins when host networking is a shared, continuously-evolving platform service.

Back-of-Envelope Capacity Model

The numbers an expert computes before designing, each derived step-by-step from the System Constraints (§4) and the domain model (§8). All formulas shown; no asserted-only numbers.

  • B1 — Packets per second at line rate (10 GbE, 64 B frames). On the wire a 64 B Ethernet frame carries 20 B of overhead (7 B preamble + 1 B SFD + 12 B inter-frame gap). pps = line_rate / ((frame_bytes + overhead) × 8) = 10e9 / ((64 + 20) × 8) = 10e9 / 672 = 14.88e6 → 14.88 Mpps. This is the canonical "must hit 14.88 Mpps/10G" target in §4 and the §Phase 9 gate.
  • B2 — Per-packet cycle budget (1 core @ 2.2 GHz at 14.88 Mpps). cycles_per_pkt = CPU_Hz / pps = 2.2e9 / 14.88e6 ≈ 148 → ≈148 cycles/packet (≈67 ns). This derives the ≤150-cycle budget asserted in §4 and MM2, and the §8.7 worked breakdown (≈80–135 cycles) must fit under it.
  • B3 — 100 GbE escalation. At 100 GbE, B1 scales: pps = 100e9 / 672 ≈ 148.8 Mpps. Budget per core unchanged at ≈148 cycles, so cores needed = 148.8e6 / 14.88e6 = 10 cores minimum just to keep up at 64 B — confirming the Scalability Analysis claim that line rate scales by adding lcores + RX queues (RSS spread).
  • B4 — RX ring buffer RAM per queue. ring_RAM = descriptors × desc_size. With the §4 default 1024-entry ring and a 16 B descriptor: 1024 × 16 = 16 KiB/queue. For 16 queues: 16 × 16 KiB = 256 KiB — negligible; rings are not the memory pressure (the mbuf pool is, B5).
  • B5 — mbuf pool size and RAM. §4 sizes the pool as ≥ 2 × (n_queues × ring_size + per_core_cache × n_cores) + in-flight margin. For 16 queues × 1024 + 16 cores × 512 cache, doubled: 2 × (16×1024 + 16×512) = 2 × (16384 + 8192) = 49,152 mbufs. Each mbuf = 64 B metadata + 128 B headroom + 2048 B data room + tailroom ≈ 2304 B. pool_RAM ≈ 49,152 × 2304 ≈ 113 MiB. With 2 MiB hugepages: ⌈113 MiB / 2 MiB⌉ = 57 hugepages — well within the §4 1–64 GiB envelope.
  • B6 — DIR-24-8 tbl24 footprint. The first level is 2^24 entries; at 2 B/entry (next-hop id or pointer-flag): 2^24 × 2 = 32 MiB (4 B/entry → 64 MiB, the §Phase 5/ADR-011 figure). This is the classic space-for-time trade (MM2): 32–64 MiB of RAM buys a 1-memory-access lookup. The hot working set (a few thousand active /24s) stays in LLC.
  • B7 — Cycles for one LPM cache miss. A DRAM access is ~70 ns ≈ 70e-9 × 2.2e9 ≈ 154 cycles — more than the entire per-packet budget (B2). This is why prefetch (MM6, §Phase 9) is mandatory: a single un-prefetched tbl24 miss blows the budget; prefetching packet i+1's entry while processing i hides it.
  • B8 — Per-core throughput at the §8.7 budget. At ≈80 cycles/pkt (QoS off, §8.7): pps_per_core = 2.2e9 / 80 ≈ 27.5 Mpps; at ≈110 (QoS on): ≈20 Mpps. Both exceed 14.88 Mpps (B1), giving the headroom the §4 vNIC target (10–20 Mpps/core) and §Phase 0 (≥10 Mpps) rely on.
  • B9 — Multi-core aggregate and scaling efficiency. §Phase 1 requires ≥0.85× linear to 8 cores. aggregate = single_core_pps × cores × efficiency = 14.88e6 × 8 × 0.85 ≈ 101 Mpps — the ~100 Mpps figure in the §Performance Engineering 8-core target. Efficiency < 1 because the MPMC ring CAS and any residual shared line (false sharing, I14) cost grows with cores.
  • B10 — FD budget. §4 caps FDs at ≤64. AF_XDP uses 1 XSK socket/queue + 1 UMEM fd; for 16 queues: 16 + 1 = 17 fds, plus a handful of pcap/telemetry-socket fds → comfortably < 64. This is why the FD budget is a constraint, not a bottleneck.
  • B11 — Latency floor (UDP echo, vNIC). With no kernel and busy-poll, one-way cost ≈ B2 budget × a few stages. §4 targets p50 ≤ 2 µs: 2 µs = 4400 cycles @ 2.2 GHz — ample versus ~80–135 cycles of processing; the latency is dominated by the burst-fill wait (up to 32 packets) + ring depth, not compute. This is why §Phase 9 adds adaptive burst drain under low load (drain a partial burst after a short spin) to protect p99.
  • B12 — Conntrack table RAM. A FlowEntry (§11 Core Schema) ≈ 5-tuple (37 B) + state + last_seen (8 B) + nat ptr (8 B) + timer handle (8 B) ≈ 64 B (one cache line). For 1M active flows: 1e6 × 64 = 64 MiB/core-set. With per-core sharding across 16 cores that is ~4 MiB/core if flows are evenly spread (symmetric RSS, MM8) — keeping the hot flow set near LLC and bounding the §Phase 10 flowtable_full pressure.

Alternative Architectures (Roads Not Taken)

Three fundamentally different architectures for the same goal (line-rate userspace/host packet processing), each embodied by a real system, with the regime where it wins and why this blueprint rejected it.

Alt-1 — In-kernel XDP/eBPF dataplane (no userspace bypass).

   NIC ──IRQ/NAPI──▶ XDP hook (eBPF program, in driver)
                       │  verdict: XDP_DROP / XDP_TX / XDP_REDIRECT
                       ├─▶ XDP_REDIRECT ─▶ another netdev / CPU / AF_XDP socket
                       └─▶ XDP_PASS ─▶ normal kernel stack (skb)
   (program is JIT'd in-kernel; runs before skb allocation)

Regime where it wins: DDoS scrubbing, load balancing, and per-packet filtering where you want to run inside the kernel before skb allocation, share the NIC with the host stack, and deploy/upgrade a small program without a dedicated core or a separate process. Embodied by Cilium / Katran (Facebook's XDP L4 load balancer) and the XDP framework (Høiland-Jørgensen, CoNEXT 2018, paper 2). Why rejected here: the eBPF verifier bounds program complexity (no unbounded loops, limited state), so full stateful L2–L4 processing, hierarchical QoS, and conntrack/NAT at this richness do not fit the model; and the goal of this project is to teach the dataplane mechanisms themselves (mempool, rings, PMD), which XDP hides inside the kernel. We instead consume AF_XDP as a backend (§Phase 2) rather than living inside the XDP hook.

Alt-2 — Microkernel / dataplane-OS with hardware-enforced isolation.

   ┌──────────── control plane (full OS kernel) ────────────┐
   │  sets up protection domains, NIC queues, memory         │
   └───────────────────────┬─────────────────────────────────┘
                            │ (control only; off the data path)
   ┌──────────── data plane (per-app protection domain) ─────┐
   │  app owns its NIC queue directly (hardware-virtualized) │
   │  run-to-completion, zero syscalls, batched, polled       │
   └──────────────────────────────────────────────────────────┘

Regime where it wins: multi-tenant hosts that need both line rate and hardware-enforced isolation between untrusted dataplane apps — the OS sets up protected NIC queues once, then each app runs its own dataplane with the kernel fully off the path. Embodied by Arrakis (Peter et al., OSDI 2014, paper 6) and IX (Belay et al., OSDI 2014, paper 5), which split control/data planes and give apps direct, protected device access. Why rejected here: it requires SR-IOV / hardware virtual functions and a custom OS or dom0-style control plane — explicitly a non-goal of this blueprint (§1: no SR-IOV, no VF passthrough). We borrow the control/data-plane split (§3 architecture, telemetry socket) and the run-to-completion model (IX → §Phase 8) without the hardware-isolation machinery; the dataplane-OS regime wins when you must isolate mutually-distrusting tenants at line rate.

Alt-3 — Interrupt-driven, allocate-per-packet socket stack (the thing we are not building).

   NIC ──IRQ──▶ softirq/NAPI ──▶ alloc skb ──▶ protocol stack
                                      │  copy to socket buffer
                                      └─▶ recvmsg() syscall ──▶ app
   (one interrupt + one skb alloc + one copy + one syscall per packet-ish)

Regime where it wins: the overwhelming majority of applications — anything that is not bottlenecked on packet rate. At ≤1 Mpps with bursty, latency-tolerant traffic, paying the kernel tax (MM3) buys you the entire mature kernel stack (TCP, routing, netfilter, sockets) for free, with no dedicated cores burned and no special privileges. Embodied by the Linux network stack itself (Bovet & Cesati, book 9), the reference our differential oracle compares against (§Phase 12). Why rejected here: it caps at ~1 Mpps/core and adds unbounded latency jitter from interrupts and allocation (principle 1/2) — precisely the wall this entire project exists to break through; but it is the correct choice whenever the cycle budget (MM2) is not the binding constraint, which is why it remains the default for general-purpose hosts.

Pipeline model Processing split into stages, each on its own core, connected by rings.
EAL Environment Abstraction Layer — hugepages, lcores, per-core data, NUMA topology.

Magazine cache Per-core array of free mbufs enabling atomic-free alloc/free on the common path.
rte_ring / Ring Lockless bounded queue (SPSC or MPMC) with head/tail counters and explicit ordering.

FILL / COMPLETION / RX / TX ring AF_XDP's four rings: empty-to-fill, sent-reclaim, received, to-send.

AF_PACKET v3 Portable mmap'd block-ring packet capture/send fallback (TPACKET_V3).

RSS Receive Side Scaling — spreading flows across queues/cores by a hash.
Toeplitz hash The RSS hash function over the 5-tuple using a fixed key.
Indirection table Maps RSS hash to an RX queue (reprogrammable).
Symmetric RSS Serialization making a flow and its reverse hash to the same queue (state locality).
Flow steering Overriding RSS for specific n-tuples to a chosen queue.

LPM Longest-Prefix-Match routing lookup.

RCU Read-Copy-Update — lock-free reads with deferred reclamation of old versions.

Distributor An RX core that fans packets to worker cores, sticky per flow.
FILL starvation RX returns nothing because the AF_XDP FILL ring was not refilled.

False sharing Two cores writing the same cache line, causing cache-line bouncing.
