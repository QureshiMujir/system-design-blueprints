Hard questions (§37)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why is the FFT both faster and more accurate than the naïve DFT, and how do you encode that in a test? Synthesize §4.1 (error derivation) + I2/MM3 (§34) + Phase 13 (§25.2 differential): the bound must be N-parameterized (c·log₂N·ε), and the suite logs FFT-vs-naïve error side-by-side to prove the selling point.
  2. Given N = 44100, walk the planner's decision and predict the plan tree. Synthesize §11.4 (PlanTree) + §17.2 (factor → 2²·3²·5²·7²) + §22.2 (cost model/measure): mixed-radix nodes over small-prime codelets, no Bluestein needed; contrast with N=1009 which routes to Bluestein/Rader (§18).
  3. Why does wisdom key on (N,dir,layout,ISA,dtype) and not just N — what breaks if you drop ISA? Synthesize §11.9 (WisdomKey) + I9 (§7) + §22.6 (pitfalls) + MM4 (§34): a plan measured under AVX-512 reused on an AVX2-only core is suboptimal or selects an unavailable codelet — a correctness-adjacent perf bug.
  4. A prime-N transform is 5× slower than the nearest power-of-2. Is that a bug? Synthesize §4 (prime-N row) + C10 (§36) + §18.7 (Bluestein overhead) + §33 (prime-N scaling): no — Bluestein's M=next_pow2(2N−1) gives a bounded ~3–6× constant factor; only outside that range is it a bug (§27 prime-size cliff).
  5. Where is the single unsafe seam, and what two invariants must hold or it becomes memory-unsafe? Synthesize §3.3 (boundaries) + P6 (§6) + I3 + I15 (§7) + §23.6: the SIMD codelets + in-place permutation; the bijection (I3) and the planner's scratch sizing/alignment (I15) are the preconditions.
  6. Why assert error bounds instead of bit-equality, and when must you offer bit-equality anyway? Synthesize P7 (P7) + ADR-18/ADR-25 + §29 (Compatibility) + I4: accumulation order is plan-dependent, so bit-equality across plans is unmaintainable; a PFFT_DETERMINISTIC mode is the stable contract for regulatory replay.
  7. Trace a forward→inverse round-trip under each normalization convention. Where can a factor of N leak in twice? Synthesize §8.1 (conventions) + I5 (§7) + §20.2/20.6 (normalization step + double-normalize guard): the scale is one explicit step keyed to Normalization; the guard + norm_convention_id prevent the caller-plus-IFFT double scale.
  8. Why is a single 1-D FFT hard to thread, and where does parallelism actually come from? Synthesize §3.3 (concurrency boundary) + §33 (scalability) + I11 + §21.10: each stage depends on the previous (sequential); parallelism comes from batching and multi-dim row/column independence (disjoint cover, I11).
  9. What makes bit-reversal the performance villain at large N, and what's the lever? Synthesize §8.4 + C5/C7 (§36) + §24.6 (pitfalls) + §32 (cache artifacts): scattered access blows the cache once N exceeds L2 (N>L2/16); blocked/cache-oblivious permutation is the win.
  10. How does Rader reduce a prime-N DFT to a convolution, and what number-theoretic object makes it work? Synthesize §8.8 (Rader) + §18.2 (primitive_root/modinv) + I10: a primitive root g of N reindexes the N−1 non-DC outputs into a length-(N−1) cyclic convolution; DC is handled separately.
  11. Why does the complex multiply use the 4-mul form, not the 3-mul Karatsuba form — and when would you flip? Synthesize ADR-19 + §11.1 + the ADR-19 "when rejected wins" cell (§9): 4-mul has better FP error and pipelines better on FP hardware; 3-mul wins only where multiplies dominate and adds are free (fixed-point/integer transforms).
  12. How does RFFT achieve ~2× speed and ½ memory, and which two output bins are special? Synthesize §8.6 + I6 + MM8 (§34) + §19.2: pack reals into a half-size complex FFT + one unscramble pass; X[0] (DC) and X[N/2] (Nyquist) are purely real and must store zero imaginary parts.
  13. An FFTW-compatible C caller passes an unaligned, wrong-length buffer with a NaN inside. Trace what happens to each. Synthesize I1 + I12 + I13 (§7) + §23.6/§26 (threat model): wrong length/alignment → validated to a typed error/null plan before compute; NaN → propagated per IEEE-754, never "cleaned."
  14. Why is the bignum-multiplication hook precision-limited, and what's the principled fix? Synthesize §8.9 + §20.6 (pitfalls) + §11.12 (NTT note) + §27 (bignum overrun): f64's 53-bit mantissa loses carry precision past ~2⁵³; the NTT (exact modular transform) is the robust path (deferred).
  15. What does the cost model compute in ESTIMATE mode, and why isn't it enough — what's the safety valve? Synthesize §11.7 (cost_estimate) + §22.2/22.6 + ADR-09: a static Σ codelet_flops + memory_traffic·bytes_cost; miscalibrated constants pick poor plans, so MEASURE + wisdom is the valve.
  16. Two candidate plans for the same N tie on measured time. How is the tie broken, and why does it matter? Synthesize I4 (§7) + §22.6 (stable tie-break) + ADR-25: prefer the canonical plan on ties so the plan-tree hash (I9) and deterministic mode stay reproducible.
  17. Why does AVX-512 sometimes lose to AVX2 on large FFTs, and how does the design guard against shipping the regression? Synthesize §24.6 (downclock pitfall) + §4 (bandwidth-bound) + §24.9/§28 (CI bench matrix): AVX-512 downclocking + bandwidth-bound large N; per-ISA bench gates block regressions at merge.
  18. A 2D FFT comes out transposed/scrambled. What are the two likeliest causes and the catching test? Synthesize §21.6 (axis/transpose pitfalls) + MM9 (§34) + §21.4 (2D oracle diff): wrong contiguous-axis convention or a transpose bug; the 2D naïve-DFT oracle diff is the net.
  19. Why is the naïve O(N²) oracle, not FFTW, the primary source of truth — even though FFTW is faster and battle-tested? Synthesize ADR-20 + §6 (P1) + §25.6 (FFTW-diff masking): FFTW shares sign/normalization conventions with us, so it could mask a shared-convention bug; the independent oracle cannot.
  20. How does deterministic mode coexist with a planner whose whole job is to pick different plans per machine? Synthesize ADR-25 + I4/I9 (§7) + §29 (Compatibility): PFFT_DETERMINISTIC forces a fixed canonical plan + accumulation order, trading the planner's adaptivity for bit-replay — a separate, stable contract.
  21. What is the arithmetic intensity of an FFT, and what does it tell you about where to spend optimization effort? Synthesize C8 (§36) + §32 (roofline) + §33: AI ≈ 0.156·log₂N flop/B → large N is bandwidth-bound, so memory layout (bit-reversal/transpose/twiddle streaming) matters more than shaving flops there.
  22. Why are there separate twiddle tables for split-radix, and what invariant ties them to the main table? Synthesize §11.5 (TwiddleKind::SplitRadixW3) + I7 + §16.2/16.6: split-radix needs W^{3k}; it must share the exact sign convention of W^k or outputs are subtly wrong (the same generator, different stride).
  23. When the planner picks Bluestein for a prime N whose N−1 is itself prime, what happens recursively, and what bounds the depth? Synthesize §8.8 + §18.7/18.8 (edge) + §22.8: the inner length-(N−1) convolution may itself need Bluestein; the planner bounds search/recursion depth, and Bluestein's pow2 inner FFT terminates the chain.
  24. Why does execute take &self while mutating scratch, and what contract makes that sound? Synthesize §11.3 (interior UnsafeCell) + I14 + ADR-06: a single-thread-per-execute contract; concurrent execute on the same plan requires external sync or a clone — documented, not enforced by the type.
  25. How would you detect, in production telemetry, that twiddle recurrence drift (not a codelet bug) is degrading accuracy? Synthesize I7 + §14.6 (drift) + §27 (accuracy drift) + §28 (telemetry): twiddle_max_err rising with N while per-codelet diffs stay green points at recurrence drift → switch to direct-trig (the ADR-07 knob).

34. Mental Models & First Principles

The compressed insights an FFT expert carries. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — The FFT is divide-and-conquer on the DFT's algebraic structure; the twiddle factor is the merge step. The DFT matrix factors into sparse stage matrices; each Cooley–Tukey split is "solve two half-size DFTs, then merge with a diagonal of twiddles." Predicts: every variant (radix-r, mixed-radix, split-radix) is just a different factoring of the same matrix, so they all compute the same X to within rounding. Bug class without it: treating radix-4/split-radix as "a different transform" and expecting different results, instead of asserting one shared oracle bound. Applied: §8.2, §8.7, Phase 1 (§13), Phase 4 (§16).
  • MM2 — W_N^{k+N/2} = −W_N^k is the whole speedup. The half-period antisymmetry of the roots of unity lets one twiddle multiply serve two outputs (the butterfly's a±w·b). Predicts: the flop count is ~(N/2)·log₂N butterflies because each stage reuses every twiddle product twice; lose the symmetry and you're back to O(N²). Bug class: computing w·b twice (once per output) — correct but throws away the constant factor that makes it an FFT. Applied: §8.1–8.3, Phase 1 (§13.2).
  • MM3 — Accuracy improves with the fast algorithm because error counts stages, not terms. Each value passes through log₂N butterfly roundings, vs N additions in the naïve DFT → forward error ~c·log₂N·ε·‖x‖ vs ~N·ε·‖x‖. Predicts: the FFT is both faster and more accurate; accuracy degrades only logarithmically with N. Bug class: setting a fixed absolute tolerance independent of N (false fails at large N, missed bugs at small N) instead of an N-parameterized bound. Applied: §4.1, I2, Phase 3 (§15.2), Phase 13 (§25).
  • MM4 — There is no single best FFT; the optimal plan is a function of (N's factorization, cache, ISA). The best decomposition trades flops against memory traffic against codelet quality, all machine-dependent — hence the planner. Predicts: a hardcoded "always radix-2" loses to a measured plan on composite/prime N and on other CPUs; wisdom must key on ISA+dtype. Bug class: baking one decomposition in, or keying wisdom on N alone → a plan measured on one machine misapplied on another. Applied: §3.2 (planner), ADR-09/ADR-17, Phase 10 (§22).
  • MM5 — Plan once, execute many; the plan owns all the memory. Planning is amortized over thousands of executes; execute must be allocation-free and re-entrant on its own scratch. Predicts: steady-state latency is jitter-free only if no allocation/planning happens per call (I14); real-time use depends on it. Bug class: allocating scratch or re-planning inside execute → latency spikes, no real-time guarantee. Applied: ADR-06, I14, §11.3, Phase 10 (§22).
  • MM6 — Bit-reversal is a permutation, and permutations are bijections — prove it, don't eyeball it. DIT requires the input in bit-reversed order; the permutation must hit every index exactly once. Predicts: an off-by-one (reversing b vs b−1 bits) yields a plausible-but-wrong spectrum that no magnitude check catches — only a bijection test (histogram all-ones) and the oracle diff do. Bug class: silent index corruption that passes casual inspection. Applied: §8.4, I3, Phase 1 (§13.6), Phase 13 (§25).
  • MM7 — Any DFT is a convolution in disguise (Bluestein), and any convolution is a DFT (the convolution theorem). Bluestein turns a length-N DFT into a length-≥(2N−1) convolution computable by a power-of-2 FFT; the convolution theorem turns conv into FFT·FFT. Predicts: no size is unsupported — the prime-N "cliff" is a bounded constant factor (~3–6×), not an asymptotic wall; and fast multiplication/filtering ride on the same kernel. Bug class: declaring prime sizes unsupported, or padding insufficiently and getting silent circular wrap-around. Applied: §8.8, §8.9, I10, Phase 6 (§18), Phase 8 (§20).
  • MM8 — Real input has Hermitian symmetry, so half the spectrum is free. X[N−k]=conj(X[k]) → only N/2+1 outputs are independent; pack two reals into one complex FFT. Predicts: RFFT is ~2× faster and ½ memory; X[0] and X[N/2] are purely real. Bug class: storing nonzero imaginary parts for DC/Nyquist, or running reals through full c2c and paying 2× for nothing. Applied: §8.6, I6, ADR-13, Phase 7 (§19).
  • MM9 — A multi-dimensional FFT is separable: transform along each axis independently. 2D/3D = batched 1-D FFTs per axis (row-column). Predicts: the bottleneck is the transpose/strided access between axes, not the FFTs; blocking the transpose is the lever. Bug class: doing strided column FFTs without a transpose (cache thrash), or mixing up which axis is contiguous (transposed spectrum). Applied: §3.2 (multidim), Phase 9 (§21), §33 (Scalability).
  • MM10 — The butterfly tile lives in registers; data streams past it. Peak fraction is won when accumulators + twiddles fit the vector register file and independent chains hide FMA latency; lost the instant the codelet spills. Predicts: a butterfly too wide for the register file falls off a performance cliff (visible in disasm as spills) — the same failure mode as a GEMM micro-kernel. Bug class: widening a codelet past the register budget and silently regressing throughput. Applied: P4 (P4), §11.6, Phase 11 (§23.6), Phase 12 (§24).

Required reading (§5)

5.1 Books

  • Van Loan, Computational Frameworks for the Fast Fourier Transform (SIAM 1992) — the definitive FFT matrix framework: factorizations of the DFT matrix (radix-2/4, split-radix, mixed-radix, PFA), Kronecker-product notation. The semantics oracle for every variant. Applied: §8 (domain model), Phase 4 (§16, split-radix), Phase 5 (§17, mixed-radix).
  • Oppenheim & Schafer, Discrete-Time Signal Processing (3e) — ch.8 (DFT, properties), ch.9 (FFT algorithms: DIT/DIF radix-2/4, prime-factor, chirp-z/Bluestein, Goertzel). Core derivations. Applied: §8.2–8.8, Phase 1 (§13), Phase 6 (§18).
  • Cormen, Leiserson, Rivest, Stein, Introduction to Algorithms (CLRS) — ch.30 (Polynomials and the FFT): the divide-and-conquer derivation, bit-reversal, iterative FFT, FFT-based polynomial/integer multiplication. Clean pseudocode (study, do not copy). Applied: §8.2/8.4, Phase 1 (§13), Phase 3 (§15), Phase 8 (§20, bignum hook).
  • Higham, Accuracy and Stability of Numerical Algorithms (2e) — §24 (the Fast Fourier Transform): the O(log N) error bound, twiddle-factor error, why FFT is more accurate than naïve DFT. Source of every accuracy bound we assert. Applied: §4.1, I2/I7/I8, Phase 3 (§15), Phase 13 (§25).
  • Press et al., Numerical Recipes (3e) — ch.12–13 (FFT, applications): real/multidim FFT, convolution/correlation, overlap-add/save, power spectra. Pragmatic; note its in-place index tricks. Applied: Phase 7 (§19, RFFT), Phase 8 (§20, convolution), Phase 9 (§21, multidim).
  • Brigham, The Fast Fourier Transform and Its Applications — intuition for DIT/DIF flow graphs, windowing, leakage. Applied: §8.2/8.3 (butterfly/flow-graph), Phase 1 (§13).
  • Tolimieri, An & Lu, Algorithms for Discrete Fourier Transform and Convolution — group-theoretic view; Rader/PFA/Winograd; convolution algebra. Applied: §8.8 (Rader), Phase 6 (§18).
  • Hennessy & Patterson, Computer Architecture (6e) — ch.2 (memory hierarchy), App.B/C. For twiddle-table residence & bit-reversal cache behavior. Applied: §4 constraints, Phase 12 (§24), §32 (Performance Engineering).
  • Agner Fog, Optimizing subroutines + instruction tables — FMA/shuffle latency-throughput for the butterfly register budget. Applied: P4 (§6), Phase 11 (§23), Phase 12 (§24, butterfly budget).

5.2 Papers

  • Cooley & Tukey, "An Algorithm for the Machine Calculation of Complex Fourier Series" (Math. Comp. 1965) — the paper. The recursive even/odd split. Foundational. Applied: §8.2, Phase 1 (§13.2), Phase 3 (§15.2).
  • Frigo & Johnson, "The Design and Implementation of FFTW3" (Proc. IEEE 2005) — the planner, codelets, genfft, wisdom, the estimate/measure dichotomy. The architecture blueprint for this project. Applied: §3.2 (planner box), ADR-09/ADR-17, Phase 10 (§22.2).
  • Frigo, "A Fast Fourier Transform Compiler" (PLDI 1999) — how FFTW generates optimal straight-line codelets; informs our hand-written codelet shapes. Applied: ADR-08, Phase 11 (§23.2), Phase 12 (§24.2, small-N codelets).
  • Bluestein, "A linear filtering approach to the computation of the DFT" (1970) — the chirp-z transform for arbitrary N. Applied: §8.8, I10, Phase 6 (§18.2).
  • Rader, "Discrete Fourier transforms when the number of data samples is prime" (Proc. IEEE 1968) — prime-N DFT via cyclic convolution + primitive root. Applied: §8.8, Phase 6 (§18.2, rader).
  • Duhamel & Hollmann, "Split-radix FFT algorithm" (Electron. Lett. 1984) — the lowest-flop power-of-2 FFT. Applied: §8.7, Phase 4 (§16.2, split_radix).
  • Singleton, "An algorithm for computing the mixed radix FFT" (IEEE ASSP 1969) — practical mixed-radix; FFTPACK lineage. Applied: §8.7, Phase 5 (§17.2, cooley_tukey/codelets).
  • Sorensen et al., "Real-valued fast Fourier transform algorithms" (IEEE ASSP 1987) — RFFT / Hermitian-symmetry exploitation, the packing tricks. Applied: §8.6, I6, Phase 7 (§19.2).
  • Bailey, "FFTs in external or hierarchical memory" (Supercomputing 1989) — the four-step / six-step FFT for cache/large-N; informs mixed-radix blocking. Applied: §8.7, Phase 12 (§24), §33 (Scalability).
  • Schönhage & Strassen, "Schnelle Multiplikation großer Zahlen" (Computing 1971) — FFT-based integer multiplication; the #370 consumer's basis. Applied: §8.9, Phase 8 (§20.2, bignum_hook), §11.12 (NTT note).
  • Swarztrauber, "FFT algorithms for vector computers" (Parallel Computing 1984) — vectorization of butterflies; informs SIMD codelets. Applied: ADR-23, Phase 11 (§23.2).
  • Johnson & Frigo, "A modified split-radix FFT with fewer arithmetic operations" (IEEE TSP 2007) — current record flop count; accuracy tradeoff. Applied: §4.1, Phase 4 (§16), §32 (flop model).

5.3 Reference Implementations

  • FFTW3 (kernel/, dft/, rdft/, genfft/, api/) — the gold standard: planner, codelets, wisdom, the estimate/measure machinery, the C ABI we mirror. Study; do not copy. Lesson: the plan/codelet split. Pitfall to avoid: genfft is OCaml-generated C — we hand-write explicit Rust codelets, not a code generator (deferred). Applied: §3.2 (planner), ADR-08/09/16/17, Phase 10 (§22), Phase 11 (§23, ABI).
  • PocketFFT (pocketfft_hdronly.h) — a clean, dependency-free, mixed-radix + Bluestein C++ FFT (NumPy/SciPy's backend). Lesson: pragmatic mixed-radix + real FFT + Bluestein in a compact form. The closest readable model for our scope. Pitfall: heavy templating. Applied: Phase 5 (§17), Phase 6 (§18), Phase 7 (§19).
  • KISS FFT (kiss_fft.c, kiss_fftr.c) — minimal mixed-radix + real FFT. Lesson: the smallest correct mixed-radix core; great for the P5 baseline. Pitfall: not tuned (a baseline, not a perf model). Applied: Phase 5 (§17.2, baseline), Phase 7 (§19).
  • FFTPACK / FFTPACK5 (Fortran) — the historic mixed-radix reference (Swarztrauber). Read for codelet recurrences (radix-3/4/5 hand kernels). Pitfall: 1980s style; semantics oracle, not architecture. Applied: §8.7, Phase 5 (§17.2, codelets::{r3,r5,r7}).
  • Intel MKL-FFT / mkl_dfti — the DFTI descriptor API (plan-like). Lesson: a production plan/descriptor API surface and storage/strides conventions. Applied: §11.7–11.8 (planner API), ADR-06, Phase 10 (§22).
  • RustFFT (src/algorithm/) — a mature Rust FFT (mixed-radix, Bluestein, Rader, SIMD). Lesson: idiomatic Rust planner/codelet structure & SIMD dispatch in our language. Pitfall: don't copy; re-derive to learn. Applied: §3.2, Phase 6 (§18), Phase 11 (§23, SIMD dispatch).
  • FFTW wisdom file format — the text/binary wisdom encoding we aim to remain interoperable with (or document divergence from). Applied: §11.9 (wisdom record), Phase 10 (§22.2, wisdom), §29 (Compatibility).

Glossary (§40) · 36 terms · site-wide glossary

DFT
Discrete Fourier Transform: X[k]=Σ x[n]·W_N^{nk}. IDFT the inverse.
FFT
Fast Fourier Transform: any O(N log N) DFT algorithm.
Cooley–Tukey
the divide-and-conquer FFT (recursive even/odd or radix-r split).
Twiddle factor
W_N^k = e^{−2πik/N}, a power of the primitive N-th root of unity.
Butterfly
the atomic combine (a,b,w) → (a+w·b, a−w·b).
Radix-2 / radix-4
FFT splitting into 2 / 4 sub-DFTs per stage.
DIT (decimation-in-time)
split the input (bit-reversed in, natural out).
DIF (decimation-in-frequency)
split the output (natural in, bit-reversed out).
Bit-reversal permutation
reordering index n to its bit-reversed value; an involution and bijection.
Split-radix
radix-2/4 hybrid; lowest known flop count (~4N log₂N) for power-of-2.
Mixed-radix
Cooley–Tukey for composite N via factor decomposition.
Codelet
a small straight-line (often hand-written/SIMD) FFT kernel for a base size.
Bluestein / chirp-z
FFT of arbitrary N via a power-of-2 convolution.
Rader's algorithm
prime-N DFT via a length-(N−1) cyclic convolution + primitive root.
Primitive root
a generator of the multiplicative group (ℤ/pℤ)*.
RFFT / IRFFT
real-input FFT exploiting Hermitian symmetry / its inverse.
Hermitian symmetry
X[N−k]=conj(X[k]) for real input → N/2+1 independent outputs.
Halfcomplex layout
packed real array storing the N/2+1 complex outputs.
Normalization convention
placement of the 1/N (or 1/√N) scale factor.
Convolution theorem
conv(a,b)=IFFT(FFT(a)·FFT(b)).
Overlap-add / overlap-save
block methods for streaming long-signal convolution.
Parseval's theorem
energy preservation: Σ|x|² = (1/N)Σ|X|².
Planner
the component choosing/persisting the best plan (FFTW-style).
Plan / execute
the two-step API: build a Plan once, execute it many times.
Wisdom
persisted measured-plan choices keyed by (N, dir, layout, ISA, dtype).
Estimate / measure / patient
plan modes: cost-model / timed / exhaustive.
Plan tree
the recursive codelet decomposition of N.
Four-step / six-step FFT
cache/large-N formulation viewing the data as a 2-D array.
Row-column method
multi-dim FFT as batched 1-D FFTs along each axis.
Flop model 5N·log₂N
the standard radix-2 real-flop count (the roofline x-reference).
NTT
Number-Theoretic Transform: exact integer DFT over ℤ/pℤ (deferred).
ISA dispatch
runtime selection of the widest available instruction set.
u (unit roundoff) / ε
2⁻²⁴ (f32) / 2⁻⁵³ (f64).
FMA
fused multiply-add, single rounding.
YMM/ZMM
256-/512-bit vector registers.
Oracle
the naïve O(N²) DFT reference (the trusted truth).
