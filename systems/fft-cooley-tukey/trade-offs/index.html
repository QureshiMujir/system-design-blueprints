Decisions (§9) · 31 ADRs

ADR-01

Impl language

Chosen

Rust 2021, MSRV pinned

Rejected

C, Fortran, C++, Python

When the rejected choice is right

C wins when you need the literal FFTW/MKL ABI with no shim and a 1980s-stable toolchain on an exotic target with no Rust backend (e.g. some DSP/embedded compilers); Python+pyFFTW wins for a one-off analysis script where dev time ≫ run time

Why: safety seam around unsafe codelets; intrinsics; portfolio fit (§1.9)

ADR-02

Build/workspace

Chosen

Cargo workspace, 13 crates

Rejected

single crate

When the rejected choice is right

a single crate wins for a tiny KISS-FFT-class library (≤2k LOC, one author) where the crate-split ceremony and cross-crate pub(crate) friction cost more than the layering buys

Why: crate boundaries enforce layering (core ↛ codelets)

ADR-03

SIMD access

Chosen

core::arch intrinsics + scalar fallback

Rejected

autovectorize; std::simd (unstable); asm

When the rejected choice is right

autovectorization wins when the compiler provably hits peak (simple radix-2 stride-1 loops on a known LLVM version) and you'd rather not maintain per-ISA intrinsics; std::simd wins once stabilized and the target set is portable-SIMD-clean

Why: determinism & control of butterfly codegen; no nightly

ADR-04

ISA dispatch

Chosen

runtime is_x86_feature_detected! once, cached fn ptrs

Rejected

compile-time target-feature; per-call detect

When the rejected choice is right

compile-time target-feature wins when you ship one binary per known host (HPC cluster, -C target-cpu=native in-house builds) — no dispatch branch, the compiler inlines wider

Why: portable binary; no illegal-instruction

ADR-05

Complex repr

Chosen

#[repr(C)] struct{re,im} interleaved (AoS)

Rejected

split real/imag (SoA) arrays

When the rejected choice is right

SoA at the API wins for a GPU/SIMD-first engine (cuFFT, MKL planar layout) where coalesced re/im streams beat interleaved loads and no _Complex interop is required

Why: C-ABI compat (_Complex); FFTW interop; SoA reconsidered for SIMD internally (ADR-23)

ADR-06

API shape

Chosen

plan/execute two-step (FFTW model)

Rejected

one-shot fft(x) per call

When the rejected choice is right

one-shot wins for an interactive REPL / notebook (NumPy np.fft.fft) where the user transforms one array once and never wants a planning step in their face

Why: reuse plans; allocation-free execute; real-time (P2)

ADR-07

Twiddle strategy

Chosen

direct-trig default; recurrence opt-in

Rejected

recurrence-only; recompute per butterfly

When the rejected choice is right

recurrence-only wins on a memory-starved embedded DSP where the O(N) twiddle table won't fit and a √N-reseeded recurrence's bounded drift is acceptable; recompute-per-butterfly wins when N is huge and bandwidth-bound (on-the-fly trig beats streaming the table, §32)

Why: accuracy floor (I7) vs speed; cached tables

ADR-08

Codelet form

Chosen

hand-written straight-line + SIMD intrinsics

Rejected

code-gen (FFTW genfft); compiler loops

When the rejected choice is right

a code generator (FFTW genfft) wins once you support dozens of base sizes × several ISAs — hand-writing r2/r3/r4/r5/r7/r8/r11/r13 × AVX2/AVX-512/NEON is unmaintainable; that is exactly FFTW's regime

Why: readable, debuggable, deterministic; generator deferred

ADR-09

Plan policy

Chosen

cost-model ESTIMATE + timed MEASURE + wisdom

Rejected

always estimate; exhaustive search

When the rejected choice is right

always-estimate wins when planning latency must be deterministic and tiny (a real-time plugin that plans on the audio thread); exhaustive search wins for a build-time autotuner (ATLAS/MKL offline tuning) where plan time is free

Why: FFTW-style; fast common path, optimal hot path

ADR-10

Arbitrary N

Chosen

mixed-radix + Bluestein + Rader

Rejected

power-of-2 only; pad-to-pow2 only

When the rejected choice is right

power-of-2-only wins for a fixed-pipeline OFDM/radar system where N is a hardware constant (always 2048/4096) and every byte of code space matters; pad-to-pow2 wins when the application can choose its own N freely (zero-padding spectra)

Why: first-class any-N (P9); bounded prime cliff

ADR-11

Normalization

Chosen

configurable {None, 1/N, 1/√N}, explicit

Rejected

hardcoded 1/N on inverse

When the rejected choice is right

hardcoded 1/N-on-inverse wins for a closed application that only ever does forward→process→inverse and wants the simplest possible surface (one fewer enum to misuse)

Why: convention is a contract (I5, P7)

ADR-12

In-place support

Chosen

DIT/DIF in-place + out-of-place

Rejected

out-of-place only

When the rejected choice is right

out-of-place-only wins for a Stockham-autosort engine (cuFFT/GPU) where avoiding the bit-reversal permutation entirely (at the cost of a second buffer) is the faster, simpler design — memory is cheap, scattered writes are not

Why: memory (P8); but adds bit-reversal complexity

ADR-13

Real FFT

Chosen

dedicated RFFT/IRFFT (Hermitian)

Rejected

route reals through c2c

When the rejected choice is right

routing reals through c2c wins in a prototype or a code path used so rarely that the 2× cost is irrelevant and the extra RFFT packing code isn't worth maintaining/testing

Why: 2× speed / ½ memory (P8)

ADR-14

Threading

Chosen

own pool; partition batched/multi-dim transforms

Rejected

rayon; OpenMP; thread a single 1-D FFT

When the rejected choice is right

rayon/OpenMP wins when the host app already runs one (avoid two thread pools oversubscribing cores) — relink onto the ambient pool; threading a single 1-D FFT wins only for enormous N on many cores where a parallel six-step (Bailey) FFT pays off

Why: no dep; determinism; single 1-D FFT is sequential

ADR-15

Error handling

Chosen

Result<_, FftError> internal; null-plan/code at ABI

Rejected

panics across FFI

When the rejected choice is right

panicking (abort) wins in a no_std/panic=abort embedded build where there is no unwinder and an invalid size is a programmer bug that should halt, not return a code

Why: FFI safety (I12)

ADR-16

C ABI

Chosen

FFTW-compatible subset + native pfft_*

Rejected

bespoke ABI only

When the rejected choice is right

a bespoke ABI wins greenfield (no FFTW callers to satisfy) where mimicking FFTW's plan-flag/guru-interface baggage only constrains you — a leaner native ABI is cleaner

Why: drop-in for existing FFTW callers

ADR-17

Wisdom

Chosen

persisted measured plans, file-backed, keyed by (N,dir,layout,ISA,dtype)

Rejected

no persistence; recompute

When the rejected choice is right

no-persistence wins for a short-lived process (a CLI filter invoked once) where writing/reading a wisdom file costs more than the single MEASURE it would save, or in a read-only/sandboxed FS with nowhere to persist

Why: re-plan in µs (P5); FFTW parity

ADR-18

Numerics promise

Chosen

error bounds + deterministic mode; not bit-equal across plans

Rejected

bit-reproducible always

When the rejected choice is right

bit-reproducible-always wins for regulatory/scientific reproducibility (a published result that must replay bit-identically on any machine forever) — pin one plan, one order, forgo the planner's speedups

Why: honest, testable (P7)

ADR-19

Accumulation

Chosen

fixed per plan; complex mul = 4-real-mul form

Rejected

3-mul Karatsuba complex mul

When the rejected choice is right

the 3-mul form wins when multiplies are the hard bottleneck and adds are free — e.g. a fixed-point/integer transform, or hardware where a multiply costs ≫ an add and the slightly worse FP error is irrelevant

Why: 3-mul has worse FP error & pipelining (matches #349 ADR-16)

ADR-20

Testing oracle

Chosen

naïve O(N²) DFT + FFTW differential (non-dep)

Rejected

self-consistency only

When the rejected choice is right

self-consistency-only (round-trip + Parseval) wins when no independent oracle is affordable — but only acceptable for a non-critical tool; here correctness is sacred (P1) so it is rejected

Why: independent truth

ADR-21

ADR-22

ADR-23

Internal SIMD layout

Chosen

38. Alternative Architectures (Roads Not Taken)

Fundamentally different designs for the same "compute the DFT" mission — not parameter tweaks. Each: sketch, winning regime, real system, why rejected here.

ALT-1 — Naïve O(N²) DFT (dense matrix–vector).

x[0..N-1] ──► [ W matrix, N×N, W[k,n]=e^{-2πikn/N} ] ──► X[0..N-1]
              one GEMV: X = W·x        (no divide-and-conquer)

Wins when: N is tiny (≤ ~16–32) where O(N²) ≤ the FFT's constant-factor overhead, or as the oracle (trusted truth). Also when only a few output bins are needed (→ Goertzel, a one-bin special case). Real system: used internally by every FFT library as the small-N base case and the test oracle (our conformance::oracle, §25.2; ADR-20). Why rejected as the engine: O(N²) is catastrophic at scale (C2: 8.4×10⁴× slower at N=2²⁰) and less accurate (N·ε vs log₂N·ε, MM3) — it is our reference, not our product.

ALT-2 — Recursive radix-2 (function-call tree) vs the iterative bit-reversed form we chose.

 RECURSIVE (call tree)                 ITERATIVE (chosen, Phase 3)
   fft(N)                                 step A: bit_reverse_permute(data)
   ├── fft(N/2) on evens                  step B: log₂N stages, stride-doubling
   │     └── ... down to N=1                      each stage = N/2 butterflies
   └── fft(N/2) on odds                           sweeping the whole array
         └── ...                          ──────────────────────────────────
   merge ◄── twiddle-weighted             one flat array, no recursion,
   butterflies up the tree                no call overhead, O(1) extra memory

Wins when: clarity/teaching matters more than speed (the recursion is the Cooley–Tukey proof), or for a one-off where call overhead is irrelevant. Real system: CLRS ch.30's RECURSIVE-FFT (pedagogical, §5.1 book 3); we build it first in Phase 1 (§13) precisely to anchor correctness. Why rejected as the production form: per-call overhead + poor cache behavior + repeated trig; the iterative in-place form (Phase 3, §15) is ≥5× faster and allocation-free (I14) — so recursion is the teaching path, the iterative kernel is the shipping path.

ALT-3 — Prime-Factor Algorithm (PFA / Good–Thomas) instead of mixed-radix Cooley–Tukey for composite N.

N = N1·N2 with gcd(N1,N2)=1  ──► CRT index map ──► N1×N2 grid
   ──► N2 DFTs of length N1, then N1 DFTs of length N2  (NO twiddle multiply between them)

Wins when: N factors into coprime parts (e.g. 1008 = 16·9·7) — PFA eliminates the inter-stage twiddle multiply entirely (the CRT reindex absorbs it), saving those flops; classic on fixed coprime sizes. Real system: FFTW includes a PFA/Good–Thomas step; Winograd's WFTA builds on it; FFTPACK-era radix-3/5/7 kernels combine with it. Why rejected as the default: it only applies to coprime factors and needs the more intricate CRT index machinery; general mixed-radix Cooley–Tukey (Phase 5, §17) handles all composite N (including prime powers like 2^a) with one uniform twiddle-multiply step — PFA is a deferred optimization for coprime N, not the base mechanism.

ALT-4 — Cache-oblivious recursive (Stockham auto-sort), out-of-place, no explicit bit-reversal.

Stockham: each stage reads from buffer A in one order, writes buffer B in the
   "self-sorting" order ──► after log2(N) stages the data is naturally ordered.
   Ping-pong A↔B every stage; the bit-reversal permutation never appears.

Wins when: scattered writes are catastrophic but bandwidth is cheap — i.e. GPUs and vector machines, where avoiding the irregular bit-reversal permutation is worth a second buffer; also large out-of-cache N where the auto-sort's regular access beats a separate scattered permutation pass. Real system: NVIDIA cuFFT and most GPU FFTs use Stockham auto-sort out-of-place; Bailey's vector-computer FFTs (§5.2 paper 9, 11) too. Why rejected as the default: it mandates out-of-place (two buffers, 2× memory) and forgoes the in-place selling point (ADR-12, MM10); on a CPU with in-place support the explicit blocked bit-reversal (Phase 12, §24) is competitive while keeping O(1) extra memory. We keep Stockham in view for the deferred GPU path (§40) and large-N out-of-place plans.
