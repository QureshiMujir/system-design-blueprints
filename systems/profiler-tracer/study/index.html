30. Mental Models & First Principles

  1. MM1 — A profiler is a sampling statistician, not a debugger. Insight: every sampled profile carries Poisson measurement error; it predicts that a rare-but-expensive function can be statistically invisible at low Hz. Bug class without it: treating "absent from the profile" as "not costly." Applied in §4 (Hz choice) and §28.1 (methodology).
  2. MM2 — The signal handler runs inside another program's undefined-behavior boundary. AS-safety is the literal edge of defined behavior, not a style guideline. Predicts: any libc call outside signal-safety(7) is a latent deadlock. Bug class: silent hangs under signal delivery. Applied in §12 (P1) and §14 (I2).
  3. MM3 — Build-id is identity; path is address. Like a stable node id vs. a mutable network address. Predicts symbol mismatches across redeploys/containers when identity is path-keyed. Bug class: silently-wrong symbolication that looks plausible. Applied in §13 and §17.
  4. MM4 — A stack is a reconstructed proof of causality, not raw data. The CPU destroys the call chain on every ret; unwinding is inference from what survives (frame pointers, DWARF metadata), not observation. Predicts unwinding is fundamentally lossy when metadata is missing. Bug class: trusting a partial/garbage stack as ground truth instead of marking it [unknown]. Applied in §16 and §8.
  5. MM5 — A span is a distributed causal token, not a log line. Dapper/X-Trace's insight: causality must travel with the request, not be reconstructed after the fact from timestamps. Predicts cross-service causality is unrecoverable without explicit propagation. Bug class: broken or truncated traces at service boundaries. Applied in §19 and §8.
  6. MM6 — The exporter owns time; the producer owns none. Separating "produce" from "decide when to flush/batch/retry" is what keeps a hot path bounded. Predicts any producer that also does I/O will blow its own latency budget. Bug class: a hot-path p99 regression traced to an inline batching decision. Applied in §6 (P8) and §19.
  7. MM7 — Don't let the profiler measure itself with the wrong ruler. Overhead must be measured as the target's wall-clock delta with/without the agent attached — never via perf stat on the agent process, which measures the wrong subject entirely. Predicts a team can convince itself of a false low-overhead number. Bug class: publishing an unverified M1/M2 claim. Applied in §28 and §12.
  8. MM8 — Offline symbolization trades agent memory for query-time latency. Shipping (build-id, offset) defers cost to the analysis tier, valid because query volume is much less than ingest volume. Predicts a naive "resolve on the agent" design blows the RSS budget at fleet scale even though it looks fine on a single dev box. Bug class: agent OOM in production. Applied in §17 and §32.

5. Required Reading

Books

  • Brendan Gregg, Systems Performance: Enterprise and the Cloud, 2nd ed., Pearson, 2020. Ch. 6 (CPUs), 7 (Memory), 13 (Profiling). Applied in §16 (unwinding), §18 (flamegraphs), §28 (perf methodology).
  • Brendan Gregg and Sasha Goldshtein, BPF Performance Tools, Addison-Wesley, 2019. Ch. 5 (bcc), 7 (bpftrace), 12 (CPU profiling). Applied in §15 (eBPF sampling backend).
  • The DWARF Debugging Information Format Committee, DWARF Debugging Information Format, Version 5, 2017. Section 6.4 (Call Frame Information), section 7.23 (Address Class). Applied in §16.2 (DWARF CFI walker) and §8.3 (unwind state machine).
  • Free Standards Group, Linux Standard Base Core Specification, section 10.6 (.eh_frame). Applied in §16.2 — the .eh_frame vs .debug_frame distinction.
  • Levine, J., Linkers and Loaders, Morgan Kaufmann, 1999. Ch. 3 (object-file formats), Ch. 8 (symbol resolution). Applied in §13.2 (ELF module reader) and §17.3 (symtab fallback).
  • Cantrill, B., Solaris Internals co-author work on DTrace instrumentation — see also Cantrill, Shapiro, Leventhal below (paper). Applied in §15.4 (USDT probes) as the design origin of static-probe instrumentation.

Papers

  • Sigelman, B. et al., "Dapper, a Large-Scale Distributed Systems Tracing Infrastructure," Google Technical Report, 2010. Applied in §11.6 (Tracer/Span/Context), §8.4 (causal ordering).
  • Fonseca, R. et al., "X-Trace: A Pervasive Network Tracing Framework," NSDI 2007. Applied in §8.2 and §19.4 (traceparent propagation) — the causal-metadata-propagation model this SDK adopts.
  • Barham, P. et al., "Using Magpie for Request Extraction and Workload Modelling," OSDI 2004. Applied in §18.1 (per-request stack/span correlation via causal joins).
  • Kaldor, J. et al., "Canopy: An End-to-End Performance Tracing and Analysis System," SOSP 2017. Applied in §21 (fleet-wide continuous ingestion and query architecture).
  • Gregg, B., "The Flame Graph," Communications of the ACM 59(6), 2016. Applied in §18.5 (flamegraph renderer geometry).
  • Mace, J. et al., "Pivot Tracing: Dynamic Causal Monitoring for Distributed Systems," SOSP 2015. Applied in §8.4 (causal-join semantics) and §31 (comparative architecture).
  • Cantrill, B., Shapiro, M., Leventhal, A., "Dynamic Instrumentation of Production Systems," USENIX ATC 2004 (the DTrace paper). Applied in §15.4 (USDT static probes, uprobe attach).
  • Desnoyers, M., Dagenais, M., "The LTTng Tracer: A Low Impact Performance and Behavior Monitor for GNU/Linux," Linux Symposium 2006. Applied in §14.1 (lock-free ring design discipline for a tracing producer).

Reference Implementations

  • Linux perf, tools/perf/util/unwind-libdw.c, tools/perf/util/event.c. Applied in §15.2 (interpreting PERF_RECORD_SAMPLE) and §26.2 (the perf-comparison conformance bucket).
  • Polar Signals Parca, pkg/profiler/cpu/cpu.go, pkg/symbolizer/symbolizer.go, bpf/cpu.bpf.c. Applied in §15.1 (eBPF CPU-profile program) and §17 (offline symbolization design, ADR-09).

Glossary (§36) · 53 terms · site-wide glossary

AS-safety (async-signal-safety):
the property that a function may be safely called from within a signal handler; the hard floor on the §14 producer path (P1, I2).
SIGPROF:
the POSIX signal used to deliver profiling timer interrupts to a thread.
perf_event_open(2):
the Linux syscall opening a kernel performance-counter/sampling fd.
SPSC ring:
single-producer, single-consumer lock-free ring buffer; the §14 producer's data structure.
Build-id:
a GNU-convention 20-byte identifier (.note.gnu.build-id) uniquely identifying a compiled binary, stable across redeploys (I4, ADR-09).
ELF:
Executable and Linkable Format, the Linux binary/object-file container format.
DWARF:
the standard debugging information format; source of line tables and unwind info.
CFI (Call Frame Information):
DWARF's per-instruction description of how to recover the previous stack frame.
.eh_frame / .debug_frame:
the two DWARF CFI section flavors — runtime (exception unwinding) and debugger-only, respectively.
FDE / CIE:
Frame Description Entry / Common Information Entry — the two DWARF CFI record types evaluated during unwinding (§8.3).
ORC (Oops Rewind Capability):
the Linux kernel's internal unwind format, used kernel-side by bpf_get_stackid() (ADR-19).
Frame pointer:
the rbp(x86_64)/fp(aarch64) register convention enabling fast stack walking when the binary opts in (-fno-omit-frame-pointer).
Symbolization:
resolving an instruction pointer to (function, file, line).
Demangling:
reversing a compiler's name-mangling scheme (Itanium C++, Rust v0) to a human-readable symbol.
Inline-frame expansion:
reporting the full call chain for an address inside an inlined function, not just the outer function.
StackTable:
the parent-pointer-tree structure deduplicating shared stack prefixes (§11.5).
SymbolId / StackId:
interned 32-bit handles standing in for a resolved string or a full stack, respectively (P9).
pprof:
Google's protobuf-based profile interchange format (google/pprof/profile.proto).
Folded stack:
Brendan Gregg's func1;func2;func3 count text encoding, the flamegraph renderer's input format.
Flamegraph:
Gregg's SVG visualization where stack width encodes sample count.
Speedscope / Chrome Trace:
ancillary operator-facing profile visualization formats.
OTLP (OpenTelemetry Protocol):
the wire protocol for exporting traces/metrics/logs to a collector, over HTTP or gRPC.
Span:
a single named, timed operation with attributes, events, and a status, the unit of distributed tracing.
Trace:
the causally-linked tree of spans sharing one TraceId.
traceparent / tracestate:
the W3C Trace Context HTTP headers propagating trace identity across service boundaries (§8.2).
Causal ordering:
the guarantee that a child span's start time is never before its parent's (I9).
Head-based sampling:
deciding whether to sample a trace at its start, before its outcome is known (contrast: tail-based, §34 Alt-B).
Poisson sampling:
a sampling discipline where events are selected with independent, memoryless probability — the heap profiler's allocation-sampling model (§20).
Off-CPU profiling:
measuring time a thread spends blocked (I/O, futex, sleep) rather than executing.
Lock contention:
time threads spend waiting to acquire a lock rather than holding it.
Futex:
the Linux fast userspace mutex primitive; FUTEX_WAIT/FUTEX_WAKE are the syscall operations the §20 lock-contention tracer hooks.
LD_PRELOAD:
the dynamic-linker environment variable causing a shared library to be loaded before others, enabling function interposition (the §20 heap shim's mechanism).
jemalloc:
an allocator with built-in sampling-profiler support, an alternative heap- profiling path to the LD_PRELOAD shim (ADR-17).
LSan (LeakSanitizer):
an LLVM sanitizer whose leak-report text format the §20 leak detector's output is compatible with.
eBPF:
the Linux kernel's verified, sandboxed in-kernel bytecode execution facility.
BPF verifier:
the kernel component statically proving an eBPF program's safety before load.
CO-RE (Compile Once — Run Everywhere):
the eBPF technique for kernel-struct-layout portability across kernel versions via BPF_CORE_READ relocations.
Tracepoint:
a static, kernel-defined instrumentation point (e.g. sched_switch) eBPF programs can attach to.
Uprobe / USDT:
dynamic (uprobe) and static (USDT, via .note.stapsdt) user-space instrumentation points eBPF programs attach to for zero-source-change tracing.
ringbuf:
the BPF_MAP_TYPE_RINGBUF kernel-to-userspace event-delivery map type (kernel 5.8+).
Capability (CAP_PERFMON/CAP_BPF):
Linux fine-grained privileges gating perf_event_open/BPF-program loading (I13).
Continuous profiling:
always-on, low-overhead, fleet-wide sampling with durable retention and historical query (§21, contrast with perf's ad hoc single-host model, §31).
Ingestion server:
the fleet-wide component (prof-server) accepting uploaded profiles and exposing the query API.
Object store:
the pluggable durable storage backend (file:///s3:///gs://) behind the ingestion server (ADR-24).
Profile window:
a bounded (default 10 s) sampling interval the continuous-profiling agent uploads as one unit.
RTO (Recovery Time Objective):
the maximum acceptable time to restore service after a failure (§4, §23 FM7).
LRU (Least Recently Used):
the symbol-cache eviction policy, pinned against active build-ids (I14).
Arena allocator:
a bump-pointer allocation strategy freeing an entire region at once (P10's per-window and interner arenas).
Symbol table:
the in-memory mapping from SymbolId to resolved string (§11.4).
Mangled name:
a compiler-encoded symbol name requiring demangling to be human-readable.
Last Branch Record (LBR):
an Intel CPU feature recording the last N taken branches, usable for partial stack reconstruction without unwinding.
ptrace(2):
the Linux syscall for process inspection/control; notably not used by this runtime's primary sampling path (ADR-03 rejects a ptrace-dependent unwinder).
vDSO:
the kernel-mapped virtual dynamic shared object present in every process's address space, a special case in the §13 /proc/<pid>/maps classifier.
