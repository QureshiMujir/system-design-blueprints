⬜ Phase 1 — The mc-lang modeling language §13

Objectives
  • Lex + parse mc-lang (Promela/NuSMV-flavored guarded-command DSL) → Module AST; never panic on untrusted text.
  • StateEncoder: bijective map each VarDecl → contiguous bit range in packed State; encode/decode round-trip.
  • compile(&Module) -> TransitionSystem: produce initial: Vec<State>, next: Box<dyn Fn>, label: Box<dyn Fn>, props.
  • Full ParseError taxonomy (lex/parse/type/range/encode) with source spans; deterministic output.
Deliverable

mc-lang parses a .mc model + LTL/CTL spec lines into Module, StateEncoder gives a bijective encode/decode, and compile() returns a runnable TransitionSystem whose initial/next/label drive mc-explicit. Wired into mcheck check --parse-only (dump AST + encoding table).

Acceptance
  • Round-trip: ∀ valuation v in range, decode(encode(v)) == v; property test, 10⁴ random valuations, 0 failures.
  • total_bits = Σ per-var widths; a 3-process mutex model (≤24 vars) encodes in ≤64 bits.
  • compile() + reachable() on peterson.mc (Phase 2 stub) finds the documented state count exactly.
  • 100% of malformed fixtures (§13.5) return Err(ParseError) with correct kind + span; zero panics under cargo test + fuzz.

Pitfalls
  • Off-by-one in width: 0..5 is 6 values → width=ceil(log2(6))=3, not log2(5). Symptom: decode wraps; debug by asserting 2^width >= hi-lo+1.
  • Non-total next: forgetting stutter self-loop → deadlock states look like end-of-trace; reachable() undercounts. Add stutter only when no guard enabled; document it (affects liveness).
  • Boxed closure capture: next/label must own (Arc/move) the StateEncoder + AST, not borrow — lifetime errors or dangling after compile returns.
  • Pratt precedence drift: a & b | c must bind & tighter than |; mis-tabled precedence silently changes guards. Golden-parse AST fixtures.
  • Signed/unsigned range with lo≠0: store val-lo in bits, add lo on decode; forgetting the offset corrupts non-zero-based ranges.

⬜ Phase 4 — LTL-to-Buchi construction (tableau / GPVW) §16

Objectives
  • Implement ltl_to_buchi(f: &LtlFormula) -> BuchiAutomaton in mc-ltl via the GPVW tableau construction (Gerth/Peled/Vardi/Wolper 1995).
  • Input is NNF (assume to_nnf applied upstream — Phase 3); output is a degeneralized standard BuchiAutomaton consumable by mc-explicit::Product.
  • Pipeline: closure → tableau nodes (consistent/elementary subsets) → generalized Buchi (one accepting set per Until) → degeneralization → state simplification.
  • Correctness over compactness, but apply cheap optimizations: unsatisfiable-node pruning, equivalent-state merging, true-self-loop sink for True.
Deliverable

ltl_to_buchi produces a correct standard BuchiAutomaton for any NNF LtlFormula; mcheck internal command ltl2ba <formula> prints states/edges/accepting set (HOA-like dump) for inspection; integrates as the Buchi(!phi) factory for Phase 5 Product.

Acceptance
  • G p, F p, p U q, G F p, F G p, X p, ¬(p U q) each yield automata whose accepted ω-language matches the textbook reference (verified by Phase-5 product on hand-built systems).
  • Size bounds: |states| ≤ 2^O(|f|); for the 7 canonical formulas, state count ≤ Spot's within 1.5×.
  • Cross-check vs Spot (ltl2tgba) on a 1000-formula random corpus: language-equivalence (or simulation-containment both ways) holds for 100%.
  • Degeneralized automaton has exactly one accepting set; empty-language formulas (p ∧ ¬p) yield 0 states or no accepting cycle.

⬜ Phase 5 — Automata-theoretic LTL model checking (product + nested DFS) §17

Objectives
  • Implement Product = synchronous product of TransitionSystem × BuchiAutomaton(!phi); accepting iff Buchi component accepting.
  • Implement nested_dfs(&Product) -> Option<Trace>: outer DFS finds accepting states (post-order), inner DFS seeks path back to outer stack → accepting cycle (lasso). Some ⇒ phi violated.
  • On-the-fly: product states generated lazily via ts.next() × Buchi edges; no full graph stored. Memory = StateTable over product states only.
  • Close the loop: full LTL checking holds | violation(Trace); agree with check_invariant on safety (G p) properties.
Deliverable

mc-explicit exporting Product + nested_dfs; mcheck check --ltl "<formula>" model.mc returns HOLDS or prints a lasso Trace. Differential: G p via check_ltl agrees with check_invariant.

⬜ Phase 6 — Counterexample generation and trace replay §18

Objectives

  • Project product states (s, q) back onto model States (drop Buchi component) → human-readable run.

⬜ Phase 7 — CTL syntax and explicit CTL model checking §19

Objectives

⬜ Phase 10 — Bounded model checking (SAT unrolling) §22

Objectives
  • Implement mc-bmc (in mc-symbolic): bmc(ts, phi, k) -> Option<Trace> — find a length-≤k counterexample to phi or prove none exists up to a completeness threshold.
  • Encode I(s0) ∧ ⋀_{i<k} T(sᵢ,sᵢ₊₁) ∧ ⟦¬phi⟧ₖ(s0..sk) into CNF; solve with the project-277 SAT engine.
  • SAT → decode model into a length-k Trace (lasso if loop closure asserted); UNSAT to threshold → phi holds.

⬜ Phase 12 — Fairness and lite abstraction (CEGAR) §24

Objectives
  • Add weak fairness (justice: enabled-infinitely-often → taken-infinitely-often) + strong fairness (compassion: enabled-i.o. → taken-i.o.) constraints to the LTL/Buchi liveness pipeline → restrict accepting cycles to fair runs only.
