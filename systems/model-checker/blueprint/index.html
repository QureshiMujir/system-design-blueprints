279 — Model Checker from Scratch

Goal: Implement, from scratch in Rust, a finite-state model checker with three engines — explicit-state on-the-fly reachability + safety, the automata-theoretic LTL approach (LTL-to- Buchi + product + nested-DFS accepting-cycle detection for liveness), symbolic CTL checking over a from-scratch ROBDD package (image/pre-image fixpoints), and SAT-based bounded model checking (unrolling delegated to the project-277 SAT engine). It accepts a guarded-command modeling language, verifies LTL + CTL properties, and emits a replayable lasso counterexample on failure. It is a model checker, not a SAT solver (#277), an SMT solver (#278), or a theorem prover (#280).

1. Goal

Goal: A from-scratch finite-state model checker — mcheck — that verifies LTL + CTL temporal-logic properties of concurrent reactive systems written in a guarded-command DSL, via three complementary engines (explicit-state on-the-fly + nested-DFS, symbolic BDD fixpoint, SAT-based bounded), emitting a concrete lasso counterexample trace when a property fails.

1.1 Precise engineering definition

A verifier that consumes a model in the mc-lang guarded-command DSL plus a temporal spec, compiles it to a TransitionSystem (initial, next, label), and decides whether the spec holds — proving it or producing a counterexample Trace.

Dimension Definition
Input .mc model (Promela/NuSMV-flavored) + LTL/CTL property
Semantic model Kripke structure / TransitionSystem over a bit-packed State
Property logics LTL (X F G U R), CTL (EX EU EG AX AF AG AU)
Decision procedure language-emptiness (LTL), fixpoint labeling (CTL), bounded unrolling (BMC)
Output Trace = lasso (prefix + optional cycle) on FAIL; QED on PASS
Three engines explicit-state · symbolic-BDD · bounded-SAT (differential cross-check)

Core principle (LOCKED): phi holds iff the system has NO run satisfying !phi. The automata-theoretic path builds BuchiAutomaton for !phi, takes Product = TS x Buchi(!phi), and checks emptiness — a reachable accepting cycle = lasso CEX.

1.2 The three engines

Engine Crate Method Strength Cost driver
Explicit-state mc-explicit on-the-fly BFS/DFS + nested_dfs accepting-cycle exact CEX, no preprocessing, fine-grained POR StateTable RAM (state explosion)
Symbolic mc-symbolic + mc-bdd TransitionRelation as BDD, pre_image, EX/EU/EG fixpoints sets-not-states; 10^20 states tractable when BDD small BDD node count (variable order)
Bounded mc-bmc unroll T to depth k -> CNF -> project-277 SAT engine fast shallow-bug finding; no full reachability SAT formula size; completeness threshold for proofs

1.3 System boundaries

See §3 for the full architectural diagram. Three boundaries: Trust — at mc-lang (model text is untrusted; parser hardened; engines bounded by configurable state/node/time/memory limits). Concurrency — engines single-threaded; parallel/swarm search is PhaseDeferred. Persistence — none at runtime; StateTable + BDD tables in RAM; traces to stdout.

1.6 Recommended language

Rust, edition 2021, MSRV 1.78, std. Model checking is dominated by giant hash/BDD tables where memory layout and cache behavior decide if a model fits. Rust: manual layout + safety over untrusted state spaces; enum exhaustive matching over LTL/CTL AST. Rejected: C/C++ (unsafe), Go (GC pauses hurt inner loop), Python (orders of magnitude too slow).

1.7 Prerequisites

Automata theory (NFA/Buchi, GBA, language emptiness) · temporal logic (LTL+CTL syntax/semantics, NNF) · fixpoint theory (lfp/gfp, monotone operators over powerset lattice) · ROBDDs (canonicity, ite/apply) · the project-277 SAT engine (CNF interface for BMC) · graph search (BFS/DFS, SCC, nested-DFS). Key references: SPIN (Holzmann) · NuSMV (Cimatti et al) · CUDD (Somenzi) · Vardi & Wolper 1986 · Courcoubetis et al 1992 · Burch/Clarke/McMillan/Dill 1990 · Biere/Cimatti/Clarke/Zhu 1999 · Clarke/Grumberg/Peled, Model Checking.

2. Why Build This

2.1 Unique knowledge this project teaches

Model checking is the algorithmic face of formal verification: a decision procedure that either proves a temporal property holds over all runs of a finite system or returns a concrete counterexample. Building one from scratch internalizes a cluster of ideas that no other project in this track exposes:

Idea What it teaches Where it lands
Automata-theoretic verification Verification = language emptiness. phi holds iff system has no run satisfying !phi. Build Buchi for !phi, take product, check for a reachable accepting cycle. mc-ltl, mc-explicit
LTL-to-Buchi A temporal formula becomes a machine (tableau/GPVW): closure sets, elementary sets, generalized->degeneralized Buchi. Logic = automaton. ltl_to_buchi, Phase 4
Nested DFS Accepting-cycle detection in O(states+transitions) with two colors, on-the-fly (states minted by next() during search — no graph stored). nested_dfs, Phase 5
CTL fixpoints Branching-time operators ARE fixpoints over state sets: EX p = pre_image(p); EG p = gfp(p AND EX Z); E[p U q] = lfp(q OR (p AND EX Z)). Monotone operators + Knaster-Tarski. check_ctl, Phase 7/9
ROBDDs A canonical representation of Boolean functions: fixed variable order + reduction rules => unique form; ite is the universal apply; complemented edges + computed cache make it fast. mc-bdd, Phase 8
The symbolic breakthrough Represent state sets (not states) as BDDs; image/pre-image are BDD ops. Burch/Clarke/McMillan/Dill verified 10^20 states — intractable explicitly, trivial when the BDD is small. mc-symbolic, Phase 9
SAT-based BMC Unroll T to depth k, conjoin bounded !phi, hand the CNF to a SAT engine; a model decodes to a length-k Trace; UNSAT past the completeness threshold => proof. mc-bmc, Phase 10
State-explosion reductions ` states

The throughline: a property is a question about an infinite set of infinite runs, answered in finite time by reducing it to graph search (explicit), fixpoint iteration over symbolic sets (BDD), or a satisfiability query (BMC). Three engines, one semantic model (TransitionSystem), cross-validated against each other.

2.2 Why model checking matters

  • Turing-award core. Clarke, Emerson, Sifakis won the 2007 Turing Award; the BDD+symbolic line (Bryant, McMillan) and the automata-theoretic line (Vardi, Wolper) are foundational CS.
  • Real systems, real bugs. SPIN/Promela verified Bell Labs telephony protocols; NuSMV/nuXmv verifies hardware + cache-coherence + railway interlocking; CUDD is the BDD substrate under most of EDA.
  • Bug-finding / proof duality. One tool finds concrete shortest-path counterexamples (lasso, replayable via simulate) and proves their absence over the full finite state space.
  • Architecturally: the canonical study of fighting combinatorial blowup — on-the-fly generation, hash visited-sets, canonical compression (BDDs), and SAT delegation recur across every state-space tool.

2.4 Calibration value

Staff-level checkpoint tying discrete math (fixpoints, lattices), automata theory (Buchi, emptiness), data-structure engineering (BDDs, hash tables), and systems delegation (SAT backend) into one coherent artifact. Three independent engines over one TransitionSystem provide a built-in oracle; differential agreement is a strong correctness signal absent from most single-algorithm projects.

2.6 What Mastery Looks Like

A builder who has mastered this project can do all of the following without reference material:

  • Automata-theoretic reasoning (Phase 5 / §17): Given any LTL formula φ, immediately construct Buchi(!φ) by hand for simple cases (G p, F p, G F p), explain why a reachable accepting cycle is exactly a counterexample to φ, and trace through how nested_dfs finds that cycle in O(states+transitions) with two color bits.
  • Fixpoint computation (Phase 7 & 9 / §19, §21): Write out the EX/EU/EG fixpoint equations from memory, explain why EG uses a greatest fixpoint and EU uses a least fixpoint (monotone operator direction), and trace a 4-state Kripke structure by hand to verify a CTL formula using both explicit labeling and BDD pre-image.
  • ROBDD invariants (Phase 8 / §20): Construct a BDD for a 3-variable function step by step, apply the two reduction rules (no-redundant-node, no-structural-duplicate), encode complemented edges, and explain why the computed cache is sound only when cleared on GC.
  • Encoder bijection (Phase 1 / §13): Given a mc-lang model with three variables, lay out the StateEncoder bit ranges by hand, encode a specific valuation, and explain why stale tail bits break the StateTable dedup invariant (→ INV-VISIT, INV-ENC).
  • Cross-engine differential (Phase 13 / §25): Explain what it means for explicit, symbolic, and BMC engines to "agree", which verdicts BMC can and cannot contribute (bounded vs full), and how a disagreement localizes the bug to one of the three engines.
  • State-explosion mitigation (Phase 11 / §23): For a given concurrent model, choose between POR (ample sets), symmetry reduction, and BDD sifting, explain the conditions under which each is sound, and identify which reductions are forbidden when the property is LTL with X over a reordered action.
  • Threat boundary reasoning (§4 / Threat Model): Given an adversarial .mc model, enumerate the DoS surfaces (state explosion, Buchi blowup, BDD blowup, parser crash), identify which budget knob caps each, and explain why Unknown(BudgetExceeded) is the only safe response rather than a silent Holds.

4. System Constraints

All targets: x86-64, single core, release build, MSRV 1.78, std-only. LTL model checking is PSPACE-complete → worst-case unbounded. Every engine honors explicit budgets or reports Unknown (never crash, never silent wrong answer).

4.1 Resource Budget

Dimension Target / cap Mechanism
Bytes/visited state 8–32 B amortized bit-packed State.bits; StateId slot; StateTable load factor ≤ 0.75
StateTable capacity default 64 Mi states (~1–2 GiB) --max-states; halt → Unknown
Bytes/BDD node 16 B BddNode{var:u32, lo:BddRef, hi:BddRef} packed; complement bit in MSB
BDD unique table default 16 Mi nodes (~256 MiB) --max-bdd-nodes; GC (mark-sweep) at 90%
BDD computed cache 2^20 entries (~16 MiB), lossy direct-mapped (op,f,g,h)→BddRef; miss costs recompute
Explicit throughput > 1M states/sec next()+hash+insert inner loop; LLC-resident StateTable probe
BDD throughput > 1M ite/sec (cache-warm) unique-table + computed-cache lookup
BMC depth default cap 200; --bmc-k CNF ≈ k·|T| clauses → project-277 SAT
Parse limits #vars ≤ 4096; #processes ≤ 64 rejected at parse_model/compile

Budget checks polled every 2^16 state expansions / BDD ops (cooperative, not signal-based).

4.2 Soundness & Completeness

Engine CEX guarantee "Holds" guarantee
Explicit (reach/invariant/nested-DFS) always a real run (concrete Trace) sound+complete within explored set; Unknown if budget exceeded
Symbolic (CTL fixpoint) sat-set witness decodes to real path sound+complete when fixpoint converges in budget
BMC (depth k) real length-≤k run decoded from SAT model sound only up to k; Unknown unless k ≥ completeness threshold

No panic on untrusted input — parse_model returns Result<_, ParseError> for any byte stream. Single-threaded engines; no global mutable state; same model+seed ⇒ byte-identical verdict + CEX.

6. Design Principles

Fourteen non-negotiable principles. Each: rule, rationale (X → Y because Z), tradeoff + operational implication, failure-on-violation. Referenced by later phases (## 12–## 25) and the Invariants (## 7).

6.1 Soundness of counterexamples is absolute

  • Rule: every reported Trace MUST be a real run of the compiled TransitionSystem — prefix ⊆ reachable states via next(), cycle (if any) a true lasso back-edge. Replayable via mcheck simulate with byte-identical state sequence.
  • Violation: nested-DFS reconstructs a lasso from the inner-DFS color stack but drops one back-edge → simulate replay diverges → a "violated" verdict no engineer can reproduce.

6.2 Property = emptiness of the !phi product

  • Rule: LTL checking is ALWAYS: build ltl_to_buchi(!phi), form Product = TS × Buchi(!phi), test language emptiness via nested_dfs. A reachable accepting cycle ⇔ phi violated. No ad-hoc per-operator checkers.
  • Violation: a hand-rolled G p invariant path that skips the Buchi product mishandles G(p U q) → misses a liveness violation, reports phi holds.

6.3 On-the-fly by default

  • Rule: explicit search (reachable, check_invariant, nested_dfs) generates successors lazily via next(); the only materialized structure is the StateTable visited set. Never build the full state graph or KripkeStructure for search.
  • Violation: materializing all Transitions up front → OOM on a 12-process model that on-the-fly DFS would have refuted in the first 10^4 states.

6.4 BDD canonicity is sacred

  • Rule: with a FIXED var_order + the two reduction rules (no node with lo==hi; no two structurally-equal nodes), every Boolean function has a UNIQUE BddRef. BddManager enforces this at every node creation through the unique table; complemented edges normalized (regular-then-complement convention on the high child).
  • Violation: a complemented-edge normalization bug creates two refs for the same function → and(a,b) cache returns a stale result → check_ctl computes a wrong sat-set, reports phi holds on a structure where it fails.

6.5 Bounded resources → "unknown", never crash

  • Rule: every engine takes explicit budgets (max states, max BDD nodes, wall-clock, RAM). On exhaustion → return Verdict::Unknown { reason, budget_hit }. NEVER OOM-abort, panic, or silently truncate.
  • Violation: unbounded StateTable insert → process killed by OOM killer → CI flakes, no diagnostic, user can't distinguish "too big" from "tool bug".

6.6 Three engines, one semantics

  • Rule: mc-explicit, mc-symbolic, mc-bmc consume the SAME TransitionSystem (initial, next, label, props). On any model+property in their common fragment, verdicts MUST agree; disagreement is a P0 bug caught by differential checking (Phase 13).
  • Violation: StateEncoder assigns var bit-ranges one way for symbolic, another for explicit → same model yields different reachable counts → silent unsoundness until differential test fires.

6.7 BMC delegates to the project-277 SAT engine

  • Rule: bmc unrolls I(s0) ∧ ⋀ T(s_i,s_{i+1}) ∧ boundedNeg(phi) to CNF and hands it to the project-277 SAT engine. This project re-derives NEITHER CDCL, clause learning, NOR restarts.
  • Violation: a homegrown DPLL in mc-bmc → 100× slower at k=40, plus a second CDCL bug surface, defeating the point of delegation.

6.8 Reductions must preserve the checked property

  • Rule: partial-order reduction (ample sets) and symmetry reduction may prune ONLY interleavings independent + invisible to phi; BDD sifting may change var_order but never the function. A reduction that can change a verdict is forbidden, gated, and differential-checked against the unreduced run.
  • Violation: ample set ignores the C3 cycle proviso → an accepting cycle's enabling transition is permanently deferred → liveness violation pruned away, phi falsely "holds".

6.9 Determinism on a fixed search order

  • Rule: given the same model, spec, and config, every engine produces the SAME verdict AND the SAME Trace (same successor enumeration order, same tie-breaks, same StateTable iteration). No wall-clock, no address-dependent ordering, no nondeterministic hashing of states.
  • Violation: next() returns successors in HashMap iteration order → two runs report different lassos for the same bug → users distrust the tool and bisection on CEX length breaks.

6.10 Variable order is a first-class tuning knob

  • Rule: the BDD var_order is an explicit, inspectable, overridable parameter (model heuristic → static order → dynamic sifting). Treated as configuration, surfaced in bench, never buried as an implementation accident.
  • Violation: ordering all current vars before all next vars → TransitionRelation BDD explodes → symbolic engine OOMs on a model the explicit engine refutes trivially.

6.11 Parse never panics

  • Rule: parse_model and the LTL/CTL parsers return Result<_, ParseError> for ALL malformed input — never panic, never unwrap. The trust boundary is model text; every byte sequence maps to either a Module/formula or a located ParseError.
  • Violation: an unguarded slice[i] in the lexer on a truncated token → panic on a fuzzed model → no error location, CI crash instead of a clean ParseError.

6.12 Completeness is explicit

  • Rule: every "holds" verdict states its completeness: explicit/symbolic "holds" = FULL (exhaustive over reachable states); BMC "holds" = BOUNDED unless k ≥ the completeness threshold, then FULL. The Verdict type encodes Holds { full: bool, bound: Option<usize> }; never report bounded absence-of-CEX as unconditional truth.
  • Violation: bmc returns Holds{full:true} at k=15 without a completeness argument → user ships a system whose deadlock first appears at depth 16.

6.13 The TransitionSystem is the only semantic contract

  • Rule: engines depend on TransitionSystem (the mc-types interface), never on mc-lang AST internals. compile() is the single boundary that turns a Module into semantics; new front-ends or hand-built systems plug in below it.
  • Violation: nested_dfs reaches into Module.trans for a shortcut → a compile() change breaks search in a way no engine test covers, and hand-built test systems no longer exercise the real path.

6.14 State is canonical and hashed once

  • Rule: a State is its packed bits valuation; two states are equal iff bit-identical. StateTable interns each visited State to one StateId via one hash; no two StateIds denote the same valuation, none denote unreachable padding.
  • Violation: an uninitialized don't-care bit varies between two encodings of the same valuation → StateTable stores it twice → search revisits, may not terminate, and reachable-count differs from the symbolic engine (breaks 6.6).

8. Domain Model — Kripke Structures, LTL/CTL, and Buchi Automata

The shared vocabulary all three engines consume. Every engine reads one semantic object: a TransitionSystem (mc-types). mc-lang produces it; mc-explicit walks it on-the-fly; mc-symbolic encodes its relation as a BDD; mc-bmc unrolls it into CNF.

8.1 mc-lang grammar (EBNF)

model        = { decl } ;
decl         = module | typedef ;
module       = "module" ident "{" var_block init_block trans_block spec_block "}" ;

var_block    = "var" "{" { var_decl } "}" ;
var_decl     = ident ":" var_type ";" ;
var_type     = "bool"
             | "range" "(" int ".." int ")"     (* finite integer range, both bounds incl *)
             | "enum" "{" ident { "," ident } "}" ;

init_block   = "init" "{" expr "}" ;            (* predicate over vars; true => valid initial state *)

trans_block  = "trans" "{" { guarded } "}" ;
guarded      = "[" [ ident ] "]" expr "->" update { "," update } ";" ;  (* [label] guard -> updates *)
update       = ident "'" "=" expr ;             (* primed = next-state assignment *)

spec_block   = "spec" "{" { spec } "}" ;
spec         = "ltl" string ":" ltl_formula ";"
             | "ctl" string ":" ctl_formula ";" ;

ltl_formula  = ltl_or ;
ltl_or       = ltl_and { "||" ltl_and } ;
ltl_and      = ltl_until { "&&" ltl_until } ;
ltl_until    = ltl_unary { ("U"|"R") ltl_unary } ;
ltl_unary    = ("X"|"F"|"G"|"!") ltl_unary | ltl_atom ;
ltl_atom     = "true" | "false" | atom | "(" ltl_formula ")" ;

ctl_formula  = ctl_or ;
ctl_or       = ctl_and { "||" ctl_and } ;
ctl_and      = ctl_unary { "&&" ctl_unary } ;
ctl_unary    = path_quant temporal | "!" ctl_unary | ctl_atom ;
path_quant   = "A" | "E" ;
temporal     = "X" ctl_unary | "F" ctl_unary | "G" ctl_unary
             | "(" ctl_formula "U" ctl_formula ")" ;
ctl_atom     = "true" | "false" | atom | "(" ctl_formula ")" ;

atom         = ident relop expr | ident ;       (* `pc=crit`, `x<3`, or a bool var *)
relop        = "=" | "!=" | "<" | "<=" | ">" | ">=" ;
expr         = (* finite-domain arithmetic/boolean over declared vars + literals *) ;
ident        = letter { letter | digit | "_" } ;

Notes: [label] names a transition (for fairness + POR visibility); a guarded with no enabled successor at a state contributes nothing — a state with no enabled guard is a deadlock (see 8.9). Atomic propositions are exactly the atom predicates appearing in init/specs, interned to AtomicProp(u32).

8.2 Kripke structure / TransitionSystem semantics

A Kripke structure M = (S, S0, R, AP, L):

Element Math mc-types realization
S finite state set reachable closure of State valuations
S0 ⊆ S initial states TransitionSystem.initial: Vec<State>
R ⊆ S×S transition relation, total next: Fn(&State)->Vec<State>
AP atomic props props: Vec<AtomicProp>
L: S->2^AP labeling label: Fn(&State)->Label

Totality requirement: every state has ≥1 successor (else liveness semantics break). mc-lang enforces by adding an implicit [stutter] true -> (no-op) self-loop only to genuine deadlock states unless --deadlock-as-error (then deadlock is reported as a safety violation; see 8.9). A run/path π = s0 s1 s2 … with s0∈S0, (si,si+1)∈R; the trace is L(s0)L(s1)… ∈ (2^AP)^ω. Trace { prefix, cycle } is a lasso when cycle = Some(_) (ultimately periodic word, the only kind a finite M can witness for liveness).

8.3 StateEncoder — variables to packed State

bool        -> 1 bit
range(a..b) -> ceil(log2(b-a+1)) bits, stored as (value - a)
enum{k...}  -> ceil(log2(|k|)) bits, ordinal index
  • Layout: fields concatenated in declaration order into State.bits: BitVec; StateEncoder holds var -> (offset, width).
  • encode(valuation)->State / decode(&State)->valuation; out-of-range value during next() is an encoder bug (debug-asserted), out-of-range literal in source is a ParseError::RangeError.
  • Same bit layout is the BDD variable set (mc-symbolic) and the BMC variable vector (mc-bmc): one canonical encoding shared across engines so traces are cross-decodable. Current/next vars in symbolic mode: bit i -> BDD var 2i (current), 2i+1 (next).
  • StateId(u64) = hash of State.bits assigned by StateTable on first insertion; identity is by valuation, not by id.

8.4 LTL syntax + semantics (over ω-words)

π,i ⊨ φ means suffix π[i..] satisfies φ. φ holds on M iff every run from S0 satisfies φ.

Op Syntax Semantics at (π,i) Dual / NNF identity
atom p p p ∈ L(s_i) —
not !φ not π,i⊨φ pushed to atoms in NNF
and/or φ&&ψ,φ||ψ both / either De Morgan
next X φ π,i+1 ⊨ φ !Xφ ≡ X!φ (X self-dual)
finally F φ ∃ j≥i: π,j⊨φ Fφ ≡ true U φ
globally G φ ∀ j≥i: π,j⊨φ Gφ ≡ false R φ ≡ !F!φ
until φ U ψ ∃ j≥i: π,j⊨ψ ∧ ∀i≤k<j: π,k⊨φ !(φUψ) ≡ !φ R !ψ
release φ R ψ ∀ j≥i: π,j⊨ψ ∨ ∃i≤k<j: π,k⊨φ !(φRψ) ≡ !φ U !ψ

to_nnf(&LtlFormula): push all Not to atoms using the dual column; expand nothing else (X/U/R kept primitive; F/G are sugar lowered to U/R during NNF). Result: negations only on Ap. Invariant: to_nnf(to_nnf(f)) == to_nnf(f) (idempotent).

8.5 CTL syntax + semantics

State formulas over the branching tree. M,s ⊨ φ.

Op Meaning at s Basis reduction
EX φ ∃ successor ⊨ φ primitive = pre_image(φ)
EG φ ∃ path, all states ⊨ φ νZ. φ ∧ EX Z (greatest fixpoint)
E[φ U ψ] ∃ path, φ until ψ μZ. ψ ∨ (φ ∧ EX Z) (least fixpoint)
EF φ ∃ path reaching φ E[true U φ]
AX φ all successors ⊨ φ !EX !φ
AF φ all paths reach φ !EG !φ
AG φ all paths, always φ !EF !φ
A[φ U ψ] all paths φ until ψ !(E[!ψ U (!φ∧!ψ)] ∨ EG !ψ)

Adequate basis: {EX, EU, EG} (+ boolean). check_ctl evaluates bottom-up, returning the BDD sat-set for each subformula; result for M = sat(φ) ⊇ S0. LTL≠CTL: neither subsumes the other (e.g. AG EF p not LTL; F G p not CTL) — both engines retained deliberately.

8.6 LTL-to-Buchi pipeline

LtlFormula φ  ──to_nnf──>  φ_nnf   (negations at atoms only)
   │
   │ build CLOSURE cl(φ): all subformulas + their negations
   ▼
ELEMENTARY SETS: maximal consistent subsets of cl(φ)
   (sat boolean consistency + local temporal rules:
      Xφ membership pins successor; φUψ expansion ψ ∨ (φ ∧ X(φUψ)))
   │
   ▼
GENERALIZED BUCHI (GBA): states = elementary sets; edge s->t if t's X-requirements
   match s's Next-obligations; ONE accepting set F_i per Until subformula
   (fairness: forbid a U-promise deferred forever)
   │  degeneralize (counter 0..|F|): track which acceptance set is "owed"
   ▼
BuchiAutomaton { states: Vec<BAState>, init, edges:(usize,Label,usize), accepting: BitSet }

ltl_to_buchi(&LtlFormula) implements GPVW (tableau). Edge guards are Labels (conjunctions of literals over AP). Size: worst-case 2^O(|φ|) states; in practice optimized by on-the-fly construction + simplification (remove unreachable / equivalent / non-accepting-trap states). We always build the Buchi for !φ so an accepting run = a counterexample to φ.

8.7 Worked examples

Safety — mutual exclusion (spec { ltl "mutex": G !(pc1=crit && pc2=crit); }): 2-process Petersen-style model; pc1,pc2 ∈ {idle,wait,crit}, turn ∈ {1,2}. Encoding: 2+2+1 = 5 bits, ≤ 32 states. check_invariant runs BFS; correct model returns Ok(()); a buggy guard lets both reach crit and BFS returns the shortest-path Trace{prefix:[…,(crit,crit,_)], cycle:None}. Predecessor map ensures minimal length.

Liveness — response (spec { ltl "resp": G(req -> F ack); }): check !φ = F(req && G !ack). ltl_to_buchi(!φ) produces a 2–3 state GBA with accepting state q1 (self-loop guard !ack). nested_dfs on the product finds an accepting cycle where ack never holds → lasso Trace{prefix:[…],cycle:Some([…])}. No accepting cycle → None → φ holds.

Symbolic safety — BDD fixpoint: same G !(crit1&&crit2) via mc-symbolic. Reach = μZ. Init ∨ image(TR,Z) iterated to convergence; Bad = BDD(crit1∧crit2); Reach∧Bad==BddRef(0) → holds; else extract a minterm and walk pre_image back to Init for a CEX. The entire reachable set is one BDD — 10^20-state models tractable when node count is small. Phase 13 differential: symbolic Reach∧Bad==0 must agree with explicit check_invariant.

Fixed order wins when ordering is known to be near-optimal from domain knowledge (e.g. hardware designs where signal groupings are published), avoiding sifting overhead.

11.1 Cross-cutting conventions

Concern Decision Rationale
Ownership Engines borrow &TransitionSystem; own their StateTable, BDD BddManager, Trace. Single semantic model, many consumers.
Mutation State data immutable post-encode; search structures (StateTable, BddManager) &mut. Visited-set + node-table grow; model frozen.

Errors Parse/encode return Result<_, E>; engines return Option<Trace> / Result<(), Trace> (Trace = the violation witness). A counterexample is not an error — it's the answer.

/// Hash/index handle for a visited state. Dense u64 assigned by StateTable on
/// first insertion; stable for the lifetime of one search. NOT serialized.
#[derive(Clone, Copy, PartialEq, Eq, Hash)]
pub struct StateId(pub u64);

/// Packed valuation of ALL model variables. The dominant memory unit — one per
/// visited state in the StateTable. bits laid out per StateEncoder var->range.
/// Hash + Eq are over the raw bit pattern (canonical: encoder zero-pads unused).
#[derive(Clone, PartialEq, Eq, Hash)]
pub struct State { pub bits: BitVec }   // BitVec = compact in-crate bit buffer

/// Interned proposition id (e.g. "x>3", "pc==crit"). u32 -> 4B keys, dense.
#[derive(Clone, Copy, PartialEq, Eq, Hash)]
pub struct AtomicProp(pub u32);

/// Set of AtomicProps true in a given state. BitSet indexed by AtomicProp.0.
/// Produced by TransitionSystem::label; consumed as Buchi-edge guards.
#[derive(Clone, PartialEq, Eq)]
pub struct Label(pub BitSet);

/// An explicit edge (used by KripkeStructure / explicit CTL labeling, NOT by
/// on-the-fly search which never materializes edges).
#[derive(Clone, Copy)]
pub struct Transition { pub from: StateId, pub to: StateId }

State — sizing target: ≤ ceil(sum(var_bits)/8) bytes + length word; e.g. 64-bit valuation = 8B + overhead. Hash must be order-stable across runs for differential checking (## 25). No interior mutability.

Label — width = props.len(); cheap Clone (one BitSet word per 64 props). Equality used in Buchi guard matching.

/// The semantic model every engine consumes. Built once by mc-lang::compile.
/// Closures are Fn (pure, reentrant) -> usable from a single-threaded DFS
/// without &mut; capture the StateEncoder by Arc/Rc. No Send/Sync required.
pub struct TransitionSystem {
    pub initial: Vec<State>,                       // 1+ initial states
    pub next:  Box<dyn Fn(&State) -> Vec<State>>,  // successor (next-state) fn
    pub label: Box<dyn Fn(&State) -> Label>,       // proposition labeling
    pub props: Vec<AtomicProp>,                    // declared proposition vocab
}
  • Ownership/concurrency: owned by caller; engines borrow &TransitionSystem. Fn (not FnMut) → reentrant; dyn Fn not Send → single-threaded only.
  • Cost contract: next is hot (called once per visited state); O(enabled transitions); no allocation beyond the result Vec. TransitionSystem immutable after construction.
/// Explicit finite graph form: used by explicit CTL fixpoint labeling (## 19)
/// where the reachable set is materialized. Built by reachable() snapshotting.
pub struct KripkeStructure {
    pub states: Vec<State>,            // index = implicit StateId
    pub trans:  Vec<Transition>,       // explicit successor edges
    pub labels: Vec<Label>,            // labels[i] = label of states[i]
}

/// Open-addressing hash SET of visited State -> StateId. THE dominant memory
/// cost of explicit search. Linear probing, power-of-two capacity, Robin-Hood
/// optional; load factor <= 0.75 then grow x2 + rehash. No deletes (monotone).
pub struct StateTable { /* keys: Vec<Option<State>>, ids assigned on insert */ }

impl StateTable {
    pub fn new() -> Self;
    /// Returns (id, is_new). is_new=false => already visited (cycle/merge point).
    pub fn intern(&mut self, s: &State) -> (StateId, bool);
    pub fn contains(&self, s: &State) -> bool;
    pub fn len(&self) -> usize;        // # distinct visited states
}

StateTable — memory budget: cap * (sizeof(State)+8) ; target ≥ 2M states/GB at 8B valuations. &mut self for intern; not shared across threads. Monotone-growing, never shrinks during a search.

/// Counterexample. Pure prefix (safety) => cycle=None. Lasso (liveness) =>
/// cycle=Some: states repeat prefix.last() .. and loop. Replayed by `simulate`.
pub struct Trace {
    pub prefix: Vec<State>,        // path from an initial state
    pub cycle:  Option<Vec<State>> // Some => accepting cycle (omega = prefix.(cycle)^w)
}
  • cycle=None → finite safety witness; cycle=Some(c) → lasso prefix·c^ω (accepted by TS×Buchi(!phi)). Every adjacent step is a real next edge (checked by simulate, §18/INV-TRACE).

/// Complemented edge into the node table. High bit = complement flag; index in
/// low bits. Halves the table (f and !f share a node). NOT a Box -> just a u32.

/// A reduced node: top variable + lo(else)/hi(then) children. Interned in the
/// unique table -> structural sharing; never two equal nodes (canonicity).
#[derive(Clone, Copy, PartialEq, Eq, Hash)]
pub struct BddNode { pub var: u32, pub lo: BddRef, pub hi: BddRef }

/// Owns ALL BDD memory: unique table (de-dup), computed cache (memoize ite),
/// variable order. Single owner per symbolic check; &mut for every op (it may
/// allocate nodes / grow the cache). Not Send/Sync.
pub struct BddManager { /* unique: HashMap<BddNode,BddRef>, cache, var_order: Vec<u32> */ }

impl BddManager {
    pub fn var(&mut self, i: u32) -> BddRef;                       // projection x_i
    pub fn ite(&mut self, f: BddRef, g: BddRef, h: BddRef) -> BddRef; // universal apply
    pub fn and(&mut self, a: BddRef, b: BddRef) -> BddRef;         // = ite(a,b,0)
    pub fn or (&mut self, a: BddRef, b: BddRef) -> BddRef;         // = ite(a,1,b)
    pub fn not(&self,     a: BddRef) -> BddRef;                    // flip complement bit (O(1))
    pub fn restrict(&mut self, f: BddRef, var: u32, val: bool) -> BddRef;
    pub fn exists(&mut self, vars: &BddRef, f: BddRef) -> BddRef;  // existential quant (image)
}

16. Phase 4 — LTL-to-Buchi construction (tableau / GPVW)

16.1 Objectives

  • Implement ltl_to_buchi(f: &LtlFormula) -> BuchiAutomaton in mc-ltl via the GPVW tableau construction (Gerth/Peled/Vardi/Wolper 1995).
  • Input is NNF (assume to_nnf applied upstream — Phase 3); output is a degeneralized standard BuchiAutomaton consumable by mc-explicit::Product.
  • Pipeline: closure → tableau nodes (consistent/elementary subsets) → generalized Buchi (one accepting set per Until) → degeneralization → state simplification.
  • Correctness over compactness, but apply cheap optimizations: unsatisfiable-node pruning, equivalent-state merging, true-self-loop sink for True.

16.2 Detailed Implementation Steps

Governing decisions: ADR-08 (GPVW tableau over LTL2BA). References: P9 (Gerth/Peled/Vardi/Wolper GPVW tableau — the primary algorithm), P10 (Gastin-Oddoux LTL2BA — optimization reference after GPVW baseline). Degeneralization follows B2 Ch5 counter construction; state simplification follows P10 Section 4.

Module / file Work
mc-ltl/src/closure.rs closure(f) -> Vec<LtlFormula>: all subformulas + their NNF negations; intern to SubId(u32) for bitset membership
mc-ltl/src/tableau.rs GPVW node: Node { incoming: BitSet<NodeId>, now: BitSet<SubId>, next: BitSet<SubId>, old: BitSet<SubId> }; expand() worklist
mc-ltl/src/gba.rs GeneralizedBuchi { states, edges, accept_sets: Vec<BitSet<NodeId>> } — one set per Until subformula

  • Tableau expansion rules: And → add both conjuncts to now; Or → split node; Until(a,b) (a U b) → b OR (a ∧ X(a U b)), record obligation; Release(a,b) → b ∧ (a ∨ X(a R b)); Next f → push f to next; literal/Ap → add to now, check now consistency (no p ∧ ¬p).
  • Edge guard = conjunction of literals (Ap/Not(Ap)) held in now, encoded as Label (positive bits) + a negative-literal mask; True literal-set ⇒ universal guard.
  • Generalized acceptance: for each Until(a,b) in closure, accept-set = nodes where b ∈ now OR (a U b) ∉ now (eventuality discharged).
  • Degeneralization: states = (node, layer); m = accept_sets.len(); layer i → i+1 mod m when node ∈ accept_sets[i]; final BuchiAutomaton.accepting = states with layer == 0 ∩ accept_sets[0] (single Buchi set). If m==0, all states accepting.

17. Phase 5 — Automata-theoretic LTL model checking (product + nested DFS)

17.1 Objectives

  • Implement Product = synchronous product of TransitionSystem × BuchiAutomaton(!phi); accepting iff Buchi component accepting.
  • Implement nested_dfs(&Product) -> Option<Trace>: outer DFS finds accepting states (post-order), inner DFS seeks path back to outer stack → accepting cycle (lasso). Some ⇒ phi violated.
  • On-the-fly: product states generated lazily via ts.next() × Buchi edges; no full graph stored. Memory = StateTable over product states only.
  • Close the loop: full LTL checking holds | violation(Trace); agree with check_invariant on safety (G p) properties.

17.2 Detailed Implementation Steps

Governing decisions: ADR-07 (automata-theoretic LTL), ADR-09 (nested_dfs emptiness). References: P1 (Vardi-Wolper: LTL = language emptiness — the theoretical spine of this entire phase), P2 (Courcoubetis/Vardi/Wolper/Yannakakis: exact nested_dfs algorithm, 2-color scheme, post-order discipline). INV-NDFS and INV-TRACE are the correctness invariants for this phase.

  • mc-explicit/src/product.rs: pub struct Product { ts: &TransitionSystem, ba: &BuchiAutomaton, label_cache }. Product state = (State, ba_state: usize); id = pack StateId (64-bit) + Buchi index → ProdId(u128) or two-table scheme.
  • Product successors: succ((s,q)) = for each s' ∈ ts.next(s), for each Buchi edge (q, guard, q') with guard ⊆ ts.label(s) (edge guard satisfied by label of source s — Vardi/Wolper convention) → emit (s', q'). Initial = ts.initial × ba.init.
  • accepting((s,q)) = ba.accepting.contains(q). Single Buchi accepting set (degeneralized in Phase 4) ⇒ standard nested DFS.
  • mc-explicit/src/nested_dfs.rs: nested_dfs(prod). Colors via two StateTable-backed bitsets: outer_visited, inner_visited. Outer DFS (iterative, explicit stack); on post-order pop of accepting s, launch inner DFS from s seeking any node on the current outer stack (on_outer_stack membership set). Hit ⇒ accepting cycle.
  • Lasso reconstruction (full in Phase 6): record outer-stack path = prefix, inner-DFS path back to seed = cycle; assemble Trace { prefix, cycle: Some(..) } projecting product states → State.
  • check_ltl(ts, phi) driver in mc-explicit/src/lib.rs: to_nnf(!phi) → ltl_to_buchi → Product → nested_dfs; None ⇒ Ok(()) (holds), Some(t) ⇒ Err(t).

  • Implement lite predicate abstraction (existential, over a predicate set P) + a CEGAR loop: abstract → check → replay CEX concretely → if spurious, refine by adding a separating predicate.
  • Deliverable: fairness-aware liveness + a terminating spurious-CEX refinement loop on a small example.

24.2 Detailed Implementation Steps

Governing decisions: ADR-20 (fairness in LTL/Buchi pipeline), ADR-21 (lite CEGAR). References: P13 (Clarke/Grumberg/Jha/Lu/Veith CAV 2000 — CEGAR loop: abstract, check, validate, refine on spurious), B4 Ch3 (fairness encodings in CTL/LTL), B1 Ch9 (abstraction lattice). Fairness correctness: a fair accepting cycle must satisfy all declared fairness sets simultaneously — the generalized-Buchi (multi-set) acceptance condition from B2 Ch5.

  • mc-ltl/src/fairness.rs: pub enum Fair { Weak{en:Label,act:Label}, Strong{en:Label,act:Label} }; pub struct FairnessSet(pub Vec<Fair>). Compile each Fair into an auxiliary LTL constraint GF(en→act-like) folded into !phi OR carried as extra accepting sets.
  • mc-explicit/src/product.rs: extend Product with pub fair: Vec<BitSet> (one accepting set per fairness conjunct → generalized Buchi). Cycle is fair iff it hits every set.
  • mc-explicit/src/nested_dfs.rs: generalized variant nested_dfs_gen(prod) -> Option<Trace> using a counter/index over fair sets (degeneralize on-the-fly: track which sets still unseen on the candidate cycle).
  • mc-explicit/src/abstract.rs (new): pub struct Predicate(pub LtlFormula /*state pred*/); pub struct AbsModel{ preds:Vec<Predicate>, ts:TransitionSystem }. build_abstract(conc:&TransitionSystem,&[Predicate]) -> TransitionSystem (existential next over predicate valuations; abstract state = bitvector of predicate truth).
  • mc-explicit/src/cegar.rs (new): pub fn cegar(conc:&TransitionSystem, phi:&LtlFormula, p0:Vec<Predicate>) -> Verdict; loop: build_abstract → nested_dfs_gen → if CEX, replay_concrete(conc,&trace) → on spurious, refine() adds predicate from the failing transition (weakest-precondition-lite / split state where abstract step has no concrete witness).
  • Verdict = Holds | Violated(Trace) | Refined(usize /*iters*/).

24.6 Pitfalls

  • Degeneralization off-by-one → counter resets mid-cycle, accepts unfair lasso. Root: index advances on wrong set membership. Debug: assert each accepted cycle re-visited under all k sets; dump per-set hit log.
  • Spurious-CEX false-negative → concrete replay uses abstract next, always "replays" → misses spuriousness. Root: replay must use concrete ts.next. Debug: tag traces with model source.
  • Refinement non-progress → same predicate re-added → infinite loop. Root: WP-lite returns existing pred. Debug: dedup predicate set, assert |P| strictly grows; cap iters = state-var count.
  • Fairness on finite paths → fairness is an ω-property; applying to safety/prefix CEX is meaningless. Root: fairness folded into invariant check. Debug: gate fairness to liveness path only.
  • Existential abstraction over-approx → abstract may have spurious-only cycles; never report Violated without concrete replay. Root: trusting abstract CEX directly.

24.7 Performance Concerns

  • Fairness adds k accepting sets → nested_dfs_gen colors grow O(k); memory +k bits/state. Keep k≤8 typical; degeneralized product size ×(k+1).
  • CEGAR: each iter rebuilds abstract model (cheap, |2^|P|| states) + one full nested_dfs; abstract state space 2^|P| ≪ concrete. Refinement bounded by #model predicates.
  • Replay is O(|trace|) concrete steps — negligible vs search.

24.8 Edge Cases

  • Empty predicate set → single abstract state, everything reachable; first refinement bootstraps.
  • All fairness sets empty → degenerates to plain nested_dfs.
  • Fairness constraint never enabled → vacuously satisfied; cannot block any cycle.
  • Abstract model deterministic (preds = all vars) → CEGAR equals concrete check, 1 iter.
  • CEX lasso prefix length 0 (initial accepting) → replay from initial state.

24.9 Failure Analysis

  • Unfair cycle accepted: differential: WF-check vs hand model → fix degeneralize counter
  • Infinite CEGAR loop: iter > #predicates guard → abort Refined(cap), log preds
  • Spurious reported as real: concrete replay mismatch → force replay-before-report invariant
  • Abstract under-approx (missed CEX): must be over-approx only; assert no concrete-only successor dropped → use existential (∃) image

The Unknown verdict (central design rule)

Verdict = Holds | Violated(Trace) | Unknown(reason)
reason ∈ { BudgetExceeded, Timeout, FormulaTooLarge, EngineDisagreement, EncodingTooWide }
  • Never turn a resource ceiling into a silent Holds or a process crash. Exhaustion -> Unknown. This is the load-bearing safety property of the whole tool: the only way to claim Holds is to actually complete the check.

Cross-engine differential agreement (P13) is the meta-soundness check: {Holds, Violated} verdicts must coincide for any model+property in all engines' scope; disagreement = Unknown(EngineDisagreement). Worst-case PSPACE cost is inherent — cap, not solve. Spurious CEX from lite predicate-abstraction (P12) is expected; CEGAR refines or returns Unknown, never reports a spurious violation without simulate confirmation. Parallel/swarm search is deferred (no shared-StateTable race surface).

Mental Models & First Principles

MM1 — Verification is language-emptiness. A temporal property φ holds on system M iff no run of M satisfies ¬φ — equivalently, L(M) ∩ L(Buchi(¬φ)) = ∅. Every engine answers this question; the engines differ only in how they represent and search the infinite set of runs.

MM2 — State = packed valuation, not object. A model-checking state is a bit-vector of variable values, not a pointer or object. This determines memory: 8–48 B/state decides whether 10^8 states fits in 4 GB or not. Every design choice about State, StateEncoder, and StateTable flows from this.

MM3 — On-the-fly ≡ no graph stored. The next() closure generates successors from a state without consulting a pre-built adjacency list. This means a reachable accepting cycle can be found before the entire reachable state space is explored — critical for liveness checking when the graph is too large to store.

MM4 — Fixpoints are set iterations, not loop enumerations. EX Z = {s | ∃s'. T(s,s') ∧ s'∈Z} is a set transformer. BDDs let you compute the next iterate without enumerating each element of Z — so 10^20 states may occupy a BDD of 10^5 nodes when the function is structurally simple.

MM5 — CTL uses least fixpoint (EU) for "eventually" and greatest fixpoint (EG) for "always". This is Knaster-Tarski: the least fixpoint of a monotone operator over a complete lattice is the limit of iterating from ⊥ (empty set) upward; greatest from ⊤ (all states) downward. Swapping them gives a wrong answer, not a runtime error.

MM6 — BDD canonicity is the invariant, not a property. Every Boolean function has exactly one ROBDD node-graph under a fixed variable order and the two reduction rules. If two nodes differ structurally under the same manager and order, they represent different functions — you can compare BddRef by equality instead of truth-table comparison.

MM7 — Counterexamples are lassos, not trees. A Kripke structure M has a finite reachable state space. Any infinite run either visits a repeated state (lasso) or contradicts finiteness. So every liveness CEX is representable as prefix·cycle^ω — a finite datum that simulate can replay step by step.

MM8 — Partial-order reduction preserves the property, not the state space. POR (ample sets C0–C3) selects a subset of enabled transitions at each state such that the checked LTL_-X property has the same verdict over the reduced graph. The reduced graph is not isomorphic to the full graph — it may have different reachable states.

MM9 — Three engines, one semantic model. All three engines consume the same TransitionSystem produced by mc-lang::compile. They cannot disagree due to different interpretations of the model — only due to bugs. Agreement is therefore a correctness oracle, not a coincidence.

MM10 — "Unknown" is the only safe failure mode. Any resource ceiling, encoding limit, or verification timeout that cannot produce a proved or refuted verdict MUST return Unknown(reason). Collapsing a resource limit into Holds is a soundness violation; into a crash is a reliability violation.

Alternative Architectures (Roads Not Taken)

Alt-1 — Monolithic Explicit Checker with Full KripkeStructure

mc-lang → KripkeStructure (states[], trans[], labels[]) → CTL labeler → LTL nested-DFS
           ↑ pre-build full adjacency + label arrays

Regime: small models (≤10^5 states) where the full graph fits comfortably in RAM and fast predecessor lookups justify the upfront cost.

Real system: explicit-state CTL labeling in Clarke-Emerson 1981; NuSMV's explicit-CTL mode; standard textbook presentation (B1 Ch4, B2 Ch6).

Rejection rationale: on-the-fly (ADR-05) avoids materializing the full adjacency list — a CEX can be found before the exponential graph is built, and memory is dominated by the StateTable only. The CTL explicit labeler (Phase 7) does materialize a KripkeStructure as a local oracle for small models only; it is never the primary engine for large ones. Wins for: repeated re-verification of the same model (cached predecessors amortize cost), interactive CTL query evaluation over a fixed state space.

Alt-2 — BDD-Only (Symbolic-Only) without Explicit Engine

mc-lang → TransitionRelation (BDD) → BDD fixpoints for ALL operators (LTL+CTL)
           skip explicit StateTable entirely

Regime: structured hardware-like models (synchronous, regular, wide datapaths) where BDD sizes stay bounded and |states| is too large for explicit enumeration.

Real system: SMV (McMillan 1992), early NuSMV, CUDD-based EDA flows.

Rejection rationale: BDDs can blow up exponentially on asynchronous/irregular models where the variable interaction is dense. The explicit engine handles these cases efficiently (POR + small hash table), while BDDs struggle with the unstructured interleaving. Our three-engine design keeps explicit for irregular protocols and symbolic for structured datapaths. Wins for: verifying synchronous hardware designs with millions of states but highly regular transition structure — exactly NuSMV's original use case.

Alt-3 — Pure SAT / IC3/PDR without BDD or Explicit Engine

mc-lang → CNF encoding (all depths k) → IC3/Property-Directed Reachability
           no StateTable, no BDD unique table

Regime: safety properties (invariants) on large industrial hardware where IC3/PDR outperforms BDD fixpoints and where property-directed over-approximation allows scalable proofs.

Real system: IC3 / PDR (Bradley 2011, Een/Mishchenko/Brayton 2011) as used in ABC, nuXmv, JasperGold.

Rejection rationale: IC3/PDR is a significant algorithmic complexity beyond the scope of this project and requires a mature SAT solver with incremental/assumption mode as a deeply integrated substrate, not just a delegated backend. Our BMC (Phase 10) already uses the project-277 SAT engine for bounded checking; full IC3 is PhaseDeferred. It wins for: industrial safety proofs where the recurrence diameter is unknown and BMC cannot reach it, but the property is an invariant with a small inductive strengthening.

LTL Linear Temporal Logic. LtlFormula (mc-ltl); operators over a single run. Checked via negate→Buchi→product→emptiness.
CTL Computation Tree Logic. CtlFormula (mc-symbolic); branching-time, path quantifiers A/E paired with temporal ops. Checked by fixpoint labeling.
negation normal form (NNF) to_nnf (mc-ltl): pushes Not to atoms via dualities (!F=G!, !Xp=X!p, !U↔R). Temporal ops: X/Next, F/Finally, G/Globally, U/Until, R/Release; CTL prefixes each with A/E. Prereq for GPVW.
Buchi automaton BuchiAutomaton (mc-ltl): ω-automaton with accepting set; accepts runs visiting an accepting state infinitely often. Built from !phi by ltl_to_buchi.
accepting cycle / lasso Reachable cycle in the product containing an accepting state of BuchiAutomaton. = nonempty product language = CEX. Represented as Trace{prefix, cycle:Some(..)}. Generalized Buchi (multiple accepting sets) degeneralized via counter before nested_dfs.
product automaton Product (mc-explicit): synchronous product TransitionSystem × BuchiAutomaton(!phi). Its accepting cycles are exactly runs of the system violating phi.
language emptiness Decision "does the product accept any run?". Empty ⇒ phi holds; nonempty ⇒ lasso CEX. Decided on-the-fly by nested_dfs.
nested DFS nested_dfs (mc-explicit): outer DFS finds accepting states in post-order; inner DFS from each seeks a path back to the outer stack (accepting cycle). O(states+transitions), constant extra colors.
counterexample Trace (mc-types): concrete witness a property fails — finite path (safety) or lasso (liveness). Replayable via simulate.
fairness Constraint restricting attention to "fair" runs. Weak: continuously-enabled ⇒ eventually taken. Strong: infinitely-enabled ⇒ infinitely taken. Encoded into the LTL/Buchi pipeline.
ROBDD Reduced Ordered Binary Decision Diagram (mc-bdd): canonical DAG for a Boolean fn under a fixed variable order + reduction rules. Canonical ⇒ equality = pointer compare.
BDD node BddNode{var, lo, hi} (mc-bdd): decision on variable var, branching to lo (=0) / hi (=1) child BddRefs.
unique table BddManager hash HashMap<BddNode,BddRef>: ensures structural sharing — no two equal nodes — enforcing canonicity.
computed cache BddManager memo of ite(f,g,h) triples → results. Turns exponential recursion into polynomial; eviction policy bounds memory.
complemented edge BddRef(u32) with a sign/complement bit: edge denoting the negation of its target. Halves table size; not is O(1) edge flip.
variable order Permutation of BDD variables in BddManager. Dominates BDD size (polynomial vs exponential for same fn); interleaving current/next vars usually best for TransitionRelation.
sifting / reordering Dynamic variable-reordering heuristic (mc-bdd, Phase 11): slide each variable to its size-minimizing position. Reduces peak nodes mid-run.
ite / apply BddManager::ite(f,g,h) = "if f then g else h" — the universal apply; and=ite(a,b,0), or=ite(a,1,b), not=edge flip. Recurses on top variable, memoized by computed cache.
image Forward successor set: `{s'
pre-image pre_image (mc-symbolic): backward = `{s
least / greatest fixpoint Fixpoint iteration over BDD sets. E[p U q] = LFP of q ∨ (p ∧ EX Z); EG p = GFP of p ∧ EX Z. Converge when the set BDD stops changing.
transition relation TransitionRelation{bdd} (mc-symbolic): T(s,s') over current × next-state variables as a single BDD. Subject of image/pre_image.
bounded model checking bmc (mc-symbolic/mc-bmc): seek a CEX of length ≤ k by unrolling T into CNF and solving. CEX found ⇒ violated; UNSAT to completeness threshold ⇒ holds.
completeness threshold Depth k at which BMC UNSAT proves phi (e.g. recurrence diameter). Below it, UNSAT means only "no CEX ≤ k". Unrolling: I(s0)∧⋀T(si,si+1)∧bounded(!phi) → CNF → SAT.
state explosion #reachable states (and product/BDD size) grows exponentially in variables/processes. The central obstacle; motivates symbolic encoding + reductions.
partial-order / symmetry / abstraction POR (Phase 11): expand only an ample set (C0–C3) of enabled transitions — others independent+invisible to phi. Symmetry: quotient by orbit, explore one canonical representative. Abstraction (Phase 12): map concrete→abstract states (lite predicate abstraction); may introduce spurious CEXs.
CEGAR Counterexample-Guided Abstraction Refinement (Phase 12): abstract → check → if spurious CEX replay fails → refine predicates → repeat.
