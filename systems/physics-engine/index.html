In one paragraph

A physics engine moves solid objects forward in time and stops them passing through each other. This design is a Python 3.11+ library that a game or simulation embeds. The host calls step(dt) once per tick and reads back body transforms (§1). Inside, it narrows candidate collisions in stages, solves for the pushes that keep bodies apart, and puts settled piles to sleep (§3, §8). Its defining constraints are inspectability (the solver math can be stepped in a REPL, ADR-01) and determinism: the same inputs replay bit-exactly on the same platform (§4, ADR-30). The design target is 1,000 awake bodies and 500 contacts within a 16 ms step (§4).

The problem, concretely

Moving every body by velocity × dt each frame and testing for overlap leaves four problems, each named in the blueprint.

First, testing every body against every other body costs n(n−1)/2 pair tests (§34), so something has to discard impossible pairs cheaply, and it must never discard a real one (P5, MM4). Second, a fast body can travel farther in one step than a wall is thick and never register a hit (tunnelling). The blueprint's fixture is a 0.05 m-radius sphere at 50 m/s against a 0.02 m wall at 1/60 s (§22, §34). Third, snapping a penetrating body straight out injects an instantaneous velocity jump, "energy from nowhere", and a stack pops apart (P2). Fourth, if a change in iteration order changes the outcome, a recorded game cannot be replayed (P3, MM3).

The whole structure of §3 answers those pressures: filter pairs conservatively, find exact contacts, solve for impulses with a fixed iteration budget, correct leftover overlap in a separate pass, and fix the order of everything (§3, §8).

How it works, end to end

Follow one tick through the stages of §8's step pipeline, which §3 draws as boxes. The diagram below is adapted from §3 (stage order from the §8 "Step Pipeline" table, boxes named as in §3).

 World.step(dt)  [fixed dt only, I10]
   1  wake check            (forces on sleeping bodies)
   2  Integrator            forces -> velocity (semi-implicit Euler)
   3  Broad Phase           spatial hash / dynamic BVH -> candidate pairs
   4  Narrow Phase          analytic / SAT / GJK-EPA -> ContactManifold
   5  Manifold Cache        match last frame's contacts by feature-id -> warm-start impulses
   6  Island Manager        union-find over contacts + joints -> islands
   7  Constraint Solver     sequential impulse: contacts + joints, restitution, friction
   8  integrate velocity -> position (renormalize quaternions, I7)
   9  NGS position pass     fixes residual penetration without touching velocity
  10  Sleeping Manager      per-island consensus
  11  CCD pass              bullets only, conservative advancement
  1. World owns every body, shape, joint, the broad-phase structure and the manifold cache. It is the only mutable root (§3). step(dt) refuses any dt other than the configured one (I10).
  2. Integrator advances velocity from forces (gravity, applied impulses) using semi-implicit Euler and does not move positions at this point (§3, §8 pipeline row 2, P10).
  3. Broad phase (physics/broadphase/; a spatial hash promoted to a dynamic BVH, ADR-07) returns candidate pairs. False positives are expected; a false negative is a correctness bug (§3, P5).
  4. Narrow phase (physics/narrowphase/) picks a routine per shape-pair type: analytic code for primitives, SAT for convex polytopes, GJK/EPA as the general fallback (ADR-08), and emits ContactManifolds (§3, §10).
  5. Manifold cache (physics/solver/manifold.py) matches new contact points to last frame's by feature_id so accumulated impulses carry over (§8 persistence rule, P4, P12).
  6. Island manager (physics/islands/island_manager.py) groups touching dynamic bodies via union-find; static bodies are never graph nodes (§8, I13).
  7. Constraint solver (physics/solver/velocity_solver.py) runs the velocity pass. Contacts and joints share one solver (P13, §10).
  8. Position pass: integrate velocity into position, then a separate NGS pass (nonlinear Gauss-Seidel, physics/solver/position_solver.py) cleans up residual overlap without changing velocity (§8 rows 8-9, §10, ADR-13, P2).
  9. Sleeping manager (consensus lives in island_manager.py, §10) and the CCD pass (physics/ccd/) close the step; the query interface (physics/query/) reuses the BVH for raycasts and overlap tests (§3, §10). The debug-draw seam and determinism harness are consumers outside the pipeline (§3).

Order inside the step is itself part of the specification (P3, I4).

The core ideas

Fixed-step semi-implicit Euler (§8, ADR-05, P10, P14)

Plain words: update velocity first, then move the body using the new velocity. The blueprint contrasts two schemes (§8):

Scheme Velocity Position Behaviour (§8)
Explicit Euler v(t+dt) = v(t) + a(t)·dt x(t+dt) = x(t) + v(t)·dt (old velocity) systematically gains energy on constrained systems
Semi-implicit (symplectic) Euler v(t+dt) = v(t) + a(t)·dt x(t+dt) = x(t) + v(t+dt)·dt (new velocity) energy oscillates but does not drift upward

The only difference is which velocity moves the body, so an ordering slip silently turns the engine into explicit Euler; the milestone table lists that "explicit-Euler-by-accident" risk for Phase 1 (§40). Orientation uses a unit quaternion renormalized every step: q(t+dt) = normalize( q(t) + 0.5 · dt · ω_quat · q(t) ) (§8, I7). The timestep is an engine-wide constant, not a per-call parameter, and mixing timesteps invalidates the stability and determinism claims (P14, I10).

Finding contacts: filter cheaply, then be exact (§8, P5, P6, ADR-07, ADR-08)

The broad phase pads boxes (AABBs, axis-aligned bounding boxes) so it errs toward extra pairs (P5). The narrow phase works on every convex shape through one support function, the "direction → extreme point contract" (§38, §8 shapes table, P6). Planes are the exception: they are half-spaces handled analytically (§8).

SAT (separating axis theorem) for two polytopes, per §8:

Step Action
1 Candidate axes: face normals of A, face normals of B, cross products of one edge from each
2 Project both shapes onto each axis and measure the interval overlap
3 Any axis with zero or negative overlap means separated: stop, no contact
4 Otherwise the minimum-overlap axis is the contact normal; its overlap is the depth
5 Face-type axis: clip faces into a manifold. Edge-edge axis: closest points of the two edges

GJK/EPA (§8 termination table) handles shapes without a fast path. GJK grows a simplex of 1 to 4 points; it stops with "separated" if a new support point does not pass the origin, and stops with "overlap" when a tetrahedron contains the origin. EPA then expands that tetrahedron until the nearest face stops moving outward; that face gives normal and depth. Both are capped at 32 iterations, returning a best estimate rather than hanging (§8, T2).

Contact manifolds and warm starting (§8, ADR-09, ADR-12, P4, P12)

A ContactManifold holds up to 4 ContactPoints per body pair, each with a feature_id derived from the vertex/edge/face indices that produced it (§8). The persistence rule is three steps (§8):

  1. At the start of narrow phase, match each new point to last frame's by feature_id.
  2. A match carries over normal_impulse and tangent_impulse as the warm start.
  3. An unmatched new point starts cold; an unmatched old point is dropped.

Keying by pair index would silently degrade to a cold start every frame, because pair indices are not stable across a broad-phase resort (P4). When matching fails the engine falls back to a fresh contact, softer for one frame but never a crash (P12, FM-7).

Sequential impulses: one constraint at a time (§8, ADR-10, MM1)

Plain words: a contact is a rule "these bodies must not approach along the normal". Fix one rule at a time, using the latest velocities, and repeat for a fixed number of passes (8 by default, ADR-11, P1). That is Gauss-Seidel iteration (sequential impulse, MM1). For one constraint, with Jacobian J and bias b (§8):

λ = − (J·v + b) / (J · M⁻¹ · Jᵀ),   m_eff = 1 / (J · M⁻¹ · Jᵀ)
v' = v + M⁻¹ · Jᵀ · λ

The accumulated impulse is clamped (λ_total = clamp(λ_total + λ, lo, hi)) and only the change is applied, so normal impulses never go negative (I8) and friction stays within μ·λ_n per tangent axis (Coulomb pyramid, I9, ADR-14). Restitution only applies when the approach speed exceeds restitution_velocity_threshold (the §8 example uses 1.0 m/s), which stops resting contacts from bouncing forever (ADR-15).

The blueprint's own worked example (§8): body A, 1 kg, falls at v_A = (0, −2, 0) m/s onto a static body B; normal n = (0, 1, 0), restitution e = 0.5.

Quantity Value (§8)
v_n along the normal −2
m_eff (B is static, so only A counts) 1 kg
Target after impact, −e·v_n 1.0 m/s separation (2 m/s exceeds the 1 m/s threshold)
Impulse λ = −m_eff · (v_n − v_n') 3 N·s
New velocity v_A' (0, 1, 0) m/s

One iteration is enough here because there is a single uncoupled contact (§8). The blueprint is inconsistent on the example's penetration: §8 gives penetration = 0.01 m and says it is "below slop", so the position bias is zero, while §4 and I2 set penetration_slop to 0.002 m.

Fixing leftover overlap, and catching fast bodies (§8, ADR-13, ADR-18, P2, P11)

Two other mechanisms keep bodies out of walls:

  • Position correction. The blueprint compares Baumgarte (mixing a fraction of position error into the velocity bias, b = (β/dt)·C(x), which can inject energy at high β) with soft constraints, and chooses a third option: a separate NGS pass that moves only positions (§8, ADR-13). It stops correcting once penetration is within penetration_slop of 2 mm (§4, I2). §34 gives a recovery example in the Numbers section below.
  • Continuous collision detection (CCD). For bodies flagged bullet, conservative advancement finds the largest time advance that cannot reach contact, using separation and a bound on relative speed. Time of impact is reached when that advance falls below a tolerance; if it exceeds 1.0 there is no hit this step (§8, ADR-18). It is opt-in, translation-only, and bodies not flagged bullet pay nothing (P11, ADR-18).

Islands and sleeping (§8, ADR-17, ADR-20, MM6, MM7)

Plain words: two piles that never touch can be solved separately, and a pile that has stopped moving can be skipped. An island is a connected set of dynamic bodies linked by contacts or joints, built with union-find. Static bodies are never graph nodes, so a shared floor does not merge unrelated stacks (§8, I13, MM6). The island sleep state machine (§8):

State Entry Exit
AllAwake any member above velocity threshold every member below threshold for N consecutive steps
Settling every member below threshold, timer running timer reaches sleep_time_threshold, then Asleep; any member re-exceeds, then AllAwake (timer resets fully)
Asleep settling timer expired an impulse above wake_impulse_threshold on any member wakes the whole island

One twitching body keeps the entire island awake on purpose (P8, MM7). Sleeping bodies must cost zero integration and zero solver work (I14).

The trade-offs — where engineers disagree

Language: Python, not C++ (ADR-01, ADR-02)

Chosen: Python 3.11+, with NumPy arrays for bulk state and a pure-Python solver loop, so the solver math can be inspected and stepped in a REPL (ADR-01, ADR-02, §1). Rejected: C++, Rust, C; a fully vectorized NumPy solver; an upfront Cython rewrite. The solver inner loop is data-dependent and does not vectorize (ADR-02, §1). When the rejected choice is right: "A shipped console title needs sub-millisecond native step times" (ADR-01); for the native core, when "Contact count exceeds ~5,000/step and step time is the bottleneck" (ADR-02). The blueprint gives different figures for that ceiling: §31 puts it at "a few thousand active contacts" and says §34 derives the exact number, while §34 derives ≈ 625 contacts and §37's un-defer trigger uses that ~625 figure.

Integrator: semi-implicit Euler (ADR-05)

Chosen: semi-implicit (symplectic) Euler, with bounded energy drift at negligible cost (ADR-05, P10). Rejected: explicit Euler, RK4, implicit Euler. RK4 is more accurate for smooth forces but does not respect the symplectic structure and costs more per step (§8). When the rejected choice is right: "A stiff cloth/soft-body-adjacent system needing unconditional stability at large dt" (ADR-05).

Broad phase: spatial hash promoted to a dynamic BVH (ADR-07)

Chosen: start with a spatial hash and promote to a dynamic BVH, which handles clustering and scale variance better than axis-sorted lists (ADR-07). §8 lists BVH update as O(log n) per moved proxy against O(n) amortized for the hash. Rejected: sweep-and-prune as the production path (ADR-07). When the rejected choice is right: "Scenes are sparse and axis-coherent frame-to-frame (Box2D-style)" (ADR-07).

Narrow phase: analytic + SAT + GJK/EPA fallback (ADR-08)

Chosen: analytic routines for primitive pairs and SAT for polytopes, with GJK/EPA as the fallback; analytic and SAT are cheaper and more numerically robust for the common cases (ADR-08). Rejected: GJK/EPA for every pair (ADR-08). When the rejected choice is right: "Shape library is fully general/unbounded convex meshes with no primitive fast paths" (ADR-08). §33 says Bullet makes this choice for that reason.

Solver: sequential impulse (ADR-10)

Chosen: sequential impulse (projected Gauss-Seidel on the contact LCP), linear cost per iteration and robust at real-time budgets (ADR-10). Rejected: direct pivoting LCP (Lemke) and XPBD (ADR-10, §36 A1, A2). When the rejected choice is right: "A small, tightly-coupled offline scene needing an exact LCP solution" (ADR-10). XPBD wins for deformable systems, which are non-goals here (§36 A2, §1).

Position correction: a separate NGS pass (ADR-13)

Chosen: a separate NGS position pass that decouples position error from velocity and avoids energy injection (ADR-13, P2). Rejected: velocity-level Baumgarte bias as the primary mechanism (ADR-13). When the rejected choice is right: "An extremely tight step budget where a second pass isn't affordable" (ADR-13). The cost of the choice is a second traversal of the constraint graph (P2).

Sleeping: island consensus (ADR-17)

Chosen: a per-body energy threshold plus island-level agreement, because sleeping is the whole performance argument at scale (ADR-17, I14, P8). Rejected: never sleep (ADR-17). When the rejected choice is right: "A networked lockstep game where sleep/wake nondeterminism risk outweighs CPU savings" (ADR-17).

Determinism: same platform only (ADR-30, ADR-19)

Chosen: a bit-exact guarantee on the same platform, an explicit non-guarantee across platforms, and a canonical contact sort before solving (ADR-30, ADR-19, §4). The reason is that FMA contraction and libm differences make a cross-platform claim false in practice (ADR-30). Rejected: claiming cross-platform bit-exactness (ADR-30); hash-map iteration order for contacts (ADR-19). When the rejected choice is right: a single fixed deployment target (ADR-30), or "A single-player build with no replay/determinism requirement" (ADR-19).

Where the sort happens is stated inconsistently. §15.6 says the canonical sort "must be applied before pairs leave this stage" (the broad phase), and §35's hard question 3 says ordering is canonicalized at broad-phase output. The §11 query_pairs comment says order is "NOT guaranteed here; canonical sort happens later", and ADR-19 and I4 say "pre-solve", with a sort key that includes feature-id (ADR-19).

Roads not taken (§36, §37)

Direct LCP/MLCP solve (§36 A1). Wins for small, tightly coupled scenes of tens of bodies that need an exact simultaneous answer, such as offline research validation. Rejected because pivoting scales worse than linearly with contacts and has no warm-start analog.

Position-based dynamics / XPBD (§36 A2). Wins for deformable, mass-varying or very stiff systems (cloth, soft bodies), which are this blueprint's non-goals. Rejected because the rigid-body scope does not need its main advantage and would give up the citable sequential-impulse lineage.

Fully implicit Newton-based contact, as in MuJoCo (§36 A3). Wins for contact-rich robotic manipulation research needing smooth gradients and tolerating higher per-step cost. Rejected because Newton iterations per step do not fit the §4 real-time budget.

Penalty/spring contact (§36 A4). Wins for very simple engines or deliberately soft, squishy contact. Rejected because a stiff spring needs a tiny dt or an implicit integrator to stay stable, which is the trade-off the sequential-impulse solver was chosen to avoid.

Native solver core (§37). Deferred, not rejected. Un-defer when measured contact count in production exceeds §34's derived ceiling (§37).

What must never be false

  • I1: total mechanical energy in a frictionless closed system does not rise by more than 1% per simulated second. Noticed by the energy-drift regression fixture and StepStats.total_kinetic_energy (§7).
  • I2: no persistent penetration beyond penetration_slop (2 mm) after the position pass. Noticed by a per-step max-depth sample, StepStats.max_penetration (§7, §4).
  • I3: a settled stack neither jitters (linear-velocity RMS under 0.01 m/s) nor sinks. Noticed by the stack-settle regression fixture, StepStats.awake_islands (§7).
  • I4: contact ordering is identical across runs for identical state and dt. Noticed by a cross-run contact-order hash diff, StepStats.contact_order_hash (§7).
  • I5: a sleeping island wakes on any impulse above wake_impulse_threshold on any member. Noticed by a per-step impulse test, StepStats.wake_events (§7).
  • I6: no velocity or orientation becomes NaN and spreads. Noticed by an isnan scan every step, StepStats.nan_quarantine_count (§7).
  • I7: quaternions stay within 1e-6 of unit length. Noticed by a norm check every step, StepStats.max_quat_drift (§7).
  • I8: the accumulated normal impulse is never negative (contacts only push). Noticed by an assertion in the solver, StepStats.clamp_events (§7).
  • I9: friction impulse never exceeds mu * normal_impulse. Noticed by an assertion in the friction solve, StepStats.friction_clamp_events (§7).
  • I10: the world advances only in fixed dt. Noticed by comparing dt to the configured step; the call is rejected with PhysicsError; StepStats.dt_violation_count (§7).
  • I11: a quarantined body is left out of island solves until manually reset. Noticed by the quarantine flag check, StepStats.quarantined_bodies (§7).
  • I12: manifold feature-ids are stable across frames for an unchanged shape pair. Noticed by a match-rate sample, StepStats.manifold_match_rate (§7).
  • I13: a static body never bridges two islands. Noticed by an island-membership audit fixture, StepStats.island_count (§7).
  • I14: sleeping bodies cost zero integration and zero solver work. Noticed by a CPU-time-by-state profile, StepStats.sleeping_body_count (§7).

When something looks wrong, §7 says to find the violated row first (jitter to I3, drift to I1/I7, solver divergence to I8/I9, replay mismatch to I4, a frozen or exploding body to I6/I11) and never patch a symptom such as a global velocity clamp (§7).

What breaks in production

  • FM-1: stack jitter. Cause: an under-iterated solver or aggressive position bias. Detected by linear-velocity RMS above threshold on a settled scene. There is no automatic recovery; raise velocity_iterations/position_iterations and enable warm start (§25, P1).
  • FM-2: persistent penetration beyond slop. Cause: too few position iterations or a too-tight max_correction. Detected by StepStats.max_penetration against the I2 bound. The engine adds bounded extra position iterations; otherwise raise position_iterations and re-tune (§25).
  • FM-4: constraint explosion. Velocities diverge from a singular constraint, a joint-limit conflict, or energy injected by the position pass. Detected by a velocity-magnitude check; a documented, logged velocity clamp is the automatic response, and the operator traces the offending joint or contact (§25).
  • FM-5: tunnelling through thin walls. Cause: a fast body not flagged bullet, or the CCD cap exhausted. Found only after the fact (a body on the wrong side of geometry); there is no automatic recovery because CCD is opt-in. Flag the body and re-run the scene-validation lint (§25).
  • FM-6: a sleeping body fails to wake. Cause: threshold too high, or a force API that bypasses the wake check. Detected by StepStats.wake_events staying silent despite an applied force. Fix the call path so it routes through the wake check (I5, §25).
  • FM-7: warm-start loss or visible softness. Cause: feature-id matching failure. Detected by a falling StepStats.manifold_match_rate. The engine falls back to cold contacts (not an error); the manual fix is to investigate reference-face flips (§25, I12, P12).
  • FM-8: replay divergence. Cause: nondeterministic iteration order, uninitialized state, or cross-platform float differences. Detected by a two-run hash diff; recovery is bisecting with scripts/run_determinism_harness.sh (§25, I4). §4 gives a recovery-time target for the bisect run.
  • FM-10: GJK/EPA non-termination or wrong normal. Cause: a near-degenerate simplex or a scale-dependent epsilon mismatch. Detected by iteration-count telemetry; an iteration cap gives a conservative fallback, and the tolerance is re-tuned by hand (§25, T2).

Threats a reader should know (§24):

  • T2: a crafted degenerate mesh causes a non-terminating loop. Answered by hull validation at load and GJK/EPA iteration caps, with the shape quarantined if the cap is hit (§24).
  • T3: adversarial input drives a divide-by-zero and injects NaN. Answered by NaN quarantine at the integrator and solver boundary (I6, I11, P9).
  • T4: a client deliberately desyncs a lockstep game for advantage. Answered by deterministic contact ordering and per-step state hashing; resync is the host's job, not the engine's (§24).
  • T8: a dense pile of thousands of overlapping bodies forces a contact explosion. Answered by the §4 contacts-per-step cap and dropping the lowest-priority contacts (§24).
  • T9: compiler, FMA or libm differences break determinism across client builds. Answered by the documented same-platform-only guarantee and a cross-build hash diff in CI (ADR-30, §24).

How it compares

  • Box2D commits fully to 2D, so manifolds and joints shrink to 2-3 degrees of freedom. That is the better trade for any inherently 2D game, where this design's 3D generality is overhead (§33).
  • Bullet uses GJK/EPA as the primary narrow-phase path, with sequential impulse and conservative-advancement CCD. That fits shape libraries dominated by general convex meshes with few primitive fast paths, such as robotics CAD geometry (§33, ADR-08).
  • Chipmunk2D makes the "arbiter" an explicit persistent-contact object and uses a spatial hash. That suits embeddable, scripting-hosted environments where explicit lifetimes matter more than raw solver throughput (§33).
  • Rapier uses a TGS-soft solver variant and a GIL-free native core with cross-island thread parallelism. It wins in exactly the regime ADR-20 defers, a compiled core where thread-per-island pays off (§33, ADR-20).
  • MuJoCo drops contact manifolds for a smooth, implicit convex-optimization contact model. It suits contact-rich robotics research needing Newton-level accuracy per step, at a cost the §4 real-time budget cannot afford (§33, §36 A3).

If you only remember three things

Every visual artefact (jitter, softness, slow settling) is a convergence story about iteration count and ordering, not about physics coefficients (MM1, P1). Cheap stages filter conservatively and expensive stages run only on survivors: a broad phase that rejects nothing wrongly, opt-in CCD, and sleeping islands (P5, P11, P8). Determinism is a property of the whole pipeline's order, so contact order, a fixed dt and the same-platform limit are written into the design (MM3, P3, ADR-30).

Words used here

  • Rigid body: a solid object whose shape never deforms, described by position, orientation, velocities and mass (§8).
  • Broad phase: the cheap first pass that lists pairs of bodies that might touch (§8, P5).
  • Narrow phase: the exact per-pair test that finds real contacts (§8).
  • AABB: axis-aligned bounding box, the coarse box the broad phase uses (§38).
  • Support function: "farthest point of this shape in direction d", the one interface every convex shape offers (§8, P6).
  • Contact manifold: the up-to-4 contact points between two bodies, persisted across frames (§8).
  • Feature-id: a stable label for the vertex, edge or face behind a contact point, used to match frames (§8, P4).
  • Sequential impulse: fixing one constraint at a time with impulses, over several passes (§8, ADR-10).
  • Warm starting: starting this step's solve from last step's impulses (§8, ADR-12).
  • NGS: nonlinear Gauss-Seidel, the position-only correction pass (§38, ADR-13).
  • Island: a group of touching dynamic bodies solved independently (§8, I13).
  • Tunnelling: a fast body skipping through thin geometry between steps (§34).
  • CCD: continuous collision detection, the sweep that prevents tunnelling for flagged bodies (§8, ADR-18).
  • Quarantine: isolating a body whose state became NaN until it is manually reset (I6, I11).
