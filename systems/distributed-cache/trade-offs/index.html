Decisions (§9) · 24 ADRs

ADR-01

Core language

Chosen

Rust 2021, MSRV 1.75

Rejected

Go; C++

When the rejected choice is right

Go wins with zero in-house Rust experience and no strict p99 SLA — e.g. an internal tool at < 10K QPS

Why: FFI-free reuse of ranks 59/69/72's Rust crates + GC-free tail latency for M3

ADR-02

Async runtime

Chosen

Tokio

Rejected

async-std; glommio (io_uring)

When the rejected choice is right

glommio wins for a fixed-topology, NVMe-bound workload with heavy per-request disk I/O

Why: tonic/hyper/tower cover gRPC+RESP3+Memcached fan-out from one runtime

ADR-03

Concurrency model

Chosen

Per-shard event loop, shared-nothing

Rejected

Global hashmap + mutex shards

When the rejected choice is right

a shared-lock design wins on a ≤4-core single box where cross-shard atomic multi-key ops matter more than per-core scaling

Why: mirrors Redis/Dragonfly; avoids lock contention on the hot path

ADR-04

Slot count

Chosen

16,384 (Redis Cluster convention)

Rejected

1,024 slots; no slot indirection

When the rejected choice is right

fewer slots (1,024) win for small fixed clusters (≤ 8 nodes) where gossip payload size matters more than migration granularity

Why: right granularity to a 1,000-shard fleet; load-bearing (I13)

ADR-05

Hash strategies

Chosen

Jump, rendezvous, ketama (all three)

Rejected

single strategy only

When the rejected choice is right

a single ketama ring wins when interoperating with legacy memcached clients that only implement ketama

Why: no one hash wins on both uniform-count and weighted-shard axes

ADR-06

Gossip

Chosen

SWIM + Lifeguard, consume rank 72

Rejected

reimplement in-repo; consume etcd/Consul gossip

When the rejected choice is right

embedding etcd's gossip wins when the deployment already runs etcd for service discovery

Why: avoid duplicating a correctness-critical protocol

ADR-07

Cluster coordinator

Chosen

Raft, separate quorum, consume rank 39

Rejected

Raft embedded per data node; single non-replicated coordinator

When the rejected choice is right

embedding Raft per node wins for a small (3–5 node) fixed cluster not worth a second quorum — etcd's own bet

Why: keeps consensus off the hot path (P3); a coordinator failure doesn't compound with a data-plane failure

ADR-08

Replication mode

Chosen

Async, primary → N replicas

Rejected

Synchronous quorum replication

When the rejected choice is right

sync replication wins when cached values cannot be cheaply recomputed (idempotency tokens, distributed locks)

Why: cache workloads tolerate losing the last few acked writes for steady-state latency (M6)

ADR-09

Wire surface

Chosen

Multi-protocol on every node

Rejected

Protocol-specific node pools

When the rejected choice is right

protocol-specific pools win when one protocol's clients generate pathological load operators want isolated

Why: one key namespace; client picks protocol; avoids fleet fragmentation

ADR-10

TLS / ACL granularity

Chosen

rustls; ACL per namespace

Rejected

OpenSSL bindings; per-key ACL

When the rejected choice is right

per-key ACL wins for a low-QPS admin namespace where finer tenancy outweighs the O(1) constraint

Why: rustls avoids OpenSSL CVE churn; per-namespace ACL keeps per-command check O(1)

ADR-11

Reshard protocol

Chosen

Double-write window + ASK/MOVED

Rejected

Stop-the-world migration; 2PC per key

When the rejected choice is right

stop-the-world wins for a cache already tolerating maintenance windows (batch-only, no live traffic)

Why: mirrors Redis Cluster exactly; free wire-compat with the Redis client ecosystem

ADR-12

Coherency default

Chosen

Write-through

Rejected

Write-back as default

When the rejected choice is right

write-back-by-default wins once a namespace has provisioned the WAL and is write-latency-sensitive

Why: the only policy correct without a WAL; safe default for unprovisioned namespaces

ADR-13

Stampede protection

Chosen

XFetch

Rejected

Fixed jittered TTL; Facebook-style leases

When the rejected choice is right

leases win when the backing-store call is so expensive even XFetch's small false-early-refresh rate is unacceptable

Why: close to optimal (Vattani et al. 2015), cheap, no memory overhead

ADR-14

Hot-key detection

Chosen

Count-min sketch, client-side

Rejected

Exact per-key counters; server-side only

When the rejected choice is right

exact counters win at ≤ 10K distinct keys where memory isn't constrained and precision matters (billing alerts)

Why: O(1) memory per client, tunable; false positives are cheap

ADR-15

Request coalescing

Chosen

Single-flight per (key, op)

Rejected

Facebook-style lease tokens

When the rejected choice is right

leases win at Facebook regional-pool scale needing cross-process, not just cross-task, coalescing

Why: standard primitive, simpler to reason about; leases solve cross-process coalescing (deferred)

ADR-16

License

When the rejected choice is right

AGPL wins for a project wanting to force hosted competitors to open-source modifications

ADR-17

Hash function

Persistence

None in Phase 0; WAL (rank 69) only

Roads not taken (§36)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt 1 — Proxy-Routed Topology

client -> [stateless proxy tier] -> shard 1..N
              (consistent hash,
               no cluster awareness
               in the client)

Regime where it wins: many small, independent, polyglot client fleets that should never see cluster topology; the simplest possible client library. Real system: Twemproxy, mcrouter. Rejected because it hides topology from the application (violates P1), adds a network hop, and turns the proxy tier itself into a new capacity-planning and SPOF-class problem this design's client-routed model avoids entirely.

Alt 2 — Gossip-Only Topology (no separate consensus quorum)

node1 <--gossip--> node2 <--gossip--> node3
   (slot ownership derived from
    gossip-converged state, no Raft)

Regime where it wins: small-to-medium fixed clusters (tens of nodes) where operating a second quorum is not worth it. Real system: Redis Cluster. Rejected because gossip is eventually consistent; a split vote during a network partition can produce two nodes both believing they own a slot — this design's I1/I2 require linearizable ownership, which gossip alone cannot provide (§33).

Alt 3 — Embedded Consensus Per Node

[node1 = data + Raft peer] <-> [node2 = data + Raft peer] <-> [node3 = data + Raft peer]
        (every data node is also a consensus voter)

Regime where it wins: small fixed clusters (3–7 nodes) where a second quorum is pure overhead and the team wants one binary, one deployment unit. Real system: etcd, CockroachDB. Rejected because coupling every data node to consensus-quorum membership degrades quorum latency as the data plane scales — it violates P3 at scale beyond roughly 7 nodes, well below this project's 1,000-shard target (§31, HQ19).
