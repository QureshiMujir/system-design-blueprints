3. Architectural Overview

Client library. Owns the hash ring and the redirect-follower state machine; the only place a MOVED permanently updates routing state (I6). Runs inside the caller's process — no separate hop.

Wire layer. Three concurrent listeners (Memcached binary : 11211, RESP3 : 6379, gRPC : 50051) sharing one key namespace; the magic byte / first frame token disambiguates the protocol per connection, never per node (P5).

Routing / slot table. A read-mostly SlotTable (§11) behind an ArcSwap; the data path reads a local snapshot and never calls the coordinator inline (P3). This is the concurrency boundary between the hot path and cluster control.

Coherency engine. Dispatches to one of five policies per namespace (§20); the boundary between "cache" and "cache in front of a backing store."

Per-node engine. Delegated to LRU-LFU-Cache (rank 59) behind the Engine trait (§11); this is the persistence-adjacent boundary — the engine owns in-memory storage, the WAL (rank 69) owns durability when write-back is enabled.

Replication. Async, primary → N replicas, lag-tracked per replica; the data-plane's own internal consistency boundary, distinct from cluster-layer consensus.

Migration. The four-phase (Importing → DoubleWrite → Catchup → Cutover) state machine that moves slot ownership online; touches both the data plane (double-write) and the cluster layer (the SlotMoved commit).

Cluster layer. Gossip (liveness, eventually consistent) and the Raft coordinator (ownership, linearizable) are structurally separate processes on separate hosts — this is the project's central trust and authority boundary (I5, ADR-07).

Operability layer. The rebalancer, dashboard, and admin CLI are the only sanctioned callers of the coordinator's ProposeEvent RPC (§11); this is the admin trust boundary (§24, admin surface).

Three properties recur throughout this document: the data path is one-way at steady state (client hashes → client routes → server serves → replicas tail); the cluster layer is strictly out-of-band of the data path; the wire layer is multi-protocol by construction, never a per-node configuration choice.

8. Domain Model / Protocol / Data Model

Memcached binary protocol frame

24-byte fixed header, then extras / key / value:

0:     magic (0x80 request, 0x81 response)
1:     opcode
2–3:   key length (u16 BE)
4:     extras length
5:     data type (0x00 in this implementation)
6–7:   vbucket id / status (u16 BE)
8–11:  total body length (u32 BE)
12–15: opaque (passthrough)
16–23: CAS (u64 BE)

Replication record layout

seq (u64) | epoch (Epoch) | op (Set|Delete|Migrate) | timestamp | HMAC — applied in strict seq order (I8); a corrupted or out-of-order record is rejected, never applied speculatively.

Malformed-input example

A Memcached frame whose declared total body length (bytes 8–11) does not equal key_len + extras_len + value_len: the codec rejects the frame, closes the connection, and increments wire_malformed_frame_total (T-1) — it never attempts a best-effort parse.

Failure-path example

A replica receives a replication record whose HMAC fails verification: the record is rejected (I8, I3 remain intact because nothing is applied), the replica requests a rebase, and the primary streams a fresh engine snapshot from scan_slot (FM-4).

Design principles (§6)

  • P1 — The client is the router. Routing logic lives in the client library, not a proxy. Tradeoff: the client library carries more logic than a thin proxy client would. Operational implication: topology is observable to the application (metrics, tracing attach to the caller's own process). Violating it (routing in a proxy) breaks P1's whole premise — see §36 Alt 1's rejection.
  • P2 — Cluster topology is consensus-backed. Slot ownership, replica assignment, and the epoch live in the Raft log (I1, I2). Tradeoff: a second quorum to operate. Violating it (deriving ownership from gossip) produces split-brain slot ownership (MM2, §36 Alt 2).
  • P3 — The data path never blocks on the cluster path. The data path reads a local SlotTable snapshot; it never calls the coordinator inline. Tradeoff: topology updates are eventually — not immediately — visible to the data plane. Violating it collapses the p99 latency target (§4, M3) the instant a Raft round trip lands on the hot path.
  • P4 — Migrations are online by construction. Exactly one node is authoritative for a slot at every instant; the migration window admits reads from both sides. Tradeoff: a more complex state machine (§18) than stop-the-world migration. Violating it (skip the double-write window) reintroduces the maintenance-window outage this design exists to avoid.
  • P5 — The wire surface is multi-protocol, simultaneously. Every node listens on Memcached binary, RESP3, and gRPC concurrently over one key namespace. Tradeoff: three codecs to maintain instead of one. Violating it (protocol-specific node pools) fragments the fleet and reintroduces the operational cost this design avoids (ADR-09).
  • P6 — The per-node engine is pluggable, not bespoke. Eviction is delegated to the Engine trait (rank 59). Tradeoff: an extra trait-object indirection on every engine call. Violating it (forking the cluster code per eviction policy) makes TinyLFU/ARC/ S3-FIFO experiments require a cluster-code rewrite.
  • P7 — No silent fallbacks. MOVED is a client bug (stale hash table); ASK is a migration in flight and must not be retained as authoritative (I6). Tradeoff: clients must implement the redirect state machine correctly. Violating it produces redirect storms (FM-2, MM3).
  • P8 — Replication is async and lag-aware. The primary acks after local apply; reads with a freshness requirement specify min_lag_ms. Tradeoff: acknowledged writes can be lost on primary failure (ADR-08, FM-6). Violating it (silently promoting a lagging replica) serves stale reads as if they were fresh.
  • P9 — Hot keys are a client concern first, server concern second. Detection, ephemeral caching, and coalescing happen client-side; shadow replicas (§21) are the server-side escalation. Tradeoff: client library complexity. Violating it pushes all hot-key load onto a single shard primary with no absorption layer.
  • P10 — Determinism is the default for the rebalancer. The rebalancer's plan is a pure function of (current topology, target topology, weights, seed). Tradeoff: less "clever" heuristic freedom. Violating it makes two operators running the same rebalance get different plans — unacceptable for change management.
  • P11 — Slot count is a load-bearing constant, never parameterized at runtime. 16,384 is compiled in (ADR-04, I13). Tradeoff: changing it requires a new cluster, not an online operation. Violating it (making slot count configurable per cluster) breaks every slot-indexed structure's fixed-size assumptions (§34).
  • P12 — Observability is a first-class deliverable, not an afterthought. Every phase ships metrics and traces before it ships a feature flag to disable them. Tradeoff: more upfront work per phase. Violating it means the first production incident is also the first time anyone looks at what telemetry exists.
  • P13 — Fail closed on ambiguous authorization. An ACL check that cannot resolve (stale cache, unknown principal) denies rather than allows. Tradeoff: a transient ACL propagation delay can cause spurious denials. Violating it fails open, the worse security failure mode (§24).
  • P14 — Backward compatibility is a wire-format contract, not a convention. Every wire/storage schema change is versioned and dual-read for one release (§27). Tradeoff: slower schema iteration. Violating it breaks a rolling upgrade mid-fleet.
