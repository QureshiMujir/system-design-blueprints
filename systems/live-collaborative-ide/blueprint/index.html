1. Goal

1.1 What Is Built

A server-authoritative real-time collaborative IDE engine in Rust. Multiple clients edit a shared multi-file workspace concurrently; every keystroke is a CRDT operation that converges to byte-identical documents on all peers. A virtual project filesystem is itself a CRDT tree. A per-workspace language-server multiplexer maps CRDT positions to deliver diagnostics and completions to every participant.

System boundaries (in-scope):

Component Boundary
CRDT text engine Full YATA/RGA-style sequence CRDT; insert/delete/tombstone/GC
Sync protocol State-vector delta exchange; causal buffering; catch-up on join
WebSocket transport Framing, auth handshake, routing, backpressure
Session room actor Per-workspace membership, op ordering authority, fan-out
Durable op log + snapshots Append-only frames; periodic snapshot; crash recovery
Presence/awareness Ephemeral cursor/selection/viewport; clock-expiry; follow-mode
Virtual filesystem CRDT FileNode tree; create/delete/rename/move; cycle resolution
Undo/redo + tombstone GC Per-site selective undo; compaction against snapshot
LSP multiplexer Spawn LS per (workspace, language); position mapping; diag fan-out
Auth + ACL Token handshake; per-workspace read/write/none enforcement
Headless CLI client lcide-cli: serve, join, edit-script, dump, bench

Explicit non-goals:

  • Browser UI, editor front-end, DOM rendering — out of scope.
  • Conflict resolution by human merge UI — CRDT handles all conflicts automatically.
  • Distributed server cluster, consensus across server replicas — single-server workspace host.
  • Git/VCS integration — workspace CRDT is not a commit graph.
  • Plugin system, extension marketplace, themes.
  • Voice/video, screen share beyond follow-mode viewport sync.
  • Mobile or tablet client support.

1.2 Deployment Model

Single Rust binary (lcide-server) hosting N workspaces, each in its own room actor. Clients connect via WebSocket (TLS-terminated upstream). Workspace op logs and snapshots written to a local directory tree under WORKSPACE_STORE_PATH. Horizontal scaling deferred — one server, one store, one process. Target: tens of workspaces per server, 10–30 concurrent writers per workspace.

Target users / operators / developers:

Role Interaction
End user (editor client) Connects via WebSocket; sends/receives SyncMessage; never sees CRDT internals
Workspace operator Provisions server; sets WORKSPACE_STORE_PATH, token secrets, per-room limits
Integrator/developer Imports lcide-core, lcide-crdt, lcide-doc as libraries; drives lcide-cli for testing
Test/bench harness Runs lcide-cli bench or edit-script to simulate N concurrent clients

1.3 Phase 0 Deliverable — Locked Crates and Modules

The following crates exist after Phase 0 (workspace scaffolding + lcide-core):

  1. lcide-core — shared types: SiteId, ClientId, DocId, WorkspaceId, OpId, Lamport, StateVector; no I/O; exhaustive PartialOrd/Hash/serde derives; pure library.
  2. lcide-crdt — sequence CRDT: Item, YATA integration ordering, tombstones, arena, id→Item map; insert/delete/lookup.
  3. lcide-doc — Document: applies local edits, emits TextOp, integrates remote ops, materializes UTF-8, undo/redo stacks, per-doc StateVector.
  4. lcide-workspace — virtual project filesystem as CRDT tree: FileNode, create/delete/rename/move ops, path index, FsCrdtOp.
  5. lcide-sync — sync protocol: state-vector diff, delta computation, causal buffering, catch-up, Ack/retransmit.
  6. lcide-presence — ephemeral AwarenessState; clock-based expiry; follow-mode; never persisted.
  7. lcide-session — per-workspace room actor: membership, join/leave, op ordering, fan-out, backpressure.
  8. lcide-persist — append-only op log + periodic snapshots, workspace metadata, crash recovery.
  9. lcide-net — WebSocket transport: handshake/auth, frame codec, per-connection send queue, room routing.
  10. lcide-lsp — language-server multiplexer: spawn LS, position mapping through CRDT, diag/completion fan-out.
  11. lcide-server — server binary: wires net + session + sync + persist + lsp; multi-workspace host.
  12. lcide-cli — headless client + ops: serve | join | edit-script | dump | bench.

1.6 Recommended Language: Rust — Rationale

The hot path is local edit → CRDT integrate → WebSocket fan-out under tens of concurrent writers per workspace; it must be tail-latency-stable with no GC pauses on the merge path, must hold large interned op/tombstone state in bounded memory, and must encode the op/event taxonomy as exhaustive enums the compiler checks. Rust gives predictable latency, arena/index-based document storage, zero-copy framing, and Send/Sync-checked concurrency for the per-room actor model. The server core, sync protocol, document model, and LSP multiplexer are all Rust; a thin reference client is out of scope (a headless test client in the same workspace suffices).

2.2 Historical and Architectural Significance

  • OT lineage (1989–2010): Ellis & Gibbs showed the transformation-based approach; Jupiter (Lotus Notes) productionized it; Google Wave (2009) exposed its brittleness at scale (quadratic transformation complexity, ordering dependency on server).
  • CRDT shift (2011–present): Shapiro et al formalized CRDTs; RGA (Roh 2011) and YATA (Nicolaescu 2016) gave practical sequence CRDTs; Yjs and Automerge demonstrated sub-millisecond integration. This project builds that lineage end-to-end.
  • Production art: Figma's multiplayer (room/fan-out), VS Code Live Share (LSP tunneling over RPC), and Google Docs (OT + server authority) are the production reference points. Building this system closes the gap between paper CRDTs and deployable architecture.
  • Database parallels: Op log + snapshot is structurally identical to WAL + checkpoint in PostgreSQL. Compaction against snapshot mirrors RocksDB level compaction. Engineers who build this gain WAL intuition transferable to database internals.

2.4 Production Engineering Concepts Exercised

  • Append-only durability; fsync-on-flush; torn-write detection via CRC.
  • Backpressure via bounded channels; slow-consumer eviction without deadlock.
  • Clock-based expiry without a global timer: per-item expires_at field checked on access.
  • Admission control: reject join when room is at capacity before allocating any per-member state.
  • Observability: every op carries OpId; convergence divergence detectable via (state_vector, content_hash) pair.
  • Resource isolation: per-workspace actor; one bad workspace cannot starve another.

2.6 Calibration Value

Building this system places an engineer at the intersection of distributed systems theory (CRDT convergence), systems programming (arena allocation, zero-copy I/O), and protocol engineering (LSP, WebSocket, delta sync). Few production systems combine all three. An engineer who finishes Phase 14 can reason about: SEC vs linearizability tradeoffs; when CRDT is preferable to OT; how to design a GC-safe compaction window; how to build a multiplexed LSP layer that survives concurrent document mutations. This is principal-level distributed systems depth.

2.7 What Mastery Looks Like

After completing all phases, the engineer commands the following concrete competencies:

  • CRDT correctness reasoning (Phases 2–3): Can derive the YATA 4-case integration rule from first principles, construct a counterexample showing how a single-origin CRDT permits interleaving (P-H), and prove that origin-pair encoding prevents it. Can extend the algorithm to handle new op types without breaking SEC.
  • Durable system design (Phase 4): Can design an append-only, crash-only storage layer from scratch — choosing CRC framing, fsync batching, and torn-frame truncation — and explain why each alternative (WAL+redo, SQLite, mmap) trades correctness for complexity in this model.
  • Delta sync and causal ordering (Phase 5): Can implement a state-vector delta protocol from scratch, prove it terminates for any partition/reconnect pattern, and design the causal buffer with correct GC semantics so it never leaks or starves.
  • Room actor and backpressure (Phases 7, 13): Can architect a single-owner async actor that serializes all mutations without shared locks, design a bounded-queue fan-out with slow-consumer eviction that guarantees no room stall, and tune the admission policy under production load.
  • Tombstone GC and compaction (Phase 10): Can derive the safe GC predicate (min-SV condition), reason about GC-compaction interaction during partition/reconnect, and write a snapshot-equivalence test that would catch any off-by-one in the replay boundary.
  • LSP position mapping (Phase 11): Can navigate the full UTF-8/UTF-16/CRDT-OpId three-way position translation, design a mirror that stays consistent under concurrent CRDT ops from multiple sites, and build supervision logic that restores LS state correctly after a crash.
  • Convergence verification at scale (Phase 14): Can design a property-based fuzz harness that exercises SEC under arbitrary partitions, write the content-hash-based divergence probe, and map a failing seed to the exact integration-rule branch that caused it.

3.2 Subsystem Responsibilities

lcide-net — The transport boundary. Accepts raw WebSocket connections; performs Hello/AuthOk handshake with token validation; encodes/decodes SyncMessage as length-prefixed frames (little-endian u32 length + payload). Maintains a per-connection bounded mpsc send queue; if the queue is full, the connection is considered a slow consumer. Routes inbound messages to the correct lcide-session room actor by WorkspaceId. Owns ping/pong liveness; emits Bye on clean close. Trust boundary: all data from the wire is untrusted until AuthOk; post-auth, SiteId is attested by the server (not client-claimed). Concurrency: one tokio task per connection for reads; writes from room fan-out via queue. No persistence.

lcide-session — The room actor. One tokio task per active workspace. Owns the authoritative SessionRoom struct: members, order_clock (Lamport), per-member send queues. Serializes all inbound ops: assigns monotonically increasing delivery Lamport; forwards to lcide-doc for integration; fans out to all other members via their send queues. Manages join/leave lifecycle: on join, triggers state-vector catch-up via lcide-sync; on leave, removes member and notifies remaining peers. Applies backpressure: if a member's queue is full, drops that member rather than stalling the room. Does not interpret op content — CRDT convergence is lcide-crdt's responsibility. Persistence boundary: delegates durability to lcide-persist after integration.

lcide-sync — The delta sync engine. Implements state-vector diff: given sv_mine and sv_peer, computes the set of ops peer is missing per site. Ships Delta(Vec<TextOp>). Maintains a causal buffer: holds an op whose origin_left/origin_right are not yet integrated; releases it when dependencies arrive. Manages catch-up on join: new member sends its StateVector; room responds with full delta. Handles Ack tracking and retransmit on timeout. Idempotency: re-applying a known op (identified by OpId) is a no-op (I5).

lcide-presence — Ephemeral awareness only. Receives AwarenessState from clients; broadcasts to all other room members; never writes to op log or snapshot (I7). Maintains per-client expires_at; on expiry or disconnect, broadcasts a tombstoned AwarenessState to clear the peer's cursor. Follow-mode: when client A follows client B, server forwards B's viewport changes to A. No causal ordering required; last-write wins per client.

lcide-workspace — The filesystem CRDT. Owns WorkspaceTree: a forest of FileNode items, each with LWW name_reg and parent register. Create, delete, rename, move are all CRDT ops serialized as FsCrdtOp, sent on the same SyncMessage channel. Concurrent-move cycle resolution: if two sites independently move A into B and B into A, the resolver canonically picks one (by OpId ordering) to win; the other becomes a no-op. Deleting a directory tombstones the full subtree. Maintains a path-string index for fast path → DocId lookup. Binds a DocId to each file node on creation.

lcide-doc / lcide-crdt — The document layer. lcide-crdt owns the sequence CRDT: Item arena, id→position index, YATA integration ordering, tombstone flags. lcide-doc wraps it as Document: translates (line,col) offsets to CRDT neighbor ids, emits TextOp, integrates remote TextOp, materializes UTF-8 text (pure function of item set — I6, I9). Maintains per-doc StateVector, undo_stack, redo_stack. No I/O; pure computation. The critical invariant: materialize(items) is deterministic regardless of integration order (I1, P9).

lcide-persist — Durability. Appends OpLogEntry frames (length + CRC + versioned payload) to per-doc op log files. Periodically writes Snapshot (materialized items + state vector + taken_at_op). On startup, loads nearest snapshot then replays tail — result must equal full-log replay (I9). Torn last frame (server killed mid-write) detected by CRC failure; truncated to last intact frame (P11). Stores workspace metadata (tree.meta). Provides recover_workspace(id) returning (WorkspaceTree, Map<DocId, Document>).

lcide-lsp — The LSP multiplexer. Spawns one language-server process per (workspace, language) pair via stdin/stdout pipes. Maintains a shadow Document copy per LSP client (the LS does not speak CRDT). On each integrated TextOp, generates a textDocument/didChange notification with incremental edits translated from CRDT position to LSP (line,col). Routes completion/hover requests from a specific client to the LS with that client's CRDT-mapped position. Fans diagnostics (publishDiagnostics) back to all members. Supervises LS process: crash → respawn → re-sync full document state.

lcide-server — The wiring binary. Reads config; initializes lcide-persist store directories; starts lcide-net listener; spawns lcide-session actors per workspace on first join; registers shutdown signal handler; flushes in-flight logs on graceful stop. Multi-workspace isolation: each SessionRoom is independent; a panic in one room does not tear down others (task supervision boundary).

lcide-cli — Headless test and operations client. serve: launches server inline. join: connects as a client, prints received ops. edit-script: replays a file of timed edit operations (for deterministic latency benchmarking). dump: prints op log or snapshot in human-readable form. bench: spawns N concurrent clients with randomized edits, reports convergence time and p99 fan-out latency.

6. Design Principles

The twelve principles below are normative. Each section: states the principle precisely, identifies its tradeoff, gives operational guidance for implementation, and describes the system failure that results from violation. Reference principles by P-number throughout all phases and ADRs.

P1. Strong Eventual Consistency

Principle: Any two sites that have received the same set of TextOps and FsCrdtOps — regardless of delivery order — produce byte-identical materialized text, identical StateVectors, and an identical workspace tree.

  • Formal statement: ops_A = ops_B ⟹ materialize(A) = materialize(B) ∧ sv(A) = sv(B).
  • Tradeoff: Convergence without coordination means no global lock, no round-trip before a keystroke is recorded locally. Accept temporary divergence between peers (read-your-own-writes only). Users see each other's edits with network-bounded delay.
  • Operational implications:
    • materialize() is a pure function of the item set (see P9 for determinism requirement).
    • Every integration rule in lcide-crdt is deterministic given only Item fields — no external state.
    • Integration tests permute delivery order across all (n! or a sampled subset) orderings and assert identical output.
    • Phase 14 convergence fuzz: spawn N SiteIds, generate random TextOp streams with random partition/heal cycles, assert blake3(materialize(site_i)) = blake3(materialize(site_j)) for all pairs after partition heal.
  • Violation consequence: Two clients diverge permanently (split-brain). Users see different file contents for the same DocId. The LSP multiplexer receives inconsistent mirror documents and emits diagnostics referencing wrong line numbers. Recovery requires a full re-sync from a server snapshot — all unsaved local edits from the divergence period are lost.
  • Enforcement loci: lcide-crdt integration ordering; lcide-doc materialize(); Phase 14 convergence fuzz (N sites, random partitions, assert I1).

P2. Intention Preservation

Principle: A user's insert lands between the logical neighbours they observed at edit time. origin_left and origin_right in the Item encode that intent. The YATA integration rule resolves concurrency without ever placing an insert outside the observed neighbourhood.

  • Formal statement: If site S inserts character c between Items L and R at local time t, then in every converged state, c appears between L and R (or between them and items inserted concurrently from the same site, but never on the far side of either).
  • Tradeoff: Storing two neighbour OpIds per Item costs ~16 extra bytes per character versus a single predecessor. Sequence CRDTs with a single predecessor (WOOT, naive RGA) suffer interleaving anomalies under specific concurrent patterns (P-H). The 16-byte cost is justified by the no-interleaving guarantee.
  • Operational implications:
    • On local insert at (line, col): resolve the Item boundary using lcide-doc::position_to_boundary(line, col) -> (Option<OpId>, Option<OpId>); store as origin_left and origin_right in the emitted TextOp::Insert.
    • Never store raw byte offsets in TextOp; offsets become stale the moment any concurrent insert is integrated.
    • YATA 4-case integration rule (from P-C) determines placement of concurrent inserts with overlapping origins:
      1. If op.origin_left ≠ scan.origin_left → use origin_left ordering to place.
      2. If site IDs differ → place by SiteId order (deterministic tiebreak).
      3. If op.origin_right differs → use origin_right to disambiguate.
      4. Equal origins, equal sites → impossible (OpId globally unique).
  • Violation consequence: Concurrent inserts at the same logical position interleave characters. "AB" from site A and "CD" from site B converge to "ACBD" instead of "ABCD" or "CDAB". Users see corrupted tokens; language-server parse errors cascade from the corruption.
  • Enforcement loci: lcide-crdt 4-case YATA integration rule; Phase 2 concurrent-insert regression tests; Phase 14 fuzz with interleaving-detection assertion (scan materialized text for interleaved known substrings).

P3. Server Orders, CRDT Decides Content

Principle: The room actor in lcide-session assigns a monotonic Lamport order_clock for fan-out sequencing and durable log ordering. Document content is determined solely by the CRDT item set — never by the server arbitrating which concurrent edit wins.

  • Contrast with OT: In OT-Jupiter, the server transforms and potentially discards a client op if it conflicts. Here the server only sequences; the CRDT ensures all ops survive and converge.
  • Tradeoff: The server cannot "simplify" conflicts by last-write-wins. All concurrent inserts appear in the converged document. For malicious or accidental spam, rate-limiting is applied at the session boundary before ops are logged (Phase 13).
  • Operational implications:
    • Room actor critical path: receive SyncMessage::Delta(ops) → validate ACL (I10) → assign order_clock per op → write OpLogEntry to lcide-persist → fan-out SyncMessage::Delta(ops) to all members.
    • No merge, no transform, no conflict detection in this path.
    • order_clock (Lamport) appears in OpLogEntry for crash-recovery ordering only; it is not stored in Item and does not influence materialize().
    • lcide-doc's integrate() is called after fan-out, not before — the room does not integrate on behalf of clients.
  • Violation consequence: If the server drops a losing concurrent insert, one user's keystrokes vanish with no error signal. Data loss is silent and non-recoverable after the client's offline buffer is purged.
  • Enforcement loci: lcide-session has no merge/arbitrate path; all integration logic is in lcide-crdt and lcide-doc; audit that lcide-session's op-intake loop has zero content-decision branches; static analysis: grep -r 'integrate\|merge\|conflict' lcide-session/src/ should return zero hits in the hot path.

P4. Ephemeral vs Durable Separation

Principle: AwarenessState (cursors, selections, follow-mode, viewport, color, expiry timestamp) is never written to the op log or a snapshot. Only TextOps and FsCrdtOps are durable. The two data classes flow through different code paths and are tested separately.

  • Formal statement: ∀ entry ∈ op_log, entry.type ∈ {TextOp, FsCrdtOp} (I7).
  • Tradeoff: Presence cannot be reconstructed after a reconnect; clients re-broadcast their AwarenessState on join. This is intentional: a stale cursor position from five minutes ago is more confusing than no cursor. Clock-based expiry handles graceful disappearance.
  • Operational implications: lcide-session routes incoming SyncMessage::Awareness(...) to the presence broadcast path before any persist call. lcide-persist has no awareness write API at the type level — the compiler enforces the separation.
  • Violation consequence: Op log inflates with per-keystroke cursor updates (potentially 10× document-op volume). Snapshot/restore resurrects stale cursors with wrong timestamps. Clock-based expiry in lcide-presence is defeated by replayed history.
  • Enforcement loci: I7 invariant; lcide-persist schema (no awareness field); integration tests assert that no AwarenessState frame type byte ever appears in the op log file.

P5. Causal Delivery

Principle: An op is integrated into a document only after its causal predecessors (origin_left, origin_right, and for FsCrdtOps their parent node) are already present. Out-of-order arrivals are held in the causal buffer in lcide-sync until all origins are integrated.

  • Formal statement: Integrate(op) is called only when ∀ dep ∈ deps(op), dep ∈ integrated_set.
  • Tradeoff: Causal buffering adds per-connection memory (bounded by max_causal_buffer) and latency for ops that arrive before their predecessors. In a server-fan-out topology, out-of-order delivery is rare but must be handled for correctness under network jitter and reconnect scenarios.
  • Operational implications: On receive: check origin_left ∈ arena ∧ origin_right ∈ arena. If false, enqueue in the causal buffer keyed by missing OpIds. After each successful integration, drain the causal buffer (re-check all buffered ops). Bounded buffer: if full, request a catch-up delta from server.
  • Violation consequence: An insert integrated with a dangling origin_left reference produces undefined sequence position. The YATA 4-case rule references Item pointers that do not exist; behavior is undefined. Convergence breaks silently.
  • Enforcement loci: I3 invariant; lcide-sync can_integrate() predicate; Phase 5 causal delivery tests with synthetic out-of-order delivery.

P6. Bounded Memory

Principle: Tombstones and op-log history are garbage-collected once an op's OpId falls below min_sv = ∩ {sv(site) : site ∈ all_connected_sites}. A workspace running for months must not grow without bound in RAM or on disk.

  • Formal GC condition: can_gc(op_id) = ∀ connected_site s, sv(s)[op_id.site] ≥ op_id.seq.
  • Tradeoff: GC requires periodic global state-vector minimum computation. Offline members block GC until they reconnect or are evicted by a server-side TTL policy. Configuring a max-offline-member TTL trades GC aggressiveness against risk of data loss for long-absent clients.
  • Operational implications:
    • Room actor tracks min_sv by intersecting all member state vectors; updated on every Ack and on member join/leave.
    • lcide-crdt exposes gc_below(threshold: StateVector) -> usize (returns count of removed Items).
    • lcide-persist exposes compact(snapshot_sv: StateVector): writes a new Snapshot, then truncates op log entries where entry.op_id ≤ threshold.
    • GC is scheduled during quiescent periods (configurable idle timeout after last op). Never during active editing bursts.
    • Memory invariant: RSS(workspace) = O(live_chars + pending_tombstones_above_min_sv); tombstones below min_sv are removed.
  • Violation consequence: A long-lived document accumulates O(total-edits) tombstones regardless of current document size. Materialization slows (tombstone scan dominates the item array). Eventually OOM or disk exhaustion in production.
  • Enforcement loci: Phase 10; I4 (tombstones permanent pre-GC, absent post-GC); lcide-cli bench subcommand reporting RSS growth over a synthetic 24-hour long-running workload with GC enabled and disabled.

P7. Backpressure Everywhere

Principle: Every async send path uses a bounded channel. A slow consumer's queue filling causes the slow consumer to be throttled then evicted — never the room loop, other consumers, or the persist path.

  • Formal statement: ∀ send_queue q, capacity(q) = SEND_QUEUE_CAPACITY (const); try_send is used in fan-out; await on a member's channel is never held inside the room lock.
  • Tradeoff: Dropping or evicting a slow client is disruptive. The alternative (unbounded queue) is silent OOM. Bounded queues surface the failure at a known, configurable threshold.
  • Operational implications: Fan-out loop uses try_send for each member. On Err(Full): increment slow_consumer.queue_full metric, mark member for grace-period drain (configurable). After grace period, evict: close connection, remove from room. Never await send inside the fan-out loop.
  • Violation consequence: One client on a slow mobile link causes the room actor to stall. All other clients stop receiving updates. Effectively a denial-of-service by any single poorly-connected participant.
  • Enforcement loci: Phase 7 slow-consumer integration test (one client with artificially throttled read, assert other clients continue unaffected); Phase 13 admission and eviction; tokio bounded mpsc throughout lcide-net and lcide-session.

P8. Offline-First Convergence

Principle: A client edits while partitioned from the server. On reconnect it exchanges StateVectors, pushes local missing ops as a delta, and pulls server missing ops as a delta. After exchange both are fully synced regardless of partition duration.

  • Formal protocol:
    1. Client sends SyncMessage::SvRequest(local_sv) on reconnect.
    2. Server computes missing_for_client = {op : op ∈ server_log ∧ op.id ∉ local_sv} → sends SyncMessage::Delta(missing_for_client).
    3. Client computes missing_for_server = {op : op ∈ unacked_ops ∧ op.id ∉ server_sv} → sends SyncMessage::Delta(missing_for_server).
    4. Both sides drain causal buffers; convergence holds by I1 and I5 (idempotent re-apply).
  • Tradeoff: The client buffers all locally emitted ops since the last acked seq. Buffer bounded by max_offline_ops (configurable, default 50,000). If exceeded, the client falls back to a full state-based re-sync (more expensive but safe and rare).
  • Operational implications:
    • lcide-sync client maintains unacked_ops: VecDeque<TextOp>; ops retired only on SyncMessage::Ack { up_to_seq }.
    • Reconnect trigger: TCP connection drop or WebSocket close code; lcide-net signals reconnect to lcide-sync via a channel.
    • Exponential backoff on reconnect: 100 ms → 200 ms → 400 ms → … → 30 s max; jitter to avoid thundering herd.
  • Violation consequence: If the client discards local ops on disconnect, those edits are permanently lost (data loss, no user-visible error). If the server discards the reconnecting client's ops, the client's work vanishes silently after the unacked buffer is garbage-collected on the next GC pass.
  • Enforcement loci: Phase 12; I1 convergence after partition; integration test: generate 1000 ops offline across two clients with different offline histories, reconnect both, assert materialize(A) = materialize(B).

P9. Determinism of Materialization

Principle: materialize(item_set) -> String is a pure function of the integrated item set. No wall-clock, no random seed, no hashmap iteration order, no server-arrival sequence influences the rendered document bytes.

  • Formal statement: materialize is injective on converged item sets; equal item sets produce equal byte strings, always.
  • Tradeoff: Rust's default HashMap uses a random seed (SipHash with runtime-seeded state). Do not use HashMap for any iteration that feeds materialize(). Use IndexMap or sort-stable structures, or iterate the CRDT sequence order directly.
  • Operational implications: The materialization pass iterates Items in CRDT sequence order (left-to-right by integration position, determined by origin pair rules), skipping tombstones. The sequence order derives only from integration rules applied to Item fields — never from insertion order into any hash structure.
  • Violation consequence: Two sites with identical op-sets produce different text. Looks like a convergence failure; the state vectors match but content hashes differ. False divergence alarms fire; the divergence cannot be explained by missing ops; debugging is extremely difficult.
  • Enforcement loci: I6 coordinate soundness; I1 convergence; unit tests comparing materialize() output across every permutation of a small op set; #[cfg(test)] harness that seeds with different random inputs and asserts identical output.

P10. Observability by Default

Principle: Every op carries its OpId (site + seq). Every fan-out event, document state transition, and causal-buffer drain is emitted as a structured log entry tagged with the OpId. Convergence divergence is detectable by comparing StateVectors and a BLAKE3 content hash between any two peers.

  • Key metrics: room.op.applied { op_id, doc_id, site, seq, latency_us }; sync.delta_sent { doc_id, client_id, op_count }; crdt.tombstone_gc_count { doc_id, removed }; client.sv_hash { doc_id, sv_fingerprint, content_hash }.
  • Tradeoff: Structured per-op logging increases log volume at high op rates. Mitigate with sampling at steady-state (configurable sample rate); full logging only in debug or after a convergence alarm.
  • Operational implications: lcide-cli implements dump --doc-id X to print materialized text, dump --sv to print StateVector, and hash-doc to print BLAKE3 content hash. Mismatch between two clients' content hashes while state vectors agree is an I1 violation; auto-alarm and trigger reconcile.
  • Violation consequence: A silent convergence bug goes undetected for hours. Users report "my text looks different from yours" but there is no diagnostic path. Debugging requires full log replay from scratch, which may take O(hours) for a large workspace.
  • Enforcement loci: Phase 14 conformance tests compare content hashes across N sites; operational runbook includes hash-doc + dump-sv as first-line diagnostic commands.

P11. Crash-Only Persistence

Principle: The op log is append-only and the server is assumed to be killed with SIGKILL at any moment. Recovery procedure: open log, scan forward, stop at first frame failing CRC, truncate there, load nearest snapshot, replay log tail. No graceful shutdown required for correctness.

  • Frame layout (normative):
| u32 total_len | u8 version | u64 doc_id | u64 server_seq | u32 payload_len | payload_bytes | u32 crc32c |
  ^--- includes all fields up to but not including crc32c field
  • Tradeoff: A torn last frame (SIGKILL mid-write) causes at most one op to be lost. That op will be retransmitted by the client on reconnect (unacked buffer, P8). The CRDT is idempotent on re-application (I5), so no corruption results from re-apply.
  • Operational implications:
    • scan_log(path) -> Result<LogBoundary>: reads frames sequentially; stops and returns last_good_offset at first CRC mismatch; truncates file to last_good_offset.
    • Snapshot writer: write_snapshot(doc) -> Result<SnapshotId>; after write, verify CRC of written bytes before atomically updating snapshots/latest pointer.
    • Recovery entry point: recover_workspace(workspace_id) -> Document: loads nearest snapshot, replays from snap.taken_at_op to end of valid log.
    • Invariant: log.fsync() is called after every OpLogEntry write; O_DIRECT or equivalent is considered for durability at the cost of write amplification.
  • Violation consequence: A partial write that is not detected (missing CRC check) corrupts all subsequent log reads. The server serves a document that has permanently diverged from the actual op history. Clients on different reconnect paths see different content with no alarm.
  • Enforcement loci: I9 snapshot fidelity; Phase 4 crash-recovery test (truncate log at random byte offset, assert clean recovery produces a valid document); Phase 14 op-log fuzz reader (random truncation and bit-flip corruption patterns).

P12. Fail-Closed Authorization

Principle: Every connection presents a valid token before joining a room; every mutating op is checked against the caller's AclLevel before integration. Absence of a decision — auth backend unreachable, ACL entry missing — resolves to deny, never to allow.

  • Formal statement: ∀ conn, joined(conn) ⟹ verify(conn.token) = Ok(principal); ∀ op ∈ {TextOp, FsCrdtOp}, integrate(op) ⟹ acl(op.site) = Write.
  • Tradeoff: Fail-closed means a misconfigured or crashed auth backend blocks all new connections rather than admitting unauthenticated clients — availability is sacrificed for confidentiality/integrity. Existing authenticated sessions are unaffected: ACL is checked at connection time and cached in Member.acl, not re-verified against the auth backend on every op.
  • Operational implications: AuthService::verify returns Result, never a default-allow; a missing AclEntry defaults to AclLevel::None, not Write; ACL hot-reload swaps the table via ArcSwap so no window exists where a stale grant is read after revocation is committed.
  • Violation consequence: A default-allow bug or a race in ACL hot-reload lets a revoked or unauthenticated client mutate a workspace; the resulting ops are durable in the op log and can only be undone by manual forensic replay, not by re-checking auth after the fact.
  • Enforcement loci: I10 invariant; lcide-net handshake and lcide-session pre-integration ACL check (Phase 13); test_auth_reject_invalid_token and test_readonly_member_op_rejected fixtures.

8.3.1 SyncMessage Wire Frame (lcide-net)

+--------+----------+-------------------+
| u32 BE | u8 type  | payload bytes...  |
| length | tag      | (bincode encoded) |
+--------+----------+-------------------+
  • Length prefix includes type byte but not itself.
  • Maximum frame: 4 MiB; frames exceeding this trigger protocol error + Bye.
  • Type tags: 0x01 Hello, 0x02 AuthOk, 0x03 SvRequest, 0x04 Delta, 0x05 Awareness, 0x06 FsOp, 0x07 LspMsg, 0x08 Ack, 0x09 Bye, 0xFF ProtocolError.

| 4 bytes| 1 byte | seq    | doc_id | payload  | TextOp | CRC32  |
|        |        |        |        | length   |        |        |
+--------+--------+--------+--------+----------+--...--+--------+

8.3.5 TextOp Serialization (bincode, little-endian)

Insert = tag(0) ++ OpId(site:u64,seq:u64) ++ Lamport(u64)
       ++ origin_left(Option<OpId>) ++ origin_right(Option<OpId>)
       ++ char(u32 Unicode scalar)
Delete = tag(1) ++ target_id(OpId)

Option<OpId>: None = 0x00 byte; Some = 0x01 ++ OpId.

8.4 CRDT Integration Semantics (YATA)

8.4.1 Integration Ordering Rules

For a new Item N being inserted between origin_left L and origin_right R:

precondition: L and R are already integrated (I3)
candidates: all Items with same (origin_left, origin_right) not yet ordered relative to N
sort key (ascending): (Lamport, SiteId)  — deterministic tie-break
N inserted after last candidate with lower sort key

Invariant I1: any permutation of inserts with same op-set yields identical item sequence.

8.4.2 Item Arena Layout

Arena: Vec<Item>  — index is slot; items never moved after allocation
IdMap: HashMap<OpId, usize>  — id -> slot
PosList: SkipList<usize>  — ordered by integration position, excludes tombstones for offset math

Insert: O(log n) via skip-list find + integrate; Delete: O(1) id lookup + tombstone flag set.

8.4.3 Position Mapping (offset <-> OpId)

offset_to_item(n): walk PosList skipping tombstones; nth live item -> OpId  O(log n)
item_to_offset(id): PosList rank of id among live items  O(log n)

Invariant I6: mapping is a pure function of item set; no wall-clock or delivery order dependency.

8.5 StateVector Semantics

StateVector = HashMap<SiteId, u64>
  -- value = highest contiguous seq received from that site
  -- missing SiteId => 0 (no ops from that site seen)

merge(a, b) -> StateVector:
  union of keys; value = max(a[k], b[k])

is_ready(sv, op: OpId) -> bool:
  sv.get(op.site).unwrap_or(0) >= op.seq - 1
  AND all origins of op have seq <= sv[their site]

missing_ops(have: StateVector, full_log) -> Vec<TextOp>:
  for each op in log: if op.id.seq > have[op.id.site] -> include

Delta computation is O(log N) with a per-site sorted op index.

8.7 Causal Buffer Semantics

struct CausalBuffer {
  pending: HashMap<OpId, (TextOp, Instant)>,  -- buffered ops awaiting origins
  deadline: Duration,                          -- default 10 s; then error
}

on_recv(op):
  if is_ready(sv, op) -> integrate immediately, drain buffer
  else -> insert into pending
  prune entries older than deadline -> emit CausalError(op_id) to session log

Draining: after each successful integration, re-check all pending ops whose origins include the just-integrated id.

8.8 Awareness / Presence Model

AwarenessState {
  client: ClientId,
  site: SiteId,
  doc: DocId,
  cursor: Position,       -- (line, col) rebased through CRDT on each remote op
  selection: Range,       -- (start, end) both rebased
  viewport: Range,        -- informational; not rebased (coarse scroll position)
  color: u32,             -- ARGB assigned by server on join
  expires_at: Instant,    -- now + 30 s; refreshed on each Awareness message from client
}
  • Broadcast path: client -> lcide-net -> lcide-session -> lcide-presence -> fan-out to all members.
  • Never enters op log (I7); lost on server restart; clients resend on reconnect.
  • Cursor rebase: on receiving a remote Insert at position P < cursor.col on same line -> cursor.col += 1; on Delete at P < cursor.col -> cursor.col -= 1 (clamped to 0). Range rebased independently on each endpoint.
  • Follow-mode: server sets a member's viewport = followed peer's viewport on each Awareness update from the followed peer; client opt-in flag in AwarenessState.

8.9 FileSystem CRDT (WorkspaceTree)

8.9.1 FileNode and LWW Registers

FileNode {
  id: OpId,                       -- creation op; stable identity
  kind: File | Dir,               -- immutable after creation
  name_reg: LWWReg<String>,       -- last-write-wins by Lamport; concurrent = higher SiteId wins
  parent_reg: LWWReg<OpId>,       -- LWW parent directory id
  doc: Option<DocId>,             -- Some for File kind; None for Dir
  deleted: bool,                  -- tombstone; monotone
}
LWWReg<T> { value: T, lamport: Lamport, site: SiteId }
merge(a, b) -> LWWReg<T>: if a.lamport > b.lamport -> a; elif b.lamport > a.lamport -> b; else max(a.site, b.site)

8.9.2 Concurrent Move Cycle Resolution

problem: A moves dir X into Y while B moves Y into X -> cycle
detection: after applying parent_reg update, BFS from moved node; if ancestor chain includes self -> cycle
resolution: reject the lower-Lamport move (revert parent_reg to prior value); if equal Lamport, reject lower SiteId

Invariant I8: resolver runs before path index update; path index never holds a cyclic reference.

8.9.3 Subtree Tombstone Propagation

delete_subtree(node): set node.deleted = true, then tombstone every child of node via DFS over children(node.id), recursing into each; every descendant deletion is emitted as its own FsCrdtOp(Delete).

FsCrdtOp stream on same sync channel as TextOp; ordered by Lamport; applied in causal order.

8.10 Undo / Redo Semantics

  • Per-site selective undo: inverts only ops from this site that are within the undo window.
  • Undo of Insert(id, ...) -> generates Delete(target: id) as a new op with a fresh OpId.
  • Undo of Delete(target) -> generates Insert(id: fresh, ..., content: original_char) with same origin neighbors.
  • Undo op is a regular TextOp; appended to log; broadcast as Delta; other sites integrate it normally.
  • Undo stack: Vec<OpId> of local ops in emission order; redo stack: Vec<(undo_op_id, original_op_id)>.
  • Undo across a remote concurrent insert: the new Insert's neighbors are unchanged; the undo lands at the original boundary, not displaced (intention preservation P2).
  • Undo window: configurable (default 200 local ops); ops below window are compaction-eligible.

8.11 LSP Position Mapping

LSP uses (line, character) with character = UTF-16 code unit offset.
CRDT uses (line, col) with col = Unicode scalar offset.
Mapping:
  crdt_to_lsp(pos): re-walk the line's items, count UTF-16 units up to scalar offset
  lsp_to_crdt(pos): re-walk the line's items, count scalars up to UTF-16 offset

LS document mirror (lcide-lsp):

on TextOp received:
  convert to LSP TextDocumentContentChangeEvent { range, text }
  send textDocument/didChange to LS process stdin
  update mirror_sv[doc_id] = op.id
on completion request from ClientId:
  translate client's CRDT position -> LSP position
  send textDocument/completion to LS
  receive response; translate LSP positions back to CRDT positions
  send LspMsg(completion_resp) to requesting ClientId only
on publishDiagnostics from LS:
  translate all LSP positions -> CRDT positions
  fan-out to all members of workspace

LS crash supervision: lcide-lsp holds a JoinHandle per LS process; on exit, log + restart with back-off (1 s, 2 s, 4 s, cap 30 s); mirror rebuilt from current Document materialization after restart.

8.12 Tombstone GC and Op-Log Compaction

gc_eligible(item: Item) -> bool:
  item.deleted
  AND for all peer_sv in known_state_vectors: peer_sv[item.id.site] >= item.id.seq

compaction_trigger: op_count > COMPACTION_THRESHOLD (default 50_000) OR wall timer (default 1 h)
compaction steps:
  1. take Snapshot of current Document state
  2. write Snapshot to disk; fsync
  3. rewrite oplog omitting all ops whose items are gc_eligible
  4. atomic rename tmp log -> live log
  5. update in-memory op index

Bounded memory invariant (P6, I4): after GC, no tombstoned Item with seq below all peers' SVs remains in arena.

8.13 Worked Example — Concurrent Insert Convergence

Initial doc: "ac"  (items: [a:site1/seq1, c:site1/seq2])

Site 1 inserts 'b' between 'a' and 'c':
  op_B = Insert { id:{site:1,seq:3}, origin_left:{1,1}, origin_right:{1,2}, ch:'b', lamport:5 }

Site 2 inserts 'x' between 'a' and 'c' concurrently:
  op_X = Insert { id:{site:2,seq:1}, origin_left:{1,1}, origin_right:{1,2}, ch:'x', lamport:5 }

Both sites receive both ops.
Integration at Site 1 (already has op_B, receives op_X):
  candidates with same (origin_left, origin_right): {op_B, op_X}
  sort by (Lamport, SiteId): both Lamport=5; SiteId 1 < 2 -> op_B first, op_X after
  result: "abxc"

Integration at Site 2 (has op_X, receives op_B):
  same sort: op_B (site 1) before op_X (site 2)
  result: "abxc"

Both sites converge to "abxc". I1 satisfied.

8.14 Failure-Path Example — Causal Buffer Overflow

Site 1 emits op_A (seq=10) and op_B (seq=11, origin_left=op_A).
Network reorders: site 2 receives op_B before op_A.
CausalBuffer at site 2: op_B buffered (is_ready returns false).
  -- if op_A arrives within deadline: buffer drains, integration proceeds normally.
  -- if op_A never arrives (deadline exceeded):
       CausalBuffer logs CausalError(op_B.id, "origin timeout")
       Session room emits SessionEvent::CausalTimeout to operator metrics
       op_B dropped; site 2 requests full SvRequest -> server retransmits missing ops
       Reconnection path (Phase 12) handles re-convergence.

8.15 Edge Cases

Edge Case Handling
Insert with origin_left == origin_right (zero-width) Both point to same Item; integration treats as left-only; right is re-anchored post-insert
Delete of already-tombstoned Item No-op; idempotent (I5)
StateVector entry for unknown SiteId on Delta recv Accept; add SiteId to SV with seq from op
Snapshot CRC mismatch Skip to next-highest snap; if none, replay full log from empty
Concurrent rename + delete of same FileNode Delete wins if deleted.lamport >= rename.lamport; else rename then delete on next propagation
Empty doc (no items) StateVector has no entries; materialize returns empty string; valid initial state
SiteId collision on new client assign Server assigns SiteId via atomic counter (u64); collision impossible in practice; enforce uniqueness in meta.json
LS process produces positions beyond doc end Clamp to (last_line, last_col); log warning; do not crash fan-out
Client sends op with seq gap (seq=5, SV shows 3) CausalBuffer holds; SvRequest triggers retransmit of seq=4
Room actor task panic tokio::spawn with catch_unwind wrapper; FAULTED state; recover from snapshot
Backpressure: client send queue full Drop connection (Bye); client enters RECONNECTING; I7 preserved (no lost durable ops — they are in log)

11.1 lcide-core

OpId

#[derive(Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub struct OpId { pub site: SiteId, pub seq: u64 }
  • Ordering: lexicographic (seq, site) — higher seq is later; site breaks ties deterministically.
  • Invariant I2: site.seq increases by 1 per emitted op; no gaps allowed in contiguous SV entry.
  • Serialized as (u64, u64) varint pair on wire and in op log.
  • OpId::ROOT = OpId { site: SiteId(0), seq: 0 } — sentinel for item origins before first op.

Lamport

pub struct Lamport(pub u64);
impl Lamport {
    pub fn tick(&mut self) -> Lamport;          // self += 1; return new value
    pub fn merge(&mut self, other: Lamport);    // self = max(self, other) + 1
}
  • Copy. Monotone. Used by SessionRoom.order_clock and Item.lamport for tie-breaking.
  • Never used for wall-clock time. Never persisted as a causality source (SV is the causal summary).

StateVector

pub struct StateVector(BTreeMap<SiteId, u64>);
impl StateVector {
    pub fn observe(&mut self, id: OpId);
    pub fn get(&self, site: SiteId) -> u64;
    pub fn merge(&mut self, other: &StateVector);
    pub fn diff<'a>(&'a self, other: &'a StateVector) -> impl Iterator<Item=(SiteId,u64,u64)> + 'a;
    pub fn dominates(&self, other: &StateVector) -> bool;
}
  • Owned; cloned for transmission; mutated only inside room actor (single writer per workspace).
  • diff yields (site, self_seq, other_seq) for sites where they differ — drives delta computation.
  • dominates(other) iff ∀ site: self.get(site) >= other.get(site).
  • Serialized: sorted [(SiteId, u64)] varint list; compatible across versions by sorted-merge.

1.6 Pitfalls

  • Contiguous-only SV gap rejection causes silent buffering loops: if the sync layer never delivers the gap-filling op, the receiver stalls. Signal: SeqGap count metric rising without bound. Debug: log (site, expected_seq, received_seq) on every gap.
  • OpId sentinel collision: INVALID = OpId { site: SiteId(0), seq: 0 } — must never be assigned to a real op. Enforce: server starts site-id allocation at 1.
  • Lamport overflow at u64::MAX: tick() must saturate or panic loudly, not wrap silently. Use checked_add(1).expect(...).
  • HashMap iteration order in StateVector merge: merge must produce identical output regardless of insertion order. Use sorted iteration in tests.
  • VersionCmp::Equal vs Concurrent: two SVs are equal only when every site entry matches; concurrent when neither dominates. Off-by-one in dominates logic produces false-concurrent reads.

1.7 Performance Concerns

  • StateVector clone is O(sites) — keep SiteId count bounded (< 1024 per workspace) to avoid hot-path allocations.
  • OpId is 16 bytes (two u64s); keep it Copy to avoid heap allocation in per-op paths.
  • missing_seqs allocates a Vec — call only on join/catch-up, never on every op.
  • Avoid HashMap::clone in the fan-out hot path; use Arc<StateVector> where shared immutably.

1.8 Edge Cases

  • SiteId(0) is the INVALID sentinel; server must reject any client claiming it.
  • seq wraps at u64::MAX — defined as a hard error, not silent wrap.
  • Empty StateVector (no known sites): dominates({}) is true for any non-empty SV; {} dominates {} is Equal.
  • Two sites with identical SiteId values: impossible by server assignment contract, but must be caught at session-join time.
  • Lamport skew: witness value from a misbehaving client much larger than server's clock — cap witness input at server_lamport + MAX_SKEW (configured, default 2^32).

YATA integration algorithm (describe, not code):

  1. Locate the segment [origin_left+1 .. origin_right) in the current sequence order.
  2. Within that segment, find the correct insertion point by scanning concurrent items: an item u is a "conflicting" item if its origin_left is dominated by the new item's origin_left and its origin_right dominates the new item's origin_right.
  3. Among conflicting items, order by (OpId.site, OpId.seq) for determinism (Lamport as secondary tie-break).
  4. Insert new item at the resolved position in IndexedList.
  5. Update id_index in Arena.
  6. Return Err(MissingOrigin) if either origin is absent — caller must buffer (P5/I3).

Tombstone: Delete { target: OpId } sets item.deleted = true; item remains in Arena and IndexedList; live_count decrements; materialize() skips tombstoned items.

Idempotency (I5): on integrate, check id_index.contains(op.id()) first; return Ok(()) without side-effects if already present.

2.6 Pitfalls

  • Integration scan over full concurrent segment: worst-case O(n) scan during a burst of concurrent inserts at the same position. Mitigation: bound concurrent-insert batch size; use skip-list or B-tree segment scan.
  • origin_right boundary escape: if origin_right item is later deleted, the segment boundary shifts; tombstones must remain in IndexedList for boundary computation.
  • HashMap id_index probe cost at high item count: at >1M items, HashMap<OpId,usize> exceeds L3 cache. Mitigation: consider Vec-backed sorted array with binary search for cold lookups.
  • char vs byte offset confusion: offset_to_item counts live Char items (Unicode scalar values), not bytes. Callers expecting byte offsets will misindex. Document the contract clearly; add a separate byte_offset_to_item if LSP requires UTF-16 (Phase 11).
  • Concurrent delete of already-deleted item: must be idempotent; second delete must not decrement live_count again.
  • Arena slab index invalidation: Arena uses stable indices (append-only Vec); never remove items, only tombstone them. Compaction (Phase 10) rebuilds a fresh arena.

2.7 Performance Concerns

  • IndexedList live_count tree must support O(log n) prefix-sum for offset queries; a Fenwick tree or augmented B-tree is appropriate.
  • materialize() is O(total items) including tombstones; cache the result and invalidate on each integrate call.
  • Arena Vec<Item> layout: Item is ~64 bytes; 1M items = ~64 MB; keep deleted: bool at the end of the struct to minimize padding.
  • Avoid per-item heap allocation; Content::Char(char) must be inline, not boxed.
  • Batch inserts from a Delta(Vec<TextOp>) message in a single integrate_batch call to amortize index rebuilds.

2.8 Edge Cases

  • Empty sequence: offset_to_item(0) returns None; materialize() returns "".
  • Insert at boundary: origin_left = None (start-of-document) and origin_right = None (end-of-document) are valid.
  • All items tombstoned: live_count = 0; materialize() returns "".
  • OpId with site = SiteId(0) (INVALID sentinel): integrate must reject with Err(InvalidOp).
  • Sequence with 0 live items but non-zero tombstone count: offset_to_item(0) = None, but Arena is non-empty.
  • Unicode surrogate pairs in char: Rust char is a Unicode scalar value, never a surrogate — no special handling needed, but verify roundtrip with multi-byte codepoints (e.g., U+1F600).

3.6 Pitfalls

  • LineIndex stale after remote op: remote ops can insert newlines, invalidating LineIndex without going through apply_local. Always invalidate materialized_cache (and transitively LineIndex) on any apply_remote.
  • Off-by-one in origin_left at line start: col=0 means insert at start of line; offset_to_item(byte_offset - 1) must handle byte_offset = 0 (start of document) as origin_left = None.
  • UTF-16 surrogate pairs inflate col count: LSP uses UTF-16 offsets; a single emoji (U+1F600, 4 UTF-8 bytes, 2 UTF-16 units) shifts all subsequent col values by 1 in UTF-16 vs 3 in UTF-8. Mismatch causes LSP completions at wrong positions.
  • Undo emitting ops with new OpIds: compensating ops must carry fresh OpIds (new seq), not re-use the original's id; otherwise I5 idempotency falsely suppresses them.
  • materialize rebuilds on every read in edit-heavy sessions: cache invalidation on apply_local is correct but rebuild cost is O(items); for high-frequency edits, batch multiple ops before materializing.
  • Multi-byte char insert at col boundary: col is a char index within the line (not a byte index) in the Utf8 encoding variant; document this contract explicitly.

3.7 Performance Concerns

  • LineIndex rebuild is O(materialized text length); for a 1 MB document, this is ~1 ms. Amortize by rebuilding only when LSP or presence queries require it.
  • apply_local must not call materialize() unless LineIndex is stale; add a line_index_valid: bool flag.
  • UndoGroup vec grows unboundedly without Phase 10 GC; pre-Phase 10, cap at 1000 undo groups and log a warning when truncated.
  • apply_remote batch path: lcide-sync delivers Delta(Vec<TextOp>); process all in one loop, then invalidate cache once at the end.
  • StateVector::observe is called per remote op; HashMap insert is O(1) amortized but hot in bulk-catch-up; use entry().and_modify() to avoid double-hashing.

3.8 Edge Cases

  • Position{line: u32::MAX, col: 0}: returns Err(OutOfBounds).

  • lcide-sync/src/causal.rs — CausalBuffer: hold ops whose origins are not yet integrated
  • lcide-sync/src/ack.rs — AckTracker: per-client last-acked seq; retransmit window

State-vector delta algorithm (delta.rs):

  1. For each site in local_sv or remote_sv: compute local_have = local_sv[site], remote_have = remote_sv[site].
  2. If local_have > remote_have: fetch ops with site == site AND seq IN (remote_have+1 ..= local_have) from OpLog.
  3. Collect into Vec<TextOp>, sorted by (site, seq) (causal order within a site guaranteed; cross-site order doesn't matter for correctness).
  4. Return as Delta(ops) message.

SyncMessage flow on join:

Client            Server (lcide-session -> lcide-sync)
  -- Hello(workspace_id, token, client_sv) -->
  <-- AuthOk(site_id, server_sv) --
  -- SvRequest(client_sv) -->
  <-- Delta(missing_ops) --
  -- Ack(last_integrated_seq) -->

Causal buffer (causal.rs):

  • CausalBuffer { pending: VecDeque<TextOp> }
  • On receive: if op.origin_left and op.origin_right present in Document.items -> integrate immediately; else enqueue.
  • After each successful integration: drain buffer (repeatedly attempt pending ops) until stable.
  • Stall detection: if buffer non-empty and no progress for T seconds -> log warning; request full SvRequest from sender.
  • Buffer cap: MAX_CAUSAL_BUFFER (default 4096 ops per peer); exceed -> disconnect that peer (I3 cannot be satisfied).

Ack + retransmit (ack.rs):

  • Server tracks last_acked_seq: HashMap<ClientId, u64>.
  • Client sends Ack(seq) after integrating each batch.
  • Server retransmit: if no Ack for batch within ACK_TIMEOUT_MS (default 5000), resend delta.
  • Idempotent re-apply: Document::integrate_remote checks OpId already in item set (I5); duplicate silently ignored.

Catch-up on join:

  • recover_and_sync(doc_id, client_sv, persist_handle) -> Vec<TextOp>: calls recover_document if doc not in memory, then compute_delta.
  • Large catch-up (>10k ops): stream in chunks of 512 ops to avoid single large allocation.

5.7 Performance Concerns

  • Delta scan iterates op-log; use the frame-offset index from Phase 4 for O(log n) seek per site.
  • Allocate Vec<TextOp> once per delta call; avoid per-op allocations.
  • Causal buffer drain is O(pending^2) in the worst case (each drain scans all pending); use a per-origin-id map to reduce to O(1) lookup.
  • Streaming large catch-up in 512-op chunks avoids holding a giant Vec in the session actor's heap.
  • SvRequest serialization: StateVector is a HashMap<SiteId, u64>; for workspaces with many sites (>100), use sorted Vec<(SiteId,u64)> for deterministic encoding.

5.8 Edge Cases

  • Site in client sv but unknown to server: server has 0 ops for it; delta for that site is empty; server ignores foreign sites in sv.
  • Client seq in sv exceeds server's log: malformed client; reject with Bye(MalformedStateVector).
  • Op with seq = u64::MAX: prevented by I2; treat as invariant violation -> disconnect site.
  • Server restarts mid-catch-up: client resends SvRequest on reconnect; idempotency absorbs re-sent ops.
  • FsCrdtOp on same sync channel: delta computation applies identically; compute_delta is op-type-agnostic at the framing layer.

6.1 Objectives

6.2 Detailed Implementation Steps

  • conn.rs — Connection: per-client task; owns ws split halves + send queue; router.rs — RouterTable: WorkspaceId -> Sender<RoomMsg>; liveness.rs — ping/pong with timeout.

Frame codec (codec.rs):

Offset Size Field
0 4 payload_len (u32, little-endian)
4 N SyncMessage (bincode-encoded)
  • Delivered as a single WebSocket binary message per frame; max frame size MAX_FRAME_BYTES (default 4 MB) — exceed closes with 1009 Message Too Big.
  • FrameCodec::encode(msg: &SyncMessage) -> Bytes allocates once (re-encode-on-retry acceptable); FrameCodec::decode(raw: &[u8]) -> Result<SyncMessage, CodecError> validates length prefix before bincode decode.

Auth handshake (handshake.rs):

Client sends: Hello { version: u16, workspace_id: WorkspaceId, token: String, client_sv: StateVector }
Server sends: AuthOk { site_id: SiteId, server_sv: StateVector, client_id: ClientId }
         OR:  Bye { reason: AuthFailed | UnknownWorkspace | VersionMismatch }
  • Token validation via opaque TokenValidator trait (impl in lcide-server, Phase 13); version check Hello.version must match PROTOCOL_VERSION (currently 1) — mismatch → Bye(VersionMismatch).
  • Timeout HANDSHAKE_TIMEOUT_MS (default 3000) — no message within timeout closes connection; SiteId assignment queries lcide-session room actor for existing site for this token, assigns new SiteId if first connect.

Connection task (conn.rs):

  • Spawns two sub-tasks per connection: recv_loop (ws → decode → route to room) and send_loop (room → encode → ws); send_loop reads from SendQueue (bounded mpsc, cap SEND_QUEUE_DEPTH, default 256 messages).
  • recv_loop forwards decoded SyncMessage to room actor via RouterTable (unknown workspace → drop + warn); on SendQueue full, drop message + increment net_send_queue_drop_total (never block recv loop, P7); on ws close/error, signal room actor with Bye(ClientId).

Router table (router.rs): DashMap<WorkspaceId, Sender<RoomMsg>> (concurrent, lock-free reads); register(workspace_id, sender) on room creation, deregister(workspace_id) on room close; route via router.send(workspace_id, msg) → Err(NotFound) if workspace unknown → close connection.

Liveness (liveness.rs): Server sends WebSocket ping every PING_INTERVAL_MS (default 15000); if pong not received within PONG_TIMEOUT_MS (default 5000) → close connection, notify room actor; uses tokio time::interval, reset on any received frame (not just pong).

Graceful Bye: Either side sends SyncMessage::Bye { reason } then calls ws.close(); receiving side drains outgoing queue, stops recv loop, logs reason.

6.7 Performance Concerns

Phase 7 — Session Room Actor + Membership

7.1 Objectives

  • Implement lcide-session crate: one async actor task per WorkspaceId owning all documents in that workspace.

  • Enforce per-room op ordering authority while leaving convergence to the CRDT.

Room actor loop (lcide-session/src/room.rs)

  workspace: WorkspaceId
  members: HashMap<ClientId, MemberSlot>
  docs: HashMap<DocId, Document>          // owned by room
  order_clock: Lamport
  op_rx: mpsc::Receiver<RoomCmd>

  workspace_tree: WorkspaceTree           // Phase 9 bridge

7.6 Pitfalls

  • Fan-out mutation during iteration: cloning client_id list before iterating to avoid borrow conflicts when try_send triggers eviction mid-loop.
  • Order clock reset on crash: if order_clock restarts at 0, recovered ops may tie-break incorrectly; persist max_lamport in workspace metadata, reload on start.
  • Catch-up race: client sends ops before catch-up delta arrives; causal buffer in lcide-sync must hold these until catch-up completes.
  • Channel deadlock: room actor sends to persist layer synchronously; if persist back-pressures and persist calls room, deadlock. Use one-way fire-and-forget try_send to persist.
  • Duplicate join: same ClientId sends two JoinMember cmds (reconnect race); check members.contains_key and replace slot atomically.
  • Memory leak on empty room: idle room tasks hold doc allocations; idle-timeout and room teardown required.

7.7 Performance Concerns

  • Fan-out is O(members) per op; at 256 members with 10 KB ops, bulk clone dominates — use Arc<SyncMessage> to fan-out reference-counted without per-member copy.
  • mpsc::Sender::try_send is contention-free (tokio); no mutex in hot path.
  • Lamport increment is a single atomic fetch-add if moved to AtomicU64; avoids lock.
  • Per-op HashMap lookup for doc by DocId; use pre-resolved DocId in RoomCmd to avoid string keys.
  • Batch persist: accumulate up to 64 OpLogEntrys before flush to reduce fsync calls.

  • Lamport overflow at u64::MAX — assert/invariant; practical impossibility but must not wrap silently.
  • Member's send queue tx dropped (client process died) → try_send returns Disconnected; schedule LeaveClient.

    CreateFile  { id: OpId, parent: OpId, name: String, doc_id: DocId },
    CreateDir   { id: OpId, parent: OpId, name: String },
    Delete      { target: OpId, ts: Lamport, site: SiteId },
    Rename      { target: OpId, name: String, ts: Lamport, site: SiteId },
    Move        { target: OpId, new_parent: OpId, ts: Lamport, site: SiteId },
}

Integration algorithm (lcide-workspace/src/apply.rs)

  • CreateFile/CreateDir: insert FileNode with name_reg and parent_reg initialized (parent must exist, else causal buffer); Delete: set deleted = true, recursively tombstone all descendants (BFS on nodes where parent_reg.value == target), remove from path index.
  • Rename: LWW merge on name_reg — accept if op.ts > node.name_reg.ts || (op.ts == node.name_reg.ts && op.site > node.name_reg.site), rebuild path index entry; Move: LWW merge on parent_reg, then run cycle check.
  • Cycle resolution: after any Move integration, run is_ancestor(new_parent, target) before committing; if true (cycle detected), reject the move (keep old parent); emit fs.cycle_rejected metric. Winning move determined by LWW on parent_reg; loser reverted.
  • Path index rebuild: on any structural mutation, walk from mutated node to root, concatenate name_reg.value segments; update path_index. Full rebuild O(N) only on snapshot load; incremental on mutation.
  • Subtree tombstone: delete_subtree(id) — BFS all descendants, mark deleted=true, remove path index entries, set doc fields to None (docs remain in doc store for GC).
  • DocId binding / Causal buffer: CreateFile carries doc_id (room actor calls docs.entry(doc_id).or_insert_with(|| Document::new(doc_id))); FsCrdtOp with missing parent OpId buffers in lcide-sync's causal queue (same mechanism as TextOp), drains when parent op arrives.
  • Persistence: FsCrdtOp persisted as OpLogEntry in same log as TextOp (tagged by type); snapshot includes serialized WorkspaceTree.

Path resolution (lcide-workspace/src/path.rs) — resolve_path(path: &str) -> Option<OpId> splits on / and walks path_index; path_of(id: OpId) -> Option<String> walks the parent chain to root and joins segments; both ignore deleted nodes.

Observability: counter fs.ops_applied, fs.cycle_rejected, fs.tombstones; gauge fs.node_count.

9.6 Pitfalls

  • Cycle check incomplete: checking only immediate parent instead of full ancestor path allows long-cycle creation; is_ancestor must walk to root.
  • Stale path index after LWW conflict: losing Rename applied first then reverted; index must be rebuilt after each op, not just on wins.
  • Infinite subtree tombstone: a large directory with thousands of files causes BFS to block room actor; run subtree tombstone as a background task, yield periodically.
  • DocId reuse on re-create: deleting a file then creating a new one at the same path assigns a new OpId and new DocId; old DocId doc must not be surfaced.
  • Causal buffer memory growth: adversarial client sends child ops without parent; cap causal buffer per client; evict oldest if full.
  • Path collision on concurrent create: two sites create foo/bar.rs concurrently; both get distinct OpIds; path index holds last-integrated winner; the other node is live but unreachable by path. Detect with a reverse_path_index: HashMap<OpId, String> audit.

9.7 Performance Concerns

  • Path index rebuild on every mutation: at 10 000 nodes, full rebuild is O(N log N) — use incremental update (only walk from mutated node to root); LWW comparisons are O(1), not a bottleneck.
  • Subtree BFS on delete: O(subtree_size), acceptable for typical IDE projects (< 10 000 files) — log if subtree > 1000.
  • Snapshot serialization of WorkspaceTree: use compact binary (bincode/postcard) not JSON (10 000 nodes < 1 MB); path index as HashMap<String, OpId> — avoid String clone per lookup by using &str in read paths.

9.8 Edge Cases

  • Move node to itself (target == new_parent) — reject immediately, no cycle check needed.
  • Rename to empty string — reject with validation error before integration.
  • Two creates with identical (parent, name) in same LWW tick — both live; path index holds one; surface as conflict marker in lcide-cli ls.
  • Delete of root sentinel node — guard: id == self.root → reject.
  • FsCrdtOp for unknown target (deleted node): no-op if deleted=true (idempotent), else buffer as causally unready; snapshot load with cycle (corrupt snapshot): cycle detection pass on load, break cycle by resetting losing parent_reg.

Phase 10 — Undo/Redo + Tombstone GC + Compaction

10.1 Objectives

  • Per-site selective undo: invert only the acting site's ops without rolling back concurrent peers' edits.
  • Redo: re-apply an undone op as a new compensating Insert, preserving causal lineage.
  • Tombstone GC: free Item memory for DeletedItems whose OpId is below every known peer's state vector.
  • Op-log compaction: replace a prefix of the append-only log with a Snapshot, shrinking recovery time.
  • Invariants: I1 (convergence) survives undo; I4 (tombstone permanence) holds until GC threshold; I6 (coordinate soundness) maintained after GC removes items; I9 (snapshot fidelity) holds after compaction.

10.2 Detailed Implementation Steps

Theory anchors: P-M (tombstone GC predicate: op below min-SV), P6 (bounded memory), P-I (WOOT space cost motivates GC), B8 (compaction = snapshot + log truncation), ADR-09 (append-only log), I4 (tombstone permanence until GC), I9 (snapshot fidelity post-compaction).

lcide-doc — undo/redo stacks

Symbol Type Role
undo_stack Vec<UndoGroup> chronological local-op groups (per-site)
redo_stack Vec<UndoGroup> ops popped from undo, available for redo
UndoGroup { ops: Vec<OpId>, compensating: Vec<TextOp> } original OpIds + pre-computed inverses
  • local_insert(pos, ch) → push new UndoGroup; clear redo_stack.
  • local_delete(pos) → tombstone target Item; push to undo.
  • undo() → pop UndoGroup, emit compensating TextOps (Delete for undone Inserts; Insert-with-new-OpId for undone Deletes), push to redo_stack; broadcast compensating ops through session room like any other op.
  • redo() → pop redo_stack, emit compensating-of-compensating ops; push back to undo_stack.
  • Remote ops from other sites never touch the local undo/redo stacks.
  • Compensating ops carry fresh OpId {site: self_site, seq: next_seq} so they integrate correctly.

lcide-crdt — GC sweep

  • Document::gc(global_min_sv: &StateVector) → iterate items arena; for each Item where content == Deleted and id.seq <= global_min_sv[id.site], remove from arena and id-map; update position_index (skip-list or B-tree reindex).
  • GC is only correct after all peers' state vectors confirm they have seen the Delete op (I4 safe threshold).
  • GlobalMinSv computed by lcide-session: element-wise minimum across all Member.state_vector plus persisted peer records.

lcide-persist — compaction

  • Trigger: op-log segment exceeds COMPACTION_THRESHOLD (configurable, default 64 MB per doc).
  • Steps: (1) materialize current Snapshot (state_vector + full item set), (2) atomically write snapshot file, (3) truncate op-log prefix up to taken_at_op using write-rename (crash-safe), (4) update snapshots/ index.
  • Recovery: load snapshot → replay only tail ops after snapshot.state_vector.
  • Verify I9 after compaction in CI via fixture comparison.

10.6 Pitfalls

  • Undo of a Delete creates orphaned Insert: compensating Insert uses new OpId; its origin_left/origin_right reference the original neighbors — those may be GC'd. Guard: do not GC an Item referenced by any live undo group's compensating ops.
  • GC races with in-flight ops: a remote op arrives for a peer at seq N-1 after GC deleted that item at N-2. Guard: GC threshold is always min_sv - 1; never GC an item at or above min_sv.
  • Compaction tears on crash: write snapshot to temp file, fsync, rename. On recovery, detect partial snapshot (magic/CRC mismatch) → ignore, replay from prior valid snapshot.
  • Redo after concurrent remote edit: redo re-inserts at stale neighbors; CRDT integration handles this by intention-preservation (P2) but visual position may shift — expected, not a bug.
  • Undo stack unbounded on long-lived doc: cap MAX_UNDO_DEPTH; silently drop oldest group; log undo_overflow metric.
  • Double-GC on reconnect: a client that was partitioned returns with a state vector behind global min; GC ran while it was away; server must not serve GC'd ops (snapshot is the answer — Phase 12 reconciliation uses snapshot + tail).

10.7 Performance Concerns

  • Arena reindex after GC: O(n) skip-list rebuild; schedule as background task, not on the hot path.
  • Compaction I/O: sequential write of snapshot, then fsync; hold doc write-lock for the snapshot-materialize step only (~ms); release before fsync.
  • Undo-stack memory: UndoGroup holds only Vec<OpId>; compensating TextOps generated lazily at undo time, not stored pre-computed.
  • GC sweep frequency: run at most once per GC_INTERVAL wall-clock seconds to amortize arena scan cost.

10.8 Edge Cases

  • Undo on an empty undo stack: no-op, return Err(UndoError::NothingToUndo).
  • Redo after a new local edit: redo stack is cleared on any new local op.
  • GC with a single offline peer: min_sv stalls; add PEER_TIMEOUT_GC_OVERRIDE — after peer absent > threshold, exclude it from min_sv for GC purposes; log gc_peer_excluded.
  • Compaction triggered mid-join (new member catch-up): new member may need ops before snapshot; serve snapshot + tail to joining member (Phase 5 catch-up path).
  • Undo spanning a boundary where compaction removed old Items: compensating op's origin_left may be absent → use tombstone placeholder; invariant I3 still satisfied because tombstone stub is retained in arena until undo group is cleared.

Phase 11 — LSP Multiplexer

11.1 Objectives

  • lcide-lsp: spawn exactly one language-server process per (WorkspaceId, language) pair; supervise crashes.
  • Maintain a per-LS mirror document by replaying CRDT TextOps as LSP textDocument/didChange incremental edits.
  • Map CRDT Position ↔ LSP Position correctly (UTF-16 code-unit offset semantics per LSP spec).
  • Fan out publishDiagnostics notifications to all current members of the workspace.
  • Route textDocument/completion, hover, definition, etc. per requesting ClientId.
  • Constraint: LS process is isolated per workspace; no cross-workspace LS leakage.

11.2 Detailed Implementation Steps

Theory anchors: S4 (LSP 3.17 spec: didOpen, didChange incremental, publishDiagnostics), S5 (UTF-16 code unit offsets), S10 (RFC 6902 JSON Patch = LSP TextDocumentContentChangeEvent semantics), R5 (helix LSP lifecycle), R6 (vscode-languageserver wire format), ADR-22 (lsp-types + tokio::process).

11.6 Pitfalls

  • Stale mirror diverges from CRDT: if ops arrive out of order or a GC removes items the mirror still references, positions map incorrectly. Guard: mirror always derives from Document::materialize(); never infer text from partial op stream.

11.7 Performance Concerns

  • UTF-16 conversion per op: amortize with a LineIndex structure (sorted vec of line-start byte offsets + UTF-16 widths); rebuild on didChange, O(n_lines) not O(n_chars).
  • Diagnostic storage: DiagnosticCache bounded per URI; evict on didClose.

  • LS outputs non-UTF-8 on stderr: capture as bytes; log truncated hex; never panic.

Phase 12 — Reconnection + Offline Edits + Convergence

12.1 Objectives

  • Client buffers TextOps and FsCrdtOps while disconnected, replays on reconnect without data loss; reconnect protocol: bidirectional state-vector exchange → push local delta → pull remote delta → converge.
  • Guarantee convergence after arbitrary partition (any number of concurrent edits on any subset of sites); duplicate-op suppression via OpId idempotency (I5).
  • Presence (AwarenessState) resurrected fresh on reconnect (I7: never restored from log); resumable from last server-acknowledged seq (last_acked_seq) — no re-transmission of confirmed ops.

12.2 Detailed Implementation Steps

Theory anchors: P8 (offline-first convergence), P-K (staleness bounds + causal tokens), P-A (SEC survivability across partition), I5 (idempotent duplicate suppression), I3 (causal readiness on reconnect delta), ADR-03 (Tokio reconnect exponential backoff).

Client-side offline buffer (lcide-sync::offline)

OfflineBuffer {
    site_id: SiteId,
    last_acked_seq: u64,           // server acked up to here
    pending: VecDeque<TextOp>,     // ops with seq > last_acked_seq
    pending_fs: VecDeque<FsCrdtOp>,
}
  • Every local op appended to pending immediately (before send attempt); on SyncMessage::Ack { seq } from server, drain pending entries with op.id.seq <= seq and update last_acked_seq.
  • On disconnect: stop attempting sends, buffer continues accumulating; buffer size limit OFFLINE_BUFFER_MAX (default 10 000 ops) — on overflow, mark needs_full_resync = true (triggers full state transfer on reconnect instead of delta).

Reconnection handshake (lcide-net / lcide-sync)

1. Client sends Hello { site_id, client_id, workspace_id, token }
2. Server sends AuthOk { new_client_id, server_sv: StateVector }
3. Client sends SvRequest(client_sv: StateVector)
4. Server computes delta = ops where op.id.seq > client_sv[op.id.site]
   Server sends Delta(missing_ops) in causal order
5. Client sends Delta(pending ops with seq > server_sv[client_site])
6. Both sides apply received ops via lcide-crdt integration + causal buffering
7. Client sends fresh AwarenessState (cursor/selection reset to doc head if prior position invalid)
  • Step 4 delta computation: same compute_delta(have: &StateVector, all_ops: &OpLog) -> Vec<TextOp> used in Phase 5, sorted by causal order; causal buffering holds ops whose origin_left/origin_right are not yet integrated in CausalBuffer, retried on each new integration (I3); after both deltas applied, verify client_sv == server_sv (exchange a final SvRequest round-trip) — mismatch triggers full resync.

Duplicate-op suppression

  • Document::integrate(op) checks state_vector[op.id.site] >= op.id.seq → skip (I5); server-side lcide-session also deduplicates before persisting to op log; no special handling needed beyond the state-vector check.

Presence resurrection

  • On reconnect, after delta exchange completes, client computes cursor position from current materialized doc (best-effort: map old CRDT Item.id to new offset; if tombstoned, default to end-of-doc), then sends fresh AwarenessState { expires_at: now + PRESENCE_TTL }; server does NOT restore prior AwarenessState from any store (I7).

Follow-mode continuity

  • If client was in follow-mode targeting peer P: send FollowRequest(peer_site_id) after reconnect; session restores the subscription if P is still present.

needs_full_resync path

  • Client sends SvRequest(empty_sv) to request all ops from server snapshot + tail; server responds with current Snapshot pointer + Delta(tail_ops); client reconstructs Document from snapshot (Phase 4 recovery path) then applies tail.

Observability

  • Metric: reconnect_delta_ops_sent, reconnect_delta_ops_received, reconnect_full_resync_total, offline_buffer_depth, causal_buffer_depth; tracing span sync.reconnect, sync.delta_apply.

12.6 Pitfalls

  • Causal buffer starvation: op A requires origin B, which never arrives (B was GC'd on server while client was offline). Resolution: if origin is below server's global min_sv and tombstone is gone, treat as implicitly integrated (server provides a GcWatermark in AuthOk; client uses it to unblock buffered ops).
  • last_acked_seq race: client emits ops, ACK arrives after disconnect; last_acked_seq not updated; on reconnect, those ops re-sent. Server deduplicates via OpId check (I5). No data corruption; slight redundancy acceptable.
  • State-vector mismatch after delta exchange: floating-point or integer overflow in seq arithmetic → always use u64; checked arithmetic; assert no u64 wrap in CI.
  • Snapshot deserialization version skew: client requests snapshot taken with newer schema. Guard: snapshot header carries schema_version; client rejects unknown versions, falls back to SvRequest(empty_sv) with base ops only.
  • Presence at invalid position after long partition: prior cursor's Item.id is GC'd — guard: AwarenessState cursor validity checked at broadcast, if item absent, clamp to (0,0). Follow-mode to offline peer: target peer's presence expired — FollowRequest silently ignored, client notified via FollowError::PeerAbsent.

12.7 Performance Concerns

  • Delta computation on large op log: O(log per op in log) — use per-site sorted index site_seq_index: HashMap<SiteId, BTreeMap<u64, OpLogOffset>> in lcide-persist, seek directly to client_sv[site] + 1 per site; causal buffer scan retries on every new integration, amortized by indexing waiting ops by origin_left → woken directly.
  • Offline buffer serialization: pending is in-memory VecDeque — on client crash, buffer lost (acceptable, full resync on restart); do not persist to disk in this phase.
  • Batch delta send: transmit as Delta(Vec<TextOp>) with framing, single websocket write per delta (not per op); presence broadcast on reconnect is a single AwarenessState message, no loop over history.

12.8 Edge Cases

  • Client reconnects with site_id unknown to server (new install, server restarted with fresh store): server assigns new SiteId; old local ops have stale site; client must discard offline buffer and start fresh — emit reconnect_site_id_reset metric.
  • Multiple rapid disconnect/reconnect cycles: each cycle a new WebSocket connection; ClientId changes each time; SiteId stable. Session room tolerates multiple Join/Leave sequences.
  • Reconnect during compaction: server's op log tail may start after a snapshot; server sends Snapshot ref + tail instead of raw delta.
  • Clock skew between client and server: expires_at in AwarenessState uses server-relative duration, not wall-clock — send ttl_ms not an absolute timestamp, server sets expires_at = recv_time + ttl_ms; two clients with same SiteId (misconfiguration) collide at OpId level — server detects duplicate site_id on join, rejects the second with AuthError::SiteIdConflict.

Phase 13 — auth, access control, multi-workspace, backpressure

13.1 Objectives

  • Token-based auth on websocket handshake in lcide-net (unauthenticated connections closed before room entry); per-workspace ACL table (read/write/none) stored in lcide-persist workspace metadata, enforced in lcide-session.
  • Read-only members receive fan-out ops but any emitted op is rejected with an error frame (I10); multi-workspace server in lcide-server — each WorkspaceId maps to an independent SessionRoom actor, rooms isolated by channel boundaries.
  • Global resource limits (total connections, total op-log size) and per-room limits (member count, queue depth, op rate); slow-consumer eviction: when a member's send queue exceeds threshold, the room drops the connection.
  • Admission control on WorkspaceJoin: deny if room is at capacity or workspace is in recovery mode.

13.2 Detailed Implementation Steps

Theory anchors: P12 (fail-closed authorization), S9 (JWT/JWE token auth), S12 (WebSocket bearer token placement), ADR-28 (opaque token over JWT), I10 (ACL soundness), P7 (backpressure + slow-consumer eviction), B9 (fail-closed auth; resilience by design).

lcide-net — auth handshake

  • Hello { token: String, workspace: WorkspaceId, site: SiteId } frame triggers AuthService::verify(token) -> Result<AuthPrincipal>.
  • AuthPrincipal { site, acl: AclLevel } where AclLevel = Read | Write | None.
  • On None or verification failure: send AuthError frame, close socket immediately; no room entry.
  • AuthOk { client_id: ClientId, acl: AclLevel } frame returned on success; ClientId server-assigned monotonic u64.
  • Connection state machine: Handshaking -> Authenticated -> Joined -> Closing.

lcide-persist — ACL storage

  • Workspace metadata record: WorkspaceMeta { id, owner_site, acl_list: Vec<AclEntry>, created_at, flags }.
  • AclEntry { site: SiteId, level: AclLevel }. Missing entry defaults to None.
  • ACL loaded at room creation; hot-reloaded on AclUpdate admin message without room restart.
  • Mutations to ACL are themselves persisted as a versioned metadata record (not an op log entry).

lcide-session — ACL enforcement + multi-workspace

  • Before integrating any incoming TextOp or FsCrdtOp: check member.acl == Write; else reply PermissionDenied and discard.
  • SessionRegistry: HashMap<WorkspaceId, Sender<RoomMsg>> behind a RwLock; server-scoped singleton.
  • Room actor spawned on first join; torn down after last member leaves + configurable idle timeout.
  • Isolation: rooms share no data structures; all cross-room paths are forbidden at the type level (no Arc<Document> leaks across rooms).
  • Per-room limits enforced at join: member_count >= MAX_ROOM_MEMBERS -> JoinDenied { reason: Capacity }.
  • Global connection counter (atomic u64); MAX_GLOBAL_CONNECTIONS checked in lcide-net accept loop.

Backpressure / slow-consumer eviction

  • Each member has send_queue: BoundedChannel<SyncMessage>(capacity=SEND_QUEUE_CAP).
  • Room fan-out: try_send into each queue; on TrySendError::Full increment slow_consumer_count counter, close the connection, emit log::warn! with client_id and workspace_id.
  • Op-rate limiter per client: token bucket (rate_per_sec, burst); excess ops dropped with RateLimitDrop metric.
  • Global op-log size guard: if persist::total_log_bytes() > MAX_LOG_BYTES -> new workspaces denied until GC runs.

Admission control

  • AdmissionPolicy::check(workspace, principal) -> AdmissionResult; consulted by room actor on JoinRequest.
  • Blocks join when: room in recovery, workspace locked by admin, principal banned, capacity exceeded.
  • Recovery mode flag set during snapshot restore; cleared when room is ready for new ops.

  • Server boots with token verification active (unauthenticated clients rejected at the TCP handshake phase); per-workspace ACL enforced — read-only client receives all ops, write is refused with error frame.

  • lcide-cli serve exposes --max-connections, --max-room-members, --send-queue-cap flags.

13.6 Pitfalls

  • ACL check after buffering: if the causal buffer in lcide-sync holds ops before ACL check, a revoked client's buffered ops may integrate after revocation. Fix: ACL check at emission point (connection receive loop), before any buffering.
  • Race on ACL hot-reload: room actor may apply an op between ACL fetch and reload. Mitigation: ACL stored as ArcSwap<AclTable>; updates replace atomically; no lock held during op integration.
  • Queue capacity misconfiguration: SEND_QUEUE_CAP too large -> memory exhaustion before eviction fires. Debug: monitor send_queue_depth histogram per client.
  • Idle room leak: room actor not torn down after last member leaves. Symptom: SessionRegistry grows. Fix: room actor sends RoomIdle event; registry reaps after configurable timeout + confirms zero members.
  • Global connection limit race: two connections accepted simultaneously at limit. Fix: atomic fetch-and-increment with compare-exchange; reject if post-increment exceeds limit then decrement.
  • Read-only fan-out amplification: read-only clients receive all ops but never produce backpressure relief; large number of read-only members can exhaust fan-out capacity. Mitigation: separate queue tier for read-only members; lower eviction threshold.

13.7 Performance Concerns

  • SessionRegistry RwLock under high join/leave churn: shard by WorkspaceId % N_SHARDS.
  • Per-member try_send in fan-out loop is O(N members); for large rooms, batch via a per-member task that drains a shared broadcast.
  • Token verification (HMAC/JWT): cache verified tokens by hash with TTL to avoid per-op crypto; invalidation on revoke.
  • ACL table lookup: HashMap<SiteId, AclLevel>; hot path per op; keep in L1 by interning small ACL tables.
  • Global connection counter: single AtomicU64; no contention concern.
  • Rate limiter per client: token bucket state in connection struct; no shared lock; update on each op receive.

13.8 Edge Cases

  • Client reconnects mid-eviction: old connection closed, new Hello arrives; must not double-count toward room capacity.
  • ACL downgrade (write -> read) while client has buffered ops in flight: server must re-check at integration time using current ACL, not the ACL at buffer insertion.
  • Workspace WorkspaceId reuse after deletion: metadata must record deletion tombstone; new workspace with same numeric id must be rejected (use monotonic server-assigned ids, never reuse — DocId/WorkspaceId invariant).
  • AuthService backend unavailable at startup: server must refuse all connections, not silently allow; fail-closed.
  • AclLevel::None site sends presence/awareness: discard silently (not an error frame), preventing information leakage about workspace contents.
  • Token without workspace claim: ambiguous; reject with AuthError { reason: MissingWorkspaceClaim }.

14.2 Detailed Implementation Steps

Theory anchors: P1 (SEC — the property under test), I1/I9 (correctness invariants asserted empirically here), ADR-18 (proptest/cargo-fuzz harness), ADR-21 (criterion + wall-clock benchmarking), P-A (SEC formal definition validated by the convergence fuzzer).

Convergence fuzzer (lcide-cli bench / tests/convergence_fuzz.rs)

  • FuzzConfig { n_sites: usize, n_ops: usize, partition_prob: f64, seed: u64 }; simulated site: in-process Document + StateVector, no I/O, deterministic with seeded RNG.
  • Op generation: random Insert (random position in current text, random char) or Delete (random live item) per site; partition: with probability partition_prob, randomly divide sites into two groups, ops generated during partition buffered per group.
  • Merge: exchange buffered op deltas (state-vector diff); each site integrates remote ops via lcide-crdt.
  • Assertion: after full delivery, compare Document::materialize() across all N sites (must be byte-identical) and state_vector across all sites (must be equal); record failing seed, site count, op sequence, partition schedule as a reproducible fixture.
  • Corpus: 1000 random seeds at CI; 10 000 seeds in nightly extended run.

Op-log fuzz reader (tests/oplog_fuzz.rs)

  • Use cargo-fuzz (libfuzzer-sys) targeting lcide-persist::OpLogReader::read_all(data); verify no panic, no UB — returns Ok(entries) or Err(Corrupt { offset }).
  • Cover: truncated frame mid-header, truncated frame mid-payload, bad CRC, version mismatch, zero-length op, op count overflow, interleaved snapshot header in op stream; regression corpus stores crashing inputs as fuzz/corpus/oplog/ fixtures.

Latency benchmark (benches/fanout_latency.rs)

  • Setup: in-process lcide-server with N_CLIENTS websocket connections, single workspace; measure wall-clock from TextOp sent by client 0 to last Delta received by client N-1.
  • Report: p50 / p95 / p99 / max latency, throughput (ops/sec); threshold gates (configurable via env): P99_LATENCY_MS <= 10 for N=50 clients, 1KB ops.
  • Regression guard: benchmark output written to target/bench/fanout_latest.json; CI compares against bench/fanout_baseline.json; fails if p99 regresses > 20%.

Snapshot/restore equivalence (tests/snapshot_equivalence.rs)

  • For each workspace fixture: generate op sequence, take snapshot at midpoint, continue ops; assert full_replay_text == snapshot_plus_tail_text and full_replay_sv == snapshot_plus_tail_sv.
  • Edge: snapshot taken with no ops (empty doc), snapshot taken after GC, snapshot at exact op boundary; cover snapshot truncated mid-write (simulate crash during snapshot flush) — verify recovery falls back to prior snapshot.

Workspace pack/unpack (lcide-persist::pack module)

  • WorkspacePack { version: u32, workspace_id: WorkspaceId, meta: WorkspaceMeta, snapshots: Vec<SnapshotRecord>, oplog_tail: Vec<OpLogEntry>, tree_state: WorkspaceTreeState, acl: Vec<AclEntry> }; serialization: bincode + zstd compression, single .lcidepkg file.
  • Export: lcide-cli dump --pack <workspace_id> --out <path> calls pack::export(workspace_id, dest); import: lcide-cli dump --unpack <path> --workspace-id <new_id> calls pack::import(src, new_id) — rebinds WorkspaceId, validates all op CRCs before committing.
  • Round-trip assertion: export -> import -> full_replay_text == original_text.

Invariant property tests (tests/invariants.rs)

  • I2 (seq monotonicity): per-site seq never gaps; checked after every fuzz run.
  • I3 (causal readiness): integration rejected if origin not present; tested with deliberately reordered op streams.
  • I4 (tombstone permanence): deleted item never reappears after GC pass; property test over GC schedule.
  • I5 (idempotency): apply same TextOp 3x; assert doc state == apply once.
  • I6 (coordinate soundness): random (line,col) -> OpId -> offset round-trip; assert stable mapping.

I11 (id non-reuse): fuzzed allocator sequence asserts monotonic, never-reused DocId/WorkspaceId. I12 (workspace isolation): fuzzed multi-workspace fan-out asserts zero cross-workspace op leakage.

14.6 Pitfalls

  • Non-deterministic materialization leaking into fuzz comparison: if Document::materialize() depends on HashMap iteration order (violation of P9 / I1), convergence tests give false negatives. Fix: sort items by OpId before materialization; audit all map iterations in lcide-crdt.
  • Fuzz seed reproducibility: using thread_rng in fuzz harness makes failures non-reproducible. Fix: always seed from FuzzConfig::seed via StdRng::seed_from_u64; log the seed on assertion failure.
  • Op-log fuzzer OOM on large payload field: libfuzzer may generate a payload_len field of u32::MAX. Fix: bound payload_len read before allocation; return Err(Corrupt) immediately on implausible lengths.
  • Snapshot truncation fallback silently loses ops: if the fallback reads prior snapshot but op-log tail starts after the truncated snapshot's taken_at_op, ops between the two snapshots are skipped. Fix: OpLogReader scans backward to find the last intact snapshot whose taken_at_op is <= the earliest contiguous op log frame.
  • Pack import WorkspaceId collision: importing a pack while the original workspace is live causes two rooms with conflicting state. Fix: import rejects if WorkspaceId already registered in SessionRegistry; --force flag tombstones old workspace first.
  • Benchmark warm-up bias: first ops trigger JIT/branch-predictor effects skewing p99. Fix: discard first 10% of measurements as warm-up; document warm-up in benchmark harness.
  • Concurrent move cycle under randomized fuzz: cycle resolver must be deterministic (lowest OpId wins parent assignment); if resolver is non-deterministic, two sites may resolve to different trees, breaking I1 for the workspace tree.

14.7 Performance Concerns

  • Fuzz harness allocates a new Document per run — use a pool of pre-allocated arenas reset between seeds to reduce allocator pressure; materialize() called N times per convergence assertion (once per site) — cache the materialized string if no ops applied since last call, invalidate on each integrate.
  • Op-log replay during snapshot_equivalence reads entire log into memory for small fixtures; stream in 4KB chunks for large fixtures to avoid OOM in CI.
  • Pack serialization with zstd: use streaming encoder; avoid Vec<u8> intermediate for large op logs.
  • Latency benchmark: pin benchmark client tasks to CPU cores to reduce scheduler jitter, report stddev alongside percentiles; invariant_i8_acyclicity graph traversal: WorkspaceTree cycle check is O(N) — for large N use union-find with path compression.

14.8 Edge Cases

  • Zero-site convergence fuzz (N=0 or N=1): trivially passes; assert fuzz config rejects N < 2.

  • Pack export of workspace with in-progress snapshot write: partial snapshot in export; import must detect partial snapshot via CRC and use prior one.

Tracing Strategy

  • Instrument with tracing crate; emit structured spans at every crate boundary.
  • Top-level spans: net.frame_recv, net.frame_send, session.apply_op, session.fanout, sync.compute_delta, sync.causal_buffer_hold, persist.append_entry, persist.snapshot_write, lsp.handle_request, lsp.position_map.
  • Propagate workspace_id, client_id, op_id, site_id, seq as span fields through the full request path; allows trace-based root-cause on a specific op.
  • Sample: 100 % error spans + all spans with duration > 50 ms; 1 % success spans in production; 100 % in staging and bench environments.
  • Export via OpenTelemetry OTLP to Jaeger or Grafana Tempo; tail-sampled with a 1 h retention for errors.
  • Causal buffer hold/release events traced with origin_op_id, wait_duration_ms, buffer_depth_at_hold.
  • Fan-out spans carry member_count, delta_ops_count, bytes_sent to attribute latency to batch size.
  • Snapshot and GC events carry tombstone_count_before, tombstone_count_after, seq_range_compacted.

Structured Logging

  • Format: JSON lines; mandatory fields: timestamp (RFC 3339 µs), level, target (crate::module::fn), workspace_id, client_id, op_id, trace_id, msg.
  • Level allocation:
    • ERROR — invariant violation (I1–I12), panic recovery, auth failure, CRC mismatch, ACL bypass.
    • WARN — rate limit triggered, slow-consumer grace-period entered, GC anomaly, causal buffer stall > 5 s, snapshot CRC fail.
    • INFO — workspace create/destroy, member join/leave, snapshot taken (seq range), LS crash + restart, compaction completed, rolling-upgrade drain start/end.
    • DEBUG — per-op detail (OpId, site, seq, lamport, content_len), sync delta sizes, causal buffer depth on each dequeue; disabled in production via RUST_LOG=lcide=info.
  • Mandatory PII/secret exclusions: no bearer tokens, no auth cookies, no file content, no user display names in logs; client_id is opaque handle.
  • Log rotation: size-based (256 MB) + daily time-based; 7-day local retention; ship to centralized store (Loki / Elasticsearch) with 30-day retention.
  • Log integrity: each log file has a SHA-256 footer written on rotation; integrity verified on upload to centralized store.

Alerting Philosophy

  • Page (wake-on-call): SLO burn-rate breach (any SLO), content hash divergence (SLO-4, any mismatch), disk > 95 % full on any workspace node, room actor down > 30 s, auth failure spike (> 100/min).
  • Ticket (business hours): LSP crash rate > 1/hour on any workspace, tombstone count > 1 M in any doc, causal buffer stall > 60 s, snapshot age > 2 × snapshot_interval.
  • Info (dashboard only): per-event rate-limit events, ACL violations, slow-consumer evictions, GC runs.
  • Alert on symptoms (latency, availability, correctness), not causes (CPU, memory) — derive cause from traces and structured logs, not alert labels.
  • Multi-window burn rate: use both 1 h (fast) and 6 h (slow) burn-rate alerts in parallel to catch both spikes and slow degradations.
  • Silence policy: silence infra alerts during planned maintenance windows only; never silence SLO-4 (convergence).

Rollback

  • Standard rollback: redeploy previous binary tag; nodes start on existing op logs (format-version range covers previous version).
  • Verify post-rollback: lcide_workspace_active stable; SLO-1 p99 within bounds; re-run convergence endpoint.
  • Storage format rollback: if the new binary introduced a format_version bump, run lcide-cli migrate --rollback --workspace <id> to rewrite log to previous format before starting old binary; migration is always to a new file, never in-place.
  • Wire-only rollback (no storage change): simply redeploy; clients reconnect and catch up via state-vector delta.
  • Rollback time target: < 5 minutes from decision to all nodes running previous version.

Mental Models & First Principles

The compressed insights an expert holds about collaborative-editing systems. Each predicts a class of bug you write without it. Every cited § resolves to a real heading in this blueprint.

MM1. A CRDT op is a value, not a command. Integration is commutative and idempotent: integrate(a, b) == integrate(b, a), and replaying an already-seen op is a no-op. Predicts: any two replicas that have absorbed the same op set converge byte-for-byte. Bug without it: treating an op as an imperative "insert at index 7" — indices shift under concurrency and replicas diverge. Applied: §8 (Item/TextOp), Phase 2 (Sequence CRDT), I-convergence invariants in §7.

MM2. origin_left/origin_right are the only total order that survives concurrency. YATA orders concurrent inserts by their origin anchors then by (id), never by arrival time. Predicts: two users typing at the same caret produce a deterministic, interleave-free merge. Bug without it: tie-breaking on Lamport alone yields character interleaving ("ababab") between two words. Applied: §8.1 (Item.origin_left/right), Phase 2.

MM3. The state vector is a causal frontier, not a version number. StateVector: Map<SiteId,u64> records the highest contiguous seq seen per site; a delta is exactly the ops with seq > SV[site]. Predicts: sync cost is O(ops-behind), not O(doc-size). Bug without it: a single global counter cannot express "I have site A through 50 but site B only through 12," so you resend everything. Applied: §8.1 (StateVector), Phase 5 (state-vector delta sync), §4.1 ("State-vector delta compute ≤ 1 ms").

MM4. Tombstones are unforgettable until everyone has seen them. A deleted Item must stay as a tombstone until its op is below the minimum state vector across all live peers; only then is GC safe. Predicts: the safe-GC window and why aggressive GC corrupts laggards. Bug without it: GC a tombstone a slow peer still references → that peer's op lands with a dangling origin → resurrection or panic. Applied: Phase 10 (Tombstone GC), P6, §4.1 ("Tombstone GC trigger: op age > all peer state vectors").

MM5. The room actor is a serialization point you buy data-race freedom with. Each workspace is owned by exactly one SessionRoom task; concurrency exists across rooms, never within one. Predicts: zero locks on the hot path and the ~500-client fan-out ceiling. Bug without it: sharing a mutable Document across tasks → races, torn reads, non-deterministic order. Applied: §8.1 (SessionRoom), Phase 7, Scalability Analysis (Bottleneck Map).

MM6. Causal delivery is a buffering problem, not a transport problem. An op whose origin references an op you have not yet integrated must wait in a per-connection causal buffer. Predicts: why a bounded buffer (256/site, §4.1) plus disconnect-on-overflow is sufficient and safe. Bug without it: integrating out of causal order produces a dangling origin reference and a corrupt sequence. Applied: Phase 12 (causal buffer), §4.1 ("Causal buffer max depth 256").

MM7. Materialization is an O(items) fold — never do it per-op. Rebuilding the UTF-8 string walks the whole arena; it belongs to snapshots and reads, not the keystroke path. Predicts: the 5 ms / 100 K-item materialization budget vs the 500 µs single-op integrate budget. Bug without it: re-materializing on every keystroke turns an O(1) edit into O(N). Applied: Phase 3 (Document materialization), §4.1 (materialization vs integrate targets).

MM8. Presence is not part of the document. Awareness (cursor, selection, viewport, color) is ephemeral, clock-expired, never persisted, never causally ordered. Predicts: why presence rides a separate lower-priority broadcast and never enters the op-log. Bug without it: logging presence into the op-log makes the log unbounded and replay produces stale ghost cursors. Applied: §8.1 (AwarenessState), Phase 8 (Presence/Awareness).

MM9. Reconnection is a re-sync, not a replay-from-zero. The returning client sends its StateVector; the server replies with only the delta. Predicts: reconnection bandwidth is O(ops-missed), bounded by offline duration. Bug without it: full document resend on every flaky-network blip → bandwidth spikes and head-of-line blocking. Applied: Phase 12 (reconnect/offline), Phase 5 (delta sync).

MM10. The LSP mirror is a lossy projection that melts under op rate. The language server consumes plain text via didChange; it has no concept of CRDT structure, so per-op notifications overwhelm it. Predicts: the need for a 50 ms debounce window batching ops into one didChange. Bug without it: one didChange per keystroke drives the LS to 100% CPU and stalls diagnostics. Applied: Phase 11 (LSP multiplexer), Scalability Analysis ("LS document mirror diffs").

Yjs chose a compact struct-store with run-length item encoding and a pluggable provider model, optimizing for browser memory and any-transport portability; it wins where the editor is web-native and the network layer is heterogeneous (WebRTC, y-websocket, y-webgl). This blueprint instead centralizes a room actor for server-authoritative ordering and durable op-logs because the target is a hosted IDE, not a P2P widget.

Automerge preserves the entire change history (no tombstone GC) to support time-travel, blame, and Git-like branching, and uses columnar compression for the log; it wins for document databases and audit-heavy collaboration. We reject full-history retention because an IDE op-log grows ~28 MB/hr per active doc (Capacity Model C5) and must be compacted, trading historical branching for bounded storage.

ShareDB is OT, server-authoritative: the server holds the canonical op log and transforms concurrent ops; it wins for JSON-document apps where a central server is a given and clients are thin. We reject OT because transform-function composition is O(n²) in concurrent op count and notoriously hard to get correct for rich structures (the well-documented difficulty behind Google Wave's OT); CRDTs move correctness into the data type.

VS Code Live Share relays edits through the host's editor (host is the source of truth) with no durable CRDT log, optimizing for zero-setup pair programming; it wins when one trusted host is always online and persistence is the host's local disk. We reject host-authoritative relay because it cannot survive host disconnect, offers no multi-region durability, and cannot scale past the host's single machine.

  • C1 — Per-workspace fan-out bandwidth. writers × char_rate × (writers−1) × op_bytes = 30 × 5 × 29 × 80 B ≈ 348 KB/s outbound per saturated workspace. Confirms the p95 ≤ 10 ms fan-out target (§4.1) is bandwidth-trivial; CPU, not network, is the limit.
  • C2 — Server outbound at scale. 348 KB/s × 50 workspaces ≈ 17 MB/s sustained. Within a single NIC; matches the "Max clients per workspace 512 → ≤ 50 MB/s" ceiling (Scalability Analysis) as the per-room worst case.
  • C3 — Hot-workspace memory budget. Server ceiling 4 GB ÷ 256 MB/active workspace = ≈ 16 fully-active workspaces resident; the other 34 of 50 must be idle (≤ 8 MB each = 272 MB). Derives the LRU-eviction requirement (§4.1 "idle workspace ≤ 8 MB").
  • C4 — Item arena per max document. 2 M items × 50 B/Item = 100 MB per doc; reconciles with the "Max op-log before compaction 100 MB" and the 10 M-item / ~500 MB hard arena ceiling (Scalability Analysis).
  • C5 — Op-log growth & compaction cadence. 100 ops/s × 80 B = 8 KB/s = 28.8 MB/hr; against the 100 MB compaction threshold (§4.1) ⇒ compaction roughly every 3.5 h of continuous editing.
  • C6 — File-descriptor budget. 4 × (workspaces + clients) (§4.1). With 50 ws + (30×50)=1500 clients ⇒ 4 × 1550 = 6 200 FDs; requires ulimit -n ≥ 8192.
  • C7 — State-vector payload. sites × 8 B: 30 active sites = 240 B (fits a cache-line cluster, §4.1); a long-lived workspace with 1 000 historical sites = 8 KB per sync, motivating below-min-SV site compaction.
  • C8 — Snapshot storage amplification. 3 × materialized_size (§4.1): a 2 MB doc ⇒ 6 MB on disk (snapshot + tail + one prior snapshot).
  • C9 — Recovery replay bound. Snapshot every ≤ 10 K ops ⇒ cold start replays ≤ 10 K ops; at < 100 µs/op group-committed that is < 1 s integrate, inside the ≤ 10 s RTO (§4.1).
  • C10 — Per-member send-queue memory. 1024 msgs × 80 B avg = 80 KB typical, 1024 × 64 KB max frame = 64 MB worst case; justifies eviction at queue-full (P7) rather than unbounded buffering.
  • C11 — LSP load reduction. Raw 150 ops/s per busy workspace debounced into a 50 ms window ⇒ ≤ 20 didChange/s to the language server — a 7.5× reduction (Phase 11), keeping LS off the critical path.
  • C12 — Fan-out CPU ceiling. Single room actor at ~2 ms/op fan-out work saturates one core near ~500 concurrent clients (Scalability Analysis Bottleneck Map); past that, shard by WorkspaceId.

Alternative Architectures (Roads Not Taken)

Four fundamentally different designs for the same system, not parameter tweaks.

Alt-A — Operational Transform, server-authoritative (Google Docs / ShareDB / Live Share).

clients --ops--> [ central transform server ] --transformed ops--> clients
                  (canonical op log, transforms concurrent edits)

Wins when: a central always-on server is a given, clients are thin, and the document model is simple JSON/text. Embodied by: Google Docs, ShareDB, VS Code Live Share. Rejected because: transform composition is O(n²) in concurrent ops and historically error-prone for rich/tree structures (the difficulty that sank Google Wave); CRDTs (MM1) move correctness into the data type and enable offline edits (MM9).

Alt-B — Pessimistic region locking (collaborative DB style).

client --lock(region)--> server --grant--> client edits --release--> next waiter

Wins when: edits are coarse-grained (whole-cell, whole-section) and strong single-writer-per-region consistency is required, e.g. structured form editing. Embodied by: locking document stores, some wiki engines. Rejected because: concurrent character-level editing of the same line is the core requirement; locking serializes typing and adds RTT-bound latency to every keystroke (violates §4.1 fan-out targets).

Alt-C — RGA + columnar log (Automerge model).

each replica: append-only change log (columnar) --sync(SV)--> merge, full history retained

Wins when: time-travel, branching, and blame over the whole edit history are first-class needs (legal docs, research notebooks). Embodied by: Automerge. Rejected because: retaining full history conflicts with the IDE op-log growth rate (Capacity C5) and the need for tombstone GC and compaction (MM4, Phase 10); YATA linked items integrate more cheaply for the live-typing path.

Alt-D — Peer-to-peer mesh, no central server (WebRTC).

client A <==WebRTC==> client B
   \\==WebRTC==>  client C  (every pair connected; CRDT sync over data channels)

Wins when: there is no trusted server, censorship resistance or zero server cost matters, and sessions are small and ephemeral. Embodied by: y-webrtc, Conclave. Rejected because: a hosted IDE needs durable history, server-side LSP processes, auth/ACL (Phase 13), and NAT traversal/relay fallback erodes the "no server" benefit; the single room actor (MM5) gives a clean durability and ordering point.

Glossary

Alphabetical. Each term is defined at the precision level required for implementation decisions.

Term Definition
ACL (Access Control List) Per-workspace map ClientId -> Permission{Read,Write,None}; enforced in lcide-session before fan-out; read-only members receive Delta messages but any emitted op is rejected (I10).
Awareness / Presence Ephemeral per-client state (AwarenessState): cursor, selection, viewport, color, expiry. Never logged, never snapshotted (I7, P4).
Backpressure Per-client bounded send queue in lcide-net; when full, the session room drops the slow client rather than blocking fan-out (P7).
Causal buffering Holding an incoming TextOp in a per-doc queue until all causally prior ops (origin_left, origin_right) are integrated (I3, P5).
Causal delivery Delivery guarantee: op o is integrated only after every op that o causally depends on is already present in the local item set.
Catch-up On join, the server computes missing = ops not in client's StateVector, ships them as Delta; client integrates in causal order.
Client (ClientId) A live WebSocket connection; transient. Distinct from SiteId which is stable across reconnections.
Compaction Rewriting the op log to a new Snapshot + trimmed tail, removing ops already subsumed by the snapshot and below all peers' state vectors.
Content hash SHA-256 of materialize() output; compared across sites to detect convergence divergence without full text transfer (P10).
Convergence Strong Eventual Consistency (SEC): any two sites that have integrated the same op set produce byte-identical materialized text and identical StateVectors (I1).
CRDT (Conflict-free Replicated Data Type) Data structure whose merge operation is commutative, associative, and idempotent; requires no consensus for convergence.
Delta sync Sync pattern: sender ships only the ops the receiver is missing (those above the receiver's StateVector); avoids full-log retransmission.
didChange mirror In lcide-lsp, the in-memory document replica fed via LSP textDocument/didChange notifications reconstructed from CRDT ops.
Ephemeral state State that exists only while its producer is connected; AwarenessState is the canonical example. Excluded from op log and snapshot.
Fan-out Session room broadcasting an integrated op to every connected member except the originating sender.
Follow-mode Presence feature: a client opts to mirror another client's viewport; lcide-presence propagates viewport updates to all followers.
Intention preservation CRDT property: an Insert arrives between origin_left and origin_right as seen at edit time, not at a stale offset; P2.
Item Atomic CRDT text element `{ id: OpId, origin_left, origin_right, content: Char
Lamport timestamp Logical clock Lamport(u64): max(local, received) + 1 on receive; used as integration tie-breaker when two Items share the same origin pair (YATA Rule 2).
LWW Register (Last-Write-Wins) CRDT register where the update with the highest Lamport timestamp wins; used for FileNode.name_reg and FileNode.parent in workspace tree.
Materialization Pure function over the integrated item set: visits Items in CRDT order, skips tombstones, returns UTF-8 string. Deterministic; independent of integration order (P9, I6).
Op log Append-only durable file of OpLogEntry records with CRC framing; single source of truth for crash recovery (P11).
OpId { site: SiteId, seq: u64 } — globally unique identifier for one operation. Causal key for origin references and state-vector tracking.
Operational Transformation (OT) Predecessor concurrency model (Ellis & Gibbs 1989); requires transformation functions and is notoriously hard to prove correct. Rejected in favor of CRDT (see section 5).
Partition Network split where one or more clients cannot reach the server; offline edits are buffered locally and reconciled on reconnect (P8).
Position mapping Bijection between (line, col) byte offsets and OpId item boundaries; maintained in lcide-doc and translated for LSP in lcide-lsp.
RGA (Replicated Growable Array) Sequence CRDT (Roh 2011); Items carry left-neighbor id for integration order; YATA is a refinement avoiding certain quadratic-time cases.
Room actor SessionRoom in lcide-session: single-owner async task per workspace; serializes op integration + fan-out; owns per-room Lamport clock.
SEC (Strong Eventual Consistency) Consistency model: no synchronization needed for convergence; any two correct replicas with the same op set agree (Shapiro 2011).
Sequence CRDT CRDT modeling an ordered list/string; each element has a stable opaque id; insertions specify left/right neighbors at creation time.
Site (SiteId) Stable author identity SiteId(u64) assigned at workspace join; persists across reconnections; used as the namespace in OpId.
Slow consumer A client whose send queue is consistently full; session room detects via queue capacity threshold and evicts to protect other members (P7).
Snapshot { doc_id, state_vector, materialized_items, taken_at_op } — checkpoint enabling fast recovery without replaying the full op log (I9).
StateVector Map<SiteId, u64> of highest contiguous seq received per site; the compact summary of "what this peer has seen." Drives delta computation.
Tombstone Logical deletion marker on an Item: content = Deleted. Item stays in arena for causal reference; GC removes it once below all state vectors (I4, P6).
Tombstone GC Garbage-collection pass: removes Items whose OpId is below every known peer's state-vector floor; safe because no future op can reference them.
YATA (Yet Another Transformation Approach) Sequence CRDT algorithm (Nicolaescu 2016); integration rule uses (origin_left, origin_right) pairs and Lamport tie-break to yield deterministic order without transformation functions.
