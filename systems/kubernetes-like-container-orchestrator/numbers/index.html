4.2 Hard Invariants (always hold)

  • resourceVersion monotonic — every object's resource_version == store Revision at last write; strictly increasing per keyspace; never reused, never decremented. Foundation of optimistic concurrency + watch ordering.
  • Global write serialization — orc-store assigns Revision under a single logical clock; concurrent writes totally ordered; no two writes share a Revision.
  • Watch gap-freedom — a Watch from R delivers every change with Revision > R, in Revision order, no gaps, no dups; compacted R → 410 Gone, client relists. (No correctness path tolerates a dropped event.)
  • Single-writer-per-field — kubelet is sole writer of pod.status; scheduler/controllers write spec only; scheduler is sole writer of spec.node_name. Prevents status/bind races without locks.
  • Bind exclusivity — a Pod binds exactly once (spec.node_name set via CAS; second bind → 409).
  • Reconcile idempotence — reconcile reads current desired+observed and is safe to run N times; never relies on a specific event sequence (level-triggered).

4.3 Concurrency & Consistency Model

  • Consistency: orc-store is linearizable for reads/writes within a single Revision timeline; apiserver reads served from a watch cache are bounded-stale (≤ WATCH propagation latency). Clients needing strong reads pass resourceVersion=0-bypass → direct store range.
  • No distributed locks — coordination is via CAS on resourceVersion + leader election (one active controller/scheduler instance per kind; standbys hot-idle).
  • Independent async actors — each binary is a separate Tokio process; the only shared state is orc-store; all cross-component coordination flows through watch+CAS.
  • Backpressure — slow watchers get a bounded ring buffer; overflow → close stream with 410 (client relists) rather than unbounded apiserver heap growth.

4.5 Explicit Non-Constraints (out of scope this phase)

  • No multi-region / WAN latency budget; no cloud-provider load balancer SLA.
  • No CRD/operator throughput target (Custom resource hook only — Phase 1 non-goal).
  • No full RBAC matrix performance; no service-mesh / Ingress dataplane targets.
  • No CSI plugin ecosystem SLA (hostPath/emptyDir + stub CSI only).
  • No quorum-latency budget until the Raft HA store lands (then store-write p99 shifts to the quorum column above).
