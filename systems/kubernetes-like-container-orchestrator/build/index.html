⬜ Phase 1 — Bootstrap, object-model shells, and orc-store MVCC key-value store §12

Objectives
  • Bootstrap: stand up the Cargo workspace (edition 2021, MSRV 1.78, Tokio); lay compile-only shells for every cross-crate boundary (orc-api object model, orc-store Store trait, orc-controller Reconciler/SharedIndexInformer, orc-scheduler FilterPlugin/ScorePlugin, orc-runtime ContainerRuntime); build the orc-allinone dev binary; pass the smoke test (POST a Pod → persist → GET returns it with server-assigned uid + resourceVersion); establish no-panic typed-error policy; green CI.
  • orc-store: WAL-backed keyspace with one monotonic global Revision (i64, +1 per committed mutation) as logical clock ↔ resourceVersion; ops: range/get, put, delete, txn (compare-and-set), watch (gap-free, Revision-ordered, Bookmarks), lease_grant/keepalive (TTL), compact; crash-recover via WAL replay; MVCC retention; cascade-delete leased keys on lease expiry; single-node only, raft_hook.rs seam for later HA (cross-link 42).
Deliverable
  • Smoke: cargo run -p orc-apiserver --bin orc-allinone serves REST on :8080; make smoke POSTs pod.json, GETs it, asserts round-trip + assigned uid/resourceVersion. Artifacts: Makefile, Dockerfile, docker-compose.yml, .github/workflows/ci.yml.
  • Store: orc-store crate with WAL-backed MemStore impl of Store; passes watch-gap-freedom, CAS-conflict, lease-expiry, crash-replay tests. orc-apiserver (Phase 3) links it directly; no network surface yet.

Pitfalls
  • Watch gap on concurrent write: publish outside the write lock → later rev arrives before earlier. Fix: enqueue under lock. Debug: assert per-watcher last_rev strictly increases.
  • History/live race: watcher attaches after reading history snapshot but misses gap events. Fix: register live subscription before draining history, dedup by mod_rev.
  • fsync skipped: apiserver acks a write that survives only in RAM. Fix: fsync (or group-commit) before returning rev. Debug: kill -9 harness.
  • Lease keepalive lost under load: coarse timer tick. Fix: timer wheel keyed to next expiry.
  • resourceVersion read before put commits (smoke): reading Revision separately from the put. Fix: put returns assigned Revision atomically.
  • serde deny_unknown_fields omitted: typo fields silently dropped. Set on all object types from day 0.

⬜ Phase 2 — orc-api: object model, selectors, codec, resourceVersion §13

Objectives
  • Define orc-api as the apimachinery foundation: TypeMeta, ObjectMeta, Object trait, all typed kinds → every other crate depends only on orc-api for object shapes.
  • LabelSelector matching (matchLabels + matchExpressions: In/NotIn/Exists/DoesNotExist) + field selectors; one canonical matcher used by scheduler/controller/apiserver.
  • JSON codec (serde) with apiVersion/kind tagging, lossless round-trip, unknown-field policy → wire compatibility across components.
  • resourceVersion semantics: meta.resource_version == store mod_rev decimal string; opaque/ordered; never client-authored. generation bumps on spec change only.
  • ListOptions (label+field selector, resourceVersion, limit/continue) → pagination + consistent-read contract for apiserver/informer.
Deliverable

orc-api crate (std, no tokio): all kinds encode/decode round-trip byte-identical; matches() + field-selector evaluator; ListOptions/List/WatchEvent; per-kind validate(). Unit + conformance tests green; cargo test -p orc-api passes.

Acceptance
  • Round-trip: for every kind, decode(encode(x)) == x (PartialEq), byte-stable across runs (deterministic key order).
  • Selector: conformance table (≥40 cases) all pass; matches() < 1 µs for ≤16 labels.
  • Unknown field rejected under strict mode (apiserver create), tolerated under non-strict (watch decode of newer server).
  • resourceVersion is opaque string; encoding never parses it as int in orc-api; ordering left to orc-store.
  • generation field present, defaults 1; validate() rejects empty name, non-DNS-1123, selector/template mismatch.

⬜ Phase 3 — orc-apiserver: REST CRUD, admission, namespaces, watch endpoint, optimistic concurrency §14

Objectives
  • Generic Registry<T: Object> over orc-store: kind ⇄ /registry/<kind>/<ns>/<name> key mapping; one codepath for all kinds.
  • REST handlers: create / get / list / update / patch / delete; namespaced vs cluster-scoped kinds; namespace existence + finalizer-on-delete gating.
  • Admission trait: mutating then validating chain; per-resource validation; defaulting.
  • WATCH endpoint: HTTP chunked stream of WatchEvent from a resourceVersion, Bookmarks, 410-Gone relist contract.
  • Optimistic concurrency: update carries read resourceVersion; server Txn CAS on store Revision; mismatch → 409.
  • authn/authz hook points (no-op pass-through now; filled Phase 12). NON-GOAL: RBAC matrix, webhooks (Phase 12).
Deliverable

orc-apiserver binary serving full CRUD + list + watch over the Phase-2 object model, persisted via orc-store; orctl get/apply round-trips; admission chain wired; 409 + watch-from-RV + admission-reject tests pass.

Acceptance
  • Create→Get round-trips object byte-identical except server-set uid/resourceVersion/creationTimestamp.
  • Stale-RV update → HTTP 409 Conflict with reason: "Conflict"; fresh re-read + retry succeeds.
  • Watch from RV R delivers every change with Revision > R in order, no gaps/dupes; Bookmark ≤ every 60s.
  • Watch from compacted RV → HTTP 410 Gone; client relists + re-watches at returned RV.
  • Create-into-missing-namespace → 404; rejected-by-validating-admission → 422 with cause list.
  • p99 create+watch-deliver latency < 50 ms at 1k concurrent watchers.

⬜ Phase 4 — orc-controller framework: reflector, informer, workqueue, reconciler §15

Objectives
  • Generic controller runtime in orc-controller: Reflector → DeltaFIFO → SharedIndexInformer<T> (indexed shared cache + Lister) → rate-limited dedup WorkQueue<K> → Reconciler.
  • Enforce level-triggered contract: reconcile reads CURRENT state from cache, NEVER the event payload; idempotent; missed-event-harmless.
  • Periodic resync (re-enqueue all cache keys), 410 Gone relist, exponential-backoff RateLimiter, per-item forget, leader-election hook over a store Lease.
Deliverable
  • Crate orc-controller exporting SharedIndexInformer, Lister, WorkQueue, RateLimiter, Reconciler, Reconcile, Request, Controller, LeaderElector. Example no-op reconciler binary driven by live orc-apiserver watch. cargo test -p orc-controller green.
Acceptance
  • Watch-driven enqueue: POST/UPDATE/DELETE an object → key appears in WorkQueue ≤ 50 ms; reconcile invoked from cache state.
  • Dedup: 1000 rapid updates to one key while reconcile in-flight → ≤ 2 reconciles (in-flight + 1 dirty).
  • Backoff: failing reconcile re-enqueues at 5ms,10ms,20ms… capped 1000s; forget resets to 5ms.
  • Missed-event-harmless: drop one watch event → resync (≤ 30s) re-enqueues key → cache converges to store.
  • Leader election: 3 controllers, exactly 1 active; kill holder → another acquires ≤ ttl+keepalive (≤ 20s).

⬜ Phase 5 — Core controllers: ReplicaSet, GarbageCollector, Node-lifecycle §16

Objectives
  • Implement three built-in Reconcilers on the Phase-4 framework (SharedIndexInformer + WorkQueue), all level-triggered + idempotent (read cache, drive observed → desired).
  • ReplicaSet: maintain spec.replicas Pods matching spec.selector via adopt/orphan through controller OwnerReference; create/delete Pods; write status.{replicas,readyReplicas,observedGeneration}.
  • GarbageCollector: build cluster-wide ownerRef dependency graph; cascading delete of children on owner delete; honor finalizers + blockOwnerDeletion; foreground/background/orphan policies.
  • Node-lifecycle: watch Node Lease; missed lease → Node Ready=False (NotReady); after grace → taint node.orc/unreachable:NoExecute + evict Pods so they reschedule.
  • Non-goal: Deployment/ReplicaSet orchestration (Phase 9), scheduling (Phase 6), PDB-aware drain (Phase 13).
Deliverable

orc-controller binary runs all three controllers under the framework + leader-election hook; orctl scale rs/<n> --replicas=K converges; orctl delete rs/<n> cascades to Pods; killing a node's Lease reschedules its Pods. Drives the live cluster from Phase 1–4.

Acceptance
  • Scale RS 3→10: 7 Pods created, status.replicas==10, observedGeneration==spec.generation within 2s (no scheduler).
  • Scale 10→3: 7 deleted by deletion-cost order; idempotent re-reconcile creates/deletes 0.
  • Adopt: pre-existing matching label-only Pod gains controller ownerRef; count not double-incremented.
  • delete rs (background): RS gone immediately, all child Pods deleted ≤1s; (foreground): RS lingers w/ finalizer until last child gone.
  • Node Lease lost: Ready=False ≤ grace (default 40s), taint added, Pods evicted + recreated on live nodes.

⬜ Phase 6 — orc-scheduler: filter/score scheduling framework and binding §17

Objectives
  • Watch unscheduled Pods (spec.node_name == None, no deletion_timestamp) -> enqueue into SchedulingQueue (priority + backoff sub-queues).
  • One scheduling cycle per Pod: Filter (feasible Nodes) -> Score (rank 0..100 weighted) -> Bind (write spec.node_name).
  • Filters: PodFitsResources (Node allocatable - sum of bound pod requests), NodeSelector, Taints/Tolerations, required Affinity/AntiAffinity (requiredDuringScheduling).
  • Scores: LeastRequested, MostRequested, BalancedResourceAllocation, SpreadPriority (topology), preferred affinity. Weighted-sum, pick argmax (ties -> deterministic lowest node name).
  • Bind = exclusive, write-once (Txn CAS on node_name == None); no feasible Node -> mark Unschedulable + requeue with backoff. Preemption hook: trait wired, returns None (deferred to Phase 13).
Deliverable

orc-scheduler binary: watches unscheduled Pods, binds each to a feasible Node honoring resources/selectors/taints/affinity; writes spec.node_name via apiserver CAS; emits Scheduled/FailedScheduling Events. Library exports FilterPlugin, ScorePlugin, SchedulingContext, Binding, SchedulingQueue.

Acceptance
  • Pod with requests{cpu:500m,mem:256Mi} binds only to a Node with ≥ that allocatable - already-requested; over-committed Node filtered out.
  • nodeSelector / required nodeAffinity mismatch -> Node infeasible; matching taint w/o toleration -> infeasible.
  • No feasible Node -> Pod stays Pending, status.conditions[PodScheduled]=False reason=Unschedulable, requeued (not lost).
  • Bind is write-once: concurrent second bind -> 409, no overwrite; bound node_name immutable.
  • Scheduling throughput ≥ 500 pods/s (100-Node cluster, in-mem store); per-pod p99 latency < 20ms.

⬜ Phase 7 — orc-kubelet: node agent, pod lifecycle, status, node lease, probes §18

Objectives
  • Register Node (capacity/allocatable/conditions/taints) on startup; renew its orc-store Lease (TTL 10s, renew every 2.5s) as the liveness heartbeat consumed by the Node-lifecycle controller (Phase 5).
  • Watch Pods where spec.node_name == self (field selector); spawn one PodWorker per pod; converge each to desired phase via a level-triggered sync loop reading full pod state (never per-event).
  • Drive pod lifecycle: admit -> sandbox -> pull images -> create+start containers -> Running; honor RestartPolicy with crash backoff; terminate with grace period.
  • Kubelet is the SOLE writer of pod.status (single-writer invariant); report PodStatus + Node.status via optimistic-concurrency PATCH.
  • Run liveness/readiness/startup probes via ProbeManager: liveness fail -> restart container; readiness gates EndpointSlice membership; startup gates the other two until first success.
  • Drive orc-runtime only through the ContainerRuntime trait — stubbed this phase (in-memory fake; real OCI/runc in Phase 8).
Deliverable

orc-kubelet binary: registers a Node + holds its lease, watches bound Pods, takes a bound Pod to Running against the stub ContainerRuntime, reports pod.status, and runs probes. orctl get pods -o wide shows the pod Running on the node; orctl get nodes shows Ready.

⬜ Phase 8 — orc-runtime: OCI images, runc-like container exec, cgroups/namespaces §19

Objectives
  • ImageStore: pull OCI image (Docker registry v2 / OCI distribution), verify manifest + layer digests (sha256), unpack layers into overlayfs rootfs; content-addressed, dedup by digest.
  • runc-like exec: build OciSpec, create Linux namespaces (pid/net/mnt/uts/ipc/user), apply cgroups v2 limits (cpu/memory/pids), bind mounts + pivot_root, exec entrypoint as PID 1 of pid-ns.
  • Pod Sandbox: shared net+ipc+uts namespace (pause-like infra container) the pod's containers join; per-container pid/mnt.
  • ContainerRuntime (CRI-like) impl wiring kubelet's PodWorker; restart policy + exponential crash backoff.
  • Stub runtime on non-Linux (cfg-gated) so CI + unit tests run cross-platform. NON-GOAL: image build, full registry auth flows beyond bearer/basic, GPU/devices.
Deliverable

orc-runtime launches a real container from a pulled OCI image (Linux): verified digests, overlay rootfs, enforced cgroup limits, namespace isolation; wired into orc-kubelet PodWorker. Demo: orctl apply a busybox Pod -> Running with pod.status from kubelet. Stub runtime green on macOS CI.

Acceptance
  • Image pull: manifest digest + every layer digest verified; tampered byte -> pull fails (no unpack). Re-pull of cached digest does zero network fetch.
  • memory.max=64Mi Pod that allocates 128Mi -> OOMKilled, exit 137, status reflects it; cpu.max throttles (measured <50% of one core at 50000 100000).
  • Namespace isolation: container ps sees only its tree (PID 1 = entrypoint); host PID differs; container hostname == pod name.
  • Sandbox shares net: two containers in one Pod reach each other on 127.0.0.1.
  • Crash loop: container exiting nonzero restarts with backoff sequence 10ms,20ms,…capped 5min; RestartPolicy::Never -> Failed, no restart.
