261 — DOM Event System

Goal: Implement, from scratch in Rust, the WHATWG DOM event system — the EventTarget interface (addEventListener / removeEventListener / dispatchEvent), the Event object and its flags/phases/timing, the capturing -> at-target -> bubbling dispatch algorithm with invoke / inner_invoke and listener ordering, event-path computation with shadow-tree retargeting and composedPath(), propagation control and cancelation, listener options (capture / once / passive / signal) with AbortSignal integration, default actions / activation behavior, a minimal task + microtask event loop with the trusted-event gate, and representative event interfaces — all generic over any host node tree via an EventTarget trait. It is an event-dispatch engine, not an HTML parser, a layout/paint engine, or a JavaScript engine.

Project Number: 261

Project Name: DOM Event System

Owner: Mujir Qureshi

1. Goal

Goal: A from-scratch, spec-exact WHATWG DOM event dispatch engine in Rust — given a target and an event, decide which listeners run, in what order, what propagates, and whether the default is prevented — generic over any host node tree.

1.1 What is built

A no_std + alloc Rust library (7 evt-* crates) + the domevt CLI implementing the WHATWG DOM Events model:

# Capability Spine surface
1 EventTarget interface — addEventListener / removeEventListener / dispatchEvent, exact listener list semantics + dedup add_event_listener, remove_event_listener, EventTarget trait
2 Event object — flags, phases, timing Event, EventPhase, EventFlags
3 Dispatch algorithm — capturing → at-target → bubbling, invoke/inner_invoke, listener ordering + snapshot dispatch, evt-dispatch
4 Event path — get_the_parent walk, shadow retargeting, composedPath() EventPathItem, retarget, composed_path
5 Propagation control — stopPropagation / stopImmediatePropagation / preventDefault, canceled flag EventFlags, dispatch
6 Listener options — capture / once / passive / signal + AbortSignal integration AddEventListenerOptions, evt-signal
7 Default actions / activation behavior ActivationBehavior, legacy pre/canceled hooks
8 Minimal HTML-style event loop — task + microtask queues, trusted-event gate EventLoop, TaskSource, fire_event
9 Representative event interfaces — Event, CustomEvent, UIEvent/MouseEvent/KeyboardEvent/PointerEvent shells Phase 11

Generic over a host tree via the EventTarget trait (mirrors project 258's Element trait); listener callbacks are opaque CallbackRef handles.

1.2 System boundaries — NON-goals

  • No HTML parser — host supplies an already-built node tree (reference: evt-dom).
  • No CSS / layout / paint, no hit-testing or input-device decoding — we accept already-formed events; no device → event translation.
  • No JavaScript engine — a listener is an opaque host callable (CallbackRef, equality by identity); no script binding, no value marshalling.
  • No full event-interface property sets — only fields dispatch reads (bubbles, cancelable, composed, relatedTarget, target/phase/flags); interface bodies are shells.
  • No full HTML event-loop / render scheduler — minimal task/microtask queues the host drives via tick; no rendering opportunity, no per-spec task prioritization beyond TaskSource.
  • No networking / navigation / timer subsystems — TaskSource::{Networking, Timer} are sources only, not implementations.

1.3 Deployment model & target users

  • Form: embeddable Rust library (evt-core/-path/-dispatch/-signal/-loop core; evt-dom reference tree) + domevt CLI (load, listen, dispatch, trace, bench).
  • Consumers: browser-engine + headless-DOM engines (wire their own EventTarget); test runners / WPT harnesses; automation / scraping tools; project 263's island-hydration runtime (attaches listeners to hydrated subtrees).
  • Users: browser-engine, headless-DOM, and tooling engineers.

1.4 Recommended language — Rust (edition 2021, MSRV 1.78)

Dispatch walks an untrusted tree and runs untrusted listeners that re-enter the API mid-dispatch (add/remove listeners, nested dispatch). Rationale: memory safety + precise aliasing on a re-entrant hot path; enums + exhaustive match model EventPhase/flags/path-item state at zero cost; Rc+RefCell model JS-like shared-mutable listener lists with explicit borrow discipline; Servo/Blink/spec map onto typed state machines. Rejected: C/C++ (unsafe under re-entrancy), Go (GC, weak sum types), TypeScript (want allocation control + no_std core, no JS-engine dependency).

1.5 Phase-0 deliverable — the seven crates

  1. evt-core — normative types: Event, EventPhase, EventFlags, EventListener, EventTarget trait, CallbackRef, Atom, EventError. no_std + alloc.
  2. evt-path — EventPathItem, build_event_path, retarget, composed_path.
  3. evt-dispatch — dispatch, three phases, invoke/inner_invoke, activation hooks.
  4. evt-signal — AbortController / AbortSignal (abort/timeout/any, dependent signals).
  5. evt-loop — EventLoop, TaskQueue per TaskSource, microtask checkpoint, fire_event, trusted gate. std.
  6. evt-dom — NodeRef arena (document/element/text/shadow-root/slot), impl EventTarget. std.
  7. evt-cli — domevt binary. std.

Phase-0 acceptance: workspace builds; add_event_listener + dispatch on one node fires the callback (smoke test, ## 12).

2. Why Build This

2.1 Unique systems knowledge this teaches

Concept What it forces you to internalize
Re-entrant dispatch over a mutable set A listener callback can add_event_listener / remove_event_listener / dispatch nested events mid-walk; correctness demands an inner_invoke snapshot + removed flag, not naive iteration. The hardest mutate-during-iteration problem in the DOM.
Capture / at-target / bubble propagation Path computed ONCE; three directional walks (root→target, target, target→root); per-step currentTarget / eventPhase; the DOM2 Events bidirectional model that all UI frameworks inherit.
Shadow-tree retargeting retarget(B,A) enforces an encapsulation/privacy guarantee: closed-shadow internals never leak as target/relatedTarget/composedPath(). Composed flag gates boundary crossing; non-composed paths truncate at the shadow-including root.
Passive listeners passive decouples a listener from preventDefault so the compositor scrolls without a main-thread round-trip; teaches the latency/cancelation tradeoff behind smooth scroll.
AbortSignal-scoped lifetime signal ties listener removal to an external lifetime (abort algorithm fires → listener drops); dependent (any) + timeout signals teach declarative resource teardown vs manual removeEventListener.
Event loop + microtask checkpoint Task runs to completion → drain microtasks (which may enqueue more) → next task/render. The ordering law underneath await, queueMicrotask, MutationObserver, promise scheduling.

2.2 Why it matters — historically + architecturally

  • Every user interaction (click, key, pointer, scroll) flows through dispatch(); after style/layout it is among the most-executed DOM algorithms — a hot path that runs untrusted code.
  • Canonical prior art: DOM Level 2 Events (capture/bubble, 2000) → WHATWG DOM dispatch/invoke/inner invoke; Shadow DOM v1 added retarget + composedPath(). Reference impls (Servo script, Blink EventDispatcher/EventPath, WebKit EventContext) all converge on the same typed state machine this blueprint rebuilds.
  • The trusted-event gate (isTrusted) is a security boundary: UA-generated events vs script dispatchEvent; conflating them breaks click-jacking and synthetic-input defenses.

2.3 Engineering muscles built

  • Modeling a flag/phase state machine as Rust enums + bitflags (EventPhase, EventFlags) with exhaustive match, zero-cost.
  • Shared-mutable graph discipline: Rc+RefCell listener lists with a re-entrancy-safe borrow protocol; no UB under callback re-entry.
  • Generic-over-host design: the EventTarget trait (mirrors 258's Element trait) decouples algorithm from tree; CallbackRef/OpaqueTarget keep the core no_std + JS-engine-free.
  • Differential conformance discipline: WPT dom/events + shadow-dom, fuzzing the mutate-during-dispatch surface.

2.5 Calibration value

Mid/large blueprint: 7 crates, 13 phases, ~6–9k LOC. Hard parts are semantic (re-entrancy, retargeting privacy, snapshot ordering, event-loop turn), not algorithmic-complexity-bound. Calibrates judgment on spec-fidelity engineering where a one-line ordering bug is observable web-compat breakage; the WPT suite gives an objective pass/fail bar.

2.6 What Mastery Looks Like

After building this, you can — each competency tied to the phase that forges it:

  • Reason about mutate-during-iteration as a first-class invariant (Phase 4, §16): you instinctively reach for snapshot-then-drop-borrow on any structure a callback can re-enter, and can state exactly which mutations are visible to the in-flight pass and which are deferred.
  • Implement an encapsulation boundary that survives an adversary (Phase 8, §20): you can prove, not assert, that closed-shadow internals never leak through target/relatedTarget/composedPath() for any currentTarget outside the boundary — and know the one arg-order bug (retarget(A,B) vs retarget(B,A)) that breaks it.
  • Build a three-phase directional dispatch from one frozen path (Phases 3–5, §15–§17): you can derive why the path is computed once and read three ways, and place every eventPhase/currentTarget transition correctly including the stop/cancel short-circuits.
  • Tie resource lifetime to a signal declaratively (Phase 7, §19): you can wire AbortSignal teardown that is correct under abort-mid-dispatch, dependent (any) fan-out, and once self-cleanup, with Weak links that never leak a cycle.
  • Sequence a run-to-completion event loop with a microtask checkpoint (Phase 10, §22): you understand the exact ordering law beneath await/queueMicrotask/promises and can defend why a microtask checkpoint must drain to empty (incl. re-enqueues) before the next task.
  • Defend a trusted/synthetic security boundary (Phase 10, §22): you can route isTrusted through a single authority so script can never forge it, and articulate the privilege-escalation class that conflation opens.
  • Hold the engine to a spec, not to intuition (Phase 12, §24): you can stand up a differential oracle + WPT bucket + property laws so every ordering/retargeting decision is checkable, and treat a one-line divergence as a CI-blocking regression, not a judgment call.

3.1 evt-loop

Minimal HTML-style scheduler. Responsibilities: per-TaskSource TaskQueues (Dom, UserInteraction, Networking, Timer), one microtasks queue, perform_microtask_checkpoint, host-driven tick, trusted-event gate, fire_event (UA-originated). In: host queue_task/queue_microtask + a chosen Task. Out: synchronous dispatch on a target. Invariant: task runs to completion, THEN one microtask checkpoint fully drains microtasks (incl. re-entrant enqueues) before next task/render; fire_event is the ONLY producer of is_trusted = true. Referenced by: Phase 10 (## 22) primarily; gate consumed by Phase 11/12 trusted-event tests.

3.2 evt-dispatch

Dispatch state machine. Responsibilities: dispatch() driving CapturingPhase -> AtTarget -> BubblingPhase, invoke/inner_invoke, listener snapshotting, once pre-removal, stop_propagation/stop_immediate_propagation/canceled handling, passive preventDefault guard, activation-behavior + legacy_pre_activation_behavior/legacy_canceled_activation_behavior hooks. In: (&T: EventTarget, &mut Event, legacy_target_override). Out: bool = !canceled (defaultPrevented); Event flags + current_target/event_phase mutated then reset (currentTarget=null, eventPhase=None). Invariant: path computed ONCE at start; inner_invoke iterates a SNAPSHOT (mid-invoke adds never run, removed skipped, once removed before callback); DISPATCH flag rejects re-entrant dispatch of SAME event (AlreadyDispatching) but permits nested dispatch of OTHER events. Referenced by: Phases 4–5 (## 16–17) core; extended by 9 (activation), 10 (loop-driven), 12 (conformance/fuzz).

3.3 evt-path

Propagation-path computation. Responsibilities: build Vec<EventPathItem> via get_the_parent walk, retarget(a,b), composed_path, shadow-including ancestor traversal, slot/slottable handling, related-target + touch-target retargeting. In: build_event_path(&target, &event) over a tree + event's composed flag. Out: ordered path (root..target) of EventPathItem carrying shadow_adjusted_target, related_target, touch_target_list, root_of_closed_tree, slot_in_closed_tree. Invariant: encapsulation — exposed target for item w/ invocation target A + cross-tree B is retarget(B, A); non-composed events truncate path at nearest shadow-including root containing target; composed_path() filters by closed-tree visibility relative to currentTarget. Referenced by: Phase 3 (## 15) flat tree; Phase 8 (## 20) shadow retargeting; reused by 4/12.

3.4 evt-core

Normative type layer. Responsibilities: Event, EventPhase, EventFlags, EventListener + AddEventListenerOptions/EventListenerOptions, EventTarget trait (listener registry + get_the_parent + activation hooks), CallbackRef, EventInit dictionaries, Atom (interned type), EventError, add_event_listener/remove_event_listener. In: target + (ty, CallbackRef, opts). Out: mutations to a ListenerListRef; constructed/initialized Events. Invariant: listener dedup key is (type, callback identity, capture) — duplicate add is a no-op; passive/once/signal NOT part of key; preventDefault sets CANCELED only when cancelable && !IN_PASSIVE_LISTENER. Referenced by: every crate + phase; established in Phases 0–1 (## 12–13), extended for options in Phase 6 (## 18).

3.5 evt-signal

Abort integration. Responsibilities: AbortController + AbortSignal (aborted, reason, abort_algorithms, source_signals/dependent_signals), abort, timeout, any, throw_if_aborted, follow relationship, addEventListener's signal option. In: a signal handed to a listener add, or host abort/timeout trigger. Out: abort algorithms that REMOVE the associated listener from its list. Invariant: firing once sets aborted + reason permanently and runs each abort algorithm at most once; dependent signals (any) abort exactly when any source_signals member aborts; weak refs prevent controller<->signal cycle leaks. Referenced by: Phase 7 (## 19); aborts exercised under re-entrancy in Phases 5/12.

3.6 evt-dom

Concrete reference tree. Responsibilities: Node arena (document, element, text, shadow root, slot) impl EventTarget + tree hooks; open/closed shadow trees (ShadowMode); slot assignment. In: programmatic tree construction + listener registration via NodeRef. Out: a host tree whose get_the_parent drives evt-path. Invariant: flat tree honors slot assignment + shadow encapsulation so retargeting/composedPath are deterministic + spec-faithful; only std-linked tree backing tests, CLI, conformance, fuzzing. Referenced by: Phase 2 (## 14) flat tree; Phase 8 (## 20) shadow/slots; test/conformance substrate for Phases 4–12.

3.7 evt-cli

The domevt binary. Responsibilities: subcommands load, listen, dispatch, trace, bench over an evt-dom tree. In: scenario fixtures + CLI args. Out: dispatch results, per-step propagation traces, benchmark numbers. Invariant: thin host driving public API only (no privileged internals); all serialization off the dispatch hot path. Referenced by: Phase 12 (## 24) for differential traces + benchmarks; usable as debugging harness from Phase 4 onward.

4. System Constraints

In-process library; the only "resource" budgets are CPU latency, allocation, and bounded recursion. No NUMA, network, file-descriptor, or disk budgets — evt-core/evt-path/evt-dispatch/evt-signal are no_std + alloc; std only in evt-dom/evt-loop/evt-cli. Startup = zero global init (no lazy_static, no ctor, no thread-locals at load); Atom table and arenas are constructed explicitly by the host.

4.1 Latency Targets (synchronous dispatch)

Scenario p50 p95 p99 Notes
Single target, 0 listeners (path build + phase walk) < 80 ns < 300 ns < 1 µs path len 1; no invoke calls
Single target, ≤4 listeners, no bubble < 200 ns < 1 µs < 5 µs inner_invoke over snapshot, zero alloc
Bubbling, depth 100 < 6 µs < 20 µs < 60 µs O(depth) get_the_parent + per-item invoke
Bubbling, depth 1000 < 60 µs < 200 µs < 600 µs linear in depth; no super-linear term
Shadow retarget, depth 100, 4 boundaries < 12 µs < 40 µs — retarget O(1) amortized per path item
composed_path() recompute, depth 100 < 4 µs < 15 µs — filter saved path by closed-tree gates

Path build is O(depth), computed ONCE per dispatch. retarget(a,b) is O(shadow-including-ancestors of b); cached per dispatch so total path build stays O(depth). No per-listener heap walk: listener list is one Vec.

4.2 Memory

Item Budget
EventListener record ≤ 48 B (Atom u32 + CallbackRef ptr + 3 bool/Option bytes; Vec-backed)
EventPathItem ≤ 64 B; path: Vec<EventPathItem> reserved to depth once
inner_invoke snapshot ZERO steady-state alloc — reusable SmallVec<[ListenerSlot; 8]> thread-local-free scratch passed down the call stack
Event object ≤ 128 B + path Vec (single allocation)

inner_invoke MUST NOT allocate on the hot path; the snapshot buffer is reused across invoke calls within one dispatch (grown only on first overflow past inline cap 8).

4.3 Hard Caps (DoS / re-entrancy)

Cap Limit On breach
MAX_PATH_DEPTH (path build) 8192 truncate path at cap, emit diagnostic; dispatch still completes safely
MAX_LISTENERS_PER_TARGET 65 536 add_event_listener becomes a no-op + diagnostic (dedup key unaffected)
MAX_NESTED_DISPATCH_DEPTH 64 nested dispatch returns EventError::AlreadyDispatching-class guard; no stack overflow
Microtask checkpoint work bounded-work diagnostic only (warn past N drained or T elapsed) — never silently drops tasks

Re-entrancy invariant: DISPATCH flag set for in-flight event ⇒ re-dispatching the SAME event (or an Uninitialized one) yields EventError::AlreadyDispatching / Uninitialized; nested dispatch of OTHER events allowed up to MAX_NESTED_DISPATCH_DEPTH.

4.4 Robustness & Availability

  • Never panics on adversarial input (cyclic/oversized trees, malformed Event, hostile get_the_parent, callbacks that mutate the list or nest-dispatch mid-invoke): all fallible paths return Result<_, EventError>, enforced by Phase-12 fuzz over tree shape, listener-mutation-during-dispatch, and shadow boundaries.
  • Bounded recursion: dispatch is iterative over the precomputed path; only nested dispatch consumes host stack, capped at 64. A malformed event or pathological tree can never take down the host — caps + Result + no-panic bound CPU/stack/memory to the limits above; the host keeps ticking the EventLoop.

6. Design Principles

Non-negotiable for project 261; each referenced by name in Phases (## 12–## 24). Violation predicts a named defect class.

6.1 Spec is the oracle

Rule: WHATWG DOM ("Events", "Aborting ongoing activities") + HTML ("event loop", activation, trusted events) are normative; algo names (dispatch, invoke, inner_invoke, retarget, build event path) mirror spec prose 1:1; UI Events fixes interface defaults. Tradeoff: fidelity over intuition — legacy-pre-activation + legacy_target_override stay, web-compat only. Op: every decision cites a spec step; Phase 12 (§24) runs WPT dom/events+shadow-dom + differential vs Servo/Blink/jsdom, no "looks right". Breaks: silent web-incompat; un-auditable divergence, no ground truth.

6.2 Dispatch is re-entrant-safe

Rule: a CallbackRef MAY mid-dispatch add/remove listeners on any target + dispatch OTHER events; realized via Rc+RefCell lists; never hold a RefCell borrow across a callback. Tradeoff: snapshot cost (one Vec clone/invoke) + runtime borrow checks vs zero-cost-unsafe aliasing. Op: inner_invoke drops all borrows before calling; loom/miri + re-entrancy fuzz (Phase 4/12); same-event re-dispatch → AlreadyDispatching. Breaks: RefCell borrow-panic/UB on the #1 real pattern (handlers mutating handlers) — top crash source.

6.3 Compute the path once

Rule: build_event_path runs ONCE at dispatch start over the ancestor chain; the Vec<EventPathItem> is frozen for capturing→at-target→bubbling; tree mutation during dispatch does NOT alter it. Tradeoff: one upfront O(depth) walk+alloc vs re-walking per phase (spec-wrong, O(depth²)). Op: capturing root→target (excl.); at-target = target's listeners; bubbling target→root only if event.bubbles; composedPath() served from the saved path. Breaks: listeners on detached/moved nodes get wrong (in)visibility; composedPath() lies; quadratic blowup on deep trees.

6.4 No encapsulation leak

Rule: retarget(B, A) MUST never expose closed-shadow internals across a boundary — for item with invocation target A + related/touch target B, exposed = retarget(B, A); non-composed events truncate path at the nearest shadow-including root containing target. Tradeoff: retargeting math + per-item root_of_closed_tree/slot_in_closed_tree bookkeeping vs naive pass-through. Op: shadow_adjusted_target/related_target/every touch_target_list entry retargeted per item; composed_path filters by closed-tree visibility rel currentTarget; Phase 8 (§20) tests open-vs-closed asymmetry. Breaks: security/privacy — light-tree script reads closed-shadow node identities; conformance failure with exploit surface.

6.5 Passive means passive

Rule: in a listener with effective passive==true (IN_PASSIVE_LISTENER set), preventDefault is a no-op + diagnostic; MUST NOT set CANCELED. Tradeoff: ignoring author intent vs honoring the compositor-scroll contract — contract wins. Op: default-passive types (touchstart/touchmove/wheel-class, Phase 6) start passive unless explicit passive:false; guard in the preventDefault path, gated on IN_PASSIVE_LISTENER. Breaks: passive handler blocks the compositor → janky/blocked scrolling, the regression passive prevents.

6.6 Listener identity is the dedup key

Rule: dedup key = (type, callback identity, capture); CallbackRef eq-by-identity; duplicate add is a no-op; passive/once/signal NOT in key. Tradeoff: identity-keyed sets ignore option drift (2nd add w/ diff once dropped) vs multiplicity (spec-wrong, double-fires). Op: add_event_listener checks key before insert; remove_event_listener(ty,cb,capture) matches the same triple; Phase 1/6 fixtures cover capture-vs-bubble as distinct entries. Breaks: handlers fire twice / fail to remove — classic web bug (double form-submit, leaked listeners).

6.7 Synchronous dispatch, asynchronous firing

Rule: dispatch is fully synchronous — returns only after every listener + default action ran; UA "firing" is async (queue_task → later tick → fire_event → synchronous dispatch). Tradeoff: sync re-entrancy complexity (§6.2) vs ordering guarantees authors depend on. Op: fire_event (evt-loop) is the only async entry; script dispatchEvent + invoke never yield; render/microtask interleave only between tasks. Breaks: observable ordering changes; e.defaultPrevented after dispatchEvent wrong; subtle author-visible reordering.

6.8 Trusted is user-agent-only

Rule: is_trusted==true ONLY for events evt-loop creates+dispatches (fire_event sets it); script dispatchEvent always false; no API forges it. Tradeoff: immutable UA-gated bit vs author convenience — security wins. Op: trusted gate solely in evt-loop; Event ctor defaults is_trusted=false; Phase 10 (§22) tests the gate. Breaks: synthetic events bypass trust checks (forged activation/click) — privilege-escalation class.

6.9 Once removed before invocation

Rule: a once listener is removed from the real list BEFORE its callback runs (during inner_invoke, after the snapshot is captured). Tradeoff: mutate-then-call vs simpler call-then-remove (double-fires on nested re-dispatch). Op: inner_invoke order = snapshot → set removed / remove-if-once on real list → drop borrow → call; nested dispatch of the same type sees it gone. Breaks: once fires twice under re-entrancy — conformance + idempotency failure.

6.10 Snapshot, then iterate

Rule: inner_invoke iterates a SNAPSHOT taken at invoke time; listeners added during invoke NOT called; listeners flagged removed (incl. via §6.9/§6.13) skipped. Tradeoff: snapshot alloc per phase-step vs iterator invalidation / unbounded loops. Op: stopImmediatePropagation halts remaining listeners on the CURRENT target; stopPropagation halts subsequent path items (checked between items); both read EventFlags, not the snapshot. Breaks: add-during-dispatch causes infinite/order-dependent fires; iterator-invalidation UB without snapshotting.

6.11 Bounded everything

Rule: hard configurable caps — event-path depth, listeners-per-target, listeners-per-type, nested-dispatch depth; exceeding = a defined non-panicking error/clamp, never unbounded recursion/alloc. Tradeoff: rejecting pathological-but-legal trees vs DoS resistance on an untrusted tree + callbacks. Op: nested-dispatch counter on loop/dispatch context; path build clamps at max depth; fuzz (Phase 12) targets caps; defaults in Operational Readiness. Breaks: stack overflow / OOM from a deep tree or recursive re-dispatch — remote-DoS surface.

6.12 Generic over the host tree

Rule: core generic over the EventTarget trait (listeners/get_the_parent/activation_behavior/legacy hooks/opaque); no concrete DOM in evt-core/path/dispatch; NodeRef is ONE impl, mirrors project 258's Element trait. Tradeoff: trait indirection + OpaqueTarget erasure vs a monomorphic faster-but-coupled engine. Op: tests/CLI/fuzz use evt-dom; an embedder supplies its own tree; path/dispatch touch nodes only via trait methods + OpaqueTarget. Breaks: engine fuses to one tree model, un-reusable/un-testable in isolation — layering rot.

6.13 Signal-driven removal

Rule: addEventListener's signal ties listener lifetime to an AbortSignal; on abort a registered abort algorithm removes the listener (sets removed); already-aborted at add → never registers. Tradeoff: weak back-refs (WeakVec source/dependent) + bookkeeping vs manual removeEventListener. Op: evt-signal integrates with the evt-core add path; AbortSignal::any/timeout propagate via dependent/follow links; removed-mid-dispatch listener skipped per §6.10. Breaks: listener leaks after abort (memory + spurious fires); broken AbortController ergonomics.

6.14 Microtask-checkpoint discipline

Rule: a task runs to completion, THEN perform_microtask_checkpoint drains the microtask queue (may enqueue more) fully before the next task/render; performing_checkpoint guards re-entry. Tradeoff: strict drain-to-empty vs interleaving microtasks with task steps (spec-wrong). Op: tick = run one task → checkpoint; queue_microtask appends to microtasks; no listener/task observes a half-drained queue. Breaks: promise/microtask ordering diverges from browsers — observable async-timing bugs awaiting between events.

6.15 Observable dispatch

Rule: dispatch/invoke/inner_invoke/path build/retarget/loop ticks expose structured trace hooks (consumed by domevt trace), zero-cost when disabled. Tradeoff: hook plumbing + feature-gated overhead vs an opaque black-box engine. Op: traces are the primary debugging + differential-diff surface (Phase 12); hooks compile out under default features on the hot path. Breaks: un-diagnosable ordering/retargeting bugs; can't localize a differential-test mismatch to a step.

6.16 Flags are the state machine

Rule: EventFlags (STOP_PROPAGATION, STOP_IMMEDIATE_PROPAGATION, CANCELED, IN_PASSIVE_LISTENER, COMPOSED, INITIALIZED, DISPATCH) + EventPhase are the single source of truth for dispatch state (enums/bitflags, exhaustive match); currentTarget/eventPhase set per step, reset (null/None) after dispatch. Tradeoff: centralized flag discipline vs ad-hoc booleans across call sites. Op: DISPATCH enforces the §6.2 re-entrancy guard (AlreadyDispatching); defaultPrevented == CANCELED; uninitialized dispatch → Uninitialized. Breaks: inconsistent stop/cancel handling, leaked currentTarget after dispatch, missing re-entrancy guards — divergent untestable control flow.

7.3 Cross-cutting enforcement & trace conventions

  • Single reset guard: current_target, event_phase, DISPATCH clearing (INV-06, INV-07) share one RAII drop-guard set in dispatch's prologue, so every return path (normal, stopPropagation, Err) restores state — no manual reset duplicated.

8.3 Dispatch algorithm + EventPhase state machine

dispatch<T: EventTarget>(target, event, legacy_target_override) -> bool (returns !canceled). Ordered steps:

D1  if ¬INITIALIZED        -> Err(Uninitialized)            // throws
D2  if DISPATCH            -> Err(AlreadyDispatching)       // InvalidStateError
D3  set DISPATCH; clear STOP_PROPAGATION|STOP_IMMEDIATE_PROPAGATION|CANCELED
D4  event.target = target.opaque() (or override); is_trusted unchanged
D5  event.path = build_event_path(target, event)           // §8.4, ONCE
D6  legacy_pre_activation_behavior() on activation target if any
D7  CAPTURING: for item in path[root .. target)  (top-down, EXCLUDE target)
        if STOP_PROPAGATION break;  invoke(item, event, CapturingPhase)
D8  AT_TARGET: invoke(target_item, event, AtTarget)        // unless STOP_PROPAGATION
D9  BUBBLING: if event.bubbles: for item in path(target .. root]  (bottom-up, EXCLUDE target)
        if STOP_PROPAGATION break;  invoke(item, event, BubblingPhase)
D10 event_phase = None; current_target = None
D11 if CANCELED: legacy_canceled_activation_behavior() else activation_behavior()(event)
D12 clear DISPATCH; return ¬CANCELED

invoke(item, event, phase): set current_target = item.invocation_target; compute exposed target/related_target via item's shadow_adjusted_target/related_target; select listeners matching phase (capture-flag ⇔ Capturing; AtTarget runs both in registration order); inner_invoke.

inner_invoke(event, listeners, phase) -> bool: iterate a SNAPSHOT of listeners; per listener: skip if removed; skip if capture-flag mismatches phase (except AtTarget); if once remove from REAL list before calling; set IN_PASSIVE_LISTENER iff passive; run callback; clear IN_PASSIVE_LISTENER; if STOP_IMMEDIATE_PROPAGATION return early.

EventPhase transition table (None=0,Capturing=1,AtTarget=2,Bubbling=3):

From Trigger To
None dispatch D7, path has pre-target items CapturingPhase
None D7 empty (target is root) → D8 AtTarget
CapturingPhase path exhausted above target → D8 AtTarget
CapturingPhase STOP_PROPAGATION set (jump) AtTarget? no — D8 guarded; effectively None at D10
AtTarget D9, bubbles true BubblingPhase
AtTarget bubbles false OR STOP_PROPAGATION None (D10)
BubblingPhase path exhausted OR STOP_PROPAGATION None (D10)

Note: AtTarget always runs unless STOP_PROPAGATION set during capturing; event_phase is AtTarget while target listeners run regardless of capture flag.

8.4 Listener list, get_the_parent, EventPathItem

EventTarget trait (evt-core): listeners() -> ListenerListRef (shared-mutable Rc<RefCell<Vec<EventListener>>>), get_the_parent(&self,&Event) -> Option<Self>, activation_behavior(), opaque().

EventListener fields: ty:Atom, callback:CallbackRef, capture:bool, passive:Option<bool>, once:bool, signal:Option<AbortSignalRef>, removed:bool. Dedup key = (ty, callback identity, capture); duplicate add = no-op; passive/once/signal excluded from key.

get_the_parent: flat-tree parent during dispatch — element→parent node; slotted node's parent is its assigned slot; shadow root's parent is its host iff event composed or current target is the shadow root (else None, truncating path); Document→None.

build_event_path(target, event): walk get_the_parent target→root, one EventPathItem per node (target first, root last); per item compute shadow_adjusted_target, related_target (via retarget), closed-tree gate bits.

EventPathItem fields:

Field Type Meaning
invocation_target OpaqueTarget node whose listeners run here (current_target)

shadow_adjusted_target Option<OpaqueTarget> exposed event.target here (None ⇒ unchanged); Some only at shadow-tree boundaries

slot_in_closed_tree bool item is a slot inside a closed shadow tree

retarget(a, b) -> OpaqueTarget: while a's root is a shadow root AND b not a shadow-including inclusive descendant of a's root → a = a.root.host; return a. Encapsulation: closed internals never leak as target/relatedTarget.

16. Phase 4 — Core dispatch algorithm (capture / at-target / bubble)

4.1 Objectives

  • Implement evt-dispatch::dispatch<T: EventTarget>(target, event, legacy_target_override) -> bool returning !CANCELED.
  • Drive 3 phases over the Phase-3 path: CapturingPhase (root→target, exclusive), AtTarget, BubblingPhase (target→root, only if event.bubbles).
  • Spec invoke+inner_invoke with listener snapshot: mid-dispatch adds excluded; removed skipped; once removed from real list before callback.
  • Entry: set DISPATCH + event.target. Per step: mutate current_target/event_phase. Exit: reset both to None.
  • Scope = ordering + phase walk + snapshot only. Out of scope: stop*/preventDefault/passive (P5), signal removal (P7), retargeting/closed-tree gates (P8), activation (P9). At-target retarget = identity; honor shadow_adjusted_target if present.
  • Constraint: callbacks RE-ENTER (add/remove/nested dispatch) → never hold live borrow of listeners() across a callback.

  • Path: event.path = build_event_path(target, event) (P3); target_index = last item where invocation_target == event.target.
  • Walk (index ranges over path, struct-of-indices, no closures over the list):

17. Phase 5 — Propagation control and cancelation

  • Remove then re-add same key within one inner_invoke → re-add targets real list; snapshot still runs (now-removed) original once.
  • passive:Some(false) explicit on default-passive type → honors explicit false (overrides default).
  • Duplicate add where survivor is removed=true (pending GC) → treated as absent → new add succeeds.
  • capture toggled across two adds of same cb → two independent listeners, two independent once flags.

6.9 Failure Analysis

  • Mis-bucketing (capture listener in non-capture Vec) → phase-ordering corruption; blast radius = all dispatches on target; detect via mixed_buckets.json ordering assert; recover by rebuild from registration log.
  • Passive bit leak (never cleared) → all subsequent preventDefault silently no-op app-wide; detect: invariant IN_PASSIVE_LISTENER clear between top-level dispatches; operator sees passive_pd_blocked spike.
  • Dedup regression → unbounded listener growth → memory creep + N× callbacks; detect: per-target listener-count gauge + dup assertion in debug builds.

25. Threat Model

Attack surface = (a) an untrusted host node tree (arbitrary depth/shape, adversarial shadow nesting), (b) untrusted RE-ENTRANT listener callbacks (CallbackRef) that mutate the listener list / dispatch nested events mid-inner_invoke, (c) adversarial event sequences driven through dispatch / EventLoop::tick. 25.3 Encapsulation / privacy analysis (closed shadow trees)

  • Retarget invariant (LOCKED): for path item with invocation target A and related/touch target B, exposed = retarget(B, A) ⇒ B never observable to a current_target outside B's shadow-including root. Property test: ∀ closed-tree node X, ∀ outer current_target C: composed_path(event, C) ∌ X and event.target/related_target seen by C is the retargeted ancestor, not X.
  • Composed flag: composed=false ⇒ path truncated at nearest shadow-including root containing target; events cannot escape the tree they fire in.
  • composedPath() gating: filters saved path by root_of_closed_tree / slot_in_closed_tree relative to current_target — closed roots/slots elided, no node-count side-channel beyond spec.
  • Open vs Closed: Open mode exposes shadow root via host API; Closed mode never does — ShadowMode::Closed must not leak child node ids, slot assignment, or sibling counts through any path item or EventPathItem.shadow_adjusted_target.

25.5 Residual risk & assumptions

  • A CallbackRef may run arbitrarily long / loop forever — out of scope (host owns interruption/timeouts; we are not preemptive). Documented non-goal.
  • Caps are DoS bounds, not correctness limits; legitimate workloads stay ≪ caps. Hitting a cap = EventError (T1/T8) or no-op (T2/T6/T7), never UB / panic / leak.
  • Wall-clock side channels (callback timing → tree shape) are NOT mitigated; spec-level composedPath gating is the privacy contract, nothing stronger.
  • Memory safety + encapsulation hold under ALL re-entrant interleavings (Phase 12 fuzzing + property tests are the gate; retarget_invariant_fail_total and spoofed_trusted_total must be 0).

F1 — Listener not firing (S1, TOP)

  • Symptoms: registered callback never invoked; trace shows the path item present but the listener absent from the snapshot, or in the wrong phase bucket. Root causes: (a) dedup-key mismatch — (type, callback identity, capture) with the wrong CallbackRef identity (clone vs same handle) → re-add silently no-ops/never matches; (b) bucket bug — capture=true listener queried in the bubble walk; (c) snapshot taken AFTER removed/clear. Detect: WPT dom/events/AddEventListener*; debug_assert! snapshot non-empty when ≥1 matching listener registered; trace diff vs expected. Recover: none (correctness) — fail loud; domevt trace --listeners dumps live list + dedup-key per registration vs per-item snapshot. Operator: verify Atom interning identical register-vs-dispatch; CallbackRef identity holds across host marshaling. Forensic: snapshot vector + dedup-key table per item. Long-term: property "any registered (ty,cb,capture) with no stop* fires exactly once"; snapshot precedes any mutation.

F6 — Retargeting wrong = encapsulation leak (S0, GRAVEST — privacy)

  • Symptoms: event.target/relatedTarget/composedPath() exposes a node inside a closed shadow tree to an outside listener; non-composed event observed above its shadow-including root. Root causes: retarget(b,a) arg order swapped; shadow_adjusted_target not recomputed per item; non-composed path not truncated at the shadow-including root; root_of_closed_tree/slot_in_closed_tree gates inverted in composed_path. Detect (CI-blocking): leak oracle — per item, assert the exposed OpaqueTarget is shadow-including-ancestor-visible to current_target; WPT shadow-dom/event-*; differential vs Servo/Blink retarget tables; any failure fails the build. Recover: fail-closed — on gate uncertainty expose null/host, never the internal node; domevt trace --retarget prints per-item adjusted/related targets + closed flags. Operator: audit composed; confirm ShadowMode::Closed boundaries in the tree dump. Forensic: full Vec<EventPathItem> + retarget I/O. Long-term: fuzz random open/closed trees + slot assignments; invariant "no exposed target crosses a closed boundary"; security regression class.

F2 — Listener fires twice (S1)

  • Causes: once listener not removed from real list BEFORE callback runs; dedup admitted duplicate (passive/once/signal wrongly in key). Detect: assert invoke count per dedup-key ≤1 within an invoke; WPT once tests. Recover: none (loud). Forensic: per-key invoke counter. Long-term: property "once ⇒ exactly one invocation across all future dispatches".

F3 — Wrong invocation order (S1)

  • Causes: path built target→root instead of root→target; at-target not interleaving capture+non-capture in registration order; bubbling walks wrong direction or runs when bubbles=false. Detect: ordered-sequence assertion in trace; WPT propagation tests. Forensic: (seq, phase) per invoke. Long-term: golden ordered traces per fixture; EventPhase monotonicity assert (1→2→3).

F4 — stop* not honored (S1)

  • Causes: STOP_IMMEDIATE_PROPAGATION checked after next listener; STOP_PROPAGATION not gating subsequent path items; flag cleared between items. Detect: assert no invoke after flag set (immediate=this item, propagation=later items); WPT stop tests. Forensic: flags snapshot at each listener boundary. Long-term: property "post-stopImmediate count in item == 0".

F5 — preventDefault leaks through passive listener (S2)

  • Causes: IN_PASSIVE_LISTENER not set during passive invoke → preventDefault sets CANCELED. Spec: in passive listener preventDefault is no-op + diagnostic. Detect: assert CANCELED unset after passive-only dispatch; check default-passive types resolve passive. Recover: suppress cancel; emit diagnostic count. Forensic: passive-flag + cancel-attempt log. Long-term: property "passive listener cannot set CANCELED".

F7 — composedPath() wrong (S1)

  • Causes: returns unfiltered saved path; visibility computed vs target not current_target; closed-tree gates misapplied. Detect: WPT composedPath tests; differential vs Blink. Forensic: saved path + filter decision per node. Long-term: shared filter oracle with F6 leak check.

F8 — AbortSignal not removing listener (S1)

  • Causes: abort algorithm not registered when signal option present; already-aborted signal not rejecting add_event_listener; dependent/timeout signal abort not propagated to source listeners; WeakVec dropped algorithm. Detect: WPT abort tests; assert listener gone after AbortSignal::abort. Recover: none. Forensic: signal→listener linkage dump. Long-term: property "post-abort, signaled listeners never fire"; test AbortSignal::any/timeout fan-out.

F9 — Nested-dispatch corruption / iterator invalidation (S1)

  • Causes: same Event re-dispatched mid-dispatch not caught (must throw AlreadyDispatching); RefCell borrow held across callback re-entering add/remove_event_listener → panic/UB-shaped; snapshot aliasing live list during nested dispatch. Detect: DISPATCH flag guard returns EventError::AlreadyDispatching; nested dispatch of OTHER events allowed; fuzz re-entrant add/remove/dispatch. Recover: guard rejects; borrows scoped before callback. Forensic: dispatch-stack depth + flag log. Long-term: never hold a listener list borrow across a CallbackRef invoke; loom/concurrency-style re-entrancy fuzz.

F10 — Microtask checkpoint re-entrancy (S1)

  • Causes: perform_microtask_checkpoint re-entered while performing_checkpoint=true (callback queues+drains microtasks recursively) → unbounded recursion/reordering. Detect: assert performing_checkpoint re-entry is no-op (enqueue only); fixture queuing microtask from microtask. Recover: guard flag — nested calls enqueue, do not drain. Forensic: checkpoint depth + microtask count. Long-term: invariant "≤1 active checkpoint; queued-during-drain run in same drain, FIFO".

F11 — Event-loop task starvation (S2)

  • Causes: one TaskSource (e.g. Timer) monopolizes tick; microtask queue never empties (callback re-enqueues forever). Detect: per-tick task/microtask budget counter; bench watchdog. Recover: round-robin/oldest across TaskSource; cap microtask drain iterations w/ diagnostic. Forensic: per-source queue depths over ticks. Long-term: fairness property test; surface starvation metric in domevt bench.

31.3 Allocator analysis

path: Vec<EventPathItem> + per-invoke snapshot are SmallVec<[_; N]> (N=16 path covers ~99% real DOM depth, N=8 snapshot) → zero heap alloc for shallow/typical. inner_invoke copies live entries into a reused thread-local buffer (cleared, not freed) → steady-state alloc = 0 (dhat-verified); heap only on depth/listener overflow. Re-entrant nested dispatch uses a depth-indexed pool of snapshot buffers → nested invokes alloc-free, pool grows once to max observed depth.

31.4 Branch prediction — phase switch

Per-item match event.event_phase {Capturing|AtTarget|Bubbling} mispredicts only at the 2 phase boundaries/dispatch (amortized 0 on deep trees); the phase decision is hoisted OUT of the per-listener loop (constant across one invoke), EventPhase is #[repr(u8)] → jump-table not chained compares. EventFlags stop/cancel checks are predictable bitand on a hot register (almost-always-not-set) → cost ≈ 0 until triggered.

31.5 Lock analysis

No locks — dispatch is single-threaded per loop, engine !Send/!Sync by design. RefCell borrows on ListenerListRef are aliasing checks not locks, held only across the snapshot copy (µs) and released before any CallbackRef runs → re-entrant add/remove cannot hit BorrowMutError. The node tree is read-mostly during dispatch; structural mutation is outside dispatch; concurrency is the host's problem (no contention model).

31.6 Passive-listener compositor benefit

passive:true sets IN_PASSIVE_LISTENER → preventDefault is a no-op (diagnostic only) → the compositor need NOT block on JS for scroll/touch/wheel cancelation. Default-passive types (touchstart/touchmove/wheel/mousewheel on roots) get this implicitly → scroll-jank elimination: the compositor proceeds in parallel rather than awaiting dispatch p99 (budget: §35 C8).

31.7 Tail-latency analysis

Deep trees: O(depth), no per-item alloc → p99 tracks depth linearly, no GC pauses (no GC); tail risk = SmallVec spill past depth 16 (one amortized alloc), pre-reserve when depth known. Huge listener lists: once removal is O(1) swap-mark before callback, the removed sweep deferred/amortized → a 1 000-listener target stays O(n)/dispatch not O(n²); the p99 spike source is pathological add-during-dispatch growth, bounded by the snapshot (new listeners excluded this invoke). Adversarial (fuzz-derived) listener-thrash + nested dispatch is profiled worst-case p99.9, asserted bounded vs §4 budgets.

33. Mental Models & First Principles

The compressed insights a principal engineer holds about DOM event dispatch. Each: the model, what it lets you predict, the bug class you write without it, and the resolving section reference.

MM1 — The path is a frozen filmstrip, read three ways. build_event_path shoots one strip of EventPathItems root→target ONCE; capturing plays it forward (root→target), at-target is one frame, bubbling plays it backward (target→root). Predicts: tree mutation mid-dispatch never adds/removes a frame; composedPath() is the same strip re-filtered, never re-walked. Without it: you re-walk get_the_parent per phase → O(depth²), and listeners on moved/detached nodes get the wrong (in)visibility. Resolves: §6.3, §8.4, INV-01 (Phase 3, §15).

MM2 — inner_invoke iterates a photograph, not the live list. At invoke entry you clone the listener list into a snapshot, drop the borrow, then call. Adds during the call land in the live Vec (not the photo); removals flip a removed tombstone the photo re-checks; a once listener is torn out of the live list before its callback so a nested same-type dispatch can't re-find it. Predicts: exactly which mutations are visible this pass vs deferred. Without it: iterator-invalidation UB, infinite self-feeding loops, once double-fire under re-entrancy. Resolves: §6.9, §6.10, §8.3, INV-02/03 (Phase 4, §16).

MM3 — retarget(B, A) is a one-way mirror at every shadow boundary. Standing at invocation target A, any cross-tree node B you'd expose is first climbed to the nearest ancestor A is allowed to see. Closed internals are behind the mirror; you only ever see the boundary host. Predicts: arg order is load-bearing — retarget(B, A), never retarget(A, B); relatedTarget and every touch target get the same treatment per item. Without it: a light-DOM listener reads closed-shadow node identities — a privacy/security leak (the gravest failure, F6). Resolves: §6.4, §8.4, §8.5, INV-08 (Phase 8, §20).

MM4 — composed is the boundary's one-bit passport; absence truncates the trip. A composed event's path crosses shadow roots via the host hop; a non-composed event's get_the_parent returns None at the shadow-including root, so the path simply ends there. Predicts: a non-composed event physically cannot reach a listener above its own shadow root; composedPath() from outside that tree is empty. Without it: you append the host anyway and fire listeners that spec says never run. Resolves: §6.3, §8.7, INV-09 (Phase 8, §20).

MM5 — Flags are the only state; currentTarget/eventPhase are scratch. Seven EventFlags bits + the phase enum are the dispatch state machine; currentTarget/eventPhase are set per step and MUST reset to null/None at every exit. defaultPrevented is literally CANCELED ∈ flags; DISPATCH is the re-entrancy interlock. Predicts: a single RAII drop-guard clearing these covers every return path (normal, stop, Err, panic-unwind). Without it: leaked currentTarget after dispatch, missing re-entrancy guard, ad-hoc booleans that disagree across call sites. Resolves: §6.16, §8.2, INV-06/07 (Phase 5, §17).

MM6 — passive trades cancelability for a parallel compositor. A passive listener's preventDefault is a deliberate no-op so the compositor scrolls without awaiting the main thread. The contract is one-directional: IN_PASSIVE_LISTENER set ⇒ cancel suppressed, never the reverse. Predicts: default-passive types (touchstart/touchmove/wheel/mousewheel on roots) start passive precisely to keep scroll off the JS critical path. Without it: a passive handler that "cancels" silently blocks scroll, or you honor a cancel you must ignore — the jank passive exists to prevent. Resolves: §6.5, §8.8, INV-05 (Phase 6, §18).

MM7 — A task is a turn; the microtask checkpoint is the turn's settling. One task runs to completion, then the checkpoint drains all microtasks (including those they enqueue) before the next task or render. The checkpoint is non-re-entrant: a microtask requesting another checkpoint enqueues, it does not nest. Predicts: the exact ordering of await, queueMicrotask, MutationObserver, promise jobs relative to events. Without it: promise/microtask ordering diverges from every browser — async-timing bugs that only bite between events. Resolves: §6.14, INV-10 (Phase 10, §22).

MM8 — Trust is conferred by the door you entered, not the claim you make. isTrusted=true is set by exactly one authority (fire_event); script's dispatchEvent is structurally incapable of forging it (private field, crate-sealed). Predicts: synthetic input can never trip a UA-only default action gated on isTrusted. Without it: click-jacking / synthetic-input defenses collapse — a privilege-escalation class. Resolves: §6.8, INV-11 (Phase 10, §22).

MM9 — The engine bounds itself, never the callback. A CallbackRef is opaque host code that may loop forever or recurse; the engine cannot preempt it, so it instead caps its own resources — path depth, listeners/target, nested-dispatch depth, microtask budget — and turns every breach into a defined EventError/no-op, never a panic or UB. Predicts: a pathological tree or listener-bomb degrades to a diagnostic, the host keeps running. Without it: stack overflow / OOM from untrusted input — a remote-DoS surface. Resolves: §6.11, §4.3, Threat Model T1/T3/T7 (Phase 12, §24).

MM10 — Identity, not structure, crosses every boundary. OpaqueTarget and CallbackRef compare by identity only; they are the sole tokens that cross the host↔engine and shadow boundaries, and they never deref to host internals. Predicts: the dedup key works (CallbackRef identity), path equality is cheap, and no Rc/raw pointer leaks heap layout to script. Without it: dedup misfires on cloned closures, or you leak ASLR-defeating pointers as targets. Resolves: §6.6, §6.12, ADR-09, ADR-06 (Phase 1, §13).

35. Back-of-Envelope Capacity Model

Numbers an expert computes before building, each derived from the System Constraints (§4). B=bytes, D=tree depth, L=listeners/target.

C1 — Listener record footprint. EventListener = Atom(u32 id, 4B) + CallbackRef(handle, 8B) + capture/once/removed (3×1B) + passive: Option<bool> (1–2B) + signal: Option<AbortSignalRef> (8B) ≈ 24–26B payload; with Vec slot alignment → ≤ 48 B/listener (matches §4.2 budget). Formula: record = align8(4+8+3+2+8).

C2 — Listener-table RAM for a heavy page. nodes × listeners/node × 48 B. A large app DOM ≈ 50 000 nodes; suppose 10% carry a listener, mean 2 each → effective 5 000 × 2 × 48 B = 480 KB. Even a pathological 50 000 × 4 × 48 B = 9.6 MB stays well under any host budget — the listener table is not the memory bottleneck; the DOM nodes themselves are.

C3 — Path build cost = O(D). One EventPathItem (≤ 64 B, §4.2) per ancestor. Typical web D ≈ 12–32; path Vec = 32 × 64 B = 2 KB, a single allocation reserved once (SmallVec<[_;16]> covers ~99% depth-free of heap, §31.3). Capture+bubble path length = 2D item-visits per bubbling dispatch (root→target then target→root), D for a non-bubbling one.

C4 — Dispatch cost per event. O(D · L̄) where L̄ = mean matching listeners/item (§32). For D=20, L̄=2: ~40 listener slots examined + ~40 path-item steps. At §4.1's ≤ 6 µs p50 for depth-100/1-listener, the per-path-item floor ≈ 6 µs / 100 ≈ 60 ns/item (path-build + phase bookkeeping), consistent with the < 200 ns single-target fast path.

C5 — Snapshot allocation budget. inner_invoke snapshot = min(L, inline_cap=8) records on stack; heap only when L > 8. For the §4.3 cap MAX_LISTENERS_PER_TARGET = 65 536, worst-case snapshot = 65 536 × 48 B = 3 MB for one degenerate target — bounded, one-shot, freed at invoke end. Steady-state alloc target: 0 B (reused scratch, §31.3).

C6 — Retarget hop bound. retarget climbs shadow-including ancestors; cost O(S), S = shadow-nesting depth. Real pages nest ≤ 4–8 shadow roots; §8.4 asserts ≤ 32. Per-item retarget for relatedTarget + each touch target → worst (1 + touch_points) × S; with no relatedTarget/touch (the common case) retarget is skipped entirely (fast path).

C7 — composedPath() cost. O(D) filter over the saved path, fresh Vec<OpaqueTarget> (8 B/entry) per call → 32 × 8 B = 256 B for a deep path; not memoized (currentTarget-dependent), so a handler calling it in a hot loop pays D each call — a documented foot-gun (§8.7).

C8 — Passive-scroll latency budget. A blocking (non-passive) touchmove/wheel listener forces the compositor to await main-thread dispatch: at a 60 Hz frame budget of 16.6 ms/frame, a dispatch that takes even 2 ms steals ~12% of the frame. Passive listeners remove this from the scroll critical path entirely → the compositor proceeds in parallel, bounding scroll latency to the compositor's own ~1 frame regardless of JS time (§31.6).

C9 — Microtask checkpoint bound. MAX_MICROTASKS_PER_CHECKPOINT = 1<<20 (§25.4) = ~1.05 M jobs. At an optimistic 80 ns/microtask (§31.1 perf target), a fully-saturated checkpoint = 1.05M × 80 ns ≈ 84 ms — far past a frame, which is why the budget exists: it bounds a microtask-storm livelock to a diagnostic-and-yield rather than an unbounded hang.

C10 — Nested-dispatch stack bound. MAX_NESTED_DISPATCH = 64 (§4.3). Each nested dispatch frame is the host call stack only (the path itself is iterative). At a conservative ~2 KB Rust stack frame per dispatch level → 64 × 2 KB = 128 KB worst-case added stack — comfortably inside a default 8 MB thread stack, with margin for the host's own frames between dispatches.

C11 — Throughput ceiling, single thread. §12.4 targets ≥ 1.0 M dispatch/s at depth-4/1-listener → ~1 µs/dispatch. Since dispatch is !Send (§32), this is per-thread; the scaling axis is documents/agents across cores (linear), never one dispatch parallelized. cores × 1.0 M is the realistic aggregate ceiling for independent documents.

C12 — Add/dedup cost. add_event_listener linear-scans the listener Vec for the dedup triple → O(L) per add, O(L²) to bulk-register L listeners on one target. For L=256: ~32 K comparisons (identity u32/ptr, ~1 ns each) ≈ 32 µs total — acceptable; past ~256 the §6.6 note recommends a Map<(Atom,bool), Vec> index (deferred), and the §4.3 cap bounds the worst case.

37. Alternative Architectures (Roads Not Taken)

Four fundamentally different architectures for "decide which listeners run for an event", not parameter tweaks. Each: sketch, winning regime, the real system that embodies it, why this blueprint rejected it.

ALT-1 — Capture+bubble three-phase per-node dispatch (CHOSEN)

Show the original text diagram
            ┌──────── path computed ONCE (root..target) ────────┐
 root ─cap→ … ─cap→ parent ─cap→ [TARGET] ─bub→ parent ─bub→ … ─bub→ root
            per node: snapshot listeners, run matching phase, honor stop/cancel
  • Regime where it wins: a real tree with security boundaries (shadow DOM) where authors register listeners anywhere and expect spec-exact phase ordering, retargeting, and composedPath(). The only model that honors closed-tree encapsulation.
  • Real system: the WHATWG DOM model as built by Blink/WebKit/Servo.
  • Why chosen: it is the spec this project must implement faithfully; web-compat is the objective bar (WPT).

ALT-2 — Flat delegation at the root (one listener, virtual path)

Show the original text diagram
 [ROOT] ── single real listener per type
    │  on event: read event.target, walk a VIRTUAL tree, synthesize capture/bubble
    └─ dispatch to handlers keyed by (component, type) — real DOM nodes carry no listeners
  • Regime where it wins: a framework that already owns a component/virtual tree and wants uniform cross-engine behavior, event pooling, and batched flushing — N per-node registrations collapse to one per type, and the framework controls exactly when handlers run.
  • Real system: React SyntheticEvent (root delegation since React 16, React-root since 17).
  • Why rejected: it abandons true DOM-phase fidelity and cannot retarget across shadow boundaries; it presupposes a virtual tree this engine has no business owning. It is a consumer of a dispatch engine, not a replacement for one (project 263's hydration runtime sits at this layer atop our EventLoop).

ALT-3 — Direct per-node handlers, no propagation

Show the original text diagram
 node.on(type, fn)  →  node.fire(type)  →  call node's fns in add order; STOP
 (no path, no capture/bubble, no retargeting)
  • Regime where it wins: non-tree or tree-but-propagation-irrelevant pub/sub — streams, servers, an actor mailbox — where "call my listeners in order" is the entire contract and a path is pure overhead.
  • Real system: Node.js EventEmitter (Map<name, fn[]> per emitter, array-copy on emit).
  • Why rejected: the DOM is a tree with capture/bubble semantics and closed-shadow privacy that authors depend on; dropping the path would make this not a DOM event system. Kept as the explicit contrast in the Comparative Architecture table to show what the path buys.

ALT-4 — Global event bus / single dispatcher table

Show the original text diagram
 ┌─────────────── one global Dispatcher ───────────────┐
 │ register(targetId, type, capture) → table[(id,type)] │
 │ dispatch(targetId, ev): look up table, no tree walk  │
 └──────────────────────────────────────────────────────┘
  • Regime where it wins: a closed system with a fixed, known set of targets and no need for ancestor propagation — a state-machine UI, a game's input router, Redux-style action dispatch — where a central table is simpler to reason about and trivially serializable.
  • Real system: Flux/Redux-style single dispatchers; OS-level global input routers.
  • Why rejected: it has no concept of an ancestor path, so capture/bubble, retargeting, and composedPath() are inexpressible; it centralizes what the DOM deliberately distributes per node. A global mutable table is also at odds with the !Send, one-loop-per-thread, no-global-state design (§27).

39. Glossary

Terms are normative; spelling matches the spine. "spec" = WHATWG DOM Standard "Events".

Term Definition (implementation-relevant)
event target Object that can have an event listener registered + be a dispatch target. Modeled by trait EventTarget; each impl owns a listener list + supplies get_the_parent. evt-dom NodeRef is the reference impl.
event listener Registration record EventListener { ty: Atom, callback: CallbackRef, capture, passive: Option<bool>, once, signal, removed }. Lives in the listener list. Invoked by inner_invoke when type+phase match.
listener list Per-event target ordered list (ListenerListRef, Rc<RefCell<…>>) of EventListeners, in registration order. Shared-mutable: callbacks may add/remove mid-dispatch.
capture / capturing phase EventPhase::CapturingPhase = 1. Path walked ROOT→target (excluding target); only capture=true listeners run.
at-target EventPhase::AtTarget = 2. Target's own listeners run in registration order, capture + non-capture together.
bubbling phase EventPhase::BubblingPhase = 3. Path walked above-target→ROOT; only capture=false listeners run; entered only if event.bubbles.
propagation path / event path Ordered Vec<EventPathItem> from target up to ROOT, computed ONCE at dispatch start by build_event_path. Drives all three phases.
composed path composed_path(event, current) -> Vec<OpaqueTarget>: the saved path filtered by closed-tree visibility relative to currentTarget. Backs composedPath().
get the parent EventTarget::get_the_parent(&self, &Event) -> Option<Self>: returns the next ancestor for path building (flat tree; slot for slottables).
dispatch dispatch(target, &mut Event, legacy_target_override) -> bool (!canceled). The capture→at-target→bubble state machine; sets/clears the DISPATCH flag, currentTarget, eventPhase.
invoke invoke(item, &mut Event, phase): per-EventPathItem step. Sets currentTarget = item target + shadow_adjusted_target/related_target, then calls inner_invoke. Spec "invoke".
inner invoke inner_invoke(&mut Event, &[EventListener], phase) -> bool: iterates a SNAPSHOT of the list; skips removed; removes a once listener BEFORE its callback; honors stop-immediate.
retargeting retarget(a, b) -> OpaqueTarget: spec "retarget"; computes the target of a relative to b so closed-shadow internals don't leak across boundaries.
shadow-adjusted target EventPathItem.shadow_adjusted_target: the target value exposed while currentTarget is at this item, after retargeting. None ⇒ skip the item's at-target exposure.
related target Event.related_target / EventPathItem.related_target: secondary target (e.g. mouseover). Retargeted per path item via retarget(B, A).
slottable / slot Slottable = a node assignable into a <slot>. Slot = the shadow-tree insertion point; a slottable's get_the_parent yields its assigned slot.
assigned slot The slot a slottable is assigned to; inserted into the flat-tree path so distributed nodes propagate through their host's shadow tree.
open vs closed shadow tree ShadowMode::{Open, Closed}. Open ⇒ retargeting still applies but internals are inspectable; Closed ⇒ path items flagged root_of_closed_tree/slot_in_closed_tree and hidden from composed_path.
shadow-including root The topmost root reachable by crossing shadow boundaries. Non-composed events truncate their path at the nearest shadow-including root containing the target.
composed flag EventFlags::COMPOSED (init from Event.composed). True ⇒ event crosses shadow boundaries; false ⇒ path truncated at the host's shadow root.
stop propagation flag EventFlags::STOP_PROPAGATION. Set by stopPropagation(); halts subsequent EventPathItems (current item's remaining listeners still run).
stop immediate propagation flag EventFlags::STOP_IMMEDIATE_PROPAGATION. Set by stopImmediatePropagation(); halts the current target's remaining listeners AND later path items.
canceled flag EventFlags::CANCELED. Set by preventDefault() iff cancelable && !IN_PASSIVE_LISTENER. Equals defaultPrevented; suppresses the default action.
default action Host-defined behavior after dispatch when not canceled (e.g. link navigation). Realized via activation behavior.
activation behavior ActivationBehavior host hook (fn(&Event)) returned by EventTarget::activation_behavior; runs post-dispatch on the activation target unless canceled. Drives click().
legacy-pre-activation behavior EventTarget::legacy_pre_activation_behavior: runs BEFORE dispatch for legacy controls (e.g. checkbox toggle); paired with legacy_canceled_activation_behavior to undo if canceled.
passive listener Listener with passive == Some(true). During its invoke IN_PASSIVE_LISTENER is set; preventDefault() becomes a no-op (emit diagnostic).
default-passive Event types defaulted to passive (e.g. touch/wheel scroll types) when passive is unspecified (None); resolves passive to true for those types.
once listener Listener with once == true; removed from the real listener list before its callback runs, so it fires at most once.
AbortSignal AbortSignal { aborted, reason, abort_algorithms, source_signals, dependent_signals } (AbortSignalRef). The signal option ties a listener's lifetime to it; abort ⇒ remove listener.
abort algorithm A callback in AbortSignal.abort_algorithms; run once when the signal aborts. Used to deregister listeners registered with that signal.
dependent signal A signal in dependent_signals derived via AbortSignal::any / ::timeout; aborts when any source_signals member aborts (weak refs avoid cycles).
trusted event / isTrusted Event.is_trusted. True ONLY for events evt-loop creates+dispatches (fire_event); script dispatchEvent yields false. The trusted-event gate enforces this.
synthetic event A script-created event dispatched synchronously via dispatchEvent; is_trusted == false. Contrast trusted event.
task source TaskSource::{Dom, UserInteraction, Networking, Timer}: labels a Task; selects which task queue it enters.
task queue EventLoop.task_queues: Map<TaskSource, VecDeque<Task>>. Per-source FIFO; one Task runs to completion per tick.
microtask A Task on EventLoop.microtasks; queued via queue_microtask; drained at the microtask checkpoint, may enqueue more.
microtask checkpoint perform_microtask_checkpoint: drains microtasks to empty after each task / before next render; guarded by performing_checkpoint against re-entry.
event loop EventLoop: owns task queues + microtask queue; tick runs one task then a checkpoint; fire_event dispatches a trusted event synchronously within a task.
currentTarget Event.current_target: the event target whose listeners are running this invoke. None outside dispatch.
eventPhase Event.event_phase: EventPhase. None outside dispatch; set per phase during dispatch.
defaultPrevented Boolean view of the canceled flag; dispatch returns !defaultPrevented.
OpaqueTarget Identity-only handle to an event target stored in Event/EventPathItem (avoids generic infection of the path); resolved by the host.
CallbackRef CallbackRef: opaque host handle to a callable listener; equality by identity (used in the dedup key); engine never introspects it.
Atom Interned event-type string in evt-core; O(1) equality for type matching in inner_invoke and the dedup key.
EventError enum EventError { Uninitialized, AlreadyDispatching }: thrown by dispatch for uninitialized events or events already mid-dispatch (DOM InvalidStateError).
dedup key (type, CallbackRef identity, capture): identity of an event listener; re-adding is a no-op. passive/once/signal excluded.
dispatch flag EventFlags::DISPATCH: set for the duration of dispatch; re-dispatching the same flagged event ⇒ AlreadyDispatching. Permits nested dispatch of other events.
