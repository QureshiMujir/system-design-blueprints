Decisions (§9) · 26 ADRs

ADR-01

Implementation language

Chosen

Rust, edition 2021, MSRV 1.78

Rejected

C/C++; Go; TypeScript

When the rejected choice is right

TypeScript wins when the engine ships inside a JS VM already (jsdom, a polyfill) — sharing the host GC/value model erases the CallbackRef/JsValueRef marshaling tax that dominates a foreign-language core.

Why: Untrusted listeners RE-ENTER the API mid-dispatch → need memory safety + precise aliasing on a re-entrant hot path; C/C++ unsafe under re-entrancy, Go's GC + weak sum types can't model mutate-during-dispatch borrow discipline, TS forces a JS-engine dep + no alloc control.

ADR-02

Workspace shape

Chosen

Cargo workspace, 7 members evt-{core,path,dispatch,signal,loop,dom,cli}

Rejected

Monolith; 2-crate lib+bin

When the rejected choice is right

Monolith wins below a complexity threshold (a few k LOC, one maintainer, no no_std split): a single crate compiles faster and skips the cross-crate versioning tax that 7 lockstep crates pay.

Why: One crate per spec layer enforces the dep DAG (core←path←dispatch; signal←core; loop←dispatch; dom/cli atop), isolates the no_std boundary, lets fuzz/bench target a layer.

ADR-03

Core environment

Chosen

no_std+alloc in cores; std only in evt-dom/-loop/-cli

Rejected

std everywhere; no_std everywhere

When the rejected choice is right

std everywhere wins if the only deployment target is a server-class host (a test runner, a desktop UA) — no_std discipline then buys nothing and forbids HashMap/Instant/threads you'd freely use.

Why: Engine must embed in a no_std host (browser/runtime); std confined to the reference tree, clock, and binary.

ADR-04

Host node abstraction

Chosen

EventTarget trait generic over host tree

Rejected

Concrete DOM struct

When the rejected choice is right

Concrete struct wins for a single-consumer engine (one browser, one tree type): monomorphizing on the real node removes trait-object/OpaqueTarget indirection and unlocks layout-aware fast paths Blink/WebKit actually take.

Why: Mirrors 258's Element trait; any host tree implements dispatch; NodeRef is one reference impl, not load-bearing.

ADR-05

Listener-list storage

Chosen

Rc<RefCell<Vec<EventListener>>> (ListenerListRef)

Rejected

&mut Vec; Box<[_]>; RwLock

When the rejected choice is right

RwLock/Arc wins if listener registration must be thread-safe (a host exposing addEventListener from worker threads) — at the cost of atomics on the hot path this engine's !Send design forbids.

Why: Models JS shared-mutable lists where a callback adds/removes mid-dispatch; RefCell gives runtime borrow checks; Rc matches the single-thread loop.

ADR-06

Listener callback repr

Chosen

CallbackRef opaque host handle, eq-by-identity

Rejected

Box<dyn Fn(&Event)>; fn ptr; trait object

When the rejected choice is right

Box<dyn Fn> wins for a pure-Rust embedding (a game UI, a TUI) with no JS host — native closures are directly callable and need no host trampoline or JsValueRef plumbing.

Why: Dedup needs callback IDENTITY (Box<dyn Fn> not comparable); listeners are host JS callables, not Rust closures; engine asks the host to run them.

ADR-07

Event-path materialization

Chosen

Compute path ONCE into Vec<EventPathItem>

Rejected

Lazy get_the_parent walk per phase

When the rejected choice is right

Lazy walk wins only for fire-and-forget non-bubbling events on shallow trees (depth ≤2) where building+freezing a Vec costs more than the at-target step it guards — a micro-opt Blink applies to a known set of leaf-only events.

Why: Spec freezes the path: tree mutation mid-dispatch must NOT change visited targets; one walk, all phases index one Vec.

ADR-08

Event flag set

Chosen

bitflags EventFlags (7 bits)

Rejected

Separate bools; enum-per-flag

When the rejected choice is right

Separate bools win when flags are seldom read together and clarity beats density (a teaching prototype) — named fields debug better than a packed word until the hot loop demands single-word tests.

Why: One word, cheap clear/test, atomic snapshot of dispatch state; matches spec "flags" vocabulary.

ADR-09

Target identity

Chosen

OpaqueTarget identity token, eq-by-identity

Rejected

Compare node structs; string IDs

When the rejected choice is right

String IDs win for a cross-process / serialized trace boundary (the differential harness over stdio) where a pointer token is meaningless and a stable string survives the wire.

Why: Path items / related_target / retarget / composedPath need cheap identity eq without exposing host internals.

ADR-10

Retargeting fidelity

Chosen

Spec retarget(A,B) + per-item adjusted/related targets exactly

Rejected

"No shadow leak" heuristic

When the rejected choice is right

Heuristic wins for an engine with zero closed shadow roots (an internal tool, a flat-DOM headless UA) — full retarget math is dead weight when no boundary is ever crossed.

Why: Closed-shadow encapsulation is observable + WPT-tested; retarget(B,A) is the only correct rule across boundaries.

ADR-11

Shadow-tree model

Chosen

Open + Closed modes + slots

Rejected

Open-only; no shadow

When the rejected choice is right

Open-only wins where closed shadow is out of product scope (an SSR pipeline, an a11y-only consumer) — dropping Closed removes the root_of_closed_tree/slot_in_closed_tree bookkeeping entirely.

Why: Composed crossing, non-composed truncation, and closed-tree gates need both modes to validate composedPath.

ADR-12

Default-passive source

Chosen

Static Atom table (touchstart/touchmove/wheel/mousewheel)

Rejected

Host per-call; runtime config

When the rejected choice is right

Runtime config wins when the host targets a non-web input model (XR, a custom gesture layer) whose passive-by-default set differs from the four web scroll types.

Why: Spec fixes the set; a compile-time table is auditable + matches Blink/WebKit; resolves passive:None deterministically.

ADR-13

Abort-signal graph

Chosen

WeakVec source/dependent signals

Rejected

Rc/strong both ways

When the rejected choice is right

Strong refs win if signals must outlive every dependent deterministically (an arena that frees them en masse) — then a cycle collector or arena drop, not Weak, owns lifetime.

Why: any/timeout form a graph; strong cycles leak; weak links break them, abort walks live dependents.

ADR-14

Event-loop scope

Chosen

Minimal host-driven tick(); task/microtask only

Rejected

Full HTML scheduler + render

When the rejected choice is right

Full scheduler wins inside a complete browser engine (project 260) that owns rendering opportunities, frame budgets, and requestAnimationFrame — a minimal loop can't sequence paint.

Why: Non-goal is the real scheduler; we give TaskQueue[source] + checkpoint, host calls tick.

ADR-15

Queue data structure

Chosen

VecDeque<Task> per source + 1 microtask VecDeque

Rejected

Linked list; binary heap

When the rejected choice is right

Binary heap wins the moment task ordering needs deadlines/priorities beyond source FIFO (a real timer wheel, QoS scheduling) — setTimeout ordering by fire-time is the canonical case.

Why: Tasks FIFO per source; microtasks FIFO + may enqueue more; VecDeque O(1) push/pop; spec has no priority.

ADR-16

Trusted-event gate

Chosen

isTrusted=true only via fire_event

Rejected

Caller-settable; trust by type

When the rejected choice is right

Caller-settable wins only in a trusted test harness replaying real UA events that must re-assert isTrusted=true — acceptable precisely because there is no adversarial script in that process.

Why: Trust is conferred by the UA path; routing through fire_event makes one authority; synthetics can't forge it.

ADR-17

CustomEvent detail / reason

Chosen

JsValueRef opaque host value

Rejected

Generic <T>; bytes; Box<dyn Any>

When the rejected choice is right

Generic <T> wins for a typed pure-Rust event bus where the payload type is known at the call site — static typing beats an opaque handle when no JS value ever flows through.

Why: detail/reason are arbitrary host values the engine never inspects; opaque ref avoids monomorph blowup + coupling.

ADR-18

Event-type repr

Chosen

Interned Atom

Rejected

String; &str; u32 enum

When the rejected choice is right

u32 enum wins for a closed event universe (a fixed embedded UI with N known types) — a dense enum indexes a jump table faster than interning and needs no intern table at all.

Why: Dedup / lookup / default-passive compare types constantly; interning gives O(1) eq + small footprint; open set rules out a closed enum.

ADR-19

Error strategy

Chosen

Result + EventError

Rejected

panic!; Option; silent no-op

When the rejected choice is right

panic! wins where these states are genuine programmer bugs that should abort (a strict test build, panic=abort fuzzing) — fail-fast localizes the defect better than a swallowed Result.

Why: Same-event re-dispatch + uninitialized are recoverable host errors; Result surfaces them; panics reserved for true bugs.

ADR-20

Trace format

Chosen

Line-oriented text trace

Rejected

Binary blob; ad-hoc Debug

When the rejected choice is right

Binary wins for high-volume production capture (always-on tracing in a shipping browser) where text serialization overhead and size dominate over human-readability.

Why: Deterministic text powers differential + golden tests; one row per invoke.

ADR-21

Fuzz harness

Chosen

cargo-fuzz / libFuzzer

Rejected

AFL standalone; proptest-only

When the rejected choice is right

proptest-only wins when bugs are shrinkable-structural not coverage-driven (the retarget algebra) — minimized counterexamples beat raw coverage for a small, total state machine.

Why: libFuzzer integrates with workspace + coverage; targets feed arbitrary trees/scripts to hunt re-entrancy panics.

ADR-22

Differential oracle

Chosen

jsdom primary + Servo secondary

Rejected

Hand-written expected only; Blink

When the rejected choice is right

Hand-written expected wins for behaviors NO oracle implements (a custom resource cap, a domevt-specific diagnostic) — there is nothing real to diff against, so the spec-derived golden is the oracle.

Why: jsdom is scriptable + spec-tracking; Servo cross-checks retargeting; trace divergence = bug.

ADR-23

Benchmarking

Chosen

criterion

Rejected

#[bench] nightly; ad-hoc timers

When the rejected choice is right

ad-hoc timers win for a one-off back-of-envelope check during exploration where wiring criterion costs more than the answer is worth.

Why: Statistical, regression-tracked, stable-Rust; guards the hot path.

ADR-24

CI

Chosen

GitHub Actions matrix

Rejected

Local-only; other providers

When the rejected choice is right

Other providers (GitLab CI, Buildkite) win when the org's source host or self-hosted runner fleet isn't GitHub — the choice is org-infra-driven, not technical.

Why: Reproducible stable+1.78 matrix; conformance + fuzz smoke per PR.

ADR-25

MSRV & dep policy

Chosen

MSRV 1.78 pinned; bitflags+hashbrown only in core

Rejected

Floating MSRV; heavy deps

When the rejected choice is right

Floating MSRV wins for an application (not a library) with no downstream embedders — always-latest unlocks new std/lang features at zero compatibility cost.

Why: Core stays no_std; hashbrown backs maps without std; pinned MSRV keeps embeddability.

ADR-26

License

Chosen

MIT OR Apache-2.0 dual

Rejected

GPL; single license

When the rejected choice is right

GPL wins when copyleft is a deliberate strategy to force downstream contribution (a reference implementation meant to keep forks open).

Why: Rust-ecosystem standard; permissive dual maximizes adoption.

Roads not taken (§37)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

ALT-1 — Capture+bubble three-phase per-node dispatch (CHOSEN)

            ┌──────── path computed ONCE (root..target) ────────┐
 root ─cap→ … ─cap→ parent ─cap→ [TARGET] ─bub→ parent ─bub→ … ─bub→ root
            per node: snapshot listeners, run matching phase, honor stop/cancel
  • Regime where it wins: a real tree with security boundaries (shadow DOM) where authors register listeners anywhere and expect spec-exact phase ordering, retargeting, and composedPath(). The only model that honors closed-tree encapsulation.
  • Real system: the WHATWG DOM model as built by Blink/WebKit/Servo.
  • Why chosen: it is the spec this project must implement faithfully; web-compat is the objective bar (WPT).

ALT-2 — Flat delegation at the root (one listener, virtual path)

 [ROOT] ── single real listener per type
    │  on event: read event.target, walk a VIRTUAL tree, synthesize capture/bubble
    └─ dispatch to handlers keyed by (component, type) — real DOM nodes carry no listeners
  • Regime where it wins: a framework that already owns a component/virtual tree and wants uniform cross-engine behavior, event pooling, and batched flushing — N per-node registrations collapse to one per type, and the framework controls exactly when handlers run.
  • Real system: React SyntheticEvent (root delegation since React 16, React-root since 17).
  • Why rejected: it abandons true DOM-phase fidelity and cannot retarget across shadow boundaries; it presupposes a virtual tree this engine has no business owning. It is a consumer of a dispatch engine, not a replacement for one (project 263's hydration runtime sits at this layer atop our EventLoop).

ALT-3 — Direct per-node handlers, no propagation

 node.on(type, fn)  →  node.fire(type)  →  call node's fns in add order; STOP
 (no path, no capture/bubble, no retargeting)
  • Regime where it wins: non-tree or tree-but-propagation-irrelevant pub/sub — streams, servers, an actor mailbox — where "call my listeners in order" is the entire contract and a path is pure overhead.
  • Real system: Node.js EventEmitter (Map<name, fn[]> per emitter, array-copy on emit).
  • Why rejected: the DOM is a tree with capture/bubble semantics and closed-shadow privacy that authors depend on; dropping the path would make this not a DOM event system. Kept as the explicit contrast in the Comparative Architecture table to show what the path buys.

ALT-4 — Global event bus / single dispatcher table

 ┌─────────────── one global Dispatcher ───────────────┐
 │ register(targetId, type, capture) → table[(id,type)] │
 │ dispatch(targetId, ev): look up table, no tree walk  │
 └──────────────────────────────────────────────────────┘
  • Regime where it wins: a closed system with a fixed, known set of targets and no need for ancestor propagation — a state-machine UI, a game's input router, Redux-style action dispatch — where a central table is simpler to reason about and trivially serializable.
  • Real system: Flux/Redux-style single dispatchers; OS-level global input routers.
  • Why rejected: it has no concept of an ancestor path, so capture/bubble, retargeting, and composedPath() are inexpressible; it centralizes what the DOM deliberately distributes per node. A global mutable table is also at odds with the !Send, one-loop-per-thread, no-global-state design (§27).
