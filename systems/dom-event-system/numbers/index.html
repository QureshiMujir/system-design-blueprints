4. System Constraints

In-process library; the only "resource" budgets are CPU latency, allocation, and bounded recursion. No NUMA, network, file-descriptor, or disk budgets — evt-core/evt-path/evt-dispatch/evt-signal are no_std + alloc; std only in evt-dom/evt-loop/evt-cli. Startup = zero global init (no lazy_static, no ctor, no thread-locals at load); Atom table and arenas are constructed explicitly by the host.

Path build is O(depth), computed ONCE per dispatch. retarget(a,b) is O(shadow-including-ancestors of b); cached per dispatch so total path build stays O(depth). No per-listener heap walk: listener list is one Vec.

4.2 Memory

Item Budget
EventListener record ≤ 48 B (Atom u32 + CallbackRef ptr + 3 bool/Option bytes; Vec-backed)
EventPathItem ≤ 64 B; path: Vec<EventPathItem> reserved to depth once
inner_invoke snapshot ZERO steady-state alloc — reusable SmallVec<[ListenerSlot; 8]> thread-local-free scratch passed down the call stack
Event object ≤ 128 B + path Vec (single allocation)

inner_invoke MUST NOT allocate on the hot path; the snapshot buffer is reused across invoke calls within one dispatch (grown only on first overflow past inline cap 8).

4.3 Hard Caps (DoS / re-entrancy)

Cap Limit On breach
MAX_PATH_DEPTH (path build) 8192 truncate path at cap, emit diagnostic; dispatch still completes safely
MAX_LISTENERS_PER_TARGET 65 536 add_event_listener becomes a no-op + diagnostic (dedup key unaffected)
MAX_NESTED_DISPATCH_DEPTH 64 nested dispatch returns EventError::AlreadyDispatching-class guard; no stack overflow
Microtask checkpoint work bounded-work diagnostic only (warn past N drained or T elapsed) — never silently drops tasks

Re-entrancy invariant: DISPATCH flag set for in-flight event ⇒ re-dispatching the SAME event (or an Uninitialized one) yields EventError::AlreadyDispatching / Uninitialized; nested dispatch of OTHER events allowed up to MAX_NESTED_DISPATCH_DEPTH.

4.4 Robustness & Availability

  • Never panics on adversarial input (cyclic/oversized trees, malformed Event, hostile get_the_parent, callbacks that mutate the list or nest-dispatch mid-invoke): all fallible paths return Result<_, EventError>, enforced by Phase-12 fuzz over tree shape, listener-mutation-during-dispatch, and shadow boundaries.
  • Bounded recursion: dispatch is iterative over the precomputed path; only nested dispatch consumes host stack, capped at 64. A malformed event or pathological tree can never take down the host — caps + Result + no-panic bound CPU/stack/memory to the limits above; the host keeps ticking the EventLoop.

35. Back-of-Envelope Capacity Model

Numbers an expert computes before building, each derived from the System Constraints (§4). B=bytes, D=tree depth, L=listeners/target.

C1 — Listener record footprint. EventListener = Atom(u32 id, 4B) + CallbackRef(handle, 8B) + capture/once/removed (3×1B) + passive: Option<bool> (1–2B) + signal: Option<AbortSignalRef> (8B) ≈ 24–26B payload; with Vec slot alignment → ≤ 48 B/listener (matches §4.2 budget). Formula: record = align8(4+8+3+2+8).

C2 — Listener-table RAM for a heavy page. nodes × listeners/node × 48 B. A large app DOM ≈ 50 000 nodes; suppose 10% carry a listener, mean 2 each → effective 5 000 × 2 × 48 B = 480 KB. Even a pathological 50 000 × 4 × 48 B = 9.6 MB stays well under any host budget — the listener table is not the memory bottleneck; the DOM nodes themselves are.

C3 — Path build cost = O(D). One EventPathItem (≤ 64 B, §4.2) per ancestor. Typical web D ≈ 12–32; path Vec = 32 × 64 B = 2 KB, a single allocation reserved once (SmallVec<[_;16]> covers ~99% depth-free of heap, §31.3). Capture+bubble path length = 2D item-visits per bubbling dispatch (root→target then target→root), D for a non-bubbling one.

C4 — Dispatch cost per event. O(D · L̄) where L̄ = mean matching listeners/item (§32). For D=20, L̄=2: ~40 listener slots examined + ~40 path-item steps. At §4.1's ≤ 6 µs p50 for depth-100/1-listener, the per-path-item floor ≈ 6 µs / 100 ≈ 60 ns/item (path-build + phase bookkeeping), consistent with the < 200 ns single-target fast path.

C5 — Snapshot allocation budget. inner_invoke snapshot = min(L, inline_cap=8) records on stack; heap only when L > 8. For the §4.3 cap MAX_LISTENERS_PER_TARGET = 65 536, worst-case snapshot = 65 536 × 48 B = 3 MB for one degenerate target — bounded, one-shot, freed at invoke end. Steady-state alloc target: 0 B (reused scratch, §31.3).

C6 — Retarget hop bound. retarget climbs shadow-including ancestors; cost O(S), S = shadow-nesting depth. Real pages nest ≤ 4–8 shadow roots; §8.4 asserts ≤ 32. Per-item retarget for relatedTarget + each touch target → worst (1 + touch_points) × S; with no relatedTarget/touch (the common case) retarget is skipped entirely (fast path).

C7 — composedPath() cost. O(D) filter over the saved path, fresh Vec<OpaqueTarget> (8 B/entry) per call → 32 × 8 B = 256 B for a deep path; not memoized (currentTarget-dependent), so a handler calling it in a hot loop pays D each call — a documented foot-gun (§8.7).

C8 — Passive-scroll latency budget. A blocking (non-passive) touchmove/wheel listener forces the compositor to await main-thread dispatch: at a 60 Hz frame budget of 16.6 ms/frame, a dispatch that takes even 2 ms steals ~12% of the frame. Passive listeners remove this from the scroll critical path entirely → the compositor proceeds in parallel, bounding scroll latency to the compositor's own ~1 frame regardless of JS time (§31.6).

C9 — Microtask checkpoint bound. MAX_MICROTASKS_PER_CHECKPOINT = 1<<20 (§25.4) = ~1.05 M jobs. At an optimistic 80 ns/microtask (§31.1 perf target), a fully-saturated checkpoint = 1.05M × 80 ns ≈ 84 ms — far past a frame, which is why the budget exists: it bounds a microtask-storm livelock to a diagnostic-and-yield rather than an unbounded hang.

C10 — Nested-dispatch stack bound. MAX_NESTED_DISPATCH = 64 (§4.3). Each nested dispatch frame is the host call stack only (the path itself is iterative). At a conservative ~2 KB Rust stack frame per dispatch level → 64 × 2 KB = 128 KB worst-case added stack — comfortably inside a default 8 MB thread stack, with margin for the host's own frames between dispatches.

C11 — Throughput ceiling, single thread. §12.4 targets ≥ 1.0 M dispatch/s at depth-4/1-listener → ~1 µs/dispatch. Since dispatch is !Send (§32), this is per-thread; the scaling axis is documents/agents across cores (linear), never one dispatch parallelized. cores × 1.0 M is the realistic aggregate ceiling for independent documents.

C12 — Add/dedup cost. add_event_listener linear-scans the listener Vec for the dedup triple → O(L) per add, O(L²) to bulk-register L listeners on one target. For L=256: ~32 K comparisons (identity u32/ptr, ~1 ns each) ≈ 32 µs total — acceptable; past ~256 the §6.6 note recommends a Map<(Atom,bool), Vec> index (deferred), and the §4.3 cap bounds the worst case.
