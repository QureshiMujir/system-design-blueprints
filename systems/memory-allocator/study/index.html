32. Mental Models & First Principles

  • MM1 — Class recovery must not require extra state. Insight: a correct allocator can always answer "what class is this pointer" in O(1) without walking a list. Predicts: any design that cannot do this needs either an in-band header (defeats P4) or accepts the overflow-corrupts-header bug class. Bug class without it: T1/T4's header-corruption family. Resolving: §11 Core Schema & Types, Phase 17.
  • MM2 — Segregation trades search for waste. Insight: eliminating best-fit search costs a bounded, known amount of internal fragmentation. Predicts: any scheme claiming O(1) placement and zero waste is wrong — the waste has to surface somewhere in the class step (ADR-08). Bug class without it: unbounded fragmentation surprises in production. Resolving: §4, Phase 15, "Back-of-Envelope Capacity Model".
  • MM3 — A lock's cost is its longest possible hold time, not its average. Insight: I7's O(1)-hold-time invariant matters more under contention than lock choice itself. Predicts: a spinlock with an occasional syscall inside its critical section loses to a ticket lock with a strictly bounded critical section. Bug class without it: tail-latency cliffs under load invisible to single-thread benchmarks. Resolving: §7 (I7), Phase 16, Performance Engineering.
  • MM4 — Address space and memory are different resources. Insight: reserving VA is nearly free (P6); committing/residency is the real cost. Predicts: an allocator that conserves VA aggressively will hit reallocation/fragmentation problems a generous-reservation design avoids. Bug class without it: spurious "arena exhausted" failures under a workload a bigger up-front reservation would absorb. Resolving: §4, Phase 13, Phase 16.
  • MM5 — Out-of-band metadata converts a memory-safety bug into a lookup miss. Insight: moving bookkeeping off the object doesn't prevent corruption of the object — it prevents corruption of the object from becoming corruption of the allocator. Predicts: a benchmark that never writes past its buffers shows no difference between in-band and out-of-band designs; the difference appears only under an adversarial or buggy workload. Bug class without it: T1/T4's whole family collapses back into scope. Resolving: Phase 17 (I3), Threat Model.
  • MM6 — Manual allocation is a liveness proof the programmer writes by hand. Insight: every free call asserts "no one will read this again"; a tracing GC computes that proof automatically at a throughput/latency cost instead. Predicts: unclear ownership produces more UAF/leak bugs under manual allocation than under a GC, but manual allocation wins every pause-time-tail comparison. Bug class without it: being unable to explain when a tracing collector is the correct call. Resolving: §5 (Jones, Hosking, Moss), Alternative Architectures.
  • MM7 — A benchmark number without a pinned rig is not a number. Insight: cache/frequency/Turbo noise routinely exceeds the effect size an allocator change produces. Predicts: an unpinned CI run eventually flags a false regression (FM9). Bug class without it: chasing phantom regressions, or shipping a real one that noise masked. Resolving: Phase 23, Performance Engineering.
  • MM8 — A remote free is a message, not a memory write. Insight: touching a foreign thread's cache directly on a cross-thread free reintroduces exactly the races per-thread caches exist to avoid. Predicts: any tcache skipping a remote-free queue shows heisenbugs specifically under producer-consumer thread patterns, never under single-thread benchmarks. Bug class without it: torn or lost cache-state updates across threads. Resolving: §7 (I13), Phase 18.

Required reading (§5)

Books

  • Knuth, D. The Art of Computer Programming, Vol. 1, section 2.5 "Dynamic Storage Allocation" — the boundary-tag method and the buddy-system origin. Applied in Phase 14 (boundary-tag coalescing) and Phase 16 (buddy allocator).
  • Silberschatz, A., Galvin, P., Gagne, G. Operating System Concepts, memory management chapters — paging, segmentation, fragmentation vocabulary. Applied in §4 (System Constraints) and §8 (Domain Model).
  • Stallings, W. Operating Systems: Internals and Design Principles, memory management chapters — buddy-system worked examples. Applied in Phase 16 (buddy allocator).
  • Drepper, U. What Every Programmer Should Know About Memory (Red Hat, 2007) — cache-line, TLB, prefetch reasoning. Applied in Phase 18 (per-thread cache) and Performance Engineering.
  • Love, R. Linux System Programming — mmap/madvise semantics and cost. Applied in Phase 19 (mmap fallback) and Phase 16 (buddy).
  • Jones, R., Hosking, A., Moss, E. The Garbage Collection Handbook — liveness and metadata-tracking vocabulary contrasted against manual allocation. Applied in Alternative Architectures ("A traced/moving collector") and MM6.

Reference Implementations

  • jemalloc (github.com/jemalloc/jemalloc) — study src/arena.c, src/tcache.c. Lesson: size-class table + per-thread cache bins. Pitfall: do not copy its extent-locking model wholesale — too complex for a Phase 0–6 bring-up. Applied in Phase 15 (size classes) and the Comparative Architecture Table.
  • tcmalloc / gperftools (github.com/gperftools/gperftools) — study src/tcmalloc.cc, src/central_freelist.cc. Lesson: central-freelist span batching. Pitfall: the legacy span table is monolithic; do not port the whole file. Applied in Phase 17 (batched refill/drain) and the Comparative Architecture Table.
  • mimalloc (github.com/microsoft/mimalloc) — study src/page.c, src/segment.c. Lesson: free-list sharding (regular/local/thread-delayed lists). Pitfall: its segment-per-thread model complicates a single-arena bring-up — defer that shape to a later ADR revisit. Applied in Phase 18 (remote-free design contrast) and the Comparative Architecture Table.
  • glibc malloc / ptmalloc2 (sourceware.org/git/glibc, malloc/malloc.c). Lesson: arena-per-thread contention model, fastbins. Pitfall: the fastbin double-free CVE class — study it, never replicate the in-band header layout. Applied in Phase 22 (ABI/symbol compatibility) and the Threat Model (T3).
  • musl libc (git.musl-libc.org/cgit/musl, src/malloc/mallocng). Lesson: mallocng's out-of-band meta-object design. Pitfall: its slot-count bitmap is compact but hard to debug live — the radix map (I1) is chosen instead. Applied in Phase 17 (out-of-band metadata, I3).

Glossary (§38) · 43 terms · site-wide glossary

arena
A logical heap with its own freelists, buddy region, and lock; per-thread caches attach to one arena at a time.
ABI
Application Binary Interface — the frozen symbol/layout contract consumers link against (ADR-20).
best-fit
A placement policy searching a freelist for the smallest chunk that still satisfies a request (Phase 14's precursor policy).
bin
A freelist for one size class within an arena.
boundary tag
An in-band header/footer pair recording a chunk's size and in-use bit, enabling O(1) coalescing with neighbors.
buddy allocator
A page-grain allocator that recursively splits and coalesces power-of-two regions.
blowup ratio
The ratio of memory held by an allocator to memory actually live; Hoard's founding metric.
canary
A magic value placed inside or after a chunk; a corrupted canary indicates a buffer overrun.
class (size class)
One entry in the fixed progression of sizes an allocator rounds requests up to.
coalescing
Merging adjacent free chunks/blocks into one larger free region.
decay-based purging
Returning pages to the OS on a time-decay curve rather than immediately (jemalloc's policy, Comparative Architecture Table).
decommit
Releasing a region's resident pages to the OS without returning the virtual address range.
DFD (double-free detection)
A bounded table of recently-freed pointers checked on every free to catch a repeat free.
external fragmentation
Free memory that exists but is too scattered or small to satisfy a request.
false sharing
Performance loss from two threads' unrelated data sharing one cache line.
fork-safety
The guarantee that a process forking mid-allocation leaves the child in a consistent, lock-free state (I12).
freelist
A linked list of free chunks belonging to one size class or region.
guard page
A PROT_NONE page placed adjacent to an allocation so an out-of-bounds access faults immediately.
hardening
The set of opt-in features (redzones, canaries, guard pages, quarantine) trading performance for corruption detection.
internal fragmentation
Wasted space inside an allocated chunk, between the requested size and the class size it was rounded to.
LD_PRELOAD
A dynamic-linker environment variable loading a shared object before others, letting it intercept symbols like malloc.
magazine
A small per-CPU stack of free objects; the unit of transfer between a slab cache and its central depot (Bonwick & Adams 2001).
madvise
A POSIX syscall giving the kernel a hint about a memory range's future use (e.g., MADV_DONTNEED, MADV_FREE).
mmap
A POSIX syscall mapping pages into a process's address space, the allocator's ultimate source of memory.
mprotect
A POSIX syscall changing a memory range's protection flags (used for guard pages and quarantine).
out-of-band metadata
Allocator bookkeeping stored in a side table rather than adjacent to user-visible memory (P4, I3).
quarantine
Deferring a freed allocation's reuse for N free calls to widen the detection window for use-after-free.
radix map
A multi-level tree mapping a pointer to its owning arena and size class in O(1) (ADR-12).
redzone
A fixed byte pattern placed after a chunk; a mismatch on free indicates a tail overrun.
remote-free queue
A per-arena MPSC queue receiving frees issued by a thread that does not own the target chunk (I13).
RSS (resident set size)
The portion of a process's mapped memory actually backed by physical pages.
segregated free list
An allocator design using one freelist per size class instead of one general-purpose list.
slab
A page-or-more region containing identical fixed-size objects, tracked by a free bitmap or count.
span
A contiguous run of pages managed as one unit by the page-grain backend.
tcache (per-thread cache)
A thread-local set of freelists serving the allocator's fast path without a lock.
ticket lock
A fair spinlock granting access in FIFO order via a ticket/serving-counter pair.
TLB reach
The total memory a TLB can map without a miss, equal to entry count × page size.
top chunk
The freelist's highest-address chunk, grown by requesting more memory from the OS when exhausted.
use-after-free
A memory-safety bug where freed memory is read or written after it becomes reuse-eligible.
virtual address space (VA)
The range of addresses a process can reference, distinct from physically resident memory.
watermark / limit
A configured ceiling (e.g., a tcache bin's limit) that triggers a drain or refill when crossed.
weak symbol
A linker symbol yielding to a strong definition elsewhere — the mechanism LD_PRELOAD interception relies on.
working set
The set of pages a program actively touches within a given time window.
