4. System Constraints

Reference rig (used for every number below unless stated): AMD EPYC 7763 (64 cores), 256 GB DDR4-3200, Linux 6.6, glibc 2.39, single NUMA node pinned via numactl. The one defining property: the fast path issues zero syscalls and holds zero locks — every number below is a consequence of preserving that property.

34. Back-of-Envelope Capacity Model

  1. Size-class count = 29. Derived from the internal-fragmentation bound (§4, ≤ 12.5%): a class step ratio r yields worst-case waste (r−1)/(2r); solving (r−1)/(2r) ≤ 0.125 gives r ≤ 1.29. Applying r ≈ 1.2–1.25 from 128 B to 4096 B (log(4096/128) / log(1.25) ≈ 15 steps) plus 9 fixed small steps below 128 B (sm_size_classes, §11.6) totals 29 classes.
  2. Per-object radix-map overhead ≈ negligible (< 0.01 B/object). A 3-level radix tree (ADR-12) with 256 entries/level × 8 B/pointer = 2 KiB/level populated path; amortized over a fully populated 2 MiB leaf span holding 2^18 minimum-size (8 B) objects: (3 × 2 KiB) / 2^18 ≈ 0.023 B/object — confirms §4's "0 B in-band" row (the map overhead lives outside user-visible memory entirely).
  3. Thread-cache footprint per thread ≤ 390 KiB. Σ(sm_size_classes) = 26,376 B (8+16+…+4096, §11.6) × limit 15 = 395,640 B ≈ 386 KiB, rounded to the §4 ceiling of 390 KiB.
  4. Max live allocations ≈ 2^37. Arena VA reservation 16 GiB (P6) × 64 arenas (§4 max concurrency) = 1 TiB total reserved VA; 1 TiB ÷ 8 B min class = 2^40 / 2^3 = 2^37 (matches the revised §4 row).
  5. Minimum idle RSS floor ≈ 128 MiB. 64 arenas (§4) × ≤ 2 MiB idle-arena RSS ceiling (§4) = 128 MiB — the floor below which RSS cannot usefully be tuned once every arena has been touched once.
  6. TLB reach at 4 KiB pages ≈ 6 MiB; at 2 MiB huge pages ≈ 3 GiB. Reference rig assumption: 1536-entry L2 TLB (typical modern x86_64); 1536 × 4 KiB = 6 MiB reach — smaller than a single arena's hot working set, motivating MADV_HUGEPAGE (P6, Phase 13): 1536 × 2 MiB = 3 GiB reach once huge pages back the region.
  7. Composed worst-case fragmentation multiplier ≈ 1.52×. Internal (≤ 12.5%, §4) and external (≤ 25%, §4) bounds compose as independent multipliers: 1 / ((1 − 0.125) × (1 − 0.25)) = 1 / 0.65625 ≈ 1.524 — i.e. mapped bytes can reach 1.524× live bytes in the documented worst case.
  8. Memory-bandwidth demand at the M6 target ≈ 7.7 GB/s/core. 60 M ops/s (M6, Performance Engineering) × 64 B object × 2 (write-on-alloc, read-on-free touch) ≈ 7.68 GB/s; against the reference rig's DDR4-3200 dual-channel bandwidth (~25.6 GB/s/socket), this leaves headroom for roughly 3 fully-loaded cores before the slab microbenchmark becomes bandwidth-bound rather than latency-bound.
