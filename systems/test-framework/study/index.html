  16. Contrast this design's Alternative Architecture 2 (in-process thread isolation) against the locked choice — under what load characteristics would the alternative actually outperform the locked choice on wall time? (§35, §4)

31. Mental Models & First Principles

  • MM1 — Isolation is a lifetime, not a promise. A test is isolated exactly as long as its process lives; anything that outlives the process boundary (a Session fixture, a shared temp dir) is where isolation leaks hide. Predicts: any bug reproducible only with --workers=1 --isolation=InProcess but not with Spawn is a global-state leak. Bug class avoided: silent cross-test coupling. Applies in §17 (I1).
  • MM2 — A fixture graph is a lifetime lattice, not a call graph. Scope is a partial order (Session ⊇ Module ⊇ Class ⊇ Function); a dependency edge is only valid if it respects that order. Predicts: any ScopeViolation is detectable statically, before any test runs. Bug class avoided: use-after- teardown. Applies in §14 (I2).
  • MM3 — A shrinker manipulates the recipe, not the cake. The conjecture buffer is the recipe; the generated value is the cake. Shrinking the recipe (deleting/zeroing bytes) and re-baking is strictly more general than trying to shrink the cake directly. Predicts: any generator, however complex, gets shrinking for free once it's buffer-driven. Bug class avoided: the "generator/shrinker API drift" bug where a hand-written shrinker silently diverges from its generator. Applies in §18 (ADR-06/07).
  • MM4 — Determinism is a function, not a property you hope for. (tests, seed, config, source hash) → (order, shards, generator sequence) must be a pure function; anything that depends on wall-clock time, thread-scheduling order, or hash-map iteration order breaks it. Predicts: any "works on my machine, flaky in CI" report traces to a hidden input to this function. Applies in §17 (I5).
  • MM5 — A worker crash is information, not noise. The crash signal, the test it was running, and the crash count rate are a diagnostic signal, not something to paper over with a silent respawn. Predicts: a system that hides crash counts will eventually hide a real memory-corruption bug behind "flakiness." Applies in §17 (I9, P13).
  • MM6 — Statistical confidence beats a magic number. "Retry 3 times" encodes no actual confidence level; a beta-binomial posterior at a stated θ does. Predicts: any fixed-retry-count policy either under- or over-quarantines depending on the test's true flake rate, which a fixed count cannot see. Applies in §20 (ADR-21).
  • MM7 — Content-addressing turns "did this change" into an equality check. A snapshot keyed by a hash of its normalized content converts "review this diff" into "does the hash match" for the 99% case where nothing changed. Predicts: any snapshot system without a normalization step will show false diffs from whitespace/ordering noise. Applies in §19 (P4, I6).
  • MM8 — The reporter is a projection, not a source of truth. RunReport is the single source of truth; TAP/JUnit-XML/console are projections of it. Predicts: two reporters ever disagreeing on pass/fail for the same test is always a projection bug, never a "the test actually ran twice differently" bug. Applies in §8.7, §21.

5. Required Reading

Books

  • Kent Beck, Test-Driven Development: By Example (Addison-Wesley, 2002). Read Part II (the money example) for the red-green-refactor cycle. Applied in §15 (assertion-first design) and §12 (Phase-0 correctness kernel is built test-first).
  • Gerard Meszaros, xUnit Test Patterns: Refactoring Test Code (Addison-Wesley, 2007). Read the "Test Fixture" and "Four-Phase Test" chapters. Applied in §14 (fixture scope/teardown model) and §7 (I2, I11).
  • Andreas Zeller, Why Programs Fail, 2nd ed. (Morgan Kaufmann, 2009). Read the delta-debugging chapter. Applied in §18 (shrinker strategy set) and §35 (Alternative 2).
  • Michael Feathers, Working Effectively with Legacy Code (Prentice Hall, 2004). Read the "seams" chapter. Applied in §22 (mock/spy seam design).
  • Brian Okken, Python Testing with pytest (Pragmatic Bookshelf, 2017). Read the fixtures chapter. Applied in §14 (scope resolution) and §13 (collection model).
  • Fred Hebert, Property-Based Testing with PropEr, Erlang, and Elixir (Pragmatic Bookshelf, 2019). Read the shrinking chapter. Applied in §18 (integrated shrinking) and §6 (P5).

Papers

  • Koen Claessen & John Hughes, 2000. QuickCheck: A Lightweight Tool for Random Testing of Haskell Programs. ICFP. The seminal property-testing paper. Applied in §18.1 (generator model) and §9 (ADR-06).
  • Andreas Zeller & Ralf Hildebrandt, 2002. Simplifying and Isolating Failure-Inducing Input. IEEE TSE. The delta-debugging algorithm. Applied in §18.6 (shrinker pitfalls) and §35.
  • Eugene Myers, 1986. An O(ND) Difference Algorithm and Its Variations. Algorithmica. Applied in §15.4 (diff engine) and §9 (ADR-10).
  • Kent Beck, 1994. Simple Smalltalk Testing: With Patterns. The Smalltalk Report, Vol. 4 No. 2. The original SUnit design — setUp/tearDown, TestCase, TestSuite. Applied in §14 (hook naming) and §2.
  • Koen Claessen, Jonas Duregård & Michał Pałka, 2015. Generating Constrained Random Data with Uniform Distribution. Journal of Functional Programming. Applied in §18.3 (generator weighting).
  • Michał Zalewski. American Fuzzy Lop Technical Details (whitepaper, lcamtuf.coredump.cx/afl/technical_details.txt). Coverage-guided feedback loop. Applied in §36 (Deferred Features Register — fuzzing) and §35 (Alternative 3).
  • Barton P. Miller, Louis Fredriksen & Bryan So, 1990. An Empirical Study of the Reliability of UNIX Utilities. CACM. The origin of fuzz testing. Applied in §36 and §24 (FM-9).
  • Qingzhou Luo, Farah Hariri, Lamyaa Eloussi & Darko Marinov, 2014. An Empirical Analysis of Flaky Tests. FSE. Empirical taxonomy of flaky-test root causes. Applied in §20 (flake model) and §24 (FM-4).

Reference Implementations

  • pytest (github.com/pytest-dev/pytest) — src/_pytest/fixtures.py, src/_pytest/python.py, src/_pytest/runner.py. The fixture resolver and the collector/item/node split. Applied in §14; pitfall: pytest resolves fixtures in registration order, not full topological order — we chose full topological (ADR-14 → §14.2) and document the tradeoff.
  • Jest (github.com/facebook/jest) — packages/jest-runner/src, packages/jest-worker/src, packages/jest-snapshot/src, packages/expect/src. The worker pool/IPC contract and the matcher-factoring model. Applied in §15, §17, §19; pitfall: Jest's worker recycling under long watch sessions leaks memory — our §17.6 crash-budget model is the mitigation.
  • JUnit 5 (github.com/junit-team/junit5) — junit-jupiter-engine, junit-platform-engine. The Platform/Engine split. Applied in §13 (discovery contract) and §9 (ADR-19).
  • Hypothesis (github.com/HypothesisWorks/hypothesis) — hypothesis-python/src/hypothesis/internal/conjecture. The conjecture-buffer engine and integrated shrinker. Applied in §18 end-to-end; pitfall: naive buffer mutation produces non-minimal shrinks without the "sort blocks" strategy (§18.6).
  • cargo / libtest (github.com/rust-lang/rust, library/test) — the built-in Rust harness. Applied in §13.2 (registration via inventory, contrasted with #[test]'s linker-section approach) and §9 (ADR-01, ADR-13).
  • GoogleTest (github.com/google/googletest) — googletest/include/gtest/. Death tests and parameterized-test macros. Applied in §18.2 (parameterisation) and §17.7 (process-isolated death-test analogue).

Glossary (§37) · 53 terms · site-wide glossary

TestId
content-addressed identifier: BLAKE3(file, suite, name, param_index), truncated to 128 bits (§11).
TestCase
the smallest dispatchable unit of work; body + fixtures + timeout + retry policy (§11).
Suite
a tree node grouping tests and nested suites, carrying hooks and fixture definitions (§8.1).
Fixture
a piece of state with explicit setup/teardown and a declared scope (§8.1).
FixtureGraph
the DAG of fixture dependencies; its topological sort is the setup order (§11, I2).
FixtureScope
one of Session|Module|Class|Function; bounds a fixture's lifetime (§8.1).
ScopeViolation
a fixture depending on a narrower-lifetime fixture than itself; rejected at build time (§14.2).
Hook
a beforeAll/afterAll/beforeEach/afterEach callback attached to a suite (§11).
HookSchedule
the precomputed, nesting-aware firing order of hooks around each test (I11).
RunPlan
the frozen, discovery-produced input to the runner: tests, fixture graph, config, seed (§11).
RunConfig
worker count, isolation mode, reporter list, timeout, retry budget (§11).
IsolationMode
Spawn (default), Fork (Unix opt-in), or InProcess (development only) (§11, ADR-03).
Worker
a child process running one TestCase at a time, owning one IPC channel to the runner (§11).
WorkerPool
the runner's collection of live workers, sized to core count by default (§17.2).
MsgPackChannel
the length-prefixed msgpack IPC channel between runner and worker (§11, ADR-02).
IpcMessage
the tagged union of all runner↔worker frame payloads (§11).
Backpressure
the in-flight-test budget per worker, default 1 (§4, ADR-04).
Work-stealing deque
per-worker task queue; an idle worker steals half the busiest peer's remaining work (§17.2).
Deterministic permutation
the ChaCha20-seeded shuffle of the test list that fixes ordering and shard assignment for a given seed (I5).
Shard
a deterministic slice of the test set assigned to one CI machine via --shard M/N (§20.2).
AssertionResult
the typed output of a matcher: pass/fail, actual, expected, optional diff, source location (§11).
Matcher
a trait implementing one named comparison; built-in or user-supplied (§11).
Value
the framework's universal comparable representation of any test data (§11).
DiffArtifact
the lazily-computed diff (Myers or structural) attached to a failed AssertionResult (§11).
Myers diff
the canonical O(N+D²) shortest-edit-script algorithm (Myers 1986, §5).
Structural diff
a tree-walk diff over Value::Object/Value::Array, producing PathDiff entries (§8.3).
Snapshot
a content-addressed golden recording of a test's output (§11, P4).
SnapshotKey
(test_id, label, index), the primary key of a snapshot (§11).
Content-addressing
keying stored data by a hash of its own (normalized) content (§31 MM7).
Normalization
the format-specific canonicalization applied before hashing/comparing a snapshot (§19.2).
Drift detection
flagging snapshots updated unusually often within a rolling window (§19.2).
ConjectureSource
the byte-buffer randomness source shared by generation and shrinking (§11, ADR-06).
Generator
a trait producing a typed value by drawing from a ConjectureSource (§11).
Shrinker
the engine that replays a property against progressively smaller candidate buffers until a fixed point (§11, I7).
Integrated shrinking
shrinking the byte buffer rather than the generated value (§31 MM3, ADR-07).
FlakeRecord
the per-test beta-binomial posterior state (§11, ADR-21).
Beta-binomial model
the statistical model underlying flake classification (§20.1).
Quarantine
the monotonic state a test enters once its flake score crosses the confidence threshold (I13).
Flake score
1 - pass_probability, derived from a FlakeRecord (§11).
Reporter
a trait consuming the streamed TestOutcome event sequence (§11, P7).
TAP
Test Anything Protocol, a line-oriented streamed test-result format (§5, §21.2).
JUnit-XML
the community-consensus XML schema for CI-tool test ingestion (§5, §21.2).
CI annotation
a structured inline failure marker consumed by a CI platform's log parser (§21.2).
Coverage instrumentation
LLVM source-based -fprofile-instr-generate -fcoverage-mapping compilation flags (§9 ADR-08).
.profraw
per-worker raw coverage data file, merged via llvm-profdata (§11, I12).
MockRegistry
the per-sandbox store of recorded mock/spy calls (§11, P11).
VirtualClock
the process-local, test-injected time-control primitive (§11, P12).
Sandbox
the per-test resource holder: temp dir, scrubbed env, rlimits, clock (§11).
RTO
Recovery Time Objective; here, worker-crash-to-replacement time (§4, M7).
Blast radius
the scope of impact of a single failure (e.g. one worker's current test and in-flight Session fixture) (§8.5).
Isolation leak
process-local mutation observed by a later test in the same process (I1, FM-6).
Cycle detection
the check rejecting a depends_on loop in the fixture graph at build time (§14.2, I2).
Topological sort
the ordering algorithm (Kahn's) producing fixture setup order from the DAG (§14.2).
