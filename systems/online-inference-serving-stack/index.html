3.2 Subsystem Responsibilities

API Gateway (crate gateway) terminates external connections: authentication, authorization, payload validation (16 MB cap, §4), quota enforcement, request tracing initialization, protocol negotiation. Intentionally stateless — no routing or scheduling state lives here. Trust boundary: untrusted external traffic becomes an authenticated, tenant-scoped request. Failure implications: malformed-traffic amplification, tenant-isolation bypass, replay spoofing (see Threat Model, §22).

Request Router (crate router) performs model-to-worker routing, tenant-aware partitioning, sticky-session semantics, topology-aware routing, drain coordination during rollout. Concurrency boundary: async dispatch, no shared mutable routing table across requests (P6). Persistence boundary: none — the routing table is a rebuildable in-memory projection of registry state. Operational implication: incorrect routing directly moves p99 latency (I4).

Admission Controller (crate admission) enforces queue budgets, concurrency limits, overload shedding, fairness, tenant isolation. Critical invariant: no unbounded queue growth (I1).

Dynamic Batch Engine (crate batching) aggregates shape-compatible requests into execution batches: timeout handling, fairness preservation, microbatch construction, padding-policy enforcement. Failure mode: latency amplification from oversized batching windows (Pitfall, §15.6).

Scheduler Core (crate scheduler) performs worker selection, GPU placement, memory-fit validation, model-residency planning, fairness accounting. Dominant scaling bottleneck at cluster sizes beyond ~500 workers (§29). Concurrency boundary: per-lease ownership, no global mutable placement table (ADR-08).

Runtime Worker Pool (crate runtime-worker) owns model memory residency, execution threads, CUDA streams, execution queues, allocator management. Crash-isolation boundary: one OS process per worker; a worker crash cannot corrupt another worker's state (I9).

Inference Runtime (inside runtime-worker, behind the RuntimeExecutor trait, §11) provides ONNX execution, TensorRT integration, tensor validation, execution-graph dispatch, memory binding. FFI boundary: isolated behind a stable executor trait so CUDA/TensorRT failures cannot propagate undefined behavior into the scheduler.

Telemetry Pipeline (crate telemetry) captures metrics, traces, structured logs, scheduler decisions, replay identifiers, queue timing. Critical invariant: telemetry emission must never block inference execution (I7) — enforced via a bounded MPSC with drop-oldest overflow.

Replay + Audit Store (crate replay) persists request metadata, deterministic execution traces, scheduler decisions, rollout history, failure snapshots for debugging, postmortems, regression reproduction, and conformance replay. Persistence boundary: append-only log (I2).

8. Domain Model — Serving & Scheduling Protocol

8.1 Core Entities

Entity Description
Tenant Logical isolation boundary; owns quota and fairness weight
Deployment An active model rollout binding a model_key to a manifest version
ModelArtifact Immutable binary payload referenced by content hash
WorkerNode Runtime execution process; owns GPU/CPU residency
InferenceRequest Execution payload submitted by a client
Batch Aggregated execution unit formed by the batch engine
ReplayRecord Durable execution event in the append-only log
SchedulerLease Temporary placement grant binding a batch to a worker
TenantQuota Per-tenant queue-depth, concurrency, and rate budget

8.2 Request Lifecycle

Client -> Gateway -> Router -> Admission Controller -> Batch Queue
       -> Scheduler -> Worker -> Runtime -> Response
       -> Telemetry -> Replay Store

8.3 Request State Machine

State Description Exit Conditions
RECEIVED Accepted by gateway payload validated
VALIDATED Payload/auth accepted routed to tenant partition
QUEUED Waiting in admission queue batch assignment or shed
BATCHED Attached to a batch worker lease assigned
EXECUTING Runtime executing the batch success or failure
COMPLETED Terminal success telemetry + replay persisted
FAILED Terminal error telemetry + replay persisted
REPLAYABLE Replay artifact durable eligible for archival/replay

8.4 gRPC Protocol

InferenceRequest fields: request_id, tenant_id, model_name, model_version, tensor_payload, timeout_ms, priority, replay_enabled, tracing_context.

InferenceResponse fields: request_id, execution_duration_ns, batch_id, worker_id, output_tensors, replay_token, error_code.

8.5 Failure Path Example

Malformed tensor shape:

Client -> Gateway validation failure -> error classification
        -> trace emission -> replay snapshot -> 400 response

This path is exercised by fixtures/proto/invalid_field.pb (§13.5) and must never reach the scheduler or a worker (I5, P11).
