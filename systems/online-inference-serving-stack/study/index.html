33. Hard Questions (Self-Examination)

  • Q1. If the scheduler's placement-scoring loop (§16) must stay under the 500 µs decision budget (§4) while also accounting for tensor-parallel shard grouping (§20), which scoring term gets cut first under CPU pressure, and which invariant (§7) does cutting it risk?
  • Q2. Given the batch-formation window is bounded to 0.5-8 ms (§4) and the admission controller (§14) sheds load at queue-depth 10,000/tenant, at what arrival rate does the batch window become irrelevant because admission has already shed the excess?
  • Q3. Replay determinism (§19) requires SimClock everywhere, but multi-region replication (§21) introduces cross-region clock skew — how does replay distinguish legitimate cross-region ordering ambiguity from a real determinism bug?
  • Q4. Model-registry immutability (§18) and the compiled-graph cache (§20) both cache derived artifacts keyed on content — what invalidates the compiled-graph cache when the underlying manifest is superseded, and how does that differ from artifact GC in §18?
  • Q5. Warm-pool cold-start mitigation (§21) and fragmentation-aware placement (§16) pull in opposite directions — how should the scheduler arbitrate, and which §4 budget breaks first if it arbitrates wrong?
  • Q6. The crash-only worker principle (§17) says never repair in place, but tensor-parallel shard groups (§20) share a logical lease across physical leases — does a single-shard crash still satisfy crash-only, or does group semantics quietly reintroduce partial-repair behavior?
  • Q7. Telemetry must never block inference (§19), yet compiled-graph selection (§20) depends on timely telemetry-derived shape-frequency signals — what happens to graph-selection quality when telemetry backpressure triggers drop-oldest?
  • Q8. Fairness accounting (§14, §16) is per-tenant, but tensor-parallel shard groups (§20) consume multiple workers per logical request — does fairness accounting need to weight by shard count, and what breaks in TenantQuota (§11) if it doesn't?
  • Q9. Rollback (§18) and canary promotion share one rollout-state machine — if a canary is mid-promotion when rollback triggers, which state wins, and does the answer differ for a tensor-parallel model (§20) with shard-group state to unwind?
  • Q10. The replay-log compaction job and forensic export tooling (§19) both read the append-only log — what ordering guarantee must compaction respect, relative to the replay-durability-delay budget (§4), so a forensic export mid-compaction never sees a torn view?
  • Q11. Cross-region failover (§21) must complete within the RTO (§4), but re-establishing scheduler leases (§16) in the failover region requires fencing every ambiguous lease — does fencing-token generation scale linearly with cluster size, and does that fit inside the RTO at the cluster-size ceiling (§4)?
  • Q12. GPU-fragmentation-aware placement (§16) and the batch engine's padding policy (§15) both consume the same fragmentation budget (§4) — if both subsystems independently believe they have headroom, what detects the double-counted budget before a placement fails?
  • Q13. Wire-compatibility (§13, §25) guarantees N-1 SDK compatibility, but tensor-parallel and dynamic-graph-compilation fields (§20) are additive to the wire schema — does an N-1 SDK's ignorance of shard-group fields silently break replay reconstruction (§19) for requests it originated?
  • Q14. Deferred RDMA transport (§35, anchored at §13) would change the gateway's trust-boundary assumptions (§3) — which Threat Model rows (§22) would need re-derivation before RDMA could be undeferred, and why doesn't gRPC-over-TCP's current mitigation set simply carry over?
  • Q15. The admission controller's retry-budget accounting (§14) and the scheduler's lease-expiration recovery (§16) both re-queue work under failure — under a correlated multi-worker failure, can these two independent retry paths compound into a retry storm?
  • Q16. Multi-region replication (§21) makes the registry's immutable-once-published guarantee (§18) a per-region fact until replication completes — what is the actual consistency window, and which §32 capacity number bounds how long a cross-region reader can observe a stale manifest?
  • Q17. Speculative decoding, deferred at §17 and registered at §35, would produce variable-length outputs per request within a batch — what invariant in §15 would need redesign, not just extension, before speculative decoding could be undeferred?
  • Q18. The scheduler's fairness invariant (§16) and the warm-pool manager's cold-start prediction heuristic (§21) both make resource-allocation decisions ahead of demand — if the heuristic starts favoring one tenant's model family, does that constitute a fairness-invariant violation even though warm-pooling isn't itself a §16 scheduling decision?

30. Mental Models & First Principles

  • MM1 — Batching is a latency/throughput exchange rate, not free throughput. Every millisecond of batch window borrowed from the latency budget buys queueing-theory throughput. Predicts: batch- window tuning has a hard ceiling set by the p50 budget (§4). Bug class without it: unbounded adaptive batch growth chasing throughput past the latency budget. Applies in §15.
  • MM2 — Leases are the concurrency-control primitive, not locks. A lease is time-bounded and fencible; a lock is not. Predicts scheduler behavior under partition (fencing, not blocking). Bug class without it: treating a distributed lease as a mutex and blocking on acquisition instead of failing closed. Applies in §16.
  • MM3 — Crash-only is a simplification, not a compromise. Restart-driven recovery is strictly simpler to verify than in-place partial repair. Predicts fewer recovery-path bugs over the system's lifetime. Bug class without it: "smart" partial-recovery code that reintroduces the corruption it was meant to fix. Applies in §17.
  • MM4 — Replay determinism is a testability property, not a nice-to-have. If a system can't replay a request, it can't prove a fix worked. Predicts incident MTTR directly. Bug class without it: shipping without a replay path and discovering the gap during the first real incident. Applies in §19.
  • MM5 — Backpressure without shedding is just a bigger buffer. A bounded queue with no shed policy only delays the OOM, it doesn't prevent it. Predicts eventual outage under sustained overload regardless of queue-size tuning. Bug class without it: bounded-but-blocking-forever enqueue code. Applies in §14.
  • MM6 — Fragmentation is a placement problem, not an allocator problem. GPU-memory fragmentation under heterogeneous model sizes is fundamentally bin-packing. Predicts fragmentation growth with model-size variance, not request rate. Bug class without it: trying to fix fragmentation purely with a smarter allocator instead of residency-aware placement. Applies in §16 and §17.
  • MM7 — Tail latency is dominated by the slowest constituent, not the average. p99 is set by fan-out and hedging behavior (Dean & Barroso, §5), not mean service time. Predicts why hedging and batching tradeoffs matter more than mean-case optimization. Bug class without it: optimizing average latency while p99 silently degrades. Applies in §14 and §28.
  • MM8 — Immutability turns concurrency bugs into staleness bugs. Immutable manifests and artifacts convert torn-write bugs into stale-read bugs, which are strictly easier to detect and bound. Predicts registry correctness under concurrent publish. Bug class without it: mutable- in-place metadata racing under concurrent access. Applies in §18.

  • Systems Performance: Enterprise and the Cloud, 2nd ed — Brendan Gregg (2020), ch. 6-7, 9-10: flamegraph methodology, latency analysis, kernel bottleneck diagnosis; applied in §28.
  • Database Internals — Alex Petrov (2019), ch. 2-4, 7: durability semantics, storage layering, compaction reasoning; applied in §19 and §18.
  • Programming Rust, 2nd ed — Jim Blandy, Jason Orendorff, Leonora Tindall (2021), ch. 4-5, 19-20: ownership models, Send/Sync invariants, trait boundaries; applied in §11 and §17.

  • "Ray: A Distributed Framework for Emerging AI Applications" — Philipp Moritz et al., 2018, OSDI: distributed actor execution, dynamic task scheduling → comparative baseline for Scheduler Core; applied in §31.

Reference Implementations

  • NVIDIA/TensorRT-LLM — study cpp/tensorrt_llm/batch_manager: in-flight batching layers, runtime memory handling; pitfall: do not couple batching directly into execution — keep §15 and §17 in separate crates; applied in §15.
  • triton-inference-server/server — study src/backends and the model-repository layout: backend abstraction, versioning-directory semantics; pitfall: do not copy its config-protobuf sprawl — keep the §11 manifest schema minimal; applied in §18.
  • envoyproxy/envoy — study source/common/filter: filter-chain composition, the stats/tag model; pitfall: do not copy xDS-style dynamic reconfiguration into the gateway until §21 actually needs it; applied in §13.
  • tokio-rs/tokio — study tokio/src/runtime: cooperative-scheduling budget, reactor/driver integration; pitfall: do not spawn CPU-bound tensor work on the async reactor — it starves the cooperative budget; applied in §17.
  • apache/arrow — study cpp/src/arrow/tensor.cc: zero-copy tensor/columnar layout design; pitfall: do not adopt Arrow's dictionary-encoding assumptions — inference tensors are dense, not categorical; applied in §11.

Glossary (§36) · 40 terms · site-wide glossary

Admission Control
the bounded-queue overload-protection layer between the router and the batch engine (§14).
Artifact Manifest
the immutable metadata record describing a published model version (§11, §18).
Backpressure
propagating a bounded-capacity signal upstream instead of buffering unboundedly (P2).
Batch Window
the maximum time a request waits for compatible peers before dispatch (§4, 0.5-8 ms).
Canary Deployment
a partial-traffic rollout of a new model version before full promotion (§18).
Compiled Graph
an ahead-of-time-compiled execution plan for a frequent input-shape bucket (§20).
Content Hash
the Blake3 digest identifying an immutable artifact (§11, I11).
Cross-Shard Deadline
a single execution deadline shared by every shard in a tensor-parallel group (§20).
Determinism
the property that identical inputs and clock state always produce identical outputs and traces (P1).
Drain Mode
graceful removal of a worker from routing before lease revocation (§14, §16).
Fairness Weight
a per-tenant scheduling weight bounding starvation (§11 TenantQuota, I3).
Fencing Token
a monotonically increasing value invalidating a stale lease holder's writes (I6).
Fragmentation
unusable memory segmentation from variable-size allocation over time (§4, §16).
Graceful Shutdown Window
the 30 s budget for draining in-flight work before SIGKILL (§4).
Lease
a time-bounded, fencible placement grant binding a batch to a worker (§11 SchedulerLease, I6).
Microbatch
a fallback batch of size 1 (or below target) dispatched at the timeout ceiling (§15).
Model Residency
the state of a model being fully loaded into a worker's execution memory (I5).
NUMA
non-uniform memory access; a memory-locality property the scheduler must be aware of (§4, §16).
Padding Policy
the rule set governing tensor-shape normalization inside a batch (§15).
Pinned Memory
non-pageable host memory used for faster host-device transfer (§17).
Placement Score
the scheduler's fitness metric combining NUMA, GPU-fit, and residency terms (§16).
Queue Age
how long a request has waited in the admission queue (§14).
Region Affinity
a tenant's preferred home region for routing under multi-region replication (§21).
Replay Determinism
the property that a replayed request reconstructs a byte-identical execution trace (I10, §19).
Replay Token
the identifier binding an InferenceResponse to its durable replay record (§8.4).
Residency Scoring
placement preference favoring workers that already have the target model loaded (§16).
RPO
Recovery Point Objective; maximum acceptable data loss window on failure (§4, < 5 s).
RTO
Recovery Time Objective; maximum acceptable time to restore service (§4, < 10 min).
Runtime Executor
the trait boundary isolating ONNX/TensorRT execution from the scheduler (§11).
Scheduler Domain
a placement-coordination partition of the cluster (§29, candidate future work).
Shard Group
the set of workers jointly executing one tensor-parallel model instance (§20).
Shed
rejecting a request rather than queueing it past a bounded limit (P2, I1).
Staged Rollout
the sequence of rollout states from canary through full promotion (§11 RolloutState, §18).
Starvation
a tenant's requests systematically failing to clear the queue due to unfair scheduling (I3).
Tail Latency
high-percentile (p95/p99) response delay, dominated by the slowest constituent (MM7, §5 Dean & Barroso).
Tenant
the logical multi-tenancy isolation boundary (§8, §11).
Tensor Parallelism
sharding a single model's execution across multiple GPUs as one logical unit (§20).
Warm Pool
a standing set of pre-loaded, idle workers reducing cold-start latency (§21).
Wire Compatibility
the guarantee that older SDKs remain functional across a rolling upgrade (I4, P5).
Worker Eviction
forced removal of a stale or unhealthy worker from the scheduler's registry (§16).
