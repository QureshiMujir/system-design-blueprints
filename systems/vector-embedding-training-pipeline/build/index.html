⬜ Phase 0 — Repo Skeleton, Core Types, RunConfig, DualEncoder Forward, InfoNCE (in-batch), Single-Device Smoke Train + Eval Stubs

Objectives

Stand up the vetp package; define vetp.types + RunConfig; a forward-only DualEncoder (encoder adapter → mean pool → projection → L2 norm); in-batch InfoNCE; a single-device train loop scaffold; metric stubs; RunManifest/Checkpoint schema. CLI runs a tiny end-to-end smoke (ingest→train→eval) on a synthetic toy corpus. Establish determinism + typing discipline from line one.

Deliverable

vetp train --config smoke.yaml runs N steps single-device on a synthetic corpus, loss decreases, embeddings L2-normalized; vetp eval prints Recall@k/MRR/nDCG/MAP on a toy eval set; pytest green; mypy --strict clean on typed cores.

Acceptance
  • InfoNCE init loss ≈ ln(B) on random embeddings (I10 sanity) within ±5%.
  • Loss strictly decreases on a learnable synthetic task over ≥ 200 steps.
  • All sampled embeddings satisfy ‖v‖₂ = 1 ± 1e-5 (I3).
  • Eval metrics match a hand-computed fixture exactly (small ranked list + qrels).
  • config-validator rejects 4 malformed configs (τ≤0, dim mismatch, bad pooling, missing field) with correct ConfigError.
Fixtures
  • conformance/configs/smoke.yaml — minimal run. conformance/data/toy_train/, toy_eval/ (synthetic). golden_metrics/p0_eval.json (hand-computed metrics). Malformed: configs/bad_temperature.yaml, bad_dim.yaml, bad_pooling.yaml, missing_field.yaml. fixtures/metric_handcalc.json (ranked+qrels→expected).
Pitfalls
  • Un-normalized embeddings into InfoNCE → loss couples magnitude + direction → unstable. Root: missing/misordered norm. Debug: embedding_norm_mean ≠ 1. Recover: normalize last (I3); compute loss on normalized.
  • Mean pooling ignores attention mask → pads pollute the embedding. Root: plain mean over Lq. Debug: embedding changes with padding length. Recover: mask-weighted mean (sum(masked)/sum(mask)).
  • Loss in fp16/bf16 by default → overflow / wrong gradients. Root: not forcing fp32. Debug: NaN at higher τ⁻¹. Recover: cast logits to fp32 before CE (I8).
  • Diagonal-label off-by-one after concatenating negatives → wrong positive target. Root: label index drift. Debug: init loss ≠ ln(B); accuracy at chance even when separable. Recover: assert labels point at the positive column (I10).
  • config_hash unstable (dict ordering, float repr) → manifest churn, replay mismatch. Root: non-normalized hashing. Debug: hash changes on logically-equal config. Recover: canonicalize (sorted keys, rounded floats) before hashing.

⬜ Phase 1 — Data Ingestion, Dedup, Filtering, `.vshard` Sharded Format, Streaming Loader, Seeded Exactly-Once Sampler

Objectives

Build the real data path: ingest corpora, dedup (MinHash+exact), language/quality filter, construct Examples, write immutable .vshard shards + DataManifest; a StreamingDataset with a seeded ShardSampler guaranteeing exactly-once-per-epoch consumption (I2) and a resumable cursor; train/eval split with disjointness enforcement (I1).

Deliverable

vetp ingest --in corpus/ --out data/ produces .vshard shards + DataManifest (with dedup/filter/leakage stats); vetp train streams from shards; epoch coverage verified exactly-once; resume from a mid-epoch cursor continues without duplication.

Acceptance
  • Exact + near-dup removal correct vs a labeled dup fixture (precision/recall on known dups).
  • Train∩eval overlap = 0 (I1) on a fixture with planted overlap (must be detected + removed/aborted).
  • Epoch coverage == n_examples, zero duplicates/skips across 3 epochs (I2).
  • Resume at step k reproduces the same subsequent (shard,row) order as an uninterrupted run (I2).
  • .vshard round-trips exactly (crc match, I deserialize == serialized).
Fixtures
  • conformance/data/dup_fixture/ (planted exact+near dups). data/leakage_fixture/ (planted train/eval overlap). data/multilang/ (language filter). golden/p1_manifest.json (expected dedup/filter/leakage stats). replay_traces/sampler_order.json (expected (shard,row) sequence for a seed). Malformed: data/corrupt_shard.vshard (crc mismatch → DataError).
Pitfalls
  • Non-deterministic dedup (random MinHash seed) → different shards each run → replay breaks. Root: unseeded permutations. Debug: data_version changes on identical input. Recover: fix permutation seed (I4).
  • Leakage via near-duplicates (eval doc is a near-dup of a train doc) → inflated metrics. Root: exact-only disjointness check. Debug: suspiciously high Recall@1. Recover: dedup across the train/eval boundary too (I1).
  • Sampler not exactly-once under DDP (overlapping rank partitions) → duplicated examples. Root: bad partitioning. Debug: epoch_coverage > n or dup_examples > 0. Recover: disjoint rank shards (I2).
  • Resume cursor off by a batch → a few examples skipped/repeated on resume. Root: cursor saved after consume, restored before. Debug: post-resume order diff. Recover: checkpoint cursor at exact step boundary (I2/I6).
  • Shard offset-index corruption → wrong row decoded. Root: writer/reader offset mismatch. Debug: crc + schema assertion on read. Recover: rebuild shard; crc gate (DataError).

⬜ Phase 2 — Tokenizer Integration, Padding/Truncation, Attention Masks, Prefixing, Batch Collation Hardening

Objectives

Wire a trained tokenizer (#113) behind vetp.tokenize: encode Example texts to input_ids+attention_mask, truncate/pad to max_seq_len (batch-max padding), support task prefixes (E5-style query:/passage:), and harden Batch collation including ragged hard-negatives. Make tokenization deterministic and a non-bottleneck.

Deliverable

StreamingDataset yields fully tokenized, padded, masked Batches with prefixing + ragged hard-negs; tokenization throughput ≥ target; deterministic across runs.

Acceptance
  • Tokenization output bit-identical across runs for the same input (determinism, I4).
  • Padding/mask correctness: masked positions never affect pooled embedding (differential vs unpadded single example) within fp tolerance.
  • Truncation respects max_seq_len; no id ≥ vocab_size.
  • Tokenization throughput ≥ 200K examples/s aggregate (cached short texts) — loader not the bottleneck (I5).
  • Prefixing applied correctly per field (query vs doc) per fixture.
Fixtures
  • conformance/data/tokenize_cases/ (short, long-truncated, unicode, empty, prefix). golden/p2_tokenized.json (expected ids/mask for fixtures). configs/prefixed.yaml (E5-style prefixes). Edge: data/oversized_text.jsonl (truncation), data/empty_text.jsonl.
Pitfalls
  • Global-max padding → huge wasted compute on short batches. Root: padding to max_seq_len always. Debug: tokens/s low, padding ratio high. Recover: pad to batch-max length.
  • Mask/padding mismatch → pads counted in mean pool. Root: mask built from wrong lengths. Debug: embedding varies with pad count. Recover: mask == (ids != pad_id) AND within true length.
  • Tokenizer artifact drift (different tokenizer than data was built with) → silent id mismatch. Root: not verifying tokenizer_ref hash. Debug: vocab/ids inconsistent with manifest. Recover: assert tokenizer hash == manifest tokenizer_ref.
  • Prefix applied to wrong field (query prefix on doc) → asymmetric encoding bug. Root: collate field confusion. Debug: query/doc embeddings systematically off. Recover: prefix per field, fixture-tested.
  • Tokenization on the main thread → GIL-bound, GPU starves. Root: no worker parallelism. Debug: gpu_idle_pct high, loader CPU-bound. Recover: multi-worker loader + caching (ADR-002 Rust ext if needed).

⬜ Phase 3 — Dual-Encoder Model: Towers (shared/separate), Pooling Variants, Projection Head, L2 Normalization, Optional Teacher

Objectives

Complete the model: configurable shared vs separate query/doc towers, all three pooling strategies, projection head to embedding_dim, mandatory L2 normalization (I3), embedding-dim invariant (I15), and an optional cross-encoder teacher interface for later distillation. Forward path production-ready (AMP-safe, gradient-checkpointing-ready).

Deliverable

A configurable DualEncoder producing normalized embeddings under all pooling/tower options; gradient-checkpointing reduces activation memory; teacher interface available; forward path AMP-safe.

Acceptance
  • All embeddings L2-normalized (I3) across pooling/tower configs.
  • Mean pooling mask-correct (differential vs manual computation).
  • Shared vs separate towers both train (loss decreases) on the synthetic task.
  • Gradient checkpointing cuts peak activation memory ≥ 40% with identical outputs (within fp tolerance).
  • embedding_dim constant and equal to config across forward/eval/export probes (I15).
Fixtures
  • configs/{shared_mean.yaml,separate_cls.yaml,last_token.yaml,with_projection.yaml}. golden/p3_pooling.json (expected pooled outputs for fixed inputs/weights). Edge: configs/grad_ckpt.yaml. Teacher: fixtures/teacher_scores.json.
Pitfalls
  • CLS pooling on a model with no meaningful CLS (random-init or non-BERT) → weak embeddings. Root: pooling/encoder mismatch. Debug: poor Recall vs mean pooling. Recover: prefer mean pooling unless CLS is trained (Sentence-BERT lesson).
  • Projection head collapses dimensions → low effective rank. Root: bad init / too-small proj_dim. Debug: embedding rank ≪ d (Phase 10). Recover: sane init; proj_dim ≥ task needs.
  • Separate towers with shared optimizer LR → one tower dominates. Root: imbalanced grad scale. Debug: per-tower grad norm divergence. Recover: balanced init / per-tower LR if needed.
  • Normalization before pooling → wrong (normalizing token vectors, not the sentence). Root: layer order. Debug: embeddings not unit-norm at output. Recover: pool → project → normalize (I3 order).
  • Gradient checkpointing changes outputs → silent numerical drift. Root: nondeterministic recomputation / RNG in dropout. Debug: output diff with/without ckpt. Recover: deterministic dropout seeding (I4); recompute must match.

⬜ Phase 4 — Contrastive Loss Suite, In-Batch Negatives, False-Negative Masking, Single-GPU Training Loop, AMP + Grad Accumulation

Objectives

Make single-GPU training real and strong: full loss suite (InfoNCE/NT-Xent, MNR, triplet/margin), in-batch negatives with false-negative masking (I11), AMP autocast + GradScaler (I8), gradient accumulation, LR warmup/decay, grad clip. This is the first configuration that trains a useful embedding model on one GPU.

Deliverable

vetp train on a single GPU trains a real dual-encoder on a real (small) retrieval dataset with InfoNCE + in-batch + false-negative masking + AMP + accumulation; loss + grad-norm curves healthy; eval Recall@k rises.

Acceptance
  • InfoNCE init loss ≈ ln(num_columns) (I10); masking removes false negatives (verified on a planted-duplicate batch, I11).
  • AMP: no NaN/Inf loss over a full run; GradScaler skip-rate < 1% steady state (I8).
  • Gradient accumulation: effective-batch-N run ≈ true-batch-N run (loss trajectory within fp tolerance) on a fixture.
  • Eval Recall@10 on a small benchmark beats a BM25 baseline after training.
  • All three losses train (loss decreases) on their respective fixtures.
Fixtures
  • configs/{infonce_inbatch.yaml,mnr.yaml,triplet.yaml,amp.yaml,accum8.yaml}. data/small_retrieval/ (real-ish train+eval+qrels). golden_metrics/p4_recall.json (post-train Recall floor). fixtures/false_neg_batch.json (planted in-batch false negative → must be masked). replay_traces/accum_equivalence.json.
Pitfalls
  • In-batch false negatives (another example's positive is also relevant to this query) → model penalized for correct docs. Root: no masking. Debug: loss floor high, Recall stalls. Recover: mask_false_neg by doc-id/positive-set (I11).
  • GradScaler scale too high → persistent Inf → many skipped steps → no learning. Root: bad init scale / fp16 loss. Debug: high skip-rate, grad-norm spikes. Recover: fp32 loss (I8), default scaler growth schedule.
  • Accumulation without scaling loss → effective LR wrong (loss summed not averaged). Root: not dividing loss by accum. Debug: divergence vs true-batch. Recover: average micro-batch losses.
  • Temperature too low (τ→0) → razor-sharp softmax → unstable grads; too high → no contrast. Root: untuned τ. Debug: loss NaN (low τ) or flat (high τ). Recover: τ∈[0.01,0.1] typical; validate (I12).
  • Clipping after scaler.step (wrong order) → clip on scaled grads. Root: AMP step order. Debug: clip ineffective. Recover: unscale_ → clip → step → update.

⬜ Phase 5 — Checkpointing, Resume, Run Manifest, RNG/Sampler State, Deterministic Reproducibility

Objectives

Make runs durable, resumable, and reproducible: atomic checkpoints of model+optimizer+scheduler+sampler+all RNG (I6); RunManifest joining data↔code↔config (I13); checkpoint↔config compatibility gate on resume (I7); end-to-end determinism so a resumed run matches an uninterrupted one and a replayed run matches the original (I4).

Deliverable

A run can be killed mid-epoch and resumed to produce a loss trajectory identical (fp tolerance) to an uninterrupted run; RunManifest records data+code+config; incompatible resume is refused; checkpoints are atomic + checksummed.

Acceptance
  • Resume-at-step-k loss trajectory == uninterrupted run within fp tolerance (I4/I2) over ≥ 1000 subsequent steps.
  • Sampler cursor restored exactly: post-resume (shard,row) order == uninterrupted (I2).
  • All RNG states restored (verified: next random draws match) — torch/cuda/numpy/python.
  • Incompatible config resume → ResumeError (I7) on a deliberately-altered config.
  • Crash during checkpoint write → no corrupt checkpoint; prior checkpoint intact (I6) — verified by injected mid-write kill.
Fixtures
  • replay_traces/resume_equivalence.json (uninterrupted vs resumed loss). configs/altered_arch.yaml (resume-incompat → ResumeError). fixtures/partial_ckpt/ (truncated checkpoint → rejected). golden/p5_manifest.json.
Pitfalls
  • CUDA RNG not checkpointed → resumed run diverges (dropout differs). Root: only CPU RNG saved. Debug: post-resume loss diverges. Recover: save torch.cuda.get_rng_state_all() too (I6).
  • Sampler cursor saved at wrong boundary → examples skipped/repeated on resume. Root: cursor not aligned to step. Debug: epoch_coverage off after resume. Recover: snapshot cursor exactly at the checkpointed step (I2/I6).
  • Non-atomic checkpoint write → kill mid-write → corrupt file → can't resume. Root: write-in-place. Debug: load fails / partial keys. Recover: temp+fsync+rename (I6).
  • Optimizer state mismatch on resume (Adam moments lost) → LR effectively resets → loss spike. Root: optimizer state not saved/restored. Debug: grad-norm/loss spike at resume. Recover: full optim_state round-trip.
  • config_hash includes non-architectural fields → false resume rejections (e.g., changing ckpt_every blocks resume). Root: over-broad arch signature. Debug: spurious ResumeError. Recover: arch_signature = only architecture-affecting fields (I7).

⬜ Phase 6 — Hard-Negative Mining: ANN over Current Model + BM25, Negative Cache, Scheduled Refresh, False-Negative Filtering, Optional Distillation

Objectives

Build the data↔model feedback loop (the project's distinguishing subsystem): mine hard negatives by retrieving near-but-wrong documents using the current model's embeddings (ANN) ⊕ BM25 lexical negatives, cache them per example, refresh on a schedule (I11 false-negative filtering), and optionally denoise/distill via a cross-encoder teacher. This is the ANCE recipe.

Deliverable

Training mines hard negatives from the current model + BM25, refreshes the cache on schedule, filters false negatives, and (optionally) distills from a teacher; eval Recall@k improves measurably vs in-batch-only.

Acceptance
  • Mined negatives are harder than random (mean similarity to query > random negs) — verified.
  • No mined negative equals a true positive (I11) on a planted fixture.
  • Refresh reduces staleness to 0 and cadence respected (staleness_steps ≤ refresh_every, principle 11).
  • Hard-negative training beats in-batch-only on eval Recall@10 by a measurable margin on the benchmark.
  • Mining is off the hot path: training-step throughput unchanged between refreshes (only periodic dips during refresh).
Fixtures
  • configs/{ance_mining.yaml,bm25_negs.yaml,distill.yaml}. data/mining_corpus/ (corpus + queries + qrels). fixtures/false_neg_mining.json (positive planted in mined set → must be filtered). golden_metrics/p6_recall_improvement.json. fixtures/teacher_scores.json (distillation).
Pitfalls
  • Mined negatives include the true positive (false negative) → model penalized for the right answer. Root: no filtering. Debug: Recall drops after mining starts. Recover: filter by positive-set/qrels id (I11).
  • Stale negatives (cache from a model 50k steps old) → effectively easy → wasted compute. Root: refresh cadence too slow / refresh failed silently. Debug: staleness_steps high; loss flat. Recover: bound cadence; alert on staleness (principle 11).
  • Mining OOM / index build failure stalls training. Root: corpus too large for one GPU encode / index. Debug: MiningError::IndexBuildFailed. Recover: shard the encode across GPUs; contain mining failure (keep last cache, log, continue).
  • ANN recall too low (cheap index) → "hard" negs aren't actually near → weak signal. Root: under-tuned HNSW/IVF. Debug: mined-neg similarity not elevated. Recover: tune index params / exact for small corpora.
  • Over-hard negatives without denoising → many are actually relevant → noisy gradient. Root: top-1 mining, no teacher. Debug: training instability, Recall regression. Recover: sample from top-k with margin; teacher denoising (RocketQA).

⬜ Phase 7 — Distributed Data-Parallel Training: DDP, Embedding All-Gather (global negatives), Cross-Batch Memory, Gradient Cache, Deterministic Collectives

Objectives

Scale negatives and throughput across GPUs: DDP gradient all-reduce (#115); all-gather of embeddings so every query sees all ranks' documents as negatives (global negatives, I9 — correct gradient flow); cross-batch memory queue (MoCo/RocketQA); gradient cache (GradCache) for huge effective batch within memory; deterministic collective ordering for replay (I4).

Deliverable

Multi-GPU single-node DDP training with global in-batch negatives via all-gather, cross-batch memory, and gradient cache; near-linear scaling; correct distributed contrastive gradients (matches single-GPU semantics at equal effective batch); deterministic at fixed world size.

Acceptance
  • DDP scaling efficiency ≥ 0.85× linear to 8 GPUs (throughput).
  • All-gather gradient correctness (I9): single-GPU run at effective batch == 8-GPU run (loss trajectory within fp tolerance) — proves only local-slice grad flows.
  • All-gather overhead ≤ 5% step time at world=8 (embeddings small).
  • Cross-batch memory + gradcache increase effective negatives to target (≥ 4,096/query) within memory budget.
  • Deterministic: same (config,seed,world) → identical loss trajectory + sample assignment across runs (I4).
Fixtures
  • configs/{ddp_allgather.yaml,xbm.yaml,gradcache.yaml}. scaling/{ddp_1,2,4,8}.yaml. fixtures/gather_grad_equivalence.json (single-vs-multi-GPU grad). replay_traces/ddp_determinism.json. fixtures/effective_batch_count.json.
Pitfalls
  • All-gather without detaching other ranks' slices → gradient double-counted / wrong → silent training corruption. Root: gathering with grad on all rows. Debug: grads differ single vs multi GPU (I9 test fails). Recover: gradient flows only to local slice; rest detached + re-attached locally.
  • Label offset wrong after gather (not offset by rank) → positive target points at wrong column. Root: labels=0..B-1 instead of rankB+i. Debug: init loss ≠ ln(BW); accuracy at chance. Recover: offset labels by rank*B (I10).
  • Non-deterministic collective ordering → replay diverges across runs. Root: async/unordered NCCL ops. Debug: replay_loss_max_abs_diff > tol. Recover: deterministic ordering + deterministic algorithms (I4).
  • Cross-batch memory holding grad → memory leak / wrong grad. Root: enqueuing non-detached embeddings. Debug: memory grows; grad through queue. Recover: detach before enqueue (xbm negatives are detached).
  • GradCache embeddings recomputed differently in pass 2 (dropout RNG differs) → cached grad mismatched. Root: nondeterministic re-forward. Debug: loss inconsistent vs non-gradcache. Recover: deterministic RNG across both passes (I4).
  • DDP + gradient accumulation no_sync misuse → grads synced every micro-batch (slow) or never (wrong). Root: missing no_sync context on non-final micro-batches. Debug: throughput low or grads wrong. Recover: no_sync on all but the last accumulation micro-batch.

⬜ Phase 8 — Evaluation Harness: Retrieval Metrics (Recall@k, MRR, nDCG, MAP), Embedding Quality (alignment/uniformity/rank), Regression Gates

Objectives

Build the evaluation that gates releases (principle 10): encode a held-out corpus + queries, retrieve, compute Recall@k/MRR/nDCG/MAP against qrels, measure embedding quality (alignment/uniformity/rank for collapse), and enforce regression gates vs a baseline. Train/eval disjointness re-checked here (I1). Shares metric semantics with #331.

Deliverable

vetp eval --config ... --ckpt best produces an EvalReport (Recall@{1,10,100}, MRR, nDCG@10, MAP, alignment, uniformity, rank) and a gate verdict vs baseline; integrated into training (eval_every) to track the best checkpoint.

Acceptance
  • Metrics match a reference implementation (BEIR/#331) on a shared benchmark within fp tolerance.
  • Hand-computed fixture (small ranked+qrels) reproduces exact metric values.
  • Regression gate correctly fails a deliberately-worse model and passes an improved one.
  • Alignment ↓ + uniformity ↓ over training on a healthy run; flagged on a collapse fixture (Phase 10).
  • Eval leakage check (I1) catches a planted train/eval overlap.
Fixtures
  • data/eval_benchmark/ (corpus+queries+qrels). golden_metrics/p8_reference.json (reference metric values). fixtures/metric_handcalc.json (exact small case). fixtures/{worse_model.pt,better_model.pt} (gate). collapse_cases/collapsed_emb.json (quality flags). fixtures/eval_leakage.json (I1).
Pitfalls
  • Metric definition drift (Recall@k counting / nDCG gain/discount variant) → numbers don't match references. Root: ambiguous metric spec. Debug: diff vs BEIR. Recover: pin definitions to #331/TREC; fixture-test exact values.
  • Eval uses a different distance than training (dot vs cosine on un-normalized) → wrong rankings. Root: normalization/distance mismatch. Debug: eval Recall inconsistent with training loss. Recover: normalized + cosine consistently (I3).
  • Qrels graded relevance ignored in nDCG/MAP → metrics wrong for graded judgments. Root: binary treatment. Debug: nDCG off vs reference. Recover: honor graded relevance.
  • Leakage discovered only via suspiciously high metrics → fake state-of-the-art. Root: no eval-time disjointness check. Debug: Recall@1 near 1.0. Recover: I1 re-check at eval; re-split data.
  • Gate tolerance too loose/tight → ships regressions or blocks noise. Root: untuned tolerances. Debug: gate false pass/fail. Recover: per-metric tolerances calibrated to eval noise.

⬜ Phase 9 — Model Export (ONNX/TorchScript), Parity Verification, Batch Embedding Generation, Model Versioning

Objectives

Make the trained encoder consumable: export to ONNX (pinned opset) and TorchScript with parity verification vs eager (I14), batch-embed a target corpus producing normalized vectors + ids, and version the model so downstream consumers (#255 ANN, #328 cache) can reference it precisely. Export preserves the full training contract — pooling + normalization (principle 15, I3/I15).

Deliverable

vetp export --ckpt best --format onnx produces a parity-verified ONNX encoder (+ TorchScript), and vetp embed --corpus ... produces normalized vectors + ids; all artifacts carry a model_version.

Acceptance
  • ONNX + TorchScript outputs match eager within tolerance on a probe set (I14).
  • Exported embeddings are L2-normalized (I3) and embedding_dim == config (I15).
  • Batch embedding of a corpus reproduces eval-time embeddings (same vectors) within tolerance.
  • Export round-trips: re-import the exported model, re-embed, identical vectors.
  • model_version deterministic and recorded in all artifacts (I13).
Fixtures
  • configs/export_onnx.yaml, export_torchscript.yaml. fixtures/export_probes.json (inputs → expected eager outputs). golden/p9_parity.json (parity diffs within tol). Edge: fixtures/unsupported_op.json (opset-unsupported → ExportError).
Pitfalls
  • Export omits normalization (exports up to pooling only) → consumer gets un-normalized vectors → wrong neighbors. Root: partial forward exported. Debug: exported ‖v‖₂ ≠ 1. Recover: export full forward incl. norm (principle 15, I3).
  • Opset mismatch → an op (e.g., a pooling/norm variant) unsupported → export fails or differs. Root: unpinned/low opset. Debug: ExportError::OpsetUnsupported or parity diff. Recover: pin a sufficient opset; replace unsupported ops.
  • Dynamic axes wrong → exported model fixed to one batch/seq length → breaks on real input. Root: static trace. Debug: shape error at inference. Recover: declare dynamic batch + sequence axes.
  • Training-serving skew (different tokenizer/prefix at serve time) → embeddings incompatible. Root: contract not documented. Debug: downstream Recall regression. Recover: handoff manifest states tokenizer + prefix + normalization (principle 15).
  • fp16 export parity drift → exported fp16 diverges from fp32 eager beyond tol. Root: precision mismatch. Debug: parity diff. Recover: export fp32 (or accept a documented fp16 tolerance).

⬜ Phase 10 — Observability: Loss/Grad/Throughput Curves, Embedding-Collapse Detection, Mining Staleness, Dashboards, Alerting

Objectives

Make the run observable (principle 12): emit training curves (loss, grad norm, lr, throughput), embedding-collapse detection (alignment/uniformity/rank/std), mining staleness, GPU/loader utilization; export to Prometheus + scalar logs; define dashboards + alert thresholds. Collapse + staleness are the two failure modes that silently waste GPU-weeks — catch them early.

Deliverable

A live metrics endpoint + dashboards showing training health, collapse signals, throughput, and mining staleness; alerts fire on collapse / staleness / NaN / starvation; all events structured-logged with versions.

Acceptance
  • Collapse detector flags a synthetic collapsing run (std→0, rank≪d, uniformity↑) before eval would.
  • Healthy run shows alignment↓ + uniformity↓ + stable rank — no false collapse alarm.
  • Throughput + GPU-util metrics match measured reality (cross-check vs profiler).
  • Mining staleness gauge tracks refresh cadence; alert fires when staleness > budget.
  • All metrics exported + scrapeable; logs parse as structured JSON.
Fixtures
  • collapse_cases/{dimensional_collapse.json,full_collapse.json,healthy.json} (detector behavior). fixtures/throughput_crosscheck.json. configs/obs_full.yaml. fixtures/staleness_alert.json.
Pitfalls
  • Collapse detected too late (only at eval) → GPU-weeks wasted. Root: no online collapse signal. Debug: Recall flat, embeddings degenerate at eval. Recover: online alignment/uniformity/std/rank (this phase).
  • False collapse alarm (alignment naturally drops early) → spurious aborts. Root: bad thresholds / single-signal. Debug: alarm on healthy run. Recover: multi-signal (std AND rank AND uniformity), calibrated thresholds.
  • Metric overhead on hot path → throughput hit. Root: expensive per-step metric (e.g., full rank every step). Debug: throughput drop with metrics on. Recover: cheap per-step scalars; expensive metrics (rank) on a cadence.
  • GPU util misleading (high util, low useful work due to padding) → false sense of efficiency. Root: util ≠ throughput. Debug: util high but samples_per_sec low. Recover: track samples/s + padding ratio, not just util.
  • Staleness gauge not updated on failed refresh → silent staleness. Root: gauge updated only on success. Debug: training flat, gauge stuck. Recover: increment staleness every step, reset only on successful refresh (principle 11).

⬜ Phase 11 — Deterministic Replay, Conformance Suite, ANN Index Handoff, Soak, Reproducibility Gate, Release Engineering

Objectives

Lock correctness + determinism + handoff: deterministic replay harness (I4 — re-run a captured config+data+seed, assert identical loss trajectory + sample order), full conformance suite (data, training, eval, export, collapse), the ANN index handoff (#255) + semantic-cache feed (#328), soak (long-run stability, no leak), and the reproducibility + release gate.

Deliverable

make conformance + make replay + make soak (nightly) + handoff to a live ANN index all green; a VETP-trained model's vectors are indexed by #255 and queried correctly; determinism proven across the suite; release pipeline produces a signed, SBOM'd package.

Acceptance
  • Replay: identical loss trajectory (fp tol) + identical sample order across runs for every captured trace (I4/I2) — 100%.
  • Conformance: all buckets green (data integrity, training correctness, eval-vs-reference, export parity, collapse detection).
  • Handoff: #255 index built from VETP vectors returns the same top-k as eval-time exact retrieval (within ANN recall); #328 consumes the contract correctly (dim/normalization/distance match, I15).
  • Soak: multi-hour run — zero memory/FD leak, staleness within budget, atomic checkpoints, replay holds post-soak.
  • Performance gate: throughput + scaling within target; no > 10% regression vs committed baseline.
Fixtures
  • replay_traces/*.json (per-config determinism traces). conformance/configs/* + data/* + golden_metrics/* + collapse_cases/*. fixtures/handoff_roundtrip.json (eval top-k vs #255 ANN top-k). fixtures/soak_manifest.json. fixtures/handoff_contract.json (dim/norm/distance for #328).
Pitfalls
  • Replay diverges (hidden nondeterminism: unseeded op, async collective, dataloader worker RNG, non-deterministic kernel). Root: impure run input. Debug: replay_loss_max_abs_diff > tol; bisect inputs. Recover: seed all generators; deterministic algorithms + collectives; fixed worker seeding (I4).
  • Handoff dim/normalization mismatch → #255 index incompatible / #328 wrong neighbors. Root: contract not enforced. Debug: dim/norm assertion fails; downstream Recall wrong. Recover: HandoffManifest states + asserts dim/normalization/distance (I3/I15).
  • Soak memory leak (cache/queue/embedding accumulation) → OOM after hours. Root: unbounded buffer (xbm/cache/metrics). Debug: RSS/GPU mem grows monotonically. Recover: bound all buffers (principle 13); leak test in soak.
  • Bench flakiness (shared GPU host) → false perf regressions. Root: noisy host. Debug: variance. Recover: pinned/isolated GPU, relative thresholds, multiple runs.
  • Replay across world sizes expected to match (it can't — sample assignment differs). Root: misunderstanding determinism scope. Debug: cross-world diff. Recover: determinism is per-fixed-world-size (documented constraint, I4).
