Mental Models & First Principles

The compressed intuitions an expert holds. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — Negatives are the gradient; positives only set the target. A contrastive step's signal comes almost entirely from how many and how hard the negatives are; the positive just names the column the softmax should peak at. Predicts: doubling effective negatives improves Recall far more than tweaking the positive. Without it: you over-engineer positive construction and starve the loss with 63 in-batch negatives, then wonder why loss drops but Recall stalls. Applied: §3 (loss box), P5/P6, Phase 4, Phase 7, Capacity Model #4.
  • MM2 — Embeddings live on a sphere; temperature, not magnitude, sets sharpness. After L2-normalization every vector has norm 1, so dot product is cosine and only τ controls how peaked the softmax is. Predicts: un-normalized vectors make the loss couple direction and magnitude → unstable; lowering τ sharpens contrast until grads explode. Without it: you build an index on un-normalized vectors and get wrong neighbors (training-serving skew). Applied: I3, P3, P7, Phase 3, Phase 9, MM-driven §8.5.
  • MM3 — A training run is a pure function of (config, data_version, seed, world); anything else is a bug. Determinism means every byte of output is reproducible from those four inputs. Predicts: if a resumed or replayed run diverges, an impure input leaked in (CUDA RNG, async collective, unseeded worker). Without it: regressions are undebuggable — you cannot bisect what you cannot reproduce. Applied: I4, P1, Phase 5, Phase 11 (replay gate), MM-driven Hard Questions HQ7/HQ13.
  • MM4 — Effective batch is a dial independent of GPU RAM. device_batch × accumulation × world × xbm + mined decouples the negative pool from the memory that holds activations. Predicts: you can hit 16k+ effective batch on a 24 GiB card via accumulation/gather/gradcache without a bigger GPU. Without it: you buy hardware to solve a problem that is a software decoupling (GradCache's two-pass trick). Applied: ADR-015, P6, Phase 7, Capacity Model #3/#4.
  • MM5 — The all-gather is free; the gradient detach is everything. Embeddings are tiny (B×d×2 bytes), so gathering them across ranks costs ≤5% of step time; the entire correctness risk is whether gradient flows only through the local rank's slice. Predicts: the cheap operation (gather) is safe; the subtle operation (detach boundary) is where silent corruption hides. Without it: you double-count or zero gradients and only the single-vs-multi-GPU equivalence test catches it. Applied: I9, Phase 7, §8.6, Hard Question HQ4.
  • MM6 — A hard negative mined from a stale model is just an easy negative wearing a costume. Mining's value is that the negatives are hard for the current model; an old cache retrieves negatives the model already separates. Predicts: Recall plateaus while loss looks fine when staleness ≫ refresh_every. Without it: you burn GPU-weeks training on negatives that carry no signal, with no alarm. Applied: P11, Phase 6, Phase 10 (staleness gauge), Failure Modes (stale negatives).
  • MM7 — Loss is a proxy; the metric you ship on is retrieval. Training loss can improve while Recall/nDCG regress (collapse, leakage, easy negatives). Predicts: gating releases on loss ships bad models; gating on held-out retrieval catches them. Without it: you promote a checkpoint whose loss curve looked great and whose neighbors are garbage. Applied: P10, Phase 8 (regression gate), Phase 11.
  • MM8 — Collapse is a rank/variance phenomenon you can see before eval. Degenerate embeddings show as per-dim std→0, effective rank ≪ d, rising uniformity — all measurable online, cheaply, on a sample. Predicts: a same-hour alarm instead of a week-late eval discovery. Without it: you find collapse only when retrieval craters, after the compute is spent. Applied: §8.8, P12, Phase 10, paper #6 (Wang & Isola).
  • MM9 — Exactly-once consumption is what makes resume == uninterrupted. If the sampler's cursor is the single source of "what's next," checkpointing it makes a killed-and-resumed run identical to one that never stopped. Predicts: a cursor saved at the wrong boundary skips/repeats examples and diverges on resume. Without it: resume silently biases training and breaks the determinism gate. Applied: I2, I6, P2, Phase 1, Phase 5.
  • MM10 — The handoff contract is the API; vectors without it are uninterpretable. A vector array is meaningless to a downstream index unless dim, normalization, and distance are stated and enforced. Predicts: an undocumented contract surfaces as a downstream Recall regression, not a crash. Without it: #255/#328 interpret your vectors under the wrong distance and return wrong neighbors. Applied: I15, I3, P15, Phase 9, Phase 11 (HandoffManifest).

Books

  • Goodfellow, Bengio, Courville, Deep Learning (2016) — Ch. 6 (feedforward, softmax/cross-entropy), Ch. 8 (optimization: Adam, schedules), Ch. 10 (sequence models). Baseline for loss + optimizer + encoder. Applied in: Phase 0 (InfoNCE/softmax), Phase 4 (AdamW + schedule).
  • Manning, Raghavan, Schütze, Introduction to Information Retrieval (2008) — Ch. 6–8 (vector space, scoring), Ch. 8 (evaluation: MAP, nDCG, MRR), Ch. 11 (BM25). Retrieval metrics + BM25 mining baseline. Applied in: Phase 6 (BM25 negatives), Phase 8 (Recall@k/MRR/nDCG/MAP).
  • Murphy, Probabilistic Machine Learning: An Introduction (2022) — softmax, contrastive/energy-based intuition, temperature. Loss derivations. Applied in: Phase 4 (loss suite, temperature τ; I12).
  • Tunstall, von Werra, Wolf, Natural Language Processing with Transformers (2022) — encoder architectures, pooling, tokenization, fine-tuning loop. Model tower design. Applied in: Phase 2 (tokenization), Phase 3 (towers + pooling).
  • Lin, Nogueira, Yates, Pretrained Transformers for Text Ranking: BERT and Beyond (2021) — dense retrieval, dual-encoders, hard negatives, distillation. The core subject; extract DPR/ANCE/distillation recipes. Applied in: Phase 3 (dual-encoder), Phase 6 (mining + distillation).
  • Géron, Hands-On Machine Learning, 3e (2022) — training loop pragmatics, mixed precision, callbacks. Engineering pragmatics. Applied in: Phase 4 (AMP + GradScaler; I8).
  • Kleppmann, Designing Data-Intensive Applications (2017) — Ch. 3–4 (storage/encoding), Ch. 11 (batch/stream). Sharded data format + manifest + reproducible batch jobs. Applied in: Phase 1 (.vshard + DataManifest), Phase 5 (run manifest).
  • Huyen, Designing Machine Learning Systems (2022) — data pipelines, versioning, training-serving skew, evaluation discipline, regression gates. Operational frame. Applied in: Phase 1 (versioning), Phase 8 (regression gate; P10), Phase 9 (skew; P15).
  • Raschka, Machine Learning Q and AI (2024) — contrastive learning, embedding evaluation (alignment/uniformity). Collapse diagnostics. Applied in: Phase 10 (collapse detection; alignment/uniformity panel).

Glossary · 45 terms · site-wide glossary

Embedding
Dense vector representation of text on the unit hypersphere (L2-normalized).
Dual-encoder / Bi-encoder
Two-tower model: separate (or shared) query and document encoders producing comparable embeddings.
Cross-encoder
Single model scoring a (query, doc) pair jointly; accurate but not indexable; used as a distillation teacher.
Contrastive learning
Training to pull positives together and push negatives apart in embedding space.
InfoNCE / NT-Xent
Temperature-scaled cross-entropy over one positive vs many negatives (the workhorse loss).
Triplet / margin loss
Loss enforcing positive closer than negative by a margin.
MNR (multiple-negatives-ranking)
In-batch contrastive loss using other examples' positives as negatives (Sentence-BERT).
Temperature (τ)
Scalar dividing similarities; controls softmax sharpness (τ>0, I12).
In-batch negatives
Other examples' positives in the same batch, reused as negatives (free).
Global negatives
In-batch negatives gathered across all DDP ranks via all-gather (I9).
Hard negative
A document the current model wrongly ranks near a query; the only negatives with signal late in training.
Mining (hard-negative)
Retrieving hard negatives via ANN over the current model's embeddings (+ BM25), refreshed on a schedule (ANCE).
False negative
A "negative" that is actually relevant; must be excluded from the loss (I11).
Negative cache
Per-example store of mined negative ids; versioned; refreshed periodically.
Staleness
How many steps since the negative cache was refreshed (a key alertable metric).
Cross-batch memory (xbm)
FIFO queue of recent detached embeddings reused as extra negatives (MoCo/RocketQA).
Gradient cache (GradCache)
Two-pass technique decoupling effective batch from activation memory.
Effective batch
Total examples (and hence negatives) the loss sees: device batch × accumulation × world × xbm.
Pooling
Reducing token embeddings to one vector: CLS, mean (mask-weighted), or last-token.
Projection head
Linear layer mapping encoder hidden to embedding_dim.
L2 normalization
Scaling a vector to unit norm; makes dot product == cosine (I3).
Alignment
E‖q−d⁺‖² over positives; lower = positives close (a healthy-embedding signal).
Uniformity
log E e^{−2‖x−y‖²} over pairs; lower = embeddings spread on the sphere; collapse if rising.
Embedding collapse
Degenerate embeddings (std→0, low rank, all-similar); training fails silently.
Effective rank
Rank of the embedding matrix; ≪ d indicates dimensional collapse.
Recall@k
Fraction of queries whose relevant doc is in the top-k retrieved.
MRR
Mean Reciprocal Rank of the first relevant doc.
nDCG
Normalized Discounted Cumulative Gain (honors graded relevance).
MAP
Mean Average Precision across queries.
qrels
Relevance judgments (query→relevant docs), TREC format.
BM25
Probabilistic lexical ranking function; lexical hard-neg source + baseline.
ANN
Approximate Nearest Neighbor search (HNSW/IVF/PQ); used for mining + handoff (#255).
.vshard
VETP's immutable, content-addressed sharded corpus format.
DataManifest
Metadata pinning a data version: shards, dedup/filter/leakage stats, split.
RunManifest
Joins model↔data↔code: data_version + code_hash + config_hash (I13).
Checkpoint
Atomic snapshot of model+optimizer+scheduler+sampler+RNG (I6).
arch_signature
Hash of architecture-affecting config; gates resume compatibility (I7).
Exactly-once consumption
Each example visited once per epoch; cursor checkpointed (I2).
Deterministic replay
Re-running a captured (config, data_version, seed, world) yields identical loss + sample order (I4).
Export parity
Exported ONNX/TorchScript matches eager outputs within tolerance (I14).
HandoffManifest
Contract to #255/#328: embedding_dim + normalization + distance + vectors (I15).
Training-serving skew
Mismatch between training and serving encoding (tokenizer/prefix/normalization) → wrong neighbors.
Distillation
Training the bi-encoder to mimic a cross-encoder teacher's scores (Margin-MSE).
AMP / GradScaler
Automatic mixed precision; scaler manages fp16 gradient overflow (I8).
DDP
Distributed Data Parallel: replicate model, all-reduce gradients across GPUs.
