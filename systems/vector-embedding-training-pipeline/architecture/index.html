Per-box dense notes:

  • Caller / inputs — raw corpora (text files / JSONL / parquet), optional qrels (relevance labels) and supervised pairs, a trained tokenizer artifact (#113), and a RunConfig YAML. Trust boundary: corpora are untrusted (size/encoding/PII risk) → validated + bounded in ingestion.
  • Ingestion & curation — normalizes text, dedups near-duplicates (MinHash LSH), filters by language + quality heuristics, constructs Example rows, writes immutable .vshard shards + a DataManifest (content hash, row counts, schema, dedup stats). Data version is pinned here and recorded in every downstream manifest (leakage + reproducibility).
  • Streaming loader — a seeded ShardSampler yields a deterministic, exactly-once-per-epoch permutation of (shard, row); workers decode shards, tokenize, collate into Batch; a bounded prefetch queue provides backpressure to the trainer. The epoch cursor is part of checkpoint state (resume).
  • Dual-encoder model — query tower + document tower (shared weights by default; separate optional). Each: encoder adapter (transformer) → pooling (CLS/mean/last-token) → projection head → L2 normalize. Output EmbeddingTensor [B, d] on the unit hypersphere (normalization is an invariant, I3). Optional cross-encoder teacher for distillation.
  • Hard-negative miner — periodically (every refresh_every steps) encodes the document corpus with the current model, builds a transient ANN index (+ static BM25), retrieves top-k near-but-wrong docs per query → NegativeCache. Cross-link #255 (reuses ANN), #113 (BM25 lexical). Runs off the training hot path; staleness is a tracked metric.
  • Loss + negatives — combines in-batch negatives, cross-device all-gathered negatives, cross-batch-memory queue, and mined hard negatives into one similarity matrix; computes InfoNCE/MNR/triplet with temperature τ, numerically stable (log-sum-exp). Gradient cache enables huge effective batch with bounded memory.
  • Trainer — AMP autocast + GradScaler, gradient accumulation, AdamW + LR scheduler (warmup+decay), grad clip, optimizer step; consumes each example exactly once per epoch; emits TrainMetrics (loss, grad norm, lr, throughput).
  • Distributed — DDP gradient all-reduce; the embedding all-gather that turns per-rank in-batch negatives into global negatives (the single most impactful distributed detail; gradient must flow through the local rank's slice only — I9). NCCL backend; deterministic collective ordering for replay.
  • Checkpoint + manifest — atomic checkpoint of model+optimizer+scheduler+sampler+RNG (CPU/CUDA/Python/numpy); RunManifest{data_version, code_hash, config_hash, library_versions}; resumable; a checkpoint↔config compatibility check refuses to resume with incompatible architecture/config (I7).
  • Evaluation — encodes a held-out eval corpus + queries, retrieves, computes Recall@k/MRR/nDCG/MAP against qrels, plus alignment/uniformity; regression gates block promotion if a tracked metric regresses beyond tolerance. Train/eval disjointness enforced (I1, leakage).
  • Export + handoff — selects the best checkpoint, exports the encoder to ONNX/TorchScript (parity-checked vs PyTorch), batch-embeds a target corpus, and emits a HandoffManifest (vectors + ids + model version + normalization contract) for the ANN index (#255) / semantic cache (#328).
  • Observability — loss/grad-norm/lr curves, collapse detector (alignment ↓, uniformity ↑, embedding-matrix rank, std-dev), throughput (samples/s, tokens/s, GPU util, loader wait), mining staleness; the replay harness re-runs a captured config+data+seed and asserts identical loss trajectory (determinism gate, Phase 11).

8. Domain Model

8.1 Example schema (training unit)

Example {
  id:           string                 # stable example id (for dedup, mining join)
  query:        string                 # anchor text (may carry task prefix, e.g. "query: ")
  positive:     string                 # relevant document text ("passage: ...")
  hard_negs:    list<string>           # mined hard negatives (may be empty early)
  hard_neg_ids: list<string>           # ids of negatives (to filter false negatives, I11)
  weight:       float = 1.0            # optional example weight (denoising/distillation)
  teacher_score:float|null             # optional cross-encoder score (distillation target)
  source:       string                 # corpus/source tag (for filtering/sampling)
}

Supervised variant carries qrels-derived positives; unsupervised variant (Contriever-style) derives (query, positive) as two spans of the same document. Every text is later tokenized to input_ids + attention_mask (≤ max_seq_len).

8.2 Tokenized Batch (collated, on device)

Batch {
  q_input_ids:   int32[B, Lq]      # query token ids (padded to Lq ≤ max_seq_len)
  q_attn_mask:   int8 [B, Lq]
  d_input_ids:   int32[B, Ld]      # positive-doc token ids
  d_attn_mask:   int8 [B, Ld]
  hn_input_ids:  int32[B, K, Ld]   # K mined hard negs per example (K may be 0)
  hn_attn_mask:  int8 [B, K, Ld]
  hn_ids:        int64[B, K]        # for false-negative filtering (I11)
  ex_ids:        int64[B]           # example ids (mining join, debugging)
  weight:        float32[B]
}

Collation pads to batch-max length (not global max) to save compute. Hard-neg tensor is ragged-padded; K=0 rows handled (in-batch negatives only).

8.3 .vshard on-disk format (sharded corpus)

DataManifest {
  data_version:   string            # content hash of the whole snapshot (pins reproducibility, I13)
  schema_version: semver
  n_examples:     u64
  n_shards:       u32
  shard_index:    list<ShardEntry>  # {path, n_rows, byte_offset_table_ref, crc32}
  tokenizer_ref:  string            # tokenizer artifact hash (#113)
  dedup_stats:    {near_dup_removed:u64, exact_dup_removed:u64}
  filter_stats:   {lang_dropped:u64, quality_dropped:u64}
  split:          enum{train, eval} # disjointness recorded per shard (I1)
}
ShardEntry { path, n_rows, crc32 }
  # Each .vshard = header + row-offset index + concatenated serialized Examples (length-prefixed).
  # Immutable once written. Random access via offset index; sequential decode for streaming.

8.4 Training state machine (run lifecycle)

 INIT ──build model/opt/sched, open dataset, stamp RunManifest──► READY
 READY ──(fresh)──► TRAINING            READY ──(--resume + compat OK, I7)──► TRAINING
 READY ──(--resume + compat FAIL)──► ABORTED(resume_compat_fail)
 TRAINING ──every refresh_every steps──► MINING ──cache refreshed──► TRAINING
 TRAINING ──every ckpt_every / on SIGTERM──► CHECKPOINTING ──atomic write (I6)──► TRAINING
 TRAINING ──every eval_every──► EVALUATING ──metrics + reg gate (Phase 8)──► TRAINING
 EVALUATING ──new best──► (mark best checkpoint)
 TRAINING ──max_steps / max_epochs reached──► DONE
 TRAINING ──NaN/Inf loss (I8) & no recovery──► FAILED(nan)
 DONE ──► EXPORTING ──parity OK (I14)──► HANDOFF ──manifest emitted──► COMPLETE
 (any) ──fatal (OOM/IO)──► FAILED ──(resume from last checkpoint)──► READY

States are sequential within a step boundary; MINING/CHECKPOINTING/EVALUATING are interludes that return to TRAINING. Only step boundaries are valid transition points (no mid-step mutation).

8.5 Loss / negative assembly (worked example, single rank, B=4, K=2)

q_emb [4,d], d_emb [4,d] (positives), hn_emb [4,2,d] (mined negs)
Similarity matrix S (cosine, since normalized):
  for query i: positives+negatives columns =
     [ d_emb[0..3] (in-batch: own positive is target, others are negatives) ,
       hn_emb[i,0..1] (own mined negs) ]
  S[i, :] = q_emb[i] · concat(d_emb, hn_emb[i]) / τ
  label[i] = i              # the diagonal positive (I10)
  loss = CrossEntropy(S/τ, label), excluding columns whose id ∈ positives of i (I11)
init sanity: with random embeddings, loss ≈ log(num_columns) (I10 check)

8.6 Distributed negative assembly (world=W, per-rank B → global B·W)

local q_emb[B,d], d_emb[B,d]
all_gather → d_emb_global[B·W, d]  (gradient flows only to THIS rank's B rows; others detached, I9)
S[i, :] = q_emb[i] · d_emb_global / τ          # B·W in-batch negatives
label[i] = rank*B + i                            # offset by rank (I10)
+ optional cross-batch-memory queue Q[M,d] (detached, momentum) concatenated as extra negatives

8.7 Mining refresh sequence (every refresh_every steps)

1. snapshot current encoder weights (eval mode, no grad)
2. batch-encode document corpus → doc_emb [N_docs, d]  (sharded across GPUs)
3. build transient ANN index (HNSW/IVF) over doc_emb (FAISS, #255 lib)
4. for each query: retrieve top-(k+margin) docs; drop true positives (I11) → top-k hard negs
5. (optional) BM25 lexical negs union; (optional) teacher score denoising (RocketQA-style)
6. write NegativeCache{ex_id → [neg_ids]}; bump cache_version; record staleness=0
7. resume TRAINING; loader injects hard_negs from cache by ex_id

8.8 State-transition table (collapse / recovery decisions, Phase 10)

Signal Healthy Warning Action
alignment (E‖q−d⁺‖²) decreasing flat check positives quality; raise mining freq
uniformity (log E e^{−2‖x−y‖²}) decreasing (more uniform) increasing collapse risk → lower LR / raise τ-care / more negatives
embedding std-dev across dims stable > floor → 0 collapse → abort, inspect (dead embeddings)
effective rank of embedding matrix ≈ d ≪ d dimensional collapse → add negatives / regularize
Recall@k on eval rising flat/falling negatives stale or LR wrong → mine + tune

8.9 Malformed / failure-path examples

  • Example with empty positive → curation drops it; quality_dropped++; never reaches loader.
  • Mined negative id equals the example's positive id → filtered (I11); false_negative_filtered++.
  • d from config ≠ encoder hidden after projection → ConfigError::EmbeddingDimMismatch at model build (I15).
  • Resume with a checkpoint whose arch_signature ≠ current config → ResumeError::IncompatibleCheckpoint (I7); no silent continue.
  • fp16 overflow in similarity logits → loss Inf → GradScaler skips step + reduces scale (I8); if persistent → FAILED(nan).
  • All examples in a batch share one positive (degenerate shard) → in-batch negatives become false negatives → flagged; batch reshuffled (I11/I2).

8.x Domain Deep Dive — Anatomy of a Contrastive Step with Global + Mined Negatives

(Unnumbered relative to 8.1–8.9 by design — a supplementary worked trace, not a core domain-model subsection, so its heading never collides with a Phase's own N.10 Operational Notes numbering; see §15 collision rule.)

A concrete trace of one optimizer step on a 4-GPU DDP run with InfoNCE, all-gathered global negatives, cross-batch memory, and mined hard negatives. Shows where each negative source enters, how the loss target is set, and why the distributed gradient is correct.

Setup: world W=4, device batch B=64, embedding d=768, τ=0.05, K=4 mined hard-negs/example, xbm queue M=8192. Effective in-batch negatives per query = B×W = 256; + xbm 8192 + mined 4 ⇒ ~8,452 negatives/query (≫ small-batch InfoNCE).

Per-rank step (rank r):

1. loader yields Batch (B queries + B positive docs + B×K mined-neg docs), tokenized, on device r
2. forward (AMP autocast): q_emb[64,768], d_emb[64,768], hn_emb[64,4,768]  (all L2-normalized, I3)
3. all_gather(d_emb) → d_global[256,768]   # gradient flows only to rank r's 64 rows (I9); others detached
4. xbm.negatives() → Q[8192,768]            # detached, momentum queue
5. assemble SimilarityMatrix for query i:
     cols = [ d_global[0..255]  (global in-batch: pos at col r*64+i) ,
              Q[0..8191]         (cross-batch memory negs) ,
              hn_emb[i,0..3]     (this query's mined hard negs) ]
     logits[i,:] = q_emb[i] · cols / τ        # fp32 (I8)
     label[i] = r*64 + i                        # offset by rank (I10)
     mask_false_neg: exclude any col whose doc-id ∈ positives(i)  (I11)
6. loss = weighted CrossEntropy(logits, label) over masked cols   # ≈ ln(num_cols) at init (I10)
7. scaler.scale(loss).backward()              # DDP all-reduces grads (bucketed, overlaps backward)
8. xbm.enqueue(d_emb.detach())                # update cross-batch memory
9. scaler.unscale_; clip_grad_norm; scaler.step(optim); scaler.update; sched.step()
10. emit TrainMetrics(loss, grad_norm, lr, samples/s); every refresh_every → MINING interlude (Phase 6)

Why the distributed gradient is correct (I9): in step 3, all_gather returns all 256 document embeddings, but the autograd graph attaches gradient only to rank r's own 64 rows (the other 192 are detached copies). So each rank contributes gradient for its documents as positives/negatives, and DDP all-reduce (step 7) sums the query-tower and document-tower gradients across ranks. The net effect is identical to a single-GPU run with batch 256 — proven by the equivalence test (I9). Get the detach wrong and gradients are double-counted or zeroed: silent corruption that only the equivalence test catches.

Why the loss target is correct (I10/I11): the positive for query i is its own document, now at global column r*64 + i after gather. A naïve label=i would point at rank-0's i-th document — wrong on ranks > 0. The false-negative mask (I11) removes any negative column that is actually relevant to query i (e.g., a mined neg that is secretly a positive, or another query's positive that also answers i) so the model is never penalized for ranking a correct document highly.

Why the negatives matter (principle 5/6): with B=64 alone, InfoNCE sees 63 negatives — too few; the model trivially separates them and learns a weak embedding. All-gather lifts that to 255 (free, embeddings are tiny), the xbm queue adds 8,192 recent negatives (detached, near-free), and mining adds 4 hard negatives per query (the ones the current model wrongly ranks high — the only negatives that still carry signal late in training). Effective negatives ≈ 8,452 within a 24 GiB budget — the whole point of the negative-engineering stack.

Determinism (I4): every input to the step is reproducible — seeded sampler (exactly-once, I2), deterministic tokenization, deterministic encoder (seeded dropout), deterministic all-gather/all-reduce ordering, fixed τ. Replaying (config, data_version, seed, world=4) reproduces this exact loss value and the entire trajectory within fp tolerance.

Failure-path variant (stale negatives): suppose mining last refreshed 40k steps ago (refresh loop silently failed). The mined hard-negs are now near-trivial for the current model → loss is artificially low, grad signal weak, eval Recall plateaus. staleness_steps reads 40,000 ≫ refresh_every=5,000 → alert fires (principle 11). The fix is to repair/re-run the refresh loop, not to keep burning GPU on easy negatives — the exact failure the staleness metric exists to surface.

Design principles (§6)

  • Determinism over convenience. Identical (config, data_version, seed, world_size) ⇒ identical sample order + loss trajectory (fp tolerance). All randomness flows from named, seeded generators; torch.use_deterministic_algorithms(True); deterministic collective ordering. Tradeoff: some fast nondeterministic kernels disabled (small throughput cost). Violation: irreproducible runs → undebuggable regressions; the replay gate fails.
  • Exactly-once example consumption per epoch. The ShardSampler produces a permutation visiting each example once per epoch; the cursor is checkpointed. Tradeoff: sampler state adds checkpoint complexity. Violation: duplicated/skipped examples bias training; resume diverges from an uninterrupted run.
  • Embeddings live on the unit hypersphere. Every embedding the loss, eval, export, or index sees is L2-normalized (‖v‖₂=1±1e-5). Temperature, not magnitude, controls sharpness. Tradeoff: normalization layer on the hot path. Violation: cosine vs dot-product ambiguity; index built on un-normalized vectors returns wrong neighbors (training-serving skew).
  • Train and eval are disjoint and audited. No eval/qrels document or query appears in training data; the data pipeline enforces and logs disjointness. Tradeoff: curation overhead, smaller train set. Violation: metric inflation, a model that "evaluates well" but doesn't generalize — the single most common silent failure in embedding work.
  • Negatives are the product; positives are easy. Engineering effort centers on negatives — in-batch, global (all-gather), cross-batch memory, and mined hard negatives refreshed from the current model. Tradeoff: mining infrastructure (index rebuild, cache). Violation: easy/random negatives → loss drops but Recall@k stalls; the model learns nothing useful.
  • Effective batch is decoupled from device memory. Gradient accumulation × world size × cross-batch memory × gradient cache yield a large effective negative pool independent of GPU RAM. Tradeoff: gradient-cache adds a two-pass forward. Violation: contrastive learning starved of negatives → weak embeddings (small-batch InfoNCE underperforms).
  • Numerical stability is mandatory. Contrastive loss via log-sum-exp; loss + softmax in fp32 even under AMP; GradScaler for fp16; assert finite loss/grads. Tradeoff: casts on the hot path. Violation: NaN loss, silent fp16 overflow, training divergence.
  • Backpressure between loader and trainer. Bounded prefetch queue; loader never outpaces or starves the trainer unboundedly. Tradeoff: tuning queue depth. Violation: unbounded prefetch OOMs host RAM, or a slow loader idles the GPU (low util).
  • Checkpoint is complete and atomic. Model + optimizer + scheduler + sampler cursor + all RNG states, written atomically (temp + rename). A checkpoint↔config compatibility check gates resume. Tradeoff: larger checkpoints (optimizer + master weights). Violation: resume that silently changes the run; corrupt partial checkpoint on crash.
  • Evaluation gates releases, loss does not. Promotion/export is gated on retrieval metrics (Recall@k/MRR/nDCG/MAP) with regression tolerances — never on training loss alone. Tradeoff: eval cost per checkpoint. Violation: shipping a model whose loss improved but retrieval regressed.
  • The mining loop must not stall or go stale silently. Refresh cadence bounded; staleness is a tracked, alertable metric; mining runs off the training hot path with its own failure containment. Tradeoff: periodic throughput dips at refresh. Violation: negatives mined from a 50k-step-old model → effectively easy → wasted compute.
  • Observability is not optional. Loss/grad-norm/lr, alignment/uniformity/rank (collapse), throughput, mining staleness emitted on the hot path as cheap scalars. Tradeoff: logging overhead. Violation: collapse discovered only at eval, after burning a week of GPU time.
  • Bounded resource usage. GPU/host memory ceilings, prefetch depth, negative-cache size, FD budget, checkpoint retention all explicit. Tradeoff: tuning. Violation: one run starves the box (host OOM from prefetch, disk full from un-GC'd checkpoints).
  • Data and model are versioned and joined in the manifest. Every checkpoint/export records data_version, code_hash, config_hash, library versions. Tradeoff: manifest plumbing. Violation: "which data + code produced this model?" is unanswerable → unauditable, unreproducible.
  • Export preserves the training contract. Exported encoder (ONNX/TorchScript) reproduces eager outputs within tolerance, applies the same pooling + normalization, and the handoff manifest states the normalization + distance contract. Tradeoff: parity testing. Violation: training-serving skew — the index returns different neighbors than training assumed.
