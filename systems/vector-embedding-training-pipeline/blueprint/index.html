Project Number: 329

Project Name: Vector Embedding Training Pipeline from Scratch

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal

Build an end-to-end Vector Embedding Training Pipeline (VETP): a system that trains dense text (optionally multimodal) embedding models from scratch via contrastive / metric learning, producing L2-normalized vectors for retrieval and similarity. Input is raw corpora (+ optional supervised labels); output is a versioned embedding model + exported encoder + an evaluation report + an ANN-index handoff manifest. The novelty over a plain training loop: a closed data↔model loop — the model mines its own hard negatives (BM25/ANN over current embeddings), refreshes them on a schedule, and the whole run is deterministic and resumable (exactly-once example consumption, checkpoint↔config compatibility, fixed-seed shuffling).

System boundaries (in scope):

  • Data ingestion & curation: corpora ingest, dedup (MinHash/SimHash), language + quality filtering, (query, positive, hard_negatives[]) example schema, sharded on-disk format (.vshard), streaming reader, reproducible seeded shuffling.
  • Pair / triplet mining: positive construction (in-batch, mined, supervised), hard-negative mining (BM25 + ANN over current model), negative cache + scheduled refresh.
  • Tokenizer integration: BPE / WordPiece interface, padding/truncation, max-seq-len, attention masks (cross-link #113 BPE Tokenizer).
  • Model: dual-encoder / bi-encoder (shared or separate towers), pooling (CLS / mean / last-token), projection head, L2 normalization; optional cross-encoder teacher for distillation.
  • Losses: InfoNCE / NT-Xent, triplet/margin, multiple-negatives-ranking (MNR), temperature; in-batch negatives; large-batch tricks (cross-batch memory, gradient cache) for huge effective batch.
  • Distributed training: data-parallel (DDP-style), gradient sync, all-gather of embeddings for global negatives, mixed precision (AMP), gradient accumulation; ZeRO-style sharding deferred.
  • Checkpointing & reproducibility: deterministic seeds, checkpoint = model+optimizer+scheduler+sampler+RNG, resumable, run manifest (data version + code hash + config), exactly-once per-epoch consumption.
  • Evaluation: retrieval benchmarks; metrics = Recall@k, MRR, nDCG, MAP; embedding quality (alignment/uniformity); held-out harness; regression gates (cross-link #331 AI Evaluation Harness).
  • Export & handoff: model versioning, ONNX / TorchScript export, batch embedding generation, handoff to ANN index (#255), feeds #328 Semantic Caching Engine.
  • Observability: loss curves, gradient norms, embedding-collapse detection (alignment/uniformity/rank), throughput (samples/s, tokens/s, GPU util), negative-mining staleness.

Explicit non-goals (each deferred via PhaseDeferred(...); every anchor below resolves to a real heading and is listed in the Deferred Features Register):

  • Pretraining a base LM from scratch — encoder may init from random OR a provided checkpoint; MLM pretraining is out of scope. PhaseDeferred("§1 non-goal") (cross-link #114 Transformer Training).
  • The ANN index internals — VETP produces vectors + a handoff manifest; the index is #255. PhaseDeferred("Phase 11").
  • Tokenizer training itself — VETP consumes a trained tokenizer artifact (#113). PhaseDeferred("§1 non-goal").
  • Model-parallel / tensor-parallel / ZeRO-3 parameter sharding — data-parallel only here. PhaseDeferred("Phase 9") (cross-link #115, #250).
  • RLHF / preference optimization of embeddings. PhaseDeferred("§1 non-goal") (cross-link #120).
  • Online / streaming continual training; VETP runs are batch jobs over a frozen data snapshot. PhaseDeferred("§1 non-goal").
  • Production serving of embeddings at QPS — export only; serving is downstream. PhaseDeferred("§1 non-goal").

Deployment model: a Python package (vetp) + a vetp CLI. Subcommands: vetp ingest, vetp mine, vetp train, vetp eval, vetp export, vetp handoff, vetp replay. Runs single-GPU, multi-GPU single-node (DDP), or CPU (smoke). Reads a RunConfig (YAML) + data snapshot; writes checkpoints, manifests, eval reports, exported encoders, and an ANN handoff bundle to a run directory. Embeds in an MLOps pipeline as the "train an embedding model" stage.

Target users/operators/developers: ML/IR engineers training retrieval embeddings; data-infra engineers debugging negative-mining staleness or embedding collapse at 3 a.m.; learners who want the Sentence-Transformers / DPR / E5 / GTE training stack built end to end with production discipline.

Phase 0 deliverable (numbered packages/modules):

  1. vetp.types — Example, Batch, Schema, RunConfig, EmbeddingTensor, error hierarchy.
  2. vetp.data — .vshard reader/writer skeleton, StreamingDataset, seeded ShardSampler (rows/bytes counting only).
  3. vetp.tokenize — tokenizer adapter interface, padding/truncation, attention mask.
  4. vetp.model — DualEncoder skeleton (encoder adapter + pooling + projection + L2 norm) forward only.
  5. vetp.loss — InfoNCE (in-batch) skeleton.
  6. vetp.train — single-device train step + loop scaffold (no AMP/accum yet).
  7. vetp.eval — metric stubs (recall_at_k, mrr, ndcg, map) + harness skeleton.
  8. vetp.manifest — RunManifest, Checkpoint schema, config-hash + data-version stamping.
  9. vetp — CLI dispatch: ingest/train/eval wired to a tiny end-to-end smoke run.

What later phases unlock: sharded ingest + dedup + streaming loader (Phase 1); tokenizer hardening (Phase 2); full dual-encoder + pooling/normalization (Phase 3); contrastive losses + in-batch negatives + single-GPU loop (Phase 4); checkpoint+resume+reproducibility (Phase 5); hard-negative mining + refresh loop (Phase 6); distributed DDP + cross-device negative gather + AMP + gradient cache (Phase 7); evaluation harness + retrieval metrics + regression gates (Phase 8); export + ANN handoff (Phase 9); observability + collapse detection (Phase 10); soak + reproducibility conformance (Phase 11).

Timeline: Phase 0 = 6–14 weeks. Full plan = 6–9 months.

Recommended language: Python 3.11+ with a PyTorch-style autodiff/training core, plus a fast data loader extension (Rust via PyO3, optional). Rationale: (a) the deep-learning ecosystem (autodiff, AMP, NCCL collectives, ONNX/TorchScript export, optimizer/scheduler library) is Python-native — reimplementing it would dwarf the project's actual subject (the pipeline + contrastive learning + mining loop); (b) portfolio convention — #114 Transformer Training Loop, #115 Distributed Training, #120 RLHF are Python; (c) the hot data path (shard decode, tokenize, hard-negative cache lookups) is the one place Python's GIL hurts, so that path is isolated behind a typed loader interface implementable as a Rust/C extension (justified ADR-001/ADR-004); (d) determinism is achievable in PyTorch (torch.use_deterministic_algorithms, seeded generators, deterministic NCCL ops) — required for our replay gate; (e) pytest + hypothesis + torch.testing cover property/numerical/conformance testing the contrastive math demands. Locked in ADR-001.

Prerequisites: linear algebra (cosine similarity, L2 norm, matmul); softmax / cross-entropy; transformers & attention (encoder, pooling); contrastive/metric learning (InfoNCE, triplet, temperature); information retrieval (BM25, Recall@k/MRR/nDCG/MAP, qrels); SGD/Adam/AdamW + LR schedules; mixed precision + gradient scaling; data-parallel training + collective ops (all-reduce, all-gather); ANN indexing basics (HNSW/IVF) for mining + handoff; reproducibility hygiene (seeds, determinism flags); on-disk sharded data formats + streaming I/O.

2. Why Build This

  • Unique systems knowledge: the data↔model feedback loop of representation learning. Most "train a model" projects teach the optimizer step; VETP teaches what makes embeddings actually retrieve well — hard-negative mining refreshed from the current model, global negatives via cross-device all-gather, effective batch decoupled from device batch (gradient cache / cross-batch memory), and collapse avoidance. This is where DPR, ANCE, E5, GTE, and Sentence-Transformers get their wins.
  • Historical/architectural significance: the field's shift from sparse lexical retrieval (BM25) and word2vec/GloVe static embeddings to dense dual-encoder retrieval trained contrastively (DPR 2020, SimCSE 2021, E5 2022, GTE/BGE 2023). VETP rebuilds that training recipe: bi-encoder + InfoNCE + in-batch + mined hard negatives + large effective batch.
  • Engineering muscles: deterministic large-scale data pipelines; exactly-once streaming consumption; numerically-stable contrastive loss (log-sum-exp, temperature, fp16 overflow); distributed embedding all-gather with correct gradient flow; checkpoint/resume of all RNG + sampler state; an offline↔online mining loop that doesn't deadlock or go stale; evaluation that gates releases (retrieval metrics, not loss).
  • Production concepts exercised: data versioning + run manifests; mixed precision + gradient accumulation; backpressure between the loader and the trainer; embedding-collapse detection (alignment/uniformity/rank); regression gates; model versioning + export + downstream handoff contracts.
  • Cross-links:
    • #113 BPE Tokenizer — the tokenizer artifact VETP consumes (vetp.tokenize adapter).
    • #114 Transformer Training Loop — the encoder forward/backward + AMP discipline VETP reuses for its towers.
    • #115 Distributed Training / #250 Distributed Parameter Server — the DDP + collective patterns vetp.dist builds on; ZeRO deferred to them.
    • #46 Embedding + Similarity Search / #255 ANN Index — the consumer of VETP's vectors; vetp.export produces their handoff bundle.
    • #331 AI Evaluation Harness — shares metric definitions + regression-gate philosophy with vetp.eval.
    • #328 Semantic Caching Engine — a downstream user of VETP-trained embeddings.
  • Calibration value: after this you can diagnose any embedding model that "trains but doesn't retrieve" (collapse, stale/easy negatives, temperature wrong, eval leakage), reason about effective-batch tricks, and design a reproducible training pipeline whose results a colleague can byte-reproduce.

What Mastery Looks Like — concrete competencies the finished builder holds, each earned in a named phase:

  • Assemble a numerically-stable contrastive loss and prove its target index — write InfoNCE/MNR/triplet over a similarity matrix, force fp32 + log-sum-exp, and demonstrate the init-loss ≈ ln(num_cols) check that catches a label off-by-one (Phase 0, Phase 4; I8/I10).
  • Make a large-scale data pipeline deterministic and exactly-once — a seeded sampler whose epoch permutation, cursor, and resume reproduce the same (shard,row) order byte-for-byte, with leakage proven absent (Phase 1; I1/I2).
  • Decouple effective batch from device memory — combine gradient accumulation, cross-batch memory, and gradient cache to reach ≥ 16,384 effective batch inside 24 GiB, and explain why small-batch InfoNCE underperforms (Phase 4, Phase 7; ADR-014/ADR-015).
  • Get distributed contrastive gradients provably correct — implement the embedding all-gather where gradient flows only through the local rank's slice, and gate it with a single-GPU-vs-multi-GPU equivalence test (Phase 7; I9).
  • Run the data↔model feedback loop without stalling or going stale — mine hard negatives from the current model on a bounded schedule, filter false negatives, and treat staleness as an alertable metric (Phase 6; I11, P11).
  • Gate releases on retrieval metrics, not loss — compute Recall@k/MRR/nDCG/MAP against qrels matching a reference implementation, and detect collapse online via alignment/uniformity/rank before eval would (Phase 8, Phase 10; P10/P12).
  • Guarantee byte-reproducibility and zero training-serving skew — a replay harness that re-derives an identical loss trajectory, plus an exported encoder whose ONNX/TorchScript output matches eager within tolerance under a stated normalization+distance contract (Phase 9, Phase 11; I4/I14/I15).

Per-box dense notes:

  • Caller / inputs — raw corpora (text files / JSONL / parquet), optional qrels (relevance labels) and supervised pairs, a trained tokenizer artifact (#113), and a RunConfig YAML. Trust boundary: corpora are untrusted (size/encoding/PII risk) → validated + bounded in ingestion.
  • Ingestion & curation — normalizes text, dedups near-duplicates (MinHash LSH), filters by language + quality heuristics, constructs Example rows, writes immutable .vshard shards + a DataManifest (content hash, row counts, schema, dedup stats). Data version is pinned here and recorded in every downstream manifest (leakage + reproducibility).
  • Streaming loader — a seeded ShardSampler yields a deterministic, exactly-once-per-epoch permutation of (shard, row); workers decode shards, tokenize, collate into Batch; a bounded prefetch queue provides backpressure to the trainer. The epoch cursor is part of checkpoint state (resume).
  • Dual-encoder model — query tower + document tower (shared weights by default; separate optional). Each: encoder adapter (transformer) → pooling (CLS/mean/last-token) → projection head → L2 normalize. Output EmbeddingTensor [B, d] on the unit hypersphere (normalization is an invariant, I3). Optional cross-encoder teacher for distillation.
  • Hard-negative miner — periodically (every refresh_every steps) encodes the document corpus with the current model, builds a transient ANN index (+ static BM25), retrieves top-k near-but-wrong docs per query → NegativeCache. Cross-link #255 (reuses ANN), #113 (BM25 lexical). Runs off the training hot path; staleness is a tracked metric.
  • Loss + negatives — combines in-batch negatives, cross-device all-gathered negatives, cross-batch-memory queue, and mined hard negatives into one similarity matrix; computes InfoNCE/MNR/triplet with temperature τ, numerically stable (log-sum-exp). Gradient cache enables huge effective batch with bounded memory.
  • Trainer — AMP autocast + GradScaler, gradient accumulation, AdamW + LR scheduler (warmup+decay), grad clip, optimizer step; consumes each example exactly once per epoch; emits TrainMetrics (loss, grad norm, lr, throughput).
  • Distributed — DDP gradient all-reduce; the embedding all-gather that turns per-rank in-batch negatives into global negatives (the single most impactful distributed detail; gradient must flow through the local rank's slice only — I9). NCCL backend; deterministic collective ordering for replay.
  • Checkpoint + manifest — atomic checkpoint of model+optimizer+scheduler+sampler+RNG (CPU/CUDA/Python/numpy); RunManifest{data_version, code_hash, config_hash, library_versions}; resumable; a checkpoint↔config compatibility check refuses to resume with incompatible architecture/config (I7).
  • Evaluation — encodes a held-out eval corpus + queries, retrieves, computes Recall@k/MRR/nDCG/MAP against qrels, plus alignment/uniformity; regression gates block promotion if a tracked metric regresses beyond tolerance. Train/eval disjointness enforced (I1, leakage).
  • Export + handoff — selects the best checkpoint, exports the encoder to ONNX/TorchScript (parity-checked vs PyTorch), batch-embeds a target corpus, and emits a HandoffManifest (vectors + ids + model version + normalization contract) for the ANN index (#255) / semantic cache (#328).
  • Observability — loss/grad-norm/lr curves, collapse detector (alignment ↓, uniformity ↑, embedding-matrix rank, std-dev), throughput (samples/s, tokens/s, GPU util, loader wait), mining staleness; the replay harness re-runs a captured config+data+seed and asserts identical loss trajectory (determinism gate, Phase 11).

4. System Constraints

Dimension Target
GPU memory ceiling (per device) configurable; default fit 24 GiB; activation checkpointing + grad cache keep effective batch ≫ device batch
Device batch size default 64 examples/device; effective batch (with accum × world × xbm) target ≥ 16,384
Effective negatives per query in-batch + gathered + xbm + mined; target ≥ 4,096 negatives/query
Training throughput (single A100-class GPU, 110M encoder, seq 128) ≥ 2,000 examples/s forward+backward (AMP)
Loader throughput ≥ 1.2× trainer consumption (never the bottleneck); prefetch hides decode+tokenize
Tokenization throughput ≥ 200K examples/s aggregate across loader workers (cached short texts)
Hard-negative refresh latency corpus re-encode + index build ≤ 10 min for 1M docs (8 GPUs); off hot path
Negative staleness budget mined negs refreshed every ≤ refresh_every steps (default 5,000); staleness ≤ that window
Checkpoint write atomic; ≤ 30 s for 110M-param model (fp32 master + optimizer); never blocks > 1 step boundary
Checkpoint cadence every ckpt_every steps (default 2,000) + on best-eval
Resume correctness bit-resumable: post-resume loss trajectory == uninterrupted run (within fp tolerance)
Eval latency (encode + retrieve, 100K corpus, 10K queries) ≤ 5 min on 1 GPU
Scaling efficiency (DDP) ≥ 0.85× linear to 8 GPUs single node (NVLink/NCCL)
All-gather overhead (embeddings) ≤ 5% step time at world=8 (embeddings are small: B×d×2 bytes)
Startup (CLI cold → first train step) ≤ 60 s (model build + dataset open + first batch)
Shutdown / fault atomic checkpoint on SIGTERM; resume from last checkpoint; no corrupt partial checkpoint
Determinism identical (config, data_version, seed, world_size) ⇒ identical loss trajectory (fp tolerance) + identical sample order
Numerical no NaN/Inf in loss or grads (I8); fp16 overflow handled by GradScaler; loss in fp32
Storage amplification (shards) ≤ 1.3× raw text (tokenization deferred to load time; shards store text + ids)
Embedding contract every exported/queried vector is L2-normalized (‖v‖₂ = 1 ± 1e-5) (I3)
Train/eval leakage zero overlap between train and eval/qrels corpora (I1); enforced + audited

Scaling assumptions: single node, 1–8 GPUs (A100/H100-class), 100M–1B parameter encoders, corpora 10⁶–10⁸ examples. Multi-node + ZeRO deferred (cross-link #115/#250). Vertical scaling: AMP + activation checkpointing + gradient cache push effective batch up; horizontal scaling: DDP + embedding all-gather grows global negatives with world size.

6. Design Principles

  1. Determinism over convenience. Identical (config, data_version, seed, world_size) ⇒ identical sample order + loss trajectory (fp tolerance). All randomness flows from named, seeded generators; torch.use_deterministic_algorithms(True); deterministic collective ordering. Tradeoff: some fast nondeterministic kernels disabled (small throughput cost). Violation: irreproducible runs → undebuggable regressions; the replay gate fails.
  2. Exactly-once example consumption per epoch. The ShardSampler produces a permutation visiting each example once per epoch; the cursor is checkpointed. Tradeoff: sampler state adds checkpoint complexity. Violation: duplicated/skipped examples bias training; resume diverges from an uninterrupted run.
  3. Embeddings live on the unit hypersphere. Every embedding the loss, eval, export, or index sees is L2-normalized (‖v‖₂=1±1e-5). Temperature, not magnitude, controls sharpness. Tradeoff: normalization layer on the hot path. Violation: cosine vs dot-product ambiguity; index built on un-normalized vectors returns wrong neighbors (training-serving skew).
  4. Train and eval are disjoint and audited. No eval/qrels document or query appears in training data; the data pipeline enforces and logs disjointness. Tradeoff: curation overhead, smaller train set. Violation: metric inflation, a model that "evaluates well" but doesn't generalize — the single most common silent failure in embedding work.
  5. Negatives are the product; positives are easy. Engineering effort centers on negatives — in-batch, global (all-gather), cross-batch memory, and mined hard negatives refreshed from the current model. Tradeoff: mining infrastructure (index rebuild, cache). Violation: easy/random negatives → loss drops but Recall@k stalls; the model learns nothing useful.
  6. Effective batch is decoupled from device memory. Gradient accumulation × world size × cross-batch memory × gradient cache yield a large effective negative pool independent of GPU RAM. Tradeoff: gradient-cache adds a two-pass forward. Violation: contrastive learning starved of negatives → weak embeddings (small-batch InfoNCE underperforms).
  7. Numerical stability is mandatory. Contrastive loss via log-sum-exp; loss + softmax in fp32 even under AMP; GradScaler for fp16; assert finite loss/grads. Tradeoff: casts on the hot path. Violation: NaN loss, silent fp16 overflow, training divergence.
  8. Backpressure between loader and trainer. Bounded prefetch queue; loader never outpaces or starves the trainer unboundedly. Tradeoff: tuning queue depth. Violation: unbounded prefetch OOMs host RAM, or a slow loader idles the GPU (low util).
  9. Checkpoint is complete and atomic. Model + optimizer + scheduler + sampler cursor + all RNG states, written atomically (temp + rename). A checkpoint↔config compatibility check gates resume. Tradeoff: larger checkpoints (optimizer + master weights). Violation: resume that silently changes the run; corrupt partial checkpoint on crash.
  10. Evaluation gates releases, loss does not. Promotion/export is gated on retrieval metrics (Recall@k/MRR/nDCG/MAP) with regression tolerances — never on training loss alone. Tradeoff: eval cost per checkpoint. Violation: shipping a model whose loss improved but retrieval regressed.
  11. The mining loop must not stall or go stale silently. Refresh cadence bounded; staleness is a tracked, alertable metric; mining runs off the training hot path with its own failure containment. Tradeoff: periodic throughput dips at refresh. Violation: negatives mined from a 50k-step-old model → effectively easy → wasted compute.
  12. Observability is not optional. Loss/grad-norm/lr, alignment/uniformity/rank (collapse), throughput, mining staleness emitted on the hot path as cheap scalars. Tradeoff: logging overhead. Violation: collapse discovered only at eval, after burning a week of GPU time.
  13. Bounded resource usage. GPU/host memory ceilings, prefetch depth, negative-cache size, FD budget, checkpoint retention all explicit. Tradeoff: tuning. Violation: one run starves the box (host OOM from prefetch, disk full from un-GC'd checkpoints).
  14. Data and model are versioned and joined in the manifest. Every checkpoint/export records data_version, code_hash, config_hash, library versions. Tradeoff: manifest plumbing. Violation: "which data + code produced this model?" is unanswerable → unauditable, unreproducible.
  15. Export preserves the training contract. Exported encoder (ONNX/TorchScript) reproduces eager outputs within tolerance, applies the same pooling + normalization, and the handoff manifest states the normalization + distance contract. Tradeoff: parity testing. Violation: training-serving skew — the index returns different neighbors than training assumed.

8.1 Example schema (training unit)

  positive:     string                 # relevant document text ("passage: ...")

8.5 Loss / negative assembly (worked example, single rank, B=4, K=2)

q_emb [4,d], d_emb [4,d] (positives), hn_emb [4,2,d] (mined negs)
Similarity matrix S (cosine, since normalized):
  for query i: positives+negatives columns =
     [ d_emb[0..3] (in-batch: own positive is target, others are negatives) ,
       hn_emb[i,0..1] (own mined negs) ]
  S[i, :] = q_emb[i] · concat(d_emb, hn_emb[i]) / τ
  label[i] = i              # the diagonal positive (I10)
  loss = CrossEntropy(S/τ, label), excluding columns whose id ∈ positives of i (I11)
init sanity: with random embeddings, loss ≈ log(num_columns) (I10 check)

8.6 Distributed negative assembly (world=W, per-rank B → global B·W)

local q_emb[B,d], d_emb[B,d]
all_gather → d_emb_global[B·W, d]  (gradient flows only to THIS rank's B rows; others detached, I9)
S[i, :] = q_emb[i] · d_emb_global / τ          # B·W in-batch negatives
label[i] = rank*B + i                            # offset by rank (I10)
+ optional cross-batch-memory queue Q[M,d] (detached, momentum) concatenated as extra negatives

8.7 Mining refresh sequence (every refresh_every steps)

1. snapshot current encoder weights (eval mode, no grad)
2. batch-encode document corpus → doc_emb [N_docs, d]  (sharded across GPUs)
3. build transient ANN index (HNSW/IVF) over doc_emb (FAISS, #255 lib)
4. for each query: retrieve top-(k+margin) docs; drop true positives (I11) → top-k hard negs
5. (optional) BM25 lexical negs union; (optional) teacher score denoising (RocketQA-style)
6. write NegativeCache{ex_id → [neg_ids]}; bump cache_version; record staleness=0
7. resume TRAINING; loader injects hard_negs from cache by ex_id

8.9 Malformed / failure-path examples

  • Example with empty positive → curation drops it; quality_dropped++; never reaches loader.
  • Mined negative id equals the example's positive id → filtered (I11); false_negative_filtered++.

8.x Domain Deep Dive — Anatomy of a Contrastive Step with Global + Mined Negatives

(Unnumbered relative to 8.1–8.9 by design — a supplementary worked trace, not a core domain-model subsection, so its heading never collides with a Phase's own N.10 Operational Notes numbering; see §15 collision rule.)

A concrete trace of one optimizer step on a 4-GPU DDP run with InfoNCE, all-gathered global negatives, cross-batch memory, and mined hard negatives. Shows where each negative source enters, how the loss target is set, and why the distributed gradient is correct.

Setup: world W=4, device batch B=64, embedding d=768, τ=0.05, K=4 mined hard-negs/example, xbm queue M=8192. Effective in-batch negatives per query = B×W = 256; + xbm 8192 + mined 4 ⇒ ~8,452 negatives/query (≫ small-batch InfoNCE).

Per-rank step (rank r):

1. loader yields Batch (B queries + B positive docs + B×K mined-neg docs), tokenized, on device r
2. forward (AMP autocast): q_emb[64,768], d_emb[64,768], hn_emb[64,4,768]  (all L2-normalized, I3)
3. all_gather(d_emb) → d_global[256,768]   # gradient flows only to rank r's 64 rows (I9); others detached
4. xbm.negatives() → Q[8192,768]            # detached, momentum queue
5. assemble SimilarityMatrix for query i:
     cols = [ d_global[0..255]  (global in-batch: pos at col r*64+i) ,
              Q[0..8191]         (cross-batch memory negs) ,
              hn_emb[i,0..3]     (this query's mined hard negs) ]
     logits[i,:] = q_emb[i] · cols / τ        # fp32 (I8)
     label[i] = r*64 + i                        # offset by rank (I10)
     mask_false_neg: exclude any col whose doc-id ∈ positives(i)  (I11)
6. loss = weighted CrossEntropy(logits, label) over masked cols   # ≈ ln(num_cols) at init (I10)
7. scaler.scale(loss).backward()              # DDP all-reduces grads (bucketed, overlaps backward)
8. xbm.enqueue(d_emb.detach())                # update cross-batch memory
9. scaler.unscale_; clip_grad_norm; scaler.step(optim); scaler.update; sched.step()
10. emit TrainMetrics(loss, grad_norm, lr, samples/s); every refresh_every → MINING interlude (Phase 6)

Why the distributed gradient is correct (I9): in step 3, all_gather returns all 256 document embeddings, but the autograd graph attaches gradient only to rank r's own 64 rows (the other 192 are detached copies). So each rank contributes gradient for its documents as positives/negatives, and DDP all-reduce (step 7) sums the query-tower and document-tower gradients across ranks. The net effect is identical to a single-GPU run with batch 256 — proven by the equivalence test (I9). Get the detach wrong and gradients are double-counted or zeroed: silent corruption that only the equivalence test catches.

Why the loss target is correct (I10/I11): the positive for query i is its own document, now at global column r*64 + i after gather. A naïve label=i would point at rank-0's i-th document — wrong on ranks > 0. The false-negative mask (I11) removes any negative column that is actually relevant to query i (e.g., a mined neg that is secretly a positive, or another query's positive that also answers i) so the model is never penalized for ranking a correct document highly.

Why the negatives matter (principle 5/6): with B=64 alone, InfoNCE sees 63 negatives — too few; the model trivially separates them and learns a weak embedding. All-gather lifts that to 255 (free, embeddings are tiny), the xbm queue adds 8,192 recent negatives (detached, near-free), and mining adds 4 hard negatives per query (the ones the current model wrongly ranks high — the only negatives that still carry signal late in training). Effective negatives ≈ 8,452 within a 24 GiB budget — the whole point of the negative-engineering stack.

Determinism (I4): every input to the step is reproducible — seeded sampler (exactly-once, I2), deterministic tokenization, deterministic encoder (seeded dropout), deterministic all-gather/all-reduce ordering, fixed τ. Replaying (config, data_version, seed, world=4) reproduces this exact loss value and the entire trajectory within fp tolerance.

Failure-path variant (stale negatives): suppose mining last refreshed 40k steps ago (refresh loop silently failed). The mined hard-negs are now near-trivial for the current model → loss is artificially low, grad signal weak, eval Recall plateaus. staleness_steps reads 40,000 ≫ refresh_every=5,000 → alert fires (principle 11). The fix is to repair/re-run the refresh loop, not to keep burning GPU on easy negatives — the exact failure the staleness metric exists to surface.

In-batch-only wins when the device batch is already huge (e.g. SimCLR-scale 4k+ on a TPU pod) so in-batch negatives saturate the loss and mining/xbm add complexity for no gain.
015 Large effective batch gradient cache (GradCache) + grad accumulation bigger GPU only Decouple effective batch from memory (principle 6). "Bigger GPU" wins when an 80 GB H100 (or pod) fits the target batch directly — GradCache's extra no-grad forward pass is then pure overhead.
016 Hard-neg mining ANN (FAISS) over current model + BM25; refreshed static random negs ANCE-style mining is the central idea (Phase 6). Static random negatives win in the earliest training phase (random model → ANN negs are noise) and for tiny corpora where every non-positive is effectively in-batch already.
017 ANN library (mining + handoff) FAISS (depend, not reimplement) reimplement index Index internals are #255; VETP consumes/handoffs. Reimplementing wins only when the project's subject is the index (#255), or when a custom on-disk/streaming ANN is required that FAISS does not provide.

SGD+momentum wins for very long training of vision-style encoders where it generalizes better and uses half the optimizer-state memory; plain Adam wins where decoupled weight decay is undesired.

Loss-only gating wins for a fast inner-loop hyperparameter sweep where running full retrieval eval per trial is too expensive and loss is a good-enough proxy for ranking.

0.4 Acceptance Criteria

  • InfoNCE init loss ≈ ln(B) on random embeddings (I10 sanity) within ±5%.
  • Loss strictly decreases on a learnable synthetic task over ≥ 200 steps.
  • All sampled embeddings satisfy ‖v‖₂ = 1 ± 1e-5 (I3).
  • Eval metrics match a hand-computed fixture exactly (small ranked list + qrels).
  • config-validator rejects 4 malformed configs (τ≤0, dim mismatch, bad pooling, missing field) with correct ConfigError.

0.5 Conformance Fixtures

  • conformance/configs/smoke.yaml — minimal run. conformance/data/toy_train/, toy_eval/ (synthetic). golden_metrics/p0_eval.json (hand-computed metrics). Malformed: configs/bad_temperature.yaml, bad_dim.yaml, bad_pooling.yaml, missing_field.yaml. fixtures/metric_handcalc.json (ranked+qrels→expected).

0.6 Pitfalls

  • Un-normalized embeddings into InfoNCE → loss couples magnitude + direction → unstable. Root: missing/misordered norm. Debug: embedding_norm_mean ≠ 1. Recover: normalize last (I3); compute loss on normalized.
  • Mean pooling ignores attention mask → pads pollute the embedding. Root: plain mean over Lq. Debug: embedding changes with padding length. Recover: mask-weighted mean (sum(masked)/sum(mask)).
  • Loss in fp16/bf16 by default → overflow / wrong gradients. Root: not forcing fp32. Debug: NaN at higher τ⁻¹. Recover: cast logits to fp32 before CE (I8).
  • Diagonal-label off-by-one after concatenating negatives → wrong positive target. Root: label index drift. Debug: init loss ≠ ln(B); accuracy at chance even when separable. Recover: assert labels point at the positive column (I10).
  • config_hash unstable (dict ordering, float repr) → manifest churn, replay mismatch. Root: non-normalized hashing. Debug: hash changes on logically-equal config. Recover: canonicalize (sorted keys, rounded floats) before hashing.

0.7 Performance Concerns

Smoke scale only — but establish patterns: batch tensors contiguous; pooling vectorized (no Python loop over rows); similarity matrix is one matmul q_emb @ d_emb.T; avoid per-example Python in the step. Keep the synthetic corpus in memory (no I/O bottleneck at this phase).

0.8 Edge Cases

B=1 (no negatives → InfoNCE degenerate; document + warn); all-pad sequence (mask sum 0 → guard divide-by-zero); single distinct positive across batch (all in-batch negatives are false → flagged later); empty eval qrels (metrics defined as 0/NaN-guarded); identical query==positive text (sanity: high similarity expected).

0.9 Failure Analysis

Malformed config → ConfigError pre-run (blast radius: that run). NaN loss on a bad synthetic seed → I8 guard aborts with the offending batch logged. No data path yet → failures are config/model-shape only. Recovery: fix config/seed, re-run; smoke is cheap.

0.10 Operational Notes

Structured logs per step (step, loss, grad_norm, lr, embedding_norm_mean). No metrics endpoint yet (Phase 10). RunManifest written at run start with config_hash+code_hash — first reproducibility artifact. seed_all logged so a run can be reproduced from logs alone.

  • Epoch coverage == n_examples, zero duplicates/skips across 3 epochs (I2).
  • Resume at step k reproduces the same subsequent (shard,row) order as an uninterrupted run (I2).

  • conformance/data/dup_fixture/ (planted exact+near dups). data/leakage_fixture/ (planted train/eval overlap). data/multilang/ (language filter). golden/p1_manifest.json (expected dedup/filter/leakage stats). replay_traces/sampler_order.json (expected (shard,row) sequence for a seed). Malformed: data/corrupt_shard.vshard (crc mismatch → DataError).

1.6 Pitfalls

  • Non-deterministic dedup (random MinHash seed) → different shards each run → replay breaks. Root: unseeded permutations. Debug: data_version changes on identical input. Recover: fix permutation seed (I4).
  • Leakage via near-duplicates (eval doc is a near-dup of a train doc) → inflated metrics. Root: exact-only disjointness check. Debug: suspiciously high Recall@1. Recover: dedup across the train/eval boundary too (I1).
  • Sampler not exactly-once under DDP (overlapping rank partitions) → duplicated examples. Root: bad partitioning. Debug: epoch_coverage > n or dup_examples > 0. Recover: disjoint rank shards (I2).
  • Resume cursor off by a batch → a few examples skipped/repeated on resume. Root: cursor saved after consume, restored before. Debug: post-resume order diff. Recover: checkpoint cursor at exact step boundary (I2/I6).
  • Shard offset-index corruption → wrong row decoded. Root: writer/reader offset mismatch. Debug: crc + schema assertion on read. Recover: rebuild shard; crc gate (DataError).

1.7 Performance Concerns

Ingestion is batch (one-time per data version); MinHash LSH bounded memory (banding). .vshard sequential decode is the streaming hot path — length-prefixed + offset index avoids parsing overhead; crc per shard not per row. Prefetch queue depth tuned so decode/tokenize hides behind GPU compute (I5). Avoid loading whole shards into RAM — stream rows.

1.8 Edge Cases

Empty corpus (manifest with 0 examples, train aborts with clear error); single shard; example larger than a shard threshold (split/cap); all examples deduped (empty train set); eval with no qrels (eval skipped); shard count < world size (some ranks idle — warn).

1.9 Failure Analysis

Corrupt shard → DataError::CrcMismatch on read; blast radius: that shard's rows; recovery: re-ingest. Leakage detected → DataError::LeakageDetected, run aborts pre-train (highest-value catch — prevents a wasted run reporting fake metrics). Disk full during ingest → partial shards discarded (atomic manifest write last); re-run.

1.10 Operational Notes

  • Validation: assert ids < vocab_size; mask matches non-pad positions.

  • Tokenization output bit-identical across runs for the same input (determinism, I4).
  • Padding/mask correctness: masked positions never affect pooled embedding (differential vs unpadded single example) within fp tolerance.
  • Truncation respects max_seq_len; no id ≥ vocab_size.
  • Tokenization throughput ≥ 200K examples/s aggregate (cached short texts) — loader not the bottleneck (I5).
  • Prefixing applied correctly per field (query vs doc) per fixture.

2.5 Conformance Fixtures

  • conformance/data/tokenize_cases/ (short, long-truncated, unicode, empty, prefix). golden/p2_tokenized.json (expected ids/mask for fixtures). configs/prefixed.yaml (E5-style prefixes). Edge: data/oversized_text.jsonl (truncation), data/empty_text.jsonl.

2.6 Pitfalls

  • Global-max padding → huge wasted compute on short batches. Root: padding to max_seq_len always. Debug: tokens/s low, padding ratio high. Recover: pad to batch-max length.
  • Mask/padding mismatch → pads counted in mean pool. Root: mask built from wrong lengths. Debug: embedding varies with pad count. Recover: mask == (ids != pad_id) AND within true length.
  • Tokenizer artifact drift (different tokenizer than data was built with) → silent id mismatch. Root: not verifying tokenizer_ref hash. Debug: vocab/ids inconsistent with manifest. Recover: assert tokenizer hash == manifest tokenizer_ref.
  • Prefix applied to wrong field (query prefix on doc) → asymmetric encoding bug. Root: collate field confusion. Debug: query/doc embeddings systematically off. Recover: prefix per field, fixture-tested.
  • Tokenization on the main thread → GIL-bound, GPU starves. Root: no worker parallelism. Debug: gpu_idle_pct high, loader CPU-bound. Recover: multi-worker loader + caching (ADR-002 Rust ext if needed).

2.7 Performance Concerns

Tokenize in loader workers (parallel), cache short texts (LRU), pad to batch-max. The ragged hard-neg tensor is the largest (B×K×Ld) — only materialize when K>0. Pinned-memory host buffers + non-blocking H2D copy overlap transfer with compute. This is the phase where ADR-002's optional Rust/PyO3 loader earns its place if Python tokenization can't hit target.

2.8 Edge Cases

Empty text (single special token + mask 1, or drop per policy); text far over max_seq_len (truncate, warn if frequent); all-OOV text (UNK ids); K varies per example in a batch (pad to batch-max K); query == doc (legal).

2.9 Failure Analysis

Tokenizer hash mismatch → DataError (abort: data and tokenizer must agree). Truncation losing the relevant span → silent metric loss (not a crash) — mitigated by recipe-appropriate max_seq_len + truncation strategy, surfaced by eval. Recovery: adjust max_seq_len/strategy, re-run.

2.10 Operational Notes

Metrics: tokens_per_sec, padding_ratio, truncation_rate, oov_rate, tokenize_cache_hit. Log max_seq_len, prefixes, tokenizer hash at run start. Loader-wait vs compute time tracked (I5) — the early-warning for a tokenization bottleneck.

3.1 Objectives

Complete the model: configurable shared vs separate query/doc towers, all three pooling strategies, projection head to embedding_dim, mandatory L2 normalization (I3), embedding-dim invariant (I15), and an optional cross-encoder teacher interface for later distillation. Forward path production-ready (AMP-safe, gradient-checkpointing-ready).

3.2 Detailed Implementation Steps

  • vetp/model/encoder.py: encoder adapter — wrap a transformer encoder; load from encoder_ref (random init OR provided checkpoint, ADR-011); expose hidden states + attention mask; gradient-checkpointing flag (memory vs compute).

  • vetp/model/projection.py: optional linear (+activation+LayerNorm) head hidden → embedding_dim; identity if proj_dim == hidden.
  • vetp/model/normalize.py: L2 normalize → [B, d] on unit sphere (I3); epsilon-guarded.
  • vetp/model/dual_encoder.py: shared_towers (default: one encoder for both) vs separate (two encoders, e.g. asymmetric query/doc). encode_query/encode_doc/forward(batch) → (q_emb, d_emb, hn_emb). Assert embedding_dim constant (I15).
  • vetp/model/teacher.py: cross-encoder teacher interface (score(query, doc) -> float) for Margin-MSE distillation (used in Phase 6, optional); frozen, no grad.

3.3 Deliverable

A configurable DualEncoder producing normalized embeddings under all pooling/tower options; gradient-checkpointing reduces activation memory; teacher interface available; forward path AMP-safe.

3.4 Acceptance Criteria

  • All embeddings L2-normalized (I3) across pooling/tower configs.
  • Mean pooling mask-correct (differential vs manual computation).
  • Shared vs separate towers both train (loss decreases) on the synthetic task.
  • Gradient checkpointing cuts peak activation memory ≥ 40% with identical outputs (within fp tolerance).
  • embedding_dim constant and equal to config across forward/eval/export probes (I15).

3.5 Conformance Fixtures

  • configs/{shared_mean.yaml,separate_cls.yaml,last_token.yaml,with_projection.yaml}. golden/p3_pooling.json (expected pooled outputs for fixed inputs/weights). Edge: configs/grad_ckpt.yaml. Teacher: fixtures/teacher_scores.json.

3.6 Pitfalls

  • CLS pooling on a model with no meaningful CLS (random-init or non-BERT) → weak embeddings. Root: pooling/encoder mismatch. Debug: poor Recall vs mean pooling. Recover: prefer mean pooling unless CLS is trained (Sentence-BERT lesson).
  • Projection head collapses dimensions → low effective rank. Root: bad init / too-small proj_dim. Debug: embedding rank ≪ d (Phase 10). Recover: sane init; proj_dim ≥ task needs.
  • Separate towers with shared optimizer LR → one tower dominates. Root: imbalanced grad scale. Debug: per-tower grad norm divergence. Recover: balanced init / per-tower LR if needed.
  • Normalization before pooling → wrong (normalizing token vectors, not the sentence). Root: layer order. Debug: embeddings not unit-norm at output. Recover: pool → project → normalize (I3 order).
  • Gradient checkpointing changes outputs → silent numerical drift. Root: nondeterministic recomputation / RNG in dropout. Debug: output diff with/without ckpt. Recover: deterministic dropout seeding (I4); recompute must match.

3.7 Performance Concerns

Encoder forward dominates FLOPs; gradient checkpointing trades ~30% recompute for large activation savings (enables bigger device batch → more in-batch negatives). Shared towers halve parameter memory + cache. Pooling/projection/norm are cheap. AMP autocast on the encoder; keep norm + loss in fp32. Batch-max padding (Phase 2) directly cuts encoder FLOPs.

3.8 Edge Cases

All-pad sequence (mask sum 0 → epsilon guard, embedding well-defined); single-token sequence; proj_dim == hidden (identity projection); separate towers with different max_seq_len; teacher unavailable (distillation disabled gracefully).

3.9 Failure Analysis

embedding_dim mismatch at build → ConfigError::EmbeddingDimMismatch (I15), pre-train. NaN from un-guarded normalization of a zero vector → guarded (epsilon); I8 catches residuals. Recovery: fix config; zero-vector guard. Wrong pooling → no crash, weak metrics → surfaced at eval, fixed by config.

3.10 Operational Notes

Log model summary at start (towers, pooling, embedding_dim, params, grad-ckpt on/off). Metrics: param_count, peak_activation_mem, embedding_norm_mean/std (I3 + early collapse signal). The pooling/tower choice is recorded in the manifest (affects arch_signature, I7).

Phase 4 — Contrastive Loss Suite, In-Batch Negatives, False-Negative Masking, Single-GPU Training Loop, AMP + Grad Accumulation

4.1 Objectives

Make single-GPU training real and strong: full loss suite (InfoNCE/NT-Xent, MNR, triplet/margin), in-batch negatives with false-negative masking (I11), AMP autocast + GradScaler (I8), gradient accumulation, LR warmup/decay, grad clip. This is the first configuration that trains a useful embedding model on one GPU.

4.2 Detailed Implementation Steps

  • vetp/loss/matrix.py: assemble SimilarityMatrix — columns = in-batch positives (others' positives act as negatives, DPR paper #3) ⊕ each example's own mined hard-negs (if any) ; labels = positive column (I10); mask_false_neg excludes columns whose doc-id ∈ this query's positive set (I11).
  • vetp/loss/infonce.py: temperature-scaled cross-entropy (InfoNCE, paper #2; NT-Xent temperature τ from SimCLR, paper #8; ADR-013), fp32, log-sum-exp stable (I8, P7); per-example weight applied.
  • vetp/loss/mnr.py: multiple-negatives-ranking (Sentence-BERT, paper #7; symmetric option: query→doc and doc→query). vetp/loss/triplet.py: margin-based triplet for the triplet recipe.
  • vetp/train/amp.py: autocast region around forward+loss; GradScaler.scale(loss).backward(), unscale_, clip, scaler.step, scaler.update; skip-step on Inf (I8).
  • vetp/train/trainer.py: gradient accumulation over accum_steps micro-batches (effective batch = device_batch × accum); LR schedule stepped per optimizer step; exactly-once consume (I2) preserved across accumulation.
  • vetp/train/optim.py: AdamW, linear warmup then linear/cosine decay; grad clip by global norm.

4.3 Deliverable

vetp train on a single GPU trains a real dual-encoder on a real (small) retrieval dataset with InfoNCE + in-batch + false-negative masking + AMP + accumulation; loss + grad-norm curves healthy; eval Recall@k rises.

4.4 Acceptance Criteria

  • InfoNCE init loss ≈ ln(num_columns) (I10); masking removes false negatives (verified on a planted-duplicate batch, I11).
  • AMP: no NaN/Inf loss over a full run; GradScaler skip-rate < 1% steady state (I8).
  • Gradient accumulation: effective-batch-N run ≈ true-batch-N run (loss trajectory within fp tolerance) on a fixture.
  • Eval Recall@10 on a small benchmark beats a BM25 baseline after training.
  • All three losses train (loss decreases) on their respective fixtures.

4.5 Conformance Fixtures

  • configs/{infonce_inbatch.yaml,mnr.yaml,triplet.yaml,amp.yaml,accum8.yaml}. data/small_retrieval/ (real-ish train+eval+qrels). golden_metrics/p4_recall.json (post-train Recall floor). fixtures/false_neg_batch.json (planted in-batch false negative → must be masked). replay_traces/accum_equivalence.json.

4.6 Pitfalls

  • In-batch false negatives (another example's positive is also relevant to this query) → model penalized for correct docs. Root: no masking. Debug: loss floor high, Recall stalls. Recover: mask_false_neg by doc-id/positive-set (I11).
  • GradScaler scale too high → persistent Inf → many skipped steps → no learning. Root: bad init scale / fp16 loss. Debug: high skip-rate, grad-norm spikes. Recover: fp32 loss (I8), default scaler growth schedule.
  • Accumulation without scaling loss → effective LR wrong (loss summed not averaged). Root: not dividing loss by accum. Debug: divergence vs true-batch. Recover: average micro-batch losses.
  • Temperature too low (τ→0) → razor-sharp softmax → unstable grads; too high → no contrast. Root: untuned τ. Debug: loss NaN (low τ) or flat (high τ). Recover: τ∈[0.01,0.1] typical; validate (I12).
  • Clipping after scaler.step (wrong order) → clip on scaled grads. Root: AMP step order. Debug: clip ineffective. Recover: unscale_ → clip → step → update.

4.7 Performance Concerns

Similarity matrix is q_emb @ d_emb.T ([B,B]) + hard-neg block — one big matmul (GPU-efficient). AMP halves encoder memory/compute (more negatives per GPU). Accumulation grows effective batch with no extra memory (more compute). Avoid materializing the full [B, num_cols] in fp32 if num_cols huge — but at single-GPU scale it's fine; the concern grows in Phase 7. Pin host buffers; overlap H2D with compute.

4.8 Edge Cases

B=1 (no in-batch negatives → loss undefined → require B≥2 or mined negs); all queries share one positive (all in-batch are false negs → masked → degenerate, warn); τ at validation boundary; accum_steps=1 (no accumulation); a micro-batch with K=0 hard-negs mixed with K>0 (ragged handling).

4.9 Failure Analysis

NaN loss (I8) → skip step; if persistent, abort FAILED(nan) with batch + scaler state dumped. Mask bug (false negatives not removed) → metric stall, caught by false_neg_batch fixture + eval. Recovery: deterministic re-run from last checkpoint; the offending batch is reproducible (I4).

4.10 Operational Notes

Metrics: loss, grad_norm, lr, temperature, scaler_scale, nan_loss_events, gradscaler_skips, false_negative_filtered, samples_per_sec. Loss + grad-norm + Recall curves are the operator's primary training-health view. Runbook: docs/runbooks/nan-loss.md (symptom → scaler/τ/lr → action).

Phase 6 — Hard-Negative Mining: ANN over Current Model + BM25, Negative Cache, Scheduled Refresh, False-Negative Filtering, Optional Distillation

6.1 Objectives

Build the data↔model feedback loop (the project's distinguishing subsystem): mine hard negatives by retrieving near-but-wrong documents using the current model's embeddings (ANN) ⊕ BM25 lexical negatives, cache them per example, refresh on a schedule (I11 false-negative filtering), and optionally denoise/distill via a cross-encoder teacher. This is the ANCE recipe.

6.2 Detailed Implementation Steps

  • vetp/sampler/miner.py: HardNegativeMiner.mine(model, corpus, queries) — orchestrates ANN + BM25 mining, false-negative filtering, optional teacher denoising.
  • vetp/sampler/ann.py: snapshot current encoder (eval, no grad) → batch-encode the doc corpus → build a transient FAISS index (HNSW/IVF, #255 lib) → retrieve top-(k+margin) per query.
  • vetp/sampler/bm25.py: static BM25 index over the corpus → lexical hard negatives (union with ANN negs); robust complementary signal early when embeddings are weak.
  • vetp/sampler/cache.py: NegativeCache{ex_id → [neg_ids]}, versioned; staleness_steps; persisted between refreshes; loader injects hard_negs by ex_id into batches.
  • vetp/sampler/refresh.py: scheduled refresh every refresh_every steps — pause training at a step boundary, mine, swap cache, bump version, reset staleness; runs off the training hot path (own failure containment).
  • False-negative filter (I11): drop any mined neg whose id ∈ the example's positive set / qrels.
  • Optional distillation (teacher.py): cross-encoder scores mined (query, neg) pairs → Margin-MSE / re-weight (RocketQA denoising); demote/drop negs the teacher rates as actually relevant.

6.3 Deliverable

Training mines hard negatives from the current model + BM25, refreshes the cache on schedule, filters false negatives, and (optionally) distills from a teacher; eval Recall@k improves measurably vs in-batch-only.

6.4 Acceptance Criteria

  • Mined negatives are harder than random (mean similarity to query > random negs) — verified.
  • No mined negative equals a true positive (I11) on a planted fixture.
  • Refresh reduces staleness to 0 and cadence respected (staleness_steps ≤ refresh_every, principle 11).
  • Hard-negative training beats in-batch-only on eval Recall@10 by a measurable margin on the benchmark.
  • Mining is off the hot path: training-step throughput unchanged between refreshes (only periodic dips during refresh).

6.5 Conformance Fixtures

  • configs/{ance_mining.yaml,bm25_negs.yaml,distill.yaml}. data/mining_corpus/ (corpus + queries + qrels). fixtures/false_neg_mining.json (positive planted in mined set → must be filtered). golden_metrics/p6_recall_improvement.json. fixtures/teacher_scores.json (distillation).

6.6 Pitfalls

  • Mined negatives include the true positive (false negative) → model penalized for the right answer. Root: no filtering. Debug: Recall drops after mining starts. Recover: filter by positive-set/qrels id (I11).
  • Stale negatives (cache from a model 50k steps old) → effectively easy → wasted compute. Root: refresh cadence too slow / refresh failed silently. Debug: staleness_steps high; loss flat. Recover: bound cadence; alert on staleness (principle 11).
  • Mining OOM / index build failure stalls training. Root: corpus too large for one GPU encode / index. Debug: MiningError::IndexBuildFailed. Recover: shard the encode across GPUs; contain mining failure (keep last cache, log, continue).
  • ANN recall too low (cheap index) → "hard" negs aren't actually near → weak signal. Root: under-tuned HNSW/IVF. Debug: mined-neg similarity not elevated. Recover: tune index params / exact for small corpora.
  • Over-hard negatives without denoising → many are actually relevant → noisy gradient. Root: top-1 mining, no teacher. Debug: training instability, Recall regression. Recover: sample from top-k with margin; teacher denoising (RocketQA).

6.7 Performance Concerns

Corpus encode (the expensive part) is sharded across GPUs in eval mode (no activations); index build is FAISS (fast). Mining runs every refresh_every steps — amortized cost small if cadence sane. NegativeCache lookup is O(1) by ex_id. Hard-neg tensors enlarge batches (B×K×Ld) → more encoder FLOPs per step (the cost of better negatives). Reuse the doc encode for both mining and (optionally) eval if versions align.

6.8 Edge Cases

Corpus too small for k negatives (use all non-positives); query with no qrels (skip false-neg filter, mine anyway); first refresh before any training (negs from random model — weak but valid; BM25 carries early signal); refresh exactly at checkpoint/eval boundary (order interludes deterministically); teacher unavailable (distillation off, mining proceeds).

6.9 Failure Analysis

Mining failure → contained: keep previous cache, log MiningError, continue training (staleness rises, alerts). Blast radius: negative quality, not correctness. False-negative leak → metric regression, caught by fixture + eval. Recovery: fix filter, re-mine. Index OOM → shard encode / smaller index; mining is restartable (idempotent given model snapshot).

6.10 Operational Notes

Metrics: mining_refresh_count, staleness_steps, mined_neg_mean_sim, false_negative_filtered, mining_duration_secs, index_recall, cache_version. Runbook: docs/runbooks/mining-stale.md (symptom: flat Recall + high staleness → check refresh loop → re-mine). Refresh events logged with model version + cache version (audit). This subsystem is the most operationally subtle — staleness is the alert that matters most.

Phase 7 — Distributed Data-Parallel Training: DDP, Embedding All-Gather (global negatives), Cross-Batch Memory, Gradient Cache, Deterministic Collectives

7.1 Objectives

Scale negatives and throughput across GPUs: DDP gradient all-reduce (#115); all-gather of embeddings so every query sees all ranks' documents as negatives (global negatives, I9 — correct gradient flow); cross-batch memory queue (MoCo/RocketQA); gradient cache (GradCache) for huge effective batch within memory; deterministic collective ordering for replay (I4).

7.2 Detailed Implementation Steps

  • vetp/dist/env.py: init process group (NCCL/Gloo), rank/world/device, deterministic NCCL ordering, seeded per-rank generators (offset by rank for data, shared for model init).
  • vetp/dist/ddp.py: wrap model in DDP; gradient all-reduce on backward; ensure model params identical across ranks at start (broadcast from rank 0).
  • vetp/dist/gather.py: all_gather_embeddings(emb, world, rank) → [B*world, d]; gradient flows only to the local rank's B rows (others detached) — the critical correctness detail (I9). Loss labels offset by rank*B (I10).
  • vetp/loss/xbm.py: CrossBatchMemory FIFO queue [M, d] of detached (optionally momentum-encoder) embeddings; concatenated as extra negatives; bounded size (principle 13).
  • vetp/loss/gradcache.py: two-pass GradCache — (1) no-grad forward all micro-batches → cache embeddings → compute loss + per-embedding grad; (2) re-forward with grad, apply cached grad. Decouples effective batch from activation memory (ADR-015).
  • Determinism: deterministic all-gather/all-reduce ordering; same global sample assignment across runs at fixed world size (I4).

7.3 Deliverable

Multi-GPU single-node DDP training with global in-batch negatives via all-gather, cross-batch memory, and gradient cache; near-linear scaling; correct distributed contrastive gradients (matches single-GPU semantics at equal effective batch); deterministic at fixed world size.

7.4 Acceptance Criteria

  • DDP scaling efficiency ≥ 0.85× linear to 8 GPUs (throughput).
  • All-gather gradient correctness (I9): single-GPU run at effective batch == 8-GPU run (loss trajectory within fp tolerance) — proves only local-slice grad flows.
  • All-gather overhead ≤ 5% step time at world=8 (embeddings small).
  • Cross-batch memory + gradcache increase effective negatives to target (≥ 4,096/query) within memory budget.
  • Deterministic: same (config,seed,world) → identical loss trajectory + sample assignment across runs (I4).

7.5 Conformance Fixtures

  • configs/{ddp_allgather.yaml,xbm.yaml,gradcache.yaml}. scaling/{ddp_1,2,4,8}.yaml. fixtures/gather_grad_equivalence.json (single-vs-multi-GPU grad). replay_traces/ddp_determinism.json. fixtures/effective_batch_count.json.

7.6 Pitfalls

  • All-gather without detaching other ranks' slices → gradient double-counted / wrong → silent training corruption. Root: gathering with grad on all rows. Debug: grads differ single vs multi GPU (I9 test fails). Recover: gradient flows only to local slice; rest detached + re-attached locally.
  • Label offset wrong after gather (not offset by rank) → positive target points at wrong column. Root: labels=0..B-1 instead of rankB+i. Debug: init loss ≠ ln(BW); accuracy at chance. Recover: offset labels by rank*B (I10).
  • Non-deterministic collective ordering → replay diverges across runs. Root: async/unordered NCCL ops. Debug: replay_loss_max_abs_diff > tol. Recover: deterministic ordering + deterministic algorithms (I4).
  • Cross-batch memory holding grad → memory leak / wrong grad. Root: enqueuing non-detached embeddings. Debug: memory grows; grad through queue. Recover: detach before enqueue (xbm negatives are detached).
  • GradCache embeddings recomputed differently in pass 2 (dropout RNG differs) → cached grad mismatched. Root: nondeterministic re-forward. Debug: loss inconsistent vs non-gradcache. Recover: deterministic RNG across both passes (I4).
  • DDP + gradient accumulation no_sync misuse → grads synced every micro-batch (slow) or never (wrong). Root: missing no_sync context on non-final micro-batches. Debug: throughput low or grads wrong. Recover: no_sync on all but the last accumulation micro-batch.

7.7 Performance Concerns

Embedding all-gather moves B×d×2 bytes per rank — tiny vs gradient all-reduce (full model) → cheap (≤5%). DDP gradient all-reduce overlaps with backward (bucketed). GradCache adds a no-grad forward pass (~+50% forward FLOPs) but unlocks huge effective batch (the contrastive win). NVLink/NCCL bandwidth is the scaling ceiling. Cross-batch memory is a bounded buffer (cheap). Mixed precision shrinks both compute and all-gather bytes.

7.8 Edge Cases

World=1 (all-gather is identity; gradcache still valid); uneven last batch across ranks (pad/drop consistently to keep gather shapes equal); a rank with K=0 hard-negs while others have K>0 (align); NCCL timeout (slow rank → detect, abort); world-size change between runs (sample assignment changes → not bit-comparable, documented constraint).

7.9 Failure Analysis

All-gather grad bug → silent wrong embeddings: caught only by the single-vs-multi-GPU equivalence test (I9) — hence it's a hard gate. Rank desync (one rank crashes) → NCCL hang → timeout → abort all ranks → resume from checkpoint. Blast radius: whole run (DDP is all-or-nothing). Forensics: per-rank logs, grad-norm divergence, collective timing.

7.10 Operational Notes

Metrics (per rank + aggregated): samples_per_sec, scaling_efficiency, allgather_secs, allreduce_secs, gathered_neg_count, xbm_size, effective_batch, gpu_util, nccl_timeouts. Log world/rank/device + collective backend at start. Launch via scripts/ddp-launch.sh (torchrun). The I9 equivalence test is the most important correctness check in the project — distributed contrastive grads are easy to get subtly wrong.

Phase 8 — Evaluation Harness: Retrieval Metrics (Recall@k, MRR, nDCG, MAP), Embedding Quality (alignment/uniformity/rank), Regression Gates

8.1 Objectives

Build the evaluation that gates releases (principle 10): encode a held-out corpus + queries, retrieve, compute Recall@k/MRR/nDCG/MAP against qrels, measure embedding quality (alignment/uniformity/rank for collapse), and enforce regression gates vs a baseline. Train/eval disjointness re-checked here (I1). Shares metric semantics with #331.

8.2 Detailed Implementation Steps

  • vetp/eval/encode.py: batch-encode eval corpus + queries with the (best) checkpoint, normalized (I3); cache embeddings.
  • vetp/eval/retrieve.py: exact (brute-force cosine, small corpora) or ANN (large; reuse #255 lib) top-k retrieval per query → ranked lists.
  • vetp/eval/metrics.py: recall_at_k, mrr, ndcg_at_k, map_score against qrels (TREC format) — definitions matched to #331 for cross-consistency.
  • vetp/eval/quality.py: alignment (E‖q−d⁺‖² over positives), uniformity (log E e^{−2‖x−y‖²}), embedding-matrix effective rank, per-dim std-dev — the collapse signals (Phase 10).
  • vetp/eval/gate.py: regression_gate(report, baseline, tol) — fail promotion if any tracked metric regresses beyond tolerance; pass/fail + reasons.
  • Leakage re-check (I1): assert eval corpus/query ids disjoint from train at eval time (defense in depth).
  • EvalReport persisted to the run dir; best-by-primary-metric checkpoint marked in RunManifest.

8.3 Deliverable

vetp eval --config ... --ckpt best produces an EvalReport (Recall@{1,10,100}, MRR, nDCG@10, MAP, alignment, uniformity, rank) and a gate verdict vs baseline; integrated into training (eval_every) to track the best checkpoint.

8.4 Acceptance Criteria

  • Metrics match a reference implementation (BEIR/#331) on a shared benchmark within fp tolerance.
  • Hand-computed fixture (small ranked+qrels) reproduces exact metric values.
  • Regression gate correctly fails a deliberately-worse model and passes an improved one.
  • Alignment ↓ + uniformity ↓ over training on a healthy run; flagged on a collapse fixture (Phase 10).
  • Eval leakage check (I1) catches a planted train/eval overlap.

8.5 Conformance Fixtures

  • data/eval_benchmark/ (corpus+queries+qrels). golden_metrics/p8_reference.json (reference metric values). fixtures/metric_handcalc.json (exact small case). fixtures/{worse_model.pt,better_model.pt} (gate). collapse_cases/collapsed_emb.json (quality flags). fixtures/eval_leakage.json (I1).

8.6 Pitfalls

  • Metric definition drift (Recall@k counting / nDCG gain/discount variant) → numbers don't match references. Root: ambiguous metric spec. Debug: diff vs BEIR. Recover: pin definitions to #331/TREC; fixture-test exact values.
  • Eval uses a different distance than training (dot vs cosine on un-normalized) → wrong rankings. Root: normalization/distance mismatch. Debug: eval Recall inconsistent with training loss. Recover: normalized + cosine consistently (I3).
  • Qrels graded relevance ignored in nDCG/MAP → metrics wrong for graded judgments. Root: binary treatment. Debug: nDCG off vs reference. Recover: honor graded relevance.
  • Leakage discovered only via suspiciously high metrics → fake state-of-the-art. Root: no eval-time disjointness check. Debug: Recall@1 near 1.0. Recover: I1 re-check at eval; re-split data.
  • Gate tolerance too loose/tight → ships regressions or blocks noise. Root: untuned tolerances. Debug: gate false pass/fail. Recover: per-metric tolerances calibrated to eval noise.

8.7 Performance Concerns

Encoding the eval corpus dominates eval cost — batch + AMP + reuse across checkpoints where possible. Exact retrieval is O(queries × corpus × d) — fine for small corpora, switch to ANN for large (reuse mining index). Metrics computation is cheap (rank-list processing). Eval runs every eval_every steps — cadence balances signal vs cost.

8.8 Edge Cases

Query with no relevant doc in qrels (excluded from metrics or counted as 0 per convention); ties in similarity (stable tie-break for determinism); empty corpus (eval skipped); k > corpus size (Recall@k capped); graded vs binary qrels (both supported); single-query eval (metrics defined).

8.9 Failure Analysis

Metric bug → wrong release decision (ships bad model / blocks good one): caught by reference + hand-calc fixtures (hard gate). Leakage → fake metrics: I1 re-check blocks. Collapse undetected → wasted training: quality metrics + collapse detector (Phase 10) surface it. Recovery: fix metric/leakage, re-eval; deterministic so reproducible.

8.10 Operational Notes

Metrics: recall_at_{1,10,100}, mrr, ndcg_at_10, map, alignment, uniformity, embedding_rank, embedding_std, gate_pass, eval_leakage. EvalReport is the release artifact. Regression gate verdict logged with baseline reference. Dashboards plot metrics vs step (the curve that actually matters, not loss). Best-checkpoint selection by primary metric (configurable, e.g. nDCG@10).

Phase 9 — Model Export (ONNX/TorchScript), Parity Verification, Batch Embedding Generation, Model Versioning

9.1 Objectives

Make the trained encoder consumable: export to ONNX (pinned opset) and TorchScript with parity verification vs eager (I14), batch-embed a target corpus producing normalized vectors + ids, and version the model so downstream consumers (#255 ANN, #328 cache) can reference it precisely. Export preserves the full training contract — pooling + normalization (principle 15, I3/I15).

9.2 Detailed Implementation Steps

  • vetp/export/onnx.py: trace/export the query and doc encoders (or shared) to ONNX with a pinned opset; export the full forward including pooling + L2 normalization (so consumers get normalized vectors directly). Dynamic axes for batch + sequence length.
  • vetp/export/torchscript.py: torch.jit.script/trace export as an alternative; same forward contract.
  • Parity (I14): run eager vs ONNX vs TorchScript on a probe set; assert max abs diff < tol (ExportError::ParityFailed otherwise). Verify normalization holds post-export (I3) and dim == config (I15).
  • vetp/export/embed.py: batch-embed a corpus with the exported (or eager) model → vectors [N, d] + ids, written to parquet/arrow (ADR-021).
  • Model versioning: model_version = hash of (best checkpoint + config + data_version) recorded in RunManifest and carried into export artifacts (I13).

9.3 Deliverable

vetp export --ckpt best --format onnx produces a parity-verified ONNX encoder (+ TorchScript), and vetp embed --corpus ... produces normalized vectors + ids; all artifacts carry a model_version.

9.4 Acceptance Criteria

  • ONNX + TorchScript outputs match eager within tolerance on a probe set (I14).
  • Exported embeddings are L2-normalized (I3) and embedding_dim == config (I15).
  • Batch embedding of a corpus reproduces eval-time embeddings (same vectors) within tolerance.
  • Export round-trips: re-import the exported model, re-embed, identical vectors.
  • model_version deterministic and recorded in all artifacts (I13).

9.5 Conformance Fixtures

  • configs/export_onnx.yaml, export_torchscript.yaml. fixtures/export_probes.json (inputs → expected eager outputs). golden/p9_parity.json (parity diffs within tol). Edge: fixtures/unsupported_op.json (opset-unsupported → ExportError).

9.6 Pitfalls

  • Export omits normalization (exports up to pooling only) → consumer gets un-normalized vectors → wrong neighbors. Root: partial forward exported. Debug: exported ‖v‖₂ ≠ 1. Recover: export full forward incl. norm (principle 15, I3).
  • Opset mismatch → an op (e.g., a pooling/norm variant) unsupported → export fails or differs. Root: unpinned/low opset. Debug: ExportError::OpsetUnsupported or parity diff. Recover: pin a sufficient opset; replace unsupported ops.
  • Dynamic axes wrong → exported model fixed to one batch/seq length → breaks on real input. Root: static trace. Debug: shape error at inference. Recover: declare dynamic batch + sequence axes.
  • Training-serving skew (different tokenizer/prefix at serve time) → embeddings incompatible. Root: contract not documented. Debug: downstream Recall regression. Recover: handoff manifest states tokenizer + prefix + normalization (principle 15).
  • fp16 export parity drift → exported fp16 diverges from fp32 eager beyond tol. Root: precision mismatch. Debug: parity diff. Recover: export fp32 (or accept a documented fp16 tolerance).

9.7 Performance Concerns

Export is one-time per model version. Batch embedding of a large corpus is the heavy step — batch + AMP + multi-GPU shard. ONNX/TorchScript may run faster than eager at serve time (graph fusion) — a downstream win, not a training concern. Vector storage (parquet) sized N×d×4 bytes (fp32) — note fp16 storage option for the index.

9.8 Edge Cases

Shared vs separate towers (export one or both); proj_dim == hidden (identity projection exports cleanly); empty corpus (no vectors); very long sequences at export (dynamic axis upper bound); model that uses an op with no ONNX equivalent (fallback to TorchScript).

9.9 Failure Analysis

Parity failure (I14) → block export (ships a model that serves differently than it trained). Skew (undocumented contract) → downstream Recall regression, caught by #255/#328 integration tests. Recovery: re-export with full forward + correct opset; document contract. Blast radius: every downstream consumer of this model version.

9.10 Operational Notes

Metrics: export_parity_max_diff, export_format, opset_version, embedded_vectors, embed_secs, model_version. The exported encoder + model_version are the deliverable to #255/#328. Parity report archived. Runbook note: a downstream Recall regression → first check export parity + handoff contract (skew is the usual culprit).

Phase 10 — Observability: Loss/Grad/Throughput Curves, Embedding-Collapse Detection, Mining Staleness, Dashboards, Alerting

10.1 Objectives

Make the run observable (principle 12): emit training curves (loss, grad norm, lr, throughput), embedding-collapse detection (alignment/uniformity/rank/std), mining staleness, GPU/loader utilization; export to Prometheus + scalar logs; define dashboards + alert thresholds. Collapse + staleness are the two failure modes that silently waste GPU-weeks — catch them early.

10.2 Detailed Implementation Steps

  • vetp/obs/metrics.py: Prometheus exporter + TensorBoard/CSV scalars; per-step counters/gauges (cheap, on the hot path).
  • vetp/obs/collapse.py: periodic collapse detector — alignment, uniformity (Wang & Isola), embedding-matrix effective rank, per-dim std-dev, mean pairwise similarity; raise collapse_warning / collapse_alarm per thresholds (§8.8 table).
  • vetp/obs/logging.py: structured (JSON) logs; every reopt/refresh/checkpoint/eval event logged with context (model + data + cache versions).
  • Throughput instrumentation: samples_per_sec, tokens_per_sec, gpu_util, loader_queue_depth, gpu_idle_pct (I5 backpressure health).
  • Mining staleness gauge (staleness_steps) + refresh events (principle 11).
  • Dashboards (docs/performance/): training curves, collapse panel, throughput/util, mining staleness, eval-metric-vs-step (the gate curve).
  • Alerting: collapse alarm, staleness over budget, NaN-loss events, GPU starvation, gate failure.

10.3 Deliverable

A live metrics endpoint + dashboards showing training health, collapse signals, throughput, and mining staleness; alerts fire on collapse / staleness / NaN / starvation; all events structured-logged with versions.

10.4 Acceptance Criteria

  • Collapse detector flags a synthetic collapsing run (std→0, rank≪d, uniformity↑) before eval would.
  • Healthy run shows alignment↓ + uniformity↓ + stable rank — no false collapse alarm.
  • Throughput + GPU-util metrics match measured reality (cross-check vs profiler).
  • Mining staleness gauge tracks refresh cadence; alert fires when staleness > budget.
  • All metrics exported + scrapeable; logs parse as structured JSON.

10.5 Conformance Fixtures

  • collapse_cases/{dimensional_collapse.json,full_collapse.json,healthy.json} (detector behavior). fixtures/throughput_crosscheck.json. configs/obs_full.yaml. fixtures/staleness_alert.json.

10.6 Pitfalls

  • Collapse detected too late (only at eval) → GPU-weeks wasted. Root: no online collapse signal. Debug: Recall flat, embeddings degenerate at eval. Recover: online alignment/uniformity/std/rank (this phase).
  • False collapse alarm (alignment naturally drops early) → spurious aborts. Root: bad thresholds / single-signal. Debug: alarm on healthy run. Recover: multi-signal (std AND rank AND uniformity), calibrated thresholds.
  • Metric overhead on hot path → throughput hit. Root: expensive per-step metric (e.g., full rank every step). Debug: throughput drop with metrics on. Recover: cheap per-step scalars; expensive metrics (rank) on a cadence.
  • GPU util misleading (high util, low useful work due to padding) → false sense of efficiency. Root: util ≠ throughput. Debug: util high but samples_per_sec low. Recover: track samples/s + padding ratio, not just util.
  • Staleness gauge not updated on failed refresh → silent staleness. Root: gauge updated only on success. Debug: training flat, gauge stuck. Recover: increment staleness every step, reset only on successful refresh (principle 11).

10.7 Performance Concerns

Per-step metrics are scalar (negligible). Collapse metrics (rank via SVD, uniformity over pairs) are O(sample²·d) — compute on a small sampled subset on a cadence, not every step. Prometheus scraping is pull (no hot-path cost). Logging is async/buffered. The observability budget is < 1% of step time.

10.8 Edge Cases

Early training (alignment/uniformity noisy → warm-up window before alarms); single-GPU (no per-rank aggregation); eval-only run (no training curves); collapse on one tower only (per-tower std); refresh during a metric window (consistent snapshot).

10.9 Failure Analysis

Missed collapse → wasted run: multi-signal detector + alarm mitigates. False alarm → unnecessary abort: calibrated multi-signal thresholds. Metric pipeline failure → blind operation: metrics export health-checked; logs are the fallback. Recovery: collapse alarm → runbook (lower LR / raise negatives / check positives), then resume or restart with fixes.

10.10 Operational Notes

Metrics catalogue (full): training (loss,grad_norm,lr,temperature), collapse (alignment,uniformity,embedding_rank,embedding_std,mean_pairwise_sim), throughput (samples_per_sec,tokens_per_sec,gpu_util,loader_queue_depth,gpu_idle_pct), mining (staleness_steps,mining_refresh_count,mined_neg_mean_sim), eval (recall_at_k,mrr,ndcg,map,gate_pass), checkpoint (ckpt_write_ok,ckpt_bytes). Runbooks: collapse.md, mining-stale.md, nan-loss.md. Dashboards in docs/performance/. This phase turns "the loss looks fine but Recall is flat" from a week-late discovery into a same-hour alert.

Phase 11 — Deterministic Replay, Conformance Suite, ANN Index Handoff, Soak, Reproducibility Gate, Release Engineering

11.1 Objectives

Lock correctness + determinism + handoff: deterministic replay harness (I4 — re-run a captured config+data+seed, assert identical loss trajectory + sample order), full conformance suite (data, training, eval, export, collapse), the ANN index handoff (#255) + semantic-cache feed (#328), soak (long-run stability, no leak), and the reproducibility + release gate.

11.2 Detailed Implementation Steps

  • vetp/obs/replay.py + capture: capture (config_hash, data_version, seed, world_size) + the loss trajectory + sample-order trace; vetp replay <trace> re-runs and asserts identical loss trajectory (fp tol) + identical (shard,row) order (I4/I2). This is the determinism gate.
  • Conformance runner: conformance/ buckets — data (dedup/leakage/sampler), training (loss/AMP/accum/DDP-equivalence), eval (metrics vs reference), export (parity), collapse (detector), replay (determinism).
  • vetp/export/handoff.py: HandoffManifest{model_version, embedding_dim, normalization=l2, distance, vectors_path, ids_path, n_vectors, data_version} → drive an ANN index build (#255) and emit the contract the Semantic Caching Engine (#328) consumes (dim + normalization + distance must match, I3/I15).
  • Soak: multi-hour training run — assert no host/GPU memory leak, no FD leak, mining staleness bounded, checkpoints atomic, replay-after-soak holds.
  • Differential/regression: eval metrics vs golden baselines gate releases; export parity gate; replay gate.
  • Release: release.yml (tag → build → SBOM → sign → publish); CHANGELOG; version stamping (vetp + config + checkpoint + handoff schema versions).

11.3 Deliverable

make conformance + make replay + make soak (nightly) + handoff to a live ANN index all green; a VETP-trained model's vectors are indexed by #255 and queried correctly; determinism proven across the suite; release pipeline produces a signed, SBOM'd package.

11.4 Acceptance Criteria

  • Replay: identical loss trajectory (fp tol) + identical sample order across runs for every captured trace (I4/I2) — 100%.
  • Conformance: all buckets green (data integrity, training correctness, eval-vs-reference, export parity, collapse detection).
  • Handoff: #255 index built from VETP vectors returns the same top-k as eval-time exact retrieval (within ANN recall); #328 consumes the contract correctly (dim/normalization/distance match, I15).
  • Soak: multi-hour run — zero memory/FD leak, staleness within budget, atomic checkpoints, replay holds post-soak.
  • Performance gate: throughput + scaling within target; no > 10% regression vs committed baseline.

11.5 Conformance Fixtures

  • replay_traces/*.json (per-config determinism traces). conformance/configs/* + data/* + golden_metrics/* + collapse_cases/*. fixtures/handoff_roundtrip.json (eval top-k vs #255 ANN top-k). fixtures/soak_manifest.json. fixtures/handoff_contract.json (dim/norm/distance for #328).

11.6 Pitfalls

  • Replay diverges (hidden nondeterminism: unseeded op, async collective, dataloader worker RNG, non-deterministic kernel). Root: impure run input. Debug: replay_loss_max_abs_diff > tol; bisect inputs. Recover: seed all generators; deterministic algorithms + collectives; fixed worker seeding (I4).
  • Handoff dim/normalization mismatch → #255 index incompatible / #328 wrong neighbors. Root: contract not enforced. Debug: dim/norm assertion fails; downstream Recall wrong. Recover: HandoffManifest states + asserts dim/normalization/distance (I3/I15).
  • Soak memory leak (cache/queue/embedding accumulation) → OOM after hours. Root: unbounded buffer (xbm/cache/metrics). Debug: RSS/GPU mem grows monotonically. Recover: bound all buffers (principle 13); leak test in soak.
  • Bench flakiness (shared GPU host) → false perf regressions. Root: noisy host. Debug: variance. Recover: pinned/isolated GPU, relative thresholds, multiple runs.
  • Replay across world sizes expected to match (it can't — sample assignment differs). Root: misunderstanding determinism scope. Debug: cross-world diff. Recover: determinism is per-fixed-world-size (documented constraint, I4).

11.7 Performance Concerns

Replay re-runs training → as expensive as the original (run on small fixtures for CI; full-scale nightly). Conformance data is tiny (fast CI); full benchmarks nightly. Handoff embedding generation is the heavy step (multi-GPU). Soak is long but low-intensity (stability, not throughput). Determinism (deterministic algorithms) costs some throughput — measured + accepted (correctness over performance, principle 1).

11.8 Edge Cases

A run with no mining (replay simpler); a run that hit a NaN (replay reproduces the NaN deterministically → debuggable); empty handoff corpus; #255 index params differ from mining index (re-tune); soak interrupted (resume + continue soak); replay of a multi-GPU run (fixed world size).

11.9 Failure Analysis

Replay divergence → highest-severity reproducibility bug → blocks release; bisect nondeterminism source (I4). Handoff mismatch → downstream breakage → blocked by contract assertions (I15). Soak leak → would OOM production → blocked by leak test. Conformance/eval regression → block release. Containment: CI gates everything; nothing ships without green replay + conformance + handoff + soak.

Compatibility & Versioning

  • RunConfig schema: SemVer (schema_version). Additive optional fields → minor; required-field add / semantics change / removal → major. Validator rejects unknown major.
  • Checkpoint format: SemVer; safetensors weights + JSON sidecar; arch_signature gates resume (I7). Cross-major resume unsupported (documented). Optimizer-state format changes are major.
  • .vshard / DataManifest: versioned; immutable + content-addressed (data_version). Format change → new version; old shards re-ingested. No in-place mutation.
  • HandoffManifest: SemVer; states embedding_dim + normalization + distance — the contract with #255/#328 (I3/I15). Dim/normalization change → new model_version, not silent.
  • Public API (vetp.model/vetp.loss/vetp.eval): stable within a major; deprecation = one minor of warning before removal.
  • Exported model (ONNX/TorchScript): opset pinned per export; parity-guaranteed vs the eager model of that model_version (I14).
  • Metric definitions (vetp.eval): pinned to #331/TREC semantics; a definition change is a major (it moves the numbers) + CHANGELOG.
  • Semantic versioning policy: package, config, checkpoint, handoff share independent SemVer lines; pre-1.0 minors may break (documented). Behavioral changes (new default loss/mining) ship default-off behind flags first, CHANGELOG-noted.

Scalability Analysis

  • Bottlenecks: encoder forward/backward (FLOPs — mitigated by AMP + activation checkpointing); loader/tokenization (GIL — mitigated by multi-worker + caching + Rust ext); mining corpus encode (sharded across GPUs); all-gather is cheap (small embeddings).
  • Scaling ceilings: single-node GPU count (DDP scales to NVLink/NCCL bandwidth); GPU memory (gradcache + activation ckpt extend effective batch); host RAM (bounded prefetch); disk (shards + checkpoints + mining index).
  • Horizontal scaling: multi-node DDP is the next seam (deferred, #115); the vetp.dist collective layer + sharded sampler already model it. ZeRO sharding deferred (#250) for > 1B params.
  • Vertical scaling: AMP + activation checkpointing + gradient cache push effective batch (negatives) up; bigger GPU → bigger device batch → more in-batch negatives.
  • Negative scaling: effective negatives = in-batch (B) × world (W) via all-gather + xbm queue (M) + mined (K) — grows with GPUs and queue size (the contrastive win); the all-gather cost stays small (embeddings tiny).
  • Sharding/partitioning: data sharded across ranks (disjoint, exactly-once, I2); mining corpus encode sharded; vectors sharded for handoff.
  • Coordination overhead: DDP all-reduce overlaps backward (bucketed); embedding all-gather ≤ 5% step; mining is periodic + off hot path.
  • Replication pressure: xbm queue + mined-neg tensors bounded (principle 13); broadcast of model params only at start.
  • Storage growth: shards (per data version), checkpoints (last-N + best, GC'd), mining index (transient), exported vectors (per model version) — all bounded/retentioned.
  • Metadata scaling: RunManifest/DataManifest/HandoffManifest are O(1)/O(shards); event log append-only, bounded per run.

Mental Models & First Principles

The compressed intuitions an expert holds. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — Negatives are the gradient; positives only set the target. A contrastive step's signal comes almost entirely from how many and how hard the negatives are; the positive just names the column the softmax should peak at. Predicts: doubling effective negatives improves Recall far more than tweaking the positive. Without it: you over-engineer positive construction and starve the loss with 63 in-batch negatives, then wonder why loss drops but Recall stalls. Applied: §3 (loss box), P5/P6, Phase 4, Phase 7, Capacity Model #4.
  • MM2 — Embeddings live on a sphere; temperature, not magnitude, sets sharpness. After L2-normalization every vector has norm 1, so dot product is cosine and only τ controls how peaked the softmax is. Predicts: un-normalized vectors make the loss couple direction and magnitude → unstable; lowering τ sharpens contrast until grads explode. Without it: you build an index on un-normalized vectors and get wrong neighbors (training-serving skew). Applied: I3, P3, P7, Phase 3, Phase 9, MM-driven §8.5.
  • MM3 — A training run is a pure function of (config, data_version, seed, world); anything else is a bug. Determinism means every byte of output is reproducible from those four inputs. Predicts: if a resumed or replayed run diverges, an impure input leaked in (CUDA RNG, async collective, unseeded worker). Without it: regressions are undebuggable — you cannot bisect what you cannot reproduce. Applied: I4, P1, Phase 5, Phase 11 (replay gate), MM-driven Hard Questions HQ7/HQ13.
  • MM4 — Effective batch is a dial independent of GPU RAM. device_batch × accumulation × world × xbm + mined decouples the negative pool from the memory that holds activations. Predicts: you can hit 16k+ effective batch on a 24 GiB card via accumulation/gather/gradcache without a bigger GPU. Without it: you buy hardware to solve a problem that is a software decoupling (GradCache's two-pass trick). Applied: ADR-015, P6, Phase 7, Capacity Model #3/#4.
  • MM5 — The all-gather is free; the gradient detach is everything. Embeddings are tiny (B×d×2 bytes), so gathering them across ranks costs ≤5% of step time; the entire correctness risk is whether gradient flows only through the local rank's slice. Predicts: the cheap operation (gather) is safe; the subtle operation (detach boundary) is where silent corruption hides. Without it: you double-count or zero gradients and only the single-vs-multi-GPU equivalence test catches it. Applied: I9, Phase 7, §8.6, Hard Question HQ4.
  • MM6 — A hard negative mined from a stale model is just an easy negative wearing a costume. Mining's value is that the negatives are hard for the current model; an old cache retrieves negatives the model already separates. Predicts: Recall plateaus while loss looks fine when staleness ≫ refresh_every. Without it: you burn GPU-weeks training on negatives that carry no signal, with no alarm. Applied: P11, Phase 6, Phase 10 (staleness gauge), Failure Modes (stale negatives).
  • MM7 — Loss is a proxy; the metric you ship on is retrieval. Training loss can improve while Recall/nDCG regress (collapse, leakage, easy negatives). Predicts: gating releases on loss ships bad models; gating on held-out retrieval catches them. Without it: you promote a checkpoint whose loss curve looked great and whose neighbors are garbage. Applied: P10, Phase 8 (regression gate), Phase 11.
  • MM8 — Collapse is a rank/variance phenomenon you can see before eval. Degenerate embeddings show as per-dim std→0, effective rank ≪ d, rising uniformity — all measurable online, cheaply, on a sample. Predicts: a same-hour alarm instead of a week-late eval discovery. Without it: you find collapse only when retrieval craters, after the compute is spent. Applied: §8.8, P12, Phase 10, paper #6 (Wang & Isola).
  • MM9 — Exactly-once consumption is what makes resume == uninterrupted. If the sampler's cursor is the single source of "what's next," checkpointing it makes a killed-and-resumed run identical to one that never stopped. Predicts: a cursor saved at the wrong boundary skips/repeats examples and diverges on resume. Without it: resume silently biases training and breaks the determinism gate. Applied: I2, I6, P2, Phase 1, Phase 5.
  • MM10 — The handoff contract is the API; vectors without it are uninterpretable. A vector array is meaningless to a downstream index unless dim, normalization, and distance are stated and enforced. Predicts: an undocumented contract surfaces as a downstream Recall regression, not a crash. Without it: #255/#328 interpret your vectors under the wrong distance and return wrong neighbors. Applied: I15, I3, P15, Phase 9, Phase 11 (HandoffManifest).

  • DPR (Karpukhin et al. 2020) — the canonical BERT dual-encoder with in-batch negatives; the decision it made differently is simplicity — one-shot BM25 hard negatives and no refresh loop. VETP generalizes it: the ANCE-style refreshed mining loop (Phase 6), cross-device all-gather (Phase 7), and cross-batch memory are exactly the negative-engineering DPR's base recipe leaves on the table.

VETP borrows its determinism-and-resume discipline for .vshard (Phase 1) but defines a simpler, mining-join-friendly format rather than adopting MDS's general one (ADR-008).

Back-of-Envelope Capacity Model

The numbers an expert computes before designing, each derived step-by-step from the System Constraints table (§4) and the Domain Deep Dive setup (110M-param encoder, d=768, device batch B=64, world W=8, 24 GiB GPU, 1M-doc corpus). Formulas shown; no asserted-only numbers.

  • #1 Embedding-table / model RAM (fp32 weights). params × 4 bytes = 110e6 × 4 = 440 MB weights. With AdamW (2 moments) + fp32 master: 110e6 × 4 × (1 master + 2 moments + 1 grad) ≈ 110e6 × 16 = 1.76 GB optimizer+master+grad. Source: §4 "110M encoder", ADR-018.
  • #2 Checkpoint bytes. weights(safetensors, fp32) + optimizer state = 440 MB + 2×440 MB (Adam m,v) ≈ 1.32 GB per checkpoint; with last-N=3 + best retention ⇒ ~5.3 GB disk/run. Source: §4 "checkpoint write ≤30 s", P13 retention. Confirms the ≤30 s write target is plausible at ~1.3 GB over NVMe (~2–3 GB/s) ≈ 0.5–0.7 s raw + fsync.
  • #3 Effective batch reachable on 24 GiB. device_batch × accum × world = 64 × 32 × 8 = 16,384 — meets the §4 "effective batch ≥ 16,384" target without exceeding the 24 GiB ceiling because accumulation and gather add no activation memory. Source: §4 batch rows, ADR-015, MM4.
  • #4 Effective negatives per query. in-batch(B·W − 1) + xbm(M) + mined(K) = (64×8 − 1) + 8192 + 4 = 511 + 8192 + 4 = 8,707 ≈ §4 "≥ 4,096" target, doubled. Source: §4 "effective negatives ≥ 4,096", Domain Deep Dive setup, P5.
  • #5 All-gather bytes/step (world=8). per rank sends B×d×bytes(fp16) = 64×768×2 = 98,304 B ≈ 96 KB; ring all-gather moves ≈ data×2(W−1)/W = 96 KB × 1.75 ≈ 168 KB/rank/step — negligible vs gradient all-reduce. Source: §4 "all-gather ≤ 5% step", MM5.
  • #6 Gradient all-reduce bytes/step. params × 4 × 2(W−1)/W = 110e6 × 4 × 2×7/8 = 440 MB × 1.75 ≈ 770 MB/rank/step moved over NCCL — ~4,600× the all-gather, confirming the all-gather is the cheap one (MM5). Source: §4 DDP scaling row, standard ring all-reduce volume.
  • #7 Single-GPU epoch time (10⁷ examples). samples / (throughput) = 1e7 / 2000 ex/s = 5,000 s ≈ 1.39 h/epoch single GPU; at 0.85× linear scaling on 8 GPUs ⇒ 1.39 h / (8×0.85) ≈ 0.20 h ≈ 12 min/epoch. Source: §4 "≥ 2,000 ex/s", "≥ 0.85× linear to 8".
  • #8 Mining corpus encode (1M docs, 8 GPU). docs / (per-GPU eval throughput × W). Eval-mode encode (no backward) ≈ 3× train throughput ⇒ ~6,000 ex/s/GPU × 8 = 48,000 ex/s ⇒ 1e6 / 48,000 ≈ 21 s encode + FAISS HNSW build (~minutes) ⇒ within the §4 "≤ 10 min" refresh budget. Source: §4 "refresh ≤ 10 min for 1M docs (8 GPU)".

If a refresh ≈ 10 min and steps run at ~31 steps/s (2000 ex/s ÷ 64), 5,000 steps ≈ 161 s between refreshes ⇒ refresh dominates unless mining overlaps; hence mining runs off the hot path (P11). With overlap, step throughput between refreshes is unchanged. Source: §4 staleness budget, P11.

Alternative Architectures (Roads Not Taken)

Three fundamentally different architectures for the same goal (train retrieval embeddings at scale). Each: sketch, the regime where it wins, the real system that embodies it, why this blueprint rejected it.

ALT-A — Parameter-server asynchronous SGD (instead of synchronous data-parallel DDP).

        ┌───────────────┐   push grads / pull weights   ┌──────────┐
worker0─┤               ├◄──────────────────────────────┤  Param   │
worker1─┤  async, stale ├──────────────────────────────►│  Server  │
worker2─┤  no barrier   │   (no all-reduce, no barrier)  │ (shards) │
        └───────────────┘                                └──────────┘
  • Regime where it wins: thousands of cheap/unreliable CPU workers, stragglers common, model small enough to shard on a PS — throughput matters more than reproducibility. Classic for word2vec-scale and early large-scale ML.
  • Real system: DistBelief / parameter-server (Dean et al. 2012; Li et al. 2014); Hogwild! (Recht et al. 2011) is the lock-free shared-memory cousin.
  • Why rejected: asynchrony makes runs non-deterministic (stale gradients depend on timing) — fatal to VETP's replay gate (I4, P1); and contrastive learning's whole-batch coupling (every query needs many consistent negatives) fights asynchronous, stale updates. Synchronous DDP + all-gather (Phase 7) gives consistent global negatives and bit-reproducibility.

ALT-B — Full in-memory single-node training (no sharded streaming format).

   ┌──────────────────────────────────────────┐
   │  load ENTIRE tokenized corpus into RAM     │
   │  (one big tensor / arrays) → index by idx  │
   │  shuffle indices → slice batches → GPU      │
   └──────────────────────────────────────────┘
  • Regime where it wins: corpus fits comfortably in host RAM (≤ ~10⁷ short examples), single node, no resume-across-machines need — simplest possible loader, zero decode/format overhead, trivially deterministic shuffle.
  • Real system: the default PyTorch TensorDataset + DataLoader(shuffle=True) pattern used in most research code and SimCLR/SimCSE reference training.
  • Why rejected: VETP targets 10⁶–10⁸ examples (§4) that exceed host RAM; it needs exactly-once resumable streaming (I2/Phase 1), content-addressed immutable data versions (I13), and a mining join by ex_id — none of which an in-RAM array gives. The .vshard format (ADR-008) buys streaming + crc + immutability + random-access mining at the cost of a decode path.

ALT-C — Streaming / online continual embedding update (instead of batch jobs over a frozen snapshot).

  new docs ──► incremental encode ──► update embeddings in place
       ▲                                   │
       └──────── drift monitor ◄───────────┘  (no epoch, no frozen data_version)
  • Regime where it wins: a never-ending stream where the corpus and query distribution drift continuously and the index must stay fresh (news, social, fraud) — you cannot afford to retrain from a frozen snapshot.
  • Real system: online/streaming recommendation and embedding-refresh pipelines (e.g. NVIDIA Merlin's incremental training patterns; production feature-store-driven continual training).
  • Why rejected: VETP is explicitly a batch job over a frozen data snapshot (§1 non-goals, PhaseDeferred("§1 non-goal")) so that runs are reproducible (data_version pins the corpus, I13/I4). Online update sacrifices the frozen-snapshot reproducibility that the replay gate (Phase 11) and audit story (I13) depend on; continual training is a separate system whose drift/catastrophic-forgetting problems are out of scope here.

ALT-D — Late-interaction multi-vector retrieval (ColBERT-style) instead of single-vector bi-encoder.

query tokens [Lq,d] ──┐                    doc tokens [Ld,d] (one vector PER token, kept)
                       ▼                              │
              MaxSim(q_tok_i, all d_tok) summed over i ◄───── no single pooled vector
                       │
              score = Σ_i max_j (q_i · d_j)   (late interaction, not one dot product)
  • Regime where it wins: accuracy-critical re-ranking over a modest candidate set (hundreds–thousands of docs), where the extra per-token storage and MaxSim compute are affordable and the accuracy gain over single-vector cosine is worth it — token-level interaction captures phrase-level relevance a single pooled vector discards.
  • Real system: ColBERT (Khattab & Zaharia, SIGIR 2020; paper #16); ColBERTv2 and PLAID extend it with compression + faster MaxSim.
  • Why rejected: VETP's contract is a single L2-normalized EmbeddingTensor [B,d] per item (I3/I15), handed off as flat vectors to a standard ANN index (#255, HNSW/IVF/PQ) via HandoffManifest — the entire export/handoff/index-compatibility story (Phase 9/Phase 11) assumes one vector per item. Late interaction needs per-token vector storage (≈Ld× more bytes, Capacity Model #12 scales linearly), a MaxSim-aware index/re-ranker #255 does not build, and a different training loss (no clean InfoNCE-over-one-similarity-matrix, §8.5). It would change the ADR-017 choice (plain ANN → a late-interaction-aware index) and the export contract (ADR-021) system-wide — a different project, not a parameter tweak to this one.

Glossary

Term Definition
Embedding Dense vector representation of text on the unit hypersphere (L2-normalized).
Dual-encoder / Bi-encoder Two-tower model: separate (or shared) query and document encoders producing comparable embeddings.
Cross-encoder Single model scoring a (query, doc) pair jointly; accurate but not indexable; used as a distillation teacher.
Contrastive learning Training to pull positives together and push negatives apart in embedding space.
InfoNCE / NT-Xent Temperature-scaled cross-entropy over one positive vs many negatives (the workhorse loss).
Triplet / margin loss Loss enforcing positive closer than negative by a margin.
MNR (multiple-negatives-ranking) In-batch contrastive loss using other examples' positives as negatives (Sentence-BERT).
Temperature (τ) Scalar dividing similarities; controls softmax sharpness (τ>0, I12).
In-batch negatives Other examples' positives in the same batch, reused as negatives (free).
Global negatives In-batch negatives gathered across all DDP ranks via all-gather (I9).
Hard negative A document the current model wrongly ranks near a query; the only negatives with signal late in training.
Mining (hard-negative) Retrieving hard negatives via ANN over the current model's embeddings (+ BM25), refreshed on a schedule (ANCE).
False negative A "negative" that is actually relevant; must be excluded from the loss (I11).
Negative cache Per-example store of mined negative ids; versioned; refreshed periodically.
Staleness How many steps since the negative cache was refreshed (a key alertable metric).
Cross-batch memory (xbm) FIFO queue of recent detached embeddings reused as extra negatives (MoCo/RocketQA).
Gradient cache (GradCache) Two-pass technique decoupling effective batch from activation memory.
Effective batch Total examples (and hence negatives) the loss sees: device batch × accumulation × world × xbm.
Pooling Reducing token embeddings to one vector: CLS, mean (mask-weighted), or last-token.
Projection head Linear layer mapping encoder hidden to embedding_dim.
L2 normalization Scaling a vector to unit norm; makes dot product == cosine (I3).
Alignment E‖q−d⁺‖² over positives; lower = positives close (a healthy-embedding signal).
Uniformity log E e^{−2‖x−y‖²} over pairs; lower = embeddings spread on the sphere; collapse if rising.
Embedding collapse Degenerate embeddings (std→0, low rank, all-similar); training fails silently.
Effective rank Rank of the embedding matrix; ≪ d indicates dimensional collapse.
Recall@k Fraction of queries whose relevant doc is in the top-k retrieved.
MRR Mean Reciprocal Rank of the first relevant doc.
nDCG Normalized Discounted Cumulative Gain (honors graded relevance).
MAP Mean Average Precision across queries.
qrels Relevance judgments (query→relevant docs), TREC format.
BM25 Probabilistic lexical ranking function; lexical hard-neg source + baseline.
ANN Approximate Nearest Neighbor search (HNSW/IVF/PQ); used for mining + handoff (#255).
.vshard VETP's immutable, content-addressed sharded corpus format.
DataManifest Metadata pinning a data version: shards, dedup/filter/leakage stats, split.
RunManifest Joins model↔data↔code: data_version + code_hash + config_hash (I13).
Checkpoint Atomic snapshot of model+optimizer+scheduler+sampler+RNG (I6).
arch_signature Hash of architecture-affecting config; gates resume compatibility (I7).
Exactly-once consumption Each example visited once per epoch; cursor checkpointed (I2).
Deterministic replay Re-running a captured (config, data_version, seed, world) yields identical loss + sample order (I4).
Export parity Exported ONNX/TorchScript matches eager outputs within tolerance (I14).
HandoffManifest Contract to #255/#328: embedding_dim + normalization + distance + vectors (I15).
Training-serving skew Mismatch between training and serving encoding (tokenizer/prefix/normalization) → wrong neighbors.
Distillation Training the bi-encoder to mimic a cross-encoder teacher's scores (Margin-MSE).
AMP / GradScaler Automatic mixed precision; scaler manages fp16 gradient overflow (I8).
DDP Distributed Data Parallel: replicate model, all-reduce gradients across GPUs.
