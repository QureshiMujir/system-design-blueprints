  3. The round() unit passes its standalone exhaustive truth table. After wiring it into add, 1 in 2^24 test cases in TestFloat fails with an incorrect result. The failing cases share the property that the alignment shift d equals exactly p+1. What went wrong, and which invariant was violated? (Synthesis: P2, P3, §8.5 cancellation note, I2.)
  4. A user reports that Money::add in currency USD gives $0.01 instead of $0.00 for $0.005 + $0.005 under the default rounding policy. Is this a bug or correct behavior?   5. Explain why sqrt(−0.0) must return −0.0 and not 0.0 or NaN. Trace the exact path through the P6 domain checks and identify which IEEE-754 clause governs this. (Synthesis: §8.8, §8.16, I3, I14, Appendix D.)
  6. On a no_std embedded target without division hardware, your soft-float divide uses a restoring algorithm producing p+2 quotient bits. The TestFloat f32_div suite passes at RNE but fails at RTZ for a specific value. What is the most likely cause involving the remainder and sticky bit? (Synthesis: §8.7, §8.4, ADR-09, I1, I5.)
  7. The BID library encodes decimal64 value 9.999999999999999 × 10^384. What is its combination field, and why would a DPD encoder for the same value produce a different bit pattern? Are these two encodings interchangeable? (Synthesis: §8.13, ADR-08, P10, I11, Appendix C.)
  8. You add a new rounding mode roundTiesToOdd (ties round to odd last bit). Enumerate every component that must change and every invariant that must be re-verified. What new conformance vectors are needed? (Synthesis: §8.4, §8.17, P2, ADR-12, I2, I9, §6 Principle 12.)
  9. A BigDecimal division 1 / 3 is requested without an explicit scale or rounding policy. What should happen, and what does P11 implement? Contrast with how decimal64 handles the same division. (Synthesis: §8.13, §8.14, P11, ADR-17, I11.)
  10. The Ryū algorithm requires a precomputed power-of-5 table. If that table has one wrong entry at index k, what is the observable consequence, and which TestFloat/conformance mechanism would catch it? Why might unit tests that cover all exponents miss this bug? (Synthesis: P9, ADR-15, P7 Adams, P13 conformance, §8.15 worked examples.)
  11. Describe the exact state of FpContext.flags after computing x = add(1.0, 2^{-53}) then y = sub(x, 1.0) in binary64. Which flags are set after each op and why? What does the final state tell a caller? (Synthesis: §8.10, §8.5, ADR-13, I13, I17.)
  12. A constant-folding compiler uses this library to evaluate sqrt(2.0) at compile time and stores the result as a binary64 literal.   13. The strtod parser encounters the string "3.141592653589793238". It must produce the nearest binary64 value. Describe the cases where the basic algorithm (multiply by power of 2) is insufficient and the bignum fallback from P4 (Clinger) is triggered. (Synthesis: P9, P4, P6, ADR-16, §8.15 worked examples.)
  14. Two threads simultaneously call add(a, b, &ctx1) and mul(c, d, &ctx2) with different FpContext objects. One thread's context uses RNE; the other uses RTZ. Is there a data race? What property of the design guarantees safety? (Synthesis: §4 Concurrency row, ADR-13, §6 Principle 3b, I15.)

How would this escape the grep-based gate, and what additional verification would catch it? (Synthesis: ADR-02, ADR-29, §4 Hardware-float row, I12, I15.)
  18. The soft-float add for binary128 uses #370 bignum for the significand product intermediate. A performance regression test shows it is 50× slower than binary64 add. Is this expected? What is the theoretical bound, and what could reduce the gap without violating ADR-29?   19. Explain why the "table-maker's dilemma" means exp and log cannot be included in this project's correctly-rounded core, while sqrt, div, and fma can. What is the fundamental structural difference? (Synthesis: Appendix E, §1 non-goals, §6 Principle 1, MM9, Deferred Features Register.)

Mental Models & First Principles

MM1. A float is a triple, not a number. Every IEEE value is (sign, biased_exp, trailing_sig). All behavior — special values, subnormals, NaN payloads — follows from the bit fields; no "floating point is magic" thinking survives once you hold the triple. Predicts: you can construct any NaN payload or signed zero on demand. Bug class without it: conflating "NaN" as a single object; surprised by sNaN vs qNaN; losing −0. Resolving sections: §8.1–8.2, P0.

MM2. Guard/round/sticky make one extra bit sufficient for exact rounding. Three bits below the kept significand represent all information needed for any algebraic op: G is the first discarded bit, R the second, S the OR of all remaining. No matter how long the exact result, the rounding decision is the same as if you had computed it to infinite precision. Predicts: you never need to widen the intermediate beyond 2p + 3 bits. Bug class without it: truncating early, losing sticky, producing off-by-1-ulp results that pass casual tests and fail TestFloat. Resolving sections: §8.4, P2, I2.

MM3. The rounding unit is the single source of truth. Every op must funnel its discarded bits through one GRS unit; any per-op shortcut that re-derives the increment rule independently will drift. Predicts: bugs in rounding will appear consistently across all ops; fixing one place fixes all. Bug class without it: each op has a slightly different GRS computation; RNE tie-to-even works for add but not for mul, causing conformance failures that look op-specific. Resolving sections: §6 Principle 12, ADR-12, P2.

MM4. FMA rounds exactly once — the key differentiator from mul; add. The full 2p-bit product is never rounded before the addend is aligned; only the final combined value sees the rounding unit. Double-rounding (rounding a×b, then adding c) gives a different bit pattern in about 1 in 2^(p+1) cases. Predicts: a mul; add emulation will produce ~1 wrong last bit per 2^53 cases for binary64 — rare enough to pass most hand tests, caught only by a systematic differential. Bug class without it: implementing FMA as mul-then-add, passing 99.999999% of tests, failing just enough for a compiler that depends on it to constant-fold wrong. Resolving sections: §8.9, §6 Principle 7, ADR-11, P7, I10.

MM5. Subnormals are the continuity property, not an edge case. The transition from smallest normal to zero is gradual; without subnormals the gap between 0 and min_normal would be 2^(emin−1) times larger than the gap between adjacent normals. This is not a quirk — it is what makes |a − b| = 0 ⟹ a = b true for finite floats. Bug class without it: flush-to-zero quietly corrupts subtraction near emin; max_subnormal + 1_ulp silently returns wrong normal. Resolving sections: §6 Principle 6, §8.16 max-subnormal boundary, I7, P0 (classify), P2 (pack underflow path).

MM6. Decimal is exact in base-10; binary is not. 0.1 is not representable in binary but is trivially coeff=1, exp=−1 in decimal. This is not imprecision but a property of the base. Predicts: any financial system using binary float will have systematic penny rounding errors over repeated transactions. Bug class without it: using f64 for currency, noticing test failures only at aggregate level. Resolving sections: §6 Principle 8, §8.15 money example, P11–P12.

MM7. Exception flags are monotone sticky state, not exceptions. NV/DZ/OF/UF/NX bits only set, never clear implicitly; they accumulate across a computation. An explicit FpContext.clear() call is the only reset. Predicts: after a sequence of ops, any bit set means at least one op raised it — a composition property that makes audit straightforward. Bug class without it: checking flags mid-computation, missing a raised NX from a subnormal intermediate, or being surprised that a subsequent exact op doesn't clear Inexact. Resolving sections: §8.10, §6 Principle 3, ADR-13, I13, I17.

MM8. Correct rounding via remainder is a decision, not a measurement. For div and sqrt, the correctly-rounded result is determined by asking: is the exact real result above, below, or exactly at the midpoint between two adjacent floats? A nonzero remainder after p+2 bits definitively answers "not at the midpoint" and determines the round direction. Computing a remainder sign is O(1) — vastly cheaper than extended-precision computation. Bug class without it: stopping digit-recurrence at p bits, guessing the round direction, producing 1-ulp errors that defeat the spec. Resolving sections: §8.7 (div), §8.8 (sqrt), ADR-09, ADR-10, P5–P6.

MM9. Bit-exact soft-float is an integer computation with a specification. Every arithmetic result is determined by the IEEE-754 standard to the last bit; there is no approximation or "numerical" ambiguity — only correct and wrong. Predicts: differential testing against any conformant implementation (hardware or another soft-float) should give ulp error = 0 for every correctly-implemented op. Bug class without it: treating ±1 ulp as "close enough," accepting a library that gives wrong last bits on div/sqrt, silently corrupting dependent systems (constant folding, FPU-less MCU). Resolving sections: §1, §4 (conformance row), §6 Principle 1, P13, I1.

MM10. The cohort is the decimal identity, not the encoding. In decimal arithmetic, 1.0, 1.00, and 100×10⁻² are the same value in different representations (the "cohort"). Equal-value members of a cohort compare equal and participate in arithmetic as if they were one value; only the "quantum" (preferred exponent) governs the output representation. Bug class without it: treating two BID encodings of 1.0 as unequal, producing decTest failures on compare and quantize, or picking the wrong ideal exponent. Resolving sections: §8.13, §8.11 (decimal cohort), I11, P10, P11.

Lessons most frequently re-learned: double-rounding (round to wide then narrow), sticky-bit loss during multi-bit alignment shifts, sNaN mishandling (must signal + quiet), subnormal flush creeping in, −0.0 sign lost in add, cohort confusion in decimal (treating 1.0 ≠ 1.00 as a value difference), flag accumulation oversight (checking flags before all ops complete), carry-out renormalization skip after rounding increment.

values below the smallest normal, with gradual underflow.
gradual underflow
representing tiny values via subnormals instead of flushing to zero.
signed zero
+0 and −0 are distinct (1/−0 = −inf).
infinity
±inf, the overflow/limit value.
qNaN / sNaN
quiet vs signaling Not-a-Number.
NaN payload
the significand bits of a NaN, propagated by ops.
guard bit (G)
first bit beyond the kept significand.
round bit (R)
second bit beyond.
sticky bit (S)
OR of all remaining lower bits.
GRS
guard/round/sticky, the basis of correct rounding.
ulp
unit in the last place; the spacing between adjacent floats.
correct rounding
result is the representable value nearest the exact answer (≤ 0.5 ulp).
round-half-even (banker's)
ties go to the even last digit; unbiased; the default.
round-half-away
ties round away from zero.
round-toward-zero / +∞ / −∞

exception flags

FMA
fused multiply-add with a single rounding.
double rounding
rounding twice (e.g., to extended then to target), which can give a wrong result.
normalization
shifting the significand so the leading bit is in the canonical position.
cohort
the set of decimal representations of one value (different exponents).

declet

Dekker / double-double

quantum / quantize

minor unit
