401 — IEEE-754 Soft-Float + Decimal Arithmetic from Scratch

Project Number: 401 Project Name: IEEE-754 Soft-Float + Decimal Arithmetic from Scratch Document: FINAL_BLUEPRINT.md Owner: Mujir Qureshi Status: specification — locked

1. Goal

Build a correctly-rounded, integer-only software floating-point and decimal arithmetic library — no hardware FPU dependence anywhere in the core. Class peers: Berkeley SoftFloat, LLVM compiler-rt soft-float builtins, rustc_apfloat.

Binary scope (IEEE 754-2019). Interchange formats binary16, binary32, binary64, binary128 (+ optional bfloat16). All required operations:

Op Signature shape Correctly rounded
add, sub (F,F)->F yes (≤0.5 ulp)
mul (F,F)->F yes
div (F,F)->F yes
sqrt (F)->F yes
fma (F,F,F)->F yes, single rounding
remainder (IEEE) (F,F)->F exact
compare (F,F)->{Lt,Eq,Gt,Unordered} exact
conversions int↔F, F↔F, F↔string, round-to-integral per-spec

All 5 rounding modes, subnormals (gradual underflow), signed zero, ±inf, qNaN/sNaN, and the 5 exception flags (NV, DZ, OF, UF, NX).

Decimal scope (IEEE 754-2019 decimal). decimal32, decimal64, decimal128 in both encodings — BID (binary integer significand) and DPD (densely packed decimal). Decimal ops + decimal rounding (half-even, half-up, …). Cohort-aware.

Arbitrary-precision + money. BigDecimal (unscaled BigInt + scale) backed by #370 Bignum. Money = scaled fixed-point with explicit rounding policy + currency.

System boundaries. Library (no_std core) + a conformance CLI + a TestFloat-style differential harness. The library computes values and updates an explicit FpContext (rounding mode + sticky flags). It does not own threads, IO, or global state.

Explicit non-goals.

  • NOT a transcendental libm. exp/log/sin/cos/pow correctly-rounded → PhaseDeferred("Deferred Features Register") (stretch). Core ships only algebraic ops the standard requires correctly rounded.
  • NOT hardware-float-using in the core. Zero f32/f64/f80/f128 in binary/, bits/, decimal/. Integer-only. Enforced by lint + feature gate (ADR-02).
  • NOT a bignum integer library. Wide intermediates for binary128/decimal/BigDecimal come from #370 Bignum; this project consumes, does not reimplement, BigInt.
  • NOT GPU / SIMD-vectorized. Scalar reference correctness first; vectorization is out of scope.
  • NOT a numerics application (no linear algebra, no solvers). Primitive arithmetic only.

Deployment model. Published as a Rust workspace of crates; no_std core with optional alloc feature for arbitrary precision. Consumers: compiler back-ends lowering float ops, VM interpreters, FPU-less embedded targets, financial systems needing exact base-10. A softfp-cli binary runs conformance suites and ad-hoc evaluation.

Target users. Compiler/runtime engineers (float lowering, constant folding), embedded engineers (no-FPU MCUs), finance engineers (decimal/money), and standards-conformance testers.

Phase 0 deliverable — numbered modules (crates).

  1. softfp-formats — format parameter definitions (binary16/32/64/128, bfloat16, decimal32/64/128).
  2. softfp-bits — pack, unpack, classify, GRS extraction, leading-zero/normalize helpers.
  3. softfp-context — FpContext, Flags bitset, RoundingMode.
  4. softfp-binary — add, sub, mul, div, sqrt, fma, rem, compare, round-to-integral.
  5. softfp-convert — int↔float, float↔float, parse (strtod-correct), format (Ryū shortest).
  6. softfp-decimal — BID + DPD decode/encode, decimal ops, decimal rounding.
  7. softfp-arbdec — BigDecimal on #370 BigInt.
  8. softfp-money — Money fixed-point, currency, rounding policies.
  9. softfp-cli — conformance + REPL front-end.
  10. softfp-harness — TestFloat/decTest vector generation + differential runner.

What later phases unlock. P2 rounding unit unblocks every arithmetic op. P3–P7 deliver the algebraic core. P8 conversions enable round-tripping. P9 dtoa/strtod give human IO. P10–P12 deliver decimal + money. P13 is conformance + enforcement. Transcendentals deferred.

Deferred features. Correctly-rounded transcendental libm → PhaseDeferred("Deferred Features Register"). SIMD batch ops → PhaseDeferred("Deferred Features Register"). Decimal interchange-with-binary conversions beyond round-to-nearest → PhaseDeferred("Deferred Features Register").

Timeline. Phase 0 (P0–P13 scalar reference, fully conformant): 8–14 weeks single engineer. Transcendental stretch + perf hardening: additional months.

Recommended language: Rust.

Criterion Rust C (reference langs) High-level (Python/Java/Go)

no_std, no hidden float first-class yes but UB-prone no

Reject C: it is the reference (SoftFloat, compiler-rt) but signed-overflow/aliasing UB makes bit-exact determinism fragile. Reject Python/Java/Go: need raw fixed-width bit manipulation, no hidden float promotion, and no_std embedding. Rust gives precise integer control, safety on the many branchy edge paths, and a lint surface to ban f32/f64 from the core.

Prerequisites. Binary number representation (two's complement, fixed-width ints); bit manipulation (shifts, masks, leading/trailing zero count, Hacker's Delight tricks); rounding theory (round-to-nearest-even, directed rounding, ulp); the IEEE 754-2019 standard text; integer multiply/divide algorithms (schoolbook, restoring division, Newton-Raphson reciprocal); Goldberg's What Every Computer Scientist Should Know About Floating-Point Arithmetic; basic Rust (ownership, traits, const fn, no_std).

Sequencing rationale. Phase order is non-arbitrary: (a) P0–P1 lock the format encoding and special-value semantics before any arithmetic; (b) P2 builds the rounding unit standalone so every later op can call it without re-deriving the rule; (c) P3–P7 build arithmetic bottom-up (add → mul → div → sqrt → fma), each depending on P2 but not on later phases; (d) P8–P9 add conversion after arithmetic is stable — widening and narrowing depend on the round unit; (e) P10–P12 add decimal/money which depend on binary (for error model) but are otherwise self-contained; (f) P13 runs the complete conformance suite after all ops are implemented — you cannot pass TestFloat incrementally at the full level because it cross-checks flags across all ops simultaneously.

2. Why Build This

Knowledge taught — the real internals of a float.

  • Exponent alignment before add/sub; normalization after; the implicit (hidden) leading bit.
  • Guard / Round / Sticky bits and why three extra bits suffice for correct rounding of all algebraic ops.
  • Correct rounding (≤0.5 ulp) and why naive truncate-after-compute is wrong.
  • Gradual underflow via subnormals vs flush-to-zero, and the max-subnormal → min-normal boundary.
  • NaN propagation, qNaN vs sNaN, payloads, and the which-NaN selection rule.
  • Exception flags as sticky state, not exceptions-in-the-PL sense.
  • Decimal vs binary: why 0.1 is exact in decimal and not in binary; the cohort concept (one value, many encodings).
  • Single rounding for FMA and why double rounding silently corrupts results.

Significance. Every CPU, every compiler constant-folder, every language runtime relies on exactly this machinery. Soft-float is the only path on FPU-less embedded parts. IEEE 754-2008 added decimal precisely because binary float must never hold money. This project is the substrate beneath "numbers just work."

Engineering muscles. Bit-exact reasoning; exhaustive/edge-case discipline; differential testing against an oracle (hardware); reading and obeying a formal standard verbatim; building a component (rounding unit) that many call sites depend on; performance work under a "no shortcut may change the bits" constraint.

Cross-links.

  • #370 Bignum — wide intermediates for binary128 and decimal; the BigInt backing BigDecimal. Hard dependency.
  • #30 Compiler / #31 VM — both must lower float literals + ops; this library is the semantics they target (constant folding must match runtime bit-for-bit).
  • #44 LLM Inference — quantization and low-precision formats (bfloat16, fp16) reuse these pack/unpack/round primitives.
  • This project (#401) underpins numeric correctness across the portfolio: anything that prints, parses, or computes a float should agree with it.

Calibration value. After this, "floating point is weird" becomes "floating point is a precisely specified state machine." Permanently raises the ceiling on systems-numeric work: you can now debug an off-by-1-ulp discrepancy, explain a missing Inexact flag, and trust your own dtoa.

What Mastery Looks Like

  • P0–P1: Format internals command. Given any 64-bit hex pattern, instantly reads off sign, biased exponent, significand, and class (±0, subnormal, normal, ±inf, qNaN, sNaN) without consulting a table; reproduces the bit layout for all five binary formats from the defining parameters (w, p, bias).
  • P2: Rounding theory depth. Derives the GRS increment rule for each of the five modes from first principles; explains why three extra bits are sufficient for all algebraic ops; constructs a witness case that distinguishes RNE from RNA in the tie scenario; traces a carry-out renormalization through a concrete 1.111…→10.000… example.
  • P3–P7: Algebraic-op correctness ownership. Traces the guard/round/sticky chain from input bits through alignment shift to final round decision for add, mul, div, sqrt, and FMA; diagnoses a double-rounding bug in an FMA implementation from a given witness vector; explains why digit-recurrence with an exact remainder test guarantees the last bit for div and sqrt.
  • P8–P9: Conversion and IO round-trip. Explains the Clinger/Gay strtod algorithm and when the bignum fallback is needed; explains why Ryū guarantees shortest round-trip; constructs a case where Dragon4 and a naïve implementation diverge.
  • P10–P12: Decimal and money substrate. Distinguishes BID from DPD encoding at the bit level; explains the cohort concept and the ideal-exponent rule; constructs a money-allocation scenario that fails with binary float and passes with BigDecimal + largest-remainder; explains why half-even is unbiased over repeated transactions.
  • P13: Conformance ownership. Reads a Berkeley TestFloat failure output (op, mode, inputs, expected result+flags, got result+flags), identifies the root cause (rounding vs flag timing vs special-case ordering), and knows which source module to fix; explains the relationship between the ulp-diff histogram and a formally correct implementation.
  • Architecture-level: Redesign capability. Given a new constraint (e.g., "port to a 16-bit ALU with no 32-bit multiply", or "add a 6th rounding mode"), identifies exactly which components change (GRS unit, pack, ADR row), which invariants are stressed, and what new TestFloat vectors are needed — without rereading this document.

Figure 3b: Decimal and Money/Fixed-point pipelines.

DECODE. Splits a stored bit pattern into raw (sign, biased_exp, trailing_significand). Pure shifts/masks per softfp-formats constants. No interpretation yet.

CLASSIFY. Maps raw fields to FpClass. Conditions: exp all-zero + frac zero → ±0; exp all-zero + frac≠0 → subnormal; exp all-ones + frac zero → ±inf; exp all-ones + frac≠0 → NaN (MSB of frac = quiet bit → qNaN else sNaN). Else normal. Feeds special-value fast paths so cores only see finite operands.

UNPACK. Produces the internal Unpacked{sign, exp (unbiased i32), sig (extended), grs}. Normal values get the implicit bit restored; subnormals keep leading zeros and an exponent pinned at emin. The significand is widened so cores can accumulate guard/round/sticky.

OPERATION CORES. Each algebraic op works on Unpacked and emits an unrounded (sign, exp, sig, G, R, S). Cores never round and never set flags except the intrinsic ones (e.g., div-by-zero detection lives at the special-path layer). They produce enough low-order information (G, R, S) for the rounding unit to be exact.

ROUNDING UNIT. The single chokepoint. Given mode + (L, G, R, S) + sign, decides truncate vs increment, handles carry-out renormalization (e.g., 1.111…→10.000… bumps exponent), and detects overflow/underflow at the boundary. Built and tested standalone in P2 before any arithmetic uses it.

EXCEPTION AGGREGATOR. Sticky-ORs raised flags into FpContext.flags. Inexact set whenever any of G,R,S nonzero (or rounding changed value); Overflow/Underflow at exponent range limits; Invalid/DivByZero from special paths.

PACK / NORMALIZE. Re-biases exponent, drops the implicit bit, clamps to inf on overflow (mode-dependent), produces subnormal encodings on underflow, writes the final bit pattern.

DECIMAL DECODE/ENCODE. BID stores the coefficient as a plain binary integer; DPD packs 3 decimal digits per 10 bits (declets). Both share the combination-field exponent/MSD scheme. Decode → {sign, coeff:BigInt-or-u128, exp}.

DECIMAL ROUNDING. Operates in base-10 on the integer coefficient; default half-even; cohort selection picks the preferred exponent per the standard.

MONEY/FIXED-POINT. A scaled BigInt (unscaled value + decimal scale) plus an explicit RoundPolicy and Currency. Arithmetic stays exact until an explicit quantize/round, which applies the policy.

6. Design Principles

  1. Correct rounding is non-negotiable. Every algebraic op returns the correctly-rounded image of the exact real result (≤0.5 ulp). Mechanism: guard+round+sticky are mandatory; cores must preserve enough low-order information. Tradeoff: more intermediate width + a remainder step for div/sqrt. Operational: TestFloat diff is the gate. Violation: off-by-1-ulp results that pass casual tests but fail conformance and silently corrupt downstream numerics.

  2. No hardware float in the core. Determinism + FPU-less targets demand integer-only arithmetic. Mechanism: f32/f64 banned in bits/binary/decimal via lint + a core feature that does not link any float intrinsic (ADR-02). Tradeoff: slower, more code. Violation: non-reproducible bits across targets; impossible on no-FPU MCUs; secret double-rounding through an x87 80-bit register.

  3. Exception flags are first-class sticky state. NV/DZ/OF/UF/NX accumulate in an explicit FpContext, never thrown, never reset implicitly. Tradeoff: every op takes &mut FpContext. Operational: flags are asserted in conformance vectors. Violation: a "fast" path that skips flag updates passes value checks but fails flag checks; consumers relying on Inexact (e.g., exact-arithmetic detection) break.

3b. Explicit context, no globals. Rounding mode + flags live in a passed FpContext, not thread-local hardware state. Tradeoff: API verbosity. Operational: trivially testable, parallel-safe, reproducible. Violation: hidden global mode makes tests order-dependent and non-deterministic.

  1. NaN propagation follows the standard exactly. sNaN input → qNaN output + raise NV; qNaN propagates quietly; the which-NaN selection and payload rules are obeyed. Tradeoff: extra branches on every op entry. Violation: sNaN silently treated as qNaN hides signaling errors; nondeterministic NaN payloads break differential tests.

  2. Signed zero and signed infinity semantics preserved. +0 ≠ −0 in sign bit though they compare equal; 1/+0=+inf, 1/−0=−inf; x+(-x)=+0 (RNE). Violation: losing −0 breaks branch-cut conventions (complex libs) and reciprocal sign.

  3. Gradual underflow, never flush-to-zero (core). Subnormals are computed exactly and rounded; UF flag set per standard. Tradeoff: a separate subnormal alignment path. Violation: FTZ changes results near emin, breaks the max-subnormal→min-normal continuity, fails conformance.

  4. FMA rounds once. a*b+c keeps the full 2p-bit product, aligns c against it, and rounds the single combined result. Tradeoff: widest intermediate in the library. Violation: rounding the product first (double rounding) gives a different, wrong bit pattern; defeats the entire reason FMA exists.

  5. Decimal for exact base-10; money never in binary float. Currency lives in decimal*/BigDecimal/Money, never binary64. Violation: 0.1+0.2≠0.3 errors accumulate into accounting discrepancies.

  6. Banker's rounding (half-even) is the money default. Eliminates the upward bias of half-up over many transactions. Tradeoff: surprises users expecting half-up; policy is explicit + overridable. Violation: systematic rounding bias in aggregates.

  7. Determinism + bit-exact cross-platform. Identical inputs + mode produce identical bits on any architecture, compiler, opt-level. Mechanism: integer-only, no fast-math, no reassociation, fixed evaluation order. Violation: "works on my machine" numeric bugs; broken reproducible builds.

  8. Test against the standard's own vectors. Self-authored tests are necessary but insufficient; Berkeley TestFloat + IBM decTest + a slow-exact oracle are the authority. Violation: shared blind spots between implementation and home-grown tests pass while real conformance fails.

  9. One rounding unit, one source of truth. All ops funnel GRS through a single round() component (P2). Tradeoff: a slightly more general interface. Violation: per-op ad-hoc rounding drifts; bugs must be fixed N times.

  10. Special values handled before the cores. inf/NaN/zero resolved at a fast-path layer; cores only see finite, classified operands. Violation: cores littered with if inf checks, easy to get an ordering wrong (e.g., inf*0 vs inf+(-inf)).

  11. Lightweight schemas, never source. Blueprint carries signatures, bit-layouts, ≤2-line rounding fragments; no function bodies (CRITICAL RULE 10).

  12. Reproducible, audited dependencies. Only #370 Bignum + std test-only crates; cargo deny/vet; SBOM. Violation: a transitive crate pulling libm/hardware float into the core silently breaks Principle 2.

Implicit leading bit: value of a normal number = (-1)^s × 1.frac × 2^(E-bias). Value of a subnormal = (-1)^s × 0.frac × 2^(emin) (exponent field = 0 but effective exponent pinned at emin). Stored exponent E ∈ [1, 2^w−2] for normals; E=0 subnormal/zero; E=2^w−1 inf/NaN.

8.2 Value classes

Class Condition (E = biased exp field, T = trailing significand)
+0 / −0 E = 0, T = 0 (sign bit distinguishes)
subnormal E = 0, T ≠ 0

NaN payload = T with the quiet bit (MSB of T) masked. sNaN with payload-low bits all zero except quiet bit reserved per format; an all-zero payload with quiet bit clear would be inf, so sNaN requires at least one payload bit set.

8.3 Internal unpacked representation

Unpacked {
  sign : bool,          // true = negative
  exp  : i32,           // unbiased; subnormals normalized lazily
  sig  : Wide,          // integer significand, MSB-aligned, implicit bit explicit
  // low-order rounding info produced by cores:
  g    : bool,          // guard  (first bit below LSB kept)
  r    : bool,          // round  (second bit below)
  s    : bool,          // sticky (OR of all remaining lower bits)
}

Wide = u64/u128 for ≤binary64, u256/BigInt(#370) for binary128 and FMA products. Cores keep sig so its top set bit indicates normalization; rounding position derived from format p.

8.4 Rounding modes + GRS decision

| Mode (IEEE name) | Alias | Increment rule (given retained LSB L, guard G, round R, sticky S; rest = R|S) | |------------------|-------|---------------------------------------------------------------------------------| | roundTiesToEven | RNE (default) | inc = G & (rest \| L) — tie (G&!rest) rounds to even | | roundTiesToAway | RNA | inc = G — tie rounds away from zero | | roundTowardPositive | RTP / ceil | inc = (!sign) & (G \| rest) | | roundTowardNegative | RTN / floor | inc = sign & (G \| rest) | | roundTowardZero | RTZ / trunc | inc = 0 (drop GRS) |

Two-bit simplification (sticky folds R): with guard G and sticky S' = R|S: RNE inc = G & (S' | L); RNA inc = G; RTP inc = !sign & (G|S'); RTN inc = sign & (G|S'); RTZ inc = 0. Carry-out: if inc makes sig overflow p bits (1.11…1 → 10.0…0), shift right 1 and exp += 1 (may trigger overflow).

8.5 Add / subtract algorithm

Steps (effective op determined by signs):

  1. Classify; special paths (NaN, inf, zero, ±0 rules).
  2. Order by exponent; d = exp_large − exp_small.
  3. Shift smaller significand right by d, capturing shifted-out bits into G,R,S (sticky = OR of all bits past round position).
  4. Effective add (like signs) → may carry out → normalize right 1. Effective subtract (unlike signs) → may cancel leading bits → normalize left (renormalize), pulling in zeros (G,R,S feed back).
  5. Round (P2). Set NX if any GRS set; OF/UF at range limits. Cancellation note: massive cancellation (e.g., x − y, x≈y) yields few significant bits; sticky from the alignment is what makes the rounded result correct.

8.6 Multiply

  1. Special paths (0×inf→NaN+NV; inf×finite→inf; etc.).
  2. Full product P = sig_a × sig_b = up to 2p bits.
  3. exp = exp_a + exp_b (+ normalization adjust).
  4. Normalize: top bit of P sets whether to shift 1.
  5. Round using bits below position p: G = bit p+? , S = OR of the rest of the 2p-bit product. Exact because the full product is retained.

8.7 Divide

  1. Special paths (x/0→inf+DZ for finite x≠0; 0/0,inf/inf→NaN+NV).
  2. Compute quotient significand to p bits plus guard + round, with a remainder to derive sticky exactly.
    • Restoring/non-restoring long division: produce p+2 quotient bits; sticky = (final remainder ≠ 0).
    • OR Newton-Raphson reciprocal: q ≈ a × recip(b); refine to p+2 good bits; compute residual a − q·b sign/zero → guard/round/sticky.
  3. exp = exp_a − exp_b (+ adjust).
  4. Round; NX if remainder ≠ 0.

8.8 Square root

  1. Special paths: sqrt(−x) (x>0)→NaN+NV; sqrt(−0)=−0; sqrt(+inf)=+inf; sqrt(NaN) propagate.
  2. Even-exponent reduction: factor 2^(2k) so radicand mantissa ∈ [1,4).
  3. Digit-recurrence (SRT-style) or Newton-Raphson for 1/√ then multiply; produce p+2 bits.
  4. Correct rounding via remainder sign: compare result² (or (result±½ulp)²) to radicand to decide round direction exactly. NX if not a perfect square.

8.9 Fused multiply-add

  1. Special paths including the FMA-specific (0×inf)+c and inf+(-inf) orderings (NV where mandated).
  2. Exact product P = sig_a × sig_b (2p bits), exp_p = exp_a + exp_b.
  3. Align addend c against P (shift to common exponent; the wider of product/addend ranges sets the field; capture sticky on the short side).
  4. Add/subtract in the wide accumulator; normalize.
  5. Single rounding to p bits. NX/OF/UF from the one rounding. No intermediate rounding of P.

8.11 NaN details

  • Quiet bit = MSB of trailing significand. qNaN sets it; sNaN clears it (with ≥1 other payload bit set).
  • sNaN as operand → raise NV, return a qNaN (quieted: set MSB, preserve remaining payload where possible).
  • Which-NaN selection (two NaN operands): return one input NaN quieted; this library's rule = prefer the first operand's NaN, else second; payload preserved. Documented + tested (the standard leaves it implementation-defined; we fix it for determinism, I15).
  • NaN never compares ordered; any compare with NaN → Unordered; equality with NaN is false (even NaN==NaN).

8.12 Conversions

Conversion Rule
int → float round per mode (large ints inexact → NX); sign preserved
float → int round-to-integral toward chosen direction then truncate to int; out-of-range / NaN → NV + defined result (e.g., saturate or INT_MIN per ABI)
float → wider float exact (no rounding); subnormal source becomes normal in wider format
float → narrower float round per mode; may overflow→inf (OF) or underflow→subnormal/0 (UF)
round-to-integral per mode; result is an integral float; NX only if mode-dependent variants require (the "exact" variant raises NX, the others do not)

8.13 Decimal formats

IEEE decimal interchange = sign(1) + combination(5) + exponent-continuation(w) + coefficient-continuation(t).

Format bits w t precision p (digits) emax emin exponent bias
decimal32 32 6 20 7 96 −95 101
decimal64 64 8 50 16 384 −383 398
decimal128 128 12 110 34 6144 −6143 6176

Combination field encodes the two most-significant exponent bits and the most-significant digit (MSD) jointly (because MSD ∈ 0..9 needs <4 bits, leaving room). Two encodings of the coefficient continuation:

  • BID (Binary Integer Decimal): coefficient is one plain binary integer; arithmetic is binary-integer on the coefficient. Fast on binary hardware.
  • DPD (Densely Packed Decimal): 3 decimal digits packed per 10-bit declet (1000 values < 1024); coefficient is a digit string. Compact, decimal-native.

Cohort: a finite decimal value has many representations (coeff × 10^exp) (e.g., 1.0 = 10×10⁻¹ = 1×10⁰ = 100×10⁻²). The set is the cohort. Operations pick a preferred exponent per the standard (e.g., add/sub prefer the smaller exponent of operands). Equality is by value, not encoding.

Decimal rounding modes: the five binary modes plus roundHalfUp, roundHalfDown, roundDown, roundUp, roundCeiling, roundFloor (the RoundPolicy enum, §11). Default for IEEE decimal ops = roundTiesToEven; default for Money = HalfEven.

8.14 Fixed-point / money

Money { amount: BigDecimal{ unscaled: BigInt(#370), scale: i32 }, currency: Currency, policy: RoundPolicy }

Value = unscaled × 10^(−scale). Arithmetic stays exact (scales reconcile by widening) until an explicit quantize(scale, policy) applies rounding. Currency carries the canonical minor-unit scale (USD=2, JPY=0, BHD=3). Q-format fixed-point (Qm.n, binary scaled int) supported as a separate FixedQ type for embedded DSP use.

8.16 Malformed / edge cases

  • sNaN propagation across every op (must quiet + NV).
  • +0.0 vs −0.0: 1/−0 = −inf; (+0)+(−0)=+0 (RNE), (−0)+(−0)=−0; min(+0,−0),max sign rules.
  • Overflow at emax: result magnitude just above max finite → inf (RNE/RNA) or max finite (RTZ, and directed toward zero) → OF+NX.
  • Gradual underflow at emin: rounding a tiny exact value into the subnormal range → UF+NX; result may round up to min normal (boundary case must be exact).
  • Max subnormal → min normal boundary: max_subnormal + 1ulp = min_normal; the carry from subnormal into the implicit-bit position must set the exponent correctly.
  • Double-rounding pitfall: rounding to extended precision then to target; forbidden — must round once to target (relevant to FMA and to narrowing conversions).
  • Ties in each mode: construct exact-half cases and assert RNE→even, RNA→away, RTP/RTN/RTZ→directed.

ADR-23 Fuzzing cargo-fuzz on op inputs + parsers manual test expansion only corner-case discovery Manual wins when the codebase is small (a few hundred lines, ≤2 formats) and the entire input space can be covered exhaustively; binary16 can be tested 2^32 pairs exhaustively, making fuzzing redundant for that format
ADR-24 SIMD scalar core; SIMD batch behind feature SIMD in core determinism first; vectorize verified paths later SIMD-in-core wins when building a high-throughput inference or DSP pipeline where you control the platform (AVX-512 x86-64) and the scalar path's 10–100× overhead is unacceptable; acceptable if SIMD ops are verified against the scalar reference per vector
ADR-25 Build/CI cargo + GitHub Actions; TestFloat gate ad hoc Makefile + manual regression-proof Ad-hoc Makefile wins for a tiny embedded project with one developer and a private repo where CI infrastructure is unavailable or overkill; acceptable when the test suite is small enough to run manually before each release
ADR-26 Benchmarking criterion + cycle counts vs compiler-rt wall-clock timing only meaningful soft-float comparison Wall-clock wins when the library is never performance-critical (used only in unit tests, tooling, or low-frequency configuration paths) and the setup cost of criterion + perf counters is not warranted
ADR-27 Packaging crate (softfp) + CLI single binary (no library crate) reusable library Single-binary wins if the only use case is a standalone command-line tool for developers that will never be embedded as a library dependency — a valid choice for a one-off conformance checker
ADR-28 Licensing Apache-2.0 OR MIT GPL portfolio default; note SoftFloat BSD provenance GPL wins when the project is a standalone academic research tool not intended for embedding in commercial products, and the author wants to enforce open-source distribution of derivative works
ADR-29 Reproducibility bit-exact, platform-independent results allow platform variance a soft-float must be deterministic everywhere Allowing platform variance wins in a simulation or visualization tool where reproducibility across platforms is not required and targeting the native FPU (with its vendor-guaranteed IEEE conformance) is the simplest and fastest approach
ADR-30 const-eval ops usable in const fn where feasible runtime only compile-time constant folding Runtime-only wins when the ops rely on table lookups or division algorithms that Rust's const fn cannot express without unsafe or nightly features — acceptable until the stabilized const fn subset catches up

11. Core Schema and Core Types

Normative signatures; no bodies. The binary core uses NO hardware float; all arithmetic is integer/bit. Operations take and update an explicit FpContext (rounding mode + sticky flags).

// formats (storage newtypes over raw bit patterns)
struct Binary16(u16);  struct Binary32(u32);  struct Binary64(u64);  struct Binary128(u128);
struct Bfloat16(u16);
struct Decimal32(u32); struct Decimal64(u64); struct Decimal128(u128);

trait Float {                      // associated constants per format
  const EXP_BITS: u32; const SIG_BITS: u32; const BIAS: i32;
  const EMIN: i32; const EMAX: i32;
  fn classify(self) -> FpClass;
  fn unpack(self) -> Unpacked;
  fn pack(u: Unpacked, ctx: &mut FpContext) -> Self;   // normalizes + rounds + sets flags
}

enum FpClass { Zero{neg:bool}, Subnormal{neg:bool}, Normal{neg:bool},
               Infinity{neg:bool}, Nan{signaling:bool, payload:u128} }

struct Unpacked { sign: bool, exp: i32, sig: u128, g: bool, r: bool, s: bool }  // G/R/S = guard/round/sticky

enum RoundingMode { TiesToEven, TiesToAway, TowardPos, TowardNeg, TowardZero }
struct Flags(u8);                  // NV|DZ|OF|UF|NX sticky bits
struct FpContext { mode: RoundingMode, flags: Flags }

// binary ops (NO bodies) — each updates ctx.flags
fn add<T:Float>(a:T, b:T, ctx:&mut FpContext) -> T;
fn mul<T:Float>(a:T, b:T, ctx:&mut FpContext) -> T;
fn div<T:Float>(a:T, b:T, ctx:&mut FpContext) -> T;
fn sqrt<T:Float>(a:T, ctx:&mut FpContext) -> T;
fn fma<T:Float>(a:T, b:T, c:T, ctx:&mut FpContext) -> T;     // single rounding
fn compare<T:Float>(a:T, b:T) -> Option<Ordering>;          // None = unordered (NaN)

// decimal
enum DecimalEncoding { Bid, Dpd }
struct DecimalUnpacked { sign: bool, coeff: u128, exp: i32 }      // coeff = integer significand
struct BigDecimal { unscaled: BigInt /*#370*/, scale: i32 }       // arbitrary precision
enum RoundPolicy { HalfEven, HalfUp, HalfDown, Ceiling, Floor, Down, Up }
struct Money { amount: BigDecimal, currency: Currency, policy: RoundPolicy }
struct Currency { code: [u8;3], minor_units: u8 }                 // e.g., USD, 2

// errors are expressed as flags + value; conversions that cannot represent set NV/NX

Ownership: all value types are Copy/immutable; FpContext is mutated in place to accumulate sticky flags (per-thread or explicitly threaded — never a hidden global). BigDecimal/Money own heap BigInt. Serialization: binary formats serialize as their bit patterns; decimal as canonical strings; results are bit-exact and platform-independent (ADR-29).

12. Phase-by-Phase Implementation Plan

Fourteen phases (0–13). Each ends in a runnable/measurable artifact with explicit acceptance criteria; conformance is gated on Berkeley TestFloat (binary) and IBM decTest (decimal). No hardware float appears in the core at any phase.

Phase 0 — Repo skeleton + formats + pack/unpack/classify + GRS + FpContext

0.1 Objectives

Bootstrap workspace; define all format newtypes + Float constants; implement bit pack/unpack/classify and FpContext/Flags. No arithmetic yet.

0.2 Detailed Implementation Steps

[B1 Ch.2; B4 Ch.5; R7 format-newtypes; §8.1–8.3; ADR-02; ADR-04]

  • formats/ — Binary16/32/64/128, Bfloat16, Decimal32/64/128; per-format EXP_BITS/SIG_BITS/BIAS/EMIN/EMAX (B1 Ch.2 Table 3.1).
  • bits/classify.rs — classify() → FpClass from exponent/significand (zero, subnormal, normal, inf, qNaN/sNaN); quiet-bit = MSB of trailing significand (§8.2; I3).
  • bits/unpack.rs — decode to Unpacked{sign,exp,sig,g,r,s} (ADR-04); add implicit leading 1 for normals; exp = EMIN for subnormals (§8.3; I8); B4 Ch.5 for clz.
  • context/ — RoundingMode (5), Flags (NV/DZ/OF/UF/NX), FpContext (ADR-13; §8.4); sticky-OR invariant (I13; I17).
  • enforce no-hardware-float via scripts/no_hw_float_check.sh (greps core for f32/f64) as a CI gate (ADR-02; I12).

0.3 Deliverable

Library decodes/encodes bit patterns and classifies values for all formats; CLI inspect prints fields.

0.4 Acceptance Criteria

pack ∘ unpack identity for all non-rounding values; classify matches reference for ±0, ±inf, qNaN, sNaN, min/max normal, min/max subnormal.

0.5 Conformance Fixtures

formats/canonical_patterns.json (bit→class); roundtrip/decode_encode.json.

0.6 Pitfalls

(a) Dropping the implicit leading bit. (b) Losing sign of zero. (c) sNaN/qNaN convention (quiet bit = MSB of trailing significand). (d) Subnormal exponent off-by-one (use EMIN).

0.7 Performance Concerns

Pack/unpack are hot; branch-light; table-driven classify.

0.8 Edge Cases

Max exp + zero significand = inf vs NaN; NaN with zero payload must stay NaN; negative zero.

0.9 Failure Analysis

Misclassification cascades into every op; caught by canonical-pattern vectors.

0.10 Operational Notes

No runtime surface; CI gates on no-hw-float + classify vectors.

Phase 1 — Comparisons, sign ops, round-to-integral, special-value semantics

1.1 Objectives

Non-arithmetic operations: total/partial compare, copySign/abs/negate, roundToIntegral, and full NaN/inf/zero behavior. Establishes the special-value semantic contract that every arithmetic op in P3–P12 depends on.

1.2 Detailed Implementation Steps

[§8.2 value classes; §8.11 NaN details; §8.4 rounding modes; I3; I14; ADR-14]

  • binary/compare.rs — IEEE compare → Option<Ordering> (None = unordered when either is NaN; §8.11); −0 == +0 (I14; §8.16).
  • sign ops as pure bit manipulation (no flags except sNaN handling in some; I3; ADR-14).
  • binary/roundint.rs — round to integral value per mode (uses the P2 rounding unit's decision; §8.4; ADR-12).
  • special-value matrix: inf±inf, inf×0, comparisons with NaN, signed-zero division sign (Appendix D; I4; I5; I14).

1.3 Deliverable

Predicate/sign/round-to-integral API across formats.

1.4 Acceptance Criteria

TestFloat compare + roundToIntegral suites pass; −0 == +0 true but 1/−0 = −inf; any NaN compare = unordered.

1.5 Conformance Fixtures

testfloat/compare_*, testfloat/round_to_int_*.

1.6 Pitfalls

(a) Treating −0/+0 as unequal. (b) Signaling-NaN in compare not raising Invalid (quiet compares vs signaling compares). (c) Round-to-integral sign of zero result.

1.7 Performance Concerns

Compare is branch-heavy; consider total-order bit trick (flip for negatives).

1.8 Edge Cases

NaN vs NaN; inf vs inf; subnormal vs zero; round-to-integral of already-integral.

1.9 Failure Analysis

Wrong unordered handling breaks sort/min/max downstream; caught by compare vectors.

1.10 Operational Notes

Document the difference between quiet and signaling comparison predicates.

Phase 2 — Rounding unit (all five modes via GRS)

2.1 Objectives

A single, audited rounding component: given (sign, truncated significand, G, R, S, mode) decide truncate vs increment; the keystone every op depends on (ADR-12). Must be exhaustively tested before any arithmetic op is wired — a bug here corrupts every op uniformly (I2).

2.2 Detailed Implementation Steps

[B1 Ch.3 §3.3; B4 Ch.2 (branchless inc); §8.4 GRS table; §8.17 state table; ADR-12; I1; I2; I9]

  • bits/grs.rs — compute guard/round/sticky from discarded bits; sticky = OR of all bits below round (B1 Ch.3; I2; §8.4 two-bit simplification).
  • decision rule per mode (≤2-line): TiesToEven increments iff G ∧ (R ∨ S ∨ lsb) (I9 tie→even); TiesToAway iff G; TowardPos iff ¬sign ∧ (G∨R∨S); TowardNeg iff sign ∧ (G∨R∨S); TowardZero never; branchless via B4 Ch.2 boolean arithmetic.
  • post-increment carry → renormalize (significand overflow bumps exponent; §8.4 "carry-out" note); set Inexact iff G∨R∨S (I1 mechanism; ADR-12 central unit).
  • pack() (deferred from P0) now finalized using this unit; overflow→inf/max per mode (+OF+NX; I6), underflow→subnormal/0 (+UF when inexact; I7; B1 Ch.3 §3.5).

2.3 Deliverable

Standalone rounding unit with exhaustive small-width tests.

2.4 Acceptance Criteria

Exhaustive truth-table test over (sign,G,R,S,lsb,mode); round-half-even shows zero statistical bias on a uniform corpus.

2.5 Conformance Fixtures

fpgen/rounding_truth_table.json; overflow/underflow boundary cases.

2.6 Pitfalls

(a) Sticky not OR-ing all low bits. (b) Forgetting carry-out renormalization. (c) Underflow flag timing (raised on inexact subnormal result) — IEEE detail. (d) Double rounding if a value is rounded twice.

2.7 Performance Concerns

Branchless increment decision via boolean algebra; avoid per-bit loops for sticky (use masks).

2.8 Edge Cases

Increment overflowing to next binade; rounding a subnormal up to the min normal; rounding at EMAX → inf.

2.9 Failure Analysis

A rounding bug corrupts every arithmetic op uniformly; isolate via the standalone unit's vectors before wiring ops.

2.10 Operational Notes

This unit is the most-cited component; changes require full TestFloat re-run.

Phase 3 — Addition and subtraction (binary32/binary64)

3.1 Objectives

Correctly-rounded add/sub with exponent alignment, effective subtraction, cancellation, and sticky tracking. First op to exercise the P2 rounding unit in production; establishes the CI TestFloat gate pattern used by every subsequent arithmetic phase.

3.2 Detailed Implementation Steps

[§8.5 add/sub algorithm; B1 Ch.4 §4.1; R1 f64_add.c; B4 Ch.2 sticky-OR; ADR-12; I1; I14]

  • binary/add.rs/sub.rs — sort by exponent; shift the smaller significand right (capture G/R/S from shifted-out bits; B4 Ch.2 mask trick; I2); add or subtract aligned significands (§8.5 steps).
  • effective subtraction (opposite signs) → possible massive cancellation → leading-zero normalize left-shift, exponent down (§8.5 cancellation note; R1 f64_add.c leading-zero path; I1).
  • result sign rules incl. exact-zero results (x + (−x) → +0 except TowardNeg → −0; I14; §8.16 signed-zero).
  • finalize via P2 rounding unit (ADR-12); raise NX/OF/UF as applicable (I1; I6; I7).

3.3 Deliverable

add/sub for binary32/64 passing TestFloat.

3.4 Acceptance Criteria

f32_add, f64_add, f32_sub, f64_sub TestFloat suites pass across all 5 modes; 0.1 + 0.2 yields the correct binary64 value with Inexact set.

3.5 Conformance Fixtures

testfloat/f32_add_*, testfloat/f64_add_*, roundtrip/cancellation.json.

3.6 Pitfalls

(a) Losing sticky during alignment shift. (b) Wrong zero sign on exact cancellation. (c) One-bit overflow carry not renormalized. (d) Subnormal operand alignment.

3.7 Performance Concerns

Alignment shift + leading-zero count dominate; use hardware clz-style intrinsics on integers (not floats).

3.8 Edge Cases

inf+(−inf)=NaN+NV; x+0 sign rules; subnormal+subnormal → normal; huge exponent difference (result = larger operand, but NX from sticky).

3.9 Failure Analysis

Cancellation bugs surface as catastrophic precision loss; differential vs hardware flags them.

3.10 Operational Notes

Establish the per-op TestFloat CI gate here; record ulp histograms.

Phase 4 — Multiplication

4.1 Objectives

Correctly-rounded multiply via full-width significand product. Introduces the 2p-bit wide intermediate (ADR-05) and the sign-from-XOR rule; foundational for FMA (P7) which extends the same product without rounding.

4.2 Detailed Implementation Steps

[§8.6 multiply; B1 Ch.4 §4.2; B3 §4.3 schoolbook mul; ADR-05 u128; ADR-12; I1]

  • binary/mul.rs — significand product 2·SIG_BITS wide (u128 for binary64; ADR-05; B3 §4.3); exponent = ea + eb − bias adjustments (§8.6 step 3).
  • normalize the 2p product (leading bit at known position; B1 Ch.4 §4.2), capture G/R/S from the lower half, round via P2 rounding unit (ADR-12; I1).
  • sign = sa XOR sb; handle subnormal inputs (no implicit bit; I8); gradual-underflow output (I7; §6 Principle 6).
  • flags: OF when exponent > EMAX (I6), UF on inexact subnormal (I7), NX from rounding (I1).

4.3 Deliverable

mul for binary16/32/64 passing TestFloat.

4.4 Acceptance Criteria

f*_mul suites pass all modes; overflow→±inf+OF+NX; underflow→subnormal/0+UF.

4.5 Conformance Fixtures

testfloat/f32_mul_*, testfloat/f64_mul_*, subnormal-product cases.

4.6 Pitfalls

(a) Truncating the wide product before rounding (loses sticky). (b) Exponent bias double-subtraction. (c) Subnormal input normalization. (d) 0 × inf = NaN + NV.

4.7 Performance Concerns

Wide multiply is the cost; use u128 for ≤binary64, bignum only for binary128.

4.8 Edge Cases

±0 × finite; inf × 0; smallest×smallest → underflow to zero; largest×largest → overflow.

4.9 Failure Analysis

Lost low product bits cause off-by-1-ulp; differential ulp-diff harness catches.

4.10 Operational Notes

Track cycles vs compiler-rt __mulsf3/__muldf3.

Phase 5 — Division

5.1 Objectives

Correctly-rounded divide with an exact remainder to drive the sticky bit. Division is the slowest algebraic op and the hardest to get the last bit right; the remainder test (ADR-09) is the correctness mechanism (B7; I1).

5.2 Detailed Implementation Steps

[§8.7 divide; B7 div chapters; B1 Ch.5; P11 (Newton alt); ADR-09; I1; I5]

  • binary/div.rs — digit-recurrence restoring/SRT (B7 div chapters; B1 Ch.5) producing SIG_BITS+2 quotient bits plus a nonzero-remainder flag → sticky (ADR-09; I1 exact-remainder guarantee).
  • exponent = ea − eb + bias (§8.7 step 3); normalize quotient; round via P2 rounding unit (ADR-12).
  • flags: DZ when divisor is ±0 and dividend finite nonzero (→ ±inf; I5; §8.10); NV for 0/0 and inf/inf (I4).

5.3 Deliverable

div for binary16/32/64 passing TestFloat.

5.4 Acceptance Criteria

f*_div suites pass all modes; x/0 = ±inf + DivByZero; 0/0 = NaN + Invalid.

5.5 Conformance Fixtures

testfloat/f32_div_*, testfloat/f64_div_*, div-by-zero + 0/0 cases.

5.6 Pitfalls

(a) Stopping the recurrence one bit too early (no round/sticky info). (b) Remainder sign for sticky. (c) Subnormal quotient gradual underflow. (d) inf/inf and 0/0 both NaN+NV.

5.7 Performance Concerns

Division is the slowest op; SRT radix-4 reduces iterations; bound worst case.

5.8 Edge Cases

finite/inf = ±0; inf/finite = ±inf; subnormal/large → underflow; exact division (remainder 0 → no NX).

5.9 Failure Analysis

Quotient last-bit errors are classic; remainder-based sticky guarantees correctness — verify against TestFloat.

5.10 Operational Notes

Record divide latency distribution; it dominates tail latency.

Phase 6 — Square root

6.1 Objectives

Correctly-rounded sqrt via digit-recurrence with a remainder test. The remainder sign directly determines the round bit for the correctly-rounded result (ADR-10; I1); tie cases are rare but definitively resolved — no guessing.

6.2 Detailed Implementation Steps

[§8.8 sqrt; B7 sqrt chapters; B1 Ch.5; P11 (Newton alt); ADR-10; I1; I3]

  • binary/sqrt.rs — even-exponent adjustment (§8.8 step 2); digit-by-digit recurrence (B7 sqrt ch.; B1 Ch.5) producing SIG_BITS+2 bits; remainder sign → round decision (ADR-10; I1 remainder test).
  • domain: sqrt(−x) for x>0 → NaN+NV (I3; §8.8 special paths); sqrt(−0) = −0 (I14; §8.16); sqrt(+inf)=+inf (Appendix D).

6.3 Deliverable

sqrt for binary32/64 passing TestFloat.

6.4 Acceptance Criteria

f32_sqrt, f64_sqrt suites pass all modes; sqrt(2) correctly rounded; sqrt(−1)=NaN+NV.

6.5 Conformance Fixtures

testfloat/f32_sqrt_*, testfloat/f64_sqrt_*.

6.6 Pitfalls

(a) Odd-exponent handling (shift to make even). (b) Remainder sign for tie-breaking. (c) sqrt(−0) must be −0, not NaN. (d) Subnormal input scaling.

6.7 Performance Concerns

Digit recurrence is iterative; Newton converges faster but needs a correctly-rounded final step.

6.8 Edge Cases

Perfect squares (exact, no NX); subnormal radicands; sqrt(+inf); sqrt(+0)=+0.

6.9 Failure Analysis

Tie-rounding errors near half-ulp; remainder test resolves; differential check.

6.10 Operational Notes

sqrt + div share the recurrence engine; benchmark together.

Phase 7 — Fused multiply-add (single rounding)

7.1 Objectives

fma(a,b,c) computing a·b + c with exactly one rounding of the infinitely-precise result.

7.2 Detailed Implementation Steps

[§8.9 FMA; B1 Ch.4 §4.4; P2 Dekker error-free transform; ADR-11; ADR-05 wide intermediate; I10; I1]

  • binary/fma.rs — full-width 2p product (no rounding; ADR-11; I10; P2 Dekker exact-product reasoning); align c to the product's binary point in extended precision (§8.9 step 3; widest intermediate ADR-05); add/subtract; normalize; round once via P2 rounding unit (ADR-12; I1 single-rounding).
  • preserve all bits below the round position into the sticky during the addend alignment (B1 Ch.4 §4.4 sticky-through-alignment; I10 no intermediate rounding).

7.3 Deliverable

fma for binary32/64 passing TestFloat.

7.4 Acceptance Criteria

f32_mulAdd, f64_mulAdd suites pass; cases where mul-then-add double-rounds yield the correct single-rounded value here.

7.5 Conformance Fixtures

testfloat/f32_mulAdd_*, testfloat/f64_mulAdd_*, double-rounding witnesses.

7.6 Pitfalls

(a) Rounding the product before the add. (b) Addend alignment losing sticky. (c) Sign of zero in a·b + (−a·b). (d) Catastrophic cancellation after an exact product.

7.7 Performance Concerns

Widest intermediate of all ops; cost ≈ multiply + wide add; specialize per format.

7.8 Edge Cases

fma(0, inf, c) = NaN + NV; subnormal addend; exact product then cancellation; c = ±inf.

7.9 Failure Analysis

Double-rounding is the classic FMA bug; compare against a hardware fma oracle in tests.

7.10 Operational Notes

Document that the library never silently contracts a*b+c into fma except where requested.

8.1 Objectives

Integer↔float, float↔float (widen exact / narrow round), and extend all ops to binary16 and binary128 (bignum intermediates).

8.2 Detailed Implementation Steps

[§8.12 conversions; B5 Ch.5; ADR-05 u128/bignum; ADR-06 binary16/128; I16; I1]

  • convert/float_float.rs — widening is exact (no flags except sNaN→qNaN+NV; I3; §8.12); narrowing rounds via P2 (ADR-12) with OF/UF/NX (I6; I7; I16).

8.3 Deliverable

Full conversion matrix; binary16 + binary128 arithmetic.

8.4 Acceptance Criteria

TestFloat conversion suites ({i,ui}{32,64} ↔ f{16,32,64,128}) pass; widening exact; narrowing correctly rounded; binary128 add/mul/div/sqrt pass.

8.5 Conformance Fixtures

testfloat/*_to_*, testfloat/f128_*.

8.6 Pitfalls

(a) float→int overflow handling (saturate + Invalid, not wrap). (b) Rounding large int→float. (c) Subnormal results on narrowing. (d) Undersized binary128 intermediate.

8.7 Performance Concerns

binary128 uses bignum (slower); keep binary32/64 on u128 fast paths.

8.8 Edge Cases

float→int of NaN/inf (NV + defined result); INT_MIN; widening preserves NaN payload; subnormal narrowing to zero.

8.9 Failure Analysis

Conversion rounding/saturation errors; differential vs hardware casts.

8.10 Operational Notes

Phase 9 — Float ↔ string (correctly-rounded parse + shortest print)

9.1 Objectives

strtod-correct decimal→binary parsing and shortest round-tripping binary→decimal printing (Ryū), with a Dragon4 fallback.

9.2 Detailed Implementation Steps

Operational Readiness

As a library the "operational" surface is its test/CI dashboards and the per-call diagnostics:

  • Runbooks: result-differs-from-hardware.md (capture (op,a,b,mode), diff GRS), flag-mismatch.md (UF/NX timing), dtoa-roundtrip-failure.md (shortest-output triage).
  • Deployment: embeds as a crate; no service to operate; reproducible across platforms by construction.

Compatibility Guarantees

  • Bit-format compatibility: binary16/32/64/128 and decimal32/64/128 bit patterns are IEEE-754 conformant and interoperate with any conformant implementation.
  • Decimal encodings: both BID and DPD decode accepted; canonical form emitted on encode; BID↔DPD round-trips.
  • Bit-exact result stability: results are deterministic and platform-independent; a documented op never changes its rounding/flags across minor versions (ADR-29).
  • API stability: semantic versioning; the softfp crate public API is stable within a major; internal crates may evolve.
  • dtoa output: the canonical shortest-decimal format is frozen; changes are major-version events.
  • Deprecation: removing/altering a rounding behavior is a major-version change announced one release ahead.

Testing Strategy

  • Berkeley TestFloat: the primary oracle — every binary op × every format × all five rounding modes, including flags; gated in CI.
  • IBM decTest: the decimal oracle for arithmetic, rounding, encoding, and quantize.
  • FPgen / corner cases: generator-produced hard cases (halfway, subnormal boundaries, overflow edges).
  • Differential vs hardware: a test-only harness (harness/oracle.rs, the sole place hardware f32/f64/f128 is permitted) compares ulp error and flags.
  • Property tests: parse∘format identity, add/mul commutativity, monotonicity of rounding, FMA single-rounding, decimal total conservation in Money.
  • Exhaustive (where feasible): binary16 add/mul over all 2^16 × 2^16 pairs; all binary16 sqrt/conversions.
  • Fuzzing: op_binary (random op vs oracle), parse_decimal, decode_format; ≥ 24 h nightly; ASAN.
  • No-hardware-float gate: static check that core crates contain no f32/f64.

Build and Release Engineering

  • SBOM + signing: generated per release; artifacts signed; provenance attested.
  • Dependency audit: cargo-deny/cargo-audit; the only runtime dependency is the #370 bignum crate (for binary128/decimal/arbitrary-precision).
  • CI topology: build/test/lint matrix (std/no_std), TestFloat shard jobs, decTest job, fuzz-smoke per PR, release job.
  • Provenance: record SoftFloat/decTest vector corpus SHAs used for each conformance run.

Performance Engineering

  • Cost model: soft-float is inherently 10–100× slower than hardware; division and square root dominate; binary128/decimal add bignum cost.
  • Optimizations: table-driven leading-zero/normalize; branchless GRS rounding; specialize binary32/64 on u128 fast paths; avoid bignum except for binary128/decimal; cache powers of ten for decimal scaling; SIMD batch behind a feature flag for verified paths.
  • Benchmarks: criterion + cycle counts per op/format; compare against compiler-rt builtins (__adddf3, __divdf3, …).
  • Targets: within a small constant factor of compiler-rt for binary32/64 basic ops; documented ulp = 0 (correctly rounded).

Scalability Analysis

  • Per-op cost scales with significand width: binary16/32/64 are u128-bounded; binary128 and decimal use wide/bignum arithmetic.
  • Arbitrary-precision decimal grows with digit count: BigDecimal working precision must be bounded by policy to avoid blowup.
  • Bottlenecks: divide and sqrt (iterative), bignum multiply (binary128/decimal), and dtoa hard cases.
  • Throughput: embarrassingly parallel across independent operations; SIMD batching is the main vectorization lever; no shared mutable state (with explicit FpContext).
  • Digit-recurrence scaling: div/sqrt require p + 2 iterations (p = format precision bits); binary64 needs 55 iterations, binary128 needs 115 — roughly 2× more work, plus wider integer arithmetic per step. SRT radix-4 halves the iteration count at the cost of a more complex quotient-digit selection table.
  • Conformance test scaling: TestFloat binary32 exhaustive add is 2^48 ≈ 3 × 10^{14} pairs — infeasible; TestFloat uses random + structured sampling (~10^8 vectors) to achieve practical coverage. Binary16 is exhaustive at 2^32 = 4.3 × 10^9 pairs, feasible at ~43 s. (Back-of-Envelope items 6–7.)
  • BigDecimal scale blowup: division of a k-digit value by an m-digit value to n result digits costs O(n × (k+m)) with schoolbook bignum multiply, or O((k+m+n) log(k+m+n)) with FFT-based multiplication from #370. For the money use case (k, m ≤ 34 digits), schoolbook is faster; unbounded-precision scientific use triggers the FFT path.
  • Concurrency: no shared state means the library scales linearly with thread count; each thread passes its own FpContext; the only contention is in any shared BigInt allocator from #370 (controlled by that library's allocator policy).

Mental Models & First Principles

MM1. A float is a triple, not a number. Every IEEE value is (sign, biased_exp, trailing_sig). All behavior — special values, subnormals, NaN payloads — follows from the bit fields; no "floating point is magic" thinking survives once you hold the triple. Predicts: you can construct any NaN payload or signed zero on demand. Bug class without it: conflating "NaN" as a single object; surprised by sNaN vs qNaN; losing −0. Resolving sections: §8.1–8.2, P0.

MM2. Guard/round/sticky make one extra bit sufficient for exact rounding. Three bits below the kept significand represent all information needed for any algebraic op: G is the first discarded bit, R the second, S the OR of all remaining. No matter how long the exact result, the rounding decision is the same as if you had computed it to infinite precision. Predicts: you never need to widen the intermediate beyond 2p + 3 bits. Bug class without it: truncating early, losing sticky, producing off-by-1-ulp results that pass casual tests and fail TestFloat. Resolving sections: §8.4, P2, I2.

MM3. The rounding unit is the single source of truth. Every op must funnel its discarded bits through one GRS unit; any per-op shortcut that re-derives the increment rule independently will drift. Predicts: bugs in rounding will appear consistently across all ops; fixing one place fixes all. Bug class without it: each op has a slightly different GRS computation; RNE tie-to-even works for add but not for mul, causing conformance failures that look op-specific. Resolving sections: §6 Principle 12, ADR-12, P2.

MM4. FMA rounds exactly once — the key differentiator from mul; add. The full 2p-bit product is never rounded before the addend is aligned; only the final combined value sees the rounding unit. Double-rounding (rounding a×b, then adding c) gives a different bit pattern in about 1 in 2^(p+1) cases. Predicts: a mul; add emulation will produce ~1 wrong last bit per 2^53 cases for binary64 — rare enough to pass most hand tests, caught only by a systematic differential. Bug class without it: implementing FMA as mul-then-add, passing 99.999999% of tests, failing just enough for a compiler that depends on it to constant-fold wrong. Resolving sections: §8.9, §6 Principle 7, ADR-11, P7, I10.

MM5. Subnormals are the continuity property, not an edge case. The transition from smallest normal to zero is gradual; without subnormals the gap between 0 and min_normal would be 2^(emin−1) times larger than the gap between adjacent normals. This is not a quirk — it is what makes |a − b| = 0 ⟹ a = b true for finite floats. Bug class without it: flush-to-zero quietly corrupts subtraction near emin; max_subnormal + 1_ulp silently returns wrong normal. Resolving sections: §6 Principle 6, §8.16 max-subnormal boundary, I7, P0 (classify), P2 (pack underflow path).

MM6. Decimal is exact in base-10; binary is not. 0.1 is not representable in binary but is trivially coeff=1, exp=−1 in decimal. This is not imprecision but a property of the base. Predicts: any financial system using binary float will have systematic penny rounding errors over repeated transactions. Bug class without it: using f64 for currency, noticing test failures only at aggregate level. Resolving sections: §6 Principle 8, §8.15 money example, P11–P12.

MM7. Exception flags are monotone sticky state, not exceptions. NV/DZ/OF/UF/NX bits only set, never clear implicitly; they accumulate across a computation. An explicit FpContext.clear() call is the only reset. Predicts: after a sequence of ops, any bit set means at least one op raised it — a composition property that makes audit straightforward. Bug class without it: checking flags mid-computation, missing a raised NX from a subnormal intermediate, or being surprised that a subsequent exact op doesn't clear Inexact. Resolving sections: §8.10, §6 Principle 3, ADR-13, I13, I17.

MM8. Correct rounding via remainder is a decision, not a measurement. For div and sqrt, the correctly-rounded result is determined by asking: is the exact real result above, below, or exactly at the midpoint between two adjacent floats? A nonzero remainder after p+2 bits definitively answers "not at the midpoint" and determines the round direction. Computing a remainder sign is O(1) — vastly cheaper than extended-precision computation. Bug class without it: stopping digit-recurrence at p bits, guessing the round direction, producing 1-ulp errors that defeat the spec. Resolving sections: §8.7 (div), §8.8 (sqrt), ADR-09, ADR-10, P5–P6.

MM9. Bit-exact soft-float is an integer computation with a specification. Every arithmetic result is determined by the IEEE-754 standard to the last bit; there is no approximation or "numerical" ambiguity — only correct and wrong. Predicts: differential testing against any conformant implementation (hardware or another soft-float) should give ulp error = 0 for every correctly-implemented op. Bug class without it: treating ±1 ulp as "close enough," accepting a library that gives wrong last bits on div/sqrt, silently corrupting dependent systems (constant folding, FPU-less MCU). Resolving sections: §1, §4 (conformance row), §6 Principle 1, P13, I1.

MM10. The cohort is the decimal identity, not the encoding. In decimal arithmetic, 1.0, 1.00, and 100×10⁻² are the same value in different representations (the "cohort"). Equal-value members of a cohort compare equal and participate in arithmetic as if they were one value; only the "quantum" (preferred exponent) governs the output representation. Bug class without it: treating two BID encodings of 1.0 as unequal, producing decTest failures on compare and quantize, or picking the wrong ideal exponent. Resolving sections: §8.13, §8.11 (decimal cohort), I11, P10, P11.

Berkeley SoftFloat (Hauser, UCB): the reference implementation this project mirrors. Its key differentiation is extreme minimalism — it targets the smallest possible C footprint for hardware emulation. It uses a single global rounding-mode variable (softfloat_roundingMode), which makes it non-reentrant and non-deterministic under concurrent use. This wins in firmware/QEMU contexts where a single thread controls the FP environment and code size is paramount.

LLVM compiler-rt: optimized for the ABI contract — the compiler emits __adddf3 call sites; compiler-rt must match the ABI calling convention and link into any binary. It does not expose a rounding-mode API; the caller's C fenv state governs. Wins when you need the minimum possible binary size for compiler-generated soft-float calls with no explicit mode control.

Intel BID library (IntelRDFPMathLib): the production decimal implementation targeting Intel x86-64. Exploits SSE2/AVX for coefficient arithmetic, making it 5–10× faster than a scalar BID implementation. Its architecture is a large machine-generated table plus hand-tuned assembly kernels. Wins when you need the fastest possible IEEE decimal on Intel hardware and accept the non-portable generated tables and Intel-specific license.

Java BigDecimal / MathContext: the closest match to the Money path, but not IEEE 754 decimal. BigDecimal is an arbitrary-precision base-10 type with MathContext controlling precision and rounding, not IEEE 754 decimal32/64/128 interchange. It wins in Java ecosystems with existing BigDecimal contracts and where IEEE decimal interchange format compatibility is not required.

Back-of-Envelope Capacity Model

All numbers derived from the System Constraints table (§4). Formula shown for each.

1. binary64 significand intermediate width. Formula: 2 × p = 2 × 53 = 106 bits. Needed for full multiply product. Fits in u128 (128 bits) with 22 bits to spare — no bignum needed. (§4: "Wide-intermediate sizing": mul needs 2p-bit product; ADR-05.)

2. FMA accumulator width (binary64). Formula: 2p + alignment_headroom = 106 + ~10 bits alignment + 3 GRS = ~120 bits. Fits in u128; for binary128 (p=113): 2×113 + 10 + 3 = 239 bits → requires u256 or bignum. (§4 FMA row; ADR-05.)

3. binary128 multiply product width. Formula: 2 × 113 = 226 bits. Next power-of-2 container = u256 (256 bits, 30 bits overhead) or a 4-limb u64 bignum from #370. (§4; ADR-05.)

4. Decimal64 coefficient size. Formula: max p = 16 decimal digits; log2(10^16) ≈ 16 × 3.32 = 53.1 bits. Fits in a u64 (64 bits); BID stores it as a plain u64. (§8.13 decimal64 row; ADR-08.)

5. Decimal128 coefficient size. Formula: max p = 34 decimal digits; log2(10^34) ≈ 34 × 3.32 = 112.9 bits. Requires u128 (128 bits, 15 bits to spare). (§8.13 decimal128 row; ADR-05 bignum fallback optional.)

6. TestFloat vector volume (binary32 exhaustive add). Formula: 2^24 significand values × 2^24 = 2^48 ≈ 2.8 × 10^14 pairs. At ~100 M ops/s soft-float, this is 2.8 × 10^6 seconds — not feasible exhaustively. TestFloat samples ~10^8 random + structured vectors → reduces to ~1 s. (§4 Conformance row; Appendix H; R2 methodology.)

7. binary16 exhaustive add volume. Formula: 2^16 × 2^16 = 2^32 ≈ 4.3 × 10^9 pairs. At 100 M ops/s: 43 seconds. Feasible (Appendix H M2 milestone). (§4; Appendix B M2.)

8. Soft-float throughput estimate vs hardware. Formula: hardware binary64 add ≈ 1 cycle at 3 GHz = 0.33 ns; soft-float add ≈ 30–100 cycles (alignment + normalize + GRS) → 10–33 ns, i.e., 30–100× slower. (§4 Throughput row; §6 Principle 2 tradeoff.)

9. BigDecimal precision for Money. Formula: a sum of N transactions each up to 10^15 USD (absurd upper bound): needs 15 + log10(N) digits of precision. For N = 10^9 transactions: 15 + 9 = 24 digits; fits comfortably in decimal128 (34 digits). BigDecimal is unbounded — uses bignum only when decimal128 overflows. (§8.14; ADR-17.)

10. DPD declet count for decimal128. Formula: p = 34 digits; MSD handled separately in combination field; remaining 33 digits → 33 / 3 = 11 declets × 10 bits = 110 bits. Matches the t = 110 row in §8.13. (§8.13 decimal128 row; ADR-08.)

11. Memory per FpContext. Formula: RoundingMode (3 bits) + Flags (5 bits) = 8 bits = 1 byte; padded to natural alignment: likely 2 bytes in practice. Zero heap. Confirms §4 "Memory — binary core: no heap". (ADR-13; §4.)

12. Fuzz corpus coverage estimate. Alternative Architectures (Roads Not Taken)

Alt-A: Hardware-Float-Assisted with Fixup

  inputs (f32/f64)
       │
       ▼
  hardware FPU op (f64 add/mul/div/sqrt)
       │  ~1 ulp result
       ▼
  residual computation: r = exact(a op b) − hw_result
       │  using Dekker/Veltkamp splitting or FMA-based error
       ▼
  round-direction fixup (remainder sign → 0 or 1 ulp adjust)
       │
       ▼
  correctly-rounded output

Regime where this wins: Platforms with a fast IEEE-754-compliant FPU (x86-64 SSE2, ARMv8). The hardware does 53-bit significant arithmetic in 1–4 cycles; the fixup adds 5–15 cycles of integer math. Total: ~20 cycles vs ~100 cycles for a pure integer path. Used by Markstein (P11) for IA-64. Requires: the hardware FPU be IEEE-754 compliant (no x87 80-bit extended surprises), the fixup be verified for all cases. Real system: glibc __ieee754_sqrt on x86-64 uses hardware SQRTSD + a single Newton correction. This blueprint rejects it because (a) requires FPU — fails on FPU-less embedded (§4); (b) non-trivial to audit for correctness; (c) ADR-02 (no hardware float in core) is an explicit design principle.

Alt-B: Posit / Type-III Arithmetic (John Gustafson's Unum)

  posit(n, es) encoding:
  [s | regime (k ones + 0) | exponent (es bits) | fraction]
       │
       ▼
  posit-native add: tapered precision, no inf, one NaN ("NaR")
       │
       ▼
  result: smaller error for values near ±1; larger error near 0/∞

Regime where this wins: Experimental scientific computing where the IEEE "wasteful" exponent range near extremes is undesirable; applications where "no infinity, only NaR" simplifies error handling; research into alternative FP representations. The posit scheme uses a variable-length "regime" field to achieve higher precision for values near 1.0 and trades it off near 0 and ∞. Real system: John Gustafson's Posit Arithmetic standard; SoftPosit library. This blueprint rejects it because (a) IEEE 754-2019 is the universal standard — every compiler, hardware, and interchange format expects binary/decimal IEEE; (b) money applications require decimal, not posit; (c) a soft-float library's primary purpose is IEEE conformance, not exploring alternatives.

Alt-C: Interval Arithmetic Core

  Interval = [lo, hi] where lo ≤ exact_value ≤ hi
       │
       ▼
  interval_add([a_lo,a_hi], [b_lo,b_hi]) = [RTN(a_lo+b_lo), RTP(a_hi+b_hi)]
       │  two soft-float ops with directed rounding per add
       ▼
  result width = certified error bound; width = 0 → exact

Regime where this wins: Verified numerical computation — scientific simulations where you need a proof that the computed result lies within a given error bound (e.g., global optimization, proof assistants, interval Newton methods). Every operation is two directed-rounding soft-float calls, giving a certified bound. Real system: INTLAB (MATLAB), Arb (C, arbitrary-precision intervals), boost::numeric::interval. This blueprint rejects it because (a) doubles operation cost; (b) IEEE 754 standard does not define interval types — this would be an extension above the library, not the library itself; (c) the target users (compiler back-ends, embedded, finance) do not require interval output — they require bit-exact scalars.

Alt-D: SIMD-First Batch Soft-Float

  8× binary32 values packed in AVX2 __m256i
       │
       ▼
  parallel unpack: VPAND/VPSR/VPCMPEQ (8 lanes)
       │
       ▼
  aligned add (8 lanes, variable shift per lane via VPSRLVD)
       │
       ▼
  parallel GRS + rounding (VPAND/VPCMPEQ on low bits)
       │
       ▼
  8× result packed, flags OR'd across lanes

Regime where this wins: Bulk inference pipelines (language model weight quantization, physics simulation batches) where you process thousands of binary32 values per frame and a scalar reference validated the semantics. SIMD batch yields 4–8× throughput recovery vs scalar soft-float for binary32/64. Real system: Intel's _mm256_* soft-float approximations in production ML frameworks; custom operator implementations in torch.compile backends targeting FPU-less or constrained hardware. This blueprint rejects it because (a) SIMD in the core breaks the correctness-first, FPU-less guarantee (ADR-24); (b) SIMD lanes would prevent the per-value FpContext flags model; (c) design explicitly separates scalar-correct core from SIMD batch (feature flag, deferred), consistent with ADR-24.

Glossary

  • IEEE-754 — the standard for floating-point arithmetic (2008/2019).
  • binary32/64/128 — single/double/quad binary interchange formats.
  • decimal32/64/128 — decimal interchange formats.
  • bfloat16 — 8-bit-exponent 16-bit float used in ML.
  • significand (mantissa) — the fraction part of a float.
  • exponent — the scale; stored biased.
  • bias — constant added to the true exponent for storage.
  • implicit (hidden) bit — the leading 1 of a normal significand, not stored.
  • subnormal (denormal) — values below the smallest normal, with gradual underflow.
  • gradual underflow — representing tiny values via subnormals instead of flushing to zero.
  • signed zero — +0 and −0 are distinct (1/−0 = −inf).
  • infinity — ±inf, the overflow/limit value.
  • qNaN / sNaN — quiet vs signaling Not-a-Number.
  • NaN payload — the significand bits of a NaN, propagated by ops.
  • guard bit (G) — first bit beyond the kept significand.
  • round bit (R) — second bit beyond.
  • sticky bit (S) — OR of all remaining lower bits.
  • GRS — guard/round/sticky, the basis of correct rounding.
  • ulp — unit in the last place; the spacing between adjacent floats.
  • correct rounding — result is the representable value nearest the exact answer (≤ 0.5 ulp).
  • round-half-even (banker's) — ties go to the even last digit; unbiased; the default.
  • round-half-away — ties round away from zero.
  • round-toward-zero / +∞ / −∞ — directed rounding modes.
  • exception flags — Invalid (NV), DivByZero (DZ), Overflow (OF), Underflow (UF), Inexact (NX).
  • FMA — fused multiply-add with a single rounding.
  • double rounding — rounding twice (e.g., to extended then to target), which can give a wrong result.
  • normalization — shifting the significand so the leading bit is in the canonical position.
  • cohort — the set of decimal representations of one value (different exponents).
  • BID — binary integer decimal encoding (integer significand).
  • DPD — densely packed decimal encoding (declets).
  • declet — 10 bits encoding 3 decimal digits.
  • fixed-point — integer scaled by a fixed power (Q-format).
  • Q-format — fixed-point notation Qm.n.
  • BigDecimal — arbitrary-precision decimal (unscaled × 10^−scale).
  • dtoa — float-to-decimal-string conversion.
  • Ryū — a fast shortest-round-trip dtoa algorithm.
  • Dragon4 — a classic exact dtoa algorithm.
  • Dekker / double-double — representing extra precision as a pair of floats.
  • soft-float — floating-point implemented in integer software, no FPU.
  • quantum / quantize — the exponent/scale a decimal result should carry.
  • minor unit — the smallest currency denomination (cents).
  • largest-remainder allocation — splitting a sum so rounded parts conserve the total.
  • FpContext — explicit rounding-mode + sticky-flags state threaded through ops.
  • TestFloat / decTest — the standard conformance test corpora.
  • emin / emax — the minimum/maximum exponents of a format.
  • binade — the range of floats sharing one exponent ([2^e, 2^{e+1})).
  • quantum — the value of a unit in the last place of a decimal at a given exponent.
  • rescale / quantize — adjust a decimal's exponent to a target, rounding the coefficient.
  • declet — 10-bit DPD group encoding three decimal digits.
  • ideal exponent — decTest's preferred result exponent for an exact decimal operation.
  • error-free transform — an operation pair recovering the exact rounding error (TwoSum, TwoProduct).
  • Sterbenz interval — operand ratio range guaranteeing exact subtraction.
  • table-maker's dilemma — the unbounded-precision problem for correctly rounding transcendentals.
  • saturation — clamping an out-of-range conversion to the representable extreme (with Invalid).
  • canonical encoding — the unique preferred bit pattern emitted for a decimal value.

Appendix E — Numerical Hazards and Identities

Implementation- and caller-relevant properties; the library guarantees correct rounding, but callers must understand these to use it safely.

  • Catastrophic cancellation — subtracting nearly equal values amplifies prior rounding error; the subtraction itself is exact (correctly rounded) but the inputs' error dominates. Mitigation lives in caller algorithms (reformulation), not in the op.
  • Sterbenz lemma — for finite a,b with a/2 ≤ b ≤ 2a, a−b is computed exactly (no rounding). Useful invariant for argument-reduction tests.
  • Compensated (Kahan) summation — recovers the rounding error of each add via a correction term; the building blocks (TwoSum, TwoProduct via FMA) are expressible with the correctly-rounded ops here. Provided as an example, not a core op.
  • TwoSum / FastTwoSum — exact error-free transforms: s = a+b, e = (a−(s−b))+(b−(s−(s−b))); relies on correct rounding (P3) — used in extended-precision examples.
  • TwoProduct — p = a×b, e = fma(a,b,−p) recovers the product's rounding error exactly (requires FMA, P7).
  • Table-maker's dilemma — correctly rounding transcendentals can require unbounded intermediate precision near halfway points; this is why correctly-rounded exp/log/sin are deferred (a stretch phase), while the algebraic ops (±,×,÷,√,FMA) are always correctly rounded.
  • Monotonicity — the basic ops are monotonic in each argument; rounding modes preserve order; tests assert this property.
  • Double rounding — rounding to a wider format then to the target can differ from rounding once to the target; avoided by computing each op directly at target precision (and single-rounded FMA).
  • Decimal exactness — decimal arithmetic represents base-10 fractions exactly (0.1, 0.2), which binary cannot; the reason money uses the decimal/Money path.
  • Cohorts — in decimal, 1.0, 1.00, 1.000 are equal in value but differ in exponent (quantum); operations follow decTest "ideal exponent" rules to choose the result's quantum.

Appendix I — Per-Operation Algorithm Step Reference

High-level step outlines (not source) that each implementation phase realizes; every step preserves guard/round/sticky and finalizes through the Phase-2 rounding unit.

I.1 Add / Subtract (Phase 3).

  • Unpack both operands; handle NaN/inf/zero specials first (Appendix D).
  • Compare exponents; right-shift the smaller significand by the exponent difference, accumulating shifted-out bits into G/R/S.
  • For like signs add significands; for unlike signs subtract (effective subtraction) and take the magnitude.
  • Normalize: left-shift on cancellation (exponent down) or right-shift one place on carry-out (exponent up), updating G/R/S.
  • Round via the rounding unit; set sign of an exact-zero result per the mode; raise NX/OF/UF.

I.2 Multiply (Phase 4).

  • Unpack; resolve specials (0×inf → NaN+NV).
  • Compute the 2p-bit significand product and exp = ea + eb − bias; adjust for subnormal inputs.
  • Normalize the product (leading bit position is one of two places); capture G/R/S from the low half.
  • Round; sign = sa XOR sb; raise OF/UF/NX.

I.3 Divide (Phase 5).

  • Unpack; resolve specials (x/0 → ±inf+DZ; 0/0,inf/inf → NaN+NV).
  • Digit-recurrence produces p+2 quotient bits plus a nonzero-remainder flag → sticky; exp = ea − eb + bias.
  • Normalize the quotient; round; raise DZ/NV/OF/UF/NX.

I.4 Square root (Phase 6).

  • Unpack; resolve specials (sqrt(−x) → NaN+NV; sqrt(−0)=−0).
  • Make the exponent even (shift radicand); digit-recurrence yields p+2 bits + remainder sign for rounding.
  • Normalize (exponent halved); round; raise NV/NX.

I.5 Fused multiply-add (Phase 7).

  • Unpack all three; resolve specials.
  • Form the exact 2p product; align the addend to the product's binary point in extended precision; add/subtract.
  • Normalize; round once; raise NV/OF/UF/NX. No intermediate rounding.

I.6 Conversions (Phase 8).

  • int → float: form magnitude, normalize, round to target precision (NX/OF).
  • float → int: shift by exponent; out-of-range or NaN/inf → saturate + NV; apply directed rounding for round-to-int variants.
  • float → float: widening copies exactly (sNaN→qNaN+NV); narrowing rounds with OF/UF/NX.
