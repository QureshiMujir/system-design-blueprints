⬜ Phase 0 — Repo skeleton + formats + pack/unpack/classify + GRS + FpContext

Objectives

Bootstrap workspace; define all format newtypes + Float constants; implement bit pack/unpack/classify and FpContext/Flags. No arithmetic yet.

Deliverable

Library decodes/encodes bit patterns and classifies values for all formats; CLI inspect prints fields.

Acceptance

pack ∘ unpack identity for all non-rounding values; classify matches reference for ±0, ±inf, qNaN, sNaN, min/max normal, min/max subnormal.

Fixtures

formats/canonical_patterns.json (bit→class); roundtrip/decode_encode.json.

Pitfalls

(a) Dropping the implicit leading bit. (b) Losing sign of zero. (c) sNaN/qNaN convention (quiet bit = MSB of trailing significand). (d) Subnormal exponent off-by-one (use EMIN).

⬜ Phase 1 — Comparisons, sign ops, round-to-integral, special-value semantics

Objectives

Non-arithmetic operations: total/partial compare, copySign/abs/negate, roundToIntegral, and full NaN/inf/zero behavior. Establishes the special-value semantic contract that every arithmetic op in P3–P12 depends on.

Deliverable

Predicate/sign/round-to-integral API across formats.

Acceptance

TestFloat compare + roundToIntegral suites pass; −0 == +0 true but 1/−0 = −inf; any NaN compare = unordered.

Fixtures

testfloat/compare_*, testfloat/round_to_int_*.

Pitfalls

(a) Treating −0/+0 as unequal. (b) Signaling-NaN in compare not raising Invalid (quiet compares vs signaling compares). (c) Round-to-integral sign of zero result.

⬜ Phase 2 — Rounding unit (all five modes via GRS)

Objectives

A single, audited rounding component: given (sign, truncated significand, G, R, S, mode) decide truncate vs increment; the keystone every op depends on (ADR-12). Must be exhaustively tested before any arithmetic op is wired — a bug here corrupts every op uniformly (I2).

Deliverable

Standalone rounding unit with exhaustive small-width tests.

Acceptance

Exhaustive truth-table test over (sign,G,R,S,lsb,mode); round-half-even shows zero statistical bias on a uniform corpus.

Fixtures

fpgen/rounding_truth_table.json; overflow/underflow boundary cases.

Pitfalls

(a) Sticky not OR-ing all low bits. (b) Forgetting carry-out renormalization. (c) Underflow flag timing (raised on inexact subnormal result) — IEEE detail. (d) Double rounding if a value is rounded twice.

⬜ Phase 3 — Addition and subtraction (binary32/binary64)

Objectives

Correctly-rounded add/sub with exponent alignment, effective subtraction, cancellation, and sticky tracking. First op to exercise the P2 rounding unit in production; establishes the CI TestFloat gate pattern used by every subsequent arithmetic phase.

Deliverable

add/sub for binary32/64 passing TestFloat.

Acceptance

f32_add, f64_add, f32_sub, f64_sub TestFloat suites pass across all 5 modes; 0.1 + 0.2 yields the correct binary64 value with Inexact set.

Fixtures

testfloat/f32_add_*, testfloat/f64_add_*, roundtrip/cancellation.json.

Pitfalls

(a) Losing sticky during alignment shift. (b) Wrong zero sign on exact cancellation. (c) One-bit overflow carry not renormalized. (d) Subnormal operand alignment.

⬜ Phase 4 — Multiplication

Objectives

Correctly-rounded multiply via full-width significand product. Introduces the 2p-bit wide intermediate (ADR-05) and the sign-from-XOR rule; foundational for FMA (P7) which extends the same product without rounding.

Deliverable

mul for binary16/32/64 passing TestFloat.

Acceptance

f*_mul suites pass all modes; overflow→±inf+OF+NX; underflow→subnormal/0+UF.

Fixtures

testfloat/f32_mul_*, testfloat/f64_mul_*, subnormal-product cases.

Pitfalls

(a) Truncating the wide product before rounding (loses sticky). (b) Exponent bias double-subtraction. (c) Subnormal input normalization. (d) 0 × inf = NaN + NV.

⬜ Phase 5 — Division

Objectives

Correctly-rounded divide with an exact remainder to drive the sticky bit. Division is the slowest algebraic op and the hardest to get the last bit right; the remainder test (ADR-09) is the correctness mechanism (B7; I1).

Deliverable

div for binary16/32/64 passing TestFloat.

Acceptance

f*_div suites pass all modes; x/0 = ±inf + DivByZero; 0/0 = NaN + Invalid.

Fixtures

testfloat/f32_div_*, testfloat/f64_div_*, div-by-zero + 0/0 cases.

Pitfalls

(a) Stopping the recurrence one bit too early (no round/sticky info). (b) Remainder sign for sticky. (c) Subnormal quotient gradual underflow. (d) inf/inf and 0/0 both NaN+NV.

⬜ Phase 6 — Square root

Objectives

Correctly-rounded sqrt via digit-recurrence with a remainder test. The remainder sign directly determines the round bit for the correctly-rounded result (ADR-10; I1); tie cases are rare but definitively resolved — no guessing.

Deliverable

sqrt for binary32/64 passing TestFloat.

Acceptance

f32_sqrt, f64_sqrt suites pass all modes; sqrt(2) correctly rounded; sqrt(−1)=NaN+NV.

Fixtures

testfloat/f32_sqrt_*, testfloat/f64_sqrt_*.

Pitfalls

(a) Odd-exponent handling (shift to make even). (b) Remainder sign for tie-breaking. (c) sqrt(−0) must be −0, not NaN. (d) Subnormal input scaling.

⬜ Phase 7 — Fused multiply-add (single rounding)

Objectives

fma(a,b,c) computing a·b + c with exactly one rounding of the infinitely-precise result.

Deliverable

fma for binary32/64 passing TestFloat.

Acceptance

f32_mulAdd, f64_mulAdd suites pass; cases where mul-then-add double-rounds yield the correct single-rounded value here.

Fixtures

testfloat/f32_mulAdd_*, testfloat/f64_mulAdd_*, double-rounding witnesses.

Pitfalls

(a) Rounding the product before the add. (b) Addend alignment losing sticky. (c) Sign of zero in a·b + (−a·b). (d) Catastrophic cancellation after an exact product.

⬜ Phase 8 — Conversions + binary16/binary128

Objectives

Integer↔float, float↔float (widen exact / narrow round), and extend all ops to binary16 and binary128 (bignum intermediates).

Deliverable

Full conversion matrix; binary16 + binary128 arithmetic.

Acceptance

TestFloat conversion suites ({i,ui}{32,64} ↔ f{16,32,64,128}) pass; widening exact; narrowing correctly rounded; binary128 add/mul/div/sqrt pass.

Fixtures

testfloat/*_to_*, testfloat/f128_*.

Pitfalls

(a) float→int overflow handling (saturate + Invalid, not wrap). (b) Rounding large int→float. (c) Subnormal results on narrowing. (d) Undersized binary128 intermediate.

⬜ Phase 9 — Float ↔ string (correctly-rounded parse + shortest print)

Objectives

strtod-correct decimal→binary parsing and shortest round-tripping binary→decimal printing (Ryū), with a Dragon4 fallback.

Deliverable

Parse/format for all binary formats.

Acceptance

parse ∘ format is identity for all finite values; output is the shortest round-tripping decimal; matches reference strtod/printf rounding.

Fixtures

roundtrip/shortest.json, hard values (5e-324, 1.7976931348623157e308, halfway cases).

Pitfalls

(a) Double rounding in parse. (b) Non-shortest output. (c) Locale decimal separators in core. (d) −0, subnormal, inf/NaN text forms.

⬜ Phase 10 — Decimal formats (BID + DPD)

Objectives

decimal32/64/128 decode/encode in both BID and DPD encodings; classification; cohorts.

Deliverable

Decimal format codecs + classify.

Acceptance

decTest decode/encode pass; BID↔DPD round-trips; cohort members (e.g., 1.0 vs 1.00) compare equal but retain exponent.

Fixtures

dectest/decDecode*, cohort cases, non-canonical inputs.

Pitfalls

(a) Combination-field special-case encoding (inf/NaN). (b) Declet table errors. (c) Cohort (same value, different exponent) confusion. (d) Coefficient overflow at max digits.

⬜ Phase 11 — Decimal arithmetic + arbitrary-precision BigDecimal

Objectives

Decimal add/sub/mul/div with decimal rounding; arbitrary-precision BigDecimal on #370 bignum.

Deliverable

Decimal arithmetic + BigDecimal.

Acceptance

decTest arithmetic suites pass; exact base-10 results exact (0.1 + 0.2 = 0.3); BigDecimal supports unbounded scale.

Fixtures

dectest/decAdd*, decMultiply*, decDivide*; money fixtures.

Pitfalls

(a) Exponent-alignment overflow. (b) Non-terminating division (must specify scale + rounding). (c) Wrong "quantum"/ideal exponent. (d) Coefficient growth without bound.

⬜ Phase 12 — Money / fixed-point types

Objectives

A Money type (BigDecimal + currency + rounding policy) and fixed-point Q-format arithmetic.

Deliverable

Currency-aware money arithmetic with correct rounding and exact allocation.

Acceptance

Splitting/allocating a sum conserves the total to the minor unit; half-even default; cross-currency operations rejected without an explicit rate.

Fixtures

money/allocate.json, money/round_policy.json, multi-currency cases.

Pitfalls

(a) Binary float creeping in (forbidden). (b) Lost cents on division (use largest-remainder allocation). (c) Mixing currencies. (d) Sign handling in rounding.

⬜ Phase 13 — Conformance + fuzzing + no-hardware-float enforcement

Objectives

Reach the conformance and fuzzing bar; enforce the no-hardware-float rule; report ulp accuracy.

Deliverable

Conformance-green, fuzzed, enforced library.

Acceptance

TestFloat + decTest 100% on supported ops; ≥24 h fuzz with zero crashes; differential ≤ 0.5 ulp; zero f32/f64 in core crates.

Fixtures

testfloat/* (full), dectest/* (full), fuzz/corpus/*, fpgen/*.

Pitfalls

(a) Flag-timing mismatches (UF/NX subtleties). (b) Exhaustive binary16 cost. (c) sNaN handling gaps. (d) Double rounding in conversions.
