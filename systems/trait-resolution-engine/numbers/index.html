Network: offline, local execution by default; telemetry export is optional and localhost-only unless explicitly configured. CPU: x86_64 baseline, cache-sensitive allocation layout, hot-path branch prediction tuned for the common Proven outcome. NUMA: single-node preferred; cross-node allocation avoided entirely in Phase 0–9 (distribution is PhaseDeferred("§18")). Scaling assumption: vertical first (memory + CPU), horizontal only via the deferred distributed query cache. These budgets are carried unchanged into §28 (targets table) and §32 (capacity arithmetic) — no drift permitted.

32. Back-of-Envelope Capacity Model

  • C1 — Intern table RAM. 1,000,000 types × 64 B/entry = 64 MB, well inside the 1.5 GB RSS ceiling (§4).
  • C2 — Canonical cache RAM. 200,000 entries × 4 KB median (§4) = 800 MB, + 12% fragmentation slack (§4) = 896 MB, fitting alongside C1 inside the 1.5 GB ceiling.
  • C3 — Per-query transient peak. 8 MB budget/query (§4) × 32 concurrent queries (§4) = 256 MB worst-case transient allocation, still inside the 1.5 GB ceiling alongside C1 and C2.
  • C4 — Sustained throughput headroom. 100,000 obligations/min (§4) ÷ 60 s = 1,667 obligations/sec required average, vs. 5,000/sec single-core capacity at the 200 µs p50 budget (§4) = 3× headroom over the required floor.
  • C5 — Cache-lookup bandwidth. 20,000 queries/sec (§4) × 4 KB median entry (§4) = 80 MB/sec read bandwidth, far under typical single-channel DDR4 bandwidth (~20 GB/s), confirming the lookup path is CPU-bound.
  • C6 — Worker-pool contention ceiling. 32 threads (§4) × 500 µs p99 lock wait (M10, §28) = 16 ms aggregate worst-case serialized wait per round, inside the 25 ms p99 recursive-solve budget (§4, M3).
  • C7 — Replay-log storage. 100,000 obligations/min (§4) × 1.5× amplification (§4) × 200 B/event = 30 MB/min raw replay volume = 1.8 GB/hour before compression.
  • C8 — Snapshot compression. 1.8 GB/hour raw (C7) × (1 − 0.40 compression floor, §4) = 1.08 GB/hour archived, fitting a 24 GB/day retention budget on a CI runner's local disk.
  • C9 — FD-budget ceiling. 256 FDs (§4) ÷ 3 FDs/query-context (fixture + snapshot + telemetry socket) = 85 concurrent query contexts addressable, above the 32-thread ceiling (§4).
  • C10 — Cold-start deserialization rate. 500 ms cold-init ceiling (§4) for a 64 MB intern table (C1) = 128 MB/s minimum deserialization throughput, achievable via zstd-compressed postcard (ADR-17) at >500 MB/s single-core decompression.
