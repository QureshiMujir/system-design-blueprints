  • Q16. §6's P6 and §22's T2 both bound obligation growth — using §15 and §32's C3, explain why P6's queue cap and I10's recursion-depth cap are not redundant even though both prevent unbounded memory growth.

30. Mental Models & First Principles

  • MM1 — Canonicalization is a normal form, not an optimization. Two goals are the same query iff their canonical forms are byte-identical, exactly like a term-rewriting normal form. Predicts: any two structurally-distinct-looking goals meaning the same thing must hash identically after canonicalization. Bug class without it: cache-miss storms from inconsistent normalization. Applies in §14.
  • MM2 — A proof tree is a certificate, not a log. It exists to be re-checked without re-solving, not merely to record what happened. Predicts: you can always answer "why is this proven" without invoking the solver again. Bug class without it: solving twice — once to decide, once to explain. Applies in §19.
  • MM3 — A recursion budget converts an unsoundness risk into an availability risk. Bounding recursion fixes hangs, not wrong answers; only the occurs check (I4) fixes correctness. Predicts: a system can be simultaneously "safe from hangs" and "unsound" if the budget is the only defense. Bug class without this distinction: conflating "capped" with "correct." Applies in §15.
  • MM4 — Backpressure is a scheduling policy, not an error path. Rejecting load under P6 is a deliberate decision, not a failure. Predicts: queue-full telemetry should read as "policy fired," not "bug triggered." Bug class without it: treating legitimate load-shedding as an incident. Applies in §20.
  • MM5 — Coherence is a global property, checkable locally only via transitive closure. A pairwise overlap check without closure misses transitively-implied conflicts. Predicts: any coherence check that skips closure will eventually admit a contradictory impl pair undetected. Bug class without it: silent global unsoundness from a locally-correct-looking check. Applies in §17.
  • MM6 — Incrementality must trade over-invalidation for under-invalidation, never the reverse. Slow-but-correct beats fast-but-wrong. Predicts: any "optimization" that removes a dependency edge to speed up invalidation is a latent correctness bug. Bug class without it: silent stale diagnostics (FM-2). Applies in §18.
  • MM7 — Determinism under concurrency requires a canonical total order independent of wall-clock scheduling. Thread interleaving must never leak into the result. Predicts: "works on a single thread, flakes under load" is the signature of a missing total order, not a data race. Bug class without it: replay divergence with no reproducible race to point at. Applies in §20.
  • MM8 — Ambiguity is information, not failure. An Ambiguous result tells the caller "insufficient evidence," which is itself a useful, actionable fact. Predicts: any solver that forces a pick under ambiguity produces silently-wrong downstream compilation. Bug class without it: nondeterministic candidate selection masquerading as a deterministic result. Applies in §15.

5. Required Reading

Books

  • Types and Programming Languages — Benjamin C. Pierce (2002), ch. 9–32: subtyping, universal and existential polymorphism, algorithmic typing rules; applied in §11 and §14.
  • Advanced Topics in Types and Programming Languages — ed. Benjamin C. Pierce (2004), ch. on type classes and qualified types: constraint-based inference groundwork; applied in §15 and §16.
  • Engineering a Compiler — Keith Cooper & Linda Torczon (3rd ed., 2022), ch. on IR design and semantic analysis: compiler-pipeline integration boundaries; applied in §3 and §10.
  • Compilers: Principles, Techniques, and Tools — Aho, Lam, Sethi, Ullman (2nd ed., 2006), semantic-analysis chapters: symbol-table and typing-environment design; applied in §11.
  • Purely Functional Data Structures — Chris Okasaki (1998): persistent, immutable graph structures and amortized analysis; applied in §12 and §13.
  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. on consistency and replication: durability/consistency framing for the incremental store; applied in §18.
  • Rust Atomics and Locks — Mara Bos (2023): memory-ordering correctness for lock-free counters and the parallel executor's work-stealing queues; applied in §20.

Papers

  • "How to Make Ad-hoc Polymorphism Less Ad hoc" — Wadler & Blott, 1989, POPL: origin of the dictionary-passing model that trait obligations generalize; applied in §11.
  • "Type Classes in Haskell" — Hall, Hammond, Peyton Jones, Wadler, 1996, ACM TOPLAS: constraint resolution and context reduction rules → obligation lifecycle design; applied in §15.
  • "Modular Implicits" — White, Bour, Yallop, 2014, ML Workshop: scoped, first-class resolution without global coherence → informs orphan-rule scoping tradeoffs; applied in §17.
  • "Tabled Evaluation with Delaying for General Logic Programs" — Chen & Warren, 1996, JACM: SLG resolution / tabling for recursive logic evaluation → cycle-detection strategy; applied in §13 and §16.
  • "Adapton: Composable, Demand-Driven Incremental Computation" — Hammer, Phang, Hicks, Foster, 2014, PLDI: demand-driven recomputation with correctness-by-construction → incremental query design; applied in §18.
  • "Incremental Computation with Names" — Hammer, Dunfield, Head, Foster, Hicks, 2015, OOPSLA: name-based invalidation → dependency-edge design in crates/incremental; applied in §18.
  • "RustBelt: Securing the Foundations of the Rust Programming Language" — Jung, Jourdan, Krebbers, Dreyer, 2018, POPL: semantic soundness framing → coherence violations are soundness bugs, not lints; applied in §17.
  • "Type Inference with Constrained Types" — Sulzmann, Odersky, Wehr, 1999, HM(X) framework: extensible constraint-system parameterization → generalizes to trait obligations; applied in §14 and §15.
  • "Datalog and Recursive Query Processing" — Green, Huang, Loo, Zhou, 2013, Foundations and Trends in Databases: fixed-point semantics for recursive rules → obligation fixed-point model; applied in §15.

Reference Implementations

  • rust-lang/chalk — study chalk-solve/, chalk-ir/: canonicalization architecture and slot-based binders; pitfall: do not copy Chalk's unbounded SLG tabling — it lacks the hard wall-clock cutoff this blueprint requires (§4); applied in §14 and §16.
  • rust-lang/rust — study compiler/rustc_trait_selection/: diagnostics rendering and coherence checking at scale; pitfall: do not copy the legacy solver's ad hoc caching, a known source of rustc cache bugs; applied in §17 and §19.
  • GHC — study the typechecker's constraint solver (TcCanonical, TcInteract): ambiguity handling and context-reduction ordering; pitfall: GHC's solver has no incremental-reuse story — do not port its caching absence; applied in §15.
  • Scala compiler (Dotty) — study the implicit-search engine: specialization-adjacent priority rules; pitfall: unbounded exponential backtracking is exactly the DoS shape this blueprint's recursion budget prevents (T2); applied in §15.
  • Soufflé — study the Datalog fixed-point evaluator: bottom-up semi-naive evaluation for recursive rules; pitfall: semi-naive evaluation assumes a closed rule set, which does not hold for an incrementally-edited trait program; applied in §16.
  • salsa-rs/salsa — study the revision-tracked incremental query framework: durability levels and dependency-tracked memoization; pitfall: salsa assumes single-threaded query execution — §20's parallel executor must add its own synchronization; applied in §18.

RFCs / Specifications

  • RFC 0195 — Associated Items (rust-lang/rfcs): defines the associated-type projection surface this engine normalizes; applied in §16.
  • RFC 1023 — Rebalancing Coherence (rust-lang/rfcs): the coherence/orphan rule this engine validates; applied in §17.
  • RFC 1210 — impl specialization (rust-lang/rfcs): the specialization-ordering model this engine defers; applied in §17 and registered as PhaseDeferred("§15") in §35.
  • Language Server Protocol Specification, Diagnostics (spec section 3.17): the diagnostic shape this engine's output must be adaptable to for IDE embedding; applied in §19.

Glossary (§36) · 43 terms · site-wide glossary

Obligation
a trait-proof requirement generated during solving; the unit of work in the obligation queue.
Canonicalization
normalization of a goal's free variables into a stable form suitable for cache-key derivation (P2).
Projection
access to an associated type through a trait bound (<T as Trait>::Assoc).
Universe
a binder-scoping domain preventing placeholder capture across nested binders (I9).
Ambiguity
a first-class SolveResult outcome meaning insufficient evidence, distinct from failure (P11).
Coherence
the global property that at most one impl applies to any concrete goal (I8).
Orphan Rule
the ownership restriction preventing impls of foreign traits for foreign types.
Proof Tree
the acyclic derivation graph certifying a Proven result (I5).
Fixed Point
the stable state reached when recursive obligation solving stops producing new obligations.
Inference Variable
an unknown-type placeholder scoped to one query context (I6).
Placeholder
a universally-quantified (skolem) variable introduced during goal negation or higher-rank checking.
Replay
deterministic re-execution of a captured obligation sequence for debugging (I7).
Snapshot
a serialized, versioned capture of solver/intern state for restart or replay.
Candidate
a possible impl match considered during candidate assembly.
Query Key
the canonical cache identifier derived from a CanonicalGoal (§11).
Datalog
a logic-programming execution model based on bottom-up fixed-point rule evaluation; studied for §16's normalization but not adopted whole-program (§31, §34 Alt A).
Occurs Check
the unification-time check preventing cyclic (infinite) substitutions (I4).
Arena Allocation
bulk, lifetime-scoped allocation avoiding per-object allocator churn (P8).
Incremental Graph
the dependency graph between queries and source items driving invalidation propagation (§18).
Projection Cache
the memoized store of normalization results keyed by canonical projection shape (§16).
Canonical Variable
a De Bruijn-indexed placeholder replacing a free inference variable during canonicalization.
Binder
a scope-introducing construct (universal/existential quantifier) over one or more canonical variables.
De Bruijn Index
a positional variable-naming scheme immune to alpha-renaming, used for stable canonical hashing.
Skolemization
replacing a universally-quantified variable with a fresh placeholder for proof purposes.
Blanket Impl
an impl applying to an entire unconstrained (or lightly constrained) generic parameter, e.g. impl<T> Foo for T.
Specialization
a mechanism allowing a more specific impl to override a more general one; deferred beyond overlap-rejection (§35).
Where-Clause
a bound attached to a generic parameter constraining which types satisfy it.
Trust Boundary
the point where unvalidated external input becomes validated internal IR (§3, T1).
Backpressure
a deliberate load-shedding policy bounding queue growth under load (P6, MM4).
Work Stealing
a scheduling strategy where idle workers pull tasks from busy workers' queues (§20).
Durability
a salsa-style classification of how often a query's inputs are expected to change, used to prune unnecessary re-derivation.
Dirty Propagation
the process of marking downstream queries stale after an upstream input changes (§18).
Dependency Edge
a directed edge in the incremental graph recording that one query reads another (§11).
Epoch
a query-scoped generation boundary at which arena memory is reclaimed (P8, I11).
Recursion Budget
the hard, instrumented cap on recursive obligation-solving depth (I10, P5).
Tabling
memoizing intermediate results of a recursive logic derivation to avoid re-deriving suspended goals (SLG resolution, §5).
SLG Resolution
Chen & Warren's tabled logic-resolution strategy adapted for cycle detection in §13 and §16.
Overlap Graph
the transitively-closed graph of impl pairs whose applicability regions intersect (I8).
Structural Sharing
reusing immutable substructure across interned nodes instead of copying, per Okasaki's persistent-data-structure model.
Interning
deduplicating structurally-identical values behind a single stable identifier (P10).
Region Erasure
dropping lifetime/region information before canonicalization while still propagating it through obligations (§14.2).
Negative Reasoning
deriving that a trait bound does not hold, distinct from failing to prove that it does.
Fixpoint Convergence
the point at which iterative obligation solving stops producing changes to the proof state.
