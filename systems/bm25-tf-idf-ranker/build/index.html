⬜ Phase 0 — Tokenizer and Normalization Pipeline §12

Objectives

Build the complete text analysis pipeline: Unicode-correct tokenization (UAX #29), NFKC normalization, Unicode case-folding, optional accent stripping, Porter2 stemming, and configurable stop-word filtering. The pipeline is the correctness foundation for all later phases. P1 and P11 govern this phase; I1 and I2 are first exercised here.

Deliverable

cargo test -p ranker-core passes. ranker-cli index --debug-tokens corpus.jsonl prints token stream to stdout. Conformance tests pass against Whoosh reference output.

Acceptance
  • All 6 conformance tokenizer fixtures pass with exact token list equality.
  • "İSTANBUL" lowercases to "istanbul" (Unicode case fold test).
  • Position gaps: "the quick" with stop-word "the" → tokens ["quick"] with position=1 (not 0).
  • "ﬁle" NFKC-normalizes to "file" (ligature test).
  • Tokenizer throughput ≥ 50 MB/s on Wikipedia 10 MB fixture (criterion).
  • Zero panics on fuzz corpus of 10,000 random byte sequences.
Fixtures
Filename Purpose Expected Output
tokenizer/basic_english.in/out Core English tokenization ["hello","world","run","test"] (Porter2 stems)
tokenizer/unicode_cjk.in/out CJK boundary handling ["日本語テスト"] (single token; future bigram deferred)
tokenizer/unicode_accents.in/out NFKC + accent strip + stem ["unicod"] from "Ünïcödé"
tokenizer/stop_words.in/out Stop-word removal with position gap ["quick","brown","fox"]; positions 1,2,3
tokenizer/empty.in/out Empty input [] (no panic)
tokenizer/malformed_nul.in/out NUL bytes in input NUL stripped; remaining tokens normal
Pitfalls
  1. Offset invalidation after stemming. Porter2 shortens text; start/end must reference original source, not stemmed form. Verify by &source[token.start..token.end] matching pre-stemmed text.
  2. Position gaps after stop-word removal. If StopWordFilter renumbers positions, phrase distance semantics break silently. Test: phrase query "quick brown" on "the quick brown fox" must match even with stop-word "the".
  3. NFKC changes token length. "ﬁ" (3 bytes) → "fi" (2 bytes). Offsets reference original source; token.text.len() != token.end - token.start is expected and correct.
  4. Turkish İ case-fold. str::to_ascii_lowercase("İ") → "İ" (wrong). Only full Unicode case-fold tables handle this correctly.
  5. Zero-length tokens. Some UAX #29 boundary rules emit zero-length spans. Filter token.start == token.end before emitting.

⬜ Phase 1 — In-Memory Inverted Index §13

Objectives

Build the complete in-memory index structure: DocId/TermId type system, HashMap-backed term dictionary, PostingsBuilder, in-memory DocStore, CorpusStatsBuilder, and MemorySegment. Phase 0 pipeline feeds this; Phase 2 scoring engine reads it. I1, I2, I3, I9 first enforced here.

Deliverable

cargo test -p ranker-index passes. ranker-cli index corpus.jsonl indexes 100 documents. ranker-cli search "rust" returns correct DocId list.

Acceptance
  • Conformance fixture index/insert_3docs.json: correct TermId assignments and postings lists.
  • index/duplicate_terms.json: document with "foo foo foo" → Posting{term_freq=3}.
  • index/avgdl.json: 3 docs of lengths 10, 20, 30 → avgdl == 20.0.
  • index/empty_doc.json: empty body → field_length=0; no postings.
  • seek(t) property test: for all t ∈ [0, max_doc_id], seek(t).doc_id >= t (I9).
  • Zero TermId assignment drift across 10 restarts on same corpus (I12).
Fixtures
Fixture Purpose Expected
index/insert_3docs.json Basic TermId and postings correctness Correct TermIds, sorted postings
index/duplicate_terms.json TF accumulation term_freq=3 for repeated term
index/empty_doc.json Zero-length document handling field_length=0, no postings
index/avgdl.json CorpusStats correctness avgdl=20.0
index/seek_regression.json seek() correctness on sparse postings Every seek(t) returns doc_id >= t
Pitfalls
  1. Non-monotonic document insertion. Parallel ingestion may violate DocId order. PostingsBuilder::finalize() must sort; debug assert verifies sorted order before any query.
  2. HashMap non-determinism. HashMap iteration order varies. Serialization or diff of term dict state must use BTreeMap or sort by TermId first.
  3. TermFreq overflow. tf > u16::MAX is pathological but possible (URL-stuffed documents). Clamp to u16::MAX = 65535 with a tracing::warn! log.
  4. Shared mutable state in parallel builds. Phase 1 is single-threaded. Do not add concurrency to PostingsBuilder prematurely — it requires Mutex or per-thread partial segments with merge (Phase 9).

⬜ Phase 2 — TF-IDF Scoring Engine §14

Objectives

Implement the Scorer trait, all four TF variants, smooth IDF, TfIdfScorer, and end-to-end scoring with conformance against Whoosh. Establish the correctness baseline for Phase 3 BM25. P1, P2, P9, P10 govern this phase.

Deliverable

cargo test -p ranker-score passes. ranker-cli search --scorer tfidf "rust" on the 3-doc fixture returns correct ranked results matching Whoosh.

Acceptance
  • tfidf/corpus_3docs.json: query "rust" → D1 > D3 > D2 (score=0) with correct scores.
  • tfidf/idf_zero_contribution.json: term in all documents → IDF ≈ 0; all scores ≈ 0.
  • Smooth IDF for df=80%N is strictly positive (not negative as with classic formula).
  • Augmented TF with max_tf=0 does not divide by zero.
  • Scores match Whoosh reference within 1e-4 on all 4 fixture queries.
Fixtures
Fixture Purpose Expected
tfidf/corpus_3docs.json D1:"rust sys prog", D2:"python web prog", D3:"rust web" Base corpus
tfidf/scores_query_rust.json Query: "rust" D1 > D3 > D2 (D2 score=0)
tfidf/scores_query_programming.json Query: "programming" D1 ≈ D2 > D3
tfidf/idf_zero_contribution.json Universal term IDF ≈ 0
Pitfalls
  1. f32 vs f64 divergence. Whoosh uses Python f64; Rust uses f32. Epsilon must be 1e-4, not 1e-7.
  2. Augmented TF zero division. max_tf=0 when all tokens are stop words. Guard: return 0.0.
  3. Classic IDF negatives. Classic ln(N/df) returns negative for df > N/e. Smooth IDF prevents this; tests must verify positivity for df=0.8N.
  4. Missing term in query. If a term has no postings, df=0; IDF is high but tf=0 for all documents. Score contribution is 0 regardless. Executor must handle missing terms via empty postings iterator.

⬜ Phase 3 — BM25 Scoring Engine §15

Objectives

Implement Robertson IDF, BM25 TF normalization, Bm25Scorer, BM25+ variant, and parameter sensitivity tests. Conformance against Tantivy. P1, P2, P3, P7 govern. I3, I7, I13 exercised.

Deliverable

ranker-cli search --scorer bm25 --k1 1.2 --b 0.75 "rust programming" returns ranked results matching Tantivy on the fixture corpus.

Acceptance
  • bm25/scores_k1_1.2_b0.75.json: scores match Tantivy within 1e-4 on all queries.
  • bm25/scores_k1_0_b0.json: all docs with the term score identical IDF value.
  • bm25/scores_bm25plus.json: delta=0.5 → all BM25+ scores > corresponding BM25 scores.
  • bm25/nfcorpus_sample.json: NDCG@10 within 1% of pyserini reference on 50-doc sample.
  • robertson_idf(50000, 100000) > 0.0 (high-df term is still positive).
Fixtures
Fixture Purpose Expected
bm25/scores_k1_1.2_b0.75.json Default params vs Tantivy Within 1e-4
bm25/scores_k1_0_b0.json Parameter edge: k1=0, b=0 All docs with term score IDF only
bm25/scores_bm25plus.json BM25+ lower bound BM25+ > BM25 for all tf≥1
bm25/nfcorpus_sample.json 50-doc NFCorpus NDCG check NDCG@10 within 1% of pyserini
Pitfalls
  1. avgdl across segments. Global avgdl = Σ(total_tokens) / Σ(num_docs), not mean of per-segment avgdl values. CorpusStats::merge() sums numerator/denominator separately (I3).
  2. df across segments. Per-term df must be summed across all live segments. Single-segment df yields wrong IDF in multi-segment index.
  3. Zero-document corpus. robertson_idf(0, 0) is mathematically defined; return empty result set before scoring is invoked rather than computing on empty corpus.
  4. BM25 and TF-IDF on different scales. Never compare raw scores across scoring models; normalization is required. Tests must not assert bm25_score > tfidf_score.

⬜ Phase 4 — Persistent Index Storage §16

Objectives

Define and implement the binary segment format, VByte codec, skip pointers, mmap-backed SegmentReader, FST term dictionary, WAL, and PersistentIndex. Enables crash recovery and zero-copy query path. P3, P5, P6, P8 govern. I4, I5, I8, I9, I10, I11 enforced here.

Deliverable

ranker-cli index --dir ./myindex corpus.jsonl writes to disk. ranker-cli search --dir ./myindex "rust" reopens and returns results. Process restart between index and search verifies persistence.

Acceptance
  • store/segment_roundtrip.json: scores after disk round-trip match in-memory scores exactly.
  • store/wal_recovery.json: crash after insert, before commit → WAL replay restores all documents.
  • store/delete_bitmap.json: 100 docs, delete 20 → deleted docs never appear in any of 1000 queries.
  • store/magic_bytes.bin: first 8 bytes of segment file == b"RANKRSEG".
  • FST lookup: insert terms in non-lexicographic order, verify FST sort then build succeeds.
  • mmap cold-page read: seek(target) returns correct posting on a cold OS page cache.
Fixtures
Fixture Purpose Expected
store/segment_roundtrip.json Disk round-trip correctness Exact score match
store/wal_recovery.json WAL replay after crash All documents present
store/delete_bitmap.json Delete correctness Zero deleted docs in results
store/magic_bytes.bin Format integrity Magic + version match format.rs
Pitfalls
  1. mmap SIGBUS on truncated file. After write, call fsync and verify file size before mapping. In tests, use std::panic::catch_unwind around mmap reads.
  2. FST out-of-order insert. fst::MapBuilder panics on non-lexicographic keys. Sort terms before FST construction; test with a term set not in lexicographic insertion order.
  3. Skip pointer off-by-one. Skip table entry at stride i stores doc_id_at_i. seek(target) finds last entry with doc_id < target, decompresses forward from that point. Off-by-one wastes one stride block but does not corrupt results.
  4. WAL unbounded growth. max_wal_entries=1,000,000 triggers auto-flush. Test: long-running index never exhausts disk.
  5. Concurrent mmap and segment write. Flush writes to a new file (SegmentId), never overwrites. index.meta update is atomic rename. Old mmap regions held by in-flight queries are valid until their reference count drops.

⬜ Phase 5 — Query Language and Parsing §17

Objectives

Build the complete query pipeline: hand-written lexer, recursive descent parser (EBNF grammar from §8), QueryPlanner, AND/OR/NOT merge iterators. No parser-combinator libraries (nom, pest) — understand the character-by-character state machine. P1, P5, P9, P13 govern.

Deliverable

ranker-cli search --dir ./myindex 'rust AND "systems programming" NOT java' executes correctly with boolean semantics and returns top-10 results.

Acceptance
  • query/parse_and.ast.json: "a AND b" → AndNode([TermNode("a"), TermNode("b")]) exactly.
  • query/parse_phrase.ast.json: '"hello world"' → PhraseNode(["hello","world"], slop=0).
  • query/parse_nested.ast.json: "(a OR b) AND c" → correct nested AST.
  • query/parse_boost.ast.json: "rust^2.5" → TermNode("rust", boost=2.5).
  • query/parse_error.in: "((unclosed" → RankerError::QueryParse.
  • AND-merge property test: seek(t).doc_id >= t for all t ∈ [0, max_doc_id] (I9 enforced on iterators).
  • Empty query (all stop words) → EmptyPlan → empty result set (not "match all").
Fixtures
Fixture Purpose Expected
query/parse_and.in/ast.json AND parse Correct AST
query/parse_phrase.in/ast.json Phrase parse PhraseNode
query/parse_nested.in/ast.json Nested grouping Correct nesting
query/parse_boost.in/ast.json Boost suffix boost=2.5
query/parse_error.in Malformed query RankerError::QueryParse
Pitfalls
  1. Analyzer mismatch. Query parser must apply same AnalysisPipeline used at index time. Pipeline config stored in index.meta; loaded at query time; mismatch returns RankerError::SegmentFormat.
  2. AND-merge seek semantics. After seek(target) returns Some(doc_id) where doc_id > target, the next next() must return doc_id, not the following entry. Buffer the result of seek() in peeked: Option<Posting>. Property test verifies this.
  3. Empty plan from all-stop-word query. QueryPlanner must return QueryPlan::Empty → executor returns empty result set, not a scan of all documents.
  4. Boost and WAND upper bounds. max_term_score() must be multiplied by the boost factor. Ignoring boost in max_term_score causes WAND (Phase 8) to produce incorrect top-K results.

⬜ Phase 6 — Multi-Field and Boosted Scoring §18

Objectives

Extend the index and scoring to support multiple named fields with per-field normalization. Implement BM25F (multi-field BM25 combining field-weighted TF before a single IDF). Enable field-qualified query syntax (title:rust^3). P9 governs. I3 extended to per-field avgdl.

Deliverable

ranker-cli search --dir ./myindex "title:rust^3 body:programming^1" returns results ranked by BM25F with correct per-field weights.

Acceptance
  • bm25f/scores_two_fields.json: BM25F scores match hand-computed values within 1e-4.
  • bm25f/field_boost_dominates.json: document with term in title ranks above document with term in body only (weight title=3.0 > body=1.0).
  • Per-field avgdl stored in CorpusStats: avgdl_title ≠ avgdl_body on a typical corpus.
  • Missing field (document has no title): contributes tf=0 to tf_tilde without error.
Fixtures

⬜ Phase 7 — Positional Index and Phrase Queries §19

Objectives

Extend postings to store token positions. Implement phrase query executor with slop support. Enable "systems programming" and "systems programming"~2 (slop=2) query syntax. I1 extended to position ordering.

Deliverable

ranker-cli search '"systems programming"' returns only documents with exact sequence. '"systems programming"~2' returns documents with up to 2-word gap.

Acceptance
  • phrase/exact_match.json: only document with "systems programming" in sequence is returned.
  • phrase/slop_2.json: documents with up to 2-word gap are returned; documents with gap > 2 are not.
  • phrase/no_match.json: terms appear in document but not in order → not returned.
  • Phrase query with all stop words → empty result set (not error).
Fixtures
Fixture Purpose Expected
phrase/exact_match.json Exact phrase Only ordered occurrence returned
phrase/slop_2.json Slop window Gap≤2 matches; gap>2 does not
phrase/no_match.json Reversed terms Not returned
Pitfalls
  1. Position delta overflow. Same term in multiple fields: use a field-boundary gap of 100 (Lucene default) between fields so position deltas are always non-negative.
  2. Phrase with stop words. Stop words removed from positional index → phrase query on stop words returns empty. Document this in API.
  3. Position loading cost. Load positions only for documents passing AND-merge, not for all candidates.

⬜ Phase 8 — Top-K Retrieval and WAND §20

Objectives

Implement WAND (Broder et al. 2003) and Block-Max WAND (Ding & Suel 2011) for efficient top-K retrieval. WAND skips documents whose maximum possible score is below the current K-th threshold. 3–10× speedup over naive OR-merge on multi-term queries. I7 is critical correctness invariant here.

Deliverable

Criterion benchmark: WAND produces K=10 results 3–10× faster than naive OR-merge on 100K-document corpus with 3-term queries. Correctness test passes on 10,000 random pairs.

Acceptance
  • wand/top10_equivalence.json: WAND top-10 == naive top-10 on all test queries (I7 validation).
  • wand/threshold_skips.json: WAND instrumented counter shows skipped_postings / total_postings > 70% on 3-term queries over 1M-doc corpus.
  • wand/single_term.json: WAND degenerates correctly to sequential scan for single-term queries.
  • Criterion: WAND p50 < 5ms, p99 < 25ms for K=10 on 1M-doc warm index (M3, M4).
Fixtures
Fixture Purpose Expected
wand/top10_equivalence.json Correctness vs naive Identical top-10
wand/threshold_skips.json Skip efficiency >70% skip rate
wand/single_term.json Degenerate case Sequential scan
Pitfalls
  1. max_score underestimate → missing top-K results. WAND requires max_term_score ≥ all actual scores (I7). BM25+ delta must be included in upper bound. Any BM25 parameter change requires re-checking max_term_score formula.
  2. Threshold update race. Phase 8 is single-threaded; note that multi-threaded WAND requires atomic threshold. Isolate threshold in ThresholdManager struct for future safety.
  3. WAND with AND queries. WAND applies to OR (disjunctive) semantics only. AND queries use AND-merge iterator. Do not apply WAND to AND plans.

⬜ Phase 9 — Index Merging and Segment Architecture §21

Objectives

Implement tiered merge policy, k-way segment merge writer, delete-aware compaction, and background MergeManager. Bound segment count for 10M-document ingest. I4, I5, I10, concurrent read safety. P3, P6 govern.

Deliverable

Long-running ranker-cli index session ingesting 10M documents triggers automatic merges. After ingest: ≤ 70 segments in ./myindex. Query latency not degraded relative to fresh index.

Acceptance
  • merge/two_segment_merge.json: merged scores == scores from separate-segment query (CorpusStats merge correctness).
  • merge/delete_compaction.json: deleted docs absent from merged segment.
  • merge/corpus_stats_merge.json: merged avgdl == (Σ total_tokens) / (Σ num_docs).
  • Segment count ≤ 70 after 10M-document ingest on standard test machine.
  • Concurrent read test: 100 queries in flight during merge → zero incorrect results (I4, I5).
Fixtures
Fixture Purpose Expected
merge/two_segment_merge.json Score correctness Exact match
merge/delete_compaction.json Delete compaction Zero deleted docs
merge/corpus_stats_merge.json avgdl correctness Weighted formula
Pitfalls
  1. GlobalDocId collisions. Local DocId values across segments are not globally unique. Merged documents get new GlobalDocIds (I10). External caches of GlobalDocId must be invalidated on merge.
  2. FST union incompatible key spaces. Segments may assign different TermId to same term string. Merge must use term string as primary key; reassign TermId in merged segment.
  3. Merge amplification under high ingest. If ingest > merge throughput, segment count grows unboundedly. Implement write-ahead throttle: block inserts at segment_count > 100; warn at > 50.

⬜ Phase 10 — HTTP Query API and Benchmarking Harness §22

Objectives

Expose the ranking engine as an HTTP service (Axum). Implement snippet generation. Add Prometheus metrics. Build the TREC evaluation harness. Evaluate on MS MARCO passage subset. P2, P4, P10 govern. This phase ties all prior phases together.

Deliverable

docker-compose up brings up API on port 8080, Prometheus on 9090, Grafana on 3000. curl -X POST http://localhost:8080/search -d '{"query":"rust programming","k":10}' returns ranked JSON. TREC evaluation on MS MARCO meets NDCG@10 ≥ 0.18.

Acceptance
  • api/post_search_response.json: response schema correct (all required fields present).
  • trec/msmarco_ndcg10.txt: NDCG@10 ≥ 0.18 on MS MARCO dev 500 queries.
  • bench/baselines_2025.json: Criterion baselines committed; CI gates on regression (> 5% degradation fails PR).
  • P50 search latency < 5ms, P99 < 25ms on 1M-doc warm index (M3, M4).
  • Concurrent POST /index + GET /search: no partially-indexed document ever appears in results.
Fixtures
Fixture Purpose Expected
api/post_search_response.json Schema correctness All fields present
trec/msmarco_ndcg10.txt End-to-end quality ≥ 0.18
bench/baselines_2025.json Performance baseline Committed; CI gates
Pitfalls
  1. Shared mutable index in Axum handlers. POST /index must queue via tokio::sync::mpsc::Sender<IndexCommand>. Indexing task owns PersistentIndex. Handlers read from Arc<RwLock<ReadableIndex>> snapshot.
  2. TREC metric divergence from trec_eval. trec_eval uses binary relevance for MAP by default; NDCG uses graded relevance. Run both tools on same input; assert metrics match to 4 decimal places.
  3. Snippet highlight corruption. Apply html_escape::encode_text() to raw text BEFORE inserting <em> tags. Text containing <, >, or & produces malformed HTML if escaped after tag insertion.
