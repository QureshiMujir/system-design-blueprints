31. Mental Models & First Principles

MM1 — The inverted index is a phone book read backwards.
A forward index maps document → words. An inverted index maps word → documents. The insight: queries are word lookups, not document scans. Without it, you build a per-document scorer that scans all N documents for every query (O(N) per query). With it, you scan only the df documents containing each query term (O(df) per query, where df << N). Applied at §8, §13 Phase 1, §17 Phase 5.

MM2 — IDF is the logarithm of the probability that a query term is NOT in a random document.
IDF(t) ≈ log(N/df). A term in 1% of documents has IDF = log(100) ≈ 4.6. A term in 100% of documents has IDF = 0. Bug class without it: treating all terms equally, so "the" ranks above "quantum" for the query "quantum mechanics." Applied at §8 (IDF formula), §14 Phase 2, §15 Phase 3.

MM3 — k1 is the TF saturation valve; b is the document length dial.
Without k1, raw TF is unbounded — a document that repeats "rust" 1000 times would dominate everything. k1 controls how quickly additional occurrences become worthless. Without b, long documents beat short ones at equal density. Bug class without MM3: setting k1=100 turns BM25 into raw TF ranking (spammable); setting b=0 makes length normalization invisible (long documents systematically over-rank). Applied at §8 (BM25 formula), §15 Phase 3, §29 Performance Engineering.

MM4 — A postings list is already sorted; AND-merge is free intersection, not set intersection.
Set intersection on two hash sets: O(min(|A|, |B|)) with hash lookups. Sorted-merge AND: O(min(|A|, |B|)) comparisons, no hashing, cache-friendly. Bug class without it: using HashSet intersection, missing the O(1)-amortized seek() that powers WAND. The sorted invariant (I1) is what makes this possible. Applied at §17 Phase 5 (AND-merge), §20 Phase 8 (WAND), §8 (PostingsList).

MM5 — WAND is a branch predictor for document evaluation.
WAND computes an upper-bound score before evaluating a document. If the upper bound is below the current K-th score, the document cannot enter the top-K — skip it. This turns O(sum df) OR-merge into O(K × constant) amortized evaluation. Bug class without MM5: the max_term_score underestimates the actual maximum (I7 violation) → WAND silently drops documents from top-K. Applied at §20 Phase 8, §7 System Invariants (I7), §11 Core Types (max_score()).

MM6 — Immutable segments are the foundation of concurrent safety.
A segment written to disk is never mutated. Consequence: any thread can read any segment without a lock; reads are reference-counted via Arc; the OS handles page sharing transparently. The merge manager produces a new segment file atomically via rename; no reader ever sees partial state. Bug class without MM6: mutating a live mmap'd region produces SIGBUS or silent data corruption, which is a data-race on the memory map. Applied at §3 Architecture, §6 P3, §7 I4, §16 Phase 4, §21 Phase 9.

MM7 — Delta encoding trades random access for sequential throughput.
Storing doc_id - prev_doc_id instead of raw doc_id shrinks typical values from 4-byte integers to 1–2-byte VByte values. Cost: cannot access posting at position i without decoding positions 0..i. Skip pointers (every 64 entries) restore O(log n) random access. Bug class without MM7: negative delta values from out-of-order doc_ids corrupt the entire postings list (I1, I9). Applied at §8 (delta encoding), §16 Phase 4, §7 I9.

MM8 — avgdl is not a property of a query; it is a property of the corpus.
avgdl must be computed once at segment-flush time and stored as part of CorpusStats. It is not recomputed per query. Bug class without MM8: reading avgdl from a live global during a concurrent segment flush produces a race where half the documents contribute to the old avgdl and half to the new — BM25 scores become inconsistent across documents from the same corpus snapshot. Applied at §6 P7, §7 I3, §8 (CorpusStats), §15 Phase 3.

MM9 — A phrase query is an AND query filtered by positional constraint.
Phase 1: find documents containing all terms (AND-merge). Phase 2: for each candidate, check if terms appear adjacent. Loading positions for all OR-merge candidates (before AND-merge) is ≈ 100× more work. Bug class without MM9: applying position check to all OR-merge candidates, causing 100× slowdown for common phrase queries on large corpora. Applied at §19 Phase 7, §7 I1 (position ordering).

Glossary (§37) · 50 terms · site-wide glossary

AnalysisPipeline
The chained sequence of Tokenizer + TokenFilter instances applied to document text at index time and query text at query time. Configuration stored in index.meta; mismatch between index-time and query-time pipeline is a fatal correctness error.
avgdl
Average document length in tokens across the entire corpus. Computed as total_tokens / num_docs. Stored in CorpusStats; recomputed correctly via weighted sum on segment merge. Not a global mutable variable (P7, I3).
BM25 (Best Match 25)
A probabilistic ranking function derived from the 2-Poisson mixture model by Robertson et al. 1994. Default ranking model in Elasticsearch, Solr, and Lucene. Parameterized by k1 (TF saturation) and b (length normalization). The current state-of-the-art sparse retrieval baseline.
BM25+
A variant of BM25 that adds a lower bound δ to the TF component, guaranteeing every document containing a query term receives a strictly positive score contribution. Addresses the "zero contribution" pathology of standard BM25 for low-TF documents.
BM25F
Multi-field extension of BM25 that combines per-field term frequencies (weighted by field-specific normalization) into a single pseudo-TF before applying a single IDF. Requires per-field avgdl in CorpusStats.
Block-Max WAND (BMW)
Extension of WAND that stores per-block (B=64) maximum term scores in skip tables, enabling more aggressive block-level skipping. Ding & Suel 2011.
Codec
An encode/decode pair for a data format. Refers specifically to integer compression codecs for postings lists: VByte (Phase 0) and PFOR-delta (Phase 6+).
CorpusStats
Snapshot-consistent struct: {num_docs, total_tokens, avgdl, doc_freq: HashMap<TermId, u32>}. Computed at segment flush time; merged at query time via weighted sum. Never read from a mutable global.
DAAT (Document-At-A-Time)
Query evaluation strategy that processes one document at a time, accumulating contributions from all query terms for each document. Contrasted with TAAT (Term-At-A-Time). Enables early termination and WAND pruning.
DCG (Discounted Cumulative Gain)
Ranking metric: Σ rel(i) / log₂(i+1). The denominator penalizes relevant documents at lower ranks. Normalized by IDCG to produce NDCG.
Delete bitmap
RoaringBitmap of DocId values logically deleted from a segment. Applied as a filter at query result time. Compacted (removed) during segment merge. Maintains I6.
df (Document Frequency)
Number of documents containing a given term. Used in IDF calculation. Must be summed across all live segments for correctness; partial df from a single segment produces wrong IDF.
Delta encoding
Storing the difference between consecutive ascending integers rather than raw values. Applied to DocId in postings lists. Reduces average VByte byte width from 4 to 1–2 bytes for typical postings with sequential doc IDs.
DocId
Newtype u32. Monotonically increasing integer within a segment. Never reused after deletion. Packed with segment_index: u32 into GlobalDocId: u64.
DocStore
Per-document storage: {doc_id, field_lengths: HashMap<FieldName, u32>, stored_fields: HashMap<FieldName, String>}. Field lengths power BM25 length normalization; stored fields power snippet generation.
FST (Finite-State Transducer)
A compressed, ordered map from strings to values. O(len(term)) lookup with no heap allocation. Minimal memory footprint (≈1 byte/entry). Requires lexicographic key insertion order (I8). Used as the on-disk term dictionary from Phase 4.
GlobalDocId
Newtype u64. Encodes (segment_index: u32) << 32 | (local_doc_id: u32). Invalidated on segment merge (I10). Callers must not cache GlobalDocId across merge operations.
IDF (Inverse Document Frequency)
Measure of term rareness: inverse of the proportion of documents containing the term. Robertson IDF: ln((N - df + 0.5) / (df + 0.5) + 1). Always positive. Terms in fewer documents have higher IDF.
index.meta
File listing active SegmentIds forming the current index snapshot. Updated atomically via std::fs::rename. Ensures readers always observe a consistent segment list (I5).
Inverted index
Mapping from each term to its postings list: the list of documents containing that term with frequency information. The fundamental data structure of full-text search. Contrasted with a forward index (document → terms).
k1 (BM25 parameter)
TF saturation parameter. At k1=0: binary scoring (TF irrelevant). As k1→∞: approaches raw TF weighting. Default: 1.2. Range: [0.0, ∞).
MAP (Mean Average Precision)
Mean over all queries of Average Precision. AP = mean Precision@K at each rank K where a relevant document appears.
mmap
Memory-mapped I/O. Maps segment file into virtual address space; reads are zero-copy slice operations (P8). Risk: SIGBUS if file is truncated after mapping (T5).
MRR (Mean Reciprocal Rank)
Mean of 1/rank(first_relevant) across all queries. Measures how quickly the first relevant document is found.
NDCG@K (Normalized Discounted Cumulative Gain)
DCG@K / IDCG@K. Normalized to [0,1]. Standard metric for graded relevance evaluation. Primary quality target: NDCG@10 ≥ 0.18 on MS MARCO dev.
NFKC
Unicode Normalization Form KC: compatibility decomposition followed by canonical composition. Handles ligatures (ﬁ → fi), superscripts, compatibility forms. Applied by the unicode-normalization crate.
Okapi BM25
The specific BM25 variant developed at the Okapi IR system (City University London), standardized by Robertson et al. SIGIR 1994. The formula used as default in this blueprint.
PFOR-delta (Patched Frame Of Reference)
Integer compression codec that encodes integers as deviations from a frame of reference (base value), with exception patches for outliers. Enables AVX2-vectorized decoding. Phase 6+ codec.
Phrase query
Query requiring terms to appear adjacent (or within a slop window) in the document. Requires positional index. "systems programming"~2 = exact phrase with slop ≤ 2.
Porter2
The Snowball variant of the Porter stemming algorithm. IR standard for English; available via rust-stemmers. Reduces inflected forms to their root: "running" → "run".
Postings list
Sorted list of (DocId, TermFreq, [positions]) entries for documents containing a specific term. Sorted by DocId (I1). Skip pointers enable O(log n) seek.
RoaringBitmap
Compressed bitset using mixed array/bitmap/run-length containers. O(1) membership test; union in O(n/64). Standard delete bitmap representation (Lucene, Tantivy, this project).
Robertson IDF
BM25 IDF formula: ln((N - df + 0.5) / (df + 0.5) + 1). Always positive; standard BM25 IDF. Contrasted with smooth IDF (TF-IDF variant): ln((N+1)/(df+1)) + 1.
Scorer
Trait with score(tf, doc_len, df, num_docs, avgdl) -> f32 and max_term_score(df, num_docs) -> f32. Implemented by TfIdfScorer, Bm25Scorer, Bm25fScorer. Generic over scoring model (P9).
Segment
Immutable unit of index storage: term dictionary + postings + doc store + delete bitmap + CorpusStats. Written once; never mutated (P3, I4). Multiple segments form an Index.
SegmentId
UUID v4. Stable across restarts. Used in index.meta to identify active segments.
Skip pointer
Periodic index into a postings list: every SKIP_STRIDE=64 entries, stores (doc_id_at_position, byte_offset). Enables O(log n) seek(target) without decompressing the entire list (I13, P13).
Slop
Maximum allowed gap between consecutive phrase terms in position space. slop=0: exact phrase. slop=2: up to 2 intervening words.
TF (Term Frequency)
Number of times a term appears in a document. Used in TF-IDF and BM25 scoring. BM25 applies TF saturation via k1 to prevent spamming.
TF-IDF
Term Frequency × Inverse Document Frequency. Classic scoring model. Multiplies how often the term appears in the document by how rare it is in the corpus.
TermDictionary
Maps normalized term strings to monotonically assigned TermId integers. Phase 0: HashMap. Phase 4+: fst::Map.
TermFreq
Newtype u32. Raw occurrence count of a term in a document. Clamped at 65535 (u16::MAX) for pathological documents.
TermId
Newtype u32. Monotonically assigned within a segment. Stable across queries against the same segment (I12). Reassigned on segment merge.
TieredMergePolicy
Segment merge strategy grouping segments by size into tiers; merges within a tier when count exceeds threshold. Amortizes merge cost; bounds segment count at ≤ 70 for 10M documents.
Token
{text: String, start: ByteOffset, end: ByteOffset, position: u32}. text is the normalized, stemmed form. start/end reference the original source text (not the stemmed form) for highlighting.
TREC
Text REtrieval Conference. Standard venue and format for IR evaluation. .qrel files specify relevance judgments for queries.
UAX #29
Unicode Standard Annex #29: Unicode Text Segmentation. Defines word-break rules used by the Unicode-aware tokenizer.
VByte
Variable-length integer codec: 7 data bits per byte, high bit = continuation flag. Encodes u32 as 1–5 bytes. Delta-encoding reduces average width to 1–2 bytes for sequential doc IDs.
WAL (Write-Ahead Log)
Append-only binary log of IndexCommand entries with monotonically increasing sequence numbers (I11). Enables crash recovery via replay. Truncated at last valid CRC-checked entry on corruption.
WAND (Weak AND)
Top-K retrieval algorithm using per-term upper-bound scores to skip documents whose maximum possible score is below the current K-th threshold. O(K × constant) amortized vs O(Σdf) naive. Broder et al. CIKM 2003. ---
