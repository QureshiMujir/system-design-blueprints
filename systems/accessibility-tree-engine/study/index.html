Mental Models & First Principles

The compressed intuitions an expert holds about this engine. Each: the model · what it predicts · the bug class written without it · where this blueprint applies it.

  • MM1 — The AX tree is a projection, not a copy. The DOM is the source of truth; the AX tree is f(styled DOM) — pruned, reparented, role-coalesced, recomputed on change. Predicts: you never "edit" the AX tree directly; you change the DOM and re-derive. Bug without it: mutating AXNodes in place and drifting from the DOM (the stale-tree class). Applied: §3 (persistence boundary = NONE), §8, Phase 6/8 (## 18/## 20).
  • MM2 — Invalidation is the whole game; computation is easy. Computing a role/name once is trivial; knowing exactly which nodes a mutation invalidated is the hard, correctness-critical part. Predicts: dependency edges (name-from-content ancestors, aria-labelledby referrers) dominate the design, not the per-node math. Bug without it: under-invalidation → stale name/state to AT. Applied: P3, I-8, Phase 8 deps (## 20).
  • MM3 — Over-invalidate, never under-invalidate. The two error directions are not symmetric: over-marking wastes CPU (recoverable), under-marking ships a wrong tree (silent S1 incident). Predicts: when unsure whether a mutation affects a node, dirty it. Bug without it: a "clever" minimal-dirtying heuristic that misses a dependency. Applied: P3, I-8, Performance Engineering (dirty-set vs cost).
  • MM4 — A name is a recursive computation over an adversarial graph. aria-labelledby makes naming mutually recursive across arbitrary author-controlled id refs, which can cycle. Predicts: termination needs a visited set + non-reentry, not a depth limit alone. Bug without it: hang / stack overflow on cyclic aria-labelledby (a real a11y DoS). Applied: P4, I-2, ADR-09, Phase 5 (## 17).
  • MM5 — Generational ids make use-after-free a typed miss, not a crash. An AXNodeId is index+generation; a stale id fails resolution rather than aliasing a recycled slot. Predicts: reparent/prune churn is safe without Rc<RefCell> cycles or raw pointers. Bug without it: dangling-pointer CVEs that dominate C++ a11y-engine history. Applied: ADR-05, I-10, §11.1.
  • MM6 — "Unset" and "false" are different values. ARIA tri-state (checked=mixed, pressed absent vs =undefined) means a boolean cannot encode the domain. Predicts: state is quad-valued (True/False/Mixed/Undefined) and "key absent" ≠ Undefined. Bug without it: a non-toggle button announced as un-pressed, or mixed collapsed to false. Applied: ADR-07, §11.1, Phase 4 (## 16).
  • MM7 — Pruning must be auditable, never silent. "Why did my element vanish from the AX tree?" is the #1 a11y debugging question; deletion destroys the answer. Predicts: excluded nodes stay in the arena with an IgnoredReason, not dropped. Bug without it: undiagnosable missing-element reports. Applied: P6, I-6, Phase 6 (## 18).
  • MM8 — The diff stream is a log; a gap desyncs the consumer. AT reconstructs state by applying ordered AXTreeUpdate deltas from a baseline — exactly like a replication log. Predicts: updates are causal+ordered (removals→adds→reparents→field changes) and a dropped update forces a full re-baseline. Bug without it: out-of-order NodeAdded before its parent → orphan apply. Applied: P12, I-9, ADR-13, Phase 8 (## 20), Operational Readiness (stream lifecycle).
  • MM9 — Platform mapping is a pure leaf function, deliberately. Each map_* depends on one AXNode only — no tree walk, no retained state. Predicts: projections are cacheable, parallelizable, trivially diffable, and the stale-state bug class cannot reappear at the platform boundary. Bug without it: backend-held state desyncs from the tree (P3's bug, one layer down). Applied: P10, I-11, ADR-14, Phase 9 (## 21).
  • MM10 — Spec is the oracle; a single browser is not. Behavior derives from WAI-ARIA/HTML-AAM/accname/Core-AAM, cross-checked differentially against Chromium — divergences are spec-clause disputes, not "Chromium is right." Predicts: every fixture maps to a clause; intentional spec-correct deviations are enumerated, not hidden. Bug without it: copying a browser quirk as if it were the spec. Applied: P1, ADR-20, Phase 12 (## 24), Compatibility & Versioning (differential parity).

Glossary · 54 terms · site-wide glossary

accessibility tree
Derived projection of the styled DOM exposing roles/names/descriptions/states/properties/relations to assistive technology. Represented by AXTree; differs from the DOM via pruning + aria-owns reparenting.
accessible object
A single exposed node in the accessibility tree. Concretely an AXNode with ignored == false.
AXNode
ax-core struct: {id, role, name, description, states, props, dom_node, parent, children, ignored, bounds}. The unit of the AX tree.
AXNodeId
Generational u32 handle into the AXTree arena; stable across recompute unless the node is removed.
role
The semantic category of an AXNode (Role enum). Drives name-from-content gating, state validity, and platform mapping.
explicit role
First valid, non-abstract token parsed from the role attribute fallback list (parse_role_tokens). Highest precedence.
implicit role
Host-language role from HTML-AAM tag+attribute table / input[type] matrix (implicit_role). Used when no explicit role applies.
abstract role
A Role taxonomy category (RoleType, Widget, Composite, Input, Landmark, Range, Section, Sectionhead, Select, Structure, Window, Command) NEVER valid as an attribute value; rejected by parse_role_tokens -> AbstractRoleUsed.
computed role
Final resolved role per precedence: explicit -> implicit -> Generic (compute_role).
generic role
Role::Generic fallback when no explicit/implicit role yields semantics.
presentational role
role=presentation/none -> flatten element, keep children, drop its semantics.
presentational role conflict resolution
A presentational element is re-exposed (not flattened) if it is focusable or carries global ARIA.
ARIA
Author-supplied accessibility semantics via role/aria-* attributes.
WAI-ARIA
The W3C spec (1.2) defining ARIA roles/states/properties; normative reference.
HTML-AAM
"ARIA in HTML" mapping spec; source of implicit_role and native-state contributions.
Core-AAM
"Core Accessibility API Mappings 1.2"; governs ax-platform role/state -> UIA/IA2/AT-SPI2/NSAccessibility.
accname
"Accessible Name and Description Computation 1.2"; algorithm implemented by compute_name/compute_description.
accessible name
The computed label of an AXNode (AccessibleName{text, from, sources}).
accessible description
Supplementary computed text (AccessibleDescription{text, from}), distinct from the name.
name from content
Name derived by recursively concatenating descendant names; only when the role permits (gated). NameFrom::Contents.
name from author
Name from author-supplied aria-label/aria-labelledby. NameFrom::Author.
aria-labelledby
Highest-precedence name source; concatenates names of referenced nodes (recursing, but a labelledby traversal does not re-enter the same labelledby).
aria-label
Direct author string; used when non-empty and no aria-labelledby.
aria-describedby
Reference source for the accessible description; resolves to AXRelation::DescribedBy.
state vs property
State = dynamic, machine-changeable condition (AXStateSet, e.g. checked/expanded); property = relatively static characteristic (AXPropertyMap, e.g. level/setsize).
tri-state
AXStateValue{True, False, Mixed, Undefined}; e.g. aria-checked="mixed", aria-pressed.
aria-hidden
aria-hidden=true prunes the node + subtree (ignored=true). A focusable aria-hidden node is an authoring error (engine still honors hidden).
pruning
Excluding nodes/subtrees from the AX tree (display:none, aria-hidden, no-semantics).
included-in-tree / ignored node
is_included decides exposure; ignored == true nodes exist in the arena but are not surfaced to AT.
relations
Non-parent/child links (AXRelation: Owns, Controls, LabelledBy, DescribedBy, FlowTo, ActiveDescendant, Details, ErrorMessage).
aria-owns
Reparents referenced nodes under the owner in the AX tree (DOM order otherwise); resolved by apply_relations.
reparenting
Moving an owned node out of its DOM-order AX parent under the aria-owns owner.
orphan
A relation reference to a non-existent/unincluded target; AXError::OrphanReference.
live region
A subtree (aria-live/Alert/Log/Status/...) whose changes AT announces; aria-atomic/aria-relevant modulate announcements.
landmark
Navigational region role (Banner, Main, Navigation, Region, Search, ...).
composite widget
A role managing owned child widgets + focus (ComboBox, Grid, ListBox, Menu, Tree, ...).
platform mapping
Translating an AXNode to a platform schema via map_uia/map_ia2/map_atspi/map_macos.
UIA
Microsoft UI Automation; e.g. Button -> ControlType.Button.
IAccessible2
Cross-platform extension of MSAA; e.g. Button -> ROLE_PUSH_BUTTON.
MSAA
Microsoft Active Accessibility; legacy base IA2 extends.
AT-SPI2
Linux/GNOME accessibility bus; e.g. Button -> PUSH_BUTTON.
NSAccessibility
macOS accessibility protocol; e.g. Button -> NSAccessibilityButtonRole.
AXTreeUpdate
Serialized incremental diff (NodeAdded/NodeRemoved/RoleChanged/NameChanged/StateChanged/Reparented) emitted by recompute.
AXTreeSerializer
Chromium component whose minimal-diff semantics the recompute + AXTreeUpdate emission mirror.
dirty node
An AXNode flagged by mark_dirty (in AXTree.dirty) needing recompute after a DOM mutation.
incremental serialization
Recomputing only dirty subtrees and emitting the minimal AXTreeUpdate set, not a full re-serialization.
assistive technology
External consumer (screen reader, etc.); not implemented here — we model the platform projection + PlatformBackend.
focusable
Whether the host node can receive focus (DomNode::is_focusable); affects presentational conflict resolution + the focusable state.
aria-activedescendant
AXRelation::ActiveDescendant; points the active descendant within a composite widget without moving DOM focus.
name-from-content gating
The role-keyed allowlist (button/link/heading/cell/menuitem/...) deciding whether compute_name may use name-from-content.
DomNode
ax-dom trait abstracting the styled host DOM (local name, attrs, computed display/visibility, focusability, text, native state, shadow/slot).
OpaqueDomId
Stable host-node identity used in dom_to_ax, name-computation visited sets, and mark_dirty.
PlatformBackend
ax-platform trait (apply(&mut self, updates: &[PlatformUpdate])); default inspect/JSON backend; real OS IPC deferred.
PhaseDeferred
Marker for deliberately out-of-scope work (concrete OS accessibility-API IPC).
