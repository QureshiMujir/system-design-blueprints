262 — Accessibility Tree Engine

Project Number: 262

Project Name: Accessibility Tree Engine

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

Compute the accessibility tree — roles, accessible names/descriptions, states, properties, relations — that a styled DOM exposes to assistive technology, and keep it incrementally correct under DOM mutation.

Engineering definition. A from-scratch Rust engine that derives the accessibility tree (a tree of AXNode accessible objects) from a styled host DOM. It performs: (1) computed role = explicit ARIA role token-list parse → implicit HTML-AAM role → Generic; (2) accname accessible name + description (recursion, visited guard, role-gated name-from-content); (3) state vs property computation (ARIA + native host state, tri-state AXStateValue); (4) tree construction with pruning of aria-hidden/display:none/presentational nodes; (5) relations + aria-owns reparenting (cycle/orphan/duplicate guards); (6) incremental recompute → minimal AXTreeUpdate diffs; (7) Core-AAM platform mapping (UIA / IAccessible2+MSAA / AT-SPI2 / NSAccessibility) as a serializable projection. Generic over the host via the DomNode trait (mirrors project 258 Element, 261 EventTarget).

System boundary. Input = a styled DomNode tree (computed display/visibility, attributes, ARIA, native form state, shadow/slot, focusability). Output = an AXTree + serialized AXTreeUpdate stream + per-platform projection consumed via PlatformBackend.

NON-goals (do not build):

Out of scope Provided by / how handled
DOM/CSS engine, layout, computed-style resolution consumed via DomNode (projects 124/260)
HTML parsing upstream; we read a parsed styled tree
Layout / paint / render, bounds geometry host supplies Rect; we do not lay out
Actual screen reader, speech, braille, TTS external AT consumes our export
Real OS a11y-API IPC (UIA/IA2/AT-SPI2/AX wire) modeled behind PlatformBackend; PhaseDeferred("## 21. Phase 9 — Platform mapping (Core-AAM)") (Deferred Features Register)
Authoring an assistive technology n/a

Deployment model. Embeddable no_std + alloc Rust library (ax-core/ax-role/ax-name/ax-build) + std edges (ax-dom, ax-platform) + the axtree CLI (build/dump/diff/name-trace/validate). Linked into browser engines, headless/testing harnesses, and a11y linters/auditors.

Target users. Browser-engine accessibility implementers; a11y tooling/QA/audit engineers (axe-core-class linters, conformance harnesses); embedders needing a Chromium-AXTree-shaped projection without a full browser.

Phase-0 deliverable — the Cargo workspace, 7 ax-* crates:

  1. ax-core — normative types: AXNode, AXNodeId, Role, AXStateSet, AXPropertyMap, AccessibleName/AccessibleDescription, AXRelation, AXTree, AXTreeUpdate, AXError.
  2. ax-dom — the DomNode trait + a concrete reference styled-DOM arena (tests/CLI/conformance/fuzz).
  3. ax-role — explicit ARIA parse + implicit HTML-AAM role + role validation.
  4. ax-name — accname name + description algorithm.
  5. ax-build — DOM→AX walk, inclusion/exclusion, relations + owns reparent, incremental recompute.
  6. ax-platform — Core-AAM mapping → {UIA, IA2+MSAA, AT-SPI2, macOS} + PlatformBackend.
  7. ax-cli — the axtree binary.

Phase-0 smoke test: <button>Hi</button> → role=Button, name="Hi".

What later phases unlock. P1 reference DOM → P2 explicit roles → P3 implicit HTML-AAM → P4 states/properties → P5 accname → P6 prune/build → P7 relations/owns → P8 incremental diffs → P9 platform export → P10 focus/hit-test/live regions → P11 validation + inspector + name-trace → P12 conformance (WPT wai-aria/accname/html-aam) + differential-vs-Chromium + fuzz + benches.

Deferred behind PhaseDeferred. Concrete OS IPC for UIA/IA2/AT-SPI2/NSAccessibility (anchor ## 21); full live region timing/queuing semantics (## 22); shadow-DOM slot/reparenting + cross-shadow relation edge cases (## 18, ## 19). All five are enumerated in the Deferred Features Register with un-defer triggers.

Timeline. Phase-0 walking skeleton 6–14 weeks; full 13-phase engine months.

Recommended language — Rust (edition 2021, MSRV 1.78). The AX tree is an invalidation-driven projection of a large mutable tree: ownership + typed sum types (Role, tri-state AXStateValue) catch the role/state-mapping and stale-tree bug classes that dominate C++ a11y-engine CVE/incident history; arena + generational AXNodeId model the DOM↔AX mapping without dangling refs. Rejected: C/C++ (the cautionary bug history), Go (weak sum types, GC pauses on the incremental path), TypeScript (no no_std/allocation control).

Prerequisites. DOM tree model; WAI-ARIA 1.2, HTML-AAM, accname 1.2, Core-AAM 1.2 specs; tree traversal/diff algorithms; Rust arenas + generational ids; incremental computation (dirty-marking, AXTreeSerializer-style minimal diffs).

2. Why Build This

2.1 Unique systems knowledge

This is the only portfolio project where the deliverable is a derived semantic projection of a large mutable tree, kept correct under mutation. Distinct muscles, each rare:

Skill What it forces Where it lives
Derived-tree computation AX tree ≠ DOM tree: pruned, reparented, role-coalesced. The mapping dom_to_ax is many-to-fewer + reordered ax-build::build_tree, AXTree.dom_to_ax
Role/state mapping algebra Closed taxonomy (Role, AXStateValue tri/quad-state) with precedence: explicit → implicit (HTML-AAM) → Generic; presentational role conflict resolution ax-role::compute_role, ax-core::AXStateSet
Recursive accname w/ cycle guards Mutually-recursive name resolution over aria-labelledby + name-from-content; NameContext.visited prevents infinite recursion on cyclic refs; whitespace flatten/trim ax-name::compute_name
Incremental invalidation + minimal diff Dirty-mark a MutationKind, recompute only dirty subtrees, emit minimal AXTreeUpdate set. Mirrors Chromium AXTreeSerializer ax-build::mark_dirty / recompute
Dependency tracking Name depends on descendants (name-from-content) + aria-labelledby targets → those edges must dirty the dependent AXNode ax-build dirty propagation
Platform mapping One Role → 4 platform schemas (UIA / IA2+MSAA / AT-SPI2 / NSAccessibility); serializable projection behind PlatformBackend ax-platform::map_{uia,ia2,atspi,macos}

The combinatorics — roles × states × host-language defaults × pruning rules × relation reparenting — are exactly where typed sum types + arena/generational ids (AXNodeId(u32)) earn their keep: stale-tree and role/state-mapping bugs become unrepresentable or compile errors, not the dangling-pointer CVEs that define C++ a11y-engine history.

2.2 Why the accessibility tree matters

  • Architecturally: the AX tree is the contract between the web platform and assistive technology. Screen readers never see the DOM — they see this projection via UIA/IA2/AT-SPI2/NSAccessibility. It is the least-understood but highest-impact derived tree in a browser (DOM, layout tree, paint tree, AX tree).
  • Historically: codified by WAI-ARIA 1.2 + HTML-AAM + accname 1.2 + Core-AAM 1.2; the reference implementations (Chromium AXObjectCacheImpl/AXTree, Firefox DocAccessible, WebKit AXObjectCache) all converged on the same derived-tree + incremental-serialization shape this project rebuilds.
  • Legal/regulatory weight: correctness is enforceable, not optional — WCAG 2.x, the ADA (US), Section 508, and EN 301 549 (EU procurement) make a wrong role or empty accessible name a compliance defect, not a cosmetic one.

2.3 Portfolio cross-links

  • 258 CSS Selector Engine — DomNode mirrors 258's Element; computed style (computed_display_is_none, computed_visibility_hidden) drives pruning.
  • 260 Browser Rendering Pipeline — adds the AX tree as the fourth derived tree alongside layout/paint; shares the styled-DOM input.
  • 261 DOM Event System — EventTarget analog; supplies focus + activation, feeding focused/focusable states + aria-activedescendant (Phase 10).
  • 263 Islands hydration — hydrated islands must keep the AX tree correct across client takeover → exercises mark_dirty/recompute incremental path.
  • Incremental-computation / reactive-runtime projects — same invalidation discipline (dirty set, minimal diff) as a reactive graph, applied to a semantic tree.

2.4 Calibration value

Teaches building to four interlocking W3C specs at once under a legal correctness bar, with a fully testable oracle (WPT wai-aria/accname/html-aam + differential vs Chromium AX dump, Phase 12). Few engineers have touched the AX layer; the role/state algebra + recursive accname + incremental-diff trifecta is a strong staff/principal calibration signal.

2.5 What Mastery Looks Like

After building this engine you can, on demand:

  • Derive a semantic projection of a mutable tree and keep it incrementally correct — dirty-mark, propagate dependency closure, emit a minimal diff, prove it equals a full rebuild (Phases 6/8, ## 18/## 20).
  • Resolve a closed taxonomy with precedence + conflict resolution — explicit→implicit→fallback role computation with presentational re-exposure, expressed as total functions over a sum type (Phases 2/3, ## 14/## 15).
  • Write a terminating recursive resolver over an adversarial reference graph — accname with a visited set + non-reentry guard that never hangs on cyclic aria-labelledby (Phase 5, ## 17).
  • Reparent a tree under id-reference relations with structural guards — aria-owns one-owner / no-cycle / no-orphan enforcement that never corrupts the parent/child forest (Phase 7, ## 19).
  • Build a stale-tree-proof identity model — generational arena ids that turn use-after-free into a typed miss, the type-level defense against the bug class that dominates C++ a11y CVEs (Phase 6, ## 18).
  • Project one model onto four platform schemas as pure total functions — Core-AAM role/state mapping to UIA/IA2/AT-SPI2/NSAccessibility, differential-tested against Chromium (Phase 9, ## 21).
  • Stand up a spec-as-oracle conformance harness — WPT buckets + differential vs a real browser AX dump + fuzz equivalence as the "done" gate (Phase 12, ## 24).

Boundaries (LOCKED):

Boundary Where Rule
Trust DomNode inputs (role attr, aria-*, text, native state) All author markup + ARIA UNTRUSTED: every token validated, every relation cycle/orphan-guarded, every recursion visited-guarded. No input crashes/loops the engine; malformed -> Generic / ignored / AXError, never panic.
Recompute / concurrency build_tree + recompute (ax-build) SINGLE-THREADED over an immutable DOM snapshot. No interior mutation of the host during a walk; one writer to AXTree.dirty. Parallelism only as a future opt-in (PhaseDeferred); correctness never depends on it.
Cross-process ax-platform export -> AT The ONLY place AX state leaves the host. Crossed exclusively as a serializable projection (PlatformUpdate) + AXTreeUpdate diffs; real OS IPC deferred behind PlatformBackend / PhaseDeferred.
Persistence NONE The accessibility tree is a DERIVED, EPHEMERAL projection of the styled DOM. No on-disk state, no DB, no cache survives a process. The sole serialized form is the AXTreeUpdate diff stream (mirrors Chromium AXTreeSerializer). Rebuildable from scratch via build_tree.

3.2 Components (one box per crate)

ax-role — Computes the Role for every element. In: a DomNode (role attr, local name, namespace, key attributes). Out: exactly one Role. Pipeline: parse_role_tokens (first valid, non-abstract token of the role fallback list) -> implicit_role (HTML-AAM tag+attribute table + input[type] matrix) -> Generic. Key invariant: the computed role is ALWAYS a concrete enum variant — abstract roles (Widget, Composite, Landmark, Range, …) are NEVER produced as values (rejected by parse_role_tokens, surfaced as AXError::AbstractRoleUsed in validate_role). Referenced by: Phase 2 (## 14 explicit), Phase 3 (## 15 implicit), Phase 5 (name-from-content gating), Phase 6 (presentational flatten), Phase 11 (## 23 validate_role).

ax-name — Computes AccessibleName + AccessibleDescription per accname 1.2. In: a DomNode + its already-computed Role (compute_name<N>(n, role)). Out: AccessibleName{ text, from: NameFrom, sources } + AccessibleDescription. Algorithm: role-gated precedence aria-labelledby (concatenate referenced node names, recursing) -> aria-label (non-empty) -> native (label/alt/caption/legend/figcaption/title) -> name-from-content (ONLY if Role permits) -> title/placeholder; whitespace flattened + trimmed. Key invariant: termination — NameContext.visited (OpaqueDomId set) + in_aria_labelledby guard make recursion total on cyclic/self references; a labelledby traversal never re-enters the same labelledby. Referenced by: Phase 5 (## 17), Phase 8 (## 20 name depends on descendants + labelledby targets -> dirty propagation), Phase 11 (## 23 name-trace).

ax-build — Constructs and maintains the AXTree. In: DOM root (build_tree<N>(root)) + mutation signals (mark_dirty(tree, dom, kind)). Out: AXTree, then Vec<AXTreeUpdate> from recompute. Does: DOM->AX walk, is_included inclusion/exclusion (display:none subtree drop, aria-hidden prune, presentational flatten), apply_relations (aria-owns reparenting + relation resolution), maintains dom_to_ax mapping, dirty marking + minimal-diff recompute. Key invariant: structural integrity — every reachable AXNode has ≤1 owner; parent/children form a single acyclic tree; dom_to_ax stays bijective over non-ignored nodes; recompute emits the MINIMAL AXTreeUpdate set and never a full re-serialization. Referenced by: Phase 6 (## 18 build/prune), Phase 7 (## 19 relations/owns), Phase 8 (## 20 incremental), Phase 10 (## 22 focus/hit-test/live-region recompute).

ax-core — Normative type vocabulary; the shared contract every other crate depends on. In: nothing (pure types). Out: AXNode, AXNodeId, Role, AXStateValue/AXStateSet, AXPropertyMap, AccessibleName/NameFrom/NameSource, AccessibleDescription, AXRelation, AXTree, AXTreeUpdate/AXEvent, AXError. no_std + alloc. Key invariant: AXNodeId is a GENERATIONAL id into AXTree.nodes: Arena<AXNode> — a stale id resolves to None/AXError::OrphanReference, never a dangling/aliased node (the type-level defense against the stale-tree class that dominates C++ a11y CVEs). Tri/quad-state AXStateValue{True,False,Mixed,Undefined} makes "unset vs false" unrepresentable-as-the-same. Referenced by: ALL phases (every crate imports it); Phase 0 (## 12 onward).

ax-platform — Maps the in-memory AXNode to platform-specific projections per Core-AAM 1.2. In: &AXNode. Out: map_uia->UiaNode, map_ia2->Ia2Node, map_atspi->AtspiNode, map_macos->MacAxNode; a serializable export consumed by PlatformBackend::apply(&[PlatformUpdate]) (default inspect/JSON backend; real OS IPC deferred). std. Each Role->platform role + states->platform state bits (e.g. Button -> UIA ControlType.Button / IA2 ROLE_PUSH_BUTTON / AT-SPI2 PUSH_BUTTON / NSAccessibilityButtonRole). Key invariant: mapping is a PURE, total projection of one AXNode — no host access, no mutation, every Role/state has a defined mapping on all four targets (no silent drop). The cross-process boundary lives here and nowhere else. Referenced by: Phase 9 (## 21), Phase 12 (## 24 differential vs Chromium AX dump).

ax-dom — The styled-host abstraction + a concrete reference DOM. Out: the DomNode trait (local_name, namespace, attr, aria, computed_display_is_none, computed_visibility_hidden, is_focusable, text_content, native_state, parent/children, assigned_slot, shadow_root, opaque) + an arena-backed reference DOM with a fixture builder for tests/CLI/conformance/fuzz. std. Key invariant: the engine reads style + structure ONLY through DomNode — it consumes computed style + attributes, never parses HTML/CSS or lays out (NON-GOAL); opaque() -> OpaqueDomId is stable per DOM identity so dom_to_ax + visited sets are well-defined. Mirrors project 258's Element / 261's EventTarget. Referenced by: Phase 1 (## 13 reference DOM), and as the input trait for every compute/build phase.

ax-cli — The axtree binary: developer + conformance entry point. In: a DOM fixture (CLI/file). Out: subcommands build, dump (serialized AXTree), diff (two AXTree -> AXTreeUpdate set), name-trace (per-node accname precedence trace), validate (AXError + authoring diagnostics). std; depends on all crates + ax-dom. Key invariant: a thin orchestration shell — ZERO accessibility logic of its own; it only sequences build_tree/recompute/map_*/validate_role, so CLI output is byte-identical to library results (the conformance + differential harness drives the engine through it). Referenced by: Phase 11 (## 23 inspector + name-trace), Phase 12 (## 24 conformance/differential/fuzz/bench harness).

4. System Constraints

Derived projection over a large mutable tree → constraints are dominated by invalidation cost, recursion bounds, and the platform serialization boundary. In-process engine: no NUMA / network / FD budgets. Single boundary that is I/O: ax-platform serialized export → PlatformBackend (size + throughput targeted below).

4.1 Performance budgets

ID Operation Metric Target Crate
P1 Full build_tree over 100k-node styled DOM wall < 50 ms (≤ 0.5 µs/node amortized) ax-build
P2 Incremental single-attr change (mark_dirty→recompute→AXTreeUpdate) p50 < 100 µs ax-build
P3 same p95 < 500 µs ax-build
P4 same p99 < 2 ms ax-build
P5 compute_role per node (explicit→implicit→generic) wall < 1 µs ax-role
P6 compute_name (accname, role-gated, subtree-bounded) wall O(visited subtree); < 10 µs typical widget ax-name
P7 apply_relations owns-reparent + cycle check (≤10k relations) wall < 5 ms ax-build
P8 Per-Role platform map (map_uia/map_ia2/map_atspi/map_macos) wall < 200 ns/node ax-platform
P9 Cold start to first build_tree callable global init 0 (no statics, no lazy global) all
  • P1/P2 invariant: incremental path touches only dirty subtrees — recompute cost ∝ |dirty closure|, NOT tree size. Name-from-content + aria-labelledby targets propagate dirtiness to dependents.
  • accname cost = O(distinct visited nodes) bounded by NameContext.visited (no node counted twice) AND by the recursion-depth cap (C2).

Item Budget Note

4.3 Hard caps (DoS / adversarial markup)

ID Cap Limit On exceed
C1 DOM→AX walk depth 4096 stop descent; node ignored=true
C2 accname recursion depth 64 truncate, return partial name (no panic)
C3 aria-owns chain depth 256 reject further owns; AXError::RelationCycle if loop
C4 max relation references per node (IDREF list) 1024 drop excess; AXError::OrphanReference logged
C5 dirty-set size per recompute ≤ tree node count; degrades to full rebuild if ≥ 50% bounded, no unbounded growth
C6 role token-list length parsed 64 tokens first valid non-abstract wins (precedence)
  • Cycle detection: apply_relations runs DFS color-marking over the owns/relation graph → O(V+E), V,E ≤ caps; duplicate ownership & self-ownership rejected (a node has ≤1 owner).

4.4 Robustness & safety invariants

  • Never panics on adversarial markup (deep nesting, cyclic aria-owns/aria-labelledby, malformed roles, dangling IDREFs, huge attr lists): all fallible paths return Result<_, AXError>; enforced by fuzz (Phase 12).
  • No unsafe in ax-core/ax-role/ax-name/ax-build (arena uses generational AXNodeId, no raw pointers → no dangling on DOM↔AX remap).
  • No global mutable state: every entry point takes explicit &N: DomNode / &mut AXTree (P9).
  • Determinism: identical styled DOM → byte-identical AXTree + export (stable child/sibling order; owns-reparent preserves deterministic order).
  • no_std + alloc core (ax-core/ax-role/ax-name); std confined to ax-dom, ax-platform, ax-cli.
  • MSRV 1.78, edition 2021; zero build.rs codegen in core crates.

6.2 Principle detail

  • P1 Spec is the oracle. Behavior derives from the four normative specs, not intuition or imitation of a single browser. Tradeoff: slower to author than copying Blink; spec ambiguities require a recorded ADR. Operational: every Phase 12 (## 24) WPT fixture maps to a spec clause; differential runs flag ax-build vs Chromium AX dump deltas as spec-clause disputes. Violation: divergent role/name across engines -> AT users get behavior no author tested against.
  • P2 Never silently drop a name. A computed empty name on a node the spec names is treated as a defect, surfaced by name-trace, and asserted in conformance. Tradeoff: tolerating a wrong-but-present name vs an empty one — present-but-wrong is still less catastrophic than silence. Operational: compute_name records NameFrom + Vec<NameSource>; NameFrom::Prohibited is the only legitimate empty. Violation: a button reads as "button" with no label -> unusable control, the dominant a11y incident class.
  • P3 Incremental correctness over speed. A mark_dirty/recompute pass must converge to exactly the full-rebuild tree. Name-from-content + aria-labelledby dependencies dirty the dependent, not just the mutated node. Tradeoff: conservative dirtying costs CPU; correctness wins every time. Operational: Phase 8 (## 20) asserts recompute(after N mutations) == build_tree(final DOM) via a fuzz oracle. Violation: stale AXNode -> AT announces a control that moved/changed/vanished.
  • P4 Bounded recursion. accname recursion and owns resolution carry a NameContext.visited set + a hard depth cap; exceeding it truncates deterministically, never overflows. Tradeoff: a pathological deep label may truncate. Operational: caps are constants in ax-name/ax-build, fuzzed in Phase 12. Violation: adversarial DOM -> stack overflow / hang in compute_name.
  • P5 No cycles. apply_relations rejects relation cycles and self/duplicate ownership before mutating structure. Tradeoff: one extra graph pass per build. Operational: a node has at most one owner; second owner -> AXError::RelationCycle/dropped per Phase 7 (## 19) rules. Violation: infinite reparent loop or non-terminating recompute.
  • P6 Pruning is reversible + auditable. Inclusion is a pure function is_included(n, role); excluded nodes keep ignored=true with a reason (display:none / aria-hidden subtree / presentational flatten / no semantics), not deletion. Tradeoff: memory for ignored nodes + reasons. Operational: axtree dump shows ignored nodes + cause; un-hiding re-includes by clearing dirty. Violation: a node disappears with no trace -> undiagnosable "missing element" bugs.
  • P7 Generic over the host DOM. No core crate names a concrete DOM type; everything is <N: DomNode>. Tradeoff: trait-call indirection vs concrete inlining. Operational: ax-dom's reference arena is one impl among many (mirrors 258 Element / 261 EventTarget); host engines (124/260) supply their own. Violation: engine couples to one DOM -> not reusable, untestable in isolation.
  • P8 ARIA overrides native, except where forbidden. When both aria(...) and native_state() apply, ARIA wins unless the spec pins native (documented exception table in Phase 4, ## 16). Tradeoff: author error in ARIA can mask correct native state. Operational: exceptions live in one table; default branch = ARIA. Violation: checkbox shows native checked while aria-checked=false -> contradictory state to AT.
  • P9 Presentational conflict resolution is explicit. role=presentation/none flattens unless the element is is_focusable() or carries global ARIA, in which case it is re-exposed with computed role. Tradeoff: extra check per presentational node. Operational: a single presentational_role_conflict predicate, asserted by WPT. Violation: a focusable element silently dropped -> keyboard focus lands on an invisible (to AT) node.
  • P10 Platform mapping is a pure projection. ax-platform mappers are &AXNode -> {Uia,Ia2,Atspi,Mac}Node with zero retained state; PlatformBackend::apply consumes &[PlatformUpdate] only. Tradeoff: re-derive projection each push vs caching. Operational: real OS IPC is PhaseDeferred; default backend is inspect/JSON. Violation: backend-held state desyncs from AXTree -> the same stale-tree class P3 forbids, one layer down.
  • P11 Observable computation. Every role + name decision is reconstructable: compute_role exposes explicit/implicit/generic path; AccessibleName.sources records each contributing node. Tradeoff: trace bookkeeping cost (disable-able). Operational: axtree name-trace <node> prints the precedence walk; validate uses the same hooks. Violation: a wrong name with no trace -> hours of guesswork, no regression test.
  • P12 Minimal diffs. recompute emits only changed AXTreeUpdate variants (NodeAdded/Removed/RoleChanged/NameChanged/StateChanged/Reparented); unchanged subtrees produce nothing. Tradeoff: diff computation cost vs resend-all simplicity. Operational: Phase 8 asserts |updates| is minimal against a recorded baseline; mirrors AXTreeSerializer. Violation: over-broad updates -> AT re-announces unchanged UI, flooding the user.
  • P13 Typed totality, no panics in core. Core crates are no_std + alloc; all fallible input paths return Result<_, AXError>; Role/AXStateValue tri-states make illegal states unrepresentable. Tradeoff: more Result plumbing than unwrap. Operational: #![forbid(unsafe_code)] in core; clippy denies unwrap/panic on input. Violation: a malformed role token panics the host browser's a11y thread — the exact C++ crash class Rust was chosen to eliminate.

6.3 Precedence among principles

When principles conflict, resolve in this order: P1 (spec) > P3 (incremental correctness) > P2 (name present) > P12 (minimal diff) > performance. Example: a minimal diff (P12) that would leave a stale name loses to P3; a spec rule (P1) that mandates an empty name (NameFrom::Prohibited) overrides P2's "never empty". All principles outrank raw throughput; performance targets (Phase 12 benches) are satisfied within these constraints, never by relaxing them.

7.2 I-1 — Determinism / reproducibility

  • Statement: build_tree(root) over a frozen DomNode snapshot yields a byte-identical serialized AXTree across runs/threads/platforms; output depends only on local_name, namespace, attr, aria, computed display/visibility, focusability, text, native_state, structure. No clock, RNG, hashmap-iteration-order, or AXNodeId raw value leaks into output.
  • Why: conformance diffing (Phase 12), differential vs Chromium AX dump, and reproducible incident triage all require a canonical output; nondeterminism makes every other invariant untestable.
  • Enforced: dom_to_ax/relation maps iterated in deterministic order (BTree or sorted by OpaqueDomId, never raw HashMap); arena allocation in DOM pre-order; serializer keys sorted; AXNodeId is opaque in dumps.
  • Detection: Phase 12 builds same fixture twice, asserts equal serialization; fuzz runs 2× with shuffled child-visit micro-order.
  • Telemetry / Recovery / Debug: axtree dump --canonical emits stable form, --seed-trace logs nondeterministic-prone iteration sites; no runtime recovery — divergence is a hard CI failure; diff the two --canonical dumps, first differing path locates the source.

7.3 I-2 — accname termination

  • Statement: compute_name / compute_description always halt; NameContext.visited (set of OpaqueDomId) plus a hard depth cap (DEPTH_MAX = 100) bound recursion; in_aria_labelledby blocks re-entering a labelledby traversal.
  • Why: cyclic aria-labelledby/describedby (a→b→a) or name-from-content loops would otherwise hang or stack-overflow — a classic a11y-engine DoS.
  • Enforced: every recursion enters via visited.insert; already-visited → contributes empty string; depth > DEPTH_MAX → truncate + record name_truncated.
  • Detection: fixtures with cyclic labelledby and 200-deep nesting; fuzzer targets reference graphs.
  • Telemetry / Recovery / Debug: axtree name-trace <id> prints each precedence step, visited hits, and depth-cap truncation; truncated branch yields a partial name (never panics); cross-check the labelledby/owns edges at the revisit/depth event.

7.4 I-3 — no abstract role as computed role

  • Statement: compute_role never returns an abstract Role (RoleType, Widget, Composite, Input, Landmark, Range, Section, Sectionhead, Select, Structure, Window, Command). parse_role_tokens rejects abstract tokens → falls through to next token / implicit / Generic.
  • Why: abstract roles have no platform mapping; an abstract computed role would break I-11 and Core-AAM export, and violates WAI-ARIA.
  • Enforced: parse_role_tokens filters via an is_abstract(Role) predicate; validate_role returns AXError::AbstractRoleUsed if one ever reaches it; abstract variants are never constructible from a string.
  • Detection: exhaustive unit test maps each abstract token → expected fallback; validate_tree scans all nodes.
  • Telemetry / Recovery / Debug: Phase 11 diagnostic warns "abstract role X ignored", trace logs token-list resolution; skip the abstract token per spec and continue; axtree validate flags the node + offending role value.

7.5 I-4 — at most one aria-owns owner

  • Statement: in the final AX tree each AXNode has ≤ 1 owner via aria-owns; if multiple owners reference the same id, exactly one wins (first owner in DOM pre-order); self-ownership rejected.
  • Why: a node with two parents corrupts the tree structure, double-counts in traversal, and crashes platform AT.
  • Enforced: apply_relations tracks a claimed: Set<OpaqueDomId>; second claim ignored + AXError-logged; owned node's prior DOM-order AX parent is detached exactly once.
  • Detection: validate_tree asserts each node has one parent and the owns graph is a forest; conflicting-owns fixtures.
  • Telemetry / Recovery / Debug: axtree dump --relations shows resolved vs dropped owns edges; drop the losing claim (node stays under first owner); the dump lists the duplicate claim + winning owner id.

7.6 I-5 — acyclic parent chain & relation graph

  • Statement: following parent from any node reaches root in finite steps; the aria-owns/relation graph has no cycle (a owns b owns a rejected).
  • Why: cycles ⇒ infinite traversal in build, recompute, name-from-content, and AT.
  • Enforced: apply_relations runs cycle detection (DFS color marking) before committing a reparent; AXError::RelationCycle aborts that edge.
  • Detection: validate_tree walks ancestors with a visited set; fuzz emits random owns edges.
  • Telemetry / Recovery / Debug: trace logs the rejected edge + cycle path; reject only the cycle-closing edge (rest of tree intact); dump the owns chain to find the closing edge.

7.7 I-6 — every ignored node records a reason

  • Statement: when is_included sets ignored=true, the node stores an IgnoredReason ∈ {DisplayNone, AriaHidden, Presentational, VisibilityHidden, NoSemantics, EmptyText, …}; never ignored-without-reason.
  • Why: "why is my element missing from the AX tree?" is the #1 a11y debugging question; silent pruning is undebuggable.
  • Enforced: is_included returns (included, reason); build requires a reason to set ignored.
  • Detection: validate_tree asserts ignored ⇒ reason.is_some().
  • Telemetry / Recovery / Debug: axtree dump --show-ignored lists ignored nodes + reason + per-reason counters; recovery n/a (internal completeness); the dump answers the missing-node question directly.

7.8 I-7 — no content leak from aria-hidden subtrees

  • Statement: any node in an aria-hidden=true subtree is ignored=true and contributes nothing to the exposed tree, to any ancestor's name-from-content, or to platform export. Exception: a focusable node inside aria-hidden is an authoring error — engine still hides it but emits a diagnostic.
  • Why: leaking hidden content (passwords, off-screen menus) into AT is a privacy/security defect, the AX analogue of an info leak.
  • Enforced: aria-hidden propagated as a build-walk flag (subtree-wide); compute_name skips ignored descendants; map_* never receives ignored nodes.
  • Detection: fixtures assert hidden text absent from name + export; validate_tree asserts no exposed node has an aria-hidden ancestor.
  • Telemetry / Recovery / Debug: counter aria_hidden_subtrees + focusable-inside-hidden diagnostic; hide regardless (fail-closed, never expose on ambiguity); name-trace shows excluded descendants, dump confirms pruning.

7.9 I-8 — recompute never under-invalidates

  • Statement: any DOM mutation that could change a node's role/name/state/relations/inclusion marks the correct set of dirty nodes. Dependency closure: name-from-content ⇒ ancestor dirties on descendant text/structure change; aria-labelledby/describedby targets ⇒ referrer dirties on target change; aria-owns ⇒ both owner and owned dirty.
  • Why: under-invalidation ⇒ stale AX tree exposed to AT — the dominant, hardest-to-detect bug class in C++ a11y engines and the core reason for Rust here.
  • Enforced: mark_dirty(tree, dom, kind) consults a reverse-dependency index (target→referrers, child→name-owner ancestors); recompute walks the dirty closure. Over-invalidation is acceptable (correct but slower); under-invalidation is the forbidden direction.
  • Detection: Phase 12 oracle — after each random mutation, compare recompute output to a full build_tree; any field diff = under-invalidation bug. Fuzz drives long mutation streams.
  • Telemetry / Recovery / Debug: axtree diff --trace logs the dirtied set + propagating dependency edges per mutation; no silent recovery (mismatch is a CI failure), --paranoid forces full rebuild as the operational mitigation; binary-search the mutation stream to the first divergent op and inspect its reverse-dep edges.

7.10 I-9 — diff/rebuild equivalence

  • Statement: for any mutation sequence M, applying the emitted Vec<AXTreeUpdate> to the prior serialized tree yields a tree byte-identical to build_tree(DOM after M). (Mirrors Chromium AXTreeSerializer semantics.)
  • Why: the platform/AT consumer reconstructs state from incremental diffs; any drift desyncs AT from reality.
  • Enforced: recompute emits a minimal, complete update set; serializer is the single source for both paths.
  • Detection: core fuzz property — apply(serialize(prev), updates) == serialize(rebuild); also tested per fixture in Phase 8/12.
  • Telemetry / Recovery / Debug: axtree diff prints the update set, --verify re-applies + asserts equivalence inline; on mismatch the backend requests a full snapshot (keyframe resync); dump prev/expected/got — the first mismatching node localizes a missing/extra AXTreeUpdate.

7.11 I-10 — dom_to_ax consistency

  • Statement: AXTree.dom_to_ax: Map<OpaqueDomId, AXNodeId> is bijective onto live, non-stale arena entries: every mapped AXNodeId resolves to a live AXNode whose dom_node round-trips to the same OpaqueDomId; removed DOM/AX nodes are purged from the map atomically with arena removal.
  • Why: stale map entries ⇒ dangling reparents, double-free-style logic bugs, AXError::OrphanReference; the map is the hinge of incremental recompute.
  • Enforced: node removal updates arena, parent's children, and dom_to_ax in one operation; generational AXNodeId makes stale ids fail resolution rather than alias.
  • Detection: validate_tree asserts map↔arena↔dom_node round-trip for every entry; fuzz with heavy insert/remove churn.
  • Telemetry / Recovery / Debug: counter dom_to_ax_size vs live node count (must match), --verify flags orphans; orphan lookup returns None/AXError::OrphanReference (never a wrong node); dump map vs arena — a mismatched key/generation pinpoints the removal that skipped a map update.

7.12 I-11 — platform projection purity

  • Statement: map_uia/map_ia2/map_atspi/map_macos(node) depend only on that single AXNode's fields (role/states/props/name/description/bounds) — no tree walk, no global state, no mutation. Same AXNode ⇒ identical platform node every call.
  • Why: projections must be cacheable, parallelizable, and trivially diffable; hidden inputs would reintroduce stale-state bugs at the platform boundary.
  • Enforced: map_* signatures take &AXNode only; no &AXTree parameter; PlatformBackend::apply consumes precomputed PlatformUpdates.
  • Detection: unit tests assert idempotence + field-coverage per Role→platform-role table (button→UIA Button / IA2 PUSH_BUTTON / AT-SPI2 PUSH_BUTTON / AX NSAccessibilityButtonRole); validate_tree not needed (compile-time enforced by signature).
  • Telemetry / Recovery / Debug: axtree dump --platform=uia|ia2|atspi|macos shows the projection; recovery n/a (pure — re-derive from the AXNode); feed the AXNode to map_* in isolation and compare against the dump.

7.13 I-12 — single focus owner

  • Statement: at most one AXNode carries states.focused=True at any time; set_focus clears the prior holder before setting the new one, and a removed focused node clears focus (emitting FocusChanged{new:None}). aria-activedescendant marks a logical focus on the descendant without violating this (DOM focus stays on the composite owner).
  • Why: two focused nodes make AT announce the wrong element or thrash; a dangling focused flag on a pruned node is an OrphanReference-class bug (Phase 10).
  • Enforced: AXTree.focused_id: Option<AXNodeId> is the single source; set_focus is the only mutator; recompute reconciles focus on NodeRemoved of the focused id.
  • Detection: invariant test over 10k random focus ops asserts exactly one focused=True; validate_tree scans the focus flag count.
  • Telemetry / Recovery / Debug: counter ax_focus_invariant_violations (must stay 0) + --focus-trace; recovery clears all then sets one; the focus-trace shows the old→new transition and any reconcile on removal.

8.2 Role computation (ax-role::compute_role)

Ordered decision procedure (explicit → implicit → generic), then conflict resolution — compute_role(n):

  1. If n.aria("role") is present: r = parse_role_tokens(value) — split on ASCII whitespace, first VALID token wins; skip unknown + abstract tokens (the "fallback list"). If r = Some(role), set explicit = role.
  2. Else explicit = None.
  3. implicit = implicit_role(n) — the HTML-AAM tag(+attr) table.
  4. role = explicit ?? implicit ?? Generic.
  5. Presentational role conflict resolution: if role ∈ {None, Presentation} AND (n.is_focusable() OR n has any global ARIA state/property OR n has a required-owned semantic), then role = implicit ?? Generic (re-expose; presentation is ignored).
  6. validate_role(role, ctx) — required context/owned check (Phase 7).
  • parse_role_tokens: returns the first non-abstract, known token; an all-unknown/all-abstract list ⇒ None ⇒ implicit fallback.
  • A valid explicit role overrides the implicit role even when semantically odd (<button role="heading"> → Heading); validation only diagnoses (Phase 11), never silently rewrites except the presentation conflict in step 5.

8.3 Accessible name & description (ax-name::compute_name)

compute_name(n, role) -> AccessibleName { text, from: NameFrom, sources }. Steps run in order, role-gated, short-circuiting on the first non-empty result; a NameContext { visited, traversal_root, in_aria_labelledby } carries the recursion guard.

compute_name(n, role) step sequence:

  • A. If NameFrom would be Prohibited for role (e.g. Generic, Paragraph, Presentation, password): return empty, from=Prohibited.

  • B. aria-labelledby: for each idref → resolve node; recurse compute_name, concatenate with single spaces. Skip if in_aria_labelledby already set for that target (a labelledby traversal does NOT re-enter the same labelledby). NameFrom=RelatedElement.

  • C. aria-label: if present AND non-empty (after trim) → NameFrom=Author.

  • D. Native markup: <label for>/wrapping label, img@alt, <caption>, <legend>, <figcaption>, table summary, <title> on SVG. NameFrom=Author.

  • E. Name from content (ONLY if role allows, §8.1): concatenate compute_name(child) over descendants in tree order, guarded by visited. NameFrom=Contents.

  • F. Title attribute, then placeholder → NameFrom={Title, Placeholder}.

  • → Whitespace: collapse runs to single space, trim ends (steps B/E join with " ").

  • Visited guard: each node's OpaqueDomId is inserted into visited before recursing into it; a revisit returns empty, terminating cycles.

  • compute_description(n): aria-describedby (concat referenced names) → aria-description → title (if not already the name). Emits AccessibleDescription { text, from }.

8.4 Tree inclusion / exclusion (ax-build::is_included)

Decision table; first matching row wins. "Excluded" ⇒ AXNode.ignored=true (or no node at all for whole-subtree removals).

Condition (on DomNode) Subtree effect AX result
computed_display_is_none() entire subtree removed no AX nodes
aria-hidden="true" entire subtree ignored ignored=true, children ignored
role ∈ {None, Presentation} AND no conflict (§8.2) flatten this element element ignored, children kept, reparented to grandparent
computed_visibility_hidden() this node ignored; descendants re-evaluated (a visible descendant re-appears) nuanced: node ignored, subtree walked
no semantics (Generic, no name/role/focus/global ARIA) flatten ignored, children kept
text node, non-whitespace — included as text/inline content
otherwise — included AXNode
  • aria-hidden on a focusable element: authoring error. Documented engine behavior — ignored=true is still applied (the node is pruned), but Phase 11 emits an authoring diagnostic (focusable-inside-aria-hidden). The engine does not auto-re-expose (unlike presentation conflict resolution).
  • visibility:hidden vs display:none: display:none deletes the subtree; visibility:hidden ignores the node but a descendant with visibility:visible re-enters the tree.

8.5 Worked example — custom role=checkbox with aria-labelledby + aria-checked=mixed + nested icon

DOM:

<span id="lbl">Accept <em>all</em> terms</span>
<div role="checkbox" aria-checked="mixed" aria-labelledby="lbl" tabindex="0">
  <svg role="img" aria-label="check"><!-- icon --></svg>
</div>

Computation:

  1. compute_role(div): explicit token checkbox → valid, non-abstract ⇒ Role::Checkbox.
  2. compute_name(div, Checkbox): Step B aria-labelledby="lbl" → resolve #lbl (Generic, but reached via labelledby so name-from-content is allowed in this traversal) → concat "Accept " + compute_name(<em>)="all" + " terms" = "Accept all terms". Short-circuits at B → NameFrom::RelatedElement, sources=[#lbl]; the nested <svg aria-label="check"> is not consulted (labelledby won; step E never runs).
  3. States: aria-checked="mixed" → checked=AXStateValue::Mixed; tabindex=0 ⇒ focusable=true.

Resulting AXNode:

AXNode { role:Checkbox, name:{text:"Accept all terms", from:RelatedElement, sources:[#lbl]},
  description:{text:"", from:None}, states:{checked:Mixed, focusable:True}, ignored:false,
  children:[ AXNode{ role:Img, name:{text:"check", from:Author}, ignored:false } ] }

The icon's Img node remains a child even though it did not contribute to the checkbox name — name selection ≠ tree pruning.

8.6 Worked example — aria-owns reparenting (DOM order vs AX order)

DOM (toolbar references a button declared later, out of DOM order):

<div role="toolbar" aria-owns="extra">
  <button id="a">A</button>
</div>
<button id="extra">Extra</button>

apply_relations reparents #extra under the owner; an owned node leaves its DOM-order AX parent (here, the document root):

  • DOM tree: AX tree (after owns reparent):
  • root Toolbar
    • ├── Toolbar(div) ├── Button "A" (#a, DOM child)
    • │ └── Button "A" (#a) └── Button "Extra" (#extra, OWNED — moved here)
    • └── Button "Extra" (#extra) (#extra no longer under root)

Ordering: aria-owns idref order places owned nodes after DOM-order children unless interleaved per spec; ≤1 owner per node (OrphanReference/duplicate guards in §8.7).

11. Core Schema and Core Types

Normative API surface every phase (## 12–## 24) builds against. Grouped by crate. Signatures + contracts only; no bodies beyond illustrative ≤2-line examples.

Cross-cutting semantics (apply to all types below):

  • Ownership: all AXNodes live in one Arena<AXNode> inside AXTree; everything references them by AXNodeId (generational u32), never by &/Box. Eliminates dangling-pointer + stale-tree CVE class of C++ a11y engines.
  • Mutation: the tree is rebuilt or patched, never mutated in place where it aids diffing — recompute produces a fresh AXNode for a dirty id and swaps it; old vs new feed the AXTreeUpdate differ (mirrors AXTreeSerializer). bounds/structural-only edits may patch in place.
  • Concurrency: build_tree/recompute are single-threaded over an immutable DOM snapshot (DomNode borrowed read-only for the call). No interior mutability in ax-core. The only cross-process surface is the ax-platform projection (PlatformUpdate + mapped nodes); AXTree itself never crosses a thread/process boundary.
  • Serialization: two wire forms — AXTreeUpdate/AXEvent (incremental, intra-engine + to backend) and the platform projection (UiaNode/Ia2Node/AtspiNode/MacAxNode). ax-core is no_std + alloc; serde lives behind a feature.
  • Compatibility: Role, NameFrom, AXRelation, AXError are #[non_exhaustive] — new ARIA roles/relations are additive minor bumps. AXNodeId layout, is_included outcome set, and platform role table are SemVer-significant.

/// Read-only view of one styled DOM node. Implemented by the host (projects 124/260)
/// and by ax-dom's reference arena. Borrowed immutably for the whole build/recompute call.
pub trait DomNode: Sized + Clone {
    fn local_name(&self) -> &LocalName;             // lowercased tag, e.g. "button"
    fn namespace(&self) -> &Namespace;              // HTML / SVG / MathML -> gates implicit role
    fn attr(&self, name: &str) -> Option<&str>;     // non-namespaced attr (type, href, alt...)
    fn aria(&self, name: &str) -> Option<&str>;     // "aria-*"/"role"; None if absent
    fn computed_display_is_none(&self) -> bool;      // true -> whole subtree excluded
    fn computed_visibility_hidden(&self) -> bool;    // visibility:hidden|collapse (nuanced inclusion)
    fn is_focusable(&self) -> bool;                  // tabindex/native -> presentational conflict input
    fn text_content(&self) -> Option<&str>;          // for name-from-content leaves
    fn native_state(&self) -> NativeState;           // checked/disabled/required/readonly/value/open
    fn parent(&self) -> Option<Self>;
    fn children(&self) -> Vec<Self>;                 // DOM order; flattened tree (post-slotting)
    fn assigned_slot(&self) -> Option<Self>;         // shadow slotting -> AX follows flat tree
    fn shadow_root(&self) -> Option<Self>;           // shadow host -> descend into shadow tree
    fn opaque(&self) -> OpaqueDomId;                 // stable identity; key for dom_to_ax + visited set
}
  • Contract: methods are pure for a snapshot — repeated calls return equal values during one build. opaque() must be stable across calls for the same node (mutation identity) so mark_dirty can target it. children() returns the flattened tree (slots resolved) so AX matches rendered order.

  • Abstract role leaking as a value → invalid platform mapping downstream. Root cause: enumerating abstract in Role. Mitigation: abstract live only in the &[&str] reject list; grep test forbids abstract identifiers in the enum.
  • Stopping at the first recognized-but-abstract token instead of skipping → returns Generic for "widget button". Fix: abstract must be a skip, never a terminate.
  • split_whitespace vs split_ascii_whitespace → Unicode whitespace divergence from WPT. Use ASCII per spec.
  • Empty-string token from leading space if using split(' ') → spurious None. Use split_ascii_whitespace.

14.7 Performance Concerns

  • Zero allocation: operate on borrowed &str slices; find_map short-circuits at first hit. Common case (1 token) is one hash probe.
  • from_token via a compile-time perfect hash (phf) or length-bucketed match → O(token-len) no branch-mispredict storm. Abstract binary_search over ~12 strings.
  • Hot on incremental path (role recompute on attr mutation) — keep branch-free; Role is Copy (1 byte/discriminant via repr(u8) candidate, ~80 < 256).

14.8 Edge Cases

  • Absent role attr → None (→ implicit/Generic). Present-but-empty role="" → Generic.
  • Mixed valid/invalid/abstract ordering covered by fallback semantics; only first valid concrete matters.
  • Very long attr (DoS attempt): iteration is linear + early-exit; cap not required but RoleTrace truncates skipped_tokens at 32.
  • role="none presentation" parses to None(presentation) variant — flattening handled in Phase 6, NOT here.

14.9 Failure Analysis

  • Wrong role → cascades into wrong name-from-content gating (Phase 5), wrong states (Phase 4), wrong platform role (Phase 9). Blast radius: the node + name-dependent ancestors. Detection: differential vs Chromium AX dump (Phase 12) flags role mismatches first.

  • Operator visibility: role-trace shows chosen vs skipped tokens for any node in the inspector.

20.6 Pitfalls

  • Under-invalidation of name-from-content: forgetting that a text/child change dirties named ancestors → stale button name. Root cause: missing name_from_content_parents edge. Debug: diff equivalence test flags it; name-trace on the ancestor shows old contents.
  • Stale dependency index: editing aria-labelledby changes the referencer set but deps not rebuilt → next text edit dirties the wrong node. Fix: rebuild labelledby_refs whenever an aria-labelledby attr mutates, before clearing dirty.
  • Reparent ordering: emitting NodeAdded before its new parent exists at the consumer → orphan apply. Mitigate: parents-first add ordering; assert in diff builder.
  • Double-dirty / id reuse: a generational AXNodeId recycled mid-recompute aliases a removed node. Detect via generation tag mismatch → skip.
  • Presentational conflict flip: adding global ARIA to a role=presentation node re-exposes it (conflict resolution) — a StyleChanged that toggles focusability must dirty inclusion, not just state.
  • Owns + remove race: removing a DOM node that is an owns target must clear it from owner's children AND owns_refs, else dangling reparent.

20.7 Performance Concerns

  • Dirty set = Set<AXNodeId> (bitset over arena indices) → O(1) insert, dense iteration; topo-order via in-arena depth field, no allocation.
  • recompute reuses scratch Vec<AXTreeUpdate> from a per-tree pool; name recomputation reuses a thread-local String buffer (avoid per-node alloc).
  • Batching: coalesce a burst of mark_dirty calls (one event-loop microtask) into a single recompute; redundant dirties on the same node collapse via the set.
  • Relations re-resolved only when an owns/relation-bearing node is dirty (guarded flag), not per recompute → avoids O(tree) relation pass on a leaf text edit.
  • Tail latency: largest contributor is name-from-content on deep subtrees; cap recursion + memoize child names within one recompute pass.

20.8 Edge Cases

  • Mutation on a node not in dom_to_ax (was pruned/ignored) → may newly include it (e.g. aria-hidden removed): seed parent dirty so the walk re-includes the subtree.
  • Root mutation (<html> lang/dir) → state-only; never reparents root.
  • Cyclic aria-labelledby introduced by mutation → name computation's visited guard terminates; emit truncated name, flag diagnostic.
  • Self-owns / duplicate-owns after mutation → relation resolver keeps first owner, drops rest; Reparented not emitted for rejected edge.
  • Rapid toggle (hidden true→false→true within one batch) → net no-op, zero updates emitted (start==end state).
  • Overflow: > u32::MAX cumulative node allocations → arena returns AXError, recompute aborts, tree left at prior valid state (no partial apply).

20.9 Failure Analysis

  • What breaks: under-invalidation → assistive technology reads stale role/name/state (the dominant a11y incident class). Detection: equivalence property test in CI; runtime self-check mode recompute vs periodic rebuild (sampled).
  • Blast radius: bounded to the dependent subtree(s) of the missed edge; a missed labelledby edge mis-names one node, a missed display:none drop leaks a whole subtree to AT.
  • Recovery: axtree build full rebuild always available as the authoritative fallback; on equivalence-check mismatch the engine can force a full rebuild + emit a single replacing update set.
  • Operator visibility: RecomputeStats.updates_emitted vs true_diff divergence logged at WARN; mismatch count is a metric.

20.10 Operational Notes

  • Metrics: ax_recompute_duration_us (histogram), ax_dirty_nodes, ax_updates_emitted, ax_full_rebuild_total, ax_equivalence_mismatch_total (alert if > 0).

12.8 Edge Cases

  • Empty document / detached subtree → build_tree yields root-only AXTree; no panic.

Threat Model

Frame. No code execution, no network, no secrets. The engine is a pure derived projection: styled DomNode tree → AXTree. "Threat" = inputs that crash, hang, blow memory, leak content the author hid, build an inaccessible (trap) tree, or feed assistive technology (AT) a wrong/stale projection. Attacker = whoever authors markup + ARIA (untrusted page content); secondary = a buggy host (DomNode impl) or operator misusing the API.

Trust boundaries

[ UNTRUSTED ] author HTML/ARIA attrs, aria-* token lists, text content  --+
[ SEMI ]      host DOM + CSS (DomNode impl): display/visibility/focus      |--> ax-role/ax-name/ax-build  --(AXTreeUpdate)-->  ax-platform projection --> [ EXTERNAL/TRUSTED-OUT ] AT
[ TRUSTED ]   ax-core types, engine algorithms, fixtures                   |        ^ all parsing bounded, never panic, pure
[ OPERATOR ]  caller of build_tree/mark_dirty/recompute, snapshot choice --+

Boundary rules: (a) every value crossing UNTRUSTED→engine is parsed with bounded, total functions (no panic, no unbounded alloc); (b) engine→AT crossing is a validated read-only projection (map_uia/map_ia2/map_atspi/map_macos), never raw author strings unescaped; (c) the engine trusts DomNode for structure but defends against adversarial structure (cycles, depth, fan-out) since markup drives it; (d) operator owns invalidation correctness — engine adds consistency assertions, not trust.

Content-leak vs a11y-trap analysis (the two AX-specific hazards)

  • Content leak is spec-mandated visibility, not a bypass: accname intentionally includes a hidden node's text when it is a labelledby/describedby target (per accname 1.2) so authors can place visually-hidden labels. The defense is fidelity, not blocking — the engine adds no traversal beyond what accname/inclusion rules dictate, never reads cross-document/cross-shadow except via explicit ARIA refs + slot/shadow per DomNode, and name-trace makes every NameSource/NameFrom auditable so authors see exactly what is exposed. display:none text is still excluded from naming; aria-hidden subtrees are pruned from the tree (ignored=true) while remaining nameable only as an explicit ref — both behaviors are pinned by WPT accname fixtures.
  • A11y trap is the inverse failure: the engine must never produce a tree where focusable/interactive content is unreachable by AT. Enforced by presentational role conflict resolution (focusable or global-ARIA + role=presentation/none ⇒ re-expose), by is_included refusing to prune focusable nodes, and by validate diagnostics flagging aria-hidden on a focusable node (documented authoring error: engine still prunes per spec but emits a diagnostic). Differential testing vs Chromium AX dump catches silent trap/over-prune regressions.

Non-threats / explicitly out of scope (no mitigation owed)

XSS / script execution (no JS runtime — project 259), CSS/layout injection (consume computed style — projects 124/260), real OS a11y-API IPC attacks (PhaseDeferred behind PlatformBackend), authoring an AT/screen reader, HTML parsing exploits. The engine is side-effect-free and offline: the only "output" is the serializable projection, so the residual surface is correctness/availability of that projection, fully covered by T1–T10.

Detail: gravest classes

F1 — empty/wrong name (S1). Symptoms: AT announces nothing or wrong text; name.text=="" on a name-required role (button/link/heading/menuitem/...). Root causes: aria-labelledby IDREF unresolved → empty concatenation (NOT falling through to aria-label); name-from-content gating wrong for the role; native source (label/alt/legend/figcaption/title) missed; whitespace collapse erasing all text; precedence inverted. Detection: axtree name-trace <id> prints the full precedence walk — NameFrom chosen + each NameSource with raw/flattened text; empty-name lint flags S1 candidates at validate. Recovery: none automatic (a wrong name is a correct computation over wrong input); fix is in compute_name precedence or DomNode::aria/text_content. Operator: run name-trace, compare against accname WPT fixture. Mitigation: every accname precedence branch has a WPT-derived test; empty-name on named-required role fails CI.

F3 — stale tree (S1/S2). Symptoms: AT reads removed/old content, missing new nodes, wrong checked/expanded after toggle. Root cause: a MutationKind that did not call mark_dirty, or a dependency (name-from-content descendant, aria-labelledby target) not dirtied on the dependent node. Detection: AXTree carries an epoch checksum; a shadow build_tree every N=256 recomputes (debug: every recompute) compares against incremental result; mismatch ⇒ F3 logged. Auto-recovery: discard incremental tree, full rebuild, resync dom_to_ax, emit NodeRemoved+NodeAdded resync batch. Manual: inspect dirty-set snapshot vs the actual MutationKind stream. Mitigation: dirty-propagation is table-driven (mutation → dirty closure), property-tested by random mutation sequences asserting recompute ≡ build_tree.

  • role-trace localizes F2/F8: shows which token won or why None/Presentation was (not) re-exposed.
  • diff --rebuild is the standing oracle for F3/F9 — drift means incremental serialization diverged from ground truth.

Cross-cutting recovery invariants

  • Full-rebuild fallback (F3/F9) is always available, O(DOM), bit-identical to build_tree; correctness never depends on the incremental path.
  • Relation/recursion guards (F4/F5/F10) fail closed — drop the offending edge/branch, keep the tree well-formed, never panic, never emit a cyclic AX structure: a node has ≤1 owner (second aria-owns claim dropped, original parent kept, no Reparented); aria-hidden subtree ⇒ ignored=true (F7), and a focusable aria-hidden node is an authoring error surfaced by validate but still pruned (do not auto-unhide).
  • No failure class may raise an OS exception across PlatformBackend::apply; mapping gaps (F11) export a best-effort role + log, never abort the projection.

SemVer policy (ax-*)

  • Workspace crates version-locked in lockstep (single workspace.version); a major bump bumps all 7, ax-core major = workspace major. Pre-1.0 0.y (y = breaking axis), post-1.0 standard SemVer.
  • MSRV 1.78, edition 2021. MSRV raise = minor (documented, never silent); CI pins {1.78, stable, beta}; rust-version in every manifest. #[doc(hidden)]/__private + dev-only fuzz/conformance helpers carry no guarantee.

Adding roles / states / properties without breaking consumers

  • New Role variant → minor (#[non_exhaustive], consumers match _ =>); default platform mapping = nearest abstract ancestor's projection until map_* rows added (same release). New StateKey/property key → minor; absent key reads as AXStateValue::Undefined/None, never panic.
  • New NameFrom/DescriptionFrom → minor (NameSource list append-only). Removing/renaming a variant = major; deprecate ≥1 minor first via #[deprecated(since, note)] alias.

Spec-tracking & deprecation

  • Pin a spec snapshot tuple: {WAI-ARIA 1.2, HTML-AAM <date>, accname 1.2, Core-AAM 1.2} recorded in ax-core::SPEC_SNAPSHOT. Upstream spec deltas (e.g. WAI-ARIA 1.3 role/name-from-content gating changes) land behind a minor with a CHANGELOG spec-diff entry.
  • Behavior change that alters a computed role/name/state for existing input = observable break → minor only if gated by snapshot bump + documented; else major. Default tracks newest pinned snapshot; older retained ≥2 minors via SpecProfile selector.
  • Deprecation window: ≥1 minor with warning before removal; CVE/spec-errata fixes may ship in patch with a CHANGELOG callout.

Differential-parity guarantee

  • Parity pinned vs Chromium AX-dump @ fixed milestone + axe-core @ fixed version (versions in tests/parity/PINNED). Conformance (Phase 12, ## 24) asserts byte-stable diff over WPT wai-aria/accname/html-aam corpora.
  • Parity is a release gate, not a runtime promise: an upstream-tracked divergence (Chromium quirk vs spec) is logged as an xfail with rationale; intentional spec-correct deviations are enumerated in PARITY_DEVIATIONS.md. Re-pinning the Chromium/axe-core baseline = minor bump.

Allocator & buffer reuse

  • Build-time: pre-size nodes arena + dom_to_ax to DOM node count → amortize Vec growth to O(1) reallocs.
  • ax-name reuses a NameContext-scoped String accumulator + visited Set across siblings (clear, never realloc) → no per-node alloc on the name-from-content path (dominant accname cost); recompute reuses the dirty Set + an update scratch Vec built into a caller-supplied buffer.

Relations pass vs walk · concurrency

  • Walk: O(N) over DOM, one compute_role/compute_name/state pass per included node. apply_relations: O(R) reference resolution + aria-owns reparent, cycle/orphan/duplicate guards union-find-ish O(R·α); a separate post-walk pass because owns targets may not yet exist mid-walk. Tie-back §4: relations ≤ ~15% of build at typical 1–2% owns density; pathological 50% owns approaches walk cost.
  • Build + recompute are single-threaded over a consistent DOM snapshot — no locks/atomics/contention; the host serializes mutation, the engine never observes a torn DOM. Parallel subtree build is a PhaseDeferred option (independent arenas merged), not in scope.

Dirty-set size vs recompute cost

  • recompute cost ≈ Σ(dirty subtree sizes), not tree size; mark_dirty MUST propagate to dependents (reverse labelledby edges, name-from-content ancestors) — under-marking → stale name (correctness bug), over-marking → wasted work (perf only), so bias toward correctness (MM3). Crossover: dirty fraction > ~30% → full build_tree beats incremental (recompute may fall back).

Mental Models & First Principles

The compressed intuitions an expert holds about this engine. Each: the model · what it predicts · the bug class written without it · where this blueprint applies it.

  • MM1 — The AX tree is a projection, not a copy. The DOM is the source of truth; the AX tree is f(styled DOM) — pruned, reparented, role-coalesced, recomputed on change. Predicts: you never "edit" the AX tree directly; you change the DOM and re-derive. Bug without it: mutating AXNodes in place and drifting from the DOM (the stale-tree class). Applied: §3 (persistence boundary = NONE), §8, Phase 6/8 (## 18/## 20).
  • MM2 — Invalidation is the whole game; computation is easy. Computing a role/name once is trivial; knowing exactly which nodes a mutation invalidated is the hard, correctness-critical part. Predicts: dependency edges (name-from-content ancestors, aria-labelledby referrers) dominate the design, not the per-node math. Bug without it: under-invalidation → stale name/state to AT. Applied: P3, I-8, Phase 8 deps (## 20).
  • MM3 — Over-invalidate, never under-invalidate. The two error directions are not symmetric: over-marking wastes CPU (recoverable), under-marking ships a wrong tree (silent S1 incident). Predicts: when unsure whether a mutation affects a node, dirty it. Bug without it: a "clever" minimal-dirtying heuristic that misses a dependency. Applied: P3, I-8, Performance Engineering (dirty-set vs cost).
  • MM4 — A name is a recursive computation over an adversarial graph. aria-labelledby makes naming mutually recursive across arbitrary author-controlled id refs, which can cycle. Predicts: termination needs a visited set + non-reentry, not a depth limit alone. Bug without it: hang / stack overflow on cyclic aria-labelledby (a real a11y DoS). Applied: P4, I-2, ADR-09, Phase 5 (## 17).
  • MM5 — Generational ids make use-after-free a typed miss, not a crash. An AXNodeId is index+generation; a stale id fails resolution rather than aliasing a recycled slot. Predicts: reparent/prune churn is safe without Rc<RefCell> cycles or raw pointers. Bug without it: dangling-pointer CVEs that dominate C++ a11y-engine history. Applied: ADR-05, I-10, §11.1.
  • MM6 — "Unset" and "false" are different values. ARIA tri-state (checked=mixed, pressed absent vs =undefined) means a boolean cannot encode the domain. Predicts: state is quad-valued (True/False/Mixed/Undefined) and "key absent" ≠ Undefined. Bug without it: a non-toggle button announced as un-pressed, or mixed collapsed to false. Applied: ADR-07, §11.1, Phase 4 (## 16).
  • MM7 — Pruning must be auditable, never silent. "Why did my element vanish from the AX tree?" is the #1 a11y debugging question; deletion destroys the answer. Predicts: excluded nodes stay in the arena with an IgnoredReason, not dropped. Bug without it: undiagnosable missing-element reports. Applied: P6, I-6, Phase 6 (## 18).
  • MM8 — The diff stream is a log; a gap desyncs the consumer. AT reconstructs state by applying ordered AXTreeUpdate deltas from a baseline — exactly like a replication log. Predicts: updates are causal+ordered (removals→adds→reparents→field changes) and a dropped update forces a full re-baseline. Bug without it: out-of-order NodeAdded before its parent → orphan apply. Applied: P12, I-9, ADR-13, Phase 8 (## 20), Operational Readiness (stream lifecycle).
  • MM9 — Platform mapping is a pure leaf function, deliberately. Each map_* depends on one AXNode only — no tree walk, no retained state. Predicts: projections are cacheable, parallelizable, trivially diffable, and the stale-state bug class cannot reappear at the platform boundary. Bug without it: backend-held state desyncs from the tree (P3's bug, one layer down). Applied: P10, I-11, ADR-14, Phase 9 (## 21).
  • MM10 — Spec is the oracle; a single browser is not. Behavior derives from WAI-ARIA/HTML-AAM/accname/Core-AAM, cross-checked differentially against Chromium — divergences are spec-clause disputes, not "Chromium is right." Predicts: every fixture maps to a clause; intentional spec-correct deviations are enumerated, not hidden. Bug without it: copying a browser quirk as if it were the spec. Applied: P1, ADR-20, Phase 12 (## 24), Compatibility & Versioning (differential parity).

Back-of-Envelope Capacity Model

Numbers an expert computes before designing, each derived step-by-step from §4 System Constraints. Inputs (from §4): per-AXNode ≤ 256 B (excl. name/desc strings); dom_to_ax entry ≤ 16 B; AXTreeUpdate ≤ 512 B/single-attr change; build ≤ 0.5 µs/node; map_* ≤ 200 ns/node; incremental p50 < 100 µs. Assume a "large page" ≈ 100k DOM nodes with a typical live-fraction (non-pruned) of ~0.6 (the rest display:none/aria-hidden).

  • N1 — AX nodes from DOM. ax_nodes = dom_nodes × live_fraction = 100k × 0.6 = 60k exposed AXNodes. (Pruning is the first capacity lever — §4.2 budgets the resident arena, not the DOM.)
  • N2 — Arena RAM. ax_nodes × per_node = 60k × 256 B ≈ 15.4 MB for node bodies; +dom_to_ax 60k × 16 B ≈ 0.96 MB. Total ≈ 16.3 MB, comfortably under the §4.2 ceiling of 32 MB / 100k nodes (which budgets the full 100k as if unpruned — a 2× headroom).
  • N3 — Name/description string heap. Strings are excluded from the 256 B. At an estimated ~40 B average accessible name over, say, 40% of nodes that carry one: 0.4 × 60k × 40 B ≈ 0.96 MB. Arena + strings ≈ 17.3 MB — still < 32 MB.
  • N4 — Cold build wall time. dom_nodes × 0.5 µs/node = 100k × 0.5 µs = 50 ms (the §4.1 P1 target). Walk visits every DOM node once (pruned subtrees are visited to decide exclusion but not allocated), so the divisor is DOM size, not AX size.
  • N5 — Full platform projection time. ax_nodes × 200 ns = 60k × 200 ns = 12 ms per platform (§4.1 P8). Four platforms on demand = up to 48 ms if all four are projected; in practice one target is active.
  • N6 — Full serialized export size. §4.2 budgets ≤ 8 MB for a 100k export; at 60k exposed nodes and ~130 B/node compact ≈ 60k × 130 B ≈ 7.8 MB — at the ceiling, confirming the compact projection (not JSON) is required for the IPC path.
  • N7 — Incremental cost per single-attr mutation. Dirty closure for a leaf attribute change ≈ the node + its name-dependent ancestors. With a name-from-content depth of ~3, dirty ≈ 4 nodes × (recompute role+name+state ≈ a few µs) ≈ tens of µs → within the < 100 µs p50 (§4.1 P2). The AXTreeUpdate payload ≈ 4 × ≤512 B ≈ ≤2 KB.
  • N8 — Update throughput at a typing cadence. A fast typist drives ~8 attr/text mutations/s into a form field; coalesced per microtask, that is ~8 recompute calls/s × ~tens of µs ≈ < 1 ms/s of CPU — recompute is nowhere near the bottleneck; egress of AXTreeUpdate to AT is (N9).
  • N9 — Update egress bandwidth at high churn. At a stress rate of 10k changed-node-updates/s (Scalability Analysis m) × ≤512 B = ≈ 5 MB/s to the backend — the reason updates must coalesce per node per tick and style/visibility churn is debounced (Scalability Analysis ceilings).
  • N10 — accname work bound. A name-from-content over a 1k-node subtree is O(subtree); at the §4.1 P6 budget (~10 µs/typical widget) the dominant cost is the visited-set probes — ≤ 1000 OpaqueDomId inserts, each O(1) amortized — bounded by C2 (depth 64) and the per-node memoization in recompute.
  • N11 — Relations pass. apply_relations over ≤10k relations targets < 5 ms (§4.1 P7); union-find + DFS is O(R·α(R)) ≈ 10k × ~4 ≈ 40k ops — sub-millisecond of pure work, the budget covers dom_to_ax lookups + child-vec splices.
  • N12 — Per-document thread footprint. N independent documents = N shared-nothing arenas; at ~17 MB/100k-node doc, 10 concurrent docs ≈ 170 MB resident — linear, the basis for the "N docs → N threads" parallelism model (Scalability Analysis).

Alternative Architectures (Roads Not Taken)

Four fundamentally different designs for the same engine. Each: sketch · winning regime · the real system that embodies it · why this blueprint rejected it.

ALT-1 — Eager mirror tree (chosen).

DOM --walk--> AXTree (full mirror, arena) --mark_dirty/recompute--> minimal AXTreeUpdate --> backend
  • Wins when: the AT walks/queries the tree heavily and a complete materialized projection amortizes; cross-process delivery needs a serializable snapshot + deltas.
  • Real system: Chromium (ui::AXTree + AXTreeSerializer).
  • Chosen here because it matches the multi-process browser target, gives a clean differential oracle (dump the whole tree), and makes incremental correctness checkable against a full rebuild (I-8/I-9).

ALT-2 — Lazy / on-demand AX nodes.

AT query (node X) --> compute role/name/state for X on demand (memoized) --> return; neighbors computed only when asked
  • Wins when: the AT touches a small fraction of a huge tree (deep page, screen reader reading one region) — you never pay to materialize unread nodes.
  • Real system: the platform pull model (UIA / NSAccessibility query elements lazily); WebKit's on-demand object creation.
  • Rejected because incremental correctness becomes far harder (no full tree to diff against), live-region/event semantics need a materialized tree anyway, and the differential-vs-Chromium oracle assumes a full dump.

ALT-3 — Push serialized snapshots to a separate a11y process.

DOM --build--> serialize WHOLE tree --IPC--> a11y process holds the only AXTree --> platform map there
  • Wins when: you want the compute side to hold no tree state and a dedicated process owns all AX logic (isolation, crash containment, off-main-thread AT).
  • Real system: WebKit isolated tree (and the spirit of out-of-process a11y).
  • Rejected (for the core) because full-snapshot push per change is bandwidth-prohibitive at our mutation rates (Back-of-Envelope N9), and it duplicates the tree; we keep the option as PhaseDeferred parallel/isolated build, shipping deltas instead of snapshots.

ALT-4 — Direct DOM-walk per query (no AX tree).

AT query --> walk the live DOM, compute role/name/state inline each time --> answer; no AXTree, no cache
  • Wins when: the tree is tiny, mutation is constant (cache would thrash), or for a one-shot audit tool that reads each node once.
  • Real system: axe-core-style auditors compute role/name on demand over the live DOM (no persistent AX tree, no incremental diff).
  • Rejected for a browser engine because recomputing names (with recursive aria-labelledby) on every AT query is O(subtree) per access — quadratic under repeated reads — and there is no diff stream for AT to track changes.
