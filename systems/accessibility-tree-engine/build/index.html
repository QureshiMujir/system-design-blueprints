⬜ Phase 0 — Skeleton, DomNode trait, and the "button -> role+name" smoke test §12

Objectives
  • Stand up Cargo workspace: 7 members (ax-core, ax-dom, ax-role, ax-name, ax-build, ax-platform, ax-cli) + dependency edges per spine. Edition 2021, MSRV 1.78 (pinned rust-toolchain.toml).
  • Define DomNode trait (stubbed unimplemented!() bodies) + all ax-core shell types: AXNode, AXNodeId, Role (full variant list, no logic), AXStateValue/AXStateSet, AXPropertyMap, AccessibleName/NameFrom/NameSource, AccessibleDescription/DescriptionFrom, AXRelation, AXTree, AXTreeUpdate/AXEvent, AXError.
  • no_std + alloc gating on ax-core/ax-role/ax-name/ax-build (compile-fail guard via #![no_std] + CI target). std on ax-dom/ax-platform/ax-cli.

  • Differential-oracle scaffold: Chromium AX-dump fixture format + parser behind dev feature diff-oracle (no comparison logic yet).
  • Constraint introduced: every public type #[non_exhaustive] where future variants land (Role, AXError, AXTreeUpdate); all stubs return AXError or unimplemented!(), never silently default.
Deliverable

  • cargo test --workspace runs; the smoke test passes.
  • axtree binary builds; every subcommand reachable (exits 2, "unimplemented").
  • make ci green locally; CI workflow green on push.
  • diff-oracle dev feature compiles; fixture parser round-trips one sample Chromium dump.

  • Scope: Node arena (element + text), inline computed-style fields (display/visibility), attribute + aria-attribute storage, NativeState, focusability, parent/children, shadow_root/assigned_slot, stable OpaqueDomId, and a compact fixture builder (HTML-ish + inline style) for tests/CLI/conformance/fuzz.

⬜ Phase 2 — Role enum and explicit ARIA role parsing §14

Objectives
  • Define the full Role enum in ax-core (module role): every concrete value across WIDGET/COMPOSITE/STRUCTURE/LANDMARK/LIVE/WINDOW categories; abstract roles modeled but never constructible as a computed value.
  • Implement parse_role_tokens(value: &str) -> Option<Role>: split the space-separated WAI-ARIA role token list, return the first valid concrete token, skip unknown + abstract tokens, None when none valid.
  • Implement compute_role's explicit branch only (implicit HTML-AAM deferred to Phase 3): explicit wins → else None here → caller falls back; Generic is the terminal fallback wired in 2.2.
  • Constraint: no_std + alloc; token parsing is allocation-free over &str slices (no String per token). Abstract-role rejection is data-driven, not a long match arm.
Deliverable
  • cargo build -p ax-core -p ax-role clean. compute_role resolves explicit roles end-to-end against the ax-dom reference DOM; implicit_role is a None-returning stub. Explicit fallback + abstract-rejection + generic matrix green.
Acceptance
  • Role has every spine-listed concrete variant; 0 abstract variants constructible (compile-time: no abstract identifiers in the enum).
  • Token matrix: ≥ 60 cases pass, incl. fallback ("foo button"→Button), abstract-skip ("widget link"→Link), abstract-only ("range widget"→Generic), empty (""→Generic), whitespace-only → Generic.
  • parse_role_tokens ≤ 200 ns for a 4-token attr (no heap alloc — verified by #[global_allocator] counting harness). Round-trip from_token(name) == Some(r) for all concrete name.

⬜ Phase 3 — Implicit role mapping (HTML-AAM) §15

Objectives
  • Implement implicit_role<N: DomNode>(n) -> Option<Role> per ARIA-in-HTML (HTML-AAM): tag-name table + attribute-dependent variants + the input[type] matrix.
  • Compose compute_role = explicit (Phase 2) → implicit → Generic, with presentational role conflict resolution woven in.
  • Scope: HTML namespace only; SVG/MathML → Generic/None placeholder (deferred). No name/state/tree work (Phases 4–6).
  • Constraints: pure fn of one DomNode + bounded ancestor/sibling queries; no AX tree, no allocation beyond &str parses; deterministic; data-table-driven (single static map) so the table is auditable against the HTML-AAM spec.
Deliverable

ax-role builds with implicit_role + full compute_role (explicit→implicit→Generic + conflict resolution). cargo test -p ax-role passes the HTML-AAM fixture suite. CLI axtree dump --roles on an ax-dom fixture prints the computed role per node; <input type=checkbox>→Checkbox, <th scope=row>→RowHeader, <a>(no href)→Generic.

Acceptance
  • 100% of HTML-AAM tag/input[type] mappings in the table have a passing fixture; every non-abstract spine Role produced by ≥1 fixture or explicitly marked unreachable-by-implicit.
  • Conflict-resolution matrix: focusable + role=presentation re-exposes implicit role (≥6 cases incl. <button role=none>, <a href role=presentation>); non-focusable bare role=none stays flattened.
  • compute_role median < 1.5 µs/node, p99 < 5 µs (warm static table); zero heap allocs per call (verified via allocation-counting harness). Table lookup O(1).
  • Differential spot-check vs Chromium AX dump (Phase 12 hook): ≥99% role agreement on the seeded HTML-AAM corpus.

⬜ Phase 4 — State and property computation §16

Objectives
  • Populate AXNode.states: AXStateSet + AXNode.props: AXPropertyMap from ARIA attributes + native host state (DomNode::native_state), independent of tree construction (consumed later by ax-build).
  • Model aria-checked/expanded/pressed/selected/grabbed as AXStateValue tri/quad-state (True|False|Mixed|Undefined); booleans (disabled/required/readonly/busy/multiline/atomic/modal) as bool.
  • Implement ARIA-over-native precedence with the spec's forbidden-override exceptions; compute aria-hidden → states.hidden + an ignored hint (pruning itself is Phase 6).
  • Constraints introduced: no_std + alloc; per-node, side-effect-free given a node + its Role; no tree walk (relations/recursion deferred). Scope EXCLUDES name (Phase 5) + pruning (Phase 6).
Deliverable

compute_states + compute_props compile in ax-core (no_std), callable standalone. The tri-state + ARIA-vs-native precedence test matrix passes. axtree dump --states <fixture> prints role + states + props + per-entry source.

Acceptance
  • Matrix: ≥120 (attrs,native,role) cases incl. all tri-state combos (true/false/mixed/undefined) × {radio, checkbox, switch, button, option, row, tab} — 100% pass.
  • Precedence: ≥20 conflict cases (ARIA vs native) assert correct winner incl. ≥4 forbidden-override exceptions.
  • compute_states ≤ 400 ns/node typical (≤12 attrs), ≤ 1.5 µs worst case (all states); zero heap alloc for ≤16 entries (inline AXStateSet); ≤ 96 bytes AXStateSet + ≤ 128 bytes AXPropertyMap resident/node.
  • Numeric parse: malformed/overflow never panics (clamp/Undefined); 0 panics under fuzz (Phase 12).

⬜ Phase 6 — Tree construction and pruning §18

Objectives
  • Implement ax-build::build_tree<N: DomNode>(root: &N) -> AXTree: one full DOM→AX walk producing the accessibility tree (accessible objects) from a styled DOM, integrating Phases 2–5 (role/name/state).
  • Implement is_included<N: DomNode>(n: &N, role: Role) -> bool: inclusion/exclusion per Core-AAM "Excluding Elements" + presentational flatten.

Deliverable

  • A pruning/inclusion fixture suite (≥40 fixtures) green; BuildStats emitted; dom_to_ax round-trips every retained DOM node.
Acceptance
  • cargo test -p ax-build green; ≥40 inclusion fixtures, line-exact vs goldens. Coverage of is_included branches ≥95% (cargo llvm-cov).
  • Determinism: identical DOM → byte-identical dump across 1000 runs (no map/hash-order leakage; use insertion-ordered children).
  • Performance: build a 100k-DOM-node tree in ≤40 ms (single thread, release); peak heap ≤ 2.2 × (ax_nodes × sizeof AXNode); zero unbounded recursion (work-stack depth bounded by DOM depth, asserted ≤ 65 536).
  • No panics on any fuzz-generated DOM (Phase 12 fuzzer seeded from these fixtures); display:none subtrees contribute 0 AXNodes.

⬜ Phase 7 — Relations and aria-owns reparenting §19

Objectives
  • Implement apply_relations(tree: &mut AXTree) in ax-build (module build): resolve all id-reference relations + perform aria-owns reparenting after Phase 6 produced the DOM-order pruned AX tree.
  • Relations covered → AXRelation::{Controls, LabelledBy, DescribedBy, FlowTo, ActiveDescendant, Details, ErrorMessage} (id-ref resolution only); Owns additionally mutates AX structure.
  • Invariants enforced: one-owner-max per node; no self-ownership; no ownership cycle (AXError::RelationCycle); dangling/empty/ignored ref → AXError::OrphanReference (drop edge, do not abort).
  • Constraint: apply_relations runs over AXNodeId space only (no DomNode re-walk); resolves ids via tree.dom_to_ax. Non-goal: live-region/activedescendant semantics (Phase 10 consumes the resolved edge), platform projection (Phase 9).
  • Determinism: owns reparent order = owner's aria-owns IDREF token order; remaining DOM-order children keep relative order.
Deliverable
  • apply_relations resolves all 7 non-owns relation kinds into RelationEdges and performs aria-owns reparenting, emitting Vec<AXError> (non-fatal diagnostics) without panicking on any malformed input.
  • axtree dump --relations prints resolved edges + reparented structure; axtree validate surfaces RelationCycle/OrphanReference/duplicate-owner diagnostics.
Acceptance
  • ≥ 40 unit fixtures green incl. cycle / self / duplicate / orphan / forward-ref / cross-shadow-rejected.
  • apply_relations is O(R + N) (R = relation edges, N = AX nodes); ≤ 1 DFS per owns component; zero re-walk of DomNode.
  • Reparent latency ≤ 5 µs per owned node (10k-node tree, warm); apply_owns total ≤ 2 ms on 10k nodes / 1k owns edges.
  • No edge resolution allocates beyond the owner's IDREF token Vec; RelationMap reserved once at start.
  • 100% of WPT wai-aria aria-owns/controls/relations subset (Phase 12 gate) reparent identically to Chromium AX dump.

⬜ Phase 8 — Incremental recomputation §20

Objectives
  • Implement mark_dirty + recompute (ax-build): DOM mutation → minimal AXTreeUpdate set, vs. full build_tree rebuild. Target: recompute touches O(dirty subtree), not O(tree).
  • Map each MutationKind → dirty AXNodeId(s) via dom_to_ax; propagate dependency dirtiness (name-from-content → ancestors; aria-labelledby/describedby target → referencer; aria-owns target → owner subtree).
  • Emit ordered diff mirroring Chromium AXTreeSerializer: NodeAdded/NodeRemoved/RoleChanged/NameChanged/StateChanged/Reparented. Invariant: recompute result == diff(rebuild) — the equivalence property.
  • Constraints introduced: dirty propagation must be sound (never under-invalidate) yet bounded; no new public types beyond MutationKind; AXTree.dirty is the only mutable scheduling state.
Deliverable

ax-build::{mark_dirty, recompute} compile and run: mutate the reference DOM (ax-dom), call mark_dirty per change, then recompute returns an AXTreeUpdate stream that, applied to the prior AXTree, yields a tree byte-identical (via canonical serialization) to a fresh build_tree. axtree diff old.html new.html consumes this path. Property test + under-invalidation regression test green.

Acceptance
  • Equivalence property (proptest, ≥10k cases): for random fixture + random mutation script, apply(recompute) == build_tree(mutated) (canonical AXNode serialization). 0 mismatches.
  • Under-invalidation regression: ≥40 curated scripts (text→ancestor name, label-target→referencer, owns retarget, hidden toggle, type-attr role flip) each assert the dependent node IS in the update set.
  • Minimality: emitted updates ⊆ true field-level diff; no spurious StateChanged on unchanged nodes (assert updates.len() == true_diff.len()).
  • Latency: single attribute mutation on a 50k-node tree recomputes in < 120 µs (p99); subtree of N dirty nodes < 2.5 µs × N. recompute allocates ≤ O(updates), not O(tree).
