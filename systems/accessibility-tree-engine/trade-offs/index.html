Decisions (§9) · 25 ADRs

1

Implementation language

Chosen

Rust, edition 2021, MSRV 1.78

Rejected

C/C++; Go; TypeScript

When the rejected choice is right

C++ wins when embedding into an existing C++ engine (Blink/WebKit) where FFI cost + a second toolchain outweigh memory-safety gains, and the team already carries the a11y-CVE tax.

Why: Ownership + typed sum types catch the stale-tree / role-state-mapping / memory-safety bugs dominating C++ a11y-engine CVE history; arena + generational ids model DOM↔AX without dangling refs. Go = weak sum types + GC pauses on the incremental path; TS = no allocation control, blocks no_std.

2

Crate decomposition

Chosen

Cargo workspace, 7 members (ax-core/ax-dom/ax-role/ax-name/ax-build/ax-platform/ax-cli)

Rejected

Single mega-crate; per-spec micro-crates

When the rejected choice is right

Single crate wins for a one-shot internal tool with no external embedders — fewer manifests, faster incremental compile, no published-API surface to keep stable.

Why: Layered DAG (core ← dom ← role ← name ← build; core ← platform) isolates the normative vocabulary, enables independent fuzz/bench targets, keeps the no_std boundary crisp.

3

Core std posture

Chosen

ax-core/ax-role/ax-name/ax-build = no_std + alloc; std only in ax-dom/ax-platform/ax-cli

Rejected

std everywhere; full #![no_alloc]

When the rejected choice is right

std everywhere wins if the engine only ever runs in a full-std browser process and never targets WASM/embedded — std::collections + threads simplify the code with no portability cost.

Why: Embeddable core (browser/WASM host); std confined to reference DOM, export, binary. Tree growth needs alloc.

4

Host DOM coupling

Chosen

Generic over DomNode trait; concrete arena DOM in ax-dom for tests/CLI/fuzz only

Rejected

Hard dependency on one DOM crate; dyn trait objects

When the rejected choice is right

dyn DomNode wins when many DOM impls coexist in one binary and code-size from monomorphization matters more than the per-node vtable indirection (plugin host loading foreign DOMs).

Why: Consumes computed style + attributes via DomNode (mirrors 258 Element / 261 EventTarget); monomorphized, zero vtable cost on the hot walk.

5

AX node identity & storage

Chosen

AXNodeId(u32) generational ids into an Arena<AXNode> in AXTree

Rejected

Rc<RefCell<AXNode>> graph; Box tree; raw pointers

When the rejected choice is right

Rc<RefCell> wins for a tiny tree with no serialization and heavy ad-hoc cross-links where borrow-checker friction outweighs arena bookkeeping (a prototype, not a production engine).

Why: Stable ids survive reparent/prune, serialize directly, dirty-set is Set<AXNodeId>; generational tags turn use-after-free into a typed miss.

6

Role representation

Chosen

Role as one closed enum (abstract roles only as documented rejected values)

Rejected

String / interned role tokens; open enum

When the rejected choice is right

Interned strings win if the role set must be open at runtime (host injects vendor roles the engine cannot know at compile time) — the closed enum cannot represent them.

Why: Exhaustive match over WAI-ARIA 1.2; validate_role/implicit_role/platform mapping are total; abstract roles unrepresentable as live values.

7

State value model

Chosen

AXStateValue { True, False, Mixed, Undefined } tri/quad-state in AXStateSet

Rejected

bool per state; Option<bool>

When the rejected choice is right

bool wins for a domain with only true/false states (no mixed, no tri-state ARIA) — the extra variants are dead weight and widen every match.

Why: aria-checked=mixed/aria-pressed/aria-expanded need >2 values; quad-state makes "unset vs false" explicit per ARIA + Core-AAM.

8

Accessible name shape

Chosen

AccessibleName { text, from: NameFrom, sources: Vec<NameSource> }

Rejected

plain String

When the rejected choice is right

Plain String wins for a non-debuggable embedded sink that never surfaces a trace UI and is byte-budget-constrained — the sources Vec is pure overhead there.

Why: Provenance powers name-trace (## 23) + diagnostics; text alone loses the precedence audit trail accname demands.

9

accname recursion safety

Chosen

Explicit NameContext { visited, traversal_root, in_aria_labelledby }

Rejected

Implicit call-stack recursion; depth cap only

When the rejected choice is right

Depth-cap-only wins when inputs are trusted/non-cyclic (server-rendered, validated markup) and the per-call visited set allocation is a measured hot-path cost.

Why: Cyclic aria-labelledby must terminate; visited set + in_aria_labelledby enforce labelledby-no-reentry without a magic depth limit.

10

name-from-content gating

Chosen

Role-gated: only button/link/heading/cell/menuitem/… recurse into content

Rejected

Always recurse; never recurse

When the rejected choice is right

Always-recurse wins for a content-summarization tool (not AT) that wants aggregate descendant text regardless of role — a different product, not an accname engine.

Why: Matches accname gating + axe-core rules; ungated recursion leaks container text into names.

11

Relations / aria-owns placement

Chosen

Separate apply_relations pass after the walk

Rejected

Inline reparenting during the walk

When the rejected choice is right

Inline reparenting wins if aria-owns only ever targets already-visited (earlier-in-DOM) nodes — no forward refs means a second pass is wasted work.

Why: Owns reparenting needs the full node set (forward refs); a second pass resolves all relations + guards cycle/orphan/dup/self-ownership.

12

Recomputation strategy

Chosen

Incremental dirty-set: mark_dirty → recompute walks only dirty subtrees

Rejected

Full rebuild on every mutation

When the rejected choice is right

Full rebuild wins for small/static trees (<1k nodes, rare mutation) where a sub-ms full walk beats the complexity + bug surface of dependency-tracked invalidation.

Why: Mutation-driven projection of a large mutable tree; recompute cost ∝ changed subtrees. Name/labelledby deps dirty dependents transitively.

13

Diff / update model

Chosen

AXTreeUpdate enum diff stream (Add/Remove/Role/Name/State/Reparent), mirrors Chromium AXTreeSerializer

Rejected

Resend whole tree; ad-hoc callbacks

When the rejected choice is right

Resend-whole-tree wins when the tree is tiny or the channel is cheap/local (in-process AT) — diffing cost + ordering bugs exceed the resend cost.

Why: Minimal serialized delta to AT; proven Chromium model; enables axtree diff.

14

Platform mapping shape

Chosen

Pure map_uia/map_ia2/map_atspi/map_macos → serializable projection; PlatformBackend::apply

Rejected

Trait-per-platform with embedded state; direct OS calls inline

When the rejected choice is right

Direct inline OS calls win in a single-platform shipping product (macOS-only app) where the projection indirection adds latency with no cross-platform payoff.

Why: Core-AAM is a stateless Role+state→platform-role transform; pure fns are unit-testable + differential-checkable.

15

Real OS accessibility IPC

Chosen

Deferred behind PhaseDeferred; ship a serializable projection + inspect backend

Rejected

Bundle UIA/IA2/AT-SPI2/AXAPI bridges now

When the rejected choice is right

Bundling bridges now wins for a product whose sole purpose is shipping AT integration on one OS this quarter — deferral would block the only deliverable.

Why: Non-goal: live OS IPC. Model the projection + PlatformBackend; concrete bridges risk platform lock-in.

16

Serialization formats

Chosen

JSON for dump/inspect; compact binary for the PlatformBackend IPC path

Rejected

One format only; XML; protobuf hard dependency

When the rejected choice is right

Protobuf/FlatBuffers win at very high cross-process update rates where schema-evolution discipline + zero-copy parse beat JSON's readability (a hot multi-process AT bus).

Why: JSON = readable + matches Chromium AX dump for differential testing; binary = low-overhead delta channel. Via serde (gated).

17

Tracing / introspection

Chosen

Built-in name-trace + role-trace hooks surfacing NameSources + role precedence

Rejected

Ad-hoc logging; rebuild externally

When the rejected choice is right

External rebuild wins for a frozen, spec-stable engine where the trace plumbing's binary-size/maintenance cost outweighs in-process introspection (rare).

Why: Debuggability of computed role/name is first-class (## 23); provenance already on AccessibleName/NameFrom.

18

Error handling discipline

Chosen

Result<_, AXError> for recoverable faults; panic only on internal invariant breach

Rejected

Panic on bad author input; silent best-effort

When the rejected choice is right

Silent best-effort wins for a fire-and-forget batch auditor that never reports per-node errors and prizes throughput — Result plumbing is then noise.

Why: Malformed authoring is expected input, not a crash; typed AXError drives validate diagnostics.

19

Fuzzing harness

Chosen

cargo-fuzz (libFuzzer): role parse, accname recursion, build, owns reparent, incremental

Rejected

No fuzzing; QuickCheck-only

When the rejected choice is right

proptest/QuickCheck-only wins for purely structural invariants where shrinking matters more than coverage-guided byte mutation (no parser surface to fuzz).

Why: Recursion + reparenting + dirty diffing are cycle/orphan/panic-prone; coverage-guided fuzzing finds them (## 24).

20

Differential oracle

Chosen

Chromium AX dump + axe-core computed role/name as conformance oracles

Rejected

Hand-written expectations only

When the rejected choice is right

Hand-written expectations win where no comparable engine exists, or to intentionally diverge from Chromium quirks toward strict spec (the oracle would mislead).

Why: Authoritative third-party baselines across the role matrix; catches spec-interpretation drift (## 24).

21

Conformance corpus

Chosen

W3C WPT wai-aria + accname + html-aam

Rejected

Bespoke fixtures only

When the rejected choice is right

Bespoke fixtures win for a private superset/subset of ARIA not covered by WPT (an internal design-system role vocabulary) where WPT under-tests the real surface.

Why: Normative, spec-tracked coverage; the same suite reference engines target.

22

Benchmarking

Chosen

criterion micro + macro (cold build, incremental recompute, name compute)

Rejected

#[bench] nightly; none

When the rejected choice is right

No benches win for a correctness-only tool with no latency SLA (an offline linter) where bench maintenance buys nothing.

Why: Stable-channel statistical benches guard the incremental budget (## 24).

23

CI

Chosen

GitHub Actions: build, test, clippy -D warnings, fmt, MSRV 1.78, fuzz smoke, WPT/oracle

Rejected

None; ad-hoc local

When the rejected choice is right

Local/ad-hoc wins for a solo throwaway spike before any collaborators — CI setup outweighs its value pre-team.

Why: Enforces MSRV + lint + conformance every push.

24

Dependency policy

Chosen

Minimal vetted set: hashbrown, bitflags, serde (gated); dev-only criterion/cargo-fuzz/proptest

Rejected

Heavy framework deps; petgraph; ad-hoc hashing

When the rejected choice is right

petgraph wins if relation analysis grows into general graph algorithms (dominators, SCC variants) beyond owns-cycle detection — reimplementing them in-crate would be the larger risk.

Why: Small audited surface keeps the no_std core lean + supply-chain risk low; graph logic stays in-crate.

License

Chosen

MIT OR Apache-2.0 (SPDX)

Rejected

GPL; single-license

When the rejected choice is right

GPL wins if the goal is to force downstream a11y improvements back upstream (a copyleft-aligned reference engine) at the cost of proprietary-embedder adoption.

Why: Permissive dual license = Rust-ecosystem norm, maximal embeddability.

Alternative Architectures (Roads Not Taken)

Four fundamentally different designs for the same engine. Each: sketch · winning regime · the real system that embodies it · why this blueprint rejected it.

ALT-1 — Eager mirror tree (chosen).

DOM --walk--> AXTree (full mirror, arena) --mark_dirty/recompute--> minimal AXTreeUpdate --> backend
  • Wins when: the AT walks/queries the tree heavily and a complete materialized projection amortizes; cross-process delivery needs a serializable snapshot + deltas.
  • Real system: Chromium (ui::AXTree + AXTreeSerializer).
  • Chosen here because it matches the multi-process browser target, gives a clean differential oracle (dump the whole tree), and makes incremental correctness checkable against a full rebuild (I-8/I-9).

ALT-2 — Lazy / on-demand AX nodes.

AT query (node X) --> compute role/name/state for X on demand (memoized) --> return; neighbors computed only when asked
  • Wins when: the AT touches a small fraction of a huge tree (deep page, screen reader reading one region) — you never pay to materialize unread nodes.
  • Real system: the platform pull model (UIA / NSAccessibility query elements lazily); WebKit's on-demand object creation.
  • Rejected because incremental correctness becomes far harder (no full tree to diff against), live-region/event semantics need a materialized tree anyway, and the differential-vs-Chromium oracle assumes a full dump.

ALT-3 — Push serialized snapshots to a separate a11y process.

DOM --build--> serialize WHOLE tree --IPC--> a11y process holds the only AXTree --> platform map there
  • Wins when: you want the compute side to hold no tree state and a dedicated process owns all AX logic (isolation, crash containment, off-main-thread AT).
  • Real system: WebKit isolated tree (and the spirit of out-of-process a11y).
  • Rejected (for the core) because full-snapshot push per change is bandwidth-prohibitive at our mutation rates (Back-of-Envelope N9), and it duplicates the tree; we keep the option as PhaseDeferred parallel/isolated build, shipping deltas instead of snapshots.

ALT-4 — Direct DOM-walk per query (no AX tree).

AT query --> walk the live DOM, compute role/name/state inline each time --> answer; no AXTree, no cache
  • Wins when: the tree is tiny, mutation is constant (cache would thrash), or for a one-shot audit tool that reads each node once.
  • Real system: axe-core-style auditors compute role/name on demand over the live DOM (no persistent AX tree, no incremental diff).
  • Rejected for a browser engine because recomputing names (with recursive aria-labelledby) on every AT query is O(subtree) per access — quadratic under repeated reads — and there is no diff stream for AT to track changes.
