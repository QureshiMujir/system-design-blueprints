4.1 Worked complexity derivation

W×H image, k×k kernel, separable into k+k:

  • Dense convolution: O(W·H·k²). Separable: row pass O(W·H·k) + column pass O(W·H·k) = O(W·H·k) — the win grows with k.
  • FFT convolution: pad to next size, FFT (#369) O(W·H·log(W·H)) independent of k → wins for large k (crossover ≈ k where k² > c·log(WH)).
  • Box (integral): integral image O(W·H); each window sum O(1) (4 lookups) ⇒ O(W·H) independent of window.
  • Canny: smooth O(W·H·k) + gradient O(W·H) + NMS O(W·H) + hysteresis O(W·H) (each pixel pushed once) ⇒ O(W·H·k).
  • Hough lines: O(edge_pixels · |θ|) votes + O(|ρ|·|θ|) peak scan; circle adds a radius dimension (gradient-guided cuts it).
  • Harris: gradients O(W·H) + windowed structure tensor (separable box/Gaussian) O(W·H·k) + response O(W·H).
  • Homography DLT: build 2N×9 matrix, SVD O(N + 9³) via #349; RANSAC × iterations.
  • Connected components: two-pass union-find O(W·H·α). Constants dominated by #181 SIMD (pixel loops), #369 FFT (large-kernel conv), #349 SVD (homography); most ops are memory-bandwidth-bound at small kernels. These derivations ground the quantified targets (M1–M14) in §32.1 and the BoE numbers in §36.

36. Back-of-Envelope Capacity Model

The numbers an expert computes before designing, each derived from §4 System Constraints with the formula shown. Baseline image: 1920×1080 (≈2.07 MP) unless stated.

1. Per-pixel work: dense vs separable vs FFT (k×k kernel).

dense:      k²   multiply-adds / pixel
separable:  2k   multiply-adds / pixel   (row pass + column pass)
FFT-conv:   ~c·log₂(W·H) / pixel, independent of k   (c ≈ small constant)
k=3:  dense 9,  separable 6   → separable barely wins (use it anyway, MM1)
k=15: dense 225, separable 30 → separable 7.5× fewer ops
k=31: dense 961, separable 62 → separable 15× ; FFT now competitive (see #5)

2. Separable Gaussian throughput vs the §4 target.

§4: 3×3 conv ≥ 500 Mpix/s single core (SIMD #181)
separable 3×3 = 6 MAC/pixel; at 500 Mpix/s → 3.0 G MAC/s effective
a 9×9 separable Gaussian = 18 MAC/pixel → 3.0e9 / 18 ≈ 167 Mpix/s
→ on a 2.07 MP frame: 2.07e6 / 167e6 ≈ 12.4 ms/frame  → ~80 fps single core, bandwidth permitting

3. Integral-image memory and overflow bound.

§4: bounded O(W·H); box must be window-size-independent
integral of u8 image, W·H ≤ 100 MP: max sum = 255 × 100e6 = 2.55e10
2.55e10 > u32 max (4.29e9)  → integral accumulator MUST be u64 (or i64)  (I13)
integral storage: 100 MP × 8 B = 800 MB  → for >25 MP images, tile the integral or use i32 with bounded tiles

4. FFT-conv crossover kernel size (derivation).

spatial (dense) cost/pixel ≈ k² ; FFT cost/pixel ≈ c·log₂(W·H), c≈3 (fwd+mul+inv amortized)
crossover when k² ≈ c·log₂(W·H)
2.07 MP: log₂(2.07e6) ≈ 21 ; c·log₂ ≈ 3×21 = 63 ; k ≈ √63 ≈ 7.9 (dense)
vs separable 2k: 2k ≈ 63 → k ≈ 31 before FFT beats *separable*
→ FFT beats DENSE near k≈8 but beats SEPARABLE near k≈31  → the §4 "k≳15" gate is the conservative dense crossover (matches MM4)

5. Scale-pyramid memory (geometric series).

base 2.07 MP f32 = 2.07e6 × 4 B = 8.29 MB
Gaussian pyramid total = base × (1 + 1/4 + 1/16 + …) = base × 4/3 ≈ 11.05 MB
Laplacian pyramid ≈ same 4/3 factor (band-pass residuals)
→ a full pyramid costs ≈ 1.33× the base image — cheap (§22.7)

6. Hough line accumulator size (ρ bins × θ bins).

ρ range = ±image diagonal = ±√(W²+H²) ; for 1920×1080: diag = 2202 px → ρ ∈ [−2202, 2202]
ρ_res = 1 px → 4405 ρ bins ; θ_res = π/180 (1°) → 180 θ bins
accumulator = 4405 × 180 = 792,900 cells × 4 B (u32) ≈ 3.17 MB
→ fits in L2/L3-adjacent working set; finer θ_res = 0.5° doubles it to 6.34 MB (§18.7)

7. Hough line voting cost.

votes = edge_pixels × |θ bins|
a frame with 1% edge density: 2.07e6 × 0.01 = 20,700 edge pixels
votes = 20,700 × 180 = 3.73e6 accumulator increments  → sub-millisecond at memory speed
→ confirms standard Hough is cheap on sparse edge maps; dense (texture) maps are the cost (§18.8)

8. Hough circle: why the naïve 3-D accumulator is rejected.

naïve (a,b,r) accumulator = W × H × |r bins|
1920 × 1080 × 100 radii × 4 B = 829 MB  → too large, and votes = edge_px × |r| × circumference
gradient method: 2-D centers (W×H×4B = 8.29 MB) + 1-D radius histogram per center
→ ~100× smaller accumulator + edge_px (not edge_px×|r|×circumference) votes  → the whole reason for ADR-12 (§19.6)

9. Brute-force descriptor matching cost.

§21: matching O(n·m·D) ; ORB descriptor D = 256 bits = 4 × u64 words
two images, n=m=2000 keypoints: comparisons = 2000 × 2000 = 4e6 pairs
each = 4 popcounts (Hamming) → 1.6e7 popcount ops  → ~ms with SIMD popcount (#181)
n=m=50,000 (retrieval): 2.5e9 pairs × 4 = 1e10 popcounts → seconds  → this is where FLANN/ANN wins (ADR-14, §35)

10. Homography DLT + RANSAC cost.

DLT: build 2N×9 matrix, SVD O(N + 9³) via #349 ; 9³ = 729 → negligible per fit
RANSAC iterations for 99% confidence at outlier ratio ε, sample size s=4:
   iters = log(1−0.99) / log(1 − (1−ε)⁴)
   ε=0.3 → (0.7)⁴ = 0.24 → iters = log(0.01)/log(0.76) ≈ 4.605/0.274 ≈ 17 iterations
   ε=0.5 → (0.5)⁴ = 0.0625 → iters = 4.605/0.0645 ≈ 71 iterations
→ RANSAC is tens of cheap DLT fits, not thousands (§23.7); confirms §4 "robust to 30% outliers"

11. Warp throughput vs §4.

§4: bilinear warp ≥ 100 Mpix/s single core
bilinear = 4 samples + 4 mul + 3 add per dst pixel ≈ 11 ops/pixel
2.07 MP dst: 2.07e6 / 100e6 ≈ 20.7 ms/frame
bicubic = 16 samples → ~4× the sampler cost → ~25 Mpix/s → 83 ms/frame  (ADR-16 quality/speed knob)

12. End-to-end deskew pipeline budget (the #387 path, §3.4).

decode (#173) + gray + gaussian(9×9 sep, #2 above ~12 ms) + canny (~3× a conv pass ≈ 6 ms)
   + hough lines (~1 ms, #7 above) on a 2.07 MP page
≈ 12 + 6 + 1 + overhead ≈ ~20–25 ms/page single core
→ ~40–50 pages/s single core before I/O; comfortably real-time for document deskew (§3.4)
