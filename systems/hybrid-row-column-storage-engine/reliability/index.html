Threat Model

Scope: a single-node, embeddable storage engine. The primary adversary is untrusted on-disk bytes — pages, WAL records, and column segments that may be corrupt (hardware/media faults, partial writes) or adversarial (a tampered data directory). Secondary: untrusted input rows (via the API/hydb CLI) and operator error. Out of scope (other projects own them): network attackers (no protocol, 33/64), authn/authz/multi-tenant isolation, distributed/Byzantine actors (36/86/102), side-channel/timing attacks. We do not assume the data directory is a security boundary against a privileged local user; we assume the OS enforces file permissions.

26.1 Trust boundaries

  trusted: in-RAM engine types (Page after decode, Tuple, ColumnBatch, Snapshot)
  ----------------------------------- ON-DISK FORMAT BOUNDARY -----------------------------------
  UNTRUSTED bytes: segment files (hy-page), WAL file (hy-wal), column segment blobs (hy-col),
                   the manifest/catalog (hy-catalog)
  ----------------------------------- API / CLI INPUT BOUNDARY ----------------------------------
  UNTRUSTED input: caller-supplied rows, keys, predicates, ScanSpec, CLI args
  • Rule: every byte crossing the on-disk boundary is validated before becoming a trusted type — no unsafe transmute without prior checksum + bounds + tag check. Decode is total (from_bytes returns Result, never panics on any input; panics on adversarial bytes are bugs, Phase 13 fuzz gate). The MVCC visible(h,snap) predicate is the single gate for data exposure; no read path bypasses it.

26.2 Security properties (durability/atomicity as security)

Property → enforced by: Integrity (read = last committed write or typed error, never silently wrong) → CRC32C + pageLSN; Atomicity (all-or-nothing across row+delta+main) → WAL log-before-data + ARIES/CLR; Durability (committed survives crash) → flush(lsn) before ack + group commit; Isolation (no uncommitted/GC'd-early version) → visible() + Vacuum watermark; Recoverability (column store rebuildable from WAL+row/delta) → ColumnFlush + idempotent redo.

26.3 Threat catalog

T1 — Corrupt / torn pages

  • Vector / detect: partial 4 KiB write (power loss), bit rot, sector reorder; CRC32C over page body in PageHeader (verified on every buffer-pool load) + pageLSN ≤ WAL tail sanity.
  • Mitigate / recover / telemetry: log-before-data makes the page redo-reconstructible from recLSN; optional double-write buffer (torn_page_guard); if unrecoverable and not in DPT, quarantine + ErrorKind::Corruption{page}. Counters page.checksum_fail, page.torn_repaired.

T2 — Malformed column segments

  • Vector / detect: bad encoding length, out-of-range dict code, BitPacked{bits}>64, RLE run overflowing n_rows, FoR delta exceeding bits, offset past segment end; per-segment CRC32C + bounds-checked decoders validate every offset/length vs segment size + n_rows (dict codes < dict.len()).
  • Mitigate / recover / telemetry: decoders return Result, a failed segment fails only its RowGroup scan (never reads neighbor memory); fuzz target per Encoding (Phase 13); rebuild via forced re-merge from delta+WAL. col.decode_reject{encoding}, col.segment_checksum_fail.

T3 — WAL tampering / truncation

  • Vector / detect: truncated tail, flipped bytes, injected record, reordered LSN; per-record CRC32C + length prefix + monotone Lsn + known-variant tag (exhaustive match rejects unknown tags).
  • Mitigate / recover / telemetry: clean truncation point — first bad-CRC/length/non-monotone record defines EOL, all after discarded (unfinished group commit); a Commit with a bad payload CRC is treated as not committed; redo to the truncation point, undo losers with CLRs. wal.truncated_bytes, wal.checksum_fail_at_lsn. (Durability also assumes fsync truly persists — the documented PostgreSQL "fsyncgate" (2018) showed an fsync EIO can be reported once and lost; we treat an fsync error as fatal and refuse to ack, never retry-and-assume-durable.)

T4 — Resource exhaustion (DoS)

  • Sub-vector → cap: huge tuple → max_tuple_bytes reject at insert; delta overflow → delta_max_{rows,bytes} forced merge + backpressure (DeltaFull above hard cap); unbounded chains (long reader) → Vacuum watermark + chain-length alert + txn_age_max refusal; pathological scan → scan_max_rowgroups + cancellation token; ColumnBatch/hash-agg blowup → batch ≤ 2048 + agg_mem_budget spill; huge-WAL recovery → checkpoint_interval bounds redo span. Telemetry: delta.fill_ratio, vacuum.oldest_snapshot_age, txn.aborted_overflow.

T5 — MVCC visibility leaks

  • Vector / mitigate: a bug exposing uncommitted/aborted/prematurely-GC'd versions; single visible(h,snap) predicate is the only visibility check (get, scan, delta-merge, mover all route through it), Vacuum never reclaims a version newer than the oldest live Snapshot (watermark), aborted txn ids stay in active-set logic until cleaned.
  • Test / telemetry: proptest random interleavings assert SI (no dirty read, no lost-update-vs-SI, no torn delta/main read) + differential vs SQLite serial history; mvcc.visibility_invariant_fail = 0 (CI gate).

T6 — Decoder / parser panics on adversarial bytes

  • Vector / mitigate: OOB index, unwrap/arithmetic panic, infinite loop (RLE run=0, cyclic next_version), allocation panic (length → huge Vec); decode paths deny unwrap_used, gate allocation by validated length ≤ segment/page size, bound the next_version walk by a visited-budget.
  • Fuzz / telemetry: Phase 13 targets for page/WAL/Encoding/BTree-node decode; decode.error{kind}, any fuzz panic = release blocker.

T7 — Integer overflow in offsets / lengths / ids

  • Vector / mitigate: slot off+len wrap, n_rows*width overflow, Lsn/TxnId wrap; checked_*/saturating_* on all untrusted math (overflow ⇒ ErrorKind::Corruption), CI -C overflow-checks=on + overflow test profile; TxnId/Lsn u64 (no realistic single-node wrap, documented).

T8 — Supply-chain risk

  • Mitigate / telemetry: cargo-deny (license allowlist, cargo-audit advisories, banned/dup gates), minimal justified dep set, no proc-macro/network crates in the core, --locked + vendored lockfile; CI fails on any new advisory or non-allowlisted license.

T9 — Operator mistakes

  • Vector / detect: deleting/renaming a segment, hydb recover against the wrong dir, mixing two DBs' segments, partial restore; a signed manifest (hy-catalog) lists every live SegmentId + CRC + per-DB UUID, startup verifies manifest ↔ files (missing/extra/mismatch ⇒ refuse to open), each segment header embeds the DB UUID (cross-DB mixing rejected).
  • Mitigate / recover / telemetry: hydb recover idempotent + dry-run; compact/checkpoint never delete a referenced segment; a missing-but-reconstructible segment re-merges from WAL+delta, else fail loud. manifest.mismatch{kind}, open.refused.

T10 — Stale format reader / version mismatch

  • Vector / detect: an older engine binary opens a data directory written by a newer format version (bumped PageHeader.format_ver, WalFileHeader.wal_ver, or SegmentHeader.format_ver); without a version gate the older reader may silently misparse newer layout bytes as valid old-format data; detected by the per-unit magic+version check at byte 0 of every persisted unit (b"HYPG", b"HYWL", b"HYCS", b"HYMF").
  • Mitigate / recover / telemetry: FMT-1 invariant (Compatibility Guarantees): ErrorKind::FormatTooNew { found, supported }, exit 75, never partial-parse; WAL reader refuses wal_ver > N before analysis begins; MANIFEST version gate at open; all per-unit magic+version checks run before any byte interpretation. Metric open.format_too_new. Recovery: roll back to a prior engine binary or run hydb recover --upgrade (Compatibility Guarantees) with the new binary before opening.

26.4 Cross-cutting controls & residual risk

  • Checksums everywhere: CRC32C (HW-accelerated) on pages, WAL records, segments, manifest — first defense for T1/T2/T3/T9. Defense in depth: checksum (detect) → bounds-checked decode (contain) → WAL redo / re-merge (recover) → quarantine + loud error (fail safe); never read-through corruption silently.
  • Residual risk (accepted): undetected multi-bit corruption inside a CRC collision window (~2⁻³²/segment); a privileged local user can delete the data dir (OS-level, out of scope); no encryption at rest (defer to FS/LUKS). CI security gates (block release): zero fuzz panics, zero mvcc.visibility_invariant_fail, clean cargo-audit/cargo-deny, overflow-checks profile green.
