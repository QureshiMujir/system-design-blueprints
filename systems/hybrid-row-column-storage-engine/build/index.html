⬜ Phase 1 — Row store and buffer pool §13

Objectives
  • Durable buffer-pool-backed row heap (hy-page+hy-row), the OLTP write/point-read substrate: Page (4 KiB) + PageHeader{lsn,kind,free_ptr}, BufferPool (frame table, clock evict, pin/dirty), FileManager (segment files), PageGuard RAII pin, SlottedPage (slot dir + heap-from-end), Tuple codec vs Schema, RowStore heap (insert→RowId, get, FSM). ⬜ Phase 2 — Primary B+Tree index §14

Objectives
  • hy-index B+Tree keyed by primary-key bytes → RowId over 4 KiB PageGuard pages: lookup(key,snap)->Option<RowId> (point) + range(lo,hi,snap)->RangeIter; variable-length keys (Str/Bytes/composite), unique-key dedup, structural split/merge/rebalance; crash-safe page mutation (WAL hooks Phase 3); structural checker (balanced/sorted/no-orphan). NON-GOAL: secondary indexes, latch-coupling beyond a coarse tree latch (Phase 11), MVCC visibility (delegated to hy-txn::visible).
Deliverable

hy-index integrated with RowStore: hydb insert/get route through the B+Tree; hydb get <key> does an indexed point lookup, hydb scan --range lo..hi uses RangeIter. Microbench cargo bench -p hy-index compares index point/range vs full RowStore heap scan. check.rs invariant checker callable + run in tests.

Acceptance
  • Correctness: 1 M random unique-key inserts → all lookup succeed, all absent keys return None; range scan returns keys in sorted order, count matches predicate.
  • Performance: point lookup ≤ 5 µs warm (buffer-pool hit), tree height ≤ 4 at 1 M rows (fanout ≥ ~200 for 8-byte keys); index point lookup ≥ 100× faster than full heap scan at 1 M rows.
  • Duplicate insert on unique key → Err(DuplicateKey), tree unchanged.
  • Invariant checker passes after every randomized insert/delete sequence (10⁵ ops): balanced, sorted, fill ≥ 40% (except root), no orphan/leaked pages, sibling chain total == leaf cell count.

⬜ Phase 3 — Write-ahead log and ARIES recovery §15

Objectives
  • Make every row/index mutation durable + crash-recoverable: WAL-before-data, ARIES analysis/redo/undo, CLR-idempotent undo, basic Checkpoint. Targets: ≥256 commits/fsync, redo ≥200 MiB/s, recovery ∝ checkpoint distance, zero committed loss / uncommitted survival across N kill points. Out of scope: MVCC visibility (Phase 4); ColumnFlush defined here, replayed in Phase 12.
Deliverable

hy-wal crate compiling; hydb recover <dir> replays the log; RowStore + BTree mutations fully logged. A crash_harness test binary that forks, kills the writer with SIGKILL at randomized byte/op offsets, then runs Recovery and asserts the durability invariant.

Acceptance
  • 1000 randomized kill points: every txn with a durable Commit is present post-recovery; every txn without one leaves no trace (RowStore + BTree). 100% pass.
  • Recovery is idempotent: running Recovery::run twice yields byte-identical pages (re-crash during undo recovers cleanly via CLRs).
  • WAL rule never violated: instrumentation counter wal_rule_violations == 0 across all tests.
  • Group commit: at 64 concurrent committers, fsync count ≤ commits/256 + 1.

  • pageLSN outside page latch → redo-gate race (double-apply/lost redo); assign page.lsn under the mutation's latch, debug via non-monotone (lsn, pageLSN) per page.

Pitfalls
  • Commit visibility race: dropping from active before publishing commit_ts → snapshot sees "not active, not committed" (phantom invisibility); publish ts then drop, one critical section. xmax semantics: txn_max=0 = LIVE, not txn 0; reserve TxnId(0) INVALID, assert id != 0.

⬜ Phase 5 — Columnar main fundamentals §17

Objectives
  • RowGroup = 65_536-row partition (encoding/zone-map/delete-vector/merge unit; final group may be partial). ColumnSegment = one column's values per group {col,encoding,zone,n_rows,null_count,data:SegmentId}, column-at-a-time. Nulls: per-segment bitmap + cached null_count; decision: full-length values array + separate null bitmap (simpler SIMD Plain decode). Encoding::Plain = typed fixed-width arrays + var-len offset+blob (no compression yet). SegmentId-addressed bytes in hy-page files (may span pages). ColumnReader::scan fills ColumnBatch full-scan, verified byte-equal to RowStore projected to that column.
Deliverable

hydb load <csv> --table T builds immutable columnar RowGroups from RowStore contents; hydb scan --table T --col c streams that column as ColumnBatches to stdout. A test loads N rows, converts to row groups, scans column c, asserts byte/value-equal to the row store projected to c.

Acceptance
  • Round-trip exactness: for every column type, scan output == RowStore values incl. NULLs, all orderings preserved (row-group order = insert order). 0 mismatches over ≥10⁶ rows.
  • Row-group boundaries: N=200_000 → 4 groups (65536·3 + 3392); partial final group correct.
  • null_count == bitmap popcount == actual NULLs, per segment.
  • Plain size ≈ n_rows·width + ceil(n/8) (+32B header); within 1% for fixed-width.
  • Full-scan throughput ≥ 500 M values/s for i64 Plain (single thread, warm BufferPool).
  • cargo test -p hy-col green; segment files reopen across process restart (persistence).

Pitfalls
  • Null slot garbage: leaving uninitialized bytes in value array at NULL positions → nondeterministic Plain size / diff failures. Root cause: skip-write on NULL. Fix: write type-zero at NULL slots; debug via hexdump golden compare.
  • Off-by-one offsets (var-len): n+1 offsets required; using n drops last value's length. Symptom: last Str truncated/empty. Assert offsets.len()==n_rows+1 && off[n]==blob.len.

  • Endianness: native-LE on disk; assert target is LE (MSRV/CI) or always serialize explicit LE.

⬜ Phase 6 — Encodings and compression §18

Objectives
  • Add four light-weight encodings to Encoding (Dictionary, Rle, BitPacked, FrameOfReference), each encoder + SIMD decoder, round-trip exact. Build Compressor (inspects ColumnStats, picks the smallest valid encoding, falls back to Plain, writes segment + recomputed ZoneMap). Decode O(values), branch-light, whole-segment into a ColumnBatch, no per-value alloc; decoders panic-free on corrupt bytes (ErrorKind::Corrupt, fuzz-enforced). NON-GOAL: pushdown/pruning (Phase 7), aggregation (Phase 8) — this phase only encodes/decodes full segments.
Deliverable

hydb compact produces row groups whose ColumnSegments carry chosen non-Plain encodings; hydb analyze --print-encodings <table> reports per-column encoding + raw/encoded bytes + ratio. A fuzz target fuzz_decode consumes arbitrary (encoding_tag, n_rows, bytes) and never panics. Round-trip unit + property tests green.

Acceptance
  • decode(encode(x)) == x for all 4 encodings × all DataTypes (proptest, 10k cases each).
  • Compression vs Plain on SSB lineorder row group (65_536 rows): dict-heavy cols ≥ 4×, FoR date/key cols ≥ 2×, overall row group ≥ 2.5× smaller.
  • Decode throughput ≥ 1.0 GB/s (decoded bytes) single-thread for BitPacked/FoR; ≥ 400 MB/s Dictionary.
  • Compressor::choose picks the encoding within 5% of the true-smallest on the fixture set (no pathological mis-pick).
  • cargo fuzz run fuzz_decode survives 10M execs, zero panics, zero UB (miri-clean unpack kernels).

Pitfalls
  • BitPacked word straddle: an N-bit value spanning a u64 boundary — naive single-word read drops high bits -> wrong decode. Root cause: ignoring bit_off + bits > 64. Debug: golden vector at bits∈{3,7,13,17}, assert per-value. Fix: read two words, OR shifted halves.
  • bits=0 degenerate: constant column -> range=0 -> ceil(log2(1))=0. Packing 0 bits = no data; decoder must special-case bits==0 (emit min × n_rows) else divide-by-zero / infinite loop.
  • Dictionary code width drift: card grows past 2^bits mid-build (e.g. recount) -> codes overflow silently. Root cause: computing bits before final distinct count. Fix: two-pass — finalize dict, then pack.
  • RLE run u32 overflow: a 65_536-row group fits u32, but a single all-equal run is fine; bug appears if run counter is u16. Use u32 runs.
  • FoR signed underflow: v - base on I64 near i64::MIN overflows. Root cause: base=min, v=min is fine, but mixed signs with wide range. Fix: compute delta as u64 = (v as i128 - base as i128) as u64 after range validation.
  • Null splice misalignment: physical (non-null) index vs logical row index conflated -> values shift after first null. Debug: fixture with leading + trailing nulls. Fix: iterate logical rows, advance physical cursor only on set bits.

⬜ Phase 7 — Zone maps, scan pruning, and late materialization §19

Objectives
  • Per-segment ZoneMap{min,max,null_count} at encode time → cheap segment/row-group skipping with zero false negatives (never skip a matching segment). SelectionVector-driven filtering (predicate cols → surviving indices, downstream ops touch only those); late materialization (evaluate filter cols first, decode projected cols only for survivors). Targets: ≥10× speedup on selective queries, pruning ratio reported, property test certifies no false negatives.
Deliverable

hydb scan --predicate "<col op val>" --project <cols> over a multi-row-group table that physically skips non-matching RowGroups/ColumnSegments; emits rows_scanned / rows_pruned / rowgroups_pruned / pruning_ratio; late materialization decodes projected columns only for surviving rows.

Acceptance
  • Pruning ratio ≥ 95% on a point-range predicate over a sorted/clustered 64-row-group table (only matching RG scanned).
  • No-false-negative property test: 10⁵ random (data, predicate) pairs → pruned RGs contain zero matching rows (cross-checked vs full scan).
  • Late mat: projected-column decode count == |SelectionVector|, not n_rows, verified by decode counter.
  • Selective scan (1% selectivity) ≥10× faster wall-clock than non-pruned full scan on 4M-row table.
  • ZoneMap build adds ≤5% to encode time; metadata ≤64 B/segment.

⬜ Phase 8 — Vectorized scan and aggregation §20

Objectives
  • Batch-at-a-time execution over ColumnBatch + SelectionVector, surfaced via hy-store::scan -> BatchIter. Operators: vectorized filter (Predicate→SelectionVector), project (late-mat decode of selected rows), aggregate (SUM/COUNT/MIN/MAX/AVG) + GROUP BY hash aggregation. SIMD-friendly straight-line branch-free kernels (#[inline], slice-iter, no hot-loop bounds checks); minimal per-batch alloc (pooled buffers, zero steady-state heap except hash-table growth). Validate vs a scalar reference; hit §4 OLAP targets (≥1.5 GB/s scan, ≥500 M values/s aggregate, 1 core).
Deliverable

hydb aggregate --table T --select "SUM(x),COUNT(*) GROUP BY g" [--where pred] runs the vectorized path end-to-end over the column store, returns correct results, and emits per-query stats (rows scanned, segments pruned, batches, ns/value). Vectorized result == scalar reference result bit-for-bit on all fixtures.

Acceptance
  • Correctness: vectorized SUM/COUNT/MIN/MAX/AVG + GROUP BY == scalar reference on every fixture; AVG within 1 ULP for f64.
  • Throughput (1 core, native target-cpu): decoded scan ≥ 1.5 GB/s; ungrouped aggregate ≥ 500 M values/s; GROUP BY (≤ 10⁴ groups) ≥ 200 M values/s.
  • Allocation: steady-state per-batch heap allocs == 0 (verify via dhat/counting allocator) except hash-table resize.
  • Selectivity scaling: 1% selective filter+project ≥ 5× faster than 100% (late materialization works).

⬜ Phase 9 — Delta/main architecture and the unified read path §21

Objectives
  • Build DeltaStore (row-format MVCC writes + per-row validity bitmap) and MainStore (immutable columnar RowGroups + per-group delete vector), and the unified read path: under one Snapshot, merge visible delta + non-deleted-visible main for get and scan. Invariant: exactly-one-visible-version per (table, PK) per snapshot — no doubling/loss across the delta↔main boundary. Out of scope: conversion mechanics (Phase 10), router (Phase 11); this phase assumes static main + growing delta.
Deliverable

HybridTable::get and HybridTable::scan return rows from delta+main combined under a snapshot; hydb get/hydb scan exercise it. A test fixture loads N rows into main, applies M inserts/updates/deletes into delta, then asserts the merged result equals a reference oracle (exactly-once per PK).
