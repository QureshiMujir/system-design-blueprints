Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why must page.lsn (pageLSN) be assigned under the same page latch as the data mutation it describes, and what redo anomaly appears if it is set after the latch is released? (Phase 3 §15; §6.6; I1 INV-WAL)
  2. A row is updated in MAIN, then re-updated in DELTA, then a scan runs. Trace exactly how shadow_filter prevents both versions from being emitted, and prove the result has no double and no loss. (Phase 9 §21; §6.2; I3 INV-MULTISET)
  3. The tuple mover writes new segments, crashes before MergeCommit is durable, and restarts. Walk through recovery's decision and prove no committed row is lost and none is doubled. (Phase 12 §24; §27.3; MM5)
  4. Why does visible(h, snap) forbid reading the live commit-ts oracle inside the predicate, and what differential-test failure appears if it does? (§8.7; §6.5; Phase 13 §25)
  5. A FrameOfReference segment stores base + delta bit-packed; show how an outlier value can silently corrupt results if bits is computed wrong, and which invariant + which fixture catch it. (§8.6e; Phase 6 §18; §6.11)
  6. The OLAP target is ≤250 ms/core for a 100 M-row SUM, but the back-of-envelope shows a single core needs ~533 ms for an uncompressed column. Reconcile this — name the two mechanisms that close the gap and the § that gates each. (Back-of-Envelope §7; Phase 7 §19; Phase 8 §20)
  7. A long-running OLAP scan pins the oldest snapshot for minutes. Explain the full cascade: which reclamation stops, why the delta cannot drain, and which metric alarms first. (§27.6; §6.9; Operational Readiness txn.oldest_snapshot_age; MM9)
  8. Why is a zone map allowed to over-include but never under-include, and what is the exact arithmetic that makes a NULL or a dictionary code produce a false negative if mishandled? (§6.12; Phase 7 §19; INV-ZONE)
  9. Group commit must hit ≥10 txns/fsync for the OLTP target. Derive that number and explain the failure mode if the linger window is set too large vs too small. (Back-of-Envelope §6; ADR-13; Phase 3 §15)
  10. The access-path router picks IndexLookup for a predicate that is now non-selective because a merge rewrote MAIN without refreshing stats. Explain the 1000× slowdown, why it is a perf (not correctness) bug, and the guard. (Phase 11 §23; §6.10; §6.14)
  11. Prove that a reader running latch-free over MAIN during a tuple-mover swap observes either the entire pre-merge or entire post-merge state, never a torn mix. Name the publish primitive and the ordering constraints. (Phase 10 §22; I7 INV-SWAP; MM8)
  12. After a delete + re-insert of the same primary key, how many version-chain entries exist, what does each (txn_min, txn_max) hold, and which one does a snapshot taken between the delete and the insert see? (§8.7c; Phase 4 §16; §6.4)
  13. The differential oracle compares hydb to SQLite and DuckDB. Name three documented, non-bug divergences the harness must normalize, and which produces them. (Compatibility Guarantees; Phase 13 §25; §4)
  14. Why is MAIN reconstructible from WAL + row/delta after any crash, while a naive engine that logs only page images is not? Tie this to what ColumnFlush records and what redo replays. (Phase 12 §24; §6.7; I8 INV-REC)
  15. A 65 536-row group is fully delete-vectored. Explain why scans still pay to skip it, when its space is reclaimed, and which background process does it. (Phase 9 §21; §6.3; Phase 10 §22)
  16. Walk the full path a single corrupt byte in a compressed ColumnSegment takes from read to recovered result: detection, containment, recovery, and the fail-closed fallback. (Threat Model T2; §27.9; MM10)
  17. Why is the DELTA in row format and the MAIN in column format, rather than both columnar or both row? Give the workload each format wins and the cost of unifying them. (ADR-7, ADR-8; §6.2; Performance Engineering)
  18. The B+Tree points at a version-chain head RowId, but an update creates a new head. Explain how index and heap stay coupled across update-as-new-version and across Vacuum, and the dangling-RowId bug if they desync. (Phase 4 §16; I7 INV-IDX; §27.8)
  19. Under what condition does a write-skew anomaly commit successfully in this engine, why is that correct under the chosen isolation level, and what would forbidding it cost? (ADR-14; Phase 4 §16; §8.7)
  20. Why does the engine prefer S1 (refuse a write) over S0 (silently drop it) when the WAL volume fills, and what backpressure mechanism enforces this? (§27.4; §27.11; §6.1)
  21. A merge sets a row group's ZoneMap from staging buffers using dictionary codes instead of decoded values. Which queries silently return wrong results, and which invariant + test class catch it? (Phase 10 §22; §6.12; Phase 7 §19)
  22. Decode speed, not compression ratio, is said to bound scan latency. Construct a concrete case where a higher-ratio encoding produces a slower scan, and name the design rule that rejects it. (MM7; §6.11; Performance Engineering Performance Engineering.7)

Mental Models & First Principles

The compressed insights a storage-engine expert holds. Each: the model, what it predicts, the bug class you write without it, and the resolving § of this blueprint.

MM1 — The WAL is the database; pages are a cache. Insight: cluster state is the replay of the log; data pages, B+Tree nodes, and column segments are reconstructible caches of it. Predicts: durability reduces to one observable — "is the LSN flushed?" — and backup = WAL + last checkpoint, nothing else. Bug class without it: acking a commit before its Commit record is fsynced (silent lost-update on crash), or flushing a dirty page ahead of its log (unrecoverable corruption). Applied in: §6.1, §6.6; I1 (INV-WAL), I2 (INV-DUR); Phase 3 (§15); Phase 12 (§24).

MM2 — One logical row, two physical layouts, one MVCC clock. Insight: DeltaStore (row) and MainStore (column) are projections of one row set, not two datasets; every live row is visible in exactly one. Predicts: count(*) = live(delta) + live(main) always, and the merge boundary is the single highest-risk window. Bug class without it: a row left in delta and re-encoded into main — double-counted in aggregates, resurrected after delete. Applied in: §6.2; I3 (INV-MULTISET); Phase 9 (§21) shadow_filter; Phase 10 (§22) atomic swap.

MM3 — Visibility is a pure function, frozen at snapshot time. Insight: visible(h, snap) reads no clock and no live oracle state inside; the commit-ts oracle is sampled once when the Snapshot is taken and frozen into snap.active/snap.ts. Predicts: row-path and column-path reads of the same RowId agree by construction because they call the identical predicate. Bug class without it: branching visibility on wall-clock or live oracle state → two readers at the same snapshot disagree → differential tests diverge from SQLite. Applied in: §6.5; I5 (INV-VIS); §8.7; Phase 4 (§16).

MM4 — Recovery is repeat-history-then-undo, and it must be idempotent. Insight: ARIES redoes all logged changes (winners and losers) from recLSN, gated by pageLSN, then undoes losers, logging a CLR per undone action. Predicts: a crash during recovery converges to the same state on re-run — the CLR undo_next chain resumes, never re-applies. Bug class without it: redoing a change onto a page that already has it (no pageLSN gate → double-applied increment), or undo without CLRs (re-crash re-reverses already-reversed work). Applied in: §6.7; I8 (INV-REC); Phase 3 (§15); Phase 12 (§24).

MM5 — A single durable commit edge defines the recovery rule. Insight: every multi-step state change has exactly one durable edge — Commit{ts} for a txn, MergeCommit/ColumnFlush for a merge — and recovery's rule is "before the edge → discard, after → redo." Predicts: a half-written tuple-mover merge is always safe — its segments are orphaned and reaped if MergeCommit never became durable. Bug class without it: trimming the delta before MergeCommit is durable → committed rows vanish from both delta and main. Applied in: §27.3, §27.11; Phase 10 (§22); Phase 12 (§24).

MM6 — Zone maps may over-include but must never under-include. Insight: a ZoneMap{min,max,null_count} is an optimization layered over correctness; a false positive (scanning a non-matching segment) wastes time, but a false negative (skipping a matching segment) silently drops result rows. Predicts: pruning may only skip a segment when the predicate range is provably disjoint from [min,max] and NULL-aware. Bug class without it: comparing dictionary codes instead of decoded values, or tightening bounds from the delete vector → a matching segment skipped → rows missing, undetectable without a --no-prune parity run. Applied in: §6.12; INV-ZONE; Phase 7 (§19).

MM7 — Decode speed, not compression ratio, bounds scan latency. Insight: scans are memory-bandwidth- and decode-bound; lightweight encodings (dict/RLE/bit-pack/FoR) are chosen because they decode O(values) SIMD-friendly and are predicate-pushable, not because they compress best. Predicts: a general block compressor (zstd) with a better ratio can be slower on scan because it must decompress a whole block before any value is accessible, defeating late materialization and zone-map skipping. Bug class without it: picking encodings by ratio alone → OLAP SLOs blown despite smaller files. Applied in: §6.10, §6.11; ADR-10; Phase 6 (§18); Phase 8 (§20).

MM8 — Immutability is what makes lock-free reads and atomic swap possible. Insight: because a published RowGroup/ColumnSegment is write-once, concurrent readers scan it without latches, zone maps are freely shareable, and a merge publishes by a single pointer swap (ArcSwap) of new segments — deletes go to a separate delete vector, never edit segment bytes. Predicts: a reader holds an immutable epoch for its whole scan; the swap is all-or-nothing. Bug class without it: mutating a segment a reader is mid-scan over → torn read / use-after-free on shared decoded slices → SI broken. Applied in: §6.3, §6.13; I4 (INV-IMMUT), I7 (INV-SWAP); Phase 5 (§17); Phase 10 (§22).

MM9 — GC safety is one watermark: the oldest live snapshot. Insight: a version may be freed only when invisible to all current and future snapshots — i.e. its successor is committed and it is older than oldest_live = min(active Snapshot.xmin). Predicts: a single long-running reader pins the watermark low and blocks all reclamation, so version-chain bloat and delta-drain stalls are a policy symptom (a forgotten commit/abort), not a GC bug. Bug class without it: freeing a version still visible to a long reader → that reader sees a gap; unrecoverable, hence the hard pre-free assert. Applied in: §6.4, §6.9; INV-VAC; Phase 4 (§16); §27.6.

MM10 — Fail closed: a wrong answer is worse than a crash. Insight: the severity ladder puts S0 (silent wrong result / lost commit) above S1 (unavailability) — a query that answers wrongly is more dangerous than one that refuses, because the caller trusts it. Predicts: every corruption path ends in detect (CRC) → contain (bounded decode) → recover (WAL/re-merge) → else quarantine + loud error; a result is served only past the invariant check. Bug class without it: a _ => catch-all over WalRecord that silently drops a record during redo, or a decoder that returns guessed bytes on corruption. Applied in: §6.15, §27.11; the Threat Model; Phase 13 (§25) differential gate.

Glossary · 56 terms · site-wide glossary

HTAP
Hybrid Transactional/Analytical Processing. One engine serves OLTP point writes/reads and OLAP scans/aggregations over the same data without ETL, via delta/main + dual row/column formats.
OLTP
Online Transaction Processing. High-rate point inserts/updates/deletes/lookups, latency-sensitive (target p99 point lookup < 50 µs warm). Served by row store + primary index + delta store.
OLAP
Online Analytical Processing. Large scans/aggregations over many rows, throughput-sensitive (target ≥ 1 GiB/s/core decoded). Served by column store via vectorized execution.
row store
Write-optimized heap of slotted pages (RowStore, hy-row). Stores whole tuples contiguously; backs point lookup/update; physical home of the delta store.
column store
Read-optimized MainStore (hy-col): immutable row groups of column segments, each light-weight encoded, with zone maps. The OLAP scan target.
delta store
DeltaStore (hy-store): recent writes in row format + per-row validity bitmap. Absorbs all inserts/updates fast; merged into main by the tuple mover.
main store
MainStore (hy-store): immutable compressed columnar row groups + a delete vector. Never updated in place; rebuilt at each delta/main merge.
delta/main merge
Background conversion: drain GC-safe delta rows + surviving main rows into new compressed row groups, choose encodings, write column segments, atomically swap, drop merged versions + reset delete vector. SAP-HANA model.
tuple mover
TupleMover (hy-store): the component that runs the delta/main merge + row→column conversion + version GC, MVCC-safe under concurrent readers. Triggered by delta-size/age thresholds or hydb compact.
row group
RowGroup (hy-col): unit of columnar storage/encoding/zone-map/delete-vector/merge. Default 65 536 rows. Trades scan parallelism + pruning granularity vs per-group metadata overhead.
column segment
ColumnSegment (hy-col): one column's values for one row group: { col, encoding, zone, n_rows, null_count, data: SegmentId }. The decode/scan unit.
encoding
Per-segment compression scheme (Encoding), chosen by the Compressor from ColumnStats: Plain, Dictionary, Rle, BitPacked, FrameOfReference. Decode must be O(values), SIMD-friendly.
dictionary encoding
Dictionary{ dict }: distinct values → small codes + a dict segment. For low-cardinality strings/ints; enables predicate eval on codes.
RLE
Run-length encoding (Rle): (value, run-length) pairs. For long runs / sorted or clustered columns.
bit-packing
BitPacked{ bits }: pack integers into ceil(log2(range)) bits/value. For small-range integers / dictionary codes.
frame-of-reference
FrameOfReference{ base, bits }: store base + small bit-packed deltas. For clustered near-values (e.g. timestamps, IDs).
zone map
ZoneMap{ min, max, null_count } per column segment. Enables segment/row group skipping when a predicate cannot match its [min,max].
delete vector
Bitmap per row group marking main rows deleted since the last merge. Applied at scan time; physically removed at the next delta/main merge.
selection vector
SelectionVector(Vec<u32>): surviving row indices after a predicate. Threaded through operators so later ops touch only selected rows.
late materialization
Decode only the surviving rows (per selection vector) of projected columns, and as late as possible — minimizes decode work and memory.
vectorized execution
Batch-at-a-time processing: filter/project/aggregate over a column batch (1024–2048 values) + selection vector, amortizing dispatch and enabling SIMD kernels.
column batch
ColumnBatch (hy-col): up to 1024/2048 decoded values + a selection vector; the unit of vectorized execution and scan() -> BatchIter output.
slotted page
SlottedPage (hy-row): 4 KiB page with a slot directory growing from the front and tuple heap from the end; slots indirect to variable-length tuples, allowing in-page compaction without RowId change.
tuple
Tuple{ header, payload } (hy-row): one row's MVCC version; payload decoded against a Schema. Identified by RowId{ page, slot }.
tuple header
TupleHeader: in-tuple MVCC metadata { txn_min, txn_max, next_version, flags, null_bitmap }; basis of visibility and the version chain.
buffer pool
BufferPool (hy-page): in-memory frame cache over segment files; clock/LRU eviction, pin counts, dirty flags. Enforces log-before-data (no dirty flush before its WAL is durable).
page guard
PageGuard (hy-page): RAII pin; derefs to &Page/&mut Page, unpins on drop. Prevents eviction of in-use pages and leaked pins.
pin / eviction
Pin = increment frame use count (cannot be evicted while pinned). Eviction = clock sweep selects an unpinned, ideally clean frame; dirty victims flushed (WAL-gated) first.
B+Tree
BTree (hy-index): primary index keyed by primary-key bytes; internal separators, leaves hold RowId lists. Supports point lookup + range scan; crash-safe page writes; node split/merge.
primary index
The B+Tree mapping primary key → RowId for the row store/delta; the OLTP get/update access path.
point lookup
Single-key fetch: lookup(key, snap) -> Option<RowId> then row read, filtered by visibility. Routed to the row+delta path by the access-path router.
range scan
range(lo, hi, snap) -> RangeIter: ordered key-range traversal over B+Tree leaves.
write-ahead log
Wal (hy-wal): append-only WalRecord stream with group commit + flush(lsn). Source of truth for redo/undo.
log-before-data
WAL invariant: a page's change is durable in the WAL (its pageLSN ≤ flushed Lsn) before that dirty page reaches disk.
ARIES
The recovery algorithm: analysis → redo → undo, with CLRs and physiological logging. Recovery (hy-wal) implements it.
analysis / redo / undo
ARIES phases: analysis rebuilds ATT + DPT from the last checkpoint; redo repeats history from each page's recLSN (idempotent via pageLSN); undo rolls back losers, logging CLRs.
CLR
Compensation Log Record (Clr{ txn, undo_next }): logs an undo action so undo is idempotent across repeated crashes; undo_next skips already-undone work.
checkpoint
Checkpoint/CheckpointRec: periodic snapshot of ATT + DPT (+ column-flush state) bounding recovery scan length. Fuzzy (non-quiescent).
pageLSN
The Lsn of the last update applied to a page, stored in its PageHeader. Gates redo idempotency: skip redo when pageLSN ≥ record.lsn.
recLSN
Recovery LSN: the earliest Lsn that may have dirtied a page, recorded in the DPT. Redo starts from min(recLSN).
dirty page table (DPT)
Map page → recLSN of unflushed updates; rebuilt in analysis, bounds redo start.
active transaction table (ATT)
Map TxnId → state/lastLSN of in-flight txns; rebuilt in analysis, drives undo of losers.
MVCC
Multi-Version Concurrency Control: updates/deletes create new tuple versions (no in-place overwrite); readers see a consistent Snapshot. Writers never block readers.
snapshot isolation
IsolationLevel::SnapshotIsolation: each txn reads a fixed Snapshot; visibility uses xmin/xmax/active set + commit timestamp.
read committed
IsolationLevel::ReadCommitted: a fresh Snapshot per statement, so each statement sees latest committed data.
version chain
Logical chain of a row's versions via RowId.next_version in each tuple header; walked under a Snapshot to find the visible version.
visibility
visible(h, snap) -> bool: SI predicate — version visible iff txn_min committed before snap AND not in active AND (txn_max=0/uncommitted OR committed after snap).
commit timestamp
Monotonic Timestamp assigned by the TxnManager oracle at commit; orders versions and defines snapshot boundaries.
vacuum / GC
Vacuum (hy-txn): reclaims tuple versions older than the oldest live Snapshot; also drops delta rows already merged into main.
group commit
Batch many txns' Commit records into one WAL fsync to amortize sync cost; raises commit throughput at small latency cost.
torn page
A partially written page after a crash (sub-page atomicity). Detected/repaired via WAL redo + page checksum / double-write so recovery never trusts a half-written page.
access path
AccessPath: chosen physical read strategy — RowLookup, IndexLookup, ColumnScan(ScanSpec), or DeltaScan.
access-path router
hy-store component selecting an access path from the request shape + TableStats (rule + stats based, NOT a cost optimizer): point/get → row+delta; scan/aggregate → column+delta.
hash aggregation
Build a hash table keyed by GROUP BY columns over column batches; accumulate SUM/COUNT/MIN/MAX/AVG per group. The OLAP aggregation operator.
table format
TableFormat (hy-catalog): per-table config of which columns/row-groups are row vs column and the row group size; drives the tuple mover + access-path router.
q-error
Statistics quality metric = max(est/act, act/est); tracked for ColumnStats/TableStats to gauge router/encoding-selection accuracy.
