Decisions (§9) · 28 ADRs

ADR-01

Implementation language

Chosen

Rust 1.78+ MSRV

Rejected

OCaml, Haskell, C++

When the rejected choice is right

OCaml wins for a rapid research prototype where GC pauses are acceptable and the team is PL-academic, not systems

Why: self-hosted dogfooding; memory safety for a soundness-critical tool; mature petgraph/smallvec/bumpalo ecosystem

ADR-02

Input IR

Chosen

MIR-mini custom calculus, no Rust parser

Rejected

full Rust grammar via syn

When the rejected choice is right

a linter ingesting real .rs files directly needs the full syn-based frontend despite the churn cost

Why: isolates the checker from parser/macro-expansion churn; teaches the load-bearing primitives without syntactic noise

ADR-03

Lifetime model

Chosen

NLL only, lexical not shipped

Rejected

lexical-lifetime mode as a flag

When the rejected choice is right

a teaching tool whose explicit goal is showing the historical model side-by-side benefits from shipping both

Why: NLL is a strict superset acceptance of lexical; shipping both roughly doubles constraint-gen and test surface

ADR-04

Region inference strategy

Chosen

constraint-graph fixed point

Rejected

Polonius-style Datalog (Datafrog)

When the rejected choice is right

Polonius wins once the checker must accept the strict superset of NLL-sound programs that require flow-sensitivity (documented in divergences-from-rustc.md)

Why: simpler to implement, debug, and terminate-prove (I13); Polonius deferred as a stretch (§36)

ADR-05

Two-phase borrows

Chosen

on by default

Rejected

off by default / opt-in flag

When the rejected choice is right

a strict "aliasing linter, ergonomics be damned" variant wins by disabling it to surface every implicit reservation

Why: v.push(v.len())-shaped patterns are pervasive; off-by-default rejects the majority of idiomatic corpora

ADR-06

Panic-edge modeling

Chosen

explicit UnwindAction terminator field

Rejected

implicit (assume no unwind / panic=abort-only)

When the rejected choice is right

a permanently panic=abort embedded/no_std target wins by dropping unwind edges to shrink the CFG and speed Phase 8

Why: destructors-during-unwind is a real soundness-gap category (I5); implicit hides it

ADR-07

Closure capture

Chosen

dedicated pass (bc-closures)

Rejected

infer capture mode inline during constraint generation

When the rejected choice is right

a language with only one capture mode (always-by-reference, e.g. GC'd) wins by skipping this pass entirely

Why: avoids the circular dependency between capture mode and the closure body's own constraints (MM5)

ADR-08

Variance computation

Chosen

structural, per type declaration

Rejected

nominal/hardcoded table for built-ins only

When the rejected choice is right

a fixed, closed type universe (no user generics) wins with a hardcoded table, avoiding structural computation cost

Why: user-defined generics need correct variance too, or the checker mis-approximates every custom type

ADR-09

Suggestion scope

Chosen

4 fix patterns only (add-&, add-clone, restructure, Rc<RefCell<T>>)

Rejected

full auto-fix / arbitrary rewrite search

When the rejected choice is right

an IDE plugin with human-in-the-loop review wins with a broader unverified set since a human vets before applying

Why: each suggestion is independently verified (I11); an open-ended search space cannot be exhaustively verified in bounded time

ADR-10

Soundness oracle

Chosen

differential against a pinned rustc version

Rejected

hand-written positive/negative corpus only

When the rejected choice is right

a from-scratch language with no compatible existing checker must rely solely on hand fixtures plus formal proof

Why: hand-written fixtures under-sample real-world patterns; rustc is the closest available ground truth

ADR-11

Iteration determinism

Chosen

BTreeMap/sorted iteration in every hot path

Rejected

HashMap with a fixed seed

When the rejected choice is right

a throughput-only internal cache with no diagnostic-visible iteration wins by using HashMap for the constant-factor speedup

Why: fixed-seed HashMap is deterministic per-build but not across std/hashbrown version bumps; BTreeMap is stable by construction

ADR-12

Fuzzing strategy

Chosen

4 targets (parser, regions, borrow, differential) under cargo-fuzz/libFuzzer

Rejected

AFL++, single end-to-end target only

When the rejected choice is right

AFL++ wins when cross-language corpus sharing with a C/C++ sibling fuzzer is required

Why: per-pass targets isolate which pass owns a found bug (P13); cargo-fuzz's Arbitrary tooling integrates with bc-ir directly

ADR-13

CI/CD topology

Chosen

GitHub Actions matrix (Linux/macOS/Windows × x86_64/aarch64)

Rejected

self-hosted Buildkite/Jenkins

When the rejected choice is right

a project needing GPU runners or >6h fuzz jobs wins with self-hosted runners for cost and time-limit control

Why: free for OSS scale; first-class cargo caching actions

ADR-14

Packaging

Chosen

crates.io workspace publish (13 crates)

Rejected

single monolithic crate

When the rejected choice is right

a single-binary, no-library-reuse distribution wins by collapsing to one crate to simplify versioning

Why: downstream frontends may want bc-ir+bc-types without diagnostics/suggestions

ADR-15

Containers

Chosen

Dockerfile/compose for the conformance/fuzz harness only

Rejected

containerize the checker binary for end users

When the rejected choice is right

a hosted "borrow-check as a service" product wins by containerizing behind an API for sandboxing untrusted input

Why: the checker is a native CLI/library; containerizing adds cold-start latency violating the 50 ms target (§4)

ADR-16

Input sandboxing

Chosen

none beyond structural validation

Rejected

run each fixture in a seccomp/gVisor sandbox

When the rejected choice is right

once bc-driver gains an "execute the accepted program" mode (deferred, §37), sandboxing becomes mandatory

Why: the checker never executes the input program, only analyzes its IR — no code-execution surface exists (T1–T11, §24)

ADR-17

Release/versioning channel

Chosen

SemVer with a 0.x pre-1.0 contract

Rejected

calendar versioning

When the rejected choice is right

a project needing strict downstream API stability from day one (e.g. a stdlib) wins with strict 1.0 SemVer immediately

Why: crate APIs (§11) are still stabilizing per phase; SemVer's minor-bump-for-breaking during 0.x matches that

ADR-18

Build reproducibility

Chosen

Cargo.lock committed, --locked enforced in CI, cargo vendor snapshot at release

Rejected

floating dependency versions

When the rejected choice is right

a rapidly-iterating research fork wins with floating versions to pick up dependency fixes without a lockfile ritual

Why: a soundness-critical tool needs byte-identical builds across CI and release for audit (I9 extends to the build)

ADR-19

Time source

Chosen

no wall-clock in any analysis pass; monotonic clocks only for telemetry

Rejected

wall-clock timestamps embedded in diagnostics

When the rejected choice is right

an interactive IDE integration wins by embedding wall-clock "last checked at" in a UI-only side channel, never in the diagnostic JSON

Why: wall-clock in the analysis path breaks I9 determinism across machines/timezones

ADR-20

Concurrency/backpressure

Chosen

bc-driver bounds concurrent per-function checks to num_cpus via a bounded rayon queue

Rejected

unbounded spawn-per-function

When the rejected choice is right

a tiny corpus (<100 functions) wins by running sequentially, avoiding pool-setup overhead

Why: unbounded spawn on a 50,000-statement corpus (§4) exhausts memory (region graphs are the dominant allocator, I6)

ADR-21

Licensing

Chosen

dual MIT/Apache-2.0

Rejected

GPL-family

When the rejected choice is right

a project explicitly preventing proprietary forks wins with (A)GPL despite the adoption cost

Why: matches the Rust ecosystem convention; maximizes downstream frontend adoption

ADR-22

Logging/tracing

Chosen

tracing crate, structured spans per phase

Rejected

log + env_logger

When the rejected choice is right

a minimal embedded build with no telemetry consumer wins with bare log to shave compile-time/binary-size cost

Why: span nesting matches the phase pipeline (§3) naturally and feeds OTel export (§26)

ADR-23

Metrics

Chosen

metrics facade + Prometheus exporter in bc-driver

Rejected

hand-rolled counters printed to stdout

When the rejected choice is right

a one-shot CLI invocation with no long-running canary wins with stdout-only counters, skipping the exporter dependency

ADR-24

Diagnostic serialization

Chosen

serde_json, no binary wire format

Rejected

a custom binary diagnostic protocol

When the rejected choice is right

an LSP server wrapping this checker at very high message volume wins by moving to bincode once JSON is the measured bottleneck

Why: diagnostics are consumed by humans and editor tooling; JSON is universally parseable and eases I9/I10 diffing

ADR-25

Async/concurrency runtime

Chosen

none — OS threads via rayon only

Rejected

a tokio-based async pipeline

When the rejected choice is right

a networked "check-as-a-service" mode (deferred, §37) wins with an async runtime to multiplex client connections cheaply

Why: the checker is CPU-bound with zero I/O-wait in the hot path; async adds no throughput here

ADR-26

Testing framework

Chosen

cargo test + insta snapshot testing for diagnostic goldens

Rejected

a hand-rolled string-diff harness

When the rejected choice is right

a project targeting only pass/fail conformance buckets (no golden-text review) wins with the lighter hand-rolled harness

Why: insta gives reviewable snapshot diffs in CI for diagnostic text, matching I9/I10

ADR-27

Dependency policy

Chosen

cargo vet/cargo-deny license+advisory gate in CI

Rejected

no dependency audit gate

When the rejected choice is right

an internal-only prototype with no external distribution wins by skipping the audit gate to move faster pre-freeze

Why: a 13-crate soundness-critical chain must not silently absorb a yanked/vulnerable transitive dependency

ADR-28

Persistence/caching

Chosen

none — stateless per invocation, JSON report is the only artifact

Rejected

a persistent incremental-compilation cache (à la rustc's query cache)

When the rejected choice is right

once corpus size routinely exceeds the §4 50,000-statement ceiling, incremental caching wins to avoid re-solving unchanged functions

Why: incremental caching is a proven multi-month project on its own; out of scope for Phase 0–11 (deferred, §37)

36. Alternative Architectures (Roads Not Taken)

Alt A — Polonius / Datalog-first.

   MIR-mini --> facts: loan(L,P), subset(R1,R2,P) --> Datafrog engine
                          |                                |
                     semi-naive evaluation ---------------->
                          |
                 loans-live-at(L,P) relation --> borrow check

Regime where it wins: whenever flow-sensitive precision matters more than implementation simplicity — exactly the divergence cases in FM-2/T6. Real system: rust-lang/polonius (§5, §33). Rejected here because implementation and debugging complexity exceeds the Phase 0–11 timeline (§1, §4), and rustc itself shipped NLL first for the identical reason (ADR-04).

Alt B — Mutable Value Semantics (no borrow checker at all).

   let y = x;   // implicit copy or move-with-elision, never aliasing
   mutate(y);   // y is a distinct value; x is never observed changed

Regime where it wins: application-level code where copy cost is negligible relative to the programmer cognitive load of lifetimes. Real system: the Val/Hylo language (§33). Rejected here because this project's explicit pedagogical goal (§2) is teaching the reference-aliasing discipline itself — adopting value semantics would eliminate the entire subject matter.

Alt C — Explicit Region Annotations (Cyclone-style, no inference).

   fn f<region r>(x: &r mut T) -> &r U { ... }   // r is programmer-supplied,
                                                   // never inferred

Regime where it wins: a systems-programming population already fluent in manual memory regions (e.g. an arena-allocator-heavy C codebase migrating incrementally). Real system: Cyclone (§5, §33). Rejected here because manual region-annotation burden is exactly what NLL/rustc's ergonomic history (§1, RFC 2094) shows programmers reject at scale.

Alt D — Runtime Borrow Checking (dynamic flag, no static analysis).

   access(place) {
     if flag[place] == Borrowed { panic!("already borrowed") }
     flag[place] = Borrowed; ...; flag[place] = Free;
   }

Regime where it wins: a dynamically-typed or JIT'd host language where static whole-program analysis is infeasible. Real system: Rust's own std::cell::RefCell/RwLock, used pervasively as the dynamic escape hatch within Rust itself. Rejected here because runtime checks convert a class of bugs from compile-time rejections into production panics, violating P1 (soundness before completeness) applied to when errors surface, not just whether they are caught.
