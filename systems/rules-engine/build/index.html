⬜ Phase 1 — Facts, WorkingMemory, WME lifecycle

Objectives
  • Implement re-facts: Fact, Value, FactId, Wme, WmeId, WorkingMemory, per-type index, deftemplate schema.
  • Define assert/retract/modify with modify = atomic retract+assert (I10).
  • Establish the alpha-routing callback seam (network plugs in later).
  • Scope introduced: identity/lifetime model for facts and WMEs; SoA storage layout.
Deliverable
  • re-facts crate compiles; a standalone harness asserts/retracts/modifies facts and prints WM contents + per-type index; modify shows atomic swap with stable FactId.
Acceptance
  • Unit tests: assert returns fresh WmeId; retract removes from get + index; modify keeps FactId, changes slots, emits exactly one logical change. Generational WmeId reuse detected (stale handle → NoSuchWme).
  • Bench: assert/retract 10^6 facts < 200 ms aggregate; per-op p99 < 1 µs (no network yet).
  • 100% of re-facts public API covered by tests.
Fixtures
  • fixtures/scripts/wm_basic.facts — assert/retract/modify sequence; golden WM dump.
  • wm_modify_identity.facts — verify FactId stability across modify.
  • wm_stale_handle.facts — retract then reuse handle → expect NoSuchWme.
  • Malformed: wm_bad_slot.facts — slot out of range → SlotOutOfRange.
Pitfalls
  • Modify non-atomicity: naive retract-then-assert exposes an empty-agenda window → spurious negation-node activations later. Root cause: two separate notifications. Debug: trace change events; assert single combined event. Fix: batch the notification (I10).
  • FactId vs WmeId confusion: using FactId where WmeId expected (or vice versa) routes wrong handle into the network. Debug: newtypes prevent at compile time. Signal: type error.
  • Stale handle reuse: arena slot reuse after retract → operating on a new fact. Fix: generational ids; mismatch → error.
  • Index/store divergence: retract removes from store but not index. Detection: invariant audit (index entries all live). Signal: alpha_mem_sizes mismatch downstream.

⬜ Phase 2 — Rule + Condition/Pattern AST + rule DSL parser

Objectives
  • Implement re-ast (Rule/Condition/Action/Constraint/Expr) and re-parser (lexer + recursive-descent + Pratt expr).
  • Semantic analysis: variable binding/scoping, type checking, reject unbound RHS vars and type mismatches before the network.
  • Scope: a complete, diagnosable rule DSL per §8.1 EBNF.
Deliverable
  • parse(&str) -> Result<Vec<Rule>, Diagnostics>; CLI re-cli load <file> prints parsed AST + binding report; malformed rules produce coded diagnostics with spans.
Acceptance
  • Parses all examples/*.rdsl to expected ASTs (snapshot tests).
  • Every malformed fixture yields the exact expected error code + span.
  • Round-trip: AST → pretty-print → re-parse → identical AST.
  • Parser handles 10^4-rule file < 200 ms.
Fixtures
  • fixtures/rules/adult_senior.rdsl, loan_approval.rdsl, fraud_alerts.rdsl → golden ASTs.
  • Malformed: unbound_rhs.rdsl (E-UNBOUND-RHS-VAR), type_mismatch.rdsl (E-TYPE-MISMATCH), unknown_template.rdsl, dup_rule.rdsl, bad_paren.rdsl (recovery).
  • Pretty-print round-trip fixtures.
Pitfalls
  • Variable scope in negation: vars bound only inside not(...) leaking to RHS → silent wrong bindings. Detect: scope checker; reject. Signal: E-UNBOUND-RHS-VAR.
  • Operator precedence bugs in Pratt parser → ?a + ?b * 2 misparsed. Debug: precedence table tests.
  • Greedy lexing of <- vs </-, >= vs >/=. Fix: maximal-munch with explicit two-char tokens.
  • Span drift after comment skipping → wrong error locations. Fix: track byte offsets through skips.
  • Duplicate rule names silently overwriting → lost rule. Detect: E-DUP-RULE-NAME.

⬜ Phase 3 — Alpha network (constant tests + alpha memories) + WME indexing

Objectives
  • Build the alpha network: ObjectTypeNode (type discrimination), AlphaNode (single constant test) chains, AlphaMemory (set of passing WMEs).
  • Route each asserted WME to the correct alpha memories; support retraction removal.
  • Introduce equality hash-indexing to collapse alpha fan-out.
Deliverable
  • Asserting a fact populates the correct alpha memories; CLI alpha-dump shows AlphaMemory contents; retract empties them. DOT export (basic) shows OTN→AlphaNode→AlphaMemory.
Acceptance
  • For a rule set, each WME appears in exactly the alpha memories whose tests it satisfies (I9), validated against re-evaluation oracle.
  • Equality routing: 10^3 distinct constant values → O(1) routing (bench shows constant time vs linear chain baseline).
  • Retract removes WME from all alpha memories; post-retract audit: no alpha memory references a dead WmeId.
Fixtures
  • alpha_routing.rdsl + alpha_routing.facts → golden per-AlphaMemory membership.
  • alpha_range_tests.rdsl (age>=18, age<65) → chained tests.
  • alpha_equality_index.rdsl (many status=="X") → hash routing.
  • Malformed: assert fact of unknown type → no-op (logged), not a crash.
Pitfalls
  • Test ordering in chains affects sharing but not correctness; inconsistent ordering defeats dedup. Fix: canonicalize constraint order (sort by slot,op).
  • Float/NaN equality in alpha tests → never matches. Fix: reject NaN at parse (Phase 2); document float-eq caveat.
  • Range vs equality mix: age==18 should use index; age>=18 cannot — misclassification slows routing. Fix: classify per op.
  • WME→AlphaMem membership not tracked → O(all memories) retract. Fix: store membership list on WME (or reverse index).

⬜ Phase 4 — Beta network (join nodes, beta memories, tokens, left/right activation)

Objectives
  • Implement the beta network: BetaMemory, Token (parent-chained partial match), JoinNode with left activation (token) and right activation (WME), join tests on inter-condition variable bindings.
  • Wire alpha memories (right) + beta memories (left) into join chains; dummy top BetaMemory for first join.
  • This is the algorithmic heart: incremental multi-way join.
Deliverable
  • Multi-condition rules produce correct tokens in terminal beta memories; CLI beta-dump/tokens shows partial matches; assert builds tokens, retract removes them. Differential check vs naive nested-loop oracle.
Acceptance
  • Match completeness (I1): set of terminal tokens == brute-force join of conditions, across all conformance rule sets.
  • Incremental cost: asserting one WME builds only the newly-matching tokens (instrumented count == oracle delta), not a full recompute.
  • Retract removes exactly the dependent tokens; post-retract: zero tokens reference dead WMEs (I3, I4).
  • Hash-join: join of two 10^4-WME memories on an equi-key completes in O(matches); bench vs nested-loop baseline shows ≥10x on selective joins.
Fixtures
  • join_two_cond.rdsl (Person ⨝ Adult) + script → golden tokens.
  • join_three_cond.rdsl → multi-way join token chains.
  • join_retract_cascade.facts → assert then retract, golden token deltas.
  • join_explosion.rdsl (cross product) → expected token count + fan-out warning.
  • Differential: every fixture also run through the naive oracle; agendas/tokens must match.
Pitfalls
  • Token parent-chain indexing errors: FieldRef depth off-by-one → reads wrong condition's binding. Debug: unit-test field resolution; trace bindings per token. Signal: differential mismatch.
  • Right/left activation asymmetry bugs: building tokens only on one activation path → missed matches when the other side asserts first. Detect: fixtures that assert in both orders; both must converge.
  • Combinatorial join explosion: over-broad join → token blowup → OOM. Detect: fan-out tripwire (I11). Contain: governor cap + abort with offending join id.
  • Forgotten back-references: WME retracted but tokens linger (dangling). Detect: I3/I4 post-retract scan. Signal: dangling_token_errors>0.
  • Index staleness: join-key index not updated on token removal → ghost probe hits. Fix: update index in lockstep with beta memory.

⬜ Phase 5 — Negation and existential nodes (NCC)

Objectives
  • Implement NegationNode (negated condition: emit token iff no matching WME) and existential quantification (exists: emit iff ≥1 match).
  • Implement NCC (negated conjunctive condition): not(C1 C2 …) — a negated sub-network.
  • Correctly maintain negation under incremental assert/retract (the hardest correctness case).
Deliverable
  • Rules with not, exists, and not(...) conjunctions match correctly; toggling facts across the negation boundary flips activations exactly once per transition. CLI shows negation node counters.
Acceptance
  • Differential vs oracle for negation/existential/NCC fixtures (I1).
  • Negation flicker test: assert/retract a blocking fact repeatedly → activation appears/disappears exactly per transition, no duplicates, no stale (I2, I3).
  • Leading-negation rule (not Person(...)) fires when WM has no such fact and retracts when one is asserted.
  • NCC nesting depth 2 validated.
Fixtures
  • negation_basic.rdsl (Adult(?p) not Senior(of:?p)) + flicker script → golden activation timeline.
  • exists_basic.rdsl → golden.
  • ncc.rdsl (not(Order(?o) Cancelled(of:?o))) → golden.
  • leading_negation.rdsl → golden.
  • Malformed: unbound var inside negation referenced outside → E-UNBOUND-RHS-VAR (caught Phase 2).
Pitfalls
  • Counter desync: missing a decrement on WME retract → token never re-propagates (stuck-blocked) or double-counts. Debug: assert counter == live matching WMEs invariant. Signal: differential mismatch on retract.
  • Transition double-fire: propagating on 0→1→0 without idempotence → duplicate retract/assert of downstream token. Fix: only act on actual count transitions across 0.
  • NCC binding leakage: sub-network vars must not bind in the main chain. Detect: scope checker + differential.
  • Leading negation without dummy token: no left token → negation never evaluates. Fix: dummy top token.
  • Existential as not-not subtlety: double-negation must not double-count; prefer direct node.

⬜ Phase 6 — Terminal nodes, Activation, Agenda

Objectives
  • Implement TerminalNode (token → Activation), Activation, and the Agenda priority structure.
  • Connect token assert/retract to activation insert/remove.
  • Establish recency tagging and a default conflict-resolution ordering (full strategies in Phase 7).
Deliverable
  • A full LHS match posts an activation; agenda lists pending activations ordered by salience+recency; retracting a contributing fact removes the activation. CLI agenda shows ordered activations with sort keys.
Acceptance
  • Agenda contents == set of satisfied instantiations (I1) for all fixtures.
  • Removal: retracting a fact removes its activations in O(log n); agenda never holds an activation for an unsatisfied rule (I3).
  • Deterministic ordering: identical (rules,facts) → identical agenda order (I6) — snapshot stable across runs.
  • Agenda insert/pop bench O(log n); 10^5 activations.
Fixtures
  • agenda_order.rdsl (rules with distinct saliences) → golden ordered agenda.
  • agenda_recency.rdsl (same salience, different recency) → golden order.
  • agenda_retract_removes.facts → activation removed on fact retract.
  • agenda_signature.rdsl (two fact sets → two activations of same rule) → both present, distinct signatures.
Pitfalls
  • Stale activation after retract: terminal not wired to token removal → activation fires on dead facts. Detect: I3 scan; signal: fire on retracted FactId.
  • Binding extraction errors: wrong token-chain walk → RHS sees wrong values. Debug: compare extracted bindings to oracle.
  • Heap removal cost: linear scan to remove → O(n) per retract. Fix: indexed heap / tombstones.
  • Recency tag overflow / ties: equal recency must fall back to seq deterministically (I6).
  • Signature collision: different fact tuples hashing to same signature → wrong refraction (Phase 7). Fix: signature = ordered FactId list, not hash alone.

⬜ Phase 7 — Conflict resolution strategies + refraction

Objectives
  • Implement pluggable ConflictResolutionStrategy (depth, breadth, LEX, MEA, specificity, rule-order) with a total, deterministic order.
  • Implement refraction: an activation fires at most once for an unchanged fact set (I2).
  • Lock deterministic tie-breaking down to seq.
Deliverable
  • Switching strategy reorders firing deterministically; refraction prevents an activation firing twice on a stable fact set; modifying a contributing fact re-enables firing. CLIPS-parity tests pass.
Acceptance
  • Firing order matches CLIPS for each strategy on shared fixtures (within documented equivalence).
  • Refraction: a rule whose LHS stays satisfied fires once, not repeatedly (no infinite loop on stable WM) (I2).
  • Re-fire after modify: modifying a contributing fact re-fires the rule once.
  • Determinism: identical inputs → identical firing sequence across 1000 runs (I6).
Fixtures
  • cr_depth.rdsl, cr_breadth.rdsl, cr_lex.rdsl, cr_mea.rdsl, cr_specificity.rdsl → golden firing orders.
  • refraction_stable.facts (rule stays satisfied) → fires once.
  • refraction_remodify.facts (modify re-enables) → fires again.
  • CLIPS cross-reference: same rule set run in CLIPS → expected order documented.
Pitfalls
  • Incomplete tie-break → nondeterminism. Detect: multi-run determinism test; fix: seq final key.
  • Refraction key too coarse (rule only, ignoring fact tuple) → suppresses legitimate distinct firings. Fix: key includes fact signature.
  • Refraction not cleared on modify → rule never re-fires after legitimate change. Detect: re-fire fixture.
  • Recency definition drift between LEX/MEA → wrong order. Fix: precise per-strategy recency spec + tests.
  • Salience starvation: very high-salience rule monopolizes agenda → low-salience rules starve. Detect: starvation runbook; mitigate: document, optional fairness.

⬜ Phase 8 — Forward-chaining recognize-act cycle

Objectives
  • Implement the driver loop: fire (one activation) and fire_all (until quiescent or fire_limit).
  • RHS execution: assert/retract/modify re-enter the match (recognize-act).
  • Implement the Session lifecycle state machine (§8.5) and termination guard (I7).
Deliverable
  • End-to-end: load rules + assert facts + fire_all → rules fire in correct order, RHS mutates WM, derived facts trigger further firings, loop quiesces. CLI run produces a firing trace. The §8.4 worked example reproduces exactly.
Acceptance
  • Worked example (§8.4) produces the exact firing sequence + final WM.
  • fire_all quiesces on all terminating fixtures; trips fire_limit with diagnostic on the cyclic fixture.
  • RHS assert/retract/modify correctly re-trigger matching (recognize-act).
  • Determinism (I6): identical firing trace across runs.
  • Modify atomicity (I10): no spurious mid-modify activation observed.
Fixtures
  • recognize_act_basic.rdsl (chained derivations) → golden trace.
  • rhs_modify.rdsl → modify re-triggers.
  • infinite_loop.rdsl → fire_limit trip + diagnostic.
  • halt_action.rdsl → halts mid-run.
  • adult_senior.rdsl (§8.4) → exact golden trace + final WM.
Pitfalls
  • Infinite recognize-act loop: rule re-asserts what it consumes. Detect: fire_limit + non-progress detector (I7). Debug: trace last K firings; identify the assert/retract cycle. Recovery: fix rule or add refraction-respecting guard.
  • Concurrent modification of agenda during RHS: RHS retract removes an activation that's mid-iteration. Fix: mutate agenda through controlled API; never iterate-and-mutate.
  • Refraction bypass: RHS asserting a fact that re-satisfies a just-fired rule with a new tuple — legitimate re-fire vs loop; distinguished by signature change.
  • Modify exposing intermediate state: non-atomic modify fires a negation rule spuriously. Fix: I10 atomicity.
  • Halt mid-cascade: halt leaves agenda non-empty — define resume semantics (state Halted; explicit re-fire_all resumes).

⬜ Phase 9 — Truth maintenance / logical retraction propagation

Objectives
  • Implement JTMS-style truth maintenance: facts asserted via logical assert are justified by the firing activation's matched facts.
  • When a justification's support is retracted, auto-retract the justified fact (cascade) — non-monotonic reasoning (I8).
  • Maintain the WM-support / justification graph; handle multiple justifications, re-derivation, and cycles.
Deliverable
  • The §8.4 retraction cascade works: retracting Person auto-retracts Adult and Senior (both logically asserted). CLIPS (dependents)-style introspection lists justifications. CLI justifications <fact> and dependents <fact>.
Acceptance
  • WM-support consistency (I8): a logical fact exists iff ≥1 justification fully supported; zero unsupported-justified facts after any operation.
  • Cascade correctness: §8.4 retraction removes exactly Adult + Senior; differential vs oracle.
  • Multiple justifications: fact persists until last support removed.
  • Re-derivation: auto-retracted fact re-appears when re-justified.
  • Cycle: self-justifying logical fact retracts when external support removed (no permanent ghost).
Fixtures
  • tms_cascade.rdsl + tms_cascade.facts (§8.4) → golden cascade trace.
  • tms_multi_justify.rdsl (two rules justify same fact) → persists until both supports gone.
  • tms_rederive.facts → retract then re-justify.
  • tms_stated_vs_logical.rdsl → stated fact survives support loss.
  • tms_cycle.rdsl → self-supporting fact handled.
Pitfalls
  • Over-retraction: auto-retracting a fact that still has another justification or is stated. Detect: check all justifications + stated flag before retract. Signal: I8 audit.
  • Under-retraction: failing to retract when last support gone → ghost fact. Detect: unsupported-justified scan must be 0.
  • Cascade explosion / non-termination: deep or cyclic justification chains. Fix: DFS with visited set; cycle detection.
  • Re-derivation churn: fact retracted+re-asserted each cycle → recency thrash, refraction reset loops. Detect: monitor tms_rederive rate; mitigate: structural-equality dedup before re-assert.
  • Justification leak: justifications referencing retracted activations not cleaned → memory growth + stale support. Fix: remove justification when its activation/support dies.

⬜ Phase 10 — Backward chaining (goal-driven) engine

Objectives
  • Implement a backward-chaining solver: given a goal Pattern, prove it from working memory and rules (treating rule RHS-derivable facts as provable subgoals).
  • Reuse Fact/Pattern/unification; provide query(goal) -> Vec<Bindings> distinct from forward firing.
  • Support conjunctive goals, recursion, and depth/cycle guards.
Deliverable
  • query(goal) returns all binding solutions; CLI query Senior(of:?p) lists matches, proving via rules + facts. Monkey-banana / ancestor-style recursive example resolves.
Acceptance
  • Soundness: every returned binding makes the goal provable (verify each solution against WM+rules).
  • Completeness (bounded): all solutions within max_depth are found; documented incompleteness beyond depth.
  • Recursion: ancestor(X,Y) over parent facts terminates with cycle guard.
  • Negation-as-failure behaves per closed-world spec on fixtures.
  • Determinism: identical solution order across runs.
Fixtures
  • bc_facts_only.rdsl (goal provable directly from WM) → golden bindings.
  • bc_rule_chain.rdsl (goal via rule whose LHS is provable) → golden.
  • bc_recursive_ancestor.rdsl → terminates, all ancestors.
  • bc_naf.rdsl (negation-as-failure) → golden.
  • bc_no_solution.rdsl → empty result.
  • Malformed: goal referencing unknown template → error.
Pitfalls
  • Infinite recursion on cyclic rules (ancestor without base) → stack blow. Fix: cycle guard (goal+bindings seen) + max_depth. Signal: bc_depth_exceeded.
  • Binding leakage across branches: failing to undo bindings on backtrack → wrong solutions. Fix: trail/restore bindings per choice point.
  • Negation-as-failure soundness: floundering on non-ground negated goals. Fix: require negated subgoals ground before NAF; else error.
  • Exponential blowup on deep proof trees. Mitigate: tabling-lite memoization of proven subgoals; depth cap.
  • Order-dependence vs determinism: ensure rule/fact iteration order fixed.

⬜ Phase 11 — Incremental update correctness + node sharing / compilation optimization

Objectives
  • Implement node sharing: identical alpha/join/negation nodes shared across rules (compact network, less redundant work) while preserving per-rule semantics (I5). Cross-link #298 Incremental Computation Engine.
  • Add right/left unlinking (Doorenbos) so inactive sub-networks cost nothing.
  • Validate incremental-update correctness against the unshared baseline.
Deliverable
  • Large rule bases compile to a compact shared network (measured node reduction); shared and unshared produce identical results; unlinking measurably reduces propagation work on sparse WM. CLI reports sharing_ratio.
Acceptance
  • Node-sharing correctness (I5): shared network agenda/WM == unshared, for all conformance fixtures + property tests.
  • Sharing ratio ≥ 40% node reuse on loan_approval/fraud_alerts (rules with overlapping conditions).
  • Unlinking: on a WM where most types are absent, propagation cost scales with present data, not rule count (bench).
  • No regression: full conformance suite passes on the shared network.
Fixtures
  • sharing_overlap.rdsl (rules with common leading conditions) → expected shared node count + identical results to unshared.
  • sharing_divergence_probe.rdsl (near-identical rules differing in one test) → must NOT over-share.
  • unlink_sparse.facts (most types empty) → propagation-cost assertion.
  • Differential: shared vs unshared agendas for every existing fixture.
Pitfalls
  • Over-sharing → binding leakage (I5): two rules share a join but need different downstream bindings. Detect: shared-vs-unshared differential; root cause: sharing key omits a distinguishing test. Fix: include all join tests in key.
  • Canonicalization gaps: semantically-identical conditions with different syntax fail to share (missed optimization) — or different conditions wrongly share (bug). Fix: rigorous canonical form + tests both directions.
  • Unlink/relink races with retraction: unlinking mid-cascade drops a needed activation. Fix: relink before propagating; test with retract-heavy scripts.
  • Sharing breaks DOT/trace attribution: which rule owns a shared node. Fix: nodes carry a set of owning rule ids for observability.
  • Stale node cache across rule reload (Phase 13). Fix: rebuild cache per network version.

Acceptance

  • Trace replayability: a recorded trace deterministically reconstructs the firing sequence (matches a fresh run) (I6).

Fixtures
  • dot_shapes.rdsl → golden DOT (normalized).

  • explain_nonfiring.rdsl → golden explanation (names blocking condition).
  • snapshot_agenda.facts → golden agenda snapshot.
Pitfalls

  • Non-deterministic DOT ordering (HashMap iteration) → diff churn. Fix: sort nodes/edges by id.
  • Snapshot tearing: snapshotting mid-cycle yields inconsistent state. Fix: snapshot only at cycle boundaries (Quiescent/AgendaPopulated).
  • Explain false negatives: explain must use the same matcher as runtime, not a re-implementation. Fix: derive from actual memories.
  • Unbounded trace files on long runs. Fix: rotation / size cap / ring buffer.

⬜ Phase 13 — Rule serialization / versioning + hot rule reload

Objectives
  • Serialize rule-sets and compiled networks (bincode + JSON interchange); version-pin both (I12).
  • Implement hot rule reload: add/remove/replace rules at runtime, incrementally updating the network and reconciling existing WM-derived state — without a full session restart.
  • (BRMS UI, decision-table import remain PhaseDeferred("Deferred Features Register: BRMS UI").)
Deliverable
  • Serialize a KB to JSON + bincode and reload identically; add a rule at runtime and have it immediately match existing facts; remove a rule and have its activations vanish. CLI save/load/add-rule/remove-rule.
Acceptance
  • Round-trip: serialize→deserialize KB → byte-identical network behavior (differential).
  • Version pinning (I12): loading an incompatible version is rejected with a clear error.
  • Hot add: post-add agenda == agenda of a from-scratch build with the rule present (priming correctness).
  • Hot remove: node refcounts correct; no orphan nodes; shared nodes retained; removed-rule activations gone.
Fixtures
  • serialize_roundtrip.rdsl → JSON + bincode round-trip equality.
  • version_reject.bin (old format) → load rejection.
  • hot_add_prime.facts (facts present, then add rule) → primed activations == from-scratch.
  • hot_remove_refcount.rdsl (shared nodes) → correct node retention/removal.
Pitfalls
  • Priming omission: added rule doesn't see existing facts → silently under-fires until next assert. Detect: differential vs from-scratch; fix: replay populated memories into new sub-network.
  • Node refcount bugs on remove: remove a node still used by another rule (breaks it) or leak an unused node. Fix: owning-rule set per node; remove only at refcount 0. Signal: I5 differential.
  • Version drift unguarded: loading mismatched network format → garbage/UB. Fix: version check first (I12).
  • Reload mid-fire: editing the network during the recognize-act loop. Fix: only reload in Quiescent/Idle (or serialize).
  • TMS/justification staleness on rule removal: logical facts justified by the removed rule must be reconciled. Fix: drop those justifications → cascade.

⬜ Phase 14 — Performance hardening (indexed joins, memory pooling)

Objectives
  • Optimize the hot paths to the §4 constraints: indexed beta joins, memory pooling/arenas for tokens, SoA layouts, and (optionally) concurrent read snapshots.
  • Push to 10^6-fact scale with bounded latency; eliminate allocation churn.
Deliverable
  • Engine meets §4 targets: ≥1M WME-propagations/sec, p99 assert < 100 µs, p99 retract < 150 µs, ≤64 B/token, 10^6 facts within memory ceiling. Criterion suite green; flamegraphs documented.
Acceptance
  • All §4 constraint targets met on the benchmark workloads (documented hardware).
  • No correctness regression: full conformance + differential suite passes post-optimization (correctness-over-performance, P1).
  • Allocation: steady-state firing does zero heap allocations on the hot path (dhat-verified) beyond arena growth.
  • Read snapshot (if built): N concurrent readers + 1 writer with no data race (loom/ThreadSanitizer where applicable).
Fixtures
  • bench_assert_1e6.facts (latency histogram thresholds).
  • bench_join_scaling.rdsl (selective vs cross-product timing).
  • bench_retract_cascade.facts (cascade latency).
  • alloc_zero_hotpath.facts (dhat assertion).
  • All Phase 1–13 fixtures re-run on the optimized engine (no behavioral diff).
Pitfalls
  • Optimization-induced correctness regression — index desync, pooled-token aliasing. Detect: the full differential/conformance suite is the gate; never ship an optimization that fails it.
  • Index maintenance cost exceeding probe savings on low-selectivity joins. Measure: adaptive — index only when |memory| over threshold.
  • Pool fragmentation / leak under churn. Detect: dhat; arena high-water metrics.
  • False sharing in SoA arrays across cores (read snapshots). Fix: cache-line padding.
