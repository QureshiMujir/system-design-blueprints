4. System Constraints

Quantified engineering targets (single modern x86-64 core, ~3 GHz, L2 ~1 MB, L3 ~32 MB unless noted). The one defining property: incremental match cost is proportional to the affected token set per change, not to the rule count.

22. Back-of-Envelope Capacity Model

Each number derived from the §4 System Constraints table; formula shown.

  • BE1 — Beta-memory RAM at typical scale. tokens ≈ WM × avg_fan-out. With WM = 10^5 (§4) and a conservative avg 3 tokens/fact → 3×10^5 tokens. At ≤64 B/token (§4) → 3e5 × 64 B = 19.2 MB. Comfortably under the 2 GB ceiling (§4).
  • BE2 — Beta-memory RAM at the join-explosion tripwire. A single join warns at 10^4 tokens (§4). 10 such joins near the cap → 1e5 × 64 B = 6.4 MB per such layer; the hard cap exists precisely because an unbounded cross-product would blow past 2 GB (2e9 / 64 ≈ 3.1e7 tokens is the absolute token ceiling).
  • BE3 — Alpha-memory RAM at upper-bound WM. WM = 10^6 facts (§4), each in ~2 alpha memories average, at ≤16 B/entry (§4) → 1e6 × 2 × 16 B = 32 MB. Alpha state is cheap relative to beta state — consistent with MM1's "joins dominate."
  • BE4 — Sustained assert bandwidth. Throughput ≥ 1 M propagations/sec (§4); if an average assert triggers ~5 propagations (alpha route + a few join probes), sustained 1e6 / 5 = 2×10^5 asserts/sec single core.
  • BE5 — p99 latency budget vs throughput. p99 assert < 100 µs (§4) means even worst-case asserts cap at 1 / 100e-6 = 10^4 ops/sec if every op were p99; the p50 < 5 µs (2×10^5 ops/sec) is what sustains BE4 — the gap is the tail driven by fan-out.
  • BE6 — Network compile budget. < 50 ms for 10^3 rules (§4) → 50 ms / 1e3 = 50 µs per rule of build work (alpha/join node creation + sharing-cache lookup) — sets the per-rule compiler cost target.
  • BE7 — Agenda cost at scale. Agenda ops O(log n) (§4); at n = 10^5 pending, log2(1e5) ≈ 17 comparisons/op; at integer-tuple compares (~ns each) the agenda is never the bottleneck vs join probes (BE4).
  • BE8 — Retract cascade ceiling. Retract is O(affected tokens) (§4). Worst case a single high-fan-out WME contributes to the 10^4-token tripwire layer → up to 10^4 token removals; at p99 retract < 150 µs (§4) that bounds per-token removal at 150e-6 / 1e4 = 15 ns — achievable only with back-ref indexing, motivating Phase 4's WME→token maps.
  • BE9 — TMS graph size. With 10^5 facts and (say) 20% logically derived at avg 1.5 justifications each → 2e4 × 1.5 = 3×10^4 justification records; at ~32 B each (activation id + small support set header) → ~1 MB — negligible, confirming TMS is not a memory bottleneck.
  • BE10 — FD budget headroom. §4 caps FDs at ≤16 (DOT export + trace file + fixtures). A single embedded session uses ~2–3 (trace sink, optional DOT) — the budget is generous; FD exhaustion is a non-issue for the embedded core.
