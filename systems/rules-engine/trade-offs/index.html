Decisions (§9) · 30 ADRs

ADR-01

Implementation language

Chosen

Rust (edition 2021, MSRV pinned)

Rejected

Java, Python, C++, Clojure

When the rejected choice is right

Java/Clojure when you need an existing JVM BRMS ecosystem (Drools tooling, hot class reload) and can tolerate GC pauses; Python for a throwaway teaching prototype where dev speed beats throughput.

Why: No-GC predictable latency; ownership maps to token/WME lifetimes; memory-safe dense graph (§1.4).

ADR-02

Match algorithm

Chosen

RETE with beta-memory state saving

Rejected

TREAT (no beta mem), naive re-match, PHREAK-first

When the rejected choice is right

TREAT wins when WM churns so fast that beta memories are mostly invalidated each cycle (retract-heavy, memory-tight) — recompute beats maintaining stale state (Miranker 1987). Naive re-match wins for ≤ a handful of rules/facts where network overhead dominates.

Why: RETE = canonical incremental match; state saving gives O(Δ) updates.

ADR-03

Graph references

Chosen

Typed arena indices (NodeId/TokenId/WmeId = newtype u32)

Rejected

Raw pointers, Rc<RefCell>, Arc<Mutex>

When the rejected choice is right

Rc<RefCell> wins for a quick single-threaded prototype where you accept refcount churn and runtime borrow panics for less boilerplate; Arc<Mutex> wins when you genuinely need a multi-writer graph (not our single-writer model).

Why: Indices = memory-safe, cache-dense, serializable; avoid dangling tokens.

ADR-04

Memory allocation

Chosen

Slab/arena per memory type (generational)

Rejected

Global allocator per node, Vec<Box<_>>

When the rejected choice is right

Per-node global allocation wins when the network is tiny and lifetimes are irregular, so arena bookkeeping isn't worth it; Vec<Box<_>> wins for a first correctness-only build before profiling.

Why: Bulk alloc/free of tokens on retract; cache locality; generational ids catch use-after-free.

ADR-05

Working-memory store

Chosen

SoA fact store + per-type index (HashMap)

Rejected

Single Vec<Fact> scan, B-tree

When the rejected choice is right

A Vec<Fact> scan wins for ≤ ~100 facts where the HashMap and SoA overhead exceeds a linear scan; a B-tree wins when you need ordered range scans over a slot as a primary access path.

Why: O(1) type routing into alpha network; SoA improves cache use on hot slots.

ADR-06

Alpha indexing

Chosen

Hash index on equality constants; chained tests for ranges

Rejected

Linear test chain only, full trie

When the rejected choice is right

A linear test chain wins when each type has only 1–2 patterns (index build/lookup not worth it); a full trie wins for symbol-heavy bases with deep shared constant prefixes (deferred to Phase 14).

Why: Equality hash-index collapses fan-out; ranges remain chained.

ADR-07

Beta join probe

Chosen

Hash join on bound vars; nested-loop fallback for non-equi

Rejected

Always nested-loop, sort-merge

When the rejected choice is right

Nested-loop wins for non-equi joins (<, between) and tiny memories; sort-merge wins when both inputs are already sorted on the join key and you stream them once.

Why: Hash join is O(matches); nested-loop only when join predicate is non-equality.

ADR-08

Agenda structure

Chosen

Binary heap keyed by (salience, tie-break, recency, seq)

Rejected

Sorted Vec, BTreeSet, skip list

When the rejected choice is right

A sorted Vec wins when the agenda rarely exceeds ~16 entries (insertion sort beats heap constants); a skip list wins under pop-heavy churn with concurrent readers (revisited Phase 14).

Why: O(log n) insert/pop; total order ensures determinism.

ADR-09

Conflict resolution

Chosen

Pluggable strategy trait; default depth + salience

Rejected

Hard-coded single strategy

When the rejected choice is right

A hard-coded strategy wins for a single-purpose embedded engine where the policy is fixed and the vtable indirection per insert is measurable overhead.

Why: CLIPS/OPS5 parity (LEX/MEA/depth/breadth); pluggability for conformance.

ADR-10

Truth maintenance

Chosen

JTMS (justification-based) support graph

Rejected

ATMS, no-TMS

When the rejected choice is right

ATMS (de Kleer 1986) wins when you must reason over many hypothetical contexts simultaneously (diagnosis, constraint exploration) and want label-based context switching without re-derivation; no-TMS wins for purely monotonic rule bases.

Why: JTMS matches Drools/CLIPS "logical" assertions; ATMS multi-context overkill.

ADR-11

Backward chaining

Chosen

Separate goal-driven solver sharing Pattern/unification

Rejected

RETE-only, SLD-resolution full prover

When the rejected choice is right

A full SLD-resolution prover wins when the workload is logic-programming (Prolog-style deep recursion, complex unification with structured terms), not flat-fact rule evaluation.

Why: Goal queries need depth-first proof; full prover out of scope.

ADR-12

Rule DSL

Chosen

Custom CLIPS/Drools-flavored DSL

Rejected

Embed Lua, serde-JSON only, reuse CLIPS grammar verbatim

When the rejected choice is right

Embedding Lua/JS wins when rules need arbitrary host scripting in actions; a verbatim CLIPS grammar wins when drop-in CLIPS-file compatibility is a hard product requirement.

Why: Tailored AST for the network; JSON form added Phase 13.

ADR-13

Parser

Chosen

Hand-written lexer + Pratt/recursive-descent

Rejected

pest, nom, lalrpop

When the rejected choice is right

A PEG/parser-generator (pest/lalrpop) wins when the grammar churns rapidly and diagnostics quality is secondary, so generated tables save hand-maintenance.

Why: Best error messages + spans; no codegen dependency; full control over recovery.

ADR-14

Why: Native, reproducible, crate boundaries enforce layering.

24. Alternative Architectures (Roads Not Taken)

  • A1 — TREAT (no beta memories).
    alpha memories ──▶ [on change: recompute all joins for the affected rule] ──▶ conflict set
    Wins when: working memory churns so hard that beta memories are mostly invalidated each cycle (retract-heavy, memory-constrained), so maintaining stale partial matches costs more than recomputing. Real system: Miranker's TREAT (1987); RETE*/RC++ (Wright & Marshall 2000) generalizes both. Why rejected: our target is stable-to-moderate WM with bounded per-op latency (§4); RETE's O(Δ) updates beat per-change recompute there (ADR-02, MM2).
  • A2 — PHREAK-style lazy/segmented evaluation.
    network split into SEGMENTS; deltas queued per segment;
a segment is evaluated only when a downstream rule's result is demanded
    Wins when: the rule base is huge and mostly dormant per cycle, so eager propagation wastes work on rules no one will fire. Real system: Drools PHREAK. Why rejected (for the core): eager incremental gives simpler, more predictable per-op latency and easier determinism; PHREAK is the natural Phase 11+ extension, not the from-scratch base (ADR-02).
  • A3 — Decision-tree / sequential compilation (no network sharing of partial matches).
    rules ──compile──▶ decision tree over fact attributes ──▶ matched rule(s)
    Wins when: rules are largely single-pattern classifications with little inter-condition joining (e.g. flat decision tables), where a discrimination tree is faster and tiny. Real system: gorules/zen-engine (JDM decision tables). Why rejected: it does not generalize to multi-way joins, negation, or TMS — the core value of this project (§21 Comparative Architecture).
  • A4 — ATMS (assumption-based truth maintenance).
    every fact carries a LABEL = set of environments (assumption sets) under which it holds;
queries select an environment instead of retracting
    Wins when: you must reason over many hypothetical contexts at once (diagnosis, configuration search) and switch contexts without re-derivation. Real system: de Kleer's ATMS (1986). Why rejected: the engine targets a single evolving world with logical assertions; JTMS matches CLIPS/Drools semantics at far lower bookkeeping cost (ADR-10, MM6).
