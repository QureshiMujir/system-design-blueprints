20. Mental Models & First Principles

  • MM1 — A rule engine is an incremental, materialized multi-way join. The beta network is exactly a streaming join graph whose intermediate results (tokens) are materialized and maintained under deltas. Predicts: match cost tracks join multiplicity, not rule count; the same indexing that speeds a SQL join speeds a beta node. Bug without it: treating the matcher as "loop over rules" → O(rules×facts) re-evaluation. Applied in: Phase 4, §19.
  • MM2 — State is traded for time; that trade is the whole algorithm. RETE keeps alpha/beta memories so a change re-evaluates only the delta; TREAT keeps less and recomputes more. Predicts: RETE wins on stable WM, TREAT on churny WM; memory is the price of incremental speed. Bug without it: choosing RETE for a retract-heavy workload and drowning in stale-state maintenance. Applied in: §9 (ADR-02), §24.
  • MM3 — A token is a fact tuple frozen at a prefix of the LHS. Each token = the matched facts for conditions 1..k, parent-chained. Predicts: retracting any contributing WME must remove every descendant token; bindings are recoverable by walking the chain. Bug without it: dangling tokens / wrong bindings (the canonical RETE bug). Applied in: §8.3, Phase 4.
  • MM4 — Negation is a count, and only the 0↔1 crossing matters. A negation node holds a per-token match count; the token flips state only as the count crosses zero. Predicts: multiple blockers don't multiply work; only boundary transitions fire/retract. Bug without it: flicker, double-fire, stuck-blocked tokens. Applied in: Phase 5.
  • MM5 — Refraction is the fixpoint guard. Forward chaining is a fixpoint computation; refraction is what keeps it from re-firing a satisfied rule forever. Predicts: a stable fact set must quiesce; a loop means either refraction failed or the rule genuinely changes WM each cycle. Bug without it: infinite recognize-act loops on stable data. Applied in: Phase 7, Phase 8.
  • MM6 — Truth maintenance is reference counting over derivations. A logical fact lives while ≥1 justification's support is alive — a refcount whose increments are firings and whose decrements are retractions. Predicts: cascades are transitive decrefs; cycles need the same care as cyclic GC. Bug without it: ghost facts (under-retract) or vanished facts (over-retract). Applied in: Phase 9.
  • MM7 — Determinism is a total order you must author, not discover. Conflict resolution is only reproducible if the sort key is total down to a unique seq. Predicts: any tie left to HashMap iteration is a latent flaky bug; replay is free once the order is total. Bug without it: nondeterministic firing, unreproducible incidents. Applied in: Phase 7, §8.5.
  • MM8 — Compilation and execution are separate clocks. Building the network (compile) and propagating facts (run) are distinct phases; keeping them separate is what makes hot reload and incremental compilation possible. Predicts: you can swap a sub-network while WM is live, if you prime it. Bug without it: coupling that forces a full restart on any rule change. Applied in: §6 (P11), Phase 13 (hot reload).

Required reading (§5)

Books

  • Doorenbos, "Production Matching for Large Learning Systems" (CMU CS PhD thesis, CMU-CS-95-113, 1995). Ch. 2 (basic RETE), Ch. 3 (Rete/UL — unlinking for large rule bases), Ch. 4–5 (right/left unlinking, sharing). Why: the single most precise, implementable description of RETE — alpha/beta memories, tokens as parent-chained dotted pairs, join-node activation algorithms, negation nodes, unlinking optimization. Primary implementation reference for re-rete. Applied in: Phase 4 (beta network), Phase 11 (sharing/unlinking).
  • Forgy, "OPS5 User's Manual" (CMU-CS-81-135, 1981). Why: the original production-system semantics — recognize-act cycle, conflict resolution (LEX, MEA), refraction, recency. Applied in: Phase 7 (conflict resolution), Phase 8 (cycle).
  • Giarratano & Riley, "Expert Systems: Principles and Programming" (4th ed.). Ch. 3–5 (rule-based systems, pattern matching, the inference engine), Ch. 7 (CLIPS internals). Why: canonical treatment of forward chaining, agenda, salience, refraction; CLIPS behavior is the conformance baseline. Applied in: Phases 6–9.
  • Russell & Norvig, "Artificial Intelligence: A Modern Approach" (3rd/4th ed.). Ch. 7 (propositional logic, inference), Ch. 9 (forward/backward chaining, unification, resolution). Why: formal grounding for forward vs backward chaining and unification. Applied in: Phase 10 (backward chaining).
  • Friedman-Hill, "Jess in Action" (Manning, 2003). Ch. 7–8 (the Rete engine, defrules, working memory). Why: a pragmatic Java-RETE engineer's view; useful for API ergonomics and salience/agenda semantics. Applied in: Phases 6–7 (agenda/strategy).
  • Hopcroft, Motwani, Ullman, "Introduction to Automata Theory, Languages, and Computation." Ch. 2–3 (discrimination/decision structures). Why: the alpha network is a discrimination tree; informs constant-test sharing and trie indexing. Applied in: Phase 3 (alpha network).
  • Garcia-Molina, Ullman, Widom, "Database Systems: The Complete Book." Ch. 15–16 (join algorithms, hash joins, indexing). Why: beta-node joins are hash/index joins; informs join design. Applied in: Phase 4 and Phase 14 (indexed joins).
  • Herlihy & Shavit, "The Art of Multiprocessor Programming." Ch. 9–11 (linked lists, skip lists, priority queues). Why: agenda priority structure and concurrent read snapshots. Applied in: Phase 6 (agenda), Phase 14 (COW snapshots).

Papers

  • Forgy, C. (1982). "Rete: A Fast Algorithm for the Many Pattern/Many Object Pattern Match Problem." Artificial Intelligence 19(1), 17–37. Contribution: the RETE network — state-saving incremental match avoiding re-evaluation of all rules per cycle. Relevance: the foundational algorithm this engine implements. Normative. Applied in: §3, Phase 4.
  • Miranker, D. P. (1987). "TREAT: A Better Match Algorithm for AI Production Systems." AAAI-87 (also UT-Austin TR-87-58). Contribution: TREAT drops beta memories, recomputing joins on change (trades memory for recompute). Relevance: the principal rejected alternative to RETE's beta-memory state saving; informs ADR-02 and the Comparative Architecture analysis. Applied in: §9 (ADR-02), Phase 4, §24 (Alternative Architectures).
  • Doorenbos, R. (1993). "Matching 100,000 Learned Rules." AAAI-93, 290–296. Contribution: right/left unlinking to keep match cost sub-linear when most rules are inactive. Relevance: Phase 11 node-sharing + unlinking for large rule bases. Applied in: Phase 11.
  • Doyle, J. (1979). "A Truth Maintenance System." Artificial Intelligence 12(3), 231–272. Contribution: justification-based TMS — beliefs supported by justifications, retracted when support vanishes. Relevance: Phase 9 logical retraction / WM-support graph. Applied in: Phase 9.
  • de Kleer, J. (1986). "An Assumption-Based TMS." Artificial Intelligence 28(2), 127–162. Contribution: ATMS — multiple contexts/labels. Relevance: contrast for Phase 9 (we implement JTMS-style, not ATMS — ADR-10 rationale). Applied in: §9 (ADR-10), Phase 9, §24 (Alternative Architectures).
  • Forgy, C. & McDermott, J. (1977). "OPS, A Domain-Independent Production System Language." IJCAI-77, 933–939. Contribution: production-system language design + recognize-act cycle. Relevance: DSL + cycle semantics. Applied in: §8 (Domain Model), Phase 8.
  • Tarjan, R. E. (1975). "Efficiency of a Good But Not Linear Set Union Algorithm." JACM 22(2), 215–225. Contribution: union-find with near-linear amortized cost. Relevance: TMS support-graph bookkeeping and cycle detection. Applied in: Phase 9 (cycle handling).
  • Sottara, D., Mello, P. & Proctor, M. (2010). "A Configurable Rete-OO Engine for Reasoning with Different Types of Imperfect Information." IEEE TKDE 22(11), 1535–1548. Contribution: the object-oriented Rete (Drools lineage) and its extensibility points (segments, evaluation). Relevance: informs the RETE-OO/PHREAK comparison and node-layout choices. Applied in: §9 (ADR-02), Phase 11, §21 (Comparative Architecture).
  • Wright, I. & Marshall, J. (2000). "The Execution Kernel of RC++: RETE, A Faster Rete with TREAT as a Special Case." (Univ. of Bristol TR, archived 2004).* Contribution: a RETE variant parameterized so TREAT is a special case (memory-vs-recompute spectrum). Relevance: memory-layout and store-vs-recompute tradeoff for tokens/WMEs. Applied in: Phase 4, Phase 14, §24 (Alternative Architectures).

Reference Implementations

  • kiegroup/drools — study drools-core/src/main/java/org/drools/core/reteoo/ (classic RETE-OO: JoinNode, BetaMemory, AlphaNode, ObjectTypeNode, RuleTerminalNode) and org/drools/core/phreak/ (PHREAK eval). Lessons: node-sharing structure, beta-memory tuple management, terminal-node activation. Pitfall not to copy: deep Java class hierarchy + heavy object boxing (memory bloat); mutable shared state guarded by coarse locks (we use single-writer + arenas). Applied in: Phase 4, Phase 6, Phase 11.
  • CLIPS (clipsrules.net source). Study factmngr.c, network.c, reteutil.c, agenda.c, engine.c. Lessons: canonical conflict-resolution strategies (depth/breadth/LEX/MEA/complexity/simplicity), agenda + salience, refraction, recognize-act loop. Pitfall: C pointer graph with manual free — exactly the dangling-token hazard we avoid via arena indices. Applied in: Phase 7, Phase 8.
  • Jess (jess.Rete, jess.ReteCompiler, node classes). Lessons: compiler→network mapping, defrule semantics. Pitfall: JVM dependence; reflection-based fact slots (slow). Applied in: Phase 2 (DSL), Phase 11 (builder).
  • gorules/zen-engine (Rust). Lessons: a modern, embeddable decision/rules engine in Rust; API ergonomics. Pitfall: it is decision-table/JDM-oriented, not a full RETE — use only for API/ergonomics inspiration, not the evaluation model. Applied in: §11 (Core Schema API shape), Phase 13 (server).
  • cerny/clara-rules (Clojure). Study network compilation + truth maintenance. Lessons: clean, functional RETE with logical retraction and a tidy session API; good model for Session semantics and TMS. Pitfall: persistent-data-structure overhead; JVM hosting. Applied in: Phase 5, Phase 9 (TMS).
  • PyKnow / Experta (Python, CLIPS-like). Lessons: readable DSL + agenda for spec calibration. Pitfall: naive matcher (not true RETE) — reference for semantics, not performance. Applied in: Phase 2 (DSL semantics), Phase 7.

Glossary (§26) · 56 terms · site-wide glossary

Activation:
a rule instantiation whose LHS is fully satisfied; lives on the agenda until fired or retracted. Carries rule id, matched fact tuple, bindings, salience, recency.
Agenda:
ordered set of pending activations; ordering decided by the conflict-resolution strategy.
Alpha network:
portion of the RETE network performing intra-condition (single-pattern) constant tests.
Alpha memory:
set of WMEs that have passed an alpha node's test chain; right-input to join nodes.
Alpha node:
a node applying one constant test to a WME.
Backward chaining:
goal-driven inference — prove a goal by recursively proving rule LHS subgoals.
Beta network:
portion performing inter-condition joins; contains join, negation, and beta-memory nodes.
Beta memory:
set of tokens (partial matches) produced by a join node; left-input to the next join/terminal.
Binding:
assignment of a value to a rule variable derived from a matched fact.
Canonicalization:
normalizing a condition (sort constraints, positional variable names) so identical conditions produce identical sharing keys.
Conflict resolution:
choosing the next activation to fire among equally-eligible ones (salience, recency, specificity, order).
Conflict set:
the set of all current activations (the agenda's contents).
deftemplate:
a fact schema declaring slots and types.
Discrimination network:
the tree/graph of tests that incrementally filter and combine facts (the RETE network).
Existential condition:
exists P — satisfied iff at least one matching fact exists.
Fact:
a unit of data in working memory; an instance of a template with slot values.
FactId / WmeId:
stable fact identity / arena handle for a working-memory element.
Fire (firing):
executing a popped activation's RHS actions.
Fire limit:
cap on total firings per fire_all run; termination guard.
Forward chaining:
data-driven inference — facts trigger rule firings in the recognize-act cycle.
Governor:
the resource component enforcing token/agenda/WM/fire caps via controlled abort.
Justification:
a record that a logically-asserted fact is supported by a firing activation's matched facts (TMS).
Join node:
beta node combining a token (left) with a WME (right) under inter-condition tests.
JTMS:
justification-based truth maintenance (Doyle 1979) — a single-context support graph.
Left activation:
propagation triggered by a new token arriving from the parent beta memory.
LEX / MEA:
OPS5 conflict-resolution strategies based on the recency of matched facts (LEX = lexicographic on all; MEA = first condition dominates).
Logical assertion:
a fact asserted with TMS support; auto-retracted when its support vanishes.
Modify:
atomic retract+assert of a fact preserving identity where possible.
NCC (negated conjunctive condition):
not(C1 C2 …) — negation of a conjunction; implemented via a negated sub-network.
Negation as failure:
proving not C by failing to prove C (closed-world assumption); used in backward chaining.
Negation node:
beta node propagating a token iff no matching WME exists (negative join).
Node sharing:
reuse of identical alpha/join/negation nodes across multiple rules for compactness.
ObjectTypeNode (OTN):
first-level node discriminating WMEs by fact type.
OrderKey:
the total-order sort key (salience, tie-break, recency, seq) used by the agenda.
Partial match:
a token — a tuple of facts satisfying a prefix of a rule's conditions.
Pattern / Condition:
a single LHS element matching facts of a type with constraints.
PHREAK:
Drools' lazy, segmented, goal-oriented evaluation extending RETE-OO.
Priming:
running existing working memory through a newly-added rule's sub-network so it reflects current facts immediately (hot reload).
Quiescence:
state where the agenda is empty and no further firings are possible.
Recency:
how recently a fact was asserted/modified; used by recency-based strategies.
Recognize-act cycle:
match → conflict-resolve → fire → re-match loop of a forward-chaining engine.
Refraction:
the rule that an activation fires at most once for an unchanged matched fact set.
RETE:
Forgy's state-saving incremental pattern-match algorithm (Latin "net").
Right activation:
propagation triggered by a new WME arriving at a join's alpha-memory side.
Salience:
integer rule priority; primary conflict-resolution key.
Session:
a runtime instance over a knowledge base with its own working memory and agenda.
Specificity:
number/strength of LHS constraints; a conflict-resolution tie-break.
Stated fact:
a fact explicitly asserted (not TMS-justified); not auto-retracted.
Terminal node:
end of a rule's join chain; converts a full-match token into an activation.
Token:
a partial match stored in a beta memory; a parent-chained list of matched WMEs.
TREAT:
Miranker's match algorithm that omits beta memories, recomputing joins on change (memory-vs-recompute tradeoff vs RETE).
Truth maintenance (TMS / JTMS):
machinery tracking belief justifications so derived facts are retracted when support is lost.
Unification:
matching a goal pattern against a fact/rule head, computing variable bindings (backward chaining).
Unlinking:
Doorenbos optimization skipping activation of joins whose alpha/beta memory is empty.
Working memory (WM):
the set of currently-believed facts.
WME (working-memory element):
a handle representing one fact's presence in the network.
