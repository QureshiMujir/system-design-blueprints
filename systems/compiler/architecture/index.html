Every stage is a pure function over typed values, returning either a refined output or Vec<Diagnostic>; only mlc-driver writes to disk. mlc-diag sits across every phase: every error type (LexErr, ParseErr, ResolveErr, TypeErr, IrErr, OptErr, BackendErr) converts to a Diagnostic with a stable code (E0001..E0999), a primary span, optional secondary spans, and an optional hint (I9). The trust boundary is the source-file boundary: anything read from SourceFile is untrusted until past mlc-lex's error-token gate (Threat Model T1–T5). The concurrency boundary is null in Phase 0 — the pipeline is single-threaded per compilation unit; bench/ measures wall-clock, not parallel throughput (Deferred Features Register, parallel front-end). The persistence boundary is the object/executable write in Phase 8 only.

8. Domain Model — The Source Language mlc

Full grammar lives in docs/spec/grammar.ebnf; this section is the readable, normative form. Worked examples, a recovery state table, and malformed/failure-path examples follow, per §6 (this standard's §6, not the blueprint's own §6 Design Principles — disambiguated here as "this document's §8").

Lexical Structure

  • Identifiers: [a-z_][A-Za-z0-9_']*; trailing ' legal (x').
  • Constructors: [A-Z][A-Za-z0-9_]* (Some, None, Cons, Nil, Ok, Err).
  • Type variables: ' + lowercase identifier ('a, 'b).
  • Keywords: let rec in fun match with if then else module import type and as where mutable open.
  • Integer literals: 0|[1-9][0-9_]*, 0x[0-9a-fA-F_]+, 0o[0-7_]+, 0b[01_]+. Underscores stripped before value parse.
  • Float literals: [0-9][0-9_]*\.[0-9_]*([eE][-+]?[0-9_]+)?.
  • String literals: double-quoted, \n \t \\ \" \u{XXXX}, raw r"...".
  • Char literals: 'a', '\n', '\u{1F600}'.
  • Comments: -- to end of line; (* ... *) nested (depth-counted).
  • Operators: + - * / mod = == != < <= > >= && || |> >> << :: ; , : -> => | plus float-kind variants +. -. *. /. >..

Surface Grammar (EBNF sketch)

module      ::= ('module' Ident)? toplevel*
toplevel    ::= 'import' modpath
              | 'type' Ident type_params? '=' type_def
              | 'let' 'rec'? Ident pat* (':' ty)? '=' expr
              | 'open' modpath
type_def    ::= ty                                     -- alias
              | constructor_def ('|' constructor_def)*  -- ADT
              | record_def | extern_def                 -- record | FFI
expr        ::= 'let' 'rec'? bindings 'in' expr
              | 'fun' pat* '->' expr
              | 'if' expr 'then' expr 'else' expr
              | 'match' expr 'with' arm+
              | expr op expr | expr expr                -- binop | application
              | atom
arm         ::= '|' pat ('when' expr)? '->' expr
pat         ::= '_' | Ident | Constructor pat*
              | '(' pat (',' pat)+ ')'                  -- tuple
              | '{' fieldpat (',' fieldpat)* '}'         -- record
              | pat '::' pat | '[]' | '[' pats ']'       -- list sugar
              | literal
ty          ::= "'" Ident | Constructor ty_arg*
              | ty '->' ty | '(' ty (',' ty)+ ')'
              | '{' fielddecl (',' fielddecl)* '}' | "'" Ident

LL(2) once the Pratt expression parser handles operator precedence (Phase 2, §14). Application is left-associative, parsed at a higher-precedence Pratt level than every binary operator.

Type System

  • Hindley-Milner with let-generalization, level-based à la OCaml (Pottier 2014) — avoids the classical O(n)-per-variable "occurs check costs you the world" generalization walk.
  • Rank-1 polymorphism only; function arguments never carry polymorphic types, only let-bindings generalize. Rank-N is an explicit non-goal absent a promoting ADR.
  • ADTs: nominal, named constructors, optional payload tuple.
  • Records: structural, row-polymorphic (Leijen 2005): { x: int, y: int | r } reads "has x, y, and zero-or-more other fields r".
  • Tuples: structural sugar for anonymous records.
  • Pattern exhaustiveness: Maranget's algorithm (I13, Phase 4). Non-exhaustive matches warn in Phase 0; --strict-match promotes to error.
  • Effects: not modeled in Phase 0 (Deferred Features Register).

Module System

A module is a file; its module name is the basename in PascalCase (option.ml → Option). Modules open each other, forming a DAG; cycles are E0303. Phase 0 has no functors.

Worked Example — mandelbrot.ml

module Mandelbrot

let max_iter = 1000

let mandelbrot cx cy =
  let rec loop zx zy i =
    if i = max_iter then 0
    else
      let zx2 = zx *. zx in
      let zy2 = zy *. zy in
      if zx2 +. zy2 >. 4.0 then i
      else loop (zx2 -. zy2 +. cx) (2.0 *. zx *. zy +. cy) (i + 1)
  in
  loop 0.0 0.0 0

This exercises: integer/float/char literals, kind-tagged float arithmetic (*.), let rec, if-then-else, and closures over max_iter. It is the canonical M7 end-to-end fixture (conformance/programs/exec/mandelbrot/).

Parser Recovery State Table

State Trigger Action Resulting State
Normal unexpected token at item boundary emit Item::Error, skip to next sync token (let/type/module/import) Normal
Normal unexpected token inside ( … ) emit Expr::Error, skip to matching ) Normal
Normal unexpected token inside { … } emit Expr::Error/Pat::Error, skip to matching } Normal
Normal EOF inside an open bracket emit E0299 (unterminated group), synthesize close Normal (diagnostic emitted once)
Normal second error before any sync token consumed suppress diagnostic (cascade guard) Suppressed
Suppressed a sync token is consumed resume normal diagnostic emission Normal

Malformed-Input Example

Input: let x = 1 + (dangling operator, EOF). Lexer: emits Int(1), Plus, Eof — no lexer error (I12: never panics). Parser: Pratt loop requests a right operand, finds Eof, emits E0210: expected expression after infix operator, synthesizes Expr::Error as the right operand, and the let binding is retained with a poisoned body so later let-bindings in the file still parse and resolve (P4).

Failure-Path Example

Input: let f x = x + true (type error). Lexer/parser/resolver succeed. Type checker: unifies int (from +'s int-kind signature, §8 Type System) against bool (from true), fails, emits E0401: type mismatch with primary span on true and secondary span on the + operator, substitutes Ty::Err for f's return type, and continues checking the rest of the module (I5, P4). f's call sites downstream still type-check against the poisoned signature without cascading a second error per call site (cascade-guard analogous to the parser's Suppressed state above).

Typed IR Shape

Every IR function is a CFG of basic blocks with block parameters (not phi nodes — the Cranelift/MLIR convention, ADR-09): bb0(%n: i64): %t0 = icmp lt %n, 2; cond_br %t0, bb1, bb2. Terminators (Br, CondBr, Switch, Return, TailCall, Unreachable) are syntactically distinct from instructions (Const, BinOp, Call, Load, Store, Closure, Tag), which materially simplifies dataflow analysis versus phi-form SSA (Phase 5, §17).
