⬜ Phase 1 — Lexer §13

Objectives
  • Turn UTF-8 source bytes into a Vec<Token> with byte-precise spans, never panicking on adversarial input (I12, P4).
  • Establish the diagnostic-code convention (E01xx) that every later phase follows (P5, I9).
Deliverable

mlc --emit lex foo.ml prints a deterministic token stream with spans; cargo test -p mlc-lex is green; the lex fuzz target runs 1 hour with zero panics.

Acceptance
  • 50+ positive fixtures pass with exact token-kind + span match (see 1.5).
  • 20+ negative fixtures pass, each asserting the exact DiagCode.
  • Lex throughput ≥ 50 MB/s on Apple M2 Pro, single core (M1, §30, ties to §4 constraint row).
  • Fuzz target lex.rs runs 3,600 s with 0 crashes (I12).
  • insta span-correctness snapshots: 0 diffs on a clean run.
Fixtures
Fixture Purpose Expected
lex/idents-unicode-001.ml Unicode-aware identifier scanning token stream matches .expected.json
lex/float-vs-field-002.ml 1.0 vs 1.foo disambiguation Float then error (no numeric field access)
lex/unterminated-string-003.ml Malformed input: unterminated string E0101, lexer continues to EOF
lex/nested-comment-004.ml (* (* nested *) *) depth counting correctly closes at depth 0
lex/bad-escape-005.ml "\q" invalid escape E0103, TokKind::Error, lexer continues
Pitfalls
  • Underscores in numeric literals are idiomatic Rust habits users import; strip before value parse, not after.
  • A trailing ' in identifiers is legal (x') but conflicts with some naive grammars' string-quote lexing — resolved by requiring ' only in trailing position, never leading, for identifiers.
  • The Newline token is easy to omit as "useless" since the grammar is whitespace-insensitive — omitting it removes the parser's only cheap recovery synchronization signal.
  • A wrong span in the lexer is cheap to introduce and expensive to trace once it surfaces three phases later as a wrong type-error span — enforce with insta span snapshots at this phase, not downstream.

⬜ Phase 2 — Parser §14

Objectives
  • Convert Vec<Token> into a Module<'arena> via hand-rolled recursive descent + Pratt (ADR-04), prioritizing diagnostic quality and recovery over grammar-generator convenience.
  • Guarantee every syntax error emits exactly one diagnostic, never a cascade (P4).
Deliverable

mlc --emit parse foo.ml prints a deterministic AST; cargo test -p mlc-parse is green; the parser fuzz target runs 1 hour with zero panics; the pretty-printer round-trip property holds on the full corpus.

Acceptance
  • 100+ positive parse fixtures pass with exact AST match.
  • 40+ negative parse fixtures pass, each asserting the exact DiagCode (e.g. E0210 for the malformed-input example in §8).
  • Parse throughput ≥ 20 MB/s (M2, §30).
  • proptest round-trip property: 0 counterexamples over 10,000 generated cases.
  • Fuzz target parse.rs: 3,600 s, 0 panics.
Fixtures
Fixture Purpose Expected
parse/pratt-precedence-001.ml All 11 precedence levels in one expression exact AST shape
parse/missing-then-002.ml Malformed if missing then ["E0210"], recovers to next item
parse/dangling-operator-003.ml let x = 1 + (§8 malformed-input example) ["E0210"], Expr::Error synthesized
parse/unterminated-group-004.ml EOF inside open ( ["E0299"]
parse/pretty-roundtrip-005.ml Round-trip via pretty-printer parse(pretty(x)) == parse(x)
Pitfalls
  • Leaving the parser in "happy path only" mode — without recovery it emits one diagnostic per file and stops; users hate that (build recovery from day one, P4).
  • Conflating the surface and resolved ASTs (P1) at parse time — resist adding semantic fields to the surface AST "for convenience."
  • Application-as-juxtaposition (f x) parsed at the wrong Pratt level silently reassociates f x + 1 as f (x + 1) — application must bind tighter than every binary operator (§8 grammar level 9 vs 6/7).
  • Forgetting the cascade guard turns one typo into fifty diagnostics — always test with intentionally broken multi-error files.

Objectives

Deliverable

Acceptance
  • 40+ positive resolve fixtures (cross-module imports, mutual recursion, shadowing) pass.
  • 20+ negative resolve fixtures pass, each asserting the exact DiagCode (E0301–E0305).
  • Zero DefTable lookup misses on the standard-library prelude (I2).
  • Resolve throughput folded into the ≥ 20 MB/s parse-adjacent budget (no independent floor; measured jointly with Phase 2 in bench/micro/resolve.rs).
Fixtures
Fixture Purpose Expected

Pitfalls
  • Getting let rec ... and ... sequencing wrong breaks mutual recursion silently — all names in the block must be in scope in every body before pass 2 resolves any of them.
  • Confusing pattern-position lowercase identifiers (bindings) with constructor-position uppercase identifiers (must resolve) — the grammar-level distinction (§8) must be enforced here, not deferred to type checking.
  • Resolving open eagerly before the opened module itself finishes pass 1 — process the module DAG in topological order.

⬜ Phase 4 — Type Checker §16

Objectives
  • Implement level-based Hindley-Milner inference with let-generalization (Damas & Milner 1982; Pottier 2014), producing a fully typed TypedModule (I4, I5).
  • Implement row-polymorphic records (Leijen 2005, Rémy 1992) and Maranget exhaustiveness checking (I13).
Deliverable

mlc --emit typed foo.ml prints a fully annotated AST; the standard-library prelude type-checks; all seven canonical benchmark programs type-check.

Acceptance
  • 80+ positive type-check fixtures pass with exact inferred-type match.
  • 60+ negative fixtures pass, each asserting the exact DiagCode.
  • Type-check throughput ≥ 5 MB/s (M3, §30).
  • Zero occurs-check false negatives on the typeck fuzz corpus (I5).
  • Maranget exhaustiveness: 100% of negative/non-exhaustive-* fixtures correctly flagged with a reconstructed missing-pattern example.
Fixtures
Fixture Purpose Expected
typeck/let-poly-id-001.ml let id x = x generalizes across two use sites both uses type-check at different instantiations
typeck/row-poly-record-002.ml { x: int, y: int | r } row unification I13 holds, no duplicate field

Pitfalls
  • Eager type pretty-printing walks unifier chains and silently triggers extra occurs-check work — render types lazily, only when a diagnostic actually needs one.
  • Forgetting the value restriction once mutable references exist (Phase 1+) unsoundly generalizes a mutable reference's type — Phase 0 is safe only because there is no mutation yet; flag this explicitly in BUILD_PLAN.md before references ship.
  • Expanding type aliases eagerly but rendering the alias name in diagnostics requires keeping the pre-expansion name alongside the expanded Ty — losing it produces confusing "expected int, found int"-style errors when the mismatch is actually between two differently named aliases of int.
  • Anonymous recursive record types must be rejected (occurs check fires) — nominal ADT recursion is fine, structural record recursion is not, and conflating the two reintroduces I5 violations.

Fixtures
Fixture Purpose Expected

Pitfalls
  • LLVM version drift: inkwell 0.4 ties to LLVM 17; pin it, and document the install in docs/runbooks/llvm-version-upgrade.md (Phase 0 pitfall, resurfaces here for real).

  • Treating LLVM textual IR as a stable serialization format — it is versioned per LLVM major release; textual IR is for diagnostics only, never a persisted artifact across LLVM upgrades.
  • musttail is not universally eligible (signatures must match exactly) — the lowering must verify eligibility, not assume it, or LLVM's own verifier rejects the module.

  • Binary size of the mandelbrot reference < 200 KB stripped (§4, §30 M9).
  • Linker invocation succeeds against cc, clang, and gcc in the CI matrix (three-way fallback tested, not assumed).
Fixtures
Fixture Purpose Expected
exec/gc-stress-001.ml Allocation-heavy loop forcing multiple collections correct output, no crash
exec/gc-root-scan-002.ml Deeply nested call stack with live references all live roots survive collection
exec/cross-compile-003.ml --target aarch64-apple-darwin from an x86_64 host binary runs correctly under emulation/CI runner

Pitfalls
  • Forgetting that cc is not always present — the driver must probe cc, clang, gcc in order and document the fallback; CI matrix-tests all three (8.4).
  • GC root-scanning via DWARF call-stack walking is fragile across debug-info format changes — pin the DWARF version (DWARF 5 spec) and test root-scan correctness under both optimized and unoptimized builds.
  • Bump-pointer allocation without an overflow check corrupts adjacent memory silently — the header's size field must be validated against the remaining region before every allocation (I11).
  • Cross-compiling the runtime but not the user program's calling convention (SysV vs AAPCS64 mismatch) — the target triple must consistently propagate through mlc-llvm, mlc-link, and mlc-rt's build.
