32. Mental Models & First Principles

MM1 — A type is a proof obligation, not a label. HM inference treats every expression's type as something that must be derived, not merely annotated. Predicts: a unification failure signals a missing lemma (an unhandled case), not a cosmetic mismatch. Bug class without it: silently accepting ill-typed programs via loose Any-style casting, defeating the entire point of static typing. Applies in Phase 4 — Type Checker; §8 Domain Model.

MM2 — SSA is functional programming for imperative code. Block parameters are lambda parameters; dominance is lexical scoping restated over a control-flow graph (Cytron et al. 1991). Predicts: any dataflow analysis that respects dominance is as compositional as a functional-language analysis. Bug class without it: treating IR values as mutable variables and reintroducing aliasing bugs the SSA form exists to eliminate. Applies in Phase 5 — IR Construction; I6, I7.

MM3 — The parser's job is choosing synchronization points, not maximizing grammar coverage. Recovery quality, not grammar completeness, is what makes a parser pleasant to use under real (broken) input. Predicts: the recovery state table (§8) determines diagnostic quality more than the grammar's EBNF does. Bug class without it: a parser that accepts every valid program but produces useless diagnostics on every invalid one. Applies in Phase 2 — Parser.

MM4 — Levels are a poor-man's region inference for generalization. A unification variable's level (Pottier 2014) tracks "how deep in the let-nesting was this introduced," the same question region inference asks about allocation scope. Predicts: level-adjustment bugs look exactly like region-escape bugs. Bug class without it: reverting to the classical O(n²) generalization walk, or generalizing a variable that should stay monomorphic. Applies in Phase 4 — Type Checker; ADR-07.

MM5 — An IR verifier is a compiler's type system for its own compiler. mlc-ir-verify plays the same role for Program values that mlc-typeck plays for user programs — it rejects ill-formed values before they can cause damage downstream. Predicts: verifier bugs are exactly as dangerous as type-checker soundness bugs (both let a category error slip through). Bug class without it: LLVM segfaults replace actionable diagnostics (P6, I6, I7). Applies in Phase 5 — IR Construction; Phase 6 — Optimizer Scaffold.

MM6 — Closures are data with a code pointer, not magic. A closure is { code_ptr, env }, nothing more — the same shape a hand-written vtable-plus-context C idiom would use. Predicts: closure bugs are almost always environment-layout bugs, not "closure semantics" bugs. Bug class without it: treating closures as an opaque primitive and missing an environment-aliasing or capture-order defect. Applies in Phase 5 — IR Construction; Phase 7 — LLVM Code Generation.

MM7 — Register allocation is graph coloring, and spilling is admitting defeat gracefully. Even though Phase 0 delegates allocation to LLVM, the underlying model (Chaitin/Briggs) is that live-range interference is a graph-coloring problem, and a spill is simply "this graph needs more than k colors here." Predicts: allocation quality problems are interference-graph density problems, not "the allocator is bad." Bug class without it: not recognizing why a native x86_64 backend (Deferred Features Register) is a multi-month project, not a weekend one. Applies in §36 Alternative Architectures; Deferred Features Register.

MM8 — A diagnostic is a proof of what a human needs to know, span-first. The primary span is the claim; the message is the argument; the hint is the suggested next step (P5). Predicts: a diagnostic without an actionable primary span is a diagnostic that will be misread regardless of how well the message is worded. Bug class without it: prose-quality diagnostics that are technically correct but impossible to act on because the span points at the wrong token. Applies in Phase 9 — Diagnostics Polish; I9.

Glossary (§38) · 43 terms · site-wide glossary

ADR
Architecture Decision Record; a locked, numbered decision with rejected alternatives (§9).
ADT
Algebraic Data Type; a nominal type with named constructors and optional payloads (§8).
ANF
A-Normal Form; an IR discipline where every subexpression is named before use (Flanagan et al. 1993).
Arena
a bump-allocated memory region (bumpalo) backing the AST, types, and IR (P3).
Block parameter
an SSA value bound at a basic block's entry, replacing phi nodes (ADR-09).
Bump allocator
an allocator that advances a pointer linearly, used both at compile time (arenas) and at runtime (mlc-rt, GC fast path).
Closure conversion
the Phase 5 transformation turning a capturing lambda into a {code_ptr, env} pair (MM6).
Conformance fixture
a named input/expected-output pair in conformance/programs/, the executable specification (P11).
CPS
Continuation-Passing Style; an IR/evaluation discipline where control flow is reified as explicit continuations (rejected IR shape, §36).
DefId
a dense u32 identifying a resolved binder (§11, I2).
Determinism
bit-for-bit reproducible output for identical (input, version, triple) (I8, P8).
Diagnostic
the structured error/warning/note value every phase boundary produces instead of panicking (§11, P5).
DiagCode
the stable numeric code (E0001–E0999) identifying a diagnostic's meaning (I9).
Dominance / dominator
block A dominates block B if every path to B passes through A; the basis of SSA well-formedness (Cytron et al. 1991).
DCE
Dead-Code Elimination; removes instructions whose result is unused and side-effect-free (Phase 6).
DWARF
the debug-information format mlc-llvm emits at function granularity in Phase 0 (§5 RFCs).
Escape analysis
determines whether a heap allocation's lifetime is provably stack-boundable (deferred pass, §37).
Exhaustiveness checking
verifying a match covers every constructor, via Maranget's decision-tree algorithm (I13).
FileId
a dense identifier for a source file within a FileMap (§11).
Fixpoint (pass manager)
running a set of passes repeatedly until no further change occurs, bounded by max_iters (Phase 6).
Generalization
promoting a monomorphic inferred type to a polymorphic type scheme at a let (§8, ADR-07).
HM (Hindley-Milner)
the type-inference discipline underlying mlc's type checker (Damas & Milner 1982).
ICE
Internal Compiler Error; an unrecoverable failure caught at the mlc-driver panic boundary (T8).
IR (Intermediate Representation)
the typed ANF+SSA Program value between the type checker and the backend (§11).
Level (type checker)
the let-nesting depth at which a unification variable was introduced, used for efficient generalization (ADR-07, MM4).
LLVM
the compiler-infrastructure project providing mlc's primary backend via inkwell (ADR-10).
Maranget's algorithm
the decision-tree compilation strategy for pattern matches (Maranget 2008, ADR-08).
Monomorphization
specializing a generic function per concrete instantiation, used here for row-polymorphic records ("specialization by use," Phase 5).
musttail
the LLVM call attribute enforcing true tail-call semantics, used for TailCall terminators (Phase 7).
NodeId
a dense u32 identifying an AST node (§11, P2, I1).
Occurs check
the unification-time test preventing infinite types (I5).
PassManager
the Phase 6 component sequencing pre/fixpoint/post optimizer passes.
Pratt parsing
precedence-climbing expression parsing keyed on operator binding power (Phase 2).
Recovery (parser)
synchronizing past a syntax error to continue parsing the rest of the file (P4, §8 state table).
Row polymorphism
a record-typing discipline permitting "this record has at least these fields" (Leijen 2005, I13).
Span
a byte-precise (FileId, lo, hi) triple identifying a source location (§11).
SSA (Static Single Assignment)
the IR discipline where every value is assigned exactly once (Cytron et al. 1991).
TailCall
an IR terminator marking a self- or mutually-recursive call in tail position (Phase 5).
Ty::Err
the poison-type sentinel that lets type checking continue past an error (P4, I5).
TyVar
a dense identifier for a unification (type) variable (§11).
Unification
the algorithm merging two types (or type variables) into a consistent solution (Phase 4).
Value restriction
the ML rule that only syntactic values generalize at a let, preserving soundness once mutation exists (Phase 4, subsection 4.6).
Verifier (mlc-ir-verify)
the component rejecting ill-formed IR before any optimizer or backend runs (P6, I6, I7, MM5).
