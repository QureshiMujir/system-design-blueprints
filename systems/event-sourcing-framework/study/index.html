Mental Models & First Principles

Compressed expert models (MM1–MM9). Each: the insight, what it predicts, the bug class written without it, and where this blueprint applies it.

  1. MM1 — The log is the database; every table is a cache. Current state = fold(apply, events); storing state is memoization, never truth. Predicts: any read model is reconstructible; DR = restore log + rebuild; "fixing data" = appending a compensating event. Bug class without it: dual-writes (store + log updated non-atomically) → undetectable drift. Applied: principle 6.2, §3.7, Phase 6 §17.2, Compatibility & Versioning (rebuild guarantees).
  2. MM2 — Durability is a watermark, not a boolean. write() returning is meaningless; there are two offsets (appended, durable) and only the second survives power loss. Predicts: consumers shown anything above the watermark act on data a crash can erase; recovery truncates the gap. Bug class: ghost deliveries — read models referencing events that no longer exist after restart. Applied: INV-12, Phase 1 §12.2, §18.8.
  3. MM3 — Exactly-once is an effect property, not a delivery property. Delivery is at-least-once everywhere (seam, crash, restart); only idempotent apply + atomic checkpoint makes effects exactly-once. Predicts: redelivery counters > 0 are healthy; a double effect always means broken idempotency, never bad luck. Bug class: balance += x without an offset guard → double counting (FM-6). Applied: principles 6.4/6.9, INV-4, Phase 6 §17.2.
  4. MM4 — An aggregate is a fold; a command is a pure decision. handle proposes events, apply folds them; neither touches clock/RNG/IO. Predicts: byte-identical replays, given-when-then testing, forensic reconstruction of any historical state. Bug class: impurity in apply → divergent rebuilds caught only by differential replay (INV-9). Applied: §11.6, principle 6.3, Phase 4 §15.2.
  5. MM5 — Schema evolution is reinterpretation, never rewriting. Bytes freeze at append; meaning evolves through pure upcaster chains at read. Predicts: readers-before-producers deploy order; rollback blocked across an introducing version. Bug class: in-place "migration" that corrupts replay determinism and every backup (FM-4/FM-10). Applied: principle 6.5, INV-8, Phase 8 §19.2.
  6. MM6 — Ordering is bought per partition; global order is a coordination bill. Predicts: linear writer scaling at P partitions; cross-partition workflows must tolerate causal-at-best order. Bug class: cross-stream sequence assumptions that silently break at reshard. Applied: principle 6.11, §3.4, §20.8, Scalability Analysis.
  7. MM7 — Backpressure is topology: a slow consumer may slow only itself. Predicts: bounded per-consumer queues; writer throughput invariant to fan-out health (M10). Bug class: synchronous fan-out or unbounded buffers → writer collapse or OOM. Applied: principle 6.6, Phase 7 §18.2, FM-1.
  8. MM8 — Contention is a modeling smell, not a locking problem. A hot stream's VersionConflict storm indicts the aggregate boundary, not the lock. Predicts: the conflict-rate SLI doubles as a domain-model health metric. Bug class: raising retry caps instead of splitting the aggregate → livelock (FM-3). Applied: principle 6.8, INV-6, Phase 2 §13.10.
  9. MM9 — Crash-only: recovery is the only startup path. If kill -9 is safe, every shutdown is. Predicts: rollback = stop + redeploy + recover; no correctness dependency on graceful drains. Bug class: state persisted only on clean shutdown → loss at power cut. Applied: principle 6.7, Phase 1 §12.2, Operational Readiness (rollback).

5. Required Reading

5.1 Books

  • B1 — Designing Data-Intensive Applications, Kleppmann. Ch. 3, 5, 7, 11. Foundational log-structured storage, ordering, exactly-once. Applied: §3.3–§3.4 (log + partitioning); Ch. 7 → Phase 2 §13.2 (expected-version CAS as optimistic validation); Ch. 11 → Phase 6 §17.2 (exactly-once effect).
  • B2 — Implementing Domain-Driven Design, Vernon. Ch. 4, 6, 8 + ES appendix. Aggregate boundaries, invariants, domain-event modeling. Applied: §8.4 (stream↔aggregate identity), Phase 4 §15.2 (given-when-then, boundary discipline), §13.10 (FM-3 remediation = boundary redesign).
  • B3 — Patterns of Enterprise Application Architecture, Fowler. Event Sourcing, CQRS, Unit of Work. Canonical pattern definitions. Applied: §2.1 (pattern framing), principle 6.13, Phase 10 §21.2 (query facade).
  • B4 — Database Internals, Petrov. Ch. 2–6. Segment files, recovery, durability (WAL, fsync). Applied: Phase 1 §12.2 (segment layout, fsync policy, recovery scan), §8.3 (record framing).
  • B5 — Streaming Systems, Akidau et al. Ch. 1–3. Checkpoint, watermark, idempotency — exactly-once semantics + state. Applied: Phase 6 §17.2 (checkpoint atomicity), Phase 7 §18.2 (durable watermark = the system's low-watermark analogue), principle 6.4.
  • B6 — Enterprise Integration Patterns, Hohpe. Process Manager, Idempotent Receiver — saga design. Applied: Phase 9 §20.2 (process-manager runtime), Phase 2 §13.2 (Idempotent Receiver → INV-11 dedup).

5.2 Papers

  • P1 — ARIES, Mohan et al., 1992, ACM TODS. WAL recovery (redo/undo), LSN. Applied: Phase 1 §12.2 (recovery scan-truncate is the redo-pass analogue; offset ≈ LSN), INV-3 density check.
  • P2 — CALM, Hellerstein & Alvaro, 2020, CACM. Monotonicity ⇒ coordination-free consistency. Applied: Phase 6 §17.2 (per-offset idempotent apply is monotone ⇒ projections need no coordination), principle 6.4.
  • P3 — Bayou, Terry et al., 1995, SOSP. Eventual consistency, anti-entropy, write log. Applied: Deferred Features Register (consensus-replication row — the replicated-log road), §20.8 (causal-only cross-partition tolerance).
  • P4 — Kafka, Kreps et al., 2011, NetDB. Partitioned, replicated, ordered log. Applied: §3.4 (partitioning), Phase 7 §18.2 (consumer offset ≈ checkpoint), ADR-30 (fixed partition count).
  • P5 — Calvin, Thomson et al., 2012, SIGMOD. Deterministic transaction ordering via log. Applied: principle 6.3 + INV-9 (determinism from agreed log order), Phase 4 §15.2 (replay fold).
  • P6 — LSM-Tree, O'Neil et al., 1996, Acta Inf. Log-structured merge storage. Applied: Phase 1 §12.2 (segment roll lineage), Scalability Analysis (storage-growth levers).
  • P7 — LFS, Rosenblum & Ousterhout, 1992, ACM TOCS. Log-structured filesystem. Applied: Phase 1 §12.2 (append-only segment layout), Phase 5 §16.2 (retain-K GC ≈ segment cleaning).
  • P8 — Time, Clocks…, Lamport, 1978, CACM. Happens-before, logical ordering. Applied: principle 6.11 (per-partition order), §8.2 (causation/correlation ids encode happens-before), §20.8.
  • P9 — Sagas, Garcia-Molina & Salem, 1987, SIGMOD. Long-lived transactions as compensatable sub-transaction sequences. Applied: Phase 9 §20.2 (compensation in reverse causal order), §8.8 (saga state machine).

Glossary · 30 terms · site-wide glossary

Event
immutable fact record; once appended + synced, never mutated/deleted (INV-1); in an EventEnvelope.
Stream
ordered events for one aggregate, StreamId = "<category>-<instance>"; unit of optimistic concurrency.
Append-only log
system of record (es-log): O_APPEND segment files, never edited in place; source of all derived state (principle 6.2).
Segment
monotonically numbered log file; active appended, sealed immutable; rolled at size/count cap (§12.2).
Aggregate
consistency boundary; state = pure fold (apply) over its stream; enforces invariants in handle (§11.6).
Command
intent to change an aggregate; routed by target_stream; produces events via handle; may carry idempotency_key (§11.7).
Projection / read model
queryable view built by idempotent apply to a store w/ checkpoint; rebuildable from 0 (§11.10).
Snapshot
persisted aggregate state at (stream,version); bounds replay tail; never authoritative (principle 6.10, INV-5).
Upcaster
pure total vN→vN+1 transform applied lazily on read to current shape (§11.13, INV-8).
Saga / process manager
stateful event-sourced consumer: reacts to events, emits commands, schedules timers, runs compensation (§11.12).
CQRS
Command Query Responsibility Segregation: write side (aggregates + log) + read side (projections) diverge intentionally (principle 6.13).
Optimistic concurrency
append supplies expected_version; mismatch rejected as VersionConflict, not merged (INV-6).
Expected version
ExpectedVersion (Any/NoStream/StreamExists/Exact(v)) asserted at append (§11.4).
Idempotency
re-processing/redelivery causes no extra effect; offset/id-keyed handlers (principle 6.4).
Idempotency key
optional command id letting store dedup retries + return original AppendResult (§13.2, INV-11).
Checkpoint
consumer's (name, partition, offset); advanced atomically w/ its effect; monotonic (INV-4/10).
Catch-up subscription
reads historical events (offset→head) then hands to live tailing w/ no gap (§18.2).
Dispatcher
per-partition single reader delivering events in offset order w/ bounded backpressure (§3.8).
Backpressure
bounded per-consumer buffers; slow consumer slows only itself (principle 6.6).
Global offset
strictly-increasing dense per-partition position per record; basis of ordering + checkpoints (INV-3). Stream version: 0-based gapless per-stream sequence (INV-2).
Partition
independent ordered log + single writer; hash(stream_id) mod P; unit of scaling + total order (§3.4).
Replay
reconstruct state by re-applying events from a start point; deterministic given pure apply/handle (principle 6.3, INV-9). Rebuild = drop read model + checkpoint, replay from 0 to regenerate byte-identically (INV-4).
Crypto-shredding
GDPR erasure: destroy per-subject key ⇒ PII ciphertext unreadable forever, no record deletion (TM-3).
Durable offset
highest fsync-durable offset; consumers see only ≤ durable_offset (distinct from appended_offset) (INV-12).
Exactly-once (effect)
effect applied once via idempotent apply + atomic checkpointing over at-least-once delivery (§3.8; principle 6.9, INV-4).
Fsync policy
operator knob (PerBatch/GroupCommit/OsFlush) trading durability/RPO vs throughput (§12.2, §4).
Poison event
event no codec/upcaster can decode; quarantined so it pauses only its consumer (principle 6.12, FM-9).
Correlation id / causation id
metadata linking a workflow's events (correlation_id) + an event's cause (causation_id) (§8.2).
CRC-32C
Castagnoli per-record checksum, verified on every read for torn-write/bit-rot detection (ADR-27, INV-7).
AppendResult
successful-append outcome: stream_version + dense (first,last) offsets + partition (§11.5).
