3. Architectural Overview

3.1 Canonical Architecture Diagram

3.2 Subsystem Descriptions

csearch-ingest (index path, entry). Walks a repo tree recursively; respects .gitignore / .ignore rules; detects language by extension + shebang + content sniff; skips binaries (null-byte scan), minified files (line-length heuristic), and files exceeding the size ceiling. Computes sha256 per file as content identity (I5). Emits a stream of (path, repo, lang, bytes, sha256) records to csearch-trigram and csearch-index. Trust boundary: untrusted filesystem content; enforces size + binary filters before any indexing work. No persistence of its own.

csearch-trigram (index path, trigram extraction). Receives raw file bytes; slides a 3-byte window one byte at a time (overlapping); deduplicates the per-document trigram set; optionally emits case-folded trigrams for case-insensitive mode; estimates trigram frequencies for cost planning. Output: Vec<Trigram> per document. Stateless; pure transformation. No I/O.

csearch-symbol (index path, symbol extraction). Lightweight per-language definition extraction using ctags-style regex heuristics (not full AST parse). Emits SymbolEntry { name, kind, doc_ref, line } records. Builds a parallel posting index keyed by symbol name (trigrams of the name for prefix/substring lookup, plus exact-match entries). Output fed into csearch-index alongside content trigrams.

csearch-index (index path, accumulation + shard writer). Accumulates (Trigram, DocId) pairs in memory; spills to temporary segments when memory ceiling is hit; sorts and merges segments; encodes posting lists as ascending delta+varint byte sequences. Captures DocMeta per document. Writes the final immutable shard file: ShardHeader, sorted trigram table (binary-searchable), concatenated posting list blobs, doc-meta table, trailing CRC. Assigns deterministic DocIds. Produces a build manifest. Persistence: write-once shard file.

SHARD (on-disk, immutable, mmap-able). Layout: { magic(4) | version(2) | ShardHeader(fixed) | trigram_table(sorted array of (Trigram, offset, len)) | posting_lists(blob) | doc_meta_table | crc32(4) }. Read via mmap; CRC verified on open. Never mutated after seal (I3). DocIds are local to the shard; globally unique as (ShardId, DocId).

csearch-shard (search path, mmap reader). Opens the shard file with mmap; verifies CRC; wraps a zero-copy PostingReader (seeks into the trigram table, returns a PostingList<'a> borrowing the mapped bytes). Decodes varint+delta on iteration. Provides doc_meta(DocId) -> DocMeta lookup. Concurrency boundary: multiple readers share the same mmap; writer creates a new file (never mutates). The mmap lifetime is tied to the ShardHandle.

csearch-incremental (index path, change detection + compaction). On re-index trigger: compares per-file sha256 + mtime against the previous manifest; rebuilds only repos with changed files into new shards; marks superseded shards in the manifest (I9). Runs LSM-style compaction: merges small shards into larger ones when shard count exceeds a threshold, producing a merged shard with filtered-out deleted docs. Atomically swaps the active manifest file (I7). Does not mutate existing shard bytes (I3).

csearch-query (search path, query parsing). Parses the user query string per the grammar: bare literal, /regex/, and filter fields (file:RE, lang:go, repo:RE, case:yes, sym:Name). Produces a QueryAst + Vec<Filter>. Reports structured errors for malformed input. Stateless; no I/O.

csearch-regex (search path, regex compiler + matcher). Parses a regex string into a Hir (high-level IR) using the regex-syntax crate. Compiles to a Thompson NFA. Executes via PikeVm (thread-list, leftmost-first, submatch capture). Guarantees O(len(text) × |NFA|) runtime — no backtracking (I4). Used by csearch-search to verify candidates and extract MatchSpans.

csearch-trigquery (search path, lowering). Walks the regex Hir to extract required substrings and alternations; converts each substring to an AND of its constituent trigrams; joins alternations with OR; emits a TrigramQuery tree. Soundness obligation (I1, P2): every document matching the regex satisfies the query. . / .* / short patterns → TrigramQuery::All (full-scan fallback). Tested by a fuzz harness in Phase 14.

csearch-search (search path, executor). Given a QueryAst + Vec<Filter>: lowers to a TrigramQuery via csearch-trigquery; fans out across all active shards (concurrent, per-query deadline P6); per shard: intersects/unions posting lists with galloping merge → candidate DocId set; applies Filter predicates on DocMeta (lang, repo, file-path regex); dispatches PikeVm verification per candidate; collects MatchSpans (line/col); calls csearch-rank; applies result cap; short-circuits. Emits per-query observability counters (P10).

csearch-rank (search path, scorer). Computes RankScore(f32) = match density (matches per line-count) + path importance (shallow path, non-test, non-vendor prefix) + symbol definition bonus + repo weight. Selects top-k via bounded max-heap. Tie-breaks deterministic by (path, line) (I10).

csearch-server (serving layer). HTTP/JSON API on configurable port. Endpoints: POST /search (query + filters + paging), GET /health, GET /metrics. Streams results as NDJSON. Maintains a ShardRegistry hot-reloaded on manifest swap (I7). Per-request deadline enforced. Concurrent requests limited by semaphore. Metrics: candidate_count, verified_count, shards_touched, stage_latency_ms.

csearch-cli (operator interface). Subcommands: index (build or re-index repos), search (interactive / scripted search), merge (explicit shard compaction), stat (shard statistics, trigram table sizes), doctor (CRC verification, manifest consistency check). Thin wrapper over the library crates.

8. Domain Model

8.1 Core Entity Taxonomy

Entity Type Cardinality Owns
Repo Root aggregate 1..N repos per index N docs
Doc Content unit 1..M per repo trigrams, symbols, metas
Trigram Index key ≤16,777,216 distinct posting list per shard
Posting DocId in a trigram's list O(docs × avg_trigrams) encoded bytes in shard
Shard Immutable on-disk unit grows via compaction trigram table + postings + doc-meta
Manifest Atomic shard registry exactly one active ordered shard set + deletion markers
SymbolEntry Named definition 1..K per doc name, kind, line
QueryAst Parsed search intent 1 per query literals, regex Hir, filters
TrigramQuery Boolean over trigrams derived from QueryAst AND/OR/Trigram/All/Any
MatchSpan Verified match location 0..R per candidate line, col, len, line_text_ref
SearchResult Final ranked hit top-k per query DocMeta + spans + RankScore

8.2 Trigram Packing — Bijection and Representation

Pack:  T = (b0 << 16) | (b1 << 8) | b2    where b0,b1,b2 ∈ [0,255]
Unpack: b0 = (T >> 16) & 0xFF
        b1 = (T >>  8) & 0xFF
        b2 =  T        & 0xFF
Domain: T ∈ [0, 16_777_215]  (24-bit unsigned)
  • I8: pack/unpack is bijective; no two 3-byte sequences map to same u32.
  • Trigram(u32) stores raw bytes, never code-points; indexing is byte-oriented.
  • Case-fold variant: for case-insensitive mode, emit both original and to_ascii_lowercase trigrams; no separate fold field; soundness preserved because superset generated.
  • Boundary handling: file shorter than 3 bytes → zero trigrams extracted; file of exactly 3 bytes → exactly one trigram.

8.3 Posting List: Storage Layout and Encoding

On-disk layout (per trigram, within shard):
  [varint: n_postings]
  [varint: first DocId]
  [varint: delta_1]  (DocId[1] - DocId[0])
  [varint: delta_2]  (DocId[2] - DocId[1])
  ...
  • Lists are strictly ascending (I2); delta is always ≥ 1.
  • Varint encoding: little-endian base-128 (continuation bit = bit 7).
  • PostingReader iterates by decoding running sum; no random access within list.
  • PostingWriter accumulates sorted DocIds, encodes on flush.
  • Galloping intersection (Phase 8): skip-pointer advances when gap between iterators is large; O(n log(max/min)) vs O(n) for dense lists.

Worked Example — 4-doc posting list for trigram "int":

DocIds: [3, 7, 12, 20]
Deltas: [3, 4, 5, 8]
Varint bytes: 04 03 04 05 08   (first byte = count=4)

Failure path — corrupt varint (continuation bit set on final byte):

  • Decoder returns Err(PostingDecodeError::UnterminatedVarint).
  • Shard reader closes the list; candidate doc is skipped (safe: may miss a match from corrupt data, flagged via metrics).
  • CRC mismatch on shard open → Err(ShardError::CrcMismatch) → shard excluded from fan-out; error logged.

8.4 Shard On-Disk Layout

Byte offset  Field
0            magic: [u8;8] = b"CSEARCH1"
8            version: u32
12           n_docs: u32
16           n_trigrams: u32
20           trigram_table_off: u64   -- absolute offset to trigram index
28           doc_table_off: u64       -- absolute offset to doc-meta table
36           postings_off: u64        -- absolute offset to posting-list blob
44           crc32: u32               -- CRC of bytes [0..44)
48           [trigram table]          -- sorted array of (Trigram: u24, list_offset: u40) pairs, 8 bytes each
             [posting-list blob]      -- concatenated encoded lists
             [doc-meta table]         -- length-prefixed CBOR records, one per DocId (ascending)
  • Trigram table: binary-searched by Trigram value; O(log n_trigrams) lookup.
  • Doc-meta table offset indexed by DocId (variable-length → an auxiliary offset array at doc_table_off).
  • Shard is written once; sealed with CRC; never mutated (I3).
  • mmap opens read-only; PostingList<'a> holds &'a [u8] slice into the mapped region (P5 zero-copy).

8.5 Manifest Format

{
  "version": 1,
  "shards": [
    { "shard_id": 1, "path": "shard-0001.csi", "repo_ids": [1,2], "generation": 3 },
    ...
  ],
  "deleted_docs": [
    { "shard_id": 1, "doc_id": 42 }
  ],
  "created_at": "<unix-ms>"
}
  • Written atomically: new file → fsync → rename over old (I7).
  • deleted_docs list filters superseded docs at query time until compaction (I9).
  • generation counter increments on each rebuild or merge; monotonically increasing.
  • Hot-reload in csearch-server: inotify/kqueue watch on manifest path; swap active shard registry under a read-write lock.

8.6 QueryAst and Filter Grammar (EBNF)

query       ::= clause (WS clause)*
clause      ::= filter_expr | term
filter_expr ::= field ':' value
field       ::= 'file' | 'lang' | 'repo' | 'case' | 'sym'
value       ::= bare_word | quoted_string | '/' regex_body '/'
term        ::= quoted_string | bare_word | '/' regex_body '/'
bare_word   ::= [^ \t\n:/]+
quoted_string ::= '"' ([^"\\] | '\\' .)* '"'
regex_body  ::= ([^/\\] | '\\' .)*
  • Implicit AND across space-separated clauses.
  • case:yes / case:no toggles ASCII case-folding globally for the query.
  • sym:Name routes to symbol posting index (Phase 10), bypasses trigram scan.
  • file: and lang: applied as post-candidate DocMeta filters (no trigram overhead).
  • Malformed query (unclosed /, unrecognized field) → QueryParseError with byte offset; HTTP 400.

8.7 TrigramQuery Lowering State Machine

Regex Hir node         TrigramQuery produced
-----------------      --------------------------------
Literal(s), |s|≥3      And(trigrams(s))        -- all overlapping trigrams required
Literal(s), |s|<3      All                     -- no constraint extractable; sound (P2)
Concat(a, b)           And(lower(a), lower(b))
Alternation(a,b,..)    Or(lower(a), lower(b), ..)
Repetition(min=0,..)   All                     -- may match zero chars; no guarantee
Repetition(min≥1, e)   lower(e)
Dot / AnyByte          All
Class(ranges)          All  (conservative; could enumerate if small)
  • And(All, x) simplifies to x; Or(All, x) simplifies to All.
  • And([]) = All; Or([]) = Any (vacuously false — no doc matches).
  • Soundness obligation (I1): lower(R) must be satisfied by every doc D where R matches D. Verified by fuzz corpus (Phase 14).

Worked Example — literal "struct Foo":

trigrams: "str","tru","ruc","uct"," Fo","Foo"
TrigramQuery: And(["str","tru","ruc","uct"," Fo","Foo"])  (encoded as Trigram(u32) values)

Worked Example — regex /err|warn/:

lower("err") = And(["err"])
lower("warn") = And(["war","arn"])
TrigramQuery: Or(And(["err"]), And(["war","arn"]))

Edge case — regex /.*/ : lowers to All; every shard is scanned (full-scan path); result cap + deadline apply (P6).

Edge case — regex /a{0,}/: min=0 → All; same as .*.

Failure path — trigram query returns empty candidate set: valid result; zero SearchResults; not an error.

8.8 Search Execution Sequence

Client               csearch-server          csearch-search          csearch-shard (×N)
  |--POST /search-------->|                       |                         |
  |                       |--parse QueryAst------->|                         |
  |                       |                       |--lower TrigramQuery----->|
  |                       |                       |<--PostingList iterators--|
  |                       |                       |--gallop intersect------->|
  |                       |                       |<--candidate DocIds-------|
  |                       |                       |--apply DocMeta filters-->|
  |                       |                       |--verify with PikeVm----->|
  |                       |                       |<--MatchSpans-------------|
  |                       |                       |--rank + top-k----------->|
  |                       |<--SearchResults--------|                         |
  |<--JSON response--------|                       |                         |
  • Fan-out across shards is concurrent (tokio tasks per shard); first shard to fill result cap cancels others (P6).
  • Deadline carried as Instant; each stage checks before proceeding.
  • Metrics emitted per query: shard_count, candidate_count, verified_count, false_positive_ratio, latency_ms per stage (P10).

8.9 Thompson NFA / Pike VM Execution Model

NFA state set: S ⊆ {0..num_states}
At each byte b of input text:
  next(S, b) = ε-closure( { t | ∃s∈S, (s,b)→t ∈ transitions } )
  S ← next(S, b)
Match: accept_state ∈ S after processing input prefix
Submatch capture: Pike VM threads carry capture vectors; priority = leftmost-longest
  • Compile once per query; reuse NFA across all candidate docs (P3).
  • NFA size bounded by regex AST node count; no exponential blowup.
  • I4: O(len(text) × |NFA|) per doc; |NFA| fixed at compile time.
  • Anchors: ^ = start from position 0 only; $ = accept only at newline/EOF.
  • Line/col extraction: scan backward from match start offset to prior newline.

8.10 Incremental Indexing State Transitions

State: {CLEAN, DIRTY, BUILDING, MERGING}

CLEAN  --file_changed(repo)--> DIRTY
DIRTY  --trigger_build-------> BUILDING
BUILDING --shard_written-----> CLEAN  (manifest updated; old shard superseded)
CLEAN  --merge_threshold met-> MERGING
MERGING --compacted_shard-----> CLEAN  (merged shard replaces N old shards; manifest atomic swap)
  • Dirty detection: compare file mtime + sha256 against DocMeta.sha256 in existing shard.
  • Superseded shard: added to manifest.deleted_shards; excluded from search; GC after merge.
  • Merge trigger: shard count > threshold (default 16); merge smallest N shards into one.
  • BUILDING state is per-repo; multiple repos can build concurrently; manifest updates are serialized.

8.11 DocMeta Record Layout (CBOR)

{
  doc_id:     u32,
  path:       text,       -- repo-relative UTF-8 path
  repo_id:    u32,
  lang:       text,       -- "rust", "go", "python", etc. or "unknown"
  size:       u64,        -- bytes
  sha256:     bytes[32],
  line_count: u32,
  mtime:      u64         -- unix seconds
}
  • Stored in shard doc-meta table in DocId-ascending order.
  • lang field populated by csearch-ingest (extension → shebang → content sniff priority order).
  • Binary files: lang = "binary"; never indexed for trigrams; not returned for text queries.

8.12 Symbol Index Model

SymbolEntry:
  name:    text          -- qualified or bare identifier
  kind:    Def|Class|Func|Struct|Enum|Const|Macro|..
  doc_id:  (ShardId, DocId)
  line:    u32
  col:     u16
  • Symbol posting index mirrors trigram posting index: name → sorted (ShardId, DocId) list.
  • Key: 4-byte FNV hash of lowercased name (collision tolerated; false positives filtered by exact match at verify step).
  • sym:Foo query: lookup hash(Foo) → candidate docs → verify symbol name at returned line.
  • Rank bonus: SymbolEntry.kind ∈ {Def, Class, Func} → +0.15 RankScore addend.

8.13 Ranking Model

RankScore = w_density  × match_density(doc, spans)
           + w_path    × path_importance(doc_meta.path)
           + w_symbol  × symbol_bonus(spans)
           + w_repo    × repo_weight(doc_meta.repo_id)
Factor Computation Default weight
match_density spans count / line_count, capped at 1.0 0.40
path_importance 1/(depth+1) × non_test × non_vendor 0.30
symbol_bonus 1 if any span on a SymbolEntry line else 0 0.20
repo_weight configurable per-repo float [0,1] 0.10
  • Top-k via bounded max-heap (k = result_cap, default 20).
  • Tie-break: (path lexicographic ASC, line ASC) — deterministic (I10).
  • BM25 not used for code search (token boundaries ill-defined in code); match_density replaces IDF.

8.14 Edge Cases and Failure Catalog

Scenario System Behavior Invariant
File < 3 bytes Zero trigrams; doc stored but never a candidate I2
All-binary repo No docs ingested; zero-doc shard not written —
Trigram → empty posting list Candidate set = ∅; zero results; not an error I1
Shard CRC mismatch on open Shard excluded; error metric incremented I3
Regex catastrophic backtrack attempt Rejected by Thompson NFA; linear time guaranteed I4
Regex .* (no trigram constraint) TrigramQuery = All; full scan; deadline enforced P6
Duplicate sha256 across repos DocMeta stored per repo; no dedup at index level (distinct paths) I5
Manifest swap mid-query Query sees either old or new manifest; never partial (atomic rename) I7
sym: on doc with no symbols Symbol index empty; zero results; no error —
Very long line (> 64KB) line_text_ref truncated to 512 bytes for response; full match coords preserved I6
Deleted doc queried before compaction Filtered via manifest.deleted_docs at fan-out start I9
Result cap reached mid-fan-out Remaining shard tasks cancelled; partial result set returned P6
