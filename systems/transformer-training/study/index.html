30. Mental Models & First Principles

  1. MM1 — The loss is a compass, not a target. A decreasing training loss only confirms the gradient direction is being followed; it says nothing about generalization. Predicts: train/eval loss divergence signals overfitting long before eval perplexity plateaus. Bug class without it: chasing train loss into an overfit model that eval-fails silently. Applies at §19 (P6, eval-is-observational) and §29.
  2. MM2 — Gradient accumulation is arithmetic, not scheduling. Accumulation must reproduce the exact math of a larger batch, not merely "spread work over more steps." Predicts: any un-scaled accumulation diverges by a predictable factor (the accumulation count). Bug class without it: silent LR-scale bugs that look like instability. Applies at §17, I3.
  3. MM3 — The optimizer's memory is a second copy of the model. AdamW's fp32 master weights + two fp32 moments roughly triple the memory footprint of the parameters alone, independent of activation memory. Predicts VRAM budgets that surprise engineers who only counted parameter bytes. Bug class without it: OOM diagnosed as "the model is too big" when it's the optimizer state that doesn't fit. Applies at §4, §11.4, §32.
  4. MM4 — Determinism is a chain, not a single flag. Bit-exact resume requires simultaneously correct shuffle-seeding, RNG capture (5 streams), config hashing, and code-version pinning — any single weak link breaks the whole chain. Predicts partial-determinism efforts (e.g. seeding torch but not numpy) fail silently, only visible on resume. Bug class without it: "works on my resume" flukes that do not reproduce. Applies at §18, I1, I12.
  5. MM5 — Precision and dynamic range are different axes. bf16 trades mantissa bits for fp32-equivalent exponent range; fp16 trades exponent range for mantissa bits. Predicts which failure mode each dtype exhibits under stress (bf16: precision loss in small updates; fp16: gradient underflow to zero). Bug class without it: misdiagnosing an fp16 underflow as a bf16-style precision issue and reaching for the wrong fix. Applies at §16, ADR-09.
  6. MM6 — Checkpointing trades time for space, asymmetrically across depth. Recomputing activations during backward has a fixed per-block cost; the O(√L) checkpoint-count optimum balances this against O(L) activation storage. Predicts diminishing returns from checkpointing more blocks than the optimum. Bug class without it: checkpointing every block and eating ~2× compute for no additional memory benefit past the sweet spot. Applies at §17, Chen et al. 2016.
  7. MM7 — Communication is the tax on parallelism. Every scheme — DDP's all-reduce, ZeRO's reduce-scatter/all-gather, tensor parallelism's per-layer collectives, pipeline parallelism's bubble — is a different way of paying a communication cost for a memory or compute benefit. Predicts the point where adding GPUs stops helping (communication-bound regime). Bug class without it: naively scaling GPU count expecting linear speedup indefinitely. Applies at §20, §29, §34.
  8. MM8 — A loss spike is a symptom, not a diagnosis. The same observable symptom (loss > 3× rolling median) can stem from a corrupted data batch or from genuine numerical instability — the flag alone cannot distinguish them. Predicts that acting on the flag alone (blind restart) fixes nothing if the root cause is a bad shard. Bug class without it: repeated restarts that never address the actual cause. Applies at §19, P8, I9.

5. Required Reading

Books

  • Goodfellow, Bengio & Courville — Deep Learning (MIT Press, 2016). Ch. 6 "Deep Feedforward Networks" (backprop mechanics) and Ch. 8 "Optimization for Training Deep Models" (SGD-family convergence, ill-conditioning). Applied in §8.5–§8.7, §15 (AdamW derivation).
  • Jurafsky & Martin — Speech and Language Processing (3rd ed. draft, 2023). Ch. 9 "Transformers and Large Language Models" — the standard curriculum treatment of self-attention and causal LMs. Applied in §8.2–§8.4, §14.
  • Kleppmann — Designing Data-Intensive Applications (O'Reilly, 2017). Ch. 5 "Replication" and Ch. 9 "Consistency and Consensus" — the durability/atomicity vocabulary this blueprint reuses for checkpoint writes. Applied in §18, §23.
  • Hennessy & Patterson — Computer Architecture: A Quantitative Approach (6th ed., Morgan Kaufmann, 2019). Ch. 4 "Data-Level Parallelism in Vector, SIMD, and GPU Architectures" — the roofline model underlying MFU. Applied in §29, §32.
  • Gregg — Systems Performance (2nd ed., Addison-Wesley, 2020). Ch. 4 "Observability Tools" and Ch. 6 "CPU" — the profiling methodology (USE method) this blueprint's Performance Engineering section adopts. Applied in §21, §28.
  • Jain — The Art of Computer Systems Performance Analysis (Wiley, 1991). Ch. 12 "Workload Characterization" — the methodology for defining a representative benchmark batch. Applied in §28.

Papers

  • Vaswani et al., 2017, NeurIPS. "Attention Is All You Need." The architecture's origin. Applied in §8.2–§8.5, §14 (P1).
  • Radford et al., 2019. "Language Models are Unsupervised Multitask Learners" (GPT-2). Decoder-only simplification, pre-norm. Applied in §4, §12, §14.
  • Brown et al., 2020, NeurIPS. "Language Models are Few-Shot Learners" (GPT-3). AdamW β=(0.9,0.95), grad-clip 1.0, cosine+warmup, 3.2M-token batch. Applied in §4, §15, ADR-08/ADR-12.
  • Touvron et al., 2023. "LLaMA: Open and Efficient Foundation Language Models." RMSNorm, RoPE, SwiGLU, β2=0.95. Applied in §9, §14.
  • Loshchilov & Hutter, 2019, ICLR. "Decoupled Weight Decay Regularization" (AdamW). The decoupled-WD derivation. Applied in §8.7, §15 (P/I on optimizer).
  • Kingma & Ba, 2015, ICLR. "Adam: A Method for Stochastic Optimization." Moment estimates + bias correction. Applied in §8.7, §15.
  • Zhang & Sennrich, 2019, NeurIPS. "Root Mean Square Layer Normalization." Mean-subtraction-free norm. Applied in §8.4, §14, ADR-04.
  • Su et al., 2021. "RoFormer: Enhanced Transformer with Rotary Position Embedding." Relative-position-preserving rotation. Applied in §8.2, §14, ADR-05.
  • Shazeer, 2020. "GLU Variants Improve Transformer." SwiGLU derivation. Applied in §8.4, §14, ADR-06.
  • Micikevicius et al., 2018, ICLR. "Mixed Precision Training." fp32-master + loss-scaling rationale; bf16's dynamic-range argument. Applied in §8.8, §16, ADR-09.
  • Chen et al., 2016. "Training Deep Nets with Sublinear Memory Cost" (gradient checkpointing). O(√L) memory via selective recompute. Applied in §8.9, §17.
  • Rajbhandari et al., 2020, SC. "ZeRO: Memory Optimizations Toward Training Trillion Parameter Models." Optimizer/gradient/parameter sharding stages. Applied in §8.10, §20.
  • Shoeybi et al., 2019. "Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism." Tensor + pipeline parallelism. Applied in §8.10, §20, §34.
  • Kaplan et al., 2020. "Scaling Laws for Neural Language Models." Loss vs. (params, data, compute) power laws. Applied in §4, §32.
  • Hoffmann et al., 2022. "Training Compute-Optimal Large Language Models" (Chinchilla). 20-tokens/param rule. Applied in §4, §32.

Reference Implementations

  • karpathy/nanoGPT — model.py, train.py. Lesson: a correct GPT-2 reproduction fits under 1,000 lines. Pitfall: single-file global config does not scale past one experiment; do not copy that part. Applied in §12, §21.
  • NVIDIA/Megatron-LM — megatron/core/tensor_parallel/, megatron/core/pipeline_parallel/. Lesson: column/row-parallel linear layers compose into full 3D parallelism. Pitfall: topology assumptions are NCCL/NVLink-specific and silently degrade on non-NVIDIA fabrics. Applied in §20, §34.
  • microsoft/DeepSpeed — deepspeed/runtime/zero/. Lesson: ZeRO stage 1/2/3 progressively shard optimizer state, gradients, and parameters. Pitfall: CPU-offload trades throughput for memory in a way that is easy to enable accidentally and hard to notice until step time triples. Applied in §20.
  • pytorch/pytorch — torch/distributed/fsdp/. Lesson: FullyShardedDataParallel wraps ZeRO-3-equivalent sharding into the framework itself. Pitfall: activation checkpointing composed with FSDP needs the non-reentrant wrapper or gradients silently double-count. Applied in §17, §20.
  • EleutherAI/gpt-neox — configs/, megatron/. Lesson: production-scale open training run with full logging/checkpoint-conversion tooling. Pitfall: config sprawl across YAML-include layers obscures the effective config; this blueprint's single frozen TrainConfig is a direct reaction. Applied in §21, §24.
  • EleutherAI/pythia (model suite + training logs). Lesson: the most carefully-instrumented public run — fixed data order, 154 public checkpoints. Pitfall the project itself documents: bit-exact batch-order reproduction across restarts is harder than it looks, motivating this blueprint's I1/I2. Applied in §18.

Glossary (§36) · 44 terms · site-wide glossary

AdamW
Adam with decoupled weight decay (Loshchilov & Hutter 2019); this project's default optimizer (§8.7, ADR-07).
Activation checkpointing
discarding intermediate activations and recomputing them during backward to trade compute for memory (§8.9, §17).
Autocast
PyTorch's context manager that runs ops in a reduced- precision dtype while keeping reductions in fp32 where needed (§8.8).
bf16 (bfloat16)
16-bit float with fp32's 8-bit exponent and a 7-bit mantissa; this project's default compute dtype (§8.8, ADR-09).
Bit-exact resume
the guarantee that a crashed-and-resumed run matches an uninterrupted run to fp64 tolerance (§18, I1, P2).
Causal mask
the attention mask preventing position i from attending to positions > i (§8.3).
Checkpoint retention policy
the rule keeping the last N checkpoints, the best-eval checkpoint, and periodic milestones (§18, P7).
Chinchilla-optimal
the 20-tokens-per-parameter training-data ratio from Hoffmann et al. 2022 (§4, §32).
Config hash
a SHA-256 over a TrainConfig's YAML source, embedded in every checkpoint for provenance (§11.1, I8).
Cosine-with-warmup schedule
LR ramps linearly during warmup then decays along a cosine curve (§8.7, ADR-08).
DDP (DistributedDataParallel)
PyTorch's data-parallel wrapper; every rank holds a full model replica (§8.10, ADR-21).
Decoupled weight decay
applying weight decay directly to parameters rather than through the adaptive gradient scale (§8.7).
Deterministic shuffle
a shuffle that is a pure function of (seed, epoch) (§8.1, I2, P3).
Effective batch size
micro_batch × grad_accum_steps × dp_world_size (§4, §32, I11).
Eval harness
the held-out perplexity + benchmark evaluation subsystem, observational only (§19, P6).
FSDP (FullyShardedDataParallel)
PyTorch's native parameter/gradient/ optimizer-state sharding wrapper (§8.10, §20, ADR-24).
Gradient accumulation
summing loss-scaled gradients over several micro-batches to simulate a larger batch (§8.9, I3, P5).
Gradient checkpointing
see Activation checkpointing.
Gradient clipping (global-norm)
rescaling the full gradient vector so its L2 norm does not exceed a threshold (§8.6, ADR-12).
GQA (Grouped-Query Attention)
sharing key/value projections across groups of query heads (§8.3, §11.1 n_kv_head).
IEEE 754
the floating-point arithmetic standard defining fp32/fp16/ bf16 bit layouts (§5, §16).
LayerNorm
mean-and-variance normalization layer; an alternative to RMSNorm (§8.4, ADR-04).
Loss spike
a training step whose loss exceeds 3× the rolling median (§19, I9, P8).
MFU (Model FLOPs Utilization)
achieved FLOPs/s divided by the GPU's theoretical peak FLOPs/s (§21, §28, §32).
Micro-batch
one forward/backward pass's worth of data within an accumulation cycle (§8.9, §11.3).
Mixed precision
running forward/backward in a reduced-precision dtype while keeping optimizer state in fp32 (§8.8, I4).
NaN gate
the pre-optimizer-step scan that halts on NaN/Inf gradients (§16, I6).
NCCL
NVIDIA's Collective Communications Library, the transport for DDP/FSDP collectives (§5, §20, §28).
Non-reentrant checkpointing
the torch.utils.checkpoint variant compatible with FSDP without gradient double-counting (§17, §20).
Packing (sequence packing)
concatenating multiple documents into one fixed-length training sequence separated by EOS tokens (§8.1, ADR-17).
Perplexity
exp(eval_loss), the standard LM evaluation metric (§11.5, §19).
Pipeline parallelism
splitting model layers across GPUs and pipelining micro-batches through them (§8.10, §34).
Pre-norm
applying normalization before, not after, each sublayer (§8.4, ADR-03).
RMSNorm
mean-subtraction-free normalization (Zhang & Sennrich 2019), this project's default norm (§8.4, ADR-04).
RNG snapshot
the captured state of all five randomness sources needed for bit-exact resume (§11.5, I12).
RoPE (Rotary Position Embedding)
relative-position-preserving rotation of query/key vectors (Su et al. 2021, §8.2, ADR-05).
Rolling median
the median loss over a fixed recent window, the baseline for spike detection (§19, I9).
Shard catalog
the manifest of .npy token shards with integrity hashes (§8.1, §11.2, ADR-15).
SwiGLU
a gated-linear-unit MLP variant (Shazeer 2020), this project's default MLP activation (§8.4, ADR-06).
Tensor parallelism
splitting individual matmuls across GPUs within one layer (§8.10, §34, Shoeybi et al. 2019).
Tied embeddings
sharing one weight matrix between the token embedding and the output projection (§8.2, ADR-14, I10).
torch.compile
PyTorch's graph-compilation API for reduced per-step overhead (§21, ADR-20).
Warmup steps
the initial steps during which LR ramps linearly from 0 to its peak value (§8.7, ADR-08).
ZeRO (Zero Redundancy Optimizer)
progressive sharding of optimizer state / gradients / parameters across data-parallel ranks (Rajbhandari et al. 2020, §8.10, §20).
