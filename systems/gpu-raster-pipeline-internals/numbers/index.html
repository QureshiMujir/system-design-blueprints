34. Back-of-Envelope Capacity Model

Fill rate and 4K frame time. fill_rate = rop_count * clock_ghz * 1e9 pixels/second. For 64 ROPs at 1.5 GHz: fill_rate = 64 * 1.5e9 = 9.6e10 pixels/second. A 4K frame (3840x2160 = 8,294,400 pixels) at overdraw factor 3: frame_time = (8,294,400 * 3) / 9.6e10 = 2.59e-4 seconds ≈ 0.26 ms of pure fill time (excludes shading/texture cost, isolating the ROP term per §8.7).

Memory bandwidth needed per frame vs. VRAM budget. bandwidth_needed = pixels * overdraw * bytes_per_pixel_touched * frames_per_second. For the same 4K frame, overdraw 3, 16 bytes/pixel-touched (IMR read+write of a typical color+depth combo), 60 FPS: bandwidth_needed = 8,294,400 * 3 * 16 * 60 = 2.39e10 bytes/second ≈ 23.9 GB/s. Against a modeled VRAM budget of 700 GB/s, this frame is nowhere near the roofline ridge for bandwidth alone at this overdraw — but at overdraw 30 (heavy transparency), bandwidth_needed ≈ 239 GB/s, materially closer to the ceiling, showing the roofline crossover directly (§8.10).

Occupancy from registers. warps = register_file_size / (registers_per_thread * warp_width), capped by the scheduler. For a 65,536-register file, 64 registers/thread, warp width 32: warps = 65536 / (64*32) = 32, capped at the scheduler's 64-warp ceiling — register-limited at 32 (reproduces §8.3's worked example exactly).

Texture bandwidth. texture_bandwidth = texels_fetched * bytes_per_texel / hit_rate_adjustment, where hit_rate_adjustment discounts fetches served from cache. For 1e8 texel fetches/frame at 4 bytes/texel and an 80% L1 hit rate (only the 20% miss fraction reaches VRAM): vram_texture_bandwidth = 1e8 * 4 * 0.20 = 8e7 bytes/frame ≈ 80 MB/frame, or 4.8 GB/s at 60 FPS.

Quad-overshading waste for tiny triangles. helper_lane_fraction = wasted_quad_lanes / total_quad_lanes. A 1-pixel triangle inside an otherwise-empty 2x2 quad wastes 3 of 4 lanes: helper_lane_fraction = 3/4 = 0.75 — the worst-case value used as the Phase 6 acceptance target (§18.4, §8.12).

TBDR bandwidth saving. From §8.8: IMR_traffic ≈ P * V * bytes_per_pixel * 2, TBDR_traffic ≈ P * bytes_per_pixel, so savings_factor ≈ 2V. At overdraw V=4: savings_factor ≈ 8x less VRAM traffic for TBDR versus IMR on the same tile.

Warp-divergence throughput loss. throughput_fraction = active_lanes / warp_width. Reproducing §8.2's worked example: pass 1 at 20/32 = 0.625, pass 2 at 12/32 = 0.375, average active-lane fraction across the two passes = 0.5 — half of peak achievable warp throughput for that divergent instruction.
