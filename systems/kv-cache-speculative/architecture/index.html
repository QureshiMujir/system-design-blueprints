Request router. Terminates HTTP/gRPC, tokenizes, validates SamplingParams/ SpeculativeParams (§11.4), assigns a SequenceId, hands the Sequence to the scheduler. Trust boundary: the only place untrusted client input is parsed.

Scheduler. Owns four named sequence sets (I3) and the fairness policy (P7); the sole concurrency boundary between request arrival and GPU execution — one schedule_step() call per tick, never re-entrant.

KV-cache manager. Owns the physical block pool, the per-sequence block tables, the hash-keyed prefix cache, and copy-on-write; the sole authority on GPU-memory admission (can_allocate) — the persistence boundary for anything that must survive a preemption (swap to host memory, §15.6).

Model forward. Pure function of BatchPlan → BatchOutput (I5); the protocol boundary between scheduler-owned bookkeeping and kernel-owned tensor math; never mutates scheduler or cache-manager state directly.

Speculative decoder. Wraps the model forward with a propose/verify/accept loop; scheduler-visible (P4) — the scheduler, not the model, decides whether a step is speculative and how many slots to reserve.

Detokenizer + stream. Per-request incremental detokenization and the external streaming interface (SSE); the only component touching a str — everything upstream is token ids.

All later sections stay consistent with this diagram; a component not shown here does not exist in the runtime path.

8. Domain Model

8.1 KV-cache layout

Per-layer, per-head K and V tensors are stored in a single physical pool tensor of shape (2, num_layers, num_blocks, block_size, num_kv_heads, head_dim). A block holds block_size (16) contiguous token positions' K and V for every layer — one block allocation serves the whole model depth, avoiding per-layer fragmentation.

Physical pool tensor (conceptual layout):

  axis 0: {K=0, V=1}
  axis 1: layer   0 .. L-1
  axis 2: block   0 .. num_blocks-1      <- BlockId indexes here
  axis 3: slot    0 .. block_size-1      <- offset_within_block
  axis 4: kv_head 0 .. num_kv_heads-1
  axis 5: dim     0 .. head_dim-1

  addressing: physical_slot(seq, position) =
      block_table[seq].physical[position // block_size]   -> BlockId
      offset = position % block_size                       -> slot index

8.3 Draft/target speculative verification — worked example

K = 3 proposed tokens, draft distribution q, target distribution p, per Leviathan et al. 2023 §2:

step   draft token   q(token)   p(token)   accept prob = min(1, p/q)   outcome
1      "the"         0.60       0.55       0.917                       accept (r=0.40)
2      "cat"         0.45       0.20       0.444                       reject (r=0.70)
       -> resample from  max(0, p - q) normalized over full vocab
       -> resampled token: "dog"                                       (I9 holds: distribution = p)
(step 3 not reached; verification stops at first reject + 1 bonus token)

Accepted prefix = ["the", "dog"] (2 tokens from 1 forward pass of the target model, vs. 2 sequential target forwards without speculation). The accept/reject decision uses a single uniform draw r ~ U(0,1) per proposed token, compared against min(1, p(x)/q(x)) — this is the entire correctness-critical logic of I9.

8.4 Malformed-input examples

  • Prefix-cache hash collision: two distinct token sequences hash to the same content_hash (xxHash3, ADR-19). Detection: §16.5 verify step re-compares the actual token ids on a candidate cache hit before serving it; a mismatch is logged as prefix_cache_hash_collision_total and treated as a cache miss (never served as a false hit).
  • Draft/target vocab mismatch: a draft model with a different tokenizer or vocab size than the target. Detection: a startup-time check (SpeculativeParams validation, Phase 5) compares vocab_size and a fixed set of special-token ids; mismatch is a startup error, never a runtime crash (P4, FM-7).
  • num_speculative_tokens exceeding remaining max_seq_len budget: the admission check (I8) clamps the speculative window to max_seq_len - current_len before allocating speculative blocks; an unclamped request would over-allocate blocks that are immediately freed, wasting a can_allocate cycle.

8.5 Failure-path example

A Running sequence mid-speculation loses its draft-model forward (draft-model worker OOM). Recovery path: the speculative decoder catches the draft failure, falls back to speculative_method = off for that sequence only (P4), logs spec_draft_failure_total, and the scheduler continues the sequence in plain decode mode for the remainder of its lifetime — the sequence is never aborted for a draft failure (I8's abort path is reserved for max_seq_len and explicit operator kill only).

Design principles (§6)

  • P1 — Block-as-allocation-unit. KV memory is allocated/freed/shared/evicted as fixed-size blocks (B = 16 tokens default). Tradeoff: internal fragmentation ≤ B−1 tokens/sequence vs. the unbounded external fragmentation of contiguous allocation. Violating it (falling back to per-sequence contiguous buffers) reintroduces the 30–60% fragmentation loss the vLLM paper measured — see ADR-02.
  • P2 — Prefix-sharing by default. Sequences with a common prompt prefix share blocks by reference (§16); no opt-in flag required. Tradeoff: a refcounted block is immutable once shared (forces copy-on-write, P3). Violating it (per-sample copies) costs O(n) memory for n-way parallel sampling instead of O(1) extra.
  • P3 — Copy-on-write on divergence. The first writer to a shared block forks a new physical block (§16.4). Tradeoff: one extra block-copy per divergence point vs. correctness under concurrent mutation. Violating it silently corrupts a sibling sequence's cache (I6).
  • P4 — Speculative-as-config. speculative_method ∈ {off, draft, medusa, lookahead} is a per-request or per-deployment toggle; scheduler and cache manager are speculation-agnostic below §17. Tradeoff: extra indirection (SpeculativePlan, §11.6) vs. the ability to disable speculation in production with zero code change when acceptance collapses (FM-6).
  • P5 — Never-recompute-prefix. A cache hit on a hashed prefix (§16.3) is a lookup, never a re-forward. Tradeoff: hashing cost (~50 ns/block, xxHash3) vs. skipping an entire prefill forward (milliseconds). Violating it defeats the entire purpose of the prefix cache.
  • P6 — KV-quant orthogonal. The dtype of a KV block (FP16/INT8/INT4) is a per-pool configuration invisible to the scheduler, prefix cache, and speculative loop (§20). Tradeoff: an extra dequant step in the attention kernel vs. keeping every upstream component dtype-agnostic. Violating it (hardcoding FP16 assumptions) blocks quantization from ever shipping without a scheduler rewrite.
  • P7 — Fairness policy is named and singular. Exactly one SchedulingPolicy (FCFS, priority, or fair-share) is active per deployment, implemented once (§15.3). Tradeoff: less per-request flexibility vs. a debuggable, single code path. Violating it (heuristics scattered across three files) is the #1 documented root cause of scheduler bugs in production serving stacks (TGI issue history, §31).
  • P8 — Preemption, not panic. A sequence that cannot fit a new block is swapped to host memory or aborted (I8); out-of-memory in the cache manager is a scheduled state transition, never an unhandled exception. Tradeoff: swap bandwidth cost (~PCIe Gen5 ~50 GB/s) vs. never crash-looping the worker under load.
  • P9 — One model forward per scheduler step. Prefill, decode, and speculative verification for every admitted sequence share one forward(BatchPlan) call (I5). Tradeoff: a more complex ragged-batch kernel vs. avoiding per-step Python/kernel-launch overhead doubling. Violating it (separate prefill/decode passes) costs the ~200 µs per-step launch overhead twice, dominating at small batch sizes.
  • P10 — Tokenizer/detokenizer in-process. No network round-trip for tokenization; the CPU-side incremental detokenizer runs on the same host as the GPU worker. Tradeoff: CPU core contention with NCCL/driver threads vs. removing a network hop from the token-emission critical path.
  • P11 — Numerics tested against a reference, always. Every kernel (paged attention, fused RMSNorm/RoPE, sampler) is unit-tested against a PyTorch-eager reference at a stated per-element tolerance (I11). Tradeoff: a slower CI numerics suite (~10 min) vs. catching silent precision drift before it reaches production (the single hardest class of bug to diagnose post-hoc).
  • P12 — Benchmarks are reproducible artifacts. Every benchmark run pins CUDA toolkit, driver, model-weight hash, prompt corpus, and RNG seed, and is invoked by one make bench target (§27). Tradeoff: benchmark-harness maintenance cost vs. a number nobody can dispute in a regression review.
  • P13 — Output-distribution equivalence is non-negotiable. Any speculative method must produce token distributions statistically indistinguishable from the target model run without speculation (I9). Tradeoff: rejecting faster-but-approximate accept rules (e.g. always-accept top-1) in favor of the proven rejection-sampling construction (Leviathan et al. 2023, Chen et al. 2023).
  • P14 — Every accelerant is independently toggleable and independently measured. Paging, prefix caching, speculation, and quantization each have a benchmark and a kill-switch (§28 M-series, §11.4 config flags). Tradeoff: a combinatorial benchmark matrix (§27) vs. being able to attribute a regression to exactly one subsystem.
