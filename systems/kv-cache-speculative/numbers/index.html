32. Back-of-Envelope Capacity Model

Derived from §4's constraint table; formula shown for every number.

  1. KV bytes/token = 2 · L · Hkv · Dh · b = 2 · 32 · 8 · 128 · 2 = 131,072 B (128 KiB). [§4 row 1]
  2. KV bytes for one 8K-context sequence = 131,072 B/token × 8,192 tokens = 1,073,741,824 B (1 GiB). [chained from #1]
  3. Usable GPU memory for KV-cache, 1×H100 80 GiB = 80 GiB − 14.9 GiB weights − 4 GiB reserved overhead = ≈ 61.1 GiB. [§4 rows 2, weight math from §1]
  4. Max concurrent 8K-context sequences, 1×H100 = 61.1 GiB / 1 GiB = ≈ 58 sequences. [chained from #2, #3 — matches §4's stated ceiling]
  5. Blocks per 8K-context sequence = 8,192 tokens / 16 tokens-per-block = 512 blocks. [§4 block-size row]
  6. Total physical blocks needed at max concurrency = 58 sequences × 512 blocks = ≈ 29,696 blocks. [chained from #4, #5]
  7. NCCL all-reduce bytes per TP step, 2-way TP, hidden=4096, FP16 = 4,096 × 2 B = 8,192 B per token per layer × 32 layers = ≈ 262 KiB/token cross-GPU traffic. [derived from model config, §4]
  8. Swap bandwidth budget = PCIe Gen5 x16 ≈ 50 GB/s; time to swap one 1 GiB sequence (#2) = 1,073,741,824 B / 50e9 B/s ≈ 21.5 ms. [chained from #2, §4's PCIe assumption]
  9. Aggregate tokens/s target (M3) implies GPU-side memory bandwidth demand: at 1,800 tokens/s aggregate and 131,072 B/token KV read+write per decode step ≈ 1,800 × 131,072 B ≈ 236 MB/s minimum KV-traffic floor (well under H100's ~3.35 TB/s HBM bandwidth — confirms KV-cache capacity, not bandwidth, is the binding constraint at this scale, consistent with §4's defining property).
  10. INT4 quantization reduces #4's ceiling upward: 58 sequences × 4× (ADR-09) = ≈ 232 sequences at the same memory budget, before accounting for the dequantization kernel's own working-memory overhead. [chained from #4, ADR-09]
