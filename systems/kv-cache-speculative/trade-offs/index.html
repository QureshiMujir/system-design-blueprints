Decisions (§9) · 22 ADRs

ADR-01

Primary language split

Chosen

Python 3.11 orchestration + CUDA C++/Triton kernels

Rejected

Pure Rust (cudarc); pure C++; Go

When the rejected choice is right

Pure Rust wins for a CPU-only or embedded-inference deployment with no GPU kernel ecosystem dependency (e.g. edge inference of a distilled model)

Why: Kernels dominate wall time (§4); Python's per-step overhead is amortized; Rust's CUDA-kernel ecosystem is immature

ADR-02

KV-cache allocation unit

Chosen

Paged, block_size=16 (ADR default)

Rejected

Contiguous per-sequence buffer

When the rejected choice is right

Contiguous wins for single-user, single-sequence local inference (llama.cpp's default use case) where fragmentation never occurs

Why: Contiguous wastes 30–60% to fragmentation at production concurrency (Kwon et al. 2023 §2)

ADR-03

Batching mode

Chosen

Continuous batching only

Rejected

Static batch-then-run

When the rejected choice is right

Static batching wins for offline bulk-scoring jobs with known, near-uniform sequence lengths and no latency SLA

Why: Static batching's tail latency is bounded by the longest sequence in the batch, 2–3× throughput loss

ADR-04

Forward passes per scheduler step

Chosen

Exactly one (BatchPlan → BatchOutput)

Rejected

Separate prefill pass + decode pass

When the rejected choice is right

Two passes win when prefill and decode must run on physically separate hardware (disaggregated serving, §34 Alt-2)

Why: Two passes double per-step launch overhead (~200 µs × 2)

ADR-05

Prefix-cache keying

Chosen

Hash-keyed (model_id, tokenizer_id, block_tokens), deterministic

Rejected

Per-session cache only

When the rejected choice is right

Per-session-only wins when prompts are unique per tenant and cross-tenant caching is a compliance violation

Why: Cross-session reuse (shared system prompts) is the dominant hit pattern in chat workloads

ADR-06

Parallel-sampling / beam-search memory

Chosen

Copy-on-write shared blocks

Rejected

Full per-sample copy

When the rejected choice is right

Full-copy wins when branch frequency is so high (e.g. beam width ≥ 32) that CoW-fork overhead exceeds the copy cost

Why: CoW gives O(prefix + suffix) vs O(n × full) memory for n-way sampling

ADR-07

Default speculative method

Chosen

Independent draft model

Rejected

No speculation; Medusa-first

When the rejected choice is right

No-speculation wins on memory-constrained single-GPU deployments where a second model cannot fit

Why: Draft model requires no fine-tuning step, lowest integration effort

ADR-08

Draft-free alternatives

Chosen

Medusa (Phase 6) and lookahead (Phase 7) both shipped, config-selectable

Rejected

Only one alternative shipped

When the rejected choice is right

Draft model wins when a well-matched smaller sibling model already exists (e.g. Llama-3-8B draft for Llama-3-70B target)

Why: Medusa avoids draft-target tokenizer skew; lookahead avoids the fine-tuning step entirely; no single method dominates all workloads (§31)

ADR-09

KV-cache quantization schedule

Chosen

FP16 (Phase 0) → INT8 (Phase 8) → INT4 (Phase 8.5)

Rejected

FP8 KV cache

When the rejected choice is right

FP8 wins when the deployment fleet is homogeneously H100/H200 and portability is not a requirement

Why: FP8 requires H100+ hardware, not portable to the Phase-0 target fleet

ADR-10

Multi-GPU parallelism strategy

Chosen

Tensor-parallel via NCCL

Rejected

Pipeline-parallel

When the rejected choice is right

Pipeline-parallel wins for training-adjacent workloads with very large batch sizes where bubble overhead amortizes

Why: Pipeline parallel head-of-line-blocks prefill behind decode stages

ADR-11

Paged-attention kernel source

Chosen

FlashInfer (wrapped)

Rejected

Hand-written CUDA from scratch

When the rejected choice is right

Hand-written CUDA wins when a novel attention variant (e.g. a custom sparsity pattern) has no existing kernel library support

Why: FlashInfer ships a maintained paged variant; hand-rolling duplicates a solved problem

ADR-12

Fused elementwise kernels (RMSNorm, RoPE)

Chosen

Triton

Rejected

Hand-written CUDA C++

When the rejected choice is right

Hand-written CUDA wins where Triton's lack of warp-level primitives costs >10% (measured case: tree attention, ADR-18)

Why: Triton kernels are debuggable from Python, iterate faster

ADR-13

Weight-loading format

Chosen

safetensors, mmap'd

Rejected

pickle

When the rejected choice is right

pickle is tolerable only in a fully air-gapped, self-authored research script with no external weight source — any production or shared deployment must use safetensors

Why: pickle is a remote-code-execution vector on untrusted weight sources

ADR-14

Prefix-cache eviction policy

Chosen

LRU

Rejected

LFU

When the rejected choice is right

LFU wins for workloads with a small set of extremely hot, long-lived system prompts reused far more than recency alone predicts (e.g. a single fixed few-shot template shared by 10,000 requests/hour)

Why: Chat workloads show strong recency-skew, weak frequency-skew

ADR-15

Scheduler fairness policy default

Chosen

FCFS (Phase 3) → priority + fair-share (Phase 8)

Rejected

Priority-only from Phase 3

When the rejected choice is right

Priority-first wins in a multi-tenant SaaS deployment from day one, where FCFS would let a free-tier burst starve paid tenants

Why: FCFS is the simplest correct baseline; priority adds complexity a Phase-3 reader doesn't need yet

ADR-16

OOM handling

Chosen

Swap-out to host memory before abort

Rejected

Abort-on-OOM

When the rejected choice is right

Abort-on-OOM wins when host memory is also constrained (edge device) and swap would itself thrash

Why: A 90%-complete generation should not be killed for a new admission

ADR-17

External API surface

Chosen

OpenAI-compatible HTTP (/v1/completions, /v1/chat/completions) + SSE

Rejected

Bespoke REST API

When the rejected choice is right

A bespoke API wins when the deployment is fully internal and the OpenAI schema's constraints (e.g. no native tool-call batching) block a required feature

Why: Client ecosystem is dominated by OpenAI-shaped SDKs

ADR-18

Tree-attention kernel language

Chosen

CUDA C++

Rejected

Triton

When the rejected choice is right

Triton wins for the non-tree (linear) speculative decode path, where the overhead does not appear (§17)

Why: Triton lacks warp-level scan primitives; measured ~20% slower for tree attention

ADR-19

Block content-hash function

Chosen

xxHash3

Rejected

SHA-256

When the rejected choice is right

SHA-256 wins for the model-weight integrity check at load time, where cryptographic collision resistance against an adversarial model source matters

Why: xxHash3 is the fastest non-cryptographic hash with acceptable collision odds at 16-token blocks; verified on hit (§16.5)

ADR-20

Observability stack

Chosen

OpenTelemetry traces + Prometheus metrics

Rejected

Vendor-specific APM SDK

When the rejected choice is right

A vendor APM SDK wins inside an organization already standardized on one platform-wide, where OTel would be a redundant second pipeline

Why: Open standards avoid vendor lock-in for a self-hosted engine

ADR-21

Build/dependency management

Chosen

uv, pinned via uv.lock

Rejected

conda

When the rejected choice is right

conda wins when the deployment must also manage non-Python native dependencies uv does not model (e.g. a bundled MPI implementation)

Why: Faster installs, cleaner separation from system CUDA than conda's bundled toolchain

ADR-22

License

Chosen

Apache-2.0 (engine); reserved ELv2 (future hosted control plane)

Rejected

MIT

When the rejected choice is right

MIT wins for a pure-research fork with no patent-exposure concern and a preference for the shortest possible license text

Why: Apache-2.0's explicit patent grant is safer for a project touching hardware-vendor kernel code (NVIDIA CUDA)

34. Alternative Architectures (Roads Not Taken)

Alt-1 — Contiguous per-sequence KV-cache (no paging).

 [ sequence A: contiguous KV buffer, max_seq_len sized ]
 [ sequence B: contiguous KV buffer, max_seq_len sized ]
 [ ... unused tail space wasted per sequence ...       ]

Regime where it wins: single-user or small-batch local inference with no concurrent- sequence memory pressure (consumer GPU, one chat session at a time). Real embodiment: llama.cpp's default KV-cache (§31). Rejected here because production concurrency (dozens of variable-length sequences, §4) makes fragmentation the dominant memory cost — exactly the problem PagedAttention (Kwon et al. 2023) was built to solve, and this blueprint's entire premise (§3) is serving that concurrency regime.

Alt-2 — Disaggregated prefill/decode serving.

 [ prefill GPU pool ] --KV transfer--> [ decode GPU pool ]
     (compute-bound)                      (memory-bandwidth-bound)

Regime where it wins: workloads with a sharp, predictable prefill/decode compute- profile split at very large fleet scale, where dedicating separate hardware pools to each phase avoids the one-forward-per-step principle's (P9, ADR-04) implicit coupling of prefill and decode resource contention. Real embodiment: DistServe and Splitwise (both published systems disaggregating prefill and decode across hardware pools). Rejected here (PhaseDeferred("§15.10"), §35) because it requires a KV-transfer network protocol and doubles operational complexity (two hardware pool types to capacity-plan) for a benefit that only appears at fleet scales well beyond this blueprint's single-to-few-replica target (§3's single-driver-plus-N-workers model).

Alt-3 — Heterogeneous CPU/GPU offload (FlexGen-style).

 [ GPU: hot layers/weights ] <--offload--> [ CPU/NVMe: cold layers, KV overflow ]

Regime where it wins: throughput-oriented batch inference on a single consumer GPU with insufficient memory for the full model + KV-cache, where latency is not a constraint (offline batch scoring). Real embodiment: FlexGen (Sheng et al. 2023, throughput-oriented single-GPU LLM serving via CPU/disk offload). Rejected here because this blueprint targets interactive-latency serving (§4's p50/p99 targets) where CPU/NVMe round-trips for cold weights or overflowed KV blocks would violate the inter-token latency budget by an order of magnitude.
