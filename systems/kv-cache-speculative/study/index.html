30. Mental Models & First Principles

  1. MM1 — A block is a page, a block table is a page table. Predicts: any OS virtual-memory bug class (fragmentation, TLB-miss-equivalent lookup cost, sharing via copy-on-write) has a direct analog here. Bug class without it: reinventing contiguous allocation and rediscovering fragmentation the hard way. Applied in §14.
  2. MM2 — The KV-cache is the buffer pool; sealing is checkpointing. Predicts: a sealed (immutable, hashed) block behaves like a committed database page — safe to share, unsafe to mutate. Bug class without it: mutating a shared block in place (I6 violations). Applied in §16.
  3. MM3 — Continuous batching is weighted-fair-queuing over heterogeneous flow sizes. Predicts: the same starvation/fairness failure modes that plague naive network schedulers (short flows starving behind long ones, or vice versa under a bad policy) apply directly to sequence scheduling. Bug class without it: an undocumented heuristic-du-jour preemption policy (P7's entire justification). Applied in §15.
  4. MM4 — Speculative decoding is importance-sampling correction, not a heuristic speedup. Predicts: the acceptance rule must take the exact min(1, p/q) form or the output distribution silently shifts — this is a probability-theory constraint, not an engineering tradeoff. Bug class without it: "just accept the top-1 draft token" (§17.6's documented anti-pattern). Applied in §17.
  5. MM5 — A Medusa tree is a speculative-decode search tree, not a batch. Predicts: tree depth/fan-out trades verification cost against expected accepted length combinatorially, not linearly. Bug class without it: an unbounded tree topology that regresses below non-speculative baseline (§18.6). Applied in §18.
  6. MM6 — Lookahead is Jacobi iteration over the decode recurrence. Predicts: it converges fastest exactly where the sequence has high internal redundancy (code, repetitive text) and slowest on genuinely novel content — the same convergence profile Jacobi methods show on diagonally-dominant vs. ill-conditioned systems. Bug class without it: deploying lookahead as a universal default and being surprised by workload-dependent regressions (§19.6). Applied in §19.
  7. MM7 — Quantization is a signal-processing quality/bandwidth trade, not a free lunch. Predicts: per-channel scaling beats per-tensor scaling because KV values' dynamic range varies by channel, not uniformly — the same reason per-channel quantization wins in classical DSP compression. Bug class without it: a perplexity regression traced to per-tensor scaling instead of the intended per-channel approach (§20.6). Applied in §20.
  8. MM8 — Tensor parallelism is distributed shared memory with an explicit consistency protocol. Predicts: any distributed-consistency bug class (a dropped update, a stale replica) maps directly onto I13's block-table-divergence detection problem. Bug class without it: assuming NCCL broadcasts are exactly-once with no verification step. Applied in §21.

Reference Implementations

  • vLLM (vllm-project/vllm) — vllm/core/block_manager.py, vllm/core/scheduler.py, vllm/engine/llm_engine.py. Lesson: the block manager and scheduler are cleanly separated from the model executor. Pitfall not to copy: early vLLM versions coupled prefix-cache eviction to LRU without a content-hash verify step (fixed upstream after a correctness bug report) — the verify step is built in from the start. Applied in §16.5.
  • TensorRT-LLM (NVIDIA/TensorRT-LLM) — cpp/tensorrt_llm/batch_manager/. Lesson: the in-flight-batching state machine. Pitfall: its C++ batch-manager couples scheduling tightly to the engine build step, which we deliberately decouple (ADR-01). Applied in §15.2.
  • llama.cpp (ggml-org/llama.cpp) — ggml-cuda.cu, llama-kv-cache.cpp. Lesson: a simpler, single-process KV-cache management style, useful as a numerics cross-check. Pitfall: its default KV-cache is contiguous per-sequence, not paged — fine for single-user CPU/small-GPU inference, wrong for our concurrency target (ADR-02). Applied in §31 (comparative baseline).
  • FlashInfer (flashinfer-ai/flashinfer) — flashinfer.decode, flashinfer.prefill. Lesson: the paged-attention kernel API shape we adopt verbatim. Pitfall: its int64 slot-mapping convention silently mismatches PyTorch's int32 default — a documented Phase-1 pitfall. Applied in §13.3, §13.6.
  • HuggingFace Text Generation Inference (TGI) (huggingface/text-generation-inference) — router/src/queue.rs. Lesson: a Rust-implemented scheduler queue, useful as a cross-language design comparison. Pitfall: its continuous-batching admission logic historically under-accounted for speculative-slot memory, causing OOM under speculation, informing I8's admission check. Applied in §31, I8.

Glossary (§36) · 37 terms · site-wide glossary

Acceptance rate
fraction of speculatively proposed tokens accepted by the target model's verification step (I9).
Admission
the scheduler decision to move a sequence from Waiting to Running (I3, I8).
Batch manager
TensorRT-LLM's term for its in-flight-batching state machine (§5, §31).
BatchOutput
the model forward's return type (§11.5).
BatchPlan
the model forward's input type, carrying block tables and slot mappings (§11.5).
Block
the fixed-size (16-token default) unit of KV-cache allocation (P1).
BlockTable
per-sequence logical-to-physical block mapping (§11.2).
Continuous batching
admitting/ retiring sequences at every scheduler tick rather than waiting for a batch to drain (ADR-03).
Copy-on-write (CoW)
forking a shared block on first divergent write (P3, I6).
Decode
the autoregressive one-token-at-a-time generation phase, as opposed to prefill.
Draft model
a small model proposing candidate tokens for speculative verification (§17).
FCFS
first-come-first-served scheduling policy (ADR-15).
Fragmentation
wasted memory from contiguous-allocation's inability to reuse partially-freed space (ADR-02).
GQA
grouped-query attention, fewer KV heads than query heads (§4's Hkv).
Head dim
the per-attention-head embedding dimension (Dh, §4).
Inter-token latency
time between consecutive emitted tokens during decode (§4 M4-M6).
KL-divergence
statistical distance measure used to test speculative-decoding output-distribution equivalence (I9).
KV-cache
stored key/value tensors from prior decode steps, avoiding recomputation.
Lookahead decoding
draft-free speculation via n-gram extrapolation and Jacobi iteration (§19, Fu et al. 2024).
Medusa
multi-head speculative decoding replacing a separate draft model (§18, Cai et al. 2024).
NCCL
NVIDIA Collective Communications Library, used for tensor-parallel collectives (§21).
Paged attention
the attention kernel variant reading K/V from non-contiguous physical blocks via a block table (Kwon et al. 2023).
Perplexity
a language-model quality metric; used here to bound quantization-induced quality loss (§20).
Preemption
removing a running sequence (swap or abort) to admit or continue another (P8).
Prefill
the initial forward pass over the full prompt before decode begins.
Prefix cache
hash-keyed store of sealed blocks enabling cross-request prefix reuse (§16, ADR-05).
Ref count
number of live block-table entries pointing at a physical block (I2).
Rejection sampling
the probabilistic accept/reject construction underlying speculative decoding's distribution-preservation guarantee (I9, Leviathan et al. 2023).
RoPE
rotary position embedding.
Sealed block
an immutable, content-hashed, full block eligible for prefix-cache sharing (I7).
Slot mapping
the tensor mapping each input token to its physical KV-cache slot (§11.5).
Speculative decoding
proposing multiple future tokens and verifying them in one forward pass (§17).
Swap
moving a sequence's KV-cache blocks to host memory to free GPU memory without aborting the sequence (P8, ADR-16).
Tensor parallelism
sharding a model's weights and computation across multiple GPUs (§21, ADR-10).
Tree attention
the attention variant verifying a tree of speculative candidates (rather than a linear sequence) in one pass (Medusa, SpecInfer, §18).
TTFT
time to first token, the prefill-dominated latency metric (§4 M7).
xxHash3
the non-cryptographic hash function used for block content-hashing (ADR-19). ---
