7. System Invariants

7.1 Match Soundness — No False Negatives Within Advisory Feed Coverage

  • Statement: for every (component, advisory) pair where component.version ∈ advisory.affected_range, a Finding MUST be emitted.
  • Why: missing a critical CVE in a deployed dependency is a safety/compliance defect.
  • Enforced in: scs-match version-range satisfiability check; per-ecosystem comparator; regression test suite.
  • Violation detection: property-based tests (proptest) generate random versions and check match against known-affected ranges; golden-file tests for all major CVEs.
  • Telemetry: scs_match_soundness_check{ecosystem, advisory_id} counter; alert on test failure in CI.
  • Recovery: comparator bug → hotfix + re-scan; no silent retry — always surface the mismatch.
  • Debugging: enable RUST_LOG=scs_match=debug to trace per-comparison inputs/outputs; dump version + range as structured log.

7.2 AffectedRange Half-Open Semantics

  • Statement: version ∈ [introduced, fixed) means introduced ≤ version < fixed; version == fixed is NOT affected.
  • Why: off-by-one on exclusive upper bound = false negative on exactly the patched version.
  • Enforced in: AffectedRange::contains(&self, v: &Version) -> bool; unit tests with boundary cases v == introduced, v == fixed, v == fixed - epsilon.
  • Violation detection: boundary-condition unit tests required for every comparator; fuzz target on range parser input.
  • Telemetry: none (pure computation); violations caught in test.
  • Recovery: fix comparator; bump MSRV-compatible version of comparator crate if upstream bug.
  • Debugging: AffectedRange::explain(v) method returns string "in range [x, y)" / "fixed: version >= y" for diagnostic output.

7.3 Provenance Fail-Closed

  • Statement: any verification error in Sigstore/cosign/Rekor/in-toto yields Provenance { verified: false }; never defaults to verified: true on error path.
  • Why: an error swallowed as "verified" turns a network hiccup or attacker-crafted response into a security bypass.
  • Enforced in: scs-provenance; every ? propagation from verification returns ScsError, not Ok(verified=true).
  • Violation detection: mutation testing: inject error at each verification step, assert verified == false in output.
  • Telemetry: scs_provenance_verified{result=true|false|error} counter; alert if error rate spikes.
  • Recovery: transient Rekor unavailability → --offline-provenance flag; provenance section marked unverified with reason.
  • Debugging: structured log {rekor_url, entry_uuid, error_type, component_purl} at WARN level for every failure.

7.4 Scan Determinism

  • Statement: scan(inputs, feed_snapshot) → report is a pure function; same inputs + same snapshot → bit-identical JSON output.
  • Why: non-deterministic output makes diff-based triage meaningless; engineers lose trust in "no new findings" result.
  • Enforced in: all collections sorted before output; no HashMap in serialization paths (use BTreeMap); no Instant::now() in finding content (only in feed_snapshot.fetched_at).
  • Violation detection: run scan twice on same input; diff output JSON; CI test asserts zero diff.
  • Telemetry: scs_determinism_check{result=pass|fail} in CI benchmark; alert on fail.
  • Recovery: locate non-deterministic collection → replace with BTreeMap/sorted Vec; re-run test.
  • Debugging: binary-search over phases: emit intermediate JSON per phase, diff phase-by-phase to isolate non-determinism source.

7.5 Path Completeness

  • Statement: every Finding.path is a non-empty Vec<Purl> from the affected component to a project root; the last element is always a direct dependency of the scanned project.
  • Why: path-less findings force manual graph traversal; triage SLA increases; fix ownership ambiguous.
  • Enforced in: scs-resolve BFS stores predecessor map; scs-match extracts path at Finding construction; assertion finding.path.last() == root in tests.
  • Violation detection: unit test: construct graph with transitive dep, assert finding path length ≥ 2 and terminal element is root.
  • Telemetry: scs_finding_path_length_p99 histogram; alert if p99 > 64 (truncation happening).
  • Recovery: path truncated at 64 hops (configurable); log {component_purl, path_len=64, truncated=true} at WARN.
  • Debugging: scs resolve --dump-graph --dot > graph.dot → visualize with graphviz; trace BFS predecessor map.

7.6 SBOM Round-Trip Fidelity

  • Statement: parse(emit(sbom)) == sbom for all components, relationships, and non-lossy metadata fields.
  • Why: SBOMs are artifacts handed to compliance/legal/downstream tools; silent field loss invalidates them.
  • Enforced in: scs-sbom; round-trip property test per schema version (SPDX 2.3, CycloneDX 1.5/1.6).
  • Violation detection: proptest-driven round-trip: generate random Sbom, emit, parse, assert equality; golden-file tests for known SBOM samples.
  • Telemetry: none (pure in-process); violations caught in CI test.
  • Recovery: fix emitter or parser; schema field added → add test case; lossy field → document in code commentary.
  • Debugging: diff emit(sbom) vs emit(parse(emit(sbom))) as JSON/text; field mismatch pinpoints loss site.

7.7 Feed Freshness Recording

  • Statement: every ScanReport includes feed_snapshot: Vec<FeedRef> covering all advisory sources used; no scan produces a report with empty feed_snapshot (even in offline mode).
  • Why: without snapshot metadata, a report cannot be reproduced or audited; compliance requires "scan dated X used feed version Y".
  • Enforced in: scs-vulndb returns FeedRef with every query; scs-report asserts feed_snapshot.len() > 0 before writing output.
  • Violation detection: integration test: run scan, assert report.feed_snapshot non-empty; assert fetched_at parses as RFC3339.
  • Telemetry: scs_feed_age_seconds{source} gauge; alert policy: WARN if > 24 h, ERROR if > 72 h.
  • Recovery: expired cache → re-fetch; network unavailable → proceed with cached, log age warning; --require-fresh-feed flag rejects stale cache and exits non-zero.
  • Debugging: scs feed status subcommand prints feed refs, ages, and cache hit/miss per source.

7.8 No Silent Skipping of Withdrawn Advisories

  • Statement: a withdrawn advisory (Advisory.withdrawn.is_some()) is NEVER silently excluded from matching; it is matched and reported with vex_status = Withdrawn + withdrawn timestamp.
  • Why: silent exclusion means a previously reported CVE disappears without explanation; analysts lose audit trail.
  • Enforced in: scs-match match loop includes withdrawn advisories; Finding.vex_status set to Withdrawn; scs-policy may suppress display but never before match.
  • Violation detection: test: insert withdrawn advisory, run match, assert finding emitted with vex_status=Withdrawn.
  • Telemetry: scs_findings_total{vex_status=withdrawn} counter; unexpected drop → investigation.
  • Recovery: if advisory incorrectly flagged withdrawn → update feed; finding reappears on next scan.
  • Debugging: --include-withdrawn flag (default on) explicit; log advisory id + withdrawn timestamp at DEBUG.

7.9 Lockfile Primacy

  • Statement: when a lockfile is present, resolved versions come from the lockfile; manifest version ranges are never used as the sole source for matching.
  • Why: lockfile reflects actual deployed versions; manifest ranges are theoretical; matching against ranges produces false positives/negatives.
  • Enforced in: scs-manifest returns source: LockfileDerived vs source: ManifestDerived on each Component; scs-match emits WARN if matching against ManifestDerived versions.
  • Violation detection: integration test: project with both package.json and package-lock.json; assert all components have source = LockfileDerived.
  • Telemetry: scs_manifest_derived_components_total counter; high count → missing lockfile warning.
  • Recovery: instruct user to commit lockfile; --require-lockfile flag exits non-zero if lockfile absent.
  • Debugging: scs manifest --dump-components --format=json shows source field per component.

7.10 No Cross-Ecosystem Version Comparison

  • Statement: version comparisons are ALWAYS dispatched by Ecosystem enum; no comparison crosses ecosystem boundaries (e.g., no SemVer comparator applied to PEP 440 versions).
  • Why: SemVer pre-release ordering differs from PEP 440; cross-application silently produces wrong range results.
  • Enforced in: VersionComparator trait; match dispatch in scs-match uses advisory.ecosystem to select comparator; compile-time enum exhaustiveness.
  • Violation detection: unit tests: known cross-ecosystem confusions (e.g., 1.0.0-alpha ordering in SemVer vs PEP440) with expected outcome per ecosystem.
  • Telemetry: none (pure type-checked dispatch); violations caught at compile time + test.
  • Recovery: add new ecosystem arm to comparator dispatch; existing arms unchanged.
  • Debugging: scs match --explain --purl <purl> --advisory <id> prints which comparator was selected and the comparison result.

7.11 Input Size Enforcement

  • Statement: all file inputs (manifests, lockfiles, advisory feeds, SBOMs) are rejected with ScsError::InputTooLarge if they exceed configured limits (default 64 MiB per file).
  • Why: unbounded input enables OOM DoS of the scanner in CI; adversarial lockfile can exhaust runner memory.
  • Enforced in: scs-manifest and scs-sbom readers wrap file handles with take(max_bytes); scs-vulndb feed reader uses streaming parse with byte counter.
  • Violation detection: test: feed a 65 MiB synthetic lockfile; assert ScsError::InputTooLarge returned, not panic.
  • Telemetry: scs_input_size_bytes{type=manifest|lockfile|feed|sbom} histogram; scs_input_rejected_total counter.
  • Recovery: operator increases limit via scs.toml config [limits] max_input_bytes; audit log records override.
  • Debugging: error includes {file_path, actual_bytes, limit_bytes} in structured error payload.

7.12 Dependency Graph Acyclicity After Dedup

  • Statement: after scs-resolve deduplication and version unification, the DependencyGraph MUST be a DAG (no cycles in the resolved graph); cycles in the raw constraint graph are detected and reported before resolution.
  • Why: cycle in resolved graph breaks topological sort used for BFS path finding; Tarjan's algorithm hangs on true cycles.
  • Enforced in: scs-resolve runs Tarjan SCC post-dedup; SCC size > 1 → ScsError::CycleDetected { members: Vec<Purl> }; resolution aborts.
  • Violation detection: test: construct synthetic circular dependency; assert CycleDetected error; assert no Finding emitted for cycle members.
  • Telemetry: scs_cycle_detected_total{ecosystem} counter; alert (cycles are unusual; indicate malformed lockfile or resolver bug).
  • Recovery: report cycle to user with member purls; user must fix lockfile or exclude cyclic workspace member.
  • Debugging: scs resolve --dump-graph --dot + graphviz to visualize SCC; cycle members highlighted.

7.13 Policy Gate Atomicity

  • Statement: the policy gate decision (pass / fail) is computed from the complete set of Findings; it is never emitted until all phases (manifest, resolve, sbom, match, provenance, threat) are complete.
  • Why: partial gate decision on incomplete Findings could produce false pass if a later phase would have produced fail.
  • Enforced in: scs-cli pipeline: all phases run to completion (or controlled error); scs-policy is the final stage; early-exit only on unrecoverable errors, never on partial completion.
  • Violation detection: integration test: inject advisory matching only a transitive dep discovered late in resolve; assert gate decision reflects it.
  • Telemetry: scs_gate_decision{result=pass|fail|error} counter; scs_phase_completion{phase} gauge.
  • Recovery: phase error → gate emits error decision (non-zero exit 2); never silently emits pass on incomplete scan.
  • Debugging: --verbose flag prints phase completion timestamps; partial scans show which phase errored.

7.14 Purl Canonicalization Stability

  • Statement: Purl::from_component(c) produces the same string for the same logical package across all scan runs and all ecosystems; no two distinct logical packages map to the same purl.
  • Why: non-canonical purl breaks cross-scan deduplication, advisory correlation, and SBOM component identity.
  • Enforced in: scs-core Purl constructor validates against purl-spec regex; lowercase-normalizes scheme + type; encodes qualifiers in sorted order.
  • Violation detection: unit tests for each ecosystem purl generator; round-trip test parse(purl.to_string()) == purl.
  • Telemetry: scs_purl_parse_error_total{ecosystem} counter; spike indicates parser regression.
  • Recovery: purl format bug → fix generator; existing SBOMs may need re-emission; log migration warning.
  • Debugging: scs manifest --dump-purls prints canonical purl per component; diff against expected for regression.
