3. Architectural Overview

3.1 Canonical Data-Flow Diagram

    project manifests/lockfiles (package.json, Cargo.lock, go.sum, pom.xml, requirements.txt)
            |
      [scs-manifest] parse per-ecosystem -> Components (purl, version, hashes)
            |
      [scs-resolve] transitive dependency graph (constraint solve, dedup, cycles, dev/prod scopes)
            |
            +--> [scs-sbom] emit/ingest SPDX / CycloneDX inventory
            |
      [scs-match] <---- [scs-vulndb] (OSV / NVD / GHSA feeds, per-ecosystem version-range index)
            |  version-range satisfiability -> Findings (component x advisory + dep path)
            |
      [scs-provenance] verify Sigstore/cosign signatures, in-toto/SLSA attestations, Rekor inclusion, hash pinning
      [scs-threat]     typosquatting / dependency confusion / install-script + obfuscation heuristics
            |
      [scs-policy] severity thresholds + SPDX license + VEX + waivers -> gate (pass/fail)
            |
      [scs-report] SARIF / JSON / table, SBOM diff, CI exit codes

3.2 scs-manifest — Parse Boundary

  • Responsibility: ingest project root (or explicit paths), detect manifest/lockfile types, parse per-ecosystem into Vec<Component>
  • Ecosystems: npm (package.json + package-lock.json/yarn.lock/pnpm-lock.yaml), Cargo (Cargo.toml + Cargo.lock), PyPI (requirements.txt, Pipfile.lock, poetry.lock, pyproject.toml), Go (go.mod + go.sum), Maven (pom.xml), Ruby (Gemfile + Gemfile.lock)
  • Trust boundary: all inputs treated as adversarial; parsers use serde-based deserializers, never eval/exec; malformed inputs return ScsError::ParseError, never panic
  • Purl generation: deterministic mapping from (ecosystem, name, version) → canonical pkg:<ecosystem>/<name>@<version>
  • Lockfile-vs-manifest reconciliation: detect lockfile staleness (manifest constraint not satisfiable by locked version); flag as Finding::LockfileStale
  • Hash extraction: SHA-256/SHA-512 from lockfiles where available; forwarded to scs-provenance for pinning checks
  • Concurrency: parsers run in parallel via rayon across detected manifests (bounded thread pool, MAX_PARSE_THREADS=8)
  • Output: Vec<Component> + ManifestMeta { ecosystem, manifest_path, lockfile_path, parsed_at }

3.3 scs-resolve — Graph Construction

  • Responsibility: build DependencyGraph (DAG) from Vec<Component> + manifest-declared constraints; compute transitive closure; classify scope
  • Algorithm: BFS from root components; version-constraint resolution against declared ranges; dedup by (purl, version) identity
  • Cycle detection: DFS with grey/black coloring; cycles in DAG are ScsError::CyclicDependency (some ecosystems permit cycles in dev deps)
  • Scope classification: Scope::Prod / Scope::Dev / Scope::Optional; scopes propagate transitively (prod dep of dev dep → dev)
  • Dedup: multiple paths to same (purl, version) → single Component node, all inbound edges retained for path completeness
  • Output: DependencyGraph { roots: Vec<Purl>, nodes: HashMap<Purl, Component>, edges: Vec<(Purl, Purl, Scope)> }
  • Invariant: graph is a DAG post-cycle-removal; every node reachable from at least one root; path to root calculable via reverse-BFS

3.4 scs-sbom — SBOM Boundary

  • Responsibility: emit DependencyGraph as SPDX 2.3 or CycloneDX 1.5/1.6; parse external SBOMs into Vec<Component> for downstream matching
  • SPDX emit: SPDXDocument { packages, relationships (DESCRIBES/DEPENDS_ON/CONTAINS), snippets, annotations }
  • CycloneDX emit: BOM { metadata, components, dependencies, compositions }
  • Round-trip invariant: emit-then-parse preserves all Component fields + relationship topology (tested by scs-bench fixture corpus)
  • Protocol boundary: SBOM files are the inter-process boundary in pipelines; format versioning enforced at parse
  • SBOM ingestion: accept external SBOMs as primary input (bypasses scs-manifest + scs-resolve); feeds directly into scs-match
  • Hashes: SHA-256 and SHA-512 per component; required for provenance cross-check

3.5 scs-vulndb — Advisory Index

  • Responsibility: sync OSV JSON feed, NVD CVE API v2, GHSA GraphQL API; normalize to Advisory; build per-ecosystem range index
  • Feed sources: OSV (osv.dev/v1/...), NVD (services.nvd.nist.gov/rest/json/cves/2.0), GHSA (api.github.com/graphql)
  • Normalization: map all to Advisory { id, aliases, affected: Vec<AffectedRange>, severity: Cvss, fixed_versions, withdrawn }
  • AffectedRange semantics: half-open [introduced, fixed) — introduced is the first vulnerable version, fixed is the first non-vulnerable
  • Per-ecosystem index: HashMap<Ecosystem, BTreeMap<PackageId, Vec<Advisory>>> — O(log n) lookup by name
  • CVE↔GHSA↔OSV correlation: alias graph; a single vulnerability may have entries in all three; deduplicated by primary ID
  • Feed freshness: every sync records FeedSnapshot { source, fetched_at, entry_count, digest } — stored alongside index
  • Persistence: SQLite (via rusqlite) or flat JSON files; configurable; advisory index is append-only per snapshot
  • Concurrency: feed sync is async (tokio); reads are concurrent; writes are single-writer per source

3.6 scs-match — Matching Engine

  • Responsibility: for each Component in DependencyGraph, query scs-vulndb index, evaluate version-range satisfiability, emit Vec<Finding>
  • Version-range satisfiability: per-ecosystem dispatch — SemVer ranges, PEP 440 specifiers, Maven version ranges, Go pseudo-version ordering
  • Half-open range check: introduced <= version < fixed; inclusive last_affected semantics handled explicitly
  • Soundness invariant: any component version inside an AffectedRange is ALWAYS reported; no suppression except via VEX/waiver
  • Path inclusion: every Finding carries path: Vec<Purl> — shortest dependency chain from component to a graph root (BFS reverse)
  • Withdrawn/disputed: Advisory.withdrawn → Finding.vex_status = Disputed; still reported, never silently dropped
  • EPSS integration: if EPSS score available, attached to Finding.epss; used in severity ranking, never for suppression
  • Output: Vec<Finding> sorted by (severity DESC, purl ASC) for deterministic ordering

3.7 scs-provenance — Signature Verification

  • Responsibility: verify Sigstore/cosign signatures, in-toto link/layout attestations, SLSA provenance predicates, Rekor transparency log inclusion, hash pinning
  • Sigstore: verify ECDSA-P256/Ed25519 signatures against Fulcio-issued certificates; check Rekor inclusion proof (Merkle path verification)
  • in-toto: parse link.json and layout.json; verify step signatures + threshold; validate material/product hashes
  • SLSA: extract provenance predicate from in-toto attestation; classify as SLSA Level 0–3 per spec
  • Rekor: gRPC or REST query to rekor.sigstore.dev; verify inclusion proof (Merkle consistency proof against checkpoint)
  • Hash pinning: compare Component.hashes (from lockfile) against registry-fetched hashes and/or attestation hashes; mismatch → Finding::HashMismatch
  • Fail-closed invariant: any verification failure → Provenance.verified = false → Finding::ProvenanceFailed; never treated as verified
  • Trust boundary: external: Rekor TLS + certificate transparency; internal: verified attestation objects only

3.8 scs-threat — Heuristics Layer

  • Responsibility: statically detect supply-chain attack patterns without executing code
  • Typosquatting: edit-distance (Levenshtein ≤ 2) + homoglyph substitution against popular-package name list per ecosystem
  • Dependency confusion: detect internal/scoped package names (e.g., @company/pkg) published on public registries at higher versions
  • Install-script detection: parse package.json.scripts.{preinstall,install,postinstall}; flag shell commands, network calls, eval patterns
  • Obfuscation/entropy: Shannon entropy of install-script content; base64-encoded payloads; Buffer.from(...,'hex') patterns
  • Maintainer/age signals: package age < 7 days + first publish + install scripts = high suspicion; requires registry metadata (fetched at feed sync, not scan time)
  • Output: Vec<Finding> with FindingKind::ThreatHeuristic { signal, confidence }; confidence score 0.0–1.0

3.9 scs-policy — Gate Layer

  • Responsibility: apply user-defined policy to Vec<Finding> → PolicyDecision { pass: bool, blocked: Vec<Finding>, warnings: Vec<Finding> }
  • Policy inputs: Policy { severity_threshold, license_deny: Vec<SpdxExpr>, license_allow, vex_file: Option<Path>, waivers: Vec<Waiver> }
  • Severity threshold: findings at or above severity_threshold (CVSS 7.0 default) → block
  • SPDX license compliance: evaluate component License expression against deny/allow policy; copyleft detection
  • VEX consumption: OpenVEX or CSAF VEX; not_affected + justification → suppresses finding; affected + action_statement overrides
  • Waivers: Waiver { purl_pattern, advisory_id, expires, reason }; expired waivers → ScsError::WaiverExpired
  • Audit trail: every suppressed finding records suppression reason + waiver/VEX reference
  • Output: PolicyDecision + PolicyAuditLog { applied_rules, suppressions, gate_result }

3.10 scs-report — Output Layer

  • Responsibility: serialize (PolicyDecision, Vec<Finding>, DependencyGraph, Sbom) into target formats; set process exit code
  • SARIF 2.1: SarifLog { runs: [{ tool, results, artifacts }] }; location = manifest file + line where possible
  • JSON: canonical ScsReport { meta, findings, policy_decision, sbom_ref, feed_snapshot }
  • Table: human-readable terminal output via comfy-table; severity color-coding
  • SBOM diff: compare two SBOMs (e.g., before/after PR); emit added/removed/changed components
  • CI exit codes: 0 = pass, 1 = policy failure (blocked findings), 2 = scan error, 3 = stale feed warning
  • PR annotations: GitHub Actions / GitLab CI annotation format; maps findings to manifest file locations
  • Determinism: output ordering is stable (purl ASC, advisory_id ASC); timestamps excluded from hashed output

3.11 scs-cli — Orchestration Driver

  • Entry point: clap-based CLI; subcommands scan, sbom, db sync, db status, report diff, policy check
  • Configuration loading: scs.toml (project), ~/.config/scs/config.toml (user), env vars (SCS_*), CLI flags (precedence: CLI > env > project > user)
  • Pipeline orchestration: sequential phase execution with tokio for async I/O (feed sync, Rekor queries) and rayon for CPU-bound parsing/matching
  • Concurrency budget: --jobs flag controls rayon thread count; default = logical CPU count, max 16
  • Feed snapshot pinning: --snapshot <id> for reproducible offline scans; default = latest synced

8. Domain Model — Software Supply Chain Security

8.1 Core Entity Hierarchy

Project (workspace root)
  └─ Manifest (package.json, Cargo.toml, pom.xml, go.mod, requirements.txt, Gemfile)
       └─ Lockfile (package-lock.json, Cargo.lock, go.sum, poetry.lock, Gemfile.lock)
            └─ Component { purl, version, hashes, licenses, direct, scope }
                 └─ DependencyGraph { roots, edges: DAG<Purl> }
                      ├─ Finding { component, advisory, path, severity, vex_status }
                      │    └─ Advisory { id, aliases, affected: Vec<AffectedRange>, cvss }
                      ├─ Sbom (SPDX | CycloneDX)
                      └─ Provenance { attestation, slsa_level, rekor_inclusion, verified }

Entity invariants:

  • Every Component has exactly one canonical Purl; purl namespace + name are lowercase-normalized.
  • DependencyGraph is a DAG (cycles detected and broken during resolve; reported as warnings).
  • Every Finding has a non-empty path: Vec<Purl> from affected component to a root; min length = 1 (direct dep).
  • Advisory.withdrawn set → findings still emitted with vex_status: Disputed; never silently dropped.
  • AffectedRange uses half-open semantics [introduced, fixed); last_affected only used when fixed is absent.

8.2 Purl Canonical Form

EBNF:
  purl       = "pkg:" type "/" [namespace "/"] name ["@" version] ["?" qualifiers] ["#" subpath]
  type       = "npm" | "cargo" | "pypi" | "golang" | "maven" | "gem"
  namespace  = *(unreserved / pct-encoded / "/")
  name       = *(unreserved / pct-encoded)
  version    = *(unreserved / pct-encoded)

Normalization rules (enforced in scs-core::Purl::canonicalize):

Field Rule
type lowercase
namespace lowercase; empty string for npm unscoped, cargo, pypi
name npm: preserve case; cargo/pypi/gem: lowercase; maven: groupId/artifactId split
version strip leading v/V; pypi: normalize via PEP 440
qualifiers sorted by key, url-encoded values
subpath drop trailing /

Worked examples:

  • pkg:npm/%40types/node@20.1.0 — scoped npm package; namespace = @types
  • pkg:cargo/serde@1.0.190 — no namespace for Cargo
  • pkg:pypi/Django@4.2.7 — normalized to pkg:pypi/django@4.2.7
  • pkg:maven/org.springframework.boot/spring-boot-starter@3.1.0
  • pkg:golang/github.com/gin-gonic/gin@v1.9.1
  • pkg:gem/rails@7.1.0

Failure: malformed purl (missing pkg: scheme, empty name) → ScsError::InvalidPurl; reject at parse boundary; never propagate.

8.3 Version Model and Range Semantics

Three distinct version algebras used in matching:

Ecosystem Algebra Crate Example Range
npm, Cargo, Go (modules) SemVer (semver 1.0) semver >=1.2.3, <2.0.0
PyPI PEP 440 pep440 >=1.0.0,!=1.0.1,<2.0
Maven ComparableVersion custom [1.0,2.0)
Gem RubyGems (semver-like) rubygems-version ~> 1.2

Half-open range [introduced, fixed) mapping:

introduced=1.0.0, fixed=1.0.5:
  affected = {v | v >= 1.0.0 AND v < 1.0.5}
  edge case: v = 1.0.5 -> NOT affected (strictly less)
  edge case: introduced absent -> range starts at -∞ (any version)
  edge case: fixed absent, last_affected=1.0.4 -> affected = {v | v >= introduced AND v <= 1.0.4}

Multiple-range advisory (disjunction):

affected = range_A ∪ range_B
version v is affected iff ANY range in affected[] satisfies

OSV affected[].ranges schema fields → AffectedRange:

OSV field AffectedRange field Notes
introduced introduced "0" = beginning of time
fixed fixed exclusive upper bound
last_affected last_affected inclusive; only when fixed absent
limit (ignored) redundant with fixed in practice

PEP 440 exclusion clauses (!=1.0.1): materialized as gap in range; requires interval-difference logic.

Maven bracket notation: [1.0,2.0) → introduced=1.0, fixed=2.0; (,2.0] → no introduced, last_affected=2.0.

8.4 DependencyGraph State Machine

States a component traverses during scs-resolve:

          ┌─────────┐
  parse   │ PENDING │  component seen in manifest; version not yet resolved
  ───────>│         │
          └────┬────┘
               │ constraint solve
               ▼
          ┌──────────┐
          │ RESOLVED │  concrete version selected; purl finalized
          └────┬─────┘
               │ fetch metadata (hashes, licenses)
               ▼
          ┌──────────────┐
          │  ENRICHED    │  hashes + licenses populated
          └────┬─────────┘
               │ all transitive deps resolved
               ▼
          ┌──────────────┐
          │  GRAPH_BUILT │  DAG complete; topological order stable
          └──────────────┘

Cycle detection:

  • DFS with WHITE/GRAY/BLACK coloring during graph construction.
  • GRAY back-edge → cycle; break by treating target as already-RESOLVED; emit Finding::Diagnostic(CycleDetected).
  • Rust crates with [patch] sections can create virtual cycles; treat patch targets as roots.

Scope resolution rules:

Scope Included in prod scan Included in dev scan
Prod yes yes
Dev no yes
Optional no (unless --include-optional) yes

Deduplication: components with same purl but different resolved versions (duplicate subtree) → keep all, tag as duplicate: true; emit warning; report each finding independently (do not deduplicate findings).

8.5 Advisory Lifecycle and State

State machine for Advisory:
  ACTIVE     — published, affects active versions
  WITHDRAWN  — advisory retracted; findings still emitted, vex_status=Disputed
  DISPUTED   — CVE rejected/disputed; still emitted
  FIXED      — all affected ranges have `fixed` version; still matched for un-upgraded components

Feed ingestion state per advisory ID:

Event State transition
First fetch from OSV/NVD/GHSA NEW → INDEXED
Re-fetch, no change INDEXED (no-op)
Re-fetch, fields changed INDEXED → UPDATED; old snapshot retained
withdrawn timestamp set ACTIVE → WITHDRAWN
Alias mapping received ID linked to canonical ID

Advisory deduplication (aliasing):

  • OSV aliases[] field links CVE ↔ GHSA ↔ OSV IDs.
  • Canonical ID selection: CVE-YYYY-NNNNN preferred; GHSA-* if no CVE; OSV ID as fallback.
  • Match against canonical ID only; alias lookup returns same Advisory object.
  • Pitfall: NVD and GHSA may have different affected ranges for same CVE; merge strategy = union of ranges (conservative).

8.6 Vulnerability Matching Sequence

scs-match matching pipeline:

  DependencyGraph (GRAPH_BUILT)
       |
  [1] for each Component c in graph:
       |   ecosystem = c.purl.type
       |   purl_key  = (ecosystem, name, namespace)
       |   advisories = scs-vulndb::lookup_by_purl(purl_key)
       |
  [2] for each Advisory a in advisories:
       |   for each AffectedRange r in a.affected:
       |     if r.ecosystem == ecosystem:
       |       if version_satisfies(c.version, r):
       |         emit Finding { component=c, advisory=a, path=shortest_path(c) }
       |
  [3] apply VEX status from scs-policy::vex_lookup(c.purl, a.id)
       |   AFFECTED / NOT_AFFECTED / FIXED / UNDER_INVESTIGATION
       |
  [4] de-alias findings: merge findings with same canonical advisory ID
       |
  [5] rank by CVSS score (descending), then by path depth (ascending = closer to root first)

Sequence diagram — single component match:

scs-match          scs-vulndb          scs-policy
   |                   |                   |
   |-- lookup(purl) -->|                   |
   |<- [Advisory...] --|                   |
   | version_satisfies(v, range)?          |
   |-- vex_lookup(purl, cve_id) ---------->|
   |<- VexStatus ----------------------------
   | build Finding { vex_status }
   | emit via mpsc channel -> scs-report

Edge cases in matching:

  • Version 0.0.0 (unversioned): matches any range starting from introduced="0"; always flag.
  • Pre-release versions (e.g., 1.0.0-beta.1): SemVer pre-release < stable; >=1.0.0-alpha,<1.0.0 matches beta; verify semver crate pre-release semantics.
  • Yanked Cargo crates: resolved version is yanked → emit Finding::Diagnostic(YankedVersion) in addition to vuln findings.
  • CPE matching fallback: if purl lookup returns nothing, attempt CPE-based NVD lookup; lower confidence; tag matched_by: Cpe.

Malformed advisory examples that must not crash:

  • fixed before introduced (invalid range) → skip range, emit parse warning, continue.
  • Unknown ecosystem in affected → skip range for that ecosystem, continue matching other ranges.
  • Null CVSS score → severity = Unknown; still report finding.

8.7 Finding Model and Severity Ranking

// signatures only — not implementation
struct Finding {
    component: Component,
    advisory:  Advisory,
    path:      Vec<Purl>,      // dep chain: affected → ... → root
    severity:  Severity,
    fixed:     Option<Version>,
    vex_status: VexStatus,
    matched_by: MatchSource,   // Purl | Cpe | Heuristic
}

enum Severity { Critical, High, Medium, Low, Unknown }
enum VexStatus { Affected, NotAffected, Fixed, UnderInvestigation, None }
enum MatchSource { Purl, Cpe, Heuristic }

Severity mapping:

CVSS v3 Score Severity
9.0–10.0 Critical
7.0–8.9 High
4.0–6.9 Medium
0.1–3.9 Low
none/unavailable Unknown

EPSS integration: Finding carries optional epss_score: Option<f32> (0.0–1.0); policy engine can gate on EPSS > threshold.

Path computation:

  • BFS from affected component outward in reverse-dependency graph.
  • Shortest path selected for Finding.path; all paths available via --all-paths flag.
  • Path = [affected_purl, intermediate..., root_purl]; root = direct dep of project.
  • Direct dep: path length = 1; path = [affected_purl].

8.8 SBOM Domain Model

SPDX 2.3 / CycloneDX 1.5 both supported for emit and parse.

SPDX package record fields → Component mapping:

SPDX Field Component field Notes
SPDXID internal id format: SPDXRef-<purl-hash>
PackageName purl.name
PackageVersion version
ExternalRef: PACKAGE-MANAGER purl purl canonical purl
PackageChecksum hashes SHA-256 preferred
PackageLicenseConcluded licenses[0] SPDX expression
Relationship: DEPENDS_ON graph edge

CycloneDX component fields → Component:

CDX Field Component field
bom-ref internal id
purl purl
version version
hashes[].content hashes
licenses[].expression licenses
dependencies[].ref graph edges

Round-trip invariant: parse(emit(sbom)) == sbom for all components and relationships. Test fixture: reference SBOMs for known projects (lodash, numpy, serde) committed in scs-bench/fixtures/sbom/.

SBOM diff (scs-report):

  • Added components: in new SBOM, not in baseline.
  • Removed components: in baseline, not in new SBOM.
  • Version-changed: same purl name, different version.
  • New findings: findings for added/changed components not present in baseline findings.

8.9 Provenance and Sigstore Domain Model

Sigstore verification pipeline:

  Artifact (OCI image digest or source tarball hash)
       |
  [1] fetch Rekor transparency log entry by artifact hash
       |   Rekor entry: { logID, logIndex, body{ kind, spec }, integratedTime }
       |
  [2] verify Rekor inclusion proof (Merkle path from leaf to STH)
       |   failure → Provenance { verified: false, reason: RekorInclusionFailed }
       |
  [3] decode cosign bundle: { Signature, Certificate }
       |   Certificate: subject (email/OIDC), issuer (Fulcio CA), SAN
       |
  [4] verify certificate chain to Fulcio root CA
       |   failure → Provenance { verified: false, reason: CertChainFailed }
       |
  [5] verify signature over artifact digest using cert public key
       |   failure → Provenance { verified: false, reason: SignatureInvalid }
       |
  [6] verify certificate validity window ⊇ Rekor integratedTime
       |   (short-lived cert; keyless signing)
       |
  [7] check build OIDC claims: issuer = github-actions, repo = expected_repo
       |
  Provenance { attestation, slsa_level, rekor_inclusion: Some(entry), verified: true }

in-toto attestation fields → Provenance:

Field Meaning
_type https://in-toto.io/Statement/v0.1
subject[].digest.sha256 matches Component.hashes
predicateType SLSA provenance URI
predicate.builder.id CI identity (GitHub Actions, etc.)
predicate.buildConfig source of build inputs
predicate.materials[].uri upstream source refs

SLSA level determination:

Level Requirements
L0 no provenance
L1 provenance exists, not verified
L2 provenance hosted service, verified build
L3 hardened build, verified + Rekor inclusion

Failure modes:

  • Rekor network unreachable → fail-closed: verified=false, reason=RekorUnreachable; never assume verified.
  • Clock skew > 5 min between cert validity and integratedTime → fail; log skew delta.
  • OIDC issuer mismatch → fail; policy engine receives slsa_level=L0.
  • Missing cosign bundle → verified=false, reason=NoBundleFound.

Hash pinning (non-Sigstore provenance):

  • Lockfile hash (sha256/sha512) compared to Component.hashes.
  • Mismatch → Finding::Diagnostic(HashMismatch) with severity Critical.
  • Go go.sum dual hash (h1:sha256-of-zip + sha256-of-dir) → both verified.

8.10 Malicious Package Threat Model

Heuristics evaluated by scs-threat, each producing a ThreatSignal:

struct ThreatSignal {
    kind: ThreatKind,
    score: f32,       // 0.0–1.0 confidence
    evidence: String,
}

enum ThreatKind {
    Typosquatting,
    DependencyConfusion,
    SuspiciousInstallScript,
    ObfuscatedCode,
    MaintainerAnomaly,
    PackageAgeTooNew,
    UnusuallyHighDownloadSpike,
}

Typosquatting detection algorithm:

  1. Compute edit distance (Damerau-Levenshtein, threshold ≤ 2) between candidate package name and all packages in popular-package corpus.
  2. Also check: homoglyph substitution (0/O, 1/l, rn/m), hyphen/underscore swap, prefix/suffix addition (-util, -js, -py).
  3. Corpus: top-10,000 packages per ecosystem from download stats, updated weekly.
  4. Score = f(edit_distance, download_ratio_delta, age_delta).
  5. Pitfall: legitimate forks with similar names; output as signal, not automatic block; policy engine decides.

Dependency confusion detection:

  • Package exists in both public registry and private registry → confusion risk.
  • Detection: compare package name against internal namespace list (from --private-namespace config).
  • Version in lockfile > latest public version → strong signal (classic Birsan attack vector).
  • published_by different from expected org → signal.

Install script analysis:

  • Parse package.json::scripts.{preinstall,install,postinstall} for npm.
  • Parse setup.py cmdclass for PyPI.
  • Flag: shell exec (exec, eval, subprocess, child_process), network calls, file writes outside package dir, base64-decoded payloads.
  • High entropy string detection: Shannon entropy > 4.5 bits/char in string literals → flag.
  • Regex patterns for common obfuscation: String.fromCharCode, atob, eval(Buffer.from(...,'base64')).

Maintainer/age signals:

  • Package age < 7 days + direct dependency + no prior versions → high-risk signal.
  • Maintainer account age < 30 days + recent ownership transfer → signal.
  • Single-maintainer package suddenly transferring ownership → signal.
  • Source: registry metadata API (npm registry JSON, PyPI JSON API); fetched during enrichment phase.

Combination scoring (ensemble):

final_threat_score = weighted_sum(signals) / normalization_factor
threshold > 0.7 → ThreatKind::HighRisk finding
threshold 0.4–0.7 → ThreatKind::MediumRisk finding

8.11 Policy Engine Domain Model

Policy file schema (TOML, evaluated by scs-policy):

[policy]
fail_on_severity = "High"          # Critical | High | Medium | Low
fail_on_threat   = true
license_allow    = ["MIT", "Apache-2.0", "BSD-2-Clause", "BSD-3-Clause"]
license_deny     = ["GPL-3.0-only", "AGPL-3.0-only"]
max_epss         = 0.7             # gate if EPSS > 70%

[[ignore]]
advisory_id  = "GHSA-xxxx-yyyy-zzzz"
package      = "pkg:npm/lodash@4.17.21"
expires      = "2024-12-31"
reason       = "mitigated by WAF rule"

[[vex]]
advisory_id  = "CVE-2023-12345"
package      = "pkg:cargo/openssl@0.10.55"
status       = "not_affected"
justification = "vulnerable_code_not_in_execute_path"

Policy evaluation order (short-circuit):

1. VEX status check → if NotAffected, skip further evaluation (not a failure)
2. Waiver/ignore check → if active waiver, mark ignored, continue (no failure)
3. Severity threshold → if Finding.severity >= fail_on_severity → FAIL
4. EPSS threshold → if epss_score > max_epss → FAIL
5. License deny list → if any Component.license ∈ license_deny → FAIL
6. Threat score → if threat_score > threshold AND fail_on_threat → FAIL
7. All checks pass → PASS

Gate decision state machine:

GateState: PASS | FAIL | WARN
- Start: PASS
- Any FAIL trigger → FAIL (sticky; does not revert)
- Ignored finding → WARN (does not cause FAIL unless all findings ignored and --strict-ignores)
- Final: GateState determines exit code (0=PASS, 1=FAIL, 2=ERROR)

License compliance:

  • SPDX expression parsing: MIT AND Apache-2.0, GPL-2.0-or-later OR MIT, LicenseRef-custom.
  • Copyleft detection: any expression containing GPL/AGPL/EUPL/OSL → flag.
  • Unknown license → configurable: warn or fail.
  • Dual-license: if ANY branch of OR expression is in allow list → allowed (permissive interpretation).

8.13 Feed Snapshot and Determinism Model

Feed snapshot: every scan records:

struct FeedSnapshot {
    osv_fetched_at:  DateTime<Utc>,
    nvd_fetched_at:  DateTime<Utc>,
    ghsa_fetched_at: DateTime<Utc>,
    osv_schema_version: String,
    total_advisories: u64,
    snapshot_hash: [u8; 32],  // SHA-256 of sorted advisory IDs + modified timestamps
}

Determinism invariant:

  • scan(inputs, snapshot_A) == scan(inputs, snapshot_A) always (same snapshot, same inputs).
  • scan(inputs, snapshot_A) != scan(inputs, snapshot_B) allowed if new advisories added.
  • Output includes snapshot_hash for auditability; CI can pin snapshot for reproducible checks.

Feed sync modes:

Mode Behavior
--offline use local cache only; fail if cache absent
--update sync feeds before scan; update local SQLite
--snapshot <hash> use exact snapshot by hash; fail if not cached
default use latest cached; warn if older than 24h

Local advisory cache: SQLite database at $XDG_CACHE_HOME/scs/advisories.db; schema in scs-vulndb.

8.14 Error Domain

enum ScsError {
    InvalidPurl(String),
    ManifestParse { path: PathBuf, cause: String },
    LockfileNotFound { manifest: PathBuf },
    AdvisoryFeedFetch { url: String, status: u16 },
    AdvisoryFeedParse { source: AdvisorySource, cause: String },
    VersionParse { purl: Purl, raw: String },
    RangeParse { advisory: String, raw: String },
    ProvenanceVerification { purl: Purl, reason: ProvenanceError },
    SbomParse { format: SbomFormat, cause: String },
    PolicyParse { path: PathBuf, cause: String },
    CycleDetected { component: Purl },
    HashMismatch { purl: Purl, expected: String, actual: String },
    RekorUnreachable { url: String },
    Io(std::io::Error),
}

Error propagation:

  • ManifestParse → recoverable; skip that manifest, continue with others; aggregate errors in final report.
  • AdvisoryFeedFetch → if --offline flag absent, treat as ScsError → exit code 2; if --offline, silently use cache.
  • ProvenanceVerification → fail-closed always; never demote to warning; Finding emitted regardless.
  • CycleDetected → non-fatal; graph construction continues; finding emitted as Diagnostic.
