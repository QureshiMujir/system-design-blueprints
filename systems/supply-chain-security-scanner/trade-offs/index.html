Decisions (§9) · 30 ADRs

ADR-001

Implementation language

Chosen

Rust (edition 2021, MSRV 1.78)

Rejected

Go (Trivy/Grype precedent), Python, Java

When the rejected choice is right

Go wins when matching the Trivy/Grype ecosystem and contributor familiarity outweigh parse-safety; Python wins for a quick prototype reusing pip/packaging internals directly

Why: Safe parsing of untrusted manifests; zero-cost graph algorithms; native crypto; reproducible binaries; no GC pauses in hot matching loops

ADR-002

Build system

Chosen

Cargo workspace (11 crates)

Rejected

Bazel, Buck2, plain Makefile

When the rejected choice is right

Bazel wins for polyglot monorepos needing hermetic, remote-cached builds across many languages

Why: Native Rust toolchain; workspace-level test/bench/lint; no extra toolchain dep; cargo xtask for auxiliary scripts

ADR-003

Async runtime

Chosen

Tokio 1.x (multi-thread scheduler)

Rejected

async-std, smol, blocking threads

When the rejected choice is right

Blocking threads win for a purely local scan with no network feeds, where a simple thread pool beats async machinery

Why: Feed fetch + registry API calls are I/O-bound; Tokio ecosystem (reqwest, tokio-postgres) widest; multi-thread for parallel matching

ADR-004

HTTP client

Chosen

reqwest (Tokio + rustls)

Rejected

hyper directly, ureq, curl-sys

When the rejected choice is right

hyper-directly wins when you need fine-grained control of connection lifecycle or HTTP/2 features reqwest abstracts away

Why: Async; rustls avoids OpenSSL linking; connection pooling; redirect handling; used in scs-vulndb + scs-provenance

ADR-005

TLS stack

Chosen

rustls 0.21+

Rejected

OpenSSL/openssl-sys, native-tls

When the rejected choice is right

OpenSSL/native-tls wins when FIPS-validated crypto or the OS system trust store / hardware engines are mandated

Why: Pure Rust; no system OpenSSL dep; reproducible; no linking complexity in CI; acceptable perf

ADR-006

CLI framework

Chosen

clap 4.x (derive API)

Rejected

argh, structopt (deprecated), pico-args

When the rejected choice is right

pico-args wins when binary size and compile time dominate and the CLI surface is tiny

Why: Rich help generation; subcommand support; shell completions; env-var override integration

ADR-007

Serialization (JSON/YAML/TOML)

Chosen

serde + serde_json + serde_yaml + toml

Rejected

quick-xml only, nom-based parsers

When the rejected choice is right

A hand-written nom parser wins for one high-throughput binary format where serde reflection overhead is measurable

Why: Universal derive macro; zero-copy where possible; TOML for policy files; YAML for SPDX; JSON for SARIF/OSV/CycloneDX

ADR-008

Advisory cache / local DB

Chosen

SQLite via rusqlite

Rejected

Postgres, DuckDB, flat JSON files, RocksDB

When the rejected choice is right

Postgres wins when one advisory index is shared by many concurrent scanner instances needing a central server; RocksDB wins for write-heavy LSM ingest

Why: Embedded; zero server dep; fast purl-range index queries; acceptable for millions of advisories; FTS5 for text search

ADR-009

SemVer parsing + constraint

Chosen

semver 1.0 crate

Rejected

custom parser, node-semver port

When the rejected choice is right

A custom/node-semver port wins when you must reproduce a package manager's non-standard range quirks the crate refuses to model

Why: Canonical Rust ecosystem SemVer; range satisfiability tested; SemVer npm quirks handled via normalization layer

ADR-010

PEP 440 version handling

Chosen

custom pep440 crate (in-tree)

Rejected

packaging-py via FFI, pyo3

When the rejected choice is right

pyo3/packaging wins when a Python runtime is already embedded and exact CPython-parity behaviour is required

Why: No Python runtime dep; PEP 440 spec complex (epoch, post, dev); own impl avoids FFI overhead + safety boundary

ADR-011

Crypto (hashing)

Chosen

sha2 + sha3 crates (RustCrypto)

Rejected

ring, openssl-sys

When the rejected choice is right

ring wins when you need its assembly-optimized throughput and constant-time guarantees on a hashing-heavy hot path

Why: Pure Rust; no C FFI; audited by RustCrypto; covers SHA-256/SHA-512/SHA-3 needed for SBOM hashes

ADR-012

Sigstore/cosign verification

Chosen

sigstore-rs (SigStore Rust SDK)

Rejected

reimplementing Rekor/Fulcio client from scratch, calling cosign binary via subprocess

When the rejected choice is right

Subprocess cosign wins when you must track cosign's bleeding-edge features faster than the SDK ships them

Why: Native Rust; avoids subprocess + PATH dep; correctness maintained by upstream SDK; Rekor Merkle proof in-library

ADR-013

in-toto attestation parsing

Chosen

in-toto crate / custom DSSE parser

Rejected

calling in-toto-run binary

When the rejected choice is right

The reference in-toto-run binary wins when it is the compliance-required oracle for attestation verification

Why: No binary dep; DSSE envelope parse + verify is tractable in Rust; reduces attack surface

ADR-014

ADR-028

Parallel scan execution

Chosen

Rayon (data parallel) for graph matching + Tokio (I/O) for feed/network

Rejected

pure Tokio threadpool, single-thread

When the rejected choice is right

Pure Tokio wins for an entirely I/O-bound workload with little CPU matching; single-thread wins for tiny scans where parallelism overhead dominates

Why: Rayon for CPU-bound matching across large graphs; Tokio for I/O-bound feed sync; two-tier concurrency model

ADR-029

SBOM format selection

Chosen

Both SPDX 2.3 + CycloneDX 1.5 (configurable default)

Rejected

SPDX only, CycloneDX only

When the rejected choice is right

A single format wins when the consuming toolchain is locked to exactly one of SPDX or CycloneDX and dual emit is wasted effort

ADR-030

Vulnerability severity normalization

Chosen

CVSS v3.1 primary; CVSS v2 fallback; NVD v3.1 preferred over GHSA

Rejected

EPSS-only ranking, severity enum without score

When the rejected choice is right

EPSS-only ranking wins when prioritizing by real-world exploitation probability matters more than nominal severity; an enum-only score wins for a coarse pass/fail gate

Why: CVSS v3.1 most widely available; EPSS supplemental only (predictive, not prescriptive); NVD authoritative CVSS source

Alternative Architectures (Roads Not Taken)

Alt-A — Reachability-first scanner (call-graph gated).

deps --build call graph--> [ keep only findings whose vulnerable symbol is reachable ] --> report

Wins when: alert fatigue is the dominant problem and the languages have tractable static call graphs (Java, Go). Embodied by: Endor Labs, Snyk reachability. Rejected (as default) because: call-graph construction is language-specific and incomplete, so gating on it risks false negatives (violates MM4); reachability is used to re-rank, not suppress (MM5), and the heavier analysis is deferred.

Alt-B — Continuous SaaS monitoring service.

repos --webhook--> [ hosted service: re-scan on push, open fix PRs ] --> dashboard

Wins when: teams want zero local setup, continuous monitoring, and automated remediation PRs. Embodied by: Snyk, GitHub Dependabot. Rejected because: the blueprint targets a deterministic, offline-capable CLI/CI binary (MM9) with no proprietary feed or server dependency, so scans are reproducible and air-gappable.

Alt-C — SBOM-only (generate, don't match).

project --> [ enumerate components ] --> SBOM (SPDX/CycloneDX); matching is someone else's job

Wins when: you want a clean separation of inventory from policy, feeding SBOMs into a separate vulnerability service. Embodied by: Syft. Rejected because: the product goal is end-to-end find→match→prioritize→report; SBOM generation is one stage (§15), not the whole tool, though SBOM ingestion lets it interoperate with Syft-style producers.

Alt-D — OS/container-package-first scanner.

image --extract layers--> [ match OS packages (deb/rpm/apk) against distro CVEs ] --> report

Wins when: the primary risk surface is the base image and OS packages, not language dependencies. Embodied by: Trivy, Grype. Rejected (deferred) because: this blueprint focuses on application-dependency provenance and malicious-package detection; OCI image-layer scanning is captured in the Deferred Features Register.
