Hard questions

  1. Why does matching on package name alone produce wrong-ecosystem false positives, and what fixes it? (MM1 + §17 + §8)
  2. Why must the scanner read the lockfile rather than the manifest when both exist? (MM3 + §13 + §14)
  3. Why is "0 false negatives for in-range versions" a hard invariant while false positives are tolerable? (MM4 + §4.1 + §4.4)
  4. How is "version V in range R" decided differently for npm, PyPI, and Maven? (MM2 + ADR-009/ADR-010 + §17)
  5. Why can reachability re-rank but not suppress a finding by default? (MM5 + MM4 + §18)
  6. Trace a provenance verification from signature to SLSA level, naming each link and its failure mode. (MM6 + §19 + §4.4 Rekor timeout)
  7. What ground truth does typosquatting detection require, and what false positive appears without it? (MM7 + §20 + Capacity model)
  8. Why is a stale advisory feed the most dangerous failure mode, and how is it surfaced? (MM8 + §16 + §4.1)
  9. Why is bit-identical output a feature, and which two workflows depend on it? (MM9 + §22 + §23)
  10. What does the purl-keyed index buy over naive matching at 5 K deps × ~1 M advisories? (MM1 + Capacity C3 + §17)

Mental Models & First Principles

The compressed insights an expert in supply-chain security holds. Each predicts a bug class. Every cited § resolves to a real heading.

MM1. A purl is the join key of the entire system. Package identity is pkg:type/namespace/name@version; every correlation (manifest ↔ advisory ↔ SBOM ↔ provenance) joins on it. Predicts: correct cross-database (OSV/NVD/GHSA) matching. Bug without it: matching on bare name → flagging the npm lodash advisory against the PyPI lodash, a wrong-ecosystem false positive. Applied: §8 (purl model), §14 (purl generation), §17 (CVE↔GHSA↔OSV correlation).

MM2. Vulnerability matching is version-range satisfiability, not string equality. "Is version V inside range R?" must be evaluated under the ecosystem's own ordering (SemVer, PEP 440, Maven). Predicts: correct match across npm ^/~, PEP 440 epochs, Maven ranges. Bug without it: lexical comparison says 1.10.0 < 1.9.0 and misses a vulnerable version. Applied: §17 (range satisfiability), ADR-009/ADR-010, §8 domain.

MM3. A lockfile is truth; a manifest is intent. When a lockfile exists, scan the resolved versions, not the declared ranges. Predicts: accurate findings for what actually ships. Bug without it: scanning the declared ^1.0.0 range either over-reports (every matching CVE) or under-reports (misses the resolved 1.2.3). Applied: §13 (lockfile reconciliation), §14 (dependency resolution), MM1.

MM4. Soundness beats completeness: zero false negatives for in-range versions is the hard invariant. A false positive wastes triage time; a false negative ships a vulnerability. Predicts: the property-based matching tests (§4.1 "Match soundness"). Bug without it: tuning the matcher to suppress noisy alerts and silently dropping a real in-range hit. Applied: §4.1 (match soundness), §17 (matching engine), §4.4 failure budget.

MM5. Reachability is the precision lever, not the detection gate. A vulnerable symbol present in the graph is not the same as called; reachability re-ranks, it must not suppress by default (MM4). Predicts: lower noise without sacrificing soundness. Bug without it: using reachability as a hard filter and dropping a finding whose call path the analysis missed. Applied: §18 (severity + reachability), Alternative Architectures, MM4.

MM6. Provenance is a chain you verify, not a flag you trust. Signature (Sigstore) + transparency-log inclusion (Rekor) + attestation (in-toto/DSSE) + SLSA level — each link checked. Predicts: resistance to forged or self-asserted attestations. Bug without it: trusting an attestation's claims without verifying its Rekor inclusion proof → accepting a fabricated provenance. Applied: §19 (provenance + signature verification), ADR-012/ADR-013.

MM7. Name-based attacks need a popularity corpus. Typosquatting is edit-distance against popular names; dependency confusion is internal/public namespace ambiguity. Predicts: detection requires the top-N package list as ground truth. Bug without it: flagging every new low-download package as a typosquat → false-positive flood. Applied: §20 (malicious-package detection), §4.2 (aho-corasick), Capacity model.

MM8. The advisory feed is a cache with a freshness SLA. A stale feed produces silent false negatives — the worst failure mode. Predicts: the need to surface StaleFeed as a first-class finding (§4.1). Bug without it: scanning against a 2-week-old feed and reporting "clean" while CVEs published yesterday go unseen. Applied: §16 (advisory ingestion), §4.1 (feed freshness SLA), §4.4.

MM9. Determinism is a feature, not a nicety. Identical inputs + identical advisory snapshot must yield bit-identical output (no timestamps, no random ordering). Predicts: clean CI diffs, stable baselines, delta scans. Bug without it: nondeterministic finding order makes every CI run a noisy diff and breaks baseline suppression. Applied: §4.1 (determinism), §22 (reporting + baseline), §23 (incremental/caching).

MM10. The SBOM is the inventory contract; conversion must be lossless. SPDX ↔ CycloneDX round-trips must preserve every component and relationship. Predicts: the 100% round-trip fidelity invariant (§4.1). Bug without it: a lossy SPDX→CycloneDX conversion drops a transitive component and a downstream scan misses it. Applied: §15 (SBOM generation/ingestion), ADR-029, §4.1 fidelity invariant.

Glossary · 46 terms · site-wide glossary

Advisory
Structured record (CVE/GHSA/OSV) describing a vulnerability in one or more package versions; contains AffectedRange list, CVSS score, fixed versions, aliases.
AffectedRange
Half-open interval [introduced, fixed) within a single ecosystem; a component version v is affected iff introduced <= v < fixed (or v >= introduced when fixed is absent).
Attestation
Signed metadata artifact (in-toto DSSE envelope) asserting facts (build provenance, test results, SLSA level) about a software artifact; verified by scs-provenance.
CAPEC
Common Attack Pattern Enumeration and Classification; referenced as weakness classification alongside CWE in enriched advisories.
Component
Single versioned package node in the dependency graph: { purl, version, hashes, licenses, source, direct: bool, scope: Scope }. Unit of analysis for vuln-matching and provenance.
Cosign
Sigstore CLI + Go library for signing OCI artifacts and publishing signatures to Rekor; referenced as external verifier by scs-provenance.
CPE
Common Platform Enumeration; NVD-native identifier (cpe:2.3:a:vendor:product:version:...); mapped to purl for matching in scs-vulndb.
CVSS
Common Vulnerability Scoring System (v3.1/v4.0); base/temporal/environmental scores on 0.0–10.0 scale; drives Severity enum thresholds in scs-policy.
CVE
Common Vulnerabilities and Exposures identifier (CVE-YYYY-NNNNN); canonical vuln ID issued by MITRE/CNAs; aliased by GHSA and OSV records.
CycloneDX
SBOM standard (OWASP); JSON/XML schema for component inventory, vulnerabilities, licenses, dependencies; supported as emit/parse target in scs-sbom.
Dependency Confusion
Attack (Birsan 2021): attacker publishes a package to a public registry with the same name as a private internal package at a higher version number, causing package managers to prefer it. Detected by scs-threat via registry-origin checks.
DependencyGraph
DAG of Component nodes with typed edges; { roots, edges, scopes }; constructed by scs-resolve; iterated by scs-match + scs-provenance.
DSSE
Dead Simple Signing Envelope (sigstore spec); JSON envelope { payload, payloadType, signatures }; wraps in-toto Link/Layout attestations.
Ecosystem
Package registry namespace: cargo, npm, pypi, go, maven, gem; determines version-comparison semantics and advisory range format.
EPSS
Exploit Prediction Scoring System; 0.0–1.0 probability that a CVE will be exploited in the wild within 30 days; supplements CVSS for prioritization in scs-policy.
Feed Snapshot
Immutable, timestamped advisory dataset used for a scan run; identified by (source, etag/commit, timestamp); stored in scs-vulndb metadata; required for scan reproducibility.
Finding
Output unit: { component, advisory, path: Vec<Purl>, severity, fixed: Option<Version>, vex_status }; carries full dep-chain to graph root.
Fulcio
Sigstore CA that issues short-lived OIDC-bound code-signing certificates; certificates embedded in Sigstore signatures; verified via Rekor CT log.
GHSA
GitHub Security Advisory; GitHub's advisory namespace (GHSA-xxxx-yyyy-zzzz); aliases CVE; primary feed source alongside OSV for scs-vulndb.
Hash Pinning
Manifest-declared sha256/sha512 expected digest for a downloaded artifact; scs-manifest parses and scs-provenance verifies against actual fetched content.
in-toto
Supply-chain integrity framework (Torres-Arias 2019); defines Link (step evidence) and Layout (policy) metadata types; scs-provenance verifies in-toto attestation chains.
License
SPDX license expression (e.g., MIT, GPL-2.0-or-later, Apache-2.0 OR MIT); parsed per component; evaluated against allow/deny lists in scs-policy.
Lockfile
Deterministic, fully-resolved package manifest (e.g., Cargo.lock, package-lock.json, go.sum); preferred input for scs-manifest; preferred over loose manifests for reproducibility.
Manifest
Human-authored dependency declaration (Cargo.toml, package.json, requirements.txt); may contain version ranges; less precise than lockfile.
Malicious Install Script
preinstall/postinstall (npm), setup.py hooks, build.rs anomalies that exfiltrate data or download payloads at install time; detected by scs-threat via static script analysis.
Match Soundness
Invariant: every Component version that falls inside an advisory's AffectedRange is reported as a Finding; false negatives are defects.
OSV
Open Source Vulnerability schema (Google); normalized JSON format unifying GHSA/CVE/PyPA/RustSec/etc.; primary feed format for scs-vulndb.
PackageId
{ ecosystem: Ecosystem, name: String }; canonical identifier stripped of version; used as index key in advisory lookups.
PEP 440
Python version specifier standard; defines epochs, pre/post/dev releases, and version operators (>=, ~=, !=, ===); implemented in scs-resolve/scs-match for PyPI.
Policy
Declarative configuration (TOML) in scs-policy; contains severity thresholds, license allow/deny, VEX paths, waiver list, EPSS cutoffs, SLSA level requirements; produces gate decision.
Provenance
Metadata proving where and how an artifact was built: { attestation, slsa_level, rekor_inclusion, verified: bool }; fail-closed invariant.
Purl
Package URL (purl spec): pkg:<type>/<namespace>/<name>@<version>?<qualifiers>#<subpath>; canonical cross-ecosystem component identifier used throughout as primary key.
Rekor
Sigstore's transparency log (Merkle tree); stores signature/attestation entries; scs-provenance verifies inclusion proofs via rekor-rs or REST API.
SARIF
Static Analysis Results Interchange Format (OASIS); JSON schema for tool results; emitted by scs-report for GitHub/GitLab CI integration.
Scan Determinism
Invariant: identical inputs (manifests/lockfiles) + identical advisory feed snapshot → identical finding set and report; requires canonical purl ordering, stable sort.
Scope
Dependency classification: Prod (shipped), Dev (test/build tooling), Optional (feature-gated); propagated through graph; policy can gate on scope.
SBOM
Software Bill of Materials; structured inventory of components, licenses, hashes, relationships; emitted as SPDX or CycloneDX by scs-sbom.
SemVer
Semantic Versioning (semver.org); MAJOR.MINOR.PATCH[-pre][+build]; used by Cargo/npm ecosystems; implemented via semver crate in scs-resolve.
Sigstore
Open-source project providing cosign (signing), Fulcio (CA), and Rekor (transparency log) for artifact signing and verification.
SLSA
Supply-chain Levels for Software Artifacts; framework with levels 0–3 (4 in v1.0) encoding build integrity guarantees; scs-provenance maps attestation content to SLSA level.
SPDX
Software Package Data Exchange (Linux Foundation); SBOM standard with tag-value and JSON formats; supported as emit/parse target in scs-sbom.
Typosquatting
Attack: publish package with name closely resembling a popular package (reqeusts vs requests); scs-threat detects via edit-distance + phonetic similarity.
VEX
Vulnerability Exploitability eXchange (OpenVEX / CSAF VEX); machine-readable statement that a known vuln does not affect a product in a specific context; consumed by scs-policy to suppress findings.
Version
Parsed, ecosystem-specific version struct; supports comparison operators per ecosystem semantics; stored alongside VersionReq (range constraint).
VersionReq
Version requirement/constraint; ecosystem-specific range expression (^1.2, >=1.0,<2.0, ~=3.5); evaluated by scs-resolve during constraint solving.
Withdrawn Advisory
Advisory marked retracted/disputed; Advisory.withdrawn: Option<Time>; scs-match suppresses or flags findings with VEX-like status rather than treating as active.
