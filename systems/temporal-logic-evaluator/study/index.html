Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why is the gravest failure class a silent verdict flip rather than a crash? What property of GPVW and nested DFS makes this inevitable, and why does fuzzing alone not catch it? (synthesis: §7 System Invariants — INV-7; Threat Model — T4)
  2. GPVW builds nodes lazily. Under what exact condition does a node get materialized in the on-the-fly construction, and what invariant guarantees no node is generated twice? (synthesis: §18 Phase 6; §7 System Invariants — INV-4)
  3. The nested DFS launches the inner DFS in post-order from an accepting state. Give a concrete 4-state automaton where launching in pre-order would cause emptiness to incorrectly return None. (synthesis: §20 Phase 8; §7 System Invariants — INV-7)
  4. degeneralize maps (state, counter) to a flat usize id via s*k + c. Show that the single accept set of the output Nba is visited infinitely often if and only if all k generalized accept sets of the input Ngba are. (synthesis: §19 Phase 7; §7 System Invariants — INV-5)

  14. An LTL formula φ is said to be monitorable. Does this mean every finite observation over the formula eventually reaches a definitive verdict? Precisely state what monitorability guarantees and what it does not. (synthesis: §21 Phase 9; §6 Design Principles — P11)
  15. The product construction uses label(s') (next-state guard convention). Explain what would go wrong if label(s) (current-state) were used instead, and give a concrete formula+Kripke pair where this matters. (synthesis: §7 System Invariants — INV-6; §20 Phase 8)

Mental Models & First Principles

The eight mental models below are the minimum set needed to reason correctly about this engine's behavior. Each is stated as a falsifiable claim; violation of any of them leads to a specific, observable failure class.

MM1 — Model checking as language intersection. K ⊨ Aφ reduces to asking whether the ω-language of the system (K as a Kripke generator → all its infinite paths as ω-words) intersects the language of bad behaviors (L(Nba(¬φ))). Emptiness of the intersection = holds. Predicts: any bug in product/emptiness is automatically a soundness bug, never a mere performance issue. Bug class without it: engineers "patch" a wrong verdict locally instead of tracing it to the intersection contract. This is not just the design — it IS the correctness definition (INV-1). Applies at §20 Phase 8 and §7 System Invariants (INV-1).

MM2 — GPVW node = obligation set. Every GPVW node is precisely a set of obligations over the subformula closure — a now-set of things that must hold on the current edge plus a next-set of things to check next. Predicts: any node-construction bug is classifiable as either a now/next split error or a closure-completeness error. Bug class without it: a bug in the now/next split produces an automaton that accepts too much (soundness) or too little (completeness), with no principled way to localize which. Applies at §18 Phase 6.

MM3 — Degeneralization as fair progress. The k-counter in degeneralize implements fairness: it forces the automaton to demonstrate progress on each of the k eventualities (one per Until-subformula) in round-robin. Predicts: the degeneralized Nba's state count is exactly (k+1)×|Ngba|, never more. Bug class without it: an off-by-one in the acceptance wrap-around makes the degeneralized automaton accept runs that starve one eventuality — a silent language-overapproximation → missing counterexamples. Applies at §19 Phase 7 and §7 System Invariants (INV-5).

MM4 — Nested DFS post-order invariant. The inner DFS in CVWY is launched strictly in post-order from an accepting state. Predicts: launching in pre-order means the outer DFS may not have finished exploring a path that loops back to the accepting state. Bug class without it: the inner DFS then fails to close the cycle even though one exists — the most common nested-DFS implementation bug, and it is silent (returns None instead of a real lasso). Applies at §20 Phase 8 and §7 System Invariants (INV-7).

MM5 — Progression as formula derivative. progress(f, s) is the Brzozowski/LTL derivative of f with respect to the single event s. The residual is a formula that talks about all remaining events. Predicts: a residual that simplifies to True means every continuation satisfies f (good prefix), and False means no continuation can (bad prefix) — the foundation of LTL3 verdicts. Bug class without it: treating progress as an ad-hoc rewrite (rather than a derivative with a formal end-of-trace collapse) reintroduces the weak/strong-next confusion independently in every client. Applies at §16 Phase 4 and §21 Phase 9.

MM6 — CTL fixpoints: direction matters. EU is a least fixpoint (start from the terminal set sat(ψ), grow upward by adding φ-predecessors) because eventualities require minimal solutions. EG is a greatest fixpoint (start from sat(φ), shrink downward removing states with no φ-successor) because safety requires maximal solutions. Predicts: swapping either direction changes which states are labeled without any crash. Bug class without it: silently misclassified reachable states, invisible until a differential/known-result cross-check. Applies at §17 Phase 5 and §6 Design Principles (P13).

MM7 — Explicit-state is correct up to the hard ceiling. This engine is correct for all formula/model instances within the size caps (ADR-06): up to |φ|≤256-closure nodes, Ngba ≤ 2²⁰ states, Kripke ≤ 10⁷ states. Predicts: any input beyond the ceiling either succeeds slowly or fails with a typed error — never silently wrong. Bug class without it: treating a resource-cap failure as a correctness bug, or worse, silently truncating work near the ceiling instead of erroring. The symbolic/BDD engine (#281) is needed above that ceiling. Applies at §4 System Constraints and §6 Design Principles (P6).

MM8 — Differential testing is the primary correctness guard. Unlike a theorem prover, a temporal logic evaluator has no self-certifying output: check_ltl returns Ok(()) with no proof. The only ground truth is an external, independently correct tool. Predicts: any silent verdict flip is invisible to unit tests and fuzzing alike, and becomes visible only under a cross-tool comparison. Bug class without it: shipping on "all tests green" while a soundness bug survives because no test compares against an independent implementation. Spot (ltl2tgba) is that tool for LTL; the Phase 13 differential harness is the only structural guard against silent verdict flips. Applies at §25 Phase 13.

Glossary · 12 terms · site-wide glossary

LTL
Linear Temporal Logic. Formulas over a single linear path (an omega-word). Operators X/U/R/F/G + boolean. Model-checked via the automata-theoretic path (ltl_to_ngba → degeneralize → product → emptiness). Kind::Ltl.
CTL
Computation Tree Logic. Each temporal op is fused with a path quantifier (E/A). Branching over the tree of runs from a state. Checked by CtlChecker labeling. Kind::Ctl. State formulas only at top level.
CTL\
Superset unifying LTL path formulas + CTL quantifier nesting. Non-goal: this engine does NOT implement CTL*; only LTL, CTL, PastLtl, LTLf are parsed.
LTLf
Finite-trace LTL (De Giacomo–Vardi). Same syntax as LTL but evaluated over a finite Trace; the next-operator splits into weak/strong at end-of-trace. Evaluated by eval_ltlf (progression) and Phase 11's LTLf→DFA. Kind::Ltlf.
Past-time LTL
LTL extended with past operators Y/O/H/S. Evaluated by tl-eval dynamic programming (Phase 10), each state's past-obligation vector derived from the previous state. Kind::PastLtl.
Atomic proposition (AP)
A boolean observable; pub type Ap = u32, an interned id assigned by tl-syntax. A State is the set of APs that hold there (a Bitset). Formula::Atom(Ap).
State formula
A formula whose truth is evaluated at a single Kripke state (e.g. any CTL formula, an AP).
Path formula
A formula whose truth is evaluated along a path/omega-word (the inside of a CTL quantifier, or any LTL formula). The state-vs-path distinction is enforced by Phase 2 well-formedness.
Negation normal form (NNF)
Form where Not appears only on atoms; produced by nnf(&Formula) -> Formula using dualities (not X = X not; not(p U q) = (not p) R (not q); not F = G not; not G = F not; not Ex = Ax not; …). GPVW and the labeling algorithm assume NNF.
Subformula closure
The set of subformulas (and their negations, in NNF) of a formula; closure(&Formula) -> Vec<Formula>. Indexes GPVW tableau obligations and CTL labeling.
Formula
The typed AST enum in tl-formula: True/False/Atom/Not/And/Or, future LTL X/U/R/F/G, past Y/O/H/S, CTL Ex/Ax/Eg/Ag/Ef/Af/Eu/Au. Boxed children.
Kind
Well-formedness classification enum Kind { Ltl, Ctl, PastLtl, Ltlf } assigned to a parsed Formula; gates which evaluator is legal.
