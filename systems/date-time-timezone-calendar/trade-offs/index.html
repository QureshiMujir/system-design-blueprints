Decisions (§9) · 30 ADRs

ADR-1

Implementation language

Chosen

Rust (edition 2021, MSRV 1.74)

Rejected

C, C++, Go, Python, Zig

When the rejected choice is right

C wins when the deliverable is the OS tzdb itself — IANA tzcode (zic/localtime.c) must compile in a freestanding libc bootstrap with no Rust toolchain; Python wins for a throwaway analysis script over tzdb where dateutil ships in minutes

Why: safe untrusted parsing; newtypes prevent civil/instant conflation; canonical modern tz corpus is Rust

ADR-2

Core/std split

Chosen

no_std core + std loader behind feature="std"

Rejected

monolithic std-only

When the rejected choice is right

Monolithic std wins for a server-only product (NodaTime's target): the no_std seam adds feature-flag complexity and CI matrix cost that buys nothing when every target has an allocator and a filesystem

Why: embeddable/WASM core; tzdb filesystem isolated to std

ADR-3

Instant representation

Chosen

i64 secs + u32 nanos

Rejected

i128 nanos; f64 Julian-date; i64 millis

When the rejected choice is right

i128 nanos wins inside a high-frequency-trading or PTP capture path where every value is a sub-microsecond delta in a tight ±292-year window and a single 128-bit counter (no carry logic) beats a struct; i64 millis wins for a JS/Date-compatible wire layer (Temporal's epochMilliseconds)

Why: avoids year-2262 boundary; cache-friendly 16 B; integer-exact; ns resolution

ADR-4

Canonical internal calendar

Chosen

proleptic Gregorian day-number

Rejected

Julian internal; Rata-Die-from-year-1; JDN

When the rejected choice is right

JDN (Julian Day Number) wins for an astronomy/ephemeris pipeline whose every input already arrives in JD and whose epoch (4713 BCE noon) is the field standard; Julian-internal wins for a pre-1582 historical-records system where the source documents are themselves Julian-dated

Why: one calendar to test; Hinnant algorithms; others derived (I2, B1)

ADR-5

tz data loading

Chosen

both: parse system /usr/share/zoneinfo at runtime and optional bundled tzdb (feature bundled-tzdb)

Rejected

system-only; bundled-only

When the rejected choice is right

System-only wins for a long-lived Linux daemon that must track the OS tzdata package the sysadmin patches (no rebuild on a DST-law change); bundled-only wins for an air-gapped/WASM target with no /usr/share/zoneinfo and a hard reproducibility mandate

Why: system = current law; bundled = reproducible/hermetic builds + Windows/WASM

ADR-6

Future transitions beyond tabulated

Chosen

POSIX TZ footer rule (parse + generate)

Rejected

extrapolate last transition; error

When the rejected choice is right

Extrapolate-last wins for a zone with no DST and a constant offset where the POSIX footer is absent or trivial; error wins for a conservative finance/audit system that must refuse to guess an offset past the last legislated transition rather than emit a prediction

Why: RFC 8536-mandated; correct indefinite-future DST

ADR-7

Leap-second policy

Chosen

Unix default (no leaps) + opt-in TAI/UTC-leap scale

Rejected

always-leap; always-smear

When the rejected choice is right

Always-smear wins for a fleet behind Google/AWS smearing NTP, where every host already sees a smeared clock and a non-smeared library would disagree with the OS; always-leap (true UTC) wins for a metrology/GNSS lab where 23:59:60 is a real observed second that must never be collapsed

Why: matches ecosystem default; TAI available for precision users (P6 principle)

ADR-8

Ambiguity policy default

Chosen

Compatible (gap→forward, overlap→earlier)

Rejected

silent earliest; panic

When the rejected choice is right

Panic/Reject-by-default wins for a medication-dosing or legal-deadline system where a silently-shifted local time is a safety incident and the caller must be forced to choose; silent earliest wins for a best-effort UI clock where any nearby instant is acceptable and ergonomics trump precision

Why: matches java.time/Temporal; explicit + overridable (P3 principle)

ADR-9

Period arithmetic order

Chosen

left-to-right, clamp at month-end, non-associative documented

Rejected

normalize months↔days; reject ambiguous

When the rejected choice is right

Normalize months↔days wins for a billing engine on a fixed 30-day "month" (interest/lease accrual) where 1 month == 30 days exactly and clamping is wrong; reject-ambiguous wins for a strict scheduling kernel that refuses Jan31 + 1mo outright rather than silently clamp

Why: matches java.time Period; predictable (I6)

ADR-10

RRULE engine shape

Chosen

lazy iterator (pull-based, bounded)

Rejected

eager Vec materialization

When the rejected choice is right

Eager materialization wins for a calendar UI rendering a fixed visible window (one month grid) where the full small set is needed at once, is trivially bounded, and a sorted Vec is simpler to paginate and diff

Why: constant memory; cap enforceable mid-stream (I8)

ADR-11

Format/parse implementation

Chosen

hand-written recursive-descent + table-driven strftime

Rejected

parser-combinator lib; regex; chrono format DSL

When the rejected choice is right

A parser-combinator (nom/winnow) wins for a team already standardized on it across many formats, where uniform combinator style and shared error machinery outweigh the dependency; regex wins for a one-off log-scraper extracting timestamps, not a library

Why: zero deps in core; positioned errors; total parsers (P12)

ADR-12

Fractional-second handling

Chosen

truncate to 9 digits (ns), lossless within ns

Rejected

round-half-even; store full decimal

When the rejected choice is right

Store full decimal wins for a scientific-instrument archive that must preserve picosecond/attosecond fractions verbatim for replay; round-half-even wins when down-converting ns→ms for a display layer where statistical unbiasedness across many samples matters

Why: deterministic; matches RFC-3339 practice

ADR-13

Error model

Chosen

typed enums (ParseError, RangeError, AmbiguousTime, NonexistentTime, ExpansionLimit)

Rejected

String errors; anyhow; panics

When the rejected choice is right

anyhow wins inside ztool/scripts and tests — application-edge code that only prints the error and exits, where exhaustive matching is pure ceremony; a string message is the whole requirement

Why: exhaustive matching; no panic on input (P12); stable error codes

ADR-14

Arithmetic

Chosen

checked integer (checked_add/sub), bignum-free

Rejected

wrapping; saturating; bigint

When the rejected choice is right

Saturating wins for a "clamp to representable range" UI slider over dates where pinning at the boundary beats an error dialog; bigint wins for a calendrical-research tool exploring dates millions of years out where i64 days genuinely overflow

Why: overflow = typed error (I15, P10); predictable cost

ADR-15

Serialization (interchange)

Chosen

ISO-8601 / RFC-3339 text; optional serde behind feature

Rejected

bincode; protobuf; custom binary

When the rejected choice is right

bincode/custom binary wins for a high-throughput column store or append-only log where billions of instants must pack to 8–12 bytes each and text framing would dominate storage and bandwidth

Why: human-readable, wire-stable, round-trip (I14); no schema lock-in

ADR-16

Logging/tracing

Chosen

tracing facade behind feature="trace", no-op in core

Rejected

log; println; mandatory

When the rejected choice is right

log wins for an embedder whose entire stack is built on the log facade and never adopted tracing — matching the host's existing sink beats introducing a second one

Why: observability optional, zero-cost when off; structured spans

ADR-17

Metrics

Chosen

counters via metrics facade (feature-gated); else inert

Rejected

embedded Prometheus; none

When the rejected choice is right

Embedded Prometheus exporter wins for a standalone ztool service deployment (rare) that has no host to delegate to and must expose /metrics itself; none wins for a no_std embedded target with no metrics infrastructure at all

Why: host chooses backend; library only emits

ADR-18

Unit/integration testing

Chosen

cargo test + golden fixtures + proptest

Rejected

only example tests

When the rejected choice is right

Example-only tests win for a frozen, feature-complete release in pure maintenance mode where new property machinery would churn a stable surface for no new coverage

Why: property + differential (Testing & Verification Strategy)

ADR-19

Differential oracles

Chosen

zdump, Python dateutil/zoneinfo, ICU, java.time vectors

Rejected

self-consistency only

When the rejected choice is right

Self-consistency-only wins for a novel calendar (no oracle exists — e.g. a fictional or proposed reform calendar) where round-trip/property tests are the only available truth; importing an oracle would just import its bugs

Why: catch spec-misreadings against authorities (R1,R4,R9)

ADR-20

Fuzzing

Chosen

cargo-fuzz (libFuzzer) targets: TZif, POSIX-TZ, ISO-8601, RRULE

Rejected

manual edge cases only

When the rejected choice is right

Manual edge cases win when all parser input is trusted and internally generated (e.g. a closed pipeline that only ever reads its own re-serialized output) — the adversarial threat model that justifies a fuzzer is absent

Why: adversarial coverage; zero-panic goal (P12)

ADR-23

Packaging

Chosen

ADR-24

tzdb version pinning

Chosen

pin to released tag (e.g. 2024a) + record SHA-256 in tzdb.lock

Rejected

When the rejected choice is right

Track-latest wins for an always-online consumer service that wants the freshest DST law the instant IANA ships it and treats reproducibility as secondary to currency (a clock-display widget, not an audit ledger)

ADR-25

tzdb update process

Chosen

automated PR on new IANA release: re-vendor, re-run full conformance, bump version

Rejected

manual; never

When the rejected choice is right

Manual wins for a tiny project with rare releases where the automation's maintenance cost exceeds the ~10×/yr update toil; never (freeze) wins for a regulatory snapshot artifact that must reproduce a historical tzdb version forever and must not drift

Why: timely correctness w/ gated validation (Build & Release Engineering)

ADR-28

Concurrency model

Chosen

Rejected

per-thread mutable globals (tzcode style)

When the rejected choice is right

Per-thread mutable global (tzset/localtime style) wins for a strictly single-threaded embedded program where one ambient zone and zero Arc/lock overhead is the right minimal model — exactly libc's original niche

Why: no tzset global-state bugs (R1 pitfall); lock-free hot path (I18)

Alternative Architectures (Roads Not Taken)

Fundamentally different designs for the same system — not parameter tweaks. Each: sketch, the regime where it wins, the real system that embodies it, why this blueprint rejected it.

ALT-1 — Broken-down-fields everywhere (one mutable struct tm-style record).

Show the original text diagram
   [ struct: year, mon, mday, hour, min, sec, wday, yday, isdst ]
            |  mktime()                 ^  localtime()
            v                           |
        time_t (seconds)  <----  ambient global TZ + tzset()

Regime where it wins: a single-threaded C program with one ambient zone and no need to hold two zones at once — minimal memory, no allocation, no type ceremony. Real system: C standard library / POSIX (struct tm, mktime, localtime, tzset). Why rejected: it conflates civil and absolute time in one mutable record (violates P1/MM1), routes the zone through process-global tzset state (the R1 pitfall, not thread-safe — ADR-28), and makes ambiguity invisible (mktime's isdst is a lossy hint, not the 0/1/2 model of I4). It cannot give the structural civil-vs-instant guarantee that is this library's entire thesis.

ALT-2 — Seconds-since-epoch only; no civil type at all.

Show the original text diagram
   i64 seconds since 1970  ──(display only, on demand)──►  Y-M-D h:m:s string
   all storage, comparison, arithmetic happen on the raw integer

Regime where it wins: a logging/storage substrate that only ever orders, diffs, and stores timestamps and renders human form rarely at the edge — minimal footprint, trivial comparison, no calendar code in the hot path. Real system: classic Unix time / most database TIMESTAMP storage. Why rejected: it pushes every calendar and zone concern to the caller, re-creating the civil/instant confusion at each display site, and offers no place for Period arithmetic, DST resolution, or recurrence — the very capabilities (§8.9, §8.8, §8.11) this library exists to provide. It is a component this design contains (the Instant), not a viable whole.

ALT-3 — Locale/CLDR-first string engine.

Show the original text diagram
   locale + skeleton ("yMMMd")  ──►  CLDR pattern DB  ──►  formatted string
                                          |
                       calendar + tz data are plugins under the formatter

Regime where it wins: a user-facing product whose primary job is localized presentation in dozens of languages and calendars — the formatter and its data are the product. Real system: ICU (ICU4C/ICU4X), and the Intl/CLDR layer Temporal delegates to. Why rejected: it inverts this blueprint's priority order (correctness → observability → maintainability → performance): it makes a huge locale-data dependency and string formatting central, whereas this library wants a small algorithmic core that emits locale-stable machine forms and defers CLDR behind a stubbed LocaleHook (P11, ADR-30). The CLDR engine is the deferred outer layer here, not the core.

ALT-4 — Rules-interpreter tzdb (interpret zic source at runtime).

Show the original text diagram
   tzdata SOURCE (Rule/Zone/Link lines)  ──►  in-process rule interpreter  ──►  offset(t)
        (no precompiled TZif binary)            expands rules on demand

Regime where it wins: a tool that must answer "why is this offset what it is" or re-derive zones from edited source without running zic — it keeps the human-readable rules and their provenance. Real system: the zic compiler's own front end and research/tooling that consume tz source rather than compiled output. Why rejected: interpreting source at runtime is slower and far larger in code than binary-searching a precompiled transition array, and it duplicates zic's subtle rule-expansion semantics (P5) inside the hot path. This design consumes the compiled TZif (RFC 8536, §8.6, Phase 4) — the same artifact every OS ships — and treats zic as an upstream build step, getting O(log n) lookups (C5) and a small footprint (C2) instead.
