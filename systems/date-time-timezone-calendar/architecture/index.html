Per-box detail:

  • TZif files / zoneinfo — compiled binary zone definitions (e.g. America/New_York), shipped by OS or bundled. Source of historical truth. Untrusted: may be truncated, oversized, or version-mismatched. Read-only; loaded lazily and cached by zone id.
  • POSIX TZ string — compact textual rule (EST5EDT,M3.2.0,M11.1.0) from TZ env or TZif footer; expresses an indefinite future DST rule when no further transitions are tabulated. Untrusted; small but adversarial.
  • leap-seconds.list — IERS-published cumulative TAI−UTC offsets with expiry; consumed only in TAI/leap-aware mode; default Unix mode ignores it. Has an expiry timestamp → staleness telemetry.
  • TZif PARSER — validates magic/version, reads 6 counts, bounds-checks all counted arrays, parses v1 32-bit block then (v2/v3) 64-bit block + footer POSIX string. Emits TimeZone or typed ParseError. Pure, allocation-bounded by declared counts (capped).
  • POSIX-TZ PARSER — recursive-descent over the EBNF; produces a PosixTz with std/dst offsets + Mm.w.d/Jn/n start/end rules + transition local-times. Generates concrete transitions per year on demand.
  • LEAP TABLE LOADER — parses leap records (NTP-epoch seconds + cumulative offset); stores sorted; supports tai_minus_utc(instant) lookups.
  • TimeZone — the unified in-memory zone: a strictly-increasing transition array indexing into a type table, plus an optional POSIX rule covering all instants after the last tabulated transition, plus leap records. Immutable after construction; shared Arc read-only across threads.
  • CONVERSION CORE — the numeric heart: proleptic-Gregorian day-number math, offset lookup via binary search, and the offset resolution logic that maps a local civil time to 0/1/2 candidate offsets and applies an AmbiguityPolicy. Pure, deterministic, no_std.
  • Instant — (secs:i64, nanos:u32, scale); the absolute coordinate. Total order. Arithmetic with Duration.
  • CivilDate/Time/DateTime — wall-clock fields, calendar-relative, no offset. Arithmetic with Period (calendrical) or Duration (exact, on the underlying day-number).
  • ZonedDateTime — (civil, offset, zone); the fully-resolved local time. Round-trips to Instant via the stored offset.
  • Duration — exact elapsed time (secs+nanos); machine arithmetic; never variable-length.
  • Period — calendrical span (Y/M/D); variable wall-length; resolved only against a concrete date.
  • FORMATTER/PARSER — hand-written ISO-8601/RFC-3339/strftime; round-trip-faithful within resolution; rejects malformed input with positioned errors.
  • CALENDARS — Gregorian (canonical), Julian, ISO-week; calendrical ops (month add with clamping, ordinal/weekday/week-number).
  • RRULE ENGINE — lazy iterator: per-FREQ candidate generation → BY* expand/limit filters → BYSETPOS selection within each period → dedupe/sort → EXDATE subtraction / RDATE union → hard-bounded by COUNT/UNTIL/iteration cap.

8. Domain Model

8.1 Time scales

Scale Counts Leap seconds Epoch Use
Unix (default) non-leap seconds since 1970-01-01T00:00:00Z; a day is always 86,400 not counted (the leap second shares the same Unix value as the prior second, or is "smeared") 1970-01-01T00:00:00Z wire timestamps, logs, DB
UTC civil seconds incl. inserted leap seconds (23:59:60) counted 1972-01-01 (UTC defined) calendar-correct absolute time
TAI SI seconds, no leaps, continuous n/a (never inserts) 1958-01-01 physics, precise elapsed time
Monotonic opaque steady ticks; no relation to civil time n/a arbitrary boot epoch measuring durations only

Relationships: TAI − UTC = 10 s at 1972-01-01, growing by inserted leap seconds to 37 s since 2017-01-01. Unix = UTC − (leap seconds since 1972) in the "skip" convention; in "smear" convention Unix is continuous but each second is slightly ≠ 1 SI second across the smear window. Monotonic is incomparable to all civil scales — used only for Duration measurement (P8 of Design Principles).

All 27 insertions 1972→2017 are positive (+1). No negative leap second has ever occurred (the standard permits one). The library stores [Leap{ at_unix: i64, correction: i32 }] sorted; tai_minus_utc(instant) = 10 + count of leaps ≤ instant.

8.2 Instant representation

Instant { secs: i64, nanos: u32, scale: TimeScale } — secs since the scale's epoch (Unix epoch for Unix/UTC modes), nanos ∈ [0,1e9) (I9). Total order by (secs, nanos). Default scale = Unix. i64 secs gives ±292 Gyr — never the binding limit; the practical limit is the supported civil year range (§4). Rejected i128-nanos default (ADR-3): doubles size, hurts cache, and the year-2262 boundary of i64-nanos is avoided by storing seconds, not nanoseconds, as the wide field.

8.3 Civil fields

CivilDate { y: i32, m: u8 /*1–12*/, d: u8 /*1–31*/ }, CivilTime { h: u8 /*0–23*/, m: u8 /*0–59*/, s: u8 /*0–60, 60 only in UTC-leap mode*/, ns: u32 }, CivilDateTime { date, time }. Year is astronomical/proleptic: signed, includes year 0 (= 1 BCE) (I17). No offset, no zone — purely positional on a calendar.

8.4 days_from_civil / civil_from_days (Hinnant algorithm, reference-formula table — no runnable code)

Serial day number = days since 1970-01-01 (Unix civil epoch); equivalently Rata Die shifted by the constant 719,468 (= days from 0000-03-01 to 1970-01-01). Both directions are pure integer-floor arithmetic (⌊⌋ = integer division, truncating toward −∞ for the era split); no branch is a loop or a function call — each row below is one closed-form quantity.

days_from_civil(y, m, d) → serial (P3 Hinnant; enforced by I1):

Step Quantity Formula Range / note
1 March-shifted year y′ = y − 1 when m ≤ 2, else y′ = y shifts so March = month 0
2 Era era = ⌊y′ / 400⌋ for y′ ≥ 0; era = ⌊(y′ − 399) / 400⌋ for y′ < 0 400-year era index
3 Year-of-era yoe = y′ − era × 400 [0, 399]
4 March-based month m′ = m − 3 when m > 2, else m′ = m + 9 [0, 11]
5 Day-of-year doy = ⌊(153 × m′ + 2) / 5⌋ + d − 1 March-based, [0, 365]
6 Day-of-era doe = yoe × 365 + ⌊yoe/4⌋ − ⌊yoe/100⌋ + doy [0, 146096]
7 Result serial = era × 146097 + doe − 719468 day number, 1970-01-01 = 0

civil_from_days(z) → (y, m, d) (inverse of the above; same enforcement):

Step Quantity Formula Range / note
1 Shifted count z′ = z + 719468 aligns to the March-based epoch
2 Era era = ⌊z′ / 146097⌋ for z′ ≥ 0; era = ⌊(z′ − 146096) / 146097⌋ for z′ < 0 400-year era index
3 Day-of-era doe = z′ − era × 146097 [0, 146096]
4 Year-of-era yoe = ⌊(doe − ⌊doe/1460⌋ + ⌊doe/36524⌋ − ⌊doe/146096⌋) / 365⌋ [0, 399]
5 March-shifted year y′ = yoe + era × 400
6 Day-of-year doy = doe − (365 × yoe + ⌊yoe/4⌋ − ⌊yoe/100⌋) March-based, [0, 365]
7 March-based month mp = ⌊(5 × doy + 2) / 153⌋ [0, 11]
8 Day d = doy − ⌊(153 × mp + 2) / 5⌋ + 1 [1, 31]
9 Month m = mp + 3 when mp < 10, else m = mp − 9 [1, 12]
10 Year y = y′ + 1 when m ≤ 2, else y = y′ undoes the step-1 shift

Properties: integer-only, branch-light, no table lookups, exact over the full i64 day range; 146097 = days per 400-year Gregorian cycle (97 leap years); 719468 aligns the March-based internal epoch to 1970-01-01. I1 asserts the bijection (civil_from_days ∘ days_from_civil = identity).

Weekday: weekday(days) = (days + 4) mod 7 with 0 = Sunday (since 1970-01-01 is a Thursday → offset 4). Ordinal day-of-year: days_from_civil(y,m,d) − days_from_civil(y,1,1) + 1.

8.5 Rata Die / serial day number

Rata Die (RD) = days since the proleptic Gregorian 0001-01-01 (RD 1). Internal day number n relates by RD = n + 719162. We standardize on the 1970-based day number internally (matches Unix, avoids large constants in hot math); RD is offered only at the calendar API boundary for interop with Dershowitz–Reingold literature.

8.6 TZif binary format (RFC 8536) — byte layout

Big-endian throughout. Header (44 bytes):

Offset Field Size Meaning
0 magic 4 ASCII "TZif"
4 version 1 0x00('1'), 0x32('2'), 0x33('3')
5 reserved 15 must be zero (ignored)
20 isutcnt 4 (u32) count of UT/local indicators
24 isstdcnt 4 count of std/wall indicators
28 leapcnt 4 count of leap-second records
32 timecnt 4 count of transition times
36 typecnt 4 count of local-time-type records (≥1)
40 charcnt 4 total bytes of abbreviation strings

Data block (V1 sizes shown; V2/V3 second block uses 8-byte transition times):

Array Count × elem size Contents
transition times timecnt × 4 (V1) / ×8 (V2+) sorted ascending Unix seconds of each transition (I3)
transition types timecnt × 1 index into ttinfo array for the offset after each transition
ttinfo records typecnt × 6 each: utoff: i32 (4), isdst: u8 (1), desigidx: u8 (1, index into abbr)
abbreviation chars charcnt × 1 NUL-separated abbreviation strings (e.g. LMT\0EST\0EDT\0)
leap records leapcnt × (4+4) V1 / (8+4) V2+ occur: time, corr: i32 cumulative correction
std/wall flags isstdcnt × 1 per ttinfo: transition time was std (1) or wall (0)
ut/local flags isutcnt × 1 per ttinfo: transition time was UT (1) or local (0)

V2/V3 layout: the entire header+data block repeats with 8-byte transition times, followed by a footer: \n + POSIX TZ string + \n describing transitions after the last tabulated one. V3 extends the POSIX string to allow hour values [-167,167] (transitions ≥ 24:00). Parser policy: if version ≥ '2', skip the V1 block and use the 64-bit block + footer (the V1 block exists only for legacy 32-bit readers and truncates at 2038).

Validation rules (parser, P4): magic == "TZif"; version ∈ {0,'2','3'}; each count ≤ its §4 cap; declared array lengths fit remaining bytes (no over-read); typecnt ≥ 1; every transition type index < typecnt; every desigidx < charcnt; abbreviation region contains required NULs; transition times strictly increasing.

8.7 POSIX TZ string grammar (EBNF)

tz        = std offset [ dst [ offset ] [ "," rule "," rule ] ]
std       = name                 ; >=3 chars, or "<"+/-alnum+">"
dst       = name
name      = ( ALPHA{3,} ) | ( "<" (ALPHA|DIGIT|"+"|"-"){1,} ">" )
offset    = [ "+" | "-" ] hh [ ":" mm [ ":" ss ] ]   ; hh 0..24 (V3: 0..167)
            ; sign convention: time = UTC + offset  ⇒  west is POSITIVE
rule      = date [ "/" time ]
date      = "J" julian            ; Jn : 1..365, Feb29 NEVER counted
          | julian0               ; n  : 0..365, Feb29 counted (leap years)
          | "M" month "." week "." day   ; Mm.w.d
month     = 1..12
week      = 1..5                  ; 5 = "last" occurrence of `day` in month
day       = 0..6                  ; 0 = Sunday
time      = [ "+" | "-" ] hh [ ":" mm [ ":" ss ] ]   ; default 02:00:00 local

Examples: EST5EDT,M3.2.0,M11.1.0/2 (US Eastern: std UTC−5, dst UTC−4, spring = 2nd Sunday of March, fall = 1st Sunday of November at 02:00); <+03>-3 (fixed UTC+3, bracket name); GMT0 (no DST). Note the inverted sign: EST5 means UTC−5 (offset is "hours to add to local to get UTC"). The parser normalizes to internal Offset(secs east of UTC) = −posix_value.

8.8 DST transition semantics

Two discontinuities arise from offset changes:

GAP (spring-forward, offset increases, e.g. -5h -> -4h):
   wall clock jumps 02:00 -> 03:00; local times in [02:00,03:00) DO NOT EXIST.
   timeline:  ...01:59:59(-5)  | [skip 1h] |  03:00:00(-4)...
   offsets_for(02:30) -> 0 candidates  (NonexistentTime)

OVERLAP (fall-back, offset decreases, e.g. -4h -> -5h):
   wall clock repeats 01:00 -> 02:00 then again 01:00 -> 02:00; local times in
   [01:00,02:00) OCCUR TWICE (once at -4, once at -5).
   timeline:  ...01:59:59(-4)  01:00:00(-5)  01:59:59(-5)  02:00:00(-5)...
   offsets_for(01:30) -> 2 candidates  (AmbiguousTime: {-4 earlier, -5 later})

Resolution policies (AmbiguityPolicy), deterministic (I5):

Policy Gap behavior Overlap behavior Reference
Compatible (default) shift forward by the gap (02:30 → 03:30) pick earlier offset java.time, Temporal compatible
Earliest pick offset before the gap (→ 01:30-equivalent instant) pick earlier offset Temporal earlier
Latest pick offset after the gap pick later offset Temporal later
Reject return NonexistentTime error return AmbiguousTime error Temporal reject

offsets_for(civil) returns LocalResult ∈ {None(gap), Single(off), Ambiguous(earlier, later)} (I4); resolve(civil, policy) collapses it to a ZonedDateTime or typed error.

8.9 Duration vs Period

Duration Period
Represents exact elapsed time calendrical span
Fields secs: i64, nanos: u32 years: i32, months: i32, days: i32
Length fixed (1 day = 86,400 s always) variable (1 month = 28–31 days; 1 day across DST = 23/24/25 h)
Resolves against nothing (absolute) a concrete anchor date/zone
Add to Instant yes (exact) no (meaningless)
Add to CivilDate only via day-count yes (calendrical, clamps — I6)
Associative yes (I10) no (+1mo +1mo ≠ +2mo at month-ends)

Key trap: 2021-01-31 + 1 month + 1 month clamps to 2021-02-28 then 2021-03-28; +2 months directly gives 2021-03-31. Period arithmetic is intentionally order-dependent; document it (I6, ADR-9).

8.10 ISO-8601 / RFC-3339 grammar (EBNF)

; --- date forms ---
date         = calendar-date | ordinal-date | week-date
calendar-date= year "-" month "-" day            ; 2021-03-14
ordinal-date = year "-" doy                        ; 2021-073
week-date    = year "-W" week [ "-" weekday1 ]     ; 2021-W10-7
year         = [ "+" | "-" ] 4*DIGIT               ; ISO-8601-2 expanded: "+"5*DIGIT
month        = 2DIGIT                               ; 01..12
day          = 2DIGIT                               ; 01..31
doy          = 3DIGIT                               ; 001..366
week         = 2DIGIT                               ; 01..53
weekday1     = DIGIT                                ; 1=Mon .. 7=Sun (ISO)
; --- time forms ---
time         = hh [ ":" mm [ ":" ss [ frac ] ] ] [ offset ]
frac         = ( "." | "," ) 1*DIGIT               ; truncated to 9 digits (ns)
offset       = "Z" | ( "+" | "-" ) hh ":" mm       ; RFC3339 requires ":"
hh           = 2DIGIT  ; 00..23 (24:00:00 allowed end-of-day in ISO, normalized)
; --- datetime ---
datetime     = date "T" time                        ; RFC3339 allows space sep
; --- duration ---
duration     = "P" [ nY ] [ nM ] [ nD ] [ "T" [ nH ] [ nM ] [ nS ] ]
             | "P" weeks "W"
nY|nM|nD|nH|nS = 1*DIGIT ( "Y"|"M"|"D"|"H"|"S" )   ; S may carry fraction
; --- interval ---
interval     = datetime "/" datetime               ; start/end
             | datetime "/" duration               ; start/dur
             | duration "/" datetime               ; dur/end
             | "R" [ n ] "/" interval               ; repeating

RFC-3339 is a strict ISO-8601 profile: requires T (or space) separator, requires : in offsets, requires full YYYY-MM-DDThh:mm:ss, offset mandatory (Z or ±hh:mm), case-insensitive T/Z but canonical uppercase. Parser policy: accept ISO-8601 superset, emit RFC-3339 canonical; truncate fractional beyond 9 digits with documented rounding (round-half-to-even or truncate — locked in ADR-12: truncate, lossless within ns).

8.11 RFC 5545 RRULE

Parameter table (RECUR value type):

Part Values Role expand/limit per FREQ
FREQ SECONDLY..YEARLY base period (required) —
INTERVAL ≥1 (default 1) every Nth period —
COUNT ≥1 total occurrences (mutually exclusive w/ UNTIL) bound
UNTIL datetime (UTC if DTSTART has tz) inclusive end bound bound
BYMONTH 1..12 month filter/expand expand if FREQ<MONTHLY else limit
BYWEEKNO ±1..53 ISO week filter expand only if FREQ=YEARLY
BYYEARDAY ±1..366 day-of-year expand if FREQ in {SECONDLY,MINUTELY,HOURLY,DAILY*}; limit if larger
BYMONTHDAY ±1..31 day-of-month expand if FREQ<DAILY context; limit if WEEKLY
BYDAY [±n]MO..SU weekday (optional ordinal, e.g. -1MO) expand/limit depends on FREQ (see below)
BYHOUR 0..23 hour expand if FREQ<HOURLY else limit
BYMINUTE 0..59 minute expand if FREQ<MINUTELY else limit
BYSECOND 0..60 second (60 = leap) expand if FREQ=SECONDLY-context else limit
BYSETPOS ±1..366 select Nth within the expanded set per period post-filter
WKST MO..SU (default MO) week start; affects WEEKLY + BYWEEKNO —

Expand-vs-limit rule (RFC 5545 Section 3.3.10 table): a BY* part expands the candidate set when its period is finer than FREQ (e.g. BYMONTH under FREQ=YEARLY multiplies the set), and limits (filters) when coarser/equal. BYDAY is special: with an ordinal prefix (3MO) it limits under MONTHLY/YEARLY; bare (MO) it expands under WEEKLY/MONTHLY/YEARLY. BYSETPOS applies after all expansion within one FREQ period, selecting by 1-based position (negative = from end). EXDATE removes specific instances; RDATE adds explicit instances (unioned, then re-sorted, deduped).

8.12 Worked examples

(a) DST gap — 2021-03-14T02:30:00 America/New_York. On 2021-03-14, EST(−5)→EDT(−4) at 02:00 local; wall jumps 02:00→03:00. offsets_for(02:30) = None (gap). Policies: Compatible/Latest → 2021-03-14T03:30:00−04:00 (instant = 1615707000); Earliest → 2021-03-14T01:30:00−05:00-equivalent shifted instant; Reject → NonexistentTime{ civil, gap=3600s }.

(b) Overlap — 2021-11-07T01:30:00 America/New_York. EDT(−4)→EST(−5) at 02:00 local; wall repeats 01:00→02:00. offsets_for(01:30) = Ambiguous(earlier=−4, later=−5). Compatible/Earliest → 01:30−04:00 (instant 1636266600); Latest → 01:30−05:00 (instant 1636270200, +3600 s); Reject → AmbiguousTime{ civil, earlier:-4, later:-5 }.

(c) "Last Friday of each month, 10 occurrences." DTSTART:20210101T090000;RRULE:FREQ=MONTHLY;BYDAY=FR;BYSETPOS=-1;COUNT=10. Per month: expand all Fridays via BYDAY=FR, then BYSETPOS=-1 selects the last; emit until COUNT=10. Output: 2021-01-29, 02-26, 03-26, 04-30, 05-28, 06-25, 07-30, 08-27, 09-24, 10-29 (all 09:00). Equivalent form BYDAY=-1FR (ordinal) yields the same set.

(d) Leap second — 2016-12-31T23:59:60Z. Valid only in UTC-leap mode. Unix mode: the second :60 is rejected (or mapped to 23:59:59/00:00:00 per smear policy). UTC-leap mode: s=60 is accepted; instant→TAI adds the 37th leap; round-trips to the same civil. Telemetry: leap_second_parsed counter.

(e) Month-end clamp. 2021-01-31 + Period{months:1} → candidate 2021-02-31 invalid → clamp to last valid day 2021-02-28 (I6). In leap year 2024-01-31 + 1mo → 2024-02-29.

8.14 RRULE generator state table

Pipeline per FREQ period (one "interval window"):

Stage Input Operation Output
S0 advance current period start step by INTERVAL × FREQ next period window [start,end)
S1 candidates period window enumerate base candidates per FREQ (e.g. each day for DAILY, each second-slot for finer) candidate set C0
S2 expand C0 apply expanding BY* (cartesian product per §8.11 table) expanded set C1
S3 limit C1 apply limiting BY* (boolean filter) filtered set C2
S4 setpos C2 sort; select by BYSETPOS positions (1-based, neg from end) selected set C3
S5 dedupe C3 sort ascending, remove duplicates ordered set C4
S6 bound C4 drop > UNTIL; stop at COUNT; enforce < DTSTART removal except first emitted ⊆ C4
S7 except emitted subtract EXDATE, union RDATE, re-sort/dedupe final stream
S8 guard loop if total iters > cap or no candidates for K empty periods → stop terminate

State machine terminates when: COUNT reached, candidate > UNTIL, or guard cap hit (I8). Empty-period guard: after MAX_EMPTY=1,000,000/INTERVAL-bounded consecutive non-emitting periods (e.g. BYMONTHDAY=30 under FREQ=YEARLY;BYMONTH=2), terminate to avoid infinite scan of impossible constraints.

Design principles (§6)

  • Civil time ≠ Instant — type-enforced. Wall-clock fields and absolute coordinates are distinct unconvertible-without-a-zone types. Tradeoff: more types, more ceremony. Operational: logs/serialization must declare which one. Violation: "store local time, compare as UTC" → off-by-offset bugs, double-counted DST hours, ordering inversions.
  • Proleptic Gregorian is the canonical internal calendar. All conversions pivot through Gregorian day-number (Rata Die-equivalent). Tradeoff: Julian/ISO-week are derived, not primary. Operational: one calendar to test exhaustively. Violation: multiple competing internal epochs → conversion drift, irreconcilable round-trips.
  • Ambiguity is explicit and API-visible. Gap/overlap never resolved silently; caller supplies an AmbiguityPolicy or receives an enumerated LocalResult. Tradeoff: callers must decide. Operational: every conversion site documents its policy. Violation: silent "pick one" → the canonical DST bug (meetings off by an hour twice a year).
  • Determinism + reproducibility. Same inputs + pinned tzdb version ⇒ identical bytes out; no hidden wall-clock reads, no RNG, no locale env in core. Tradeoff: tzdb version is an explicit input to pin. Operational: incidents reproducible from inputs + version. Violation: "works on my machine" timezone bugs, unbisectable failures.
  • tz data is versioned input, not baked-in law. tzdb updates ~10×/yr; the version is a first-class, queryable, pinnable artifact. Tradeoff: must ship update tooling. Operational: tzdb_version() in telemetry; pinned SHA in builds. Violation: stale law → wrong offsets after a country changes DST; or unannounced behavior change on rebuild.
  • Leap seconds are opt-in and explicit. Default = Unix time (no leap seconds; a day is 86,400 s; the leap second is not counted). TAI/leap-aware mode is a separate scale chosen explicitly. Tradeoff: two semantics to maintain. Operational: the chosen scale is part of every Instant. Violation: mixing scales → 27–37 s discrepancies, 23:59:60 parse failures, smear/no-smear mismatches across systems.
  • Bounded recurrence — every RRULE expansion has a hard cap. COUNT, UNTIL, and an absolute iteration ceiling bound all generation. Tradeoff: a legitimately huge series must paginate. Operational: ExpansionLimit is observable. Violation: an attacker (or a typo) submits FREQ=SECONDLY with no bound → CPU exhaustion / hang.
  • Monotonic and civil clocks are separated. The library models civil/absolute conversion; it never assumes the reading clock is monotonic or disciplined (that is #394). Tradeoff: callers choose which OS clock to read. Operational: durations measured from a monotonic source; instants tagged by scale. Violation: measuring elapsed time across a clock step (NTP slew, DST, leap) → negative or doubled durations — the exact mechanism of the Cloudflare 2017-01-01 leap-second outage (see Failure Modes & Recovery, Phase 7.6).
  • Round-trip fidelity. parse ∘ format == identity within declared resolution; civil_from_days ∘ days_from_civil == identity over the supported range; instant→civil→instant stable under fixed zone+policy. Tradeoff: formatting must preserve enough precision. Operational: property tests assert this continuously. Violation: lossy serialization → silent data corruption in stored timestamps.
  • Overflow is a typed error, never UB or wraparound. Every arithmetic op that can exceed range returns RangeError. Tradeoff: +/- are fallible (checked_*). Operational: callers handle range explicitly at extremes. Violation: wraparound at year boundaries → dates jumping by 2^n, security-relevant in expiry checks.
  • No locale assumptions in core. Month/weekday names, first-day-of-week display, AM/PM are pushed to a LocaleHook; core emits numeric/ISO forms only. Tradeoff: human-facing formatting needs the (stubbed) hook. Operational: core output is locale-stable for machines. Violation: env LC_*/LANG leaks into parsing/formatting → non-reproducible output, parse failures abroad.
  • Parsers are total and bounded. Every parser (TZif, POSIX-TZ, ISO-8601, RRULE) handles all byte sequences: valid → value, invalid → positioned ParseError; allocation bounded by validated counts. Tradeoff: no panic!/unwrap on input paths. Operational: fuzzers must find zero panics. Violation: a truncated TZif or hostile RRULE panics/OOMs the host process.
