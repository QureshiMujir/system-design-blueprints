Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why is the linearization point the level-0 CAS (insert) and the level-0 mark (delete), and not the top-level link? (§22 + ADR-13, synth with MM6/MM7.)
  2. A reader holds a raw pointer to a node; another thread deletes and the allocator reuses its address. Which mechanism prevents the resulting ABA, and why does marking alone not suffice? (§21 pitfalls + §23, ADR-14.)
  3. Derive the expected number of key comparisons for a search at p=1/2 and N=10⁶ from first principles, then say why p=1/4 lowers memory but can raise that count. (Capacity C3/C6 + §18 + ADR-05.)
  4. One thread pins an EBR epoch and then blocks indefinitely. What exactly stalls, what is the blast radius, and which counter detects it before OOM? (§23 + Failure Modes + ADR-14, synth with MM8.)
  5. Show that insert and delete are correct given a correctly filled update[], and identify the one place update[] is subtle (levels above the current list height). (§14 + §15/§16, MM2.)
  6. Why can the sequential SkipList never be made Send + Sync by adding a Mutex around random_level() alone? (§11 Core Schema + ADR-09, synth with §13.)
  7. Explain why a weakly-consistent iterator cannot return an exact len() under concurrency, and what the strongly-consistent alternative costs. (§24 + ADR-25, MM10.)
  8. The 1-2-3 deterministic variant gives worst-case O(log n). What did you trade away versus the randomized list, in both memory and write amplification? (§19 + ADR-10, MM4.)
  9. Why is Acquire/Release sufficient for pointer following but SeqCst required for the epoch-advance check? Give the interleaving that breaks if both used Acquire. (ADR-15 + §23, MM9.)
  10. A differential test against BTreeMap passes but the loom test fails. What class of bug does each catch that the other cannot? (Testing Strategy + ADR-17/ADR-18.)
  11. How does IndexableSkipList keep rank(select(i)) == i through a delete, and which level's span is most error-prone? (§20 + Failure Modes, MM5.)
  12. Justify max_level = 32 for the default p=1/2: what N does it cover, and what degrades past it? (§4 + ADR-06 + Scalability Analysis, synth with C1.)
  13. Why does find re-read from the level entry point after a failed snip-CAS rather than continuing from a cached predecessor? (§22 + §21 pitfalls, MM7.)
  14. Compare the reclamation story of this design to crossbeam-skiplist and to ConcurrentSkipListMap; why does each diverge? (Comparative Architecture + §23 + ADR-22.)
  15. Under what concurrent workload does the lock-free design lose to a simple RwLock<SkipList>, and why? (ADR-12 + Scalability Analysis concurrent curve.)
  16. Where is the per-insert allocation, why is it acceptable in the randomized list, and how does Phase 12's arena change the tradeoff? (ADR-08 + §24, synth with C4.)
  17. Trace a torn-read bug on ARM that never reproduces on x86, naming the missing ordering and the field read uninitialized. (ADR-15/ADR-16 + §11 Core Schema, MM9.)
  18. Why does logical deletion mark top-down but the linearization point sit at the bottom (level 0)? (§22 + MM6, synth with the I-series invariants in §7.)
  19. Given the capacity model, at what N does the working set exceed last-level cache, and how does that move the binding throughput number? (Capacity C5/C7/C8.)
  20. How would you detect, in production telemetry, that an adversary is feeding inputs that push the randomized list toward its O(n) tail — and what is the mitigation? (MM1 + Threat Model + §19.)
  21. The span field doubles tower overhead. When is IndexableSkipList still the right choice over a separate Fenwick tree? (§20 + ADR-11, synth with C11.)
  22. Why is bulk load O(n) and not O(n log n), and what determines each node's height in that path? (§17 + ADR-05, synth with C6.)

Mental Models & First Principles

The compressed insights an expert holds before touching the code. Each: the model, what it predicts, the bug class you write without it, and the resolving section (cited per entry, e.g. "Resolved: §18").

  • MM1 — A skip list is a probabilistic balanced tree whose balance is an expectation, not an invariant. No structural property guarantees O(log n) on any single operation; the geometric height distribution makes it O(log n) in expectation and with high probability. Predicts: the tail is unbounded — a pathological RNG run can produce an O(n) search. Bug without it: writing an SLA or a hard real-time path that assumes worst-case O(log n) from SkipList; treating a slow query as a correctness bug rather than a tail event. Resolved: §18 (Phase 6 analysis); the deterministic escape hatch is §19 (Phase 7).
  • MM2 — The update[] array is the whole algorithm. Search, insert, and delete are one traversal that records, per level, "the last node whose forward pointer I must rewrite." Predicts: insert and delete are trivial given update[]; all the difficulty is filling it correctly. Bug without it: duplicating traversal logic across insert/delete and letting them drift; off-by-one at levels above the current list height. Resolved: §14–§16 (Phases 2–4).
  • MM3 — Height is decided once, at birth, by a coin, and never changes (sequential). A node's tower height is sampled at insert and is immutable; the structure never rotates or rebalances. Predicts: there is no rebalancing cost and no rotation bug — but also no way to "fix" a tall node later. Bug without it: attempting AVL/red-black-style rebalancing on a randomized skip list and corrupting the level invariant. Resolved: §13 (Phase 1), ADR-08. (The deterministic variant breaks this model deliberately — see MM4.)
  • MM4 — The 1-2-3 deterministic skip list is a B-tree of order 2, drawn sideways. A gap of 1/2/3 level-i nodes between consecutive level-(i+1) nodes is exactly a B-tree node of 2/3/4 children; raise = split, lower = merge. Predicts: worst-case O(log n) follows from B-tree theory, not probability; balance is now an enforced invariant. Bug without it: implementing ad-hoc rebalance triggers instead of the split/merge propagation a B-tree mandates. Resolved: §19 (Phase 7), ADR-10.
  • MM5 — A span is "how many level-0 steps does this one pointer skip." Order statistics need no second structure: each forward pointer carries the count of base-level nodes it jumps, and rank is the sum of spans along the search path. Predicts: rank/select are O(log n) and maintained incrementally; insert/delete touch O(log n) spans. Bug without it: keeping a parallel rank array and rebuilding it O(n) per mutation, or mis-attributing a +1 to the wrong level on insert. Resolved: §20 (Phase 8), ADR-11.
  • MM6 — Logical deletion precedes physical deletion; a marked pointer is a tombstone in the low bit. A node is "removed" the instant its level-0 next is marked, long before it is unlinked. Readers must treat marked nodes as absent; unlink is lazy cleanup. Predicts: delete is two phases (mark, then snip), and the linearization point is the mark, not the unlink. Bug without it: treating a logically-deleted node as present, or racing two threads to physically unlink and double-freeing. Resolved: §21–§22 (Phases 9–10), ADR-13.
  • MM7 — Helping is how a non-blocking structure stays live: every traversal cleans up after stalled mutators. When find meets a marked node it CASes it out itself, regardless of whether it is reading, inserting, or deleting. Predicts: a thread suspended mid-delete cannot wedge the list — others finish its unlink — which is exactly what makes the structure lock-free. Bug without it: a dedicated cleanup thread (reintroduces a single point of stall) or unbounded marked-node accumulation. Resolved: §22 (Phase 10), MM6.
  • MM8 — In a GC-free lock-free structure, the hard problem is not the algorithm — it is knowing when a node is safe to free. A reader can hold a raw pointer to a node another thread just unlinked; freeing it is use-after-free, and reusing its address is ABA. Predicts: you need a reclamation scheme (EBR here), and its failure modes (epoch stall, retire backlog) become first-class operational concerns. Bug without it: the classic "it passes stress tests, then segfaults in production under churn" because reclamation was hand-waved. Resolved: §23 (Phase 11), ADR-14.
  • MM9 — Memory ordering is a contract between a publish site and a consume site, not a per-atomic property. A Release store of a pointer "publishes" everything written before it; an Acquire load that reads that pointer "consumes" those writes. Orderings are chosen in pairs. Predicts: a node's key/value are visible to any thread that reaches it via an Acquire load of an Acquire/Release-paired pointer; a single misplaced Relaxed breaks the chain silently. Bug without it: a torn node read (seeing the pointer but not the initialized fields) that appears only on weakly-ordered hardware (ARM), never on x86. Resolved: §22 (Phase 10), ADR-15/ADR-16.
  • MM10 — A concurrent iterator is a weakly-consistent prefix, not a snapshot. Lock-free traversal sees every node present at its start and may or may not see concurrent inserts; it never blocks writers. Predicts: you cannot compute a transactionally-consistent aggregate from a weak iterator; that requires a different (more expensive) mechanism. Bug without it: reporting an exact len() or sum from a weak scan and being subtly wrong under concurrency. Resolved: §24 (Phase 12), ADR-25.

5.4 Specifications / Notes

Harris find contract (Phase 9), named-algorithm prose: find(key, preds[], succs[]) descends from the top level to level 0. Entering each level it loads the successor with Acquire. It advances past any node whose key is < key and past any node whose next is marked (logically deleted); a marked successor is helped out with an AcqRel CAS(preds[level].next, cur → cur.next.unmarked) (snip) before advancing. When it can advance no further it records succs[level] = the first unmarked node with key ≥ key and preds[level] = the last unmarked predecessor, then drops a level. After level 0 it reports membership as succs[0].key == key. Marking encoding and ordering: see the MarkedPtr layout (§8.8) and ADR-13/ADR-16.

EBR protocol (Phase 11 contract). State: a global AtomicUsize epoch cycling 0,1,2 (mod 3); per thread a local_epoch, a pinned flag, and three retire_lists (one per epoch). The four operations, described as named steps:

Op Effect
pin() snapshot local_epoch ← global_epoch (SeqCst); set pinned = true (enters a critical region)
unpin() clear pinned; attempt an epoch advance
retire(p) push p onto retire_lists[local_epoch] (deferred free)
advance() precondition for bumping the global epoch: every thread is either unpinned or already on the current global epoch; on success increment the global epoch and free the now-stale retire list (two epochs behind)

The three-epoch window guarantees no thread still holds a reference into the list being freed.

C11 / Rust atomic memory-ordering rules (applied in skl-concurrent):

Operation Required ordering Rationale
CAS (success) on MarkedPtr AcqRel Publish new node; acquire predecessor's chain
CAS (failure) on MarkedPtr Acquire Read latest pointer; no write needed
load in find() traversal Acquire See all writes before the CAS that set this pointer
store of epoch pin SeqCst Total order with epoch advance check
load in epoch advance check SeqCst Must observe all thread pins
Span/width reads in IndexableSkipList Relaxed (single-threaded crate) No concurrent mutation

Deterministic 1-2-3 invariant (Phase 7 contract):

  • Between any two consecutive level-(i+1) pointers there are exactly 1, 2, or 3 level-i nodes.
  • Insert: if a gap reaches 4, split by raising the middle node to level i+1; propagate upward.
  • Delete: if a gap reaches 0 (merge needed), borrow or merge with neighbor; propagate downward.
  • Worst-case height = ceil(log_{4/3} n) ≈ 2.4 log₂ n; all ops O(log n) worst-case.

Glossary · 43 terms · site-wide glossary

skip list
Probabilistic ordered data structure: a tower of sorted singly-linked lists where level 0 holds every node and higher levels hold geometric-random subsets; expected O(log n) search/insert/delete.
tower
The column of forward pointers belonging to one node across all levels at which it appears (height drawn from geometric distribution).
level
A single horizontal sorted linked list within the tower structure; level 0 is the base (densest), higher levels are sparser.
forward pointer
Node.forward[i]: pointer to the next node at level i; in CNode stored as MarkedPtr with the logical-deletion tag in the low bit.
head sentinel
A dummy node at -∞ with max_level forward pointers; every search starts at its top-level forward pointer.
drop-down search
Core traversal: advance along forward[i] while next.key < target; when blocked, drop to level i-1; repeat until level 0.
update array
update[0..max_level]: predecessor nodes recorded per level during a sequential search; used by insert/delete to splice or unlink.
geometric distribution
Height selection: a node reaches level i with probability p^i; successive fair coin flips with success probability p give tower height.
level generator
LevelGenerator { p_inv, max_level, rng }: generates random tower heights by repeated Bernoulli trials capped at max_level.
parameter p
Promotion probability per level; typical values 1/2 or 1/4; controls space-time trade-off: smaller p → shorter towers + faster search constant but sparser higher levels.
probabilistic balancing
No explicit rebalancing; the geometric distribution ensures O(log n) levels with high probability, analogous to a balanced BST in expectation.
expected height
E[tower height] = 1/(1-p); e.g. p=1/2 → E=2; max_level set to ⌈log_{1/p}(n)⌉.
max level
Hard cap on tower height, typically ceil(log_{1/p}(N_max)); prevents degenerate towers on adversarial Rng seeds.
deterministic skip list
DetSkipList: skip list variant maintaining the gap invariant instead of randomness; achieves worst-case O(log n).
1-2-3 skip list
Specific deterministic variant where between any two consecutive level-(i+1) nodes there are exactly 1, 2, or 3 level-i nodes; insert/delete restore invariant via local restructuring.
gap invariant
The 1-2-3 constraint: 1 ≤ (# level-i nodes between consecutive level-(i+1) nodes) ≤ 3; maintained at all times; ensures O(log n) worst case.
indexable skip list
IndexableSkipList: augments each forward pointer with a span (count of level-0 nodes it skips); enables O(log n) rank/select operations.
span / width
The span stored on forward[i]: number of level-0 positions skipped by one hop at level i; updated incrementally on insert/delete.
rank
rank(key) -> usize: number of keys strictly less than key; computed by summing spans along the search path in IndexableSkipList.
select
select(i) -> Option<&K>: the i-th smallest key (0-indexed); follows forward pointers consuming accumulated spans until total reaches i.
order statistics
The pair (rank, select) provided by IndexableSkipList; analogous to an order-statistics tree; both O(log n).
lock-free
Progress guarantee: at least one thread makes progress in a finite number of steps regardless of scheduling; the ConcurrentSkipList is lock-free (any blocked thread can be helped).
non-blocking
Umbrella term covering lock-free (and stronger: wait-free); used interchangeably for CAS-based structures in this codebase.
CAS
Compare-And-Swap: atomic compare_exchange(expected, new, ord_success, ord_fail); the primitive for lock-free insert and helping-unlink in ConcurrentSkipList.
marked pointer
MarkedPtr<K,V>(AtomicPtr<Node<K,V>>): low bit of the raw pointer encodes logical deletion; set atomically before physical unlink.
logical deletion
First step of ConcurrentSkipList::remove: mark all of the node's forward pointers top-down via CAS; the node is "deleted" once all marks are set, before physical unlinking.
physical unlink
Removal of a marked node from the list's pointer chain via CAS on the predecessor's forward pointer; done lazily by find() traversal or by helping during insert/remove.
helping
When find() encounters a marked pointer, it CASes the predecessor's pointer to skip the marked node, advancing physical cleanup; enables lock-freedom without a dedicated GC thread.
linearizability
Correctness condition: each concurrent operation appears to take effect atomically at some point (linearization point) within its real-time interval; verified via loom harness.
linearization point
The single atomic event that makes an operation visible: insert → CAS that sets the level-0 forward pointer; delete → CAS that sets the first mark on the node.
ABA problem
CAS hazard: pointer changes A→B→A between a read and CAS, making the CAS succeed incorrectly; mitigated by tagged pointers or EBR ensuring nodes are not reallocated while referenced.
epoch-based reclamation (EBR)
Ebr: memory reclamation scheme tracking a global epoch counter + per-thread epoch pins; a thread retires a node to its retire list; the node is freed only once all threads have advanced past the epoch of retirement.
pin
A thread "pins" by reading and recording the global epoch before accessing shared data; while pinned, no node from a previous epoch can be freed under it.
retire list
Per-thread list of (pointer, retirement-epoch) pairs queued for deferred free; drained when the thread detects the global epoch has advanced enough.
quiescent state
A point where a thread holds no references to retired nodes; advancing through a quiescent state allows global epoch advancement and enables retire-list draining.
weakly-consistent iterator
Concurrent iterator that reflects a prefix of insertions/deletions; may miss concurrent updates without throwing; defined contract: sees every node present at construction, may or may not see nodes inserted after.
memory ordering
Rust std::sync::atomic::Ordering (Acquire, Release, AcqRel, SeqCst, Relaxed); ConcurrentSkipList uses Release on CAS-insert at level 0, Acquire on loads to establish happens-before.
acquire / release
Acquire load pairs with Release store to establish happens-before; used at linearization points so a successful CAS publish is visible to subsequent Acquire loads.
loom
Rust model-checking crate (tokio/loom) that systematically explores all interleavings of atomic operations; used in skl-bench's linearizability harness for ConcurrentSkipList.
OrderedMap
pub trait OrderedMap<K: Ord, V> in skl-core: the shared interface implemented by SkipList, DetSkipList, IndexableSkipList, and ConcurrentSkipList.
LevelGenerator
pub struct LevelGenerator { p_inv: u32, max_level: usize, rng: Rng } in skl-core; generates random tower heights via geometric trials; shared across sequential + concurrent variants.
Rng
pub struct Rng(u64) in skl-core; xorshift/wyrand PRNG; fast per-node height sampling on hot insert path; no_std-compatible.
SklError
pub enum SklError { Empty } in skl-core; only error class currently surfaced (e.g. range on empty list).
