Decisions (§9) · 25 ADRs

ADR-01

Implementation language

Chosen

Rust 2021, MSRV 1.78

Rejected

C/C++, Go, Java

When the rejected choice is right

Java/Go when reclamation is not the lesson and a GC is acceptable — ConcurrentSkipListMap ships a correct lock-free map in 1/10th the code because the runtime solves the hardest part. C when embedding in an existing C codebase (Redis t_zset) with no Rust toolchain.

Why: Rust: safe marked-pointer API over unsafe internals; loom model-checker; atomics discipline at compile time. C: no model checker. Go: GC hides reclamation; no marked-pointer control; sync.Map unordered. Java: GC obscures the EBR teaching goal; object headers bloat node layout.

ADR-02

Workspace layout

Chosen

6 crates: skl-core, skl-list, skl-variants, skl-concurrent, skl-bench, skl-cli

Rejected

Single crate; 2-crate split

When the rejected choice is right

A single crate wins for a tiny library with no no_std ambition and one consumer — fewer Cargo.tomls, faster clean builds, no cross-crate version skew; appropriate if only the sequential SkipList ships.

Why: Fine-grained crates enforce dependency direction (core → list/variants/concurrent; bench/cli depend on all); no_std boundary enforced by crate flags rather than features.

ADR-03

no_std + alloc for core/list/variants/concurrent

Chosen

Enabled on skl-core, skl-list, skl-variants, skl-concurrent

Rejected

std everywhere

When the rejected choice is right

std everywhere wins when the only deployment target is an application binary that already links std — std::collections, HashMap-backed thread-local RNG, and std::thread simplify code, and the no_std discipline buys nothing.

Why: Enables embedding in OS kernels, firmware, LSM memtables; forces explicit allocations; atomics available without std. skl-bench, skl-cli are std.

ADR-04

Public ordered-map API

Chosen

OrderedMap<K: Ord, V> trait with get, insert, remove, range, iter

Rejected

Inherent methods only; a more complex SortedMap trait

When the rejected choice is right

Inherent methods win when only one concrete type ever exists and dynamic dispatch / generic monomorphization bloat is undesirable — a trait earns its keep only once two impls must be swapped behind it.

Why: Trait lets skl-bench swap sequential vs concurrent behind one interface for differential tests; Rust Ord bound avoids a custom Comparator object on the hot path (comparator stored separately for callers needing custom ordering).

ADR-05

LevelGenerator default p

Chosen

p = 1/2 (p_inv = 2)

Rejected

p = 1/4 (p_inv = 4), p = 1/e

When the rejected choice is right

p=1/4 wins for memory-bound, cache-sensitive workloads (Redis t_zset uses 1/4): ~1.33n vs 2n pointers shrinks node footprint and fits more nodes per cache line, trading a higher search constant that is hidden by fewer cache misses.

Why: p=1/2: lower constant on expected search comparisons (≈2·log₂n); simplest geometric flip (one RNG bit). p=1/4 saves space (≈4n/3 ptrs vs 2n) but increases constant; p=1/e is theoretical optimum but irrational. API exposes p_inv so callers can override.

ADR-06

max_level cap

Chosen

32

Rejected

64; dynamic; per-instance parameter only

When the rejected choice is right

64 wins when n routinely exceeds 2^32 (very large in-memory indexes at small p, where log_{1/p} N is taller); dynamic growth wins for a library that cannot know n in advance and must avoid degenerate towers without over-provisioning the head sentinel.

Why: 32 covers n up to 2^32 at p=1/2; beyond that expected O(log n) still holds with probability overwhelming; 64 wastes HEAD sentinel space; max_level is also a per-instance constructor arg for flexibility.

ADR-07

Fast per-thread RNG

Chosen

Rng(u64) — wyrand (or xorshift64)

Rejected

rand crate (std), SmallRng, thread-local HashMap RNG

When the rejected choice is right

The rand crate / SmallRng wins when the project already depends on rand, needs cryptographically-seeded or reproducible-across-platforms streams, or wants distribution adapters — paying the dependency for ecosystem-standard RNG quality and audited statistical properties.

Why: wyrand: 1-2 ns/call, no_std-compatible, 64-bit state fits in a register. rand crate adds a heavy dependency + std in some configs. SmallRng acceptable but requires rand dep.

ADR-08

Node tower storage

Chosen

Vec<*mut Node<K,V>> (heap-allocated per node)

Rejected

Fixed array [*mut Node; MAX_LEVEL]

When the rejected choice is right

A fixed inline array wins when max_level is small (e.g. 4–8) and allocation latency dominates: it removes the per-node Vec allocation and indirection, packs the tower into the node for one cache line, and suits arena/slab layouts where every node is the same fixed size.

Why: Vec length = actual tower height → no wasted slots for short towers; p=1/2 gives E[height]=2 so average node holds 2 ptrs. Fixed array wastes 32 slots per node regardless; unacceptable for large n. Downside: Vec allocation per insert; accepted because insert cost already dominates.

ADR-09

Pointer safety boundary

Chosen

unsafe raw pointers internally; safe &self/&mut self public API

Rejected

Rc<RefCell<Node>> / Arc<Mutex<Node>> everywhere

When the rejected choice is right

Rc<RefCell> wins for a single-threaded, all-safe-code teaching implementation where avoiding any unsafe is the priority and the concurrent variant is out of scope — correctness is borrow-checked and the cost is acceptable for non-hot-path use.

Why: Rc/RefCell: no send/sync → concurrent variant impossible. Arc/Mutex: per-node locking contradicts lock-free goal. Raw pointers: unavoidable for lock-free + no_std; encapsulated behind safe traits so callers never touch raw ptrs.

ADR-10

Deterministic variant

Chosen

DetSkipList — 1-2-3 skip list (gap invariant 1..=3)

Rejected

Treap; AVL/red-black rebalance; skip list with explicit rebalance triggers

When the rejected choice is right

A red-black tree wins when the worst-case structure must also be the production structure with the tightest constant and lowest space (no tower overhead at all), and the codebase already wants an in-place pointer tree — e.g. the Linux kernel rbtree and std::collections::BTreeMap's design lineage.

Why: 1-2-3 skip list is isomorphic to a B-tree of order 2 — directly demonstrates worst-case O(log n) without introducing a separate tree structure. Treap = still randomized.

ADR-11

Order-statistics variant

Chosen

IndexableSkipList — span/width count on each forward pointer

Rejected

Augmented BST (order-statistics tree); separate rank array

When the rejected choice is right

A separate rank array (or Fenwick/BIT) wins when the key set is static or append-only and queries dominate: O(1) select and O(log n) rank with far better cache locality than pointer-chasing, at the cost of O(n) rebuild on arbitrary insert/delete.

Why: Span stored inline on the forward pointer; incremental O(log n) maintenance on insert/delete; no extra allocation. Augmented BST would require a second data structure, violating the "skip list native" constraint.

ADR-12

Concurrent design

Chosen

Lock-free: Harris/Fraser marked-pointer + CAS + helping (ConcurrentSkipList)

Rejected

Lock-striped (per-segment mutex); global RwLock<SkipList>

When the rejected choice is right

Lock-striping wins at low-to-moderate core counts and low write contention where its far simpler, easier-to-verify code matters more than the last 2× of scaling; a global RwLock wins for read-mostly workloads on few cores where writes are rare and a snapshot-consistent iterator (impossible lock-free) is required.

Why: Lock-free: scales to high core counts, no deadlock, demonstrates linearizability techniques. Lock-striped: simpler but per-segment lock limits scaling; skl-bench notes it is sufficient for low-concurrency use (documented). Global RwLock: read-scale OK but write bottleneck; rejected for production path.

ADR-13

Linearization point

Chosen

Level-0 CAS (insert) / first successful mark on node.next[0] (delete)

Rejected

Level-top CAS; lock-based critical section

When the rejected choice is right

A lock-based critical section as the LP wins when the structure is already lock-based (ADR-12 lock-striped/RwLock path): the LP is then simply "inside the lock", the proof is trivial, and no marked-pointer machinery is needed.

Why: Level-0 is the only level all traversals must cross — defining LP here gives the cleanest linearizability proof (consistent with Herlihy & Shavit §14).

ADR-14

Memory reclamation

Chosen

EBR via Ebr struct (global epoch, per-thread pin, retire lists)

Rejected

Hazard pointers (HP); reference counting (Arc); deferred free with quiescent-state fence

When the rejected choice is right

Hazard pointers win when bounded memory and predictable reclamation latency are required (real-time / memory-constrained): EBR can stall reclamation indefinitely if one thread fails to quiesce (the epoch-stall failure mode), whereas HP reclaims as soon as the last hazard is dropped. Reference counting (Arc) wins for low-contention structures where simplicity beats throughput.

Why: EBR: low overhead on the common (read-heavy) path — pin is a single atomic load + store. HP: lower latency reclamation but per-pointer overhead on every pointer load (2×store). Arc: atomic refcount on every pointer deref — unacceptable on lock-free hot path.

ADR-15

Memory ordering — reads

Chosen

Acquire on pointer loads in traversal

Rejected

SeqCst; Relaxed

When the rejected choice is right

SeqCst wins when the algorithm needs a single total order across multiple atomics (e.g. a Dekker-style fence or the epoch-advance check, which this design already uses SeqCst for) — there Acquire is insufficient. Relaxed wins for statistics counters where no happens-before is needed.

Why: Acquire pairs with Release stores; sufficient for pointer-following correctness. SeqCst adds a full fence on x86 (mfence vs xchg) — measurable overhead on concurrent bench; rejected. Relaxed unsafe without corresponding Release stores at all publish sites.

ADR-16

Memory ordering — writes

Chosen

Release on CAS / pointer stores that publish nodes

Rejected

Relaxed

When the rejected choice is right

Relaxed writes win for fields that play no part in establishing happens-before — e.g. an approximate length counter or a height-histogram bucket incremented for telemetry, where a stale read is harmless and the fence cost is pure waste.

Why: Ensures that the node's key/value writes are visible to any thread that subsequently loads the pointer with Acquire.

ADR-17

Concurrency model-checker

Chosen

loom (dev-dependency on skl-concurrent tests + skl-bench)

Rejected

shuttle; sanitizers only (ThreadSanitizer)

When the rejected choice is right

shuttle wins when the state space is too large for loom to exhaust (loom's combinatorics explode past a few threads / many atomics): randomized scheduling with a fixed seed covers deep schedules loom cannot reach in bounded time. ThreadSanitizer wins for finding data races in code paths loom does not model (FFI, std sync primitives) on real hardware.

Why: loom: exhaustive interleaving exploration under Rust's memory model — directly detects ABA and ordering bugs in the CAS sequences. shuttle: probabilistic, less exhaustive. TSan: dynamic, misses rare interleavings in CI.

ADR-18

Differential test oracle

Chosen

std::collections::BTreeMap (sequential) + crossbeam-skiplist (concurrent)

Rejected

A hand-verified reference; a separate in-house sorted vec

When the rejected choice is right

A hand-verified in-house sorted vec wins when the oracle itself must be no_std / dependency-free, or when testing a property BTreeMap cannot express (e.g. exact span/rank values for IndexableSkipList, which BTreeMap does not expose) — then a trivially-correct O(n) sorted vec is the oracle.

Why: BTreeMap: stdlib, no extra dep, provides ground truth for get/range/iter semantics. crossbeam-skiplist: independent lock-free skip list implementation — differential concurrent test. Both are dev-dependencies only.

ADR-19

Property + fuzz testing

Chosen

proptest (property); cargo-fuzz / libFuzzer for op-sequence fuzzing

Rejected

QuickCheck; manual random tests

When the rejected choice is right

QuickCheck wins for teams already standardized on it or wanting its simpler, type-class-driven shrinking model; hand-written deterministic random tests win when a fixed corpus must be replayed bit-identically in CI (no shrinker non-determinism) for regression gating.

Why: proptest generates typed op sequences (insert/delete/range); cargo-fuzz drives the fuzzing harness; loom re-runs interesting schedules for concurrent fuzzing.

ADR-20

Benchmarking framework

Chosen

criterion in skl-bench

Rejected

divan; std::time

When the rejected choice is right

divan wins when fast compile times and low-ceremony microbenchmarks matter more than HTML reports and criterion's heavier statistical machinery; raw std::time wins for a one-off throughput number in an integration test where pulling in a bench framework is overkill.

Why: criterion: statistical rigor, HTML reports, wall-clock + instruction counts; widely adopted; dev-only dep.

ADR-21

MSRV

Chosen

1.78

Rejected

1.70 (too old, missing AtomicPtr::compare_exchange ergonomics); stable latest

When the rejected choice is right

Pinning to stable latest wins for an application (not a library) with no external consumers — it can always use the newest APIs and need not support older toolchains; a lower MSRV wins for a foundational library that must compile on enterprise/LTS toolchains years behind stable.

Why: 1.78 stabilized LazyLock, improved AtomicPtr API — used in Ebr; stable enough for CI/CD matrix.

ADR-22

Dependency policy

Chosen

Minimal: zero runtime deps in skl-core/list/variants/concurrent; dev-only: crossbeam-skiplist, criterion, proptest, loom, cargo-fuzz

Rejected

Thin wrappers over crossbeam-epoch for EBR

When the rejected choice is right

Depending on crossbeam-epoch wins for a production library that is not a teaching exercise: it is battle-tested, maintained, and handles edge cases (thread exit, nested pins) a hand-rolled Ebr will get wrong — reinventing it is a liability when EBR is not the deliverable.

Why: Rolling our own Ebr is intentional — the goal is to teach EBR; using crossbeam-epoch as a runtime dep would black-box the mechanism. Crossbeam used only as a benchmark oracle.

ADR-23

License

Chosen

MIT OR Apache-2.0

Rejected

MIT only; GPL

When the rejected choice is right

GPL wins when the goal is to force downstream openness (copyleft as policy) — appropriate for a project that must remain free and prevent proprietary forks; MIT-only wins when even the Apache patent grant is unwanted ceremony for a trivial component.

Why: Dual license matches Rust ecosystem norms; allows embedding in proprietary projects without copyleft concern.

ADR-24

skl-cli binary name

Chosen

sklist

Rejected

skl; skiplist

When the rejected choice is right

skl wins if the shortest possible name is desired and the target environment is known not to ship a conflicting skl binary (e.g. a controlled container image); skiplist wins for maximum discoverability in a crowded $PATH where the explicit name aids users.

Why: Short, unambiguous, matches project colloquial name; avoids collision with skl system tools on some Linux distros.

ADR-25

Concurrent iterator consistency

Chosen

Weakly-consistent (snapshot of nodes encountered during level-0 traversal; may miss concurrent inserts, may see concurrent deletes as absent)

Rejected

Strongly-consistent snapshot (full lock); epoch-pinned snapshot

When the rejected choice is right

A strongly-consistent snapshot wins when a range scan must be transactionally coherent — e.g. computing an exact aggregate over the map, taking a backup, or any reader that cannot tolerate seeing a partial concurrent mutation; there the cost of pausing writers or RCU-copying is justified by the correctness requirement.

Why: Strongly-consistent snapshot requires pausing writers or copying the whole list. Weakly-consistent iterator: standard for production concurrent maps (java.util.concurrent.ConcurrentSkipListMap); documented in API contract; a seqlock/RCU snapshot option is deferred to Phase 12 hardening.

Alternative Architectures (Roads Not Taken)

Fundamentally different ordered-map designs for the same job. Each: sketch, the regime where it wins, the real system that embodies it, why 404 rejected it.

ALT-1 — Red-black / AVL balanced BST.

        (B,7)              balance = enforced invariant (color/height rules)
       /     \             rotations on insert/delete restore it
   (R,3)     (B,9)         worst-case O(log n) guaranteed, no probability
   /   \
(B,1) (B,5)

Wins: hard worst-case latency with the tightest constant and lowest memory (no tower; 2 child ptrs + 1 colour bit). Embodied by: the Linux kernel rbtree, C++ std::map, Java TreeMap. Rejected because: rotations are notoriously hard to make lock-free, defeating 404's concurrency goal; the deterministic O(log n) niche is already covered by DetSkipList (§19, ADR-10) without leaving the skip-list family.

ALT-2 — B-tree / B+-tree (high fan-out, cache-optimized).

            [ 17 | 42 ]                fan-out F (e.g. 16–64 keys/node)
           /     |      \              height ≈ log_F N  ⇒ few cache misses
   [.. <17 ..][17..42][.. >42 ..]      keys packed contiguously per node

Wins: minimizes cache-line/page misses (height log_F N with F≫2), and matches block/SSD I/O — the disk-friendly ordered structure. Embodied by: std::collections::BTreeMap, every B-tree-backed database index, RocksDB SSTable index blocks. Rejected because: node splits/merges under concurrency need either locking or complex lock-free B-tree protocols; 404's mandate is the skip-list family as the in-memory primitive, and the B-tree is the explicit Project 67 sibling (§2.4).

ALT-3 — Lock-free binary search tree (e.g. Ellen et al. external BST).

   internal nodes = routers, leaves = keys
   updates use "operation records" + child CAS
   ┌── flag/mark protocol coordinates concurrent splices ──┐

Wins: a pointer-lean lock-free tree with no tower overhead, competitive for read-mostly ordered sets. Embodied by: the Ellen–Fatourou–Ruppert–van Breugel non-blocking BST (PODC 2010) and derivatives. Rejected because: its operation-record/flagging protocol is materially harder to reason about and model-check than marked-pointer skip-list find+helping (§22), and it offers no clean order-statistics or range story comparable to spans (§20).

ALT-4 — Learned index (model replaces the search structure).

   key ──► [ trained model f(key) ≈ position ] ──► predicted slot
                         │ error bound ε
                         ▼  local search within ±ε in a sorted array

Wins: near-O(1) lookup with tiny memory when the key distribution is learnable and the data is read-mostly/static; can beat comparison trees on lookup latency. Embodied by: Kraska et al. "The Case for Learned Index Structures" (SIGMOD 2018); RMI and successors. Rejected because: updates are the weak point — arbitrary insert/delete invalidate the model and need retraining or a delta buffer — which directly conflicts with 404's write-heavy, mutation-correct concurrent goal (§22) and its expected-balance model (MM1).
