404 — Skip List

Goal: Implement, from scratch in Rust, a probabilistic ordered-map library built around the skip list — the classic sequential skip list (randomized tower heights, search/insert/delete, range scans, ordered iteration), a deterministic 1-2-3 variant for worst-case O(log n), an indexable variant with span/width counts for rank/select order statistics, and a lock-free concurrent skip list (the Fraser/Herlihy-Shavit/ConcurrentSkipListMap design) using marked pointers, CAS, helping, and epoch-based memory reclamation. An analysis harness validates the expected O(log n) bounds and concurrent scaling, benchmarked against BTreeMap and crossbeam-skiplist. It is the in-memory ordered-structure primitive, not a durable store.

1. Goal

Build a from-scratch probabilistic ordered-map library in Rust: a classic sequential skip list, a deterministic (1-2-3) variant, an indexable (order-statistics) variant, and a lock-free concurrent skip list with epoch-based reclamation — packaged as six embeddable crates plus the sklist CLI.

2. Why Build This

2.1 Unique Systems Knowledge Acquired

Three distinct layers of difficulty, each teaching a distinct engineering discipline:

Layer Skill cluster
Probabilistic balancing (sequential) Geometric distributions; expected-value analysis; tower height calibration; p vs height vs search cost trade-off
Deterministic + order-statistics Structural invariant maintenance (1-2-3 gap); incremental span bookkeeping; rank/select in O(log n) without auxiliary arrays
Lock-free concurrent + EBR Marked-pointer CAS protocol; linearization-point identification; HELPING as a liveness mechanism; safe memory reclamation without GC

The lock-free layer is the deep part: a correct ConcurrentSkipList with MarkedPtr, helping, and EBR is one of the hardest standard data structures to implement correctly and verify. Loom elevates this from "probably correct" to model-checked.

2.2 Historical and Architectural Significance

System Skip-list role

LevelDB / RocksDB (Project 68 cross-link) Skip list is the canonical LSM memtable; in-memory sorted buffer before compaction to SSTables

2.3 Engineering Muscles

  • Probability + expected-value reasoning — proving O(log n) from geometric tower height; empirically verifying constants via histogram.
  • Lock-free reasoning — identifying linearization points; proving that helping makes delete wait-free for the deleter; ABA avoidance via EBR (not counted pointers — EBR is simpler and idiomatic in Rust).
  • Memory ordering — choosing Acquire/Release vs SeqCst at each CAS; load+mark sequences; proving no torn reads.
  • Model checking — using loom to replace std::sync::atomic and exhaustively explore interleavings; catching bugs that stress tests miss.
  • unsafe Rust discipline — raw pointer towers (sequential list); AtomicPtr + pointer tagging (concurrent list); maintaining invariants across unsafe boundaries.

2.6 What Mastery Looks Like

The reader who finishes this blueprint can do the following — each competency tied to the phase that confers it:

  • Derive the O(log n) bound from scratch — solve Pugh's expected-search recurrence and pick p/max_level for a target n by hand, not by quoting a table (Phase 6, §18; calibrated against ADR-05/ADR-06).
  • Maintain a non-trivial structural invariant under mutation — restore the 1-2-3 gap on every insert/delete and argue worst-case height without a high-probability hedge (Phase 7, §19).
  • Augment a search structure for order statistics — keep spans correct through splice and unlink, and prove rank(select(i)) == i (Phase 8, §20).
  • Write a correct two-phase lock-free delete — mark-then-unlink with HELPING, and name the single CAS that is the linearization point (Phase 9–10, §21–§22; ADR-13).
  • Choose memory orderings deliberately — justify Acquire/Release at each publish/consume site and prove no torn node read (Phase 10, §22; I-series ordering invariants).
  • Reclaim memory without a GC — build EBR (epoch, pin, retire) and explain why a single stalled reader stalls all reclamation (Phase 11, §23; ADR-14).
  • Model-check a concurrent structure — drive loom to exhaust interleavings and read a failing schedule back to the offending CAS (Phase 13, §25; ADR-17).
  • Falsify a structure differentially — run the same op log against BTreeMap/crossbeam-skiplist oracles and localize the first divergence (Phase 13, §25; ADR-18).

3.3 Component Responsibilities

skl-core — shared vocabulary; zero data structures, only traits + tiny types.

  • OrderedMap<K,V> trait: get / insert / remove / range / iter; all variants implement it.
  • LevelGenerator: geometric distribution with p_inv (e.g. 2 → p=1/2, 4 → p=1/4); random_level() flips until fail or max_level; E[height] = 1/(1−p).
  • Rng(u64): xorshift / wyrand; no_std; seeded per-thread; <5 ns per call.
  • Comparator: newtype over key comparison; supports reverse and custom orderings.
  • SklError { Empty }: thin error enum; future variants behind feature flags.
  • Invariant: no heap allocation; no unsafe.

skl-list — sequential SkipList — the canonical Pugh structure.

  • Node<K,V>: key, value, forward: Vec<*mut Node<K,V>>; forward[0] = level-0 successor.
  • SkipList<K,V>: head (sentinel, max_level forward nulls), level (current top level), max_level, len, gen: LevelGenerator.
  • Search path: start at head.forward[level-1]; advance while forward[i].key < target; drop down; record update[i] at each drop.
  • Insert: fill update[] via search; random_level() → L; allocate Node; splice into forward[0..L]; bump level if L > level.
  • Delete: fill update[]; unlink node at each i it appears; shrink level while head.forward[level-1] is null.
  • Invariant: forward[0] traversal yields all keys in ascending order at all times.
  • Phase refs: search → §14; insert → §15; delete → §16; range → §17; analysis → §18.

skl-variants — DetSkipList — deterministic worst-case O(log n).

  • Maintains gap invariant: between any two consecutive level-(i+1) pointers there are exactly 1, 2, or 3 level-i nodes.
  • Insert: may trigger a cascade of raises to restore the invariant; analogous to B-tree node splitting.
  • Delete: may trigger lowering; analogous to B-tree underflow merge/redistribute.
  • Isomorphic to a B-tree with fanout 2–4; gives same worst-case guarantee without rotations.
  • Phase ref: §19.

skl-variants — IndexableSkipList — order-statistics via span counts.

  • Each forward[i] pointer carries a span: usize = number of level-0 nodes it skips over (including the pointed-to node).
  • rank(key): walk search path; accumulate span for each forward step taken; O(log n).
  • select(i): walk forward consuming span until i is exhausted; O(log n).
  • Insert/delete: update spans on update[] predecessors; O(log n) incremental maintenance.
  • Invariant: sum of all level-0 spans = len; sum of spans on any level path = exact node count skipped.
  • Phase ref: §20.

skl-concurrent — MarkedPtr + ConcurrentSkipList — lock-free ordered map.

  • MarkedPtr<K,V>(AtomicPtr<CNode<K,V>>): low bit = logical-delete mark; is_marked() checks bit; unmark() strips it; pointer arithmetic avoids alignment UB via repr(C) on CNode.
  • CNode<K,V>: key, value, top_level: usize, next: Vec<MarkedPtr<K,V>>.
  • ConcurrentSkipList: head: *const CNode<K,V> (never reclaimed), max_level, gen: LevelGenerator, ebr: Ebr.
  • find(key, preds, succs): for each level top→bottom, advance while next < key; if next is marked, CAS it out (HELPING); record preds[i] and succs[i]; return found: bool.
  • Insert: find(); if found → Err; allocate CNode; CAS preds[0].next[0] to new node (level-0 link = linearization point); then CAS upper levels bottom-up (best-effort; incomplete towers are safe).
  • Delete: find(); mark next[top..=0] top-down (logical delete); physical unlink via next find() call that traverses and helps CAS them out.
  • Helping ensures wait-free delete for the deleter; any thread meeting a marked node removes it.
  • Phase refs: lock-free foundations → §21; full ConcurrentSkipList → §22; EBR → §23.

skl-concurrent — Ebr — epoch-based reclamation.

  • Global epoch counter (0/1/2 cycling); per-thread Pin struct increments on guard entry.
  • retire(ptr): pushes ptr onto per-thread retire list tagged with current epoch.
  • Epoch advance: when all threads have observed the current epoch (all pins ≥ current), advance global epoch; free retire-list entries from epoch − 2.
  • Quiescent state: between operations (no live guard held).
  • Invariant: a retired node is freed only after every thread that could have read it has passed a quiescent state.
  • Phase ref: §23.

skl-bench — analysis and validation harness.

  • Height distribution: histogram of random_level() outputs; compare to geometric PMF.
  • O(log n) empirical: time get at n = 10³, 10⁴, 10⁵, 10⁶, 10⁷; fit log curve; assert slope matches 1/(1−p)·log₂(n).
  • Sequential throughput: SkipList vs std::BTreeMap at varied p and n.
  • Concurrent scaling: ConcurrentSkipList ops/sec/core at 1, 2, 4, 8, 16 threads; assert near-linear read scaling.
  • Loom harness: tiny ConcurrentSkipList (≤4 nodes) under loom scheduler; assert no data races + linearizability of concurrent insert/delete/get sequences.
  • Phase ref: §25.

skl-cli — sklist binary — developer and demonstration interface.

  • Subcommands: insert <k> <v>, get <k>, del <k>, range <lo> <hi>, rank <k>, select <i>, load <file> (bulk sorted input), stats (level histogram, height, len), bench, viz (ASCII tower dump).
  • --variant sequential|deterministic|indexable|concurrent selects the backend.
  • --p and --max-level configure LevelGenerator.
  • Phase ref: §25.

3.4 Data Flow — Insert (Sequential)

caller: insert(k, v)
  → SkipList::insert
    → search fills update[0..level]: per-level last node with key < k
    → LevelGenerator::random_level() → picked height L
    → allocate Node { key=k, value=v, forward = L null slots }
    → splice levels 0..L: new node's forward[i] takes update[i].forward[i];
       update[i].forward[i] now points at the new node (linearizes per level)
    → if L exceeds self.level: head.forward[self.level..L] point at new node; self.level ← L
    → self.len incremented by 1

Splice order is bottom-up; level-0 is the canonical successor chain. Cost: expected O(log n) (M-series, Performance Engineering).

3.5 Data Flow — Concurrent Delete (Lock-Free)

caller: remove(k)
  → ConcurrentSkipList::remove
    → find(k, preds, succs) → found=true, victim = succs[0]
    → logical delete, top-down (level victim.top_level down to 1):
        each victim.next[i] CAS'd unmark → mark
    → victim.next[0] CAS'd unmark → mark  (level-0 mark = linearization point of delete)
    → retire(victim) via Ebr             (physical unlink deferred to helping)

Top-down marking means an upper-level pointer is never observed marked while a lower one is still live; the level-0 mark is the single point at which the key becomes logically absent.

5.4 Specifications / Notes

Harris find contract (Phase 9), named-algorithm prose: find(key, preds[], succs[]) descends from the top level to level 0. Entering each level it loads the successor with Acquire. It advances past any node whose key is < key and past any node whose next is marked (logically deleted); a marked successor is helped out with an AcqRel CAS(preds[level].next, cur → cur.next.unmarked) (snip) before advancing. When it can advance no further it records succs[level] = the first unmarked node with key ≥ key and preds[level] = the last unmarked predecessor, then drops a level. After level 0 it reports membership as succs[0].key == key. Marking encoding and ordering: see the MarkedPtr layout (§8.8) and ADR-13/ADR-16.

EBR protocol (Phase 11 contract). State: a global AtomicUsize epoch cycling 0,1,2 (mod 3); per thread a local_epoch, a pinned flag, and three retire_lists (one per epoch). The four operations, described as named steps:

Op Effect
pin() snapshot local_epoch ← global_epoch (SeqCst); set pinned = true (enters a critical region)
unpin() clear pinned; attempt an epoch advance
retire(p) push p onto retire_lists[local_epoch] (deferred free)
advance() precondition for bumping the global epoch: every thread is either unpinned or already on the current global epoch; on success increment the global epoch and free the now-stale retire list (two epochs behind)

The three-epoch window guarantees no thread still holds a reference into the list being freed.

C11 / Rust atomic memory-ordering rules (applied in skl-concurrent):

Operation Required ordering Rationale
CAS (success) on MarkedPtr AcqRel Publish new node; acquire predecessor's chain
CAS (failure) on MarkedPtr Acquire Read latest pointer; no write needed
load in find() traversal Acquire See all writes before the CAS that set this pointer
store of epoch pin SeqCst Total order with epoch advance check
load in epoch advance check SeqCst Must observe all thread pins
Span/width reads in IndexableSkipList Relaxed (single-threaded crate) No concurrent mutation

Deterministic 1-2-3 invariant (Phase 7 contract):

  • Between any two consecutive level-(i+1) pointers there are exactly 1, 2, or 3 level-i nodes.
  • Insert: if a gap reaches 4, split by raising the middle node to level i+1; propagate upward.
  • Delete: if a gap reaches 0 (merge needed), borrow or merge with neighbor; propagate downward.
  • Worst-case height = ceil(log_{4/3} n) ≈ 2.4 log₂ n; all ops O(log n) worst-case.

6. Design Principles

P1 — Probabilistic balance; no rotations

Random tower heights (geometric, parameter p) give expected O(log n) with zero rotation logic. Trade: worst-case O(n) on adversarial seed if Rng is predictable → DetSkipList (1-2-3) as the hard-guarantee variant. Violating it (e.g., always height 1) collapses to O(n) linked-list. Operational: seed Rng from a thread-local or user-supplied seed so tests are reproducible; production seeds from OS entropy.

P2 — One OrderedMap trait across all variants

get / insert / remove / range / iter presented identically whether backed by SkipList, DetSkipList, IndexableSkipList, or ConcurrentSkipList. Trade: ConcurrentSkipList::insert takes &self (interior mutation) → the trait uses an associated AccessMode or two blanket impls; the extra indirection is acceptable. Violating it forces callers to switch APIs on variant switch, breaking substitutability.

P3 — Reproducible randomness; no nondeterministic tests

Rng(u64) (wyrand/xorshift) is seedable. Every test that exercises probabilistic behavior seeds the Rng from a fixed constant; proptest seeds are logged on failure. Violating it produces flaky tests that are unreplayable. Operational: LevelGenerator::with_seed(s) for test constructors; production path seeds from thread-local RNG seeded at startup.

P4 — Level-0 list is the single source of truth

Every key appears exactly once at level 0 in sorted order; upper levels are an index (probabilistic or deterministic). Invariant: the len counter counts level-0 nodes only. range() and iter() walk level 0 exclusively. Violating it (e.g., removing from upper levels only) leaves stale keys reachable from level 0.

P5 — Lock-free reads never block writers; writers never block readers

ConcurrentSkipList::get holds a pin but takes no locks; a stalled reader cannot stall an inserter or deleter. Trade: readers may see a slightly stale level-0 snapshot (a key just logically deleted but not physically unlinked is invisible — its mark bit is checked). Violating it (a lock on any read path) invalidates the non-blocking progress guarantee and kills scalability under read-heavy workloads.

P6 — Mark then unlink; never unlink without marking first

Logical deletion (set mark bit on MarkedPtr for every level, top-down) happens atomically before physical unlinking. Any concurrent traversal that encounters a marked node CASes it out (HELPING). Violating it (physical removal without prior marking) allows a concurrent insert to splice a new node after a freshly-removed one, then lose it when the remove's CAS unlinks the predecessor — corrupting the list.

P7 — Define and prove linearization points explicitly

insert linearizes at the level-0 CAS success; remove linearizes at the top-level mark CAS success. Both are documented as comments adjacent to the CAS site in skl-concurrent. Violating it (ambiguous linearization) makes the concurrent correctness argument informal and untestable by loom.

P8 — Reclaim with epochs; never free early

A retired node enters the epoch-local retire list; it is freed only after the global epoch has advanced twice (all threads have passed through a quiescent state). Violating it (free on physical unlink) causes use-after-free: another thread's find() may be reading the node's key for comparison at the moment of free. This is the most common lock-free bug.

P9 — Model-check concurrency with loom; this is mandatory

skl-bench's loom harness runs the concurrent skip list under loom's controlled scheduler, exhausting all interleavings for small (3–4 thread, 5–8 op) programs. Violating it (ship without loom) means correctness is asserted by code review only; loom has historically found mark/CAS ordering bugs in skip-list implementations that review misses.

P10 — Bench against std::collections::BTreeMap and crossbeam-skiplist

skl-bench measures: sequential random insert/get/remove (ns/op vs BTreeMap); concurrent throughput at 1/2/4/8/16 threads (Mops/s vs crossbeam-skiplist); range scan throughput (MB/s). Without a concrete baseline the performance claims are unverifiable. Violating it (benchmark only against self) hides cases where the implementation is slower than BTreeMap at low thread counts.

P11 — Bounded max_level; never grow the tower unboundedly

max_level is set at construction as ceil(log_{1/p} N_expected) and is immutable. A tower is always capped at max_level. Violating it allows a pathological Rng to produce a tower of height 10⁶ for n = 100 nodes, wasting memory and making the level-shrink logic unboundedly slow.

P12 — no_std + alloc for core, std only at the edges

skl-core, skl-list, skl-variants, skl-concurrent compile without std; they use alloc::{vec, boxed, collections}. skl-bench and skl-cli are std. Violating it (pulling std into core crates) blocks embedding in kernel modules, embedded RTOS, or Wasm runtimes — all plausible skip-list embedding targets.

P13 — Unsafe is bounded and auditable

All raw pointer dereferences and AtomicPtr loads live in skl-list::node, skl-concurrent::list, and skl-concurrent::ebr. Each unsafe block has a // SAFETY: comment stating the invariant it relies on. Violating it (unsafe spread across modules) makes soundness auditing O(codebase) instead of O(unsafe-surface).

P14 — Span invariant is maintained incrementally, not recomputed

IndexableSkipList updates each affected forward pointer's span during insert/delete (same O(log n) traversal; no full recount). Violating it (recount after each op) makes rank/select O(n) in practice despite the O(log n) proof.

P15 — The deterministic variant is a strict superset of the sequential API, not a workaround

DetSkipList exports the same OrderedMap API and is benchmarked on the same workloads. It exists to provide worst-case guarantees, not as an emergency fallback. Violating it (treating it as untested dead code) means users have no verified path to hard latency bounds.

8.5 Probability Model

Core probability:

Quantity Formula p=1/2 p=1/4
P[node at level ≥ i] p^(i−1) (1/2)^(i−1) (1/4)^(i−1)
E[tower height] 1/(1−p) 2 4/3
E[forward ptrs/node] 1/(1−p) + max_level·p^max_level ≈2 ≈4/3
E[total forward ptrs] n/(1−p) 2n 4n/3
max_level (cap) ⌈log_{1/p}(n)⌉ ⌈log₂(n)⌉ ⌈log₄(n)⌉
Expected search cost (1/p)·log_{1/p}(n) + 1/(1−p) ≈2·log₂(n) ≈(4/3)·log₄(n)+4/3

Search cost derivation sketch:

  • At level i, expected nodes traversed before dropping down = 1/(1−p) (geometric).
  • Number of levels = log_{1/p}(n) in expectation.
  • Total expected comparisons = O(log n); constant factor ≈ 1/(p·ln(1/p)).

Tail bound (Pugh): P[search cost > c·log n] ≤ 1/n^(c-1) for suitable c; probability of exceeding 3·log n is polynomially small.

p choice: p=1/2 default (balanced: lower constant vs p=1/4's smaller space cost; p=1/4 suits memory-constrained no_std).

8.6 Deterministic 1-2-3 Skip List — Gap Invariant + B-Tree Correspondence

Gap invariant: between any two consecutive level-(i+1) nodes, the number of level-i nodes is ∈ {1, 2, 3}.

Worked insert rebalance (gap violation = 4):

Before: ... A(L2) --[4 L1 nodes]--> B(L2) ...
         A-L2 -- n1 -- n2 -- n3 -- n4 -- B-L2 (gap=4 at L2: VIOLATION)
Action:  Raise n2 to L2 → split gap into (1 + 1 + 2) or similar ≤3 segments.
         A-L2 -- n1 -- n2(L2) -- n3 -- n4 -- B-L2  (gaps = 1, 2 ✓)

Insert: find insertion point; insert at level 0; walk up, check gap — if gap = 4, raise middle node, possibly cascading up.

Delete: remove node; check gap — if gap = 0 (two consecutive level-i+1 nodes adjacent), lower one; if gap causes upward violation, cascade.

B-tree correspondence:

B-tree (order 2) 1-2-3 skip list
Internal node with fanout 2–4 Raised node covering gap 1–3
Split when fanout = 5 Raise when gap = 4
Merge when fanout = 1 Lower when gap = 0
Tree height = O(log n) (worst-case) Level count = O(log n) (worst-case)

Worst-case: O(log n) search + O(log n) rebalance; no randomness required.

8.7 Indexable Skip List — Span Mechanism, rank + select

Span: each forward pointer forward[i] carries an integer span = number of level-0 nodes it skips over (including the destination node at level 0, counted once).

Annotated diagram (spans in parentheses):

Level 2: HEAD --(3)--> 30 --(3)--> 60 --> NIL
Level 1: HEAD --(2)--> 20 --(1)--> 30 --(2)--> 50 --(1)--> 60 --> NIL
Level 0: HEAD --(1)--> 10 --(1)--> 20 --(1)--> 30 --(1)--> 40 --(1)--> 50 --(1)--> 60 --> NIL

rank(key=50) — count level-0 nodes strictly before 50:

cur=HEAD, rank=0, i=2
  forward[2].key=30 < 50  → rank += span[2]=3, cur=30
  forward[2].key=60 ≥ 50  → drop i=1
  forward[1].key=50 ≥ 50  → drop i=0
  forward[0].key=50 ≥ 50  → stop
  rank = 3  (keys 10, 20, 30 are before 50; off-by-one: check = 3 ✓)

select(i=4) — the 4th node (0-indexed) = key 40:

cur=HEAD, remaining=4, i=2
  span[2]=3 ≤ 4  → remaining -= 3 = 1, cur=30, advance
  span[2]=3 > 1  → drop i=1
  span[1]=2 > 1  → drop i=0
  span[0]=1 ≤ 1  → remaining -= 1 = 0, cur=40
  result: &40  ✓

Span maintenance on insert (new node at position r, tower height h):

  • For each level i where update[i] precedes new node: new.span[i] = update[i].span[i] - (r - rank_of_update[i]); update[i].span[i] = r - rank_of_update[i] + 1.
  • For levels above new node's height: update[i].span[i] += 1.

On delete: reverse the span arithmetic; all O(log n) because the search path visits O(log n) nodes.

Concurrent Insert (CAS bottom-up, level-0 = linearization point)

Concurrent insert, named-algorithm prose. First find(key, preds, succs) fills preds[i] (predecessor at level i, snipping marked nodes en route) and succs[i] (successor at level i). A fresh CNode(key, value, top_level=L) is allocated and its next[0..=L] slots are initialised (plain stores, before the node is reachable) to the recorded succs[i].

The linearization point is the level-0 link: a single CAS(preds[0].next[0], succs[0] → new). If it fails (a concurrent writer changed level 0), find re-runs to refresh preds/succs and the CAS is re-attempted; the node is published the instant this CAS succeeds. Higher levels (1..=L) are then linked the same way — each CAS(preds[i].next[i], succs[i] → new), refreshing via find on failure — but this is post-LP work: the node is already reachable at level 0, so a stall here only costs index quality, never correctness.

Why level-0 is the linearization point: a concurrent get traversing level 0 either sees the new node (returns it) or misses it (as if insert hadn't happened) — exactly one of these is consistent with any serial order.

Concurrent Delete (mark top-down → helping unlink)

Concurrent delete, named-algorithm prose. Logical delete marks every pointer of the victim top-down (level top_level down to 0). At each level the victim's next[i] is read: if it is already marked another thread won the race for that level and this level is done; otherwise a CAS(node.next[i], ptr → marked(ptr)) sets the mark, retrying on a benign CAS failure. The level-0 mark is the linearization point of the delete.

Physical unlink is not performed by the deleter directly: it calls find(key, preds, succs), whose snipping splices the marked node out of every level. This is the helping mechanism — any thread that later traverses through the marked node unlinks it.

Helping invariant: find() always CASes away marked successors before returning preds/succs. Physically unlinked nodes are retired to EBR; any thread pinned to current epoch defers their deallocation.

ABA Scenario + Avoidance

Thread T1: reads preds[0] -> A, succs[0] -> B; preempted.
Thread T2: deletes B, then inserts B' at same address (memory reuse without EBR) → A.next = B'.
T1 resumes: CAS(A.next, B, new) succeeds — but B ≠ B'; ABA corruption.

Avoidance:

  1. Marked pointers: a node is logically deleted (marked) before physical unlink; find() CASes away marked nodes rather than re-using them — so preds[0] is always an unmarked node.
  2. EBR (Ebr): retired nodes are freed only after all current epoch readers exit — no memory reuse while any thread holds a pointer to B.
  3. Mark-then-unlink ordering: once marked, a node's pointer cannot be CASed by an inserting thread (mark check precedes CAS in find()).

    ///   2. Physical unlink: call find(), which snips marked nodes as a side effect (HELPING).
    pub fn remove(&self, key: &K) -> Option<V>;
}

11.5 Cross-Cutting Invariants and Memory Ordering Summary

Type Thread Safety Ownership Key Invariant
SkipList<K,V> single-thread owns Node via raw ptrs; Drop frees forward[0] chain is sorted, no gaps
DetSkipList<K,V> single-thread same gap invariant: 1–3 level-i nodes between consecutive level-(i+1) nodes
IndexableSkipList<K,V> single-thread owns INode span sum across level = total node count below
ConcurrentSkipList<K,V> Send+Sync EBR owns retired CNodes marked bit → logically deleted; physical unlink via helping
MarkedPtr<K,V> atomic borrows CNode low bit = mark; Acquire load / AcqRel CAS / Release store
Ebr Send+Sync reclaims retired ptrs after epoch advance no thread references a retired node after 2 epoch rotations

Linearization points:

  • ConcurrentSkipList::insert → level-0 CAS succeeds (node becomes visible).
  • ConcurrentSkipList::remove → mark of level-0 next pointer succeeds (node logically gone).
  • ConcurrentSkipList::get → Acquire load of succs[0] after find() returns true.

Memory ordering discipline (skl-concurrent):

  • MarkedPtr::load → Acquire; ensures subsequent reads of node fields see initialised values.
  • MarkedPtr::compare_exchange success → AcqRel; failure → Acquire.
  • Head sentinel stored once at construction with Release; subsequent loads Acquire.
  • cfg(loom) replaces core::sync::atomic entirely; CI runs loom with LOOM_MAX_PREEMPTIONS=3.

2.2 Detailed Implementation Steps

skl-list/src/search.rs (internal; called by SkipList methods). Algorithm (named, not coded) — drop-down/forward search: start at the head sentinel on the top live level (self.level - 1, 0-indexed). At each level advance to the next node while that node exists and its key is < the target; when it cannot advance, drop one level, carrying the current node down. At level 0 the candidate is the current node's level-0 successor; the key is present iff that candidate exists and its key equals the target. Expected O(log n) levels and steps.

Signature:

pub(crate) fn search<K: Ord, V>(
    head: *mut Node<K,V>, level: usize, key: &K,
) -> Option<*mut Node<K,V>>;   // returns matching node ptr or null

pub(crate) fn search_update<K: Ord, V>(

) -> bool;   // true if key already present

update[i] = the last node at level i whose forward[i].key < key (or head if none). Levels above list_level → update[i] = head (consistent with future inserts raising the list level).

15. Phase 3 — Sequential insert

3.1 Objectives

  • Implement SkipList::insert in skl-list/src/list.rs: search → update[] → allocate node → splice at all levels.
  • Duplicate key: overwrite value, return Some(old_value); new key: return None.
  • Grow self.level when picked tower height L > current level; update head sentinel's forward[self.level..L].
  • Post-condition: level-0 is a sorted singly-linked list; level-i is a sorted subset of level-(i-1); self.len accurate.

3.2 Detailed Implementation Steps

File: skl-list/src/list.rs — add impl<K: Ord, V> SkipList<K, V>.

search_update(key) -> (*mut Node, [*mut Node; MAX_LEVEL]), named-algorithm prose: begin at the head with update[] pre-filled with the head. Descending from the top live level to level 0, advance along each level while the next node exists and its key is < the target, then record that level's last visited node into update[i] before dropping down. On return, update[0].forward[0] is the first node with key ≥ target. Expected O(log n).

insert(key, value) -> Option<V>, named-algorithm prose:

  1. Run search_update(&key) to populate update[]. The duplicate candidate is update[0].forward[0].
  2. Duplicate key (candidate exists and its key equals key): overwrite the value in place with mem::replace and return Some(old_value); len unchanged.
  3. New key: pick a tower height lvl = gen.random_level() (1..=max_level). If lvl exceeds the current list level, point the entries self.level..lvl of update[] at the head (so the new top levels link from the sentinel) and raise self.level to lvl.
  4. Allocate Node { key, value, forward = lvl null slots } (via Box::into_raw).
  5. Splice levels 0..lvl: the new node's forward[i] takes update[i].forward[i], then update[i].forward[i] is repointed to the new node.
  6. Increment len; return None.
  • Node::forward is Vec<*mut Node<K,V>>; allocated length = picked level (not max_level) → minimal allocation.
  • random_level: xorshift64 in Rng; loop while rng.next_u64() < u64::MAX / p_inv and count < max_level.
  • Head sentinel allocated with forward: vec![null; MAX_LEVEL]; never holds a key.
  • impl Drop for SkipList: walk level-0, Box::from_raw each non-head node.

16. Phase 4 — Sequential delete

4.1 Objectives

  • Implement SkipList::remove in skl-list/src/list.rs: search → fill update[] → check key match → unlink at all levels → free node → shrink level.
  • Missing key: return None without mutation.
  • Empty list: return None; no UB on null dereference.
  • Post-condition: sorted invariant preserved; self.len decremented; self.level shrunk to highest non-empty level.

4.2 Detailed Implementation Steps

File: skl-list/src/list.rs — add remove to existing impl<K: Ord, V> SkipList<K, V>.

remove(key: &K) -> Option<V>, named-algorithm prose:

  1. Run search_update(key) to fill update[]; the target is update[0].forward[0].
  2. Miss (target is null or its key ≠ key): return None, no mutation.
  3. Unlink: across every live level, wherever update[i].forward[i] points at the target, repoint it to the target's own forward[i] (the target drops out of that level). A level where the node never appeared is left untouched — correct because update[i] is the last node at level i with key < target.
  4. Shrink level: while the list has more than one level and the head's top live level points at nothing, drop self.level by one.
  5. Decrement len, reclaim the node with Box::from_raw (its key/forward drop, its value is moved out), and return Some(value).
  • Unlink loop iterates (0..self.level).rev() then checks update[i].forward[i] == node; a level where the node doesn't appear is skipped automatically — correct because search_update fills update[i] = last node at level i with key < target.
  • Box::from_raw(node) reclaims heap; .value moved out via Some(owned.value); .key and .forward drop normally.
  • search_update is shared with insert; no duplication.
  • Level shrink: loop while self.level > 1 && head.forward[self.level-1].is_null().

Theory anchors: unlink-per-level via the shared update[] array → Pugh P1 §3 delete routine; Box::from_raw reclamation → ADR-09 (sequential analogue of the EBR retire in ADR-14/§23); level-shrink + len decrement preserve the sorted + height invariants (I-series, §7); differential check vs BTreeMap → ADR-18.

5.7 Performance Concerns

Iter is lazy (no Vec allocation); collect() in tests is for assertion only. successor/predecessor each O(log n); no amortization needed.

5.8 Edge Cases

Empty list iteration: Iter { current: head.forward[0] } → null → next() returns None immediately. Single-element list: iter yields exactly one item; range may yield 0 or 1. Bulk load with duplicate keys in input: spec requires sorted input; duplicates → UB (caller must dedupe, debug_assert). successor of max key: update[0].forward[0] is null → None. predecessor of min key: update[0] is head → None. Mutation during iter: Iter holds &'a SkipList; mutable borrow excluded by borrow checker.

// Traverses snipping every marked curr via CAS(pred.next, (curr,false), (curr.next_unmarked,false))
// Returns when curr is unmarked and curr.key >= key.
// insert(key, val) -> bool  { find; if found return false; CAS pred.next }
// delete(key)     -> bool  { find; if !found return false;

6 Wrong Ordering on logical-delete CAS Relaxed mark CAS lets other thread see unmarked node after visible deletion Use AcqRel on all mutation CAS; Acquire on all loads in find

9.7 Performance Concerns

  • find is O(n) in worst case if many stale marked nodes accumulate before a traversal; bounded in practice when EBR reclaims promptly (Phase 11).
  • Each CAS failure causes a full re-traversal from head — acceptable at level 0 (bounded list length) but motivates per-level entry points in Phase 10.
  • load_mark_ref must not be inlined if compiler re-orders the load past a CAS; use #[inline(never)] in loom builds or assert with loom's atomic::fence.
  • Miri is ~100× slower; limit Miri fixtures to N ≤ 500.

9.8 Edge Cases

  • Empty list: head.next = null; find returns (head, null, false) — insert CAS target is null.
  • Single-node list, delete that node: logical-delete CAS, then find from head snips it; list returns to empty.
  • Concurrent inserts of equal keys: only one CAS on pred.next wins; loser re-calls find, sees key present, returns false.
  • Key at i64::MIN or i64::MAX: sentinel uses a type-level negative-infinity sentinel node (not a valid K value); CNode carries Option<K> where None = sentinel.
  • Marked head sentinel: must never be marked; assert head.load_mark_ref().1 == false in debug builds on every find entry.

find.rs — multi-level find, signature:

fn find<K: Ord, V>(
    head: *const CNode<K,V>, key: &K, max_level: usize,
    preds: &mut [*mut CNode<K,V>], succs: &mut [*mut CNode<K,V>]
) -> bool;

Named-algorithm prose: descend from max_level to level 0. At each level advance the cursor past nodes whose key is < target, skipping (and helping to snip) marked nodes — a marked successor is removed with CAS(preds[i].next[i], (curr,false) → (next_of_curr,false)) and the level is retried from the snip point. Record preds[i] = last unmarked node with key < target and succs[i] = first node with key ≥ target. Membership is reported as succs[0].key == key with succs[0] unmarked. Snipping is best-effort per level: if CAS fails, advance without snipping (another thread helped); correctness unaffected. find always re-reads from the level's entry point after a mark-snip CAS failure, never from a stale local pointer.

insert — fn insert(list: &ConcurrentSkipList<K,V>, key: K, val: V) -> bool; Named-algorithm prose: (1) find(key, preds, succs); if the key is present and unmarked, return false. (2) Allocate a CNode, pick top_level via gen.random_level(). (3) Level-0 link = LINEARIZATION POINT: set new.next[0] = succs[0], attempt CAS(preds[0].next[0], (succs[0],false) → (new,false)); on failure re-run find and retry — the node becomes visible the instant this CAS succeeds. (4) Higher levels (1..top_level), post-LP: for each, set new.next[i] = succs[i], attempt CAS(preds[i].next[i], (succs[i],false) → (new,false)), refreshing preds/succs via find on failure — the node is already reachable at level 0, so these add index quality, not correctness.

remove — fn remove(list: &ConcurrentSkipList<K,V>, key: &K) -> bool; Named-algorithm prose: (1) find(key, preds, succs); if not found, return false. (2) victim = succs[0]. Logical delete, top-down (level top_level down to 1): mark each next[i] with CAS(mark false → true); a benign CAS failure means reload and retry, and if another thread already marked the level, proceed. (3) Mark next[0] = LINEARIZATION POINT: the CAS that sets the level-0 mark is the moment the key becomes logically deleted. (4) Call find(key, _, _) to physically unlink (HELPING) — its snipping removes every marked level. Physical unlink is entirely via find's snipping; remove does NOT CAS-unlink itself after marking.

Linearization points summary

Op LP
insert level-0 CAS(preds[0].next[0], …, new) succeeds
remove level-0 mark CAS (victim,false) → (victim,true) succeeds
contains / get point of reading succs[0] + checking mark (no CAS needed)

Theory anchors: multi-level lock-free skip list lifting Harris to a tower → Fraser P5 Ch. 4 + Herlihy & Shavit B1 Ch. 14; level-0 CAS / level-0 mark as the sole linearization point → ADR-13 (B1 §14 proof); bottom-up insert / top-down mark + HELPING uphold the lock-free progress + linearizability invariants (I-series, §7); orderings → ADR-15/ADR-16 (B4); weakly-consistent iterator follows ConcurrentSkipListMap (P8) → ADR-25; verified by loom (ADR-17) and differential replay vs crossbeam-skiplist (ADR-18).

23. Phase 11 — Memory reclamation (epoch-based, Ebr)

11.1 Objectives

  • Implement skl-concurrent/src/ebr.rs: epoch-based reclamation with global epoch counter, per-thread Guard (pin), and per-epoch retire lists.
  • Integrate with ConcurrentSkipList unlink path: replace Box::leak with guard.retire(ptr).
  • Guarantee: a retired node is freed only after every thread that could hold a pointer to it has quiesced past the epoch of retirement.
  • Deliverable: zero use-after-free under concurrent readers/writers (ASAN + Miri); bounded retired-node backlog under sustained churn.

11.2 Detailed Implementation Steps

ebr.rs — core structures

static GLOBAL_EPOCH: AtomicUsize = AtomicUsize::new(0);  // incremented by collectors

pub struct Ebr {
    threads: Mutex<Vec<Arc<ThreadState>>>,  // registry; Mutex only on register/unregister
}
struct ThreadState {
    local_epoch: AtomicUsize,  // 0 = unpinned (sentinel); else current epoch when pinned
    retire_lists: [Vec<Retired>; 3],  // indexed by (epoch % 3); drained when safe
}
pub struct Guard<'a> { state: &'a ThreadState, epoch: usize }
pub struct Retired { ptr: *mut u8, drop_fn: unsafe fn(*mut u8) }

Ebr::pin() -> Guard: loads GLOBAL_EPOCH with Acquire, stores into state.local_epoch with Release, returns Guard. Guard::drop: stores 0 into state.local_epoch with Release (= unpinned/quiescent). Guard::retire<T>(ptr: *mut T): pushes Retired { ptr as *mut u8, drop_in_place_and_dealloc::<T> } onto state.retire_lists[epoch % 3].

Epoch advancement and collection — fn try_collect(ebr: &Ebr, state: &mut ThreadState); Named-algorithm prose: read the current GLOBAL_EPOCH E (Acquire). Scan every registered ThreadState; if any pinned thread (local_epoch != 0) lags behind E, collection is not yet safe and try_collect returns. Otherwise every pinned thread is at E (the rest unpinned), so the retire list two epochs back, slot (E-2) % 3, is safe to free. Bump the global epoch with an AcqRel CAS(E → E+1); even if that CAS loses to another advancer, freeing slot (E-2) % 3 remains correct, so its Retired entries are dropped regardless. Collection triggered: on Guard::drop if retire_lists total size > threshold (e.g. 64 nodes). Three-epoch window (E, E-1, E-2): a thread pinned at E cannot reference nodes retired at < E-1; freeing E-2 list is always safe once no thread is pinned below E.

Integration with list.rs

// In ConcurrentSkipList::remove, after find() confirms physical unlink:
let guard = self.ebr.pin();
guard.retire(victim_ptr);   // victim_ptr: *mut CNode<K,V>
// drop(guard) → quiescent state; triggers try_collect if threshold exceeded

find's snipping CAS: after winning the snip-CAS, the snipper does NOT retire; the thread that called remove owns retirement of that node. Sentinel nodes (head, tail): never retired; their lifetime == ConcurrentSkipList lifetime. CNode drop_fn: unsafe fn drop_cnode<K,V>(ptr: *mut u8) { Box::from_raw(ptr as *mut CNode<K,V>); } — reconstructs Box and drops.

Theory anchors: epoch-based reclamation (global epoch, per-thread pin, three-epoch retire window) → Fraser P5 Ch. 5; EBR chosen over hazard pointers (P6) → ADR-14; the quiescent-state definition + advancement condition → Dice/Shalev/Shavit P7; pin/unpin orderings (Acquire/Release, advance check SeqCst) → ADR-15; rolling our own Ebr rather than crossbeam-epoch → ADR-22; the "retire-once" + "no use-after-free" rules added to the I-series (§7); epoch-stall failure mode tracked in Failure Modes.

11.7 Performance Concerns

Cross-thread retirement (one thread retires a node another allocated): acceptable; retire only pushes to the calling thread's list, no cross-thread list access except during try_collect's read-only scan. NUMA concern: GLOBAL_EPOCH is a single cache line; under 64+ cores, use a padded CachePadded<AtomicUsize> to avoid false sharing with adjacent state.

11.8 Edge Cases

Single thread: try_collect sees only its own local_epoch, can always collect after unpinning, epoch advances monotonically. Thread exits mid-collection: deregister removes Arc<ThreadState> from registry; if the thread's retire list is non-empty at deregister, flush it to a global orphan list collected on next try_collect. Zero retired nodes: try_collect called, nothing to free, epoch may or may not advance, no error. Epoch counter overflow at usize::MAX: usize wraps; three-slot window (% 3) is modular, safe as long as no thread is pinned for > usize::MAX / 2 epoch ticks (effectively impossible). Retire called outside a pin (no guard): panic in debug, undefined in release — enforce by taking &Guard as a parameter to retire. ConcurrentSkipList::drop with active threads: quiesce_all must be documented as a precondition; caller must join threads before dropping the list.

Differential harness — skl-bench/tests/differential.rs, signature fn run_differential(ops: Vec<Op<u64,u64>>); (SkipList vs BTreeMap oracle). Threat Model

Trust Boundary

Library code executes in caller's process, same address space. No network surface. Attack vectors are: (a) caller-supplied keys/values; (b) thread schedules in concurrent usage; (c) misconfiguration of p, max_level, or RNG seed. Adversary can control key content and insertion order; cannot directly write memory or intercept CAS operations.

T1 — Adversarial Key Distribution

  • Root cause: random_level() output is only as unpredictable as the RNG; a leaked seed lets attacker craft a sequence that maximizes tower heights, pushing search to O(n).
  • Mitigation: DetSkipList (1-2-3 variant) gives worst-case O(log n) independent of key order or tower heights; use when adversarial input is plausible.
  • Additional: max_level cap in LevelGenerator bounds height at ceil(log_{1/p}(N_max)) even under a bad RNG run.
  • Detection: stats subcommand / level_histogram() returning a flat or top-heavy histogram signals imbalance; alert if max observed height > 3 × E[height].

T2 — RNG Predictability

  • Policy: Rng (xorshift/wyrand) seeded from a non-deterministic source (OsRng / getrandom) in production builds; seedable only under #[cfg(test)] or explicit with_seed() constructor.
  • Invariant: LevelGenerator::new() (no seed arg) must not use a fixed or time-derived seed; this is a compile-time API contract, not a runtime option.
  • Residual risk: even with a good seed, the sequential list is randomized; use DetSkipList for hard latency guarantees.

T3 — Concurrency Hazards (torn reads, lost updates)

  • Protocol: MarkedPtr uses AtomicPtr; all loads carry at minimum Acquire; all CAS operations use AcqRel / SeqCst where required by the linearizability proof.
  • find() invariant: snips marked nodes via CAS before returning preds/succs; no caller ever operates on a marked predecessor.
  • Linearization point: level-0 CAS in insert; top-down mark in remove. These are the only points that change observable state.
  • Verification: loom model-checks all interleavings in skl-bench; any assertion failure is a critical regression gate.

T4 — Use-After-Free / Double-Free

  • Root cause: ConcurrentSkipList physically unlinks CNode via find() helping; the pointer must not be freed while any thread holds it.
  • Mitigation: Ebr — pin before any traversal; retire only after unlink; reclaim only after all threads exit the epoch; ConcurrentSkipList::drop() flushes all retire lists after a final epoch advance.
  • Detection: AddressSanitizer + Miri in CI on every push; loom-based tests exercise UAF schedules.

T5 — ABA Problem

  • MarkedPtr low-bit tag: once a node is marked (logical delete), its pointer is never CASed back to unmarked in the same epoch; EBR ensures the memory is not reused until all threads have advanced past the retire epoch. ABA is structurally prevented, not just avoided.

T6 — Livelock

  • Scenario: high-contention insert + concurrent helping of the same node → CAS loop never exits.
  • Mitigation: bounded retry with exponential backoff (std::hint::spin_loop); after K retries, find() restarts from head. Progress argument: at least one thread completes per retry round because the failing CAS means another thread succeeded.
  • Observable: cas_retry_rate metric; alert threshold defined in runbook (Operational Readiness).

T7 — Memory Exhaustion

  • Unbounded inserts: caller's responsibility; SkipList / ConcurrentSkipList do not cap size. Document that callers must apply their own quota.
  • EBR backlog: a pinned thread stalls epoch advance, accumulating retired nodes. Mitigation: Ebr::pin() is scoped (RAII Guard); no thread holds a pin outside a read/write operation. Backlog metric exposed; alert if retired-node count > threshold.

T8 — Unsafe Raw-Pointer Soundness

  • Policy: all unsafe blocks are in skl-list, skl-concurrent; every block carries a // SAFETY: comment naming the invariant it relies on.
  • Encapsulation: raw pointers never escape public API; only references or owned values cross the API boundary.
  • Tooling: cargo miri test in CI; #[cfg(debug_assertions)] null/alignment checks on every pointer deref in debug builds.

T9 — Weakly-Consistent Iterator Misuse

  • Contract: ConcurrentSkipList iterators are weakly-consistent — they may miss concurrent inserts or observe elements concurrently deleted. This is documented on the type, matching java.util.concurrent.ConcurrentSkipListMap semantics.
  • Misuse pattern: caller assumes snapshot isolation and acts on a "complete" range scan.
  • Mitigation: iterator doc says "may not reflect concurrent mutations; use DetSkipList or external synchronization for snapshot reads."

T10 — Supply Chain

  • deny.toml (cargo-deny): deny(licenses) to approved SPDX list; deny(unmaintained); deny(duplicate); minimal dep tree (skl-core: no deps beyond core/alloc; skl-concurrent adds only the atomics substrate).
  • Reproducible builds: Cargo.lock committed; pinned in CI.

Incident Runbooks

"Height too tall" (current_height >> E[height]):

  1. Check LevelGenerator config: p_inv ∈ {2, 4}; max_level = ceil(log_{1/p}(N_expected)).
  2. Verify non-deterministic seed path (not fixed seed in production).
  3. If key distribution is adversarial, migrate workload to DetSkipList.
  4. Run sklist stats to dump level histogram; compare against Pugh's expected distribution.

"Concurrent throughput collapses":

  1. Check cas_retry_rate: if > 100/op, contention is pathological.
  2. Inspect key distribution: hot-key clustering → shard by key range.
  3. Check helping_unlink_total: spike means delete-heavy workload with many logically-deleted nodes accumulating.
  4. Reduce thread count temporarily; re-run skl-bench concurrent scaling test.
  5. Profile with perf / cargo flamegraph; identify CAS loop hot spot.

"Memory grows under churn" (EBR backlog):

  1. Check ebr_retired_nodes + ebr_reclaim_lag_epochs.
  2. Identify stalled thread holding Guard across a long operation (pin held outside op scope).
  3. Verify Guard is always dropped before calling any blocking I/O or sleeping.
  4. Flush: call Ebr::flush() (manual reclaim attempt) after identifying the stall.

Behavioral Contracts (Stable)

  • Ordered-map semantics: iter() yields (K, V) pairs in ascending key order for all variants. This is a breaking-change boundary; no variant may yield out-of-order pairs.
  • Linearizability: ConcurrentSkipList is linearizable with respect to insert, remove, and get. The linearization points (level-0 CAS for insert; top-down mark for remove) are part of the documented behavioral contract, not an implementation detail. Relaxing linearizability is a semver-major change.
  • Iteration order (sequential): stable across patch/minor; reordering due to internal restructuring is a breaking change.
  • Weakly-consistent concurrent iterator: documented contract — may miss concurrent inserts; may observe concurrently-deleted elements; will not crash or deadlock; will not return duplicates within a single iterator session. This weakening is a stable contract, not a bug.

  • MSRV: Rust 1.78 (locked in Cargo.toml rust-version field).

  • Rationale: 1.78 provides stable AtomicPtr CAS with cmpxchg-style API, const generics needed for fixed-size tower arrays, and std::hint::spin_loop.

Memory-Ordering Guarantees (ConcurrentSkipList)

  • All MarkedPtr loads in read paths use Acquire.
  • All MarkedPtr CAS operations use AcqRel success / Acquire failure.
  • The level-0 insert CAS uses SeqCst (the linearization point); all other level CAS use AcqRel.
  • Callers relying on happens-before guarantees between insert and get across threads may assume: a successful insert on thread A happens-before any get on thread B that observes the inserted key.
  • These ordering guarantees are part of the public contract; downgrading them is a breaking change.

Adding New Variants Behind OrderedMap

New variants (e.g., a finger skip list) implement OrderedMap<K, V> without altering the trait. Callers parameterized on impl OrderedMap<K, V> accept new variants without recompilation. The trait itself is sealed (pub(crate) trait Sealed) to prevent external implementations, preserving the right to add methods with defaults in minor versions.

Feature Flag Semantics

  • concurrent, deterministic, indexable are additive; enabling any combination does not alter the behavior of already-enabled variants.
  • All variants behind all flags implement identical ordered-map semantics (same get/insert/remove/range contracts).
  • Disabling a flag removes the type from the public API without affecting other crates' compilation; this is not a breaking change for callers who do not use that variant.

Hot Paths + Cache / Branch Analysis

Sequential search (drop-down / forward):

  • Each level hop: pointer dereference → potential cache miss on Node.forward[].
  • Top levels sparsely populated → high miss rate if tower nodes not co-located.
  • Level 0 hop chain: dense, sequential-ish → prefetchable; forward[0] at Node offset 0.
  • Branch: key < next.key (inner loop) — well-predicted on random keys; mis-predicted on adversarial sorted inserts.

RNG on insert (hot path):

  • LevelGenerator::random_level() called per insert; must be < 5 ns. wyrand: ~2 ns, single multiply + xor, no syscall.
  • Slow path: tower realloc when level exceeds current. Mitigated by pre-allocating max_level forward slots.

Concurrent find / CAS:

  • find(preds, succs) traverses all levels → L pointer loads; each may be a cache miss.
  • CAS retry on contention: back-off not implemented by default; add exponential backoff flag under feature = "backoff".
  • Helping: a thread helping unlink a marked node adds ~1 extra CAS per level; amortized over the deleter's cost.

Mental Models & First Principles

The compressed insights an expert holds before touching the code. Each: the model, what it predicts, the bug class you write without it, and the resolving section (cited per entry, e.g. "Resolved: §18").

  • MM1 — A skip list is a probabilistic balanced tree whose balance is an expectation, not an invariant. No structural property guarantees O(log n) on any single operation; the geometric height distribution makes it O(log n) in expectation and with high probability. Predicts: the tail is unbounded — a pathological RNG run can produce an O(n) search. Bug without it: writing an SLA or a hard real-time path that assumes worst-case O(log n) from SkipList; treating a slow query as a correctness bug rather than a tail event. Resolved: §18 (Phase 6 analysis); the deterministic escape hatch is §19 (Phase 7).
  • MM2 — The update[] array is the whole algorithm. Search, insert, and delete are one traversal that records, per level, "the last node whose forward pointer I must rewrite." Predicts: insert and delete are trivial given update[]; all the difficulty is filling it correctly. Bug without it: duplicating traversal logic across insert/delete and letting them drift; off-by-one at levels above the current list height. Resolved: §14–§16 (Phases 2–4).
  • MM3 — Height is decided once, at birth, by a coin, and never changes (sequential). A node's tower height is sampled at insert and is immutable; the structure never rotates or rebalances. Predicts: there is no rebalancing cost and no rotation bug — but also no way to "fix" a tall node later. Bug without it: attempting AVL/red-black-style rebalancing on a randomized skip list and corrupting the level invariant. Resolved: §13 (Phase 1), ADR-08. (The deterministic variant breaks this model deliberately — see MM4.)
  • MM4 — The 1-2-3 deterministic skip list is a B-tree of order 2, drawn sideways. A gap of 1/2/3 level-i nodes between consecutive level-(i+1) nodes is exactly a B-tree node of 2/3/4 children; raise = split, lower = merge. Predicts: worst-case O(log n) follows from B-tree theory, not probability; balance is now an enforced invariant. Bug without it: implementing ad-hoc rebalance triggers instead of the split/merge propagation a B-tree mandates. Resolved: §19 (Phase 7), ADR-10.
  • MM5 — A span is "how many level-0 steps does this one pointer skip." Order statistics need no second structure: each forward pointer carries the count of base-level nodes it jumps, and rank is the sum of spans along the search path. Predicts: rank/select are O(log n) and maintained incrementally; insert/delete touch O(log n) spans. Bug without it: keeping a parallel rank array and rebuilding it O(n) per mutation, or mis-attributing a +1 to the wrong level on insert. Resolved: §20 (Phase 8), ADR-11.
  • MM6 — Logical deletion precedes physical deletion; a marked pointer is a tombstone in the low bit. A node is "removed" the instant its level-0 next is marked, long before it is unlinked. Readers must treat marked nodes as absent; unlink is lazy cleanup. Predicts: delete is two phases (mark, then snip), and the linearization point is the mark, not the unlink. Bug without it: treating a logically-deleted node as present, or racing two threads to physically unlink and double-freeing. Resolved: §21–§22 (Phases 9–10), ADR-13.
  • MM7 — Helping is how a non-blocking structure stays live: every traversal cleans up after stalled mutators. When find meets a marked node it CASes it out itself, regardless of whether it is reading, inserting, or deleting. Predicts: a thread suspended mid-delete cannot wedge the list — others finish its unlink — which is exactly what makes the structure lock-free. Bug without it: a dedicated cleanup thread (reintroduces a single point of stall) or unbounded marked-node accumulation. Resolved: §22 (Phase 10), MM6.
  • MM8 — In a GC-free lock-free structure, the hard problem is not the algorithm — it is knowing when a node is safe to free. A reader can hold a raw pointer to a node another thread just unlinked; freeing it is use-after-free, and reusing its address is ABA. Predicts: you need a reclamation scheme (EBR here), and its failure modes (epoch stall, retire backlog) become first-class operational concerns. Bug without it: the classic "it passes stress tests, then segfaults in production under churn" because reclamation was hand-waved. Resolved: §23 (Phase 11), ADR-14.
  • MM9 — Memory ordering is a contract between a publish site and a consume site, not a per-atomic property. A Release store of a pointer "publishes" everything written before it; an Acquire load that reads that pointer "consumes" those writes. Orderings are chosen in pairs. Predicts: a node's key/value are visible to any thread that reaches it via an Acquire load of an Acquire/Release-paired pointer; a single misplaced Relaxed breaks the chain silently. Bug without it: a torn node read (seeing the pointer but not the initialized fields) that appears only on weakly-ordered hardware (ARM), never on x86. Resolved: §22 (Phase 10), ADR-15/ADR-16.
  • MM10 — A concurrent iterator is a weakly-consistent prefix, not a snapshot. Lock-free traversal sees every node present at its start and may or may not see concurrent inserts; it never blocks writers. Predicts: you cannot compute a transactionally-consistent aggregate from a weak iterator; that requires a different (more expensive) mechanism. Bug without it: reporting an exact len() or sum from a weak scan and being subtly wrong under concurrency. Resolved: §24 (Phase 12), ADR-25.

Alternative Architectures (Roads Not Taken)

Fundamentally different ordered-map designs for the same job. Each: sketch, the regime where it wins, the real system that embodies it, why 404 rejected it.

ALT-1 — Red-black / AVL balanced BST.

        (B,7)              balance = enforced invariant (color/height rules)
       /     \             rotations on insert/delete restore it
   (R,3)     (B,9)         worst-case O(log n) guaranteed, no probability
   /   \
(B,1) (B,5)

Wins: hard worst-case latency with the tightest constant and lowest memory (no tower; 2 child ptrs + 1 colour bit). Embodied by: the Linux kernel rbtree, C++ std::map, Java TreeMap. Rejected because: rotations are notoriously hard to make lock-free, defeating 404's concurrency goal; the deterministic O(log n) niche is already covered by DetSkipList (§19, ADR-10) without leaving the skip-list family.

ALT-2 — B-tree / B+-tree (high fan-out, cache-optimized).

            [ 17 | 42 ]                fan-out F (e.g. 16–64 keys/node)
           /     |      \              height ≈ log_F N  ⇒ few cache misses
   [.. <17 ..][17..42][.. >42 ..]      keys packed contiguously per node

Wins: minimizes cache-line/page misses (height log_F N with F≫2), and matches block/SSD I/O — the disk-friendly ordered structure. Embodied by: std::collections::BTreeMap, every B-tree-backed database index, RocksDB SSTable index blocks. Rejected because: node splits/merges under concurrency need either locking or complex lock-free B-tree protocols; 404's mandate is the skip-list family as the in-memory primitive, and the B-tree is the explicit Project 67 sibling (§2.4).

ALT-3 — Lock-free binary search tree (e.g. Ellen et al. external BST).

   internal nodes = routers, leaves = keys
   updates use "operation records" + child CAS
   ┌── flag/mark protocol coordinates concurrent splices ──┐

Wins: a pointer-lean lock-free tree with no tower overhead, competitive for read-mostly ordered sets. Embodied by: the Ellen–Fatourou–Ruppert–van Breugel non-blocking BST (PODC 2010) and derivatives. Rejected because: its operation-record/flagging protocol is materially harder to reason about and model-check than marked-pointer skip-list find+helping (§22), and it offers no clean order-statistics or range story comparable to spans (§20).

ALT-4 — Learned index (model replaces the search structure).

   key ──► [ trained model f(key) ≈ position ] ──► predicted slot
                         │ error bound ε
                         ▼  local search within ±ε in a sorted array

Wins: near-O(1) lookup with tiny memory when the key distribution is learnable and the data is read-mostly/static; can beat comparison trees on lookup latency. Embodied by: Kraska et al. "The Case for Learned Index Structures" (SIGMOD 2018); RMI and successors. Rejected because: updates are the weak point — arbitrary insert/delete invalidate the model and need retraining or a delta buffer — which directly conflicts with 404's write-heavy, mutation-correct concurrent goal (§22) and its expected-balance model (MM1).

Glossary

Term Definition
skip list Probabilistic ordered data structure: a tower of sorted singly-linked lists where level 0 holds every node and higher levels hold geometric-random subsets; expected O(log n) search/insert/delete.
tower The column of forward pointers belonging to one node across all levels at which it appears (height drawn from geometric distribution).
level A single horizontal sorted linked list within the tower structure; level 0 is the base (densest), higher levels are sparser.
forward pointer Node.forward[i]: pointer to the next node at level i; in CNode stored as MarkedPtr with the logical-deletion tag in the low bit.
head sentinel A dummy node at -∞ with max_level forward pointers; every search starts at its top-level forward pointer.
drop-down search Core traversal: advance along forward[i] while next.key < target; when blocked, drop to level i-1; repeat until level 0.
update array update[0..max_level]: predecessor nodes recorded per level during a sequential search; used by insert/delete to splice or unlink.
geometric distribution Height selection: a node reaches level i with probability p^i; successive fair coin flips with success probability p give tower height.
level generator LevelGenerator { p_inv, max_level, rng }: generates random tower heights by repeated Bernoulli trials capped at max_level.
parameter p Promotion probability per level; typical values 1/2 or 1/4; controls space-time trade-off: smaller p → shorter towers + faster search constant but sparser higher levels.
probabilistic balancing No explicit rebalancing; the geometric distribution ensures O(log n) levels with high probability, analogous to a balanced BST in expectation.
expected height E[tower height] = 1/(1-p); e.g. p=1/2 → E=2; max_level set to ⌈log_{1/p}(n)⌉.
max level Hard cap on tower height, typically ceil(log_{1/p}(N_max)); prevents degenerate towers on adversarial Rng seeds.
deterministic skip list DetSkipList: skip list variant maintaining the gap invariant instead of randomness; achieves worst-case O(log n).
1-2-3 skip list Specific deterministic variant where between any two consecutive level-(i+1) nodes there are exactly 1, 2, or 3 level-i nodes; insert/delete restore invariant via local restructuring.
gap invariant The 1-2-3 constraint: 1 ≤ (# level-i nodes between consecutive level-(i+1) nodes) ≤ 3; maintained at all times; ensures O(log n) worst case.
indexable skip list IndexableSkipList: augments each forward pointer with a span (count of level-0 nodes it skips); enables O(log n) rank/select operations.
span / width The span stored on forward[i]: number of level-0 positions skipped by one hop at level i; updated incrementally on insert/delete.
rank rank(key) -> usize: number of keys strictly less than key; computed by summing spans along the search path in IndexableSkipList.
select select(i) -> Option<&K>: the i-th smallest key (0-indexed); follows forward pointers consuming accumulated spans until total reaches i.
order statistics The pair (rank, select) provided by IndexableSkipList; analogous to an order-statistics tree; both O(log n).
lock-free Progress guarantee: at least one thread makes progress in a finite number of steps regardless of scheduling; the ConcurrentSkipList is lock-free (any blocked thread can be helped).
non-blocking Umbrella term covering lock-free (and stronger: wait-free); used interchangeably for CAS-based structures in this codebase.
CAS Compare-And-Swap: atomic compare_exchange(expected, new, ord_success, ord_fail); the primitive for lock-free insert and helping-unlink in ConcurrentSkipList.
marked pointer MarkedPtr<K,V>(AtomicPtr<Node<K,V>>): low bit of the raw pointer encodes logical deletion; set atomically before physical unlink.
logical deletion First step of ConcurrentSkipList::remove: mark all of the node's forward pointers top-down via CAS; the node is "deleted" once all marks are set, before physical unlinking.
physical unlink Removal of a marked node from the list's pointer chain via CAS on the predecessor's forward pointer; done lazily by find() traversal or by helping during insert/remove.
helping When find() encounters a marked pointer, it CASes the predecessor's pointer to skip the marked node, advancing physical cleanup; enables lock-freedom without a dedicated GC thread.
linearizability Correctness condition: each concurrent operation appears to take effect atomically at some point (linearization point) within its real-time interval; verified via loom harness.
linearization point The single atomic event that makes an operation visible: insert → CAS that sets the level-0 forward pointer; delete → CAS that sets the first mark on the node.
ABA problem CAS hazard: pointer changes A→B→A between a read and CAS, making the CAS succeed incorrectly; mitigated by tagged pointers or EBR ensuring nodes are not reallocated while referenced.
epoch-based reclamation (EBR) Ebr: memory reclamation scheme tracking a global epoch counter + per-thread epoch pins; a thread retires a node to its retire list; the node is freed only once all threads have advanced past the epoch of retirement.
pin A thread "pins" by reading and recording the global epoch before accessing shared data; while pinned, no node from a previous epoch can be freed under it.
retire list Per-thread list of (pointer, retirement-epoch) pairs queued for deferred free; drained when the thread detects the global epoch has advanced enough.
quiescent state A point where a thread holds no references to retired nodes; advancing through a quiescent state allows global epoch advancement and enables retire-list draining.
weakly-consistent iterator Concurrent iterator that reflects a prefix of insertions/deletions; may miss concurrent updates without throwing; defined contract: sees every node present at construction, may or may not see nodes inserted after.
memory ordering Rust std::sync::atomic::Ordering (Acquire, Release, AcqRel, SeqCst, Relaxed); ConcurrentSkipList uses Release on CAS-insert at level 0, Acquire on loads to establish happens-before.
acquire / release Acquire load pairs with Release store to establish happens-before; used at linearization points so a successful CAS publish is visible to subsequent Acquire loads.
loom Rust model-checking crate (tokio/loom) that systematically explores all interleavings of atomic operations; used in skl-bench's linearizability harness for ConcurrentSkipList.
OrderedMap pub trait OrderedMap<K: Ord, V> in skl-core: the shared interface implemented by SkipList, DetSkipList, IndexableSkipList, and ConcurrentSkipList.
LevelGenerator pub struct LevelGenerator { p_inv: u32, max_level: usize, rng: Rng } in skl-core; generates random tower heights via geometric trials; shared across sequential + concurrent variants.
Rng pub struct Rng(u64) in skl-core; xorshift/wyrand PRNG; fast per-node height sampling on hot insert path; no_std-compatible.
SklError pub enum SklError { Empty } in skl-core; only error class currently surfaced (e.g. range on empty list).
