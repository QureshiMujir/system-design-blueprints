Hard questions (§34)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does index-free adjacency (P1, §13) require a paged, fixed-width store (ADR-04) rather than an LSM-on-keys layout (ADR-03), and under what workload would that trade-off reverse (§35 AA1)?
  2. Walk the sequence by which a page write becomes durable, from Store.set_property (§11.9) through the WAL record (§14.2) to the page's LSN field (§11.2) — where would a bug that skips WAL-before-page (I3) first become visible (§24, FM-2/FM-8)?
  3. Why is (xmin, xmax, active) the minimum snapshot representation (§11.3, I4) and not (xmin, xmax) alone — construct the anomaly a two-field snapshot would miss, using the write-skew fixture (§15.5)?
  4. GC (§15.2, I6) must never race the oldest-active-snapshot pointer. Explain the atomic read that prevents this and connect it to FM-4 (§24) and the M9 soak target (§29).
  5. Why does the rule-based planner (§18.2, ADR-09) ship before the cost-based planner, and what does the cost model (§18.2) assume about cardinality estimation (§16.2) that a rule-based planner does not need?
  6. Trace MATCH (a)-[:KNOWS*1..3]->(b) (§17.1) through the AST (§11.4), the logical plan (§11.5), and the bounded-BFS physical execution (§18.2) — where does the path-materialization pitfall (§18.6) manifest, and which invariant would a fuzz run catch it with?
  7. Why is Brandes' algorithm (§19.2) not run exactly on the full Reference Deployment Graph (§4), and how does the Capacity Model (§33, C9) justify that scoping decision?
  8. Contrast a torn WAL write (§14.6, FM-8/T9) with a page checksum mismatch (§11.2, T4) — why does one halt replay at a point and the other quarantine a single page?
  9. Why does the Bolt session state machine (§11.8, §20.2) reject an out-of-order RUN instead of queuing it, and what would happen to §20.9 Failure Analysis if it queued instead?
  10. Using §4 and the Capacity Model (§33, C4), explain the tension between the 16 GiB default page-cache ceiling and a 5%-hot-set assumption on the Reference Deployment Graph — which operational lever (§25) resolves it?
  11. Why is composite property indexing deferred (ADR-21, §36) rather than shipped in Phase 4 (§16), and what workload assumption would force it forward?
  12. Contrast this design's snapshot-isolation default (ADR-07, I4) with Dgraph's model (§32) — under what workload does Dgraph's choice win?
  13. Why does the Repository Layout (§10) put fuzz targets under fuzz/ rather than conformance/, and how does that split map onto M9 vs M10 (§29)?
  14. Why does relationship visibility (§11.3, I7) require checking both endpoints, not just the relationship record's own xmin/xmax — construct the anomaly skipping it would produce?
  15. Why did this blueprint reject a GraphBLAS-first analytics runtime (§35 AA2) despite RedisGraph proving it works, and how does §32's scheduling row explain the rejection?
  16. Trace the ADR chain (§9) that makes Rust (ADR-01) a precondition for the no-GC recovery-time bound (M8, §29) — which rejected language (ADR-02) would break that bound and why?
  17. Why is the label index's maintained count (§16.2) the planner's cardinality source (§18.2) instead of periodic sampling — what does Kossmann's survey (§5) say about that trade-off, and where would sampling actually help (§30)?
  18. Why does Phase 0 (§12.2) ship an in-memory MemStore before the paged store (§13) exists, and what does that ordering protect in the correctness kernel (I1, I7)?
  19. Using T6 (§23) and FM-5 (§24), explain how a single unindexed high-fan-out MATCH can trigger both a resource-exhaustion threat and a planner cost blow-up — which single mitigation (§18.6) addresses both?
  20. Why does distributed partitioning remain a Deferred Feature (§36) rather than a phase, when TigerGraph (§35 AA4) ships it from day one — what does the Capacity Model (§33) say about the single-node ceiling that justifies the sequencing?

31. Mental Models & First Principles

  • MM1 — "A node is a pointer, not a row." Predicts why joins disappear in graph queries. Bug class without it: reintroducing hash-join thinking and indexing for traversal instead of using adjacency. Applies in §13, P1.
  • MM2 — "The WAL is the truth, the page cache is a rumor." Predicts recovery correctness. Bug class without it: writing pages before the WAL (violates P5/I3). Applies in §14.
  • MM3 — "A snapshot is a frozen set of visible transaction ids, not a frozen clock reading." Predicts why (xmin, xmax, active) and not (xmin, xmax) alone. Bug class without it: accepting a phantom-visible active transaction. Applies in §15, I4.
  • MM4 — "The planner is a search over a lattice of join orders." Predicts why cost-based planning is dynamic programming, not greedy. Bug class without it: exponential blow-up without memoization. Applies in §18, ADR-09.
  • MM5 — "A B-tree page split is not one write, it's a chain." Predicts why WAL log records must be grouped. Bug class without it: a partially-split tree visible after a crash. Applies in §16.
  • MM6 — "Pregel is BSP: think in supersteps, not in threads." Predicts deterministic analytics results. Bug class without it: races from mutating shared state mid-superstep. Applies in §19.
  • MM7 — "Bolt's state machine is the contract, not the bytes." Predicts why drivers crash on an illegal transition. Bug class without it: a server that accepts an out-of-order RUN. Applies in §20, I10.
  • MM8 — "Index-free adjacency trades storage locality for pointer-chase locality." Predicts why cache-unfriendly random access dominates at scale. Bug class without it: assuming sequential-scan performance for a traversal workload. Applies in §4, §30.

Reference Implementations

  • Neo4j — record-storage engine (fixed-width node/relationship records), WAL, Cypher runtime module. Lesson: index-free adjacency as a first-class on-disk layout. Pitfall not to copy: its JVM GC-pause budget (ADR-02). Applied in §13, §14, §8.
  • Memgraph — in-memory MVCC storage, planner. Lesson: version-chain visibility without a disk WAL. Pitfall not to copy: no crash-durability story without an external snapshot. Applied in §15.
  • Dgraph — posting-list storage, query layer. Lesson: an inverted-index-backed traversal engine is a real alternative to record-oriented adjacency. Applied in §32 (Comparative Architecture Table).
  • JanusGraph — storage abstraction over Cassandra/HBase/BerkeleyDB. Lesson: what a graph database loses when the store is generic wide-column. Applied in §35 (AA1), §9 (ADR-03).
  • ArangoDB — multi-model layout (arangod/Aql, arangod/StorageEngine). Lesson: a uniform engine serving graph/document/key-value needs multiple planners under one roof. Applied in §32.
  • RedisGraph — GraphBLAS-backed adjacency-matrix traversal engine. Lesson: the linear-algebra view of graph queries. Applied in §35 (AA2), §19.

Glossary (§37) · 45 terms · site-wide glossary

Index-free adjacency
a node stores a direct pointer to its first relationship; neighbours are found by pointer chase, not index probe (P1).
Property graph
nodes and relationships each carrying an arbitrary set of typed key/value properties.
Node record
the fixed-width on-disk representation of a node (§8.2).
Relationship record
the fixed-width on-disk representation of a directed, typed relationship (§8.2).
Property record
a chained, semi-variable-width record holding one property value (§8.2).
Page cache
the fixed-capacity buffer pool mediating between pages and disk (§11.2).
WAL
write-ahead log; every change is durable in the log before the page is dirtied (P5).
LSN
log sequence number; a monotonic position in the WAL (§11.1).
Checkpoint
a WAL marker recording the dirty-page and transaction tables to bound recovery time (§14.2).
ARIES
the redo/undo/analysis recovery algorithm this engine implements (Mohan et al. 1992).
Redo pass
replays committed-but-not-yet-flushed changes.
Undo pass
rolls back uncommitted changes via compensation log records.
Analysis pass
reconstructs the dirty-page and transaction tables from the last checkpoint. CLR (compensation log record) — a redo-only record produced during undo.
MVCC
multi-version concurrency control; readers see a consistent snapshot without blocking writers.
Snapshot isolation
the isolation level where reads see a fixed snapshot and writers conflict only on the same record (P4).
Version chain
the linked list of a property's historical values (§8.2).
xmin/xmax
the creating/deleting transaction ids stamped on every record.
Active set
the set of transactions running when a snapshot was taken (I4).
Write skew
an SI anomaly where two transactions' disjoint writes are individually consistent but jointly inconsistent; permitted under SI (I5).
Lost update
two transactions overwriting the same record; rejected under SI (I5).
Serializable Snapshot Isolation (SSI)
a stronger isolation level closing SI's anomalies (Cahill et al. 2008, deferred).
Label index
a B-tree mapping label to node ids with a maintained count (§16.2).
Cardinality estimation
predicting how many rows an operator will produce (P8).
openCypher
the declarative graph query language this engine implements a subset of.
AST
abstract syntax tree, the parser's output (§11.4).
Logical plan
a storage-agnostic tree of relational-algebra-like operators (§11.5).
Physical plan
the logical plan lowered to concrete, storage-aware operators (§11.5).
Volcano iterator model
the pull-based init/next/close execution contract (§11.6).
Predicate push-down
moving a filter as early as possible in the plan.
Cost model
the formulas estimating an operator's execution cost (§18.2).
Join order
the sequence in which pattern parts are combined; searched by the cost-based planner.
Bolt protocol
the binary wire protocol this engine's primary driver interface implements (§8.3).
PackStream
Bolt's serialization format.
Session state machine
the finite-state contract governing a Bolt connection's lifecycle (I10).
Pregel
the vertex-centric, bulk-synchronous-parallel analytics programming model (Malewicz et al. 2010).
Superstep
one round of a Pregel computation.
Combiner
a function reducing multiple messages to one vertex before delivery.
PageRank
an iterative centrality algorithm modelling a random surfer; requires dangling-node redistribution (§19.6).
Betweenness centrality
the fraction of shortest paths passing through a node (Brandes 2001).
LDBC SNB
the Social Network Benchmark used as this engine's macro conformance/performance workload.
TCK
technology compatibility kit; the openCypher conformance test suite.
Checksum
the xxhash3-64 value verifying a page's integrity on read (I2).
Group commit
batching multiple transactions' fsync calls to amortize durability cost (§14.2).
Read replica
a read-only copy of the primary streaming and replaying its WAL (Phase-1+).
RTO
recovery time objective; the bound on crash-recovery duration (§4, M8). ---
