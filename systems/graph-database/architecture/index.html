Three properties this diagram fixes for the rest of the document. First, storage is record-oriented and fixed-width for nodes/relationships with index-free adjacency: a node record holds a pointer to its first relationship; relationship records form a doubly-linked list per direction (P1, P2). Second, the MVCC version chain lives inside the property record, not a separate undo log (P2, I4). Third, the planner emits Volcano operators that pull from each other; execution is single-threaded per query in Phase 0 and parallelised at the operator boundary later, so the planner never branches on parallelism (P7). Every later section stays consistent with these three facts and this box list.

8. Domain Model

8.1 Property Graph Data Model

A node is (id, label-set, properties); a relationship is (id, type, direction, start-node, end-node, properties) — always directed and always typed, exactly one type per relationship. A property value is one of: null | bool | i64 | f64 | string | list | map | point | date | time | datetime | duration (the Bolt/PackStream structure set, §8.3). Pattern grammar (EBNF fragment, the Phase-5 parser target, §17):

Pattern       ::= PatternPart (',' PatternPart)*
PatternPart   ::= NodePattern (RelPattern NodePattern)*
NodePattern   ::= '(' Variable? Labels? Properties? ')'
RelPattern    ::= ('-' | '<-') '[' Variable? RelTypes? RangeLit? Properties? ']' ('-' | '->')
Labels        ::= (':' SymbolicName)+
RelTypes      ::= ':' SymbolicName ('|' SymbolicName)*
RangeLit      ::= '*' IntegerLit? ('..' IntegerLit?)?

8.2 Storage Record Layout

Every record type is fixed-width (P2); the property record's payload chains via next_prop/prev_version.

Record Field Size Meaning
NodeRecord (40 B) in_use 1 B 1 = live, 0 = free (feeds I12 free-list check)
label_set_id 4 B bitset id, or pointer into label store if > 32 labels
first_rel 8 B first outgoing/incoming relationship (0 = none) — the I1 anchor
first_prop 8 B first property-chain block (0 = none)
xmin / xmax 8 B / 8 B creator / deleter transaction (I4)
padding 3 B rounds to 40 B ((8192-32)/40 = 204 records/page)
RelRecord (88 B) in_use, rel_type 1 B, 4 B live flag, relationship-type id
start_node, end_node 8 B, 8 B endpoint node ids
start_prev_rel/start_next_rel 8 B ea doubly-linked list at the start node
end_prev_rel/end_next_rel 8 B ea doubly-linked list at the end node (I1)
first_prop, xmin, xmax 8 B ea property chain head, MVCC stamps
padding 11 B rounds to 88 B (8160/88 = 92 records/page)
PropertyRecord (64 B) in_use, key_id, kind 1 B, 4 B, 1 B live flag, dictionary key, value-type tag
inline 16 B small values stored in place
overflow_block 8 B pointer into the dynamic block store for large values
next_prop 8 B property chain link
xmin, xmax 8 B ea MVCC stamps
prev_version 8 B version-chain link (I4, older version, 0 = none)
padding 2 B rounds to 64 B (8160/64 = 127 records/page)

Page header (32 B, prefixes every 8,192 B page): magic(4B) page_type(1B) reserved(1B) slot_count(2B) page_id(8B) lsn(8B) checksum(8B).

8.3 Wire Protocol Frame Layout

Bolt v4 frames a message as a sequence of length-prefixed chunks terminated by a zero-length chunk; PackStream serializes the property-value set of §8.1 plus the Node/Relationship/Path structures.

Bolt chunk field Size Meaning
chunk_len 2 B big-endian byte count of the chunk body (0 = message terminator)
chunk_body chunk_len B PackStream-encoded bytes; a message may span many chunks

Session states (the I10 state machine, detailed in §20.2): Disconnected → Connected → Ready ⇄ Streaming, and Ready ⇄ TxReady ⇄ TxStreaming, with Failed/Interrupted as error states reachable from any state and requiring an explicit RESET to return to Ready.

8.4 Query Semantics — Logical → Physical Lowering (Worked Example)

MATCH (a:Person)-[:KNOWS]->(b:Person) WHERE b.age > 30 RETURN b.name lowers as:

AST                     Logical Plan                  Physical Plan
Match(a:Person)     ->  NodeByLabelScan(Person, a) ->  NodeByLabelScan(Person, a)
-[:KNOWS]->(b:Person)  Expand(a, OUT, KNOWS, b)     ->  ExpandAll(a, OUT, KNOWS, b)
Where b.age > 30    ->  Filter(b.age > 30)          ->  Filter(b.age > 30)
Return b.name       ->  Project(b.name)             ->  Projection(b.name)

Predicate push-down (§18.2, ADR-09) would move Filter earlier only if age were bound before the expand; here it cannot, since b is produced by Expand.

8.5 Transaction & Snapshot State Machine

State Entered by Reads see Exits to
Active BEGIN Snapshot{xmin, xmax, active} taken at entry Committed or Aborted
Committed conflict-free COMMIT (I5) — (terminal; versions become visible to later snapshots) terminal
Aborted conflict detected, or explicit ROLLBACK — (terminal; versions unlinked and freed) terminal

8.6 Worked Example — End-to-End Trace

Ingest two :Person nodes (Ada, Grace) and one [:KNOWS] relationship, then run MATCH (a:Person)-[:KNOWS]->(b:Person) RETURN b.name. Trace: NodeByLabelScan(Person) yields {Ada, Grace} in id order → ExpandAll(OUT, KNOWS) walks Ada.first_rel (I1), finds the KNOWS relationship to Grace, yields (Ada, Grace) — Grace has no outgoing KNOWS so contributes no row → Projection(b.name) emits {"name": "Grace"}. One row.

8.7 Malformed-Input Example

MATCH (a)-[:KNOWS]->(b RETURN b.name (missing closing paren). The parser (§17.3) fails at the token following b, expected one of {')', ':', '{'}; graphd-cypher emits a ParseError{position: 27, expected: [...], found: "RETURN"} — no partial execution occurs.

8.8 Failure-Path Example

A transaction writes INSERT_PROP and COMMIT WAL records (durable), but the process is killed before the dirtied property page is flushed. Recovery: Analysis finds the transaction in the transaction table as committed; Redo replays INSERT_PROP because the on-disk page LSN is older than the record's LSN (I3, I8); Undo does nothing for this transaction. Post-recovery, the property is visible — exactly the ARIES contract (§14.5).

Design principles (§6)

  • P1 — Index-free adjacency is load-bearing. A node's neighbours are reachable by pointer chase, not a B-tree probe. Tradeoff: no secondary structure to keep in sync for traversal, at the cost of random-access page churn at high degree. Violating it (e.g. storing adjacency as a keyed lookup) turns every traversal into a probe and removes the engine's reason to exist.
  • P2 — Records are fixed-width; properties are chained. Node/relationship/label records are fixed-width so record id resolves to id * record_size. Tradeoff: wasted padding bytes vs O(1) offset math. Violating it means variable offsets and a directory structure the page cache must consult before every read.
  • P3 — One page format, one checksum. Every page is 8 KiB with a 32-byte header (magic, type, LSN, slot count, checksum) and an xxhash3-64 body checksum verified on every disk read. Tradeoff: 0.4% header overhead per page vs corruption detection. Violating it hides bit rot until a query returns wrong answers.
  • P4 — Snapshot isolation is the default. Readers see the snapshot at transaction start; writers see their own writes plus that snapshot. Tradeoff: write skew is possible (accepted); lost update is not (rejected at commit). Violating it either serializes everything (throughput loss) or silently drops updates (correctness loss).
  • P5 — The WAL is the source of truth. Every change is logged before the page is dirtied (write-ahead rule); recovery is "redo committed, undo uncommitted" (ARIES). Tradeoff: an fsync on the write path vs a database that can survive kill -9. Violating it makes crash recovery a coin flip.
  • P6 — openCypher is the one query language. Not Gremlin, not GQL-native, not SPARQL. Tradeoff: a smaller, well-specified surface (public TCK) vs the imperative composability Gremlin offers. Violating it (shipping two first-class languages at once) forces two planners to stay semantically identical forever.
  • P7 — The planner emits Volcano pull operators. Each operator is init/next/ close; the runtime is single-threaded per query in Phase 0. Tradeoff: simplicity and backpressure-for-free vs throughput left on the table until operator-level parallelism lands. Violating it (push-based execution) requires an explicit backpressure protocol from day one.
  • P8 — Cardinality lives in the index, not the planner. The planner asks "how many nodes match label X" and the index answers from a maintained counter. Tradeoff: the index carries bookkeeping weight vs a planner that stays storage-agnostic. Violating it (planner-side heuristics) drifts from ground truth as the index is the only thing that is ever exactly right.
  • P9 — Bolt is the wire format of record. gRPC and REST are convenience adapters over the same session machine. Tradeoff: adopting someone else's binary framing vs a from-scratch protocol. Violating it (inventing a new wire format) forfeits every existing Bolt driver.
  • P10 — Determinism is default. Two reads of the same snapshot, or two runs of the same query at the same snapshot, return bit-identical results (row order excepted absent ORDER BY). Tradeoff: cardinality estimates must be pinned to the snapshot, not to wall-clock sampling. Violating it makes EXPLAIN a lie and a flaky conformance suite.
  • P11 — Single writer per transaction, unlimited concurrent readers. A transaction's own writes are never contended by itself; other writers detect conflict only at commit (I5). Tradeoff: optimistic concurrency (retries) vs pessimistic locking (stalls). Violating it (locking on first write) turns every hot node into a serialization point.
  • P12 — Backpressure is implicit in pull iteration. A consumer only calls next when ready; no explicit credit protocol exists inside one process. Tradeoff: simplicity vs the need for an explicit protocol once execution crosses a process/network boundary (Bolt's PULL n message is exactly that boundary crossing, §20).
  • P13 — Recovery must be idempotent. Redo, applied twice, produces the same state as applied once (I8). Tradeoff: every WAL record must carry enough information (page LSN comparison) to become a no-op on replay. Violating it turns a second crash during recovery into data corruption instead of a safe retry.
  • P14 — Every deferred surface gets an ADR and a register row. No feature is silently dropped; it is either built or explicitly deferred with an anchor in the Deferred Features Register (§36). Violating it is how a codebase accumulates undocumented scope gaps that surface as production surprises.
