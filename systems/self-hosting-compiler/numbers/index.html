32. Back-of-Envelope Capacity Model

  • C1 — Parser Arena Footprint. 10,000,000 LOC × ~150 B live AST/token bytes per LOC = 1.5 GB, exactly the §4 parser ceiling (arena reset between files bounds peak, not cumulative usage).
  • C2 — Incremental Cache Steady-State Size. 10,000,000 LOC × ~350 B average serialized MIR+SSA cache entry per LOC = 3.5 GB, inside the §4 4 GB daemon ceiling with 500 MB headroom for index overhead.
  • C3 — Cold Compile Wall-Clock. 10,000,000 LOC ÷ 250,000 LOC/minute (§4 throughput floor) = 40 minutes for a from-scratch build of the full workspace.
  • C4 — Worker Pool Sizing. 64 cores (§4 vertical ceiling) × 4 logical workers per core (I/O-bound phases overlap CPU-bound phases) = 256 workers, exactly the §4 concurrency ceiling.
  • C5 — Monomorphization Peak. 8 GB ceiling ÷ ~2 KB average monomorphized-instance footprint = ~4,000,000 concurrently live generic instantiations before fail-closed rejection triggers.
  • C6 — Package Resolution Graph Walk. 5,000 nodes × 1.2 average edges per node × ~80 μs average SemVer-range constraint check per edge = 480 ms, inside the §4 500 ms budget.
  • C7 — FD Budget Under Peak Concurrency. 256 workers × 28 average open FDs per worker (source files + object outputs + linker pipes) = 7,168 FDs, inside the §4 8,192 soft limit with 12.5% headroom.
  • C8 — Incremental Recompile Latency Floor. 2 ms semantic-hash lookup + 200 ms p95 semantic reanalysis (§4) + 400 ms worst-case backend re-lowering = 602 ms, inside the §4 2,000 ms p99 incremental target with 3.3× margin.
  • C9 — Storage Amplification Ceiling. 10,000,000 LOC × ~120 B average source-byte footprint = 1.2 GB source tree, × 3 amplification ceiling (§4) = 3.6 GB maximum incremental-cache-plus-artifact footprint before compaction is forced.
  • C10 — Bootstrap Cycle Cost. 4 stages (stage0→stage3) × 40 minutes per full-workspace cold build (C3) = 160 minutes worst-case sequential bootstrap, amortized in practice because stage1/stage2 run incrementally (C8) rather than cold.
  • C11 — RTO Cache-Rebuild Feasibility. 5-minute RTO (§4) ÷ 40-minute cold-build baseline (C3) = an 8× shortfall, so the RTO target only holds if rebuild reuses a warm on-disk artifact cache — this is why I11's purge scope is per-entry, not global.
  • C12 — Deterministic Rebuild Verification Budget. 10 minutes (§4) ÷ 2 (build once, rebuild once to diff) = 5 minutes per build allowed, 8× less than the 40-minute cold-build baseline (C3), so the reproducibility gate must diff against a warm incremental cache, never a cold rebuild.
