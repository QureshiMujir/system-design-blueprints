Architecture, continued — the self-hosting/bootstrap plane (lyra-fixpoint) and the verification plane (lyra-diff), which sit beneath the query→codegen pipeline above.

   ───────────────────────  SELF-HOSTING / BOOTSTRAP PLANE  (lyra-fixpoint) ───────────────────────
     stage0 (Rust lyrac0) ──compiles Lyra-source compiler──► stage1 (lyrac1, in bytecode/native)
     stage1 ──recompiles its OWN Lyra source──► stage2 ;  GATE: bytes(stage1) == bytes(stage2)
     DDC: independent host lyrac0' ──► stage1' ; compile compiler with stage1 and stage1' ; compare.

   ───────────────────────  VERIFICATION PLANE  (lyra-diff) ───────────────────────
     clean build(out_c)  ==  incremental build(out_w after edit-replay)   [per-artifact byte compare]

Box: lyra-driver. CLI front door (lyrac build|check|emit|fixpoint|gc). Parses args, selects a build profile (debug/release/bootstrap — profile is a fingerprint input), opens/creates the cache, sets cli_flags() and source_text() input queries, demands the root query (codegen of all CGUs, or check for typeck-only), drains the diagnostics sink (sorted deterministically), persists the cache on success. Owns cache lifecycle (open → use → flush → close); never computes derived facts itself.

Box: lyra-db (query engine). The heart. Stores every query node: key, last value, output fingerprint, the revision at which value last changed/was verified, recorded input dependencies (edges), verified_at revision. Implements red-green: on a new revision derived queries are maybe-dirty; a query is re-verified by checking whether any dependency's fingerprint changed (green = unchanged → reuse value, no recompute; red = changed → recompute, then compare new fingerprint for early cutoff). Owns Revision counter + durability tiers, the Fingerprint store, the Dependency DAG + cycle detector, and serialization to/from the on-disk cache.

Box: lyra-span / lyra-intern. Interns files and strings; assigns Symbol, FileId, ItemPath. Critically provides relative spans — spans stored relative to an enclosing item's start, plus item-path hashes — so inserting a blank line at the top of a file does not change spans/IDs of items below it, so their derived queries stay green. This is the linchpin that makes incrementality not invalidate a whole file on every edit.

Box: parse(File) → AST. Derived query: takes source_text(File) (input), runs the error-recovering parser, returns an arena of AST nodes with AstIds. Fingerprint = hash of AST shape (not raw bytes), so reformatting-only edits that don't change structure early-cutoff downstream.

Box: resolve(Item) → HIR refs. Name resolution per item: builds module scopes, resolves identifiers to DefIds, lowers AST → HIR. Depends on parse of relevant files and on module_scope queries.

Box: type_of(Def) → Ty. Bidirectional + HM unification inference/checking for a definition. Depends on resolve and on type_of of referenced defs (forming the DAG the engine memoizes; type cycles are detected and surfaced as errors, not hangs).

Box: lir(Def) → SSA + opt. Lowers typed HIR to SSA-form LIR, runs the deterministic optimization pipeline. Output fingerprint enables early cutoff: a comment-only edit may change type_of fingerprint but not lir, stopping recompute before codegen.

Box: codegen(Cgu). Groups defs into content-addressed codegen units (CGU name = hash of the set of lir fingerprints it contains), emits bytecode or C99 text. Content-addressing means an unchanged CGU's artifact is reused verbatim — the core incremental win at codegen, and the thing that must be deterministic for the fixpoint.

Box: lbc modules / lyra-vm. Bytecode artifact format + register-machine interpreter with a tiny host shim (I/O, allocation). The VM runs lyrac1 (the self-hosted compiler) in the bootstrap plane.

Box: C99 text → external cc / native exe. Alternative backend emitting portable C99 text handed to system cc. Trust boundary: external cc/linker are outside our determinism control, so native fixpoint is checked at the C-text level (our output) plus the final binary when cc is itself reproducible.

Box: on-disk cache (.lyra-cache/). Persists DAG, fingerprints, serialized query values, artifacts. Crash-only: temp-file + atomic rename + fsync; corrupt entries detected by checksum and dropped (treated as cold). GC reclaims values unreachable from current roots within a durability budget.

Box: lyra-fixpoint (self-hosting plane). Orchestrates stage0→1→2, performs the byte-identity gate bytes(stage1) == bytes(stage2), runs diverse double-compilation (DDC) against an independent host build. Trust boundary: stage0 is the root of trust; DDC reduces reliance on it.

Box: lyra-diff (verification plane). Runs a clean build and an incremental build (cold cache vs warm-after-edit-replay) and byte-compares every artifact, enforcing any incremental build == equivalent clean build.

Box: Diagnostics. Collects errors/warnings with stable ordering (sorted by file, then byte offset, then code) so diagnostic output is reproducible (a fingerprint input under --deny-warnings).

8. Domain Model / Source Language (Lyra) — Grammar + AST + IR

8.1 Language overview (just enough to self-host)

Statically typed; module system; functions; struct/enum (sum types) with pattern matching; generics via monomorphization; traits/interfaces (static dispatch only in v1, dynamic dispatch deferred §19); explicit ownership + move semantics, no GC (the compiler manages its own arenas, like a real compiler); Result/Option-style error handling via enums; bounded integer + float + bool + string + array + reference types. No closures capturing by environment in v1 beyond top-level fn pointers (lambdas deferred to keep stage0 small, PhaseDeferred §19). Enough to express a lexer, parser, type-checker, IR, and codegen — i.e. itself.

8.2 Concrete grammar (EBNF, normative — docs/spec/lyra-lang.md)

Program     ::= { Item } ;
Item        ::= Module | FnDef | StructDef | EnumDef | TraitDef | ImplBlock | UseDecl | ConstDef ;
Module      ::= "mod" Ident "{" { Item } "}" ;
UseDecl     ::= "use" Path [ "as" Ident ] ";" ;
Path        ::= Ident { "::" Ident } ;
ConstDef    ::= "const" Ident ":" Type "=" Expr ";" ;

FnDef       ::= [ "pub" ] "fn" Ident [ Generics ] "(" [ Params ] ")" [ "->" Type ]
                ( Block | ";" ) ;            (* ";" = extern/forward decl *)
Generics    ::= "<" GenericParam { "," GenericParam } ">" ;
GenericParam::= Ident [ ":" TraitBound { "+" TraitBound } ] ;
TraitBound  ::= Path ;
Params      ::= Param { "," Param } ;
Param       ::= [ "mut" ] Ident ":" Type ;

StructDef   ::= [ "pub" ] "struct" Ident [ Generics ] "{" { Field } "}" ;
Field       ::= [ "pub" ] Ident ":" Type "," ;
EnumDef     ::= [ "pub" ] "enum" Ident [ Generics ] "{" { Variant } "}" ;
Variant     ::= Ident [ "(" Type { "," Type } ")" ] "," ;
TraitDef    ::= "trait" Ident [ Generics ] "{" { FnSig } "}" ;
FnSig       ::= "fn" Ident [ Generics ] "(" [ Params ] ")" [ "->" Type ] ";" ;
ImplBlock   ::= "impl" [ Generics ] [ Path "for" ] Type "{" { FnDef } "}" ;

Type        ::= "&" [ "mut" ] Type            (* reference *)
              | "[" Type ";" Expr "]"          (* fixed array *)
              | "[" Type "]"                    (* slice *)
              | Path [ "<" Type { "," Type } ">" ]  (* named / generic *)
              | "(" [ Type { "," Type } ] ")"  (* tuple/unit *)
              | PrimType ;
PrimType    ::= "i8"|"i16"|"i32"|"i64"|"u8"|"u16"|"u32"|"u64"|"usize"|"isize"
              | "f32"|"f64"|"bool"|"char"|"str" ;

Block       ::= "{" { Stmt } [ Expr ] "}" ;     (* trailing expr = block value *)
Stmt        ::= LetStmt | ExprStmt | ItemStmt ;
LetStmt     ::= "let" [ "mut" ] Pattern [ ":" Type ] [ "=" Expr ] ";" ;
ExprStmt    ::= Expr ";" | BlockExpr ;
ItemStmt    ::= FnDef | StructDef | EnumDef | ConstDef ;

Grammar, continued — the expression precedence ladder, patterns, and literals.

Expr        ::= Assign ;
Assign      ::= LogicOr [ "=" Assign ] ;
LogicOr     ::= LogicAnd { "||" LogicAnd } ;
LogicAnd    ::= Compare { "&&" Compare } ;
Compare     ::= Term { ("=="|"!="|"<"|"<="|">"|">=") Term } ;
Term        ::= Factor { ("+"|"-"|"|"|"^") Factor } ;
Factor      ::= Unary { ("*"|"/"|"%"|"&"|"<<"|">>") Unary } ;
Unary       ::= ("!"|"-"|"&"|"&mut"|"*") Unary | Postfix ;
Postfix     ::= Primary { Call | Index | Field | TryOp } ;
Call        ::= "(" [ Expr { "," Expr } ] ")" ;
Index       ::= "[" Expr "]" ;
Field       ::= "." Ident | "." IntLit ;        (* field / tuple index *)
TryOp       ::= "?" ;                             (* error propagation *)
Primary     ::= Literal | Path | "(" Expr ")" | BlockExpr | StructLit
              | "(" Expr { "," Expr } ")" ;       (* tuple *)
BlockExpr   ::= Block | IfExpr | MatchExpr | LoopExpr | WhileExpr | ForExpr
              | ReturnExpr | BreakExpr | ContinueExpr ;
IfExpr      ::= "if" Expr Block [ "else" ( IfExpr | Block ) ] ;
MatchExpr   ::= "match" Expr "{" { MatchArm } "}" ;
MatchArm    ::= Pattern [ "if" Expr ] "=>" ( Expr "," | BlockExpr ) ;
LoopExpr    ::= "loop" Block ;
WhileExpr   ::= "while" Expr Block ;
ForExpr     ::= "for" Pattern "in" Expr Block ;
ReturnExpr  ::= "return" [ Expr ] ;
StructLit   ::= Path "{" { Ident ":" Expr "," } "}" ;
Pattern     ::= "_" | Literal | Ident | Path [ "(" Pattern { "," Pattern } ")" ]
              | Path "{" { Ident [ ":" Pattern ] "," } "}" | "(" Pattern { "," Pattern } ")" ;
Literal     ::= IntLit | FloatLit | StrLit | CharLit | "true" | "false" ;

Lexical: identifiers [A-Za-z_][A-Za-z0-9_]*; ints with optional suffix (123i64, 0xFF, 0b1010, _ separators); floats 1.0, 1e9, f32 suffix; strings double-quoted with escapes; char single-quoted; comments // line, /* */ block (nesting allowed); trivia (whitespace/comments) preserved in the token stream for span fidelity but ignored by the grammar.

8.3 AST (lyra-ast) — node taxonomy + IDs

  • Arena-allocated; every node has an AstId (arena index, stable within one parse) and a relative span (offset from the enclosing item start). Top-level items also carry an ItemPath (e.g. crate::parser::expr).
  • Node families: Item{Fn,Struct,Enum,Trait,Impl,Mod,Use,Const}, Stmt{Let,Expr,Item}, Expr{Lit,Path,Bin,Un,Call,Index,Field,If,Match,Loop,While,For,Block,StructLit,Tuple,Return,Break,Continue,Try,Assign}, Pat{Wild,Lit,Bind,Tuple,Variant,Struct}, Type{Ref,Array,Slice,Path,Tuple,Prim}.
  • Error recovery: an ErrorNode family member exists for each family (ExprError, TypeError, ItemError) so a malformed subtree is localized, not fatal.

Illustrative AST node signatures (≤2 lines each, schema only):

struct FnDef { path: ItemPath, generics: Vec<GenericParam>, params: Vec<Param>, ret: TypeId, body: Option<BlockId>, span: RelSpan }
enum Expr { Lit(LitId), Path(PathId), Bin{op:BinOp,l:ExprId,r:ExprId}, Call{callee:ExprId,args:Vec<ExprId>}, /* … */ Error }

8.4 HIR (lyra-hir) — name-resolved, desugared

  • AST → HIR drops sugar: for → loop + iterator protocol calls; ? → match on Result; while → loop+if+break; method calls → fully-resolved function calls with explicit self; trait-bounded generic calls record the resolved impl. Every identifier becomes a DefId or a local HirId.
  • DefId = (crate, ItemPath-hash, disambiguator) — stable across edits as long as the item path is unchanged (INV-6). Local variables get HirIds scoped to the owning DefId.
struct DefId { crate_: u32, path_hash: u64, disambig: u16 }  // stable identity
enum HirExpr { Call{def:DefId, generic_args:Vec<Ty>, args:Vec<HirId>}, Match{scrut:HirId, arms:Vec<HirArm>}, /* … */ }

8.5 LIR (lyra-lir) — SSA mid-level IR (docs/spec/lir.md)

  • Per-DefId function = list of basic blocks; each block = list of SSA instructions ending in a terminator. Values are SSA %n. φ-nodes at control-flow merges (placed via dominance frontiers, P3). Types fully monomorphized (generics resolved → concrete Ty); no generic remains in LIR.
  • Memory model: explicit alloca/load/store before mem2reg; after mem2reg, scalars are SSA values, only address-taken locals remain in memory.

LIR text form (illustrative syntax shape only — no worked lowering):

fn @<crate::path> (%<arg>: <ty>, …) -> <ty> {
  bb<n>:
    %<v> = <opcode> %<operand>, …      ; arithmetic/compare/memory/cast (opcode set below)
    <terminator>                        ; br | condbr %<v>, bb<t>, bb<f> | switch | ret <v> | unreachable
  bb<t>: ret <v>
  bb<f>: %<v> = phi [bb<a>: <v>, bb<b>: <v>]
}

LIR opcode set (compact): arithmetic (add sub mul sdiv udiv srem urem and or xor shl shr), compare (eq ne slt sle ult ule sgt …), memory (alloca load store gep), aggregate (extractvalue insertvalue), control (br condbr switch ret unreachable), call (call), const (iconst fconst), cast (trunc zext sext fptosi sitofp bitcast), phi (phi). Type lattice: integer widths, float widths, pointer, aggregate (struct/array), bool, unit.

Verifier rules (enforced before opt + before codegen): SSA dominance (def dominates use); types well-formed; terminators end every block; φ operands = predecessor count; no use of poison after unreachable.

8.6 LBC bytecode (docs/spec/lbc.md)

  • Register VM (not stack): each function declares a register count; instructions are 4-byte aligned (opcode:u8, a:u8, b:u8, c:u8) with wide immediates in a side table; a per-module constant pool holds ints/floats/strings/function refs. Reloc-free: calls reference constant-pool function indices, resolved at module load, so module bytes are position-independent and content-addressable.
  • Module layout: [magic 'LBC0'][version u16][const pool][function table][code section][debug section(optional, excluded from fingerprint)].

8.8 Worked example — a 1-line edit, red-green propagation

Source: fn add(a:i64,b:i64)->i64 { a + b }. User edits the body a + b → a + b + 0.

revision r=7  (source_text(add.lyra) changed)
  lex(add.lyra)          : recompute → fp changes (token stream differs)
  parse(add.lyra)        : recompute → fp changes (AST has extra Bin node)
  module_scope(crate)    : verify → deps' fps unchanged (no new items) → GREEN (early cutoff)
  resolve(add)           : recompute → fp changes (HIR body differs)
  type_of(add)           : recompute → SAME fp (signature i64,i64->i64 unchanged) → EARLY CUTOFF
  typeck_body(add)       : recompute → fp changes (typed body differs)
  lir(add,[])            : recompute → fp changes (extra add %x,0 … then const-fold removes it!)
                           after opt the LIR is IDENTICAL to before → SAME fp → EARLY CUTOFF
  cgu_partition()        : verify → lir fps unchanged → GREEN
  codegen(cgu_of_add)    : verify → member lir fps unchanged → GREEN (artifact reused)
RESULT: zero artifacts re-emitted; warm rebuild ~ a few ms; INV-2 holds (clean build of the
        new source const-folds the same way → identical artifact).

This shows why early cutoff matters (the +0 is folded away, so codegen never runs) and why determinism matters (the fold must be identical clean vs warm).

8.10 State transition table — query node lifecycle

State Event Next state Action
Absent demanded Running execute, record edges + fp
Running completes Green@rev store value, fp, edges, verified_at=rev
Green@rev new revision r' MaybeDirty mark, do not recompute yet
MaybeDirty demanded at r' Verifying check each dep: recurse-verify
Verifying all deps green/unchanged fp Green@r' bump verified_at, reuse value (no recompute)
Verifying a dep's fp changed Running recompute; compare new fp
Running (after recompute) new fp == old fp Green@r' (early cutoff) keep value identity; do not dirty dependents
Running (after recompute) new fp ≠ old fp Green@r' (changed) store new value+fp; dependents become MaybeDirty
Green/MaybeDirty GC: unreachable from roots & beyond durability window Absent (evicted) drop value (keep fp+edges if cheap, else full evict)
any cache load checksum fail Absent treat as cold

Design principles (§6)

  • Determinism is the prime directive. Same inputs → byte-identical outputs, always (§4 = 100%). It is the precondition for both the self-hosting fixpoint and incremental==clean. Tradeoff: forbids HashMap iteration in any output path, ad-hoc thread interleaving in codegen, wall-clock/PID/env leakage. Operationally: a single nondeterministic byte = a CI-red fixpoint, debugged by bisecting passes with a determinism harness. Violating it makes the fixpoint flaky and the cache unsafe.
  • The incremental result must equal the clean result. (incremental == clean, §4, central invariant.) Every cache hit is a claim that recompute would produce the same value; the diff harness (lyra-diff) continuously falsifies that claim. Tradeoff: more bookkeeping (fingerprints, edges). Violating it = silent miscompile that only appears after an edit — the worst class of bug.
  • Inputs vs derived, strictly separated. Only source_text, file_list, cli_flags are inputs (set by the driver, bump the revision). Everything else is a pure function of inputs + other queries. Tradeoff: no hidden mutable state, no I/O inside derived queries. Violating it breaks red-green (a query that reads the clock can't be memoized correctly).
  • Fingerprints are content-addressed and versioned. A query's fingerprint = BLAKE3 of its serialized value; the cache carries a schema/compiler version that invalidates everything on mismatch (§7 INV-9). Tradeoff: cross-version cache reuse is sacrificed for correctness unless a fingerprint is provably stable. Violating it = a warm cache from an old compiler poisons a new one (cache poisoning, §Threat Model).
  • Stable identities survive edits. Relative spans + item-path hashing + interned DefIds mean inserting a line doesn't renumber items (§3 lyra-span). Tradeoff: indirection cost on every span resolve. Violating it = spurious invalidation (everything below an edit goes red → no incrementality) or, worse, ID reuse → silent miscompile.
  • Early cutoff is first-class, not incidental. A query that recomputes to the same fingerprint stops propagation immediately. Tradeoff: must compute the full value before knowing the fingerprint (no free lunch on the changed query, only on its dependents). Violating it = signature-preserving edits recompile the world (perf failure, §4 N-dependents target).
  • Crash-only persistence. The cache is written via temp+rename+fsync; any interrupted write leaves the prior consistent state; corrupt entries are checksum-detected and dropped (treated as cold), never trusted. Tradeoff: write amplification, fsync latency. Violating it = a torn write produces a valid-looking corrupt value → miscompile.
  • Bounded resources everywhere. Recursion-limited query depth (cycle detector), bounded codegen queue (backpressure), GC-bounded cache size (§4). Tradeoff: pathological inputs get a clean error, not a hang/OOM. Violating it = a malicious or generated program DoSes the compiler (§Threat Model).
  • Observability by default. Every query records hit/miss/red/green, recompute time, fingerprint; a structured red-green audit log is dumpable. Tradeoff: small per-query overhead (kept off the hot path via sampling in release). Violating it = "works clean, breaks incremental" is undebuggable.
  • The seed is the root of trust, and we minimize + verify it. stage0 (Rust) is small, audited, and its provenance is recorded; DDC (§23) is the standing defense against a compromised seed. Tradeoff: DDC doubles bootstrap cost. Violating it = a trusting-trust backdoor survives undetected.
  • No nondeterministic parallelism in output paths. Parallel query execution is allowed (it's pure), but order of effects (interning, codegen emission, diagnostics) is canonicalized by sorting on stable keys before serialization. Tradeoff: a sort/merge step. Violating it = thread-race nondeterminism → fixpoint flake.
  • Errors are values, recovery is mandatory. The parser/type-checker recover and continue, producing partial IR + sorted diagnostics; a query never panics on bad input. Tradeoff: error nodes thread through the IR. Violating it = one syntax error aborts the whole incremental session.
  • One source of truth per fact. A DefId's type is computed by exactly one query (type_of); no duplicate computation paths. Tradeoff: discipline on query boundaries. Violating it = two paths can disagree → nondeterminism + cache divergence.
  • Lyra stays small enough to self-host but no smaller. Feature set is bounded by "can it express this compiler?" Nothing added for elegance alone. Tradeoff: ergonomics sacrificed. Violating it = the language balloons, stage0 grows, the trust base widens, bootstrap slows.
  • Profiles are explicit and fingerprinted. debug/release/bootstrap differ in opt level + flags; the profile is a fingerprint input so a debug cache never serves a release build. Tradeoff: separate caches per profile. Violating it = cross-profile cache reuse → wrong artifact.
