Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. A lir query is reused as green after a fn-body edit, yet the clean build of the same source produces a different artifact. Which invariant is violated, which two harnesses detect it, and what is the first forensic artifact you inspect? (§24 + INV-2/INV-4 + §Failure Modes + MM2)
  2. Derive, from §4, the average CPU-time-per-query budget for the cold build, and explain why the front end being far under that budget does not mean the front end is irrelevant to warm-rebuild latency. (§Back-of-Envelope C6/C7 + §4 + §Performance Engineering)
  3. Explain why a type_of fingerprint that included the function body would pass every correctness test yet fail the §4 N-dependents target, and where the split between type_of and typeck_body enforces the right behavior. (§8.7 + §8.8 + Phase 5 §17 + MM3 + Principle 6)
  4. The fixpoint passes cold but a warm-cache fixpoint fails. Localize the bug class: what property must a cached CGU artifact have for the two to agree, and which design decision guarantees it? (§24 + §8.7 + ADR-13 + MM6/MM7 + INV-3)
  5. Why does diverse double-compilation defeat a Thompson backdoor that a GCC-style stage2==stage3 byte-compare does not, and what assumption must the "diverse" host satisfy for the DDC result to mean anything? (§Comparative Architecture + Phase 11 §23 + P1/P2 + ADR-18 + MM8)
  6. A blank line is inserted at the top of a 2000-line source file. Explain, query by query, why only the edited region's items recompute, naming the mechanism that keeps the DefIds below the edit stable. (§3 lyra-span box + §8.4 + Phase 3 §15 + INV-6 + MM5)
  7. Compute the warm 1-line-edit recompute count from the §4 hit-rate target and node count, then explain why the p50 latency is recompute-bound rather than verify-bound. (§Back-of-Envelope C4 + §4 + §8.10 + MM3)
  8. Why are source_text, file_list, and cli_flags the only input queries, and what specifically breaks in red-green if a derived query reads the wall clock? (§8.7 + Principle 3 + ADR-28 + MM9 + INV-1)
  9. A torn write during a cache flush leaves a file on disk. Explain why it can never be served as a valid-looking wrong value, naming the two mechanisms that jointly guarantee this. (Phase 6 §18 + §8.7 + ADR-13 + INV-8 + MM7/MM10)
  10. The same compiler-src/ is compiled by lyrac0 (Rust) and lyrac1 (Lyra). Why must their bytes agree before Phase 11 is even attempted, and what single class of bug most commonly breaks that agreement? (Phase 9 §21 + Phase 11 §23 + INV-1 + MM4)
  11. Why does the cache carry a version header that triggers full invalidation on mismatch rather than a migration, and what would a migration path put at risk? (INV-9 + §Compatibility Guarantees + §Operational Readiness + MM10)
  12. Trace how a comment-only edit can change the parse fingerprint's input yet still early-cut before resolve, and contrast it with a reformat that changes no AST shape. (§8.8 + §8.9 + §8.7 + Principle 6)
  13. Explain why monomorphization is collected as a BTreeSet and what determinism failure a HashSet would introduce, tracing the consequence all the way to the fixpoint. (Phase 5 §17 mono_instances + ADR-17 + INV-1 + Phase 11 §23 + MM4)
  14. Given the §4 VM throughput and the "≤5× native" target, estimate the worst-case cold VM self-compile time and justify why stage2 prefers the C-native lyrac1. (§Back-of-Envelope C8 + §4 + Phase 10 §22)
  15. Why is an absolute-byte-span model an automatic incrementality failure even though it is functionally correct, and which real reference implementation's span design does this project follow instead? (ADR-5 + INV-6 + §5 R1 + MM5)
  16. A second target triple is added. Enumerate everything that must fold the triple into its identity for incremental==clean and the fixpoint to still hold. (§8.7 CGU naming + §Deferred Features Register + INV-1/INV-2 + Phase 8 §20)
  17. Explain why content-addressed CGU naming is simultaneously the codegen incremental win and a fixpoint enabler — i.e. why the same mechanism serves both hard properties. (§8.7 + §20 + §24 + MM6/MM7)
  18. The determinism harness must run 100× cold builds. Compute why this forces a PR-vs-nightly split and which weaker check stands in on every PR. (§Back-of-Envelope C11 + §Testing Strategy + INV-1)
  19. Why can a query cycle (e.g. struct S { x: S }) never hang the compiler, and what bounds both the detection and the recovery? (§8.9 + Phase 4 §16 + INV-7 + Phase 5 §17)
  20. Distinguish the two failure signatures of DefId instability — spurious invalidation vs silent miscompile — and explain which is a perf bug and which is a correctness bug, with the detection path for each. (Phase 3 §15 + INV-6 + §Failure Modes + MM5)
  21. Why does the C99 backend emit float constants as hex-float literals rather than decimal, and how does this connect the external-cc trust boundary to INV-14? (Phase 8 §20 + §3 C-backend box + INV-14 + ADR-29)
  22. Explain why "restore" of the cache is identical to a cold build, and why this makes the cache the one piece of state never backed up. (§Operational Readiness backup/restore + Phase 6 §18 + MM10 + INV-8)
  23. A signature change touches N true dependents. Derive why warm-rebuild cost is ~50 ms × N and what mechanism prevents false dependents from inflating N. (§4 + §8.8 + Principle 6 + MM3)
  24. Why is the bootstrap seed (stage0) the one component whose memory safety is non-negotiable, and how does ADR-1's language choice plus DDC jointly bound the trust placed in it? (Principle 10 + ADR-1 + §Threat Model + Phase 11 §23 + MM8)
  25. Given the §4 cache-size bound (≤3× artifacts) and the keep-one-prior-revision rule, derive the GC's reclamation target and explain why keeping exactly one prior revision (not zero, not many) is the chosen point. (§Back-of-Envelope C5 + Phase 6 §18 + §4 + §Scalability Analysis)

Mental Models & First Principles

The compressed intuitions an expert holds about an incremental, self-hosting compiler. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — Incremental compilation is a memoized pure function; the cache is a claim that recompute would agree. Every query is a deterministic function of its inputs; a green (reused) node asserts "recomputing me yields the same value." Predicts: correctness reduces to two obligations — the function is pure (no hidden inputs) and every input it read is recorded as a dependency. Bug without it: treating the cache as a side store you "update", introducing a path where the cached value and a fresh recompute disagree. Applied: Principle 1/2/3 (§6), §8.7 query DAG, Phase 4 (§16), MM cross-link to INV-4.
  • MM2 — A missing dependency edge is the canonical silent miscompile, not a perf bug. If a query reads something it didn't record, an edit to that something leaves the query wrongly green. Predicts: the failure is invisible until a specific edit sequence fires, and only a clean-vs-warm differential catches it — unit tests never will. Bug without it: "works clean, breaks incremental" miscompiles that ship. Applied: INV-5, Phase 4 edge capture (§16), Phase 12 incremental==clean (§24), §Failure Modes.
  • MM3 — Early cutoff is the difference between O(edit) and O(program). A query that recomputes to the same fingerprint must stop dirty-propagation there; without it a signature-preserving body edit re-runs the world. Predicts: the +0-then-const-folded edit (§8.8) re-emits zero artifacts iff cutoff fires at lir; a fingerprint that includes irrelevant data kills cutoff and the §4 N-dependents target. Bug without it: warm rebuilds scale with program size, not edit size. Applied: Principle 6 (§6), §8.8 worked example, §8.10 state table, Phase 4 (§16), C-model link below.
  • MM4 — Determinism is engineered, not inherited; a single unordered iteration poisons everything downstream of it. Parallelism, HashMap order, libc float formatting, timestamps, and thread-race interning are all latent nondeterminism. Predicts: one HashMap in a const-pool emit makes the fixpoint flake on a different machine, invisible on yours. Bug without it: a flaky bytes(stage1)==bytes(stage2) gate that gets "retried away" instead of root-caused. Applied: Principle 1/11/17 (§6), ADR-17/ADR-29, INV-1/INV-13/INV-14, Phase 8 (§20).
  • MM5 — Stable identity is a content property, not a position property. A DefId keyed by item-path hash survives a blank-line insert; one keyed by sequential position does not. Predicts: if IDs renumber on insert, either everything below an edit goes red (no incrementality) or — worse — a cache entry keyed by an ID that now denotes a different item is reused (miscompile). Bug without it: ID reuse → the most dangerous bug class in the system. Applied: ADR-5/ADR-6, INV-6, §8.4 DefId, Phase 3 (§15), Phase 12 move-item fixture (§24).
  • MM6 — Self-hosting is a determinism proof, and incrementality is a determinism risk; the project is the collision of the two. The fixpoint bytes(stage1)==bytes(stage2) can only hold if codegen is deterministic; a warm cache introduces a second way to produce those bytes that must agree with the cold way. Predicts: a warm-cache fixpoint can pass while a cold one fails (or vice-versa) iff a cached artifact embeds anything not a pure function of its members. Bug without it: certifying the fixpoint cold and assuming it holds warm. Applied: §1 (the union property), INV-2 ∧ INV-3, Phase 11 (§23), Phase 12 warm-cache fixpoint (§24).
  • MM7 — Content-addressing turns "is this artifact reusable?" into a hash comparison and makes reuse safe by construction. A CGU named by blake3(member fingerprints ++ profile ++ target) cannot be confused with a different CGU, and a torn write whose bytes don't hash to its name is self-detecting. Predicts: dedup is automatic (identical CGUs share one file) and a corrupt cache entry can never be silently trusted. Bug without it: a name collision serves the wrong artifact, or a torn write surfaces as a valid-looking value. Applied: §8.7 CGU naming, ADR-13, INV-8, Phase 6 (§18), Phase 8 (§20).
  • MM8 — Trusting-trust means the seed's identity, not its source, is the trust root — so you attack it by diversity, not by reading code. A backdoor can reproduce through self-hosting even when compiler-src/ is clean; reading the source proves nothing. Predicts: only compiling the compiler with two independent hosts and comparing outputs (DDC) can show the output is seed-identity-independent. Bug without it: believing "I audited the source, therefore the binary is clean." Applied: Principle 10, P1/P2, ADR-18, Phase 11 DDC (§23), §Threat Model.
  • MM9 — Inputs vs derived is a hard wall; the moment a derived query reads the clock/env/disk it stops being memoizable. Only source_text/file_list/cli_flags may be inputs; everything else is a pure function of them. Predicts: a derived query that reads wall-clock time can be green when it should be red (its hidden input changed) — red-green is unsound for it. Bug without it: non-reproducible builds and unsound caching from one stray I/O. Applied: Principle 3 (§6), §8.7 (input vs derived), Phase 4 (§16), ADR-28 (clock discipline).
  • MM10 — The cache is derived data: its correct recovery action is always "throw it away and recompute," never "repair it." Because every cached value is reconstructible from source, a version skew, a corrupt entry, or a torn write is recovered by dropping to cold — repair logic would be a new, untested code path that can itself miscompile. Predicts: the right response to any cache anomaly is invalidation, and "restore" is just a cold build. Bug without it: building cache-repair/migration machinery that introduces a wrong-value path the rebuild path can't. Applied: INV-8/INV-9, ADR-14, §Operational Readiness (backup/restore), Phase 6 (§18).

Glossary · 45 terms · site-wide glossary

Lyra
The small statically-typed systems language defined + compiled by this project; the compiler is written in it (self-hosting).
stage0 / lyrac0
The bootstrap compiler written in Rust; the root of trust; compiles Lyra source.
stage1 / lyrac1
The Lyra-source compiler compiled by stage0 (runs on the VM or as C-native).
stage2 / lyrac2
stage1 recompiling its own source; must be byte-identical to stage1 (the fixpoint).
Bootstrap fixpoint
The property bytes(stage1) == bytes(stage2); the self-hosting acceptance gate (INV-3).
Self-hosting
A compiler able to compile its own source language, written in that language.
Trusting trust
Thompson's attack: a compromised compiler injects a backdoor that survives self-hosting even with clean source (P1).
DDC (diverse double-compilation)
Wheeler's defense (P2): compile the compiler with two independent hosts; identical output ⇒ no seed-dependent backdoor.
Seed provenance
The recorded, auditable account of how stage0 was built (toolchain, host, hash); a security artifact.
Incremental compilation
Recompiling only the parts affected by an edit, via a memoized dependency graph.
Query
A pure, memoized unit of compilation (e.g. parse(File), type_of(Def)); the node of the incremental engine.
Input query
A query whose value is set externally (source_text, file_list, cli_flags); bumps the revision.
Derived query
A query computed purely from inputs + other queries; memoized + fingerprinted.
Demand-driven
Computation triggered by demanding a result (lazy), not eagerly; the engine's execution model.
Red-green algorithm
The verification scheme: dirty (red) nodes recompute; clean (green) nodes reuse their value.
Early cutoff
Stopping dirty-propagation when a recomputed value has the same fingerprint as before.
Fingerprint
A BLAKE3 hash of a query's canonical value; equality ⇒ unchanged ⇒ early cutoff.
Revision
A monotonically increasing counter bumped on every input change; orders red-green checks (INV-10).
Durability tier
A classification (Volatile/Low/High) governing whether a cached value is fsync'd; bounds flush latency.
Content-addressed
Named by the hash of its contents (artifacts, CGUs, cache values) ⇒ automatic dedup + tamper-evidence.
CGU (codegen unit)
A group of monomorphized defs codegen'd together; its name = hash of member fingerprints (§8.7).
Relative span
A source span stored relative to its enclosing item's start, so edits elsewhere don't shift it (INV-6).
DefId
A stable item identity = (crate, item-path hash, disambiguator); survives edits that don't change the path.
Symbol
An interned string id, assigned deterministically across threads (INV-13).
HIR
High-level IR: name-resolved, desugared AST (§8.4).
LIR
Low/mid-level IR in SSA form, fully monomorphized; the optimization + codegen substrate (§8.5).
SSA
Static single assignment: each value assigned once; φ-nodes merge at control-flow joins.
mem2reg
The pass promoting alloca-backed locals to SSA registers.
Monomorphization
Generating a concrete copy of a generic for each set of type arguments used.
Bidirectional typing
A type-checking discipline alternating check(expr,expected) and infer(expr)→Ty (P10).
HM (Hindley–Milner)
Type inference with unification + let-generalization yielding principal types (P11).
LBC
The reloc-free register-VM bytecode module format (§8.6).
lyra-vm
The register-machine interpreter that executes LBC (runs lyrac1 during bootstrap).
Mangling
Deterministic encoding of (item path, type args) into a unique symbol name (INV-15).
incremental == clean
The central invariant: a warm (cached) build's output is byte-identical to a cold build's (INV-2).
Warm-cache fixpoint
The interaction property: the bootstrap fixpoint still holds when built with a warm incremental cache (§24).
Cache poisoning
Serving a stale/incompatible/tampered cache value as current → silent miscompile (threat).
Cache version
A header tag = compiler/cache-format version; a mismatch triggers full invalidation (INV-9).
Crash-only
A persistence design where the only "shutdown" is a crash; recovery = reopen a consistent prior state.
Atomic rename
The POSIX rename(2) used to publish cache writes atomically (the commit point, INV-8).
Trivia
Whitespace/comments preserved in the token stream for span fidelity but ignored by the grammar.
Edit script
A serialized sequence of byte-range edits used by the fuzzer + replayer to drive incremental tests.
Confluence
The property that optimization passes reach the same result regardless of order; needed for determinism.
Profile
A build configuration (debug/release/bootstrap); a fingerprint input; caches are isolated per profile (INV-12).
Root of trust
stage0 — the one component whose integrity the whole self-hosting chain depends on.
