Mental Models & First Principles

The compressed insights an expert decompiler engineer holds. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — A decompiler is a compiler run backwards. Lifting = parsing; SSA/data-flow = the middle-end; structuring = the inverse of lowering; emission = the inverse of codegen. Predicts: every compiler analysis has a decompiler dual. Without it: you reinvent SSA/data-flow badly instead of borrowing 40 years of theory. Applied: §3, Phase 4–8.
  • MM2 — Flags are state; drop them and you lose the conditionals. cmp writes ZF/SF/CF/OF; jcc reads them. Predicts: the sign of every recovered </> lives in which jcc consumed the flags. Without it: inverted/garbage conditions — the #1 beginner bug. Applied: I1, §8.2, Appendix D.3.
  • MM3 — SSA makes data-flow sparse. One def per value makes def-use explicit; propagation/DCE become near-trivial. Predicts: O(program-points) analyses become O(values). Without it: quadratic def-use rebuilds and propagation across redefinitions. Applied: I2, Phase 4–5, Appendix I.
  • MM4 — φ lives at the iterated dominance frontier. A value defined in several blocks needs a merge exactly where their dominance ends. Predicts: too few φ = wrong values, too many = noise. Without it: ad-hoc φ that is both incorrect and bloated. Applied: I3, Phase 1/4, Appendix H.
  • MM5 — A monotone transfer on a finite-height lattice always terminates. Predicts: convergence is bounded by height × |blocks|; a hang means the transfer isn't monotone. Without it: data-flow that loops forever on adversarial input. Applied: I5, Phase 5, Appendix I.
  • MM6 — Reducibility is the line between structured and goto. A reducible CFG collapses to one node via interval analysis → goto-free; irreducible needs node-split or goto. Predicts: which functions can be made pretty. Without it: spaghetti output or wrong structure. Applied: I7/I8, Phase 8/9.
  • MM7 — Correctness ≠ resemblance. The contract is semantic equivalence to the binary, not similarity to the lost source. Predicts: optimized code legitimately decompiles to correct-but-different structure. Without it: you "fix" output to look like source and break it. Applied: I4, Phase 11, Appendix N.2.
  • MM8 — Types are evidence, not truth. Each use is a constraint; the type is the unification of all of them; conflict means widen, not pick. Predicts: confidently-wrong types come from trusting one weak signal. Without it: misleading declarations. Applied: I10, Phase 7, Appendix F.
  • MM9 — Single-use folding turns assembly into expressions. Substituting a value defined once and used once into its use builds nested expressions. Predicts: readability scales with safe fold opportunities. Without it: flat three-address soup. Applied: Phase 6, §6.2.
  • MM10 — Per-function isolation is the scaling primitive. Each function is an independent, arena-scoped, Send unit. Predicts: throughput scales linearly with cores and a bad function fails alone. Without it: cross-function corruption and no parallelism. Applied: I11/I12, Scalability Analysis.

Required reading (§5)

Books

  • Cifuentes, Reverse Compilation Techniques (PhD thesis, 1994) — the foundational decompilation + structuring algorithms (intervals, derived sequences); applied in Phase 8/Phase 9 (structuring) — the project's backbone throughout.
  • Aho/Lam/Sethi/Ullman, Compilers (Dragon), 2e — book's own §6 (IR), §8–9 (data-flow, SSA intro), §9.7 (structuring); applied in Phase 0 (IR design), Phase 4/5 (SSA + data-flow), Phase 8/9 (structuring in reverse).
  • Cooper & Torczon, Engineering a Compiler — dominators, SSA construction, data-flow framework (read forward, apply backward); applied in Phase 1 (dominators), Phase 4 (SSA), Phase 5 (data-flow framework).
  • Muchnick, Advanced Compiler Design & Implementation — control-flow + data-flow analyses, interval analysis, structuring; applied in Phase 1 (intervals), Phase 5 (data-flow), Phase 8/9 (structuring).
  • Appel, Modern Compiler Implementation — SSA, liveness, register/temp modeling; applied in Phase 0 (the lifter's value model), Phase 4 (SSA), Phase 5 (liveness).
  • Eilam, Reversing: Secrets of Reverse Engineering — practical decompilation context + idioms; applied in Phase 6 (idiom recovery) and the Threat Model (obfuscation posture).
  • Pierce, Types and Programming Languages — constraint-based typing basis; applied in Phase 7 type recovery (cf. #238).
  • Klabnik & Nichols, The Rust Programming Language — enums, pattern matching, arenas/ownership; applied in Phase 0 (IR type definitions) and every crate's arena-scoped graph code.

Glossary · 52 terms · site-wide glossary

Decompiler
Tool recovering high-level structured code from machine code.
Lifting
Translating instructions into IR with explicit semantics (incl. flags).
IR
Intermediate Representation; low register-transfer form here.
SSA
Static Single Assignment; each value defined once, with φ at joins.
φ (phi)
SSA node selecting a value per incoming CFG edge.
Dominator
A block on every path from entry to a given block.
Immediate dominator (idom)
The closest strict dominator.
Dominance frontier
Blocks where a definition's dominance ends; φ-placement sites.
Interval
Cifuentes' single-entry CFG region used for structuring.
Reducible CFG
A CFG structurable into loops/conditionals without gotos.
Irreducible CFG
A CFG with multiple-entry loops; needs node-split or gotos.
Natural loop
A loop defined by a back-edge whose head dominates the tail.
Back-edge
A CFG edge to a dominating (header) block.
Liveness
Whether a value is used on some path after a point.
Reaching definitions
Which defs may reach a use.
Def-use chain
Links from a definition to its uses.
Constant propagation
Replacing values known-constant.
Copy propagation
Replacing a copy's target with its source.
Dead-code elimination (DCE)
Removing computations with no live use.
Flag modeling
Representing CPU condition flags (ZF/SF/CF/OF) in IR.
Relational folding
Recovering <,== from flag-defining op + conditional jump.
Idiom recovery
Rewriting compiler patterns into readable source forms.
Type recovery
Inferring size/sign/pointer-ness of values.
Constraint solving
Unifying type constraints (union-find) to assign types.
Structuring
Converting a CFG into nested loops/conditionals/switch.
Node splitting
Duplicating a block to make an irreducible region reducible.
Goto fallback
Emitting labeled gotos when structuring is impossible.
Stack slot
A stack frame offset treated as a candidate variable.
Calling convention
ABI rules for argument/return registers + saved regs.
Coalescing
Merging SSA versions back into one named variable for output.
Semantics preservation
A transform not changing observable behavior.
Emulator (reference)
The IR interpreter used as the semantics oracle.
Pseudo-C
Readable C-like output approximating the source.
Approximation
The honest status of decompiler output (not a guaranteed recompile).
Worklist
Queue driving fixed-point data-flow/iteration.
Lattice
The ordered value domain of a data-flow analysis.
Fixed point
The stable result of an iterative monotone analysis.
Derived sequence
Cifuentes' successive interval graphs; collapse ⇒ reducible.
Latch
The block with the back-edge to a loop header.
Pre-test / post-test loop
Condition at the top (while) vs bottom (do-while).
Immediate post-dominator
The join point of a branch; the if merge.
Short-circuit
&&/`
Loop-carried value
A value updated each iteration (φ at the header).
Interference
Two values simultaneously live (cannot share a name).
Live range
The span over which a value is live.
Coalesce
Merge non-interfering values/versions into one variable.
Un-SSA
Removing φ/versions to produce named variables for output.
Magic-number division
Multiply-by-reciprocal + shift implementing / const.
Opaque predicate
An always-true/false branch inserted to obstruct analysis.
Semantic equivalence
Identical observable behavior (the correctness criterion).
Quality metric
A measured-but-non-gating property (structure/type accuracy, goto rate).
Capstone
This project's role: the top of the 333→334→335 pipeline.
