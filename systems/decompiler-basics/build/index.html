⬜ Phase 0 — Skeleton, IR, Lifter (integer subset), CFG Import, Naive Emission, CLI

Objectives

Define the IR (dec-ir), lift the #334 integer subset to IR with explicit flag effects (I1), import the CFG + compute dominators, and emit a naive (unstructured, goto-per-edge) listing. Constraint: flags are modeled from the very first instruction lifted.

Deliverable

decomp fn a.out main lifts main to IR and prints a (gotos-everywhere) C-like listing whose control flow matches the CFG.

Acceptance
  • Lifts the integer subset; dec-emu (stub) confirms ≥10 hand vectors covering every opcode in Appendix D.2 (I1 spot-check, fixtures lift/mov_arith/lift/cmp_jcc/lift/mem_loadstore).
  • Naive output's control flow matches #334 CFG exactly (fixture pseudoc/naive_goto).
  • Dominator tree correct on fixtures cfg/idom_diamond/cfg/idom_loop (vs hand-computed).
  • Fuzz smoke: any #334 input → 0 panics over ≥1e5 seed executions (I9).
Fixtures
Fixture Purpose Expected
lift/mov_arith mov/add/sub/lea lift incl. flags IR matches Appendix D.2; lea→arithmetic, no Load
lift/cmp_jcc flag defs + conditional branch Branch(Flag-expr,…); ZF/SF/CF/OF all set (I1)
lift/mem_loadstore memory operands Load/Store with correct size
cfg/idom_diamond dominators on a diamond idom matches hand-computed (M4)
cfg/idom_loop dominators with a back-edge header dominates latch; loop detected
pseudoc/naive_goto unstructured baseline control flow matches #334 CFG exactly
Pitfalls
  • Forgetting flags (I1) → jcc conditions unknown later; model from day 0.
  • lea is arithmetic, not a load → IR add/shl, no memory access.
  • Sub-register writes (al vs rax) → partial-def modeling (or widen conservatively).
  • Sign vs zero extension in lifts → wrong values.

⬜ Phase 1 — Dominators, Dominance Frontiers, Interval Analysis

Objectives

Solidify the structural foundation: immediate dominators, dominance frontiers (for SSA), and Cifuentes intervals / derived sequence (for structuring). Constraint: correct on reducible and irreducible graphs.

Deliverable

decomp cfg --dom --intervals <fn> prints dom tree, DF, intervals, loops, reducibility.

Acceptance

idom/DF match reference exactly on cfg/golden_* (100% match, M4); loop nesting depth correct on cfg/nested_loops; irreducible graphs detected on cfg/irreducible (0 misclassifications).

Fixtures
Fixture Purpose Expected
cfg/nested_loops loop nesting + intervals nesting depth + headers match golden
cfg/irreducible multi-entry loop flagged irreducible, not misclassified (MM6)
cfg/switch_cfg jump-table dispatch n-way successor set recognized
cfg/self_loop single-block back-edge natural loop with one latch
cfg/golden_* dom/DF/intervals lock match hand-computed reference (M4)
Pitfalls
  • Irreducible CFGs (from goto/optimized code) break naive interval analysis → detect + flag for Phase 9.
  • Multiple back-edges to one head → single loop with multiple latches.
  • Unreachable blocks skew dominators → prune first.
  • DF computation off-by-one → wrong φ placement later (I3).

⬜ Phase 2 — Reference IR Emulator (semantics oracle)

Objectives

Build a tiny IR interpreter (dec-emu) that executes IrCfg over a register/memory state, to serve as the semantics-preservation oracle for the lifter (I1) and every transform (I4). Constraint: the emulator is the ground truth for "did this transform change behavior?"

Deliverable

decomp verify <fn> runs lifted-IR vs reference on random inputs and reports semantic equivalence; the transform-check harness is reusable by later phases.

Acceptance

Lifted IR matches reference on 10k random input vectors per fixture (I1); harness detects an injected semantics-breaking transform.

Fixtures
Fixture Purpose Expected
lift/semantics_vectors lifted IR vs reference match on 10k random inputs/fixture (I1)
dataflow/transform_equiv before/after a pass identical observable state (I4)
lift/injected_bug planted lift error differential catches it (proves the oracle)
lift/undef_flags x86 undefined-flag cases undefined flags modeled "unknown", not compared
Pitfalls
  • Undefined flags after some ops (x86 leaves some undefined) → model as "unknown", don't compare those.
  • Memory aliasing in the emulator → conservative model.
  • Wraparound/overflow semantics must match x86 exactly.
  • Nondeterministic inputs → seed the random vectors (I6).

Deliverable

decomp fn shows calls with recovered args (foo(a, b)) and stack slots as distinct variables.

Acceptance

Stack slots correctly separated (fixture dataflow/stack_slots); args recovered for both calling conventions (fixtures dataflow/sysv_args, dataflow/msx64_args); callee-saved restores recognized as ABI, not data (fixture dataflow/callee_saved, 0 false-positive locals).

Fixtures

⬜ Phase 4 — SSA Construction (φ placement + renaming)

Objectives

Transform the IR into SSA: place φ at iterated dominance frontiers (I3), rename values to versioned defs (I2), verify single-assignment. SSA is the substrate for all later analyses (principle 2).

Deliverable

decomp ssa <fn> prints SSA-form IR with φ nodes; verifier passes.

Acceptance

SSA verifier passes on 100% of fixtures (I2, fixture ssa/diamond_phi/ssa/loop_phi/ssa/nested/ssa/flags_ssa); φ count matches the iterated-DF count exactly (M5, I3); renaming correct vs the hand-traced example, byte-for-byte on ssa/golden_* (§8.3).

Fixtures
Fixture Purpose Expected
ssa/diamond_phi φ at a simple join one φ at the post-dominator; args = 2 preds (I3)
ssa/loop_phi loop-carried value (Appendix H) header φ captures init + latch versions (I2)
ssa/nested nested loops φ at each header; iterated DF correct
ssa/flags_ssa flags as SSA variables flag versions distinct; no missed φ (4.6)
ssa/golden_* renaming golden matches §8.3 hand-trace exactly
Pitfalls
  • Forgetting flags as SSA variables → flag versions wrong → bad conditionals.
  • Sub-register defs create partial defs → model as read-modify-write or widen.
  • Iterated DF (φ creates new defs needing more φ) → fixpoint, not one pass.
  • Memory in SSA → keep memory out of scalar SSA (model as Load/Store; optional memory-SSA later).

⬜ Phase 5 — Data-Flow: Liveness, Reaching Defs, Const/Copy Propagation, DCE

Objectives

Run the analysis suite on SSA via a monotone-lattice worklist (I5): liveness, reaching defs, def-use chains; then constant + copy propagation and dead-code elimination — crucially killing dead flag computations (I11). Every transform preserves semantics (I4).

Deliverable

decomp ssa --opt <fn> shows propagated, DCE'd SSA — far fewer temporaries; dead flags gone.

Acceptance

Analyses converge within the height × |blocks| iteration cap (I5, fixture dataflow/nonconverge_guard); propagation+DCE preserve semantics on the emulator (I4, fixtures dataflow/const_prop/dataflow/copy_prop); dead-flag elimination removes ≥90% of lifted flag defs (M7, fixture dataflow/dce_flags); no live code removed (I11, 0 regressions on dataflow/liveness).

Fixtures
Fixture Purpose Expected
dataflow/const_prop constant folding known constants substituted; emulator-equiv (I4)
dataflow/copy_prop copy collapse x=y chains removed; semantics preserved
dataflow/dce_flags dead-flag elimination ≥90% flag defs removed (M7); no live flag dropped (I11)
dataflow/liveness backward liveness live sets match hand-computed
dataflow/nonconverge_guard non-monotone transfer injected E.NONCONVERGENCE raised, not a hang (I5)
Pitfalls
  • Over-aggressive DCE removing a flag still used by a later branch → liveness must include flags (I11).
  • Propagating across a redefinition (non-SSA thinking) → SSA prevents, but φ care needed.
  • Memory propagation without alias analysis → unsound; restrict to scalars.
  • Non-convergence from a non-monotone transfer → enforce lattice monotonicity (I5).

Fixtures
Fixture Purpose Expected

Pitfalls

  • Over-folding into unreadable mega-expressions → cap nesting depth / keep named temps for reuse.
