Application Layer. The user-facing surface: instantiate a Pattern, call coordinator.run(pattern, inputs), consume an AsyncIterator[Event]. No coordination logic leaks here.

Coordinator (Phase 4). The single orchestrator. Compiles a pattern into a DAG, runs the dispatch loop, owns the budget/deadline/stuck-loop watchdogs, and is the only place routing decisions are made.

Contract Net (Phase 3). Task allocation by announce/bid/award/result with timeouts. The default allocator; FIPA-shaped envelopes.

DAG Executor (Phase 5). Walks the compiled graph in topological order with branching, bounded loops, persistent state for pause/resume, and streaming through edges.

Message Bus (Phase 2). The only inter-agent channel. Typed Pydantic envelopes, bounded queues with backpressure, dead-letter on retry exhaustion, three delivery modes.

Worker (Phase 1). A thin wrapper around the Agentic-Framework runtime adding typed I/O and a per-message span. The kernel never reaches into the agent's tool registry or model provider.

Blackboard (Phase 6). Shared state, not communication. Concurrent KV with CAS, subscriptions, conflict detection, TTL, per-run isolation.

Per-Agent Memory (Phase 7). Episodic (verbatim log), semantic (distilled facts), shared (team knowledge base on the Vector-Database).

Tracing + Observability (Phase 8). OpenTelemetry spans mirroring the dialogue, Prometheus metrics, and a per-call cost ledger.

Three load-bearing properties: (1) the data path is one-way — tasks flow application→coordinator→workers, results flow back through the bus; messages between agents are always routed through the bus, never directly. (2) The worker abstraction is a thin wrapper; the kernel touches only the agent's message-handling surface. (3) Every cross-cut (tracing, cost, cancellation, budget) is owned by the coordinator and exposed by interface-bound calls elsewhere; no layer reaches across another.

These three properties are not decoration — each closes a known failure class. Property (1) is why the trace is complete: with all traffic through the bus, no agent dialogue can happen off-record (it forecloses the "hallucinated manager who reports to nobody" failure of §2). Property (2) is why the kernel can evolve independently of the model provider: nothing above the Worker line knows whether an agent calls one model or ten (it forecloses provider-coupling debt, the most common refactoring cost in pattern libraries). Property (3) is why budget, cost, and cancellation are enforceable at all: a cross-cut owned in one place can be guaranteed; a cross-cut scattered across layers can only be hoped for (it forecloses the "$200 stuck loop" failure of §2). Read top to bottom, the diagram is also the dependency order — each layer depends only on the layers below it, and the coordinator is the single layer that sees all of them.

8. Domain Model / Protocol / Data Model

The kernel's domain is a conversation among roles, mediated by the bus and the blackboard, allocated by the contract net. The unit of work is a task; the unit of communication is an envelope; the unit of shared state is a blackboard key.

8.1 The Envelope

Every message on the bus is wrapped in an Envelope (frozen). It carries identity (msg_id), the run/thread it belongs to (run_id, thread_id), reply linkage (parent_msg_id), provenance (sender_role, sender_worker), addressing (recipient_role, recipient_worker — None means broadcast/any), timing (sent_at, deadline), and a discriminated payload (payload_kind + payload validated against the kind's schema). Full signatures in §11.

8.2 Contract-Net Worked Example

A coordinator needs a 200-line patch reviewed. It announces to the reviewer role:

TaskAnnounce(task_id=T1, description="review patch P", eligible_roles=["reviewer"],
             deadline_for_bids=t0+2s, award_strategy="highest-confidence")

Three reviewers bid: Bid(T1, r1, cost=0.04, wall=8s, confidence=0.7), Bid(T1, r2, cost=0.05, wall=6s, confidence=0.9), Bid(T1, r3, …). At t0+2s the coordinator picks r2 (highest confidence) and awards Award(T1, awarded_to=r2, deadline=t0+62s, budget_usd=0.075). r2 returns Result(T1, r2, outcome="success", output={…}, cost_usd=0.048, wall=5.9s). The coordinator records the outcome, updates the ledger, and unblocks the downstream synthesiser node.

8.3 Contract-Net State Table

State Event Next state Action
ANNOUNCED bid received ANNOUNCED append bid
ANNOUNCED bid deadline elapsed, ≥1 bid AWARDED pick winner, send Award
ANNOUNCED bid deadline elapsed, 0 bids FAILED raise NoBidders; re-announce per retry policy
AWARDED Result(success) DONE record outcome, unblock downstream
AWARDED Result(failure/timeout/budget) FAILED re-announce (≤3); then escalate
AWARDED work deadline elapsed FAILED Cancel winner, re-announce
FAILED retry count > 3 ESCALATED promote to manager-choice, longer deadline
any run budget exhausted CANCELLED Cancel, clean shutdown

8.4 Malformed Input

  • Untyped/invalid payload: rejected at the bus send path (I1); mac_bus_invalid_total++; the send raises before the message reaches the wire.
  • Role hallucination: a reply whose sender fields do not match registration is dead-lettered (I2); the worker is flagged for arbitration.
  • Unknown payload_kind: the discriminator misses PAYLOAD_KINDS; the envelope is rejected as malformed.
  • Stale CAS version: a Write with a mismatched expected_version is rejected with a conflict; the loser retries (I6).
  • Bid after deadline: silently dropped (the worker is treated as having chosen not to bid); the timeout disambiguates crash from abstention.

8.5 Failure Path

When a winner crashes mid-task: heartbeats stop; after the work deadline the coordinator marks the task FAILED, emits Cancel (idempotent), and re-announces. If the crashed worker later returns a Result with the original msg_id, the duplicate is detected (I8) and dead-lettered. No double-completion occurs because only a Result of-record completes a task (P11/I8).

8.6 Envelope Field Layout

Field Type Required Role
msg_id UUID yes identity; dedup key for exactly-once and partition recovery
run_id UUID yes the coordinator-run this belongs to
thread_id UUID yes the dialogue sub-conversation; the FIFO-ordering key (I7)
parent_msg_id UUID? no reply linkage; builds the trace tree
sender_role / sender_worker RoleId / WorkerId yes provenance; enforced against registration (I2)
recipient_role / recipient_worker RoleId? / WorkerId? no addressing; None = broadcast / any
sent_at / deadline datetime / datetime? yes / no timing; the recipient gives up at deadline
payload_kind str yes discriminator into PAYLOAD_KINDS
payload dict yes validated against the kind's schema

8.7 Dialogue Threading & Message Flow

A thread (thread_id) is a sub-conversation; the bus guarantees per-thread FIFO order (I7) and nothing across threads (ADR-21). A debate round is one thread; a code-review of one patch is one thread. Threads let two patterns run concurrently on the same coordinator without their messages interleaving incorrectly.

A single contract-net cycle threads through the system as:

coord ──TaskAnnounce(role)──▶ bus ──broadcast──▶ {workers in role}
{workers} ──Bid──▶ bus ──▶ coord   (collected until deadline_for_bids)
coord ──Award(winner)──▶ bus ──send_to──▶ winner
winner ──Result──▶ bus ──▶ coord ──▶ unblock downstream DAG node

Each arrow is one envelope and one span; parent_msg_id links the Bid to the TaskAnnounce, the Award to the winning Bid, and the Result to the Award, so the trace tree reconstructs the full cycle without re-running it (P9, MM8). The coordinator is on the receive side of every arrow that returns to it, which is what makes all inter-agent traffic observable (P2).
