⬜ Phase 1 — Worker Abstraction §13

Objectives

Define the Worker boundary: a thin wrapper around an Agentic-Framework Agent that adds typed Pydantic I/O, a per-message OpenTelemetry span, role registration, permission scoping, and an idempotent handle(envelope) -> AsyncIterator[Envelope]. Scope: the seam itself, not agent internals (P1 — the kernel never reaches past this line).

Deliverable

src/mac/worker/{base,llm,tool}.py plus the handshake and role-hallucination fixtures — a running two-worker handshake an operator can invoke via examples/worker_handshake.py.

Acceptance

The two-worker handshake test passes; the worker.handshake conformance bucket is Pass; role hallucination is caught and dead-lettered on 100% of corpora/worker/role-hallucination.jsonl cases; a span is emitted for every handle call (zero missing spans in the fixture run).

Fixtures
Fixture Purpose Expected
two workers, one role dispatch a Speak; both reply replies carry correct sender_*
corpora/worker/role-hallucination.jsonl LLM addressed an unregistered role RoleHallucination raised; message dead-lettered
cpu-bound worker blocks then cancelled cancellation propagates within cleanup window
Pitfalls
  • Letting the worker mutate the input envelope; envelopes are frozen — construct new ones for replies.
  • Treating handle as a coroutine; it is an async generator — yield is the contract.
  • Forgetting to flush the span; use the start_as_current_span context manager, not the manual API.

⬜ Phase 2 — Typed Message Bus §14

Objectives

Build the only inter-agent channel: typed Pydantic envelopes, bounded queues with backpressure, three delivery modes, dead-letter handling, schema validation on send, and per-thread FIFO ordering. Constraint: no hidden buffer ever absorbs a burst (I1, ADR-21).

Deliverable

src/mac/bus/{inproc,pubsub,deadletter,delivery}.py plus the delivery fixtures — a runnable 10k-envelope fan-out benchmark under benchmarks/.

Acceptance

Fair-fan-out (each consumer within 5% share) and delivery-ordering tests pass; the bus.delivery conformance bucket is Pass; throughput ≥ 50,000 envelopes/s on the reference 64-core host (M7, §4).

Fixtures
Fixture Purpose Expected
10k envelopes, one role fair fan-out under round-robin each consumer within 5% share
corpora/bus/delivery.jsonl recorded sequences per mode deliveries match recorded ordering
invalid payload schema rejection send raises; mac_bus_invalid_total++
dead-letter path 4th delivery attempt message dead-lettered with reason
Pitfalls
  • Letting the bus drop messages silently; every drop is mac_bus_dropped_total + a log line.
  • Using asyncio.Queue directly; mixing with AnyIO streams leaks FDs and reorders.
  • Trusting cross-process delivery to be exactly-once by default; it is at-least-once, dedup is opt-in.

⬜ Phase 3 — Contract-Net Protocol §15

Objectives

Implement Smith's announce/bid/award/result allocation with four award strategies, bid/work deadlines, and re-announcement on failure. Constraint: the allocator never blocks the bus (P2) and never double-completes a task (I8).

Deliverable

src/mac/contract_net/{announcer,bidder,awarder,protocol}.py plus the auction fixture — a runnable 5-bidder auction script under examples/.

Acceptance

Strategy tests pass for all four award strategies; the contract_net.protocol conformance bucket is Pass; deterministic strategies (lowest-cost, first-acceptable) match the recorded winner exactly (0 mismatches over 100 cassette cases); manager-choice lands within the recorded acceptable set ≥ 80% of runs (§24.2).

Fixtures
Fixture Purpose Expected
5-bidder, lowest-cost strategy correctness cheapest bidder wins
5-bidder, manager-choice LLM-judge ranking manager's pick wins (cassette)
corpora/contract_net/auction.jsonl recorded auctions per strategy live picks match recorded
zero-bid announce failure path NoBidders; re-announce
Pitfalls
  • Awarding before the bid deadline; the race lets a fast bidder win cheaply over better late bids.
  • Letting a losing bidder retain pre-allocated resources; the loser must release on award failure.
  • Treating silence as rejection without a timeout; the timeout disambiguates crash from abstention.

⬜ Phase 4 — Coordinator (Orchestrator) §16

Objectives

Build the single orchestrator: run lifecycle, budget watchdog, deadline watchdog, stuck-loop detector + arbitration loop, structured cancellation, state persistence, and an output event stream. Constraint: every cross-cut (budget, cancellation, tracing) is owned here and nowhere else (§3 property 3).

Deliverable

src/mac/coordinator/{coordinator,budget,deadline,arbitration}.py and src/mac/policy/{rules,llm_judge,human}.py — a runnable 5-agent debate under budget enforcement, inspectable via the Event stream.

Acceptance

Budget and stuck-loop tests pass; the coordinator.lifecycle conformance bucket is Pass; budget detection latency ≤ 1 s (§4); no leaked children after cancellation (0 orphaned tasks across the fixture suite).

Fixtures
Fixture Purpose Expected
5-agent debate, $0.50 cap budget watchdog fires before cap exceeded
corpora/coordinator/budget.jsonl recorded exhaustion points live cancel at same point (±1 s)
echo loop stuck-loop detection detected within window; arbitration consulted

Pitfalls
  • Mixing asyncio.Task and AnyIO TaskGroup; pick one (AnyIO) — mixing leaks children on cancel.

Deliverable

Loop and resume tests pass; the dag.execution conformance bucket is Pass; 1000-node DAG dispatch latency p99 ≤ 100 ms (M8, §4); crash-resume meets RPO ≤ 1 transition and RTO ≤ 30 s.

Fixtures

⬜ Phase 6 — Shared Blackboard §18

Deliverable

Acceptance

The CAS-race test passes; the blackboard.cas conformance bucket is Pass; write latency (in-mem, single-key contended) p99 ≤ 400 µs (§4); races resolve deterministically across 100 repeated runs (0 lost updates).

Fixtures
Fixture Purpose Expected

The trace-coverage test passes; the trace.coverage conformance bucket is Pass; every agent and message is visible in the 5-agent debate trace (100% node coverage vs recorded shape); every LLM call has a matching cost-ledger row (0 gaps).

Fixtures
Fixture Purpose Expected

Ship five patterns as typed Pattern dataclasses: Debate, CodeReviewCommittee, ResearchTeam, CustomerSupportTriage, SoftwareEngineeringTeam. Constraint: a pattern missing a required role fails at construction, never at first dispatch (I10).

Deliverable

src/mac/patterns/{debate,code_review,research_team,customer_support,software_team}.py plus examples/ and pattern corpora — five runnable end-to-end demos.

Acceptance

Each pattern runs end to end; pattern.debate, pattern.code_review, pattern.research_team, pattern.support_triage are Pass (≥80% majority-of-3-judge agreement, §24.2); pattern.software_team meets the ≥70% test-pass criterion over its cassette suite.

Fixtures
Fixture Purpose Expected

corpora/patterns/<name>/inputs.jsonl recorded I/O (3-judge majority) per-bucket pass criterion met
missing-role pattern I10 raises at construction
Pitfalls
  • Hard-coding role names; role names are Pattern parameters.
  • Letting a loop run forever; every loop has max_iterations and terminate_when.
  • Treating the LLM judge as ground truth; conformance measures against a recorded reference, not the judge.

Anti-patterns explicitly excluded (will not ship even at Sealed): Byzantine consensus over agent votes (the kernel ships Vote + majority-vote only); multi-agent reinforcement learning (belongs in the Agentic-Framework); federated learning across fleets (separate blueprint); auto-discovery over the network (a security and operational hazard — workers register explicitly).

⬜ Phase 10 — REST + WebSocket Boundary §22

Objectives

Expose the kernel over HTTP/WebSocket: REST routes, a per-run event stream, API-key auth with per-pattern ACLs, rate limiting, run isolation, and idempotent run creation. Constraint: the REST response never carries the full transcript (large output is fetched lazily).

Deliverable

src/mac/server/{api,ws,auth}.py, docs/api/{openapi.yaml,ws-protocol.md}, and the server corpus — a runnable httpx+websockets notebook that starts and streams a Debate.

Acceptance

The notebook example works; server.rest and server.ws conformance buckets are Pass; every OpenAPI example validates against a live response (0 schema mismatches); idempotent creation returns the identical run_id on 100% of replayed Idempotency-Key requests.

Fixtures
Fixture Purpose Expected
examples/ notebook (httpx + websockets) start Debate, stream events events stream end to end
corpora/server/openapi-examples.jsonl every OpenAPI example live responses validate
idempotency-key replay dedup same run id returned
Pitfalls
  • Forgetting the WebSocket heartbeat; idle sockets get killed by intermediaries — ping every 30 s.
  • Returning the full transcript in the REST response; it can be large — clients opt into the WS.
  • Running FastAPI in the coordinator's event loop; they run in separate threads with a bounded handoff queue.

⬜ Phase 11 — Distributed Workers (Deferred surface, contract frozen) §23

Objectives

Specify (not implement at Phase 0) a worker pool across machines: location-transparent registration, failure detection, partition handling, and sticky sessions. The full surface is deferred — see the Deferred Features Register. Constraint: the frozen contract must make scale-out additive later, never a rewrite (§32).

Deliverable

The frozen contract in this section plus the deferred-bucket wiring in the conformance runner — no runnable distributed pool at Phase 0, by design.

Acceptance

At Phase 0: distributed.partition is Deferred with blueprint_ref populated (0 unbucketed deferrals); the envelope/bus contract is unchanged (0 breaking diffs vs §11/§14); when un-deferred, the scale target is ≥95% completion under single-machine failure across a 100-worker/4-machine batch.

Fixtures
Fixture Purpose Expected
corpora/distributed/partition (deferred) partition recovery bucket emits Deferred with blueprint_ref
100-worker / 4-machine batch (deferred) scale target ≥95% completion under single-machine failure
Pitfalls
  • Trusting heartbeats over result-of-record; an acked-but-undelivered task must be re-issued (P11/I8).
  • Letting sticky sessions starve the queue; a crashed sticky worker orphans the thread — recover with a new sticky assignment.
  • Introducing a distributed-only type into Envelope/Bus "just in case"; the frozen contract (§23.2) is what keeps scale-out additive — any Phase-0 leakage of distributed concerns is itself a defect.
