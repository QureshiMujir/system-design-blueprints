ADR-01

Implementation language

Chosen

Rust 1.78+ MSRV

Rejected

C, C++, Go

When the rejected choice is right

C wins contributing directly to upstream Linux netfilter, which requires C ABI

Why: memory safety in security-critical parsing (§1)

ADR-02

Hook model

Chosen

Five-hook, netfilter-compatible

Rejected

Single direction-tagged hook

When the rejected choice is right

single-hook wins in a from-scratch sidecar proxy with no operator legacy expectations

Why: operator familiarity, unambiguous NAT placement (P1)

ADR-03

Packet-path structure

Chosen

Node-graph pipeline (Click/VPP-style)

Rejected

Hardcoded stage sequence

When the rejected choice is right

hardcoded sequence wins for a fixed-function, flash-constrained embedded firewall

Why: runtime rewiring without recompilation

ADR-04

Rule authoring

Chosen

Typed DSL (nftables-inspired) + compiled bytecode

Rejected

Raw bytecode authoring

When the rejected choice is right

raw bytecode wins for a machine-generated ruleset pipeline no human ever reads

Why: parse-time error catching (§8.5)

ADR-05

Conntrack key

Chosen

5-tuple + zone

Rejected

3-tuple (IP+proto only)

When the rejected choice is right

3-tuple wins tracking non-port-bearing protocols (ESP/GRE) keyed by SPI/Call-ID instead

Why: distinguishes concurrent flows on different ports

ADR-06

TCP tracking

Chosen

Full RFC 793 state names + RFC 5382 NAT extensions

Rejected

Binary "established or not" tracking

When the rejected choice is right

binary state wins for a pure bump-in-the-wire DDoS scrubber needing only "seen SYN"

Why: mid-stream RST/FIN correctness (§8.3)

ADR-07

UDP timeout

Chosen

30 s unreplied / 180 s established

Rejected

Single flat UDP timeout

When the rejected choice is right

flat timeout wins in a controlled mesh where all UDP is known-conversational

Why: distinguishes conversational vs single-datagram flows (RFC 4787 REQ-5)

ADR-08

Default hook substrate

Chosen

Linux netfilter/netlink integration

Rejected

Raw AF_PACKET/DPDK-only from day one

When the rejected choice is right

DPDK-only wins for a bare-metal appliance bypassing the kernel stack entirely by design

Why: fastest path to correctness using existing kernel routing/ARP

ADR-09

Fastpath timing

Chosen

eBPF/XDP as Phase 12 stretch, not baseline

Rejected

XDP-first design

When the rejected choice is right

XDP-first wins when the only requirement is L3/L4 DDoS scrubbing, no L7 ever

Why: verifier restricts stateful ALG/DPI logic the correctness kernel needs first

ADR-10

IPv6 transition

Chosen

First-class, Phase 11

Rejected

When the rejected choice is right

omission wins for a data-center east-west firewall that is IPv4-only by policy indefinitely

ADR-11

Conformance oracle

Chosen

Differential testing against nftables

Rejected

Hand-written oracle only

When the rejected choice is right

hand-written oracle wins when target semantics deliberately diverge from nftables

ADR-12

Conntrack hash function

Chosen

SipHash, daily-rotated key

Rejected

Jenkins/FNV (unkeyed)

When the rejected choice is right

unkeyed hash wins in a trusted, non-adversarial lab testbed where 2 ns vs 5 ns matters more

Why: chosen-key collision DoS resistance (Aumasson & Bernstein 2012)

ADR-13

Conntrack concurrency

Chosen

Per-bucket spinlock + atomic CAS transitions

Rejected

Single global lock; full RCU

When the rejected choice is right

full RCU wins above ~50M entries on 32+-core NUMA boxes

Why: global lock serializes all cores (measured pre-2.6.35 bottleneck); RCU adds grace-period complexity below ~10M entries

ADR-14

Port allocation

Rejected

Sequential-only

When the rejected choice is right

sequential wins in a lab NAT valuing deterministic, human-readable port assignment

Why: sequential is trivially predictable, off-path attack surface

ADR-16

When the rejected choice is right

ADR-17

DPI activation

Chosen

When the rejected choice is right

ADR-18

SYN-flood defense

Chosen

Rejected

When the rejected choice is right

ADR-19

Chosen

Lazy (insert-time bucket walk) default

Rejected

When the rejected choice is right

ADR-20

When the rejected choice is right

ADR-22

Concurrency model

Chosen

Synchronous per-core hot path; tokio only in control plane

ADR-23

Correctness strategy

Chosen

When the rejected choice is right

ADR-28

Backpressure

Chosen

Bounded MPSC channel, drop-and-count on full, between fastpath and userspace consumer

Rejected

Unbounded channel / blocking producer

When the rejected choice is right

blocking producer wins in an offline packet-capture tool where losing a record is worse than stalling

Why: unbounded channel is an OOM vector; a blocking producer stalls the packet path

38. Alternative Architectures (Roads Not Taken)

Alternative 1 — Full kernel-bypass, DPDK/VPP-first.

NIC ──DMA──▶ [ DPDK PMD ] ──▶ [ VPP-style node graph: classify─NAT─policy ] ──▶ NIC
              (no kernel network stack touched at all)

Regime where it wins: dedicated appliances targeting sustained 100 Gbps+ with no need for kernel routing/ARP integration. Real system: VPP/DPDK-based vRouters and appliances. Rejected here because Phase 0–11 need incremental adoption on existing Linux estates (§1 deployment model) and kernel-integration for routing/ARP (§1 boundaries) — XDP is added as a stretch (§24) precisely to get some of this benefit without discarding the kernel integration baseline.

Alternative 2 — eBPF/XDP-only, no default path.

NIC ──▶ [ XDP program: classify + conntrack (eBPF maps) + NAT ] ──▶ NIC
         (netfilter/default path removed entirely)

Regime where it wins: cloud-native L4 NAT/load-balancing at very high PPS with limited L7 richness required (Kubernetes service dataplanes). Real system: Cilium, Katran. Rejected here because DPI (§22) and full ALG payload rewriting (§20) exceed current eBPF-verifier expressiveness — I13's fastpath/default-path parity requirement exists precisely because this alternative cannot yet cover the full rule surface.

Alternative 3 — Centralized SDN control plane, dumb dataplane.

[ Central controller: computes per-flow decision ]
        │ pushes decision, per new flow
        ▼
[ Dataplane switch: applies pushed decision, no local policy engine ]

Regime where it wins: large multi-tenant data centers where centralized visibility and consistent policy across thousands of hosts outweighs per-box autonomy and latency. Real system: OpenFlow/ONOS-style SDN firewalls, cloud VPC Security-Group control planes. Rejected here because a per-new-flow controller round-trip breaks this design's p99 added-latency budget (§4) for a single inline box — this system's policy evaluation must stay local (P3, P4).

Alternative 4 — Formally-verified separation-kernel firewall.

[ seL4-style microkernel ]
   ├─ isolated component: packet classifier (proven)
   ├─ isolated component: NAT engine (proven)
   └─ isolated component: conntrack (proven)
   (inter-component channels formally verified, not just tested)

Regime where it wins: certification-driven government/defense deployments where a mathematical isolation proof outweighs development velocity. Real system: seL4-based and Muen separation-kernel firewalls. Rejected here because a full formal model of the whole system (ADR-23's rejected alternative) is disproportionate to the 47-week, 14- phase timeline (§1) and this project's iteration-speed goal — differential/property/ fuzz testing (§30) is the chosen tradeoff instead.
