Hard questions (§37)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why can a load-balancer-injected RST with an out-of-window sequence number still be a legitimate termination rather than an attack? (§8.3, §15)
  2. Trace exactly which invariant would first detect a hook implementation that both forwards and locally delivers the same packet. (§7 I2, §13)
  3. Why does DNAT executing at POSTROUTING instead of PREROUTING break the architecture, not just violate a style rule? (§3, §9 ADR-02/ADR-03, §7 I3)
  4. Derive the memory cost of raising the conntrack ceiling from 10M to 50M entries, and name the next bottleneck that surfaces first. (§36 item 1, §33)
  5. Why is a keyed hash (SipHash) necessary for the conntrack table but not strictly necessary for the classifier's IPset? (§9 ADR-12, §6 P12, §14)
  6. Why does the SYN-proxy's cost model (§36 item 6) only work if cookie verification is cheaper than conntrack insertion — what breaks if that inequality reverses? (§21, §7 I11)
  7. Why is an ALG restricted to creating an Expectation rather than a general firewall rule, and how does that shape prevent CVE-2002-0985's exact failure? (§6 P7, §20)
  8. Why does full-cone NAT being the default (not restricted) simultaneously help P2P and enlarge the attack surface — and where is that tradeoff made explicit? (§8.4, §9 ADR-15)
  9. Why must a ruleset reload be atomic at the generation level rather than at the individual-rule level? (§7 I10, §19)
  10. What specifically would go wrong if XDP were the only dataplane, with no default- path fallback? (§9 ADR-09, §24, §38 Alternative 2)
  11. Why does NAT64 reuse the §17 NAT engine instead of implementing its own port allocator? (§17, §23)
  12. Why is DPI's SNI extraction fundamentally limited even before considering performance — what class of policy can it never enforce regardless of engineering effort? (§22, §26 T14)
  13. Construct the argument for why per-bucket spinlocks are correct at 10M entries but wrong at 50M+ entries on a 32-core NUMA box. (§9 ADR-13, §33)
  14. Why does scrub-first fragment reassembly close an evasion class that per-fragment matching cannot, even in principle? (§9 ADR-20, §18)
  15. Trace how a MAP-T port-derivation misconfiguration produces the same failure shape as a Phase-5 PBA misconfiguration, despite being computed statelessly. (§17, §23)
  16. Why does this design delegate routing-table computation to the OS instead of implementing it, and what would have to change architecturally to bring it in- house? (§1 system boundaries, §35 vs. VPP)
  17. Why is "the fastpath and default path must agree" (I13) a correctness invariant and not merely a performance nice-to-have? (§7 I13, §24, MM7)
  18. Given the §36 capacity model, at what throughput does the default path's headroom (item 5) disappear, and which lever (§33) is pulled next? (§36, §33)

34. Mental Models & First Principles

  • MM1. "The conntrack table is the constitution; every hook is a branch of government that must consult it before acting." Predicts: any hook that maintains parallel state will eventually disagree with another hook. Bug class without it: split-brain flow state. Applies in §7 (I1, I2) and §3.
  • MM2. "A Verdict is a monad with one absorbing element per terminal state." Predicts: Continue is the only non-terminal value; everything else short-circuits the remaining hooks. Bug class without it: a rule author assumes an implicit Accept on fallthrough. Applies in §8.2 and §13.
  • MM3. "NAT is a pure function of (tuple, pool-state) at the moment of first packet; every subsequent packet just replays the recorded mapping." Predicts: the interesting bugs are all in first-packet allocation, not steady-state rewriting. Bug class without it: debugging effort misdirected at the rewrite path instead of the allocator. Applies in §8.6 and §17.
  • MM4. "A state machine's safety property is exactly its transition table's completeness — an unlisted edge is a security bug, not a missing feature." Predicts: any input triggering an unlisted transition is either a bug or an attack. Bug class without it: silently permissive fallback on unrecognized packet sequences. Applies in §7 (I4) and §15.
  • MM5. "An ALG's privilege boundary is the shape of the data structure it can create, not a runtime check." Predicts: bounding an ALG to Expectation-creation only (not general rule injection) closes an entire vulnerability class by construction. Bug class without it: CVE-2002-0985-style arbitrary firewall-rule injection. Applies in §6 (P7) and §20.
  • MM6. "A cookie is a stateless credential; verifying it must cost less than storing the state it stands in for." Predicts: SYN-proxy viability depends on cookie-verify cost staying far below conntrack-insert cost. Bug class without it: a "DDoS mitigation" that itself becomes the resource-exhaustion target. Applies in §21 and §36 (item 6).
  • MM7. "Every fastpath is a claim of equivalence, and an unverified claim of equivalence is a policy bug waiting to happen." Predicts: any dataplane acceleration (XDP, hardware offload) needs a differential test against the reference path, not just a throughput benchmark. Bug class without it: silent policy divergence between fast and slow paths. Applies in §7 (I13) and §24.
  • MM8. "Capacity planning is arithmetic on §4's numbers, not a separate art." Predicts: every operational ceiling (memory, PPS, subscriber count) is derivable from the System Constraints table without new assumptions. Bug class without it: under-provisioning discovered in production instead of in the capacity model. Applies in §4 and §36.

5. Required Reading

Books

  • Cheswick, W., Bellovin, S., Rubin, A. — Firewalls and Internet Security: Repelling the Wily Hacker, 2nd ed. (Addison-Wesley, 2003). Ch. 3 (Packet Filtering), Ch. 9 (Classes of Attacks) — extract the packet-filtering vs. proxy distinction and the attack taxonomy. Applied in §8.5 (rule/match engine) and §26 (Threat Model).
  • Stevens, W.R. — TCP/IP Illustrated, Volume 1 (Addison-Wesley, 1994). Ch. 18 (TCP Connection Establishment and Termination), Ch. 24 (TCP Timeout and Retransmission) — extract the state diagram and RTO/timeout mechanics. Applied in §8.3 and §15 (Phase 3).
  • Rosen, R. — Linux Kernel Networking: Implementation and Theory (Apress, 2014). Ch. 9 (Netfilter), Ch. 11 (Connection Tracking) — extract the hook-priority model and the extension-infrastructure pattern. Applied in §8.2, §17 (Phase 5), ADR-08.
  • Hansteen, P.N.M. — The Book of PF, 3rd ed. (No Starch Press, 2014). Ch. 4 (Scrub), Ch. 6 (NAT) — extract the scrub-before-match normalization argument. Applied in §18 (Phase 6), ADR-20.
  • Benvenuti, C. — Understanding Linux Network Internals (O'Reilly, 2006). Ch. 24 (Netfilter hooks), the sk_buff chapter — extract hook dispatch and packet-buffer lifecycle. Applied in §3 (Architectural Overview) and §13 (Phase 1).
  • Gregg, B. — Systems Performance: Enterprise and the Cloud, 2nd ed. (Addison-Wesley, 2020). Ch. 6 (CPU), Ch. 10 (Network) — extract the profiling/benchmarking methodology. Applied in §32 (Performance Engineering) and every phase's N.7.

  • Schuba, C., Krsul, I., Kuhn, M., Spafford, E., Sundaram, A., Zamboni, D. — "Analysis of a Denial of Service Attack on TCP." IEEE S&P 1997. SYN-flood mechanics and cookie defenses. Applied in §21 (Phase 9), ADR-18, I11.
  • Handley, M., Paxson, V., Kreibich, C. — "Network Intrusion Detection: Evasion, Traffic Normalization, and End-to-End Protocol Semantics." USENIX Security 2001. Scrub-before-match normalization against fragmentation evasion. Applied in §18 (Phase 6), ADR-20.
  • Ford, B., Srisuresh, P., Kegel, D. — "Peer-to-Peer Communication Across Network Address Translators." USENIX ATC 2005. Endpoint-independent mapping/STUN hole- punching. Applied in §8.4, §17 (Phase 5), ADR-15.
  • Dobrescu, M., Egi, N., Argyraki, K., et al. — "RouteBricks: Exploiting Parallelism to Scale Software Routers." SOSP 2009. Parallel software-dataplane scaling. Applied in §24 (Phase 12), §33 (Scalability Analysis).
  • Kohler, E., Morris, R., Chen, B., Jannotti, J., Kaashoek, M.F. — "The Click Modular Router." ACM TOCS 2000. Node-graph packet-processing pipelines. Applied in §3 (Architectural Overview), ADR-03.

Reference Implementations

  • Linux netfilter / nf_conntrack (net/netfilter/ in the Linux kernel tree) — study nf_conntrack_core.c, nf_nat_core.c: hook priorities, extension infrastructure. Pitfall to avoid: the pre-2.6.35 single global conntrack lock — do not reintroduce a global lock (ADR-13). Applied in §15, §17.
  • OpenBSD pf (sys/net/pf.c, pfvar.h) — scrub-then-match, the state tree keyed on src/dst. Pitfall to avoid: pf's historically weak FTP-ALG sandboxing (CVE history, §26 T4). Applied in §18, §20.
  • nftables / libnftnl (github.com/nftables) — the bytecode VM (src/rule.c, expression modules), atomic ruleset commit via netlink batching. Pitfall to avoid: fully generic opcode dispatch with no JIT — the perf cost shows up directly in rule- eval latency. Applied in §19 (Phase 7), ADR-04, ADR-11.
  • VPP (fd.io, src/vnet/) — the node-graph pipeline with vectorized (batched) dispatch. Pitfall to avoid: per-packet node-function-pointer dispatch without batching — the dominant VPP perf lesson. Applied in §3, §24.
  • Cilium (github.com/cilium/cilium, pkg/datapath, bpf/) — eBPF conntrack + NAT map layout for Kubernetes. Pitfall to avoid: Cilium's early single-LRU-map eviction- under-pressure behavior (silent early eviction masked as capacity, not admission control). Applied in §24, §35 (Comparative Architecture Table).
  • Katran (github.com/facebookincubator/katran) — XDP L4 load-balancer conntrack structure. Pitfall to avoid: fixed consistent-hash sizing assumed at compile time — our conntrack ceiling (§4) must stay a runtime parameter. Applied in §24.

Glossary (§40) · 46 terms · site-wide glossary

5-tuple
: (src_ip, dst_ip, src_port, dst_port, proto), the flow-identity key.
ALG
: Application-Layer Gateway; rewrites embedded addresses in application payloads.
BPF/eBPF
: (extended) Berkeley Packet Filter; in-kernel verified bytecode execution.
CGN
: Carrier-Grade NAT; many subscribers share one public IPv4 address.
Conntrack
: the connection-tracking subsystem; the single source of truth for flow state (P2).
CT zone
: an isolation context for overlapping address spaces (I9).
DDoS
: Distributed Denial of Service.
DNAT
: Destination NAT; rewrites destination address/port, applied at PREROUTING.
DPI
: Deep Packet Inspection; opt-in application-protocol identification (§22).
DS-Lite
: Dual-Stack Lite; IPv4-in-IPv6 tunneling to an AFTR (RFC 6333).
Endpoint-independent mapping
: same NAT mapping regardless of destination (RFC 4787).
Endpoint-dependent mapping
: a distinct NAT mapping per destination (symmetric NAT).
Expectation
: a bounded, single-fire pending conntrack entry created by an ALG (I7).
Five-hook model
: PREROUTING/INPUT/FORWARD/OUTPUT/POSTROUTING (P1).
Full-cone NAT
: endpoint-independent mapping + endpoint-independent filtering.
Hairpinning
: internal → own public IP → internal traffic flow (§18).
Helper
: the trait behind every ALG/DPI/transition extension (P14, §11).
IPset
: a hash-accelerated set of addresses/ranges for O(1) match (§14).
MAP-E
: Mapping of Address and Port with Encapsulation (RFC 7597).
MAP-T
: Mapping of Address and Port with Translation (RFC 7599).
Masquerade
: SNAT to the current egress-interface address, re-resolved on change.
MSS clamping
: rewriting the TCP MSS option to fit through a tunnel.
NAT
: Network Address Translation.
NAT-T
: NAT Traversal for IPsec (RFC 3948; ESP wrapped in UDP 4500).
NAT64
: stateful IPv6-to-IPv4 translation (RFC 6146).
netfilter
: the Linux kernel hook framework this design's default path integrates with.
nftables
: the modern netfilter userspace/bytecode-VM tooling; the conformance oracle (ADR-11).
PAT
: Port Address Translation, a synonym overlapping with NAPT/NAT.
PBA
: Port Block Allocation; contiguous per-subscriber port ranges for CGN (§17).
Path MTU (PMTU)
: the smallest MTU along a path; discovered via ICMP (RFC 8201).
pf
: the OpenBSD packet filter; source of the scrub-first design lesson (ADR-20).
Port-restricted NAT
: filtering that additionally requires matching the prior destination port.
RFC 4787 / 5382 / 5508
: NAT behavioral-requirements RFCs for UDP/TCP/ICMP respectively.
RST
: TCP reset segment; terminates a connection regardless of sequence state (I4).
SACK
: TCP Selective Acknowledgment option.
SipHash
: the keyed pseudorandom function used for the conntrack hash and SYN cookies (P12).
Slot
: the internal hash-bucket linked-list node owning one ConntrackEntry (§11).
SNAT
: Source NAT; rewrites source address/port, applied at POSTROUTING.
STUN
: Session Traversal Utilities for NAT (RFC 5389); NAT-mapping discovery.
SYN cookie / SYN proxy
: cryptographic-cookie-based SYN-flood defense (I11, §21).
Symmetric NAT
: address+port-dependent mapping and filtering (ADR-15 opt-in).
TCP Fast Open
: an extension allowing data in the initial SYN.
TLS SNI
: the Server Name Indication field in a TLS ClientHello, extractable by DPI.
Verdict
: the terminal (or Continue) value returned by a hook pass (§8.2).
XDP
: eXpress Data Path; the pre-sk_buff kernel fastpath hook (§24).
Zone
: see CT zone.
