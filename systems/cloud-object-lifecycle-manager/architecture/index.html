Per-box detail.

olmctl (CLI, P10). Thin client over olm-api. Subcommands: policy put|get|lint|diff|rm, dryrun, scan status, queue stat, audit tail|grep, drain, pause|resume, kill-switch. Validates policy locally (links olm-policy) before sending so malformed input never reaches the server. No state of its own; exit codes are machine-parseable. Trust boundary: authenticated caller; mutating commands require an operator role token.

olm-api (Control API, P10). The only mutation entry point for policies + operator controls. Stateless request handlers; all durable state lives in olm-meta/olm-audit. Validates every policy through olm-policy (reject malformed/over-large/conflicting before persist). Exposes dry-run preview (runs olm-eval over a sampled or full namespace without enqueuing). Read endpoints surface scan/queue/audit status. Hosts the kill-switch and drain/pause controls. Trust boundary: external operators; rate-limited; never executes actions itself.

Policy Store (in olm-meta, P2). bucketId → versioned LifecyclePolicy document. Each write creates a new immutable policy version with a monotonically increasing policy_epoch; evaluation always reads the epoch active at scan start and pins it for the whole run (determinism). Concurrency: single-writer via the API; readers (scanner) snapshot. Persistence: same store as object metadata or a dedicated namespace.

Status/Metrics view (P11). Read-only projection: per-bucket last-scan timestamp + checkpoint, objects scanned, decisions emitted, work queued/in-flight/done/dead, bytes transitioned, expirations executed. Backed by metrics counters + the audit log; no write path.

Clock Source (P3). Provides the eval-clock: a single UTC instant frozen at scan-run start, used for every age/date comparison in that run. Backed by CLOCK_REALTIME for the absolute instant, guarded by CLOCK_MONOTONIC to detect wall-clock jumps mid-run (abort + alert on backward jump). Why frozen: two objects evaluated 6 hours apart in the same daily run must see the same "today" so the run is deterministic and reproducible.

Scan Supervisor (P4). Triggers per-bucket scans on the daily cadence (cron model from #204) and on operator demand. Splits each bucket into prefix-shards, spawns a resumable scan task per shard, enforces leader-per-shard via the olm-audit lease, throttles concurrent scans to the configured fan-out. Owns the scan-completion SLO.

Namespace Scanner (P4). Streams ObjectMeta (including the full version chain for versioned buckets) from olm-meta via enumerate(prefix, after_key, limit), partitioned by prefix for parallelism, checkpointing (prefix-shard, last_key, policy_epoch, eval_clock) after each batch so a crash resumes mid-bucket without rescanning completed ranges (monotonic checkpoints). Applies backpressure from the downstream queue.

olm-meta MetaStore (P2). Abstracts object metadata + version chains + the policy store behind one trait. In-memory impl for tests/Phase-0; persistent impl (LSM-style, #68) for scale — sorted by (bucket, key, version-ordinal) for ordered prefix scans, bloom filters to skip absent prefixes. The scanner's only read dependency; the executor reads version metadata here too before acting.

Eval Engine (olm-eval, P3). Pure function decide(&ObjectMeta, &Policy, eval_clock) -> Vec<EvalDecision>: match filters (prefix ∧ tags ∧ size), select applicable actions, resolve conflicts/overlaps (most-specific / earliest-effective wins; transition-vs-expiration ordering), apply min-age/min-days lattice rules, emit decisions. Deterministic and side-effect-free → unit-testable and fuzzable in isolation. No I/O.

Durable Work Queue (olm-queue, P5). WAL-backed FIFO-with-priority queue. enqueue(WorkItem) is durable before ack to the scanner. Consumers lease(batch, visibility_timeout); on success ack, on failure nack → retry with exponential backoff + jitter; after max_attempts → dead-letter. Per-tenant token-bucket rate limiting + global concurrency cap provide backpressure to the scanner. Idempotency: duplicate ActionToken enqueues collapse.

Executors (olm-exec, P6–P8). Lease WorkItems, re-read current version metadata (guard against staleness), and perform the action through Backend: transition (copy/relocate to new storage class, verify, update metadata, optionally delete source), expiration (delete a specific version / insert or remove a delete marker), abort-MPU (abort incomplete multipart uploads older than N days), noncurrent transition/expiration (act on the version chain honouring NewerNoncurrentVersions), intelligent-tiering (access-time-driven tier moves). Every action is idempotent given its ActionToken; every result is audited.

Backend (olm-backend, P6). Narrow trait the executors call: copy_object, set_storage_class, delete_version, put_delete_marker, list_multipart_uploads, abort_multipart_upload, head_version. Impls: local-FS (a faithful versioning-aware store for tests + small deployments) and #107 object store. Cloud S3/GCS/Azure impls are designed-for but PhaseDeferred("Deferred Features Register"). Trust boundary: this is the only component with destructive authority.

Audit + WAL (olm-audit, P9). Append-only log of every decision + action + result (who/what/when/which-version/why-rule). WAL with group-commit + fsync policy + recovery scan (from #69/#71). Hosts the idempotency-token table (was this ActionToken already completed?), the leader-election lease, and durable checkpoint persistence. The forensic source of truth; never mutated in place.

8. Domain Model / Policy Language

Lifecycle Policy DSL (JSON on the wire; compiled to typed LifecyclePolicy)

A policy is a bucket-scoped list of rules. Each rule = { id, status, filter, actions[] }. Wire format mirrors S3/GCS field names for conformance; we accept S3-style JSON and a GCS-compatibility shim.

EBNF (abstract grammar):

Policy        ::= "{" "rules" ":" "[" Rule { "," Rule } "]" "}"
Rule          ::= "{" "id" ":" String ","
                      "status" ":" ("Enabled" | "Disabled") ","
                      [ "filter" ":" Filter "," ]
                      "actions" ":" "[" Action { "," Action } "]" "}"
Filter        ::= "{}"                              (* match all *)
                | "{" "prefix" ":" String "}"
                | "{" "objectSizeGreaterThan" ":" UInt "}"
                | "{" "objectSizeLessThan" ":" UInt "}"
                | "{" "tag" ":" Tag "}"
                | "{" "and" ":" "{" FilterTerms "}" "}"   (* AND-combine *)
FilterTerms   ::= [ "prefix" ":" String ]
                  [ "tags" ":" "[" Tag { "," Tag } "]" ]
                  [ "objectSizeGreaterThan" ":" UInt ]
                  [ "objectSizeLessThan" ":" UInt ]
Tag           ::= "{" "key" ":" String "," "value" ":" String "}"
Action        ::= Transition | Expiration | NoncurrentTransition
                | NoncurrentExpiration | AbortIncompleteMPU
Transition    ::= "{" "type" ":" "Transition" ","
                      ( "days" ":" UInt | "date" ":" Rfc3339Date ) ","
                      "storageClass" ":" StorageClass "}"
Expiration    ::= "{" "type" ":" "Expiration" ","
                      ( "days" ":" UInt
                      | "date" ":" Rfc3339Date
                      | "expiredObjectDeleteMarker" ":" Bool ) "}"
NoncurrentTransition ::= "{" "type" ":" "NoncurrentVersionTransition" ","
                      "noncurrentDays" ":" UInt ","
                      [ "newerNoncurrentVersions" ":" UInt "," ]
                      "storageClass" ":" StorageClass "}"
NoncurrentExpiration ::= "{" "type" ":" "NoncurrentVersionExpiration" ","
                      "noncurrentDays" ":" UInt
                      [ "," "newerNoncurrentVersions" ":" UInt ] "}"
AbortIncompleteMPU   ::= "{" "type" ":" "AbortIncompleteMultipartUpload" ","
                      "daysAfterInitiation" ":" UInt "}"
StorageClass  ::= "STANDARD" | "STANDARD_IA" | "ONEZONE_IA"
                | "INTELLIGENT_TIERING" | "GLACIER_IR"
                | "GLACIER" | "DEEP_ARCHIVE"

Storage-Class Lattice (Allowed Transitions + Min-Days)

Partial order by "colder/cheaper-to-store, slower-to-retrieve". A transition is legal only downward (toward colder) and only after the source class's minimum residency.

From \ To STD_IA ONEZONE_IA INT_TIER GLACIER_IR GLACIER DEEP_ARCHIVE
STANDARD ✓ (≥30d*) ✓ (≥30d*) ✓ (≥0d) ✓ (≥0d) ✓ (≥0d) ✓ (≥0d)
STANDARD_IA — — ✓ ✓ ✓ (≥30d) ✓ (≥30d)
ONEZONE_IA — — ✓ ✓ ✓ (≥30d) ✓ (≥30d)
INT_TIER — — — ✓ ✓ ✓
GLACIER_IR — — — — ✓ ✓
GLACIER — — — — — ✓ (≥90d)
DEEP_ARCHIVE — — — — — —

* STD→IA min-days is configurable (S3 historically 30d; some classes 0d). — = illegal (enforced by I1). Upward transitions (warming) are not a lifecycle action (require RESTORE, deferred §8). The lattice is encoded as a const table in olm-model; olm-eval consults it before emitting a Transition decision.

Object / Version Metadata Record (Read by Scanner + Executor)

ObjectMeta {
  bucket: BucketId,
  key: ObjectKey,                 // UTF-8, ≤ 1024 bytes
  version: VersionId,             // opaque; "null" for unversioned
  is_latest: bool,                // current version of the key?
  is_delete_marker: bool,         // version is a delete marker
  size: u64,                      // bytes (0 for delete marker)
  storage_class: StorageClass,
  created_at: Utc,                // version creation (last-modified)
  noncurrent_since: Option<Utc>,  // when it became noncurrent (for NoncurrentDays)
  last_access_at: Option<Utc>,    // for intelligent-tiering
  tags: TagSet,                   // object tags (AND-combined in filters)
  etag: Etag,
  owner: Option<OwnerId>,
}

Version chain for a key = the latest version + ordered noncurrent versions (newest→oldest) + delete markers, sorted by created_at desc. noncurrent_since for version v = created_at of the version that superseded v (S3 semantics: a version becomes noncurrent when a newer version is written).

Versioning Semantics

  • Unversioned bucket: one version per key; Expiration deletes the object; transitions change its class in place.
  • Versioned bucket: Expiration on the current version inserts a delete marker (the object "disappears" but versions remain). NoncurrentVersionExpiration permanently deletes noncurrent versions. ExpiredObjectDeleteMarker: true deletes a delete marker that has no noncurrent versions behind it (cleanup of orphaned markers). NewerNoncurrentVersions: K retains the K newest noncurrent versions and only acts on the rest.
  • Delete-marker rules: an expiration Days/Date action does not apply to delete markers (only ExpiredObjectDeleteMarker targets them). A delete marker with zero noncurrent versions behind it is "expired" and may be removed.
  • Latest vs noncurrent: Transition/Expiration (non-"Noncurrent" actions) apply to the current version; NoncurrentVersion* apply to noncurrent versions.

Worked Examples

E1 — tier then expire current versions:

{ "rules": [{
  "id": "logs-tier-expire", "status": "Enabled",
  "filter": { "prefix": "logs/" },
  "actions": [
    { "type": "Transition", "days": 30,  "storageClass": "STANDARD_IA" },
    { "type": "Transition", "days": 90,  "storageClass": "GLACIER" },
    { "type": "Expiration", "days": 365 } ] }] }

E2 — keep 3 noncurrent, expire older after 30d; clean orphan markers:

{ "rules": [{
  "id": "versions", "status": "Enabled", "filter": {},
  "actions": [
    { "type": "NoncurrentVersionExpiration", "noncurrentDays": 30, "newerNoncurrentVersions": 3 },
    { "type": "Expiration", "expiredObjectDeleteMarker": true } ] }] }

E3 — size + tag filter, abort stale uploads:

{ "rules": [{
  "id": "big-cold", "status": "Enabled",
  "filter": { "and": { "prefix": "data/", "tags": [{"key":"tier","value":"cold"}],
                       "objectSizeGreaterThan": 1048576 } },
  "actions": [
    { "type": "Transition", "days": 0, "storageClass": "GLACIER_IR" },
    { "type": "AbortIncompleteMultipartUpload", "daysAfterInitiation": 7 } ] }] }

Conflict / Overlap Resolution Rules

  • Two rules match one object: union of non-conflicting actions; for the same action class on the same target, the shorter Days / earlier Date wins (most-aggressive-but-legal), matching S3's "smallest applicable" behaviour; ties broken by lexically-smallest rule.id (determinism).
  • Transition vs Expiration on the same object/day: Expiration wins (no point transitioning an object that expires the same day) — emit only the expiration.
  • Multiple transitions: ordered by effective day; each must be lattice-legal from the expected class at its effective day (not the current class) — the evaluator simulates the class timeline.
  • Disabled rules: ignored entirely (status != Enabled).
  • Prefix overlap: more-specific prefix does not override; both apply, then per-action-class resolution above runs.
  • Result is order-independent: resolution is a deterministic fold → same EvalDecision[] regardless of rule order (I7).

Design principles (§6)

  • Idempotency over speed. (P1) Every executed action is keyed by a deterministic ActionToken; re-execution is a no-op. Tradeoff: an idempotency-table lookup + write per action. Operational: a crashed/retried executor never double-deletes or double-bills. Violation breaks: at-least-once retries become at-least-once effects → duplicate deletes, mass data loss.
  • Version-id pinning. (P2) Decisions and actions name an exact VersionId; the executor re-heads the version and aborts if the pinned version no longer matches (overwritten/deleted concurrently). Tradeoff: extra HEAD per action. Operational: a PUT racing a scan never causes the wrong object to be expired. Violation breaks: expire the current object when you meant a noncurrent one — irreversible.
  • Determinism of rule evaluation. (P3) decide(meta, policy, eval_clock) is a pure function; identical inputs → identical outputs, byte-for-byte. Tradeoff: the clock must be frozen + threaded explicitly (no now() inside eval). Operational: dry-run preview equals real run; re-scan is reproducible; conformance is testable. Violation breaks: flaky decisions, un-auditable behaviour, "why did it delete that?" with no answer.
  • Dry-run before destructive action. (P4) Every policy change and every operator-triggered run can preview decisions without enqueuing; destructive actions on a new policy default to a dry-run grace window. Tradeoff: a preview pass costs a scan. Operational: operators see blast radius before bytes vanish. Violation breaks: a typo in a Prefix deletes the wrong tree on first apply.
  • Crash-only / replayable. (P5) No graceful-shutdown-only invariants; the WAL + checkpoints make any kill point recoverable; recovery is replay, not repair. Tradeoff: fsync on the critical path; replay logic to maintain. Operational: kill -9 is a supported shutdown. Violation breaks: a crash mid-transition leaves orphaned copies / lost deletes with no recovery.
  • Backpressure everywhere. (P6) Bounded channels/queues; the scanner blocks when the queue is full; executors pull at the backend's pace; per-tenant rate limits cap fan-out. Tradeoff: lower peak throughput than unbounded. Operational: olmd never OOMs and never overruns the meta-store/backend. Violation breaks: unbounded queue growth → OOM → loss of in-flight state.
  • Append-only audit. (P7) Every decision + action + result is appended, never mutated; the log is the forensic + idempotency source of truth. Tradeoff: storage growth → compaction needed. Operational: "prove this deletion was authorised" is a log query. Violation breaks: destructive actions become unaccountable.
  • Bounded resource usage. (P8) Fixed memory/FD/thread budgets (§4); streaming, never buffering, the namespace. Tradeoff: must checkpoint + resume rather than hold state. Operational: predictable footprint at any scale. Violation breaks: a 10^10-object bucket OOMs a naive in-memory scan.
  • Fail safe, not fail open. (P9) If anything is uncertain — clock jumped, policy ambiguous, version mismatch, backend error — do nothing destructive and alert. Tradeoff: delayed actions, more alerts. Operational: the worst case is "expired late," never "deleted wrong." Violation breaks: uncertainty → destruction.
  • Single writer per bucket. (P10) A bucket-shard is owned by exactly one leader via a lease; no two olmd instances act on the same object concurrently. Tradeoff: leader election + fencing complexity; one bucket's throughput bounded by one node. Operational: no concurrent conflicting deletes/transitions. Violation breaks: split-brain double-execution.
  • Separation of decision and execution. (P11) olm-eval decides (pure); olm-exec acts (effectful); they communicate only through the durable queue. Tradeoff: an extra serialisation hop. Operational: you can re-run decisions without acting, and replay actions without re-deciding. Violation breaks: untestable, unreplayable tangle (the MinIO/Ceph pitfall).
  • Explicit, versioned policy epochs. (P12) A scan pins one policy_epoch; a mid-scan policy change takes effect next run. Tradeoff: up to one cadence of staleness. Operational: no half-old-half-new evaluation within a run. Violation breaks: nondeterministic, irreproducible runs.
  • Verify after transition. (P13) After a copy/relocate, the executor verifies the new object (etag/size/storage-class) before deleting the source (end-to-end argument). Tradeoff: extra HEAD/read. Operational: never delete the source of a failed copy. Violation breaks: silent data loss on a partial copy.
  • Least privilege + kill-switch. (P14) olm-backend is the only delete-capable surface; a global + per-bucket kill-switch halts destructive work instantly. Tradeoff: an extra check per action. Operational: an operator can stop a runaway deletion in one command. Violation breaks: no brake on a misbehaving policy.
  • Conformance to a published spec, not folklore. (P15) Behaviour is defined by differential tests against S3/GCS documented semantics, not by what we happen to implement. Tradeoff: maintain a spec oracle + fixtures. Operational: predictable, portable semantics. Violation breaks: surprising day-boundary / version edge-case behaviour.
