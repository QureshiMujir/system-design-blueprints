⬜ Phase 0 — Workspace Skeleton & Governance

Objectives

Stand up the 12-crate Cargo workspace, CI, governance, and a trivial end-to-end dry-run path. No business logic. Constraint introduced: everything compiles, make ci green, deterministic toolchain.

Deliverable

cargo build green ×12 crates; olmd --version; olmctl dryrun --policy examples/empty.json prints "0 decisions"; CI green.

Acceptance

fmt+clippy(-D warnings) clean; cargo test passes (smoke); cargo deny check ok; build reproducible under --locked; cold olmd start ≤ 1 s (no work).

Fixtures

empty.json (no rules → 0 decisions); three-objects.json (in-mem namespace); version.smoke (binary --version golden).

Pitfalls
  • Crate cycles (olm-model must not depend on others) → enforce layering in deny.toml bans.
  • async_trait boxing surprises → fix object-safety early.
  • CI nondeterminism from unpinned toolchain → rust-toolchain.toml.

⬜ Phase 1 — Domain Model & Policy DSL (`olm-model`, `olm-policy`)

Objectives

Implement all §11 types and the §8 policy language: JSON → AST → validate → typed LifecyclePolicy with policy_epoch. Lattice table encoded. Constraint: malformed policies are rejected before persistence (principle 4, 15).

Deliverable

olmctl policy lint <file> validates + pretty-prints normalized policy or precise error; library parses S3 and GCS shapes.

Acceptance

100% of §8 malformed cases rejected with the listed error; 100% of valid S3/GCS fixtures compile; parse never panics (fuzzed, P12 seed); compile is deterministic (same JSON → identical bytes).

Fixtures

valid/*.json (E1–E3 §8 + S3 doc examples); invalid/*.json (one per PolicyError); gcs/*.json (shim); golden/*.norm (normalized output snapshots via insta).

Pitfalls
  • Accepting both days and date silently → must be DaysDateConflict.
  • Non-midnight date (S3 truncates to midnight UTC) → reject or document truncation; we reject (BadDate) to be explicit.
  • Tag value Unicode normalization mismatches filter matching → normalize NFC at compile.
  • Prefix with embedded NUL / >1024 bytes → bounds check before store.

⬜ Phase 2 — Object Metadata Store / Index (`olm-meta`)

Objectives

MetaStore trait + in-memory + persistent (LSM, #68) impls; ordered prefix enumeration of version chains; versioned policy store. Constraint: ordered, paginated, resumable reads at 10^10 keys.

Deliverable

olmctl meta scan <bucket> --prefix p/ streams version chains in key order; persistent store survives restart.

Acceptance

Enumeration is total + ordered + gap-free under concurrent writes (snapshot semantics); bloom false-positive ≤ 1%; 1M-object in-mem scan ≤ 1 s; persistent prefix scan ≥ 200k chains/s; restart preserves all keys (checksum).

Fixtures

namespace/small.jsonl (hand-built chains); namespace/versioned.jsonl (latest+noncurrent+markers); namespace/1M.gen (script-generated); policy-epochs.jsonl (multi-epoch).

Pitfalls
  • Version ordinal vs created_at ties (same ms) → tiebreak on VersionId lexive for determinism.
  • Listing during compaction → snapshot iterator pins segment set.
  • Delete markers mis-ordered in chain → markers are versions too; sort with them.
  • Unbounded Page size → cap limit; enforce server-side.

⬜ Phase 3 — Rule Evaluation Engine (`olm-eval`)

Objectives

Pure decide(meta/chain, policy, eval_clock) -> Vec<EvalDecision>: filter match → action selection → conflict/overlap resolution → lattice/min-age guards. Constraint: deterministic, total, allocation-light, fuzz-clean (I7).

Deliverable

olm-eval library + olmctl dryrun produces a stable decision list for any (namespace, policy, clock).

Acceptance

Determinism: 1000× re-eval byte-identical (I7 = 0); decisions match S3/GCS oracle on the conformance corpus (P12 seeds here); decide p99 ≤ 100 µs/object warm (§4); zero panics under fuzz; no now()/IO in crate (lint-enforced).

Fixtures

eval/expire-current.{in,out}; eval/tier-then-expire.{in,out}; eval/noncurrent-keep-k.{in,out}; eval/orphan-marker.{in,out}; eval/conflict-resolution.{in,out}; eval/lattice-illegal.{in,out} (expect skip+reason).

Pitfalls
  • Using current class instead of simulated-at-effective-day class for transition legality → false illegal/legal.
  • Off-by-one on day boundary (S3 acts after midnight UTC following threshold) → centralize age→eligible math; test boundaries ±1 day.
  • Applying Expiration Days to delete markers → must not (§8); only ExpiredDeleteMarker.
  • NewerNoncurrentVersions counting markers as versions → exclude markers from the retained-K count.
  • Tag match case/space sensitivity → exact match on normalized tags.

⬜ Phase 4 — Namespace Scanner & Checkpoints (`olm-scan`)

Objectives

Daily-cadence + on-demand scanner: shard buckets by prefix, stream chains through eval, checkpoint resumably, backpressure to the queue, freeze eval-clock per run. Constraint: close the daily window at 10^9 objects (§4); crash-resumable (I5, I9).

Deliverable

olmd runs scheduled scans; olmctl scan status <bucket> shows shard progress + ETA; crash mid-scan resumes without rescanning completed ranges.

Acceptance

10^9-object bucket scans ≤ 12 h on ≤ 4 nodes (§4); resume after kill loses 0 progress beyond last checkpoint; eval-clock constant within a run (I9 metric = 0); checkpoint never regresses (I5 metric = 0); backpressure holds memory ≤ 64 MiB/task.

Fixtures

scan/resume.scenario (kill at 50%, resume, assert no dup/skip); scan/clock-jump.scenario (inject backward clock → abort); scan/shard-balance.scenario (skewed prefixes); scan/empty-and-huge.scenario.

Pitfalls
  • Checkpoint committed before downstream durability → resumes past un-enqueued work; commit checkpoint only after queue ack (ordering!).
  • Shard boundaries splitting a version chain across tasks → shard on key, never within a key's versions.
  • Clock captured per-shard not per-run → different "now" per shard breaks I9; capture once per run.
  • Cadence drift / overlapping runs → guard: refuse a new run while previous epoch's run is active.

⬜ Phase 5 — Durable Work Queue & Scheduler (`olm-queue`)

Objectives

WAL-backed durable queue with lease/ack/nack, retry/backoff/dead-letter, per-tenant rate limiting, idempotent enqueue (token dedupe). Constraint: exactly-once-effective over at-least-once delivery (I4); bounded, never drops (I11).

Deliverable

olmctl queue stat (depth/in-flight/dead per tenant); durable queue survives kill -9 with no lost/duplicated effects.

Acceptance

0 dropped items (I11 metric); duplicate-token enqueues collapse (I4 test); crash mid-lease → item re-leased after visibility timeout, executed once-effectively; enqueue p99 ≤ 5 ms (WAL fsync, §4); dead-letter on poison after max_attempts.

Fixtures

queue/dedupe.scenario (same token ×100 → 1 effect); queue/crash-release.scenario; queue/backoff.scenario (assert exp+jitter schedule); queue/deadletter.scenario; queue/ratelimit.scenario (per-tenant fairness).

Pitfalls
  • Ack before durable side-effect → lost work on crash; ack only after executor terminal audit (couple with P9).
  • Visibility timeout < action duration → double execution; size vis to p99 exec latency + margin (idempotency still protects).
  • Unbounded retry of poison item → starves queue; enforce max_attempts + dead-letter.
  • Token collision (hash) → 32-byte H domain-separated; collision negligible but audited.

⬜ Phase 6 — Transition Executor & Storage-Class Backends (`olm-exec`, `olm-backend`)

Objectives

Execute TransitionTo / TierMove: re-head (I3) → copy/relocate or set-class → verify (I10) → optional source delete → terminal audit. Implement Backend trait + local-FS + #107 impls. Constraint: never delete source of a failed copy; fenced single-writer (I8). Deferred surfaces: cloud S3/GCS/Azure backend PhaseDeferred("Deferred Features Register"); cross-region/replica fan-out PhaseDeferred("Deferred Features Register").

Deliverable

End-to-end: a Transition decision moves an object to a colder class through local_fs and #107; verified; audited.

Acceptance

Verify-after-copy enforced (I10 test: corrupt copy → source retained, dead-letter); illegal transition rejected (I1); fenced stale-leader action rejected (I8); transition exec p99 ≤ 2 s excl. byte copy (§4); idempotent replay = no-op (I4).

Fixtures

exec/transition-inplace.scenario; exec/transition-relocate.scenario; exec/verify-fail.scenario (copy corrupted → no source delete); exec/fenced-stale.scenario; exec/idempotent-replay.scenario. (Cloud-backend fixtures are Deferred per §6.5.)

Pitfalls
  • Deleting source before verifying destination → data loss; ordering is copy→verify→delete, always (I10).
  • Class change losing user metadata/tags/ACL → copy must preserve metadata; assert in verify.
  • Multipart-copy for large objects partial → treat as not-yet-verified; retry whole.
  • Etag semantics differ across backends (multipart etag ≠ MD5) → compare size+backend-native validator, not raw MD5.

⬜ Phase 7 — Expiration Executor & Versioning Semantics (`olm-exec`)

Objectives

Execute Expiration on current versions honouring versioned vs unversioned semantics (§8): unversioned → permanent delete; versioned current → insert delete marker; expired-object-delete-marker cleanup. Constraint: I2 (only rule-matched deletes), I3 (version pinning), I4 (idempotent).

Deliverable

Expiration end-to-end on both bucket types; delete markers inserted/removed per S3 semantics; every delete audited with rule provenance.

Acceptance

Unmatched-delete attempts = 0 (I2 metric); versioned expiration inserts marker (not permanent delete); ExpiredObjectDeleteMarker removes only truly-orphaned markers; idempotent replay = no-op; matches S3/GCS oracle for delete-marker behaviour (P12).

Fixtures

expire/unversioned.scenario; expire/versioned-insert-marker.scenario; expire/orphan-marker-cleanup.scenario; expire/marker-with-noncurrent-kept.scenario (must NOT remove); expire/provenance-violation.scenario (must abort).

Pitfalls
  • Permanently deleting the current version on a versioned bucket (should insert a marker) → catastrophic; gate by is_versioned(bucket).
  • Removing a delete marker that still has noncurrent versions behind it → "un-deletes" the object; recheck chain freshly (I3).
  • Applying Days-Expiration to a delete marker → forbidden (§8, validated P1, re-checked here).
  • Race: PUT after decision makes a new current version → pinned version is now noncurrent; skip (I3), next run reconsiders.

⬜ Phase 8 — Abort-MPU, Noncurrent Handling & Intelligent Tiering (`olm-exec`)

Objectives

AbortIncompleteMultipartUpload; NoncurrentVersionTransition/Expiration with NewerNoncurrentVersions; access-time intelligent tiering. Constraint: correct version-chain ranking; idempotency on aborts. Deferred surfaces: Glacier RESTORE (warming) PhaseDeferred("Deferred Features Register"); KMS-rotation lifecycle action PhaseDeferred("Deferred Features Register"); ML tiering advisor PhaseDeferred("Deferred Features Register").

Deliverable

Stale uploads aborted; noncurrent versions tiered/expired honouring K-retention; intelligent-tiering moves cold objects.

Acceptance

NewerNoncurrentVersions:K retains exactly the K newest noncurrent versions (markers excluded; verified for K=3 via noncurrent/keep-3-expire-rest.scenario); abort is idempotent across ≥5 retries (mpu/abort-idempotent.scenario); tiering moves cold objects after ≥90 d no-access (§4); matches S3 oracle; restore/KMS/ML paths return PhaseDeferredError (typed).

Fixtures

noncurrent/keep-3-expire-rest.scenario; noncurrent/transition-then-expire.scenario; mpu/abort-stale.scenario; mpu/abort-idempotent.scenario; tiering/cold-access-move.scenario; deferred/restore.scenario (asserts PhaseDeferred("Deferred Features Register")).

Pitfalls
  • Counting delete markers toward the retained-K → markers are not "versions to keep"; exclude.
  • noncurrent_since mis-derived (must be successor's created_at) → wrong age → premature/late expiry.
  • Aborting an in-progress legitimate upload (initiated recently) → respect daysAfterInitiation strictly.
  • Tiering ping-pong (move cold → access → warm → cold) → hysteresis on access threshold.

⬜ Phase 9 — Idempotency, WAL, Audit & Crash Recovery (`olm-audit`)

Objectives

The durability + accountability spine: WAL (group-commit), append-only hash-chained audit, idempotency-token table, leader-election lease + fencing, durable checkpoints, recovery scan. Constraint: RPO 0 for audit/idempotency; crash-only recovery (I4, I6, I8, I12).

Deliverable

kill -9 at any point recovers: no lost audit, no double-effect, leases re-acquired, in-flight items reconciled. tools/audit-verify validates the hash chain.

Acceptance

RPO 0 (fsync-before-ack) verified by crash-injection; audit chain verifies (I6 = 0 breaks); idempotent replay = no-op (I4); every WorkItem has exactly one terminal record (I12 = 0 missing); fenced stale action rejected (I8); startup recovery ≤ 5 s for 10^6 in-flight (§4).

Fixtures

recover/crash-midwrite.scenario; recover/replay-idempotent.scenario; audit/chain-tamper-detect.scenario; lease/split-brain-fence.scenario; recover/orphan-reconcile.scenario.

Pitfalls
  • fsync skipped/batched-too-late → RPO violation on crash; fsync (or fdatasync) before scanner/queue ack.
  • Audit chain break on partial last record → recovery truncates to last complete record + reseals.
  • Idempotency table GC removing tokens still needed → retain until WorkItem terminal + audit sealed.
  • Lease clock skew → use lease epoch + monotonic renew, not absolute wall time alone.

⬜ Phase 10 — Control API & CLI (`olm-api`, `olm-cli`)

Objectives

Operator surface: policy CRUD (validated), dry-run preview, status/metrics read, kill-switch, drain/pause. Stateless handlers over durable stores. Constraint: only mutation entry point; never executes actions itself.

Deliverable

Full operator workflow via olmctl: put policy → dry-run → review blast radius → enable → monitor → drain.

Acceptance

Malformed policy rejected at API (never persisted); dry-run decisions == real-run decisions for same epoch+clock (I7); kill-switch halts destructive work ≤ 1 s (I13); mutations require operator role; status reflects live state.

Fixtures

api/policy-crud.scenario; api/dryrun-blast-radius.scenario; api/killswitch-latency.scenario; api/authz-deny.scenario; cli/exit-codes.golden.

Pitfalls
  • Dry-run using a different clock/epoch than the real run → false preview; pin same inputs, document "as-of".
  • Kill-switch that only stops new leases (in-flight still deletes) → must also gate each destructive op (I13).
  • Policy DELETE silently stopping all lifecycle → require confirm + audit; keep last epoch retrievable.
  • Unauthenticated status leaking object listings → status is aggregate, not per-object, by default.

⬜ Phase 11 — Observability, Multi-Tenancy Fairness & Resilience

Objectives

Production hardening: full metrics/traces/logs, per-tenant fairness + quotas, circuit breakers/bulkheads, graceful degradation. Constraint: a misbehaving tenant/policy cannot starve others or melt the backend. Deferred surfaces: event-driven incremental mode via CDC #103 PhaseDeferred("Deferred Features Register"); per-object cost accounting PhaseDeferred("Deferred Features Register").

Deliverable

Grafana dashboards; per-tenant fairness under a noisy-neighbour load test; circuit breaker demonstrably protects the backend.

Acceptance

Noisy tenant capped to its quota (co-tenant p99 latency delta ≤ 5%); breaker opens after 5 consecutive errors within a 10 s window and half-opens after 30 s; overload degrades to dry-run (0 destructive ops) within 2 s of breach detection; 100% of actions traceable end-to-end by trace id (obs/trace-end-to-end.scenario).

Fixtures

resil/noisy-neighbour.scenario; resil/backend-brownout.scenario (breaker opens); resil/overload-degrade.scenario; obs/trace-end-to-end.scenario.

Pitfalls
  • Global concurrency cap without per-tenant fairness → one tenant monopolizes (Borg lesson, §5); enforce per-tenant + global.
  • Breaker open dropping work → items go back to queue (delayed), never dropped (I11).
  • Metric cardinality explosion (per-bucket×per-class labels) → bound labels; aggregate.
  • Degraded mode still deleting → degrade must stop destructive ops first.

⬜ Phase 12 — Conformance, Benchmarks & Chaos

Objectives

Prove correctness vs S3/GCS documented semantics (differential), lock performance via regression-gated benchmarks, and validate safety under fault injection. Constraint: the conformance oracle, not folklore, defines behaviour (principle 15).

Deliverable

Green conformance report (decisions match oracle); benchmark baselines committed + gated; chaos suite passing with all invariants intact.

Acceptance

Conformance: 100% of fixtures match oracle (or documented divergence ADR); perf: decide p99 ≤ 100 µs, scan ≥ 200k/s, no regression > 5% vs baseline; chaos: 0 wrong-version, 0 unmatched-delete, 0 audit-chain-break across the suite; soak: memory ≤ §4 ceilings over 72 h.

Fixtures

conformance/fixtures/** (the full S3/GCS-derived corpus); bench/*.rs; chaos/*.scenario; soak/100M.gen; report/conformance.report.json (machine-readable verdict per bucket).

Pitfalls
  • Oracle drift from real S3 behaviour → cite doc version; ADR any intentional divergence.
  • Benchmarks on debug build / noisy CI → --release, pinned runner, statistical gate (criterion).
  • Chaos that only kills cleanly → also inject kill -9, partial writes, byzantine backend.
  • Soak masking a slow leak → track RSS slope, not just peak.
