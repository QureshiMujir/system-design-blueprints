Per-box dense notes:

  • Caller / CLI — constructs an immutable EvalRequest; all seeds explicit. Trust boundary: request validated (task/model exist, budgets sane) before any inference spend.
  • Registry — resolves (name, version) to content-hashed specs; refuses unversioned or drifted specs. Source of truth for what a task is. Cross-link #137 (deterministic test selection ≈ deterministic task resolution).
  • Task binder — turns a spec into an executable Task; enforces split discipline (eval reads only the declared split) and runs the contamination check (train/test overlap, canary strings). Token-budget enforcement happens here against the model's context window.
  • Dataset — loaders compute a content-hash over the materialized split (post-filter, post-shuffle-with-seed) → the hash that enters the cache key and manifest. Maintains a leakage/contamination index.
  • Prompt — versioned templates; deterministic few-shot exemplar selection (fixed seed over the train/dev pool, never the eval split); chat vs completion formatting; role assembly.
  • Runner — the execution core. Computes the cache key per sample (output-affecting inputs only — Invariant I1/I6), checks the run-cache, calls the model on a miss, journals progress for crash-resume, guarantees exactly-once scoring. Concurrency + backpressure boundary against the model backend.
  • Run-cache — content-addressed completion store: key → Completion. Makes re-runs free and resumable; the key must include every output-affecting input or stale completions poison results (I6).
  • Model-under-test — pluggable backend protocol; local model, hosted API, or #330 streaming runtime. Owns retry/timeout/rate-limit + deterministic-generation controls (seed, temperature=0) where supported. Trust + non-determinism boundary: backend output may be non-deterministic; the cache + manifest pin a specific observed output.
  • Scoring — score(response, reference, metric@version) is a pure function (I2); no I/O, no clock, no RNG (except seeded bootstrap downstream). Deterministic given inputs.
  • LLM-as-judge — a model used as a metric; rubric or pairwise; position-bias mitigated by swap-and-average; calibrated against human labels; judge model is versioned and pinned. Bias/variance are first-class telemetry.
  • Statistics — converts per-sample scores into an aggregate with a confidence interval (bootstrap), paired significance vs a baseline, variance decomposition (sample vs judge vs decoding noise), multiple-comparison correction across slices, and power/MDE guidance. Never emits a bare point estimate (Design Principle 6).
  • Regression + leaderboard — pins baselines, compares A/B with overlapping/paired CIs, gates CI on a significant regression (not noise), breaks down per slice, persists a leaderboard.
  • Result store — append-only persistence of predictions, transcripts, per-sample scores, and the manifest; the substrate for replay and audit.
  • Provenance + report + observability — RunManifest binds code hash ⊕ data hash ⊕ model version ⊕ config ⊕ RNG seeds ⊕ env; the REPLAY harness reconstructs an identical aggregate from the manifest + stored completions (determinism gate, §Phase 11); reports render HTML/MD/JSON; metrics cover throughput, cost, cache-hit, judge budget, flakiness.

8. Domain Model

8.1 Task specification (declarative, the source of truth)

EBNF (TaskSpec, conceptual):

TaskSpec    := "task" Name "@" Version "{"
                 DatasetRef Split TemplateRef FewShot MetricSet DecodeParams [Slices] [Contamination]
               "}"
DatasetRef  := "dataset" Name "@" Version          ; resolves to content-hashed loader
Split       := "split" ("train" | "dev" | "test")   ; eval reads exactly one (I4)
TemplateRef := "template" Name "@" Version           ; rendered prompt is hashed (I10)
FewShot     := "shots" N "from" ("train"|"dev") "seed" S  ; never "test" (I4)
MetricSet   := "metrics" "[" Metric ("," Metric)* "]"  ; each Metric is name@version (I2)
DecodeParams:= "decode" "{" temperature top_p max_tokens [seed] stop "}" ; output-affecting (I6)
Slices      := "slices" "[" SliceKey* "]"             ; stratified aggregation keys
Contamination := "canaries" "[" String* "]"          ; strings that must not appear in eval data

8.2 Core record schemas (lightweight)

Sample      { id: str, input: Any, reference: Any, split: Split, slice_keys: dict, meta: dict }
Prompt      { sample_id: str, rendered: ChatMessages|str, template_hash: str, few_shot_ids: [str] }
Completion  { sample_id: str, text: str, logprobs: Optional, finish_reason: str,
              model_id: str, model_version: str, tokens_in: int, tokens_out: int, cache_key: str }
Prediction  { sample_id: str, completion: Completion, parsed: Any }   ; parsed = extracted answer
Score       { sample_id: str, metric: str, metric_version: str, value: float|bool, detail: dict }
MetricResult{ metric: str, version: str, aggregate: float, ci_low: float, ci_high: float,
              method: str, n: int, error_n: int, per_slice: dict }
RunManifest { run_id, harness_version, code_hash, task: TaskRef, dataset_hash, template_hash,
              model: ModelRef, decode_params, seeds: dict, env: EnvFingerprint,
              budgets: BudgetSpec, created_at, completions_hash }

8.3 Run state machine

   Created ──validate(request, budgets, content-hashes I10)──► Bound
   Bound   ──bind(dataset∩split, template@v, few-shot seed; leakage check I4)──► Ready
   Ready   ──dispatch samples (cache I6 / model I5; journal I13)──► Running
   Running ──all samples have a Completion──► Scored        (score purely I2, exactly-once I3)
   Scored  ──aggregate ± CI (seeded I12); stratify; significance──► Aggregated
   Aggregated ──finalize manifest (I8); store append-only (I7)──► Finalized
   any ──fatal (budget breach I5 / hash mismatch I10)──► Aborted (partial persisted, resumable)
   Running ──crash──► Resumable ──resume from journal (I13)──► Running

8.4 Cache-key derivation (the most safety-critical function)

cache_key(sample) = SHA256( canonical_json({
   harness_version, task_name, task_version,
   model_id, model_version, decode_params,        # temperature, top_p, max_tokens, seed, stop
   rendered_prompt_hash                            # H(template@v rendered with this sample + few-shot)
}))

Every field is output-affecting (I6). Excluded by design: wall-clock, run_id, worker_id, attempt number — these must NOT change the key (else cache never hits / resume re-spends). Adding a field is a major key-schema bump (ADR-030).

8.5 LLM-as-judge protocols

RubricJudge   : prompt = (rubric, question, response) → verdict ∈ {score 1..K | pass/fail}; calibrated vs human.
PairwiseJudge : prompt = (question, A, B) → winner ∈ {A,B,tie}.
                MUST evaluate BOTH (A,B) and (B,A); verdict = mean (swap-&-avg, I9).
SelfConsistency: sample judge T times (seeded), majority/mean → reduce judge variance.

Position-bias telemetry: pos_bias = win_rate(first) − win_rate(second) over swapped pairs; residual after swap-&-avg should be ≈ 0.

8.6 Statistics: estimators & tests (selection table)

Metric / question Estimator CI method Significance test (paired)
Accuracy / EM (binary per sample) mean bootstrap or Wilson paired bootstrap / McNemar
Token-F1 / BLEU / ROUGE (continuous) mean bootstrap (BCa) paired bootstrap
pass@k (code) unbiased pass@k estimator bootstrap over problems paired bootstrap over problems
Pairwise win-rate (judge) mean of swapped verdicts bootstrap over pairs paired bootstrap / sign test
Calibration (ECE) binned acc−conf
Multi-slice / multi-metric per-slice mean bootstrap per slice + multiple-comparison correction (Holm/BH)

Power/MDE: given baseline variance σ², target effect δ, α, β → required n (closed-form for proportions; bootstrap-empirical otherwise). Reported as guidance, not a gate.

8.7 Worked example — GSM8K, 5-shot, accuracy with CI

TaskSpec gsm8k@1: dataset gsm8k@1 split test; template gsm8k_cot@2; shots 5 from train seed 1234;
  metrics [exact_match@1]; decode {temperature 0, max_tokens 512}.
Run: bind → 1319 test samples; few-shot drawn from train (seed 1234), 0 overlap with test (I4 pass).
  cache_key per sample = H(harness ⊕ gsm8k@1 ⊕ model@v ⊕ decode{t=0,...} ⊕ rendered_prompt_hash).
  Runner: 1280 cache hits (warm), 39 misses → model.generate; exactly-once scoring (I3).
  Score: exact_match per sample (pure I2); n=1319, error_n=0.
  Stats: accuracy=0.612, bootstrap 95% CI [0.586, 0.638] (10K resamples, seed 7), per-slice by digit-count.
  Manifest: code_hash, dataset_hash, template_hash, model@v, seeds {few_shot:1234, bootstrap:7}, env.
  Report: "GSM8K 5-shot EM = 61.2% [58.6, 63.8], n=1319". Never "61.2%" alone (Principle 1).

8.8 Malformed / failure-path examples

  • TaskSpec with shots ... from test → bind rejected, PlanError::FewShotFromEvalSplit (I4).
  • Prompt exceeds model context window → TaskError::TokenBudgetExceeded at bind (truncate-or-fail per config).
  • Dataset hash ≠ manifest hash on replay → ProvenanceError::ContentHashMismatch (I10); refuse run.
  • Pairwise judge called with only (A,B) ordering → JudgeError::UnswappedComparison (I9).
  • Bootstrap invoked with global RNG → StatsError::UnseededRNG (I12).
  • pass@k with n < k samples → MetricError::InsufficientSamples (I15).
  • Resume finds a journal gap (missing seq) → RunnerError::JournalGap (I13); re-dispatch missing samples only.
  • Budget breach mid-run → BudgetError::Exceeded (I5); run Aborted, partial results persisted, resumable.

Design principles (§6)

  • (P1) Every reported number carries a confidence interval. No bare point estimates ever leave the system — an aggregate is (value, ci_low, ci_high, method, n). Tradeoff: a bootstrap pass per metric. Operational: dashboards show error bars; gates test significance. Violation: a 0.3% "improvement" within noise gets shipped, then reverts — the canonical eval failure.
  • (P2) Scoring is a pure function of (response, reference, metric-version). No I/O, clock, RNG, or global state inside a metric. Operational: metrics are unit-testable + cacheable + replayable. Violation: a metric that calls a tokenizer with a process-global seed produces different scores on different machines → unreproducible numbers.
  • (P3) The cache key includes every output-affecting input. H(task@v ⊕ model@v ⊕ rendered-prompt ⊕ decode-params ⊕ harness-version). Tradeoff: over-keying loses some cache reuse. Operational: changing a prompt template must miss the cache. Violation: under-keying serves a stale completion for a changed prompt → silently wrong scores (the worst bug class — looks fine, is wrong).
  • (P4) Same manifest ⇒ same aggregate. Code hash ⊕ data hash ⊕ model version ⊕ config ⊕ seeds ⊕ env fully determine the headline number (given stored completions). Operational: a reviewer reproduces a paper number from the manifest. Violation: "works on my machine" benchmarks; irreproducible research.
  • (P5) No train/test leakage; few-shot never touches the eval split. Eval reads only its declared split; exemplars drawn only from train/dev with a fixed seed; contamination index checked. Violation: exemplar = eval question → inflated score that collapses on a clean set.
  • (P6) Determinism of the control plane; non-determinism quarantined to the backend. The runner, cache, scorer, and stats are deterministic; only the model backend may be non-deterministic, and its output is pinned in the cache + manifest. Violation: re-running gives a different number with no recorded reason.
  • (P7) Exactly-once scoring under crashes and retries. A sample is scored once per run regardless of retries/resume, via a journal + content-addressed completions. Violation: resume double-counts → inflated n, wrong CI width.
  • (P8) Bounded, fail-closed budgets. Token, cost, and judge-call ceilings are enforced before spending; breach aborts cleanly with partial results persisted. Violation: a runaway judge loop spends the monthly API budget overnight.
  • (P9) Judge bias and variance are first-class, not assumed away. Position bias mitigated (swap-&-avg), verbosity/self-preference flagged, judge calibrated vs human labels, judge model versioned. Violation: a position-biased judge "proves" the candidate that happened to go first is better.
  • (P10) Provenance is append-only and total. Predictions, transcripts, scores, and manifests are written once, never mutated; the run is fully auditable. Violation: an edited result with no audit trail; silent score laundering.
  • (P11) Datasets and prompts are content-addressed and versioned. A dataset's hash is over its materialized split; a prompt's hash over its rendered template. Violation: "the benchmark changed under us" with no version bump — irreproducible deltas.
  • (P12) Stratified before aggregate; distributions before means. Report per-slice metrics and score distributions, not just a global mean. Violation: a global accuracy hides a catastrophic regression on a minority slice.
  • (P13) Regression gates test significance, not point deltas. A gate fires only on a statistically significant paired regression after multiple-comparison correction. Tradeoff: needs adequate n/power. Violation: a noisy gate flaps and gets disabled — worse than no gate.
  • (P14) Conservative under estimator error. Sketch/sample error bounds widen CIs; a marginal judge verdict (near 0.5) is reported as uncertain, not forced to a winner. Violation: over-claiming significance from a wide-CI difference.
  • (P15) Replayability first. Any run can be reconstructed from its manifest + stored completions without re-spending inference; the replay harness asserts identical aggregates (determinism gate). Violation: you can never reproduce last quarter's leaderboard.
