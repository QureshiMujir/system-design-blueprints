Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. If decode_params includes a seed field but the hosted API ignores it silently, the cache key will treat two runs as equivalent even though the completions may differ. How does the system distinguish a backend that respects seeds from one that does not, and how does the manifest record this distinction to prevent a reviewer from assuming bit-exact replay? (§8.4, §Phase 3, I6, I8, MM10)
  2. The cache key is derived from rendered_prompt_hash, which is itself a hash of the template content and the few-shot exemplars. If the few-shot pool changes between two runs (e.g., because the train split was re-filtered) but the template version does not change, will the cache correctly miss? Trace the hash dependency chain from the train split to the final cache key and identify every invariant that must hold. (§8.4, §Phase 1, §Phase 2, I4, I6, I10, ADR-030)
  3. Bootstrap CIs are valid when samples are i.i.d. In a stratified-aggregation scenario where you compute per-slice CIs and then report a weighted aggregate, the slice scores are correlated if a sample belongs to multiple slices. What is the correct resampling strategy, and how does the multiple-comparison correction interact with per-slice significance thresholds? (§8.6, §Phase 9, ADR-015, ADR-017, MM3)
  4. The pairwise judge evaluates (A, B) and (B, A). Swap-and-average removes first-order position bias. Does it remove verbosity bias? How would you design a conformance fixture that distinguishes a judge with pure position bias from one with pure verbosity bias, and what additional mitigation would each require? (§8.5, §Phase 8, I9, MM4)
  5. A MetricResult carries n = number of successfully scored samples and error_n = number of errors. The bootstrap CI is computed over the n scores. Under what conditions does a high error_n invalidate the CI's coverage guarantee, and what should the report say to the operator? (§8.2, §Phase 9, I11, §Phase 6, MM6)
  6. The replay harness asserts that manifest + stored completions → identical aggregate. If the scoring code (metric@version) is updated between the original run and the replay, the assertion should fail. How does the system differentiate a legitimate version-bump divergence from a hidden-nondeterminism divergence, and what does it report in each case? (§Phase 11, I1, I2, ADR-030, Compatibility & Versioning, MM7)
  7. The pass@k estimator is 1 − C(n−c, k)/C(n, k). When n is large and c is small (rare passes), the combinatorial terms underflow float64. How should evalh.metric.passk implement this numerically, and what is the conformance test that catches a naive implementation? (§Phase 7, I15, §8.6, ADR-015)
  8. A run has max_judge_calls = 2000 and requires 1000 pairwise comparisons × 1 self-consistency sample = 2000 calls. Exactly at the ceiling. The budget guard checks before dispatch. If the dispatcher pre-reserves the budget for a batch of calls and some calls fail and are retried, is the ceiling still honored? Trace the budget accounting through a retry. (§Phase 5, §Phase 8, I5, I3, ADR-011, ADR-029)
  9. Contamination detection uses n-gram overlap between the few-shot pool and the eval split. A test question appears in the training data paraphrased at the sentence level but not verbatim. The n-gram index misses it. What is the residual contamination risk after the current design, and how would you bound it quantitatively given a specific n-gram size? (§Phase 1, §Phase 13, I4, §1, MM9)
  10. The regression gate fires only on a significant paired regression after Holm-Bonferroni correction across the metric-slice family. Suppose a developer adds 50 new slices to a task to improve observability. Does this increase or decrease the gate's sensitivity to a real per-slice regression? How should the gate policy be adjusted, and which invariant governs the decision? (§Phase 10, §Phase 9, I14, ADR-017, MM3, MM6)
  11. The run-cache is content-addressed and never mutates a stored completion (I7). A metric bug is discovered post-run. The correct completions are already cached. Describe the full recovery procedure: which artifacts need to change, which remain valid, what version bumps are required, and which invariants are exercised. (§Phase 6, §Phase 11, I2, I7, ADR-030, Compatibility & Versioning, §Phase 0)
  12. Two runs of the same task on the same model produce n_A = 1319 and n_B = 1301 (18 samples errored in run B). The A/B comparison must be paired. How should the system construct the paired sample, and what should the report say about the 18 missing samples? Does the CI on the paired delta correctly reflect the uncertainty from those missing samples? (§8.6, §Phase 10, §Phase 9, I11, ADR-016, MM3)
  13. The evalh CLI cold-start target is ≤ 300 ms to first sample dispatched (§4). The registry loads from disk; the task binder runs a leakage check; the model backend initializes a connection pool. Profile each contributor to this budget and identify which phase adds the most risk of exceeding it as the registry grows. (§Phase 0, §Phase 1, §Phase 3, §4, MM2)
  14. An operator runs evalh replay <run_id> after migrating to a new Python version. The aggregate differs by 1e-8 from the stored value. Is this within the documented determinism boundary, a float-platform drift case, or a genuine nondeterminism bug? What is the diagnostic procedure, and which invariants determine when the difference is acceptable vs a blocker? (§Phase 11, I1, I2, Compatibility & Versioning, ADR-034, MM10)
  15. The judge's scorer_fp (judge model fingerprint) is recorded in the manifest. A provider silently updates their model under the same API name between two runs of the same task. How does the system detect this, and what is the recovery path for a leaderboard entry whose judge is now under a different distribution? (§Phase 8, §Phase 11, I8, ADR-012, §Phase 10, MM8)
  16. The bootstrap uses a seeded numpy.random.Generator. In a process pool (ADR-010), each worker receives a copy of the same seed at fork time. If two workers both bootstrap independently, their bootstrap distributions are identical (same seed). Is this a problem for the aggregate CI, and what is the correct seeding strategy in a parallel scoring context? (§Phase 9, §Phase 5, I12, ADR-010, ADR-015)
  17. A TaskSpec pins decode {temperature 0.0}. A researcher wants to estimate the variance of the model's output distribution (not just the greedy decoding) to inform power calculations. Explain the design change required to the TaskSpec, the impact on the cache-key schema, and the version bump required. (§8.1, §8.4, ADR-030, §Phase 9, §Phase 3, I6, MM2)
  18. The contamination index checks n-gram overlap at task-bind time. But the few-shot pool is drawn at run time (seeded, from train). If a different seed happens to select exemplars that do overlap with eval (even though the pool overall does not), the pre-run check would pass but a specific run would be contaminated. Is this possible given the current design, and which invariant closes the gap? (§Phase 1, §Phase 2, I4, §8.1, §Phase 5, MM9)
  19. The result store is append-only. An operator wants to annotate a run with a post-hoc human review of 10 randomly sampled predictions. Where in the architecture does this annotation live, how is it linked to the immutable run, and what does it mean for the manifest's completeness invariant? (§Phase 11, I7, I8, §Phase 4, §8.2, MM7)
  20. The Holm-Bonferroni correction applied to K tests controls the family-wise error rate (FWER). The Benjamini-Hochberg procedure controls the false-discovery rate (FDR). For a leaderboard with 20 slices and 5 metrics (100 tests), which correction is appropriate for a CI regression gate vs a research exploration report, and what is the practical consequence of choosing the wrong one? (§Phase 10, §Phase 9, ADR-017, I14, MM3, MM6)
  21. The journal uses a monotone sequence number (I13) to ensure resume completeness. If two workers write to the same journal file (e.g., after a shard reassignment on crash), the sequence may have gaps or collisions. What is the correct journal write protocol for multi-worker runs, and which invariant governs the acceptable journal topology? (§Phase 5, §Phase 13, I13, I3, ADR-010, MM5)
  22. A new metric is contributed as a plugin via the entry-point mechanism. It uses a global mutable normalization table that is loaded at import time. What is the specific invariant it violates, what property test would catch it, and what change to the plugin contract would prevent such plugins from being registered? (§Phase 6, I2, ADR-021, ADR-026, ADR-030, MM8)

Mental Models & First Principles

  1. MM1 — Content-addressed storage decouples identity from location. Predicts: any object stored by its SHA-256 hash is immutable, deduplicated, and self-verifying on retrieval. Without it: you write a mutable cache indexed by a run-id or a timestamp and silently serve stale completions after a prompt change. Applied: §8.4 (cache_key derivation), §Phase 5 (run-cache store), §Phase 11 (result store, manifest).

  2. MM2 — A key must include all and only the output-affecting inputs. Predicts: over-keying loses cache reuse; under-keying serves wrong completions. Either failure is silent unless you have a key-coverage test. Without it: you omit decode_params from the key, temperature changes are invisible, and you report a "new" number that is actually the old run's cached output. Applied: §8.4, §Phase 5, §Phase 2 (template_hash feeds the key), ADR-030.

  3. MM3 — Paired comparison eliminates between-subject variance. Predicts: for two models evaluated on the same samples, the paired test (paired bootstrap, McNemar) has strictly higher power than an unpaired test at the same n. Without it: you use a two-sample t-test, miss a real regression because the inter-sample noise swamps the signal, and disable the gate as "too noisy." Applied: §8.6, §Phase 9, ADR-016, §Phase 10.

  4. MM4 — A pairwise judge's verdict is a random variable with position and verbosity bias as systematic components. Predicts: a single-order judge vote is E[verdict] + position_bias + verbosity_bias + noise; swap-and-average removes the first-order position component. Without it: whichever response appears first consistently "wins," and you ship a model simply because it happened to be candidate A. Applied: §8.5, §Phase 8 (swap-&-avg, I9), §Phase 8 (bias telemetry).

  5. MM5 — Exactly-once semantics requires journaling before side-effecting, not after. Predicts: if you journal after scoring, a crash between score and journal-write causes re-scoring on resume, inflating n and narrowing the CI. Without it: a killed run at 50% through produces a resume that double-counts hundreds of samples and reports a CI width that is too narrow. Applied: §Phase 5 (journal, I3, I13), §8.3 (run state machine).

  6. MM6 — Statistical power is a design constraint, not a post-hoc concern. Predicts: given baseline variance σ², target effect δ, α, and β, you can compute the required n before running; running with insufficient n produces a wide CI that neither gates a regression nor validates an improvement. Without it: you ship "improvements" that are within noise (Card et al. EMNLP 2020). Applied: §8.6, §Phase 9 (evalh.stats.power, MDE), §Phase 10 (gate design).

  7. MM7 — Provenance is a total order over inputs; a missing field is a reproducibility hole. Predicts: if any output-affecting input (model version, env, seed, decode params) is absent from the manifest, a reviewer cannot reproduce the number. Without it: "works on my machine" benchmarks — a number published without its manifest is not a scientific claim. Applied: §8.2 (RunManifest), §Phase 11 (I8, finalize completeness check), §Phase 0 (manifest spine).

  8. MM8 — An eval metric is only as trustworthy as its calibration against the ground truth it proxies. Predicts: BLEU correlates poorly with human judgment at the sentence level; an LLM judge's κ against human labels is the only honest measure of its reliability. Without it: you optimize a metric proxy and regress on the thing you actually care about. Applied: §8.5 (judge calibration), §Phase 8 (judge/calibration.py), §Phase 6 (differential oracle, ADR-022).

  9. MM9 — Contamination inflates scores monotonically with overlap; a clean-set held out is the only reliable detection. Predicts: n-gram overlap between train and eval data produces scores that collapse when re-evaluated on a genuinely unseen set. Without it: a leaderboard winner is the model most exposed to test questions during training, not the most capable one. Applied: §Phase 1 (contamination index, I4), §Phase 13 (contamination audit), §1 (non-goals: training data is not in scope).

  10. MM10 — Non-determinism must be quarantined at the boundary and pinned, not eliminated end-to-end. Predicts: a hosted API is never bit-deterministic even at temperature=0 (hardware batching, version drift); the correct design pins the observed completion in the cache and replays the stored output. Without it: your "deterministic" run gives a different number each time because the backend silently shifted, and you can never reproduce a published result. Applied: §Phase 3 (nondeterministic backend handling), §8.4 (cache key), §Phase 11 (replay, I1), Principle 6.

Required reading (§5)

Books

  • Efron & Tibshirani, An Introduction to the Bootstrap (1993) — Ch. 6–8 (bootstrap CIs), Ch. 14 (permutation/paired). The statistical core of every reported number. -> applied in §9 (bootstrap CI, BCa), Phase 9 (evalh.stats.bootstrap, seeded resampling)
  • Wasserman, All of Statistics (2004) — Ch. 8 (bootstrap), Ch. 10 (hypothesis testing), Ch. 9 (parametric inference). Significance + power foundations. -> applied in §9 (significance + power), Phase 9 (paired bootstrap, power/MDE)
  • Jurafsky & Martin, Speech and Language Processing, 3e (draft) — chapters on evaluation metrics (BLEU, ROUGE, perplexity, exact-match/F1). Metric semantics + pitfalls. -> applied in §6 (BLEU/ROUGE/perplexity/EM semantics), Phase 6 (metric implementations)
  • Hastie, Tibshirani, Friedman, The Elements of Statistical Learning, 2e — Ch. 7 (model assessment, cross-validation, optimism). Why estimates are biased; calibration. -> applied in §8.6 (model assessment, calibration), Phase 9 (bias/variance tradeoff)
  • Manning, Raghavan, Schütze, Introduction to Information Retrieval — Ch. 8 (evaluation: precision/recall/F, significance of differences). Stratified + significance testing. -> applied in §6 (precision/recall/F, significance), Phase 9 (stratified significance)
  • Gelman et al., Bayesian Data Analysis, 3e — Ch. 6 (model checking), calibration; informs ECE + judge calibration intuition. -> applied in §8 (ECE, judge calibration intuition), Phase 8 (judge calibration)
  • Kleppmann, Designing Data-Intensive Applications — Ch. 11 (stream processing), Ch. 12 (derived data) — idempotency, exactly-once, content-addressing, provenance. -> applied in §5 (idempotency, exactly-once, content-addressing, provenance), Phase 5/Phase 11 (run-cache, journal, append-only store)
  • Hunt & Thomas / Beck, testing classics + xUnit Test Patterns (Meszaros) — fixtures, deterministic test selection, golden tests — the conceptual ancestor (#137) for conformance + run-cache. -> applied in §Phase 0 (conformance fixtures, golden tests), Phase 13 (conformance suite)
  • Tukey, Exploratory Data Analysis (1977) — distributions over point estimates; why you plot score distributions, not just means. -> applied in Phase 12 (distributions before means, score distributions, evalh.report.render)

Glossary · 44 terms · site-wide glossary

Aggregate
A metric's summary (value, ci_low, ci_high, method, n) over a task's samples; never a bare mean (Principle 1).
BCa
Bias-corrected-and-accelerated bootstrap CI; used for skewed metrics (ADR-015).
Bootstrap CI
Confidence interval from seeded resampling of per-sample scores (I12).
Cache key
SHA-256 over all output-affecting inputs of a sample (§8.4); determines run-cache hits (I6).
Calibration (judge)
Agreement of an LLM judge with human labels (Cohen's κ, accuracy) before it is trusted (Phase 8).
Canary
A benchmark string that must not appear in train/few-shot data; contamination probe (I4).
Completion
A model's raw output for a prompt, with tokens/logprobs/finish_reason, content-addressed in the cache.
Conformance fixture
A stored input→expected case that gates merges (conformance/**).
Contamination
Leakage of eval data into few-shot exemplars or a baseline's training set; inflates scores (I4/I7).
Decode params
Temperature, top_p, max_tokens, seed, stop — output-affecting, part of the cache key (I6).
Differential oracle
Cross-checking our metric implementations against reference libraries (ADR-022).
ECE
Expected Calibration Error; binned
EM
Exact Match after normalization (SQuAD-style).
Exactly-once scoring
Each (sample, metric) is scored once per run despite retries/resume (I3).
Few-shot
In-context exemplars prepended to a prompt; drawn only from train/dev with a fixed seed (I4).
Finalize
Sealing a run after a complete manifest is written; store becomes immutable (I7/I8).
Gate (regression)
A CI check that fires only on a significant paired regression post-correction (I14).
Holm / BH
Holm-Bonferroni (FWER) / Benjamini-Hochberg (FDR) multiple-comparison corrections (ADR-017).
Journal
Append-only, totally-ordered log of sample completions enabling exactly-once resume (I3/I13).
Judge (LLM-as-judge)
A model used as a metric (rubric or pairwise); bias/variance treated as first-class (Principle 9).
Leaderboard
Append-only ranked store of model results with CIs and per-slice breakdown (I7).
Manifest (RunManifest)
The full provenance binding code⊕data⊕model⊕config⊕seed⊕env that makes a run reproducible (I8).
McNemar
Paired significance test for binary (correct/incorrect) outcomes (ADR-016).
MDE
Minimum Detectable Effect for a given n, α, β; power guidance (Phase 9).
Metric
A pure function score(response, reference, version) (I2).
MockModel
A deterministic backend used for tests/conformance (no inference).
Pairwise judge
Judge comparing two responses; must evaluate both orderings (swap-&-avg, I9).
pass@k
Probability ≥1 of k sampled programs passes tests; unbiased combinatorial estimator (I15).
Position bias
A judge's tendency to favor the first-presented response; removed by swap-&-avg (I9).
Power
Probability of detecting a true effect of size δ at sample size n (Phase 9).
Provenance
Append-only record of predictions/transcripts/scores/manifests; full audit trail (I7/Principle 10).
Prompt (rendered)
The concrete prompt produced by a versioned template + few-shot; its hash feeds the cache key (I10).
Replay
Reconstructing a run's aggregate from manifest + stored completions without re-spending (Principle 15, I1).
Run-cache
Content-addressed store of completions keyed by §8.4; makes warm re-runs free (I6).
Sample
One dataset item: input, reference, split, slice keys, meta (§8.2).
Sandbox
Isolated executor (#50) for untrusted model-generated code in pass@k (ADR-013).
Score
A metric's per-sample result (metric, version, value, detail) (§8.2).
Self-consistency
Sampling a judge multiple (seeded) times to reduce verdict variance (Phase 8).
Shard
A deterministic partition of samples for parallel workers (H(id)%N).
Slice
A stratification key (e.g., difficulty, language) for per-slice aggregation (Principle 12).
Split
train/dev/test; eval reads exactly one; few-shot never from eval (I4).
TaskSpec
Declarative task definition: dataset + template + few-shot + metrics + decode params (§8.1).
Token-F1
Harmonic mean of token precision/recall between response and reference.
Win-rate
Mean of swap-corrected pairwise judge verdicts (Phase 8).
