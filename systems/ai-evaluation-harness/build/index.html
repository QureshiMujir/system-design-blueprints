⬜ Phase 0 — Repo Skeleton, Core Types, Registry, Task Binder, MockModel, Single-Process Runner, EM Metric, Report, CLI §12

Objectives

Stand up the package; define evalh.types core records + content-hash helpers; a Registry resolving (name, version); a Task binder; a deterministic MockModel; a single-process Runner (no cache/parallelism yet); the ExactMatch metric (pure, I2); a minimal report; evalh run end-to-end on MockModel. This phase establishes the deterministic spine every later phase depends on.

Deliverable

evalh run --task toy_em@1 --model mock:echo executes single-process, scores ExactMatch, prints a report with n and a placeholder CI; pytest green; mypy --strict clean; ruff clean.

Acceptance
  • ExactMatch score on a 100-sample toy task matches a hand-computed golden exactly.
  • content_hash is byte-stable across two processes / two OSes (same input → same hex) — the cornerstone test (I10).
  • Registry rejects unversioned task registration + duplicate version with typed errors.
  • Re-running the identical request yields a byte-identical canonical-JSON report (modulo timestamp envelope) — first determinism check (I1 precursor).
Fixtures
  • conformance/tasks/toy_em@1/ (samples.jsonl + expected_scores.json + expected_report.json). conformance/metrics/exact_match_golden.json (input→Score pairs incl. normalization edge cases). conformance/cache_keys/ placeholder. Malformed: tasks/unversioned_task.json → registry error.
Pitfalls
  • Non-canonical JSON hashing → hashes differ across dict-ordering / float repr / platforms → cache misses + manifest mismatch everywhere. Root: using json.dumps defaults. Debug: hash same object twice with shuffled keys. Recover: route all hashing through canonical_json (RFC 8785), never raw json.
  • Mutable dataclasses → a sample mutated after hashing → hash no longer matches stored. Root: non-frozen records. Debug: hash-after-use mismatch. Recover: frozen=True everywhere; copy-on-derive.
  • EM normalization hidden in the metric, unversioned → silently changing strip/lowercase changes scores with no version bump. Root: normalization not part of metric_version. Debug: score drift with no code-diff trace. Recover: normalization params are part of the metric version (I2/ADR-030).
  • Float in cache-key/manifest serialized lossily → 0.1 round-trips differently. Root: float repr. Debug: key instability on decode params. Recover: canonicalize floats (shortest round-trip repr) or store as exact decimals/strings.

⬜ Phase 1 — Dataset Loaders + Content-Hash + Split Discipline + Leakage/Contamination Check §13

Objectives

Make datasets first-class, content-addressed, and split-disciplined. Implement JSONL + HF-adapter loaders; compute a content-hash over the materialized split (post-filter, post-seeded-shuffle); enforce that eval reads only its declared split and that few-shot exemplars are drawn only from train/dev; implement the contamination/leakage index (I4) and canary check.

Deliverable

A real task (e.g., a small QA set) loads from JSONL with a stable content-hash; the binder draws few-shot only from train, runs the leakage check, and rejects a deliberately contaminated config. EXPLAIN-style report shows dataset_hash, split, few_shot_source.

Acceptance
  • content_hash stable across runs/processes; changes iff the materialized split bytes change (mutation test).
  • Leakage check flags a planted overlap (an eval question inserted into the few-shot pool) → bind rejected (I4).
  • Canary string present in eval data → contamination flagged.
  • Few-shot selection is deterministic (same seed → same exemplar IDs) and never includes a test-split ID.
Fixtures
  • conformance/tasks/qa_small@1/ (train.jsonl, dev.jsonl, test.jsonl + expected dataset_hash). conformance/contamination/leakage_positive/ (planted overlap), contamination/clean/ (no overlap), contamination/canary/ (planted canary). Malformed: dataset/bad_schema.jsonl (missing reference) → loader error.
Pitfalls
  • Shuffle without a seed before hashing → non-stable dataset_hash → cache + manifest churn. Root: unseeded shuffle. Debug: two loads → two hashes. Recover: seeded, deterministic ordering; hash the post-order bytes.
  • Few-shot drawn from the eval split (the canonical leakage bug) → inflated, irreproducible scores. Root: pool = full dataset. Debug: exemplar IDs ∩ eval IDs ≠ ∅. Recover: pool restricted to train/dev; I4 assert.
  • Near-duplicate contamination missed (paraphrased eval item in train) → leakage slips through exact-match index. Root: exact-string index only. Debug: high score that collapses on a held-out clean set. Recover: n-gram / fuzzy fingerprint index; document residual risk.
  • HF dataset revision unpinned → "the dataset changed under us". Root: floating dataset version. Debug: dataset_hash changed with no code change. Recover: pin HF revision; record it in the manifest.

⬜ Phase 2 — Prompt / Template Management: Versioned Templates, Few-Shot, Chat/Completion Formatting, Token-Budget Enforcement §14

Objectives

Make the prompt — the single biggest source of irreproducible eval deltas — versioned, hashed, and budget-checked. Implement the versioned template engine (chat + completion formats), deterministic few-shot assembly, role construction (system/user/assistant), and tokenization-budget enforcement against the model's context window.

Deliverable

A versioned CoT template renders a GSM8K-style 5-shot prompt deterministically in both chat and completion form; template_hash stable; over-long prompts rejected/truncated with a recorded decision. Report shows template@version, template_hash, few_shot_ids.

Acceptance
  • Same (template@v, sample, few-shot seed) → byte-identical rendered prompt + identical template_hash across processes.
  • Editing the template body without a version bump → CI lint failure (template_unversioned_edit).
  • Token-budget enforcement: a prompt exceeding the window is detected pre-call (no wasted inference).
  • Chat and completion renders are both deterministic and self-consistent (same exemplars, same order).
Fixtures
  • templates/gsm8k_cot@2.txt + conformance/tasks/gsm8k_cot_render/ (sample + few-shot → golden rendered prompt, chat + completion). conformance/prompt/over_budget.json (→ TokenBudgetExceeded). Edge: prompt/empty_fewshot.json (0-shot).
Pitfalls
  • Template edited without version bump → cache serves completions for the old prompt → silently wrong scores. Root: no version discipline. Debug: scores moved with no model change; template_hash differs from manifest. Recover: version-bump lint + template_hash in cache key (I6).
  • Few-shot order non-deterministic → prompt varies run-to-run → cache misses + irreproducible numbers. Root: unseeded selection / set iteration. Debug: few_shot_ids differ across runs. Recover: seeded permutation; record IDs.
  • Tokenizer mismatch (budget counted with tokenizer A, model uses B) → off-by context, truncation surprises. Root: unpinned tokenizer. Debug: budget passes but API rejects length. Recover: pin the model's tokenizer @version (ADR-014).
  • Chat-role leakage (putting the answer in a system message; instruction in the wrong role) → format artifacts dominate the score. Root: sloppy role assembly. Debug: score swings with role layout. Recover: explicit, tested role construction; ablate format in conformance.

⬜ Phase 3 — Model-Under-Test Abstraction: Backends (Mock / API / #330 Runtime), Deterministic Generation, Retry/Timeout/Rate-Limit, Batching §15

Objectives

Define the pluggable Model protocol and implement real backends: hosted API (OpenAI/Anthropic-style), the #330 streaming token-generation runtime (local), and the deterministic Mock. Add request batching, retry/timeout/rate-limit handling (token-bucket + backpressure, I5), and deterministic-generation controls (seed, temperature=0 path) where the backend supports them — and explicit handling where it does not.

Deliverable

A task runs against a real API backend and against the #330 local runtime; rate limits respected (no 429 storms); transient failures retried; deterministic backends produce identical completions on re-run (temperature=0 + seed). Report shows model@version, tokens, cost, and per-backend determinism status.

Acceptance
  • Mock + #330 (temperature=0, fixed seed) → byte-identical completions across two runs (determinism where supported).
  • Rate-limit handling: a burst of N requests against an R-RPM cap never exceeds the cap (measured); no 429-induced data loss.
  • Retry path: injected transient 500s recovered without losing samples; permanent failures land in error_n (I11), not silently dropped.
  • Cost/token accounting matches a hand-computed expectation on a fixed fixture.
Fixtures
  • conformance/tasks/api_smoke/ (mock-API server transcript → expected completions). conformance/model/ratelimit_burst.json (N requests, R cap → no breach). conformance/model/retry_transient.json (injected 500s → recovered). conformance/model/determinism_temp0.json (two runs → identical).
Pitfalls
  • Assuming temperature=0 ⇒ determinism on a hosted API — many APIs are not bit-deterministic even at t=0 (batching/hardware nondeterminism). Root: false determinism assumption. Debug: two t=0 runs differ. Recover: pin the observed completion in the cache + manifest (Principle 6); mark backend nondeterministic; replay uses stored output, never regeneration.
  • Retry without idempotency key → double-charged / duplicate completions. Root: re-issuing a non-idempotent request. Debug: tokens_out double-counted. Recover: dedupe by cache_key; idempotent put (I3/I7).
  • Unbounded asyncio.gather → ignores rate limits → 429 storm + bans. Root: no concurrency cap. Debug: 429 spike, backend errors. Recover: bounded queue + token-bucket (I5).
  • Streaming reassembly bug (#330 backend) → truncated/concatenated completions. Root: mishandling stream end / partial chunks. Debug: completion length vs token count mismatch. Recover: explicit stream-finish handshake; verify finish_reason.
  • Rate-limit retry hides a real outage → run "completes" mostly as errors. Root: errors counted as samples. Debug: error_n high but n reported full. Recover: I11 — n = successfully scored only; surface error_n.

⬜ Phase 4 — Multi-Turn / Agent Rollout Adapter (minimal), Prediction Parsing, Answer Extraction §16

Objectives

Bridge from raw completions to scorable predictions, and support the minimal multi-turn rollout an agent task needs. Implement answer-extraction/parsers (the task-specific bridge from free-text to a typed answer), and a bounded multi-turn adapter (model ↔ environment turns) sufficient for tool-use/agent tasks — without building a full agent framework.

Deliverable

A QA task extracts the final numeric/string answer from CoT output and scores it; a minimal 2–3 turn tool-use task runs a bounded rollout against a deterministic environment stub and scores the final outcome. Transcripts persisted.

Acceptance
  • Answer extraction matches a golden on a CoT fixture (incl. tricky cases: multiple numbers, negative, formatted).
  • Parse failures are counted separately and do not crash the run; score = wrong (or per-task policy).
  • Multi-turn rollout is deterministic given a seeded environment; transcript is complete and ordered.
  • max_turns enforced (no infinite loops); budget (I5) counts every turn's tokens.
Fixtures
  • conformance/tasks/gsm8k_parse/ (CoT completions → expected extracted answers, incl. malformed). conformance/tasks/tooluse_2turn/ (deterministic env → expected final score + transcript). Edge: parse/unparseable.json (→ parse_failure, not crash).
Pitfalls
  • Greedy regex extraction grabs the wrong number (e.g., a step's intermediate value, not the final answer). Root: under-specified parser. Debug: extracted ≠ expected on multi-number CoT. Recover: anchor on the answer marker ("####", "the answer is", boxed); version the parser.
  • Parse failure counted as a model error → wrong error_n/n bookkeeping. Root: conflating parse vs backend failure. Debug: error breakdown. Recover: distinct parse_failure category (I11).
  • Unbounded multi-turn loop → runaway cost. Root: no max_turns. Debug: cost/turn spike. Recover: hard turn cap + budget guard (I5).
  • Non-deterministic environment in a rollout → irreproducible agent score. Root: env uses wall-clock/RNG. Debug: replay divergence. Recover: seed the env; if external/nondeterministic, mark the run nondeterministic and rely on stored transcript (Principle 6).

⬜ Phase 5 — Runner Core: Async Execution, Sharding, Content-Addressed Run-Cache, Exactly-Once Journal, Resume §17

Objectives

Turn the single-process runner (Phase 0) into the production execution engine: async I/O dispatch to model backends, CPU scoring on a process pool, sharding across workers, a content-addressed run-cache (I6), an append-only journal for exactly-once + resumable runs (I3, I13). Constraint introduced: every spent inference call is cached and journaled before it is scored.

Deliverable

evalh run <taskspec> --model <backend> --workers N executes a full task with caching + journaling; killing and restarting mid-run resumes with zero double-scoring and zero re-spend on cached completions.

Acceptance
  • Warm re-run of a completed task: 100% cache hits, 0 model calls, identical aggregate.
  • Kill at 50% → resume → final n equals cold-run n (no double count); journal has no gaps.
  • Throughput ≥ 500 scored samples/s for a MockModel (scoring-bound) on 8 workers.
  • Budget ceiling honored: a run capped at K calls makes ≤ K calls then aborts cleanly.
Fixtures
  • conformance/replay/warm_rerun.json — cold then warm; assert hit-rate=1.0, equal aggregate.
  • conformance/tasks/resume_midrun.json — kill/resume; assert n + journal continuity.
  • conformance/cache_keys/key_coverage.json — mutate each output-affecting field → key changes; mutate run_id/worker_id → key stable (I6).
  • conformance/tasks/budget_abort.json — call ceiling → BudgetError::Exceeded, partial persisted.
Pitfalls
  • Cache key under-keying → stale completion served for a changed prompt (Principle 3); manifests as "scores didn't move when I changed the template". Detect via key-coverage test; debug by recomputing key field-by-field.
  • Resume double-count → inflated n, narrowed CI; root cause: scoring before journaling. Fix: journal completed before scored; idempotent score keyed by (sample,metric).
  • Async queue unbounded → memory blow-up under a slow backend; root cause: asyncio.gather over all samples. Fix: bounded queue + worker pool (ADR-011).
  • Process-pool nondeterminism → scores depend on worker count; root: shared mutable state. Fix: pure metrics (I2), no globals.

⬜ Phase 6 — Core Metrics: EM, Token-F1, Accuracy, BLEU, ROUGE, METEOR, Perplexity/Log-Likelihood, Calibration; Plugin Contract + Differential Oracle §18

Objectives

Implement the lexical/probabilistic metric suite as pure functions (I2) behind the Metric plugin contract, each validated against a reference library (differential oracle, ADR-022). Constraint: a metric never does I/O, never reads a clock/RNG, and is byte-stable across platforms.

Deliverable

evalh run scores any task with the full lexical suite; evalh metric verify runs each metric against its reference-library golden and reports max abs diff.

Acceptance
  • BLEU/ROUGE within 1e-6 of sacrebleu/rouge-score on the differential corpus (ADR-022).
  • All metrics pass a Hypothesis property test: score(x)==score(x) across processes/platforms (I2).
  • EM/F1 match SQuAD reference on its dev fixtures.
  • Metric throughput ≥ 50k scores/s (EM/F1) single-core.
Fixtures
  • conformance/metrics/{em,f1,bleu,rouge,meteor,ppl,ece}_golden.json — input→expected (vs reference lib).
  • conformance/metrics/normalization_cases.json — Unicode, articles, numbers, casing.
  • conformance/metrics/purity_property.json — determinism across runs.
Pitfalls
  • Tokenizer drift → BLEU/ROUGE numbers shift silently when a dep updates; root: unpinned tokenizer. Fix: pin version (ADR-014); version is part of metric version.
  • Normalization mismatch → our EM ≠ published EM; debug via per-step normalization trace against reference.
  • Locale-dependent casing (Turkish-i) → nondeterministic lowercase; fix: locale-independent normalization (I2).
  • NaN from empty references → divide-by-zero in F1; fix: defined edge semantics (empty ref → score 0/1 by spec).

⬜ Phase 7 — Code-Execution Metrics: pass@k via #50 Sandbox, Unbiased Estimator §19

Objectives

Score code-generation tasks by executing candidate programs against unit tests inside the isolated #50 sandbox (ADR-013), and aggregate with the unbiased pass@k estimator (I15). Constraint: untrusted model-generated code never runs in-process; always sandboxed, resource-capped, no network.

Deliverable

evalh run humaneval@1 --model <backend> --n 20 --k 1,10 produces pass@1 and pass@10 with CIs (Phase 9), executing all candidates in the sandbox.

Acceptance
  • pass@k matches the unbiased combinatorial formula on synthetic (n,c) fixtures exactly (I15).
  • Sandbox blocks network + filesystem escape + fork bombs (security fixtures pass).
  • n < k → MetricError::InsufficientSamples (I15), never a wrong number.
  • No sandbox leak: all subprocesses reaped; FD/temp dirs cleaned.
Fixtures
  • conformance/metrics/passk_formula.json — (n,c,k)→expected estimator value.
  • conformance/metrics/sandbox_security.json — malicious snippets (network, file write, infinite loop) → contained.
  • conformance/tasks/humaneval_mock.json — deterministic MockModel solutions → known pass@k.
Pitfalls
  • Flaky tests (timing/random in problem tests) → nondeterministic pass; fix: seed + generous timeout; flag flaky problems.
  • Resource exhaustion by a candidate → starves the run; fix: hard cpu/mem/wall caps per candidate (ADR-013).
  • Estimator misuse with n<k or n varying per problem → biased; fix: enforce n≥k, aggregate per-problem then over problems (I15).
  • Zombie processes → FD leak; fix: process-group kill + reap.

⬜ Phase 8 — LLM-as-Judge: Rubric + Pairwise + Swap-&-Avg + Self-Consistency + Calibration + Bias Telemetry §20

Objectives

Make model-graded evaluation trustworthy: rubric and pairwise judges with position-bias removal (swap-&-avg, I9), self-consistency, calibration against human labels, and first-class bias telemetry (Principle 9). Constraint: a pairwise verdict is invalid unless both orderings were evaluated.

Deliverable

evalh run mt-bench@1 --judge <model> produces swap-corrected pairwise win-rates with position-bias telemetry and a judge-calibration report.

Acceptance
  • Every pairwise call has both orderings (I9); unswapped_judge_call = 0.
  • Residual position bias after swap-&-avg ≈ 0 on the bias fixture.
  • Self-consistency reduces verdict variance vs single-sample on the fixture.
  • Calibration report emits κ + accuracy vs human labels; refuses to headline a judge below a configured κ floor.
Fixtures
  • conformance/judge/swap_avg.json — biased single-order vs swap-corrected.
  • conformance/judge/calibration_humanset.json — judge vs human labels → κ.
  • conformance/judge/self_consistency.json — variance reduction with T.
  • conformance/judge/position_bias.json — synthetic first-position-favoring judge → detected.
Pitfalls
  • Position bias → "A always wins because it's first"; fix: swap-&-avg (I9); telemetry residual ≈ 0.
  • Verbosity bias → judge rewards length; detect via length-vs-win correlation; report, optionally length-normalize.
  • Self-preference → judge favors its own model family; mitigate: cross-family judge, disclose scorer_fp.
  • Judge drift → silent provider model update changes verdicts; fix: pin judge version (I8); recalibrate on bump.

⬜ Phase 9 — Statistics: Bootstrap CI (+BCa), Paired Significance, Multiple-Comparison Correction, Power/MDE, Variance Decomposition §21

Objectives

Guarantee Principle 1 (no bare point estimates) and Principle 13 (gates test significance): seeded bootstrap CIs, paired significance tests, multiple-comparison correction, power/MDE guidance, and variance decomposition. Constraint: every aggregate is (value, ci_low, ci_high, method, n) computed with a seeded RNG (I12).

Deliverable

Every reported metric carries a CI; evalh compare A B reports paired deltas with significance + correction; evalh power gives required-n for a target effect.

Acceptance
  • Bootstrap CI reproducible bit-for-bit given a fixed seed (I12); unseeded_bootstrap = 0.
  • CI coverage validated on synthetic data with known parameters (≈95% coverage at 95% CI).
  • Paired test recovers known significant/non-significant differences on fixtures.
  • Correction reduces false-positive rate across many slices on a null fixture.
Fixtures
  • conformance/stats/bootstrap_coverage.json — known dist → CI coverage ≈ nominal.
  • conformance/stats/paired_known.json — designed significant + null pairs.
  • conformance/stats/correction_null.json — many null slices → FWER/FDR controlled.
  • conformance/stats/seed_repro.json — same seed → identical CI.
Pitfalls
  • Unpaired test on paired data → loses power / wrong p; fix: paired bootstrap/McNemar (ADR-016).
  • No multiple-comparison correction → some slice "significant" by chance; fix: Holm/BH (I14, ADR-017).
  • Global RNG → irreproducible CIs; fix: explicit seeded Generator (I12).
  • Tiny-n over-claim → wide CI reported as a win; fix: power/MDE guidance + Principle 14 conservatism.

⬜ Phase 10 — Regression Detection, Baseline Pinning, A/B Compare, Leaderboards, CI Gates §22

Objectives

Operationalize comparison: pin baselines, run A/B model comparisons with CIs, render leaderboards, and fire CI regression gates only on statistically significant paired regressions after correction (I14, Principle 13). Constraint: a gate never fires on a point delta within noise.

Deliverable

evalh compare baseline candidate → A/B report with significance; evalh ci-gate → pass/fail used in GitHub Actions; evalh leaderboard → ranked board with error bars.

Acceptance
  • Gate does NOT fire on a null A/A comparison (no self-regression) across repeated runs.
  • Gate fires on an injected significant regression fixture.
  • Leaderboard ordering stable given identical inputs (deterministic, I1).
  • Per-slice regression surfaced even when global mean is flat.
Fixtures
  • conformance/regress/aa_null.json — A vs A → never fires.
  • conformance/regress/injected_regression.json → fires with correct p.
  • conformance/regress/slice_hidden.json — flat global, regressed slice → flagged.
  • conformance/regress/leaderboard_render.json — golden board.
Pitfalls
  • Flaky gate (no correction/power) → disabled by frustrated devs (worse than none); fix: significance + correction + adequate n (I14).
  • Baseline drift (provider model changed under a pinned name) → spurious regression; fix: pin model version/fingerprint in baseline manifest (I8).
  • Comparing across task versions → apples-to-oranges; fix: refuse compare on differing task@v.
  • Multiple-metric cherry-picking → fix: correct across the whole metric/slice family.

⬜ Phase 11 — Reproducibility: RunManifest, Env Fingerprint, Deterministic Replay Harness (I1 gate), Append-Only Provenance §23

Objectives

Make any run reconstructable from its manifest + stored completions without re-spending inference (Principle 15), and enforce the determinism gate (I1): replay reproduces the identical aggregate. Constraint: a run cannot be Finalized without a complete manifest (I8).

Deliverable

evalh replay <run_id> reconstructs the aggregate from manifest + completions and asserts a bit-identical result; evalh manifest <run_id> prints the full provenance.

Acceptance
  • Replay of any stored run reproduces the headline aggregate exactly (I1).
  • Finalize refuses a run missing any manifest field (I8).
  • Result store rejects writes after finalize (I7); mutation_after_finalize = 0.
  • A reviewer reproduces a published number from the manifest alone (given completions).
Fixtures
  • conformance/replay/manifest_roundtrip.json — run → replay → identical aggregate.
  • conformance/replay/incomplete_manifest.json → finalize refused.
  • conformance/replay/immutable_store.json → post-finalize write rejected.
  • conformance/replay/env_fingerprint.json — deterministic fingerprint.
Pitfalls
  • Hidden nondeterminism (a metric/judge touching global RNG) → replay diverges; fix: I2/I12 purity; replay gate catches it in CI.
  • Manifest omission (an output-affecting field not recorded) → irreproducible; fix: completeness check (I8) + key-coverage test (I6).
  • Mutable results → silent score laundering; fix: append-only store (I7).
  • Floating-point drift across platforms → tiny aggregate differences; fix: pinned numerics + tolerance spec, document determinism boundary.

⬜ Phase 12 — Observability + Reporting: OTel/Prometheus Meters, Report Renderer, A/B + Regression Reports, Dashboards §24

Objectives

Make a run observable in flight and legible after: structured logs, OTel traces, Prometheus meters (ADR-018/019/020), and canonical reports (md/html/json) that render distributions + CIs, not just means. Constraint: every headline renders with error bars (Principle 1) and per-slice breakdown (Principle 12).

Deliverable

evalh report <run_id> → md/html/json report with CIs + distributions + slices; live Prometheus metrics during a run; Grafana dashboards from compose.

Acceptance
  • Report renders CI + distribution + per-slice for every metric, verified against conformance/report/ci_render.json and conformance/report/slice_breakdown.json — 0 metrics missing a CI (Principles 1, 12).
  • Canonical JSON report is byte-stable for identical inputs: two renders of conformance/report/canonical_json.json produce identical SHA-256 over the output bytes (0-byte diff).
  • Live meters reflect cache-hit/cost within the run: cache_hit_rate and budget_remaining gauges update within ≤ 1 s of the underlying event (ADR-019).
  • Trace spans attribute cost to run/sample/judge: 100% of model/judge calls in a 100-sample smoke run carry a span with a non-null cost_usd attribute (ADR-020).
Fixtures
  • conformance/report/canonical_json.json — identical inputs → identical bytes.
  • conformance/report/slice_breakdown.json — per-slice present.
  • conformance/report/ci_render.json — error bars present (no bare mean).
Pitfalls
  • Bare-mean reports → ship-on-noise; fix: renderer refuses to emit a metric without a CI (Principle 1).
  • Unbounded cardinality in metric labels (per-sample id) → Prometheus blowup; fix: bounded label sets.
  • Hot-path logging cost → throughput drop; fix: structured async logging, sampled debug logs.
  • Non-canonical report bytes → spurious diffs; fix: RFC-8785 canonicalization.

⬜ Phase 13 — Hardening: Fuzzing, Soak, Conformance Suite, Contamination Audit, Differential Oracle CI §25

Objectives

Production-harden: fuzz parsers/cache-key/judge-parse (ADR-023), soak long runs, lock the conformance suite into CI, automate the contamination audit (I4/I7-style for eval), and wire the differential metric oracle gate. Constraint: no malformed input crashes the harness; no eval set is silently contaminated.

Deliverable

Green CI: lint + type (mypy --strict) + tests + property + replay gate + fuzz smoke + conformance + differential oracle; a nightly soak job; a contamination report artifact.

Acceptance
  • Fuzz: 0 crashes / 0 unhandled exceptions over the nightly budget.
  • Soak: 6h run, flat memory, 0 leaked sandboxes/FDs, n correct after N kills.
  • 100% conformance fixtures pass; differential oracle within tolerance.
  • Contamination audit runs on every benchmark task; overlaps reported.
Fixtures
  • conformance/** (full suite is the gate).
  • fuzz/corpus/* — seeded malformed inputs.
  • conformance/contamination/{leak_positive,clean}.json — audit detects the planted leak.
Pitfalls
  • Flaky conformance (a nondeterministic fixture) → erodes trust; fix: seed everything (I1/I12).
  • Fuzz finds an unhandled parse path → crash on hostile TaskSpec; fix: typed errors (ADR-029), no bare except.
  • Soak memory creep from unbounded caches/logs; fix: GC + bounded buffers.
