Back-of-Envelope Capacity Model

All inputs are taken from §4 (System Constraints); arithmetic is shown.

  1. Failure detection latency. 3 × T_hb + propagation = 3 × 1 s + ε ≈ 3–5 s (matches §4.1 "< 5 s").
  2. Shuffle fan-out. M maps × R reduces = all-to-all; 1000 executors as both → up to 1000 × 1000 = 1e6 logical fetches, capped at min(num_map, 50) concurrent per reducer (§4.4) — a bounded connection pool.
  3. Driver state. 1M partitions → MapOutputTracker ≈ 1e6 × ~16 B = 16 MB; full DAG + lineage for 10K stages < 2 GB (§4.2).
  4. Shuffle throughput. 1 TB/job (§4.3); map write ≥ 200 MB/s × 10 executors = 2 GB/s aggregate → 1e12 / 2e9 ≈ 500 s spill-bound; reduce fetch ≥ 500 MB/s aggregate per executor.
  5. WordCount 10 GB / 10 executors. 1 GB/executor; map read + shuffle write ≈ 1e9 / 200e6 ≈ 5 s + fetch + reduce → < 60 s budget (§4.3).
  6. FD budget. ≤ 4096 FDs/executor (§4.4); one file per 1M partitions would blow it → sort-based single-file+index is mandatory (MM3).
  7. Speculation. straggler detected within ≤ 1 s poll → duplicate launched < 2 s (§4.1); extra CPU = (straggler fraction) × (task runtime).
  8. Checkpoint cost. dataset size S at ≥ 100 MB/s (§4.1), 1× + ≤ 1.2× overhead (§4.5); a 10 GB cached RDD → ~100 s to checkpoint.
  9. Recompute depth. iterative job of K iterations without checkpoint → depth = K; auto-checkpoint every 10 (§4.6) bounds it to ≤ 10.
  10. RTO single executor loss. < 2 × longest-recompute-stage runtime (§4.6); only lost partitions recompute, not the whole stage.
  11. Task dispatch. p50 < 2 ms (§4.1), 10K in-flight (§4.3) → driver must sustain > 5K tasks/s → batched launches + async fan-out.
  12. PageRank 1M nodes, 10 iter, 10 executors. each iteration shuffles the rank vector (1e6 × 8 B = 8 MB) joined with edges; 10 iterations < 10 min (§4.3) → ~60 s/iteration budget.
