Input Adapter: the single point where untrusted bytes enter the system; owns a contiguous buffer or borrows a caller-provided one, and is the only component permitted to perform I/O. SIMD Structural Scanner: stage 1 of the simdjson design — classifies each byte as structural, whitespace, or string-interior using vectorized comparisons and prefix-XOR quote tracking, never interprets values. UTF-8 Validator: independently verifies byte well-formedness (RFC 3629) before any string content is trusted; runs scalar or SIMD depending on ADR-08. Tokenizer: consumes the structural index (or scans byte-by-byte on the scalar path) to emit Tokens with SourceLocation spans into the input buffer — it does not allocate. Parser: recursive-descent by default, switches to the iterative deep-path parser (Phase 9) once nesting exceeds a low static threshold, enforcing the depth limit before recursing (I2). Value Builder: turns a stream of tokens/parser calls into Value nodes, requesting storage from the Arena Allocator. Arena Allocator: bump-allocates fixed blocks for the lifetime of one Document; the sole heap-allocation path for DOM mode. DOM Value Tree: the tagged-union Value graph rooted at Document; owns no bytes directly — string leaves either borrow the input buffer (zero-copy) or point into arena-owned unescape buffers. String Unescaper: converts escape sequences to UTF-8 bytes lazily, only when a view is materialized or when escapes are present. Number Converter: implements the exact decision table of §16 (integer fast path, Eisel-Lemire, big-integer slow path). SAX Event Emitter: alternative to the Value Builder — emits SaxEvents to a caller-provided handler with no DOM construction, enabling constant-memory streaming. Serializer: walks a Value tree or receives SAX-shaped calls and produces bytes, applying the escaping decision table (§20) and optional pretty-printing. Limits Enforcer: cross-cutting component consulted by the tokenizer, parser, and value builder before any allocation or recursion, holding the Limits struct (depth, document size, string length, number length). JSON Pointer/Patch: Phase 11 layer operating purely on the completed Value tree, never on raw bytes. Buffer ownership: the Input Adapter is the sole owner of the byte buffer for the lifetime of a Document; every StringView in the DOM is a borrow with a lifetime obligation documented in §11.

8. Domain Model

8.1 Grammar (EBNF, per RFC 8259)

value      = ws , ( object | array | string | number | "true" | "false" | "null" ) , ws ;
object     = "{" , ws , [ member , { "," , member } ] , ws , "}" ;
member     = string , ws , ":" , value ;
array      = "[" , ws , [ value , { "," , value } ] , ws , "]" ;
string     = quotation-mark , { char } , quotation-mark ;
char       = unescaped | escape ;
number     = [ "-" ] , int , [ frac ] , [ exp ] ;
int        = "0" | ( digit1-9 , { digit } ) ;
frac       = "." , digit , { digit } ;
exp        = ( "e" | "E" ) , [ "-" | "+" ] , digit , { digit } ;
ws         = { %x20 | %x09 | %x0A | %x0D } ;

Structural characters (six, per RFC 8259 section 2): { } [ ] : ,. Whitespace (three plus space, per RFC 8259 section 2): space (0x20), tab (0x09), line feed (0x0A), carriage return (0x0D) — no others, including no BOM. What the specification permits versus what implementations commonly get wrong: RFC 8259 permits arbitrary nesting depth and arbitrary-precision numbers textually (no grammar-level limit) — implementations commonly get this wrong by either accepting unbounded nesting (T1) or silently truncating number precision without a documented policy (P3). RFC 8259 leaves duplicate object keys as implementation-defined (section 4) — implementations commonly get this wrong by choosing silently and divergently (I10, T6).

8.3 String Escape Table

Escape Meaning Decoded Byte(s)
\" quotation mark U+0022
\\ backslash U+005C
\/ solidus U+002F
\b backspace U+0008
\f form feed U+000C
\n line feed U+000A
\r carriage return U+000D
\t horizontal tab U+0009
\uXXXX BMP code point or surrogate half combine per below if surrogate

Surrogate-pair combining rule: if the decoded \uXXXX value hi is in [0xD800, 0xDBFF], the next token must be \uXXXX with value lo in [0xDC00, 0xDFFF]; the combined code point is 0x10000 + ((hi - 0xD800) << 10) + (lo - 0xDC00). A high surrogate not followed by a matching low surrogate, or a low surrogate not preceded by a high surrogate, is a lone surrogate (ErrorCode::LoneSurrogate).

Worked example — astral-plane character U+1F600 (GRINNING FACE): encoded in the JSON text as 😀. hi = 0xD83D, lo = 0xDE00. Combined: 0x10000 + ((0xD83D - 0xD800) << 10) + (0xDE00 - 0xDC00) = 0x10000 + (0x3D << 10) + 0x200 = 0x10000 + 0xF400 + 0x200 = 0x1F600. The unescaper emits this as the 4-byte UTF-8 sequence F0 9F 98 80.

Worked accept: E2 82 AC (U+20AC EURO SIGN) — byte 1 in 0xE1–0xEC range, bytes 2–3 in 0x80–0xBF — accepted. Worked reject (overlong): E0 80 80 — byte 1 is 0xE0, byte 2 (0x80) falls outside the required 0xA0–0xBF range for that leading byte — rejected as an overlong encoding of U+0000. Worked reject (surrogate): ED A0 80 — byte 1 is 0xED, byte 2 (0xA0) falls outside the required 0x80–0x9F range — rejected because it would encode U+D800, a surrogate code point with no valid UTF-8 representation.

8.5 Number Grammar and Conversion

Integer-versus-double decision table:

Textual Form No ./e/E Fits in int64 Decision
42 yes yes NumberKind::Integer, exact int64
99999999999999999999 yes no (overflows int64) NumberKind::Double, converted via slow path if needed
3.14 no n/a NumberKind::Double
1e10 no n/a NumberKind::Double
-0 yes yes (special-cased) NumberKind::Double, value negative zero, sign bit preserved (see below)

Exact-conversion procedure (named steps): (1) classify — scan the number span once to determine integer-vs-double per the table above without allocating; (2) fast_int — for integer-classified spans within int64 range, multiply-add with overflow checking, done; (3) eisel_lemire — for double-classified spans, attempt the Eisel-Lemire fast path (Lemire 2021): look up the binary power-of-ten in a precomputed table, perform a 128-bit multiply, round; succeeds for the documented ~99.5% of real-world inputs; (4) slow_path — on Eisel-Lemire's documented failure signal, fall back to a correctly-rounded arbitrary-precision decimal-to-binary conversion (Gay 1990); (5) finalize — apply sign, and for the -0 case, preserve the IEEE 754 negative-zero sign bit rather than normalizing to positive zero.

Worked example (beyond 2^53): 9007199254740993 (2^53 + 1) is not exactly representable as a double; the slow path (or Eisel-Lemire, which agrees with it) rounds to the nearest representable double, 9007199254740992.0, via round-half-to-even.

Worked example (slow path required): 2.2250738585072014e-308 sits at the subnormal boundary where Eisel-Lemire's fast-path table lookup is documented to be insufficiently precise; the big-integer slow path is invoked and produces the correctly-rounded subnormal result.

Worked example (huge exponent): 1e400 exceeds double's finite range (max finite exponent ~308); per ADR-15 this converts to +Infinity only if ParseOptions::allow_infinity_on_overflow is set, otherwise it is rejected with ErrorCode::NumberOutOfRange — the default is reject, because Infinity is not itself a valid JSON literal and silently producing one violates P1.

Worked example (-0): the literal -0 parses to NumberKind::Double with value negative zero; -0 == 0 numerically but the sign bit differs, and serialization (§17) must reproduce -0 exactly, not 0, to satisfy I4.

8.6 SIMD Structural-Scan Bitmask Pipeline

Stage Operation Output
1 Load 64-byte chunk into vector register(s) raw bytes
2 Compare against " byte, produce quote bitmask quote_mask
3 Compare against \ byte, compute odd-length-backslash-run mask via carry-chain, XOR into quote mask escaped_quote_mask
4 Prefix-XOR-scan quote_mask (adjusted for escapes) to produce "inside string" region mask in_string_mask
5 Compare against the six structural bytes, AND with NOT in_string_mask structural_mask
6 Compare against the four whitespace bytes, AND with NOT in_string_mask whitespace_mask
7 pext/iterate-and-clear the structural_mask to emit byte offsets into the structural-index array structural_indices[]

Worked 64-byte example (abbreviated to the load-bearing 16 bytes): input {"a":1,"b":"\"x\""}. Byte 0 { → structural. Bytes 1,4 " → quote boundaries, not inside a backslash run, toggle in_string_mask. Byte 11 is \ immediately followed by " at byte 12 — the escaped quote is excluded from quote_mask by the backslash-run parity check in stage 3, so it does not toggle in_string_mask a third time; the scanner correctly keeps bytes 12–14 (x\" content) inside the string region rather than terminating early.

8.7 DOM Value Bit-Layout Table

Field Bits Meaning
tag 3 ValueTag: Null, Bool, Integer, Double, ShortString, String, Array, Object (8 variants fit in 3 bits)
inline_flag 1 1 = payload stored inline in the union; 0 = payload is an indirect Arena offset
payload 60 inline: bool/short-string bytes/small-int; indirect: 32-bit arena block index + 28-bit intra-block offset

Inline-versus-indirect storage rule: Null, Bool, and strings ≤ 7 bytes (ShortString) store their payload inline in the 60 payload bits, avoiding an arena allocation entirely; Integer and Double store the full 64-bit value inline via a second machine word (the tagged union is 16 bytes total, tag+flag+padding in the first 8, full-width payload in the second, to satisfy 8-byte alignment); String (>7 bytes), Array, and Object store an indirect arena reference. Alignment and padding: the 16-byte Value is 8-byte aligned; the 3 tag bits and 1 inline flag occupy the low 4 bits of word 1, with 60 bits of word 1 unused when word 2 carries the full payload (accepted padding cost, traded for branch-free tag dispatch — ADR-09).

8.8 Arena Allocation Model

Blocks are fixed-size (§4: 64 KiB), bump-allocated within a block, and chained in a singly-linked list owned by Document. An allocation request larger than one block gets its own dedicated oversized block. Reset (on parse failure, P7) discards the entire block chain without per-node destructors, an O(blocks) operation, not O(nodes).

8.11 JSON Pointer Grammar and Patch Semantics

json-pointer   = *( "/" reference-token ) ;
reference-token = *( unescaped / escaped ) ;

Patch Op Required Members Semantics
add path, value insert at path, or append if path's last segment is - for an array
remove path delete member/element at path
