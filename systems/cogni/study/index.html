32. Mental Models & First Principles

  1. MM1 — A proof is a certificate, not a re-computation.
    • Predicts: verification cost should never scale with the computation it certifies (P11).
    • Bug class without it: engineers keep "optimizing" the verifier by speeding up re-execution instead of shrinking the certificate.
    • Applied in §11, §19.2.
  2. MM2 — Determinism is a property you design into the numerical pipeline, not a property that emerges from testing.
    • Predicts: fixed-point + canonical reduction order must be fixed at circuit-design time (I9).
    • Bug class without it: intermittent, hard-to-reproduce "slashing" of honest operators.
    • Applied in §13, §7.
  3. MM3 — Stake is a bond against a specific class of provable misbehaviour, not a general trust score.
    • Predicts: slashing conditions must be mechanically checkable on-chain (I10), never a vote.
    • Bug class without it: governance capture disguised as "community moderation."
    • Applied in §18, P1.
  4. MM4 — A trust boundary is where you stop verifying and start assuming.
    • Predicts: every box in §3's diagram that crosses a trust boundary needs either a proof or an economic bond, never a policy document.
    • Bug class without it: a "trusted matcher" quietly becomes a single point of censorship (T10/E8).
    • Applied in §3, §16.
  5. MM5 — Succinctness is a circuit-design decision, not a proof-system marketing claim.
    • Predicts: a proof system's asymptotic succinctness only holds if the circuit itself avoids re-encoding the full computation into the constraint count (P11, custom gates).
    • Bug class without it: "we use a succinct proof system" while gas still scales with model size.
    • Applied in §17, §22.
  6. MM6 — Recursion amortises cost; it does not eliminate it.
    • Predicts: folding schemes (Phase 10) still pay a real per-step cost (§5 Ref-impl #3's pitfall) — budget it, don't assume it's free.
    • Applied in §22.6, §22.7.
  7. MM7 — A bridge's blast radius is bounded by what it custodies, not by what it verifies.
    • Predicts: a checkpoint relay that carries no funds (only a state-root hash, ADR-23) is structurally safer than a funds-custodying bridge even with the same code quality.
    • Applied in §23.9.
  8. MM8 — Economic security and cryptographic security are complementary, not substitutes.
    • Predicts: restaking (ADR-24) can bootstrap Phase 6's stake liquidity, but it never substitutes for the soundness of the proof system itself (I2 stands regardless of how much stake is bonded).
    • Applied in §18.2, §33.
  9. MM9 — A single number (the north-star metric) forces every downstream tradeoff into the open.
    • Predicts: once VIPD is the one number everyone watches, a feature that doesn't move VIPD (token price, follower count) reveals itself as a distraction rather than progress.
    • Bug class without it: teams optimise vanity metrics that correlate with, but don't cause, network health.
    • Applied in §16.2 (Marketplace Fill Rate as a supporting metric), §30.
  10. MM10 — Every trust boundary you remove, you must replace with either a proof or a bond — never with a promise.
    • Predicts: as Cogni removes trust in the operator (via proofs) and trust in the matcher (via the order-log fallback), each removal must land on I1–I14 or a stake mechanism, never on "the team says so."
    • Bug class without it: a roadmap slide claims "trustless" while a component still runs on an unenforced promise.
    • Applied in §7, §24.

Required reading (§5)

Books

  • Justin Thaler, Proofs, Arguments, and Zero-Knowledge (2023) — ch. on sum-check protocol and PIOPs; extract the arithmetization cost model. Applied in §12 (Phase 0 circuit budgeting), §34 item 7.
  • David Wong, Real-World Cryptography (Manning, 2021) — ch. on zero-knowledge proofs and elliptic-curve cryptography; extract BN254/KZG parameter choices. Applied in §9 ADR-03/ADR-04.
  • Andreas Antonopoulos & Gavin Wood, Mastering Ethereum (O'Reilly, 2018) — ch. on the EVM, gas, and precompiled contracts; extract the gas-accounting model. Applied in §4, §14.
  • Jimmy Song, Programming Bitcoin (O'Reilly, 2019) — ch. on elliptic-curve and finite-field arithmetic; extract field-arithmetic implementation patterns reused in the BN254 circuit. Applied in §12 N.2.
  • Martin Kleppmann, Designing Data-Intensive Applications (O'Reilly, 2017) — ch. on consensus and replication; extract the determinism/consistency vocabulary reused for I9. Applied in §8.1, §13 N.2.
  • Jon Gjengset, Rust for Rustaceans (No Starch Press, 2021) — ch. on unsafe code and async; extract the concurrency model for the Cogni Node daemon. Applied in §15 N.2.

Reference Implementations

  • zcash/halo2 — study halo2_proofs/src/plonk/ (circuit synthesis API). Lesson: custom-gate composition for matmul/activation. Pitfall: copying their Poseidon MDS constants without re-deriving for BN254. Applied in §17 (Phase 5).
  • arkworks-rs/groth16 — study src/prover.rs, src/verifier.rs. Lesson: Groth16 CRS structure and pairing-check order. Pitfall: naive multi-scalar multiplication without Pippenger windowing. Applied in §12 (Phase 0).
  • risc0/risc0 — study risc0/zkvm/. Lesson: continuations for large computation. Pitfall: assuming continuation boundaries are free — recursion overhead is real. Applied in §22 (Phase 10).
  • a16z/jolt — study jolt-core/src/jolt/. Lesson: lookup-table decomposition. Pitfall: table-size explosion with unconstrained ranges. Applied in §22 (Phase 10).
  • libp2p/rust-libp2p — study protocols/gossipsub/, protocols/kad/. Lesson: gossipsub mesh parameters. Pitfall: default mesh degree too low under adversarial churn. Applied in §15 (Phase 3).
  • ethereum-optimism/optimism — study packages/contracts-bedrock/src/L1/. Lesson: L2 settlement-bridge design. Pitfall: underestimating challenge-window latency. Applied in §9 ADR-06, §20 (Phase 8).

Glossary (§38) · 56 terms · site-wide glossary

ADR:
Architectural Decision Record — numbered, dated, capturing context/choice/consequences (P12).
ANO:
Active Node Operators, last-7-day count.
ArchitectureId:
stable identifier binding a ModelCommitment to its matching CircuitId (I1, T3).
CBOR:
Concise Binary Object Representation, RFC 8949 — wire format for Receipt/InferenceJob.
CCIP:
Cross-Chain Interoperability Protocol pattern (Chainlink-style oracle relay, ADR-23).
CircuitId:
stable identifier for a zk-ML circuit corresponding to one model architecture.
Cogni Chain:
the settlement layer (EVM L2, Phase 2+).
Cogni Node:
the long-running operator daemon (Phase 3).
Cogni Prover:
the Rust + GPU library producing a Proof.
Cogni Sovereign:
the on-prem/sovereign-cloud deployment artefact (Phase 11).
DePIN:
Decentralized Physical Infrastructure Network.
DMC:
Distinct Models Committed.
EncryptionSpec:
client-declared encryption scheme + pubkey for an encrypted InferenceJob.
ExecError:
enumerated operator-execution failure (ModelNotLoaded, Timeout, ProverPanic, QuantisationDrift).
Folding scheme:
recursive proof composition (Nova/SuperNova/HyperNova).
Groth16:
trusted-setup zk-SNARK; Phase 0 only (ADR-03).
Halo2:
Plonk-style proof system, Phase 1–9 (ADR-03).
HardwareClass:
operator-advertised hardware tier (Consumer | Datacenter | TeeAttested).
Howey test:
US Supreme Court test for what constitutes a security.
InferenceJob:
client-signed request to run a model on an input.
JobId:
32-byte single-use job identifier (I5).
KZG:
polynomial-commitment scheme used in Plonk variants.
Lookup argument:
cryptographic primitive (Lasso, Jolt) collapsing non-arithmetic ops to near-constant cost.
MiCA:
Markets in Crypto-Assets regulation (EU).
ModelCommitment:
author-signed merkle root of model weights plus metadata (I14).
NodeIdentity:
operator's on-chain identity bound to a staking key.
PCR:
Proof Cost Ratio — prover wall-clock ÷ raw inference wall-clock.
PIOP:
Polynomial Interactive Oracle Proof — the arithmetization abstraction behind Plonk/STARKs (Thaler, §5).
Plonk:
universal-setup SNARK (Gabizon/Williamson/Ciobotaru).
Proof:
cryptographic attestation of correct inference execution.
ProofChain:
composition of multiple Proofs under one aggregate proof (Phase 11).
ProofSystem:
the trait boundary making the proof primitive swappable (P10).
Quote:
an operator's bid price + ETA for a job.
Receipt:
on-chain record of a completed InferenceJob (I5, I11, I13).
Restaking:
delegating already-staked collateral (e.g., ETH) to secure a second protocol (EigenLayer pattern, ADR-24).
SchemaId:
version identifier for a model-specific input encoding.
SDD:
Sovereign-Domain Deployments.
SE10K:
Slashing Events per 10,000 proofs.
Slashing:
burn of operator stake on proven misbehaviour (I10).
SlaTier:
BestEffort | Standard | Premium job service-level class.
STARK:
transparent, scalable proof system (no trusted setup).
TEE:
Trusted Execution Environment (Intel SGX/TDX, AMD SEV).
TGE:
Token Generation Event.
VEV:
Validator-Extractable Value — the MEV analogue for inference job ordering.
VIPD:
Verified Inferences per Day — the network's north-star throughput metric.
VRAM floor:
the minimum GPU memory needed to prove a given model size (§34 item 7).
Wassenaar:
multilateral export-control arrangement covering dual-use items.
zk-ML:
zero-knowledge machine learning — cryptographic proofs of correct inference.
BN254:
the pairing-friendly elliptic curve used by Cogni's Groth16/Plonk circuits (Phase 0–9).
EmissionSchedule:
the on-chain-encoded, mechanical token-issuance curve (P6, §8.3).
FeeSplit:
the on-chain record dividing settled fees between operator, treasury, and burn (§8.3, ADR-25).
FSM:
Finite State Machine — the job-lifecycle model of §8.1.
MSM:
Multi-Scalar Multiplication — the elliptic-curve operation whose windowing efficiency dominates Groth16 prover cost (§5 Ref-impl #2).
PoS:
Proof of Stake — the validator-security model Ethereum and EigenLayer use, contrasted with Cogni's proof-based verification in §33.
slashingMultiplier:
the on-chain constant scaling required stake to a job's maxFee (I6).
VRAM:
Video RAM — the GPU memory budget that gates model size per operator (§34 items 7 and 9).
