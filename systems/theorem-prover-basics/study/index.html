34. Mental Models & First Principles

# Model Compressed Insight What It Predicts Bug Class Without It Resolving §
MM1 LCF Kernel Discipline Only Thm constructor proves theorems; all creativity lives outside Any function outside tp-kernel that takes Thm values cannot forge them Tactic bug mistaken for soundness bug; panics inside kernel §3, §6 (P1)
MM2 de Bruijn Namelessness Bound variables are indices, not names; α-equivalence is structural equality Two terms that look different syntactically are equal iff structurally identical after printing Variable-capture bugs in substitution; shadowing errors §8, §13
MM3 Trust-Boundary Minimisation TCB = tp-kernel only; outer crates may be arbitrarily buggy A bug in tp-tactic produces Err, never an unsound Thm Confusion about which bugs affect soundness §3, §7 (I1)
MM4 Proof as Certificate A Proof value is a DAG of rule applications; validity is checkable independent of how it was found recheck_proof is O( proof ) and always terminates
MM5 Budget as Safety Valve Every proof attempt has a step and time budget Infinite tactic loops are impossible to observe from outside Hanging proofs consuming unbounded resources §4, §28 (SLO-2)
MM6 Resource Monotonicity Term and assumption sets grow; kernel rules never shrink them (except INST_TYPE which substitutes) Size bounds must be enforced at construction, not at use Term blowup discovered too late (after allocating) §4, §26 (T3)
MM7 Differential Soundness HOL Light is the oracle; any divergence is a prove bug Differential tests catch semantic drift early Silent divergence discovered only by theorem-prover users §30.4, §35
MM8 Zero-Copy Arena Hot-path term nodes must not allocate per-step Rule-app throughput is determined by allocation rate, not computation Premature pessimisation from naïve Box<Term> §32, §11
MM9 Failure-First API All fallible operations return Result; tp-kernel never panics on valid input Adversarial inputs produce Err, not SIGABRT Panic in kernel treated as soundness violation (it is not, but alarming) §7 (I9), §26
MM10 Semver as Contract The kernel API version encodes semantic compatibility; proof files are versioned artifacts A proof file valid for kernel 1.x may not typecheck under kernel 2.x Silent proof invalidation after upgrade §29, §31

Glossary (§40) · 38 terms · site-wide glossary

α-equivalence
Structural equality of terms up to renaming of bound variables; with de Bruijn indices, this is literal structural equality.
ADR
Architecture Decision Record — a structured rationale for a load-bearing design choice; 25 ADRs in §9.
Arena allocator
A memory region from which term nodes are bump-allocated; freed all at once when the proof context is dropped.
Assumption set
The set of Term hypotheses under which a Thm holds; part of the Thm value in tp-kernel.
Budget
The per-proof cap on rule applications and wall-clock time (§4) enforced by tp-tactic.
CC
Congruence Closure — a decision procedure for ground equalities, implemented in tp-auto (§24).
CIC
Calculus of Inductive Constructions — the dependent type theory underlying Coq/Rocq; not used by prove.
de Bruijn index
A natural number representing a bound variable by its binding depth; eliminates name-capture in substitution.
de Bruijn shift
The renumbering of free indices in a term when it is placed under an additional binder.
Definitional mechanism
A rule that extends the global signature without changing provability; new_constant and new_type_op in §16.
Elaboration
The process of filling in implicit arguments and type information in surface syntax before type-checking; in tp-parse.
Flex-flex pair
A HOU unification constraint between two terms both headed by metavariables; inherently undecidable without bounds.
Flex-rigid pair
A HOU constraint where one side is headed by a metavariable and the other by a constant; solvable by projection or imitation.
HOU
Higher-Order Unification — unification in a simply-typed λ-calculus; semi-decidable (Huet 1975).
HOL
Higher-Order Logic — a classical logic built on simply-typed λ-calculus; the logic of prove.
Inference rule
A function in tp-kernel that takes Thm values (and possibly Term / Type values) and produces a new Thm.
LCF discipline
The design pattern (Edinburgh LCF, 1979) in which Thm is an abstract type whose only constructor is the kernel; guarantees soundness by construction.
LinArith
Linear arithmetic decision procedure based on Farkas' lemma / Omega test; in tp-auto §24.
MSRV
Minimum Supported Rust Version — 1.78 for this project (§4).
Metavariable
A unification variable in tp-auto; existential, not part of tp-kernel's term language.
Occurs check
The test that a metavariable does not appear in its own candidate solution; required for well-founded unification.
Phase gate
A mandatory benchmark or test threshold that blocks progression to the next development phase (§32).
Primitive rule
One of the 10 inference rules whose implementation lives entirely within tp-kernel; the only way to construct Thm values.
recheck_proof
The function in tp-kernel that re-derives a Thm from a Proof term without trusting the tactic that produced it.
Resolution
A refutation-complete proof procedure for first-order logic (Robinson 1965); implemented in tp-auto §23.
SBOM
Software Bill of Materials — a machine-readable inventory of all dependencies; generated per release (§31.3).
SLO
Service Level Objective — a quantified target for system behaviour; four SLOs in §28.5.
Sequent
A judgement of the form Γ ⊢ t : τ (type) or Γ ⊢ p (proof); the internal assertion of tp-kernel.
Signature
The global mapping from constant names to their types; extended by definition mechanisms (§16).
Simply-typed λ-calculus
The type theory underlying HOL; function types α → β, product types, and base types only; no dependent types.
Skolemisation
Replacement of existentially quantified variables with fresh function symbols in first-order normalization; in tp-logic.
Tactic
A function of type Goal → Result<(Vec<Goal>, Justification), Error> in tp-tactic; goal-directed proof construction.
TCB
Trusted Computing Base — the code whose correctness must be assumed for soundness; tp-kernel only in this system.
Term
An element of the HOL term language: variables, constants, applications, λ-abstractions (de Bruijn).
Thm
The abstract type in tp-kernel representing a proved sequent; private constructor enforces LCF discipline.
TPTP
Thousands of Problems for Theorem Provers — a standard benchmark library for ATP systems; used in conformance testing (§30.10).
Type operator
A constructor for compound types, e.g., fun, bool, prod; introduced by new_type_op.
Universe
A hierarchy of type sorts in dependent type theories (Coq, Lean 4); not present in HOL's simple type theory.
