1. Goal & Scope

prove is an interactive theorem prover built on the LCF discipline: soundness reduces to auditing tp-kernel alone — the sole trusted computing base (TCB). ABSTRACT Thm type; private field; 10 primitive inference rules are the only constructors.

1.1 Phase-0 in-scope modules

  1. tp-kernel — TRUSTED TCB: Type, Term (de Bruijn), ABSTRACT Thm, Sequent, 10 primitive rules, new_basic_definition, new_basic_type_definition, type_of.
  2. tp-term — untrusted term/type utilities (substitution, alpha/beta/eta, FV, matching).
  3. tp-parse — lexer/parser/pretty-printer for terms, types, proof-script language.
  4. tp-logic — HOL-lite constants + derived intro/elim theorems.
  5. tp-tactic — Goal/GoalState/Tactic/Justification, tacticals, core tactics.
  6. tp-auto — Unify, ResolutionProver, CongruenceClosure, LinearArith.
  7. tp-cli — the prove REPL + script runner + check + bench.

1.2 System boundaries

  • Provides: LCF-style HOL-lite kernel, tactic engine, FOL automated prover, proof-term re-checker.
  • Does NOT provide: full dependent-type CIC (Coq/Lean scale) PhaseDeferred("§25"), SAT solver (#277), SMT solver (#278), model checker (#279), industrial math library.
  • Trust boundary: only tp-kernel is trusted. Untrusted INPUT = the proof script (.thm).
  • Concurrency: single-threaded REPL/checker. Persistence: none at runtime; Proof optionally serialized.

1.5 Language: Rust (edition 2021, MSRV 1.78, std)

Soundness-decisive rationale: enums + exhaustive match model Term/Type/Thm precisely; module privacy hides Thm's constructor — the LCF discipline enforced by the type system, not convention; no GC perturbing de-Bruijn substitution hot path; #![forbid(unsafe_code)] on tp-kernel.

Rejected: OCaml/SML (classic LCF host, but portfolio Rust toolchain + no runtime desired); C/C++ (memory-unsafe — one buffer bug forges Thm); Python/Lisp (too slow + too dynamic to seal the kernel boundary at compile time).

1.6 Timeline

  • Phase-0: 1–2 weeks. Full system: ~28 weeks total (§Appendix B).
  • Prerequisites: lambda calculus; simple types + rank-1 polymorphism; natural deduction; FOL + HOL; unification (FO, Miller patterns); resolution; de Bruijn indices.

3. Architectural Overview

One Cargo workspace of seven crates split by a single load-bearing line: the TRUST BOUNDARY. Exactly one crate — tp-kernel — is the TCB. Everything above the line is UNTRUSTED.

    proof script (.thm) / REPL  ──  prove CLI (prove · check · repl · bench)
                         |  parse
                         v
    tp-parse : Parser -> Term/Type/script · notation/fixity · PrettyPrinter · ParseError
                         |  parsed Terms + tactic scripts
                         v
    tp-tactic : Goal · GoalState · Tactic + Justification
        tacticals THEN/ORELSE/REPEAT/TRY · intro · apply · assumption · exact
                         |  uses derived rules          | builds Thm via Justification(Vec<Thm>)
                         v                              v
    tp-logic : HOL-lite constants = ==> /\ \/ ~ T F ! ? choice + derived intro/elim
        ^  defined via primitives (conservative)        |
        |                                               v
    tp-auto : Unify (unify_fo + unify_pattern/Miller) · ResolutionProver · CongruenceClosure · LinearArith
        |  every result = a sequence of primitive-rule calls -> a Thm
        v
    ====================== TRUST BOUNDARY — everything below is the TCB ======================
    tp-kernel : Term (de Bruijn) · Type · Thm (ABSTRACT, private field) · Sequent · type_of
        primitive rules:  refl · trans · mk_comb · abs · beta · assume · eq_mp · deduct_antisym
                          · inst · inst_type · new_basic_definition · new_basic_type_definition
    Trust:   ONLY tp-kernel trusted. Untrusted code obtains Thm solely via primitive rules.
    Input:   proof script (.thm) — may crash/loop; cannot derive a false Thm.
    Concurrency: single-threaded REPL/checker.  Persistence: none at runtime; Proofs serializable.

Central claim. Any value of type Thm is, by construction, a sequent derivable in HOL-lite. Bugs in tp-tactic/tp-auto/tp-parse degrade completeness (proof attempt fails) but never soundness (wrong theorem accepted). This is the LCF discipline, enforced by Rust's module privacy.

4. System Constraints

Overriding constraint: SOUNDNESS. No input may yield a false Thm. Every other target is subordinate.

Dimension Target Rationale / failure mode
TCB size (tp-kernel LOC) < 1500 LOC (target ~800) Soundness ∝ 1/kernel-size; HOL Light ≈ 500 LOC reference.
tp-kernel deps std only; zero 3rd-party crates Each dep widens the TCB.
MAX_TERM_DEPTH 4096 (parser + kernel constructors reject beyond) Deep nesting → stack overflow / quadratic type_of.
MAX_PROOF_NODES 2²⁶ per proof OOM/DoS bound on proof-term recording.
Max sequent hyps soft 4096 DoS bound on Sequent.hyps set.
Primitive-rule throughput ≥ 2 × 10⁶ rule-apps/sec single core Tactic replay + resolution refutation replay cost.
Proof-check time ≤ 5 s for reference library (~500 lemmas) via recheck_proof de Bruijn criterion must be cheap to be credible.
Parse + typecheck ≥ 10⁵ terms/sec; ≥ 5 MB/s script Interactive REPL latency.
type_of total, deterministic, O(size·types) Every rule re-runs it; must not diverge.
Unification unify_fo linear (union-find); unify_pattern decidable+unitary (Miller) Hot path shared with apply/rewrite/resolution.
Resolution budget max_inferences = 10⁶ default + timeout = 30 s default Exhaustion → prove_fol → None; never unsound.
Stack iterative or depth-capped; no unbounded recursion on attacker input Avoid stack-overflow on deep terms.
Startup zero global init; no lazy statics, no global mutable theorem store in kernel Determinism + reproducibility.

Resource / DoS: all size/depth caps enforced at parse-time and re-enforced in kernel constructors (defense in depth). Proof-search resources capped; breach → clean abandonment, TacticError/None, never a partial Thm.

6. Design Principles

Fourteen principles (P1…P14). Each: rule → tradeoff → operational implication → failure-if-violated. Referenced throughout by P#.

P1 — Soundness is the only invariant that matters. Rule: no reachable path may produce a Thm whose Sequent is not derivable in HOL-lite. Tradeoff: accept slower proof search, uglier APIs, more Result plumbing. Operational: soundness bugs are P0; all other classes ranked below. Violated → |- F makes every goal provable via eq_mp/inst.

P2 — The kernel is the TCB — keep it tiny and audited. Rule: tp-kernel is the entire TCB. Budget: ≤ ~800 LOC; every line hand-audited. Tradeoff: convenience ops banished to tp-term/tp-logic. Operational: PRs touching tp-kernel require explicit soundness review; kernel LOC counter runs in CI. Violated → TCB bloat hides typing holes; auditability collapses.

P3 — Thm is abstract — constructor private. Rule: pub struct Thm(Sequent) with field private to tp-kernel. Only the ten rules + new_basic_definition/new_basic_type_definition construct it. Tradeoff: untrusted crates read Thm only through dest_thm/accessors. Violated → any untrusted crate writes Thm(Sequent{..}) and forges |- F.

P4 — Tactics and automation are untrusted — a bug FAILS, never forges. Rule: tp-tactic/tp-auto/tp-parse are UNTRUSTED. A logic error → prove() returns Err(TacticError), never a Thm for an underivable sequent. Operational: prove(goal, tac) checks the final Thm.concl α-equals goal; mismatch → TacticError. Violated → automation bugs become soundness bugs.

P5 — Definitions are conservative extensions. Rule: new_basic_definition(c := t) admits only: c fresh, t closed, no type variables on RHS absent from c's type. Type def requires proven-nonempty subset. Violated → unconstrained definition introduces inconsistency permanently.

P6 — The kernel is total and deterministic. Rule: type_of and all ten rules are total (no panic!, no unwrap!, no infinite loop on well-formed finite input), deterministic, and fail only via Result<_, KernelError>. Operational: #![deny(clippy::unwrap_used, clippy::panic)] on tp-kernel; fuzz (§25) targets totality. Violated → kernel panic on adversarial input = DoS; nondeterminism breaks proof-term replay.

P7 — de Bruijn indices make alpha-equivalence syntactic. Rule: bound variables are Bound(u32) de Bruijn indices; free vars named Var(Name,Type) (locally-nameless). Two terms alpha-equal iff structurally ==. Substitution is capture-avoiding by index shifting. Tradeoff: index arithmetic is fiddly — localized to tp-kernel/tp-term and exhaustively tested. Violated → named-variable kernels need explicit capture-avoidance; missed rename forges a Thm.

P8 — Proofs are checkable — the de Bruijn criterion. Rule: every Thm derives a proof term; recheck_proof re-runs it through tp-kernel independently. Trust reduces to the small checker, not the producer. Tradeoff: optional proof-term recording costs memory; off by default. Violated → subtle kernel-API misuse in automation that happened to typecheck goes undetected.

P9 — Derived rules over kernel bloat. Rule: new inference power added as derived rules (untrusted functions composing primitives) — never by adding a primitive rule. Ten primitives + two definition rules are frozen. Tradeoff: some derived rules slower than hypothetical native primitives — accepted. Violated → every new primitive enlarges and re-opens the audited TCB.

P10 — Resource limits cause failure, never unsoundness. Rule: proof search bounded by step/time/clause limits. Hitting a limit returns None/TacticError — incomplete, never wrong. Operational: all limits explicit config (--max-clauses, --timeout). Violated → a timeout causing a partial proof to be accepted converts resource knob into soundness knob.

P11 — Parse and pretty-print round-trip. Rule: parse(pretty_print(x)) α-equals x for every well-formed term. Single notation/fixity table. Operational: property test (Phase 6). Violated → printer silently changes meaning of a displayed theorem.

P12 — Automation produces proofs, not verdicts. Rule: tp-auto never returns a bare boolean. prove_fol returns Option<Proof> — a kernel-checkable rule sequence. Decision procedures emit certificates the kernel re-derives. Tradeoff: building a checkable proof from a resolution refutation is strictly more work than yes/no — accepted. Violated → a yes/no oracle makes automation bugs soundness bugs.

P13 — One trust boundary, crossed only by Thm. Rule: the sole value crossing from untrusted into "established fact" is a Thm. Untrusted code hands the kernel Terms/Types as requests; kernel hands back Thms as guarantees. Violated → a second trust-bearing type creates a backdoor around Thm's abstraction.

P14 — Errors are typed, explicit, and never silent. Rule: kernel failures use KernelError {TypeMismatch, NotEquation, FreeVarEscape, IllTyped, BadDefinition}; tactics use TacticError; CLI uses CliError. No failure swallowed or defaulted. Violated → a swallowed TypeMismatch in eq_mp lets a mismatched Thm through; silent error handling is how P6 totality degrades into P1 unsoundness.

8. Domain Model — Logic, Terms, Inference Rules

The TCB. All types/rules below live in tp-kernel (TRUSTED) unless tagged otherwise.

8.1 Term + Type grammar (EBNF)

(* tp-kernel::Type — simple types + rank-1 polymorphism *)
Type = Tyvar , Name
     | Tyapp , Name , "[" , [ Type { "," Type } ] , "]" ;

(* tp-kernel::Term — de Bruijn for bound vars; named free Vars (locally nameless) *)
Term = Var   , Name , Type
     | Bound , u32
     | Const , Name , Type
     | Comb  , Term , Term
     | Abs   , Type , Term ;

Abs(ty, body) binds index 0 in body; each enclosing Abs shifts the reference up by one. Bound(k) with k ≥ (number of enclosing Abs) = dangling index = malformed (rejected by type_of/constructors). Alpha-equivalence is syntactic equality of Term.

8.5 Capture-avoiding substitution (de Bruijn worked example)

  • shift ↑ᵈ_c(t): add d to every Bound(k) with k ≥ c; c increments under each Abs.
  • subst t[j ↦ s]: replace Bound(j) by s (shifted to current depth).
  • beta of Comb(Abs(τ,body), arg): body[0 ↦ arg], then ↑⁻¹ free indices.

Reduce (\x. \y. x) a:

Comb( Abs(α, Abs(β, Bound(1))), Var("a",α) )
beta: substitute arg for Bound(0) in Abs(β, Bound(1)):
  - enter inner Abs → cutoff c=1; Bound(1) refers to x (depth 0 outside)
  - replace with arg shifted by 1 → Var("a",α)
  - drop consumed binder, shift remaining free indices down 1
result : Abs(β, Var("a",α))    i.e.  \y. a
thm    : ⊢ (\x. \y. x) a = (\y. a)

8.7 Worked proofs

Proof 1 — ⊢ p ==> p:

Goal       :  ⊢ p ==> p
intro()    :  subgoal  {p} ⊢ p
assumption :  close via assume(p) : p ⊢ p
justify    :  j1 = |th| DISCH(p, th); j2 = |_| assume(p)
prove()    :  j1(j2(∅)) → ⊢ p ==> p

Proof 2 — ⊢ !x. P x ==> ?y. P y:

intro()   → ⊢ P a ==> ?y. P y  (GEN, fresh a:α)
intro()   → {P a} ⊢ ?y. P y    (DISCH)
exists(a) → {P a} ⊢ P a        (EXISTS, witness a)
assumption → close via assume(P a)
justify (bottom-up): assume(P a) · EXISTS · DISCH · GEN

11.1 tp-kernel — Type, Term — [TRUSTED]

pub enum Type {
    Tyvar(Name),              // type variable, e.g. 'a
    Tyapp(Name, Vec<Type>),   // type constructor applied to args
}
pub enum Term {
    Var(Name, Type),          // FREE variable, carries its type
    Bound(u32),               // de Bruijn index: 0 = innermost Abs
    Const(Name, Type),        // declared/defined constant, instantiated monotype
    Comb(Box<Term>, Box<Term>), // application (f x)

25.8 Edge Cases

  • A TPTP problem whose expected SZS status is Unknown (undecided by the reference solver) — the conformance runner must not conflate this with a prove_fol failure.

Fields are appended only; no field removal within a MINOR series. Optional fields default to identity values. A reader from version N can skip unknown trailing fields from version N+k (k ≥ 1).

30. Testing & Verification Strategy

30.1 Unit Tests

Every module in every crate has co-located #[cfg(test)] tests. Invariant coverage requirement: each System Invariant I1–I11 (§7) must have at least one unit test directly named test_invariant_I<N>.

30.2 Integration Tests

tests/ directory at workspace root. Each phase (§12–§25) has one integration test file tests/phase_NN.rs that exercises the full stack from parse to Thm. Integration tests may not use unsafe.

30.3 Property-Based Tests

proptest used in outer crates only. Core properties:

  • ∀ t: Term, alpha_norm(alpha_norm(t)) == alpha_norm(t) (idempotent normalisation).
  • ∀ t: Term, type_of(t) == type_of(alpha_norm(t)) (type invariant across α).
  • ∀ rule r, ∀ valid premises, r(premises).is_ok() (no panic, only Result::Err).
  • Round-trip: ∀ t, parse(print(t)) == Ok(t).

Ties to I3 (de Bruijn correctness), I5 (term-size bound), I9 (no panic).

30.4 Differential Testing

tp-kernel rule outputs compared against HOL Light (OCaml) checkpoint data for 500+ pre-generated problems. Differential runner in tests/differential/: reads HOL Light output from fixtures/hol_light_oracle/, applies same derivation in tp-kernel, compares Thm conclusions structurally. Ties to I1 (soundness) and I2 (completeness of primitives).

30.5 Fuzzing

30.6 Chaos / Fault Injection

tp-tactic tests include a FaultInjector wrapper that randomly returns Err(Budget) to verify tactic combinators handle failure gracefully. No kernel fault injection (kernel is pure; failures are deterministic on input).

30.7 Deterministic Replay

Every proof derivation is deterministic given the same kernel and term input (no randomness in tp-kernel). Replay tests: record tactic trace as JSON, replay from trace, assert identical Thm sequence.

48-hour soak: 10⁶ random TPTP problems in a loop; monitor RSS, CPU, and error rate. Acceptance: zero OOM, zero panics, error rate < 0.01%.

HOL Light is the direct ancestor of prove's type theory and the oracle for differential testing (§30.4, §35). Its ≈400-line kernel is the gold standard for minimalism; prove is larger due to Rust verbosity but targets the same trust model.

Coq / Rocq uses the Calculus of Inductive Constructions, which subsumes HOL but at the cost of a much larger trusted kernel and a complex universe hierarchy. prove deliberately chose simple type theory to keep the kernel auditable (ADR-02); dependent types are deferred to §39.

Lean 4 achieves high performance via a compiled IR and incremental elaboration. Its kernel is larger than HOL Light but well-engineered. prove borrows Lean 4's de Bruijn representation strategy but does not target the dependent-type tier.

Isabelle/HOL layers a powerful outer logic and Sledgehammer oracle-call mechanism over an HOL kernel. prove's tp-auto and tp-logic are structurally analogous to Isabelle's outer reasoner, but without the Sledgehammer call-out to external ATPs (deferred to §39 SMT oracle entry).

   M4: 10⁵ terms/s; average term token length ≈ 20 chars
   Input bandwidth consumed: 10⁵ × 20 = 2 MB/s  →  well within stdio/pipe throughput.

4. Conformance suite runtime
   50 TPTP problems; average proof length 200 steps:
   50 × 200 = 10⁴ steps total; at M1: 10⁴ / 2×10⁶ = 5 ms total kernel time.
   Dominated by parse + tactic overhead; full suite < 10 s.

5. Proof file size
   10⁴-step proof; each step serialised as rule-id (1 B) + 2 term references (8 B each):
   10⁴ × 17 B ≈ 170 KB per proof file  →  fits in L2 cache for recheck.

6. Fuzz corpus storage
   60 s × 3 targets × 10⁴ inputs/s (libfuzzer typical) = 1.8×10⁶ inputs.
   Average minimised input: 200 B  →  360 MB corpus.  Trimmed with `cargo-fuzz cmin` to < 10 MB.

38. Alternative Architectures (Roads Not Taken)

Alt-1: Sequent Calculus Core Instead of Natural Deduction

┌──────────────────────────────────┐
│  Sequent: Γ ⊢ Δ (multi-conclusion)│
│  Rules: Cut, Axiom, ⊗L, ⊗R, ...  │
│  Proof search: backward chaining  │
└──────────────────────────────────┘

Regime where it wins: automated first-order reasoning; cut-elimination gives completeness; proof-search-oriented systems (LK style) avoid the asymmetry of natural deduction.

Real system embodying it: LKS (Liang & Miller), Twelf (linear logic), Coq's Tauto.

Why rejected: HOL Light and its successors (the differential oracle, §35) use natural deduction; adopting sequent calculus would forfeit the HOL Light oracle and make differential testing harder. Also, multi-conclusion sequents complicate the simple-type-theory kernel.

Alt-2: Global Term Hash-Consing Table Instead of Arena

┌──────────────────────────────────┐
│  HashMap<TermShape, TermId>       │
│  All equal terms share one node  │
│  Structural sharing automatic    │
└──────────────────────────────────┘

Regime where it wins: developments with massive term duplication (large shared subexpressions); reduces memory and speeds α-equality checks to pointer comparison.

Real system embodying it: Lean 4 (expression hash-consing), HOL4.

Why rejected: Hash-consing requires a global mutable table — introducing shared mutable state into the kernel, complicating unsafe-freedom guarantees. The arena model (ADR-15) trades space for simplicity. At ≤10⁷ nodes the arena is adequate.

Alt-3: Proof-Carrying Code with External Verifier

┌─────────────────┐     proof certificate     ┌──────────────┐
│  Proof Search   │ ───────────────────────── │  Tiny Checker│
│  (untrusted)    │                            │  (Metamath-  │
│                 │                            │   style)     │
└─────────────────┘                            └──────────────┘

Regime where it wins: when the search engine is large and complex; external checker is minimal and formally verified (e.g., CakeML-verified Candle).

Real system embodying it: Metamath + metamath-lamp; Candle (CakeML HOL Light port).

Why rejected: The LCF discipline already narrows TCB to tp-kernel; externalising the checker adds a second trusted artifact and an IPC boundary. The recheck_proof approach (§25) achieves the same goal without process separation.

Alt-4: Dependent Type Theory Kernel (CIC)

┌──────────────────────────────────────────────┐
│  Universes: Prop, Set, Type₀, Type₁, ...     │
│  Π-types, inductive families, eliminators    │
│  Definitional equality with reduction rules  │
└──────────────────────────────────────────────┘

Regime where it wins: when proofs and programs must be unified; certified program extraction; universe-polymorphic libraries.

Real system embodying it: Coq/Rocq, Lean 4, Agda.

Why rejected: CIC's kernel is an order of magnitude larger than HOL; its type-checking algorithm is undecidable without universe constraints; definitional equality makes the checker substantially more complex. Simple type theory (HOL) is sufficient for the target use case and auditable in ≤1500 LOC. Deferred to §39.

40. Glossary

Term Definition
α-equivalence Structural equality of terms up to renaming of bound variables; with de Bruijn indices, this is literal structural equality.
ADR Architecture Decision Record — a structured rationale for a load-bearing design choice; 25 ADRs in §9.
Arena allocator A memory region from which term nodes are bump-allocated; freed all at once when the proof context is dropped.
Assumption set The set of Term hypotheses under which a Thm holds; part of the Thm value in tp-kernel.
Budget The per-proof cap on rule applications and wall-clock time (§4) enforced by tp-tactic.
CC Congruence Closure — a decision procedure for ground equalities, implemented in tp-auto (§24).
CIC Calculus of Inductive Constructions — the dependent type theory underlying Coq/Rocq; not used by prove.
de Bruijn index A natural number representing a bound variable by its binding depth; eliminates name-capture in substitution.
de Bruijn shift The renumbering of free indices in a term when it is placed under an additional binder.
Definitional mechanism A rule that extends the global signature without changing provability; new_constant and new_type_op in §16.
Elaboration The process of filling in implicit arguments and type information in surface syntax before type-checking; in tp-parse.
Flex-flex pair A HOU unification constraint between two terms both headed by metavariables; inherently undecidable without bounds.
Flex-rigid pair A HOU constraint where one side is headed by a metavariable and the other by a constant; solvable by projection or imitation.
HOU Higher-Order Unification — unification in a simply-typed λ-calculus; semi-decidable (Huet 1975).
HOL Higher-Order Logic — a classical logic built on simply-typed λ-calculus; the logic of prove.
Inference rule A function in tp-kernel that takes Thm values (and possibly Term / Type values) and produces a new Thm.
LCF discipline The design pattern (Edinburgh LCF, 1979) in which Thm is an abstract type whose only constructor is the kernel; guarantees soundness by construction.
LinArith Linear arithmetic decision procedure based on Farkas' lemma / Omega test; in tp-auto §24.
MSRV Minimum Supported Rust Version — 1.78 for this project (§4).
Metavariable A unification variable in tp-auto; existential, not part of tp-kernel's term language.
Occurs check The test that a metavariable does not appear in its own candidate solution; required for well-founded unification.
Phase gate A mandatory benchmark or test threshold that blocks progression to the next development phase (§32).
Primitive rule One of the 10 inference rules whose implementation lives entirely within tp-kernel; the only way to construct Thm values.
recheck_proof The function in tp-kernel that re-derives a Thm from a Proof term without trusting the tactic that produced it.
Resolution A refutation-complete proof procedure for first-order logic (Robinson 1965); implemented in tp-auto §23.
SBOM Software Bill of Materials — a machine-readable inventory of all dependencies; generated per release (§31.3).
SLO Service Level Objective — a quantified target for system behaviour; four SLOs in §28.5.
Sequent A judgement of the form Γ ⊢ t : τ (type) or Γ ⊢ p (proof); the internal assertion of tp-kernel.
Signature The global mapping from constant names to their types; extended by definition mechanisms (§16).
Simply-typed λ-calculus The type theory underlying HOL; function types α → β, product types, and base types only; no dependent types.
Skolemisation Replacement of existentially quantified variables with fresh function symbols in first-order normalization; in tp-logic.
Tactic A function of type Goal → Result<(Vec<Goal>, Justification), Error> in tp-tactic; goal-directed proof construction.
TCB Trusted Computing Base — the code whose correctness must be assumed for soundness; tp-kernel only in this system.
Term An element of the HOL term language: variables, constants, applications, λ-abstractions (de Bruijn).
Thm The abstract type in tp-kernel representing a proved sequent; private constructor enforces LCF discipline.
TPTP Thousands of Problems for Theorem Provers — a standard benchmark library for ATP systems; used in conformance testing (§30.10).
Type operator A constructor for compound types, e.g., fun, bool, prod; introduced by new_type_op.
Universe A hierarchy of type sorts in dependent type theories (Coq, Lean 4); not present in HOL's simple type theory.
