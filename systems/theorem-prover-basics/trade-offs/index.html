Decisions (§9) · 25 ADRs

ADR-01

Implementation language

Chosen

Rust, edition 2021, MSRV 1.78, std

Rejected

OCaml/SML; C/C++; Python/Lisp

When the rejected choice is right

OCaml/SML win when plugging into an existing ML proof assistant ecosystem (HOL4, Isabelle); C wins for embedding in a bare-metal OS kernel verifier with no runtime

Why: Enums + exhaustive match model Term/Type/Thm; module privacy hides Thm ctor (LCF discipline at compile time); no GC on de-Bruijn subst hot path; #![forbid(unsafe_code)]

ADR-02

Code structure

Chosen

Cargo workspace, 7 members tp-kernel … tp-cli

Rejected

Single crate; monorepo of binaries

When the rejected choice is right

Single crate wins for small educational provers where audit scope is the whole file (< 500 LOC), no need for separate trust granularity

Why: Crate boundary = trust boundary; tp-kernel module privacy on Thm field is unforgeable across crates

ADR-03

Foundational logic

Chosen

HOL-lite (classical HOL)

Rejected

FOL natural deduction; CIC / dependent types

When the rejected choice is right

CIC wins when the project requires dependent types, proof-relevant programming, or extraction to certified compilers (CompCert style)

Why: HOL = simple types + rank-1 polymorphism: expressive, decidable typing, tiny kernel; FOL too weak; CIC kernel is huge

ADR-04

Kernel discipline

Chosen

Abstract Thm type, ctor private, obtained ONLY via rules

Rejected

Public Thm struct + runtime checker; capability tokens

When the rejected choice is right

Runtime checker wins for a prover running in a dynamic language (Lisp/Python) or for a distributed verifier where Thms cross process boundaries

Why: LCF correct-by-construction: any Thm = derivable theorem; reduces trust to kernel audit; Rust privacy gives guarantee statically

ADR-05

Term representation

Chosen

de Bruijn indices (Bound(u32)), named free Var, binder-type Abs

Rejected

Named bound vars; locally-nameless with both named

When the rejected choice is right

Named-variable representation wins when term readability in debugging is critical and alpha-renaming bugs are tolerable (small research provers, educators)

Why: de Bruijn makes alpha-equivalence syntactic; substitution capture-avoiding by index shift; no name-capture bugs by construction

ADR-06

Type representation

Chosen

`Type = Tyvar(Name)

Rejected

Tyapp(Name, Vec<Type>)`; simple types → rank-1 polymorphism

When the rejected choice is right

Rank-1: total deterministic type_of, no inference undecidability, tiny kernel

Why: Monomorphic only; System-F / higher-rank; dependent types

ADR-07

Primitive rule set

Chosen

HOL-Light ten: refl/trans/mk_comb/abs/beta/assume/eq_mp/deduct_antisym/inst/inst_type

Rejected

Larger axiomatic ND rule set; sequent-calculus rules

When the rejected choice is right

A larger sequent-calculus rule set wins when you want a direct Curry-Howard correspondence with natural-deduction proof terms (Gentzen LK/LJ systems)

Why: Ten rules + 2 definition principles is the smallest known complete basis for HOL (Harrison); minimal TCB

ADR-08

Definition mechanism

Chosen

new_basic_definition (c:=t, conservative) + new_basic_type_definition (nonempty subset)

Rejected

Asserting axioms directly; new_axiom for everything

When the rejected choice is right

Free axioms win for rapid prototyping / proof sketching where conservativity is not a requirement and you control the consistency argument externally

Why: Conservative extension: cannot introduce inconsistency; axioms can

ADR-09

Logic bootstrap

Chosen

Define =, then T, /, ==>, !, ?, ~, F, /, choice from primitives; intro/elim as derived rules in tp-logic

Rejected

Connectives as primitive constants + axioms

When the rejected choice is right

Primitive-connective approach wins when you need the kernel to reason about connectives directly (sequent-calculus–style proof search at the kernel level)

Why: Definitional HOL bootstrap keeps kernel ignorant of logic-specific constants; tp-logic replaceable

ADR-10

Tactic model

Chosen

Tactic: Goal -> (Vec<Goal>, Justification); backward proof

Rejected

Proof-term-first / Curry-Howard; forward-only

When the rejected choice is right

Proof-term-first / Curry-Howard wins for type-theoretic provers (Coq, Lean) where the proof term IS the program; forward-only wins for certifying compilers with fixed proof patterns

Why: LCF tactics are untrusted orchestration; a buggy tactic fails to produce a Thm, never forges one

ADR-11

Tacticals

Chosen

then/orelse/REPEAT/TRY as Rust higher-order functions

Rejected

Separate tactic DSL / Ltac-style metalanguage

When the rejected choice is right

A tactic metalanguage wins when users need a scriptable, introspectable proof language without recompiling (interactive use at scale, Isabelle Eisbach)

Why: Tacticals as plain Rust = no interpreter to trust, full host-language power

ADR-12

Unification

Chosen

unify_fo (FO) + unify_pattern (Miller HO-pattern)

Rejected

Full higher-order unification (Huet); FO only

When the rejected choice is right

Full HOU wins in λProlog-style systems where the logic itself requires higher-order unification at the meta-level; FO-only wins for pure first-order proof checking

Why: FO unitary/decidable; Miller patterns decidable + unitary, cover apply/rewrite/resolution; full HOU undecidable+infinitary

ADR-13

Automated FOL prover

Chosen

Ordered resolution (given-clause loop, KBO/LPO, subsumption) + connection tableau

Rejected

Superposition (full); paramodulation-only; tableau-only

When the rejected choice is right

Superposition wins for heavy equational reasoning (Vampire, E prover style); tableau alone wins for goal-directed interactive use with small search spaces

Why: Resolution is refutation-complete for FOL (Robinson); tableau complements for goal-directed search; output is kernel-checked

ADR-14

Decision procedures

Chosen

CongruenceClosure + LinearArith as proof-producing oracle tactics

Rejected

Trust as unchecked oracles; full SMT integration

When the rejected choice is right

Unchecked oracles win when DP results are used only for performance (memoizing known facts) and a separate proof checker is already present; full SMT integration wins when the prover is tightly coupled to an SMT solver as a service

Why: DPs run untrusted in tp-auto, emit kernel-checkable certificates; no blind oracle trust

ADR-15

Induction / datatypes

Chosen

Datatype defs via new_basic_type_definition + derived recursors; induct tactic

Rejected

Built-in inductive types in the kernel (Coq-style)

When the rejected choice is right

Kernel-native inductives win for a CIC/Lean-style system where inductive types are fundamental to the logic itself

Why: Keeps kernel datatype-agnostic; kernel-native inductives = large TCB

ADR-16

Proof terms

Chosen

Record proof term; recheck_proof re-validates independently

Rejected

No proof terms; LCF-only

When the rejected choice is right

No-proof-terms wins for a pure interactive session tool where memory is severely constrained and all checking is done in-session

Why: de Bruijn criterion: tiny independent checker re-runs proofs; serializable for offline third-party checking

ADR-17

Parser

Chosen

Hand-written lexer + Pratt parser in tp-parse; configurable fixity table

Rejected

Parser generator (LALRPOP/pest/yacc); combinator lib (nom)

When the rejected choice is right

Parser-generator wins for a fixed grammar with no user-extensible operators and team members unfamiliar with Pratt parsing

Why: Pratt cleanly handles user-extensible infix fixity/notation; no codegen; precise ParseError; fully untrusted

ADR-18

Pretty-printer

Chosen

PrettyPrinter sharing the notation table; round-trip parse ∘ print = id

Rejected

Debug-only printing; separate ad-hoc formatter

When the rejected choice is right

Separate printer wins when readability is the only goal and terms will never be fed back to the parser

Why: Single source of fixity ⇒ printed terms re-parse; round-trip is a Phase-6 conformance test

ADR-19

Kernel size budget

Chosen

tp-kernel ≤ ~1500 LOC (target ~800) tracked; CI fails on regression

Rejected

No budget; "keep it small" informally

When the rejected choice is right

A larger kernel budget wins when the logic is inherently more complex (CIC, linear types) and auditability relies on formal verification of the kernel itself

Why: TCB audit cost scales with size; enforced LOC ceiling keeps soundness reviewable

ADR-20

Dependency policy

Chosen

ZERO external deps in tp-kernel (std only); deps allowed in untrusted crates

Rejected

Helper crates in kernel (smallvec, etc.)

When the rejected choice is right

External kernel deps win when a formally-verified data structure library (e.g., a verified hash map) is available and itself is part of the trusted base

Why: Every kernel dep is TCB; zero-dep kernel = entire TCB auditable in one workspace

ADR-21

Fuzzing

Chosen

cargo-fuzz "cannot-forge-Thm" harnesses; assert no ill-typed Sequent or false theorem

Rejected

Hand-written negative tests only

When the rejected choice is right

Hand-written tests alone win for extremely simple kernels (< 100 LOC) where coverage is trivially complete by inspection

Why: Fuzzing the untrusted boundary is the empirical complement to the static LCF guarantee

ADR-22

Differential oracle

Chosen

Differential test against HOL Light on a shared lemma set

Rejected

No external cross-check; self-consistency only

When the rejected choice is right

Self-consistency wins when the prover implements a different logic than any existing system, making differential testing inapplicable

Why: HOL Light is the reference kernel; agreement raises confidence in tp-logic derived rules

ADR-23

Benchmarking

Chosen

criterion micro-benches + TPTP-subset macro-bench; targets: ≥1e6 rule-apps/sec

Rejected

No benches; wall-clock only

When the rejected choice is right

Wall-clock only wins for research tools where throughput is not a design goal and correctness is the sole concern

Why: Quantified perf gates on substitution/rule hot path and prove_fol saturation; regression-tracked in CI

ADR-24

CI

Chosen

GitHub Actions: build + clippy -D warnings + test + fuzz smoke + kernel-LOC gate + bench-regression; pinned MSRV 1.78

Rejected

Ad-hoc local testing

When the rejected choice is right

Ad-hoc testing wins for single-developer research code where CI overhead exceeds the cost of occasional bugs

Why: Soundness-critical project needs every gate (esp. LOC + fuzz) enforced per-PR

Licensing

Chosen

MIT OR Apache-2.0 (dual)

Rejected

GPL; single license

When the rejected choice is right

GPL wins when the project must prevent proprietary forks; single-license wins for simplicity in jurisdictions with complex dual-license interpretation

Roads not taken (§38)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt-1: Sequent Calculus Core Instead of Natural Deduction

┌──────────────────────────────────┐
│  Sequent: Γ ⊢ Δ (multi-conclusion)│
│  Rules: Cut, Axiom, ⊗L, ⊗R, ...  │
│  Proof search: backward chaining  │
└──────────────────────────────────┘

Regime where it wins: automated first-order reasoning; cut-elimination gives completeness; proof-search-oriented systems (LK style) avoid the asymmetry of natural deduction.

Real system embodying it: LKS (Liang & Miller), Twelf (linear logic), Coq's Tauto.

Why rejected: HOL Light and its successors (the differential oracle, §35) use natural deduction; adopting sequent calculus would forfeit the HOL Light oracle and make differential testing harder. Also, multi-conclusion sequents complicate the simple-type-theory kernel.

Alt-2: Global Term Hash-Consing Table Instead of Arena

┌──────────────────────────────────┐
│  HashMap<TermShape, TermId>       │
│  All equal terms share one node  │
│  Structural sharing automatic    │
└──────────────────────────────────┘

Regime where it wins: developments with massive term duplication (large shared subexpressions); reduces memory and speeds α-equality checks to pointer comparison.

Real system embodying it: Lean 4 (expression hash-consing), HOL4.

Why rejected: Hash-consing requires a global mutable table — introducing shared mutable state into the kernel, complicating unsafe-freedom guarantees. The arena model (ADR-15) trades space for simplicity. At ≤10⁷ nodes the arena is adequate.

Alt-3: Proof-Carrying Code with External Verifier

┌─────────────────┐     proof certificate     ┌──────────────┐
│  Proof Search   │ ───────────────────────── │  Tiny Checker│
│  (untrusted)    │                            │  (Metamath-  │
│                 │                            │   style)     │
└─────────────────┘                            └──────────────┘

Regime where it wins: when the search engine is large and complex; external checker is minimal and formally verified (e.g., CakeML-verified Candle).

Real system embodying it: Metamath + metamath-lamp; Candle (CakeML HOL Light port).

Why rejected: The LCF discipline already narrows TCB to tp-kernel; externalising the checker adds a second trusted artifact and an IPC boundary. The recheck_proof approach (§25) achieves the same goal without process separation.

Alt-4: Dependent Type Theory Kernel (CIC)

┌──────────────────────────────────────────────┐
│  Universes: Prop, Set, Type₀, Type₁, ...     │
│  Π-types, inductive families, eliminators    │
│  Definitional equality with reduction rules  │
└──────────────────────────────────────────────┘

Regime where it wins: when proofs and programs must be unified; certified program extraction; universe-polymorphic libraries.

Real system embodying it: Coq/Rocq, Lean 4, Agda.

Why rejected: CIC's kernel is an order of magnitude larger than HOL; its type-checking algorithm is undecidable without universe constraints; definitional equality makes the checker substantially more complex. Simple type theory (HOL) is sufficient for the target use case and auditable in ≤1500 LOC. Deferred to §39.
