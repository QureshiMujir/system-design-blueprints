✅ Phase 0 — Skeleton, governance, and the round-trip smoke test (Week 1) §12

Objectives

Make the next phases land cleanly: clone → make bootstrap → make build → make test all exit 0. A smoke test inserts 1,000 strings into bloom::Classic sized for n=10_000, fpr=0.01, asserts each is present (I1), asserts ≤1.5% of 9,000 unrelated strings are present (I2 band), and serializes + deserializes back to bit-identical bytes (I4, I13).

Deliverable

Repository at production-scaffold bar; passing smoke test; ADR-01/02/03/11/12/13/14/16 written and filed under docs/adr/.

Acceptance

make build and make test return exit code 0 on a clean clone with no manual steps beyond make bootstrap; the smoke test (1,000 dict words + 9,000 unrelated words) passes with fpr ≤ 1.5% (I2 band); serialize→deserialize round-trip is bit-identical (I4/I13); all eight named ADRs exist under docs/adr/.

Fixtures
Fixture Purpose Expected
1,000 dict words inserted I1 all report present
9,000 unrelated words I2 band ≤1.5% report present
serialize→deserialize I4/I13 bit-identical bytes
make test CI gate exit 0, one passing test
Pitfalls

Bit array is little-endian by convention — document it or a big-endian reader produces silently incompatible files. make bootstrap installs nothing system-wide; it bootstraps a nix develop/direnv shell and prints the next step. PoC ships Vec<u64> word-level ops for clarity (ADR-22).

✅ Phase 1 — Hash primitive layer (Week 1) §13

Objectives

Ship the hash foundation: every downstream false-positive/error bound depends on it. Four hash families behind one trait (§11.1), plus the KM combinator (P3, ADR-03) and a SIMD batch path.

Deliverable

src/hash/*; the combinator; the SIMD batch path; ADR-02, ADR-03, ADR-23.

Acceptance

cargo test -p pdsr hash:: passes all four families against upstream SMHasher/wyhash/ SipHash vectors (100% match); the combinator proptest (residue coverage over power-of-two m) is green; benches/hash.rs runs and writes a committed baseline JSON.

Fixtures
Fixture Purpose Expected
SMHasher vectors (xxhash3, murmur3) reference parity match upstream
wyhash repo fixtures reference parity match upstream
SipHash paper test vectors keyed parity match
combinator over power-of-two m I3 coverage visits every residue when k≥m
Pitfalls

Use the 128-bit xxhash3 variant exclusively (high 64 = h1, low 64 = h2). wyhash seed quality matters: derive the pair (seed, seed ^ 0xa076_1d64_78bd_642f). The combinator's h2 must be non-zero — force the low bit on (always odd); sufficient for power-of-two m, and the mod m step still distributes uniformly for arbitrary m.

✅ Phase 2 — Classical and counting Bloom filter (Week 2) §14

Objectives

Ship the simplest sketch and the conformance ground truth for every later membership filter, plus the counting variant with delete.

Deliverable

src/bloom/{classic,counting,sizing}.rs; ADR-21.

Acceptance

conformance bloom.classic and bloom.counting buckets Pass (empirical fpr ≤ 1.5× documented at all four (n,f) fixture points); merge proptest (commutativity, identity) green; counting-Bloom saturation test confirms is_saturated()==true at counter MAX.

Fixtures
Fixture Purpose Expected
dict words + SMHasher corpus + edge cases (empty, null byte, 4 KiB) I1 all present
(n,f) ∈ {(1k,.1),(10k,.01),(100k,.001),(1M,.0001)} I2 band empirical fpr ≤ 1.5f
serialize/deserialize I4/I13 bit-identical
counting: insert×2, delete×1, contains delete semantics still present
counting: drive a slot to MAX I8 is_saturated() true
Pitfalls

Small n (n<100) gives k>30; cap k at 32 and document the fpr drift. The fpr() diagnostic must read the bit population, so a filter past design n reports a higher fpr — the right answer. Counting-Bloom delete is not the inverse of insert: insert-twice delete-once still reports present (P14, §8 state table).

✅ Phase 3 — Blocked Bloom filter (Week 2) §15

Objectives

Trade ~10% relative fpr for 2–3× throughput by keeping every probe in one 64-byte cache line (ADR-04). The recommended variant for cache admission and DB block filters.

Deliverable

src/bloom/blocked.rs; benches/bloom_blocked.rs with committed baseline.

Acceptance

conformance bloom.blocked Pass at the documented ~10%-inflated band; M1 (≥100M lookups/s) met on reference HW (§4); prefetch A/B shows the documented lift.

Fixtures
Fixture Purpose Expected
conformance corpus at blocked band I2 (blocked) empirical fpr ≤ 1.5× blocked target
(n_blocks,k_per_block) sweep throughput M1 ≥ 100M lookups/s
cold vs warm workload prefetch effect ~20% lift documented
Pitfalls

64-byte block is a hard requirement on x86_64/aarch64; gate the SIMD path with #[cfg(target_arch)], document POWER9/RISC-V line sizes (ADR-04 6th column). Base-hash low-bit avalanche must be uniform across blocks — xxhash3 has none, early Murmur variants do.

✅ Phase 4 — Scalable and partitioned Bloom (Week 3) §16

Objectives

Ship a Bloom that grows past its design n without losing the fpr target (scalable) and a partitioned reformulation that is computationally cleaner.

Deliverable

src/bloom/{scalable,partitioned}.rs.

Acceptance

conformance bloom.scalable and bloom.partitioned Pass; chain-length test confirms chain_length() == ⌈log_r(overload_factor)⌉ after 100× design-capacity overload; union fpr stays ≤ 1.5× target (I2).

Fixtures
Fixture Purpose Expected
insert 100× design capacity (scalable) growth law chain length = ⌈log_r(100×)⌉
union fpr after overload I2 ≤ 1.5× target
partitioned conformance I2 as classical
Pitfalls

Scalable lookup cost grows linearly with chain length — ship compact(). Partitioned per-partition saturation is uneven; the weakest partition dominates the fpr.

✅ Phase 5 — Cuckoo, vacuum, and quotient filters (Week 3–4) §17

Objectives

Ship three delete-capable membership filters that beat classical Bloom on space or speed at typical fpr: quotient (native delete + sort-merge), cuckoo (fingerprint + eviction), and vacuum (a smaller-fingerprint cuckoo variant).

Deliverable

src/quotient/quotient.rs; src/cuckoo/{cuckoo,vacuum}.rs.

Acceptance

conformance quotient Pass at ~10^-3 with 11-bit remainders across load 50/75/90%; conformance cuckoo.basic and cuckoo.vacuum Pass at load 0.95 (f≈0.0024 for cuckoo, ADR-05); delete semantics verified for all three (post-delete contains returns false); the Error::Full failure path leaves prior items queryable.

Fixtures
Fixture Purpose Expected
quotient load 50%/75%/90% sliding-window correctness fpr within band at all three
quotient insert, delete, contains delete semantics returns false after delete
two 1M quotient filters merge sort-merge O(2M); union correct
cuckoo/vacuum load 0.95 fpr band within documented band
cuckoo insert until Error::Full P6/§8 failure path subsequent inserts still fail; landed items queryable
cuckoo insert, delete, contains delete returns false
item whose fingerprint hashes to 0 I11 mapped to 1; no corruption
Pitfalls

The quotient sliding window during insert is the easy place to introduce a bug that works at low load and breaks above 75% — run conformance at 50/75/90%. Cuckoo: fp == 0 is the empty marker; map a real zero fingerprint to a fixed non-zero value (1) and document the slight fpr inflation (I11). A deterministic RNG breaks the eviction symmetry analysis — use a per-instance xorshift seeded from the salt. max_kicks=500 matches the paper; 50 produces premature Error::Full above 90% load (ADR-05).

Objectives

Ship static membership filters — built once from a finite set, queried many times, never modified — faster, smaller, and tighter-fpr than cuckoo.

Deliverable

src/xor/{xor8,xor16,binary_fuse}.rs; benches/xor.rs.

Acceptance

conformance xor.xor8/xor16/binary_fuse_8 Pass (fpr ≈ 0.0039 for xor8, ≈0.000015 for xor16, ≤1.5× band); construction-failure retry path succeeds on next seed with no partial filter ever returned; BinaryFuse8 shows fewer cache misses than Xor8 in the throughput benchmark.

Fixtures
Fixture Purpose Expected
1M set, xor8 fpr band ≈0.0039, ≤1.5× band
1M set, xor16 fpr band ≈0.000015, ≤1.5× band
seed that defeats peeling retry path succeeds on next seed; no partial filter
BinaryFuse8 vs Xor8 throughput fuse fewer cache misses
Pitfalls

The peeling DAG uses 3–5× the final filter size during construction — document the peak (§4) and offer streaming construction (Deferred). The fingerprint width and the mod choice interact; use the published constants verbatim and cite the line numbers.

✅ Phase 7 — Count-Min Sketch, conservative update, count-sketch, and AMS (Week 5) §19

Objectives

Ship frequency estimation two ways: Count-Min Sketch (d rows × w counters, min-across-rows estimate) with its conservative-update variant (default, ADR-07), and signed-counter count-sketch with its AMS F2-moment application.

Deliverable

src/cms/{classic,conservative,count_sketch,ams}.rs.

Acceptance

conformance cms.classic/cms.conservative Pass (top-100 estimate within eps·n on Zipfian α∈{0.7,1.0,1.2,1.5}, 1M items); CMS-CU estimate ≤ classical estimate on identical input; merge test green (CMS exact, CMS-CU within band); conformance cms.count_sketch Pass; cms.ams F2 estimate within 5% of exact on a 1M-item d=7,w=4096 stream.

Fixtures
Fixture Purpose Expected
Zipfian streams α∈{0.7,1.0,1.2,1.5}, 1M items (CMS) accuracy top-100 estimate within eps·n
disjoint streams merged vs combined (CMS) merge correctness CMS agrees exactly; CMS-CU within band
drive a counter to u32::MAX (CMS) I8 is_saturated() true
Zipfian streams (count-sketch) relative-error band median-of-rows within band
1M-item stream, d=7 w=4096 (AMS) accuracy F2 estimate within 5% of exact
stream with negative updates (count-sketch) signed correctness estimate tracks net frequency
Pitfalls

Row seeds must be independent — seeds[i] = seed ^ i is a known-bad antipattern; use the chained KDF and document it (ADR-23). Counter saturating_add at u32::MAX is the silent failure mode — expose is_saturated() (I8, P12). High variance for low-frequency items in count-sketch — expose variance_estimate() and recommend larger d. Sign hash must be independent of the column hash, or the estimator biases.

conformance hll.classic and hll.plus Pass (accuracy within 1.04/√(2^p) + floor across streams 10^3–10^7 at p∈{4,8,12,14,16,18}); n=1,10,100 fixtures confirm no small-range underestimate (I10); sparse→dense crossing is continuous; DataSketches parity (ADR-20) holds within each bound; M6/M7/M8 met.

Fixtures
Fixture Purpose Expected
