34. Mental Models & First Principles

  • MM1 — A sketch is lossy compression with a known error distribution, not a database. Predicts that every query has a bound, not an answer. Without it you treat estimate() as exact and ship a billing system that over-charges by the overestimate. Applied §19, §21, §32.
  • MM2 — The fpr is a function of load, not a constant. f ≈ (1−e^(−kn/m))^k rises super-linearly past design n. Predicts the ~4× fpr at 2× overload. Without it you trust the design fpr and silently degrade. Applied §14 (P14, I2).
  • MM3 — Hash independence is the load-bearing assumption. The d/k-fold confidence is a product of per-row independence; correlate the rows and the product collapses. Without it (e.g. seed^i) the empirical error blows past the bound while every unit test passes. Applied §13, §19 (P3, I3).
  • MM4 — Cache-line locality beats algorithmic constant factors at these sizes. A blocked Bloom touches one line; a classical Bloom touches k lines. Predicts the 2–3× throughput win for a ~10% fpr cost. Without it you optimise instruction count and miss the memory wall. Applied §15 (§4 latency budget).
  • MM5 — Static and streaming filters are different problems. A set known in advance can be peeled (xor: ~1.23 bytes/item at fpr 0.0039); a mutable filter cannot. Predicts xor wins on read-only sets, cuckoo/Bloom win when you must insert later. Without it you reach for Bloom when xor would halve the memory. Applied §18 (P13, I12).
  • MM6 — Saturation is a phase change, not a gradual drift. A counter at MAX stops counting; the filter's guarantee silently inverts (counting Bloom starts producing false negatives). Predicts a cliff, not a slope. Without it you watch averages and miss the cliff. Applied §19 (I8, P12).
  • MM7 — The on-disk format is a wire protocol, so treat every loaded byte as hostile. Predicts the deserializer's failure modes (overflow, over-allocation, garbage) before they happen. Without it a single flipped byte returns a confidently wrong answer. Applied §23, §26 (I5, I6, P11).
  • MM8 — Mergeability is an algebraic property of the sketch, not a feature you add. Bloom is a monoid under OR only with equal (m,k,seed); HLL under register-max; GK under nothing. Predicts exactly which sketches federate. Without it you ship a merge that is silently wrong. Applied §33, §22 (P5, I7).

5. Required Reading

You will not write a correct sketch without reading these. Read in this order; do not skip the foundational papers. Each entry names the §/Phase where its idea is applied.

Books

  • Gakhov, Probabilistic Data Structures and Algorithms for Big Data Applications (2019). Worked examples; the sanity check on edge cases — applied across every phase's N.5 fixtures.
  • Broder & Mitzenmacher, Network Applications of Bloom Filters: A Survey (2004). Engineering perspective the original paper omits — applied in §6 design principles and Phase 2 (§14).
  • Cormode et al., Synopses for Massive Data: Samples, Histograms, Wavelets, Sketches (2011, monograph). The unifying treatment of CMS/AMS/quantile sketches — applied Phases 7–10 (§19–§22).
  • Knuth, TAOCP Vol. 3 (sorting & searching, hashing chapters). Hash-table fundamentals behind quotient filters — applied Phase 5 (§17, quotient).
  • Drmota & Szpankowski, Analytic Combinatorics lecture notes (HLL analysis). The harmonic-mean estimator analysis — applied Phase 9 (§21).
  • Dean & Barroso, The Datacenter as a Computer (3rd ed). Tail-latency and memory-bandwidth framing — applied §4 constraints and Performance Engineering.

Papers

  • Bloom, 1970, Space/Time Trade-offs in Hash Coding with Allowable Errors. The fpr algebra — applied Phase 2 (§14).
  • Mitzenmacher, 2002, Compressed Bloom Filters. The bound f = (1 − e^(−kn/m))^k every later paper assumes — applied Phase 2 sizing (§14.2).
  • Kirsch and Mitzenmacher, 2006, Less Hashing, Same Performance. Double hashing at no fpr cost — applied Phase 1 (§13) and everywhere via the combinator.
  • Putze, Sanders, Singler, 2007, Cache-, Hash- and Space-Efficient Bloom Filters. The blocked Bloom — applied Phase 3 (§15).
  • Almeida et al., 2007, Scalable Bloom Filters. Applied Phase 4 (§16.1).
  • Fan et al., 2000, Summary Cache. Counting Bloom in practice; per-counter sizing — applied Phase 2 (§14.2, counting Bloom).
  • Bonomi et al., 2006, An Improved Construction for Counting Bloom Filters. d-left counting Bloom; quotient precursor — applied Phase 5 (§17).
  • Pagh, Pagh, Rao, 2005, An Optimal Bloom Filter Replacement. Quotient-filter foundations — applied Phase 5 (§17).
  • Fan, Andersen, Kaminsky, Mitzenmacher, 2014, Cuckoo Filter. Applied Phase 5 (§17).
  • Wang et al., 2019, Vacuum Filters. Applied Phase 5 (§17, vacuum).
  • Graf and Lemire, 2019, Xor Filters. Applied Phase 6 (§18).
  • Dietzfelbinger and Walzer, 2019, Constant-Time Retrieval with O(log m) Extra Bits. Binary-fuse foundations — applied Phase 6 (§18, binary fuse).
  • Lemire, 2022, Binary Fuse Filters. The static-membership format we ship — applied Phase 6 (§18).
  • Cormode and Muthukrishnan, 2005, The Count-Min Sketch and Its Applications. Applied Phase 7 (§19).
  • Estan and Varghese, 2002, New Directions in Traffic Measurement and Accounting. Conservative update — applied Phase 7 (§19.2, CMS-CU).
  • Charikar, Chen, Farach-Colton, 2002, Finding Frequent Items in Data Streams. Count-sketch — applied Phase 7 (§19).
  • Alon, Matias, Szegedy, 1996, The Space Complexity of Approximating the Frequency Moments. AMS / F2 — applied Phase 7 (§19, AMS).
  • Misra and Gries, 1982, Finding Repeated Elements. Applied Phase 8 (§20).
  • Karp, Shenker, Papadimitriou, 2003, A Simple Algorithm for Finding Frequent Elements. The production reformulation — applied Phase 8 (§20).
  • Flajolet, Fusy, Gandouet, Meunier, 2007, HyperLogLog. Applied Phase 9 (§21).
  • Heule, Nunkesser, Hall, 2013, HyperLogLog in Practice. HLL++ sparse, bias correction, thresholds — applied Phase 9 (§21, HLL++).
  • Dunning and Ertl, 2019, Computing Extremely Accurate Quantiles Using t-Digests. Applied Phase 10 (§22).
  • Karnin, Lang, Liberty, 2016, Optimal Quantile Approximation in Streams (KLL). Applied Phase 10 (§22, KLL).
  • Greenwald and Khanna, 2001, Space-Efficient Online Computation of Quantile Summaries. GK — applied Phase 10 (§22, GK).
  • Shrivastava et al., 2004, Medians and Beyond (q-digest). Applied Phase 10 (§22, q-digest).
  • Cormode, 2011, Sketching Streams Through the Net. Merge / federation story — applied §6 P5 and Deferred federation.

Reference implementations

  • Apache DataSketches (datasketches-cpp/java/python). Reference for HLL, t-digest, KLL behaviour at scale — applied to the cross-format parity fixtures, Phase 11 (§23) and conformance.
  • RedisBloom. Production Bloom / cuckoo / CMS / top-k module — applied as the API-shape reference in Comparative Architecture.
  • Google Guava BloomFilter. The widely-used JVM Bloom — applied as the sizing and serialization reference, Phase 2 (§14).
  • Twitter Algebird (algebird-core). Monoid/merge API choices — applied in §6 P5, Phase 7 (§19).
  • Stripe Veneur. Production t-digest / HLL pipeline — applied in Phase 10 (§22) and examples.
  • xxHash (github.com/Cyan4973/xxHash) and wyhash (github.com/wangyi-fudan/wyhash). Hash reference vectors — applied in Phase 1 (§13).

RFCs / standards

  • CRC-32C (Castagnoli), as used in iSCSI (RFC 3385) and SCTP (RFC 4960). The trailer polynomial — applied Phase 11 (§23.2) and ADR-11.
  • SipHash reference (Aumasson & Bernstein, 2012, with RFC-adjacent test vectors). Keyed-hash adversarial path — applied Phase 1 (§13.2).

The literature changes faster than this document. If a paper after 2026 supersedes one of these for our purposes, an ADR captures the change.

Glossary (§40) · 49 terms · site-wide glossary

fpr
false-positive rate; probability a membership filter reports contains(x)==true for an un-inserted x.
false negative
reporting contains==false for an inserted item; Bloom variants never do this (I1) except via counter saturation in counting Bloom (I8).
load factor
for cuckoo/quotient/xor filters, ratio of inserted items to total slots.
bits/item
total filter size in bits divided by inserted items; the space-efficiency metric.
k
number of hash functions / bit-probes per item in a Bloom filter.
m
Bloom bit-array length in bits.
MAX_KICKS
cuckoo eviction bound; evictions tried before declaring Error::Full.
MAX_TRIES
xor/fuse construction seed-retry bound (256, ADR-06).
eps, delta
CMS/count-sketch parameters: eps additive error relative to stream length, delta failure probability.
w, d
CMS table dimensions: w columns (width), d rows (depth).
conservative update
CMS-CU rule incrementing only the minimum cells (Estan-Varghese).
count-sketch
signed-counter frequency sketch using a sign hash; estimate is the median.
AMS
Alon-Matias-Szegedy F2 (second frequency moment) estimator.
heavy hitter
an item whose frequency exceeds a threshold phi of the stream.
Misra-Gries
bounded-counter heavy-hitter algorithm.
p
HLL precision; m = 2^p registers.
register
HLL slot storing a leading-zero count.
harmonic-mean estimator
HLL's cardinality formula over register values.
small-range correction
HLL adjustment preventing underestimation at low n (I10).
bias correction
HLL++ empirical correction tables (Heule 2013).
sparse / dense
HLL++ representations below / above a precision-dependent threshold.
cardinality
number of distinct items in a stream.
quantile
value below which a given fraction of the data falls.
rank
number of items ≤ a given value.
centroid
t-digest cluster of weighted samples.
K2
t-digest scale function k(q) = (delta/2π)·arcsin(2q−1).
KLL compactor
a KLL level performing random-coin halving when full.
q-digest
binary-tree quantile sketch over a value domain.
GK
Greenwald-Khanna quantile summary; not associatively mergeable.
fingerprint
cuckoo/xor/fuse per-item identifier (8–16 bits).
peeling
xor/fuse construction; topological sort assigning fingerprints to slots.
blocked Bloom
Putze 2007 variant confining all probes to one cache line.
scalable Bloom
Almeida 2007 chain of geometrically growing, tightening Blooms.
partitioned Bloom
Bloom with k disjoint bit partitions, one per hash.
quotient filter
Pagh 2005 hash-table filter with native delete and sort-merge.
cuckoo filter
Fan 2014 fingerprint filter with two candidate buckets and eviction.
vacuum filter
Wang 2019 cuckoo variant; smaller fingerprints, smarter eviction.
xor filter
Graf-Lemire 2019 static membership filter built by peeling.
binary fuse filter
Lemire 2022 segmented xor filter with better cache locality.
Kirsch-Mitzenmacher
double-hashing combinator h_i = h1 + i·h2.
avalanche
degree to which a hash spreads input bit changes across the output.
CRC32C
Castagnoli CRC32; the on-disk trailer (ADR-11).
frame
the on-disk envelope: magic, version, kind, flags, body_len, body, CRC.
magic
the 4-byte PDSR file signature.
Mergeable
the trait implemented exactly where the sketch algebra admits a merge.
monoid
an algebra with an associative combine and an identity; the merge abstraction.
W-TinyLFU
Window TinyLFU cache admission policy using a Bloom front-door.
SSTable
sorted-string-table; LSM-tree on-disk segment with per-block Bloom filters.
PhaseDeferred
the anchor marking work recorded in the Deferred Features Register.
