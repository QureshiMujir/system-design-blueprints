ADR-01

Core language

Chosen

Rejected

C++, Zig

When the rejected choice is right

C++ if you must link into an existing C++ monorepo with no Rust toolchain

ADR-02

Default hash

Chosen

xxhash3 (128-bit)

Rejected

wyhash, murmur3, SipHash, Blake3

When the rejected choice is right

wyhash for ≤8-byte keys; SipHash under adversarial inputs

Why: Fastest non-crypto with documented avalanche

ADR-03

Rejected

When the rejected choice is right

38. Alternative Architectures (Roads Not Taken)

A1 — Server-side sketch service (the RedisBloom shape).

Show the original text diagram
[clients] --network--> [sketch server: owns sketches + persistence]

Wins when sketches must be shared across many processes/languages over the network and persisted with an existing datastore. Embodied by RedisBloom. Rejected: pdsr is a library with FD budget 0 (§4); a network hop would dominate the 10 ns blocked-Bloom lookup and defeat the entire latency story (§36 #4). The federation layer is the controlled, Deferred concession to this regime.

A2 — Byte-compatible drop-in for Apache DataSketches.

Show the original text diagram
[DataSketches .bin] <--same wire format--> [pdsr]

Wins when the goal is to replace DataSketches in a pipeline without re-serializing existing sketches. Embodied by Apache DataSketches' portable format. Rejected (ADR-20): matching their byte layout would couple every pdsr sketch to their evolving format and forbid the CRC32C trailer and KM-seed design we want; we assert answer-parity instead and own our format (P4).

A3 — Generic monoid framework over a Sketch trait (the Algebird shape).

trait Monoid { fn zero(); fn combine(a,b); }  // every sketch is just a Monoid instance

Wins for compositional stream-processing where sketches flow through generic aggregate/reduce combinators (Spark/Scalding). Embodied by Twitter Algebird. Rejected for the core: forcing every sketch into one monoid trait erases the per-algebra preconditions (Bloom needs equal (m,k,seed); GK has no monoid) that pdsr makes explicit and type-checked (P5, I7). We expose Mergeable per-type instead, keeping the typed mismatch error.

A4 — Single-family library (the Guava shape).

[one Bloom implementation, zero configuration]

Wins when an application needs exactly one well-tested Bloom filter and nothing else. Embodied by Google Guava BloomFilter. Rejected: the project's pedagogical and portfolio goal (§2) is to own the full surface — cuckoo, xor, CMS, HLL, quantiles — which a single-family library cannot teach.
