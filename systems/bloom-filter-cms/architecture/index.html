Bindings. PyO3, WASM, and C-ABI shims. They own marshalling and ownership semantics only; the algorithms live exactly once in core. Java is a JNI shim around the C-ABI, Deferred.

Public Rust API. The user-facing surface: one module per sketch family, each concrete sketch a type that implements at least one of the four sketch traits and (where the algebra holds) Mergeable.

Sketch traits. ApproxMembership, FrequencyEstimator, Cardinality, Quantile, Mergeable. Every concrete sketch implements at least one. Benchmarks and conformance code program against the traits, not the concrete types.

Serialization. Owned by the core, not by each sketch. Sketches expose a single Serialize/Deserialize pair; the format carries magic + version + CRC32C trailer and is little-endian regardless of host. The on-disk bytes are stable across language runtimes.

Hash primitive layer. The only place that chooses a hash function. Sketches accept a Hasher type parameter so benchmarks and conformance can swap hashes without touching sketch code. The double-hashing combinator and SIMD batch path live here.

8. Domain Model / Protocol / Data Model

The domain object is a sketch: a fixed-size (or bounded-growth) summary of a stream of items, supporting a probabilistic query. The shared protocol is construct → mutate* → query* → (merge)* → serialize.

Worked example — classical Bloom round-trip. Construct Bloom::sized_for(n=10_000, f=0.01) → computes m = 95_851 bits, k = 7. Insert b"alice": hash to h: u128, derive 7 indices via KM, set those 7 bits. contains(b"alice") → all 7 bits set → true. contains(b"mallory") (never inserted) → true only if all 7 happen to collide (prob ≈ f). serialize() → PDSR | v=1 | kind=Bloom | flags | body_len | body(m,k,seed,items,hasher_kind,bits) | crc32c. from_bytes verifies CRC, reads fields, reconstructs a bit-identical filter (I4, I13).

State-transition table — counting Bloom slot (4-bit counter, saturating):

Current Op Next Note
0 insert 1 slot now occupied
c (0<c<15) insert c+1 normal
15 insert 15 saturated (I8); slot now permanently set
c (0<c≤15) delete c−1 unless saturated path was hit
15 delete 15 cannot un-saturate; false-negative risk documented
0 delete 0 underflow no-op

Malformed input handling. Empty item b"" is valid (hashes normally). A 4 KiB item is valid (single hash call). On the wire: a .pdsr file with bad magic → Error::BadMagic; unknown version → Error::UnsupportedVersion; body_len exceeding the file → Error::Truncated; body_len exceeding the memory cap → Error::TooLarge; CRC mismatch → Error::Corrupt (I5, I6). None of these allocate before validation.

Failure path. Cuckoo insert that cannot place a fingerprint after 500 kicks → Error::Full; the filter is left consistent (the in-flight fingerprint is held, not lost into a half-evicted bucket) and prior items remain queryable (§17.5). Xor construction that cannot peel after 256 seeds → Error::ConstructionFailed; no partial filter is returned (P6, I12).
