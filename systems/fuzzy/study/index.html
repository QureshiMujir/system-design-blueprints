30. Mental Models & First Principles

  1. MM1 — A confident<T> value is a possible-worlds compressor, not a single fact. It predicts that any operation over it (comparison, join, aggregate) must define what happens across the implied distribution of worlds, not just the point value. Without it you write operators that silently assume c=1.0 everywhere. Applied in §8.4, §15.
  2. MM2 — Confidence is metadata about the writer's belief, not a property of the world. Predicts that two sources can disagree about the same v and both be "correctly" reporting their own confidence — which is exactly why the conflict log (§19) exists rather than a single overwritten cell. The bug class without it: treating disagreement as an error condition instead of data. Applied in §19, §20.
  3. MM3 — Propagation is a semiring combination, not an ad hoc formula. Predicts that MIN, PRODUCT, and BAYESIAN must each be associative/commutative to compose safely across multi-way joins (Green et al. 2007, §5). The bug class without it: a propagation mode that gives different answers depending on join order. Applied in §8.4, §15.6, §18.6.
  4. MM4 — Decay is a pure function of elapsed time, never a running mutation. Predicts that a crashed, resumed, or repeated sweep is always safe (idempotent). The bug class without it: confidence drifting further from truth with every re-sweep. Applied in §17.2, §17.6, §8.9.
  5. MM5 — An extension's ABI surface is someone else's implementation detail. Predicts that any internal (non-public) Postgres API used will eventually move; the only defense is an explicit inventory (§21.2) and a compatibility shim, never hoping the API stays put. The bug class without it: a working extension that silently stops building on the next Postgres minor. Applied in §9 ADR-01, §22 T2, §23 FM-1.
  6. MM6 — Attribution is what makes correction possible. Predicts that a system without a mandatory source on every write cannot ever build a feedback loop, because there is nothing to re-weight. The bug class without it: "confidence" that never improves no matter how many corrections arrive. Applied in §7 I2, §20.
  7. MM7 — Calibration and confidence are not the same number. Predicts that a model reporting c=0.9 is not necessarily right 90% of the time unless it has been calibrated (Niculescu-Mizil & Caruana 2005, §5) — Fuzzy stores the number faithfully but does not manufacture calibration. The bug class without it: treating confident<T> as a probability guarantee the database itself does not and cannot provide. Applied in §16.6, Glossary §36.
  8. MM8 — A background worker is a second failure domain, not a free lunch. Predicts that anything run in fuzzy_decay needs its own crash isolation, cancellation, and throttling story, independent of the backend's. The bug class without it: a decay bug that takes down user queries instead of just delaying a sweep. Applied in §17, I9, I11.

Required reading (§5)

Books

  • Petrov, A. — Database Internals (O'Reilly, 2019). Chapters 1–3 (storage engines), Ch. 7 (B-Trees). Extract: how a heap-organized row store lays out variable-length fields — needed for the confident<T> wire format (§8.1, §11.1). Applied in §11, Phase 0 (§12).
  • Gray, J. & Reuter, A. — Transaction Processing: Concepts and Techniques (Morgan Kaufmann, 1993). Ch. 3 (transaction models), Ch. 8 (locking). Extract: why the conflict log must be append-only inside the user transaction, not a side-effect. Applied in §19 (Phase 7), I6.
  • Kleppmann, M. — Designing Data-Intensive Applications (O'Reilly, 2017). Ch. 5 (replication), Ch. 9 (consistency and consensus). Extract: the vocabulary for distinguishing "eventually consistent decay" from "transactional write" — used to scope Phase 5 (§17) correctly. Applied in §17, §29 Scalability.
  • Gelman, A. et al. — Bayesian Data Analysis, 3rd ed. (CRC Press, 2013). Ch. 2 (single-parameter models — Beta-Binomial). Extract: the closed-form Beta posterior update used by BAYESIAN propagation and the feedback reliability update. Applied in §8.4.3, Phase 4 (§16), Phase 8 (§20).
  • Shafer, G. — A Mathematical Theory of Evidence (Princeton University Press, 1976). Ch. 1–2 (belief functions, Dempster's rule of combination). Extract: why combining belief masses is a different, heavier operation than either MIN or PRODUCT. Applied in §8.4.4 (deferred DEMPSTER-SHAFER mode), §35 Deferred Features Register.
  • Stonebraker, M. & Hellerstein, J. (eds.) — Readings in Database Systems, 5th ed. (MIT Press, 2015). Part 1 (classical systems), Part 5 (extensibility). Extract: the historical case for treating a new domain type as a first-class citizen instead of a layered application concern. Applied in §2, §9 ADR-01.
  • Bishop, C. — Pattern Recognition and Machine Learning (Springer, 2006). Ch. 1.5 (decision theory), Ch. 2.1 (Beta distribution). Extract: the mathematical basis for treating a model's reported confidence as a calibratable quantity, not ground truth. Applied in §8.4.3, Glossary "calibration" (§36).

Papers

  • Stonebraker, M. & Rowe, L. — "The Design of POSTGRES," SIGMOD 1986. Contribution: the abstract-data-type extensibility model that makes a new parametric column type possible at all. Applied in §11 Core Schema & Types, Phase 0 (§12).
  • Dalvi, N. & Suciu, D. — "Efficient Query Evaluation on Probabilistic Databases," VLDB 2004. Contribution: possible-worlds semantics and the complexity of evaluating predicates over uncertain tuples. Applied in §8 Domain Model, §8.4 join algebra.
  • Widom, J. — "Trio: A System for Integrated Management of Data, Accuracy, and Lineage," CIDR 2005. Contribution: the first system to unify confidence and lineage in one relational model. Applied in §20 Phase 8 (feedback + provenance), §31 Comparative Architecture.
  • Antova, L., Koch, C. & Olteanu, D. — "MayBMS: A Probabilistic Database Management System," SIGMOD 2007 (demo) / VLDB J. 2009 (full). Contribution: world-set decomposition storage for correlated probabilistic tuples. Applied in §31 Comparative Architecture, ADR-04 rejected-alternative regime.
  • Sen, P. & Deshpande, A. — "Representing and Querying Correlated Tuples in Probabilistic Databases," ICDE 2007. Contribution: correlated-tuple representations for multi-source disagreement. Applied in §19 Phase 7 Conflict Log design.
  • Dempster, A. — "Upper and Lower Probabilities Induced by a Multivalued Mapping," Annals of Mathematical Statistics 38(2), 1967. Contribution: the original rule of combination for belief masses. Applied in §8.4.4, §35 (DEMPSTER-SHAFER deferral).
  • Niculescu-Mizil, A. & Caruana, R. — "Predicting Good Probabilities With Supervised Learning," ICML 2005. Contribution: empirical calibration of model-reported confidence scores. Applied in §7 I4, Glossary "calibration" (§36), R-17-equivalent risk in §22 Failure Modes.
  • Green, T., Karvounarakis, G. & Tannen, V. — "Provenance Semirings," PODS 2007. Contribution: an algebraic framework for combining annotations (confidence is one instance) across relational operators. Applied in §8.4 (propagation-as-semiring framing), §30 Mental Models MM3.
  • Gray, J., Lorie, R., Putzolu, G. & Traiger, I. — "Granularity of Locks and Degrees of Consistency in a Shared Data Base," IFIP 1976. Contribution: the classical analysis of concurrent-write anomalies under fine-grained locking. Applied in §19 Phase 7 N.6 Pitfalls, I6.

Reference Implementations

  • pgrx (github.com/pgcentralfoundation/pgrx) — dirs pgrx-macros/, pgrx-tests/. Lesson: safe Rust-to-Postgres-ABI codegen for types, operators, and bgworkers. Pitfall: do not allocate with the global Rust allocator inside a Postgres-called function — use PgMemoryContexts, or cross-context frees corrupt the executor's memory arena. Applied in Phase 0 (§12), ADR-01.
  • PostgreSQL core (github.com/postgres/postgres) — dirs src/backend/utils/adt/ (type I/O, e.g. numeric.c), src/backend/optimizer/plan/ (planner hooks). Lesson: the exact contract a type input function must satisfy (must not use SPI, must be deterministic). Pitfall: relying on internal-only APIs that break across minor versions (R-01-equivalent, §22 T2). Applied in §8.1, §9 ADR-23.
  • pgvector (github.com/pgvector/pgvector) — dirs src/vector.c, src/ivfflat.c. Lesson: the precedent for shipping a new parametric type + operator class + index support as an out-of-core extension. Pitfall: index method integration is far more invasive than operator definition alone — scoped out of Phase 0–9 here (§35). Applied in §9 ADR-04, §31.
  • TimescaleDB (github.com/timescale/timescaledb) — dir src/bgw_*. Lesson: background-worker scheduling, throttling, and per-database worker lifecycle. Pitfall: forgetting cooperative-cancellation checks inside a long sweep loop stalls checkpointing. Applied in §17 Phase 5, ADR-08, I9.
  • Citus (github.com/citusdata/citus) — dir src/backend/distributed/planner/. Lesson: composing a custom planner hook with Postgres's own hook chain without breaking other extensions. Pitfall: hook-ordering assumptions that silently break when a second extension also hooks planner_hook. Applied in §14 Phase 2, ADR-23.

Glossary (§36) · 45 terms · site-wide glossary

confident<T>
the parametric Postgres type: (v, c, s, t, decay_ref, conflict_ix) (§8.1).
Confidence (c)
a scalar in [0.0, 1.0] reporting a source's belief in v; not a calibrated probability by construction (MM7, §5 Niculescu-Mizil & Caruana 2005).
Source (s)
a source_id identifying the producer of an observation (§8.1, I2).
Source registry
fuzzy_source (§11.2); maps handles to kinds and reliability priors.
Source kind
enum {model, agent, sensor, human, system} classifying a source.
Decay function
a configured rule (half_life, linear, step, none, §11.4) by which confidence ages, applied only by fuzzy_decay (P5).
Half-life decay
confidence halves every configured N days from t.
Linear decay
confidence ramps linearly to zero over a configured horizon.
Step decay
confidence multiplied by a factor after a configured interval.
Decay engine (fuzzy_decay)
the bgworker walking columns and applying decay (§17).
Cooperative cancellation
a bgworker checking a cancellation flag at bounded intervals (≤10,000 rows, I9) rather than being forcibly killed.
Conflict log
fuzzy_conflict_log (§11.5); append-only store of every observation written to a track_conflicts cell (P10).
Resolution mode
per-column rule (MAX_CONFIDENCE, NEWEST, BAYESIAN_FUSE) computing the canonical value from the conflict log (§19.2).
Propagation mode
per-join rule (MIN, PRODUCT, BAYESIAN, deferred DEMPSTER-SHAFER) combining input confidences at a join (§8.4).
Beta-binomial conjugate prior
the closed-form posterior update used by BAYESIAN propagation and the feedback reliability update (Gelman et al. 2013, §5).
Reliability prior (α, β)
a source's Beta-distribution parameters in fuzzy_source, updated only via the feedback rule (I10, §20.2).
Feedback
a correction recorded via fuzzy_apply_feedback, updating the originating source's reliability prior (§20).
Calibration
whether a reported confidence matches empirical correctness frequency; a modeling responsibility of the caller, not a Fuzzy guarantee (MM7).
EXPLAIN (FUZZY)
the Fuzzy variant of EXPLAIN; reports rewrites, propagation modes, and decay state (§8.6, I5, P7).
Post-parse rewriter
the hook desugaring WITH confidence > X into plain predicates (ADR-23, §14.2).
Planner hook
the hook attaching a propagation mode to join plan nodes (§8.4, §15.2).
Wire format
the packed binary tuple encoding of confident<T> (§8.1, ADR-05, additive-only per P14/I3).
Abstract data type (ADT) extensibility
the Postgres mechanism allowing a new parametric type to become first-class (Stonebraker & Rowe 1986, §5).
pgrx
the Rust framework binding Postgres's C ABI safely (§5, ADR-01).
palloc / PgMemoryContexts
Postgres's per-context memory allocator; must be used instead of the global Rust allocator inside extension code (§12.6).
Operator class
the Postgres mechanism letting a B-tree index understand ordering over a custom type (§14.2).
Possible-worlds semantics
the formal model treating an uncertain database as a distribution over possible exact databases (Dalvi & Suciu 2004, §5).
World-set decomposition
MayBMS's storage technique representing correlated uncertain tuples as (tuple, condition) pairs (§5, §31, ADR-04).
Semiring combination
an algebraic framing (associative/commutative combination) used to reason about propagation-mode composability (Green et al. 2007, §5, MM3).
Dempster-Shafer theory
a belief-combination framework heavier than MIN/PRODUCT, deferred to a later phase (§8.4.4, §5 Dempster 1967/Shafer 1976).
Consensus confidence
confident_consensus's output: Σc_i[agree] / Σc_i[all] (§8.5).
Disagreement entropy
confident_disagreement's output, Shannon entropy of a cell's source distribution (§19.2, Sen & Deshpande 2007).
Conformance suite
the fixture-driven correctness harness in conformance/ (§26).
Write amplification
extra write cost imposed by a feature (e.g. conflict-log appends) versus a plain UPDATE (M10, §4).
Retention cap
a per-column max-observations/max-age limit bounding conflict-log growth (§19.2).
fuzzy_audit_log
the append-only audit trail for feedback and reliability changes, introduced Phase 8 (§20.10).
panic_disable GUC
an emergency setting disabling rewriter/planner hooks without uninstalling the extension (§24).
Propagation-depth cap
a bound on join-propagation chain depth preventing pathological plans (ADR-21, T1).
statement_timeout
standard Postgres GUC bounding query execution time, reused as a backpressure mechanism (ADR-21).
SemVer
semantic versioning discipline locking MAJOR/MINOR/PATCH meaning to wire/storage compatibility (ADR-18, §25).
RTO (Recovery Time Objective)
the maximum acceptable time to recover from a failure (e.g. < 60s after a bgworker crash, §4, I11).
Idempotent sweep
a decay sweep computed fresh from t and elapsed time each pass, safe to re-run after a crash (§8.9, MM4).
TOAST
Postgres's mechanism for storing oversized variable-length values out-of-line; relevant to confident<T> for large T (§12.6).
RUSTSEC
the Rust security-advisory database checked by cargo-deny in CI (ADR-03, §27).
SBOM (Software Bill of Materials)
a generated inventory of build dependencies attached to every release (§27).
