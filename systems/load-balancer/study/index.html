33. Mental Models & First Principles

  • MM1 — A pick is a load-balancing decision under uncertainty, not a routing table lookup. Compressed insight: every Selector is answering "which backend is least likely to make this request slow," and P2C's win over round-robin is precisely that round-robin ignores the uncertainty entirely (§5 Mitzenmacher). Predicts: round-robin degrades badly the moment backends are heterogeneous in speed, even briefly. Bug class without it: "but round-robin is fair" reasoning that ignores transient backend slowness, leading to a P2C-vs-RR regression that only shows up under real skew, never in a synthetic uniform-latency test. Resolving: §15.

  • MM2 — Health is a lagging, reconciled signal, not ground truth. Compressed insight: BackendStatus.healthy is always a stale AND of two independently-lagging observers (active probe interval, passive ejection window) — it is an estimate, not a fact (P5). Predicts: a backend can receive traffic for up to one probe interval after it actually died. Bug class without it: "why did we send traffic to a dead backend" incidents where the engineer expects instant detection instead of bounded-latency detection. Resolving: §7 I4, §17.

  • MM3 — Config is data, not state; a reload is a new value, not a mutation. Compressed insight: ConfigSnapshot behind ArcSwap is RCU — readers never block, writers never wait for readers, and the old value survives exactly as long as its last reader (ADR-07). Predicts: any hot-reload design that instead mutates a shared map in place will eventually drop in-flight requests. Bug class without it: the canonical "reload dropped 12,000 gRPC streams" incident (§1, §2). Resolving: §7 I1/I2, §22.

  • MM4 — Consistent hashing trades perfect balance for minimal disruption. Compressed insight: Maglev/Ketama/Jump all accept a small balance imperfection in exchange for the property that removing one backend moves close to 1/N of keys, not close to all of them (§5 Karger, Eisenbud). Predicts: a naive hash(key) % N scheme will look fine in a demo and then reshuffle nearly every key the moment N changes. Bug class without it: cache stampedes or session loss on every backend-count change. Resolving: §8.7, §15.

  • MM5 — Backpressure is a property of the whole pipe, not a buffer setting. Compressed insight: streaming bodies end-to-end (P11) means a slow reader anywhere throttles the writer at every stage automatically, via the kernel's own TCP flow control — no explicit buffer-size tuning is the actual goal. Predicts: any design that buffers "just this one stage" reintroduces unbounded memory growth exactly at that stage. Bug class without it: a 1 GiB upload behind a slow upstream OOMs the proxy despite every individual buffer being "reasonably sized." Resolving: §6 P11, §13.

  • MM6 — Tail latency is a fan-out and variance problem, not an average problem. Compressed insight: p99 is dominated by rare, correlated slow events (a GC pause, a cold cache line, a contended lock) that averages hide entirely (§5 Dean & Barroso). Predicts: optimizing mean latency can leave p99 untouched or even worsen it (e.g. batching helps mean throughput but can hurt tail latency). Bug class without it: shipping a change that improves the dashboard's average-latency graph while an SLO burn alert fires on p99. Resolving: §31.

  • MM7 — A circuit breaker's half-open state is rate-limiting the truth, not the traffic. Compressed insight: half-open exists to answer "is this backend actually better now" with a bounded, safe sample size — not to gradually ramp traffic back up (I12). Predicts: skipping the probe quota and going straight to Closed on any single success reintroduces the thundering-herd failure the breaker was built to prevent. Bug class without it: a recovery-triggered outage that looks identical to the original outage. Resolving: §20.

  • MM8 — An admin API is a distributed system's only legible causality. Compressed insight: because every mutation is audited before being applied (I10), the admin API is the one place where "what changed, when, and who did it" is provably reconstructible — everything else (discovery pushes, health-check transitions) is inferred from telemetry, not recorded as intent. Predicts: an unaudited mutation path (SIGHUP, a config file poked outside the discovery watcher) will eventually be the thing nobody can explain during an incident. Resolving: §6 P10, §22.

Required reading (§5)

Books

  • Kleppmann, M. — Designing Data-Intensive Applications (O'Reilly, 2017). Ch. 5 (Replication), Ch. 8 (The Trouble with Distributed Systems), Ch. 9 (Consistency & Consensus). Extract: the eventual-consistency reasoning behind a reload racing discovery. Applied in §32, §24.2.
  • Stevens, W. R. — TCP/IP Illustrated, Volume 1 (Addison-Wesley, 1994). Ch. 17–18 (TCP connection establishment/teardown), Ch. 21 (timeout & retransmission). Extract: the FIN/RST half-close semantics the L4 proxy must mirror. Applied in §12.2, §4.
  • Stevens, W. R.; Fenner, B.; Rudoff, A. — UNIX Network Programming, Vol. 1, 3rd ed. (Addison-Wesley, 2003). Ch. 7 (socket options, SO_REUSEPORT lineage), Ch. 16 (non-blocking I/O). Extract: why SO_REUSEPORT is required for multi-core accept scaling. Applied in §12.2, §24.2.
  • Kerrisk, M. — The Linux Programming Interface (No Starch Press, 2010). Ch. 63 (epoll), Ch. 36 (process resource limits). Extract: the RLIMIT_NOFILE raise mechanics. Applied in §12.2, §4.
  • Beyer, B.; Jones, C.; Petoff, J.; Murphy, N. R. (eds.) — Site Reliability Engineering (O'Reilly, 2016). Ch. 19–20 (load balancing at the front-end/in the datacenter), Ch. 4 (SLOs), Ch. 6 (monitoring). Extract: the four-golden-signals dashboard philosophy. Applied in §27, §21.2.
  • Grigorik, I. — High Performance Browser Networking (O'Reilly, 2013). Ch. 2 (TCP), Ch. 4 (TLS), Ch. 12 (HTTP/2). Extract: the handshake and flow-control cost model. Applied in §18.2, §23.2.
  • Blandy, J.; Orendorff, J.; Tindall, L. — Programming Rust, 2nd ed. (O'Reilly, 2021). Ch. 19 (Concurrency), Ch. 22 (Unsafe Code). Extract: reasoning about the atomics in BackendStatus/BackendStats. Applied in §11, §15.2.

Papers

  • Eisenbud, D. et al., 2016. "Maglev: A Fast and Reliable Software Network Load Balancer." NSDI. Contribution: consistent-hash table construction with 1/N disruption on backend removal. Applied in §15.2, §35.
  • Karger, D. et al., 1997. "Consistent Hashing and Random Trees." STOC. Contribution: the foundational consistent-hashing construction. Applied in §15.2.
  • Lamping, J.; Veach, E., 2014. "A Fast, Minimal Memory, Consistent Hash Algorithm." arXiv:1406.2294. Contribution: the two-line jump-hash algorithm. Applied in §15.2.
  • Mitzenmacher, M., 2001. "The Power of Two Choices in Randomized Load Balancing." IEEE Transactions on Parallel and Distributed Systems. Contribution: the survey-form proof that two random probes reduce max load exponentially. Applied in §15.2, §33 MM1.
  • Mitzenmacher, M., 1996. "The Power of Two Choices in Randomized Load Balancing." Ph.D. thesis, UC Berkeley. Contribution: original derivation. Applied in §15.2, §35.
  • Dean, J.; Barroso, L. A., 2013. "The Tail at Scale." Communications of the ACM 56(2). Contribution: tail-latency amplification under fan-out and the case for load-aware/hedged requests. Applied in §31, §15.2.
  • Fielding, R., 2000. "Architectural Styles and the Design of Network-based Software Architectures." Ph.D. dissertation, UC Irvine. Ch. 5 (REST). Contribution: statelessness as a routing-layer design constraint. Applied in §8, §16.2.
  • Langley, A. et al., 2017. "The QUIC Transport Protocol: Design and Internet-Scale Deployment." SIGCOMM. Contribution: QUIC's stream/connection model and its production deployment lessons. Applied in §23.2, §34.

Reference Implementations

  • HAProxy — src/proxy.c, src/backend.c, src/check.c, src/connection.c. Lesson: the canonical L7 connection state machine. Pitfall: its config language conflates listener and backend configuration — do not copy that coupling. Applied in §13.2, §17.2.
  • NGINX — src/event/ngx_event.c, src/http/modules/ngx_http_upstream*.c. Lesson: the multi-process worker model and shared-memory keepalive cache. Pitfall: the worker-shared- memory dance is unneeded in a single-process async model — do not import it. Applied in §13.2, §21.2.
  • Envoy — source/common/upstream/cluster_manager_impl.cc, source/common/router/router.cc, api/envoy/service/discovery/v3/. Lesson: the xDS-driven cluster-manager abstraction. Pitfall: full xDS is overkill for a single-proxy fleet — borrow the eventual-consistency model, not the protocol surface. Applied in §14.2, §22.2.
  • Cloudflare Pingora (pingora-proxy crate). Lesson: a pure-Rust Tokio+Hyper proxy at production scale with connection-reuse pooling. Pitfall: its background-service model assumes a specific process supervisor — do not assume identical liveness-probe behavior. Applied in §13.2, §14.2.
  • Facebook Katran. Lesson: the eBPF/XDP L4 kernel-bypass datapath and packet-level consistent hashing. Pitfall: health-checking is out-of-band (a user-space checker informs the XDP maps) — the kernel program cannot self-heal. Applied in §37, ADR-16.
  • Twitter Finagle (LoadBalancerFactory; the "Introducing EWMA load balancing" blog post). Lesson: the latency-aware P2C variant. Pitfall: its JVM-based EWMA tuning assumes GC-pause-driven latency noise a Rust proxy does not have — retune alpha. Applied in §15.2.

Glossary (§39) · 47 terms · site-wide glossary

ALPN (Application-Layer Protocol Negotiation)
TLS extension negotiating h2/ http/1.1/h3 during the handshake; drives listener protocol dispatch (§18.2).
ArcSwap
a lock-free atomically-swappable Arc pointer; the mechanism behind hot-reload (ADR-07, I1/I2).
Backend
one upstream server instance, identified by BackendId (§11.2).
BackendPool
the per-cluster, ArcSwap-backed collection of Backends (§11.3).
BackendStatus
the reconciled health/draining/ejection state of a Backend (§11.2, I4).
Bulkhead
a per-backend/per-cluster concurrency cap that isolates overload (§20.2).
Canary
routing a small traffic percentage to an alternate cluster (§16.2).
Circuit Breaker
a state machine (Closed/Open/HalfOpen) that short-circuits traffic to a failing cluster or backend (§20, §8.3).
ConfigSnapshot
the immutable, versioned config object behind ArcSwap (§11.5, I1).
Connection Pool
the per-backend keepalive connection cache (§13.2).
Consistent Hashing
a hash scheme minimizing key movement on membership change; Maglev/ Ketama/Jump are the three variants shipped (§15.2, §5 Karger).
Discoverer
a trait implementation that watches a backend source and pushes updated lists (§11.7, §14).
Draining
a backend/listener state excluded from new picks but still serving existing work (P12, I9).
EWMA (Exponentially-Weighted Moving Average)
the latency-smoothing statistic behind EWMA-P2C and LatencyAware (§15.2, ADR-12).
FD (File Descriptor)
the kernel handle for a socket; budgeted explicitly (§4).
Half-Open
the circuit-breaker probing state between Open and Closed (§8.3, I12).
Health Check, Active
a proxy-initiated probe (TCP/HTTP/gRPC/exec) (§17.2).
Health Check, Passive
outlier ejection derived from real request outcomes (§17.2, P5).
Hop-by-hop Header
a header meaningful only for one connection segment, stripped before forwarding (I7, RFC 7230 section 6.1).
HPACK
HTTP/2 header compression (RFC 7541, §23.2).
Jump Hash
the Lamping & Veach O(1)-memory consistent-hash algorithm (§15.2, §5).
Ketama
the classic virtual-node ring consistent-hash algorithm (§15.2, §5 Karger).
Maglev
Google's O(1)-lookup, 1/N-disruption consistent-hash table (§15.2, §5 Eisenbud).
mTLS (mutual TLS)
both client and server present certificates; used for the admin API and optionally upstream re-encryption (P8, P10).
Outlier Ejection
passive removal of a misbehaving backend from the pick set (§17.2, I4).
P2C (Power of Two Choices)
sampling two backends and picking the less-loaded one (§15.2, §5 Mitzenmacher).
PROXY protocol v2
a wire header injecting original client address info on a re-proxied connection (§8.5).
QPACK
HTTP/3's header-compression scheme, QUIC's analog of HPACK (RFC 9204, §23.2).
QUIC
the UDP-based transport underlying HTTP/3 (RFC 9000, §23.2).
Rate Limiter, Leaky Bucket
a smooth-output-rate limiting algorithm (§19.2).
Rate Limiter, Token Bucket
a burst-tolerant limiting algorithm (§19.2).
RCU (Read-Copy-Update)
the general concurrency pattern ArcSwap implements: readers never block, a writer publishes a new value atomically (§33 MM3).
Reload Generation
the monotonic counter identifying a ConfigSnapshot version (§11.5, §28).
Route
a (matcher, action) pair resolving a request to a cluster or synthetic response (§11.5, §16).
Selector
the trait implementing a load-balancing algorithm (§11.4, §15).
Shadow Traffic
mirroring a request to a secondary cluster without affecting the primary response (§16.2).
SLO (Service-Level Objective)
the target success/latency rate a route is held to (§21.2, §27).
SNI (Server Name Indication)
the TLS ClientHello field selecting which certificate to serve (§18.2).
Split-brain
a window where two nodes both believe they own the same key, possible during a gossip partition (§24.8).
Sticky Session
request affinity to a specific backend, achieved here via consistent-hash keying rather than server-side session state (§15.2).
Traffic Split
weighted request distribution across N clusters via stable hashing (§16.2).
TTL (Time to Live)
the validity duration of a DNS record or similar cached value (§14.2).
Two-Phase Reload
build-and-validate, then commit; rolls back on validation failure (§22.2, I2).
VIP (Virtual IP)
a floating IP address shared by an active-passive pair (§24.2).
VRRP (Virtual Router Redundancy Protocol)
the protocol keepalived uses to manage VIP failover (§24.2).
WRR (Weighted Round Robin), Smooth
the NGINX-style weighted round-robin avoiding burst-then-pause (§15.2).
xDS
Envoy's family of dynamic-configuration discovery protocols (CDS/EDS/RDS/LDS), contrasted with this blueprint's ArcSwap-based model (§34).
