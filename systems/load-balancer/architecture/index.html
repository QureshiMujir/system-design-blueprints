Three properties recur throughout this document. First, the data path is one-way: request → listener → router → algorithm library → backend pool → upstream socket; the response mirrors it back. The control plane never blocks the data path (P4). Second, the L4 and L7 listeners share the algorithm library, the backend pool, and the admin/metrics/ discovery surface; only the listener-side framing diverges. Third, config is an immutable snapshot behind arc_swap::ArcSwap<ConfigSnapshot> (ADR-07); a reload allocates a new snapshot and swaps the pointer atomically (I1, I2) — in-flight requests keep the old snapshot until they complete; new requests see the new one immediately. There is no shared mutable state between control plane and data path.

Per-box description. Admin API — the sole mutation surface (P10); mTLS by default; writes an audit record before applying any change (I10). Control Plane — owns discovery watchers, health-check timers, and the two-phase reloader; runs on its own task set. Listeners — one per protocol; L4 (raw TCP/UDP) skips routing entirely (P1); L7 listeners share one Service boundary. L7 Router — a pure function of (request, snapshot) (P7); resolves host/path/header/method/JWT matchers to a RouteAction. RateLimit/Circuit/Auth — ordered per-request gates before backend selection. Algorithm Library — the Selector trait and its ten implementations (§15); reads the BackendPool snapshot, never mutates it. BackendPool — the single source of truth for backend health and connections; written by discovery, health checks, and the outlier ejector; read by every pick. Upstream sockets — plaintext or re-encrypted TLS; PROXY protocol v2 injection is opt-in per cluster. Cross-cuts — metrics, tracing, and access logs observe every box without altering data-path control flow.

8.5 Wire layout: PROXY protocol v2 header (upstream injection, §12.2, §24.2)

Signature (12B): 0x0D 0x0A 0x0D 0x0A 0x00 0x0D 0x0A 0x51 0x55 0x49 0x54 0x0A
Ver/Cmd  (1B):   top nibble = version (2), low nibble = command (1=PROXY, 0=LOCAL)
Fam/Proto(1B):   top nibble = address family, low nibble = transport
Length   (2B):   length of the address block that follows, big-endian
Address block:   src_addr | dst_addr | src_port | dst_port  (sizes per Fam/Proto)

Malformed-input example: a length field that overruns the segment the proxy read from the socket is rejected at parse time (never trusted past the declared Length); the connection is reset and lb_header_violations_total{kind="proxy_v2_overrun"} increments (I7 sibling check).

8.6 gRPC-over-HTTP/2 frame layout (§23.2)

compressed-flag (1B) | message-length (4B, big-endian) | protobuf payload (message-length bytes)

The proxy treats the payload as opaque bytes (P1/P3: no per-request allocation to parse protobuf); only the HTTP/2 DATA frame boundaries and the grpc-status/grpc-message trailers are inspected.

8.7 Worked example: Maglev lookup table, M=7, N=2

Backends B0, B1. offset(Bi) = h1(Bi) % M, skip(Bi) = h2(Bi) % (M-1) + 1. Take offset(B0)=3, skip(B0)=2 → permutation [3,5,0,2,4,6,1]; offset(B1)=0, skip(B1)=3 → permutation [0,3,6,2,5,1,4]. Construction visits backends round-robin; each proposes the next unfilled slot in its own permutation, skipping slots already claimed:

Step Backend Proposes Slot claimed
1 B0 3 3
2 B1 0 0
3 B0 5 5
4 B1 3 (taken) → 6 6
5 B0 0 (taken) → 2 2
6 B1 2 (taken) → 5 (taken) → 1 1
7 B0 4 4

Final table (slot → backend): [B1, B1, B0, B0, B0, B0, B1]. Lookup for key k is table[hash(k) % 7] — O(1). Removing B1 rebuilds with N=1; only the 3 slots B1 held move, matching the 1/N disruption bound (§35) — this is the O(M·N) build cost quantified in §35 and the reason I13 forbids running it on the request path.

8.8 Failure-path example: upstream connection reset mid-stream

  1. Client sends GET /orders/42; proxy picks B7 via EWMA-P2C (§15.2).
  2. Upstream connection to B7 accepts, streams 4 KiB of the response, then sends TCP RST (backend process crashed).
  3. Proxy's copy_bidirectional/Hyper body stream observes the RST as an I/O error mid-frame.
  4. Proxy cannot retry transparently — headers and 4 KiB of body have already been flushed to the client (HTTP/1.1 has no mid-response rollback). The connection to the client is reset with lb_requests_total{status_class="5xx"} incremented and the incident logged with request_id, backend_id=B7.
  5. B7's consecutive_5xx (or, since this is a transport-level reset rather than a 5xx status, a distinct connection_reset counter) increments; five such events within 30 s trigger passive ejection (I4, §20.2).
  6. Active health check on B7 (§17) fails next probe; BackendStatus.healthy flips false independently, confirming the passive signal (§7 debugging methodology).

8.9 Malformed-input example: HTTP request smuggling (CL.TE)

A request carrying both Content-Length: 44 and Transfer-Encoding: chunked is ambiguous about framing. Per RFC 7230 section 3.3.3 and I7, Hyper's parser refuses to resolve the ambiguity in the proxy's favor; the proxy rejects the request outright (HTTP 400) rather than guessing, because guessing wrong is exactly the CL.TE smuggling vector documented in the conformance fixtures conformance/corpora/routing/smuggling_cl_te.json (§13.5, T4 in §25).

Design principles (§6)

  • P1 — One Core, Two Listeners. The algorithm library, backend pool, discovery layer, health checker, metrics surface, admin API, and hot-reload contract are written once and used by every listener kind. Tradeoff: L4-specific latency shaving (e.g. splice(2)-style zero-copy) is harder to bolt on later. Operational implication: a pick_backend bug fix is a bug fix everywhere. Violated: duplicated code paths silently diverge and one gets fixed, the other doesn't.
  • P2 — Hot-Reload Is In-Flight-Safe. A config reload never drops an in-flight request; long-lived gRPC streams against a removed backend continue until they close. Tradeoff: requires holding old Arc<ClusterConfig>/Arc<Backend> memory until the last reference drops. Operational implication: reload frequency is rate-limited (ADR-07, I2). Violated: the canonical "reload dropped 12,000 gRPC streams" incident (§33 MM3).
  • P3 — Zero Per-Request Heap Allocation on the Hot Path. Backend selection and body framing use pre-allocated buffers and bytes::Bytes views. Tradeoff: more upfront design complexity (niche-optimized IDs, Arc-based sharing). Operational implication: allocator pressure is bench-asserted, not assumed. Violated: allocator contention shows up as p99 latency jitter under load (§31).
  • P4 — The Control Plane Never Blocks the Data Path. Discovery push, health-check timers, metric scrapes, and admin calls run on separate tasks; the data path communicates via ArcSwap and lock-free channels only. Tradeoff: eventual, not immediate, consistency between control and data plane. Operational implication: a stuck discoverer cannot stall requests. Violated: a health-check HTTP call blocking on the request-handling thread pool stalls unrelated traffic.
  • P5 — Health Is Observed, Never Assumed. Active checks (TCP/HTTP/gRPC/exec) provide baseline truth; passive outlier ejection provides fast-path eviction. Tradeoff: two subsystems must reconcile via one BackendStatus (I4). Operational implication: a backend can be evicted before the next scheduled active probe. Violated: traffic keeps flowing to a backend mid-5xx-storm until the next probe fires.
  • P6 — One Algorithm at a Time per Cluster, No Silent Fallback. A cluster declares exactly one Selector; if it cannot pick, the proxy fails open and observes rather than silently falling back to round-robin. Tradeoff: an operator must explicitly choose a fallback policy. Operational implication: algorithm behavior is always predictable from config. Violated: a silent fallback masks a real bug in the configured algorithm.
  • P7 — Routing Is a Pure Function of (Request, Snapshot). No hidden per-request mutable state; canary/split assignment is a stable hash of a request key. Tradeoff: statefulness (e.g. sticky sessions beyond hash-based) needs an explicit key, not implicit affinity. Operational implication: a route decision is reproducible from logs alone. Violated: non-deterministic routing makes incident reproduction impossible.
  • P8 — TLS Terminates Here; Upstream Re-Encryption Is Default-On. Plaintext-to-upstream is opt-in per cluster, never the default. Tradeoff: extra CPU cost for the second handshake. Operational implication: upstream cert expiry becomes an operational surface (T9, §25). Violated: an accidentally-plaintext upstream hop leaks data on a compromised internal network.
  • P9 — Metrics Are Typed, Not Stringly-Typed. Every metric is a typed handle declared at construction; label cardinality is bounded at the type level. Tradeoff: a new metric requires a code change, not a config change. Operational implication: no typo'd metric names in production. Violated: an unbounded label (e.g. raw upstream IP) blows Prometheus cardinality.
  • P10 — The Admin API Is the Only Mutation Surface. No SIGHUP, no inotify-watched config file as a mutation trigger (though it exists as a discovery source), no out-of-band poke; every mutation is an audited admin call (I10). Tradeoff: an extra network hop for local config changes. Operational implication: every mutation has an auditable actor. Violated: an unaudited config change is undebuggable after the fact.
  • P11 — Backpressure Propagates, Never Gets Absorbed. Both proxy directions stream; a slow reader on one side throttles the read from the other via bounded buffers, never via unbounded in-memory queuing. Tradeoff: a slow client can hold upstream resources longer. Operational implication: OOM from a large body is structurally impossible. Violated: a 1 GiB upload behind a slow upstream buffers entirely in DRAM and OOMs the proxy.
  • P12 — Draining Is Not Unhealthy. A draining backend is healthy from the upstream's perspective but excluded from new picks; the health checker must not flag it. Tradeoff: two independent boolean flags (healthy, draining) instead of one enum simplifies concurrent writers at the cost of an extra invariant (I9) to maintain. Operational implication: draining backends still serve their existing long-lived streams. Violated: conflating the two states either kills in-flight streams early or keeps sending new traffic to a backend mid-decommission.
  • P13 — Time Is Injected, Never Read Raw. All timers, TTLs, and EWMA updates go through the Clock trait (MonotonicClock in production, MockClock in tests). Tradeoff: an extra trait-object indirection on every timestamp read. Operational implication: deterministic replay and chaos testing become possible (§29). Violated: a flaky test that depends on wall-clock timing cannot be reproduced deterministically.
  • P14 — Every Stochastic Algorithm Ships a Deterministic Conformance Fixture. P2C, EWMA-P2C, Maglev, Ketama, and Jump all have a seeded fixture asserting a chi-square-bounded pick distribution. Tradeoff: fixture maintenance cost on every algorithm change. Operational implication: a regression in pick fairness is caught in CI, not production. Violated: a bug in P2C's sampling-without-replacement only manifests under real load (§15.6).
