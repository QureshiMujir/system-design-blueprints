16 — Polis

Project Number: 16

Project Name: Polis

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

Polis is a synthetic-civilizations simulation platform: a substrate for instantiating populations of LLM-powered agents — each carrying a declared, inspectable PsychologyProfile, a memory model, a closed action repertoire, and a communication protocol — inside scriptable environments with resources, geography, and institutions, advancing simulated time through a custom parallel event-loop engine, and exposing every run for deterministic-where-possible replay, forking, and side-by-side comparison. It is a research instrument for computational social science and policy stress-testing, engineered to the reliability bar of a distributed-systems platform — not a chatbot, game engine, or forecasting product.

Phase-0 deliverable (numbered modules, built in §12):

  1. core/schema — Agent, PsychologyProfile, Environment, Event, Relationship, EmergentMetric, Scenario types (§11).
  2. core/contracts — Agent, Environment, Event-Loop normative contracts (§8).
  3. orchestrator/scheduler — single-process tick scheduler (five-phase cycle).
  4. orchestrator/determinism — event stamping and the append-only determinism log.
  5. agents/frontier — one frontier-model agent class bound to a hosted inference API.
  6. env/dsl — minimal YAML environment description + loader (no expression engine yet).
  7. env/runtime — resource-layer and geography-layer interpreter.
  8. storage/object — local-disk scenario-card serializer.
  9. core/conformance — the first conformance-suite fixtures (§12.5).

System boundaries.

  • Provides: agent contract, memory model, environment DSL, event-loop engine, determinism log, scenario forking, emergent-metric reduction, replay/diff surfaces, and a conformance suite gating template admission.
  • Delegates: raw LLM inference to external frontier-model providers and to vLLM/TGI for locally-hosted fine-tunes (ADR-04/ADR-05, §9); GPU batch scheduling below the request layer to the inference server; object durability to S3-compatible storage; wire transport to NATS/Kafka (ADR-11/ADR-12).
  • Does NOT provide: predictive forecasting of real-world outcomes (Anti-goal, below); a general-purpose game engine; a chat product; a digital twin of a specific real institution; hosting of identifiable real individuals as agents (Design Principle P14, §6; Invariant I10, §7).

Non-goals: bit-exact replay across LLM-sampled ticks (§8.5); real-time synchronous multiplayer session semantics; a marketplace ranking/recommendation algorithm beyond the conformance-and-ethics admission gate (§21).

Deployment model: managed multi-tenant SaaS for Phases 0–8; a single-tenant on-prem / air-gapped SKU is deferred (§35) until a government-tier engagement exists.

Target users / operators: computational social scientists and policy-simulation engineers as end users; the Polis SRE/on-call rotation operating the orchestrator, Agent Pool, and storage tiers.

What later phases unlock: Phase 3 (§15) unlocks multi-shard runs past the 1,000-agent single-node ceiling; Phase 7 (§19) unlocks 100,000+-agent runs via multi-node scale engineering; Phase 8 (§20) unlocks measurable cultural drift and language emergence; Phase 9 (§21) unlocks institution-level political-faction formation and third-party template admission.

Recommended language + rationale + rejected languages. Python 3.12 (ADR-01, §9): the LLM-orchestration ecosystem (vLLM, Hugging Face, the frontier-provider SDKs) is Python-native, and iteration speed on the agent/psychology/environment contracts dominates raw scheduler throughput until Phase 3. Rejected: Rust — superior tick-scheduler throughput, but ecosystem friction integrating rapidly-changing inference stacks; adopted narrowly as a Cython hot path inside the scheduler (§15) once profiling shows it is warranted. Go — simpler concurrency primitives but a weak numerical/ML ecosystem, forcing a second-language boundary at every agent-policy integration point.

Prerequisites (systems knowledge required): distributed event ordering (logical clocks), discrete-event simulation scheduling, LLM inference-serving internals (batching, KV-cache), columnar time-series storage, and the ethics/threat-modeling discipline required for dual-use research platforms.

Estimated timeline. Phase 0: 4 weeks (repo skeleton + correctness kernel, a 100-agent single-node demo stable for one sim-year). Full system (Phases 0–9): approximately 30 months to the Phase 9 political-formation-at-scale exit criteria (§21.4).

Deferred features (full table in §35), each flagged with a PhaseDeferred(...) anchor: continuous shadow-society ingestion (PhaseDeferred("§21.10")), a government on-prem/air-gapped SKU (PhaseDeferred("§24")), inter-Polis federation of scenario cards (PhaseDeferred("§17.3")), a cross-run longitudinal memory channel (PhaseDeferred("§13.2")), and premium-psychology-model marketplace revenue share (PhaseDeferred("§21.3")).

2. Why Build This

  • Unique systems knowledge. Building Polis teaches barrier-synchronized parallel discrete-event scheduling over a stochastic, non-idempotent per-actor workload (LLM sampling); reproducibility engineering when the compute substrate is itself non-deterministic; high-cardinality time-series storage at population × tick scale; and dual-use platform threat modeling for research tooling.
  • Why it matters architecturally. Every prior agent-based-modeling system (Mesa, NetLogo — §31) assumed cheap, deterministic, hand-coded agent policies. Polis answers the question those systems never had to ask: what happens when the per-agent decision function is an expensive, stochastic, black-box LLM call, at six-figure population scale — a problem with no analogue in classical distributed systems (no expensive nondeterministic compute unit per actor) and none in classical ABM (no language or culture emergence).
  • Why it matters historically. Simulation has always traded fidelity for scale: DSGE macro models buy scale by discarding per-agent heterogeneity; Smallville-class generative agents and DeepMind Concordia buy fidelity by discarding scale (§31). Polis bets that inference-serving techniques (batching, KV-cache reuse, distillation, §19) can move that fidelity/scale frontier, the way paging moved the working-set/scale frontier for operating systems.
  • Engineering muscles built. Tick-phase barrier design under partial failure; determinism-as-a-product-property rather than an afterthought; cache design for behaviorally-equivalent-but-not-textually-identical inputs (the psychology-proxy cache, §19); an ethics gate as a first-class control-plane component, not a compliance bolt-on.
  • Cross-links to sibling systems. The event-loop engine is a barrier-synchronized bulk-synchronous-parallel scheduler, the same family as Pregel/Giraph graph-processing supersteps; the determinism log is structurally a write-ahead/commit log, the same family as Kafka's partitioned log (ADR-12, §9); the psychology-proxy cache is a content-addressed cache, the same family as a build-system remote cache keyed on input-hash, not wall-clock recency.
  • Calibration value. A reader who can explain why Polis's replay guarantee is a confidence band, not bit-exactness (§8.5), and why that is the correct engineering answer rather than a cop-out, has internalized the central lesson of reproducibility under stochastic compute — directly transferable to any ML-pipeline reproducibility problem.

What Mastery Looks Like:

  1. Explain why the event loop enforces five strict barrier phases per tick, and what breaks if COMMUNICATE is allowed to interleave with ACT — mastery gained in Phase 3 (§15).
  2. Derive the KV-cache reuse argument for shared-psychology-prefix batching from first principles (PagedAttention, §5) and size a GPU fleet from it — mastery gained in Phase 7 (§19).
  3. Distinguish a reproducibility confidence band from bit-exact replay, and state exactly which stack layer (environment resolution vs. LLM sampling) each applies to — mastery gained in Phase 5 (§17).
  4. Enumerate the conformance-suite tests required before a psychology profile or environment ships, and explain why each exists — mastery gained in Phase 0 (§12) and Phase 9 (§21).
  5. Design an ethics-gate trigger set for a novel dual-use research platform, using Polis's five triggers as a template — mastery gained across §7 (I10) and §22 (Threat Model).
  6. Trace one emergent-metric value (e.g. a faction-formation count) from the raw event stream through the reducer to the Lens dashboard, naming every component it passes through — mastery gained in Phase 4 (§16) and Phase 9 (§21).
  7. Explain why cultural drift and language emergence are sequenced after trade/alliance/conflict/politics rather than built first — mastery gained across Phase 8 (§20) and Design Principle P6 (§6).

Polis Studio. The composer where a researcher assembles a population template, an environment template, a scenario script, and a run budget; the cockpit for live-run panels.

Polis Lens. The post-run analysis and replay surface: population dashboards, agent-zoom replay of a single agent's subjective timeline, relationship-graph time-slices, and side-by-side scenario diffs.

Control Plane. A stateless Python (ADR-01) service exposing the scenario API, enforcing budget and ethics gates (I10, §7), and routing dispatch to an orchestrator instance.

Orchestrator. The brain of a single run: owns the tick scheduler, shards agents across worker processes (ADR-07), manages RNG seeds and the determinism log, and coordinates barrier synchronization between event-loop phases (P9, §6).

Agent Pool. Where LLM-powered agents live: a mix of frontier-model agents for psychologically demanding roles, fine-tuned smaller ("modal psychology") models for routine agents, and a psychology-proxy cache (P12) that short-circuits behaviorally-equivalent ticks.

Environment Runtime. Interprets the environment DSL (ADR-18): maintains resource stocks, geographic adjacency, institutional state, and applies deterministic action-resolution rules — never inspecting agent internals (P5, I6).

Event-Loop Engine. The custom, barrier-synchronized parallel engine that advances simulated time; each tick is the five-phase cycle in §8.2.

GPU Cluster Layer. Batches inference requests, reuses KV-caches for shared psychology-prefixes (§19), and applies speculative decoding to cut per-tick latency.

Emergent Metrics Bus. Streams per-tick reducer output into the Time-Series Store and into live Studio panels (NATS for live, Kafka for cross-run pipelines — ADR-11/ADR-12).

Time-Series Store. ClickHouse for high-cardinality emergent metrics and the per-agent action log; TimescaleDB for relationship-graph snapshots and SQL-ergonomic queries (ADR-09/ADR-10).

Scenario Forking Engine + Template Store. Materializes a scenario card, stamps an immutable content-addressed run hash, maintains the fork DAG, and (Phase 9, §21) governs signed, versioned civilization templates.

All later sections stay consistent with this diagram; component names here are used identically in §10 (Repository Layout), §11 (Core Schema & Types), and every phase.

6. Design Principles

P1. Psychology Is Declared, Never Hidden. Every agent's PsychologyProfile (§11) is a structured, inspectable object; no agent's behavior may be explained only by "the model decided." Tradeoff: constrains prompt-engineering freedom. Operational implication: every psychology ships with a conformance-suite stability fixture (§12.5). Violation: unexplainable behavior divergence during replay debugging, and failure of the ethics-gate provenance check (I10).

P2. Every Run Is Forkable. Any run produces a Scenario card (§11) sufficient to re-instantiate it, from the first prototype onward. Tradeoff: upfront serialization discipline before feature velocity. Operational implication: no exploratory run skips card emission. Violation: an unreproducible result cannot be published or cited (§2).

P3. Reproducibility-Where-Possible, Not Bit-Exactness. LLM stochasticity is acknowledged; reproducibility is a distributional confidence-band claim (§8.5), never bit-exact across sampled ticks. Tradeoff: a weaker guarantee than classical deterministic replay. Operational implication: every published claim carries a Reproducibility Rate figure. Violation: overclaiming bit-exactness is a scientific-integrity failure (FM-6, §23).

P4. Closed Action Repertoire. An agent may not emit an action outside its declared action_repertoire (§11), even under LLM hallucination; the orchestrator rejects and logs. Tradeoff: forecloses some creative behavior unless explicitly added. Operational implication: expanding emergent capability (P6) is an explicit, versioned repertoire change. Violation: an unconstrained action space breaks deterministic environment resolution (I7).

P5. Environment Never Inspects Agent Internals. The Environment (§11) reads only the actions an agent submits, never its psychology, memory, or reasoning trace. Tradeoff: environment logic cannot "cheat" using hidden agent state. Operational implication: this is the trust boundary drawn in §3. Violation: breaks the auditable psychology/environment separation (I6).

P6. One Emergent Capability at a Time, Fully Validated. Trade (§14) before alliance (§14) before conflict (§14) before politics (§21) before language emergence (§20); no half-shipped emergent surface reaches production. Tradeoff: slower path to the most publicity-worthy capabilities. Operational implication: each capability gets its own conformance fixtures before the next unlocks. Violation: compounding emergent-behavior bugs become undebuggable once untested capabilities interact.

P7. No Retroactive Schema Breakage. Once the Core Schema (§11) reaches v1.0 (Phase 1 GA, §13), all changes are additive and versioned (§25). Tradeoff: early mistakes are carried forward as deprecated fields rather than deleted. Operational implication: every schema change is an ADR (§9) with a migration note. Violation: silent breakage of every stored scenario card and published citation.

P8. Compute Discipline. Every architectural decision is judged against per-agent-hour cost (§28); compute is the central economic constraint, not an afterthought. Tradeoff: some fidelity-improving features are deliberately capped. Operational implication: the psychology-proxy cache hit-rate floor (§4) is a release gate. Violation: unit economics collapse before the Phase 7 exit criteria (§29).

P9. Barrier-Synchronized Tick Phases. PERCEIVE → DELIBERATE → ACT → COMMUNICATE → WRITE execute in strict order with an explicit barrier between each (§8.2, I3). Tradeoff: a slow agent in DELIBERATE stalls the whole tick (mitigated by per-agent timeout + proxy fallback, §15.6). Operational implication: tick p95/p99 latency (§4) is dominated by the slowest shard. Violation: causally-inverted events corrupt every downstream emergent metric.

P10. Total Event Ordering. Every event is stamped (scenario_id, run_id, tick, phase, agent_id, seq) (§11) and this tuple totally orders all events in a run (Lamport, §5). Operational implication: replay and diff (§17) are defined purely as replays of this ordered log. Tradeoff: stamping overhead (≥ 50k events/sec floor, §4) is sustained even at low population. Violation: two independently-replayed runs could disagree on causal order, breaking P3.

P11. Ethics Gate Before Scale. Any scenario tripping a defined trigger — population above 10,000; mass-death modelling; an identifiable real population; a persuasion / radicalization / coercion purpose; government-tier deployment — MUST receive an EthicsGateResult of PASS or PASS_WITH_CONDITIONS before dispatch (§7, I10). Tradeoff: added review latency on the largest, most scientifically interesting runs. Operational implication: Phase 1 reviews are human (an external advisory board, §24) and deliberately not automated further. Violation: an undispatched-but-bypassed gate is the single worst governance failure in the platform (§22, T1–T5).

P12. Cache Psychologically-Equivalent Ticks. The psychology-proxy cache (§19) keys on (psychology_hash, perception_digest) and may return a cached action distribution instead of a fresh LLM call for a behaviorally-equivalent tick. Tradeoff: a small, bounded fidelity loss (bounded by cache-correctness fixtures, §12.5) for the order-of-magnitude cost reduction that makes Phase 7+ scale economically viable. Operational implication: cache hit rate is a first-class performance target (M3, §28). Violation: without it, per-agent-hour cost (§4) makes 100k-agent runs computationally infeasible.

P13. Open-Core Boundary Fixed at Design Time. The agent contract, environment DSL, event-loop engine, and baseline psychology library are open (MIT); premium fine-tuned psychology models, the marketplace transaction layer, and managed/government deployments are commercial (ADR-20, §9); the boundary is set once. Tradeoff: forgoes some monetization flexibility. Operational implication: conformance-suite parity is guaranteed for the open core so third parties build against it without a hidden commercial dependency. Violation: retroactively closing an open component breaks the community trust the conformance-suite ecosystem depends on.

P14. No Real Individual Modeled Without Consent. Initial conditions may use aggregated, public, or licensed population data; never an identifiable individual as an agent without explicit, auditable opt-in (Scenario.provenance field's constraints, §11; T5, §22). Tradeoff: forecloses some high-value but ethically untenable use cases. Operational implication: the data-provenance block on every Scenario card is checked mechanically at the ethics gate. Violation: this is the platform's brightest ethical line; crossing it is a top-severity incident (FM-5, §23).

8. Domain Model

8.1 Conceptual Model

Polis's domain has three first-class concepts: an Agent (declared psychology + memory + repertoire + protocol), an Environment (resources + geography + institutions + deterministic resolution rule), and a tick (one five-phase advance of simulated time, §8.2). Every observable occurrence is an Event (§11); relationships between agents and aggregate observations over the event stream are derived, not primary — a Relationship and an EmergentMetric (§11) are both reducers over the Event log, never independently mutable state.

8.2 Tick Phase State Machine

From Phase To Phase Trigger Barrier Condition
(tick start) PERCEIVE orchestrator advances tick previous tick WRITE durable (I4)
PERCEIVE DELIBERATE all agents' perception payloads delivered no agent writes permitted in PERCEIVE
DELIBERATE ACT all agents' intents collected or per-agent timeout fired intents queued, not yet applied
ACT COMMUNICATE environment resolution applied, EnvironmentDelta produced all actions validated against I1
COMMUNICATE WRITE all inter-agent messages routed under ProtocolSpec bandwidth caps messages queued for memory consolidation
WRITE (tick end) memory consolidation + metric reduction + log durability complete I4 durability ACK issued

8.3 Agent Status State-Transition Table

From To Trigger Reversible?
(none) ALIVE spawn_tick reached, scenario initial conditions n/a
ALIVE DORMANT environment-declared dormancy condition (e.g. seasonal migration) yes, DORMANT → ALIVE
DORMANT ALIVE environment-declared reactivation condition yes
ALIVE DEAD MortalitySpec threshold crossed (starvation, age, exogenous event) no (I9) — fork only
DORMANT DEAD MortalitySpec threshold crossed while dormant no (I9)

8.4 Event Total Ordering & Causality

Every Event (§11) carries caused_by: List[EventId], forming a causal DAG. The (scenario_id, run_id, tick, phase, agent_id, seq) tuple (P10, Lamport §5) totally orders all events; caused_by additionally records which prior events causally justify this one (e.g. a MESSAGE event caused by the ACT event that sent it), which the conformance suite (§12.5) uses to detect causally-inverted replay bugs.

8.5 Determinism & Replay Semantics

LLMs are stochastic; the reproducibility posture (P3) has four mechanisms: (1) Frozen model versions — a scenario card pins exact model artefacts (model_pins, §11). (2) Seeded sampling — where the inference stack permits it (vLLM, temperature > 0), seeds derive deterministically from (scenario_seed, agent_id, tick, phase). (3) Tick-ordering determinism — the orchestrator imposes a canonical action-resolution order per tick; shard outputs merge in a defined order (ADR-07, §9). (4) Confidence bands, not bit-exactness — the published contract is distributional: an independent re-run of the same card lands inside a declared confidence band on the headline emergent metric (Reproducibility Rate, §26). Bit-exact replay is achievable, and used, for the environment-resolution-only regression suite (no LLM calls in the loop) — see ADR-16 (§9).

8.6 Fork Semantics

A fork is a new Scenario (§11) with parent set and fork_diff a JSONPatch (RFC 6902, §5) against the parent. I12 (§7) requires the resulting fork DAG stay acyclic and every scenario have at most one parent — a tree, not a general graph — so replay of any node resolves by walking a single parent chain.

8.8 Malformed-Input Example

An environment DSL document referencing a nonexistent resource id (resource: "grain_reserve_v2" where the loaded template only declares "grain") fails JSON Schema validation (ADR-18, §5) at load time with a schema-path error pointing at the offending resources[].id reference; the Environment Runtime refuses to instantiate and the Control Plane returns a 422-equivalent scenario-rejection with the schema-path diagnostic — the run never dispatches (fails closed, consistent with I10's fail-closed posture).

8.9 Failure-Path Example

A shard worker crashes mid-WRITE (FM-1, §23) after COMMUNICATE completed but before memory consolidation is durable. On restart: the orchestrator detects the missing durability ACK for tick=42 (I4 telemetry), replays the determinism log from the last durable tick (tick=41), re-derives tick=42's COMMUNICATE output deterministically from the logged ACT-phase events (§8.5, mechanism 3), and re-executes WRITE. No agent-visible state is lost; the recovery is invisible to Studio beyond a tick-latency spike (M1/M2, §28).

12. Phase 0 — Repo Skeleton & Correctness Kernel

12.1 Objectives

Stand up the repo skeleton (§10) and the correctness kernel: a single-process, single-shard event loop that can run a small deterministic population end-to-end. Establish the Core Schema v0 (subset of §11) and the first conformance fixtures. No parallelism, no multi-provider routing, no cache — those are later phases (§15, §19).

12.2 Detailed Implementation Steps

core/schema implements Agent, Event, Scenario (v0 subset of §11) as Pydantic v2 models (ADR-03). core/contracts implements the Agent/Environment/Event-Loop ABCs (§8) as Python abstract base classes — signatures only, enforcing I1/I6/I7 structurally. orchestrator/scheduler implements the five-phase tick (§8.2) synchronously, single process, honoring the phase-barrier invariant I3 (P9). orchestrator/determinism stamps every event (scenario_id, run_id, tick, phase, agent_id, seq) (I2, Lamport §5) to an append-only local file. agents/frontier wires one frontier-model agent class to a hosted API with a single "modal villager" PsychologyProfile (§11). env/dsl loads a hand-written YAML for a 30-location village (homes, fields, well, market, tavern) with two resources (grain, water) — no expression engine yet (full DSL is ADR-18, Phase 2, §14).

12.3 Deliverable

A 100-agent, single-node run stable for one simulated year (365 ticks, 1 tick = 1 sim-day), inspectable via a terminal-based tick-replay tool reading the determinism log directly.

12.4 Acceptance Criteria

  • 365-tick run completes without an unhandled exception on a single 8-vCPU node.
  • Zero I1/I3 violations across the full run (polis-sim-harness assertion count = 0 failures).
  • Determinism-log replay of the same scenario card reproduces identical event counts per phase (bit-exact at this phase — no LLM sampling variance yet permitted to differ, since Phase 0 uses greedy/deterministic decoding).
  • Named fixture fixtures/phase0_village_100.yaml passes end-to-end in < 10 minutes wall clock.

12.6 Pitfalls

  • Silent phase-crossing: a naive implementation lets an agent's ACT-phase side effect leak into COMMUNICATE before the barrier — manifests as relationship strength updates one tick early; caught only by the I3 assertion, not by casual inspection. Debug via polis-sim-harness per-invariant assertions (§7).
  • Determinism-log torn writes: unflushed buffered writes on process crash corrupt the last N log entries — root cause is missing fsync before the I4 durability ACK; signal is a hash-chain mismatch on next-start replay.
  • Greedy-decoding false confidence: Phase 0's deterministic decoding masks the P3 distributional-reproducibility problem that appears the moment temperature > 0 is introduced (Phase 1, §13) — do not conclude "reproducibility is solved" from Phase 0 alone.

12.7 Performance Concerns

Single-process synchronous tick means DELIBERATE-phase LLM latency is fully serial across 100 agents; expect tick p50 well above the §4 target (which assumes GPU batching, not introduced until Phase 7, §19) — Phase 0 explicitly does not gate on M1/M2 (§28).

12.8 Edge Cases

Malformed DSL resource reference (§8.8); an agent emitting a hallucinated out-of-repertoire action (I1); a scenario card missing rng_seed (reject at load); a frontier-provider timeout mid-DELIBERATE (per-agent timeout stub, full backoff logic is ADR-05/Phase 7).

12.9 Failure Analysis

A crash mid-WRITE (§8.9) at this phase loses only the in-flight tick, since no I4-durable ACK was issued for it; recovery is "delete the partial tick's log tail, replay from last ACKed tick" — the full production recovery path (shard-level, multi-node) is built in Phase 3 (§15) and Phase 7 (§19).

12.10 Operational Notes

No dashboards yet; polis-sim-harness console output is the only observability surface. Structured JSON logging to stdout, one line per event, tagged with the full I2 tuple for grep-based debugging until OpenTelemetry lands (ADR-19, Phase 6, §18).

13.1 Objectives

15. Phase 3 — Event-Loop Parallelization & Determinism Log

15.1 Objectives

Move from Phase 0's synchronous single-process tick to a multi-shard, barrier-synchronized parallel event loop (P9, Kahn Process Networks §5), with the determinism log promoted to an append-only on-disk partitioned structure.

15.2 Detailed Implementation Steps

orchestrator/shard implements agent_id mod n sharding (ADR-07) across a process pool; each shard runs PERCEIVE/DELIBERATE/ACT locally, then a cross-shard barrier merges ACT outputs in canonical order (§8.5, mechanism 3) before COMMUNICATE begins — implementing the Kahn-Process-Network-style deterministic composition of independently-scheduled sequential processes (§5). orchestrator/determinism moves the log to append-only on-disk files with a Kafka-style partition-per-shard layout (§5 Kafka ref-impl), each entry idempotency-keyed on the full I2 tuple. The tick-scheduler hot path (the merge/barrier logic) is profiled and, where it dominates wall-clock, ported to Cython (ADR-08). orchestrator/scheduler adds a per-agent DELIBERATE timeout with fallback to the Phase 1 memory-adapter's last cached intent (foreshadowing the full proxy cache of Phase 7, §19).

15.3 Deliverable

15.4 Acceptance Criteria

  • Zero I2 duplicate-key violations across a 24-hour soak run.
  • Barrier-violation count (I3) = 0 across 10,000 ticks under injected per-shard latency jitter (chaos fixture, below).
  • Named fixture fixtures/phase3_shard_barrier_chaos.yaml passes with recovery time ≤ 5 min (RTO, §4) after a killed shard worker.

  • Barrier deadlock under partial failure: a naive barrier implementation waits indefinitely for a crashed shard's ACT output — mitigated by the per-agent DELIBERATE timeout (§15.2) plus a shard-level heartbeat timeout that triggers the FM-1 recovery path (§23) rather than an indefinite stall.
  • Non-canonical merge order: if the cross-shard ACT merge uses arrival order instead of a declared canonical order (e.g. agent_id ascending), replay diverges between runs with different scheduling jitter — this is the single most common source of "unreproducible" bug reports; always merge by the declared canonical key, never wall-clock arrival.
  • Cython hot-path drift from the Python reference: once ADR-08's Cython path exists, it is easy for a bugfix to land in only one implementation — conformance fixtures must run against both paths in CI until the Python path is retired.

15.7 Performance Concerns

Cross-shard barrier synchronization overhead grows with shard count; at 8 shards on one node this should stay under 50ms per tick — the cross-node case (Phase 7, §19) has a separate, larger budget (M11, §28). Profile lock contention on the shared determinism-log writer; prefer per-shard log partitions merged asynchronously over a single shared-lock log.

15.8 Edge Cases

A shard that never crashes but consistently runs slow (soft straggler, not a hard failure) — must still be bounded by the per-agent timeout, not allowed to silently degrade every tick's p99; clock skew between worker processes affecting wall-clock-based timeout logic (use monotonic clocks, never wall-clock, for timeout arithmetic); a replay that must merge logs from a run that changed shard count mid-run (not supported — shard count is fixed per run, a rebalance requires forking, §8.6).

15.9 Failure Analysis

See §8.9 (Failure-Path Example) for the canonical WRITE-phase-crash recovery trace; this phase is where that recovery path is first implemented and load-tested (the chaos fixture, §15.5). 20. Phase 8 — Cultural Drift & Language Emergence Primitives

20.1 Objectives

Implement the fourth and fifth emergent capabilities in the P6 sequence: cultural drift (norm transmission, prestige bias, conformity dynamics) and language emergence (novel-term coinage and propagation), each with its own conformance fixtures before the next phase's political-formation work depends on them.

20.2 Detailed Implementation Steps

agents/psychology extends cultural_overlay with norm-transmission rules: prestige-bias weighting (higher-strength Relationship partners disproportionately influence value drift, Henrich §5) and conformity dynamics (value convergence pressure proportional to local network density). A cultural-distance EmergentMetric (§11) is defined per cohort per region, feeding a Lens heatmap (§18). The communication protocol (ProtocolSpec, §11) is extended to allow agents to coin novel terms outside their initial vocabulary; a novelty-propagation reducer tracks adoption rate across the population, materializing a language-drift corpus (output_type: CORPUS, §16.8) to ClickHouse per region per generation.

20.3 Deliverable

A reproducible "two villages diverge" demo: two initially-identical village populations, geographically separated, tracked over 200 sim-years, showing measurable cultural-distance divergence and at least one novel term reaching > 50% adoption in one village and 0% in the other.

20.4 Acceptance Criteria

  • Cultural-distance metric shows monotonic divergence (no reversion) across the 200-sim- year reference run, with a documented confidence band (P3) on the divergence rate.
  • At least one coined term reaches ≥ 50% adoption in its origin village within 50 sim-years in ≥ 3 of 5 independent seeded runs (a Reproducibility-Rate-style claim, §26).
  • Named fixture fixtures/phase8_two_villages_200y.yaml completes and reproduces the qualitative divergence pattern (not necessarily the exact term) across reruns.
  • Prestige-bias weighting demonstrably changes convergence rate vs. a prestige-bias-disabled control (statistically distinguishable at p < 0.05 over 20 paired runs).

20.6 Pitfalls

  • Divergence-by-noise vs. divergence-by-mechanism: without the prestige-bias-disabled control fixture, apparent cultural divergence could be pure sampling noise — always compare against the ablation, not just presence of divergence.
  • Corpus-storage schema mismatch: CORPUS-type metrics (raw text) do not fit ClickHouse's typical numeric-column optimization path — a naive implementation degrades ingestion performance (§16.6's per-event-insert pitfall, recurring in a new form); use a dedicated text-optimized column family or a separate object-storage side-channel indexed by tick/region.
  • Prestige-bias runaway feedback: an unbounded prestige-bias weight can produce a single-agent-dominates-all-values collapse rather than gradual drift — bound the weight and validate against the conformity-saturation fixture.

20.7 Performance Concerns

Cultural-distance computation over large cohorts is O(cohort²) if implemented naively (pairwise value-vector distance) — use a sketch-based or centroid-based approximation above a cohort-size threshold, trading exactness for the tick-latency budget (§4).

20.8 Edge Cases

A coined term colliding with an existing vocabulary token (must be disambiguated, not silently merged); cultural drift interacting with the mortality model (a term's sole speakers all dying before it propagates — a legitimate emergent outcome, not a bug, but must be distinguishable from a propagation-tracking bug via the adoption-curve fixture); cross-region contact reintroducing convergence after divergence (must be handled by the same reducer, not a special case).

20.9 Failure Analysis

A corpus-materialization failure (ClickHouse text-column write error) degrades gracefully: the scalar cultural-distance metric continues to update even if the raw-text corpus write fails, with the failure logged and retried — the qualitative demo (§20.3) does not depend on zero corpus-write failures, only on the scalar metric's integrity.

24. Operational Readiness

Metrics & tracing. OpenTelemetry (ADR-19) traces every Control-Plane request and every tick's phase transitions; per-tick spans enable forensic profiling of a specific slow tick. Structured JSON logs tag every line with the full I2 event tuple where applicable.

Dashboards. One dashboard per EmergentMetric type (§16); an ingestion-lag SLO dashboard; a cost dashboard tracking polis.cost.per_agent_hour against the M4 target (§28); an ethics-gate determination dashboard (PASS / PASS_WITH_CONDITIONS / HOLD / REJECT rates).

Alerting philosophy. Alert on invariant violations (I1–I13 telemetry) and SLO breaches (§4), never on raw resource utilization alone — a utilization spike with no invariant or SLO impact is not paged.

SLOs. Control Plane 99.5% availability; Orchestrator 99.0% (best-effort batch workload); tick p95 ≤ 5 s at 1,000 agents (§4); RTO ≤ 5 min; RPO = 0 ticks (I4).

Incident response. Severity tiers keyed to the Failure Modes table (§23): FM-5 (ethics- gate bypass) and FM-2 (log corruption) are Sev-1 (immediate page, public-disclosure review per T1–T5, §22); FM-3/FM-4/FM-11 are Sev-2 (on-call, no external disclosure required).

Named runbooks. docs/runbooks/shard-crash-recovery.md (FM-1), docs/runbooks/ ethics-gate-outage.md (§18.9), docs/runbooks/cross-node-partition.md (FM-11).

Backup/restore. Object storage (scenario cards, run blobs) is versioned with 90-day retention; ClickHouse/TimescaleDB snapshots nightly, retained 30 days; the determinism log is the append-only source of truth and is never restored from a lossy backup — only from its own replicated partitions.

Deployment topology. Managed multi-tenant cloud for Phases 0–8; a deferred single- tenant on-prem/air-gapped SKU (§35) for government-tier deployments, gated on SOC 2 Type II, ISO 27001, and a FedRAMP-equivalent posture driven by the specific customer's requirement, with audit-log retention of at least 7 years for that tier.

Canary / rolling upgrade / rollback / migration. Control-Plane and Orchestrator releases roll out canary-first to a small scenario-dispatch percentage; any I-series invariant violation observed in canary blocks promotion; rollback is a version-pin revert, never a schema rollback (schema changes are additive-only, I11, so a code rollback remains schema-compatible).

Research-ethics review process. Phase 1–8: a three-member external advisory board (ethicist, computational social scientist, domain practitioner) reviews any HOLD_FOR_REVIEW-triggering scenario, with decisions logged; Phase 9+ government-tier deployments add a standing review committee with a documented charter and conflict-of- interest policy, modeled on established human-subjects-research review practice.

25. Compatibility & Versioning

Wire compatibility. Event and metric wire formats (NATS/Kafka payloads, §16) follow Core Schema versioning (I11): additive fields only after v1.0; consumers ignore unknown fields.

Storage compatibility. ClickHouse/TimescaleDB schema migrations are additive-column-only in the steady state; a genuinely breaking storage change requires a dual-write migration window documented in an ADR (§9 template) with an explicit cutover date.

Schema evolution. Governed by SemVer 2.0.0 (§5 RFC): a MAJOR bump requires a migration ADR and a deprecation window (minimum one full phase); MINOR bumps are additive fields; PATCH bumps are non-schema fixes.

API stability. The Control-Plane scenario API and the Agent/Environment/Event-Loop contracts (§8) are stable within a MAJOR version; the CLI/SDK follow the same MAJOR-version contract as the API they wrap.

Migration & deprecation policy. A deprecated field remains readable for at least one full MAJOR-version cycle before removal; every deprecation is announced in CHANGELOG.md (§10) with the removal-eligible version.

Rolling-upgrade guarantees. A mixed-version Orchestrator fleet (during a rolling upgrade) must agree on tick-phase barrier semantics — any change to the barrier protocol itself (not just schema) is treated as a MAJOR version requiring a full-fleet drain, never a rolling upgrade.

26. Testing & Verification Strategy

Unit tests cover every Core Schema type's validation logic and every contract's ABC enforcement (I1, I6, I7 structural checks).

Integration tests exercise a full tick across PERCEIVE→WRITE on a multi-shard local cluster (Phase 3, §15 fixtures).

Property-based tests assert I1–I13 hold under randomized action/event sequences, mirroring the Jepsen adversarial-testing philosophy (§5 Kingsbury) rather than happy-path-only fixtures.

Differential tests compare the Python reference tick-scheduler path against the Cython hot path (ADR-08) on identical inputs, catching the drift pitfall noted in §15.6.

Fuzzing targets the Environment DSL loader (fuzz/env_dsl/, §14.4) and the agent action-repertoire validator with adversarially-malformed and hallucinated inputs.

Chaos testing injects shard crashes (§15.5), network partitions (§19.5), and provider rate-limit storms (FM-3) against a running cluster, verifying RTO/RPO (§4) empirically rather than by inspection alone.

Deterministic replay testing re-executes the environment-resolution-only path bit-exactly (ADR-16) as a regression gate on every PR touching env/runtime.

Soak testing runs the Phase 3 24-hour dup-key-detection fixture (§15.5) and a 30-day ethics-gate-bypass audit window (§18.4) on a fixed cadence.

Fault injection covers KV-cache exhaustion (FM-4), determinism-log torn writes (FM-2), and cache staleness (FM-9) via targeted chaos scripts in benchmarks/.

Conformance testing (§12.5-style, one suite per phase) gates every template-store admission (I13) and every merged PR touching the agent contract, environment runtime, or event-loop engine — the reproducibility discipline requires every such PR to extend the conformance suite, never merely pass the existing one.

Performance-regression gating ties every M-table target (§28) to a CI gate: a PR that regresses a target below its Phase Gate value fails CI, not just a post-merge dashboard alert.

Every test class above ties back to the System Invariants (§7) it exercises and the per-phase Conformance Fixtures (N.5) that instantiate it concretely.

29. Scalability Analysis

What stays constant. Per-event stamping cost (I2) is O(1) regardless of population size; the environment-resolution API surface (I6/I7) does not change shape with scale.

What grows, and the Big-O. Cross-shard barrier merge cost grows O(shards) per tick (§15.7); faction-formation clustering (§21.7) is the steepest per-tick cost, O(agents × belief-dimensionality) naively, mitigated to a coarser cadence; ClickHouse storage grows O(agents × events-per-tick × ticks) before compression (§32 #3).

Named bottlenecks, in order. (1) DELIBERATE-phase LLM call latency and cost — the dominant constraint below Phase 7's cache/distillation maturity (P8). (2) Cross-node barrier synchronization overhead (M11) once multi-node sharding is introduced (§19). (3) Faction-formation and cultural-distance reducer cost at 100,000-agent scale (§20.7, §21.7). (4) ClickHouse ingestion/storage cost at sustained high-population continuous operation (§32 #3), the binding constraint for any future continuous shadow-society workstream (deferred, §35).

Horizontal vs. vertical scaling. Agent population scales horizontally (more shards, more nodes, ADR-07); per-tick latency for a fixed population scales vertically only up to the GPU-batching ceiling (§4), beyond which horizontal GPU-cluster scaling (§19) is required.

Sharding/partitioning. agent_id mod n (ADR-07) is chosen for simplicity and even load distribution; it does not co-locate frequently-interacting agents (e.g. dense local communities), which is an accepted tradeoff — geography-aware sharding is a lever available beyond the current ceiling (below) but is not built, since agent_id mod n has not yet been shown to bottleneck at the Phase 9 target scale.

Coordination overhead. Cross-node barrier coordination (§19) is the primary coordination cost; it grows with node count, not agent count directly, which is why node count (not agent count) is capped more conservatively relative to headroom in §4.

Practical ceiling and levers beyond it. The Phase 9 100,000-agent target is not the platform's structural ceiling; the practical ceiling before a further architectural change is required is estimated (§32) in the low millions of agents, bounded by ClickHouse ingestion cost and cross-node coordination overhead. Levers beyond that ceiling: geography- aware sharding (co-locating interacting agents to cut cross-shard COMMUNICATE-phase traffic), a tiered storage architecture (hot ClickHouse window + cold object-storage archive, reducing the working-set the ingestion pipeline must sustain), and a hierarchical faction-formation reducer (regional pre-aggregation before a global merge, cutting the O(agents × dimensionality) cost).

30. Mental Models & First Principles

MM1. "An agent is a state machine wrapped around a stochastic policy; the event loop is its clock." Predicts: barrier-phase design is mandatory once policy calls are asynchronous/expensive. Bug class without it: agents racing across tick boundaries. Applies in §8.2 and §15.

MM2. "Reproducibility is a distributional claim whenever a sampler sits in the loop; only sampler-free layers can be bit-exact." Predicts: environment-resolution-only replay can be exact (ADR-16) while full-run replay cannot. Bug class without it: false bit-exact- replay claims. Applies in §8.5 and §25.

MM3. "A cache is correct only over an equivalence class you can name; naming the wrong equivalence class is silent data corruption, not a crash." Predicts: the psychology-proxy cache needs an explicit, testable equivalence definition. Bug class without it: the cache returns behaviorally-wrong actions with no error signal. Applies in §11 and §19.

MM4. "Emergent behavior is execution-order-sensitive; making the order explicit is cheaper than debugging its absence." Predicts: implicit-ordering systems (Mesa/NetLogo style) become undebuggable at scale. Bug class without it: irreproducible faction-formation results. Applies in §8.4 and §7 (I2/I3).

MM5. "Institutions are the aggregate memory of a population; agent memory alone cannot explain multi-generational drift." Predicts: cultural drift and political formation need environment-level (InstitutionLayer) state, not just per-agent memory. Bug class without it: modeling culture purely as agent memory, which cannot survive agent turnover. Applies in §20 and §21.

MM6. "Ethics gates are structural, not aspirational, only if they block dispatch mechanically." Predicts: a documentation-only gate is bypassed under deadline pressure. Bug class without it: FM-5. Applies in §7 (I10) and §22 (T1–T5).

MM7. "Cost is a first-class architectural input, not a post-launch optimization." Predicts: deferring cost consideration forces expensive later rewrites instead of designing it in from Phase 0. Bug class without it: an economically nonviable Phase 7. Applies in §4, §19, §28.

MM8. "A scenario card is a contract, not a log dump — it must be sufficient to re-derive the run, not merely describe it." Predicts: under-specified cards (missing a model pin or seed) look fine until the first fork attempt fails. Bug class without it: forks that silently diverge from their parent. Applies in §11 (Scenario) and §17.

Stanford Generative Agents (Smallville) made the opposite bet from Polis: maximize per-agent narrative fidelity at trivial scale, with no reproducibility formalism, because it was a research demo rather than a platform others build on (§5, Park et al. 2023).

DeepMind Concordia wins where strict game-master arbitration is preferable to a declarative environment DSL — useful when environment rules are too situational to pre-declare, at the cost of a bespoke arbiter per scenario rather than a reusable DSL.

Altera AI Project Sid demonstrates the closest scale/fidelity combination to Polis's Phase 9 target, but without a published reproducibility or ethics-gate framework — validating that the scale is achievable while leaving the governance gap Polis is designed to close (§5; §22).

32. Back-of-Envelope Capacity Model

  1. GPU fleet size, Phase 1 GA scale. GPUs = ceil(target_agent_hours_per_week / seconds_per_week / agent_ticks_per_sec_per_gpu). At an assumed 500 agent-ticks/sec per GPU (batch depth 512, §4) and a 10M-agent-hour/week target: 10,000,000 / 604,800 ≈ 16.5 agent-ticks/sec required → ≈ 1 GPU of raw throughput, provisioned to a small redundant fleet in practice.
  2. KV-cache RAM per node. RAM = batch_depth × context_len × 2(K,V) × num_layers × head_dim × num_heads × bytes_per_param. At batch depth 512, context 4,096 tokens, an ~80-layer model class, this lands in the ≤ 60 GB range on an H100 (80 GB) — the exact figure that fixes the §4 KV-cache ceiling.
  3. Determinism-log storage growth/year at 100,000-agent continuous scale. events/tick = 5 phases × 100,000 agents = 500,000; at 24 ticks/day (1 tick = 1 sim-hour): 12,000,000 events/day × ≈ 300 bytes/event ≈ 3.6 GB/day raw → × 365 ≈ 1.31 TB/year raw → ÷ 1.6 compression amplification (§4) ≈ 820 GB/year effective ClickHouse footprint.
  4. FD budget check. FDs/node = shards(64) × connections_per_shard(≈15: storage + metrics-bus + ~12 dyadic conversations) ≈ 960 FDs/node — well under the 4,096 soft ceiling (§4), a 4× headroom factor.
  5. Live-streaming bandwidth, Phase 1 scale. bytes/sec = agents(1,000) × metrics/tick(20) × payload(200 bytes) / tick_seconds(2) = 2,000,000 bytes/sec ≈ 16 Mbps — comfortably inside a same-rack NATS deployment.
  6. Reproducibility-harness sample size. Detecting a shift from RR = 0.85 to RR = 0.70 (the FM-6 threshold) at 95% confidence requires n ≈ 68 re-run scenarios (standard two-proportion power calculation) — sets the minimum published-scenario sample size the harness (§17) must maintain.
  7. Psychology-proxy cache working set. size = distinct_hashes(≈200: 3 fine-tuned models × ≈65 cultural-overlay combinations) × perception_buckets(≈10,000/hash) × entry_size(≈2 KB) ≈ 4 GB — fits a single Redis node comfortably, validating ADR-06.
  8. Marginal cost per agent-hour. GPU-hour cost($2.50) ÷ agent-ticks/GPU-hour(500 × 3,600 = 1,800,000) ≈ $0.0000014 marginal GPU cost/agent-hour before cache savings; at the 60% cache-hit floor (M3, §28) effective marginal cost ≈ $0.00000056/agent-hour — the M4 target of a 5× total-cost reduction by Phase 7 layers non-GPU overhead (storage, control plane) atop this floor.

34. Alternative Architectures (Roads Not Taken)

Alternative 1 — Optimistic Time-Warp rollback.

  agent A: ---tick1---tick2---tick3--X (violation detected)
                                     |
                              rollback + anti-message
  agent B: ---tick1---tick2---tick3---tick2'---tick3'---

Regime where it wins: very low agent-count, very cheap per-agent compute, deep-lookahead scenarios (classical large-scale network/discrete-event simulation). Real system: the Time Warp mechanism (Jefferson, 1985, §5). Rejected because: LLM inference calls are too expensive to speculatively discard on rollback — an anti-message would waste an entire, costly DELIBERATE-phase LLM call, unlike cheap rule evaluation in classical DES.

Alternative 2 — Fully centralized single-process simulation.

  +--------------------------------------+
  |  single process: all agents + env    |
  |  synchronous scheduler, no sharding  |
  +--------------------------------------+

Regime where it wins: population < 5,000, single-researcher local runs, Phase-0-scale demos. Real system: Mesa, NetLogo (§31). Rejected because: does not scale past the Phase 1 1,000-agent ceiling (§4), let alone the Phase 9 100,000-agent target.

Alternative 3 — Fully decentralized CRDT-based simulation.

  agent A (local CRDT replica) <--merge--> agent B (local CRDT replica)
       ^                                          ^
       +--------------- gossip protocol ----------+
  (no central orchestrator, no tick barrier)

Regime where it wins: federated deployments tolerant of eventual (not tick-ordered) consistency, with no shared-clock requirement. Real system: CRDT-based collaborative systems (e.g. Automerge). Rejected because: emergent institutional state (§21) requires a single agreed tick-ordered view of institutional transitions; eventual consistency cannot support the ethics gate's need for a well-defined "this scenario, this population size, right now" dispatch decision (I10).

Alternative 4 — Deterministic bit-exact execution VM.

  +---------+   +---------+   +---------+
  | replica |   | replica |   | replica |   consensus over
  |   VM 1  |==>|   VM 2  |==>|   VM 3  |   deterministic
  +---------+   +---------+   +---------+   instruction stream

Regime where it wins: adversarial multi-party settings requiring byte-for-byte verifiable replay with no trust in the operator (e.g. blockchain rollup execution). Real system: Ethereum-Virtual-Machine-style deterministic execution. Rejected because: LLM sampling is not expressible as a deterministic VM instruction without abandoning the frontier-model agent tier (P1, P3), and consensus overhead is unjustified for a single-operator research platform with no adversarial multi-party trust requirement.

36. Glossary

  • Action Repertoire. The closed set of ActionTypes an agent may emit; enforced by I1.
  • Agent. A simulated entity with a declared psychology, memory, action repertoire, and communication protocol.
  • Agent-hour. One simulated agent advanced through one simulated hour; the unit of compute and of throughput targets (§28).
  • Barrier Synchronization. The explicit wait-for-all-shards checkpoint between tick phases (P9, I3).
  • Conformance Suite. The reference test suite an agent class, environment, or memory adapter must pass to ship or be admitted to the Template Store (I13).
  • Control Plane. The stateless service exposing the scenario API, ethics gate, and budget guard.
  • Cultural Overlay. The PsychologyProfile field pointing to a Culture record shaping values, beliefs, and drift dynamics (§20).
  • Cultural Drift. Norm transmission and value convergence/divergence over generations (Phase 8, §20).
  • Determinism Log. The append-only, totally-ordered event record that is the run's source of truth (§11, I2).
  • EmergentMetric. A reducer over the event stream, published live and stored durably.
  • Ethics Gate. The Control-Plane check that runs before a triggering scenario dispatches (I10).
  • Event. The atomic, totally-ordered unit of a Polis run.
  • Faction-Formation Reducer. The clustering reducer over PsychologyProfile.beliefs producing faction counts and membership (§21).
  • Fork. A new run derived from a parent scenario card via a JSONPatch diff.
  • Fork DAG. The acyclic lineage of scenario forks (I12).
  • Institution Layer. The environment subsystem modeling currencies, courts, schools, and emergent political assemblies (§21).
  • KV-Cache. The transformer key/value cache reused across batched inference requests (PagedAttention, §5).
  • Lens. The post-run analysis and replay surface.
  • Memory Adapter. The per-agent interface for episodic/semantic memory read, write, and consolidation (§11).
  • Modal Psychology. A small, fine-tuned model absorbing the bulk of routine agent ticks at low cost.
  • Perception Digest. The hashed perception payload used as half the psychology-proxy cache key (§11, P12).
  • Polis Studio. The composer and live-run cockpit web UI.
  • Proxy Cache (Psychology-Proxy Cache). The (psychology_hash, perception_digest)-keyed cache short-circuiting behaviorally-equivalent LLM calls (P12, §19).
  • Psychology Profile. The structured object declaring an agent's traits, values, beliefs, and decision policy.
  • Reproducibility Rate (RR). Fraction of published runs whose re-execution lands inside the declared confidence band.
  • Scenario Card. The serialized, hash-addressable, forkable artefact that fully specifies a run.
  • Shadow Society. A deferred continuously-running simulation tracking real-world conditions (§35).
  • Sharding. Partitioning agents across worker processes/nodes by agent_id mod n (ADR-07).
  • Sim-year. One simulated calendar year of agent activity.
  • Template Store. The marketplace of civilization templates, gated by conformance and the ethics gate (§21).
  • Tick. One five-phase simulation step (PERCEIVE, DELIBERATE, ACT, COMMUNICATE, WRITE).
  • Tick Phase. One of the five ordered stages within a tick (§8.2).
  • Time-Series Store. ClickHouse (metrics/events) plus TimescaleDB (relationship snapshots).
  • Total Ordering. The property that (scenario_id, run_id, tick, phase, agent_id, seq) totally orders all events in a run (P10).
  • Trust Boundary. The structural separation preventing the Environment from reading agent internals (P5, I6).
