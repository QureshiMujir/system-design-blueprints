⬜ Phase 0 — Repo Skeleton & Correctness Kernel §12

Objectives

Stand up the repo skeleton (§10) and the correctness kernel: a single-process, single-shard event loop that can run a small deterministic population end-to-end. Establish the Core Schema v0 (subset of §11) and the first conformance fixtures. No parallelism, no multi-provider routing, no cache — those are later phases (§15, §19).

Deliverable

A 100-agent, single-node run stable for one simulated year (365 ticks, 1 tick = 1 sim-day), inspectable via a terminal-based tick-replay tool reading the determinism log directly.

Acceptance
  • 365-tick run completes without an unhandled exception on a single 8-vCPU node.
  • Zero I1/I3 violations across the full run (polis-sim-harness assertion count = 0 failures).
  • Determinism-log replay of the same scenario card reproduces identical event counts per phase (bit-exact at this phase — no LLM sampling variance yet permitted to differ, since Phase 0 uses greedy/deterministic decoding).
  • Named fixture fixtures/phase0_village_100.yaml passes end-to-end in < 10 minutes wall clock.
Fixtures
Fixture Purpose Expected Output
phase0_single_agent_tick.yaml one agent, one tick, sanity 5 events, one per phase, I2-valid
phase0_village_100.yaml 100-agent, 365-tick stability zero I1/I3 violations, durable log
phase0_malformed_dsl.yaml invalid resource reference (§8.8) schema-validation rejection, no dispatch
phase0_out_of_repertoire.yaml forced hallucinated action I1 rejection + polis.action.rejected emitted
phase0_replay_regression.yaml replay same seed twice identical event-type counts per phase
Pitfalls
  • Silent phase-crossing: a naive implementation lets an agent's ACT-phase side effect leak into COMMUNICATE before the barrier — manifests as relationship strength updates one tick early; caught only by the I3 assertion, not by casual inspection. Debug via polis-sim-harness per-invariant assertions (§7).
  • Determinism-log torn writes: unflushed buffered writes on process crash corrupt the last N log entries — root cause is missing fsync before the I4 durability ACK; signal is a hash-chain mismatch on next-start replay.
  • Greedy-decoding false confidence: Phase 0's deterministic decoding masks the P3 distributional-reproducibility problem that appears the moment temperature > 0 is introduced (Phase 1, §13) — do not conclude "reproducibility is solved" from Phase 0 alone.

⬜ Phase 1 — Agent Contract & Psychology Profile §13

Objectives

Formalize the Agent Contract (§8) as production Pydantic v2 models, build the psychology profile generator, and add a real memory adapter (vector-store backed, ADR-17). Introduce mortality rules and the first multi-agent emergent behavior (dyadic conversation).

Deliverable

100-agent, 30-sim-day run with dyadic conversations and a public-square broadcast producing an inspectable relationship graph (Relationship, §11) and a first emergent metric (average daily action-type distribution).

Acceptance
  • Core Schema v1.0 locked (I11 in force from this point forward); schema-diff CI gate (ADR-based) passes with zero non-additive changes across 3 subsequent PRs.
  • Psychology-stability conformance fixture: 1,000 ticks with zero un-logged big_five drift (I5).
  • Memory adapter capacity/forgetting-curve fixture passes at declared capacity ± 5%.
  • Named fixture fixtures/phase1_dyadic_100.yaml produces ≥ 50 distinct Relationship rows with kind populated.
Fixtures
Fixture Purpose Expected Output
phase1_psychology_stability.yaml 1,000-tick drift check zero un-logged mutations (I5)
phase1_memory_capacity.yaml forgetting-curve correctness recall rate matches declared curve ± 5%
phase1_dyadic_100.yaml 100-agent, 30-day conversation ≥ 50 Relationship rows
phase1_mortality_starvation.yaml forced grain scarcity Death events at declared threshold, I9 held
phase1_schema_v1_lock.yaml schema-compat regression zero non-additive diffs vs. v1.0 baseline
Pitfalls
  • Memory-adapter capacity miscalibration: an under-sized vector store silently drops the oldest episodic memories before forgetting_curve says it should, producing agents that "forget" formative relationships too early — detected only by the capacity fixture, not by casual replay inspection.
  • Psychology-generator correlation collapse: naive independent Big-Five sampling produces population-level trait correlations inconsistent with the declared cultural_overlay (Henrich, §5) — validate against published population norms, not just marginal distributions.
  • Conversation bandwidth starvation: an unbounded public-square channel lets a few agents monopolize broadcast slots — ProtocolSpec bandwidth caps must be enforced per tick, not per run.

⬜ Phase 2 — Environment DSL & Resource/Institution Layers §14

Objectives

Replace the Phase 0 hand-written YAML with the full Environment DSL v1 (ADR-18): YAML-with-expressions, JSON-Schema-validated (§5 RFC), covering resources, geography, and institutions. Ship three reference environments and the trade/alliance/conflict action primitives (P6's first three stages).

Deliverable

A 1,000-agent run on the market-town reference environment producing a stable price-index metric and a measurable alliance-size distribution, replayable from its scenario card.

Acceptance
  • JSON Schema validation rejects 100% of a fuzzed-malformed-DSL corpus (≥ 200 documents, fuzz/env_dsl/) with a schema-path diagnostic, none silently accepted.
  • Price-index metric converges to within 15% of the theoretical equilibrium for a controlled two-resource, fixed-supply test scenario.
  • 1,000-agent, 30-sim-day run completes with zero I6/I7 violations.
  • Named fixture fixtures/phase2_market_town_1k.yaml produces ≥ 10 distinct alliances with strength > 0.3.
Fixtures
Fixture Purpose Expected Output
phase2_dsl_fuzz_corpus.yaml 200+ malformed DSL documents 100% schema-rejection, zero silent accepts
phase2_price_equilibrium.yaml fixed-supply two-resource control price index within 15% of theoretical equilibrium
phase2_alliance_decay.yaml alliance decay-rule correctness strength decays per declared rate ± 5%
phase2_conflict_escalation.yaml escalation ladder ordering insult→boycott→sabotage sequence never skips a rung
phase2_env_isolation.yaml I6/I7 negative test zero successful direct-write or internal-read attempts
Pitfalls
  • Expression-grammar ambiguity: an under-specified precedence rule in the DSL's arithmetic expressions produces environment-author-surprising resolution order — mitigate with an explicit grammar spec reviewed against the JSON Schema, not inferred from the parser implementation.
  • Institution state-transition races: two agents' actions in the same tick both attempting to mutate the same Institution (e.g. a court ruling) — the deterministic resolution order (§8.5, mechanism 3) must define a canonical tie-break, or replay diverges.
  • Reference-environment overfitting: hand-tuning the three reference environments to "look emergent" defeats the purpose — validate against the price-equilibrium fixture's theoretical baseline, not visual plausibility.

⬜ Phase 3 — Event-Loop Parallelization & Determinism Log §15

Objectives

Move from Phase 0's synchronous single-process tick to a multi-shard, barrier-synchronized parallel event loop (P9, Kahn Process Networks §5), with the determinism log promoted to an append-only on-disk partitioned structure.

Deliverable

A 1,000-agent run sharded across 8 worker processes on a single node, with the determinism log durable and replayable from cold storage, and a documented per-agent DELIBERATE-timeout fallback path.

Acceptance
  • Determinism-log append throughput ≥ 50,000 events/sec sustained (§4 floor) on the reference 8-shard, 1,000-agent run.
  • Zero I2 duplicate-key violations across a 24-hour soak run.
  • Barrier-violation count (I3) = 0 across 10,000 ticks under injected per-shard latency jitter (chaos fixture, below).
  • Named fixture fixtures/phase3_shard_barrier_chaos.yaml passes with recovery time ≤ 5 min (RTO, §4) after a killed shard worker.
Fixtures
Fixture Purpose Expected Output
phase3_shard_barrier_chaos.yaml kill a shard mid-tick recovery ≤ 5 min, zero data loss (I4)
phase3_log_throughput.yaml sustained append load ≥ 50,000 events/sec/node
phase3_dup_key_soak.yaml 24-hour soak zero I2 duplicate-key violations
phase3_deliberate_timeout.yaml forced per-agent timeout fallback intent used, logged, no barrier stall
phase3_cross_shard_merge_order.yaml canonical ACT-merge ordering merge order identical across 3 repeated runs
Pitfalls
  • Barrier deadlock under partial failure: a naive barrier implementation waits indefinitely for a crashed shard's ACT output — mitigated by the per-agent DELIBERATE timeout (§15.2) plus a shard-level heartbeat timeout that triggers the FM-1 recovery path (§23) rather than an indefinite stall.
  • Non-canonical merge order: if the cross-shard ACT merge uses arrival order instead of a declared canonical order (e.g. agent_id ascending), replay diverges between runs with different scheduling jitter — this is the single most common source of "unreproducible" bug reports; always merge by the declared canonical key, never wall-clock arrival.
  • Cython hot-path drift from the Python reference: once ADR-08's Cython path exists, it is easy for a bugfix to land in only one implementation — conformance fixtures must run against both paths in CI until the Python path is retired.

⬜ Phase 4 — Time-Series Store & Emergent Metrics Bus §16

Objectives

Move emergent-metric and event storage from local files to the production Time-Series Store (ClickHouse + TimescaleDB, ADR-09/ADR-10) and stand up the live/cross-run metrics bus (NATS + Kafka, ADR-11/ADR-12), enabling live Studio panels and durable cross-run analytics.

Deliverable

Live Studio panels streaming price-index, alliance-size, and conflict-density metrics during an in-progress 1,000-agent run, with the full event history durably queryable in ClickHouse within 5 seconds of tick completion.

Acceptance
  • ClickHouse ingestion lag ≤ 5 s p95 from tick-WRITE-durable to query-visible (M8, §28).
  • Live NATS panel latency ≤ 500 ms p95 from metric-reducer output to Studio render.
  • Zero metric-value discrepancy between the live NATS stream and the durable ClickHouse value for the same (scenario_id, run_id, tick) across a 10,000-tick comparison run.
  • Named fixture fixtures/phase4_ingestion_lag.yaml holds p95 ≤ 5 s under a 100k-event/sec synthetic load spike.
Fixtures
Fixture Purpose Expected Output
phase4_ingestion_lag.yaml load-spike ingestion p95 lag ≤ 5 s under 100k events/sec
phase4_live_vs_durable_consistency.yaml NATS vs. ClickHouse agreement zero discrepancies across 10,000 ticks
phase4_reducer_correctness.yaml price/alliance/conflict reducers matches hand-computed reference values ± 1%
phase4_batch_insert_regression.yaml insert-pattern regression zero per-event (non-batched) inserts detected
phase4_bus_backpressure.yaml forced consumer slowdown producer backs off, zero event loss
Pitfalls
  • Per-event insert regression: a well-intentioned "real-time" code path that inserts one row per event instead of batching per tick silently degrades ClickHouse throughput over weeks, not immediately — guard with the batch-insert regression fixture in CI, not manual review alone.
  • Live/durable metric skew: if the NATS live path and the ClickHouse durable path compute the reducer independently (rather than the durable path being the source of truth replayed to NATS), floating-point or ordering differences silently diverge — always derive the live stream from the same reducer invocation as the durable write.
  • Unbounded metadata cardinality: tagging every metric with free-form metadata fields from Agent.metadata explodes ClickHouse column cardinality — cap and allowlist tag keys (FM-7, §23).

⬜ Phase 5 — Scenario Forking Engine & Reproducibility Harness §17

Objectives

Implement the Scenario Forking Engine (§8.6) and the reproducibility test harness that measures Reproducibility Rate (RR) against the confidence-band contract (P3, §8.5). Add the bias-audit framework.

Deliverable

A published-scenario reproducibility dashboard showing RR per scenario over its last 10 re-runs, and a working polis fork CLI verb (Phase 6 ships the full CLI, §18) that produces a valid child Scenario from a parent + a declared variable change. Cross- institution federation of scenario cards is explicitly out of scope here — PhaseDeferred("§17.3"), register row §35.

Acceptance
  • Reproducibility Rate ≥ 0.80 measured across a sample of ≥ 20 published scenarios (matches the Phase 1 GA target carried into M5, §28, with the Phase 2 GA target of ≥ 0.85 gating later).
  • Fork-creation cycle-detection rejects 100% of an adversarial cycle-inducing test corpus (I12).
  • Bias-audit framework reproduces the Schelling segregation-threshold result within a documented tolerance, or explicitly logs the deviation as a bias-profile entry.
  • Named fixture fixtures/phase5_fork_diff_roundtrip.yaml: forking then replaying a fork reconstructs the identical child scenario card byte-for-byte.
Fixtures
Fixture Purpose Expected Output
phase5_fork_diff_roundtrip.yaml fork then reconstruct byte-identical child card
phase5_cycle_rejection.yaml adversarial cycle attempts 100% rejection (I12)
phase5_repro_rate_sample20.yaml RR measurement RR ≥ 0.80 across 20 scenarios
phase5_bias_audit_schelling.yaml canonical-finding replication within documented tolerance or logged deviation
phase5_malformed_fork_diff.yaml corrupted JSONPatch rejected at load, no partial application
Pitfalls
  • Confidence-band overfitting: choosing a band wide enough to always "pass" defeats the metric's purpose — the band width must be derived from the metric's own historical variance, not tuned to hit a target RR.
  • Fork-diff drift from parent: if the parent scenario card is later corrected (schema-migrated, §25) without recomputing dependent forks' diffs, replaying an old fork against the new parent silently diverges — forks pin their parent's exact hash, never a mutable reference.
  • Bias-audit false negative: a canonical-finding replication that "passes" only because the test scenario was hand-tuned to the expected result — guard by pre-registering the expected result and tolerance before running the replication, mirroring Jepsen's adversarial-not-friendly testing posture (§5).

⬜ Phase 6 — Observation Surfaces (Studio & Lens Contracts) §18

Objectives

Ship the production Studio composer API and Lens replay/diff API contracts (§3), the CLI/ SDK, and Ethics Gate v1 in the Control Plane — the first surfaces a non-operator researcher touches directly.

Deliverable

A researcher can, without operator assistance, compose a scenario in Studio, watch it run live, replay it in Lens (including agent-zoom), fork it with one variable changed, and diff the two runs side by side — with every triggering scenario passing through Ethics Gate v1 before dispatch.

Acceptance
  • Scenario-Fork Latency (SFL) < 60 s from "click fork, change one variable" to first emergent-metric plot, at 1,000-agent scale (M6-adjacent target, gated at 100k-agent scale in Phase 7, §19, at < 10 min).
  • Ethics Gate v1 evaluates 100% of dispatched scenarios against all five triggers with zero bypass (I10) across a 30-day operational window.
  • CLI round-trip (polis run → polis fork → polis export) produces a re-importable scenario card on a clean environment.
  • Named fixture fixtures/phase6_ethics_gate_trigger_matrix.yaml: all five trigger conditions independently exercised, each producing the correct determination.
Fixtures
Fixture Purpose Expected Output
phase6_ethics_gate_trigger_matrix.yaml all 5 triggers independently correct determination per trigger
phase6_sfl_1k.yaml fork-to-plot latency < 60 s at 1,000 agents
phase6_cli_roundtrip.yaml run→fork→export→import re-importable, byte-identical card
phase6_agent_zoom_replay.yaml single-agent subjective replay matches determinism-log ground truth
phase6_gate_bypass_scan.yaml audit-scan for gate bypass zero bypassed dispatches over 30-day window
Pitfalls
  • Gate-check-after-dispatch regression: a Control-Plane refactor that moves the ethics check after the dispatch call (rather than blocking before it) is the exact FM-5 failure class (§23) — CI must include a regression test asserting gate-before-dispatch ordering, not just gate-correctness.
  • Lens replay divergence from live view: agent-zoom replay reconstructing a slightly different perception payload than what the agent actually saw live (e.g. a caching bug in the replay path) — validate replay against the determinism log directly, never against a secondary cache.
  • SFL measured only on cheap forks: reporting SFL from trivial single-parameter forks while ignoring forks that change population size — measure across a representative fork mix, not the fastest case.

⬜ Phase 7 — Scale Engineering (Multi-Node, GPU Autoscale, KV-Cache Hierarchy) §19

Objectives

Extend the Phase 3 single-node shard model to multi-node, add GPU cluster autoscaling, and build the KV-cache hierarchy and psychology-proxy cache that make 100,000-agent runs economically viable (P8, P12).

Deliverable

A 100,000-agent run sharded across 8 nodes with GPU autoscaling responding to DELIBERATE queue depth, psychology-proxy cache hit rate ≥ 60% at steady state, and documented cross-node barrier recovery under an injected network partition.

Acceptance

  • Per-agent-hour cost reduced ≥ 3× from the Phase 1 GA baseline (feeding the Phase 3-cycle 5× target in M4, §28).
  • Cross-node barrier-sync overhead ≤ 150 ms p95 added per tick at 8-node scale (M11, §28).
  • Named fixture fixtures/phase7_partition_recovery.yaml: injected network partition between orchestrator nodes recovers within the §4 RTO (≤ 5 min).
Fixtures
Fixture Purpose Expected Output
phase7_cache_hit_rate.yaml steady-state cache measurement ≥ 60% hit rate
phase7_partition_recovery.yaml cross-node network partition recovery ≤ 5 min RTO
phase7_gpu_autoscale_response.yaml queue-depth-driven scaling scale-out within 60 s of threshold breach
phase7_cost_reduction_3x.yaml per-agent-hour cost tracking ≥ 3× reduction vs. Phase 1 GA baseline
phase7_cache_shadow_compare.yaml cache vs. live-inference divergence sampling divergence rate below documented threshold
Pitfalls
  • Cache staleness on model-pin change (FM-9, §23): forgetting to invalidate the proxy cache when model_pins update produces silently-wrong cached actions — invalidation must be automatic and tested (phase7_cache_shadow_compare.yaml), not procedural.
  • Cross-node clock skew corrupting timeout arithmetic: reuse the Phase 3 monotonic-clock discipline (§15.6) across nodes via NTP-disciplined but monotonic-per-node timers, never comparing raw wall-clock timestamps across nodes for barrier timeout decisions.
  • Autoscaling oscillation: naive threshold-based GPU autoscaling can flap under bursty DELIBERATE queue depth — apply hysteresis (separate scale-out and scale-in thresholds).

⬜ Phase 8 — Cultural Drift & Language Emergence Primitives §20

Objectives

Implement the fourth and fifth emergent capabilities in the P6 sequence: cultural drift (norm transmission, prestige bias, conformity dynamics) and language emergence (novel-term coinage and propagation), each with its own conformance fixtures before the next phase's political-formation work depends on them.

Deliverable

A reproducible "two villages diverge" demo: two initially-identical village populations, geographically separated, tracked over 200 sim-years, showing measurable cultural-distance divergence and at least one novel term reaching > 50% adoption in one village and 0% in the other.

Acceptance
  • Cultural-distance metric shows monotonic divergence (no reversion) across the 200-sim- year reference run, with a documented confidence band (P3) on the divergence rate.
  • At least one coined term reaches ≥ 50% adoption in its origin village within 50 sim-years in ≥ 3 of 5 independent seeded runs (a Reproducibility-Rate-style claim, §26).
  • Named fixture fixtures/phase8_two_villages_200y.yaml completes and reproduces the qualitative divergence pattern (not necessarily the exact term) across reruns.
  • Prestige-bias weighting demonstrably changes convergence rate vs. a prestige-bias-disabled control (statistically distinguishable at p < 0.05 over 20 paired runs).
Fixtures
Fixture Purpose Expected Output
phase8_two_villages_200y.yaml cultural-divergence reference run monotonic cultural-distance divergence
phase8_term_adoption_curve.yaml novel-term propagation ≥ 50% adoption in ≥ 3 of 5 seeded reruns
phase8_prestige_bias_control.yaml prestige-bias ablation statistically distinguishable convergence rate, p < 0.05
phase8_corpus_materialization.yaml language-drift corpus storage CORPUS-type metric queryable per region/generation
phase8_conformity_saturation.yaml conformity-dynamics ceiling check value convergence does not exceed network-density-implied bound
Pitfalls
  • Divergence-by-noise vs. divergence-by-mechanism: without the prestige-bias-disabled control fixture, apparent cultural divergence could be pure sampling noise — always compare against the ablation, not just presence of divergence.
  • Corpus-storage schema mismatch: CORPUS-type metrics (raw text) do not fit ClickHouse's typical numeric-column optimization path — a naive implementation degrades ingestion performance (§16.6's per-event-insert pitfall, recurring in a new form); use a dedicated text-optimized column family or a separate object-storage side-channel indexed by tick/region.
  • Prestige-bias runaway feedback: an unbounded prestige-bias weight can produce a single-agent-dominates-all-values collapse rather than gradual drift — bound the weight and validate against the conformity-saturation fixture.

⬜ Phase 9 — Political Formation & Template-Store Admission §21

Objectives

Implement the final P6-sequenced emergent capability — political formation via the InstitutionLayer (assemblies, councils, parties) — and build the Template-Store admission pipeline gating third-party civilization templates on the conformance suite and the ethics gate (I13, I10).

Deliverable

A 100,000-agent, nation-scale reference run over 50 sim-years producing at least one observable emergent political faction with a documented formation trigger, plus a working Template-Store admission pipeline that has processed ≥ 3 submitted templates end-to-end (pass or reject, both documented). (Premium-model marketplace revenue share: PhaseDeferred("§21.3"), §35.)

Acceptance
  • 100,000-agent, 50-sim-year reference run completes within the §4 multi-node constraints, producing ≥ 1 faction with sustained membership ≥ 500 agents for ≥ 5 consecutive sim-years.
  • Template-Store admission pipeline processes a submitted template end-to-end (conformance
    • ethics review) in ≤ 72 hours median.
  • Zero templates admitted with a failing conformance-suite fixture (I13 held with zero exceptions across the first 10 submissions).
  • Named fixture fixtures/phase9_nation_100k_50y.yaml reproduces at least the qualitative faction-formation pattern (count within ±2) across 3 independent seeded runs.
Fixtures
Fixture Purpose Expected Output
phase9_nation_100k_50y.yaml civilization-scale reference run ≥ 1 faction, ≥ 500 members, ≥ 5 sim-years sustained
phase9_faction_reproducibility.yaml cross-seed faction-count stability count within ±2 across 3 seeded reruns
phase9_template_admission_pipeline.yaml end-to-end submission processing pass/reject determination ≤ 72 h median
phase9_conformance_gate_zero_exceptions.yaml I13 enforcement zero admissions with a failing fixture
phase9_institution_transition_audit.yaml extractive/inclusive transition correctness transitions match declared policy-history rule
Pitfalls
  • Faction-formation reducer sensitivity to clustering hyperparameters: an under-documented clustering threshold makes "faction count" an artifact of tuning rather than emergence — publish the clustering method and threshold alongside every faction-count claim, and validate against the cross-seed reproducibility fixture, not a single run.
  • Template admission rubber-stamping: under submission-volume pressure, a reviewer shortcut that skips the full conformance suite for "obviously fine" templates directly violates I13 — the pipeline must make the conformance run structurally mandatory (no manual-override path that bypasses it), not merely policy-mandatory.
  • Institution-transition oscillation: a poorly-bounded extractive/inclusive characterization rule can flip-flop tick to tick under noisy policy-decision history — require a hysteresis window (N consecutive ticks of consistent signal) before transitioning.
