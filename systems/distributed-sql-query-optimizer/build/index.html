⬜ Phase 2 — Logical Properties + Functional Dependencies — quasar-props §14

Objectives

Derive LogicalProps bottom-up for every bound RelExpr node, computed once at construction (or on demand before memo insertion in Phase 3). Algorithms: FD closure (seed ColSet → closure under all FDs); FD-simplified ordering (drop constants, collapse equiv to canonical, used in OrderingChoice); key minimization (drop supersets from keys). Deliverable: derive_props(expr:&RelExpr, input_props:&[&LogicalProps], cat:&dyn CatalogResolver) -> LogicalProps; flag quasar opt --props "<sql>" annotates each node.

  • out_cols: ColSet — cols produced, visible to parent. not_null: ColSet — provably non-null (null-rejecting analysis thru filters/joins).
  • keys: Vec<ColSet> — candidate keys, minimal col sets determining all out_cols. FuncDepSet — equiv groups (equijoin/= filter), const cols (col=const), strict FDs (keys + group-by).
  • cardinality: Cardinality — {min,max}: Scan={0,table_rows}, Filter≤input, GroupBy≤input, distinct≤input, SemiJoin≤left. outer_cols: ColSet — referenced not produced, correlation markers for subquery lifting.
Deliverable
  • quasar opt --props "SELECT a FROM t WHERE a > 1" → Select[out={a}, not_null={a}, keys=[{a}], card={0,1000}, FD:{}]\n Scan[t, out={a,b}, keys=[{a}], FD:{a}->b].
  • quasar opt --props "SELECT COUNT(*) FROM t GROUP BY b" → GroupBy[out={b,count}, keys=[{b}], FD:{b}->{b,count}].
  • quasar opt --props "SELECT a FROM t JOIN s ON t.a=s.a" → merged FDs; equiv {t.a,s.a}; key {t.a,s.pk}.
  • quasar opt --props "SELECT DISTINCT a FROM t" → keys=[{a}], FD:{a}->a.
  • quasar opt --props "SELECT a FROM t LIMIT 1" → card={0,1}; all Phase 0/1 tests still pass.
Acceptance
  • Props golden fixtures (§2.5): 100% match. cardinality.max non-increasing thru Select: 100 random filters → Select.max <= Scan.max. GroupBy key = grouping_cols (non-empty): fixture + unit test.
  • SemiJoin out_cols == left: unit, no right cols in output. InnerJoin key = union(left,right): fixture, two keyed scans. FD closure {a}->b,{b}->c ⊢ {a}={a,b,c}: unit in fd.rs.
  • FD-simplified ordering drops const (a=5 → [a,b] simplifies to [b]). Null-rejection WHERE a>1 → a in not_null: fixture. LeftJoin right cols NOT in not_null: unit test.
  • --props latency, 10-table join < 5 ms. derive_props_tree alloc, 10-table join < 1 MB heap delta. cargo test --workspace: 100% pass.
  • Invariants (§7): I5 (FD closure correct), I6 (keys minimal), I7 (cardinality bounds monotone thru operators).

⬜ Phase 3 — The Memo — quasar-memo (groups, expressions, interning, normalize hook) §15

Objectives

Build the central shared data structure on which all subsequent phases operate. Acceptance: identical ScanOp subtrees collapse; no group holds duplicate ExprIds; memo-dump goldens match byte-for-byte.

  • Group arena: Arena<Group>, GroupId(u32) handles, append-only, no removals. MExpr arena: Arena<MExpr>, ExprId(u32) handles, structural dedup via intern map.
  • ScalarExpr arena: Arena<ScalarExpr>, ScalarId(u32), shared across groups. Interning: MExprKey{op_tag:u8,children:SmallVec<[GroupId;3]>,scalar:Option<ScalarId>}→ExprId via HashMap<MExprKey,ExprId>; identical exprs share one slot.
  • Insertion: Memo::insert(RelExpr)->GroupId recursively interns children, builds MExpr, looks up intern map, adds to existing group or creates singleton. LogicalProps derived once at group creation via quasar-props (Phase 2), stored Group::logical, never recomputed.
  • Normalize hook: Memo::factory(&mut self,expr:MExpr)->MExpr called before interning, placeholder for Phase 4 rules to rewrite MExpr. GroupState: enum GroupState{Unexplored,Exploring,Explored} per Group, used by Phase 10 Cascades search.
  • Memo dump: quasar memo "<sql>" renders groups+members+LogicalProps+winner slots (empty here) deterministically for goldens. Deliverable: cargo test -p quasar-memo passes; quasar memo "SELECT a FROM t WHERE a>1" emits parseable dump; interning fixtures confirm shared GroupIds.

  • cargo test -p quasar-memo → arena, interning, dedup, dump, LogicalProps tests. cargo test -p quasar-props (regression) → props unchanged from Phase 2; dump format stable ASCII, downstream opt-test goldens consume it verbatim.

⬜ Phase 5 — Statistics + Cardinality Estimation — quasar-stats §17

Objectives

Build stat catalog + cardinality/selectivity layer; propagate Statistics onto group LogicalProps. Acceptance: q-error ≤3× on TPC-H-lite; selectivity goldens pass; missing-stats path → is_estimated=true, no panic.

  • Stat catalog load: quasar-stats reads JSON/TOML fixtures — per-table row_count; per-col ColumnStatistic{distinct_count,null_count,histogram,avg_size}; multi-col joint distinct_count over ColSet; per-col HLL sketch (offline → distinct_count). HLL integration: sketch stored as serialized bytes, hll::HLL::cardinality()→distinct_count, no query-time collection (offline analysis feeds catalog).
  • Equi-depth histogram: Histogram{buckets:Vec<Bucket>}, Bucket{upper_bound,num_eq,num_range,distinct_range}, loaded from file, drives range selectivity.
