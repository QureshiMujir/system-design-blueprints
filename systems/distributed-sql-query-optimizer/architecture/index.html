3.2 Per-Component Dense Description

quasar-sql — Lexer + recursive-descent parser for an intentional SQL subset. In: UTF-8 SQL text. Out: RawStmt AST (untyped; no name resolution, no type inference). Inv: parser never touches catalog/type system; all errors purely syntactic. Extended grammar = projects 259/313.

quasar-bind — Optbuilder/binder: RawStmt → bound RelExpr/ScalarExpr. Does name resolution (table aliases, column refs), type checking, ColumnId allocation (globally unique u32 per output col), subquery unnesting markers, correlation detection, FK/constraint hookup. In: RawStmt + quasar-cat handle. Out: root RelExpr, all ColumnIds assigned. Inv: every output ColumnId is catalog-sourced or freshly allocated; no dangling refs.

quasar-cat — Catalog: schemas, tables, columns, types, indexes (partial/inverted/computed), zone configs, regions/localities, range/leaseholder placement. Read-only to optimizer (DDL out of scope). In: schema store (in-memory tests; pluggable trait for integration). Out: TableDescriptor, IndexDescriptor, ZoneConfig, RegionSet, RangeMeta for quasar-bind/-constraint/-distsql. Inv: catalog snapshot fixed for one optimize() lifetime; concurrent mutations do not affect in-flight optimization.

quasar-ir — Defines RelExpr/ScalarExpr enums + operator structs (ScanOp, IndexScanOp, JoinOp, LookupJoinOp, MergeJoinOp, ...); ColumnId, ColSet (compact bitset), TableId, IndexId, Datum. No execution logic. Used by quasar-bind (construct) + quasar-rules (match patterns). Inv: enums avoid #[non_exhaustive] — adding a variant forces all match arms updated at compile time, catching missing rule coverage.

quasar-memo — The Memo: Group arena + MExpr arena + scalar arena, interning HashMap (MExprKey → ExprId), per-group winner table (PhysProps → Winner). Factory memo.add_expr(op, children, scalar) runs normalization immediately + dedups structurally identical exprs before insert. In: RelExpr/Operator + child GroupIds. Out: (GroupId, ExprId). Inv: logically identical exprs → same ExprId (structural dedup); LogicalProps immutable once computed; winners set-only, never cleared.

quasar-props — Derives + stores LogicalProps (out_cols, not_null, keys, FD closure, cardinality bounds, outer_cols) + PhysProps (ordering choice, distribution). LogicalProps computed once per group on first member insert + cached. PhysProps = required-vs-provided reconciliation domain for quasar-search. FD closure includes equivalency groups, constant columns, strict FDs. Inv: LogicalProps derivation = pure function of operator + child group props; no side effects.

quasar-stats — Statistics: row counts, HLL-derived NDV (distinct_count), equi-depth histograms (Bucket: upper_bound, num_eq, num_range, distinct_range), null counts, multi-column stats, avg row size. Selectivity estimators: range (histogram interpolation), equality (NDV), IN-list, IS NULL, LIKE prefix, join (min-of-NDV heuristic + multi-column). Cardinality propagated through project/select/join/group-by. Inv: missing stats → is_estimated = true; never crash; degrade to bounded heuristics (row_count = 1000, selectivity = 0.1).

quasar-optgen — Build-time rule DSL compiler. At build.rs time reads .opt files in quasar-rules, parses rule syntax (name, kind tag, pattern tree, replacement tree), emits Rust match arms + replacement construction into generated/rules.rs. In: .opt sources. Out: generated Rust via include!. Inv: generated code = pure function of .opt sources; regenerated on any change; never hand-edited.

quasar-rules — .opt source rule defs + generated dispatch. Normalization: constant folding, predicate merge/pushdown, projection pruning, simplification, fold/eliminate. Exploration: join commutativity/associativity, join-order xforms, GenerateIndexScans, predicate/limit pushdown variants, GroupBy/Distinct rewrites. Implementation: Scan→TableReader, Join→HashJoin/MergeJoin/LookupJoin, GroupBy→HashAgg/StreamAgg, Sort→Sorter enforcer, Distribute enforcer. Dispatch entrypoint consumed by quasar-memo (Normalize) + quasar-search (Explore/Implement). Inv: every normalization rule is confluent + cost-reducing (never enlarges or ties expr size); enforced by conformance suite.

quasar-constraint — Constraint/span solver. Given a predicate conjunction + an index's key column list, derives Spans (sorted Span { start, start_boundary, end, end_boundary }) covering rows satisfying prefix-column predicates, plus a remaining scalar filter for non-prefix predicates. Tight = spans exactly match predicate (no false positives → no post-filter). Handles: range, equality, IN-list (→ point spans), OR (span union), IS NULL, computed columns, partial index predicates, inverted index applicability. Inv: tight constraint → remaining is TRUE; loose → remaining must be applied.

quasar-cost — Per-operator cost model via Coster: fn cost(&self, memo: &Memo, expr: ExprId, required: &PhysProps) -> Cost. Components: cpu (tuple processing), io (page reads/seeks), net (cross-node bytes); total is ordering key; net dominates distributed. Distribution-aware: cross-region net applies a latency multiplier. In: operator type, cardinality from group LogicalProps.stats, PhysProps (distribution), index descriptor (seek cost). Inv: cost = deterministic pure function of memo state + required props; no randomness; no syscalls.

quasar-search — Cascades search engine. Vec<Task> stack; types: OptimizeGroup, OptimizeExpr, ExploreGroup, ExploreExpr, ApplyRule, EnforceProps. B&B: tracks cost budget per goal; tasks for goals whose current-best already exceeds budget are pruned. Winners in Group.winners[PhysProps]. Plan extraction: walk winner chain from root. EnforceProps inserts Sort/Distribute enforcers when required props unprovided by any member. Inv: no Task pushed for a (group, req) pair whose winner cost is already below the current best sibling; B&B pruning is monotone.

quasar-distsql — Lowers winning physical plan (quasar-search winner chain) into a FlowSpec: Vec<ProcessorSpec> + Vec<Stream>. Node placement: each ProcessorSpec → NodeId via leaseholder locality from quasar-cat (scans → leaseholder node for the key range; joins → build-side node; aggregators follow data). Routers: ByHash (hash-distributed joins), ByRange (range-distributed scans), PassThrough (local pipelines), Mirror (broadcast). Local-vs-distributed: all ranges on one node → local (gateway-only) flow. Inv: every Stream connects a valid (source ProcId, dest ProcId); no dangling streams.

quasar-explain (in quasar-cli) — Renders optimizer output as text or JSON. (OPT): annotated plan tree — operator, output columns, cardinality estimate, per-node cost. (DISTSQL): FlowSpec diagram — processors, streams, routers, node placement. quasar memo: group table with members, logical props, winners per PhysProps. Not a separate crate; rendering logic in quasar-cli. Inv: EXPLAIN output deterministic given identical (memo, winners, FlowSpec); used as conformance golden output.

quasar-cache — Plan cache for prepared statements. (fingerprint → CachedPlan); fingerprint = normalized SQL text + catalog version + stats version. Generic plan: optimized with placeholder types, not values (placeholder selectivity uncertain). Custom plan: optimized with bound values (value selectivity matters). Generic-vs-custom chosen by plan cost variance across recent executions. Staleness: catalog schema change or stats refresh bumps version; stale entries evicted lazily. Inv: a cached plan is never served after its catalog or stats version is stale.

quasar-obs — Observability wrapper over the full pipeline. tracing spans per task (OptimizeGroup duration, rule applications, cost evaluations). Metrics: memo group count, MExpr count, rules fired, search tasks executed, optimization duration, plan cache hit/miss. Optimizer event log: structured record of every task + outcome + cost, serializable for replay. Replay harness: given an event log, replays optimization with same rule order + costs + stats → must produce identical plan. Inv: any original-vs-replay divergence is a bug; replay is the primary non-determinism debugging tool.

3.3 Boundary Enumeration

Trust boundary:

  • Untrusted: SQL text (arbitrary input; quasar-sql must not panic on malformed input), placeholder values (type-checked, user-supplied values), catalog statistics (from stats daemon; may be stale/absent).
  • Trusted core: memo, rules, search, cost — pure functions over validated inputs; no network I/O, no filesystem, no unsafe untrusted access.

Concurrency boundary:

  • optimize() is single-threaded per query — no shared mutable state in memo/search/rule engine.
  • quasar-cat + quasar-cache read-shared across concurrent calls — Arc<dyn CatalogReader> + Arc<Mutex<PlanCache>>.
  • No intra-optimization parallelism; parallel planning is caller-managed (one thread per query).

Persistence boundary:

  • Catalog + stats: read-only external inputs; Quasar never writes them.
  • Plan cache: in-memory only (quasar-cache); no disk persistence in scope.
  • Memo: per-query ephemeral heap; dropped after optimize() returns.
  • Event log: quasar-obs in-memory ring buffer; flushed to disk only on replay request.

Protocol boundary:

  • In: bound RelExpr tree (quasar-ir types) from quasar-bind.
  • Out: FlowSpec (quasar-distsql types) — serializable physical plan for execution engine (project 318).
  • EXPLAIN: UTF-8 text or JSON; for operators + tooling.
  • Errors: Result<PhysicalPlan, OptError> — all failures encoded in OptError; no panics on recoverable errors.

8. Domain Model / Source Language / Protocol

Normative reference for every artifact Quasar consumes/produces. All phases derive schemas, grammars, data flows from here.

8.1 Supported SQL Subset — EBNF

query        ::= select_stmt | insert_stmt | update_stmt | delete_stmt
select_stmt  ::= SELECT proj_list FROM table_refs
                 [WHERE expr]
                 [GROUP BY group_list [HAVING expr]]
                 [ORDER BY order_list]
                 [LIMIT expr [OFFSET expr]]

proj_list    ::= STAR | proj_item (',' proj_item)*
proj_item    ::= expr [AS ident] | table '.' STAR

table_refs   ::= table_ref (join_clause)*
table_ref    ::= table_name [AS ident] | '(' select_stmt ')' [AS ident]
join_clause  ::= [join_type] JOIN table_ref ON expr
join_type    ::= INNER | LEFT [OUTER] | SEMI | ANTI
                 (* CROSS JOIN = INNER with no ON predicate *)

group_list   ::= expr (',' expr)*
order_list   ::= order_item (',' order_item)*
order_item   ::= expr [ASC | DESC] [NULLS FIRST | NULLS LAST]

insert_stmt  ::= INSERT INTO table_name ['(' col_list ')']
                 (VALUES '(' expr_list ')' (',' '(' expr_list ')')* | select_stmt)
update_stmt  ::= UPDATE table_name SET assign_list [WHERE expr]
assign_list  ::= assign (',' assign)*
assign       ::= col_name '=' expr
delete_stmt  ::= DELETE FROM table_name [WHERE expr]

expr         ::= literal | placeholder | col_ref | func_call
               | expr bin_op expr | unary_op expr
               | expr IS [NOT] NULL | expr [NOT] IN '(' expr_list | select_stmt ')'
               | EXISTS '(' select_stmt ')' | expr cmp_op ANY | ALL '(' select_stmt ')'
               | CASE [expr] (WHEN expr THEN expr)+ [ELSE expr] END
               | COALESCE '(' expr_list ')' | CAST '(' expr AS type ')'
               | '(' select_stmt ')'       (* scalar subquery *)
               | '(' expr ')'

bin_op       ::= '+' | '-' | '*' | '/' | '%' | '||'
               | '=' | '<>' | '<' | '>' | '<=' | '>=' | LIKE | ILIKE | SIMILAR TO
               | AND | OR
unary_op     ::= '-' | NOT
cmp_op       ::= '=' | '<>' | '<' | '>' | '<=' | '>='

col_ref      ::= [table_name '.'] col_name
func_call    ::= func_name '(' [DISTINCT] expr_list ')'   (* incl. aggregate fns *)
placeholder  ::= '$' uint                                  (* 1-indexed *)

literal      ::= int_lit | float_lit | string_lit | bool_lit | NULL
type         ::= INT | BIGINT | FLOAT | DECIMAL | TEXT | BOOL | TIMESTAMP | DATE | JSONB | BYTES

Not supported (deferred/out of scope): DDL, WINDOW (Phase 13 ext), LATERAL, TABLESAMPLE, CTEs (WITH), RETURNING, MERGE. Full grammar: project 259/313.

8.2 Relational Algebra Operator Table

Operator Inputs Output Columns LogicalProp Effects
Scan(ScanOp) ∅ ScanOp.cols from table schema cardinality = table row count; keys from PK; FDs from schema
IndexScan(IndexScanOp) ∅ IndexScanOp.cols cardinality = selectivity × table rows; ordering = index key order
Select{input, filters} {input} input.out_cols cardinality reduced by selectivity(filters); FDs preserved
Project{input, projections, passthrough} {input} projected + passthrough cols FDs narrowed to surviving cols; keys only if key cols survive
InnerJoin(JoinOp) {left, right} left.out_cols ∪ right.out_cols cardinality = left × right × selectivity(on); FK join may preserve key
LeftJoin(JoinOp) {left, right} left.out_cols ∪ right.out_cols cardinality ≥ left.rows; right cols nullable
SemiJoin(JoinOp) {left, right} left.out_cols cardinality ≤ left.rows; left duplicates preserved
AntiJoin(JoinOp) {left, right} left.out_cols cardinality ≤ left.rows
HashJoin(JoinOp) {build, probe} same as InnerJoin physical: requires no ordering; provides Any distribution
MergeJoin(MergeJoinOp) {left, right} same as InnerJoin physical: requires ordered input on join keys; provides ordered output
LookupJoin(LookupJoinOp) {input} input.out_cols ∪ index.cols physical: preserves input ordering; often Single distribution
InvertedJoin {input} input.out_cols ∪ table.cols physical: JSONB / geo inverted index
ZigzagJoin {idx1, idx2} intersection of key cols physical: two-pointer traversal over sorted index scans
GroupBy{input, grouping_cols, aggs} {input} grouping_cols ∪ agg_result_cols key = grouping_cols (if unique); cardinality ≤ NDV(grouping_cols)
ScalarGroupBy{input, aggs} {input} agg_result_cols cardinality = 1
Distinct{input, cols} {input} input.out_cols cardinality ≤ NDV(cols)
Sort{input, ordering} {input} input.out_cols provides ordering; enforcer node
Limit{input, n, offset} {input} input.out_cols cardinality = min(input.card, n)
UnionAll {left, right} left.out_cols cardinality = left.rows + right.rows
Union {left, right} left.out_cols cardinality ≤ left.rows + right.rows; dedup
Intersect / Except {left, right} left.out_cols cardinality ≤ min/left rows
Values ∅ declared cols cardinality = literal row count
WithScan{id} ∅ CTE cols cardinality = CTE's stats
Distribute{input, distribution} {input} input.out_cols enforcer: provides requested distribution; net cost added
SortEnforcer{input, ordering} {input} input.out_cols enforcer: provides ordering; CPU sort cost
Insert / Update / Delete / Upsert {input, table} mutation result cardinality = affected rows
Window {input} input.out_cols ∪ window_cols Phase 13 extension

8.3 Scalar Expression Grammar (Type System)

scalar_expr  ::= Column(ColumnId)                          (* bound col reference *)
               | Const(Datum)                              (* typed literal *)
               | Placeholder(PlaceholderIdx)               (* $N, 1-indexed *)
               | And(Vec<ScalarId>)                        (* short-circuit; ≥ 2 *)
               | Or(Vec<ScalarId>)
               | Not(Box<ScalarId>)
               | Comparison { op: CmpOp, l: ScalarId, r: ScalarId }
               | BinOp { op: BinOpKind, l: ScalarId, r: ScalarId }
               | UnaryOp { op: UnaryOpKind, expr: ScalarId }
               | Function { id: FuncId, args: Vec<ScalarId> }
               | Cast { expr: ScalarId, typ: DataType }
               | Case { base: Option<ScalarId>, when_then: Vec<(ScalarId,ScalarId)>, else_: Option<ScalarId> }
               | Coalesce(Vec<ScalarId>)
               | Tuple(Vec<ScalarId>)
               | Array(Vec<ScalarId>)
               | Subquery(GroupId)                         (* scalar subquery -> group returns 1 row, 1 col *)
               | Exists(GroupId)
               | AnyAll { cmp: CmpOp, scalar: ScalarId, sub: GroupId }

datum        ::= Int(i64) | Float(f64) | Decimal(Decimal128) | Text(Arc<str>)
               | Bool(bool) | Null | Bytes(Bytes) | Timestamp(i64) | Date(i32)
               | JsonB(Arc<Value>) | Array(Arc<[Datum]>) | Tuple(Arc<[Datum]>)

Type checking: quasar-bind resolves every ScalarExpr to a DataType; type errors → OptError::Unsupported (human-readable). Implicit casts follow CockroachDB promotion rules (int→float, int→decimal, …).

8.4 Bound IR (RelExpr / ScalarExpr) from Spine

SPINE definitions normative. Constraints imposed by quasar-bind:

  • Every ColumnId globally unique within a query; allocated monotonically from a per-query counter.
  • Subqueries = GroupId refs into memo; correlated columns appear as outer_cols in referenced group's LogicalProps.
  • ScanOp.cols/IndexScanOp.cols = minimal ColSet needed (projection pushdown applied by binder).
  • GroupBy aggregation inputs as ScalarId in aggregations; result cols are fresh binder-allocated ColumnIds.

8.5 Worked Example: End-to-End (3-Table Join + Filter + Group-By)

SQL:

SELECT c.region, COUNT(*) AS orders
FROM customer c
JOIN orders o ON c.id = o.customer_id
JOIN order_item i ON o.id = i.order_id
WHERE i.amount > 100
GROUP BY c.region
ORDER BY orders DESC
LIMIT 10;

Step 1 — quasar-sql: raw AST (abbreviated)

SelectStmt {
  proj: [Column("c.region"), FuncCall("COUNT", [Star])],
  from: Join(Join(Table("customer","c"), Table("orders","o"), ON c.id=o.customer_id),
              Table("order_item","i"), ON o.id=i.order_id),
  where: Comparison(>,Column("i.amount"),Lit(100)),
  group_by: [Column("c.region")], order_by: [Desc("orders")], limit: Lit(10)
}

Step 2 — quasar-bind: Bound RelExpr tree

Sort [col7 DESC]
  Limit [n=10]
    Project [col5 (c.region), col6 (COUNT)]
      GroupBy [grouping=col5] [agg: COUNT(*)->col6]
        Select [col4 > 100]                    ; i.amount
          InnerJoin [col2 = col3]              ; o.id = i.order_id
            InnerJoin [col0 = col1]            ; c.id = o.customer_id
              Scan(customer, cols={col0,col5}) ; id, region
              Scan(orders,   cols={col1,col2}) ; customer_id, id
            Scan(order_item, cols={col3,col4}) ; order_id, amount

ColumnIds: col0=customer.id, col1=orders.customer_id, col2=orders.id, col3=order_item.order_id, col4=order_item.amount, col5=customer.region, col6=COUNT result.

Step 3 — quasar-memo: Initial memo (logical groups)

GroupId Operator Children LogicalProps (cardinality)
G0 Scan(customer) — rows≈1M, keys={col0}
G1 Scan(orders) — rows≈5M, keys={col2}
G2 InnerJoin [col0=col1] G0,G1 rows≈5M
G3 Scan(order_item) — rows≈20M, keys={PK}
G4 InnerJoin [col2=col3] G2,G3 rows≈20M
G5 Select [col4>100] G4 rows≈2M (sel≈0.1)
G6 GroupBy [col5] G5 rows≈200 (NDV(region))
G7 Project [col5,col6] G6 rows=200
G8 Limit [10] G7 rows=10
G9 Sort [col6 DESC] G8 rows=10

Step 4 — Normalization (on-construct)

  • Select [col4>100] pushed below InnerJoin [col2=col3] → Select on G3 (Scan order_item); new group G3' = Select{G3, col4>100}, rows≈2M.
  • Two InnerJoin predicate-merge: no merge (different predicates).
  • Sort + Limit → single Sort-with-limit-hint on G8 (limit pushdown into ordering).

Step 5 — Exploration (during search, Phase 8) — alternatives for G4 (join of G2, G3'):

Alternative Rule Notes
InnerJoin(G3',G2) JoinCommutativity reorder operands
InnerJoin(G0, InnerJoin(G1,G3')) JoinReassociate different tree shape
InnerJoin(G2, G3') GenerateIndexScan G3' may use IndexScan on order_item(order_id)

chosen physical plan (post search, costs in (cpu, io, net)):

  HashAgg [col5] -> col6         cost=(0.5, 0, 0)    ; StreamAgg rejected (no ordering)
    LookupJoin [col2=col3]       cost=(0.2, 1.2, 0)  ; order_item PK lookup from orders

Step 7 — DistSQL FlowSpec (Phase 12, single-region)

FlowSpec:
  P0: TableReader{customer PK scan}  @ node-1
  P1: TableReader{orders FK idx}     @ node-1
  P2: MergeJoiner{col0=col1}         @ node-1   <-- stream P0,P1
  P3: TableReader{order_item lookup} @ node-2   <-- lookup key from P2
  P4: HashJoiner{col2=col3}          @ gateway  <-- stream P2 (hash col2), P3 (hash col3)
  P5: Aggregator{HashAgg col5}       @ gateway
  P6: Sorter{col6 DESC, limit=10}    @ gateway
Streams: P0->P2, P1->P2, P2->P4(ByHash col2), P3->P4(ByHash col3), P4->P5, P5->P6

8.6 Index Constraint Example

Schema. events(a INT, b INT, c TEXT), index idx_ab(a ASC, b ASC). Predicate. WHERE a = 5 AND b > 10 AND c = 'ok'

Constraint derivation (quasar-constraint):

Index key cols: [a, b]
Predicate analysis:
  a = 5        -> exact match on col 0  -> start=[5,⊥], end=[5,∞]  (equality prefix)
  b > 10       -> range on col 1        -> start=(5,10], end=[5,∞)  (exclusive start on b)
  c = 'ok'     -> not an index col      -> remaining filter

Constraint {
  cols: [col_a, col_b],
  spans: [Span { start: Key[5,10], start_boundary: Exclusive,
                  end:   Key[5],   end_boundary:   Exclusive /* open */ }],
  tight: false   (* remaining filter: c = 'ok' not covered *)
}
remaining_filter: ScalarExpr::Comparison { op: Eq, l: Column(col_c), r: Const("ok") }

IN expansion. WHERE a IN (3, 7) AND b > 10:

Spans: [Span{[3,10]excl .. [3]open}, Span{[7,10]excl .. [7]open}]  tight: false

Partial index. idx_partial(a) WHERE status = 'active': applicable only when query WHERE includes status = 'active' (quasar-constraint partial-index filter matcher). Inverted index. WHERE jsonb_col @> '{"key":"val"}': constraint builder extracts inverted span from containment predicate; remaining filter re-checks exact match.

8.7 Distribution and Locality Model

Regions / Ranges / Leaseholders. CockroachDB-style cluster partitions table data into Ranges (RangeId); each range has a leaseholder on a NodeId in a RegionId. quasar-cat accessors (signatures):

fn leaseholder_node(range: RangeId) -> NodeId;
fn node_region(node: NodeId) -> RegionId;
fn ranges_for_span(table: TableId, index: IndexId, span: &Span) -> Vec<RangeId>;

Distribution enum:

Distribution::Any          -- data may be anywhere; optimizer chooses placement
Distribution::Single(r)    -- all rows at gateway region r (final result)
Distribution::Set(regions) -- data partitioned across this region set (distributed join)

Distribute enforcer needed when:

  • Root always requires Single(gateway_region).
  • HashJoin hashing both sides by join key: each side needs Set(all_nodes) + ByHash router.
  • MergeJoin: both sides need matching ordering AND distribution to avoid cross-region streaming.
  • Local-only plan (all ranges in gateway region): distribution already Single; no enforcer.

Locality-optimized search (LOS): join build side all-local (gateway region) → prefer LookupJoin over HashJoin even if cardinality favors hash, because net cost dominates. LOS = Phase 11 net-cost uplift.

Distribution derivation per operator:

Operator Provided Distribution
Scan / IndexScan Set(regions_of_ranges(table, spans))
LookupJoin same as input (input drives, lookups co-located)
HashJoin Set(all_nodes) after hash routing both sides
MergeJoin same as inputs (must match; enforcer inserts if not)
Aggregator (HashAgg) Any → placed at gateway after partial agg
Distribute enforcer exactly the requested distribution
Values Single(gateway)

8.8 Search Task State Machine

Cascades search runs a task stack. Initial: stack = [OptimizeGroup(root, required_props)].

Task Pre-conditions Actions Posts tasks
OptimizeGroup(g, req) g not optimized check winners, compute cost bound OptimizeExpr(e, req) ∀ e ∈ g.members
g has winner prune if winner.cost ≥ budget (none)
OptimizeExpr(e, req) e physical cost e; update winner if better OptimizeGroup(child, child_req) ∀ child
e logical skip (logical not directly costed) ExploreExpr(e) if not explored
ExploreGroup(g) g.explored == false set g.explored = true ExploreExpr(e) ∀ e ∈ g.members
ExploreExpr(e) e logical for each applicable explore rule ApplyRule(e, r) ∀ unapplied rule
e physical (no explore rules apply) (none)
ApplyRule(e, r) r ∉ e.applied fire rule; intern new MExpr(s); set e.rules_applied.set(r) ExploreExpr/OptimizeExpr(new_e)
EnforceProps(g, req) no winner satisfies req create enforcer MExpr (Sort/Dist) OptimizeExpr(enforcer_e, req)
winner exists (no-op) (none)

Termination. Stack empty → complete. Budget exceeded → return current best winner or NoPlanFound.

Explore vs Optimize phase: Explore = only logical→logical rules fire, no costing. Optimize = implementation rules fire (logical→physical), physical exprs costed, winners updated.

8.9 Failure-Path Examples

8.9.1 Unsupported SQL

Input:  SELECT * FROM t1 FULL OUTER JOIN t2 ON t1.id = t2.id
Result: OptError::Unsupported("FULL OUTER JOIN not in supported operator set")
EXPLAIN: (none; error returned before memo construction)

8.9.2 Missing Statistics

Input:  SELECT * FROM new_table WHERE col = 1  (stats never collected)
Effect: quasar-stats returns Statistics { row_count: DEFAULT_ROW_COUNT (1000),
          col_stats: {col → ColumnStatistic { distinct_count: DEFAULT_NDV,
          null_count: 0, histogram: None, avg_size: 8 }}, is_estimated: true }
Plan:   proceeds; may be sub-optimal (no histogram → uniform selectivity)
Warn:   metric stats.estimated_fallback incremented; EXPLAIN shows "estimated (no stats)"

8.9.3 Unsatisfiable Constraint

Input:  WHERE a > 10 AND a < 5 over index on a
Solver: Span{(10,∞)} ∩ Span{(-∞,5)} = ∅  (empty intersection)
Result: Constraint { spans: Spans::empty(), tight: true }
Plan:   IndexScan empty spans → zero rows; optimizer prunes to Values(empty)
        via normalization rule EmptySpanElimination → RelExpr::Values(rows=0)

8.9.4 Unbound Placeholder

Input:  quasar opt "SELECT * FROM t WHERE id = $1"  (no binding provided)
Mode:   single-shot (not prepared statement path)
Result: OptError::PlaceholderUnbound(PlaceholderIdx(0))
        message: "placeholder $1 has no binding and no generic-plan mode active"

8.9.5 Budget Exceeded

Input:  50-table join (complex star schema)
Effect: budget (Cost::default_budget()) exhausted before full exploration
Result: OptError::BudgetExceeded(actual_cost_spent)
        OR: best plan so far returned with warning header in EXPLAIN
Note:   quasar-cache can store partial-plan result; next call w/ same fingerprint may reuse

8.9.6 Catalog Missing

Input:  SELECT * FROM nonexistent_table
Bind:   quasar-bind calls catalog.resolve_table("nonexistent_table") → None
Result: OptError::CatalogMissing("table 'nonexistent_table' not found")
        returned before memo construction
