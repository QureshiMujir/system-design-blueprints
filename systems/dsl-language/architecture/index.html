Lexer (lume-syntax) — converts UTF-8 source to a span-tagged token stream, preserving trivia (whitespace, comments) as token-attached data rather than discarding it; this is the substrate the Formatter depends on. Parser (lume-parser) — recursive descent for structure, a Pratt sub-parser for operator precedence, synchronizing error recovery so one syntax error never aborts the whole parse. Resolver (lume-resolve) — builds lexical scopes, resolves every identifier to a binding, walks the file-is-module import graph and rejects cycles (I6). Type Checker (lume-types) — Algorithm W with level-based generalization over structural row-polymorphic records and anonymous sum types; the occurs check (I2) is the soundness backbone. Diagnostic bus (lume-diag) — every phase boundary converts internal failure into a Diagnostic value with a primary span (I4); a human (ariadne) and a JSON renderer consume the same value (P7). Evaluator (lume-eval) — strict, environment-passing tree-walker; capabilities are ordinary values, wired only at the CLI's capability-construction boundary (P3, I14) — the trust boundary in the diagram. stdlib codecs (lume-stdlib) — pure functions from Value to JSON/YAML text; the only effectful builtins require a capability argument, and the regex builtin is deliberately bounded-backtracking (T9). REPL/Formatter/LSP — three thin wrappers around the same pipeline; the LSP is the one external-protocol, untrusted-input boundary (JSON-RPC over stdio, debounced 200 ms, I13) besides file input itself. Host process boundary — the outermost box in the diagram is also the only place capability values are ever constructed (I14); every subsystem drawn inside it receives capabilities exclusively as function arguments, never by reaching outside the box.

8. Domain Model

Surface Grammar (EBNF)

module      = { item } ;
item        = let_item | type_alias | import ;
let_item    = "let" , ident , [ ":" , type_expr ] , "=" , expr , ";" ;
type_alias  = "type" , ident , "=" , type_expr , ";" ;
import      = "import" , string_lit , ";" ;

expr        = assert_expr ;
assert_expr = [ "assert" , expr , "in" ] , if_expr ;
if_expr     = "if" , expr , "then" , expr , "else" , expr | let_expr ;
let_expr    = "let" , ident , [ ":" , type_expr ] , "=" , expr , "in" , expr | lambda ;
lambda      = "\" , param , { param } , "." , expr | binary ;
binary      = binary , bin_op , binary | unary ;
unary       = ( "-" | "!" ) , unary | application ;
application = application , postfix | postfix ;
postfix     = postfix , "." , ident | postfix , "//" , record_lit | primary ;
primary     = literal | ident | "(" , expr , ")" | record_lit | list_lit | match_expr ;
match_expr  = "match" , expr , "with" , { "|" , pattern , "=>" , expr } ;
record_lit  = "{" , [ field , { "," , field } ] , "}" ;
field       = ident , "=" , expr ;
list_lit    = "[" , [ expr , { "," , expr } ] , "]" ;
literal     = int | float | string | "true" | "false" | "null" ;
pattern     = "\"" , tag , "\"" , [ ident ] | "_" ;

type_expr   = forall_ty | arrow_ty ;
forall_ty   = "forall" , ident , { ident } , "." , arrow_ty ;
arrow_ty    = record_ty , [ "->" , arrow_ty ] ;
record_ty   = "{" , [ ty_field , { "," , ty_field } ] , [ "|" , ident ] , "}" | sum_ty ;
sum_ty      = "[" , tag_ty , { "|" , tag_ty } , "]" | atom_ty ;
tag_ty      = "\"" , tag , "\"" , [ atom_ty ] ;
atom_ty     = ident , { atom_ty } | "(" , type_expr , ")" ;

The AST shape realizing this grammar is normative in §11 Core Schema & Types (Expr, TypeExpr). Application binds tighter than field access — f x.y parses as f (x.y); this is locked because it is the more common shape in configuration.

Type System — Judgments

Judgment Meaning Rule source
Γ ⊢ e : τ expression e has type τ under environment Γ Algorithm W (Damas & Milner 1982)
τ₁ ≐ τ₂ τ₁ and τ₂ unify, producing a substitution union-find unifier, lume-types::unify
gen(Γ, τ) generalize τ's free variables not free in Γ into a Forall level-based generalization (Pottier & Rémy 2005)
inst(σ) instantiate a Forall scheme with fresh variables lume-types::infer
`{ℓ₁: τ₁, … ρ} ⊑ {ℓᵢ: τᵢ}` row ρ accepts field ℓᵢ at type τᵢ

Evaluation Semantics — Evaluation Table

Expr Form Evaluation Rule Result / Effect
Lit(v) identity Value corresponding to the literal
Ident(x) environment lookup, force if Thunk the bound Value; unbound is impossible post-resolution (I from §3 diagnostic bus)
If(c, t, e) evaluate c to Bool, then evaluate exactly one of t/e left-to-right, depth-first (I10)
Let(x, v, body) non-recursive: evaluate v, extend env, evaluate body strict binding
Let rec(x, v, body) bind x to a Thunk, evaluate body, force on first use breaks recursion without general loops (P2)
App(f, args) evaluate f and each arg left-to-right, then apply capability check occurs here (I3)
Record(fields) evaluate each field value in source order order preserved for deterministic JSON key order
Field(r, ℓ) evaluate r, look up ℓ row-typed at check time, so lookup is total post-typecheck
Update(r, fields) evaluate r, produce a new record with fields overlaid never mutates r in place (structural sharing via Rc)
Match(s, arms) evaluate s to a tagged value, select the matching arm exhaustiveness proven at type-check time
Assert(cond, body) evaluate cond; if false, trap; else evaluate body traps surface as a Diagnostic via lume-diag

Worked Example

let port : Int = 8080;
let svc = { name = "api", port = port, replicas = 3 };
svc

Type-checks to {name: Str, port: Int, replicas: Int}; evaluates left-to-right, depth-first (I10) to {"name":"api","port":8080,"replicas":3} — a direct, deterministic JSON encoding via lume-stdlib::json (RFC 8259).

Malformed-Input Examples

let x : Int = "hello";

Diagnostic E-TYPE-001, primary span on "hello", message "expected Int, found Str", secondary label on x : Int reading "expected due to this ascription," help "remove the ascription or change the literal to an integer" (P1).

import "./a.lm";   -- a.lm itself imports "./b.lm", which imports "./a.lm"

Diagnostic E-RESOLVE-004 naming the full cycle a.lm → b.lm → a.lm (I6); compilation of the importing module aborts, sibling modules are unaffected.

Failure-Path Example

import "./secrets.lm";   -- secrets.lm calls fs.read without a capability argument

At evaluation time fs.read is applied to a value that is not Capability(FileRead); lume-eval::apply's type-directed dispatch raises Trap::MissingCapability{expected: "FileRead", span} (I3), surfaced through lume-diag as a runtime-trap diagnostic rather than a host-level I/O error — the capability boundary is enforced inside the language, not by the OS.

This table is the concrete DFS gray/black marking Phase 3 (§15) implements for I6; a resolver bug is, by construction, a wrong transition in this table, not an ad hoc special case.

This is the concrete realization of the diagram in §3: the LSP box is steps 1–5 above wrapped around the same Lexer→Parser→Resolver→Type Checker→Diagnostic bus pipeline every other front end uses (P11).
