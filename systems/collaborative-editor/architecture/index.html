Editor Core. The single front-end both engines hide behind. Owns the materialized text (rope for O(log n) splice), a cursor/selection map keyed by siteId, and an undo facade. Translates UI intent (insert at index, delete range) into engine-neutral local edits; receives engine-neutral remote effects and re-renders. Defines DocumentReplica so the harness can swap engines without touching call sites. Holds no consistency logic itself — purely the boundary and the buffer.

OT Engine. Represents edits as operations over the current document: Insert(pos,str), Delete(pos,len), with Retain(n) for the composable "operation = sequence of components" view. Implements compose(a,b), invert(op,doc), and the core transform(a,b) -> (a',b') (inclusion/exclusion transform, IT/ET). Maintains a per-site revision counter and a buffer of unacknowledged ops; rewrites incoming server ops against the local pending buffer. Correctness rests on TP1 (and, avoided here, TP2). No content-addressed ids — positions only.

CRDT Engine. Two interchangeable implementations. RGA: each character is an element with id (siteId, seq), inserted after a referenced element; deletes set a tombstone; integration order resolves concurrent inserts-after-same-anchor by id. Logoot/LSEQ: each character gets a dense position identifier (a path of (digit, siteId)) drawn between neighbours so the total order is intrinsic; no anchors. Both require causal delivery (an insert's anchor / preceding ids must already be present). Tombstones persist until GC.

Transport / Sync. Frames SyncMessages over WebSocket. OT path routes through the server-relay: the server imposes one total order, returns acks carrying server-revision, clients transform their pending buffer against intervening ops. CRDT path performs a state-vector exchange (SV1 = my version vector → peer replies SV2 + missing updates → I send my missing updates) and supports P2P pairwise sync. Handles offline buffering and reconnect merge.

Awareness. Ephemeral, non-persisted presence: siteId → {cursor, selection, name, color, last_seen}. Cursor positions are transformed on every concurrent edit (OT: via transform_cursor; CRDT: cursor stored as an element id / relative position so it survives concurrent edits without explicit transform). TTL eviction; lost presence is self-healing.

Persistence. OT: append-only oplog of server-ordered revisions + periodic materialized snapshot + version index. CRDT: state store (full state or accumulated deltas) + snapshots. Persistence is for durability/restart, not consistency. Snapshot ↔ GC coupling: a snapshot below the stability frontier lets the oplog/tombstones before it be reclaimed.

GC. Computes the causal-stability frontier = component-wise min over all sites' version vectors (every site has seen everything up to that point). Tombstones and oplog entries strictly below the frontier are reclaimable; CRDT ids below it can be compacted. Resurrection (a delayed insert referencing a GC'd anchor) is prevented by never collecting above the frontier. Snapshots persist the post-GC state.

8. Domain Model / Protocol

8.1 OT operation model

An operation transforms a document of known length into a new document. Canonical composable form (ot.js style) = a sequence of components:

Op        := Component*                       // applies to a doc of length = sum(retain+delete lens)
Component := Retain(n: usize)                 // keep n chars
           | Insert(s: String)                // insert literal
           | Delete(n: usize)                 // remove n chars
baseLen(op)   = Σ retain + Σ delete           // required input length
targetLen(op) = Σ retain + Σ insert.len       // produced length

UI-facing convenience constructors collapse to/from positional form: Insert(pos,str) ≡ Retain(pos) · Insert(str) · Retain(rest); Delete(pos,len) ≡ Retain(pos) · Delete(len) · Retain(rest).

Compose compose(a,b) (a then b; targetLen(a)==baseLen(b)): merge the two component streams into one. Invert invert(a, doc) produces a⁻¹ such that apply(apply(doc,a), a⁻¹)==doc (needs the deleted text from doc).

Transform transform(a,b) -> (a', b') where a,b apply to the same state. Result satisfies TP1:

apply(apply(doc, a), b') == apply(apply(doc, b), a')        // (the two operands "swap" cleanly)

i.e. compose(a, b') ≡ compose(b, a') as documents. Inclusion transform IT(a,b) = transform a to include b's effect; exclusion transform ET(a,b) = transform a to exclude b (needed by some control algorithms / undo). Tie-break for two concurrent inserts at the same position: by a fixed priority (here: client < server, or by siteId) so both sides agree on order.

TP1 vs TP2.

  • TP1 (convergence property 1): the 2-operand swap above. Required by every OT system.
  • TP2 (transformation property 2): transform(transform(x, a), transform(b,a)) == transform(transform(x,b), transform(a,b)) — transforms commute over a third operation. Required only when an op may be transformed against different sequences of concurrent ops in different orders (a peer mesh). Jupiter avoids TP2 by giving every op a single, server-defined predecessor chain: each client always transforms against the same totally-ordered history, so the multi-order case never arises. This is the central reason our OT engine needs a server and cannot go pure-P2P.

Control algorithm — Jupiter / server-relay (Nichols 1995). Each client keeps (rev_server, pending: VecDeque<Op>).

Actor Trigger Resulting Action
Client Local edit e Build op = positional(e); apply to local_doc immediately. If pending is empty, send Submit{base_rev=rev_server, op} and push op onto pending. Otherwise (an op is already in flight) push op onto pending without sending — only one Submit is ever outstanding per client; queued edits may be composed to reduce traffic.
Server Submit{base_rev, op} from site S Fold IT across every history entry after base_rev: start op' = op, then for each srv_op in history[base_rev..] set op' = IT(op', srv_op) (server priority wins ties). Append op' to history (rev_server += 1), apply op' to server_doc, and broadcast Apply{rev, op', origin=S} to every client.
Client Apply{rev, op', origin}, origin == self This is the client's own ack: set rev_server = rev, pop the front of pending (the just-acked op), and — if pending is still non-empty — send Submit{base_rev=rev_server, pending.front()} for the next queued op.
Client Apply{rev, op', origin}, origin != self This is a remote op: let x = op', then fold transform(x, p) front-to-back across every op p in pending (rebasing the remote op past each locally-pending op and updating each p in place to p'). Apply the fully-rebased x to local_doc, set rev_server = rev, and call transform_cursor(local_cursor, x) to keep the caret valid.

Invariant: at the client, pending are exactly the local ops after rev_server; the server's single order + per-op IT chain guarantees TP1 suffices (no TP2). (See INV-4, INV-8.)

8.2 CRDT model

RGA (engine A). Element = { id: (siteId, seq), value: char, deleted: bool, after: Option<id> }. Document order: a stable traversal where each element follows its after anchor; concurrent inserts after the same anchor are ordered by id descending (RGA's "newer first" rule — Roh 2011) so all sites agree. Delete = set deleted=true (tombstone); value retained for ordering of later inserts that anchored on it. Insert needs the anchor present ⇒ causal delivery (INV-2).

RgaId        := (site: u32, seq: u64)            // total order: by seq desc, then site (tie)
Element      := { id, value: char, deleted: bool, origin_left: RgaId }   // origin_left = anchor
integrate(e) := find anchor; skip over later concurrent (id > new comers) per rule; splice

Logoot / LSEQ (engine B). No anchors; each char gets a dense position identifier (a path) drawn strictly between its neighbours' ids; intrinsic total order:

PosId   := [ (digit: u64, site: u32) ]   // variable-length path; compared lexicographically
alloc(p_left, p_right, site) := a fresh PosId with  p_left < new < p_right
            Logoot: random digit in the open interval at the deepest common level,
                    descending a level when the interval is exhausted.
            LSEQ:   alternate allocation strategy per depth (boundary+ / boundary-),
                    chosen by a per-level coin, to bound average path growth.

Delete = remove (Logoot keeps a tombstone for id stability of neighbours only if needed; LSEQ similar). Identifier growth: adversarial monotonic insertion (always at one end) grows path length → bytes/char balloon; LSEQ's adaptive strategy keeps average path bounded. This is a key matrix axis (Phase P12).

Causal delivery requirement. Op-based CRDTs (our default) require each update delivered after its causal dependencies. State-based merge (full VV-guarded join) is causal-delivery-free but heavy; delta-CRDT is the middle path. We implement op-based with a causal-delivery buffer, plus a state-based merge fallback for initial sync/repair.

8.3 SEC (CRDT correctness)

Strong Eventual Consistency holds iff the merge/integration is commutative, associative, idempotent under causal delivery. RGA: integrate of two concurrent elements yields the same ordering regardless of arrival order (id tie-break) ⇒ commutative; re-integrating an existing id is a no-op ⇒ idempotent; associativity from the deterministic order. Logoot/LSEQ: position ids are immutable & totally ordered ⇒ set-union of (PosId,char) is trivially a join-semilattice ⇒ SEC. Property tests assert these laws (Phase P5, Phase P6).

8.4 Sync wire protocol

SyncMessage :=
    Hello{ proto_ver, site, doc_id, mode: Server|P2P }
  | SV1{ vv: VersionVector }                       // "here is what I have"
  | SV2{ vv: VersionVector, updates: [Update] }     // reply: my vv + ops you lack
  | Update{ ops: [WireOp] }                          // ops the SV1 sender lacked
  | Submit{ base_rev: u64, op: WireOp }              // OT client→server only
  | Apply{ rev: u64, op: WireOp, origin: site }      // OT server→clients (also ack)
  | Awareness{ site, cursor, selection, name, color, ts }   // ephemeral, not persisted
  | Ack{ up_to: VersionVector }                      // CRDT delivery ack (for GC frontier)
  | Bye{ site }
WireOp := tagged union of {OtComponent stream | CrdtElement | CrdtPosInsert | CrdtDelete}

Two-step state-vector exchange (CRDT, Yjs-style). On connect: A sends SV1{vv_A}; B computes diff = ops B has that A lacks (from vv_A), replies SV2{vv_B, diff}; A integrates diff, computes its own diff from vv_B, sends Update{...}. Both now mutually caught up. Idempotent (INV-6) so overlap is harmless. OT path instead uses Submit/Apply against the server's single order (§8.1).

8.5 Worked example — concurrent edit through BOTH engines

Initial doc on all sites: "abc". Site X inserts "X" at pos 1; site Y concurrently deletes "b" (pos 1, len 1). Intended converged result: aXc.

OT trace (Jupiter, server order: X's op first).

Step Actor Event and resulting state
1 X Builds op_X = Retain(1)·Insert("X")·Retain(2); applies locally → "aXbc"; sends Submit{base=0, op_X}.
2 Y Builds op_Y = Retain(1)·Delete(1)·Retain(1); applies locally → "ac"; sends Submit{base=0, op_Y}.
3 Server history empty; takes op_X first → rev1, server_doc "aXbc"; broadcasts Apply{1, op_X, X}.
4 Server Processes op_Y at base=0 → IT(op_Y, op_X): op_X inserted "X" before Y's delete target (op_X inserts at 1; op_Y deletes original pos 1), giving op_Y' = Retain(2)·Delete(1)·Retain(1); rev2, applies to "aXbc" → "aXc"; broadcasts Apply{2, op_Y', Y}.
5 X Receives Apply{1,op_X,X}: its own ack, pending pops. Then receives Apply{2,op_Y',Y}: rebases past an empty pending → applies op_Y' to local "aXbc" → "aXc".
6 Y Receives Apply{1,op_X,X}: a remote op; rebases past Y's pending op_Y via transform(op_X, op_Y) → op_X' = Retain(1)·Insert("X")·Retain(1) (Y already removed "b" locally); applies op_X' to local "ac" → "aXc". Then receives Apply{2,op_Y',Y}: its own ack, pops. Converged at "aXc".

CRDT/RGA trace.

Step Site / event Resulting order and text
1 Seed Doc elements (left→right) with ids: a@(_,0) b@(s0,1) c@(_,2) — authored by site s0.
2 X inserts "X" after a New element X@(X,7), origin_left=a → local order a X b c → text "aXbc".
3 Y deletes b Tombstones b (deleted=true) → local order a [b] c → rendered text "ac".
4 Exchange: X receives Y's delete(b) Marks b deleted → order a X [b] c → text "aXc".
5 Exchange: Y receives X's insert(X after a) Splices X after a, before b → order a X [b] c → text "aXc".
6 Converged Both sites render "aXc". No transform needed — ids are stable; the delete and the insert commute.

Both converge to aXc. Note the mechanism differs: OT rewrote op_Y's position; RGA never moved anything — it ordered by id and tombstoned.

8.6 Malformed / duplicate / out-of-order delivery

Case OT handling CRDT handling
Duplicate op Apply for an already-acked rev → ignore (rev ≤ rev_server) id already in store → no-op (INV-6)
Out-of-order remote Server linearizes; clients only see in-order Apply Holdback buffer until deps present (INV-2)
Op with bad base_rev (too old) Server transforms past extra history (fine) or, if before snapshot, full re-sync n/a
Insert whose anchor is GC'd / missing n/a (positions) reject as resurrection (INV-9) or hold then re-sync
baseLen(op) != doc.len reject MalformedOp; request re-sync n/a (no positional precondition)
PosId equal to existing (collision) n/a impossible: (digit,site) path includes unique site ⇒ ids distinct
Truncated/garbled frame length-prefix + checksum → drop, request resend same
Clock regression from a site reject; expect monotonic seq (INV-7) reject; seq must increase per site

Design principles (§6)

  • One API, two engines, zero leakage. DocumentReplica is the only seam; no OT- or CRDT-specific concept escapes into editor-core. Tradeoff: the trait must be the union's least-common-denominator (op-or-effect neutral), costing some engine-specific optimization. Operational: harness swaps engines by type param only. Violation: if the editor branches on "is this a CRDT?", the comparison is no longer fair and tests rot.
  • Convergence is the prime invariant. Correctness (identical text on identical history) outranks latency, memory, and elegance. Tradeoff: we accept slow paths (e.g., full transform against pending buffer) over clever-but-unproven fast paths. Operational: every fuzz run asserts convergence as the oracle. Violation: a "performance" shortcut that breaks TP1 or commutativity silently corrupts documents — the worst possible failure.
  • Causality before delivery (CRDT). No CRDT element integrates before its causal dependencies (anchor / preceding ids). Tradeoff: a causal-delivery buffer adds memory + a holdback queue. Operational: out-of-order frames wait, not fail. Violation: integrating an insert whose anchor is absent → dangling reference, divergence, or panic.
  • Single total order makes OT tractable. Route OT through the server-relay (Jupiter) so there is exactly one global sequence; this sidesteps TP2. Tradeoff: OT cannot run pure-P2P; a server is mandatory. Operational: the server is the order authority; clients only rebase against it. Violation: attempting peer-to-peer OT without TP2 → known divergence on 3-way concurrency.
  • Determinism over convenience. Identical op/element sets must yield identical state on every machine, every run. No HashMap iteration in ordering paths, no wall-clock tie-breaks, no nondeterministic float. Tradeoff: sorted/BTreeMap structures, explicit tie-break by (clock, siteId). Operational: deterministic replay reproduces any bug from the oplog. Violation: a HashMap-ordered merge diverges across platforms → unreproducible "heisenbugs".
  • Idempotent integration. Applying the same op/element twice equals applying it once. Tradeoff: dedup needs a seen-set / version vector check on every integrate. Operational: retransmits, reconnect floods, and at-least-once delivery are safe. Violation: double-applying an insert duplicates characters → divergence.
  • Honest memory accounting. Every per-character byte (id, pointers, flags, tombstone) is counted and reported by the harness; no hiding overhead behind arenas. Tradeoff: instrumentation cost; explicit size methods. Operational: the comparison matrix's memory axis is trustworthy. Violation: under-reporting CRDT overhead makes the whole comparison a lie.
  • Crash-only, replayable state. Both engines reconstruct from persisted log/snapshot; killing a process at any instant is safe. Tradeoff: append-only oplog, fsync discipline, snapshot cadence. Operational: RTO = snapshot-load + tail-replay. Violation: in-memory-only revision counters → post-crash divergence vs peers.
  • Backpressure everywhere. Bounded channels between transport, engine, and persistence; slow consumers slow producers, never silently drop. Tradeoff: a fast editor may block on a slow network — surfaced as UI latency, not data loss. Operational: queue-depth metrics; shed only with explicit policy. Violation: unbounded inbound queue under partition heal → OOM.
  • Observability by default. Every op/element carries enough provenance (siteId, clock, revision) to trace its life; counters + traces are first-class, not bolted on. Tradeoff: slightly larger structs/logs. Operational: divergence is diagnosable post-hoc. Violation: a convergence bug with no provenance is unfixable.
  • Stable wire compatibility. SyncMessage is versioned; old clients negotiate down. Tradeoff: version field + negotiation handshake on every connection. Operational: rolling upgrades don't desync the cohort. Violation: silent wire change → two encodings → divergence at the protocol layer.
  • Bounded resource usage. Doc size, site count, tombstone ratio, queue depths all have ceilings (§4) and enforcement. Tradeoff: reject/snapshot rather than grow unbounded. Operational: predictable RSS. Violation: unbounded tombstone growth → memory blow-up over a long-lived doc.
  • GC only below the causal-stability frontier. Never reclaim a tombstone/id that any reachable site might still reference. Tradeoff: GC stalls while a site is offline/lagging. Operational: frontier = min over VVs; offline site pins the frontier. Violation: premature collection → tombstone resurrection → divergence.
  • Fairness in the comparison harness. Identical workloads, identical schedules, identical measurement points for both engines. Tradeoff: harness must drive both via the neutral API only. Operational: matrix verdicts are reproducible. Violation: tuning one engine's workload favorably invalidates conclusions.
  • Explicit ownership & no shared mutable aliasing. Engine state is owned by one task; cross-task communication is by message. Tradeoff: copies/serialization at boundaries. Operational: no data races; Rust borrow-checker enforces. Violation: shared &mut to a replica from transport + UI threads → UB / torn state.
