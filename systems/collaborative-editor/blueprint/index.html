293 — Collaborative Editor (OT + CRDT Comparison) from Scratch

Project Number: 293 Project Name: Collaborative Editor (OT + CRDT Comparison) from Scratch Owner: Mujir Qureshi Document: FINAL_BLUEPRINT.md Status: specification — locked

1. Goal

Build, from scratch, two independent real-time collaborative-text engines — an Operational Transformation (OT) engine and a sequence-CRDT engine — behind one shared editor API (DocumentReplica trait), plus a rigorous comparison harness that measures both against the same workloads. The educational payload is the OT-vs-CRDT tradeoff space, made concrete and falsifiable.

Precise terms. Both engines converge a replicated linear text buffer under concurrent, network-delayed edits. OT: ops Insert/Delete/Retain over positions, a transform operator, a server-relay (Jupiter) control algorithm giving a single total order. CRDT: per-element unique identifiers with a dense total order, integration by id, tombstones for deletes, causal delivery. Same front-end (apply_local, integrate_remote, text(), version()), same wire envelope, same fuzz schedules → an apples-to-apples matrix.

System boundaries (in scope).

  • Linear UTF-8 text document (insert/delete; rich-text marks gated, see Phase P9).
  • OT engine: op model, compose, invert, IT/ET transforms, TP1, Jupiter server-relay control.
  • CRDT engine A: RGA (Replicated Growable Array). CRDT engine B: Logoot/LSEQ dense ids (comparison foil).
  • Causality stack: Lamport clocks, vector clocks, version vectors, dotted-version-vectors (DVV).
  • Sync protocol over WebSocket: state-vector exchange, update messages, offline/reconnect merge.
  • Awareness/presence: cursors, selections, transformed through both models.
  • Collaborative undo/redo (per-user, selective) in both engines.
  • Tombstone GC under causal stability; snapshotting.
  • Comparison harness + differential convergence testing + fuzz.

Explicit non-goals.

  • Rich-text/JSON/tree CRDTs beyond a marks demo (PhaseDeferred("Deferred Features Register")).
  • Byzantine fault tolerance, encrypted/E2EE sync (PhaseDeferred("Deferred Features Register")).
  • Production auth/ACL/multi-tenant control plane (PhaseDeferred("Deferred Features Register")).
  • Mobile native bindings; only Rust core + WASM browser shim demo.
  • Distributed consensus (Raft/Paxos) — sync server is a single-writer relay, not a quorum.
  • Compression-optimal CRDT encoders (Yjs-grade bit-packing) — PhaseDeferred("Deferred Features Register").

Deployment model. Three modes, one core:

  1. Client library (Rust + WASM) embedded in an editor; offline-capable.
  2. Sync server (relay): assigns total order for OT (Jupiter), fan-outs CRDT updates, persists oplog/snapshots.
  3. P2P mode: no server; sites exchange state-vectors and updates pairwise (CRDT only — OT central-order requirement excludes pure P2P, see §8 TP2).

Target users. Systems engineers learning consistency models; editor authors choosing OT vs CRDT; researchers needing a side-by-side instrumented testbed.

Phase-0 numbered module list (crates).

  1. editor-core — DocumentReplica trait, text buffer (rope/gap), op/edit front-end, undo facade.
  2. ot — op model, compose/invert, transform (IT/ET), TP1 props, Jupiter control.
  3. crdt — RGA + Logoot/LSEQ, ids, integration, tombstones, GC.
  4. causality — Lamport, vector clock, version vector, DVV, causal-delivery buffer.
  5. sync — wire protocol, state-vector exchange, WebSocket transport, reconnect merge.
  6. awareness — presence, cursor/selection transform across both engines.
  7. harness — comparison matrix, workload generators, metrics, differential tester.
  8. fuzz — random concurrent schedules, partition/merge, convergence oracle.
  9. wasm-shim — browser binding demo (P2P + server).
  10. protocol — shared wire types, serialization, version negotiation.

What later phases unlock. P0 buffer → P1–P3 full OT → P4 causality → P5 RGA + SEC proof harness → P6 Logoot/LSEQ + interleaving → P7 networked sync → P8 presence + offline → P9 marks (gated) → P10 undo → P11 persistence + GC → P12 comparison matrix + DST simulator (the deliverable) → P13 conformance + fuzzing + hardening + extra-engine slots + release.

Deferred features (gated).

  • Tree/JSON CRDT → PhaseDeferred("Deferred Features Register").
  • Peritext deep rich text → PhaseDeferred("Deferred Features Register").
  • Optimal binary encoding → PhaseDeferred("Deferred Features Register").
  • E2EE / Byzantine resistance → PhaseDeferred("Deferred Features Register").

Timeline. Phase-0 skeleton (P0–P3 OT path) 8–12 weeks. CRDT + causality + sync (P4–P9) ~3–4 months. Undo/GC/marks/harness/fuzz/hardening (P10–P13) ~2–3 months. Full build ~7–9 months for one engineer.

Prerequisites. Distributed systems (happens-before, causality, replication); concurrency (lock-free intuition, message passing); consistency models (eventual, causal, strong eventual / SEC); data structures (balanced trees / ropes, intrusive linked lists); the OT and CRDT literature (§5); basic networking (WebSocket framing, RTT, partitions).

2. Why Build This

Unique lesson: the OT-vs-CRDT tradeoff space, lived end-to-end. Most engineers know the slogans ("CRDTs need no server", "OT is simpler client-side"). This project forces the measured truth: where each model's correctness argument actually bites, what concurrency anomaly each admits, and the real byte/latency/complexity bill.

Concept inventory exercised.

  • Consistency models: convergence (CP1/CP2), intention preservation, Strong Eventual Consistency (SEC), causal consistency.
  • Causality machinery: Lamport clocks, vector clocks, version vectors, dotted-version-vectors, causal delivery, causal-stability frontier.
  • Algebra of edits: OT transform (an operator satisfying TP1/TP2), CRDT operations forming a commutative/associative/idempotent join semilattice.
  • The TP2 problem: why concurrent transforms in a peer mesh need TP2, why a central total order (Jupiter/Wave) sidesteps it, and the practical cost (a server).
  • Identifier design: dense position ids (Logoot/LSEQ) vs causal element ids (RGA); identifier growth pathologies; allocation strategies (boundary, LSEQ adaptive).
  • Interleaving anomaly (Kleppmann Fugue): why some CRDTs interleave concurrent runs of insertions and others don't; tradeoff vs id size.
  • Garbage collection of tombstones only below the causal-stability frontier (min over version vectors); resurrection hazards.
  • Wire protocol design: state-vector exchange, delta sync, offline reconnect merge.

Historical / architectural weight. OT: GROVE (Ellis & Gibbs 1989), adOPTed (Ressel 1996), Jupiter (Nichols 1995), Google Wave/Docs. CRDTs: WOOT (2006), RGA (2011), Logoot (2009)/LSEQ (2013), Shapiro et al SEC (2011), Automerge (2017), Yjs/YATA (2016), diamond-types. Every modern collaborative editor sits somewhere on this axis; this project rebuilds the axis itself.

Engineering muscles. Reasoning about partial orders not timelines; designing for commutativity not locking; instrumenting memory honestly (tombstones, id bytes); building differential test oracles; writing property tests for algebraic laws (TP1, idempotence); thinking in failure-as-default (partitions, reorder, dup, offline).

Cross-links to portfolio.

  • Consensus engines (Raft/Paxos) — contrast coordination-based vs coordination-free convergence.
  • Distributed KV / Dynamo-style — version vectors, DVV, anti-entropy (same causality stack).
  • Compilers — transform is an algebra; property tests resemble optimizer-soundness checks.
  • Storage engines — oplog persistence, snapshot/compaction ↔ tombstone GC.
  • Networking stacks — framing, backpressure, reconnect.
  • Observability stacks — the harness is a measurement platform.

Calibration value. After this, "use a CRDT" or "use OT" becomes a decision with a spreadsheet behind it: per-axis verdicts on metadata overhead, memory, convergence guarantees, server requirement, P2P feasibility, latency, complexity, anomaly class, GC cost, offline behaviour. That judgment is rare and durable.

What Mastery Looks Like.

  • After Phase P3 (Jupiter control): can implement and property-test TP1, explain why TP2 is avoided, and trace any OT divergence to a transform case table.
  • After Phase P5 (RGA): can derive the RGA ordering rule from first principles, write SEC property tests, predict the interleaving anomaly from the per-char anchor model.
  • After Phase P6 (Logoot/LSEQ): can compute worst-case id-path growth, explain why adversarial monotone insertion breaks Logoot but not LSEQ, and size the memory bill honestly.
  • After Phase P11 (GC): can compute the causal-stability frontier from a site VV table, identify the offline-site pinning hazard, and write the GC safety argument.
  • After Phase P12 (Comparison Matrix): can fill the OT-vs-CRDT decision matrix from measured numbers, defend a choice of algorithm for a given deployment profile, and explain the server-trust implication of each model.
  • After Phase P13 (Fuzzing): can design a convergence oracle, write a DST harness, and diagnose a fuzz-found divergence from its seed + shrunk schedule.
  • After Phase P13 (Hardening + Release): can audit a CRDT or OT implementation for nondeterminism leaks, GC safety violations, and backpressure gaps; write a conformance suite from spec laws; and ship a reproducible signed release.

Editor Core. The single front-end both engines hide behind. Owns the materialized text (rope for O(log n) splice), a cursor/selection map keyed by siteId, and an undo facade. Translates UI intent (insert at index, delete range) into engine-neutral local edits; receives engine-neutral remote effects and re-renders. Defines DocumentReplica so the harness can swap engines without touching call sites. Holds no consistency logic itself — purely the boundary and the buffer.

OT Engine. Represents edits as operations over the current document: Insert(pos,str), Delete(pos,len), with Retain(n) for the composable "operation = sequence of components" view. Implements compose(a,b), invert(op,doc), and the core transform(a,b) -> (a',b') (inclusion/exclusion transform, IT/ET). Maintains a per-site revision counter and a buffer of unacknowledged ops; rewrites incoming server ops against the local pending buffer. Correctness rests on TP1 (and, avoided here, TP2). No content-addressed ids — positions only.

CRDT Engine. Two interchangeable implementations. RGA: each character is an element with id (siteId, seq), inserted after a referenced element; deletes set a tombstone; integration order resolves concurrent inserts-after-same-anchor by id. Logoot/LSEQ: each character gets a dense position identifier (a path of (digit, siteId)) drawn between neighbours so the total order is intrinsic; no anchors. Both require causal delivery (an insert's anchor / preceding ids must already be present). Tombstones persist until GC.

Transport / Sync. Frames SyncMessages over WebSocket. OT path routes through the server-relay: the server imposes one total order, returns acks carrying server-revision, clients transform their pending buffer against intervening ops. CRDT path performs a state-vector exchange (SV1 = my version vector → peer replies SV2 + missing updates → I send my missing updates) and supports P2P pairwise sync. Handles offline buffering and reconnect merge.

Awareness. Ephemeral, non-persisted presence: siteId → {cursor, selection, name, color, last_seen}. Cursor positions are transformed on every concurrent edit (OT: via transform_cursor; CRDT: cursor stored as an element id / relative position so it survives concurrent edits without explicit transform). TTL eviction; lost presence is self-healing.

Persistence. OT: append-only oplog of server-ordered revisions + periodic materialized snapshot + version index. CRDT: state store (full state or accumulated deltas) + snapshots. Persistence is for durability/restart, not consistency. Snapshot ↔ GC coupling: a snapshot below the stability frontier lets the oplog/tombstones before it be reclaimed.

GC. Computes the causal-stability frontier = component-wise min over all sites' version vectors (every site has seen everything up to that point). Tombstones and oplog entries strictly below the frontier are reclaimable; CRDT ids below it can be compacted. Resurrection (a delayed insert referencing a GC'd anchor) is prevented by never collecting above the frontier. Snapshots persist the post-GC state.

6. Design Principles

  1. One API, two engines, zero leakage. DocumentReplica is the only seam; no OT- or CRDT-specific concept escapes into editor-core. Tradeoff: the trait must be the union's least-common-denominator (op-or-effect neutral), costing some engine-specific optimization. Operational: harness swaps engines by type param only. Violation: if the editor branches on "is this a CRDT?", the comparison is no longer fair and tests rot.

  2. Convergence is the prime invariant. Correctness (identical text on identical history) outranks latency, memory, and elegance. Tradeoff: we accept slow paths (e.g., full transform against pending buffer) over clever-but-unproven fast paths. Operational: every fuzz run asserts convergence as the oracle. Violation: a "performance" shortcut that breaks TP1 or commutativity silently corrupts documents — the worst possible failure.

  3. Causality before delivery (CRDT). No CRDT element integrates before its causal dependencies (anchor / preceding ids). Tradeoff: a causal-delivery buffer adds memory + a holdback queue. Operational: out-of-order frames wait, not fail. Violation: integrating an insert whose anchor is absent → dangling reference, divergence, or panic.

  4. Single total order makes OT tractable. Route OT through the server-relay (Jupiter) so there is exactly one global sequence; this sidesteps TP2. Tradeoff: OT cannot run pure-P2P; a server is mandatory. Operational: the server is the order authority; clients only rebase against it. Violation: attempting peer-to-peer OT without TP2 → known divergence on 3-way concurrency.

  5. Determinism over convenience. Identical op/element sets must yield identical state on every machine, every run. No HashMap iteration in ordering paths, no wall-clock tie-breaks, no nondeterministic float. Tradeoff: sorted/BTreeMap structures, explicit tie-break by (clock, siteId). Operational: deterministic replay reproduces any bug from the oplog. Violation: a HashMap-ordered merge diverges across platforms → unreproducible "heisenbugs".

  6. Idempotent integration. Applying the same op/element twice equals applying it once. Tradeoff: dedup needs a seen-set / version vector check on every integrate. Operational: retransmits, reconnect floods, and at-least-once delivery are safe. Violation: double-applying an insert duplicates characters → divergence.

  7. Honest memory accounting. Every per-character byte (id, pointers, flags, tombstone) is counted and reported by the harness; no hiding overhead behind arenas. Tradeoff: instrumentation cost; explicit size methods. Operational: the comparison matrix's memory axis is trustworthy. Violation: under-reporting CRDT overhead makes the whole comparison a lie.

  8. Crash-only, replayable state. Both engines reconstruct from persisted log/snapshot; killing a process at any instant is safe. Tradeoff: append-only oplog, fsync discipline, snapshot cadence. Operational: RTO = snapshot-load + tail-replay. Violation: in-memory-only revision counters → post-crash divergence vs peers.

  9. Backpressure everywhere. Bounded channels between transport, engine, and persistence; slow consumers slow producers, never silently drop. Tradeoff: a fast editor may block on a slow network — surfaced as UI latency, not data loss. Operational: queue-depth metrics; shed only with explicit policy. Violation: unbounded inbound queue under partition heal → OOM.

  10. Observability by default. Every op/element carries enough provenance (siteId, clock, revision) to trace its life; counters + traces are first-class, not bolted on. Tradeoff: slightly larger structs/logs. Operational: divergence is diagnosable post-hoc. Violation: a convergence bug with no provenance is unfixable.

  11. Stable wire compatibility. SyncMessage is versioned; old clients negotiate down. Tradeoff: version field + negotiation handshake on every connection. Operational: rolling upgrades don't desync the cohort. Violation: silent wire change → two encodings → divergence at the protocol layer.

  12. Bounded resource usage. Doc size, site count, tombstone ratio, queue depths all have ceilings (§4) and enforcement. Tradeoff: reject/snapshot rather than grow unbounded. Operational: predictable RSS. Violation: unbounded tombstone growth → memory blow-up over a long-lived doc.

  13. GC only below the causal-stability frontier. Never reclaim a tombstone/id that any reachable site might still reference. Tradeoff: GC stalls while a site is offline/lagging. Operational: frontier = min over VVs; offline site pins the frontier. Violation: premature collection → tombstone resurrection → divergence.

  14. Fairness in the comparison harness. Identical workloads, identical schedules, identical measurement points for both engines. Tradeoff: harness must drive both via the neutral API only. Operational: matrix verdicts are reproducible. Violation: tuning one engine's workload favorably invalidates conclusions.

  15. Explicit ownership & no shared mutable aliasing. Engine state is owned by one task; cross-task communication is by message. Tradeoff: copies/serialization at boundaries. Operational: no data races; Rust borrow-checker enforces. Violation: shared &mut to a replica from transport + UI threads → UB / torn state.

8. Domain Model / Protocol

8.1 OT operation model

An operation transforms a document of known length into a new document. Canonical composable form (ot.js style) = a sequence of components:

Op        := Component*                       // applies to a doc of length = sum(retain+delete lens)
Component := Retain(n: usize)                 // keep n chars
           | Insert(s: String)                // insert literal
           | Delete(n: usize)                 // remove n chars
baseLen(op)   = Σ retain + Σ delete           // required input length
targetLen(op) = Σ retain + Σ insert.len       // produced length

UI-facing convenience constructors collapse to/from positional form: Insert(pos,str) ≡ Retain(pos) · Insert(str) · Retain(rest); Delete(pos,len) ≡ Retain(pos) · Delete(len) · Retain(rest).

Compose compose(a,b) (a then b; targetLen(a)==baseLen(b)): merge the two component streams into one. Invert invert(a, doc) produces a⁻¹ such that apply(apply(doc,a), a⁻¹)==doc (needs the deleted text from doc).

Transform transform(a,b) -> (a', b') where a,b apply to the same state. Result satisfies TP1:

apply(apply(doc, a), b') == apply(apply(doc, b), a')        // (the two operands "swap" cleanly)

i.e. compose(a, b') ≡ compose(b, a') as documents. Inclusion transform IT(a,b) = transform a to include b's effect; exclusion transform ET(a,b) = transform a to exclude b (needed by some control algorithms / undo). Tie-break for two concurrent inserts at the same position: by a fixed priority (here: client < server, or by siteId) so both sides agree on order.

TP1 vs TP2.

  • TP1 (convergence property 1): the 2-operand swap above. Required by every OT system.
  • TP2 (transformation property 2): transform(transform(x, a), transform(b,a)) == transform(transform(x,b), transform(a,b)) — transforms commute over a third operation. Required only when an op may be transformed against different sequences of concurrent ops in different orders (a peer mesh). Jupiter avoids TP2 by giving every op a single, server-defined predecessor chain: each client always transforms against the same totally-ordered history, so the multi-order case never arises. This is the central reason our OT engine needs a server and cannot go pure-P2P.

Control algorithm — Jupiter / server-relay (Nichols 1995). Each client keeps (rev_server, pending: VecDeque<Op>).

Actor Trigger Resulting Action
Client Local edit e Build op = positional(e); apply to local_doc immediately. If pending is empty, send Submit{base_rev=rev_server, op} and push op onto pending. Otherwise (an op is already in flight) push op onto pending without sending — only one Submit is ever outstanding per client; queued edits may be composed to reduce traffic.
Server Submit{base_rev, op} from site S Fold IT across every history entry after base_rev: start op' = op, then for each srv_op in history[base_rev..] set op' = IT(op', srv_op) (server priority wins ties). Append op' to history (rev_server += 1), apply op' to server_doc, and broadcast Apply{rev, op', origin=S} to every client.
Client Apply{rev, op', origin}, origin == self This is the client's own ack: set rev_server = rev, pop the front of pending (the just-acked op), and — if pending is still non-empty — send Submit{base_rev=rev_server, pending.front()} for the next queued op.
Client Apply{rev, op', origin}, origin != self This is a remote op: let x = op', then fold transform(x, p) front-to-back across every op p in pending (rebasing the remote op past each locally-pending op and updating each p in place to p'). Apply the fully-rebased x to local_doc, set rev_server = rev, and call transform_cursor(local_cursor, x) to keep the caret valid.

Invariant: at the client, pending are exactly the local ops after rev_server; the server's single order + per-op IT chain guarantees TP1 suffices (no TP2). (See INV-4, INV-8.)

8.2 CRDT model

RGA (engine A). Element = { id: (siteId, seq), value: char, deleted: bool, after: Option<id> }. Document order: a stable traversal where each element follows its after anchor; concurrent inserts after the same anchor are ordered by id descending (RGA's "newer first" rule — Roh 2011) so all sites agree. Delete = set deleted=true (tombstone); value retained for ordering of later inserts that anchored on it. Insert needs the anchor present ⇒ causal delivery (INV-2).

RgaId        := (site: u32, seq: u64)            // total order: by seq desc, then site (tie)
Element      := { id, value: char, deleted: bool, origin_left: RgaId }   // origin_left = anchor
integrate(e) := find anchor; skip over later concurrent (id > new comers) per rule; splice

Logoot / LSEQ (engine B). No anchors; each char gets a dense position identifier (a path) drawn strictly between its neighbours' ids; intrinsic total order:

PosId   := [ (digit: u64, site: u32) ]   // variable-length path; compared lexicographically
alloc(p_left, p_right, site) := a fresh PosId with  p_left < new < p_right
            Logoot: random digit in the open interval at the deepest common level,
                    descending a level when the interval is exhausted.
            LSEQ:   alternate allocation strategy per depth (boundary+ / boundary-),
                    chosen by a per-level coin, to bound average path growth.

Delete = remove (Logoot keeps a tombstone for id stability of neighbours only if needed; LSEQ similar). Identifier growth: adversarial monotonic insertion (always at one end) grows path length → bytes/char balloon; LSEQ's adaptive strategy keeps average path bounded. This is a key matrix axis (Phase P12).

Causal delivery requirement. Op-based CRDTs (our default) require each update delivered after its causal dependencies. State-based merge (full VV-guarded join) is causal-delivery-free but heavy; delta-CRDT is the middle path. We implement op-based with a causal-delivery buffer, plus a state-based merge fallback for initial sync/repair.

8.3 SEC (CRDT correctness)

Strong Eventual Consistency holds iff the merge/integration is commutative, associative, idempotent under causal delivery. RGA: integrate of two concurrent elements yields the same ordering regardless of arrival order (id tie-break) ⇒ commutative; re-integrating an existing id is a no-op ⇒ idempotent; associativity from the deterministic order. Logoot/LSEQ: position ids are immutable & totally ordered ⇒ set-union of (PosId,char) is trivially a join-semilattice ⇒ SEC. Property tests assert these laws (Phase P5, Phase P6).

8.4 Sync wire protocol

SyncMessage :=
    Hello{ proto_ver, site, doc_id, mode: Server|P2P }
  | SV1{ vv: VersionVector }                       // "here is what I have"
  | SV2{ vv: VersionVector, updates: [Update] }     // reply: my vv + ops you lack
  | Update{ ops: [WireOp] }                          // ops the SV1 sender lacked
  | Submit{ base_rev: u64, op: WireOp }              // OT client→server only
  | Apply{ rev: u64, op: WireOp, origin: site }      // OT server→clients (also ack)
  | Awareness{ site, cursor, selection, name, color, ts }   // ephemeral, not persisted
  | Ack{ up_to: VersionVector }                      // CRDT delivery ack (for GC frontier)
  | Bye{ site }
WireOp := tagged union of {OtComponent stream | CrdtElement | CrdtPosInsert | CrdtDelete}

Two-step state-vector exchange (CRDT, Yjs-style). On connect: A sends SV1{vv_A}; B computes diff = ops B has that A lacks (from vv_A), replies SV2{vv_B, diff}; A integrates diff, computes its own diff from vv_B, sends Update{...}. Both now mutually caught up. Idempotent (INV-6) so overlap is harmless. OT path instead uses Submit/Apply against the server's single order (§8.1).

8.5 Worked example — concurrent edit through BOTH engines

Initial doc on all sites: "abc". Site X inserts "X" at pos 1; site Y concurrently deletes "b" (pos 1, len 1). Intended converged result: aXc.

OT trace (Jupiter, server order: X's op first).

Step Actor Event and resulting state
1 X Builds op_X = Retain(1)·Insert("X")·Retain(2); applies locally → "aXbc"; sends Submit{base=0, op_X}.
2 Y Builds op_Y = Retain(1)·Delete(1)·Retain(1); applies locally → "ac"; sends Submit{base=0, op_Y}.
3 Server history empty; takes op_X first → rev1, server_doc "aXbc"; broadcasts Apply{1, op_X, X}.
4 Server Processes op_Y at base=0 → IT(op_Y, op_X): op_X inserted "X" before Y's delete target (op_X inserts at 1; op_Y deletes original pos 1), giving op_Y' = Retain(2)·Delete(1)·Retain(1); rev2, applies to "aXbc" → "aXc"; broadcasts Apply{2, op_Y', Y}.
5 X Receives Apply{1,op_X,X}: its own ack, pending pops. Then receives Apply{2,op_Y',Y}: rebases past an empty pending → applies op_Y' to local "aXbc" → "aXc".
6 Y Receives Apply{1,op_X,X}: a remote op; rebases past Y's pending op_Y via transform(op_X, op_Y) → op_X' = Retain(1)·Insert("X")·Retain(1) (Y already removed "b" locally); applies op_X' to local "ac" → "aXc". Then receives Apply{2,op_Y',Y}: its own ack, pops. Converged at "aXc".

CRDT/RGA trace.

Step Site / event Resulting order and text
1 Seed Doc elements (left→right) with ids: a@(_,0) b@(s0,1) c@(_,2) — authored by site s0.

Both converge to aXc. Note the mechanism differs: OT rewrote op_Y's position; RGA never moved anything — it ordered by id and tombstoned.

11. Core Schema and Core Types

Lightweight signatures only (CRITICAL RULE 10 — no implementation bodies). For each: ownership · mutation · concurrency · persistence · serialization · compatibility.

DocumentReplica (shared trait — the seam).

trait DocumentReplica {
    type Op;                                  // engine-native op/element
    fn apply_local(&mut self, edit: LocalEdit) -> Self::Op;     // UI intent → native, mutate
    fn integrate_remote(&mut self, op: Self::Op);               // remote native → mutate
    fn text(&self) -> &str;                                     // materialized doc
    fn version(&self) -> VersionVector;                         // causal summary
    fn size_report(&self) -> SizeReport;                        // honest memory (Principle 7)
}

Ownership: one owner (actor task). Mutation: only via the two *_local/_remote methods. Concurrency: single-threaded per replica; cross-task via channels. Persistence: engine-specific (oplog/state). Serialization: Op ↔ WireOp in protocol. Compatibility: trait is stable; engines version their WireOp.

LocalEdit / RemoteEffect.

enum LocalEdit { Insert{ at: usize, text: String }, Delete{ at: usize, len: usize } }
enum RemoteEffect { Inserted{ at: usize, text: String }, Deleted{ at: usize, len: usize } }

Engine-neutral; at is a code-point index. Owned by editor-core. Not persisted (transient). Serialization: n/a (internal). Compatibility: additive variants only.

OT — Op / Component.

enum Component { Retain(usize), Insert(String), Delete(usize) }
struct Op { components: Vec<Component>, base_len: usize, target_len: usize }

Ownership: client pending buffer & server revlog own copies. Mutation: ops are immutable post-construction (transform yields new ops). Concurrency: passed by value across channels. Persistence: serialized into oplog. Serialization: CBOR tag per variant. Compatibility: component tag space reserved; new component kinds bump proto_ver.

OT — transform signature.

fn transform(a: &Op, b: &Op, prio: Priority) -> (Op, Op)   // (a', b'), TP1
fn compose(a: &Op, b: &Op) -> Op
fn invert(a: &Op, doc: &str) -> Op
enum Priority { Left, Right }                              // deterministic tie-break

OT — RevisionLog / ServerState / ClientState.

struct RevisionLog { entries: Vec<(u64 /*rev*/, Op, SiteId /*origin*/)> }
struct ServerState { doc: Rope, log: RevisionLog, rev: u64 }
struct ClientState { doc: Rope, acked_rev: u64, pending: VecDeque<Op> }

Ownership: server owns ServerState (single relay task); each client owns its ClientState. Mutation: append-only log; pending push/pop. Concurrency: actor-isolated. Persistence: log + periodic snapshot; client pending persisted for crash-resume. Serialization: log entries CBOR. Compatibility: snapshot format versioned; replay tolerant of trailing partial entry.

CRDT — CrdtId / PosId.

struct RgaId { site: u32, seq: u64 }                  // Ord: by (seq desc, site)
struct PosId { path: SmallVec<[(u64,u32);8]> }         // Logoot/LSEQ; lexicographic Ord

Ownership: embedded in elements. Mutation: immutable once allocated. Concurrency: by-value. Persistence: stored with element. Serialization: varint path. Compatibility: path digit width fixed at u64; site u32.

CRDT — RgaNode / Element / Tombstone.

struct Element { id: RgaId, value: char, deleted: bool, origin_left: RgaId }   // RGA
struct LogootEntry { pos: PosId, value: char, deleted: bool }                  // Logoot/LSEQ
type Tombstone = Element;   // with deleted=true (RGA) — kept for ordering until GC

Ownership: replica's element store (sorted structure: BTree by order key). Mutation: deleted flag set on delete; never un-set except by GC removal. Concurrency: actor-isolated. Persistence: in CRDT state/delta store. Serialization: CBOR struct. Compatibility: flag byte reserved bits.

Causality — VersionVector / VectorClock / Lamport / DVV.

struct Lamport(u64)
struct VectorClock(BTreeMap<SiteId, u64>)        // deterministic iteration
struct VersionVector(BTreeMap<SiteId, u64>)      // = max seq seen per site
struct Dot { site: SiteId, seq: u64 }
struct DVV { dot: Dot, vv: VersionVector }       // dotted version vector (siblings)

Ownership: per replica (one VV). Mutation: monotonic increment / component-wise max on merge. Concurrency: actor-isolated; merged on integrate. Persistence: stored with snapshot. Serialization: sorted (site,seq) pairs. Compatibility: width grows with sites (bounded by GC); old VVs subset-compatible.

SyncMessage / WireOp. (see §8.4) — owner: transport frames; immutable; CBOR/JSON; proto_ver gated (Principle 11).

Awareness.

struct Presence { site: SiteId, cursor: CursorPos, selection: Option<Range>, name: String, color: u32, last_seen: Instant }
enum CursorPos { Index(usize) /*OT*/, RelativeTo(RgaId, i32) /*CRDT*/ }

Ownership: awareness map per replica. Mutation: upsert on Awareness msg; TTL evict. Concurrency: actor-isolated. Persistence: never persisted (ephemeral). Serialization: CBOR. Compatibility: additive fields.

UndoManager.

struct UndoManager { stacks: HashMap<SiteId, Vec<UndoEntry>> }   // per-user
enum UndoEntry { Ot(Op /*inverse*/), Crdt(Vec<CrdtId> /*to re-tombstone/restore*/) }

Ownership: editor-core, delegates to engine. Mutation: push on local edit, pop on undo. Concurrency: local only. Persistence: optional (session). Serialization: n/a. Compatibility: per-user isolation invariant.

SizeReport (honest accounting).

struct SizeReport { live_chars: usize, tombstones: usize, meta_bytes: usize, id_bytes: usize, oplog_bytes: usize }

Ownership: computed on demand. Drives the Phase P12 comparison-matrix memory axis.

Error types.

enum CollabError { MalformedOp, BaseLenMismatch, RevisionDesync, CausalHoldback,
                   TombstoneResurrection, LimitExceeded(LimitKind), Codec(CodecError), Transport(TransportError) }

Phase P1 — OT op model (Insert/Delete/Retain) + apply + compose + invert

P1.1 Objectives

  • Component { Retain(n) | Insert(s) | Delete(n) } and Op { components, base_len, target_len } (§8.1, §11).
  • apply(doc, op) -> String with strict base_len == doc.char_len precondition.
  • compose(a,b) (a then b, targetLen(a)==baseLen(b)); invert(op, doc) -> op⁻¹.
  • Canonical normalization: merge adjacent same-kind components, drop trailing Retain.
  • Positional convenience: LocalEdit → Op (Insert/Delete bracketed by Retains).

P1.2 Detailed Implementation Steps

  1. op.rs: enums + base_len/target_len accessors; OpBuilder (push with auto-merge). (P1 Ellis & Gibbs 1989 op model; ADR-01.)
  2. apply.rs: walk components over rope; Retain advances, Insert splices, Delete removes; assert lengths. (P1 op model; INV-8 base-len precondition.)
  3. compose.rs: dual-cursor merge of a,b component streams; case table Retain×{Retain,Insert,Delete}, Insert×…, Delete×… (9 + boundary splits). (Ellis & Gibbs 1989 compose; needed by P3 server revlog compaction.)
  4. invert.rs: scan op over doc; Insert(s)→Delete(s.len), Delete(n)→Insert(captured_text), Retain unchanged; capture deleted substrings from doc. (P10 selective-undo prerequisite; ET foundation.)
  5. Normalization pass; equality up to normalization for tests. (P5 determinism — normalised form is canonical.)
  6. LocalEdit→Op constructors; round-trip Op→effects for editor-core. (P1 seam; ADR-01.)

P1.3 Deliverable

ot crate: op model + apply + compose + invert + normalization, unit-tested with the §8.1 case table.

P1.4 Acceptance Criteria

Law / check Statement
apply precondition base_len(op)==doc.len else BaseLenMismatch
compose assoc apply(d, compose(compose(a,b),c)) == apply(d, compose(a, compose(b,c)))

length algebra target_len(compose(a,b))==target_len(b); base_len==base_len(a)

P1.5 Conformance Fixtures

  • conformance/ot/ (new compose/, invert/): (doc, a, b) → compose_result; (doc, op) → inverse, restored.
  • Edge fixtures: empty op (identity), insert-only, delete-only, full-replace.
  • Cross-impl: same fixtures reproduced from ot.js outputs (sanity, not copied code).

P1.6 Pitfalls

  • Off-by-one in component boundary splits (the classic OT bug). Enumerate all 9 compose cases explicitly; proptest against the apply-equivalence law.
  • invert needs the pre-image doc — inverting against the wrong doc silently wrong; thread doc explicitly, never cache.
  • Forgetting trailing-Retain trim → length asserts fire spuriously.
  • Insert string length measured in code points vs bytes — must match position unit (ADR-27).

P1.7 Performance Concerns

  • Compose allocates a new component vec — preallocate cap = a.len + b.len.
  • Avoid per-char component creation on large inserts (keep Insert(String) whole).
  • criterion bench: compose of two 1k-component ops ≤ 10 µs.

P1.8 Edge Cases

  • Compose where a deletes what b would retain; a inserts then b deletes the inserted run (must cancel); zero-length Insert/Delete (reject or drop).
  • Invert of an op that both inserts and deletes; multi-byte deletes (capture exact code points).

P1.9 Failure Analysis

  • A wrong compose corrupts the server revlog compaction (P3) → divergence later, far from cause. Mitigate: compose law in CI + fuzz before P3 depends on it.
  • Panic vs error: malformed external op → MalformedOp error; internal invariant break → debug_assert panic.

P1.10 Operational Notes

  • tools/op-pretty renders an Op as R3 I"x" D2 for trace logs.
  • Telemetry: op_components_len, compose_calls.
  • Spans carry base_len/target_len for post-hoc validation.

Phase P2 — OT transformation functions (IT/ET) + TP1 property tests

P2.1 Objectives

  • transform(a,b,prio) -> (a',b') satisfying TP1 (§7 INV-4, §8.1): compose(a,b') ≡ compose(b,a').
  • Inclusion transform IT(a,b) and exclusion transform ET(a,b) (ET needed by selective undo P10).
  • Deterministic tie-break Priority{Left,Right} for concurrent inserts at the same position (INV-11).
  • proptest TP1 harness with shrinking → minimal counterexamples.

P2.2 Detailed Implementation Steps

  1. transform.rs: dual-cursor walk of a,b (both over the same base). Component pair case table: (P1 Ellis & Gibbs 1989; Ressel et al. 1996 TP1/TP2 taxonomy; INV-4.)
    • Insert(a) vs anything: a's insert is retained in a'; b' gains a Retain(len) to skip it (priority decides order when both insert at same point).
    • Delete vs Delete: overlapping ranges cancel (deleted-by-both becomes nothing on both sides).
    • Retain vs Delete / Delete vs Retain: shrink/extend accordingly.
  2. Symmetry: transform(a,b,Left) and transform(b,a,Right) must agree (swap roles). (INV-11 determinism; Sun & Ellis 1998 CP1.)
  3. IT/ET: IT is the forward transform; ET = transform that removes an already-included effect (used to relocate an op back to a prior context for undo). (P10 selective-undo; Sun et al. 1998 GOTO.)
  4. props.rs: random (doc, a, b) generator (a,b both valid on doc); assert TP1; shrink on failure. (INV-4 TP1; Ressel 1996 TP1 formal statement.)
  5. Tie-break: when both insert at identical position, prio==Left ⇒ a's text first; server always Right-wins in P3. (ADR-02 Jupiter single-order; INV-11 determinism.)

P2.3 Deliverable

transform/IT/ET + a green TP1 proptest (≥10⁵ cases) + symmetry test.

P2.4 Acceptance Criteria

Property Statement
TP1 apply(apply(d,a),b') == apply(apply(d,b),a') ∀ concurrent a,b
Symmetry transform(a,b,L) == swap(transform(b,a,R))
Identity transform(a, identity) == (a, identity)
ET inverse-of-IT ET(IT(a,b), b) ≡ a (relocation round-trip)
Tie determinism same (a,b,prio) → identical (a',b') every run/arch

P2.5 Conformance Fixtures

  • conformance/ot/transform/: (doc, a, b, prio) → (a_prime, b_prime) JSON; include both Left/Right.
  • Adversarial pairs: same-position inserts; nested deletes; insert-inside-delete-range; delete spanning an insert point.
  • TP1 regression corpus: every historical proptest counterexample frozen as a fixture.

P2.6 Pitfalls

  • TP2 temptation: do NOT attempt peer-mesh transform here; only TP1 is required because P3 uses a single total order (§8.1). Building/testing TP2 wastes effort and likely fails (TP2 is hard — Ressel 1996).
  • Insert-vs-insert ordering must be globally consistent — a non-symmetric tie-break diverges (INV-11).
  • Delete-delete overlap double-counting → characters vanish or survive on one side only.
  • Transforming against an op from a different base state (not concurrent) → silent corruption; enforce "same base" in types/asserts.

P2.7 Performance Concerns

  • Transform is O(|a|+|b|) components; the hot path in P3 is op vs k pending → O(k·|op|). Keep per-pair allocation minimal.
  • Bench: transform of two 1k-component ops ≤ 12 µs; chain of 64 ≤ 50 µs (§4).

P2.8 Edge Cases

  • One op empty; both delete the same single char; insert at pos 0 vs insert at pos 0 (tie-break); delete range exactly equals an insert's footprint; transform across a multi-byte char boundary.
  • a inserts, b deletes the region a inserted into (a's insert relocates to the surviving boundary).

P2.9 Failure Analysis

  • A TP1 break is the single most dangerous OT defect: silent, history-dependent divergence. Mitigation: TP1 proptest is a merge-blocking gate; differential fuzz (P13) re-checks under real schedules.
  • Use proptest shrinking to get a 2–3 component minimal case; freeze as fixture.

P2.10 Operational Notes

  • tp1_violation counter wired (INV-4); CI fails on any.
  • Determinism CI: run TP1 fixtures on two arches (x86_64, aarch64), diff outputs (INV-11).
  • Runbook divergence.md: first suspect after a divergence in OT mode = a transform case.

Phase P3 — OT control algorithm (Jupiter / server-relay) + client revisions + selection transform

P3.1 Objectives

  • Jupiter control (Nichols 1995, §8.1): server imposes one total order; clients rebase against it. This is why only TP1 is needed (no TP2).
  • ServerState{doc, log: RevisionLog, rev}; ClientState{doc, acked_rev, pending: VecDeque<Op>} (§11).
  • Server: transform incoming Submit{base_rev,op} past history[base_rev..] via IT chain; append; broadcast Apply{rev,op',origin}.
  • Client: on Apply(self) ack+pop+send-next; on Apply(remote) rebase past whole pending buffer (update pending in place); single-op-in-flight discipline.
  • transform_cursor(local_cursor, applied_op) keeps presence valid (INV-12).

P3.2 Detailed Implementation Steps

  1. revlog.rs: append-only Vec<(rev, Op, SiteId)>; slice(base_rev..); snapshot anchor index. (ADR-09 oplog; P8 crash-only replay; Nichols et al. 1995 Jupiter history model.)
  2. control.rs server side: recv Submit → fold IT over history tail (server priority Right) → append (rev+=1) → apply to doc → broadcast. (Nichols et al. 1995 Jupiter; P4 Ressel 1996 — single order avoids TP2; INV-8.)
  3. control.rs client side: state machine per §8.7 table (Synced / AwaitingAck / AwaitingAckBuffered). Only one op in flight; subsequent local edits buffer (optionally compose to reduce traffic). (ADR-02 Jupiter; INV-8; Sun & Ellis 1998 control-algorithm discipline.)
  4. Ack handling: Apply.origin==self ⇒ acked_rev=rev, pending.pop_front(), send next. (INV-8 revision consistency.)
  5. Remote handling: fold transform(x, p) over pending front→back, mutating each p to its p', yielding rebased remote x; apply(local_doc, x); acked_rev=rev. (INV-4 TP1 applied; INV-5 no lost updates.)
  6. transform_cursor: shift index by net insert/delete deltas left of cursor (clamp to [0,len]). (INV-12; ADR-27 code-point units.)
  7. Desync path: base_rev older than snapshot ⇒ server sends full snapshot + tail; client resets ClientState. (P8 crash-only; INV-1 re-convergence.)

P3.3 Deliverable

End-to-end OT over an in-process relay: N clients, concurrent edits converge byte-identically; cursor follows; the §8.5 worked example reproduced as a test.

Check Target

P3.5 Conformance Fixtures

  • conformance/ot/jupiter/: interleaving transcripts [(site, edit, at_rev)…] → final_doc + per-client rev.
  • Scenarios: 2 inserts same pos; insert vs delete (overlap); 3-way concurrent (still 1 server order); buffered local edits while awaiting ack; reconnect after missed Applys.
  • Cursor fixtures: edit left/right/inside selection → expected transformed range.

P3.6 Pitfalls

  • Forgetting to mutate pending in place during remote rebase → next remote rebases against stale pending → divergence. Update each *p = p'.
  • Allowing >1 op in flight without composing → ack/rev bookkeeping desyncs (INV-8).
  • Server applying op (not transformed op') → server doc diverges from clients.
  • Treating a self-Apply as remote (double-apply) → duplicated text. Match on origin.
  • Cursor transform using byte deltas instead of code-point deltas → off-by-bytes.

P3.7 Performance Concerns

  • Remote rebase is O(|pending| · |op|); cap pending (compose buffered local edits) to bound it (§4: k≤64 ⇒ p95 ≤ 50 µs).
  • Server IT-fold is O(history_tail · |op|); keep tail short via frequent ack & snapshotting.
  • Broadcast fan-out O(clients); batch Applys under load.

P3.8 Edge Cases

  • Two clients submit at identical base_rev (server serializes — first wins order).
  • Client offline during several server ops → on reconnect, base_rev far behind → catch-up replay or snapshot.
  • Empty Submit (no-op) — drop, don't advance rev.
  • Local edit exactly cancels a pending op (compose to identity) — remove from buffer.

P3.9 Failure Analysis

  • Divergence symptom + diagnosis: hash mismatch at quiescence → dump both RevisionLogs + client pending; binary-search the rev where docs split → almost always a transform/rebase ordering bug.
  • Server crash mid-broadcast → some clients lack latest Apply; reconnect SV/rev resync recovers (crash-only, Principle 8).
  • Stuck client (never acks) → pins nothing for OT (server order independent) but stalls its own pending; surface via pending_buffer_depth.

P3.10 Operational Notes

  • Telemetry: pending_buffer_depth, acked_rev, server_rev, rebase_transforms_total, revision_desync (INV-8).
  • Runbook divergence.md: replay both logs in one process; reconnect-storm.md: thundering reconnect after server restart.
  • tools/oplog-inspector lists revisions with origin + op pretty-print.

Phase P4 — Causality primitives (Lamport, vector clocks, version vectors, DVV, causal delivery)

P4.1 Objectives

  • Lamport(u64); VectorClock(BTreeMap<SiteId,u64>); VersionVector (= max seq seen/site); DVV{dot, vv} for concurrent siblings (§11).
  • Partial-order ops: happens_before, concurrent, merge (component-wise max), dominates.
  • Causal-delivery buffer (delivery.rs): holdback an op until its causal deps ⊆ delivered set (INV-2).
  • Deterministic tie-break (clock, siteId) for total ordering of concurrent events (INV-11).
  • Foundation for CRDT (P5+) integration gating, sync (P8), and GC frontier (P11).

P4.2 Detailed Implementation Steps

  1. lamport.rs: tick() (local++), recv(other)→max(self,other)+1; pair (Lamport, SiteId) is a total order. (Kleppmann Ch.8; Tanenbaum Ch.6; INV-7 monotonic clocks; INV-11 determinism.)
  2. vclock.rs: per-site counters; merge, partial_cmp → Less|Greater|Equal|None(concurrent). (Tanenbaum Ch.6; Kleppmann Ch.8; Shapiro et al. 2011 causal ordering; P4 ADR-06.)
  3. vv.rs: VersionVector; covers(dot); add(dot); merge; diff(other)→dots other lacks (drives SV exchange Phase P7). (Kleppmann Ch.5; Shapiro et al. 2011; INV-2 causal delivery; GC frontier P11.)
  4. dvv.rs: dotted-version-vector (Preguiça) — one dot + a VV summarizing the past; is_sibling, sync(a,b). (ADR-06 DVV; Kleppmann Ch.5 concurrent-write detection.)
  5. delivery.rs: holdback Vec<(deps, Op)>; on new op, if deps ⊆ vv deliver+bump+re-scan buffer (cascade), else enqueue; timeout → request-missing. (Cachin et al. causal broadcast; INV-2; Shapiro et al. 2011 op-based CRDT delivery requirement.)
  6. Define "deps": op-based CRDT op carries minimal causal context (RGA: anchor id's dot; Logoot: neighbour ids' dots). (P6 Roh et al. 2011 RGA; P7 Preguiça et al. 2009 Logoot; INV-2.)

P4.3 Deliverable

causality crate: clocks + VV + DVV + a causal-delivery buffer with cascade redelivery, fully property-tested.

P4.4 Acceptance Criteria

Property Statement
Lamport monotonic local clock strictly increases (INV-7)
VC partial order a→b ⇒ VC(a)<VC(b); concurrent ⇒ incomparable
VV merge = lub merge is least upper bound (idempotent, commutative, associative)
Causal delivery no op delivered before all deps (INV-2); buffer drains when deps arrive
Cascade delivering one dep can release a chain of held ops
DVV siblings concurrent writes detected as siblings, not overwrites

P4.5 Conformance Fixtures

  • conformance/ causality: event sequences → happens_before/concurrent truth table.
  • Delivery transcripts: out-of-order arrival [op3, op1, op2] (deps 1<2<3) → delivery order [1,2,3].
  • VV diff fixtures: (vv_a, vv_b) → dots_b_lacks (feeds P8).
  • DVV: concurrent-write fixtures → sibling sets.

P4.6 Pitfalls

  • Using wall-clock or HLC for ordering where causal correctness is required → false ordering of concurrent ops (INV-11). Lamport/VC only in ordering paths.
  • VV component-wise max bugs (forgetting absent sites = 0) → missed deps.
  • Holdback buffer leak: deps that never arrive pin the buffer forever — needs timeout + re-request, not infinite hold.
  • BTreeMap (not HashMap) for deterministic iteration (INV-11).
  • Counting deps too broadly (whole VV) inflates op size; carry minimal deps only.

P4.7 Performance Concerns

  • VV ops are O(#sites); width bounded by GC (§4). Cache sorted site list.
  • Holdback re-scan is O(buffer) per delivery; index pending by missing-dep to make release O(released).
  • DVV is heavier than VV — use only where sibling tracking is needed, not on the hot insert path.

P4.8 Edge Cases

  • First event from a never-seen site (VV component implicitly 0).
  • Self-dependency (op deps on own prior op) — always satisfied locally.
  • Duplicate dot delivered (idempotent — VV already covers) → drop (INV-6).
  • Concurrent ops with equal Lamport → break by SiteId.
  • Site whose counter is reloaded from snapshot must not regress (INV-7).

P4.9 Failure Analysis

  • A causal-delivery bug surfaces as a CRDT divergence or panic (dangling anchor) far downstream → test causality in isolation first.
  • Holdback stall (causal_holdback_stalled, INV-2): a missing op; diagnose via VV gap → re-request range.
  • Clock regression after crash (counter not persisted) → reused dots → divergence; persist max-seq per site.

P4.10 Operational Notes

  • Telemetry: causal_holdback_depth, missing_deps_total, vv_width, per-site max_seq.
  • tools/vv-visualizer: render VVs across sites + the causal-stability frontier (min) used by GC.
  • Runbook gc-stall.md references VV frontier; this crate computes it.

Phase P5 — CRDT sequence engine A: RGA (Replicated Growable Array)

P5.1 Objectives

  • Primary CRDT (ADR-03): Element{ id: RgaId, value: char, deleted: bool, origin_left: RgaId } (§8.2, §11).
  • integrate(e) with the RGA ordering rule: concurrent inserts after the same anchor ordered by id (newer/higher (seq desc, site) first) so all sites agree (INV-3).
  • Delete = tombstone (deleted=true), value retained for anchoring later inserts (INV-9).
  • Causal delivery gate (P4): integrate only when origin_left present (INV-2).
  • DocumentReplica impl for RGA; SEC laws (commutative/associative/idempotent) property-tested (§8.3, INV-1).

P5.2 Detailed Implementation Steps

  1. rga.rs store: ordered structure keyed by document position — a sorted Vec<Element> or a balanced index (id→slot) plus an order-tree for O(log n) insert; choose order-tree to keep splice sub-linear at scale (§4 10M chars). (Roh et al. 2011 RGA element model; ADR-03; INV-3 total order of ids.)
  2. Insert path: apply_local(Insert{at,text}) → for each char: find element at at-1 as origin_left (or HEAD sentinel), allocate id=(self.site, seq++), build element, integrate locally, emit native op carrying (id, value, origin_left) + causal dot. (Roh et al. 2011 RGA insert; INV-7 monotonic seq; P4 causality.)
  3. integrate(e): locate origin_left slot; scan rightward over elements that are also anchored ≥ e.origin_left and have id > e.id (concurrent, higher id) — skip them; splice e before the first element with id < e.id (descending rule). Idempotent: if e.id already present, drop (INV-6). (Roh et al. 2011 RGA ordering rule; Shapiro et al. 2011 SEC idempotence; INV-3.)
  4. Delete path: tombstone set (INV-9); resurrection guard via frontier (P11 GC, INV-9); holdback for unseen deps (INV-2; Phase P4 delivery.rs).
  5. text(): traverse order, skip tombstones, collect values; cache + invalidate on mutation. (P7 honest accounting; Attiya et al. 2016 lower bounds — tombstones are the cost of convergence.)
  6. version(): VV over (site→max seq). size_report(): live vs tombstone counts, id_bytes = 12·elements, meta bytes. (P7 honest memory; §4 24 B/char constraint; ADR-06.)
  7. Cursor model: store cursor as RelativeTo(RgaId, offset) (ADR-29) so it survives concurrent edits without transform. (INV-12; Phase P8 cursor handling.)

P5.3 Deliverable

RGA engine behind DocumentReplica; multi-replica in-process convergence (no network yet) on concurrent insert/delete schedules; SEC property tests green.

Check Target

P5.5 Conformance Fixtures

  • conformance/crdt/rga/: element schedules [(id, value, origin_left, op)…] in varying delivery orders → expected text() + order key list.
  • Concurrent-anchor fixtures: 3 sites insert after the same char → canonical id-descending order.
  • Tombstone fixtures: delete then concurrent insert anchored on deleted element → insert survives in correct position.
  • Idempotent-delivery fixtures: duplicated element stream → unchanged text.

P5.6 Pitfalls

  • Interleaving on RGA: concurrent runs of insertions after the same point interleave char-by-char (the anomaly P12/Fugue addresses); document it, fixture it, defer the fix to engine selection (§6 vs Fugue). Manifestation: "HELLO"+"WORLD" concurrently → "HWEOLRLLOD". Root cause: per-char anchoring + id tie-break. Debug: dump order keys; instrument with interleave_runs counter.
  • Wrong scan direction in the ordering rule → inconsistent order across sites → divergence. Property-test the comparator (INV-3) before integrate.
  • Resolving at→element by live index vs all-elements index (tombstones counted?) — apply_local indexes live chars; integrate works by id. Mixing them mis-anchors. Keep two distinct mappings.
  • Materialized-string cache not invalidated on tombstone set → stale text().
  • Allocating seq non-monotonically after crash reload → id reuse → divergence (INV-7); persist max seq.

P5.7 Performance Concerns

  • Naive Vec insert is O(n); the concurrent-anchor scan can be O(n) per insert worst case → use an order-statistics tree (rank/select) for O(log n) anchor lookup + splice.
  • Tombstones inflate traversal (text() walks them) → keep a parallel live-only index or run-length-encode runs (diamond-types idea) post-P13.
  • id_bytes dominate memory at 24 B/char (§4) — measure honestly; this is the CRDT cost axis.
  • Cache line behavior: element struct ≤ 32 B keeps two per line; avoid pointer-chasing linked-list layout (read yrs/block.rs).

P5.8 Edge Cases

  • Insert at HEAD (origin_left=HEAD sentinel) and at tail; delete already-deleted element (no-op, idempotent); insert anchored on a tombstone; two sites allocate same seq (impossible — site disambiguates); empty doc; 10M-char stress (order-tree depth).
  • Concurrent delete of the same element by two sites → both set the same tombstone (idempotent).

P5.9 Failure Analysis

  • Divergence in RGA mode → dump per-replica ordered (id, value, deleted) lists; diff the first position where order keys differ → comparator or scan bug (INV-3). Blast radius: the document; containment: re-sync from a converged replica.
  • Dangling anchor panic (integrate before origin_left arrives) → causal-delivery gate missing (INV-2); never integrate ungated.
  • Tombstone resurrection (late delete after GC) → frontier guard (INV-9); forensic: compare op VV vs frontier.

P5.10 Operational Notes

  • Telemetry: rga_elements, rga_tombstones, tombstone_ratio, integrate_latency, interleave_runs, id_bytes.
  • tools/doc-state-dumper extended: emit RGA order + tombstone map + per-site seq.
  • Runbook divergence.md: RGA branch — comparator/scan first; CRDT cannot "rebase", so divergence = ordering disagreement.

Phase P6 — CRDT sequence engine B: Logoot/LSEQ dense position ids + interleaving handling

P6.1 Objectives

  • Secondary CRDT (ADR-04): PosId { path: [(digit:u64, site:u32)] }, lexicographic total order; LogootEntry{ pos, value, deleted } (§8.2, §11).
  • alloc(p_left, p_right, site) producing a dense id strictly between neighbours: Logoot (random digit, descend level on exhaustion) and LSEQ (per-level boundary+/boundary− strategy by coin, bounding average path growth).
  • Set-union semilattice: immutable totally-ordered ids ⇒ SEC trivially (§8.3, INV-1) — the comparison foil to RGA's anchor model.
  • Interleaving handling: show LSEQ's interleaving behavior vs RGA; document the YATA/Fugue origin-based fix as the design lever (cross-link Fugue P12 / engine selection).

P6.2 Detailed Implementation Steps

  1. id.rs extend: PosId lexicographic Ord over (digit, site) pairs; MIN/MAX sentinels for ends. (Preguiça et al. 2009 Logoot dense-id model; INV-3 total order; ADR-04.)
  2. logoot.rs alloc: descend the shared prefix of p_left,p_right; at the deepest level with a free interval, pick a random digit in (left_digit, right_digit) tagged with site; if interval empty, append a new level. (Preguiça et al. 2009 Logoot alloc algorithm; §4 id-path ceiling.)
  3. lseq.rs: per-depth allocation strategy stored in strategy[] decided by a deterministic-per-site coin; boundary+/boundary−; doubling base per level. (Nédelec et al. 2013 LSEQ adaptive allocation; §4 avg path O(log n) target.)
  4. Store: sorted BTreeMap<PosId, LogootEntry> (deterministic order, INV-11); insert + delete. (ADR-04; Shapiro et al. 2011 SEC set-union semilattice for Logoot.)
  5. DocumentReplica impl: apply_local(Insert) allocates ids per char; integrate is idempotent (INV-6); causal delivery via Phase P4 holdback. (INV-2; Preguiça et al. 2009.)
  6. Interleaving experiment hooks: two-site concurrent-run workload; record for Phase P12 matrix. (Kleppmann et al. 2022 Fugue interleaving anomaly analysis; Comparative Architecture Table.)

P6.3 Deliverable

Logoot + LSEQ engines behind DocumentReplica; convergence on concurrent schedules; an instrumented interleaving comparison vs RGA; id-path-length growth measured under sequential and adversarial typing.

P6.5 Conformance Fixtures

  • conformance/crdt/logoot/: (p_left, p_right, site, rng_seed) → alloc'd PosId; deterministic given seed.
  • Order fixtures: random PosId sets → sorted order (totality check).
  • Growth fixtures: sequential N-char typing → recorded path-length series (LSEQ vs Logoot).
  • Interleaving fixtures: two concurrent runs at one boundary → resulting char order (compare RGA vs LSEQ).

P6.6 Pitfalls

  • Path explosion under monotone insertion (always at one end): Logoot grows path ~linearly → bytes/char balloon (§4 up to 200 B). Manifestation: memory blow-up on "append-only" docs. Root cause: no free interval at shallow levels. Mitigate: LSEQ adaptive strategy; instrument pos_path_len.
  • RNG determinism: alloc uses randomness — must be seeded per-site and reproducible (INV-11) or replay/differential tests diverge. Never use thread RNG in the ordering path.
  • Tombstone vs removal: Logoot can remove (absolute ids) but a removed id can't be a UI cursor anchor afterward — store cursors as resolved indices or nearest live id.
  • Base/level off-by-one in alloc → non-dense ids (can't insert between) → alloc fails to find a slot.
  • LSEQ strategy array must be agreed implicitly (same coin per depth) — but it is per-site; ids stay globally ordered because the digit comparison is global. Confusing per-site strategy with global order → bugs.

P6.7 Performance Concerns

  • alloc is O(path len); path len O(log n) (LSEQ) to O(n) (Logoot adversarial). Hot path → cache the neighbour PosIds at the cursor.
  • BTreeMap<PosId,_> compares variable-length paths — O(path) per comparison; large paths slow inserts. Bound via LSEQ.
  • Memory: PosId is a SmallVec; inline small paths (≤8) to avoid heap per char.
  • text() walks the BTree in order — O(n); cache + invalidate.

P6.8 Edge Cases

  • Insert between adjacent ids with no free digit at any shared level (must descend/extend); insert at the very start (MIN,first) / end (last,MAX); two sites alloc between the same pair concurrently (both succeed, ids differ by site, order by digit then site); empty doc; massive adversarial append (path-length ceiling alarm).

P6.9 Failure Analysis

  • Divergence: differing id sets → a dropped/duplicated insert; same id set differing text → impossible unless value mismatch on same pos (corruption) → checksum values. Blast radius: document; recovery: state-based re-merge (union of (pos,value)).
  • Path-length exhaustion (ceiling breach limit_exceeded{pos_path}): adversarial workload; mitigate by switching to LSEQ or compacting ids at GC (re-base paths below frontier).
  • RNG divergence across builds → differential test fails on two arches (INV-11) → fix seed plumbing.

P6.10 Operational Notes

  • Telemetry: pos_path_len histogram, logoot_entries, alloc_latency, id_bytes (compare to RGA's).
  • tools/vv-visualizer extended to plot id-path-length growth curves (LSEQ vs Logoot) — feeds the Phase P12 comparison matrix.
  • Engine-selection note in docs/comparison.md: dense-id vs anchor-id tradeoff (bytes vs interleaving), Fugue as the reconciling design.

Phase P7 — Sync protocol: WebSocket transport, server-relay + P2P state-vector exchange

P7.1 Objectives

  • protocol crate finalized: SyncMessage/WireOp (§8.4), CBOR + JSON codecs (ADR-08), length-prefix framing, proto_ver negotiation (Principle 11).

  • OT path: server-relay (Submit/Apply) — the order authority from P3 over the wire.
  • CRDT path: two-step state-vector exchange (SV1/SV2/Update, §8.4) for both server fan-out and P2P pairwise sync.
  • Idempotent integrate (INV-6) makes overlap/retransmit safe; bounded channels (Principle 9) provide backpressure.

P7.2 Detailed Implementation Steps

  1. protocol/message.rs: SyncMessage enum + WireOp tagged union (OT component stream | RGA element | Logoot insert | delete). codec.rs: CBOR encode/decode, JSON debug encoder, 4-byte length prefix + CRC32 (§8.6 garbled-frame drop). version.rs: Hello{proto_ver} handshake, negotiate min(common); reject incompatible with Bye.

  • CBOR encode/decode allocation per message → reuse buffers; batch small Updates into one frame.

  • Two peers initiate SV exchange simultaneously (both send SV1) → both reply SV2; idempotence makes the double exchange harmless.
  • Frame larger than max size → fragment or reject with LimitExceeded (INV-10).
  • Half-open TCP (peer vanished) → ping/pong timeout → treat as disconnect, buffer offline (P8).

  • Wire-layer divergence (two encodings) is the protocol analog of INV-1 breach — Principle 11 prevents it via versioning; detection: decode error counters spike, or convergence oracle fails only across-version.

  • Reconnect storm: many clients reconnect at once after a server restart → thundering SV1/Submit; rate-limit + jittered backoff (runbook reconnect-storm.md).
  • Replaying offline OT ops without rebasing past intervening server ops → divergence; must transform the whole backlog first (P3).

P8.7 Performance Concerns

  • Awareness chatter: cursor-move floods → throttle to ~30 Hz, coalesce; awareness is best-effort, droppable (unlike ops).
  • TTL sweep O(#peers) per tick — fine at 256 sites; use a min-heap by last_seen if larger.
  • Reconnect catch-up cost bounded by backlog size (§4 convergence-after-heal); batch the backlog into few frames.
  • CRDT cursor resolution at render is O(log n) (order-tree rank) — cache per frame.

P8.8 Edge Cases

  • Peer disconnects mid-selection → selection cursor expires with presence.
  • Offline edits that exactly cancel (type+delete) → compose to identity before resync (OT); CRDT emits insert+tombstone (no cancellation, but converges).
  • Clock-skewed last_seen → TTL uses local receipt time, not sender clock.
  • Reconnect after the doc was snapshotted+GC'd while offline → offline op references a GC'd anchor → resurrection guard / full re-sync (INV-9).
  • Two sites pick the same color/name → cosmetic only; disambiguate by siteId in UI.

P8.9 Failure Analysis

  • Lost presence (peer's cursor stuck) → TTL self-heals; if not, awareness send loop wedged → awareness_send_errors.
  • Offline divergence on reconnect → almost always un-rebased OT backlog (OT) or a held dep never requested (CRDT, INV-2); diagnose via causal_holdback_depth + backlog dump.
  • Backpressure stall (editor frozen offline) → buffer ceiling hit; surface as UI signal + limit_exceeded{offline_buffer}.
  • Forensics: offline buffer snapshot + the server rev/vv at reconnect.

Phase P10 — Undo/redo: per-user selective undo under concurrency (both engines)

P10.1 Objectives

  • Per-user selective undo (undo my last edit, not the globally-last) under concurrency, for both engines (§11 UndoManager).
  • OT: undo = apply invert(op) then transform it past all ops applied since (so it undoes the original intention in the current context) — uses ET/IT (P2).
  • CRDT: undo of an insert = tombstone its element(s); undo of a delete = clear the tombstone (restore) — redo is the inverse. Selective by tracking each local op's element ids.
  • Redo stacks; group consecutive keystrokes into one undo unit; per-user isolation invariant (one user's undo never reverts another's edit).

P10.2 Detailed Implementation Steps

  1. editor-core/undo.rs: UndoManager{ stacks: HashMap<SiteId, Vec<UndoEntry>> }; UndoEntry::Ot(inverse_op) | Crdt(Vec<ElementId> + kind) (§11). Push on each local edit; group by a coalescing timer/word boundary.
  2. OT undo: pop inverse inv; transform inv past every op applied after the original (server ops + own later ops) via repeated IT so it lands in the current document context; apply; emit as a new op (undo is itself an op that propagates). Redo: invert the inverse similarly.
  3. CRDT undo: pop entry; for an undone insert, tombstone those ids (emit deletes); for an undone delete, restore (emit "un-delete" = clear tombstone, a new op type guarded by causal rules). Redo re-applies.
  4. Selective semantics: each user's stack holds only their ops; undoing transforms/restores only those, even after others' concurrent edits interleaved.
  5. Concurrency correctness: undo ops go through the same convergence machinery (OT transform / CRDT integrate) → other replicas converge on the undo (INV-1).
  6. Edge handling: undoing an insert that others already deleted (CRDT: tombstone already set → idempotent no-op); undoing into a region that changed shape (OT: transform handles relocation).

P10.3 Deliverable

Working per-user undo/redo in both engines, correct under concurrent remote edits; an undo by user A never reverts user B's text; convergence preserved.

P10.4 Acceptance Criteria

Check Target

CRDT undo/redo tombstone/restore round-trips; idempotent
Per-user isolation A's undo affects only A's edits (no cross-user revert)

Redo redo == undo of undo (state round-trip)
Grouping a typed word undoes as one unit

P10.5 Conformance Fixtures

  • conformance/ undo: (initial, [local + remote ops], undo k) → expected text (both engines).
  • Selective fixtures: interleaved A/B edits, A undoes → only A's change reverted.
  • OT relocation fixtures: undo an insert after the surrounding text was concurrently edited → inverse transformed correctly.
  • CRDT restore fixtures: undo a delete → element un-tombstoned; concurrent delete by other → stays deleted (resolution documented).

P10.6 Pitfalls

  • OT undo without transforming the inverse past intervening ops → undoes the wrong region (the classic selective-undo bug); always relocate via IT chain.
  • CRDT "un-delete" reintroduces resurrection concerns (INV-9): only valid above the frontier; a delete below frontier can't be undone (already universally applied) — surface as a no-op + log.
  • Cross-user revert: undo touching another user's element ids → isolation violation; stacks are strictly per-SiteId.
  • Grouping boundaries wrong → undo reverts too much/little; coalesce by time + word, document the rule.
  • Redo stack not cleared on a new edit → redo applies a stale op into a changed doc → corruption; clear redo on fresh local edit.

P10.7 Performance Concerns

  • OT undo transform cost O(ops-since-original) — bounded by snapshot horizon; cap stack depth.
  • CRDT undo is O(affected ids) — cheap; restore just flips flags + emits ops.
  • Undo stacks grow per user → bound depth (e.g. 1000 entries); oldest dropped.

P10.8 Edge Cases

  • Undo with an empty stack (no-op); undo an op already undone by convergence (idempotent); undo a delete whose element was GC'd (no-op + log); undo across an offline/reconnect boundary (op rebased); redo after remote edits; interleaved undo+redo by two users.

P10.9 Failure Analysis

  • Undo causes divergence → the undo op itself broke TP1 (OT) or wasn't integrated everywhere (CRDT); treat undo ops exactly like normal ops in the oracle.
  • Wrong-region undo → un-relocated inverse; reproduce with the intervening op set; fixture it.
  • Cross-user revert → isolation bug; audit stack keying by SiteId.
  • Forensics: undo-stack dump + the op ids each entry references.

P10.10 Operational Notes

  • Telemetry: undo_ops, redo_ops, undo_stack_depth{site}, undo_noop (already-applied/GC'd).
  • Undo ops carry provenance (is_undo=true, original op id) for tracing.
  • docs/comparison.md: undo-semantics verdict — OT (transform inverse) vs CRDT (tombstone toggle); CRDT undo simpler, OT undo more faithful to original intention.

Phase P11 — Persistence: oplog + snapshot + tombstone GC / compaction

P11.1 Objectives

  • OT persistence (ADR-09): append-only oplog of server-ordered revisions + periodic materialized snapshot + version index; crash-only replay (Principle 8).
  • CRDT persistence (ADR-10): delta/state store + snapshot.
  • Tombstone GC (ADR-11, INV-9): compute the causal-stability frontier = component-wise min over all sites' version vectors; reclaim tombstones/oplog/ids strictly below it; never above (resurrection guard).
  • Compaction: rewrite snapshot post-GC; truncate oplog before snapshot; CRDT id re-basing (optional) below frontier.
  • Document load/replay: restart reconstructs identical state (INV-1, INV-7 counters restored).

P11.2 Detailed Implementation Steps

  1. sync/persist.rs OT: oplog file = length-prefixed CBOR (rev, Op, SiteId) records (append, fsync on batch); snapshot = (rev, materialized text); version index maps rev → file offset. Replay = load snapshot + apply oplog tail.
  2. CRDT store: either full-state snapshot (elements + tombstones + VV) or accumulated deltas since last snapshot; snapshot persists post-GC compacted state + the frontier VV.
  3. crdt/gc.rs: collect all reachable sites' VVs (server tracks via Ack{up_to}, §8.4); frontier = min_component(VVs); mark reclaimable = tombstones whose causal dot ≤ frontier and no live element anchors them above frontier; physically remove; OT: drop oplog entries < frontier rev (after snapshot).
  4. GC trigger: on each frontier advance, or every N ops / tombstone-ratio breach (§4 ≤2× live); run incrementally to bound pause.
  5. Crash recovery: on load, restore per-site max-seq (INV-7) from snapshot+oplog; tolerate a trailing partial/corrupt record (truncate to last valid, Principle 8); validate via checksum.
  6. Snapshot↔GC coupling: a snapshot below the frontier lets everything before it be reclaimed safely (the snapshot is the universally-agreed past).
  7. Frontier acks: clients send Ack{up_to: vv} periodically; server maintains per-site VV; an offline site pins the frontier (INV-13) — bounded by an eviction policy (a long-gone site can be force-evicted with operator action, advancing the frontier).

P11.3 Deliverable

Durable docs: kill -9 at any point and reload to identical converged state (both engines); tombstone GC reclaims memory below the frontier; snapshot+compaction bounds storage (§4 amplification ≤3×).

P11.4 Acceptance Criteria

Check Target

GC safety post-GC convergence with a late op below frontier → rejected as resurrection (INV-9)

P11.5 Conformance Fixtures

  • conformance/ persistence: (snapshot + oplog tail) → reconstructed text + VV.
  • GC fixtures: (elements, tombstones, site VVs) → frontier + reclaimable set + post-GC state.
  • Crash fixtures: oplog truncated mid-record → recovered state == pre-truncation valid prefix.
  • Resurrection fixtures: late delete with dot < frontier → rejected (INV-9).

P11.6 Pitfalls

  • GC too early (above frontier) → tombstone removed, then a concurrent insert that anchored on it arrives → dangling/resurrection (INV-9, the cardinal GC bug). Never reclaim above the strict min.
  • Frontier stuck at an offline site → no GC, unbounded tombstones (INV-13 tradeoff); needs site eviction policy + operator runbook (gc-stall.md).
  • Not persisting per-site max-seq → post-crash id reuse → divergence (INV-7). Restore counters before accepting new local edits.
  • fsync omitted → lost tail on power-loss → divergence vs peers; batch+fsync with a bounded window.
  • Snapshot taken mid-mutation (torn) → reload corruption; snapshot from a consistent point (between ops, single-owner actor makes this clean).
  • OT oplog truncated below a client's acked_rev while that client is offline → its reconnect base_rev is gone → must full-resync (handled, but must be detected not silently dropped).

P11.7 Performance Concerns

  • Snapshot write is O(doc); cadence trades startup time vs write amplification — tune to §4 (≤3× amplification, ≤50 ms startup).
  • GC scan is O(tombstones); run incrementally to avoid a stop-the-world pause; bound per-cycle work.
  • fsync latency dominates durability path → batch ops per fsync (group commit); expose fsync_latency.
  • CRDT id re-basing at GC (compacting PosId paths / RGA seq) is expensive — optional, gated behind a compaction job, not the hot path.
  • Memory after GC should drop measurably — the harness (Phase P12) reports pre/post-GC SizeReport.

P11.8 Edge Cases

  • Empty oplog (fresh doc); snapshot newer than oplog (no tail to replay); all sites at the same VV (frontier = full state, max GC); a never-acking site (frontier pinned); doc with 50% tombstones pre-GC; concurrent GC + incoming op (GC reads a consistent frontier snapshot, new op buffered).
  • Reload after format-version bump → snapshot migration (Compatibility & Versioning).

P11.9 Failure Analysis

  • Oplog corruption → checksum catches it; truncate to last valid + resync the rest from peers/snapshot; blast radius bounded to the corrupt tail.
  • Premature GC resurrection → divergence; detection: tombstone_resurrection_attempt (INV-9); recovery: re-sync from a replica that retained the tombstone; long-term: audit frontier computation.
  • GC stall (frontier pinned) → memory growth alarm (tombstone_ratio high) + gc_frontier flat; recovery: identify the lagging/offline site (vv-visualizer), evict per policy.
  • Lost fsync on crash → post-restart divergence vs peers; detection: convergence oracle on reconnect; recovery: re-sync (CRDT) / re-submit pending (OT).
  • Forensics: snapshot + oplog + frontier history; tools/oplog-inspector.

P11.10 Operational Notes

  • Telemetry: oplog_bytes, snapshot_age, gc_frontier, gc_reclaimed, tombstone_ratio, fsync_latency, replay_duration.
  • Runbook gc-stall.md: diagnose pinned frontier → identify lagging site → evict; backup/restore procedure.

Phase P12 — Comparison harness + convergence simulator (DST) + benchmark matrix (THE DELIVERABLE)

P12.1 Objectives

  • The project's headline artifact: a fair, reproducible OT-vs-CRDT comparison matrix across all axes — correctness, metadata overhead, latency, memory growth, GC cost, server dependence, complexity, undo semantics, rich-text, anomaly class.
  • Deterministic Simulation Testing (DST): a single-threaded, seed-driven simulator that models N sites, a network (delay/reorder/dup/drop/partition/heal), and drives both engines through identical schedules; the convergence oracle asserts INV-1 at every quiescence.
  • Differential testing: same input → OT vs CRDT (and RGA vs Logoot/LSEQ) must reach the same text (where semantics agree) and any documented divergence (e.g. interleaving) is asserted, not accidental.

P12.2 Detailed Implementation Steps

  1. harness/workloads.rs: generators — Typing{wpm, sites}, Paste{size}, ConcurrentHotspot{sites, pos}, AdversarialAppend, PartitionChurn{heal_after}; each emits a deterministic Vec<LocalEdit> per site given a seed.
  2. fuzz-core/lib.rs: the DST core — a logical-time event loop; each step picks (by seeded RNG) a site to make a local edit or the network to deliver/reorder/drop/dup a buffered message; partitions split the site set, heal reconnects and floods the backlog. No wall-clock, no threads → fully reproducible (INV-11).
  3. harness/differential.rs: run the same schedule through OT (over an in-process relay) and each CRDT engine; at every quiescence (all messages delivered) hash text() across replicas and across engines; assert INV-1; record any engine-disagreement as a typed result (expected vs bug).
  4. harness/metrics.rs: collect per-engine SizeReport (honest bytes, Principle 7), apply/integrate latency histograms (criterion-fed), convergence time, message/byte counts, GC reclaim; pre/post-GC memory.
  5. harness/matrix.rs: aggregate metrics + qualitative verdicts into the comparison matrix; render to docs/comparison.md (markdown table) and a CSV in benchmarks/results/.

  7. Soak mode: long-running random schedule with periodic GC, asserting bounded memory + sustained convergence.

  • Fuzzers testing only one engine miss cross-engine divergence; the differential target is the high-value one.
  • Non-reproducible fuzz inputs (unseeded) → can't replay a crash; libFuzzer corpus + DST seed captured always.
  • Fixtures encoding current (possibly buggy) behavior as "expected" → freezes a bug; derive expecteds from spec/laws (INV-4, SEC), not the implementation.
  • Ceilings without backpressure → OOM (no limit) or silent drop (hard limit, no signal); pair every limit with a shed-with-policy.
  • Non-reproducible build (timestamps, parallel codegen ordering) → provenance broken; pin everything (ADR-26).

P13.7 Performance Concerns

  • Fuzz throughput: keep targets allocation-light so libFuzzer explores deeply; reuse input buffers.
  • Enforcement checks on the hot path (size/limit) must be O(1) amortized — counters, not scans.
  • Release builds with full optimization + LTO; verify determinism preserved under LTO (ADR-26).

P13.8 Edge Cases

  • Fuzzer generates an op on an empty doc, a max-size doc, all-tombstone state, single-site schedule, never-healing partition (assert per-partition only).
  • Exactly-at-ceiling vs one-over; a burst that momentarily exceeds a queue then drains; new engine with a larger Op type stressing the wire codec; reproducible build across two machines/OSes.

P13.9 Failure Analysis

  • A fuzz-found divergence → highest priority; replay → shrink → fix → freeze as fixture (same process as P12.9).
  • A ceiling that fires under normal load → mis-tuned (§4 too tight); limit_exceeded spikes; re-tune.
  • Backpressure deadlock (cyclic wait between channels) → consistent channel acquire order (§6 P15); detect via queue-depth saturation.
  • Unsigned/unreproducible artifact → release blocked; provenance gate in release.yml.

P13.10 Operational Notes

  • Telemetry: conformance_pass_rate, fuzz_exec_per_s, corpus_size, determinism_diffs, limit_exceeded{kind}, queue-depth gauges, build-provenance labels.
  • Every merged PR must keep the conformance suite green; fuzz-found regressions block merge until fixtured.
  • Release notes document wire/API/storage version changes (Compatibility & Versioning, semver).
  • On-call references docs/runbooks/ + the comparison matrix for engine-specific behaviour.

Failure Modes & Recovery

Comprehensive taxonomy. Each class: symptoms · root causes · detection · automatic recovery · manual recovery · forensic artifacts · long-term mitigation.

F1 — Divergence (INV-1 breach). Symptoms: two replicas show different text() at quiescence; users see different documents. Root causes: OT transform/rebase bug (broke TP1), CRDT comparator/ordering bug (INV-3), nondeterminism leak (INV-11), lost fsync after crash. Detection: convergence oracle (harness/fuzz) hashes text(); production divergence alarm via periodic cross-replica checksum exchange. Auto recovery: CRDT — re-run state-vector exchange (union of state); OT — client full re-sync from server snapshot+oplog. Manual: dump both oplogs, replay in one process, binary-search the splitting op; freeze as fixture. Forensics: per-replica oplog + VV + op provenance. Long-term: the divergent op class becomes a permanent property/fuzz fixture.

F2 — Dropped op. Symptoms: a user's edit missing on peers (INV-5). Root causes: lost frame, channel shed, missed broadcast. Detection: op in local log absent in peer after quiescence (lost_update). Auto: OT pending buffer re-Submit; CRDT VV-diff resend. Manual: diff local oplog vs peer state by op id. Forensics: pending buffer + VV gap. Long-term: idempotent resend on every reconnect (INV-6).

F3 — Duplicated op. Symptoms: (none, if correct) — duplicated text only if idempotence broken. Root causes: at-least-once delivery + a missing seen-check. Detection: duplicate_integrate_count nonzero with text unchanged (good) vs changed (bug). Auto: VV/id seen-check drops dupes (INV-6). Manual: assert text-hash unchanged on replay of duplicates. Forensics: op ids + VV. Long-term: idempotence property test.

F4 — Reordered delivery. Symptoms: CRDT integrate of an op before its deps. Root causes: multi-peer P2P delivers a later-dep op first. Detection: causal_holdback_depth grows. Auto: holdback buffer orders correctly; cascade releases on dep arrival (INV-2). Manual: inspect holdback + VV gap; re-request missing range. Forensics: holdback contents. Long-term: keep the holdback on every receive path, even over FIFO transports.

F5 — Partition + heal. Symptoms: sides edit independently; on heal a large backlog. Root causes: network split. Detection: connection loss; backlog size on reconnect. Auto: SV exchange (CRDT) / rebase backlog + Submit (OT) converges within backlog bound (§4). Manual: none if within bounds; if backlog huge → throttle catch-up. Forensics: offline buffer + server rev/VV at heal. Long-term: bounded offline buffer (INV-10) + jittered reconnect (reconnect-storm.md).

F6 — Clock anomaly / regression. Symptoms: reused dots → id collision → divergence (INV-7). Root causes: per-site seq not persisted across crash; HLC/wall-clock used in an ordering path (INV-11). Detection: clock_regression; a received op with seq ≤ already-seen from a site. Auto: reject the regressed op. Manual: restore per-site max-seq from snapshot+oplog before accepting edits. Forensics: per-site max_seq history. Long-term: persist counters (P11); ban wall-clock from ordering (lint, INV-11).

F7 — GC too early → tombstone resurrection. Symptoms: a deleted character reappears; divergence (INV-9). Root causes: reclaimed a tombstone above the frontier; frontier mis-computed. Detection: tombstone_resurrection_attempt; a late delete/insert referencing a reclaimed id. Auto: resurrection guard rejects ops whose dot < frontier (already universally applied). Manual: re-sync from a replica that retained the tombstone; audit frontier = strict min over all reachable VVs. Forensics: frontier history + the offending op's VV. Long-term: never reclaim above min (Principle 13); GC unit-tested against the frontier.

F8 — GC stall (frontier pinned). Symptoms: unbounded tombstone/memory growth; GC never advances. Root causes: an offline/lagging site pins min (INV-13). Detection: gc_frontier flat + tombstone_ratio rising. Auto: none (correct behavior — can't GC what a site might need). Manual: identify the lagging site (vv-visualizer), evict per policy (operator), frontier advances. Forensics: per-site VV + last-seen. Long-term: eviction policy + alarm; document in gc-stall.md.

F9 — Oplog / snapshot corruption. Symptoms: reload fails or yields wrong state. Root causes: torn write, disk fault. Detection: per-record checksum mismatch (oplog_checksum_fail). Auto: truncate to last valid prefix (Principle 8); re-sync the rest from peers. Manual: restore from backup snapshot+oplog; restore-test confirms. Forensics: the corrupt record offset + checksum. Long-term: group-commit fsync + redundant snapshots + restore drills.

F10 — OT revision desync. Symptoms: client acked_rev disagrees with server order (INV-8). Root causes: base_rev below a truncated snapshot; >1 op in flight bookkeeping bug. Detection: revision_desync. Auto: server full re-sync (snapshot + tail). Manual: compare client/server revision logs. Forensics: both revision logs + client pending. Long-term: single-op-in-flight discipline + snapshot horizon ≥ slowest client (P3/P11).

F11 — Holdback never drains. Symptoms: CRDT ops stuck, doc stops converging. Root causes: a dep dropped and never re-requested. Detection: causal_holdback_stalled (timeout). Auto: timeout → request-missing-range via SV exchange. Manual: inspect VV gap, force a state-based merge (full union). Forensics: holdback buffer + VV. Long-term: timeout + re-request, never infinite hold (INV-2).

F12 — Backpressure deadlock. Symptoms: system wedges, queues saturated both directions. Root causes: cyclic wait between bounded channels. Detection: multiple queue_depth gauges pinned at max, no progress. Auto: none. Manual: restart the wedged actor (crash-only). Forensics: queue-depth snapshot + task states. Long-term: consistent channel acquire order (Principle 15); avoid cycles by design.

Migration: snapshot format carries a version; loader migrates older snapshots (Compatibility & Versioning).

Compatibility & Versioning

Wire compatibility (Principle 11, ADR-08). SyncMessage/WireOp carry proto_ver; Hello negotiates the min common version. Within a major version: additive message/component variants only; unknown variants from a newer peer are rejected gracefully (negotiated down), never misparsed. A major bump (incompatible framing/semantics) requires both ends to support it or the connection refuses with Bye. CRC + length framing are version-invariant.

Storage compatibility. Oplog records and snapshots carry a format version. The loader reads all versions ≥ a documented floor; older snapshots are migrated forward on load (one-way). A trailing partial record is tolerated (truncate to last valid, Principle 8). Snapshot evolution: new fields are additive with defaults; removed fields are reserved, never reused.

Op / id format stability. OT Component tag space is reserved (Retain=0, Insert=1, Delete=2; future tags bump proto_ver). CRDT RgaId (site:u32, seq:u64) and PosId (path of (u64,u32)) widths are fixed; changing them is a major version. This stability lets cross-version replicas converge on the linear-text core.

Cross-version replicas. Two replicas on different minor versions converge because: (a) the wire is negotiated to the common subset; (b) op/id formats are stable within the major; (c) integrate is idempotent (INV-6) so any redundant transfer is harmless. A replica that cannot represent a newer op variant negotiates down rather than diverge.

API stability. DocumentReplica (the seam, Principle 1) is the public contract; it is stable within a major version (additive default methods only). Engine-internal types may change freely behind it. The harness and any embedding editor depend only on the trait.

Semantic versioning (ADR-28 license; semver policy). MAJOR = incompatible wire/storage/trait change; MINOR = additive (new variant/method/engine) backward-compatible; PATCH = fixes. Deprecation: a feature is marked deprecated for one MINOR cycle (with telemetry on use) before removal in the next MAJOR. Wire proto_ver and storage format version are tracked in CHANGELOG.md.

Rolling-upgrade guarantee. A cohort mid-upgrade (mixed minor versions) stays converged for the duration, by the cross-version argument above. This is what makes canary + rollback safe (Operational Readiness).

Scalability Analysis

  • Editors per doc. Server mode ≤ 256 active (§4) — bounded by VV width (= sites ever seen, shrinkable by GC) and broadcast fan-out O(sites). P2P ≤ 32 — mesh is O(n²) connections + n-way SV exchange. Beyond these, shard editors via sub-documents or a fan-out tier (deferred).
  • Oplog / tombstone growth. OT oplog truncates to snapshot → O(doc) steady-state. CRDT tombstones grow until GC; bounded by the frontier (≤2× live between cycles, §4). A pinned frontier (offline site) is the scaling risk → eviction policy (INV-13, F8).
  • Server fan-out. Each op broadcast to all subscribers → O(sites) per op; Arc-shared payloads + batched frames bound CPU/bandwidth; a busy doc with 256 editors at 10 ops/s = 2.56k broadcasts/s/doc — fine; 1k such docs = 2.56M sends/s aggregate → the server scaling ceiling, mitigated by per-doc actors + horizontal doc sharding.
  • P2P mesh limits. O(n²) links; SV exchange is O(n) per new peer; gossip/anti-entropy could reduce fan-out (cross-link Gossip #72, Anti-Entropy #99) — deferred. P2P is for small cohorts (≤32).
  • GC pressure. GC scan O(tombstones), run incrementally to bound pause; frequency trades CPU vs memory. A doc with high churn + a lagging site is the worst case (growing tombstones, no GC) → alarm + eviction.
  • Storage growth. Per-doc snapshot + oplog tail; 1k docs × 1 MB + tails ≤ 4 GB RSS (§4) with truncation. Cold docs paged out / snapshot-only.
  • Metadata scaling. VV width = #sites (GC-bounded); PosId path length = O(log n) (LSEQ) to O(n) (Logoot adversarial) — the dense-id scaling hazard, why LSEQ + compaction matter. RGA id is fixed 12 B regardless of n.
  • Coordination overhead. OT needs a single relay per doc (ADR-02) → that relay is the coordination point + scaling unit (shard by doc). CRDT needs no coordination for convergence → scales to disconnected/offline trivially; the only coordination is GC frontier acks (cheap, periodic). This contrast is a headline matrix verdict.

Mental Models & First Principles

# Insight Prediction Bug Class Without It Resolving §
MM1 Transform is a commutativity repair. OT transform(a,b) produces (a',b') so that compose(a,b') = compose(b,a') — it restores the commutativity that raw positional ops lack. Without this mental model, engineers write fast paths that skip transform and produce silent divergence. Any 2-way concurrent edit through a correct transform will converge, regardless of arrival order. Positional shortcut that skips transform for "nearby" ops → divergence on 3-character documents; takes days to find. §8.1, §7 INV-4, Phase P2
MM2 A CRDT element's id IS its position. In RGA, the id (site,seq) never changes and the document order is derived from the id set + the integration rule — not from a position index. Thinking in terms of positions causes you to mutate ids or re-number on delete. Adding a character never invalidates another character's id. Deletes are tombstones, not removals. The id set is append-only. Trying to "re-index" CRDT elements after a delete → ids collide → divergence. Storing cursors as integer positions in a CRDT → cursors jump on concurrent edits. §8.2, §7 INV-3, Phase P5
MM3 Causal delivery is a prerequisite, not an optimisation. For op-based CRDTs, delivering an insert before its anchor is present is not a performance loss — it is a correctness violation (dangling anchor → undefined integration order). The holdback buffer is mandatory, not optional. An op-based CRDT system without causal delivery will appear to work in most tests (TCP is FIFO) and fail mysteriously on multi-path P2P or after partition heals. Removing the causal-delivery buffer to "simplify" → occasional phantom text on reconnect; only reproducible under specific concurrent partition patterns. §7 INV-2, Phase P4, Phase P5.6
MM4 The Jupiter single-order trick. By giving every OT op a single total-order (server sequence), Jupiter ensures that every client transforms its pending buffer against the same history prefix — so TP1 suffices and TP2 is never needed. TP2's complexity arises only when the same op can be transformed against different sequences in different clients. Any OT system with a trusted server-relay that assigns sequence numbers needs only TP1 to be correct. Attempting peer-mesh OT with only a TP1 transform → divergence on any 3-way concurrent edit. This is the historical bug of early OT (Ellis & Gibbs 1989 dOPT bug class). §8.1, §6 P4, Phase P3, Comparative Architecture Table
MM5 Tombstones are the price of correctness. Every deleted CRDT element must persist until provably unreachable (below the causal-stability frontier). Engineers who GC tombstones by time or reference-count instead of by frontier cause tombstone resurrection — deleted text reappears after a delayed delivery. The frontier is the only safe GC boundary. The memory overhead of a CRDT grows with the total edit history, not just the current document size, until GC runs. Early GC of a tombstone: a concurrent insert anchored on that id arrives later → anchor missing → either a panic or a doc-level divergence. The bug is silent until a delayed delivery. §7 INV-9/INV-13, Phase P11, Back-of-Envelope Capacity Model
MM6 Dense position ids grow monotonically under adversarial insertion. A Logoot PosId between two adjacent ids with a free digit gap of 1 at every depth must append a new level — so monotone append at one end grows path length O(n). LSEQ's adaptive strategy randomises the "direction" per depth to maintain O(log n) average. Knowing this predicts where memory explodes in production (append-only logs, chat systems). Sequential typing near one end of a Logoot document will cause id-path lengths to balloon, visible as pos_path_len histogram drift. LSEQ will not exhibit this pattern under uniform typing. Choosing Logoot (not LSEQ) for a chat/log system → ids balloon to 200 B/char → 10× memory overhead vs expected → OOM on large documents. §8.2, §4 metadata constraint, Phase P6.6, Back-of-Envelope Capacity Model
MM7 State-vector exchange is a set-difference query. When peer A sends SV1{vv_A} to B, B computes `ops_B_lacks_from_A = {op ∈ B.log op.dot ∉ vv_A}` and sends them. It is not a version-number comparison — it is a set-theoretic VV difference. This generalises to any number of sites without a global sequence. Given vv_A and vv_B, you can compute which ops each peer lacks in O(#sites + #missing) without transmitting the full state. Using a single global sequence number instead of per-site VVs → correct only with a single server; breaks in P2P where no global counter exists.
MM8 The interleaving anomaly is a consequence of per-character anchoring. RGA's "concurrent inserts after the same anchor are interleaved by id" is correct (it converges!) but produces "HWEOLRLLOD" from "HELLO" + "WORLD" typed concurrently. YATA/Fugue fix this by using an origin-based rule that groups a run of insertions together. The tradeoff is a slightly larger id or more complex comparator. Any CRDT that resolves concurrent inserts purely by a global id comparison (without run-origin tracking) will interleave concurrent typing runs. Deploying RGA in a collaborative document editor where users type long runs simultaneously → garbled text on convergence; users see it as "bug" even though the document is technically converged. Phase P5.6, Comparative Architecture Table, §2 concept inventory
MM9 Awareness is not persistence. Presence (cursors, selections) is ephemeral: it is not used for convergence, does not affect text(), and must not be persisted. Persisting presence causes ghost cursors after restart; using presence for ordering causes divergence. The correct model: presence is best-effort, TTL-evicted, and entirely separate from the consistency plane. A system that loses awareness state on restart or under partition still converges. Missing presence is only a UX degradation. Persisting presence to the oplog → ghost cursors after restart → user confusion; using presence timestamps for causal ordering → non-deterministic merge (INV-11). Phase P8, §3 Awareness box, §7 INV-12

Yjs/YATA (CRDT). Chose origin-based conflict resolution to eliminate the interleaving anomaly that RGA admits. Every insert carries the id of the item to its immediate left at insertion time; concurrent inserts with different origins interleave at origin boundaries, not character boundaries. The cost is a slightly heavier integration comparator. Wins when interleaving-free convergence under concurrent typing is a hard UX requirement and the 32 B/char overhead is acceptable.

Automerge (CRDT, JSON). Generalised from text sequences to arbitrary JSON documents. The core insight: track every operation as an immutable fact in a columnar oplog; the "document" is a query over the oplog. This makes merge trivial (union of facts) but changes the storage model fundamentally. Wins for applications that need collaborative editing of structured data (forms, code ASTs, databases) where Automerge's JSON CRDT covers the whole domain rather than just text.

Firepad/ShareDB (OT). The open-source Jupiter-alike most teams reach for first: an Express server, a Firebase/MongoDB adapter, and ot.js text operations. Wins for teams that already have a Node.js backend and want a working collaborative text editor in days rather than months. The cost: no CRDT path, no P2P, and the system's correctness depends entirely on ot.js's transform (which has known edge cases documented in its issue tracker).

Alternative Architectures (Roads Not Taken)

Alt-1: Pure Peer-Mesh OT with a TP2-Satisfying Transform

Site A ──────────────────────────── Site B
   │  transform(a, b→c→...) = a''       │
   │  transform(b, a→c→...) = b''       │
   │◄──────────── op mesh ──────────────►│
         (no server; every peer
          transforms against every
          other peer's history prefix)

Regime where this wins: Fully decentralised deployments where a trusted server is unavailable (mobile mesh networks, offline-first native apps) and the team has the expertise to implement and verify a TP2-correct transform function.

Real system: adOPTed (Ressel et al. 1996) and GOTO (Sun & Ellis 1998) attempted this. Google Wave also explored multi-path OT before settling on a server-relay.

Why rejected: TP2 is notoriously hard to satisfy correctly — Ressel (1996) formalised it but did not produce a general correct implementation for text; Sun & Ellis (1998) identified correctness bugs in prior systems. No widely-deployed open-source TP2 text transform is verified correct. The system would inherit the known TP2 failure modes without the ability to certify correctness. Jupiter's single-server insight is specifically the choice to trade P2P capability for a provably-correct simpler transform.

Alt-2: State-Based CvRDT (No Causal Delivery Required)

Site A                        Site B
│ full_state_A ───────────────► merge(full_state_A, state_B)
│                               = new state B
│ ◄─────────────────────────── full_state_B
│ merge(full_state_B, state_A)
│ = identical to B's result

Regime where this wins: Extremely lossy/unreliable networks where causal-delivery guarantees are impractical; batch-sync scenarios (daily sync of disconnected devices); when the implementation simplicity of "just exchange full state and take the join" outweighs the bandwidth cost.

Real system: CvRDT formalism from Shapiro et al. (2011); used in some Dynamo-inspired KV stores for simple register/set CRDTs. Not mainstream for text because full-state exchange is O(document) per sync.

Why rejected: Full-state exchange is O(document size) per sync event, not O(delta). For a 10 MB document at 10 sync events/second (even just heartbeats), this is 100 MB/s per connection — prohibitive. The delta-CRDT / op-based model achieves O(missing ops) per sync, which is orders of magnitude smaller. The state-based fallback is retained only for initial sync and repair (ADR-05), not the hot path.

Alt-3: Centralised Last-Write-Wins (LWW) with Operational Log

Client A ──► Server (applies ops in receipt order, LWW on conflict) ──► Client B
             │ op_A at t=100 wins over op_B at t=99
             │ (wall-clock or Lamport decides winner)

Regime where this wins: Applications where convergence under true concurrency is rare (one primary editor, others view-only or rarely edit simultaneously); where the acceptable failure mode is "one user's edit is silently dropped" rather than "the edit is transformed to preserve intention"; configuration files, form fields, low-concurrency documents.

Real system: Firebase Realtime Database (transaction + LWW for document fields); Notion's early real-time collaboration (reportedly LWW per block); most naive "collaborative" tools that drop data silently.

Why rejected: LWW does not preserve intention — a user's edit is silently dropped when it loses the clock race, which is indistinguishable from a network failure. For a text editor, this means typed characters vanish without notice. The entire educational mission of this system is to demonstrate approaches that never lose an acknowledged edit (INV-5). LWW is the degenerate baseline that the OT-vs-CRDT comparison is measured against.

Alt-4: Operational Transformation over a Conflict-Free Replicated Log (Hybrid)

Sites ──► Shared Replicated Log (Raft/Paxos) ──► each site applies log in order
                │  (total order provided by consensus)
                │  (OT transform still needed if sites buffer local edits before log commit)

Regime where this wins: Systems where consensus/Raft is already deployed for other reasons (multi-leader databases, distributed transaction coordinators), the replication group is small (3–5 nodes), and the latency of Raft commit (5–50 ms) is acceptable for collaboration.

Real system: Apache BookKeeper / Ditto (hybrid CRDT + Raft log). Some internal Google Docs infrastructure reportedly runs variants of this pattern for document-level consensus.

Why rejected: Consensus adds a hard latency floor of ~2 RTTs per committed operation (Raft leader round-trip). For a real-time collaborative text editor targeting p50 ≤ 5 µs local apply latency (§4), consensus on the critical path is incompatible — local edits must apply immediately and propagate asynchronously. The Jupiter relay achieves total order without consensus by accepting that the relay is a single-writer (SPOF) rather than a quorum. This is the explicit trade-off (ADR-02): correctness + low latency via single-writer vs correctness + high availability via consensus.

Glossary

Term Definition (implementation-relevant)
OT (Operational Transformation) Convergence by rewriting ops against concurrent ops via transform; positions, not ids.
IT (Inclusion Transform) Transform op a to include concurrent b's effect; the forward transform.
ET (Exclusion Transform) Transform op a to exclude an already-included effect; used to relocate ops (selective undo).
TP1 Transformation Property 1: compose(a, transform(b,a)) ≡ compose(b, transform(a,b)); required by all OT; our INV-4.
TP2 Transformation Property 2: transforms commute over a third op; needed only for peer-mesh OT; avoided here via a single server order (Jupiter).
Jupiter Nichols 1995 server-relay OT control: one total order, clients rebase against it → only TP1 needed.
CP1/CP2 Convergence/causality-preservation properties of OT control algorithms (Sun & Ellis).
Intention preservation The effect a user intended is preserved despite concurrent edits (OT goal beyond mere convergence).
CRDT Conflict-free Replicated Data Type: convergence by algebraic structure (commutative/associative/idempotent merge), no transform.
CvRDT (state-based) CRDT that merges full states via a join (least-upper-bound); causal-delivery-free, heavier.
CmRDT (op-based) CRDT that ships ops; requires causal delivery; lighter. Our default.
Delta-CRDT Ships small deltas instead of full state; middle ground between op- and state-based.
RGA Replicated Growable Array: per-char element with id (site,seq), inserted after an anchor; concurrent inserts ordered by id.
Logoot Sequence CRDT with dense fractional position identifiers; random allocation between neighbours.
LSEQ Logoot variant with per-depth adaptive allocation (boundary±) bounding average id-path growth.
Treedoc / WOOT / YATA Other sequence CRDTs (Treedoc=binary-tree ids; WOOT=tombstone ordering; YATA=Yjs origin-based, avoids interleaving). Cited; only RGA + Logoot/LSEQ built.
Fugue CRDT (Kleppmann 2022) avoiding the interleaving anomaly via maximal-non-interleaving ordering.
Peritext Rich-text CRDT (Litt 2021): marks as objects with boundary-anchored ranges; intention-preserving formatting.
Tombstone A deleted element retained (flag set) for ordering/anchoring until provably collectable.
Interleaving anomaly Concurrent runs of insertions interleaving char-by-char (e.g. HWEOLRLLOD); some CRDTs admit it, others (YATA/Fugue) don't.
Position identifier A dense, totally-ordered, immutable id locating a char in the sequence (Logoot/LSEQ).
Element id A causal id (site,seq) identifying a CRDT element (RGA).
SEC Strong Eventual Consistency: replicas with the same delivered ops have identical state; holds iff merge is commutative+associative+idempotent under causal delivery.
Causal delivery Deliver an op only after all ops in its causal past; enforced by the holdback buffer.
Happens-before (→) Lamport's partial order; a→b if a causally precedes b; else concurrent.
Lamport clock Scalar logical clock; (clock, site) gives a total order consistent with →.
Vector clock Per-site counter vector; detects concurrency (incomparable vectors).
Version vector (VV) Per-site max-seq-seen; summarizes a replica's causal history; drives delivery, SV exchange, GC frontier.
Dotted version vector (DVV) A dot + VV; tracks concurrent siblings precisely (Preguiça).
Causal-stability frontier Component-wise min over all reachable VVs; everything below is universally applied → safe to GC.
Anti-entropy Background reconciliation of replica states (state-based merge / SV exchange) to repair divergence.
State-vector exchange Two-step (SV1/SV2) protocol: peers exchange VVs + the ops the other lacks (Yjs-style).
Awareness / presence Ephemeral, non-persisted per-site cursor/selection/identity state; best-effort, TTL-evicted.
Rope Balanced-tree text buffer giving O(log n) splice; the materialized document store.
Oplog Append-only log of (server-ordered) ops; replayed on restart; truncated to snapshots.
Snapshot Materialized state at a point; with the frontier, enables oplog truncation + tombstone GC.
Backpressure Bounded queues slowing producers when consumers lag; prevents drop/OOM.
DST Deterministic Simulation Testing: single-threaded seeded model of sites + network; reproducible convergence testing.
Convergence oracle The check that all replicas' text() are byte-identical at quiescence (INV-1).
Quiescence A state with no in-flight messages and empty holdback buffers; the point at which convergence is asserted.

Verdict summary (the calibration payoff). Choose OT when a trusted central server already exists, metadata/memory must stay near-zero, and faithful intention-preserving undo matters — accepting transform-correctness complexity and a coordination SPOF. Choose a CRDT when offline-first / P2P / no-trusted-server is required and per-char metadata + GC cost are acceptable — RGA for compact fixed-size ids (watch interleaving), Logoot/LSEQ for anchor-free dense ids (watch path growth; prefer LSEQ), or a Fugue/YATA-style engine when interleaving must be eliminated.
