Mental Models & First Principles

# Insight Prediction Bug Class Without It Resolving §
MM1 Transform is a commutativity repair. OT transform(a,b) produces (a',b') so that compose(a,b') = compose(b,a') — it restores the commutativity that raw positional ops lack. Without this mental model, engineers write fast paths that skip transform and produce silent divergence. Any 2-way concurrent edit through a correct transform will converge, regardless of arrival order. Positional shortcut that skips transform for "nearby" ops → divergence on 3-character documents; takes days to find. §8.1, §7 INV-4, Phase P2
MM2 A CRDT element's id IS its position. In RGA, the id (site,seq) never changes and the document order is derived from the id set + the integration rule — not from a position index. Thinking in terms of positions causes you to mutate ids or re-number on delete. Adding a character never invalidates another character's id. Deletes are tombstones, not removals. The id set is append-only. Trying to "re-index" CRDT elements after a delete → ids collide → divergence. Storing cursors as integer positions in a CRDT → cursors jump on concurrent edits. §8.2, §7 INV-3, Phase P5
MM3 Causal delivery is a prerequisite, not an optimisation. For op-based CRDTs, delivering an insert before its anchor is present is not a performance loss — it is a correctness violation (dangling anchor → undefined integration order). The holdback buffer is mandatory, not optional. An op-based CRDT system without causal delivery will appear to work in most tests (TCP is FIFO) and fail mysteriously on multi-path P2P or after partition heals. Removing the causal-delivery buffer to "simplify" → occasional phantom text on reconnect; only reproducible under specific concurrent partition patterns. §7 INV-2, Phase P4, Phase P5.6
MM4 The Jupiter single-order trick. By giving every OT op a single total-order (server sequence), Jupiter ensures that every client transforms its pending buffer against the same history prefix — so TP1 suffices and TP2 is never needed. TP2's complexity arises only when the same op can be transformed against different sequences in different clients. Any OT system with a trusted server-relay that assigns sequence numbers needs only TP1 to be correct. Attempting peer-mesh OT with only a TP1 transform → divergence on any 3-way concurrent edit. This is the historical bug of early OT (Ellis & Gibbs 1989 dOPT bug class). §8.1, §6 P4, Phase P3, Comparative Architecture Table
MM5 Tombstones are the price of correctness. Every deleted CRDT element must persist until provably unreachable (below the causal-stability frontier). Engineers who GC tombstones by time or reference-count instead of by frontier cause tombstone resurrection — deleted text reappears after a delayed delivery. The frontier is the only safe GC boundary. The memory overhead of a CRDT grows with the total edit history, not just the current document size, until GC runs. Early GC of a tombstone: a concurrent insert anchored on that id arrives later → anchor missing → either a panic or a doc-level divergence. The bug is silent until a delayed delivery. §7 INV-9/INV-13, Phase P11, Back-of-Envelope Capacity Model
MM6 Dense position ids grow monotonically under adversarial insertion. A Logoot PosId between two adjacent ids with a free digit gap of 1 at every depth must append a new level — so monotone append at one end grows path length O(n). LSEQ's adaptive strategy randomises the "direction" per depth to maintain O(log n) average. Knowing this predicts where memory explodes in production (append-only logs, chat systems). Sequential typing near one end of a Logoot document will cause id-path lengths to balloon, visible as pos_path_len histogram drift. LSEQ will not exhibit this pattern under uniform typing. Choosing Logoot (not LSEQ) for a chat/log system → ids balloon to 200 B/char → 10× memory overhead vs expected → OOM on large documents. §8.2, §4 metadata constraint, Phase P6.6, Back-of-Envelope Capacity Model
MM7 State-vector exchange is a set-difference query. When peer A sends SV1{vv_A} to B, B computes `ops_B_lacks_from_A = {op ∈ B.log op.dot ∉ vv_A}` and sends them. It is not a version-number comparison — it is a set-theoretic VV difference. This generalises to any number of sites without a global sequence. Given vv_A and vv_B, you can compute which ops each peer lacks in O(#sites + #missing) without transmitting the full state. Using a single global sequence number instead of per-site VVs → correct only with a single server; breaks in P2P where no global counter exists.
MM8 The interleaving anomaly is a consequence of per-character anchoring. RGA's "concurrent inserts after the same anchor are interleaved by id" is correct (it converges!) but produces "HWEOLRLLOD" from "HELLO" + "WORLD" typed concurrently. YATA/Fugue fix this by using an origin-based rule that groups a run of insertions together. The tradeoff is a slightly larger id or more complex comparator. Any CRDT that resolves concurrent inserts purely by a global id comparison (without run-origin tracking) will interleave concurrent typing runs. Deploying RGA in a collaborative document editor where users type long runs simultaneously → garbled text on convergence; users see it as "bug" even though the document is technically converged. Phase P5.6, Comparative Architecture Table, §2 concept inventory
MM9 Awareness is not persistence. Presence (cursors, selections) is ephemeral: it is not used for convergence, does not affect text(), and must not be persisted. Persisting presence causes ghost cursors after restart; using presence for ordering causes divergence. The correct model: presence is best-effort, TTL-evicted, and entirely separate from the consistency plane. A system that loses awareness state on restart or under partition still converges. Missing presence is only a UX degradation. Persisting presence to the oplog → ghost cursors after restart → user confusion; using presence timestamps for causal ordering → non-deterministic merge (INV-11). Phase P8, §3 Awareness box, §7 INV-12

Glossary · 40 terms · site-wide glossary

OT (Operational Transformation)
Convergence by rewriting ops against concurrent ops via transform; positions, not ids.
IT (Inclusion Transform)
Transform op a to include concurrent b's effect; the forward transform.
ET (Exclusion Transform)
Transform op a to exclude an already-included effect; used to relocate ops (selective undo).
TP1
Transformation Property 1: compose(a, transform(b,a)) ≡ compose(b, transform(a,b)); required by all OT; our INV-4.
TP2
Transformation Property 2: transforms commute over a third op; needed only for peer-mesh OT; avoided here via a single server order (Jupiter).
Jupiter
Nichols 1995 server-relay OT control: one total order, clients rebase against it → only TP1 needed.
CP1/CP2
Convergence/causality-preservation properties of OT control algorithms (Sun & Ellis).
Intention preservation
The effect a user intended is preserved despite concurrent edits (OT goal beyond mere convergence).
CRDT
Conflict-free Replicated Data Type: convergence by algebraic structure (commutative/associative/idempotent merge), no transform.
CvRDT (state-based)
CRDT that merges full states via a join (least-upper-bound); causal-delivery-free, heavier.
CmRDT (op-based)
CRDT that ships ops; requires causal delivery; lighter. Our default.
Delta-CRDT
Ships small deltas instead of full state; middle ground between op- and state-based.
RGA
Replicated Growable Array: per-char element with id (site,seq), inserted after an anchor; concurrent inserts ordered by id.
Logoot
Sequence CRDT with dense fractional position identifiers; random allocation between neighbours.
LSEQ
Logoot variant with per-depth adaptive allocation (boundary±) bounding average id-path growth.
Treedoc / WOOT / YATA
Other sequence CRDTs (Treedoc=binary-tree ids; WOOT=tombstone ordering; YATA=Yjs origin-based, avoids interleaving). Cited; only RGA + Logoot/LSEQ built.
Fugue
CRDT (Kleppmann 2022) avoiding the interleaving anomaly via maximal-non-interleaving ordering.
Peritext
Rich-text CRDT (Litt 2021): marks as objects with boundary-anchored ranges; intention-preserving formatting.
Tombstone
A deleted element retained (flag set) for ordering/anchoring until provably collectable.
Interleaving anomaly
Concurrent runs of insertions interleaving char-by-char (e.g. HWEOLRLLOD); some CRDTs admit it, others (YATA/Fugue) don't.
Position identifier
A dense, totally-ordered, immutable id locating a char in the sequence (Logoot/LSEQ).
Element id
A causal id (site,seq) identifying a CRDT element (RGA).
SEC
Strong Eventual Consistency: replicas with the same delivered ops have identical state; holds iff merge is commutative+associative+idempotent under causal delivery.
Causal delivery
Deliver an op only after all ops in its causal past; enforced by the holdback buffer.
Happens-before (→)
Lamport's partial order; a→b if a causally precedes b; else concurrent.
Lamport clock
Scalar logical clock; (clock, site) gives a total order consistent with →.
Vector clock
Per-site counter vector; detects concurrency (incomparable vectors).
Version vector (VV)
Per-site max-seq-seen; summarizes a replica's causal history; drives delivery, SV exchange, GC frontier.
Dotted version vector (DVV)
A dot + VV; tracks concurrent siblings precisely (Preguiça).
Causal-stability frontier
Component-wise min over all reachable VVs; everything below is universally applied → safe to GC.
Anti-entropy
Background reconciliation of replica states (state-based merge / SV exchange) to repair divergence.
State-vector exchange
Two-step (SV1/SV2) protocol: peers exchange VVs + the ops the other lacks (Yjs-style).
Awareness / presence
Ephemeral, non-persisted per-site cursor/selection/identity state; best-effort, TTL-evicted.
Rope
Balanced-tree text buffer giving O(log n) splice; the materialized document store.
Oplog
Append-only log of (server-ordered) ops; replayed on restart; truncated to snapshots.
Snapshot
Materialized state at a point; with the frontier, enables oplog truncation + tombstone GC.
Backpressure
Bounded queues slowing producers when consumers lag; prevents drop/OOM.
DST
Deterministic Simulation Testing: single-threaded seeded model of sites + network; reproducible convergence testing.
Convergence oracle
The check that all replicas' text() are byte-identical at quiescence (INV-1).
Quiescence
A state with no in-flight messages and empty holdback buffers; the point at which convergence is asserted.
