4. System Constraints

Constraint Target Notes
Max doc size 10 MB / ~10M chars rope keeps splice O(log n); CRDT id arrays scale linearly
Max concurrent sites (server mode) 256 active editors / doc vector-clock width = #sites ever seen (bounded by GC)
Max concurrent sites (P2P) 32 mesh fan-out O(n²); state-vector size grows
Local op apply latency (OT) p50 ≤ 5 µs, p95 ≤ 20 µs, p99 ≤ 80 µs rope splice + revlog append
Local op apply latency (CRDT RGA) p50 ≤ 8 µs, p95 ≤ 40 µs, p99 ≤ 150 µs id alloc + integration walk
Remote integrate (OT, 1 op vs k pending) p95 ≤ 50 µs at k≤64 k transforms
Remote integrate (CRDT RGA, 1 elem) p95 ≤ 30 µs anchor lookup + insert
Sync round-trip (server, LAN) p50 ≤ 2 ms, p95 ≤ 10 ms WebSocket echo + apply
Sync round-trip (server, WAN) p95 ≤ 120 ms RTT-dominated; offline buffer covers gaps
CRDT metadata overhead — RGA ≤ 24 B/char live + ≤ 24 B/tombstone id(12) + ptr/flags(12); pre-GC
CRDT metadata overhead — Logoot/LSEQ 8–200 B/char (path-length dependent) adversarial insert grows path; LSEQ caps avg
OT metadata overhead ~0 B/char steady state oplog truncated to snapshot; no per-char meta
Memory ceiling (server, 1k docs) ≤ 4 GB RSS snapshots + hot oplog tails
Tombstone growth ≤ 2× live chars between GC cycles GC each causal-stability advance or 10k ops
Convergence-time bound (delivered, no partition) ≤ 1 RTT after last op both engines
Convergence after partition heal ≤ #buffered-ops × per-op integrate bounded by oplog/update backlog
Startup (load 1 MB doc) ≤ 50 ms (snapshot replay) snapshot + tail oplog
Shutdown flush pending + fsync snapshot, ≤ 200 ms crash-only: safe to kill anytime
FD budget (server) ≤ 2 per connection ws socket + occasional file
Storage amplification (OT oplog) ≤ 3× doc until snapshot then truncated
Availability (server) single relay; RTO ≤ 5 s (restart+replay) not HA in P0; HA deferred
Availability (P2P/CRDT) 100% local (offline-first) converges on reconnect

Hard correctness constraints (non-negotiable, see §7). Both engines MUST achieve convergence: any two replicas that have applied the same set of operations/elements show byte-identical text. OT MUST satisfy TP1 under the Jupiter total order. CRDT MUST satisfy SEC (commutative+associative+idempotent merge) under causal delivery. No lost updates. Idempotent integrate (duplicate delivery is a no-op).
