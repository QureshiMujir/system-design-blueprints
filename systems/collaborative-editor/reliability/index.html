7. System Invariants

Format per invariant: statement · why · where enforced · detection · telemetry · recovery · debugging.

INV-1 Convergence / SEC. Two replicas with the same delivered op/element set have byte-identical text(). · The product's entire promise. · CRDT: merge join-semilattice; OT: TP1 under total order. · Differential oracle in harness/fuzz hashes text() across replicas each quiescence. · divergence_detected{engine,doc} counter; diverging replica dumps oplog. · Re-sync from authoritative oplog/snapshot; in P2P, re-run state-vector exchange. · Replay both replicas' logs in a single process; binary-search the op where hashes split.

INV-2 Causal delivery (CRDT). An element integrates only after all elements in its causal past are present. · Anchors/preceding ids must exist. · causality holdback buffer gates integrate by version vector. · Holdback non-empty beyond timeout → causal_holdback_stalled. · Missing dep counter; buffer depth gauge. · Request missing range via state-vector exchange. · Inspect holdback buffer + VV gap; identify the unsent dependency.

INV-3 Total order of CRDT ids. The set of element ids has a deterministic total order identical on all sites (RGA: anchor walk + id tie-break; Logoot/LSEQ: dense path order). · Order is document order. · Comparator unit-tested for totality/antisymmetry/transitivity; debug_assert on insert. · id_order_violation (comparator returned inconsistent result). · n/a (programming error) → panic in debug. · Property test the comparator on random id pairs/triples.

INV-4 OT TP1. ∀ concurrent a,b on the same state: compose(a, transform(b,a)) ≡ compose(b, transform(a,b)) (both yield the same document). · The transform's soundness under a 2-way merge. · ot::transform + property tests. · TP1 property test failure in CI. · tp1_violation test counter. · Fix transform; never ship on red. · Shrink the failing op pair (proptest) to a minimal counterexample.

INV-5 No lost updates. Every accepted local op eventually appears (transformed) in every replica's converged state. · Users must not lose typed text. · OT: pending buffer + ack; CRDT: VV gap → resend. · Op present in local log but absent in peer after quiescence → lost_update. · Per-site applied-vs-acked gauge. · Resend from pending buffer / VV diff. · Diff local oplog vs peer state by op id.

INV-6 Idempotent integrate. Integrating an already-seen op/element is a no-op. · At-least-once delivery + reconnect floods. · Seen check via version vector / id set before mutate. · duplicate_integrate_count (expected nonzero, but text unchanged). · n/a. · Assert text hash unchanged on duplicate in tests.

INV-7 Monotonic clocks per site. A site's Lamport/seq counter only increases; (clock,siteId) are unique. · Id uniqueness + happens-before. · causality clock allocator; debug_assert!(new>prev). · clock_regression if a received op has seq ≤ already-seen from that site (out of order → buffer, not regress local). · Per-site max-seq gauge. · n/a / reject. · Trace seq allocation; check persistence reload restores counter.

INV-8 OT revision consistency. Client's view of server revision matches server's order; pending ops are exactly those after acked_rev. · Jupiter correctness. · ot client state machine. · Mismatch between client acked_rev and server-sent base → revision_desync. · pending_buffer_depth, acked_rev gauges. · Full re-sync (server resends from snapshot). · Compare client/server revision logs side by side.

INV-9 Tombstone non-resurrection. A deleted element's tombstone persists until provably unreachable (below frontier); never re-inserted by a late op. · Resurrected text = divergence. · GC gated on causal-stability frontier. · A delete arriving for an id absent from store after GC → tombstone_resurrection_attempt. · Frontier gauge; tombstone count. · Reject the late op (its dependencies are below frontier ⇒ already universally applied). · Check frontier vs the op's VV.

INV-10 Bounded metadata / sizes. Tombstone ratio, id path length, queue depth, doc size stay within §4 ceilings. · Predictable memory. · Size guards + GC triggers. · Ceiling breach → limit_exceeded{kind}. · Gauges per kind. · GC / snapshot / reject. · Inspect which kind breached; tune cadence.

INV-11 Deterministic merge order. No HashMap iteration, wall-clock, or platform float in any ordering/merge path. · Cross-platform convergence. · Code review + a "no-nondeterminism" lint/test (sorted structures only). · Differential test across two builds/arches diverges → nondeterminism present. · n/a. · Diff the two builds' op-application traces.

INV-12 Selection/cursor validity. A transformed cursor index stays within [0, len] and (best-effort) preserves user intent across concurrent edits. · UX correctness; no panics on render. · awareness transform clamps. · Out-of-range index → cursor_clamp warn. · cursor-clamp counter. · Clamp + recompute from anchor (CRDT) . · Reproduce with the concurrent edit that moved it.

INV-13 GC frontier is a bounded, non-resurrecting monotone. The causal-stability frontier (component-wise min over all sites' version vectors) only ever advances, never regresses, and must never be computed above any site's true delivered VV — so it is bounded below by the slowest/most-offline reachable site. · Correctness (INV-9 depends on the frontier never overshooting) and liveness (GC must eventually make progress) are two faces of the same computation. · gc::frontier() recomputes min over all tracked per-site VVs on each GC cycle; an offline site's last-known VV pins the computation until evicted. · An offline/lagging site holds gc_frontier flat while tombstone_ratio climbs → gc_frontier_stalled. · gc_frontier gauge (should trend upward over time, never backward); per-site VV lag gauge. · Operator force-evicts the lagging site per policy, which drops its pinning VV from the min computation and lets the frontier advance. · Inspect per-site VV + last_seen timestamps to identify which site is pinning the frontier; compare successive gc_frontier samples to confirm monotonicity.

Failure Modes & Recovery

Comprehensive taxonomy. Each class: symptoms · root causes · detection · automatic recovery · manual recovery · forensic artifacts · long-term mitigation.

F1 — Divergence (INV-1 breach). Symptoms: two replicas show different text() at quiescence; users see different documents. Root causes: OT transform/rebase bug (broke TP1), CRDT comparator/ordering bug (INV-3), nondeterminism leak (INV-11), lost fsync after crash. Detection: convergence oracle (harness/fuzz) hashes text(); production divergence alarm via periodic cross-replica checksum exchange. Auto recovery: CRDT — re-run state-vector exchange (union of state); OT — client full re-sync from server snapshot+oplog. Manual: dump both oplogs, replay in one process, binary-search the splitting op; freeze as fixture. Forensics: per-replica oplog + VV + op provenance. Long-term: the divergent op class becomes a permanent property/fuzz fixture.

F2 — Dropped op. Symptoms: a user's edit missing on peers (INV-5). Root causes: lost frame, channel shed, missed broadcast. Detection: op in local log absent in peer after quiescence (lost_update). Auto: OT pending buffer re-Submit; CRDT VV-diff resend. Manual: diff local oplog vs peer state by op id. Forensics: pending buffer + VV gap. Long-term: idempotent resend on every reconnect (INV-6).

F3 — Duplicated op. Symptoms: (none, if correct) — duplicated text only if idempotence broken. Root causes: at-least-once delivery + a missing seen-check. Detection: duplicate_integrate_count nonzero with text unchanged (good) vs changed (bug). Auto: VV/id seen-check drops dupes (INV-6). Manual: assert text-hash unchanged on replay of duplicates. Forensics: op ids + VV. Long-term: idempotence property test.

F4 — Reordered delivery. Symptoms: CRDT integrate of an op before its deps. Root causes: multi-peer P2P delivers a later-dep op first. Detection: causal_holdback_depth grows. Auto: holdback buffer orders correctly; cascade releases on dep arrival (INV-2). Manual: inspect holdback + VV gap; re-request missing range. Forensics: holdback contents. Long-term: keep the holdback on every receive path, even over FIFO transports.

F5 — Partition + heal. Symptoms: sides edit independently; on heal a large backlog. Root causes: network split. Detection: connection loss; backlog size on reconnect. Auto: SV exchange (CRDT) / rebase backlog + Submit (OT) converges within backlog bound (§4). Manual: none if within bounds; if backlog huge → throttle catch-up. Forensics: offline buffer + server rev/VV at heal. Long-term: bounded offline buffer (INV-10) + jittered reconnect (reconnect-storm.md).

F6 — Clock anomaly / regression. Symptoms: reused dots → id collision → divergence (INV-7). Root causes: per-site seq not persisted across crash; HLC/wall-clock used in an ordering path (INV-11). Detection: clock_regression; a received op with seq ≤ already-seen from a site. Auto: reject the regressed op. Manual: restore per-site max-seq from snapshot+oplog before accepting edits. Forensics: per-site max_seq history. Long-term: persist counters (P11); ban wall-clock from ordering (lint, INV-11).

F7 — GC too early → tombstone resurrection. Symptoms: a deleted character reappears; divergence (INV-9). Root causes: reclaimed a tombstone above the frontier; frontier mis-computed. Detection: tombstone_resurrection_attempt; a late delete/insert referencing a reclaimed id. Auto: resurrection guard rejects ops whose dot < frontier (already universally applied). Manual: re-sync from a replica that retained the tombstone; audit frontier = strict min over all reachable VVs. Forensics: frontier history + the offending op's VV. Long-term: never reclaim above min (Principle 13); GC unit-tested against the frontier.

F8 — GC stall (frontier pinned). Symptoms: unbounded tombstone/memory growth; GC never advances. Root causes: an offline/lagging site pins min (INV-13). Detection: gc_frontier flat + tombstone_ratio rising. Auto: none (correct behavior — can't GC what a site might need). Manual: identify the lagging site (vv-visualizer), evict per policy (operator), frontier advances. Forensics: per-site VV + last-seen. Long-term: eviction policy + alarm; document in gc-stall.md.

F9 — Oplog / snapshot corruption. Symptoms: reload fails or yields wrong state. Root causes: torn write, disk fault. Detection: per-record checksum mismatch (oplog_checksum_fail). Auto: truncate to last valid prefix (Principle 8); re-sync the rest from peers. Manual: restore from backup snapshot+oplog; restore-test confirms. Forensics: the corrupt record offset + checksum. Long-term: group-commit fsync + redundant snapshots + restore drills.

F10 — OT revision desync. Symptoms: client acked_rev disagrees with server order (INV-8). Root causes: base_rev below a truncated snapshot; >1 op in flight bookkeeping bug. Detection: revision_desync. Auto: server full re-sync (snapshot + tail). Manual: compare client/server revision logs. Forensics: both revision logs + client pending. Long-term: single-op-in-flight discipline + snapshot horizon ≥ slowest client (P3/P11).

F11 — Holdback never drains. Symptoms: CRDT ops stuck, doc stops converging. Root causes: a dep dropped and never re-requested. Detection: causal_holdback_stalled (timeout). Auto: timeout → request-missing-range via SV exchange. Manual: inspect VV gap, force a state-based merge (full union). Forensics: holdback buffer + VV. Long-term: timeout + re-request, never infinite hold (INV-2).

F12 — Backpressure deadlock. Symptoms: system wedges, queues saturated both directions. Root causes: cyclic wait between bounded channels. Detection: multiple queue_depth gauges pinned at max, no progress. Auto: none. Manual: restart the wedged actor (crash-only). Forensics: queue-depth snapshot + task states. Long-term: consistent channel acquire order (Principle 15); avoid cycles by design.
