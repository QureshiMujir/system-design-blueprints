⬜ Phase P1 — OT op model (Insert/Delete/Retain) + apply + compose + invert

Objectives
  • Component { Retain(n) | Insert(s) | Delete(n) } and Op { components, base_len, target_len } (§8.1, §11).
  • apply(doc, op) -> String with strict base_len == doc.char_len precondition.
  • compose(a,b) (a then b, targetLen(a)==baseLen(b)); invert(op, doc) -> op⁻¹.
  • Canonical normalization: merge adjacent same-kind components, drop trailing Retain.
  • Positional convenience: LocalEdit → Op (Insert/Delete bracketed by Retains).
Deliverable

ot crate: op model + apply + compose + invert + normalization, unit-tested with the §8.1 case table.

Acceptance
Law / check Statement
apply precondition base_len(op)==doc.len else BaseLenMismatch
compose assoc apply(d, compose(compose(a,b),c)) == apply(d, compose(a, compose(b,c)))
compose correctness apply(d, compose(a,b)) == apply(apply(d,a), b)
invert apply(apply(d,a), invert(a,d)) == d
length algebra target_len(compose(a,b))==target_len(b); base_len==base_len(a)
normalization idempotent norm(norm(op))==norm(op)
Fixtures
  • conformance/ot/ (new compose/, invert/): (doc, a, b) → compose_result; (doc, op) → inverse, restored.
  • Edge fixtures: empty op (identity), insert-only, delete-only, full-replace.
  • Cross-impl: same fixtures reproduced from ot.js outputs (sanity, not copied code).
Pitfalls
  • Off-by-one in component boundary splits (the classic OT bug). Enumerate all 9 compose cases explicitly; proptest against the apply-equivalence law.
  • invert needs the pre-image doc — inverting against the wrong doc silently wrong; thread doc explicitly, never cache.
  • Forgetting trailing-Retain trim → length asserts fire spuriously.
  • Insert string length measured in code points vs bytes — must match position unit (ADR-27).

⬜ Phase P2 — OT transformation functions (IT/ET) + TP1 property tests

Objectives
  • transform(a,b,prio) -> (a',b') satisfying TP1 (§7 INV-4, §8.1): compose(a,b') ≡ compose(b,a').
  • Inclusion transform IT(a,b) and exclusion transform ET(a,b) (ET needed by selective undo P10).
  • Deterministic tie-break Priority{Left,Right} for concurrent inserts at the same position (INV-11).
  • proptest TP1 harness with shrinking → minimal counterexamples.
Deliverable

transform/IT/ET + a green TP1 proptest (≥10⁵ cases) + symmetry test.

Acceptance
Property Statement
TP1 apply(apply(d,a),b') == apply(apply(d,b),a') ∀ concurrent a,b
Symmetry transform(a,b,L) == swap(transform(b,a,R))
Identity transform(a, identity) == (a, identity)
ET inverse-of-IT ET(IT(a,b), b) ≡ a (relocation round-trip)
Tie determinism same (a,b,prio) → identical (a',b') every run/arch
Fixtures
  • conformance/ot/transform/: (doc, a, b, prio) → (a_prime, b_prime) JSON; include both Left/Right.
  • Adversarial pairs: same-position inserts; nested deletes; insert-inside-delete-range; delete spanning an insert point.
  • TP1 regression corpus: every historical proptest counterexample frozen as a fixture.
Pitfalls
  • TP2 temptation: do NOT attempt peer-mesh transform here; only TP1 is required because P3 uses a single total order (§8.1). Building/testing TP2 wastes effort and likely fails (TP2 is hard — Ressel 1996).
  • Insert-vs-insert ordering must be globally consistent — a non-symmetric tie-break diverges (INV-11).
  • Delete-delete overlap double-counting → characters vanish or survive on one side only.
  • Transforming against an op from a different base state (not concurrent) → silent corruption; enforce "same base" in types/asserts.

⬜ Phase P3 — OT control algorithm (Jupiter / server-relay) + client revisions + selection transform

Objectives
  • Jupiter control (Nichols 1995, §8.1): server imposes one total order; clients rebase against it. This is why only TP1 is needed (no TP2).
  • ServerState{doc, log: RevisionLog, rev}; ClientState{doc, acked_rev, pending: VecDeque<Op>} (§11).
  • Server: transform incoming Submit{base_rev,op} past history[base_rev..] via IT chain; append; broadcast Apply{rev,op',origin}.
  • Client: on Apply(self) ack+pop+send-next; on Apply(remote) rebase past whole pending buffer (update pending in place); single-op-in-flight discipline.
  • transform_cursor(local_cursor, applied_op) keeps presence valid (INV-12).
Deliverable

End-to-end OT over an in-process relay: N clients, concurrent edits converge byte-identically; cursor follows; the §8.5 worked example reproduced as a test.

Acceptance
Check Target
2-client concurrent insert/delete converge to identical text (INV-1)
Worked example §8.5 yields aXc on every client
Ack discipline pending == ops after acked_rev always (INV-8)
Single-in-flight ≤1 unacked Submit per client at any time
Cursor validity transformed index ∈ [0,len] (INV-12)
Lost-update every accepted local op appears post-convergence (INV-5)
Fixtures
  • conformance/ot/jupiter/: interleaving transcripts [(site, edit, at_rev)…] → final_doc + per-client rev.
  • Scenarios: 2 inserts same pos; insert vs delete (overlap); 3-way concurrent (still 1 server order); buffered local edits while awaiting ack; reconnect after missed Applys.
  • Cursor fixtures: edit left/right/inside selection → expected transformed range.
Pitfalls
  • Forgetting to mutate pending in place during remote rebase → next remote rebases against stale pending → divergence. Update each *p = p'.
  • Allowing >1 op in flight without composing → ack/rev bookkeeping desyncs (INV-8).
  • Server applying op (not transformed op') → server doc diverges from clients.
  • Treating a self-Apply as remote (double-apply) → duplicated text. Match on origin.
  • Cursor transform using byte deltas instead of code-point deltas → off-by-bytes.

⬜ Phase P4 — Causality primitives (Lamport, vector clocks, version vectors, DVV, causal delivery)

Objectives
  • Lamport(u64); VectorClock(BTreeMap<SiteId,u64>); VersionVector (= max seq seen/site); DVV{dot, vv} for concurrent siblings (§11).
  • Partial-order ops: happens_before, concurrent, merge (component-wise max), dominates.
  • Causal-delivery buffer (delivery.rs): holdback an op until its causal deps ⊆ delivered set (INV-2).
  • Deterministic tie-break (clock, siteId) for total ordering of concurrent events (INV-11).
  • Foundation for CRDT (P5+) integration gating, sync (P8), and GC frontier (P11).
Deliverable

causality crate: clocks + VV + DVV + a causal-delivery buffer with cascade redelivery, fully property-tested.

Acceptance
Property Statement
Lamport monotonic local clock strictly increases (INV-7)
VC partial order a→b ⇒ VC(a)<VC(b); concurrent ⇒ incomparable
VV merge = lub merge is least upper bound (idempotent, commutative, associative)
Causal delivery no op delivered before all deps (INV-2); buffer drains when deps arrive
Cascade delivering one dep can release a chain of held ops
DVV siblings concurrent writes detected as siblings, not overwrites
Fixtures
  • conformance/ causality: event sequences → happens_before/concurrent truth table.
  • Delivery transcripts: out-of-order arrival [op3, op1, op2] (deps 1<2<3) → delivery order [1,2,3].
  • VV diff fixtures: (vv_a, vv_b) → dots_b_lacks (feeds P8).
  • DVV: concurrent-write fixtures → sibling sets.
Pitfalls
  • Using wall-clock or HLC for ordering where causal correctness is required → false ordering of concurrent ops (INV-11). Lamport/VC only in ordering paths.
  • VV component-wise max bugs (forgetting absent sites = 0) → missed deps.
  • Holdback buffer leak: deps that never arrive pin the buffer forever — needs timeout + re-request, not infinite hold.
  • BTreeMap (not HashMap) for deterministic iteration (INV-11).
  • Counting deps too broadly (whole VV) inflates op size; carry minimal deps only.

⬜ Phase P5 — CRDT sequence engine A: RGA (Replicated Growable Array)

Objectives
  • Primary CRDT (ADR-03): Element{ id: RgaId, value: char, deleted: bool, origin_left: RgaId } (§8.2, §11).
  • integrate(e) with the RGA ordering rule: concurrent inserts after the same anchor ordered by id (newer/higher (seq desc, site) first) so all sites agree (INV-3).
  • Delete = tombstone (deleted=true), value retained for anchoring later inserts (INV-9).
  • Causal delivery gate (P4): integrate only when origin_left present (INV-2).
  • DocumentReplica impl for RGA; SEC laws (commutative/associative/idempotent) property-tested (§8.3, INV-1).
Deliverable

RGA engine behind DocumentReplica; multi-replica in-process convergence (no network yet) on concurrent insert/delete schedules; SEC property tests green.

Acceptance
Check Target
Convergence any 2 replicas, same element set → identical text() (INV-1)
RGA order rule concurrent inserts-after-same-anchor deterministic by id (INV-3)
Commutativity integrate(a);integrate(b) == integrate(b);integrate(a) (text + order)
Idempotence re-integrating any element is a no-op (INV-6)
Associativity any integration order of a fixed set → identical state
Tombstone retention deleted element still anchors later concurrent insert (INV-9)
Worked example §8.5 (RGA) yields aXc
Fixtures
  • conformance/crdt/rga/: element schedules [(id, value, origin_left, op)…] in varying delivery orders → expected text() + order key list.
  • Concurrent-anchor fixtures: 3 sites insert after the same char → canonical id-descending order.
  • Tombstone fixtures: delete then concurrent insert anchored on deleted element → insert survives in correct position.
  • Idempotent-delivery fixtures: duplicated element stream → unchanged text.
Pitfalls
  • Interleaving on RGA: concurrent runs of insertions after the same point interleave char-by-char (the anomaly P12/Fugue addresses); document it, fixture it, defer the fix to engine selection (§6 vs Fugue). Manifestation: "HELLO"+"WORLD" concurrently → "HWEOLRLLOD". Root cause: per-char anchoring + id tie-break. Debug: dump order keys; instrument with interleave_runs counter.
  • Wrong scan direction in the ordering rule → inconsistent order across sites → divergence. Property-test the comparator (INV-3) before integrate.
  • Resolving at→element by live index vs all-elements index (tombstones counted?) — apply_local indexes live chars; integrate works by id. Mixing them mis-anchors. Keep two distinct mappings.
  • Materialized-string cache not invalidated on tombstone set → stale text().
  • Allocating seq non-monotonically after crash reload → id reuse → divergence (INV-7); persist max seq.

⬜ Phase P6 — CRDT sequence engine B: Logoot/LSEQ dense position ids + interleaving handling

Objectives
  • Secondary CRDT (ADR-04): PosId { path: [(digit:u64, site:u32)] }, lexicographic total order; LogootEntry{ pos, value, deleted } (§8.2, §11).
  • alloc(p_left, p_right, site) producing a dense id strictly between neighbours: Logoot (random digit, descend level on exhaustion) and LSEQ (per-level boundary+/boundary− strategy by coin, bounding average path growth).
  • Set-union semilattice: immutable totally-ordered ids ⇒ SEC trivially (§8.3, INV-1) — the comparison foil to RGA's anchor model.
  • Interleaving handling: show LSEQ's interleaving behavior vs RGA; document the YATA/Fugue origin-based fix as the design lever (cross-link Fugue P12 / engine selection).
Deliverable

Logoot + LSEQ engines behind DocumentReplica; convergence on concurrent schedules; an instrumented interleaving comparison vs RGA; id-path-length growth measured under sequential and adversarial typing.

Acceptance
Check Target
Convergence identical id set → identical text() (INV-1)
Id totality PosId Ord total/antisymmetric/transitive (INV-3)
Density alloc always yields left < new < right
Idempotence re-inserting a (pos,value) is a no-op (INV-6)
LSEQ growth avg path length under sequential typing O(log n), not O(n)
Logoot growth adversarial monotone insert grows path linearly (documented foil)
Collision-free distinct sites never collide (site in every digit, §8.6)
Fixtures
  • conformance/crdt/logoot/: (p_left, p_right, site, rng_seed) → alloc'd PosId; deterministic given seed.
  • Order fixtures: random PosId sets → sorted order (totality check).
  • Growth fixtures: sequential N-char typing → recorded path-length series (LSEQ vs Logoot).
  • Interleaving fixtures: two concurrent runs at one boundary → resulting char order (compare RGA vs LSEQ).
Pitfalls
  • Path explosion under monotone insertion (always at one end): Logoot grows path ~linearly → bytes/char balloon (§4 up to 200 B). Manifestation: memory blow-up on "append-only" docs. Root cause: no free interval at shallow levels. Mitigate: LSEQ adaptive strategy; instrument pos_path_len.
  • RNG determinism: alloc uses randomness — must be seeded per-site and reproducible (INV-11) or replay/differential tests diverge. Never use thread RNG in the ordering path.
  • Tombstone vs removal: Logoot can remove (absolute ids) but a removed id can't be a UI cursor anchor afterward — store cursors as resolved indices or nearest live id.
  • Base/level off-by-one in alloc → non-dense ids (can't insert between) → alloc fails to find a slot.
  • LSEQ strategy array must be agreed implicitly (same coin per depth) — but it is per-site; ids stay globally ordered because the digit comparison is global. Confusing per-site strategy with global order → bugs.

  • conformance/sync/: SV-exchange transcripts (vv_a, ops_a, vv_b, ops_b) → post-exchange vv + text.

  • OT Submit racing with a server snapshot truncation → base_rev below snapshot → must trigger full re-sync (P3 desync path), not silently drop.

⬜ Phase P10 — Undo/redo: per-user selective undo under concurrency (both engines)

Objectives
  • Per-user selective undo (undo my last edit, not the globally-last) under concurrency, for both engines (§11 UndoManager).
  • OT: undo = apply invert(op) then transform it past all ops applied since (so it undoes the original intention in the current context) — uses ET/IT (P2).
  • CRDT: undo of an insert = tombstone its element(s); undo of a delete = clear the tombstone (restore) — redo is the inverse. Selective by tracking each local op's element ids.
  • Redo stacks; group consecutive keystrokes into one undo unit; per-user isolation invariant (one user's undo never reverts another's edit).
Deliverable

Working per-user undo/redo in both engines, correct under concurrent remote edits; an undo by user A never reverts user B's text; convergence preserved.

Acceptance
Check Target
Undo restores intent OT: undo after remote edits restores the intended prior state in context
CRDT undo/redo tombstone/restore round-trips; idempotent
Per-user isolation A's undo affects only A's edits (no cross-user revert)
Convergence under undo undo ops converge on all replicas (INV-1)
Redo redo == undo of undo (state round-trip)
Grouping a typed word undoes as one unit
Fixtures
  • conformance/ undo: (initial, [local + remote ops], undo k) → expected text (both engines).
  • Selective fixtures: interleaved A/B edits, A undoes → only A's change reverted.
  • OT relocation fixtures: undo an insert after the surrounding text was concurrently edited → inverse transformed correctly.
  • CRDT restore fixtures: undo a delete → element un-tombstoned; concurrent delete by other → stays deleted (resolution documented).
Pitfalls
  • OT undo without transforming the inverse past intervening ops → undoes the wrong region (the classic selective-undo bug); always relocate via IT chain.
  • CRDT "un-delete" reintroduces resurrection concerns (INV-9): only valid above the frontier; a delete below frontier can't be undone (already universally applied) — surface as a no-op + log.
  • Cross-user revert: undo touching another user's element ids → isolation violation; stacks are strictly per-SiteId.
  • Grouping boundaries wrong → undo reverts too much/little; coalesce by time + word, document the rule.
  • Redo stack not cleared on a new edit → redo applies a stale op into a changed doc → corruption; clear redo on fresh local edit.

⬜ Phase P11 — Persistence: oplog + snapshot + tombstone GC / compaction

Objectives
  • OT persistence (ADR-09): append-only oplog of server-ordered revisions + periodic materialized snapshot + version index; crash-only replay (Principle 8).

  • Tombstone GC (ADR-11, INV-9): compute the causal-stability frontier = component-wise min over all sites' version vectors; reclaim tombstones/oplog/ids strictly below it; never above (resurrection guard).

  • Document load/replay: restart reconstructs identical state (INV-1, INV-7 counters restored).
Deliverable

  • Resurrection fixtures: late delete with dot < frontier → rejected (INV-9).
Pitfalls
  • GC too early (above frontier) → tombstone removed, then a concurrent insert that anchored on it arrives → dangling/resurrection (INV-9, the cardinal GC bug). Never reclaim above the strict min.
  • Frontier stuck at an offline site → no GC, unbounded tombstones (INV-13 tradeoff); needs site eviction policy + operator runbook (gc-stall.md).
  • Not persisting per-site max-seq → post-crash id reuse → divergence (INV-7). Restore counters before accepting new local edits.
  • fsync omitted → lost tail on power-loss → divergence vs peers; batch+fsync with a bounded window.
  • Snapshot taken mid-mutation (torn) → reload corruption; snapshot from a consistent point (between ops, single-owner actor makes this clean).
  • OT oplog truncated below a client's acked_rev while that client is offline → its reconnect base_rev is gone → must full-resync (handled, but must be detected not silently dropped).

⬜ Phase P12 — Comparison harness + convergence simulator (DST) + benchmark matrix (THE DELIVERABLE)

Objectives
  • The project's headline artifact: a fair, reproducible OT-vs-CRDT comparison matrix across all axes — correctness, metadata overhead, latency, memory growth, GC cost, server dependence, complexity, undo semantics, rich-text, anomaly class.
  • Deterministic Simulation Testing (DST): a single-threaded, seed-driven simulator that models N sites, a network (delay/reorder/dup/drop/partition/heal), and drives both engines through identical schedules; the convergence oracle asserts INV-1 at every quiescence.
  • Differential testing: same input → OT vs CRDT (and RGA vs Logoot/LSEQ) must reach the same text (where semantics agree) and any documented divergence (e.g. interleaving) is asserted, not accidental.
  • Workload generators: realistic typing, paste, concurrent hotspots, adversarial monotone-append, partition-heavy.
Deliverable

cargo run -p harness -- matrix produces the OT-vs-CRDT comparison matrix (committed to docs/comparison.md + benchmarks/results/); the DST simulator runs millions of seeded schedules with zero convergence failures; differential OT-vs-CRDT oracle is green.

Pitfalls
  • Unfair harness: tuning one engine's workload/measurement favorably (Principle 14) → invalid conclusions; drive both only via DocumentReplica, identical schedules, identical measurement points.
  • Nondeterministic simulator (thread RNG, wall-clock, HashMap order) → unreproducible failures (INV-11); the DST must be single-threaded + seeded throughout.
  • Quiescence detection wrong (declaring converged while messages in flight) → false pass; oracle must wait for an empty network + empty holdback buffers.
  • Measuring memory with arenas hiding overhead (Principle 7) → dishonest matrix; SizeReport counts every byte.
  • Comparing apples to oranges (OT with server vs CRDT P2P) without noting the server-dependence axis → misleading; the matrix must state OT's server requirement explicitly (ADR-02).
  • Shrinking a divergence by hand instead of automated minimization → slow; wire schedule shrinking into the DST.

⬜ Phase P13 — Conformance suite, fuzzing, hardening & release readiness

Objectives
  • Promote scattered fixtures (P0–P12) into a versioned, engine-neutral conformance suite that any future engine must pass (conformance/). (ADR-17; INV-1/INV-4/INV-6.)
  • Coverage-guided fuzzing (cargo-fuzz, ADR-18): ot_transform_tp1, crdt_converge, schedule_diff, codec_roundtrip.
  • Differential fuzzing: fuzzer-generated concurrent schedules through OT + both CRDTs; convergence oracle (INV-1) as the panic-on-mismatch invariant.
  • Production-hardening: resource ceilings enforced (§4, INV-10), backpressure verified end-to-end (P9), observability complete (Operational Readiness).
  • Extra-engine slots: define the EngineConformance checklist so WOOT/Treedoc/YATA can be added later (PhaseDeferred("Deferred Features Register")) and run the suite immediately — proving the seam (P1) generalises.
  • Release engineering: reproducible builds (ADR-26), SBOM (ADR-24), signing, channels.
Deliverable

Green conformance suite + four fuzz targets in CI; every historical bug frozen as a regression fixture; multi-arch determinism verified; all §4 ceilings enforced; signed reproducible artifacts + SBOM; complete docs; demonstrated extra-engine slot. This phase closes the loop: correct (P0–P11), measured (P12), tested + hardened + shippable (P13).
