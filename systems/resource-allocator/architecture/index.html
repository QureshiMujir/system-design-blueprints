3. Architectural Overview

                       +--------------------------+
   operator/apps  --->  |   API Gateway (stateless) |  authn (mTLS/SPIFFE), rate-limit, audit
                       +------------+-------------+
                                    | gRPC (submit/inspect/drain)
        ============================|=================================  TRUST BOUNDARY
                       +------------v-------------+
                       |  Control Plane Manager   |   (Raft leader = 1 of 3-7)
                       |  +--------------------+  |
     scheduling loop   |  | scheduler-core     |  |---- offers ----> lease-engine
     (single-writer)   |  | queue-manager(DRF) |  |
                       |  | quota-engine       |  |
                       |  | placement scoring  |  |
                       |  +---------+----------+  |
                       |            | apply(mutation)                  CONCURRENCY BOUNDARY
                       |  +---------v----------+  |   (one writer thread per shard)
                       |  | state machine (RAM)|<-+---- replay ----+
                       +------------+-------------+                 |
                                    | propose                      |
        ============================|===============  PERSISTENCE  BOUNDARY
                       +------------v-------------+                 |
                       | metadata-store (Raft)    |---- WAL/snapshot|--> RocksDB (disk)
                       |  quorum of managers      |
                       +------------+-------------+
                                    | heartbeat streams (bounded, credit-flow)
        ============================|=================================  PROTOCOL BOUNDARY
     +------------------------------v-------------------------------------------+
     |                         Worker Agent Fleet (100-10,000)                  |
     | +---------------+  +----------------+  +----------------------+          |
     | | heartbeat/    |  | resource probe |  | runtime-executor     |          |
     | | reconcile     |  | (capacity)     |  | (cgroups v2 + ns)    |          |
     | +-------+-------+  +--------+-------+  +----------+-----------+          |
     |         +------------------ agent state ---------+  -> OCI runtime shim  |
     +--------------------------------------------------------------------------+
  • API Gateway — stateless, horizontally scalable front door. Terminates mTLS, authenticates SPIFFE identities, rate-limits, validates, audits, routes to the current leader. Fails closed; never mutates cluster state directly.
  • Control Plane Manager — the scheduling brain. Hosts scheduler-core, queue-manager, quota-engine, placement scoring. Exactly one manager is Raft leader and runs the single-writer scheduling loop; followers stand by hot. All decisions become mutations proposed to Raft before they take external effect (I7).
  • State machine (RAM) — the deterministic, in-memory projection of the committed WAL: node inventory, leases, queues, quotas, workloads. It is a cache of the log (MM3); rebuilt by replay on restart.
  • metadata-store (Raft) — replicated WAL + periodic snapshots over RocksDB. Provides linearizable commit ordering (I3), quorum durability (I7) and monotonic epochs (I2).
  • Agent fleet — semi-trusted per-node daemons. Probe true capacity, stream heartbeats under bounded credit-flow, supervise executors, and locally reconcile against manager intent. Managers re-validate all agent-reported state.
  • runtime-executor — applies cgroups v2 limits + namespaces and invokes an OCI runtime to launch the workload process, capturing stdout/stderr and exit codes.
  • Data flows. submit → admission (quota-engine) → queue → DRF pick → offer → framework/auto-accept → lease (WAL-committed) → launch RPC → agent executor → running → exit/preempt → reclaim.
  • Trust boundary (double line). Everything above it (operator/apps, gateway) is untrusted input; agents below are semi-trusted and re-validated. Only the manager, gated by Raft, mutates authoritative state.
  • Concurrency boundary. The scheduling loop is single-writer per shard (P5); cross-shard work and agent I/O are message-passed, never shared-memory — this is where race-freedom is enforced.
  • Persistence boundary. Below it, nothing is authoritative until quorum-committed (I7); above it, RAM state is a rebuildable projection (MM3).
  • Protocol boundary. Manager↔agent is bounded, credit-flow gRPC (ADR-21); a slow or flooding agent cannot back-pressure into the scheduler core.
  • Queues/channels. The admission queue, per-agent heartbeat streams, and the event bus are all bounded (P2); overflow is rejection, never unbounded buffering.

8. Domain Model / Protocol / Data Model

8.1 Resource model

Resources are a fixed-arity vector over typed dimensions: cpu_millicores, memory_bytes, disk_bytes, net_bps, gpu_units, ephemeral_ports. All allocation math is vector algebra with per-dimension conservation (I10).

ResourceVector { cpu_mc:u64, mem_b:u64, disk_b:u64, net_bps:u64, gpu:u32, ports:u16 }
NodeCapacity   { total:ResourceVector, allocated:ResourceVector,
                 reserved:ResourceVector, available:ResourceVector,   // available = total-allocated-reserved (I10)
                 overcommit:OvercommitRatio }
DominantShare  = max over dims( tenant_usage[dim] / cluster_total[dim] )   // DRF (I8)

8.2 Workload lifecycle (state machine)

From Event To Guard
SUBMITTED admit ok ADMITTED quota headroom (I4)
SUBMITTED admit deny REJECTED over max-share
ADMITTED enqueue QUEUED queue bounded (P2)
QUEUED DRF pick + feasible PLACED lowest dominant share (I8)
PLACED lease committed LAUNCHING quorum commit (I7)
LAUNCHING agent ack RUNNING RUNNING idempotent (I13)
RUNNING task exit 0 COMPLETED —
RUNNING task exit ≠0 / crash FAILED retry policy
RUNNING preempt PREEMPTED victim fenced (I14)
RUNNING node LOST LOST heartbeat timeout (I5)
any active kill TERMINATING→COMPLETED fence (I11)

Failure terminals: FAILED, LOST, PREEMPTED, REJECTED. Retries re-enter as a new attempt (I13 keys on it).

8.3 Offer protocol (sequence)

Manager -> Framework : RESOURCE_OFFER {offer_id, node_id, vector, epoch, ttl}
Framework -> Manager : ACCEPT_OFFER  {offer_id, workload_id, epoch}     # I6 checks epoch
Manager  (commit lease to WAL, I7) -> Agent : LAUNCH {lease_id, spec, attempt, epoch}
Agent -> Manager : STATUS RUNNING {lease_id, attempt}                    # I13 dedup
Agent -> Manager : STATUS EXITED  {lease_id, code}  -> reclaim (I10)

Un-accepted offers expire at ttl and their capacity returns to available (P8). Auto-mode: the built-in scheduler accepts on the framework's behalf.

8.4 Placement constraints

Affinity / anti-affinity (workload↔workload, workload↔node label), rack awareness, NUMA locality, resource labels, taints/tolerations. Constraints are feasibility filters (hard) or score modifiers (soft); Tetris-style alignment scoring breaks ties toward tight packing (§16).

8.5 Worked example

Cluster of 2 nodes, each <9 cpu, 18 GB>; cluster total <18, 36>. Tenant A tasks <1 cpu, 4 GB> (mem-dominant: 4/36=0.111 > 1/18=0.056). Tenant B tasks <3 cpu, 1 GB> (cpu-dominant: 3/18=0.167 > 1/36=0.028). DRF equalises dominant shares → A gets 3 tasks (<3,12>, dom 0.33), B gets 2 tasks (<6,2>, dom 0.33): the Ghodsi et al. NSDI-2011 canonical example.

Preemption walk-through. Queue Q-batch (guarantee 40% CPU) runs 8 low-priority tasks filling 60% CPU by borrowing idle capacity (I4). Queue Q-svc (guarantee 40%) submits a high-priority gang needing 30% CPU but the cluster is full. Sequence: (1) quota-engine confirms Q-svc is under guarantee and Q-batch is over its guarantee on borrowed capacity; (2) queue-manager selects victims from Q-batch by lowest priority then latest start, choosing the fewest tasks that free ≥ 30% CPU; (3) victims get SIGTERM→grace→SIGKILL (§18); (4) resources are NOT offered to Q-svc until each victim's exit is acked (I14) — premature_reuse_total must stay 0; (5) the freed capacity is committed as a lease for the Q-svc gang atomically (I9). If any victim fails to die within grace, the gang stays QUEUED rather than partially placed.

8.6 Malformed / failure paths

  • Malformed input: an offer ACCEPT whose vector exceeds the offer's vector → rejected by resource-model bounds check, offer_overclaim_total++, offer voided.
  • Failure path: LAUNCH committed (I7) but agent never acks RUNNING within launch-deadline → lease enters LAUNCHING timeout → fence (I11) → reclaim capacity (I10) → workload retried as new attempt (I13).

8.7 WAL record & wire layouts

Every durable mutation is a length-prefixed, checksummed WAL record; every RPC frame is protobuf over HTTP/2. Layouts (bytes, little-endian):

WAL record (metadata-store):
  +0   u32   total_len            # record length excluding this field
  +4   u64   log_index            # strictly increasing (I3)
  +12  u64   epoch                # cluster generation (I2)
  +20  u8    entry_type           # WalEntry discriminant (never renumbered, P14)
  +21  var   payload (protobuf)   # entry body
  +N   u256  blake3               # checksum over bytes [0..N) (I12)

Heartbeat frame (agent -> manager):
  node_id:16B  hlc:{wall_ms:u64, logical:u32}  seq:u64
  capacity_delta:ResourceVector  running_task_ids_delta:[LeaseId]
  suspicion_ack:u8               # echoes detector state for tuning (§13)

Snapshot header:
  magic:u32 "RASN"  sm_version:u32  at_log_index:u64  epoch:u64
  entry_count:u64   blake3:u256    writer_semver:[u8;16]   # §25 downgrade-safety

Records are self-describing and forward-compatible: an unknown entry_type in a mixed-version quorum is gated by feature-epoch (§25) so it is never written before every replica can apply it.

Design principles (§6)

  • P1 — Determinism over convenience. Rule: the scheduler state machine is a pure function of the committed WAL; identical logs replay to identical state. Tradeoff: forbids wall-clock reads and RNG in the apply path (must feed them as log entries). Operational implication: any incident is reproducible by replay. Violation: non-reproducible failovers and un-debuggable fairness drift.
  • P2 — Backpressure at every hop. Rule: every queue, channel and stream is bounded with credit-based flow control (ADR-21). Tradeoff: rejects/throttles under overload instead of buffering. Operational: load is shed at the edge, not amplified in the core. Violation: unbounded memory growth → OOM cascade (FM-9).
  • P3 — The log is the database. Rule: durable truth lives only in the Raft WAL + snapshots; RAM state is a rebuildable cache (MM3). Tradeoff: every externally-visible mutation costs one quorum commit. Operational: RPO 0. Violation: state divergence between managers after failover.
  • P4 — Fence, don't trust liveness. Rule: before reissuing a lease held by a possibly-dead node, fence the old holder by epoch (I11, MM4). Tradeoff: a slow-but-alive node loses its lease. Operational: no double-allocation. Violation: two executors believe they own the same resources (I1 breach).
  • P5 — Single-writer per shard. Rule: each state shard is mutated by exactly one thread; cross-shard work is message-passed (ADR-08). Tradeoff: no shared-memory parallelism inside a shard. Operational: no data-race class of bugs; lock-free reads via epoch snapshots. Violation: torn reads of inventory, phantom capacity.
  • P6 — Isolation before density. Rule: enforce cgroups limits before packing tighter (ADR-17). Tradeoff: lower utilisation than best-effort oversubscription. Operational: one tenant cannot starve another's CPU/mem. Violation: noisy-neighbour SLO breaches.
  • P7 — Quota is admission, not eviction. Rule: reject at submit when a tenant is over max-share; do not admit-then-kill (quota-engine, §18 admission). Tradeoff: bursty tenants see rejections. Operational: predictable cluster headroom. Violation: churn from admit/kill loops (FM-12).
  • P8 — Offers are revocable leases. Rule: an offer is a time-boxed, epoch-stamped claim, not ownership (MM1). Tradeoff: frameworks must accept promptly or lose the offer. Operational: no offer hoarding starves the cluster. Violation: stale offers double-book capacity (I6).
  • P9 — Conserve capacity exactly. Rule: for every node and resource, allocated + reserved + available = total, always (I10). Tradeoff: every mutation must update the vector atomically. Operational: accounting reconciles to zero. Violation: phantom or leaked capacity.
  • P10 — Fairness is progress, not snapshots. Rule: always allocate next to the tenant with the lowest dominant share (I8, DRF). Tradeoff: short-term inefficiency for long-term fairness. Operational: no tenant starves. Violation: dominant-resource monopolisation.
  • P11 — Idempotent side effects. Rule: launch/kill/preempt RPCs carry (workload, attempt, epoch) and are safe to retry (I13). Tradeoff: agents keep a dedup window. Operational: at-least-once RPC is safe. Violation: duplicate task launches after retry.
  • P12 — Observable by construction. Rule: every state transition emits a structured event with request_id/epoch/queue (§20). Tradeoff: telemetry volume. Operational: on-call can localise regressions in one dashboard. Violation: blind failovers.
  • P13 — Explicit failure domains. Rule: manager, agent and executor crash independently and reconcile, never cascade. Tradeoff: more reconciliation code. Operational: blast radius bounded to one domain. Violation: one agent crash stalls the scheduler.
  • P14 — Compatible by version, not by luck. Rule: wire and storage schemas evolve additively; fields are never reused (§25, ADR-05). Tradeoff: deprecated fields linger. Operational: rolling upgrades never break. Violation: mixed-version corruption.
