32. Back-of-Envelope Capacity Model

Each number is derived from the §4 System Constraints table.

  1. Heartbeat ingest rate = nodes ÷ interval = 10,000 ÷ 2 s = 5,000 hb/s. (Drives M3.)
  2. Heartbeat bandwidth = rate × payload. Payload ≈ 4 KB (resource vector + running-task ids). 5,000 × 4 KB = 20 MB/s ≈ 160 Mbps ingest per leader.
  3. Inventory RAM = nodes × per-node record. Record ≈ 8 KB (capacity vectors + labels + state). 10,000 × 8 KB = 80 MB (Phase 3 acceptance).
  4. Lease-table RAM = active leases × record. 500,000 × 256 B = 128 MB.
  5. Workload-state RAM = workloads × record. 500,000 × 2 KB = 1.0 GB. Sum (3)+(4)+(5) ≈ 1.2 GB core state ⇒ 16 GB manager ceiling (§4) leaves headroom for telemetry/indexes (M11).
  6. Snapshot size ≈ core state = 1.2 GB (from 5). At 500 MB/s NVMe (§4), write time = 1.2 GB ÷ 500 MB/s = 2.4 s ⇒ within the ≤ 5 s snapshot budget (M5).
  7. WAL write rate = peak placements × entry size. 5,000 tasks/s (M12) × 512 B = 2.5 MB/s; with Raft quorum ×3 replication = 7.5 MB/s cluster WAL traffic — trivial for NVMe, so M4 is fsync-latency-bound, not bandwidth-bound.
  8. Recovery time = snapshot load + tail replay. Tail = ingest × snapshot-interval. At 5,000 entries/s over a 60 s snapshot interval = 300,000 entries; replay at ~200k entries/s = 1.5 s; + snapshot load 2.4 s (6) = ~4 s ⇒ far under RTO 300 s and even the 30 s target (M6/M8).
  9. Scoring ops per cycle = queued × candidates-per-workload. With feasibility pre-filter to ~100 candidates: 500,000 × 100 = 5 × 10⁷ scoring ops/cycle. At ~50 M ops/s/core that is ~1 s/core ⇒ shard across ~4 cores to hit the ≤ 500 ms recompute (M7).
  10. FD budget = agent connections + client streams. 10,000 agents (HTTP/2 multiplexed, 1 conn each) + ~10,000 operator/client streams = ~20,000 FDs ⇒ well under the 200,000 budget (§4), leaving room for ephemeral connections.
  11. Availability budget = (1 − 0.9995) × 30 days = 21.9 min/month downtime. With ~4 s failovers (8), that permits ~300 unplanned failovers/month before the budget is spent — the error-budget lever for release gating (§24).
  12. Telemetry egress = placement rate × span size. 5,000 placements/s (M12) × ~1 KB/span = 5 MB/s trace data; at 10% head-sampling + full tail-sampling that is ~0.6 MB/s steady per manager — small vs. the 160 Mbps heartbeat ingest (2), so telemetry is not a bandwidth constraint but a cardinality one (§20 pitfall).
