34. Alternative Architectures (Roads Not Taken)

A. Shared-state optimistic scheduling (Omega model).

[ Scheduler 1 ]-\                       /-> conflict?
[ Scheduler 2 ]--> shared cell state <--   retry on stale
[ Scheduler N ]-/    (versioned)         \-> commit if unchanged

Multiple schedulers read a shared, versioned cell state and optimistically commit placements, retrying on conflict. Wins at extreme scale/heterogeneity where a single scheduling loop is the bottleneck (the §32 #9 scoring wall). Embodied by Omega (Schwarzkopf et al. 2013, §5). Rejected here (ADR-23) because conflict-retry storms under high contention hurt tail latency (M1) and the added complexity isn't justified below the 10k-node ceiling; revisit if that ceiling is hit (§29).

B. Monolithic scheduler (Kubernetes/Borg model).

[ submit ] -> [ single scheduler: filter -> score -> bind ] -> [ etcd ]

One central scheduler makes every decision against a global view. Wins when global-optimal packing and simple reasoning matter more than framework autonomy, and one operator owns all workloads. Embodied by the Kubernetes scheduler and Borg (§5). Rejected here because it couples all frameworks to one scheduling policy and one throughput ceiling; the offer model (ADR-23) preserves per-framework autonomy — though we borrow its filter/score plugin structure (§16).

C. Gossip-based decentralized allocation (no central log).

[ agent ]<->[ agent ]<->[ agent ]   (peer gossip of capacity; local claims)

Agents gossip capacity and place work peer-to-peer with no central WAL. Wins for very large, loosely-consistent, best-effort clusters where eventual consistency and partition tolerance beat strict correctness. Embodied by Sparrow (Ousterhout et al. 2013, §5), which uses batch sampling of a few nodes per decision. Rejected here because it cannot provide the no-double-allocation invariant (I1) or RPO 0 (§4) — our defining property (§4) requires a linearizable log (P3).

D. Batch/gang-exclusive HPC scheduling (Slurm model).

[ job queue ] -> [ backfill scheduler ] -> whole-node/whole-core allocation
                          |                (exclusive, gang, wall-time limits)
                          +-> reservation + fair-share tree

Jobs request whole nodes/cores for a bounded wall-clock time; a backfill scheduler packs shorter jobs into reservation gaps. Wins for HPC/MPI workloads needing exclusive, tightly-coupled gangs and predictable wall-time (tightly-coupled scientific computing). Embodied by Slurm. Rejected here because whole-node exclusivity wastes capacity for the fine-grained, long-running, elastic services this allocator targets (ADR-27 chose millicore granularity); the gang and reservation primitives (§19, I9) are borrowed, the exclusivity model is not.
