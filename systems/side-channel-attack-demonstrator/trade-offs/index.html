ADR-01

Primary language

Chosen

Rust

Rejected

C++, Go

When the rejected choice is right

C++ wins when a team already has a mature cycle-accurate simulator codebase and no bandwidth to port it (e.g. extending gem5 itself)

Why: deterministic ownership, no GC pause on the probe hot path, FFI to perf_event_open

Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — eBPF/BPF-Based Instrumentation

+-------------------+     +----------------------+     +------------------+
|  Attacker Logic   | --> |  eBPF probe program   | --> |  Ring buffer map |
|  (userspace)       |     |  (kernel, verified)   |     |  (kernel->user)  |
+-------------------+     +----------------------+     +------------------+

Regime where it wins: broad, low-overhead, system-wide continuous production profiling without per-experiment PMU FD lifecycle management. Real system embodying it: bpftrace/BCC. Rejected because: the eBPF verifier's timestamp resolution and program-size constraints are too coarse for sub-microsecond cache-timing classification (§4 M1/M2 targets), and per-probe verifier overhead is unpredictable relative to the direct rdtsc/perf_event_open path (ADR-11).

Alt B — Full Microarchitectural Simulation

+------------------+     +--------------------+     +-------------------+
|  Workload Binary | --> |  gem5 timing model  | --> |  Simulated trace  |
+------------------+     +--------------------+     +-------------------+

Regime where it wins: modeling a not-yet-fabricated microarchitecture with perfect observability and reproducibility. Real system embodying it: gem5. Rejected because: simulated timing diverges from silicon by construction; this platform's pedagogical value depends on measuring real hardware leakage (§2), not modeled leakage — used only as a comparative reference in §31, never embedded.

Alt C — Ptrace-Based Deterministic Single-Stepping

+-------------------+     +-------------------+     +--------------------+
|  Traced Process    | <->|  ptrace supervisor | -->|  Logical-clock log |
+-------------------+     +-------------------+     +--------------------+

Regime where it wins: deterministic bug reproduction where exact wall/cycle timing does not matter. Real system embodying it: rr (Mozilla rr-debugger). Rejected because: rr virtualizes away real timing into a logical clock to achieve determinism, which destroys the very timing signal this platform exists to measure (§14 objective).

Alt D — Centralized Streaming Telemetry Broker

+-------------------+     +-------------------+     +--------------------+
|  Experiment Host   | -->|  Network broker    | -->|  Aggregation store |
+-------------------+     +-------------------+     +--------------------+

Regime where it wins: fleet-wide, multi-host telemetry aggregation at scale. Real system embodying it: an OpenTelemetry Collector / Jaeger-style distributed tracing backend. Rejected because: the added network hop and serialization latency would contaminate the sub-microsecond probe-adjacent telemetry path; the local mmap append-only store (ADR-04) keeps the write path off the network entirely — this is why distributed telemetry aggregation is registered as deferred (§35, anchor §21) rather than designed in from the start.
