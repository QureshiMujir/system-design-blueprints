30. Mental Models & First Principles

  • MM1 — Signal vs. Scheduler Noise. Any latency bimodality is scheduler-caused until proven otherwise. Predicts: bimodal histograms without affinity-drift telemetry are false leaks, not real signal. Bug class without it: chasing a phantom "leak" that is actually CPU migration. Applies in §17.
  • MM2 — Determinism Is a Product Feature, Not a Nice-to-Have. Without byte-identical replay, every statistic is unfalsifiable. Predicts: any shortcut reading wall-clock/PRNG outside the seed eventually breaks a regression fixture. Bug class: irreproducible CI flakiness blamed on "the CPU." Applies in §14.
  • MM3 — The Trust Boundary Is a Process Boundary. Shared address space always eventually leaks more than the channel under study. Predicts: any optimization merging victim/attacker into one process reintroduces the side channel as noise. Bug class: attacker inadvertently reading victim state directly instead of through the timing channel. Applies in §16.
  • MM4 — A Mitigation Without a Baseline Is Not a Result. "Signal reduced" requires the same manifest run twice, once per mode. Predicts: any single-mode measurement claiming mitigation efficacy is unfalsifiable. Bug class: publishing a report with no vulnerable-twin comparison. Applies in §21.
  • MM5 — Compilers Are Adversarial Collaborators. An optimizing compiler removes exactly the behavior a demonstrator depends on if it can prove that behavior dead. Predicts: a flat "vulnerable" distribution is a compiler bug hunt, not a hardware finding. Bug class: mistaking compiler-mitigated code for successfully demonstrated leakage. Applies in §16.
  • MM6 — Every Number Needs a Confidence Interval or It Is an Adjective. "Leakage detected" without a CI is indistinguishable from noise. Predicts: any report section lacking a Welch's-t-test p-value will eventually be cited incorrectly. Bug class: false-positive leakage claims propagating into a published report. Applies in §19.
  • MM7 — Hardware State Is Global, Software State Is Not. PMU counters, branch history, and cache sets are shared across every process on a core/socket; isolation must be re-asserted at every layer software believes it owns. Predicts: an "isolated" experiment still contends with other tenants unless cpuset/LLC/SMT are explicitly controlled. Bug class: unexplained cross-experiment correlation traced back to hardware sharing days later. Applies in §20.
  • MM8 — Firmware Can Silently Rewrite the Experiment. Microcode updates change the ground truth a demonstrator depends on without changing any source line. Predicts: a "known-vulnerable" fixture eventually stops reproducing after a routine kernel/firmware update. Bug class: filing a bug against the attack engine when the actual cause is a mitigated microcode revision. Applies in §18.

5. Required Reading

Books

  • Computer Systems: A Programmer's Perspective — Bryant & O'Hallaron (2015), ch. 6, 8, 12: memory hierarchy, exceptional control flow, and concurrency semantics that underlie cache-aware execution; applied in §11 and §17.
  • Computer Architecture: A Quantitative Approach — Hennessy & Patterson (2017), ch. 2–3: pipeline execution, branch prediction, and cache design fundamentals; applied in §13 and §18.
  • Linux Kernel Development — Robert Love (2010), ch. 4, 7: scheduler internals, timing primitives, and kernel synchronization; applied in §15.
  • Systems Performance — Brendan Gregg (2020), ch. 6, 9, 13: perf subsystem mechanics, CPU profiling, and PMU-interpretation methodology; applied in §13 and §28.
  • Practical Binary Analysis — Dennis Andriesse (2018), ch. 3, 10: ELF/DWARF structure and runtime instrumentation techniques; applied in §16.
  • Serious Cryptography — Jean-Philippe Aumasson (2017), ch. 1, 11: constant-time implementation discipline and side-channel resistance in crypto primitives; applied in §16 and §22.

Papers

  • "Timing Attacks on Implementations of Diffie-Hellman, RSA, DSS, and Other Systems" — Kocher, 1996, CRYPTO: foundational proof that variable-time modular exponentiation leaks key bits → motivates the constant-time victim profile; applied in §16.
  • "Cache-Timing Attacks on AES" — Bernstein, 2005, preprint: table-lookup AES leaks its key schedule via L1 timing → drives the lookup-table victim workload design; applied in §16.
  • "Cache Missing for Fun and Profit" — Percival, 2005, BSDCan: cross-thread L1/L2 timing leakage on SMT cores → basis of probe calibration methodology; applied in §13 and §17.
  • "Cache Attacks and Countermeasures: The Case of AES" — Osvik, Shamir & Tromer, 2006, CT-RSA: introduces Prime+Probe and Evict+Time on set-associative caches → drives eviction-set construction; applied in §17.
  • "FLUSH+RELOAD: A High Resolution, Low Noise, L3 Cache Side-Channel Attack" — Yarom & Falkner, 2014, USENIX Security: clflush-based shared-memory cache attack with sub-nanosecond resolution → core Flush+Reload engine design; applied in §17.
  • "The Spy in the Sandbox: Practical Cache Attacks in JavaScript" — Oren, Kemerlis, Sethumadhavan & Keromytis, 2015, CCS: Prime+Probe under coarse timer resolution → informs noise-model timer-degradation fixtures; applied in §19.
  • "Spectre Attacks: Exploiting Speculative Execution" — Kocher et al., 2019, IEEE S&P: branch-target misprediction leaks across protection boundaries via transient execution → mistraining-loop design; applied in §18.
  • "Meltdown: Reading Kernel Memory from User Space" — Lipp et al., 2018, USENIX Security: out-of-order execution bypasses privilege checks before fault delivery → transient-execution probe design; applied in §18.
  • "Foreshadow: Extracting the Keys to the Intel SGX Kingdom with Transient Out-of-Order Execution" — Van Bulck et al., 2018, USENIX Security: L1TF terminal-fault speculation breaks SGX isolation → scopes the deferred SGX instrumentation register entry; applied in §18.
  • "ZombieLoad: Cross-Privilege-Boundary Data Sampling" — Schwarz et al., 2019, CCS: microarchitectural data sampling leaks in-flight load-buffer data → noise-model fill-buffer contention fixture; applied in §19.
  • "A Survey of Microarchitectural Timing Attacks and Countermeasures on Contemporary Hardware" — Ge, Yarom, Cock & Heiser, 2018, Journal of Cryptographic Engineering: taxonomy of timing channels and mitigation classes → threat-model surface enumeration; applied in §22.

Reference Implementations

  • torvalds/linux — study tools/perf/ and kernel/events/core.c: PMU abstraction, ring-buffer sample delivery, event multiplexing; pitfall: do not copy perf's userspace ABI versioning scheme wholesale, it assumes a single kernel-resident consumer; applied in §13.
  • 0xADE1A1DE/Mastik — study L1.c, L3.c: cache-attack primitive structure and probe calibration harness; pitfall: do not copy Mastik's global-state probe singletons, they block concurrent multi-experiment isolation; applied in §17.
  • gem5/gem5 — study src/mem/cache/: microarchitectural cache and coherence modeling; pitfall: do not fold cycle-accurate timing models into a real-hardware demonstrator, simulated timing diverges from silicon; applied in §18 as comparative reference only.
  • intel/pcm — study src/cpucounters.cpp: uncore/PMU counter enumeration and MSR access patterns; pitfall: do not copy PCM's direct MSR writes, prefer perf_event_open for portability (ADR-11); applied in §13.
  • rr-debugger/rr — study src/ReplaySession.cc: deterministic record/replay via ptrace and performance-counter-driven scheduling; pitfall: do not copy rr's single-core replay assumption, this platform must replay under multi-core scheduler noise; applied in §14.
  • google/safeside — study demos/: minimal reproducible Spectre/Meltdown-class measurement harness structure; pitfall: do not copy safeside's fixed-iteration calibration loop, it undercounts noisy-environment variance; applied in §16 and §18.

RFCs / Specifications

  • Intel 64 and IA-32 Architectures SDM, Volume 3 — pins MSR layout, performance-monitoring event selectors, and invariant-TSC CPUID leaf semantics; applied in §13.
  • AMD64 Architecture Programmer's Manual, Volume 2 — pins cross-vendor performance-counter and RDTSC serialization semantics; applied in §13.
  • Linux perf_event_open(2) manual page — pins the syscall ABI, perf_event_attr layout, and ring-buffer mmap contract used for PMU sampling; applied in §13 and §20.
  • DWARF Debugging Information Format, Version 5 — pins symbol and line-table structure used by tools/trace-inspector for postmortem stack attribution; applied in §14.

Glossary (§36) · 47 terms · site-wide glossary

PMU
performance monitoring unit; on-core hardware exposing event/cycle counters.
TSC
timestamp counter; per-core cycle counter read via rdtsc.
Invariant TSC
a TSC guaranteed to increment at a fixed rate independent of core frequency scaling.
Replay Frame
an immutable, checksum-terminated experiment snapshot (§8.4, §11).
Leakage Signal
measurable secret-correlated timing or counter behavior.
Cache Eviction Set
a set of addresses mapping to a shared cache set, used to evict a victim's line.
Speculative Window
the transient-execution interval between a mispredicted branch and pipeline squash.
Flush+Reload
a cache-timing attack using clflush plus reload-latency measurement.
Prime+Probe
a cache-occupancy attack that primes then probes a shared cache set.
Constant-Time
execution whose timing is independent of secret data.
SMT
simultaneous multithreading; multiple logical cores sharing one physical core's resources.
NUMA
non-uniform memory access; memory latency varies by socket/node distance.
LLC
last-level cache, typically shared across all cores on a socket.
Telemetry Span
a structured, timed scope emitted by scd-telemetry.
Replay Determinism
the property that replay reproduces the original trace's timing/classification exactly.
Affinity Pinning
forcing a thread/process to execute on a specific CPU set.
Mistraining Loop
repeated correctly-predicted branch executions used to prime a predictor before a mispredicting probe.
Transient Execution
instructions executed speculatively before their correctness is confirmed.
Branch Predictor
hardware unit predicting conditional/indirect branch outcomes ahead of resolution.
Branch History
recorded outcomes feeding the branch predictor's prediction state.
Cache Residency
whether a given address's line currently occupies a cache level.
Threshold Classifier
the calibrated cycle-count boundary distinguishing cache hit from miss.
Watchdog
a timer-armed monitor that force-aborts a stalled experiment (I9).
Futex Barrier
a kernel-futex-backed rendezvous primitive between two processes.
Backpressure
a policy rejecting or dropping input once a bounded resource reaches capacity.
Drop-Oldest Policy
a backpressure strategy discarding the oldest queued item under overflow.
Sealed Manifest
an ExperimentManifest past the point of allowed mutation (I7).
Checksum Quarantine
isolating a frame that fails checksum verification from the active replay set.
Degraded Capability Mode
reduced-telemetry operation after a PMU/timer capability downgrade.
Welch's t-test
a two-sample hypothesis test tolerant of unequal variance and sample size.
Confidence Interval
a statistical bound expressing estimate uncertainty at a stated confidence level.
Leakage Entropy
the estimated number of secret bits distinguishable from an observed signal.
Noisy Neighbor
a co-scheduled experiment degrading another's measurement fidelity via shared hardware.
Cpuset Isolation
restricting a process group to a disjoint set of CPUs via the cgroup cpuset controller.
C-State
a CPU idle power state; deeper states add wake latency that contaminates timing.
Turbo Boost
dynamic frequency scaling above base clock under thermal/power headroom.
MSR
model-specific register; vendor-defined control/status register accessed via RDMSR/WRMSR.
CPUID
the x86 instruction/leaf enumerating CPU features and topology.
Retpoline
a compiler/kernel indirect-branch mitigation technique against branch-target-injection attacks.
Microcode
CPU-vendor-supplied firmware patch altering instruction/microarchitectural behavior.
Eviction Set Convergence
the round count at which a candidate address set is confirmed congruent to a target cache set.
Signal-to-Noise Ratio
the ratio of leakage-correlated variance to background measurement noise.
Warm-up Window
an initial discarded sample range excluded to let calibration/predictor state stabilize.
Jitter Compensation
subtracting a rolling measured offset from reported timestamps to counter scheduling noise.
ASLR
address space layout randomization; randomizes process memory layout per run.
Page Coloring
the mapping between virtual page and physical cache set/way, varying by physical RAM layout.
Hugepage
a larger-than-base-size virtual memory page reducing TLB pressure but altering cache-set mapping.
