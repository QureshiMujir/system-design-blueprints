HTTP API layer. Stateless axum/tower service; every OCI Distribution route (§8.2); terminates TLS 1.3 (ADR-25); the only network-facing box; enforces auth before any handler runs.

Auth/token service. Issues short-lived signed JWTs scoped repository:<name>:<actions> (§8.10 EBNF); bridges to an external OIDC/LDAP identity source; the registry validates tokens against this service's public key, never re-derives identity itself.

Manifest handler. Parses/validates manifests and image indexes; enforces I2 (no partial-blob visibility) and I13 (index children exist) before any DB write commits.

Blob handler. Serves HEAD/GET for existence checks and streaming reads; issues presigned-redirect or proxies bytes depending on backend (ADR-05); enforces range requests (RFC 7233).

Upload session manager. Owns the chunked/monolithic upload state machine (§8.9); all state durable in the metadata store (ADR-09), never process-local.

Content-addressable store. StorageBackend trait (§11) abstracting filesystem and S3-compatible backends; digest-prefix-sharded layout (ADR-06); the only box that touches raw blob bytes.

Metadata store. PostgreSQL; repositories, tags, manifests, referrers, upload sessions, blob-repo membership, audit log; the durability/commit boundary (ADR-08).

Reference/tag index. Logical view over the metadata store: tags table mapping (repository, name) → manifest digest, atomically updated (I5).

Garbage collector. Background worker; two-phase mark-and-sweep with a quarantine window (§18, I3); the only actor permitted to delete blobs/manifests (P8).

Signature/attestation verifier. Consumes referrer manifests with artifactType sigstore/in-toto; policy-configurable enforcement point (P13, ADR-21).

Scan-integration hook. Async webhook fan-out on push; ingests scan results as annotations/referrers; never blocks the push path (ADR-22).

Replication/mirror worker. Durable outbox consuming push events; fans out to peer registries (ADR-24); crosses the one true trust boundary in the diagram.

Pull-through cache. Proxies + caches upstream manifests/blobs; revalidates tag-referenced entries via ETag (RFC 7232), never revalidates digest-pinned entries (ADR-23).

Quota and rate limiter. Token-bucket per (token, repository), Redis-backed shared counters (ADR-20); the first check any write path performs after auth.

Audit log. Append-only, monotonically sequenced (I12); every admin/auth-relevant action.

Telemetry. OpenTelemetry traces, Prometheus metrics, structured JSON logs (ADR-26/27/28) cross-cutting every box above.

8. Domain Model

8.1 Descriptor / Manifest / Index / Config / Layer — field tables

Descriptor (per OCI Image Format Specification):

Field Type Notes
mediaType string one of MediaType (§11)
digest Digest algorithm:hex
size int64 bytes
urls string[] (optional) foreign-fetch hint, rarely used
annotations map<string,string> (optional) OCI annotation keys
platform Platform (optional, index entries only) os, architecture, variant
artifactType string (optional, OCI 1.1) referrer artifact discriminator

Manifest (image manifest): schemaVersion, mediaType, config (Descriptor → ImageConfig), layers (Descriptor[] → blobs), subject (Descriptor, optional, OCI 1.1 referrer linkage), annotations.

ImageIndex: schemaVersion, mediaType, manifests (Descriptor[] with platform), subject (optional), annotations.

ImageConfig: architecture, os, config (entrypoint/env/etc., opaque to the registry), rootfs.diff_ids (uncompressed layer digests), history. The registry treats config bytes as an opaque blob validated only by digest.

8.2 Digest-linkage diagram (Merkle structure)

 tag "v1.2.3" ──► ImageIndex (digest sha256:idx…)
                   ├─ platform linux/amd64 ─► Manifest (sha256:m1…)
                   │                            ├─ config  ─► Blob (sha256:c1…)
                   │                            ├─ layer 0 ─► Blob (sha256:l0…)
                   │                            └─ layer 1 ─► Blob (sha256:l1…)
                   └─ platform linux/arm64 ─► Manifest (sha256:m2…)
                                                ├─ config  ─► Blob (sha256:c2…)
                                                └─ layer 0 ─► Blob (sha256:l0…)  (shared, deduped)
 referrer (sig)   ─► Manifest (sha256:sig1, subject=sha256:m1) ─► Blob (signature bytes)

Each edge is a digest, i.e. a hash pointer (Merkle 1988, §5): tamper anywhere below the root and the digest chain fails to verify at the point of tamper.

8.3 Content-addressing / digest-algorithm agility

Every digest is <algorithm>:<hex>. Algorithm registry: sha256 (mandatory, 32-byte), sha512 (optional, 64-byte); an unrecognized algorithm prefix is rejected at parse time (P1). A manifest may mix algorithms across its own digest and its referenced blobs' digests, but the registry never accepts a client-asserted digest without recomputing it against the algorithm named in the reference — this is the digest-downgrade defense (T3).

8.5 Chunked-upload protocol sequence

Step Method Range accounting Resumption rule
1 POST /blobs/uploads/ offset := 0 Server returns Location + Range: 0-0
2..N PATCH /uploads/{uuid} Content-Range: start-end; server rejects if start ≠ current_offset Client GETs the upload URL to recover current_offset after any interruption
N+1 PUT /uploads/{uuid}?digest= optional final-chunk body, then rehash whole temp object Digest mismatch ⇒ reject, session stays Verifying→client may retry PUT only, not re-PATCH

Cross-repository blob mount (POST .../uploads/?mount=<digest>&from=<repo>, I10): verifies pull-scope on from, then inserts a blob_repos row referencing the existing object — zero bytes re-transferred.

8.6 Referrers / attestation linkage

A manifest with subject set is a referrer of the digest named in subject. On insert, the registry records (subject_digest, referrer_digest, artifact_type, repository_id) in the referrers index (I9). GET /referrers/{digest} returns a synthesized ImageIndex whose entries are all referrer manifests, optionally filtered by artifactType (e.g. application/vnd.dev.sigstore.bundle+json, application/vnd.in-toto+json).

8.7 Tag and reference index model

Reference is a sum type: Tag(name) or Digest(d). TagIndex: (repository_id, name) → manifest_digest, one live row per name (I5). Digest references never consult the tag index — they resolve directly against the manifest table, giving digest-pull its immutability guarantee (I4) independent of any tag mutation.

8.8 Garbage-collection mark-and-sweep (named steps, safety argument)

  1. Safe-point record — GC records mark_start_ts (Lamport-ordered sequence, §5) before scanning.
  2. Mark — full scan of tags → reachable manifests → transitively reachable child manifests/referrers → reachable blobs. Any upload session with created_at < mark_start_ts also marks its temp blob as reachable (protects in-flight pushes that predate the scan).
  3. Quarantine — unmarked blobs/manifests are flagged quarantined_at = now(), not deleted.
  4. Quarantine window wait — 48 h (§4); any push referencing a quarantined blob within the window rescues it (unflags) instead of re-uploading.
  5. Sweep — after the window, blobs/manifests still quarantined and still unmarked in a second mark pass are deleted from metadata store then storage backend.

The exact race it must not lose: a blob uploaded after mark-start but whose referencing manifest is inserted after mark completes and before sweep executes. Step 2's created_at < mark_start_ts upload-session carve-out plus the quarantine window (step 3–4) together guarantee this blob is never swept before a referencing manifest has had 48 h to appear (§18 develops the full proof).

8.9 Upload-session and manifest lifecycle state machines

UploadSession:

State On Next Failure edge
InProgress POST/first PATCH PATCH → InProgress (offset++) Non-sequential PATCH → RangeNotSatisfiable, state unchanged
InProgress PUT (finalize) → Verifying Missing chunks → digest mismatch → back to InProgress
Verifying hash matches → Finalized hash mismatch → Aborted
InProgress/Verifying TTL expiry or DELETE → Aborted —

Manifest lifecycle:

State On Next Failure edge
Validating PUT received reference-existence check Missing blob/child → reject, stays absent (never persisted)
Validating all refs present → Committed (I2) Digest mismatch on digest-reference PUT → reject
Committed tag PUT re-targets tag row updated (I5) —
Committed unreachable after GC mark → Quarantined Rescued by new tag/reference → back to Committed
Quarantined sweep after window → Deleted Rescue during window → Committed

8.10 Token-scope grammar (EBNF) and worked decision

scope       = resource-scope *( " " resource-scope ) ;
resource-scope = resource-type ":" resource-name ":" action-list ;
resource-type  = "repository" | "registry" ;
action-list = action *( "," action ) ;
action      = "pull" | "push" | "delete" | "*" ;
resource-name  = repo-path ;               (* e.g. "myorg/myimage" *)

Worked decision: token grants repository:myorg/myimage:pull. Request: POST /v2/myorg/myimage/blobs/uploads/?mount=sha256:abc&from=otherorg/base. Requires repository:myorg/myimage:push (absent → deny) AND repository:otherorg/base:pull (absent → deny). Verdict: DENIED (I7, I10) — token has neither.

8.11 Worked push-then-pull example

Push: client uploads layer0 (sha256:l0) and config (sha256:c0) monolithically, then PUT /v2/acme/app/manifests/v1 with a manifest referencing both — registry verifies both exist (I2), computes manifest digest sha256:m0, commits tags(acme/app, v1) → m0. Pull: GET /v2/acme/app/manifests/v1 → resolves tag → returns manifest body with Docker-Content-Digest: sha256:m0; client then GET .../blobs/sha256:l0 and .../blobs/sha256:c0.

8.12 Malformed-input examples

  • Digest mismatch: client asserts sha256:aaa… on finalize; recomputed hash is sha256:bbb… → reject DIGEST_INVALID (I1).
  • Manifest referencing an absent blob: layers[1].digest not in blob table → reject MANIFEST_BLOB_UNKNOWN (I2).
  • Chunk range gap: PATCH 3 declares Content-Range: 2048-4095 while current_offset = 1024 → reject RANGE_NOT_SATISFIABLE (I6).
  • Chunk range overlap: PATCH declares Content-Range: 512-2047 while current_offset = 1024 → reject, same code (I6).
  • Oversized manifest: body > 4 MiB (§4) → reject MANIFEST_INVALID before JSON parse.
  • Media-type/content mismatch: mediaType claims application/vnd.oci.image.manifest.v1+json but body parses as an index → reject MANIFEST_INVALID.
  • Cyclic index: an index whose child digest resolves back to an ancestor index digest → reject during reference-graph walk (cycle detection cap: max depth 8).

8.13 Failure-path example

Network interruption at 60% of a 4 GiB chunked upload: client retries PATCH from a stale offset; server rejects (I6) with the current offset in the Range response header; client GETs the upload URL to recover current_offset, resumes from there — zero re-transfer of already-accepted bytes (§14.4).
