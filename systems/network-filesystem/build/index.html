⬜ Phase 0 — Repo Skeleton + TCP Listener + Record-Marking + XDR Primitives

Objectives

Workspace + 12 crates; tokio TCP listener; RFC 5531 record-marking framer; XdrEncode/XdrDecode traits + all primitive codecs with defensive bounds-checks. Foundation for every later phase.

Deliverable

Daemon accepts TCP, frames records, decodes/encodes XDR primitives round-trip; cargo test + criterion xdr bench run.

Acceptance

XDR round-trip property tests pass (10k cases, proptest); framer handles split/coalesced fragments (fixtures); decode rejects oversize len in O(1) without allocation; xdr primitive encode ≥ 2 GB/s in criterion; zero clippy warnings.

Fixtures

xdr_primitives.bin (golden encodings vs RFC 4506 examples); frame_split.pcap, frame_coalesced.pcap; malformed: frame_oversize.bin (len=2^31-1), xdr_truncated.bin, xdr_badpad.bin.

Pitfalls

(1) Forgetting 4-byte pad → off-by-pad on next field. (2) Signed/unsigned confusion on fragment header (top bit). (3) Allocating Vec::with_capacity(declared_len) before validation → OOM DoS. (4) Not capping reassembly → unbounded memory. (5) Reading from a &[u8] cursor without advancing exactly.

⬜ Phase 1 — ONC RPC Dispatch + AUTH_SYS + NULL/GETATTR + portmap

Objectives

Full RPC call/reply (de)serialization; program/version/proc dispatch; AUTH_SYS + AUTH_NONE; implement NULL + a stub GETATTR; register NFS+MOUNT with portmap/rpcbind.

Deliverable

rpcinfo -p localhost lists our programs; rpcinfo -t localhost nfs 3 NULL succeeds; a hand-built GETATTR returns a reply.

Acceptance

Linux rpcinfo enumerates registrations; NULL ping < 100 µs p50; GARBAGE_ARGS returned for truncated args (not a panic); AUTH_SYS parsed with correct uid/gid; PROG_MISMATCH returns supported version range.

Fixtures

rpc_null_call.bin/.reply; rpc_getattr_call.bin; auth_sys_cred.bin; malformed: rpc_bad_rpcvers.bin (rpcvers≠2 → RPC_MISMATCH), auth_sys_toomany_gids.bin, rpc_unknown_proc.bin.

Pitfalls

(1) Replying with wrong xid (must echo call xid). (2) Mis-encoding accept-stat vs proc-result ordering. (3) Trusting AUTH_SYS uid as identity (principle 9) — it is advisory. (4) portmap registration race on restart (deregister stale first). (5) machinename string unbounded → cap it.

⬜ Phase 2 — VFS + Backing Store (inode map, handles, attr) — Local Directory Backend

Objectives

vfs layer + on-disk store: inode map, data files, file-handle encode/decode with generation, attr derivation, path resolution with export-root containment. Replace GETATTR stub with real attrs.

Deliverable

Real GETATTR over a local directory export; handles round-trip and survive process restart (stable); path resolution contained.

Acceptance

Create 1M inodes, restart, all handles still resolve (stability test); freed+reused inode → old handle gets STALE (gen test); ../symlink escape attempts blocked (containment test); GETATTR p50 < 50 µs (cached inode).

Fixtures

handle_roundtrip.json (FhInner ↔ bytes); handle_stale_gen.bin; path_escape_cases.txt (../, a/../../, abs-symlink); inode_record.golden; malformed: handle_badmagic.bin, handle_truncated.bin.

Pitfalls

(1) Encoding raw inode without gen → STALE-miss security bug (serve wrong file). (2) Symlink resolved client-side vs server-side mismatch. (3) Not journaling inode alloc → orphan/leak after crash. (4) Path resolution following mountpoints across fsid silently. (5) TOCTOU between lookup and open.

⬜ Phase 3 — NFSv3 Read Path

Objectives

Implement read-side procedures: LOOKUP, ACCESS, READ, READLINK, READDIR, READDIRPLUS, FSINFO, FSSTAT, PATHCONF. Stateless; no DRC needed (all idempotent).

Deliverable

mount -t nfs -o vers=3 srv:/export /mnt then ls, cat, find work against a real Linux client.

Acceptance

Linux v3 mount lists + reads files identically to local; find /mnt traverses 100k-entry dirs without cookie errors; READ throughput ≥ 2 GB/s cached; READDIRPLUS reduces round-trips vs READDIR+LOOKUP (measured); Connectathon basic read tests pass.

Fixtures

lookup_seq.pcap, read_eof.bin, readdirplus_largedir.bin, fsinfo_reply.golden; malformed: read_offset_overflow.bin (off+count overflow → INVAL), readdir_stale_cookie.bin, lookup_dotdot_at_root.bin.

Pitfalls

(1) READDIR cookie not stable across dir mutation → infinite loop / skipped entries. (2) READDIRPLUS reply exceeding maxcount → client truncation errors. (3) Integer overflow on offset+count. (4) Returning wrong eof flag → client hangs or stops early. (5) ACCESS computed differently from actual READ/WRITE permission (must be consistent). (6) Not capping count to rsize.

⬜ Phase 4 — NFSv3 Write Path + wcc + Duplicate Request Cache

Objectives

Mutating procedures: WRITE (UNSTABLE/DATA_SYNC/FILE_SYNC), COMMIT, CREATE (UNCHECKED/GUARDED/EXCLUSIVE), MKDIR, REMOVE, RMDIR, RENAME, LINK, SYMLINK, MKNOD, SETATTR; weak cache consistency (wcc); and the Duplicate Request Cache for at-most-once non-idempotent ops (I2).

Deliverable

Full read-write v3 mount: cp, mv, rm, mkdir, dd work from Linux client; retransmitted REMOVE doesn't return spurious ENOENT.

Acceptance

Connectathon general + special tests pass; DRC suppresses double-execution (inject duplicate REMOVE/RENAME → second is replayed, verified by drc_hit_total); EXCLUSIVE CREATE idempotent under retransmit; COMMIT after UNSTABLE writes durable across kill -9 (crash test); wcc lets client avoid spurious cache flush (measured cache-hit retention).

Fixtures

write_unstable_commit.pcap, create_exclusive_retry.bin, rename_atomic.bin, wcc_before_after.golden; DRC: remove_retransmit.bin (same xid twice), drc_eviction.json; malformed: write_count_mismatch.bin (count≠data len), setattr_badguard.bin.

Pitfalls

(1) DRC keyed only on xid (not proc+client) → cross-op collision replays wrong reply. (2) Caching idempotent ops wastes DRC. (3) EXCLUSIVE CREATE not storing createverf → retry returns EXIST instead of success. (4) COMMIT replying before fsync → silent data loss (cardinal sin, principle 13). (5) wcc pre-attrs captured after mutation → client over-invalidates. (6) RENAME not atomic → dangling entries. (7) DRC entry stored before op completes (IN_PROGRESS replayed as Done).

⬜ Phase 5 — NFS Client (mount, attr cache, data cache, readahead, write-back, CTO) over FUSE

Objectives

A working NFS client: FUSE bridge → RPC client; attribute cache (acreg/acdir TTL); data cache + readahead; write-back buffering with UNSTABLE→COMMIT; close-to-open consistency (principle 4). Enables self-interop (our client ↔ our server) and validation against real servers.

Deliverable

mount.nfs-rs srv:/export /mnt via FUSE; full POSIX file ops; CTO verified across two clients (writer closes → reader opens → sees new data).

Acceptance

Self-interop passes Connectathon; CTO test: writer close → reader open sees update within 0 staleness; attr-cache reduces GETATTR traffic ≥ 80% on repeated stat; readahead achieves ≥ 90% of server READ throughput on sequential read; write-back + COMMIT matches durability of sync writes on close.

Fixtures

cto_writer_reader.script, attrcache_ttl.script, readahead_seq.fio, writeback_close_commit.pcap; malformed/edge: stale_handle_recovery.script (server returns STALE → client re-lookups).

Pitfalls

(1) Not reusing xid on retransmit → server re-executes (DRC miss) → corruption. (2) Caching attrs past TTL → stale reads (CTO violation). (3) Not flushing on close → reader sees old data. (4) Readahead too aggressive → wasted bandwidth + cache pollution. (5) Ignoring wcc → over/under-invalidation. (6) Soft mount returning EIO mid-write → data loss; hard mount hanging forever → "client hang" incidents.

⬜ Phase 6 — NLM Byte-Range Locking + Lock Recovery Basics

Objectives

Advisory byte-range locking for v3 via NLM (program 100021) front-ending a shared lockmgr conflict engine; blocking locks with async grant; lock recovery basics (NSM/state-monitor notification on reboot). Integrated v4 LOCK reuses the same engine in Phase 8.

Deliverable

flock/fcntl byte-range locks over v3 NLM from a Linux client; blocking locks granted asynchronously when conflict clears.

Acceptance

Connectathon lock tests pass; two clients contending on overlapping ranges serialize correctly; blocking LOCK is granted on UNLOCK of holder (async GRANTED callback); lock count capped (reject NLM_DENIED at limit); after simulated reboot, NSM notification triggers reclaim.

Fixtures

nlm_lock_conflict.pcap, nlm_blocking_grant.script, nlm_cancel.bin, nsm_reboot_notify.script; malformed: nlm_unlock_unheld.bin, nlm_lock_overflow.bin (exceed cap).

Pitfalls

(1) NLM is a separate program/port — easy to misroute. (2) Async _MSG/_RES callback model is stateful and fiddly (grant races). (3) Not bounding lock count → memory DoS. (4) Owner identity confusion (svid vs client) → wrong lock released. (5) Forgetting NSM → no recovery after reboot. (6) Deadlock detection scope (advisory: deny, don't hang).

⬜ Phase 7 — NFSv4.1 COMPOUND + SEQUENCE + Session/Slot + Pseudo-FS + GETFH/PUTFH

Objectives

Stateful protocol foundation: COMPOUND op arrays with cfh/sfh threading; EXCHANGE_ID + CREATE_SESSION; SEQUENCE slot-table exactly-once (replaces DRC for v4.1, I10); pseudo-fs root namespace; PUTROOTFH/PUTFH/GETFH/SAVEFH/RESTOREFH/LOOKUP/GETATTR/READ/WRITE in compound form. No OPEN/locking yet (Phase 8).

Deliverable

mount -t nfs -o vers=4.1 srv:/ /mnt mounts the pseudo-fs; traversal into exports; read/write in compound form against a Linux v4.1 client.

Acceptance

Linux v4.1 mount + read/write works; SEQUENCE replay test (retransmit same slot/seqid → cached reply, no re-exec, I10); misordered seqid → NFS4ERR_SEQ_MISORDERED; pseudo-fs traversal exposes correct fsid boundaries; pynfs v4.1 SEQUENCE + session tests pass; COMPOUND partial-failure returns prefix results (I14).

Fixtures

compound_putfh_getattr.bin, sequence_replay.pcap, create_session.bin, pseudofs_traverse.script, attr_bitmap.golden; malformed: sequence_misorder.bin, compound_overlong.bin (op cap), bad_sessionid.bin.

Pitfalls

(1) Not making SEQUENCE first op → must reject. (2) Slot seqid off-by-one (replay vs execute boundary). (3) cfh not threaded → ops operate on wrong file. (4) Pseudo-fs leaking real paths. (5) Caching SEQUENCE reply too small (must cache whole compound reply per slot). (6) Lease not renewed by SEQUENCE → spurious expiry. (7) clientid confirmation skipped → state attaches to unconfirmed client.

⬜ Phase 8 — NFSv4 OPEN/CLOSE/LOCK + stateid + lease renew + grace + read delegations

Objectives

Stateful file access: OPEN (share access/deny, claims), CLOSE, LOCK/LOCKT/LOCKU (integrated, reusing lockmgr), stateids with seqid (I12), lease renewal + revocation (I4), grace-period recovery after reboot (I3), read delegations + recall via back channel (I15).

Deliverable

Full stateful v4.1: OPEN/CLOSE/byte-range LOCK; lease-based recovery; server reboot → clients reclaim in grace; read delegations granted + recalled.

Acceptance

pynfs v4.1 OPEN/LOCK/state tests pass; share-deny conflict enforced (second OPEN with DENY_WRITE blocks writer); lease expiry frees state (test: stop renewing → state revoked → NFS4ERR_EXPIRED); reboot → grace → CLAIM_PREVIOUS reclaim succeeds, new conflicting OPEN gets NFS4ERR_GRACE until grace ends; read delegation recalled on conflicting write within recall timeout.

Fixtures

open_share_deny.bin, lock_seqid.pcap, lease_expiry.script, grace_reclaim.script, deleg_recall.pcap, stateid_old.bin; malformed: stateid_bad.bin, open_reclaim_outside_grace.bin, close_wrong_seqid.bin.

Pitfalls

(1) seqid not bumped → client/server desync (BAD_STATEID storms). (2) Granting new state during grace → split ownership (corruption, I3). (3) Lease renewed by wrong op (only SEQUENCE in v4.1). (4) Delegation not recalled before conflicting access → incoherent caches. (5) CB back-channel down → recall can't reach client → must revoke delegation after timeout. (6) Share-deny semantics differ from POSIX advisory locks — keep separate. (7) Reclaim allowed for never-held state (must validate against pre-reboot record or edge-case it).

⬜ Phase 9 — RPCSEC_GSS / Kerberos + Export Auth + root_squash + AUTH Hardening

Objectives

Real authentication: RPCSEC_GSS (krb5 authn, krb5i integrity, krb5p privacy) via system GSSAPI; export-level auth (sec= flavor enforcement, ro/rw); root_squash/all_squash; harden AUTH_SYS to advisory-only-behind-export-ACL (principle 9).

Deliverable

mount -o sec=krb5p works against a real KDC (integration, not our KDC); root_squash maps remote root to nobody; ro exports reject writes.

Acceptance

krb5/krb5i/krb5p all establish + transfer data against MIT/Heimdal KDC; tamper with krb5i message → rejected (integrity); root_squash verified (remote uid 0 → anon, cannot chown); sec mismatch → AUTH_ERROR/NFS4ERR_WRONGSEC; replay of GSS message → rejected by seq window.

Fixtures

gss_init_continue.pcap, krb5i_mic.bin, krb5p_wrap.bin, root_squash.script, secinfo_reply.bin; malformed: gss_replay.bin, gss_bad_mic.bin, sec_mismatch.bin.

Pitfalls

(1) Trusting AUTH_SYS uid without export gating (principle 9 violation). (2) GSS sequence window too small → false replay rejects under reorder. (3) Not destroying GSS context on DESTROY → context leak. (4) krb5p performance cliff (encrypt every payload). (5) Clock skew breaking Kerberos (5-min default) → mount fails — surface clearly. (6) Privilege via supplementary gids spoofing under AUTH_SYS.

⬜ Phase 10 — SMB2 NEGOTIATE + SESSION_SETUP (NTLMSSP) + TREE_CONNECT + CREATE/READ/WRITE/CLOSE

Objectives

Second protocol front-end over the same vfs: SMB2 transport framing + 64-byte header; NEGOTIATE (dialect selection 2.0.2–3.1.1); SESSION_SETUP via SPNEGO/NTLMSSP; TREE_CONNECT to a share; CREATE/READ/WRITE/CLOSE/FLUSH. Proves the single-VFS-chokepoint thesis (principle 12).

Deliverable

mount.cifs //srv/share /mnt -o vers=3.0,sec=ntlmssp from Linux; read/write files; same files visible over NFS (cross-protocol via shared VFS).

Acceptance

Linux mount.cifs + Windows Explorer connect; CREATE/READ/WRITE/CLOSE round-trip; file written over SMB readable over NFS (shared inode/handle via vfs); NTLMSSP auth succeeds; dialect negotiation picks 3.1.1 with capable client; smbtorture smb2.create, smb2.read, smb2.write basic tests pass.

Fixtures

smb2_negotiate_311.pcap, ntlmssp_exchange.bin, tree_connect.bin, create_open_read.pcap, cross_protocol_nfs_smb.script; malformed: smb2_bad_structuresize.bin, negotiate_no_common_dialect.bin, ntlm_bad_mic.bin, header_bad_protocolid.bin.

Pitfalls

(1) StructureSize fields are fixed constants — must validate exactly. (2) MessageId/credit window mismatch → client aborts. (3) SMB path separators \ + case-insensitivity vs NFS / case-sensitive — reconcile in vfs. (4) FileId persistent vs volatile confusion. (5) NTLMSSP is fragile — validate NTLMv2 carefully, never accept LANMAN. (6) Share modes (SMB) vs advisory locks (NFS) are different models — don't conflate. (7) CREATE disposition matrix is large — table-drive it.

⬜ Phase 11 — SMB2 Oplocks/Leases + QUERY_DIRECTORY + QUERY/SET_INFO + Compound + Durable Handles + SMB3 Signing/Encryption

Objectives

SMB caching coherence + metadata + security: oplocks + leases (R/RW/RWH) with break sequence (I15); QUERY_DIRECTORY enumeration; QUERY_INFO/SET_INFO (file/fs/security classes); compounded requests; durable handles (reconnect); SMB3 signing (CMAC/GMAC) + encryption (CCM/GCM) + pre-auth integrity.

Deliverable

Windows + Linux SMB clients with working oplocks/leases, directory listing, file info, compound ops, durable-handle reconnect, signed + encrypted sessions.

Acceptance

smbtorture smb2.lease, smb2.oplock, smb2.compound, smb2.durable-open, smb2.notify pass; oplock break flushes client cache before conflicting access; SET_INFO rename atomic; SMB3.1.1 encryption verified (payload not plaintext on wire); signed session rejects tampered PDU; durable handle survives 30 s disconnect.

Fixtures

lease_break_rwh.pcap, query_dir_idboth.bin, setinfo_rename.bin, compound_create_query_close.pcap, durable_reconnect.script, smb3_encrypt_transform.bin, preauth_integrity.golden; malformed: signed_tampered.bin, setinfo_bad_class.bin, durable_reconnect_wrong_guid.bin.

Pitfalls

(1) Oplock break deadlock (server waits for ack while holding a lock client needs). (2) Lease vs oplock semantics confusion (lease survives close). (3) QUERY_DIRECTORY resume index instability across dir mutation (like READDIR cookies, I7). (4) Compound RELATED_OP FileId propagation bug. (5) Signing over wrong byte range. (6) Downgrade attack if pre-auth integrity skipped (3.1.1). (7) Durable handle GUID reuse/guessing.

⬜ Phase 12 — Durability + Crash Recovery + Performance

Objectives

Production-grade durability + recovery: journal replay correctness; handle stability across reboot (v3 immediate, v4 via grace); DRC persistence (optional); v4 state reconstruction; performance hardening (zero-copy READ, write coalescing, group commit).

Deliverable

kill -9 mid-write → restart → journal replay → consistent FS; v3 handles valid immediately; v4 clients reclaim in grace; measured zero-copy READ improvement.

Acceptance

Chaos test (kill mid-WRITE/COMMIT 1000×) → no corruption, COMMIT semantics honored (acked data survives, unacked may not); journal replay < 500 ms for 1 GB journal; v3 handle stability 100% across reboot; v4 reclaim succeeds within grace; zero-copy READ ≥ 2.5 GB/s (target §4); recovery time objective ≤ 120 s.

Fixtures

journal_replay.golden, torn_tail.bin (partial last record → discarded), crash_midwrite.script, handle_stability_reboot.script, zerocopy_read.fio; malformed: journal_bad_crc.bin, journal_reordered.bin.

Pitfalls

(1) Replaying uncommitted (torn) tail → corruption; must checksum + detect truncation. (2) Non-idempotent journal redo. (3) fsync of data but not metadata (or vice versa) → inconsistency. (4) Acking COMMIT before group-commit fsync completes (principle 13). (5) Write-verf not rotating on reboot → client trusts lost UNSTABLE data. (6) splice fallback path bugs (not all FS/socket combos support it).

⬜ Phase 13 — Conformance + Fuzzing + Interop

Objectives

Validate against industry suites + real clients; harden parsers via fuzzing; lock in interop with Linux mount -t nfs/mount.cifs and Windows SMB. The "is it actually a network filesystem" gate.

Deliverable

Green conformance suites; zero fuzzer crashes over N CPU-hours; documented interop matrix (which versions/clients pass).

Acceptance

pynfs v4.1 ≥ 95% pass (documented exceptions for deferred features); Connectathon basic+general+special+lock 100% for v3; smbtorture core suite pass; 24 CPU-hours fuzzing per parser with 0 crashes + coverage plateau; Linux v3/v4.1 + mount.cifs interop pass pjdfstest; differential test 0 mismatches vs Wireshark.

Fixtures

full conformance/expected/ manifests; fuzz/corpus/* seeds; interop/matrix.md; pcap-diff/golden/*.pcap; regression: every fixed fuzzer crash added as a corpus entry + unit test.

Pitfalls

(1) Conformance suites assume behaviors not in RFC (de-facto standards) — document deviations. (2) Fuzzing only the happy decode path (must fuzz post-decode handler too). (3) Interop "works on my client" — version skew matters (test multiple kernel versions). (4) Wireshark dissector bugs as false diffs. (5) smbtorture needs specific share config. (6) pynfs flakiness on timing-sensitive lease tests.
