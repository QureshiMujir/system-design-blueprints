3.2 Box-by-box responsibilities

  • server::listener — accepts TCP on 2049/445/111/MOUNT/NLM; spawns one tokio task per connection; enforces max-connection cap + per-IP limits; owns connection lifecycle (idle timeout, half-close, RST handling). Invariant: connection state never outlives the socket; closing a connection releases SMB handles + (after lease expiry) v4 state. Concurrency boundary: per-connection task; shared subsystems reached via Arc.
  • rpc::record_marking — frames the byte stream into RPC records: 4-byte big-endian header, top bit = last-fragment, low 31 bits = fragment length; reassembles fragments into one message; caps total message size. Invariant: a message is dispatched only after the last-fragment bit; oversized → connection killed. SMB uses its own 4-byte NetBIOS-style length prefix (smb2::framing).
  • rpc::dispatch + auth::verify + rpc::drc — parses RPC call header (xid, prog, vers, proc, cred, verf); routes to handler; verifies AUTH_SYS/RPCSEC_GSS; consults DRC for non-idempotent ops (cache hit → replay stored reply, no re-execution). Invariant: every non-idempotent op passes through DRC before execution; xid unique per connection in flight. Concurrency: DRC is a sharded LRU behind fine-grained locks.
  • nfs3::proc / nfs4::compound / smb2::command — protocol handlers. nfs3 is stateless per-op. nfs4::compound walks an op array threading a "current filehandle" + "saved filehandle", honoring SEQUENCE slot ordering. smb2::command dispatches by 16-bit command, charges credits. All three lower to vfs. Invariant: handlers never touch the store directly — only via vfs. I/O: in = decoded request struct; out = encoded reply + wcc/attr deltas.
  • vfs::vnode / vfs::handle / vfs::path / vfs::attr — the unifying layer: resolves paths within an export root (containment enforced — no .. escape), maps FileHandle ↔ vnode ↔ inode, computes Fattr3/SMB FILE_INFO, evaluates ACCESS/authorization. Invariant: handle→inode mapping stable + validated (ESTALE on mismatch); path resolution cannot escape export root. Concurrency boundary: per-inode locks for metadata mutation; the single chokepoint both protocols funnel through (ensures consistent semantics).
  • statemgr — owns NFSv4 client records, open/lock stateids, leases, delegations; SMB sessions, tree connects, opens, oplocks; the grace-period state machine. Invariant: lease renew-or-revoke (no split ownership); stateid seqid monotonic; on reboot, only reclaim allowed during grace. Concurrency: global state guarded by sharded locks keyed by client-id; hot path is lease renewal.
  • lockmgr — byte-range lock table; conflict detection; blocking-lock queues + async wakeups; NLM (v3 sidecar) and integrated v4 locking share the core conflict engine. Invariant: lock state consistent across reconnect; no two conflicting locks granted; lock counts bounded. Concurrency: per-file lock list under per-file lock.
  • store::inode_map / data / journal / fsid — on-disk persistence: inode table (mode, uid/gid, size, times, link count, generation number), data files, write-ahead journal for metadata + (optionally) v4 state, fsid registry per export. Invariant: WRITE+COMMIT durability (data on stable storage before COMMIT reply); handle generation number invalidates reused inode numbers; journal replay restores consistency after crash. Concurrency: journal append is serialized; data writes parallel per-file.
  • client:: (fuse, attrcache, datacache, writeback)* — kernel-VFS bridge via FUSE; attribute cache with acregmin/acregmax TTL; data cache + readahead; write-back buffering of UNSTABLE writes flushed by COMMIT; enforces close-to-open (GETATTR on open, flush on close). Invariant: on-close flush completes (or error surfaced) before close returns; cached attrs honored only within TTL. Concurrency: per-inode cache locks; background writeback + readahead tasks.
  • rpc::client / transport — encodes XDR requests, allocates xids, manages a connection pool per mount, retransmits on timeout (triggering server DRC), backs off. Invariant: retransmit reuses the same xid (so DRC recognizes the duplicate). Concurrency: multiplexes many in-flight requests per connection by xid.

8. Domain Model — Protocols In Depth

8.1 ONC RPC message (RFC 5531)

rpc_msg      = xid:u32, mtype:enum{CALL=0,REPLY=1}, body
call_body    = rpcvers:u32(=2), prog:u32, vers:u32, proc:u32,
               cred:opaque_auth, verf:opaque_auth, <proc args (XDR)>
opaque_auth  = flavor:enum{AUTH_NONE=0,AUTH_SYS=1,AUTH_SHORT=2,RPCSEC_GSS=6}, body:opaque<400>
reply_body   = stat:enum{MSG_ACCEPTED=0,MSG_DENIED=1}, ...
accepted     = verf:opaque_auth, stat:enum{SUCCESS=0,PROG_UNAVAIL=1,PROG_MISMATCH=2,
               PROC_UNAVAIL=3,GARBAGE_ARGS=4,SYSTEM_ERR=5}, <results | mismatch_info>
denied       = stat:enum{RPC_MISMATCH=0,AUTH_ERROR=1}, <reason>

8.2 Record marking over TCP

 byte:  0        1        2        3      ...payload (fraglen bytes)...
       ┌────────────────────────────────┐
       │ L │      31-bit fragment length │   L=1 → last fragment of this RPC message
       └────────────────────────────────┘
 message = 1+ fragments; reassemble until L=1. Cap Σfraglen ≤ MAX_MSG (e.g., 2 MiB+slop).
 SMB2 transport: 4-byte big-endian length prefix (top byte zero), then SMB2 PDU(s).

8.3 XDR rules (RFC 4506)

  • All types padded to 4-byte boundaries; big-endian (network order).
  • int/unsigned/bool/enum = 4 bytes; hyper/uhyper = 8 bytes.
  • opaque[n] fixed = n bytes + pad to 4; opaque<m> variable = u32 len (≤ m) + bytes + pad.
  • string<m> = u32 len + UTF-8/ASCII bytes + pad (no NUL terminator on wire).
  • arrays: fixed T[n]; variable T<m> = u32 count + elements.
  • union switch(disc) { case … } = disc (4 bytes) + selected arm.
  • optional T* = bool present + (T if present) — used for linked lists (e.g., entry chains).
  • Defensive rule: validate every declared len/count against a cap BEFORE allocating.

8.4 NFSv3 core XDR (RFC 1813) — lightweight schemas

nfs_fh3      = opaque<64>                          # opaque file handle (≤64 B)
filename3    = string<>                            # component name
nfspath3     = string<>                            # symlink target
fileid3      = uhyper                              # inode-ish id
cookie3      = uhyper ; cookieverf3 = opaque[8]    # READDIR cursor + verifier
nfstime3     = { seconds:u32, nseconds:u32 }
specdata3    = { specdata1:u32, specdata2:u32 }    # rdev for device nodes
ftype3       = enum{ REG=1,DIR=2,BLK=3,CHR=4,LNK=5,SOCK=6,FIFO=7 }
fattr3       = { type:ftype3, mode:u32, nlink:u32, uid:u32, gid:u32,
                 size:uhyper, used:uhyper, rdev:specdata3, fsid:uhyper,
                 fileid:fileid3, atime:nfstime3, mtime:nfstime3, ctime:nfstime3 }
sattr3       = { mode:set<u32>, uid:set<u32>, gid:set<u32>, size:set<uhyper>,
                 atime:set_time, mtime:set_time }   # each field = bool-tagged optional
wcc_attr     = { size:uhyper, mtime:nfstime3, ctime:nfstime3 }   # pre-op subset
pre_op_attr  = bool present + wcc_attr
post_op_attr = bool present + fattr3
wcc_data     = { before:pre_op_attr, after:post_op_attr }        # weak cache consistency
post_op_fh3  = bool present + nfs_fh3

wcc_data semantics: before = pre-op {size,mtime,ctime}; after = full post-op attrs. Client compares its cached ctime to before.ctime: if equal, its cache was current and it can trust after; else it invalidates. The mechanism that makes async WRITE cache-safe.

8.6 MOUNT protocol (program 100005, version 3)

Proc Name Args Result
0 MNT_NULL — —
1 MNT dirpath fhstatus3 {status, root fh, auth flavors}
2 DUMP — mountlist (who mounted what)
3 UMNT dirpath —
4 UMNTALL — —
5 EXPORT — exportlist {dir, groups}

MOUNT maps an export pathname → root file handle (the bootstrap; v3 has no PUTROOTFH). Returns supported auth flavors so the client picks AUTH_SYS vs RPCSEC_GSS.

8.7 NFSv4.1 (RFC 8881)

COMPOUND = { tag:string, minorversion:u32(=1), argarray:nfs_argop4<> } → { status, tag, resarray:nfs_resop4<> }. Ops execute left-to-right threading a current filehandle (cfh) and saved filehandle (sfh); first non-OK op halts the compound (I14).

Selected op set: SEQUENCE (must be first in v4.1; carries sessionid, slotid, sequenceid, highest_slotid), PUTROOTFH, PUTFH, PUTPUBFH, GETFH, SAVEFH, RESTOREFH, LOOKUP, LOOKUPP, ACCESS, GETATTR, SETATTR, READ, WRITE, COMMIT, OPEN, OPEN_CONFIRM (v4.0 only), OPEN_DOWNGRADE, CLOSE, LOCK, LOCKT, LOCKU, DELEGRETURN, READDIR, CREATE, REMOVE, RENAME, LINK, SECINFO, EXCHANGE_ID, CREATE_SESSION, DESTROY_SESSION, DESTROY_CLIENTID, RECLAIM_COMPLETE, TEST_STATEID, FREE_STATEID, BIND_CONN_TO_SESSION.

Session / slot table (exactly-once semantics, EOS):

 session = { sessionid:opaque[16], fore_channel_attrs{max_slots, max_req/resp size},
             back_channel_attrs, slot_table }
 slot[i] = { sequenceid:u32, cached_reply:opt, in_use:bool }
 rule: req.sequenceid == slot.sequenceid + 1  → execute, cache reply, bump
       req.sequenceid == slot.sequenceid      → replay cached reply (retransmit)
       req.sequenceid <  slot.sequenceid      → NFS4ERR_SEQ_FALSE_RETRY/MISORDERED
       req.sequenceid >  slot.sequenceid + 1  → NFS4ERR_SEQ_MISORDERED

Slot table replaces v3's DRC for v4.1 (bounded, negotiated, client-driven). highest_slotid lets server/client flow-control concurrency.

stateid = { seqid:u32, other:opaque[12] }. Special values: all-zeros (anonymous), all-ones (READ bypass). seqid bumps on each successful state-changing op on that stateid (I12). other identifies the open/lock/delegation owner-state.

OPEN carries: claim type (CLAIM_NULL new, CLAIM_PREVIOUS reclaim during grace, CLAIM_DELEGATE_CUR/PREV), share access/deny (READ/WRITE/BOTH), open owner, seqid, create flags. Returns a stateid + delegation (maybe). OPEN_CONFIRM exists in v4.0 only (v4.1 confirms via EXCHANGE_ID/sessions). CLOSE releases the open stateid.

Pseudo-fs: server presents a synthetic read-only namespace rooted at PUTROOTFH stitching exports together; clients traverse via LOOKUP without a MOUNT protocol. Export boundaries surface as fsid changes.

Delegations (read, Phase 8): server grants a client authority to cache + serve reads locally without revalidation; server recalls (via back channel, CB_RECALL) when a conflicting OPEN/WRITE arrives. Client must DELEGRETURN promptly. Lease-backed: delegation dies with the lease.

8.8 SMB2/SMB3 (MS-SMB2)

SMB2 header (64 bytes):

 0  ProtocolId    = 0xFE 'S' 'M' 'B'
 4  StructureSize = 64
 6  CreditCharge  (u16)
 8  Status / ChannelSequence (u32)
12  Command       (u16)  16  CreditRequest/Response (u16)
18  Flags (u32)   { SERVER_TO_REDIR, ASYNC, RELATED_OP, SIGNED, PRIORITY, DFS, REPLAY }
22  NextCommand (u32, compound offset)
24  MessageId (u64)        # monotonic per connection
32  Reserved/AsyncId | TreeId (u32)
36  SessionId (u64)
40  Signature (16 bytes)   # HMAC-SHA256 (3.0) / AES-CMAC (3.1.1)

Command set: NEGOTIATE=0, SESSION_SETUP=1, LOGOFF=2, TREE_CONNECT=3, TREE_DISCONNECT=4, CREATE=5, CLOSE=6, FLUSH=7, READ=8, WRITE=9, LOCK=10, IOCTL=11, CANCEL=12, ECHO=13, QUERY_DIRECTORY=14, CHANGE_NOTIFY=15, QUERY_INFO=16, SET_INFO=17, OPLOCK_BREAK=18.

Credits (flow control): each request declares a CreditCharge (≥1, ∝ payload/64KB); server grants CreditResponse; client's in-flight is bounded by granted credits (I11, backpressure per principle 15). Sequence-number window (MessageId) validated against credits.

Compounded requests: chained PDUs via NextCommand offset; RELATED_OP flag = use prior op's FileId/SessionId/TreeId (e.g., CREATE+QUERY_INFO+CLOSE in one round-trip).

Oplock levels: NONE, II (shared read), EXCLUSIVE, BATCH. Lease (2.1+): R, RW, RWH (Read/Write/Handle caching) — finer than oplocks, survives handle close (handle-caching lease). Oplock/lease break: server sends OPLOCK_BREAK notification; client flushes + downgrades + acks before server proceeds.

Durable / persistent handles: CREATE with durable-handle context lets a client reclaim an open after a brief network drop (durable v1/v2) or node failover (persistent, CA shares — deferred). Reconnect via CREATE w/ DurableHandleReconnect context.

SMB3 security: signing (mandatory when negotiated; AES-128-CMAC in 3.0, AES-128-GMAC in 3.1.1), encryption (AES-128-CCM in 3.0, AES-128-GCM in 3.1.1), pre-auth integrity (SHA-512 hash chain over NEGOTIATE+SESSION_SETUP in 3.1.1 to thwart downgrade).

8.9 State machines

NFSv4.1 client lease lifecycle:

 [NoClient] --EXCHANGE_ID--> [ClientId] --CREATE_SESSION--> [Session]
   --(open/lock ops, SEQUENCE renews lease implicitly)--> [Active]
   --RECLAIM_COMPLETE--> [SteadyState]
 [Active] --no SEQUENCE within lease(90s)--> [LeaseExpired]
   --conflicting op arrives--> [Revoked: state freed] --client SEQUENCE--> NFS4ERR_BADSESSION/EXPIRED
   --(client) EXCHANGE_ID again--> [ClientId] (recover)
 server reboot: [Grace(90s): only CLAIM_PREVIOUS/reclaim] --RECLAIM_COMPLETE from all / grace timeout--> [Normal]

SMB oplock break sequence:

 Client A holds EXCLUSIVE oplock on F.
 Client B: CREATE F  --> server detects conflict
   server --OPLOCK_BREAK(EXCLUSIVE→II or NONE)--> Client A   (async or piggybacked)
   Client A: flush dirty data (WRITE), then OPLOCK_BREAK ack with new level
   server: complete B's CREATE; B gets reduced/no oplock
 timeout: A doesn't ack within break-timeout → server force-breaks, may fail A's cached ops

Mount → tree_connect → open (cross-protocol):

 NFSv3:  portmap GETPORT(NFS) → MOUNT MNT(/export) → root fh → LOOKUP* → fh → READ/WRITE
 NFSv4.1: TCP:2049 → EXCHANGE_ID → CREATE_SESSION → PUTROOTFH+LOOKUP* → OPEN → READ/WRITE
 SMB2:   NEGOTIATE → SESSION_SETUP(SPNEGO: NTLMSSP|Kerberos) → TREE_CONNECT(\\srv\share) → CREATE → READ/WRITE → CLOSE → TREE_DISCONNECT → LOGOFF

8.10 Worked examples (time-ordered)

(a) LOOKUP + READ (NFSv3):

 C→S  RPC xid=A1 GETPORT? (skip if cached) ; then LOOKUP{dirfh=ROOT, name="data.bin"}
 S→C  LOOKUP OK {fh=H, obj_attrs, dir_attrs}                       # H minted from (fsid,ino,gen)
 C→S  RPC xid=A2 READ{fh=H, offset=0, count=1048576}
 S→C  READ OK {post_op_attr, count=1048576, eof=false, data=<1MiB>} # zero-copy from page cache
 C→S  RPC xid=A3 READ{fh=H, offset=1048576, count=1048576}
 S→C  READ OK {count=524288, eof=true, data=<512KiB>}              # short read at EOF

(b) UNSTABLE WRITE + COMMIT (NFSv3 async write):

 C→S  WRITE{fh=H, off=0, count=1MiB, stable=UNSTABLE, data} xid=B1
 S→C  WRITE OK {wcc, count=1MiB, committed=UNSTABLE, verf=V0}       # buffered, not fsync'd
 C→S  WRITE{fh=H, off=1MiB, count=1MiB, stable=UNSTABLE} xid=B2
 S→C  WRITE OK {committed=UNSTABLE, verf=V0}
 C→S  COMMIT{fh=H, off=0, count=2MiB} xid=B3
 S→C  COMMIT OK {wcc, verf=V0}                                      # fsync done; verf unchanged → safe
   if reply verf=V1 (≠V0): server rebooted; client MUST resend B1,B2 (buffered data lost)

(c) Silly-rename on open-unlink (NFSv3 client behavior):

 App: open("f") (fh=H, fd held) ; then unlink("f")
 Client: file still open → cannot truly REMOVE (stateless server has no open table)
   C→S RENAME{dir, "f" → ".nfs0000A1B2"}    # silly-rename: hide it, keep inode alive via link count
   App later close(fd) → C→S REMOVE{dir, ".nfs0000A1B2"}   # now actually delete
 Edge: client crash between → orphan .nfsXXXX files (operator cleanup runbook)

(d) Oplock break (SMB): see §8.9 sequence; instrument oplock_break_total{from,to}, break-ack latency.

8.12 DRC state table (xid × proc × client → cached reply)

 key   = hash(client_addr/clientid, prog, vers, proc, xid)
 entry = { key, state:{IN_PROGRESS|DONE}, reply_bytes:opt, ts, size }
 lookup outcomes:
   miss               → insert IN_PROGRESS, execute handler, on completion store DONE+reply
   hit DONE           → return cached reply (replay), refresh LRU ts          # I2
   hit IN_PROGRESS    → duplicate of an op still running → drop (client will retransmit later)
 eviction: LRU when size>cap or count>cap; premature eviction within retention → metric drc_evict_premature_total
 only non-idempotent procs cached (see §8.5 DRC column); idempotent procs bypass

Design principles (§6)

  • Idempotency via Duplicate Request Cache. Non-idempotent ops (REMOVE/RENAME/CREATE-excl/SETATTR-with-guard) executed twice on retransmit corrupt state ("REMOVE then re-REMOVE → spurious ENOENT to a retry that actually succeeded"). DRC keyed by (xid, proc, client-addr/clientid) caches the reply; a duplicate replays it without re-execution. Tradeoff: memory + lookup cost on every op. Operational: DRC hit-rate is a health metric. Violation: clients see phantom errors, double-creates, lost renames.
  • Stable opaque file handles. Handles are server-minted, opaque to clients, and stable: same file → same handle across cache eviction and (v3) server reboot. Encode (export_id, fsid, inode, generation). Tradeoff: generation numbers + persistent fsid cost storage; clients cannot introspect. Operational: ESTALE rate signals handle instability. Violation: clients get ESTALE storms, mounts break, data routed to wrong inode (security hole).
  • Stateless where possible; explicit state recovery where not. v3 server holds no per-client state → reboot is transparent (client retransmits). v4 holds state → must rebuild it via a bounded grace period (reclaim-only). Tradeoff: statelessness simplifies recovery but cannot express locks/delegations correctly. Operational: grace-period status is a dashboard line. Violation: skipping grace → granting new locks before reclaim → split ownership / data corruption.
  • Close-to-open consistency contract. Client revalidates attributes (GETATTR) on open and flushes dirty data on close; concurrent writers are NOT guaranteed POSIX-strong consistency. Tradeoff: weaker than local FS, but enables aggressive caching. Operational: document the contract to users; surprises = bug reports. Violation: drop the flush-on-close → readers see stale data → "my file didn't update" incidents.
  • Crash-only + lease-based recovery. No graceful-shutdown-required code paths; the daemon must recover from kill -9 identically to a clean stop. State is reconstructed from the journal + reclaim. Leases bound how long stale state survives. Tradeoff: every write path must be crash-safe (journaling cost). Violation: assuming clean shutdown → corrupt state after power loss.
  • Defensive XDR/SMB parsing. Every length, offset, count, and array bound on the wire is attacker-controlled and must be validated before allocation or indexing. Never trust a declared length; cap allocations; reject before reserving. Tradeoff: validation branches in the hot path. Operational: parser-reject counters + fuzzing. Violation: the entire memory-safety CVE class (heap overflow, OOM via huge declared array, integer overflow on offset+len).
  • Bounded resources everywhere. Cap READDIR cookies, lock counts, DRC size, open handles, in-flight ops per connection, COMPOUND op-array length, connection count. Reject with a defined error when exceeded. Tradeoff: legitimate heavy clients may hit limits. Operational: every cap has a metric + alert. Violation: a single client OOMs the server (DoS).
  • Wire compatibility is sacred. Once a version is shipped, its wire format never changes; new behavior goes behind new versions/minor-versions/flags. Reference clients (Linux, Windows) are decades-stable and unforgiving. Tradeoff: no field re-purposing; versioning overhead. Violation: a "small" struct change → real clients fail to mount.
  • Authorization at every operation. Never trust an AUTH_SYS uid implicitly; evaluate access per-op against file mode/ACL + export options (root_squash, all_squash, ro). v4/GSS bind identity to a verified credential. Tradeoff: per-op access checks cost cycles. Violation: uid spoofing → arbitrary file access (AUTH_SYS is advisory only; exports + GSS are the real gate).
  • Observability of recovery + coherence events. Stale-handle hits, lease revocations, lock conflicts, oplock/delegation breaks, grace-period transitions, DRC hits — all are first-class metrics + traces. Tradeoff: instrumentation overhead. Violation: "the client hangs sometimes" with no signal → undebuggable production.
  • Path-traversal containment. Path resolution must never escape the export root; .., symlink loops, and absolute symlinks resolved server-side are contained. Tradeoff: resolve symlinks carefully (server-side vs client-side rules differ by protocol). Violation: ../../../../etc/shadow served to a remote client.
  • Single VFS chokepoint for both protocols. NFS and SMB lower to one vfs layer so semantics (handle mapping, access, attr) are identical regardless of front-end. Tradeoff: the VFS must reconcile two protocol models (e.g., SMB share modes vs NFS advisory locks). Violation: divergent behavior → "works over NFS, corrupts over SMB" cross-protocol bugs.
  • Durability is explicit, never implicit. Data is on stable storage only after fsync; COMMIT (v3) / FLUSH (SMB) / WRITE-FILE_SYNC reply means durable. UNSTABLE writes may be lost until COMMIT. Tradeoff: throughput (async) vs durability (sync) is the client's choice, honored exactly. Violation: acking COMMIT before fsync → silent data loss on crash (the cardinal NFS sin).
  • Determinism of error mapping. A given failure always maps to the same protocol error code (errno → NfsStat3 / Nfs4Err / NtStatus), via one table. Tradeoff: none meaningful. Violation: nondeterministic errors → clients misbehave (retry vs fail decisions hinge on exact codes, e.g., NFS4ERR_GRACE vs NFS4ERR_STALE).
  • Backpressure over buffering. When downstream (disk, state lock, client socket) is slow, apply backpressure (credit limits in SMB, in-flight caps in RPC) rather than unbounded queueing. Tradeoff: clients throttle. Violation: unbounded queues → memory blowup → OOM kill mid-operation.
