3. Architectural Overview

3.1 Canonical Architecture Diagram

Show the original text diagram
    agent --remember(obs)--> [mem-ingest] extract facts/entities (LlmIface), dedup, chunk, embed
                                   |  MemoryRecord
                            [mem-store]  WAL + record store (mmap, crash recovery, compaction)
                              |        |          |            |
                       [vec ANN/HNSW][BM25 inverted][recency/temporal][importance]   (mem-index)
                              |________|__________|____________|
                                          |
    agent --recall(query)--> [mem-retrieve] hybrid fusion (RRF) + MMR + rerank hook
                                          |  ranked MemoryRecords
                            [mem-context] token-budget pack -> prompt context --> agent
    background: [mem-consolidate] summarize/reflect/merge/link     [mem-forget] decay/evict/tier/archive
                            [mem-telemetry] taps all paths

3.2 mem-ingest — Write Pipeline Entry Point

  • Responsibilities: accept raw Observation strings; dispatch to LlmIface::extract_facts() and LlmIface::extract_entities(); chunk oversized content; call mem-embed for embedding vector; dedup via content-hash + semantic similarity threshold; write MemoryRecord to mem-store; notify mem-index of new record; push ConsolidationJob to background queue.
  • Concurrency boundary: single-writer channel (tokio::sync::mpsc); multiple callers enqueue Observations; single ingest worker drains the channel sequentially to enforce WAL ordering.
  • Failure modes: LlmIface timeout → store record with embedding_ref: None; dedup collision → return existing MemoryId to caller; store write failure → return MemError::StoreFull / MemError::Io.
  • Invariant: every successfully returned remember() call has a durably fsynced WAL entry before Ok(MemoryId) is returned.

3.3 mem-store — Durable Engine

  • Responsibilities: append-only WAL (segment files, CRC32 per entry, configurable fsync policy); record store (fixed-layout pages, mmap for reads); crash recovery (WAL replay on open, discard trailing partial entries); compaction (background generation sweep, atomic segment swap); snapshots (consistent read view for backup/replica).
  • Persistence boundary: only crate that touches the filesystem (except mem-embed's embedding cache). WAL directory and record-store directory are separate paths; configurable.
  • Concurrency boundary: exclusive write lock via RwLock-protected StoreInner; mmap read path acquires shared lock on active generation; compaction runs on separate thread with generation pointer swap.
  • Invariants: WAL entry order = MemoryId monotonic order; record store is rebuild-from-WAL-capable; compaction never drops a live record; every eviction writes a tombstone to WAL before removal.

3.4 mem-index — Multi-Index Layer

  • Responsibilities: maintain four parallel indices over MemoryRecords: (1) HNSW vector ANN graph (M, ef_construction configurable); (2) BM25 inverted index with per-namespace term statistics; (3) recency/temporal B-tree index keyed by created_at / last_access; (4) importance/salience sorted-set. Plus secondary metadata indices (namespace filter, kind filter, as_of timestamp filter).
  • Protocol boundary: IndexHandle trait exposes insert(), delete(), search(), snapshot(); HNSW backend pluggable (internal pure-Rust impl or FFI to hnswlib).
  • Concurrency boundary: HNSW write serialized; BM25 uses append-only posting-list with background merge; recency and importance indices use BTreeMap behind RwLock.
  • Invariant: index entries and store records never dangle; compaction calls index.delete() atomically with store record deletion; as_of queries filter by created_at ≤ timestamp.

3.5 mem-embed — Embedding Interface + Cache

  • Responsibilities: implement EmbeddingProvider trait backed by LlmIface::embed(); chunk text to model token limit (configurable chunker strategy: sentence / fixed-token / semantic); maintain in-memory LRU embedding cache keyed by content-hash; batch embedding requests for throughput.
  • External interface: LlmIface trait is the only outbound network dependency; implementation can be HTTP REST, gRPC, or local FFI.
  • Failure modes: provider timeout → MemError::EmbedTimeout; dimension mismatch → MemError::DimMismatch; cache miss + provider down → store record without embedding, flag embedding_ref: None, schedule retry via ConsolidationJob.
  • Invariant: embedding dimension D is fixed per namespace at creation; Embedding structs in index are always dimension-D vectors.

3.6 mem-retrieve — Hybrid Retrieval Read Path

  • Responsibilities: accept Query; dispatch in parallel to: HNSW ANN search, BM25 inverted-index search, recency index scan (top-K by last_access + recency_bias), importance index scan (top-K by salience * importance_bias); fuse ranked lists via RRF (k=60 default); apply MMR diversity pass (λ configurable); invoke optional LlmIface::rerank() hook on top-N candidates; return Vec<RetrievalResult>.
  • Concurrency boundary: all four index searches run in parallel (tokio::spawn + join_all); each index provides a snapshot-consistent read handle.
  • Determinism invariant: fixed index state + query → identical ranked set; stable tie-break by score (desc) then MemoryId (asc, ULID order).
  • Failure modes: HNSW search error → fallback to BM25 + recency only; rerank timeout → skip rerank, return RRF-fused result; k > index_size → return all records.

3.7 mem-context — Context-Window Assembler

  • Responsibilities: maintain working-memory ring buffer (MemoryKind::Working, bounded by ContextBudget.max_tokens); accept ranked Vec<RetrievalResult> from mem-retrieve; greedy-pack highest-priority records within token budget (tokenizer via LlmIface::count_tokens()); evict lowest-salience working memories to long-term (mem-ingest write path) when budget exceeded; assemble final prompt context string/blocks.
  • Invariant: assembled context never exceeds ContextBudget.max_tokens; overflow always evicts working memories to long-term before truncating retrieval results; reserved tokens always held back for system prompt.
  • Failure modes: all records exceed budget → return single highest-salience record + truncation marker; LlmIface::count_tokens() unavailable → use character-based approximation (4 chars/token).

3.8 mem-consolidate — Background Consolidation Pipeline

  • Responsibilities: drain ConsolidationJob queue; run summarization (LlmIface::summarize()) on episodic clusters to produce semantic memories; run reflection (LlmIface::reflect()) on recent memory windows to produce higher-order insight records; merge near-duplicate records (cosine similarity > threshold); maintain links: Vec<MemoryId> graph edges; write new consolidated MemoryRecords back through mem-ingest.
  • Concurrency boundary: single background tokio::task; jobs are idempotent (re-runnable on restart); job state persisted in WAL (ConsolidationJob record type).
  • Failure modes: LlmIface call failure → job retried with exponential backoff (max 5 attempts); merge produces duplicate → dedup detects via content-hash, returns existing ID; reflection over corrupted cluster → skip cluster, emit telemetry warning.

3.9 mem-forget — Decay, Eviction, Tiering, Archival

  • Responsibilities: run periodic decay sweep: salience = salience * exp(-λ * Δt); evict records below salience threshold ε (configurable per namespace); enforce TTL (ttl: Option<Duration> field); move cold records to cold-tier (compressed storage or external object store); archive terminal records (write to archival WAL segment, remove from live index).
  • Invariant: every eviction writes a tombstone WAL entry with reason (decay, TTL, explicit forget, budget pressure) before index + store removal; no silent loss.
  • Tiering: hot (mmap + in-memory index), warm (mmap + index but lower priority), cold (compressed on-disk, excluded from default retrieval unless include_cold=true).
  • Failure modes: eviction of record with active links → write orphan-link warning to telemetry, proceed (dangling links are inert, not read); cold-tier write failure → retain in warm tier, emit metric.

3.10 mem-api — Public Agent-Facing Surface

  • Responsibilities: expose AgentMemory struct with remember(), recall(), forget(), reflect(), new_session(), set_namespace(); orchestrate calls across mem-ingest, mem-retrieve, mem-context, mem-consolidate, mem-forget; enforce namespace isolation (NsId plumbed through all calls); provide async Rust API.
  • Trust boundary: caller is the agent process; namespace isolation enforced at this layer; no cross-namespace data leakage.
  • Protocol boundary: pure Rust API (no HTTP, no gRPC at this layer); serialization only for persistence, not for IPC.

3.11 mem-telemetry — Observability Tap

  • Responsibilities: expose tracing spans and metrics counters/histograms for every hot path; per-crate instrumentation hooks (write latency, retrieval latency, index sizes, consolidation job throughput, eviction counts, embedding cache hit rate, WAL segment sizes); Prometheus-compatible export endpoint (optional feature flag).
  • Cross-cutting: taps all crates via tracing::instrument macros and metrics::counter! / metrics::histogram! calls; no crate depends on mem-telemetry (telemetry depends on crates, not vice versa).

8.3 Write Path Sequence (remember())

Show the original text diagram
Agent
  │ remember(obs: Observation, ns: NsId, session: SessionId)
  ▼
mem-api ──validates ns, session──> mem-ingest
  │
  ├─ LlmIface::extract_facts(obs.content) ──> Vec<Fact>
  ├─ dedup_check(content_hash, ns) vs record store
  │     hit  ──> bump access_count, return existing MemoryId (no new record)
  │     miss ──> continue
  ├─ chunker::split(content, chunk_cfg) ──> Vec<Chunk>
  ├─ mem-embed::embed_chunks(chunks) ──> Vec<(ChunkId, Embedding)>
  │     cache hit: skip LlmIface call; cache miss: LlmIface::embed()
  ├─ build MemoryRecord { kind, content, embedding_ref, salience=initial_salience(), ... }
  ├─ mem-store::append_wal(OP_BEGIN_INGEST)
  ├─ mem-store::write_record(record)
  ├─ mem-store::fsync() [per SyncPolicy]
  ├─ mem-index::insert(vec_index, bm25_index, recency_index, importance_index)
  ├─ mem-store::append_wal(OP_RECORD_COMMITTED)
  └─ return Ok(MemoryId)

Failure paths:
  embed failure        ──> OP_INGEST_ABORTED, record not committed, no index mutation
  fsync failure        ──> error propagated, partial WAL entry detected on next recovery
  index insert failure ──> OP_INDEX_PARTIAL logged; repair job scheduled

Timing contract: WAL fsync before returning Ok (strict durability); or per SyncPolicy::Batched(interval) (relaxed, documented trade-off).

8.5 RRF Fusion Formula

RRF_score(d) = Σ_i  w_i / (k_rrf + rank_i(d))

where:
  i ∈ { vec, bm25, recency, importance }
  w_vec         = 1.0 - recency_bias - importance_bias          (≥ 0)
  w_bm25        = 1.0 - recency_bias - importance_bias          (shared with vec, normalized)
  w_recency     = recency_bias  (Query.recency_bias ∈ [0,1])
  w_importance  = importance_bias
  k_rrf         = 60 (default, configurable)

Tie-break: equal RRF score → lower MemoryId (Ulid, lexicographic = chronological).
Invariant: deterministic given fixed index state + query.

8.6 MMR Diversity Reranking

MMR(query q, candidate set S, selected set R, lambda λ):
  score(d) = λ · sim(d, q) - (1-λ) · max_{r∈R} sim(d, r)
  greedily select d* = argmax score(d) from S \ R; add to R; repeat k times.

λ = 0 → max diversity; λ = 1 → pure relevance.
Default λ = 0.5 (configurable per Query).
sim = cosine similarity on Embedding vectors.
Complexity: O(k · |S| · D) where D = embedding dim; acceptable for k ≤ 50, |S| ≤ 200.

8.7 Working Memory & Context Assembly

SessionCtx.working_memory = circular buffer, capacity = cfg.working_mem_cap (default 32 MemoryIds)
ContextBudget { max_tokens: usize, reserved: usize }  → available = max_tokens - reserved

Assembly algorithm (mem-context):
  1. Rank working memories by (salience DESC, last_access DESC).
  2. Greedily pack records until token count would exceed (max_tokens - reserved).
  3. Overflow: evict lowest-priority working memories to long-term (episodic) store.
     - Eviction = append OP_EVICT_TO_LONGTERM(id) to WAL; remove from working_memory buffer.
  4. Append retrieved long-term memories (from recall()) similarly.
  5. Return ContextPacket { items: Vec<MemoryRecord>, tokens_used }.

Invariant: tokens_used ≤ max_tokens always; overflow raises ContextOverflowError not silent truncation.
Edge case: single record > available tokens → error MemError::RecordExceedsBudget(id).

8.8 Consolidation Pipeline

ConsolidationJob kinds:
  Summarize   — group episodic memories by time window / topic → one SemanticMemory
  Reflect     — LlmIface::reflect(memories) → higher-order insight → new SemanticMemory
  Merge       — near-duplicate records (cosine sim > merge_threshold) → single record
  LinkGraph   — extract entity co-occurrence → update MemoryRecord.links

Scheduling: background tokio task, interval-driven; also triggered when
  episodic_count(ns) > cfg.consolidation_trigger_count.

Execution sequence:
  1. ConsolidationScheduler picks job from queue (priority: Merge > Summarize > Reflect).
  2. Lock source records (optimistic: read-only; no write lock on record store).
  3. LlmIface call (summarize / reflect / embed result).
  4. Write new MemoryRecord (kind=Semantic or Procedural).
  5. WAL: OP_CONSOLIDATED(source_ids: Vec<MemoryId>, new_id: MemoryId).
  6. Update indices: insert new, remove/mark source records (tombstone or downgrade salience).
  7. Update MemoryRecord.links on related records.
  8. Release.

Failure modes:
  LlmIface timeout   → job retried with exponential backoff (max 3 retries); sources untouched.
  Partial write      → WAL replay detects OP_BEGIN_CONSOLIDATE without matching OP_CONSOLIDATED → re-run.
  Duplicate reflect  → content_hash dedup prevents identical insight from being stored twice.

ConsolidationJob state machine:

State → Next Condition
Queued Running scheduler picks up
Running Done LlmIface + WAL commit succeed
Running Failed LlmIface error or WAL error
Failed Queued retry_count < max_retries
Failed Abandoned retry_count ≥ max_retries; alert emitted
Done — terminal

8.9 Decay & Forgetting Model

decay_score(record, t_now) =
    w_r · recency(record, t_now)
  + w_s · record.salience.0
  + w_a · access_frequency(record)

recency(r, t) = exp(- λ_r · (t - r.last_access).as_secs_f64() / 86400.0)
  λ_r default = 0.1 (half-life ≈ 7 days for λ=0.1)
access_frequency(r) = min(1.0, r.access_count as f32 / cfg.access_saturation)

w_r + w_s + w_a = 1.0 (configurable; defaults 0.4 / 0.4 / 0.2)

Tiering thresholds (configurable per NsId):
  score > hot_threshold   → Hot (in-memory index + mmap)
  warm_threshold < score ≤ hot_threshold → Warm (mmap only)
  cold_threshold < score ≤ warm_threshold → Cold (file, not mmap-pinned)
  score ≤ cold_threshold  → eviction candidate

Eviction policy (mem-forget):
  1. Collect Cold records where score ≤ cold_threshold OR ttl expired.
  2. Sort by score ASC (lowest first).
  3. Evict until free_target_bytes freed or eviction_list exhausted.
  4. WAL: OP_EVICT(id, reason: {decay|ttl|capacity}, score, ts).
  5. Remove from all live indices.
  6. Write to archive store (optional, per NsPolicy.archive_on_evict).

Invariant: every eviction logged with reason; no silent loss.
TTL: if record.ttl = Some(d) and (t_now - created_at) > d → forced eviction regardless of score.

8.10 WAL Record Layout

WAL segment file: fixed-path  data/wal/{ns_hex}/{seg_id:08}.wal
Header per segment:
  magic:      [u8; 4]  = b"MWAL"
  version:    u16
  segment_id: u64
  created_at: i64 (Unix ns)

Per-entry framing (little-endian):
  entry_len:  u32       (total bytes of payload + crc)
  op_type:    u8        (enum discriminant; see table below)
  payload:    [u8]      (bincode-encoded op-specific struct)
  crc32c:     u32       (covers op_type + payload)

Op codes:
  0x01  OP_BEGIN_INGEST       { ingest_id: Ulid, ns: NsId, session: SessionId }
  0x02  OP_RECORD_COMMITTED   { id: MemoryId, embedding_ref: EmbeddingId, kind: MemoryKind }
  0x03  OP_INGEST_ABORTED     { ingest_id: Ulid, reason: String }
  0x10  OP_TOMBSTONE          { id: MemoryId, reason: ForgetReason, ts: Timestamp }
  0x11  OP_TIER_CHANGE        { id: MemoryId, from: Tier, to: Tier, ts: Timestamp }
  0x12  OP_EVICT              { id: MemoryId, reason: EvictReason, score: f32, ts: Timestamp }
  0x13  OP_ARCHIVE            { id: MemoryId, dest: PathBuf }
  0x20  OP_BEGIN_CONSOLIDATE  { job_id: JobId, source_ids: Vec<MemoryId> }
  0x21  OP_CONSOLIDATED       { job_id: JobId, new_id: MemoryId }
  0x22  OP_CONSOLIDATE_FAIL   { job_id: JobId, reason: String }
  0x30  OP_EVICT_TO_LONGTERM  { id: MemoryId, session: SessionId }
  0x40  OP_SNAPSHOT           { snapshot_id: Ulid, lsn: u64, ts: Timestamp }
  0x41  OP_COMPACTION_DONE    { new_segment: u64, obsolete_segments: Vec<u64> }
  0xFF  OP_CHECKPOINT         { lsn: u64 }

Recovery protocol:
  1. Find last OP_CHECKPOINT; start replay from that LSN.
  2. For each entry: verify CRC32c; skip corrupt entry (log warning + metrics bump).
  3. Apply in order; ignore entries for already-committed records (idempotent).
  4. Any OP_BEGIN_* without matching OP_*_COMMITTED/FAIL → abort that operation.
  5. Rebuild indices from replayed committed records.

8.11 Record Store Layout (mmap)

data/store/{ns_hex}/records.dat   — append-only fixed-slot or variable-length records
data/store/{ns_hex}/embeddings.dat — embedding vectors, aligned to 64 bytes (SIMD)
data/store/{ns_hex}/index/hnsw.bin — HNSW graph serialized
data/store/{ns_hex}/index/bm25.bin — inverted index
data/store/{ns_hex}/index/recency.idx — sorted ring of (created_at, MemoryId)
data/store/{ns_hex}/index/importance.idx — sorted heap of (salience, MemoryId)
data/snapshots/{snap_id}.snap — snapshot (records.dat + index files, linked to WAL LSN)

Record slot in records.dat:
  slot_header: { id: [u8;16], flags: u8, payload_len: u32 }
  payload:     bincode(MemoryRecord) — variable length
  padding:     align to 8 bytes

Flags:
  0x01 = ACTIVE
  0x02 = TOMBSTONED
  0x04 = CONSOLIDATED_SOURCE (kept for provenance, excluded from retrieval)
  0x08 = ARCHIVED

mmap strategy: records.dat + embeddings.dat mapped read-only for retrieval; writes go via pwrite().
Compaction: new file written with only ACTIVE records; atomic rename; WAL OP_COMPACTION_DONE.

8.12 HNSW Index Semantics

Parameters (configurable):
  M       = 16   (max neighbours per node per layer)
  ef_c    = 200  (construction ef)
  ef_s    = 50   (search ef; tunable at query time)
  dim     = embedding dimension (must match model; validated at insert)

Distance: cosine (pre-normalize vectors to unit length → inner product = cosine).
Insert: add_node(embedding_ref: EmbeddingId, vec: &[f32]) → O(log N) amortized.
Search: search_knn(query_vec: &[f32], k: usize, ef: usize) → Vec<(EmbeddingId, f32)>.
Delete: lazy-tombstone in HNSW (set node flag DELETED); periodic background rebuild removes dead nodes.
  Invariant: deleted nodes never returned in search results (filter applied post-search).
Persistence: serialize to hnsw.bin on checkpoint; load on startup; rebuild from embeddings.dat if corrupt.
Concurrent reads: allowed (shared reader lock); writes serialized (exclusive writer lock on HNSW struct).

Edge case: dim mismatch on insert → MemError::DimMismatch { expected, got }.
Edge case: N = 0 (empty index) → search returns empty Vec (not error).

8.13 BM25 Inverted Index Semantics

Tokenizer: Unicode word boundary split + lowercase + stop-word filter (configurable list).
Stemming: optional (Porter stemmer); disabled by default (reproducibility).
Index entry: term → posting_list: [(MemoryId, tf: u32, field_len: u16)]
IDF: ln(1 + (N - df + 0.5) / (df + 0.5))   (Robertson IDF)
TF-norm: (tf · (k1+1)) / (tf + k1 · (1 - b + b · dl/avgdl))   k1=1.2, b=0.75
Score(q, d) = Σ_{t∈q} IDF(t) · TF_norm(t, d)

Updates: insert on commit; delete marks posting entries as tombstoned; compaction removes them.
Persistence: serialized to bm25.bin.
Edge case: query terms not in any document → score 0 for all; RRF rank = ∞ (treated as absent from list).
Pitfall: very short documents inflate TF-norm; field_len tracked per record.

8.14 Namespace Isolation

NsId = hash64(namespace_string)
Each namespace owns:
  - Separate WAL directory: data/wal/{ns_hex}/
  - Separate record store: data/store/{ns_hex}/
  - Separate index files
  - NsPolicy { sync_policy, archive_on_evict, consolidation_enabled, decay_params, max_records }

Cross-namespace: records are never retrievable across namespaces by default.
  Exception: explicit cross-ns link if NsPolicy.allow_cross_ns_links = true.
Isolation invariant: a Query with ns=A never returns records from ns=B.
  Enforcement: all index lookups are ns-scoped; record fetch validates ns field.

Pitfall: ns hash collision (u64) → two namespaces map to same store path.
  Mitigation: log warning + refuse second ns creation if path already claimed by different name.

8.15 Provenance & Link Graph

Provenance { source: SourceId, session: SessionId, derived_from: Vec<MemoryId> }
  source: enum { Agent(AgentId), User, System, Consolidation(JobId) }
  derived_from: populated by consolidation (new record points to source records).

MemoryRecord.links: Vec<MemoryId> — bidirectional association maintained by mem-consolidate.
Link graph traversal: BFS from seed MemoryId, depth-limited (default depth=2).
  Used by: context assembly (pull related memories), reflect job (find clusters).

Invariant: derived_from entries reference valid MemoryIds (not tombstoned at consolidation time;
  subsequent tombstone of a source is allowed — link becomes "stale ref", tracked in link_graph audit).
Pitfall: circular links (A → B → A) possible via consolidation chains; traversal must track visited set.

8.16 Worked Example — Full Lifecycle

t=0: agent calls remember("User prefers dark mode", ns="user:alice", session=S1)

8.18 Failure-Path Sequence: Crash During remember()

Show the original text diagram
Scenario: process crashes after WAL fsync of OP_BEGIN_INGEST but before OP_RECORD_COMMITTED.

Recovery:
  1. WAL replay finds OP_BEGIN_INGEST(ingest_id=I1) with no matching OP_RECORD_COMMITTED.
  2. Classify as INCOMPLETE_INGEST.
  3. Check record store: if record with embedding_ref exists (partial write) → tombstone it.
  4. Check embedding store: if E1 exists orphaned → mark for GC.
  5. Log warning: "Incomplete ingest I1 during recovery; aborted."
  6. Increment metric: recovery_aborted_ingests_total.
  7. System resumes clean; no half-committed record visible to retrieval.

Key: no index was mutated before OP_RECORD_COMMITTED → indices remain consistent.
