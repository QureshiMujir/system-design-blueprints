Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. WAL-first invariant under group-commit: If FsyncPolicy::GroupCommit { interval_ms: 5 } is configured and an agent calls remember() during the 5 ms window, at what point exactly is P1 (Durability Before Acknowledgement) satisfied — and what does remember() return before the fsync fires? Trace the code path from remember() through IngestPipeline::observe() to WalWriter::append() and the group-commit tokio task. What happens if the process dies 2 ms into the window? — §§13, 6.1, 7.1
  2. HNSW recall degradation root cause: Tombstone ratio exceeds 20% on a namespace after a mass forget() operation. Retrieval recall@10 measured by the differential harness drops from 0.92 to 0.71. What is the mechanical cause, and what is the minimum set of operations required to restore recall without dropping any live record? — §§15, 8.13, 7.10, 25
  3. RRF k-parameter sensitivity: An operator sets RRF k=10 (instead of the default 60) on a namespace. Explain what happens to the fusion score distribution, which retrieval lane is most affected, and whether MRR@10 is likely to increase or decrease for a corpus where vector similarity scores are highly concentrated near 0.9. — §§16.2, 8.14, 6.4, 4.2
  4. Consolidation and no-silent-loss: A ConsolidationJob::Merge completes: records A and B are merged into C, A and B marked RETIRED. Immediately after, the process crashes before the WAL MarkRetired entries for A and B are written. On recovery, what is the state of the knowledge graph? Does I2 (No-Silent-Loss) hold? How does the system detect and resolve the inconsistency? — §§20, 7.2, 7.12, 13
  5. Cross-crate invariant enforcement: I4 (Retrieval Determinism) states "identical index state + Query → identical ranked set". A new engineer adds a HashMap<MemoryId, f32> intermediate to the RRF fusion step. Why does this break I4, how would the differential harness in Phase 13 detect it, and what is the minimum code change to restore determinism? — §§16.2, 7.4, 25.2, 6.4
  6. Embedding-record atomicity on compaction: During a compaction cycle, the new records.tmp slab is written, but before the atomic rename, the process crashes. On recovery, which of the three files — wal.bin, records.bin, records.tmp — is authoritative, and what is the recovery algorithm? What invariant protects against a partial records.tmp poisoning the store? — §§13, 6.3, 7.3, 7.8
  7. Context budget and working-memory eviction race: Two concurrent recall() calls race with a remember() that pushes working memory over ContextBudget.max_tokens. The eviction path calls mem-ingest::observe() to persist the evicted record. What locks are held, in what order, and is deadlock possible given tokio::sync::RwLock semantics? — §§19, 7.5, 6.5, 12
  8. BM25 IDF stability at small corpus: A namespace has 20 records at project start. BM25 IDF weights for rare terms are extremely high. After 10,000 records are ingested, the same query returns a different ranked set despite no index reconstruction. Is I4 (Retrieval Determinism) violated? Is this a bug? — §§15, 8.13, 7.4, 6.4
  9. Decay lambda calibration: An operator sets lambda_r = 0.001 (per hour) for a namespace expecting memories to remain relevant for weeks. After 30 days, the hot/warm tier contains 850,000 records and warm-storage WAL is 45 GB. What is the expected decay score for a record last accessed 30 days ago with salience=0.5, access_count=3? How should the threshold be adjusted? — §§21, 8.15, 7.9, 7.11
  10. Reflection amplification: A reflection job over 50 episodic records creates 1 semantic record. That semantic record then becomes eligible for a second reflection cycle, creating another semantic record derived from the first. Over 100 consolidation cycles, what is the maximum chain depth of derived_from links? What prevents unbounded reflection amplification? — §§20, 7.12, 6.10, 8
  11. Namespace quota enforcement: NsQuota { max_records: 1_000_000 } is configured. A burst of 2,000 concurrent remember() calls hits the API. The namespace is at 999,990 records. How many succeed, which fail, what error is returned, and is the quota check atomic? — §§23, 7.7, 6.5, 11
  12. HNSW vs BM25 retrieval disagreement: For query Q, the vector ANN lane returns [A, B, C, D, E] and the BM25 lane returns [F, G, H, I, J] — completely disjoint. What does RRF fusion return? Is this a problem, and what does it indicate about the embedding model and/or the BM25 index? — §§16, 6.4, 8.14, 15
  13. WAL segment rotation and recovery time bound: wal_max_bytes = 512 MB. A WAL segment rotation creates a checkpoint, but the old WAL segment is not yet GC'd. How many WAL segments can accumulate before recovery time exceeds the 30 s target? What is the exact computation, and what configuration parameter controls the upper bound? — §§13, 8.10, 6.2, 4.3
  14. Fuzzing coverage and WAL parser: The cargo-fuzz target wal_replay generates a malformed WAL entry with a valid CRC32c but a len field that claims 4 GB of payload.   15. Differential harness false negative: The differential bench (HNSW vs brute-force kNN) reports recall@10 = 1.0 for all fixture queries. An operator incorrectly concludes the HNSW is perfect. Mental Models & First Principles

MM1 — WAL as the Source of Truth, Store as a Cache

Compressed insight: The record store (mmap slab) is not authoritative — the WAL is. Any in-memory or on-disk record state is derived from a deterministic replay of the WAL. If the store and WAL disagree, the WAL wins.

What it predicts: Compaction can be paused, aborted, or repeated without data loss, because no compaction step destroys WAL entries before a new checkpoint confirms correctness. Recovery time is bounded by WAL segment size, not record store size.

Bug class without it: Engineers treat the record store as the source of truth and optimize it (e.g., in-place mutation of a slot) without writing a WAL entry first. On crash, the mutation is undetectable and the record state is inconsistent. This violates I1 and P2.

Applied in: §13 (Phase 1) WAL layout, §6.2 Crash-Only/Replayability, §7.1 Durability Invariant, §7.8 WAL Append-Only Invariant.

MM2 — HNSW Layers are a Probabilistic Routing Network

Compressed insight: HNSW is a skip-list variant for high-dimensional spaces. Each node appears in zero or more upper layers with exponentially decreasing probability. Upper layers are a coarse routing network; layer 0 is the dense proximity graph. Search always begins at the topmost layer's fixed entry point and greedily descends.

What it predicts: Nodes inserted with a high layer assignment (rare) become long-range connectors that dramatically reduce search path length for all subsequent queries. The ef_construction parameter controls neighbor-candidate set size at build time — too small produces a poorly connected graph; too large slows build without improving recall beyond a ceiling.

Bug class without it: Engineers raise ef_construction indefinitely expecting monotonic recall improvement. After ~300, recall plateaus but build time grows quadratically. Separately, high tombstone ratios (>15%) disconnect routing paths; without this model, engineers don't know why recall degrades without any code change.

Applied in: §15 (Phase 3) HNSW construction, §16.2 (Phase 4) ANN retrieval, ADR-06, PB3 (Malkov & Yashunin 2020).

MM3 — RRF is Score-Scale Agnostic by Construction

Compressed insight: RRF replaces per-result scores with per-result ranks. Because ranks are integers in [1, N], all retrieval lanes contribute equally regardless of whether cosine similarity returns values in [0,1] while BM25 returns unbounded positive reals. The constant k=60 was chosen empirically (Cormack et al. 2009) to dampen the weight of top-ranked results, making the formula robust to one lane completely dominating.

What it predicts: Adding a new retrieval lane (recency, importance) does not require renormalizing any existing lane's scores. A bug that causes BM25 scores to inflate by 100× has zero effect on RRF fusion output.

Bug class without it: Engineers fuse by linear combination of raw scores. BM25 score scale shifts when vocabulary changes (IDF recalculation). The combined score changes, breaking MRR regression tests with no change to the underlying index quality.

Applied in: §16.2 (Phase 4) RRF fusion, §8.14 HybridRetriever, PB4 (Cormack et al. 2009).

MM4 — Embedding-Record Atomicity is a Two-Phase Commit Problem

Compressed insight: Inserting a MemoryRecord requires writing three things: (a) the WAL entry, (b) the record store slot, and (c) the ANN index node. Any subset of these can survive a crash. The only safe crash-recovery protocol is: write WAL first, then record store, then index; on recovery, replay WAL to reconstruct both store and index; detect dangling embedding_refs via mem-cli fsck.

What it predicts: You cannot safely write the embedding to the ANN index before the WAL entry confirms the record. An index node with no corresponding WAL entry cannot be recovered. An embedding_ref in a WAL record with no corresponding ANN node means the record is unretrievable via the vector lane.

Bug class without it: Engineers optimize by writing to the ANN index first (it's fastest). On crash between index write and WAL write, the index contains a vector with no MemoryId in the store. I3 (Embedding–Record Consistency) is violated silently; no error appears until a retrieval returns a MemoryId that the store cannot resolve.

Applied in: §13 (Phase 1) crash recovery, §6.3 Embedding–Record Atomicity, §7.3 Embedding–Record Consistency Invariant.

MM5 — Consolidation Idempotency via derived_from Dedup

Compressed insight: A ConsolidationJob::Summarize over a set of episodic records produces a new Semantic record with Provenance.derived_from listing all source MemoryIds. If the same job replays (crash-restart), the dedup check — "does a record already exist with this derived_from set?" — prevents double-summarization. This makes consolidation a pure function of its inputs.

What it predicts: Consolidation can be safely retried at any point without amplifying the knowledge graph. Reflection records accumulate in derived_from chains that can be traversed to reconstruct any summary's lineage.

Bug class without it: A consolidation job crashes after writing the new Semantic record but before marking the job complete in WAL. On restart, the job replays and creates a second, identical Semantic record. Over time, the knowledge graph accumulates duplicate reflections; semantic retrieval recall degrades because duplicates consume k slots.

Applied in: §20 (Phase 8) SummarizationPipeline, §7.12 Consolidation Idempotency Invariant, I12, PB6 (Sarthi et al. 2024 RAPTOR).

MM6 — Token Budget is a Knapsack with Hard Capacity

Compressed insight: Context assembly is a variant of the 0-1 knapsack problem where items are memory records, weights are token counts, and the capacity is ContextBudget.max_tokens - reserved. The greedy priority heuristic (sort by composite score, greedily pack, skip records that overflow) is O(k log k) and produces near-optimal results because records are small relative to the budget in practice.

What it predicts: A single oversized record (e.g., a verbatim transcript) can exhaust the budget alone. The assembler must detect this case and either truncate the record or skip it (configurable). Lowering reserved increases context richness but reduces LLM headroom for generation.

Bug class without it: Engineers assume records are uniformly small. An agent stores a 10 K token episodic transcript. The assembler packs it as the first item, leaving 0 capacity for any other memories. The agent receives a single giant memory with no cross-reference context, degrading response quality silently.

Applied in: §19 (Phase 7) context assembler, §7.5 Context-Budget Invariant, §6.5 Bounded Resource Usage, PB2 (Packer et al. 2023 MemGPT).

MM7 — Salience Decay is a Forgetting Curve, Not a Timer

Compressed insight: Exponential decay r(t) = exp(-λ·Δt) models the Ebbinghaus forgetting curve: memories fade continuously, not at a discrete expiry point. The composite score D = salience × recency × frequency means high-salience or frequently-accessed records are protected from eviction regardless of age. λ controls the half-life; a record with λ=0.01/hour halves its recency contribution every ~69 hours.

What it predicts: Setting λ too high causes important but rarely-accessed semantic records to fall below eviction threshold quickly. Setting it too low keeps too many stale episodic records in warm storage, bloating the index and degrading retrieval precision. Frequency access patterns can reset effective decay.

Bug class without it: Engineers implement TTL-only eviction. All records older than N days are deleted regardless of access pattern or importance. High-salience semantic knowledge accumulated over months is lost when it hasn't been queried in exactly N+1 days.

Applied in: §21 (Phase 9) decay model, §6.5 Bounded Resource Usage, §7.11 TTL Expiry Invariant, PB1 (Park et al. 2023 recency×importance scoring).

MM8 — Namespace Isolation is a Blast Radius Limiter

Compressed insight: Every operation — WAL entry, record slot, ANN node, BM25 posting — is keyed by NsId. A namespace is not a filter applied at query time; it is a structural partitioning of all storage, indexing, and compaction. Cross-namespace data access requires an explicit join or federation operation (PhaseDeferred 15.x).

What it predicts: A compaction bug in namespace A cannot corrupt namespace B's WAL. A runaway recall query in namespace B cannot exhaust namespace A's index capacity. Namespace deletion is a bounded operation: enumerate all WAL entries with NsId prefix, mark deleted, compact.

Bug class without it: Engineers key records by agent ID only and scope queries via a WHERE clause. A buggy consolidation job in agent X's session writes to a shared inverted index. Agent Y's BM25 recall returns results from agent X's memories.

Applied in: §7.7 Namespace Isolation Invariant, §6.7 Namespace Isolation principle, §23 (Phase 11) namespace management, ADR-12.

Best-Match 25 probabilistic term-weighting scoring function. Inverted index in mem-index evaluates exact/stemmed keyword relevance. Score normalized [0,∞) then mapped to [0,1] via per-namespace max.

{ max_tokens: usize, reserved: usize } invariant: assembled prompt context ≤ max_tokens; overflow triggers working→long-term eviction before LLM call.
ConsolidationJob
Unit of background work (mem-consolidate): one of Summarize/Reflect/Merge/LinkUpdate. Enqueued by scheduler, executed by worker pool.
consolidation
Background pipeline converting episodic memories into higher-fidelity semantic/procedural knowledge via summarization, reflection, and dedup-merge.
decay
Continuous salience reduction over time (exponential / power-law parameterizable). mem-forget applies decay on reads and on periodic sweep; salience dropping below eviction threshold triggers tier demotion.
dedup
Similarity-based duplicate detection in mem-ingest: embedding cosine + exact content hash; near-duplicates → merge provenance, retain higher salience.
durability invariant
A remember() returning Ok is recoverable after crash; WAL fsync must complete before acknowledgement; record store is rebuildable from WAL replay alone.
Embedding
Fixed-dimension f32 vector (dim D, provider-determined). Stored in embedding store via EmbeddingId; never inlined in MemoryRecord.
EmbeddingId
Content-addressed reference ([u8;32] hash of model-id + float bytes) linking a MemoryRecord to its vector in the embedding store.
embedding-record consistency
Invariant: every retrievable record has a valid embedding_ref; index entries and store records never dangle; compaction repairs both atomically in a single WAL batch.
episodic memory
MemoryKind::Episodic — time-stamped autobiographical events anchored to a session. High recency weight; ages into semantic over consolidation cycles.
eviction

forgetting
Controlled removal: TTL expiry, decay-driven eviction, or explicit forget() call. No silent loss invariant: every removal is audit-logged.
fusion (RRF)
Reciprocal Rank Fusion — score(d) = Σ_r 1/(k + rank_r(d)) across component result lists; k=60 default; produces single merged ranking without score normalization.

Hierarchical Navigable Small World graph. ANN index in mem-index; O(log N) insert, approximate k-NN search; configurable M (degree), ef_construction, ef_search.
hybrid retrieval
Parallel execution of vector ANN, BM25, recency, and importance sub-queries; results fused via RRF then diversified via MMR before optional rerank.
importance
Normalized salience of a record, stored in MemoryRecord.salience: Salience(f32 ∈ [0,1]); fed by LLM-assigned score at ingest and updated by access_count and consolidation.
inverted index
BM25 keyword index in mem-index; maps term→posting list (MemoryId, term_freq); used for exact/phrase/stemmed retrieval leg.
LlmIface
Abstract trait (defined in mem-core) for LLM backends: summarize, extract_facts, extract_entities, embed, rerank. All calls are async and may fail; no LLM is embedded in the system.

MemoryKind
enum { Working, Episodic, Semantic, Procedural } — controls decay rate, consolidation priority, retrieval boost weights, and tiering policy.
MemoryRecord
Core unit of storage; full schema in section 11. Immutable after write except for salience, last_access, access_count, and links (all delta-logged via WAL).
MMR (Maximal Marginal Relevance)
Diversity filter post-fusion: iteratively selects next result maximizing λ·relevance - (1-λ)·max_similarity_to_selected; λ ∈ [0,1] from Query.
mmap
Memory-mapped file I/O for read path in mem-store; pages faulted on access; compaction replaces mmap region atomically (double-buffer rename).
namespace
NsId — logical partition; enforces isolation across agents/sessions; all queries, indices, and compaction operations are namespace-scoped.
no-silent-loss invariant
Every eviction, decay, or explicit forget is written to audit log before the record is removed from primary storage; crash between log write and store delete → log replay re-issues delete.
observation buffer
Short-lived in-memory deque in mem-ingest that batches raw agent observations before extraction and ingestion; bounded capacity; back-pressure when full.
procedural memory
MemoryKind::Procedural — how-to knowledge, skills, workflows. Low decay rate; high reuse potential; retrieved on task-matching queries.
Provenance
{ source: String, session: NsId, derived_from: Vec<MemoryId> } — audit trail for every record; required for reflection lineage and deletion cascades.
RRF
See Fusion (RRF).
recency
Temporal proximity score: f(t) = exp(-λ·(now - last_access)) or power-law variant; weight blended into RRF via Query.recency_bias.
reflection
Higher-order memory synthesis: mem-consolidate batches episodic memories, calls LlmIface::summarize, stores result as new Semantic record with Provenance.derived_from links.

{ record: MemoryRecord, score: f32, components: { vec, bm25, recency, importance } } — score is post-fusion; components retained for observability and re-ranking input.

semantic memory
MemoryKind::Semantic — general world/domain knowledge, facts, distilled summaries. Lower recency weight; long TTL or none; primary consolidation output.
snapshot
Consistent point-in-time copy of store + index: WAL flushed, compaction quiesced, files hard-linked or copied; used for backup and cold-start recovery testing.
time-travel
See as-of query.
tiering
Three-tier model: hot (working memory, in-process), warm (long-term, fast mmap), cold (archive, compressed). Promotion/demotion driven by mem-forget decay and mem-context eviction.
TTL
MemoryRecord.ttl: Option<Duration> — wall-clock expiry after created_at; expired records are candidates for immediate eviction on next sweep or read.
ULID
Universally Unique Lexicographically Sortable Identifier; encodes millisecond timestamp + random bits; provides total order without coordination.
WAL
Write-Ahead Log in mem-store; append-only; every mutation (insert, salience-update, link-add, delete) serialized as a WAL entry before being applied to the record store; enables crash recovery by replay.
working memory
MemoryKind::Working — transient in-session context held in mem-context; highest decay rate; evicted to long-term (or dropped) when context budget exceeded or session ends.
