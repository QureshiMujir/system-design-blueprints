Box-by-box. Sources assign event-time and emit Watermark/WatermarkStatus::Idle per-partition (I2, I11; §14 Phase 2); they are the only place Barrier elements originate downstream propagation is in-band with records, never a side channel — the single StreamElement<T> enum is why every operator sees identical record/watermark/barrier ordering per channel (I1, I13). Operator DAG is push-based with bounded per-task mailboxes (P11, §13 Phase 1); each task is single-threaded (I9) so keyed-state mutation never races. State backend is pluggable behind one trait (P6, §16 Phase 4) — the operator code above it is identical whether the backend is a HashMap or RocksDB; only snapshot strategy and access cost differ. Checkpoint coordinator implements Carbone et al. 2015 ABS, not the original Chandy-Lamport channel-recording variant (ADR-08, §17 Phase 5) — the dataflow never stops; the snapshot is copy-on-write and asynchronous (P7, P5). Sinks are exactly-once iff they implement the TwoPhaseCommitSink contract (P4, §18 Phase 6); a sink that writes on every record without 2PC is at-least-once regardless of its label, and the conformance suite's exactly_once_label_audit bucket (§27 Testing & Verification Strategy) enforces this at the type level.

Four cross-cutting properties referenced throughout: (1) watermarks/barriers are first-class stream elements, never side-channels (I1); (2) exactly-once is a barrier-aligned-snapshot cipher — a consistent cut in the Chandy-Lamport sense, taken without halting the dataflow (I3, I4); (3) a sink's exactly-once claim is a contract (2PC), not an adjective (P4); (4) the state backend is swappable without touching operator logic (P6).

8. Domain Model / Protocol / Data Model

8.1 Stream element wire model

Every channel carries one interleaved sequence of the same element kinds (I1, I13): Record{ts, payload} | Watermark(ts) | WatermarkStatus{Active|Idle} | Barrier{ckpt_id} | LatencyMarker{source_id, emitted_at}. Ordering within a channel is FIFO (I13); a Barrier never overtakes a Record emitted before it and vice versa.

8.2 Checkpoint lifecycle (state-transition table)

State On event Next state Side effect
Idle TriggerCheckpoint(n) from coordinator AwaitingBarriers Source snapshots offsets, emits Barrier(n)
AwaitingBarriers Barrier(n) on all N inputs (I4) Aligned Buffered records released in arrival order
Aligned snapshot handed to async subsystem Snapshotting Task resumes processing (P5)
Snapshotting snapshot bytes durably shipped AckPending AcknowledgeCheckpoint(n, handle) to coordinator
AckPending global ack from coordinator Complete NotifyCheckpointComplete(n); 2PC sinks commit (I6)
AckPending NACK / timeout (10 min, §4) Aborted NotifyCheckpointAbort(n); 2PC sinks abort (I6)
Complete / Aborted next TriggerCheckpoint Idle → AwaitingBarriers Cycle repeats at configured interval

8.3 2PC sink lifecycle (state-transition table)

State On event Next state Side effect
NoTxn begin_transaction() at checkpoint n boundary Open Kafka beginTransaction / S3 CreateMultipartUpload
Open invoke(record) Open Buffered/staged into txn n
Open Barrier(n+1) arrives PreCommitted pre_commit: Kafka flush, S3 parts durably uploaded
PreCommitted checkpoint n globally acked Committed commit: Kafka commitTransaction, S3 CompleteMultipartUpload
PreCommitted checkpoint n aborted, or restart before commit Aborted or Re-Committed abort, or idempotent re-commit from checkpointed handle (I6, I14)
Committed/Aborted next barrier NoTxn → Open Cycle repeats every checkpoint interval

8.4 Streaming SQL grammar (EBNF fragment)

create_table   ::= "CREATE" "TABLE" ident "(" column_def { "," column_def } ")" "WITH" "(" kv_pair { "," kv_pair } ")" ;
column_def     ::= ident type [ watermark_clause ] ;
watermark_clause ::= "WATERMARK" "FOR" ident "AS" expr ;
select_stmt    ::= "SELECT" select_list "FROM" from_clause [ "WHERE" expr ] [ group_by_clause ] ;
group_by_clause ::= "GROUP" "BY" window_tvf { "," ident } ;
window_tvf     ::= tumble_tvf | hop_tvf | session_tvf ;
tumble_tvf     ::= "TUMBLE" "(" ident "," interval ")" ;
hop_tvf        ::= "HOP" "(" ident "," interval "," interval ")" ;
session_tvf    ::= "SESSION" "(" ident "," interval ")" ;
interval       ::= "INTERVAL" string time_unit ;

8.5 Worked example — 5-second tumbling word count (trace)

Input (event-time order, BoundedOutOfOrderness(0)): "the"@0ms, "the"@1ms, "quick"@2ms, ... through t=5000ms. Trace: keyBy(word) routes "the" to key-group hash("the") % 128; TumblingEventTimeWindows(5000) assigns window [0,5000); CountAggregator folds incrementally in ReducingState<i64>; at Watermark(5000) the EventTimeTrigger fires (watermark ≥ window.end, I10); output {"the": 2, "quick": 1, ...} for window [0,5000), deterministic from the fixed seed (§12 Phase 0 fixture word_count_5s_tumble.case1).

8.6 Malformed-input example

A WATERMARK FOR ts AS ts + RAND() clause: the expression is not monotone in ts, so the parser's watermark-monotonicity check (§21 Phase 9, fixture sql_watermark_non_monotone.case1) rejects it at deploy-time with SqlError::NonMonotoneWatermark { expr, ts_col } rather than accepting it and producing a runtime watermark-regression violation (I1).

8.7 Failure-path example

A TaskManager crashes mid-AwaitingBarriers for checkpoint 42 (§8.2). The coordinator's 10-minute timeout (§4) fires; checkpoint 42 transitions AwaitingBarriers → Aborted; 2PC sinks with an open txn for 42 call abort() (I6); the JobManager redeploys the failed task from checkpoint 41 (the last Complete state); sources rewind to checkpoint 41's offsets; the dataflow resumes from that consistent cut with at most checkpoint-interval (60 s, §4) of reprocessed — not lost — event-time (fixture chaos.tm_crash_mid_alignment, §17 Phase 5 N.5).

Design principles (§6)

  • P1 — Event-time is the contract; processing-time is a fallback. Every windowing operator, join, and aggregate is specified in event-time. Tradeoff: event-time correctness costs buffering (allowed lateness) that processing-time avoids. Operationally: dashboards built on processing-time drift silently under replay. Violate it and every late-arriving record produces a wrong answer with no error signal (Akidau Streaming 101).
  • P2 — Watermarks are heuristic, monotonic, and configurable — never a completeness guarantee. A watermark claims no record with event_time < wm will arrive; the claim is routinely false. Tradeoff: tighter bounds → more late data; looser → more latency. Operationally: late_dropped_total is the canary metric. Violate it (treat watermark as fact) and late data silently corrupts aggregates.
  • P3 — Idleness detection is mandatory, per-partition. A source silent for idle_timeout_ms emits WatermarkStatus::Idle; downstream excludes it from the output-watermark min (I11). Tradeoff: a false-idle flap on a bursty source briefly over-advances the watermark. Operationally: without this, one stalled Kafka partition halts the whole job's event-time clock. Violate it and a two-input join never fires.
  • P4 — Exactly-once is end-to-end or it is not exactly-once. Requires: replayable source (offsets in checkpoint) + checkpointed operators (state snapshot aligned to barriers) + 2PC sink. Tradeoff: 2PC costs transaction-open latency per checkpoint interval. Operationally: exactly_once_label_audit (§27) enforces the contract at the type level. Violate it (label a non-2PC sink exactly-once) and restarts silently duplicate output.
  • P5 — Barrier alignment is the price of exactly-once with multi-input operators. ABS (Carbone 2015) requires an N-input operator to buffer post-barrier records on channel i until barriers arrive on all N. Tradeoff: alignment latency under skew vs. unaligned checkpoints' larger snapshot size (ADR-09, AA2). Operationally: alignment-time metric per operator. Violate it and the snapshot is not a consistent cut.
  • P6 — Pluggable state backends; operator code never changes. KeyedState<K,V> is implemented identically by InMemoryStateBackend and RocksDBStateBackend (§11). Tradeoff: the interface must be narrow enough to abstract both cheaply. Operationally: backend swap is a config change, not a code change. Violate it (leak RocksDB types into operator code) and the abstraction stops paying for itself.
  • P7 — Incremental snapshots are mandatory once state exceeds ~1 GiB/task. Full snapshots at that size exceed the checkpoint interval (Back-of-Envelope Capacity Model §33). Tradeoff: incremental snapshot bookkeeping (SST manifest chains) vs. full-snapshot simplicity. Operationally: checkpoint.incremental_size_ratio gate (§27). Violate it and checkpoints never complete before the next one is due.
  • P8 — Keyed, operator, and broadcast state are distinct types. Keyed state is partitioned by key-group; operator state is per-task; broadcast state is replicated. Tradeoff: three APIs instead of one. Operationally: mixing them is a compile-time type error, not a runtime surprise. Violate it and rescaling redistributes the wrong state.
  • P9 — Savepoints decouple job lifecycle from infrastructure lifecycle; checkpoints do not. A savepoint is format-stable and portable across code versions and parallelism; a checkpoint is retention-bounded and format-internal. Tradeoff: savepoints are synchronous full snapshots (costlier, rarer) vs. checkpoints' async incremental cost. Operationally: only savepoints are the migration primitive (§20 Phase 8). Violate it (use checkpoints for migration) and an incompatible internal format change breaks it.
  • P10 — Allowed lateness + side outputs make "never silently drop data" achievable, not automatic. A window with allowedLateness(d) retains state d past window.end; records past that go to a side output — never silently dropped (I8). Tradeoff: retaining state longer costs memory. Operationally: deploy-time warning if a non-zero lateness window has no side output. Violate it and late data vanishes with no metric.
  • P11 — Backpressure is credit-based, never blocking-on-socket. Receivers advertise free buffer credit; senders block only when truly out of credit (ADR-04). Tradeoff: credit bookkeeping overhead vs. TCP-level backpressure's head-of-line blocking across unrelated edges. Operationally: the slowest operator becomes the throughput ceiling, by design. Violate it and one slow operator stalls unrelated channels.
  • P12 — Conformance gates, not code review, decide "done." Nexmark Q1–Q12 bit-exact reproduction, Yahoo Streaming Benchmark SLA, Jepsen-style chaos, 30-day soak (§27). Tradeoff: gate infrastructure cost vs. review-only speed. Operationally: a regression in any bucket blocks merge. Violate it and "looks correct" ships silent regressions.
  • P13 — Operator chaining trades isolation for throughput; must be an opt-out, not forced. Same-parallelism Forward-partitioned adjacent operators collapse into one task with a direct call, no network hop (§22 Phase 10). Tradeoff: chaining hides per-operator backpressure isolation. Operationally: disable_chaining() escape hatch. Violate it (force chaining always) and per-operator scaling becomes impossible.
  • P14 — Unaligned checkpoints trade snapshot size for alignment latency; opt-in, never default. Aligned (default) matches ABS as published; unaligned (ADR-09) buffers in-flight records into the snapshot instead of stalling. Tradeoff: larger, more complex snapshots vs. lower tail latency under skew. Operationally: enabled per-job for skew-prone pipelines only (AA2). Violate it (default unaligned) and snapshot sizes balloon unpredictably under normal skew.
