⬜ Phase 0 — Foundations & Correctness Kernel §12

Objectives

Stand up the repository skeleton (§10), the workspace manifest, and a "Hello, runner" vertical slice: parse a one-job pipeline, build a one-node DAG, enqueue, lease, execute under the host-shell executor (allow-listed to /bin/echo only), stream one log chunk, persist the finished WorkflowRun. Establishes I1 (stateless controller) and I3 (event-log-first mutation) before any feature work begins.

Deliverable

make bootstrap && make build && make test && make compose-up brings a working stack; POST /v1/workflows with a two-step shell pipeline runs to completion and its log is retrievable over SSE.

Acceptance

make test passes with the hello.smoke fixture green; make compose-up reaches ready state in ≤ 30 s; the event log for the smoke run replays byte-identically via conformance-runner replay (I3).

Fixtures

corpora/hello/smoke.yaml — one job, one run: echo hello step, expects log hello\n and RunStatus::Succeeded. corpora/hello/ reject_beyond_echo.yaml — a step using any binary beyond the allow-list, expects 400 Bad Request with typed error HostShellDenied.

Pitfalls

Shipping the parser before the workspace skeleton compiles is tempting and costly — a red CI on push 1 burns days debugging toolchain, not algorithm. The host-shell executor is the easiest to ship and the largest remaining attack surface (Threat Model row T5); gate it behind --allow-host-shell from commit one, never widen its allow-list casually.

⬜ Phase 1 — Workflow DSL Parser & CEL Expressions §13

Objectives

Parse the full YAML grammar (apiVersion, triggers, permissions, env, defaults, concurrency, jobs) into PipelineSpec (§11.1); evaluate CEL expressions in if:/concurrency.group:/${{ }} interpolation against a bounded context (I9, P2).

Deliverable

dsl_parser::parse accepts every fixture in corpora/parser/; the PipelineSpec snapshot is byte-stable across builds; runnerctl debug parse <file> pretty-prints the parsed spec.

Acceptance

Parser throughput ≥ 50 MB/s of YAML on the reference host (§19); CEL evaluation ≤ 1 ms per expression on a typical context; 200+ fixtures in corpora/parser/ pass byte-stable, including 30+ malformed-input cases.

Fixtures

corpora/parser/norway.yaml — on: no must parse as string "no", not boolean. corpora/parser/million_laughs.yaml — YAML alias bomb, expects rejection above 1,024 alias refs / 64 KB expanded size (I9-adjacent defense). corpora/parser/missing_digest.yaml — expects ActionMissingDigest.

Pitfalls

A run: | block is a multi-line scalar; the parser must preserve exact bytes including trailing newlines or fixture snapshots silently drift. ${{ }} interpolation happens after YAML parse, on the resulting string — treating it as a YAML construct double-evaluates and breaks escaping.

⬜ Phase 2 — DAG Construction & Matrix Expansion §14

Objectives

Turn PipelineSpec into WorkflowGraph (§11.7): validated edges, topological order, matrix-expanded leaves, static/runtime conditional classification (I8, P3).

Deliverable

dag::build produces a stable WorkflowGraph for every fixture in corpora/dag/; runnerctl debug dag <file> renders Graphviz DOT.

Acceptance

DAG build for a 1,000-job pipeline ≤ 50 ms p99 (M9-adjacent); matrix expansion of a 1,024-coordinate matrix ≤ 10 ms; 100+ fixtures in corpora/dag/ covering diamonds, fan-out, fan-in, matrix-with-needs.

Fixtures

corpora/dag/self_edge.yaml — job a needs a, expects CyclicGraph{cycle_path:["a"]} (§8.1 malformed-input example). corpora/matrix/thousand_coords.yaml — exercises the 1,024 cap boundary.

Pitfalls

A matrix with three 100-value axes generates 1,000,000 combinations before the cap is checked — validate the pre-cap cardinality arithmetically before materializing, never enumerate-then-truncate. A conditional gate false at build time prunes the whole subtree; the UI must render the pruned job Skipped, not hidden (user-visible behavior contract).

⬜ Phase 3 — Scheduler Core §15

Objectives

Single-controller priority-fair-queueing scheduler: per-tenant queues, WF²Q+ fairness (P7), capacity enforcement (I2), preemption, lease lifecycle, anti-starvation.

Deliverable

The scheduler passes every fixture in corpora/scheduler/; runnerctl debug schedule <run-id> prints the decision trace.

Acceptance

Lease decision latency p99 ≤ 5 ms at 10,000 simulated runners / 1,000 tenants (M9); fairness fixture asserts empirical share within 5% of configured weight over 10,000 simulated lease cycles.

Fixtures

corpora/scheduler/fair_10k.yaml — 1,000 tenants, weights [1,100], 10,000 lease cycles, asserts WF²Q+ convergence. corpora/scheduler/ preempt_race.yaml — preemption arriving after step-success report must be ignored (result already committed).

Pitfalls

WF²Q+'s textbook formula has off-by-one behavior at bucket boundaries — carry the proof obligation as inline comments referencing Bennett & Zhang 1996 (§5). A zero-weight tenant is degenerate; reject at registration (I10 bounds [1,100]), never silently treat as weight-1.

⬜ Phase 4 — Runner Protocol & Registration §16

Objectives

Runner agent registration (mTLS), heartbeat, long-poll lease loop, cancellation propagation, byzantine-output quarantine (I11, ADR-27).

Deliverable

The runner agent registers, leases, heartbeats, and cancels correctly against every fixture in corpora/scheduler/ and the byzantine bucket in corpora/byzantine/; mTLS is end-to-end on every gRPC call.

Acceptance

Heartbeat round-trip p99 ≤ 20 ms (M10); lease acquisition on a busy queue ≤ 100 ms p99; all three corpora/byzantine/ fixtures (bad digest, forged log, replayed heartbeat) detected and quarantined.

Fixtures

corpora/byzantine/digest_mismatch.yaml, corpora/byzantine/ forged_log.yaml, corpora/byzantine/heartbeat_replay.yaml — each expects RunnerStatus::Quarantined within one heartbeat cadence.

Pitfalls

A runner crashing mid-step never reports failure; the controller relies solely on heartbeat timeout, so the reclaim window is bounded by heartbeat cadence, not by any runner self-report (design accepts this — P10, no silent fallback that pretends otherwise). A clock-skewed runner appears stale; the agent uses monotonic time for heartbeat cadence and wall clock only for log timestamps.

⬜ Phase 5 — Executor Abstraction §17

Objectives

Implement ExecutorBackend (§11.6) for runc, Firecracker, Kubernetes, Docker (deprecated), host-shell; guarantee cross-executor determinism (P6, I6, ADR-03).

Deliverable

Each executor passes its corpora/executor/<backend>/ fixtures; the executor.cross bucket asserts identical exit code + artifact digests

  • logs (modulo host noise) across all applicable backends for the same fixture.
Acceptance

Job start latency (lease→first step) ≤ 2 s p99 for runc, ≤ 3 s p99 for Firecracker (M1-adjacent); Firecracker boot ≤ 800 ms warm / ≤ 3 s cold (M11); zero divergence in the executor.cross bucket — any divergence is a hard fail (P6 correctness contract).

Fixtures

corpora/executor/cross/divergences/ holds any historically-failing cross-executor fixture with its resolving ADR linked. corpora/ executor/firecracker/boot_budget.yaml asserts the 800 ms boot target.

Pitfalls

runc's user-namespace mapping is subtle — UID 0 inside the container must map to a non-root UID outside, or an in-container sudo is a host root escape (Threat Model row T8). Firecracker requires /dev/kvm; the scheduler must never offer a Firecracker-tagged lease to a KVM-less runner (I6 enforced via RunnerCapabilities.features). Kubernetes Jobs default activeDeadlineSeconds to unset — must be set to the workflow's timeout-minutes or zombie Jobs accumulate.

⬜ Phase 6 — Workspace, Checkout & Artifact CAS §18

Objectives

Fetch source into the executor workspace (sparse/shallow/full clone) and implement the BLAKE3-addressed artifact store (§8.3, I14, ADR-06).

Deliverable

Checkout passes corpora/executor/checkout/ fixtures (sparse, shallow, full, LFS); the CAS passes corpora/artifact/ (upload, download, dedup, retention, tenant isolation).

Acceptance

Shallow checkout of a 100 MB repo ≤ 5 s; full clone of 1 GB ≤ 60 s; artifact upload ≥ 200 MB/s, download ≥ 500 MB/s (M6, M7); dedup hit rate on a representative monorepo fixture ≥ 60% by byte count.

Fixtures

corpora/artifact/dedup_60pct.yaml — asserts the 60% dedup threshold on a fixed corpus. corpora/executor/checkout/force_push.yaml — asserts fetch-by-sha succeeds when the default ref no longer reaches it.

Pitfalls

A monorepo with a large .git benefits from partial clone by default when the server supports it — falling back silently to full clone on unsupported servers must be logged, not silent (P10). A digest collision is computationally infeasible with BLAKE3's 256-bit output, but the index must still handle detection gracefully — on collision, fail the upload with DigestCollision and alert, never overwrite.

⬜ Phase 7 — Cache Layer §19

Objectives

Keyed, scoped, tenant-isolated cache with restore-key fallback and LRU eviction (§8.3, P12, I12).

Deliverable

The cache passes corpora/cache/ fixtures including a three-link restore-key fallback chain and cross-tenant isolation asserted by the byzantine bucket.

Acceptance

Cache lookup latency p99 ≤ 50 ms (M8); download throughput ≥ 500 MB/s (bounded by the CAS, M7); eviction correctly enforced when a tenant's cache exceeds its 10 GB quota in the corpora/cache/quota_evict.yaml fixture.

Fixtures

corpora/cache/restore_chain_3.yaml — primary miss, first restore-key miss, second restore-key hit; asserts cache-matched-key output. corpora/cache/cross_tenant_denied.yaml — asserts 403 Forbidden on a cross-tenant read attempt (I12).

Pitfalls

A cache restoring a corrupted entry is a silent footgun without content addressing — because entries reference a CAS digest and the CAS download re-verifies on read (I14), corruption is always caught, never silently served. Cache-key explosion (every PR mints a unique key) is mitigated by eviction plus a per-namespace cap, not by user discipline alone.

⬜ Phase 8 — Secrets Manager & Log Pipeline §20

Objectives

KMS-backed JIT secret broker with masking and hash-chained audit log (§8.4, P8, I5); append-only log WAL with SSE fanout and durable persistence (P9, I3).

Deliverable

The broker passes corpora/secrets/ (scope, masking); the log pipeline passes corpora/logs/ (streaming, persistence) including a 1 GB log streamed with zero loss and SSE resumption without gap after disconnect.

Acceptance

Secret issuance latency p99 ≤ 50 ms; audit log throughput ≥ 10,000 events/sec; log lag p99 (emit→SSE receive) ≤ 1 s (M4); sustained log throughput per job ≥ 50 MB/s (M5).

Fixtures

corpora/secrets/scope_cross_repo.yaml — a job in repo A requesting a secret scoped to repo B, expects denial. corpora/logs/resume_offset. yaml — client disconnects mid-stream, reconnects with last-seen offset, expects zero gap or duplication.

Pitfalls

A deeply-nested-JSON secret can leak through a pretty-printing logger; the masker must scan raw bytes, not structured fields, or it misses the leak (Threat Model row T3 documents this honestly rather than overclaiming). A KMS rate-limit can stall workflows — the broker caches wrapped secrets per-step for that step's duration only, dropped at step end (never cached across steps, preserving I5's scoped-lifetime guarantee).

⬜ Phase 9 — Approvals, Environments & Retry/Idempotency §21

Objectives

Runtime conditional evaluation, manual-approval environment gates (I13, P13), environment locks, retry/backoff/idempotency (I7, P11).

Deliverable

Approval flow passes corpora/approval/; retry/backoff passes corpora/retry/; environment locks tested under concurrent deploy attempts.

Acceptance

Approval expiry enforced at min(timeout-minutes, approval_window default 24 h); jittered-exponential backoff validated against the AWS-recommended full-jitter formula in corpora/retry/jitter_formula. yaml; non-idempotent retry refused unless explicitly opted in — zero tolerance in the fixture suite.

Fixtures

corpora/approval/expiry_24h.yaml; corpora/retry/non_idempotent_ refused.yaml — asserts a Failed step, not a silent retry, absent opt-in (I7).

Pitfalls

An expired approval is the most common user error — surfaced with a clear typed reason (Failed{ApprovalExpired}), re-triggerable by re-running the workflow, every attempt audit-logged (P13). A retry re-issuing a ScopedToken must audit-log each issuance separately (I5) — collapsing retries into one audit entry loses forensic value.

⬜ Phase 10 — Fleet Autoscaling §22

Objectives

Cluster-API-driven autoscaling with warm-pool floors, scale-to-zero, spot-preemption handling (P14, ADR-09).

Deliverable

The autoscaler passes corpora/autoscale/; cluster-API integration validated against a Kind cluster plus a KubeVirt provider; cold-start latency meets budget on the reference provider.

Acceptance

Cold-start latency p99 ≤ 90 s (M2); warm-pool promotion latency ≤ 5 s; drain latency ≤ 30 s (or the in-flight step's remainder, capped at the workflow timeout).

Fixtures

corpora/autoscale/warmpool_floor.yaml — asserts the configured floor is maintained under load. corpora/autoscale/flap_guard.yaml — asserts hysteresis prevents a scale-up/scale-down oscillation within the 5 min dwell window.

Pitfalls

A flapping autoscaler wastes real provisioning cost — the hysteresis gap (scale-up threshold > scale-down threshold) is not optional tuning, it is the correctness property this phase must ship with. A cluster-API outage stalls scale-up silently unless the controller surfaces Queued{autoscaler_lag} explicitly (P10).

⬜ Phase 11 — Provenance, SLSA/in-toto & Stability Hardening §23

Objectives

Emit signed SLSA Level 3 provenance and in-toto attestations (P4, ADR-11, ADR-12, ADR-25); close the loop with chaos engineering, byzantine-runner emulation, and SLO measurement before Sealed.

Deliverable

conformance/slsa.report.json shows valid signatures for every fixture in corpora/slsa/; the chaos and byzantine buckets are green; all eight SLOs (§26 Operational Readiness) are measured with live dashboards.

Acceptance

SLSA-3 statement signature verifies against Rekor for 100% of corpora/slsa/ fixtures; a 24-hour soak run shows zero growth in any leaked-resource counter (FD count, goroutine/task count, memory RSS); all chaos scenarios in corpora/chaos/ converge within their documented recovery bound.

Fixtures

corpora/slsa/level3_roundtrip.yaml — full sign→verify round-trip. corpora/chaos/controller_restart_mid_schedule.yaml — asserts no dropped or duplicated lease after restart (I1, I3).

Pitfalls

Provenance signed only by the runner is a forgeable claim (Threat Model row T11) — the controller co-sign step is not a defense-in-depth nicety, it is the property that makes Level 2+ meaningful. A 24-hour soak that "looks stable" but leaks one FD per hour is invisible on a 1-hour test — the soak duration is chosen specifically to surface slow leaks.
