34. Back-of-Envelope Capacity Model

Derived from §4 System Constraints; formula shown for each.

  1. Controller ingest bandwidth. M3 (1,000 workflow-accepts/s) × avg parsed PipelineSpec size (~4 KB) = 4 MB/s sustained parse- path ingest — well under a single core's YAML-parse throughput (Phase 1 target ≥ 50 MB/s), confirming M3 is not parser-bound.
  2. Log fan-out bandwidth. M12 (10,000 concurrent runs) × assume 10% actively streaming × M5 (50 MB/s per job) = 50 GB/s peak theoretical fan-out — this is why §18 Phase 6 durable+SSE paths are independent (ADR-08): no single path can be provisioned for this worst case, so the design bounds it via per-tenant log-throughput quota instead (deferred cap, see Register).
  3. RAM for in-flight run state. M12 (10,000 runs) × avg 20 jobs/run × ~2 KB per JobRun in-memory projection = 400 MB controller RAM for hot run state — comfortably inside a single controller replica's memory budget.
  4. Scheduler heap entries. 1,000 tenants (I10 ceiling context) × avg 50 queued jobs/tenant = 50,000 live heap entries — at ~200 bytes/entry, 10 MB, confirming M9 (5 ms p99 decision latency) is achievable on an O(log 50,000) ≈ 16-comparison heap operation.
  5. FD budget per runner host. I4 (≤ 4,096 FDs/executor) × a warm-pool host running up to 4 concurrent step processes (parallel steps, §22-adjacent) = ≤ 16,384 FDs per host — within a standard ulimit -n 65536 ceiling with headroom.
  6. Artifact storage growth per day. Assume 1,000 workflow-accepts/s (M3) × 10% upload an artifact × avg 50 MB artifact × 60% dedup hit rate (§18 Phase 6 N.4 target) discount = 1,000 × 0.1 × 50 MB × 0.4 × 86,400 s = ~172 TB/day raw-before-retention — this number is why retention defaults (30-day logs, tenant-configured artifact retention) are load-bearing cost controls, not just hygiene.
  7. Heartbeat fan-in at 10,000 runners. 10,000 runners × 1 heartbeat/10 s = 1,000 heartbeats/s sustained inbound — well under M9's 5 ms decision-latency budget once phase-randomization (§16 Phase 4 N.7) prevents thundering-herd bunching.
  8. KMS call rate. M3-adjacent: assume 20% of jobs need ≥ 1 secret × 1,000 workflow-accepts/s × 20 jobs/workflow avg × 0.2 = 4,000 KMS- adjacent calls/s worst case — this is why §20 Phase 8 N.6 caches a wrapped secret for a step's duration only (bounded, not indefinite), trading a small cache window for KMS rate-limit headroom.
