The data path is one-way: webhook → parser → DAG → matrix expansion → scheduler → lease channel → runner → executor → log pipeline → durable store, with the only back-edges being the tightly-scoped heartbeat, log, artifact-upload, and provenance-attestation channels (I3). Executor backends are interchangeable behind the ExecutorBackend trait (§11.6); a workflow names runs-on: labels, never an executor directly — the scheduler picks based on workflow trust level and tenant policy (P6). Every cross-cutting service (secret broker, artifact CAS, log pipeline, provenance recorder) is owned by exactly one service behind exactly one gRPC contract (P5); no runner reaches across layers. The controller plane is stateless above the PostgreSQL/object-store/KMS trifecta (I1) — any replica answers any request, and a replica dying mid-job loses no more than one in-flight heartbeat. Trust boundary A (controller) is fully trusted; boundary B (runner) is semi-trusted and every runner output (digests, logs, heartbeats) is independently verified (§24 Threat Model, T2).

8. Domain Model

8.1 Pipeline / Stage / Job DAG

A PipelineSpec (§11.1) contains jobs: Map<JobId, JobSpec>; each JobSpec.needs: Vec<JobId> is a DAG edge. The DAG builder (Phase 2) topologically sorts via Kahn's algorithm into layered order: Vec<Vec <JobId>>; a cycle fails CyclicGraph{cycle_path} at build time (I8). A JobSpec.strategy.matrix expands one logical job into N MatrixCoord leaves sharing the JobId but distinguished by coordinate (§11.7); an if: gate is classified Static (prunable at build time) or Runtime (deferred to step start) per §8.4 below.

State table — RunStatus:

State Entered from Exits to Trigger
Queued (initial) Running, Cancelled scheduler grants first lease
Running Queued AwaitingApproval, Succeeded, Failed, Cancelled job progression
AwaitingApproval Running Running, Failed (expiry) environment gate (I13)
Succeeded Running (terminal) all jobs succeed
Failed Running, AwaitingApproval (terminal) a job fails without continue-on-error
Cancelled any non-terminal (terminal) POST /runs/:id/cancel
Stale Queued Queued, Cancelled max_queue_age exceeded, surfaced to operator

Worked example. A pipeline with jobs: {build, test: {needs:[build]}, deploy: {needs:[test], environment: production}} and test.strategy.matrix.node: [18, 20] builds a 4-node DAG (build, test@18, test@20, deploy) in two layers ([build], [test@18, test@20], [deploy]); deploy enters AwaitingApproval per I13 before its lease is offered.

Malformed-input example. jobs: {a: {needs:[a]}} — self-edge; DAG validator rejects at parse time with CyclicGraph{cycle_path:["a"]} before it reaches the scheduler (I8, §14.8).

Failure-path example. test@18 fails with continue-on-error: false; test@20 (independent leaf) completes; deploy never leases (I13's predecessor-status guard) and the run transitions Running → Failed; the event log (I3) records JobFailed{test@18} then RunTransition{Failed}.

8.2 Executor / Runner Model

RunnerHandle (§11.5) tracks RunnerStatus ∈ {Registered, Idle, Leased, Running, Draining, Offline, Quarantined}. A runner implements ExecutorBackend (§11.6) for whichever backends its RunnerCapabilities advertise (runc, Firecracker, Kubernetes, Docker, host-shell). The scheduler's lease-grant path picks a backend per I6; a runner lacking /dev/kvm never receives a Firecracker-tagged lease.

8.3 Artifact + Cache Model

ArtifactRef (§11.8) and CacheEntry (§11.9) are both indexed by Blake3Digest (I14); the artifact's bytes live at cas/<2-byte-prefix>/ <32-byte-digest> regardless of which ArtifactRef rows point at them (dedup). A CacheKey lookup tries primary exactly, then walks restore_keys in order for a longest-prefix partial match (§8.1 worked example continues in §19.2).

8.4 Secrets Model

A SecretRef{name, scope} resolves to a ScopedToken (§11.10) only at step-start (P8); SecretScope ∈ {Repository, Environment(ref), Organisation, Tenant} and a step's runtime context must match the declared scope or the broker refuses issuance (I5). Every issuance, read, and rotation appends to a hash-chained AuditEvent (§11.11); the chain's hash_chain_prev/hash_chain_self pair makes tampering detectable on replay.

Design principles (§6)

  • P1 — Ephemeral by default. A runner host accepts exactly one job lease and is destroyed after. Violate it → workspace contamination across unrelated tenants; the default executor carries no persisted rootfs. Tradeoff: cold-start cost, mitigated by warm pools (§22).
  • P2 — Hermetic execution is the goal, best-effort is the floor. Every step declares its inputs (workspace digest, cache keys, env, image digest); the executor refuses reads outside declared inputs unless the workflow opts into non-hermetic mode with a logged justification. Violate it → non-reproducible builds, silent supply-chain drift.
  • P3 — Deterministic, replayable runs. A WorkflowRun reconstructs fully from its append-only event log (I3). Violate it → the replay conformance bucket fails and post-incident forensics becomes guesswork.
  • P4 — Signed by construction. Every published artifact is hashed, registered in an in-toto link, and the run's SLSA provenance is countersigned by the controller's KMS key; unsigned = deployment failure, not a warning (ADR-25). Tradeoff: signing latency on the critical path (bounded, §4).
  • P5 — One owner per cross-cut. The secret broker, artifact CAS, log pipeline, and provenance recorder are each owned by exactly one service behind one gRPC contract; no runner reaches across layers. Violate it → the layering that makes the threat model tractable collapses.
  • P6 — The executor you run is not the executor you wrote against. A workflow names runs-on: labels; the scheduler picks the executor from trust level + tenant policy (I6). Violate it → a workflow author can bypass sandboxing policy by fiat.
  • P7 — The scheduler is multi-tenant and fair. Per-tenant weighted-fair-queueing (WF²Q+); no tenant starves another; none exceeds its capacity quota (I2, I10). Violate it → the platform's core economic promise (fair shared infrastructure) breaks.
  • P8 — Secrets are JIT-issued, scoped, and audit-logged. Every secret reference resolves at step start as a short-lived scoped token (I5); issuance is recorded in a hash-chained audit log. A secret leaking into a log is a P0 incident (§24 T3).
  • P9 — Logs are append-only and durable. Runner-side WAL flushes to the controller, which double-writes to SSE fanout and durable object storage (I3). A runner crash loses at most the unflushed tail.
  • P10 — No silent fallbacks. A constraint the system cannot satisfy (capacity, label mismatch, image-pull failure) surfaces as a typed error, never a silently-degraded execution. Violate it → workflows run under unstated assumptions and postmortems cannot reconstruct intent.
  • P11 — Idempotent retries only, by declaration. A retried step reuses the same workspace digest, cache keys, env, and re-issued secret scope; non-idempotent steps refuse retry unless explicitly opted in (I7).
  • P12 — Cache is keyed, scoped, tenant-isolated. A (tenant_id, namespace, primary_key, restore_keys[]) tuple; cross-tenant cache reads are impossible by construction, not by policy (I12, §24 T7).
  • P13 — Approvals and environments are first-class. A deployment to an environment requiring approval cannot proceed without a documented approver and an audit-logged decision (I13); approval is out-of-band, never an in-pipeline script.
  • P14 — The autoscaler scales to zero. A tenant with no in-flight work holds zero runner hosts; warm-pool floors are the configurable cost/latency knob (§22).
  • P15 — Errors carry full context. Every failure surfaces run ID, job ID, step ID, runner ID (if assigned), executor backend, timestamp, trace ID, human explanation, runbook pointer, reproducer hint.
