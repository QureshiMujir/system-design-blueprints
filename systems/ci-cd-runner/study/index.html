32. Mental Models & First Principles

  1. MM1 — A lease is a distributed lock with a deadline, not a promise. The scheduler does not trust a runner to return a lease; it trusts a heartbeat timeout to reclaim it. Predicts: any design that "asks the runner nicely" to give back a lease will eventually leak leases forever. Bug class without it: zombie runners (FM-1) treated as a rare edge case instead of the expected steady-state failure mode. Applied in §15 Phase 3 (lease lifecycle), §16 Phase 4 (heartbeat).
  2. MM2 — Fairness is a scheduling invariant, not a scheduling goal. WF²Q+ bounds unfairness provably (Parekh & Gallager 1993); "try to be fair" designs (round-robin without weights) degrade silently under skewed load. Predicts: an unweighted scheduler will eventually be gamed by the tenant who submits the most jobs. Bug class without it: silent tenant starvation invisible until an SLA complaint. Applied in §15 Phase 3, I10.
  3. MM3 — Content addressing turns "did the byte change" into an O(1) comparison. Once every artifact/cache/log segment is BLAKE3-keyed, corruption and poisoning both reduce to a digest mismatch, not a byte-by-byte audit. Predicts: any store that is not content- addressed will eventually need an ad hoc integrity bolt-on. Bug class without it: silent corruption propagating downstream undetected. Applied in §18 Phase 6, §19 Phase 7, I14.
  4. MM4 — JIT issuance turns "who has this secret" into "who has it right now, provably." A long-lived secret's blast radius is unbounded in time; a JIT-scoped token's blast radius is bounded by one step's duration. Predicts: any static-secret design will eventually be unable to answer "was this secret ever used outside its intended job" from the audit log alone. Applied in §20 Phase 8, I5, P8.
  5. MM5 — Hermeticity is a spectrum with a floor, not a binary. Full Bazel-style action-graph hermeticity is a research-grade stretch; the floor (fresh checkout, pinned image digest, policy-enforced egress) is what ships in Phase 0. Predicts: teams that wait for "full hermeticity" before shipping anything never ship. Applied in §1 Goal & Scope, §12 Phase 0, P2.
  6. MM6 — The executor abstraction is a trust-level router, not a feature switch. runs-on: labels never select an executor directly (P6); the scheduler's policy layer does. Predicts: a design letting workflow authors pick the sandbox directly will eventually have an author opt out of isolation "just this once." Applied in §17 Phase 5, I6.
  7. MM7 — An event log is the only correct source of truth for a state machine that must survive a crash mid-transition. Any in-memory- only WorkflowRun representation is one restart away from an unrecoverable ambiguous state. Predicts: a design that mutates state directly (not append-then-project) will eventually diverge between replicas. Applied in §12 Phase 0, §23 Phase 11, I3.
  8. MM8 — A signature without a trust anchor is theater. A runner-only-signed provenance statement proves the runner said something, not that the controller witnessed it. Predicts: any design accepting self-attestation above Level 1 will eventually be forged by a compromised low-trust component. Applied in §23 Phase 11, T11, ADR-25.

Reference Implementations

  • GitHub Actions Runner (actions/runner) — src/Runner.Listener/ JobDispatcher.cs, src/Runner.Worker/StepsRunner.cs. Lesson: listener/ worker split and the step state machine; pitfall: do not couple the listener's lease loop to worker process lifetime. Applied in §16 Phase 4.
  • GitLab Runner (gitlab-org/gitlab-runner) — executors/ directory, network/ package. Lesson: the custom-executor plug-in contract is the cleanest published executor boundary spec. Applied in §17 Phase 5 (I6).
  • Buildkite Agent (buildkite/agent) — agent/job_runner.go, artifact uploader. Lesson: "process supervision + log streamer + artifact uploader" composition. Applied in §18 Phase 6, §20 Phase 8.
  • Tekton Pipelines (tektoncd/pipeline) — pkg/reconciler/taskrun/. Lesson: leaning on Kubernetes Jobs trades executor flexibility for operational simplicity; pitfall: Job-per-step overhead at high fan-out. Applied in §17 Phase 5 Kubernetes executor, §33 Comparative Architecture Table.
  • Drone CI (harness/drone) — pipeline/runtime/. Lesson: the 0.x→1.x migration replaced a free-form DSL with typed YAML after production incidents from shell-embedding ambiguity. Applied in §13 Phase 1 (ADR-02).

Glossary (§38) · 41 terms · site-wide glossary

ADR
Architecture Decision Record; a locked, numbered decision with rejected alternatives (§9).
Anti-starvation
the scheduler mechanism bumping a job's priority after max_queue_age (§15 Phase 3).
Artifact CAS
content-addressed store for build outputs, keyed by BLAKE3 digest (§18 Phase 6).
Audit log
the hash-chained, append-only record of every secret issuance/read/rotation (§11.11).
Byzantine runner
a runner producing false/forged output (digests, logs, heartbeats); quarantined on detection (I11, T2).
CEL
Common Expression Language; the bounded expression evaluator used in if: and interpolation fields (§13 Phase 1).
Concurrency group
a named serialization key preventing overlapping deploys to the same target (§14.4).
Content addressing
identifying a byte stream by the hash of its contents rather than a location (§8.3, I14).
DAG
Directed Acyclic Graph; the job-dependency structure built from needs: edges (§8.1, §14 Phase 2).
Dedup
deduplication; two artifacts with identical bytes share one stored object (§18 Phase 6 N.2).
Ephemeral runner
a runner host destroyed after exactly one job lease (P1).
ExecutorBackend
the trait abstracting runc/Firecracker/Kubernetes/ Docker/host-shell execution (§11.6).
Fairness (WF²Q+)
the weighted-fair-queueing discipline bounding per-tenant scheduling unfairness (§15 Phase 3, MM2).
Firecracker
the microVM hypervisor used as the default untrusted- workflow executor (§17 Phase 5, ADR-03).
Hermetic execution
a step whose declared inputs fully determine its observable behavior, with no undeclared filesystem/network access (P2).
Idempotent step
a step safely re-runnable with identical inputs and no duplicated side effect (P11, I7).
In-toto
the attestation framework used for supply-chain link/layout documents (§23 Phase 11).
Invariant
a system property enforced structurally, never merely by convention (§7).
JIT issuance
just-in-time secret issuance scoped to one step's lifetime (P8, §20 Phase 8).
JobRun
the runtime instance of a JobSpec, one per matrix coordinate (§11.4).
Lease
a time-bounded grant of one job to one runner (MM1, §15 Phase 3).
Long-poll
the runner's blocking lease-request pattern bounding controller connection churn (§16 Phase 4).
Masking
best-effort redaction of registered secret values from log chunks (§20 Phase 8 N.2, T3).
Matrix expansion
the cartesian-product-plus-include/exclude algorithm producing per-coordinate job leaves (§8.1, §14 Phase 2).
mTLS
mutual TLS; the runner-controller channel authentication mechanism (§16 Phase 4).
PipelineSpec
the parsed, validated, immutable workflow specification (§11.1).
Preemption
cancelling a lower-priority in-flight job to free capacity for a higher-priority one, within a tenant only (§15 Phase 3).
Provenance
a signed statement of what ran, with what inputs, to produce what outputs (§23 Phase 11, P4).
Quarantine
the terminal RunnerStatus for a runner producing byzantine output (I11).
Restore-key fallback
the ordered longest-prefix cache-key match used on a primary-key miss (§19 Phase 7).
Rekor
the Sigstore public transparency log recording every signature (§23 Phase 11, ADR-12).
RunStatus
the top-level WorkflowRun state machine (§8.1 state table).
Scoped token
a short-lived, narrowly-permissioned secret handle issued per step (§11.10, I5).
SLSA
Supply-chain Levels for Software Artifacts; the provenance maturity framework this design targets Level 3 against (ADR-11).
Sparse checkout
fetching only a declared subset of the repository tree (§18 Phase 6 N.2).
Trust boundary
a point in the architecture where the controller stops trusting input at face value (§3, §24 Threat Model).
Tenant
the unit of isolation for scheduling fairness, secrets, cache, and artifacts (P7, P12, ADR-23).
Warm pool
pre-baked, idle runner hosts held ready for instant lease promotion (§22 Phase 10).
WF²Q+
Worst-case Fair Weighted Fair Queueing; the scheduler's cross-tenant fairness algorithm (§15 Phase 3, §5 Papers).
Workspace
the per-job checked-out source tree mounted into the executor (§18 Phase 6).
Zombie runner
a runner stuck Leased with no heartbeat (FM-1, MM1).
