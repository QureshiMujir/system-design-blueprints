34. Back-of-Envelope Capacity Model

Derived step-by-step from §4's System Constraints; formulas shown.

  1. Aggregate spawn throughput, 16-core host. M1 target 5,000,000/sec is single-runtime; on a 16-core host running one 16-worker runtime, per-worker share = 5,000,000 / 16 ≈ 312,500 spawns/sec/worker, each costing ≤ 100 ns (M2) → 312,500 × 100 ns = 31.25 ms of CPU-time/sec/worker consumed by spawn overhead alone, i.e. ≈ 3.1% of one core — leaving ~97% for actual poll work.
  2. Per-task memory footprint at 1M concurrent tasks. RawTask header ≤ 128 bytes (§4) + a typical async fn future body ≈ 200–500 bytes (framework-dependent) → 128 + 350 (avg) = 478 bytes/task × 1,000,000 tasks ≈ 478 MB resident for the task layer alone (excludes application-level data referenced by each future).
  3. Injector capacity vs. burst absorption. Default capacity 1,024 slots (§4); at the M1 spawn rate (5M/sec aggregate) a full injector drains in 1,024 / 5,000,000 sec ≈ 205 µs — i.e. the injector absorbs a burst of at most ~205 µs before backpressuring (I3), which is why the LIFO-local fast path (§14.2) is load-bearing: most spawns must avoid the injector entirely to sustain M1.
  4. Timer wheel memory at 10M pending timers. Each TimerEntry (§11) ≈ 64 bytes (deadline + waker pointer-pair + intrusive links) → 10,000,000 × 64 bytes = 640 MB — this is the dominant memory cost in a timer-heavy workload (e.g., a timer-storm example, §21.5-adjacent) and must be budgeted against the process's total memory ceiling separately from task memory (item 2).
  5. Reactor FD fan-out at the 65,536 budget (§4). At M3's ≤ 1 µs p50 wakeup latency, a fully-saturated reactor dispatching all 65,536 ready FDs in one drive call takes 65,536 × 1 µs = 65.5 ms worst case for that single drive call — this bounds how long the driver thread can be "busy dispatching" before returning to task-polling duty, motivating the drive(timeout) tuning against the cooperative-budget quantum (§22.2).
  6. Blocking-pool thread memory at the 512-thread cap (§4). Default OS thread stack ≈ 2 MB (Linux default) × 512 = 1 GB worst-case resident stack memory if every blocking-pool thread is simultaneously active — a documented sizing consideration for Builder::max_blocking_threads.
  7. Steal latency budget vs. imbalance. M4's ≤ 5 µs p99 steal latency at 50% imbalance, across 16 workers, means a full re-balancing pass (every idle worker successfully steals once) completes in 16 × 5 µs = 80 µs worst case — well under one cooperative-budget quantum's typical wall-clock duration (128 polls × ~20 ns/poll, M5, ≈ 2.56 µs if every poll is a no-op, or proportionally longer for real workloads).
  8. Channel throughput vs. CPU budget. M8's 10M sends/sec bounded mpsc pair, at ≤ 100 ns/send (derived from the same target), consumes 10,000,000 × 100 ns = 1 second of CPU time per second — i.e. a single saturated bounded-channel producer-consumer pair can consume a full core at the target rate, informing capacity planning for channel-heavy pipelines (the pipeline example, §10).
  9. Worker count vs. startup budget. M11's ≤ 5 ms startup for 16 workers means each worker's spawn-and-init cost must average 5 ms / 16 ≈ 312 µs — at the 1,024-worker hard cap (§4), the same per-worker budget would require 1,024 × 312 µs ≈ 320 ms, well past most services' liveness-probe timeout, which is why §4 documents the cap as a safety bound, not a realistic operating point (§31).
  10. Shutdown budget vs. pending-task count. M12's ≤ 100 ms p99 graceful shutdown for ≤10,000 pending tasks implies a per-task drain-and-cancel budget of 100 ms / 10,000 = 10 µs/task — since I7's cancellation transition is CAS-only and allocation-free (I4), this is comfortably above the few-hundred-nanosecond cost of the CAS itself, leaving headroom for the injector/deque drain walk (§15.2).
  11. Loom CI budget vs. state-space size. The 20-minute CI ceiling (§4) split across roughly a dozen loom-gated fixtures (§13.5, §15.5, §17.5, §19.5, §20.5) budgets 20 min / 12 ≈ 1.67 min/fixture at TC 2/3 — this is the concrete constraint that pushes TC 4–16 coverage to shuttle's randomized sampling (ADR-13) rather than exhaustive loom, since loom's state space grows exponentially past TC 3.
  12. Trace overhead vs. throughput ceiling. M10's < 2% steady-state throughput regression budget, applied to the M1 5,000,000 spawns/sec target, caps rt-trace's emission cost at 5,000,000 × 2% = 100,000 "spawn-equivalent" units/sec of overhead — i.e. the non-blocking emission channel (I12) must batch and drain fast enough that its own cost stays under one-fiftieth of the scheduler's own hot-path budget.
