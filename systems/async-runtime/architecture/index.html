Task layer. The task is the unit of accounting, cancellation, scheduling, and tracing (P1). Every other subsystem operates on a type-erased Header pointer, never on the concrete Future. Scheduler. Each worker owns one Chase-Lev deque plus a single-slot LIFO fast path (ADR-04/ADR-19); the global injector is the only cross-thread spawn boundary, sized to bound backpressure (I3). Budget. Every poll call is metered; a task that exhausts its budget is re-queued rather than run to a natural yield point, bounding any one task's monopolization of a worker (P5, I5). Timer wheel. A hierarchical wheel (Varghese & Lauck) gives O(1) insert/cancel independent of pending-timer count (P9). Reactor. A trait boundary, not an embedded dependency (P10, ADR-09); production backends are epoll/kqueue/io_uring, and a test reactor implements the same trait for deterministic unit tests. Sync/channels. Wait-list-based primitives built on the same Waker contract as the task layer — no primitive bypasses the executor's wakeup path. Introspection. A side-channel that observes but never mutates scheduling decisions (I12).

8. Domain Model

8.1 Future / Poll / Waker state machine

enum Poll<T> { Ready(T), Pending }

trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

A Future is a compiler-generated (for async fn) or hand-written state machine; poll advances it exactly one step and either returns Ready(T) (terminal) or Pending (suspended, having registered cx.waker() with whatever it is waiting on). The Waker is the callback contract: whoever holds it after a Pending return must call wake() exactly when the future can make further progress, and the executor must re-poll only after such a call (never spuriously, though spurious wakes are tolerated — a wasted poll, not a correctness bug). Pin<&mut Self> prevents the future's address from moving between polls, which is required because async fn desugaring can produce self-referential structs (a local borrowed across an .await point) — moving such a struct invalidates the internal reference (Turon; "Pin and suffering", §5).

8.2 Task state-transition table (canonical; mirrors I1)

From To Trigger Notes
— Idle spawn() allocates RawTask, returns JoinHandle initial state
Idle Scheduled schedule() called (by spawn or by a wake) pushed onto a worker deque or the injector
Scheduled Running worker dequeues and begins poll exactly one worker at a time (I2)
Running Idle poll returns Pending, no wake arrived during the poll task parks until woken
Running Scheduled poll returns Pending, but a wake arrived during the poll (notified bit set) re-queued immediately, no park
Running Complete poll returns Ready(T) output stored in the output slot
Complete Joined JoinHandle::poll observes Complete, reads output terminal
any Cancelled JoinHandle::drop or AbortHandle::abort() observed cooperatively at the task's next poll (P3)

8.3 Worked example — ping-pong wakeup

Two tasks A and B each hold a oneshot-like slot referencing the other. A's first poll registers its Waker and returns Pending; the scheduler parks A. B's first poll writes to A's slot and calls A_waker.wake(); this CASes A's header Idle→Scheduled and pushes A onto B's worker's deque (P6, local LIFO). The worker's next dequeue pops A (LIFO — cache-hot), polls it; A observes the write, returns Ready. Total round trip: 2 polls, 1 wake, 0 heap allocations (I4), 1 deque push/pop. This is the bench_yield fixture's steady-state path (§30, M6).

8.4 Malformed-input / misuse example

A future whose poll returns Pending without registering any waker (a hand-written bug, not a compiler-generated one) causes the task to park with no one who will ever call wake() — a permanent stall indistinguishable, from the scheduler's view, from legitimate long-idle I/O wait. The conformance fixture waker/no-register-pending.json (§13.5) constructs exactly this future and asserts the task is observably "parked forever" (poll count frozen, no panic, no crash) — the runtime cannot detect this class (I5's budget only bounds running time, not parked time) and the pitfall is documented, not silently corrected (§13.6).

8.5 Failure-path example — panic during poll

A task's future panics inside poll (e.g., an unwrap() on a None). The worker's poll call site wraps every poll in catch_unwind (ADR-24-adjacent hygiene); on catch, the task transitions Running→Complete with the output slot holding an error marker instead of T; the JoinHandle::poll observes this and returns Err(JoinError::Panicked(payload)) instead of Ok(T). The panic does not propagate to the worker thread (which would poison the whole scheduler) — this is the single most load-bearing failure-isolation property of the executor (FM-3, §25).

8.6 Work-stealing scheduler model

Each worker W_i owns a Chase-Lev deque (top = steal end, bottom = owner end) plus a one-slot LIFO fast-path cache. Owner operations (push_bottom, pop_bottom) are wait-free in the uncontended case; a remote steal CASes the top index. State exposed per worker: {local_queue_len, lifo_slot_occupied, parked: bool}. The global injector is a bounded MPMC ring (Vyukov) that every worker drains when its local queue and LIFO slot are both empty, on a periodic check (every 60 local-loop iterations) to bound cross-worker spawn latency without per-iteration injector-check overhead dominating (§15.3).

Worker loop (state names only, no control flow bodies):
  Running-Local  -> pop LIFO slot or deque bottom -> poll
  Local-Empty    -> drain N items from global injector
  Injector-Empty -> pick random remote worker -> attempt steal (half of remote's deque)
  Steal-Failed   -> retry another remote, bounded attempts
  All-Empty      -> park (double-check injector + steal targets first, I11)

8.7 Timer wheel model

An 8-level hierarchical wheel, 64 slots/level, level k's slot width = 64^k ms (level 0 = 1 ms, level 7 ≈ 50 years — see §18 derivation). Insert computes (deadline - now), picks the level from the leading set bit, and links the entry into that level's slot's intrusive doubly-linked list — O(1). Cancel unlinks via the entry's own pointers — O(1), no search. A tick advances the level-0 cursor by one slot (1 ms); every 64 ticks the level-1 cursor advances one slot and that slot's entries are rotated down into level-0 slots based on their now-precisely-known remaining time; the cascade continues up the levels only as often as each level's cursor wraps.

8.8 Reactor model (epoll / kqueue / io_uring)

trait Reactor {
    fn register(&self, source: RawFd, interest: Interest, waker: Waker) -> SourceToken;
    fn deregister(&self, token: SourceToken);
    fn drive(&self, timeout: Option<Duration>) -> usize; // events dispatched
}

epoll (Linux) and kqueue (BSD/macOS) are readiness-based: drive blocks in epoll_wait/kevent up to timeout, and for each ready fd calls the registered Waker. io_uring (opt-in Linux) is completion-based: operations are submitted via an SQE and completion is polled from a CQE — drive here reaps completions rather than readiness notifications, and register maps to submitting an operation rather than watching a descriptor (Stevens's readiness/completion distinction, §5). Both models converge on the same trait boundary because both terminate in "call this Waker" — the divergence is entirely inside drive's implementation, invisible to the task layer (P10).

Design principles (§6)

  • P1 — The task is the unit of accounting. Every poll, wake, spawn, and drop is tracked per task (TaskId); scheduling, cancellation, and tracing all key off the same Header. Tradeoff: extra bookkeeping per task vs. a scheduler that cannot answer "which task is stuck." Violating it: metrics and scheduling drift apart, and rt-trace (§23) cannot attribute stalls.
  • P2 — Wakers are allocation-free reference-counted handles. The RawWaker vtable (clone/wake/wake_by_ref/drop) operates on a pointer-pair into the task's Header; no heap allocation occurs in the wake path. Tradeoff: the header must be #[repr(C)] and manually reference-counted (unsafe). Violating it: a hot I/O loop's steady-state throughput collapses under allocator contention.
  • P3 — Drop is cancellation. Dropping a JoinHandle (or a TaskGroup/Scope going out of scope) signals cancellation; there is no separate .cancel() method. Tradeoff: cancellation is always cooperative and observed only at the next poll — never instantaneous. Violating it (adding a second cancel path) creates two sources of truth for "is this task alive."
  • P4 — Cooperative scheduling is a contract, not a mechanism. A future that never returns Poll::Pending is an application bug; the runtime detects (budget, P5) but does not correct it (no preemption, ADR-06). Violating this expectation (assuming the runtime preempts) causes silent starvation of every other task on that worker.
  • P5 — Fairness is budget-based, not priority-based. Every task gets a fixed poll budget per schedule quantum (I5); exhausting it yields control regardless of task "importance." Tradeoff: a latency-critical task with a long single poll still waits behind budget exhaustion elsewhere. Violating it (skipping budget checks) reintroduces unbounded monopolization.
  • P6 — Work-stealing: LIFO-local, FIFO-remote. Each worker pushes/pops its own deque LIFO (recency = cache-hot); a remote stealer takes FIFO from the opposite end (steals the coldest, least-contended half). Violating the asymmetry (e.g., stealing LIFO) causes stealers to contend with the owner on the same hot end.
  • P7 — Structured concurrency is the default fan-out. TaskGroup/Scope own their children's lifetime; the parent cannot return until every child is joined or cancelled (P3). Tradeoff: a parent's return is blocking on cancellation acknowledgement. Violating it (detached spawn as default) is the "spawn and forget" leak class.
  • P8 — Backpressure is bounded by default. The default mpsc channel and the injector queue are capacity-bounded (I3); unbounded variants are explicitly opt-in and separately named. Violating it silently trades a bounded backlog for unbounded memory growth.
  • P9 — Time is a wheel, not a heap. The hierarchical timer wheel gives O(1) insert/cancel independent of pending-timer count; a binary-heap priority queue is O(log n) and rejected (ADR-05). Violating it at scale (>1M pending timers) degrades tick latency super-linearly.
  • P10 — The reactor is an injected trait, never an embedded dependency. rt-executor-mt imports Reactor, never epoll/kqueue directly; production and test backends are equally valid implementations. Violating it couples the scheduler to one OS's I/O model and makes deterministic testing impossible.
  • P11 — No hidden global state. A Runtime is a value; multiple runtimes coexist in one process; the only process-global state is the (per-runtime) injector, which is itself owned by the Runtime value, not a static. Violating it (a static scheduler) breaks multi-runtime embedding and testing isolation.
  • P12 — Determinism is a first-class test mode, not the default. Runtime::deterministic_test() yields a single-threaded, fixed-poll-order executor for reproducible test failures; the production default is non-deterministic multi-thread scheduling for throughput. Violating it (no deterministic mode) makes flaky concurrency bugs unreproducible.
  • P13 — Send/Sync are earned, not assumed. Runtime is Send but not Sync (internal mutability the design does not want locked); JoinHandle<T> is Send + Sync only when T: Send. Violating it (blanket unsafe impls) reintroduces data races the type system exists to prevent.
  • P14 — Every public panic path and error is typed and documented. JoinError distinguishes Cancelled from Panicked(Box<dyn Any + Send>); no public API silently swallows a panic. Violating it hides application bugs behind runtime "flakiness."
  • P15 — Observability never mutates. rt-trace (§23) reads scheduling state via relaxed loads only, never CAS (I12); a trace crate that "helps" by synchronizing for a cleaner read introduces the exact side-channel bug this principle exists to forbid. Tradeoff: the exported view can be momentarily stale by one CAS window. Violating it turns a passive observer into an accidental scheduling participant.
  • P16 — A dependency is either wrapped or it is load-bearing, never both silently. libc/io-uring syscall bindings are wrapped behind Reactor (ADR-09, P10); nothing outside rt-reactor calls them directly. Tradeoff: one extra trait-dispatch indirection per I/O op. Violating it (a convenience direct call from rt-executor-mt) reintroduces the OS-coupling P10 exists to prevent.
  • P17 — Telemetry cardinality is bounded by design, not by convention. Per-task metrics are aggregated by TaskId bucket before export (ADR-30) rather than emitting one label series per raw TaskId. Tradeoff: individual-task metric resolution is bucketed, not exact. Violating it lets a high-spawn-rate workload silently produce unbounded label cardinality in the metrics backend.
  • P18 — A version is a promise about call sites, not just a number. A MINOR bump never requires a call-site change (§27); only a MAJOR bump may. Tradeoff: some internal simplifications (e.g., Header's bit-packing) must stay flexible enough to never leak into the public contract. Violating it breaks every consumer's trust in SemVer as a safe-upgrade signal.
