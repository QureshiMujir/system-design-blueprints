Decisions (§9) · 32 ADRs

1

Language

Chosen

Rust 2021

Rejected

Go, Java/JVM, C++, Python

When the rejected choice is right

Go wins for the real Grafana/OTel stack: a large team optimizing for contributor velocity + ecosystem (client libs, k8s operators) over the last 5% of p99, with GC tuned (GOGC, ballast) to keep pauses sub-ms — exactly why Loki/Mimir/Tempo are Go, not Rust.

Why: data-plane p99 (no GC); reuse #83/#78/#85; §1.9

2

Workspace

Chosen

Cargo, 13 crates

Rejected

monolith

When the rejected choice is right

A single-crate monolith wins for a one-person prototype or a teaching demo where compile time + cognitive load matter more than enforced layering — the crate boundaries pay off only once parallel teams own ingest vs query vs storage.

Why: ingest↛query↛storage layering

3

Plane split

Chosen

ingest plane ≠ query plane ≠ compactor

Rejected

one process does all

When the rejected choice is right

One all-in-one process wins for the laptop/edge/single-tenant deployment (and is shipped as Plane::AllInOne): below a few hundred k samples/s the plane contention is negligible and one binary is simpler to operate.

Why: stable query p99 under hot ingest (§3.5)

4

Wire / ingest

Chosen

OTLP gRPC + HTTP (protobuf) + scrape

Rejected

bespoke protocol

When the rejected choice is right

A bespoke binary protocol wins for a closed first-party fleet (Datadog/agent-to-backend) where you control both ends and can squeeze 2–3× on the wire (custom framing, columnar batch) without OTLP's generality tax.

Why: the de-facto standard we receive

5

Metrics backend

Chosen

#83 TSDB (Gorilla chunks, WAL, blocks)

Rejected

reimplement

When the rejected choice is right

Reimplementing the TSDB inline wins when the platform needs a metrics-specific feature the #83 ABI can't express (native histograms, out-of-order ingest à la Mimir) and an ABI bump is slower than a fork.

Why: reuse; principle 14

6

Log backend

Chosen

#78 inverted index + #85 columnar body

Rejected

full-text-everything; LSM only

When the rejected choice is right

Full-text-everything (Elastic) wins when arbitrary ad-hoc text search over all fields is the product (log-analytics/SIEM/security) and the user will pay the 5–10× storage + index cost for it — the niche Elastic owns and Loki deliberately abandons.

Why: index labels, columnar body (Loki/Honeycomb lesson)

7

Trace backend

Chosen

append-by-trace_id + trace/search index

Rejected

a relational store

When the rejected choice is right

A relational/columnar store (ClickHouse-backed tracing, e.g. SigNoz/Uptrace) wins when rich analytical span queries (group-by attribute, arbitrary aggregation over spans) matter more than the cheapest possible trace-by-id retrieval.

Why: cheap append + point lookup (Tempo lesson)

8

Correlation key

Chosen

normalized trace_id/span_id + resource_hash

Rejected

per-store ad-hoc joins

When the rejected choice is right

Per-store ad-hoc joins win when the signals are genuinely independent products with no cross-pivot requirement (a standalone metrics SaaS) — there normalizing a global identity is wasted ingest cost.

Why: the unification (principle 1, I1/I2)

9

Exemplars

Chosen

per-(series,bucket) exemplar slots

Rejected

none

When the rejected choice is right

No exemplars wins for a metrics-only deployment with no trace pillar, or where the SDKs don't emit them (pre-OpenMetrics-exemplar instrumentation) — the slot RAM + write cost buys nothing without traces to point at.

Why: metric→trace link (I3)

10

Span→metric

Chosen

deterministic streaming derivation

Rejected

offline batch only

When the rejected choice is right

Offline batch derivation (a nightly Spark job over stored spans) wins when RED/USE need not be live, span volume is huge, and batch is far cheaper per span than the streaming aggregation on the hot path.

Why: live RED/USE, reproducible (I8)

11

Pipeline

Chosen

receiver→batch→transform→relabel→fan-out (bus #58)

Rejected

direct write

When the rejected choice is right

Direct write (receiver → store, no pipeline/bus) wins at low volume or in an embedded agent where the extra hop's latency + memory outweighs decoupling — the OTel SDK's own direct exporter is exactly this.

Why: backpressure + decoupling (principle 4, I4)

12

Backpressure

Chosen

bounded queues + shed/block

Rejected

unbounded

When the rejected choice is right

Unbounded buffering wins only when an upstream durable queue (Kafka) already absorbs the burst and the process is sized so the buffer cannot exceed RAM — i.e. backpressure is delegated to the queue, not the process.

Why: no OOM (principle 4, I4)

13

Sampling

Chosen

tail-based (buffer whole trace) + head

Rejected

head-only

When the rejected choice is right

Head-only sampling wins under a hard memory/latency budget (edge, embedded) or when traces are short-lived and single-process — no buffer, decision at the root, the cost OTel collectors pay to avoid the tail-buffer RAM.

Why: keep error/slow traces (principle 5, I9)

14

Query engine

Chosen

one engine: PromQL/LogQL/trace + joins

Rejected

three separate engines

When the rejected choice is right

Three separate engines win when the pillars are deployed independently (Prometheus + Loki + Tempo as separate services) and cross-signal joins are done in the UI layer (Grafana) rather than the query engine — the actual LGTM topology.

Why: cross-signal joins (principle 2)

15

Query cache

Chosen

#59 distributed cache for results/blocks

Rejected

none

When the rejected choice is right

No cache wins for a write-heavy, query-light deployment (compliance log archive) where queries are rare and a cache is pure overhead + a staleness-correctness risk.

Why: hot-query latency

16

Cardinality

Chosen

per-tenant limits + relabel at ingest

Rejected

unbounded

When the rejected choice is right

Unbounded cardinality wins for a wide-event/columnar store (Honeycomb) whose physical layout is built for arbitrary cardinality — there a hard limit is the wrong tool; the storage model, not a limiter, bounds cost.

Why: the existential bound (principle 3, I6)

17

Storage blocks

Chosen

immutable, atomically published; head+WAL

Rejected

mutable in place

When the rejected choice is right

Mutable-in-place storage (a B-tree/LSM updated live) wins when the workload needs in-place updates/deletes (GDPR per-record erasure of a specific log) that immutable blocks make expensive (whole-block rewrite).

Why: snapshot reads (principle 6, I11)

18

Query determinism

Chosen

snapshot isolation + fixed eval order

Rejected

best-effort

When the rejected choice is right

Best-effort (no fixed eval order) wins when raw throughput trumps bit-exact reproducibility — an exploratory dashboard tolerating last-second sample races for lower query latency, where the determinism machinery is unneeded.

Why: reproducibility (principle 7, I12)

19

Multi-tenancy

Chosen

structural tenant_id partition

Rejected

policy-gated

When the rejected choice is right

Policy-gated isolation (RBAC over shared storage) wins for a single-org internal deployment with no untrusted tenants — there structural partitioning's per-tenant overhead (many small partitions) costs more than a row-level filter.

Why: isolation (principle 8, I10)

20

Retention/rollup

Chosen

compactor: TTL + downsample + rollup

Rejected

keep forever

When the rejected choice is right

Keep forever wins when retention is a legal/compliance requirement (audit, finance) and storage is cheap relative to the cost of having dropped a record someone later subpoenas.

Why: cost (principle 13)

21

Staleness

Chosen

staleness markers + lookback

Rejected

carry-forward

When the rejected choice is right

Carry-forward (last-value) wins for slow-moving gauges (a config value, a capacity limit) sampled rarely, where a stale marker would create spurious gaps and the value genuinely persists between samples.

Why: query correctness (I13)

22

Idempotency

Chosen

dedup on (key, ts)

Rejected

at-least-once dup

When the rejected choice is right

At-least-once with dup wins when downstream aggregation is idempotent anyway (set/last-value semantics) or when the dedup index's RAM is unaffordable at extreme volume — accept dups, dedupe at query time.

Why: exactly-once-ish (I15)

23

Async runtime

Chosen

Tokio (data plane)

Rejected

threads-only

When the rejected choice is right

A thread-per-core/blocking-IO model (Glommio/io_uring, or plain threads) wins for a CPU-bound query node or a small connection count where Tokio's task-scheduling overhead exceeds its concurrency benefit.

Why: high-concurrency I/O

24

Serialization

Chosen

protobuf (OTLP) + bespoke block codec

Rejected

JSON everywhere

When the rejected choice is right

JSON everywhere wins for a debugging/inspection build or a low-volume control API where human-readability + ubiquitous tooling beat the 3–5× size/CPU cost of text encoding.

Why: OTLP standard + compact blocks

25

ABI

Chosen

C ABI + HTTP/JSON query API

Rejected

none

When the rejected choice is right

No external ABI (Rust-only) wins when the platform is consumed solely by other Rust services in-tree — the C ABI's catch_unwind/validation surface is dead weight with no foreign callers.

Why: consumers + dashboards

26

Object store

Chosen

local FS now; S3/GCS deferred

Rejected

S3 now

When the rejected choice is right

S3/object-store from day one wins for a cloud-native multi-AZ deployment where durability + elastic capacity + storage/compute separation (Mimir/Tempo/Loki's real design) outweigh local-FS's lower latency and simpler ops.

Why: scope (PhaseDeferred)

27

Versioning

Chosen

SemVer; OTLP + block versions separate

Rejected

ad hoc

When the rejected choice is right

Ad-hoc/lockstep versioning wins for a single-deployment internal tool upgraded atomically (no mixed-version fleet, no external consumers) where the SemVer + dual-version discipline is ceremony with no payoff.

Why: wire/storage stability (principle 12, I14)

28

Error handling

Chosen

Result<_,ObsError>; codes at ABI

Rejected

panic across FFI

When the rejected choice is right

Panic/abort wins for an internal-only build where an FFI boundary doesn't exist and abort-on-bug gives a cleaner crash + core dump than threading Result through every layer (the "fail fast" stance).

Why: FFI safety (I16)

29

License

Chosen

Apache-2.0

Rejected

GPL

When the rejected choice is right

(A)GPL wins for a project that wants to force SaaS competitors to contribute back or buy a commercial license (the Grafana AGPLv3 / "open-core" move) — copyleft is the right tool when monetization-via-license is the goal.

Why: ecosystem norm

30

Conformance

Chosen

in-mem oracle + PromQL/LogQL/trace diff

Rejected

self-check

When the rejected choice is right

Self-check (assert against the system's own prior output) wins as a fast smoke test in early bootstrap before an oracle exists, or for properties no independent oracle can cheaply compute.

Why: independent truth (principle 14)

31

Repro builds

Chosen

pinned toolchain, lock, SBOM

Rejected

floating

When the rejected choice is right

Floating deps win in early R&D where you want the latest upstream fixes/perf daily and reproducibility/provenance is not yet a requirement — pinning slows the feedback loop before there's anything to attest.

Why: provenance

32

Bench

Chosen

ingest tput + per-signal query p99 + correlation latency

Rejected

criterion-only

When the rejected choice is right

Criterion-only microbench wins for isolating a single hot function's regression (chunk decode, posting intersection) where end-to-end throughput would hide the signal in noise — the right tool for a unit-level perf gate.

Why: the real metrics

38. Alternative Architectures (Roads Not Taken)

Fundamentally different designs for the same system; each with a sketch, the regime where it wins, the real system embodying it, and why this blueprint rejected it.

Alt-A — Federated single-pillar services, correlation in the UI (the LGTM topology).

 OTLP/scrape ─┬─► Prometheus/Mimir (metrics) ─┐
              ├─► Loki (logs) ────────────────┼─► Grafana (UI joins exemplars + trace_id)
              └─► Tempo (traces) ─────────────┘
  • Wins: when each pillar must scale, version, and be operated independently, adopted incrementally, with correlation as a UI convenience. The dominant real-world deployment.
  • Real system: Grafana LGTM (Mimir + Loki + Tempo + Grafana).
  • Rejected because: this blueprint's thesis is that the pivot is a first-class, snapshot-consistent query (§3.4, MM5), not a UI stitch across three independently-snapshotted services; folding correlation into one engine (principle 2) is the teaching goal. (The independent-services regime is captured in ADR-14's "When the Rejected Choice Wins".)

Alt-B — One wide columnar event store (the Honeycomb model).

 OTLP ─► ingest ─► one columnar store of WIDE EVENTS (a span/log = a row with N high-cardinality cols)
                    query = column select/filter/group over events; "correlation" = same-row fields
  • Wins: high-cardinality exploratory debugging where you store all events un-sampled and slice by arbitrary fields; correlation is trivial because every signal is a field on one row.
  • Real system: Honeycomb (and ClickHouse-backed tracing à la SigNoz).
  • Rejected because: a single wide-row layout sacrifices the metric-range scan efficiency of a Gorilla TSDB and the cheap trace-by-id of an append store (§8.4); three native layouts serve three query patterns better, and the cardinality story differs (MM2/MM3). Regime captured in ADR-16's "When the Rejected Choice Wins".

Alt-C — Pull/scrape-centric metrics with head-only sampling, no central pipeline.

 targets /metrics ◄── scrape loop ──► TSDB         (metrics: PULL)
 SDK head-sample ─► trace store directly           (traces: decide at root, no buffer)
  • Wins: under a hard memory/latency budget (edge, embedded, single-tenant) where a central buffering pipeline + tail buffer can't fit; scrape gives target liveness for free and head sampling needs no buffer.
  • Real system: Prometheus (pull) + head sampling in OTel SDKs.
  • Rejected because: push/OTLP is the signal this platform receives (ADR-4) and tail sampling — keeping the interesting (error/slow) traces — is a core teaching objective (§4.2); pull + head-only can't preserve error traces selectively. Regimes captured in ADR-4 and ADR-13's "When the Rejected Choice Wins".

Alt-D — Object-store-native, compute/storage-separated, globally federated (the Cortex/Mimir-at-scale + Monarch shape).

 ingesters (RAM head) ─► object store (immutable blocks) ◄─ stateless queriers (fan-out, cache)
                                  ▲ compactor                 ▲ global query fan-out across regions
  • Wins: cloud-native multi-region scale where elastic, durable object storage + stateless queriers + cross-region federation matter more than local-FS latency and single-binary simplicity.
  • Real system: Grafana Mimir / Cortex (object-store blocks) and Monarch (regional, push-based, planet scale).
  • Rejected (for the Phase-0 build) because: object-store backend and cross-cluster federation are explicitly deferred (§39, ADR-26) to keep the buildable scope to local-FS blocks and a single/small split deployment; the design leaves the seam (immutable blocks, snapshots) so this is an additive path, not a rewrite. Regime captured in ADR-26's "When the Rejected Choice Wins".
