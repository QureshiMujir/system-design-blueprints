32. Mental Models & First Principles

MM1 — PKI moves trust, it does not create it. Every certificate is a signed assertion that some CA vouched for a binding; the whole system's security is the weakest CA a relying party trusts (Ellison & Schneier, 2000). Predicts: adding more CAs to a trust store reduces aggregate security unless each is independently held to the same bar. Bug class without it: treating cross-signing or a new intermediate as a purely administrative act rather than a trust-expansion decision. Applied in §1 (non-goals), §24 (T1/T2), ADR-21.

MM2 — A key that leaves its HSM is a key you must assume is compromised. The whole architecture (P7, I4, I12) is organized entirely around keys that never move. Predicts: any "emergency export" feature request is itself a security regression, not a convenience. Bug class without it: building a "backup the private key to a file, just in case" feature that becomes the actual attack surface. Applied in §9 (ADR-03), §13, §24 (T1, T11).

MM3 — Revocation is the hardest unsolved problem in PKI. Issuance is easy; un-issuing is nearly impossible at internet scale — which is why short-lived certificates win in practice (P14). Predicts: any revocation-freshness promise beyond what CRL/OCSP infrastructure can physically deliver is a false guarantee. Bug class without it: sizing an OCSP responder for average load instead of the freshness-bound-driven worst case (I7). Applied in §18, §19, §31, §36.

MM4 — Detectability is a security property, not an afterthought. CT (P3) doesn't prevent mis-issuance; it makes it discoverable by the whole ecosystem, converting a silent single-CA failure into a public, correctable one. Predicts: a CA without CT submission has a strictly worse security posture even if its issuance logic is bug-free, because it has no external check on that assumption. Bug class without it: treating CT submission as "just an audit nicety" rather than a load-bearing control. Applied in §21, §24 (T6), §6 (P3).

MM5 — Policy and cryptography are separate concerns that must never share a failure mode. A signing bug and an authorization bug are different bugs with different blast radii; conflating them (skipping policy evaluation "just this once" for a fast path) collapses that separation. Predicts: any code path that can reach pki-hsm without first producing a PolicyVerdict is a latent mis-issuance vulnerability regardless of how unlikely it seems. Bug class without it: an "emergency issuance" bypass route added under incident pressure that never gets removed. Applied in §6 (P2), §7 (I3), §15.

MM6 — A CA's trust hierarchy is a distributed system with a single non-redundant root of trust by design, not by accident. Unlike most distributed systems, adding redundant roots does not add resilience — it adds attack surface (MM1). The resilience strategy is instead procedural (ceremony discipline, m-of-n custody) rather than architectural (replication). Predicts: attempting to "solve" root-key availability with active-active root replication is solving the wrong problem. Bug class without it: designing root-key infrastructure using the same replication playbook used for the online tiers. Applied in §3, §14, §36.

MM7 — Every cryptographic protocol boundary is also an audit boundary. RA/CA/VA/ACME separation (P11) exists so that a compromise or bug at one boundary is independently attributable — the audit log (P8) is only as useful as the boundaries it can distinguish between. Predicts: collapsing two boundaries into one process for "simplicity" destroys forensic attributability even if functionality is unaffected. Bug class without it: an incident postmortem that cannot determine whether the RA or the policy engine made the wrong call, because they share one log stream with no boundary markers. Applied in §3, §7 (I3), §26.

MM8 — A validator's false-positive is categorically worse than its false-negative. Rejecting a valid certificate is an availability incident; accepting an invalid one is a security incident that may never be detected (T7, MM4 partially compensates but is not a substitute for correctness). Predicts: every path-validation ambiguity should be resolved by rejecting, never by a permissive default (P6). Bug class without it: a "be lenient for compatibility" patch to pki-path that quietly reintroduces a false-positive risk. Applied in §17 (17.9), §28.

Reference Implementations

  • Boulder (Let's Encrypt) — github.com/letsencrypt/boulder — dirs ca/, ra/, va/, sa/. Lesson: hard RA/CA/VA/storage-authority separation over gRPC. Pitfall: its Go-ORM coupling to a specific schema shape — don't mirror that coupling. Applied in §3, Phase 3 (§14), Phase 8 (§20).
  • step-ca (Smallstep) — github.com/smallstep/certificates — dirs authority/, acme/. Lesson: single-binary CA+ACME integration with JSON-templated certificate profiles. Pitfall: its default config trusts a single online root — do not mirror for a production hierarchy (contradicts P1). Applied in Phase 2 (§14), Phase 8 (§20).
  • CFSSL (Cloudflare) — github.com/cloudflare/cfssl — dirs cli/, signer/. Lesson: clean signer-interface abstraction over local vs. remote (HSM) signing. Pitfall: its JSON profile config permits dangerously permissive default EKU sets. Applied in Phase 4 (§16), §9 (ADR-15).
  • EJBCA (Keyfactor, open edition). Lesson: enterprise CA/RA separation and full CMP/SCEP protocol breadth. Pitfall: complexity explosion from supporting every legacy enrollment protocol simultaneously. Applied in §3, §33.
  • HashiCorp Vault PKI secrets engine — vault/builtin/logical/pki/. Lesson: policy-as-code issuance gating with a short-TTL-first default. Pitfall: co-locates the root CA online by default, contradicting the offline-root principle (P1). Applied in Phase 3 (§14), §36.

Glossary (§38) · 52 terms · site-wide glossary

PKI
Public Key Infrastructure; the full set of roles, policies, and systems needed to create, manage, distribute, and revoke digital certificates.
Certificate Authority (CA)
an entity that signs certificates, vouching for the binding between a public key and an identity.
Root CA
the top-level, self-signed CA; the ultimate trust anchor of a hierarchy.
Intermediate CA
a CA certified by the root, sitting between root and issuing tiers.
Issuing CA
the online CA that signs end-entity (leaf) certificates directly.
Registration Authority (RA)
validates CSRs/identity before forwarding to the CA.
Validation Authority (VA)
publishes revocation status via CRL and/or OCSP.
X.509
the ITU-T standard defining the certificate and CRL format used throughout.
DN (Distinguished Name)
the structured name identifying a certificate's subject or issuer.
SAN (Subject Alternative Name)
an extension carrying additional identifiers (DNS, IP, email, URI) bound to the certificate.
CSR (Certificate Signing Request)
a PKCS#10 structure a requester submits to obtain a certificate.
PKCS#10
the standard defining the CSR format (RFC 2986).
DER (Distinguished Encoding Rules)
the canonical, deterministic subset of ASN.1 encoding used for certificates.
ASN.1 (Abstract Syntax Notation One)
the notation used to define the certificate, CRL, and OCSP message structures.
Trust anchor
a certificate configured as inherently trusted, the terminus of path validation.
Path building
assembling a candidate certificate chain from leaf to trust anchor.
Path validation
RFC 5280 section 6's algorithm confirming a chain is cryptographically and policy-wise acceptable.
Basic constraints
the extension declaring whether a certificate is a CA and its maximum path length.
Name constraints
the extension restricting the namespace a subordinate CA may issue into.
Key usage
the extension restricting the cryptographic operations a key may perform.
EKU (Extended Key Usage)
the extension further restricting a key's application purpose (e.g. serverAuth, clientAuth).
CRL (Certificate Revocation List)
a signed list of revoked certificate serials.
Delta CRL
a CRL listing only entries revoked since a referenced base CRL.
OCSP (Online Certificate Status Protocol)
a real-time certificate-status query protocol.
OCSP stapling
delivering a pre-fetched OCSP response during the TLS handshake itself, per RFC 8446 section 4.4.2.1.
CRLite
a browser-side bulk revocation-distribution mechanism compressing ecosystem-wide revocation state into a compact structure pushed to clients.
Revocation
the act of invalidating a certificate before its natural expiry.
Serial number
the CSPRNG-derived unique identifier of a certificate within its issuer's namespace.
ACME (Automatic Certificate Management Environment)
RFC 8555's protocol for automated certificate issuance.
Challenge
an ACME mechanism proving control over an identifier.
http-01
an ACME challenge type proving control via an HTTP resource.
dns-01
an ACME challenge type proving control via a DNS TXT record.
Certificate Transparency (CT)
RFC 6962's public, append-only log system for issued certificates.
SCT (Signed Certificate Timestamp)
a CT log's cryptographic receipt for a submitted certificate/precertificate.
CT log
an append-only, publicly auditable log accepting certificate submissions.
HSM (Hardware Security Module)
a hardened device that generates and custodies private keys, performing signing without exposing key material.
PKCS#11
the standard interface for interacting with cryptographic tokens/HSMs.
Key ceremony
a scripted, witnessed procedure for generating or activating a root or intermediate key.
m-of-n control
a quorum authorization scheme requiring m of n designated custodians to jointly authorize a sensitive operation.
Cross-signing
having a certificate signed by two different issuing hierarchies to ease a trust-anchor transition.
Short-lived certificate
a certificate with a validity window short enough that revocation checking becomes largely unnecessary.
WebTrust for CAs
the AICPA/CPA Canada audit framework CAs undergo for public trust.
Baseline Requirements (BR)
the CA/Browser Forum's minimum issuance/operations standard for publicly-trusted certificates.
Mis-issuance
issuing a certificate in violation of policy, identity validation, or the requester's actual authorization.
AIA (Authority Information Access)
the extension pointing to the issuer's certificate and/or OCSP responder URL.
CDP (CRL Distribution Point)
the extension pointing to where a certificate's CRL can be fetched.
AKI/SKI (Authority/Subject Key Identifier)
extensions linking a certificate to its issuer's key and identifying its own key, used in path building.
Precertificate
a CT-poisoned, not-yet-final certificate submitted to obtain SCTs before the final certificate is issued.
Policy mapping
an extension permitting an issuer to declare one policy OID equivalent to another for path-validation purposes.
Air gap
physical network isolation preventing any connectivity to a system, used to protect the root CA.
Zeroization
deliberately overwriting sensitive memory (e.g. key material buffers) on release to prevent residual exposure.
Fencing token
a monotonically issued token preventing a stale worker from performing a conflicting operation after a handoff.
