3. Architectural Overview

┌──────────────────────────────────────────────────────────────────────┐
│ Userspace processes (producer / consumer / peer)                     │
└──────────────────────────────┬───────────────────────────────────────┘
                                │ syscall (pipe, shm_open, mq_open, socketpair, sem_open …)
┌──────────────────────────────▼───────────────────────────────────────┐
│ ipc-cap — capability check (I7, P5, P11) gates every op below         │
└──────────────────────────────┬───────────────────────────────────────┘
                                │ authorized handle
┌──────────────────────────────▼───────────────────────────────────────┐
│ IPC objects (per-process FD table → kernel-side object)               │
│  ipc-pipe::{Pipe,Fifo} │ ipc-shm::ShmRegion │ ipc-mq::Mqueue          │
│  ipc-unix-sock::UnixSocket │ ipc-sync::{Semaphore,Mutex,CondVar}      │
│  each implements Pollable + Readable + Writable (ipc-core)            │
└───────────┬─────────────────────────────────────────────┬────────────┘
            │ backpressure signal                         │ readiness state
┌───────────▼──────────────┐                   ┌───────────▼───────────┐
│ ipc-flow — watermark /    │                   │ ipc-notify — epoll-   │
│ FlowController (P8, P9)   │                   │ like readiness        │
│                           │                   │ (blocking/non-block,  │
│                           │                   │ edge/level, §21)      │
└───────────────────────────┘                   └────────────────────────┘

Userspace processes — producers, consumers, and peers; may run at different privilege levels (§20 capability boundary is the trust boundary here). ipc-cap — every syscall entry passes through a capability check before any object is touched or allocated (I7); this is the security boundary. IPC objects — the five primitives, each a distinct kernel-side struct with its own state machine (§8); all implement the three ipc-core traits, which is the concurrency-boundary contract (interior-mutability, &self methods). ipc-flow — every object with an unbounded producer risk reports a watermark; this is the persistence/memory boundary — nothing here is bounded by default without it (P9). ipc-notify — the single readiness surface all five plug into; this is the protocol/queue boundary between "data moved" and "someone was told." All later sections stay consistent with this diagram; type names introduced elsewhere (§11) match the boxes here exactly.

8. Domain Model

8.1 Pipe / FIFO ring buffer

PipeBuffer { page: PageRef, offset: u16, len: u16 }
PageList   { head: Option<Box<PipeBuffer>>, tail: ..., page_count: usize }
States: EMPTY → PARTIAL ⇄ FULL ; per-end: OPEN → (last close) → CLOSED
State Read Write Notes
EMPTY, writers>0 blocks / EAGAIN succeeds reader waits on waiters_read
PARTIAL succeeds succeeds up to PIPE_BUF atomic
FULL succeeds (drains) blocks / EAGAIN writer waits on waiters_write
EMPTY, writers=0 returns 0 (EOF) n/a no writers left
readers=0 n/a EPIPE + SIGPIPE I2

8.2 Shared-memory segment

ShmRegion { id, size, pfn, attached_count, creator, futex_word: AtomicU32 }
States: CREATED → MAPPED(n≥1) ⇄ MAPPED(n-1) → UNLINKED(name gone, pages live while n>0) → FREED(n=0)

The futex_word is the synchronization primitive layered atop the raw shared bytes — the segment itself provides no ordering guarantee (MM2, §32); every mutation protocol built on a ShmRegion must define its own memory-ordering discipline (acquire/release pairs around the futex, per Linux futex(2)).

8.3 Message queue

Mqueue { heap: BinaryHeap<MqMsg>, max_msgs, max_msg_size, waiters }
MqMsg  { priority: u32, data: Bytes }
States: EMPTY → NONEMPTY(<max) ⇄ FULL(=max)

8.4 Unix-domain socket

UnixSocket { kind: Stream|Dgram|Seqpacket, state, recv_buf, send_peer, creds, fds }
States: CLOSED → LISTENING → (accept) → CONNECTED ⇄ HALF-CLOSED → CLOSED

8.5 Semaphore / mutex / condvar

Semaphore { count: AtomicIsize (≥0, I11), waiters }
Mutex     { owner: AtomicOption<Tid>, waiters }   // I12
CondVar   { generation: AtomicU32, waiters }

Worked example (pipe + epoll producer/consumer): producer writes 4 KiB records to a pipe; consumer registers the pipe's read end with ipc-notify in level-triggered mode. Each write ≤ PIPE_BUF is atomic (I3); the consumer's epoll_wait-equivalent returns immediately whenever bytes are resident; consumer reads until EAGAIN, then re-waits.

Malformed-input example: mq_send with a 2 MiB payload against a queue configured with mq_msgsize = 1 MiB is rejected atomically with EMSGSIZE before any heap mutation (I13) — conformance fixture mqueue/oversize.fixture.

Failure-path example: a socket's peer crashes mid-write holding two SCM_RIGHTS FD references in-flight; on socket-close cleanup, ipc-unix-sock walks the queued-message list and decrements every FD reference (I6) before the socket object is freed — this is the unix_destruct_scm-equivalent path (§5 Linux reference implementation).
