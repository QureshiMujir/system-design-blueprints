Base model box — loaded once, read-only for the life of the process; requires_grad=False is set at injection time, not merely "by convention" (I1, §7). Replacer/freeze box — the only code path permitted to mutate the module tree; installs one of LoraLinear / AdaLoraLinear / DoraLinear / IA3Linear per matched target module (§11, §14). Chat template box — a pure function from (conversation, tokenizer) to (input_ids, labels); the template name travels with the checkpoint, never with the base model card (P3, §6). Training driver box — never re-implements AMP/accumulation/clipping (P12, §6); the concurrency boundary is exactly rank-114's TrainingLoop internals, opaque to this project. Checkpoint box — the persistence boundary; the only artifact written to durable storage by default is adapter tensors + metadata (P9, §6). Merge box vs. AdapterStore box — the two production exit paths: merge trades hot-swap flexibility for zero-overhead single-tenant inference; the store trades a small per-token overhead for many-tenants-per-GPU (§38, Alt discussion). All later sections stay consistent with this diagram; a section that contradicts a box here is a defect.

8. Domain Model

Low-rank adapter equation (LoRA, Hu et al. 2021). For a frozen linear y = Wx with W ∈ R^{out×in}, the adapted forward is:

y = W x + s · B (A x)              s = α/r  (default)  or  α/√r  (rsLoRA, ADR-03)
A ∈ R^{r×in}   (down-projection, Kaiming-init)
B ∈ R^{out×r}  (up-projection, zero-init — I3, P13)

Merge / unmerge (P5, I6).

merge:    W' = W + s·B@A                      (in place, destructive; original W discarded
                                                unless the caller preserves it)
unmerge:  W  = W' - s·B@A                     (requires the original A, B retained)

AdaLoRA SVD-form (Zhang et al. 2023). BA is reparameterized as P · diag(E) · Q with P ∈ R^{out×r}, E ∈ R^{r} (learned singular values), Q ∈ R^{r×in}. The importance score per singular index k is an EMA of |E_k · ∂L/∂E_k|; every N steps the bottom-k% indices by importance are zeroed and excluded from future gradient updates (I11 enforces the resulting rank never grows back).

DoRA decomposition (Liu et al. 2024). V = W + s·BA (the LoRA-augmented direction); W_eff = m ⊙ (V / ‖V‖_c) where m is a learned per-column magnitude vector initialized to ‖W‖_c (column norm of the original base weight, ADR-09) and ‖·‖_c is the column-wise norm. LoRA is applied to the direction term only; the magnitude is a separate, small (out_features) trainable vector.

IA3 (Liu et al. 2022). Three learned per-channel scale vectors l_k, l_v, l_ff, applied element-wise to the key projection output, the value projection output, and the FFN intermediate activation respectively: y = W x ⊙ l. No rank decomposition, no A/B pair.

NF4 quantization (Dettmers et al. 2023). Each weight block of 64 elements is quantized to a 4-bit NormalFloat code via a fixed lookup table NF4[0..15] chosen so each code is equiprobable under a zero-mean unit-variance normal; per-block absmax is stored in fp32 (or, under double quantization, itself 8-bit-quantized in blocks of 256, cutting the effective constant overhead from 0.5 to 0.127 bit/parameter). Dequantization at forward time is w ≈ absmax · NF4[code].

Training-loop state machine.

State Entry Condition Exit Transition
INIT process start → LOAD_BASE
LOAD_BASE base checkpoint resolved → FREEZE_BASE
FREEZE_BASE model_prep.freeze applied → INJECT_ADAPTERS
INJECT_ADAPTERS replacer has wrapped all target modules (I1 holds) → BUILD_OPTIMIZER
BUILD_OPTIMIZER optimizer built from requires_grad filter (I2 holds) → TRAIN_STEP
TRAIN_STEP micro-batch forward+backward complete → ACCUM_GRAD or OPTIM_STEP
ACCUM_GRAD accumulation count < target → TRAIN_STEP
OPTIM_STEP accumulation count == target, I8 holds → SCHED_STEP
SCHED_STEP LR updated → EVAL_STEP (cadence hit) or TRAIN_STEP
EVAL_STEP held-out loss computed (I13 holds) → CHECKPOINT_STEP (cadence hit) or TRAIN_STEP
CHECKPOINT_STEP adapter-only save complete (P9) → TRAIN_STEP or FINALIZE
FINALIZE max steps reached → DONE
DIVERGED I8 violated 3× consecutively (FM-1) → ROLLBACK_TO_LAST_CKPT
OOM CUDA OOM raised (FM-2) → REDUCE_BATCH_OR_ENABLE_GRAD_CKPT

Worked example. Rank-8 LoRA on q_proj (in=out=4096): trainable params per instance = 2·r·in = 2·8·4096 = 65,536, versus the full matrix's 4096·4096 = 16,777,216 — a 256× reduction per matrix (generalized in §36 #1 to the whole model).

Malformed-input example. A dataset row {"instruction": "...", "output": null} (missing completion) fails dataset.formats schema validation and raises SchemaValidationError; conformance fixture bad_row_missing_output.jsonl (§13.5) asserts the loader rejects it rather than silently emitting an empty-label example.

Failure-path example. A model_prep.replacer regression that wraps a target module without clearing requires_grad on its base weight is caught by I1's step-0 param-scan before step 1 runs; the run halts with FreezeViolationError("base_model.layers.7.self_attn.q_proj.weight"), naming the exact leaked parameter path (§27, FM-1 contrast: this is a pre-flight abort, not a mid-run divergence).

Design principles (§6)

  • P1 — Adapter-Only-Trainable. Rule: every base parameter has requires_grad=False set at injection time; the optimizer is built from filter(lambda p: p.requires_grad, ...). Tradeoff: forecloses any recipe that wants to unfreeze a base layer implicitly. Operational implication: a single unit test at training start (I1, §7) is sufficient to catch every violation. Violating it: optimizer state balloons silently, VRAM budget (§4) blown, no error until OOM.
  • P2 — Label-Masking-Is-Correct-Not-Approximate. Rule: prompt, scaffolding, and padding tokens carry label -100; only assistant-response tokens contribute to loss. Tradeoff: requires the chat-template engine to emit the mask, adding a coupling. Violating it: the model learns to predict user turns, not to follow instructions — a silent quality bug, not a crash.
  • P3 — Chat-Template-Is-Data-Not-Code. Rule: the template name is stored in the adapter checkpoint; inference reads it from there, never from the base-model card. Tradeoff: one more field in AdapterMeta (§11). Violating it: FM-5 (§27), the most common LoRA-deployment bug in production.
  • P4 — Base-Frozen-By-Default-Unfreeze-Is-Explicit. Rule: any unfrozen base parameter (e.g. embeddings for vocabulary extension) requires an explicit embeddings_trainable=true recipe flag. Tradeoff: vocabulary-extension recipes need one more line. Violating it: I1's frozen-param scan produces false positives/negatives depending on which list it trusts.
  • P5 — Merge-Is-Lossless. Rule: W' = W + s·BA reproduces the unmerged forward within 1e-6 absolute tolerance at the same dtype (I6, §7). Tradeoff: merge-then-quantize must be a separate, explicitly lossy operation with its own calibration (§23). Violating it: FM-4 (§27), silent output drift after merge.
  • P6 — Multi-Adapter-Isolation. Rule: two mounted adapters never share A/B tensor storage; a request's forward touches exactly one adapter's tensors. Tradeoff: per-adapter memory is not shared even when two adapters are numerically similar. Violating it: T3/FM-8 (§26/§27), a cross-tenant data leak.
  • P7 — QLoRA-Compatible-Forward. Rule: LoraLinear composes with a Params4bit base without special-casing; dequantization happens beneath the adapter, not inside it (MM4, §34). Tradeoff: the adapter forward cannot assume a dense nn.Linear base. Violating it: Phase 7 (§19) becomes a fork of Phase 1 (§13) instead of a composition.
  • P8 — Target-Module-Config-As-Data. Rule: which modules receive adapters is declared in LoraConfig.target_modules, resolved via the per-architecture registry (§11.7), never hardcoded per model family. Tradeoff: a new architecture needs a registry entry before it works. Violating it: ADR-25's rejected alternative (graph autodetection) reappears as ad hoc per-model branches.
  • P9 — Save-Only-Adapter. Rule: the default checkpoint contains adapter tensors + config + chat template + tokenizer reference; base weights are never written by the training driver. Tradeoff: a "save full merged model" path (§23) is opt-in, not default. Violating it: checkpoint size stops being bounded by adapter rank (§4).
  • P10 — Eval-During-Train. Rule: validation loss every 100 steps, perplexity every 500, downstream metrics end-of-epoch (§4 cadence); a run that cannot report validation loss is misconfigured, not "just running." Tradeoff: eval wall-clock is a tax on every run (M12, §32). Violating it: overfitting (§18, Phase 6) is detected only after the run ends, if at all.
  • P11 — Reproducible-By-Config. Rule: one YAML recipe fully specifies a run; git SHA, package versions, recipe hash, and seed are stamped into checkpoint metadata (I12, §7). Tradeoff: no shell-flag overrides at run time. Violating it: FM-11 (§27), a resumed run that cannot be shown to be the same experiment.
  • P12 — Substrate-Delegation. Rule: gradient accumulation, mixed precision, gradient clipping, LR scheduling, and checkpoint-resume mechanics are rank-114's TrainingLoop; this project supplies only the Trainable adapter surface. Tradeoff: this project cannot diverge from rank-114's substrate semantics without an ADR. Violating it: duplicated, untested AMP/accumulation logic — the single highest-risk reimplementation bug class.
  • P13 — Zero-Init-B. Rule: B is initialized to zero (never A) so the adapter contributes exactly zero at step 0 (I3, §7; MM2, §34). Tradeoff: A's Kaiming init alone determines the initial gradient direction. Violating it: the wrapped model does not behave identically to the unwrapped base at step 0, breaking the "wraps an existing model" promise.
  • P14 — Quantization-Is-Orthogonal-To-Adapter-Math. Rule: NF4 dequantization is a property of the base layer's storage, invisible to the adapter forward's algebra (MM4, §34). Tradeoff: the adapter library cannot assume a fixed base dtype. Violating it: a quantization-aware adapter fork per method, quadrupling the maintenance surface across LoRA/AdaLoRA/DoRA/IA3.
