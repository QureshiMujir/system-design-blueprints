⬜ Phase 0 — Repo Skeleton & Correctness Kernel §12

Objectives

Stand up the repository (§10), the peft_engine.types/adapters.lora/model_prep packages, and a rank-8 LoraLinear on q_proj,v_proj of a 124M-parameter GPT-2-class base, trained against a 1,000-example Alpaca-cleaned subset, producing a <10 MB adapter checkpoint. This phase's exit gate is the correctness kernel: I1/I2/I3 all provably hold before any later phase may build on it.

Deliverable

peft-engine train recipes/phase0_gpt2_alpaca.yaml runs end to end on one GPU, writes checkpoints/phase0/adapter_model.safetensors + adapter_config.json, and peft-engine inspect checkpoints/phase0/ reports parameter counts and the I1/I2/I3 invariant status.

Acceptance

Trainable-parameter count ≤ 200,000 (measured; matches §36 #1's scaled-down derivation for 124M/12-layer/768-hidden). Checkpoint size ≤ 10 MB. Final training loss ≤ 1.8 (cross-entropy, nats) after 3 epochs on the 1,000-example fixture. I1 param-scan reports 0 leaked base parameters. Conformance fixture gradient_isolation/step0_equivalence.json passes within 1e-6 (I3).

Fixtures
Fixture Purpose Expected Output
gradient_isolation/frozen_base.json I1: base params carry no grad after one step 0 non-adapter tensors with non-null .grad
gradient_isolation/step0_equivalence.json I3: wrapped model ≡ base model at step 0 max abs diff ≤ 1e-6
label_masking/alpaca_basic.jsonl I4: prompt tokens masked, response tokens not masked_token_fraction > 0 and < 1.0
label_masking/bad_row_missing_output.jsonl malformed-input rejection (§8) SchemaValidationError raised, run does not start

Pitfalls

Freezing the base after constructing the optimizer silently produces an optimizer with stale param groups (I2 violation) — the fix is to make BUILD_OPTIMIZER a state that cannot be entered before FREEZE_BASE/INJECT_ADAPTERS (§8 state machine). Initializing both A and B nonzero breaks I3 without an obvious symptom until a downstream eval regression appears. Using torch.load instead of safetensors.torch.load_file reintroduces the ADR-05 pickle risk even in a "just for Phase 0" script. Forgetting bias="none" handling wraps bias tensors that should remain frozen.

⬜ Phase 1 — Adapter Library Core (LoRA) §13

Objectives

Generalize Phase 0's single-target LoraLinear into the full adapter library surface: rank/ alpha sweeps, rsLoRA scaling, dropout placement, and the Adapter ABC (§11.2) that every later adapter type (AdaLoRA, DoRA, IA3) will implement.

Deliverable

peft-engine train accepts any r/alpha/dropout/use_rslora combination; the merge path (stubbed, full implementation in Phase 11) round-trips for every rank in the sweep.

Acceptance

Trainable-parameter count matches the closed-form 2·r·(in+out) per target module (§8 worked example) within 0 tolerance (exact integer match) for every r in {4,8,16,32,64}. rsLoRA scaling (α/√r) differs from default scaling (α/r) by more than 1% for r≠1 (sanity check the two formulas are not accidentally identical). PiSSA init reproduces the base forward within 1e-4 at step 0 (looser than I3's 1e-6 because SVD truncation is inherently approximate).

Fixtures
Fixture Purpose Expected Output
rank_sweep/r4_r8_r16_r32_r64.json closed-form param count matches implementation exact match, all 5 ranks
rslora/scaling_diff.json rsLoRA scaling diverges from default at r≠1 relative diff > 1%
pissa_init/step0_approx.json PiSSA step-0 near-equivalence max abs diff ≤ 1e-4
dropout_placement/on_input_to_a.json dropout applied pre-A, not between A/B activation-shape trace matches ADR-04
Pitfalls

Applying dropout between A and B (the ADR-04-rejected placement) changes the effective rank distribution under training and silently invalidates the closed-form parameter-count argument used throughout this document — the fixture dropout_placement exists specifically to catch a regression back to that placement. PiSSA init requires the SVD to run before requires_grad=False is set on the original weight snapshot used for the decomposition, or the SVD sees an already-mutated tensor.

⬜ Phase 3 — Dataset Pipeline & Chat-Template Engine §15

Objectives

Build the dataset loaders (jsonl/parquet/HF datasets), the eight shipped chat templates (chatml, llama3, mistral, phi3, gemma, alpaca, vicuna, plain), and the label-masking engine that makes P2/P3/ADR-11 concrete and testable.

Train/val/test split example-id sets are pairwise disjoint (I13 precondition) verified by set intersection = ∅. Collator rejects (does not silently zero-pad into) any batch with masked_token_fraction == 1.0.

Fixtures
Fixture Purpose Expected Output

Pitfalls

Recomputing the label mask from string character offsets (the ADR-11-rejected approach) silently mis-masks whenever a tokenizer's decode-then-recount roundtrip is lossy (common with byte-pair-encoding tokenizers on non-ASCII input) — this is precisely why the mask is emitted by the template engine at render time, from the regex marker, not reconstructed later. A template whose assistant_marker_pattern is ambiguous (matches inside the assistant's own content) produces an under-masked example that trains on partial system-prompt leakage.

⬜ Phase 4 — Training Driver & Optimization Loop §16

Objectives

Compose rank-114's TrainingLoop (P12, ADR-12) with the adapter-only Trainable surface, delivering mixed precision, gradient accumulation, gradient checkpointing, gradient clipping, and LR scheduling without reimplementing any of them in this project.

Deliverable

A full training run on the Phase-0 fixture and a held-out 8B-class Llama recipe both complete without divergence, reporting per-step loss, gradient norm, and learning rate to TensorBoard + JSONL (ADR-20).

Acceptance

Training throughput ≥ 8,000 tok/s at Phase-0 scale (M3) and ≥ 3,500 tok/s at 8B/H100 scale (M4), both CI-gated. Gradient norm is finite for 100% of steps in a 500-step smoke run (I8). Two runs at the same seed converge to within 0.5% loss at every logged step (ADR-21). Gradient-accumulation effective batch size matches the recipe's declared value exactly (no off-by-one from a partial final micro-batch).

Fixtures
Fixture Purpose Expected Output
training_repro/seed_determinism_500steps.json ADR-21 tolerance loss curves within 0.5% at every step

Pitfalls

Constructing the optimizer before INJECT_ADAPTERS completes captures zero trainable parameters — a silent no-training-happens bug rather than a crash, because AdamW([]) does not raise (fix: the state machine, §8, structurally forbids this ordering). Acceptance

Full downstream eval suite (MMLU subset + IFEval + AlpacaEval) completes in ≤ 20 minutes wall-clock at 8B scale (M12). Overfit detector fires within 200 steps on the synthetic overfitting fixture (train loss ↓ >10%, val loss ↑ >5% over a 100-step window). Eval/train n-gram overlap scan reports 0% overlap on the Phase-0 Alpaca-cleaned fixture (I13 precondition sanity check).

Fixtures
Fixture Purpose Expected Output

Running MMLU/IFEval/AlpacaEval every 100 steps (instead of end-of-epoch, §4 cadence) burns the majority of a run's wall-clock budget on eval rather than training — the cadence split (loss frequent, downstream-task rare) exists specifically to avoid this. An overfit detector window too short (e.g. 10 steps) fires on ordinary loss-curve noise; too long (e.g. 5,000 steps) detects overfitting only after most of the run's compute is wasted — the 100-step window is tuned against the synthetic fixture (18.5), not asserted from theory alone.

⬜ Phase 7 — QLoRA: NF4 Quantization & Paged Optimizers §19

Objectives

Compose the adapter library (Phase 1) with a 4-bit NF4-quantized base (Dettmers et al. 2023), enabling fine-tuning of models up to 70B parameters on a single 48 GB GPU (§4), without any adapter-forward special-casing (P7, MM4).

Deliverable

peft-engine train recipes/llama3_8b_qlora_4bit.yaml and a 70B-class recipe both run on a single 48 GB GPU; peft-engine inspect reports the base model's quantization mode (nf4, double-quantized: yes/no) alongside the adapter config.

Acceptance

VRAM ceiling ≤ 48 GB for the 70B/batch-1/seq-1024 configuration (§4, measured via benchmarks/qlora_memory_footprint.py). NF4 dequantization kernel throughput ≥ 50 GB/s per GPU (M5). I10 holds (0 gradient-leak events) across a 500-step QLoRA smoke run with gradient checkpointing enabled. Double quantization reduces measured per-parameter constant overhead from the single-quantization baseline by ≥ 60% (targeting the theoretical 0.5→0.127 bit reduction, §4).

Fixtures
Fixture Purpose Expected Output
qlora/vram_70b_single_48gb.json §4 VRAM ceiling ≤ 48 GB peak allocated
qlora/nf4_dequant_throughput.json M5 gate ≥ 50 GB/s
qlora/grad_leak_with_checkpointing.json I10 under recomputation 0 leak events, 500 steps
qlora/double_quant_overhead_reduction.json double-quantization savings ≥ 60% overhead reduction vs single-quant
Pitfalls

The bitsandbytes CPU fallback path (triggered by a mismatched CUDA/driver combination) silently degrades throughput without a loud warning (§5, reference-implementation pitfall note) — Phase 7 makes this an explicit FM-10 telemetry counter rather than a silent slowdown. Gradient checkpointing combined with a misconfigured paged optimizer can both trigger simultaneously under VRAM pressure, and their interaction (recompute timing vs. CPU-offload timing) is a documented edge case (19.8), not a rare coincidence.

⬜ Phase 8 — AdaLoRA: SVD Reparameterization & Budget Pruning §20

Objectives

Implement AdaLoRA's SVD-form adapter (P·diag(E)·Q) and its importance-score-driven, monotonically-shrinking rank-pruning schedule (Zhang et al. 2023), letting the optimizer redistribute a fixed total rank budget across modules (I11).

Deliverable

peft-engine train recipes/phi3_mini_adalora.yaml trains with an initial rank budget of 16, prunes to a target of 8 by 60% of training, and peft-engine inspect reports the per-module final rank distribution (some modules end above 8, some below, summing to the total budget).

Acceptance

I11 holds: current_rank_budget(t) ≤ current_rank_budget(t-1) for every logged step across a full run (0 violations). Final per-module rank distribution is non-uniform (at least 2 modules differ in final rank by ≥2), demonstrating actual budget reallocation, not a degenerate uniform prune. orth_regularization loss term decreases by ≥30% from its step-0 value by end of training (evidence P/Q are trending toward orthogonal, per ADR-08's rationale).

Fixtures
Fixture Purpose Expected Output
adalora_pruning/monotonic_budget.json I11 enforcement 0 rank-increase events
adalora_pruning/nonuniform_reallocation.json budget redistribution evidence ≥2 modules differ by ≥2 final rank

adalora_pruning/importance_score_ema.json importance-score computation correctness EMA matches reference calculation within 1e-4

A pruning scheduler bug that re-activates a previously-pruned singular index (an I11 violation) typically manifests as a subtle accuracy improvement that later reverses — the fixture monotonic_budget.json catches the invariant violation directly rather than waiting for a downstream accuracy regression to surface it (ADR-08's rejected-alternative regime: short runs where the EMA hasn't stabilized are exactly where this bug is most likely to appear, since importance scores are noisiest early).

⬜ Phase 9 — DoRA: Weight-Decomposed Low-Rank Adaptation §21

Objectives

Implement DoRA's magnitude/direction decomposition (Liu et al. 2024) to close the residual quality gap between plain LoRA and full fine-tuning on magnitude-sensitive tasks (MM7, §34).

Deliverable

peft-engine train recipes/mistral_7b_dora.yaml completes; a held-out quality benchmark (a subset of MT-Bench or an internal instruction-following eval) shows DoRA closing ≥50% of the LoRA-to-full-fine-tune gap measured on the same base/dataset/rank.

Acceptance

Step-0 forward equivalence (DoRA's I3 analogue) holds within 1e-6 (magnitude-init correctness, ADR-09). Separate-LR-group ablation: training with a single shared LR for magnitude+direction shows ≥2× more loss-spike events (I8-adjacent) than the separate-group configuration over a 500-step run, confirming FM-12's mechanism. Merge equivalence (I6) holds within 1e-6 for DoRA merges exactly as for plain LoRA.

Fixtures
Fixture Purpose Expected Output
dora_decomposition/step0_equivalence.json magnitude-init correctness max abs diff ≤ 1e-6
dora_decomposition/separate_lr_ablation.json FM-12 mechanism confirmation shared-LR run has ≥2× loss-spike events
dora_decomposition/merge_equivalence.json I6 for DoRA max abs diff ≤ 1e-6
dora_decomposition/magnitude_direction_grad_ratio.json per-group grad-norm telemetry ratio logged and bounded within recipe's declared range
Pitfalls

Initializing magnitude to ones (the ADR-09-rejected alternative) instead of the base column-norm produces a training-time discontinuity at step 0 — the model's initial forward differs measurably from the unwrapped base, violating the DoRA analogue of I3/P13. Sharing a single LR across magnitude and direction parameter groups (FM-12) is the single most common DoRA-specific instability reported in practice; the separate-group ablation fixture exists specifically to make this regression detectable in CI rather than discovered per-recipe.

⬜ Phase 10 — IA3 & Prompt/Prefix Tuning §22

Objectives

Implement the minimum-parameter-regime methods — IA3's element-wise scaling vectors (Liu et al. 2022) and Lester et al./Li & Liang's soft-prompt and prefix-tuning — for settings where even LoRA's parameter count is a target to minimize further.

Deliverable

peft-engine train recipes/gemma_2b_ia3.yaml trains successfully; a prompt-tuning recipe against an 8B-class base model demonstrates the reparameterization trick's stability advantage over direct prefix optimization (an ablation comparing both).

Acceptance

IA3 step-0 equivalence (scale=1.0 identity) holds within 1e-6. Trainable-parameter count for IA3 on an 8B-class model is ≤ 50,000 (three vectors × attachment points × layers — an order of magnitude below LoRA r=8's 3.4M, §36). Prefix-tuning with the reparameterization MLP converges within 500 steps on the Phase-0-scale fixture; direct (non-reparameterized) prefix optimization, run as an ablation, either fails to converge in the same budget or shows ≥3× loss variance across seeds (evidence for Li & Liang §6's stability claim).

Fixture Purpose Expected Output

⬜ Phase 13 — Distributed Training & Fused Kernels §25

Objectives

Scale training beyond a single GPU via FSDP/DeepSpeed ZeRO (rank-90 project integration) and close the remaining throughput gap with Unsloth-style fused Triton kernels (ADR-17), enabling 70B-class QLoRA fine-tuning across multiple GPUs at ≥85% scaling efficiency (M11).

Deliverable

peft-engine train recipes/llama3_70b_qlora_fsdp.yaml runs across 8 H100s via FSDP with QLoRA enabled; the fused Triton kernel path is benchmarked against the unfused Phase-1 path on the same hardware.

Acceptance

Scaling efficiency from 4→8 H100s ≥ 85% (M11, measured as throughput(8)/(\N2×throughput(4))). Fused Triton kernel reduces adapter forward+backward overhead (M1/M2 combined) by ≥ 30% versus the unfused Phase-1 implementation at equal rank/target-modules. Checkpoint save from an 8-way-sharded run produces byte-identical adapter tensors to an equivalent single-GPU run (sharding-transparency check).

Fixtures
Fixture Purpose Expected Output
distributed/scaling_efficiency_4to8_h100.json M11 gate ≥ 85%
distributed/checkpoint_sharding_transparency.json sharded save matches single-GPU save byte-identical adapter tensors

Pitfalls

Sharding base-model weights and adapter weights with the same FSDP wrapping policy wastes communication bandwidth all-gathering frozen parameters that carry no gradient — the fix is a custom wrapping policy that treats adapter parameters as a distinct, fully-replicated-or- sharded-independently group (25.2). Applying the fused Triton kernel to AdaLoraLinear or DoraLinear without accounting for their different forward shapes (SVD-form vs. magnitude-direction) either produces wrong outputs silently or fails to compile — Unsloth's own kernels are LoRA-specific for this reason (§5 pitfall note), and this project's fused kernels are likewise implemented per-method, not generically.
