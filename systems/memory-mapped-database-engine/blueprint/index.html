319 — Memory-Mapped Database Engine from Scratch

Project Number: 319 Project Name: Memory-Mapped Database Engine from Scratch Owner: Mujir Qureshi Document: FINAL_BLUEPRINT.md Status: specification — locked

1. Goal

What is built. An embedded, single-file, memory-mapped key-value storage engine in the LMDB lineage. The database file is the address space: mmap the whole file once, let the OS page cache serve as the buffer pool, expose values as zero-copy pointers into the map. Writes use a copy-on-write (COW) B+tree — never mutate a live page in place; copy the touched path root-ward; publish a new root per commit by flipping between two alternating meta pages. No write-ahead log. No user-space buffer manager. Crash consistency comes entirely from atomic single-page meta writes plus a strict durability-ordering invariant.

Engineering boundary (one line each):

  • In scope: env open/geometry, read/write txns, get/put/del, cursors (range + duplicate keys), named sub-databases, nested sub-DBs, reader-aware page reclamation (freelist), durability modes (SYNC/NOSYNC/WRITEMAP), checksums for torn-page detection, map growth/remap.
  • Out of scope (hard non-goals): SQL/query planner; network protocol/server (embedded library only); physical/logical replication; multi-writer concurrency; secondary-index maintenance beyond raw named DBs; compression; encryption-at-rest; distributed transactions.
  • Deployment model: a Rust library crate (mdbx_engine) linked into a host process; optional thin C ABI (cdylib) for FFI. One process opens one env; multiple processes may share via the file lock + reader table.
  • Target users: storage-engine authors, DB internals learners, embedders needing crash-safe local KV with zero-copy reads (metadata stores, message queues, caches with durability, graph/index backends).

Phase 0 deliverable (numbered crates/modules):

  1. mdbx_engine (lib root) — public API surface (Env, Txn, Cursor, Db).
  2. mmap — mmap/munmap/remap wrappers; address-space management; madvise.
  3. page — page header codec, leaf/branch node layout, meta page, freelist page.
  4. meta — dual-meta read/select/commit-flip; geometry; checksum.
  5. tree — COW B+tree search/insert/delete/split/merge/rebalance; page lineage.
  6. txn — read (snapshot) + write (single-writer) transaction lifecycle; dirty-page tracking.
  7. freelist — reader-aware page reclamation; pending/free lists keyed by txnid.
  8. cursor — positioned traversal; range scans; dup-key navigation.
  9. lock — process write mutex + reader table (shared lock file).
  10. errors — typed error enum; PhaseDeferred.
  11. cli (mdbx-cli) — open/stat/get/put/scan/copy/verify (operator tool).

What later phases unlock: durability modes (WRITEMAP/NOSYNC), named + nested sub-DBs, duplicate keys (DUPSORT), reader-table sharing across processes, online copy/compaction, integrity verifier, fuzz + crash-injection harness, benchmark suite.

Deferred features (gated PhaseDeferred("Deferred Features Register")):

  • Encryption-at-rest → PhaseDeferred("Deferred Features Register").
  • Compression of values/pages → PhaseDeferred("Deferred Features Register").
  • 32-bit address-space large-DB workaround (windowed remap) → PhaseDeferred("Deferred Features Register").
  • Multi-writer / optimistic concurrency → PhaseDeferred("FINAL_BLUEPRINT §Phase 7").
  • Async I/O prefetch scheduler → PhaseDeferred("FINAL_BLUEPRINT §Phase 13").

Timeline. Phase 0 (Phases 1–6, single-threaded COW B+tree + dual-meta crash recovery + zero-copy reads, survives kill -9 mid-commit): 6–14 weeks. Full plan (Phases 1–13, reader-aware freelist, MVCC readers, durability modes, sub-DBs, verifier, fuzz, bench): 5–8 months.

Recommended language: Rust (stable, edition 2021). Rationale (full ADR-001 §9): ownership/borrow model encodes the txn lifetime ↔ snapshot-pin invariant at compile time (a read value's lifetime is tied to the Txn borrow, preventing use-after-remap); unsafe is required but bounded — confined to mmap/raw-pointer codec inside mmap and page modules behind audited safe wrappers; zero-cost abstractions keep the read path pointer-thin; repr(C) + explicit endian codecs give byte-stable on-disk format; no GC pauses in the commit path. The single-level-store design leans hard on raw pointers into the map, so Rust's discipline is an asset, not friction.

Prerequisites: B+tree algorithmics (split/merge from memory); virtual memory & paging (page faults, TLB, mmap, page cache, dirty writeback — see project #148); filesystem durability (fsync/fdatasync/msync, write barriers, sector atomicity — #34); MVCC snapshot isolation basics (#100); intermediate Rust (lifetimes, Send/Sync, unsafe, MaybeUninit, AtomicU64); the LMDB source as a readable reference.

2. Why Build This

Unique systems knowledge. This is the canonical single-level store: it dissolves the boundary between "in memory" and "on disk." There is no buffer manager, no page-table-of-our-own, no read syscall on the hot path. You learn what it means to let the kernel's VM subsystem be your cache, and you confront the consequences — page faults as I/O, madvise as your only prefetch lever, SIGBUS as your I/O-error channel, remap as a pointer-invalidation hazard.

Historical/architectural significance. LMDB (Howard Chu, OpenLDAP, 2011) showed that a few hundred KB of C could outrun buffer-pool engines on read-heavy workloads by being radically simpler: COW B+tree + dual meta + mmap = full ACID with no WAL, no log replay, no recovery pass. Recovery is "pick the meta page with the higher valid txnid." It anchors OpenLDAP, Monero, and (via libmdbx) many embedded stores. This project teaches why simplicity is a durability strategy.

Engineering muscles: crash-consistency reasoning without a log; reader/writer MVCC without locks on the read side; pointer-stability under address-space growth; OS-level I/O tuning (madvise, readahead, dirty accounting); torn-write reasoning and the sector-atomicity assumption that is the whole correctness linchpin.

What Mastery Looks Like

  • Achieve ACID durability with no write-ahead log — after Phase 6 you can build a commit path whose entire crash-consistency story is "write data pages durable, then atomically flip one of two meta pages," and prove via crash-injection that a kill -9 at any of the four phase points either fully commits or fully rolls back (§17.4, Principle 7, INV-META-DURABLE-ORDER).
  • Let the OS page cache be your buffer pool, and know exactly when that is wrong — after Phase 1 you can implement a single-level store (pgno → base + pgno·P) where reads are page faults and madvise is the only prefetch lever, and articulate the four pitfalls Crotty/Leis/Pavlo (CIDR 2022) document — transactional-safety loss, single-threaded page-eviction stalls, TLB shootdowns, and lost I/O ordering (§4 read-throughput target, Principle 1, ADR 004).
  • Implement copy-on-write B+tree mutation with reader-safe page reclamation — after Phases 4, 5, and 8 you can copy a touched root→leaf path, publish a new root, and reuse a freed page only once the oldest live reader's snapshot has advanced past the freeing txid, and explain why violating that rule corrupts a reader mid-scan (§15.2/§16.2/§8.2, INV-COW-NO-INPLACE, INV-READER-PIN, Principle 9).
  • Build MVCC snapshot isolation with zero locks on the read path — after Phase 7 you can pin a consistent snapshot via a shared reader table, run N lock-free readers against one serialized writer with neither side blocking the other, and reap a crashed reader's slot via PID-generation liveness (§18.4, Principle 4, INV-SINGLE-WRITER).
  • Reason about torn writes and the sector-atomicity assumption that anchors the whole design — after Phase 2 you can explain why a single-page meta write must be all-or-nothing, why commits alternate meta slots by txid & 1, and how a per-page checksum turns an undetected torn write into a fail-stop Error::Corrupt (§8.3/§8.9, INV-META-ALTERNATE, INV-CHECKSUM-VALID, Principle 6).
  • Diagnose and remediate freelist starvation in production — after Phase 8 you can read an oldest_reader_txid lag metric, identify the long-lived reader pinning a file at 50× its live size, kill or reap it, and rebuild with copy --compact (§8.10, §Failure Modes & Recovery, runbook freelist_bloat.md, INV-READER-PIN).
  • Surface a mapped-region I/O error as a recoverable error, not a process abort — after Phase 10 you can install a SIGBUS handler that translates a disk failure or truncation under the map into Error::Sigbus, and reason about the WRITEMAP wild-write hazard that no syscall can trap (§21.2/§21.9, runbook sigbus.md, Principle 13).

Box-by-box (one dense paragraph each).

  • Public API. Thin handle layer. Env = open mmap + meta + locks. Txn borrow lifetime bounds returned value pointers (Rust enforces no use-after-commit/remap). Read values are &[u8] directly into the map — zero copy. Single concurrent write txn; many read txns.
  • WriteTxn coordinator. Acquires the process write mutex (serializes writers). Tracks dirty pages in an in-memory map (pgno -> owned frame) until commit. Implements COW: any page on a touched root→leaf path is copied (new pgno from freelist or appended), parents rewritten to point at copies, yielding a fresh root. Commit publishes via meta flip.
  • ReadTxn / snapshot. On open, reads the current meta, records (root, txid), registers a slot in the reader table. Descends an immutable tree; never takes page latches; never blocks the writer; the writer never blocks it. Drop unpins the snapshot (clears reader slot), allowing reclamation to advance.
  • Freelist. Two structures: pending (pages freed by the in-flight write txn, not yet committed) and free[txid] (pages freed by committed txn txid). A free page may be reused only when txid < oldest-live-reader-txid. Otherwise held → map growth. This reader-aware rule is the source of "freelist starvation" / bloat.
  • COW B+tree. Branch pages route by key; leaf pages hold key→value (or key→[values] under DUPSORT). Search is pointer-chase through the map. Insert may split (propagating COW upward); delete may merge/rebalance. Every structural change copies pages, never mutates live ones.
  • Page codec. Fixed page size (4 KiB default). Header (16 B) + slotted directory + nodes growing toward the middle. Meta, leaf, branch, freelist, overflow page variants. Optional per-page checksum to detect torn writes on read.
  • Dual Meta. Pages 0 and 1. Each holds geometry + main-DB root + freelist-DB root + last_pgno + monotonic txid + checksum. Commit always writes the other meta with txid+1. Recovery/open picks the meta with the higher valid (checksum-passing) txid. This is the entire crash-consistency mechanism.
  • mmap single-level store. One mmap of the file; base pointer; pgno → base + pgno*pagesize. Reads fault pages in lazily; madvise is the only prefetch knob. Writes go either through the writable map (WRITEMAP) or via pwrite to the fd; durability via msync(MS_SYNC) or fsync/fdatasync. Growth requires remap; the base address may move, so internal references are page numbers/offsets, not raw pointers held across grow.
  • OS layer. Owns the actual cache, writeback timing, and fsync semantics. Trust boundary for the sector-atomicity assumption (a single page/meta write ≤ device atomic-write granularity).
  • Lock file. Sibling file holding a single write-mutex region + a fixed array of reader slots (pid,tid,txid). Enables multi-process sharing and the oldest-live-reader computation.

All later sections reference these box names verbatim.

4. System Constraints

Constraint Target / bound Note
Page size 4 KiB default; {4,8,16,64} KiB at create Must be ≥ OS page size; fixed for file lifetime.
Meta-write atomicity single page ≤ device atomic-write unit (assume ≥ 4 KiB sector / NVMe) Correctness linchpin (§8, §Threat).
Max DB size bounded by virtual address space (64-bit: effectively TB+; 32-bit: ~2 GiB usable) mmap one region; configurable maxpg geometry.
Memory ceiling (engine) RSS ≈ working set of touched pages (kernel page cache) + small fixed state (reader table, dirty map) No user buffer pool → engine heap is tiny.
Read throughput (warm) ≥ 5–20 M point lookups/s/core (pointer chase, zero-copy) Bound by cache/TLB, not syscalls.
Write throughput (SYNC) ~hundreds–few thousand commits/s One fsync/commit dominates; batch into one write txn for more.
Write throughput (NOSYNC) ≥ tens of thousands commits/s No durability of last writes on crash; ordering still safe.
Commit latency (SYNC) p50 ≈ device fsync (50–500 µs NVMe / 5–10 ms HDD); p99 ≈ fsync tail + COW path copy Dominated by storage.
Read latency (warm) p50 < 1 µs; p99 < few µs Cold = page-fault I/O (device-bound).
Startup (open) < 1 ms (read 2 metas + lock attach); no log replay Recovery = O(1) meta selection.
Shutdown clean: drop env (munmap, close, release lock); no flush needed if last commit durable Crash-only safe (no clean-shutdown requirement for correctness).
Concurrency 1 writer (serialized by mutex) + N readers (N ≤ reader-table slots, default 126) Reader table size fixed at create.
FD budget ~2 (data file + lock file) per env mmap doesn't consume FDs per page.
Recovery time objective O(1): pick valid meta; ≤ open time No scan, no replay.
Write amplification COW: whole root→leaf path copied per commit (≈ tree-height pages min per modified key, batched within a txn) Mitigate by batching writes per txn.
Space amplification up to ~2× transiently (old + new path) + freelist held by stale readers Bounded by oldest live reader.
Scaling vertical only (single node, single writer); no horizontal By design.
NUMA reads touch arbitrary pages (random faults); pin env thread or accept cross-node cache madvise/first-touch noted in §Performance.
Reader-table slots fixed at create (default 126; ≤ a few thousand) Caps concurrent readers (ReadersFull); sized to ~1 cache line each (§18.7).
Key size ≤ ~½ page minus headers (default ~511 B at 4 KiB); larger → reject Oversized keys destroy fan-out; values spill to overflow, keys do not.
Value size inline ≤ ~¼ page; beyond → overflow chain (no hard max but bounded by maxpg) Threshold tuned for branch fan-out health (§8.4, C10).
Dirty-set budget (write txn) configurable; default tens of MiB before spill (§21.2) Beyond budget → spill or TxnFull (C7).
Checksum CPU xxh3 ≈ multiple GB/s/core; flag-gated On warm pointer-chase reads even this can dominate → off by default for trusted storage (ADR 012).
Clock dependence none No timestamps in the format; txid is a logical counter — no clock-skew failure class (contrast NTP/Spanner-style designs).

Defining property (stated explicitly). The database file is the process address space, and the only durability mechanism is the atomic flip of one of two meta pages after the data it references is durable. Everything else — zero-copy reads, O(1) selection recovery, lock-free MVCC readers, reader-aware reclamation — follows from that single sentence. If a proposed change cannot be expressed without violating it (e.g. needing a write-ahead log, an in-place mutation, or a second writer), it belongs in a different engine (§Alternative Architectures).

6. Design Principles

  1. The file is the address space (single-level store). No user buffer pool; OS page cache is the cache. Tradeoff: lose fine-grained cache control + cross-platform uniformity; gain radical simplicity + zero-copy reads. Violation: reintroducing a buffer pool duplicates the page cache → double-caching, wasted RAM, lost zero-copy.
  2. Never mutate a live page (COW). Touched pages are copied; old pages stay valid for live readers. Tradeoff: write amplification (path copy). Violation: in-place mutation races a concurrent reader → reader observes a half-modified node → corruption.
  3. One write at a time (single writer). Writers serialized by a process mutex. Tradeoff: write concurrency ceiling. Violation: two writers racing the meta flip → lost update / dual roots / corruption.
  4. Readers never block, never lock pages, never copy. A reader pins a meta and walks an immutable snapshot. Violation: taking latches reintroduces reader↔writer contention and defeats the design's headline property.
  5. Durability ordering is sacred. All data/branch/leaf pages of a commit must be durable before the meta that publishes them. Tradeoff: extra sync/barrier per commit. Violation: meta points at a page not yet on disk → post-crash dereference of garbage.
  6. Single-page meta write is atomic (sector-atomicity assumption). Recovery correctness rests on a meta page being written all-or-nothing. Violation: torn meta → ambiguous root → must detect via checksum and fall back to the other meta.
  7. Recovery is selection, not replay. Open = read both metas, pick higher valid txid. Tradeoff: none vs WAL; gain: O(1) startup, no log. Violation: adding replay logic implies we trust in-place writes — contradicts the model.
  8. References are page numbers, not raw pointers across grow. Anything persisted or held across a potential remap uses pgno/offset. Violation: caching a raw *const u8 then growing the map → dangling pointer (base moved).
  9. Reclamation is reader-aware. A freed page returns to use only after the oldest live reader has advanced past the freeing txid. Tradeoff: long readers bloat the file. Violation: early reuse overwrites a page a reader still references → reader corruption.
  10. Checksums detect, they don't repair. Per-page checksum flags torn/bit-rot pages; the response is fail-stop (or meta fallback), never silent best-effort. Violation: trusting a bad page propagates corruption upward.
  11. Bounded, explicit geometry. pagesize, maxpg, reader-slot count fixed at create; growth is explicit remap up to maxpg. Violation: unbounded auto-grow without address-space accounting → SIGBUS/ENOMEM surprises.
  12. Crash-only. No clean-shutdown step is required for correctness; killing the process at any instant leaves a recoverable file. Violation: relying on a flush-on-close path makes kill -9 lossy.
  13. Fail-stop on invariant breach. Detected impossible states (bad magic, version mismatch, both metas invalid) abort the open rather than limp on. Violation: "best effort" continues silently corrupting.
  14. Zero-copy by contract, lifetime-enforced. Returned values are borrows tied to the txn; Rust forbids escaping them past commit/abort/remap. Violation: copying defeats the perf story; escaping borrows → UB.
  15. Format stability via versioned meta. fmt_ver in meta gates layout; readers reject unknown major versions. Violation: silent format drift → cross-version corruption.

7. System Invariants

For each: statement · why · enforced where · detection · telemetry · recovery · debug.

  • INV-META-DURABLE-ORDER. Data pages of txn T durable before meta(T) write. Why: prevents publishing dangling tree. Enforced: txn::commit (sync data → barrier → write+sync meta). Detect: crash-injection test asserting no post-crash root dereferences an unwritten page. Telemetry: commit_sync_phase counter. Recovery: meta selection ignores the un-published meta. Debug: strace/blktrace ordering of msync/fsync vs meta write.
  • INV-META-MONOTONIC-TXID. Committed meta txid strictly increases. Why: defines "newest" for selection. Enforced: meta::commit_flip (next = max(both)+1). Detect: open-time check both metas; assert chosen.txid ≥ other.txid. Telemetry: current_txid. Recovery: pick higher valid; if equal/torn, pick the checksum-valid one. Debug: dump both metas (mdbx-cli stat --meta).
  • INV-META-ALTERNATE. Commits alternate target meta (parity = txid & 1). Why: a torn write damages only the new meta, leaving the previous intact. Enforced: meta::target = txid & 1. Detect: parity check. Recovery: fall back to other meta. Debug: verify slot parity vs txid.
  • INV-COW-NO-INPLACE. No live (reachable-from-a-pinned-meta) page is overwritten. Why: reader safety. Enforced: tree always allocates a new pgno before mutating; freelist withholds pages pinned by readers. Detect: debug "page write guard" (writeable set ∩ live set must be ∅). Telemetry: cow_pages_copied. Recovery: none needed if held; if violated → corruption (fail-stop on checksum). Debug: page-write tracer comparing pgno against live root reachability.
  • INV-READER-PIN. A page freed at txid F is not reused while any reader's snapshot txid R satisfies R < F → page lifetime ≥ oldest reader. Why: snapshot integrity. Enforced: freelist::reclaimable(F) = F < oldest_reader_txid(). Detect: assert on alloc that candidate ∉ live snapshots. Telemetry: oldest_reader_txid, pages_held_by_readers. Recovery: if asserted violation, abort write txn. Debug: reader-table dump + freelist pending/free listing.
  • INV-CHECKSUM-VALID. Every page read on the descent passes its checksum (when enabled). Why: torn-write/bit-rot detection. Enforced: page::load verifies. Detect: checksum mismatch. Telemetry: checksum_errors. Recovery: meta → fall back to other meta; non-meta → fail txn (Error::Corrupt). Debug: hexdump page, recompute.
  • INV-ADDR-STABLE-WITHIN-TXN. Within a single txn, the map base does not move (no remap mid-txn except at controlled grow points that re-derive pointers). Why: held value pointers stay valid. Enforced: grow only at write-txn page-alloc boundary; readers never grow. Detect: assert base unchanged across a borrow. Telemetry: remap_events. Recovery: re-derive all pgno-based refs after remap. Debug: log base before/after grow.
  • INV-SINGLE-WRITER. ≤1 write txn at any instant per env (cross-process). Why: meta-flip must be serial. Enforced: lock::write_mutex (process mutex + F_SETLK on lock file). Detect: try-lock fails → Error::WriteBusy. Telemetry: write_lock_wait_ns. Recovery: caller retries/queues. Debug: inspect lock holder pid in lock file.
  • INV-FREELIST-CONSISTENT. Union(reachable pages, freelist pages, meta pages) = all allocated pages; no page in two sets. Why: no leak, no double-use. Enforced: alloc/free bookkeeping in freelist + txn. Detect: verify walk counts pages. Telemetry: leaked_pages, double_referenced_pages. Recovery: verifier reports; copy/compaction rebuilds. Debug: mdbx-cli verify.
  • INV-LAST-PGNO. meta.last_pgno ≥ max pgno reachable + freelist high-water. Why: appends never overwrite live data. Enforced: txn bumps last_pgno on append-grow. Detect: alloc beyond last_pgno only via grow. Recovery: on open, never trust file length > last_pgno region. Debug: compare file size vs last_pgno*pagesize.
  • INV-DB-VERSION. meta.fmt_ver major == engine major. Why: layout compatibility. Enforced: env::open. Detect: mismatch → Error::VersionMismatch. Recovery: refuse open; require migration tool. Debug: print fmt_ver.
  • INV-OVERFLOW-CONTIGUOUS. A BIGDATA value's overflow chain occupies physically contiguous pages (head_pgno … head_pgno+ovfl_ct-1). Why: a single value must be returnable as one &[u8] slice into the map (Principle 14, zero-copy) — non-contiguous pages cannot be one slice. Enforced: txn::alloc_overflow reserves a contiguous run at write time (Phase 4.2); reads assume contiguity (Phase 3.6). Detect: verify checks ovfl_ct pages are contiguous and within last_pgno. Telemetry: overflow_pages_written, overflow_chain_len. Recovery: non-contiguous chain → Error::Corrupt; copy --compact re-lays it contiguously. Debug: dump head page + ovfl_ct; check pgno run.
  • INV-DUP-COMPARATOR-STABLE. A DUPSORT sub-tree is always read and written with the same dup-value comparator recorded in its DbInfo.flags. Why: a comparator change silently breaks the sort order of an existing dup set → lost or unfindable values (Phase 9.6). Enforced: db::open_db reads the stored comparator id; mismatch with the requested flag → error before any access. Detect: comparator-id check at open; differential dup-count assert (Phase 9.4). Telemetry: dup_comparator_mismatch_total. Recovery: refuse the open with the wrong comparator; rebuild via copy under the correct one. Debug: print DbInfo.flags comparator id per sub-DB.

Debugging methodology. Each invariant maps to a deterministic check that the test harness exercises one-per-assertion: (1) a page-write guard (debug builds) recording every pgno written by a write txn and asserting the set is disjoint from every live snapshot's reachable set — fires on an INV-COW-NO-INPLACE or INV-READER-PIN violation at the moment it happens, not later as corruption; (2) the verify walker (Phase 11) which is the offline embodiment of INV-FREELIST-CONSISTENT, INV-LAST-PGNO, INV-CHECKSUM-VALID, INV-OVERFLOW-CONTIGUOUS, and per-node key monotonicity; (3) the crash-injection harness (MDBX_CRASH_AT, Phase 6/12) which proves INV-META-DURABLE-ORDER, INV-META-MONOTONIC-TXID, and INV-META-ALTERNATE by killing the process at each commit phase and checking the recovered txid against the atomic commit boundary; (4) property tests (proptest) generating random op streams and asserting each invariant after every op and after reopen. An invariant with no executable check is treated as unenforced and is a review failure.

8. Domain Model

8.1 Page taxonomy & geometry

  • Page size P (default 4096). pgno → file offset = pgno * P. Page 0/1 = meta. Page 2 = first usable.
  • Page kinds (flags bitfield): META, BRANCH, LEAF, OVERFLOW, FREELIST (a.k.a. free-DB leaf), LEAF2/DUPFIXED (fixed-size dup data), SUBP (embedded sub-page for small dup sets).

8.2 Page header (16 B, little-endian, repr(C))

offset size field        meaning
0      8    pgno         page number (also self-id; redundancy aids verify)
8      2    flags        kind bitfield (META/BRANCH/LEAF/OVERFLOW/FREELIST/...)
10     2    lower        end of slot directory (bytes from page start)
12     2    upper        start of node heap (grows down toward lower)
14     2    overflow_ct  # of overflow pages (when this is an OVERFLOW head) / pad

Free space within a page = upper - lower. Slot dir (u16 offsets) grows up from 16; node heap grows down from P. Optional checksum: last 8 B of page (xxh3/CRC64) — excluded from upper accounting.

8.3 Meta page (page 0/1)

magic:u32  fmt_ver:u32  pagesize:u32  flags:u32
maxpg:u64                  (geometry ceiling)
main_db:DbInfo             (root pgno, depth, entries, leaf/branch/overflow counts)
free_db:DbInfo             (the freelist's own B+tree root)
last_pgno:u64              (high-water mark of allocated pages)
txid:u64                   (monotonic; parity selects meta slot)
checksum:u64               (over the meta page minus this field)

DbInfo = { root: pgno, depth: u16, branch_pages, leaf_pages, overflow_pages, entries }.

8.4 B+tree node layout (slotted)

  • Branch node entry: { key_len:u16, child_pgno:u64, key_bytes[key_len] } (separator key + child pointer; leftmost child implied by node[0]).
  • Leaf node entry (normal): { flags:u8, key_len:u16, val_len:u32, key_bytes, val_bytes }. flags: BIGDATA (val stored in overflow chain → val_bytes = overflow head pgno), DUPDATA (val region is a sub-tree/sub-page), SUBDB (val = DbInfo of a named sub-DB).
  • Overflow page: header + raw value bytes; chained by overflow_ct/next-pgno; used when val_len exceeds page-fit threshold.
  • Keys compared as byte strings (memcmp) by default; pluggable comparator per DB.

8.5 Freelist record schema

  • The freelist is itself a B+tree (free_db) keyed by txid, value = page-number list (PNL): { count:u32, pgno[count]:u64 } sorted descending.
  • In-RAM during a write txn: pending (PNL of pages this txn frees) + working free cache. On commit, pending is written under key = committing txid.
  • oldest_reader_txid() from reader table; all free_db entries with key < oldest_reader_txid are eligible to satisfy allocations.

8.6 Transaction / snapshot model

  • ReadTxn: { txid, root: pgno, free_root: pgno, reader_slot }. Immutable view. Drop frees slot.
  • WriteTxn: { parent_txid, txid = parent+1, dirty: Map<pgno,Frame>, freed: PNL, next_pgno, root, free_root, write_guard }.

8.8 Worked example — insert causing leaf split + COW

Initial (txid=7): root=Leaf@5 [a,b,c,d] (full). Insert "bb".
1. Search root→leaf, find Leaf@5 full.
2. COW: alloc Leaf@9 (copy of @5). Split @9 → @9[a,b,bb], new Leaf@10[c,d].
   (Leaf@5 stays live for any reader pinned at txid≤7; @5 added to `freed`.)
3. Root was a leaf → create Branch@11 with separators: [<c -> @9], [>=c -> @10].
4. New root = @11. WriteTxn.root = 11; freed={5}.
5. Commit: flush @9,@10,@11 → SYNC → write meta[8&1=0]{root=11,txid=8} → SYNC.
6. Reader opening at txid=8 sees @11; reader still on txid=7 sees @5 until it drops,
   after which @5 (freed at txid=8) becomes reclaimable once oldest_reader>=8.

Worked example — reader-aware reclamation (the bloat-vs-reuse decision). Continues the tree above; shows why the oldest reader, not the current txid, gates reuse (INV-READER-PIN, MM6).

State: free_db holds {txid 8 -> PNL[5]} (page 5 was freed by the txn 8 above).
Case A — no live readers, writer begins txn 9:
  oldest = current = 9.  free_db keys < 9 → {8} eligible → pop pgno 5 from PNL[8].
  alloc_page() returns 5 (reused).  File does NOT grow.  PNL[8] now empty → key 8 dropped.
Case B — a reader is pinned at txid 7, writer begins txn 9:
  oldest = reader_table.oldest_txid() = 7.  free_db keys < 7 → {} (8 is NOT < 7).
  Page 5 is NOT reclaimable (the txid-7 reader can still reach old roots that referenced it).
  alloc_page() must APPEND (bump next_pgno, grow if needed).  File grows by one page.
Case C — the reader drops; writer begins txn 10:
  oldest = current = 10.  free_db keys < 10 → {8} eligible → page 5 reusable again.
  The space "held" during Case B is reclaimed only now — lag = (reader lifetime) of growth.

8.9 Malformed / failure-path examples

  • Torn meta: crash during SYNC-META → meta[0] checksum fails. Open: meta[0] invalid → select meta[1] (txid=7). Result: txn 8 atomically did not happen; @9/@10/@11 become unreferenced garbage reclaimable as the file tail / by verify.
  • Torn data page (no checksum): undetected → tree dereferences partial node → SIGBUS or wrong bytes. With checksum: page::load fails → Error::Corrupt, txn fails, operator runs verify/copy.
  • Both metas invalid: Error::Corrupt(meta) → refuse open. Forensics: hexdump pages 0/1.
  • Reader pinned forever (leaked txn): oldest_reader_txid frozen → freelist can't reclaim → file grows unbounded. Detect via oldest_reader_txid lag metric + reader-table dump (stale pid).

No oracle wins once the engine is the mature reference itself and no simpler ground-truth model captures the feature set (DUPSORT + overflow + freelist) more cheaply than the engine — the model becomes the maintenance burden.

No UB checking wins only if the engine contains zero unsafe (impossible here — mmap and the page codec require it); for a pure-safe-Rust KV store built on BTreeMap there is nothing for miri to find.

Ad-hoc benchmarking wins during early exploratory design when the format is still changing daily and investing in stable baselines/guards (§Performance Engineering) would just churn — the rigor pays off only once an API stabilizes.

A wiki wins for a fast-moving community project prioritizing low-friction contributor edits over a normative, versioned, in-repo spec — at the cost of the format drift FORMAT.md (§Compatibility & Versioning) exists to prevent.
028 Licensing OpenLDAP-style / MIT (engine), document LMDB inspiration GPL Permissive embedding; avoid copyleft for a library. GPL wins when the goal is to force downstream embedders to open their own source (a copyleft strategy) — appropriate for an application, hostile for a library meant to be embedded in proprietary products.

A floating toolchain wins for a library consumed only as source via crates.io (where the consumer pins versions) and which ships no binary artifact whose bit-for-bit reproducibility anyone audits.

12. Phase 1 — mmap Single-Level Store & Env Skeleton

12.1 Objectives

Establish the address-space-is-the-file foundation: open a file, mmap it, expose pgno→ptr, manage growth/remap and madvise. Constraint introduced: all higher layers address pages by pgno, never raw pointers held across grow (INV-ADDR-STABLE-WITHIN-TXN, Principle 8).

12.2 Detailed Implementation Steps

Theory anchors: Principle 1 (single-level store), Principle 8 (refs are pgno not raw ptr), Principle 11 (bounded geometry), INV-ADDR-STABLE-WITHIN-TXN, ADR 004 (mmap storage model), ADR 016 (explicit remap growth); Kerrisk Ch 49 + Love (mmap/madvise/sparse ftruncate); MM1/MM7 (faults are I/O; the map is a trust surface).

  • mmap.rs: open(path, flags) -> (fd, len); map(fd, len, writable) -> base:*mut u8 via libc::mmap (PROT_READ[|WRITE], MAP_SHARED). unmap, remap(new_len) (Linux mremap; portable fallback: munmap+mmap). UNSAFE core; safe wrapper Map { base, len } with page(pgno) -> *const u8 (addresses by pgno per Principle 8, never a cached raw pointer across grow).
  • madvise.rs helpers: RANDOM (default for B+tree faults), WILLNEED (prefetch on warm), DONTNEED, optional MADV_HUGEPAGE; MAP_POPULATE flag on map for eager fault-in.
  • geometry.rs: Geometry validation (page_size ≥ OS page, power of two, ≤ 64 KiB; max ≤ address-space budget). Compute initial map length; sparse file via ftruncate to max (or grow on demand).
  • env.rs: Env::open wires fd + map + (later) meta + lock; RDONLY maps read-only. close/Drop munmaps.
  • Growth policy: when a write txn needs pgno > mapped_pages, grow file (ftruncate) and remap by growth_step up to max; re-derive base; bump in-RAM mapped length.

12.3 Deliverable

Library opens a (possibly empty) file, mmaps it, returns a byte view of any page, grows + remaps on demand. mdbx-cli stat prints geometry (page_size, mapped pages, file size, base moved count).

12.4 Acceptance Criteria

  • Open + map a 1 GiB sparse file in < 5 ms; RSS stays near 0 until pages faulted (verify via /proc/self/status).
  • Random page reads after madvise(RANDOM) show no readahead waste (compare faults via /proc/self/stat minflt/majflt).
  • Grow from 4 MiB → 1 GiB triggers ≤ expected remaps; pgno→ptr correct after each.

12.5 Conformance Fixtures

  • conformance/meta_select/empty_4k.mdbx — zero-length grown file (no metas yet).
  • geom_pagesize_{4k,16k,64k}.json — geometry params + expected mapped layout.
  • grow_sequence.txt — sequence of required pgnos → expected remap events.

12.6 Pitfalls

  • Base moves on remap → cached raw pointers dangle. Root cause: holding *const u8 across grow. Debug: log base pre/post; assert no live borrow during grow. Recovery: address by pgno always.
  • MAP_SHARED vs MAP_PRIVATE → PRIVATE writes never hit disk (COW in RAM). Detect: data vanishes after reopen. Fix: SHARED for writable map.
  • mmap length > file length → reads past EOF fault to SIGBUS. Root cause: map larger than ftruncated size without backing. Fix: keep mapped pages ≤ file size; grow file first, then map.
  • page_size < OS page → partial-page protection/fault granularity issues. Fix: enforce ≥ OS page at create.

12.7 Performance Concerns

Cold reads = page faults (major fault → device I/O). madvise(RANDOM) suppresses wasteful readahead for random B+tree access; WILLNEED for known scans. Large maps → TLB pressure; consider huge pages for multi-GB working sets. MAP_POPULATE trades startup latency for fewer runtime faults.

12.8 Edge Cases

Zero-length file; file not multiple of page_size (truncate up); map at max already (grow → MapFull); 32-bit address-space ceiling (PhaseDeferred "Deferred Features Register"); mremap unsupported (fallback path).

12.9 Failure Analysis

mmap fails (ENOMEM/address space) → Error::MapFull, env not opened (blast radius: open only). SIGBUS on faulting an unbacked page → catch via signal handler (Phase 10) → Error::Sigbus. Forensics: file size vs mapped length vs last_pgno.

12.10 Operational Notes

Metric: mapped_bytes, remap_events, minflt/majflt deltas. Runbook grow_remap.md. Deployment: ensure vm.max_map_count adequate; document ulimit -v interaction. RDONLY opens take no write lock.

13. Phase 2 — Page Codec, Dual Meta, Crash-Consistent Open

13.1 Objectives

Define the on-disk page format and the dual-meta crash-consistency core. Introduce checksums. After this phase, a freshly created file has two valid metas and recovery = meta selection (Principle 7).

13.2 Detailed Implementation Steps

Theory anchors: Principle 6 (single-page meta atomicity), Principle 7 (recovery is selection not replay), Principle 10 (checksums detect not repair), Principle 15 (versioned meta); INV-META-MONOTONIC-TXID, INV-META-ALTERNATE, INV-CHECKSUM-VALID, INV-DB-VERSION, INV-LAST-PGNO; ADR 006 (COW+dual-meta durability), ADR 011 (LE repr(C) codec), ADR 012 (optional per-page checksum); Chu/LMDB (dual-meta selection); MM3 (recovery = pick the higher valid txid).

  • page/header.rs: PageHeader codec (LE, repr(C)); free-space accounting (lower/upper); slot-dir helpers.
  • page/checksum.rs: xxh3 over [0..P-8]; write to last 8 B; verify on load (flag-gated).
  • page/mod.rs: Page::load(map, pgno) -> Result<PageRef> (kind dispatch + checksum verify → Error::Corrupt{pgno}).
  • meta.rs: MetaPage codec; init_metas(env) writes pages 0/1 with txid 0/1 (or both 0), main/free roots empty; select(meta0, meta1) -> &Meta = higher valid txid, parity-aware; commit_flip(txid) -> slot = txid & 1.
  • env.rs: open path reads pages 0/1, validates magic/fmt_ver/page_size, selects meta, sets current = {root, free_root, txid, last_pgno}. Both invalid → Error::Corrupt(MetaBothInvalid).
  • mdbx-cli stat --meta dumps both metas (txid, roots, last_pgno, checksum ok?).

13.3 Deliverable

Env::open creates or recovers a file with two metas; selection picks the newest valid; corrupt/torn meta falls back; geometry + roots reported.

13.4 Acceptance Criteria

  • Create → reopen yields identical meta selection deterministically.
  • Manually corrupt meta[1] checksum → open selects meta[0]; checksum_errors = 1.
  • Both metas corrupt → open refuses with CorruptKind::MetaBothInvalid.
  • fmt_ver major mismatch → VersionMismatch.

13.5 Conformance Fixtures

  • meta_select/newer_meta0.mdbx, newer_meta1.mdbx — selection by txid.
  • meta_select/torn_meta1.mdbx — meta[1] half-written → select meta[0].
  • meta_select/equal_txid.mdbx — tie → pick valid/parity rule.
  • meta_select/both_bad.mdbx — refuse.
  • meta_select/badmagic.mdbx, wrong_pagesize.mdbx.

13.6 Pitfalls

  • Trusting file length over last_pgno → reading uninitialized tail as a page. Fix: bound reachable pages by last_pgno.
  • Checksum field inside checksum region → self-reference. Fix: exclude last 8 B (and the field) from digest.
  • Selecting by file mtime/order, not txid → wrong root after crash. Fix: txid + validity only.
  • Endian assumption → cross-arch corruption. Fix: explicit LE codecs everywhere; fuzz both arches.
  • Meta not parity-alternated → torn write can kill the only good copy. Fix: enforce txid & 1 target.

13.7 Performance Concerns

Meta read is 2 page faults at open (negligible). Checksum on every page adds CPU on the read path; xxh3 is ~GB/s, but for warm pointer-chase workloads even that can dominate — hence flag-gated (ADR 012). Cache: metas pinned hot.

13.8 Edge Cases

Page 0/1 partially written on first-ever create (crash during init) → re-init if both invalid and file is fresh (last_pgno==0). Page size in meta ≠ open-requested → use meta's (file is authoritative). Checksum disabled file opened with checksum on → treat as "no checksum" via flag in meta.

13.9 Failure Analysis

Torn meta: blast radius = at most the just-attempted commit; recovery automatic (other meta). Both invalid: env unopenable → operator runs verify/copy from a backup. Detection: open-time validation + checksum_errors metric. Postmortem: hexdump pages 0/1, compare txids.

13.10 Operational Notes

Spans: env.open, meta.select{chosen_txid}. Metrics: current_txid, checksum_errors, meta_fallback_total. Runbook corruption.md. NOMETASYNC flag documented as unsafe (skips meta sync → weaker durability).

14. Phase 3 — COW B+tree Search & Read Path (Zero-Copy)

14.1 Objectives

Implement immutable descent: given a root pgno, search branch→leaf and return a zero-copy &[u8] value. No mutation yet. Establishes the read path that readers and writers share.

14.2 Detailed Implementation Steps

Theory anchors: Principle 14 (zero-copy by contract, lifetime-enforced), Principle 1 (read = pointer chase into the map), INV-CHECKSUM-VALID (verify on descent), INV-LAST-PGNO (bounds-check every child pgno), INV-OVERFLOW-CONTIGUOUS (BIGDATA returnable as one slice); ADR 013 (pluggable comparator), ADR 008 (mmap reads); Bayer & McCreight 1972 + Comer 1979 (B+tree descent), Graefe 2011 (node search), Drepper (pointer-chase/TLB cost); MM1.

  • page/branch.rs: separator-key binary search → child pgno; leftmost-child convention.
  • page/leaf.rs: in-leaf binary search by comparator → node; decode flags (BIGDATA→overflow, else inline value slice).
  • tree.rs: search(map, root, key, cmp) -> Option<(leaf_pgno, slot)>; value_of(leaf, slot) -> Val (inline slice or overflow-chain assembled view).
  • page/overflow.rs: read BIGDATA value by walking overflow head + ovfl count (contiguous pages) → &[u8] spanning pages (single mmap region → still zero-copy if pages contiguous).
  • db.rs: comparator registry (memcmp default, integer-key, reverse).
  • Hook into ReadTxn::get and WriteTxn::get (write txn reads its own dirty pages first, else snapshot).

14.3 Deliverable

txn.get(db, key) returns Some(&[u8]) pointing into the map (or assembled overflow view) or None. mdbx-cli get <key> works against a hand-built fixture DB.

14.4 Acceptance Criteria

  • Point lookup on a warm 1 M-key DB ≥ 5 M ops/s/core; returned slice address ∈ map range (assert).
  • Differential: 10 k random gets vs BTreeMap model — identical results.
  • Overflow value (e.g., 1 MiB) read correctly; zero-copy when contiguous.

14.5 Conformance Fixtures

  • cow_split/three_level_tree.mdbx — branch→branch→leaf descent.
  • overflow/value_1mib.mdbx, value_spanning_17_pages.mdbx.
  • dupsort/ (read-only navigation deferred to P9 but fixtures staged).
  • get_expected.jsonl — key→value oracle.

14.6 Pitfalls

  • Returning a slice that outlives the txn → use-after-free on commit/remap. Fix: lifetime 't ties slice to txn (compile-time).
  • Overflow pages non-contiguous → can't return one slice. Decision: allocate overflow contiguously at write time; reads assume contiguity (document).
  • Comparator mismatch vs stored order → search misses present keys. Detect: differential. Fix: store comparator id in DbInfo flags.
  • Off-by-one in branch routing (>= vs >) → wrong child. Debug: log descent path; compare vs model.

14.7 Performance Concerns

Pure pointer chase: branch fan-out (≈ P/entry size) sets tree height (~3–4 for millions of keys at 4 KiB). TLB + L2/L3 misses dominate warm reads (Drepper). Binary search per node is branchy → consider linear scan for small nodes (branch-predictor friendly). No allocation on the read path.

14.8 Edge Cases

Empty DB (root = NULL pgno → None); single-leaf root; key longer than max (reject at write; on read just won't match); duplicate of separator key at boundary; overflow chain truncated (checksum/last_pgno guard).

14.9 Failure Analysis

Corrupt branch (bad child pgno > last_pgno) → Error::Corrupt(LastPgnoViolation); blast radius = that get. SIGBUS reading a faulted-but-unbacked page → Error::Sigbus. Detection: bounds-check every child pgno against last_pgno before deref.

14.10 Operational Notes

Metrics: get_total, get_overflow_total, tree_depth. Span tree.search{depth}. No durability concern (read-only). Document zero-copy contract in FORMAT.md and rustdoc.

15. Phase 4 — COW Insert, Leaf/Branch Split, Page Allocation

15.1 Objectives

Implement insertion with copy-on-write path duplication and node splitting, producing a new root in memory (not yet committed). Introduce in-txn page allocation (append for now; freelist in P8).

15.2 Detailed Implementation Steps

Theory anchors: Principle 2 (never mutate a live page — COW), Principle 8 (pgno refs), INV-COW-NO-INPLACE (first-touch copy guard), INV-LAST-PGNO (appends never overwrite live); ADR 007 (page size vs write-amp), ADR 015 (freelist deferred to P8 — append for now); Graefe 2011 (split policy), Silberschatz (split/merge mechanics); MM4 (write amplification is the COW cost).

  • txn.rs: alloc_page() -> pgno (Phase-4: bump next_pgno, grow/remap if needed; record dirty frame). dirty: Map<pgno, Box<[u8;P]>> holds writable copies.
  • tree.rs: insert(wtxn, db, key, val, flags): descend recording path; if leaf has room → COW leaf (copy live→new pgno), insert node; else split leaf → two leaves, push median separator to parent; recurse splits upward (COW each ancestor); if root splits → new root branch (tree grows one level).
  • page/leaf.rs / branch.rs: insert_node, split(at) -> (left, right, sep); slot-dir maintenance; free-space checks; BIGDATA spill to overflow when val_len > threshold.
  • COW rule: on first touch in this txn, copy the page to a dirty frame and add old pgno to freed; subsequent touches mutate the dirty frame in place (it's private to the txn).
  • Update WriteTxn.root/DbInfo counters (leaf/branch/entries).

15.3 Deliverable

wtxn.put(...) builds a new COW tree in memory; wtxn.get sees its own writes; abort discards everything (file untouched). (Commit/durability in P6.)

15.4 Acceptance Criteria

  • Insert 1 M sequential + 1 M random keys in one txn; in-txn get matches a BTreeMap model (differential).
  • Splits produce balanced fan-out (leaf occupancy ≥ 50% post-split except last).
  • freed set after N overwrites equals the count of pages superseded (no leak in bookkeeping).
  • Abort leaves on-disk metas/roots unchanged (reopen sees pre-txn state).

15.5 Conformance Fixtures

  • cow_split/split_leaf_basic.json — insert sequence → expected node layout + lineage (@5→@9,@10, root @11).
  • cow_split/root_split.json — leaf-root promotion to branch.
  • cow_split/cascade_split.json — split propagating ≥ 2 levels.
  • overflow/insert_bigvalue.json.

15.6 Pitfalls

  • Mutating a live page instead of COW copy (INV-COW). Manifest: concurrent reader sees torn node. Root: missing "first-touch copy" guard. Debug: page-write guard asserting pgno ∉ live snapshot. Recovery: none — corruption; prevent by guard.
  • Forgetting to add superseded page to freed → page leak (file grows). Debug: verify page accounting.
  • Median selection skew → unbalanced tree, poor fan-out. Fix: split at byte-midpoint of slot dir, not count, for variable-length.
  • Splitting with oversized single entry (key+val > page) → must go BIGDATA/overflow, not split forever. Detect: entry > page-fit → overflow path.
  • Parent overflow on separator insert → must recurse split into parent (don't assume parent has room).

15.7 Performance Concerns

COW path copy = O(height) page copies per first-touch path; batching many puts in one txn amortizes (later puts reuse already-dirty pages). Allocation: dirty frames are heap Boxes — pool/reuse to cut allocator churn. Split memmoves within a page (cache-friendly). Avoid re-searching: keep the descent path stack.

15.8 Edge Cases

Insert into empty DB (create first leaf root); duplicate key without DUPSORT (overwrite vs NOOVERWRITE→KeyExist); value exactly page-fit boundary; APPEND flag with out-of-order key (→error); txn dirty set exceeding memory budget (→TxnFull or spill, P10).

15.9 Failure Analysis

OOM building dirty set → Error::TxnFull; abort frees frames; file untouched (blast radius = current txn). Grow failure mid-insert → MapFull; abort. Detection: bound dirty-set size; pre-flight grow before alloc.

15.10 Operational Notes

Metrics: cow_pages_copied, splits_total, dirty_pages, overflow_pages_written. Span tree.insert{splits}. No durability yet — document that P4 alone is not crash-safe (only P6 commit publishes).

16. Phase 5 — COW Delete, Merge, Rebalance, Cursors

16.1 Objectives

Implement deletion with COW (merge/rebalance underfull nodes) and a full cursor (range scans, first/last/seek/next/prev). Complete the in-memory tree mutation surface.

16.2 Detailed Implementation Steps

Theory anchors: Principle 2 (COW on delete too), Principle 14 (cursor returns lifetime-bound slices), INV-COW-NO-INPLACE, INV-FREELIST-CONSISTENT (freed pages tracked, none leaked); ADR 013 (comparator for ordered iteration); Comer 1979 (B+tree leaf traversal), Silberschatz (merge/rebalance); MM4.

  • tree.rs: delete(wtxn, db, key): descend (COW path), remove node from leaf; if leaf underfull (< min fill) → try borrow from sibling, else merge with sibling (COW both + parent); propagate up; collapse root if it has one child (tree shrinks a level). Superseded pages → freed (INV-FREELIST-CONSISTENT bookkeeping).
  • cursor.rs: cursor = stack of (pgno, slot). first/last descend leftmost/rightmost; seek(key) = search + position; next/prev advance slot, pop/descend across leaves via parent stack (no sibling pointers needed since COW — navigate via parent stack; optionally store leaf sibling pgno for fast scan).
  • CursorMut: positioned put/del (used by DUPSORT and bulk ops).
  • Overflow page freeing on delete (free the chain → freed).

16.3 Deliverable

wtxn.del, range scans, ordered iteration via Cursor. mdbx-cli scan --from a --to z prints ordered pairs.

16.4 Acceptance Criteria

  • Delete-heavy workload keeps tree balanced (min-fill invariant; verify via verify).
  • Range scan over 1 M keys returns sorted, complete set; matches model.
  • seek semantics: returns first key ≥ target; prev/next boundaries correct at first/last leaf.
  • Mixed put/del/scan random ops (100 k) vs BTreeMap — identical (differential).

16.5 Conformance Fixtures

  • cow_split/merge_basic.json, borrow_left.json, borrow_right.json, root_collapse.json.
  • cursor_walk/range_full.jsonl, seek_boundaries.json, reverse_iter.json.
  • overflow/delete_bigvalue_frees_chain.json.

16.6 Pitfalls

  • Cursor invalidation after structural change (split/merge moves nodes). Manifest: cursor reads wrong slot. Fix: cursors are txn-scoped + read-only within a ReadTxn; CursorMut re-seeks after a write that restructures.
  • Merge with wrong sibling / across parent boundary → key order broken. Debug: assert separators monotone post-merge.
  • Underflow threshold off → degenerate near-empty nodes (space waste) or never-merge. Fix: byte-fill threshold, not count.
  • Forgetting to free overflow chain on delete → leak. Debug: verify.
  • Root collapse not handled → tree keeps a useless 1-child branch level (extra hop). Fix: collapse when branch has single child.

16.7 Performance Concerns

Scan locality: leaf-to-leaf via parent stack costs branch re-touch; optional leaf sibling pgno gives O(1) next-leaf but complicates COW (sibling pointer must be updated → wider COW). Decision: parent-stack navigation (no sibling pointer) to keep COW narrow; accept slightly higher scan cost. Delete merges memmove within pages.

16.8 Edge Cases

Delete nonexistent key (NotFound/false); delete last key (empty leaf-root → root=NULL); merge at root with two children → may collapse; cursor positioned then underlying key deleted (CursorMut); scan empty range; reverse scan from last.

16.9 Failure Analysis

Inconsistent merge (separator mismatch) → caught by verify (monotonicity) and differential tests; blast radius = the write txn (uncommitted → discard on abort). No on-disk damage pre-commit.

16.10 Operational Notes

Metrics: deletes_total, merges_total, borrows_total, scan_pages_touched. Span cursor.scan{pages}. Document cursor lifetime/invalidation rules in rustdoc.

17. Phase 6 — Write Transactions, Commit, Durability Ordering (Phase-0 Crash-Safe)

17.1 Objectives

Tie P4/P5 into a durable commit: flush dirty pages, enforce durability ordering, flip the meta. After this phase the engine survives kill -9 at any point with full crash consistency (Phase-0 done).

17.2 Detailed Implementation Steps

Theory anchors: Principle 5 (durability ordering is sacred), Principle 3 (single writer), Principle 12 (crash-only); INV-META-DURABLE-ORDER (data durable before meta), INV-META-MONOTONIC-TXID, INV-META-ALTERNATE, INV-SINGLE-WRITER; ADR 006 (durability mechanism), ADR 009 (sync primitive), ADR 010 (write-path mode); Mohan et al. ARIES 1992 (the WAL we replace — contrast), Pillai et al. ALICE 2014 (fsync-ordering pitfalls this barrier defends against); MM3 (selection recovery).

  • lock.rs: process write mutex via fcntl(F_SETLK) on lock-file write-region; begin_write acquires, commit/abort releases (INV-SINGLE-WRITER).
  • txn.rs commit per §8.7 state machine:
    1. WRITE-DATA: write every dirty page to its pgno offset (WRITEMAP: copy into map; else pwrite(fd, frame, pgno*P)).
    2. WRITE-FREELIST: store freed PNL under key txid in free_db (COWs free_db; its dirty pages join WRITE-DATA set — careful ordering: free_db pages must also be in the durable-before-meta set).
    3. SYNC-DATA: msync(MS_SYNC) (WRITEMAP) or fsync/fdatasync (file) — INV-META-DURABLE-ORDER barrier.
    4. WRITE-META: encode meta[txid&1]{root, free_root, last_pgno, txid, checksum}; write page.
    5. SYNC-META: sync just the meta page (skip if NOMETASYNC, documented unsafe).
    6. COMMITTED: update in-RAM current, release write mutex.
  • env.rs: sync(force) for NOSYNC catch-up.
  • Crash hook (test build): env var MDBX_CRASH_AT=write_data|sync_data|write_meta|sync_meta → abort process at phase point.

17.3 Deliverable

Full ACID single-writer engine: put/del/commit durable; reopen after crash yields a consistent tree at the last fully-committed txid. examples/kv_basic.rs round-trips across process restarts.

17.4 Acceptance Criteria

  • Crash-injection harness: kill at each of the 4 phase points × 1000 iterations → reopen always valid; committed-before-crash data present, mid-commit txn atomically absent (never partial).
  • SYNC commit throughput ≥ device-fsync-bound (report commits/s); NOSYNC ≥ 10× SYNC.
  • verify passes after every crash recovery (no leaked/double pages beyond the abandoned uncommitted set, which is reclaimable).

17.5 Conformance Fixtures

  • crash/at_write_data.img, at_sync_data.img, at_write_meta.img, at_sync_meta.img — pre-captured mid-commit files + expected post-recovery txid.
  • crash/replay_log.txt — op sequence to reproduce each image.
  • freelist/freed_under_txid.json — free_db entry after a deleting commit.

17.6 Pitfalls

  • Meta synced before data (ordering inversion by FS/compiler reorder) → dangling root. Manifest: post-crash SIGBUS/corrupt. Root: missing barrier or relying on MAP_ASYNC. Debug: blktrace/strace ordering; assert sync(data) returns before meta write issued. Recovery: other meta.
  • fdatasync insufficient when file size changed (metadata not durable) → grown region lost. Fix: fsync (not fdatasync) on commits that grew the file.
  • WRITEMAP + MAP_ASYNC giving false durability → msync(MS_ASYNC) doesn't guarantee on-disk. Fix: MS_SYNC for SYNC mode.
  • free_db COW pages not in durable set → meta references freelist pages not on disk. Fix: include free_db dirty pages in WRITE-DATA/SYNC-DATA before meta.
  • Releasing write mutex before meta durable → a new writer overwrites meta race. Fix: release only after SYNC-META.
  • Single fsync amortization missed → per-put fsync. Fix: one sync per commit; batch puts per txn.

17.7 Performance Concerns

fsync/msync latency dominates SYNC commits (device-bound, ms on HDD). Group many mutations into one write txn to amortize one sync. WRITEMAP avoids a user→page-cache copy (writes land in the mapped page directly) but exposes the map to accidental corruption (any wild write). NOSYNC moves the durability boundary to env.sync()/OS writeback (seconds of data at risk on crash, but ordering still preserved → never corrupt, only stale).

17.8 Edge Cases

Crash between WRITE-FREELIST and SYNC-DATA (freelist page not durable) → atomically rolled back via old meta. Empty commit (no writes) → fast path, optional no meta flip. Commit that only grows file. NOMETASYNC + power loss → may select older meta (lose last commit) but never corrupt. Disk full during WRITE-DATA → Io(ENOSPC); abort; file consistent at prior meta.

17.9 Failure Analysis

Power loss mid-commit: blast radius = the single in-flight txn (lost atomically). Recovery automatic (meta selection, O(1)). ENOSPC: writer fails, readers/older state intact. Detection: commit-phase span + return codes. Postmortem: dump both metas (which txid won), verify.

17.10 Operational Notes

Metrics: commits_total, commit_sync_phase histogram, commit_latency, bytes_written, fsync_total. Spans per phase. Runbook corruption.md. Document durability matrix (SYNC/NOSYNC/WRITEMAP/NOMETASYNC × crash → outcome). RTO ≈ open time.

18. Phase 7 — MVCC Readers, Reader Table, Single-Writer Lock

18.1 Objectives

Enable many concurrent lock-free readers across threads/processes, each pinning a consistent snapshot, with one writer — without readers blocking the writer or vice versa (Principles 3, 4).

18.2 Detailed Implementation Steps

Theory anchors: Principle 3 (single writer), Principle 4 (readers never block/lock/copy), Principle 9 (reclamation is reader-aware — sets up P8); INV-SINGLE-WRITER, INV-READER-PIN, INV-ADDR-STABLE-WITHIN-TXN; ADR 005 (single-writer + MVCC readers), ADR 014 (lock-file reader table); Reed 1978 + Bernstein & Goodman 1981 (MVCC snapshot correctness); MM5 (a snapshot is an immutable root pinned in time).

  • lock.rs: lock file layout = { write_mutex_region, reader_table[N] }; mmap the reader table into all processes (MAP_SHARED).
  • reader.rs: claim_slot(pid, tid, txid) (find slot with txid==0, CAS-write); release_slot; oldest_txid() = min nonzero across slots (skip dead pids — liveness check via kill(pid,0)/PID generation).
  • txn.rs begin_read: read current meta → (root, txid); claim reader slot stamping txid; the snapshot is immutable (COW guarantees pages reachable from that root are never overwritten while pinned, given INV-READER-PIN in P8).
  • Stale-reader detection: dead-pid reaping during oldest_txid(); NOTLS option (slot keyed by txn not thread).
  • Drop for ReadTxn: clears reader slot.

18.3 Deliverable

N reader threads/processes run concurrent consistent scans while a writer commits; readers see their pinned snapshot regardless of writer progress.

18.4 Acceptance Criteria

  • 64 reader threads + 1 writer for 60 s: zero reader errors, zero writer stalls attributable to readers; each reader's view is internally consistent (a fixed snapshot).
  • Cross-process: 2 processes share via lock file; reader in P2 sees a stable snapshot while writer in P1 commits.
  • oldest_reader_txid reflects the earliest pinned snapshot; dead readers reaped.

18.5 Conformance Fixtures

  • reader_table/concurrent_snapshot.scenario — interleaved reader/writer schedule + expected per-reader views.
  • reader_table/dead_pid_reap.scenario — kill a reader process → slot reclaimed.
  • reader_table/full.scenario — N+1 readers → ReadersFull.

18.6 Pitfalls

  • Reader slot not released (leaked ReadTxn) → oldest_reader_txid frozen → freelist bloat (P8). Debug: reader-table dump (stale pid/txid); oldest_reader_txid lag metric. Recovery: reap dead pids; for live leaks, fix caller.
  • TLS reuse across threads (thread pool reusing slot for different txn) → wrong txid pin. Fix: NOTLS mode or per-txn slots.
  • Reading meta during writer's meta flip → torn read of meta. Fix: meta read is a single-page load + checksum; on mismatch retry/other meta.
  • Dead-pid false positive (pid reused) → premature slot reclaim → reader sees reclaimed page. Fix: PID + start-time generation in slot.

18.7 Performance Concerns

Reader path: one atomic slot write at begin, one clear at end — no locks during the scan. Reader table fits one cache line per slot; false sharing if slots packed → pad to cache line. oldest_txid() is O(N slots) — cheap (N≈126). Writer never waits on readers.

18.8 Edge Cases

Reader opens exactly during commit (sees old or new txid atomically, never mixed). All slots full → ReadersFull. Process crashes holding a slot → reaped by liveness check. Single-process NOLOCK mode (caller guarantees no concurrency) — unsafe, documented.

18.9 Failure Analysis

Stale reader → file growth (not corruption); detection via oldest_reader_txid lag + map size growth; recovery = identify/kill stale reader or restart; mitigation = reader timeout policy in host. Reader-table corruption → Error::Corrupt; rebuild lock file (safe — derived state).

18.10 Operational Notes

Metrics: active_readers, oldest_reader_txid, reader_slots_used, readers_reaped. Runbook freelist_bloat.md (stale-reader → bloat → fix). Lock file is ephemeral/regenerable; document deleting it requires no active opens.

19. Phase 8 — Reader-Aware Freelist & Page Reclamation

19.1 Objectives

Reclaim freed pages safely: reuse a page only after the oldest live reader has advanced past the txid that freed it (INV-READER-PIN, Principle 9). Bound space amplification; expose freelist-starvation telemetry.

19.2 Detailed Implementation Steps

Theory anchors: Principle 9 (reader-aware reclamation), Principle 2 (free_db is itself COW); INV-READER-PIN (reuse iff freeing txid < oldest reader), INV-FREELIST-CONSISTENT (no page in two sets); ADR 015 (txid-keyed PNL freelist); Rosenblum & Ousterhout LFS 1992 (cleaner ↔ freelist reclamation analogy), Bernstein & Goodman 1981 (snapshot-safe reuse); MM6 (reclamation is garbage collection gated on the oldest live snapshot).

  • freelist.rs: free_db = txid→PNL B+tree. On commit, write this txn's freed PNL under key txid (already in P6).
  • Allocation in a write txn now prefers reuse: alloc_page():
    1. compute oldest = reader_table.oldest_txid() (or current txid if no readers).
    2. scan free_db keys < oldest (these pages are safe), pop a pgno from their PNLs.
    3. else append (bump next_pgno, grow if needed).
  • pending handling: pages freed by the current txn go to pending, written under the new txid only on commit (they aren't reusable within the same txn — they belong to the not-yet-published snapshot).
  • Reclaim of freelist's own pages (the free_db is itself COW) — careful self-reference: allocating from free_db while modifying free_db (LMDB's classic re-entrancy; reserve a small loaning buffer).
  • Coalesce adjacent freed PNLs; drop emptied txid keys.

19.3 Deliverable

Steady-state writes reuse freed pages; file size stabilizes under churn when readers are short-lived. mdbx-cli stat shows freelist size, oldest reader, reclaimable pages.

19.4 Acceptance Criteria

  • Churn workload (insert N, delete N, repeat) with no long readers → file size bounded (≤ working set + small slack), not monotonically growing.
  • With a held reader at txid R, pages freed at txid > R are NOT reused (assert); after reader drops and oldest advances, they become reusable.
  • verify: union(reachable, freelist, meta) == all pages; no overlap.

19.5 Conformance Fixtures

  • freelist/reuse_after_reader_drop.scenario — hold reader, churn, drop, observe reuse.
  • freelist/no_reuse_while_pinned.scenario — assert non-reuse.
  • freelist/self_reentrancy.scenario — alloc-from-free_db while editing free_db.
  • freelist/coalesce.json — adjacent PNL merge.

19.6 Pitfalls

  • Reusing a page freed at txid ≥ oldest reader → reader corruption. Manifest: reader reads overwritten page (wrong/torn data). Root: using current txid instead of oldest-reader. Debug: assert candidate pgno not in any pinned snapshot's reachable set (debug mode walks). Recovery: none post-fact — prevent via correct oldest.
  • Freelist re-entrancy (free_db edit needs a page, takes from free_db being edited) → infinite recursion / inconsistency. Fix: loaning page reserve; bounded edit.
  • pending reused within same txn → publishes a page still referenced by the new snapshot. Fix: pending → free only at commit under new txid.
  • PNL fragmentation → many tiny free entries, poor reuse. Fix: coalesce + descending sort.
  • Forever-held reader → unbounded growth (freelist starvation). Detect: oldest_reader_txid lag + pages_held_by_readers. Recovery: reap/kill stale reader (runbook).

19.7 Performance Concerns

alloc_page scans free_db (B+tree lookup, cheap) per allocation; cache the current reusable PNL cursor to avoid re-descend per page. Coalescing is O(PNL) — amortize at commit. Freelist write is part of the durable set (extra pages flushed per commit) — keep PNLs compact. Reuse improves locality (recent pages warm in cache).

19.8 Edge Cases

No readers → oldest = current txid → all freed pages reusable immediately. All freed pages pinned → must append/grow despite free pages existing (the bloat case). free_db itself grows under heavy churn. txid wraparound (u64 → effectively never, but documented). Empty freelist → always append.

19.9 Failure Analysis

Freelist inconsistency (page in both reachable and free) → verify flags double_referenced_pages; recovery = copy --compact rebuilds a clean file. Premature reuse bug → reader corruption (high severity) → caught by INV-READER-PIN debug asserts + differential reader tests in CI. Blast radius: readers pinned across the bad reuse.

19.10 Operational Notes

Metrics: freelist_pages, reclaimable_pages, pages_held_by_readers, oldest_reader_txid, alloc_from_freelist_total, alloc_append_total. Runbook freelist_bloat.md. Document: long-lived read txns are the #1 operational hazard; cap reader lifetime in hosts.

20. Phase 9 — Named & Nested Sub-Databases, Duplicate Keys (DUPSORT)

20.1 Objectives

Support multiple named KV namespaces in one env (each a B+tree rooted in the main DB), and duplicate keys (multiple sorted values per key) via DUPSORT/sub-pages.

20.2 Detailed Implementation Steps

Theory anchors: Principle 2 (sub-DB roots COW up to the single published root), Principle 8 (sub-DB root is a pgno revalidated per txn); INV-COW-NO-INPLACE, INV-FREELIST-CONSISTENT (deleting a sub-DB frees its whole tree), INV-DUP-COMPARATOR-STABLE (dup order never silently changes); ADR 013 (per-DB + per-dup comparator); Comer 1979 (nested B+trees), BoltDB bucket.go (bucket = sub-DB pattern); MM4 (nested DUPSORT multiplies the COW path).

  • db.rs: open_db(name, flags): a named DB is a leaf entry in the main DB with flags=SUBDB, value = DbInfo of its sub-tree root. CREATE allocates an empty sub-tree on first write. Db handle caches {dbi, root, flags}, revalidated against the live meta/main-DB each txn.
  • DUPSORT: a key's value region holds either an embedded sub-page (SUBP, small dup set) or a sub-tree root (DUPDATA, large dup set), itself a B+tree keyed by value bytes. DUPFIXED/LEAF2 packs fixed-size dup values densely (no per-value header).
  • cursor.rs: dup navigation — first_dup/next_dup/seek_dup/count_dups; cursor stack extends into the dup sub-tree.
  • put with NODUPDATA rejects exact dup; del(key, Some(val)) removes one value; del(key, None) removes all values.
  • Sub-DB roots are updated COW like any tree → main DB root changes when a sub-DB changes (lineage chains to the single published root).

20.3 Deliverable

env/txn.open_db("users"), open_db("index"); DUPSORT DB stores multiple values per key, iterable in order. examples/named_dbs.rs, examples/dupsort.rs.

20.4 Acceptance Criteria

  • ≥ 1000 named sub-DBs coexist; each independently consistent; main-DB lists them.
  • DUPSORT: insert 1 M (key, value) with heavy duplication; next_dup iterates values sorted; count_dups correct.
  • Differential vs a model BTreeMap<Vec<u8>, BTreeSet<Vec<u8>>>.
  • Sub-page → sub-tree promotion when a dup set outgrows a page; transparent to API.

20.5 Conformance Fixtures

  • dupsort/subpage_to_subtree.scenario — dup set crossing the page threshold.
  • dupsort/dupfixed_pack.json — LEAF2 dense packing.
  • named_dbs/many_subdbs.scenario, subdb_root_cow.json — sub-DB change updates main root.
  • dupsort/del_one_vs_all.json.

20.6 Pitfalls

  • Sub-DB root staleness (cached Db.root after another txn changed it). Manifest: reads/writes target an old sub-tree. Fix: revalidate Db against current main-DB each txn (root may have moved via COW).
  • Sub-page vs sub-tree boundary bugs → lost dups on promotion. Debug: assert dup count preserved across promotion.
  • DUPFIXED size mismatch (variable-length value in a fixed-dup DB) → corruption. Fix: enforce fixed length at put.
  • Nested COW depth (dup sub-tree → key leaf → main DB → root) multiplies write amplification. Note in §Performance.
  • Comparator for dup values distinct from key comparator → ordering bugs. Fix: per-DB dup comparator stored in flags.

20.7 Performance Concerns

Nested trees deepen the COW path (sub-tree root change → key-leaf COW → main-DB path COW → new root) → more pages copied per dup mutation. DUPFIXED/LEAF2 maximizes fan-out for fixed values (e.g., 8-byte secondary-index postings). Sub-page avoids a full sub-tree for small dup sets (locality). Opening many sub-DBs: main-DB lookups, cache Db handles.

20.8 Edge Cases

Empty named DB; deleting a named DB (free its whole tree → freed); DUPSORT key with exactly one value (sub-page of one); promotion exactly at threshold; reverse-ordered dup comparator; opening a DUPSORT DB without the flag (mismatch → error).

20.9 Failure Analysis

Sub-DB metadata inconsistency (DbInfo root points to wrong tree) → verify walks all sub-DBs; recovery via copy. Promotion bug losing dups → caught by dup-count assert + differential. Blast radius: the affected sub-DB only (others independent).

20.10 Operational Notes

Metrics: subdbs_open, dupsort_promotions, dup_subtree_pages. mdbx-cli stat <dbname> per sub-DB. Document the write-amplification cost of deeply nested DUPSORT for high-churn secondary indexes.

21. Phase 10 — Durability Modes, WRITEMAP, SIGBUS Handling, Spill

21.1 Objectives

Implement and harden the durability/perf tradeoff flags (SYNC/NOSYNC/WRITEMAP/MAPASYNC/NOMETASYNC), handle SIGBUS from mapped-region I/O errors, and add dirty-set spill for huge write txns.

21.2 Detailed Implementation Steps

Theory anchors: Principle 5 (ordering held across all modes), Principle 12 (crash-only), Principle 13 (fail-stop on SIGBUS), Principle 1 (WRITEMAP writes straight into the page cache); INV-META-DURABLE-ORDER (spill never publishes early), INV-CHECKSUM-VALID (the only WRITEMAP wild-write backstop); ADR 008 (mmap vs pwrite), ADR 009 (sync primitive), ADR 010 (SYNC/NOSYNC/WRITEMAP/MAPASYNC); Bovet/Cesati (writeback timing), Crotty/Leis/Pavlo CIDR 2022 (lost-I/O-ordering + transactional-safety pitfalls answered here); MM7 (the map is an attack/corruption surface).

  • flags.rs/txn.rs:
    • WRITEMAP: map PROT_WRITE; commit writes into the map directly (no separate dirty Box frames → lower memory, but exposes the map to wild writes — backstopped only by ADR 012 checksums).
    • NOSYNC: skip SYNC-DATA + SYNC-META; durability deferred to env.sync() or OS writeback (ordering still enforced relative to subsequent commits via barrier on next sync).
    • MAPASYNC (WRITEMAP+): msync(MS_ASYNC) — kernel writeback, weak durability.
    • NOMETASYNC: sync data but not meta (meta durable lazily) — last commit may be lost on crash, never corrupt.
  • SIGBUS handler (mmap.rs): install handler; on SIGBUS within mapped range → set a thread-local error flag, longjmp/recover → translate to Error::Sigbus (mapped-file I/O error, e.g., disk failure or truncation). Document the non-WRITEMAP read path SIGBUS too.
  • Spill (txn.rs): when dirty set exceeds a budget, write some dirty pages early (NOSYNC) to the map/file and drop their frames, keeping the txn bounded; final commit syncs all (ordering preserved: meta still last + synced).

21.3 Deliverable

All durability modes selectable; a documented crash-outcome matrix; SIGBUS surfaces as a recoverable Error not a process abort; multi-GB write txns complete within a bounded memory budget via spill.

21.4 Acceptance Criteria

  • Crash matrix verified by injection: (SYNC→no loss), (NOSYNC→lose un-synced tail, never corrupt), (NOMETASYNC→may lose last commit, never corrupt), (MAPASYNC→writeback-window loss, never corrupt).
  • Simulated I/O error (e.g., dmsetup error target / truncate under map) → Error::Sigbus, env remains queryable from prior committed state where possible.
  • 4 GiB single write txn completes with RSS bounded (< configured spill budget + slack).

21.5 Conformance Fixtures

  • crash/nosync_tail_loss.scenario, nometasync_lastcommit.scenario, mapasync_window.scenario.
  • sigbus/truncate_under_map.scenario, dm_error_target.scenario.
  • spill/large_txn_budget.scenario.

21.6 Pitfalls

  • WRITEMAP wild write (a bug elsewhere writes through the map) silently corrupts the DB with no syscall to trap. Manifest: corruption with no I/O error. Debug: run with WRITEMAP off in tests; checksums catch on read. Mitigation: WRITEMAP off by default; checksums on for WRITEMAP builds.
  • NOSYNC assumed durable → data loss surprise on power cut. Fix: clear docs; default SYNC.
  • SIGBUS in arbitrary thread → can't longjmp safely from non-owning context. Fix: handler sets flag; only owning txn thread recovers; others abort cleanly.
  • Spill breaks ordering if spilled pages become visible before meta. Fix: spill writes are NOSYNC and not published until meta flip; they're either reachable from the new (unpublished) root or in freed — never the old live tree.
  • MS_ASYNC mistaken for durable → same as NOSYNC trap.

21.7 Performance Concerns

WRITEMAP eliminates the user→kernel copy (write straight into page cache via the map) → higher write throughput, lower memory; cost = corruption exposure. NOSYNC/MAPASYNC trade durability for ~10× commit throughput by removing fsync from the hot path. Spill threshold tuning balances memory vs extra I/O (spilled pages may be re-touched). Dirty-frame pooling cuts allocator churn (non-WRITEMAP).

21.8 Edge Cases

WRITEMAP + RDONLY (illegal combo → error). NOSYNC then clean close without env.sync() (data in page cache, durable on OS flush, lost only on power cut). SIGBUS during meta read at open (storage failing) → Error::Sigbus at open. Spill then abort (discard spilled pages → they're in freed/unreachable, reclaimable).

21.9 Failure Analysis

Power loss in NOSYNC: lose all commits since last sync (bounded, known); never corrupt (ordering held). WRITEMAP corruption: high severity, no auto-detect without checksums; recovery from backup/copy. Disk failure → SIGBUS → env degraded to read of last durable state; operator restores. Detection: Error::Sigbus, checksum_errors, crash-matrix tests.

21.10 Operational Notes

Metrics: sync_mode, msync_total, spill_pages, sigbus_total. Runbook sigbus.md. Document the durability matrix prominently. Recommend SYNC default in production; NOSYNC only with external power protection or acceptable loss window.

22. Phase 11 — Integrity Verifier, Online Copy & Compaction

22.1 Objectives

Provide a standalone integrity walker (page accounting, checksum, order, freelist consistency) and an online copy/compact that produces a defragmented, freelist-clean file from a live env (backup primitive).

22.2 Detailed Implementation Steps

Theory anchors: Principle 10 (checksums detect; verifier is the offline detector), Principle 13 (fail-stop on impossible state), Principle 9 (compact drops stale-reader bloat); INV-FREELIST-CONSISTENT (union/disjointness walk), INV-LAST-PGNO (bound the walk), INV-CHECKSUM-VALID, INV-DB-VERSION; ADR 027 (FORMAT.md is what verify enforces); Petrov Part II (consistency checking), Rosenblum & Ousterhout (compaction ↔ LFS cleaning); MM6.

  • tools/verify: open RDONLY at a snapshot; walk main DB + all sub-DBs + free_db; assert: every reachable page within last_pgno (INV-LAST-PGNO); checksums valid (INV-CHECKSUM-VALID); keys monotone per node; separators consistent; union(reachable, free, meta) == all pages, disjoint (INV-FREELIST-CONSISTENT). Report leaked_pages, double_referenced_pages, checksum_errors.
  • env.copy(dst, compact):
    • non-compact: copy pages up to last_pgno (consistent because reads from a pinned snapshot; mmap copy).
    • compact: open a read snapshot, iterate all DBs via cursors, rebuild a fresh tree in dst (no freelist, optimal packing, new contiguous pgnos) → smaller file, drops stale-reader bloat and fragmentation.
  • mdbx-cli verify, mdbx-cli copy --compact dst.

22.3 Deliverable

verify certifies a file; copy --compact yields a minimal, defragmented backup while the env keeps serving. Backup = consistent point-in-time snapshot (pinned reader).

22.4 Acceptance Criteria

  • verify detects injected faults: double-referenced page, leaked page, bad checksum, non-monotone keys, child pgno > last_pgno — each with the right CorruptKind.
  • copy --compact of a bloated file (held-reader scenario) produces a file sized ≈ live working set; reopened verify passes; data identical (differential).
  • Copy runs concurrently with writes; backup reflects the snapshot at copy start.

22.5 Conformance Fixtures

  • verify/double_ref.img, leaked_page.img, bad_checksum.img, nonmonotone.img, child_oob.img.
  • copy/bloated_to_compact.scenario — before/after sizes + identical-data oracle.

22.6 Pitfalls

  • Verifier following a torn page into garbage → false positives/crash. Fix: bounds + checksum check before deref; bound walk by last_pgno.
  • Compact copy missing sub-DBs → silent data loss in backup. Fix: enumerate all SUBDB entries recursively.
  • Copy not pinning a snapshot → inconsistent backup (writer advances mid-copy). Fix: hold a ReadTxn for the whole copy.
  • Non-compact copy of a sparse file copying holes → bloated dst. Fix: copy only last_pgno pages; preserve sparseness.

22.7 Performance Concerns

verify is a full read traversal: O(pages); sequential where possible (madvise(WILLNEED)/SEQUENTIAL). Compact rebuild is O(entries) inserts into a fresh tree — bulk-load fast path (append-mostly, no splits churn) recommended. Copy I/O bound; throttle to avoid starving the live workload.

22.8 Edge Cases

Verify an actively-written env (snapshot is fine; freelist for newer txns may show pending). Compact a DUPSORT DB (rebuild dup sub-trees). Copy to same filesystem (space for full copy). Empty env copy. Verify with checksums disabled (skip checksum checks, still do accounting).

22.9 Failure Analysis

Verifier reports corruption → operator decides restore-from-backup vs copy --compact (which can rebuild around some issues but not recover lost data). Copy failure (ENOSPC on dst) → partial dst discarded; source untouched. Detection: verifier exit codes + report. Postmortem artifact: verifier report + both metas.

22.10 Operational Notes

Metrics: verify_pages, verify_errors{kind}, copy_bytes, copy_duration. Runbook: periodic verify in CI/cron; copy --compact as scheduled backup + bloat remediation. Backups are byte-files → store/restore is a file copy.

Theory anchors: Principle 13 (fail-stop, never UB, on hostile bytes), Principle 5 (crash-injection proves durability ordering), Principle 6 (atomicity proven by killing at SYNC-META); INV-META-DURABLE-ORDER, INV-COW-NO-INPLACE, INV-READER-PIN, INV-FREELIST-CONSISTENT (all become property-test oracles); ADR 019 (proptest + crash-injection), ADR 020 (cargo-fuzz), ADR 021 (differential vs BTreeMap), ADR 023 (miri/ASan); Bornholt et al.   • Fuzzer finds UB in unsafe codec (out-of-bounds slot offset) → must bounds-check every decoded offset against page bounds. Fix: validated accessors; never trust on-disk offsets.

Fuzzing throughput depends on open/op cost — use small tmpfs DBs. Differential overhead is the model's cost (BTreeMap) — fine. Crash-injection is process-spawn bound — parallelize schedules.

Trust boundaries: on-disk file = untrusted (codec totality required); host process = trusted (WRITEMAP relies on it); OS = trusted for sector atomicity + fsync honesty (documented assumption; virtualized disks may lie → SECURITY.md warns).

Structural defenses the design itself provides (not bolted-on). Several threat classes are neutralized by the architecture rather than by added checks: (1) No log-replay attack surface — because recovery is meta selection, not replay (Principle 7, MM3), there is no log parser for a malicious file to attack; the only recovery input is two fixed-size meta pages. (2) No partial-commit visibility — COW + meta-flip means an interrupted or malicious half-write is never reachable from a published root (Principle 2/5), so torn intermediate state cannot be observed, only discarded. (3) Reader isolation by construction — INV-COW-NO-INPLACE means a writer (even a buggy one) physically cannot mutate a page a reader can reach, so a malicious or runaway writer cannot corrupt an in-flight read. (4) Bounded blast radius — the single-writer rule (Principle 3) means at most one transaction is ever in-flight, so any single corruption or crash is scoped to that one transaction. (5) Self-describing redundancy — each page stores its own pgno (§8.2), so a misdirected/misplaced page write is detectable by comparing stored vs expected pgno during verify.

Documented hazard (verifiable source). The risks of building a DBMS on mmap — the OS writing dirty pages back out of the engine's intended order, single-threaded kernel page eviction stalling under memory pressure, TLB shootdowns on unmap, and SIGBUS surfacing storage errors as a signal rather than a return code — are documented and argued in Crotty, Leis & Pavlo, "Are You Sure You Want to Use MMAP in Your DBMS?" (CIDR 2022), which draws on the production experience of real mmap-using systems. This engine's answers are explicit: durability ordering re-imposed by an msync/fsync barrier (INV-META-DURABLE-ORDER), the SIGBUS handler of Phase 10, and the pwrite/O_DIRECT escape hatch (ADR 008 "When the Rejected Choice Wins") for deployments where mmap's tradeoffs are unacceptable. No company-specific public postmortem is cited here because none could be verified to the standard's no-fabrication bar; the CIDR paper is the verifiable documented source.

Compatibility & Versioning

  • Storage compatibility: on-disk format versioned by meta.fmt_ver (major.minor). Same major = forward/backward readable within minor additions (new optional flags). Major bump = migration via copy. FORMAT.md is normative.
  • Endianness: little-endian on disk regardless of host; opening on opposite-endian host works (codec converts). (Phase 0 may pin same-endian; cross-endian = documented support target.)
  • Page size: fixed per file at create; recorded in meta; engine adapts to the file's page size on open.
  • API stability: semver on the crate. Env/Txn/Cursor/Db signatures stable within a major; additive flags are minor.
  • Wire: none (embedded; no network).
  • Deprecation policy: flags/features deprecated for ≥1 minor before removal at next major; documented in CHANGELOG.
  • Rolling upgrade: a newer engine opens an older-major-equal file unchanged; mixed-version processes sharing one env must share the same major (lock-file/reader-table layout is part of the contract).
  • C ABI: mdbx.h versioned; symbol-versioned cdylib.
  • Lock-file/reader-table contract: the shared lock-file layout ({write_mutex_region, reader_table[N]} and ReaderSlot shape, §11) is part of the major version — two processes sharing an env must agree on it, so changing slot layout is a major bump even though the data file is untouched.
  • Geometry compatibility: page_size and maxpg are immutable for a file's life; an engine that defaults to a different page size still honors the file's recorded size on open (it does not rewrite geometry).

  - reads meta.fmt_ver = {major 1, minor 1}; major matches → proceed.
  - PGTXID flag is unknown → old engine ignores the reserved bytes it doesn't understand
    (they were reserved/zero in v1.0's layout) → reads succeed; the field is simply unused.
New engine (v1.1) opening a v1.0 file:
  - minor 0 < 1 → PGTXID-dependent features disabled for this file; reserved bytes treated
    as absent → full functionality minus the new debug field.
Rule: a minor may only ADD optional, flag-gated fields in reserved space and may never
  change the meaning/size of an existing field — that is a MAJOR bump requiring `copy`
  migration. `FORMAT.md` records, per field, the minor it was introduced.

This is why every reserved byte in §8.2/§8.3 is documented as reserved-zero: it is the forward-compatibility budget. A field that is not reserved-zero in an old version cannot later be repurposed without a major bump.

Performance Engineering

  • Benchmarking: criterion micro + macro (fillseq/fillrandom/readseq/readrandom/commit), parametrized value+dataset size, warm/cold reported.
  • Profiling: perf record + inferno flamegraphs; perf stat for IPC, cache, dTLB.

  • Tracing: commit-phase spans to attribute latency (COW copy vs sync).
  • Allocator analysis: dirty-frame pooling (non-WRITEMAP); minimize per-op alloc; jemalloc/mimalloc comparison.
  • Lock analysis: write mutex is the only contended lock (writers); readers lock-free → measure write-lock wait under contention.
  • Cache analysis: node search (linear vs binary for small nodes), key compare (memcmp/SIMD), node layout for cache lines.
  • Syscall analysis: reads have none (faults); writes = pwrite+fsync/msync — count and batch (one sync/commit).

Scalability Analysis

  • Bottlenecks: (1) single writer → write throughput ceiling = 1 commit chain at a time; (2) fsync latency (SYNC); (3) address space (max DB); (4) oldest-reader pin → space.
  • Scaling ceilings: write = thousands of SYNC commits/s (device fsync) or tens of thousands NOSYNC; read = millions/s/core, scales with cores (lock-free, shared map). DB size ≤ virtual address space (TB+ on 64-bit).
  • Horizontal: none (embedded, single node). Sharding/replication = host's job (cross-link #100/#69-style layer above).
  • Vertical: more RAM → larger working set cached (fewer faults); more cores → more read throughput (readers independent); faster disk → faster SYNC commits.
  • Sharding/partitioning: multiple envs/files for parallel writers (one writer per file) — app-level fan-out.
  • Replication pressure: N/A in-engine; copy provides snapshot for external replication.
  • Coordination overhead: only the write mutex + reader-table scan (O(N slots), tiny).
  • Storage growth: bounded by working set + freelist (oldest-reader-gated); copy --compact reclaims.
  • Metadata scaling: reader table fixed (N slots); many sub-DBs = main-DB entries (B+tree, scales); freelist scales with churn × reader lag.

Bottlenecks in order, with the lever that moves each. (1) Single-writer serialization — the binding write-throughput ceiling; lever: batch many mutations per txn (C3/M7), or shard into multiple envs/files (one writer each), or change the engine class entirely (§Alternative Architectures A3, multi-writer Bw-tree). (2) fsync latency under SYNC — dominates commit latency on slow storage (C4); lever: faster device, NOSYNC/MAPASYNC where loss is acceptable (M5), or group-commit by batching. (3) Oldest-reader pin → space — long readers convert freed pages into retained garbage (C9); lever: host-side reader-lifetime cap, copy --compact. (4) Address space — caps single-file DB size (C8); lever: 64-bit (TB+), or app-level sharding across files. (5) TLB pressure on large maps — degrades warm reads beyond TLB reach (C11); lever: MADV_HUGEPAGE (M9). The practical ceiling is therefore: one node, one writer, thousands–tens-of-thousands of commits/s, millions of reads/s/core, DB size bounded by address space — and the only lever past single-node write throughput is to step outside this engine's design (sharding above it, or a different storage class).

Mental Models & First Principles

The compressed intuitions an expert holds about a memory-mapped, copy-on-write storage engine. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it. Every cited anchor resolves.

  • MM1 — The file is the address space; a read is a page fault, not a syscall. In a single-level store there is no read() on the hot path and no buffer pool of your own — pgno → base + pgno·P is a pointer, and touching a cold page traps into the kernel as I/O. Predicts: warm reads are bounded by TLB/cache and CPU pointer-chase, not by I/O; cold reads cost a major fault (device latency); your only prefetch lever is madvise. Bug without it: building a user-space cache "for speed" that double-caches the page cache, wasting RAM and destroying the zero-copy property. Applied: Principle 1, §3 (mmap single-level store box), §4 (read-throughput target), Phase 1.7, §24.7, ADR 004.
  • MM2 — Loss of control is the price of mmap; you trade explicit eviction, prefetch, and I/O ordering for radical simplicity. Crotty/Leis/Pavlo (CIDR 2022) name the four things you give up: transactional safety (the OS can write a dirty page back whenever it likes), single-threaded page eviction in the kernel, TLB shootdowns on unmap, and lost control of write ordering. Predicts: in NOSYNC/MAPASYNC the kernel may persist a page before you intend, so durability ordering must be re-imposed with an explicit msync/fsync barrier — the OS will not order writes for you. Bug without it: assuming "the data is in the map, therefore it is safe," and discovering the meta hit disk before the data pages it points at. Applied: ADR 004/008/010, Principle 5, INV-META-DURABLE-ORDER, §21.7, §Comparative Architecture.
  • MM3 — Recovery is selection, not replay; the newest valid meta is the truth. With dual alternating meta pages and a monotonic txid, "what is the committed state?" is answered by reading two pages and picking the higher txid that passes its checksum. There is no log, no redo, no undo, no scan. Predicts: open is O(1) regardless of database size; a kill -9 mid-commit costs exactly one transaction, atomically; adding any replay logic is a smell that you no longer trust the meta-flip. Bug without it: writing ARIES-style recovery and thereby implicitly trusting in-place writes the COW model forbids. Applied: Principle 7, §8.3/§8.7, Phase 2.2, Phase 6, INV-META-MONOTONIC-TXID, §4 (RTO = O(1)).
  • MM4 — Copy-on-write turns every mutation into a path-copy; write-amplification is the cost you pay for never blocking a reader. Touching one key copies the whole root→leaf path (≈ tree height pages) plus any split/merge ancestors; nested DUPSORT multiplies it (dup sub-tree → key leaf → main DB → root). Predicts: COW shines on read-heavy and batched-write workloads and bleeds on tiny random in-place updates (where a WAL would append one small record); batching many puts into one txn amortizes the path-copy because later puts reuse already-dirtied pages. Bug without it: per-key commits on a high-churn small-row table, then blaming the disk for the write volume. Applied: Principle 2, §4 (write-amplification row), Phase 4.7, §20.7 (nested COW), ADR 006, §Comparative Architecture (vs WAL).
  • MM5 — A snapshot is an immutable root frozen in time; MVCC here is "old pages stay alive while someone is looking." A reader pins (root, txid) and walks a tree that, by INV-COW-NO-INPLACE, can never be mutated under it — no latches, no copying, no blocking. Predicts: readers never block the writer and the writer never blocks readers; correctness depends entirely on not reusing a page any live snapshot can still reach. Bug without it: taking a page latch on the read path "to be safe," reintroducing the reader↔writer contention the whole design exists to avoid. Applied: Principle 4, §8.6, Phase 7.2, INV-READER-PIN, MM6.
  • MM6 — Page reclamation is garbage collection gated on the oldest live reader. A page freed at txid F is reusable only once oldest_reader_txid > F; until then it is garbage that must be retained, exactly like a log-structured FS cleaner cannot reclaim a segment a snapshot still references (Rosenblum & Ousterhout). Predicts: a single long-lived reader freezes oldest_reader_txid and the file grows without bound even though it "holds" little live data — freelist starvation; killing the reader lets reclamation resume. Bug without it: reusing a page based on the current txid instead of the oldest reader's txid, overwriting data a reader is mid-scan on. Applied: Principle 9, §8.2/§8.6, INV-READER-PIN, INV-FREELIST-CONSISTENT, §Failure Modes & Recovery (bloat), runbook freelist_bloat.md.
  • MM7 — The mapped region and the on-disk file are trust surfaces: one for wild writes, one for hostile bytes. A bug anywhere in the process can scribble through a WRITEMAP mapping with no syscall to trap it; a corrupt or malicious file can carry out-of-bounds slot offsets, bogus pgnos, and lying PNL counts straight into the decoder. Predicts: WRITEMAP corruption is detectable only by checksum-on-read (no I/O error fires); the page codec must be total over arbitrary bytes (bounds-check every decoded offset/pgno) or a fuzzer — and an attacker — turns it into UB. Bug without it: trusting on-disk offsets, yielding an out-of-bounds read the moment a file is truncated or tampered. Applied: Principle 13, §21.6 (WRITEMAP wild write), §Threat Model (malicious file), Phase 12.2 (codec totality), INV-CHECKSUM-VALID, ADR 012.
  • MM8 — Single-page atomicity is the linchpin; the entire design is a bet that a meta write is all-or-nothing. Crash consistency rests on the device persisting a single page (≤ its atomic-write unit) without tearing; the dual-meta + parity scheme exists precisely so a torn write damages only the new copy, leaving the previous meta intact. Predicts: if the storage layer (a lying virtualized disk, a 512-vs-4K sector mismatch, a filesystem that splits the write) violates this, recovery becomes ambiguous and you must fall back to checksum + the other meta; everything else in the engine is sound only relative to this assumption. Bug without it: choosing a page size larger than the device's atomic-write granularity and getting torn metas that pass neither checksum. Applied: Principle 6, §8.3/§8.9, §4 (meta-write-atomicity row, "correctness linchpin"), INV-META-ALTERNATE, INV-CHECKSUM-VALID, §Threat Model (torn/reordered writes).

  • LMDB (Howard Chu, Symas/OpenLDAP). The direct ancestor and near-twin: it made exactly this engine's choices — mmap single-level store, COW B+tree, dual-meta commit, reader table, reader-aware freelist, no WAL. Its one decision worth contrasting is implementation form: a single hand-tuned mdb.c of dense C and macros optimized for minimal size and maximum speed, where this engine trades a little of that for Rust's compile-time lifetime enforcement of the zero-copy contract (Principle 14). LMDB wins where embedding a few hundred KB of audited C with no toolchain assumptions is paramount (it ships inside OpenLDAP and Monero). Everything else in this blueprint is, deliberately, LMDB's architecture re-derived from first principles.
  • SQLite. Made the opposite durability call: an in-place B-tree with either a rollback journal (undo) or, since 2010, a write-ahead log (redo). That is the right call for SQLite's universe — tiny random updates to small rows in the most widely deployed database on earth — because a WAL appends one small record where COW rewrites a whole path (MM4). SQLite even offers an mmap read mode, and the CIDR 2022 paper uses it as a cautionary example; SQLite wins wherever small-row OLTP churn and SQL itself are the workload, which this engine explicitly does not provide (non-goal: SQL/query planner).
  • LevelDB / RocksDB (Google / Meta). Chose a log-structured merge tree instead of a B-tree: buffer writes in an in-memory memtable, flush to immutable sorted SSTables, and compact in the background. This inverts the amplification profile — writes are cheap and sequential up front, paid back as compaction I/O later — making it the right substrate for write-heavy and ingest-heavy workloads (RocksDB backs MySQL/MyRocks, Kafka Streams, many KV services). It wins exactly where this COW-B+tree engine's per-commit path-copy hurts: sustained high-volume random writes. The contrast (§Alternative Architectures A2) is the canonical "B-tree vs LSM" storage-engine decision.
  • WiredTiger (MongoDB's storage engine). The buffer-managed, multi-writer counterpoint that keeps a B-tree: it runs its own cache with eviction threads, MVCC with document/page-level locking allowing concurrent writers, and durability via WAL + periodic checkpoints. It wins where write throughput must scale past a single core and the working set exceeds RAM under a managed cache — the regimes where ADR 004 and ADR 005 say the rejected choices win. Studying its src/btree/src/txn shows the machinery (cache manager, eviction, journal) this engine deliberately omits by delegating caching to the kernel and serializing writers.
  • bbolt (etcd's fork of BoltDB). The closest idiomatic sibling: a Go reimplementation of LMDB's design — mmap, COW B+tree, dual meta, buckets as sub-DBs, MVCC readers — backing etcd, Consul, and much of the Go ecosystem. Its instructive difference is the freelist: classic BoltDB keeps the entire freelist in memory and pays an O(n) cost to track and persist it, a known scaling pain that etcd's fork worked to mitigate. That is the concrete reason this engine chooses a txid-keyed B+tree freelist with a cached reusable cursor (ADR 015, §8.7) rather than a flat in-memory list.

Back-of-Envelope Capacity Model

The numbers an expert computes from §4 (System Constraints) before writing any code. Each is derived step-by-step; the §4 input is named. P = page size (default 4096 B).

  • C1 — Tree height for N keys (the read-path fault count). Input: §4 page size 4 KiB; §8.4 node layout. With a 16-B header + slot dir and average key+pointer ≈ 32 B, branch fan-out f ≈ (4096−16)/32 ≈ 127. Height h = ⌈log_f N⌉: for N = 10⁶, h = ⌈log₁₂₇ 10⁶⌉ = ⌈2.85⌉ = 3; for N = 10⁹, h = ⌈4.28⌉ = 5. So a point lookup is ≤ 3 page touches at a million keys, ≤ 5 at a billion — the number of potential major faults on a cold read and the depth of the pointer chase warm (§14.7).
  • C2 — Warm point-lookup throughput. Input: §4 "≥ 5–20 M lookups/s/core" and C1 height. At h = 3 and ~30 ns per L2/L3-missing node touch + binary search, a lookup costs ≈ 3 × 30 ns ≈ 90 ns + ~20 ns compare ≈ 110 ns → ~9 M lookups/s/core. Confirms the §4 5–20 M band is the right order of magnitude and that height (C1), not syscalls, sets read throughput — the MM1 prediction.
  • C3 — COW write-amplification per single-key commit. Input: §4 "whole root→leaf path copied per commit" + C1. One isolated key change dirties h pages on the path + the meta = (h+1) × P. At h = 3, P = 4 KiB: 4 × 4096 = 16 KiB written to durably commit one ~100-B value → ~160× amplification. Mitigation math: batching B keys whose paths overlap shares the upper levels; e.g. 1000 random keys touch ≈ 1000 leaves but only ~f shared branches, so amortized ≈ (1000 + ~8 + ~1)/1000 ≈ 1.01 paths/key — the quantitative case for one txn per batch (Principle 2, MM4, §15.7).
  • C4 — SYNC commit rate is fsync-bound. Input: §4 "commit latency p50 ≈ device fsync (50–500 µs NVMe / 5–10 ms HDD)" + "one fsync/commit dominates." Ceiling commits/s ≈ 1 / fsync_latency: NVMe at 100 µs → ~10⁴ commits/s; HDD at 8 ms → ~125 commits/s. This is why §4 lists "hundreds–few thousand commits/s" for SYNC and why batching (C3) is the only lever to raise logical write rate without weakening durability.
  • C5 — NOSYNC commit rate is CPU/COW-bound. Input: §4 "NOSYNC ≥ tens of thousands commits/s" + C3 path-copy cost. With fsync removed, a commit is (h+1) page copies + freelist edit ≈ a few µs of memcpy + bookkeeping → ~10⁵ commits/s order. Confirms the §4 "≥ 10× SYNC" claim (C4 NVMe 10⁴ → NOSYNC 10⁵) and locates the new bottleneck at page-copy memcpy bandwidth, not the device.
  • C6 — Reader-table memory and the concurrency ceiling. Input: §4 "N ≤ reader-table slots, default 126" + §11 ReaderSlot{pid:u32, tid:u64, txid:u64} = 20 B (padded to a 64-B cache line to avoid false sharing, §18.7). Table = 126 × 64 B = 8064 B ≈ 2 pages. oldest_txid() scans all slots: 126 reads ≈ a few hundred ns — negligible per commit. Confirms the reader table is ~2 pages and the oldest-reader computation is effectively free (§18.7).
  • C7 — Dirty-set memory for a large write txn (the spill trigger). Input: §4 "RSS ≈ working set + small fixed state"; §21.2 spill. A write txn buffering dirty frames as Box<[u8;P]> costs dirty_pages × P. Inserting 1 M random 100-B keys ≈ touches ~10⁶/127 ≈ 7900 leaves + branches ≈ ~8000 dirty pages → 8000 × 4 KiB ≈ 31 MiB held before commit. A 4 GiB single txn (§21.4) would need 4 GiB / 4 KiB = 10⁶ dirty frames = 4 GiB RAM → exceeds budget → this is exactly why spill exists (§21.2): flush early, drop frames, keep RSS bounded.
  • C8 — Address-space ceiling and vm.max_map_count. Input: §4 "Max DB size bounded by virtual address space (64-bit: TB+)" + Phase 1.10. On 64-bit the user VA is ~128 TiB, so a single map of a multi-TB file is fine; on 32-bit the ~2–3 GiB usable VA caps the DB (deferred windowed-remap). Linux vm.max_map_count (default 65530) bounds distinct VMAs, not map size — a single contiguous MAP_SHARED of the file is one VMA, so it is not the limit here (it bites designs that map per-page). Confirms the §4 "vertical only, bounded by address space" line and the Phase 1.10 vm.max_map_count note.
  • C9 — Freelist bloat from one long reader. Input: §4 "space amplification bounded by oldest live reader" + MM6. If a reader pins txid R while the writer commits at rate c commits/s each freeing k pages, retained-but-unreclaimable pages after t seconds ≈ c × k × t pages. At c = 1000/s, k = 4 (a small path), t = 3600 s → 1.4 × 10⁷ pages × 4 KiB ≈ 55 GiB held for a live set that might be megabytes. Quantifies why §Failure Modes & Recovery ranks long-lived readers the #1 operational hazard and why oldest_reader_txid lag is a paging alert (§Operational Readiness).
  • C10 — Overflow threshold and big-value page count. Input: §8.4 BIGDATA spill; §4 page size. A value spills to an overflow chain when key+val+headers > P (single-leaf-fit threshold, ~P/4 for fan-out health). A 1 MiB value at P = 4 KiB needs ⌈1 048 576 / (4096 − 16)⌉ = ⌈256.9⌉ = 257 contiguous overflow pages (header per chain, payload-packed). Confirms the §8.4/Phase 3 "value spanning 17 pages" fixture scale and the contiguity requirement that keeps overflow reads zero-copy (Phase 3.6).
  • C11 — TLB reach vs working set (C-TLB, the huge-page lever). Input: §4 "NUMA/TLB assumptions" + §24.7. A typical 64-entry dTLB with 4 KiB pages reaches 64 × 4 KiB = 256 KiB; a random B+tree walk over a multi-GB map therefore misses the TLB on nearly every node touch (Drepper). 2 MiB huge pages raise reach to 64 × 2 MiB = 128 MiB — a 512× increase — which is why MADV_HUGEPAGE is the measured win on ≥ 8 GiB maps (§24.4 acceptance). Quantifies the §24.7/Phase 13 TLB study and the Crotty/Leis/Pavlo TLB-shootdown concern.

Alternative Architectures (Roads Not Taken)

Fundamentally different ways to build a durable embedded key-value store for the same goal. Each: an ASCII sketch, the regime where it wins, the real system that embodies it, and why this blueprint rejected it.

A1 — Buffer-pool engine (in-place B-tree + WAL + user-space cache). The classic DBMS storage manager: a user-space page cache with its own replacement policy, in-place page mutation, and a write-ahead log for atomicity/durability.

   app ──get/put──▶ ┌──────────── Buffer Pool (own cache, LRU/clock) ───────────┐
                    │  pin/unpin pages · dirty list · eviction thread           │
                    └───────┬───────────────────────────────┬──────────────────┘
                            │ in-place writes                │ log records
                    ┌───────▼────────┐               ┌───────▼────────┐
                    │ data file (B-tree, mutated in place) │  WAL (redo/undo, ARIES) │
                    └────────────────┘               └────────────────┘
        recovery: scan WAL → redo committed, undo uncommitted (ANALYSIS/REDO/UNDO)
  • Wins: write-heavy workloads with small random in-place updates and working sets larger than RAM, where explicit eviction control and tiny per-update WAL records beat COW's path-copy, and where the OS page cache's lack of control (eviction, prefetch, ordering) is a liability. It is also the only portable choice where mmap durability is weak (Windows, network FS).
  • Real system: this is the architecture of Architecture of a Database System (Hellerstein/Stonebraker/Hamilton) — and concretely InnoDB, WiredTiger, and (in journal/WAL mode) SQLite; the CIDR 2022 paper argues for it over mmap precisely on these axes.
  • Rejected because: it duplicates the kernel page cache (double-caching, lost zero-copy), reintroduces the buffer manager and log-replay recovery this project exists to avoid, and forfeits the O(1) selection-recovery headline (Principle 1, Principle 7, ADR 004, ADR 006). The whole pedagogical point is that mmap + COW + dual-meta delivers ACID with none of that machinery.

A2 — Log-structured merge tree (LSM). Buffer writes in an in-memory memtable; flush to immutable sorted runs (SSTables); merge/compact runs in the background; reads merge across levels.

   put ─▶ [memtable (sorted, in-RAM)] ──flush──▶ [L0 SSTables]
                                                     │ compaction
                                                     ▼
                                   [L1] ─▶ [L2] ─▶ … (immutable, sorted runs)
   get ─▶ search memtable → L0 → L1 → … (merge; bloom filters skip levels)
   durability: WAL for the memtable; SSTables are write-once
  • Wins: write- and ingest-heavy workloads — writes are cheap sequential appends up front, amplification paid back as background compaction; excellent for time-series, logs, and high-throughput KV where read amplification is mitigated by bloom filters and caching.
  • Real system: LevelDB and RocksDB (Google/Meta); RocksDB backs MyRocks, CockroachDB's storage, Kafka Streams, and many KV services.
  • Rejected because: this project's headline is read-heavy, zero-copy, single-file simplicity with O(1) recovery. An LSM trades read latency (multi-level merge), space (level overlap + tombstones), and operational complexity (compaction tuning, write stalls) for write throughput — the opposite of the design center. It is the canonical contrast (§Comparative Architecture, MM4), built differently on purpose, not a variant of this one.

A3 — Lock-free / multi-writer B-tree (Bw-tree style). Replace the single-writer mutex + in-place COW with a latch-free B-tree: a mapping table indirects logical page IDs to physical locations, and updates are prepended as delta records installed by atomic compare-and-swap, allowing many concurrent writers.

   writers ─CAS delta─▶ ┌── Mapping Table (PID → ptr) ──┐
                        │  PID → [Δ insert]→[Δ delete]→ base page  (delta chain)
                        └───────────────────────────────┘
   consolidation folds the delta chain into a new base page (also CAS-installed)
   no page latches; concurrency via atomic pointer swaps in the mapping table
  • Wins: many-core write-scalable workloads on modern hardware where a single-writer ceiling is the bottleneck and writers touch largely disjoint key ranges — it removes the serialization point entirely.
  • Real system: the Bw-tree (Levandoski et al., ICDE 2013), used in Microsoft's Hekaton/SQL Server in-memory engine; WiredTiger likewise admits concurrent writers via MVCC + finer-grained locking.
  • Rejected because: single-writer + dual-meta is what makes commit a single atomic meta-flip and recovery a one-page selection (Principle 3, Principle 7, MM3, MM8); a lock-free multi-writer tree needs a fundamentally different durability and reclamation story (epoch-based GC, a mapping table, delta consolidation) and a far larger correctness surface. It is registered as the multi-writer un-defer path (Deferred Features Register, Phase 7 deferral, ADR 005), not adopted now — the project deliberately buys radical simplicity with a write-concurrency ceiling.

Selection recovery Recovery by choosing the higher-txid valid meta — no log replay; the O(1) alternative to ARIES (MM3, Principle 7).
