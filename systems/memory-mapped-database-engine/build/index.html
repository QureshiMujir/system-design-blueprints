⬜ Phase 1 — mmap Single-Level Store & Env Skeleton §12

Objectives

Establish the address-space-is-the-file foundation: open a file, mmap it, expose pgno→ptr, manage growth/remap and madvise. Constraint introduced: all higher layers address pages by pgno, never raw pointers held across grow (INV-ADDR-STABLE-WITHIN-TXN, Principle 8).

Deliverable

Library opens a (possibly empty) file, mmaps it, returns a byte view of any page, grows + remaps on demand. mdbx-cli stat prints geometry (page_size, mapped pages, file size, base moved count).

Acceptance
  • Open + map a 1 GiB sparse file in < 5 ms; RSS stays near 0 until pages faulted (verify via /proc/self/status).
  • Random page reads after madvise(RANDOM) show no readahead waste (compare faults via /proc/self/stat minflt/majflt).
  • Grow from 4 MiB → 1 GiB triggers ≤ expected remaps; pgno→ptr correct after each.
Fixtures
  • conformance/meta_select/empty_4k.mdbx — zero-length grown file (no metas yet).
  • geom_pagesize_{4k,16k,64k}.json — geometry params + expected mapped layout.
  • grow_sequence.txt — sequence of required pgnos → expected remap events.
Pitfalls
  • Base moves on remap → cached raw pointers dangle. Root cause: holding *const u8 across grow. Debug: log base pre/post; assert no live borrow during grow. Recovery: address by pgno always.
  • MAP_SHARED vs MAP_PRIVATE → PRIVATE writes never hit disk (COW in RAM). Detect: data vanishes after reopen. Fix: SHARED for writable map.
  • mmap length > file length → reads past EOF fault to SIGBUS. Root cause: map larger than ftruncated size without backing. Fix: keep mapped pages ≤ file size; grow file first, then map.
  • page_size < OS page → partial-page protection/fault granularity issues. Fix: enforce ≥ OS page at create.

⬜ Phase 2 — Page Codec, Dual Meta, Crash-Consistent Open §13

Objectives

Define the on-disk page format and the dual-meta crash-consistency core. Introduce checksums. After this phase, a freshly created file has two valid metas and recovery = meta selection (Principle 7).

Deliverable

Env::open creates or recovers a file with two metas; selection picks the newest valid; corrupt/torn meta falls back; geometry + roots reported.

Acceptance
  • Create → reopen yields identical meta selection deterministically.
  • Manually corrupt meta[1] checksum → open selects meta[0]; checksum_errors = 1.
  • Both metas corrupt → open refuses with CorruptKind::MetaBothInvalid.
  • fmt_ver major mismatch → VersionMismatch.
Fixtures
  • meta_select/newer_meta0.mdbx, newer_meta1.mdbx — selection by txid.
  • meta_select/torn_meta1.mdbx — meta[1] half-written → select meta[0].
  • meta_select/equal_txid.mdbx — tie → pick valid/parity rule.
  • meta_select/both_bad.mdbx — refuse.
  • meta_select/badmagic.mdbx, wrong_pagesize.mdbx.
Pitfalls
  • Trusting file length over last_pgno → reading uninitialized tail as a page. Fix: bound reachable pages by last_pgno.
  • Checksum field inside checksum region → self-reference. Fix: exclude last 8 B (and the field) from digest.
  • Selecting by file mtime/order, not txid → wrong root after crash. Fix: txid + validity only.
  • Endian assumption → cross-arch corruption. Fix: explicit LE codecs everywhere; fuzz both arches.
  • Meta not parity-alternated → torn write can kill the only good copy. Fix: enforce txid & 1 target.

⬜ Phase 3 — COW B+tree Search & Read Path (Zero-Copy) §14

Objectives

Implement immutable descent: given a root pgno, search branch→leaf and return a zero-copy &[u8] value. No mutation yet. Establishes the read path that readers and writers share.

Deliverable

txn.get(db, key) returns Some(&[u8]) pointing into the map (or assembled overflow view) or None. mdbx-cli get <key> works against a hand-built fixture DB.

Acceptance
  • Point lookup on a warm 1 M-key DB ≥ 5 M ops/s/core; returned slice address ∈ map range (assert).
  • Differential: 10 k random gets vs BTreeMap model — identical results.
  • Overflow value (e.g., 1 MiB) read correctly; zero-copy when contiguous.
Fixtures
  • cow_split/three_level_tree.mdbx — branch→branch→leaf descent.
  • overflow/value_1mib.mdbx, value_spanning_17_pages.mdbx.
  • dupsort/ (read-only navigation deferred to P9 but fixtures staged).
  • get_expected.jsonl — key→value oracle.
Pitfalls
  • Returning a slice that outlives the txn → use-after-free on commit/remap. Fix: lifetime 't ties slice to txn (compile-time).
  • Overflow pages non-contiguous → can't return one slice. Decision: allocate overflow contiguously at write time; reads assume contiguity (document).
  • Comparator mismatch vs stored order → search misses present keys. Detect: differential. Fix: store comparator id in DbInfo flags.
  • Off-by-one in branch routing (>= vs >) → wrong child. Debug: log descent path; compare vs model.

⬜ Phase 4 — COW Insert, Leaf/Branch Split, Page Allocation §15

Objectives

Implement insertion with copy-on-write path duplication and node splitting, producing a new root in memory (not yet committed). Introduce in-txn page allocation (append for now; freelist in P8).

Deliverable

wtxn.put(...) builds a new COW tree in memory; wtxn.get sees its own writes; abort discards everything (file untouched). (Commit/durability in P6.)

Acceptance
  • Insert 1 M sequential + 1 M random keys in one txn; in-txn get matches a BTreeMap model (differential).
  • Splits produce balanced fan-out (leaf occupancy ≥ 50% post-split except last).
  • freed set after N overwrites equals the count of pages superseded (no leak in bookkeeping).
  • Abort leaves on-disk metas/roots unchanged (reopen sees pre-txn state).
Fixtures
  • cow_split/split_leaf_basic.json — insert sequence → expected node layout + lineage (@5→@9,@10, root @11).
  • cow_split/root_split.json — leaf-root promotion to branch.
  • cow_split/cascade_split.json — split propagating ≥ 2 levels.
  • overflow/insert_bigvalue.json.
Pitfalls
  • Mutating a live page instead of COW copy (INV-COW). Manifest: concurrent reader sees torn node. Root: missing "first-touch copy" guard. Debug: page-write guard asserting pgno ∉ live snapshot. Recovery: none — corruption; prevent by guard.
  • Forgetting to add superseded page to freed → page leak (file grows). Debug: verify page accounting.
  • Median selection skew → unbalanced tree, poor fan-out. Fix: split at byte-midpoint of slot dir, not count, for variable-length.
  • Splitting with oversized single entry (key+val > page) → must go BIGDATA/overflow, not split forever. Detect: entry > page-fit → overflow path.
  • Parent overflow on separator insert → must recurse split into parent (don't assume parent has room).

⬜ Phase 5 — COW Delete, Merge, Rebalance, Cursors §16

Objectives

Implement deletion with COW (merge/rebalance underfull nodes) and a full cursor (range scans, first/last/seek/next/prev). Complete the in-memory tree mutation surface.

Deliverable

wtxn.del, range scans, ordered iteration via Cursor. mdbx-cli scan --from a --to z prints ordered pairs.

Acceptance
  • Delete-heavy workload keeps tree balanced (min-fill invariant; verify via verify).
  • Range scan over 1 M keys returns sorted, complete set; matches model.
  • seek semantics: returns first key ≥ target; prev/next boundaries correct at first/last leaf.
  • Mixed put/del/scan random ops (100 k) vs BTreeMap — identical (differential).
Fixtures
  • cow_split/merge_basic.json, borrow_left.json, borrow_right.json, root_collapse.json.
  • cursor_walk/range_full.jsonl, seek_boundaries.json, reverse_iter.json.
  • overflow/delete_bigvalue_frees_chain.json.
Pitfalls
  • Cursor invalidation after structural change (split/merge moves nodes). Manifest: cursor reads wrong slot. Fix: cursors are txn-scoped + read-only within a ReadTxn; CursorMut re-seeks after a write that restructures.
  • Merge with wrong sibling / across parent boundary → key order broken. Debug: assert separators monotone post-merge.
  • Underflow threshold off → degenerate near-empty nodes (space waste) or never-merge. Fix: byte-fill threshold, not count.
  • Forgetting to free overflow chain on delete → leak. Debug: verify.
  • Root collapse not handled → tree keeps a useless 1-child branch level (extra hop). Fix: collapse when branch has single child.

⬜ Phase 6 — Write Transactions, Commit, Durability Ordering (Phase-0 Crash-Safe) §17

Objectives

Tie P4/P5 into a durable commit: flush dirty pages, enforce durability ordering, flip the meta. After this phase the engine survives kill -9 at any point with full crash consistency (Phase-0 done).

Deliverable

Full ACID single-writer engine: put/del/commit durable; reopen after crash yields a consistent tree at the last fully-committed txid. examples/kv_basic.rs round-trips across process restarts.

Acceptance
  • Crash-injection harness: kill at each of the 4 phase points × 1000 iterations → reopen always valid; committed-before-crash data present, mid-commit txn atomically absent (never partial).
  • SYNC commit throughput ≥ device-fsync-bound (report commits/s); NOSYNC ≥ 10× SYNC.
  • verify passes after every crash recovery (no leaked/double pages beyond the abandoned uncommitted set, which is reclaimable).
Fixtures
  • crash/at_write_data.img, at_sync_data.img, at_write_meta.img, at_sync_meta.img — pre-captured mid-commit files + expected post-recovery txid.
  • crash/replay_log.txt — op sequence to reproduce each image.
  • freelist/freed_under_txid.json — free_db entry after a deleting commit.
Pitfalls
  • Meta synced before data (ordering inversion by FS/compiler reorder) → dangling root. Manifest: post-crash SIGBUS/corrupt. Root: missing barrier or relying on MAP_ASYNC. Debug: blktrace/strace ordering; assert sync(data) returns before meta write issued. Recovery: other meta.
  • fdatasync insufficient when file size changed (metadata not durable) → grown region lost. Fix: fsync (not fdatasync) on commits that grew the file.
  • WRITEMAP + MAP_ASYNC giving false durability → msync(MS_ASYNC) doesn't guarantee on-disk. Fix: MS_SYNC for SYNC mode.
  • free_db COW pages not in durable set → meta references freelist pages not on disk. Fix: include free_db dirty pages in WRITE-DATA/SYNC-DATA before meta.
  • Releasing write mutex before meta durable → a new writer overwrites meta race. Fix: release only after SYNC-META.
  • Single fsync amortization missed → per-put fsync. Fix: one sync per commit; batch puts per txn.

⬜ Phase 7 — MVCC Readers, Reader Table, Single-Writer Lock §18

Objectives

Enable many concurrent lock-free readers across threads/processes, each pinning a consistent snapshot, with one writer — without readers blocking the writer or vice versa (Principles 3, 4).

Deliverable

N reader threads/processes run concurrent consistent scans while a writer commits; readers see their pinned snapshot regardless of writer progress.

Acceptance
  • 64 reader threads + 1 writer for 60 s: zero reader errors, zero writer stalls attributable to readers; each reader's view is internally consistent (a fixed snapshot).
  • Cross-process: 2 processes share via lock file; reader in P2 sees a stable snapshot while writer in P1 commits.
  • oldest_reader_txid reflects the earliest pinned snapshot; dead readers reaped.
Fixtures
  • reader_table/concurrent_snapshot.scenario — interleaved reader/writer schedule + expected per-reader views.
  • reader_table/dead_pid_reap.scenario — kill a reader process → slot reclaimed.
  • reader_table/full.scenario — N+1 readers → ReadersFull.
Pitfalls
  • Reader slot not released (leaked ReadTxn) → oldest_reader_txid frozen → freelist bloat (P8). Debug: reader-table dump (stale pid/txid); oldest_reader_txid lag metric. Recovery: reap dead pids; for live leaks, fix caller.
  • TLS reuse across threads (thread pool reusing slot for different txn) → wrong txid pin. Fix: NOTLS mode or per-txn slots.
  • Reading meta during writer's meta flip → torn read of meta. Fix: meta read is a single-page load + checksum; on mismatch retry/other meta.
  • Dead-pid false positive (pid reused) → premature slot reclaim → reader sees reclaimed page. Fix: PID + start-time generation in slot.

⬜ Phase 8 — Reader-Aware Freelist & Page Reclamation §19

Objectives

Reclaim freed pages safely: reuse a page only after the oldest live reader has advanced past the txid that freed it (INV-READER-PIN, Principle 9). Bound space amplification; expose freelist-starvation telemetry.

Deliverable

Steady-state writes reuse freed pages; file size stabilizes under churn when readers are short-lived. mdbx-cli stat shows freelist size, oldest reader, reclaimable pages.

Acceptance
  • Churn workload (insert N, delete N, repeat) with no long readers → file size bounded (≤ working set + small slack), not monotonically growing.
  • With a held reader at txid R, pages freed at txid > R are NOT reused (assert); after reader drops and oldest advances, they become reusable.
  • verify: union(reachable, freelist, meta) == all pages; no overlap.
Fixtures
  • freelist/reuse_after_reader_drop.scenario — hold reader, churn, drop, observe reuse.
  • freelist/no_reuse_while_pinned.scenario — assert non-reuse.
  • freelist/self_reentrancy.scenario — alloc-from-free_db while editing free_db.
  • freelist/coalesce.json — adjacent PNL merge.
Pitfalls
  • Reusing a page freed at txid ≥ oldest reader → reader corruption. Manifest: reader reads overwritten page (wrong/torn data). Root: using current txid instead of oldest-reader. Debug: assert candidate pgno not in any pinned snapshot's reachable set (debug mode walks). Recovery: none post-fact — prevent via correct oldest.
  • Freelist re-entrancy (free_db edit needs a page, takes from free_db being edited) → infinite recursion / inconsistency. Fix: loaning page reserve; bounded edit.
  • pending reused within same txn → publishes a page still referenced by the new snapshot. Fix: pending → free only at commit under new txid.
  • PNL fragmentation → many tiny free entries, poor reuse. Fix: coalesce + descending sort.
  • Forever-held reader → unbounded growth (freelist starvation). Detect: oldest_reader_txid lag + pages_held_by_readers. Recovery: reap/kill stale reader (runbook).

⬜ Phase 9 — Named & Nested Sub-Databases, Duplicate Keys (DUPSORT) §20

Objectives

Support multiple named KV namespaces in one env (each a B+tree rooted in the main DB), and duplicate keys (multiple sorted values per key) via DUPSORT/sub-pages.

Deliverable

env/txn.open_db("users"), open_db("index"); DUPSORT DB stores multiple values per key, iterable in order. examples/named_dbs.rs, examples/dupsort.rs.

Acceptance
  • ≥ 1000 named sub-DBs coexist; each independently consistent; main-DB lists them.
  • DUPSORT: insert 1 M (key, value) with heavy duplication; next_dup iterates values sorted; count_dups correct.
  • Differential vs a model BTreeMap<Vec<u8>, BTreeSet<Vec<u8>>>.
  • Sub-page → sub-tree promotion when a dup set outgrows a page; transparent to API.
Fixtures
  • dupsort/subpage_to_subtree.scenario — dup set crossing the page threshold.
  • dupsort/dupfixed_pack.json — LEAF2 dense packing.
  • named_dbs/many_subdbs.scenario, subdb_root_cow.json — sub-DB change updates main root.
  • dupsort/del_one_vs_all.json.
Pitfalls
  • Sub-DB root staleness (cached Db.root after another txn changed it). Manifest: reads/writes target an old sub-tree. Fix: revalidate Db against current main-DB each txn (root may have moved via COW).
  • Sub-page vs sub-tree boundary bugs → lost dups on promotion. Debug: assert dup count preserved across promotion.
  • DUPFIXED size mismatch (variable-length value in a fixed-dup DB) → corruption. Fix: enforce fixed length at put.
  • Nested COW depth (dup sub-tree → key leaf → main DB → root) multiplies write amplification. Note in §Performance.
  • Comparator for dup values distinct from key comparator → ordering bugs. Fix: per-DB dup comparator stored in flags.

⬜ Phase 10 — Durability Modes, WRITEMAP, SIGBUS Handling, Spill §21

Objectives

Implement and harden the durability/perf tradeoff flags (SYNC/NOSYNC/WRITEMAP/MAPASYNC/NOMETASYNC), handle SIGBUS from mapped-region I/O errors, and add dirty-set spill for huge write txns.

Deliverable

All durability modes selectable; a documented crash-outcome matrix; SIGBUS surfaces as a recoverable Error not a process abort; multi-GB write txns complete within a bounded memory budget via spill.

Acceptance
  • Crash matrix verified by injection: (SYNC→no loss), (NOSYNC→lose un-synced tail, never corrupt), (NOMETASYNC→may lose last commit, never corrupt), (MAPASYNC→writeback-window loss, never corrupt).
  • Simulated I/O error (e.g., dmsetup error target / truncate under map) → Error::Sigbus, env remains queryable from prior committed state where possible.
  • 4 GiB single write txn completes with RSS bounded (< configured spill budget + slack).
Fixtures
  • crash/nosync_tail_loss.scenario, nometasync_lastcommit.scenario, mapasync_window.scenario.
  • sigbus/truncate_under_map.scenario, dm_error_target.scenario.
  • spill/large_txn_budget.scenario.
Pitfalls
  • WRITEMAP wild write (a bug elsewhere writes through the map) silently corrupts the DB with no syscall to trap. Manifest: corruption with no I/O error. Debug: run with WRITEMAP off in tests; checksums catch on read. Mitigation: WRITEMAP off by default; checksums on for WRITEMAP builds.
  • NOSYNC assumed durable → data loss surprise on power cut. Fix: clear docs; default SYNC.
  • SIGBUS in arbitrary thread → can't longjmp safely from non-owning context. Fix: handler sets flag; only owning txn thread recovers; others abort cleanly.
  • Spill breaks ordering if spilled pages become visible before meta. Fix: spill writes are NOSYNC and not published until meta flip; they're either reachable from the new (unpublished) root or in freed — never the old live tree.
  • MS_ASYNC mistaken for durable → same as NOSYNC trap.

⬜ Phase 11 — Integrity Verifier, Online Copy & Compaction §22

Objectives

Provide a standalone integrity walker (page accounting, checksum, order, freelist consistency) and an online copy/compact that produces a defragmented, freelist-clean file from a live env (backup primitive).

Deliverable

verify certifies a file; copy --compact yields a minimal, defragmented backup while the env keeps serving. Backup = consistent point-in-time snapshot (pinned reader).

Acceptance
  • verify detects injected faults: double-referenced page, leaked page, bad checksum, non-monotone keys, child pgno > last_pgno — each with the right CorruptKind.
  • copy --compact of a bloated file (held-reader scenario) produces a file sized ≈ live working set; reopened verify passes; data identical (differential).
  • Copy runs concurrently with writes; backup reflects the snapshot at copy start.
Fixtures
  • verify/double_ref.img, leaked_page.img, bad_checksum.img, nonmonotone.img, child_oob.img.
  • copy/bloated_to_compact.scenario — before/after sizes + identical-data oracle.
Pitfalls
  • Verifier following a torn page into garbage → false positives/crash. Fix: bounds + checksum check before deref; bound walk by last_pgno.
  • Compact copy missing sub-DBs → silent data loss in backup. Fix: enumerate all SUBDB entries recursively.
  • Copy not pinning a snapshot → inconsistent backup (writer advances mid-copy). Fix: hold a ReadTxn for the whole copy.
  • Non-compact copy of a sparse file copying holes → bloated dst. Fix: copy only last_pgno pages; preserve sparseness.

⬜ Phase 12 — Fuzzing, Crash-Injection, Differential & Property Testing §23

Objectives

Systematically attack the format and algorithms: fuzz codecs, crash-inject every commit phase, differential against a model and (optionally) LMDB, property-test invariants.

Deliverable

CI-runnable fuzz smoke (5 min/target), reproducible crash-injection suite, differential test passing on long random runs, property suite green.

Acceptance
  • Fuzz targets: 0 crashes/UB in CI smoke; corpus minimized + checked in.
  • Crash-injection: 10 000 kills across phases → 100% recover, 0 corruption, correct atomic boundary.
  • Differential: 1 M-op random stream (incl. reopen mid-stream) matches model exactly.
  • miri/ASan: no UB on codec/mmap tests.
Fixtures
  • fuzz/corpus/* — minimized crashing/edge inputs per target.
  • crash/schedule_*.txt — fuzzed kill schedules.
  • diff/op_stream_*.jsonl — recorded streams + model outputs.
Pitfalls
  • Fuzzer finds UB in unsafe codec (out-of-bounds slot offset) → must bounds-check every decoded offset against page bounds. Fix: validated accessors; never trust on-disk offsets.
  • Non-determinism breaks differential (HashMap iteration, timestamps) → use ordered structures; seed RNG.
  • Crash hook changes timing/ordering → masks the real bug. Fix: hook only aborts the process (no extra syncs).
  • Fuzz corpus rot (format change invalidates corpus) → version corpus with fmt_ver.

⬜ Phase 13 — Performance Engineering, Benchmarks, madvise Tuning, FFI §24

Objectives

Measure and tune: lookups/s, commits/s, fill, randread; tune madvise/huge pages/readahead; ship the C ABI and finalize docs.

Deliverable

Reproducible benchmark suite + report (docs/performance/), tuned defaults, working C ABI with example, regression gate in CI.

Acceptance
  • Warm randread ≥ 5 M ops/s/core (checksum off); ≥ target with checksum on documented.
  • SYNC commit throughput within ~1 fsync/commit of device limit; NOSYNC ≥ 10×.
  • Huge pages reduce dTLB misses measurably on a ≥ 8 GiB map (report delta).
  • C ABI example links and round-trips put/get.
Fixtures
  • benchmarks/baselines/*.json — committed perf baselines for the guard.
  • examples/ffi_roundtrip.c — C consumer.
Pitfalls
  • Benchmarking cold vs warm conflated → misleading numbers. Fix: explicit warmup + madvise(WILLNEED); report both.
  • Checksum cost hidden → "fast" numbers with checks off mistaken for prod. Fix: report both modes.
  • mmap readahead polluting random benchmark → inflated I/O. Fix: madvise(RANDOM) for randread.
  • Criterion measuring allocator not engine → noise. Fix: pre-allocate, pin CPU, isolate.
  • FFI lifetime leak (C holds a value pointer past txn) → UB across the boundary. Fix: document copy-out requirement in C API.
