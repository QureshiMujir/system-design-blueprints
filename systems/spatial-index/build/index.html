⬜ Phase 1 — Core Geometry: Point, Rect, Distances

Objectives
  • Define Point<const D: usize> and Rect as the canonical coordinate types used by every downstream crate.
  • Implement Euclidean distance, MINDIST(point, rect), and MINMAXDIST(point, rect) meeting the kNN pruning contract (I6).
  • Enforce min[i] <= max[i] on every axis as a structural invariant (P8).
  • Provide property-based test harness confirming non-negativity and MINDIST <= MINMAXDIST for all inputs.
  • Scope: sidx-core only. No heap allocation for small D (stack arrays). No I/O, no trait objects.
Deliverable
  • sidx-core compiles as #![no_std]-compatible (alloc only for Vec in later crates).
  • cargo test -p sidx-core passes all unit + proptest suites.
  • Point, Rect, NodeId, DataId, euclidean, mindist, minmaxdist exported from sidx_core.
  • Rust doc on every public symbol with invariant stated.

Pitfalls
  • NaN propagation: a single NaN coordinate causes all distance comparisons to fail silently; validate on construction, return SidxError::MalformedRect rather than propagating NaN.
  • MINMAXDIST formula off-by-one: the "nearest face on axis k" picks r.min[k] if p[k] > midpoint, else r.max[k]; getting this backwards causes MINMAXDIST < MINDIST, breaking kNN pruning (I6 violation).
  • Exact equality on f64 for PartialEq: f64::NAN != f64::NAN so two NaN-coordinate points compare unequal; the to_bits approach is deterministic but only correct if NaN inputs are rejected upstream.
  • Degenerate rect (point): min == max; distance computations must return 0 not a negative; the clamp formula handles this, but verify with fixture.
  • Axis-count mismatch: generic const D means mismatches are compile-time errors; document that D=2 is the default, and D=3 usage must be explicit to prevent accidental 2D-vs-3D queries.

⬜ Phase 2 — MBR Operations

Objectives
  • Implement the complete MBR algebra in sidx-geom that all tree operations build on (P2, P8).
  • Operations: union, intersection, intersects, area/volume, enlargement, overlap_area, contains_rect, contains_point.
  • All functions are pure, allocation-free, and operate on Rect<D> from sidx-core.
  • Establish the semantic distinction: enlargement = additional area to include a rect (drives ChooseLeaf, Phase 4); overlap_area = area of intersection of two rects (drives R*-tree split, Phase 6).
  • Scope: sidx-geom only; no tree state.
Deliverable
  • sidx-geom compiles; all MBR operations available via sidx_geom::*.

  • Downstream crates sidx-rtree, sidx-rstar, sidx-bulk, sidx-knn all import from sidx-geom exclusively (no duplicate geometry logic).
  • Documentation with invariants, edge-case contracts, and complexity (O(D) per operation).

Pitfalls
  • enlargement negative due to floating-point subtraction: area(union) - area(base) can yield small negatives via catastrophic cancellation when candidate is almost inside base; clamp result to f64::max(0.0, ...) and document.
  • overlap_area vs intersects divergence: two rects touching on a single edge have intersects == true but overlap_area == 0; callers must not use overlap_area > 0 as the intersection predicate.
  • Associativity break with NaN: a single NaN propagates through union; validated upstream (Phase 1) but assert in debug mode.
  • Area overflow for large coordinate ranges: product of extents can overflow f64 for max - min ~ 1e154; document the coordinate range contract (|coord| < 1e12 recommended).
  • contains_point boundary semantics: inclusive boundaries mean a point on the rect edge is contained; callers (window search) rely on this for objects touching the query rect edge.

⬜ Phase 3 — R-tree Structure + Search

Objectives
  • Implement the R-tree node arena, tree struct, and window search in sidx-rtree.

Pitfalls
  • intersects vs contains_rect confusion in descent: internal nodes must use intersects, not contains — using contains misses partially-overlapping subtrees (I4 violation); a search rule, not an optimization.
  • contains_search false positive at leaf: check contains_rect(query_rect, leaf_entry.mbr), not the reverse; swapped args flip containment direction — unit-test with a partially-overlapping rect.
  • Arena NodeId 0 as root vs null sentinel: use NodeId(u32::MAX) as null sentinel, never 0 (node 0 is a valid root); encode as a type-level invariant.
  • SmallVec spill to heap on overflow: entries beyond M_INLINE heap-allocate silently — correct, but changes the allocation profile; track with allocator instrumentation in bench.
  • Height field stale after manual arena manipulation: tests that hand-build trees must call recompute_height() before querying; Phase 4 maintains height automatically in production.
  • Iterative descent stack depth: 1M-node tree, height 5, fanout 50 → work-stack reaches ~250 entries; pre-allocate to avoid repeated realloc.

⬜ Phase 6 — R*-tree improvements

Objectives
  • Implement sidx-rstar crate as a superset of sidx-rtree: replace ChooseLeaf, split, and overflow handling.
  • choose-subtree: at leaf level minimize overlap enlargement; above leaf level minimize area enlargement.
  • R* split: axis-selection by minimum margin-sum; distribution by minimum overlap (tie: minimum area).
  • Forced reinsertion: on first overflow at a given level, reinsert p entries instead of splitting; maintain invariants I1–I3, I7, I10 while delivering measurable P4 improvement (overlap/coverage).
Deliverable
  • sidx-rstar crate compiles with insert, delete, window_search APIs.
  • choose_subtree dispatches correctly at leaf-parent vs. upper levels.
  • Forced reinsertion reduces average overlap: verifiable by RStarStats::overlap_ratio.
  • sidx-cli build --index rstar builds an R*-tree from a CSV of rects; Phase 3 window search works unchanged over sidx-rstar nodes.
