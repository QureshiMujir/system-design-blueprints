Decisions (§9) · 28 ADRs

ADR-01

Implementation language

Chosen

Rust (stable toolchain, MSRV=1.80)

Rejected

C++, Go, Java, Zig

When the rejected choice is right

C++ when extending a mature spatial codebase (PostGIS, Boost.Geometry, libspatialindex); Go/Java when GC pauses are tolerable and dev velocity outranks tail latency

Why: Memory safety without GC; const generics for D-dimensional types; zero-cost abstractions for hot paths; ecosystem maturity

ADR-02

Build system

Chosen

Cargo (workspace with 12 member crates)

Rejected

Bazel, Buck, CMake

When the rejected choice is right

Bazel/Buck in a large polyglot monorepo needing remote build caching and cross-language targets Cargo cannot span

Why: Native Rust toolchain; workspace-level Cargo.lock; feature flags per crate; no cross-language build needed

ADR-03

Dependency policy

Chosen

Minimal: ordered-float, slab, bytemuck, thiserror, clap, criterion, proptest, arbitrary

Rejected

pulling large frameworks

When the rejected choice is right

A batteries-included framework when time-to-market dominates and a wider supply-chain surface is acceptable (prototypes, internal tools)

Why: Minimize supply-chain surface; each dep is single-purpose and widely audited; no async runtime dependency in core

ADR-04

Numeric representation

Chosen

f64 for all coordinates and distances

Rejected

f32, fixed-point, rational

When the rejected choice is right

f32 for GPU/SIMD-bound workloads at huge N where halving coordinate bandwidth matters and precision tolerance is loose; fixed-point for exact reproducible integer-grid coordinates

Why: Sufficient precision for geographic coordinates (±180/±90); MINDIST formulae require squaring; f32 risks cancellation

ADR-05

Const-generic dimensionality

Chosen

Point<const D: usize>, Rect<const D: usize>

Rejected

runtime D in a Vec<f64>, enum 2D/3D

When the rejected choice is right

Runtime D when dimensionality is data-driven and unknown at compile time (generic ingest of arbitrary nD feature tables)

Why: Compile-time D eliminates heap allocation per point; monomorphization justified because D<=4 in practice; type safety

ADR-06

Arena / node allocation

Chosen

slab crate (Slab<RTreeNode<D>>) for stable NodeId indices

Rejected

raw Vec (requires remapping on delete), typed-arena

When the rejected choice is right

Raw Vec for append-only / bulk-built static trees with no deletes, where compaction is free and NodeId stability is irrelevant

Why: Slab provides O(1) insert/remove with stable indices; avoids NodeId invalidation on remove; no unsafe needed

ADR-07

Node split default

Chosen

SplitStrategy::RStar default; Quadratic/Linear available via flag

Rejected

only quadratic, only linear

When the rejected choice is right

Linear split for write-heavy ingest (logging) where split cost dominates and query quality is secondary; quadratic when overlap is already inherently low

Why: R*-tree split minimizes overlap-coverage, measurably reducing query fan-out; quadratic retained for comparison benchmarks

ADR-08

Forced reinsertion parameter p

Chosen

p = 30% of M (Beckmann et al. recommendation)

Rejected

p=20%, p=50%

When the rejected choice is right

p=20% for insert-latency-sensitive workloads (less reinsertion churn); p=50% for read-dominated trees where maximal overlap reduction pays off

Why: Empirically optimal balance between reinsertion cost and resulting overlap reduction; matches reference paper

ADR-09

kNN algorithm

Chosen

best-first branch-and-bound (Hjaltason & Samet 1999) in sidx-knn

Rejected

incremental NN via depth-first, ANN approximation

When the rejected choice is right

Depth-first under tight memory (avoids a heap of size O(visited)); ANN at high D or when approximate neighbors are acceptable (portfolio #255)

Why: Exact kNN; MINDIST lower bound is tightest known; best-first is cache-friendlier than depth-first for k>1

ADR-10

Serialization / page format

Chosen

Custom binary layout in sidx-persist (bytemuck zero-copy cast)

Rejected

serde + bincode, Cap'n Proto, FlatBuffers

When the rejected choice is right

serde+bincode or Cap'n Proto when schema evolution and cross-language readers matter more than zero-copy speed

Why: Page-aligned, zero-copy read; bytemuck ensures safe transmute; no schema evolution needed for v1; full control of page layout

ADR-11

Page size

Chosen

4096 bytes (OS page boundary)

Rejected

512B, 8 KB, 16 KB

When the rejected choice is right

16 KB pages for disk-resident scan-heavy workloads (fewer, larger sequential I/Os); 512B on storage with tiny block size or for memory-tight caches

Why: Aligns with filesystem and OS virtual memory page; reduces partial-page I/O; fits 100 entries at D=2 (M=100)

ADR-12

Page cache eviction

Chosen

LRU (lru crate or manual VecDeque + HashMap)

Rejected

LFU, clock/CLOCK-pro, no cache

When the rejected choice is right

LFU / CLOCK-pro under scan-resistant workloads with a skewed hot set where LRU thrashes on repeated full-tree scans

Why: LRU simple and predictable; spatial locality of R-tree traversal benefits from caching ancestor nodes; configurable capacity

ADR-13

Geohash alphabet

Chosen

Standard Niemeyer base32 (geohash.org alphabet: 0-9bcdefghjkmnpqrstuvwxyz)

Rejected

z-order Morton codes, Hilbert curve encoding

When the rejected choice is right

Hilbert curve encoding when linear-order spatial clustering matters more than string-prefix interop and no external DB interop is required

Why: Compatibility with PostGIS, Elasticsearch, Redis; prefix-searchable in any sorted store; interoperability

ADR-14

Quadtree variant

Chosen

Point quadtree + PR (point-region) quadtree in same module

Rejected

k-d tree, octree, loose quadtree

When the rejected choice is right

k-d tree for static point-only data needing balanced splits; octree at D=3 volumetric; loose quadtree for many moving objects (looser bounds cut reinsertion)

Why: PR quadtree handles both point and region objects; depth-bounded subdivision prevents infinite recursion on coincident points

ADR-15

Concurrency model

Chosen

Single-threaded core; no async in library crates; optional Arc<Mutex<>> wrapper in CLI

Rejected

Rayon parallel queries, async Tokio

When the rejected choice is right

Rayon parallel queries for read-only analytical batch query sets at high core counts; async Tokio when the index sits behind a network service with many I/O-bound clients

Why: Correctness first; spatial index mutation is not trivially parallelizable; users can parallelize at the query-set level externally

ADR-16

Logging

Chosen

log facade (no direct logger dep in lib crates); env_logger in CLI

Rejected

tracing in core, slog, println

When the rejected choice is right

tracing in core when the library is the whole application and span-based profiling is the primary observability surface

Why: Facade keeps library crates log-agnostic; consumers choose their logger; negligible overhead when disabled

ADR-17

Structured tracing / metrics

Chosen

tracing crate in sidx-cli and sidx-knn for span-based query profiling

Rejected

OpenTelemetry SDK, custom counters

When the rejected choice is right

OpenTelemetry in a distributed deployment where spans must export to a collector and correlate across services

Why: Lightweight; zero-cost when no subscriber; enables measuring node visits and pruned subtrees per query (P10)

ADR-18

Property-based testing

Chosen

proptest + arbitrary crate for fuzz-style input generation

Rejected

quickcheck, manual fuzz only

When the rejected choice is right

Manual fixed corpora when shrinking is unnecessary and a deterministic regression set must be replayed byte-for-byte

Why: proptest provides shrinking; arbitrary integrates with cargo-fuzz; both used: proptest for unit properties, arbitrary for libfuzzer harnesses

ADR-19

Fuzzing harness

Chosen

cargo-fuzz (libFuzzer) for geohash encode/decode, Rect construction, insert/delete sequences

Rejected

afl.rs, honggfuzz

When the rejected choice is right

AFL for whole-binary fork-server fuzzing of a CLI with complex file inputs; honggfuzz for hardware-counter-guided coverage

Why: libFuzzer most ecosystem-supported; cargo-fuzz zero-config integration; geohash roundtrip and tree mutation are highest-value targets

ADR-20

Differential / oracle testing

Chosen

sidx-oracle brute-force linear scan in same workspace

Rejected

external golden files, snapshot testing

When the rejected choice is right

Golden files when the reference is an external authoritative system (e.g. matching PostGIS output) rather than an in-process brute-force scan

Why: Oracle always available in-process; property: for any random dataset + query, index_result == oracle_result; catches split/MBR bugs immediately

ADR-21

Benchmarking

Chosen

criterion crate; benchmarks in sidx-cli/benches/ and per-crate benches/

Rejected

divan, std::time manual

When the rejected choice is right

divan for nanosecond micro-benchmarks where criterion's statistical machinery dominates the measurement; manual timing for one-off ad-hoc checks

Why: Criterion provides statistical stability, HTML reports, comparison across runs; criterion is de-facto Rust benchmark standard

ADR-22

CI/CD

Chosen

GitHub Actions: cargo test --workspace, cargo clippy --all-targets, cargo fmt --check, cargo fuzz run (time-limited), criterion regression check

Rejected

Jenkins, GitLab CI, CircleCI

When the rejected choice is right

Self-hosted Jenkins/GitLab CI for private repos needing custom hardware (large-RAM 10M-object benches) or air-gapped builds

Why: GitHub Actions native to open-source; matrix over stable + beta Rust; fuzz step catches regressions in geohash/geometry

ADR-23

Ordered float

Chosen

ordered-float crate (OrderedFloat<f64>) for heap keys in kNN

Rejected

manual bit-casting to i64 for ordering, f64 newtype

When the rejected choice is right

Manual bit-cast in a no_std / zero-dependency context, or when all inputs are NaN-free by construction

Why: NaN-safe ordering; works directly as BinaryHeap key; well-audited and widely used

ADR-24

Error handling

thiserror for library error enums; anyhow in CLI only

Rejected

When the rejected choice is right

Box<dyn Error> for quick prototypes or where callers never match on error kind

Licensing

Rejected

GPL, BSL, proprietary

When the rejected choice is right

GPL when copyleft reciprocity is a goal (preventing proprietary forks); BSL for a commercial open-core product with a delayed-open clause

ADR-26

Reproducibility

Chosen

Cargo.lock committed; RUSTFLAGS pinned in CI; rand seeded with fixed seed in tests

Rejected

floating dependency ranges

When the rejected choice is right

Floating ranges for a library meant to be consumed downstream (apps pin the lockfile; libraries float to receive upstream fixes)

Why: Deterministic test outcomes (I10); CI failures are reproducible locally; seed exposed via --seed CLI flag

ADR-27

Feature flags

Chosen

sidx-persist behind persist feature; sidx-rstar behind rstar feature; default = rtree + quadtree + geohash + knn

Rejected

all-in default, separate crates per variant

When the rejected choice is right

All-in default for an application binary where compile time is amortized once and feature discoverability beats minimal build size

Why: Reduces compile time for users needing only in-memory index; persist adds bytemuck + I/O deps only when needed

ADR-28

Bulk-load input type

Chosen

STR::from_iter(impl IntoIterator<Item=(Rect<D>, DataId)>) — streaming input

Rejected

requiring Vec pre-allocation

When the rejected choice is right

Requiring a Vec when the caller already owns one (borrow it, skip the copy) or when input size must be known upfront for a single allocation

Why: Iterator-based avoids double allocation; STR internally collects to Vec once for sorting, then drops

Alternative Architectures (Roads Not Taken)

A1 — KD-B forest of immutable segments (BKD).

ingest → buffer → sort → write immutable segment ──┐
                                                    ├─ merge segments periodically
query → search all live segments → union ──────────┘

Wins for append-mostly, high-ingest point data where rebuilds are cheaper than in-place mutation. Embodied by Lucene/Elasticsearch BKD. Rejected because sidx targets dynamic insert/delete with low-latency updates (§4), where rebuilding immutable segments on every change is unacceptable.

A2 — Space-filling curve + B-tree (Z-order / Hilbert / geohash-as-primary).

point → SFC key (interleave bits) → B-tree → range scan over curve intervals

Wins when an ordered KV store already exists and spatial is wanted as a prefix scan with zero new engine (MongoDB S2, geohash-in-Redis). Rejected as the core index because a query box maps to many disjoint curve ranges (over-fetch) and exact kNN is awkward — sidx keeps geohash as a secondary/interop layer (Phase 10), not the primary structure.

A3 — Fixed-grid / uniform-cell hash index.

extent → uniform W×H cells → hash(point)→cell → bucket list

Wins for uniformly-dense point data with known extent (collision systems, particle sims). Rejected because real geographic data is skewed: cells either overflow or waste memory, and range queries touch many empty cells — the R-tree adapts to local density instead.

A4 — R+-tree / disjoint-partition (clipping) index.

object spanning a boundary → clipped → stored in BOTH child partitions (no overlap)

Wins for static, read-heavy workloads where eliminating multi-path descent matters more than storage and update cost. Embodied by the R+-tree (P-R6) and Cell-tree (P-R11). Rejected because clipping duplicates objects (violates I7) and complicates delete — sidx minimizes overlap via R* splits instead.
