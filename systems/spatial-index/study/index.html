Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does increasing page size (§4, ADR-11) reduce tree height yet can worsen window-query latency (Capacity Model, P4)?
  2. A dataset of 10M heavily-overlapping rectangles blows the p99 window target 10× (§4). Which levers (Phase 6 R*, Phase 7 STR) attack this and what does each trade?
  3. Best-first kNN (Phase 8) visits fewer nodes than depth-first (P-R3) yet both are correct — which invariant (I6) makes the pruning sound, and why?
  4. Deleting an entry can shrink an ancestor MBR (Phase 5 CondenseTree). Why is failing to tighten it a future-correctness bug (P2, I7) but not a bug for currently-returned results?
  5. Why can't the single-writer/multi-reader model (ADR-15, §4) be relaxed to multi-writer without redesigning split propagation (Phase 4, I2)?
  6. Geohash prefix scan misses results across cell boundaries (Phase 10, MM7). Derive the regime in which an application must fall back to the R-tree (Comparative).
  7. Reconcile STR's 95% occupancy target with quadratic-split's 50% guarantee (§4, ADR-07): which workload makes each correct, and how does occupancy feed back into height (Capacity Model)?
  8. Why does sidx reject object clipping (R+-tree, P-R6) given I7 — and in which regime (Alternative Architectures) would clipping actually win?
  9. The arena uses slab tombstones, not Vec::remove (ADR-06, MM8). What bug class in NodeId stability does this prevent during Phase 5 delete?
  10. The page cache holds 256 of 215 K pages (Capacity Model). Explain why a 0.12%-resident cache still serves most node-visits (locality + §4 LRU).
  11. Why is f64 mandated over f32 for MINDIST (ADR-04)? Connect the squaring in the MINDIST formula (P-R3, §8) to cancellation error.
  12. If D grows to 10, why does the R-tree degrade toward linear scan (P-R12), and what would you build instead (Alternative Architectures, #255)?
  13. Derive the minimum disk reads per cold window query from height and cache levels (Capacity Model, §4), and explain why STR's high occupancy lowers it.
  14. Why must the MBR be recomputed bottom-up after both insert (AdjustTree, Phase 4) and delete (CondenseTree, Phase 5)? What single invariant (I3/I7) unifies them?
  15. The oracle asserts index_result == brute_force (ADR-20, §4 gate). Why is this the only practical way to catch a subtle split bug, and what would a hand-written unit test miss?
  16. How does forced reinsertion (p=30%, ADR-08, P-R2) reduce overlap without infinite looping? What role does the per-level flag play (Phase 6)?
  17. Why does the geohash alphabet omit a,i,l,o (ADR-13, P-R9), and how does this interop choice constrain the encode/decode tables (Phase 10)?
  18. When does an immutable, merge-on-write index (Lucene BKD, Comparative) beat this mutable R-tree, and which §4 constraint flips the decision?
  19. Compute the RAM ceiling for 10M objects (Capacity Model) and explain why it lands under the §4 2 GiB / "≤ 2× raw" budget.
  20. Why is the page format versioned (S7, ADR-10), and what compatibility failure (Compatibility & Versioning) does omitting format_version cause on upgrade?

Mental Models & First Principles

  • MM1 — A node is a page; fanout is the byte budget. An R-tree node maps to one disk page, so M = floor((page_bytes − header) / entry_bytes). Predicts: changing page size changes M, which changes height, which changes I/O per query. Bug without it: picking M independently of page size → partial-page reads and wasted cache. Applied: §4, ADR-11, Phase 12.
  • MM2 — An MBR is a conservative, lossy summary that can only over-approximate. A parent MBR must cover all descendants, so a search can yield false positives but never false negatives. Predicts: correctness depends solely on the covering property, not on tightness. Bug without it: over-tightening an MBR so it excludes a child → silently missed results. Applied: I7, P2, Phase 3.
  • MM3 — Query cost is nodes-overlapping-the-query, not results-returned. Two trees with identical contents but different overlap do different amounts of work. Predicts: overlap is the enemy; R* pays at insert time to shrink it. Bug without it: optimizing occupancy while ignoring overlap → fast build, slow queries. Applied: P4, Phase 6.
  • MM4 — Best-first kNN with a MINDIST-keyed min-heap visits the provably minimum node set. MINDIST is a lower bound, exact distance an upper bound; the heap interleaves both. Predicts: no correct algorithm visits fewer nodes. Bug without it: depth-first or a wrong heap key → extra subtree visits or wrong neighbors. Applied: Phase 8, P-R5.
  • MM5 — A split is a redistribution that must rebalance upward. Overflow splits a node and propagates the new entry to the parent, possibly cascading to the root and growing height by one. Predicts: split is never local. Bug without it: splitting a leaf without AdjustTree → unbalanced tree, broken I2. Applied: I2, Phase 4.
  • MM6 — Bulk loading is sorting, not inserting. STR imposes a space-filling sort order so leaves are spatially compact and ~95% full in a single pass. Predicts: static data should never be built by repeated Insert. Bug without it: building a 10M static index one entry at a time → low occupancy and slow build. Applied: Phase 7, P-R4.
  • MM7 — A geohash is a space-filling code: a string prefix is a bounding box. Proximity reduces to a prefix scan on any ordered store, but adjacent cells can differ in prefix. Predicts: you need explicit neighbor logic at cell boundaries. Bug without it: assuming prefix-proximity is exact → missed results straddling a cell edge. Applied: Phase 10, P-R9.
  • MM8 — Arena + NodeId(u32) replaces pointers, so the tree is a flat, memcpy-serializable Vec the borrow checker accepts. Predicts: delete must not invalidate other ids (slab tombstones, not Vec::remove). Bug without it: Vec::remove shifts indices → dangling NodeIds across the tree. Applied: ADR-06, Phase 5.

5. Required Reading

Books

B1 — Samet, H. Foundations of Multidimensional and Metric Data Structures (Morgan Kaufmann, 2006)

  • Ch. 1–2: spatial hierarchies, coordinate systems, point/region objects — foundational definitions of MBR, bounding box, spatial predicate.
  • Ch. 3–4: R-tree family (R-tree, R*-tree, R+-tree, Hilbert R-tree) — insert/delete/search pseudocode, split cost analysis, occupancy theory.
  • Ch. 5–6: point quadtrees, region (PR) quadtrees, k-d trees — subdivision rules, depth bounds, range query descent.
  • Ch. 14–15: k-nearest-neighbor, incremental distance browsing — MINDIST/MINMAXDIST definitions, best-first search theorem.
  • Extract: MBR union definition, ChooseLeaf cost model, quadtree subdivision invariant, MINDIST formula derivation, proof that best-first visits minimum nodes.
  • Why: single authoritative source covering all three index families in one notation; all Phase 1–11 algorithms trace back here.

B2 — Samet, H. The Design and Analysis of Spatial Data Structures (Addison-Wesley, 1990)

  • Ch. 2: region quadtrees — splitting threshold, MBR alignment, depth bound for points.
  • Ch. 4: point quadtrees — key-ordering vs. region-ordering distinction.
  • Ch. 8: R-tree introduction — compact derivation of ChooseLeaf and split policies.
  • Extract: quadtree partition correctness proofs (I9), tight formulas for depth given capacity and input density.
  • Why: older companion volume; cleaner formal analysis than Foundations where depth-bound proofs are needed for Phase 9.

B3 — Manolopoulos, Y., Nanopoulos, A., Papadopoulos, A., Theodoridis, Y. R-Trees: Theory and Applications (Springer, 2006)

  • Ch. 2: R-tree variants survey (R+, R*, packed, Hilbert) with comparison tables.
  • Ch. 3: R*-tree algorithms in full detail — choose-subtree pseudocode, overlap-minimizing split axis + distribution, reinsertion algorithm with per-level flag.
  • Ch. 4: bulk-loading algorithms — STR, Hilbert, TGS (top-down greedy split) — complexity and occupancy comparisons.
  • Ch. 6: kNN over R-trees — depth-first vs. best-first, complexity analysis.
  • Extract: R* reinsertion flag (no infinite loop proof), STR slice-count formula P = ceil(sqrt(n/M)), split margin-sum selection.
  • Why: only book that exhaustively covers all R-tree variants with worked numerical examples; primary reference for sidx-rstar Phase 6 and sidx-bulk Phase 7.

B4 — de Berg, M., Cheong, O., van Kreveld, M., Overmars, M. Computational Geometry: Algorithms and Applications (3rd ed., Springer, 2008)

  • Ch. 5: range trees — motivates multi-level indexing and orthogonal range search.
  • Ch. 10: kD-trees — compare vs. quadtree; balance vs. space-efficiency tradeoff.
  • Ch. 14: segment intersection geometry — sweep-line; relevant to MBR intersection predicate correctness.
  • Extract: rectangle intersection test as half-plane intersection; proof that axis-aligned intersection reduces to per-axis interval overlap.
  • Why: provides geometric algorithm correctness proofs applicable to sidx-geom's intersects and contains predicates; formal basis for MBR predicate semantics.

B5 — Cormen, T., Leiserson, C., Rivest, R., Stein, C. Introduction to Algorithms (4th ed., MIT Press, 2022)

  • Ch. 6 (Heaps): binary min-heap operations — insert O(log n), extract-min O(log n); heap property maintenance.
  • Ch. 22 (BFS/DFS): graph traversal templates applied to tree descent.
  • Appendix B: set-theoretic correctness vocabulary used in invariant statements.
  • Extract: min-heap correctness invariant directly used in sidx-knn best-first PQ; heap-size analysis for memory footprint of kNN queries.
  • Why: kNN best-first search (Phase 8) depends on correct priority queue; proof of heap correctness and complexity bounds.

B6 — Ramakrishnan, R. & Gehrke, J. Database Management Systems (3rd ed., McGraw-Hill, 2003)

  • Ch. 14: tree indexes — B+ tree node format, page-aligned nodes, fixed-size serialization.
  • Ch. 16: external memory — buffer pool, LRU replacement policy, pin/unpin protocol.
  • Ch. 19: spatial and temporal data — GiST framework, spatial index integration.
  • Extract: page layout (header + slot array + entries), LRU buffer pool design, dirty-page tracking — map directly to sidx-persist Phase 12.
  • Why: production page-cache design for sidx-persist; compare vs. portfolio project #67 B-tree pager (shared design decisions).

B7 — Arge, L. & Vitter, J. External Memory Data Structures (CRC Handbook of Data Structures and Applications, 2004)

  • Sections on I/O-efficient search trees, R-tree I/O complexity.
  • Fan-out vs. page-size tradeoff: larger pages reduce tree height but increase cache pollution.
  • Extract: optimal page size formula given block-transfer cost; fan-out M as a function of page size and entry size.
  • Why: informs sidx-persist Page size selection — the block size that minimizes I/O for disk-resident spatial indexes.

Papers

P-R1 — Guttman, A. "R-Trees: A Dynamic Index Structure for Spatial Searching." SIGMOD 1984

  • Contribution: defines R-tree structure (balanced, height-uniform); ChooseLeaf (descend by minimum MBR enlargement); quadratic PickSeeds + Distribute split; linear split variant; Insert, Delete, Search algorithms.
  • Implementation relevance: direct algorithm source for sidx-rtree Phases 3–5; ChooseLeaf cost function enlargement(e, q) = area(mbr_union(e,q)) - area(e) is P2's operational formula; split loop and occupancy maintenance map to I3.
  • Key numbers: m = 2, M = 3 in paper examples; production typically m=ceil(0.4M), M=50–200.

P-R2 — Beckmann, N., Kriegel, H-P., Schneider, R., Seeger, B. "The R*-Tree: An Efficient and Robust Access Method for Points and Rectangles." *SIGMOD 1990*

  • Contribution: choose-subtree minimizes overlap enlargement at leaf level (area enlargement above); split axis selected by minimum sum of margins (perimeter); split distribution by minimum overlap; forced reinsertion of p=⌈0.3×(M+1)⌉ entries on first overflow per level.
  • Implementation relevance: primary algorithm source for sidx-rstar Phase 6; reinsertion flag per level prevents infinite reinsertion loops; overlap-minimizing split improves multi-path descent frequency (P4).
  • Key numbers: p = 30% of M+1 entries reinserted; split evaluates all M-2m+2 distributions per axis.

P-R3 — Roussopoulos, N., Kelley, S., Vincent, F. "Nearest Neighbor Queries." SIGMOD 1995

  • Contribution: defines MINDIST(p, rect) = sum over axes of max(0, max(p_i-max_i, min_i-p_i))^2 then sqrt; MINMAXDIST = minimum over axes of (max distance to closest face on that axis); depth-first branch-and-bound kNN.
  • Implementation relevance: MINDIST and MINMAXDIST formulas used verbatim in sidx-core Distance; depth-first variant (compare with best-first in P-R5); MINMAXDIST enables upper-bound pruning (I6).
  • Note: MINMAXDIST formula has a known errata — verify against Hjaltason & Samet 1999 corrected version.

P-R4 — Leutenegger, S., Lopez, M., Edgington, J. "STR: A Simple and Efficient Algorithm for R-Tree Packing." ICDE 1997

  • Contribution: Sort-Tile-Recursive — sort n rectangles by x-center into P = ceil(sqrt(n/M)) vertical slices; sort each slice by y-center; pack into leaves of M; recurse up internal levels.
  • Implementation relevance: direct algorithm source for sidx-bulk Phase 7; slice count formula P = ceil(sqrt(n/M)); generalize to D dimensions by repeating sort-slice for each axis.
  • Key numbers: STR achieves ~90–95% occupancy vs. ~65–75% for sequential insertion; query speedup 2–4× on range queries.

P-R5 — Hjaltason, G.R. & Samet, H. "Distance Browsing in Spatial Databases." TODS 1999

  • Contribution: best-first incremental kNN — single min-heap of (distance, node-or-object) pairs; pop nearest entry, if node push children with MINDIST keys, if object add to result; provably visits minimum nodes among all correct algorithms.
  • Implementation relevance: primary algorithm source for sidx-knn Phase 8; best-first visits fewer nodes than Roussopoulos depth-first for k > 1; heap carries both NodeId (keyed by MINDIST) and DataId (keyed by exact distance).
  • Correctness note: MINDIST formula used here corrects the Roussopoulos 1995 MINMAXDIST errata.

P-R6 — Sellis, T., Roussopoulos, N., Faloutsos, C. "The R+-Tree: A Dynamic Index for Multi-Dimensional Objects." VLDB 1987

  • Contribution: R+-tree avoids overlapping siblings by clipping objects to multiple nodes; eliminates multi-path descent.
  • Implementation relevance: read for contrast only — R+ duplicates objects, violating I7 (object-set conservation); sidx-rtree follows no-duplication R-tree/R*-tree approach; overlap is managed via better splits, not clipping.

P-R7 — Kamel, I. & Faloutsos, C. "Hilbert R-tree: An Improved R-tree Using Fractals." VLDB 1994

  • Contribution: uses Hilbert SFC to order objects before packing, yielding better spatial locality than STR's axis-aligned slicing.
  • Implementation relevance: background for sidx-bulk; STR is the default (simpler, near-equivalent quality); Hilbert packing is recorded as a future option in ADR table; do not implement by default.

P-R8 — Brinkhoff, T., Kriegel, H-P., Seeger, B. "Efficient Processing of Spatial Joins Using R-trees." SIGMOD 1993

  • Contribution: synchronous descent of two R-trees to compute spatial join; overlap predicate drives descent.
  • Implementation relevance: motivates precise semantics of intersects(Rect, Rect) in sidx-geom; spatial join is out of scope but the overlap metric design is shared; avoid a predicate definition that differs from OGC DE-9IM Intersects.

P-R9 — Niemeyer, G. Geohash Specification (geohash.org, 2008, public domain)

  • Contribution: base32 alphabet (32 chars from 0-9b-z omitting a,i,l,o); bit-interleaving order (longitude high bit first for even bits, latitude for odd bits); precision levels 1–12 with cell-size table.
  • Implementation relevance: direct algorithm source for sidx-geohash Phase 10; neighbor cell computation (8-direction carry logic); prefix range scan = all hashes with matching prefix (OGC-compatible bounding box approximation).

P-R10 — Finkel, R.A. & Bentley, J.L. "Quad Trees: A Data Structure for Retrieval on Composite Keys." Acta Informatica 1974

  • Contribution: original point quadtree keyed by coordinate values; 4-way split on the inserted point's coordinates.
  • Implementation relevance: background context for sidx-quadtree; the project implements PR (point-region) quadtree with fixed-region subdivision, not Finkel-Bentley key-split variant; understand the distinction before Phase 9.

P-R11 — Günther, O. "The Cell Tree: An Object-Oriented Index Structure for Geometric Databases." ICDE 1989

  • Contribution: partition-based index with disjoint cells; avoids overlap by design.
  • Implementation relevance: read for contrast; confirms R*-tree split strategy is preferable for dynamic datasets where objects span cell boundaries; reinforces why P4 (minimize overlap) matters.

P-R12 — Berchtold, S., Keim, D., Kriegel, H-P. "The X-tree: An Index Structure for High-Dimensional Data." VLDB 1996

  • Contribution: supernodes to avoid overlap in high-D where all split strategies produce high overlap; degrades gracefully from R-tree to linear scan.
  • Implementation relevance: background for D-dimensional Point<D>; explains why R-tree degrades above ~10D (the "curse of dimensionality" for MBR-based indexing); project scope is D=2 default, extension to D=3 is feasible, higher-D requires ANN (portfolio #255).

P-R13 — Papadias, D., Zhang, J., Mamoulis, N., Tao, Y. "Query Processing in Spatial Network Databases." VLDB 2003

  • Contribution: network-constrained kNN and range queries; shortest-path metrics.
  • Implementation relevance: motivates the Distance abstraction in sidx-core — the euclidean, mindist, minmaxdist functions are pluggable; network-distance kNN is out of scope but the metric interface should accommodate it without breaking I5.

Reference Implementations

R1 — libspatialindex (C++, github.com/libspatialindex/libspatialindex)

  • Files to study: src/spatialindex/Region.cc (MBR union/intersection/enlargement), src/rtree/RTree.cc (ChooseLeaf, split, condense), src/rtree/Statistics.cc (node visits, splits per level), include/spatialindex/IShape.h (interface design).
  • Lessons: node arena with serialization IDs; statistics interface for P10 observability; template for sidx-persist page format.
  • Pitfalls: raw pointer arena in C++ — replace with NodeId(u32) + Vec<RTreeNode> in Rust; do not copy the exception-based error model; use Result<T, SidxError>.

R2 — rstar Rust crate (github.com/Stoeoef/rstar)

  • Files: src/rtree/mod.rs (public API), src/rtree/insertion.rs (choose-subtree, reinsertion), src/algorithm/nearest_neighbor.rs (best-first kNN iterator), src/primitives/rectangle.rs (AABB trait).
  • Lessons: trait-based AABB abstraction; best-first kNN as a Rust iterator (lazy evaluation); generic over dimension via Point trait.
  • Pitfalls: crate uses generic AABB trait rather than a concrete Rect<D> — study interface design but avoid name collision with sidx-rstar; note crate does not implement geohash or quadtree.

R3 — boost::geometry::index::rtree (Boost C++)

  • Files: boost/geometry/index/rtree.hpp (public interface), boost/geometry/index/detail/rtree/visitors/ (query visitor pattern), boost/geometry/index/detail/algorithms/ (split implementations).
  • Lessons: policy-type SplitStrategy maps to SplitStrategy enum in sidx-rtree; visitor-pattern query dispatch; packing (linear, quadratic, rstar) as interchangeable policies.
  • Pitfalls: C++ policy templates produce complex error messages; the equivalent in Rust is an enum dispatch — simpler and sufficient for this project.

R4 — PostGIS GiST / spatial index (github.com/postgis/postgis)

  • Files: postgis/gserialized_gist_2d.c (GiST penalty = enlargement, union = MBR union, consistent = intersects), postgis/lwgeom_gist.c (geometry wrapper).
  • Lessons: production use of enlargement as the GiST penalty function — confirms ChooseLeaf cost model (P2); union function = MBR union in sidx-geom.
  • Pitfalls: PostGIS integrates with PostgreSQL's buffer manager — sidx-persist implements a simpler LRU cache; do not attempt to replicate the GiST extensibility interface.

R5 — georust/geohash Rust crate (github.com/georust/geohash)

  • Files: src/lib.rs (encode, decode, neighbor, decode_bbox).
  • Lessons: base32 lookup table (array of 32 chars); encode loop: interleave lon/lat bits alternately; decode reconstructs min/max per axis from accumulated bits; neighbor carry logic for boundary cells.
  • Pitfalls: neighbor function must handle ±90 lat / ±180 lon boundary wrapping — the crate's carry logic is the reference; off-by-one in precision shifts produces wrong cell sizes (I8 violation).

R6 — quadtree-rs Rust crate (github.com/snorrwe/quadtree-rs)

  • Files: src/lib.rs, src/node.rs.
  • Lessons: leaf-capacity threshold for subdivision; region bounding check before insert.
  • Pitfalls: does not implement PR quadtree delete + condense or region queries with containment semantics — implement Phase 9 from scratch using Samet Ch. 2, not this crate.

R7 — h3 (Uber, github.com/uber/h3)

  • Files: src/h3lib/lib/h3Index.c, src/h3lib/lib/hierarchy.c.
  • Lessons: hierarchical hex-grid indexing with parent/child relationships; compact numeric index for efficient prefix scan.
  • Pitfalls: H3 uses hexagonal cells with ~15% area variance per resolution; geohash uses rectangular cells that perfectly tile; the prefix-search property is geohash-specific and does not apply to H3.

R8 — bvh Rust crate (github.com/svenstaro/bvh)

  • Files: src/bvh_node.rs (SAH split), src/ray.rs (AABB intersection for ray queries).
  • Lessons: SAH (surface-area heuristic) split builds a BVH top-down; each split minimizes child surface area weighted by object count — analogous to R*-tree margin-sum split.
  • Pitfalls: BVH is top-down (requires all objects upfront) and static; STR (sidx-bulk) is bottom-up and also static; do not conflate; SAH is not required for Phase 7 (STR is the default).

R9 — Portfolio Project #67 (B-tree storage engine, this workspace)

  • Files: src/pager.rs (page allocation, read/write), src/node.rs (fixed-size node serialization), src/cache.rs (LRU buffer pool).
  • Lessons: page-aligned node layout with header (magic, version, level, entry_count) + entry slots; LRU cache with pin/unpin; dirty-page tracking and fsync.
  • Pitfalls: B-tree nodes are fixed-fanout with keys; R-tree nodes have variable MBR entries — sidx-persist must accommodate variable-width entry arrays within a fixed page size by storing entry_count in the page header.

Glossary · 43 terms · site-wide glossary

Area enlargement
Increase in MBR area required to accommodate a new entry; the primary cost function in ChooseLeaf for R-tree insertion. Computed by sidx-geom::enlargement(existing: Rect, new: Rect) -> f64.
Axis-aligned bounding box (AABB)
Synonym for MBR in this library; all bounding geometry is axis-aligned.
Balance (height-balanced)
All leaf nodes of an R-tree reside at level 0; no leaf is deeper or shallower than another. Maintained by bottom-up split propagation. Invariant I2.
Base32 (geohash)
32-character alphabet (0–9, b–z minus a/i/l/o) used to encode interleaved coordinate bits into printable geohash strings. Each character encodes 5 bits.
Best-first search
Priority-queue traversal in kNN (sidx-knn) where the node/entry with smallest MINDIST to the query point is always expanded next; guarantees exact k nearest without exhaustive scan.
Bit interleaving
Technique in geohash encoding: alternate longitude bits and latitude bits into a single integer, enabling a 1-D sort that approximates 2-D proximity.
Branch and bound
kNN algorithm framework: maintain a k-result bound; prune any subtree whose MINDIST exceeds the current k-th distance. Implemented in sidx-knn.
Bulk loading
Building an R-tree from a static dataset in a single pass (STR), yielding higher occupancy and better query performance than repeated insertion. See Phase 7.
ChooseLeaf
R-tree insertion subroutine: descend from root to a leaf by choosing the child whose MBR requires the least enlargement to contain the new entry (tie: least area).
Choose-subtree (R*)
R*-tree replacement for ChooseLeaf: at the leaf level minimises overlap enlargement; above leaf level minimises area enlargement. Reduces sibling overlap.
Condense tree
Post-deletion R-tree repair: walk up from the deleted leaf, remove under-full nodes (fewer than m entries), collect their orphaned entries, and reinsert them.
Containment query
Query returning all indexed objects whose MBR is entirely within the query rectangle. Predicate: query_rect.contains(entry.mbr).
Coverage / dead space
Total area of all node MBRs in a level minus the area of their union; a measure of wasted bounding volume. Minimising coverage is a split quality objective in R*-tree.
DataId
u64 opaque identifier stored at R-tree leaves and quadtree leaf slots, referencing the caller's object record. Never dereferenced inside the library.
Enlargement
See Area enlargement.
Entry
A slot within an RTreeNode: carries an MBR and either a Child(NodeId) pointer or a Data(DataId) payload.
Fanout
Number of entries per internal node; bounded between m and M (e.g., m=2, M=8 for testing; m=50, M=100 for production). Determines tree height and I/O cost.
Forced reinsertion
R*-tree overflow strategy: on the first overflow at a given level during one insertion, remove the p (typically 30%) entries farthest from the node centroid and reinsert them, often avoiding a split and improving tree structure.
Geohash
Compact string encoding of a (lat, lng) coordinate as a base32 string; longer strings denote smaller cells. Defined by GeoHash { bits: u64, precision: u8 }.
GeoHash cell
The Rect decoded from a GeoHash value; the original coordinate is guaranteed to lie within it (Invariant I8).
Intersection query
Query returning all indexed objects whose MBR intersects (overlaps) the query rectangle. Predicate: entry.mbr.intersects(query_rect).
kNN (k-nearest-neighbor)
Query returning the k objects with smallest distance from a query point, exact under the chosen metric. Implemented in sidx-knn; exact by P5.
Leaf node
An RTreeNode at level 0; its entries hold Data(DataId) payloads rather than Child(NodeId) pointers.
Linear split
O(n) node split algorithm from Guttman 1984: pick seeds by most extreme low/high coordinates on each axis; distribute remaining entries by least MBR enlargement. Low quality but fast.
MBR (minimum bounding rectangle)
The tightest axis-aligned rectangle enclosing a set of objects or child MBRs. Every node's stored MBR must satisfy Invariant I1.
MINDIST
Lower bound on the distance from a point to the nearest object in a subtree, computed from the point and the node's MBR. Used to prune branches in kNN (I6).
MINMAXDIST
Upper bound on the distance to the nearest object in a subtree; the minimum over all faces of the maximum distance from the query point to the face's far corner. Enables early termination.
NodeId
u32 arena index identifying an RTreeNode or QuadNode in the slab allocator; no raw pointer arithmetic.
Occupancy
Fraction of node slots filled; bounded by Invariant I3 (m <= count <= M for non-root). STR bulk-loading targets ~85–100% occupancy.
Overlap
Area of intersection between two sibling node MBRs; high overlap forces searches down multiple subtrees, degrading query performance. Minimised by R*-tree split.
Page / PageId
Fixed-size byte block (e.g., 4096 bytes) in sidx-persist; each tree node is serialised into one or more pages identified by PageId.
Pick seeds
First step of quadratic/linear split: select two entries as the initial pair for the two groups being formed.
Point quadtree
Quadtree variant that partitions space by inserting points; each point becomes a subdivision centre. Distinguishable from region/PR quadtree.
Prefix range
For a geohash prefix string, the contiguous lexicographic range [prefix, prefix_end) that covers all cells sharing that prefix; enables efficient DB range scans.
PR quadtree
Point-Region quadtree: space is subdivided into fixed quadrants (not centred on data points); all points in a region share the same quadrant. Implemented in sidx-quadtree.
Quadratic split
O(n²) node split: pick seeds maximising the area of the MBR of the pair minus both individual MBRs; distribute remaining entries to the group requiring less enlargement.
R*-tree
Extension of R-tree by Beckmann et al. (1990) adding overlap-minimising choose-subtree, improved split axis selection, and forced reinsertion. Implemented in sidx-rstar.
R-tree
Dynamic spatial index by Guttman (1984): height-balanced tree of MBRs, analogous to a B-tree for spatial data. Implemented in sidx-rtree.
Rect
{ min: Point, max: Point } with min[i] <= max[i] per axis. Canonical MBR type. Degenerate (min==max) permitted for point MBRs.
SplitStrategy
Enum { Quadratic, Linear, RStar } selecting which split algorithm sidx-rtree/sidx-rstar uses at node overflow.
Sort-Tile-Recursive (STR)
Bulk-loading algorithm: sort by x-centre into sqrt(n/M) vertical slices, sort each slice by y-centre, pack into full leaf nodes, recurse up. Implemented in sidx-bulk.
Spatial index
Data structure that organises objects by their geometric extent (MBR or point) to answer spatial queries in sub-linear time.
Window query
Synonym for range query: return all objects whose MBR intersects a rectangular query window. The most common spatial query type.
