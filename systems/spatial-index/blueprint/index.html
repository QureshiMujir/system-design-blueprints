1. Goal

1.1 What Is Built

A from-scratch multi-dimensional spatial index library in Rust: an R-tree with R*-tree split/reinsertion improvements and Sort-Tile-Recursive bulk loading, a point/region (PR) quadtree, and a geohash codec. Serves window, range, intersection, containment, and exact k-nearest-neighbor (kNN) queries. A brute-force linear-scan oracle (sidx-oracle) proves correctness differentially across all query types and all index variants.

1.3 Explicit Non-Goals

  • No geodesic (great-circle) distance; all geometry is Euclidean in ℝ^D.
  • No polygon clipping, Voronoi, convex hull, or topological predicates.
  • No concurrent insert/delete; all mutation is single-threaded (thread-safe reads are a deferred goal).
  • No approximate kNN; exactness is an invariant (I5).
  • No SIMD vectorization of MBR operations in this phase (PhaseDeferred("Deferred Features Register")).

1.4 Intended Deployment Model

  • Embedded library (crate dependency) for Rust applications requiring spatial lookup.
  • sidx-cli as a standalone binary for build/query/bench over binary index files.
  • Single-machine, single-process; indexes fit in RAM or spill to disk via sidx-persist page cache.
  • No daemon, no network listener, no external dependencies beyond the Rust standard library and a small set of utility crates (byteorder, ordered-float, criterion for benchmarks).

1.9 Language Rationale — Rust (Locked)

Spatial indexing is bounding-box tree machinery: insert/split that must keep MBRs tight, best-first kNN search driven by a priority queue of MINDIST bounds, and bulk loading that sorts millions of rectangles — all cache- and allocation-sensitive. Rust gives arena/index-based node storage (no pointer-chasing GC graph), exhaustive enums for node/query kinds, precise f64 geometry, and zero-copy entry slices on the search hot path. The geometry kernel, R-tree, R*-tree, quadtree, geohash, bulk loader, and kNN/window query engine are all Rust.

2.2 Historical and Architectural Significance

  • Guttman's R-tree (SIGMOD 1984) is the canonical general-purpose spatial index, the substrate of PostGIS, Oracle Spatial, and every major GIS system.
  • R*-tree (SIGMOD 1990) remains the default choice for dynamic spatial workloads: its quality improvements are adopted unchanged in libspatialindex, Boost.Geometry, and spatial DB extensions.
  • Geohash (Niemeyer, 2008) is ubiquitous in location services: enables spatial proximity queries with a plain string prefix scan on any ordered key-value store.
  • Best-first kNN (Roussopoulos 1995; Hjaltason & Samet 1999) is the reference algorithm for exact nearest neighbor in all production R-tree implementations.
  • STR bulk loading (Leutenegger 1997) is standard practice in ETL pipelines loading static geographic datasets.
  • These structures underlie map tile servers, ride-sharing dispatch, geofencing, collision detection engines, and spatial JOIN in analytical databases.

2.3 Engineering Muscles Developed

  • Tree invariant maintenance: writing code that preserves I1–I10 across every operation.
  • Geometric reasoning: exact floating-point bounds arithmetic; degenerate-case handling (zero-area rects, collocated points).
  • Priority-queue–driven search: best-first traversal vs depth-first; correctness of pruning conditions.
  • Arena-based memory management: NodeId indexing pattern instead of raw pointers; borrow-checker-compatible tree mutation.
  • Parametric data structures: generic-over-D geometry; strategy enum (SplitStrategy) selecting algorithms at runtime.
  • Disk I/O discipline: page-aligned serialization; distinguishing cache-resident from evicted nodes.
  • Correctness culture: oracle-driven differential testing; property tests for distance bounds and geometric invariants.

3.2 Subsystem Descriptions

sidx-core / sidx-geom — geometry foundation. sidx-core defines all shared types: Point<D>, Rect/MBR, NodeId(u32), DataId(u64), Entry, RTreeNode, QuadNode, GeoHash, KnnItem, Query, SplitStrategy, BulkLoad. No I/O, no algorithms. sidx-geom provides the MBR algebra every tree depends on: union (tight bounding of two rects), intersection predicate, area/volume, enlargement (area increase to absorb a new rect — drives ChooseLeaf), overlap area (drives R* split axis choice), contains predicate, and the two distance bounds mindist(point, rect) and minmaxdist(point, rect) that make kNN pruning sound. All other crates import these; the geometry boundary is strict — no tree logic leaks into sidx-geom. Data flows in as Rect pairs; results flow out as scalars (f64) or predicates (bool).

sidx-rtree — R-tree node storage and core operations. Owns an arena Vec<RTreeNode> indexed by NodeId; the root handle is a NodeId. Insert executes ChooseLeaf (least-enlargement descent), adds the Entry, and on overflow (entries > M) splits via quadratic or linear algorithm, propagating splits and MBR adjustments (AdjustTree) up to the root. Window search recurses, pruning subtrees whose MBR does not intersect the query rect; returns Vec<DataId>. Delete finds the leaf entry, removes it, executes CondenseTree (collect orphaned entries from under-full nodes, reinsert them), adjusts MBRs upward. Height is maintained by level bookkeeping; root split increases height. Trust boundary: callers must provide valid Rects; degenerate input (min > max) is normalized by sidx-geom before entry.

sidx-rstar — R-tree split and reinsertion overlay.* Replaces ChooseLeaf with choose-subtree (overlap-enlargement minimization at the leaf level; area-enlargement above). Replaces the quadratic split with R* split: sort entries by each axis, evaluate margin sum, select the axis minimizing margin, then choose the split index minimizing overlap (area as tiebreaker). On first overflow at each level during a single insert, invokes forced reinsertion of the p closest-to-center entries rather than splitting immediately. SplitStrategy::RStar selects this path in sidx-rtree. No new arena; delegates node storage entirely to sidx-rtree. The overlay boundary is the SplitStrategy enum dispatch in the insert path.

sidx-bulk — Sort-Tile-Recursive (STR) bulk loader. Accepts a slice of (Rect, DataId) pairs; produces a fully built R-tree via sidx-rtree arena. Algorithm: compute slice count S = ceil(sqrt(n/M)); sort all rects by x-center into S vertical slices; within each slice sort by y-center; pack consecutive M rects into leaf nodes; recurse one level up until root. Builds near-optimal, high-occupancy static trees far faster than repeated insertion. Output is a read-mostly tree rooted at a NodeId in the shared arena. Concurrency boundary: single-threaded; parallelism of sort passes is PhaseDeferred.

sidx-quadtree — point / region (PR) quadtree. Maintains its own arena of QuadNode: each node is either a Leaf(Vec<(Point, DataId)>) or Internal([NodeId; 4]). Insert: find the leaf whose bounds contain the point; if capacity exceeded, subdivide into four equal quadrants and redistribute entries. Point query: exact match by coordinate. Range query: recursive quadrant overlap test, collect all DataId entries from overlapping leaves. Depth is bounded to prevent infinite subdivision on duplicate/collocated points (degenerate case: bucket all collocated points into one leaf). Partition invariant I9 (children exactly partition parent bounds, no overlap, no gap) is enforced on subdivision. The quadtree is independent of the R-tree arena; it uses its own NodeId namespace.

sidx-geohash — geohash codec. Encodes a (lat, lng) pair by interleaving longitude bits (even) and latitude bits (odd) into a 64-bit integer, then base32-encoding to a string of given precision (1–12 chars). Decodes a string back to a bounding Rect (the cell). Precision controls cell size (precision 1 ≈ 5000 km × 5000 km; precision 12 ≈ 3.7 mm × 1.9 mm). Computes the 8 neighbor cell hashes (N, NE, E, SE, S, SW, W, NW) including boundary carry logic. For a query bounding box, returns the set of prefix strings whose union covers the box — enabling prefix-range scans on ordered key stores. The codec has no tree state; it is a pure function layer. Invariant I8: decoded cell always contains the original point.

sidx-knn — best-first kNN search. Implements a min-heap (BinaryHeap<KnnItem>) keyed by mindist(query_point, node_mbr). Pop the nearest unvisited node; if it is a leaf, emit its DataId entries into a k-element result max-heap, pruning any entry farther than the current k-th distance. If it is an internal node, push all children with their MINDIST. Prune a child if mindist(point, child_mbr) >= current_k_dist. Use minmaxdist to tighten the upper bound: if another node's MINMAXDIST < a candidate's MINDIST, the candidate cannot improve the result. Terminates when the heap is empty or all remaining nodes have MINDIST > current k-th dist. Returns exactly the k nearest DataId values with their distances. Correctness gate: result must match sidx-oracle kNN on every test case (I5).

sidx-query — unified query dispatch layer. Exposes a single Query enum: Window(Rect), Intersect(Rect), Contains(Rect), Knn(Point, usize), Nearest(Point). Dispatches to sidx-rtree, sidx-rstar, sidx-quadtree, or a geohash-prefilter + tree-refine pipeline depending on the index handle. Intersection semantics: any overlap between object MBR and query rect. Containment semantics: query rect fully contains object MBR. Window semantics: alias for intersection in this implementation (per Guttman). Normalizes result types across index kinds; callers see Vec<DataId> or Vec<KnnItem> uniformly. Concurrency boundary: read-only query paths are logically re-entrant; the dispatch layer itself holds no mutable state.

sidx-oracle — brute-force correctness reference. Maintains a flat Vec<(Rect, DataId)> or Vec<(Point, DataId)>. Implements every query type via linear scan. Used exclusively in tests and benchmarks, never in production code paths. Correctness gate: for every randomized dataset and query, sidx-rtree/sidx-rstar/sidx-quadtree results must equal the oracle's results (set equality for window/intersect/contains; ordered-by-distance equality for kNN). A discrepancy is a bug in the index, never in the oracle.

sidx-persist — page-aligned disk persistence. Serializes each RTreeNode into a fixed-size Page (configurable: 4 KiB or 8 KiB). PageId mirrors the NodeId arena index; the page file is a flat array of pages. An in-memory LRU page cache (capacity configurable) holds hot nodes; cache miss triggers a page read from the file. Dirty pages are written back on eviction or explicit flush. On cold start, the root NodeId is read from the header page; the tree is traversed on-demand. Node format includes: magic bytes, format version, level, entry count, entries (each: MBR as 4×f64, child NodeId or DataId as u64). Persistence boundary: sidx-rtree and sidx-rstar talk to the arena through a NodeStore trait; sidx-persist provides the disk-backed implementation; in-memory tests use a Vec-backed implementation.

sidx-cli — command-line tool. Subcommands: build (bulk-load or sequential-insert from CSV/binary input into an index file), insert (single or batch insert into an existing file), query (window/intersect/contains over a persisted index), knn (k nearest neighbors), bench (throughput/latency benchmark over configurable object count and query selectivity). Selects index type via --index {rtree|rstar|quadtree} flag. Outputs results as newline-delimited DataId values or JSON. Trust boundary: validates and normalizes all CLI input; propagates errors to stderr without panicking.

  • Ch. 1–2: spatial hierarchies, coordinate systems, point/region objects — foundational definitions of MBR, bounding box, spatial predicate.
  • Ch. 3–4: R-tree family (R-tree, R*-tree, R+-tree, Hilbert R-tree) — insert/delete/search pseudocode, split cost analysis, occupancy theory.

  • Ch. 8: R-tree introduction — compact derivation of ChooseLeaf and split policies.

6. Design Principles

P1 — Correctness Proven Against a Brute-Force Oracle

Statement: every query result returned by any index in this library must identically match the result of a linear scan over the same dataset. The index is an acceleration structure — it must never return a different answer than exhaustive search.

Mechanism:

  • sidx-oracle implements each Query variant as an O(n) linear scan with the same predicate logic as sidx-geom.
  • Differential harness (Phase 14): generate random datasets of size 1 K, 10 K, 100 K, 1 M objects; run 10 K random queries per dataset; compare index result sets vs. oracle result sets by DataId.
  • Any asymmetric difference (false negative = in oracle but not index; false positive = in index but not oracle) is a blocking defect.

Tradeoffs:

  • Oracle is O(n) per query — feasible only in tests; production index is the indexed answer.
  • Adding a new query predicate requires an oracle branch before merging; this is the correct gate.

Operational implications:

  • CI runs the differential harness on every PR; failure blocks merge.
  • Oracle result sets are the definition of correct — if the oracle has a bug, it is fixed alongside the index bug.

Violation consequence: an optimization such as early-exit during descent silently drops objects from the result set. Users receive spatially incomplete results with no error or warning. This is the most dangerous failure mode because it is silent and statistically rare for small datasets.

P2 — MBR Conservatism

Statement: every node's MBR is always the tight bounding rectangle of all objects in its subtree. "Tight" means no smaller rectangle encloses all objects. The MBR never under-represents its subtree (correctness) and ideally never over-represents it (query efficiency).

Mechanism:

  • On insert: propagate MBR adjustments from the inserted leaf up to the root (AdjustTree).
  • On delete: recompute the tight MBR at every node along the path after CondenseTree (cannot enlarge MBR; must shrink if an entry was removed).
  • On split: new parent MBR = union of the two child MBRs.
  • Post-mutation invariant check (Phase 14): for every node, assert node.mbr == union(entry.mbr for entry in node.entries).

Tradeoffs:

  • Tight MBR recomputation after deletion is O(|entries|) per node per level = O(M × height); acceptable for M ≤ 200 and height ≤ 6.
  • An approximate (too-large) MBR is safe for correctness but degrades query performance by reducing pruning efficiency.

Operational implications:

  • Bulk load (STR) computes leaf MBRs exactly; assert post-build.
  • Monitor mean_mbr_wastage (overlap area in a node's MBR not covered by any entry) as a quality metric; should be near zero after STR, may grow after repeated inserts/deletes.

Violation consequence: a too-small MBR causes search to prune a subtree that contains matching objects — false negatives (silent result loss). A too-large MBR does not break correctness but forces unnecessary subtree visits (performance regression without correctness alarm).

P3 — Balanced Height

Statement: all leaf nodes of the R-tree reside at level 0. All nodes at level k are exactly k levels above the leaves. Height = root.level. The tree is strictly height-balanced at all times.

Mechanism:

  • Insert: ChooseLeaf descends to level 0; on overflow, split propagates upward; a root split creates a new root at level = old_root.level + 1 with two children.
  • Delete: CondenseTree removes underfull nodes and reinserts their entries at the correct level, preserving the level invariant.
  • Every new node created by a split is assigned level = parent.level - 1.

Tradeoffs:

  • Height-balance means the root split doubles the root level — correct but temporarily increases search depth by 1.
  • Quadtrees are NOT height-balanced — depth varies by object distribution; this principle applies only to R-tree / R*-tree families.

Operational implications:

  • After any insert or delete, assert all nodes with entries pointing to DataIds have level == 0 (I2 check).
  • Monitor tree_height as a key metric; unexpectedly high height signals split-quality regression or extremely non-uniform data.

Violation consequence: an unbalanced tree (some leaves at different levels) produces O(n) worst-case search paths through deep branches; no error is thrown; queries silently degrade to near-linear time.

P4 — Minimize Overlap and Coverage

Statement: split quality is measured by overlap area between sibling MBRs and total dead space (coverage minus total object area). Split algorithms must minimize overlap first, then dead space.

Mechanism:

  • R*-tree split (sidx-rstar): evaluate all split axes; choose axis minimizing sum of margins (perimeter); choose distribution minimizing overlap; tie-break by minimum area (I3, fanout M-2m+2 distributions evaluated per axis).
  • Forced reinsertion: before splitting, reinsert p=⌈0.3×(M+1)⌉ entries (those farthest from the node center); gives the tree a chance to place entries in better positions first.
  • Quadratic split (sidx-rtree): PickSeeds chooses the pair maximizing the "waste" (area of combined MBR minus their individual areas); Distribute adds each remaining entry to the group with smaller enlargement.

Tradeoffs:

  • R*-tree split is O(M log M) vs. O(M²) for quadratic vs. O(M) for linear; M ≤ 200 makes R*-tree cost acceptable.
  • Forced reinsertion increases insert cost but reduces overlap accumulation; net effect is better query performance after many inserts.

Operational implications:

  • Record split_overlap_ratio and split_dead_space_ratio per split event (P10); alert if mean overlap ratio exceeds 20% — indicates poor data distribution or wrong split axis choice.
  • For pathological inputs (all objects at the same location), force a degenerate split rather than infinite reinsertion (check for convergence).

Violation consequence: high overlap between sibling MBRs forces the search algorithm to descend into multiple children on nearly every query. A tree with 50% overlap ratio on every level degrades O(log n) search to O(n) in the worst case while still appearing structurally valid.

P5 — kNN Search is Exact, Not Approximate

Statement: a k-nearest-neighbor query returns exactly the k DataIds with the smallest distance to the query point under the specified metric. No approximation factor is acceptable. Tie-breaking is deterministic (by DataId ascending).

Mechanism:

  • Best-first heap: min-heap of KnnItem keyed by MINDIST for NodeIds, exact distance for DataIds.
  • Pop loop: pop minimum; if NodeId, push all children with their MINDIST keys; if DataId, add to result and stop when k results collected.
  • MINMAXDIST pruning: if the k-th result distance is already less than MINMAXDIST of a node, that node cannot improve the result and is skipped before enqueueing.
  • Pruning condition: if heap.peek().dist > current_kth_dist { prune }.

Tradeoffs:

  • Exact search visits O(log n + k × M) nodes average; for large k or high-overlap trees, cost approaches O(n).
  • Approximate ANN (portfolio #255, HNSW) trades accuracy for speed in high-dimensional spaces; not applicable here (D=2, exact required).

Operational implications:

  • Compare kNN result list against oracle-sorted distance list element-by-element in Phase 14 differential tests (I5).
  • Monitor knn_nodes_visited per query; high values indicate poor tree quality or unusually large k.

Violation consequence: approximate results are spatially wrong; applications that depend on exact nearest neighbors (routing, proximity deduplication, geofencing) produce incorrect decisions silently.

P6 — Bulk Load When Static

Statement: for datasets known at build time, Sort-Tile-Recursive (STR) packing achieves higher occupancy, better MBR tiling, and faster build than repeated insertion. A STR-built tree is treated as read-only by convention.

Mechanism:

  • STR: sort n rects by x-center → partition into P = ceil(sqrt(n/M)) vertical slices → sort each slice by y-center → pack into leaf nodes of M → recurse up internal levels.
  • Occupancy: near-100% leaf fill vs. ~65–75% for sequential insertion.
  • Build time: O(n log n) sort-dominated vs. O(n × M × log_M n) for repeated insertion.

Tradeoffs:

  • STR requires all n objects in memory simultaneously (or a merge-sort external variant for disk-resident data).
  • Streaming datasets (objects arriving over time) must use dynamic R-tree insertion.
  • A STR tree that later receives inserts degrades packing; the convention is to either rebuild or switch to a dynamic tree after a threshold number of inserts.

Operational implications:

  • sidx-cli build --bulk invokes STR; build --dynamic invokes sequential insert; both must pass oracle verification.
  • After STR build, assert mean leaf occupancy ≥ 90% and tree height == ceil(log_M(n)).

Violation consequence: using dynamic insertion for a static 10 M-object dataset yields 3–10× higher query latency (lower occupancy → more nodes per path → more cache misses) and 2–3× more node visits vs. STR, with no structural error indication.

P7 — Bounded Node Fanout

Statement: every non-root node holds between m and M entries (I3). Default: m = ceil(0.4 × M), M = 50. Root holds ≥ 2 entries unless it is also the only leaf.

Mechanism:

  • Insert overflow (|entries| > M): split node; propagate.
  • Delete underflow (|entries| < m): condense — remove node, reinsert its entries at the correct level via Insert; repeat up to root.
  • Root collapse: if root has exactly 1 child after condense, that child becomes the new root (decreases height).

Tradeoffs:

  • Larger M reduces tree height and cache pressure per search but increases split cost and per-node memory.
  • Smaller m increases restructuring frequency but keeps nodes dense.
  • Typical production values: M=50–100 for memory; M=100–500 for disk-paged (matched to page size ÷ entry size).

Operational implications:

  • Expose m and M as configuration in BulkLoad and a separate RTreeConfig struct.
  • Assert m <= node.entries.len() <= M in debug-mode post-mutation checks (panic in test, log-and-continue in release).

Violation consequence: nodes with fewer than m entries degrade tree height and waste page space. Overfull nodes (|entries| > M) overflow the fixed-size page in sidx-persist, causing serialization buffer overflow — a memory safety issue in unsafe Rust or a panic in safe Rust.

P8 — Geometry is Exact and Well-Formed

Statement: every Rect satisfies min[i] <= max[i] for all axes. Every distance computation operates on valid f64 values (not NaN). Degenerate point-Rects (min == max) are valid. Constructors validate geometry in debug mode.

Mechanism:

  • Rect::new(min, max) asserts min[i] <= max[i] in debug builds; normalizes in release builds (swap if violated, or reject with Err).
  • Point::new(coords) rejects any coordinate that is_nan().
  • f64::INFINITY is a valid sentinel for unbounded queries and uninitialized kNN distances.
  • All sidx-geom functions are pure and contract-annotated: preconditions (well-formed inputs), postconditions (well-formed outputs).

Tradeoffs:

  • Rejecting NaN at construction requires callers to sanitize upstream; preferable to silently propagating NaN into MBR union computations.
  • Release-mode normalization (swap min/max) is forgiving but hides caller bugs; prefer assertion + Err in all modes for the public API.

Operational implications:

  • All public constructors for Point and Rect are the geometry validation boundary; internal functions may assume well-formedness.
  • Fuzz test (Phase 14): send random f64 pairs including NaN, Infinity, and -0.0 to constructors; assert no panic and correct error return.

Violation consequence: a Rect with min > max produces negative area, wrong enlargement, and inverted intersection tests. Subtrees become unfindable (I1 broken). MBR union of an invalid rect propagates invalid geometry upward through the entire tree.

P9 — Structure-Agnostic Queries

Statement: window, intersection, containment, and kNN queries are defined once in the Query enum (sidx-query) and dispatched to any index type. Predicate semantics are determined by sidx-geom functions; no index carries its own predicate logic.

Mechanism:

  • Query enum: Window(Rect), Intersect(Rect), Contains(Rect), Knn(Point, usize), Nearest(Point).
  • sidx-query dispatch: match on index type (R-tree, R*-tree, quadtree) and query variant; call sidx-geom predicates for pruning decisions.
  • sidx-oracle implements the same Query enum via linear scan with the same sidx-geom predicates.
  • Geohash prefilter: for spatial range queries on geohash-encoded datasets, compute prefix ranges → scan → refine with the R-tree; the refinement step re-applies the same Query.

Tradeoffs:

  • Unified dispatch adds one enum-match overhead per query; negligible vs. tree traversal cost.
  • Adding a new predicate requires: new Query variant + new sidx-geom predicate + new oracle branch + new differential test = one atomic changeset.

Operational implications:

  • Any caller of sidx-query uses the same API regardless of which index type is backing the store.
  • A Query::Contains query must use sidx-geom::contains(object_rect, query_rect) (object fully within query), not intersects — document the distinction clearly.

Violation consequence: predicate semantics that differ across index implementations produce inconsistent results depending on which index type a caller happens to use. A Contains query returning Intersect results is undetectable without cross-index comparison or oracle differential testing.

P10 — Observability

Statement: node visits, subtrees pruned, heap maximum size, split quality (overlap ratio, margin sum), and result count are measurable per query and per insert. sidx-cli exposes --explain and --stats flags. Benchmarks log these counters.

Mechanism:

  • QueryStats struct: nodes_visited: u64, subtrees_pruned: u64, heap_max_size: usize, results: usize.
  • InsertStats: splits: u32, split_overlap_ratio: f64, reinsertions: u32.
  • Counter increments: ~1–3 ns per node visit (cache write, no branch); negligible overhead vs. cache-miss cost of node access.
  • sidx-cli query --explain prints QueryStats per query; bench aggregates P50/P95/P99 latency and mean nodes_visited.

Tradeoffs:

  • Stats collection adds a small constant factor; disable in release builds via a feature flag if needed.
  • Heap max size is bounded by tree height × M; logging it catches runaway heap growth in pathological kNN queries.

Operational implications:

  • Regression in nodes_visited per query (e.g., 5× increase after 10 K inserts into a static tree) signals overlap accumulation — trigger a rebuild.
  • subtrees_pruned / nodes_visited ratio is the pruning efficiency; a healthy R*-tree on 2D data should prune 90–99% of subtrees on a 1% selectivity window query.

Violation consequence: without counters, a sudden 5× throughput drop is undiagnosable — could be split-quality regression, merge thrashing, kNN heap size explosion, or OS-level memory pressure. No counter means no root-cause analysis.

P11 — MBR Conservatism (Over-Approximation Safety Floor)

Statement: a node's MBR must never fail to spatially contain every point in its subtree. Over-approximation (an MBR larger than the tight union) is always safe; under-approximation (an MBR that excludes even one point actually present in a child) is a correctness failure — search silently prunes a branch holding a true hit. This is the floor beneath P2's tightness goal: P2 says "keep MBRs tight for performance"; P11 says "when tightness cannot be momentarily guaranteed, err large, never small."

Mechanism:

  • R-tree Search descent (Phase 3 window_search/intersect_search) tests intersects(entry.mbr, query_rect) purely against the stored MBR and never re-derives it from the subtree's actual contents, so soundness depends entirely on the stored MBR conservatively covering what is below it.
  • ChooseLeaf (Phase 4 choose_leaf) selects a subtree by least enlargement; enlargement is only meaningful if the compared MBRs are conservative (⊇) at the moment of comparison — an under-sized MBR makes the wrong subtree look artificially cheap and can route an insert to the wrong leaf before any split logic runs.
  • Any code path that mutates an MBR without immediately restoring at least containment (union ⊆ new MBR) violates I11 the instant it runs, not only after the mutation "settles."

Tradeoffs:

  • Over-approximating under uncertainty (e.g., a deferred-tightening or lazy-AdjustTree design) trades search efficiency (P4/P2 pruning quality) for a guarantee that is cheap to prove and cheap to check — the direction of the error only ever costs performance, never correctness.
  • The reverse trade ("assume tight, skip the containment check because AdjustTree already ran") is the one that produces silent, hard-to-reproduce false negatives; P11 exists to make that trade explicit and forbidden.

Operational implications:

  • New split, bulk-load, or persistence-path code is reviewed for "can the MBR I am about to store possibly be smaller than the true union?" before it is reviewed for tightness.
  • I11's tree-validator walk (containment only, no equality) is cheap enough to run continuously in production behind debug_invariants, precisely because it checks the invariant that must never break.

Violation consequence: identical in kind to P2's — false negatives — but broader in cause: it can occur even when I1 tightness holds in steady state, if any transient path (a partially applied batch update, a crash-recovery replay stopped mid-AdjustTree, a hand-patched page in sidx-persist) produces a momentarily under-sized MBR. This is why sidx-persist's rebuild_index integrity check and I11's validator check containment independently of whether the tree claims to be "settled."

P12 — Deterministic Split & Bulk-Load Ordering

Statement: given the same input objects in the same input order, sidx-rtree/sidx-rstar node splits (quadratic PickSeeds/Distribute, R*-tree axis/distribution selection) and sidx-bulk's STR packing produce byte-identical trees on every run, on any machine. Every tie in a split or sort comparator resolves via an explicit, total secondary key — never via hash-iteration order, thread scheduling, or unspecified sort stability.

Mechanism:

  • Quadratic split PickSeeds ties (equal "waste") resolve by lowest combined NodeId; Distribute ties (equal enlargement) resolve by smaller resulting group, then by lowest NodeId (Phase 4).
  • R*-tree axis/margin ties and distribution-overlap ties resolve by the lower axis index, then the lower distribution index (Phase 6).
  • STR's two sort passes (x-center, then y-center per slice) use a comparator with an explicit DataId tie-break so co-located objects never depend on sort-algorithm stability (Phase 7).
  • ChooseLeaf's tie-break chain (least enlargement → least area → lowest NodeId) is the same mechanism applied at insertion time (Phase 4) and is the concrete basis for I10.

Tradeoffs:

  • A fully specified total order for every tie-break adds a small constant-time comparison in the rare tie case; negligible next to the cost of the split or sort itself.
  • Determinism constrains future optimizations: a parallel or sampling-based split heuristic for very large M must preserve the same tie-break contract, or document a new, still-deterministic one — "non-deterministic but faster" is not an acceptable substitute.

Operational implications:

  • P12 is the design-level contract that I10 (Determinism) tests: I10 asserts the black-box outcome (byte-identical serialized trees across two runs); P12 is the specific comparator ruleset inside split.rs/str_pack.rs that makes that outcome possible.
  • Persistence round-trip and differential tests (Phase 14) can diff two independently built trees from the same input and attribute any divergence to whichever comparator introduced non-determinism, rather than to a generic "flaky test."

Violation consequence: a split or STR sort that leaves a tie unresolved (default sort stability, HashMap iteration, or an unspecified path through equal floating-point centers) produces a tree whose structure differs run-to-run for identical input. Query correctness is unaffected (results still match the oracle), but reproducible benchmarking, bit-for-bit persistence round-trips, and the ability to diff two builds to localize a regression all break silently — exactly what I10's byte-equality assertion is designed to catch.

7. System Invariants

I1 — MBR Containment

Field Detail
Statement Every R-tree node's stored MBR equals the tight union of its direct children's MBRs; every object in the node's subtree is spatially contained within the node's MBR.
Why it matters Pruning soundness: if !intersects(node.mbr, query_rect) is true, zero objects in the subtree can match — this is the fundamental correctness guarantee of tree-based spatial search.
Where enforced sidx-rtree adjust_tree (post-insert MBR propagation); condense_tree (post-delete MBR shrink); sidx-bulk STR leaf/internal MBR construction; sidx-rstar reinsertion path.
Detection Post-mutation audit function in tests: recursively recompute union of all children's MBRs, assert == node.mbr; differential oracle comparison catches false negatives caused by I1 violation.
Telemetry mbr_mismatch_count counter incremented in audit function; logged with node id, level, stored MBR, computed MBR.
Recovery Offline repair: walk tree bottom-up, recompute and overwrite MBRs; mark all affected pages dirty in sidx-persist; this is a maintenance tool, not a runtime recovery path.
Debug Binary search on mutation history to find the earliest violation; print the (node_id, stored_mbr, computed_mbr) triple; check the AdjustTree call that was skipped or computed incorrectly.

I2 — Height Balance

Field Detail
Statement All leaf nodes of an R-tree are at level 0; all nodes at the same level have the same depth from their leaves; the tree height = root.level.
Why it matters Guarantees O(log_M n) search cost; degenerate trees with unequal leaf levels produce O(n) worst-case searches without any error signal.
Where enforced sidx-rtree insert root-split path (new root gets level = old_root.level + 1); condense_tree reinserts orphaned entries at their original level (not at level 0); split_node assigns level = parent.level - 1 to new nodes.
Detection BFS over arena: collect all NodeIds with entries that point to DataId (leaves); assert exactly one distinct level value across all leaves.
Telemetry leaf_level_histogram: HashMap<u16, u32> — should have exactly one entry with key 0; any other entry signals imbalance.
Recovery No runtime recovery; an imbalanced R-tree requires a full rebuild from its DataId leaf entries.

I4 — Window / Intersection / Contains Query Soundness and Completeness

Field Detail
Statement Every query returns exactly the set of DataIds satisfying the predicate according to sidx-geom; no false positives (result not satisfying the predicate), no false negatives (satisfying objects not in result).
Why it matters The fundamental correctness contract; a spatial index that omits results is unusable in any proximity/geographic application.
Where enforced sidx-query dispatch + sidx-rtree / sidx-quadtree search descent; predicate applied at leaf level against actual object MBR (not node MBR — node MBR is for pruning only).
Detection Differential harness: oracle_results XOR index_results must be empty for every test query; tested in Phase 14 across dataset sizes 1 K–1 M and 10 K random queries per size.

I5 — kNN Exactness

Field Detail
Statement A k-NN query returns the k DataIds with smallest Euclidean distance to the query point; ties broken by DataId ascending; no duplicates; the (k+1)-th nearest object is strictly farther than the k-th.
Why it matters Applications using kNN (routing, proximity deduplication, geofencing) require exact results; approximate nearest neighbors silently corrupt business logic.

I6 — MINDIST / MINMAXDIST Bounds

Field Detail
Statement For any Point p and Rect r: MINDIST(p,r) ≤ dist(p, nearest object in subtree rooted at r) ≤ MINMAXDIST(p,r).
Why it matters These bounds are the correctness basis for pruning in sidx-knn; pruning a subtree whose MINDIST exceeds the current k-th distance is only safe if MINDIST is truly a lower bound.
Where enforced sidx-core distance::mindist and distance::minmaxdist functions; sidx-knn pruning condition.

I7 — Split / Merge Object Conservation

Field Detail
Statement The multiset of DataIds stored in the tree is preserved across any insert or delete operation: an insert adds exactly one new DataId; a delete removes exactly one; splits and reinsertions are neutral.
Why it matters Object loss or duplication are silent data corruption bugs; splits and forced reinsertions involve moving entries between nodes and can lose entries if the condense queue is not fully drained.
Where enforced sidx-rtree insert (ChooseLeaf + split conserves all M+1 entries across two nodes); condense_tree (orphaned entries must all be reinserted before returning); sidx-rstar reinsertion queue.
Detection Full-scan DataId count before and after each mutation in tests; assert count_after == count_before ± 1; also check for duplicate DataIds via a seen-set during full scan.
Telemetry object_count gauge updated at each insert/delete; checked in tests against actual full-scan count.
Recovery No runtime recovery; object loss requires rebuild.
Debug Log condense queue contents before and after reinsert; diff against expected removed DataId; trace the split path to verify both child entry lists sum to M+1 before the split operation.

I8 — Geohash Roundtrip

Field Detail
Statement For any (lat, lng) pair and precision p: decode(encode(lat, lng, p)) returns a Rect containing (lat, lng); encoding at precision p+1 produces a string that is a prefix of the encoding at precision p (longer hashes → smaller cells within the same parent cell).
Why it matters All geohash applications (neighbor lookup, prefix range scan, coordinate proximity grouping) depend on decode correctness and the prefix-containment property.
Where enforced sidx-geohash encode and decode functions; GeoHash.bits and precision fields.
Detection Fuzz: 1 M random (lat, lng, precision) tuples; assert point-in-decoded-rect; assert prefix property for precision 1–12.
Telemetry geohash_contain_violations, geohash_prefix_violations — fuzz-test counters.
Recovery No runtime recovery; codec defect. Verify rounding direction in decode (must round outward to ensure containment).
Debug Print (lat, lng, precision, bits_hex, decoded_rect) for the failing case; check whether the decode rounds the cell boundary inward (causes containment failure) or outward (correct).

I9 — Quadtree Partition

Field Detail
Statement A region quadtree node's four children exactly partition the parent bounds: union(child_bounds[0..4]) == parent.bounds; area(intersect(child_i, child_j)) == 0 for i ≠ j.
Why it matters Partition completeness is required for range query soundness: a point that is not in any quadrant would be unfindable; overlapping quadrants would return duplicate results.
Where enforced sidx-quadtree subdivide function; QuadNode::Internal([NodeId;4]) construction computes four sub-rects from the parent midpoint.
Detection After every subdivision: assert union of four child rects == parent rect (area and MBR equality); assert pairwise intersection area == 0.
Telemetry quadtree_partition_violation_count — test-only.
Recovery No runtime recovery; subdivision formula defect.
Debug Print parent bounds and computed four child bounds; verify midpoint computation: mid_x = (parent.min.x + parent.max.x) / 2.0; check f64 rounding: NW/NE/SW/SE bounds must share the midpoint exactly with no gap.

I10 — Determinism

Field Detail
Statement For a fixed build order (sequential insert) or STR bulk load and dataset, the tree structure (arena layout and MBRs) and all query results are bit-for-bit reproducible across runs on the same hardware.
Why it matters Reproducible benchmarks require determinism; non-deterministic failures are diagnosed only by reproducing the exact tree structure; non-determinism in production results is a correctness risk.
Where enforced sidx-rtree Vec-based arena (deterministic push order); sidx-bulk STR sort (deterministic sort_by with a total order on f64 centers); sidx-quadtree subdivision (deterministic midpoint formula).
Detection Run identical build + 1 K queries twice; serialize both trees to bytes; assert byte equality.
Telemetry N/A — determinism is a build-time property verified in CI.
Recovery If non-determinism detected, audit all HashMap uses (replace with BTreeMap or sorted Vec); audit any floating-point accumulation order (use deterministic sum).
Debug Diff serialized tree bytes from two runs; trace first diverging byte to the node id and field; find the data structure with iteration-order non-determinism (typically HashMap).

I11 — Parent-MBR Containment (Safety Floor, Weaker Than I1)

Field Detail
Statement Every non-leaf node's stored MBR spatially contains — but need not exactly equal — the union of its children's MBRs: contains_rect(node.mbr, union(child.mbr for child in node.children)). This containment must hold at all times, including transient states where I1's tightness (equality) has not yet been re-established.
Why it matters Containment, not tightness, is the minimum floor for search soundness: window_search/intersect_search/ChooseLeaf (P11) rely only on containment to avoid pruning a subtree that holds a true hit. Tightness (I1) is a layered efficiency property; a system can transiently violate I1 (e.g., mid-batch before a deferred AdjustTree pass) and remain fully correct as long as I11 holds.
Where enforced sidx-rtree adjust_tree (post-insert — guarantees containment before returning even if a deferred-tightening path skips full recomputation); split_node (a child-MBR union is a subset of the parent's assigned MBR by construction); condense_tree (post-delete — a node's MBR may be left loose/wider than necessary, but never narrower than the true union).
Detection check_parent_containment(tree) tree-validator walk: for every internal node, assert contains_rect(node.mbr, mbr_union_all(children.mbr)); unlike I1's audit (equality), this asserts only the weaker ⊇ relationship, so it is cheap enough to run continuously in production behind debug_invariants, while I1's equality audit stays test-only.
Telemetry parent_containment_violation_count — a production-safe gauge; any nonzero value is a P0 correctness bug, unlike I1 tightness drift, which is a performance-only signal.
Recovery Rebuild subtree: walk down from the first violating node, discard its stored MBR, and reconstruct the node and all descendants' MBRs bottom-up from leaf data; scoped to the violating subtree, cheaper than I1's typical full-tree rebuild.
Debug Diff node.mbr against mbr_union_all(children.mbr) at the first violating node; because containment (not equality) is being checked, a violation here means an actual excluded point — bisect ChooseLeaf's decision history (Phase 4) to find the mutation that shrank an ancestor MBR without validating containment first.

I12 — Geohash Prefix Monotonicity (String-Lattice Property)

Field Detail
Statement For any two geohash strings s and s' where s' has s as a proper prefix, decode(s') is spatially contained within decode(s): contains_rect(decode(s), decode(s')). This holds for any pair of strings related by the prefix relation — not only for hashes derived from encoding the same (lat, lng) coordinate at different precisions (that narrower, single-point property is I8).
Why it matters Prefix-range scanning (sidx-query's geohash prefilter, P9) enumerates covering cells and prefix ranges purely as strings, with no reference back to an originating coordinate; the prefilter is sound only if the string-level nesting property holds universally across the base32 alphabet, not just along one point's own encode/decode path.
Where enforced sidx-geohash encode/decode bit-interleaving (each additional 5-bit base32 character subdivides the parent cell into 32 children that exactly tile it, by the codec's bisection construction); prefix_range.rs covering_ranges range-merge logic depends on this holding for arbitrary generated prefixes, not only "real" encoded points.
Detection Round-trip property test: generate 1 M random geohash strings s of length k in [1,11] (independent of any specific lat/lng — random base32 characters), extend each with a random further character to form s', decode both, and assert contains_rect(decode(s), decode(s')); distinct from I8's fuzz, which only ever tests strings produced by encode(lat, lng, p) on a real coordinate.
Telemetry geohash_prefix_monotonicity_violation_count — property-test-only, kept separate from I8's geohash_prefix_violations so a regression is attributable to the general lattice property vs. the point-roundtrip property.
Recovery No runtime recovery; a violation is a codec defect in the bit-interleave/bisection construction — audit the base32 alphabet lookup table and the fixed 5-bit-per-character assumption.
Debug Print (s, s', decode(s), decode(s')) for the failing pair; check whether the violation occurs at a base32 alphabet boundary — the geohash alphabet 0-9b-z skips a, i, l, o and is not contiguous, a common source of lattice-property bugs if the lookup table is transcribed incorrectly.

8.3 R-tree State Machine

States apply per RTreeNode; transitions driven by insert/delete operations.

State labels:
  EMPTY    — newly allocated node, 0 entries (root only)
  UNDER    — entries < m (non-root: triggers condense)
  NORMAL   — m <= entries <= M
  OVER     — entries == M+1 (transient; split fires immediately)

Transitions:
  EMPTY  --insert(1st entry)-->  NORMAL  (if root stays leaf with >=1 entry)
  NORMAL --insert--> NORMAL      (while count < M)
  NORMAL --insert--> OVER        (count reaches M+1)
  OVER   --split-->  NORMAL + NORMAL   (two M/2..M nodes; parent gains one entry)
  NORMAL --delete--> UNDER       (count drops below m, non-root)
  UNDER  --condense--> [removed; entries reinserted at root level]
  NORMAL --delete--> EMPTY       (root leaf, all entries removed)
  OVER   (never persists; always resolved within the same operation)

Root special case: root can hold 1 entry when it is a leaf (height 0) and must have >= 2 entries when it is an internal node. If root splits, height increases by 1.

8.4 R*-tree Forced Reinsertion State

Reinsertion fires at most once per level per insert call. Track with a per-call bitmask reinserted: [bool; MAX_HEIGHT].

On overflow at level L:
  if reinserted[L] == false:
    reinserted[L] = true
    remove p farthest-from-center entries from the node
    re-insert those p entries via normal insert (reusing same reinserted mask)
  else:
    perform R* split (no further reinsertion at this level)

p = 30% of M (Beckmann et al. recommendation). Reinsertion reduces overlap across sibling nodes, improving future query fan-out.

8.5 ChooseLeaf / Choose-Subtree Semantics

R-tree ChooseLeaf(rect R, node N):
  if N.level == 0: return N          // leaf
  select child C minimizing enlargement(C.mbr, R)
  tie-break: smallest area
  recurse into C

R*-tree choose-subtree(rect R, target_level L, node N):
  if N.level == L+1:                 // children are at target level
    if L == 0 (children are leaves):
      select C minimizing overlap_enlargement(C.mbr, R, siblings)
      tie-break: area_enlargement, then area
    else:
      select C minimizing area_enlargement(C.mbr, R)
      tie-break: area
  else:
    select C minimizing area_enlargement(C.mbr, R)   // higher levels
  recurse

8.6 Split Algorithm Semantics

8.6.1 Quadratic Split (Guttman 1984)

PickSeeds: for each pair (i,j) of entries, compute d = area(mbr(i,j)) - area(i) - area(j);
           seeds = pair maximizing d (worst waste if placed together)
PickNext:  for each unassigned entry, compute diff = |area_increase_if_in_group1 - area_increase_if_in_group2|;
           assign to group with smaller increase; tie: smaller size, then first group
Terminate: stop when all assigned or one group needs all remaining to meet m

8.6.2 R* Split (Beckmann et al. 1990)

For each axis a in [0..D):
  sort entries by low[a], also by high[a] → 2*D sort orders
  for each order and each split index k in [m..M-m]:
    compute margin(k) = perimeter(mbr(group1)) + perimeter(mbr(group2))
  sum_margin[a] = sum of all margin values for axis a

choose_split_axis = axis minimizing sum_margin
along chosen axis: choose k minimizing overlap(group1,group2); tie: minimizing area

8.7 CondenseTree Algorithm

CondenseTree(leaf node N):
  path = ancestor path from N to root
  Q = empty list of orphan entries
  for each node N' on path bottom-up (excluding root):
    if N'.entries.len() < m:
      remove N' from parent
      Q += N'.entries (with their level tags)
    else:
      adjust parent.entry.mbr to tight union of N'.entries
  reinsert all entries in Q at their respective levels (level-tagged reinsert)
  if root has exactly one entry and is not leaf: collapse root, decrease height

8.8 STR Bulk Load Semantics

Input: n Rect objects with DataIds
Parameters: M (node capacity), m (min occupancy)
S = ceil(sqrt(n / M))    // number of vertical slices

1. Sort all n rects by x-center (or x-min) ascending
2. Partition into S slices of ceil(n/S) rects each
3. Within each slice, sort by y-center (or y-min)
4. Pack consecutive M-sized groups into leaf nodes → leaf level
5. Repeat steps 1-4 on the MBRs of leaf nodes → next level
6. Continue until one root node covers all children

Invariants: all leaves at level 0; every non-root node has between m and M entries; root may have fewer. Expected tree height = ceil(log_M(n)).

8.9 kNN Best-First Algorithm

Input: query point Q, integer k, R-tree root
Structures:
  PQ  = min-heap keyed by MINDIST(Q, node.mbr) or 0 for root
  RES = max-heap (size k) keyed by distance to Q

Algorithm:
  push (0.0, root) into PQ
  while PQ non-empty:
    (d_low, item) = PQ.pop()
    if d_low > RES.peek_max() and |RES| == k: break   // prune
    if item is leaf entry (DataId):
      dist = euclidean(Q, entry.point_or_mbr_centroid)
      if |RES| < k or dist < RES.peek_max():
        RES.push(dist, DataId); if |RES| > k: RES.pop_max()
    else (NodeId):
      for each child entry E in node(item):
        d = MINDIST(Q, E.mbr)
        if |RES| < k or d < RES.peek_max():
          PQ.push(d, E.child)
  return RES as sorted list

MINMAXDIST used for upper-bound pruning: if MINMAXDIST(Q, node.mbr) < current k-th distance, then at least one object in the subtree is definitely closer; conversely if MINDIST > k-th distance, entire subtree pruned.

8.10 MINDIST and MINMAXDIST Formulae (2D; generalize to D)

// Point p = (px, py), Rect R = [rx1,rx2] x [ry1,ry2]

MINDIST(p, R):
  ri_x = if px < rx1 then rx1 elif px > rx2 then rx2 else px
  ri_y = if py < ry1 then ry1 elif py > ry2 then ry2 else py
  return sqrt((px-ri_x)^2 + (py-ri_y)^2)
  // = 0 if p is inside R

MINMAXDIST(p, R):
  // for each axis a: rmk[a] = the endpoint of R on axis a farthest from p
  //                  rmi[a] = the closer endpoint on all OTHER axes to p
  // MINMAXDIST = min over axes a of (dist using rmk[a] on a, rmi on others)
  // Ensures: at least one object in R is at distance <= MINMAXDIST

Invariant I6: MINDIST(p,R) <= dist(p, nearest_object_in_R) <= MINMAXDIST(p,R) always holds.

8.11 Geohash Encoding Model

EBNF (logical bit-interleaving):
  geohash_bits(lat, lng, precision):
    total_bits = 5 * precision
    for i in 0..total_bits:
      if i is even: encode next longitude bit (MSB first in [-180,180])
      if i is odd:  encode next latitude bit  (MSB first in [-90, 90])
    base32_encode(collected_bits, precision)  → string of length precision

base32 alphabet: "0123456789bcdefghjkmnpqrstuvwxyz"  (32 chars; omits a,i,l,o)

Decode: reverse the above → cell Rect [lng1,lng2] x [lat1,lat2]
Cell area ≈ (360/2^(bits/2)) x (180/2^(bits/2)) degrees² for even precision

Neighbor cells: for each of the 8 compass directions, adjust the interleaved bit pattern to select the adjacent cell, handling boundary carry-over at ±180° longitude and ±90° latitude.

Prefix range: all geohash strings with prefix P cover a rectangular region (may be a multi-prefix union for irregular shapes; see Phase 10 for exact prefix computation).

8.12 Quadtree Subdivision Model

QuadNode(bounds = [x1,x2] x [y1,y2]):
  mid_x = (x1+x2)/2
  mid_y = (y1+y2)/2
  quadrant 0 (NW): [x1,mid_x] x [mid_y,y2]
  quadrant 1 (NE): [mid_x,x2] x [mid_y,y2]
  quadrant 2 (SW): [x1,mid_x] x [y1,mid_y]
  quadrant 3 (SE): [mid_x,x2] x [y1,mid_y]

Invariant I9: four children exactly tile the parent with no gap, no overlap. union(Q0,Q1,Q2,Q3) == parent.bounds and intersects(Qi, Qj) == false for i!=j.

Region-point ambiguity at boundary: a point on the split line is assigned to the lower-index quadrant consistently (NW before NE, N before S).

8.13 Unified Query Dispatch Semantics

Query Variant Predicate R-tree pruning rule Quadtree pruning Geohash filter
Window(R) obj.mbr intersects R skip node if node.mbr disjoint R skip quadrant if disjoint compute prefix set covering R; discard non-matching
Intersect(R) obj.mbr intersects R identical to Window identical same prefix set
Contains(R) obj.mbr contains R skip node if node.mbr cannot contain R (node.mbr smaller than R) skip if quadrant cannot contain R prefix of R's cell; refine
Knn(p,k) k nearest by dist MINDIST-based best-first heap (Phase 8) recurse by MINDIST to quadrant decode to rect; nearest cell first
Nearest(p) 1 nearest Knn(p,1) same same

Intersect vs Window: semantically identical for MBR-indexed objects (MBR intersects query rect). Contains differs: filter inverted (object must contain query rect, not merely intersect).

8.14 Persistence / Page Layout

Page format (PAGE_SIZE = 4096 bytes):
  Offset  Size  Field
  0       4     magic: 0x53494458 ("SIDX")
  4       2     format_version: u16
  6       2     node_level: u16  (0=leaf)
  8       2     entry_count: u16
  10      2     flags: u16  (bit0=dirty, bit1=pinned)
  12      4     parent_page_id: u32
  16      4*D*2 per-entry MBR (D=2 → 32 bytes per entry MBR)
  ...     var   child/data IDs (4 bytes NodeId or 8 bytes DataId per entry)
  ...     pad   zero-fill to 4096

Max entries per page at D=2: floor((4096 - 16) / (32 + 8)) = 101; set M=100 by default for clean occupancy.

LRU page cache: capacity in pages configurable; dirty pages written on eviction or explicit flush. Cache hit ratio tracked for observability (P10).

8.15 Worked Example — Insert and Split

Config: M=3, m=1, D=2, SplitStrategy::Quadratic

Initial tree: root (leaf, level=0) with 3 entries:
  E1: mbr=[0,0,2,2], DataId(1)
  E2: mbr=[1,1,3,3], DataId(2)
  E3: mbr=[5,5,7,7], DataId(3)

Insert DataId(4) with mbr=[6,6,8,8]:
  ChooseLeaf → root (only leaf)
  root.entries.len() == 4 > M=3 → overflow → split

PickSeeds (quadratic):
  pairs and waste:
    (E1,E2): area([0,0,3,3])=9  - area(E1)=4 - area(E2)=4 = 1
    (E1,E3): area([0,0,7,7])=49 - 4 - 4 = 41
    (E1,E4): area([0,0,8,8])=64 - 4 - 4 = 56   ← seeds: E1 and E4
    (E2,E3): area([1,1,7,7])=36 - 4 - 4 = 28
    (E2,E4): area([1,1,8,8])=49 - 4 - 4 = 41
    (E3,E4): area([5,5,8,8])=9  - 4 - 4 = 1

Seeds: E1 → Group1, E4 → Group2

Distribute E2: enlargement to G1 = area([0,0,3,3])-4 = 5; to G2 = area([1,1,8,8])-4=41; → G1
Distribute E3: enlargement to G1 = area([0,0,3,3] union [5,5,7,7])-9=40; to G2 = area([5,5,8,8])-4=5; → G2

Result:
  Node A (leaf): [E1(mbr=[0,0,2,2]), E2(mbr=[1,1,3,3])]; node.mbr=[0,0,3,3]
  Node B (leaf): [E4(mbr=[6,6,8,8]), E3(mbr=[5,5,7,7])]; node.mbr=[5,5,8,8]

New root (internal, level=1):
  Entry(mbr=[0,0,3,3], child=NodeA)
  Entry(mbr=[5,5,8,8], child=NodeB)

Verify I1: root.mbr = union([0,0,3,3],[5,5,8,8]) = [0,0,8,8] ✓
Verify I2: both leaves at level 0 ✓
Verify I3: both nodes have 2 entries, m=1<=2<=M=3 ✓
Verify I7: DataIds {1,2,3,4} all present, none duplicated ✓

8.16 Failure-Path Example — MBR Violation (Malformed Input)

Attempted insert: rect = [5,3,2,8] (min[0]=5 > max[0]=2 — axis-0 inverted)
Expected behavior: sidx-geom::Rect::new() returns Err(MalformedRect)
  or normalizes to [2,3,5,8] with a debug warning

If normalization is silently wrong and [5,3,2,8] is stored:
  I1 violated: any query with rect [3,4,4,6] should match the object,
  but MINDIST computed against [5,3,2,8] is undefined / garbage
  → false negative in window search
  → oracle mismatch detected by sidx-oracle differential test (Phase 14)

Enforcement: Rect::new(min,max) asserts min[i]<=max[i] for all i; panic or Result::Err in debug; normalize in release with metric counter increment.

8.17 Edge Cases

Edge Case Expected Behavior
Point objects (zero-area MBR) min == max; valid degenerate rect; MBR union with siblings works normally
Duplicate points in quadtree all placed in same leaf; leaf may exceed capacity; depth-bounded split degenerates to list at MAX_DEPTH
Query rect fully inside one node single path descent; no fan-out
Query rect spanning entire space every node visited; result = all objects
k > total object count return all objects, sorted by distance
Empty tree kNN return empty Vec
Geohash at ±90° latitude boundary bit pattern saturates; neighbor computation clamps and wraps
Geohash at ±180° longitude boundary neighbor wraps around; prefix range spans two string ranges
Delete non-existent DataId return NotFound; tree unchanged; no invariant violation
STR bulk load n=0 return empty tree (height=0, root is empty leaf)
STR bulk load n=1 single leaf with one entry; root is leaf
Root with single internal child collapse: that child becomes new root; height--
f64 NaN in coords rejected at Rect::new; sidx-core returns Err(NonFiniteCoord)

8.18 Memory / Ownership Model

Arena ownership (sidx-rtree, sidx-quadtree):
  Vec<RTreeNode<D>> arena owns all nodes; NodeId indexes into it
  No raw pointers; no reference cycles possible
  Insert/delete may reallocate arena Vec → all NodeIds remain stable
    (arena uses push/swap-remove; NodeId remapping table required for delete)

Alternatively: slab crate for stable-index arena (preferred; see ADR-09)

Query result lifetime:
  search returns Vec<DataId>; caller owns; no borrow into arena

Page cache (sidx-persist):
  Arc<Mutex<PageCache>> shared between read and write paths
  Dirty bit per page; flush-on-eviction
  No unsafe; Box<[u8; PAGE_SIZE]> per page

STR bulk load:
  Builds a temporary Vec<Rect> of all inputs in memory;
  final arena handed off to RTree struct; temp Vec dropped

Phase 1 — Core Geometry: Point, Rect, Distances

1.1 Objectives

  • Define Point<const D: usize> and Rect as the canonical coordinate types used by every downstream crate.
  • Implement Euclidean distance, MINDIST(point, rect), and MINMAXDIST(point, rect) meeting the kNN pruning contract (I6).
  • Enforce min[i] <= max[i] on every axis as a structural invariant (P8).
  • Provide property-based test harness confirming non-negativity and MINDIST <= MINMAXDIST for all inputs.

1.2 Detailed Implementation Steps

Module layout (sidx-core/src/)

rect.rs         — Rect (= MBR), constructor + normalisation, well-formedness check

Point<const D: usize>: coords: [f64; D]; PartialEq by bitwise equality (to_bits); Copy; default D=2.

Rect: { min: Point<D>, max: Point<D> }; constructor normalises so min[i] = f64::min(a[i],b[i]), max[i] = f64::max(a[i],b[i]); is_valid() checks min[i] <= max[i] for all i; degenerate (point or line) rects are valid (zero-area).

minmaxdist(p: &Point<D>, r: &Rect<D>) -> f64: per-axis "nearest far face" formula; for each axis k, pick the nearer face on k and the far face on all other axes; take the minimum over all k; guarantees an object is within this distance of p. Formula per Roussopoulos 1995 Section 2.

1.6 Pitfalls

  • NaN propagation: a single NaN coordinate causes all distance comparisons to fail silently; validate on construction, return SidxError::MalformedRect rather than propagating NaN.

Phase 2 — MBR Operations

2.1 Objectives

  • Implement the complete MBR algebra in sidx-geom that all tree operations build on (P2, P8).
  • Operations: union, intersection, intersects, area/volume, enlargement, overlap_area, contains_rect, contains_point.
  • All functions are pure, allocation-free, and operate on Rect<D> from sidx-core.
  • Establish the semantic distinction: enlargement = additional area to include a rect (drives ChooseLeaf, Phase 4); overlap_area = area of intersection of two rects (drives R*-tree split, Phase 6).
  • Scope: sidx-geom only; no tree state.

2.2 Detailed Implementation Steps

Module layout (sidx-geom/src/)

lib.rs         — re-exports all public fns
union.rs       — mbr_union(a: &Rect, b: &Rect) -> Rect
intersect.rs   — mbr_intersection(a,b) -> Option<Rect>; intersects(a,b) -> bool
area.rs        — area(r: &Rect) -> f64; volume = same fn for D>2
enlarge.rs     — enlargement(base: &Rect, candidate: &Rect) -> f64
overlap.rs     — overlap_area(a: &Rect, b: &Rect) -> f64
contains.rs    — contains_rect(outer,inner) -> bool; contains_point(r,p) -> bool

mbr_union: per-axis min = f64::min(a.min[i], b.min[i]), max = f64::max(a.max[i], b.max[i]); result always valid; associative, commutative (property tests).

mbr_intersection: per-axis lo = f64::max(a.min[i], b.min[i]), hi = f64::min(a.max[i], b.max[i]); return None if any lo > hi; otherwise Some(Rect{min:lo, max:hi}).

intersects: equivalent to mbr_intersection().is_some(); implement directly to avoid constructing the rect when not needed.

area: product of per-axis extents max[i] - min[i]; returns 0 for degenerate rects; f64.

enlargement(base, candidate): area(mbr_union(base, candidate)) - area(base); non-negative by construction (union never shrinks).

overlap_area(a, b): area(mbr_intersection(a,b)) or 0 if non-intersecting; used by R*-tree split axis/distribution selection.

contains_rect(outer, inner): outer.min[i] <= inner.min[i] && inner.max[i] <= outer.max[i] for all i.

contains_point(r, p): r.min[i] <= p.coords[i] <= r.max[i] for all i (inclusive boundary).

Property tests (proptest): union idempotent (union(a,a)==a); union associative/commutative; area(union) >= area(a), area(b); enlargement >= 0; intersects symmetric; contains_rect transitive; overlap_area <= min(area(a), area(b)).

Trait implementations: PartialEq, Clone, Copy for Rect inherited from sidx-core; all geom fns are free functions (no methods on Rect to keep sidx-core clean). Anchors: P2, P8 (mbr_union/enlargement/contains_rect are the mechanical basis of MBR tightness and geometric well-formedness); a defective mbr_union is an I1 violation and, more fundamentally, an I11/P11 (MBR Conservatism) violation if the union ever fails to contain both inputs.

Phase 4 — R-tree insertion + split

4.1 Objectives

  • Implement sidx-rtree insert path: ChooseLeaf → insert at leaf → overflow split → MBR propagation.
  • Support both SplitStrategy::Quadratic and SplitStrategy::Linear pick-seeds algorithms.
  • Maintain I1 (MBR containment), I2 (balance), I3 (occupancy) after every insert.
  • Expose insert(rect: Rect, id: DataId) -> Result<(), SidxError> on RTree.

4.2 Detailed Implementation Steps

Module: sidx-rtree/src/insert.rs, sidx-rtree/src/split.rs

ChooseLeaf (choose_leaf):

  • Traverse from root to leaf level (level == 0).
  • At each internal node: select entry whose MBR requires least area enlargement to contain rect.
  • Tie-break: least current area. Tie-tie-break: lowest NodeId for determinism (supports I10).
  • Return path as Vec<NodeId> (ancestor stack for upward propagation).

Insert at leaf:

  • Push Entry { mbr: rect, payload: Data(id) } into chosen leaf node.
  • If len <= M: only MBR adjustment needed; propagate upward and stop.
  • If len == M + 1: invoke split.

Split algorithms (split.rs):

Algorithm Pick-Seeds Distribute
Quadratic pick pair with max waste = area(union) - area(a) - area(b) assign each remaining entry to group requiring least enlargement; tie: smaller group, tie: fewer entries
Linear pick pair with max normalized separation per axis, best axis wins same distribute loop
  • split_node(node: &mut RTreeNode, strategy: SplitStrategy) -> (RTreeNode, RTreeNode): returns two nodes each with m <= len <= M.
  • Minimum group size m enforced: if one group would drop below m, force assign all remaining entries.

Propagation (propagate_split):

  • Walk ancestor stack upward.
  • Update parent entry's MBR to union of all children.
  • If split produced a sibling, insert new entry into parent; recurse split if parent overflows.
  • Root split: create new root at level = old_root.level + 1; set two children; height increases by 1.

Arena management:

  • All nodes live in NodeArena: Vec<RTreeNode> indexed by NodeId(u32).
  • Free-list for deleted slots (Phase 5); in Phase 4, arena only grows.
  • root: NodeId field on RTree; updated on root split.

Observability:

  • Counter: splits_total, inserts_total, height gauge — exposed via RTreeStats.
  • Debug-mode: log chosen leaf path and split seed indices at TRACE level. Anchors: I10 (NodeId tie-break determinism), P12 (Deterministic Split & Bulk-Load Ordering — the same tie-break chain, plus PickSeeds/Distribute tie rules, is P12's concrete mechanism); P11/I11 (ChooseLeaf's least-enlargement comparison is only correct if compared child MBRs are conservative — see Phase 3's search-time discussion of the same floor).

Phase 5 — R-tree deletion + condense

5.1 Objectives

  • Implement RTree::delete(id: DataId, rect: Rect) -> Result<bool, SidxError> in sidx-rtree.
  • FindLeaf: recursive descent visiting only nodes whose MBR contains rect; locate exact leaf entry.
  • CondenseTree: collect under-full nodes, reinsert orphaned entries, shrink MBRs upward.
  • Collapse root with a single child: reduce height, maintain I2, I3.
  • Maintain I1 (MBR containment) and I7 (no loss/duplication of entries).

5.2 Detailed Implementation Steps

Module: sidx-rtree/src/delete.rs

  • FindLeaf (find_leaf): from root, recurse into children whose MBR contains rect (not just intersects); at leaf level scan entries for payload == Data(id) AND mbr == rect; returns Option<(NodeId, usize)> (node + entry index), None if not found. Containment pruning (not intersection) reduces search space.
  • Delete entry: swap-remove entry at found index from leaf node. If leaf.entries.len() >= m OR leaf is root: no under-full condition, proceed to MBR shrink only.
  • CondenseTree (condense_tree):
Q ← empty reinsert queue
walk from leaf upward to root via ancestor stack:
  if node.entries.len() < m AND node != root:
    remove node from parent.entries
    push all node.entries to Q
    return arena slot to free-list
  else:
    update node MBR = union of all children MBRs
for each entry e in Q:
  reinsert e at correct level (e.level for internal nodes, leaf level for data entries)

Reinsert preserves level (internal orphans re-enter at their original level, not leaf level) by calling standard insert with a level hint, avoiding re-splitting at the wrong level.

  • Root collapse: after CondenseTree, if root is not a leaf AND root.entries.len() == 1, promote the single child as new root, decrement height, release old root arena slot; repeat until root has ≥2 entries or is a leaf.
  • Arena free-list: free_slots: Vec<NodeId> in NodeArena; deleted nodes pushed here; new nodes pop from free-list before appending.
  • MBR shrink propagation: after removing an entry, walk upward and recompute each ancestor's MBR as the tight union of its remaining entries.
  • Observability: counters deletes_total, condense_reinserts, root_collapses, nodes_freed. Anchors: I7 (Split/Merge Object Conservation — the reinsert queue Q must fully drain before condense_tree returns), I2 (Height Balance — reinsertion preserves each orphan's original level), I11 (Parent-MBR Containment — MBR shrink propagation after removal must still satisfy containment; I11 explicitly lists post-condense as one of its enforcement points).

Phase 6 — R*-tree improvements

6.1 Objectives

  • Implement sidx-rstar crate as a superset of sidx-rtree: replace ChooseLeaf, split, and overflow handling.
  • choose-subtree: at leaf level minimize overlap enlargement; above leaf level minimize area enlargement.
  • R* split: axis-selection by minimum margin-sum; distribution by minimum overlap (tie: minimum area).
  • Forced reinsertion: on first overflow at a given level, reinsert p entries instead of splitting; maintain invariants I1–I3, I7, I10 while delivering measurable P4 improvement (overlap/coverage).

6.2 Detailed Implementation Steps

Module: sidx-rstar/src/choose_subtree.rs, sidx-rstar/src/split.rs, sidx-rstar/src/reinsert.rs choose-subtree (choose_subtree):

if current level == leaf level - 1 (choosing which leaf subtree):
  candidates = all child entries
  pick entry minimizing overlap enlargement if rect added
  tie: minimize area enlargement; tie: minimize current area
else (internal level above leaf):
  pick entry minimizing area enlargement (identical to ChooseLeaf)
  tie: least area
  • Overlap enlargement for entry e: sum over all other entries f: overlap(union(e.mbr, rect), f.mbr) - overlap(e.mbr, f.mbr); cost O(M²) per internal node at leaf-parent level, acceptable for M <= 128.

R split* (rstar_split):

for each axis a in {x, y, ...}:
  sort entries by lower-bound on axis a; compute all M-2m+2 distributions; sum margins → S_a
  sort entries by upper-bound on axis a; compute all distributions; sum margins → S_a_upper
  axis_margin[a] = S_a + S_a_upper
choose split axis = argmin(axis_margin)
among all distributions on chosen axis:
  choose distribution minimizing overlap; tie: minimize combined area
split into two groups at chosen distribution
  • SplitStrategy::RStar dispatches to rstar_split (Quadratic/Linear remain in sidx-rtree); distributions count = M - 2m + 2 per sort order, total axis evaluations = 2 * D * (M - 2m + 2).

Forced reinsertion (forced_reinsert):

  • Per-insert, maintain reinserted_levels: BTreeSet<u16> tracking which levels have already triggered reinsertion in this insert call.
  • On first overflow at level L (not in reinserted_levels): sort node's M+1 entries by distance from node-center (farthest first); remove p = floor(0.3 * (M+1)) entries (~30% of M+1).
  • Adjust MBR of now-smaller node upward; mark level L in reinserted_levels; reinsert each removed entry via the standard insert path (may trigger further events).
  • On second overflow at same level L (already in reinserted_levels): perform split instead. reinserted_levels lives only for the duration of one top-level insert call (thread-local or passed as mutable state).

RStarTree struct (sidx-rstar/src/lib.rs): wraps NodeArena (shared logic from sidx-rtree) + RStarConfig { m, M, p_frac: f32 }; SplitStrategy fixed to RStar (choose-subtree dispatches internally); exposes same insert, delete, search API as RTree for use in sidx-query.

Observability: counters reinsertions_total, rstar_splits_total, overlap_sum_after_build (computed on demand). Anchors: P4 (Minimize Overlap and Coverage — axis/distribution selection is P4's concrete implementation), P-R2 (Beckmann, Kriegel, Schneider, Seeger, "The R*-Tree," SIGMOD 1990 — choose_subtree, rstar_split, and forced_reinsert are this paper's algorithms), P12 (Deterministic Split & Bulk-Load Ordering — axis/distribution/margin ties and the reinserted_levels bookkeeping must resolve via a total order for R*-tree builds to stay reproducible).

7.2 Detailed Implementation Steps

sidx-bulk/src/lib.rs — public entry point:

pub fn str_bulk_load(
    items: Vec<(Rect, DataId)>,
    m: usize,
    M: usize,
) -> (Arena<RTreeNode>, NodeId);  // returns arena + root NodeId

Algorithm (STR, 2-D default; D-dimensional generalization straightforward):

Step Action
1 n = items.len(); if n == 0 return empty root leaf.
2 S = ceil(sqrt(n as f64 / M as f64)) — slice count (number of vertical strips).
3 Sort all items by x-center of their MBR ((min.x + max.x) / 2.0).
4 Partition into S slices of S * M items each (last slice may be smaller).
5 Within each slice, sort by y-center.
6 Pack into leaf nodes of M entries each (last leaf in each slice may be smaller but >= m unless total < m).
7 If leaf count == 1, that is the root; done.
8 Compute MBR of each leaf node; recurse: call str_pack_level(leaf_mbrs_with_nodeids, m, M) to produce internal nodes bottom-up.
9 Continue until a single root node remains; assign level field as height from leaves.

sidx-bulk/src/str_pack.rs — internal recursive packer: fn pack_level(nodes: Vec<(Rect, NodeId)>, m: usize, M: usize, level: u16) -> Vec<(Rect, NodeId)> creates Entry { mbr, payload: Child(NodeId) } records and packs into RTreeNode { level, entries }; MBR of each new node = sidx-geom::union_all(entries.iter().map(|e| &e.mbr)).

sidx-bulk/src/validate.rs — post-build checker: verifies I1 (tight MBR), I2 (all leaves at level 0), I3 (occupancy m..=M for non-root); returns BulkLoadError::OccupancyViolation { node_id, found, min, max }.

8.2 Detailed Implementation Steps

sidx-knn/src/lib.rs — primary function:

pub fn knn_search(
    tree: &RTree,
    query: Point,
    k: usize,
    metric: DistanceMetric,
) -> Vec<KnnItem>;

Data structures:

  • MinHeap<(OrderedFloat<f64>, QueueEntry)> — priority queue (BinaryHeap in min-mode).
  • QueueEntry — enum { Node(NodeId, Rect), Leaf(DataId, Rect) }; MaxHeap<KnnItem> (size k) is the current best results, k-th distance = heap.peek().dist.

Algorithm (Roussopoulos et al. 1995 + Hjaltason & Samet 1999 incremental variant):

Step Detail
1 Push (MINDIST(query, root.mbr), Node(root_id, root.mbr)) onto min-heap.
2 Pop entry (d, e) from min-heap.
3 If result heap size == k and d >= k_th_dist: break (all remaining entries farther).
4 If e is a Node: expand — push all children as (MINDIST(query, child.mbr), child).
5 If e is a Leaf: compute euclidean(query, centroid_or_stored_point); insert into result heap if dist < k_th_dist or result size < k; evict farthest if size > k.
6 Before pushing a child node, prune if MINDIST(query, child.mbr) >= k_th_dist (I6).
7 Apply MINMAXDIST pruning: if any child has MINMAXDIST(query, child.mbr) < MINDIST(query, sibling.mbr), the sibling subtree can be pruned.
8 Repeat from step 2 until heap empty.

9.2 Detailed Implementation Steps

sidx-quadtree/src/lib.rs — public API:

pub struct QuadTree { arena: Arena<QuadNode>, root: NodeId, max_depth: u8, leaf_cap: usize }
pub fn new(bounds: Rect, max_depth: u8, leaf_cap: usize) -> QuadTree;
pub fn insert(&mut self, pt: Point, id: DataId) -> Result<(), QuadError>;
pub fn point_query(&self, pt: &Point) -> Vec<DataId>;
pub fn range_query(&self, query: &Rect) -> Vec<DataId>;

sidx-quadtree/src/node.rs — QuadNode: kind: Leaf(Vec<(Point, DataId)>) holds up to leaf_cap entries; kind: Internal([NodeId; 4]) — children in order [NW, NE, SW, SE]; bounds: Rect — exact quadrant rectangle.

Subdivision (I9):

Child x range y range
NW (0) [min.x, mid.x] [mid.y, max.y]
NE (1) [mid.x, max.x] [mid.y, max.y]
SW (2) [min.x, mid.x] [min.y, mid.y]
SE (3) [mid.x, max.x] [min.y, mid.y]

Where mid = (bounds.min + bounds.max) / 2.0 per axis.

Insert algorithm:

  1. Traverse from root; at each internal node, determine child quadrant containing pt, descend; at leaf, if entries.len() < leaf_cap OR depth >= max_depth: append (pt, id).
  2. If entries.len() == leaf_cap AND depth < max_depth: subdivide — create 4 child QuadNode leaves, redistribute existing entries + new entry; colocated points (all same coord) all land in same quadrant — depth bound prevents infinite split, accumulating in the leaf at max depth.

Point/range query: point query descends the matching child quadrant, then at the leaf does a linear scan for exact pt == stored_pt; range query recurses at internal nodes into all children whose bounds overlaps query, and at leaves collects entries where query.contains(pt) or query.intersects_point(pt).

sidx-quadtree/src/region.rs — PR quadtree variant: inserts (Rect, DataId) instead of (Point, DataId); a rect is inserted into all quadrant children whose bounds overlap it (multi-path insert); range query collects all rects overlapping query rect, deduplicated by DataId.

sidx-quadtree/src/error.rs — QuadError: OutOfBounds { pt: Point, tree_bounds: Rect } — point outside root bounds; NaNCoordinate — input validation failure.

Phase 10 — Geohash

10.1 Objectives

  • Implement sidx-geohash crate: encode (lat, lng) → GeoHash (bits + precision) → base32 string.
  • Decode GeoHash → bounding Rect (cell bounds).
  • Enumerate 8 neighbor cells (N, NE, E, SE, S, SW, W, NW) with correct boundary carry logic.
  • Produce prefix-range pairs (lo, hi) for a given bounding Rect, enabling index range scans.
  • Satisfy I8 (roundtrip: decoded cell contains original point), I10 (determinism).

10.2 Detailed Implementation Steps

sidx-geohash/src/codec.rs

  • Bit-interleave algorithm: alternate longitude bits (even positions) and latitude bits (odd positions); 5 bits per base32 char; 60 bits max (precision 12).
  • encode(lat: f64, lng: f64, precision: u8) -> GeoHash — validate ±90/±180 bounds, iteratively bisect longitude/latitude ranges, accumulate bits.
  • decode(h: GeoHash) -> Rect — reverse bisection; min/max lat/lng from bit positions → Rect { min: Point([lat_min, lng_min]), max: Point([lat_max, lng_max]) }.
  • Base32 alphabet: 0-9b-z (Geohash standard, 32 chars); encode/decode lookup tables as [u8; 128].

sidx-geohash/src/neighbor.rs

  • Neighbor table approach: for each precision level, precompute even/odd base32 neighbor tables (4 directional per parity) from Niemeyer's original lookup tables.
  • neighbors(h: GeoHash) -> [GeoHash; 8] — compute N/S first (latitude), then E/W (longitude), then diagonals from those; handle wrap at 180° longitude.
  • Border carry: when moving N at latitude +90° or S at −90°, result is same cell (pole handling); document as documented degenerate case.

sidx-geohash/src/prefix_range.rs

  • covering_ranges(bounds: Rect, precision: u8) -> Vec<(String, String)> — expand GeoHash cells covering the bounding box at given precision; merge contiguous ranges; return (lo, hi) pairs for range-scan prefiltering.
  • Cell enumeration via BFS from the southwest corner cell; stop when all cells inside bounds are visited; limit max cells to avoid combinatorial explosion (configurable, default 256).

sidx-geohash/src/lib.rs — re-exports; GeoHash, encode, decode, neighbors, covering_ranges.

sidx-oracle integration — oracle linear scan against decoded cell sets for Phase 14 differential tests. Anchors: I8 (Geohash Roundtrip — single-point encode/decode fidelity and same-path prefix nesting), I12 (Geohash Prefix Monotonicity — the stronger, point-independent guarantee that covering_ranges in prefix_range.rs depends on: any string s' with s as a prefix decodes to a rect contained in decode(s), regardless of whether s/s' came from the same original coordinate).

12.1 Objectives

12.2 Detailed Implementation Steps

Page layout (sidx-persist/src/page.rs)

Page (fixed size, default 4096 bytes):
  [0..4]   magic: u32 = 0x5349_4458 ("SIDX")
  [4..6]   version: u16
  [6..8]   node_level: u16
  [8..12]  entry_count: u32
  [12..16] flags: u32 (leaf | dirty | overflow)
  [16..N]  entries: [Entry; M] (each: mbr min_x min_y max_x max_y f64×4 + payload u64)
  [N..4096] padding: 0x00
  • PageId(u32) maps to NodeId(u32) one-to-one; Page::serialize(node: &RTreeNode) -> [u8; PAGE_SIZE] (signature only); Page::deserialize(bytes: &[u8; PAGE_SIZE]) -> Result<RTreeNode> validates magic + version.

Page file (sidx-persist/src/pager.rs)

  • Pager { file: File, page_size: usize, capacity: u64 }; read_page(id: PageId) -> Result<[u8; PAGE_SIZE]> via pread at offset id * PAGE_SIZE; write_page(id: PageId, bytes: &[u8; PAGE_SIZE]) -> Result<()> via pwrite (O_DSYNC optional).
  • Append-only growth: new pages appended, no in-place overwrite except for dirty flush; file header (page 0) holds version, root page ID, node count, tree height, page count.

LRU cache (sidx-persist/src/cache.rs)

  • LruPageCache { capacity: usize, map: HashMap<PageId, CacheEntry>, lru: LinkedList<PageId> }; get(id: PageId) -> Option<&RTreeNode> is O(1) hit; put(id: PageId, node: RTreeNode) evicts LRU dirty page on capacity overflow and writes to pager.
  • flush_all() writes all dirty pages in PageId order (sequential I/O); cache capacity configurable, default (available_memory / PAGE_SIZE) / 2.

Durable rebuild (sidx-persist/src/rebuild.rs)

  • rebuild_index(path: &Path) -> Result<AnyIndex> opens the file, reads header (page 0), DFS from root PageId, deserializes all nodes into arena, returns RTreeIndex; integrity check recomputes MBR union of each node's children and compares to stored MBR (I1); version mismatch yields Err(IncompatibleVersion { found, expected }).

  • Page size 4096 = OS page; aligns with filesystem block; avoids read-modify-write.
  • Rebuild: DFS issues reads in tree order; BFS may be better for spinning disk (sequential layout from STR bulk load).
  • f64 serialization: to_le_bytes compiles to a move on x86; no overhead.
  • Cache warm-up: pre-read root + first two levels on index open (usually < 100 pages).

12.8 Edge Cases

  • Empty tree (root is leaf, 0 entries): page 0 header + 1 leaf page; rebuild → valid empty index.
  • Single-entry root: legal (root exempt from occupancy); serialize/deserialize faithfully.
  • Overflow page: entry count > M in a page due to version drift; detect by entry_count > MAX_M; reject with Err(OverflowPage).
  • File opened read-only: rebuild_index succeeds; writes rejected with Err(ReadOnly).
  • Index file on networked FS (NFS): O_DSYNC insufficient; document as unsupported; test only on local FS.
  • PageId wraps at u32::MAX (>4 billion pages): guard + Err(IndexFull).
  • Partial fsync failure: mark affected pages dirty; retry on next flush.

  • Conformance on Contains with query rect equal to an object's MBR: that object must appear in both oracle and tree results.

Incident Response

  1. Correctness incident (oracle mismatch metric non-zero in production):

    • Immediately gate new inserts; serve reads from oracle (brute-force fallback) if latency allows.
    • Capture: failing query params, dataset snapshot, tree dump (sidx-cli dump).
    • Root-cause via Phase 14 differential test with captured seed.
    • Fix, add regression test, rebuild index, restore writes.

  2. Disk corruption incident (CRC errors on startup):

    • Refuse to serve; log corrupt PageIds.
    • Restore from last known-good snapshot.
    • If no snapshot: rebuild from source data using bulk load.

  3. Latency regression (P99 > threshold):

    • Capture node_visits_total and pruned_subtrees_total ratios.
    • Check tree height and occupancy; if degraded, trigger rebuild.
    • Profile with cargo flamegraph; compare against pre-regression flamegraph baseline.

Backup and Restore Strategy

  • sidx-persist index files are self-contained; backup = file copy.
  • Recommended: periodic snapshot (copy-on-write or rsync) after bulk-load or after N inserts.
  • Snapshot naming: <index-name>.<timestamp>.sidx — timestamp in Unix seconds.
  • Restore: atomic rename of snapshot to live path; avoids partial-file reads.
  • For memory-only indexes (no sidx-persist): re-run bulk load from source data; no incremental WAL in Phase 12 scope.

Deployment Topology

  • Library crate: linked directly into the consuming application process; no network boundary.
  • CLI (sidx-cli): single binary, no daemon; suitable for batch pipelines.
  • Embedded in-process: index lives in the caller's heap; isolation is the caller's responsibility.
  • No distributed mode in scope; sharding is the caller's responsibility (shard by geohash prefix or MBR partition).

Canary, Rolling-Upgrade, Rollback

  • Library upgrades: semver-gated (see Compatibility section); callers pin to a semver range in Cargo.toml.
  • Index file format upgrades: format version byte in page header; new library reads old format (migration path); old library rejects new format version gracefully (Err(UnsupportedPageVersion)).
  • Canary: for CLI pipelines, run new binary against a shadow copy of the index; compare query results to old binary before promoting.
  • Rollback: revert Cargo.toml pin; rebuild if index format changed; restore snapshot if data mutated.
  • Migration: sidx-cli migrate --from-version N --to-version M --input old.sidx --output new.sidx; verify before swap.

Compatibility Guarantees

Semantic Versioning Policy

crate version: MAJOR.MINOR.PATCH

PATCH: bug fix only; no API/ABI/format change; query results may change if a bug was producing wrong answers.
MINOR: additive API additions (new Query variants, new SplitStrategy), new optional config fields; backward-compatible.
MAJOR: breaking API change (type rename, removed method, format version bump requiring migration).
  • All sidx-* crates share a version lockstep (workspace version in Cargo.toml).
  • Public API surface = types and functions re-exported from the crate root (pub use); internal modules are pub(crate) only.

Type Evolution Rules

  • Point<D>: dimension D is a const generic; index files record D in the header; loading a D=3 file with a D=2 binary returns Err(DimensionMismatch).
  • Entry: adding a new Child variant in future requires MAJOR bump and migration.
  • Query enum: adding a new variant is MINOR; all existing dispatch arms are unaffected; callers using exhaustive match will get a compile error (intentional breakage warning in changelog).
  • NodeId remains u32 in v1.x; widening to u64 is a MAJOR change (changes on-disk node size).

Deprecation Policy

  • Deprecated items marked #[deprecated(since = "X.Y.Z", note = "...")].
  • Deprecated items remain for at least one MAJOR cycle (e.g., deprecated in 1.x, removed in 2.0).
  • Deprecation notice published in CHANGELOG.md with migration path.
  • CLI deprecated flags emit a [WARN] deprecated flag log line; removed in next MAJOR.

Rolling-Upgrade Guarantees

  • In-process library upgrades: no rolling upgrade needed (linked statically).
  • For pipelines with a writer process (insert) and reader process (query) sharing a sidx-persist index file:
    • Both processes must be on the same page_format_version; upgrading one before the other is safe only if the new version can read the old format.
    • Procedure: upgrade reader first (reads old format), then upgrade writer (writes new format), then migrate file if format changed.
    • Never upgrade writer before reader when a format version bump is involved.

Differential Testing — Oracle Harness (sidx-oracle)

  • sidx-oracle: linear scan over flat Vec<(DataId, Rect)>; reference implementations of window, intersect, contains, kNN.
  • Differential loop: for each random dataset size N in {100, 1 000, 10 000, 100 000}: generate N rects, build R-tree and R*-tree; generate 500 random Query values; compare index results to oracle results set-wise (DataId sets).
  • Invariants checked per run: I1 (MBR tight union after every insert), I2 (all leaves at same level), I3 (occupancy bounds), I4 (window soundness/completeness), I5 (kNN exactness), I7 (object count preserved across insert+delete).
  • False-negative gate: any result present in oracle but absent from index → fatal test failure (MBR conservatism violation, P2).
  • False-positive gate: any result present in index but absent from oracle → fatal (incorrect predicate evaluation).
  • CI enforces differential tests on every push; no merge if any scenario fails.

Horizontal / Vertical Scaling

  • In-scope (single-process, single-node): vertical scaling via STR parallelism (rayon feature flag for sort step) and larger page cache.
  • Out-of-scope for v1: distributed sharding, multi-writer concurrency, MVCC.
  • Sharding note (design only): natural partition = geohash prefix at precision P; each shard owns a prefix range; sidx-query's prefix-range API (Phase 11) supports this pattern without code changes to the index itself.
  • Concurrency model: single-writer / multiple-reader via RwLock<Arena> in sidx-rtree; write lock held only during node split propagation (bounded by height, O(log N) duration).
  • Coordination overhead: none in single-node; lock contention negligible below 8 concurrent readers at N=1M (benchmark target: >=4M read-query ops/s with 8 threads).

  • Nightly CI runs bench_scaling: insert N in {10K, 100K, 1M, 10M} and record throughput + latency.

  • Memory growth tracked: RSS at N=10M must not exceed 700 MB (arena + page cache within configured limits).

Mental Models & First Principles

  • MM1 — A node is a page; fanout is the byte budget. An R-tree node maps to one disk page, so M = floor((page_bytes − header) / entry_bytes). Predicts: changing page size changes M, which changes height, which changes I/O per query. Bug without it: picking M independently of page size → partial-page reads and wasted cache. Applied: §4, ADR-11, Phase 12.
  • MM2 — An MBR is a conservative, lossy summary that can only over-approximate. A parent MBR must cover all descendants, so a search can yield false positives but never false negatives. Predicts: correctness depends solely on the covering property, not on tightness. Bug without it: over-tightening an MBR so it excludes a child → silently missed results. Applied: I7, P2, Phase 3.
  • MM3 — Query cost is nodes-overlapping-the-query, not results-returned. Two trees with identical contents but different overlap do different amounts of work. Predicts: overlap is the enemy; R* pays at insert time to shrink it. Bug without it: optimizing occupancy while ignoring overlap → fast build, slow queries. Applied: P4, Phase 6.
  • MM4 — Best-first kNN with a MINDIST-keyed min-heap visits the provably minimum node set. MINDIST is a lower bound, exact distance an upper bound; the heap interleaves both. Predicts: no correct algorithm visits fewer nodes. Bug without it: depth-first or a wrong heap key → extra subtree visits or wrong neighbors. Applied: Phase 8, P-R5.
  • MM5 — A split is a redistribution that must rebalance upward. Overflow splits a node and propagates the new entry to the parent, possibly cascading to the root and growing height by one. Predicts: split is never local. Bug without it: splitting a leaf without AdjustTree → unbalanced tree, broken I2. Applied: I2, Phase 4.
  • MM6 — Bulk loading is sorting, not inserting. STR imposes a space-filling sort order so leaves are spatially compact and ~95% full in a single pass. Predicts: static data should never be built by repeated Insert. Bug without it: building a 10M static index one entry at a time → low occupancy and slow build. Applied: Phase 7, P-R4.
  • MM7 — A geohash is a space-filling code: a string prefix is a bounding box. Proximity reduces to a prefix scan on any ordered store, but adjacent cells can differ in prefix. Predicts: you need explicit neighbor logic at cell boundaries. Bug without it: assuming prefix-proximity is exact → missed results straddling a cell edge. Applied: Phase 10, P-R9.
  • MM8 — Arena + NodeId(u32) replaces pointers, so the tree is a flat, memcpy-serializable Vec the borrow checker accepts. Predicts: delete must not invalidate other ids (slab tombstones, not Vec::remove). Bug without it: Vec::remove shifts indices → dangling NodeIds across the tree. Applied: ADR-06, Phase 5.

  • Lucene/Elasticsearch BKD-tree chose an immutable, merge-on-write KD-B forest over a mutable R-tree because the workload is append-mostly with periodic merges — it wins for write-once document/log data at very high ingest where in-place mutation cost dominates.

  • DuckDB spatial builds a static R-tree over columnar batches and pushes spatial predicates into the vectorized scan — it wins for analytical bulk spatial joins where data is loaded once and scanned many times.

Back-of-Envelope Capacity Model

All inputs are taken from §4 (System Constraints); arithmetic is shown.

  1. Entry size. Rect (4×f64 = 32 B) + child id (8 B) + padding → 40–80 B; take 80 B worst case (§4 node-overhead row).
  2. Fanout per 4 KiB page. M = floor((4096 − 16 header) / 80) = floor(51.0) = 51 → M=50 as configured (ADR-11). Formula: M = (page − header)/entry.
  3. Tree height, N=10M. Best case ceil(log_M N) = ceil(log₅₀ 1e7) = ceil(4.12) = 5; worst case using m=20: ceil(log₂₀ 1e7) = ceil(5.38) = 6 → height 5–6 (I2).
  4. Node count. At 70% insert occupancy: leaves = 1e7 / (0.7×50) = 1e7/35 ≈ 286 K; internal ≈ 286K/35 ≈ 8.2 K; total ≈ 294 K nodes.
  5. In-RAM size. Leaf entries = 1e7 × 80 B = 800 MB; internal ≈ 8.2K × 50 × 80 B = 33 MB → ≈ 833 MB < 2 GiB and ≈ 1.3× raw data (§4 "≤ 2× raw").
  6. Page-file size (STR, 95% occupancy). Leaf pages = 1e7/(0.95×50) = 210.5 K; +internal ≈ 4.4 K → 215 K pages × 4 KiB ≈ 880 MB ≈ 1.3× raw (§4 "≤ 1.5×").
  7. Cache residency. 256-page cache vs 215 K total pages = 0.12% resident — but top two levels (root + L1 ≈ 90 pages) fit entirely, so every query serves root+L1 from cache; misses/query ≈ height − cached_levels ≈ 6 − 3 = 3 page reads.
  8. Window-query work (1% selectivity, 1M). ≈ 10 K results; nodes visited ≈ results/occupancy ≈ 10000/35 ≈ 286 leaves + ancestors ≈ ~300 node visits; at p50 ≤ 500 µs → ~1.7 µs/visit budget.
  9. Insert budget. 100 K/s → 10 µs/insert; ChooseLeaf descends 6 levels → 1.6 µs/level; an enlargement scan of 50 entries ≈ 50 × ~30 ns ≈ 1.5 µs/level ✓.
  10. kNN heap size (k=10, 1M). ~hundreds of nodes visited × M entries pushed → peak heap ~few thousand × 16 B ≈ tens of KB — negligible RAM.
  11. Geohash precision. 12 chars × 5 bits = 60 bits → cell ≈ earth-span / 2³⁰ per axis ≈ 37 mm; encode ≥ 5M/s → 200 ns/encode for ~60 bit-ops ✓.
  12. STR build, 10M. sort dominates: O(N log N) ≈ 1e7 × 23 ≈ 2.3e8 comparisons; at ≥ 500 K objs/s → ~20 s; slice count P = ceil(sqrt(N/M)) = ceil(sqrt(2e5)) = 448.

  1. Why does increasing page size (§4, ADR-11) reduce tree height yet can worsen window-query latency (Capacity Model, P4)?

  3. Best-first kNN (Phase 8) visits fewer nodes than depth-first (P-R3) yet both are correct — which invariant (I6) makes the pruning sound, and why?
  4. Deleting an entry can shrink an ancestor MBR (Phase 5 CondenseTree). Why is failing to tighten it a future-correctness bug (P2, I7) but not a bug for currently-returned results?
  5. Why can't the single-writer/multi-reader model (ADR-15, §4) be relaxed to multi-writer without redesigning split propagation (Phase 4, I2)?
  6. Geohash prefix scan misses results across cell boundaries (Phase 10, MM7). Derive the regime in which an application must fall back to the R-tree (Comparative).
  7. Reconcile STR's 95% occupancy target with quadratic-split's 50% guarantee (§4, ADR-07): which workload makes each correct, and how does occupancy feed back into height (Capacity Model)?
  8. Why does sidx reject object clipping (R+-tree, P-R6) given I7 — and in which regime (Alternative Architectures) would clipping actually win?
  9. The arena uses slab tombstones, not Vec::remove (ADR-06, MM8). What bug class in NodeId stability does this prevent during Phase 5 delete?
  10. The page cache holds 256 of 215 K pages (Capacity Model). Explain why a 0.12%-resident cache still serves most node-visits (locality + §4 LRU).
  11. Why is f64 mandated over f32 for MINDIST (ADR-04)? Connect the squaring in the MINDIST formula (P-R3, §8) to cancellation error.

  13. Derive the minimum disk reads per cold window query from height and cache levels (Capacity Model, §4), and explain why STR's high occupancy lowers it.
  14. Why must the MBR be recomputed bottom-up after both insert (AdjustTree, Phase 4) and delete (CondenseTree, Phase 5)? What single invariant (I3/I7) unifies them?
  15. The oracle asserts index_result == brute_force (ADR-20, §4 gate). Why is this the only practical way to catch a subtle split bug, and what would a hand-written unit test miss?

Alternative Architectures (Roads Not Taken)

A1 — KD-B forest of immutable segments (BKD).

ingest → buffer → sort → write immutable segment ──┐
                                                    ├─ merge segments periodically
query → search all live segments → union ──────────┘

Wins for append-mostly, high-ingest point data where rebuilds are cheaper than in-place mutation. Embodied by Lucene/Elasticsearch BKD. Rejected because sidx targets dynamic insert/delete with low-latency updates (§4), where rebuilding immutable segments on every change is unacceptable.

A2 — Space-filling curve + B-tree (Z-order / Hilbert / geohash-as-primary).

point → SFC key (interleave bits) → B-tree → range scan over curve intervals

Wins when an ordered KV store already exists and spatial is wanted as a prefix scan with zero new engine (MongoDB S2, geohash-in-Redis). Rejected as the core index because a query box maps to many disjoint curve ranges (over-fetch) and exact kNN is awkward — sidx keeps geohash as a secondary/interop layer (Phase 10), not the primary structure.

A3 — Fixed-grid / uniform-cell hash index.

extent → uniform W×H cells → hash(point)→cell → bucket list

Wins for uniformly-dense point data with known extent (collision systems, particle sims). Rejected because real geographic data is skewed: cells either overflow or waste memory, and range queries touch many empty cells — the R-tree adapts to local density instead.

A4 — R+-tree / disjoint-partition (clipping) index.

object spanning a boundary → clipped → stored in BOTH child partitions (no overlap)

Wins for static, read-heavy workloads where eliminating multi-path descent matters more than storage and update cost. Embodied by the R+-tree (P-R6) and Cell-tree (P-R11). Rejected because clipping duplicates objects (violates I7) and complicates delete — sidx minimizes overlap via R* splits instead.

Glossary

Terms are implementation-relevant; definitions reflect the semantics enforced by the codebase.

Term Definition
Area enlargement Increase in MBR area required to accommodate a new entry; the primary cost function in ChooseLeaf for R-tree insertion. Computed by sidx-geom::enlargement(existing: Rect, new: Rect) -> f64.
Axis-aligned bounding box (AABB) Synonym for MBR in this library; all bounding geometry is axis-aligned.
Balance (height-balanced) All leaf nodes of an R-tree reside at level 0; no leaf is deeper or shallower than another. Maintained by bottom-up split propagation. Invariant I2.
Base32 (geohash) 32-character alphabet (0–9, b–z minus a/i/l/o) used to encode interleaved coordinate bits into printable geohash strings. Each character encodes 5 bits.
Best-first search Priority-queue traversal in kNN (sidx-knn) where the node/entry with smallest MINDIST to the query point is always expanded next; guarantees exact k nearest without exhaustive scan.
Bit interleaving Technique in geohash encoding: alternate longitude bits and latitude bits into a single integer, enabling a 1-D sort that approximates 2-D proximity.
Branch and bound kNN algorithm framework: maintain a k-result bound; prune any subtree whose MINDIST exceeds the current k-th distance. Implemented in sidx-knn.
Bulk loading Building an R-tree from a static dataset in a single pass (STR), yielding higher occupancy and better query performance than repeated insertion. See Phase 7.
ChooseLeaf R-tree insertion subroutine: descend from root to a leaf by choosing the child whose MBR requires the least enlargement to contain the new entry (tie: least area).
Choose-subtree (R*) R*-tree replacement for ChooseLeaf: at the leaf level minimises overlap enlargement; above leaf level minimises area enlargement. Reduces sibling overlap.
Condense tree Post-deletion R-tree repair: walk up from the deleted leaf, remove under-full nodes (fewer than m entries), collect their orphaned entries, and reinsert them.
Containment query Query returning all indexed objects whose MBR is entirely within the query rectangle. Predicate: query_rect.contains(entry.mbr).
Coverage / dead space Total area of all node MBRs in a level minus the area of their union; a measure of wasted bounding volume. Minimising coverage is a split quality objective in R*-tree.
DataId u64 opaque identifier stored at R-tree leaves and quadtree leaf slots, referencing the caller's object record. Never dereferenced inside the library.
Enlargement See Area enlargement.
Entry A slot within an RTreeNode: carries an MBR and either a Child(NodeId) pointer or a Data(DataId) payload.
Fanout Number of entries per internal node; bounded between m and M (e.g., m=2, M=8 for testing; m=50, M=100 for production). Determines tree height and I/O cost.
Forced reinsertion R*-tree overflow strategy: on the first overflow at a given level during one insertion, remove the p (typically 30%) entries farthest from the node centroid and reinsert them, often avoiding a split and improving tree structure.
Geohash Compact string encoding of a (lat, lng) coordinate as a base32 string; longer strings denote smaller cells. Defined by GeoHash { bits: u64, precision: u8 }.
GeoHash cell The Rect decoded from a GeoHash value; the original coordinate is guaranteed to lie within it (Invariant I8).
Intersection query Query returning all indexed objects whose MBR intersects (overlaps) the query rectangle. Predicate: entry.mbr.intersects(query_rect).
kNN (k-nearest-neighbor) Query returning the k objects with smallest distance from a query point, exact under the chosen metric. Implemented in sidx-knn; exact by P5.
Leaf node An RTreeNode at level 0; its entries hold Data(DataId) payloads rather than Child(NodeId) pointers.
Linear split O(n) node split algorithm from Guttman 1984: pick seeds by most extreme low/high coordinates on each axis; distribute remaining entries by least MBR enlargement. Low quality but fast.
MBR (minimum bounding rectangle) The tightest axis-aligned rectangle enclosing a set of objects or child MBRs. Every node's stored MBR must satisfy Invariant I1.
MINDIST Lower bound on the distance from a point to the nearest object in a subtree, computed from the point and the node's MBR. Used to prune branches in kNN (I6).
MINMAXDIST Upper bound on the distance to the nearest object in a subtree; the minimum over all faces of the maximum distance from the query point to the face's far corner. Enables early termination.
NodeId u32 arena index identifying an RTreeNode or QuadNode in the slab allocator; no raw pointer arithmetic.
Occupancy Fraction of node slots filled; bounded by Invariant I3 (m <= count <= M for non-root). STR bulk-loading targets ~85–100% occupancy.
Overlap Area of intersection between two sibling node MBRs; high overlap forces searches down multiple subtrees, degrading query performance. Minimised by R*-tree split.
Page / PageId Fixed-size byte block (e.g., 4096 bytes) in sidx-persist; each tree node is serialised into one or more pages identified by PageId.
Pick seeds First step of quadratic/linear split: select two entries as the initial pair for the two groups being formed.
Point quadtree Quadtree variant that partitions space by inserting points; each point becomes a subdivision centre. Distinguishable from region/PR quadtree.
Prefix range For a geohash prefix string, the contiguous lexicographic range [prefix, prefix_end) that covers all cells sharing that prefix; enables efficient DB range scans.
PR quadtree Point-Region quadtree: space is subdivided into fixed quadrants (not centred on data points); all points in a region share the same quadrant. Implemented in sidx-quadtree.
Quadratic split O(n²) node split: pick seeds maximising the area of the MBR of the pair minus both individual MBRs; distribute remaining entries to the group requiring less enlargement.
R*-tree Extension of R-tree by Beckmann et al. (1990) adding overlap-minimising choose-subtree, improved split axis selection, and forced reinsertion. Implemented in sidx-rstar.
R-tree Dynamic spatial index by Guttman (1984): height-balanced tree of MBRs, analogous to a B-tree for spatial data. Implemented in sidx-rtree.
Rect { min: Point, max: Point } with min[i] <= max[i] per axis. Canonical MBR type. Degenerate (min==max) permitted for point MBRs.
SplitStrategy Enum { Quadratic, Linear, RStar } selecting which split algorithm sidx-rtree/sidx-rstar uses at node overflow.
Sort-Tile-Recursive (STR) Bulk-loading algorithm: sort by x-centre into sqrt(n/M) vertical slices, sort each slice by y-centre, pack into full leaf nodes, recurse up. Implemented in sidx-bulk.
Spatial index Data structure that organises objects by their geometric extent (MBR or point) to answer spatial queries in sub-linear time.
Window query Synonym for range query: return all objects whose MBR intersects a rectangular query window. The most common spatial query type.
