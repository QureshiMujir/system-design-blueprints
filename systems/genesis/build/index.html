⬜ Phase 0 — Skeleton, Genome IR, CI §12

Objectives

Stand up the Cargo workspace, the genesis-genome crate's IR + grammar + type-checker, and CI (ADR-16). No sandbox, no fitness DSL yet — mutation/evaluation are stubbed.

Deliverable

genesis-cli parse <file>.gnm parses, type-checks, hashes, and stores a genome; genesis-cli show <hash> retrieves and pretty-prints it.

Acceptance

100% of the EBNF grammar (§8) accepted by the parser with zero panics across a 5,000-case proptest corpus; type-checker rejects 100% of the malformed-genome fixture set (§12.5); round-trip parse→hash→store→fetch→pretty-print is byte-identical for 1,000 random genomes; CI green on 3 consecutive PRs.

Fixtures

fixtures/genome_basic.gnm — canonical well-typed genome; expected: parses + type-checks. fixtures/genome_malformed_unknown_fn.gnm — undefined identifier; expected: TypeCheckReject{UnknownIdentifier}. fixtures/genome_malformed_shadow.gnm — illegal Let shadowing; expected: reject. fixtures/genome_roundtrip_regression.gnm — pins a previously-buggy hash-stability regression.

Pitfalls

Hash instability from non-canonical arena ordering — manifests as duplicate store entries for structurally identical genomes; root cause: arena index order not normalized before hashing; debug via lineage_inspector's hash-collision scan; signal: store size grows unexpectedly while genesis_lineage_cycle_detected_total stays zero; recovery: canonicalize the arena via post-order re-index before hashing.

Type-checker accepting shadowed Let bindings — manifests as ambiguous VarRef resolution later; root cause: missing shadow-check in typecheck.rs; debug via targeted proptest; signal: genesis_typecheck_reject_total undercounts known-bad fixtures; recovery: add an explicit shadow-detection pass.

Parser accepting trailing garbage after a valid genome — manifests as silently truncated evaluation later; root cause: missing EOF assertion; debug via fuzz corpus; recovery: require full-input consumption.

⬜ Phase 1 — Sandbox + Evaluation Harness §13

Objectives

Build the genesis-sandbox crate's Wasmtime-backed execution path (ADR-02, ADR-03) and the minimal evaluation harness that invokes a compiled WASM module and returns a SandboxResult (§11), using fixed built-in test cases in place of §14's fitness DSL.

Deliverable

genesis-cli eval <hash> compiles a stored genome to WASM, runs it in a pooled sandbox against a fixed built-in test vector, and prints the SandboxResult.

Acceptance

Sandbox spawn latency p50 ≤ 1.2 ms / p95 ≤ 4 ms / p99 ≤ 12 ms on the Wasmtime path (§4); a fuel-exhaustion genome (infinite-loop Call) is hard-killed within 2× its configured CPU ceiling in 100% of 500 trials; zero observed sandbox escapes across a 10,000-trial adversarial corpus (fixtures/escape_attempts/).

Fixtures

fixtures/sandbox_ok.gnm — well-behaved genome; expected: ExitTaxonomy::Ok. fixtures/sandbox_infinite_loop.gnm — fuel exhaustion; expected: FuelExhausted within timeout. fixtures/sandbox_oob_memory.gnm — out-of-bounds linear-memory access; expected: Trap. fixtures/sandbox_escape_replay.gnm — regression pin for a prior escape-adjacent bug.

Pitfalls

Sandbox escape via shared Engine state — manifests as one candidate influencing another's execution; root cause: mutable state leaked through a shared compiled-module cache; debug via cross-candidate determinism diff; signal: genesis_sandbox_escape_attempts_total; recovery: audit Engine config for interior mutability, isolate per pool shard.

Non-determinism from float reduction order inside numeric ops — manifests as replay divergence (I1) on floating-point-heavy genomes; root cause: unspecified summation order in a Call chain; debug via the sim harness replay-diff; recovery: mandate a canonical left-to-right reduction order in codegen.

Fuel-exhaustion trap racing a legitimate slow-but-valid computation — manifests as false-positive penalization; root cause: ceiling too tight for a valid heavy .gns case; debug via ceiling-breach histogram; recovery: expose a per-run ceiling override (§11 RunConfig).

⬜ Phase 2 — Fitness DSL Compiler §14

Objectives

Implement genesis-fitness: the .gns parser + compiler producing an immutable EvaluationPlan (§11), the total-fitness penalty mapping (P3, I4), and the purity check (I13) gating spec load.

Deliverable

genesis-cli compile <spec>.gns produces a validated EvaluationPlan; genesis-cli score <hash> <spec>.gns runs a genome through Phase 1's sandbox against the compiled plan and prints per-case + total fitness.

Acceptance

The worked fib_correct example (§8) scores exactly 1.0 for a correct Fibonacci genome and exactly 0.0 for a constant-zero genome across all three cases; 100% of the malformed-.gns fixture set (§14.5) rejected at compile time, never at evaluation time; fitness is finite (no NaN/Inf) across a 50,000-trial fuzz corpus of adversarial genomes (I4).

Fixtures

fixtures/fib_correct.gns — worked example from §8; expected: total fitness 1.0 for the reference solution. fixtures/gns_malformed_arity.gns — case input-arity mismatch; expected: compile-time reject. fixtures/gns_malformed_impure.gns — a case referencing a disallowed host construct; expected: I13 reject. fixtures/gns_penalty_regression.gns — pins the exact penalty constant for a Trap exit.

Pitfalls

Fitness gaming — a candidate special-cases the exact test inputs without generalizing; manifestation: perfect score, zero generalization on held-out cases; root cause: .gns case set too small/predictable; debug via held-out case injection; signal: score variance between train/held-out case subsets; recovery: operator adds held-out cases, documented in a runbook.

Penalty-constant miscalibration — a Trap penalty numerically close to a legitimate low score; manifestation: selection can't distinguish "crashed" from "ran badly"; root cause: penalty scheme not separated by an order of magnitude from the worst legitimate score; debug via score-distribution histogram; recovery: widen the penalty floor.

Tolerance-zero Float comparisons — manifestation: intermittent false-negative case failures on numerically-equivalent results; root cause: P1's float-reduction-order variance without an explicit tolerance; debug via replay-diff; recovery: require nonzero tolerance for all Float expect values (§8).

⬜ Phase 3 — Mutation Operators §15

Objectives

Implement genesis-mutate's full operator catalogue (§8: point, subtree, hoist, shrink, permutation, size-fair) with the type-checker gate (I7) wired so no operator output can enter a job ill-typed.

Deliverable

genesis-cli mutate <hash> --operator subtree --seed N applies one operator and prints the offspring's hash and whether it passed type-check.

Acceptance

100% of 100,000 fuzz-generated operator applications produce either a well-typed offspring or a documented no-op fallback — zero ill-typed genomes ever reach the store (I7); operator-reject rate stays within the 2–5% steady-state band (§8) on the reference fibonacci_repair corpus; each operator's expected-fitness-Δ sign (§8 table) matches the observed distribution within one standard deviation across 10,000 trials.

Fixtures

fixtures/mutate_point_basic.gnm — canonical point-mutation case; expected: same-τ replacement. fixtures/mutate_subtree_no_target.gnm — no type-compatible target exists; expected: no-op fallback, not an ill-typed genome. fixtures/mutate_hoist_regression.gnm — pins a prior hoist-mutation type-check bypass bug. fixtures/mutate_size_fair_bloat_control.gnm — verifies size-matched replacement doesn't grow genome size.

Pitfalls

Subtree mutation silently degrading to always-no-op — manifestation: population diversity collapses; root cause: find_typed_subtree's depth-search budget too small for the type lattice's branching factor; debug via operator-reject-rate telemetry; signal: genesis_operator_reject_total far above the 2–5% band; recovery: widen the search budget or add more terminal types.

Hoist mutation bypassing the type-checker via a cached stale type annotation — manifestation: an ill-typed genome reaches the store; root cause: node_types not recomputed after hoist's root-swap; debug via a store-write assertion; recovery: force a full re-typecheck post-hoist, never trust cached types across a structural edit.

Permutation treating non-commutative Call arguments as swappable — manifestation: a subtle semantic change disguised as permutation; root cause: missing commutativity metadata on the primitive-function signature table (§11); debug via differential testing pre/post permutation; recovery: annotate commutative primitives explicitly, default to non-commutative.

⬜ Phase 4 — Selection & the Generational Loop §16

Objectives

Implement genesis-select: tournament selection, Real et al. (2019) AAAI age-based (regularized-evolution) replacement, and the SELECTING → REPLACING → ARCHIVING → ADVANCING arc of the state machine (§8), driving Phases 0–3's genome/sandbox/fitness/mutation crates into a working generational loop.

Deliverable

genesis-cli run --generations N --policy tournament|regularized drives N full generations end-to-end (select → breed via §15/§17 stubs → type-check → replace → archive-stub → advance) against a fixed population and prints per-generation best/mean/worst fitness plus population size.

Acceptance

Population size never exceeds population_size across 1,000 generations on a 500-genome reference population (I6, zero violations); tournament selection with k=4 reproduces Goldberg (1989)'s expected selection-intensity curve within 5% across a 10,000-trial statistical fixture; regularized evolution's age distribution matches Real et al. (2019)'s oldest-out property exactly (100% of replaced genomes are the oldest surviving cohort member) on fixtures/regularized_age_order.gnm; generation counter (I12) is strictly monotonic across 10 simulated worker-restart-mid-generation trials.

Fixtures

fixtures/select_tournament_k4.gnm — reference population with known fitness distribution; expected: selection-intensity curve within 5% of theory. fixtures/select_regularized_age_order.gnm — pins oldest-out replacement order; expected: exact age-rank match. fixtures/select_population_overflow.gnm — offspring batch exceeding ceiling; expected: truncate-lowest-fitness, I6 holds. fixtures/select_replay_regression.gnm — pins a prior counter-regression bug (I12) under simulated restart.

Pitfalls

Premature convergence from tournament size set too high — manifestation: fitness variance collapses by generation 20–30 on problems needing exploration; root cause: k too close to population size, selection pressure crowds out diversity (Goldberg 1989); debug via per-generation fitness-variance telemetry; signal: genesis_population_fitness_variance trending to near-zero far earlier than the reference corpus's expected knee; recovery: lower k or switch to regularized evolution's implicit diversity preservation.

Age-tracking drift under checkpoint/resume — manifestation: regularized evolution replaces the wrong cohort after a resume (§22); root cause: age counter reset instead of restored from checkpoint; debug via lineage-DAG cross-check of insertion generation vs stored age; signal: genesis_archive_regression_total-adjacent anomaly in oldest-out order; recovery: persist age as an explicit checkpoint field, never derive from wall-clock.

Off-by-one in population admission control — manifestation: population briefly exceeds ceiling by exactly one offspring batch; root cause: admission check runs before, not after, the full REPLACING batch is materialized; debug via I6 size assertion firing sporadically; recovery: gate admission on the post-batch size, not per-offspring.

Selection collapsing under a stale fitness cache — manifestation: tournament repeatedly picks an already-replaced genome; root cause: PopulationRecord.fitness read from a pre-REPLACING snapshot; debug via generation-boundary read/write ordering trace; recovery: SELECTING must read only the ARCHIVING-committed prior generation.

⬜ Phase 5 — Crossover & Type Preservation §17

Objectives

Implement genesis-crossover's subtree crossover (Koza 1992) with hard type preservation (P5, I7), completing the BREEDING stage of the state machine (§8) alongside Phase 3's mutation operators.

Deliverable

genesis-cli crossover <hashA> <hashB> --seed N produces one or two offspring, prints their hashes, whether each passed type-check, and whether the operation degraded to clone-fallback.

Acceptance

100% of 100,000 fuzz-generated crossover pairs produce either a well-typed offspring or a documented clone-fallback — zero ill-typed genomes reach the store (I7), matching Phase 3's bar; clone-fallback rate stays below 8% on the reference fibonacci_repair corpus at max_depth 12 (a rate above this signals a type-lattice gap per §17.6); crossover offspring depth never exceeds max_depth in 50,000 trials; a differential test against Koza (1992)'s canonical subtree-crossover semantics on 20 hand-checked genome pairs matches exactly.

Fixtures

fixtures/crossover_basic_pair.gnm — two well-typed parents with a known compatible pair; expected: both offspring well-typed, non-fallback. fixtures/crossover_no_compatible_point.gnm — parents with no shared-τ subtree within budget; expected: clone-fallback of parent A, never ill-typed. fixtures/crossover_depth_ceiling.gnm — a pair whose naive swap would exceed max_depth; expected: rejected candidate point, search continues or falls back. fixtures/crossover_regression_type_bypass.gnm — pins a prior type-checker-bypass bug found via fuzzing.

Pitfalls

Crossover point search degrading to always-fallback — manifestation: population-wide loss of recombination diversity, visible as a genesis_operator_reject_total-adjacent crossover-fallback-rate spike; root cause: depth-search budget too small relative to type-lattice branching factor, identical class of bug to §15.6's subtree-mutation collapse; debug via fallback-rate telemetry; recovery: widen the budget or add a cheaper coarse pre-filter by top-level type before the full search.

Non-local swap silently violating max_depth — manifestation: an offspring genome exceeds the depth ceiling and is rejected downstream at sandbox codegen instead of at crossover time; root cause: depth check computed pre-swap, not post-swap; debug via a depth-recompute assertion immediately after subtree substitution; recovery: recompute depth post-swap before returning the candidate, reject-and-retry if exceeded.

Commutative-argument mismatch corrupting semantic equivalence assumptions — manifestation: crossover treats two non-commutative Call argument positions as interchangeable during point matching; root cause: missing or stale commutativity metadata reused incorrectly from Phase 3; debug via differential pre/post-crossover execution trace; recovery: default every primitive to non-commutative unless explicitly annotated (same fail-safe default as §15.6).

Shared-subtree aliasing across parents from store deduplication (P4) causing a copy-on-write miss — manifestation: mutating one offspring's subtree corrupts the other parent's stored genome; root cause: crossover output arena not fully copied before substitution; debug via a post-crossover hash-stability check on both original parents; recovery: enforce copy-on-write at the arena level for every crossover output, never share arena slices across genome hashes.

⬜ Phase 6 — Archive, Lineage & Reproducibility §18

Objectives

Complete genesis-store's lineage DAG (I11), wire the full ARCHIVING-stage reproducibility contract (P9, I3), and build the seed+lineage replay harness that Phase 0–5's crates have been referencing since §7's debugging methodology.

Deliverable

genesis-cli replay --seed N --lineage-log <path> --spec <file>.gns --to-generation G reconstructs generation G's population bit-for-bit and diffs it against a recorded reference run, printing PASS/FAIL per genome hash.

Acceptance

100% bit-identical replay across 200 independent (seed, config) reference runs up to generation 500 (I1, I3); zero lineage cycles across a 500,000-edge stress-inserted DAG (I11); replay-diff harness detects an intentionally injected float-reduction-order bug in fixtures/lineage_nondeterminism_injected.gnm within one generation of divergence; lineage edge-log WAL recovers to the last fsynced edge after a simulated mid-write crash in 100/100 trials (ADR-23, I10-adjacent).

Fixtures

fixtures/lineage_replay_basic.gnm — 50-generation reference run; expected: bit-identical replay. fixtures/lineage_cycle_attempt.gnm — a malformed edge insert that would close a cycle; expected: reject, genesis_lineage_cycle_detected_total increments. fixtures/lineage_nondeterminism_injected.gnm — deliberately reordered float accumulation; expected: replay-diff flags divergence at the exact generation it occurs. fixtures/lineage_wal_crash_recovery.gnm — simulated torn WAL write; expected: recovers to last complete edge, no partial-edge corruption.

Pitfalls

Non-determinism from parallel float reduction order — manifestation: replay diverges only under multi-worker fan-in, never in single-node reference runs; root cause: a fitness-aggregation or archive-merge step summing floats in worker-arrival order instead of a canonical (e.g. genome-hash-sorted) order; debug via the replay-diff harness run once single-node, once fleet-distributed, comparing divergence generation; signal: genesis_replay_divergence_total nonzero only in fleet mode; recovery: mandate a canonical sort key before every cross-worker float reduction (extends P1's discipline from single-node to fleet-wide).

Lineage DAG unboundedness — manifestation: the WAL and RocksDB store grow without bound across a multi-week run; root cause: no retention/compaction policy on old lineage edges whose genomes have long since left the population and archive; debug via store-size-vs-generation trend; signal: disk usage exceeding the §34 capacity-model projection; recovery: compact edges older than a configurable retention horizon into a summary checkpoint (§22), retaining only archive-cell ancestry chains, not every discarded genome's full history.

Stale-worker result poisoning the lineage log — manifestation: an edge is recorded for a child genome whose evaluation result actually came from a since-retried, superseded worker attempt; root cause: lineage write not gated on the same idempotency key (I14) the scheduler (§19) uses for job dispatch; debug via cross-referencing lineage edges against the dedup ledger; signal: a lineage edge whose (genome hash, generation, attempt) key is not the ledger's accepted attempt; recovery: gate every lineage write on the scheduler's idempotency decision, never write ahead of it.

Cycle check false-negative under concurrent inserts — manifestation: two concurrent edge inserts each individually acyclic together close a cycle; root cause: cycle check read a stale DAG snapshot under concurrent writers; debug via a targeted concurrent-insert stress fixture; recovery: serialize cycle-check-and-insert as one atomic RocksDB transaction, never check-then-insert as two steps.

⬜ Phase 7 — Distributed Evaluation Scheduler §19

Objectives

Implement genesis-scheduler: credit-based backpressure (P6, ADR-21), idempotent job dispatch (P14, I14) across a worker fleet, and the gRPC control-plane transport (ADR-08) connecting genesis-api to genesis-worker.

Deliverable

genesis-worker --connect <api-addr> joins the fleet and advertises credit; genesis-cli fleet-status prints per-worker credit, in-flight job count, and dedup-ledger occupancy; a simulated 3-worker fleet completes 10 generations end-to-end over gRPC.

Acceptance

Zero duplicate fitness application across 10,000 simulated worker-restart-mid-job trials (I14); scheduler memory stays bounded (no growth beyond the configured queue depth) under a 50-worker fleet with one worker deliberately stalled for 10 minutes (P6); job dispatch reaches steady-state 800 eval/s per worker (§4) with less than 2% scheduler-attributable overhead versus direct in-process dispatch; a killed-and-restarted worker's in-flight jobs are fully re-dispatched and re-credited within one heartbeat interval in 100/100 trials.

Fixtures

fixtures/scheduler_duplicate_dispatch.gnm — simulated retry of an already-completed job; expected: rejected by dedup ledger, genesis_duplicate_job_total increments, no double fitness-apply. fixtures/scheduler_credit_exhaustion.gnm — fleet credit fully consumed; expected: new dispatch blocks, queue depth stays bounded, no unbounded growth. fixtures/scheduler_worker_restart_midjob.gnm — worker dies mid-evaluation; expected: job re-dispatched exactly once under the same idempotency key. fixtures/scheduler_stale_worker_poison.gnm — a stale worker's delayed result arrives after its job was already reassigned; expected: stale result dropped, not applied (ties to §18.6's stale-worker pitfall).

Pitfalls

Stale-worker result poisoning the population — manifestation: a slow worker's delayed result overwrites a newer, already-applied fitness for the same genome; root cause: result application not re-checked against the dedup ledger's current accepted attempt at apply time, only at dispatch time; debug via correlating result-arrival timestamps against reassignment events; signal: genesis_duplicate_job_total stays zero while population fitness shows an inexplicable regression; recovery: re-validate the idempotency key at result-apply time, not only at dispatch time — the fix generalizes §18.6's lineage-side mitigation to the scheduler's own state.

Credit accounting drift under partial heartbeat loss — manifestation: a worker's advertised credit silently diverges from its true available capacity; root cause: credit renewal message loss not distinguished from an intentional zero-credit signal; debug via per-worker credit-vs-in-flight-job-count cross-check; signal: a worker perpetually shown with negative effective credit; recovery: treat missed heartbeat as credit-zero (fail closed) rather than credit-unknown (fail open).

Backpressure deadlock from a fully circular credit wait — manifestation: the scheduler stalls dispatching to a fleet with nonzero aggregate credit; root cause: a single-queue-per-worker design head-of-line-blocked behind one slow job while credit sits idle elsewhere; debug via per-worker queue-depth-vs-credit dashboard; recovery: work-stealing across worker queues within the same credit budget, never a strict per-worker FIFO that can starve.

Idempotency key collision across generations — manifestation: two distinct evaluation attempts share a dedup key and one is incorrectly dropped; root cause: key composed of only (genome hash, attempt), omitting generation, and P4's content-addressing means the same genome can legitimately recur across generations; debug via ledger-key collision audit; recovery: the key must always be the full (genome hash, generation, attempt) triple per I14's definition, never a subset.

⬜ Phase 8 — Novelty Search & Quality-Diversity Archive §20

Objectives

Implement genesis-population's MAP-Elites behavior-space archive (Mouret & Clune 2015) and novelty search as an alternative/complementary selection pressure (Lehman & Stanley 2011), completing P7's "archive over single-best" principle and I9's archive-monotonicity invariant.

Deliverable

genesis-cli archive-status prints per-cell occupancy, coverage percentage, and mean cell fitness; genesis-cli run --selection novelty|map-elites|blend drives the generational loop under the chosen quality-diversity pressure; archive_viewer (§10) renders the grid.

Acceptance

Zero archive regressions (a cell overwritten by a strictly worse occupant) across 1,000,000 simulated concurrent-write trials (I9); archive coverage on the reference sorting_synthesis corpus reaches at least 40% of the 10,000-cell grid within 200 generations under novelty-driven search, versus under 15% under scalar-fitness-only search on the same corpus (reproducing Lehman & Stanley 2011's coverage-advantage finding); k-nearest-neighbor novelty scoring completes within the per-generation cadence budget (§4) at k=15, population 10,000; archive disk footprint matches the §4 projection (≈40 MiB per generation snapshot at default grid size) within 10%.

Fixtures

fixtures/archive_cas_race.gnm — two candidates racing for the same cell; expected: strictly-better-wins, no regression (I9). fixtures/archive_coverage_novelty.gnm — reference corpus run under novelty search; expected: ≥40% coverage by generation 200. fixtures/archive_coverage_scalar_baseline.gnm — same corpus under scalar-fitness-only; expected: <15% coverage, establishing the comparison baseline. fixtures/archive_descriptor_malformed.gnm — a behavior descriptor outside the configured grid bounds; expected: clamped to the nearest valid cell, never a silent out-of-bounds write.

Pitfalls

Archive unboundedness from an unbounded novelty-comparison set — manifestation: novelty scoring cost grows without bound across a multi-week run as the comparison archive accumulates every historically novel genome; root cause: no cap on the novelty archive's retained-genome count; debug via per-generation novelty-scoring-duration trend; signal: genesis_novelty_score_duration_seconds growing generation-over-generation; recovery: bound the novelty archive to a fixed-size reservoir sample (age- or novelty-weighted eviction), never let it grow with run length.

Premature convergence masked by archive occupancy alone — manifestation: archive coverage looks healthy while scalar-fitness progress has actually stalled; root cause: reading coverage in isolation without also tracking mean-cell-fitness trend; debug via joint coverage + mean-fitness dashboard (extends §16.6's diagnosis pattern to the archive path); recovery: pair every coverage metric with a fitness-trend metric, treat coverage alone as necessary but not sufficient evidence of healthy search.

Behavior-descriptor degeneracy collapsing diversity into few cells — manifestation: most candidates map to a small cluster of cells despite genome-level diversity; root cause: descriptor dimensions chosen too coarse or correlated with each other, not spanning the true behavior space; debug via descriptor-value distribution histogram across a random-genome sample; recovery: redesign descriptor extraction (operator-config change, versioned per P12), never silently widen grid resolution as a substitute for a better descriptor.

Archive compare-and-swap race under distributed writers — manifestation: two workers' results for the same behavior cell interleave incorrectly across the scheduler (§19); root cause: CAS implemented as read-then-write across a network round-trip instead of an atomic RocksDB transaction; debug via a targeted concurrent-write stress fixture, same failure class as §18.6's cycle-check race; recovery: the archive write must be one atomic transaction server-side, never a client-observed read followed by a separate write.

⬜ Phase 9 — Bloat Control & Parsimony Pressure §21

Objectives

Implement continuous parsimony pressure (P8) as a size-adjusted fitness term active from generation 0, and reconcile it with Phase 3's size-fair mutation (§15) to give Langdon & Poli (2002)'s bloat theory an operational, measurable mitigation.

Deliverable

genesis-cli run --parsimony-coefficient C runs the generational loop with the size-adjusted fitness term active; genesis-cli bloat-report prints mean/median/max genome size per generation and flags any run exceeding the bloat-alert threshold.

Acceptance

With parsimony_coefficient at the reference-tuned default, mean genome size growth across 500 generations on the sorting_synthesis corpus stays within 1.5× its generation-0 mean size (versus unbounded growth exceeding 8× observed with coefficient 0, reproducing Langdon & Poli 2002's bloat prediction); adjusted-fitness ranking never reorders two candidates whose raw fitness differs by more than 10× the parsimony term's maximum possible contribution (guards against parsimony dominating raw fitness); zero cases of a Trap/HostError penalty (I4) being altered by the size-adjustment term across 10,000 fuzzed candidates (penalty floor stays a size-independent constant).

Fixtures

fixtures/parsimony_bloat_baseline.gns — 500-generation run with coefficient 0; expected: size growth exceeds 8× baseline, establishing the unmitigated-bloat reference. fixtures/parsimony_bloat_controlled.gns — same run with tuned coefficient; expected: size growth stays within 1.5×. fixtures/parsimony_penalty_floor_unaffected.gns — a Trap-exit candidate under size adjustment; expected: penalty constant identical regardless of candidate size. fixtures/parsimony_ranking_stability.gns — pins a case where a large fitness gap must not be reordered by the size term.

Pitfalls

Code bloat despite an active parsimony term — manifestation: mean size still grows steadily, just slower than uncontrolled; root cause: coefficient tuned too low relative to the fitness landscape's raw-score scale, or size-fair mutation rate too low to counter crossover-driven size drift (§17); debug via the bloat-report trend against the §21.4 reference curve; signal: genesis_genome_mean_size trending above the 1.5× threshold; recovery: autotune the coefficient (§22) rather than hand-tune per run.

Parsimony term dominating and collapsing search into trivial small genomes — manifestation: population converges to minimal-size, low-raw-fitness genomes; root cause: coefficient set too high relative to the raw-fitness scale, size term overwhelms objective signal; debug via adjusted-vs-raw fitness divergence trend; signal: mean genome size dropping toward the terminal-only floor while raw fitness stagnates; recovery: lower the coefficient, verify against the §21.4 ranking-stability bound.

Fitness-function gaming via size-invariant shortcuts — manifestation: a candidate exploits a .gns case weighting to score well with degenerate near-constant logic, appearing not to be bloat but actually a fitness-oracle gap; manifestation overlaps with §14.6's fitness-gaming pitfall; root cause: parsimony pressure treated as a substitute for held-out case coverage, which it is not; debug via held-out case injection (§14.6's remedy) alongside bloat metrics; recovery: address via .gns spec design, not the parsimony coefficient — the two failure classes must not be conflated operationally.

Size-fair mutation rate and parsimony coefficient fighting each other — manifestation: bloat-control levers produce oscillating mean-size trends generation-to-generation instead of monotonic control; root cause: both levers tuned independently without joint calibration; debug via cross-correlating size-fair mutation rate changes against mean-size derivative; recovery: treat the two levers as one joint bloat-control config unit, autotuned together (§22), never adjusted independently mid-run.

⬜ Phase 10 — Checkpoint/Resume & Operator Autotuning §22

Objectives

Implement genesis-checkpoint: crash-consistent snapshot/resume (I10) satisfying the 30 s control-plane RTO (§4), and operator-rate/parsimony-coefficient autotuning per Poli, Langdon & McPhee (2008)'s practical tuning heuristics.

Deliverable

genesis-cli checkpoint --now forces an out-of-band snapshot; genesis-cli resume --from <snapshot> restores full run state and continues the generational loop; genesis-cli autotune-report prints the autotuning controller's decision log since run start.

Acceptance

Control-plane recovery from a killed process completes within the 30 s RTO (§4) in 100/100 trials on the reference 200,000-genome-population checkpoint; CRC validation rejects 100% of 500 deliberately corrupted snapshot fixtures, falling back to the prior generation's checkpoint every time (I10); autotuning converges tournament k and parsimony coefficient to within 10% of the hand-tuned reference values (§16.4, §21.4) within 50 autotuning-eligible checkpoints on the reference corpus; resumed runs replay bit-identically to an uninterrupted reference run through generation 500 (I1, I3 — extends §18.4's replay bar across a crash/resume boundary).

Fixtures

fixtures/checkpoint_crash_mid_write.gnm — simulated kill during snapshot write; expected: torn snapshot detected via CRC, fallback to prior checkpoint. fixtures/checkpoint_resume_bitidentical.gnm — resume-then-replay compared against an uninterrupted reference run; expected: bit-identical through generation 500. fixtures/autotune_convergence_reference.gnm — 50-checkpoint autotuning run; expected: converges within 10% of hand-tuned reference. fixtures/checkpoint_rto_budget.gnm — timed recovery on the reference population size; expected: under 30 s.

Pitfalls

Autotuning oscillation from overlapping control loops — manifestation: operator rates and the bloat-control unit (§21) each independently autotuned end up fighting, producing oscillating rather than converging telemetry trends; root cause: separate controllers acting on correlated signals (fitness variance and mean-size trend both react to selection-pressure changes) without joint awareness; debug via cross-correlating consecutive autotuning decisions against the telemetry deltas that triggered them; recovery: autotune as one joint controller with a single bounded-step-size policy across all levers, never as independent per-lever controllers (extends §21.6's joint-tuning lesson to the full autotuning surface).

Checkpoint RTO regression from an unbounded lineage-replay-since-snapshot window — manifestation: resume time grows with time-since-last-checkpoint instead of staying bounded; root cause: checkpoint cadence configured too sparse relative to generation cadence, forcing a long lineage replay (§18) on every resume; debug via resume-time-vs-checkpoint-interval trend; signal: RTO budget (§4) breached only after long inter-checkpoint gaps; recovery: bound checkpoint interval as a function of the RTO budget divided by observed per-generation lineage-replay cost, not a fixed generation count.

Snapshot embedding stale RunConfig after a live config change — manifestation: a resumed run silently reverts an operator-rate change an operator made between checkpoints; root cause: config-change log (P12) applied in-memory but not flushed into the next snapshot atomically with the config-change log entry; debug via diffing snapshot RunConfig against the config-change log's latest entry timestamp; recovery: snapshot writer must read the config-change log's current head atomically with population state, same atomicity discipline as the lineage-edge/result-apply ordering fix in §19.6.

Autotuning drifting parameters outside validated bounds — manifestation: the parsimony coefficient (§21) or tournament k (§16) autotunes past the range those phases' acceptance criteria were validated against; root cause: autotuning step bounds not clamped to the same validated ranges §16.4/§21.4 establish; debug via an out-of-validated-range alert on every autotuning decision; recovery: clamp autotuning to the validated envelope, require explicit operator override to exceed it.

⬜ Phase 11 — Conformance Suite & Performance Hardening §23

Objectives

Complete genesis-conformance: the deterministic sim harness (§7's debugging methodology) asserting all fourteen invariants (I1–I14) per generation, the golden-fixture runner aggregating every phase's §N.5 fixtures, and CI-gated performance-regression enforcement against the §4/§30 targets.

Deliverable

genesis-cli conformance run executes the full golden-fixture + sim-harness + property-test suite and prints a pass/fail matrix keyed by invariant ID and fixture name; make perf-gate runs the benchmark suite against the §30 targets locally, matching CI.

Acceptance

100% of every N.5 fixture across §12–§22 passes under golden.rs (zero silently-skipped fixtures — a CI check asserts fixture-file-to-assertion coverage); the sim harness runs 10,000 simulated generations with zero I1–I14 assertion failures on the reference corpus; property tests execute at least 1,000,000 total cases across type-preservation and fitness-totality properties per CI run with zero counterexamples; perf-gate.yml catches a deliberately introduced 20% eval/s regression in fixtures/perf_regression_injected/ within one CI run.

Fixtures

fixtures/conformance_full_matrix.gnm — meta-fixture asserting every §12–§22 fixture file is registered and exercised; expected: 100% coverage, zero orphaned fixtures. fixtures/sim_invariant_sweep.gnm — 10,000-generation sim-harness run; expected: zero I1–I14 failures. fixtures/perf_regression_injected/ — a deliberately slowed sandbox-spawn path; expected: perf-gate.yml fails the build. fixtures/property_type_preservation_seed_corpus/ — seed corpus for the type-preservation property test; expected: zero counterexamples across 1,000,000 generated cases.

Pitfalls

Fixture coverage rot — manifestation: a new fixture is added to a phase's §N.5 list in the blueprint but never actually wired into golden.rs; root cause: no automated cross-check between documented fixtures and registered test cases; debug via the conformance_full_matrix meta-fixture (§23.5); signal: a fixture file present on disk but absent from the coverage report; recovery: CI fails the build on any fixture-registration gap, not just on fixture failure.

Property-test shrinking masking the true minimal counterexample — manifestation: a proptest failure reports an overly complex genome instead of proptest's shrunk minimal case; root cause: a custom Arbitrary impl for GenomeRecord that doesn't implement shrinking correctly for tree-shaped IR; debug via manually re-shrinking a reported failure; recovery: implement tree-aware shrinking (subtree removal before leaf mutation) rather than relying on proptest's default derive.

Sim harness diverging from the real generational loop's behavior — manifestation: sim passes but production exhibits an invariant violation the simulator never caught; root cause: the mocked sandbox/clock omits a real-world code path (e.g. actual Wasmtime fuel-exhaustion timing jitter); debug via comparing sim-harness assertions against production telemetry for the same invariant; recovery: periodically replay a real captured production trace through sim to detect simulator/reality drift, don't trust the simulator as the sole conformance gate indefinitely.

Perf-gate false positives from noisy CI runners — manifestation: perf-gate.yml flags a regression that isn't real, blocking unrelated PRs; root cause: shared/noisy CI hardware (ADR-16 hosted runners) without statistical tolerance banding; debug via historical benchmark variance analysis (docs/performance/); recovery: require N repeated benchmark runs with a median-based comparison and a documented tolerance band before failing the gate, never a single noisy sample.
