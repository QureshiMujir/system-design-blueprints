32. Mental Models & First Principles

MM1. Evolution optimizes the measured proxy, never the intent — every fitness function is a specification bug waiting to be exploited. Predicts: a candidate will eventually find the cheapest path to a high score that isn't the intended behavior. Bug class without it: shipping a .gns spec with a narrow case set and being surprised by a gaming candidate (§14.6). Resolved by: §14 (penalty design), §28 (held-out case discipline).

MM2. A sandbox is only as trustworthy as its smallest unaudited surface — the arbiter must be smaller and safer than what it arbitrates (Provos 2003). Predicts: the escape that eventually happens comes from an overlooked import or syscall, not the audited main path. Bug class without it: adding a convenience host-function "just for debugging" that becomes T7/T8. Resolved by: §13 (sandbox contract), §24 (threat model).

MM3. Reproducibility is a property of the write path, not an afterthought bolted onto the read path — determinism must be designed into every RNG derivation and reduction order from day one. Predicts: retrofitting determinism onto an already-parallel reduction is far more expensive than building it in. Bug class without it: chasing an unreproducible replay divergence months into a run (§18.6 FM-9). Resolved by: §6 (P1), §18 (lineage/replay).

MM4. Type preservation is a search-space design decision, not a safety check bolted onto operators — it determines which mutations are even reachable. Predicts: an operator that "falls back to no-op too often" signals a type-lattice gap, not a bug in the fallback logic itself. Bug class without it: chasing phantom operator bugs when the real issue is insufficient terminal-type coverage (§15.6, §17.6). Resolved by: §8 (domain model), §15/§17.

MM5. An archive beats a single "best-ever" record because premature convergence is a property of the whole population's diversity, not any one genome's score. Predicts: fitness-only elitism will eventually plateau on deceptive landscapes long before a quality-diversity archive does. Bug class without it: diagnosing a stalled search purely from a flat best-fitness line, missing a healthy-archive/dead-fitness split. Resolved by: §20 (archive), §25 (FM-8).

MM6. Bloat is not a bug, it is the null hypothesis — genetic programming grows code size by default absent an active counter-pressure (Langdon & Poli 2002). Predicts: any run without parsimony pressure from generation 0 will bloat, regardless of problem domain. Bug class without it: adding parsimony only after observing bloat, having already paid the compile-time cost of oversized genomes. Resolved by: §21 (P8).

MM7. Backpressure converts overload into latency; unbounded queues convert overload into a crash later and worse. Predicts: a slow fitness oracle should show up as a slower generation cadence, never as scheduler OOM. Bug class without it: an unbounded channel that "worked fine" until one worker got slow enough to expose it (§19.6, P6). Resolved by: §19 (scheduler), §6 (P6).

MM8. A distributed system's correctness under retries is a property of idempotency keys, not of how rarely retries happen. Predicts: the retry path is exercised far less in testing than in production, so its correctness must be proven structurally (I14), not empirically. Bug class without it: double-counted fitness under a rare worker-restart race that testing never triggered. Resolved by: §19 (P14), §25 (FM-12).

MM9. Telemetry designed after the fact answers yesterday's incident, not tomorrow's — every invariant needs a paired signal before the code that could violate it ships (P11). Predicts: an incident without a corresponding counter/gauge will require a re-run to diagnose, burning hours a dashboard would have saved. Bug class without it: discovering mid-incident that the exact signal needed doesn't exist. Resolved by: §26 (operational readiness), §7 (debugging methodology).

MM10. A checkpoint is a cache of derivable state, not a second source of truth — lineage (I3) is the ground truth, snapshots are an optimization. Predicts: a cascading checkpoint-corruption incident is recoverable exactly because the lineage DAG independently reconstructs everything, just slower. Bug class without it: treating checkpoint loss as unrecoverable data loss instead of a performance regression in recovery. Resolved by: §22 (P9), §25 (FM-4).

Required reading (§5)

Books

  • Koza, J. (1992). Genetic Programming: On the Programming of Computers by Means of Natural Selection. MIT Press. Extract: tree-based genome representation, the four core operators (reproduction, crossover, mutation, permutation), fitness-proportionate selection. Applied in §8, §15 (Phase 3).
  • Holland, J. (1975). Adaptation in Natural and Artificial Systems. University of Michigan Press. Extract: the schema theorem, building-block hypothesis, population-level selection pressure math. Applied in §16 (Phase 4).
  • Goldberg, D. (1989). Genetic Algorithms in Search, Optimization, and Machine Learning. Addison-Wesley. Extract: selection-pressure tuning (tournament vs. proportionate), premature-convergence diagnosis. Applied in §16 (Phase 4), §25.
  • Langdon, W. & Poli, R. (2002). Foundations of Genetic Programming. Springer. Extract: bloat theory (why average program size grows without bound), size-fair operators, formal crossover/mutation locality analysis. Applied in §21 (Phase 9).
  • Banzhaf, W., Nordin, P., Keller, R., Francone, F. (1998). Genetic Programming: An Introduction. Morgan Kaufmann. Extract: strongly-typed GP representations and closure-property tradeoffs. Applied in §8.
  • Poli, R., Langdon, W., McPhee, N. (2008). A Field Guide to Genetic Programming. Lulu (open-access). Extract: practical operator-rate tuning heuristics, population sizing rules of thumb. Applied in §22 (Phase 10).

Papers

  • Weimer, W. et al. (2009). "Automatically Finding Patches Using Genetic Programming." ICSE 2009. Contribution: GP applied to real-world program repair over an existing codebase's AST. Applied in §8, §36.
  • Le Goues, C. et al. (2012). "GenProg: A Generic Method for Automatic Software Repair." ICSE 2012. Contribution: fitness = weighted test-suite pass rate; repair search over statement-level edits. Applied in §14 (Phase 2).
  • Mouret, J-B. & Clune, J. (2015). "Illuminating Search Spaces by Mapping Elites." Contribution: MAP-Elites — a behavior-space grid archive replacing scalar-fitness elitism. Applied in §20 (Phase 8).
  • Lehman, J. & Stanley, K. (2011). "Abandoning Objectives: Evolution Search by Novelty Alone." Evolutionary Computation journal. Contribution: novelty search as an alternative selection pressure to objective fitness. Applied in §20 (Phase 8).
  • Real, E. et al. (2019). "Regularized Evolution for Image Classifier Architecture Search." AAAI 2019. Contribution: age-based (oldest-out) replacement — regularized evolution — as a steady-state alternative to fitness-only replacement. Applied in §16 (Phase 4), §33.
  • Real, E. et al. (2020). "AutoML-Zero: Evolving Machine Learning Algorithms From Scratch." ICML 2020. Contribution: evolving whole programs (not just hyperparameters) from primitive instruction sets. Applied in §8, §33.
  • Romera-Paredes, B. et al. (2024). "Mathematical Discoveries from Program Search with Large Language Models." Nature. Contribution: FunSearch — LLM-proposed genome seeding combined with an evaluator/evolutionary loop. Applied in §36.
  • Fortin, F-A. et al. (2012). "DEAP: Evolutionary Algorithms Made Easy." JMLR. Contribution: scriptable, composable operator/toolbox architecture for evolutionary computation. Applied in §9 (ADR-06), §33.
  • Provos, N. (2003). "Improving Host Security with System Call Policies." USENIX Security. Contribution: syscall-policy sandboxing lineage (systrace) underlying seccomp-bpf allowlisting. Applied in §13 (Phase 1), §24.

Reference Implementations

  • DEAP — github.com/DEAP/deap — dirs deap/algorithms.py, deap/tools/. Lesson: composable, registry-based operator toolbox (toolbox.register). Pitfall not to copy: DEAP's fitness caching relies on Python object identity — Genesis needs content-addressed hashing (I11) instead of identity. Applied in §9 (ADR-06).
  • GenProg (squaresLab) — github.com/squaresLab/GenProg — dirs src/repair.ml. Lesson: statement-level edit operators over an existing AST, test-suite-weighted fitness. Pitfall not to copy: GenProg's original edit representation is untyped statement lists — Genesis requires closure-typed IR nodes (§8) so crossover stays well-typed. Applied in §14 (Phase 2), §17 (Phase 5).
  • PyGAD — github.com/ahmedfgad/GeneticAlgorithmPython — dirs pygad/pygad.py. Lesson: simple generational-loop reference for selection/crossover/mutation wiring. Pitfall not to copy: PyGAD mutates in place on a flat gene vector — not applicable to tree-shaped, type-constrained IR. Applied in §16 (Phase 4).
  • gVisor — github.com/google/gvisor — dirs runsc/, pkg/sentry/. Lesson: user-space kernel intercepting syscalls as a sandbox trust boundary. Pitfall not to copy: gVisor's per-syscall overhead is too high for the 800 eval/s target (§4) as a primary path — used only as the OCI fallback (ADR-03). Applied in §13 (Phase 1).
  • Wasmtime — github.com/bytecodealliance/wasmtime — dirs crates/wasmtime/src/store.rs, crates/environ/src/fuel.rs. Lesson: fuel-metering API gives deterministic, preemptible CPU accounting without OS-thread preemption. Pitfall not to copy: Wasmtime's default Store is not cheaply reusable across threads — the sandbox pool (§13) must pool Engine instances, not Store instances. Applied in §13 (Phase 1).

38. Glossary

  • Genome — a typed AST (§8) representing one candidate program; content-addressed by BLAKE3 hash (P4).
  • IR node — one Node enum variant (§11: IntLit, Call, If, Let, etc.).
  • Arity — the fixed number of child expressions a node type accepts (§8 typed AST node table).
  • Mutation operator — a MutationOperator (§11) trait impl producing one offspring from one parent (§15).
  • Crossover — subtree exchange between two parents producing one or two offspring (§17, Koza 1992).
  • Type preservation — the guarantee (P5, I7) that every operator output is well-typed or a documented fallback, never ill-typed.
  • Locality — how far from the mutation/crossover point a genome's behavior is expected to change (§8 operator catalogue).
  • Fitness DSL — the .gns declarative specification language compiled to an EvaluationPlan (§14).
  • Fitness landscape — the mapping from genome to fitness across the search space, referenced when discussing deceptiveness/premature convergence.
  • Selection pressure — the degree to which higher-fitness genomes are favored for reproduction (§16, Goldberg 1989).
  • Tournament selection — sampling k genomes and picking the best as a parent (§16).
  • Elitism — never letting the best-known solution be lost across generations (contrasted with archive-based approaches, P7).
  • Bloat — genome size growth unconnected to fitness gain (Langdon & Poli 2002, §21).
  • Parsimony pressure — a size-adjusted fitness term counteracting bloat (P8, §21).
  • Novelty search — selection driven by behavioral distinctiveness rather than objective fitness (Lehman & Stanley 2011, §20).
  • Behavioral descriptor — the low-dimensional feature vector extracted from a candidate's execution, used to place it in the MAP-Elites grid (§20).
  • MAP-Elites cell — one grid coordinate in the behavior-space archive, holding its best-known occupant (§11, §20).
  • Island model — a population-sharding scheme running independent sub-populations with periodic migrant exchange (§31, not built in Phases 0–11).
  • Lineage — the hash-DAG of parent→child mutation/crossover edges (I11, §18).
  • Seed determinism — the guarantee that a fixed seed plus config reproduces a bit-identical run (P1, I1).
  • Sandbox — the WASM/OCI execution boundary every candidate runs inside (P2, §13).
  • Fuel metering — Wasmtime's deterministic, preemptible CPU-accounting mechanism (ADR-02, §13).
  • Exit taxonomy — the closed set of sandbox outcomes (Ok, Trap, FuelExhausted, etc., §11).
  • Penalty mapping — the total-fitness function assigning a finite score to every crash/timeout/error (P3, I4, §14).
  • Purity check — the static-analysis pass rejecting a .gns spec that could reference host-observable state (I13, §14).
  • Content addressing — identifying a genome or spec by the hash of its structure, not an arbitrary ID (P4).
  • Idempotency key — the (genome hash, generation, attempt) triple preventing duplicate job application (I14, §19).
  • Backpressure — throttling dispatch under load instead of growing an unbounded queue (P6, §19).
  • Credit — a worker's advertised concurrent-evaluation capacity in the scheduler's flow-control scheme (§19).
  • Dedup ledger — the scheduler's idempotency-key tracking store (§19).
  • Checkpoint — a durable, crash-consistent snapshot of run state enabling resume (I10, §22).
  • Autotuning — bounded, checkpoint-boundary-gated adjustment of operator/selection/parsimony parameters (§22).
  • Replay — deterministic reconstruction of a run from seed plus lineage (§18).
  • Conformance suite — the golden-fixture, sim-harness, and property-test aggregate verifying every phase's fixtures (§23).
  • Golden fixture — a named, version-controlled input/expected-output pair used for regression testing (§23).
  • Property test — a test asserting an invariant holds across randomly generated inputs, not one example (ADR-14, §28).
  • Differential test — a test comparing Genesis's behavior against a canonical external definition (e.g. Koza 1992's crossover semantics, §17).
  • Fuzzing — automated adversarial input generation targeting parser/grammar robustness (ADR-15, §28).
  • Regularized evolution — age-based, oldest-out steady-state replacement (Real et al. 2019, §16).
  • Steady-state replacement — a replacement policy that replaces individuals continuously rather than whole-generation-at-once (§8, §11 ReplacementPolicy).
  • Generational replacement — a replacement policy that replaces the entire population each generation (§8, §11).
  • Archive coverage — the fraction of MAP-Elites grid cells currently occupied (§20).
  • Coverage plateau — a stall in archive coverage growth despite continued generations, a premature-convergence-adjacent signal (§20.9).
  • Stale-worker poisoning — a delayed evaluation result being incorrectly applied after its job was reassigned (§19.6).
  • Sandbox escape — a candidate genome executing code outside its intended sandbox boundary (T1, I2).
  • Held-out case — a .gns test case withheld from a candidate's visible scoring to detect fitness gaming (§14.6).
  • Fitness gaming — a candidate exploiting a narrow fitness specification rather than solving the intended problem (MM1, §14.6).
  • Type-checker gate — the ingest-time check rejecting any ill-typed genome before it can enter a job (I5, §12).
  • Depth-search budget — the bounded retry count for finding a type-compatible mutation/crossover target (§15, §17).
  • Size-fair mutation — a bloat-control operator that replaces a subtree with a size-matched substitute (Langdon & Poli 2002, §15).
  • WAL — write-ahead log; the lineage edge log's durability mechanism ahead of periodic compaction (ADR-23, §18).
  • Behavioral diversity — the spread of a population across the behavior-descriptor space, the object of study for novelty search and MAP-Elites alike (§20).
  • Closure property — the strongly-typed-GP requirement (Banzhaf et al. 1998) that every operator output remain within the well-typed language of the IR (§8, P5).
  • Regularized evolution age-window — the sliding cohort of oldest surviving individuals eligible for steady-state replacement (§16, Real et al. 2019).
  • Reservoir sampling — the bounded-size, age/novelty-weighted eviction scheme keeping the novelty-comparison archive from growing unbounded across a multi-week run (§20.6).
