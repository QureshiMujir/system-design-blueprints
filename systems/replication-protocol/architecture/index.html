Six properties, referenced throughout: (1) the primary's WAL is the single source of truth for all three consumer kinds (physical, logical, PITR) — they share the flush-LSN watermark and the segment format (I1, I2). (2) walsender/walreceiver are protocol- symmetric; a cascading replica cannot tell it is not talking to the primary. (3) replication slots (§15) are the durability contract preventing WAL truncation ahead of a slow consumer (I5, I6). (4) TimelineId is monotonic 4-byte state; every uncontrolled promotion bumps it (I4); a replica applying from a stale timeline is the divergence bug (§19). (5) the failover plane is operator-driven by default (ADR-14); the building blocks are automated, the policy (when to call promote()) is not. (6) trust boundaries: primary↔network (mTLS, ADR-12), network↔wire (CRC32C, I7), operator↔failover plane (explicit acknowledgement, I15) — detailed in the Threat Model (§23).

8. Domain Model / Protocol / Data Model

8.1 WAL record layout (physical)

XLogRecord (variable length):
  ┌─────────┬─────────┬──────┬──────┬──────────┬──────────┬───────────┬─────────┐
  │ lsn:u64 │ xid:u64 │rmid:u8│info:u8│ tl:u32  │prev_lsn:u64│ data:var │crc32c:u32│
  └─────────┴─────────┴──────┴──────┴──────────┴──────────┴───────────┴─────────┘
    8 bytes   8 bytes   1B     1B      4 bytes    8 bytes     N bytes    4 bytes

rmid (resource manager ID) selects the decoder: RMID_HEAP/RMID_HEAP2 (row-level data), RMID_XACT (begin/commit/abort), RMID_RELATION (DDL/relation metadata), RMID_LOGICAL_MSG (application-level pg_logical_emit_message-style payload). prev_lsn chains records within one timeline for crash-consistency verification (I1, I3).

8.2 On-wire frame layout (transport)

Frame:  [ kind:u8 ][ length:u32 BE ][ payload: length bytes ][ crc32c:u32 BE ]
        MAX_PAYLOAD = 16 MiB (fragmented above at the application layer, §11.10)

kind discriminates the WireMessage variant (§11.5): XLogData, KeepAlive, StandbyStatusUpdate, HotStandbyFeedback, LogicalEvent. CRC is computed over kind || length || payload (I7); a mismatch disconnects the stream (§13.7).

8.3 Streaming-replication command grammar (EBNF)

command       = create_slot | drop_slot | start_replication | advance_slot ;
create_slot   = "CREATE_REPLICATION_SLOT" , slot_name , kind ;
kind          = "PHYSICAL" | "LOGICAL" , plugin_name ;
drop_slot     = "DROP_REPLICATION_SLOT" , slot_name ;
start_replication
              = "START_REPLICATION" , "SLOT" , slot_name , kind , start_lsn ;
advance_slot  = "ADVANCE_REPLICATION_SLOT" , slot_name , target_lsn ;
slot_name     = identifier ;
plugin_name   = identifier ;
start_lsn     = lsn_literal ;
target_lsn    = lsn_literal ;
lsn_literal   = hex_u32 , "/" , hex_u32 ;      (* e.g. "0/1A2B3C4D" *)

Mirrors the PostgreSQL Streaming Replication Protocol grammar (§5 RFCs). replctl (§11 repo layout) is the CLI front-end that emits these commands over repl-net.

8.4 Walsender / walreceiver state machine

State On event Next state Emits
IDLE client connects + slot exists STARTED —
STARTED START_REPLICATION SLOT <name> <kind> <lsn> STREAMING first XLogData or KeepAlive
STREAMING WAL available STREAMING XLogData { start_lsn, current_lsn, records }
STREAMING keepalive-interval elapsed, no data STREAMING KeepAlive { current_lsn, request_reply }
STREAMING StandbyStatusUpdate received STREAMING slot advance() call (§15.2)
STREAMING disconnect / CRC failure (I7) IDLE slot remains ACTIVE→INACTIVE (§15.1)

8.6 Malformed-input example

A frame with length = 0xFFFFFFFF (exceeds MAX_PAYLOAD, §11.10) is rejected by the codec before allocation — the decoder validates length ≤ MAX_PAYLOAD prior to buffering, never allocates on unchecked attacker/corruption-controlled length (mitigates §23 T3/T7). A frame whose trailing CRC32C does not match its kind||length||payload is rejected per I7 and the connection is torn down; received_lsn is not advanced.

8.7 Failure-path example

Walreceiver crashes mid-apply, after received_lsn advanced but before flushed_lsn reached the same record (violating the ordering P3/I2 would demand on the primary side, but is expected transient state on a standby). On restart, WalApplier (§13.4) resumes from the standby's own last-fsynced flushed_lsn, re-reads and re-applies any records between flushed_lsn and the local WAL's tail (idempotent apply, §13.4 pitfalls), recomputes replay_lsn, and reconnects with START_REPLICATION SLOT <name> PHYSICAL <flushed_lsn> — no double-counted bytes are requested from the primary (§13.5).

8.9 Consistency semantics

  • Physical: byte-identical replay ⇒ read-after-write on the standby is exact once replay_lsn ≥ the commit's LSN ("lag-bound consistency", ADR-16). Strict linearizable reads require routing to the primary.
  • Logical: row-level equivalence, not byte-identical; ordering guarantee is per-table commit order (I3), cross-table ordering is by commit LSN, not by table-scan order.
  • Replication modes (§11.4): Async (no wait), SyncReceive (wait for received_lsn ≥ commit_lsn), SyncReplay (wait for replay_lsn ≥ commit_lsn, strictly stronger), Quorum(n) (wait for n acks, threshold floor(n/2)+1 default, P13).

Design principles (§6)

  • P1 — Physical and logical are different protocols; pick by use case. Physical serves HA/PITR; logical serves CDC/cross-version/heterogeneous sinks. Tradeoff: maintaining two pipelines costs code, but pretending one subsumes the other (Gray et al. 1996) costs correctness. Violate it and you get a "universal" replicator that is slow at HA and unsafe at CDC.
  • P2 — Sync trades latency for durability; async trades durability for latency; quorum trades both for availability. Default is async (ADR-04); sync/quorum are explicit opt-ins. Operational implication: a slot's mode is visible in replctl status; violating the default silently (advertising sync, acting async) is the #1 pitfall (§14.6).
  • P3 — The primary's local durability is unconditional (I2). WAL fsync precedes the primary's own commit ack; replication ack layers on top, never replaces it. Violating this reorders cause-before-effect and breaks every invariant downstream.
  • P4 — LSN is monotonic and never decreases anywhere (I1). A standby's flushed_lsn cannot exceed the primary's flush_lsn; a cascading replica's received_lsn cannot exceed its upstream's flush_lsn. Violation ⇒ divergence event (§19).
  • P5 — Timelines are 4-byte monotonic IDs; every uncontrolled promotion bumps one (I4). Generalizes Kafka KIP-101's leader-epoch fix for the high-watermark-truncation bug. Skip the bump and forked timelines are indistinguishable from normal catch-up.
  • P6 — Logical replication must treat DDL as a first-class event or it is wrong. A schema change the consumer never learns about is silent corruption (misread column types, phantom drops). Default policy is deny-by-default (ADR-09).
  • P7 — The output plugin is the sole contract for logical serialization. One WAL, many output formats (Avro default, JSON optional, protobuf stretch) behind one trait (§11.8). Violating this couples the decoder to a wire format and blocks future sinks.
  • P8 — Replication slots are the only thing preventing WAL truncation ahead of a slow consumer (I5, I6). Trade-off: an abandoned slot wedges disk; the mitigation is an explicit, alerted slot-timeout (ADR-18), never silent auto-drop.
  • P9 — Cascading replicas offload the primary but inherit lag additively. A third-level standby's lag is the sum of every hop's lag (§20.3); the monitoring surface must expose the whole chain, not just the immediate hop.
  • P10 — Failover is operator-driven by default; the library ships the primitives, not the policy (ADR-14). handover() (controlled) and promote() (uncontrolled) are library calls; when to call them is left to the orchestrator. Automating this without a consensus layer is split-brain bait (Gray et al. 1996; §23 T1).
  • P11 — Divergence after uncontrolled failover is detected, never silently prevented. Writes accepted by the old primary after the fault that triggered promotion are gone or must be manually merged; the detector (§19) refuses rejoin without explicit operator acknowledgement of the loss.
  • P12 — Lag is reported at all four points — send, receive, flush, replay — never fewer. A dashboard graphing only one lies about the system; the classic "40-minute unnoticed lag" bug is a monitoring bug, not a replication bug (§21.5).
  • P13 — Quorum-ack threshold defaults to floor(n/2)+1; sync-ack defaults to 1. Both survive exactly one host failure without data loss (DeCandia et al. 2007); both are explicit config, never silently widened or narrowed.
  • P14 — On-wire framing is explicit length-prefixed binary with a CRC32C trailer. Relying on the transport for framing fails in production (partial reads, TCP coalescing); the codec is the contract, not the socket.
  • P15 — TLS is non-optional for any cross-DC link. Same-host/rack replication may run plaintext for latency; anything crossing a public or shared network segment uses rustls with mTLS (ADR-12) — violating this is an unauthenticated-primary attack surface (§23 T3).
