Decisions (§9) · 25 ADRs

ADR-01

Core language

Chosen

Rust 1.78+, edition 2021

Rejected

C, C++, Go, Zig

When the rejected choice is right

Go wins for a CDC-consumer-only shim where GC pauses don't touch the sync-ack path

Why: Borrow checker eliminates buffer-aliasing bugs endemic to C replication code (§1)

ADR-02

Async runtime

Chosen

Tokio 1.x

Rejected

async-std, smol, hand-rolled epoll

When the rejected choice is right

smol wins for an embedded single-thread CLI tool with no need for a work-stealing scheduler

Why: Ecosystem maturity: rustls, tonic, tokio-util::codec all integrate cleanly

ADR-03

WAL on-disk format

Chosen

Consumed from Blueprint #69 (not reinvented)

Rejected

Invent a new WAL format here

When the rejected choice is right

Inventing a new format wins only if #69's format cannot express logical-decoding metadata — tracked as a migration ADR, not taken here

Why: Two independently-versioned WAL formats for one storage engine is a maintenance and compatibility hazard

ADR-04

Default replication mode

Chosen

Async

Rejected

Sync, SemiSync, Quorum as default

When the rejected choice is right

Sync-by-default wins for a financial ledger where every read-replica query must reflect the last commit

Why: Typical workload (eventually-read replica) tolerates async lag; sync costs latency unconditionally

ADR-05

Sync-mode default ack threshold

Chosen

1 standby

Rejected

0 (no real semantics), 2+

When the rejected choice is right

Threshold 2+ wins once a single-sync-standby SLA has been breached by a correlated dual-host failure in practice

Why: Textbook minimum that survives exactly one host failure with zero data loss

ADR-06

Quorum-mode default ack threshold

Chosen

floor(n/2)+1

Rejected

Simple majority of all nodes incl. non-voters, unanimous

When the rejected choice is right

Unanimous wins for a 3-node cluster where any single lost ack must halt writes (rare; extreme durability regime)

Why: Tolerates the largest minority that still leaves a majority for the next round (DeCandia et al. 2007)

ADR-07

Slot durability

Chosen

On-disk, atomic rename + fsync

Rejected

In-memory only, periodic snapshot

When the rejected choice is right

Periodic-snapshot wins on constrained embedded devices where fsync-per-advance exceeds the flash write budget

Why: A slot crash losing confirmed_flush_lsn equals an undetected backup loss (I5)

ADR-08

Default logical output format

Chosen

Avro

Rejected

JSON, Protobuf

When the rejected choice is right

JSON wins for a human-debugging consumer or a schema-less document sink

Why: Avro carries schema; JSON loses numeric precision/timestamp fidelity (Debezium precedent)

ADR-09

DDL handling policy

Chosen

Deny-by-default (AllowAdditive default policy)

Rejected

Silent skip, AllowAll default

When the rejected choice is right

AllowAll wins when every downstream consumer is known to handle arbitrary schema drift (rare; internal tooling only)

Why: Silent DDL skip is the #1 logical-replication corruption bug (P6)

ADR-10

TimelineId width

Chosen

4-byte monotonic integer

Rejected

8-byte, UUID

When the rejected choice is right

8-byte wins only for a simulated environment doing millions of synthetic failovers/sec in a fuzz harness

Why: Matches Postgres convention; 4 billion failovers exceeds any deployment's operational lifetime

ADR-11

On-wire framing

Chosen

Length-prefixed binary + CRC32C trailer

Rejected

Rely on transport framing, Protobuf-delimited

When the rejected choice is right

Protobuf-delimited wins if the whole stack already standardizes on gRPC/protobuf end-to-end

Why: Explicit framing survives partial reads/TCP coalescing without resync (P14)

ADR-12

Transport security

Chosen

rustls + mTLS mandatory cross-DC

Rejected

Plaintext everywhere, IPsec-only

When the rejected choice is right

Plaintext wins for same-rack same-trust-zone replication where TLS CPU cost dominates at >1 GB/s

Why: Explicit application-layer auth independent of network topology (P15)

ADR-13

On-wire compression

Chosen

Streaming zstd level 3

Rejected

lz4, no compression

When the rejected choice is right

No-compression wins on a >10 GbE same-DC link where CPU is the bottleneck, not bandwidth

Why: 3–5x compression on WAL streams at negligible CPU cost (§33 #12)

ADR-14

Automatic failover

Chosen

Operator-driven; library ships primitives only

Rejected

Fully automatic failover with built-in leader election

When the rejected choice is right

Automatic wins once a real consensus layer (Blueprint #93/#37) sits above this library

Why: Auto-failover without a consensus layer is split-brain bait (Gray et al. 1996, P10)

ADR-15

Uncontrolled-failover divergence handling

Chosen

Detect + flag; manual reconciliation

Rejected

Auto-rebase, discard silently

When the rejected choice is right

Auto-rebase wins in a disposable-replica fleet (e.g., stateless read cache) where lost writes are by design irrelevant

Why: Auto-discard destroys forensic evidence and hides data loss from the operator (P11)

ADR-16

Standby-read consistency model

Chosen

Lag-bound consistency (replay_lag ≤ L_max)

Rejected

Strict serializable reads on replicas

When the rejected choice is right

Strict serializable wins when the application cannot tolerate any staleness — route reads to primary instead

Why: Strict reads require routing to primary or a consensus read-index, out of scope here

ADR-17

Licensing

Chosen

Apache-2.0 + MIT dual

Rejected

GPL, proprietary

When the rejected choice is right

GPL wins if the project explicitly wants to force downstream disclosure (not a goal here)

Why: Standard Rust-ecosystem dual-license; unblocks embedding in proprietary datastores

ADR-18

Replication-slot timeout

Chosen

Configurable, default 24 h since last advance

Rejected

No timeout, 1 h fixed

When the rejected choice is right

1h fixed wins on a high-write-rate primary where 24h of backlog would exhaust disk (§33 #4)

Why: 24h balances "catch a stuck consumer" against "don't wedge a brief maintenance window" (P8)

ADR-19

Cascading-replica depth limit

Chosen

4 (primary + 3 hops)

Rejected

Unlimited, 1 (no cascading)

When the rejected choice is right

Unlimited wins in a strict fan-out-only topology where lag budget is generous (e.g., analytics-only replicas)

Why: Each hop adds lag additively (P9); 4 is the field-observed sweet spot

ADR-20

Jepsen harness

Chosen

Mandatory CI gate

Rejected

Optional/manual only

When the rejected choice is right

Manual-only wins for a prototype/spike branch not headed to production

Why: Split-brain prevention (I15) is the load-bearing safety property; must be continuously verified

ADR-21

Physical-protocol wire compatibility

Chosen

PostgreSQL XLog-compatible framing option

Rejected

Fully custom wire format only

When the rejected choice is right

Fully custom wins when there is no requirement to interoperate with an existing Postgres fleet

Why: Enables interop with real pg_basebackup for bootstrap (§26)

ADR-22

Logical output compatibility

Chosen

Optional Debezium-compatible output mode

Rejected

Custom-only schema envelope

When the rejected choice is right

Custom-only wins when no downstream Debezium consumer exists and envelope overhead must be minimized

Why: Lets the library serve as a drop-in source for existing Debezium consumers (§26)

ADR-23

Credential handling

Chosen

zeroize on drop for cached auth material

Rejected

Plaintext in memory, OS keychain only

When the rejected choice is right

OS-keychain-only wins on a platform where zeroize cannot reach hardware-backed key material anyway

Why: mTLS private keys and replication passwords must not linger in memory after use (§23 T3)

ADR-24

Conformance-suite gating

Chosen

Gates Done/Sealed status transitions

Rejected

Advisory-only (non-blocking)

When the rejected choice is right

Advisory-only wins during early Phase-0/1 spike work before any release gate exists

Why: Byte-for-byte physical equivalence + logical row-equivalence + Jepsen are non-negotiable release gates (§27)

ADR-25

Log-only (Aurora-style) architecture

Chosen

Deferred, not built

Rejected

Build now as a first-class mode

When the rejected choice is right

Building it now wins if the primary deployment target is a disaggregated-storage cloud environment from day one

Why: Fundamentally different architecture (shared storage layer), not a parameterization of streaming replication (§32, §35.4)

Roads not taken (§35)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Multi-primary (active-active) replication instead of single-leader streaming

   Client A ──▶ Primary A ◀──sync/async──▶ Primary B ◀── Client B
                   │  conflict resolution (LWW / vector clock / CRDT)   │
                   └────────────────────────────────────────────────────┘

Regime where it wins: multi-region write locality where cross-region write latency to a single leader is unacceptable and the application can tolerate (or resolve) write conflicts. Real system: MySQL Group Replication / Galera Cluster (certification- based conflict detection). Why rejected here: this design's whole invariant set (I1–I15) assumes a single writer per timeline; adding true multi-writer requires a conflict- resolution layer with its own correctness model — explicitly Blueprint #99's territory (§1 non-goals), not a parameter on this design.

Consensus/Raft-replicated log instead of single-leader streaming + operator failover

   Client ──▶ [ Raft leader ] ──replicate(entry)──▶ [ Follower ] [ Follower ]
                    │  commit only after quorum ack; leader election built in
                    ▼
              Applied to state machine (this design's "apply path", §13.4, generalized)

Regime where it wins: environments requiring automatic leader election and split-brain- by-construction, where the write-latency cost of a quorum round-trip per entry is acceptable. Real system: etcd/raft, embedded in CockroachDB and etcd itself. Why rejected here: this design's ADR-14 deliberately keeps failover operator-driven because a consensus layer is a separate, substantial system (Blueprints #93 Paxos / #37 Raft) that this replication transport is designed to compose underneath, not reimplement — building it in here would duplicate #93/#37's entire scope.

Statement-based logical replication instead of row-based/physical-WAL-decoded

   Primary: executes "UPDATE t SET x = x + 1 WHERE id = 5"
       │  ships the STATEMENT, not the resulting row change
       ▼
   Replica: re-executes the statement locally (must be deterministic!)

Regime where it wins: workloads where statements are naturally small relative to the rows they affect (a bulk UPDATE touching a million rows ships as one statement, not a million row-events) — historically MySQL's original binlog default. Real system: MySQL's statement-based binlog format (the default before row-based became standard practice). Why rejected here: statement replication requires the statement to be deterministic on replay (no NOW(), no non-deterministic UDFs, no auto-increment divergence) — a correctness burden this design's row-based LogicalChangeEvent model (§11.6) avoids entirely by shipping the already-resolved result of execution, matching the row-based-binlog and Postgres logical-decoding precedent (§5 Ref-impl #1, #2).

Shared-log, log-is-the-database architecture instead of per-host replicated storage

   Primary ──▶ [ Shared durable log service (multi-AZ) ] ◀── Replica reads directly
                        no per-replica "apply to local page cache" step at all

Regime where it wins: cloud environments with disaggregated storage available, where per-replica apply CPU (this design's Phase 10, §22, fights hard to optimize) is the dominant bottleneck and can instead be eliminated by having every replica read from one shared, already-durable log. Real system: Amazon Aurora (§5 Papers #7, §32). Why rejected here: this design targets a portable, storage-agnostic replication library (§1) that must work against any storage backend (including Blueprint #69's own WAL) — committing to a shared multi-AZ log service is an infrastructure dependency this project does not control, and is explicitly deferred (ADR-25, PhaseDeferred("§32")) rather than built as this design's default.
