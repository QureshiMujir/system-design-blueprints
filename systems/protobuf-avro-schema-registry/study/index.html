30. Mental Models & First Principles

  • MM1 — Wire bytes are a contract, not an implementation detail. Compressed insight: every byte layout choice is a promise to every future consumer, forever, once the first message ships. Predicts: why P3 (determinism) and P10 (interop-first) are non-negotiable. Bug class avoided: "quick fix" encoding changes that silently break every existing consumer. Applies in §14/§16.
  • MM2 — Schema evolution is a partial order, not a timeline. Compressed insight: two schema versions can each be individually compatible with the latest without being compatible with each other. Predicts: why *_TRANSITIVE modes (I7) must check all pairs, not just chronological neighbors. Bug class avoided: a transitive-compatibility engine that only walks a linked list of "previous version." Applies in §17.
  • MM3 — Absence of an error is not proof of correctness. Compressed insight: a decoder that never panics on malformed input might be silently producing wrong values instead of failing loudly. Predicts: why differential testing (P10) is required alongside fuzzing (I8), not instead of it. Bug class avoided: shipping a "robust" decoder that's robustly wrong. Applies in §21.
  • MM4 — Canonicalization is the only place equivalence can be decided. Compressed insight: without a single normalized form, "are these two schemas the same" has no stable answer. Predicts: why P9 gates I5 — a fingerprint computed before canonicalization is fully deterministic is worthless. Bug class avoided: dedup logic that works by accident on today's test inputs. Applies in §15.
  • MM5 — Backpressure must be applied before the point of no return. Compressed insight: once a request is queued, the resource commitment (memory, a DB connection) is already made; shedding after that point wastes the resource anyway. Predicts: why P13 rejects at the concurrency-limiter layer, not inside the handler after work has started. Bug class avoided: an "overload protection" layer that itself becomes the OOM source. Applies in §19.
  • MM6 — A trait boundary is a promise about what varies, not just an abstraction. Compressed insight: SchemaStore (§11) exists specifically to make the storage backend swappable — if any caller ever imports rusqlite directly, the boundary has already failed. Predicts: why P8 is enforced by an integration-test suite run against every implementation, not by convention. Bug class avoided: a "pluggable" architecture that's pluggable in name only. Applies in §18.
  • MM7 — Monotonicity is easier to prove than to patch on afterward. Compressed insight: I6's SchemaId monotonicity is trivial if the counter is the database's own primary key, and a significant redesign if bolted on after the fact with a separate counter. Predicts: why 18.6's "duplicate ID after crash" pitfall exists specifically for designs that separate the counter from the durable write. Applies in §18.
  • MM8 — Fixtures encode institutional memory; fuzzers discover it. Compressed insight: a fuzz corpus without fixture promotion (P14) forgets every bug the moment CI clears the crash directory. Predicts: why 21.4's acceptance criteria explicitly check "every 90-day-old crash has a fixture," not just "current fuzz run is clean." Applies in §21.

5. Required Reading

Books

  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 4 Encoding and Evolution: schema evolution, wire-format tradeoffs, forward/backward compatibility framing; applied in §17 and §25.
  • Database Internals — Alex Petrov (2019), Part I storage-engine chapters: varint tradeoffs, page layout, write amplification; applied in §14 and §18.
  • Crafting Interpreters — Robert Nystrom (2021), Scanning and Parsing Expressions chapters: recursive-descent architecture, error recovery, span tracking; applied in §13.
  • Engineering a Compiler — Keith Cooper & Linda Torczon (2011, 2nd ed.), ch. 2 lexical analysis: DFA-based scanner design informing token classification; applied in §13.
  • Site Reliability Engineering — Betsy Beyer, Chris Jones, Jennifer Petoff, Niall Murphy (2016), monitoring chapters: SLO-driven telemetry design; applied in §19 and §24.
  • Release It! — Michael T. Nygard (2018, 2nd ed.), stability-patterns chapters (circuit breaker, bulkhead): informs the concurrency-limit and load-shed design; applied in §19.
  • The Rust Programming Language — Steve Klabnik & Carol Nichols (2019), ch. 10 traits, ch. 15–16 smart pointers/concurrency: informs the SchemaStore trait and Arc-shared IR design; applied in §11 and §18.

Papers

  • "Time, Clocks, and the Ordering of Events in a Distributed System" — Leslie Lamport, 1978, Communications of the ACM: causal-ordering model → schema version ordering must be a partial order, not wall-clock time; applied in §17.
  • "In Search of an Understandable Consensus Algorithm" — Diego Ongaro & John Ousterhout, 2014, USENIX ATC: Raft leader-election/log-replication model → basis for the rejected distributed-registry alternative; applied in §34.
  • "The Google File System" — Sanjay Ghemawat, Howard Gobioff, Shun-Tak Leung, 2003, SOSP: append-only replicated-log model → informs single-writer-vs-replicated storage tradeoffs; applied in §18.
  • "Kafka: a Distributed Messaging System for Log Processing" — Jay Kreps, Neha Narkhede, Jun Rao, 2011, NetDB workshop: log-compacted-topic-as-source-of-truth pattern → contrasted against this project's SQLite-backed store; applied in §31.
  • "The Design and Implementation of a Log-Structured File System" — Mendel Rosenblum, John K. Ousterhout, 1991, ACM TOCS: write-amplification/compaction tradeoffs → informs WAL checkpoint sizing; applied in §18.
  • "Dynamo: Amazon's Highly Available Key-value Store" — Giuseppe DeCandia et al., 2007, SOSP: eventual-consistency/quorum-replication tradeoffs → basis for the rejected multi-region registry alternative; applied in §34.
  • "Bigtable: A Distributed Storage System for Structured Data" — Fay Chang et al., 2006, OSDI: sorted, versioned-record storage model → informs the subject/version index design; applied in §18.
  • "Zanzibar: Google's Consistent, Global Authorization System" — Ruoming Pang et al., 2019, USENIX ATC: relationship-based authorization model → informs the deferred multi-tenant ACL design; applied in §19.
  • "Schema Evolution in Avro, Protocol Buffers and Thrift" — Martin Kleppmann, 2012, widely-cited research note: cross-system compatibility-rule comparison → direct basis for §17's BACKWARD/FORWARD/FULL rule table; applied in §17.

Reference Implementations

  • protocolbuffers/protobuf — study src/google/protobuf/wire_format_lite.cc: canonical wire-tag encode/decode reference and packed-repeated layout; pitfall: do not copy its macro-heavy C++ dispatch, port the algorithm not the macros; applied in §14.
  • tokio-rs/prost — study prost/src/encoding.rs: idiomatic Rust varint/tag encoding shapes; pitfall: prost code-generates at build time from .proto, this project parses at runtime — don't copy its build.rs codegen pattern; applied in §13.
  • apache/avro (Java) — study lang/java/avro/src/main/java/org/apache/avro/Schema.java: Parsing Canonical Form and fingerprint algorithm; pitfall: do not copy its mutable, in-place-editable Schema object graph — keep the IR immutable; applied in §15.
  • confluentinc/schema-registry — study core/src/main/java/io/confluent/kafka/schemaregistry/CompatibilityChecker.java: exact BACKWARD/FORWARD/FULL/TRANSITIVE semantics and REST contract; pitfall: do not copy its legacy ZooKeeper leader-election path, deprecated upstream; applied in §17.
  • apache/avro-rs (published as apache-avro) — study avro/src/decode.rs: Rust reader/writer schema-resolution logic; pitfall: do not copy its dynamically-typed Value dispatch into this project's static SchemaKind path; applied in §16.
  • tower-rs/tower — study tower/src/limit: concurrency-limit and load-shed middleware shape; pitfall: do not adopt its generic Service wrapping wholesale, adapt only the limiter/timeout layers; applied in §19.

RFCs / Specifications

  • RFC 9110 §9 — HTTP Semantics, method definitions: pins which registry verbs must be idempotent (PUT on config) versus not (POST on version registration); applied in §19.
  • RFC 8259 §7 — The JSON Data Interchange Format, string/number grammar: pins Avro schema JSON parsing edge cases (escaped unicode, number precision); applied in §15.
  • RFC 7231 §6 — HTTP/1.1 Semantics and Content, status-code registry: pins status-code choice for compatibility-rejection responses (409 vs 422); applied in §19.
  • RFC 6902 §4 — JavaScript Object Notation (JSON) Patch, operation semantics: informs the registry config PATCH endpoint's partial-update contract; applied in §19.

Glossary (§36) · 48 terms · site-wide glossary

Varint
variable-length base-128 integer encoding used by both the protobuf tag and Avro int/long wire representations.
ZigZag
signed-to-unsigned integer mapping used for sint32/sint64 so small negatives stay short.
Wire Type
the 3-bit protobuf field category (Varint, 64-bit, Length-delimited, 32-bit).
Wire Tag
(field_number << 3) | wire_type, the leading varint of every protobuf field.
Schema Evolution
the practice of changing a schema over time while preserving readability of historical data.
Compatibility
the ability of a schema to read data written under a different schema version.
Subject
a registry namespace under which schema versions are registered sequentially.
Fingerprint
a deterministic hash of a schema's canonical form, used for identity and dedup.
Schema IR
the unified SchemaKind intermediate representation both proto and Avro compile into.
Packed Field
protobuf's compact repeated-scalar encoding (one length-delimited run, not one tag per element).
Union
an Avro field that may hold a value of one of several declared types.
Canonical Form
the normalized, alias-stripped, fully-qualified representation of a schema.
Reader Schema
the schema a consumer uses to decode data.
Writer Schema
the schema a producer used to encode data.
Descriptor
the lowered, typed representation of a compiled .proto file.
OCF
Avro Object Container File, a self-describing batch file format (deferred, §35).
SchemaId
the registry-assigned monotonic integer identifying a specific registered schema.
BACKWARD
a compatibility mode: the new schema can read data written with the old schema.
FORWARD
a compatibility mode: the old schema can read data written with the new schema.
FULL
a compatibility mode requiring both BACKWARD and FORWARD to hold.
TRANSITIVE
a compatibility-mode suffix requiring the check to hold against every stored historical version, not just the immediately preceding one.
Namespace
an Avro naming scope qualifying a type's fully-qualified name.
Alias
an alternate name for a field or type, used to match renamed fields during resolution or compatibility checks.
Default Value
a schema-declared fallback value used when a field is absent from encoded data.
Field Number
the protobuf-assigned integer identifying a field on the wire.
Recursive Descent Parser
a parser architecture with one function per grammar production, calling itself for nested constructs.
Lexer
the scanner that converts source text into a token stream.
Token
a classified, span-tagged lexical unit produced by the lexer.
AST
Abstract Syntax Tree, the parser's typed output before descriptor lowering.
Span
a byte-offset range into source text, attached to tokens and AST nodes for diagnostics.
WAL
Write-Ahead Log, SQLite's durability mechanism used by serdes-store.
Optimistic Locking
a concurrency-control pattern that detects conflicting writes at commit time rather than locking pessimistically up front.
Concurrency Limiter
a middleware layer bounding the number of in-flight requests.
Backpressure
rejecting or slowing new work before an internal queue grows unboundedly.
Load Shedding
deliberately rejecting excess requests to protect overall system health.
Differential Testing
comparing this project's output against a trusted reference implementation's output for the same input.
Corpus
the set of inputs a fuzzer has discovered to be interesting, used to seed further mutation.
Crash Minimization
reducing a fuzz-found crashing input to its smallest reproducing form.
Type Promotion
Avro's allowed numeric widening chain (int→long→float→double) during reader/writer resolution.
Branch Dispatch
selecting which union branch a value belongs to, based on its encoded index.
Block Encoding
Avro's array/map framing: a sequence of (count, items) blocks terminated by a zero-length block.
Length-Delimited
a wire value prefixed by its byte length, used for strings, bytes, and embedded messages.
Monotonic ID
an identifier guaranteed to strictly increase, never repeat or go backward.
Soft Delete
marking a subject deleted while retaining its version history for recovery.
Idempotency
the property that repeating an operation has the same effect as performing it once.
p99
the 99th-percentile latency, the value below which 99% of measured requests complete.
RTO
Recovery Time Objective, the maximum acceptable time to restore service after a failure.
RPO
Recovery Point Objective, the maximum acceptable data-loss window measured in time.
