Box notes. Clients are the trust boundary: all .proto/.avsc and registry-API input is adversarial (§22). serdes-proto-parse / serdes-avro-schema lower untrusted syntax into typed ASTs with bounded recursion (I2, I14). serdes-schema is the single normalization point — every compatibility and codec decision reads the IR, never the source ASTs directly (P1, P2). The codec layer is the only place wire bytes exist; it is intentionally the smallest, most performance- critical, most fuzzed component (§14, §16, §21). serdes-compat is pure — it takes two IR values and a mode, returns a report, and never touches storage or the network (P5). serdes-registry is the only network-facing, async, multi-tenant-adjacent component (concurrency boundary: tokio) and the only component with an authentication surface (currently deferred, §35). serdes-store is the persistence boundary: everything above it operates on SchemaKind values in memory; everything below it is bytes on disk, gated by a trait so SQLite can be swapped for a future distributed backend (P8) without touching the registry HTTP layer.

8. Domain Model — Protobuf and Avro Wire-Format Semantics

Protobuf wire tags. Every field is encoded as one leading varint: (field_number << 3) | wire_type (I1). Wire types: 0 Varint (int32/int64/uint32/uint64/sint32/sint64/bool/enum), 1 64-bit (fixed64/sfixed64/double), 2 Length-delimited (string/bytes/embedded message/packed repeated), 5 32-bit (fixed32/sfixed32/float). There is no wire type 3/4 in proto3 (groups, proto2-only, deferred — see §35).

Varint encoding. Little-endian base-128 with a continuation bit: each byte holds 7 payload bits in the low bits and a high bit set on every byte except the last. Bounded by I2 to ≤ 10 bytes (covers a full u64).

ZigZag encoding. Maps signed integers onto the unsigned varint space so small-magnitude negatives stay short: encoded = (n << 1) ^ (n >> 63) for 64-bit sint64. Used only for sint32/sint64; plain int32/int64 varint-encode negatives as full-width two's-complement (long encoding), which is why ZigZag exists as a distinct wire convention.

Avro binary encoding. Schema-directed, no field tags: fields are read/written strictly in schema declaration order (I4). A record with fields id: long, name: string encodes as <long><string> with zero framing bytes between them — the reader schema alone determines field boundaries, which is why reader/writer resolution (§16) exists as a distinct engine from the codec itself.

Schema Registry API model. POST /subjects/{subject}/versions with body {"schema": "..."} returns {"id": <SchemaId>}. Compatibility modes: NONE (no checks), BACKWARD (new schema can read data written with the old schema), FORWARD (old schema can read data written with the new schema), FULL (both directions), and the *_TRANSITIVE variants of each, which check against every historical version of the subject, not just the immediately preceding one (I7).
