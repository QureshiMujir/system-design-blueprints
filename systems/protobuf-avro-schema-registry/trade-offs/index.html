Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — Schemaless Self-Describing Envelopes

┌───────────────────────────────┐
│ Message                       │
│ [type-tag][len][value] ...    │  each field carries its own type inline
│ no external schema needed     │
└───────────────────────────────┘

Regime where it wins: zero schema-registry operational burden, trusted internal-only consumers, rapid prototyping where governance is a later concern. Real system that embodies it: MongoDB's BSON wire protocol. Rejected here because it forfeits deterministic fingerprinting (I5) and the compact wire size (§4's latency/size budgets) that a fixed, externally-agreed schema provides — and it offers no mechanism at all for the compatibility governance this project's Phase 5 (§17) exists to provide.

Alt B — Schema-in-Payload Container Files

┌──────────────┬───────────────────────────────┐
│ OCF Header   │ Data Blocks                   │
│ (schema JSON,│ [block: count|codec|records]  │
│  sync marker)│  repeated...                  │
└──────────────┴───────────────────────────────┘

Regime where it wins: batch/offline pipelines where producer and consumer are decoupled in time by months, and self-description matters more than per-message overhead. Real system that embodies it: Apache Avro's own Object Container File format (and, in spirit, Cap'n Proto's framed messages). Rejected as this project's primary path because it duplicates schema bytes across millions of small streaming messages, violating §4's storage-amplification budget, when this project's primary consumer is a low-latency streaming path, not batch files — deferred as Avro OCF support, PhaseDeferred("§16"), not abandoned.

Alt C — Raft-Replicated Distributed Registry

┌────────┐   Raft log replication   ┌────────┐
│ Node A │◄─────────────────────────►│ Node B │
│(leader)│                           │(follower)│
└───┬────┘                           └────────┘
    │            ┌────────┐
    └───────────►│ Node C │
                 │(follower)│
                 └────────┘

Regime where it wins: 5+ concurrent writer replicas needing linearizable multi-region writes. Real system that embodies it: etcd (and CockroachDB's metadata layer, built on the same Raft model). Rejected for Phases 0–9 because it triples operational complexity (consensus, leader election, snapshotting) against a single-writer workload profile — §4's availability/RTO numbers assume single-node SQLite — deferred as distributed registry clustering and Raft replication, PhaseDeferred("§18"), pending write-throughput growth past C8's ceiling (§32).
