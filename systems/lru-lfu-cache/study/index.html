Mental Models & First Principles

  • MM1 — A cache is a hash map + a DLL + an eviction policy. Predicts: every "new algorithm" is a new policy over the same two structures, so the DLL is built once and reused. Bug class without it: per-algorithm linked-list arithmetic that hides a use-after-free in each eviction path. Applied: §6 P1, Phase 0.
  • MM2 — The eviction decision is the only interesting bit. Predicts: lookup and storage are commodity; effort belongs in evict/admit/on_hit. Bug class: over-engineering the map while shipping a naive O(N) eviction scan. Applied: §6 P11, Phase 3–4.
  • MM3 — Frequency without aging is a trap. Predicts: pure LFU fossilises yesterday's hot key against today's viral one; every production frequency scheme ages. Bug class: a cache whose hit-rate silently rots as the workload shifts. Applied: Phase 2.2, Phase 4.2, Phase 2.6 Pitfalls.
  • MM4 — Admission, not just eviction, controls hit-rate. Predicts: deciding not to admit a one-hit-wonder beats evicting a useful entry to make room for it; this is why W-TinyLFU wins. Bug class: a cache that admits everything and thrashes on scans. Applied: §6 P5, Phase 4.2.
  • MM5 — Recency vs frequency is a dial, not a switch. Predicts: the best policy adapts the balance to the live workload (ARC's p, CAR). Bug class: a statically-tuned cache that is great on the benchmark and poor in production. Applied: Phase 3.2, §7 I9.
  • MM6 — Insertion order is information. Predicts: SIEVE beats CLOCK because it preserves insertion order while approximating LRU with one bit. Bug class: treating SIEVE's hand like CLOCK's and getting FIFO behaviour. Applied: Phase 4.2.
  • MM7 — The hash function is a performance feature. Predicts: a poor hash clusters shards and halves throughput before any algorithm runs. Bug class: blaming the policy for a contention problem. Applied: §6 P14, Phase 5, I12.
  • MM8 — Measure against the ceiling, not the neighbour. Predicts: only the Bélády optimum tells you whether 0.7 hit-rate is good; comparing to LRU just compares two guesses. Bug class: shipping a "win" that is far from achievable. Applied: §6 P8, Performance M5–M7.
  • MM9 — unsafe is a budget, not a tool. Predicts: concentrating all unsafe in one fuzzed, Miri-checked file makes the whole engine auditable. Bug class: UB that safe-code property tests can never see. Applied: §6 P9, I14, Phase 0.
  • MM10 — Time is a hostile input. Predicts: wall-clock jumps backward; only monotonic time is safe for expiry. Bug class: stale reads after an NTP step. Applied: §6 P13, I11, Phase 6.6.

§5 Required Reading

Read in this order; do not skip the foundational papers. Each entry names the §/Phase where its idea is applied.

Papers

  • Belady, 1966, A study of replacement algorithms for a virtual-storage computer. The optimal offline algorithm; the hit-rate ceiling. Applied: §6 P8, Performance M5–M7, Phase 4 Bélády baseline.
  • O'Neil, O'Neil & Weikum, 1993, The LRU-K Page Replacement Algorithm. Track the K-th most-recent reference; evict the largest K-distance. Applied: Phase 3.2.
  • Johnson & Shasha, 1994, 2Q: A Low Overhead High Performance Buffer Management Replacement Algorithm. A1in / A1out / Am. Applied: Phase 3.2.
  • Jiang & Zhang, 2002, LIRS. The inter-reference-recency idea CLOCK-Pro inherits. Applied: Phase 4.2.
  • Megiddo & Modha, 2003, ARC: A Self-Tuning, Low Overhead Replacement Cache. Two recency lists, two ghost lists, one adaptive parameter. Read the competitiveness proof. Applied: Phase 3.2, §7 I9.
  • Bansal & Modha, 2004, CAR: Clock with Adaptive Replacement. CLOCK approximation of ARC. Applied: Phase 4.2.
  • Jiang, Chen & Zhang, 2005, CLOCK-Pro. The CLOCK approximation of LIRS; three hands. Applied: Phase 4.2.
  • Cormode & Muthukrishnan, 2005, The Count-Min Sketch and its Applications. The estimator W-TinyLFU's frequency uses. Applied: Phase 4.2, §7 I10.
  • Einziger & Friedman, 2016, TinyLFU: A Highly Efficient Cache Admission Policy. Bloom doorkeeper + CMS with halving age. Applied: Phase 4.2, §6 P5.
  • Bloom, 1970, Space/time trade-offs in hash coding with allowable errors. The doorkeeper. Applied: Phase 4.2.
  • Pugh, 1990, Skip Lists. Read for the spirit; sets up the counter-bucket idiom. Applied: Phase 2.
  • Zhang et al., 2024, SIEVE: an Efficient Turn-Key Eviction Algorithm for Web Caches (NSDI). Single hand, one bit per entry; beats LRU on most modern traces. Applied: Phase 4.2, §6 P2.

Books

  • Hennessy & Patterson, Computer Architecture: A Quantitative Approach. Cache-locality reasoning behind the intrusive-DLL/arena decision. Applied: §9 ADR-02, Phase 0.
  • Drepper, What Every Programmer Should Know About Memory. Cache-line packing of Node<K,V>. Applied: §11, Phase 0.
  • Klabnik & Nichols, The Rust Programming Language. Ownership/lifetime model the unsafe confinement rests on. Applied: Phase 0, §6 P9.
  • Jung et al., RustBelt (and the Rustonomicon). Soundness reasoning for the arena and the PolicyState union. Applied: §11.3, Phase 0.6.
  • Tanenbaum & Bos, Modern Operating Systems. Page-replacement framing (CLOCK, second-chance). Applied: Phase 4.2.
  • Cormen et al., Introduction to Algorithms. Heap vs bucket-list cost analysis behind O(1) LFU. Applied: Phase 2.2.

Reference implementations

  • Caffeine (com.github.benmanes.caffeine.cache.BoundedLocalCache). The reference W-TinyLFU + segmented-LRU. Applied: Phase 2 & 4 conformance.
  • Ristretto (Dgraph, Go). Admission accounting and get-batching to amortise contention. Applied: Phase 5.
  • groupcache (Go). LRU simplicity and the singleflight pattern. Applied: Phase 7.2 refresh-ahead.
  • moka (Rust). Ships W-TinyLFU; the Rust shape closest to ours. Applied: Phase 4, §9 ADR-09.
  • Memcached. Slab allocator and segmented-LRU at the largest deployed scale. Applied: §11 budget, Phase 1.

RFCs / standards

  • Keep a Changelog 1.0.0. CHANGELOG.md format. Applied: Build & Release Engineering.
  • Semantic Versioning 2.0.0. Rust API semver discipline that gates binding ABI stability. Applied: Compatibility & Versioning.

The literature is not stable: SIEVE landed in 2024; CLOCK-Pro has been revised since 2005; W-TinyLFU admission accounting has variants. ADRs in docs/adr/ pin the version of every algorithm shipped.

Glossary · 50 terms · site-wide glossary

2Q:
multi-queue policy with A1in (recent FIFO), A1out (key-only ghost), Am (frequent LRU).
A1in / A1out / Am:
the three 2Q queues; new arrivals, ghost evictions, and the frequent set.
Admission filter:
a pass that decides whether to store a candidate at all, in front of eviction (TinyLFU here).
AOF (append-only file):
a log of every insert/remove, replayed to recover cache state.
Arena:
the contiguous owner of every Node<K,V>, with O(1) slot alloc/free.
ARC:
Adaptive Replacement Cache; two recency lists, two ghost lists, one adaptive parameter p.
Bélády optimum:
the offline optimal policy; evicts the entry whose next reference is furthest in the future.
Bloom doorkeeper:
a Bloom filter requiring a key to be seen twice before admission.
BucketSlot:
a slot type distinct from Slot, indexing the LFU frequency-bucket DLL.
CAR:
Clock with Adaptive Replacement; the CLOCK approximation of ARC.
CLOCK:
circular-buffer second-chance approximation of LRU with one referenced bit per slot.
CLOCK-Pro:
the CLOCK approximation of LIRS; hot/cold/test categories, three hands.
CMS (count-min sketch):
a probabilistic frequency estimator; min over d hashed rows, never underestimates.
Conformance bucket:
one named test group in the conformance suite with a pass criterion and tolerance.
Doorkeeper:
see Bloom doorkeeper.
DLL:
doubly-linked list; the structure every classical replacement algorithm rests on.
EWMA:
exponentially-weighted moving average; how the hit-rate gauge is computed cheaply.
Generation tag:
the counter on a slot that distinguishes a recycled slot from a stale pointer.
Ghost entry:
a key without its value, retained so a future access can be recognised as a recent eviction.
Hierarchical timer wheel:
a multi-level timer structure giving O(1) scheduling over any timeout range.
Hit ratio:
fraction of get calls that found the key.
Intrusive list:
a list whose pointers live inside the element nodes, not in separate list cells.
K-distance (LRU-K):
time since a key's K-th most-recent reference; LRU-K's eviction priority.
LFU:
Least Frequently Used; evicts the lowest access count.
LIRS:
Low Inter-reference Recency Set; the policy CLOCK-Pro approximates.
Loom:
the Rust concurrency-permutation testing tool used on the sharded path.
LRU:
Least Recently Used; evicts the tail of the recency DLL.
LRU-K:
LRU variant tracking the K-th most-recent reference.
MaybeUninit:
the Rust type letting the arena allocate node storage without zeroing.
Miri:
the Rust interpreter that checks unsafe code against borrow-checker semantics.
MRU:
Most Recently Used; the head of the recency DLL.
PhaseDeferred:
the anchor marking a surface deferred to a later phase, here "Deferred Features Register".
Policy:
the eviction strategy trait every algorithm implements.
PolicyState:
the per-node tagged union holding the active policy's private bookkeeping.
Refresh-ahead:
asynchronously reloading an entry near expiry to avoid a cache-fill stampede.
RPO (recovery point objective):
the maximum data loss window; ≤ 1 s at AOF fsync-every-second.
RTO (recovery time objective):
the maximum recovery time; ≤ 30 s here.
Sealed:
the much-later end-state defined by INSTRUCTIONS.md (portfolio root, sec. 8.1), reached by future sessions.
Sharded cache:
a cache split across N independently-locked sub-caches; shard = hash(key) & mask.
SIEVE:
the 2024 single-hand, one-bit eviction algorithm that preserves insertion order.
Singleflight:
coalescing concurrent identical loads into one in-flight call.
Slot:
a generational handle into the arena, used as the node pointer by every policy.
TinyLFU:
the frequency-based admission filter; the W variant adds a small recency window.
TTL (time to live):
an entry's per-entry absolute expiry time.
Weigher:
a user function returning a (K,V) pair's weight (typically bytes), consumed by the budget.
Write-around:
write only to the backing store; populate the cache lazily on the next read.
Write-back:
write to the cache and queue an async write to the backing store.
Write-through:
write to both cache and backing store before returning.
W-TinyLFU:
the windowed TinyLFU admission scheme Caffeine ships.
xxhash3:
the fast non-cryptographic key hash (ADR-06).
