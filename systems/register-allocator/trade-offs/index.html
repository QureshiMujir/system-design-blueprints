Decisions (§9) · 28 ADRs

ADR-01

Implementation language

Chosen

Rust 1.78+ MSRV

Rejected

C++; OCaml; Go

When the rejected choice is right

C++ wins when the host compiler is already a C++ codebase (e.g. embedding directly in an existing LLVM fork) and FFI cost must be zero

Why: no GC pause in JIT hot path; exhaustive enum matching for Location/InterferenceGraph; ecosystem parity with regalloc2

ADR-02

Input IR form

Chosen

strict SSA, not lowered pre-allocation

Rejected

lowered (non-SSA) CFG IR

When the rejected choice is right

non-SSA wins for a legacy backend that cannot maintain SSA through its own optimizer and would pay a re-construction cost per allocation call

Why: enables chordal fast path (I12); matches regalloc2/Go-compiler lineage

ADR-03

Allocator strategy count

Chosen

two allocators (GraphAllocator, LinearScanAllocator) behind Allocator trait

Rejected

graph-coloring only; linear-scan only

When the rejected choice is right

a single-strategy allocator wins when the project has exactly one consumer profile and the second implementation's maintenance cost is unjustified

Why: serves both AOT-quality and JIT-latency consumers

ADR-04

Interference-graph representation

Chosen

sparse adjacency default, dense bitset above per-function density heuristic (§15.2)

Rejected

always-sparse; always-dense

When the rejected choice is right

always-dense wins on register-starved embedded targets where V is small and D is uniformly high (e.g. 8-bit MCU backends)

Why: matches measured D≈V/8 break-even

ADR-05

Graph-coloring algorithm family

Chosen

Chaitin-Briggs (simplify/coalesce/freeze/select/spill)

Rejected

Chow-Hennessy priority-based coloring; pure Chaitin (no Briggs optimism)

When the rejected choice is right

priority-based coloring wins when spill decisions must be made incrementally as code is generated (Chow-Hennessy's original one-pass motivation)

Why: best-documented, most portable baseline; matches HotSpot C2 lineage

ADR-06

Coalescing default

Chosen

conservative (Briggs) merge; George-Appel iterated opt-in via Config::coalescer

Rejected

George-Appel always-on; no coalescing

When the rejected choice is right

George-Appel-always-on wins on move-heavy functions (post-inlining, heavy phi traffic) where the extra 3× compile time (M5 vs M4, §28) is acceptable

Why: bounds worst-case compile time by default

ADR-07

Spill-weight formula

Chosen

(use_count × loop_depth³) / range_length, evaluated globally

Rejected

local one-step lookahead; use-count only

When the rejected choice is right

local lookahead wins in a latency-critical single-pass JIT tier (e.g. a baseline/tier-0 JIT) where even one global O(V) pass is too slow

Why: biases against spilling hot, short-lived vregs; avoids greedy local mistakes (P7)

ADR-08

Live-range representation

Chosen

half-open interval list with explicit holes

Rejected

single [start,end] span per vreg

When the rejected choice is right

single-span wins when memory is the binding constraint and slight interference over-approximation (more spills) is an acceptable trade

Why: precise interference (§15.2); enables the copy-hint optimization

ADR-09

Program-point granularity

Chosen

half-instruction slots (even=before, odd=after)

Rejected

one slot per instruction

When the rejected choice is right

one-slot-per-instruction wins on architectures with no two-operand/destructive instructions (pure RISC, no destructive ops) where the ordering is moot

Why: disambiguates same-instruction def/use ordering (two-operand add)

ADR-10

Critical-edge policy

Chosen

resolver always splits before phi-copy insertion (I5)

Rejected

split only when a copy is actually needed

When the rejected choice is right

conditional splitting wins when code-size is the dominant constraint (embedded) and the extra empty blocks measurably bloat the binary

Why: uniform correctness; no conditional-splitting bug surface

ADR-11

Calling-convention representation

Chosen

typed constraint tables (CallingConvention), consumed as allocator input

Rejected

inline fixups after allocation

When the rejected choice is right

inline fixups win for a throwaway prototype targeting one ABI where the table infrastructure is pure overhead

Why: keeps optimizer passes constraint-aware (P10)

ADR-12

Determinism discipline

Chosen

BTreeMap/BinaryHeap with stable comparator in every inner-loop collection

Rejected

HashMap + post-hoc sort

When the rejected choice is right

HashMap + post-sort wins when the sort key is cheap and the collection is queried far more than iterated (rare in this allocator's hot loops)

Why: avoids an entire class of hard-to-reproduce bugs (I9)

ADR-13

Verifier cadence

Chosen

every allocation call in debug/CI; sampled (1/N) in release

Rejected

always-on in release; never in release

When the rejected choice is right

always-on-in-release wins in a correctness-critical AOT compiler (e.g. safety-certified toolchain) where the verifier's cost is acceptable

Why: keeps release-mode overhead bounded while catching regressions in CI

ADR-14

Rematerialization policy

Chosen

remat when defining instr is side-effect-free and operand-invariant (I14), else classic spill/reload

Rejected

never rematerialize; always rematerialize when possible

When the rejected choice is right

never-rematerialize wins when instruction-cache pressure (not memory traffic) is the bottleneck, e.g. very small hot loops

Why: balances code-size growth vs. memory traffic (P12)

ADR-15

Stack-slot assignment

Chosen

secondary interference graph over spill slots, shares non-overlapping slots

Rejected

one slot per spilled vreg (no sharing)

When the rejected choice is right

no-sharing wins when stack-frame determinism/debuggability (a fixed per-vreg slot for a debugger to find) outweighs frame-size savings

Why: bounds stack-frame growth (§18)

ADR-16

Chordal fast path

Chosen

simplicial-elimination ordering engaged only under certified strict SSA (I12)

Rejected

always run general Chaitin-Briggs

When the rejected choice is right

general-Chaitin-Briggs-always wins when the SSA certification pass itself is more expensive than the coloring it would save (very small functions)

Why: polynomial-time coloring exploiting Hack-Grund-Goos when available

ADR-17

Linear-scan interval splitting

Chosen

Wimmer-Franz SSA-based splitting enabled by default in JIT profile

Rejected

no splitting (classic Poletto-Sarkar only)

When the rejected choice is right

no-splitting wins in a tier-0/baseline JIT where every microsecond of allocation time is charged against warm-up latency

Why: closes most of the quality gap to graph coloring (M6 vs M9)

ADR-18

Second-chance / backtracking mode

Chosen

bin-packing-style priority-queue backtracking (regalloc2 "Ion" lineage) offered as alternate linear-scan mode

Rejected

none (single forward pass only)

When the rejected choice is right

single-forward-pass wins when compile-time determinism (a hard, small time budget) matters more than the quality recovered

Why: recovers quality under high register pressure without full graph coloring

34. Alternative Architectures (Roads Not Taken)

Alt. 1 — Priority-queue live-range-splitting allocator (no Simplify/ Select stack).

Live ranges --> Priority Queue (by spill weight)
                     |
              pop highest priority
                     |
        free reg? --yes--> assign
             |no
        evict lowest-priority active range
        or split its range at a cheaper point
                     |
              push split remainder back onto queue

Regime where it wins: large AOT functions with heavy register pressure, where partial-range eviction (splitting one interval instead of spilling the whole vreg) recovers materially more code quality than this project's whole-vreg Chaitin-Briggs spill. Real system: LLVM RegAllocGreedy. Rejected because: it trades away the simplicity of the stack-based Simplify/Select correctness argument (§8.4's state table) for a more complex eviction-cascade design whose termination and quality properties are harder to verify independently (MM4) — this project optimizes for verifiability first (P6, mission statement's priority order).

Alt. 2 — PBQP (Partitioned Boolean Quadratic Programming) allocator.

Interference graph --> Cost matrices per node/edge
                              |
                    Reduce degree-1/degree-2 nodes
                    (Reduce0/Reduce1/ReduceN)
                              |
                    Back-substitute optimal solution

Regime where it wins: targets with irregular, highly asymmetric register costs (e.g. some register-pair or overlapping-class architectures) where a uniform K-degree threshold (this project's core assumption, MM2) poorly models the true cost structure. Real system: LLVM's PBQP-based allocator (used historically for Hexagon). Rejected because: PBQP's general reduction is more expensive and harder to reason about per-invariant (§7's I1–I14 table has no natural PBQP analogue) than the graph-coloring degree argument this project builds on.

Alt. 3 — SSA-native backtracking bin-packing, single strategy (no separate linear scan).

SSA value lifetimes --> Bundles (merged compatible lifetimes)
                              |
                    Priority-queue bin-packing across registers
                              |
                    Second-chance: retry evicted bundle later

Regime where it wins: a pipeline that only ever needs one allocator tier and wants to avoid maintaining two implementations behind one trait (this project's P2). Real system: Cranelift regalloc2's "Ion" allocator covers both AOT and JIT profiles this way. Rejected because: this project explicitly serves two distinct consumer classes (JIT-latency-bound and AOT-quality-bound, §1) and values the pedagogical clarity of two separately-reasoned-about algorithms (Chaitin-Briggs and Poletto-Sarkar) over one unified but more complex bundle-based design.

Alt. 4 — Region-based decomposition (GCC IRA style).

Function --> Region tree (loop nests as natural region boundaries)
                    |
        Allocate innermost regions first (bottom-up)
                    |
        Stitch region-boundary values via forced same-register
        or explicit boundary spill/reload

Regime where it wins: functions beyond this project's practical ceiling (§29, V > 12,000) where whole-function graph construction is prohibitively expensive. Real system: GCC IRA. Rejected for Phase 0–9 because: it introduces a coordination layer (region-boundary stitching) this project's PhaseDeferred("§29") explicitly defers until a production workload demonstrates functions large enough to need it (§35's un-defer trigger).
