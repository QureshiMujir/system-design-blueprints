30. Mental Models & First Principles

  • MM1 — Liveness is a fixpoint over a monotone lattice; the allocator is a search over its output. Predicts: liveness always terminates and can always be cached safely as long as invalidation is explicit. Bug class without it: recomputing liveness inside the coloring loop, paying O(N) cost O(V²) times. Applied in §14 (Phase 2), §6 P3.
  • MM2 — A physical register is just a color; register allocation is graph coloring wearing a compiler's clothes. Predicts: the physical register count K directly bounds simplifiability (degree < K). Bug class without it: not understanding why a target with fewer registers needs fundamentally more spill code, not just "more optimization." Applied in §16 (Phase 4), §8.4.
  • MM3 — Interference is a relation over program points, routed through intervals, never a direct vreg-pair lookup. Predicts: any "do these two vregs conflict" check that skips the interval/hole representation will over-approximate. Bug class without it: ad hoc interference checks that miss holes and inflate spill counts. Applied in §15 (Phase 3), §8.3.
  • MM4 — A verifier that reuses the mechanism it checks is an echo, not a check. Predicts: any bug in a shared data structure escapes self-referential verification. Bug class without it: a verifier that "passes" on a systematically broken interference graph because it reads the same broken structure. Applied in §21 (Phase 9), §8.7.
  • MM5 — Determinism is a property of your data structures, not your algorithm's correctness. Predicts: a provably-correct algorithm can still produce non-reproducible output if its collections iterate in hash order. Bug class without it: flaky differential tests and non-reproducible release builds. Applied in §6 P4, §7 I9.
  • MM6 — Chordality is a gift, not a given. Predicts: SSA form buys polynomial-time coloring only as long as the structural precondition (strict SSA) holds all the way to the allocator's entry point. Bug class without it: silently mis-coloring the moment an upstream pass breaks SSA without the allocator noticing. Applied in §16 (Phase 4), §7 I12.
  • MM7 — Spilling is a global bet, not a local reflex. Predicts: scoring every candidate before committing beats greedily spilling the first high-degree node found. Bug class without it: a locally-greedy spiller that spills a hot, short-lived vreg because it looked expensive in isolation. Applied in §18 (Phase 6), §6 P7.
  • MM8 — A pass that mutates IR anywhere but one place is a pass you cannot audit. Predicts: centralizing all IR mutation in the resolver makes every miscompile traceable to one file. Bug class without it: a distributed set of "small" IR edits scattered across the allocator, each individually plausible, jointly impossible to bisect. Applied in §19 (Phase 7), §6 P9.

5. Required Reading

Books

  • Muchnick, S. — Advanced Compiler Design and Implementation, Morgan Kaufmann, 1997, Chapter 16 ("Register Allocation"). Extract: the general shape of the simplify/spill loop and the industrial spill-cost model. Applied in Phase 4 (§16) and Phase 6 (§18).
  • Appel, A. — Modern Compiler Implementation in C, Cambridge University Press, 1998, Chapter 11 ("Register Allocation"). Extract: the simplify/coalesce/freeze/select/spill state machine, presented as a worklist algorithm. Applied in Phase 4–5 (§16–§17) and the Domain Model state table (§8).
  • Cooper, K., Torczon, L. — Engineering a Compiler, 2nd ed., Morgan Kaufmann, 2011, Chapter 13 ("Register Allocation"). Extract: the top-down vs. bottom-up allocator taxonomy and the priority-based allocation alternative. Applied in Alternative Architectures (§34).
  • Aho, Lam, Sethi, Ullman — Compilers: Principles, Techniques, and Tools, 2nd ed., Section 8.8 ("Register Allocation and Assignment"). Extract: the baseline liveness dataflow equations. Applied in Phase 2 (§14).
  • Rastello, F., Tichadou, F. (eds.) — SSA-based Compiler Design, Springer, 2022. Extract: the SSA-form register-allocation chapters, chordal-graph coloring, and out-of-SSA translation correctness. Applied in Phase 4 (§16), Phase 7 (§19), and Domain Model (§8).
  • Wilhelm, R., Seidl, H. — Compiler Design: Analysis and Transformation, Springer. Extract: the formal treatment of dataflow fixpoints used to prove liveness termination. Applied in Phase 2 N.2 (§14.2) and Invariant I3/I4 (§7).

Papers

  • Chaitin, G. et al. — "Register Allocation via Coloring," Computer Languages 6(1), 1981. Contribution: the first graph-coloring allocator. Applied in Phase 4 (§16).
  • Chaitin, G. — "Register Allocation & Spilling via Graph Coloring," PLDI 1982. Contribution: the simplify/select/spill loop as shipped. Applied in Phase 4 (§16).
  • Briggs, Cooper, Torczon — "Improvements to Graph Coloring Register Allocation," ACM TOPLAS 16(3), 1994. Contribution: optimistic coloring, conservative coalescing, live-range splitting. Applied in Phase 4–6 (§16–§18).
  • George, L., Appel, A. — "Iterated Register Coalescing," ACM TOPLAS 18(3), 1996. Contribution: the George heuristic + iterated simplify/coalesce/freeze loop. Applied in Phase 5 (§17).
  • Poletto, M., Sarkar, V. — "Linear Scan Register Allocation," ACM TOPLAS 21(5), 1999. Contribution: O(N) allocation via sorted active-list walk. Applied in Phase 8 (§20).
  • Wimmer, C., Franz, M. — "Linear Scan Register Allocation on SSA Form," CGO 2010. Contribution: SSA-aware interval splitting, second-chance allocation. Applied in Phase 8 (§20).
  • Hack, S., Grund, D., Goos, G. — "Register Allocation for Programs in SSA-form," Compiler Construction (CC) 2006. Contribution: proof that SSA interference graphs are chordal ⇒ polynomial coloring. Applied in Phase 4 (§16) and Domain Model (§8).
  • Cytron, Ferrante, Rosen, Wegman, Zadeck — "Efficiently Computing Static Single Assignment Form and the Control Dependence Graph," ACM TOPLAS 13(4), 1991. Contribution: dominance-frontier construction underlying the phi-node liveness rule. Applied in Phase 2 (§14) and Phase 7 (§19).
  • Chow, F., Hennessy, J. — "The Priority-Based Coloring Approach to Register Allocation," ACM TOPLAS 12(4), 1990. Contribution: priority- queue-driven allocation, the ancestor of LLVM's RegAllocGreedy. Applied in the Comparative Architecture Table (§31) and Alternative Architectures (§34).
  • Pereira, F., Palsberg, J. — "Register Allocation via Coloring of Chordal Graphs," APLAS 2005. Contribution: constructive polynomial coloring algorithm for chordal interference graphs. Applied in Phase 4 (§16) and Domain Model (§8).

Reference Implementations

  • LLVM — llvm/lib/CodeGen/RegAllocGreedy.cpp, LiveIntervals.cpp, RegisterCoalescer.cpp. Lesson: priority-queue-driven live-range splitting beats stack-based simplify/select at scale. Pitfall not to copy: RegAllocGreedy's cascading eviction heuristics are tuned to LLVM's specific target-description system and do not port cleanly. Applied in the Comparative Architecture Table (§31) and Alternative Architectures Alt. 1 (§34).
  • Cranelift — regalloc2/src/ (ion.rs, fastalloc.rs). Lesson: a single Rust allocator crate can serve both an AOT-quality backtracking mode and a fast linear-scan mode behind one trait — directly the architecture this project follows (§3). Pitfall: regalloc2's bundle formation adds a layer of indirection this project intentionally omits in Phase 0 for pedagogical clarity. Applied in Phase 8 (§20), the Comparative Architecture Table (§31), and Alternative Architectures Alt. 3 (§34).
  • GCC — gcc/ira.c, gcc/ira-color.c, gcc/ira-lives.c. Lesson: region-based decomposition bounds coloring cost on huge functions. Pitfall: IRA's region nesting model is tightly coupled to GCC's RTL representation and does not generalize to an SSA-only IR. Applied in Scalability Analysis (§29) and Alternative Architectures Alt. 4 (§34); the region-based feature itself is PhaseDeferred("§29").
  • The Go compiler — cmd/compile/internal/ssa/regalloc.go. Lesson: a single-pass, SSA-friendly allocator can skip graph construction entirely for register-poor targets. Pitfall: its SSA-form-only design fails gracefully only because Go accepts more spill code than LLVM would tolerate. Applied in the Comparative Architecture Table (§31).
  • HotSpot C2 — share/opto/chaitin.cpp, coalesce.cpp. Lesson: the original Chaitin allocator has stayed in industrial production for over two decades essentially unchanged — evidence that the algorithm's core loop is durable. Pitfall: C2's allocator is deeply entangled with its sea-of-nodes IR; the entanglement is exactly what this project avoids by keeping ra-graph IR-representation-agnostic. Applied in Phase 4 (§16).

RFCs / Specifications

  • System V AMD64 ABI (x86-64 psABI). Argument/return registers, caller/callee-saved sets, vararg XMM-spill rule. Applied in Phase 1 (§13) and Phase 6 (§18 ABI fixtures).
  • Microsoft x64 Calling Convention. Shadow-space and register-set differences from SystemV. Applied in Phase 1 (§13).
  • ARM AAPCS64 (Procedure Call Standard for the Arm 64-bit Architecture). Register set and aliasing for aarch64. Applied in Phase 1 (§13).

Glossary (§36) · 50 terms · site-wide glossary

Active list
: in linear scan, the set of vregs whose live range covers the current scan position.
Allocator
: the component implementing the Allocator trait (§11) that maps vregs to physical registers or spill locations.
AAPCS64
: the ARM 64-bit Procedure Call Standard (calling convention).
Assignment
: the output of an allocator — a map from VirtReg to Location, plus spill and rematerialization records (§11).
BinaryHeap / BTreeMap discipline
: the P4 rule that every inner-loop collection uses a sorted, stable-ordered container, never a hash-ordered one.
Bundle
: in bundle-based allocators (e.g. regalloc2), a group of merged compatible live ranges treated as one allocation unit.
Caller-saved register
: a physical register the caller must save across a call if it holds a value the caller still needs.
Callee-saved register
: a physical register the callee must preserve across its own execution.
Chaitin coloring
: the original Build→Simplify→Select→Spill graph-coloring algorithm (Chaitin 1981/1982).
Chaitin-Briggs
: Chaitin's algorithm plus Briggs's optimistic spilling and conservative coalescing (Briggs-Cooper-Torczon 1994).
Chordal graph
: a graph in which every cycle of length ≥ 4 has a chord; polynomial-time colorable via simplicial elimination ordering.
Clique
: a fully-connected subset of the interference graph; the set of vregs live at one program point forms a clique (§8.3).
Coalescer
: the component merging move-related vregs (ra-coalesce, §11).
Conservative coalescing
: merge two move-related vregs only if the merged node's degree remains < K (Briggs's safety test).
Critical edge
: a control-flow edge from a block with multiple successors to a block with multiple predecessors.
Def (definition)
: the program point where a vreg's value is produced.
Degree
: the number of an interference-graph node's distinct neighbors.
Determinism
: the guarantee (I9) that identical input + seed produces a byte-identical Assignment across runs.
George-Appel
: the iterated-coalescing algorithm interleaving Simplify, Coalesce, and Freeze (George-Appel 1996).
Hole
: a gap between two consecutive intervals in a vreg's LiveRange, where the vreg is dead.
Interference
: the relation between two vregs whose live ranges overlap at some program point.
Interference graph
: the data structure (InterferenceGraph, §11) recording all pairwise interferences.
Interval
: a half-open [start, end) span of program points during which a vreg's value must be preserved.
Iteration cap
: the configurable bound (I8, default 100) on spill/coalesce/freeze restart loops.
K
: the number of physical registers available in a vreg's register class — the coloring threshold.
Linear scan
: the O(N) allocator walking vregs sorted by live-range start (Poletto-Sarkar 1999).
Live range
: the full set of program points over which a vreg's value must be preserved, represented as Intervals with holes.
Live-in / live-out
: the set of vregs live at a basic block's entry / exit, per the dataflow equations (§14.2).
Location
: the final placement of a vreg — Physical, Spill, or Constant (rematerialized) (§11).
Move-related
: a vreg that is the source or destination of a copy instruction, eligible for coalescing.
PBQP
: Partitioned Boolean Quadratic Programming, an alternative allocation formulation (§34 Alt. 2).
Physical register
: a real, target-defined register (PhysReg, §11).
Program point
: a half-instruction-granularity ordering position (ProgramPoint, even = before, odd = after an instruction, ADR-09).
Region-based allocation
: partitioning a function into independently-colorable regions before allocating (GCC IRA, deferred, §35).
Rematerialization
: recomputing a value at its use site instead of spilling and reloading it, when eligible (I14).
Resolver
: the component (ra-resolver) that applies an Assignment to the IR — the sole IR-mutation point (P9).
Second-chance allocation
: a linear-scan extension where a previously-spilled/evicted interval may be reconsidered for a register freed later in the walk (ADR-18).
Simplify / Select / Spill
: the three core states of Chaitin coloring (§8.4).
Simplicial elimination ordering
: the vertex ordering that colors a chordal graph exactly and polynomially (Pereira-Palsberg 2005).
Spill
: storing a vreg's value to a stack slot and reloading it at each subsequent use.
Spill slot
: a stack-frame location holding a spilled vreg's value, potentially shared across non-overlapping vregs (I10).
Spill weight
: the cost-of-spilling estimate used to rank spill candidates (ADR-07).
SSA (Static Single Assignment)
: an IR form where each vreg is defined exactly once; enables the chordal fast path (I12).
SystemV AMD64 ABI
: the canonical non-Windows x86-64 calling convention.
Two-operand instruction
: an instruction that destroys one operand (e.g. x86 add), requiring a SameAs use constraint.
Use
: a program point at which a vreg's value is read, optionally carrying a UseConstraint (§11).
UseConstraint
: AnyOf(class), Specific(preg), or SameAs(vreg) — the three forms a use may require (§11).
Verifier
: the independent-reconstruction correctness checker (ra-verifier) enforcing I1–I14 (§7, §21).
Virtual register (vreg)
: an unbounded, target-independent register in the input IR (VirtReg, §11).
Wimmer splitting
: the SSA-aware interval-splitting extension to linear scan (Wimmer-Franz 2010), reducing the quality gap to graph coloring.
