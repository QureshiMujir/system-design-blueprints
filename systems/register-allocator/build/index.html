⬜ Phase 0 — Repository Skeleton & Correctness Kernel §12

Objectives

Stand up the Cargo workspace (ADR-19), governance files, and CI matrix (ADR-25) before any allocation logic exists. Establish the crate boundaries of §10 as compiling (empty) units so every later phase adds behavior to a fixed skeleton rather than negotiating structure.

Deliverable

A workspace that builds (cargo build --all-targets) and lints clean (cargo clippy -D warnings, cargo fmt --check) on every CI matrix leg, with every crate from §10 present and empty.

Acceptance

cargo build --all-targets exit code 0 on Linux x86_64/aarch64, macOS x86_64/aarch64, Windows x86_64 (5 legs, ADR-25); cold build time < 90 s (measured, M-table adjacent); cargo metadata lists exactly the 13 crates named in §10.

Fixtures

examples/minimal_function.ron — the smallest valid fixture (1 block, 1 vreg, 1 physical register), used to smoke-test the fixture parser stub.

Pitfalls

Dependency-version skew between fixedbitset and bit-vec (only one bitset crate should ever be a workspace dependency, per ADR-04); a missing CI matrix leg produces silent platform breakage discovered only at release.

⬜ Phase 1 — Input IR, Register File & ABI Constraint Model §13

Objectives

Define the input IR's register-relevant surface (VirtReg, PhysReg, RegClass, RegisterFile, UseConstraint) and the three target calling conventions as typed constraint tables (P10, ADR-11).

Deliverable

ra-ir compiles with a canonical x86_64 RegisterFile (in tests/x86_64.rs) and canonical aarch64 RegisterFile (in tests/aarch64.rs); ra-abi exposes all three CallingConvention tables.

Acceptance

A unit test asserts aliases.contains(YMM0, XMM0) and the ZMM→YMM→XMM transitive chain closes (I13); alias-matrix construction completes in < 5 ms per target (§4 startup constraint); all three ABI tables round-trip through the conformance/buckets/abi/ fixture parser with zero diffs.

Fixtures

conformance/buckets/abi/sysv64_varargs.ron, conformance/buckets/abi/win64_shadow_space.ron, conformance/buckets/abi/aapcs64_basic.ron — one canonical fixture per ABI.

Pitfalls

For AVX-512, ZMM aliases YMM aliases XMM in a chain; a matrix that only records direct aliases (not the closure) under-reports interference between, e.g., ZMM0 and XMM0 writes — the closure step (ADR-22) exists specifically to prevent this.

⬜ Phase 2 — Liveness Analysis & Live-Range Construction §14

Objectives

Implement the stand-alone, cached liveness analysis (P3) that produces LiveRange per vreg with explicit holes (ADR-08), at half-instruction ProgramPoint granularity (ADR-09).

Deliverable

ra-liveness producing LiveRange (with sorted, non-overlapping Intervals per I3) for every vreg in a Module.

Acceptance

A property test (1,000 random programs) asserts the dataflow result matches a brute-force per-instruction liveness probe with zero mismatches; 1,000-block function completes liveness in ≤ 50 ms p50 / ≤ 100 ms p99 (M1, §28).

Fixtures

conformance/buckets/liveness/phi_predecessor_liveness.ron (the classic phi-at-predecessor-exit case); conformance/buckets/liveness/two_operand.ron (destructive-instruction ordering); conformance/buckets/liveness/malformed_dangling_phi.ron (§8.6 malformed case, expects LivenessError::DanglingPhiOperand).

Pitfalls

Treating a phi's incoming value as live at the phi block's entry instead of the predecessor's exit (the classic phi-liveness bug, P3/Cytron et al.); a two-operand instruction (x86 destructive add) that fails to declare its SameAs constraint corrupts the interval boundary at that program point.

⬜ Phase 3 — Interference Graph Construction §15

Objectives

Build InterferenceGraph (Sparse | Dense, ADR-04) as a pure function of LiveRanges (§8.3's clique rule), choosing representation per-function via the density heuristic (§15.2).

Deliverable

ra-igraph::InterferenceGraph::build producing a graph verified against a brute-force O(V²) pairwise-overlap check on the property-test corpus.

Acceptance

A property test (500 random LiveRange sets) asserts zero mismatches against brute-force; 10,000-vreg function completes construction in ≤ 200 ms p50 sparse / ≤ 100 ms p50 dense (M2, §28); sparse memory use ≤ 200 bytes/vreg on the benchmark corpus (§4).

Fixtures

conformance/buckets/igraph/holes_no_interference.ron (two vregs whose ranges overlap but have a hole exactly where the other is live — must NOT interfere); conformance/buckets/igraph/copy_hint_single_point.ron (a copy whose source range ends exactly where the destination begins — no interference, enabling the coalescing hint in Phase 5, §17).

Pitfalls

"Overlap" computed on [start,end] spans instead of the hole-aware interval list over-approximates interference and inflates spill counts — the entire reason ADR-08 chose holes over spans; a vreg with a single-program-point live range (a pure copy) that is treated as interfering with its own source produces a coalescing opportunity the coalescer can never take.

⬜ Phase 4 — Chaitin-Briggs Graph Coloring §16

Objectives

Implement the Build→Simplify→Select→Spill core loop (Chaitin 1981/1982) with Briggs's optimistic-spilling refinement (Briggs-Cooper-Torczon 1994), and the SSA-chordal fast path (Hack-Grund-Goos 2006, I12).

Deliverable

ra-graph::GraphAllocator producing a verifier-clean Assignment on the conformance/buckets/graph/ corpus, including the worked example of §8.5.

Acceptance

100% of conformance/buckets/graph/ fixtures pass (including high_pressure.ron, low_pressure.ron, pathological_clique.ron); 10,000-vreg function colors in ≤ 500 ms p50 / ≤ 1 s p99 with simple spilling only (M3, §28); the chordal fast path (I12) engages on 100% of strict-SSA fixtures and is measured to complete in under half the general path's time on the same input (regression-gated).

Fixtures

conformance/buckets/graph/high_pressure.ron, conformance/buckets/graph/low_pressure.ron, conformance/buckets/graph/pathological_clique.ron (§8.5's exact worked example, K=2, V=3 mutual clique), conformance/buckets/graph/chordal_fastpath.ron.

Pitfalls

Spilling a vreg whose defining instruction is cheaply rematerializable (load immediate, lea of a constant address) wastes a stack round trip — the spill-cost model (Phase 6, §18) must rank remat-eligible vregs lower priority for classic spill; a spill that introduces a new vreg (the reload's destination temporary) must be re-inserted into the graph and is subject to re-coloring on the Build restart — omitting this re-insertion step produces an uncoloured vreg that silently defaults to an invalid PhysReg(0).

⬜ Phase 5 — Register Coalescing (Conservative + Iterated) §17

Objectives

Implement Chaitin-Briggs conservative coalescing (default, ADR-06) and George-Appel iterated coalescing (opt-in, ADR-06), both enforcing I7 (never merge interfering vregs).

Deliverable

ra-coalesce with both CoalescerChoice variants (§11), each producing a CoalesceReport consumed by ra-graph's restart-aware Simplify loop.

Acceptance

Zero I7 violations across the entire conformance/buckets/coalesce/ corpus (a coalesce that would violate I7 must be refused, not merely logged); George-Appel measurably removes ≥ 90% of moves that Chaitin-Briggs conservative leaves as real moves on the known_hard_cases.ron fixture; 10,000-vreg function with Chaitin-Briggs coalescing completes in ≤ 800 ms p50 (M4); with George-Appel, ≤ 1.5 s p50 (M5).

Fixtures

conformance/buckets/coalesce/known_hard_cases.ron (cases where conservative coalescing leaves moves George-Appel removes); conformance/buckets/coalesce/freeze_set.ron (moves refused by conservative coalescing, verified to remain as real moves in the output).

Pitfalls

Optimistic coalescing (merge first, check later) produces miscoloring because a merged high-degree node cannot always be un-merged cleanly — Briggs's conservative test exists precisely to make this impossible by construction (P8); a freeze that fails to invalidate prior Simplify decisions can loop indefinitely without the I8 cap (George-Appel's original paper assumes termination but does not bound iteration count in adversarial inputs).

⬜ Phase 6 — Spilling, Rematerialization & Stack-Slot Assignment §18

Objectives

Implement the spill-cost model (ADR-07), the remat-vs-spill decision (I14, ADR-14), and stack-slot sharing via a secondary interference graph (ADR-15, I10).

Deliverable

ra-spill producing spill/reload/remat instruction insertions and a stack-frame layout with shared slots where legal.

Acceptance

Spill-decision latency ≤ 100 µs per spilled vreg (§4); zero I10 violations on conformance/buckets/spill/; the remat_preferred.ron fixture shows ≥ 1 remat chosen over spill when a load-immediate-defined vreg is spill-candidate; overall spill-code overhead vs. LLVM RegAllocGreedy on the benchmark corpus stays within 5% (M9, §28).

Fixtures

conformance/buckets/spill/remat_preferred.ron, conformance/buckets/spill/loop_reload_penalty.ron (a reload inside a loop, weighted heavily by the cost model), conformance/buckets/spill/slot_sharing_disjoint.ron (two non-overlapping spilled vregs sharing one slot, verified by I10).

Pitfalls

A reload placed inside a loop body is far more expensive per-execution than one outside — the cost model must weight loop depth into the reload placement decision, not just the original spill-candidate selection (ADR-07's loop_depth³ term exists for exactly this); unconditional slot-sharing across the entire function (ignoring overlap) produces a wide, wasteful stack frame that also risks an I10 violation if two sharing vregs' ranges are later extended (e.g., by a spill-introduced reload's own short range abutting incorrectly).

⬜ Phase 7 — Resolver: Edge Splitting & Code Emission §19

Objectives

Implement the sole IR-mutation point (P9): apply an Assignment to the IR, always splitting critical edges (I5) before inserting phi-copies, and ordering copies to handle cyclic swaps.

Deliverable

ra-resolver::resolve emitting a fully lowered IR (physical registers and stack-slot accesses only, no vregs remaining) plus a ResolveReport.

Acceptance

100% of conformance/buckets/resolver/ fixtures pass, including the swap-cycle and critical-edge cases; resolution on a 1,000-function module completes in ≤ 500 ms p50 / ≤ 1 s p99 (M7, §28); zero I5 violations (every critical edge split, verified independently by the verifier's CFG scan).

Fixtures

conformance/buckets/resolver/critical_edge_split.ron, conformance/buckets/resolver/phi_swap_cycle.ron (the a→b, b→a case), conformance/buckets/resolver/vararg_shadow_space.ron (Win64 ABI interaction with resolver-inserted stack layout).

Pitfalls

A critical edge left unsplit silently miscompiles — a copy meant for one predecessor path lands in a block shared with another predecessor's phi resolution (§8.6-adjacent malformed-CFG class); incorrect copy ordering on a single edge (not handling the cycle case) overwrites a value before it is read — the classic "parallel copy" bug every phi-resolution implementation must handle explicitly, not implicitly via sequential emission.

⬜ Phase 8 — Linear-Scan Allocation (Poletto-Sarkar + SSA/Second-Chance) §20

Objectives

Implement the O(N) linear-scan allocator (Poletto-Sarkar 1999) with Wimmer-Franz (2010) SSA-aware interval splitting and an optional second-chance/backtracking mode (ADR-17, ADR-18), for the JIT consumer profile (P2).

Deliverable

ra-linear::LinearScanAllocator implementing both the basic Poletto- Sarkar walk and the Wimmer extension, selectable via LinearConfig.

Acceptance

100% of conformance/buckets/linear/ fixtures pass; the differential bucket (conformance/buckets/differential/) asserts linear-scan output is functionally equivalent to graph-coloring output on the same input (same observable program behavior, not identical register assignment); 10,000-vreg function completes in ≤ 50 ms p50 / ≤ 100 ms p99 (M6, §28); spill-code overhead vs. graph coloring documented at ≤ 30% more, as an expected (not regressed) figure (§4).

Fixtures

conformance/buckets/linear/split_points_wimmer.ron, conformance/buckets/linear/caller_saved_across_call.ron (I6 respected under linear scan), conformance/buckets/differential/graph_vs_linear.ron.

Pitfalls

Picking split points incorrectly (Wimmer's algorithm has a specific rule for where to split relative to loop boundaries and use density) degrades quality below the documented 30% ceiling; a linear scan that ignores the calling convention's caller-saved constraints (ADR-11) produces a miscompile across call instructions — I6 is enforced identically regardless of which allocator produced the Assignment.

⬜ Phase 9 — Verification, Differential Conformance & Fuzzing §21

Objectives

Implement ra-verifier (I1–I14, §7) as an independent reconstruction (not a re-check of the same data structures under test, per §8.7), the differential conformance harness, and the four fuzz targets (P11).

Deliverable

ra-verifier returning Vec<VerifierError>; conformance/cli emitting a JSON pass/fail report per bucket; four fuzz targets running in CI (M11).

Acceptance

100% of conformance/buckets/verifier/ fixtures (including injected_missing_edge.ron, §8.7) correctly produce the expected violation; 10,000-vreg function verification completes in ≤ 100 ms p50 (M8, §28); each of the four fuzz targets runs 5 minutes per CI PR with zero panics (M11); the differential/ bucket's full corpus (§21.2) runs in under 5 minutes (§4).

Fixtures

conformance/buckets/verifier/injected_missing_edge.ron (§8.7's canonical regression), conformance/buckets/verifier/negative_corpus/ (fixtures that must produce a VerifierError, proving no false negatives), conformance/buckets/differential/graph_vs_linear.ron (shared with Phase 8, §20.5).

Pitfalls

A verifier that re-derives its checks from the same InterferenceGraph instance under test cannot catch a systematic construction bug (§8.7) — the independent-reconstruction discipline is the single most important design decision in this phase and is the most commonly skipped shortcut in ad hoc allocator implementations; a false positive in the verifier (flagging a legal allocation as invalid) halts the pipeline exactly like a true positive, so the negative corpus (fixtures known-valid) is as important as the positive one.
