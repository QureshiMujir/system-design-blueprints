1. Goal

1.1 Precise Engineering Scope

Build a self-contained Graph Neural Network library in Python with NumPy-only numerics (no PyTorch, TensorFlow, JAX, DGL, PyG, SciPy, or any external autodiff/GNN dependency). A user expresses a graph (node features, edge index, optional edge features) plus a stack of message-passing layers, and the library performs forward inference and gradient-based training entirely on a from-scratch reverse-mode autodiff tape over NumPy arrays. The central abstraction is message passing: gather source-node features along edges → compute message → scatter/segment-aggregate (sum/mean/max) into destination nodes → update. Every published layer — GCN (Kipf & Welling), GraphSAGE (mean/pool aggregators + neighbor sampling), GAT (multi-head edge attention), GIN (sum aggregator + MLP) — is a configuration of this one primitive. The library covers three task families: transductive node classification (full-batch, Cora-style citation graph + masks), link prediction (edge scoring with negative sampling), and graph classification (mini-batched block-diagonal graphs + readout pooling). It ships losses (cross-entropy, BCE), from-scratch optimizers (SGD-momentum, Adam) with L2 weight decay, and the numerical machinery GNNs demand: symmetric adjacency normalization (Â = D^-1/2 (A+I) D^-1/2), degree handling, softmax/attention stability, dropout (feature + edge), and BatchNorm/LayerNorm on node features.

The contract is seed-deterministic single-platform reproducibility: the same graph + model + seed + hyperparameters yields identical parameters and predictions on the same NumPy/BLAS build. Bit-exact cross-platform reproduction is an explicit non-goal (float reduction order in scatter-add, BLAS threading).

1.3 Non-Goals

  • No GPU/CUDA/SIMD-handwritten kernels; CPU + NumPy only — PhaseDeferred("FINAL_BLUEPRINT §24.7").
  • No external autodiff; the tape (Phase 2) is the sole gradient source (P6).
  • No spectral GNNs (ChebNet, full graph Fourier), no relational/heterogeneous GNNs (RGCN) in Phase 0 — PhaseDeferred("FINAL_BLUEPRINT §19.2").
  • No dynamic/temporal graphs, no graph generation (GraphVAE, GraphRNN).
  • No large dataset downloads; all datasets are small + committed or synthetically generated.
  • No subgraph samplers beyond GraphSAGE neighbor sampling (Cluster-GCN, GraphSAINT deferred).
  • No distributed training, parameter servers, or model parallelism.
  • No cross-platform bit-exactness; only single-platform seed determinism (scatter-add float order).
  • No float32 mixed-precision path; float64 throughout for gradient-check fidelity.

1.4 Intended Deployment Model

  • Importable library (import gnn): build a Graph, stack Sequential([GCNConv(...), ReLU(), GCNConv(...)]), call model.forward(graph) / Trainer(model, ...).fit(), receive trained params + metrics.
  • CLI tool (gnn-cli): train --dataset cora --model gcn --layers 2 --hidden 16 --epochs 200 --seed 7 --out run.npz; eval run.npz; predict run.npz --nodes ...; example.
  • Single process, single host. No server, no daemon, no network surface. Input graph + model config are trusted (run in-process).
  • Optional process-pool only for embarrassingly parallel hyperparameter sweeps (independent seeds via SeedSequence.spawn), not for intra-model parallelism.

1.10 Language Selection — Python (NumPy only)

A GNN's defining feature is dynamic, data-dependent message passing: the computation graph is shaped by the graph topology (gather along edges, scatter into nodes, neighbor fanout), not a static tensor program. Expressing this with eager NumPy + a tracing reverse-mode tape is legible and directly testable; the same in a static language demands a graph IR or kernel DSL that obscures the pedagogy (which is message passing, normalization, attention, oversmoothing — the point). The numeric hot path (matmul, segment reductions) is array-shaped and delegates to NumPy/BLAS, so interpreter overhead lands on orchestration, not arithmetic. Float64 throughout for gradient-check fidelity. Reproducibility is seed-based, not bit-exact (scatter-add accumulation order, BLAS reduction order). Rust was rejected: building dynamic message passing + reverse-mode AD over sparse, data-shaped computation in Rust triples the surface area (ownership of the tape, sparse-tensor abstractions) for no pedagogical gain on the algorithms (GCN/SAGE/GAT/GIN). C++ rejected for the same reason plus toolchain friction and the temptation to lean on Eigen (a "from-scratch" violation). The autodiff, graph ops, layers, optimizers, and training loop are all hand-written Python over NumPy arrays. This project deliberately reuses the reverse-mode-autodiff pattern from project 112 (Autograd) specialized to graph operations.

2. Why Build This

2.1 Unique Systems Knowledge Taught

  • How an arbitrary graph topology becomes a differentiable computation through the gather→message→scatter→update decomposition, and why gather and scatter_add are exact reverse-mode adjoints of each other.
  • Why GCN, GraphSAGE, GAT, and GIN are all the same primitive with different message/aggregate/update, and what each design choice trades (expressivity vs stability vs cost).
  • Why symmetric normalization Â = D^-1/2 (A+I) D^-1/2 keeps repeated propagation stable, and how its omission causes feature-magnitude blow-up or collapse.
  • How oversmoothing arises (repeated low-pass filtering drives node representations to a degree-weighted constant) and how depth, residuals, and normalization fight it.
  • How attention over edges (GAT) is computed and normalized with a numerically stable segment softmax, and why naive per-edge softmax overflows.
  • How reverse-mode AD over sparse, data-dependent operations works, and why the scatter-add adjoint must accumulate (not overwrite) to be correct.

2.2 Historical and Architectural Significance

Spectral GNNs (Bruna 2014, Defferrard 2016) framed graph convolution via the graph Laplacian; Kipf & Welling (2017) simplified this to the now-canonical GCN propagation rule; GraphSAGE (Hamilton 2017) made GNNs inductive and scalable via neighbor sampling; GAT (Veličković 2018) introduced attention over edges; GIN (Xu 2019) connected GNN expressivity to the Weisfeiler-Lehman test. Gilmer (2017) unified these under Message Passing Neural Networks (MPNN). This project reconstructs that lineage from first principles: the same engine that classifies Karate-club nodes classifies citation-graph papers and whole molecules, because message passing is decoupled from layer identity by one primitive.

2.3 Engineering Muscles Developed

  • Building and validating a reverse-mode AD tape with sparse gather/scatter against finite differences.
  • Reasoning about invariants (gradient correctness, permutation equivariance, normalization correctness, aggregation associativity) and turning each into an executable test.
  • Numerical robustness: stable softmax/attention, degree-normalization edge cases (isolated nodes), exploding/vanishing gradients with depth.
  • Designing a small Module/Parameter framework and an optimizer from scratch.
  • Diagnostics-driven validation: trusting a layer only after gradcheck + equivariance + a known-answer (Karate/Cora) pass.

2.4 Production Engineering Concepts Exercised

  • Determinism + seed management across stochastic ops (dropout masks, neighbor sampling, negative sampling, weight init).
  • Sparse-vs-dense efficiency tradeoffs (when COO scatter beats dense Â·X matmul).
  • Observability: per-epoch metrics (loss, train/val/test accuracy or AUC), gradient norms, feature-norm-per-layer (oversmoothing signal).
  • Conformance harness: known-answer datasets (Karate club community structure, Cora accuracy band) as golden references.
  • Graceful degradation: NaN/Inf guards that fail loud; isolated-node and empty-graph handling; gradient clipping.

2.6 Calibration Value

After this project, "train a GNN" stops being a model = GCN(); model.fit() library call and becomes a transparent pipeline: build graph → normalize adjacency → gather along edges → message → scatter-aggregate → update → readout → loss → backprop through the tape → optimizer step. The engineer can debug a non-learning GNN by reading per-layer feature norms (oversmoothing), gradient norms (vanishing/exploding), and attention distributions, and can defend why a model generalizes with val/test accuracy and equivariance guarantees rather than faith.

What Mastery Looks Like

  • Reverse-mode AD through sparse, topology-dependent computation — can derive and implement the gather/scatter adjoint duality from first principles and verify it with a finite-difference harness (Phase 2).
  • Message-passing abstraction mastery — can express any published MPNN layer (GCN, SAGE, GAT, GIN) purely as overrides of message/aggregate/update on a shared base, and prove why gather/scatter never need reimplementation (Phase 4).
  • GNN-specific numerical reasoning — can diagnose oversmoothing from Dirichlet-energy telemetry, fix it with residual connections or EdgeDropout, and separate it from vanishing-gradient failure by inspecting per-layer gradient norms (Phase 12).
  • Stable attention computation — can implement multi-head segment softmax over edges without overflow for arbitrary logit magnitudes, and explain why per-destination normalization is required (Phase 8).
  • Principled optimizer construction — can hand-derive SGD+momentum and Adam updates from the bias-correction math and validate each against a closed-form quadratic trajectory (Phase 10).
  • Inductive generalization via neighbor sampling — can construct the bipartite k-hop sampled subgraph, remap node IDs correctly, and prove the sample is an unbiased estimator of the full-batch gradient under mean aggregation (Phase 7).
  • Graph-level task design — can compose permutation-invariant readout (add/mean/max pooling over the batch index) with a mini-batched BatchedGraph, explain why block-diagonal disjoint union is sufficient, and validate invariance formally (Phase 9).
  • Conformance-driven correctness discipline — can write a gradcheck harness, an equivariance property test, and a reference-band integration test, and use them to gate every layer before trusting its output (Phase 13).

3.2 Subsystem Descriptions

gnn.core — Owns the numeric contract: float64 everywhere, the RNG abstraction (a thin wrapper over numpy.random.Generator seeded by SeedSequence), and numerically stable primitives (logsumexp, segment_softmax with per-segment max subtraction, finite-guards). All randomness — dropout masks, neighbor sampling, negative sampling, weight init — flows through this layer so runs are reproducible. Defines the exception hierarchy (ShapeError, NonFiniteError, GraphError, DimMismatchError, NotImplementedFeature). No learning logic.

gnn.autodiff — Reverse-mode AD over NumPy arrays via a dynamically recorded tape (Wengert list). Each primitive op records inputs, output, and a vector-Jacobian-product (vjp) closure. The graph-specific ops are gather (rows of X by index) and scatter_add/segment_sum/segment_mean/segment_max — gather's adjoint is scatter_add and vice-versa, the load-bearing duality of the whole library. grad/value_and_grad seed the output adjoint with 1.0 and sweep the tape in reverse. Validated against central finite differences (I4) — the highest-leverage test in the project.

gnn.graph — The Graph container: node feature matrix X (N,F), edge_index (2,E) (source row, destination row), optional edge_attr (E,Fe), labels y, boolean train/val/test masks. Sparse representation in COO (edge_index) with on-demand CSR (sorted by destination) for efficient segment ops. Utilities: add_self_loops, to_undirected, degree, symmetric normalization (Â = D^-1/2 (A+I) D^-1/2) and row normalization, and BatchedGraph (disjoint block-diagonal union of many graphs with a batch index for pooling). Validates indices, dtypes, shapes (I-graph).

gnn.message — The message-passing primitive and the conceptual center. MessagePassing defines the pipeline gather(X, edge_index[0]) → message(x_i, x_j, edge_attr) → aggregate(messages, edge_index[1], reduce) → update(aggr, X). aggregate dispatches to segment sum/mean/max over destination indices. edge_softmax (used by GAT) normalizes per-destination over incoming edges via segment_softmax. Every layer subclasses this and overrides message/update; the base owns gather, scatter, and shape contracts (P11).

gnn.nn — Parameterized building blocks and the Module/Parameter registry: Linear (Xavier/He init), MLP, activations (ReLU, LeakyReLU, ELU, Sigmoid, Tanh), Dropout (feature) and EdgeDropout (drops edges), BatchNorm/LayerNorm on node features, and Sequential for layer stacking. A Module recursively registers Parameters (each a tape Node in training); parameters() yields them for the optimizer; train()/eval() toggle dropout/norm behavior.

gnn.layers — The four message-passing layers, each a MessagePassing subclass: GCNConv (normalized-adjacency propagation), SAGEConv (mean or pool neighbor aggregation + self concat), GATConv (multi-head attention over edges via edge softmax), GINConv (sum aggregation + MLP update, with learnable/fixed ε). Each declares which invariants it satisfies (equivariance, normalization).

gnn.pool — Graph-level readout for BatchedGraph: global_add_pool, global_mean_pool, global_max_pool aggregate node embeddings per graph using the batch segment index. Each is permutation-invariant (I-perm-inv); they are special cases of segment aggregation over the batch index rather than the edge index.

gnn.loss — cross_entropy (multiclass node/graph), bce_with_logits (binary/link), l2_penalty (weight decay term), plus masked variants that restrict node-classification loss to a boolean mask. Link prediction scores node-pair embeddings (dot/MLP) against positive + negatively-sampled edges. All in log-space where applicable (P5).

gnn.optim — From-scratch optimizers: SGD (with momentum), Adam (bias-corrected first/second moments). zero_grad clears adjoints; step applies updates to Parameters; supports decoupled/standard L2 weight decay and gradient clipping by global norm. No autograd dependency — reads adjoints from the tape sweep.

gnn.train — The driver. Trainer.fit runs full-batch transductive training (one forward over the whole graph, masked loss), mini-batch graph-classification (iterate BatchedGraph batches), or neighbor-sampling training (GraphSAGE k-hop fanout per minibatch). Manages train/val/test masks, early stopping on val metric, checkpointing to NPZ, per-epoch metrics, and seed provenance. gnn.data provides datasets; gnn.cli is the entry point.

6. Design Principles

P1. Correctness Before Speed

The forward function must be the exact mathematical layer, and the gradient must be its exact adjoint. Every optimization (sparse fusion, caching) is rejected if it changes the computed value or gradient beyond float noise. Tradeoff: slower than fused frameworks. Violation example: caching a normalized Â that is stale after add_self_loops silently changes the propagation.

P2. Message Passing Is the One Abstraction

GCN/SAGE/GAT/GIN differ only in message/aggregate/update; none reimplements gather or scatter. Tradeoff: a thin layer of indirection. Violation: a layer that hand-rolls its own neighborhood loop cannot be reused, sampled, or batched and will drift from the tested primitive (P11).

P3. Gather and Scatter Are Adjoints

gather's reverse-mode vjp is scatter_add and scatter_add's vjp is gather. This duality is the backbone of AD through graphs. Tradeoff: none. Violation: implementing scatter's gradient as anything but a gather makes every GNN sample a subtly wrong gradient that gradcheck (I4) is built to catch.

P4. Scatter-Add Must Accumulate, Never Overwrite

Multiple edges target the same destination node; the aggregation must sum contributions (np.add.at / bincount semantics), not last-write-wins. Tradeoff: cannot use plain fancy-index assignment. Violation: out[idx] = vals drops all but one incoming message per node — the most common and most silent GNN bug.

P5. Numerically Stable Softmax/Attention

Edge attention and class logits go through softmax with per-segment (or per-row) max subtraction in log-space. Tradeoff: an extra max+subtract pass. Violation: raw exp(logits) overflows for moderate attention scores, making every attention weight NaN.

P6. Gradients From One Source of Truth

Every parameter gradient comes from the AD tape over the same forward code; no hand-derived gradients. Tradeoff: tape overhead. Violation: a hand-coded GCN gradient inconsistent with its forward trains to a different (wrong) model while forward unit tests pass.

P7. Permutation Equivariance/Invariance by Construction

Node-level layers are permutation-equivariant (relabel nodes → outputs relabel identically); graph readout is permutation-invariant (relabel → identical graph output). Tradeoff: forbids position-dependent ops without positional features. Violation: a layer that depends on node index order (not topology) breaks on isomorphic graphs and fails the equivariance test (I-perm).

P8. Fail Loud on Non-Finite

NaN/Inf in any activation, loss, or gradient aborts the step with a typed error and context (layer, parameter, epoch), never a silent skip. Tradeoff: a run dies rather than limps. Violation: silently zeroing NaN gradients masks exploding gradients / bad init and produces a model that "trains" to garbage.

P9. Determinism Through Explicit RNG

No global RNG. Dropout masks, neighbor sampling, negative sampling, and weight init all draw from an explicit, seeded Generator. Tradeoff: must thread RNG through training. Violation: global np.random makes runs irreproducible and invalidates seed-pinned conformance.

P10. Train/Eval Mode Is Explicit

Dropout, edge-dropout, and BatchNorm behave differently in train vs eval; the mode is an explicit flag on every Module. Tradeoff: callers must set mode. Violation: leaving dropout active at eval reports noisy, pessimistic accuracy; leaving BatchNorm in batch-stats mode at eval makes predictions batch-dependent.

P11. The Graph Is Data, the Layer Is Generic

A layer never special-cases a particular graph; it consumes (X, edge_index, edge_attr). This decouples layers from topology so the same layer runs full-batch, mini-batched, or sampled. Violation: a layer assuming a fixed N or a particular degree distribution cannot be batched or sampled.

P12. Observability by Default

Every epoch emits metrics (loss, train/val/test accuracy or AUC), and debug mode emits per-layer feature norms (oversmoothing signal), gradient global-norm, and attention-entropy. Tradeoff: minor logging cost. Violation: a model that only prints final accuracy is undebuggable when it fails to learn (vanishing gradient vs oversmoothing vs bad lr are indistinguishable without these signals).

P13. Bounded, Sparse-Aware Resource Use

Propagation uses sparse gather/scatter (O(E)) rather than dense N×N adjacency matmul whenever E ≪ N²; activation memory is bounded and documented per layer. Tradeoff: code must handle both COO and CSR. Violation: materializing a dense N×N Â for a 10⁵-node graph OOMs instantly.

8.2 Message Passing as the Universal Layer

A layer is one function over (X, edge_index, edge_attr):

propagate(X, edge_index, edge_attr) — one straight-line pass, no branching:
  src, dst  = edge_index                                     # (E,), (E,)
  x_j       = gather(X, src)                                 # (E,F) source features per edge
  x_i       = gather(X, dst)                                 # (E,F) destination features per edge
  m         = message(x_i, x_j, edge_attr)                   # (E,F') per-edge messages
  aggr      = aggregate(m, dst, N, reduce="sum")              # (N,F') segment reduce
  result    = update(aggr, X)                                # (N,F'') new node features

Every published layer overrides only message/aggregate/update; the base owns gather/scatter/shape contracts (P2, P11). This decoupling is why the same layer runs full-batch, mini-batched (BatchedGraph), and neighbor-sampled.

8.5 Gather / Scatter Semantics (State + Adjoint)

gather:      Y = X[idx]                             # Y:(E,F), idx:(E,) in [0,N)
scatter_add: out[k] = Σ_{e : dst[e]=k} vals[e]       # accumulate into node k, never overwrite (P4,I3)

adjoint duality (I2,I3):
  d/dX  of  gather(X, idx)      = scatter_add(grad_Y, idx, N)
  d/dvals of scatter_add(vals)  = gather(grad_out, dst)

segment_sum = scatter_add; segment_mean = scatter_add / degree (broadcast); segment_max = scatter-max (gradient routes to the arg-max edge only — a select, like maxpool). The max adjoint must remember which edge won per node.

8.6 GCN Forward (Sequence)

Â = normalize(add_self_loops(A))                     # symmetric, precomputed weights (I7)
H0 = X
layer l = 1..L:  Z   = H_{l-1} @ W_l                  # (N,F_l) linear transform
                 H_l = Â · Z   (== segment_sum over edges of norm_w * gather(Z,src))  # propagate
                 H_l = activation(H_l)  (+ dropout in train)  # ReLU except last
logits = H_L                                          # (N, C)
loss = masked_cross_entropy(logits, y, train_mask)

Propagation is sparse SpMM via gather+segment_sum (P13), not a dense N×N matmul, for E ≪ N².

8.7 GAT Attention (Sequence)

head h = 1..H:  Wx   = X @ W_h                                        # (N, F')
                e_ij = LeakyReLU( a_h^T [Wx_i ‖ Wx_j] )   over edges   # (E,) raw scores
                α_ij = segment_softmax(e_ij, dst)     # per-destination softmax (I11, P5)
                m_e  = α_ij * Wx_src                   # (E, F')
                H_h  = segment_sum(m_e, dst, N)        # (N, F')
H = concat_heads(H_h)  (layer1) | mean_heads(H_h)  (output layer)

segment_softmax subtracts per-destination max before exp (stability). Multi-head: concat in hidden layers, average at output.

8.8 GIN Forward + WL Connection

H_l = MLP_l( (1+ε_l) · H_{l-1} + segment_sum( gather(H_{l-1}, src), dst, N) )

Sum aggregation (not mean/max) makes GIN as discriminative as the 1-WL test (Xu 2019): mean/max lose multiplicity information (e.g. cannot distinguish a node with 2 identical neighbors from 1). ε can be fixed (0) or learnable. This is the expressivity invariant motivating sum.

8.9 BatchedGraph (Mini-Batch Construction)

Inputs: graphs g1..gk with (N1,E1),...,(Nk,Ek)
X_batch     = concat([X1,...,Xk])              # (ΣN, F)
edge_index  = concat with per-graph node offset (cumsum of N)   # block-diagonal
batch       = [0]*N1 + [1]*N2 + ... + [k-1]*Nk  # (ΣN,) graph id (for pooling)

The disjoint union is a single large graph with no inter-graph edges, so one message-passing pass processes the whole batch; gnn.pool uses batch (not edge_index) to read out per-graph embeddings.

  • Xavier/He sample variance within 5% of target.

13. Phase 2 — Reverse-mode autodiff engine (incl. graph ops)

13.1 Objectives

Build a dynamic-tape reverse-mode AD that differentiates exactly the operations used in message-passing GNNs, with the load-bearing gather/scatter_add/segment_* ops, exposing grad/value_and_grad, validated by central finite differences (I4). This is the single source of truth for all gradients (P6) and the duality core of the project (P3).

13.2 Detailed Implementation Steps

  • autodiff/tape.py: Node wrapping a NumPy array; an active-Tape stack records (output, parents, vjp) per op (Goodfellow Ch 6, ADR-3, ADR-4).
  • autodiff/ops.py: dense primitives + vjps: matmul → (g@bᵀ, aᵀ@g); relu → g·(x>0); leaky_relu/elu; sigmoid/tanh; softmax/log_softmax → (diag−outer) jvp (Bishop Ch 5); sum/mean → broadcast; concat → split; dropout → mask·g/keep (Srivastava 2014).
  • autodiff/graph_ops.py: gather(X,idx) forward X[idx], vjp scatter_add(g, idx, N) (I2, P3); scatter_add(vals,idx,N) forward accumulate via np.add.at/bincount, vjp gather(g, idx) (I2, I3, P4, ADR-8); segment_mean = scatter_add/degree (vjp divides); segment_max forward + record argmax, vjp routes grad to argmax edge only (Gilmer 2017).
  • autodiff/grad.py: forward builds tape; seed loss adjoint 1.0; reverse-sweep accumulating adjoints into Parameter.grad (sum over broadcast axes) (Goodfellow Ch 6); grad_check central differences (I4, Bishop Ch 5).

13.3 Deliverable

value_and_grad(f)(params) returns correct (value, grads) for composite functions incl. gather/scatter; grad_check passes on a battery including a full message-passing step.

13.4 Acceptance Criteria

  • grad_check passes (rtol 1e-5) for: linear+ReLU, softmax-cross-entropy, gather, scatter_add, segment_mean, segment_max, and a one-layer GCN propagation.
  • scatter_add with multiple edges to one node equals the analytic sum (I3).
  • Reverse pass cost ≤ 3× forward eval on a 1000-node, 5000-edge propagation.
  • No memory growth across repeated value_and_grad (tape released).

13.6 Pitfalls

  • Implementing scatter_add with out[idx]=vals (overwrite) drops messages (P4) — the canonical silent bug; use np.add.at/bincount.
  • Broadcasting in add/mul requires summing the adjoint over broadcasted axes; forgetting yields wrong-shaped grads.
  • segment_max ties: pick a deterministic argmax (first) so the gradient is reproducible (P9).
  • In-place NumPy mutation of a node's value corrupts the tape; ops must be pure.

13.7 Performance Concerns

  • np.add.at is slow; prefer bincount-based or sorted-segment reductions for the hot path; document the tradeoff.
  • Keep ops coarse (array-level), not per-edge Python loops.
  • Avoid retaining intermediate arrays beyond the reverse sweep.

13.8 Edge Cases

  • Empty edge set → gather/scatter return empty/zeros; gradients zero. Re-used subexpressions accumulate adjoints (DAG, not tree). Single node, no edges → scatter into N=1.

13.9 Failure Analysis

A wrong gather/scatter vjp makes every GNN train a subtly wrong model while forward tests pass (I2, I4). Detection: mandatory grad_check in CI on every layer. This is the highest-leverage test in the project.

13.10 Operational Notes

Expose grad_check as a tools/ CLI so layer authors can validate custom layers. Emit a one-line AD profile (ops recorded, peak tape size, gather/scatter counts) under debug logging.

15.1 Objectives

Mental Models & First Principles

MM1 — Gather and Scatter are Exact Adjoints Expert insight: gather(X, idx) selects rows; its reverse-mode adjoint is scatter_add, and scatter_add's adjoint is gather. This is not an approximation — it is exact. What it predicts: any gradient through a GNN layer can be computed with one gather and one scatter. Bug class written without it: implementing the scatter gradient as anything other than a gather produces subtly wrong gradients that pass forward tests but train a wrong model (I2, I3). Applied in: Phase 2 (autodiff/graph_ops.py), Phase 4 (MessagePassing base).

MM2 — Message Passing Is a Factored SpMM Expert insight: every GNN propagation step is a sparse matrix-vector multiply in disguise: H_new = Â·(H·W). The sparse adjacency operator Â is applied via gather (source rows) + segment_sum (accumulate to destination), never by materializing the dense N×N matrix. What it predicts: propagation cost is O(E·F), not O(N²·F), for E≪N². Bug class written without it: materializing a dense Â for a 10⁵-node graph exhausts RAM in seconds (P13, ADR-7). Applied in: Phase 3 (sym_norm), Phase 6 (GCNConv §8.6), Performance Engineering.

MM3 — Symmetric Normalization as Spectral Radius Control Expert insight: Â = D̃^-1/2(A+I)D̃^-1/2 has spectral radius ≤ 1, so repeated multiplication Â^L·X does not blow up (bounded by the initial norm). The 1/√(d_i·d_j) per-edge weight is the key: it balances the contribution from high-degree hubs. What it predicts: without normalization, propagation magnitudes grow (or collapse to zero for isolated nodes). Bug class written without it: raw A·H propagation causes feature-magnitude explosion in any graph with a hub node (I7, ADR-9). Applied in: Phase 3 (§8.4), Phase 6 (GCNConv), Phase 12 (numerical hardening).

MM4 — Oversmoothing Is Low-Pass Filtering to Convergence Expert insight: each GCN propagation step applies a low-pass filter (Â is a smoothing operator). With enough layers, all node representations converge to a vector proportional to the eigenvector associated with the largest eigenvalue — a degree-weighted constant that carries no local discriminative information. What it predicts: test accuracy first rises then falls as layer count increases, independently of model capacity. Bug class written without it: adding depth to fight underfitting actually hurts a well-specified shallow model (Li et al. 2018, Oono & Suzuki 2020). Applied in: Phase 12 (oversmoothing telemetry, §23.2), Failure Modes.

MM5 — Sum Aggregation Preserves Multiplicity; Mean and Max Do Not Expert insight: sum(neighbor features) counts repeated neighbors; mean and max collapse multiplicity (two identical neighbors look the same as one). The Weisfeiler-Lehman test distinguishes graphs by multiset of neighborhood features. Sum aggregation replicates this; mean/max strictly weaker. What it predicts: GIN with sum is WL-expressive; a mean-GIN cannot distinguish certain non-isomorphic graphs. Bug class written without it: using mean instead of sum in GIN produces a correctly-running but expressivity-weakened model that fails the multiplicity fixture (§8.8, Xu et al. 2019, ADR-11). Applied in: Phase 8 (GINConv), Phase 9 (readout).

MM6 — A Future/Module Is a State Machine; the Tape Is Its Accumulator Expert insight: a Node on the autodiff tape is not a value — it is a value plus a deferred adjoint accumulator. The reverse sweep visits nodes in reverse topological order and accumulates (sums) incoming adjoint contributions from all children (important for DAG reuse). What it predicts: re-used subexpressions double their contribution to the gradient unless the tape accumulates correctly. Bug class written without it: overwriting the adjoint instead of summing it (tree semantics) produces wrong gradients for any shared subexpression (I4, P6, Goodfellow Ch 6). Applied in: Phase 2 (autodiff/tape.py, autodiff/grad.py).

MM7 — Dropout as Bernoulli Masking with Inverted Scaling Expert insight: dropout at train time multiplies each feature by Bernoulli(1−p) and divides by (1−p), so expected output equals the eval output exactly. This means no rescaling is needed at eval — the model is deterministic at inference without any code change. What it predicts: omitting the 1/(1−p) scaling at train time makes the model see smaller activations at train than at eval, biasing every layer's weight. Bug class written without it: scaling at eval time instead of train time (original Srivastava formulation) requires a code path switch that is easy to misapply (P9, P10, I10, Srivastava 2014). Applied in: Phase 5 (nn/dropout.py), Phase 11 (Trainer eval mode).

MM8 — Neighbor Sampling as Variance-Bounded Gradient Estimation Expert insight: sampling k neighbors uniformly estimates the full neighborhood mean with variance 1/(k·d) where d is the true degree. The estimate is unbiased under mean aggregation. Each additional hop multiplies the sample size by k, so 2-hop sampling with fanout [25,10] touches at most 250 nodes per target. What it predicts: training with sampling converges to the same optima as full-batch but with O(fanout) cost per target rather than O(d^L). Bug class written without it: assuming the sampled subgraph is the same graph as the full training graph and recomputing global normalization instead of subgraph normalization (Hamilton et al. 2017, ADR-17). Applied in: Phase 7 (train/sampler.py, §18.2), Scalability Analysis.

PyTorch Geometric made the one key decision to rely on torch_scatter and torch_sparse C++/CUDA extensions rather than pure Python, gaining GPU throughput at the cost of a non-trivial build chain. This wins in any setting where GPU training is the primary constraint — it is the right choice for production GNN training at scale.

It wins in large-scale heterogeneous graph workloads (OGB, industrial recommendation systems) where the C++ SpMM kernels and flexible backend are the constraint, not pedagogy.

Spektral chose TF/Keras as its host, which wins when the rest of a machine learning pipeline is already in TensorFlow and operator-level consistency (layer.call, model.fit) matters more than flexibility in the message-passing abstraction.

Back-of-Envelope Capacity Model

All numbers derived from the System Constraints table (§4.1).

1. Per-layer forward FLOPs — linear transform Formula: N × F_in × F_out multiplications. Derivation: default N=10⁵ nodes, F=10³ features, F'=16 hidden (from constraints table). 10⁵ × 10³ × 16 = 1.6 × 10⁹ FLOPs for the first GCN layer transform. For the 2-layer default: Layer 1 (F=1433→16): 2708 × 1433 × 16 ≈ 6.2 × 10⁷; Layer 2 (16→7): 2708 × 16 × 7 ≈ 3 × 10⁵. Cora is small; cost is dominated by Layer 1.

2. Per-layer propagation FLOPs — gather+segment_sum Formula: E × F reads + accumulates (gather is indexed copy; segment_sum is E additions into N bins). Derivation: Cora E=5429, F=16 (after transform): 5429 × 16 ≈ 8.7 × 10⁴ operations per propagation step. Ceiling graph: E=10⁶, F=10³: 10⁹ operations.

3. Activation memory per layer Formula: L × (N × F + E × F_msg) float64 arrays held for the reverse sweep. Derivation (§4.1 constraint "Memory"): L=2 layers, N=10⁵, F=10³: node features 2 × 10⁵ × 10³ × 8 bytes = 1.6 GB. At Cora scale: 2 × 2708 × 1433 × 8 ≈ 62 MB. The constraint table sets the ceiling N≤10⁵, F≤10³, giving 1.6 GB active tensors — fits on a 16 GB workstation.

4. Reverse-pass overhead Formula: ~3× forward eval (from constraints table "Gradient overhead ≤3× forward"). Derivation: forward cost (Cora Layer 1) ≈ 6.2×10⁷ FLOPs → reverse pass ≤ 3 × 6.2×10⁷ ≈ 1.9×10⁸ FLOPs per epoch. At 200 epochs: 3.7×10¹⁰ total FLOPs — sub-second on a modern CPU at ~10¹⁰ FLOP/s.

5. Neighbor sampling working set Formula: fanout[0] × fanout[1] × batch_size nodes touched per minibatch. Derivation (§4.1 "Neighbor sampling [25,10]"): 1 target node → 25 1-hop neighbors → each has 10 2-hop neighbors: 25 × 10 = 250 nodes per target. Batch of 512 targets: 512 × 250 = 128,000 node feature lookups = 128,000 × 1433 × 8 bytes ≈ 1.5 GB per minibatch. This is the practical memory bound for sampled training on Cora-sized graphs.

6. Attention FLOPs per GAT layer Formula: heads × E × (2 × F' + 1) for score computation + heads × E × F' for weighted message. Derivation (§4.1 "GAT default 8 heads × 8 hidden"): E=5429, heads=8, F'=8: score 8 × 5429 × 17 ≈ 7.4×10⁵; weighted msg 8 × 5429 × 8 ≈ 3.5×10⁵. Total: ~1.1×10⁶ FLOPs per GAT layer — ~10× more than a GCN layer at the same hidden dim.

7. segment_softmax memory Formula: 2 × E per segment pass (one for max subtraction, one for sum normalization) + E for output. Derivation: E=5429, float64: 3 × 5429 × 8 = 130 KB. Negligible. At E=10⁶: 24 MB — still fits in L3 cache.

8. Tape memory for one forward pass Formula: num_ops × (output_array_size + closure_overhead). Derivation: a 2-layer GCN forward records ~12 ops (matmul×2, gather×2, scatter×2, relu×1, dropout×1, log_softmax×1, CE×1, mask×1). Per-op overhead ~1 output array: 12 × N × F × 8 bytes. Cora: 12 × 2708 × 16 × 8 ≈ 4 MB. Ceiling: 12 × 10⁵ × 10³ × 8 = 9.6 GB — exceeds RAM; justifies the E≪N² sparse requirement (§4.1).

9. Checkpoint size Formula: Σ param_shapes × 8 bytes (float64 NPZ). Derivation: default 2-layer GCN: W1 (1433×16) + b1 (16) + W2 (16×7) + b2 (7) = 22,928 + 16 + 112 + 7 = 23,063 parameters × 8 bytes = ~185 KB. Even a 10-layer model with F=256 hidden stays under 10 MB — disk is not a constraint.

10. Dense adjacency memory (why we avoid it) Formula: N² × 8 bytes. Derivation: §4.1 ceiling N=10⁵: (10⁵)² × 8 = 80 GB. Comparison to sparse COO: E=10⁶ edges × 2 × 4 bytes (int32 edge_index) = 8 MB. Ratio: 80 GB / 8 MB = 10,000× — this single number justifies ADR-7 completely (P13).

Alternative Architectures

Alt-A: Spectral GNN with Full Laplacian Eigenbasis

Show the original text diagram
Input graph G  -->  Compute Laplacian L = D - A
                -->  Eigendecompose: L = U Λ Uᵀ
                -->  Spectral filter: y = U · g(Λ) · Uᵀ · x
                      where g(Λ) is a learned diagonal filter
                -->  Node predictions

Regime where it wins: graphs where the spectral structure is the direct object of interest (e.g. graph signal processing, community detection via spectral clustering), and N is small enough that eigendecomposition (O(N³)) is tractable.

Real system that embodies it: Bruna et al. (2014) "Spectral Networks on Graphs" (ICLR 2014) — the original spectral GNN; also the full-graph Fourier convolution variant in Defferrard et al. (2016) before ChebNet's polynomial approximation.

Why this blueprint rejected it: eigendecomposition is O(N³) and produces a graph-specific basis; any new graph requires recomputation. The spectral filter does not generalize inductively to unseen graphs or nodes. The MPNN framework (Gilmer 2017) provides strictly greater scalability and generalization with no loss in expressivity for the tasks in scope. Deferred explicitly in §1.3 and §1.8.

Alt-B: Static-Graph Computation (No Dynamic Tape)

Define model as a static computation graph (DAG) once:
  Layer 1: Z1 = sym_norm(A) @ X @ W1
  Layer 2: Z2 = sym_norm(A) @ relu(Z1) @ W2
  Loss: cross_entropy(Z2[train_mask], y)

Compile graph -> run forward + backward via pre-compiled vjp schedule
No dynamic tape recording per forward pass

Regime where it wins: when the GNN architecture is fixed (same graph, same topology, same layer count), a compiled static graph avoids the per-forward tape overhead and enables aggressive kernel fusion (XLA, TorchScript). Wins in production inference with a frozen model on a fixed graph.

Real system that embodies it: TensorFlow 1.x (graph mode), TorchScript, JAX jit with static shapes, and the original Kipf GCN implementation (tkipf/gcn) in TF1.

Why this blueprint rejected it: message passing is data-dependent — the graph topology determines the computation structure, and in the neighbor-sampling case (Phase 7) the computation graph literally changes per minibatch. A static graph cannot represent this. The dynamic tape (ADR-4) is the only representation that handles data-dependent topology without manual re-specialization.

Alt-C: Dense Adjacency Matrix Approach

Precompute: A_norm = D^-1/2 @ (A + I) @ D^-1/2   # (N, N) dense float64
Each layer:
  H_new = relu( A_norm @ H @ W )                   # (N,F) = (N,N)@(N,F)@(F,F')
Readout: softmax( H_L )

Regime where it wins: small, nearly-complete graphs (N ≤ 500, edge density > 50%) where BLAS dgemm on the dense A_norm×H matmul has better cache utilization than scattered index operations, and where memory is not a constraint. Also wins in any setting where Â must be used repeatedly across many epochs (precomputed once, reused cheaply).

Real system that embodies it: Kipf's original pygcn implementation uses a scipy sparse matrix multiplication but can be run with dense NumPy for small graphs; several tutorial implementations materialize dense Â explicitly.

Why this blueprint rejected it: the §4.1 constraint table sets N≤10⁵ and E≤10⁶. Dense Â at N=10⁵ requires 80 GB of RAM (Capacity Model entry 10). The pedagogical goal requires the sparse path to be the primary path so that the library scales beyond toy examples. Dense adjacency is available as a degenerate case but is not the default.

Alt-D: Per-Node Python Loop (No Vectorized Gather/Scatter)

Structure (per-node scatter-free dataflow, one node at a time):
  for each node v:  neighbors(v) = {src : edge dst == v}
                    agg(v)       = Σ over neighbors(v) of X[src]   # manual sum
                    H_new(v)     = relu( (agg(v) + X[v]) @ W )
Contrast: N separate neighborhood reductions vs 1 gather + 1 segment_sum

Regime where it wins: for a debugger or interactive trace, a per-node loop makes the computation maximally inspectable — every node's neighborhood is explicit. Correct for tiny conformance tests.

Real system that embodies it: most early tutorial implementations of GCN (e.g. cs224w Stanford course notebooks) use explicit Python loops over nodes for pedagogical clarity.

Why this blueprint rejected it: a Python loop over N=2708 Cora nodes is ~100–1000× slower than vectorized gather/scatter because each iteration dispatches a Python function call and a NumPy slice. More critically, there is no path to integrate this with a tape-based autodiff: the loop body would need to be recorded per-iteration, producing a tape of N entries rather than 1 gather + 1 scatter_add. The gather/scatter abstraction (P2, P3, ADR-6) is both faster and the only form the tape can differentiate efficiently.
