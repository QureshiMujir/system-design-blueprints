⬜ Phase 1 — Core numeric substrate + RNG + errors + init §12

Objectives

Lock float64 policy, the Rng abstraction with spawnable independent streams, log-space primitives (logsumexp, segment_softmax), weight initializers (Xavier/He), finite-guards, and the typed error hierarchy. Everything stochastic and numerically delicate funnels through here (P9, P5, P8).

Deliverable

Importable gnn.core; python -c "from gnn.core import Rng, segment_softmax" works; segment_softmax matches per-segment reference; initializers produce correct-variance weights.

Acceptance
  • segment_softmax sums to 1 per segment; stable for scores up to ±700 (no overflow).
  • logsumexp matches naive for moderate inputs.
  • Rng.spawn(4) yields 4 streams with no detectable cross-correlation on 10⁶ draws.
  • Xavier/He sample variance within 5% of target.
  • mypy --strict gnn/core clean; pytest tests/core green.
Fixtures
Fixture Purpose Expected
core/segment_softmax.json per-segment normalize + stability rows sum 1; finite at ±700
core/logsumexp_extreme.json overflow safety finite
core/init_variance.json Xavier/He variance target ±5%
core/rng_independence.json stream independence |corr| < 3e-3
Pitfalls
  • segment_softmax over a segment with one edge → trivially 1; over an empty segment → must not divide by 0.
  • Reusing one Generator across processes (fork) duplicates streams — always spawn.
  • Xavier with wrong fan_in/fan_out for a layer of shape (in,out) (NumPy row-major) flips the variance.

⬜ Phase 2 — Reverse-mode autodiff engine (incl. graph ops) §13

Objectives

Build a dynamic-tape reverse-mode AD that differentiates exactly the operations used in message-passing GNNs, with the load-bearing gather/scatter_add/segment_* ops, exposing grad/value_and_grad, validated by central finite differences (I4). This is the single source of truth for all gradients (P6) and the duality core of the project (P3).

Deliverable

value_and_grad(f)(params) returns correct (value, grads) for composite functions incl. gather/scatter; grad_check passes on a battery including a full message-passing step.

Acceptance
  • grad_check passes (rtol 1e-5) for: linear+ReLU, softmax-cross-entropy, gather, scatter_add, segment_mean, segment_max, and a one-layer GCN propagation.
  • scatter_add with multiple edges to one node equals the analytic sum (I3).
  • Reverse pass cost ≤ 3× forward eval on a 1000-node, 5000-edge propagation.
  • No memory growth across repeated value_and_grad (tape released).
Fixtures
Fixture Purpose Expected
ad/gradcheck_suite.json analytic grads match central diff 1e-5
ad/scatter_accumulate.json duplicate dst (I3) sum, not overwrite
ad/gather_scatter_adjoint.json I2 duality vjp matches
ad/segment_max_argmax.json max routing grad to argmax edge only
ad/tape_release.json no leak RSS stable over 10⁴ calls
Pitfalls
  • Implementing scatter_add with out[idx]=vals (overwrite) drops messages (P4) — the canonical silent bug; use np.add.at/bincount.
  • Broadcasting in add/mul requires summing the adjoint over broadcasted axes; forgetting yields wrong-shaped grads.
  • segment_max ties: pick a deterministic argmax (first) so the gradient is reproducible (P9).
  • In-place NumPy mutation of a node's value corrupts the tape; ops must be pure.

⬜ Phase 3 — Graph container + sparse representation + normalization §14

Objectives

Implement the Graph container, COO/CSR sparse representations, self-loop/undirected utilities, symmetric and row normalization (I7), degree handling, and BatchedGraph block-diagonal union (8.9) — the data substrate every layer consumes (P11, P13).

Deliverable

Graph(...).validate() passes/raises correctly; sym_norm produces a symmetric operator with spectral radius ≤1; BatchedGraph.from_graphs([g1,g2]) yields one block-diagonal graph with correct batch index.

Acceptance
  • sym_norm weights symmetric (w(i,j)==w(j,i)); largest eigenvalue of Â ≤ 1+1e-9 (I7).
  • Isolated node handled (no NaN/div-by-zero in either norm).
  • BatchedGraph round-trips: per-graph slices via ptr recover the originals.
  • validate() raises GraphError on OOB edge_index, ShapeError on bad shapes (I13).

Pitfalls
  • Forgetting self-loops before sym-norm gives D^-1/2 A D^-1/2 (no self term) — a different, worse-performing operator; GCN needs A+I.

⬜ Phase 4 — Message-passing primitive §15

Objectives

Implement the MessagePassing base (gather→message→aggregate→update, 8.2) and segment aggregation (sum/mean/max) + edge_softmax, the one abstraction every layer subclasses (P2, P11), permutation-equivariant by construction (I5) and edge-order-independent (I8).

Deliverable

MessagePassing(aggr="mean").propagate(x, edge_index, N=N) computes the mean of neighbor features per node (a smoothing operator); gradient flows correctly through the whole pipeline.

Acceptance
  • Mean-aggregation propagate equals the analytic neighbor mean on a tiny graph (I1, I8).
  • grad_check passes on a propagate call (I4).
  • Permuting node order permutes outputs identically (equivariance, I5).
  • Shuffling edge order leaves outputs unchanged (I8).
Fixtures
Fixture Purpose Expected
mp/mean_aggregate.json correctness analytic neighbor mean
mp/permutation_equivariance.json I5 permuted output
mp/edge_shuffle_invariance.json I8 unchanged output
mp/edge_softmax.json I11 per-dst normalized
Pitfalls
  • Confusing src/dst in gather: messages flow src→dst; aggregating by src instead of dst computes the wrong neighborhood.
  • mean aggregation must divide by destination in-degree, not a constant; isolated dst → degree 0 guard.
  • edge_softmax must normalize per destination (incoming edges), not globally.

⬜ Phase 5 — nn building blocks (Linear, MLP, activations, dropout, norm) §16

Objectives

Implement the Module/Parameter registry with explicit train/eval mode (I10, P10), Linear/MLP, activations, Dropout/EdgeDropout (P9), and BatchNorm/LayerNorm on node features — the parameterized pieces layers compose.

Deliverable

A Sequential([Linear, ReLU, Dropout, Linear]) runs forward, exposes parameters, toggles train/eval; gradients flow to all parameters.

Acceptance
  • grad_check passes on Linear, MLP, each activation, BatchNorm, LayerNorm (I4).
  • Dropout: train mode masks ≈p fraction, scales correctly; eval mode is identity (deterministic, I10).
  • BatchNorm: eval uses running stats (batch-independent); train uses batch stats.
  • parameters() enumerates all weights exactly once (no double-count, no miss).
Fixtures

Pitfalls
  • Dropout scaling: inverted dropout scales by 1/(1−p) at train so eval is unscaled; forgetting biases magnitudes.
  • BatchNorm with batch size 1 (single graph) → zero variance; eps guard, or LayerNorm instead.
  • parameters() missing nested modules → optimizer doesn't update them (silent under-training).
  • EdgeDropout changing N's degree changes normalization — recompute or use raw aggregation.

⬜ Phase 7 — GraphSAGE + neighbor sampling §18

Objectives

Implement SAGEConv (mean + pool aggregators, self+neighbor concat, 8.3) and GraphSAGE neighbor sampling for scalable, inductive mini-batch training (k-hop fanout), with explicit seeded sampling (P9).

Deliverable

SAGEConv forward matches hand-computed mean/pool aggregation; neighbor-sampled training on a citation graph reaches accuracy comparable to full-batch within a tolerance band.

Acceptance
  • SAGE-mean forward matches analytic concat(self, neighbor-mean)@W (I1); grad_check passes (I4); equivariant (I5).
  • Pool aggregator: segment_max gradient routes to argmax edge (I2 via Phase 2).
  • Neighbor-sampled training accuracy within 3% of full-batch on the same graph (sampling is an estimator).
  • Sampling is reproducible under fixed seed (P9, I12).

⬜ Phase 8 — GAT (attention) + GIN (expressivity) §19

Objectives

Implement GATConv (multi-head additive attention over edges via stable edge_softmax, 8.7, I11, P5) and GINConv (sum aggregation + MLP update, WL-expressive, 8.8) — completing the layer zoo, each a MessagePassing instance (P2).

Deliverable

GAT forward matches a hand-computed 1-edge attention example; GIN forward matches the sum+MLP formula; both train on Cora (GAT) / a graph-classification set (GIN).

Acceptance
  • GAT attention weights sum to 1 per destination (I11); forward matches analytic on a tiny graph (I1); grad_check passes through softmax+attention (I4); equivariant (I5).
  • GIN sum aggregation distinguishes multiplicity (a node with 2 identical neighbors ≠ 1) where mean/max cannot (8.8 expressivity check).
  • GAT on Cora reaches a documented accuracy band (≈0.82–0.83); GIN on a TU-style set reaches a documented band.
  • Multi-head concat/mean shapes correct.
Fixtures
Fixture Purpose Expected
gat/attention_forward.json I1, I11 per-dst-normalized, analytic
gat/gradcheck.json I4 AD through softmax
gin/sum_expressivity.json 8.8 distinguishes multiplicity
gat/cora_band.json reference acc band
Pitfalls
  • GAT without per-destination max subtraction in edge_softmax overflows for moderate scores (P5) — all-NaN attention.
  • Multi-head: forgetting to concat vs mean at the right layer changes output dim and accuracy.
  • GIN with mean/max instead of sum silently loses expressivity (the whole point of GIN) — passes forward tests, underperforms.
  • LeakyReLU slope wrong (e.g. ReLU) zeroes negative attention scores, degrading attention.

⬜ Phase 10 — Losses + optimizers (SGD, Adam, L2) §21

Objectives

Implement classification losses (cross_entropy, bce_with_logits, masked variants, link-prediction scoring) in log-space (P5), and from-scratch optimizers (SGD+momentum, Adam) with L2 weight decay and gradient clipping (I14) — completing the training stack.

Deliverable

cross_entropy/bce_with_logits gradients match finite differences; SGD/Adam minimize a quadratic along the known trajectory; L2 + clipping work.

Acceptance
  • Loss grad_check passes (I4); masked CE ignores non-mask nodes exactly.
  • Adam on a convex quadratic matches the closed-form/reference trajectory (I14); SGD+momentum likewise.
  • L2 penalty gradient = 2·weight·W; clip caps global grad norm.
  • Link-prediction loss + AUC computed correctly on a toy graph.

Pitfalls
  • Numerically unstable cross-entropy (log(softmax) separately) underflows; use log_softmax (P5).

  • Coupled vs decoupled (AdamW) weight decay differ; pick and document one default.
  • Negative sampling drawing actual edges as "negatives" biases link-prediction; filter.

⬜ Phase 12 — Numerical hardening (oversmoothing, gradient scaling, sparse efficiency) §23

Objectives

Address the GNN-specific numerical pathologies: oversmoothing with depth (Li 2018), exploding/vanishing gradients, sparse-vs-dense efficiency, degree-normalization edge cases, and softmax/attention stability under extreme inputs (P5, P13, I7, I11).

Deliverable

An oversmoothing demonstration with telemetry + documented mitigations; benchmark establishing the sparse/dense crossover; hardened guards for degenerate degrees/logits.

Acceptance
  • Feature-norm/Dirichlet-energy telemetry shows expected collapse with depth and recovery with residual/JK (documented).
  • Gradient norms stay finite and bounded under clipping; init keeps early-layer gradients non-vanishing.
  • Sparse path faster than dense for the documented density range; both numerically equal within float tolerance.
  • No NaN/Inf across the degenerate-graph and extreme-logit corpus (I9, I11).
Fixtures
Fixture Purpose Expected
num/oversmoothing.json depth collapse energy decays; JK recovers
num/grad_norms.json scaling finite, bounded
num/sparse_vs_dense.json P13 sparse faster; equal values
num/extreme_logits.json I11 no overflow
Pitfalls
  • "Deeper is better" intuition is wrong for vanilla GCN — oversmoothing degrades >2–3 layers; document.
  • Residual connections across changing feature dims need projection.
  • Sparse np.add.at slowness can make the "sparse" path slower than dense for small dense graphs — benchmark, don't assume.
  • Clipping too aggressively stalls learning; too loose lets explosions through.

⬜ Phase 13 — Conformance, hardening, fuzzing, benchmarks §24

Objectives

Validate the library against analytic layer outputs and reference accuracy bands (Karate, Cora, GAT, graph-cls), fuzz graph/layer inputs for finite-output safety, benchmark propagation + training throughput, and harden error paths. Close or re-gate the deferred-feature list.

Deliverable

Green conformance report (Pass/Deferred per bucket), fuzz run clean over the corpus, committed benchmark baselines, runbooks.

Acceptance
  • All analytic layer-output buckets Pass within tolerance; full gradcheck suite green (I4).
  • Cora GCN ∈ [0.79,0.82]; GAT/Karate/graph-cls within documented bands.
  • Fuzz: ≥10⁴ random graphs/layers produce finite outputs or typed errors; zero uncaught exceptions.
  • Benchmarks within ±20% of committed baseline; no regression.

Pitfalls

  • Comparing to other frameworks' numbers without matching the recipe → false failures.
