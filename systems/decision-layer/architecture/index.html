capture-surface: VS Code extension; renders decision editor, drift inbox, anchor picker; holds no resolution logic; talks to lsp-bridge over LSP custom methods (decisionLayer/*).

lsp-bridge: Rust LSP server exposing dlcore over the Language Server Protocol; owns the editor session lifecycle, document sync (incremental, per section 3.4 of the LSP specification), and dispatch of custom requests.

ast-indexer: tree-sitter-backed parser pool; maintains one incremental parse tree per open file; applies edits via tree-sitter's InputEdit-equivalent range patch, not full reparse.

anchor-resolver: given an anchor and a current AST/text state, attempts resolution in precedence order (§8); returns ResolutionResult.

anchor-repair engine: orchestrates the named repair procedure (§8) when a resolver reports non-exact resolution; queues ambiguous cases for capture-surface confirmation.

drift-detector: compares resolved anchor state against the decision's recorded assertion; classifies into the five-way taxonomy (§8); emits DriftEvent.

decision-store: local, append-only, content-addressed op-log (I3, I4); sole writer of decision state; all other components read through it.

replay-engine: reconstructs the decision graph at any point by folding the op-log from genesis; used for verification (H-style self-check) and for team-backend ingestion.

sync-client: converts local op-log tail into SyncOp batches; handles retry, backoff, and conflict surfacing from the backend's merge response.

team-backend (API gateway + decision-graph service + Postgres + object storage): durable, multi-user store; owns tenant isolation, fork/supersede semantics, and the canonical merged op-log across contributors.

compliance-exporter: reads a ReplayCursor-bounded slice of the graph and content blobs; emits an ExportBundle in an SPDX/CycloneDX-adjacent shape plus anchor provenance.

telemetry-emitter: cross-cutting OpenTelemetry instrumentation (spans, counters, histograms) attached to every box above; never transmits source content (I12).

8. Domain Model

Decision record fields. id (content-addressed, see §11 DecisionId), title, rationale (free text, may link to an external ADR markdown file per Nygard 2011), status (lifecycle state, below), scope (anchored | repo-global), anchors (list, §11 Anchor), edges (list, §11 DecisionEdge), tags, repo_id, created_at, author, assertion (a structured rule the drift detector checks — e.g. "no direct instantiation of type X within this anchor's AST subtree").

Anchor model — field table and resolution precedence.

Field Type Precedence Notes
symbol_ref SymbolRef (qualified name + kind) 1st (highest) LSP workspace/symbol-equivalent lookup
ast_path AstPath (root-relative node-type+index sequence) 2nd Falleri et al. ASE 2014 node matching
content_hash ContentHash (blake3 of enclosing block, whitespace-normalized) 3rd Invalidated by any in-range edit
fuzzy_window text window ± N lines, normalized whitespace, edit-distance threshold 4th (lowest) Last-resort fallback before orphaning
file_path string contextual, not itself a precedence tier Scopes search space for all tiers above

Anchor-repair procedure (named steps, decision table).

Steps: (1) detect invalidation trigger from file-watcher/LSP change event; (2) attempt symbol_ref resolution via document-symbol tree; (3) on failure, attempt ast_path match via tree-sitter query, same file then repo-wide if file path changed; (4) on failure, attempt content_hash exact match scoped to the diff hunk (Myers 1986 O(ND) diff bounds the search); (5) on failure, attempt fuzzy_window match under an edit-distance threshold; (6) on total failure, mark Orphaned, emit DriftEvent(kind: Deleted-or-Unresolvable).

Steps Succeeding Outcome Confidence Tier
symbol_ref Resolved Exact
ast_path only Resolved High
content_hash only Resolved Medium
fuzzy_window only Resolved, flagged for confirmation Low — routes to Ambiguous per P9
two tiers with conflicting targets Ambiguous Requires human confirmation
none Orphaned Requires manual re-anchoring

Drift-classification taxonomy.

Kind Signature Example Trigger
Moved content_hash unchanged, file_path changed File relocated in a repo reorg
Renamed symbol_ref name changed, ast_path shape preserved Rename refactor
Modified-in-place Content within anchor bounds changed, structure preserved Logic edit inside anchored function
Deleted No candidate resolves at any precedence tier Function/file removed
Semantically-contradicted Anchor resolves, but assertion rule check fails Decision says "use pool X"; code now instantiates directly

Decision graph model. Nodes are decisions; edges are typed: supersedes (A replaces B), depends-on (A requires B to remain Active), contradicts (A and B cannot both be Active). Stored as an adjacency table (§11 DecisionEdge).

Op-log merge semantics. Each op carries (decision_id, op_type, lamport_ts, actor_id). Merge order is total: sort by (lamport_ts, actor_id), ties broken by actor_id lexicographic order (P12). Concurrent edits to the same field produce a recorded conflict marker (I10), never a silent overwrite; the later-ordered op wins for graph state, but both are retained in the op-log for audit (P3).

Worked example — decision surviving a rename then a refactor. A decision anchors payments::Ledger::commit via symbol_ref. Step 1: developer renames the function to Ledger::apply. Anchor resolver's symbol_ref lookup fails (name changed); falls to ast_path — the function's AST shape (parameter count, body structure) is unchanged, so ast_path resolves uniquely; anchor-repair engine updates symbol_ref to the new name and appends an op-log entry recording the repair with confidence High. Step 2: developer later extracts part of the function body into Ledger::apply_with_validation, splitting the AST subtree. ast_path no longer matches uniquely (two candidate subtrees share ancestry); resolver returns Ambiguous; capture-surface prompts the developer, who confirms the anchor now binds to apply_with_validation; op-log records the confirmed rebind with actor id.

Malformed-input examples. (a) An anchor referencing a file_path that was never valid UTF-8 — rejected at capture time with AnchorError::InvalidPath. (b) A content_hash computed over a byte range that no longer exists in the file (post-truncation) — resolver returns Orphaned immediately, skipping lower-precedence tiers since the block itself is gone. (c) An assertion rule referencing a symbol kind the current language's tree-sitter grammar does not define — rejected at decision-authoring time with a schema validation error.

Failure-path example. A SyncOp batch arrives at team-backend with a lamport_ts lower than the tenant's last-ingested watermark for that actor (clock regression, e.g. client clock reset). Ingestion rejects the batch (I9), returns a SyncError::ClockRegression, and sync-client requests the actor's last-known watermark before resubmitting with corrected sequencing — never silently reordering into the log.

Design principles (§6)

  • P1 — An anchor is a claim, not a fact. Every anchor must be re-verified on read, never trusted from cache alone. Tradeoff: repeated verification costs CPU (§4 latency budget). Operational implication: resolver runs on every drift scan, not just on save. Violating it: a stale anchor silently points at the wrong code, and the system lies to the user (I2).
  • P2 — Drift is detected, never auto-resolved. The system flags divergence; a human decides whether code or decision is wrong. Tradeoff: more manual triage load. Operational implication: drift inbox is a durable queue, not a transient notification. Violating it: auto-"fixing" a decision to match code silently erases the original intent (I6).
  • P3 — The decision log is append-only and content-addressed. No decision record is ever mutated in place; state changes are new op-log entries. Tradeoff: storage grows monotonically (bounded by §4 storage-growth ceiling). Operational implication: replay is the only source of current state (I3). Violating it: two replicas can silently diverge with no way to detect it.
  • P4 — Anchor resolution is precedence-ordered, never best-of-N voting. Symbol identity beats AST path beats content hash beats fuzzy window, strictly in that order. Tradeoff: a lower-precedence match is ignored even if it "looks" more confident. Operational implication: precedence order is a single hard-coded constant, tested exhaustively (§8). Violating it: nondeterministic anchor resolution across runs.
  • P5 — A decision without an anchor must be explicit, not implicit. Repo-global decisions are tagged scope: repo-global, never left with an empty anchor list by omission. Tradeoff: capture UI must force a scope choice. Operational implication: the drift detector skips repo-global decisions by design (I1). Violating it: an unanchored decision is indistinguishable from a bug.
  • P6 — Source content never leaves the client without explicit opt-in. Sync transmits anchors, decision text, and hashes; raw source snippets sync only if the user opts in per repo. Tradeoff: backend cannot show inline code context by default. Operational implication: sync-client strips snippet fields unless content_sync_enabled (I12). Violating it: an unaudited data-exfiltration channel (T1).
  • P7 — A superseded decision is retired, never deleted. Supersession is a graph edge, not an erasure. Tradeoff: the graph grows without bound. Operational implication: query layer must default to "active view" (excluding superseded/retired) with an explicit "show all" toggle. Violating it: history that cannot answer "why did we used to do X" (Cunningham 1992 applied here — deferred/changed decisions are debt, not garbage).
  • P8 — Reparse is incremental by construction, not by optimization. The AST indexer never falls back to full-file reparse except on first open or corruption. Tradeoff: incremental patch logic is more complex than "just reparse everything". Operational implication: every edit event carries a byte-range patch (§4 keystroke-batch budget). Violating it: p95 reparse latency blows the budget on large files.
  • P9 — Ambiguous anchor resolution requires human confirmation, never silent pick-first. When two candidates tie in precedence, the resolver returns Ambiguous, not an arbitrary winner. Tradeoff: more UI interruption. Operational implication: capture-surface drift inbox surfaces ambiguous cases distinctly from confirmed drift. Violating it: an anchor can silently rebind to the wrong copy-pasted block (§16 pitfall).
  • P10 — The decision graph is a directed graph with typed edges, never free-text cross-references. supersedes, depends-on, contradicts are the only edge kinds. Tradeoff: some relationships must be forced into one of three kinds. Operational implication: graph queries are typed traversals, not text search. Violating it: the graph degrades into an unqueryable pile of prose links.
  • P11 — Compliance export is independently verifiable. An export bundle must be checkable by a party that does not trust the exporting team — via content hashes and a replay-reproducible cursor. Tradeoff: export format is more rigid than free-form reports. Operational implication: compliance-exporter embeds the ReplayCursor and per-node content hashes (§8, §11). Violating it: an export that can be silently doctored defeats its own purpose (T3).
  • P12 — Team sync merges are deterministic given the same op set. Two replicas that receive the same ops in any order converge to the same graph. Tradeoff: requires a total order (Lamport timestamp + actor id tie-break), not physical wall-clock time. Operational implication: SyncOp carries a logical clock, not just a timestamp (§8 op-log merge semantics). Violating it: split-brain graphs that never reconverge (FM-7).
  • P13 — Every telemetry event is reviewed for identifier leakage before emission. File paths and symbol names are hashed or redacted in telemetry unless the repo opts into verbose diagnostics. Tradeoff: harder to debug specific repos remotely. Operational implication: telemetry-emitter has a redaction layer as a mandatory pipeline stage (I12, T5). Violating it: identifiers leak into a shared telemetry backend.
