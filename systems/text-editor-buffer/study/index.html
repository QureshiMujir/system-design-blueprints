30. Mental Models & First Principles

  • MM1 — A position is a coordinate system, not a number. Five coordinate systems exist because five different consumers (renderer, LSP client, regex engine, human, database) each have a legitimate, different unit of "where." Predicts: any bare-integer position parameter is a latent bug generator. Bug class without it: an LSP offset silently drifts on every non-ASCII line. Applied in §13.

  • MM2 — Amortized cost is a bet on locality; worst-case cost is insurance against its absence. The gap buffer bets that edits cluster near the cursor; the rope insures against the bet failing. Predicts: which backend wins for a given edit-pattern workload, without running a benchmark. Bug class without it: choosing the gap buffer for a refactor-heavy IDE and being surprised by O(n) stalls. Applied in §14, §15, §31.

  • MM3 — A summary is a monoid, and every subtree is just a fold. The rope's and piece-table's Summary/subtree counters are associative aggregates; any monoid-additive property can be maintained incrementally in O(log n). Predicts: which future per-node aggregates (e.g. a "diagnostics count") could be added cheaply, and which (e.g. "is this range currently selected," not associative) could not. Bug class without it: recomputing an aggregate from scratch on every query. Applied in §8.1, §15.2, §17.2.

  • MM4 — The observer is downstream of a single source of truth, never a second writer. A one-way edit-event flow is what makes multiple consumers provably consistent with each other. Predicts: any two-way channel between a backend and a consumer will eventually desync. Bug class without it: "the highlighter is one edit behind." Applied in §21.

  • MM5 — Immutability at the boundary buys cheap snapshots. The piece table's immutable original and the rope's Arc-based structural sharing both trade a small append/clone cost for O(1) snapshotting. Predicts: any fully-mutable-in-place structure (a raw Vec<u8> with no COW) pays O(n) to snapshot. Bug class without it: an undo implementation that full-copies the buffer per edit group. Applied in §15.2, §16.2, §18.2.

  • MM6 — Stickiness is a declared policy, not a physical property of the offset. The same numeric byte offset behaves differently under an insert depending on a stickiness flag chosen at anchor-creation time. Predicts: any anchor system without explicit stickiness will surprise a host at the exact moment of a boundary-adjacent edit. Bug class without it: a bookmark that silently jumps to the wrong side of an insertion. Applied in §19.

  • MM7 — Grapheme boundaries are stateful, not memoizable per chunk. UAX #29 boundary determination can require lookback/lookahead across an arbitrary distance (ZWJ sequences, regional indicators). Predicts: any chunk-summary cache of grapheme counts is wrong at some boundary, however rare. Bug class without it: mis-rendered emoji sequences exactly at a rope-leaf or piece boundary. Applied in §13.2, §21.2.

  • MM8 — Crash safety is bought with an extra rename, not an extra write. Atomicity comes from the filesystem's rename guarantee, not from careful ordering of writes to the original file. Predicts: any save implementation that writes-then-truncates the original path directly cannot be made crash-safe no matter how careful the write ordering is. Bug class without it: a truncated user file on power loss mid-save. Applied in §20.2.

Glossary (§36) · 50 terms · site-wide glossary

Add buffer
the piece table's append-only buffer that every edit's inserted bytes land in; never moved, never compacted (§16.2).
Anchor
a sticky byte offset that survives edits according to a declared stickiness policy (§11.4, §19).
AnchorStore
the interval-indexed structure holding every registered anchor for a buffer instance (§11.4).
Autosave journal
the host-level append-only recovery log that restores unsaved edits after a crash, distinct from save-atomicity (§8.7, §20.9).
B+-tree
the balanced-tree structure backing the line index; internal nodes hold cumulative counts, leaves hold sorted line-feed positions (§17).
B-tree rope
this project's rope backend: a B-tree with branching factor 8 whose leaves hold UTF-8 chunks (§8.1, §15).
Backend
one of the three interchangeable TextBuffer implementations: gap buffer, B-tree rope, piece table (§3).
Backpressure
the mechanism by which a slow async observer either blocks the bounded channel or explicitly signals a drop, never silently losing events (P12).
BOM (Byte Order Mark)
an optional leading byte sequence indicating encoding/endianness; stripped from buffer content and re-emitted on save per policy (§20.2).
BufferSnapshot
an immutable, cheaply-obtained view of a buffer at a fixed Revision (§11.6).
ByteOffset
the canonical typed position: a byte index into the buffer's UTF-8 content (§11.1).
CharOffset
a typed position expressed in Unicode codepoints, never used for storage (§11.1).
Chunk
a contiguous slab of UTF-8 bytes; the rope's leaf unit and the natural granularity of ChunkIter (§8.1, §11.2).
Coalescing
merging adjacent EditGroups into one undo step under explicit rules (P7, §18.2).
CoalesceKey
the (line, direction) pair used to decide whether two edit groups coalesce (§11.3).
CRDT (Conflict-free Replicated Data Type)
a class of data structures that converge under concurrent, unordered edits; this project is CRDT-ready, not CRDT-implementing (§21, §5).
Deferred feature
a capability explicitly out of this project's scope, anchored in the Deferred Features Register (§35).
Differential test
a test that runs one operation sequence against multiple backends (or against RefBuffer) and asserts identical output (P9, §26).
EditGroup
the atomic unit of undo: a coalesced sequence of EditOps plus its precomputed inverse (§11.3).
EditId
a monotonically increasing token identifying and ordering edits within one buffer instance (§11.3, I12).
EditLog
the optional append-only record of every edit with causal deps, consumed by an external CRDT/OT layer (§21.2).
EditOp
an atomic mutation: Insert or Delete (§11.3).
EditEvent
the observer-visible record of one applied edit, carrying before/after buffer length (§11.3).
Gap
in the gap buffer, the contiguous run of unused bytes between the two content regions (§8.1, §14.2).
Gap buffer
a buffer backend maintaining an unused gap near the cursor for amortized-O(1) local edits (§14).
GraphemeOffset
a typed position counting user-perceived grapheme clusters, per UAX #29 (§11.1, §13).
Grapheme cluster
one or more Unicode codepoints perceived as a single character by a user; boundary rules defined in UAX #29 (§5, §13.2).
I7 (single-writer invariant)
the contract that at most one mutation is in flight per buffer instance at a time (§7).
Invariant
a system property (I1–I14) that must hold after every operation, with a defined detection and recovery path (§7).
Leaf
a rope's or line index's terminal node holding actual content or line-feed positions, as opposed to an aggregating interior node (§8.1, §17.2).
LineCol
a typed position expressed as (LineIdx, ByteOffset-within-line) (§11.1).
LineIdx
a zero-based typed line number (§11.1).
LineIndex
the B+-tree sidecar mapping line numbers to byte offsets and back, shared by all three backends (§8.1, §17).
Observer
a downstream consumer of EditEvents, delivered either synchronously or asynchronously (§11.5, §21).
ObserverFanout
the structure that dispatches EditEvents to every registered observer in EditId order (§11.5, §21.2).
Original buffer
in the piece table, the immutable (optionally mmap'd) bytes of the file as loaded (§8.1, §16.2).
Piece
a reference (buf_tag, start, len, line_feeds) to a contiguous run of bytes in either the original or add buffer (§11 note, §16.2).
Piece table
the data structure (older name) later refined into the piece tree; first used in Bravo (§5, §8.1).
Piece tree
the red-black-tree-indexed piece-table variant this project implements, matching VS Code's design (§16).
PositionCursor
a cached traversal position that amortises sequential byte↔grapheme/UTF-16 conversion to near O(1) per step (§13.2).
Revision
a monotonic counter incremented on every edit; a buffer's logical clock, used to key snapshots (§11.6).
Rope
the 1995 Boehm-Atkinson-Plass data structure; in this project, generalized to a B-tree with chunked leaves (§5, §15).
Site ID
a per-replica identifier namespacing EditIds in the optional EditLog to prevent cross-replica collisions (§21.2).
Snapshot
see BufferSnapshot.
Sticky offset
a position that survives edits per a declared stickiness (StickyLeft/StickyRight), as opposed to a raw offset that would silently become wrong (§11.4, §19).
StickyLeft / StickyRight / Surround
the three anchor stickiness flavours (§8.4, §11.4).
Summary
the small fixed-size additive aggregate (bytes, chars, utf16, lines) maintained on every rope/piece-tree node (§8.1, §11).
UAX #29
the Unicode Annex defining grapheme-cluster boundaries, implemented exactly by this project's segmentation code (§5, §13, I13).
UTF-16 code unit
a 16-bit unit of UTF-16 text; one per BMP codepoint, two (a surrogate pair) per supplementary-plane codepoint (§8.2, §11.1).
Utf16Offset
the typed position counting UTF-16 code units, needed at the LSP boundary (§11.1, §5).
