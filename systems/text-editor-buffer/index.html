Boxes, one paragraph each:

Host Application. Owns the Box<dyn TextBuffer>; issues mutations and reads only through the trait (§11); never reaches into backend internals. Concurrency boundary: the host may run on any thread, but a given buffer instance's mutation calls are not internally synchronized — the host serializes writers (I7, §7).

Backend. Exactly one of gap buffer, rope, or piece table is live per buffer instance; all three share the TextBuffer trait and are proven behaviourally identical by the differential harness (§26). Persistence boundary: only the piece table holds a direct relationship to on-disk bytes (the immutable original_buf, possibly mmap'd); the other two fully materialise content in-process.

Line Index Sidecar. A B+-tree of cumulative line-feed counts, owned by teb-core, mutated by every backend through one entry point (apply_edit); never mutated directly by a backend reaching into its internals (P5, I3).

Position Converters. A stateless service layered over &dyn TextBuffer; converts between the five typed coordinate systems; the only place conversion logic lives (P1, P2).

Undo/Redo Stack. Optional, attached by the host; owns EditGroups with precomputed inverses and explicit coalescing rules (P7, §18).

Anchor Store. An interval-indexed structure of sticky offsets; updated synchronously on every edit before the edit is considered complete (P6, I6).

Observer Fan-out. The sole mutation-export mechanism (P5); a trust boundary — host-supplied observer callbacks must not re-enter the buffer (T4, §22) — and a concurrency boundary between the mutation thread and async subscriber threads.

teb-io. The persistence boundary to the file system; owns encoding detection, BOM handling, streaming chunked reads, and atomic-rename saves (§20).

External consumers. Downstream of the observer protocol; out of this project's scope, but the edit log's shape (Phase 9, §21) is designed so a CRDT/OT layer can consume it without buffer changes.

8. Domain Model

8.1 Backend structural models

Backend Storage shape Mutation cost (local) Mutation cost (far) Immutable region
Gap buffer (§14) one Vec<u8> + a gap Range O(1) amortised (memcpy into gap) O(n) (move_gap, one copy_within) none
B-tree rope (§15) B-tree, branching 8, leaves 4–8 KiB UTF-8 chunks, Summary{bytes,chars,utf16,lines} per node O(log n) always O(log n) always none (COW spine on snapshot)
Piece table (§16) immutable original_buf + append-only add_buf + red-black tree of Piece{buf_tag,start,len,line_feeds} O(log n) tree splice, ≤3 pieces touched O(log n), same bound original_buf (never mutated)

8.2 Position / index mapping model

Coordinate Backing structure Conversion cost Notes
ByteOffset native storage offset O(1) canonical coordinate; all others derive from it
CharOffset chunked traversal O(distance) amortised via cursor codepoint count, not byte count
Utf16Offset chunk utf16 summary O(log n) via summary, O(1) via cursor BMP codepoint = 1 unit, non-BMP = 2 (surrogate pair)
GraphemeOffset UAX #29 state machine over chunks O(distance), not summary-cacheable a chunk boundary can split a cluster; caching is unsound (§13.6)
LineCol line-index B+-tree (§17) O(log n) independent of the three coordinates above

8.3 Edit application state machine

Every insert / delete / replace transitions through the same ordered steps regardless of backend, gated by the invariants of §7:

Step State Action Guard
1 Received Validate ByteRange within [0, len]; reject if it splits a UTF-8 codepoint I2
2 Validated Locate the mutation site (move gap / descend B-tree / find pieces to split) backend-specific
3 Located Mutate backend storage —
4 Mutated Recompute node summaries / call LineIndex::apply_edit I3, I9, I10
5 Indexed AnchorStore::apply_edit shifts or collapses anchors in range I4
6 Anchored If undo attached: append EditGroup with precomputed inverse I5
7 Logged Allocate the next EditId; fan out EditEvent to observers I6, I12
8 Delivered Return EditId to the host —

A failure at step 1 aborts before any mutation (no partial state); a failure at any later step is a debug-build panic (an internal invariant violation, never triggered by host input per P14).

8.4 Anchors / marks model

Stickiness table (P6, I4), restated as the transition each flavour undergoes for an edit at [a, b) relative to an anchor at offset o:

Stickiness o < a o in [a, b), insert at a (b=a) o in [a, b), delete [a,b)
StickyLeft unchanged stays at a (insert lands to its right) collapses to a
StickyRight unchanged shifts to a + len(insert) collapses to a
Surround{start,end} unchanged each endpoint uses its own flavour both endpoints inside ⇒ range collapses to empty at a

Anchors with o > b always shift by the edit's net length delta; this row is identical across all three flavours and omitted from the table for density.

8.5 Worked example

Buffer content (7 codepoints, 8 bytes): "café!\n" → bytes 63 61 66 C3 A9 21 0A (é is U+00E9, 2-byte UTF-8, 1 UTF-16 unit, 1 grapheme). Host calls insert(ByteOffset(5), "!!")(inserting two ! right before the existing !):

  1. Step 1: ByteOffset(5) is a valid codepoint boundary (byte 5 is the start of !, byte 4 was the last byte of é) — passes I2.
  2. Step 2–3 (rope example): descend to the single leaf (buffer fits in one 4 KiB chunk); splice "!!" into the chunk at byte 5.
  3. Step 4: leaf Summary updates: bytes += 2, chars += 2, utf16 += 2, lines += 0; interior summaries (none here, single leaf) unaffected. LineIndex::apply_edit shifts the recorded line-feed position at byte 7 to byte 9.
  4. Step 5: no anchors registered in this example — no-op.
  5. Step 6: if undo attached, EditGroup{ops: [Insert{at:5, content:"!!"}], inverse: [Delete{range:5..7}]} is pushed.
  6. Step 7: EditId(N+1) allocated; EditEvent{id, op, before_len:8, after_len:10} fanned out.
  7. Result: "café!!!\n", 10 bytes, byte_to_line_col(ByteOffset(9)) == LineCol{line:0, col:9}, byte_to_utf16(ByteOffset(9)) == Utf16Offset(9) (all codepoints so far are BMP).

8.6 Malformed-input example

Host calls delete(ByteRange{start: ByteOffset(3), end: ByteOffset(4)}) on the original "café!\n". Byte 3 is 0xC3 (the first byte of é's two-byte encoding) and byte 4 is 0xA9 (its continuation byte); the requested range removes only the lead byte, which would leave a dangling continuation byte at the new offset 3 — an invalid UTF-8 sequence. Step 1 of §8.3 rejects the call: I2 fires, the buffer returns EditError::Utf8Boundary{offset: ByteOffset(3)}, no mutation occurs, no EditId is allocated, and no observer is notified. The host is expected to snap the range to the nearest codepoint boundary and retry (documented in docs/runbooks/ per §24).

8.7 Failure-path example

A host saves a 200 MB buffer (P13, §20). teb-io streams the BufferSnapshot to buffer.tmp in 64 KiB chunks; the process is killed (OOM-killer, power loss) after 150 MB is written, before the atomic rename. On restart: the original buffer.txt is untouched (I11 — the rename never happened, so the original path was never the write target); teb-io's open path finds the orphaned buffer.tmp, verifies it against a size/checksum recorded in the autosave journal (§20.10), determines it is a partial write, and discards it; if autosave was enabled, the host recovers the last complete autosave checkpoint plus any journalled edits since that checkpoint (FM-7, §23), typically losing at most the coalesce window's worth of unsaved edits (≤1 s of typing, per P7's coalescing default).

8.8 Rope worked example (leaf split and summary propagation)

Consider a rope (branching factor 8, ADR-03) whose root has two leaf children: Leaf A = "The quick brown fox jumps over" (31 bytes, Summary{bytes:31, chars:31, utf16:31, lines:0}) and Leaf B = " the lazy dog.\n" (15 bytes, Summary{bytes:15, chars:15, utf16:15, lines:1}); the root's own summary is the component-wise sum, Summary{bytes:46, chars:46, utf16:46, lines:1} (MM3 — a summary is a monoid). Host calls insert(ByteOffset(31), " and cat") — exactly at the leaf boundary. Step 2 of §8.3 descends to Leaf A (the insertion point is at its end); Leaf A grows to 39 bytes, still within [2048, 8192]'s lower bound trivially (small example; in production leaves stay 4–8 KiB), so no split is needed — but if this insert had instead been a 9,000-byte paste, Leaf A would exceed the 8 KiB ceiling (§15.2) and split into two sibling leaves, promoting a new internal node if the root's child count would otherwise exceed 8 (ADR-03). Step 4 recomputes Leaf A's summary to Summary{bytes:39, chars:39, utf16:39, lines:0} and the root's summary bottom-up to Summary{bytes:54, chars:54, utf16:54, lines:1} (I10) — no other leaf is touched, demonstrating the O(log n) locality of the summary-recomputation walk (§15.2, MM3).

8.9 Piece-table worked example (piece split under a mid-string edit)

original_buf = "The quick brown fox" (20 bytes) loaded as a single piece P0{buf:Original, start:0, len:20, line_feeds:0}; the tree has one node, subtree_bytes = 20. Host calls insert(ByteOffset(4), "very "). Step 2 of §8.3 locates the split point inside P0 at relative offset 4; P0 splits into P0a{buf:Original, start:0, len:4} ("The ") and P0b{buf:Original, start:4, len:16} ("quick brown fox"); the inserted text is appended to add_buf at offset 0 and referenced by a new piece P1{buf:Add, start:0, len:5, line_feeds:0} ("very "); the tree becomes P0a → P1 → P0b in-order (three pieces from one, matching §16.2's "at most 3 pieces touched" bound for an insert). Step 4 recomputes subtree_bytes bottom-up to 25 (I9); original_buf itself is never mutated — only the tree and add_buf grew, matching the "immutable original, append-only delta" property that makes the piece table win the "open huge file, edit small" workload (§2, VS Code reading §5).

8.10 Cross-backend equivalence example (the differential harness's core claim, by hand)

Starting from the empty buffer, apply the sequence [insert(0, "café"), insert(4, "!"), delete(0..1)] to a gap buffer, a rope, and a piece table independently. Gap buffer: "café" → "café!" → "afé!" (delete removes the leading "c", 1 byte). Rope: identical sequence produces the same content via leaf mutation and summary update at each step (§8.8's mechanism at a smaller scale). Piece table: insert(0,"café") creates one add-buffer piece; insert(4,"!") appends to the same add-buffer piece (contiguous append, no split needed since the insertion point is at the piece's end); delete(0..1) splits the piece to drop its first byte. All three report slice(ByteRange{0, 5}) == "afé!" and len_bytes() == ByteOffset(5) — the byte-for-byte agreement P9 mandates and the differential harness (§26) checks mechanically for every fixture, not just this one by-hand trace.

8.11 Undo-coalescing worked example

A host types "cat" one keystroke at a time with an attached UndoStack (default UndoConfig, §18.2):

Keystroke Elapsed since previous CoalesceKey Stack action
insert(0, "c") — (first edit) {line:0, direction:Right} opens EditGroup#1
insert(1, "a") 0.2 s {line:0, direction:Right} matches #1's key, within 1 s window → coalesces into #1
insert(2, "t") 0.3 s {line:0, direction:Right} coalesces into #1

After the third keystroke, EditGroup#1.ops = [Insert{0,"c"}, Insert{1,"a"}, Insert{2,"t"}] and EditGroup#1.inverse = [Delete{0..1}, Delete{1..2}, Delete{2..3}] computed at each step (I5). A single undo() call applies the inverse ops in reverse, removing "t", then "a", then "c" — restoring the empty buffer in one host-visible undo step, not three, which is exactly P7's "undo is structural, not character-by-character" principle made concrete.

Design principles (§6)

  • Typed positions, never bare integers (P1). A position is one of ByteOffset, CharOffset, Utf16Offset, GraphemeOffset, LineCol; implicit coercion across types is a compile-time error. Tradeoff: wider API surface, more conversion call-sites. Operational implication: position-confusion, historically the largest editor bug class, becomes structurally unrepresentable. Violation breaks: an LSP synchroniser silently drifts on every non-ASCII line.
  • UTF-8 internal, UTF-16 only at the LSP boundary (P2). The buffer never stores UTF-16 or Latin-1 internally; conversion happens at teb-positions. Tradeoff: every LSP round-trip pays a conversion. Operational implication: one conversion path to audit, not N. Violation breaks: silent double-encoding on save.
  • No silent denormalization (P3). Bytes that go in come out bit-identical on save; no BOM stripping, no line-ending conversion, unless the host opts in via BufferConfig. Tradeoff: the buffer cannot "clean up" a file automatically. Operational implication: diffs against the on-disk file are always faithful. Violation breaks: an editor that silently rewrites a vendored file's line endings on open, corrupting a checked-in diff.
  • All operations O(log n) or better, one documented exception (P4). The gap buffer's amortized-O(1)-at-the-gap guarantee is published and bounded; every other operation on every backend is O(log n) worst case. Tradeoff: the rope/piece backends pay a constant-factor tax the gap buffer does not. Operational implication: a host can reason about worst-case latency without backend-specific caveats except the one documented gap-buffer case. Violation breaks: an unbounded backend turns a 200 MB refactor into a multi-second stall.
  • The observer protocol is the only mutation export (P5). Backends never expose internal handles; downstream consumers reconstruct state from EditEvents. Tradeoff: consumers cannot cheaply peek at backend internals for debugging. Operational implication: every consumer sees the same edit stream, so there is one source of truth for "what changed." Violation breaks: a highlighter that reads backend internals directly desyncs the moment the backend is swapped.
  • Anchors are sticky, not stable (P6). An anchor's byte offset changes as edits land; stickiness (StickyLeft/StickyRight/Surround) is chosen per anchor at creation. Tradeoff: three flavours to implement and test instead of one. Operational implication: every editor's anchor semantics (cursor, selection, bookmark) is expressible without a special case. Violation breaks: a bookmark that silently points at the wrong line after an edit upstream of it.
  • Undo is structural, not character-by-character (P7). EditGroup is the atom of undo; coalescing rules are explicit (§18). Tradeoff: coalescing logic is another surface to get right. Operational implication: undo feels like a human edit, not a keystroke replay. Violation breaks: undoing a paste requires N keystrokes-worth of undo presses.
  • Streaming load and save (P8). A large file is usable for reads while it loads and editable while it saves, via a snapshot taken at save-start. Tradeoff: the IO layer is stateful and more complex than "read the whole file." Operational implication: a 200 MB file does not freeze the editor UI thread. Violation breaks: opening a large log file blocks the user for the full read duration.
  • Differential testing is the specification (P9). Every behavioural test runs against all three backends; disagreement is a failing test, not a documented quirk. Tradeoff: triples test execution time. Operational implication: "the backends disagree" becomes structurally impossible in a shipped release. Violation breaks: silent behavioural drift between backends that a host relies on being interchangeable.
  • Reproducibility is a feature (P10). Every fuzz and bench harness records its random seed; every run is replayable. Tradeoff: seed-capture plumbing in every harness entry point. Operational implication: a CI-only failure is always locally reproducible. Violation breaks: an unreproducible fuzz finding that cannot be triaged.
  • One mutation entry point per aggregate (P11). The line index has exactly one mutator, apply_edit; no backend recomputes or duplicates line-counting logic. Tradeoff: every backend must funnel through the shared sidecar rather than optimizing its own count. Operational implication: a line-index bug has one place to look. Violation breaks: two backends silently disagree on line numbers after the same edit sequence.
  • Backpressure over silent drop (P12). An async observer that falls behind either blocks the bounded channel or explicitly increments a drop counter; it never silently loses events. Tradeoff: a slow observer can throttle the whole edit path if configured to block. Operational implication: "the highlighter missed an edit" is observable via telemetry, never silent. Violation breaks: a syntax highlighter that renders stale code with no indication anything is wrong.
  • Crash safety over save throughput (P13). Autosave and atomic-rename-on-save take precedence over raw write speed. Tradeoff: a save is at least one extra fsync and rename versus a naive overwrite. Operational implication: a crash mid-save never corrupts the on-disk file. Violation breaks: a power loss during save truncates the user's file.
  • Typed, non-panicking errors on host input (P14). Every public enum is #[non_exhaustive]; every fallible operation returns a typed error; the buffer never panics on host-supplied input, only on internal invariant violation in debug builds. Tradeoff: every call site must handle a Result. Operational implication: a malformed host call degrades gracefully instead of crashing the process. Violation breaks: one bad LSP request from a misbehaving client crashes the whole editor process.
  • Save atomicity via rename, never via careful write ordering (P15). A save always writes to a temp path and renames over the target; the original file is never a direct write target (I11, I15). Tradeoff: one extra fsync/rename per save. Operational implication: a crash at any point during save leaves either the old file intact or the new one complete — never a hybrid. Violation breaks: a power-loss event during save truncates or corrupts the user's file irrecoverably (MM8).
  • Bounded integer fields with explicit rejection, never silent wraparound (P16). Every length/offset field with a fixed integer width (u32 piece lengths, gap sizes) is checked at construction and growth; an operation that would overflow is rejected with a typed error rather than silently wrapping (I16). Tradeoff: an extra bounds check on every growth path. Operational implication: a pathological paste is rejected cleanly instead of corrupting offset arithmetic. Violation breaks: a length overflow silently aliases two unrelated pieces of content, a corruption class with no error signal at the moment it occurs.
