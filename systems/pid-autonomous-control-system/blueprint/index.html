289 — PID / Autonomous Control System

Project Number: 289

Project Name: PID / Autonomous Control System

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

Goal: Build a from-scratch, production-grade, no_std-capable Rust control-systems engine — a complete PID controller (anti-windup, derivative filtering, setpoint weighting, bumpless transfer, gain scheduling, saturation + rate limits) plus a broader autonomous-control stack (plant/ODE simulation, discretization, auto-tuning, feedforward/cascade, state-space control, LQR/LQG, Kalman estimator, linear MPC, path-following) driven by a deterministic real-time fixed-step loop executor, with offline simulation, tuning, and stability-analysis tooling.

1. Goal

Precise scope: a control-laws-and-simulation engine. We build the feedback loop, not the world around it. The deliverable is a library that, given a state estimate and a reference, computes a bounded actuator command in deterministic fixed-step time, plus the simulation/tuning/analysis tooling to design, verify, and ship that loop.

In scope (control laws + plant simulation):

  • Classical: PID (parallel/standard/series), anti-windup, derivative filter, setpoint weighting, bumpless transfer, gain scheduling, output saturation + rate limits.
  • Tuning: Ziegler–Nichols (open + closed loop), relay-feedback (Åström–Hägglund).
  • Structure: feedforward, cascade, ratio.
  • Modern: state-space modeling, controllability/observability, pole placement (Ackermann), LQR (ARE), Luenberger observer, LQG.
  • Estimation: discrete Kalman filter (predict/update) — minimal, controller-facing (cross-link #285 for the full fusion stack).
  • Optimal/predictive: linear MPC (receding-horizon QP, condensed form, box/rate constraints).
  • Autonomous tracking: pure pursuit, Stanley cross-track controller.
  • Plant: transfer-function + state-space models, ODE integrators (Euler, RK4), fixed-step sim harness, discretization (Euler/Tustin/ZOH).
  • Real-time: fixed-step loop executor, deadline accounting, jitter measurement.
  • Analysis: gain/phase margins, Nyquist, root locus, step/frequency response.

Deployment model: an embeddable Rust control library. The hot path is no_std + alloc-optional (fixed-size arrays, no heap in the tick). The same crates compile (a) into firmware behind a real-time loop, and (b) into a host-side ctrlctl CLI for offline simulation, auto-tuning, batch sweeps, and plot/CSV export. No GC, no async in the hot loop, no hidden allocation.

Target users: controls engineers (process/industrial), robotics engineers (manipulators, mobile robots), embedded engineers (motor control, power electronics), and autonomous-vehicle engineers (lateral/longitudinal tracking).

  6. ctrl-tune — auto-tuning (Ziegler–Nichols, relay-feedback).
  7. ctrl-ff — feedforward / cascade / gain scheduling.
  8. ctrl-ss — state-space, controllability/observability, pole placement.
  9. ctrl-lqr — LQR / LQG / Luenberger observer.

Timeline: Phase 0 = 1–2 weeks (skeleton + governance + ctrl-core). Full arc 6–14 weeks for a single principal engineer; P1–P4 (~3 wks) yields a shippable hardened PID; P7–P10 (~4 wks) is the modern-control bulk; P11–P12 (~2 wks) is AV tracking + analysis.

Prerequisites: linear systems theory; Laplace + Z-transforms; ODEs (state-space form); linear algebra (eigenvalues, SVD, Riccati, rank); probability (Gaussian, covariance, for Kalman); convex optimization / QP (for MPC); basic real-time scheduling.

2. Why Build This

Unique knowledge taught (one bullet per durable idea):

  • Feedback: how a loop converts an error signal into corrective action and why that can stabilize or destabilize.
  • Stability: poles, margins, the gap between "it worked in sim" and "it has 6 dB / 45° to spare."
  • Discretization: why a continuous design degrades under sampling, and how Tustin preserves margins where Euler does not.
  • Estimator/controller duality: observer design is pole placement on Aᵀ; LQG = LQR ⊕ Kalman via the separation principle.
  • Optimal control: casting "good behavior" as a quadratic cost and solving the Riccati equation.
  • Receding horizon: re-solving a finite-horizon constrained optimization every tick, applying only the first move.
  • Real-time loop design: fixed-step Δt, deadline as a hard invariant, jitter as a first-class measured quantity.

Historical / architectural significance (one line each):

  • PID is the most-deployed control algorithm on Earth — process plants, drones, thermostats, motor drives.
  • Ziegler & Nichols (1942) gave the first systematic tuning rules; still a baseline.
  • Kalman (1960) unified estimation under linear-Gaussian optimality; Apollo guidance shipped it.
  • LQR/LQG formalized optimal state feedback + estimation (1960s aerospace).
  • MPC dominates refineries/chemical plants since the 1980s (DMC, GPC) where constraints are first-class.
  • Stanley (Thrun et al., DARPA Grand Challenge 2005/2006) and pure pursuit (Coulter 1992) made geometric path-tracking practical for self-driving.

Engineering muscles: numerical methods under real-time constraints; allocation-free hot loops; trait-based numeric genericity; convex solver implementation; differential testing against python-control; property-based testing of mathematical invariants (boundedness, stability).

Calibration value: after this, "tune the controller" stops being folklore. You can derive a controller from a model, prove margins, discretize without losing them, bound it against saturation, estimate hidden state, and run it inside a hard deadline.

What Mastery Looks Like

  • Discretization fidelity — given a continuous plant and a sampling rate, you can predict exactly which poles migrate outside the unit circle under forward Euler, and select Tustin or ZOH to preserve the designed margins; demonstrated in Phase 2 and validated in Phase 12.
  • Anti-windup diagnosis — you can read a saturation + integral trace, identify the windup regime, select back-calculation vs clamping with the correct Tt, and show the integrator stays bounded under any step magnitude; exercised in Phase 4.
  • Optimal gain derivation — given Q/R weights and a plant, you can solve the DARE by hand (Hamiltonian/Schur), verify Q⪰0, R≻0, and explain why the resulting K minimizes the infinite-horizon cost; built in Phase 8.
  • Observer design and separation — you can design a Luenberger observer via the dual pole-placement, explain why the separation principle lets you tune K and L independently, and swap the observer from Luenberger to Kalman without touching the controller; integrated in Phases 8–9.
  • MPC constraint assembly — you can construct the condensed QP matrices (H, F, A_c, b_c) from a prediction model and explain warm-starting, why terminal cost P_f from DARE gives stability, and how to fall back when the QP is infeasible; built in Phase 10.
  • Real-time deadline accounting — you can bound worst-case per-tick compute for each law (PID, LQR, MPC), explain how iteration caps trade optimality for deadline safety, and instrument jitter histograms to diagnose scheduling pathologies; built in Phase 2 and characterized in Phase 12.
  • Stability margins gate — you can compute gain and phase margins from a Bode plot, evaluate a Nyquist encirclement, and use the root locus to explain why increasing gain past a breakaway point destabilizes the loop; the deploy gate in Phase 12.
  • Path-tracking geometry — you can derive the pure-pursuit steering law from lookahead geometry, explain why short lookahead oscillates and long lookahead corner-cuts, and apply Stanley's front-axle cross-track law including the low-speed softening term; built in Phase 11.

One paragraph per box:

  • Plant model (offline). TF or state-space description of the system under control. Source of truth for synthesis and tuning. May be hand-written, fit from a step test (FOPDT), or exported from #171. Lives in ctrl-sim.
  • Auto-tune. Consumes a plant (or runs a relay experiment on the closed loop) and emits PID gains / controller params. Ziegler–Nichols and relay-feedback. ctrl-tune. Offline by default; relay can run online behind a safety supervisor.
  • Controller synthesis. Turns a plant + objective (Q/R weights, pole locations, horizon) into a concrete controller (PID config, K gain, MPC matrices). ctrl-ss/ctrl-lqr/ctrl-mpc.
  • Analysis. Computes gain/phase margins, Nyquist, root locus, step/frequency response; runs conformance vs analytic answers. Gate before deploy. ctrl-bench, ctrl-cli.
  • Feedforward. Model-based open-loop term u_ff added ahead of the summing junction; cancels known disturbance/reference dynamics so feedback only corrects residual error. ctrl-ff.
  • Summing junction. Forms error e = r − x̂ (or r − y). For 2-DOF PID, applies setpoint weighting (b·r − x̂). Conceptual; realized inside each controller.
  • Controller (PID | LQR | MPC | track). The control law. Single Controller::update(ref, meas, dt) -> u trait so the loop is law-agnostic. Pluggable.
  • Actuator saturation + rate limit. Hard nonlinearity: clamps to [u_min, u_max] and bounds |Δu|/Δt. Mandatory and always-on; its existence is why anti-windup is required. ctrl-core.
  • Plant (sim or real). Integrates ẋ = f(x,u) with RK4 at fixed Δt in sim; HIL is deferred. The boundary marked PLANT is also the trust boundary for "real world."
  • Sensors. Map state to measurements z = h(x) + noise. In sim, inject configurable noise/bias/dropout to test the estimator.
  • Estimator (Kalman / Luenberger). Reconstructs x̂ from z and the model. Structurally separate from the controller (separation principle). ctrl-kf / ctrl-lqr.
  • Real-time loop (ctrl-rt). Wraps the entire online region, ticking at fixed Δt, measuring jitter, enforcing the deadline, and driving safe-state on overrun. The double-line box is the real-time boundary.

RFCs / Specifications

No formal RFCs govern control law. Normative conventions we adopt and cite:

  • Transfer-function convention: G(s) = Y(s)/U(s), numerator/denominator as descending-power coefficient vectors.
  • State-space convention: ẋ = Ax + Bu, y = Cx + Du (continuous); x[k+1] = A_d x[k] + B_d u[k] (discrete).
  • PID forms per ISA-5.1 / IEEE: parallel (independent), standard/ISA (Kp(1 + 1/(Ti s) + Td s)), series (interacting). All three first-class, with documented conversions.
  • Z-transform / sampling conventions per B3/B7; Tustin with prewarping defined explicitly in §8.

6. Design Principles

  1. Determinism over convenience. Fixed-step Δt; no wall-clock-dependent branches in the law; reproducible given inputs+seed. Tradeoff: less adaptive to host scheduling slop. Operational: enables replay-debugging of any incident. Violation: non-reproducible bugs, untestable controllers, drift between sim and field.

  2. Anti-windup is mandatory whenever actuators saturate. Any integrating term must be guarded (clamping or back-calculation) the instant u_raw ≠ u. Tradeoff: slightly more state + a tuning constant Tt. Operational: prevents the classic "integrator charges during saturation, then huge overshoot." Violation: lockout, limit cycling, dangerous overshoot on recovery.

  3. Bounded output, always. Every controller output passes saturation + rate limit before reaching an actuator. Tradeoff: introduces a nonlinearity the linear analysis ignores. Operational: physical safety, actuator protection. Violation: actuator damage, model invalidity, instability from rate-limit-induced phase lag.

  4. Discretize correctly. Default Tustin (bilinear); ZOH for exact state-space; forward Euler only where speed dominates and Δt≪dynamics. Tradeoff: Tustin warps frequencies (mitigate with prewarping); ZOH costs a matrix exponential. Operational: preserves stability margins designed in continuous time. Violation: a stable continuous design goes unstable when sampled (Euler maps LHP poles outside the unit circle for large Δt).

  5. Estimator/controller separation (separation principle). Design K (control) and L/Kalman gain (estimation) independently; compose for LQG. Tradeoff: optimal only for LQG/linear-Gaussian; heuristic otherwise. Operational: modular tuning, swappable estimator. Violation: tangled code, no clean place to inject a better state estimate (#285).

  6. Bumpless transfer on every mode/gain change. Switching controllers, retuning, or manual↔auto must not step the output. Pre-load integral/state to match current u. Tradeoff: extra state bookkeeping. Operational: safe online retuning, gain scheduling. Violation: output jump → actuator slam, disturbance, possible instability.

  7. Stability is proven, not assumed. Every shipped design carries computed poles/margins; MPC carries feasibility + (where used) terminal ingredients. Tradeoff: analysis cost per design. Operational: the deploy gate. Violation: "worked on my plant" fielded controllers that oscillate.

  8. The real-time deadline is a hard invariant. Per-tick compute ≤ budget; overrun triggers a defined safe-state, never a silent skip. Tradeoff: must bound worst-case (esp. MPC QP iterations). Operational: predictable failure, not cascading lag. Violation: loop falls behind, derivative/integral terms see wrong Δt, divergence.

  9. Units and frames are explicit. Every signal carries documented units + frame (SI internally; conversions at the boundary). Tradeoff: boilerplate. Operational: prevents Mars-Climate-Orbiter-class errors. Violation: silent gain errors of 10×/57.3× (deg/rad).

  10. Observability/controllability checked before design. Compute ranks/Gramians before pole placement / LQR / observer. Tradeoff: upfront linear-algebra. Operational: fail fast with a clear diagnostic. Violation: Ackermann/ARE produce garbage gains for uncontrollable modes; observer never converges on unobservable states.

  11. Allocation-free hot loop. Zero heap in update()/tick; all buffers preallocated, sized by const generics. Tradeoff: fixed maxima for n,N. Operational: no_std/embedded-ready, no malloc jitter. Violation: unbounded latency, embedded targets can't run it.

  12. Derivative on measurement, filtered. Differentiate −x̂ not e; always low-pass the derivative (N filter coefficient). Tradeoff: filter adds phase lag. Operational: avoids "derivative kick" on setpoint steps and noise amplification. Violation: huge transient spikes on setpoint change; noise-driven actuator chatter.

  13. Fail to a defined safe state. Every failure path (NaN, overrun, infeasible QP, sensor dropout) maps to an explicit safe output (hold last good / ramp to safe / handoff). Tradeoff: must define "safe" per application. Operational: graceful degradation. Violation: NaN propagates to actuator; undefined behavior in the field.

  14. Numeric robustness first. Guard divisions, clamp before exp, use stable decompositions (Cholesky/QR), detect non-finite every tick. Tradeoff: a few extra cycles. Operational: survives ill-conditioned plants. Violation: NaN/Inf silently produced and applied.

  15. One controller interface. All laws implement Controller::update(ref, meas, dt) -> u; the loop and tooling are law-agnostic. Tradeoff: lowest-common-denominator signature; richer config via the constructor. Operational: swap PID↔LQR↔MPC without touching the loop. Violation: bespoke wiring per law, untestable in a uniform harness.

8. Domain Model / Theory

8.1 Plant representations

  • Transfer function: G(s) = N(s)/D(s), e.g. FOPDT G(s) = K e^{−Ls} / (τ s + 1). Coeff vectors, descending powers.
  • Continuous state-space: ẋ = A x + B u, y = C x + D u. A∈ℝ^{n×n}, B∈ℝ^{n×m}, C∈ℝ^{p×n}, D∈ℝ^{p×m}.
  • Discrete state-space: x[k+1] = A_d x[k] + B_d u[k], y[k] = C x[k] + D u[k].

8.2 PID forms (all three first-class)

Form Continuous Notes
Parallel / independent u = Kp·e + Ki·∫e + Kd·de/dt Gains independent; easiest to reason about
Standard / ISA / ideal u = Kp(e + (1/Ti)∫e + Td·de/dt) Ki=Kp/Ti, Kd=Kp·Td; tuning rules target this
Series / interacting u = Kp'(1+1/(Ti's))(1+Td's)·e Classic analog; convertible to standard

Discrete PID update (default: standard form, derivative-on-measurement, filtered D, with setpoint weighting b,c):

e_p = b*r - y            // proportional error (setpoint weight b)
P   = Kp * e_p
I  += Ki * e * dt        // e = r - y ; anti-windup may modify (see 8.4)
// filtered derivative on measurement (avoid kick + noise):
d_y = (y - y_prev)/dt
D    = filter(D_prev, d_y, Kd, N, dt)   // 1st-order LP, coeff N (e.g. 8..20)
u_raw = P + I - Kd*D_filtered            // sign: derivative opposes measurement change
u     = rate_limit(saturate(u_raw))

Filtered derivative (discrete, Tustin of Kd·s/(1+s·Kd/(Kp·N))): a first-order filter with time constant Tf = Td/N.

8.3 Discretization

Method Map Pros Cons
Forward Euler s ← (z−1)/Δt cheap, explicit can destabilize (poles leave unit circle)
Backward Euler s ← (z−1)/(zΔt) always stable distorts dynamics
Tustin (bilinear) s ← (2/Δt)·(z−1)/(z+1) preserves stability, maps LHP→unit disk frequency warping
Tustin + prewarp scale 2/Δt → ω₀/tan(ω₀Δt/2) exact at ω₀ one chosen frequency only
ZOH (exact, SS) A_d=e^{AΔt}, B_d=∫₀^Δt e^{Aτ}dτ·B exact for SS under ZOH needs matrix exponential

ZOH via augmented matrix exponential: [[A,B],[0,0]]·Δt → exp → [[A_d,B_d],[0,I]]. Matrix exp by scaling-and-squaring + Padé.

8.4 Anti-windup

  • Conditional integration (clamping): freeze integration when u_raw saturated and the error would push further into saturation; otherwise integrate.
  • Back-calculation: add (u − u_raw)/Tt to the integrator input; Tt tracking time constant (rule of thumb Tt ≈ √(Ti·Td) or Ti/2…Ti). Smoothly unwinds during saturation.
  • Both bound I (invariant I2). Back-calculation gives smoother recovery; clamping is simpler/cheaper.

8.5 Controllability / Observability

  • Controllability matrix 𝒞 = [B, AB, A²B, …, A^{n−1}B]; controllable iff rank(𝒞)=n.
  • Observability matrix 𝒪 = [C; CA; CA²; …; CA^{n−1}]; observable iff rank(𝒪)=n.
  • Gramians (continuous): W_c solves A W_c + W_c Aᵀ + BBᵀ = 0; W_o solves Aᵀ W_o + W_o A + CᵀC = 0 (Lyapunov). Condition number of Gramian → degree of (un)controllability.

8.6 Pole placement (Ackermann)

K = [0 … 0 1]·𝒞⁻¹·φ_d(A), where φ_d is the desired characteristic polynomial evaluated at A. SISO; multi-input uses robust eigenstructure assignment (deferred-lite). Requires controllable pair (A,B).

8.7 LQR (Riccati)

Minimize J = ∫(xᵀQx + uᵀRu) dt, Q⪰0, R≻0. Optimal u=−Kx, K=R⁻¹BᵀP, P solves continuous ARE: AᵀP + PA − PBR⁻¹BᵀP + Q = 0. Discrete (DARE): P = AᵀPA − AᵀPB(R+BᵀPB)⁻¹BᵀPA + Q, K=(R+BᵀPB)⁻¹BᵀPA. Solve via Hamiltonian eigen / Schur, or iterate the DARE.

8.8 Luenberger observer + duality

x̂̇ = A x̂ + B u + L(y − C x̂); error ė = (A−LC)e. Choose L so A−LC stable & faster than plant. Duality: designing L for (A,C) ≡ pole placement for (Aᵀ,Cᵀ), so Lᵀ = K of the dual.

8.9 Kalman filter (link #285)

Discrete predict/update; process noise Q_k, measurement noise R_k:

predict:  x̂⁻ = A x̂ + B u ;        P⁻ = A P Aᵀ + Q_k
update:   S  = C P⁻ Cᵀ + R_k ;     K = P⁻ Cᵀ S⁻¹
          x̂  = x̂⁻ + K(z − C x̂⁻) ;  P = (I − K C) P⁻   // Joseph form for PSD safety

Joseph form P=(I−KC)P⁻(I−KC)ᵀ + K R_k Kᵀ preserves symmetry/PSD. LQG = LQR gain K ⊕ Kalman gain (separation principle).

8.10 Linear MPC

  • Prediction model: stack x[k+1]=A_d x+B_d u over horizon N → X = Φ x₀ + Γ U.
  • Cost: J = Σ_{i=0}^{N−1}(xᵢᵀQxᵢ + uᵢᵀRuᵢ) + x_NᵀP_f x_N.
  • Condensed QP (eliminate states): min_U ½ Uᵀ H U + (x₀ᵀ Fᵀ) U s.t. A_c U ≤ b_c (box/rate/output constraints).
  • Receding horizon: solve, apply u₀, shift, re-solve next tick. Warm-start U from previous solution.
  • Terminal cost P_f = DARE solution → nominal stability + recursive feasibility (with terminal set).

8.11 Path following

  • Pure pursuit: pick lookahead point at distance L_d on the path; steering δ = atan2(2·Wheelbase·sin(α), L_d), α = angle to lookahead. L_d = k_v·v + L_d0.
  • Stanley: δ = θ_e + atan2(k·e_fa, v + k_s), where θ_e heading error, e_fa front-axle cross-track error, k cross-track gain, k_s softening at low speed.

8.12 Worked example — step response of standard PID on FOPDT

Plant G(s)=2 e^{−0.5s}/(3s+1). ZN open-loop (reaction curve) → Kp≈1.2·τ/(K·L)=1.2·3/(2·0.5)=3.6, Ti=2L=1.0, Td=0.5L=0.25. Closed-loop step: rises, ~10–20 % overshoot, settles ~6–8 s, zero steady-state error (integral). Refined (lower Kp, larger Ti) → ≤5 % overshoot, longer settle. Conformance fixture stores expected y[k] ± tol.

8.14 One control tick (sequence)

tick(k):
  1. wait for fixed-step deadline; record wake_jitter
  2. sample sensors -> z[k]            (sim: y + noise)
  3. estimator.update(u[k-1], z[k]) -> x̂[k]      (Kalman/Luenberger)
  4. r[k] = reference(k)               (or trajectory point)
  5. u_ff = feedforward(r[k])          (optional)
  6. u_raw = controller.update(r[k], x̂[k], dt) + u_ff
  7. u[k] = rate_limit(saturate(u_raw)); anti-windup feedback (u[k]-u_raw)
  8. assert is_finite(u[k]); enforce I1
  9. apply u[k] to plant/actuator
 10. record tick_compute_us; check deadline (I3); telemetry

  • Order-of-evaluation in RK4 stages (reuse x not updated state) → subtle bias. Dead-time buffer indexing off-by-one. TF→SS losing a pole on cancellation. Trace buffer overflow on long sims → use streaming CSV, bounded ring in no_std.

1.7 Performance Concerns

  • RK4 = 4 derivative calls/step → dominant cost in sim; keep derivative alloc-free. Trace recording I/O batched (flush every N steps). For sweeps, parallelize across scenarios (rayon, host only).

1.8 Edge Cases

  • Stiff systems (fast+slow modes) → fixed-step RK4 may need tiny Δt; document, suggest implicit (deferred). NaN in derivative (e.g. divide by state) → is_finite guard halts sim with diagnostic. Negative Δt rejected.
  • Overflow: f32 accumulation in a long-running sim (>1e7 steps) losing precision in the trace timestamp — use f64 time base even under an f32 state scalar.

1.9 Failure Analysis

  • Tustin frequency warping silently shifting a notch → require prewarp when a target frequency matters. Matrix exponential under-squaring → loss of accuracy; pick scaling by ‖AΔt‖. Busy-wait pegging a core → document, prefer timer where available. Histogram bucket saturation hiding tail latency.
  • Monotonic clock read racing a timer interrupt on embedded targets → torn reads of a 64-bit counter on a 32-bit MCU; require an atomic/read-twice pattern in the Clock impl, not just in ctrl-rt's consumer.

2.7 Performance Concerns

  • wait_until precision vs CPU burn tradeoff. Telemetry update must be branch-light, alloc-free. Matrix exponential is offline (discretize once), not in hot loop. Cache-align loop state.
  • atan2/exp calls inside libm-backed prewarp computation are offline-only; confirm no transcendental function appears in the per-tick jitter/deadline accounting path itself.

2.8 Edge Cases

  • Clock wraparound (cycle counter) → use wrapping arithmetic + monotonic guarantee. First tick (no last) → seed jitter baseline. Δt jitter beyond budget repeatedly → escalate to fault. Suspended host (laptop sleep) → detect huge gap, enter safe-state.
  • Clock-skew: NTP/host-clock step (not just wraparound) mid-run → detect a Δt read outside [0.5,2.0]×nominal and treat as a skew fault, not a jitter sample.
  • Saturation of the jitter histogram's top bucket masking a true outlier's magnitude → widen the top bucket to +∞ and log raw value alongside the bucket increment.

2.9 Failure Analysis

  • Deadline miss: symptom = deadline_miss_total rising; root causes = host scheduling, GC-like pauses elsewhere, heavy controller (MPC). Detection = telemetry + alert. Recovery = SafeState (hold/zero/handoff), shed optional work; forensic = jitter histogram + per-tick compute log. Blast radius = the controlled plant; contained by safe-state within 1 tick.
  • Clock-skew-induced control degradation: symptom = intermittent large wake_jitter_us spikes correlated with host NTP sync; detection = skew-event counter co-plotted with jitter histogram; recovery = disable NTP step-correction on the control host in favor of slew-only adjustment.

2.10 Operational Notes

  • Metrics exported: tick_compute_us{p50,p99}, wake_jitter_us, deadline_miss_total, safe_state_entries. Runbook: deadline-miss triage. Deployment: pin loop to isolated core (isolcpus), RT priority. Rollback: revert controller, not loop.

  • Derivative kick if differentiating e on setpoint step → must differentiate −y (Principle 12). Integral computed with wrong Δt under variable rate → enforce fixed Δt (I3). Sign error on D term. Trapezoidal vs rectangular integration mismatch with golden fixtures → fix one convention.

  • Scalar PID tick must be ≤5 µs at 1 kHz (budget §4). No branches on hot path beyond form match (resolve form at construction via enum/dispatch table). No allocation.
  • Fixed-point (Q15/Q31) tick: multiply-then-shift order matters for rounding bias — perform accumulation in a wider intermediate (i64 for Q31) before truncating, or systematic bias accumulates in I over long runs.

3.8 Edge Cases

  • Δt change mid-run (not allowed in hot loop; assert). First tick derivative (no y_prev) → zero D first tick. Setpoint = current output (zero error) → output holds. Integer-overflow in fixed-point accumulation → saturating add.
  • Ill-conditioning: Ti→0 (pure derivative-like standard form) makes Ki=Kp/Ti→∞; reject configuration below a minimum Ti floor rather than let it overflow silently.
  • Clock-skew analogue: a hot-reloaded config swapping Δt without a corresponding bumpless preload (Phase 4) — Phase 3's bare PID has no bumpless yet, so document this as a known gap closed in Phase 4, not silently tolerated here.

3.9 Failure Analysis

  • Wrong sign/gain → oscillation or runaway in sim (caught by sim magnitude guard, never reaches actuator). Detection: step-response fixture diff fails in CI. Recovery: corrected gains; regression fixture added.
  • Fixed-point rounding-bias drift: symptom = slow steady-state offset reappearing despite integral action; detection = long-run (≥1e6 tick) fixed-point vs f64 differential fixture; recovery = widen intermediate accumulator or switch to f64 for the integral state even in an otherwise fixed-point pipeline.

3.10 Operational Notes

  • Telemetry: p_term, i_term, d_term, e, u_raw. Config hot-reload deferred to P4 (needs bumpless). Logging structured per tick (host) / ring buffer (embedded).

Phase 4 — PID Robustness (Anti-Windup, Derivative Filter, Setpoint Weighting, Bumpless, Saturation + Rate Limits)

4.1 Objectives

  • Harden PID to production: anti-windup (clamp + back-calculation), filtered derivative, 2-DOF setpoint weighting (b,c), bumpless transfer, output saturation + rate limit fully wired (invariants I1, I2, I9; Principles 2, 3, 6, 12).

4.2 Detailed Implementation Steps

  • antiwindup.rs: Clamp (conditional integration: freeze when saturated and error deepens saturation) and BackCalc { tt } (add (u−u_raw)/Tt to integrator input, B2 ch.4; P7 back-calculation; ADR-8). (I2; Principle 2)
  • derivative.rs: first-order derivative filter Tf=Td/N, N∈[8,20] default; derivative strictly on measurement. (§8.2 filtered D; Principle 12; P13; R7)
  • setpoint.rs: proportional weight b (e_p=b·r−y), derivative weight c (usually 0). (B2 ch.5; P8 two-DOF rationale)
  • bumpless.rs: preload(u) sets integral so u_raw==u at switch; reset filter states; used by mode/gain switch and manual↔auto. (Principle 6; I9; R1 SetMode)
  • Final output stage: saturate then rate_limit (ctrl-core), feeding anti-windup the actual u. (I1; Principle 3; §8.4)
  • Back-calculation Tt auto-default Tt=√(Ti·Td) when Td>0 else Tt=Ti/2, both overridable; document why an unconditionally-fixed Tt mistunes PI-only (no D) loops. (§8.4; P7)

4.3 Deliverable

  • A PID that holds I1/I2/I9 under aggressive setpoints and actuator limits. ctrlctl sim --controller pid --saturate --aggressive shows no windup overshoot and bumpless mode switches.

4.4 Acceptance Criteria

  • With actuator clamped, a large setpoint step shows no post-saturation overshoot beyond fixture tol (back-calc) vs uncontrolled windup baseline; integral stays |I|≤I_max (I2). Mode switch produces |Δu|≤rate_limit at the switch tick (I9). Setpoint step shows no derivative kick. Steady-state error still 0 (I5). Differential vs reference anti-windup behavior within tol.

4.5 Conformance Fixtures

  • conformance/pid/windup_clamp.toml, windup_backcalc.toml (saturated step, expected bounded recovery), bumpless_switch.toml (pre/post u), setpoint_weight.toml, deriv_filter_noise.toml (noisy meas → bounded D). Degenerate: Tt→∞ (back-calc off), N→∞ (unfiltered D, expect noise amplification flagged), umin>umax rejected.
  • conformance/pid/tt_autotune_default.toml — verifies the Tt=√(Ti·Td) default against a hand-computed value for three (Ti,Td) pairs, catching a formula-substitution error (e.g. Ti·Td vs Ti+Td).
  • conformance/pid/simultaneous_sat_rate.toml — actuator hits both amplitude saturation and rate limit in the same tick; expected rate limit applied after amplitude clamp, output still within [u_min,u_max] (I1).

4.6 Pitfalls

  • Back-calc Tt too small → sluggish/limit-cycle; too large → still winds up. Rate limit introducing phase lag that destabilizes an otherwise-stable loop → account in analysis (P12). Clamping that freezes integral in the wrong direction → must allow integration out of saturation. Resetting filter on bumpless but forgetting integral preload → bump.
  • Applying rate limit before amplitude saturation (wrong order) can produce an output outside [u_min,u_max] when the rate-limited path overshoots the clamp on the way back down — fix the fixed order: saturate, then rate-limit against the previous applied (already-saturated) output.

4.7 Performance Concerns

  • Extra state (integral clamp, back-calc, filter) still ≤5 µs/tick. Branch in anti-windup minimal (one comparison). Fixed-point: back-calc division → precompute 1/Tt.
  • BackCalc division (u−u_raw)/Tt recomputed every tick even when not saturated — precompute 1/Tt once at config time (already noted) but also skip the subtraction entirely when u_raw==u to save the branch-predictable fast path.

4.8 Edge Cases

  • Simultaneous saturation + rate limit active. Setpoint and measurement both NaN-guarded. Mode switch while saturated (preload must respect clamp). Δu_max larger than umax−umin (rate limit never binds). Zero Δt during preload.
  • NaN in Tt (e.g. Ti·Td product overflow in fixed-point) → validate Tt finite and >0 at construction, reject otherwise rather than propagating NaN into every tick's back-calc term.
  • Overflow: integral clamp bound I_max set larger than the fixed-point representable range → clamp I_max to the type's safe range at config validation, not at first overflow.

4.9 Failure Analysis

  • Saturation lockout (integrator stuck, output pinned): symptom = u at limit + sat_active high + error not closing; detection = telemetry correlation; recovery = anti-windup (auto) / reduce setpoint or increase actuator (manual); forensic = integral + sat traces. Bump on switch: symptom = Δu spike at mode_switch_events; recovery = fix preload; regression fixture.
  • Wrong-order clamp/rate-limit bug (§4.6): symptom = u_applied observed outside [u_min,u_max] in telemetry despite I1 assumed enforced; detection = post-clamp range assertion (already required by I1) catching it in CI before field deploy; recovery = reorder the two stages, add simultaneous_sat_rate.toml as a permanent regression.

4.10 Operational Notes

  • New metrics: windup_events, sat_active, rate_active, mode_switch_events. Config now hot-reloadable via bumpless preload (safe online retune). Runbook: windup triage. Rollback: revert gains with bumpless preload to avoid transient.

Phase 5 — Auto-Tuning (Ziegler–Nichols, Relay-Feedback / Åström–Hägglund)

5.1 Objectives

  • Implement ctrl-tune: ZN open-loop (reaction curve) + closed-loop (ultimate gain/period) and relay-feedback auto-tuning; FOPDT fit from step data.

5.2 Detailed Implementation Steps

  • fopdt.rs: fit K, τ, L from a step-test trace (tangent + two-point / area methods). (§8.12 FOPDT example plant; I5 steady-state check)
  • ziegler_nichols.rs: open-loop tables (P/PI/PID) from K,τ,L; closed-loop from ultimate gain Ku/period Tu (proportional-only oscillation detection). (P1 Ziegler–Nichols 1942 tables; B2 ch.6)
  • relay.rs: relay-feedback experiment — drive plant with relay (±d) under safety supervisor, detect sustained oscillation, extract Ku=4d/(πa) (a=oscillation amplitude), Tu=period; map to PID via ZN/Tyreus–Luyben. (P2 Åström–Hägglund 1984; B2 ch.6; I3 deadline during online relay)
  • Output PidConfig; optionally apply via bumpless preload. (Phase 4 bumpless preload; I9; ADR-9 serde output)
  • Tyreus–Luyben rule table alongside classic ZN, selectable at the same call site (ziegler_nichols.rs::Rule::{Classic,TyreusLuyben,SomeOvershoot,NoOvershoot} per Åström–Hägglund refinements). (P8; B2 ch.6)

5.3 Deliverable

  • ctrlctl tune --plant fopdt --method zn-open and --method relay emit gains + a closed-loop step preview; relay runs in sim with amplitude/period detection.

5.4 Acceptance Criteria

  • ZN open-loop on the reference FOPDT reproduces textbook gains (Kp,Ti,Td) to 1 % and yields ≤20 % overshoot fixture. Relay experiment recovers Ku,Tu within 5 % of analytic for a known 2nd-order plant. Tyreus–Luyben option yields more conservative (lower overshoot) gains as expected.

5.5 Conformance Fixtures

  • conformance/tune/zn_open_fopdt.toml (expected gains+response), zn_closed_ultimate.toml, relay_second_order.toml (expected Ku,Tu±5 %), fopdt_fit.toml (trace→K,τ,L). Degenerate: non-oscillating relay (over-damped, tiny relay) → timeout + diagnostic; noisy step → robust fit with hysteresis.
  • conformance/tune/tyreus_luyben_gains.toml — same Ku,Tu input as zn_closed_ultimate.toml; expected Tyreus–Luyben Kp lower and Ti higher than classic ZN by the documented ratios, with resulting overshoot ≤ classic.
  • conformance/tune/relay_hysteresis_noise.toml — relay experiment on a plant with injected measurement noise at 2% of relay amplitude d; expected hysteresis band sized ≥2× noise std prevents spurious switching, Ku/Tu estimate still within 5% of noise-free case.

5.6 Pitfalls

  • Relay without hysteresis chattering on noise → add hysteresis band sized to noise. ZN's known aggressiveness (≈25 % overshoot) → document, offer refined rules. FOPDT fit sensitive to where tangent is taken → use area/two-point method, report fit residual. Running relay on an unsafe plant without limits → mandatory saturation + supervisor.
  • Running the relay experiment with d too large for the actuator's linear range → the 'plant' seen by the relay is actually saturation-limited, biasing Ku low; bound d to a documented fraction of actuator headroom and flag if the output itself saturates during the experiment.

5.7 Performance Concerns

  • Tuning is offline/online-experiment, not hot-loop; cost dominated by sim length / experiment duration. Oscillation detection (zero-crossing, peak) O(samples). No allocation needed beyond a small history buffer.
  • Zero-crossing detection for relay oscillation period is O(1) per sample but sensitive to sample-rate quantization at high frequencies; require the loop's Δt to resolve at least 20 samples per oscillation period or flag the period estimate as low-confidence.

5.8 Edge Cases

  • Plant with no dead time (L→0) → ZN open-loop formulas blow up; clamp / switch to closed-loop. Integrating plant (pole at origin) → reaction-curve invalid; use relay. Asymmetric relay response (nonlinearity) → report asymmetry, widen tolerance.
  • Clock-skew during an online relay experiment (real-time loop jitter distorting the measured period) → run relay tuning only when deadline_miss_total has been zero for a documented warm-up window.
  • Ill-conditioning: FOPDT fit on a near-integrating plant (τ→∞) makes K/τ→ ill-defined; detect via fit residual and reject the FOPDT fit in favor of an explicit integrating-plant tuning table (deferred-lite note).

5.9 Failure Analysis

  • Relay experiment fails to oscillate: symptom = no sustained limit cycle within timeout; detection = amplitude below threshold; recovery = increase relay d (within safety) or fall back to model-based; forensic = relay trace. Aggressive ZN gains destabilize field plant: detection = margins gate (P12) before deploy; recovery = refined/Tyreus–Luyben.
  • Biased Ku from a saturation-limited relay experiment (§5.6): symptom = tuned gains subsequently too aggressive/conservative vs. the plant's true linear-range dynamics; detection = compare relay-derived margins against the analysis gate in Phase 12 before shipping; recovery = re-run relay with reduced d, or model-based (ZN) tuning instead.

5.10 Operational Notes

  • Relay auto-tune is the only normally-online experiment; gate behind explicit operator action + safety supervisor + bounded d. Log experiment trace for audit. Emit tune_method, Ku, Tu, fit residual. Auto-applied gains go through bumpless preload (I9).

Phase 6 — Feedforward + Cascade Control + Gain Scheduling

6.1 Objectives

  • Implement ctrl-ff: model-based feedforward, cascade (inner/outer) composition, and gain scheduling over operating points (Principle 6 for scheduling-induced bumps; structure from §8.13).

6.2 Detailed Implementation Steps

  • feedforward.rs: static gain FF (u_ff=K_ff·r) and dynamic/model-inverse FF (invert plant or known disturbance path; cancel measurable disturbance). Sum u_ff ahead of summing junction. (§3 architecture diagram; Principle 6 bumpless; B1 ch.10)
  • cascade.rs: outer controller output becomes inner setpoint; enforce inner ≥5–10× faster; per-loop saturation/anti-windup; outer anti-windup tracks inner saturation. (§8.13 cascade ASCII diagram; I2 windup in cascade; Principle 2)
  • gain_schedule.rs: lookup/interpolate controller params by scheduling variable (e.g. speed, operating point); bumpless on segment change via preload (I9); optional smooth blend. (Phase 4 bumpless preload; ADR-9 scheduled config serde)
  • Feedforward gain-scheduling interaction: when both static FF and gain-scheduled feedback change on the same operating-point transition, sequence the update so FF updates after the feedback preload completes, avoiding a compound bump that bumpless transfer alone (per-loop) wouldn't catch. (§6.2; Principle 6; I9)

6.3 Deliverable

  • ctrlctl sim --structure cascade and --feedforward model showing faster disturbance rejection and reference tracking than single-loop PID; scheduled gains transitioning bumplessly.

6.4 Acceptance Criteria

  • Cascade rejects an inner-loop disturbance ≥5× faster than single-loop (settling-time fixture). Feedforward reduces tracking lag on a ramp reference (peak error ↓ ≥50 % vs FB-only). Gain-schedule transition shows |Δu|≤rate_limit (I9) across boundaries.

6.5 Conformance Fixtures

  • conformance/ff/static_ff_ramp.toml, model_ff_disturbance.toml, cascade_disturbance.toml (inner vs single-loop settling), gain_schedule_transition.toml (bumpless). Degenerate: non-invertible plant for FF (improper) → fall back to static + warn; cascade with inner slower than outer → reject/warn.
  • conformance/ff/ff_fb_bump_sequencing.toml — simultaneous FF-gain and scheduled-FB-gain change at one tick; expected combined |Δu| still ≤ rate limit (I9), not just each contribution individually.
  • conformance/ff/cascade_windup_crosstalk.toml — outer loop saturates while inner loop is healthy; expected outer anti-windup engages without freezing the inner loop's own (independent) integral.

6.6 Pitfalls

  • Inverting a non-minimum-phase plant for FF → unstable inverse; use stable approximate inverse / disturbance FF only. Inner loop not fast enough → cascade offers no benefit, can destabilize. Gain-schedule chattering at a boundary → hysteresis/blend. Double-counting integral action across cascade loops → windup.
  • Scheduling table interpolation using linear interpolation across a highly nonlinear gain surface → visible overshoot mid-segment; validate against a finer reference grid and flag segments needing extra breakpoints.
  • Outer-loop anti-windup naively watching its own output saturation while the actual saturation is on the inner loop's actuator → wire outer anti-windup off the inner loop's saturation flag, not a nonexistent outer actuator limit.
  • FF sign convention mismatch when the disturbance model and the plant model use opposite sign conventions for the same physical disturbance → unit/sign audit at integration, not just at each model's own tests.

6.7 Performance Concerns

  • Cascade = two PID ticks (still ≤10 µs). FF model-inverse may need a small filter (extra state). Gain-schedule lookup O(1) with precomputed segments; interpolation cheap.
  • Gain-schedule lookup on embedded targets: binary search over breakpoints is O(log segments); for ≤16 segments a linear scan is faster and branch-predictable — prefer linear scan below that threshold.

6.8 Edge Cases

  • Scheduling variable out of table range → clamp to nearest segment + flag. Inner loop saturating must back-propagate to outer anti-windup. FF and FB both saturating → combined limit handling. Operating-point jump (teleport) → bumpless preload.
  • Clock-skew/Δt hiccup during a scheduled transition → hold the previous segment's gains for that tick rather than interpolating against a corrupted timestamp.
  • NaN in the scheduling variable (sensor dropout) → fall back to the last valid segment, not an extrapolated/undefined lookup.

6.9 Failure Analysis

  • Cascade instability from sluggish inner loop: symptom = slow oscillation; detection = margins per loop; recovery = retune inner faster or decouple; forensic = inner/outer traces. FF over-actuation: symptom = u saturating on reference change; recovery = scale FF, add filter.
  • Compound bump from unsequenced FF/scheduled-FB update (§6.2/§6.6): symptom = |Δu| telemetry exceeds rate limit despite each subsystem's own bumpless logic passing its unit test; detection = the new ff_fb_bump_sequencing.toml regression; recovery = enforce the documented update order at the composition point.

6.10 Operational Notes

  • Metrics: ff_contribution, cascade_inner_sat, schedule_segment. Document scheduling table as versioned config. Rollback: disable FF (degrade to FB) safely; disable scheduling → pin to a safe segment.

7.1 Objectives

  • Implement ctrl-ss: state-space ops, controllability/observability (matrices + ranks + Gramians), Ackermann pole placement; enforce Principle 10 / invariant I4 design-time checks.

7.2 Detailed Implementation Steps

  • statespace.rs: StateSpace (reuse StateSpacePlant), series/parallel/feedback interconnection, similarity transforms, eigenvalues (QR iteration on Hessenberg form). (§8.1; B4 ch.9)

  • place.rs: Ackermann K=[0…1]𝒞⁻¹φ_d(A) (SISO, §8.6); validate controllable pair first; return typed error with uncontrollable-mode diagnostic if rank(𝒞)<n. (B4 ch.10; ADR-26 typed errors; §8.15 degenerate cases)
  • StateFeedback controller (u=−Kx̂) implementing Controller. (Principle 5 separation; Phase 8 for observer integration)
  • Report Gramian-based condition number alongside the binary rank check, so a system that is technically full-rank but numerically near-uncontrollable is flagged rather than silently accepted. (§8.5; I4)

7.3 Deliverable

  • ctrlctl analyze --plant cartpole --ctrb --obsv reports ranks/Gramians; ctrlctl sim --controller statefb --place "-2,-3,-4,-5" balances the linearized cart-pole.

7.4 Acceptance Criteria

  • Controllability/observability ranks match analytic for cart-pole, double-integrator (full rank) and a deliberately uncontrollable system (rank deficit detected). Ackermann places poles to within 1e-6 of requested (verify eig(A−BK)); closed-loop stable (I4). Differential vs python-control ctrb/obsv/place within tol.

7.5 Conformance Fixtures

  • conformance/ss/ctrb_cartpole.toml, obsv_cartpole.toml, uncontrollable_rank.toml, ackermann_place.toml (requested vs achieved poles). Degenerate: uncontrollable → error; repeated requested poles (defective) → warn (Ackermann ill-conditioned); near-uncontrollable (tiny Gramian) → high-gain warning.
  • conformance/ss/gramian_condition_flag.toml — a plant with rank(𝒞)=n but condition number >1e8; expected a near_uncontrollable warning even though the hard rank check passes.
  • conformance/ss/mimo_reject.toml — m>1 input plant passed to place_poles; expected a typed rejection directing the caller to LQR (Phase 8), not a wrong/partial SISO-only result.

7.6 Pitfalls

  • 𝒞⁻¹ ill-conditioned for near-uncontrollable systems → huge gains; check condition number, prefer robust placement (deferred-lite). Ackermann numerically poor for n>~5; document limit, recommend LQR (P8). Eigenvalue solver non-convergence on defective matrices. Frame/units error making B wrong scale.
  • Treating "rank(𝒞)=n" as sufficient without checking condition number → a technically-controllable but nearly-singular system yields Ackermann gains that are numerically valid but operationally enormous; always report both rank and condition number (§7.2).

7.7 Performance Concerns

  • Pole placement is offline (design-time). StateFeedback tick = one K·x̂ matvec, ≤10 µs for n≤16. Eigen/QR iteration cost O(n³) — offline only.
  • QR-iteration eigenvalue solver convergence can stall on nearly-defective matrices; cap iterations and report non-convergence explicitly rather than returning a partially-converged eigenvalue as if final.

7.8 Edge Cases

  • n=1 (scalar) placement. Complex-conjugate desired poles (must come in pairs for real K). MIMO (m>1) — Ackermann undefined; route to LQR or reject. Marginal stability (pole on axis) requested → warn.
  • Overflow: 𝒞⁻¹ entries blowing up for a near-uncontrollable system before the condition-number guard fires — check condition number before forming the explicit inverse, not after.
  • Ill-conditioning: repeated eigenvalues requested with a single scalar K in Ackermann (SISO) is mathematically valid but numerically fragile — flag and recommend spacing desired poles by ≥1% of the dominant time constant.

7.9 Failure Analysis

  • Uncontrollable mode: symptom = placement error / wild gains; detection = rank check (I4 pre-check); recovery = redesign actuation / accept partial placement; forensic = Gramian + 𝒞. High-gain feedback saturating actuator: detection = sim saturation; recovery = relax pole speed, use LQR weighting.
  • Numerically-enormous but "valid" Ackermann gain from a near-uncontrollable pair (§7.6): symptom = closed-loop simulation saturates the actuator immediately; detection = condition-number report at design time (before any simulation); recovery = respecify actuation or accept slower requested poles.

7.10 Operational Notes

  • Analysis outputs versioned report (ranks, Gramian condition, achieved poles) — part of deploy gate. Metric max_pole_real (must be <0 continuous). Document that pole placement chooses where, LQR chooses optimally given cost.

8.1 Objectives

  • observer.rs: Luenberger::design via pole placement on (Aᵀ,Cᵀ) (reuse ctrl-ss::place), Lᵀ=K_dual; update runs x̂̇=Ax̂+Bu+L(y−Cx̂) discretized. (§8.8 duality; B4 ch.10; Principle 5; I6)
  • lqg.rs: compose StateFeedback(K) with an estimator (Luenberger or KalmanFilter); controller uses x̂ (separation principle); single Controller impl. (§8.8 duality; B6 ch.9; Principle 5; ADR-15 diff vs python-control)
  • Verify the ARE solver's chosen invariant subspace is stable post-hoc (eig(A-BK) all LHP) even though the Hamiltonian/Schur method is expected to select it — a documented sanity check catches an eigenvalue-sorting bug in the decomposition. (§8.7; ADR-22)

8.3 Deliverable

  • ctrlctl sim --controller lqr --plant cartpole balances with optimal feedback; --observer luenberger runs output-feedback LQG using only measured outputs.

8.4 Acceptance Criteria

  • LQR gain K matches python-control.lqr within 1e-6 on cart-pole; closed-loop poles in LHP (I4); cost J lower than a comparable pole-placement design at equal settling. Observer error e=x−x̂→0 with stable, faster-than-plant dynamics (I6). LQG output-feedback stabilizes using only y.

8.5 Conformance Fixtures

  • conformance/lqr/cartpole_gain.toml (K, poles), dare_double_integrator.toml, observer_convergence.toml (error decay rate), lqg_output_feedback.toml. Degenerate: R singular → regularize + warn; (A,B) unstabilizable → ARE no stabilizing solution → error; (A,C) undetectable → observer fails.
  • conformance/lqr/are_subspace_sanity.toml — verifies eig(A-BK) strictly LHP for 5 stored (A,B,Q,R) fixtures, independent of trusting the solver's internal subspace selection.
  • conformance/lqr/luenberger_vs_kalman_gain.toml — same (A,C) pair; expected steady-state Kalman gain (Phase 9) and a hand-placed Luenberger L both stabilize A-LC, illustrating (not equating) the two design philosophies.

8.6 Pitfalls

  • ARE solver picking the wrong (anti-stabilizing) invariant subspace → unstable K; verify closed-loop stability post-solve. R near-singular → blow-up; regularize. Observer too fast → amplifies measurement noise (bandwidth tradeoff). Discretizing observer with Euler at large Δt → instability (use Tustin/ZOH, I7).
  • Confusing the continuous ARE with the discrete DARE when the plant model was discretized upstream (Phase 2) — always match the Riccati variant to the state-space representation actually in use; a continuous ARE applied to a Δt-discretized A_d silently produces the wrong K.

8.7 Performance Concerns

  • ARE/DARE solve offline (O(n³)). LQG tick = observer update (matvec+gain) + K·x̂ ≤ ~15 µs for n≤16. Joseph-form / Cholesky maintain PSD without extra cost in hot loop (observer gain is constant for Luenberger).
  • The observer's constant Luenberger gain requires no Cholesky at tick time; if swapped for time-varying Kalman gain (Phase 9) without the steady-state option, tick cost grows from O(n²) to O(n³) — document this cost step explicitly at the swap point.

8.8 Edge Cases

  • n=2 analytic ARE cross-check. Q=0 (cheap control) / R≫Q (slow). Cross-term N in cost (xᵀNu) — support or document exclusion. Unstable open-loop plant (cart-pole) — observer must still converge.
  • Overflow: R⁻¹ computed explicitly for R near-singular before the regularization guard fires — order operations so the condition-number check on R runs before any inverse is formed.
  • Clock-skew analogue: discretizing the observer update at the wrong effective Δt after a scheduler hiccup (Phase 2 skew) — observer gains tuned for nominal Δt destabilize under a stretched interval; clamp Δt fed to the observer update to the nominal value on a detected skew event.

8.9 Failure Analysis

  • Observer divergence: symptom = ‖x−x̂‖ grows, control acts on bad estimate; detection = residual/innovation monitor (I6); recovery = reset observer to measurement-consistent state, slow L; forensic = estimate vs truth trace. ARE no solution: detection = solver flag (unstabilizable); recovery = fix model/actuation.
  • Wrong Riccati variant applied post-discretization (§8.6): symptom = closed-loop simulation unstable despite K computed from a "correct-looking" ARE; detection = the I4 pole check at design time immediately flags LHP/unit-circle mismatch; recovery = re-derive from the matching (continuous vs discrete) model.
  • Time-varying-cost tick-budget surprise (§8.7): symptom = LQG tick intermittently exceeds the ≤15 µs budget after an observer swap; detection = ctrl-bench per-observer-type regression; recovery = fall back to steady-state (precomputed) gain.

8.10 Operational Notes

  • Metrics: estimator_residual, max_pole_real, LQR J. Document Q/R as the tuning knobs (Bryson's rule for initial scaling). Separation principle means estimator swappable with Kalman (P9) with no controller change. Rollback: revert to PID if state-feedback misbehaves (both implement Controller).

Phase 9 — Kalman-Filter Estimator Integration (Cross-Link #285)

9.1 Objectives

  • Implement ctrl-kf: discrete Kalman predict/update (Joseph form), Q/R tuning + NIS diagnostics; integrate as the LQG estimator; define the seam to #285 sensor fusion (invariant I6).

9.2 Detailed Implementation Steps

  • kalman.rs: predict(u) (x̂⁻=Ax̂+Bu, P⁻=APAᵀ+Q), update(z) (S=CP⁻Cᵀ+R, K=P⁻CᵀS⁻¹, x̂=x̂⁻+K(z−Cx̂⁻), Joseph-form P). Symmetrize P each step. (§8.9 predict/update equations; P3 Kalman 1960; ADR-22 Cholesky for S; I6)
  • tuning.rs: Q/R selection guidance; NIS (νᵀS⁻¹ν) and innovation-whiteness diagnostics (B6 ch.9); steady-state Kalman gain option (precompute via DARE for constant K, P11). (I6; §9 cross-link #285)
  • Integrate into lqg.rs (Kalman as drop-in estimator via Principle 5). Define #285 interface: consume an external x̂+covariance when available; Kalman here is the minimal fallback/controller-facing filter. (ADR-5 for discretization of P⁻ update)
  • Precompute and cache the steady-state Kalman gain via DARE (already noted) but also expose a runtime switch to the time-varying gain for the transient (first N ticks) before steady-state convergence, since a purely steady-state gain from t=0 under-weights the initial uncertain estimate. (§9.2; P11)

9.3 Deliverable

  • ctrlctl sim --controller lqr --observer kalman --noise meas=0.1 tracks state under sensor noise; NIS within expected χ² bounds.

9.4 Acceptance Criteria

  • On a noisy double-integrator, estimate RMSE lower than raw measurement; P converges to steady-state matching DARE solution (1e-6); NIS mean ≈ measurement dimension (consistency). Joseph form keeps P symmetric PSD (eigenvalues ≥0) over a long run. Differential vs python-control/filterpy Kalman within tol.

9.5 Conformance Fixtures

  • conformance/kf/double_integrator_track.toml (RMSE bound), steady_state_gain.toml (vs DARE), nis_consistency.toml, joseph_psd.toml. Degenerate: R=0 (perfect sensor → P→0, numerical care); Q=0 (no process noise, P shrinks); dropout (skip update, predict-only).
  • conformance/kf/transient_vs_steady_gain.toml — compares time-varying gain for the first 50 ticks against a hand-solved sequence; expected convergence to the DARE steady-state gain within 1e-6 by tick 50 on the reference double-integrator.
  • conformance/kf/outlier_gating.toml — a single injected 10σ measurement outlier; expected NIS-gated rejection (§9.8) keeps the estimate within 2σ of truth at the next tick, vs. an ungated filter's expected large transient.

9.6 Pitfalls

  • P losing symmetry/PSD without Joseph form → divergence; always Joseph + symmetrize. S⁻¹ ill-conditioned (near-singular innovation cov) → regularize/Cholesky-solve. Mis-scaled Q/R (units!) → over/under-confident filter. Using one-step instead of steady-state gain on embedded when CPU-bound → offer precomputed gain.
  • Applying the continuous process-noise intensity directly as the discrete Q_k without the Δt-dependent conversion (Q_k≈Q_c·Δt for small Δt, exact via Van Loan's method otherwise) → systematically wrong filter confidence; document which convention (Q_k vs Q_c) each config field uses.
  • Reusing the predict step's x̂⁻ in place for both the NIS computation and the next predict call without snapshotting → a subtle aliasing bug if update() mutates in-place before nis() is queried; document call-order contract (predict → nis-eligible → update).

9.7 Performance Concerns

  • Full Kalman tick = matrix ops O(n³) (the S⁻¹/P updates) — for n≤8 fine (≤20 µs); steady-state gain reduces tick to matvecs. Cholesky-solve instead of explicit inverse. Alloc-free fixed-size.
  • NIS/gating check adds one scalar comparison per tick — negligible vs the O(n³) S⁻¹/P update; the gating threshold (χ² table lookup) should be precomputed per measurement dimension, not evaluated at runtime.

9.8 Edge Cases

  • Sensor dropout (predict-only, P grows — flag). Out-of-order/late measurement (deferred to #285). Sudden large innovation (outlier) → gating (reject z if NIS > threshold). Negative-definite P from numerical error → reset/symmetrize.
  • Overflow: trace_P diverging under a persistently-gated (all measurements rejected as outliers) run — cap consecutive gated rejections and force-accept the next measurement to prevent an ever-growing, ungrounded P.
  • Ill-conditioning: S near-singular when a measurement is nearly redundant with another already fused in the same tick (batched multi-sensor update) — Cholesky-solve S and detect the failure rather than inverting explicitly.

9.9 Failure Analysis

  • Filter divergence: symptom = NIS persistently high, estimate drifts; root cause = wrong model/Q/R, missed nonlinearity; detection = NIS gate + residual whiteness; recovery = reset P, re-tune Q/R, fall back to direct measurement; forensic = innovation log. Blast radius = controller acts on bad x̂; contained by estimator-residual safe-state.
  • Persistent outlier-gating divergence (§9.8): symptom = gated-rejection counter climbing while trace_P grows unbounded; detection = a max-consecutive-gated threshold breach; recovery = force-accept the next measurement, log the episode for post-hoc sensor-health review.

9.10 Operational Notes

  • Metrics: nis, trace_P, innovation, dropout_count. Document the #285 handoff: when sensor-fusion stack is present, it supplies x̂; this Kalman is the standalone/controller-local fallback. Rollback: switch observer Kalman→Luenberger (constant gain, simpler) without touching controller.

Phase 10 — Linear MPC (Prediction Model, Horizon Cost, Constraints, Condensed QP, Receding Horizon)

10.1 Objectives

  • Implement ctrl-mpc: condensed linear MPC over horizon N with box + rate + (optional) output constraints, a dependency-light QP solver (ADMM + active-set), warm-starting, receding-horizon execution, and feasibility/fallback (invariant I10, Principle 8/13).

10.2 Detailed Implementation Steps

  • mpc.rs: build prediction matrices Φ,Γ; condense cost to H=Γᵀ Q̄ Γ + R̄, F=Γᵀ Q̄ Φ; H constant if model/weights fixed (precompute + Cholesky factor once). Terminal cost P_f from DARE. (§8.10 condensed QP; B5 ch.1–2; P12 terminal ingredients; ADR-22)
  • constraints.rs: assemble A_c U ≤ b_c from [u_min,u_max], rate limits (|Δu|), and output constraints (via Γ); soft-constraint slack option (penalty) for recursive feasibility. (B8 ch.6; B5 ch.8; I10; I1)
  • qp_admm.rs: ADMM for box/inequality QP (splitting, scaling/preconditioning, warm-start, infeasibility detection, P9/R3); qp_active_set.rs: primal active-set with warm-start across ticks (homotopy, P10/R4), iteration cap (I3 deadline). (ADR-6)
  • MpcController::update: form f from current x̂ and reference, warm-start U from previous shifted solution, solve, apply u₀, store for next tick; on Infeasible/MaxIters → soft-constrain or last-feasible/safe-state. (§8.10 receding horizon; §8.14 tick sequence; Principle 8/13; I10)
  • Cache the condensed H matrix's Cholesky factorization keyed by (model, weights, horizon) so a fixed-model deployment factors once at startup, not per tick — refactor only on an explicit model/weight change (rare, off the hot path). (§10.2; ADR-22)

10.3 Deliverable

  • ctrlctl sim --controller mpc --plant double_integrator --umax 1 --horizon 20 drives state to origin while respecting input/rate limits; constraints visibly active and honored.

10.4 Acceptance Criteria

  • Constrained double-integrator: u never violates [u_min,u_max] or rate limit (I1); state reaches origin; cost ≤ unconstrained LQR + constraint penalty. QP solution matches OSQP (binding ADR-6 reference) within tol on stored fixtures. QP solve time ≤200 µs (N≤20, m≤2) warm-started (§4). Receding-horizon closed loop stable with terminal P_f.

10.5 Conformance Fixtures

  • conformance/mpc/double_integrator_box.toml (trajectory + active constraints), rate_limited.toml, qp_vs_osqp.toml (solution match), infeasible_fallback.toml (conflicting constraints → fallback), warm_start_iters.toml (iters ↓ with warm-start). Degenerate: N=1 (≈constrained one-step); H not PD (regularize); empty feasible set.
  • conformance/mpc/cached_factorization_invalidation.toml — verifies the cached H Cholesky factor is correctly invalidated and recomputed when Q/R/horizon change at runtime, catching a stale-cache bug that would silently use last session's factorization.
  • conformance/mpc/ill_conditioned_horizon.toml — horizon N=20 on a lightly-damped plant; expected condensed H condition number flagged above a documented threshold, prompting preconditioning (ADR-6) rather than a silent ADMM stall.

10.6 Pitfalls

  • Condensed H ill-conditioned for long horizons / unstable plant → preconditioning (ADR-6) or sparse formulation (deferred). Active-set worst-case iteration blow-up → hard cap + ADMM fallback (I3 deadline). Forgetting to warm-start → solve time spikes. Soft constraints with too-small penalty → constraint violation; too-large → ill-conditioning. Off-by-one in receding shift.
  • Caching the condensed H factorization but forgetting to invalidate it on a runtime weight change (e.g. an operator retune) → controller silently optimizes against stale weights; gate any Q/R/horizon mutation through a single rebuild() that also busts the cache.

10.7 Performance Concerns

  • QP dominates the tick (§4 budget). Precompute/cache H factorization (constant). Warm-start from previous solution (few iterations steady-state). Alloc-free: all QP working memory preallocated sized by N·m max. SIMD the matvecs. Bound iterations to guarantee deadline (I3) — accept suboptimality over overrun.
  • Cholesky factorization of H is O(N·m)³ but done once (cached); the per-tick cost is then just triangular solves, O((N·m)²) — document this asymptotic split explicitly so a reviewer doesn't budget the tick as if refactoring every time.

10.8 Edge Cases

  • Infeasible due to disturbance pushing state outside admissible set → soft-constrain, return best-effort, flag. Active set cycling (degeneracy) → anti-cycling rule (Bland's) or perturbation. Reference outside steady-state-admissible set → track closest feasible. du_max tighter than reachable → slow but feasible.
  • Overflow: warm-started U from a previous horizon length after a runtime horizon change (mismatched dimension) → validate warm-start vector length against current N·m before use, fall back to cold-start (zero) on mismatch.
  • Clock-skew: a stretched Δt (scheduler hiccup) feeding a stale Φ,Γ prediction model computed for the nominal Δt → either recompute the prediction model for the actual Δt (costly) or clamp the fed Δt to nominal and flag, per the Phase 2 skew convention.

10.9 Failure Analysis

  • QP infeasibility: symptom = qp_status=Infeasible; detection = solver flag (I10); recovery = soft constraints → last-feasible U → safe-state; forensic = dump H,f,A_c,b_c, active set, residuals. Deadline miss from QP: symptom = tick_compute_us > budget; detection = telemetry (I3); recovery = iteration cap, shorter horizon, ADMM; forensic = solve-time profile vs N.
  • Stale-cache-after-retune bug (§10.6): symptom = MPC applies input trajectory optimized for old weights despite operator confirming a retune; detection = a config-version stamp check between the active controller and its cached factorization; recovery = force rebuild() on any weight/horizon mutation.

10.10 Operational Notes

  • Metrics: qp_iters, qp_solve_us{p50,p99}, qp_status, constraint_active_count, mpc_cost. Document horizon/solver as deploy-time tunables with measured worst-case solve time. Runbook: QP-infeasibility + deadline triage. Rollback: MPC→LQR (same model, no constraints) when CPU/feasibility budget exceeded.

Phase 11 — Autonomous Path-Following (Pure Pursuit, Stanley) + Trajectory Tracking

11.1 Objectives

  • Implement ctrl-track: pure pursuit and Stanley lateral controllers, Path projection/curvature, trajectory tracking; integrate with the kinematic bicycle plant and the reference from #287 (Principle 9 frames/units; §8.11).

11.2 Detailed Implementation Steps

  • path.rs: Path (waypoints, arclength param, nearest-point projection, curvature, lookahead-point search). (Principle 9 frames/units; §8.11)
  • pure_pursuit.rs: speed-scheduled lookahead L_d=k_v·v+L_d0; steering δ=atan2(2·Wheelbase·sin α, L_d). (P6 Coulter 1992; §8.11; I1 steer saturation)
  • stanley.rs: front-axle cross-track error e_fa, heading error θ_e, δ=θ_e+atan2(k·e_fa, v+k_s); saturate to steering limits. (P5 Thrun et al. 2006; §8.11; I1)
  • Kinematic bicycle plant in ctrl-sim for closed-loop tracking; longitudinal control via PID (reuse Phase 3/4) on speed. (Phase 1 harness; ADR-4 RK4 integration)
  • PathFollower trait; both implement it; consume Path (from #287) + VehicleState (from #285). (Principle 5/9; §1 cross-link table)
  • Vehicle-frame vs world-frame heading wrap handling shared by both Stanley and pure pursuit: normalize θ_e to (−π,π] once in path.rs rather than duplicating the wrap logic in each controller. (§8.11; Principle 9)

11.3 Deliverable

  • ctrlctl sim --controller stanley --path s_curve --speed 10 and --controller pure_pursuit track a path; emits cross-track + heading error traces and a top-down plot.

11.4 Acceptance Criteria

  • On a reference S-curve / lane-change path at fixed speed: steady-state cross-track error ≤0.1 m, bounded heading error, no oscillation (Stanley) and stable cornering (pure pursuit). Stanley converges from a 1 m initial offset with documented settling. Steering respects limits (I1). Differential vs published Stanley behavior qualitatively (cross-track decay).

11.5 Conformance Fixtures

  • conformance/track/stanley_lane_change.toml (cross-track decay), pure_pursuit_circle.toml (steady radius error), lookahead_tuning.toml (L_d vs stability), straight_recovery.toml (offset→0). Degenerate: path endpoint (no lookahead point → hold/stop); zero speed (Stanley k_s softening prevents blow-up); sharp corner exceeding steering limit.
  • conformance/track/heading_wrap_boundary.toml — path crossing the ±π heading boundary (e.g. a loop); expected no spurious large θ_e spike from an unwrapped angle subtraction.
  • conformance/track/reverse_driving_sign.toml — negative-speed (reverse) segment; expected steering sign convention documented and tested, not merely "undefined" per the §11.8 edge case note.

11.6 Pitfalls

  • Pure pursuit short lookahead → oscillation/instability; long → corner-cutting; schedule with speed. Stanley at low speed without k_s → divide-by-near-zero, huge steer; softening mandatory. Nearest-point projection ambiguity on self-intersecting paths. Discrete-time steering lag at high speed destabilizing → account in margins. Heading wrap (±π) errors.
  • Computing θ_e via plain subtraction of two headings without wrapping to (−π,π] → a path crossing due-north (0/2π boundary) produces a spurious near-2π error that saturates steering; always wrap (§11.2).

11.7 Performance Concerns

  • Lookahead/projection search must be O(window) not O(path) — maintain a moving index. Trig (atan2,sin) per tick — fine at vehicle rates (50–100 Hz), use libm. Alloc-free path buffer (fixed max waypoints embedded).
  • Nearest-point projection over a long path without a moving window degrades from O(1) to O(path length) as the vehicle progresses — maintain and advance a windowed search index every tick rather than re-scanning from the path start.

11.8 Edge Cases

  • Path shorter than lookahead → clamp to endpoint. Vehicle off-path (large e) → bounded recovery, not full-lock steer (saturate). Reverse driving (sign conventions). Speed = 0 (stationary) → no steering authority, hold. Curvature exceeding vehicle min-radius → best-effort + flag.
  • Overflow/ill-conditioning: curvature computed via finite differences on nearly-collinear waypoints (near-zero denominator) → clamp curvature computation with a minimum baseline distance, avoid dividing by a near-zero span.

11.9 Failure Analysis

  • Tracking oscillation (pure pursuit, short L_d): symptom = cross-track oscillates; detection = error-variance monitor; recovery = increase L_d/schedule with speed; forensic = lookahead + steer trace. Steering saturation lockout: symptom = steer pinned, path lost; recovery = slow down (longitudinal), reduce gain; forensic = e_fa+steer. Blast radius = the vehicle path; contained by speed reduction + safe-state.
  • Heading-wrap steering spike (§11.6): symptom = a brief full-lock steer command at a due-north path crossing with otherwise-correct tracking; detection = a heading-error magnitude filter flags any |θ_e| jump >π/2 in one tick without a corresponding path discontinuity; recovery = apply the wrap fix (§11.2), add heading_wrap_boundary.toml as a permanent regression.

11.10 Operational Notes

  • Metrics: cross_track_error, heading_error, lookahead_distance, steer_sat. Document frames (vehicle vs world, front-axle reference) explicitly (Principle 9). Reference comes from #287; state from #285. Rollback: reduce speed envelope; fall back to pure pursuit (more robust at low speed) vs Stanley.

Phase 12 — Stability Analysis, Benchmarks, Conformance vs Analytic Responses

12.1 Objectives

  • Implement analysis tooling (gain/phase margins, Nyquist, root locus, step/frequency response), the ctrl-bench criterion suite, and the full conformance battery vs analytic + python-control truth; make the deploy gate enforceable (Principle 7, invariants I4/I7/I12).

12.2 Detailed Implementation Steps

  • Frequency response: evaluate G(jω) over a grid; Bode magnitude/phase; gain margin (at −180° phase), phase margin (at 0 dB). (B1 ch.9–10; B3 ch.6; I4/I7; Principle 7)
  • Nyquist: plot G(jω), encirclements of −1 (Nyquist criterion); stability verdict. (B3 ch.6; §7 System Invariants I4)
  • Root locus: poles of 1+KG(s)=0 as K sweeps; departure/arrival, asymptotes. (B3 ch.5; §8.6 Ackermann context for gain selection)
  • Step/impulse/frequency response generators (closed + open loop) with analytic cross-checks. (§8.12 worked example FOPDT; ADR-15 diff vs python-control)
  • ctrl-bench: criterion benches for PID/LQR/Kalman/MPC tick + QP-vs-N; reference-plant battery; regression thresholds wired into CI (bench.yml). (ADR-17; §4 per-tick budget targets; ADR-18)
  • Conformance runner: execute all conformance/** fixtures, compare within tolerances, emit pass/fail report (the deploy gate). (ADR-15; Principle 7; Phase 0.2 CI setup)
  • Cross-check root-locus breakaway points against the analytic condition dK/ds=0 on the reference 2nd-order plant, not only against python-control's numerical locus, so a shared-library bug in both tools can't hide a wrong breakaway point. (§8.6; §12.2)

12.3 Deliverable

  • ctrlctl analyze --plant fopdt --margins --nyquist --rlocus emits margins + plots; cargo bench produces tick-budget + QP-scaling report; make diff runs the full conformance battery green.

12.4 Acceptance Criteria

  • Computed gain/phase margins match python-control.margin within 1e-3; designs flagged if PM<45° / GM<6 dB. Nyquist verdict agrees with pole-based stability on all reference plants. Root-locus breakpoints within 1e-3 of analytic. Benchmarks meet §4 budgets (PID ≤5 µs, LQR ≤10 µs, Kalman ≤20 µs, MPC QP ≤200 µs @ N≤20). Conformance battery 100 % pass within tolerances.

12.5 Conformance Fixtures

  • conformance/analysis/margins_fopdt.toml, nyquist_secondorder.toml, rlocus_breakpoints.toml, step_response_closed.toml (vs analytic 2nd-order formulas: overshoot=exp(−ζπ/√(1−ζ²)), settling≈4/(ζωn)). Perf regression baselines in benchmarks/. Degenerate: marginally stable (PM≈0); non-minimum-phase (RHP zero) margins; integrator (gain crossover at DC).
  • conformance/analysis/breakaway_analytic.toml — closed-form dK/ds=0 breakaway point for the reference 2nd-order plant compared against both the computed root locus and python-control, three-way agreement within 1e-3.
  • conformance/analysis/discrete_margin_erosion.toml — same continuous design discretized at increasing Δt; expected phase margin erosion trend matches the analytic z=e^{jωΔt} mapping, gating I12.

12.6 Pitfalls

  • Frequency grid too coarse → missed margin crossing; adaptive/dense grid near crossovers. Nyquist encirclement counting near −1 numerically fragile → robust winding-number. Root-locus near coincident poles. Comparing discrete vs continuous responses with wrong mapping (z=e^{sΔt}). Benchmark variance hiding regressions → criterion confidence intervals, min runs.
  • Trusting a single analysis tool (own implementation or python-control) without an independent analytic cross-check on at least one reference case → a shared conceptual bug (e.g. sign convention) passes both; the three-way breakaway check (§12.2) exists precisely to catch this class.

12.7 Performance Concerns

  • Analysis is offline; cost is the frequency grid (O(grid·n)) — fine. Benchmarks must isolate the tick (no I/O, warm caches). MPC QP-vs-N curve characterizes scaling (Phase scalability). Flamegraph the QP hot path.
  • Criterion benchmark warm-up iterations must exceed the JIT/branch-predictor warm-up window on the target CPU; too few warm-up iterations under-report steady-state tick cost, masking a real regression.

12.8 Edge Cases

  • Pure-delay systems (infinite-dimensional) → Padé-approx margins, document error. Systems with no gain crossover (always below 0 dB) → infinite gain margin. Closed-loop with RHP pole (open-loop unstable) → Nyquist encirclement interpretation. Δt too slow exposed as eroded discrete-time margin (I12).
  • Overflow/clock-skew composite case: benchmarking under a host experiencing thermal throttling mid-run produces an artificially bimodal tick-time distribution; detect via criterion's outlier report and re-run on a pinned, unthrottled core rather than accepting the contaminated distribution.

12.9 Failure Analysis

  • Insufficient margins fielded: prevented by gate (this phase) — symptom would be field oscillation; detection now = pre-deploy margin check; recovery = retune/redesign; forensic = Bode/Nyquist report archived per release. Perf regression: detection = bench.yml threshold; recovery = revert; forensic = flamegraph diff.
  • Single-tool analysis blind spot (§12.6): symptom = a design passes both the in-house margin check and python-control's, then oscillates in the field; detection = post-hoc, the analytic three-way check (§12.2) would have caught it — mandate it for every reference plant, not just as a spot-check.

12.10 Operational Notes

  • The conformance + margins report is a required release artifact (Build & Release). Metrics in analysis are static per design. Dashboards visualize margins/poles per controller config. Runbook: "controller oscillating in field" → pull archived margins, compare deployed Δt, check sampling (I12).

Scalability Analysis

  • State dimension n: PID O(1); state-feedback O(n) tick (matvec); Kalman O(n³) tick (full) — ceiling n≤32 (≤8 comfortable at kHz); LQR/observer/ARE O(n³) offline only.
  • MPC horizon N × inputs m: condensed QP dimension N·m; H is (N·m)²; ADMM/active-set per-iteration O((N·m)²); condensing O(N²·n·m). Ceiling: N·m≤200. Sparse/banded formulation deferred for long horizons (PhaseDeferred).
  • MPC QP scaling: characterized by the solve-time-vs-N benchmark; warm-starting keeps steady-state iterations low; worst-case bounded by iteration cap (deadline-safe).
  • Multi-loop systems: N independent controllers scale linearly in compute; shared estimator (#285) amortizes; scheduling on ctrl-rt/RTOS (#186) bounds aggregate budget.
  • Ceilings: the binding constraint is the per-tick deadline at the chosen rate, not memory (fixed, small). At 10 kHz, only PID/state-feedback/short-horizon MPC fit; high-n Kalman / long-horizon MPC require lower rates.
  • Sharding/partitioning: large decoupled plants → independent loops; coupled plants need centralized MPC (cost grows with combined n,N·m).

Mental Models & First Principles

The compressed intuitions an expert holds about feedback control. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it. Every cited section reference resolves.

  • MM1 — A feedback loop trades open-loop fragility for closed-loop robustness at the cost of phase. Every gain you add to reduce steady-state error also rotates the phase of the loop at every frequency. The phase margin is your account balance: each design choice (filter, delay, rate limit) makes a withdrawal; if the balance hits zero, the loop oscillates. Predicts: adding a low-pass filter to reduce noise will shrink the phase margin. Bug without it: engineers add filters to "clean up" the signal and then wonder why the stable loop starts oscillating. Applied: §8.3 (discretization methods that steal phase), Phase 12 (§12.2 margins gate), Principle 4.
  • MM2 — The integrator is a memory with infinite DC gain; anti-windup is the fuse. An integrator accumulates error indefinitely. When the actuator saturates, the plant output no longer responds to u, but the integrator keeps charging; when saturation releases, the stored charge overdrives the output. Back-calculation leaks charge proportional to (u − u_raw), so the integrator never charges past the actuator's saturation point. Predicts: any system with integral action and a saturating actuator exhibits windup if anti-windup is absent. Bug without it: large overshoot or sustained oscillation following any period of saturation. Applied: §8.4 (anti-windup), Phase 4 (§4.2 antiwindup.rs), I2, Principle 2.
  • MM3 — Discretization maps the s-plane to the z-plane; forward Euler maps the left half-plane to a disk that is NOT the unit disk. The transformation s = (z−1)/Δt maps the stable LHP to a circle of radius 1/2 centered at (1/2, 0); for any Δt there exist LHP poles whose image lands outside the unit circle, so the discrete system is unstable. Tustin maps the entire LHP exactly onto the open unit disk. Predicts: a marginally stable design (poles near the jω axis) goes unstable when discretized with Euler at non-tiny Δt. Bug without it: a controller designed in continuous time and sampled with Euler goes unstable in firmware even though RK4-at-tiny-Δt simulation looked fine. Applied: §8.3 (discretization table), Phase 2 (§2.2 discretizers), I7, Principle 4.
  • MM4 — Observer design is pole placement on the transpose; duality is not a coincidence, it is the same algebra. State feedback places eigenvalues of A − BK; the observer places eigenvalues of A − LC. Writing Aᵀ − CᵀLᵀ shows the observer problem is exactly the state-feedback problem for the pair (Aᵀ, Cᵀ), so every tool built for pole placement (Ackermann, LQR) works for observer-gain design by transposing. Predicts: an unobservable mode cannot be stabilized by any observer, just as an uncontrollable mode cannot be stabilized by any feedback — rank tests are symmetric. Bug without it: engineers over-design the observer (too fast, noisy) or under-design it (too slow, diverging) because they treat it as a separate ad-hoc problem rather than the dual. Applied: §8.8 (duality), Phase 7 (§7.2 ctrb/obsv), Phase 8 (§8.2 observer.rs dual placement), I6.
  • MM5 — MPC is LQR with a finite horizon, constraints, and re-solving every tick; warm-starting is what makes it real-time. Without warm-starting, each tick solves a cold QP from scratch and the solve time scales with the QP dimension; with warm-starting (shift the previous solution one step, use it as the initial point) the active set barely changes tick-to-tick in steady state and convergence is fast. The terminal cost from DARE makes the finite-horizon cost approximate the infinite-horizon LQR cost, giving nominal stability. Predicts: MPC without warm-start misses deadlines at large horizons; MPC without terminal cost may not stabilize. Bug without it: intermittent deadline misses in steady-state operation. Applied: §8.10 (condensed QP, terminal cost), Phase 10 (§10.2 warm-start, P_f from DARE, ADR-6), I3.
  • MM6 — The Kalman filter is the MMSE estimator under linear-Gaussian assumptions; if the noise is non-Gaussian or the model is wrong, NIS tells you. It minimizes mean-squared error only when the model is exact and process/measurement noise are zero-mean Gaussian with covariances Q, R. When any assumption fails, the normalized innovation squared NIS = νᵀS⁻¹ν departs from its χ² distribution — persistently above its bound means under-confident (Q/R too small), below means over-confident. Predicts: a filter that looks stable in simulation but diverges in the field has a model error or a noise mis-specification. Bug without it: Q/R set by feel, the filter slowly diverges, and there is no principled diagnostic. Applied: §8.9 (Joseph form), Phase 9 (§9.2 tuning.rs NIS, §9.8 outlier gating), I6.
  • MM7 — A rate limit introduces a phase lag the linear stability analysis cannot see; it is a nonlinearity the Bode plot does not model. The rate limit |Δu/Δt| ≤ Δu_max is a nonlinear saturation on the control derivative; it does not appear in the linear gain/phase-margin computation. Yet at high-frequency reference changes it slows the actuator response, adding equivalent phase lag, so the operating-point phase margin can be below the designed margin. Predicts: a design that passes the linear margin gate can still oscillate under fast setpoint changes or disturbances that saturate the rate limiter. Bug without it: engineers set Δu_max tightly for actuator protection and discover instability only during aggressive maneuvers. Applied: §4 (rate-limit target), Phase 4 (§4.6 pitfall), Phase 12 (§12.2 margin analysis), I1.
  • MM8 — In a fixed-step real-time loop, bounded worst-case compute is as important as average-case; the deadline is a hard invariant, not a soft goal. Average tick latency may be 20 µs, but one overrun at 10 kHz makes the derivative term integrate over 2 ticks of error instead of 1, a 2× spike; an unbounded MPC solve holds the actuator at its previous value for an unknown interval, effectively open-loop. The iteration cap is the mechanism that converts a latency-unbounded algorithm into a deadline-safe one at the cost of suboptimality. Predicts: remove the iteration cap and the loop eventually misses a deadline under a hard constraint scenario. Bug without it: the system is stable 99.9 % of the time but fails on the 0.1 % tick where the QP hits a degenerate case. Applied: §4 (deadline-miss target), Phase 2 (§2.2 ctrl-rt deadline), Phase 10 (§10.7 iteration cap), I3, Principle 8.
  • MM9 — Units and reference frames are load-bearing; a 57.3× error (degrees vs radians) in the Stanley gain produces unstable oscillation that looks like a tuning problem. The Stanley law δ = θ_e + atan2(k·e_fa, v) requires θ_e in radians and e_fa in meters; if θ_e is in degrees the heading term is 57.3× too large, the loop oscillates, and the symptom is indistinguishable from an over-tuned gain. Principle 9 exists because this error is silent, produces no type error, and reaches dangerous behavior. Predicts: every interface between subsystems (#285, #287, #171) is a units-conversion hazard. Bug without it: the Mars Climate Orbiter failure pattern — correct math, wrong units, catastrophic result. Applied: §6 (Principle 9), Phase 11 (§11.2 frame documentation, §11.6 pitfalls), §8.11.
  • MM10 — Controllability and observability are preconditions, not properties to check after the fact; designing on a rank-deficient pair produces numerically valid but physically meaningless gains. Ackermann's formula and the ARE both formally return a gain even when (A,B) is uncontrollable or (A,C) is unobservable; for an uncontrollable mode no finite control can move it, so its "gain" is zero or infinite depending on the solver, and the plant will not behave as designed. Predicts: designing LQR for a system with an uncontrollable mode yields a K that cannot stabilize that mode — the closed loop diverges along that eigenvector. Bug without it: silently designed gain matrices applied to plants that diverge in unexpected directions. Applied: §8.5 (controllability/observability), Phase 7 (§7.2 rank checks), Phase 8 (§8.5 ARE pre-checks), I4, Principle 10.

OSQP: OSQP (Stellato et al., 2020) chose a general sparse ADMM formulation that scales to large QPs (thousands of variables) without condensing. This wins when the MPC horizon is long (N·m > 200) and the dense condensed H matrix becomes ill-conditioned or too large to factor. PX4 Autopilot: PX4 adopted a cascaded PID hierarchy (position → velocity → attitude → rate) specifically for multirotor control, where the plant dynamics separate cleanly across timescales. This wins for airframes where the hierarchy assumption holds and the team does not need state-space or MPC. Its uORB pub/sub architecture and NuttX integration are optimized for that ecosystem; this blueprint stays framework-free and control-law-agnostic.

ros2_control: ros2_control chose a plugin-based controller lifecycle (configure / activate / deactivate) that integrates with the ROS 2 executor and hardware interface abstraction. This wins for robot systems that are already in the ROS 2 ecosystem and need to swap controllers at runtime. The cost is the ROS 2 coupling and non-hard-RT execution model. This blueprint's Controller trait is shaped by the same lifecycle concept (R8) but stays framework-free.

acados: acados (from the SYSCOP group) chose to focus on nonlinear MPC with the Real-Time Iteration (RTI) scheme, CasADi-based code generation, and multiple QP backends (qpOASES, OSQP, Hpipm). This wins for research and production deployments needing NMPC on complex nonlinear plants (robotic arms, aerial vehicles with significant nonlinearity). This blueprint explicitly defers NMPC (§1 Deferred Features Register) and targets the linear regime where its simpler, allocator-free design is sufficient and more auditable.

Back-of-Envelope Capacity Model

The numbers an expert computes from §4 (System Constraints) before designing. Each is derived step-by-step; the §4 input is named and the formula shown.

  • C1 — Per-tick PID compute headroom at 1 kHz. Input: §4 "loop rate default sim 1 kHz", "per-tick budget ≤ 50 % of Δt", "PID tick ≤ 5 µs". Δt = 1/1000 Hz = 1 ms = 1000 µs; budget = 0.5 × 1000 = 500 µs; headroom ratio = 500 / 5 = 100× above PID alone. The 495 µs of slack is what an estimator + MPC consume in a complex controller — PID alone barely touches the budget.
  • C2 — Per-tick LQR / state-feedback compute at 1 kHz. Input: §4 "LQR ≤ 10 µs", "n ≤ 32 dense". Take n = 16, m = 4. State-feedback tick = K·x̂ = m×n matvec = 4×16 = 64 FP multiplies ≈ 0.3 µs at 200 MFLOPS (Cortex-M7+FPU); the observer update dominates at ≈ n² = 256 ops ≈ 1.3 µs. Total ≈ 1.6 µs ≪ 10 µs budget.
  • C3 — Full Kalman tick cost vs the 20 µs budget. Input: §4 "Kalman ≤ 20 µs", "n ≤ 32". Dominant term P⁻ = A P Aᵀ + Q is two n×n×n products = 2n³. At n = 8: 2×512 = 1024 ops ÷ 200×10⁶ ≈ 5 µs (within 20 µs). At n = 16: 2×4096 = 8192 ops ≈ 41 µs — exceeds budget, so use the steady-state gain (reduces to a matvec ≈ n² = 256 ops ≈ 1.3 µs).
  • C4 — MPC condensed QP dimension vs horizon. Input: §4 "decision vars N·m ≤ 200", "condensed QP ≤ 200×200". Decision vars D = N·m; at N = 20, m = 2 → D = 40. Condensed H is D×D = 40×40 = 1600 f64 = 12.8 KB (fits L1/L2). At the ceiling D = 200: H = 200×200 = 40 000 f64 = 320 KB — borderline for cache, ADMM iteration still viable.
  • C5 — ADMM QP solve budget per tick at 1 kHz. Input: §4 "QP solve ≤ 200 µs warm-started", "budget ≤ 50 % of Δt". QP fraction = 200/1000 = 20 % of a 1 ms tick. Remaining after QP for the rest of the loop = 500 µs (budget) − 200 µs (QP) − 20 µs (Kalman n=8) − 5 µs (bookkeeping) = 275 µs margin — confirms MPC + estimator co-reside at 1 kHz.
  • C6 — Worst-case MPC iteration count from the deadline. Input: §4 "QP ≤ 200 µs" and C4's D = 40. One ADMM iteration ≈ 2D² = 2×1600 = 3200 ops ≈ 16 µs. Deadline-safe cap = floor(200/16) = 12 iterations. Warm-started steady-state ADMM converges in 3–8 iterations for well-conditioned problems, so the cap is a safe margin (MM8, ADR-6).
  • C7 — Kalman steady-state working memory. Input: §4 "n ≤ 32", "per-controller static footprint documented". Steady-state gain K = P∞ Cᵀ S⁻¹ is n×p; at n = 8, p = 4: 32 f64 = 256 B. P is n×n = 64 f64 = 512 B; Q + R = n² + p² = 64+16 = 80 f64 = 640 B; with x̂ (n = 64 B) the total per instance ≈ 1.5 KB — fits SRAM.
  • C8 — Hot-loop static footprint for PID. Input: §4 "memory ceiling: hot loop allocation = 0 bytes; buffers preallocated". PidController carries integral + deriv-filter state + y_prev + last_u = 4×8 = 32 B; PidConfig ≈ 10 Scalar fields ×8 = 80 B; per instance ≈ 112 B. Ten simultaneous PID loops ≈ 1.1 KB SRAM — negligible against any MCU budget.
  • C9 — LQG combined footprint. Input: §4 per-controller footprint + C7. For n=8, m=2, p=4: Kalman ≈ 1.5 KB (C7) + LQR K (m×n = 16 f64 = 128 B) + StateFeedback last_u (16 B) → combined LQG ≈ 1.7 KB per instance.
  • C10 — MPC footprint at N=20, m=2, n=4. Input: §4 "all working buffers preallocated", "0 bytes hot-loop allocation", C4. H = (N·m)² = 40² = 1600 f64 = 12.8 KB; constraint matrix A_c (box + rate + slack rows ≈ 3·N·m × N·m = 3×40×40 = 4800 f64 = 38.4 KB); warm-start U = N·m = 40 f64 = 320 B. Total ≈ 51 KB, all preallocated static.
  • C11 — Jitter budget for derivative-term accuracy. Input: §4 "p99 wake jitter ≤ 5 % of Δt" and I3. At 1 kHz, 5 % of 1 ms = 50 µs. D = Kd·(y − y_prev)/Δt_actual; a ±50 µs error on 1 ms is a 50/1000 = 5 % Δt error. A derivative filter N=10 attenuates it to ≈ 5 %/10 = 0.5 % — which is why the 5 % jitter target is the right floor, not arbitrary.
  • C12 — Path-tracking lookahead geometry. Input: §4 "loop rate 50–100 Hz vehicle" and §8.11 lookahead law L_d = k_v·v + L_d0. At v = 10 m/s, L_d0 = 2 m, k_v = 0.5 s → L_d = 7 m. For a 0.5 m cross-track: α ≈ atan2(0.5, 7) ≈ 4.1°, Wheelbase = 2.7 m, δ ≈ atan2(2×2.7×sin 4.1°, 7) ≈ atan2(0.385, 7) ≈ 3.1° — small-angle, linear regime, validating the ≤0.1 m steady-state conformance target (§11.4).

Alternative Architectures (Roads Not Taken)

Fundamentally different ways to build the control engine for the same goal. Each: ASCII sketch, the regime where it wins, the real system embodying it, and why this blueprint rejected it.

A1 — Event-Driven Async Controller (Tokio-based). Updates fire on sensor/reference arrival inside a work-stealing async runtime rather than at a fixed clock.

  ┌──────────────────────────────────────────────┐
  │  Tokio runtime (work-stealing executor)       │
  │                                               │
  │  sensor_stream  ─────────────────────────┐   │
  │  (async Stream)                          ▼   │
  │                                   ┌──────────┐│
  │  reference_stream ────────────▶  │controller ││
  │  (async Stream)                   │  task    ││
  │                                   └────┬─────┘│
  │  actuator_sink  ◀────────────────────── u     │
  │  (async Sink)                                 │
  └──────────────────────────────────────────────┘
  No fixed-step: update fires on sensor arrival.
  Scheduling: runtime-determined, not periodic.
  • Wins: high-level supervisory control (fleet management, mission planning) where the "control loop" is event-driven (waypoint reached → plan next segment) and latency requirements are milliseconds-to-seconds, not microseconds; also telemetry aggregation and web-API layers wrapping the controller library.
  • Real system: ROS 2's higher-level Nav2 / BehaviorTree.CPP stack, where behavior nodes fire on topic messages rather than at a fixed clock rate.
  • Rejected because: async executors introduce nondeterministic scheduling latency — a task behind others in the work-stealing queue may not wake for milliseconds, violating I3 (fixed-step deadline), and the D/I terms need a known fixed Δt (variable Δt injects integration error ∝ jitter, MM8, §2.9). ADR-7 documents the rejection; this architecture is used for host-side tooling (ctrlctl), never the hot loop.

A2 — Centralized Sparse MPC (LTI prediction over the full plant network). A single MPC solves all subsystem inputs simultaneously over a coupled sparse QP instead of independent per-loop controllers.

  ┌─────────────────────────────────────────────────────┐
  │ Centralized MPC                                     │
  │                                                     │
  │  x₁, x₂, … xₙ (all subsystem states) ─────────▶  │
  │                                         ┌─────────┐│
  │  Sparse QP:                             │ ADMM or ││
  │  min ΣᵢJᵢ(xᵢ,uᵢ)  s.t. coupling       │ OSQP    ││
  │  constraints Ax=b                       │ (sparse)││
  │                                         └────┬────┘│
  │  u₁, u₂, … uₙ ◀────────────────────────────┘     │
  └─────────────────────────────────────────────────────┘
  All subsystem inputs solved simultaneously.
  QP dimension: N·m_total across all loops.
  • Wins: strongly coupled MIMO plants where decoupled per-subsystem controllers cannot reject cross-coupling disturbances — chemical-plant sections sharing a recycle stream, multi-axis robot arms, power-grid frequency regulation with coupled generator dispatch. Sparse ADMM scales to thousands of variables when the coupling is sparse.
  • Real system: industrial MPC deployments (Honeywell Profit Controller, AspenTech DMCplus) for refinery sections with dozens of manipulated/controlled variables; also DMC/GPC (P4) in the historical literature.
  • Rejected because: this blueprint targets the embedded/library use-case (§1 deployment model) where the plant is one actuator and n ≤ 32. Centralized MPC at system scale grows as O((n_total·N)²), demands a sparse QP solver (OSQP, Hpipm) with mandatory C FFI (against ADR-6), and cannot run in a no_std fixed-step loop without major infrastructure; the Scalability Analysis marks sparse/banded formulation PhaseDeferred for long horizons.

A3 — Indirect Adaptive Control (MRAC / Self-Tuning Regulator). Controller parameters θ(t) are estimated and updated online every tick instead of being designed once from a fixed model.

  ┌─────────────────────────────────────────────────────┐
  │                                                     │
  │  reference r ──▶[Controller(θ(t))]──▶ u ──▶[Plant]─┐
  │       ▲                    ▲                        │ y
  │       │                    │                        │
  │       │             ┌──────┴────────────────────────┘
  │       │             │  Identifier / Adaptation Law
  │       │             │  θ̇ = -γ · e · φ (MIT rule)
  │       └─────────────┘  or RLS parameter estimator
  │
  │  Controller parameters θ(t) updated every tick.
  └─────────────────────────────────────────────────────┘
  • Wins: plants whose parameters drift significantly with time or operating condition — aging aircraft (fuel burn shifts c.g.), processes with catalyst deactivation, or any plant whose model uncertainty is too large for robust fixed-gain control. MRAC and self-tuning regulators adapt the gains in real time as the plant drifts.
  • Real system: self-tuning regulators in industrial process control (Åström & Wittenmark 1989); adaptive flight-control experiments on modern fighters (F/A-18 HARV); some automotive active-suspension controllers.
  • Rejected because: adaptive control is in the §1 Deferred Features Register. MRAC stability is conditional on persistent excitation (PE) of the reference — without PE the parameter estimates drift and the loop destabilizes, and proving stability with PE under saturation, rate limits, and anti-windup needs Lyapunov analysis beyond this scope. Gain scheduling (Phase 6) and relay auto-tuning (Phase 5) cover the practical cases (slow drift, initial tuning) without stability-under-adaptation complexity; MRAC is right only when drift is too fast for manual retuning and too large for robust fixed-gain design.

A4 — Full State Observer Bank (Multiple-Model / IMM). Several Kalman filters run in parallel under different model hypotheses and a mixer blends their estimates by likelihood, instead of one fixed-model filter.

  ┌──────────────────────────────────────────────────────┐
  │  Measurement z[k]                                   │
  │        │                                            │
  │        ├─────────▶ KF₁ (model: nominal)──▶ x̂₁     │
  │        ├─────────▶ KF₂ (model: fault)  ──▶ x̂₂     │
  │        └─────────▶ KF₃ (model: sensor-B)──▶ x̂₃    │
  │                                            │        │
  │             IMM Mixer: μᵢ(k) ─────────────┘        │
  │             x̂ = Σᵢ μᵢ x̂ᵢ                         │
  │                                                     │
  │  Single x̂ fed to controller                        │
  └──────────────────────────────────────────────────────┘
  Run N parallel Kalman filters; mix estimates by likelihood.
  • Wins: systems subject to abrupt mode changes or sensor faults — a vehicle that can lose a wheel-speed sensor (full → degraded measurement model), a robot transitioning between contact and free motion, aerospace vehicles with structural-damage scenarios. IMM gives graceful degradation under model uncertainty by running multiple hypotheses in parallel, weighted by likelihood.
  • Real system: IMM (Interacting Multiple Model) estimators in aerospace target tracking and radar/EO fusion; #285 Sensor Fusion (cross-linked here) is the natural home for this architecture.
  • Rejected because: this blueprint cross-links #285 for multi-model estimation (§1 cross-link table); ctrl-kf is the minimal controller-facing filter, not a fault-tolerant estimator bank. Running N filters multiplies tick cost by N (N×n³) and needs a mode-transition probability matrix designed and tuned — a domain in itself. For the embedded loop this blueprint targets, the single-filter path is the right default; IMM belongs in #285.
