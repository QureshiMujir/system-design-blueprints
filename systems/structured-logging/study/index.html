Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why must redaction execute before routing rather than after, and what pipeline-construction check enforces it? — §8, §20.
  2. Why does the producer's disabled-call path need to be allocation-free while the enabled path only needs to be allocation-bounded, and what class of production bug does violating the disabled-path rule cause under load? — §14, §30.
  3. Trace a record through an hour-long total network outage to every sink: which layer absorbs the pressure, and what is the eventual failure mode if the outage doesn't end? — §18, §21, §25.
  4. Why is at-least-once (not exactly-once) the chosen delivery guarantee, and what responsibility does that push onto downstream consumers? — §7 (I3), §18.
  5. Why does the cardinality cap drop the attribute, not the record, and what would break if it dropped the record instead? — §7 (I9), §23.
  6. Derive, with numbers, why redaction is the pipeline's throughput bottleneck rather than serialization or ingest. — §30, §34.
  7. Why is the choice of a linear-time regex engine simultaneously a security decision and a performance decision? — §9 (ADR-25), §24 (T4).
  8. Why does file-tail ingest need inode tracking instead of simply reopening the same path on every read cycle? — §19.
  9. What invariant would break if a transform stage were permitted to overwrite trace_id, and why is that enforced at pipeline construction rather than left to convention? — §7 (I11), §15.
  10. Why is the WAL fsync policy a per-producer-class tunable instead of one global default? — §18, §25 (FM-2).
  11. Contrast this design's arbitrary-attribute indexing against Loki's label-only indexing — what operational cost does this design accept that Loki avoids, and why is that trade justified here? — §33, §22.
  12. Why must a batch flush be atomic per record (I8) even though batching exists specifically to amortize per-record cost? — §7 (I8), §21.
  13. Why is the aggregator a separately-deployable, separately-versioned service rather than a library the producer also links? — §9 (ADR-07), §2.
  14. What changes between a Kafka ingest source configured at-least-once versus at-most-once, and which invariant does each configuration satisfy or violate? — §19, §7 (I3).
  15. Why does the Query API reject any query lacking a time-range predicate outright, rather than simply answering it slowly? — §22, §34.
  16. Why is DLQ replay deliberately rate-limited relative to live traffic instead of replayed as fast as possible? — §21, §26.
  17. Why does tenant isolation need to be enforced at storage, query, and ingest simultaneously rather than at any single layer? — §9 (ADR-11), §23.
  18. Why does the Luhn checksum step run after the regex match rather than replacing the regex entirely? — §20.
  19. Under what compliance regime does producer-side opt-in redaction become more important than the aggregator default, and why does the default not simply flip in that regime? — §9 (ADR-08), §20.
  20. Why is the suffix-array full-text index deferred rather than shipped as part of Phase 10's core deliverable? — §22, §37.

32. Mental Models & First Principles

  • MM1 — A log record is a schema, not a string. Predicts: any system that treats logs as opaque text eventually builds a fragile regex parser downstream to recover structure it threw away at write time. Bug class without it: silent parsing breakage on every log-format change. Applied in §8, §11.
  • MM2 — The WAL is the source of truth; the network ship is a downstream consumer of it (Kreps, §5). Predicts: durability must be measured at the WAL fsync, never at "we called the network send." Bug class without it: conflating "sent" with "durable," losing records the operator believed were safe. Applied in §18.
  • MM3 — Backpressure must be explicit at every layer or it becomes implicit blocking somewhere. Predicts: a system with no explicit admission policy at each boundary eventually blocks the application thread when any downstream layer slows. Bug class without it: mystery request-latency spikes traced back to an unbounded internal queue. Applied in §14, §18.
  • MM4 — Redaction is a trust-boundary control, not a formatting step. Predicts: redaction's position in the pipeline order is a security decision, not a stylistic one. Bug class without it: a PII leak from a pipeline misconfigured to route before it redacts. Applied in §8, §20.
  • MM5 — Cardinality is the OOM you don't see coming. Predicts: any indexed dimension without a hard cap eventually exhausts query-store memory as real-world entropy (UUIDs, timestamps-as-labels) finds its way into it. Bug class without it: a slow, unexplained memory-growth incident weeks after a seemingly unrelated schema change. Applied in §23, §34.
  • MM6 — A ring buffer's overflow policy is a business decision, not an implementation detail. Predicts: an audit-log workload and a debug-log workload need different overflow semantics (block vs drop) and a single hard-coded policy is wrong for one of them. Bug class without it: a compliance-critical log silently drops under exactly the load spike an audit needs it most. Applied in §18.6, §21.
  • MM7 — Sinks are bulkheads (Nygard, §5). Predicts: shared retry/backoff state across sinks reintroduces the coupling isolation exists to prevent. Bug class without it: one dead sink's backoff timer throttling every healthy sink. Applied in §17, §21.
  • MM8 — A regex is a program; its complexity class is a security property, not an implementation detail (Cox, §5). Predicts: any backtracking regex exposed to attacker-influenced input is a latent CPU-exhaustion vulnerability, regardless of how carefully rules are authored. Bug class without it: a crafted log body or redaction rule causing pipeline-wide CPU exhaustion. Applied in §20, §24 (T4).

Required reading (§5)

Books

  • Kleppmann, Designing Data-Intensive Applications (2017) — ch. 3 (storage engines, LSM/columnar) and ch. 11 (stream processing) — applied in §22 (columnar store design) and §8 (pipeline semantics).
  • Gregg, Systems Performance, 2nd ed. (2020) — ch. 4 (observability tools) and ch. 5 (applications, tail latency) — applied in §30 (Performance Engineering) and Phase 2 (§14, hot-path budget).
  • **Nygard, Release It!, 2nd ed. (2018)** — the Circuit Breaker and Bulkhead patterns chapters — applied in §17 (per-sink isolation, I6) and §25 (Failure Modes & Recovery).
  • Newman, Building Microservices, 2nd ed. (2021) — ch. 10 (observability across services) — applied in §15 (contextual correlation) and §33 (Comparative Architecture Table).
  • Hunt & Thomas-style engineering rigor aside — McKinley, Systems Performance companion: Fowler, Patterns of Enterprise Application Architecture (2002) — the Gateway/Data-Mapper patterns — applied in §17 (sink abstraction) and §11 (Core Schema & Types).
  • Petrov, Database Internals (2019) — Part I (storage engines: LSM-trees, WAL) — applied in §18 (durable buffer WAL design) and §22 (chunk compaction).
  • Cox et al. (eds.), The Site Reliability Engineering Workbook (2018) — ch. 4 (SLOs) — applied in §26 (Operational Readiness).

Papers

  • Kreps, "The Log: What every software engineer should know about real-time data's unifying abstraction" (2013, LinkedIn Engineering) — the log-as-source-of-truth insight — applied in §18 (WAL as the durability spine) and MM2 (§32).
  • Mogul & Ramakrishnan, "Eliminating Receive Livelock in an Interrupt-Driven Kernel" (1997, ACM TOCS) — polling vs interrupt back-pressure — applied in §14 (ring-buffer admission) and §21 (batching/back-pressure tuning).
  • Sigelman et al., "Dapper, a Large-Scale Distributed Systems Tracing Infrastructure" (2010, Google technical report) — trace/span correlation model — applied in §15 (contextual propagation).
  • DeCandia et al., "Dynamo: Amazon's Highly Available Key-Value Store" (2007, SOSP) — quorum and at-least-once delivery reasoning — applied in §18 (I3, at-least-once) and §25.
  • O'Neil et al., "The Log-Structured Merge-Tree (LSM-Tree)" (1996, Acta Informatica) — the append-then-compact storage pattern — applied in §22 (chunk compaction).
  • Vyukov, "Bounded MPMC queue" (2010, 1024cores.net, informal but widely implemented) — the lock-free ring design — applied in §14 (producer ring) and Phase 7 ingest queues (§19).
  • Fielding, "Architectural Styles and the Design of Network-based Software Architectures" (2000, PhD dissertation, UC Irvine) — REST constraints — applied in §22 (Query API HTTP surface).
  • Cox, "Regular Expression Matching Can Be Simple And Fast" (2007, swtch.com technical article) — linear-time regex (Thompson NFA), the ReDoS defense — applied in §20 (redaction regex engine) and T4 (§24).

Reference Implementations

  • Vector (github.com/vectordotdev/vector) — study src/topology/ and src/sinks/ for the pipeline-of-transforms architecture and per-sink independent buffering — applied in §17, §21. Pitfall not to copy: Vector's VRL transform language is a full DSL — this blueprint keeps transforms declarative (§20) to bound the correctness surface.
  • Fluent Bit (github.com/fluent/fluent-bit) — study plugins/in_tail/ for the inode-tracking file-tail algorithm — applied in §19.5. Pitfall not to copy: Fluent Bit's C plugin ABI trades memory safety for footprint; this blueprint keeps the redaction/parse surface in safe Rust (ADR-01).
  • Grafana Loki (github.com/grafana/loki) — study pkg/chunkenc/ for label-only indexing (no full-text index by default) — applied in §22.3 (why full-text is a deferred stretch, not core). Pitfall not to copy: Loki's label-cardinality footguns motivate the hard cap in I9.
  • OpenTelemetry Collector (github.com/open-telemetry/opentelemetry-collector) — study exporter/exporterhelper/ for per-exporter retry/queue isolation — applied in §21 (per-sink retry/DLQ, I6). Pitfall not to copy: the Collector's config-driven pipeline graph is more general than needed here; this blueprint fixes the stage order (§8).
  • Elasticsearch/OpenSearch (github.com/elastic/elasticsearch, opensearch-project/OpenSearch) — study the inverted-index and mapping-explosion (cardinality) failure mode — applied in §22 (index design) and I9 (cardinality cap), the exact production failure this blueprint defends against.

Glossary (§38) · 57 terms · site-wide glossary

Aggregator
The independently-deployed service that ingests, filters, enriches, transforms, redacts, and routes log records.
Attribute
A typed key/value field on a LogRecord.
Backpressure
An explicit admission-control signal propagated when a downstream layer cannot keep pace with an upstream producer.
Baggage
Cross-cutting key/value context propagated alongside trace/span IDs.
Batch
A group of records flushed to a sink together; atomic per record (I8), not as a whole unit.
Body
The free-form message payload of a LogRecord.
Cardinality
The count of distinct values observed for a given attribute.
Cardinality cap
The per-tenant per-attribute hard limit (I9) beyond which new values are dropped.
Checkpoint manifest
The on-disk record of WAL segment state and last-shipped offset (I10).
Chunk
A columnar storage unit scoped to (service, hour, tenant).
Compaction
The process of merging/promoting chunks between storage tiers (hot→warm→cold).
Conformance corpus
A named set of fixtures used to gate correctness for a specific format or stage.
Context
The in-process carrier of trace_id/span_id/baggage/custom fields (§15).
Contextual field
A field auto-injected into a record from the active Context.
Dead-letter queue (DLQ)
The per-sink store for batches that exhausted retry (I12).
Deferred feature
A scoped-out capability tracked in the Deferred Features Register (§37).
ECS
Elastic Common Schema — a field-naming convention for log/event data.
Enrich
The pipeline stage that adds static-config fields to a record.
Exporter
The component implementing LogExporter that ships records to one sink.
Fan-out
Delivery of one record to multiple sinks via routing.
File-tail
An ingest source that follows an existing log file's growth via inode tracking.
Filter
A pipeline stage that drops records matching (or not matching) a predicate.
Fsync policy
The WAL durability dial: fsync_each, fsync_batch, or fsync_none.
Ingest
The aggregator stage that decodes an external wire format into a LogRecord.
Instrumentation scope
The name/version of the logger that produced a record.
Invariant
A system property (I1–I14) that must hold at all times, independent of configuration.
Inverted index
A per-attribute index mapping value → matching record set.
JSON Lines
The line-delimited JSON wire format (one record per line).
Level (Severity)
The record's importance classification (Trace…Fatal, mapped to 1–24).
LogRecord
The canonical typed event structure (§11).
logfmt
The flat key=value wire format.
Luhn validation
The checksum algorithm used to reduce false-positive credit-card redaction.
Observed timestamp
The time a record was received by the ingest stage, distinct from its originating timestamp.
OTLP
OpenTelemetry Protocol — the canonical structured wire format.
Pipeline
The fixed-order sequence of aggregator stages (§8).
Processor
The producer-side component (LogProcessor) managing record lifecycle before export.
Producer
The in-process SDK component that constructs and emits records.
Quarantine
The isolated destination for malformed input records (I14).
Query API
The HTTP surface for searching and aggregating stored records.
Redaction
Replacement of sensitive field/body content with a placeholder or hash.
Resource
Attributes describing the producing service (e.g. service.name).
Retention
The per-tenant policy governing how long chunks remain queryable.
Ring buffer
The lock-free bounded structure between the producer macro and the WAL writer.
Route
The pipeline stage that assigns a redacted record to one or more sink targets.
Sampler
The component deciding whether a record is kept (ratio- or rate-based).
Schema version
The explicit version tag on every persisted/shipped record (I13).
Severity
See Level.
Sink
An output endpoint implementing LogExporter.
Structured logging
Logging where every emitted event is a typed record, not free text.
Syslog
The RFC 5424 legacy ingest/emit protocol.
Tail query
A streaming (WebSocket) query that pushes matching records as they arrive.
Tenant
The multi-tenancy isolation boundary spanning storage, query, and ingest.
Token index
The whitespace/punctuation-tokenized full-text index (word-boundary search).
Trace context
The W3C-standard carrier of trace_id/span_id across process boundaries.
Value
The OTel-shaped typed attribute/body union (Bool/Int/Double/String/Bytes/Array/KvList).
WAL
Write-Ahead Log — the on-disk durability mechanism between the ring buffer and the shipper.
Watermark
The high-water-mark trigger that causes the shipper to drain the buffer aggressively.
