32. Mental Models & First Principles

  1. MM1 — "A MethodCode is a promise, not a fact." Compiled code is provisional, revocable via deopt or code GC, never a permanent fact about the method. Predicts: every call site needs a re-validation path, never a bare cached address. Bug class without it: assuming compiled addresses are permanent leads to dangling calls after code-GC eviction (T10, FM10-adjacent). Resolving: §22 (I12), §20.
  2. MM2 — "Type feedback is a cache with a write-once-per-shape law." IC states only escalate (I6), never retreat. Predicts: monotonic promotion is the only safe direction. Bug class without it: allowing backward transitions causes promotion/demotion thrashing. Resolving: §18, §7 I6.
  3. MM3 — "SSA dominance is just 'define before use,' generalized to a graph." Predicts exactly what a verifier must check (I1) and why block arguments need dominance-frontier placement. Bug class without it: a value used on a path where it was never defined — a crash or worse, a silently wrong read of stale register contents. Resolving: §15, §7 I1.
  4. MM4 — "Deoptimization is the interpreter's insurance policy, and the optimizer pays the premium." Every speculative optimization (type specialization, escape analysis) must leave behind enough state to "pay out" a full, correct interpreter frame on failure. Predicts: a pass that can't explain its own deopt story isn't safe to ship. Bug class without it: unrecoverable speculation — the optimizer commits to an assumption with no fallback. Resolving: §20, §6 P5.
  5. MM5 — "W^X is a physical promise enforced by the MMU, not a convention." Predicts: no amount of type-level Rust safety substitutes for the OS-enforced page-permission guarantee. Bug class without it: trusting a "we never write after freeze" convention instead of a hardware-enforced one — exactly the gap JIT-spray exploits. Resolving: §12, §7 I5, §24 T1/T2.
  6. MM6 — "A safepoint is a rendezvous point the compiler negotiates with the collector." Predicts: every safepoint needs a matching, complete stack map or the rendezvous fails silently. Bug class without it: emitting safepoints without stack maps, or vice versa. Resolving: §22, §7 I3.
  7. MM7 — "Escape analysis answers 'does this pointer leave my postcondition,' not 'is this object small.'" Predicts: the analysis must track flow to returns/stores/calls, not object size. Bug class without it: treating a small-but-escaping object as safe to scalar-replace, a wrong-result bug (FM1). Resolving: §16.4.
  8. MM8 — "Tiering is a bet sized by counters, not by static prediction." Predicts: the Tier Manager's decisions are always retrospective (observed invocation/backedge counts), never a static heuristic guessing at hotness ahead of time. Bug class without it: static "this loop looks hot" heuristics mis-predict real workloads and waste the optimizing tier's compile budget on cold code. Resolving: §23, §6 P9.

Reference Implementations

  • OpenJDK HotSpot — src/hotspot/share/c1/ (client compiler, C1), src/hotspot/share/opto/ (server compiler, C2). Lesson: the AdvancedThresholdPolicy tiering state machine (applied in Phase 0/11, §12, §23). Pitfall: C2's sea-of-nodes IR is powerful but hard to verify deterministically — do not copy the IR shape (ADR-03 rejects it), copy the tiering policy.
  • V8 — src/compiler/ (TurboFan), src/maglev/ (Maglev), src/baseline/ (Sparkplug). Lesson: Sparkplug's template-JIT 1:1 bytecode-handler stitching for near-zero baseline compile latency (applied as the rejected-but-noted alternative at §36 AA4). Pitfall: TurboFan's JS-specific sea-of-nodes graph is far more complex than this project's CFG+SSA IR needs to be.
  • LuaJIT — lj_asm.c (backend), lj_ir.c (trace IR), lj_trace.c (trace recorder), lj_snap.c (snapshot/deopt). Lesson: snapshot-based side-exit deoptimization is extremely compact; applied as the comparison baseline at §33 and the rejected alternative at §36 AA1. Pitfall: trace JITs don't compose well with branchy/polymorphic code — side exits multiply (ADR-02 rejects trace-JIT for this reason).
  • PyPy / RPython — rpython/jit/metainterp/ (meta-tracing), rpython/jit/backend/x86/ (backend). Lesson: a JIT can be generated from an interpreter definition; applied as the rejected alternative at §36 AA2. Pitfall: high warm-up cost and large trace trees are a poor fit for this project's single fixed bytecode format.
  • GraalVM / Graal compiler — org.graalvm.compiler.nodes (sea-of-nodes IR), org.graalvm.compiler.lir (LIR + register allocation), Truffle partial evaluation. Lesson: Graal's DeoptimizeNode + speculation log generalizes Hölzle's guard/deopt design (applied in Phase 8, §20). Pitfall: Graal's IR is a GC-managed Java object graph — a memory- constrained native JIT (this project) cannot afford that representation.
  • Cranelift — cranelift/codegen/src/ir (CLIF IR), cranelift/codegen/src/isa/{x64,aarch64} (backends). Lesson: CLIF's block-argument SSA form (no separate phi instruction) is the model applied in Phase 3 (§15.1, ADR-03). Pitfall: Cranelift's regalloc2 backtracking allocator is more machinery than a two-tier teaching JIT needs — start with linear-scan / Chaitin-Briggs instead (ADR-04).

Glossary (§38) · 51 terms · site-wide glossary

Backedge
a control-flow edge from the end of a loop body back to the loop header; the trigger point for OSR (§19) and one of P3's mandatory safepoint sites.
Baseline JIT (Tier 1)
the 1:1 bytecode-to-machine compiler with linear-scan register allocation (§14).
BCE
bounds-check elimination; a Phase-4 pass removing provably-safe array bounds checks via induction-variable range analysis (§16.2).
Block argument
an SSA merge value carried as a basic block's parameter, replacing a separate phi instruction (§8.2, ADR-03).
Branch island
a long-range trampoline inserted into AArch64 code to reach a target beyond the ±128 MB direct-branch range (§21.2, I8).
CFG
control-flow graph; the basic-block structure underlying the SSA IR (§8.2).
Code GC
the reclamation pass that evicts cold compiled methods from the code heap under memory pressure (§22.2, ADR-24).
Code heap
the W^X-protected memory region holding all compiled machine code (§3, §12).
Coalescing
merging two non-interfering register-allocation intervals to eliminate a mov; must respect register class (I9, §17.2).
Constant blinding
XOR-obfuscating embedded constants with a per-process secret to resist JIT-spraying (P7, ADR-07).
Deoptimization (deopt)
the process of abandoning compiled execution and resuming in the interpreter with a reconstructed frame (§20, I4).
Dominance frontier
the set of blocks where a definition's dominance ends and a block argument must be inserted (Cytron et al. 1991, §5, §15.2).
Escape analysis
determining whether an allocation's result can leave the current compilation unit, enabling scalar replacement if not (§16.2, §16.4).
Frame reconstruction
rebuilding an interpreter-compatible stack frame from a DeoptBailout descriptor during a deopt bailout (§20.2).
GVN
global value numbering; a Phase-4 pass deduplicating redundant pure computations (§16.2).
Guard
a runtime check (e.g. checkshape) whose failure triggers a deopt (§8.2, §20.1).
Hidden class / Shape
a compact identifier for an object's layout, used for IC dispatch and type specialization (§11.2, §18).
IC (inline cache)
a call/property-access site that caches dispatch information to avoid repeated dynamic lookup (P4, §18).
IC site
the per-call-site record of an IC's state and observed shapes (§11.7).
Inlining
replacing a call with the callee's body at the call site, subject to a size budget and a speculative-guard cap (§16.2, ADR-14).
Interference graph
the graph whose nodes are live ranges and whose edges mark overlapping ranges, used by graph-coloring register allocation (§17.2).
jit-dump
the Linux perf file format for exposing JIT-compiled code layout to the perf profiler (§5 RFCs/Specs, ADR-21).
LICM
loop-invariant code motion; hoisting loop-invariant computations out of a loop body (§16.2).
Linear-scan register allocation
an allocator that assigns physical registers by walking sorted live intervals in one pass (Poletto & Sarkar 1999, §5, §14.3).
Live range
the span of program points over which a value is live, the unit both register allocators operate on (§14.3, §17.2).
Megamorphic
an IC state past polymorphic capacity, falling back to full dynamic dispatch (I6, §18.3).
Meta-tracing
generating a JIT automatically from an interpreter definition rather than hand-writing tiers (§36 AA2, PyPy).
Method-JIT
a JIT architecture that compiles whole methods, as opposed to traces (ADR-02, this project's chosen family).
Monomorphic
an IC state observing exactly one shape (I6, §18.2).
NaN-boxing
encoding multiple value types (int, float, object reference) into the bit pattern of a 64-bit float's NaN space (§11.2).
Optimizing JIT (Tier 2)
the SSA-IR-based tier performing inlining, escape analysis, type specialization, and graph-coloring register allocation (§15–§17).
OSR (on-stack replacement)
transitioning a currently-executing interpreted method into compiled code mid-execution, at a loop backedge (§19, I13).
PIC
polymorphic inline cache; see IC (Hölzle, Chambers, Ungar 1991, §5).
Peephole
a small local rewrite pass applied to emitted machine code before sealing (§13.2).
Phi node
the classical SSA merge-value representation; this project uses block arguments instead (ADR-03).
Polymorphic
an IC state observing up to 4 distinct shapes (ADR-15, §18.3).
Profile feedback
runtime-observed counters (invocation, backedge, IC shape) driving tier-up and type-specialization decisions (P9, I11).
Reference implementation
a real, existing JIT studied for lessons/pitfalls (§5).
Relocation (reloc)
a deferred address fixup applied to emitted code before sealing (§8.3, §11.6).
Safepoint
a program point where a thread's stack is guaranteed walkable and GC-safe (P3, I3, §22).
Scalar replacement
replacing a non-escaping allocation's fields with plain SSA values, eliminating the allocation (§16.2, §16.4).
Sea-of-nodes
an IR representation merging control and data into one graph with late scheduling (Click 1995, §5, §36 AA3).
Shape
see Hidden class.
Speculative inlining
inlining behind a guard that may later fail and deopt (P12, ADR-14).
Stack map
the per-safepoint table of which slots/registers hold live GC references (§8.4, §11.3, I3).
Tier
one of Interpreter (0), Baseline (1), Optimising (2) (§11.1).
Tier Manager
the component owning all promotion/demotion decisions (jitc-tier-manager, P2, §23).
Trace JIT
a JIT architecture that compiles observed hot execution traces rather than whole methods (§36 AA1, LuaJIT).
Type feedback
observed runtime shape/type information driving type specialization (Hölzle & Ungar 1994, §5, §16.2).
Type specialization
replacing a dynamic-dispatch operation with a guarded direct operation based on type feedback (§16.2).
W^X (Write XOR Execute)
the invariant that no memory page is simultaneously writable and executable (P6, I5).
