Decisions (§9) · 24 ADRs

ADR-01

Emitter implementation

Chosen

Hand-rolled x86_64/AArch64 encoders

Rejected

Cranelift, LLVM MC

When the rejected choice is right

A production JIT team with >2 engineer-years to spend and multi-arch parity as the top priority should adopt Cranelift directly

Why: Educational ownership of encoding; smaller binary; no external IR-compiler dependency

ADR-02

JIT architecture family

Chosen

Method-at-a-time JIT (HotSpot-style)

Rejected

Trace-based JIT (LuaJIT/TraceMonkey-style)

When the rejected choice is right

A JIT targeting overwhelmingly loop-dominated numeric kernels with few polymorphic call sites (e.g. an embedded numeric DSL) should choose trace-based

Why: Generalizes to the host VM's branchy/polymorphic workloads; trace JIT fits tight numeric loops only

ADR-03

Middle-IR shape

Chosen

Explicit CFG + block-argument SSA

Rejected

Sea-of-nodes (Click 1995)

When the rejected choice is right

A team whose top metric is peak optimized-code quality with a mature, multi-year IR investment (HotSpot C2 / V8 TurboFan scale) benefits from sea-of-nodes' finer scheduling freedom

Why: Easier to verify deterministically (I1/I2) and to visualize for debugging

ADR-04

Register allocation strategy

Chosen

Linear-scan (Tier 1) + iterated-coalescing graph coloring (Tier 2)

Rejected

Unified backtracking SSA allocator (regalloc2-style)

When the rejected choice is right

A single-tier compiler, or a team wanting one allocator codebase (Cranelift's own design), benefits from one unified backtracking allocator

Why: Two simpler, independently verifiable allocators match the two tiers' different compile-time budgets

ADR-05

Backend sequencing

Chosen

x86_64 first (Phase 1), AArch64 second (Phase 9)

Rejected

Parallel from day one

When the rejected choice is right

A team whose primary deployment target is mobile/ARM servers from day one should parallelize both backends immediately

Why: Reduces Phase-0 risk; x86_64 has the larger reference corpus (nasm golden vectors)

ADR-06

W^X strategy

Chosen

Double-mapped RW/RX pages

Rejected

Per-emit mprotect toggling

When the rejected choice is right

A memory-constrained embedded target unable to reserve 2x virtual address space per code region must accept the mprotect-toggle cost

Why: Toggling costs 2 syscalls per emitted method and creates a transient W+X window

ADR-07

Constant-embedding hardening

Chosen

Constant blinding by default (XOR with per-process secret)

Rejected

No blinding (trust ASLR alone)

When the rejected choice is right

A fully sandboxed, single-tenant, non-networked offline batch process can skip blinding for the throughput win

Why: ASLR alone doesn't stop an attacker who can already influence heap-adjacent constants

ADR-08

GC root discovery

Chosen

Explicit per-safepoint stack maps

Rejected

Conservative stack scanning (no stack maps)

When the rejected choice is right

A GC design already committed to conservative scanning (Boehm-GC-style embedding) should skip stack maps entirely

Why: Precise maps avoid pinning/false-retention issues in the collaborating GC (Ranking 34)

ADR-09

OSR mechanism

Chosen

Copy interpreter-frame → compiled-frame, then jump

Rejected

In-place bytecode-frame rewriting

When the rejected choice is right

A stack-space-constrained embedded target with deep recursion budgets (microcontroller class) should attempt in-place rewriting

Why: Simpler to verify (I13) at the cost of a transient extra frame

ADR-10

Deopt mechanism

Chosen

Full interpreter-frame reconstruction

Rejected

Partial/side-exit continuation

When the rejected choice is right

A trace JIT (LuaJIT-style, ADR-02's alternative) where side exits are cheap chained trace stubs benefits from side-exit continuation

Why: Keeps the interpreter as the single source of truth (P1); simplifies the conformance story

ADR-11

License

Chosen

Apache-2.0

Rejected

MIT, GPLv3

When the rejected choice is right

A project unavoidably linking a GPLv3 dependency (e.g. a GPLv3 disassembler) must adopt GPLv3 instead

Why: Matches host VM (Ranking 33) license; patent grant without copyleft

ADR-12

Tracing

Chosen

OpenTelemetry

Rejected

Ad hoc structured logs only

When the rejected choice is right

An embedded target with no OTEL collector and a <2 MB binary-size ceiling should drop OTEL for raw structured logs

Why: Standard span propagation across tier-up/deopt/OSR events aids production debugging (§26)

ADR-13

Metrics

Chosen

Prometheus

Rejected

StatsD

When the rejected choice is right

A push-heavy, short-lived-process deployment (serverless/FaaS, <1s lifetime) favors StatsD/push-gateway

Why: Pull-based scrape matches existing host-VM ops tooling

ADR-14

Speculative-inlining depth

Chosen

Bounded at 3 guards

Rejected

Unbounded depth

When the rejected choice is right

A workload with near-100% guard stability over months of production telemetry can raise the bound with data to back it

Why: Caps deopt-storm risk (§25 FM2)

ADR-15

Polymorphic IC capacity

Chosen

4 shapes

Rejected

2 or 8 shapes

When the rejected choice is right

A workload with high shape diversity but low per-shape call frequency (schema-validation-style code) benefits from capacity 8

Why: Matches HotSpot/V8 empirical default; balances linear-scan cost vs. megamorphic-fallback frequency

ADR-16

Optimizing-tier compile budget

Chosen

100 ms / method

Rejected

No ceiling (compile to completion)

When the rejected choice is right

An ahead-of-time/offline compilation mode (a warm-cache export batch job, §36) can drop the ceiling since latency doesn't gate a live request

Why: Bounds worst-case tier-up latency (§4, I10)

ADR-17

Method-code identity hash

Chosen

xxHash3 (xxh3)

Rejected

SHA-256

When the rejected choice is right

A deployment sharing MethodCode identity across a trust boundary (multi-tenant code sharing) must use a cryptographic hash instead

Why: Identity is a cache-coherency check, not a security boundary; xxh3 is ~10x faster

ADR-18

CFI hardening

Chosen

BTI (AArch64) / CET (x86_64) landing pads when supported

Rejected

Skip hardware CFI features

When the rejected choice is right

Targeting CPUs predating BTI/CET (pre-2019 x86_64, pre-Armv8.5 AArch64) must skip and accept the documented gap

Why: Near-zero-cost control-flow-integrity hardening on modern silicon (§24)

ADR-19

Tier-threshold configuration

Chosen

TOML file

Rejected

Environment variables

When the rejected choice is right

A container-only deployment optimizing for strict 12-factor purity may prefer env vars

Why: Structured, versionable, diffable config; matches Repository Layout norms

ADR-20

Implementation language

Chosen

Rust, 2024 edition

Rejected

C++, Zig

When the rejected choice is right

A team needing C++-ABI-first interop with an existing C++ VM host (embedding into an existing C++ engine) should use C++ instead

Why: Memory safety for the metadata layer GC root-scanning depends on; shares crates with Ranking 33

ADR-21

Debugger integration

Chosen

perf jit-dump + GDB JIT interface

Rejected

Custom proprietary debug protocol

When the rejected choice is right

A Windows-first deployment with no Linux perf/gdb ecosystem needs a custom ETW-based provider instead

Why: Reuses existing Linux tooling with zero client-side new code

ADR-22

Conformance harness language

Chosen

Python (pytest) driving the Rust binary

Rejected

Pure-Rust integration tests

When the rejected choice is right

A single-toolchain-mandated org with no budget for a second language runtime should keep conformance in Rust integration tests only

Why: Golden-file diffing and cross-arch matrix orchestration are simpler in a scripting language

ADR-23

Optimizing-compile concurrency

Chosen

Dedicated background compile thread (Phase 11)

Rejected

Compile on the mutator thread (stop-the-world compile)

When the rejected choice is right

A single-core embedded target with no spare thread budget (1-vCPU containers, microcontrollers) must compile on the mutator thread

Why: Keeps the baseline tier serving requests during optimizing-tier compiles, matching HotSpot's C2-thread model

ADR-24

Code-cache eviction policy

Chosen

Generational-by-recency (LRU-ish) code GC

Rejected

Never evict until process exit

When the rejected choice is right

A short-lived batch process with a provably small, bounded distinct-method count can skip code GC entirely

Why: Bounds code-heap growth under long-running processes with a large, slowly rotating method population (§34)

36. Alternative Architectures (Roads Not Taken)

AA1 — Trace-based JIT.

interpreter ── records hot path ──▶ linear trace IR ──▶ compiled trace
      ▲                                                        │
      └──────────────── side exit (guard fail) ◀───────────────┘

Regime: tight numeric loops, few polymorphic call sites. Real system: LuaJIT 2.x (Pall, §5). Rejected (ADR-02): the host VM's workload is branchy/polymorphic; trace JITs multiply side exits under exactly that condition, degrading rather than improving over a method JIT.

AA2 — Meta-tracing.

one interpreter definition ──▶ meta-tracer generates a JIT ──▶ N target languages served

Regime: rapid retargeting of one JIT engine across many interpreters. Real system: PyPy / RPython (Bolz et al. 2009, §5). Rejected: this project targets exactly one fixed bytecode format, so meta-tracing's cross-language generality buys nothing, while its higher warm-up cost and larger trace trees are pure downside here.

AA3 — Sea-of-nodes optimizing IR.

   ┌─ control edges ─┐     ┌─ data edges ─┐
   │  fully merged into one graph, schedule computed late  │

Regime: maximal peephole/global scheduling freedom at the cost of harder deterministic verification. Real system: HotSpot C2 / V8 TurboFan (Click 1995, §5). Rejected (ADR-03): this blueprint prioritizes deterministic verifiability (I1/I2) and debuggability over the last few percent of schedule freedom a sea-of-nodes graph would buy.

AA4 — Template / copy-and-patch baseline compiler.

bytecode op ──▶ pre-compiled machine-code template ──▶ stitched output (no IR, no regalloc)

Regime: minimize baseline-tier compile latency further, at the cost of code quality. Real system: V8 Sparkplug; also "Copy-and-Patch Compilation" (Xu & Kjolstad, 2021, Proc. ACM Program. Lang., OOPSLA, §5). Rejected here: linear-scan baseline (ADR-04) already meets the ≤10 ms tier-up SLO (§34 CM6), so the added build complexity of a template compiler isn't justified yet — noted as a Deferred Features Register entry (§37) rather than built now.
