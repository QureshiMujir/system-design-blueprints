Nine boxes, three boundaries, one queue. Interpreter (Tier 0): owned entirely by Ranking 33; this project only reads its profile counters and bytecode format, never modifies it (P1). Tier Manager: the sole owner of promotion/demotion decisions (P2); demotion happens on deopt (§20), promotion on counter thresholds (§4); enforces I11 (monotonic counters). Baseline JIT (Tier 1): a 1:1 bytecode-to-asm compiler with linear-scan register allocation (§14); it is also the fallback target when the optimizing tier's compile budget is exceeded (I10). Optimizing JIT (Tier 2): the SSA-IR pipeline (construction §15, optimization §16, register allocation §17); it is where inlining, escape analysis, and type specialization live. Codegen Backend: the only place architecture-specific code exists; both tiers call through the same Emitter trait (P8) so the optimizing pipeline never branches on architecture. Code Heap: the sink of the one-way data path — bytecode is the source of truth, tiers consume it, the code heap holds the compiled result under W^X (P6) and is reclaimable by code GC (P14, I12). Runtime Support: every cross-cutting concern (relocation, stack maps, deopt info, IC state, debugger export) is owned here and exposed to every other layer via trait-bound calls — no layer reaches across another (a design rule enforced by crate-visibility boundaries in §10). The concurrency boundary (introduced at Phase 11, ADR-23) separates the mutator thread(s), which always run Tier 0/1 synchronously, from the background optimizing-compile thread; MethodCode publication across this boundary is a single atomic pointer swap (§23.2). The persistence boundary: nothing in the code heap or runtime support layer survives a process restart — every phase's correctness argument assumes a cold start (compatibility implications discussed in §27). The trust boundary: the host process is trusted; the bytecode it executes is not (adversary A1, §24) — every defensive check in jitc-bytecode (§8) exists because of this boundary, not because the host VM's own verifier is assumed absent.

8. Domain Model

8.1 Bytecode input grammar (EBNF, integer-subset excerpt)

method       ::= header code_length code_byte+
header       ::= method_id arity max_locals max_stack
code_byte    ::= opcode operand?
opcode       ::= "iconst" | "iload" | "istore" | "iadd" | "isub" | "imul"
               | "idiv"   | "if_icmpge" | "goto" | "invokevirtual"
               | "ireturn" ;  (* ~80 opcodes total in the host VM; Phase 0
                                covers ~20 integer-arithmetic opcodes *)
operand      ::= u8 | u16 | i16 ;  (* width is opcode-dependent *)
constant_pool ::= entry_count entry+
entry        ::= int_const | method_ref | shape_ref

8.2 SSA middle-IR grammar (EBNF)

function     ::= "func" method_id "{" block+ "}"
block        ::= block_id "(" param* ")" ":" instr* terminator
param        ::= value_id ":" type
instr        ::= value_id "=" op type operand*
op           ::= "iadd" | "isub" | "imul" | "icmp" | "iload" | "istore"
               | "loadshape" | "checkshape" | "call" | "callinline"
               | "box" | "unbox" | "alloc" | "safepoint" | "deopt"
terminator   ::= "branch" block_id arg*
               | "branch_if" value_id block_id arg* "," block_id arg*
               | "switch" value_id "{" (const ":" block_id arg*)+ "}"
               | "return" value_id?
               | "unreachable"
type         ::= "i32" | "i64" | "f64" | "ref" | "bool"
arg          ::= value_id

Block parameters (Cranelift-style, no separate phi instruction, ADR-03) hold every merge value; Func::verify (§15.3) checks I1 and I2 over this grammar.

8.3 Machine-code buffer layout

RW alias (mmap #1, PROT_READ|WRITE) ── same physical pages ── RX alias (mmap #2, PROT_READ|EXEC)
+----------+------+----------+------+-----+-------------+
| method_0 | pad  | method_1 | pad  | ... | free space  |   (identical layout in both aliases)
+----------+------+----------+------+-----+-------------+
cursor: AtomicUsize, bumped on alloc_method()
relocs: Mutex<Vec<Reloc>>, applied to the RW alias only, before seal()
seal(): flush I-cache (AArch64: dc cvau + dsb ish + ic ivau + dsb ish + isb per line)

8.4 Stack-map record layout

Field Type Meaning
pc u32 Offset into the method's compiled code
gc_refs SmallVec<[Slot; 8]> Stack/spill slots holding live GC references at pc
spills SmallVec<[Slot; 4]> Non-reference spill slots live at pc (for deopt, not GC)
regs RegSet Physical registers holding live GC references at pc

One entry exists per safepoint (I3); frame_size (in the owning StackMap) gives the constant frame size needed to locate slots relative to the frame pointer.

Field Type Meaning

8.6 Worked example: sumTo(n) through all three tiers

Bytecode (Tier 0 input, integer subset):

pc opcode operand effect
0 iconst_0 — push 0 (acc)
1 istore_1 — acc = pop
2 iload_0 — push n
3 if_icmple pc=12 branch if n ≤ 0
4 iload_1 — push acc
5 iload_0 — push n
6 iadd — push acc+n
7 istore_1 — acc = pop
8 iload_0 — push n
9 iconst_1 — push 1
10 isub — push n-1
11 goto pc=2 loop (backedge → safepoint, P3)
12 iload_1 — push acc
13 ireturn — return acc

Tier 2 SSA IR (post-construction, §15.2; bb0 is the entry, bb1 the loop header with a block parameter carrying acc/n, bb2 the exit):

func sumTo {
  bb0():
    safepoint
    branch bb1(0, arg0)
  bb1(acc: i32, n: i32):
    safepoint            ; backedge safepoint, P3
    v0 = icmp le n, 0
    branch_if v0 bb2(acc), bb1_body(acc, n)
  bb1_body(acc: i32, n: i32):
    v1 = iadd acc, n
    v2 = isub n, 1
    branch bb1(v1, v2)
  bb2(result: i32):
    return result
}

Tier 1 (baseline) lowers each bytecode 1:1 through the Emitter; Tier 2 lowers the SSA form above after the §16 pipeline runs (LICM has nothing to hoist here; GVN dedupes nothing; the loop is already minimal) — both tiers ultimately emit the same instruction classes (compare, add, sub, conditional branch) via one Emitter trait (P8), differing only in register assignment strategy (linear-scan vs. graph-coloring, §14.3 vs §17.3).

8.7 State-transition table: tier-up / deopt

Current State Event Guard Next State Action
Tier 0 (Interpreter) invocation counter ≥ threshold I11 monotonic Tier 1 (Baseline) jitc-baseline::compile
Tier 0 backedge counter ≥ hot-loop threshold I11 Tier 1 via OSR jitc-runtime::osr entry (§19)
Tier 1 invocation counter ≥ tier-2 threshold I11, I10 budget available Tier 2 (Optimizing) jitc-optimising::pipeline
Tier 2 guard fails (deopt) I4 reconstruction succeeds Tier 1 (if demote count < 3) jitc-runtime::deopt bailout, §20.3
Tier 2 guard fails (deopt), demote count ≥ 3 — Tier 1, "no-reopt" cooldown Bailout + throttle re-promotion (§25 FM2)
Tier 1 or Tier 2 code GC reclaims MethodCode I12 (no live activation) Tier 0 Next call resolves via Tier Manager, re-tiers from cold counters retained (I11)
any tier Error::MalformedBranchTarget at load — Tier 0 forever Method pinned, never promoted (§8.8)

8.8 Malformed-input example

A crafted method whose goto/if_icmple operand encodes a branch target past code_length (or into the middle of another instruction's operand bytes) is rejected by jitc-bytecode's defensive range check before IR construction — this is deliberate defense-in-depth beyond the host VM's own bytecode verifier (§1 non-goals), because the JIT's trust boundary treats all bytecode as adversarial (§3 trust boundary, §24 A1). Result: Error::MalformedBranchTarget surfaces to the embedding host; the method is pinned at Tier 0 permanently (row 7 of §8.7); bytecode_reject_total increments (§24 T12).

8.9 Failure-path example: guard-failure demotion under shape churn

A call site alternates among 5 distinct shapes at high frequency (exceeding the 4-shape polymorphic capacity, ADR-15) while the optimizing tier has already speculated on the two most common shapes via checkshape guards (§16.2). Each miss deopts (I4), the demote counter (I11) increments, and after 3 consecutive misses at the same site the method demotes to Tier 1 under a cooldown (§8.7 row 5) rather than re-optimizing immediately — preventing the deopt storm described in §25 FM2 from consuming the optimizing-compile thread's budget (§4).

Design principles (§6)

  • P1 — The interpreter is the ground truth. Every tier's output must produce identical observable behavior to the Tier-0 interpreter on the conformance corpus (§28). Tradeoff: every optimizing-tier change re-verifies against the interpreter, slowing iteration. Operational implication: nightly differential runs gate release (§29). Violating it: a silently wrong optimization becomes an unowned, undebuggable production bug.
  • P2 — Tiers are explicit; promotion is automatic. The Tier Manager (jitc-tier-manager) owns promotion; user code never requests a tier. Tradeoff: applications cannot force early Tier-2 compilation, costing some warm-up latency. Operational implication: thresholds are TOML-tunable, not per-call. Violating it: "forced JIT" call sites produce nondeterministic benchmarking artifacts and defeat I11.
  • P3 — Safepoints are everywhere needed and nowhere else. Method entry, loop backedge, allocation, explicit poll (§22.1). Tradeoff: over-placing safepoints costs 1–3% throughput per extra poll (§34 CM8). Violating it: the GC cannot find roots — heap corruption (I3).
  • P4 — Inline caches are the speculation surface. Every dynamic-dispatch call goes through an IC (jitc-ic); three states — monomorphic, polymorphic (≤4 shapes), megamorphic (ADR-15). Tradeoff: the polymorphic table's linear scan costs cycles proportional to shape count. Violating it: the type-feedback loop that Phase 4 depends on (§16.2) breaks.
  • P5 — Deoptimization is correct, not fast. The first deopt at a bailout site is allowed to be slow (§4: ≤500 µs p99, not a throughput target); subsequent deopts at the same site are not specially optimized — the method demotes instead (§20.3). Tradeoff: repeated deopts always pay full reconstruction cost. Violating it: a "fast path" deopt that skips state validation corrupts resumed execution (I4).
  • P6 — W^X is a hard invariant. The code heap exposes RW and RX aliases of the same physical pages (double-mapped, ADR-06); there is no mprotect toggle per emit. Tradeoff: doubles reserved virtual address space (not physical memory). Violating it: a page that is simultaneously writable and executable is a JIT-spray primitive (§24 T1).
  • P7 — Constant blinding is the default for embedded constants. Every constant emitted in code is XOR-blinded with a per-process secret (ADR-07). Tradeoff: one extra register and one DeoptInfo slot per blinded constant. Violating it: an attacker-influenced embedded constant becomes a directly plantable JIT-spray payload.
  • P8 — One emitter per architecture; one optimizer pipeline. The baseline tier writes asm directly through the Emitter trait; the optimizing tier lowers SSA to asm through the same trait — there is no second lowering abstraction. Tradeoff: the Emitter API must serve both "dumb" 1:1 lowering and scheduled lowering. Violating it: two divergent encoders double the conformance surface (§28) and the bug surface.
  • P9 — Profile feedback is monotonic. Counters (invocation, backedge, IC-shape, I11) never decrease; a demoted method's counters are not reset. Tradeoff: a method that briefly regresses during warm-up is not "forgiven" and may re-promote slower than intuition suggests. Violating it: promotion/demotion thrashing (§25 FM2).
  • P10 — The runtime is one binary, tiers configured not compiled. jitc ships all three tiers; operators configure thresholds via TOML (ADR-19). Tradeoff: binary size includes both register-allocation backends. Violating it: multiple binaries fragment the conformance matrix (§28) and double the release-engineering surface (§29).
  • P11 — Stack maps are data, not code. The safepoint-to-GC-root mapping is an explicit per-method table (StackMap, §11), never inferred by re-disassembling code. Tradeoff: table storage cost (§34 CM1). Violating it: a root-scan bug becomes a silent use-after-free (§25 FM8).
  • P12 — Speculative inlining is bounded at three guards. ADR-14. Tradeoff: some inlining depth is foregone even when it would help. Violating it: the deopt budget blows and the tier thrashes (§25 FM2).
  • P13 — The bytecode interpreter owns semantics; the JIT owns speed only. The JIT never introduces a new observable side effect (e.g., reordering externally visible I/O). Tradeoff: some valid instruction reorderings are foregone for observational transparency. Violating it: breaks P1 by definition.
  • P14 — Code-heap space is reclaimable, never assumed permanent. Code GC (jitc-codebuf::code_gc) can evict any Tier-1/Tier-2 MethodCode under memory pressure (ADR-24); every call site re-resolves through the Tier Manager. Tradeoff: a reclaimed hot method briefly regresses to the interpreter. Violating it: pinning code forever leads to unbounded code-heap growth (§34 CM2, §31).
