1. Goal & Scope

Goal. Build a userspace TCP/IP network stack in Rust, driven by a TUN/TAP device on Linux and macOS, that implements Ethernet framing, ARP, IPv4 (with fragmentation/ reassembly), optional IPv6 (with neighbor discovery/SLAAC), ICMPv4/ICMPv6, the full RFC 9293 TCP state machine (handshake, data transfer, retransmission, congestion control, teardown, TIME-WAIT), UDP, a BSD-compatible sockets API, and a differential conformance suite validated against the host kernel as an oracle. The system is precise engineering prose, not a tutorial: every claim below is checkable against a number, a fixture, or a cited RFC section.

Phase-0 deliverable (numbered).

  1. crates/net — TUN/TAP DriverShim (Linux + macOS).
  2. crates/core/ethernet — Ethernet II frame parse + 802.1Q VLAN detection.
  3. crates/core/arp — ARP request/reply (cache lands Phase 1, §13).
  4. crates/core/ipv4 — strict header parse + checksum verification.
  5. crates/core/icmp — ICMPv4 echo request/reply.
  6. crates/core/udp — datagram parse + single-socket dispatch.
  7. crates/sockets — UDP-only socket/bind/recv_from/send_to/close; TCP entry points stubbed.
  8. examples/01_ping.rs — end-to-end ping round-trip through the stack.

System boundaries. Provides: L2–L4 protocol handling, a sockets API, TUN/TAP and AF_PACKET driver shims, a differential conformance harness. Delegates: TLS/cryptographic security (project 48, TLS/SSL Handshake), HTTP/2+HTTP/3/QUIC (project 64), a full recursive DNS resolver (project 65) — this stack ships only a stub resolver. Does NOT provide: kernel-level packet forwarding as a production router, hardware-offload integration beyond a feature-flagged checksum path, or persistence of connection state across a process restart (FM-12).

Non-goals. Production line-rate router forwarding; kernel-module deployment; a certified/safety-rated build; wire-level compatibility with proprietary vendor TCP extensions.

Deployment model. A single unprivileged userspace process (or library linked into one), reading/writing one TUN/TAP device node, running on a developer laptop, a research VM, or (via the no_std core) an embedded target with a custom driver shim.

Target users/operators. Systems engineers studying protocol internals; embedded developers needing a portable stack; the workspace's own Web Server (rank 22) and HTTP projects, which can host atop this stack's sockets API.

What later phases unlock. IPv6 dual-stack reachability (§21); WAN-grade throughput via congestion control tuning (§19); full sockets-API parity for hosting real applications (§22); a conformance corpus reusable by any future stack in this workspace.

Recommended language + rationale. Rust 2021, MSRV 1.78 (ADR-01). Rejected: C (memory-unsafety in parser code is the single largest historical TCP/IP CVE class — Rust's borrow checker removes it structurally); Go (GC pauses are incompatible with the p99 latency target in §4, and its runtime scheduler fights a hand-rolled event loop, P5); Zig (comptime is compelling but the ecosystem lacks a mature no_std sockets/async story as of MSRV 1.78).

Prerequisites. OSI/DoD layering at the "I can name what each layer does" level; bit-level binary parsing (byte order, alignment, checksums); the POSIX sockets API as both user and student of its history; Linux primitives (TUN/TAP, AF_PACKET, ip route, tcpdump); RFC 9293 read cover-to-cover; Rust to the level of unsafe, #![no_std], and a non-blocking I/O runtime; patience — protocol bugs hide for hours (§2).

Estimated timeline. Phase 0: 2 weeks. Full system (Phases 0–10): 16.5 weeks (~4 months) of focused engineering — see Appendix B for the per-phase breakdown.

Deferred features (full detail in the Deferred Features Register, §36): SYN cookies PhaseDeferred("§23"); CUBIC as the default congestion control (ships behind a flag from Phase 7) PhaseDeferred("§19"); full ECN++ negotiation PhaseDeferred("§19"); IPv4 forwarding/router mode PhaseDeferred("§14"); Path MTU Discovery PhaseDeferred("§19"); a DPDK/AF_XDP kernel-bypass fast path PhaseDeferred("§35"); Multipath TCP (RFC 8684) PhaseDeferred("§22"); BBR congestion control PhaseDeferred("§19").

2. Why Build This

  • Wire compatibility is a hard constraint, not a suggestion. Three RFCs from the early 1980s (791, 793, and the ICMP RFCs) defined the global Internet; deviating by one field byte costs hours of debugging because the rest of the world will not bend (P1).
  • The TCP state machine is a state machine, in full. Eleven states, ~30 transitions (§8.3), zero of which may be glossed over — this is the canonical exhaustive-matching exercise for a systems engineer.
  • Every "weird" TCP behavior is scar tissue from a real outage. Karn's algorithm (1987, after RTT-estimation-driven retransmit storms), Nagle (1984, after "small packet problem" congestion), Jacobson's 1988 congestion-avoidance paper (after the October 1986 NSFNET congestion collapse) — understanding why makes correct implementation nearly automatic (MM4, §31).
  • The cost of correctness at the syscall boundary is real and measurable. TUN/TAP is simple but slow; AF_PACKET is faster; DPDK is faster still. Choosing the wrong primitive for the workload is the single most common userspace-networking performance bug (Alternative Architectures, §35).
  • The empirical disposition is mandatory, not optional. A correct-looking implementation can fail differential conformance; a hacky one can be wire-compatible by accident. You measure (P6, P10) — this is the discipline every subsequent project in the portfolio depends on.
  • Cross-links: builds directly beneath the workspace's Web Server (rank 22) and SQL Database (rank 21) projects; is built beneath by the TLS/SSL Handshake (rank 48), HTTP/2 +HTTP/3 (rank 64), and DNS Resolver (rank 65) projects.

What Mastery Looks Like.

  • Can trace any TCP segment through the full RFC 9293 state-transition table (§8.3) and name the exact next state and action for an adversarial input (Phase 4, §16).
  • Can derive an RTO estimate by hand from a sequence of RTT samples using RFC 6298's smoothing constants, and explain why Karn's guard is mandatory (Phase 6, §18).
  • Can explain, with the Mathis-model formula, why a given loss rate and RTT caps achievable throughput — and why that caps this project's own M7 target (Phase 7, §19).
  • Can read a pcap of a real handshake/teardown and identify which of the eleven TCP states each segment observes and causes (Phase 8, §20).
  • Can articulate, for IPv6, why extension-header chains must be bounded and why SLAAC changes the address-assignment trust model versus DHCP (Phase 9, §21).
  • Can defend, with a concrete regime, when a rejected architectural alternative (kernel-bypass, thread-per-connection, in-kernel, hardware offload) would have been the right call instead (§35).

Application. The consumer of the sockets API (§11); trusted, runs in the same process address space, no isolation boundary from the stack itself (P8).

Sockets. Owns the SocketTable (I14) and per-socket RingBuf buffers (I9); the concurrency boundary is the single event loop (P5) — no socket is ever mutated from two threads.

L4 Transport. TCP owns the per-connection Tcb (§11) and drives the state machine (§8.3); UDP is a thin dispatcher. This is the trust boundary where a hostile peer's segments are converted into a bounded, well-typed state transition or a drop (I8, I13).

L3 Network. IPv4/IPv6 own routing (RouteTable, longest-prefix match) and fragmentation/reassembly (I7); ICMP owns error signaling. This is the persistence boundary for the reassembly cache (bounded, time-limited, never disk-backed).

L2 Datalink. Ethernet/ARP own the local-segment trust boundary — MAC-address resolution is trust-on-first-use by design in v1.0 (T5), a documented, not silently ignored, weakness.

L1 Driver shim. The DriverShim trait (§11) abstracts the packet source/sink; TUN/TAP is the default (ADR-05); AF_PACKET and a DPDK/AF_XDP fast path (§35, AA-1) implement the same trait without touching any layer above — this is the queue/channel boundary between the stack and the OS/hardware.

All later sections (Domain Model §8, Repository Layout §10, Core Schema §11, and every phase) stay consistent with this diagram: module names below map 1:1 onto these six boxes.

6. Design Principles

  • P1 — Spec-faithful. Where RFC 9293/791 say "MUST," we MUST; where "SHOULD," we SHOULD by default and document any deviation. Tradeoff: less flexibility to "improve" on the spec. Operational implication: every deviation needs a docs/adr entry. Violation breaks: wire compatibility — the entire reason to build this (§2).
  • P2 — Sum types over flag fields. Rust enums make state-machine code exhaustive (I8, ADR-03). Tradeoff: more verbose match arms than an integer switch. Operational implication: new states/variants force every match site to be revisited (compiler-enforced). Violation breaks: silent unhandled-state bugs, the single largest historical class of TCP implementation defects.
  • P3 — Zero-copy where feasible, single-copy by default. The packet buffer is slab-owned (ADR-10); layers carry a cursor, sharing slices rather than raw pointers. Tradeoff: lifetime bookkeeping complexity. Operational implication: the buffer lifetime must never outlive the event-loop tick that produced it. Violation breaks: use-after-free or excessive copy overhead (MM8).
  • P4 — no_std core. The protocol layer is no_std-friendly (ADR-02); driver/sockets use std. Tradeoff: no heap-allocation conveniences in core. Operational implication: the stack is embeddable on a custom DriverShim. Violation breaks: portability to constrained targets.
  • P5 — One event loop, deterministic by default. A single-threaded loop services TUN/TAP, timers, and socket completions (ADR-09); a worker pool exists only for copy-bound I/O. Tradeoff: one core caps throughput (§30). Operational implication: no lock contention inside the loop by construction. Violation breaks: determinism — the property that makes differential testing (P6) meaningful.
  • P6 — Differential testing. Every conformance fixture also runs against the host kernel as a reference oracle (§22.3-equivalent, §27). Tradeoff: requires network-namespace test infrastructure. Operational implication: CI needs Linux with namespace privileges. Violation breaks: "correct-looking" bugs (spec misreadings) go undetected.
  • P7 — No hidden allocations on the hot path. recv()/send() and the timer wheel allocate at startup only (I9). Tradeoff: upfront memory commitment sized from §4. Operational implication: undersizing the slab converts steady-state into an allocating path. Violation breaks: tail-latency targets (M2, M5).
  • P8 — No global mutable state. The stack is a struct; multiple instances coexist in one process for testing. Tradeoff: every subsystem needs explicit ownership wiring. Operational implication: enables sharded multi-instance scaling (§30). Violation breaks: test isolation and the sharding lever beyond the single-core ceiling.
  • P9 — Explicit timer wheel. A hierarchical wheel (ADR-04) covers retransmit, keepalive, TIME_WAIT, ARP aging, and SYN backoff with one primitive. Tradeoff: coarse tick granularity (MM6). Operational implication: one subsystem to reason about instead of five ad hoc timers. Violation breaks: timer-drift bugs scattered across every phase.
  • P10 — Honest performance numbers. Benchmarks measure what the harness measures (§29); never quoted from a different machine/kernel/driver. Tradeoff: less impressive marketing numbers. Operational implication: every M-target is CI-gated (§29). Violation breaks: trust in every other number in this document.
  • P11 — Fail closed on malformed input. Every parser rejects on the first invariant violation rather than attempting best-effort recovery (§8.7). Tradeoff: slightly less tolerant of buggy peers. Operational implication: ParseError is the only exit from a parse, never a partially-trusted struct. Violation breaks: turns parser bugs into RCE-class or DoS-class bugs (T8).
  • P12 — Defense in depth at trust boundaries. Every field crossing the wire-trust boundary is validated at entry (checksum before dispatch, I13), never downstream. Tradeoff: validation cost paid once, even for fields a given code path won't use. Operational implication: downstream code can assume validated input. Violation breaks: inconsistent validation, exactly the shape of most real-world CVEs (MM7).
  • P13 — One canonical name per concept. Module/type/file names are chosen once and reused verbatim across §10, §11, and every phase. Tradeoff: renaming later is expensive. Operational implication: Appendix A must be kept byte-identical to §10. Violation breaks: the blueprint itself — terminology drift is an automatic defect.
  • P14 — Every technique traces to its source. Karn's algorithm, the timing wheel, Reno's AIMD are named after their origin paper (§5) so a maintainer can verify intent against the source. Tradeoff: more citations to maintain. Operational implication: every phase's N.2 carries an inline anchor (§15.B). Violation breaks: tribal-knowledge rot — the exact failure this blueprint exists to prevent.

TCP segment (section 3.1 of RFC 9293, 20-byte minimum header): Src Port(2) · Dst Port(2) · Sequence Number(4) · Ack Number(4) · Data Offset/Reserved/Flags(2, incl. CWR/ECE/URG/ACK/ PSH/RST/SYN/FIN) · Window(2) · Checksum(2) · Urgent Pointer(2) · Options(0–40: MSS, Window Scale [RFC 7323], SACK-Permitted [RFC 2018], Timestamps [RFC 7323], SACK blocks).

8.2 TCP Options Encoding

Options are Kind(1) · Length(1) · Value(Length-2) triples except NOP(1) and End-of-List(1); the parser enforces a hard 40-byte options budget and a bounded iteration count (T9) — any option claiming a length exceeding the remaining budget is ParseError::UnsupportedOption, never a partial trust.

8.4 Sequence-Number Space

Sequence and ack numbers live in a 32-bit modular space (2^32 ≈ 4.295 GB); at 1 Gbps that space wraps roughly every ~34 s of sustained transfer, so every comparison must be circular (I1, MM2) — never a native integer comparison. ISS is chosen per RFC 6528 (I11); IRS is the peer's ISS, learned from the SYN.

8.5 Sliding Window & Flow Control

SND.UNA ≤ SND.NXT ≤ SND.UNA + SND.WND bounds outstanding data; the receiver's RCV.NXT/RCV.WND is the mirror. Window updates are accepted only when SND.WL1/ SND.WL2 show newer information (section 3.7 of RFC 9293). RFC 7323 window scaling multiplies the advertised 16-bit window by 2^shift (shift ≤ 14, negotiated once at SYN time, never renegotiated). Zero-window: the receiver may advertise 0; the sender then persists with 1-byte probes on exponential backoff (RTO sequence, §4) rather than silently stalling forever (FM-5).

8.6 Worked Example — Handshake + Data + Teardown

Client 10.0.0.2:40000 → Server 10.0.0.1:8000, MSS 1460:

  1. SYN seq=1000 win=64240 — client chooses ISS=1000 (I11).
  2. SYN,ACK seq=5000 ack=1001 win=64240 — server chooses ISS=5000, IRS=1000.
  3. ACK seq=1001 ack=5001 — handshake complete, both sides Established.
  4. PSH,ACK seq=1001 ack=5001 len=512 — client sends 512 B; SND.NXT becomes 1513.
  5. ACK seq=5001 ack=1513 win=64240 — server acks; RCV.NXT becomes 1513.
  6. FIN,ACK seq=1513 ack=5001 — client closes; client → FinWait1.
  7. ACK seq=5001 ack=1514 — server acks FIN; client → FinWait2.
  8. FIN,ACK seq=5001 ack=1514 — server closes; server → LastAck.
  9. ACK seq=1514 ack=5002 — client acks; client → TimeWait (arms 2×MSL=60 s, I10); server → Closed immediately on receipt.

8.7 Malformed-Input Example

A TCP segment arrives with Data Offset = 15 (claims a 60-byte header) but the IPv4 Total Length field indicates only 40 bytes of TCP payload present. Per P11/P12, the parser rejects with ParseError::Truncated before attempting checksum computation over the claimed-but-absent bytes (I13's checksum-before-trust rule applies only to present bytes — a length claim exceeding the buffer is rejected at the bounds check, never fed to the checksum routine). Fixture: conformance/negative/malformed/tcp_data_offset_overrun.yaml.

8.8 Failure-Path Example

A receiver's window-update ACK is lost in the network after the sender observed a zero window. The sender's persist timer (wheel-scheduled, ADR-04) fires at the current RTO (starting at 1 s, doubling per retransmit backoff to the 60 s ceiling, §4) and emits a 1-byte probe (§8.5). If probes go unanswered past an implementation-chosen absolute ceiling (600 s), the socket layer aborts the connection locally — no RST is sent (section 3.8.3 of RFC 9293); the application receives ETIMEDOUT. This is FM-5's canonical trace and the basis for conformance/positive/tcp_data/persist_timeout.yaml.

18. Phase 6 — TCP Retransmission, RTO Estimation & Karn's Algorithm

Duration: 1.5 weeks.

18.1 Objectives

  • Implement RFC 6298 RTO estimation, Karn's algorithm (I4), exponential backoff, fast retransmit, the persist-timer/keepalive wiring, and their shared home in the timer wheel (ADR-04, P9).

18.2 Detailed Implementation Steps

  • tcp::timer: srtt = (1-α)·srtt + α·rtt, rttvar = (1-β)·rttvar + β·|srtt-rtt|, α=1/8, β=1/4 (RFC 6298); anchors Karn & Partridge 1987 (§5) directly.
  • I4 enforced here: RTT samples from retransmitted segments are discarded (Karn's algorithm) — the RETRANSMITTED flag in TcbFlags (§11) gates the sample.
  • Exponential backoff on retransmit: rto = min(2·rto, 60s) (§4 ceiling); recomputed from srtt/rttvar on the next fresh ACK.
  • Fast retransmit on three duplicate ACKs (section 3.2 of RFC 5681) — the triple-dup counter resets on any forward progress (a common off-by-one bug, §18.6).
  • SO_KEEPALIVE wiring: idle timeout 2 h, probe interval 75 s, max unacked probes 9 (§4), sharing the timer wheel (ADR-04) with RTO/persist/TIME_WAIT.

18.3 Deliverable

  • conformance/positive/tcp_retransmit/ bucket Pass.
  • A network-loss simulation (drop 10% of packets at the TUN driver) demonstrates convergent recovery, captured as a benchmark artifact.

18.4 Acceptance Criteria

  • TCP retransmit recovery time after a single loss ≤ 2 RTT (M6).
  • Under the 10%-loss simulation, throughput converges within 10% of the Mathis-model theoretical prediction (feeds M7, fully validated in Phase 7 once cwnd exists).
  • Karn-guard fixture demonstrates zero RTT-sample contamination from a retransmitted segment across 1,000 trials.

  • Karn's algorithm is mandatory; skipping it produces RTT estimates that drift wildly after a single loss event (MM4).

19. Phase 7 — TCP Congestion Control (Reno, SACK, ECN, CUBIC-Flagged)

Duration: 2 weeks.

19.1 Objectives

  • Implement Reno (RFC 5681) as the default CongestionControl (ADR-06, ADR-19), SACK (RFC 2018, ADR-20), basic ECN negotiation (RFC 3168), and a feature-flagged CUBIC (RFC 8312) stub satisfying the pluggable trait.

19.2 Detailed Implementation Steps

  • Slow start: cwnd += MSS per ACK until ssthresh — anchors Jacobson 1988 (§5) directly; enforces I5's cwnd-floor invariant from the first ACK.

  • Application-limited senders must not grow cwnd unboundedly (RFC 7661) — bounded at the application's actual transmit rate, not the theoretical window.

20. Phase 8 — TCP Close, TIME_WAIT & Simultaneous Close

Duration: 1 week.

20.1 Objectives

  • Implement active/passive/simultaneous close, RFC 6191 TIME_WAIT-assassination-safe reuse (I10), and the RST-generation rules of section 3.10.7.5 of RFC 9293.

20.2 Detailed Implementation Steps

  • Active close: close() → FIN → Established → FinWait1 → FinWait2 → TimeWait; after 2×MSL (60 s, §4), the Tcb is freed by the timer wheel (I10, ADR-04).

  • RST generation: segments to non-existent sockets, out-of-window data on closed connections, half-open detection — per section 3.10.7.5 of RFC 9293, gated by RFC 5961's window check (T4) to avoid becoming an RST-injection oracle.

  • TIME_WAIT eviction occurs at exactly 2×MSL within ±1% (M10).
  • A TIME_WAIT-reuse fixture demonstrates safe 5-tuple reuse per RFC 6191's sequence check, rejecting a non-conforming reuse attempt (T12).
  • Simultaneous-close fixture reaches Closed on both sides within 3×RTT of the last FIN.

20.6 Pitfalls

  • Re-using a 5-tuple before TIME_WAIT expires without the RFC 6191 sequence check is the classic source of spurious "connection reset by peer" errors (FM-4).
  • RST generation that ignores RFC 5961's window check turns the stack into an off-path-attacker oracle (T4) — every RST path must consult the window check.

20.7 Performance Concerns

  • TIME_WAIT table size grows with connection churn (§33 capacity #10: at M3's 50,000 accepts/s, ~572 MiB at steady state) — a material fraction of the 16 GiB budget (§4), motivating RFC 6191 reuse as an operational necessity, not just a correctness nicety.

20.8 Edge Cases

  • A FIN retransmitted after the connection has already reached Closed locally — no TCB exists to process it; RFC 9293's RST-to-unknown-connection rule applies.
  • Simultaneous close racing with a fast-retransmit event on the same segment — the state machine (§8.3) processes FIN and data-ACK independently, never conflating them.

20.9 Failure Analysis

  • FM-4 (TIME_WAIT bloat): detection via time-wait-table-size metric; auto recovery via RFC 6191 reuse; manual recovery tunes the 2×MSL constant down for controlled lab environments (never in an Internet-facing deployment, P1).
  • FM-12 (stale TCB after crash): no persistence across restart by design; a peer's next segment to an unknown TCB receives an RST, not a hang.

20.10 Operational Notes

  • Metric tcp_time_wait_table_size (gauge) and tcp_time_wait_teardown_seconds (histogram, ties to I10).
  • docs/runbooks/time-wait-bloat.md documents the manual 2×MSL tuning procedure and its Internet-facing caveat.

26. Compatibility & Versioning

Wire compatibility. Fixed by the RFCs themselves (§5); this project never introduces a wire-format deviation without an ADR and a conformance-suite update (P1).

Storage compatibility. Not applicable — no persistent storage (§4); the conformance corpus itself is versioned via conformance/spec.md's own SemVer-independent revision log.

API stability. The sockets crate's public functions (§11 Normative Interfaces) are stable across the v1.x line (ADR-15, SemVer 2.0.0); a breaking change requires a v2.0 bump and a migration note in CHANGELOG.md.

Schema evolution. TCP option negotiation (SACK-Permitted, Window Scale, Timestamps) is the closest analogue to schema evolution here — negotiated once at SYN time, never renegotiated mid-connection (§8.2), matching RFC 9293.

Migration. N/A for wire/storage; API migrations (sockets crate) follow standard Rust SemVer deprecation: a function marked #[deprecated] for one minor version before removal in the next major.

Deprecation policy. Minimum one minor-version deprecation window; documented in CHANGELOG.md with the replacement API named explicitly.

Rolling-upgrade guarantees. None at the wire level beyond RFC compliance itself (any RFC-9293-compliant peer interoperates regardless of this stack's internal version); at the process level, see §25's blue-green draining pattern.

30. Scalability Analysis

Constant vs. grows. Per-packet parse cost is O(1) in payload size (fixed header widths, §8.1). What grows with connection count N: SocketTable lookup (O(1) amortized hash, I14), TIME_WAIT table size (linear in churn × 2×MSL, §33 #10), ARP/ND cache (O(1) per entry, bounded by LAN segment size, §33 #5), RouteTable lookup (O(log N) trie depth, §33 #6, essentially constant at end-host scale).

Named bottlenecks, in order. (1) Single event-loop core saturation (P5) — the first ceiling hit at high pps (§33 #8). (2) Slab allocator fixed sizing (ADR-10) — a hard memory ceiling, not a soft degradation. (3) Timer-wheel tick granularity (ADR-04, MM6) — bounds timer precision, not throughput, but caps how tightly RTO/backoff can track real RTT. (4) TIME_WAIT table growth under extreme churn (§33 #10) — a memory bottleneck before a CPU one.

Horizontal scaling. Not available within one process (P8's single-instance design); achieved instead by running multiple stack instances, each owning a disjoint TUN device or sharded by SO_REUSEPORT-style 5-tuple hashing, behind an external load balancer — independent instances share no state (P8 makes this safe by construction).

Vertical scaling. More cores help only the worker pool (copy-bound I/O); the event loop itself stays single-threaded (P5, ADR-09) — this is a deliberate ceiling, not an oversight (AA-2, §35, is the rejected multi-threaded alternative).

Coordination overhead. Zero between independent sharded instances (no shared state, P8); zero within one instance (single writer to every data structure, P5).

Practical ceiling & levers beyond it. The practical ceiling is approximately the M1/ M8/M11 targets on one core. Levers beyond it: (a) kernel-bypass polling (AA-1, DPDK/ AF_XDP, §35) removes the syscall-per-packet cost that caps single-core pps; (b) multi-instance sharding (above) scales horizontally without touching the core design; (c) hardware offload (AA-4, §35) trades auditability for raw throughput — rejected here but the documented escape hatch for an extreme-throughput deployment.

31. Mental Models & First Principles

  • MM1 — A TCP connection is a state machine with an adversarial input alphabet. Predicts every transition must be defined for every possible segment, not just the happy path. Bug class without it: unhandled-state hangs/crashes against malformed peers. Applies in §8.3 and Phase 4 (§16).
  • MM2 — Sequence numbers are a clock, not a counter. Predicts wraparound at 2^32 must be handled via modular comparison, never native ordering. Bug class without it: silent data corruption after ~34 s of sustained 1 Gbps transfer. Applies in §8.4 and I1.
  • MM3 — The window is a promise about buffer space, not a request. Predicts persist- timer/probe logic must exist because a promise can go to zero. Bug class without it: permanent sender deadlock on a lost window update. Applies in §8.5, §17, and FM-5.
  • MM4 — RTT estimation is a control-system problem, not a measurement problem. Predicts naive averaging fails; smoothing constants trade responsiveness for stability. Bug class without it: RTO oscillation or spurious-retransmit storms. Applies in §18 and Design Principle P14.
  • MM5 — Congestion control is a distributed control loop with no coordination channel. Predicts oscillatory equilibrium (the cwnd sawtooth) is normal, not a bug. Bug class without it: "fixing" the sawtooth by removing multiplicative decrease breaks fairness across flows. Applies in §19 and §32.
  • MM6 — A timer wheel trades precision for O(1) amortized cost. Predicts coarse tick granularity is an intentional tradeoff. Bug class without it: assuming a timer fires at the exact requested instant. Applies in I10 and ADR-04.
  • MM7 — The network is hostile until parsed and validated. Predicts every wire field is attacker-controlled until checksum+bounds are verified. Bug class without it: trusting a length field before bounds-checking it (buffer over-read). Applies in §8.7 and T8.
  • MM8 — Zero-copy has a cost horizon. Predicts that below a payload-size threshold, copying is cheaper than zero-copy's bookkeeping (cache effects, reference tracking). Bug class without it: over-engineering zero-copy for small control segments (bare ACKs) that dominate packet count. Applies in P3 and §29.

33. Back-of-Envelope Capacity Model

  1. Default per-connection memory footprint = rx_buf(64 KiB) + tx_buf(64 KiB) + TCB/retransmit-queue/timer overhead(~16 KiB) = 144 KiB. Chains into #2.
  2. Max concurrent connections at 16 GiB (§4) = 16×1024×1024 KiB / 144 KiB ≈ 116,508; applying ~15% allocator-fragmentation headroom yields the M11 target of ≥ 100,000.
  3. Loopback bandwidth-delay product at 1 Gbps (§4 M1), RTT ≈ 200 µs (§4) = 1e9 bit/s × 200e-6 s / 8 = 25,000 bytes ≈ 24.4 KiB — below the default 64 KiB window, so no window scaling is required to saturate loopback.
  4. WAN bandwidth-delay product at 1 Gbps, 100 ms RTT (§4 congestion test profile) = 1e9 × 0.1 / 8 = 12,500,000 bytes ≈ 11.9 MiB — far above the 64 KiB default window, which is exactly why RFC 7323 window scaling (up to shift 14, §8.5) is mandatory for WAN throughput, not a nice-to-have (PMTUD deferral, §36, notwithstanding).
  5. ARP cache size at a /24 subnet: 254 hosts × ~40 bytes/entry (IP+MAC+timestamp+ intrusive pointers) ≈ 10.2 KiB — trivially small versus the 16 GiB budget, which is why a flat hash map (not a compressed trie) suffices (§13.7).
  6. IPv4 routing table at end-host scale (~1,000 entries, never a full BGP table — §1 non-goals) × ~64 bytes/trie node ≈ 64 KiB — confirms a simple trie, not a hardware TCAM, suffices for an end-host stack.
  7. Timer wheel sizing: covering the RTO range 200 ms–60 s (§4) at 10 ms tick granularity needs 6,000 buckets at the finest hierarchy level (Varghese & Lauck); a 3-level cascade (250 ms/tick × 64 buckets per level) trades ~40 bytes/timer-slot overhead for O(1) amortized insert (ADR-04).
  8. UDP echo pps ceiling: at M8's 1.5 Gbps with 1500-byte frames, 1.5e9/8/1500 ≈ 125,000 pps; at a typical ~150 ns/syscall pair (recvfrom+sendto), that's ≤ 18.75 ms/s consumed in syscalls — headroom exists, but explains why batched syscalls (recvmmsg/sendmmsg, a future extension) become necessary above ~500,000 pps.
  9. Fuzz corpus throughput: at a typical ~50,000 exec/s single-core libFuzzer rate for a parser this size, a 24 h canary (M13) executes ≈ 4.32 billion iterations — the basis for the ≥95% line-coverage target being achievable in the stated window.
  10. TIME_WAIT table size under churn: at C connections/sec × 2×MSL(60 s) = C×60 concurrent TIME_WAIT entries; at M3's 50,000/s sustained, that's 3,000,000 entries × ~200 bytes/entry ≈ 572 MiB — a material fraction of the 16 GiB budget, which is why RFC 6191 reuse (I10) matters operationally, not merely for correctness.

35. Alternative Architectures (Roads Not Taken)

AA-1 — Kernel-bypass polling (DPDK/AF_XDP).

NIC -> poll-mode driver (userspace) -> lock-free ring -> protocol stack
       (no syscalls, no interrupts, busy-polled)

Regime: > 2 Gbps single-core, sub-10 µs latency budgets. Real system: seastar (ScyllaDB's framework) + DPDK, and Linux AF_XDP. Rejected because it adds a privileged setup step (hugepages, driver unbinding) that conflicts with the unprivileged-developer-loop goal (§1); the escape hatch is the DriverShim trait (§11), which AA-1 would implement without touching any layer above (ADR-05).

AA-2 — Thread-per-connection (blocking I/O).

accept() -> spawn OS thread -> blocking read()/write() -> OS scheduler multiplexes

Regime: low connection count (<10,000), simple mental model, easy porting of blocking application code. Real system: classic BSD/Solaris socket servers, early Apache httpd (prefork/worker MPM). Rejected because it does not scale past a few thousand threads (stack memory, context-switch overhead), violating P5's determinism and M11's 100,000-connection target.

AA-3 — Full kernel-module implementation (in-kernel stack).

NIC driver -> kernel netif -> in-kernel protocol stack -> syscall boundary -> userspace socket

Regime: needs zero-copy to the page cache, needs to be the OS's actual default stack. Real system: the Linux kernel's own net/ subtree, FreeBSD's sys/netinet/. Rejected because it requires kernel-privilege deployment and kernel-ABI-stability discipline that conflicts with P4 (no_std userspace embeddability) and the "runs unprivileged on a laptop" operational invariant (§1).

AA-4 — Hardware TCP offload (TOE / smartNIC).

NIC ASIC/FPGA terminates TCP entirely -> host sees a socket-like descriptor ring only

Regime: ultra-low CPU budget at very high throughput (40 Gbps+), latency-critical trading systems. Real system: historic TOE NICs (Chelsio, early 2000s), modern smartNICs (Nvidia BlueField, AWS Nitro). Rejected because it is an opaque, unauditable state machine — violating P1's spec-faithfulness verifiability and P6's differential testing (silicon cannot be fuzzed the way Rust code can) — and vendor lock-in defeats the "read and audit in an afternoon" goal (§1).

37. Glossary

ACK — acknowledgement flag/number confirming received bytes. ARP — Address Resolution Protocol (RFC 826), IP-to-MAC resolution. BDP — bandwidth-delay product, the in-flight-bytes capacity of a path. cwnd — congestion window, the sender's loss-based transmit budget. Delayed ACK — deferring an ACK to piggyback or coalesce, capped at 200 ms. DHCP — Dynamic Host Configuration Protocol (RFC 2131). ECN — Explicit Congestion Notification (RFC 3168), router-signaled congestion without a drop. Fast recovery — RFC 5681's cwnd-halving response paired with fast retransmit. Fast retransmit — retransmitting on the third duplicate ACK, ahead of an RTO. FIN — the flag signaling a graceful half-close. IRS — initial receive sequence number, the peer's ISS. ISS — initial send sequence number, chosen per RFC 6528 (I11). Karn's algorithm — discard RTT samples from retransmitted segments (I4). MSL — maximum segment lifetime, 30 s by convention here. MSS — maximum segment size, 1460 B default. MTU — maximum transmission unit, 1500 B default (Ethernet). Nagle's algorithm — coalescing small writes while data is unacknowledged. ND — Neighbor Discovery (RFC 4861), IPv6's ARP analogue. PMTUD — Path MTU Discovery, deferred (§36). RingBuf — the pre-sized, allocation-free per-socket buffer (I9). RST — the flag aborting a connection. RTO — retransmission timeout, estimated per RFC 6298. RTT — round-trip time. RTTVAR — RTT variance, RFC 6298's smoothed deviation estimate. RouteTable — the longest-prefix-match trie for outbound routing. RSA(not used) — (intentionally omitted; not part of this stack's scope). SACK — Selective Acknowledgement (RFC 2018), naming non-contiguous received ranges. SlabRef — an index into the pre-allocated buffer slab (ADR-10). Slow start — cwnd growth by 1 MSS/ACK until ssthresh. SLAAC — Stateless Address Autoconfiguration (IPv6). ssthresh — slow-start threshold, the boundary between slow start and congestion avoidance. SYN — the flag initiating a connection. SYN cookie — a stateless SYN-flood defense, deferred (§36). Tcb — Transmission Control Block, the per-connection state struct (§11). TCP — Transmission Control Protocol (RFC 9293). TIME_WAIT — the state holding a closed connection's 5-tuple for 2×MSL (I10). TOE — TCP Offload Engine, a hardware alternative (AA-4, §35). TUN/TAP — a virtual network device presenting raw IP (TUN) or Ethernet (TAP) frames to userspace. UDP — User Datagram Protocol. VLAN — Virtual LAN, 802.1Q tagging. Window scaling — RFC 7323's multiplicative extension of the 16-bit advertised window. Zero-window probe — a 1-byte segment testing whether a zero-advertised window has reopened (§8.5, FM-5). 5-tuple — (src IP, src port, dst IP, dst port, protocol), the socket-dispatch key (I14). Half-open connection — a connection whose handshake is incomplete, occupying the SYN queue (T2). Backlog — the bound on a listening socket's SYN+accept queues (§16). Accept queue — completed handshakes awaiting accept() (§11, ListenState).
