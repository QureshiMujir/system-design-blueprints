3. Architectural Overview

+------------------------------------------------------------------+
| Application  socket/bind/listen/accept/connect/send/recv/close   |
+---------------------------+----------------------------------------+
                            v
+------------------------------------------------------------------+
| Sockets (BSD-compatible)   socket table | per-socket rx/tx bufs   |
+---------------------------+----------------------------------------+
                            v
+------------------------------------------------------------------+
| L4 Transport                                                      |
|  TCP: state machine, retransmit timer, cwnd, SACK, Nagle,         |
|       delayed ACK, keepalive        | UDP: 5-tuple dispatch       |
+---------------------------+----------------------------------------+
                            v
+------------------------------------------------------------------+
| L3 Network                                                         |
|  IPv4: routing, frag/reassembly | IPv6: ND, SLAAC | ICMP v4/v6     |
+---------------------------+----------------------------------------+
                            v
+------------------------------------------------------------------+
| L2 Datalink   Ethernet: frame parse, VLAN | ARP: cache, resolve    |
+---------------------------+----------------------------------------+
                            v
+------------------------------------------------------------------+
| L1 Driver shim   TUN/TAP (default, ADR-05) | AF_PACKET | raw IP    |
+------------------------------------------------------------------+

Application. The consumer of the sockets API (§11); trusted, runs in the same process address space, no isolation boundary from the stack itself (P8).

Sockets. Owns the SocketTable (I14) and per-socket RingBuf buffers (I9); the concurrency boundary is the single event loop (P5) — no socket is ever mutated from two threads.

L4 Transport. TCP owns the per-connection Tcb (§11) and drives the state machine (§8.3); UDP is a thin dispatcher. This is the trust boundary where a hostile peer's segments are converted into a bounded, well-typed state transition or a drop (I8, I13).

L3 Network. IPv4/IPv6 own routing (RouteTable, longest-prefix match) and fragmentation/reassembly (I7); ICMP owns error signaling. This is the persistence boundary for the reassembly cache (bounded, time-limited, never disk-backed).

L2 Datalink. Ethernet/ARP own the local-segment trust boundary — MAC-address resolution is trust-on-first-use by design in v1.0 (T5), a documented, not silently ignored, weakness.

L1 Driver shim. The DriverShim trait (§11) abstracts the packet source/sink; TUN/TAP is the default (ADR-05); AF_PACKET and a DPDK/AF_XDP fast path (§35, AA-1) implement the same trait without touching any layer above — this is the queue/channel boundary between the stack and the OS/hardware.

All later sections (Domain Model §8, Repository Layout §10, Core Schema §11, and every phase) stay consistent with this diagram: module names below map 1:1 onto these six boxes.

CWR/ECE/URG/ACK/ PSH/RST/SYN/FIN) · Window(2) · Checksum(2) · Urgent Pointer(2) · Options(0–40: MSS, Window Scale [RFC 7323], SACK-Permitted [RFC 2018], Timestamps [RFC 7323], SACK blocks).

8.2 TCP Options Encoding

Options are Kind(1) · Length(1) · Value(Length-2) triples except NOP(1) and End-of-List(1); the parser enforces a hard 40-byte options budget and a bounded iteration count (T9) — any option claiming a length exceeding the remaining budget is ParseError::UnsupportedOption, never a partial trust.

8.4 Sequence-Number Space

Sequence and ack numbers live in a 32-bit modular space (2^32 ≈ 4.295 GB); at 1 Gbps that space wraps roughly every ~34 s of sustained transfer, so every comparison must be circular (I1, MM2) — never a native integer comparison. ISS is chosen per RFC 6528 (I11); IRS is the peer's ISS, learned from the SYN.

8.5 Sliding Window & Flow Control

SND.UNA ≤ SND.NXT ≤ SND.UNA + SND.WND bounds outstanding data; the receiver's RCV.NXT/RCV.WND is the mirror. Window updates are accepted only when SND.WL1/ SND.WL2 show newer information (section 3.7 of RFC 9293). RFC 7323 window scaling multiplies the advertised 16-bit window by 2^shift (shift ≤ 14, negotiated once at SYN time, never renegotiated). Zero-window: the receiver may advertise 0; the sender then persists with 1-byte probes on exponential backoff (RTO sequence, §4) rather than silently stalling forever (FM-5).

8.6 Worked Example — Handshake + Data + Teardown

Client 10.0.0.2:40000 → Server 10.0.0.1:8000, MSS 1460:

  1. SYN seq=1000 win=64240 — client chooses ISS=1000 (I11).
  2. SYN,ACK seq=5000 ack=1001 win=64240 — server chooses ISS=5000, IRS=1000.
  3. ACK seq=1001 ack=5001 — handshake complete, both sides Established.
  4. PSH,ACK seq=1001 ack=5001 len=512 — client sends 512 B; SND.NXT becomes 1513.
  5. ACK seq=5001 ack=1513 win=64240 — server acks; RCV.NXT becomes 1513.
  6. FIN,ACK seq=1513 ack=5001 — client closes; client → FinWait1.
  7. ACK seq=5001 ack=1514 — server acks FIN; client → FinWait2.
  8. FIN,ACK seq=5001 ack=1514 — server closes; server → LastAck.
  9. ACK seq=1514 ack=5002 — client acks; client → TimeWait (arms 2×MSL=60 s, I10); server → Closed immediately on receipt.

8.7 Malformed-Input Example

A TCP segment arrives with Data Offset = 15 (claims a 60-byte header) but the IPv4 Total Length field indicates only 40 bytes of TCP payload present. Per P11/P12, the parser rejects with ParseError::Truncated before attempting checksum computation over the claimed-but-absent bytes (I13's checksum-before-trust rule applies only to present bytes — a length claim exceeding the buffer is rejected at the bounds check, never fed to the checksum routine). Fixture: conformance/negative/malformed/tcp_data_offset_overrun.yaml.

8.8 Failure-Path Example

A receiver's window-update ACK is lost in the network after the sender observed a zero window. The sender's persist timer (wheel-scheduled, ADR-04) fires at the current RTO (starting at 1 s, doubling per retransmit backoff to the 60 s ceiling, §4) and emits a 1-byte probe (§8.5). If probes go unanswered past an implementation-chosen absolute ceiling (600 s), the socket layer aborts the connection locally — no RST is sent (section 3.8.3 of RFC 9293); the application receives ETIMEDOUT. This is FM-5's canonical trace and the basis for conformance/positive/tcp_data/persist_timeout.yaml.
