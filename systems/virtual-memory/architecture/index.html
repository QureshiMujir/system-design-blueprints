VMA Manager — owns the per-process address-space description; every mmap/munmap/mprotect mutates this tree first (§15). Fault Dispatcher — the single entry point from a hardware trap; classifies and routes (§17). Page Tables — the pure translation function plus the mutator that installs/removes mappings, arch-isolated (§14). Buddy Allocator — physical page supply, decoupled from policy (§16, P3). TLB Manager — the per-CPU coherence protocol between page-table writes and cached translations (§19). Replacement Queues — the eviction-candidate selection policy, decoupled from allocation (§20). Swap — the two-tier backing store for evicted anonymous pages (§21). Page Cache — the backing store and dirty-tracking layer for file-backed pages, shared across all MmStructs mapping the same file (§22). Huge Pages / NUMA — cross-cutting placement and promotion policy consulted by the fault dispatcher and allocator (§23). Security Layer — cross-cutting enforcement consulted by the mapper (W^X), the boot sequence (KASLR), and the syscall/interrupt entry trampoline (KPTI) (§24). 8. Domain Model

8.1 Address Translation Model

Translation is the pure function walk: (root: PhysAddr, vaddr: VirtAddr) -> Result<PhysAddr, WalkFault> (P1). A VirtAddr on x86-64 must be in canonical form: bits 63–48 equal bit 47 (sign-extended); a non-canonical address faults before any table is consulted (§8.7). The hardware MMU caches walk's result in the TLB; vm-tlb never re-derives the result, only invalidates it (§8.3).

8.6 Worked Example: fork() + COW Write Fault

  1. Parent process P has one Anonymous VMA [0x1000, 0x2000) mapped PRESENT+WRITABLE, frame F, refcount(F)=1.
  2. fork() clones the VMA rbtree (§18, P2); for each present user PTE, clears WRITABLE in both parent's and child's PTE; refcount(F) → 2.
  3. TLB shootdown (§19) invalidates any cached WRITABLE translation of F on every CPU that had it cached (I3).
  4. Child writes to 0x1000. Hardware raises a Protection { attempted_write: true } fault (§8.4 row 5).
  5. vm-fault checks refcount(F): 2 ⇒ slow path. Allocates frame F', copies F→F', maps F' WRITABLE in the child, decrements refcount(F) → 1 (ADR spans: I5, P10).
  6. Parent's next write to 0x1000 faults identically; refcount(F)=1 at that point ⇒ fast path: re-mark F WRITABLE in place, no copy (I5 satisfied without an allocation).

8.8 Failure-Path Example

Page-cache writeback races a truncate(): writeback thread samples a dirty page's (inode, offset) at t0; truncate() shrinks the file at t1, invalidating that offset's page-cache entry; writeback's write-out at t2 targets a now-invalid region. Detection: the page-cache entry carries a generation counter bumped by truncate; writeback re-checks the generation immediately before issuing I/O and aborts on mismatch (§22, I8's atomic- dirty-sample principle extended to generation-checking). Recovery: the aborted write is dropped (the page is legitimately gone); no corruption because the check-then-act window is closed by the generation compare happening under the same lock that truncate takes to invalidate entries.

Design principles (§6)

  • P1 — Page-table walker is pure. No side effects; deterministic function of (root, vaddr). Tradeoff: forbids caching state inside the walker itself. Operational implication: any two calls with the same inputs are diffable in a crash dump. Violating it: a stateful walker makes stale-TLB bugs indistinguishable from walker bugs.
  • P2 — VMA is immutable until torn down. Mutation creates a new VMA and replaces (rbtree swap), never edits in place. Tradeoff: extra allocation per mprotect/split. Operational implication: a VMA pointer captured under a read lock is safe to read after the lock is dropped. Violating it: reintroduces the exact in-place-mutation race this principle exists to remove.
  • P3 — Allocation decoupled from replacement. The buddy allocator has zero eviction-policy knowledge (ADR-24). Tradeoff: replacement must go through an explicit "free candidate" handoff. Operational implication: allocator and replacement policy are independently benchmarkable and independently swappable. Violating it: couples the fastest-path code (alloc/free) to the most-complex-to-change code (policy).
  • P4 — Per-CPU fast paths before global locks. Magazines (§16), lazy TLB (§19), per-CPU pending sets. Tradeoff: memory overhead of N per-CPU structures. Operational implication: contention metrics are per-CPU, not global. Violating it: a single global lock on the hot allocation path caps throughput at one CPU's worth of work.
  • P5 — TLB shootdowns batched at epoch boundaries. One IPI per epoch, not per modification (§19, ADR-26). Tradeoff: bookkeeping cost of the pending set. Operational implication: bulk munmap cost is O(1) IPIs, not O(pages). Violating it: a 1 GiB munmap costs 5 orders of magnitude more IPIs (§35 item 4).
  • P6 — W^X enforced unconditionally. No PTE has WRITABLE and EXECUTABLE simultaneously (I6). Tradeoff: JIT compilers need a write-then-switch-to-exec dance. Operational implication: closes an entire exploit class structurally. Violating it: reopens the dominant code-injection primitive of the 2000s–2010s.
  • P7 — Determinism in panic/fault paths. Crashes are reproducible from the same trace. Tradeoff: no randomized backoff in the fault path itself (randomization lives only in KASLR's one-time boot choice). Operational implication: a kdump reproduces bit-for-bit under the same input trace. Violating it: "flaky" kernel panics are undebuggable.
  • P8 — The verifier asserts invariants, not comments. Every I# (§7) has an automated detector in vm-verifier. Tradeoff: verifier overhead in debug builds (disabled in release). Operational implication: an invariant violation is a test failure, not a postmortem discovery. Violating it: invariants rot silently as the codebase changes.
  • P9 — Multi-target from day one. x86-64 and aarch64 both first-class from Phase 0. Tradeoff: ~30% more Phase-0 implementation work. Operational implication: no architecture-specific assumption can leak into vm-core because a second arch immediately contradicts it. Violating it: a single-arch-first design bakes in x86-specific assumptions (e.g. INVPCID availability) that break aarch64 porting later.
  • P10 — Reference counting is the sole authority for shared-page lifetime. COW pages, page-cache pages (I5). Tradeoff: every mapping path must remember to increment/decrement. Operational implication: a page's refcount is the single source of truth for "can this be freed." Violating it: double-free or premature-free races (§26 FM classes).
  • P11 — NUMA locality preferred, never mandatory. First-touch + fallback list, no forced interleave by default (ADR-28). Tradeoff: node imbalance under adversarial access patterns. Operational implication: the common case (local access) is fast; the rare case (cross-node) is correct but slower, never wrong. Violating it: forced locality either wastes memory (over-replication) or produces starvation on a busy node.
  • P12 — Every invariant has a telemetry signal, not just an assertion. Each I# emits a counter on violation-adjacent conditions (near-miss), not only on hard failure. Tradeoff: metric cardinality. Operational implication: an on-call engineer sees a trend (rising near-misses) before a hard failure. Violating it: the first signal of a brewing invariant violation is the crash itself.
  • P13 — Fail loud in debug, fail safe in release. Debug builds panic on invariant violation; release builds degrade (SIGSEGV the offending process, or contain to the smallest blast radius) per §26. Tradeoff: behavioral divergence between debug and release requires the conformance suite to run both. Operational implication: production never silently corrupts on a caught violation. Violating it: either debug builds are too slow to run the full fuzz canary, or release builds crash the whole machine for a single process's bug.
  • P14 — Telemetry before optimization. Fragmentation, eviction rate, fault rate, and TLB-shootdown rate are exposed (§27) before any tuning work begins. Tradeoff: instrumentation overhead must itself be budgeted (kept < 1% per M-table §31). Operational implication: every performance claim in this document is falsifiable against a live counter. Violating it: tuning decisions made on guesswork regress silently.
