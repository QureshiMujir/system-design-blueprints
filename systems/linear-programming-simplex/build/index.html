Pitfalls
  • NaN propagation in bounds: lower <= upper is false when either is NaN; add explicit NaN checks before comparing.
  • CSC col_ptr off-by-one: length must be ncols + 1; col_ptr[ncols] == nnz. Missing sentinel → OOB panics in column iteration.
  • Newtype confusion: VarId(u32)/ConstraintId(u32) share underlying type; mixing them in slices silently compiles. No From<u32> conversions in public API.
  • Infinity sentinel comparison: prefer bound.lower.is_infinite() && bound.lower < 0.0 over raw == NEG_INFINITY; document canonical form.
  • Empty matrix cols: a variable with zero nonzeros in A is valid; col_iter must return empty iterator, not panic.

⬜ Phase 2 — Standard-Form Conversion

Objectives
  • Transform any LpProblem into StandardForm suitable for simplex: minimize c·x, A_std x = b, x >= 0.
  • Handle all four cases: Le (add slack), Ge (add surplus + artificial), Eq (add artificial only).
  • Normalize Sense::Maximize by negating the objective.
  • Handle bounded variables via bounded-variable bookkeeping or free-variable splitting.
  • Record var_map so any StandardForm solution maps exactly back to original variable indices.
  • Invariant I10: optimal objective of standard form == optimal of original (up to sign flip).
Deliverable
  • to_standard_form() produces valid StandardForm for all Relation variants.
  • recover() inverts the transformation on any feasible standard-form solution.
  • Unit tests confirm A_std has correct column counts: n_struct + n_slack + n_artificial.
  • Maximize problem: negated objective produces correct minimum; recover() negates back.
  • cargo test -p lp-model passes.

Pitfalls
  • Double-negation on Maximize + negative RHS: negating the objective and independently negating a row that had b < 0 are independent operations; do not apply row-sign flip to the objective.
  • Free variable indexing drift: splitting a free variable increases n_struct; all subsequent column indices in var_map shift; compute var_map after all splits, not incrementally.
  • Artificial vs. surplus confusion: a Ge row needs both surplus (-1) and artificial (+1); omitting the surplus produces an infeasible initial basis for Phase I.
  • Bound-shifted b[i] not updated: shifting variable x' = x - lb substitutes lb into the RHS: b'[i] = b[i] - a_ij * lb for each row j containing variable i; missing this shifts Phase I artificials away from zero.
  • Equality rows and a natural basis: if A already contains an identity column matching an equality constraint (slack inserted for another row), do not insert a second artificial; check for an existing unit column before inserting.

Pitfalls
  • Pivot element magnitude threshold: exact-zero check misses near-zero pivots that corrupt accuracy. Use |p| < PIVOT_TOL (1e-7); most common numerical failure in the tableau.
  • Row elimination includes objective row: common bug is iterating 0..m instead of 0..=m; row m (objective) must also be eliminated.

⬜ Phase 4 — Primal Simplex Phase II

Objectives
  • Implement the Phase II primal simplex loop in lp-simplex, consuming a feasible Basis and StandardForm. Entering variable: most-negative reduced cost (Dantzig rule) via lp-pricing::dantzig_entering; leaving variable: minimum-ratio test on the pivot column (positive entries only). Termination: all reduced costs >= -OPT_TOL (optimality) or no positive pivot-column entry (unboundedness).
  • Maintain I2 (primal feasibility) after every pivot; verify I4 (optimality) and I5 (strong duality c.x == b.y) at termination. Dense-tableau path via lp-tableau (revised path wired in Phase 9 — Phase 4 targets tableau path exclusively); Solution reconstruction extracts x/duals_y/reduced_costs from the final tableau.

⬜ Phase 6 — Anti-Cycling

Objectives
  • Guarantee finite termination (invariant I7) of the primal simplex under all degeneracy patterns. Primary mechanism: Bland's rule in lp-pricing — smallest-column-index entering variable, smallest-basic-variable-index leaving variable. Secondary mechanism: lexicographic / perturbation method as a faster-in-practice alternative implemented in lp-pricing.
  • Auto-switch: after STALL_WINDOW consecutive degenerate pivots, switch from Dantzig to Bland automatically (PivotRule::AutoBland). Cycling is a correctness failure (not a performance issue): it must never occur in a production run. Both mechanisms pluggable via PivotRule enum; selection controlled by SolverOpts::price_rule. Stall detection must have zero overhead on non-degenerate problems.
Deliverable
  • lp-pricing exports bland_entering, bland_leaving, lex_ratio_test, perturb_rhs; PivotRule::Bland and PivotRule::AutoBland functional in Phase II loop. Beale's 1955 cycling LP terminates correctly under Bland and AutoBland; Kuhn's 1956 degeneracy LP terminates correctly under Bland and Lexicographic.
  • Stall detection triggers at most once on standard Netlib test problems; Event::RuleSwitch emitted. Basis-hash dedup in debug mode; panics on any detected cycle in test suite.

Pitfalls
  • Netlib MPS files with RANGES section: incorrect RANGES handling silently shifts the feasible region; affected instances report wrong objective. Debug by comparing parsed bounds to reference solver's model dump.
  • KKT verifier tolerance mismatch: using a stricter tolerance in the verifier than the solver's own tolerances causes false KKT failures on legitimately optimal solutions; always use the same tol_feas/tol_opt that the solver used.
  • Criterion benchmark noise on CI: wall-time measurements vary; use --sample-size 50 and record median; do not gate hard on wall time in CI — gate on iteration count or use #[bench] unit counters instead.
  • cargo publish ordering: crates with intra-workspace dependencies must be published in dependency order (lp-core first, then dependents); --dry-run does not enforce this but actual publish will fail.
  • Clippy false positives on numerical code: clippy::float_cmp, clippy::cast_precision_loss will trigger on intentional float comparisons; allow them at the crate level with a documented #[allow(...)] and a comment explaining the tolerance is handled explicitly (P6).
