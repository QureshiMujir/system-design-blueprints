Decisions (§9) · 22 ADRs

ADR-01

Core language

Chosen

Rust, MSRV 1.75

Rejected

C++, Go, OCaml

When the rejected choice is right

C++ wins when the team already owns a mature libxdiff/JGit-scale C++ codebase and a rewrite isn't justified; Go wins for an internal tool where GC pauses under 10 MB inputs are irrelevant

Why: Memory safety without a GC pause on the streaming path; zero-cost abstractions keep Myers competitive with git's C (§1)

ADR-02

Default diff algorithm

Chosen

Myers O(ND)

Rejected

Patience, Histogram as default

When the rejected choice is right

Patience wins as default for human-reviewed source diffs in a code-review UI; histogram wins as default for log -p-style large-history scans (git's own default since 2.34)

Why: Myers is the universal correctness reference every other algorithm is compared against; --algo exposes the rest

ADR-03

Default tokeniser

Chosen

Line

Rejected

Byte, Word, Char as default

When the rejected choice is right

Byte wins for binary-safe delta tooling (VCDIFF, §17.2); word/char win for inline code-review annotation

Why: Most consumers want line-oriented unified diffs

35. Alternative Architectures (Roads Not Taken)

A1 — Content-defined-chunking / rolling-hash block-copy diff (bsdiff/xdelta3-style) instead of edit-graph search.

Show the original text diagram
old: [ window ][ window ][ window ][ window ]
          │ rolling hash, pick boundary on bit-pattern match
new: [ COPY src@k,len ][ ADD bytes ][ COPY src@k',len' ]

Regime where it wins: near-duplicate large binary blobs (compiled artifacts, media files) where line/token boundaries don't exist. Real system: xdelta3, bsdiff/bspatch, VCDIFF (RFC 3284). Rejected as the primary architecture because byte-exact line-oriented text conformance with git (§4's one defining property) requires edit-graph semantics, not block-copy semantics — kept as the deferred VCDIFF surface (PhaseDeferred §17.2) for the binary-specific case it actually wins at.

A2 — CRDT/Operational-Transformation live-merge instead of offline three-way diff3 merge.

Show the original text diagram
site A: op_a ─┐
              ├─► transform(op_a, op_b) ─► converged state
site B: op_b ─┘        (OT) or CRDT merge function

Regime where it wins: real-time collaborative editing with many concurrent writers (Google-Docs-style). Real system: Automerge/Yjs (CRDTs), the original Google Wave OT engine. Rejected because this project targets asynchronous, VCS-style batch merge (§1 non-goals explicitly excludes live collaborative editing) — CRDT convergence guarantees solve a stronger, differently-shaped problem than diff3's "reconcile two finished edits against a common ancestor," at a complexity cost this toolkit's scope doesn't need.

A3 — Suffix-array/generalized-suffix-tree LCS instead of the Myers edit-graph.

Show the original text diagram
old+new → generalized suffix array → LCP array → longest common substrings
                                            │
                                    repeated-substring-heavy inputs
                                    win here; sparse-change inputs don't

Regime where it wins: repeated-substring-heavy corpora (log deduplication, genomic sequences) where O(n log n) suffix construction beats Myers' O(ND) when D is large relative to n. Real system: bioinformatics diff/alignment tools (e.g. MUMmer-family suffix-array alignment), the Hunt-Szymanski algorithm referenced in Gusfield 1997 (§5). Rejected as the default because typical source-code diffs have D ≪ n (few changed lines), making Myers' output-sensitive O(ND) faster in the overwhelmingly common case (§4's throughput targets are tuned for that regime).

A4 — AST-diff-first architecture (Difftastic-style) instead of text-diff-first.

Show the original text diagram
old.rs ──►[tree-sitter parse]──► AST_old ──┐
                                            ├──► match subtrees by structural hash ──► AstOp*
new.rs ──►[tree-sitter parse]──► AST_new ──┘

Regime where it wins: syntax-rich programming-language diffs where line-based diff misrepresents refactors (a reformatted function reads as "everything changed" line-wise but "nothing changed" structurally). Real system: Difftastic (Wilfred Hughes, §5). Rejected as the primary architecture because it requires a grammar per language (a large, ongoing maintenance surface) and because the byte-exact git-conformance goal (§4, §22) is defined over text, not ASTs — kept as the deferred semantic-diff surface (PhaseDeferred §13.2) for the code-review niche it actually wins at.
