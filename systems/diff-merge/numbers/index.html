33. Back-of-Envelope Capacity Model

  1. Non-streaming memory for a 1 GB pair: §4's "memory per diff ≤ 3×(old_len+new_len)" ⇒ 3×(1 GB+1 GB) = 6 GB resident — this is exactly why streaming mode (ADR-04, §9) is mandatory above 100 MiB, not merely nice-to-have.
  2. Streaming memory, any input size: window_size default 8 MiB (§4) × a double-buffering constant (~3×) ⇒ ≈24 MiB resident, flat, independent of file size (I11, §7) — the entire point of P7 (§6).
  3. Wall-clock for a 100 MB, 10%-changed diff: 100 MB ÷ M2's 100 MB/s (§29) = 1 s compute-bound, comfortably inside M4's 2 s streaming-mode budget (§29), leaving ~1 s of margin for streaming overhead.
  4. Hashing's share of the per-token budget: xxh3_64 at ~10 GB/s (§13.2) against M1's 1 GB/s diff-throughput target (§29) ⇒ hashing consumes ≤ 10% of the per-byte budget, leaving ≥ 90% for the edit-graph search itself — this is why M1 is achievable at all with a per-token hash.
  5. Cost-cap sizing for a 10 MB adversarial pair: assume avg line length 80 bytes ⇒ ~125,000 lines/side; a no-common-token pair gives D ≈ 250,000 (=n+m, the default cap, §4); worst-case Myers cost is O(D²) ≈ 6.25×10¹⁰ operations — at ~10⁹ ops/s this is ~60 s, far past the p99 target (M3, §29). Derivation: capping D at 50,000 instead bounds worst-case cost to O(50,000²) = 2.5×10⁹ ops ≈ 2.5 s, motivating a tuned cap well below the naive n+m default for latency-sensitive callers (§4's default is a correctness ceiling, not a performance-tuned one — callers needing the p99 target on adversarial input should lower it explicitly).
  6. Rename-detection worst-case comparison count: max_pairs=1000 (§4) caps the promoted-pair search, but the candidate enumeration itself is O(deletes×adds) before the cap filters it; for a 10,000-file tree with 5% churn (500 deletes, 500 adds) that's 250,000 Jaccard comparisons, each O(shingle-count) ≈ O(file_size/3) — for average 1000-line files (~998 shingles), ≈2.5×10⁸ shingle-set operations, which is why M9's 5 s budget (§29) requires the O(1)-per-comparison sorted-vector Jaccard (§19.7), not a naive O(shingles²) intersection.
  7. FD budget for a 10,000-file tree diff: §4's "3 + 2/file" formula would need 20,003 FDs for full concurrency — over most default ulimit -n (1024) — so batching at, say, 256 concurrent file pairs requires ⌈10,000/256⌉ ≈ 40 batches, each bounded by the FD budget.
  8. Conformance suite wall-clock budget: ~500 total fixtures across §13–§20's buckets (100+50+100+100+50+200+50+~130) at M11's < 5 min (§29) target ⇒ ≤ 600 ms/fixture average, consistent with M3's 100 ms Myers-diff budget plus git-subprocess invocation overhead per fixture (the dominant cost is spawning git, not this toolkit's own algorithm).
