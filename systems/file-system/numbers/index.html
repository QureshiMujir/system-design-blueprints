32. Back-of-Envelope Capacity Model

All numbers are chained from §4's System Constraints table.

  1. Blocks in a 1 TiB image. blocks = fs_size / block_size = 2^40 / 2^12 = 2^28 = 268,435,456 blocks.
  2. Block groups for that image at the mkfs default blocks_per_group = 32,768 (Phase 3, §15.2): groups = blocks_total / blocks_per_group = 268,435,456 / 32,768 = 8,192 groups.
  3. Group-descriptor table size at ~32 B/descriptor: gdt_bytes = groups × 32 = 8,192 × 32 = 262,144 B ≈ 64 blocks (at 4 KiB).
  4. Inodes at the default inode ratio (1 inode per 16 KiB, ADR-04): inodes_total = fs_size / inode_ratio = 2^40 / 2^14 = 2^26 = 67,108,864.
  5. Inode-table size, Inode = 256 B (§11): inode_table_bytes = inodes_total × 256 = 67,108,864 × 256 = 17,179,869,184 B ≈ 16 GiB.
  6. Buffer-cache slot count at the default 64 MiB cache (§4): slots = cache_bytes / block_size = 64 × 2^20 / 4096 = 16,384 slots.
  7. Max extent-tree depth for the max single-file size (16 TiB, §4): logical blocks = 16 × 2^40 / 4096 = 2^32 = 4,294,967,296; entries per node ≈ (4096 − 8) / 12 ≈ 340; depth = ⌈log₃₄₀(4,294,967,296)⌉ = ⌈ln(4.29×10^9)/ln(340)⌉ = ⌈22.18/5.83⌉ = ⌈3.80⌉ = 4 levels.
  8. File-handle table memory ceiling at the max-concurrency budget (§4, 65,536 FDs) and an OpenFile handle entry of ~64 B: fd_mem = 65,536 × 64 = 4,194,304 B ≈ 4 MiB.
  9. Journal replay theoretical floor vs. measured floor: replay_time_ theoretical = journal_size / seq_read_throughput = 128 MiB / 500 MB/s ≈ 0.26 s, against the M8 Phase-0 floor of 30 s — the ~115× gap is per-record checksum verification (I6) and small-record I/O overhead dominating raw sequential bandwidth, not the bandwidth itself (§18.7).
  10. Metadata write amplification per file create+fsync: 1 journal write for the inode block + 1 for the parent's dirent block + 1 commit record ≈ 3 block writes minimum per create (ordered mode, no separate data block for a zero-length file); at the M4 random-write floor of ~12,500 IOPS (50 MB/s / 4 KiB), the theoretical create-rate ceiling is 12,500 / 3 ≈ 4,167 creates/s before the metadata path itself saturates the device.
  11. Max linear-directory entries before htree conversion, at the ADR-06 threshold of 64 and an average DirEntryHeader + short name of ~24 B: linear_bytes ≈ 64 × 24 = 1,536 B, comfortably within one 4 KiB block — confirming the 64-entry cutoff is chosen to stay within a single block, not an arbitrary round number.
  12. Max filesystem size at the largest mkfs-selectable block size (64 KiB, ADR-03) and the ADR-14 block-count ceiling: max_size = 2^48 × 2^16 = 2^64 B = 16 EiB — the figure quoted in §4.
