ADR-01

Core language

Chosen

Rejected

C++, Go

When the rejected choice is right

C++ when you must embed in an existing C++ engine with no FFI budget

Why: ADTs + traits fit CRDT algebra; ownership kills use-after-free; mature WASM toolchain

ADR-02

Chosen

Rejected

Op-based when the transport already guarantees exactly-once ordered delivery (e.g. a Kafka log)

Roads not taken

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

A. Operation-based CRDTs over a reliable causal-broadcast layer

[client op] → [causal broadcast / exactly-once log] → [apply op at each replica]

Wins when the transport already provides exactly-once, causally-ordered delivery (e.g. a single Kafka partition or a TCP-ordered server fan-out) and op payloads are far smaller than state. Embodied by Yjs (op/struct-based with a reliable provider). Rejected because it pushes exactly-once delivery onto the transport (P2), which our pluggable, churn-tolerant transport (P7) cannot guarantee; state/delta-state merge is idempotent under duplication and reordering, which the wire here is not.

B. Server-authority / operational-transform with a central resolver

[clients] → [authoritative server resolves order] → [broadcast canonical log]

Wins when you need stronger-than-SEC guarantees (a single linear history, server-enforced invariants) and can tolerate a central point — the classic Google-Docs-style OT server. Embodied by Replicache/PowerSync-style server-authority sync. Rejected as the default because it forfeits offline-first peer-to-peer convergence; it is retained only as a deferred "server authority" mode (Register) for workloads where SEC is too weak.

C. Database-embedded CRDTs on a Dynamo-style ring

[client] → [hash ring vnode] → [state-based CRDT stored + replicated by the ring]

Wins when the storage engine already owns replication, hinted hand-off, and read-repair, so CRDTs are "just another column type." Embodied by Riak DT. Rejected because it couples the CRDT algebra to one storage engine's replication, violating the "sync and storage layer on top, never below" property (§3) and the pluggable-transport/persistence principles (P7, P8).

D. Columnar change-log document store

[edits] → [append to columnar change log] → [materialise document on read]

Wins when you must store and ship the full edit history compactly (audit trails, time-travel, cold storage) and can pay a heavier read-time materialisation. Embodied by Automerge's columnar encoding. Rejected as the Phase-0 default to keep the codec simple (ADR-17) and the in-memory model direct; columnar encoding is captured as a deferred feature (Register).
