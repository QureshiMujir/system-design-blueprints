⬜ Phase 0 — Repository Skeleton, Governance, CI §12

Objectives

Stand up the production scaffold: workspace, governance docs, brand/legal packs, CI/CD, conformance harness skeleton, and runnable examples — with zero CRDT algebra. Establish the deferral mechanism (P6, MergeError::PhaseDeferred) so later phases can mark surfaces Deferred legibly. Constraint introduced: every later phase must compile, lint, and test green inside this scaffold — no phase may bypass it.

Deliverable

Workspace, Makefile, Dockerfile, compose, six workflows, governance + brand + legal packs, three runnable examples, four templates, seeded corpora — inspectable end-to-end via make build && make test && make compose-up.

Acceptance

cargo build --workspace, cargo clippy --workspace -- -D warnings, and cargo test --workspace all exit 0; make compose-up starts all 3 replicas listening; conformance runner emits an all-Deferred report (§8.4 corpus format); governance, brand, legal, and example trees populated; BUILD_PLAN.md Status in progress, Phase 0 marked complete.

Fixtures
Fixture Purpose Expected
cargo build --workspace scaffold compiles green
cargo clippy --workspace -- -D warnings lint clean green
cargo test --workspace empty suites pass green
make compose-up three replicas start all three listen
empty conformance corpora deferral mechanism every bucket Deferred
deliberately-broken member (removed from Cargo.toml) regression guard cargo build fails, not silently excluded
Pitfalls
  • Skipping brand/legal packs "because it is a Rust library" — forbidden by the portfolio bar.
  • Committing empty workflow files — CI must run.
  • Marking Phase 0 done before make test returns 0.
  • Pinning resolver = "1" by accident — breaks feature unification across the workspace and silently changes downstream crate behaviour.

⬜ Phase 1 — Causality Primitives §13

Objectives

Implement the causality module: vector clock, version vector, dotted version vector, Lamport timestamp, HLC, and the causal-stability marker. Every later CRDT depends on these (P3). Constraint introduced: causality types must be no_std-friendly (P11) — BTreeMap, not HashMap.

Deliverable

causality::* modules with docs; conformance corpora seeded with real golden vectors; a reusable proptest! concurrency-property harness later phases extend.

Acceptance

All causality conformance buckets (causality.vc/.dvv/.hlc) Pass; both property tests green (concurrency I9, DVV-order-independence); conformance/causality.report.json shows 0 failures; M-causal (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/causality/vc/*.jsonl VC golden vectors from reference Python partial_cmp agrees byte-for-byte
corpora/causality/dvv/*.jsonl DVV compaction result independent of observe order
corpora/causality/hlc/*.jsonl HLC observe-and-tick obeys Kulkarni rule; SkewExceeded fires
proptest concurrency partial_cmp returns None iff concurrent property holds (I9)
proptest dvv order shuffle observe order identical final DVV
malformed golden vector (negative tick) regression guard rejected at parse, never silently clamped
Pitfalls
  • Off-by-one in tick (first tick is Tick(1), I6).
  • Calling .unwrap() on partial_cmp of concurrent clocks (I9, MM2).
  • Keying a clock by anything but a stable ReplicaId (P12).

⬜ Phase 2 — Counter CRDTs (G-Counter, PN-Counter) §14

Objectives

Implement the simplest CRDTs — G-Counter and PN-Counter — and stand up the proptest! merge-law harness (commutativity, associativity, idempotence) that every later phase reuses.

Deliverable

counter/* modules; the reusable proptest! merge-law harness (commutativity/associativity/idempotence generator, parameterised over replica count) every subsequent CRDT phase invokes unchanged.

Acceptance

Both counters implement Crdt (§11.2); CAI (commutative/associative/idempotent) properties green for ≤4 replicas across all delivery orders; bincode round-trip exact (byte-identical); counter.g/counter.pn conformance buckets Pass; M-counter (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/counter/g_counter.jsonl replay ops, assert value + state bytes exact match
corpora/counter/pn_counter.jsonl inc/dec mix value + bytes match
proptest CAI (≤4 replicas, all orders) I1–I3 hold
empty PnCounter edge value()==0
1k-op delta size M6 sanity delta < 5% of state at steady state
Pitfalls
  • Storing decrements in one G-Counter (breaks the join-semilattice — merge is no longer a valid join once subtraction enters the per-key max).
  • Returning i64::MAX for an empty PN-Counter (must be 0 — an unsigned-underflow-adjacent bug).
  • Merging p but forgetting n (asymmetric merge breaks I1/I2 for the composite type).

⬜ Phase 3 — Set CRDTs (G-Set, 2P-Set, OR-Set) §15

Objectives

Implement the three canonical set CRDTs, introducing tombstones (2P-Set) and observed-remove dots (OR-Set) as the first types with delete semantics. Constraint introduced: GC (compaction) is gated on causal stability (I4) from this phase forward.

Deliverable

set/* modules (G-Set, 2P-Set, OR-Set); the OR-Set scenario corpus covering add/remove/re-add orderings.

Acceptance

OR-Set passes the corpus including re-add (add wins per §8.2); 2P-Set permanence holds (a removed element never reappears); concurrent add/remove resolves to add-wins for OR-Set; set.or/set.2p conformance buckets Pass; M-set (Appendix B) met; M3 (100k-element 4-replica OR-Set merge < 1 s) met.

Fixtures
Fixture Purpose Expected
corpora/set/or_set/scenario_*.jsonl multi-replica orderings identical final state all orders
add/remove/re-add (§8.2) observed-remove re-add survives, add wins
corpora/set/two_p_set/*.jsonl permanence removed stays removed
proptest concurrent add/remove add wins property holds
GC-before-stability chaos I4 element resurrects → test fails if GC'd early
Pitfalls
  • Using 2P-Set where re-adds are needed (§8.7 decision table; the single most common production set-CRDT bug, MM4).
  • Dot reuse across replicas (I5).
  • GC before causal stability → resurrected elements (I4, P4, FM-2).

⬜ Phase 4 — Register CRDTs (LWW-Register, MV-Register) §16

Objectives

Implement single-value registers differentiated by conflict-resolution rule: last-writer-wins (a total order) vs multi-value (preserves concurrency). Constraint introduced: LWW requires a total-order tiebreak (I10) — the first CRDT in the library to need one.

Deliverable

register/* modules (LWW, MV); LWW + MV conformance corpora with the 3-replica concurrent-write case emphasised for MV.

Acceptance

LWW converges deterministically by (ts, replica) across all delivery orders; MV preserves all concurrent values and collapses sequential overwrites to one; set is idempotent (double-apply is a no-op, I3); register.lww/register.mv conformance buckets Pass; M-reg (Appendix B) met; M4 (1M sets, 4 replicas, full convergence < 2 s) met.

Fixtures
Fixture Purpose Expected
corpora/register/lww/*.jsonl concurrent writes converge by (ts, replica)
corpora/register/mv/*.jsonl 3-way concurrent all values preserved; sequential overwrite
proptest idempotence apply same set twice identical state (I3)
equal-timestamp tiebreak I10 higher replica wins, stable
Pitfalls
  • Wall-clock timestamps for LWW (clocks go backwards — use HLC, MM2).
  • Ignoring the replica tiebreaker on equal timestamps (breaks I10 → merge is no longer associative).
  • Returning a single value from MV-Register (it is multi-value by design; collapsing early loses information the application needed).

⬜ Phase 5 — Sequence CRDTs (RGA, WOOT, Logoot) §17

Objectives

Implement three sequence CRDTs (RGA default, WOOT oracle, Logoot opt-in) so the user picks per workload and the conformance harness cross-checks convergence across all three. Constraint introduced: concurrent-insert ordering must be total and deterministic (extends I5's dot uniqueness into a full ordering).

Deliverable

sequence/* modules (RGA, WOOT, Logoot); the permutation corpora proving cross-implementation convergence; crdt-bench sequence-diff benchmark.

Acceptance

All three converge to the identical string for every delivery permutation tested; RGA matches the Yjs oracle byte-for-byte (to_string); M5 (100k-char RGA diff < 100 ms) met; sequence.rga/.woot/.logoot conformance buckets Pass; M-seq (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/sequence/rga/*.jsonl all delivery permutations same final string
corpora/sequence/woot/*.jsonl reference cross-check matches RGA result
corpora/sequence/logoot/*.jsonl dense-id ordering matches RGA result
Yjs golden scripts oracle parity to_string matches Yjs
100k-char diff bench M5 < 100 ms
Pitfalls
  • Tombstone bloat in long-lived RGA (GC at stability is the only mitigation, FM-4).
  • Adversarial same-position inserts in Logoot (unbounded id growth → rebase/rate-limit, FM-5, Threat #4).
  • WOOT's quadratic worst case (ship as reference; expose the asymptotic in crdt-bench, never as the default per ADR-04).

⬜ Phase 6 — JSON CRDT and Tree CRDT (Yjs / Automerge shape) §18

Objectives

Compose the primitives into a JSON CRDT (Automerge-shaped object/array model) and a Yjs-shaped Y.Map tree, plus the Document composition root that owns the clock and allocates dots. Constraint introduced: a single Document commits to exactly one shape (Yjs or Automerge); mixing is rejected (I14).

Deliverable

json/*, tree/*, document/* modules; JSON + tree conformance corpora; the composition root every binding (Phase 11) and use-case example (Phase 12) is built on.

Acceptance

Documents round-trip byte-identically through encode_state/decode_state (I7/I8); different-path concurrent writes merge with both present; same-path concurrent writes resolve per the documented LWW tiebreak (§8.8 worked example); json.automerge/tree.ymap conformance buckets Pass; M-json (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/json/automerge/*.jsonl json-patch scripts final doc equal across permutations
corpora/tree/ymap/*.jsonl Y.Map scripts tree equal across permutations
different-path concurrent clean merge both writes present
same-path concurrent LWW/MV rule documented resolution
encode/decode round-trip I7/I8 byte-identical
Pitfalls
  • Mixing Yjs and Automerge shapes in one document (schema validation prevents it, I14).
  • Number precision: f64 does not round-trip integers > 2^53 (documented, not defended against — an application-level contract).
  • Array indices shifting under concurrent inserts (use object ids, not indices, for cross-document refs).

⬜ Phase 7 — Delta-State Encoding §19

Objectives

Ship the delta-state wire encoding — a state-based CRDT shipped at delta granularity — as the library default. Constraint introduced: every wire payload from this phase forward is a versioned, schema-tagged envelope (P5) that the decoder must reject-or-accept typed, never silently mis-parse (P6).

Deliverable

delta/codec.rs; docs/delta-encoding.md; the delta_fuzz.rs fuzz target that every later phase's wire path reuses.

Acceptance

Codec round-trips byte-identically (encode→decode→apply == merge of full state, I11); fuzz finds zero panics across 10⁶ generated inputs; delta sizes meet M6 (≤5% of state-based bytes) and the ~24 B/delta sanity figure for G-Counter; double-apply is idempotent (I11); delta.codec conformance bucket Pass; M-delta (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/delta/*.bin (state, delta) pairs apply_delta == merge(decode_state)
delta_fuzz.rs malformed inputs always typed MergeError, never panic
G-Counter delta size M-delta sanity ~24 bytes per delta, 4-replica
100k-char RGA single-insert delta size bound < 200 bytes compressed
double-apply I11 idempotent
Pitfalls
  • Forgetting to bump the wire version on a schema change (every change is an ADR + version bump, P5).
  • Shipping a delta the receiver cannot interpret (it returns SchemaMismatch; sender downgrades, never the reverse — Threat #8).
  • Zstd dictionary drift — no dictionary compression in Phase 0 (dictionaries deferred, see Deferred Features Register).

⬜ Phase 8 — Anti-Entropy via Merkle-Tree Diff & Transport §20

Objectives

Implement periodic catch-up sync via Merkle-tree diff over the op log, plus the pluggable Transport trait with in-memory and libp2p backends. Constraint introduced: the Merkle tree must span the entire log (I12) — a partial tree is a silent-divergence bug, not an optimization shortcut.

Deliverable

crdt-sync/merkle.rs, anti_entropy.rs; crdt-transport/* (memory/libp2p/websocket/grpc backends); the anti-entropy conformance corpus.

Acceptance

Two divergent replicas (1000-delta disjoint logs) converge in one round shipping only the differing leaves (byte count ≈ diff size, not full-log size); robust to transport truncation (retries succeed); sync.anti_entropy conformance bucket Pass; M7 (1k-delta divergence anti-entropy round < 200 ms p95) met; M-ae (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/sync/anti_entropy/*.json disjoint logs, 1000 deltas converge in one round
byte-count assertion ship only differing leaves bytes ≈ diff size
truncated transport robustness Err(Truncated), then retry succeeds
empty-tree diff edge "ship everything"
10M-leaf collision corpus xxh3 safety no false convergence
Pitfalls
  • Recomputing the whole Merkle tree per op (use the incremental path; O(N) recompute would erase the O(log N) diff advantage).
  • Diffing when one side is at null root (empty → ship everything, not an error).
  • Partial Merkle tree → silent divergence (I12, FM-1).

⬜ Phase 9 — Gossip-Based Dissemination §21

Objectives

Implement push-pull gossip to keep the steady state close to up-to-date, with selectable topologies and backpressure. Constraint introduced: gossip must degrade gracefully under load (backpressure, not unbounded queueing) and under churn (co-designed with anti-entropy, not a replacement for it).

Deliverable

crdt-sync/gossip.rs, topology.rs; the gossip conformance corpus covering (peers, churn, delta-rate) triples.

Acceptance

100 replicas converge within M8 (≤ ⌈log₂100⌉+2 = 9 rounds); still converges under 30% churn; backpressure bounds memory (no OOM under a sustained delta flood); sync.gossip conformance bucket Pass; M-gossip (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/sync/gossip/*.json (peers, churn, delta rate) triples converge in O(log N) rounds
100-replica single-delta M8 ≤ ⌈log₂100⌉+2 = 9 rounds
30% churn robustness still converges
backpressure cap enforcement back-off engages, no OOM
Pitfalls
  • Push-only gossip leaks to late joiners (push-pull is the default, ADR-22, FM-6).
  • Unbounded fanout (fanout 50 on 50 peers == full mesh; default ≈ log₂N).
  • Assuming a complete topology (a dead hub is a partition; expose a "hub healthy" predicate, application owns failover).

⬜ Phase 10 — Persistence (WAL + Snapshot, integrating rank 69) §22

Objectives

Persist deltas durably and recover byte-identically, integrating the WAL project (rank 69) for the log and a per-CRDT snapshot story. Constraint introduced: recovery must be byte-identical to pre-crash state (I13) — the strongest correctness bar in the library outside the merge laws themselves.

Deliverable

crdt-storage/* modules (log.rs wraps the WAL project, snapshot.rs, recovery.rs); the storage-recovery conformance corpus; the crash-during-snapshot chaos scenario.

Acceptance

1M-delta workload recovers byte-identically to pre-crash state (I13); snapshot writes are crash-atomic (chaos/scenarios/crash_during_snapshot.rs always recovers to a valid prior state, never a torn one); corrupted WAL records surface as a typed error, never a silent skip; startup recovery completes in < 3 s (M12, §4); storage.recovery conformance bucket Pass; M-storage (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/storage/*.bin (WAL prefix, snapshot, expected state) recovery == expected
1M-delta write+recover durability byte-identical (I13)
chaos/scenarios/crash_during_snapshot.rs atomicity recover to last durable state
corrupted WAL record no silent skip propagate corruption error
Pitfalls
  • Snapshotting under load without MVCC blocks appends (ADR-21).
  • Truncating the WAL before the snapshot is durable (sync snapshot first, then truncate — never the reverse).
  • Recovering from a corrupted WAL silently (propagate, never skip — relies on the WAL's per-record checksum, Threat #7).

⬜ Phase 11 — Bindings (WASM and Python via PyO3) §23

Objectives

Expose the library to non-Rust consumers via thin WASM (browser) and PyO3 (server) bindings. Constraint introduced: bindings carry zero merge logic (P9) — every merge decision executes in crdt-core, verified by byte-identical cross-language round-trips.

Deliverable

crdt-wasm/, crdt-py/; binding conformance corpora; the cbindgen config for the deferred C ABI surface.

Acceptance

WASM loads in Chrome/Firefox without polyfills; PyO3 installs as a wheel (manylinux + macOS + Windows); both round-trip byte-identically with the core (bindings.wasm/bindings.py conformance buckets Pass); GIL is released across merges > 1 ms with no deadlock under threaded load; M-wasm and M-py (Appendix B) met.

Fixtures
Fixture Purpose Expected
corpora/bindings/wasm/*.json headless-browser round-trip byte-identical to Rust core
corpora/bindings/py/*.json subprocess round-trip byte-identical to Rust core
GIL-release merge concurrency no GIL deadlock under threads
Pitfalls
  • Allocating in the WASM hot path (batch operations across the boundary; every crossing has fixed marshalling cost).
  • Holding the GIL across a long merge (use Python::allow_threads, else other Python threads stall).
  • Re-implementing merge in a binding (forbidden, P9 — the single-source-of-truth violation this phase exists to prevent).

⬜ Phase 12 — Use-Case Integrations and Chaos Validation §24

Objectives

Prove production fitness with four use-case integrations and a Jepsen-style chaos suite over partition, churn, and crash scenarios. Constraint introduced: examples are working code exercised end-to-end, not slideware, and chaos seeds must be recorded for reproducibility (P10).

Deliverable

Four examples with recorded transcripts (distributed-counter, whiteboard, offline-first, editor-stretch); chaos/jepsen/ + scenario suite; the 24-hour soak harness.

Acceptance

All four examples run end-to-end with a transcript matching the committed golden output; chaos suite green on partition/churn/crash scenarios (I1–I4, I12–I13 hold under adversarial conditions); 24-hour soak shows zero unhandled exceptions and zero unbounded memory growth (M9); M10 (30-day delta-codec fuzz canary, zero crashes) tracked as the Sealed gate; M-jepsen and M-soak (Appendix B) met.
