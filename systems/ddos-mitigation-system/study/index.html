32. Mental Models & First Principles

  • MM1 — DDoS defense is an economics problem: you win by making the attack cost more than the defense costs, which is why proof-of-work and amplification-factor reduction matter more than raw absorption capacity alone (P7, §34's cost-asymmetry math).
  • MM2 — the hard problem is not dropping packets, it is telling attack from legitimate at line rate under an adversary trying to look legitimate; every defense is a classifier with a false-positive cost (P2, P3).
  • MM3 — you cannot filter what you cannot see fast enough; detection and mitigation must both run at (or near) line rate, or the slow one is the bottleneck the attacker will aim at (P1, P6, I8).
  • MM4 — no single signal is sufficient against an adaptive adversary; every real mitigation decision in this system is a combination of at least two independent signals (P8, the classification table in §8).
  • MM5 — bounded memory is not an optimization, it is a security property; an unbounded data structure fed by attacker-controlled input is itself a DoS vector (P9, I4, I7).
  • MM6 — a mitigation without an expiry is a liability, not a defense; the system must assume every rule will eventually be wrong and plan for its own reversal (P5, I5).
  • MM7 — always-on and on-demand are not competing designs but complementary layers; the choice is a latency-vs-activation-time tradeoff, not a correctness question (§1 deployment model, §33).
  • MM8 — the attacker adapts to whatever the defense publishes as its threshold; any purely static, disclosed threshold is eventually obsolete, which is why statistical and combinatorial signals outlast simple thresholds (P3, Phase 11).

Glossary (§38) · 61 terms · site-wide glossary

DDoS
Distributed Denial of Service — an attack using multiple sources to exhaust a target's resources
Volumetric attack
attack aiming to exhaust raw bandwidth/packet-rate capacity
Protocol attack
attack exploiting a protocol state machine (e.g., SYN flood) rather than raw volume
Application-layer (L7) attack
attack exploiting application resource limits (HTTP flood, slow-loris) at protocol-valid traffic shape
Amplification
technique where a small attacker request produces a disproportionately large response
Reflection
technique routing an amplified response at a victim via a spoofed third-party source address
Amplification factor
ratio of response size to request size for a given protocol (Rossow 2014)
SYN flood
TCP state-exhaustion attack via masses of unanswered SYN packets
SYN cookie
stateless cryptographic technique validating a handshake without pre-allocating connection state (Bernstein)
Spoofing
forging a packet's source address
BCP 38
Best Current Practice 38 / RFC 2827, network ingress filtering to prevent spoofing
BCP 84
Best Current Practice 84 / RFC 3704, ingress filtering for multihomed networks
XDP
eXpress Data Path — Linux kernel hook for line-rate packet processing before sk_buff allocation
eBPF
extended Berkeley Packet Filter — verified, restricted bytecode execution in the kernel
DPDK
Data Plane Development Kit — userspace kernel-bypass packet I/O framework
Line rate
the maximum packet/byte throughput a link can sustain
pps
packets per second
Flow table
data structure tracking per-flow state keyed by connection tuple
Five-tuple
(source IP, destination IP, source port, destination port, protocol) — the canonical flow key
Entropy anomaly detection
detecting attacks via Shannon-entropy shifts in traffic distribution (Lakhina et al. 2005)
Count-min sketch
fixed-memory probabilistic data structure for approximate frequency counting (Cormode & Muthukrishnan 2005)
Heavy hitter
a flow/source responsible for a disproportionate share of traffic
Elephant flow
a very high-volume flow relative to typical flows (Estan & Varghese 2002)
Token bucket
rate-limiting algorithm admitting traffic against a refilling capacity budget
Rate limiting
bounding the admitted rate of traffic per key
Proof of work
requiring a client to perform costly computation before a request is served
JS challenge
requiring a client to execute JavaScript to filter non-browser automated clients
False positive
legitimate traffic incorrectly classified/blocked as an attack
False negative
attack traffic incorrectly classified/passed as legitimate
Flash crowd
a legitimate sudden surge in traffic, not an attack
Scrubbing center
a facility that filters attack traffic out of a diverted stream before returning clean traffic
Anycast
routing technique where one IP address is announced from multiple physical locations
BGP diversion
using BGP announcements to route traffic through a scrubbing center
GRE back-haul
tunneling cleaned traffic from a scrubbing center back to the origin via GRE encapsulation
Always-on
a mitigation posture where the defense is inline on all traffic continuously
On-demand
a mitigation posture activated only when an attack is detected
Reputation
a score representing a source's historical trustworthiness
Allowlist
an explicit set of sources always permitted, bypassing other checks
Blocklist
an explicit set of sources always denied
Mirai
a notable IoT botnet malware family, referenced as the botnet-scale precedent (Antonakakis et al. 2017)
Botnet
a network of compromised hosts controlled to conduct coordinated attacks
NUMA
Non-Uniform Memory Access — multi-socket architecture where memory locality affects latency
NAPI
Linux kernel's New API for interrupt-mitigated network packet reception
Softirq
Linux kernel deferred-interrupt processing context, where RX packet processing runs
Verifier
the eBPF kernel component that statically proves program safety before load
Cardinality
the number of distinct values (e.g., distinct source IPs) in a dataset
Backscatter
unsolicited response traffic caused by spoofed-source attacks, used to infer attack activity (Moore et al. 2006)
RTO
Recovery Time Objective — target maximum time to restore service after failure
RPO
Recovery Point Objective — target maximum acceptable data loss window
SLO
Service Level Objective
JA3 fingerprint
a TLS Client Hello fingerprinting technique
Slow-loris
a low-and-slow L7 attack holding many connections open at minimal rate
Cache-busting
crafting requests to defeat caching layers, forcing full backend processing
uRPF
Unicast Reverse Path Forwarding — a router technique to detect implausible source addresses
ASN
Autonomous System Number
CIDR
Classless Inter-Domain Routing notation for IP prefixes
MTU
Maximum Transmission Unit
SBOM
Software Bill of Materials
CO-RE
Compile Once – Run Everywhere, an eBPF portability technique
libbpf
the canonical userspace library for loading and managing eBPF programs
Hold-down interval
a required period of sustained clear traffic before a mitigation or diversion is withdrawn, bounding route-flap and premature-withdrawal risk (§22)
