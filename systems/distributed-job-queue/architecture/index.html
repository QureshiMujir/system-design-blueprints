Producer SDK — encodes a typed Job through the registered codec (ADR-11), attaches an idempotency key and trace context, and calls the frontend over gRPC (ADR-02). Frontend gRPC / Operator HTTP — the only network entry points; both delegate to the same Engine so business logic exists once. Engine — validates, dispatches middleware, and calls exactly one Storage method per operation (P3); it never touches adapter internals. Storage Adapter — pluggable persistence (P3, ADR-03/04/05); each adapter implements the full Storage interface (§11) and reports its Capabilities. Scheduler — single leader (P4, I4) that promotes delayed jobs, sweeps expired leases, and fires cron ticks; leader election is an advisory lock in Phase 0, Raft in the deferred upgrade (§20.2). Worker Process — pulls via long-poll Reserve, runs handlers in a bounded pool, renews the lease heartbeat (P2, I2), and drains gracefully on SIGTERM (P10). All later sections keep every name in this diagram identical to the Repository Layout (§10) and Core Schema & Types (§11) — the terminology lock.

8. Domain Model

8.1 Job record schema

Job {
  ID              string      // 26-char ULID, monotonic (§13)
  Queue           string      // [a-z0-9_-]{1,64}
  Type            string      // handler key, same charset as Queue
  Payload         []byte      // opaque to broker, ≤ MaxPayloadSize (§4)
  PayloadCodec    string      // "proto" | "cbor" | "json" (ADR-11)
  Priority        uint8       // band 0..9, default 5 (I13)
  ScheduledAt     time.Time   // zero = immediate
  Deadline        time.Time   // zero = none
  MaxAttempts     uint8       // default 25 (ADR-13)
  Attempt         uint8       // broker-incremented
  RetryStrategy   string      // policy name (ADR-13)
  LeaseDuration   time.Duration // default 30s (ADR-15)
  IdempotencyKey  string      // optional, dedup window ADR-14
  Tenant          string      // fairness scoping (P11)
  TraceID, SpanID string      // W3C Trace Context
}

8.2 State machine (delivery semantics)

Show the original text diagram
PENDING --reserve--> LEASED --ack-------------> COMPLETED
   ^                    │  \--retry(backoff)---> PENDING (attempt++)
   │                    │  \--dead-letter------> DEAD_LETTERED
DELAYED --promote-------┘   \--lease-expiry-----> PENDING (sweep, attempt++)
   (scheduled_at reached)     \--cancel----------> CANCELED

Terminology: SQS calls the lease a visibility timeout; Faktory calls the terminal-failure transition bury; this project names the primitive lease (vocabulary rationale below, I2) and the terminal-failure state DEAD_LETTERED to match ADR-16.

8.3 Worked example — at-least-once double delivery

  1. Producer calls Enqueue(Job{Type:"charge", IdempotencyKey:"order-9182"}). Broker persists, returns ID 01J...Z.
  2. Worker A reserves it; LeaseExpiresAt = now+30s.
  3. Worker A's host is SIGKILLed mid-handler (after charging the card, before Ack).
  4. Sweep reclaims at LeaseExpiresAt; job returns to PENDING, Attempt=2.
  5. Worker B reserves and re-runs the handler. The handler's own idempotency table (keyed by order-9182) recognizes the charge already happened and returns success without a second charge.
  6. Worker B calls Ack. State → COMPLETED. This sequence is exactly the idempotency_double_run conformance fixture (§26).

8.4 Malformed-input example

Enqueue(Job{Queue:"My Queue!", Payload: 2MiB}) — rejected at the SDK boundary before any network call: Queue fails [a-z0-9_-]{1,64} (space and ! are illegal), and Payload exceeds the 1 MiB hard ceiling (§4). The broker never sees a partial write; ErrInvalidQueue and ErrPayloadTooLarge are both returned in one errors.Join so the caller sees every violation at once. Fixture: conformance/fixtures/negative/enqueue_malformed.json.

8.5 Failure-path example — storage adapter outage

Redis becomes unreachable mid-Reserve. The circuit breaker (Phase 3, §15.10) opens after 5 consecutive failures within 2 s; Capabilities() reports Degraded=true; the engine returns ErrStorageUnavailable to new Enqueue/Reserve calls while in-flight leases already held by workers remain valid (no data loss, I1) until the breaker half-opens and probes recovery. Fixture: conformance/fixtures/negative/storage_outage_reserve.json.

8.6 Priority and fairness model

Bands 0–9, reserve scans band 9 → 0. A per-tenant skip counter (I13) forces the scan to restart at band 5 after 100 consecutive same-band reservations, bounding worst-case starvation of a low-priority tenant to 100 × avg_handler_duration.

8.7 Idempotency key and dedup window

idem:<key> → job_id, TTL = dedup window (24 h default, ADR-14). A second Enqueue with the same key returns the existing job_id without a new write (I8). The window survives completion so a late producer retry after the job finished still returns the same ID (Vogels 2009, eventual convergence of the dedup view).

Design principles (§6)

  • At-least-once by default; idempotency is the application's contract (P1). The broker never claims exactly-once. Tradeoff: applications must supply idempotency keys or idempotent handlers. Operational implication: the SDK docstrings and operator UI repeat this in plain language. Violating it (claiming exactly-once) misleads operators into skipping dedup logic and causes double side effects (§22 T1).
  • Visibility timeouts are leases, and leases are explicit (P2). Every reservation carries lease_expires_at; workers renew on a heartbeat (I2). Tradeoff: renewal traffic scales with in-flight count. Operational implication: lease state is inspectable from the operator UI. Violating it (implicit timeouts, Resque-style) silently drops in-flight work on slow handlers.
  • Storage is pluggable but not lowest-common-denominator (P3). Storage is a Go interface (§11); adapters expose Capabilities() rather than narrowing the contract. Tradeoff: the engine must branch on capability gaps. Violating it collapses every adapter to the weakest one's feature set.
  • Single-leader for the scheduler; multi-leader for workers (P4). Delay-promotion, sweep, and cron ticks run under one elected leader (I4); reservation is many-writer, serialized by the storage adapter. Violating it (timestamp-comparison election) produces split-brain double-scheduling (§22 T4).
  • Retries are exponential with full jitter, and capped (P5). delay = uniform(0, min(cap, base·2^attempt)), base=1s, cap=12h, max_attempts=25 (ADR-13). Tradeoff: custom policies are pluggable but the default is non-negotiable without an ADR. Violating it (unbounded retry) starves the queue on a permanently-broken handler.
  • Dead-letter is durable and inspectable, never a log line (P6). The dead-letter set is bounded, paginated, requeueable, and carries full retry history (ADR-16). Violating it loses the operator's only forensic trail for exhausted work.
  • Backpressure is explicit (P7). Producers may opt into ErrBackpressure at a depth threshold (Nygard ch. 5); silent unbounded buffering past the threshold is forbidden absent an explicit operator opt-out. Violating it turns a transient outage into an unbounded queue.
  • The wire format is typed (P8). Submit[T] encodes through a registered codec (ADR-11); interface{} in the SDK without justification is rejected in review. Violating it pushes runtime type errors into production handlers.
  • Observability is not opt-in (P9). Every broker primitive emits a Prometheus metric and an OTel span keyed by job_id (I11). Violating it makes an incident undebuggable from the operator surface alone.
  • Graceful shutdown drains (P10). SIGTERM stops new pulls, finishes in-flight up to drain_timeout, renews leases throughout the drain. Violating it drops in-flight jobs on every deploy.
  • Fairness is per-tenant, bounded, and auditable (P11). A starvation cap (§19) prevents one tenant's high-priority flood from starving another tenant's low-priority work indefinitely. Violating it turns a shared broker into a noisy-neighbor incident generator.
  • Idempotency windows expire (P12). The dedup index (ADR-14) has a TTL; an index that never expires leaks memory until the process dies. Violating it is an unbounded-memory bug disguised as a correctness feature.
  • Every cross-adapter primitive is atomic at the storage layer (P13). Multi-step operations (reserve, promote, sweep) are one Lua script (Redis) or one statement (Postgres) — never client-side read-modify-write. Violating it reintroduces the races the adapter exists to prevent (I3).
