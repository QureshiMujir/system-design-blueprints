30. Mental Models & First Principles

  1. MM1 — A lease is a bet with an expiry clock, not a proof of liveness. Predicts: a worker holding a lease might already be dead; the system must act as if every lease could be stale at expiry. Bug class without it: treating lease possession as a liveness guarantee, causing double-processing to be "surprising" instead of expected (§18.9, §8.3).
  2. MM2 — At-least-once shifts the correctness burden downstream, it does not eliminate it. Predicts: every handler must be idempotent or the system must supply an idempotency layer. Bug class without it: assuming the broker "handles" duplicates when only the application can (§7 I1, §8.7).
  3. MM3 — A queue is a work-distribution primitive with amnesia; a log is a replay primitive with memory. Predicts: once a job is acked, the record is gone — you cannot "replay" a completed job the way you replay a Kafka offset. Bug class without it: expecting queue semantics from a log or vice versa (§2, §31).
  4. MM4 — Fairness is a scheduling problem, not a queue-depth problem. Predicts: a deep queue for one tenant does not by itself starve another tenant if the scheduler enforces per-tenant bounds. Bug class without it: throttling globally instead of per-tenant, punishing quiet tenants for a noisy one (§8.6, §20).
  5. MM5 — Backpressure is a contract the caller opts into, not a physical law the broker enforces unconditionally. Predicts: an operator who never enables Backpressure: true has consciously chosen unbounded buffering. Bug class without it: assuming the broker always protects itself, then being surprised by unbounded growth (§6 P7, §22 T5).
  6. MM6 — An idempotency key is a poor man's exactly-once, bounded by a window. Predicts: after the dedup window expires, the "exactly-once" property silently reverts to at-least-once. Bug class without it: assuming permanent dedup and never re-checking after a long producer-side retry delay (§8.7, §32).
  7. MM7 — A dead-letter queue is a forensic ledger, not a graveyard. Predicts: every dead-lettered job must be requeueable with its history intact, because the operator's next action is almost always "fix and replay." Bug class without it: treating dead-letter as a terminal log line with no path back (§6 P6, §23 FM-1).
  8. MM8 — Leader election converts a distributed problem into a single-writer problem, at the cost of an availability window during handover. Predicts: the scheduler is unavailable for at most one lock-TTL period during a leader crash — a bounded, known cost, not an open-ended outage. Bug class without it: expecting zero-downtime scheduling without accounting for the handover window (§7 I4, §19.9).

Required reading (§5)

Books

  • Kleppmann, Designing Data-Intensive Applications, O'Reilly 2017, ch. 8 ("The Trouble with Distributed Systems") — clock/lease reasoning; applied in §7 (I2, I4) and Phase 6 (§18).
  • Kleppmann, Designing Data-Intensive Applications, ch. 9 ("Consistency and Consensus") — leader election, linearizability; applied in Phase 7 (§19) and §20.2.
  • Kleppmann, Designing Data-Intensive Applications, ch. 11 ("Stream Processing") — log vs queue semantics; applied in §8 and §31.
  • Petrov, Database Internals, O'Reilly 2019, ch. 5 ("Transaction Processing and Recovery") — MVCC, row locking; applied in Phase 4 (§16, ADR-04).
  • Herlihy & Shavit, The Art of Multiprocessor Programming, Morgan Kaufmann 2012, ch. 3 ("Concurrent Objects") — linearizability of the lease/reservation primitive; applied in §7 (I2, I3).
  • Nygard, Release It!, 2nd ed., Pragmatic Bookshelf 2018, ch. 5 ("Stability Patterns") — circuit breaker, bulkhead, backpressure; applied in Phase 8 (§20) and §22 (T7).
  • Cox-Buday, Concurrency in Go, O'Reilly 2017, ch. 4–5 (pipelines, cancellation) — bounded worker-pool design; applied in Phase 6 (§18).

Papers

  • Dean & Barroso, "The Tail at Scale," Communications of the ACM 56(2), 2013 — applied in §28 and §4 (p99 targets).
  • Kreps, Narkhede, Rao, "Kafka: a Distributed Messaging System for Log Processing," NetDB 2011 — applied in §8 and §31 (queue-vs-log contrast).
  • Ongaro & Ousterhout, "In Search of an Understandable Consensus Algorithm (Raft)," USENIX ATC 2014 — applied in §20.2 (deferred leader-election upgrade) and §35.
  • Burrows, "The Chubby Lock Service for Loosely-Coupled Distributed Systems," OSDI 2006 — applied in §7 (I4) and Phase 7 (§19, lease-as-session).
  • DeCandia et al., "Dynamo: Amazon's Highly Available Key-value Store," SOSP 2007 — applied in §9 (ADR-03) and §29 (partitioning).
  • Brewer, "CAP Twelve Years Later: How the 'Rules' Have Changed," IEEE Computer 45(2), 2012 — applied in §7 (I1, I5) and §22.
  • Vogels, "Eventually Consistent," Communications of the ACM 52(1), 2009 — applied in §8.7 (idempotency window) and §31.
  • Corbett et al., "Spanner: Google's Globally-Distributed Database," OSDI 2012 — applied in §32 (external-clock cost comparison) and §34 (Alternative 2).

Reference Implementations

  • Sidekiq (Ruby), lib/sidekiq/processor.rb, lib/sidekiq/scheduled.rb — the middleware chain and implicit-timeout pattern; lesson applied in Phase 6 (§18); pitfall (implicit lease) not copied — see §22 T3.
  • asynq (Go), internal/rdb/rdb.go, processor.go, scheduler.go — closest design relative; applied in Phase 3 (§15) for the Lua-script atomicity pattern.

  • AWS SQS (design as documented in the Developer Guide) — visibility timeout, FIFO dedup interval; applied in §8.2 and §4.
  • Resque (Ruby) — the simplest production queue, no lease renewal; applied as the negative example in §22 T3 and Phase 6 pitfalls (§18.6).

Glossary (§36) · 42 terms · site-wide glossary

Ack
worker signal that a job completed successfully; broker moves state to COMPLETED.
ADR
Architecture Decision Record; this document's ADR table is §9.
Advisory lock
Postgres session-scoped lock used for Phase-0 leader election (ADR-12).
At-least-once
delivery guarantee where a job may run more than once but never zero times (I1).
Attempt
broker-incremented counter of reservation count for a job.
Backpressure
explicit signal (ErrBackpressure) that a producer's enqueue was rejected due to queue depth (P7).
Band
one of ten priority levels (0–9) scanned by the reserve loop (§8.6).
Broker
the process (cmd/jobqd) hosting the Engine, Scheduler, and Storage adapter.
Capabilities
an adapter's self-reported feature/limit set (§11).
Circuit breaker
a client-side failure-detection wrapper that opens after consecutive storage failures (§15.10).
Cold start
the time from broker process launch to readiness (§4, M9).
Conformance bucket
a named group of positive/negative fixtures verifying one capability (§26).
Cron bucket
the truncated-timestamp unit (default: minute) used to key a cron idempotency key (§19.2).
Dead-letter
terminal state for a job that exhausted MaxAttempts (ADR-16, I6).
Dedup window
the TTL over which an idempotency key resolves to the same job ID (§8.7).
Delay set
the storage structure holding jobs whose ScheduledAt is in the future (§8.1).
Drain timeout
the maximum wait during graceful shutdown for in-flight handlers to finish (P10).
Engine
the business-logic layer between the API and the Storage adapter (§17).
Full jitter
a backoff formula, uniform(0, min(cap, base·2^attempt)) (ADR-13).
Handler
user-supplied callback invoked per reserved job.
Heartbeat
the periodic lease-renewal call made by a worker holding an active lease (§18.2).
Idempotency key
caller-supplied string deduplicating enqueue calls within a window (§8.7).
Lease
the explicit, renewable reservation record (JobID, WorkerID, Token, ExpiresAt) this project uses instead of an implicit visibility timeout (§8.2, MM1).
Leader election
the mechanism ensuring exactly one scheduler instance promotes/sweeps/ticks (I4).
Long-poll
a Reserve call that blocks up to a deadline waiting for an available job.
Middleware
a wrapper applied to a Handler for cross-cutting concerns (tracing, metrics, recovery).
Payload
the opaque application bytes carried by a Job.
Priority
the band (0–9) determining reserve-scan order (§8.6).
Promote
the scheduler action moving a delayed job into the immediate queue once ready (§8.1).
Reserve
the operation by which a worker takes ownership of the next eligible job.
RTO
Recovery Time Objective; the target time to restore service after a failure (§4).
RPO
Recovery Point Objective; the target maximum acceptable data loss window (§4).
SKIP LOCKED
the Postgres row-locking clause enabling concurrent, non-blocking reservation (§16.2).
Starvation cap
the consecutive-same-band reservation limit that forces a scan-restart at a lower band (I13).
Storage adapter
the pluggable persistence implementation of the Storage interface (§11).
Sweep
the scheduler action reclaiming jobs whose lease has expired (§8.1).
Tenant
the multi-tenant scoping label used for fairness quotas (§20).
ULID
Universally Unique Lexicographically-sortable Identifier, this project's job-ID format (§13).
Visibility timeout
the SQS term for what this project calls a lease (§8.2 terminology note).
Worker
the process running registered Handlers against reserved jobs.
Worker pool
the bounded-concurrency goroutine pool executing handlers (§18).
Zset
Redis sorted set, used for delayed/leased/dead-letter/done ordering by score (§15.2). ---
