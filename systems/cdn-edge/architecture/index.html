TLS + Protocol Termination — trust boundary #1: untrusted bytes become a parsed, ALPN-negotiated stream; SNI drives per-zone cert selection (up to 12k certs, §4).

HTTP Frontend — parses per-protocol wire format into one canonical Request (§11); computes the range/conditional intent; hands off a normalized CacheKey.

Cache Semantics Engine — the RFC 9111 brain: computes freshness lifetime, decides hit/stale/miss, applies Vary, decides whether a validator (ETag/Last-Modified) round-trip is needed. Pure logic, no I/O.

Tiered Cache Store — trust boundary #2 (concurrency boundary): DRAM (L1, TinyLFU-admitted) and NVMe (L2, mmap-backed, S3-FIFO-evicted); placement across the simulated fleet resolved via consistent hashing.

Single-Flight Gate — concurrency boundary: collapses N concurrent misses on the same CacheKey into 1 origin fetch.

Origin Shield + Fetch — protocol boundary to the outside world; connection pool, retry policy, circuit breaker, weighted origin selection.

Purge/Invalidation Bus — external interface (control-plane API) + async propagation channel/queue across the simulated fleet, SLA-bound.

DDoS / Poisoning Defense — cross-cutting: rate limiting and cache-key/header-normalization enforcement sit in front of and inside the Cache Semantics Engine.

Observability Plane — cross-cutting: every box emits metrics/traces; not a separate data-flow hop.

All later sections (Domain Model, Repository Layout, Core Schema, phases) name the same boxes and the same module names; drift from this diagram is a defect (terminology-lock discipline, enforced throughout this document).

8. Domain Model

8.1 Cache Object Model & CacheKey

CacheKey := SipHash24( method, authority, normalized_path, sorted(vary_map) )
CacheEntry {
  key: CacheKey, status: u16, headers: HeaderMap, body: BodyRef,
  stored_at: Instant, freshness_lifetime: Duration,
  validators: { etag: Option<ETag>, last_modified: Option<HttpDate> },
  vary_headers: Vec<HeaderName>, tags: SmallVec<[Tag; 4]>,
  version: u64, tier: TierId, size_bytes: u32,
}

version increments on every write to the same key (enforces I4, I14 region); tier ∈ {L1, L2, Shield} names where the authoritative copy lives. Tags are customer-assigned strings (ADR-08 region: purge granularity).

8.2 HTTP Cache Semantics (RFC 9111)

Freshness lifetime = explicit (max-age, or Expires) else heuristic (10% of (Date − Last-Modified), capped, RFC 9111 clause 4.2.2). Response is:

State Condition Action
Fresh age < freshness_lifetime serve directly, no origin contact
Stale-revalidate age ≥ freshness_lifetime, no override conditional GET (If-None-Match/If-Modified-Since)
Stale-while-revalidate stale + stale-while-revalidate=N and age − freshness_lifetime < N serve stale, revalidate async (P12)
Stale-if-error origin unreachable + stale-if-error=N serve stale, mark degraded
Must-revalidate must-revalidate/no-cache present never serve stale, block on origin
Uncacheable no-store, or authenticated + no explicit cache directive bypass cache entirely

Vary handling: response Vary: X records X's request-header value in vary_map (§8.1); a later request matches the CacheEntry only if every vary_map value matches. Vary: * is a magic value meaning never reusable — treated as no-store for storage purposes (P1).

8.3 Request Coalescing / Single-Flight

Exactly one origin fetch exists per (CacheKey, tier) while Fetching (I3); a losing waiter's added tail latency equals t_origin_response − t_waiter_arrival, bounded by the 80 ms p99 miss target (§4).

8.4 Origin Shield, Mid-Tier Hierarchy & Placement

A zone marked shield: true routes all its edge nodes' misses to one designated shield node, chosen by consistent hashing over the zone id (Karger et al. 1997; bounded-load variant caps any node at (1 + ε) × average_load, ε = 0.25). The shield node holds its own L1/L2 tiers and is the only node permitted to open origin connections for that zone (I11). Ring structure:

Ring: BTreeMap<u64 /*hash*/, NodeId>, V virtual nodes/physical node (V=150)
placement(zone_id) = ring.range(hash(zone_id)..).next()  // first node CW
rebalance_cost(join/leave one node) ≈ K / N of keys move (K=virtual nodes)

Node join/leave moves ≈ 1/N of keys (N = physical nodes), not (N-1)/N as with modulo hashing (P8); this is the exact property Karger et al. prove and Maggs & Sitaraman (2015) apply to CDN placement.

8.5 Purge / Invalidation State Model

Purge kind Selector Propagation Ack model
By URL exact CacheKey direct fan-out to owning node (ring lookup) per-node ack, aggregate
By tag Tag → roaring-bitmap key set fan-out to all nodes holding ≥1 key with tag per-node ack, aggregate
Soft-purge marks entry stale (freshness_lifetime = 0), keeps bytes same as URL purge per-node ack
Full flush zone-wide broadcast to zone's node set per-node ack

Every purge carries a monotonic purge_seq per key; a node applies a purge only if purge_seq > entry.version's last-seen purge_seq, making purge idempotent under retry/replay and race-safe against a concurrent insert (I4, P14).

8.6 Worked Example — Fresh Hit → Stale → Revalidated

  1. GET /p/42 arrives; CacheKey = H(GET, example.com, /p/42, {}).
  2. L1 lookup hits; stored_at=T0, freshness_lifetime=60s; age=10s → Fresh (§8.2) → served, no origin contact, I1 holds.
  3. At age=65s a new GET /p/42 arrives → Stale-revalidate.
  4. Origin Fetch sends If-None-Match: "abc123" (from validators.etag).
  5. Origin returns 304 Not Modified → freshness lifetime reset, version incremented, body untouched → served from cache with fresh headers.

8.7 Malformed-Input Example

Request: GET /a/../../etc/passwd HTTP/1.1 with Host: example.com. Path-normalization (§8.1) resolves .. segments before hashing; result: /etc/passwd relative to root, which the HTTP Frontend rejects with 400 Bad Request because it escapes the configured document root prefix — the cache is never consulted, preventing a path-traversal cache poisoning entry from ever being created (T2, I2).

8.8 Failure-Path Example

Origin for zone z1 becomes unreachable (connect timeout ×3, ADR- retry policy). Circuit breaker (§17) opens after 5 consecutive 6 s buckets above 50% failure. A request for a stale CacheEntry with stale-if-error=300 arrives: Cache Semantics Engine (§8.2) serves the stale copy, tags the response Warning: 110, increments stale_if_error_serves_total, and does not attempt origin contact until the breaker half-opens (P12, I11).

Design principles (§6)

  • P1 — Cache key independence. The store keys on an opaque hash; HTTP semantics (§8) map requests to keys. Tradeoff: key-computation bugs are invisible to the store. Operational implication: key normalization is the single highest-leverage correctness surface (Phase 5). Violate it → cross-Vary cache poisoning (T2).
  • P2 — Tiered transparency. A hit at L1 or L2 is indistinguishable to the caller. Tradeoff: extra indirection per lookup (~50 ns). Violating it (leaking tier identity into response headers inconsistently) breaks client-observable caching behavior.
  • P3 — Coalesce before fan-out. Single-flight sits between the cache and the origin fetch, never bypassed. Tradeoff: "losers" of a collapse wait for the "winner." Violating it reintroduces thundering herd (I3).
  • P4 — Freshness is computed, never assumed. Every response's freshness lifetime is derived per RFC 9111 clause 4, not cached as a boolean. Tradeoff: a few extra CPU cycles per hit. Violating it silently serves stale-as-fresh (I1).
  • P5 — Admission gates eviction. TinyLFU decides whether to admit before LRU/S3-FIFO decides what to evict. Tradeoff: sketch memory overhead (~1 byte/entry). Violating it lets one-hit-wonders evict hot objects (I9).
  • P6 — Shield the origin. All miss traffic for a shielded zone funnels through one designated mid-tier node. Tradeoff: shield-node hot-spotting risk, mitigated by consistent hashing (P8). Violating it exposes origin to full edge-fleet miss fan-out.
  • P7 — Purge is async but SLA-bound. A purge call returns immediately; propagation is a background, monitored, timed operation. Tradeoff: there exists a (bounded) window where stale content is still served. Violating the bound breaches I5.
  • P8 — Placement via consistent hashing. Content-to-node mapping uses a hash ring with bounded load (Karger et al. 1997), not modulo hashing. Tradeoff: ring maintenance cost on membership change. Violating it (naive hash % N) causes full-cache invalidation on any node join/leave.
  • P9 — Backpressure over buffering. Every queue (origin-fetch pool, purge propagation, coalescing wait-list) is bounded; excess is rejected with a typed error, never silently dropped or unboundedly queued (I10). Tradeoff: callers must handle rejection.
  • P10 — Sandbox every trust boundary. Parser input, TLS termination, and (when enabled) edge-compute execution each run behind an explicit boundary with bounded resource limits. Violating it is how Cloudbleed- class bugs happen.
  • P11 — Observability is not optional. Every request carries a trace span and increments per-zone metrics; there is no "fast path that skips telemetry." Tradeoff: ~200 ns/request overhead, budgeted in §4.
  • P12 — Fail toward staleness, not toward errors. When origin is unreachable, prefer stale-if-error over a 5xx if a stale copy exists and the zone policy allows it. Tradeoff: a client may see slightly outdated content instead of an explicit failure.
  • P13 — TLS terminates at the edge, always. No cleartext pass-through mode exists. Tradeoff: every PoP must hold private key material (mitigated by per-cert on-disk encryption, ADR-24 region).
  • P14 — No silent data loss on eviction/purge race. A purge that races an in-flight insert must resolve deterministically via version numbers (I4), never "last write wins by accident."
