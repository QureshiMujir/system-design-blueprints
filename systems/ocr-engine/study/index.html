34. Mental Models & First Principles

The compressed insights an expert holds before touching the code. Each predicts behavior and names the bug class you write without it.

  • MM1 — Binarization is a windowed-statistics decision, and the integral image is what makes "windowed" free. A threshold is a per-pixel question "is this ink?", answered locally from a window's mean+std. Naïvely that is O(W·H·w²); the integral image (prefix-sum) collapses any window sum/mean/variance to four lookups, so adaptive thresholding costs the same as global. Predicts: Sauvola runtime is flat across window size (§13.4 fixture). Bug class without it: re-summing each window → quadratic blowup, or capping window size and losing illumination robustness. Applied: §13 (Phase 1), §4.1.
  • MM2 — Every stage is an invertible coordinate transform; the page is the one true frame. Decode, deskew, crop, normalize each warp coordinates; the engine is correct only if every output box rides the inverse chain back to source pixels. Hold the transforms, not just the pixels. Predicts: a box-overlay on the original scan lands to the pixel even after a 7° deskew (§14.4, §23.4). Bug class without it: text perfect, boxes silently drifting — invisible until someone overlays hOCR. Applied: §14, §16, §23 (I1, I15).
  • MM3 — A Future-like state machine: CTC is "sum over all the ways the labels could have been spoken." You have a line image and a target string but no per-pixel character boundary. CTC inserts a blank symbol and marginalizes over every monotonic alignment of labels to frames via a forward-backward DP — turning "unsegmented image → string" into one differentiable loss. Predicts: the model learns boundaries it was never given; repeated characters need a blank between them. Bug class without it: per-frame argmax with no blank semantics → dropped/duplicated characters. Applied: §20 (Phase 8), §8.4.
  • MM4 — Blank is not "no character"; it is the alignment-glue that makes the loss differentiable and the decode collapsible. The blank lets a character occupy many frames (collapse repeats) and separates genuine doubles ("ll"). Decode is: collapse adjacent equals, then strip blanks — order matters. Predicts: "hello" needs a blank between the two l-frames or it collapses to "helo". Bug class without it: the classic CTC off-by-one — allowing a blank-skip between identical labels. Applied: §20.6, §8.4, §8.7 (I5).
  • MM5 — Layout is a graph problem wearing an image costume. Connected components are nodes; RLSA/XY-cut induce regions; reading order is a topological sort of a geometric DAG. Once you see pixels as a CC graph, segmentation and reading order are graph algorithms, not heuristics. Predicts: reading order is provably a total order (irreflexive/transitive/complete), and cycles from overlapping blocks must be broken by a geometric key. Bug class without it: emitting a partial order → scrambled multi-column text, or a cycle → nontermination. Applied: §15 (Phase 3), §8.6 (I2).
  • MM6 — The recognizer is a weak sensor; the language model is the strong prior; decode is where they multiply. Pixels give a noisy per-frame posterior; the lexicon+LM give P(text) independent of pixels; Bayes says combine them. The LM is a separable, tunable beam term (α, β), never baked into the pixel model. Predicts: a noisy line's CER drops sharply once the LM is fused, and rises again if α is too high (over-correction). Bug class without it: hard-coding the dictionary into recognition → can't OCR OOV text or tune the prior. Applied: §21 (Phase 9), §8.5 (principle 6).
  • MM7 — Prefix-beam tracks two probabilities per hypothesis (blank-ending vs non-blank-ending), or it is wrong. Because collapse depends on whether the last emission was a blank, a CTC beam must carry (p_blank, p_nonblank) per prefix and merge them by the canonical recurrence. This is the single subtlest piece of the decoder. Predicts: getting the recurrence right makes beam=1 exactly equal greedy decode (§21.4). Bug class without it: plausible-looking beam search that quietly mis-scores repeats. Applied: §21.2, §21.6, §8.5.
  • MM8 — Segmentation-then-classify has an accuracy ceiling that no classifier can raise; segmentation-free does not. Classical OCR's error is bounded below by segmentation error — a perfect glyph classifier still fails on "rn" read as "m". CTC removes the boundary decision entirely, which is the reason it wins on touching/broken print. Predicts: classical line CER stays high (≤5%, segmentation-limited) even at 95%+ isolated-glyph accuracy; neural CER goes to ≤1%. Bug class without it: endlessly tuning the classifier to fix errors that live in the segmenter. Applied: §17/§18 vs §20, §4 (principle 4).
  • MM9 — A sequence model is only as good as the distribution it trained on; degradations are not optional garnish. A net trained on clean renders memorizes clean renders and dies on real scans. The synthetic generator must inject blur, noise, skew, ink-bleed, and JPEG artifacts so the training distribution covers the deployment one — and train/test font/text splits must be disjoint or CER lies. Predicts: augmentation ablation improves degraded-set CER; font leakage produces optimistic numbers that collapse in the field. Bug class without it: a model that benchmarks at 0.5% CER and produces garbage on the first real page. Applied: §22 (Phase 10).
  • MM10 — Without an independent oracle and per-stage telemetry, "the OCR is wrong" is undebuggable. Garbage text can come from any of seven stages. The only way to localize is exact synthetic ground truth + a mature differential oracle (Tesseract) + a PageTrace that records each stage's signal (skew angle, CC count, mean line confidence, beam stats). Predicts: you can point at "binarization polarity" vs "LM over-correction" from the trace alone. Bug class without it: opaque end-to-end failures, no regression net, accuracy silently rotting. Applied: §25 (Phase 13), §28 (I-suite, ADR-23).

Required reading (§5)

5.1 Books

  • Gonzalez & Woods, Digital Image Processing (4e) — ch.3 (intensity transforms, histogram → Otsu), ch.9 (morphology), ch.10 (segmentation, Hough, edges). The image-processing oracle. Applied: Otsu in Phase 1 (§13.2), morphological denoise in Phase 2 (§14.2), Hough deskew in §14.2.
  • Bishop, Pattern Recognition and Machine Learning — ch.4–5 (classifiers), ch.13 (sequential data, HMM/forward-backward — the conceptual parent of CTC). Applied: classical classifier framing in Phase 6 (§18.2); the HMM forward-backward is the direct ancestor of the CTC lattice in Phase 8 (§20.2, MM3).
  • Goodfellow, Bengio, Courville, Deep Learning — ch.9 (CNNs), ch.10 (RNN/LSTM, the CTC-adjacent sequence material). Applied: CNN encoder in Phase 7 (§19.2), BiLSTM in Phase 8 (§20.2).
  • Jurafsky & Martin, Speech and Language Processing (3e draft) — n-gram LMs, smoothing (backoff/Kneser-Ney), beam search, edit distance / MED. Applied: the entire lexicon+LM+beam decode in Phase 9 (§21.2, ADR-14); CER/WER edit-distance metric in §25 (shared with #388).
  • Cheriet, Kharma, Liu, Suen, Character Recognition Systems — the canonical OCR text: preprocessing, segmentation, feature extraction (zoning/HOG/profiles), classical classifiers. Applied: the classical path — segmentation Phase 5 (§17.2) and zoning/HOG features Phase 6 (§18.2).
  • Bunke & Wang (eds.), Handbook of Character Recognition and Document Image Analysis — page segmentation (RLSA, XY-cut), reading order, document structure. Applied: layout Phase 3 (§15.2) — RLSA, XY-cut, and reading-order construction (I2).
  • Manning, Raghavan, Schütze, Introduction to Information Retrieval — dictionaries (tries/DAWG), edit-distance correction, n-gram indexes. Applied: the lexicon DAWG + Levenshtein correction in Phase 9 (§21.2, ADR-15).
  • Szeliski, Computer Vision: Algorithms and Applications (2e) — feature detection/description, geometric transforms. Applied: the deskew affine + interpolation background for Phase 2 (§14.2, I15) and the receptive-field geometry of Phase 7 (§19.2).

5.2 Papers

  • Otsu, "A Threshold Selection Method from Gray-Level Histograms" (IEEE SMC 1979) — between-class-variance global thresholding. Applied: the Otsu baseline in Phase 1 (§13.2, §8.3, ADR-10).
  • Sauvola & Pietikäinen, "Adaptive document image binarization" (Pattern Recognition 2000) — the local-mean+std adaptive threshold; the document-binarization workhorse. Applied: the integral-image Sauvola in Phase 1 (§13.2, MM1, ADR-10).
  • Graves, Fernández, Gomez, Schmidhuber, "Connectionist Temporal Classification: Labelling Unsegmented Sequence Data with Recurrent Neural Networks" (ICML 2006) — the CTC paper: the blank label, the forward-backward over alignments, the loss and gradient. Applied: the recognizer's core in Phase 8 (§20.2, §8.4, I4/I5, MM3); shared with #388.
  • Shi, Bai, Yao, "An End-to-End Trainable Neural Network for Image-Based Sequence Recognition and Its Application to Scene Text Recognition (CRNN)" (TPAMI 2017) — CNN+BiLSTM+CTC for scene/printed text; the exact neural architecture mirrored here. Applied: Phases 7–9 (§19/§20/§21, ADR-9).
  • Breuel, "The OCRopus Open Source OCR System" (DRR 2008) & Breuel, Ul-Hasan, Al-Azawi, Shafait, "High-Performance OCR for Printed English and Fraktur using LSTM Networks" (ICDAR 2013) — LSTM+CTC line OCR. Applied: the per-line recognizer architecture (Phase 8, §20.2) and the synthetic-training recipe (Phase 10, §22.2).
  • Smith, "An Overview of the Tesseract OCR Engine" (ICDAR 2007) — line finding, classifier, dictionary; later LSTM engine. Applied: the differential oracle in Phase 13 (§25.2, ADR-23) and the line-finding model for Phases 3–4 (§15/§16).
  • Nagy, Seth, Viswanathan, "A Prototype Document Image Analysis System for Technical Journals" (IEEE Computer 1992) / the XY-cut lineage — recursive projection-profile page segmentation. Applied: XY-cut in Phase 3 (§15.2, §8.6, ADR-11).
  • Wong, Casey, Wahl, "Document Analysis System" (IBM J. Res. Dev. 1982) — RLSA (run-length smoothing) for region segmentation. Applied: RLSA in Phase 3 (§15.2, §8.6, ADR-11).
  • Dalal & Triggs, "Histograms of Oriented Gradients for Human Detection" (CVPR 2005) — HOG features. Applied: the classical-path descriptor in Phase 6 (§18.2).
  • Hannun, Case, Casper, Catanzaro, Diamos, Elsen, et al., "Deep Speech: Scaling up end-to-end speech recognition" (arXiv 2014) — CTC + LM beam-search decoding at scale. Applied: the decode-fusion design in Phase 9 (§21.2, ADR-13); shared with #388.
  • Breuel, "The hOCR Embedded OCR Workflow and Output Format" / the ALTO schema (Library of Congress) — the structured-output standards. Applied: output serialization in Phase 11 (§23.2, §5.4).

5.3 Reference Implementations

  • Tesseract (src/ccmain, src/textord line finding, src/lstm recognizer, src/dict) — the differential oracle + architecture source. Applied: the oracle in Phase 13 (§25.2, ADR-23); line-finding model for Phases 3–4 (§15/§16); dictionary reranking informs Phase 9 (§21). Study; don't copy (Apache-2.0; we re-derive in Rust). Pitfall: decades of accreted heuristics — extract the principles, not the special cases.
  • OCRopus / OCRopy & Kraken (ocrolib, kraken/lib) — clean CLSTM+CTC line OCR + synthetic training. Applied: line normalization (Phase 4, §16.2), the CTC training loop and per-line (not per-page) recognition (Phases 8, 10, §20/§22). Pitfall: Python glue around C — we keep it all in Rust.
  • Leptonica (src/binarize.c, src/conncomp.c, src/skew.c) — the C image library under Tesseract: Sauvola, connected components, deskew. Applied: integral-image binarization (Phase 1, §13.2), CC algorithms (Phase 3, §15.2 — via #389). Pitfall: raw-pointer C; we use #389.
  • OpenCV (modules/imgproc thresholding/morphology; modules/text OCR) — algorithm reference for the #389-facing ops. Applied: the reference for binarization/morphology in Phases 1–2 (§13/§14) and CC in Phase 3 (§15). Study; don't depend ("from scratch"). Pitfall: huge surface; we need a slice.
  • warp-ctc (Baidu Research) / the standard CTC implementations — the numerically-stable log-space forward-backward. Applied: the reference for the ctc crate in Phase 8 (§20.2, I4). Pitfall: GPU-centric; we do a clean CPU version.
  • CRNN reference repos (the bgshih/crnn Torch implementation and PyTorch/Keras ports) — the CNN+BiLSTM+CTC training recipe (augmentation, LR schedule, validation CER). Applied: the synthetic-data + early-stop loop in Phase 10 (§22.2).

Glossary (§40) · 44 terms · site-wide glossary

ALTO
Analyzed Layout and Text Object; LoC XML schema for OCR output (layout + text + coordinates).
Attention / seq2seq recognizer
an encoder–decoder recognizer that learns alignment as attention and decodes characters autoregressively; the deferred alternative to CTC (§38.3, §39.8).
Baseline
the line on which characters sit; reference for line normalization.
Beam width (B)
the number of hypotheses retained per step in prefix-beam decode; the latency/accuracy knob (default 32, ADR-13).
Binarization
converting grayscale to bilevel (ink/background).
Blank (CTC)
the special label ⊘ separating/absorbing frames; enables alignment-free training.
Bounding box (bbox)
axis-aligned rectangle locating a region in the page frame.
Calibration (confidence)
the property that predicted confidence matches observed error rate; gated so downstream can triage (principle 9, I10).
CC (connected component)
maximal set of connected foreground pixels; the atom of layout.
CER / WER
Character / Word Error Rate = edit distance ÷ reference length.
CRNN
CNN + RNN (BiLSTM) + CTC — the end-to-end image-sequence recognizer.
CTC
Connectionist Temporal Classification; alignment-free sequence loss via blank-augmented forward-backward.
DAWG
Directed Acyclic Word Graph; compact prefix+suffix-shared dictionary.
Deskew
rotating a page to make text horizontal.
Edit distance (Levenshtein)
minimum insert/delete/substitute operations between two strings; basis of CER/WER and DAWG correction.
Forward-backward
the DP computing alignment marginals (α, β) over the CTC label lattice.
im2col
unrolling convolution windows into columns so a convolution becomes a single GEMM (via #349); the CNN-encode hot path (§19, §32).
hOCR
HTML microformat embedding OCR layout + text + confidence.
HOG
Histogram of Oriented Gradients; a classical glyph feature.
Integral image
prefix-sum image enabling O(1) window sum/mean/variance.
Kneser-Ney
an n-gram smoothing method using continuation counts; the LM smoothing of choice (ADR-14).
Lexicon
dictionary of valid words used to constrain/rerank decoding.
n-gram LM
language model of order n with backoff/Kneser-Ney smoothing.
Niblack
a local-mean+std binarization threshold (m + k·s); precursor to Sauvola, kept as a variant.
NMS
non-maximum suppression (edge/feature thinning; from #389).
Otsu
global threshold maximizing between-class variance.
Perplexity
the exponentiated per-symbol cross-entropy of an LM; lower = better predictive prior (§21).
Posteriors
per-frame probability distribution over alphabet+blank.
Prefix-beam search
CTC-aware beam decoding maintaining blank/non-blank prefix probabilities.
Receptive field
the input-pixel extent a CNN output frame depends on; the map from frame index to x-range for glyph-box back-projection (§19, I1).
Projection profile
row/column ink-sum histogram used for line/block segmentation.
Reading order
the total order in which blocks/lines should be read (multi-column aware).
RLSA
Run-Length Smoothing Algorithm; bridges background runs to form regions.
Sauvola
adaptive local-mean+std binarization threshold.
Scene text
text in photographs/signs/labels (vs scanned documents); the regime of the deferred detector-first architecture (§38.4).
Seam carving
finding a min-energy path between text rows to split slightly-touching/curved lines (§16).
Skew
the rotation angle of text relative to horizontal.
Structuring element
the shape used in morphological operations (from #389).
Text detector (CRAFT/DB)
a learned model that outputs text region boxes directly from a raw image, replacing classical layout in scene-text pipelines (§38.4).
Voronoi segmentation
page segmentation by merging CC-centroid Voronoi regions; the XY-cut fallback for non-Manhattan layouts (§15).
Wolf
a Sauvola variant normalized by global min and max contrast.
x-height
height of lowercase letters without ascenders; a normalization reference.
XY-cut
recursive page segmentation by projection-profile valleys.
Zoning
grid-cell ink-density glyph feature.
