⬜ Phase 0 — Skeleton: image core, page tree, I/O, harness + synthetic renderer + oracle §12

Objectives
  • Cargo workspace (ADR-2) with ocr-core/imageio/conformance skeletons; wire #389/#385/#112/#349/#173/#372 deps.
  • Define Image<T>, ImageView, geometry, the Page tree, the typed stage handles (I9), seeded Rng.
  • Ship one trivial end-to-end path (decode → fixed-threshold binarize → whole-page "one line" → null recognizer) to prove the harness.
  • Stand up the synthetic-line generator (#385 render) + the differential scaffolding every later phase reuses.
Deliverable
  • ocrc recognize page.pgm --engine null runs decode→binarize(fixed)→layout(whole-page)→null-recognizer→empty/echo text.
  • cargo test runs image/geom/page/stage/rng unit tests + synthetic renderer round-trip (rendered boxes ⊆ image).
Acceptance
  • Image ROI is zero-copy (alias check); Rect::contains/union correct; overflow-checked (I13).
  • Rng identical stream per seed across reruns (I7 golden test).
  • Stage types enforce ordering at compile time (I9) — a test that skips binarize fails to compile (doc-tested).
  • Synthetic renderer (#385) emits transcription + boxes that round-trip (boxes ⊆ image dims, I1); Miri clean.
Fixtures
  • synth_groundtruth/hello_world_arial12 (rendered + transcription + boxes); ocr-core/rect_ops, rng_stream_seed{1,2}, roi_zero_copy.
Pitfalls
  • Global/implicit RNG → non-reproducibility (I7); thread Rng explicitly.
  • ROI that copies → memory blowup on large pages; keep views borrowing (principle 12).
  • Confusing image stride with width (padded rows) → diagonal-shear bug in every pixel loop; test on a non-stride==w image.
  • Box coordinate frame ambiguity (line-local vs page) — fix top-left/page-pixels convention now (I1), or every later stage drifts.

⬜ Phase 1 — Binarization (Otsu global + Sauvola adaptive, integral images) §13

Objectives
  • Global Otsu (histogram between-class variance) and adaptive Sauvola/Niblack/Wolf via integral images (O(W·H), window-size-independent).
  • Polarity detection (white-on-black → normalize); idempotence (I8).
  • The BinaryImage stage every later stage consumes.
Deliverable
  • binarize green vs synthetic ground truth + Leptonica/Tesseract-binarized golden; ocrc binarize CLI.
Acceptance
  • Sauvola is O(W·H) — runtime flat across window sizes (the integral-image win, §4).
  • Otsu threshold matches a reference within ±1 gray level on golden histograms.
  • Idempotent: bin(bin(x))==bin(x) (I8 fixture).
  • On uneven-illumination synthetic pages, Sauvola CER (downstream) ≪ Otsu CER (documents the adaptive win).
Fixtures
  • binarize/{otsu_bimodal,sauvola_gradient_illum,niblack,wolf,polarity_invert,idempotent}; golden/sauvola_window_invariance (runtime flat).
Pitfalls
  • Integral-image overflow (sum of u8 over megapixels) → use u64 (I13).
  • sqsum precision for variance (catastrophic cancellation) → compute s² = E[x²]−E[x]² carefully; clamp negatives to 0.
  • Sauvola k/window/R defaults differ by source — pin Sauvola's (k≈0.34, R=128), document.
  • Edge windows (partial near borders) — clamp the rectangle, not the index (off-image reads).
  • Global Otsu on unimodal histograms (blank page) → degenerate threshold; guard (treat as all-background).

⬜ Phase 2 — Preprocessing (denoise, deskew, normalize) §14

Objectives
  • Denoise (median / small Gaussian / morphological open via #389); deskew to ±0.1° (projection-variance argmax / Hough via #389); contrast + height normalization; border/margin removal.
  • Record the invertible T_deskew affine (I15) so output boxes map to source pixels (I1).
Deliverable
  • preprocess green; deskew within ±0.1° on synthetic rotated pages; boxes round-trip through T_deskew⁻¹ (I15).
Acceptance
  • Deskew error ≤ 0.1° on synthetic ±10° rotations (§4).
  • T_deskew invertible: a box rotated then inverse-rotated returns within 1 px (I15 fixture).
  • Denoise removes ≥ 95% of injected salt-and-pepper without breaking strokes (stroke-continuity check).
  • Border removal crops margins without clipping text (containment check).
Fixtures
  • preprocess/{deskew_+5deg,deskew_-8deg,deskew_refine_0p1,denoise_saltpepper,border_crop}, transform_roundtrip (I15).
Pitfalls
  • Deskew on sparse pages (few text rows) → flat profile, ambiguous angle → fall back to Hough or skip with LargeSkew.
  • Rotation interpolation blurs edges → bilinear on the grayscale, re-binarize after (order: deskew grayscale → binarize, or binarize → rotate bilevel with care).
  • Forgetting to apply T_deskew to output boxes → text correct, boxes wrong (I1 violation) — the round-trip fixture guards it.
  • Over-aggressive morphological open erases periods/dots/thin strokes → size the structuring element to stroke width.
  • Border detection eating drop-caps or full-bleed images → constrain to near-edge dark runs.

⬜ Phase 3 — Layout analysis (connected components, RLSA, XY-cut, reading order) §15

Objectives
  • Connected components (#389 union-find) → component graph; RLSA bridge; XY-cut/Voronoi → blocks; block classification (text/non-text); reading-order total order (I2).
  • Produce the AnalyzedPage the line detector consumes.
Deliverable
  • layout green vs synthetic multi-column pages (known block boxes + order) + Tesseract layout golden.
Acceptance
  • CC count + boxes match #389 reference exactly.
  • Block segmentation IoU ≥ 0.9 vs synthetic ground-truth blocks.
  • Reading order is a verified total order (irreflexive/transitive/complete, I2) and matches the rendered order on 2-column fixtures.
  • Text/non-text classification ≥ 95% on the synthetic set.
Fixtures
  • layout/{cc_count,rlsa_bridge,xycut_2col,xycut_nested,reading_order_2col,classify_text_vs_image}; golden/reading_order_total (order axioms).
Pitfalls
  • RLSA thresholds (horizontal ≫ vertical) are font/DPI-dependent → derive from estimated stroke/line height, not constants.
  • XY-cut fails on non-Manhattan layouts (overlapping columns) → Voronoi fallback; document the limitation.
  • Reading-order cycles from overlapping blocks (I2) → break by geometric key, never emit a cycle.
  • Merging a figure caption into the figure block → classification + gap tuning.
  • 8- vs 4-connectivity changes CC count (diagonal touches) — pin 8-connectivity, match #389.

⬜ Phase 4 — Text-line detection + baseline + x-height §16

Objectives
  • Within each text block: detect text lines (smoothed horizontal projection valleys / seam carving); estimate baseline + x-height; extract line polygons; emit ordered Lines with boxes.
  • Produce the normalized LineImages the recognizer consumes (fixed height H).
Deliverable
  • lines green vs synthetic (known line boxes + baselines); ordered lines feed the recognizer.
Acceptance
  • Line-box IoU ≥ 0.9 vs ground truth; line count exact on clean synthetic.
  • Baseline within ±1 px; x-height within ±10% (drives normalization quality).
  • Lines ordered top-to-bottom within block; merged with block order → page line order.
  • Normalized LineImage height == H exactly; aspect preserved.
Fixtures
  • lines/{projection_simple,touching_lines_seam,baseline_fit,xheight_estimate,line_order}; synth_groundtruth/multi_line_para.
Pitfalls
  • Ascenders/descenders bridging lines → projection valleys shallow → seam carving or CC-overlap resolution.
  • Wrong x-height → recognizer normalization off → CER spike; validate against rendered metrics.
  • Diacritics/dots assigned to the wrong line → assign by vertical overlap with the baseline band.
  • Very tight leading (line spacing) → under-segmentation → adaptive threshold from line-height estimate.

⬜ Phase 5 — Classical word & character segmentation (the classical path) §17

Objectives
  • Word segmentation by inter-CC gap analysis; character over-segmentation + merge search for the classical recognizer (touching/broken glyphs).
  • This path exists for contrast/interpretability; the neural path (P7–P9) skips it (CTC is segmentation-free, principle 4).
Deliverable
  • segment green vs synthetic (known word/char boxes); feeds P6 classical recognizer.
Acceptance
  • Word-boundary F1 ≥ 0.95 on clean synthetic; character boxes IoU ≥ 0.85.
  • Merge search recovers touching "rn"→"r","n" and split "i"→dot+stem on fixtures.
  • Segmentation is deterministic given the classifier + seed (I7).
Fixtures
  • segment/{word_gaps_bimodal,char_overseg,merge_touching_rn,merge_broken_i,seg_determinism}.
Pitfalls
  • Proportional fonts: intra-word gaps ≈ inter-word → bimodal split unreliable → use the recognizer in the loop (joint seg-recognition).
  • Italic/overlapping glyphs → vertical projection misses the cut → contour/slant-aware cuts.
  • Over-segmentation explosion → bound piece count, prune merge search (beam).
  • Touching characters are the classical path's Achilles heel — the headline reason the neural path exists (document it).

⬜ Phase 6 — Classical features + glyph classifier (zoning/HOG + kNN/SVM via #372) §18

Objectives
  • Glyph features: zoning (cell ink density), HOG, projection/contour profiles, normalized bitmap.
  • Train a kNN/SVM glyph classifier (#372); produce the first end-to-end recognized text (classical engine).
Deliverable
  • ClassicalRecognizer green: segmented page → recognized text; examples/recognize_png --engine classical.
Acceptance
  • Per-glyph accuracy ≥ 95% on clean isolated synthetic glyphs.
  • Whole-line classical CER ≤ 5% on well-segmented clean print (§4) — segmentation-limited, documented.
  • Features match a hand-computed reference (zoning densities, HOG bins) within rtol=1e-5.
  • Confidence calibrated (high-conf glyphs error-rate ≪ low-conf).
Fixtures
  • features/{zoning,hog,profiles} (vs hand-computed); recognizer/{classical_isolated_glyphs,classical_line_cer}.
Pitfalls
  • Feature scale mismatch → SVM dominated by one feature → standardize (#372 scaler) before fit.
  • kNN on raw bitmaps is slow + brittle to shift → normalize centroid; prefer zoning/HOG.
  • Confusable pairs (O/0, l/1/I, rn/m) → the classical confusion set; report a confusion matrix.
  • Training/serving feature-extraction skew → share one code path (principle: same extractor at fit and predict).

⬜ Phase 7 — Neural recognizer: CNN feature extractor (#112/#349) §19

Objectives
  • CNN that maps a normalized LineImage (height H, variable width W) to a downsampled feature sequence (T × C), the input to the BiLSTM+CTC head (P8).
  • Built on #112 autograd (forward+backward) + #349 convolution-as-GEMM (im2col).
Deliverable
  • CNN forward/backward green vs #112 finite-difference gradient checks; emits a T×C sequence.
Acceptance
  • Gradients match #112 finite-difference within 1e-4 (the autograd contract).
  • Output T is a deterministic function of W and the stride (documented receptive-field map).
  • Forward uses #349 GEMM (near-peak); no private convolution (principle 11).
  • Memory bounded O(H·W·C) per line; freed after the sequence is produced.
Fixtures
  • recognizer/{cnn_grad_finite_diff,cnn_output_shape,cnn_receptive_field_map}.
Pitfalls
  • Height not reduced to exactly 1 (padding/stride arithmetic) → wrong sequence shape; pin the stack arithmetic.
  • im2col memory blowup for wide lines → tile the width; reuse #349 buffers.
  • Receptive-field/x-coordinate map off → glyph boxes wrong (I1) even when text is right.
  • Forgetting eval-mode (batch-norm/dropout) at inference → train/serve skew.

⬜ Phase 8 — Sequence model: BiLSTM + CTC loss (forward-backward) §20

Objectives
  • BiLSTM over the CNN feature sequence (bidirectional context) → linear → softmax → T×(|A|+1) posteriors (I4).
  • CTC loss: blank-augmented forward-backward (log-space), gradient to #112 (I5) — the alignment-free training objective.
Deliverable
  • BiLSTM+CTC forward/backward green; CTC gradient matches finite-difference; greedy decode on a tiny overfit set recovers the label.
Acceptance
  • CTC loss + gradient match finite-difference within 1e-4 (I5) on small random cases.
  • Forward prob == backward prob (α_T == Σβ) within ε (consistency).
  • Posteriors are valid distributions per frame (I4); log-space stable (no NaN on long T).
  • Overfit test: a single line trained to ~0 loss decodes to its exact label (sanity).
Fixtures
  • ctc/{forward_backward_small,grad_finite_diff,alpha_beta_consistency,greedy_collapse,logspace_stable_longT}; recognizer/bilstm_grad.
Pitfalls
  • Not working in log-space → underflow on long sequences → NaN loss; log-sum-exp everywhere (I4).
  • Off-by-one in the 2|l|+1 lattice (blank between every label + ends) → wrong loss; test against a hand-computed 2–3 char case.
  • Label longer than T (more characters than frames) → infeasible alignment, loss=∞ → guard + report (data/normalization bug).
  • Allowed transitions: skip a blank only between distinct labels (not repeated) — the classic CTC bug.
  • Greedy collapse order (collapse-then-strip vs strip-then-collapse) must match the canonical definition (I5).

⬜ Phase 9 — Decoding: greedy + prefix-beam + lexicon + n-gram LM fusion §21

Objectives
  • Prefix-beam decode fusing CTC posteriors + lexicon (DAWG) + char/word n-gram LM (the LM-rescue, principle 6).
  • Edit-distance dictionary correction; word lattice + per-word confidence (I10).
Deliverable
  • LM-fused beam green; examples/recognize_png --engine neural produces dictionary-corrected text; CER drop vs greedy measured.
Acceptance
  • Beam + LM yields ≥ 30% relative WER reduction vs no-LM greedy on noisy synthetic lines (§4).
  • Beam=1 (no LM) == greedy decode (consistency).
  • Edit-distance correction fixes single-character errors to in-dictionary words on fixtures.
  • Determinism: identical text per (seed, beam, model) including tie-breaks (I5/I7).
Fixtures
  • lexicon/{dawg_contains,edit_distance_k1,kneser_ney_perplexity}; decode/{beam_eq_greedy_at_b1,lm_wer_reduction,beam_determinism,oov_allowed}.
Pitfalls
  • Over-correction: a strong LM rewrites correct rare/OOV words → tune α, allow OOV at a penalty (principle 6), never forbid non-dictionary paths.
  • Prefix-beam merge of p_blank/p_nonblank is subtle — follow the canonical recurrence exactly (the common CTC-beam bug).
  • LM weight α / word bonus β untuned → garbage; tune on a dev set, document defaults.
  • Kneser-Ney implementation errors (discounting, continuation counts) → wrong perplexity; test vs a hand-computed small corpus.
  • Beam too small → search errors; too large → slow; default B=32, expose it.

⬜ Phase 10 — Training pipeline (synthetic line generation #385 + CTC SGD #112) §22

Objectives
  • Synthetic-line generator: render text (corpus-sampled) via #385 at varied fonts/sizes + degradations → (LineImage, transcription); CTC training loop on #112 (optimizer, LR schedule, validation-CER early stop); augmentation.
  • Reach the §4 CER target on clean synthetic print (the recognizer's reason to exist).
Deliverable
  • ocrc train --synth trains a neural recognizer to the CER target; checkpoints a versioned model.
Acceptance
  • Trained neural CER ≤ 1% on clean synthetic print (§4); ≤ target on degraded sets (documented curve).
  • Training is reproducible per seed (I7): same data order + init ⇒ same final CER (within noise).
  • Validation-CER early stop prevents overfit (train vs val gap monitored).
  • Augmentation improves degraded-set CER vs no-augmentation (ablation fixture).
Fixtures
  • train/{synth_render_matches_transcription,degrade_reproducible,ctc_train_overfit_small,augment_ablation}; golden/train_determinism_seed.
Pitfalls
  • Train/test font or degradation leakage → optimistic CER → disjoint font/text splits.
  • Synthetic-real gap: a model trained only on clean renders fails on real scans → degradations are essential; real-corpus fine-tune deferred (§39.6).
  • LR too high → CTC diverges (loss→∞/NaN); warmup + gradient clipping.
  • Label/image length mismatch (label longer than T) from over-aggressive normalization → filter or re-normalize.
  • Class imbalance (rare glyphs) → sample text to cover the alphabet.

⬜ Phase 11 — Output formats (hOCR / ALTO / text / JSON) + confidence + reading order §23

Objectives
  • Serialize the RecognizedPage to plain text (reading order), hOCR (HTML), ALTO (XML), JSON — all with bbox + confidence in the source-image frame (I1).
Deliverable
  • All four formats green; hOCR/ALTO validate against their schemas; round-trip JSON→Page→JSON.
Acceptance
  • hOCR/ALTO are schema-valid and open in standard viewers; boxes overlay correctly on the source image (I1).
  • x_wconf/WC ∈ [0,100]/[0,1] (I10); reading order matches the page line order (I2).
  • JSON round-trips losslessly; plain text matches the rendered reading order on synthetic pages.
Fixtures
  • output/{hocr_valid,alto_valid,text_reading_order,json_roundtrip,bbox_in_source_frame}.
Pitfalls
  • Box coordinate frame: hOCR expects source-image pixels — apply T_deskew⁻¹/crop-offset before emitting (I1/I15); the overlay fixture guards it.
  • hOCR x_wconf is 0–100; ALTO WC is 0–1 — don't mix scales.
  • Word spacing/line breaks from geometry, not guessed; reproduce paragraph structure from blocks.
  • XML/HTML escaping of recognized text (<, &) — escape, or emit invalid markup.

⬜ Phase 12 — Serialization + C ABI + performance hardening §24

Objectives
  • Versioned model serialization (weights + alphabet + meta) with round-trip (I14); stable C ABI (ocr_*) with opaque handles + result-tree accessors; meet §4 latency/throughput targets.
Deliverable
  • C example (examples/ocr_from_c.c) links libocr, recognizes an image, walks the result tree; latency/throughput meet §4.
Acceptance
  • Model round-trips: load(save(m)).recognize == m.recognize within CER tol (I14).
  • No unwinding across FFI (catch_unwind test); bad args → negative code, no compute (I12).
  • §4 throughput (≥1 page/s, ≥0.8× scaling) + per-line latency (≤30 ms) met (bench-gated); zero steady-state alloc in the recognition hot loop.
Fixtures
  • serialization/roundtrip_{neural,classical} (I14); cabi/{c_integration,bad_param_codes,result_tree_walk}; golden/no_alloc_in_recognize.
Pitfalls
  • Model/alphabet drift between versions → IncompatibleVersion on load; never silently mis-decode (I14).
  • Panic across FFI = UB → catch_unwind everywhere.
  • Result-tree lifetime (caller frees via ocr_free, not free) — document ownership; tag handles.
  • Float weight serialization must be exact bit round-trip (canonical encoding, not text).
  • Image stride at the ABI (caller's row padding) — honor the passed stride, don't assume stride==w.

⬜ Phase 13 — Conformance (vs Tesseract), fuzzing, benchmarks (CER/WER) §25

Objectives
  • Lock correctness with synthetic ground-truth + a Tesseract differential suite + pipeline-invariant asserts; fuzz the image/decode/model paths; benchmark throughput/latency + CER/WER reproducibly.
  • Define "Phase-0 done" for the future coding contract.
Deliverable
  • make conformance green; make bench emits a report; make fuzz runs N iterations clean.
Acceptance
  • Synthetic CER ≤ §4 targets; Tesseract differential within ±2% absolute CER on clean print.
  • All invariants (I1–I15) asserted and green.
  • Fuzz clean ≥ 10⁷ iterations/target (30-day canaries deferred); bench meets §4 (throughput, latency, LM-WER-reduction).
  • Determinism hashes stable across reruns.
Fixtures
  • Full conformance/ corpora (binarize/ … output/); synth_groundtruth/ (fonts × sizes × degradations); tesseract_golden/ (pinned version); golden/ determinism hashes.
Pitfalls
  • CER tolerance too tight (false fails on legit float-order CNN differences) or too loose (misses regressions) — derive per-engine from theory + observed variance.
  • Tesseract version drift changes golden CER → pin the version, regenerate deliberately, version the fixtures.
  • Fuzz not hitting edge images (1-px, blank, inverted, huge) — seed the corpus.
  • Determinism hash breaks on a legit numeric-behavior change → version the golden set with the contract (ADR-32).
  • Bench noise (turbo, neighbors) → pin governor, median-of-k.
