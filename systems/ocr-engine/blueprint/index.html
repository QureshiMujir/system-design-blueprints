387 — OCR Engine from Scratch

Goal: Implement, from scratch in Rust, an end-to-end optical character recognition engine: a raster page image enters, structured text exits (UTF-8 + per-glyph bounding boxes + confidence, as plain text / hOCR / ALTO). The pipeline is the spine: image I/O → binarization → preprocessing (denoise/deskew/normalize) → layout analysis (connected components, page segmentation, reading order) → line detection → recognition → linguistic post-processing (lexicon + n-gram LM beam search) → structured output. The recognizer ships in two interchangeable engines behind one trait: a classical glyph path (segmentation → zoning/HOG features → kNN/SVM via #372) and a neural line path (CNN feature extractor + BiLSTM + CTC, trained on synthetic lines rendered via #385). Crates: ocr-core / imageio / binarize / preprocess / layout / lines / segment / features / recognizer / ctc / lexicon / decode / output / train / cabi / bench / conformance. It is a document-recognition system modeling Tesseract (LSTM line recognizer + layout), OCRopus/ Kraken (CLSTM+CTC), and the classical zoning/HMM era — not a CV-primitive library (#389, a dependency), not a font rasterizer (#385, a dependency), not an autograd framework (#112, a dependency), not a generic image codec (#173, a dependency). Correctness is validated by differential CER/WER against Tesseract on golden fixtures, by synthetic ground-truth (text rendered by #385 with known transcription + boxes), by pipeline invariants (bbox containment, reading order totality, CTC blank-collapse determinism), and by deterministic-seed reproducibility; performance by pages/second throughput and recognition latency vs image size.

1. Goal

1.1 Engineering Definition

From-scratch OCR engine: decode image (#173) → Image<Gray8> → binarize (Otsu/Sauvola) → preprocess (denoise/deskew/normalize) → layout (connected components → blocks → reading order) → segment lines → recognize each line (classical glyph classifier OR neural CNN+BiLSTM+CTC) → post-process (lexicon + char/word n-gram LM beam search) → emit Page tree (blocks/lines/words/glyphs + bbox + confidence) serialized to text/hOCR/ALTO/JSON. Image ops (convolution, Sobel, morphology, Hough, connected components) come from #389; neural training from #112; matrix ops from #349; synthetic training corpus rendered by #385.

1.2 System Boundaries

  • In scope: grayscale/binary document images; global + adaptive binarization; denoise/deskew/normalize; connected-component analysis; RLSA + XY-cut page segmentation; block classification (text/non-text); reading-order detection; text-line detection + baseline; word/character segmentation (classical path); classical features (zoning/HOG/profiles) + kNN/SVM glyph classifier (#372); neural line recognizer (CNN encoder + BiLSTM + CTC, trained via #112); CTC loss + greedy/beam decode; pronunciation-free lexicon (trie/DAWG) + edit-distance correction + char/word n-gram LM; LM-fused beam search; confidence calibration; hOCR/ALTO/text/JSON output; synthetic-line training-data generator (#385 + degradations); model serialization; C ABI; CLI.
  • Out of scope (non-goals): CV primitives (convolution/edge/Hough/morphology) → #389 (dependency); font rasterization → #385 (dependency); image codecs (PNG/JPEG decode) → #173 (dependency); autograd/backprop → #112 (dependency); dense linear algebra → #349 (dependency); GPU training/inference → PhaseDeferred("§39.2"); page dewarping / camera-capture rectification → PhaseDeferred("§39.3"); table-structure recognition → PhaseDeferred("§39.4"); full multi-script/RTL/CJK shaping (Latin + digits + punctuation Phase-0; #398 shaping for the rest) → PhaseDeferred("§39.5"); cursive Arabic/Indic → PhaseDeferred("§39.5"); attention/transformer recognizer (CTC only Phase-0) → PhaseDeferred("§39.8"); mathematical-formula / music OCR → PhaseDeferred("§39.7"); real-corpus (IAM/ICDAR) training → PhaseDeferred("§39.6").

1.3 Deployment Model

Shipped as (a) Rust library crate (ocr facade), (b) cdylib/staticlib C ABI (ocr_*) for C/C++/Python-ctypes callers, (c) CLI ocrc (recognize/binarize/layout/train/eval/bench over image files → text/hOCR/ALTO/JSON). Single process, in-memory pages, shared-memory thread pool (per-line parallel recognition). No service, no persistence beyond model files + output documents.

1.4 Target Users

Engineers who want to understand why Sauvola beats global thresholding on uneven illumination, how connected components become a reading order, what CTC actually aligns, why a language model rescues a noisy recognizer; downstream consumers (a document-indexing pipeline feeding #177 inverted index; a PDF text layer for #386).

1.9 Recommended Language & Rationale

Rust. (a) reuse the same-batch #389 (convolution, Sobel, Canny, Hough, morphology, connected components — the entire image-op substrate), #385 (TrueType rasterizer → synthetic training pages), #112 (autograd → CNN/BiLSTM/CTC training), #349 (BLAS → CNN GEMM + SVM Gram), #173 (image codec → input decode), #372 (kNN/SVM glyph classifier); (b) ownership makes the staged pipeline (Image → Binary → Page → Lines → Text) a compile-checkable state machine — you cannot recognize before you segment; (c) zero-cost pixel loops (binarization, CC labeling) + a tight CTC forward-backward hot loop, no GC pauses mid-page; (d) extern "C" clean engine ABI; (e) Send+Sync → per-line parallel recognition for free. Rejected: C++ (Tesseract/OCRopus's language — studied as the oracle; rejected for ABI instability, weaker ownership over the multi-stage buffer lifecycle, harder differential-test tooling); Python (the research-prototyping language — but its hot loops are C/Cython and "from scratch" forbids leaning on OpenCV/NumPy); Go (weaker numeric generics/SIMD for the pixel and GEMM loops); Julia (calls LAPACK/OpenCV — defeats "from scratch").

1.10 Prerequisites

Image processing (convolution, morphology, thresholding, connected components — from #389); linear algebra (PCA whitening, SVM Gram, CNN GEMM — #349); probability/statistics (Otsu variance, GMM-free here, n-gram LM); machine learning (kNN/SVM #372, gradient descent #112); sequence modeling (CTC alignment, beam search, edit distance); information theory (entropy, perplexity); concurrency (per-line/per-block parallel map). Helpful: #389 (CV primitives), #385 (fonts), #112 (autograd), #388 (ASR — shares CTC/beam/LM/edit-distance), #177 (inverted index — downstream).

2. Why Build This

2.1 Unique Knowledge Taught

  • The document-image pipeline is a contract of coordinate frames. Every stage maps pixels → regions → lines → glyphs → characters while preserving bounding-box provenance; a single off-by-one in a crop propagates to garbage text. OCR teaches disciplined coordinate bookkeeping.
  • Adaptive binarization vs illumination. Why a single global threshold (Otsu) fails on shadows/gradients and why Sauvola's local mean+std window (with integral-image O(1) stats) is the workhorse.
  • Connected components as the atom of layout. Union-find labeling → component graph → RLSA/XY-cut segmentation → reading order. The same CC primitive underlies text-line grouping and noise removal.
  • Alignment-free sequence learning (CTC). The central idea: you have an image of a word but no per-pixel character boundary; CTC marginalizes over all alignments via a blank-augmented forward-backward, turning "unsegmented line → string" into a differentiable loss. This is the single most transferable concept (shared with #388 ASR).
  • The language model rescues the pixel model. A noisy per-frame posterior + a lexicon + an n-gram LM, fused in beam search, dramatically cuts CER — the canonical "weak sensor + strong prior" architecture.
  • Classical vs neural, side by side. Zoning/HOG + kNN/SVM (interpretable, segmentation-dependent, brittle to touching characters) vs CNN+BiLSTM+CTC (segmentation-free, robust, data-hungry) — built in one engine so the tradeoff is concrete.

2.2 Why It Matters

OCR is one of the oldest applied-AI problems (Tausheck 1929, Tesseract at HP 1985→Google) and still the backbone of digitization, document search, accessibility, and the text layer of every scanned PDF. Tesseract, OCRopus/Kraken, and the ICDAR competition lineage define the field. The pipeline exercises the full arc from signal (pixels) to symbol (text) with a probabilistic decoder — the same shape as ASR, MT, and handwriting recognition.

2.3 Engineering Muscles

Pixel-level performance (cache-friendly row scans, integral images); graph algorithms (union-find CC, reading-order DAG); dynamic programming (CTC forward-backward, edit distance, Viterbi-style beam); numerical optimization (CNN training via #112); search under a probabilistic model (LM-fused beam); differential testing vs a mature reference (Tesseract); deterministic reproducibility; staged-pipeline API design.

2.4 Production Concepts Exercised

Throughput/latency budgets (pages/s, ms/line); model versioning + serialization; confidence calibration (knowing when the OCR is unsure); reading-order correctness (an accessibility/search requirement); structured output standards (hOCR/ALTO interchange); reproducible training; degradation-aware data augmentation; graceful failure on blank/garbage pages.

Read Tesseract's ccmain/lstm and Kraken's CLSTM and explain every stage — why baseline finding precedes recognition, what the LSTM's CTC head emits, how the dictionary reranks — and reason about why a page yields garbage (binarization? skew? segmentation? LM?), not just call an API.

2.7 What Mastery Looks Like

After building this, the engineer holds these named competencies — each earned in a specific phase, not in the abstract:

  • Document-image binarization under real illumination — derive Otsu's between-class-variance threshold and Sauvola's local mean+std rule, and explain via integral images why adaptive thresholding stays O(W·H) regardless of window size (Phase 1, §13; MM1).
  • Layout as a connected-component graph — turn a bilevel page into a labeled CC set, bridge it with RLSA, cut it with XY-cut, and prove the emitted reading order is a total order, not a heuristic guess (Phase 3, §15; I2, MM5).
  • The alignment-free recognition contract (CTC) — derive the blank-augmented forward-backward, the loss −log Σ_{π:B(π)=l} ∏ y_t(π_t), and its gradient; explain exactly what CTC marginalizes and where its conditional-independence assumption breaks (Phase 8, §20; MM3, MM4).
  • Weak-sensor + strong-prior decoding — fuse a noisy per-frame posterior with a DAWG lexicon and an n-gram LM in prefix-beam search, and tune α/β to cut WER without over-correcting OOV words (Phase 9, §21; MM6, MM7).
  • Coordinate-frame provenance end-to-end — carry every bbox back through the invertible deskew/crop/normalize transforms to source pixels, so hOCR boxes overlay the original scan to the pixel (Phases 2, 11, §14/§23; I1, I15, MM2).
  • Classical-vs-neural tradeoff, concretely — quantify why zoning/HOG + kNN/SVM is segmentation-limited (capped CER on touching glyphs) while CNN+BiLSTM+CTC is segmentation-free, having built both behind one trait (Phases 6 & 8, §18/§20; MM8).
  • Training a sequence model to a numeric target — render degraded synthetic lines, run a reproducible CTC SGD loop with validation-CER early stop, and diagnose divergence vs under/overfit from the loss curve (Phase 10, §22; MM9).
  • Differential validation against a mature oracle — gate CER/WER against pinned Tesseract and exact synthetic ground truth, and localize a garbage page to the offending stage from PageTrace alone (Phase 13, §25; MM10).

3.2 Box Narratives

  • Public API / ocr facade. Re-exports the staged entry points; recognize_page(&Image, &Config, &Model) -> Page. Thin — validates image dtype/dims, selects engine (classical|neural), orchestrates stages, never holds learning logic. Enforces the stage ordering at the type level (§3.4).
  • cabi ABI. #[repr(C)] opaque OcrEngine*/OcrResult*; marshals a row-major uint8*+dims into an Image view; walks the Page tree out via index accessors (ocr_result_block_count, ocr_result_line_text); never unwinds across the boundary (catch → code).
  • ocr-core. The vocabulary. Image<T> (typed pixels, explicit stride, ROI sub-views that borrow, never copy); the Page▸Block▸Line▸Word▸Glyph tree with every node carrying a Rect in the page coordinate frame (I1); Confidence∈[0,1]; OcrError; seeded Rng (no global RNG, I7). No algorithms.
  • imageio. Wraps #173 for PNG/JPEG decode; native readers for PGM/PBM (the simplest test inputs). Converts to Image<Gray8> (luminance) for the pipeline; preserves DPI metadata (used for size-normalization).
  • binarize. Image → bilevel. Global Otsu (maximize between-class variance over the histogram). Adaptive Sauvola/Niblack/Wolf (per-pixel threshold from a local window's mean+std, computed in O(1) via integral images). Output Image<Gray8> ∈ {0,255}. Idempotent on already-binary input (I8).
  • preprocess. Denoise (median / small Gaussian / morphological open, via #389); deskew (rotate-candidate horizontal-projection-variance maximization, or dominant Hough-line angle, via #389) to ±0.1°; contrast/height normalization for the recognizer; border + black-margin removal. Each op records the transform so output boxes map back to original pixels.
  • layout. Connected components (#389 union-find) → component graph; RLSA (run-length smoothing) bridges intra-line gaps; XY-cut (recursive projection-valley splitting) / Voronoi yields blocks; block classification (text vs image/rule, by CC statistics); reading-order detection (topological sort of blocks by column + vertical position) producing a total order (I2).
  • lines. Within a text block: horizontal projection profile → smoothed → valley detection → text lines; baseline + x-height estimation (for normalization and for the neural recognizer's fixed input height); line-polygon extraction (handles slight curvature). Emits ordered Lines with boxes.
  • segment. Classical path only. Word segmentation by inter-CC gap thresholding (intra- vs inter-word gap bimodality); character over-segmentation (split at gradient/projection minima) + merge search (the recognizer scores merge hypotheses) to handle touching/broken glyphs. The neural path skips this entirely (CTC is segmentation-free).
  • features. Classical path. From a normalized glyph bitmap: zoning (per-cell ink density), HOG (gradient-orientation histograms), projection/contour profiles, raw downsampled bitmap. Output a fixed-length vector → #372 classifier.
  • recognizer. The Recognizer trait: recognize_line(&LineImage) -> (Posteriors | GlyphString). ClassicalRecognizer: per-segmented-glyph feature → kNN/SVM (#372) → char + score. NeuralRecognizer: line image (fixed height H, variable width W) → CNN (downsamples to a feature sequence) → BiLSTM (context) → linear+softmax → T×(|alphabet|+1) posteriors for CTC. Both behind one trait so decode is engine-agnostic.
  • ctc. The alignment-free bridge. Training: forward-backward over the blank-augmented label lattice → −log p(label|posteriors) + gradient (to #112). Inference: greedy (argmax/frame → collapse repeats → strip blanks) and prefix-beam (sum alignment probabilities per label prefix, fold in LM). Shared verbatim with #388.
  • lexicon. Dictionary as a trie/DAWG (compact, prefix-shared); edit-distance correction (Levenshtein over the DAWG with a cutoff); char + word n-gram LM (counts + backoff) for the decode prior. Word-frequency weights bias the beam.
  • decode. Fuses recognizer posteriors with the lexicon + LM in a beam search: extend hypotheses character-by-character (or word-by-word), score = acoustic(posterior) + α·LM + β·word-insertion; constrain/encourage dictionary words; emit a word lattice + 1-best with per-word/per-glyph confidence.
  • output. Serializes the Page tree: plain text (reading order, line breaks), hOCR (HTML with ocr_line/ocrx_word + bbox + x_wconf), ALTO (XML, library-standard), JSON (full tree). All in the original-image coordinate frame (I1).
  • train. Builds models, not part of inference. Synthetic line generator: render text (sampled from a corpus) via #385 at varied fonts/sizes, apply degradations (blur, noise, skew, ink bleed, JPEG artifacts) → (line image, transcription) pairs with exact boxes. CTC training loop on #112 (Adam/SGD, LR schedule, validation CER early-stop). Classical path: fit kNN/SVM on glyph features.
  • bench. Throughput (pages/s, lines/s), per-stage latency breakdown, CER/WER vs degradation level, neural-vs-classical A/B. Pinned, median-of-k.
  • conformance. Synthetic ground-truth (exact transcription from the renderer), the Tesseract differential harness (offline golden outputs), pipeline-invariant asserts, fuzzing (garbage/blank/huge images).

3.3 Boundaries

  • Trust boundary: C ABI (untrusted dims/pointers/config → validated) + untrusted image data (truncated/huge/adversarial pixels → bounded, never UB) + untrusted model files (version/checksum-checked, I14).
  • Concurrency boundary: blocks, lines, and glyphs are independent recognition tasks over a shared read-only binarized page → data-parallel by construction (I11).
  • Coordinate boundary: every stage transforms boxes back to the original image frame; the deskew/crop/normalize transforms are invertible and recorded (I1). Origin top-left, +x right, +y down, units = source pixels.
  • Numerical boundary: CNN/CTC FP reductions are order-dependent; match Tesseract/oracle within CER/WER tolerance, not bit-for-bit (ADR-18).
  • Stage-ordering boundary: the type system forbids recognizing an un-binarized image or segmenting an un-analyzed page (typed stage handles, I9).

3.4 Data-flow walk — one recognize_page (neural engine)

  1. imageio decodes scan.png (#173) → Image<Rgb8> → luminance Image<Gray8>; DPI read for normalization.
  2. binarize::sauvola (integral-image window) → bilevel Image<Gray8>; skew estimated.
  3. preprocess::deskew rotates by −θ (projection-variance argmax, #389); denoise (morphological open, #389); transform T_deskew recorded.
  4. layout: connected components (#389) → RLSA bridge → XY-cut blocks → classify text blocks → reading-order total order (I2).
  5. lines: per text block, projection-profile line detection + baseline/x-height; ordered Line boxes.
  6. Per line (parallel, I11): normalize to height H; NeuralRecognizer → CNN → BiLSTM → softmax → T×(|A|+1) posteriors.
  7. decode: prefix-beam over posteriors + lexicon DAWG + word n-gram LM → word sequence + per-word confidence; boxes from CTC alignment back-projected through T_deskew⁻¹ to source pixels (I1).
  8. Assemble Page▸Block▸Line▸Word▸Glyph; output::hocr serializes with bbox + x_wconf.
  9. Optional PageTrace (per-stage ms, CC count, skew angle, mean line confidence, beam stats).

Where the classical engine diverges (steps 6–7): steps 1–5 are identical. At step 6, instead of one segmentation-free neural pass, segment splits each line into words (gap analysis) and over-segments characters; features (zoning/HOG) feeds the #372 kNN/SVM, which scores merge hypotheses (the recognizer is in the segmentation loop). At step 7, decode runs over GlyphString (chars + scores) with the same lexicon/LM rerank — no CTC, no posteriors. This is the MM8 contrast made operational: the classical path's accuracy is bounded by step-6 segmentation, the neural path's is not. Both converge again at step 8 (one Page tree, one output path), so the engine choice is invisible downstream — exactly what the single Recognizer trait (§11.4) buys.

4.1 Worked complexity derivation

W×H image, C connected components, L text lines, T recognizer time-steps/line, A alphabet size, B beam width:

  • Otsu: one histogram pass O(W·H) + O(256) threshold scan.
  • Sauvola (integral): integral image O(W·H); per-pixel O(1) window mean/std ⇒ O(W·H) independent of window size (vs naïve O(W·H·w²)).
  • Connected components: two-pass union-find, O(W·H·α) with path-compression+union-by-rank.
  • Deskew: N candidate angles × projection O(W·H) ⇒ O(N·W·H); coarse-to-fine cuts N.
  • CNN encode: convolution-as-GEMM via #349; per layer O(H·W·Cin·Cout·k²) → near-peak GEMM.
  • CTC forward-backward: lattice of 2·|label|+1 states × T frames ⇒ O(T·|label|) per line, log-space.
  • Greedy decode: O(T·A) argmax + O(T) collapse. Prefix-beam: O(T·B·A) extend + LM lookup.
  • Edit-distance correction: DAWG-walk with cutoff k ⇒ pruned O(|word|·k·branching). Constants dominated by #349 GEMM (CNN/BiLSTM) and #389 filter kernels; per-page cost is CNN-encode-bound at high DPI, layout-bound at low DPI.

4.2 The one defining property

OCR is a coordinate-preserving probabilistic transduction from a 2-D raster to a 1-D symbol sequence under a learned prior. Everything else follows: because it is coordinate-preserving, every box must invert back to source pixels (I1/I15, MM2); because it is probabilistic transduction, the recognizer emits posteriors, not characters, and CTC marginalizes the unknown alignment (MM3); because it runs under a learned prior, decode fuses an LM that can be tuned or removed (MM6). The single number that defines success is character error rate (CER) against ground truth — every other target in the table exists to protect it. These targets are gated as M1…M15 in §32.1; the §32.1 table is the CI-enforced view of this constraints table.

6. Design Principles

  1. Correctness before speed; Tesseract + synthetic ground truth are the oracles. Gate every stage on CER/WER vs the renderer's exact transcription and vs Tesseract before optimizing. Violation: tuning throughput on an uncalibrated pipeline → fast wrong text.
  2. Every region carries a bounding box in the original-image frame. Deskew/crop/normalize transforms are recorded and inverted on output (I1). Violation: boxes drift from pixels → useless hOCR, broken downstream highlight/search.
  3. Stages are typed and ordered; you cannot skip one. RawImage → BinaryImage → AnalyzedPage → SegmentedLines → RecognizedPage as distinct types. Violation: recognizing an un-deskewed page → silent accuracy collapse.
  4. The recognizer is segmentation-free by default (CTC); the classical path is the contrast, not the product. Neural CNN+BiLSTM+CTC is the primary engine. Violation: depending on character segmentation → brittle on touching/broken glyphs.
  5. CTC is the alignment contract: blank-augmented forward-backward, log-space. The loss marginalizes all alignments; decode collapses repeats then strips blanks, deterministically. Violation: ad-hoc per-frame argmax without blank semantics → duplicated/dropped characters.
  6. The language model is a prior, fused at decode, never baked into the pixel model. Lexicon + n-gram rescoring is a separable, tunable beam-search term (α, β). Violation: hard-coding the dictionary into recognition → can't OCR out-of-vocabulary or tune the prior.
  7. Deterministic given a seed (and thread count + model). All randomness (training augmentation, k-means init, beam tie-breaks) from an explicit seeded Rng. Violation: irreproducible training/decoding → untestable.
  8. Binarization is idempotent and illumination-robust. Re-binarizing a binary image is identity; adaptive thresholding handles gradients. Violation: global-only thresholding → shadowed regions lost.
  9. Confidence is calibrated and emitted everywhere. Per-glyph/word/line confidence ∈ [0,1] reflects true error probability. Violation: uncalibrated confidence → downstream can't gate/triage.
  10. Numerical behavior is a CER/WER-tolerance contract, not bit-equality. Promise per-engine error-rate bounds; reductions order-deterministic per config. Violation: promising bits → broken by any GEMM order change.
  11. Reuse #389/#385/#112/#349/#173/#372; never reimplement a dependency. Convolution, fonts, autograd, BLAS, codecs, classifiers go through their owning projects. Violation: a private Sobel → numeric drift + duplicated maintenance.
  12. Bounded memory; stream pages, parallelize lines. O(W·H) page + O(T·A)/line, not O(pages·…) materialized. Violation: whole-batch buffering → OOM on a multipage scan.
  13. Validate inputs and config at the boundary. Zero dims, absurd DPI, NaN config, truncated image, incompatible model version → typed error pre-compute. Violation: trusting inputs → panics, OOB, garbage pages.
  14. Observability by default. Every page can emit per-stage timings, CC counts, skew angle, line/word confidences, beam statistics, CER on a labeled eval set. Violation: opaque failures → can't localize "which stage produced garbage."

8.3 Binarization criteria

Otsu: t* = argmax_t  ω0(t)·ω1(t)·(μ0(t) − μ1(t))²   (between-class variance; ω=class prob, μ=class mean)
Sauvola: T(x,y) = m(x,y) · [ 1 + k·( s(x,y)/R − 1 ) ]   (m=local mean, s=local std, R=128, k≈0.34)
Niblack: T(x,y) = m(x,y) + k·s(x,y)   ;   Wolf: normalizes Sauvola by global min + max contrast
Integral image: I(x,y)=Σ_{x'≤x,y'≤y} p(x',y') ⇒ window sum/mean/var in O(1) (4 lookups)

8.4 CTC objective (the alignment-free recognizer core)

Alphabet A; augment with blank ⊘. Posteriors y_t(k) = P(k at frame t), Σ_k y_t(k)=1 (I4).
A path π ∈ (A∪{⊘})^T ; collapse B(π): merge equal adjacent labels, then delete ⊘.  e.g. B(a⊘aab)= aab? → "aab" then... → "ab" handling.
Loss: −log P(l|x) = −log Σ_{π: B(π)=l} ∏_t y_t(π_t)
Forward α_t(s), backward β_t(s) over the 2|l|+1 augmented label states; P(l|x)=α_T(2|l|+1)+α_T(2|l|)
Gradient (to #112): ∂(−lnP)/∂y_t(k) = y_t(k) − (1/P)·Σ_{s∈lab(k)} α_t(s)β_t(s)
All in log-space (log-sum-exp) for stability (I4).

8.5 Decoding (beam search with LM fusion)

Greedy: ĉ_t = argmax_k y_t(k) ; output = strip⊘(collapse(ĉ_1..T))         (fast, no LM)
Prefix-beam: maintain prefixes with (p_blank, p_nonblank); extend by each char;
   score(prefix) = logP_ctc(prefix) + α·logP_LM(prefix) + β·|words(prefix)|   (α=LM weight, β=word bonus)
   prune to top-B; lexicon constrains/encourages dictionary paths (DAWG walk).
Word boundaries from space symbol or geometric gaps; per-word conf = exp(normalized beam logprob) (I10).

8.6 Reading order & segmentation

RLSA: smear runs of background shorter than threshold → connects intra-line/word ink.
XY-cut: recursively split a region at the widest valley in its horizontal/vertical projection profile
        until valleys < threshold → blocks; order = pre-order of the cut tree (top→bottom, left→right).
Reading order: build block DAG (A before B if A entirely above, or same band and left); topo-sort (I2).
Line detect: smoothed horizontal projection of a text block; lines = peaks separated by valleys;
        baseline = lower envelope fit; x-height from the projection mode.

8.7 Worked example (one short word, neural path)

Line image of "to" → CNN+BiLSTM → T=6 frames, A={t,o,…}+⊘. Greedy argmax per frame: ⊘ t t ⊘ o ⊘
collapse adjacent equal → ⊘ t ⊘ o ⊘ → strip blanks → "to".  Beam adds LM: P_LM("to")≫P_LM("ta") breaks ties.
Boxes: frames mapped back to x-ranges via CNN receptive field → glyph bboxes in line frame → page frame (I1/I15).

11. Core Schema and Core Types

Normative signatures. Lightweight only — no algorithm bodies (CRITICAL RULE 10).

11.1 Image & geometry

pub struct Image<T> { data: Vec<T>, w: usize, h: usize, stride: usize }   // row-major, explicit stride
pub type Gray8 = u8; pub type Rgb8 = [u8;3]; pub type F32 = f32;
impl<T:Copy> Image<T> { fn at(&self,x,y)->T; fn at_mut(&mut self,x,y)->&mut T;
    fn roi(&self, r:Rect)->ImageView<'_,T>;  fn dims(&self)->(usize,usize); }
pub struct ImageView<'a,T>{ /* borrows parent; never copies (principle 12) */ }
pub struct Rect { x:i32, y:i32, w:u32, h:u32 }  // page frame (I1)
impl Rect { fn contains(&self,o:&Rect)->bool; fn union(&self,o:&Rect)->Rect; fn intersect(&self,o:&Rect)->Option<Rect>; }

Image owns pixels; ImageView (ROI) borrows — crops are zero-copy. Rect arithmetic is overflow-checked (I13).

13. Phase 1 — Binarization (Otsu global + Sauvola adaptive, integral images)

13.1 Objectives

  • Global Otsu (histogram between-class variance) and adaptive Sauvola/Niblack/Wolf via integral images (O(W·H), window-size-independent).
  • Polarity detection (white-on-black → normalize); idempotence (I8).
  • The BinaryImage stage every later stage consumes.

13.2 Detailed Implementation Steps

  • binarize::integral — Integral{sum,sqsum} build O(W·H); window_mean_std(Rect) in O(1) (4 lookups each) — the integral-image trick that makes Sauvola window-size-independent (MM1, ADR-10).
  • binarize::otsu — 256-bin histogram; scan t maximizing ω₀ω₁(μ₀−μ₁)² (§8.3; Otsu 1979, paper 1); single threshold.
  • binarize::sauvola — per pixel T=m·(1+k·(s/R−1)) from the integral window (Sauvola & Pietikäinen 2000, paper 2; principle 8); Niblack/Wolf variants.
  • binarize::polarity — ink-fraction + border heuristic; invert if background is dark.
  • Output Image<Gray8>∈{0,255}; idempotence guard (already-bilevel → threshold is identity, I8).

13.3 Deliverable

  • binarize green vs synthetic ground truth + Leptonica/Tesseract-binarized golden; ocrc binarize CLI.

13.4 Acceptance Criteria

  • Sauvola is O(W·H) — runtime flat across window sizes (the integral-image win, §4).
  • Otsu threshold matches a reference within ±1 gray level on golden histograms.
  • Idempotent: bin(bin(x))==bin(x) (I8 fixture).
  • On uneven-illumination synthetic pages, Sauvola CER (downstream) ≪ Otsu CER (documents the adaptive win).

13.5 Conformance Fixtures

  • binarize/{otsu_bimodal,sauvola_gradient_illum,niblack,wolf,polarity_invert,idempotent}; golden/sauvola_window_invariance (runtime flat).

13.6 Pitfalls

  • Integral-image overflow (sum of u8 over megapixels) → use u64 (I13).
  • sqsum precision for variance (catastrophic cancellation) → compute s² = E[x²]−E[x]² carefully; clamp negatives to 0.
  • Sauvola k/window/R defaults differ by source — pin Sauvola's (k≈0.34, R=128), document.
  • Edge windows (partial near borders) — clamp the rectangle, not the index (off-image reads).
  • Global Otsu on unimodal histograms (blank page) → degenerate threshold; guard (treat as all-background).

13.7 Performance Concerns

  • Integral build is two running sums (row then column), cache-friendly; window stats are 4 loads (no per-window loop).
  • Gray8 output halves downstream bandwidth vs keeping F32.

13.8 Edge Cases

  • All-white / all-black page (no threshold); 1-pixel-tall image; salt-and-pepper noise (defer to P2 denoise); very large window (clamp to image).

13.9 Failure Analysis

  • Wrong threshold → text merges with background → everything downstream is garbage; the synthetic CER fixture localizes it to P1.
  • Blast: binarization is the first content stage; a polarity miss inverts the whole page.

13.10 Operational Notes

  • PageTrace: method, Otsu threshold, ink fraction, polarity flag.
  • docs/failure-analysis/binarization.md: diagnosing under/over-thresholding from CC statistics.

14. Phase 2 — Preprocessing (denoise, deskew, normalize)

14.1 Objectives

  • Denoise (median / small Gaussian / morphological open via #389); deskew to ±0.1° (projection-variance argmax / Hough via #389); contrast + height normalization; border/margin removal.
  • Record the invertible T_deskew affine (I15) so output boxes map to source pixels (I1).

14.2 Detailed Implementation Steps

  • preprocess::denoise — morphological open (remove specks) + optional median (#389); preserve thin strokes.
  • preprocess::deskew — candidate angles (coarse ±15° step 1°, refine step 0.1°); per angle, horizontal projection profile; score = variance/entropy of the profile (text rows ⇒ sharp peaks); argmax → skew; OR dominant Hough-line angle (#389; Gonzalez & Woods ch.10, book 1). Rotate by −θ; store the invertible T_deskew affine (I15, MM2; principle 2).
  • preprocess::normalize — stroke/height contrast normalization for the recognizer; keep a Gray8/F32 per engine.
  • preprocess::border — detect + crop black scan margins; record crop offset (I1).

14.3 Deliverable

  • preprocess green; deskew within ±0.1° on synthetic rotated pages; boxes round-trip through T_deskew⁻¹ (I15).

14.4 Acceptance Criteria

  • Deskew error ≤ 0.1° on synthetic ±10° rotations (§4).
  • T_deskew invertible: a box rotated then inverse-rotated returns within 1 px (I15 fixture).
  • Denoise removes ≥ 95% of injected salt-and-pepper without breaking strokes (stroke-continuity check).
  • Border removal crops margins without clipping text (containment check).

14.5 Conformance Fixtures

  • preprocess/{deskew_+5deg,deskew_-8deg,deskew_refine_0p1,denoise_saltpepper,border_crop}, transform_roundtrip (I15).

14.6 Pitfalls

  • Deskew on sparse pages (few text rows) → flat profile, ambiguous angle → fall back to Hough or skip with LargeSkew.
  • Rotation interpolation blurs edges → bilinear on the grayscale, re-binarize after (order: deskew grayscale → binarize, or binarize → rotate bilevel with care).
  • Forgetting to apply T_deskew to output boxes → text correct, boxes wrong (I1 violation) — the round-trip fixture guards it.
  • Over-aggressive morphological open erases periods/dots/thin strokes → size the structuring element to stroke width.
  • Border detection eating drop-caps or full-bleed images → constrain to near-edge dark runs.

14.7 Performance Concerns

15. Phase 3 — Layout analysis (connected components, RLSA, XY-cut, reading order)

15.1 Objectives

  • Connected components (#389 union-find) → component graph; RLSA bridge; XY-cut/Voronoi → blocks; block classification (text/non-text); reading-order total order (I2).
  • Produce the AnalyzedPage the line detector consumes.

15.2 Detailed Implementation Steps

  • layout::conncomp — call #389 two-pass union-find (8-connectivity); CcLabels{labels,boxes,areas} — the atom of layout (MM5).
  • layout::rlsa — horizontal + vertical run-length smoothing (smear background runs < threshold) to bond intra-line/word ink; AND the two passes (Wong/Casey/Wahl 1982, paper 8; §8.6, ADR-11).
  • layout::xycut — recursive projection-valley split (widest gap > threshold) → block tree (Nagy et al., paper 7; §8.6, ADR-11); OR Voronoi (CC-centroid Voronoi region merging) for complex layouts.
  • layout::classify — per block, CC statistics (height variance, density, aspect) → Text|Image|Rule|Table.
  • layout::reading_order — block DAG (A≺B if A above, or same band & left); topological sort with geometric tie-break (column-major) → total order (I2, MM5; ADR-12).

15.3 Deliverable

  • layout green vs synthetic multi-column pages (known block boxes + order) + Tesseract layout golden.

  • Reading order is a verified total order (irreflexive/transitive/complete, I2) and matches the rendered order on 2-column fixtures.

15.5 Conformance Fixtures

  • layout/{cc_count,rlsa_bridge,xycut_2col,xycut_nested,reading_order_2col,classify_text_vs_image}; golden/reading_order_total (order axioms).

15.6 Pitfalls

  • RLSA thresholds (horizontal ≫ vertical) are font/DPI-dependent → derive from estimated stroke/line height, not constants.
  • XY-cut fails on non-Manhattan layouts (overlapping columns) → Voronoi fallback; document the limitation.
  • Reading-order cycles from overlapping blocks (I2) → break by geometric key, never emit a cycle.
  • Merging a figure caption into the figure block → classification + gap tuning.
  • 8- vs 4-connectivity changes CC count (diagonal touches) — pin 8-connectivity, match #389.

15.7 Performance Concerns

  • CC is the cost driver at high DPI — #389's near-linear union-find; avoid re-scanning labels.
  • RLSA is two O(W·H) passes; XY-cut recursion bounded by block count.

15.8 Edge Cases

  • Single-column simple page (XY-cut trivial); dense table (many small CCs); full-page image (one non-text block); rotated-but-deskewed residual; touching columns (Voronoi).

15.9 Failure Analysis

  • Over-segmentation (lines split into blocks) or under (columns merged) → wrong reading order → block-IoU + order fixtures localize.

17. Phase 5 — Classical word & character segmentation (the classical path)

17.1 Objectives

  • Word segmentation by inter-CC gap analysis; character over-segmentation + merge search for the classical recognizer (touching/broken glyphs).
  • This path exists for contrast/interpretability; the neural path (P7–P9) skips it (CTC is segmentation-free, principle 4).

17.2 Detailed Implementation Steps

  • segment::word_gap — inter-CC horizontal gaps per line; bimodal split (intra-word vs inter-word) by Otsu-on-gaps / k-means(2) (#372) → word boundaries (Cheriet et al., book 5).
  • segment::char_overseg — split candidates at vertical projection minima / contour pinch points → over-segmented pieces (the classical segmentation model, book 5; the segmentation-dependence MM8 motivates).
  • segment::merge_search — DP/beam over piece-merge hypotheses; the recognizer (P6) scores each candidate glyph; pick the segmentation maximizing total classifier confidence + a width prior. Exists for contrast; the neural path (P7–P9) skips it (principle 4, MM8).

17.3 Deliverable

  • segment green vs synthetic (known word/char boxes); feeds P6 classical recognizer.

17.4 Acceptance Criteria

  • Word-boundary F1 ≥ 0.95 on clean synthetic; character boxes IoU ≥ 0.85.
  • Merge search recovers touching "rn"→"r","n" and split "i"→dot+stem on fixtures.
  • Segmentation is deterministic given the classifier + seed (I7).

17.5 Conformance Fixtures

  • segment/{word_gaps_bimodal,char_overseg,merge_touching_rn,merge_broken_i,seg_determinism}.

17.6 Pitfalls

  • Proportional fonts: intra-word gaps ≈ inter-word → bimodal split unreliable → use the recognizer in the loop (joint seg-recognition).
  • Italic/overlapping glyphs → vertical projection misses the cut → contour/slant-aware cuts.
  • Over-segmentation explosion → bound piece count, prune merge search (beam).
  • Touching characters are the classical path's Achilles heel — the headline reason the neural path exists (document it).

17.7 Performance Concerns

  • Merge search is the cost: bound segments/word, beam the hypotheses; cache per-piece classifier scores.

17.8 Edge Cases

  • Single-character words; all-touching cursive (out of classical scope → neural); hyphenated line-end; punctuation clusters.

17.9 Failure Analysis

  • Wrong segmentation → wrong glyphs regardless of classifier quality → the structural weakness motivating CTC; seg-F1 fixture quantifies it.
  • Blast: classical recognition accuracy is capped by segmentation; neural path is immune.

17.10 Operational Notes

  • PageTrace: words/line, segments/word, merge-search depth.

19. Phase 7 — Neural recognizer: CNN feature extractor (#112/#349)

19.1 Objectives

  • CNN that maps a normalized LineImage (height H, variable width W) to a downsampled feature sequence (T × C), the input to the BiLSTM+CTC head (P8).
  • Built on #112 autograd (forward+backward) + #349 convolution-as-GEMM (im2col).

19.2 Detailed Implementation Steps

  • recognizer::neural_cnn — a small VGG-style stack (conv→ReLU→pool ×K) reducing height H→1 while preserving a width-proportional T; channels grow C.
  • Convolution-as-GEMM: im2col + #349 GEMM (forward); #112 autograd for gradients; batch-norm optional.
  • Output Array2<f32> T×C feature sequence per line; T ≈ W / total-stride.
  • Define the receptive-field → x-coordinate map (for glyph-box back-projection, I1).

19.3 Deliverable

  • CNN forward/backward green vs #112 finite-difference gradient checks; emits a T×C sequence.

19.4 Acceptance Criteria

  • Gradients match #112 finite-difference within 1e-4 (the autograd contract).
  • Output T is a deterministic function of W and the stride (documented receptive-field map).
  • Forward uses #349 GEMM (near-peak); no private convolution (principle 11).
  • Memory bounded O(H·W·C) per line; freed after the sequence is produced.

19.5 Conformance Fixtures

  • recognizer/{cnn_grad_finite_diff,cnn_output_shape,cnn_receptive_field_map}.

19.6 Pitfalls

  • Height not reduced to exactly 1 (padding/stride arithmetic) → wrong sequence shape; pin the stack arithmetic.
  • im2col memory blowup for wide lines → tile the width; reuse #349 buffers.
  • Receptive-field/x-coordinate map off → glyph boxes wrong (I1) even when text is right.
  • Forgetting eval-mode (batch-norm/dropout) at inference → train/serve skew.

19.7 Performance Concerns

  • CNN encode is the per-line cost driver — #349 GEMM dominated; batch lines for GEMM efficiency.

19.8 Edge Cases

  • Very short line (W < min) → pad to min T; very wide line → tile; single-channel vs normalized F32 input.

19.9 Failure Analysis

  • Gradient bug → training silently won't converge → finite-diff check is the gate (P7 before P8/P10).

20. Phase 8 — Sequence model: BiLSTM + CTC loss (forward-backward)

20.1 Objectives

  • BiLSTM over the CNN feature sequence (bidirectional context) → linear → softmax → T×(|A|+1) posteriors (I4).
  • CTC loss: blank-augmented forward-backward (log-space), gradient to #112 (I5) — the alignment-free training objective.

20.2 Detailed Implementation Steps

  • recognizer::neural_bilstm — forward + backward LSTM (cells via #112 autograd); concat directions; per-frame linear to |A|+1; softmax (log-space, I4).
  • ctc::forward_backward — build the 2|l|+1 augmented label lattice; compute α (forward), β (backward) in log-space; loss −log P(l|x) (§8.4); gradient y_t(k) − (1/P)Σ_{s∈lab(k)} α_tβ_t to #112 (I5).
  • ctc::greedy — argmax/frame → collapse repeats → strip blanks (deterministic, I5).
  • Wire into #112 training step (P10 uses it).

20.3 Deliverable

  • BiLSTM+CTC forward/backward green; CTC gradient matches finite-difference; greedy decode on a tiny overfit set recovers the label.

20.4 Acceptance Criteria

  • CTC loss + gradient match finite-difference within 1e-4 (I5) on small random cases.
  • Forward prob == backward prob (α_T == Σβ) within ε (consistency).
  • Posteriors are valid distributions per frame (I4); log-space stable (no NaN on long T).
  • Overfit test: a single line trained to ~0 loss decodes to its exact label (sanity).

20.5 Conformance Fixtures

  • ctc/{forward_backward_small,grad_finite_diff,alpha_beta_consistency,greedy_collapse,logspace_stable_longT}; recognizer/bilstm_grad.

20.6 Pitfalls

  • Not working in log-space → underflow on long sequences → NaN loss; log-sum-exp everywhere (I4).
  • Off-by-one in the 2|l|+1 lattice (blank between every label + ends) → wrong loss; test against a hand-computed 2–3 char case.
  • Label longer than T (more characters than frames) → infeasible alignment, loss=∞ → guard + report (data/normalization bug).
  • Allowed transitions: skip a blank only between distinct labels (not repeated) — the classic CTC bug.
  • Greedy collapse order (collapse-then-strip vs strip-then-collapse) must match the canonical definition (I5).

20.7 Performance Concerns

  • Forward-backward O(T·|l|) per line; vectorize the per-frame state update; reuse buffers (no per-frame alloc).
  • BiLSTM matmuls via #349; sequence batched for GEMM.

20.8 Edge Cases

  • Empty label (blank line) — loss = sum of all-blank path; label length == T (forced alignment, no repeats); repeated characters ("ll", "ee") — the blank-separation case.

20.9 Failure Analysis

  • CTC math bug → training diverges or learns garbage → finite-diff + α/β-consistency + hand-computed fixtures are the gate.
  • Blast: CTC is the heart of the neural engine and is shared verbatim with #388 — a bug here breaks both.

20.10 Operational Notes

  • PageTrace: per-line loss (train), decode path length.
  • tools/ctc_align_viz plots the α·β alignment heatmap (frame × label) for debugging.

21. Phase 9 — Decoding: greedy + prefix-beam + lexicon + n-gram LM fusion

21.1 Objectives

  • Prefix-beam decode fusing CTC posteriors + lexicon (DAWG) + char/word n-gram LM (the LM-rescue, principle 6).
  • Edit-distance dictionary correction; word lattice + per-word confidence (I10).

21.2 Detailed Implementation Steps

  • lexicon::dawg — build the dictionary DAWG; contains/walk/within_edit_distance(k) (Levenshtein over the DAWG, cutoff) (Manning/Raghavan/Schütze, book 7; ADR-15).
  • lexicon::ngram — counts → backoff / Kneser-Ney (ADR-14; Jurafsky & Martin, book 4); logprob/perplexity.
  • decode::beam — prefix-beam: per frame, extend prefixes by each char; maintain (p_blank,p_nonblank); merge equal prefixes; prune to top-B (Hannun et al. "Deep Speech", paper 10; §8.5, ADR-13, MM7).
  • decode::lm_fusion — score logP_ctc + α·logP_LM + β·word_bonus (§8.5); lexicon walk constrains/encourages dictionary paths — the prior is fused at decode, never baked in (principle 6, MM6).
  • decode::confidence — per-word conf from normalized beam log-prob (I10); decode::lattice — word lattice for downstream rescoring.

21.3 Deliverable

  • LM-fused beam green; examples/recognize_png --engine neural produces dictionary-corrected text; CER drop vs greedy measured.

21.4 Acceptance Criteria

  • Beam + LM yields ≥ 30% relative WER reduction vs no-LM greedy on noisy synthetic lines (§4).
  • Beam=1 (no LM) == greedy decode (consistency).
  • Edit-distance correction fixes single-character errors to in-dictionary words on fixtures.
  • Determinism: identical text per (seed, beam, model) including tie-breaks (I5/I7).

21.5 Conformance Fixtures

  • lexicon/{dawg_contains,edit_distance_k1,kneser_ney_perplexity}; decode/{beam_eq_greedy_at_b1,lm_wer_reduction,beam_determinism,oov_allowed}.

21.6 Pitfalls

  • Over-correction: a strong LM rewrites correct rare/OOV words → tune α, allow OOV at a penalty (principle 6), never forbid non-dictionary paths.
  • Prefix-beam merge of p_blank/p_nonblank is subtle — follow the canonical recurrence exactly (the common CTC-beam bug).
  • LM weight α / word bonus β untuned → garbage; tune on a dev set, document defaults.
  • Kneser-Ney implementation errors (discounting, continuation counts) → wrong perplexity; test vs a hand-computed small corpus.
  • Beam too small → search errors; too large → slow; default B=32, expose it.

21.7 Performance Concerns

  • Beam decode O(T·B·A) + LM lookups → cache LM states; prune aggressively; DAWG walk is O(prefix).
  • Edit-distance correction only on low-confidence words (don't correct confident ones).

21.8 Edge Cases

  • Empty line (no text); all-OOV technical text (LM hurts → low α); numbers/punctuation (separate char LM); very long line (beam memory).

21.9 Failure Analysis

  • LM over-correction → confident wrong substitutions → the oov_allowed + WER-reduction fixtures bound it; runbook lm-overcorrection.md.
  • Blast: decode is the last accuracy lever; shared design with #388.

21.10 Operational Notes

  • PageTrace: beam width, LM weight, n corrections, mean word conf.
  • Expose α/β/beam in Config; document tuning in the runbook.

29. Compatibility Guarantees

  • C ABI: ocr_* signatures + OcrParams/error-code + result-tree accessor layout frozen — changing them is SemVer-major. SONAME tracks ABI. OcrParams additive-only.
  • Model serialization: model_version + alphabet hash checked on load; format change bumps it; old models load via migration or reject with IncompatibleVersion (I14) — never silently mis-decode. Schema documented.
  • Numeric behavior: per-engine CER/WER tolerance vs oracle is the contract, not bit-reproducibility across thread counts. A within-tol change = minor + CHANGELOG (ADR-18/ADR-32, §9); deterministic mode (OCR_DETERMINISTIC) is itself a stable contract.
  • Output formats: hOCR/ALTO conform to their published schemas; attribute additions are minor; coordinate frame (source pixels, top-left) is stable (I1).
  • API (Rust): SemVer; #[non_exhaustive] on OcrError/Engine/BinMethod/BlockKind; the stage types + Recognizer trait stable.
  • Tesseract parity: against a pinned Tesseract version; bumping it (may shift golden CER) is deliberate, not silent.
  • Config defaults: a default change that alters output (e.g. binarization method, LM weight) = minor + CHANGELOG.
  • Deprecation: one minor-version warning cycle before removal.

33. Scalability Analysis

  • Image-size scaling (W·H): binarization/CC O(W·H); CNN encode O(W·H·C) — high-DPI pages are CNN-bound; tiling for huge images.
  • Line scaling: per-line recognition trivially parallel (≥0.8× linear to cores, I11); CTC/decode per-line independent.
  • Beam/LM scaling: beam O(T·B·A) + LM lookups → cache states; beam width is the latency/accuracy knob.
  • Memory: O(W·H) page shared read-only across line tasks (no per-line page copy); O(T·A) per line; models O(weights), mmap-shared across pages.
  • Throughput scaling: pages are embarrassingly parallel (independent) → near-linear across cores/processes; the limit is memory bandwidth on pixel reads + GEMM on CNN.
  • Does NOT scale (by design): GPU training/inference (§39.2); multi-node distributed training (→ #115); SVM classical path beyond moderate alphabets without #372 approximations.
  • Coordination: none (no metadata service); pure in-process compute; batch eval is a local map over pages.

34. Mental Models & First Principles

The compressed insights an expert holds before touching the code. Each predicts behavior and names the bug class you write without it.

  • MM1 — Binarization is a windowed-statistics decision, and the integral image is what makes "windowed" free. A threshold is a per-pixel question "is this ink?", answered locally from a window's mean+std. Naïvely that is O(W·H·w²); the integral image (prefix-sum) collapses any window sum/mean/variance to four lookups, so adaptive thresholding costs the same as global. Predicts: Sauvola runtime is flat across window size (§13.4 fixture). Bug class without it: re-summing each window → quadratic blowup, or capping window size and losing illumination robustness. Applied: §13 (Phase 1), §4.1.
  • MM2 — Every stage is an invertible coordinate transform; the page is the one true frame. Decode, deskew, crop, normalize each warp coordinates; the engine is correct only if every output box rides the inverse chain back to source pixels. Hold the transforms, not just the pixels. Predicts: a box-overlay on the original scan lands to the pixel even after a 7° deskew (§14.4, §23.4). Bug class without it: text perfect, boxes silently drifting — invisible until someone overlays hOCR. Applied: §14, §16, §23 (I1, I15).
  • MM3 — A Future-like state machine: CTC is "sum over all the ways the labels could have been spoken." You have a line image and a target string but no per-pixel character boundary. CTC inserts a blank symbol and marginalizes over every monotonic alignment of labels to frames via a forward-backward DP — turning "unsegmented image → string" into one differentiable loss. Predicts: the model learns boundaries it was never given; repeated characters need a blank between them. Bug class without it: per-frame argmax with no blank semantics → dropped/duplicated characters. Applied: §20 (Phase 8), §8.4.
  • MM4 — Blank is not "no character"; it is the alignment-glue that makes the loss differentiable and the decode collapsible. The blank lets a character occupy many frames (collapse repeats) and separates genuine doubles ("ll"). Decode is: collapse adjacent equals, then strip blanks — order matters. Predicts: "hello" needs a blank between the two l-frames or it collapses to "helo". Bug class without it: the classic CTC off-by-one — allowing a blank-skip between identical labels. Applied: §20.6, §8.4, §8.7 (I5).
  • MM5 — Layout is a graph problem wearing an image costume. Connected components are nodes; RLSA/XY-cut induce regions; reading order is a topological sort of a geometric DAG. Once you see pixels as a CC graph, segmentation and reading order are graph algorithms, not heuristics. Predicts: reading order is provably a total order (irreflexive/transitive/complete), and cycles from overlapping blocks must be broken by a geometric key. Bug class without it: emitting a partial order → scrambled multi-column text, or a cycle → nontermination. Applied: §15 (Phase 3), §8.6 (I2).
  • MM6 — The recognizer is a weak sensor; the language model is the strong prior; decode is where they multiply. Pixels give a noisy per-frame posterior; the lexicon+LM give P(text) independent of pixels; Bayes says combine them. The LM is a separable, tunable beam term (α, β), never baked into the pixel model. Predicts: a noisy line's CER drops sharply once the LM is fused, and rises again if α is too high (over-correction). Bug class without it: hard-coding the dictionary into recognition → can't OCR OOV text or tune the prior. Applied: §21 (Phase 9), §8.5 (principle 6).
  • MM7 — Prefix-beam tracks two probabilities per hypothesis (blank-ending vs non-blank-ending), or it is wrong. Because collapse depends on whether the last emission was a blank, a CTC beam must carry (p_blank, p_nonblank) per prefix and merge them by the canonical recurrence. This is the single subtlest piece of the decoder. Predicts: getting the recurrence right makes beam=1 exactly equal greedy decode (§21.4). Bug class without it: plausible-looking beam search that quietly mis-scores repeats. Applied: §21.2, §21.6, §8.5.
  • MM8 — Segmentation-then-classify has an accuracy ceiling that no classifier can raise; segmentation-free does not. Classical OCR's error is bounded below by segmentation error — a perfect glyph classifier still fails on "rn" read as "m". CTC removes the boundary decision entirely, which is the reason it wins on touching/broken print. Predicts: classical line CER stays high (≤5%, segmentation-limited) even at 95%+ isolated-glyph accuracy; neural CER goes to ≤1%. Bug class without it: endlessly tuning the classifier to fix errors that live in the segmenter. Applied: §17/§18 vs §20, §4 (principle 4).
  • MM9 — A sequence model is only as good as the distribution it trained on; degradations are not optional garnish. A net trained on clean renders memorizes clean renders and dies on real scans. The synthetic generator must inject blur, noise, skew, ink-bleed, and JPEG artifacts so the training distribution covers the deployment one — and train/test font/text splits must be disjoint or CER lies. Predicts: augmentation ablation improves degraded-set CER; font leakage produces optimistic numbers that collapse in the field. Bug class without it: a model that benchmarks at 0.5% CER and produces garbage on the first real page. Applied: §22 (Phase 10).
  • MM10 — Without an independent oracle and per-stage telemetry, "the OCR is wrong" is undebuggable. Garbage text can come from any of seven stages. The only way to localize is exact synthetic ground truth + a mature differential oracle (Tesseract) + a PageTrace that records each stage's signal (skew angle, CC count, mean line confidence, beam stats). Predicts: you can point at "binarization polarity" vs "LM over-correction" from the trace alone. Bug class without it: opaque end-to-end failures, no regression net, accuracy silently rotting. Applied: §25 (Phase 13), §28 (I-suite, ADR-23).

Tesseract made the one decision that most shapes the field: a single LSTM+CTC line recognizer (v4) replacing the legacy per-character classifier, paired with the richest open-source page layout engine (multi-column, tables, 100+ scripts). It wins where breadth and battle-tested layout matter — arbitrary documents, many languages, production digitization — at the cost of decades of accreted C++ heuristics that are hard to reason about. This design borrows its recognizer shape and uses it as the differential oracle (ADR-23) but trades breadth for a clean, teachable two-engine core.

OCRopus/Kraken made the opposite scoping call: do one thing — per-line CLSTM+CTC recognition — extremely cleanly, and assume the page is already segmented into lines. That minimalism is exactly why it is the best architectural reference for the recognizer and training loop (ref-impl 2). It wins for trainable single-script line OCR (historical documents, Fraktur, non-Latin) where a researcher controls segmentation; it loses on full-page, multi-column, table-heavy input, which it largely delegates. This design takes its per-line recognizer model but builds the full page→line pipeline OCRopus omits.

EasyOCR made the modern scene-text decision: replace classical layout entirely with a learned text detector (CRAFT/DB-style) feeding a CRNN recognizer, bundling 80+ languages out of the box. It wins on photos, signs, and irregular layouts where projection-profile segmentation has no purchase, and on developer ergonomics (one pip install, many languages). It loses determinism and the interpretable, stage-localizable pipeline this design prizes — a detector failure is a black box, where an XY-cut failure is inspectable. This blueprint deliberately keeps classical, debuggable layout (the scene-text detector is the rejected Alternative §38.4).

ABBYY FineReader is the commercial high-water mark: proprietary adaptive binarization, rich layout + table reconstruction, an ensemble classifier tuned over decades, and strong linguistic models across 190+ languages. It wins on accuracy and format fidelity for business documents (the niche where buyers pay), at the cost of being closed, unteachable, and impossible to reason about or extend. It is the "what mature accuracy looks like" yardstick, not a buildable reference — this design optimizes for being fully understood and re-derivable, the opposite tradeoff.

36. Back-of-Envelope Capacity Model

Numbers an expert computes before designing, each derived from the System Constraints (§4) with the formula shown. Assumptions: 300 DPI, A4 (8.27 × 11.69 in), Gray8, neural engine, the §4 targets.

  • (1) Pixels per page = (300 dpi)² × area = 300² × 8.27 × 11.69 in² = 90,000 × 96.7 ≈ 8.7 M px. → a page bitmap is the unit of work; everything else scales off this.
  • (2) Page bitmap memory = pixels × 1 byte (Gray8) = 8.7 M × 1 B ≈ 8.3 MB per page; the F32 normalized working copy of one line, not the page, is what the recognizer holds (memory ceiling O(W·H) page, §4). → confirms "stream pages, don't materialize batches."
  • (3) Integral-image memory = pixels × (sum u64 + sqsum u64) = 8.7 M × 16 B ≈ 139 MB. → the integral image, not the bitmap, dominates binarization memory; it is built then dropped before layout (MM1). A u32 sum would overflow at ~16 M px (I13) — hence u64 (§13.6).
  • (4) Connected-component pass cost = O(W·H·α(n)) ≈ pixels × ~2 (two-pass union-find) ≈ 8.7 M × 2 ≈ 17 M pixel-ops; at ~1 Gops/s effective for a memory-bound scan ≈ 17 ms. → CC is a real but sub-dominant slice; the cost driver at high DPI is CNN encode (§4.1, §33).
  • (5) Text lines per page ≈ page text-height ÷ line pitch. At 11 pt body, 1.2× leading, 300 dpi: line pitch ≈ 11 × 1.2 / 72 × 300 ≈ 55 px; usable text height ≈ 10 in × 300 = 3000 px ⇒ ≈ 55 lines/page. → the per-line parallel work-unit count; sets the thread-pool granularity (I11).
  • (6) Recognizer frames per line T = line width ÷ CNN total stride. Line width ≈ 6.5 in × 300 = 1950 px; typical CRNN downsample stride ≈ 4 ⇒ T ≈ 1950/4 ≈ 490 frames/line. → drives both CTC cost (7) and posterior memory (8).
  • (7) CTC forward-backward states per line = (2|l|+1) × T. A ~75-char line ⇒ (2×75+1) × 490 ≈ 151 × 490 ≈ 74 K lattice cells/line, O(T·|label|) (§4.1). → tiny vs CNN GEMM; confirms CTC is not the bottleneck, but its per-frame state update must be alloc-free (§32).
  • (8) Posterior memory per line = T × (|A|+1) × 4 B. Latin alphabet+digits+punct ≈ 90 symbols + blank ⇒ 490 × 91 × 4 B ≈ 178 KB/line. → tiny; 55 lines × 178 KB ≈ 9.8 MB if all held, but lines stream, so peak is O(threads × 178 KB).
  • (9) Throughput floor = §4 target ≥ 1 page/s single core ⇒ per-page budget ≤ 1000 ms; spread over ~55 lines ⇒ ≤ 18 ms/line amortized, consistent with the ≤30 ms/line latency target (§4) once layout/binarize overhead is added.
  • (10) Multi-core throughput = single-core × cores × scaling. §4 promises ≥ 0.8× linear ⇒ on 8 cores ≈ 1 × 8 × 0.8 ≈ 6.4 pages/s (lines are embarrassingly parallel, I11, §33).
  • (11) Neural model memory = §4 ceiling ≤ 20 MB (CNN+BiLSTM, f32). At 4 B/param ⇒ ≈ 5 M parameters budget — a small VGG-style CNN + a modest BiLSTM, mmap-shared read-only across all page/line tasks (§33).
  • (12) CNN encode cost (dominant term) = Σ_layers O(H·W·Cin·Cout·k²). One representative 3×3 layer at H·W ≈ 32×1950 (after early pooling), Cin=Cout=64 ⇒ 32×1950×64×64×9 ≈ 2.3 Gflop/layer; a ~6-conv stack ⇒ O(10 Gflop)/line via #349 GEMM. → this, not CTC or CC, is why §33 calls high-DPI pages "CNN-bound" and why batching lines into one GEMM (§24.7, §32) is the biggest single win.

36.1 What the numbers force (design consequences)

The capacity model is not decoration — each number closes off a design option:

  • (3) forces u64 integral sums. 8.7 M px × max gray 255 overflows u32 at ~16 M px; the integral image must use u64 (I13, §13.6) — a u32 would silently wrap on a large page.
  • (2)+(8) force page-streaming, not batch materialization. One 8.3 MB page plus O(threads × 178 KB) posteriors is bounded; materializing N pages × (bitmap+posteriors) is not (principle 12). The architecture streams pages by necessity, not preference.
  • (12) forces line-batching as the headline optimization. With CNN encode at O(10 Gflop)/line and 55 lines/page, the only way to hit M5 (≥1 page/s) on CPU is to batch lines into one #349 GEMM (§24.7) — per-line GEMM calls leave the FPU idle on call overhead.
  • (6) forces a documented receptive-field map. T ≈ W/stride ties every frame to an x-range; without the exact stride arithmetic (§19.2) glyph boxes (I1) cannot be back-projected — the capacity number is the box-provenance contract.
  • (10) sets the parallelism ceiling. ≥0.8× linear to 8 cores ≈ 6.4 pages/s is the realistic single-box throughput; beyond that the limit is memory bandwidth on pixel reads, and the lever is multi-process over pages (§33), not more threads per page.

38. Alternative Architectures (Roads Not Taken)

Four fundamentally different designs for the same goal — image → structured text — not parameter tweaks. Each: sketch, winning regime, real embodiment, why rejected here.

38.1 Classic feature-extraction + per-glyph classifier (segment-then-recognize)

 page → binarize → layout → lines → CHARACTER SEGMENTATION → per-glyph features (zoning/HOG)
        → kNN/SVM classifier → char + score → dictionary rerank → text
                                  └── accuracy ceiling set by the segmenter (MM8) ──┘

Regime where it wins: clean fixed-pitch monospace print (forms, OCR-A/B, MICR cheque fonts) where segmentation is trivial and an interpretable, retrain-free, low-memory classifier beats a data-hungry net. Real system: pre-v4 Tesseract; classical commercial OCR of the 1990s; ABBYY's classifier lineage. Why rejected as the primary: segmentation error is a hard accuracy floor on touching/broken glyphs (MM8) — the headline reason CTC exists. Kept as the contrast engine (§17/§18, ADR-9), not the product.

38.2 CNN + BiLSTM + CTC line recognizer (this design's neural path)

 page → binarize → layout → lines → NORMALIZE line (height H) → CNN encoder (T×C)
        → BiLSTM (context) → linear+softmax (T×|A|+1) → CTC loss/decode → LM-fused beam → text
                                  └── no character boundary ever decided (segmentation-free) ──┘

Regime where it wins: general printed text including touching/broken/degraded print and historical fonts — the mainstream modern document-OCR sweet spot. Real system: Tesseract v4+, OCRopus/Kraken, EasyOCR, CRNN (Shi et al.). Why chosen: segmentation-free, robust, trainable to ≤1% CER (§4); the most transferable architecture (shared with #388 ASR). This is the locked primary (ADR-9).

38.3 Attention / sequence-to-sequence recognizer (encoder–decoder)

 line image → CNN/feature encoder → ENCODER states → ATTENTION → autoregressive DECODER
        → char_t conditioned on char_<t and attended image features → text
                                  └── learns alignment as attention, not via blank/marginalization ──┘

Regime where it wins: cursive scripts and strong context dependence — Arabic, handwriting, scene text with heavy ligatures — where CTC's per-frame conditional-independence assumption hurts and an autoregressive decoder's learned language modeling pays off. Real system: attention-OCR / TrOCR-style transformer recognizers; many handwriting-recognition systems. Why rejected (deferred §39.8): heavier to train, non-monotonic attention can hallucinate/loop on long lines, no clean per-frame box back-projection (worse coordinate provenance, MM2); CTC is the right first engine for printed Latin. Anchored as a deferred feature.

38.4 End-to-end scene-text detector + recognizer (detection-first, layout-free)

 whole image → TEXT DETECTOR (CRAFT / DB / EAST: per-pixel text heatmap → word/line boxes)
        → crop each detected region → CRNN/attention recognizer → text (+ box)
                                  └── no binarization, no projection-profile layout at all ──┘

Regime where it wins: photographs, signs, labels, screenshots, arbitrarily-oriented or curved text — "text in the wild," where binarization and XY-cut have no purchase and a learned detector is the only thing that finds the text. Real system: EasyOCR (CRAFT+CRNN), PaddleOCR (DB+CRNN), most scene-text pipelines. Why rejected: this blueprint targets document images (scanned pages), where classical layout is interpretable, deterministic, and stage-localizable (MM5, MM10); a learned detector is a black box that fails opaquely and needs large labeled detection corpora. Deferred for camera-capture/scene text (§39.3/§39.11).

40. Glossary

  • ALTO Analyzed Layout and Text Object; LoC XML schema for OCR output (layout + text + coordinates).
  • Attention / seq2seq recognizer an encoder–decoder recognizer that learns alignment as attention and decodes characters autoregressively; the deferred alternative to CTC (§38.3, §39.8).
  • Baseline the line on which characters sit; reference for line normalization.
  • Beam width (B) the number of hypotheses retained per step in prefix-beam decode; the latency/accuracy knob (default 32, ADR-13).
  • Binarization converting grayscale to bilevel (ink/background).
  • Blank (CTC) the special label ⊘ separating/absorbing frames; enables alignment-free training.
  • Bounding box (bbox) axis-aligned rectangle locating a region in the page frame.
  • Calibration (confidence) the property that predicted confidence matches observed error rate; gated so downstream can triage (principle 9, I10).
  • CC (connected component) maximal set of connected foreground pixels; the atom of layout.
  • CER / WER Character / Word Error Rate = edit distance ÷ reference length.
  • CRNN CNN + RNN (BiLSTM) + CTC — the end-to-end image-sequence recognizer.
  • CTC Connectionist Temporal Classification; alignment-free sequence loss via blank-augmented forward-backward.
  • DAWG Directed Acyclic Word Graph; compact prefix+suffix-shared dictionary.
  • Deskew rotating a page to make text horizontal.
  • Edit distance (Levenshtein) minimum insert/delete/substitute operations between two strings; basis of CER/WER and DAWG correction.
  • Forward-backward the DP computing alignment marginals (α, β) over the CTC label lattice.
  • im2col unrolling convolution windows into columns so a convolution becomes a single GEMM (via #349); the CNN-encode hot path (§19, §32).
  • hOCR HTML microformat embedding OCR layout + text + confidence.
  • HOG Histogram of Oriented Gradients; a classical glyph feature.
  • Integral image prefix-sum image enabling O(1) window sum/mean/variance.
  • Kneser-Ney an n-gram smoothing method using continuation counts; the LM smoothing of choice (ADR-14).
  • Lexicon dictionary of valid words used to constrain/rerank decoding.
  • n-gram LM language model of order n with backoff/Kneser-Ney smoothing.
  • Niblack a local-mean+std binarization threshold (m + k·s); precursor to Sauvola, kept as a variant.
  • NMS non-maximum suppression (edge/feature thinning; from #389).
  • Otsu global threshold maximizing between-class variance.
  • Perplexity the exponentiated per-symbol cross-entropy of an LM; lower = better predictive prior (§21).
  • Posteriors per-frame probability distribution over alphabet+blank.
  • Prefix-beam search CTC-aware beam decoding maintaining blank/non-blank prefix probabilities.
  • Receptive field the input-pixel extent a CNN output frame depends on; the map from frame index to x-range for glyph-box back-projection (§19, I1).
  • Projection profile row/column ink-sum histogram used for line/block segmentation.
  • Reading order the total order in which blocks/lines should be read (multi-column aware).
  • RLSA Run-Length Smoothing Algorithm; bridges background runs to form regions.
  • Sauvola adaptive local-mean+std binarization threshold.
  • Scene text text in photographs/signs/labels (vs scanned documents); the regime of the deferred detector-first architecture (§38.4).
  • Seam carving finding a min-energy path between text rows to split slightly-touching/curved lines (§16).
  • Skew the rotation angle of text relative to horizontal.
  • Structuring element the shape used in morphological operations (from #389).
  • Text detector (CRAFT/DB) a learned model that outputs text region boxes directly from a raw image, replacing classical layout in scene-text pipelines (§38.4).
  • Voronoi segmentation page segmentation by merging CC-centroid Voronoi regions; the XY-cut fallback for non-Manhattan layouts (§15).
  • Wolf a Sauvola variant normalized by global min and max contrast.
  • x-height height of lowercase letters without ascenders; a normalization reference.
  • XY-cut recursive page segmentation by projection-profile valleys.
  • Zoning grid-cell ink-density glyph feature.
