Decisions (§9) · 33 ADRs

1

Impl language

Chosen

Rust 2021, MSRV pinned

Rejected

C++, Python, Go

When the rejected choice is right

C++ wins when extending mature Tesseract/Leptonica in place (decades of code, not a from-scratch build); Python wins for a research prototype iterating on model architecture nightly, where OpenCV/PyTorch glue speed beats from-scratch purity

Why: ownership for staged-pipeline + box provenance; reuse #389/#385/#112/#349/#173/#372; perf (§1.9)

2

Build/workspace

Chosen

Cargo workspace, 17 crates

Rejected

single crate

When the rejected choice is right

a single crate wins for a < 3 kLOC toy or a teaching demo where crate-graph ceremony outweighs the layering benefit and compile times matter more than enforced boundaries

Why: crate boundaries enforce stage layering (core ↛ recognizer)

Image ops

Chosen

depend on #389 (conv/Sobel/Canny/Hough/morph/CC)

Rejected

reimplement filters

When the rejected choice is right

reimplementing wins if #389 is unavailable/unfinished, or if one fused binarize+CC pass (fewer image traversals) beats two library calls on a memory-bandwidth-bound embedded target

Why: reuse, same batch, single tested impl (principle 11)

Fonts/synthetic data

Chosen

Rejected

When the rejected choice is right

bundled bitmaps win for a fixed-font OCR target (one scanner, one typeface — e.g. MICR/E-13B cheque fonts) where the renderer's generality is dead weight and per-glyph templates suffice

Neural training

Chosen

Rejected

hand-rolled backprop

When the rejected choice is right

hand-rolled wins when the network is one fixed small architecture shipped frozen — a hand-derived CTC+BiLSTM backward avoids the autograd tape's per-op overhead and graph memory in a tight embedded trainer

Why: reuse autodiff + optimizers

Image decode

When the rejected choice is right

Classical classifier

Chosen

depend on #372 kNN/SVM

Rejected

private classifier

When the rejected choice is right

a private classifier wins when a domain-specific model (e.g. a tiny decision tree over 7-segment-display features) is both faster and more accurate than general kNN/SVM for a narrow glyph set

9

Primary recognizer

Chosen

CNN + BiLSTM + CTC (CRNN)

Rejected

classical-only; attention

When the rejected choice is right

classical-only wins for clean fixed-pitch monospace print (form fields, OCR-A/B) where segmentation is trivial and an interpretable, retrain-free classifier is preferred; attention/seq2seq wins for cursive scripts and severe context dependence (Arabic, handwriting) where CTC's conditional-independence assumption hurts

Why: segmentation-free, robust; attention §39.8

10

Binarization

Chosen

Otsu (global) + Sauvola (adaptive, integral)

Rejected

global-only; Niblack-only

When the rejected choice is right

global-only Otsu wins on uniformly-lit synthetic/born-digital pages (no illumination gradient) where it is faster and Sauvola's window cost is wasted; Niblack-only wins on thin-stroke line art where Sauvola's R-normalization over-erodes

Why: illumination robustness (principle 8)

Chosen

RLSA + XY-cut (+ Voronoi option)

Rejected

whitespace-only

When the rejected choice is right

whitespace-only (gap projection) wins on strictly single-column body text (novels, RFCs) where RLSA/XY-cut machinery is overkill and a one-pass gap scan is faster and less tunable

Decode

Chosen

Rejected

When the rejected choice is right

greedy wins for interactive/preview latency, for OOV-heavy text (codes, IDs, chemical names) where the LM hurts, and for a model already at < 0.5% CER where beam+LM cannot improve enough to justify the cost

Why: LM-rescue (principle 6)

Rejected

When the rejected choice is right

always-serial wins for single-page latency on one core, for deterministic debugging (no thread interleaving), and inside a caller that already parallelizes across pages (nested pools thrash)

Roads not taken (§38)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Classic feature-extraction + per-glyph classifier (segment-then-recognize)

 page → binarize → layout → lines → CHARACTER SEGMENTATION → per-glyph features (zoning/HOG)
        → kNN/SVM classifier → char + score → dictionary rerank → text
                                  └── accuracy ceiling set by the segmenter (MM8) ──┘

Regime where it wins: clean fixed-pitch monospace print (forms, OCR-A/B, MICR cheque fonts) where segmentation is trivial and an interpretable, retrain-free, low-memory classifier beats a data-hungry net. Real system: pre-v4 Tesseract; classical commercial OCR of the 1990s; ABBYY's classifier lineage. Why rejected as the primary: segmentation error is a hard accuracy floor on touching/broken glyphs (MM8) — the headline reason CTC exists. Kept as the contrast engine (§17/§18, ADR-9), not the product.

CNN + BiLSTM + CTC line recognizer (this design's neural path)

 page → binarize → layout → lines → NORMALIZE line (height H) → CNN encoder (T×C)
        → BiLSTM (context) → linear+softmax (T×|A|+1) → CTC loss/decode → LM-fused beam → text
                                  └── no character boundary ever decided (segmentation-free) ──┘

Regime where it wins: general printed text including touching/broken/degraded print and historical fonts — the mainstream modern document-OCR sweet spot. Real system: Tesseract v4+, OCRopus/Kraken, EasyOCR, CRNN (Shi et al.). Why chosen: segmentation-free, robust, trainable to ≤1% CER (§4); the most transferable architecture (shared with #388 ASR). This is the locked primary (ADR-9).

Attention / sequence-to-sequence recognizer (encoder–decoder)

 line image → CNN/feature encoder → ENCODER states → ATTENTION → autoregressive DECODER
        → char_t conditioned on char_<t and attended image features → text
                                  └── learns alignment as attention, not via blank/marginalization ──┘

Regime where it wins: cursive scripts and strong context dependence — Arabic, handwriting, scene text with heavy ligatures — where CTC's per-frame conditional-independence assumption hurts and an autoregressive decoder's learned language modeling pays off. Real system: attention-OCR / TrOCR-style transformer recognizers; many handwriting-recognition systems. Why rejected (deferred §39.8): heavier to train, non-monotonic attention can hallucinate/loop on long lines, no clean per-frame box back-projection (worse coordinate provenance, MM2); CTC is the right first engine for printed Latin. Anchored as a deferred feature.

End-to-end scene-text detector + recognizer (detection-first, layout-free)

 whole image → TEXT DETECTOR (CRAFT / DB / EAST: per-pixel text heatmap → word/line boxes)
        → crop each detected region → CRNN/attention recognizer → text (+ box)
                                  └── no binarization, no projection-profile layout at all ──┘

Regime where it wins: photographs, signs, labels, screenshots, arbitrarily-oriented or curved text — "text in the wild," where binarization and XY-cut have no purchase and a learned detector is the only thing that finds the text. Real system: EasyOCR (CRAFT+CRNN), PaddleOCR (DB+CRNN), most scene-text pipelines. Why rejected: this blueprint targets document images (scanned pages), where classical layout is interpretable, deterministic, and stage-localizable (MM5, MM10); a learned detector is a black box that fails opaquely and needs large labeled detection corpora. Deferred for camera-capture/scene text (§39.3/§39.11).
