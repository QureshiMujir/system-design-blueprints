33. Back-of-Envelope Capacity Model

Each number is derived from §4's System Constraints table, formula shown.

  1. Memory per 1M live tuples, 200-byte average payload: 1,000,000 × (32 B header + 200 B payload) = 232 MB. (From §4's 32 B header row.)
  2. Chain traversal worst case, cold tuple at cap: 1,024 versions × ~100 ns/cache-miss ≈ 102.4 µs. (From §4's 1,024-version chain-depth cap, M8's per-hop cost assumption.) 2a. HOT-pruned hot-path traversal: 8 versions × 100 ns ≈ 800 ns — within M8's 1 µs p99 budget with margin. (From §4's ≤8-version HOT-pruned depth.)
  3. Registry in_progress set memory, 100,000 concurrent txns: inline for ≤32 (32 × 8 B = 256 B), else heap BTreeSet at ~48 B/entry × 100,000 = 4.8 MB. (From §4's 100,000-txn concurrency ceiling.)
  4. GC throughput vs write rate headroom: at M1's 100,000 txn/sec with 1 write/txn and a 10-version average chain before prune, dead-version production ≈ 100,000 × (10-1) = 900,000/sec, against M6's 1,000,000/sec reclaim budget — 10% headroom, derived by dividing M6 by the production rate. (From §4's M1 and M6 rows.)
  5. WAL bandwidth at M1's commit rate: 100,000 commits/sec × (32 B CommitRecord header + ~200 B average write-set payload) ≈ 23.2 MB/sec sustained WAL write bandwidth. (From §4's M1 row and §11.9's CommitRecord layout.)
  6. RTO for a 15 GB WAL segment: 15,000 MB ÷ 500 MB/sec (M10) = 30 seconds, matching §4's stated RTO target exactly — the target is this derivation. (From §4's M10 row.)
  7. FD budget at 200 GiB resident, 1 GiB segments: 200 GiB ÷ 1 GiB/segment = 200 heap segment FDs, plus WAL segment FDs (typically ≤ 16 active) ≈ 216 FDs, within §4's ≤256-FD budget. (From §4's storage-amplification and FD-budget rows.)
  8. SIREAD lock-table size at SSI, 1M reads/sec, 1-second retention: 1,000,000 reads/sec × ~64 B/SiReadLock × 1 sec ≈ 64 MB/sec growth absent promotion — this is why ADR-17's page-level promotion is load-bearing, not optional, past this rate. (From §4's SSI false-positive-budget row and §11.10's SiReadLock size.)
  9. Snapshot construction cost, Phase 3 (pre-lock-free): O(100,000 active txns) × ~10 ns/entry scan ≈ 1 ms — 1,000× over the M5 target of 1 µs, which is exactly why Phase 10's epoch-protected projection (§22.1) is mandatory, not an optimization. (From §4's 100,000-txn ceiling and M5's 1 µs target.)
  10. Storage amplification ceiling in bytes, 1M rows, 200 B payload, 30% overhead (M11): 232 MB × 1.30 = 301.6 MB steady-state post-vacuum footprint. (From capacity #1 above and §4's M11 row.)
