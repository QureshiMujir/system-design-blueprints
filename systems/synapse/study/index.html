Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. If a resolver's ACCEPT verdict is cached (P9) and later an eval score is retroactively found gamed (post-publish regression), how does the system unwind already-served requests without violating I4's determinism guarantee? (§8.3, §19, §25 FM-6)
  2. Under C10's pool ceiling and C11's max-4-composition cap, what happens to a request specifying 5 STACK-composed adapters — resolver-time REJECT or runtime-time backpressure, and which invariant governs which? (§7 I10, §4 C11, §8.6)
  3. Given P5 (base weights never mutated except explicit merge-and-freeze) and ADR-08's dedicated LRU pool, how does an operator distinguish "the pool evicted my hot adapter" from "someone ran merge-and-freeze on the base" when diagnosing a latency spike? (§25 FM-3, §7 I3, §18)
  4. If TIES-Merging (ADR-10) trims and elects signs across adapters trained on quantized (NF4) and full-precision bases respectively, does I13's "exact alpha/r scaling per source manifest" still hold post-dequantization, or does Phase 8's promotion path need its own merge-scaling rule? (§20, §18, §7 I13)
  5. P7 makes artifacts architecture-scoped rather than checkpoint-scoped — how does the eval gate (I8) distinguish "broadly compatible" from "passed eval against one lucky checkpoint in its architecture family"? (§8.3, §19)
  6. §22's federated bridge produces an AggregatedDelta as a CapabilityId — does it pass through the same P2/I2 resolution and P12 eval gate as an individually-authored adapter, or does federated provenance grant a different promotion path? (§22, §8.5)
  7. C12's dedup assumes 40% storage reduction from shared base-fingerprint blocks — under P8 (per-blob addressing), what dedup rate should be expected between two independently-trained adapters on the same modules/base (near-zero shared bytes) versus a merge-and-freeze derivative of an existing artifact (potentially high shared bytes)? (§4 C12, P8, §18)
  8. I7 requires byte-identical composition-order preservation — how does this interact with ADR-07's SGMV batched kernel, which processes many requests' adapter sets in one batched GEMM call; does batching risk silently reordering per-request composition sequences for throughput? (§7 I7, §17, ADR-07)
  9. FM-2's resolver false-reject cascade is triggered by TargetModuleSet normalization drift — what in §28's testing strategy would have caught this before production, given per-crate unit tests don't exercise cross-service normalization consistency? (§25 FM-2, §28, §8.3)
  10. T7 (federated poisoning) and I11 (privacy-boundary requirement) both gate FederatedRound ingestion — can a well-formed secure-aggregation proof (satisfying I11) still admit a poisoned outlier update (T7), and if so, which control actually catches it? (§24 T7, §7 I11, §22)
  11. M12's distillation fidelity margin is a Phase 9 gate — combined with P10's provenance-pointer requirement and I12, what should happen if a distilled artifact scores above its teacher (an unexpectedly favorable, possibly suspicious result)? (§21, §7 I12, §19)
  12. §20's quantized-base promotion path allows an fp16-trained adapter onto an NF4 base with a "declared promotion path" — how does §8.3's decision table distinguish a legitimate promotion from T-class dtype-mismatch exploitation absent an explicit human sign-off step? (§8.3, §20, §24)
  13. C4's resident-adapter count and C7's throughput curve are functions of N concurrent adapters, but composition (C11, ≤4 per request) means one request may occupy up to 4 pool slots simultaneously — does §17's capacity planning (M4/M5) account for composed-request slot multiplication, or only distinct- adapter count? (§4 C4/C7/C11, §17, §34)
  14. §27 says manifest schema evolution is additive-only, but §8.1's byte-layout format version is independent — when a format-version bump occurs mid- registry-lifetime, do already-PUBLISHED artifacts need re-signing, or must the verifier support N and N−1 format versions simultaneously? (§27, §8.1, §29)
  15. ADR-09 places the resolver server-side, client-cached — under I4 (deterministic plan given inputs), what invalidates a client's cached ResolvedPlan when the server-side eval score changes post-hoc (e.g. a regression detected after initial ACCEPT)? (§7 I4, ADR-09, §25 FM-6)
  16. §21's cross-architecture distillation and §36's rejected full-fine-tune checkpoint registry both eventually produce a new artifact tied to a target architecture — what makes the distillation path categorically different from the rejected full-fine-tune-registry path in the trust/compatibility machinery each must satisfy? (§21, §36, P10)
  17. §26's chaos drills exercise C13 (registry failover) and C14 (blob RTO) quarterly, but T10 describes a Rekor transparency-log outage forcing fail-closed signing — is a Rekor outage itself drilled, and if not, which FM/T-row's recovery procedure has never been chaos-tested? (§24 T10, §26, §25)
  18. §34's extra-GEMM-FLOPs-per-token calculation shows composition overhead is <1% of base compute, yet C6 sets an 8% measured latency budget — what does the gap between the FLOPs-level estimate and the empirical ceiling reveal about where the real cost of composition actually lives? (§34, §4 C6, §17)

32. Mental Models & First Principles

MM1 — Composition is vector addition in weight space. Insight: a LoRA delta ΔW = (α/r)·B·A is a low-rank direction in weight space; composing two adapters is summing directions, and interference is just non-orthogonality between them. Predicts: near-orthogonal task adapters stack cleanly; adapters touching the same modules with correlated directions degrade each other. Bug without it: treating "more adapters" as strictly additive capability with no interference budget, silently shipping degraded composed output. Resolves: §18, §8.4.

MM2 — The trust boundary is per-byte, not per-file. Insight: the signature covers manifest ‖ tensor index ‖ blob digest tree as one unit (§8.1); there is no "the manifest is signed, trust the blob bytes" shortcut. Predicts: any single tampered byte anywhere in the artifact fails verification globally. Bug without it: verifying only metadata and trusting blob content unconditionally, leaving I9 violations undetected until numerically wrong output appears. Resolves: §13, §24 T5.

MM3 — Compatibility is proof, not trial-and-error. Insight: a CompatibilityVerdict is a decision-table output over declared facts (§8.3), computed before any GPU work, not inferred by attempting a load and seeing if it errors. Predicts: rejection is millisecond-cheap (M9); false negatives (over-strict subset match) are the safe failure mode, not false positives. Bug without it: "try it and see" lets coincidentally-matching shapes mask a real incompatibility, producing silent corruption (P6). Resolves: §15, §8.3.

MM4 — Base weights are read-only; adapters are functions, not patches. Insight: an adapter composes at forward time (P5); it never mutates the resident base tensor, which is what makes multi-tenant sharing of one resident base model possible at all. Predicts: N tenants share one base economically; merge-and-freeze is a rare, explicit, logged exception, never the default path. Bug without it: in-place mutation from one tenant's adapter corrupts every concurrent tenant's request on the same base (I3). Resolves: §16, §7 I3.

MM5 — Dedup is a side effect of addressing, not a feature. Insight: content-addressed, per-blob storage (P8) makes "does this tensor block already exist" a hash lookup; deduplication and garbage collection fall out of the addressing scheme rather than needing a bolted-on tracking system. Predicts: registry storage grows sublinearly in artifact count once shared base-layer blocks recur (C12's ~40% dedup). Bug without it: per-package storage (the ADR-04 rejected alternative) makes reference counting — and therefore GC — impossible without a second system. Resolves: §14, P8.

MM6 — Rank is a capacity budget, not a free parameter. Insight: artifact size and swap latency scale linearly with r (C1→C3 is an 8x jump for an 8x rank increase); capability does not scale linearly with it past a task-appropriate rank. Predicts: naive "default to high rank for safety" blows the resident-adapter budget (C4) and the throughput curve (C7) for marginal quality return. Bug without it: authors over-provision rank, and the fleet silently loses adapter-residency headroom. Resolves: §34, §4 C1–C4.

MM7 — An eval gate is a hypothesis test, not a spot check. Insight: a benchmark score has sampling noise; promotion decisions need a confidence interval (ADR-19), not a point estimate. Predicts: two artifacts with identical point-estimate scores can carry very different promotion risk if their bootstrap CI widths differ (M10). Bug without it: regressions within the noise band get promoted or blocked inconsistently, eroding the meaning of "PUBLISHED" (P12). Resolves: §19, ADR-19.

MM8 — Composition order is a non-commutative operator. Insight: for overlapping target modules, STACK(A,B) ≠ STACK(B,A) (§8.4); order is data, not an incidental request detail. Predicts: identical adapter sets requested in different order are two distinct, both valid, outputs. Bug without it: caching or logging by adapter-set-as-set conflates two genuinely different results (P3, I7). Resolves: §18, §7 I7.

MM9 — Architecture-scoping trades precision for reusability, and the eval gate is what keeps that trade safe. Insight: BaseModelFingerprint captures architecture family, not checkpoint identity (P7); a single artifact resolves against any checkpoint sharing the fingerprint, with quality enforced downstream by score rather than upstream by identity. Predicts: the same artifact reuses across a whole checkpoint lineage; safety depends entirely on the eval gate actually running. Bug without it: over-narrow checkpoint-pinning makes the registry useless at scale; over-broad with no gate makes it unsafe. Resolves: §8.3, §15.

MM10 — A privacy budget is a ledger, not a one-time knob. Insight: cumulative epsilon spend across FederatedRounds must accumulate and be enforced monotonically (I11); "we used DP-SGD" without a running ledger is theater. Predicts: a bridge that resets epsilon per round instead of accumulating silently exceeds any real guarantee after enough rounds. Bug without it: FM-7, the exact privacy-budget-breach failure class the ledger exists to prevent. Resolves: §22, §7 I11, §25 FM-7.

5. Required Reading

Books

  • Kleppmann, Designing Data-Intensive Applications — ch. 3 (Storage and Retrieval), ch. 5 (Replication): extract the index/blob separation and replication-consistency model underlying the registry's index-vs-CAS split. Applied in §14 (Phase 2).
  • Petrov, Database Internals, Vol. 1 — ch. 2–4 (B-Trees, storage engines): extract on-disk index structuring for the registry catalog and manifest lookup path. Applied in §14 (Phase 2).
  • Goodfellow, Bengio & Courville, Deep Learning — ch. 7 (Regularization), ch. 8 (Optimization): extract the low-rank/regularization theory underpinning why a low-rank delta captures a fine-tune direction. Applied in §8 (Domain Model).
  • Beyer, Jones, Petoff & Murphy (eds.), Site Reliability Engineering — ch. 4 (SLOs), ch. 6 (Monitoring Distributed Systems): extract SLO-driven telemetry design for the metrics named in §7 and §26. Applied in §26 (Operational Readiness).
  • Google, Building Secure and Reliable Systems — ch. 4 (Design for Least Privilege), ch. 13 (Designing for and Recovering from Compromise): extract the supply-chain trust-boundary design for the signer/verifier. Applied in §13 (Phase 1).
  • Bryant & O'Hallaron, Computer Systems: A Programmer's Perspective — ch. 7 (Linking), ch. 9 (Virtual Memory): extract the binary-layout/relocation-table analogy used for the tensor index and mmap-based tensor loading. Applied in §12 (Phase 0) and §16 (Phase 4).
  • Burns, Designing Distributed Systems — the sidecar and ambassador patterns: extract the adapter-loader-as-sidecar design used by the serving runtime. Applied in §16 (Phase 4).

Papers

  • Hu et al., LoRA: Low-Rank Adaptation of Large Language Models, ICLR 2022 — the low-rank delta W' = W + (α/r)·BA. Applied in §8 (Domain Model).
  • Dettmers et al., QLoRA: Efficient Finetuning of Quantized LLMs, NeurIPS 2023 — 4-bit NF4 quantized base with LoRA adapters. Applied in §20 (Phase 8).
  • Houlsby et al., Parameter-Efficient Transfer Learning for NLP, ICML 2019 — bottleneck adapter modules as an alternative target-module shape. Applied in §8 (Domain Model).
  • Li & Liang, Prefix-Tuning: Optimizing Continuous Prompts for Generation, ACL 2021 — prefix-based conditioning as a non-weight-delta capability shape. Applied in §36 (Alternative Architectures).
  • Lester, Al-Rfou & Constant, The Power of Scale for Parameter-Efficient Prompt Tuning, EMNLP 2021 — soft-prompt tuning informing the prompt/context-only alternative design. Applied in §36 (Alternative Architectures).
  • Liu et al., Few-Shot Parameter-Efficient Fine-Tuning is Better and Cheaper than In-Context Learning (IA3/T-Few), NeurIPS 2022 — scale-only adapters as a minimal TargetModuleSet shape. Applied in §8 (Domain Model).
  • Hinton, Vinyals & Dean, Distilling the Knowledge in a Neural Network, 2015 — response-based knowledge distillation, the core cross-architecture technique. Applied in §21 (Phase 9).
  • Sanh et al., DistilBERT, a distilled version of BERT, 2019 — a practical distillation recipe informing the DistillationJob schema. Applied in §21 (Phase 9).
  • Ilharco et al., Editing Models with Task Arithmetic, ICLR 2023 — task vectors as the additive composition primitive. Applied in §18 (Phase 6).
  • Yadav et al., Resolving Interference When Merging Models (TIES-Merging), NeurIPS 2023 — trim + sign-election merge rule. Applied in §18 (Phase 6).
  • Yu et al., Language Models are Super Mario (DARE), ICML 2024 — drop-and-rescale merge rule. Applied in §18 (Phase 6).
  • Sheng et al., S-LoRA: Serving Thousands of Concurrent LoRA Adapters, 2023 — unified paging for multi-adapter batched serving. Applied in §17 (Phase 5).
  • Chen et al., Punica: Multi-Tenant LoRA Serving, MLSys 2024 — segmented gather matrix-vector (SGMV) batched kernels. Applied in §17 (Phase 5).
  • McMahan et al., Communication-Efficient Learning of Deep Networks from Decentralized Data (FedAvg), AISTATS 2017 — the federated averaging round. Applied in §22 (Phase 10).
  • Bonawitz et al., Practical Secure Aggregation for Privacy-Preserving Machine Learning, CCS 2017 — secure aggregation protocol. Applied in §22 (Phase 10).
  • Kairouz et al., Advances and Open Problems in Federated Learning, 2021 — threat-model framing for the federated bridge. Applied in §22 (Phase 10) and §24 (Threat Model).
  • Abadi et al., Deep Learning with Differential Privacy (DP-SGD), CCS 2016 — the privacy-budget mechanism for federated rounds. Applied in §22 (Phase 10).

Reference Implementations

  • HuggingFace PEFT — src/peft/tuners/lora/layer.py, src/peft/tuners/lora/model.py: lesson — target-module injection via Linear layer replacement; pitfall — alpha/r scaling factor mismatched across library versions on save/load. Applied in §13 (Phase 1) and §8 (Domain Model).
  • vLLM — vllm/lora/layers.py, vllm/lora/punica.py, vllm/lora/worker_manager.py: lesson — LoRA weights held in a dedicated pinned-memory pool, swapped via CUDA streams; pitfall — heterogeneous adapter ranks in one batch force padding to max rank. Applied in §17 (Phase 5).
  • S-LoRA — slora/server/, slora/models/: lesson — unified paging of adapter memory analogous to PagedAttention; pitfall — LRU eviction under skewed request popularity causes cache thrashing. Applied in §17 (Phase 5).
  • safetensors — safetensors/src/tensor.rs header parsing: lesson — fixed-shape JSON header plus raw tensor bytes, mmap-friendly, no pickle; pitfall — an unbounded header-length field enables an allocation-overflow DoS if not bound-checked. Applied in §12 (Phase 0).
  • mergekit — mergekit/merge_methods/ties.py, dare.py, task_arithmetic.py: lesson — merge methods as composable passes over aligned tensors; pitfall — silent shape mismatch when base models diverge in vocabulary size. Applied in §18 (Phase 6).
  • LoRAX — server/lorax_server/adapters/: lesson — dynamic adapter loading with per-request routing at the scheduler level; pitfall — synchronous registry pulls blocking the scheduler hot path without async prefetch. Applied in §16 (Phase 4) and §17 (Phase 5).

Glossary (§38) · 52 terms · site-wide glossary

Adapter interference
quality degradation from composing non-orthogonal LoRA deltas on overlapping modules (MM1, §18).
Alpha (α)
LoRA scaling factor applied to the low-rank delta (§8.2, §8.4).
Architecture family
the base-model lineage field (e.g. "llama", "mistral") in BaseModelFingerprint (§11, P7).
Base-model fingerprint
BaseModelFingerprint: architecture family, hidden size, layer count, vocab size, quantization scheme, optional checkpoint digest (§11).
Bootstrap confidence interval
resampling-based CI on an eval score, used for regression-gate significance (ADR-19, M10).
Capability artifact
the signed, self-describing package containing a manifest, tensor index, and tensor blobs (§8.1).
CapabilityId
namespaced, versioned, content-addressed identifier for a capability artifact (§11).
Composition policy
CompositionPolicy: STACK/MERGE/ROUTE mode plus ordered capability list (§11, P3).
Conformance fixture
a named input/expected-output pair exercised identically across language surfaces (§12.5, §28).
Content-addressed storage
blob storage keyed by content hash, enabling per-blob dedup (§14, P8).
DARE (Drop And REscale)
merge method dropping and rescaling delta weights by Bernoulli mask (Yu et al. 2024; §8.4, ADR-10).
Digest tree
the hierarchical hash structure covering manifest, tensor index, and blobs, checked at verification (§8.1, I9).
Distillation
producing a new capability for a different base architecture by training against a teacher's outputs (§21).
DistillationJob
lifecycle record for a distillation run: source, target fingerprint, status, result (§11).
Double quantization
QLoRA technique quantizing the quantization constants themselves (Dettmers et al. 2023; §20, ADR-13).
DP-SGD
differentially private SGD bounding per-round privacy loss (Abadi et al. 2016; ADR-15).
Eval gate
the hard promotion check requiring EvalReport to clear a threshold before PUBLISHED (P12, §19).
EvalReport
benchmark scores, confidence intervals, and pass/fail record for a capability (§11).
FedAvg
federated averaging round algorithm (McMahan et al. 2017; ADR-14, §22).
FederatedRound
a bridge round record: participants, privacy budget or secure-agg proof, aggregated delta (§11).
Fidelity margin
the acceptable quality gap between a distilled student and its teacher (M12, §21).
Fulcio
the Sigstore short-lived certificate issuer used in keyless signing (§13, ADR-03).
Hot-swap
replacing a serving node's active adapter set without restarting the base-model process (§16, P5).
In-toto attestation
a signed statement about a build/publish step, providing provenance (ADR-18).
LoRA (Low-Rank Adaptation)
low-rank weight delta ΔW = (α/r)·B·A (Hu et al. 2021; §8.4).
LRU eviction
least-recently-used pool-slot reclamation policy under memory pressure (I10, ADR-08).
Merge-and-freeze
the explicit, logged operation that statically bakes an adapter into base weights, the sole exception to P5.
NF4 (4-bit NormalFloat)
QLoRA's quantized base-weight datatype (§20).
NFE (Number of Forward Evaluations)
count of benchmark forward passes underlying an eval score's bootstrap resampling (§19, ADR-19).
PEFT (Parameter-Efficient Fine-Tuning)
the family of fine-tuning methods adjusting a small parameter subset instead of all weights (Houlsby et al. 2019; §8, §5).
Plan hash
the deterministic hash identifying a ResolvedPlan for caching (§8.6, I4).
Pool slot
a unit of GPU-resident adapter memory tracked by AdapterHandle (§11, I10).
Prefix-tuning
continuous-prompt conditioning as a non-weight-delta capability shape (Li & Liang 2021; §36).
Privacy budget (epsilon/delta)
the DP-SGD spend ledger bounding worst-case membership-inference risk (DPBudget, I11).
Quantization scheme
QuantScheme: the declared base-model quantization dtype family, part of the compatibility fingerprint (§11, P13).
QLoRA
LoRA fine-tuning atop an NF4-quantized frozen base (Dettmers et al. 2023; §20, ADR-13).
Rank (r)
the LoRA low-rank dimension; capacity/size/latency budget knob (§8.2, §34 MM6).
Response-based knowledge distillation
matching student output logits to a teacher's, architecture-agnostic (Hinton et al. 2015; ADR-12).
ResolvedPlan
the deterministic, cacheable output of resolving a ServingRequest's composition against a base (§11, P9).
Secure aggregation
cryptographic protocol combining client updates without revealing individual contributions (Bonawitz et al. 2017; §22, I11).
Signature envelope
SignatureEnvelope: algorithm, signature bytes, cert chain, transparency-log index (§11, §8.1).
Sigstore
keyless signing infrastructure (Fulcio + Rekor) backing artifact signatures (ADR-03).
Soft prompt tuning
learned continuous prompt embeddings as a capability-packaging alternative (Lester, Al-Rfou & Constant 2021; §36).
SGMV (Segmented Gather Matrix-Vector)
batched-kernel strategy for heterogeneous-rank multi-adapter serving (Chen et al. 2024; ADR-07, §17).
SLSA provenance
a build-provenance predicate level standard used in attestations (ADR-18).
Target modules
TargetModuleSet: the named base-model sublayers (e.g. q_proj) an adapter touches (§11, I2).
Task arithmetic
additive composition of task vectors (deltas) across adapters (Ilharco et al. 2023; §8.4, ADR-11).
Tensor index
the ordered array of TensorIndexEntry describing each tensor's offset/shape/digest within an artifact (§8.1, §11).
TIES-Merging
trim + sign-election merge rule reducing interference (Yadav et al. 2023; §8.4, ADR-10).
Tokenizer hash/fingerprint
the digest identifying tokenizer compatibility between adapter and base (§8.2, I6).
Transparency log (Rekor)
the append-only log recording signing events, required by P4/ADR-03's fail-closed policy (§13, T10).
Unified paging
S-LoRA-style single memory pool shared across many adapters, analogous to PagedAttention (ADR-08, §33). ---
