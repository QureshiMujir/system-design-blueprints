  • HQ2. A 3-term OR top-10 query is fast with BMW but a 2-term top-1000 query is faster with MaxScore. Why, and where is that choice made? Resolve via: ADR-06 + Phase 10 (essential/non-essential partition) + Phase 8 (optimizer mode selection) + Back-of-Envelope C3.

Mental Models & First Principles

The compressed insights an expert holds about this system. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — Dynamic pruning is a proof, not a heuristic. A doc is skipped only when its provable upper bound (sum of max_score()/block_max_score()) cannot reach the heap threshold θ. Predicts: pruning correctness hinges entirely on one property — bounds are true upper bounds (INV-1); everything else is just how aggressively you skip. Bug class without it: treating max_score as "approximately the max" → silently dropped top-k hits (FM-2). Applied: Principle 1/2, INV-1/INV-3, Phase 9 — WAND, Phase 10 — BlockMax-WAND + MaxScore.

  • MM2 — A DocIdSetIterator is a monotone cursor; the executor is a lock-step merge of cursors. Every operator (conjunction, disjunction, AndNot, two-phase) is a way to combine monotone streams that only ever move forward. Predicts: any backward advance or non-monotone doc_id() corrupts every operator above it; correctness reduces to one invariant (INV-2) at the leaves. Bug class without it: conjunction sync loops forever, or skips matches, when a leaf returns a doc < the lead. Applied: Principle 3, INV-2, Core Types §11.5–11.6, Phase 4 — Physical Iterator Operators.

  • MM3 — A tighter bound buys more skips but a too-tight bound silently corrupts results; the asymmetry is everything. Loosening a bound only costs latency; tightening it past truth costs correctness. Predicts: BMW (block bounds) skips far more than WAND (global bound) but is more error-prone — invest fuzzing effort proportional to bound tightness. Bug class without it: shipping a block-max bound that is right "almost always" → intermittent recall loss only on certain blocks. Applied: Principle 1/2, INV-1, Phase 5 — BM25 (bound derivation), Phase 10 (block bounds), Phase 3 (expansion bounds).

  • MM4 — Selectivity is the planner's only knowledge of the future; order by it. The rarest clause (lowest df) seen first drives the fewest advance probes — rarest-term-first conjunction ordering is the single highest-leverage plan decision. Predicts: a wrong cardinality estimate yields a slow plan, never a wrong result (the estimate/result firewall); correlated terms (independence assumption fails) are a latency incident, not a correctness one. Bug class without it: ordering by clause text position → the densest term leads → orders of magnitude more decode work. Applied: Principle 7, Phase 7 — Selectivity & Cardinality, Phase 8 — Cost Model + Planner.

  • MM5 — A query planner is a compiler. Text → tokens → AST → logical plan → optimized logical plan → physical plan is exactly lex → parse → IR → optimization passes → codegen; the rewrite engine is a fixpoint simplification pass; plan nodes are an exhaustive IR enum. Predicts: every compiler discipline transfers — total match over node types, equivalence-preserving rewrites, deterministic lowering — and stringly-typed plans rot the same way stringly-typed IR does. Bug class without it: ad-hoc plan handling that silently mishandles a new node type. Applied: Principle 12, Phase 1 — Lexer/Parser/AST, Phase 6 — Rewrite, Phase 8 — Planner.

  • MM6 — A cache is correct only if a hit is indistinguishable from recomputation; the generation key is the proof. Caches add no semantics — a FilterKey/QueryKey that pins the immutable searcher generation guarantees a hit equals a fresh compute. Predicts: every cache correctness bug reduces to a stale key (missing generation, or generation not bumped on reopen), so the cache is contained: worst case, disable it for a pure latency cost. Bug class without it: a filter bitmap reused across a generation that deleted docs → deleted docs resurface (FM-5, INV-6/INV-8). Applied: Principle 14, INV-6/INV-13, Phase 11 — Filters & Caching; also the cheapest oracle is a mock (mock-index, Phase 0).

  • MM7 — At fan-out N, tail latency is the slowest-of-N, not the average. A scatter-gather query is only as fast as its slowest shard; p99 of the whole is driven by the p99 of any single shard amplified by N. Predicts: adding shards improves throughput and per-shard work but worsens tail-latency exposure — so partial results + hedging are not optional features, they are the structural answer to fan-out. Bug class without it: fail-closed on one slow shard → whole-query unavailability; or unbounded waits that ignore the deadline. Applied: Principle 9, INV-9/INV-11, paper P14 (Dean), Phase 12 — Distribution, Scalability Analysis, Back-of-Envelope Capacity Model.

  • MM8 — Stable pagination requires a total order, and the cursor must be that order. Top-k is a partial order on score; pagination needs a total order, so ties break by ascending docId (INV-4) and search_after compares against exactly that (score, docId) tuple. Predicts: any divergence between the heap comparator and the cursor comparator (or any nondeterministic tie-break / float-sum order) makes a doc appear on two pages or none. Bug class without it: search_after dup/skip under equal scores. Applied: Principle 4, INV-4/INV-10, Core Types §11.10, Phase 12 — Pagination.

Glossary · 51 terms · site-wide glossary

Posting list
the list of (docId, freq, [positions]) for one term in one field; the unit of the inverted index.
Inverted index
term → posting list map + term dictionary; the read-only structure the planner queries (index-api).
Term dictionary
sorted/FST map from term bytes to posting-list location + stats; supports prefix/wildcard/fuzzy enumeration by automaton.
FST (finite-state transducer)
minimal acyclic automaton over terms; compact term dictionary enabling automaton-intersection enumeration (ADR-10).
DAAT (Document-At-A-Time)
evaluate all terms' postings in lock-step by ascending docId, scoring each candidate doc fully before moving on; the model WAND/BMW/MaxScore use.
TAAT (Term-At-A-Time)
process one term's whole posting list (accumulating partial scores) before the next; alternative to DAAT, weaker for top-k pruning.
DocIdSetIterator (DISI)
the iterator over a doc-id set; next_doc/advance(target)/doc_id/cost (INV-2).
Conjunction (leap-frog)
AND of iterators: advance the lead (rarest), sync others to it; the doc all share is a match.
Galloping (exponential search)
advancing an iterator far ahead by exponential then binary probing within a block; amortized-cheap advance.
Disjunction
OR of iterators, merged via a min-heap (priority queue) keyed by docId.
AndNot
include-iterator minus exclude-iterator (MUST_NOT exclusion).
Skip list / skip pointers
sparse index over a posting list enabling advance to jump without decoding every block.
Block-max metadata
per-block (e.g. 128-doc) maximum impact/score, enabling block-level skipping (BMW); read via index-api (P10).
Two-phase iterator
cheap approximation (a superset, INV-5) + expensive confirm (matches()); used for phrases/expensive predicates.
Selectivity
fraction of docs a clause matches (≈ df/N); low selectivity (rare) = good lead for conjunction.
Cardinality estimation
predicted #docs a (sub)plan matches; drives ordering, never correctness (Principle 7).
df (document frequency)
#docs containing a term; cf (collection frequency) — total occurrences across the collection.
IDF (inverse document frequency)
ln(1 + (N-df+0.5)/(df+0.5)); rarer terms weigh more; always ≥ 0 (INV-7).
BM25
the probabilistic ranking function (k1, b, IDF, length-norm); the score the planner optimizes around (Robertson & Zaragoza).
k1 / b
BM25 params: k1 = tf saturation, b = length-normalization strength.
Field norm
quantized doc-field length used in BM25 length normalization; must match index-time (INV-12).
Impact / impact-ordered postings
postings ordered by score contribution rather than docId; enables score-at-a-time pruning (optional, ImpactsMeta).
Top-k
the k highest-scoring docs; maintained in a fixed-capacity min-heap (root = least competitive).
Threshold (θ) / min-competitive score
the heap root's score; the bar a doc must beat to enter top-k; rises as the heap fills; feeds pruning (INV-3).
WAND
Weak-AND / pivot pruning: skip docs whose summed term upper bounds can't reach θ (Broder 2003).
BlockMax-WAND (BMW)
WAND refined with per-block upper bounds to skip whole blocks (Ding & Suel 2011); production default (ADR-06).
MaxScore
partition terms into essential/non-essential by upper bound; iterate only essentials, probe non-essentials when they could compete (Turtle & Flood 1995).
Pivot
in WAND, the doc/term at which accumulated upper bounds first reach θ; the next candidate to consider.
Safe pruning
pruning that provably never changes the top-k vs exhaustive (depends on true upper bounds, INV-1/INV-3).
Upper bound (max_score / block_max_score)
a value ≥ any real score the scorer can produce (for the block); the pruning contract (INV-1, Principle 2).
Exhaustive DAAT baseline
scoring every match with no pruning; the correctness oracle for INV-3 (--exact).
Predicate pushdown / filter-before-score
applying a non-scoring filter (bitset) before scoring so only passing docs are scored (Principle 6).
Filter vs query
a filter constrains (0/1, cacheable, no score); a query ranks (scored). FILTER occur (RW-10).
ConstantScore
wraps a matcher to contribute a fixed score (no per-doc scoring); used for filters + over-limit expansions.
Roaring bitmap
compressed doc-id-set representation (array/bitmap/run containers) for the filter cache; fast and/or/andnot/rank/select (ADR-08).
Plan cache
cache of the optimized physical plan shape for repeated query shapes (optimizer is pure, INV-10).
Query cache
optional cache of merged top-k results per (query, shard, generation) (INV-6/INV-13).
EXPLAIN
first-class output: the physical plan tree + estimated-vs-actual cardinality + per-doc BM25 score breakdown (Principle 10).
Plan dump
textual/JSON rendering of the chosen physical plan + costs + prune mode; the operator's window into the planner.
Generation
a monotonic id for an immutable searcher snapshot; the cache key (INV-6) and reproducibility anchor.
Live-docs
bitset marking non-deleted docs; deletes are logical until merge; results must honor it (INV-8).
Segment
an immutable sub-index; queries execute per segment then merge (Principle 13).
Shard
a horizontal partition of the collection across nodes; scatter-gather queries fan out to shards.
Scatter-gather (query-then-fetch)
the distributed protocol: query phase gathers top-k ids+scores, fetch phase retrieves the docs (P12).
Partial results
a degraded result (some shards missing) flagged partial: true instead of failing (Principle 9, INV-9).
search_after
cursor-based deep pagination using the (score, docId) of the last seen doc under the INV-4 total order.
track_total_hits
controls total-hit counting: exact, capped-at-N (AtLeast), or early-terminated.
Levenshtein automaton
DFA accepting all strings within edit distance k of a term; intersected with the FST for fuzzy enumeration (Schulz & Mihov, ADR-11).
maxExpansions
bound on multi-term (wildcard/prefix/fuzzy) expansion; over-limit → ConstantScore bitset (RW-7).
Slop
the positional tolerance of a phrase query (max term displacement); slop 0 = exact phrase.
Analysis parity
query-time analysis matching index-time analysis; required or recall silently drops (Principle 11).
