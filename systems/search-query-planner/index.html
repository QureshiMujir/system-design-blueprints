One paragraph per box.

(A) Lexer. Converts DSL text into a token stream (terms, operators + - AND OR NOT, field separators :, quote ", range brackets [ ] { }, TO, wildcard * ?, fuzzy ~, boost ^, parens, whitespace). Tracks byte spans for error reporting. Handles escaping (\:, \"). Pure, deterministic, no index access. Owns no state beyond the cursor.

(B) Parser. Recursive-descent + Pratt precedence for boolean operators; produces the query AST (§8). Resolves operator precedence (NOT > AND > OR; explicit grouping overrides), default operator (OR or AND configurable), +/- must/must-not semantics. Error recovery: on malformed token, emits a diagnostic with span and attempts resync at the next clause boundary. No analysis yet — terms are raw.

(C) Query-time analysis. Applies the field's analyzer chain to term/phrase text: tokenize, lowercase, stem, stopword removal, synonym expansion. A single TermQuery("running") may become TermQuery("run") (stemming) or a synonym SynonymQuery/disjunction. Must mirror index-time analysis or recall breaks. Stateless given the analyzer config; reads no postings.

(D) Rewrite/Normalize. Algebraic simplification on the analyzed AST: flatten nested booleans of same type, dedupe identical clauses, push NOT down (De Morgan where it lowers cost), drop empty clauses, promote subtrees that don't need scoring into ConstantScoreQuery. Idempotent rewrite-rule engine; each rule is cost-monotone or cost-neutral. Pure AST->AST.

(E) Expansion. Turns multi-term queries (wildcard te*, prefix, fuzzy term~2) into concrete term sets by walking the term dictionary FST under an automaton (prefix DFA, Levenshtein-k DFA). Bounds expansion (max-expansions); above the bound, rewrites to ConstantScoreQuery over a bitset to avoid scoring blow-up. Reads the term dictionary (an index-api call) but not postings.

(F) Statistics / Catalog. Per-collection and per-term stats: doc-count N, document frequency df(t), collection frequency cf(t), sum of doc lengths, average field length, field norms summary. Source: index-api (precomputed at index time). Feeds IDF (scoring), selectivity (optimizer), and clause cost. Read-mostly, cached per searcher generation.

(G) Logical planner. Lowers the rewritten AST into a logical operator tree (LogicalScan(term), LogicalAnd, LogicalOr, LogicalNot, LogicalConstantScore, LogicalPhrase). Decouples what (logical) from how (physical). Annotates each node with estimated cardinality from (F).

(H) Cost-based optimizer. Rewrites/reorders the logical plan to minimize estimated cost: orders conjunction children rarest-first (lowest df leads, drives leap-frog), chooses per-node physical strategy (sorted bitset intersection vs leap-frog iterator vs PQ disjunction vs MaxScore), decides whether a clause is a filter (cacheable bitset, no score) or a scored query, and selects the pruning algorithm (WAND vs BMW vs MaxScore vs none). Uses a clause cost model (Phase 8). Produces an annotated physical plan request.

(I) Physical plan builder. Instantiates concrete Scorer/DocIdSetIterator objects from the optimized plan: Bm25Scorer leaves, ConjunctionIterator (leap-frog), DisjunctionIterator (PQ), WandScorer/BlockMaxWandScorer/MaxScoreScorer, TwoPhaseIterator wrappers for phrases/expensive predicates, ConstantScoreScorer for filters. Binds postings handles from index-api. Per segment.

(J) Executor. Drives the iterator tree to completion per segment. DocIdSetIterator advances monotonically (next_doc, advance(target)). Conjunctions leap-frog (advance the lead, sync others, gallop). Disjunctions merge via a PQ keyed by docId. Two-phase iterators do cheap matches()/approximation() then expensive confirm(). Dynamic pruning (WAND/BMW/MaxScore) uses scorer upper bounds + the collector's current min-competitive score to skip docs/blocks. Single-threaded per segment; parallel across segments.

(K) Scoring. Computes per-doc relevance: BM25 with parameters k1, b, IDF form, doc-length norm (field norm, quantized). Each Scorer exposes score(), max_score() (a true upper bound — safety invariant), and block-level block_max_score() for BMW. explain() produces a tree of score contributions for debugging/tuning. Composed bottom-up matching the iterator tree.

(L) Collector / top-k heap. Maintains the running top-k via a min-heap of size k keyed by (score, docId). Exposes the current min-competitive score (heap root) back to (J) so pruning can raise its threshold as the heap fills. Tie-break deterministically by ascending docId (or a configured secondary sort). Also counts total hits subject to track_total_hits (exact, capped, or approximate via early termination).

(M) Segment/shard coordinator. Within a node: schedules per-segment executor tasks across a thread pool, merges segment top-ks into a node top-k. Across nodes: the query phase scatters the query to each shard, gathers per-shard top-k doc ids + scores, merges to a global top-k; the fetch phase asks the owning shards for the actual documents/fields of the global top-k. On timeout or shard failure, returns partial results with a partial: true flag and which shards were missing.

(N) Caches. Filter cache: Roaring bitmaps of doc-id sets for cacheable filter clauses (e.g. status:active), keyed by (segment-generation, filter), cost-aware LRU eviction. Query cache: optional cache of fully-scored top-k per (query, shard, generation) for repeated queries; conservative, invalidated on generation bump. Both bounded by a memory ceiling (§4).

8. Domain Model / Source Language

The query DSL (string form) plus its JSON form share one AST. Below: tokens, EBNF, AST catalog, rewrite/normalization rules, worked + malformed + failure-path examples.

8.1 Tokens

Token Lexeme Notes
TERM cat, running, escaped \: unquoted word; analyzed later
PHRASE "quick brown" quoted; optional ~slop
FIELD title: identifier + :
AND / OR / NOT AND OR NOT (case-insensitive) boolean operators
MUST / MUST_NOT +term / -term prefix occur flags
LPAREN / RPAREN ( ) grouping
LBRACK/RBRACK [ ] inclusive range
LBRACE/RBRACE { } exclusive range
TO TO range separator
WILDCARD te*t, te?t * (≥0), ? (1)
PREFIX te* special wildcard at end
FUZZY term~, term~2 optional edit distance (default 2, max 2)
BOOST ^2.0 float multiplier on preceding clause
STAR * match-all when standalone
WS spaces separates clauses; default operator applies

Escaping: backslash escapes any operator char (\+ \- \: \" \( \) \[ \] \{ \} \* \? \~ \^ \\). Unterminated phrase / unmatched bracket -> lexer/parser diagnostic with byte span.

8.2 EBNF Grammar

query        = disjunction ;
disjunction  = conjunction , { "OR" , conjunction } ;          (* default op configurable *)
conjunction  = unary , { [ "AND" ] , unary } ;                 (* juxtaposition = default op *)
unary        = [ occur ] , boostable ;
occur        = "+" | "-" | "NOT" ;                             (* + must, - / NOT must_not *)
boostable    = primary , [ "^" , float ] ;
primary      = group | fielded | clause ;
group        = "(" , query , ")" ;
fielded      = field , ":" , ( group | clause ) ;
field        = identifier ;
clause       = phrase | range | term_clause | matchall ;
matchall     = "*" ;
phrase       = '"' , { token } , '"' , [ "~" , uint ] ;        (* ~slop *)
range        = ( "[" | "{" ) , range_end , "TO" , range_end , ( "]" | "}" ) ;
range_end    = term | "*" ;                                    (* * = unbounded *)
term_clause  = term , [ fuzzy | wildcard_marker ] ;
fuzzy        = "~" , [ uint ] ;                                (* default 2, clamp ≤2 *)
term         = identifier_with_wildcards ;                     (* may contain * ? -> wildcard/prefix *)
float        = digit , { digit } , [ "." , { digit } ] ;
uint         = digit , { digit } ;
identifier   = letter , { letter | digit | "_" | "." | "-" } ;

Precedence (high->low): grouping/field-scope > boost ^ > unary occur (+ - NOT) > implicit/AND > OR. Default operator (when two clauses are juxtaposed with no operator) is configurable: OR (Lucene default) or AND (more precise). Locked default: OR, overridable per request.

8.3 Query AST Catalog

AST node Fields Scored? Notes
MatchAllQuery (boost) constant matches every live doc
TermQuery field, term yes (BM25) leaf; the workhorse
PhraseQuery field, [terms], slop yes positional; two-phase
BooleanQuery [(occur, sub)], minShouldMatch yes occur ∈ {MUST,SHOULD,MUST_NOT,FILTER}
WildcardQuery field, pattern (* ?) rewrites -> expansion (Domain Model §8.5)
PrefixQuery field, prefix rewrites -> expansion
FuzzyQuery field, term, maxEdits, prefixLen rewrites -> Levenshtein DFA expansion
RangeQuery field, lo, hi, loIncl, hiIncl rewrites/filter numeric or term range
ConstantScoreQuery sub constant wraps a matcher, no per-doc scoring
BoostQuery sub, boost scaled multiplies sub's score by boost
SynonymQuery field, [terms] yes post-analysis; blended IDF

occur semantics inside BooleanQuery:

  • MUST (+): must match; contributes to score. AND lowers to all-MUST.
  • SHOULD: optional; contributes to score; minShouldMatch controls how many SHOULD must match (default 0 if any MUST present, else 1).
  • MUST_NOT (-/NOT): must not match; no score; excludes.
  • FILTER: must match; no score (constant); cacheable. Produced by the optimizer from non-scoring constraints.

8.4 Rewrite / Normalization Rules (analyzed AST -> normalized AST)

Rule Transform Guard
RW-1 analyze term/phrase text -> analyzer tokens (lowercase/stem/stop/synonym) per field analyzer
RW-2 flatten BooleanQuery whose child is same-occur BooleanQuery -> merge only MUST∪MUST, SHOULD∪SHOULD
RW-3 dedupe identical sibling clauses collapse (sum boosts) structural equality
RW-4 NOT push-down NOT (A OR B) -> NOT A AND NOT B (De Morgan) only if it lowers estimated cost
RW-5 single-clause unwrap BooleanQuery with one MUST/SHOULD -> the clause preserve boost
RW-6 empty drop clause that analyzed to empty (all-stopwords) -> remove warn if whole query empties
RW-7 const-score promote WildcardQuery/PrefixQuery/RangeQuery exceeding maxExpansions -> ConstantScoreQuery over bitset expansion > threshold
RW-8 boost fold BoostQuery(BoostQuery(x,a),b) -> BoostQuery(x,a*b) always
RW-9 matchall absorb A AND MatchAll -> A; A OR MatchAll -> MatchAll always
RW-10 filter classify SHOULD/MUST clause with no scoring need (e.g. ConstantScore, term used only to constrain) -> FILTER occur optimizer pass

All rules idempotent; the rewrite engine iterates to fixpoint (bounded iterations).

8.5 Expansion (multi-term) — worked

title:te* (prefix) -> walk term-dict FST from prefix te -> enumerate {tea, team, tech, ...} -> if count ≤ maxExpansions: BooleanQuery(SHOULD: TermQuery(tea), TermQuery(team), ...) (each scored, blended); else: ConstantScoreQuery over the union bitset (no per-term scoring; one constant score).

name:jon~2 (fuzzy, maxEdits=2) -> build Levenshtein-2 DFA for jon -> intersect DFA with term-dict FST -> enumerate terms within edit distance 2 {jon, john, joan, jan, ...} -> bounded the same way; scores blended, optionally distance-weighted boost.

8.6 Worked Examples (string -> AST -> normalized)

  1. title:"quick brown"~1 +body:fox -status:archived -> Boolean[ SHOULD PhraseQuery(title,[quick,brown],slop=1), MUST TermQuery(body,fox), MUST_NOT TermQuery(status,archived) ] After RW-10: status:archived MUST_NOT stays exclusion (no score). body:fox MUST scores; phrase SHOULD scores.

  2. (cat OR dog) AND color:black^2 -> Boolean[ MUST Boolean[SHOULD TermQuery(_default,cat), SHOULD TermQuery(_default,dog)], MUST BoostQuery(TermQuery(color,black), 2.0) ].

  3. price:[10 TO 50} -> RangeQuery(price, 10, 50, loIncl=true, hiIncl=false) -> if dense, optimizer makes it a FILTER (cacheable bitset, constant score).

8.8 Failure-Path Examples

  • Whole query analyzes to empty (all stopwords, e.g. the of a) -> RW-6 empties it -> return zero hits + W-SEM-EMPTY, not an error.
  • Wildcard * leading (*cat) -> very expensive; default rejected with E-SEM-LEADING-WILDCARD unless allow_leading_wildcard=true.
  • Fuzzy expansion exceeds maxExpansions and the field is huge -> RW-7 to ConstantScore bitset; if even the bitset would exceed the memory ceiling -> E-RESOURCE-EXPANSION, reject with guidance.
  • Field unknown in schema -> E-SEM-UNKNOWN-FIELD (or match-nothing, configurable; locked: warn + match-nothing).

Design principles (§6)

  • Correctness before speed; pruning must be provably safe. Dynamic pruning may skip a doc only if it provably cannot enter top-k. Tradeoff: safe upper bounds are looser than exact, so fewer skips. Operational: a --exact flag disables all pruning to A/B verify results. Violation: a scorer whose max_score() underestimates -> WAND skips a true top-k hit -> silent recall loss (the worst class of bug).
  • Scorer upper bounds are a contract, not a hint. max_score() (and block_max_score()) MUST be ≥ any real score the scorer can produce for any doc (in the block). Tradeoff: computing tight-yet-safe bounds is subtle (BM25 monotonicity). Operational: invariant check INV-1 fuzzes score ≤ max_score on every doc in conformance. Violation: see #1.
  • Iterators advance monotonically. next_doc/advance(target) never go backward; advance(t) lands on the first doc ≥ t. Tradeoff: forces leap-frog/galloping discipline; no random access. Operational: debug assertions on doc-id monotonicity in dev builds. Violation: non-monotonic advance -> conjunction sync loops forever or skips matches.
  • Determinism: identical query + identical index generation -> identical ranked ids and scores. Tie-break by ascending docId. Tradeoff: secondary sorts cost a comparator. Operational: stable pagination depends on this; search_after correctness relies on it. Violation: nondeterministic tie-break -> the same doc appears on two pages or is skipped.
  • Two-phase approximation is always a superset. A TwoPhaseIterator's approximation must match a superset of true matches; confirm() removes false positives. Tradeoff: approximation cost vs how many false positives confirm must reject. Operational: phrase queries, expensive predicates use this. Violation: approximation missing a true match -> recall loss that pruning cannot detect.
  • Filters do not score. A clause used only to constrain (not rank) is evaluated as a 0/1 bitset and contributes constant score. Tradeoff: must classify clauses (filter vs query) correctly in the optimizer. Operational: filters are cacheable (Roaring); queries generally are not. Violation: scoring a filter wastes CPU and pollutes relevance; caching a scored query returns stale scores.
  • Cost estimates drive ordering, never correctness. A wrong cost estimate yields a slower plan, never a wrong result. Tradeoff: invest in good df-based estimates but never let them gate output. Operational: a bad estimate is a perf incident, debuggable via plan dump; not a correctness incident. Violation: conflating "estimated empty" with "is empty" -> dropping a clause.
  • Bounded resource usage; every loop has a deadline. Timeout budget propagates to every shard and every segment task; checked at block boundaries. Tradeoff: deadline checks add a branch in the hot loop (amortized per block, not per doc). Operational: partial results on deadline, never a hung query. Violation: an unbounded fuzzy expansion or deep-page sort OOMs or stalls the pool.
  • Backpressure + partial results over failure. A slow/failed shard degrades the result (flagged partial), it does not fail the request. Tradeoff: callers must handle partial results. Operational: SLO favors availability; partial is a first-class field + metric. Violation: fail-closed on one slow shard -> whole-query unavailability.
  • Observability by default: every query can explain its plan and its score. explain() for scores; plan dump for the chosen physical plan + costs + pruning mode. Tradeoff: explain path is slower; gated by a request flag. Operational: "why is this slow / why did this rank here" is answerable without a debugger. Violation: opaque planner -> unfixable relevance/latency incidents.
  • Analysis parity: query-time analysis must match index-time analysis. Same tokenizer/stemmer/normalizer or recall silently drops. Tradeoff: analyzer config is shared state between indexer (out of scope) and planner. Operational: analyzer version stamped in catalog; mismatch warns. Violation: query stems "running"->"run" but index stored "running" -> zero matches.
  • Plan nodes are an explicit, exhaustive type. Logical and physical plans are enums; the optimizer is a total match. Tradeoff: adding a node touches all match sites (compiler-enforced completeness — a feature). Operational: no "unknown node" runtime path. Violation: stringly-typed plans -> silent mishandling of a new node.
  • Segment isolation; merge is the only cross-segment step. Each segment executes independently to a local top-k; the coordinator merges. Tradeoff: per-segment overhead (small heaps) vs trivial parallelism + isolation. Operational: one corrupt/slow segment is contained. Violation: shared mutable scorer across segments -> data races, nondeterminism.
  • Caches are correctness-neutral and generation-keyed. A cache hit must equal recomputation; all caches key on the immutable searcher generation. Tradeoff: generation bump invalidates caches (cold start). Operational: never serve a cached bitset/score from a stale generation. Violation: reusing a filter bitmap across a generation that deleted docs -> returns deleted docs.
  • Reference-equivalence is the bar. For the supported query subset, results must match a reference engine (Lucene/Tantivy) modulo documented score-formula differences. Tradeoff: constrains scoring-formula freedom. Operational: differential tests gate release (Phase 12). Violation: "looks reasonable" scoring with no oracle -> undetectable ranking regressions.
