⬜ Phase 0 — Repository, Governance, and `index-api` Skeleton

Objectives
  • Stand up the Cargo workspace (ADR-19), all 15 crate stubs, CI, lint, license gate.
  • Define index-api traits (§11.12) and a working in-memory mock-index + JSON fixture loader — every later phase tests against this, no real index required.
  • Lock governance: invariant checklist (INV-1..13) in CONTRIBUTING.md, ADR template, runbook template, perf-baseline harness shell.
Deliverable
  • cargo build green across the workspace; cargo test -p index-api runs mock-index contract tests; make plan-viz is a no-op stub; a fixture corpus exists and loads into a mock-index queryable by a hand-written postings walk.
Acceptance
  • All crates compile; clippy clean (-D warnings); MSRV job passes.
  • Mock index: build a 1,000-doc fixture, verify df, cf, N, postings membership, live-docs filtering, FST lookup + prefix enumerate all match a brute-force oracle over the JSON.
  • deny.toml passes (no GPL, no yanked/advisory deps).
Fixtures
  • corpus/tiny_10.json (10 docs, hand-verifiable), corpus/small_1k.json, corpus/with_deletes.json (live-docs), corpus/positions.json (phrase-ready). Each ships a *.expected_stats.json (df/cf/N) golden.
  • Malformed: corpus/dup_docids.json (must reject at build), corpus/empty_field.json.
Pitfalls
  • FST mock too clever — manifestation: prefix enumeration bugs masked by mock quirks. Root cause: mock diverges from real FST semantics. Debug: assert enumeration == linear scan of sorted terms under the same automaton. Instrument: mock_fst_enum_mismatch_total. Recovery: keep mock dead-simple (linear scan), correctness over speed.
  • Nondeterministic doc order — manifestation: flaky tie-break tests later. Root cause: hashmap iteration when assigning docids. Debug: assert docids == insertion order. Fix: BTreeMap/explicit ordering.
  • PostingsOptions ignored — manifestation: phrase tests "work" on a DocsOnly handle by accident. Root cause: mock always loads positions. Debug: assert positions absent unless DocsFreqsPositions.
  • Stats off-by-one — sum_total_term_freq vs sum_doc_freq confusion → wrong IDF later. Debug: cross-check both against oracle.

⬜ Phase 1 — Query Lexer, Parser, and AST

Objectives
  • Full DSL lexer (Domain Model §8.1) and recursive-descent + Pratt parser (Domain Model §8.2) producing the raw query AST (Query<String>, Core Types §11.2).
  • Error recovery + coded diagnostics (Domain Model §8.7); JSON DSL ↔ AST round-trip (ADR-16). No analysis, no index access.
Deliverable
  • parse(&str) -> (Option<Query<String>>, diagnostics); JSON DSL parse/emit; examples/ can print an AST. CLI tools/ parse-dump.
Acceptance
  • Grammar corpus (≥120 queries) parses to expected AST (golden-compared).
  • Round-trip: for all valid fixtures, parse(print(q)) == q and json->ast->json stable.
  • Malformed corpus (Domain Model §8.7) yields the exact diagnostic codes; zero panics (enforced by the P15 fuzzer, smoke-tested here).
  • Precedence table verified: a OR b AND c == a OR (b AND c); +a -b c occur flags correct; ^ binding correct.
Fixtures
  • queries/P1_grammar.jsonl (input → AST golden), queries/P1_precedence.jsonl, queries/P1_malformed.jsonl (input → diagnostic code), queries/P1_roundtrip.jsonl, queries/P1_json_dsl.jsonl.
Pitfalls
  • Boost binding ambiguity — a^2 b vs (a b)^2: manifestation wrong scores later. Root cause: ^ precedence. Debug: print AST; assert boost attaches to primary not the clause list.
  • Default-operator drift — silently switching OR/AND between string and JSON forms. Debug: assert both honor QueryConfig.default_op.
  • Greedy phrase lexing — unterminated " eats to EOF. Root cause: no resync. Debug: emit E-LEX-01 with the open-quote span; recover by closing at EOL.
  • Escaping holes — \* treated as wildcard. Debug: lexer must lower escaped operator chars to literal TERM bytes.
  • Field vs term colon — http://x mis-parsed as field http. Debug: only treat ident: as a field when followed by a clause; escape rule for URLs.

⬜ Phase 2 — Index Read Interface Binding + Query-Time Analysis

Objectives
  • Resolve Query<String> → Query<FieldId> against a schema; bind to a SegmentReader.
  • Query-time analysis (Domain Model §8.4 RW-1, §11): tokenize/lowercase/stem/stopword/synonym, mirroring index-time analysis (Principle 11). Establish analysis-parity testing.
Deliverable
  • analyze(Query<String>, &Schema) -> Query<FieldId> (analyzed); a Searcher::open(reader); example binds the mock index and analyzes a query.
Acceptance
  • Analysis-parity fixtures: for a corpus indexed with analyzer A, query-time analysis with A produces tokens that match the indexed terms (recall = 100% on the parity set).
  • Stemming/lowercasing/stopword behavior matches a golden token stream.
  • Unknown field → documented behavior (match-nothing + warning), not an error.
  • Analyzer-version mismatch surfaces W-ANALYZER-VERSION.
Fixtures
  • queries/P2_analysis.jsonl (raw term → analyzed tokens golden), P2_parity.jsonl (index analyzer == query analyzer recall check), P2_synonyms.jsonl, P2_stopwords.jsonl, P2_unknown_field.jsonl.
Pitfalls
  • Analysis asymmetry — query stems but index didn't (or different stemmer). Manifestation: silent zero results. Root cause: analyzer config drift (Principle 11). Debug: dump query tokens vs terms() enumeration; check analyzer version. Instrument: analysis_parity_miss_total. Recovery: align analyzer; warn loudly.
  • Stopword over-removal — query becomes empty. Manifestation: "no results for 'the who'". Debug: detect all-stopword, keep at least the original term or warn (config).
  • Synonym IDF blow-up — naive synonym OR inflates scores. Root cause: each synonym scored independently. Debug: use blended IDF (SynonymQuery), not raw disjunction.
  • Multi-token term — wi-fi → wi,fi: should it be phrase or AND? Config-driven; document and test both.

⬜ Phase 3 — Term Expansion (Wildcard / Prefix / Fuzzy)

Objectives
  • Expand Wildcard/Prefix/Fuzzy/Range queries to concrete term sets via FST enumeration under an automaton (prefix DFA, glob NFA→DFA, Levenshtein-k DFA), bounded by maxExpansions with RW-7 const-score promotion (Domain Model §8.5).
Deliverable
  • expand(Query<FieldId>, &SegmentReader, &QueryConfig) -> Query<FieldId> (expanded); examples show te* and jon~2 expansions + the const-score fallback.
Acceptance
  • Prefix/wildcard/fuzzy enumerations match a brute-force scan of the term dictionary under the same predicate (differential).
  • maxExpansions honored; over-limit → const-score bitset; over-budget → ExpansionTooLarge.
  • Levenshtein correctness: enumerated terms are exactly those within edit distance ≤ k (verified vs naive DP).
  • Leading wildcard rejected by default; allowed under flag.
Fixtures
  • queries/P3_prefix.jsonl, P3_wildcard.jsonl, P3_fuzzy.jsonl (each: pattern → expected term set golden), P3_overlimit.jsonl (→ const-score), P3_overbudget.jsonl (→ error), P3_leading_wildcard.jsonl.
Pitfalls
  • Automaton/FST desync — enumeration misses or over-includes terms. Root cause: subtle DFA transition bug. Debug: diff vs naive scan; visualize the DFA (tools/). Instrument: expansion_mismatch_total.
  • Fuzzy explosion — a~2 on a huge dict enumerates millions. Root cause: no prefix_len, low selectivity. Debug: cap + const-score fallback; require prefix_len ≥ 1 for short terms (config).
  • Levenshtein off-by-one — includes distance-3 terms. Debug: cross-check the universal automaton against textbook DP for a sample.
  • Const-score score discontinuity — same query scores differently above/below maxExpansions (scored disjunction vs constant). Document as expected; test both branches; warn in explain().
  • Leading-wildcard footgun — *term accidentally allowed → full-dict scan. Debug: default-reject; require explicit opt-in.

⬜ Phase 4 — Physical Iterator Operators (Conjunction / Disjunction / AndNot / Skip)

Objectives
  • The executor core (Core Types §11.5–11.6): DocIdSetIterator, leaf PostingsIterator binding, ConjunctionIterator (leap-frog + galloping), DisjunctionIterator (PQ), AndNotIterator, skip-list/advance usage. No scoring yet — pure boolean matching to validate iterator algebra (INV-2) before scoring/pruning layer on top.
Deliverable
  • A boolean matcher: given an expanded Query<FieldId> (no scoring), enumerate matching doc ids per segment via the iterator tree. examples/embed_search.rs prints matching ids for +a +b -c.
Acceptance
  • For all boolean fixtures, iterator-tree doc-id set == brute-force set intersection/union/difference over postings (differential).
  • INV-2 (monotonic advance) holds under a dev-build assertion across the whole corpus + fuzz (iterator_monotonic target smoke).
  • Live-docs honored (INV-8): deleted docs never emitted.
  • advance(target) lands on first doc ≥ target (skip correctness) — verified against linear scan.
Fixtures
  • queries/P4_conjunction.jsonl, P4_disjunction.jsonl, P4_andnot.jsonl, P4_skip.jsonl (advance targets → landing doc golden), P4_livedocs.jsonl (deletes excluded), P4_matchall.jsonl.
Pitfalls
  • Conjunction restart loop — lead never converges. Root cause: a child returns a doc < lead (INV-2 violation) or off-by-one in sync. Debug: log (lead, child, returned) on each sync; assert monotonicity. Recovery: fail fast in dev.
  • Disjunction current-matchers wrong — heap pops the wrong subset → scoring/positions later use wrong children. Debug: assert all popped children have doc_id == current.
  • Galloping overshoot — binary search lands past the target. Debug: invariant result ≥ target; unit-test the gallop boundary.
  • Skip-list misuse — advance decodes a full block when a skip pointer existed. Manifestation: latency, not wrong results. Debug: count blocks decoded vs skipped (postings_blocks_decoded_total).
  • AndNot exclude desync — exclude iterator advanced past then can't go back. Root cause: exclude shared/advanced incorrectly. Debug: exclude must only ever advance forward to the include's current doc.

⬜ Phase 5 — BM25 Scoring, Weight Factory, Top-K Collector (Exhaustive Baseline)

Objectives
  • Scoring (Core Types §11.7): Similarity/Weight/Bm25Scorer with k1/b, IDF, field-norm; explain() tree; max_score() as a true upper bound (INV-1). Top-k collector (Core Types §11.10): min-heap, deterministic tie-break (INV-4), track_total_hits. This is the exhaustive DAAT baseline — score every match, no pruning — the oracle for INV-3.
Deliverable
  • End-to-end exhaustive ranked search over the mock index: query → expanded AST → physical scorer tree → top-k ranked (doc, score) with explain(). examples/explain_query.rs prints the explanation tree.
Acceptance
  • BM25 numeric oracle: for hand-computed fixtures (known df/tf/len/N), scores match to f32 tolerance.
  • INV-1: fuzz score(d) ≤ max_score() for all d (smoke here, full in P15) — zero violations.
  • INV-4: same query twice → byte-identical ranked ids (deterministic tie-break).
  • INV-7: all scores finite, ≥0.
  • explain() value == score() for the explained doc (tree sums correctly).
  • Differential vs reference (Lucene/Tantivy) BM25 ranking on the shared corpus modulo documented formula constants (Principle 15).
Fixtures
  • queries/P5_bm25_oracle.jsonl (df/tf/len → expected score), P5_topk.jsonl (query → ranked ids+scores golden), P5_tiebreak.jsonl (equal-score docs → ascending-doc order), P5_total_hits.jsonl, P5_explain.jsonl (explanation tree golden), P5_ref_diff.jsonl (vs Lucene/Tantivy export).
Pitfalls
  • Loose max_score kills future pruning — manifestation: WAND barely skips in P9. Root cause: bound uses global-min norm regardless of which docs the term hits. Debug: compare bound to observed max score per term; tighten with per-term norm stats if available. (Still must stay a true bound — INV-1 first.)
  • IDF negative — df > N (stale stats) → negative IDF → negative score (breaks INV-7 + heap). Debug: clamp IDF ≥ 0; root-cause the stat.
  • Tie-break instability — heap pops in nondeterministic order for equal scores. Root cause: comparator ignores doc id. Debug: assert ScoreDoc Ord includes doc asc; run twice and diff.
  • Norm decode mismatch — wrong quantization table → wrong length → wrong score (INV-12). Debug: explain() shows norm; compare to index-time value.
  • SHOULD scoring with minShouldMatch — clauses that don't meet the threshold still scored. Debug: enforce minShouldMatch before scoring contribution.
  • Heap "full" semantics — first k docs must all enter regardless of score; only after full does min_competitive gate. Debug: test with k > #matches.

⬜ Phase 6 — Query Rewriting / Normalization + Boolean Simplification

Objectives
  • The rewrite engine (Domain Model §8.4, Core Types §11.3): RW-2..RW-10 — flatten, dedupe, NOT push-down (De Morgan), single-clause unwrap, empty drop, const-score promote, boost fold, matchall absorb, filter classify. Idempotent, cost-monotone (Principle 7), to fixpoint.
Deliverable
  • rewrite(Query<FieldId>) -> Query<FieldId> (normalized, fixpoint); plan-dump shows pre/post-rewrite AST. Examples demonstrate flatten/dedupe/NOT-pushdown/const-score.
Acceptance
  • Idempotence: rewrite(rewrite(q)) == rewrite(q) for all fixtures.
  • Semantic equivalence: rewritten query returns the same doc set + scores as the unrewritten query (differential vs P5 baseline) — rewrite changes shape, never results (except documented const-score relevance cliffs and empty-drop).
  • Cost-monotonicity: estimated cost of rewritten ≤ original (where stats exist; P8 closes the loop).
  • Fixpoint terminates within max_iters; adversarial nesting bounded.
Fixtures
  • queries/P6_flatten.jsonl, P6_dedupe.jsonl, P6_demorgan.jsonl, P6_unwrap.jsonl, P6_empty_drop.jsonl, P6_const_promote.jsonl, P6_idempotence.jsonl, P6_equivalence.jsonl (rewritten vs baseline doc set).
Pitfalls
  • Rewrite changes results — a rule isn't actually equivalence-preserving. Manifestation: differential mismatch vs baseline. Root cause: e.g. De Morgan on a SHOULD with minShouldMatch, or dedupe collapsing clauses with different boosts. Debug: run rewritten vs unrewritten through P5, diff; bisect rules. Instrument: rewrite_equivalence_mismatch_total. Recovery: disable the offending rule.
  • Non-idempotent rule — fixpoint never reached → hits max_iters. Root cause: two rules undo each other (flatten ↔ unwrap). Debug: log rule firing sequence; assert convergence.
  • Dedupe boost loss — collapsing a^2 and a^3 to one. Debug: sum/choose boosts per documented semantics; test.
  • Empty-query surprise — RW-6 silently empties a query. Debug: emit W-SEM-EMPTY; never silent.
  • Filter misclassification — classifying a scored clause as FILTER → relevance changes. Root cause: RW-10 heuristic too aggressive. Debug: only classify clauses provably score-irrelevant; differential check.

⬜ Phase 7 — Statistics / Catalog + Selectivity & Cardinality Estimation

Objectives
  • The catalog (Core Types §11.8): per-generation cached stats (df, cf, N, sum_tf, avg_len, norms summary) from index-api; selectivity + cardinality estimation for the optimizer (Core Types §11.9). Estimates drive ordering, never correctness (Principle 7).
Deliverable
  • StatsProvider with cached stats + estimate_cardinality(LogicalOp) -> u64; plan dump annotates each node with estimated cardinality. Examples print estimates for a boolean query.
Acceptance
  • Stats correctness: cached df/cf/N == index-api source == brute-force over the corpus.
  • Estimation sanity: estimated cardinality is within an order of magnitude of actual on the fixture set (estimates need only be good enough to order, not exact).
  • Estimates are monotone where expected (adding a MUST clause never increases conjunction estimate).
  • Generation bump invalidates the cache (INV-6); no stale stats served.
Fixtures
  • queries/P7_stats.jsonl (term → df/cf golden), P7_card_conj.jsonl, P7_card_disj.jsonl, P7_card_andnot.jsonl (logical op → estimated vs actual), P7_generation.jsonl (stat refresh on bump).
Pitfalls
  • Independence assumption wildly off — correlated terms (e.g. "new york") → conjunction grossly over-/under-estimated. Manifestation: suboptimal ordering (slow, not wrong). Root cause: independence assumption. Debug: log estimated vs actual cardinality (the plan-dump est_card vs collector's actual count); it is a perf signal only (Principle 7). Mitigation: optional 2-term co-occurrence stats (deferred).
  • Stale stats after merge — generation not bumped → old df. Manifestation: wrong IDF + wrong ordering. Debug: assert stats generation == reader generation (INV-6).
  • Divide-by-zero — N=0 empty index. Debug: clamp; selectivity 0.
  • Global vs local IDF confusion — per-shard IDF differs from global → cross-shard score incomparability. Root cause: distributed scoring without global stats. Debug: config flag; gather global df when consistency matters (Phase 12).

⬜ Phase 8 — Cost Model + Logical→Physical Planner

Objectives
  • The optimizer (Core Types §11.9): a clause cost model, rarest-term-first conjunction ordering, strategy selection (sorted-bitset intersection vs leap-frog iterator vs PQ disjunction vs MaxScore), filter-vs-query finalization, and plan-shape decisions (AND vs OR evaluation). Pure function of (logical plan, stats, config) → physical plan (INV-10). This is the brain that turns correct-but-naive execution into a good plan.
Deliverable
  • optimize(LogicalOp, &StatsProvider, &CostModel, &QueryConfig) -> PhysicalOp; plan dump shows ordering + strategy + cost. examples/plan_dump.rs prints the chosen plan for a complex query.
Acceptance
  • Rarest-first: for conjunctions, the lead child is the lowest-df clause (verified on fixtures).
  • Plan determinism (INV-10): same inputs → byte-identical plan dump (run twice).
  • Strategy correctness: the chosen strategy never changes results vs the P5 baseline (differential) — only latency (Principle 7).
  • Measured improvement: rarest-first ordering reduces advance calls / decoded blocks vs naive (left-to-right) ordering by a meaningful margin on the benchmark set.
Fixtures
  • queries/P8_rarest_first.jsonl (conjunction → expected lead/order), P8_strategy.jsonl (clause profile → chosen strategy golden), P8_plan_determinism.jsonl, P8_filter_classify.jsonl, P8_equivalence.jsonl (optimized vs baseline results identical).
Pitfalls
  • Cost model overfit — weights tuned to one corpus, bad on another. Manifestation: regressions on a different dataset. Root cause: hardcoded weights. Debug: weights are config (ADR-23); A/B with plan dump + actual latency.
  • Ordering changes results — a "smart" reorder that isn't equivalence-preserving (e.g. reordering across a MUST_NOT incorrectly). Debug: differential vs baseline (P8 equivalence fixtures); ordering must be result-neutral. Instrument: plan_equivalence_mismatch_total.
  • Nondeterministic plan — hashmap iteration in ordering → flaky plan dumps + unreproducible perf. Debug: assert plan-dump stability; use ordered maps / stable sort (INV-10).
  • Bitset chosen when sparse — dense-strategy on sparse postings wastes memory. Debug: cost compare must include materialization cost; threshold by density.
  • Estimate-driven wrong lead — bad cardinality est picks a non-rarest lead → slow. Manifestation: latency. Debug: plan dump est_card vs actual; refine stats (P7). Not a correctness bug (Principle 7).

⬜ Phase 9 — Dynamic Pruning: WAND

Objectives
  • WAND (Broder 2003, Core Types §11.7): pivot-based skipping over a disjunction using per-term max_score() upper bounds + the collector's min_competitive_score() threshold. Safe pruning — identical top-k to the exhaustive baseline (INV-3), the central correctness gate of this phase.
Deliverable
  • WandScorer integrated as a PruneMode::Wand disjunction; the optimizer (P8) selects it for SHOULD-heavy / disjunctive top-k queries. Plan dump shows prune=Wand. examples/ runs WAND vs exact and diffs.
Acceptance
  • INV-3 (the gate): WAND top-k == exhaustive top-k (same ids, scores, order) on every fixture + fuzz (pruned_vs_exact target). Zero mismatches.
  • Pruning effectiveness: WAND scores ≤ ~20% of the candidate docs vs full OR for top-10 on typical queries (§4 target); measured docs_scored_wand / docs_scored_exact.
  • Threshold monotonicity: threshold never decreases during a query (asserted).
  • Latency: ≥ a few× wall-time speedup vs exhaustive on the disjunction benchmark.
Fixtures
  • queries/P9_wand_vs_exact.jsonl (query → must equal exhaustive top-k), P9_pruning_ratio.jsonl (records docs-scored ratio), P9_threshold.jsonl (monotonicity trace), P9_unsafe_bound.jsonl (a deliberately-loose-but-valid bound still yields correct top-k), P9_few_terms.jsonl (degenerate: WAND ≈ exhaustive).
Pitfalls
  • Unsafe upper bound → silent recall loss — the worst bug class. Manifestation: WAND drops a true top-k hit; no error, just wrong results. Root cause: max_score() underestimates (INV-1 violated). Debug: pruned_vs_exact differential pinpoints the missing doc; then check that doc's real score vs its scorer's claimed max. Instrument: inv1_violations_total, pruned_vs_exact_mismatch_total (both must be 0). Recovery: --exact fallback + fix the bound.
  • Threshold set before heap full — pruning starts too early, the first k docs aren't all admitted. Debug: threshold = -inf until heap has k entries; assert.
  • Pivot computation off-by-one — wrong pivot scorer → skips a candidate or never converges. Debug: unit-test pivot selection against a hand-traced example; log (sorted docs, max_scores, running sum, pivot).
  • Non-monotone threshold — a heap replacement that lowers the root (impossible if correct) → broken pruning. Debug: assert min_competitive non-decreasing.
  • Scorer re-sort cost — re-sorting N scorers every step dominates for large N. Debug: use a small structure / partial re-sort; measure (this is a perf, not correctness, issue).

⬜ Phase 10 — BlockMax-WAND + MaxScore + Block-Max Metadata

Objectives
  • BlockMax-WAND (Ding & Suel 2011) and MaxScore (Turtle & Flood 1995), the production-default pruners (ADR-06): tighter, block-level upper bounds (block_max_score(), INV-1) for far more skipping; MaxScore's essential/non-essential partitioning for low-k/few-term cases. Both must still satisfy INV-3.
Deliverable
  • BlockMaxWandScorer + MaxScoreScorer as PruneMode::BlockMaxWand/MaxScore; optimizer auto-selects; plan dump shows the chosen pruner. Benchmark compares full-OR vs WAND vs BMW vs MaxScore.
Acceptance
  • INV-3: BMW top-k == MaxScore top-k == WAND top-k == exhaustive top-k on every fixture + fuzz. Zero mismatch across all four modes.
  • BMW pruning effectiveness > WAND (fewer docs scored, fewer blocks decoded) on the benchmark — the block-level skip pays off.
  • MaxScore beats BMW for the low-k/few-term fixture class (validates the optimizer's selection rule).
  • block_max_score() is a true bound (INV-1) per block — fuzzed.
Fixtures
  • queries/P10_bmw_vs_exact.jsonl, P10_maxscore_vs_exact.jsonl, P10_all_modes_agree.jsonl (4-way equality), P10_block_bounds.jsonl (block_max_score ≥ all in-block scores), P10_mode_selection.jsonl (clause profile → chosen pruner), P10_blocks_skipped.jsonl (effectiveness).
Pitfalls
  • Block-max bound not per-block-true — block_max_score() underestimates a doc in the block. Manifestation: BMW drops a true hit (silent recall loss). Root cause: block-max meta stale/wrong, or scorer ignores the current block. Debug: pruned_vs_exact; fuzz score(d) ≤ block_max_score(block(d)). Instrument: inv1_violations_total. Recovery: fall back to WAND (global bound) or --exact.
  • advance_shallow decodes postings — defeats the purpose (no speedup). Manifestation: BMW not faster than WAND. Debug: assert shallow advance touches only block metadata, not posting bytes; count decoded blocks.
  • MaxScore partition wrong — a scorer wrongly classified non-essential → its docs missed. Debug: differential; re-derive the partition threshold; the partition must be recomputed as threshold rises.
  • Mode selection backfires — optimizer picks BMW where MaxScore wins (or vice versa). Manifestation: latency only. Debug: plan dump + per-mode benchmark; refine selection rule (Principle 7 — perf, not correctness).
  • Float drift across modes — different summation order → different last-decimal scores → spurious INV-3 "mismatch". Debug: compare scores within an epsilon; define a canonical summation order or epsilon tolerance consistently with the baseline.

⬜ Phase 11 — Filters, Facets, Predicate Pushdown, Caching + EXPLAIN + Plan Cache

Objectives
  • Filters (non-scoring constraints) as cacheable Roaring bitsets (§11.11); predicate pushdown (filter before score); filter cache + query cache (generation-keyed, INV-6); the EXPLAIN facility (plan tree + estimated-vs-actual + score explain()) and a plan cache for repeated query shapes. Basic faceting (term/range aggregation over the filtered set).
Deliverable
  • Filters cached + pushed below scoring; ?explain=true returns the plan tree + est/actual + score explanation; plan cache + query cache operational with eviction. Example shows a filtered+faceted query with EXPLAIN.
Acceptance
  • INV-6: no cache entry served across a generation bump (asserted; cache_stale_generation_hits_total = 0).
  • INV-13 (cache correctness): cache hit == fresh recomputation (differential, randomized).
  • Filter-before-score: scored-doc count with a selective filter ≈ filter cardinality, not total matches (measured score_calls_total drops).
  • EXPLAIN: plan-tree explain() value == actual score(); est cardinality present per node; actual filled.
  • Filter cache hit-rate target met on a repeated-filter workload (§4); memory stays under budget (eviction works).
Fixtures
  • queries/P11_filter.jsonl, P11_filter_cache.jsonl (hit/miss + generation invalidation), P11_pushdown.jsonl (score-call reduction), P11_query_cache.jsonl (hit==recompute), P11_explain.jsonl (plan tree + score golden), P11_plan_cache.jsonl, P11_facets.jsonl, P11_eviction.jsonl (budget enforcement).
Pitfalls
  • Stale cache across generation — serving a bitset/result from a generation that deleted docs (INV-6 / INV-8 violation). Manifestation: deleted docs reappear; wrong counts. Root cause: key missing generation, or generation not bumped on reopen. Debug: assert entry.generation == reader.generation on hit; cache_stale_generation_hits_total. Recovery: drop entry, recompute.
  • Scoring a filter — a FILTER clause leaks into scoring → wrong relevance + wasted CPU (Principle 6). Debug: assert FILTER scorers contribute constant 0; explain() shows no filter contribution.
  • Query cache returns stale scores — caching a query whose scoring inputs changed. Debug: key on generation + normalized plan; disable for non-deterministic queries.
  • Eviction thrash — budget too small → constant evict/rebuild. Manifestation: low hit-rate + high CPU. Debug: hit-rate + eviction-rate metrics; raise budget or scope cacheable filters.
  • EXPLAIN cost — explain path much slower, accidentally on by default. Debug: gate by request flag; never compute explanation unless asked.
  • Plan-cache aliasing — two different queries hash to the same digest → wrong plan. Root cause: weak digest. Debug: 128-bit digest of the fully normalized plan including field ids + occur + boosts.

⬜ Phase 12 — Phrases, Pagination, Distribution, Performance Hardening + Conformance

Objectives
  • Positional / phrase queries with slop via TwoPhaseIterator (approx + positional confirm, INV-5); pagination (from/size, search_after, track_total_hits); distribution (segment parallelism + shard scatter-gather query/fetch with partial results, INV-9/INV-11); performance hardening + the IR-effectiveness/latency benchmark + conformance harness (the release gate, Principle 15). This phase makes the planner production-shaped and locks correctness against a reference.
Deliverable
  • Phrase/slop queries; from/size + search_after + track_total_hits; multi-segment + multi-shard execution with partial results; the full conformance + bench + IR-eval harness gating CI. docker-compose.yml runs searchd + 3 mock shards + load-gen.
Acceptance
  • Phrase correctness: phrase + slop results match a brute-force positional matcher (INV-5; differential vs reference for exact + sloppy).
  • Pagination: search_after over the whole result set, page by page, visits every doc exactly once in INV-4 order (no dup, no skip) — the deep-paging correctness test.
  • Distribution: scatter-gather top-k == a single "fat" index of the same docs (INV-11 differential); partial results flagged correctly under injected shard timeout/failure (INV-9).
  • Performance: p50/p95/p99 within §4 targets on the benchmark; pruning ratios (P9/P10) hold under load; no regression vs committed baseline (bench.yml gate).
  • IR effectiveness: nDCG/MAP on the labelled collection within tolerance of the reference engine (Principle 15) — ranking quality, not just mechanics.
  • Reference-equivalence: full supported-subset differential vs Lucene/Tantivy green (modulo documented formula constants).
Fixtures
  • queries/P12_phrase.jsonl, P12_slop.jsonl (vs positional brute force), P12_search_after.jsonl (full-set walk, no dup/skip), P12_total_hits.jsonl, P12_scatter_gather.jsonl (vs fat-index, INV-11), P12_partial.jsonl (injected failure → partial flag), P12_ir_eval/ (labelled qrels → nDCG/MAP), P12_latency/ (perf baselines), P12_ref_diff_full.jsonl (vs Lucene/Tantivy).
Pitfalls
  • Phrase approximation misses a match — two-phase approximation isn't a true superset (INV-5). Manifestation: silent recall loss on phrases (pruning can't catch it). Root cause: approximation = wrong conjunction, or positions misread. Debug: differential vs brute-force positional; dump approx set vs exact set diff. Instrument: twophase_false_negative_total (0). Recovery: fall back to exact positional matcher.
  • search_after dup/skip — a doc appears on two pages or none. Root cause: nondeterministic tie-break (INV-4 violated) or cursor comparison off-by-one (> vs ≥). Debug: walk the full set page-by-page, assert a partition; the cursor compare must mirror the heap's total order exactly. Instrument: paging_dup_or_skip_total (0).
  • Cross-shard score incomparability — per-shard local IDF makes scores from different shards non-comparable → wrong global merge. Root cause: local vs global stats. Debug: enable global IDF (P7) or document the approximation; INV-11 differential vs fat index.
  • Partial-result silent data loss — a slow shard's results dropped without flagging. Manifestation: fewer/worse results, no signal. Root cause: missing partial propagation (Principle 9 / INV-9). Debug: inject shard delay, assert partial=true + missing-shard list; partial_results_total.
  • Deadline not propagated — a segment task runs past the request deadline. Debug: assert every block-boundary checks the shared deadline; inject a tiny deadline, assert bounded work + partial. Instrument: deadline_exceeded_total.
  • Deep-page OOM — from=1_000_000 materializes a huge intermediate. Debug: cap from+size; steer to search_after; reject beyond a configured depth (DoS).
  • Float nondeterminism cross-shard — different summation order per shard → unstable global order. Debug: canonical order + epsilon, consistent with INV-4.
