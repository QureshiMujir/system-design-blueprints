7. System Invariants

Each: statement — why · where enforced · detection · telemetry · recovery · debugging.

  • INV-1 — Scorer upper-bound safety. score(d) ≤ max_score() for all d; score(d) ≤ block_max_score(block(d)) for all d in block. Why: WAND/BMW correctness — pruning uses these bounds. Where: Scorer impls; checked in conformance + dev assertions. Detection: fuzz harness scores every doc and compares; max_score < observed triggers a hard fail. Telemetry: inv1_violations_total (must be 0). Recovery: disable pruning (--exact) for the affected query class; fix bound. Debugging: dump the doc, its computed score, the claimed max, the term stats feeding the bound.

  • INV-2 — Advance monotonicity. For any iterator, successive doc_id() values are strictly increasing; advance(t) returns the first d ≥ t (or NO_MORE_DOCS). Why: conjunction/disjunction sync correctness. Where: all DocIdSetIterator impls. Detection: dev-build assertion new_doc > prev_doc; conformance replays. Telemetry: iter_monotonicity_violations_total. Recovery: none at runtime (it is a logic bug); fail fast in dev. Debugging: log the iterator type + (prev, new, target).

  • INV-3 — Top-k completeness under pruning. The top-k returned with pruning equals the top-k returned without pruning (same ids, same scores, same order), given INV-1. Why: pruning is an optimization, not a semantic change. Where: executor + collector. Detection: differential test pruned-vs-exact on every fixture. Telemetry: pruned_vs_exact_mismatch_total. Recovery: --exact fallback. Debugging: re-run both modes, diff heaps doc-by-doc, find the first divergence.

  • INV-4 — Deterministic tie-break. Equal scores break by ascending docId (then configured secondary key); same input -> same output ordering. Why: stable pagination / search_after. Where: collector comparator. Detection: run query twice, byte-compare result ids. Telemetry: nondeterministic_result_total. Recovery: none (logic bug). Debugging: inspect comparator and heap pop order.

  • INV-5 — Two-phase superset. A two-phase approximation matches ⊇ true matches; matches() only ever removes, never adds. Why: no true match may be dropped pre-confirmation. Where: TwoPhaseIterator impls (phrase, expensive filter). Detection: differential vs a brute-force exact matcher on fixtures. Telemetry: twophase_false_negative_total (must be 0). Recovery: fall back to exact (non-two-phase) matcher. Debugging: dump approximation set vs exact set difference.

  • INV-6 — Generation immutability of caches. A cache entry is valid only for the generation it was computed under; reads check generation. Why: deleted/updated docs must not resurface. Where: cache crate keys. Detection: assert entry-generation == reader-generation on hit. Telemetry: cache_stale_generation_hits_total (must be 0). Recovery: drop the entry, recompute. Debugging: log (key, entry_gen, reader_gen).

  • INV-7 — Score non-negativity & finiteness. Every score is finite and ≥ 0 (BM25 with standard params). Why: heap comparisons + threshold math assume finite, ordered, non-negative. Where: Bm25Scorer. Detection: assert score.is_finite() && score >= 0 in dev. Telemetry: score_nan_or_neg_total. Recovery: clamp + log (last resort); root-cause the stat (e.g. negative IDF from df>N). Debugging: print df, N, tf, norm.

  • INV-8 — Live-docs honored. Deleted docs (live-docs bitset = 0) never appear in results. Why: deletes are logical until merge; query must filter them. Where: leaf iterators wrap live-docs; or a final filter. Detection: fixture with deletes; assert none returned. Telemetry: deleted_doc_returned_total (must be 0). Recovery: re-apply live-docs filter. Debugging: check the live-docs bitset for the segment + the leaf wrapper.

  • INV-9 — Timeout budget monotonicity. Once a deadline passes, no new block is decoded; the query returns partial. Why: bounded latency (§4). Where: executor block-boundary check + coordinator. Detection: inject tiny deadline, assert partial=true and bounded work. Telemetry: deadline_exceeded_total, partial_results_total. Recovery: return what is collected, flag partial. Debugging: trace deadline propagation + last-checked timestamp.

  • INV-10 — Plan determinism given stats. The optimizer produces the same physical plan for the same logical plan + same stats snapshot. Why: reproducible perf, debuggable plan dumps. Where: planner (pure function of inputs). Detection: plan twice, compare plan dump. Telemetry: plan_nondeterminism_total. Recovery: none (logic bug). Debugging: diff plan dumps; check for nondeterministic map iteration / hashing.

  • INV-11 — Shard result mergeability. Per-shard top-k are independently sorted by (score, shard-local global docId mapped to a global id) such that a k-way merge yields the global top-k. Why: scatter-gather correctness. Where: coordinator merge. Detection: compare scatter-gather result to a single-shard "fat" index of the same docs. Telemetry: shard_merge_mismatch_total. Recovery: re-fetch; flag partial. Debugging: dump per-shard top-k + merged top-k.

  • INV-12 — Field-norm consistency. The norm used in scoring matches the norm stored at index time for that (doc, field). Why: BM25 length normalization correctness + analysis parity. Where: scoring reads norms via index-api. Detection: explain() shows norm; compare to expected for a fixture doc. Telemetry: norm_mismatch_total. Recovery: reload norms; check analyzer version. Debugging: compare quantized norm byte to expected.

  • INV-13 — Cache correctness (hit == recompute). A cache hit (filter bitset or query top-k) is bit-for-bit indistinguishable from a fresh recomputation under the same generation. Why: a cache must add no semantics (Principle 14) — it is either fully transparent or a correctness bug. Where: cache crate (FilterCache/QueryCache lookups). Detection: randomized differential — force-recompute a sampled cache-hit key and diff against the served value. Telemetry: cache_correctness_mismatch_total (must be 0). Recovery: evict the offending entry, recompute, alarm. Debugging: replay the query with caching disabled and diff against the cached result.

Failure Modes & Recovery

Taxonomy. Each: symptoms · root causes · detection · automatic recovery · manual recovery · operator actions · forensic artifacts · long-term mitigation.

FM-1 — Planner picks a bad plan (slow, not wrong)

  • Symptoms: a query class is suddenly slow; p95/p99 spike; CPU up; results correct. Root causes: bad cardinality estimate (correlated terms, P7 independence assumption), stale stats, mis-tuned cost weights, wrong strategy/pruner selection (P8/P10). Detection: latency SLO alarm; card_estimate_error_ratio high; plan dump shows wrong lead/strategy. Auto recovery: none (correct, just slow); deadline caps the damage (partial). Manual: retune cost weights (config, no redeploy); refresh stats; force a pruner/strategy per query class. Operator: EXPLAIN-on-slow-query → read plan dump → compare est vs actual cardinality. Forensics: captured plan dump + per-stage timing. Long-term: co-occurrence stats; adaptive plan feedback (deferred).

FM-2 — Unsafe pruning changes results (silent recall loss) — CRITICAL

  • Symptoms: a true top-k hit missing; no error; relevance regression reports. Root causes: max_score/block_max_score underestimate (INV-1), block-max meta stale/wrong, MaxScore partition bug. Detection: pruned_vs_exact_mismatch_total > 0, inv1_violations_total > 0; --exact shadow canary divergence. Auto recovery: fall back to --exact for the affected class (kill-switch). Manual: fix the bound / reindex block-max meta. Operator: flip the pruning kill-switch immediately; this is sev-1. Forensics: differential names the dropped doc; dump its real score vs claimed bound + the feeding term stats. Long-term: keep the exhaustive oracle permanent; expand fuzz; shadow-canary always-on.

FM-3 — Stale statistics → mis-estimation / wrong IDF

  • Symptoms: bad ordering (slow) and/or shifted scores (relevance) after a merge/reopen. Root causes: generation not bumped, stats cache not invalidated (INV-6), df>N. Detection: stats-vs-oracle drift; INV-7 (negative IDF); stats_cache_hit_ratio anomalies. Auto recovery: generation bump drops the cache; IDF clamp (INV-7). Manual: force a searcher reopen; verify stats source. Operator: trigger reopen; check analyzer/stats version. Forensics: log (term, df, N, generation). Long-term: assert generation consistency on every stats read.

FM-4 — Iterator desync vs index (wrong/duplicate/missing docs)

  • Symptoms: results differ from brute-force; INV-2/INV-8 assertion fires (dev). Root causes: non-monotonic advance, skip-list misuse, live-docs not applied, conjunction sync bug. Detection: brute-force differential (P4); iter_monotonicity_violations_total, deleted_doc_returned_total. Auto recovery: none (logic bug); dev builds fail fast. Manual: replay in brute-force mode, diff doc sets, bisect. Operator: file sev-2; disable the affected operator path if possible. Forensics: iterator type + (prev, new, target) trace. Long-term: keep dev assertions + brute-force oracle in CI; fuzz iterator_monotonic.

FM-5 — Plan-cache / query-cache staleness (deleted docs resurface, wrong counts)

  • Symptoms: deleted docs in results; stale scores/counts. Root causes: cache key missing generation (INV-6), generation not bumped. Detection: cache_stale_generation_hits_total > 0; INV-13 differential. Auto recovery: generation key drops stale entries; flush on reopen. Manual: disable cache (config, perf-only cost). Operator: flush caches; verify reopen bumped generation. Forensics: (key, entry_gen, reader_gen) log. Long-term: caches correctness-neutral by design (Principle 14); assert on every hit.

FM-6 — OOM on disjunction heap / expansion / caches

  • Symptoms: RSS climb; allocator pressure; OOM-kill. Root causes: huge OR arity, unbounded expansion, cache budget too high, deep paging. Detection: memory budget breakers; RSS alarm; memory_budget_rejections_total. Auto recovery: reject over-budget (ExpansionTooLarge / deep-page reject); evict caches. Manual: lower budgets; cap arity. Operator: tighten config; identify the offending query (slow-query log). Forensics: query + expansion count + cache bytes at OOM. Long-term: every unbounded structure gets a budget (ADR-24, Principle 8).

FM-7 — Partial results / shard failure

  • Symptoms: fewer results than expected; partial: true; missing-shard list. Root causes: shard timeout, shard crash, network. Detection: partial_results_total, per-shard latency/error. Auto recovery: return partial flagged (Principle 9, INV-9); optional hedged retry to a replica. Manual: investigate the slow/failed shard. Operator: check shard health; partial is degraded-but-available (by design). Forensics: which shards missing, their last latency. Long-term: replica hedging; adaptive timeout.

FM-8 — Analysis parity break (silent recall loss on a field)

  • Symptoms: zero/poor results for a field; no error. Root causes: query analyzer ≠ index analyzer (Principle 11). Detection: analysis_parity_miss_total; canary recall vs known-good. Auto recovery: none (config mismatch). Manual: realign analyzer; reindex if index-side changed. Operator: check analyzer version stamp; sev-2. Forensics: query tokens vs terms() enumeration diff. Long-term: analyzer version stamp + mismatch alarm; treat analyzer change as reindex-class.

FM-9 — Nondeterministic results / pagination corruption

  • Symptoms: same query returns different order; a doc on two pages or none. Root causes: tie-break not deterministic (INV-4), float summation order, hashmap iteration in planner (INV-10). Detection: run-twice byte compare; nondeterministic_result_total, paging_dup_or_skip_total. Auto recovery: none (logic bug). Manual: enforce INV-4 comparator + canonical float order + ordered maps. Operator: sev-2 (breaks pagination). Forensics: two result sets diffed. Long-term: determinism fuzz (run-twice) in CI.

FM-10 — Query-of-death / single-query resource exhaustion (DoS class)

  • Symptoms: one crafted query spikes CPU/RSS or stalls a pool thread while aggregate load is normal (distinct from FM-6's aggregate OOM); p99 spike traceable to a single request shape. Root causes: unbounded wildcard/fuzzy expansion (a*, a~2 on a huge dict), deeply-nested boolean / huge clause count, from=1e7 deep paging, or an expensive-plan combination (many SHOULD × phrases × no filter). Detection: pre-execution circuit breakers — maxExpansions + memory budget (ADR-24), AST depth/byte/clause caps (Phase 1), deep-page cap (Phase 12), cost estimate > budget (Threat Model); query_rejected_total{reason}, expansion_rejected_total, deadline_exceeded_total. Auto recovery: reject before damage (ResourceError::ExpansionTooLarge / deep-page reject), or bound at the deadline → partial (INV-9). Manual recovery: tighten per-request limits (config, no redeploy); identify the offending shape via the slow-query log. Operator: sev-2; the limits are perf/availability knobs, never correctness (Principle 7/8). Forensics: rejected query + pattern/field + enumerated count + decision (scored/const/reject). Long-term: every unbounded structure carries a budget (ADR-24, Principle 8); fuzz the parser (Phase 1) and expansion (Phase 3) bounds; admission control sheds over-budget queries (Scalability Analysis).
