Hard questions (§37)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why is discovery AP while the coordination store (#36/etcd) is CP, and what exactly breaks if you put discovery on a CP core — quantify the failure? (§2.7 + §4.2 + §21 + I13)
  2. Derive the intra-region propagation time from fanout, gossip interval, and node count, and show it meets the §4 p99 — then explain why anti-entropy, not gossip, sets the worst-case bound. (§4.1 + §36 C1/C9 + §16 + I9)
  3. A node GC-pauses for 1 s. Trace exactly how the system avoids falsely evicting its instances, and what would go wrong with a tighter probe timeout. (§4.3 + §14 + §8.10 + I6 + principle 8)
  4. Why are two liveness signals (lease + SWIM) necessary — give a concrete failure each one alone misses, and state the combined Passing rule. (§8.3 + §6 principle 4 + §13 + §14 + I3/I6)
  5. Show why the (incarnation, logical_ts) order must be total for convergence, and construct the divergence that results if it is merely partial. (§8.12 + §11.3 + §12 + I7/I11 + MM4)
  6. A gossip frame is dropped under load. Walk the path by which the two affected nodes nonetheless converge, and bound the time. (§15 + §16 + §4.4 + I9 + principle 3)
  7. Compute the Merkle digest bytes exchanged when two 10^5-key replicas differ in 100 keys, and explain why deterministic key ordering is load-bearing. (§36 C9 + §8.5 + §16 + MM9 + I9)
  8. Distinguish the steady-state gossip bandwidth from the registry-storm worst case; name every mitigation that bounds the storm and which § enforces each. (§4.4 + §8.14 + §6 principle 5 + §36 C2/C3 + I8)
  9. Under a WAN partition between regions A and B, what does a resolve in A return for a B-only service, and what flag/age accompanies it — and why does A's local discovery stay up? (§8.13 + §20 + §21 + I10/I13 + principle 6)
  10. Explain the catalog/health consistency split: which writes go through Raft, which never do, and why routing health through Raft is the classic mistake. (§2.7 + §22 + §6 principle 7 + I14)
  11. Why does the resolution hot path forbid a global lock, and what concretely happens at 50 k QPS if one slips in? Name the data structure that avoids it. (§3.5 + §17 + §32 + §6 principle 9 + ADR-19)
  12. Define the staleness bound under no-partition vs partition, show each is enforced and reported, and explain why bounded-stale beats both unbounded-stale and CP-blocking. (§4.2 + §21 + §6 principle 2 + I10 + MM1)
  13. Trace a blocking (long-poll) query end-to-end and identify the race that, mishandled, makes it hang until timeout. (§8.7 + §17 + §11.8 + I5)
  14. Why use an incarnation+LWW register instead of vector clocks for instance health — and name the case where you would need vector clocks. (§8.12 + ADR-7 + §35 Dynamo + MM4)
  15. How does SWIM keep failure-detection load and detection time O(1) as the region grows to 10^6 instances — what is membership actually over? (§4.3 + §36 C7/C8 + §14 + §33 + I6)
  16. Self-preservation: when does it fire, what does it stop, and what is the danger it introduces (and why is that the lesser evil)? (§8.3 + §21 + ADR-9 + principle 1)
  17. A huge service has 10^4 instances. Why does naive resolution melt, and how does EndpointSlice sharding fix both DNS and the query path? (§17.8 + §24 + §35 CoreDNS + §33)
  18. Why is federation strictly off the local read critical path, and what one design slip would make a WAN blip cascade into a local outage? (§20.6 + §8.11 + §6 principle 6 + I13 + MM8)
  19. How does the deterministic simulation reproduce a divergence bug that is impossible to reproduce on a live cluster — and what makes a DST run a lie if you're not careful? (§25 + §6 principle 14 + §30 + MM10)
  20. Walk the full headline path: a cross-region registration in B becoming discoverable (and ordered) for a client in A, naming every subsystem and the invariant at each hop. (§3.4 + §8.13 + §20 + I2/I8/I9/I12)
  21. Why are wire/DNS/gRPC versions tracked separately from the crate SemVer, and what rolling-upgrade failure does negotiation prevent? (§29 + ADR-30 + §6 principle 12 + I15)
  22. Compare the cost of a false positive vs slow detection in the failure detector, and explain why the defaults lean conservative. (§4.3 + §14.9 + §27 + principle 8 + MM6)
  23. A catalog-Raft minority partition occurs. Which operations block, which keep working, and how does the split protect discovery availability? (§22 + §2.7 + I14 + principle 7)
  24. Why is the single-region oracle kept deliberately trivial, and what failure mode arises if the oracle shares logic with the system under test? (§25.6 + §12 + §6 principle 14 + MM10)

34. Mental Models & First Principles

The compressed insights an expert holds about internet-scale discovery. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — Discovery is a liveness oracle, not a truth oracle. It answers "where are instances that were healthy a bounded moment ago," never "where are instances that are healthy now" (impossible across a network). Predicts: every answer is inherently a recent past; correctness is bounded staleness, not zero staleness. Bug class without it: treating a returned instance as guaranteed-live → no client-side health check / retry → traffic black-holed at a just-died instance. Applied: §2.7, §4.2 (staleness budget), §21 (P9), I10.
  • MM2 — Availability is the product, consistency is a feature. If discovery can't answer, every dependent request fails — discovery down = fleet down. A stale answer costs one retry; no answer costs an outage. Predicts: under partition you serve stale, never block; the asymmetry forces the AP corner. Bug class without it: putting discovery on a CP core (etcd-only) → consensus unavailability = discovery unavailability → a minority-partition region's routing dies. Applied: §2.7 (the §36/etcd contrast), §6 principle 1, §21 (P9), I13.
  • MM3 — Gossip is probabilistic speed; anti-entropy is deterministic certainty. Epidemic dissemination converges fast (O(log N)) but lossily; periodic Merkle reconciliation guarantees no permanent divergence. They are complementary, not redundant. Predicts: gossip-only eventually diverges on packet loss; anti-entropy-only is minutes-slow. Bug class without it: shipping gossip-only → a dropped UDP frame leaves two nodes permanently disagreeing, undetected. Applied: §6 principle 3, §15 (P3), §16 (P4), I9.
  • MM4 — The version is the conflict-resolution algorithm. A total order (incarnation desc, logical_ts desc) makes merges commutative/associative/idempotent → any gossip/anti-entropy delivery order converges to the same state with zero coordination. Predicts: if the order isn't total, two nodes pick different winners and anti-entropy can't fix it (they disagree on truth). Bug class without it: ≥ instead of > in the apply rule → equal-version events ping-pong forever; a non-total order → permanent divergence. Applied: §8.12, §11.3 (Version::dominates), I7/I11, §12 (P0).
  • MM5 — Two liveness signals because each is blind to the other's failure. A lease catches a process that exited cleanly or is stuck-but-present (not renewing); SWIM catches a node that vanished suddenly and bounds detection time. Neither alone covers both. Predicts: lease-only → slow crash detection (full TTL); SWIM-only → an up-but-not-renewing instance looks alive. Bug class without it: relying on one signal → either dead instances served for a full TTL, or hung instances never detected. Applied: §6 principle 4, §8.3, §13 (lease, P1), §14 (SWIM, P2), I3/I6.
  • MM6 — Failure detection lives on a frontier, not at a point. Detection-time and false-positive-rate trade off continuously; you pick a point on the curve, you don't eliminate the tradeoff. A false positive evicts healthy instances (real traffic loss); slow detection serves dead ones (retries). Predicts: aggressive timeouts flap healthy nodes out under load/GC; lax timeouts serve corpses. Bug class without it: tuning for fast detection and discovering healthy instances vanish whenever a node GC-pauses. Applied: §4.3 (detection budget), §14 (P2), §6 principle 8, I6.
  • MM7 — Cost is driven by churn, not by size. Gossip bandwidth ∝ event-rate × fanout × event-size, independent of the total instance count; a million stable instances gossip almost nothing. Predicts: the registry storm (mass restart), not steady scale, is the bandwidth worst case. Bug class without it: sizing capacity off instance-count and being surprised when a deploy-wide restart broadcast-storms the cluster. Applied: §4.4 (gossip-bandwidth budget), §8.14 (storm), §6 principle 5, §33, I8.
  • MM8 — A region is the unit of independence; the WAN is best-effort glue. Local discovery must never sit on the WAN critical path; federation replicates selectively and asynchronously, and a WAN partition degrades only remote answers. Predicts: any synchronous cross-region read makes a WAN blip a local outage. Bug class without it: a "resolve anywhere" path that round-trips the WAN on every miss → WAN latency/partition cascades into local resolution. Applied: §6 principle 6, §20 (P8), §3.3 failure boundary, I13.
  • MM9 — Merkle reconciliation pays for the difference, not the whole. A hash tree over (key→version) lets two nodes skip matching subtrees and exchange only divergent keys — but only if both build the identical tree (deterministic key ordering). Predicts: steady-state anti-entropy is near-free (digests match); it spikes only after divergence. Bug class without it: non-deterministic key ordering → digests never match → every reconcile ships the full state → bandwidth blowup. Applied: §8.5, §16 (P4), §4.4, I9.
  • MM10 — Determinism is the only debugger for eventual consistency. Divergence/lost-update/unbounded-staleness bugs are unreproducible on a live cluster (timing-dependent); you must drive the whole system at virtual time from a seed, with injected faults, and assert against a trivially-correct oracle. Predicts: without a deterministic harness, these bugs ship and manifest as "service X randomly invisible in region B." Bug class without it: "just rerun it" on a flaky distributed test → papering over a real nondeterminism bug. Applied: §6 principle 14, §25 (P13, DST), §12 (oracle, P0).

Required reading (§5)

5.1 Books

  • Tanenbaum & van Steen, Distributed Systems (3e) — ch. on naming, consistency & replication, fault tolerance, gossip/epidemic protocols. The conceptual backbone (eventual consistency, failure models, naming). Applied: §8.12 (convergence/consistency model), §1.1 naming hierarchy (P0), §15.2 gossip (P3).
  • Kleppmann, Designing Data-Intensive Applications — ch.5 (replication), ch.9 (consistency & consensus, CAP framing). Why AP vs CP, leaderless replication, read-repair / anti-entropy. The single most relevant book. Applied: §2.7 + §21 (the AP/CAP choice, P9), §16 (anti-entropy/read-repair, P4), §22 (catalog consistency split, P10).
  • Cachin, Guerraoui, Rodrigues, Introduction to Reliable and Secure Distributed Programming (2e) — failure detectors (the formal model behind SWIM), broadcast abstractions, quorum reasoning. Applied: §14 (SWIM failure detector, P2), §4.3 (detection-time/false-positive budget).
  • Birman, Reliable Distributed Systems — epidemic/gossip protocols, virtual synchrony, the convergence intuition. Applied: §15 (gossip dissemination, P3), §4.1 (propagation-time budget).
  • Liu, DNS and BIND (5e) — DNS RR types, SRV, zone semantics, TTL behavior, authoritative-server design. The DNS interface spec in practice. Applied: §18 (DNS + DNS-SD authoritative interface, P6), §8.8 wire protocols.
  • Newman, Building Microservices (2e) — the operational context: why service discovery exists, registry patterns, client- vs server-side discovery, health checking. Applied: §2.2 (why it matters), §3.2 agent model, §13 (registry/leases, P1).
  • Burns, Designing Distributed Systems — patterns (sidecar/agent, replicated services) relevant to the agent + federation model. Applied: §3.2 (sdd-agent box), §20 (federation, P8).
  • Petrov, Database Internals — anti-entropy, Merkle trees, gossip dissemination, failure detection, and replication chapters — the implementation-level treatment of exactly this convergence core. Applied: §16 (Merkle anti-entropy, P4), §11.6 Merkle types, §15 (gossip, P3).

5.2 Papers

  • Das, Gupta, Motivala, "SWIM: Scalable Weakly-consistent Infection-style Process Group Membership Protocol" (DSN 2002) — the failure detector: direct + indirect probes, suspicion, scale-independent load. The membership crate (P2) blueprint.
  • Demers et al., "Epidemic Algorithms for Replicated Database Maintenance" (PODC 1987) — the foundational gossip paper: anti-entropy, rumor mongering, push/pull/push-pull, convergence math. The gossip + anti-entropy crates (P3/P4).
  • van Renesse, Minsky, Hayden, "A Gossip-Style Failure Detection Service" (Middleware 1998) — gossip-based membership/failure detection; informs the SWIM+gossip integration. Applied: §14 (SWIM, P2) + §15.2 (gossip-piggybacked health, P3), I6.
  • DeCandia et al., "Dynamo: Amazon's Highly Available Key-value Store" (SOSP 2007) — AP design, gossip membership, anti-entropy via Merkle trees, vector clocks, hinted handoff. The closest production AP system to this; the Merkle anti-entropy + AP reasoning (P4/P9).
  • Lakshman & Malik, "Cassandra: A Decentralized Structured Storage System" (2010) — gossip + anti-entropy + Merkle reconciliation at scale; tunable consistency. Applied: §16 (Merkle anti-entropy at scale, P4) + §24 (10^5–10^6 scale tuning, P12), I9.
  • Gilbert & Lynch, "Brewer's Conjecture and the Feasibility of Consistent, Available, Partition-tolerant Web Services" (2002) — the CAP theorem proof; why you can't have all three. Applied: §2.7 (the AP choice) + §21 (partition behavior, P9), I13.
  • Abadi, "Consistency Tradeoffs in Modern Distributed Database System Design (PACELC)" (IEEE Computer 2012) — PACELC: the else-latency dimension; why discovery is PA/EL. Applied: §2.7 (PA/EL classification) + §19 (cache-for-latency in the else case, P7), principle 1/10.
  • Lamport, "Time, Clocks, and the Ordering of Events in a Distributed System" (CACM 1978) — logical clocks / causality (#95); the basis for conflict resolution reasoning. Applied: §8.12 + §11.3 (the logical_ts half of the LWW Version order, I11, P0), §20.6 (cross-region Lamport counters, P8).
  • Cheriton & Mann, "Decentralizing a Global Naming Service for Improved Performance and Fault Tolerance" (TOCS 1989) — hierarchical/federated naming, caching, the internet-scale naming lineage (the DNS ancestor of this design). Applied: §20 (federation/region projection, P8), §8.1 naming hierarchy.
  • Mockapetris, "Development of the Domain Name System" (SIGCOMM 1988) — why DNS is hierarchical, cached, and eventually consistent — the original internet-scale discovery system; the federation/TTL intuition. Applied: §18 (DNS interface, P6), §19 (TTL/caching, P7), §2.2 (the internet-scale-discovery lineage).
  • van Renesse, Dumitriu, Gough, Thomas, "Efficient Reconciliation and Flow Control for Anti-Entropy Protocols" (LADIS 2008) — making anti-entropy bandwidth-efficient (the Merkle/flow-control practice, P4).

5.3 Reference Implementations

  • HashiCorp Consul (agent/, agent/consul/, vendored serf/memberlist) — multi-DC WAN gossip, LAN/WAN gossip pools, the agent model, catalog + health split, prepared queries (locality-aware resolution). The primary model. Lesson: LAN vs WAN gossip pools, the sparse WAN pool, anti-entropy. Pitfall: don't copy its Raft coupling for health (health is gossip, not Raft).
  • HashiCorp Serf / memberlist — the SWIM + gossip implementation underneath Consul. Lesson: SWIM + Lifeguard refinements (suspicion timeout adaptation, false-positive reduction), event piggybacking. The membership + gossip crates' direct reference.
  • Netflix Eureka — the canonical AP registry; self-preservation mode (stop expiring leases when too many heartbeats are lost — assume network, not mass death). Lesson: AP-first, lease/renew model, self-preservation under partition. Pitfall: its registry is eventually consistent everywhere (no catalog-CP option) — we add the split.
  • CoreDNS (plugin/kubernetes, plugin/etcd) + Kubernetes EndpointSlices — DNS-as-discovery at scale; how endpoints become DNS/SRV records; EndpointSlice sharding for large services. Lesson: the DNS interface, SRV semantics, endpoint sharding. Pitfall: its consistency is etcd-CP (the API server) — the contrast case (§2.7).
  • etcd (server/, the Raft + MVCC store) — the CP contrast (#36): linearizable, refuses minority-partition writes. Study to understand exactly what we are not building and why discovery must not be only this. Lesson: when CP is right (locks/leader election), when it is wrong (discovery availability).
  • Apache ZooKeeper — the older CP coordination service; the "discovery on a CP core" anti-pattern (herd effects on watches at scale). Lesson: why CP coordination doesn't scale as a discovery substrate; watch-storm pitfalls.
  • CoreDNS / Avahi / mDNS (avahi-daemon) — DNS-SD / mDNS for the wire-format and DNS-SD record patterns (RFC 6762/6763). Lesson: DNS-SD PTR/SRV/TXT enumeration.

Glossary (§40) · 45 terms · site-wide glossary

Service discovery
the mechanism by which a client finds the network location(s) of a named service's healthy instances. The substrate every microservice request depends on.
Registry / catalog
the authoritative record of services → instances (address/port/metadata/tags). The "what exists" tier.
Instance
a single running copy of a service, identified by InstanceId, with an address/port/locality/tags/weight.
Lease (TTL)
a time-bounded liveness assertion an instance must renew; expiry → the instance is presumed gone. One of the two liveness signals.
Heartbeat / renew
the periodic call that resets a lease's expiry (renew-at-ttl/3 to tolerate skew + loss).
Health state
Passing | Warning | Critical; resolution filters by a health policy.
SWIM
Scalable Weakly-consistent Infection-style Process group Membership: a failure detector using direct + indirect probes, suspicion, and incarnation numbers; O(1) load, bounded detection. The second liveness signal.
Direct / indirect probe
SWIM pings a peer directly; on no ack, asks k other peers to probe it (filters transient slowness → fewer false positives).
Suspicion
SWIM's intermediate state (Alive → Suspect → Dead) giving a node time to refute before eviction.
Incarnation number
a per-node monotonic counter; a node refutes a false Suspect by re-asserting Alive with a higher incarnation. The per-key version that makes LWW correct across the refute race.
Gossip / epidemic protocol
randomized peer-to-peer dissemination; state spreads in O(log N) rounds at fanout k. Fast but lossy.
Push / pull / push-pull
gossip modes: push new events, pull a peer's events, or exchange digests-then-deltas (push-pull converges fastest).
Fanout (k)
the number of random peers an event is gossiped to per round.
Dissemination limit
the max times an event is gossiped before retiring (~log N); bounds bandwidth.
Piggybacking
attaching gossip events to SWIM probe/ack messages (free propagation).
Anti-entropy
periodic full-state reconciliation (here via Merkle trees) that repairs anything gossip dropped → guaranteed eventual convergence. Gossip's correctness backstop.
Merkle tree
a hash tree over (key → version); matching subtrees are skipped, so reconciliation transfers only the diff, not the whole state.
Read repair
repairing a stale replica during a read/reconcile (the anti-entropy mechanism).
Eventual consistency
replicas converge to the same state given no new updates + time; reads may transiently differ (bounded here).
AP (CAP)
under partition, choose Availability + Partition-tolerance over Consistency: keep answering with bounded-stale data. Discovery's choice.
CP (CAP)
choose Consistency + Partition-tolerance, refusing progress under partition (etcd/#36). The contrast; wrong for discovery availability.
PACELC
extends CAP: else (no partition) trade Latency vs Consistency. Discovery is PA/EL (favors availability under partition, latency otherwise).
Bounded staleness
a hard cap on how stale a returned answer can be (gossip-round + health-TTL, or anti-entropy-interval + WAN-RTT under partition), always flagged with an age.
LWW register
Last-Writer-Wins: concurrent updates to a key resolve by a total order (incarnation desc, logical_ts desc); commutative/idempotent → convergence.
Logical clock / Lamport timestamp
a per-node monotonic counter giving a causal-ish order without synchronized wall-clocks (used in the Version order).
Self-preservation
Eureka's safeguard: when too many heartbeats are lost at once, assume a network problem (not mass death) and stop expiring leases — avoids evicting a healthy fleet during a blip.
Federation
linking independently-authoritative regional registries over the WAN with selective replication. The internet-scale layer.
WAN gossip pool
a sparse set of designated nodes per region that gossip region-level summaries cross-region (bounds WAN traffic; the Consul model).
Selective / demand-driven replication
a region replicates a remote service only if a local client queried it (or per policy) — not the whole world to everywhere.
Region projection
a read-only, freshness-tagged local view of a remote region's service.
Locality ladder
the resolution ordering preference: same-zone → same-region → other-region.
Blocking query / long-poll
a resolution that holds the request open until the result set's version changes or a timeout fires (efficient change notification without polling).
DNS-SD
DNS-Based Service Discovery (RFC 6763): _service._proto PTR enumerate → SRV+TXT resolve.
SRV record
a DNS record giving a service's host+port+priority+weight (RFC 2782).
Negative caching
caching a "no result / NXDOMAIN" answer with a short bounded TTL (RFC 2308) to shed repeat misses.
Stale-if-error
serving expired (stale, flagged) cached data when the source is unreachable — an AP cache behavior.
Single-flight / request coalescing
collapsing concurrent misses for the same key into one source fetch (anti-stampede).
Registry storm
a burst of registrations (mass restart/deploy) that can broadcast-storm gossip if not batched + rate-limited.
Flap damping
hysteresis on health transitions to avoid gossiping a rapidly-flapping instance's every state change.
Timer wheel
a hierarchical timing-wheel data structure giving O(1)-amortized expiry for millions of leases.
EndpointSlice
sharding a huge service's instance set into bounded slices (the Kubernetes/CoreDNS technique) so resolution/DNS doesn't materialize the whole set.
Deterministic simulation (DST)
running the whole distributed system in one process at virtual time with seeded fault injection, so convergence/staleness are asserted reproducibly. The correctness backbone.
Single-region oracle
the trivially-correct single-store reference the distributed system is validated against.
Split (catalog/health)
the design decision to put rarely-changing catalog metadata on an optional consistency tier (per-region Raft) while keeping constantly-changing health eventually consistent (gossip). The system's signature decision.
Crash-only
a node can be killed at any time and rejoin cleanly (via gossip + anti-entropy) with no data loss.
