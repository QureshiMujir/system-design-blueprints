3.2 Box Narratives

  • sdd-agent (client agent). The local caching resolver every app talks to (the Consul-agent / Eureka-client model). Caches resolutions (cache tier 1, §3.x), serves them at sub-ms latency, renews the app's own registrations/leases, and holds watch/long-poll subscriptions for change notifications. Shields the region servers from per-request load; serves stale-if-error when the region is unreachable (AP, principle 6). The single most load-bearing component for resolution latency.
  • resolve (query engine). Answers "give me healthy instances of service X" filtered by health (only Passing/Warning per policy), tag, locality (prefer same-AZ/region, the locality ladder), and weight. Supports blocking queries (long-poll: hold the request open until the result set changes or a timeout — the efficient watch primitive). Composes the registry's current state + health into an ordered candidate list. Does not load-balance (returns candidates; the caller picks).
  • registry (catalog + lease manager). The per-region source of truth: the catalog (services → instances → address/port/metadata/tags) and the lease manager (each instance has a TTL lease it must renew; expiry → mark unhealthy/remove). Emits a change-stream (the substrate for gossip events and blocking-query notifications). Optionally serializes catalog writes through a per-region Raft group (P10) while keeping health out of consensus (the split, principle 7).
  • membership (SWIM). The failure-detection layer (#197 reused): each node periodically probes a random peer (ping/ack); on no ack, indirect-probes via k other peers; persistent failure → suspect then dead, with incarnation numbers so a node can refute a false suspicion (alive with a higher incarnation). Provides cluster membership and a fast liveness signal for instances co-located with a dead node. Bounded detection time (§4).
  • gossip (dissemination). The epidemic engine (#72 reused): registry change events and membership/health updates are piggybacked on SWIM probes and on periodic push-pull rounds to random peers, with fanout k and a dissemination limit (each event gossiped O(log N) times then retired). Spreads state across the region in O(log N) rounds. Lossy by design — anti-entropy is the backstop.
  • antientropy (Merkle reconciliation). The convergence guarantee (#99/#71 reused): periodically, two nodes exchange a Merkle digest of their catalog/health state and reconcile only the differing subtrees (read-repair style). Catches anything gossip dropped, so no two nodes stay permanently divergent. The reason gossip can be lossy-but-correct.
  • dns (authoritative server). The legacy-compatible interface (#65 wire-format reused, server side): answers A/AAAA (instance IPs), SRV (host+port+weight+priority), TXT (metadata), and DNS-SD (PTR enumerate → SRV+TXT resolve, RFC 6763). Lets any DNS-speaking client discover services with zero SDK. TTLs on responses tie into the cache strategy.
  • cache (multi-tier TTL). The latency + load-shedding layer (#59 reused): tier 1 = agent cache (per host), tier 2 = regional cache (per server, shields the authoritative store + cross-region), authoritative = the registry. TTL per entry, negative caching (NXDOMAIN/empty), stale-if-error (serve expired data when the source is down — AP), and anti-stampede (single-flight / request coalescing so a popular key's TTL expiry doesn't storm the source).
  • federation (WAN). The internet-scale layer: links regions over the WAN. A sparse WAN gossip pool (a few designated nodes per region, not all-to-all, the Consul model) exchanges region-level summaries; selective/locality-scoped replication (a region replicates only the services another region actually queries, or per a policy) keeps WAN traffic bounded; cross-region resolution lets a client ask for service X in region B; region catalog projection presents remote services locally. Each region stays independently authoritative — a WAN partition does not stop local discovery (principle 6, the AP heart).
  • runtime. Node/region lifecycle: bootstrap (a node joins its region's gossip cluster via seed/join addresses, gets identity), the HTTP/gRPC API surface (register/deregister/renew/resolve/watch/catalog), config, and (P10) the optional per-region catalog Raft group.
  • bench / conformance. Propagation-time (register→discoverable), resolution-latency (cache hit/miss), and gossip-bandwidth/CPU harnesses (vs §4); the single-region oracle (one authoritative store, no gossip — the trusted result); a deterministic-simulation (DST) differential (virtual time + injected partitions/loss/skew/reorder — convergence + staleness assertions); fault/partition injection.

3.3 Boundaries

  • Trust boundary: the network — clients (register/resolve), gossip peers (intra-region), and WAN peers (other regions). Inputs are validated/length-checked; a peer can be slow, dead, byzantine-lite (send a stale/forged update — defended by incarnation numbers + monotonicity, not full BFT). The DNS/HTTP/gRPC surface is the public attack surface.
  • Consistency boundary: health/liveness is eventually consistent (gossip + anti-entropy, AP); catalog writes may be per-region linearizable (optional Raft, P10). Cross-region is always eventually consistent (federation never blocks local reads). This split is the central boundary (principle 7).
  • Concurrency boundary: per node — gossip/SWIM threads (timing-sensitive), the DNS server, the HTTP/gRPC server, watch/long-poll waiters, the cache, lease-expiry timers. No shared lock on the resolution hot path (principle 9).
  • Failure boundary: a region is the unit of independence — a region keeps serving under WAN partition; within a region, a node failure is handled by gossip+SWIM, not by stopping. The coordinator-free data plane (gossip) means no single point of failure for discovery (contrast a central registry).

3.4 Data-flow walk — one cross-region registration → discovery (the headline path)

  1. Instance i of service payments starts in region B; its sdd-agent calls register(payments, addr, port, tags, locality=B/az2, ttl=15s) → the local region-B registry writes the catalog record + a Lease{ttl=15s}, sets health Passing (I2/I3).
  2. The registry emits a change event → gossip piggybacks it on SWIM probes + push-pull rounds → within O(log N) gossip rounds every region-B node has the record (propagation bound, §4; I8).
  3. antientropy runs periodically; if any node missed the gossip event, the next Merkle reconciliation repairs it (I9) — convergence guaranteed, not just probable.
  4. The instance's agent renews the lease every ttl/3 ≈ 5s (renew); each renewal resets expiry (I3). SWIM independently probes the node hosting i; if that node dies, SWIM marks it dead → all its instances flagged unhealthy fast (I6), without waiting for lease expiry.
  5. A client in region A resolves payments with locality=A, allow_remote=true. Region A's resolve first returns region-A healthy instances; finding none (service only in B), it consults the federation projection of region B (replicated selectively, §3.x) → returns region-B instances ordered by locality (I12).
  6. The answer flows through the cache tiers (regional tier 2 → agent tier 1) with a TTL = min(record_ttl, health_ttl); subsequent resolutions hit the agent cache at sub-ms (I11). Negative results (no healthy instance) are negatively cached briefly.
  7. Instance i is later gracefully drained (deregister) → catalog record removed → gossiped → converges. Had it crashed instead, lease expiry (≤15s) + SWIM (≤§4 bound) would have removed it (I3/I6) — the two liveness signals.
  8. Throughout, a WAN partition between A and B would not stop either region serving its local view; region A would serve its last-known (stale, bounded by §4) projection of region B's payments, marked stale (I10, principle 6). Trace records propagation time, gossip rounds, anti-entropy repairs, resolution latency, staleness.

3.5 Per-node concurrency model (threads, timers, waiters)

  • SWIM prober thread(s): periodic probe/ack + indirect probe on a fixed cadence (timing-sensitive — jitter must not falsely suspect; principle 8, I6); piggybacks gossip.
  • Gossip thread(s): periodic push-pull to random peers; drains the dissemination queue; bounded fanout (I8).
  • Anti-entropy thread: lower-frequency Merkle exchange + reconcile (I9).
  • Lease-expiry timer wheel: a hierarchical timer wheel firing per-instance TTL expiry (O(1) amortized, scales to 10^6 leases; I3).
  • DNS server (UDP+TCP) + HTTP/gRPC server: async, serve from cache/registry; never block on gossip.
  • Watch/long-poll waiters: parked tasks woken by the registry change-stream (the blocking-query primitive; I5).
  • Federation/WAN thread: sparse WAN gossip + selective replication; isolated so WAN slowness never stalls local serving (principle 6).
  • Cache maintenance: TTL expiry, single-flight coalescing.
  • Synchronization: the catalog is read-mostly (resolution) + write-rare (register/health) → an RCU/arc-swap-style read-optimized structure (principle 9); no global lock on resolution. Cross-thread ordering only via the change-stream + explicit versions, never hidden locks on the hot path.

8. Domain Model — Naming, Records, Liveness, Gossip, Federation, Resolution

8.1 Naming hierarchy

  • A fully-qualified service name: service[.tag].namespace.region.<root> — e.g. payments.prod.us-east.svc.discovery. (DNS-compatible labels; I1). Components:
    • service — the logical service (payments).
    • namespace — tenancy/isolation boundary (prod, staging).
    • region — the authoritative region (us-east).
    • DNS-SD form: _payments._tcp.prod.us-east.svc.discovery. (RFC 6763 _service._proto prefix).
  • Resolution may omit region (→ "any/locality-preferred region", I12) or pin it (→ a specific region, cross-region allowed by policy).
  • Tags subset a service (payments with tag v2 → only v2 instances) — expressed as a query filter, not a separate name.

8.2 Core records (the catalog)

Record Fields (lightweight) Consistency tier
Service name, namespace, default-port, metadata catalog (CP-able, P10)
Instance InstanceId, service, addr, port, locality, tags, metadata, weight catalog (CP-able)
Lease instance, ttl, last_renew, expiry liveness (AP, gossip)
Health instance, state{Passing/Warning/Critical}, check_output, incarnation, logical_ts liveness (AP, gossip)
NodeMember node-id, addr, status{Alive/Suspect/Dead}, incarnation membership (AP, SWIM)
  • The split (principle 7): Service/Instance (the catalog — rare changes) may sit on a per-region linearizable tier; Lease/Health/NodeMember (constant changes) are always eventually consistent (gossip/SWIM). A resolution joins catalog + health at read time.

8.3 Liveness — leases + SWIM (the two signals)

Signal Who asserts/detects Catches Timescale
Lease (TTL renew) the instance renews clean exit, stuck-but-present (not renewing), graceful drain TTL (5–90 s, default 15 s)
SWIM probe peer nodes detect sudden node death, network-isolated node < 3×probe_interval (< 3 s)
  • Combined rule: an instance is Passing iff (lease not expired) and (its node is Alive in SWIM) and (its health check passes). Any failing → degrade (I4). SWIM is fast for node death; lease is the catch-all; the health check is application-level.
  • Eureka self-preservation (a key AP safeguard): if a node loses heartbeats from a large fraction of instances at once (renewal rate drops below a threshold), assume network, not mass death — stop expiring leases until the rate recovers (avoids evicting a healthy fleet during a network blip). A bounded, AP-preserving override of I3.

8.4 Gossip dissemination

  • Model: each registry/health/membership change becomes an event {key, value, incarnation, logical_ts}. Events are (a) piggybacked on SWIM probe/ack messages and (b) spread by periodic push-pull rounds to k random peers.
  • Push / pull / push-pull: push = send my new events; pull = ask a peer for its events; push-pull = exchange digests then deltas (the default — converges fastest, Demers 1987).
  • Dissemination limit (I8): each event is gossiped at most ~log N times (a counter per event), then retired — bounds bandwidth; anti-entropy (I9) catches anyone who missed it.
  • Apply rule (I7/I11): a received event for key is applied iff (incarnation, logical_ts) is strictly greater than the local value's → monotonic, conflict-free, deterministic winner.

8.5 Anti-entropy (Merkle reconciliation)

  • Purpose (I9): guarantee convergence despite gossip loss. Periodically, node A and node B exchange a Merkle tree over their (key → version) state; matching subtrees are skipped, differing subtrees recursed into; only the differing keys are exchanged (read-repair).
  • Tree (#71): leaves = hash(key, incarnation, logical_ts); internal = hash(children); root mismatch → walk down to the differing leaves. Bandwidth ∝ diff size, not state size (§4.4).
  • Frequency: lower than gossip (e.g. every 10–30 s); the convergence backstop, not the primary path.

8.6 Federation / WAN

  • WAN gossip pool: a sparse set (e.g. 3 designated nodes per region) join a cross-region gossip pool exchanging region-level summaries (the Consul model) — not every node talks WAN (bounds WAN traffic, principle 6/§4.4).
  • Selective replication: a region replicates a remote service's instances only if (a) a local client has queried it (demand-driven) or (b) a replication policy includes it. Avoids replicating the whole world to every region.
  • Region projection: remote services appear locally as a read-only projection tagged with their origin region + a freshness/staleness age (I10).
  • Cross-region resolution (I12): resolve locally first; if empty or policy says allow_remote, consult region projections, ordered by the locality ladder.
  • Independence (I13): the WAN path is off the local read critical path — a WAN partition degrades remote answers (served stale, flagged) but never blocks local discovery.

8.7 Resolution / query engine

  • Input: ResolveQuery{ name, tags, health_policy, locality, allow_remote, max_results, weight_mode }.
  • Steps: (1) canonicalize name (I1); (2) gather candidate instances (local catalog ⨝ health); (3) filter by health policy (I4) + tags; (4) order by locality ladder (I12) then weight; (5) if empty and allow_remote, repeat over region projections (I13); (6) cap to max_results; (7) cache the result with TTL (I10).
  • Blocking query (I5): the client sends a last_seen_version; the server holds the request until the result set's version exceeds it or the timeout fires → efficient change notification without polling.
  • The engine returns candidates; it does not pick one (no load balancing) — the client/LB chooses (with retries across candidates, the AP recovery for a stale entry).

8.8 Wire protocols (lightweight)

  • Gossip frame: [magic | version | type | from-node | seq | len | checksum | payload]; types: Probe, Ack, IndirectProbe, Push, Pull, PushPull, AeDigest, AeDelta, WanSummary, Bye. UDP for SWIM/gossip (small, lossy-ok), TCP for anti-entropy/large deltas.
  • DNS: standard RFC 1035 message; we author A/AAAA/SRV/TXT/PTR answers; TTL per record from the cache strategy.
  • API: gRPC (HTTP/2) Register/Deregister/Renew/Resolve/Watch/Catalog; proto versioned (I15).
  • Apply / merge: every state-bearing frame carries (incarnation, logical_ts) for the apply rule (I7/I11).

8.9 State machines

  • Instance: Registered(Passing) → {Warning | Critical} → {Passing (recover) | Deregistered (graceful) | Expired (lease) | Evicted (node dead)}.
  • Node (SWIM): Alive → Suspect → Dead; Suspect → Alive on refutation (higher incarnation, I11); Dead gossiped, then forgotten after a tombstone window.
  • Lease: Active → (renew → Active) | (no renew within ttl → Expired).
  • Region link (federation): Connected → {Degraded(stale) → Connected | Partitioned(serve-local-only) → Connected}.

8.12 Convergence / consistency model (eventual + conflict resolution)

  • Consistency class: the health/membership state is an eventually consistent, conflict-free replicated map keyed by InstanceId/node-id, values ordered by (incarnation, logical_ts) — a last-writer-wins register per key with a deterministic total order (I11). This is a CRDT-flavored design (an LWW-register map): merges are commutative, associative, idempotent → any gossip/anti-entropy order converges to the same state.
  • Why not vector clocks (#95) for the value? Vector clocks detect concurrent updates so the application can merge them; here the desired semantic for "instance health" is simply the most recent assertion wins (a node's own incarnation is authoritative for its own state), so an incarnation+timestamp LWW register is sufficient and far cheaper (O(1) vs O(N) metadata). Vector clocks inform the reasoning and would be needed if we allowed third-party edits to an instance's state (we do not — each node owns its own + its instances').
  • Incarnation numbers (the SWIM mechanism): a node's incarnation increments whenever it must refute a suspicion ("I'm alive, incarnation N+1") — this lets a falsely-suspected node override the Suspect gossip deterministically (I11/principle 8). Incarnations are the per-key version that makes LWW correct across the refute/suspect race.
  • Convergence guarantee (I9): gossip gives probabilistic fast convergence; anti-entropy gives deterministic eventual convergence (Merkle reconcile transfers any missing/older keys). Together: bounded-time convergence (§4.1) with a hard backstop. No two correct nodes stay divergent past one anti-entropy interval.
  • What is NOT guaranteed: linearizability of health (it's AP — a read may return data another node has already superseded, within the staleness bound, I10); monotonic-read consistency across different agents (each agent's cache may be at a different version — bounded, flagged). The catalog tier (P10) optionally adds per-region linearizability for catalog writes only.

8.13 Worked example — Consul-style multi-DC, demand-driven federation

  • Setup: regions us-east, us-west, eu. Service payments runs only in us-east (10 instances). A client in us-west resolves payments with allow_remote=true.
  • First resolution: us-west has no local payments, no projection yet → federation queries the us-east WAN pool → fetches the 10 instances → caches a projection locally (tagged origin us-east, age 0) → returns them ordered (all remote, same locality tier).
  • The projection now subscribes (demand-driven selective replication): us-east's WAN pool gossips payments health/membership changes to us-west's WAN pool → subsequent us-west resolutions are local-projection cache hits (sub-ms), kept fresh within the WAN propagation bound (§4.1).
  • An instance in us-east goes Critical → gossiped within us-east (< 2 s) → WAN-gossiped to us-west projection (< +WAN-RTT+round) → us-west resolutions stop returning it (< ~3–5 s total, I10 staleness bound).
  • WAN partition us-east ↔ us-west: us-west keeps serving its last-known payments projection, flagged stale with a growing age (I10/I13); when age exceeds a policy threshold the projection may be marked all-Critical (fail-safe) or kept (fail-stale) per config (P9). us-east is entirely unaffected (serves locally). Neither region's discovery goes down for a WAN issue (principle 1/6).
  • Contrast with a hypothetical CP design: a global linearizable catalog would have refused the us-west registration-or-read on the minority side of the partition → us-west's payments routing down until heal. The AP design degrades to stale, not down (§2.7).

8.14 Worked example — registry storm (mass restart) and how it's shed

  • Trigger: a 10^4-instance region's hosts all restart (a rolling deploy gone wide, or a power event) → every instance's agent re-registers within seconds → O(10^4) catalog writes + health events in a burst.
  • Naive failure: each event gossiped independently at fanout k → O(10^4 · k · log N) messages in seconds → gossip broadcast storm → CPU/NIC saturation → SWIM probes delayed → false failure detections → more churn → meltdown (the feedback loop).
  • Mitigations (principle 5, §4.4):
    • Dissemination batching: the gossip layer coalesces many pending events into one push-pull message (amortize per-message overhead) — O(10^4) events ride in O(10^4 / batch) messages.
    • Rate-limited / jittered re-registration: agents spread re-registration over a window (randomized backoff) so the burst is smeared, not instantaneous.
    • SWIM isolation: the failure detector runs on its own cadence (and self-preservation, §8.3, kicks in if the renewal rate craters — assume network, don't evict) → the storm does not cause cascading false deaths.
    • Anti-entropy convergence: even if many gossip events are dropped under load, the post-storm Merkle reconcile (I9) converges everyone — correctness is preserved even when the fast path is overwhelmed.
  • Outcome: the storm is bounded and shed (batched, rate-limited, self-preserving), convergence is guaranteed (anti-entropy), and detection stays stable (SWIM isolation + self-preservation). The §4 50 k/s burst target is the design point for this scenario.

Design principles (§6)

  • Discovery is AP, not CP — choose availability under partition. Every region keeps answering with bounded-stale data rather than blocking to agree. Violation: a CP discovery core (etcd-only) → discovery availability = consensus availability → a partition takes the whole fleet's routing down (§2.7). Tradeoff: transient stale answers (bounded, recoverable) over outages.
  • Bounded staleness, always reported — never unbounded, never silent. Stale answers carry an age/stale flag; the staleness bound (§4.2) is enforced (gossip + anti-entropy + TTL). Violation: unbounded or unlabeled staleness → clients trust dead data indefinitely → silent black-holing of traffic.
  • Gossip for speed, anti-entropy for certainty. Gossip disseminates fast but lossily (O(log N)); periodic Merkle anti-entropy guarantees eventual convergence (catches drops). Violation: gossip-only → a dropped update leaves nodes permanently divergent; anti-entropy-only → propagation is minutes, not seconds.
  • Two liveness signals: lease (instance asserts) + SWIM (peers detect) — combine them. Leases catch clean exits / stuck-but-present; SWIM catches sudden node death fast and bounds detection. Violation: leases-only → slow detection of crashed nodes (wait full TTL); SWIM-only → can't catch an instance that's up but unhealthy/not-renewing.
  • Backpressure + bounding everywhere — survive the registry storm. Gossip fanout, dissemination limits, batching, rate-limited re-registration, bounded caches, single-flight. Violation: unbounded gossip on mass restart → broadcast storm → cluster meltdown; unbounded caches → OOM (§4.4).
  • A region is independently authoritative; the WAN is best-effort. Local discovery never depends on a remote region or the WAN link being up. Federation replicates selectively and asynchronously. Violation: synchronous cross-region dependency → a WAN partition stops local discovery (the opposite of AP, principle 1).
  • Split catalog (consistency-leaning) from health (eventual). Rarely-changing catalog metadata may be per-region linearizable (Raft); constantly-changing health is always eventual (gossip). Violation: all-CP → health changes need consensus → unscalable + blocks resolution; all-AP catalog → conflicting metadata (two ports for one instance) with no authority.
  • Failure detection is bounded and false-positive-aware. Detection time < a fixed bound (§4.3); indirect probes + incarnation numbers minimize false positives. Violation: aggressive timeouts → healthy instances flap out of resolution (real traffic loss); lax timeouts → dead instances served for minutes.
  • Resolution is read-mostly and lock-free on the hot path. The catalog is RCU/arc-swap-read-optimized; resolution never takes a global write lock. Violation: a lock on the resolution path → contention collapses QPS under load (the hot path is 50 k+ QPS/node).
  • Cache aggressively with TTLs, negative caching, and stale-if-error. Multi-tier (agent → regional → authoritative) shields the source and serves AP under failure. Violation: no caching → every request hits the authoritative store → it melts; no stale-if-error → a source blip = a resolution outage (un-AP).
  • Conflict resolution is deterministic (incarnation + LWW), not ad hoc. Concurrent updates to the same instance resolve by incarnation number then timestamp — total order, every node agrees. Violation: non-deterministic merge → nodes converge to different states (divergence that anti-entropy can't fix because they disagree on the winner).
  • Stable wire compatibility across gossip, DNS, and the API. Gossip/WAN frames, DNS responses, and the gRPC schema are versioned; mixed-version nodes negotiate or refuse. Violation: silent protocol drift during a rolling upgrade → corruption / partition between versions.
  • Observe every propagation, every convergence, every staleness. Emit propagation time, gossip rounds, anti-entropy repairs, resolution latency by tier, staleness age, false-positive rate. Violation: opaque convergence → "why isn't service X visible in region B?" is undebuggable.
  • Correctness anchored to a single-region oracle + deterministic simulation. A single authoritative store (no gossip) is the reference; DST (virtual time + injected faults) verifies convergence/staleness deterministically. Violation: no oracle → eventual-consistency bugs (the worst kind) are unreproducible and undebuggable.
