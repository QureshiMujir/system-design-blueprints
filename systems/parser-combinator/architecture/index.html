Reference Parsers (top box). Seven crates under parsers-*; each is simultaneously a demonstration and a conformance-corpus producer. Trust boundary: input here is untrusted network/file bytes (§25 T1–T4).

Pratt Climber / Packrat+Left-Rec / Grammar Macro (middle row). Three independent accelerators over the combinator core — none is required to use the others. Concurrency boundary: each has its own owned state (MemoTable, climber operator tables) per top-level parse invocation, never shared across threads.

Combinator Core. The one-way data path: bytes/tokens flow up through Stream into the combinator chain; IResult<I,O,E> flows down. All primitives, branching, repetition, mapping, recognition, and the error tree live here (§13–§17); streaming semantics (§18) are a mode switch on the same combinators, not a separate crate.

Stream backends / ParseError tree. Persistence boundary: Stream impls borrow from the caller's buffer (zero-copy); nothing is owned except the Vecs repetition combinators allocate. Protocol boundary: ParseError<I> is the sole channel between a parse failure and a human-readable diagnostic.

mini-source. Shared position/rendering substrate; a single source-position type across this project and Lexer-Tokenizer is non-negotiable (P2, §6).

Erased escape hatch. Cuts across every layer above; a caller boxes at exactly the recursion boundary that needs compile-time relief (§23), never library-wide.

8. Domain Model / Protocol / Data Model

8.1 The grammar formalism

Every grammar in this document is written as EBNF-like PEG notation: / is ordered choice (alt), juxtaposition is sequence (seq), */+/? are many0/many1/opt, &e/!e are peek/not. This notation is used identically in phase prose and the parser! macro (§21).

8.2 The result-state algebra

IResult<I,O,E> = Result<(I,O), Err<E>>. State-transition table for alt(p1, p2):

Current state (running p1) alt action Resulting state
Ok((rest, out)) return immediately Ok((rest, out))
Err(Error(e)) try p2 on original input whatever p2 returns
Err(Failure(e)) propagate, do not try p2 Err(Failure(e))
Err(Incomplete(n)) propagate, do not try p2 Err(Incomplete(n))

cut(p) state transition: Ok(_) passes through unchanged; Err(Error(e)) becomes Err(Failure(e)); Err(Failure(e)) and Err(Incomplete(n)) pass through unchanged.

8.3 Worked example — JSON object grammar (EBNF)

value    = ws (object / array / string / number / "true" / "false" / "null") ws
object   = "{" ws members? ws "}"
members  = member ("," ws member)*
member   = string ws ":" ws value
array    = "[" ws elements? ws "]"
elements = value ("," ws value)*

Commit points (§17): after object consumes "{", the remainder of that alternative is cut — there is no other alternative once { is seen, so a malformed body is a Failure, not an Error alt could route around.

8.4 Malformed-input trace

Input {"a": } (missing value). Trace: object matches "{" → commits (cut) → members → member matches "a", ":" → value tries object(Error, next char is }) → tries array (Error) → tries string (Error) → tries number (Error) → tries literals (Error) → all of value's alternatives exhausted → Err::Error(merged expected-set) at position 7 → because this is inside the cut from object, the enclosing member/ members/object chain converts it to Err::Failure at the object boundary → reported as "expected a value after : at line 1 column 8" (Context chain: object → members → member).

8.5 Failure-path example — left-recursive expression

Grammar expr = expr "+" term / term on input 1+2+3 (§19 Phase 7 seed-and-grow): seed expr at position 0 with Err::Error(LeftRecursion); non-recursive alternative term matches 1 (length 1); grow: re-run with seed = 1, recursive alternative now matches expr "+" term = 1+2 (length 3, longer) → replace seed; grow again: 1+2+3 (length 5, longer) → replace seed; grow again: no longer match → stop. Final parse: left-associative (1+2)+3, matching invariant I6.

Design principles (§6)

  • The byte slice is the ground truth (P1). Every combinator has an implementation against &[u8]; &str and token-iterator backends are derived. Conformance compares against the byte-slice path. Tradeoff: derived backends may lag the ground truth briefly during development. Operational implication: a bug fixed only in &str and not back-ported to &[u8] is a conformance-suite failure by construction. Violating it: backend drift, silently different parse results per backend.
  • One trait, two-plus backends (P2). Parser<I,O,E> is defined once; Stream is implemented per backend. Tradeoff: one extra associated type/type parameter vs. a BytesParser/StrParser hierarchy. Operational implication: the shipped reference parsers (§24) work unmodified against any backend. Violating it: combinator duplication across backends, doubling the maintenance surface.
  • Monomorphisation is the default; erasure is opt-in (P3). Hot-path chains monomorphise (nom-style); BoxedParser (chumsky-style) is opt-in at the boundary the caller picks. Tradeoff: compile time vs. throughput, paid only where chosen (ADR-02, ADR-07). Operational implication: a 50-rule grammar can choose 12 s compile / 500 MB/s or 8 s compile / 180 MB/s per boundary (§35 row 7). Violating it (erasing by default): silent throughput loss with no compile-time benefit for small grammars.
  • Errors are values; failures are commit points (P4). IResult returns Ok, Err::Error (recoverable — alt retries), or Err::Failure (committed — alt propagates). Only cut converts Error→Failure (I2, I10). Tradeoff: the caller must place cut correctly (§17 Phase 5). Operational implication: error-message quality is a direct function of cut placement. Violating it: garbage "expected one of: [50 items]" messages (FM3).
  • Spans are everywhere (P5). Every combinator output can carry a ByteSpan cheaply (recognize_with_span); every error carries a span at the failure point. Tradeoff: one u32 pair per span. Operational implication: IDE/reporter tooling never needs the user to thread positions by hand. Violating it: unrecoverable loss of provenance (MM6).
  • PEG semantics, deterministic ordered choice (P6). alt tries alternatives in declaration order (Ford 2004); it is not the CFG |. Tradeoff: alt(short, long) can make long unreachable. Operational implication: documented three times (rustdoc, docs/commit-points.md, README gotchas) because it is the dominant support load. Violating it (assuming commutativity): silently wrong parses on overlapping alternatives.
  • Packrat is opt-in (P7). memoize(rule) wraps a rule in a packrat table; the rest of the grammar allocates no memo table. Tradeoff: O(input×rules) memory only where chosen (ADR-05, C4). Operational implication: left-recursive rules require left_recursive(rule) (Frost/Hafiz/Callaghan + Warth). Violating it (memoising everything): the memory blow-up quantified in §35 row 1.
  • No allocation on the combinator hot path (P8). The chain itself is zero-allocation; many0/many1/separated_list allocate a Vec because they must — fold0/fold1 are the zero-allocation alternative. Tradeoff: the caller chooses allocation explicitly. Operational implication: an allocation-counting CI job gates every combinator (I12). Violating it: a 30% throughput regression per historical measurement (§28 Phase pitfall lineage).
  • Compile-time grammars where ergonomic (P9). The parser! macro (§21 Phase 9) is sugar over the explicit chain, adding no runtime cost beyond it. Tradeoff: macro-expansion diagnostics are harder to author than plain Rust errors (ADR-16, ADR-21). Operational implication: a 50-rule grammar via macro compiles in ≤ 12 s (M7) vs. ≈ 90 s hand-written. Violating it (skipping the macro): 20-rule grammars balloon to hundreds of lines of boilerplate.
  • Streaming is first-class but not default (P10). Incomplete(Needed) is a third return variant; Streaming/Complete modes are per-call-site (nom-7 style), not per-library. Tradeoff: two combinator variants to maintain per streaming-capable primitive. Operational implication: a grammar can mix modes ("streaming until the top-level value, complete inside it"). Violating it (streaming-only): forces every caller to pay the Incomplete-handling cost even for in-memory-only inputs.
  • Reference parsers are conformance, not demos (P11). Every shipped grammar (§24) is simultaneously documentation and a conformance-corpus producer; there is no "example code" that conformance does not also gate. Tradeoff: shipped parsers must stay in lock- step with their RFC/spec even when a demo-only parser would not. Operational implication: a parsers-json regression is caught by conformance.yml, not manual review. Violating it: bit-rotting examples that no longer reflect the library's actual behavior.
  • Errors are rendered, not stringly-typed (P12). The error tree (ParseError/ ErrorKind/Expected/Context) is structured; reporters (ariadne, codespan- reporting) are pure functions over it, never string concatenation inside combinators. Tradeoff: one extra type layer between "a combinator failed" and "text on screen". Operational implication: swapping reporters (ADR-09) costs zero combinator changes. Violating it: reporter-specific formatting leaking into the combinator core.
  • Composability over completeness (P13). The library ships primitives sufficient to build any PEG grammar rather than special-casing every grammar shape (no built-in regex engine, no built-in JSON-specific fast path outside parsers-json). Tradeoff: some grammars need more combinator composition than a bespoke tool would require. Operational implication: the seven shipped parsers (§24) are proof the primitive set is sufficient. Violating it: feature creep turning the core into a grammar-specific tool.
