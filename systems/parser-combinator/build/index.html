⬜ Phase 0 — Skeleton, Governance, Smoke Parser §12

Objectives

Stand up the repository skeleton (§10), the virtual workspace, CI, and the empty Parser/ Stream trait shells (§11) so every later phase compiles incrementally. Land ADR-01, ADR-02, ADR-03, ADR-04, ADR-08, ADR-10, ADR-11 as initial governance decisions (§9). No combinators exist yet beyond the smoke parser.

Deliverable

make bootstrap && make build && make test all exit 0. mini-comb-cli reads a decimal integer from stdin and prints either the parsed u32 or a Debug-rendered ParseError.

Acceptance

cargo build --workspace --all-features exit 0; cargo test --workspace passes ≥ 2 tests (smoke_parser_positive, smoke_parser_rejects_non_digit); cargo clippy --workspace --all-targets -- -D warnings exit 0; cargo metadata --format-version 1 succeeds (validates no stray root [package] table alongside [workspace], §12.6).

Fixtures

conformance/corpora/smoke/valid_u32.jsonl (100 valid decimal strings, e.g. "0", "4294967295") → expect Ok. smoke/invalid_u32.jsonl (empty string, "12a", "-5") → expect Err::Error. smoke/overflow_u32.jsonl ("4294967296") → expect Err::Error(Custom).

Pitfalls

A virtual workspace declaring a root [package] table alongside [workspace] is rejected by cargo — verify with cargo metadata. rust-toolchain.toml pinning the floating stable channel (not an exact version like 1.83.0) leaves builds non-reproducible. Declaring parsers-* as workspace members before src/lib.rs exists breaks cargo build --workspace — stub each crate first.

⬜ Phase 1 — Primitives & Stream Backends §13

Objectives

Implement the five foundational primitives — char, tag, take, take_while, take_until — and the byte-slice and &str Stream impls (P1, P2) from which every later combinator is expressed.

Deliverable

All five primitives implemented for both backends; docs/parser-trait.md documents the trait shape and the closure-blanket-impl design.

Acceptance

Conformance buckets primitive.char, primitive.tag, primitive.take_while all report Pass with ≥ 200 cases each (§29). Proptest property take_while(p) monotone in p holds over 10,000 generated cases. tag("") is a documented no-op (zero-length match, Ok).

Fixtures

corpora/primitive/char.jsonl (256 single-byte cases, boundary at 0x00/0xFF). corpora/primitive/tag.jsonl (exact-match, partial-prefix, empty-literal cases). corpora/primitive/take_while.jsonl (empty match, full-consume, malformed-UTF-8-in-&str- mode rejection cases).

Pitfalls

The &str backend must reject take(n) at a non-codepoint boundary — return None from split_at, never panic (I8, T4); an alternate take_chars(n) takes n characters instead of bytes. take_while returns impl Fn, not impl FnMut, to keep the resulting combinator Copy-compatible for alt's I: Clone bound (§14). tag with an empty literal must not be rejected — shipped grammars occasionally emit it deliberately.

⬜ Phase 2 — Branching & Ordered Choice §14

Objectives

Implement alt, seq, opt, peek, not, eof — the PEG ordered-choice and sequencing primitives (P6, Ford 2004) — establishing I1 and I2's Error-vs-Failure propagation rule for the first time.

Deliverable

All six combinators implemented and documented; examples/lisp_repl.rs gains a partial calculator skeleton demonstrating alt+seq composition (completed in §20).

Acceptance

Conformance buckets branch.alt, branch.peek, branch.not report Pass. A test asserts alt(tag(b"foo"), tag(b"foobar")) matches only "foo" out of "foobar" (documenting the non-commutativity of I1/P6 with a named, checked example, not prose alone).

Fixtures

corpora/branch/alt.jsonl (ordered-choice precedence cases, incl. the foo/foobar gotcha). corpora/branch/peek.jsonl (lookahead-does-not-consume assertions). corpora/branch/not.jsonl (negative-lookahead success/failure pairs).

Pitfalls

alt requires I: Clone; free for Copy byte-slice inputs, real cost for owned/buffered streaming inputs (§18) — Stream deliberately requires Copy to keep this cheap. The PEG ordered-choice surprise (alt(short, long) makes long unreachable) is the largest single support load across every PEG library (chumsky, nom); documented in the alt rustdoc, docs/commit-points.md, and the README gotchas section, per P6.

⬜ Phase 3 — Repetition §15

Objectives

Implement many0/many1, separated_list0/separated_list1, delimited/preceded/ terminated, fold0/fold1, count, many_m_n — establishing I4's infinite-loop guard, the load-bearing safety property of every repetition combinator.

Deliverable

All seven repetition combinators implemented with the I4 guard; a property test asserts many0(p) and fold0(p, Vec::new, push) produce identical output.

Acceptance

Conformance buckets repetition.many0, repetition.fold0, repetition.sep_list report Pass. many0(opt(p)) on any input completes in bounded time (I4 regression test, explicit timeout assertion at 100 ms).

Fixtures

corpora/repetition/many0.jsonl (empty-input, single-element, zero-width-match cases). corpora/repetition/fold0.jsonl (output-equivalence-with-many0 cases). corpora/repetition/sep_list.jsonl (trailing-separator-present/absent cases).

Pitfalls

The I4 infinite-loop guard is mandatory: many0(opt(p)) matches the empty input forever without it. separated_list0 has the trailing-separator gotcha — shipped grammars (§24) universally use terminated(separated_list0(...), opt(sep)) when a trailing separator must be accepted. count(0, p) must succeed with Vec::new(), not error.

⬜ Phase 4 — Mapping & Recognition §16

Objectives

Implement map, map_res, flat_map, recognize, recognize_with_span, value, verify — the transformation layer between "matched some input" and "produced a typed AST node with provenance" (P5, Hutton 1992's higher-order-function view).

Deliverable

All seven combinators implemented; recognize unit-tested against tag+take_while for slice equality with the consumed prefix (I7).

Acceptance

Conformance bucket recognize.span reports Pass: every fixture's ByteSpan.start/end equals the parsed byte range exactly (I7). map_res's error carries the pre-parse position, verified by a dedicated regression fixture.

Fixtures

corpora/recognize/span.jsonl (span-equals-consumed-range assertions across primitive, branch, and repetition combinators). A map_res regression fixture asserting the error span points before, not after, the parsed prefix.

Pitfalls

recognize must compute the consumed length from the position delta, not by re-running p a second time — re-running risks side-effect divergence if p is stateful (e.g. wraps a memoised rule, §19) and is a documented historical regression class. flat_map's second parser's type depends on the first's output — this occasionally requires BoxedParser (§23) to keep the surface compilable in recursive grammars. map_res must save the input position before running f, or the error span points past the parsed prefix.

⬜ Phase 5 — Error Tree & Commit Points §17

Objectives

Implement ParseError/ErrorKind/Expected/Context (§11.3), the cut/labelled combinators, and the ariadne/codespan-reporting reporter integrations — the center of gravity of the whole library (P4, P12; Leijen & Meijer 2001; Wadler 1985).

Deliverable

ParseError<I>, Err<E> variants, cut, labelled all implemented; a config-file key-value grammar in examples/url_normalize.rs exercises the full discipline end to end.

Acceptance

insta snapshot tests (ADR-15) pass on 5 canonical error scenarios (truncated JSON, missing comma, mismatched bracket, unexpected character, unexpected EOF) for both reporters — 10 snapshots total, zero unreviewed diffs. Conformance buckets commit.cut, commit.labelled report Pass.

Fixtures

corpora/commit/cut.jsonl (Err::Failure propagates past alt — 20 fixtures spanning 1–4 nesting levels). corpora/commit/labelled.jsonl (context-chain-matches-recorded-chain fixtures). tests/snapshots/error_{truncated_json,missing_comma,mismatched_bracket, unexpected_char,unexpected_eof}.snap × 2 reporters.

Pitfalls

cut is a one-way door — indiscriminate use produces unrecoverable error positions, arguably worse than no cut at all; the rule is "cut at the minimal-discriminator boundary" (documented in docs/commit-points.md, not earlier, not later). The Expected set must dedupe or alt of three digit-matchers emits a triple-repeated message (§36 Q7). Context.label is &'static str, never String — the per-error allocation cost of a String would violate P8/I12 on the error path, which is exercised on every malformed input.

⬜ Phase 6 — Streaming & Incomplete Semantics §18

Objectives

Implement the Streaming/Complete per-call-site mode split (P10, ADR-08; nom-7 lineage) and the Incomplete(Needed) return variant, establishing I9 (non-consumption on Incomplete) for the first time.

Deliverable

The streaming submodule of mini-comb-core with streaming variants of tag, take, take_while, take_until, char; examples/streaming_jsonl.rs runs against a multi-chunk synthetic JSONL input.

Acceptance

Conformance bucket streaming.tag reports Pass: every fixture's Needed::Size(n) value matches the exact byte shortfall. examples/streaming_jsonl.rs processes a 1 GB synthetic JSONL stream fed in 4 KB chunks with zero panics (M9 soak precursor). PhaseDeferred("§18.4: async streaming driver wrapping this synchronous core; owned by Event-Loop project") is registered (§38) rather than implemented here — this phase ships the synchronous Incomplete contract only.

Fixtures

corpora/streaming/tag.jsonl (partial-buffer fixtures at every truncation point of a multi-byte tag, each asserting the exact Needed::Size). A soak fixture: 10,000-line JSONL file split at 4 KB boundaries, replayed through the streaming driver contract.

Pitfalls

Err::Incomplete is neither Err::Error nor Err::Failure — alt propagates it unconditionally (never retries the next branch), a distinct rule from I2 worth restating because it is easy to conflate the three-way split with a two-way one. A driver that feeds zero new bytes between Incomplete responses spins forever — the discipline (documented, not enforced by the type system) is "never feed less than one byte"; violating it is a caller bug, not a library bug, but the library's docs must say so explicitly.

⬜ Phase 7 — Packrat Memoisation & Left Recursion §19

Objectives

Implement memoize(rule) (Ford 2002 packrat) and left_recursive(rule) (Frost, Hafiz & Callaghan 2007 seed-and-grow + Warth & Piumarta 2007 head-set tracking for indirect recursion), establishing I5 and I6.

Deliverable

memoize/left_recursive implemented in mini-comb-memo; a benchmark (benchmarks/packrat_left_rec.rs) compares memoised vs. naive recursion on a 1,000-token arithmetic expression.

Acceptance

The classical left-recursive grammar expr = expr "+" term / term; term = term "*" factor / factor; factor = number / "(" expr ")" parses 1+2+3 as left-associative (1+2)+3 (§8.5 worked trace). Conformance bucket packrat.left_rec reports Pass. benchmarks/ packrat_left_rec.rs shows linear (not exponential) scaling from 100 to 10,000 tokens (≤ 2× wall-clock per 10× input, the packrat linearity signature).

Fixtures

corpora/packrat/memo.jsonl (repeated-position hit fixtures — second hit at the same (rule, pos) must be O(1), verified by an instruction-count budget via iai-callgrind). corpora/packrat/left_rec.jsonl (direct and indirect left-recursion fixtures, incl. the four-alternative arithmetic grammar of §8.5).

Pitfalls

Two distinct rules sharing a rule_id (a hand-written, non-macro-generated collision) conflates their memo entries — caught only by the I5 debug assertion, not by any type-level mechanism (the parser! macro of §21 avoids this by auto-assigning unique IDs). Growing must terminate because each grow step consumes strictly more input (I6); a left-recursive rule with an empty-matching alternative violates this and is rejected at construction, not at parse time. Memo entries hold outputs by Clone — expensive-to-clone ASTs defeat the speedup; the recommendation (docs/packrat-and-leftrec.md) is to memoise rules whose output is Rc<AstNode>, not AstNode by value.

⬜ Phase 8 — Pratt Operator-Precedence Climbing §20

Objectives

Implement PrattClimber (§11.7) — Pratt 1973's operator-precedence algorithm in its recursive "precedence climbing" formulation (Nystrom 2021 Ch. 17) — supporting mixed prefix, infix, and postfix operators with configurable associativity.

Deliverable

PrattClimber implemented in mini-comb-pratt; the calculator in examples/lisp_repl.rs (started in §14) is completed using it.

Acceptance

The calculator produces the correct AST for 1 + 2 * 3 (Add(1, Mul(2,3)), precedence), 2 ^ 3 ^ 4 (Pow(2, Pow(3,4)), right-associativity), and -3! (Neg(Fact(3)), prefix binds looser than postfix). benchmarks/pratt_expression.rs parses a 1,000,000-token arithmetic expression and reports ≥ 80,000,000 tokens/s (M5).

Fixtures

corpora/pratt/calc.jsonl (full power-table coverage: left-assoc, right-assoc, prefix, postfix, and the mixed---disambiguation case, ≥ 30 fixtures).

Pitfalls

Right-associative operators have inverted power triples ((20,19), not (19,20)) — an off-by-one here is the single most common Pratt bug; tests must cover both associativity directions explicitly (§20.4's 2^3^4 case). The cut after an operator match is critical for correctness, not just message quality: without it, an outer alt can swallow a "missing right operand" Error and silently produce a wrong-but-plausible shorter parse (§36 Q15 connects this to I2).

⬜ Phase 9 — Grammar Macro Ergonomics §21

Objectives

Implement the parser! declarative macro (P9, ADR-16, ADR-21) — a peg-style grammar DSL that expands to plain combinator chains with zero added runtime cost, easing the boilerplate of 20+-rule grammars (motivated in §5's pest reference-implementation entry as the build-time-codegen alternative this macro avoids, §37 A3).

Deliverable

The parser! macro implemented in mini-comb-macros; an ergonomic rewrite of the JSON grammar (anticipating parsers-json, §24) demonstrates a 20-rule grammar in macro form.

Acceptance

A 50-rule synthetic grammar compiles via the macro in ≤ 12 seconds, cold cache (M7). Macro-expansion golden-output test (I13) confirms byte-identical expansion across the two oldest and newest compiler versions in rust-toolchain.toml's supported range. A deliberately malformed grammar (missing () on a rule head) produces a pinpointed proc-macro-error diagnostic, not a multi-hundred-line generic trait-bound error.

Fixtures

tests/macro/small_grammar.rs (5-rule grammar, exercises every DSL operator once). tests/macro/json_grammar.rs (20-rule grammar, exercises memoize!/mutual recursion). tests/macro/malformed_grammar.rs (5 deliberately malformed fragments, asserts diagnostic text via insta, per ADR-15's discipline extended to macro diagnostics).

Pitfalls

Macro hygiene around bound names: name:expr binds name only in that rule's action block — the action block must not incidentally see other macro-internal identifiers (historical bug class in syn-based macros with careless hygiene). Recursive expansion of mutually recursive rules needs the forward-declaration struct-of-methods pattern or the type checker rejects the cycle outright. Diagnostic spans must point at the offending grammar fragment, not the macro invocation as a whole, or debugging a 50-rule grammar becomes a linear scan (FM8).

⬜ Phase 10 — SIMD Literal Fast Path §22

Objectives

Accelerate literal-byte scanning via memchr/bytecount (ADR-17) without porting the full simdjson structural pre-pass (Langdale & Lemire 2019) — the Phase-0-appropriate slice of that paper's throughput argument.

Deliverable

memchr-backed take_until/take_while_byteclass; benchmarks/json_throughput.rs confirms the literal fast path's throughput on the citm_catalog.json fixture (used identically in §24's parsers-json).

Acceptance

benchmarks/json_throughput.rs reports ≥ 500 MB/s on citm_catalog.json (1.7 MB, M1). A differential test (FM6) runs the same corpus with the memchr feature on and off, byte-comparing every output — zero divergence permitted.

Fixtures

benchmarks/results/json_throughput.json (recorded throughput number, gated in CI per §31). A differential-test corpus of 500 JSON documents run through both the SIMD and scalar code paths.

Pitfalls

memchr operates on &[u8]; the &str backend must slice via as_bytes() and re-validate UTF-8 on the way out — the validation cost is negligible because core::str::from_utf8 is itself vectorised on common targets. The fast path applies only to static byte-class predicates; a user-supplied closure does not qualify and must use the explicit take_while_byteclass API rather than being silently un-accelerated (ADR-17).

⬜ Phase 11 — Erased Combinators & Compile-Time Relief §23

Objectives

Implement BoxedParser (§11.8, ADR-02, ADR-07) — the opt-in dynamic-dispatch escape hatch that trades one indirect call per combinator boundary for dramatically shorter compile times on large or deeply recursive grammars (chumsky's headline design, §5, §34).

Deliverable

BoxedParser<'a,I,O,E> implemented in mini-comb-erased; benchmarks/erased_vs_mono.rs compares monomorphised vs. erased dispatch on the JSON fixture.

Acceptance

A 50-rule grammar compiles in ≈ 90 s monomorphised vs. ≈ 8 s erased (cold cache, matching M6/C12's worked numbers). benchmarks/erased_vs_mono.rs reports erased-mode JSON throughput ≥ 180 MB/s (M12) against the monomorphised path's ≥ 500 MB/s (M1) — both recorded, neither regresses silently.

Fixtures

benchmarks/results/erased_json.json (recorded ≥ 180 MB/s). A compile-time regression fixture: a fixed 50-rule grammar's compile-time is tracked release-over-release in benchmarks/results/ for both dispatch modes.

Pitfalls

Recursive grammars that omit BoxedParser at the recursion boundary fail to compile with a type-size error, not a runtime bug — easy to misdiagnose as a macro bug rather than a missing erasure boundary (§21.2's auto-insertion mitigates this for macro-authored grammars only; hand-written recursive chains must box manually). The 'a lifetime mismatch between a captured reference and the box's lifetime is a common first-attempt compile error for new contributors.

⬜ Phase 12 — Shipped Reference Parsers & Conformance Corpus §24

Objectives

Ship seven reference parsers — HTTP/1.1 request line, JSON (RFC 8259), CSV (RFC 4180), IPv4/IPv6, RFC 3339/2822 date-times, URL (WHATWG), S-expressions/Lisp — each simultaneously documentation and a conformance-corpus producer (P11), proving the combinator set sufficient for real-world grammars (P13) and delivering the library's success criterion: replacing a downstream nom/chumsky user.

Deliverable

All seven parser crates compile, pass their conformance corpora, and carry rustdoc with a runnable example each; every crate has ≥ 1 cargo-fuzz target (fuzz/fuzz_targets/).

Acceptance

parsers-json hits ≥ 500 MB/s on the literal fast path (M1); parsers-http hits ≥ 100 MB/s (M2); parsers-csv hits ≥ 250 MB/s (M3); parsers-net::ipv6 sustains ≥ 3,000,000 addresses/s on a 10M-address corpus (M4). Every JSONTestSuite fixture's accept/reject vector matches exactly (json.suite bucket). Conformance suite aggregate wall-clock ≤ 90 s (M8).

Fixtures

conformance/corpora/{http,json,csv,net,rfc-dates,sexp}/ — 23 buckets total (§29 lists all), including json.suite (JSONTestSuite mirror, ~300 fixtures), net.ipv6 (::- elision, embedded-IPv4, zone-ID cases), net.url (WHATWG accept/reject), dates.rfc_3339 (parse+format round-trip).

Pitfalls

JSON \uXXXX surrogate-pair mishandling (decoding a lone \uD83D as U+D83D instead of combining with its low surrogate) is the single most common JSON-parser bug and produces invalid UTF-8 if unguarded. IPv6 :: elision must enforce "exactly one :: per address" — a naive many0(group) accepts multiple :: and produces ambiguous addresses. RFC 3339 and RFC 2822 differ in time-zone notation; the two crates must not share parsing code without a pinned differential test. WHATWG URL and RFC 3986 disagree on percent-encoding and userinfo handling — the default (WHATWG) must be documented as a deliberate, not accidental, divergence from the RFC.
