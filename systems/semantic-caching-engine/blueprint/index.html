328 — Semantic Caching Engine from Scratch

Project Number: 328

Project Name: Semantic Caching Engine from Scratch

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal

Build a single-node, multi-core Semantic Caching Engine: a cache for LLM / embedding-API responses keyed by semantic similarity of the prompt, not exact bytes. A request embeds the prompt → ANN lookup in a vector index → if nearest neighbor's similarity ≥ threshold AND validity checks pass → return the cached response (HIT); else MISS → call the backing model, store (embedding, prompt, response, metadata). The novelty over a key-value cache is the fuzzy match plus a correctness gate: the central tension is false hit (returning a semantically-close-but-wrong answer) vs false miss (paying for a redundant model call). False-hit rate is a first-class SLO, not an afterthought.

System boundaries (in scope):

  • Embedding provider abstraction (sc-embed): pluggable local model vs remote API; deterministic embedding-model versioning; embedding-model-version is part of the cache key namespace — mixing versions in one index is an invariant violation (I1).
  • Vector index (sc-index): ANN over cached keys. HNSW primary; IVF-PQ alternative; incremental insert/delete; tombstones; rebuild/compaction. Cross-link #255 (ANN), #45 (Vector DB), #46 (Embedding + Similarity Search).
  • Similarity gating (sc-policy): cosine threshold, per-namespace thresholds, calibration; the false-hit / false-miss tradeoff lives here.
  • Hit verification / re-ranking (sc-policy): optional exact re-score, cross-encoder re-rank, response staleness / faithfulness checks before serving a HIT.
  • Cache store (sc-store): response payloads + metadata (prompt hash, embedding ref, model version, timestamps, token cost saved, TTL); value store separated from vector index; persistence + WAL for crash recovery.
  • Eviction & invalidation (sc-store + sc-policy): LRU / LFU + semantic-aware eviction (cluster pruning); TTL; explicit invalidation by key / namespace / model-version. Cross-link #57 (LRU/LFU), #60 (Key Expiration & Eviction).
  • Admission control / backpressure (sc-admit): don't cache low-value or non-deterministic responses; cost-benefit admission; load shedding. Cross-link #59 (Distributed Cache).
  • Consistency & correctness: per-namespace isolation, embedding-version isolation, monotonic timestamps, exactly-once store, no torn reads under concurrent insert / evict.
  • Observability (sc-observe): hit rate, false-hit rate (sampled via ground-truth probes), latency saved, cost saved, threshold drift, index recall; deterministic replay of a request + stats trace.
  • Deployment: a library crate (sc-core) plus a semcache server (HTTP/gRPC) sitting as a proxy in front of an LLM / embedding API, with streaming passthrough on a MISS.

Explicit non-goals (deferred, gated PhaseDeferred("Deferred Features Register")):

  • Training / fine-tuning embedding models — we consume an embedding provider, never train one. PhaseDeferred("Deferred Features Register").
  • The backing LLM itself — semcache proxies an external model endpoint; generation is out of scope. PhaseDeferred("Deferred Features Register").
  • Distributed / multi-node sharded cache (consistent-hash ring, cross-node fan-out, replicated index). The seam exists (Namespace + shard-key) but is single-node here. PhaseDeferred("Deferred Features Register") (cross-link #59).
  • GPU-accelerated ANN / embedding kernels — portable scalar + SIMD-autovectorized distance only. PhaseDeferred("Deferred Features Register").
  • RAG document chunking / retrieval orchestration — semcache caches the model call, not a retrieval pipeline. PhaseDeferred("Deferred Features Register") (cross-link #251 RAG, #327 AI Agent Memory).
  • Learned / online-trained admission or threshold policies — thresholds are calibrated offline + adjusted by bounded feedback, not RL. PhaseDeferred("Deferred Features Register").

Deployment model: a library crate (sc-core) embeddable in an application's model-call path, plus a thin semcache server binary that exposes an OpenAI-compatible-ish HTTP/gRPC surface, forwards MISSes to a configured upstream, streams the response back while storing it, and exports metrics + a request/decision trace. Operators run it as a sidecar or gateway in front of their model provider.

Target users / operators / developers: application engineers cutting LLM spend + latency by caching repeated/near-duplicate prompts; platform engineers running an inference gateway who must bound false-hit rate; learners building the GPTCache / semantic-cache design end to end with real correctness gates and observability.

Phase 0 deliverable (numbered crates/modules):

  1. sc-types — Embedding, CacheKey, Namespace, ModelVersion, CacheEntry, Similarity, Decision, error enum, wire/IR types + serde.
  2. sc-embed — EmbeddingProvider trait; a deterministic mock/hash provider (real providers land in §13); embedding-version stamping.
  3. sc-index — VectorIndex trait + a brute-force exact-cosine baseline (HNSW lands in §14); insert/search/delete signatures.
  4. sc-store — in-memory value store keyed by EntryId (persistence/WAL land in §15); metadata records.
  5. sc-policy — similarity gate skeleton: cosine threshold compare → Decision::{Hit, Miss} (calibration/verification land in §16–§17).
  6. sc-observe — counters (hit, miss) + structured logging skeleton (full metrics/probes land in §22).
  7. sc-server — HTTP skeleton: POST /v1/lookup (embed→search→gate) and POST /v1/store; MISS passthrough stub.
  8. semcache — CLI/driver: load config, run a lookup/store over a fixture corpus, print HIT/MISS + decision trace.

What later phases unlock: real embedding providers + key namespace/versioning (Phase 1); HNSW insert/search + tombstones (Phase 2); value store + persistence/WAL + crash recovery (Phase 3); similarity gating + threshold calibration (Phase 4); hit verification + re-rank (Phase 5); eviction + TTL + invalidation (Phase 6); admission control + backpressure (Phase 7); the semcache server + streaming passthrough on MISS (Phase 8); compaction / rebuild / index GC (Phase 9); observability + false-hit probing + threshold-drift detection (Phase 10); deterministic replay + conformance + differential (Phase 11); soak + chaos + recall/false-hit drift gate (Phase 12).

Timeline: Phase 0 = 6–14 weeks. Full plan = 6–9 months.

Recommended language: Rust (edition 2021, ≥1.78). Rationale: (a) the hot path is latency-critical (embed→ANN→gate must add ≪ the cost of a model call) and Rust has no GC tail latency to poison p99; (b) explicit ownership makes the index's node arena, the value store's buffers, and WAL segment lifetimes leak-free and tear-free without a tracing GC; (c) Send/Sync make concurrent insert/search/evict data-race-freedom a compile-time property — critical because the index mutates while queries read; (d) zero-cost slices + SIMD give the distance kernels (cosine/dot over f32) the autovectorization an ANN engine needs; (e) cargo fuzz, Miri, and loom cover the fuzz / UB / concurrency-permutation testing a concurrent index + WAL demand. Locked in ADR-001.

Prerequisites: vector embeddings + cosine/dot/L2 distance; ANN algorithms (HNSW graph structure, IVF-PQ quantization, recall/latency tradeoff); cache theory (LRU/LFU, TTL, admission, Belady); WAL + crash recovery + checkpointing; concurrency (lock-free reads, copy-on-write, epoch reclamation); probabilistic sketches (HLL for cardinality, reservoir sampling for probes); Rust borrow checker + Send/Sync + unsafe for arena layout; HTTP/gRPC + streaming; basic statistics (calibration, ROC/precision-recall, drift detection).

2. Why Build This

  • Unique systems knowledge: a cache where the match itself is approximate and can be wrong. Classic caches answer "is this key present?" (boolean, exact). A semantic cache answers "is there a stored answer close enough to be correct?" — a statistical decision under uncertainty on the hot path. Building it teaches calibration, false-positive cost modelling, and how to make a probabilistic gate observable and tunable in production.
  • Historical / architectural significance: the industry's response to LLM inference being slow + expensive + repetitive. GPTCache (2023) popularized embedding-keyed caching; production inference gateways (vLLM front-ends, model routers, RAG stacks) all bolt on semantic caches. This project rebuilds that core with real correctness gates instead of a naive "nearest neighbor wins."
  • Engineering muscles: ANN index internals (HNSW graph construction, neighbor selection, tombstones, compaction); concurrent reads over a mutating structure (epoch/COW); WAL + crash recovery for a value store decoupled from a rebuildable index; admission control + backpressure; deterministic replay of a system whose decisions are similarity comparisons; sampling-based ground-truth measurement of an error rate you cannot measure exactly online.
  • Production concepts exercised: SLO design for a correctness metric (false-hit rate), not just latency; cost accounting (tokens/$ saved); cache invalidation across a version namespace; graceful degradation (cache down ⇒ pass through, never fail the request); threshold drift detection; canarying a behavioral change (a threshold) safely.
  • Cross-links:
    • #255 ANN / #45 Vector DB / #46 Embedding + Similarity Search — the index + distance machinery sc-index rebuilds; shared HNSW/IVF vocabulary.
    • #57 LRU/LFU + #60 Key Expiration & Eviction — the eviction/TTL policies extended with semantic-aware (cluster-pruning) eviction in §6.
    • #59 Distributed Cache — the sharding seam (Namespace + shard-key) and backpressure model in §7; multi-node deferred.
    • #251 RAG / #327 AI Agent Memory Architecture / #253 Online Inference Serving — semcache sits in front of an inference server (#253) and beside a RAG/memory layer (#251/#327); shared ModelVersion + Namespace concepts.
  • Calibration value: after this you can reason about any approximate-match cache, debug a false-hit incident from telemetry, design a similarity threshold with a defensible error budget, and build feedback control over a probabilistic gate that stays stable and observable.

What Mastery Looks Like

  • Probabilistic gate engineering (Phase 4): calibrate a cosine threshold from labeled data, derive a false-hit SLO, set up an error budget, and defend the calibrated τ statistically — skills applicable to any approximate-match decision system.
  • ANN index internals (Phase 2): implement HNSW from the Malkov & Yashunin graph construction, tune ef/M for the recall/latency Pareto frontier, and diagnose recall regressions from tombstone bloat or centroid drift.
  • Concurrent index design (Phase 2, 9): apply epoch-based reclamation to give lock-free reads over a mutating HNSW graph; understand when COW is preferable to fine-grained locking.
  • WAL + crash-only design (Phase 3): implement write-ahead ordering (I9), group-commit fsync, checkpoint truncation, and idempotent replay (I5) — directly applicable to any durable KV or log-structured system.
  • Observability of invisible errors (Phase 10): design seeded reservoir-sampling probes to measure a false-hit rate that cannot be observed online; build drift detection that alerts before an SLO is breached.
  • Deterministic replay (Phase 11): architect a system so that every decision is a pure function of sealed config + captured inputs; use this to turn production incidents into permanent regression fixtures (I2).
  • Cost-benefit admission (Phase 7): model the expected value of caching a response (P(reuse) × cost_saved − storage_cost − false_hit_penalty) and use it to prevent index bloat from unique prompts (I15).

Per-box dense notes:

  • Caller / Client — supplies prompt + Namespace + ModelVersion (+ generation params hashed into the key). Trust boundary: malformed/oversized requests rejected by the server validator (§8) before any embed/index work.
  • Server / Proxy — terminates HTTP/gRPC; routes by (Namespace, ModelVersion) to the correct index shard; on MISS forwards to upstream and streams the response back while admission decides whether to store. Concurrency boundary: many in-flight requests; per-namespace index accessed concurrently (reads lock-free).
  • Embedding provider — turns prompt → Embedding{vec, model_id, embed_ver}. Determinism: same prompt + same embed_ver ⇒ identical vector (within provider's numeric determinism). embed_ver is part of the key namespace — an entry embedded with v1 is never comparable to a v2 query (I1). Cross-link #46.
  • Policy / Gate — the correctness decision. Runs ANN search, compares top-candidate cosine to a per-namespace calibrated threshold, optionally re-scores exactly / re-ranks with a cross-encoder / checks staleness, then emits Decision. Samples a fraction of HITs as false-hit probes (force a real upstream call, compare) to estimate false-hit rate offline. Determinism: decision is a pure function of (query embedding, retrieved candidates, thresholds, sealed config) — no wall-clock/RNG except seeded probe sampling (I2).
  • Vector index — HNSW (primary) over cached key embeddings; supports incremental insert, soft-delete (tombstone), search; periodic compaction reclaims tombstones (§9). Concurrency boundary: single-writer / many-reader via epoch reclamation or COW snapshot (I8). The index is rebuildable from the store — it is not the source of truth (the value store + WAL are).
  • Admission control — decides whether a MISS's response is worth caching: cost-benefit (token cost saved × expected reuse vs storage + false-hit risk), cacheability (deterministic, not a streaming tool-call side-effect), and backpressure (under memory/QPS pressure, shed admissions and even bypass the cache entirely). Cross-link #59.
  • Cache store — EntryId → CacheEntry. The source of truth for responses + metadata; the vector index merely maps embeddings → EntryId. Holds eviction state (LRU/LFU recency/frequency + semantic cluster membership), TTL, hit counters, cost saved. Value store is decoupled from the index so the index can be rebuilt without losing responses.
  • Durability / WAL — append-only log of store mutations (Put, Invalidate, Evict) + periodic checkpoint of the value store + index manifest; on restart, replay WAL → reconstruct value store, then rebuild the index from stored embeddings (index need not be persisted). Exactly-once store (I5): a Put is idempotent on EntryId.
  • Observability — emits hit/miss/false-hit (sampled), latency saved (model-call latency avoided), cost saved (tokens/$), threshold drift, index recall (vs offline exact-kNN), per-namespace breakdowns; the REPLAY harness re-feeds a captured request + stats trace and asserts identical decisions (determinism gate, §11).

4. System Constraints

Cache-lookup added latency (HIT path, excl. embed) p50 ≤ 0.5 ms, p95 ≤ 2 ms, p99 ≤ 5 ms (ANN search + gate, d=768, N=1M)

Startup (cold, with WAL replay + index rebuild) ≤ 30 s for N=1M (rebuild dominates); ≤ 1 s if index snapshot present
Shutdown drain in ≤ 2 s; WAL fsync'd; checkpoint optional; no orphan FDs
Concurrency scales to physical cores; reads lock-free; single writer per namespace index

Recovery time objective (crash) replay WAL + rebuild index ≤ 30 s (N=1M); zero acknowledged-Put loss
Availability single process; cache down ⇒ proxy passes through to upstream (degrade, never fail the request)
Determinism identical (request trace, sealed config, seeded probes) ⇒ identical Decision sequence
Cost-saved accounting accuracy ±5% of true tokens-saved (tokenizer-estimated)

Scaling assumptions: single node, 8–64 cores, 32 GiB–512 GiB RAM, NVMe for WAL/spill. Horizontal scaling deferred (the Namespace/shard-key is the seam, cross-link #59). Vertical scaling: HNSW ef/parallel search; value-store sharding by EntryId hash; admission-driven backpressure keeps memory bounded.

6. Design Principles

  1. A false hit is worse than a miss. A MISS costs money + latency (recoverable). A false HIT returns a wrong answer the caller trusts (silent, possibly unbounded harm). Every gate decision is biased toward MISS near the threshold. Tradeoff: lower hit rate. Violation: one over-eager threshold serves wrong answers at scale and you learn from a customer, not a dashboard.
  2. The store is truth; the index is derived. Responses + metadata live in sc-store (WAL-durable). The vector index maps embeddings → EntryId and is rebuildable from the store. Tradeoff: startup rebuild cost. Violation: persisting the index as truth → a corrupt index loses responses; recovery becomes index-shaped instead of log-shaped.
  3. Embedding version partitions the keyspace. An entry embedded with embed_ver=A is incomparable to a query embedded with embed_ver=B. Versions never share an index. Violation: cross-version cosine is meaningless → silent false hits/misses (I1).
  4. Determinism of the decision plane. A Decision is a pure function of (query embedding, retrieved candidates, sealed thresholds/config). The only randomness is seeded probe sampling. Violation: non-reproducible HIT/MISS → undebuggable incidents; replay harness fails (I2).
  5. Degrade, never fail. If the index, store, or embedding provider is unavailable/slow, the proxy passes the request through to upstream (a guaranteed-correct MISS) rather than erroring. Tradeoff: lost savings during degradation. Violation: a cache outage becomes an application outage.
  6. Bounded resource usage. Index memory, value-store memory, FD budget, WAL size, and admission rate are explicit ceilings; eviction + compaction + load-shedding enforce them. Violation: one hot namespace OOMs the process and takes down all namespaces.
  7. Concurrent reads must never tear. Search reads a consistent snapshot of the index/store while a writer inserts/evicts (epoch reclamation or COW). Violation: a reader follows a half-linked HNSW node → crash or wrong neighbor (I8).
  8. Observability is not optional — measure the error you can't see. False-hit rate is unobservable online (you don't know the right answer). Sampled ground-truth probes estimate it; it is dashboarded + alerted + error-budgeted by default. Violation: you ship a threshold that quietly doubles false hits.
  9. Admission is a cost-benefit decision, not "always cache." Cache only when expected value (cost saved × reuse probability) exceeds expected cost (storage + false-hit risk) and the response is cacheable (deterministic, not a one-shot side-effect). Violation: caching unique/non-deterministic prompts bloats the index + raises false-hit risk for zero benefit.
  10. Invalidation is explicit and versioned. Entries are invalidated by key, namespace, or model-version; a model upgrade bumps ModelVersion and the old generation is invalidated/aged out. Violation: stale answers from a deprecated model served indefinitely.
  11. Crash-only, value-durable. No graceful-shutdown dependency for correctness: a kill -9 loses nothing acknowledged (WAL group-commit); the index is rebuilt. Violation: recovery logic that assumes clean shutdown → data loss on crash.
  12. Backpressure everywhere. Embedding queue, upstream-forward queue, WAL write queue, and admission rate are all bounded; full downstream throttles or sheds. Violation: unbounded queues → OOM no eviction can save.
  13. Thresholds are calibrated, not guessed; changes are canaried. A per-namespace threshold is set from a labeled calibration set (target false-hit ≤ SLO) and changed only behind a flag with shadow evaluation. Violation: a hand-tuned threshold drifts the false-hit rate silently.
  14. Conservative under embedding/index uncertainty. ANN is approximate (recall < 1) and embeddings are noisy; near the threshold or when recall is low, prefer MISS and widen search (raise ef) rather than risk a wrong HIT. Violation: trusting a single low-recall ANN result → false hit.
  15. Exactly-once store, idempotent on EntryId. A Put(EntryId, …) replayed (WAL recovery, retry) is idempotent; no torn or duplicated entries. Violation: double-insert → duplicate index nodes → inconsistent eviction accounting (I5).

8. Domain Model

8.1 Wire / request protocol (input)

EBNF (lookup/store request, pre-validated):

LookupRequest := "lookup" Namespace ModelVersion Prompt [Params] [Options]
StoreRequest  := "store" Namespace ModelVersion Prompt Response Metadata
Namespace     := Ident                  ; logical partition (tenant / use-case)
ModelVersion  := Ident "@" SemVer        ; e.g. "gpt-4o@2024-08"  (generation model)
Prompt        := Utf8String              ; the text being embedded
Params        := KV+                     ; temperature, max_tokens, system_prompt, ... (hashed into key)
Options       := "threshold=" Float | "verify=" Bool | "max_candidates=" Int | "ttl=" Duration
Response      := Bytes                   ; the model output to cache (text/tokens/JSON)
Metadata      := "tokens_in=" Int "tokens_out=" Int "cost=" Float "latency_ms=" Int

Every request carries (Namespace, ModelVersion); the embedding model version (embed_ver) is determined by the configured EmbeddingProvider, not the request — both partition the keyspace (I1, principle 3).

8.2 Cache key + entry model (what the engine stores)

CacheKey   := hash( Namespace ‖ ModelVersion ‖ canonical(Params) )   ; the *exact-match* sub-key
                                                                     ; semantic match is over Embedding, not CacheKey
Embedding  := { vec: f32[d], norm≈1 (I3), model_id, embed_ver }      ; the *fuzzy* key
CacheEntry := { id: EntryId, key: CacheKey, prompt_hash: u64,
                embed_ref: EmbeddingId, model_ver: ModelVersion,
                response: Bytes, created_ts, last_access_ts, hits: u64,
                tokens_saved: u64, cost_saved: f64, ttl: Option<Duration>,
                state: EntryState }
EntryState := Live | Tombstoned | Expired

Two-level keying: CacheKey (exact: namespace+model+params) scopes which index and guards param-sensitive responses; Embedding (fuzzy: prompt semantics) is the ANN key within that scope. A HIT requires (a) same (Namespace, ModelVersion, embed_ver) scope and (b) cosine(query_emb, entry_emb) ≥ threshold and (c) entry Live + not TTL-expired (I10).

8.3 Index + search model

  • HNSW (sc-index): multi-layer graph; node = (EntryId, Embedding); layer-0 holds all nodes, upper layers are sparse navigation. Search: greedy descent from entry point, beam width ef. Insert: find M neighbors per layer via search, bidirectional link, heuristic neighbor selection. Delete: tombstone (mark node dead, skip in results); compaction (§9) physically removes + relinks.
  • IVF-PQ (alternative): coarse quantizer (k-means centroids) → inverted lists; residuals product-quantized. Lower memory, lower recall; chosen per-namespace for large/cold sets.
  • Search returns Vec<(EntryId, similarity)> top-k, descending. Gate consumes top-1 (or top-k for re-rank).

8.4 Decision state machine (per lookup)

                 embed(prompt) → query Embedding (normalized, I3)
   Received ───────────────────────────────────────────────► Embedded
                                                                │ ANN search (ef, top-k) in (ns,embed_ver) index
                 search empty / no candidate ≥ floor             ▼
   Embedded ─────────────────────────────────► Miss            Searched
        │ top candidate sim ≥ threshold (I4)                     │
        └──► Gated ──► validity(entry Live, not expired, I10) ──►│

                          └──► RejectedHit(stale|tombstoned) ──► Miss(reason)
   Gated, valid ──► [verify? §5: re-score / cross-encoder / faithfulness]
                          │ verify fails                         │
                          └──► RejectedHit(verify) ──────────────► Miss(reason)
   verify passes / disabled ──► Hit(entry)  [+ seeded probe? force upstream, compare (I14)]
   Miss ──► forward upstream ──► admission(§7) ──► [store? Put(EntryId) (I5)] ──► respond

Decision order (deterministic, single pass): scope-check(I1) → ANN-search → threshold-gate(I4) → validity(I10) → verify(§5) → probe-sample(I14). No fixpoint, no re-search loop except an explicit "widen ef on low confidence" (principle 14) bounded to ≤1 retry.

8.5 Similarity / threshold semantics

  • Cosine on L2-normalized vectors ∈ [-1, 1]; for text embeddings effectively [0, 1]. Threshold τ ∈ [0,1] (I4), per (Namespace, embed_ver).
  • sim ≥ τ → candidate HIT; sim ∈ [τ−margin, τ) → "marginal" → MISS (conservative, principle 14) unless verify enabled.
  • Calibration (§4/§10): from a labeled set of (prompt_a, prompt_b, same_answer?) pairs, pick τ minimizing false-hit rate subject to a hit-rate floor; store τ + the calibration metadata hash (sealed, I4).

8.6 State-transition table (lookup outcome under conditions)

Top-candidate sim vs τ Entry state verify probe drawn? Outcome Stored?
sim ≥ τ Live, fresh off no Hit no (already cached)
sim ≥ τ Live, fresh on, passes no Hit no
sim ≥ τ Live, fresh on, fails — RejectedHit(verify) → Miss yes (admit)
sim ≥ τ Tombstoned/Expired — — RejectedHit(stale) → Miss (I10) yes (admit)
sim ∈ [τ−margin, τ) Live off — Miss (conservative) yes (admit)
sim < τ−margin — — — Miss yes (admit)

8.7 Malformed / failure-path examples

  • Request with embed_ver not matching the index's version → PolicyError::VersionMismatch (I1); routed/rejected pre-search.
  • Unnormalized query vector (provider bug) → IndexError::Unnormalized (I3); normalize or reject.
  • Threshold τ = 1.5 in config → ConfigError::ThresholdRange (I4); reject at load.
  • ANN returns an EntryId absent from store (dangling) → drop candidate, treat as MISS (I7); emit dangling_entryid.
  • WAL replay encounters a duplicate Put(EntryId) → idempotent no-op (I5); dup_put incremented.
  • Cosine compared across different d (dimension) → IndexError::DimMismatch; reject (guards a misconfigured provider).
  • Embedding provider times out → cache bypass, forward to upstream (I12); cache_bypass{embed_timeout}.

12. Phase 0 — Repo Skeleton, Core Types, Mock Embedding Provider, Brute-Force Index, In-Memory Store, Gate Skeleton, CLI

12.1 Objectives

Stand up the workspace; define sc-types (embeddings, keys, entries, wire); a deterministic mock EmbeddingProvider; a brute-force exact-cosine VectorIndex baseline (oracle for later ANN recall); an in-memory ValueStore; a threshold-gate skeleton producing Decision::{Hit, Miss}; a semcache CLI that runs lookup/store over a fixture corpus and prints a decision trace. No persistence, no HNSW, no server.

12.2 Detailed Implementation Steps

  • sc-types: Embedding (normalized, I3; ADR-004), CacheKey, Namespace, ModelVersion, EmbedVer, EntryId, CacheEntry, EntryState, Decision, ScError hierarchy; serde JSON wire (LookupRequest/StoreRequest; ADR-013).
  • sc-embed: EmbeddingProvider trait (ADR-005); mock.rs = deterministic hash-to-vector (hash prompt → seed → fill f32[d] → L2-normalize, I3). Same prompt + embed_ver ⇒ identical vector (I2/I3 basis; Principle 4).
  • sc-index: VectorIndex trait; brute.rs = store all (EntryId, Embedding), search = linear cosine scan → top-k (exact; the recall oracle; CLRS Ch. 6 priority queue). This is the differential oracle baseline (ADR-022).
  • sc-store: in-memory HashMap<EntryId, CacheEntry>; put/get/touch; EntryId allocation (dense counter, monotonic — never reuse); idempotent put (I5 basis; ARIES idempotency principle).
  • sc-policy: gate.rs — compare top-1 cosine to a fixed τ → Hit/Miss; emit Decision (I2, Principle 4). No verify/calibration yet.
  • sc-observe: hit/miss counters; tracing span per lookup (ADR-018).
  • semcache: CLI — load config + corpus JSON, run lookups, print per-request Decision + similarity + HIT/MISS (ADR-028).
  • tools/config-validator: range-check τ ∈ [0,1] (I4), dim > 0, namespace presence.

12.3 Deliverable

semcache run --config c.json --corpus pairs.json embeds each prompt (mock), searches brute-force, gates at a fixed τ, prints HIT/MISS + similarity; cargo test green; Miri clean on safe paths.

12.4 Acceptance Criteria

  • Mock embeddings deterministic: identical vector across 100 runs for same prompt (I2/I3).
  • Brute-force search returns exact top-k cosine (verified vs hand-computed on small set).
  • Gate: sim ≥ τ → Hit, else Miss; matches a golden decision snapshot (insta).
  • Config validator rejects 4 malformed configs with correct ConfigError.

12.5 Conformance Fixtures

  • corpora/tiny_pairs.json (10 prompt pairs, labeled same/different). golden_decisions/p0_gate.json. calibration/ empty. Malformed: configs/tau_out_of_range.json, configs/dim_zero.json.

12.6 Pitfalls

  • Unnormalized vectors → cosine threshold meaningless. Root: forgetting L2-normalize in provider. Debug: assert norm≈1 (I3); brute-force sims out of [−1,1]. Recover: normalize in sc-embed::normalize.
  • Non-deterministic mock (per-run RNG seed) → replay impossible later. Root: unseeded RNG. Debug: vector diff across runs. Recover: derive seed from prompt hash (I2).
  • EntryId reuse after delete → dangling/aliased entries later. Root: id recycling. Debug: id collision. Recover: monotonic id allocation (never reuse).
  • Float comparison exactness in tests → flaky. Root: == on f32. Debug: epsilon mismatch. Recover: compare with tolerance.

12.7 Performance Concerns

Brute-force search is O(N·d) — fine for fixtures/oracle, never the hot path (HNSW lands §2). Keep Embedding.vec contiguous (Box<[f32]>) for autovectorized dot. Batch-embed the corpus once. Avoid per-lookup allocation of the query vector.

12.8 Edge Cases

Empty corpus (every lookup MISS); single entry; identical prompts (sim=1.0); τ=1.0 (only exact-embedding HITs); zero-dim config (validator rejects); all prompts distinct.

12.9 Failure Analysis

Malformed config → validator error pre-run (blast radius: that invocation). Missing corpus file → WireError::Source. No persistence yet → process exit loses all entries (documented limit; durability §3).

12.10 Operational Notes

tracing span per lookup; counters lookup_total, hit_total, miss_total. Decision trace printed to stdout/JSON — the first observability window. No metrics endpoint yet (§10).

13. Phase 1 — Embedding Provider Abstraction: Local + Remote, Batching, Key Namespace + Version Partitioning

13.1 Objectives

Make sc-embed real: a local embedding model provider and a remote-API provider behind the same trait; batching for throughput; and the keyspace partitioning that makes (Namespace, embed_ver) the unit of index isolation (I1, principle 3). Wire embed_ver + ModelVersion into the CacheKey and into index routing.

13.2 Detailed Implementation Steps

  • sc-embed/local.rs: load a small embedding model (e.g. a sentence-transformer via an inference crate or ONNX runtime, per Reimers & Gurevych SBERT Paper 14) behind the trait; embed_ver derived from model artifact hash; L2-normalize (I3; ADR-004). Principle 3 (embedding version partitions keyspace).
  • sc-embed/remote.rs: HTTP client to an embedding API; embed_ver from the API's reported model id/version; retry + timeout → on failure, surface error so sc-server can bypass (I12; Principle 5; ADR-001 async Tokio runtime).
  • sc-embed/batch.rs: coalesce concurrent embed requests into batches (latency/size window, ADR-010); preserves per-request order. Validates dimension == index config at flush (I3 enforcement).
  • sc-types/key.rs: CacheKey = hash(Namespace ‖ ModelVersion ‖ canonical(Params)); canonicalization of params (sorted keys, normalized values) for stable hashing (ADR-014; CLRS Ch. 11 hashing).
  • Index routing: sc-core keys index instances by (Namespace, embed_ver) (I1, Principle 3); inserting/searching with a mismatched embed_ver → IndexError::VersionMismatch. Invariant I1 is the primary correctness guard here.
  • sc-types/version.rs: EmbedVer, ModelVersion (SemVer per ADR-033); invalidation-by-version hook stub (full in Phase 6).

13.3 Deliverable

semcache can embed via a local OR remote provider (config-selected); batching reduces embed latency under concurrent load; entries/queries are isolated per (Namespace, embed_ver); cross-version lookups are rejected.

13.4 Acceptance Criteria

  • Local + remote providers produce normalized vectors (I3) of the configured d.
  • Same prompt + same embed_ver ⇒ identical vector (local) / stable vector (remote, modulo provider determinism); documented tolerance for remote.
  • Batching: ≥ 3× embed throughput vs one-at-a-time at concurrency 16 (local).
  • Cross-embed_ver lookup rejected with VersionMismatch (I1) — fixture verified.

13.5 Conformance Fixtures

  • corpora/two_versions.json (same prompts, embed_ver v1 vs v2). golden_decisions/p1_version_isolation.json. Malformed: requests/cross_version_lookup.json (→ VersionMismatch). configs/local_provider.json, configs/remote_provider.json.

13.6 Pitfalls

  • Mixing embed versions in one index → meaningless cosine, silent false hits/misses. Root: routing by namespace only, not embed_ver. Debug: version_mismatch should fire; if not, false-hit probes spike. Recover: key index by (ns, embed_ver) (I1).
  • Remote provider non-determinism breaks replay. Root: provider changes vectors silently. Debug: replay diff. Recover: pin embed_ver; document remote as best-effort-deterministic; prefer local for replay-critical paths.
  • Param canonicalization drift → same logical request, different CacheKey. Root: unsorted/format-variant params. Debug: cache-key mismatch for identical requests. Recover: strict canonical form (sort keys, normalize numbers/whitespace).
  • Batch window too large → tail latency on light load. Root: fixed timeout. Debug: p99 embed latency at low QPS. Recover: adaptive window (flush on size OR small timeout).
  • Dimension mismatch between provider and index config. Root: config drift. Debug: DimMismatch at insert. Recover: validate provider dim() == index d at startup.

13.7 Performance Concerns

Local embedding dominates HIT-path latency at low N (before model call savings) — batch + reuse the model session; pin to a CPU set or GPU (deferred). Remote embedding adds an RTT — only worth it when the model call it saves is far more expensive. Canonical-key hashing is O(params) — cheap. Keep one provider instance (model loaded once).

13.8 Edge Cases

Empty prompt (embed of "" — define behavior: MISS or error); very long prompt (truncate/chunk per provider max tokens; document); identical prompts across namespaces (different CacheKey, different index); remote provider returns wrong dim (reject); concurrent first-request (batch of 1).

13.9 Failure Analysis

Remote provider down/slow → embed error → sc-server bypasses to upstream (I12), cache_bypass{embed_unavailable}. Local model load failure at startup → fatal (config error; can't serve cache, but proxy can still pass through if configured). Blast radius: degraded savings, not correctness.

13.10 Operational Notes

Metrics: embed_latency{provider}, embed_batch_size, embed_errors, version_mismatch{ns}. ModelVersion/embed_ver surfaced in every decision log + EXPLAIN. Runbook cache-bypass.md covers embed-provider degradation. Provider switch is a config + embed_ver change → triggers index isolation (old version aged out, §6).

14. Phase 2 — Vector Index: HNSW Insert/Search/Delete, IVF-PQ Alternative, Distance Kernels, Concurrent Reads

14.1 Objectives

Replace the brute-force baseline with a real ANN index: HNSW (primary) with incremental insert, beam search, and tombstone delete; IVF-PQ (alternative) for memory-efficient large/cold namespaces; SIMD distance kernels; concurrent reads over a mutating graph via epoch reclamation / COW (I8). The brute-force index remains as the recall oracle.

14.2 Detailed Implementation Steps

  • sc-index/hnsw/graph.rs: node arena (EntryId → node), per-layer adjacency lists; entry point; HnswParams{m, ef_construction, ef_search, max_layer} (ADR-002; Paper 1 — Malkov & Yashunin TPAMI 2018).
  • sc-index/hnsw/search.rs: greedy descent through upper layers; layer-0 beam search with candidate heap + visited set (CLRS Ch. 6 priority queue); return top-k (EntryId, sim) (Paper 1). Beam width ef is the recall/latency knob (Book 2 — ann-benchmarks methodology).
  • sc-index/hnsw/insert.rs: assign random layer (geometric distribution, Paper 1 §4), search for neighbors per layer, bidirectional link. Each insert is O(M · ef_construction · d).
  • sc-index/hnsw/select.rs: heuristic neighbor selection (Paper 1 Algorithm 4 — keep diverse neighbors, prune by distance); recall is critically sensitive to this; naive nearest-only produces clustered graphs with recall cliff (2.6 Pitfall).
  • sc-index/distance.rs: cosine/dot over normalized f32 slices; SIMD-autovectorized (Drepper Book 7, cache-line-aligned layout); d-specialized fast paths (ADR-004).
  • sc-index/tombstone.rs: soft-delete bitset; search skips tombstoned nodes (I7); ratio tracked for compaction trigger at 20% (Phase 9).
  • sc-index/ivfpq/*: coarse k-means quantizer → inverted lists; residual product quantization (Paper 2 — Jégou PQ TPAMI 2011); nprobe lists scanned at search (ADR-003); asymmetric distance computation (ADC) over PQ codes.
  • sc-index/epoch.rs + snapshot.rs: crossbeam-epoch for lock-free reads (ADR-009; I8); writer links nodes via release-store, readers traverse a committed graph; reclamation deferred until readers drain. loom model of insert vs search (ADR-024).

14.3 Deliverable

HNSW index supports insert/search/tombstone with recall ≥ 0.95 vs brute-force oracle at tuned ef; IVF-PQ usable per-namespace; concurrent search during insert is race-free (loom + Miri); search latency p99 ≤ 5 ms at N=1M, d=768.

14.4 Acceptance Criteria

  • HNSW recall@10 ≥ 0.95 vs exact-kNN oracle (tuned ef_search) on a 1M-vector fixture.
  • Search p50 ≤ 0.5 ms, p99 ≤ 5 ms (N=1M, d=768, 8 cores) — §4 target.
  • Concurrent insert+search: 0 data races (loom on small model; Miri on safe paths); no torn-node crash (I8).
  • IVF-PQ recall ≥ 0.90 at configured nprobe; memory ≤ 40% of HNSW for same N.

14.5 Conformance Fixtures

  • benchmarks/recall/sift1m_subset.fvecs (or synthetic 1M×768). corpora/ann_recall_set.json (queries + exact-kNN ground truth). golden_decisions/p2_recall.json (recall report). configs/hnsw_default.json, configs/ivfpq_large.json.

14.6 Pitfalls

  • Bad neighbor-selection heuristic → recall cliff. Root: keeping nearest-only (clustered) neighbors. Debug: recall@k far below 0.95. Recover: diversity heuristic (Malkov select-neighbors-heuristic).
  • Torn HNSW node under concurrent insert → reader follows half-linked node → crash/wrong result. Root: non-atomic link update visible to readers. Debug: loom; sporadic crash under churn. Recover: publish nodes via release-store; reclaim under epoch (I8).
  • ef_search too low → fast but low recall (false misses) → false-hit's opposite, lost savings. Root: under-tuned. Debug: recall vs ef sweep. Recover: per-namespace ef; raise on marginal (principle 14).
  • Unnormalized vector slips into index → wrong distance. Root: provider/caller bug. Debug: norm assert (I3). Recover: assert/normalize at insert.
  • IVF centroid drift as data grows → unbalanced lists, recall drop. Root: static centroids. Debug: list-size skew. Recover: periodic re-train / re-cluster on compaction (§9).
  • Visited-set allocation per search → GC-like churn. Root: fresh HashSet each query. Debug: alloc/query in flamegraph. Recover: reusable visited bitset (epoch-tagged).

14.7 Performance Concerns

Distance kernel is the hot loop — contiguous f32, SIMD, d-specialized; cosine = dot on normalized. HNSW node link-lists cache-locality (pack neighbor ids); prefetch next candidate. Beam search heap small + cache-resident. IVF-PQ: PQ code table fits L2; ADC (asymmetric distance) lookup tables precomputed per query. Reusable visited bitset avoids per-query allocation. Search parallelism: independent queries across cores (reads lock-free).

14.8 Edge Cases

Empty index (search → no candidate → MISS); single node; all vectors identical (degenerate graph; sim=1 cluster); query == an indexed vector (sim≈1.0); tombstone fraction high (search skips many — motivates compaction §9); k > live nodes; IVF list empty for a query's centroid.

14.9 Failure Analysis

Index node corruption (bug/unsafe error) → IndexError::NodeCorrupt → drop result → MISS (degrade); detect via Miri/assertions. Recall regression → false-miss spike (lost savings, not wrong answers) → caught by recall gate (Phase 12). Blast radius: one namespace's index (rebuildable from store, I6). Recovery: rebuild index from store.

14.10 Operational Notes

Metrics: index_search_latency{ns}, index_recall_estimate{ns}, index_nodes{ns}, tombstone_ratio{ns}, ef_search{ns}, epoch_lag, reader_count. EXPLAIN/decision log annotates each lookup with candidate sim + ef used. Runbook recall-drop.md. Index params (m, ef) are tunable config; changing them = rebuild.

15. Phase 3 — Cache Store: Persistence, WAL, Checkpoint, Crash Recovery, Exactly-Once Store, Index Rebuild

15.1 Objectives

Make the value store durable + recoverable (principle 2, 11): WAL-first writes (I9), periodic checkpoint, crash recovery via replay, exactly-once Put (I5), and index rebuild from the store (I6) — the index is derived, not persisted-as-truth.

15.2 Detailed Implementation Steps

  • sc-store/store.rs: log-structured value store (Petrov Database Internals Book 4, Part I); EntryId → CacheEntry; in-memory map + on-disk segments; eviction state hooks (Phase 6).
  • sc-store/wal/log.rs + segment.rs: append-only WAL (ARIES Paper 9 — Mohan et al. TODS 1992; ADR-007); records Put/Invalidate/Evict/Checkpoint with crc32c (I11); segment rotation under FD budget (§4 ≤ 256 FDs).
  • Write path (I9): append WAL record → fsync (group-commit) → make mutation visible. Put(EntryId) idempotent — replay/duplicate is a no-op (I5; ARIES idempotency). Write-ahead ordering (I9) is enforced by a single sequential WAL writer.
  • sc-store/wal/checkpoint.rs: periodically snapshot the value store + emit an index manifest (list of (EntryId, EmbeddingId) so the index can be rebuilt); truncate WAL prefix older than checkpoint (Helland "Immutability" Book 3 — append-only + derived index).
  • sc-store/wal/replay.rs: on restart, load latest checkpoint → replay WAL tail → reconstruct value store → call VectorIndex::rebuild from stored embeddings (I6; Principle 2; ADR-008).
  • sc-store/segment.rs + reader/writer.rs: value-byte segments with crc32c per record (I11; round-trip exact); spill cold entries to NVMe.
  • Group-commit: batch fsync across concurrent Puts (ADR-007); durability lag ≤ 50 ms or N writes (§4 System Constraints). WAL writer is a single Tokio task; all stores enqueue a (entry, oneshot_ack) — writer batches until timeout or size, then fsyncs and acks all (ADR-010).

15.3 Deliverable

Entries survive kill -9: on restart, the store replays WAL, rebuilds the index, and serves the same HITs; no acknowledged Put is lost; duplicate Put (replay) is idempotent.

15.4 Acceptance Criteria

  • Crash (SIGKILL) after N Puts → restart recovers all N (zero loss of acknowledged writes); verified by fault-injection harness.
  • Duplicate Put(EntryId) during replay → single entry (I5); dup_put counted.
  • Index rebuilt from store equals a freshly-inserted index (same recall) (I6) — differential.
  • WAL/segment crc detects a flipped byte (I11) → record rejected/recovered.
  • Recovery time ≤ 30 s for N=1M (rebuild dominates) (§4).

15.5 Conformance Fixtures

  • request_traces/crash_after_n_puts.json. conformance/wal/crc_corruption.json (flipped byte → detect). golden_decisions/p3_recovery.json (post-restart HITs match pre-crash). configs/group_commit.json.

15.6 Pitfalls

  • Store mutation visible before WAL durable → crash loses acknowledged write. Root: write-behind. Debug: recovery missing entries. Recover: strict write-ahead order (I9); fsync before ack.
  • Non-idempotent Put → duplicate index nodes after replay. Root: insert appends blindly. Debug: dup_put=0 but node count > entry count. Recover: idempotent on EntryId (I5).
  • Checkpoint without index manifest → can't rebuild index → must persist index (violates principle 2). Root: incomplete checkpoint. Debug: rebuild fails post-restart. Recover: manifest = (EntryId, EmbeddingId) list in checkpoint.
  • WAL never truncated → unbounded log → slow recovery + disk fill. Root: no checkpoint truncation. Debug: WAL size grows monotonically. Recover: truncate prefix at checkpoint.
  • Group-commit starves a lone writer → latency. Root: waiting for batch that never fills. Debug: p99 put latency at low QPS. Recover: flush on size OR timeout.
  • Torn segment write (partial) on crash → corrupt value. Root: non-atomic append. Debug: crc fail on recovery. Recover: crc per record (I11); skip torn tail.

15.7 Performance Concerns

WAL append sequential + batched (group-commit) → high write throughput, bounded fsync cost. Checkpoint is a background snapshot (copy-on-write or fork-style) to avoid stalling writes. Value segments sequential I/O; cold spill keeps hot set in memory. Recovery: rebuild is O(N) inserts — parallelizable across cores (index insert is the cost, not WAL replay).

15.8 Edge Cases

Crash mid-checkpoint (use previous checkpoint + WAL); empty store recovery (no-op); WAL with only-tombstones; checkpoint exactly at a Put boundary; disk full during WAL append (backpressure/shed writes); recovery with a corrupt checkpoint (fall back to older + longer WAL replay).

15.9 Failure Analysis

Disk full during WAL → WalError → admission shed (stop caching, still serve cache + passthrough, I12) until space frees. Checkpoint corruption → fall back to prior checkpoint + replay (longer recovery). WAL crc fail mid-log → recover up to last good record (acknowledged writes preserved if fsync ordering held). Blast radius: durability of un-fsynced tail only. Recovery: rebuild index always available (I6).

15.10 Operational Notes

Metrics: wal_append_lag, wal_bytes, wal_replay_ops, dup_put, checkpoint_duration, recovery_duration, index_rebuild_ms, value_crc_fail. Runbook wal-recovery.md. Deployment: WAL + segments + checkpoints on a durable NVMe volume (compose binds it). Backup = copy checkpoint + WAL tail; restore = point binary at the volume → recover.

16. Phase 4 — Similarity Gating + Threshold Calibration (the false-hit / false-miss tradeoff)

16.1 Objectives

Turn the fixed-τ skeleton into a real gate: per-namespace calibrated thresholds (I4), a marginal-band conservative policy (principle 14), and an offline calibration procedure that picks τ from a labeled set to satisfy the false-hit SLO. This is where the false-hit / false-miss tradeoff is made explicit and tunable.

16.2 Detailed Implementation Steps

  • sc-policy/threshold.rs: Threshold{ns, embed_ver, tau, margin, calib_hash} sealed (I4; Principle 13); loaded per (Namespace, embed_ver); range-checked ∈[0,1].
  • sc-policy/gate.rs: ANN top-1 (or top-k) → sim; sim ≥ τ → candidate Hit; sim ∈ [τ−margin, τ) → Marginal → Miss (conservative; Principle 14); sim < τ−margin → Miss. Pure fn of (emb, candidates, sealed threshold) (I2; Principle 4). Manning IIR Book 1 Ch. 6: cosine semantics; ESL Book 10 Ch. 4.4: binary decision boundary calibration.
  • sc-policy/calibrate.rs: input = labeled pairs (prompt_a, prompt_b, same_answer: bool); embed both; compute cosine; sweep τ over a grid; for each, compute false-hit rate (positives where different-answer pairs scored ≥ τ) + hit rate (true-dup pairs ≥ τ) — the ROC-style tradeoff (ESL Book 10); pick smallest τ meeting false-hit ≤ SLO with max hit rate; emit τ + calib_hash (sealed config, I4; ADR-032 reproducibility).
  • Per-namespace override: high-stakes namespace (code-gen) → higher τ (near-zero false hits); tolerant namespace (FAQ) → lower τ. Reflects principle that false hits are domain-cost-weighted (Principle 1).
  • widen_ef_on_marginal: if top-1 is marginal, re-search with higher ef once (bounded retry, Principle 14; ADR-002 ef tuning) before deciding MISS.

16.3 Deliverable

The gate produces calibrated HIT/MISS per namespace; a calibration run on a labeled corpus emits a τ that holds false-hit ≤ SLO on a held-out set; marginal candidates conservatively MISS.

16.4 Acceptance Criteria

  • Calibrated τ holds false-hit rate ≤ 1% (default SLO) on a held-out labeled set (not the calibration set).
  • Hit rate is maximized subject to that constraint (Pareto point reported).
  • Marginal band: candidates in [τ−margin, τ) MISS by default (verified); enabling verify (§5) re-evaluates them.
  • Decision is deterministic (I2): identical (emb, candidates, sealed τ) → identical Decision across 100 runs.

16.5 Conformance Fixtures

  • calibration/faq_pairs.json (labeled dup/non-dup), calibration/codegen_pairs.json (stricter). golden_decisions/p4_gate.json. calibration/expected_tau.json (calibration output). Edge: calibration/all_distinct.json (no dups → τ near 1.0).

16.6 Pitfalls

  • Threshold set globally, not per namespace → one domain's false hits, another's lost savings. Root: single τ. Debug: per-namespace false-hit variance. Recover: per-(ns, embed_ver) τ (I4).
  • Calibrating on the test set → optimistic τ, real false-hit higher. Root: no held-out split. Debug: prod false-hit > calibration. Recover: held-out calibration; periodic recalibration (§10).
  • Margin too small → marginal candidates served → false hits near boundary. Root: margin ignores embedding noise. Debug: false-hits cluster at sim≈τ. Recover: widen margin; verify marginal (§5).
  • Cosine compared on different d / unnormalized → garbage threshold. Root: I3/dim drift. Debug: sims out of range. Recover: assert norm + dim.
  • Threshold drift after embedding-model swap → stale τ. Root: τ tied to old embed_ver. Debug: false-hit jump post-swap. Recover: τ keyed by (ns, embed_ver); recalibrate on swap (I1/principle 13).

16.7 Performance Concerns

The gate is a single comparison (top-1 sim vs τ) — negligible cost. Calibration is offline (not hot path). widen_ef_on_marginal adds a bounded second search only for marginal cases (rare if τ well-calibrated) — cap to ≤1 retry to bound tail latency.

16.8 Edge Cases

All candidates below τ (MISS); top-1 exactly at τ (HIT — inclusive); sim exactly at τ−margin (boundary → MISS); multiple candidates ≥ τ (pick highest; re-rank §5); namespace with no calibrated τ (PolicyError::NoThresholdForNs → conservative default or reject); empty index (MISS).

16.9 Failure Analysis

Mis-calibrated τ (too low) → false-hit SLO breach → caught by probe sampling (§10) → alert + threshold rollback (principle 13). Blast radius: one namespace's correctness. Containment: per-namespace isolation; conservative default; canary new τ behind a flag with shadow eval. Recovery: revert τ to last-good sealed config.

16.10 Operational Notes

Metrics: threshold{ns} gauge, gate_decision{ns,kind}, marginal_rate{ns}, widen_ef_retries. Every decision logs sim + τ + margin + calib_hash (audit). Runbook false-hit-spike.md: symptom (probe false-hit > SLO) → check τ, recent swap, drift → raise τ / recalibrate. Calibration is a versioned artifact (calibration/); changing τ is a CHANGELOG'd behavioral change behind a flag.

17. Phase 5 — Hit Verification + Re-ranking (exact re-score, cross-encoder, staleness/faithfulness)

17.1 Objectives

Add a second, higher-precision gate after ANN+threshold: optional exact re-score (recompute precise similarity on the full text), cross-encoder re-rank (a model that scores query↔candidate jointly, far more accurate than bi-encoder cosine), and staleness / faithfulness checks — to convert marginal/ambiguous candidates into safe HIT/MISS and drive false-hit rate toward zero for high-stakes namespaces.

17.2 Detailed Implementation Steps

  • sc-policy/verify/rescore.rs: recompute exact cosine on top-k candidates' full embeddings (no ANN approximation; ADR-022 exact-kNN oracle technique) → re-order; cheap, removes HNSW-approximation error (especially relevant when IVF-PQ is the index).
  • sc-policy/verify/cross_encoder.rs: feed (query_prompt, candidate_prompt) to a cross-encoder model (Reimers & Gurevych Paper 14; ColBERT-style late-interaction Paper 15) → relevance score; HIT only if score ≥ a (separately calibrated) cross-encoder threshold. Cross-encoders model prompt-pair interaction jointly (vs bi-encoder cosine); far more precise, more expensive → applied to top-1/top-k only, gated by VerifyMode (I2 — verify-model ver in sealed config).
  • sc-policy/verify/faithfulness.rs: optional check that the cached response is still valid for the query (e.g. response not contradicting query constraints, not past a freshness window for time-sensitive content) — domain hook (Principle 10, TTL semantics).
  • sc-policy/gate.rs: pipeline threshold-gate → [verify per VerifyMode] → Hit/RejectedHit (I2; Principle 4). VerifyMode::{Off, ExactRescore, CrossEncoder, Faithfulness} per namespace.
  • Verification only runs on candidates that already passed the cosine gate (or marginal band if configured) — never on the hot path for clear HITs unless VerifyMode demands (Principle 1: bias toward MISS).

17.3 Deliverable

A namespace configured with cross-encoder verify serves HITs only when both cosine ≥ τ AND the cross-encoder agrees; marginal cosine candidates are correctly resolved; false-hit rate on a high-stakes corpus drops materially vs cosine-only.

17.4 Acceptance Criteria

  • On a hard corpus (semantically-near-but-different prompts), cross-encoder verify reduces false-hit rate ≥ 2× vs cosine-only at equal hit rate (or holds false-hit ≤ SLO at higher hit rate).
  • Exact re-score corrects ANN-approximation reorderings (top-1 matches brute-force oracle after re-score).
  • Verify adds bounded latency: VerifyMode::CrossEncoder p99 added latency ≤ a configured budget (still ≪ a model call).
  • RejectedHit(verify) path → MISS → upstream + admit (verified).

17.5 Conformance Fixtures

  • corpora/hard_near_pairs.json (cosine-confusable, different answers). golden_decisions/p5_verify.json. configs/cross_encoder_verify.json, configs/exact_rescore.json. Edge: corpora/easy_dups.json (verify agrees with cosine).

17.6 Pitfalls

  • Cross-encoder on every lookup → latency/cost blows the savings. Root: verify not gated. Debug: verify latency dominates HIT path. Recover: verify only top-1/top-k of cosine-passing candidates; per-namespace VerifyMode.
  • Verify model version unversioned → non-reproducible verify decisions. Root: cross-encoder ver not in sealed config. Debug: replay diff. Recover: include verify-model version in calib_hash/sealed config (I2).
  • Faithfulness check too strict → rejects valid HITs → lost savings. Root: over-tight freshness/contradiction rule. Debug: high RejectedHit(verify) with low true false-hit. Recover: tune per namespace; make faithfulness opt-in.
  • Re-score on approximate embeddings still approximate. Root: re-scoring the stored (possibly quantized IVF-PQ) vector, not full precision. Debug: re-score ≠ oracle. Recover: keep a full-precision embedding for re-score, or re-embed.
  • Verify latency variance → tail spikes. Root: cross-encoder batch stalls. Debug: verify p99. Recover: batch + timeout; fall back to cosine decision on verify timeout (conservative → MISS).

17.7 Performance Concerns

Exact re-score: O(k·d) on full vectors — cheap, big precision win, do always when IVF-PQ is the index. Cross-encoder: a model inference — expensive; restrict to top-1/top-k, batch, and only for namespaces where false-hit cost justifies it. Faithfulness: domain logic, keep O(1). Verify is off the hot path for clear, high-confidence HITs (cosine ≫ τ).

17.8 Edge Cases

Cross-encoder disagrees with high cosine (reject — embedding fooled); both top candidates pass cosine, cross-encoder picks the lower-cosine one (re-rank); verify-model unavailable (fall back to cosine decision OR conservative MISS, configurable); response past freshness window (faithfulness → MISS); empty candidate set (no verify, MISS).

17.9 Failure Analysis

Verify model down → fall back to cosine gate (degrade precision, not availability) OR conservative MISS (config); verify_unavailable counted. Cross-encoder mis-scores (model bug) → false hit/miss → caught by probes (§10). Blast radius: one namespace's precision. Recovery: disable verify (cosine-only) or swap verify model + recalibrate.

17.10 Operational Notes

Metrics: verify_decision{ns,mode,result}, verify_latency{ns,mode}, rejected_hit{reason}, verify_unavailable. Decision log records cosine sim + verify score + mode. Runbook false-hit-spike.md includes "enable/strengthen verify" as a mitigation. Verify model is a versioned dependency (its version partitions decisions like embed_ver).

18. Phase 6 — Eviction, TTL, and Invalidation (LRU/LFU + semantic cluster prune; by key/namespace/model-version)

18.1 Objectives

Bound store + index memory (principle 6) with eviction (LRU/LFU + adaptive ARC + semantic-aware cluster pruning), TTL expiry (I10), and explicit invalidation by key / namespace / model-version (principle 10). Evicting a value must tombstone its index node first (I7); TTL-expired entries are never served (I10).

18.2 Detailed Implementation Steps

  • sc-store/evict/lru.rs + lfu.rs + arc.rs: recency (LRU; O'Neil LRU-K Paper 10), frequency (LFU via Count-Min sketch from sc-observe; Cormode & Muthukrishnan Paper 6), and adaptive (ARC: balance recency/frequency, Megiddo & Modha Paper 11; ADR-016). Per-namespace budget; evict on pressure. Belady's algorithm (Paper 12) defines the offline upper bound for any eviction policy.
  • sc-store/evict/cluster.rs: semantic cluster pruning — when over budget, prefer evicting from dense clusters (many near-duplicate entries; one survivor covers the cluster's queries) over isolated entries (unique coverage). Uses HNSW index neighbor density (ADR-002 graph structure reuse; no extra data structure). This is semantically-aware Belady: evict the entry with highest expected replacement coverage.
  • sc-store/ttl.rs: per-entry ttl; lazy expiry (checked at serve, I10) + a background reaper; expired → EntryState::Expired → tombstone index node (I7 ordering, Principle 10).
  • sc-store/invalidate.rs: InvalSelector::{Id, Namespace, ModelVersion, Expired} (Kleppmann DDIA Book 8, Ch. 5: invalidation strategies); invalidating a ModelVersion ages out a whole model generation (Principle 10); tombstones matching index nodes (I7).
  • Eviction ↔ index ordering: tombstone index node before dropping the value (I7; ensures ANN search never returns a dangling EntryId); value reclaimed after readers drain (epoch, I8; ADR-009).
  • sc-observe/countmin.rs: prompt-frequency sketch feeding LFU (Paper 6 Count-Min); hot-prompt detection; ADR-015 deterministic sketch with fixed seeds (I14).

18.3 Deliverable

Under a fixed memory budget, the cache evicts cold/redundant entries (LRU/LFU/ARC + cluster prune) while keeping hit rate high; TTL-expired entries are reaped and never served; invalidating a namespace or model-version removes the right entries.

18.4 Acceptance Criteria

  • Under budget pressure, hit rate within X% of an unbounded cache on a workload with reuse + churn (eviction policy effective; ARC ≥ LRU on a recency+frequency mix).
  • Semantic cluster prune: at equal budget, ≥ Y% higher hit rate than plain LRU on a near-duplicate-heavy workload (evicting redundant cluster members).
  • TTL-expired entry never served as HIT (I10) — served_expired=0 across fixtures.
  • InvalSelector::ModelVersion removes all entries of that generation (verified); index has no dangling EntryId (I7).

18.5 Conformance Fixtures

  • workload/reuse_churn.json (Zipfian reuse + churn). workload/near_dup_heavy.json (cluster prune win). request_traces/ttl_expiry.json. golden_decisions/p6_invalidation.json (per-namespace/version invalidation). Edge: workload/no_reuse.json (eviction = no-op benefit).

18.6 Pitfalls

  • Value dropped before index tombstoned → search returns dangling EntryId → dangling_entryid, wrong-looking HIT. Root: wrong ordering. Debug: ann result → store miss. Recover: tombstone index first (I7), reclaim value after.
  • TTL checked only by reaper, not at serve → expired entry served between reaper passes. Root: lazy-only-background expiry. Debug: served_expired > 0. Recover: check ttl at serve (I10) AND background reap.
  • LFU never ages → stale "hot" entries pinned forever. Root: unbounded frequency counts. Debug: old entries with high count never evicted. Recover: decay (windowed Count-Min) / ARC.
  • Cluster prune evicts the cluster's only survivor → lose coverage of a query region. Root: prune ignores "last member." Debug: hit-rate drop in a region post-prune. Recover: keep ≥1 representative per cluster.
  • Invalidate-by-namespace racing with insert → new entry of old generation survives. Root: invalidation not atomic vs concurrent insert. Debug: post-invalidation residue. Recover: version-fence (reject inserts of invalidated ModelVersion).

18.7 Performance Concerns

Eviction metadata (LRU list / LFU sketch) updated on every access — keep O(1) (intrusive list / Count-Min), off the search critical path where possible. Cluster-prune density query reuses the index (no extra structure). Background reaper batched + rate-limited (avoid eviction storms). Tombstone-then-reclaim avoids stalling readers (epoch, I8).

18.8 Edge Cases

Evict the entry currently being served (epoch keeps it alive for the reader); TTL=0 (never cache / immediate expiry); invalidate empty namespace (no-op); evict last entry (empty index); all entries in one cluster (prune to representatives); budget smaller than working set (thrash → detect + alert).

18.9 Failure Analysis

Over-eviction (budget too small) → hit-rate collapse → lost savings (not wrong answers) → alert on hit-rate drop. Dangling EntryId (ordering bug) → MISS-degrade (drop result) + bug telemetry. Invalidation miss (residue) → stale answers (correctness) → caught by model-version audit. Blast radius: one namespace. Recovery: re-run invalidation; rebuild index from store (I6).

18.10 Operational Notes

Metrics: evictions{ns,policy}, eviction_reason, ttl_reaped, served_expired (alert if >0, I10), invalidations{selector}, cluster_prune_count, cache_size_bytes{ns}, hit_rate{ns}. Runbook: budget tuning + invalidation procedure. Model upgrade = bump ModelVersion → invalidate old generation (planned, canaried). Eviction policy is per-namespace config.

19. Phase 7 — Admission Control + Backpressure (cost-benefit caching; load shedding)

19.1 Objectives

Decide whether a MISS's response is worth caching (principle 9) — cost-benefit + cacheability (I15) — and enforce backpressure / load shedding (principle 12) so the engine stays within memory + QPS ceilings (principle 6) and never lets unbounded queues OOM it.

19.2 Detailed Implementation Steps

  • sc-admit/cost.rs: CostModel{token_price, reuse_estimate, storage_cost, false_hit_penalty} (Principle 9); expected value = cost_saved × P(reuse); admit iff value ≥ storage_cost + false_hit_risk. P(reuse) estimated from prompt frequency (Count-Min sketch Phase 6, Paper 6; Cormode & Muthukrishnan) + namespace base rate. This is an expected-utility gate, not a heuristic.
  • sc-admit/cacheable.rs: reject non-cacheable responses (I15; Principle 9): non-deterministic (high-temperature/random), one-shot side-effects (tool calls, time-sensitive), explicit no-store hint, or responses flagged by the caller as uncacheable. Cacheability flags are set by the embedding/response metadata (ADR-005 trait surface).
  • sc-admit/backpressure.rs: bounded queues on embed, upstream-forward, and WAL-write paths (Principle 12; ADR-010 Tokio bounded channels); full → throttle. Queue bound derived from §4 memory ceiling / average entry size.
  • sc-admit/shed.rs: under memory/QPS pressure, escalate: (1) stop admitting low-value entries → (2) stop admitting all → (3) bypass the cache entirely (pure passthrough, I12; Principle 5) — degrade savings, never correctness or availability. Hysteresis prevents oscillation around shed thresholds.
  • Admission runs after a MISS resolves upstream, before Put (I5; ARIES idempotency Paper 9). Bypassed responses are still returned to the caller (just not stored).

19.3 Deliverable

Low-value / non-deterministic / one-off prompts are not cached; under load, the engine sheds admissions (and ultimately bypasses) to stay within budget; the cache never OOMs and the proxy never fails a request due to admission.

19.4 Acceptance Criteria

  • Non-cacheable responses (high-temp, tool-call) are never stored (I15) — fixture verified.
  • On a unique-prompt flood (no reuse), admission rejects most → index growth bounded (vs naive always-cache blow-up).
  • Under injected memory pressure, shedding engages before the budget ceiling; 0 process OOM (principle 6); requests still served (bypass, I12).
  • Cost-benefit: on a mixed workload, admitted set yields ≥ baseline cost-saved per stored byte vs always-cache.

19.5 Conformance Fixtures

  • workload/unique_flood.json (no reuse → mostly reject). workload/mixed_value.json (high+low value mix). request_traces/pressure_shed.json (memory pressure → shed/bypass). golden_decisions/p7_admit.json. Edge: requests/no_store_hint.json.

19.6 Pitfalls

  • Always-cache → index bloat, higher false-hit risk, wasted memory on one-offs. Root: no admission. Debug: index grows with no hit-rate gain. Recover: cost-benefit admission (principle 9).
  • Caching non-deterministic responses → false hits (the cached answer was one random sample). Root: ignoring temperature/randomness. Debug: false-hit probes on high-temp namespace. Recover: cacheability flag (I15); don't cache non-deterministic.
  • Unbounded forward queue → OOM under upstream slowdown. Root: no backpressure. Debug: queue depth unbounded, RSS climbs. Recover: bounded queue + shed (principle 12).
  • Shedding too aggressively → near-zero hit rate under mild load. Root: low pressure thresholds / no hysteresis. Debug: shed events at low utilization. Recover: hysteresis; shed low-value first, bypass last.
  • P(reuse) overestimate → admit one-offs. Root: frequency sketch cold-start. Debug: admitted entries never re-hit. Recover: require minimum observed frequency or namespace prior.

19.7 Performance Concerns

Admission decision is cheap (cost arithmetic + a frequency lookup) and off the HIT path (only on MISS, after upstream). Backpressure via bounded channels (no allocation under steady state). Shedding is a fast path (bypass = skip embed+search+store entirely under full pressure → lowers per-request cost when overloaded).

19.8 Edge Cases

Caller no-store hint (never cache, I15); response exactly at the cost-benefit boundary (admit/reject deterministically); pressure oscillating around threshold (hysteresis prevents flapping); first-ever prompt (no frequency history → namespace prior); upstream returns an error (don't cache errors).

19.9 Failure Analysis

Backpressure deadlock (cyclic full queues — shouldn't occur, DAG is acyclic embed→search→forward→store) → blocked-request dump, loom. Shed misconfig → hit-rate collapse (lost savings) → alert. Bypass storm under sustained overload → degraded savings but correct + available (I12). Blast radius: savings, not correctness/availability. Recovery: scale up / raise budget / tune thresholds.

19.10 Operational Notes

Metrics: admit_decision{ns,result}, admit_rejected{reason}, shed_events, cache_bypass{reason} (I12), queue_depth{stage}, backpressure_events. Runbook cache-bypass.md: bypass cause → action. Admission cost params + shed thresholds are per-namespace config. Bypass under pressure is expected + healthy degradation, distinct from an error.

20. Phase 8 — Server / Proxy: HTTP + gRPC, MISS Passthrough, Streaming Relay, Degrade-Never-Fail

20.1 Objectives

Expose sc-core as the semcache server/proxy (sc-server): an HTTP/1.1+2 (and optional gRPC) surface that sits in front of an upstream model API, serves HITs from the cache, forwards MISSes upstream and streams the response back while admission stores it, and degrades to passthrough on any cache fault (I12, principle 5).

20.2 Detailed Implementation Steps

  • sc-server/http.rs + routes.rs: axum routes (ADR-011) — POST /v1/lookup (embed→search→gate→HIT or MISS per §8 state machine), POST /v1/store, plus an OpenAI-compatible-ish POST /v1/chat/completions-style proxy endpoint that does lookup-then-passthrough transparently (RFC 9110/9112 HTTP surface).
  • sc-server/passthrough.rs: on MISS (or bypass), forward the original request to the configured upstream (Principle 5, I12); on success, return response + (if admitted) Put (I5 idempotent; ARIES Paper 9). Connection pooling to upstream (ADR-010 Tokio runtime).
  • sc-server/stream.rs: relay upstream streaming tokens (SSE/chunked per RFC 9112 chunked transfer) to the caller as they arrive; buffer the full response in parallel for storage (store only the complete, admitted response; never a partial; ADR-013 serde bincode).
  • sc-server/middleware.rs: request validation (size/format caps), per-request timeout, tower-based concurrency limit + backpressure (ties to sc-admit backpressure.rs; Principle 12).
  • sc-server/fallback.rs: any cache-path error (embed/index/store) → log + cache_bypass{reason} → passthrough (I12; Principle 5). The request never fails because the cache failed. Helland "Immutability" design: the log + store are truth; a derived-index failure can't corrupt serving.
  • sc-server/grpc.rs (tonic, ADR-012): binary Lookup/Store for embedded low-overhead callers (gRPC over HTTP/2 RFC 9113).
  • sc-server/config.rs: namespaces, thresholds, upstream endpoint, budgets, verify modes — loaded + validated at startup (ADR-030 typed errors; config validator tool).

20.3 Deliverable

semcache serve --config c.json runs a proxy: clients hit it instead of the model API; HITs return cached responses in ≪ a model call; MISSes stream through transparently and are stored; killing the index/store mid-flight degrades to passthrough with no client-visible failure.

20.4 Acceptance Criteria

  • End-to-end: HIT returns in ≤ 2% of the upstream model-call latency (≥ 50× faster) on a HIT-heavy workload.
  • MISS passthrough streams tokens with ≤ a small fixed overhead vs calling upstream directly; stored response equals the streamed response (no partial stored).
  • Injected cache fault (index panic, store error) → request still succeeds via passthrough (I12); cache_bypass emitted.
  • Concurrency: server sustains target QPS with bounded memory (backpressure engaged, no OOM).

20.5 Conformance Fixtures

  • request_traces/proxy_hit_miss_mix.json. request_traces/streaming_passthrough.json (token stream relay). request_traces/cache_fault_bypass.json (fault → passthrough). golden_decisions/p8_proxy.json. configs/proxy_upstream_mock.json (mock upstream).

20.6 Pitfalls

  • Storing a partial/aborted stream → corrupt cached response served later as a confident HIT. Root: storing before stream completes. Debug: cached response truncated. Recover: store only on complete + successful upstream response (atomic Put).
  • Cache fault fails the request → cache outage = app outage. Root: no fallback path. Debug: 5xx correlates with cache errors. Recover: catch-all → passthrough (I12, principle 5).
  • Embedding on the critical path for every request adds latency even on MISS. Root: embed-then-forward serially. Debug: MISS latency = embed + upstream. Recover: for clear non-cacheable/bypass, skip embed; speculative parallel forward (config).
  • Streaming relay buffers entire response in memory under many concurrent streams → OOM. Root: unbounded per-stream buffer. Debug: RSS scales with concurrent streams. Recover: bounded buffers + backpressure; cap concurrent streams.
  • Request canonicalization mismatch (proxy vs lookup) → cache key drift → low hit rate. Root: different param handling on the two endpoints. Debug: hit-rate gap proxy vs direct lookup. Recover: shared canonicalization (§1).

20.7 Performance Concerns

HIT path: avoid copying the response (zero-copy Bytes); serialize once. MISS path: overlap embed + speculative forward where cacheability allows; stream relay with bounded buffers (no full buffering). Tokio reactor handles I/O; ANN/embed run on a CPU pool off the reactor (ADR-010) so search doesn't block the event loop. Connection pooling to upstream.

20.8 Edge Cases

Upstream times out (return error to caller — don't fabricate; don't cache); client disconnects mid-stream (abort upstream, don't store partial); malformed request (validator 4xx, no cache work); HIT during a concurrent invalidation of that entry (epoch keeps it valid for the in-flight read, I8); zero-length response.

20.9 Failure Analysis

Upstream down → proxy returns upstream's error (cache can't fabricate answers) — this is the one case the request "fails," and it fails because upstream failed, not the cache. Cache subsystem fault → passthrough (I12). Server overload → backpressure + shed (§7). Blast radius: bounded to the faulting path; cache faults never propagate to correctness. Recovery: cache self-heals (rebuild/restart) while passthrough keeps serving.

20.10 Operational Notes

Metrics: request_total{endpoint}, result_source{cache,upstream,bypass} (I12), e2e_latency{source}, upstream_latency, stream_relay_bytes, concurrent_streams. Tracing span per request (embed → search → gate → [upstream]); trace IDs propagate to upstream. Runbook cache-bypass.md. Deployment: sidecar or gateway; health endpoint reports cache up/degraded (passthrough) status.

21. Phase 9 — Index Compaction, Rebuild, GC, and IVF Re-training (reclaim tombstones; bound memory drift)

21.1 Objectives

Keep the index healthy over time: compaction to physically remove tombstoned nodes + relink (HNSW), reclaim IVF list space, re-train IVF centroids as the distribution drifts, and validate that a compacted/rebuilt index preserves recall (I6). Bound tombstone ratio + memory drift.

21.2 Detailed Implementation Steps

  • sc-index/compact.rs: triggered when tombstone_ratio > 20% (§4 System Constraints) or scheduled; build a new graph from live nodes (or relink in place under epoch, I8; ADR-009), drop tombstones, swap atomically (COW snapshot; readers finish on old, new readers see compacted; ADR-002).
  • sc-index/rebuild.rs: full rebuild from store (reused from Phase 3 recovery path + as a recall-repair tool; I6 Principle 2; Helland "Immutability" Book 3); parallel insert across cores (rayon thread pool, ADR-010).
  • HNSW compaction: relinking must preserve graph connectivity → re-run neighbor selection (Paper 1 Malkov Algorithm 4) for nodes that lost neighbors to tombstones (avoid orphaning; Phase 9 pitfall 9.6).
  • IVF re-training: periodically re-cluster centroids on a sample of live vectors (distribution drift → unbalanced lists → recall drop; Paper 2 PQ; Paper 3 FAISS IVF); reassign vectors; re-quantize residuals.
  • Compaction is background, rate-limited, and online (search continues on the pre-compaction snapshot via epoch/COW; I8; ADR-009); swap is O(1) atomic pointer (epoch fences).
  • Recall validation post-compaction: sample queries, compare recall@10 vs brute-force oracle (ADR-022); if recall regressed beyond tolerance → keep old index (I6), alert recall_post_compaction (Phase 10 observability).

21.3 Deliverable

A long-running index with heavy churn (inserts + invalidations) maintains bounded tombstone ratio + memory via online compaction; recall holds ≥ 0.95 post-compaction; IVF re-training restores list balance after distribution drift.

21.4 Acceptance Criteria

  • After churn driving tombstone ratio > 20%, compaction reduces it < 5% and reclaims memory; search uninterrupted (I8).
  • Post-compaction recall@10 ≥ 0.95 vs oracle (no connectivity regression).
  • IVF re-train restores list-size balance (max/median ratio) within tolerance after injected drift.
  • Compaction is online: search p99 during compaction within 2× steady-state (rate-limited, no stall).

21.5 Conformance Fixtures

  • workload/heavy_churn.json (insert+invalidate cycles → high tombstone ratio). workload/distribution_drift.json (IVF re-train trigger). golden_decisions/p9_compaction.json (recall preserved). Edge: workload/no_tombstones.json (compaction no-op).

21.6 Pitfalls

  • Compaction orphans nodes (lost all neighbors to tombstones) → unreachable → recall cliff. Root: relink doesn't re-select neighbors. Debug: post-compaction recall drop; unreachable-node count. Recover: re-run neighbor selection for affected nodes.
  • Non-atomic swap → readers see a half-built compacted graph. Root: in-place mutation visible mid-compaction. Debug: loom; sporadic wrong results during compaction. Recover: COW snapshot + atomic pointer swap (I8).
  • Compaction storm (triggered too often) → CPU/latency thrash. Root: low threshold / no hysteresis. Debug: frequent compaction events, latency spikes. Recover: hysteresis (compact at 20%, don't re-trigger until well below).
  • IVF re-train invalidates cached query tables without notice → transient recall dip. Root: centroid change mid-flight. Debug: recall dip at re-train boundary. Recover: re-train into a new index, swap atomically.
  • Compaction reclaims a value still referenced → dangling. Root: index compacted but store not consulted. Debug: dangling_entryid. Recover: compaction only drops nodes whose entry is Tombstoned/Expired in store (I7).

21.7 Performance Concerns

Compaction is O(live nodes) — amortized over time (background, rate-limited). COW doubles peak index memory transiently → budget headroom for compaction. Parallel rebuild across cores. IVF re-train k-means on a sample, not all vectors. Swap is O(1) pointer. Keep compaction off the foreground query path (epoch readers unaffected).

21.8 Edge Cases

Compaction with zero tombstones (no-op); compaction while a rebuild is in progress (serialize — one structural mutation at a time); all nodes tombstoned (compact → empty index); IVF with one centroid (degenerate → re-train); compaction interrupted by crash (no harm — index rebuildable from store, I6).

21.9 Failure Analysis

Compaction bug corrupts graph → caught by post-compaction recall validation → keep old index, alert, rebuild from store (I6). Compaction OOM (COW peak) → abort compaction, keep old index, raise budget. Blast radius: one namespace's index (always rebuildable). Recovery: rebuild from store is the universal repair.

21.10 Operational Notes

Metrics: compaction_events{ns}, compaction_duration, tombstone_ratio{ns} (pre/post), reclaimed_bytes, recall_post_compaction, ivf_retrain_events, index_peak_bytes (COW). Runbook recall-drop.md includes compaction/rebuild. Compaction thresholds + schedule are config. Rebuild-from-store is the operator's "fix the index" button.

22. Phase 10 — Observability + False-Hit Probing + Threshold-Drift Detection + Cost/Latency Accounting

22.1 Objectives

Make the system's correctness and value observable (principle 8): metrics for hit/miss/recall/latency/cost, sampled false-hit probes (the only way to estimate an error you can't see online, I14), threshold-drift detection, and accurate cost/latency-saved accounting. Full Prometheus exporter + decision audit + dashboards.

22.2 Detailed Implementation Steps

  • sc-observe/metrics.rs: counters/gauges/histograms — hit/miss, result_source, e2e_latency, index_recall_estimate, cost_saved, tokens_saved, latency_saved, per-namespace. Prometheus exporter (ADR-019; metrics facade).
  • sc-observe/reservoir.rs + probe.rs: false-hit probing — sample a seeded fraction (I14; Vitter reservoir sampling Paper 7 TOMS 1985; ADR-015) of served HITs; for each, also call upstream, compare cached vs fresh response (exact / semantic / cross-encoder equivalence), label as true-hit or false-hit; aggregate sampled false-hit rate. Bounded rate (cost-controlled, I14; Principle 8).
  • sc-observe/tdigest.rs: streaming quantiles for latency + similarity distributions (p50/p95/p99; Dunning & Ertl t-digest Paper 8) without storing all samples (O(1) space per digest).
  • sc-observe/hll.rs + countmin.rs: distinct-key cardinality per namespace (HyperLogLog, Flajolet et al. Paper 5, relative error 1.04/√m); prompt frequency (Count-Min, Cormode & Muthukrishnan Paper 6, feeds LFU Phase 6 + admission Phase 7).
  • sc-observe/drift.rs: detect threshold drift — track the distribution of served-HIT similarities + sampled false-hit rate over a window (Principle 13); alert when false-hit rate trends toward/over SLO or similarity distribution shifts (embedding-model change, data drift; I1 embed_ver boundary).
  • sc-observe/audit.rs: append-only decision audit (sim, τ, verify score, decision, source; ADR-020) — replay + postmortem input (Phase 11; I2 determinism gate).

22.3 Deliverable

A live metrics endpoint + dashboards showing hit rate, sampled false-hit rate vs SLO, recall, latency/cost saved per namespace; drift alerts fire when false-hit trends up; the decision audit log feeds replay.

22.4 Acceptance Criteria

  • Sampled false-hit rate estimate within a documented confidence interval of the true rate on a labeled fixture (probe sampling correct, I14).
  • Cost-saved accounting within ±5% of true tokens-saved (§4).
  • Drift detector flags an injected threshold/embedding drift before false-hit SLO is breached on a held-out trace.
  • Probe sampling is seeded + bounded-rate (I14): identical sampling across replay runs; probe cost ≤ configured fraction.

22.5 Conformance Fixtures

  • request_traces/false_hit_probe.json (known false-hit rate → estimate matches). request_traces/drift_injected.json (drift → alert). golden_decisions/p10_metrics.json (cost/latency-saved accounting). Edge: request_traces/zero_false_hit.json.

22.6 Pitfalls

  • No false-hit measurement → ship a threshold that silently doubles false hits. Root: treating false-hit as unmeasurable. Debug: customer reports wrong answers, dashboard blind. Recover: probe sampling (I14, principle 8).
  • Unbounded probe rate → probes cost more than the cache saves. Root: probing every HIT. Debug: upstream calls ≈ total requests (probes negate savings). Recover: small seeded fraction (I14).
  • Probe comparison too strict/loose → wrong false-hit estimate. Root: exact-match where semantic-equivalence intended (or vice versa). Debug: estimate diverges from labeled truth. Recover: namespace-appropriate equivalence (exact / semantic / cross-encoder).
  • Cost accounting double-counts (counting savings on probed HITs that also called upstream) → inflated savings. Root: probe path not excluded. Debug: cost-saved > plausible. Recover: exclude probed HITs from savings (they paid upstream).
  • Drift detector noisy → alert fatigue. Root: window too short / threshold too tight. Debug: frequent flapping alerts. Recover: longer window, hysteresis, trend not point.

22.7 Performance Concerns

Metrics are cheap counters (lock-free / per-core, summed). Sketches (HLL/CMS/t-digest/reservoir) are O(1)/event, bounded memory — never proportional to N. Probe sampling adds upstream cost only for the sampled fraction (the point is to pay a little to measure). Audit log append is sequential + batched. Keep all observability off the critical decision path (record after deciding).

22.8 Edge Cases

Zero HITs (no probes, no false-hit estimate — report "insufficient data"); namespace with probe rate 0 (no false-hit measurement — explicit opt-out, flagged); all probes true-hit (false-hit ≈ 0, confidence-bounded); drift at an embedding-model swap boundary (expected — correlate with embed_ver change); cost when token prices change (config-versioned price).

22.9 Failure Analysis

False-hit SLO breach (probe estimate > SLO) → alert + auto-action option (raise τ / enable verify / canary rollback) — the central safety mechanism. Probe path failure (can't reach upstream) → probes paused, false-hit unmeasured → degrade to conservative thresholds + alert "blind." Blast radius: measurement, not serving. Recovery: restore probing; recalibrate.

22.10 Operational Notes

Metrics catalogue (Prometheus): hit_rate{ns}, false_hit_rate_sampled{ns} (SLO panel), recall_estimate{ns}, cost_saved_total{ns}, tokens_saved_total{ns}, latency_saved_ms{ns}, probe_rate{ns}, threshold_drift{ns}, distinct_keys{ns} (HLL). Dashboards: hit/false-hit vs SLO, savings (cost/latency), recall, drift, per-namespace breakdown. Alerts: false-hit > SLO, recall < floor, drift trend, savings collapse. Runbook false-hit-spike.md is driven by these.

23. Phase 11 — Deterministic Replay, Conformance Suite, Differential vs Exact-kNN/FAISS

23.1 Objectives

Lock correctness + determinism: a deterministic replay harness (I2/I14) that re-feeds a captured request+stats trace and asserts identical Decision sequences; a full conformance suite (recall, false-hit, eviction, invalidation, recovery, calibration); and a differential oracle (exact-kNN brute force + FAISS offline) cross-validating nearest-neighbor + false-hit behavior.

23.2 Detailed Implementation Steps

  • sc-trace/capture.rs: record each request's inputs + the sealed config (I4 calib_hash) + the seeded probe draws (I14; ADR-032 fixed seeds) + the resulting Decision into a trace (ADR-020 decision/event log format).
  • sc-trace/replay.rs: feed a captured trace through the engine (with the same sealed config + seeds) → assert identical Decision sequence + identical similarities + identical store mutations (I2; ADR-032 reproducibility). Embedding determinism: replay uses captured embeddings (or deterministic mock provider Phase 0) so the only variable is the engine logic. Principle 4: Decision is a pure function.
  • Conformance buckets: recall/ (HNSW/IVF vs oracle; Paper 1/2), false_hit/ (probed estimate vs labeled truth; Vitter Paper 7), eviction/ (policy effectiveness; ARC Paper 11), invalidation/ (key/ns/version; I1/I7), recovery/ (crash → WAL replay → rebuild; I6/I9/ARIES Paper 9), calibration/ (τ vs SLO; ESL calibration Book 10).
  • Differential: brute-force exact-kNN as the in-process oracle; FAISS (Paper 3 Johnson et al. 2017) offline as a second independent oracle for recall + nearest-neighbor agreement; compare semcache HIT/MISS labels vs oracle "is there a true near-duplicate?" Tie-break by EntryId (deterministic).
  • tools/decision-diff + tools/recall-eval: diff two decision traces; compute recall@k vs oracle (Book 2 ann-benchmarks methodology).

23.3 Deliverable

make replay + make conformance + make differential green: identical decisions on replay; recall + false-hit + eviction + recovery all meet targets; semcache agrees with exact-kNN + FAISS oracles within tolerance.

23.4 Acceptance Criteria

  • 100% deterministic replay across the conformance trace set (I2): identical Decision sequence + similarities + store mutations, across 100 runs.
  • Recall@10 ≥ 0.95 (HNSW) / ≥ 0.90 (IVF-PQ) vs both oracles on the recall set.
  • Sampled false-hit rate ≤ SLO on every conformance corpus at the calibrated τ.
  • Crash-recovery conformance: post-restart decisions match pre-crash for all retained entries (I6/I9).

23.5 Conformance Fixtures

  • conformance/request_traces/* (replay). conformance/corpora/* (recall + false-hit, labeled). conformance/calibration/* (τ). golden_decisions/* (decision snapshots). FAISS oracle outputs cached for differential. Negative: malformed requests, cross-version lookups, bad configs.

23.6 Pitfalls

  • Replay diverges (non-determinism leaked). Root: unseeded probe RNG, wall-clock in a decision, or non-deterministic embedding. Debug: bisect decision inputs; replay diff. Recover: seed everything (I14); capture embeddings; purge clocks from decisions (I2).
  • Oracle disagreement on ties (equal-distance neighbors) → spurious recall mismatch. Root: tie-break order differs. Debug: mismatches only at equal distances. Recover: deterministic tie-break (by EntryId); compare sets not order at ties.
  • Differential corpus has unlabeled near-dups → false "false-hit." Root: incomplete labels. Debug: flagged false-hits that are actually correct dups. Recover: curate labels; treat ambiguous as excluded.
  • Replay uses live config, not sealed → drift. Root: reading current τ instead of trace's sealed config. Debug: replay differs after a config change. Recover: replay from sealed config in the trace (I4).

23.7 Performance Concerns

Replay is off the hot path; must be cheap enough to run in CI on the trace set. Differential vs FAISS runs offline (not per-PR). Recall eval samples queries (not all). Conformance at N=1M stresses index + recovery + compaction paths. Keep golden snapshots small + diffable.

23.8 Edge Cases

Trace with all MISSes (replay trivial); trace spanning a config change (replay each segment with its sealed config); trace with probes (replay reproduces seeded probe draws + comparisons); empty corpus; trace from an older format version (compat check — reject or migrate).

23.9 Failure Analysis

Replay divergence → highest-severity determinism bug → block release. Recall regression → false-miss (savings) → block on recall gate. False-hit conformance failure → correctness → block. Containment: CI gates everything; nothing ships without green replay + recall + false-hit. Recovery: fix determinism/recall; re-run.

23.10 Operational Notes

make replay/conformance/differential in CI. Decision-diff + recall-eval tools for triage. Golden decisions versioned; format changes → CHANGELOG. This phase is the correctness + determinism gate; replay traces double as regression fixtures (a prod incident → capture trace → permanent test).

24.1 Objectives

24.2 Detailed Implementation Steps

  • fuzz/fuzz_targets/ (ADR-023): wire_ir.rs (malformed requests → validator never panics; ADR-030 no panic on data path), wal_replay.rs (arbitrary/corrupt WAL → recovery never panics/loses acknowledged writes; I9/I11; ARIES Paper 9), index_ops.rs (random insert/search/delete sequences → no crash, no torn node; I8; ADR-024 loom), gate_decision.rs (random embeddings/thresholds → decision pure + bounded; I2).

24.6 Pitfalls

  • Wire IR (HTTP/gRPC): SemVer (format_version). Additive fields/variants → minor; removal/rename/semantic change → major. Validator rejects unknown major. #[non_exhaustive] on public enums for additive evolution.
  • Store / WAL format: SemVer (format_version); recovery reads any compatible minor; major change → migrate on checkpoint or rebuild. crc + version-stamped records.
  • Vector index: not a compatibility surface — always rebuilt from the store (principle 2, I6). HNSW/IVF param changes (m, ef, nlist) → rebuild; never a wire/storage break.
  • embed_ver / ModelVersion: data versions that partition the keyspace (I1), independent of code SemVer. A new embedding model or generation model = a new keyspace partition; the old one is aged out/invalidated (principle 10), never silently mixed.
  • Threshold / calibration: τ + calib_hash are sealed per (ns, embed_ver); changing τ is not an API break but is a CHANGELOG'd behavioral change, shipped default-off behind a flag with shadow eval (principle 13).
  • Public API (sc-core): stable within a major; pre-1.0 minor may break (documented). Deprecation: one minor of warning before removal.
  • Decision/trace format: versioned; replay across versions requires matching major; used for replay/conformance.
  • Semantic versioning policy: workspace crates share a major. Verify-model version partitions decisions like embed_ver (a verify-model swap requires recalibration + is CHANGELOG'd).

Scalability Analysis

  • Bottlenecks: embedding latency (mitigated by batching + local provider); HNSW search at large N (mitigated by ef tuning, IVF-PQ for large/cold sets); WAL fsync (mitigated by group-commit); index memory (mitigated by IVF-PQ quantization + eviction + compaction).
  • Scaling ceilings: single-node RAM bounds resident index (N·d·4 + links); NVMe bandwidth bounds WAL/spill; cores bound concurrent search throughput.
  • Horizontal scaling: the Namespace + shard-key is the seam (cross-link #59); a future distributed layer shards namespaces / vector ranges across nodes with a consistent-hash ring + per-shard index + replicated WAL. Deferred (PhaseDeferred("Deferred Features Register")). The value-store/index split already models a shardable design.
  • Vertical scaling: more cores → more concurrent lookups (lock-free reads); larger RAM → larger resident N; IVF-PQ trades recall for 2–8× memory reduction at large N.
  • Sharding/partitioning: per-namespace indexes already partition; within a namespace, vector-space partitioning (IVF lists) + value-store sharding by EntryId hash.
  • Replication pressure: distributed mode (deferred) replicates WAL + rebuilds index per replica from its store (principle 2 makes replicas cheap — ship the log, rebuild the index).
  • Coordination overhead: single-writer per namespace index serializes structural mutations — bounded (inserts are fast, compaction is background); no cross-namespace coordination single-node.
  • Network fanout: N/A single-node; distributed fan-out = scatter-gather ANN across shards + merge top-k (deferred).
  • Scheduler saturation: embedding + verify model inference can saturate CPU/GPU — batched + bounded; admission/shed prevents overload.
  • Storage growth: value store + WAL grow with admitted entries; eviction + compaction + checkpoint-truncation bound it; spill cold entries to disk.
  • Metadata scaling: per-namespace Threshold/calibration + index manifest are O(namespaces); decision audit append-only, bounded per retention window.

Mental Models & First Principles

MM1 — A semantic cache is a statistical decision, not a lookup. Insight: classic caches answer a boolean ("is key present?"); a semantic cache answers a probabilistic question ("is there a stored entry close enough to be correct?") with bounded error. It predicts: false-hit rate is a first-class output, not a side-effect. Bug class without it: treating the cache as correct-by-construction, shipping no false-hit measurement, and learning about errors from users. Applied: §4 System Constraints (false-hit SLO); Phase 4 (calibrate.rs); Failure Modes (false-hit SLO breach).

MM2 — The store is truth; the index is a derived view. Insight: Helland's "Immutability Changes Everything" — append-only records + derived views decouple durability from query structures. The WAL + value store are immutable truth; the HNSW graph is a derived index rebuilt from them. It predicts: index loss ≠ data loss; index bugs don't corrupt responses. Bug class without it: persisting the index as truth → a corrupt index requires rebuilding responses from an unavailable source. Applied: Design Principle 2; Phase 3 (rebuild path); ADR-008; I6.

MM3 — Calibration is the ROC curve applied to a gate. Insight: threshold selection is a precision-recall tradeoff from binary classification. A similarity threshold τ moves along the ROC curve: lower τ = more HITs (higher recall) + more false hits (lower precision). The SLO is a precision floor; τ is set at the Pareto point. It predicts: any threshold change moves hit rate and false-hit rate in opposite directions. Bug class without it: setting τ by feel, overshooting hit rate, shipping a false-hit rate 5× the SLO. Applied: Phase 4 (calibrate.rs, τ sweep, held-out split); §4 false-hit SLO; MM8.

MM4 — Epoch reclamation: defer freeing until readers drain. Insight: lock-free concurrent data structures defer memory reclamation until no thread holds a reference to an old version. In HNSW, a reader traversing a graph node must finish before a writer reclaims that node. Crossbeam-epoch implements this via pinned readers + per-epoch garbage lists. It predicts: without epoch, a reader following a pointer to a reclaimed node crashes or reads garbage. Bug class without it: use-after-free under concurrent insert/compact. Applied: Phase 2 (sc-index/epoch.rs); I8; ADR-009; Phase 9 (COW swap).

MM5 — Write-ahead: the log is the source of truth for durability. Insight: ARIES WAL: append the intent before mutating state; replay the log on recovery; an fsync'd WAL record guarantees the mutation survives a crash. The store is reconstructable from the log. It predicts: any mutation visible before the WAL record is fsync'd can be lost on crash. Bug class without it: write-behind store → crash drops acknowledged writes. Applied: Phase 3 (wal/log.rs, write path I9); I5 (idempotent replay); ADR-007; Design Principle 11.

MM6 — Admission is expected-value filtering, not a heuristic. Insight: cache only when E[cost_saved] > E[storage_cost + false_hit_penalty]. P(reuse) is estimated from frequency sketches; false_hit_penalty is the SLO-weighted cost of a wrong answer. This model predicts: unique prompts (P(reuse)≈0) have negative expected value and should be rejected. Bug class without it: always-cache bloats the index with one-offs, raises false-hit risk, and yields zero savings per stored byte. Applied: Phase 7 (sc-admit/cost.rs); I15; Design Principle 9.

MM7 — Embedding version partitions the similarity space. Insight: cosine similarity is meaningful only within a fixed embedding function. Two embeddings from different model versions are not comparable — their inner product has no semantic interpretation. The keyspace is partitioned by (Namespace, embed_ver); cross-version comparisons violate geometry. It predicts: mixing embed versions silently degrades recall or produces false hits with no metric signal. Bug class without it: routing queries to a mismatched index partition after a model upgrade. Applied: I1; Design Principle 3; Phase 1 (version routing); Phase 4 (τ per (ns, embed_ver)).

MM8 — You cannot observe false-hit rate online; you must measure it by probe. Insight: on a HIT, you return a cached response to the caller without calling upstream — so you never know if the cached answer was correct. The only way to estimate false-hit rate is to occasionally force an upstream call for a served HIT, compare outcomes, and sample the ratio. This is reservoir sampling applied to a latent variable. It predicts: a cache without probing cannot report its false-hit rate; operators are blind to the central correctness SLO. Bug class without it: shipping a threshold that is quietly 5× the SLO. Applied: Phase 10 (sc-observe/reservoir.rs + probe.rs); I14; Design Principle 8; §4 false-hit SLO.

GPTCache made the decision to skip a correctness gate and treat "nearest neighbor wins" as sufficient — this wins in demo/prototype settings where false hits are tolerable and engineering simplicity dominates. The tradeoff: index corruption requires index-level recovery, not log replay.

This wins when the operational team already runs Redis and wants to co-locate semantic search with existing KV/TTL/pub-sub semantics in one process. This wins when the use case is a multi-modal, multi-tenant search platform where operational simplicity (deploy one system) outweighs GC pause latency and when hybrid sparse+dense retrieval is required. Back-of-Envelope Capacity Model

All numbers derived from §4 System Constraints. Formulas shown.

C1 — Index memory (HNSW, N=1M, d=768): Vector storage: N × d × 4 bytes = 1,000,000 × 768 × 4 = 3,072 MiB ≈ 3.0 GiB. HNSW link overhead: each node holds M=16 bidirectional links per layer × avg 1.3 layers × 8 bytes/id = ≈ 0.2 GiB. Total index resident: ≈ 3.2 GiB. Evict before 90% of 4 GiB budget = 3.6 GiB → safe headroom at 1M entries.

C2 — Value store memory (N=1M entries): Average response size estimate: 500 tokens × ~4 bytes/token = 2 KB/entry. N × 2 KB = 2,000,000 KB = ≈ 2.0 GiB resident (cold entries spill to NVMe). With metadata overhead (128 bytes/entry): 1M × 128 B = 128 MiB additional. Total hot store ≈ 2.13 GiB.

C3 — WAL write throughput requirement: Target admission rate = MISS rate × QPS = 50% × 50k lookups/s = 25k new entries/s. WAL record per entry = ≈ 2.1 KB (avg response) + 64 B header + 4 B crc32c ≈ 2.2 KB. WAL bandwidth = 25k × 2.2 KB = 55 MB/s sequential writes. NVMe sustains ≥ 1 GB/s sequential → 18× headroom. Group-commit (ADR-007) batches at 50 ms → at most 1,250 entries/batch, single fsync per batch = ≤ 500 fsyncs/s (well below NVMe IOPS limit of ~100k/s).

C4 — Lookup throughput target vs cores: §4 target: ≥ 50k lookups/s on 8 cores = 6,250 lookups/s/core. HNSW search at N=1M, d=768, ef=64: empirically ≈ 0.4 ms/search = 2,500 searches/s/core (single-threaded). With lock-free parallel reads (I8, ADR-009): 8 cores × 2,500 = 20,000 searches/s for search alone. Embedding (local, batched, c=16): ≈ 5 ms/embed → 200 embeds/s single-core, but batching + pipelining at 8 cores → ≈ 3k-6k embed/s throughput. Target 50k/s requires: embed latency hidden by batching (ADR-010) + accept that HIT path dominates at high hit rate (embed is only on every request, not just MISSes). Achieved at hit rate ≥ 80% by queueing embeds.

C5 — FD budget: WAL segments: rotate at 64 MB → at 55 MB/s write rate, 1 new segment every ~1.2 s; keep 4 active = 4 FDs. Value-store segments: max 128 MB each; at 2 GiB resident → ≈ 16 segments = 16 FDs. Checkpoint files: 2 (current + prior) = 2 FDs. Network connections (server): ≤ 128 concurrent (backpressure cap) = 128 FDs. Upstream connection pool: ≤ 16 connections = 16 FDs. Total: ≈ 166 FDs. Budget ceiling §4 is 256 → 90 FD headroom for spill / miscellaneous.

C6 — Embedding batch latency budget: To keep HIT-path embed ≤ 5 ms p95 (§4), batch window must be ≤ 5 ms. At 6,250 requests/s/core, arrivals in 5 ms window ≈ 31 prompts → batch size 16–32 is achievable and gives ≥ 3× throughput (§13.4 criterion), confirming batch window selection.

C7 — False-hit probe cost: Probe rate = 1% (I14 default). At 50k HITs/s × 1% = 500 probes/s. Each probe = one upstream model call ≈ 500 ms latency, but runs in background. Probe upstream cost = 500 calls/s × avg token cost $0.01/call = $5/s = $432k/day — clearly too high. Reality: 50k HITs/s is the ceiling; at typical 10k HITs/s, 1% = 100 probes/s = $0.01/call × 100 = $1/s — acceptable. Probe rate must be tuned per namespace to keep probe cost < 1% of total cost saved. Design: rate cap in I14.

C8 — Compaction COW peak memory: Compaction builds a new graph while the old one is live (COW, Phase 9). Peak = 2× index memory = 2 × 3.2 GiB = 6.4 GiB. Budget ceiling: index budget 4 GiB (§4) + overage → compaction must be triggered before budget is full. Trigger at tombstone_ratio > 20% when index is < 70% of budget → 2× = 140% ≤ 200% of budget. Headroom: 512 GiB RAM assumed on large node (§4 scaling assumption); 6.4 GiB is negligible.

C9 — Recall vs ef sweep (search latency): HNSW beam width ef controls the recall/latency Pareto. Empirical from Paper 1 and ann-benchmarks (Book 2): ef=16: recall ≈ 0.90, search ≈ 0.2 ms; ef=64: recall ≈ 0.95, search ≈ 0.4 ms; ef=256: recall ≈ 0.99, search ≈ 1.5 ms. Target: recall ≥ 0.95 at p99 ≤ 5 ms → ef=64 is the design point. Marginal widen (Principle 14) to ef=128 on marginal candidates; p99 impact: +1.1 ms ≤ 5 ms p99 budget (acceptable).

C10 — Storage amplification (WAL + compaction): Pre-compaction: WAL grows at 55 MB/s; checkpoint every 5 min → WAL tail = 55 × 300 = 16.5 GB before truncation. After truncation, only the tail since last checkpoint survives ≈ 55 MB/s × 50 ms group-commit interval × entries-since-checkpoint. Storage amplification from WAL: < 2× logical (§4 target). Post-compaction: index reclaims tombstone overhead → amplification drops to ≈ 1.3× as stated in §4.

C11 — HyperLogLog cardinality estimation error: Each namespace HLL uses m=2^14 = 16,384 registers → relative error = 1.04/√m = 1.04/128 ≈ 0.81%. Memory per HLL: 16,384 × 6 bits = 12 KB per namespace. At 100 namespaces: 100 × 12 KB = 1.2 MB total HLL overhead — negligible.

C12 — End-to-end HIT latency budget (§4 ≤ 2% of model call): Model call: 500 ms (§4 System Constraints HIT vs MISS speedup note). 2% = 10 ms HIT latency budget. Actual HIT path: embed 5 ms (p50) + HNSW search 0.4 ms + gate 0.001 ms + response retrieval 0.1 ms = 5.5 ms p50. p99 budget: embed 15 ms + search 5 ms + gate 0.002 ms + retrieval 0.2 ms = 20.2 ms p99. At p99 ≡ 4% of 500 ms model call. For a 1.5 s model call (§4 HIT vs MISS note), 20 ms = 1.3% → within the ≤ 2% target. Embed dominates; batching is the primary lever.

Alternative Architectures (Roads Not Taken)

Alt-1 — Shared-Nothing Distributed Semantic Cache

 Client ──► Consistent-Hash Router
              │         │         │
         [Node A]  [Node B]  [Node C]
         HNSW+WAL  HNSW+WAL  HNSW+WAL
         (shard 0) (shard 1) (shard 2)
         fan-out ANN query → merge top-k across shards

Regime where it wins: prompt corpus exceeds single-node RAM (N > 50M entries at d=768); QPS > 500k/s requiring horizontal throughput scaling; multi-tenant isolation at the shard level (one namespace per node).

Real system embodying it: Milvus (distributed vector database with consistent-hash sharding + WAL replication per shard).

Why rejected: single-node covers the stated design target (N≤1M, 8–64 cores, 32–512 GiB RAM). Distributed adds cross-shard fan-out latency (adds 10–50 ms RTT per ANN query), consensus overhead for WAL replication, and a partition-tolerance decision (split-brain tolerates stale HITs or refuses). The Namespace/shard-key seam is designed so this architecture can be layered on later without changing sc-core (cross-link #59, deferred).

Alt-2 — Exact-Match + Fuzzy Prefix Cache (No Vector Index)

 Client ──► Exact-match LRU cache (prompt hash)
              │ MISS
              ▼
            N-gram / LSH fingerprint index
              │ MISS
              ▼
            LLM upstream

Regime where it wins: prompt population has very low diversity (dominated by templates with slot-fill variants); embedding a model per request is too expensive or unavailable; correctness requirements are very high (every answer must be exactly right, not approximately).

Real system embodying it: Varnish / Nginx cache keyed by URL + Vary headers — exact-match caching for HTTP, widely deployed.

Why rejected: for LLM prompts with free-text variation (paraphrases, reformulations), exact-match yield is near-zero (HIT rate < 5% on a typical conversational corpus). N-gram/LSH fingerprints have poor recall on semantic paraphrases. The semantic cache's ANN core is precisely the mechanism that converts semantically-equivalent prompts into HITs. A pure exact-match cache is a degenerate special case of this design (τ=1.0) with far lower savings.

Alt-3 — LLM-as-Judge Gate (No Vector Index at All)

 Client ──► Store recent (prompt, response) pairs in a list
              │ lookup
              ▼
            LLM "is this new prompt semantically equivalent to any stored prompt?"
              │ HIT: return cached; MISS: call upstream
              ▼
            Store new (prompt, response)

Regime where it wins: corpus is tiny (< 100 entries); correctness requirement is extreme (false-hit rate must be near-zero); inference cost per cache check is acceptable; the embedding model is unavailable.

Real system embodying it: GPT-based semantic de-duplication pipelines used in legal/medical document review, where each pair is explicitly judged.

Why rejected: O(N) LLM calls per lookup — latency grows linearly with cache size and is prohibitively expensive at N > 100. Latency of an LLM judgment (500 ms–5 s) exceeds the latency of a model call we're trying to avoid. The ANN index + threshold gate is the efficient approximation of this exact oracle; verify (Phase 5) approximates it further with a cross-encoder.

Alt-4 — Write-Through KV Cache with Embedding Pre-Computation (No ANN)

 Client ──► Embed prompt → exact-match lookup (embedding hash) ──► HIT
              │ MISS
              ▼
            LLM upstream
              │
            Embed response prompt → store (embedding_hash → response)
            (precomputed embeddings, retrieved by exact hash of the embedding vector)

Regime where it wins: application controls prompt generation (finite template set); all prompt variants are enumerable at build time; the embedding space is discrete (not free-form text); team needs the simplicity of an exact KV without building an ANN index.

Real system embodying it: Redis caching of computed ML features keyed by a feature hash (feature-store pattern), used widely in recommendation systems.

Why rejected: requires the prompt-to-embedding mapping to be injective and stable — any paraphrase of a prompt produces a different embedding hash, yielding a MISS. Real LLM applications have free-text prompts where semantically equivalent variants have different embedding vectors by construction (the whole reason an ANN index is needed). This architecture is only correct for a constrained prompt schema, not the general case.

Domain Deep Dive — Anatomy of a Lookup (embed → search → gate → verify → serve / passthrough)

A concrete trace of the hot path on a lookup, showing every decision point and why the bias is toward a correct MISS over a risky HIT.

Request (FAQ namespace, embed_ver=v3, generation model gpt-4o@2024-08):

prompt = "how do I reset my password?"

A semantically near-identical entry is cached: "what's the way to reset a password?" → answer A, embedded with v3, τ_faq = 0.86, margin = 0.02, VerifyMode = Off.

Step table — what the engine does at each boundary:

Step Action Result Invariant / principle
1 Validate request (size, params, ns known) OK threat-model input guard
2 Scope: route to (faq, v3) index; check embed_ver match v3 I1 (version isolation)
3 Embed prompt (local provider) → L2-normalize q (norm≈1) I3 (normalized cosine)
4 HNSW search (ef=64, top-1) in (faq, v3) candidate E (cached "reset a password?") sim=0.91 recall ≥ 0.95
5 Threshold gate: sim 0.91 ≥ τ 0.86 candidate HIT I4 (sealed τ)
6 Validity: E Live, not TTL-expired valid I10 (no stale serve)
7 Verify (mode Off) skipped §5 (per-ns mode)
8 Probe sample? seeded draw at rate 1% not drawn this request I14 (seeded probes)
9 Decision = Hit(E, 0.91) serve answer A from cache I2 (pure decision)
10 Record metrics: hit, cost_saved, latency_saved dashboards updated principle 8

HIT served in ~5.5 ms (embed 5 ms + search 0.4 ms + gate 1 µs) vs a ~1.5 s model call → ~270× faster, full token cost saved.

Marginal variant (conservative MISS): suppose the only candidate scored 0.85 (just under τ=0.86, inside [τ−margin, τ) = [0.84, 0.86)). With VerifyMode=Off the marginal candidate is not served — Decision = Miss(Marginal) → forward upstream → admit → store. The system pays for one model call rather than risk serving answer A to a subtly different question (principle 1, 14). If this namespace had VerifyMode=CrossEncoder, the marginal candidate would be re-scored jointly; the cross-encoder either confirms (→ HIT) or rejects (→ MISS) — turning an ambiguous cosine into a defensible decision (§5).

Probe variant (measuring the unmeasurable): on a different request, step 8's seeded draw fires (1% sample). The engine serves the cached HIT to the caller and calls upstream in the background, compares the fresh answer to the cached one (namespace-appropriate equivalence), and labels the pair true-hit or false-hit. This sampled label feeds false_hit_rate_sampled{faq} — the headline correctness SLO. The probe pays one extra model call to measure an error rate that is otherwise invisible (I14, principle 8). Probe savings are excluded from cost_saved (it paid upstream).

Degradation variant (cache fault): suppose at step 4 the index panics (a bug, or it is mid-rebuild). The server's catch-all (fallback.rs) logs cache_bypass{index_fault} and forwards the request to upstream — the caller gets a correct answer, slightly slower, and never sees an error (I12, principle 5). Meanwhile the index self-heals (rebuild from store, I6) and resumes serving HITs. A cache fault is a savings degradation, never an availability or correctness incident.

Why decisions are deterministic + replayable: every input to step 9's Decision is either the (captured) query embedding, the retrieved candidates + their similarities, the sealed Threshold (with calib_hash), or the seeded probe draw. No wall-clock, no unseeded RNG, no thread-completion-order. Replaying the captured trace with the same sealed config + seeds reproduces the identical Decision sequence and store mutations, byte for byte (I2/I14) — so a production false-hit incident becomes a deterministic regression fixture.

Glossary

Term Definition
Semantic cache Cache keyed by similarity of prompt meaning (embedding), not exact bytes.
HIT A cached response is returned because a stored entry is similar + valid enough.
MISS No suitable cached entry; the backing model is called (and the result possibly stored).
False hit A HIT that returns a wrong answer (a close-but-different prompt matched). The cardinal error.
False miss A MISS where a correct cached answer existed but wasn't matched (lost savings).
Embedding Dense vector representation of text; the fuzzy cache key (L2-normalized).
embed_ver Embedding-model version; partitions the keyspace (entries/queries must share it).
ModelVersion Generation (LLM) model version; part of the exact CacheKey scope.
Namespace Logical partition (tenant / use-case) with its own index + threshold + budget.
Cosine similarity Dot product of L2-normalized vectors ∈ [−1,1]; the similarity score gated against τ.
Threshold (τ) Per-(namespace, embed_ver) cosine cutoff; sim ≥ τ → candidate HIT.
Margin Band below τ where candidates are treated as marginal → conservative MISS (or verify).
ANN Approximate Nearest Neighbor search — fast, recall < 1.0.
HNSW Hierarchical Navigable Small World graph ANN index (primary).
IVF-PQ Inverted-file + product-quantization ANN index (memory-efficient alternative).
Recall@k Fraction of true k-nearest neighbors the ANN index returns vs exact kNN.
ef HNSW search beam width; higher = better recall, slower.
Tombstone Soft-deleted index node, skipped in search, reclaimed by compaction.
Compaction Physically remove tombstones + relink the index; reclaim memory.
Rebuild Reconstruct the index from the store (the universal index repair, I6).
Cross-encoder A model scoring query↔candidate jointly; high-precision HIT verification.
Re-rank Re-order ANN candidates with a more precise scorer (exact re-score / cross-encoder).
Verification Second gate after threshold: re-score / cross-encoder / faithfulness before HIT.
Calibration Offline selection of τ from labeled pairs to meet the false-hit SLO.
Admission control Cost-benefit + cacheability decision on whether to store a MISS's response.
Cacheable A response that is deterministic + reusable + has no one-shot side-effect.
Eviction Remove entries under memory pressure (LRU/LFU/ARC + semantic cluster prune).
Semantic cluster prune Evict redundant near-duplicate entries, keeping a cluster representative.
TTL Time-to-live; expired entries are never served (I10).
Invalidation Explicit removal by key / namespace / model-version.
Backpressure Bounded queues; full downstream throttles upstream.
Load shedding Under pressure, reject admissions then bypass the cache (degrade savings).
Bypass / passthrough Forward to upstream without caching (on fault or under load); the request never fails (I12).
WAL Write-ahead log; durable record of store mutations, replayed on recovery (I9).
Checkpoint Periodic store snapshot + index manifest; truncates WAL prefix.
Exactly-once Put Put(EntryId) is idempotent under replay/retry (I5).
Source of truth The value store + WAL; the index is derived/rebuildable (principle 2, I6).
Epoch reclamation Lock-free read scheme: defer freeing until readers drain (I8).
False-hit probe Seeded sampled HIT also sent upstream to label true/false (measures false-hit, I14).
Threshold drift Slow change in served-similarity distribution / false-hit rate over time.
Deterministic replay Re-feeding a captured trace yields identical decisions + mutations (I2).
Cost saved Token / dollar cost avoided by serving from cache instead of upstream.
Latency saved Model-call latency avoided by a HIT.
EntryId Dense id joining a vector-index node to its CacheEntry (I7).
CacheKey Hash of (namespace ‖ model-version ‖ canonical params); the exact-match scope.
