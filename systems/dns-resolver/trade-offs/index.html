Decisions (§9) · 29 ADRs

ADR-01

Core language

Chosen

Rust 2024

Rejected

Go

When the rejected choice is right

A forwarding-only cache with no DNSSEC validation, where GC pause budget is irrelevant (e.g. CoreDNS's plugin-chain niche)

Why: No GC stalls on the crypto/cache hot path; lifetimes encode bailiwick ownership at the type level; hickory-dns is the proximate proof point

ADR-02

Core language vs. C

Chosen

Rust 2024

Rejected

C

When the rejected choice is right

A resource-constrained embedded target with a certified C toolchain and no Rust cross-compilation support

Why: We compete on correctness and eliminating the buffer-overflow CVE class this exact domain has produced repeatedly, not on BIND/Unbound's operator-feature maturity

ADR-03

Async runtime

Chosen

tokio

Rejected

async-std, smol

When the rejected choice is right

A minimal single-transport (UDP-only) resolver where tokio's larger dependency tree isn't justified

Why: Uniform async story across UDP/TCP/DoT/DoH/DoQ; hyper/quinn/rustls are tokio-first

ADR-04

QUIC/DoQ stack

Chosen

When the rejected choice is right

A deployment already vendoring BoringSSL/quiche for HTTP/3 elsewhere, wanting one QUIC stack for both

Why: Mature pure-Rust QUIC with a stable ALPN doq story

ADR-05

TLS stack

rustls

Rejected

FIPS-140 certification is contractually required and rustls's FIPS module isn't approved in-jurisdiction

Why: Memory-safe TLS without OpenSSL's surface area; required for DoT and DoH's TLS layer

ADR-06

ADR-07

Crypto primitives

Chosen

Rejected

RustCrypto (rsa, p256, ed25519-dalek)

When the rejected choice is right

An algorithm ring doesn't expose is mandated (e.g. a regional GOST requirement)

ADR-08

Buffer ownership

Chosen

bytes::Bytes

Rejected

Vec<u8> with explicit copies

When the rejected choice is right

A one-shot CLI tool with no cross-boundary sharing (dns-cli uses Vec<u8> at its edges, §21.4)

Why: Zero-copy slicing across the codec/cache/transport boundary

ADR-09

Cache granularity

Chosen

Per-RR, keyed (Name, Type, Class)

Rejected

Per-message (whole Message cached verbatim)

When the rejected choice is right

A pure forwarding proxy with no validation/trust-ranking need (see dnsdist packet-cache mode, §32)

Why: The RRset is the reusable unit across unrelated messages; per-message caching produces staleness the moment two queries share an RRset

35. Alternative Architectures (Roads Not Taken)

Alt-1 — Thread-per-connection, blocking I/O.

Show the original text diagram
[client]──►[blocking accept thread]──►[dedicated worker thread]──►[blocking upstream call]

Regime where it wins: small connection counts, simpler single-step debugging (a thread's stack trace is the whole request). Real system: classic BIND 9's pre-9.16 worker model. Rejected here: does not scale to the M2 concurrency target (§4, §30) without a thread per in-flight query, which blows the FD/memory budget (§33 item 2) at 10,000 q/s.

Alt-2 — Unified authoritative + recursive process.

Show the original text diagram
[one binary]──►[authoritative zone store]
            └─►[recursive resolver + cache]

Regime where it wins: a single-operator hobbyist deployment wanting one binary, one config file. Real system: BIND 9's default named.conf supports both roles in one process. Rejected here (ADR-19): security separation and blast-radius containment outweigh operational simplicity at this design's target scale.

Alt-3 — Prefetching cache (refresh-before-expiry).

Show the original text diagram
[TTL countdown]──►[prefetch trigger at ~10% TTL remaining]──►[background refresh]──►[swap]

Regime where it wins: high-traffic, predictable-popularity zones (ISP-scale resolver where a cache miss on a popular name is expensive in aggregate). Real system: Unbound's prefetch: yes. Rejected here (§36 Deferred Features Register): added complexity/memory overhead isn't justified at Phase-0's target load; revisit if traffic profile shifts.

Alt-4 — Forward-only encrypted proxy, no local recursion or validation.

Show the original text diagram
[client]──►[DoH/DoT forwarder]──►[public recursive resolver]
              (no cache, no validator, no NS-chase)

Regime where it wins: client devices behind corporate egress control needing transport encryption without owning resolution logic. Real system: cloudflared/dnscrypt-proxy in forward mode. Rejected here: defeats this project's pedagogical goal (§2) — recursion and DNSSEC validation are the entire point, not a delegable concern.
