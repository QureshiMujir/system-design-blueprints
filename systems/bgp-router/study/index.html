Hard questions (§36)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does treating an AS_SET segment as length-N instead of length-1 in AS-PATH comparison invert a tie-breaker, and which two sections define the correct behavior and its test? (§8.4, §16)
  2. Why is MED comparison restricted to routes sharing the same immediate-upstream AS, and what network-level problem would "always-compare-MED" create? (§8.4, §16, I13)
  3. Why does route reflection (§19) trade away the "free choice" property that a full iBGP mesh has, and under what topology does this matter in practice? (§19, §38, §5 Griffin & Wilfong)
  4. Why is the FIB programmer decoupled from BGP session state via a trait boundary rather than called directly from the FSM, and what would break if it weren't? (§3, §11, §23)
  5. Why does graceful restart distinguish end-of-RIB for IPv4 unicast (zero-NLRI UPDATE) from every other family (zero-NLRI MP_UNREACH_NLRI), and what bug results from conflating them? (§8.2, §20)
  6. Why is route-flap damping opt-in and default-off rather than always-on, and what real-world route pattern does always-on damping harm? (§21, §5 RFC 7196)
  7. Why does RPKI origin validation (§22) not defend against a route-leak with a technically-valid origin AS, and what mechanism would close that gap? (§22, §38 BGPsec)
  8. Why must the best-path decision process be a pure function with no hidden IO, and what two invariants would break if IGP cost were queried live instead of snapshotted? (P1, I2, §16)
  9. What does the Griffin-Wilfong stable-paths result imply about whether any policy configuration is guaranteed to converge, and how does this router's design accept or mitigate that risk? (§5, §38)
  10. Why does this design intern PathAttributes (P11) rather than storing a full copy per route, and what specific memory-ceiling number (§4) would be violated without it? (§11, §35)
  11. Why is TCP-MD5 session security silent-on-failure (no NOTIFICATION on mismatch) by protocol design, and how does the operational runbook compensate for that observability gap? (§25 T-4, §26 FM-6, §27)
  12. Why does the Adj-RIB-Out layer need to exist at all, rather than generating outbound UPDATEs directly from Loc-RIB on every change? (§8.3, §26 FM-5)
  13. Why does this router treat NotFound RPKI classification differently from Invalid, and what would over-rejecting NotFound do to the current internet's route acceptance rate? (§22, §22.6)
  14. Why is iBGP full-mesh's O(n²) scaling a "named bottleneck" rather than an implementation detail, and what two mechanisms in this design remove it at different scales? (§19, §32, §5 R-BGP)
  15. Why does the filter DSL require parse-time exhaustiveness checking (every branch reaches accept/reject) rather than a runtime default, and what production failure mode does this specifically close? (§17, §17.9, §26 FM-12)

33. Mental Models & First Principles

  • MM1 — BGP is a distributed database with no consensus; each router computes its own answer from locally-visible state. Predicts: two routers can legitimately disagree transiently, and global convergence is emergent, not coordinated. Bug class without it: assuming a network-wide "current best route" exists as a single fact rather than per-router state. Applied in §16, §32.
  • MM2 — The FSM is a contract, not a suggestion; an unhandled (State,Event) pair is a silent deadlock, not a crash. Predicts: the worst FSM bugs are invisible until the exact event ordering that hits the gap occurs. Bug class without it: treating "it works in testing" as sufficient without exhaustive (State,Event) coverage (I10). Applied in §14.
  • MM3 — Loop-freedom in path-vector routing is self-describing, not centrally coordinated: the AS_PATH itself is the loop detector. Predicts: any place that skips inspecting the full AS_PATH (e.g., a fast-path optimization) reintroduces the loop risk BGP was designed to prevent. Bug class without it: silent routing loops from partial AS_PATH validation. Applied in §8.1, §16, §32.
  • MM4 — Route-flap damping trades convergence speed for stability — a CAP-like tradeoff, not a free lunch. Predicts: always-on damping looks safer but actively harms legitimately-dynamic routes (RFC 7196). Bug class without it: enabling damping by default and being surprised by suppressed-but-legitimate multihomed failover. Applied in §21.
  • MM5 — iBGP full-mesh is O(n²); route reflection breaks the mesh at the cost of the free-choice property (Griffin & Wilfong). Predicts: a route reflector can, in pathological configurations, hide a route a full-mesh topology would have chosen — a real, not hypothetical, correctness-vs-scalability trade. Bug class without it: assuming route reflection is "free" scaling with zero semantic cost. Applied in §19, §38.
  • MM6 — Policy is a pure function; any side effect in the filter engine is a bug, not a feature. Predicts: a filter that "sometimes" behaves differently on identical input has a purity violation somewhere, not a legitimate stateful policy need. Bug class without it: policy debugging that assumes non-determinism is normal. Applied in §17 (I9).
  • MM7 — The RIB pipeline (Adj-RIB-In → policy → Loc-RIB → policy → Adj-RIB-Out) is structurally the same shape as a compiler's front-end → middle-end → back-end. Predicts: bugs that would be "type errors" in a compiler (an ill-typed filter field) should be caught at the same pipeline stage a compiler would catch them — parse/type-check time, not codegen/runtime. Bug class without it: policy errors surfacing as production route anomalies instead of config-validation failures. Applied in §8.5, §17.
  • MM8 — MED is only a hint, scoped to a single upstream AS; treating it as a global priority is a category error. Predicts: any cross-AS MED comparison produces results the sending AS never intended. Bug class without it: "always-compare-MED" configurations that invert traffic-engineering intent. Applied in §16 (I13).

Reference Implementations

  • BIRD (CZ-NIC/bird): proto/bgp/ (FSM + attribute codec), filter/ (typed filter DSL). Lesson: a filter language type-checked at parse time eliminates a whole class of operator error — applied in §17. Pitfall not to copy: BIRD's filter grammar overloads int for both plain integers and pair-encoded communities; we keep them distinct types (ADR-04, §9).
  • FRRouting (FRRouting/frr): bgpd/bgp_fsm.c (state machine), zebra/ (RIB-to-FIB abstraction). Lesson: decoupling the FIB programmer behind an IPC boundary (zebra) lets multiple protocol daemons share one FIB safely — applied in §3, §23. Pitfall: zebra's IPC adds a serialization hop we avoid by keeping the FIB programmer in-process (ADR-07, §9).
  • GoBGP (osrg/gobgp): internal/pkg/table/ (RIB representation), pkg/server/ (gRPC control API). Lesson: an RPC-exposed control plane makes BGP programmable from external controllers — applied in the deferred gRPC API design (§38). Pitfall: GoBGP's global mutex around the whole RIB serializes all peers; we use per-AFI/SAFI table locks instead (I9, applied in §7).
  • OpenBGPD (openbgpd-portable): session.c (minimal FSM), rde.c (route decision engine). Lesson: a small, security-focused codebase with a privilege-separated session process is a strong security posture — applied in §22, §25 T-4. Pitfall: OpenBGPD's single-threaded RDE caps throughput; we accept per-peer concurrency instead (P2, §6).
  • Quagga (Quagga-project, predecessor to FRR): bgpd/bgp_route.c (best-path tie-breakers). Lesson: the exact ordering of the ten RFC 4271 §9.1 tie-breakers, applied in §16 (Best-Path Decision Process). Pitfall: Quagga's historical CVEs in variable-length attribute parsing (§26 FM-1) are applied as the rationale for Rust (§1) and for strict length-field validation (I4, applied in §7).

Glossary (§39) · 49 terms · site-wide glossary

Adj-RIB-In
: per-peer, per-(AFI,SAFI) table of received routes, pre-import-policy (§8.3).
Adj-RIB-Out
: per-peer, per-(AFI,SAFI) table of routes to advertise, post-export-policy (§8.3).
AFI
: Address Family Identifier (e.g., 1 = IPv4, 2 = IPv6, RFC 4760).
AS
: Autonomous System, an independently routed network under one administrative control.
AS_PATH
: the path-vector attribute listing every AS a route has traversed (§8.2).
AS_SET
: an unordered AS group, produced by route aggregation; counts as length 1 in best-path (I3).
AS_SEQUENCE
: an ordered AS list, the common case for AS_PATH segments.
AS_CONFED_SEQUENCE / AS_CONFED_SET
: confederation-internal AS_PATH segment types (RFC 5065).
BFD
: Bidirectional Forwarding Detection, a sub-second liveness protocol (hook only, §39 deferred full impl).
BGP
: Border Gateway Protocol, the inter-domain path-vector routing protocol (RFC 4271).
BGPsec
: RFC 8205's cryptographic AS_PATH signing extension (deferred, §38).
CLUSTER_LIST
: route-reflector loop-prevention attribute (§8.2, I8).
COMMUNITY
: a 32-bit policy tag attribute (RFC 1997, §8.2).
Confederation
: an AS split into member sub-ASes appearing as one AS externally (RFC 5065).
eBGP
: External BGP, a session between routers in different ASes.
Extended Community
: a 64-bit typed policy tag (RFC 4360, §38 deferred usage).
FIB
: Forwarding Information Base, the kernel/hardware forwarding table (§23).
Flowspec
: BGP-carried traffic-filtering rules (RFC 5575, deferred §38).
FSM
: Finite State Machine, RFC 4271 §8's six-state session lifecycle (§8.1, §14).
GR
: Graceful Restart, RFC 4724's session-loss churn-avoidance mechanism (§20).
GTSM
: Generalized TTL Security Mechanism, an off-path attack defense (RFC 5082, §14).
Hold Timer
: the negotiated session-liveness timeout; expiry transitions the FSM to Idle (§8.1).
iBGP
: Internal BGP, a session between routers within the same AS.
IGP
: Interior Gateway Protocol (OSPF, IS-IS); supplies the IGP-cost tie-breaker input (§8.4).
Keepalive
: the periodic liveness message resetting the peer's Hold Timer (§8.1).
Large Community
: a 96-bit policy tag solving the 16-bit-AS Community limit (RFC 8092).
LOCAL_PREF
: an iBGP-only per-route preference attribute; higher wins in best-path (§8.2, §8.4).
Loc-RIB
: the per-(AFI,SAFI) authoritative post-import-policy, post-best-path route table (§8.3).
MED
: Multi-Exit Discriminator, an inter-AS-boundary tie-breaker scoped to same-upstream-AS (§8.4, I13).
MP-BGP
: Multiprotocol BGP, RFC 4760's generalization of BGP to any (AFI,SAFI) family.
NLRI
: Network Layer Reachability Information, the prefix list carried in an UPDATE (§8.2).
NEXT_HOP
: the egress address attribute for a route (§8.2; IPv6/other families use MP_REACH_NLRI's next-hop).
NOTIFICATION
: the BGP message type signaling a session-terminating error (§8.2, §11).
OPEN
: the BGP session-initiation message carrying capabilities (§8.2, §11).
ORIGIN
: the route-origin-type attribute (IGP/EGP/Incomplete, §8.2, §8.4).
ORIGINATOR_ID
: the route-reflector-injected attribute identifying the originating router (§8.2, I7, I8).
Path attribute
: any of the RFC 4271 §4.3 route-metadata fields carried in an UPDATE (§8.2).
Patricia trie
: the radix-tree structure used for longest-prefix-match RIB lookup (ADR-06, §11).
Prefix
: an IP address plus a mask length, the unit of routing (§11).
RIB
: Routing Information Base, the general term covering Adj-RIB-In/Loc-RIB/Adj-RIB-Out (§8.3).
Route Reflector (RR)
: an iBGP router that relaxes the no-iBGP-to-iBGP-reflection rule for its clients (§19).
Route-flap damping (RFD)
: RFC 2439's penalty-based route-oscillation suppression mechanism (§21).
RPKI
: Resource Public Key Infrastructure, the cryptographic basis for origin validation (RFC 6480, §22).
RTR
: RPKI-to-Router protocol, the cache-distribution protocol this router consumes as a client (RFC 8210, §22).
SAFI
: Subsequent Address Family Identifier, refines an AFI to a specific route type (e.g., unicast vs VPN).
Split-horizon
: the rule that a route is never re-advertised to the peer it was learned from (§8.3, I6).
Stable Paths Problem
: Griffin & Wilfong's formalization of when BGP-like policy configurations converge (§5, §36).
TCP-MD5
: the TCP option authenticating BGP sessions via a shared key (RFC 2385, §14).
UPDATE
: the BGP message type carrying route announcements and withdrawals (§8.2, §11).
