Six load-bearing properties. First, the Adj-RIB-In is the per-peer, per-AFI "as received" record — a trust boundary between an untrusted peer and this router's decision logic; nothing downstream of it trusts peer input directly. Second, the filter engine is the only mutation point between Adj-RIB-In and Loc-RIB (import) and between Loc-RIB and Adj-RIB-Out (export) — a concurrency boundary is not needed here because the filter engine is pure (I9, §7). Third, Loc-RIB is the single per-AFI/SAFI authoritative table; best-path selection (§16) is a pure function over its per-prefix candidate set. Fourth, the FIB programmer is a protocol boundary: it consumes a "best route changed" event stream and is fully decoupled from BGP session state — it can be swapped for a mock backend (bgp-fib-mock) in conformance tests without touching any BGP logic. Fifth, each peer session is an isolated concurrency boundary (one task, one channel pair) so a single flapping/hostile peer cannot corrupt another peer's state — only Loc-RIB and the filter engine are shared, behind short critical sections. Sixth, the persistence boundary is intentionally absent in Phase 0-11: all RIB state is in-memory and rebuilt from peer re-establishment; Phase 12's conformance suite treats this as an explicit design choice (ADR-14, §9), not an oversight.

8. Domain Model

8.1 The BGP Finite State Machine (RFC 4271 §8)

Six states: Idle → Connect → Active → OpenSent → OpenConfirm → Established. The transition table below covers the load-bearing subset (full table has 28 events × 6 states; the remainder are symmetric error/stop handling collapsed into the _ → Idle rows).

State      | Event                    | Next State  | Actions
-----------|--------------------------|-------------|----------------------------
Idle       | ManualStart/AutoStart    | Connect     | StartConnectRetryTimer, InitiateTCP
Connect    | Tcp_CR_Acked/Confirmed   | OpenSent    | StopConnectRetryTimer, SendOPEN, StartHoldTimer(240)
Connect    | ConnectRetryTimer_Expire | Connect     | RestartConnectRetryTimer, InitiateTCP
Connect    | TcpConnectionFails       | Active      | RestartConnectRetryTimer
Active     | Tcp_CR_Acked/Confirmed   | OpenSent    | StopConnectRetryTimer, SendOPEN, StartHoldTimer(240)
Active     | ConnectRetryTimer_Expire | Connect     | RestartConnectRetryTimer, InitiateTCP
OpenSent   | BGPOpen                  | OpenConfirm | SendKEEPALIVE, StartKeepaliveTimer, negotiate HoldTime (I13n/a)
OpenSent   | BGPHeaderErr/OpenMsgErr  | Idle        | SendNOTIFICATION, ReleaseResources
OpenSent   | HoldTimer_Expires        | Idle        | SendNOTIFICATION(HoldTimerExpired)
OpenConfirm| KeepAliveMsg             | Established | SyncRIB (send full initial UPDATE set)
OpenConfirm| NotifMsg/HoldTimerExpire | Idle        | ReleaseResources
Established| UpdateMsg                | Established | ProcessUpdate → RIB pipeline (§8.3)
Established| KeepAliveMsg             | Established | RestartHoldTimer
Established| HoldTimer_Expires        | Idle        | SendNOTIFICATION(HoldTimerExpired), WithdrawAllRoutes
Established| UpdateMsgErr             | Idle        | SendNOTIFICATION(UpdateMessageError), WithdrawAllRoutes
any        | TcpConnectionFails       | Idle        | ReleaseResources, WithdrawAllRoutes
any        | unhandled (State,Event)  | Idle        | SendNOTIFICATION(FsmError) — I10 forbids reaching this row

Collision detection (RFC 4271 §6.8): when two TCP connections to the same peer race (both sides open simultaneously), the connection whose initiator has the higher BGP Identifier wins; the other is closed with Cease/ConnectionCollisionResolution.

Worked example. Peer AS 64512, local AS 64500, both configured with Hold Time 90s. ManualStart fires → Connect, TCP SYN sent. TCP handshake completes → Tcp_CR_Acked → OpenSent, our OPEN sent (Version=4, MyAS=64500, HoldTime=90, BGPID=10.0.0.1), local HoldTimer armed at 240s (interim value until negotiation completes). Peer's OPEN arrives (MyAS=64512, HoldTime=90, BGPID=10.0.0.2) → BGPOpen event → OpenConfirm; negotiated Hold Time = min(90,90) = 90s, Keepalive = 30s; KEEPALIVE sent. Peer's KEEPALIVE arrives → KeepAliveMsg → Established; SyncRIB sends the full initial Adj-RIB-Out. Steady state: KEEPALIVE every 30s resets the 90s hold timer on each side.

Malformed-input example. Peer sends an OPEN with Version=3 → BGPOpen event evaluated, version check fails → BGPOpenMsgErr → Idle, NOTIFICATION(OpenMessage, subcode UnsupportedVersionNumber, data = supported version 4) sent, TCP connection closed, connect-retry timer restarts per configured backoff.

Failure-path example. Session Established, peer stops sending KEEPALIVE (process hang on the peer side). Local HoldTimer (90s) expires with no KEEPALIVE/UPDATE received → HoldTimer_Expires → Idle; NOTIFICATION(HoldTimerExpired) sent (best-effort, TCP may already be dead); every route in that peer's Adj-RIB-In is withdrawn, triggering best-path re-selection for every affected prefix (I12 convergence budget applies per-prefix).

8.2 The UPDATE Message and Path Attributes (RFC 4271 §4.3)

UPDATE wire layout:
+------------------------+
| Withdrawn Routes Len(2)|
| Withdrawn Routes (var) |  each: (prefix-len:1, prefix-bytes:var)
| Total Path Attr Len (2)|
| Path Attributes (var)  |  see attribute layout below
| NLRI (var)             |  each: (prefix-len:1, prefix-bytes:var)
+------------------------+

Path attribute layout:
+------------------------+
| Flags (1)  | TypeCode(1)|  flags: Optional|Transitive|Partial|ExtLen
| Length (1 or 2, per ExtLen flag)                     |
| Value (var, per TypeCode)                            |
+------------------------+
Type Attribute Category Semantics
1 ORIGIN well-known mandatory 0=IGP, 1=EGP, 2=Incomplete; I13-adjacent tiebreak input
2 AS_PATH well-known mandatory segments: 1=AS_SET, 2=AS_SEQUENCE, 3=AS_CONFED_SEQUENCE, 4=AS_CONFED_SET (RFC 5065)
3 NEXT_HOP well-known mandatory IPv4 egress address (IPv4 unicast only; else via MP_REACH_NLRI)
4 MULTI_EXIT_DISC optional non-transitive u32, lower wins, only same-upstream-AS (I13)
5 LOCAL_PREF well-known (iBGP only) u32, higher wins, never sent eBGP
6 ATOMIC_AGGREGATE well-known discretionary zero-length flag: do not de-aggregate
7 AGGREGATOR optional transitive (AS:2/4, router-id:4) of the aggregator
8 COMMUNITY (RFC 1997) optional transitive list of (AS:2, value:2) policy tags
9 ORIGINATOR_ID optional non-transitive RR-injected; loop defense (I8)
10 CLUSTER_LIST optional non-transitive RR-injected list of cluster-ids; loop defense (I8)
14 MP_REACH_NLRI (RFC 4760) optional non-transitive (AFI, SAFI, next-hop, NLRI) for non-IPv4-unicast families
15 MP_UNREACH_NLRI (RFC 4760) optional non-transitive (AFI, SAFI, withdrawn NLRI); zero-NLRI = GR end-of-RIB (§20)
16 EXTENDED_COMMUNITIES (RFC 4360) optional transitive 8-byte typed tags (route-target, etc.), deferred use (§38)
17 AS4_PATH (RFC 6793) optional transitive 4-byte-AS carrier for legacy 2-byte peers
18 AS4_AGGREGATOR (RFC 6793) optional transitive 4-byte-AS aggregator carrier
32 LARGE_COMMUNITY (RFC 8092) optional transitive (AS:4, fn:4, param:4) — solves 16-bit-AS community limit

Attribute parsing pitfalls (I4). The Extended-Length flag (bit 4 of the flags byte) decides a 1-byte vs 2-byte length field; misreading it truncates or overruns the attribute. The attribute type occupies only the low 7 bits (bit 7 reserved). The Partial flag, once set by any AS along the path, is propagated unchanged, never cleared. An attribute with the Optional flag clear that this router does not recognize is a NOTIFICATION-triggering error (well-known attributes must be known); an unrecognized Optional-Transitive attribute is retained and re-advertised with Partial set; an unrecognized Optional-Non-transitive attribute is silently dropped.

Worked example (UPDATE decode). Peer AS 64512 sends an UPDATE advertising 203.0.113.0/24 with ORIGIN=IGP, AS_PATH=(SEQUENCE [64512]), NEXT_HOP=198.51.100.1, MED=100, COMMUNITY=[(64512,100)]. Decode produces one Route { prefix: 203.0.113.0/24, attrs: {...}, source_peer: 64512 }; inserted into that peer's Adj-RIB-In (§8.3); triggers import-policy evaluation (§8.5) and, if accepted, a best-path re-run for that prefix (§8.4).

Malformed-input example. The same UPDATE but with Total Path Attribute Length field claiming 40 bytes while only 30 bytes remain in the message: decode fails length validation (I4) before any attribute is parsed → NOTIFICATION(UpdateMessage, subcode MalformedAttributeList) → FSM UpdateMsgErr → session reset, full Adj-RIB-In withdrawal for that peer.

Failure-path example. An UPDATE contains AS_PATH = SEQUENCE [64512, 64500] where 64500 is this router's own AS: I1 rejects the route at Adj-RIB-In insert (loop detection) before it ever reaches Loc-RIB; the withdrawal-vs-acceptance decision is logged with reason loop_own_as (telemetry bgp_loop_reject_total).

8.3 RIB Model: Adj-RIB-In → Loc-RIB → Adj-RIB-Out

Three logical tables per (AFI, SAFI), per §3's pipeline:

  • Adj-RIB-In (per peer): routes as received, pre-import-policy — the trust boundary (§3).
  • Loc-RIB: the per-AFI/SAFI authoritative table; one entry per prefix holding the current best route plus all surviving candidates (post-import-policy, pre-best-path-elimination).
  • Adj-RIB-Out (per peer): routes to advertise to that peer, post-export-policy; the basis for implicit-withdraw semantics (a new UPDATE for a prefix supersedes the prior one without an explicit withdraw).
Prefix lifecycle state machine (per (peer, prefix)):
  Absent --UPDATE(nlri)--> AdjRibIn::Present --import accept--> LocRib::Candidate
  LocRib::Candidate --best-path win--> LocRib::Best --export accept--> AdjRibOut::Advertised
  LocRib::Candidate --best-path loss--> LocRib::Candidate (retained, not advertised)
  AdjRibIn::Present --WITHDRAW/session-reset--> Absent --triggers--> LocRib re-selection

Worked example. Prefix 203.0.113.0/24 received from peers A (LOCAL_PREF 100) and B (LOCAL_PREF 200). Both pass import policy → both become LocRib::Candidate. Best-path (§8.4) picks B's route on LOCAL_PREF (tie-break 1) → B's route is LocRib::Best; A's route remains LocRib::Candidate (retained for fast failover if B withdraws). Export policy runs for every peer other than B (split-horizon, I6) and for B's own re-advertisement rules; Adj-RIB-Out entries generated.

Malformed-input example. A WITHDRAW for 203.0.113.0/24 arrives from peer C, who never advertised that prefix (no matching Adj-RIB-In entry): per RFC 4271, this is silently ignored — not an error — logged at debug level only (bgp_spurious_withdraw_total).

Failure-path example. Peer B's session resets (hold-timer expiry, §8.1): all of B's Adj-RIB-In entries are withdrawn atomically; Loc-RIB re-runs best-path for every affected prefix; 203.0.113.0/24 falls back to A's route (LOCAL_PREF 100), and Adj-RIB-Out for every other peer regenerates an UPDATE reflecting the new best route (implicit withdraw of the old, per Adj-RIB-Out bookkeeping, §26 FM-5).

8.4 Best-Path Decision Process (RFC 4271 §9.1)

Ten deterministic tie-breakers, applied in order until one produces a strict winner:

1. Highest LOCAL_PREF                         (P9, I2)
2. Locally originated (network/aggregate)      wins over learned
3. Shortest AS_PATH length (AS_SET counts 1)   (I3)
4. Lowest ORIGIN (IGP < EGP < Incomplete)
5. Lowest MED, only same immediate-upstream AS (I13)
6. eBGP-learned over iBGP-learned
7. Lowest IGP cost to NEXT_HOP (snapshotted, P1)
8. Lowest router-ID (or ORIGINATOR_ID if present, RR case)
9. Shortest CLUSTER_LIST (route-reflection case, §19)
10. Lowest peer TCP source address              (total order, P9)

Worked example. Candidates for 203.0.113.0/24: Route X (LOCAL_PREF 100, AS_PATH len 3, eBGP), Route Y (LOCAL_PREF 100, AS_PATH len 2, eBGP). Tie-break 1 ties (100=100); tie-break 2 ties (neither local); tie-break 3 resolves: Y (len 2) wins.

Malformed-input example. A candidate route with an absent MED (no MULTI_EXIT_DISC attribute) is treated as MED=0 (the RFC-4271 default reading, ADR-16), not as "missing → skip tie-break 5" — this distinction is a common implementation divergence (BIRD/FRR agree on default-0; documented explicitly to keep interop, §24).

Failure-path example. Two candidates tie through tie-break 9 (identical router-ID due to operator misconfiguration, §26 FM-3): tie-break 10 (peer TCP source address) is total and always resolves — I2 guarantees no unresolved tie ever reaches the FIB, even under this misconfiguration; the resulting choice is stable but arbitrary from the operator's perspective, which is why router-ID uniqueness is a Threat-Model item (T-9, §25).

8.5 Route Policy (Import/Export Filter Engine)

Grammar (EBNF), the typed filter DSL:

filter      = "filter" ident "{" stmt* "}" ;
stmt        = if_stmt | assign_stmt | call_stmt | terminal_stmt ;
if_stmt     = "if" cond "then" stmt_block ["else" stmt_block] ;
cond        = aspath_match | community_match | numeric_cmp ;
aspath_match= "bgp_path" "~" aspath_pattern ;
numeric_cmp = field ("<"|">"|"=") literal ;
assign_stmt = field "=" expr ;
call_stmt   = field "." method "(" args ")" ;
terminal_stmt = "accept" | "reject" ;
field       = "bgp_local_pref" | "bgp_med" | "bgp_community"
            | "bgp_origin" | "bgp_next_hop" ;

Semantics table (worked example as data, not as executable script):

Rule Condition Action
R1 bgp_path matches pattern [* 64513 *] reject (deny transit via AS 64513)
R2 bgp_med > 1000 set bgp_local_pref = 50 (deprioritize)
R3 (unconditional, last rule) add community (64500,100), accept

Malformed-input example. A filter referencing an undeclared field (bgp_locl_pref, a typo) fails at parse time (P3) with a type-checker error naming the unknown field — the route stream is never touched, unlike a runtime-typed config that would silently no-op.

Failure-path example. A filter with no reachable accept/reject on some execution path (e.g., an if with no else and no trailing terminal) is rejected at parse time by an exhaustiveness check (ADR-04 extension); this closes the "falls through, ambiguous default" failure mode present in the original draft of this design (corrected during this revision).
