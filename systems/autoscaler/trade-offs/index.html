Decisions (§9) · 28 ADRs

001

Implementation language

Chosen

Rust 2021, MSRV 1.78

Rejected

Go (HPA/CA language), Python, MATLAB/control DSL

When the rejected choice is right

Go wins when you must contribute back to upstream HPA/Cluster-Autoscaler (same language, shared client-go) or staff a team already fluent in it; the GC pause is irrelevant at a 15 s sync_period.

Why: Sum types model policy/decision/scale-direction precisely; exhaustive match totalizes the control-law branches; no GC tail latency on the tick; memory-safe metric hot path. Go = GC + weak enums + float footguns; Python = no determinism + GIL; MATLAB = not a daemon.

002

Async runtime

Chosen

Tokio (multi-thread)

Rejected

async-std, smol, thread-per-scraper, blocking sync

When the rejected choice is right

Thread-per-scraper (blocking) wins at ≤a handful of sources where simplicity beats an async runtime's binary/cognitive cost — a single-target ascaled with 2 scrapes needs no executor.

Why: One runtime drives N concurrent MetricSource::fetch + the periodic loop + the actuator; mature timer/select!/cancellation; de-facto ecosystem.

003

Workspace decomposition

Chosen

8 crates (asc-metrics/-policy/-control/-target/-predict/-cluster/-api/-cli)

Rejected

Single crate; metrics+policy merged; control+target merged

When the rejected choice is right

A single crate wins for a throwaway/prototype or a teaching artifact where compile-time crate isolation buys nothing and the build-graph overhead slows iteration.

Why: Trust/concurrency/persistence boundaries map to crate edges: asc-policy/asc-predict are pure std → fuzzable in isolation; I/O crates pull tokio; asc-cli is the only bin.

004

Core control law

Chosen

HPA proportional ratio ceil(ready * (cur/target)) over READY replicas

Rejected

PID controller (cf. 289), additive/integral control, RL/bandit

When the rejected choice is right

PID/continuous control wins for a continuous setpoint actuator (CPU-frequency governor, queue-admission rate, thermal control) where the manipulated variable is real-valued and integral action eliminates steady-state error — see project 289.

Why: Replica counts are integer, discrete, level-triggered — the ratio law is proven, needs no gain tuning, reaches target in ~1 step. A PID integral term induces windup/overshoot on a quantized actuator with actuation lag; the tolerance band (ADR 010) is the deadband a PID would add anyway.

005

Metric arithmetic

Chosen

Decimal (fixed-point) for all desired math

Rejected

f64, f32, rational/bignum

When the rejected choice is right

f64 wins when the math is genuinely a heavy numeric kernel (the forecaster doing FFT/regression over thousands of points) where SIMD float throughput matters and the result is re-quantized to an integer replica count anyway.

Why: Determinism: identical input ⇒ byte-identical Decision, replayable. f64 ratio/ceil is platform-/order-sensitive near tolerance edges → nondeterministic flap.

006

Ready-replica accounting

Chosen

Average over READY replicas only; unready excluded

Rejected

Average over all replicas; include Pending

When the rejected choice is right

Counting all replicas is acceptable when readiness is instantaneous (no warm-up, e.g. a stateless function with sub-second cold start) so unready never meaningfully dilutes the average.

Why: A warming replica reports ~0 load; counting it deflates the average and double-counts the in-flight scale-up → overshoot/oscillation.

007

Multi-metric combine

Chosen

Final desired = MAX of per-metric desireds

Rejected

Sum, weighted average, min, priority-first

When the rejected choice is right

Priority-first / weighted wins when one metric is authoritative and others advisory (cost-capped scaling: a budget metric should cap, not be MAX-ed) — there MAX is wrong and you want min/priority.

Why: Must satisfy the most-demanding metric; MAX is monotone + safe; averaging under-provisions on a spike. Stale excluded (ADR 008).

008

Missing/stale policy

Chosen

Fail-safe: exclude; missing MUST NOT scale-DOWN; total staleness → HOLD + degraded Condition

Rejected

Treat missing as 0; last-known-value forever; scale on partial data

When the rejected choice is right

Last-known-value wins for a slow-moving, highly-reliable metric (daily-batch backlog) where a brief gap is genuinely safe to bridge and holding adds harmful lag.

Why: "Can't prove we can shrink" → never shrink on bad data; never panic (ADR 022).

009

Stabilization asymmetry

Chosen

DOWN = MAX over down-window (300 s); UP = MIN over up-window (0 s)

Rejected

Symmetric windows; EMA both ways; none

When the rejected choice is right

Symmetric windows win for a workload where scaling down is as cheap/safe as up (stateless, instant drain) and surplus capacity is the dominant cost — then slow-down is pure waste.

Why: Asymmetry matches cost/risk: react fast up, shrink slowly only if the most aggressive recent rec agreed.

010

Tolerance band

Chosen

Default 0.1; `

Rejected

ratio−1

When the rejected choice is right

0.0 (no deadband); adaptive only

Why: ≤tol` ⇒ NoOp

011

Anti-flap secondary

Chosen

Cooldown + RateLimit; clamp rate AFTER stabilization

Rejected

Cooldown only; rate-limit only; token-bucket

When the rejected choice is right

Token-bucket smoothing wins when scaling actions have a hard external quota (cloud API call budget) and you want to amortize bursts smoothly rather than hard-block a direction.

Why: Layered defense: cooldown blocks same-direction churn; rate-limit caps Δ/period. Order: ratio → MAX → stabilize → bounds clamp → rate clamp → cooldown.

012

Ingestion interface

Chosen

MetricSource trait (resource/custom/external)

Rejected

Built-in Prometheus-only; hardcoded sources

When the rejected choice is right

A built-in Prometheus client wins for a closed appliance shipped against exactly one TSDB, where the trait's indirection adds no value and a direct PromQL client is simpler.

Why: NON-GOAL: not a monitoring system — it consumes. Trait keeps backends swappable + the loop source-agnostic.

013

Time-series store

Chosen

Per-Series fixed RingBuffer<Sample> + windowed Aggregation

Rejected

Embedded TSDB (sled/RocksDB), unbounded Vec, query Prometheus each tick

When the rejected choice is right

Query the TSDB each tick wins when an external Prometheus already holds long, high-fidelity history and the autoscaler should be stateless — at the cost of a query-latency-bound tick + TSDB availability coupling.

Why: Only a bounded recent window is needed; ring = O(1) insert, bounded memory, no compaction. Embedded TSDB = scope creep.

014

Actuation interface

Chosen

ScalableTarget trait; set_scale IDEMPOTENT; level-triggered

Rejected

Fire-and-forget delta; edge-triggered; assume write applied

When the rejected choice is right

Edge-triggered delta wins on a perfectly reliable, totally-ordered command bus (a single in-process actuator with synchronous acks) where re-reading state each tick is pure overhead.

Why: Never assume the last write took → re-read ScaleStatus each tick (K8s controller model; cross-link 268). Idempotent set_scale makes retries safe.

015

Target drivers

Chosen

Process-pool, Deployment→268, node-group

Rejected

Single hardcoded target; shell-out only

When the rejected choice is right

A single hardcoded target wins for a purpose-built scaler bound to exactly one runtime (a managed service scaling only its own workers) where pluggability is dead weight.

Why: Trait + 3 drivers proves the abstraction; Deployment adapter is the HPA-equivalent path (Phase 10).

016

Cluster scale-UP

Chosen

Bin-packing Simulator: smallest ScaleUpPlan add that schedules pending

Rejected

Fixed +1 step; utilization-threshold; ML predictor

When the rejected choice is right

Utilization-threshold (+1 when >X%) wins for a homogeneous pool with uniform pods where bin-pack simulation is overkill and a simple high-watermark trigger converges fine.

Why: Demand-driven: add only nodes that let pending work schedule; pick cheapest via sim (Cluster Autoscaler model).

017

Cluster scale-DOWN

Chosen

ScaleDownCandidate iff underutilized AND reschedulable AND budget allows → cordon+drain

Rejected

Utilization-only; immediate terminate; no drain

When the rejected choice is right

Immediate terminate (no drain) wins for stateless, interruption-tolerant workloads on spot/preemptible nodes that are designed to vanish — drain ceremony adds latency for no safety gain.

Why: Removing a node is a disruption; prove movability + respect budgets, cordon then drain.

018

Forecasting models

Chosen

Ewma + HoltWinters; Forecast{value,confidence}; low-conf ⇒ reactive

Rejected

ARIMA, Prophet, LSTM/neural, Kalman

When the rejected choice is right

ARIMA/ML (Prophet, LSTM) wins when load has complex multi-seasonal/holiday structure and a dedicated forecasting team + offline training pipeline exists — accuracy then justifies the opacity (AWS predictive uses ML).

Why: Proven, cheap, explainable, deterministic (cf. Scryer/AWS predictive). EWMA = drift, HW = diurnal seasonality. ML = heavy/opaque/un-replayable.

019

Decision durability

Chosen

append-only replayable DecisionLog

Rejected

Mutable status only; log lines; external DB

When the rejected choice is right

An external DB / event bus wins at fleet scale where many ascaleds must centralize audit for cross-target correlation and the local-file append-log can't serve org-wide queries.

Why: Audit + post-incident replay; append-only ⇒ deterministic re-derivation. The only durable state besides AutoscalerStatus.

020

Default actuation

Chosen

Recommend-only / dry-run is DEFAULT; actuation opt-in

Rejected

Actuate-by-default

When the rejected choice is right

Actuate-by-default wins for a low-stakes, well-understood, frequently-redeployed scaler (a dev-cluster autoscaler) where the dry-run soak ceremony costs more than the rare misconfiguration.

Why: High blast radius: ship safe. Operators observe before granting actuation authority; guardrails on by default.

021

Clock

Chosen

Injected Timestamp; no wall-clock/RNG in math

Rejected

SystemTime::now() in math; ambient time

When the rejected choice is right

Ambient SystemTime is acceptable for a quick script with no replay/test-determinism requirement — there injection is needless plumbing.

Why: Determinism + replay + virtual-clock sim (Phase 12). tick(now) takes time as a param.

022

Error model

Chosen

Typed errors via thiserror; the loop NEVER panics

Rejected

unwrap/panic, stringly, anyhow in libs

When the rejected choice is right

anyhow/unwrap wins in the asc-cli binary and one-shot tooling where a fail-fast panic with a backtrace is the correct, simplest behavior (no loop to wedge).

Why: A panic in the loop = stuck autoscaler = outage. Every fallible path returns typed error; degrade (HOLD), don't abort.

023

Serde + config

Chosen

serde; YAML policies; JSON for API/log wire

Rejected

TOML policies, custom parser, protobuf-only

When the rejected choice is right

Protobuf wins when policies are machine-generated and exchanged over a typed gRPC control plane at scale — schema-evolution + wire compactness beat human-authorability.

Why: YAML matches K8s operator muscle memory; one serde derive across YAML/JSON.

024

Observability

Chosen

tracing spans + Prometheus endpoint

Rejected

log crate, println!, custom logger

When the rejected choice is right

The log crate wins for a tiny embedded build where the tracing subscriber's footprint isn't justified and flat lines suffice.

Why: Per-tick span correlation scrape→decide→actuate; exports its own loop health.

025

Testing strategy

Chosen

Virtual-clock Simulator + proptest properties

Rejected

Live integration only; wall-clock sleeps; example unit tests only

When the rejected choice is right

Live integration only wins for final pre-release acceptance against a real orchestrator, where fidelity to production beats the simulator's abstraction — used in addition, not instead.

Why: Injected clock replays days of load in ms; properties encode the LOCKED invariants as the done gate.

026

Fuzzing

Chosen

cargo-fuzz on control math + policy parse

Rejected

No fuzzing; random property inputs only

When the rejected choice is right

Skipping fuzz and relying on property tests alone is acceptable for a pure, total, small-input-space function already exhaustively covered by a differential corpus.

Why: Fuzz the safety-critical math + YAML parse for panics/overflow/clamp violations.

027

CI / supply chain

Chosen

GH Actions + MSRV job + cargo-deny

Rejected

Unpinned toolchain; no advisory gate; latest

When the rejected choice is right

A looser policy (no advisory gate) is tolerable for an internal-only tool behind a trusted registry mirror where supply-chain risk is bounded by the network.

Why: MSRV tested not commented; cargo-deny blocks vulnerable/incompatible/dup deps on a safety-critical daemon.

028

License

Chosen

Apache-2.0

Rejected

MIT, GPL, proprietary

When the rejected choice is right

GPL/AGPL wins when copyleft is the goal — forcing downstream forks of a hosted autoscaler to publish changes; proprietary wins for a closed commercial product.

Why: Patent grant + permissive; matches the K8s/CNCF ecosystem it models.

Alternative Architectures (Roads Not Taken)

Fundamentally different designs for the same problem; each with sketch, the regime where it wins, the real system that embodies it, and why 269 rejected it.

ALT-1 — PID / continuous control loop. Treat replicas as a continuous manipulated variable; run a tuned proportional-integral-derivative controller against the metric error.

error = target - current ─► PID(Kp,Ki,Kd) ─► Δcapacity ─► actuate ─► (loop)
                                   ▲ integral term eliminates steady-state error

Wins: a continuous, real-valued actuator with no quantization and tolerable overshoot — CPU-frequency/thermal governors, admission-rate control. Embodied by: classical control systems (and project 289's PID toolkit). Rejected because: replica counts are discrete and integer; integral windup + derivative noise cause overshoot/oscillation on a quantized actuator with multi-tick actuation lag, and the proportional ratio already reaches target in ~1 step (ADR-004, MM1).

ALT-2 — Edge-triggered, event-sourced scaler. Drop the periodic loop; react to metric-threshold events (alarm crossed → emit a scale command), never re-reading full state.

metric stream ─► threshold alarm ─► scale event ─► command queue ─► actuator
                                            (no periodic reconcile, no re-read)

Wins: very low actuation latency and minimal idle work when events are reliable, totally-ordered, and exactly-once — a single-process in-memory autoscaler on a trusted bus. Embodied by: classic CloudWatch-alarm → ASG step actions (event-driven). Rejected because: on a real distributed target, events are lost/reordered/duplicated; an edge-triggered scaler accumulates silent drift and never self-heals. 269 is level-triggered: re-read truth each tick, reconcile observed→desired (P6.5, Inv-7, MM5).

ALT-3 — Centralized control plane (stateless workers + shared store). One global scheduler owns all autoscaling state in a replicated store; thin stateless workers execute decisions; coordination via the store.

                ┌──────── global decision store (Raft) ────────┐
   workers ───► │ targets · policies · decisions · leases       │ ◄─── workers
                └──────────────────────────────────────────────┘
                 every decision is a transaction on the store

Wins: a very large multi-tenant fleet needing org-wide policy, cross-target coordination, and a single audit plane (thousands of targets across regions). Embodied by: cloud-provider managed autoscaling control planes (AWS Application Auto Scaling shape). Rejected because: it adds consensus on the hot path (latency + operational weight) for a problem that is embarrassingly parallel per target — 269 keeps state per-target-local and shards by target_ref, paying coordination cost only at lease handover (Scalability), not per tick.

ALT-4 — Pure forecast-driven (open-loop) provisioning. Provision entirely from a forecast model; no reactive ratio loop — capacity follows the predicted curve.

history ─► forecaster (ML/seasonal) ─► predicted load(t+h) ─► provision(t) ─► (no feedback on error)

Wins: highly predictable, strongly seasonal load with long warm-up where reacting is always too late, and a mature forecasting/ML team — large consumer services with stable diurnal/weekly patterns. Embodied by: Netflix Scryer / AWS predictive scaling (in their pure form). Rejected because: an open loop has no fail-safe — a regime change or forecast error provisions wrong with nothing to catch it. 269 keeps prediction strictly additive over an authoritative reactive floor with a confidence gate (P6.11, Phase 8 ## 20, MM9).
