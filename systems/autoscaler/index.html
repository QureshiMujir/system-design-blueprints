3.2 Component Responsibilities (one box per paragraph)

asc-metrics — ingestion + aggregation pipeline

Owns MetricSource and turns raw backend reads into one frozen MetricsSnapshot per tick: Series (per-label ring of Sample{ts,value:Decimal}), Aggregation over a Window (avg/sum/rate/p50/p90/p99/max), MetricsSnapshot{at, per_metric, stale}. Bounded history in fixed-cap rings (downsample on overflow → constant memory/series); last_scrape_age() drives staleness. Invariant: snapshot immutable + complete for one tick — every MetricId is in per_metric or stale, never silently dropped; aggregation never reads ts > snapshot.at. Phase 1 (## 13: trait/rings/agg/downsample/staleness/synthetic+resource), Phase 6 (## 18: custom+external).

asc-policy — declarative policy model + desired-value math

Owns Policy/Bounds + the four ScalingRule kinds, per-metric TargetType + tolerance, and desired_for_target_tracking(...) -> u32 (HPA ratio, ceil). Invariant: min<=max + sane targets validated at load (never at tick); pure (no I/O/clock/RNG → deterministic). Phase 2 (## 14: model/TargetTracking/ratio/validation), Phase 7 (## 19: Step+Scheduled+precedence), Phase 8 (## 20: Predictive).

asc-control — the central control loop / reconciler

Owns Controller, Decision, ScaleDirection, and the anti-flap trio StabilizationBuffer/Cooldown/RateLimit. tick(now) -> Result<Decision, ControlError>: per-metric HPA desired over READY → MAX → tolerance NoOp → stabilize (max-down/min-up window) → cooldown → rate-limit → clamp [min,max]. Invariants: deterministic, bounds always respected, missing/stale never scales DOWN (fail-safe). Phase 3 (## 15: ratio+tolerance+clamp), Phase 4 (## 16: anti-flap trio), Phase 6 (## 18: MAX+fail-safe), Phase 8 (## 20: blend).

asc-target — the scalable-target abstraction + actuators

Owns ScalableTarget, ScaleStatus{desired,current,ready}, ScaleSubresource: Decision.to → set_scale(desired), truth via scale_status(). Drivers: process-pool, Deployment→268 (scale subresource + pod metrics), node-group. Controller scales on ready (not current) → no double-count. Invariant: set_scale(n) IDEMPOTENT; level-triggered re-read each tick, never trust the last write. Phase 5 (## 17: trait/idempotent/readiness/process-pool/reactive E2E), Phase 10 (## 22: Deployment adapter + watch).

asc-predict — predictive + scheduled forecasting

Owns Forecaster, Forecast{value,confidence,horizon}, Ewma, HoltWinters. Consumes asc-metrics history → forward value+confidence; asc-control blends predicted vs reactive, falls back to reactive below confidence threshold — predicted may pre-warm UP but never overrides the reactive fail-safe. Invariant: pure/deterministic per observation sequence; low confidence cannot drive a DOWN. Phase 8 (## 20).

asc-cluster — the cluster autoscaler (node scaling)

Owns NodeGroup, NodeGroupProvider, ScaleUpPlan, ScaleDownCandidate, the bin-packing Simulator. Scale-up: pending/unschedulable demand → simulate against each NodeTemplate → smallest add that schedules. Scale-down: underutilized nodes whose workload reschedules elsewhere → cordon+drain respecting disruption budgets → set_size (IDEMPOTENT). Invariant: never drain unless all workload provably reschedules AND budgets allow; current within Bounds. Phase 9 (## 21).

asc-api — autoscaler API, status, and audit

Owns Autoscaler{spec,status}, AutoscalerStatus, ScalingEvent, the append-only DecisionLog. Out: queryable status, Conditions (e.g. Degraded on staleness), events, replayable audit, and the recommend-only/dry-run surface. Invariant: DecisionLog append-only + replay reproduces the same Decision sequence (pairs with determinism); the only durable state, stays small. Phase 11 (## 23: status/conditions/events/log/dry-run/guardrails).

ascaled / asctl — the drivers (asc-cli)

ascaled: long-running daemon — concurrent scrapers, tick on sync_period (serialized per target), persists asc-api state. asctl: operator CLI — apply/plan(dry-run)/status/history. Invariant: asctl plan is side-effect-free and shares the exact tick code path as ascaled, so a dry-run matches the daemon. Phase 0 (## 12: skeletons + smoke test); both binaries grow per later phase (status/history by Phase 11).

8. Domain Model — Metrics, Policies, and the Control Law

The kernel of the autoscaler: how raw samples become a frozen MetricsSnapshot, how a Policy declares intent, and the exact, deterministic control law that maps (snapshot, policy, state) → Decision. Everything here is float-free (Decimal/fixed-point), clock-injected, RNG-free → replayable. Cross-links: metrics ingestion = asc-metrics (Phase 1, ## 13); control loop = asc-control (Phases 3–4, ## 15–## 16); actuation = asc-target (Phase 5, ## 17).

8.1 The metric model — Sample, Series, ring buffer, kinds, aggregation, window, staleness

Type spine (home asc-metrics): Sample{ts,value:Decimal}, Series{labels,ring}, MetricKind{Resource,Custom,External}, Aggregation{Avg,Sum,Rate,P50,P90,P99,Max}, Window{duration,resolution} — full signatures in §11.1.

MetricKind semantics (drives how current is computed, and the legal TargetType):

Kind Scope Source example current derivation Legal TargetType
Resource per-ready-replica cpu/mem of pods (via #268) sum(usage over READY) / ready → utilization vs request Utilization, AverageValue
Custom per-object req/s per pod, conn count sum(metric over READY) / ready AverageValue, Value
External global / off-target queue length, Kafka lag raw aggregate (NOT per-replica) AverageValue, Value
  • Resource util = usage/request (0..1+, the only Utilization-yielding kind). External is global → AverageValue ÷ ready, Value does not (never excludes unready).

Ring buffer (per Series): fixed-capacity, sized ceil(retention/resolution) (30 min @ 15 s = 120 slots), O(1) overwrite-oldest; ≤16 B/sample × 120 × cardinality (~19 MB @ 10k series); cap (10k) rejects new label-sets with CardinalityExceeded.

Aggregation over a Window ([now-duration, now] → one AggValue):

Agg Formula / rule Use
Avg / Sum Σvalue / n · Σvalue resource util · external totals
Rate (last − first)/Δt, counters only; reset (Δ<0) → segment-sum req/s, throughput
P50/P90/P99 nearest-rank percentile tail-sensitive custom metrics
Max max value burst-protective targets
  • Resolution = scrape interval; samples align to grid for p*/rate stability. Downsampling folds same-bucket samples by the series' agg (avg/sum/max) → bounded slots, no Rate double-count. Rate requires a counter (monotonic-with-reset); on a gauge → KindMismatch.

Staleness: last_scrape_age() = now − newest ts; stale when age > max(factor×resolution, min_staleness) (factor 3, min 60 s) → excluded + listed in stale; empty window (n=0) also stale.

8.2 Freezing a tick — the MetricsSnapshot

One tick(now) takes a single immutable read of all series → freezes MetricsSnapshot{at, per_metric: BTreeMap<MetricId,AggValue>, stale} (signatures §11.1; AggValue{value,ready,kind,agg}). The control law sees nothing else; mid-tick scrapes are invisible until next tick → determinism + replayability. Freeze (per policy metric): match Series by labels → aggregate over Window → staleness check → place in per_metric (live) or stale. ready captured from scale_status() at the SAME now so per-replica math and snapshot agree. Stored verbatim in Decision.metrics + DecisionLog → a tick replays from its snapshot alone.

8.3 The policy model — Policy, Bounds, the four rules, TargetType

Type spine (home asc-policy, signatures §11.2): Policy{target_ref,bounds,rules,sync_period}, Bounds{min,max}, ScalingRule{TargetTracking|Step|Scheduled|Predictive}, TargetTracking{metric,target,tolerance} (default tol 0.1), TargetType{Utilization(0..1)|AverageValue|Value}.

TargetType semantics (what target means, what current is compared to):

TargetType target current Ratio
Utilization(u) fraction 0..1 avg(usage/request) over ready current_util / u
AverageValue(v) per-replica total / ready (total/ready) / v
Value(v) absolute aggregate (not divided) total / v

Compact config — a target-tracking policy (YAML-ish):

target_ref: { kind: Deployment, name: web, via: orchestrator-268 }
bounds:      { min: 2, max: 20 }
sync_period: 15s
rules:
  - target_tracking:
      metric: cpu                          # Resource kind
      target: { utilization: 0.60 }        # 60%
      tolerance: 0.10                       # +/-10% no-op band
  - target_tracking:
      metric: requests_per_sec             # Custom kind
      target: { average_value: 50 }        # 50 rps per replica
      tolerance: 0.10
stabilization: { scale_down_window: 300s, scale_up_window: 0s }
cooldown:      { scale_up: 60s, scale_down: 300s }
rate_limit:    { up:   { pods: 4, percent: 100, period: 60s },
                 down: { percent: 10,            period: 60s } }

Validation (at parse; asc-policy::validate): min ≤ max, min ≥ 0, max ≥ 1; 0 < tolerance < 1; Utilization ∈ (0,1]; AverageValue/Value > 0; metric kind ↔ TargetType legal (table §8.1); cron parses; non-empty rules; sync_period ≥ 1s. Failure ⇒ PolicyError (rejected, never partially applied).

8.4 The control law — the full ordered pipeline

One tick runs this ordered, pure-given-(snapshot,state,now) pipeline (the typed-stage form is §7.2): (1) per-metric desired — ratio = current/target; |ratio−1|≤tolerance → desired_m = current_replicas (NoOp band) else ceil(ready × ratio); (2) step/scheduled — StepPolicy breach → ±delta, ScheduledPolicy overrides bounds in-window; (3) multi-metric MAX over live desired_m (stale/missing excluded; if it would imply DOWN → hold, fail-safe); (4) stabilization — DOWN = MAX over down-window (300 s), UP = MIN over up-window (0 s); (5) cooldown — blocked direction holds at current; (6) rate-limit clamp |desired−current| per period; (7) bounds clamp clamp(min,max) → Decision{from,to,direction,reason,metrics,at,recommended_only}.

The HPA proportional formula (LOCKED): desiredReplicas = ceil( readyReplicas × ( currentMetricValue / targetMetricValue ) ).

  • Over READY replicas (unready excluded from both the average and the multiplier → no double-count). Tolerance band (0.1) applied per-metric BEFORE the MAX. ceil, integer, Decimal (no drift); target==0 impossible (validation). Stabilization buffer holds (ts, recommended), read MAX-down/MIN-up (see §8.6 + Phase 4 ## 16).

8.5 Worked examples (exact arithmetic)

# current_replicas / ready metric current target ratio per-metric desired after pipeline direction
i 4 / 4 cpu util 0.90 0.60 1.50 ceil(4×1.50)=6 6 (≤max 20) Up
ii 6 / 6 cpu util 0.30 0.60 0.50 ceil(6×0.50)=3 6 held (max-over-300s window still 6) None (waits)
iii 5 / 5 cpu util 0.63 0.60 1.05 NoOp (|1.05−1|=0.05 ≤ 0.10) 5 None
  • (i) 90% vs 60% at 4 ready → up to 6 (up-window 0; +2 ≤ +4 cap). (ii) 30% vs 60% recommends 3, but the down-window (300 s) still holds a recent recommended=6 → MAX-over-window=6 → hold until it ages out (no premature shrink). (iii) ratio 1.05 in the ±0.10 band → NoOp.

Multi-metric MAX: cpu→6, rps→8 ⇒ max(6,8)=8. If rps is stale and would imply 3 (a shrink), it is excluded and the shrink suppressed (fail-safe).

8.6 State / decision transition table

Inputs: per-metric band status (within-band / breach-up / breach-down) × stabilization verdict (agrees / holds) × cooldown (open / blocked). Output: ScaleDirection.

Band status Stabilization Cooldown to vs from Direction Notes
within-band (all metrics) — — to = from None tolerance NoOp
breach-up agrees open to > from Up apply ceil ratio, then rate-limit/bounds
breach-up agrees blocked to = from None cooldown holds (recent up-scale)
breach-up min-window holds (lower recent rec) open to = from None up-window suppresses transient spike
breach-down agrees (max-window low) open to < from Down shrink permitted
breach-down holds (max-window high) open to = from None stabilization waits
breach-down agrees blocked to = from None scale-down cooldown
any metric stale ⇒ would shrink — — to = from None fail-safe: never shrink on missing data
desired > max — — to = max Up/None bounds clamp
desired < min — — to = min Up/Down bounds clamp

8.7 Step scaling and scheduled scaling

StepPolicy — breach magnitude (current−target) → additive delta over (lower, upper, delta) bands, e.g. steps: [{0,20,+1},{20,40,+2},{40,~,+4}] (open top). Example: target 60%, current 95% → breach 35 → [20,40) → +2. Additive (not ratio), bounded [min,max]; bypasses ceil-ratio but still passes stabilization→cooldown→rate→bounds.

ScheduledPolicy — cron window overrides Bounds (e.g. {cron:"0 8 * * MON-FRI", bounds:{min:10,max:40}} business-hours floor; evening {min:2,max:20}); inside the window schedule min/max replace base. A scheduled floor (min:10) forces scale-UP without a breach (pre-warm); overlapping windows → most-recently-started wins, ties → MAX(min)/MAX(max); applied in stage (7), never triggers DOWN below a reactive desired (stage-3 MAX dominates upward).

8.8 Malformed inputs and failure-path behavior

Failure Detection Behavior Surfaced as
No data / total staleness last_scrape_age > threshold, n=0 metric → stale; no scale-down; HOLD if all stale MetricsDegraded; ScalingEvent{applied:false}
One of N metrics stale per-metric staleness exclude from MAX; suppress any shrink it implied PartialMetrics
min>max / target ≤0 validate() at parse reject whole policy PolicyError::BoundsInverted/InvalidTarget
NaN/negative/non-finite sample ingest guard drop, do not store MetricError::InvalidSample + counter
desired out of [min,max] stage (7) clamp to bound reason: "clamped to min/max"
set_scale fails TargetError don't assume write took; retry next tick; record ScaleFailed; ScalingEvent{applied:false,error}
Non-monotonic ts ts < last seen reject sample MetricError::NonMonotonicTs
Cardinality explosion series count > cap reject new label-set MetricError::CardinalityExceeded

Invariants enforced here (Phase 12 ## 24): min≤to≤max always; stale-metric tick never decreases replicas; identical input ⇒ identical Decision; set_scale re-read each tick; no NaN/negative enters the ring or the control law.
