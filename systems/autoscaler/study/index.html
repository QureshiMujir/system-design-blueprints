Mental Models & First Principles

The compressed insights an expert holds. Each: model · what it predicts · the bug you write without it · where applied (resolving section).

MM1 — Stability is set by the guards, not the gain. The HPA ratio is trivial; stability comes from deadband + stabilization + cooldown + rate-limit. Predicts: incidents are guard-tuning, never the formula. Bug: "fixing flapping" by editing the ratio. Applied: P6.1, Phase 4 (## 16), Failure Modes F1.

MM2 — Absence of a signal is not a signal of absence. A missing/stale metric is unknown, not low; treating it as 0 is the #1 autoscaling outage. Predicts: any gap reaching the math scales to min mid-peak. Bug: "Prometheus blip → util 0 → scaled to min → cascade." Applied: P6.3, Inv-3, Phase 6 (## 18), Threat Model T2.

MM3 — Scaling is asymmetric: slow-up is an outage, slow-down is a cost. Up/down are not mirror ops; windows/cooldowns/rates differ. Predicts: symmetric tuning thrashes (fast down) or wastes (slow up). Bug: a 30 s dip sheds capacity that cold-starts under the returning wave. Applied: P6.6, ADR-009, Phase 4 (## 16).

MM4 — A new replica carries no load yet; count only ready. Dividing by all replicas deflates utilization and double-counts the in-flight scale-up. Predicts: unready-counting → a sawtooth no stabilization removes. Bug: 5→10, 5 new report 0%, avg halves, loop reverses → orbit. Applied: P6.8, Inv-8, ADR-006, §8.1, Phase 3 (## 15), Failure Modes F5.

MM5 — Never trust your own last write. Level-triggered: re-read truth each tick, reconcile observed→desired; edge-triggered diverges the instant a write is dropped/clamped/overridden. Predicts: edge-triggered accumulates silent drift. Bug: a quota-rejected set_scale believed successful → permanent under-capacity. Applied: P6.5, Inv-7, ADR-014, Phase 5 (## 17), Phase 10 (## 22).

MM6 — Determinism is a feature of the math, bought by banishing wall-clock/RNG/float. A pure (snapshot,policy,state,now)→Decision is replayable+testable+fuzzable+auditable; any impurity forfeits all four. Predicts: the first Instant::now()/f64 makes sim and prod disagree. Bug: 0.1+0.2≠0.3 flips a tolerance-edge decision; tests flake. Applied: P6.4, Inv-4, ADR-005/021, Phase 3 (## 15), Phase 12 (## 24).

MM7 — Bounds/guardrails are an outer envelope the math cannot widen. Policy bounds clamp last; global guardrails sit outside policy and hold even when the math is wrong. Predicts: a target ≈0 without an unconditional final clamp requests u32::MAX. Bug: a unit error inflates the ratio 1e6× and the clamp wasn't last → cluster-wide blast. Applied: P6.2/P6.10, Inv-1/11, Phase 11 (## 23).

MM8 — The metric you scale on may be the metric you are changing. Per-replica CPU falls as you add replicas — a self-coupled loop that oscillates regardless of guards. Predicts: some flapping is structural, fixed only by a leading/independent metric (queue depth), not tuning. Bug: endless tuning of a metric that cannot settle. Applied: Failure Modes F1/F5, Operational Readiness runbook, P6.7.

MM9 — Prediction may only add lead, never subtract safety. Blend predicted with reactive by MAX under a confidence gate; a forecast pre-warms but a low-confidence dip never shrinks live capacity. Predicts: any min/replace blend scales down into a real spike on a bad forecast. Bug: HW mis-fits a holiday → pre-scales down → outage. Applied: P6.11, Phase 8 (## 20), Threat Model T12, Failure Modes F8.

MM10 — At the cluster layer, the autoscaler can create the unschedulable demand it removes. Draining a node whose pods can't land, or violating a budget, strands workloads. Predicts: scale-down safety must be proven before cordon and re-proven before each eviction. Bug: a "tidy idle nodes" pass evicts pods with nowhere to go. Applied: P6.12, Inv-12, Phase 9 (## 21), Failure Modes F9.

Glossary · 60 terms · site-wide glossary

metric
A named, labeled signal the autoscaler reacts to (e.g. cpu utilization, queue depth). One of three MetricKinds: Resource, Custom, External. Identified by MetricId.
sample
A single Sample { ts, value: Decimal }: one observation at a monotonic Timestamp. Value is Decimal (fixed-point) to avoid float drift in desired-replica math.
series
A Series { labels: BTreeMap, ring: RingBuffer<Sample> }: one label-set's time-ordered samples in a fixed-capacity ring buffer. Per-series, not global.
aggregation
Aggregation enum reducing a Window of samples to one AggValue: Avg, Sum, Rate, P50, P90, P99, Max. Rate = delta/Δt for counters; percentiles for latency-style metrics.
window
Window { duration, resolution }: the look-back span over which an Aggregation runs. duration = how far back; resolution = bucket size.
resolution
Bucket/step size inside a Window; samples within one resolution bucket are pre-reduced (downsampled). Trades memory vs fidelity.
downsampling
Reducing high-frequency samples to one-per-resolution-bucket on ingest, bounding ring-buffer memory and aggregation cost while preserving the window's shape.
staleness
MetricSource::last_scrape_age() exceeding a threshold → metric marked in MetricsSnapshot.stale. Stale metrics are excluded from the tick and trigger fail-safe (no scale-down).
MetricsSnapshot
MetricsSnapshot { at, per_metric, stale }: the FROZEN, immutable per-tick input to the control law. Pinning it makes tick() deterministic + replayable.
resource metric
MetricKind::Resource: per-replica cpu/mem utilization, averaged over ready replicas. Drives Utilization target type.
custom metric
MetricKind::Custom: a per-object application metric (e.g. requests/sec per pod). Drives AverageValue/Value.
external metric
MetricKind::External: a metric not tied to a scaled object (queue length, SQS depth, Kafka lag). KEDA-style event-driven scaling input.
target value
The desired operating point for a metric; the denominator in the HPA ratio. Encoded by TargetType.
target type
TargetType: how a target value is interpreted — Utilization(0..1) (fraction of request), AverageValue (per-ready-replica), Value (absolute, not divided by replicas).
tolerance band
TargetTracking.tolerance (default 0.1): if |ratio - 1.0| <= tolerance → NoOp. The primary anti-flap guard against acting on noise.
desired replicas
The output of the control law: ceil(currentReplicas * (current/target)), then clamped to [min, max], stabilized, and rate-limited → Decision.to.
current replicas
The replica count observed now via ScaleStatus.current. The HPA-ratio multiplier.
ready replicas
ScaleStatus.ready: replicas passing readiness. The current-value average is computed over READY replicas only, so warming-up replicas don't double-count a scale-up.
the HPA proportional algorithm
desiredReplicas = ceil(currentReplicas * (currentMetricValue / targetMetricValue)) over ready replicas, with tolerance NoOp band, then [min,max] clamp. The core control law.
scaling policy
Policy { target_ref, bounds, rules: Vec<ScalingRule>, sync_period }: declarative spec binding metrics+targets to one ScalableTarget.
target-tracking
ScalingRule::TargetTracking: hold a metric at a target value via the HPA ratio. The default reactive rule.
step scaling
ScalingRule::Step(StepPolicy): breach magnitude → discrete replica delta via Vec<Step>. Larger breach → larger step.
scheduled scaling
ScalingRule::Scheduled(ScheduledPolicy { schedule: Cron, bounds }): time-window min/max override (e.g. raise floor before a known peak).
predictive scaling
ScalingRule::Predictive(PredictivePolicy): scale ahead of forecasted load (AWS predictive / Netflix Scryer style) using asc-predict forecasts.
bounds (min/max)
Bounds { min, max }: hard u32 limits. INVARIANT: min <= desired <= max. Final clamp on every Decision; safety floor/ceiling.
control loop
The level-triggered reconciler in asc-control: re-reads metrics + ScaleStatus every sync_period and recomputes from scratch (never trusts its last write).
tick
One iteration: Controller::tick(now) -> Decision. Serialized per target. Pure function of MetricsSnapshot + policy + state + stabilization history.
sync period
Policy.sync_period: the control-loop cadence (e.g. 15 s). How often a tick runs.
Decision
Decision { from, to, direction, reason, metrics, at, recommended_only }: the full, auditable record of one tick's computation and outcome.
scale direction
ScaleDirection { Up, Down, None }: classifies a Decision; gates direction-specific cooldown + stabilization + rate limits.
scale-up
to > from (ScaleDirection::Up): governed by the up-stabilization window (min-over-window, default 0) + up-cooldown + up-rate-limit.
scale-down
to < from (ScaleDirection::Down): governed by the down-stabilization window (max-over-window, default 300 s) + down-cooldown + down-rate-limit. Suppressed on stale/missing metrics.
NoOp
ScaleDirection::None: tolerance band satisfied, or stabilization/cooldown/rate-limit blocked the change. to == from. The expected steady-state outcome.
stabilization window
StabilizationBuffer: ring of (ts, recommended). Scale-DOWN uses MAX over the down-window (shrink only if even the most aggressive recent rec agreed); scale-UP uses MIN over the up-window.
cooldown
Cooldown { scale_up, scale_down, last_scale }: minimum quiet time after a scale before another in the same direction. Blunt thrash guard layered atop stabilization.
rate limit
RateLimit { max_up_per_period, max_down_per_period, period }: caps change per period (e.g. +4 pods or +100% / 60 s). Applied AFTER stabilization.
hysteresis
Asymmetric scale-up vs scale-down behavior (eager up, reluctant down via longer down-stabilization) so the system doesn't oscillate around the target.
flapping / thrash
Rapid up/down oscillation from acting on noise. Prevented by tolerance band + stabilization + cooldown + rate limits + hysteresis. A primary failure mode + test target.
convergence
Reaching and holding desired ≈ target within bounds after a load change, without overshoot/oscillation. Property-tested under step load in Phase 12.
idempotent actuation
ScalableTarget::set_scale(n): re-applying the same n is a no-op at the target. Controller never assumes its write took effect; re-reads scale_status next tick.
ScalableTarget
The actuation abstraction: scale_status(), idempotent set_scale(desired), ref_id(). Drivers: process pool, Deployment adapter (#268), node group.
scale subresource
The narrow scale-only interface on a target (read ScaleStatus, write desired) — modeled on Kubernetes /scale; the Deployment adapter (#268) speaks it.
readiness gating
Scaling decisions use only ready replicas (ScaleStatus.ready); unready/starting replicas are excluded from the current-value average to avoid double-counting a pending scale-up.
recommend-only / dry-run
Decision.recommended_only = true: compute the full Decision + log it but DO NOT call set_scale. The shadow/validation surface (asctl plan).
forecast
Forecast { value, confidence, horizon }: a Forecaster's predicted metric value at a future horizon, with a 0..1 confidence used for fallback.
EWMA
Ewma { alpha }: exponentially-weighted moving average. Cheap, single-parameter Forecaster; smooths short-term noise.
Holt-Winters
HoltWinters: triple-exponential smoothing (level + trend + seasonal). The seasonal Forecaster for diurnal/weekly patterns.
seasonal
A repeating periodic pattern (e.g. daily/weekly) the HoltWinters seasonal component models for predictive scaling.
confidence
Forecast.confidence (0..1): forecast trustworthiness. Below a threshold → blend falls back to the reactive desired (fail toward proven control).
cluster autoscaler
asc-cluster: scales the cluster's NODES (not replicas) by adding node-group capacity for pending demand and draining underutilized nodes.
node group
NodeGroup { id, bounds, current, template }: a homogeneous, independently-scalable set of nodes with its own Bounds and NodeTemplate.
pending / unschedulable
Workload units that cannot be placed on existing nodes (insufficient capacity). The scale-UP trigger for the cluster autoscaler.
scale-up plan
ScaleUpPlan { group, add }: the SMALLEST node-group addition (found via bin-packing simulation) that lets all pending units schedule.
scale-down candidate
ScaleDownCandidate { node, utilization }: an underutilized node eligible for removal — only if all its workload can reschedule elsewhere AND disruption budgets allow.
cordon
Mark a node unschedulable (no new placements) prior to draining, so it can be safely emptied.
drain
Evict and reschedule a cordoned node's workload onto other capacity before removing it. Respects disruption budgets.
disruption budget
A constraint on how many replicas of a workload may be voluntarily evicted at once; drains must respect it, else the scale-down candidate is rejected.
decision log / audit
DecisionLog: append-only, replayable record of every Decision + ScalingEvent (applied?/error). The durable audit trail; enables deterministic replay.
fail-safe
On source failure / total staleness: HOLD — no scale-down (can't prove safe shrink), optionally no action — and surface a degraded Condition, rather than acting on bad data.
guardrail
Hard outer safety limits independent of policy math: max scale rate, emergency freeze, sanity bounds. Last line of defense against a runaway or buggy Decision.
