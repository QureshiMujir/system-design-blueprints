269 — Autoscaler

Goal: Build, from scratch in Rust + Tokio, an autoscaling decision + actuation engine modeled on the Kubernetes HPA, the Cluster Autoscaler, and AWS target-tracking / step / scheduled / predictive scaling: a metrics ingestion + windowed-aggregation pipeline (asc-metrics), a declarative scaling-policy model with the HPA proportional control law (asc-policy), a periodic control loop with stabilization / cooldown / rate-limits that kills flapping (asc-control), an idempotent level-triggered ScalableTarget actuator (asc-target), forecast-driven predictive scaling (asc-predict), a cluster (node-group) autoscaler (asc-cluster), and an auditable decision API (asc-api) — driven by the ascaled daemon + asctl CLI. It decides and actuates capacity; it is not a metrics system, a scheduler/orchestrator, or a load balancer.

1. Goal

Goal: A from-scratch autoscaling decision + actuation engine — ingest pluggable metrics → evaluate declarative scaling policies → a periodic control loop computes a desired replica/node count via the HPA proportional algorithm under stabilization / cooldown / rate-limits → idempotently actuate a ScalableTarget; plus predictive and cluster autoscaling. Determinism, bounded behavior, fail-safe. Modeled on Kubernetes HPA + Cluster Autoscaler + AWS target-tracking/step/scheduled/predictive + KEDA.

1.1 What we are building (engineering definition)

A daemon + CLI that answers, on a fixed cadence: given the metrics, how many replicas/nodes should exist, and apply it safely. End-to-end pipeline per tick:

scrape (asc-metrics)  → MetricsSnapshot (frozen per-tick input)
evaluate (asc-policy) → desired per metric via HPA ratio, ceil
combine (asc-control) → MAX across metrics → tolerance NoOp band → clamp [min,max]
                      → StabilizationBuffer → Cooldown → RateLimit → Decision
actuate (asc-target)  → set_scale(desired)  [IDEMPOTENT, level-triggered]
record (asc-api)      → DecisionLog (append-only) + AutoscalerStatus + ScalingEvent

Plus two orthogonal capabilities layered on the same loop:

  • Predictive/scheduled (asc-predict): forecast load (Ewma / HoltWinters), blend predicted + reactive desireds, confidence-gated fallback.
  • Cluster autoscaling (asc-cluster): scale node groups on pending/unschedulable demand; drain underutilized nodes respecting disruption budgets.

Components: ascaled (long-running control-loop daemon, runs the loop per sync_period) and asctl (CLI: configure policies, plan/dry-run a decision, status, history).

1.2 The core control law (load-bearing facts)

The full ordered pipeline + LOCKED formula is §8.4; the load-bearing facts: HPA proportional ceil(currentReplicas × current/target) over READY only (no warm-up double-count); tolerance band |ratio−1|≤0.1 → NoOp (primary anti-flap); bounds clamp [min,max] (INVARIANT min≤desired≤max); multi-metric = MAX of per-metric desireds; missing/stale excluded, MUST NOT scale-DOWN (fail-safe → HOLD + degraded); stabilization DOWN = MAX over down-window (300 s), UP = MIN over up-window (0); cooldown blocks same-direction re-scale; rate-limit caps Δ/period (+4 or +100%/60s, −10%/60s) after stabilization; determinism identical input → identical Decision (no wall-clock/RNG → replayable); idempotent level-triggered actuation set_scale(n) no-op if already n, re-read ScaleStatus each tick (268 reconcile).

1.3 System boundaries

TRUST BOUNDARY       : untrusted/noisy/missing metrics + actuation authority over real capacity.
CONCURRENCY BOUNDARY : scrapers run concurrently; the control tick is serialized per target.
PERSISTENCE BOUNDARY : asc-api DecisionLog + AutoscalerStatus (only durable state; small).
INPUT                : metric backends (resource/custom/external), orchestrator #268 status, forecast feed.
OUTPUT               : set_scale (replicas) / set_size (nodes) → real capacity.

1.4 Non-goals (explicit)

NOT a metrics/monitoring system (consumes via MetricSource, not Prometheus), a scheduler/orchestrator (#268 places pods), a load balancer/router, a FinOps/cost platform, or a general control-theory toolkit (specific proven laws, not PID/LQR/MPC). Expanded in §2.6/§4.3.

1.5 Deployment model

  • ascaled daemon runs the loop on Policy.sync_period (default 15 s), one autoscaler per target OR a multi-target daemon (each ticked independently, serialized per target); asctl = apply/plan(dry-run)/status/history; recommend-only mode emits Decision{recommended_only:true}, never set_scale.

1.6 Target users

  • SRE/platform run ascaled, author/tune policies, debug flapping; capacity owners set bounds/targets/scheduled overrides + review DecisionLog; service teams (indirect) attach a TargetTracking policy to a #268 Deployment for HPA-equivalent autoscaling.

1.11 Language: Rust 2021 + Tokio (rationale)

MSRV 1.78, Tokio. A wrong/flapping high-blast-radius decision is an outage/cost incident, so: determinism + bounded behavior on the hot path (no GC tail latency, injected clock + no RNG → replayable); sum types model ScalingRule/Decision/ScaleDirection with total match; Decimal avoids float drift in ratio/ceil; level-triggered actuation + memory safety → safe to wield actuation authority; Tokio drives concurrent scrapers + loop + actuator without GC pauses. Rejected: Go (GC + weak enums + float footguns), Python (no determinism, GIL), MATLAB/control DSL (not a daemon). See ADR-001.

2. Why Build This

2.1 The core problem

Elastic capacity is the central promise of cloud. The decision "given the metrics right now, how many replicas/nodes should exist — and apply it safely" is a closed-loop control problem over a noisy, partially-missing signal with a high-blast-radius actuator. Get the control law subtly wrong and you produce one of the most recognizable production incident classes: a flapping autoscaler oscillating capacity every tick (latency spikes on cold starts, cost burn, downstream connection storms), or a runaway scale that exhausts quota / budget, or a frozen scaler that holds at min during a traffic surge → outage. This project builds the decision + actuation engine (not the metrics store, not the orchestrator) and forces you to confront stability, convergence, and fail-safe behavior head-on.

2.3 Why it matters — historically + architecturally

  • Elasticity is the product — the autoscaler converts a static fleet into capacity-on-demand; capacity + cost are downstream of this one loop. Canonical prior art is narrow + well-studied, so reimplementing it teaches the field's lessons directly: HPA (proportional algo, tolerance, ready-accounting, stabilization), Cluster Autoscaler (pending-pod scale-up sim, drain-respecting scale-down), KEDA (external/queue metrics), AWS App Auto Scaling/ASG (target-tracking/step/scheduled/cooldown), predictive (AWS/Netflix Scryer forecast-ahead). Flapping is a named incident class — every story converges on the same fixes (tolerance/stabilization/cooldown/rate-limit); building them teaches which knob fixes which failure. Architecturally it sits at a trust boundary holding actuation authority — separating "what should be" from "what is" (level-triggered re-read), the controller pattern under modern orchestration.

2.4 Engineering muscles it builds

  • Control loops (periodic, level-triggered, convergence/stability as goals); time-series math (windowed agg, downsampling, staleness, EWMA/Holt-Winters); reasoning about stability+convergence as executable property tests (no-flap, converge-under-step, bounds-always, determinism); fail-safe design (HOLD on degraded, asymmetric up/down); capacity + reliability judgement that permanently raises your ability to size and de-risk any elastic system.

3.2 Component Responsibilities (one box per paragraph)

asc-metrics — ingestion + aggregation pipeline

Owns MetricSource and turns raw backend reads into one frozen MetricsSnapshot per tick: Series (per-label ring of Sample{ts,value:Decimal}), Aggregation over a Window (avg/sum/rate/p50/p90/p99/max), MetricsSnapshot{at, per_metric, stale}. Bounded history in fixed-cap rings (downsample on overflow → constant memory/series); last_scrape_age() drives staleness. Invariant: snapshot immutable + complete for one tick — every MetricId is in per_metric or stale, never silently dropped; aggregation never reads ts > snapshot.at. Phase 1 (## 13: trait/rings/agg/downsample/staleness/synthetic+resource), Phase 6 (## 18: custom+external).

asc-policy — declarative policy model + desired-value math

Owns Policy/Bounds + the four ScalingRule kinds, per-metric TargetType + tolerance, and desired_for_target_tracking(...) -> u32 (HPA ratio, ceil). Invariant: min<=max + sane targets validated at load (never at tick); pure (no I/O/clock/RNG → deterministic). Phase 2 (## 14: model/TargetTracking/ratio/validation), Phase 7 (## 19: Step+Scheduled+precedence), Phase 8 (## 20: Predictive).

asc-control — the central control loop / reconciler

Owns Controller, Decision, ScaleDirection, and the anti-flap trio StabilizationBuffer/Cooldown/RateLimit. tick(now) -> Result<Decision, ControlError>: per-metric HPA desired over READY → MAX → tolerance NoOp → stabilize (max-down/min-up window) → cooldown → rate-limit → clamp [min,max]. Invariants: deterministic, bounds always respected, missing/stale never scales DOWN (fail-safe). Phase 3 (## 15: ratio+tolerance+clamp), Phase 4 (## 16: anti-flap trio), Phase 6 (## 18: MAX+fail-safe), Phase 8 (## 20: blend).

asc-target — the scalable-target abstraction + actuators

Owns ScalableTarget, ScaleStatus{desired,current,ready}, ScaleSubresource: Decision.to → set_scale(desired), truth via scale_status(). Drivers: process-pool, Deployment→268 (scale subresource + pod metrics), node-group. Controller scales on ready (not current) → no double-count. Invariant: set_scale(n) IDEMPOTENT; level-triggered re-read each tick, never trust the last write. Phase 5 (## 17: trait/idempotent/readiness/process-pool/reactive E2E), Phase 10 (## 22: Deployment adapter + watch).

asc-predict — predictive + scheduled forecasting

Owns Forecaster, Forecast{value,confidence,horizon}, Ewma, HoltWinters. Consumes asc-metrics history → forward value+confidence; asc-control blends predicted vs reactive, falls back to reactive below confidence threshold — predicted may pre-warm UP but never overrides the reactive fail-safe. Invariant: pure/deterministic per observation sequence; low confidence cannot drive a DOWN. Phase 8 (## 20).

asc-cluster — the cluster autoscaler (node scaling)

Owns NodeGroup, NodeGroupProvider, ScaleUpPlan, ScaleDownCandidate, the bin-packing Simulator. Scale-up: pending/unschedulable demand → simulate against each NodeTemplate → smallest add that schedules. Scale-down: underutilized nodes whose workload reschedules elsewhere → cordon+drain respecting disruption budgets → set_size (IDEMPOTENT). Invariant: never drain unless all workload provably reschedules AND budgets allow; current within Bounds. Phase 9 (## 21).

asc-api — autoscaler API, status, and audit

Owns Autoscaler{spec,status}, AutoscalerStatus, ScalingEvent, the append-only DecisionLog. Out: queryable status, Conditions (e.g. Degraded on staleness), events, replayable audit, and the recommend-only/dry-run surface. Invariant: DecisionLog append-only + replay reproduces the same Decision sequence (pairs with determinism); the only durable state, stays small. Phase 11 (## 23: status/conditions/events/log/dry-run/guardrails).

ascaled / asctl — the drivers (asc-cli)

ascaled: long-running daemon — concurrent scrapers, tick on sync_period (serialized per target), persists asc-api state. asctl: operator CLI — apply/plan(dry-run)/status/history. Invariant: asctl plan is side-effect-free and shares the exact tick code path as ascaled, so a dry-run matches the daemon. Phase 0 (## 12: skeletons + smoke test); both binaries grow per later phase (status/history by Phase 11).

4.2 Topology, Timing & Fail-Safe Envelope

  • Topology: single ascaled process, no quorum/leader/consensus — idempotent + level-triggered, so a missed tick self-corrects and duplicate writes are no-ops (C18); HA = supervisor restart, not replication. Concurrency: scrapers concurrent (bounded Tokio join), the tick serialized per TargetRef (cross-target may overlap). Persistence: only DecisionLog+AutoscalerStatus durable (< 10 MB typical); rings volatile, rebuilt by re-scraping (C19). Trust: untrusted/noisy/missing metrics + actuation authority (Threat Model).
  • Clock: one injected Clock (now arg), no SystemTime::now() in asc-control/asc-policy math (C17); Sample.ts monotonic for windowing, wall-clock only for cron + audit. Math < 1 ms (C2) ⇒ fetch-bound; a tick exceeding sync_period skips the next (no backlog) + degraded Condition.
  • Fail-safe: stale/missing excluded from the MAX, never scale-DOWN ("can't prove we can shrink"); total staleness ⇒ HOLD + degraded. Target unreachable ⇒ NoOp + retry (no partial actuation). Readiness gating: average over READY only.

4.3 Resource, Numeric, Platform

  • All desired/ratio math Decimal (no f64); counts u32, 0 only if Bounds.min==0 (scale-to-zero), else min≥1. CPU < 5% of a core idle; scrape fan-out ≤32 in-flight fetch. 6. Design Principles

Twelve non-negotiable principles. Each governs the control law, the actuation path, or the safety envelope; violations are cited so later phases (## 12–## 24) can reference them by name. Tradeoffs and operational implications are stated as keyword clauses, not prose.

6.1 Stability over reactivity

  • Rule + mechanism: flapping is worse than lag — a correct-but-jittery loop is an incident, a slow-but-steady one is not. Tolerance band (default 0.1, NoOp when |ratio-1|<=tol) + StabilizationBuffer + Cooldown beat fast twitchy scaling.
  • Tradeoff + ops: adds seconds–minutes to legitimate scale events — accept it; flap rate is a top-line SLO, tuned via tolerance/down-window, not loop speed.
  • Violation: drop the tolerance band → ±5% noise drives ±1 replica every sync_period; target oscillates, connections reset, downstream caches cold-start; direction_changes/hour explodes (Phase 4 ## 16; Phase 12 "no flapping under stable load").

6.2 Bounds are inviolable

  • Rule + invariant: min <= desired <= max ALWAYS — under bugs, overflow, NaN-equivalents, malformed policy. Clamp is the LAST, unconditional step of tick(); Bounds{min,max} validated min<=max at admission (Phase 2 ## 14).
  • Tradeoff + ops: clamping can mask a runaway signal → surface ScalingLimited Condition, never silently pin; pinned-at-max for N ticks = under-provisioned alert, min-pinned = over-tight floor.
  • Violation: ratio 1e6 (target misconfigured ~0) without the final clamp → desired = u32::MAX, actuator requests millions, blast radius = whole cluster (Phase 3 ## 15; Phase 12 "bounds always respected").

6.3 Fail safe on bad data

  • Rule + asymmetry: missing/stale/source-failed metrics MUST NOT trigger scale-DOWN — hold last good, emit degraded Condition. Stale excluded from the MAX (Phase 6 ## 18) but treated as "cannot prove we can shrink"; scale-up may proceed from present metrics only.
  • Staleness + tradeoff: last_scrape_age() > threshold ⇒ MetricsSnapshot.stale; total staleness ⇒ HOLD + MetricsDegraded. Holds surplus capacity during outages (cost) — cheaper than blind shrink during a spike that broke the metrics path.
  • Violation: Prometheus adapter returns empty on a network blip; without fail-safe the loop reads "0 utilization" → scales to min mid-peak → cascading overload as metrics recover (Phase 1 ## 13; Phase 12 chaos).

6.4 Determinism in the control math

  • Rule + mechanism: identical (MetricsSnapshot, Policy, state, stabilization history) ⇒ identical Decision. Clock injected; all arithmetic over Decimal so ceil(current/target) never drifts; iteration over BTreeMap (sorted), never HashMap. No wall-clock, no RNG.
  • Tradeoff + ops: Decimal is ns-slower than f64 — irrelevant against a seconds sync_period; every Decision replays from the DecisionLog (Phase 11 ## 23) for post-incident replay, regression, virtual-clock sim (Phase 12 ## 24).
  • Violation: f64 ratio → 0.1+0.2 != 0.3, boundary decisions differ across machines; sim and prod disagree, property tests flake, audit replay can't reproduce the live decision.

6.5 Idempotent, level-triggered actuation

  • Rule + mechanism: set_scale(n) idempotent (same n = target no-op); controller NEVER assumes its last write took — each tick begins with scale_status() and reconciles observed→desired, not "what I asked last time." Cross-link 268 reconcile.
  • Tradeoff + ops: one extra read/tick buys self-healing — dropped writes, target restarts, external edits all converge; safe to crash/restart ascaled mid-decision or let a human co-write the scale subresource (last reconcile wins).
  • Violation: edge-triggered "I scaled to 10 so it's 10" → target rejected the write (quota) but controller believes success → permanent drift, silent under-capacity (Phase 5 ## 17; Phase 10 ## 22 watch).

6.6 Scale up fast, scale down slow

  • Rule + mechanism: asymmetric anti-flap. Scale-UP responds within ~1 tick (up-window default 0, MIN over up-window); scale-DOWN waits the down-window (default 300 s, MAX over window → shrink only if the most aggressive recent rec agreed) + down-cooldown. Asymmetric Cooldown and RateLimit.
  • Tradeoff + ops: keeps surplus ~5 min after load drops (cost) — protects against premature shrink before a second wave; tune down-window per workload volatility.
  • Violation: symmetric fast windows → 30 s dip sheds capacity, load returns, loop cold-starts under pressure → latency spike + thrash (Phase 4 ## 16).

6.7 Multi-metric takes the MAX

  • Rule + rationale: desired per metric independently; final desired = MAX across present metrics — each rule asserts a constraint, the binding one is the largest required count. Never average/sum. Combines with P6.3 (stale excluded, cannot force a down).
  • Tradeoff: can over-provision on a mis-targeted metric — the safe direction; correctness over thrift.
  • Violation: averaging CPU-desired (4) and queue-desired (40) → 22 replicas; the queue (real bottleneck) starves, backlog grows unbounded (Phase 6 ## 18; Phase 12 convergence).

6.8 Account for ready replicas only

  • Rule + rationale: the HPA ratio divides current load over READY replicas; unready/warming EXCLUDED — a just-started replica carries ~0 load, counting it deflates utilization and double-counts the in-flight scale-up → overshoot.
  • Mechanism + tradeoff: ScaleStatus{desired,current,ready}; math + readiness gating (Phase 5 ## 17) use ready. Slightly slower convergence while warming — prevents oscillation around the transient.
  • Violation: include unready → scale 5→10, 5 new report 0 CPU, average halves, loop scales back down before they take load → sawtooth (Phase 3 ## 15).

6.9 Every decision is auditable and explainable

  • Rule + mechanism: every tick() emits Decision{from,to,direction,reason,metrics,at,recommended_only} with a human-readable reason + full snapshot, appended to the replayable DecisionLog + ScalingEvent{applied,error} (Phase 11 ## 23). No silent scaling, including NoOps/clamps.
  • Tradeoff + ops: one small durable write/decision — required for trust in a high-blast-radius actor; answers "why did we scale at 03:14?" from the log alone (reason names binding metric, ratio, which guard fired).
  • Violation: scale without a recorded reason → an unexplained 02:00 scale-to-max is unattributable; on-call can't tell a correct reaction from a bug.

6.10 Guardrails bound blast radius

  • Rule + layering: hard guardrails independent of the control law cap damage — max scale rate (RateLimit), emergency freeze (admin halt-all), sanity bounds beyond Bounds. A SEPARATE outer envelope (defense-in-depth with P6.2) that holds even if a policy or the math is wrong.
  • Mechanism + tradeoff: Decision clamped to RateLimit AFTER stabilization; freeze short-circuits actuation to NoOp + Frozen (Phase 11 ## 23). A freeze can hold a genuinely-needed scale — operator chooses safety during an investigation.
  • Violation: no rate limit + a bad target flips 5→500 in one tick → 495 cold starts saturate node pool / image registry / DB pool simultaneously → a scale event becomes an outage.

6.11 Predictions degrade gracefully

  • Rule + mechanism: predictive/scheduled is an ENHANCEMENT, never an SPOF. Forecast{value,confidence,horizon}; blend predicted+reactive only when confidence >= threshold, else reactive; predicted may PRE-warm (raise floor) but reactive can always scale further up.
  • Tradeoff + ops: under-uses a conservative-confidence forecast (acceptable); cold-start/regime-change ⇒ low confidence ⇒ automatic reactive fallback, no intervention.
  • Violation: trust a HoltWinters forecast through a seasonality break (holiday) → pre-scale DOWN for "predicted low" while real load spikes; without reactive override, outage (Phase 8 ## 20; Phase 12 chaos).

6.12 Cluster scale-down must be safe

  • Rule + mechanism: never strand workloads. Scale a node DOWN only if underutilized AND all workload reschedulable elsewhere (Simulator) AND disruption budgets allow — cordon → drain → NodeGroupProvider::set_size (idempotent, P6.5). Scale-UP only if a group template lets pending units schedule (ScaleUpPlan = smallest add).
  • Tradeoff + ops: conservative down leaves nodes underutilized longer (cost) — stranding (no place to land) is an outage, strictly worse; disruption budget = cluster-level analog of the down-stabilization margin.
  • Violation: drain a node whose pods can't reschedule → pods stuck Pending, capacity lost; the autoscaler created the unschedulable demand it exists to prevent (Phase 9 ## 21).

6.13 Recommend-only first

  • Rule + mechanism: every new policy/target/source ships recommend-only (dry-run) before automated actuation — loop logs Decision{recommended_only:true}, no set_scale; asctl plan surfaces it; promotion is an explicit operator action.
  • Tradeoff + ops: delays automation benefit — buys a zero-blast-radius window to validate against real traffic; the same records prove convergence/flap in shadow; instant rollback = flip back to recommend-only (a freeze, P6.10).
  • Violation: push a freshly-authored policy live with the wrong TargetType (Utilization vs AverageValue) → first tick mis-scales production 10×; dry-run would have shown the bad Decision harmlessly in the log (Phase 11 ## 23).

6.14 Principle interaction & precedence

Hot-path governance: snapshot → 6.3/6.4/6.8; compute desired → 6.4/6.7/6.8/6.2; anti-flap → 6.1/6.6; rate-limit/freeze → 6.10/6.2; actuate → 6.5/6.13; predict/blend → 6.11/6.7; cluster scale → 6.12/6.5/6.2; record → 6.9/6.4. Precedence on conflict: safety/bounds (6.2) > fail-safe (6.3) > guardrails (6.10) > stability (6.1) > availability (6.6/6.7) > efficiency (6.11/6.12). The math may recommend anything; the safety envelope decides what is applied.

7.3 Per-invariant detail

Inv-1 — bounds clamp is last. Why: a decision outside [min,max] is an over/under-provision incident; clamp must see the post-rate-limit value, else rate-limit could re-inflate past max. Enforce: Bounds::clamp as the final math stage; Clamped newtype only constructible here. Detect/recover: debug_assert!(min<=to<=max) in Decision ctor; release out-of-range ⇒ inv1.violation, freeze, hold last good; BoundsClamped Condition if raw!=to for N ticks (saturation). Telemetry decision.clamped{raw,min,max,to}; debug = replay, inspect raw vs to.

Inv-2 — tolerance band ⇒ NoOp. Why: primary anti-flap; noise must not actuate. Enforce: desired_for_target_tracking returns from, direction=None when |current/target-1|<=tolerance. Detect/recover: post-check ratio_in_band ⇒ to==from && None; a NoOp emitting non-None is a hard bug ⇒ freeze. Telemetry decision.noop{ratio,tolerance}; debug = verify Decimal (no float) at the band edge.

Inv-3 — missing/stale metric never scales down. Why: absence of data is not proof we can shrink; scaling down on a gap is the classic outage. Enforce: snapshot merge marks stale; combine excludes stale but if any contributing metric is stale the down-direction is suppressed (floored at from). Detect/recover: guard has_stale && Down ⇒ violation; hold at from, raise MetricsStale; scale-up still permitted. Telemetry decision.downsuppressed{stale_ids}; debug = last_scrape_age vs Window.duration.

Inv-4 — tick() determinism. Why: replayability + testability. Enforce: math takes (snapshot,policy,state,history,now) only; Clock injected; no Instant::now/rand in asc-control/asc-policy. Detect/recover: replay re-runs logged inputs ⇒ byte-identical Decision; CI bans Instant/rand via clippy.toml; mismatch ⇒ quarantine the impurity + freeze. Telemetry replay.mismatch{tick_id,field}; debug = first divergent field localizes the impure call.

Inv-5 — scale-down needs max-over-window agreement. Why: anti-thrash; shrink only if the most aggressive recent rec agreed. Enforce: StabilizationBuffer returns max over down-window (300 s) for down, min over up-window (0 s) for up. Detect/recover: assert down-to >= max-over-down-window; cold/empty buffer ⇒ no-agreement ⇒ no scale-down. Telemetry stabilization{dir,window_s,considered,chosen}; debug = dump ring, confirm eviction at now-window.

Inv-6 — cooldown + rate-limit after stabilization, before actuation. Why: rate-limit must clamp the stabilized value, cooldown blocks repeat-direction churn; both precede the irreversible actuate. Enforce: typed pipeline (§7.2); Cooldown::allows then RateLimit::clamp. Detect/recover: stage newtypes prevent skipping; cooldown block ⇒ NoOp this tick (re-evaluated next, level-triggered). Telemetry cooldown.block, ratelimit.clamp; debug = verify rate-limit uses post-stabilization to.

Inv-7 — idempotent actuation + level-triggered. Why: controller never assumes its write landed (K8s/268 reconcile). Enforce: set_scale(n) no-ops if already n; tick always re-reads scale_status(); no cached desired. Detect/recover: actuating without a preceding read ⇒ violation; set_scale(n) twice ⇒ one effective change; dropped write self-heals next tick. Telemetry actuate{desired,was_current,changed}; debug = diff ScaleStatus.current vs logged to.

Inv-8 — current value over ready replicas only. Why: unready/warming dilute the average and double-count an in-flight scale-up ⇒ overshoot. Enforce: per-metric average divides by ScaleStatus.ready, not current; ratio multiplier = ready. Detect/recover: assert ready<=current; ready==0 ⇒ cannot compute ⇒ NoOp + NoReadyReplicas (fail-safe). Telemetry snapshot.ready{ready,current,excluded}; debug = confirm denominator == ready.

Inv-9 — DecisionLog append-only + replayable; actuation implies logged Decision. Why: audit + replay; no actuation without a durable record. Enforce: append returns a seq; tick actuates only after append (write-ahead); entries immutable. Detect/recover: monotonic-seq gap/rewrite check; orphan actuation ⇒ violation; append failure ⇒ abort actuation (no log ⇒ no action); corrupt tail ⇒ truncate-to-last-valid + flag. Telemetry decisionlog.append/replay; debug = replay [seq_a,seq_b] vs observed.

Inv-10 — multi-metric desired = MAX. Why: satisfy the most-demanding metric; MIN/AVG under-provisions. Enforce: combine desired = per_metric.values().max(); stale excluded (Inv-3). Detect/recover: assert combined >= each contributing; empty set ⇒ hold; all stale ⇒ NoOp (Inv-3). Telemetry combine{per_metric, chosen, winner_id}; debug = log per-metric desired, identify winner_id.

Inv-11 — guardrails unbypassable. Why: freeze + global max-rate are operator overrides no policy field can disable; they gate after policy math. Enforce: guardrail stage runs after bounds clamp, reads global config (not Policy); freeze ⇒ force None,to=from; global max_rate re-clamps past policy rate-limit. Detect/recover: actuating while frozen or exceeding global max-rate ⇒ violation; freeze ⇒ persistent NoOp + FrozenByGuardrail. Telemetry guardrail.freeze/maxrate.clamp; debug = confirm config source is global, stage runs last.

Inv-12 — cluster scale-down safety. Why: draining a node whose pods can't reschedule, or violating a budget, causes the outage autoscaling must avoid. Enforce: Simulator proves all pods fit elsewhere AND drain respects budgets before cordon+drain. Detect/recover: precondition all_fit && budgets_ok must hold; cordon without it ⇒ violation; any failure ⇒ skip candidate, keep node, never partial-drain. Telemetry scaledown.candidate, drain{evicted,blocked}; debug = replay Simulator input, find the unplaceable pod.

8. Domain Model — Metrics, Policies, and the Control Law

The kernel of the autoscaler: how raw samples become a frozen MetricsSnapshot, how a Policy declares intent, and the exact, deterministic control law that maps (snapshot, policy, state) → Decision. Everything here is float-free (Decimal/fixed-point), clock-injected, RNG-free → replayable. Cross-links: metrics ingestion = asc-metrics (Phase 1, ## 13); control loop = asc-control (Phases 3–4, ## 15–## 16); actuation = asc-target (Phase 5, ## 17).

8.1 The metric model — Sample, Series, ring buffer, kinds, aggregation, window, staleness

Type spine (home asc-metrics): Sample{ts,value:Decimal}, Series{labels,ring}, MetricKind{Resource,Custom,External}, Aggregation{Avg,Sum,Rate,P50,P90,P99,Max}, Window{duration,resolution} — full signatures in §11.1.

MetricKind semantics (drives how current is computed, and the legal TargetType):

Kind Scope Source example current derivation Legal TargetType
Resource per-ready-replica cpu/mem of pods (via #268) sum(usage over READY) / ready → utilization vs request Utilization, AverageValue
Custom per-object req/s per pod, conn count sum(metric over READY) / ready AverageValue, Value
External global / off-target queue length, Kafka lag raw aggregate (NOT per-replica) AverageValue, Value
  • Resource util = usage/request (0..1+, the only Utilization-yielding kind). External is global → AverageValue ÷ ready, Value does not (never excludes unready).

Ring buffer (per Series): fixed-capacity, sized ceil(retention/resolution) (30 min @ 15 s = 120 slots), O(1) overwrite-oldest; ≤16 B/sample × 120 × cardinality (~19 MB @ 10k series); cap (10k) rejects new label-sets with CardinalityExceeded.

Aggregation over a Window ([now-duration, now] → one AggValue):

Agg Formula / rule Use
Avg / Sum Σvalue / n · Σvalue resource util · external totals
Rate (last − first)/Δt, counters only; reset (Δ<0) → segment-sum req/s, throughput
P50/P90/P99 nearest-rank percentile tail-sensitive custom metrics
Max max value burst-protective targets
  • Resolution = scrape interval; samples align to grid for p*/rate stability. Downsampling folds same-bucket samples by the series' agg (avg/sum/max) → bounded slots, no Rate double-count. Rate requires a counter (monotonic-with-reset); on a gauge → KindMismatch.

Staleness: last_scrape_age() = now − newest ts; stale when age > max(factor×resolution, min_staleness) (factor 3, min 60 s) → excluded + listed in stale; empty window (n=0) also stale.

8.2 Freezing a tick — the MetricsSnapshot

One tick(now) takes a single immutable read of all series → freezes MetricsSnapshot{at, per_metric: BTreeMap<MetricId,AggValue>, stale} (signatures §11.1; AggValue{value,ready,kind,agg}). The control law sees nothing else; mid-tick scrapes are invisible until next tick → determinism + replayability. Freeze (per policy metric): match Series by labels → aggregate over Window → staleness check → place in per_metric (live) or stale. ready captured from scale_status() at the SAME now so per-replica math and snapshot agree. Stored verbatim in Decision.metrics + DecisionLog → a tick replays from its snapshot alone.

8.3 The policy model — Policy, Bounds, the four rules, TargetType

Type spine (home asc-policy, signatures §11.2): Policy{target_ref,bounds,rules,sync_period}, Bounds{min,max}, ScalingRule{TargetTracking|Step|Scheduled|Predictive}, TargetTracking{metric,target,tolerance} (default tol 0.1), TargetType{Utilization(0..1)|AverageValue|Value}.

TargetType semantics (what target means, what current is compared to):

TargetType target current Ratio
Utilization(u) fraction 0..1 avg(usage/request) over ready current_util / u
AverageValue(v) per-replica total / ready (total/ready) / v
Value(v) absolute aggregate (not divided) total / v

Compact config — a target-tracking policy (YAML-ish):

target_ref: { kind: Deployment, name: web, via: orchestrator-268 }
bounds:      { min: 2, max: 20 }
sync_period: 15s
rules:
  - target_tracking:
      metric: cpu                          # Resource kind
      target: { utilization: 0.60 }        # 60%
      tolerance: 0.10                       # +/-10% no-op band
  - target_tracking:
      metric: requests_per_sec             # Custom kind
      target: { average_value: 50 }        # 50 rps per replica
      tolerance: 0.10
stabilization: { scale_down_window: 300s, scale_up_window: 0s }
cooldown:      { scale_up: 60s, scale_down: 300s }
rate_limit:    { up:   { pods: 4, percent: 100, period: 60s },
                 down: { percent: 10,            period: 60s } }

Validation (at parse; asc-policy::validate): min ≤ max, min ≥ 0, max ≥ 1; 0 < tolerance < 1; Utilization ∈ (0,1]; AverageValue/Value > 0; metric kind ↔ TargetType legal (table §8.1); cron parses; non-empty rules; sync_period ≥ 1s. Failure ⇒ PolicyError (rejected, never partially applied).

8.4 The control law — the full ordered pipeline

One tick runs this ordered, pure-given-(snapshot,state,now) pipeline (the typed-stage form is §7.2): (1) per-metric desired — ratio = current/target; |ratio−1|≤tolerance → desired_m = current_replicas (NoOp band) else ceil(ready × ratio); (2) step/scheduled — StepPolicy breach → ±delta, ScheduledPolicy overrides bounds in-window; (3) multi-metric MAX over live desired_m (stale/missing excluded; if it would imply DOWN → hold, fail-safe); (4) stabilization — DOWN = MAX over down-window (300 s), UP = MIN over up-window (0 s); (5) cooldown — blocked direction holds at current; (6) rate-limit clamp |desired−current| per period; (7) bounds clamp clamp(min,max) → Decision{from,to,direction,reason,metrics,at,recommended_only}.

The HPA proportional formula (LOCKED): desiredReplicas = ceil( readyReplicas × ( currentMetricValue / targetMetricValue ) ).

  • Over READY replicas (unready excluded from both the average and the multiplier → no double-count). Tolerance band (0.1) applied per-metric BEFORE the MAX. ceil, integer, Decimal (no drift); target==0 impossible (validation). Stabilization buffer holds (ts, recommended), read MAX-down/MIN-up (see §8.6 + Phase 4 ## 16).

8.5 Worked examples (exact arithmetic)

# current_replicas / ready metric current target ratio per-metric desired after pipeline direction
i 4 / 4 cpu util 0.90 0.60 1.50 ceil(4×1.50)=6 6 (≤max 20) Up
ii 6 / 6 cpu util 0.30 0.60 0.50 ceil(6×0.50)=3 6 held (max-over-300s window still 6) None (waits)
iii 5 / 5 cpu util 0.63 0.60 1.05 NoOp (|1.05−1|=0.05 ≤ 0.10) 5 None
  • (i) 90% vs 60% at 4 ready → up to 6 (up-window 0; +2 ≤ +4 cap). (ii) 30% vs 60% recommends 3, but the down-window (300 s) still holds a recent recommended=6 → MAX-over-window=6 → hold until it ages out (no premature shrink). (iii) ratio 1.05 in the ±0.10 band → NoOp.

Multi-metric MAX: cpu→6, rps→8 ⇒ max(6,8)=8. If rps is stale and would imply 3 (a shrink), it is excluded and the shrink suppressed (fail-safe).

8.7 Step scaling and scheduled scaling

StepPolicy — breach magnitude (current−target) → additive delta over (lower, upper, delta) bands, e.g. steps: [{0,20,+1},{20,40,+2},{40,~,+4}] (open top). Example: target 60%, current 95% → breach 35 → [20,40) → +2. Additive (not ratio), bounded [min,max]; bypasses ceil-ratio but still passes stabilization→cooldown→rate→bounds.

ScheduledPolicy — cron window overrides Bounds (e.g. {cron:"0 8 * * MON-FRI", bounds:{min:10,max:40}} business-hours floor; evening {min:2,max:20}); inside the window schedule min/max replace base. A scheduled floor (min:10) forces scale-UP without a breach (pre-warm); overlapping windows → most-recently-started wins, ties → MAX(min)/MAX(max); applied in stage (7), never triggers DOWN below a reactive desired (stage-3 MAX dominates upward).

11. Core Schema and Core Types

Normative APIs; all phases build against these exact signatures. Cross-cutting: Policy/Bounds/ScalingRule/MetricsSnapshot are frozen inputs per tick (read, never mutated → reproducible); mutable state (StabilizationBuffer/Cooldown/last-desired) lives in Controller (sole writer, serialized per target); DecisionLog append-only (in at order → replayable); injected now: Timestamp (no Instant::now() in math → deterministic + virtual-clock); Decimal everywhere on the desired path (no f32/f64, no NaN/-0.0); Timestamp = monotonic nanos since injected epoch, total-ordered, Copy.

11.1 asc-metrics — ingestion + aggregation types

/// One observed value at one monotonic instant. Copy; ~24 B.
pub struct Sample { pub ts: Timestamp, pub value: Decimal }

/// A labeled time series; ring = fixed-capacity overwrite buffer (oldest evicted),
/// pushed concurrently (own lock); the tick reads a consistent window snapshot.
pub struct Series {
    pub labels: BTreeMap<String, String>,   // identity; BTreeMap → deterministic order
    pub ring:   RingBuffer<Sample>,          // cap = window.duration / resolution + slack
}

/// What the value MEANS — selects the desired-value formula downstream.
pub enum MetricKind {
    Resource,   // cpu/mem PER REPLICA → averaged over ready replicas
    Custom,     // per-object app metric (rps, depth) → AverageValue/Value
    External,   // not tied to a replica (queue length, topic lag) → Value
}

/// Windowed reduction over a Series' samples in [now-duration, now].
pub enum Aggregation { Avg, Sum, Rate, P50, P90, P99, Max }

/// Window = lookback `duration`, sampled at `resolution` (downsampling buckets raw samples before aggregating).
pub struct Window { pub duration: Duration, pub resolution: Duration }

/// Pluggable backend (resource/custom/external). Async fetch; reports its own staleness → fail-safe. Send+Sync.
pub trait MetricSource: Send + Sync {
    fn name(&self) -> &str;
    async fn fetch(&self, query: &MetricQuery, window: Window)
        -> Result<Vec<Series>, MetricError>;
    fn last_scrape_age(&self) -> Duration;     // > staleness_threshold ⇒ stale
}

/// FROZEN input to one tick: per-metric aggregate at `at`; `stale` = metrics past the staleness threshold
/// (excluded from math, MUST NOT drive scale-DOWN). Immutable; Clone for the log.
pub struct MetricsSnapshot {
    pub at:         Timestamp,
    pub per_metric: BTreeMap<MetricId, AggValue>,  // MetricId = (source, name, kind)
    pub stale:      Vec<MetricId>,
}
  • Ownership/concurrency: each MetricSource owns its Series map (controller borrows a read snapshot); N scrapers fill N Series concurrently (tokio::spawn, ring Mutex/RwLock-guarded), aggregation reads a consistent window copy → no torn reads. MetricsSnapshot owned by the tick, Cloned into ScalingEvent.
  • Serialization/cardinality: Sample/Series in-memory only (cheap to rebuild); MetricsSnapshot derives Serialize for the durable DecisionLog. Bounded: ≤10⁴ active series, ring cap ≤256 samples/series → ~tens of MB.

11.2 asc-policy — declarative policy model + desired math

/// Versioned, declarative, IMMUTABLE per tick. Loaded from YAML, validated once,
/// then read-only. `schema_version` gates back-compat (additive fields only).
pub struct Policy {
    pub schema_version: u32,           // bump on incompatible field semantics
    pub target_ref:     TargetRef,     // which ScalableTarget this scales
    pub bounds:         Bounds,
    pub rules:          Vec<ScalingRule>,  // combined by MAX of per-rule desireds
    pub sync_period:    Duration,      // tick cadence (default 15 s)
}

/// INVARIANT: min <= desired <= max, AND min <= max (validated at load).
pub struct Bounds { pub min: u32, pub max: u32 }

/// Sum type → exhaustive match makes the control-law branches total.
pub enum ScalingRule {
    TargetTracking(TargetTracking),
    Step(StepPolicy),
    Scheduled(ScheduledPolicy),
    Predictive(PredictivePolicy),
}

/// Hold `metric` at `target`; `tolerance` is the no-op band (default 0.1).
pub struct TargetTracking { pub metric: MetricId, pub target: TargetType, pub tolerance: Decimal }

/// How `target` is interpreted vs the current metric value.
pub enum TargetType {
    Utilization(Decimal),    // 0..1 fraction of requested resource (per ready replica)
    AverageValue(Decimal),   // absolute value PER ready replica
    Value(Decimal),          // absolute aggregate value (external metric)
}

/// Breach magnitude → replica delta (CloudWatch-style step scaling).
pub struct StepPolicy { pub metric: MetricId, pub steps: Vec<Step> }
pub struct Step { pub lower: Option<Decimal>, pub upper: Option<Decimal>, pub delta: i32 }

/// Time-windowed bounds override (cron). Active window replaces `Bounds`.
pub struct ScheduledPolicy { pub schedule: Cron, pub bounds: Bounds }

/// THE HPA PROPORTIONAL ALGORITHM (pure, no clock/RNG): `ceil(current_replicas * current/target)` over READY;
/// `|ratio-1.0| <= tolerance` ⇒ return current_replicas (NoOp). Caller clamps to Bounds.
pub fn desired_for_target_tracking(
    current_replicas: u32,
    current:          Decimal,
    target:           &TargetType,
    ready:            u32,
    tolerance:        Decimal,
) -> u32;
  • Ownership/serde: Policy is Arc-shared, read-only after validation; asctl edits swap the whole Arc<Policy> atomically. YAML-authored, Decimal round-trips exactly, schema_version mismatch ⇒ load error.
  • Compatibility: additive fields only within a schema_version (semantic changes bump it); unknown fields ⇒ reject (no silent drop on a capacity-deciding doc).

11.3 asc-control — control loop, decision, anti-flap state

pub enum ScaleDirection { Up, Down, None }   // None = NoOp tick

/// Output record of ONE tick: FROZEN snapshot + reason → fully replayable; `recommended_only` ⇒ dry-run. Clone+Serialize.
pub struct Decision {

    pub to:               u32,
    pub direction:        ScaleDirection,

    pub at:               Timestamp,

}

/// MUTABLE ring of (ts, recommended), owned by Controller. Anti-flap: DOWN = MAX over down-window (300 s,
/// shrink only if the most aggressive recent rec agreed); UP = MIN over up-window (0 s).
pub struct StabilizationBuffer { /* ring of (Timestamp, u32 recommended) */ }
impl StabilizationBuffer {
    pub fn record(&mut self, ts: Timestamp, recommended: u32);
    pub fn stabilized(&self, dir: ScaleDirection, up_win: Duration, down_win: Duration, now: Timestamp) -> u32;
}

/// Blocks another scale in the SAME direction for a period after `last_scale`.
pub struct Cooldown { pub scale_up: Duration, pub scale_down: Duration, pub last_scale: Option<Timestamp> }

/// Caps change per period AFTER stabilization (e.g. max_up = +4 or +100%/60s; max_down = -10%/60s).
pub struct RateLimit { pub max_up_per_period: Scale, pub max_down_per_period: Scale, pub period: Duration }
pub enum Scale { Absolute(u32), Percent(Decimal) }

/// Owns ALL mutable per-target loop state; tick SERIALIZED per target (one `&mut self`, no concurrent ticks).
/// `clock` injected → deterministic, virtual-clock testable.
pub struct Controller {
    /* sources: Vec<Box<dyn MetricSource>>, policy: Arc<Policy>,
       target: Box<dyn ScalableTarget>, stabilization: StabilizationBuffer,
       cooldown: Cooldown, rate_limit: RateLimit, clock: Clock */
}
impl Controller {
    /// Pipeline: scrape→snapshot→per-rule desired→MAX→clamp Bounds→stabilize→
    /// cooldown→rate-limit→Decision→(actuate unless recommended_only). Deterministic

    pub async fn tick(&mut self, now: Timestamp) -> Result<Decision, ControlError>;
}

  • enforce ordering: freeze (→ block all actuation) → sanity bounds (reject to outside [sane_min, sane_max] regardless of policy bounds) → hard rate cap (clamp |to-from| ≤ hard_max_rate over period, independent of per-policy RateLimit).   • replay(entries): fold log into AutoscalerStatus (last applied to → current/desired, last_scale_time, derived conditions) — pure, no I/O, no clock.
  • Conditions: AbleToScale, ScalingActive, ScalingLimited (bounds/rate/guardrail), MetricsAvailable (from snapshot stale).
  • Theory anchors: B7 (status-subresource + condition vocabulary), B2 (autoscaler-fighting-deploy → recommend-only), S6 (RFC 3339 log timestamps), Inv-9/11 (append-before-actuate, unbypassable guardrail), P6.9/P6.10/P6.13, ADR-019/020.

11.6 Pitfalls

  • Replay drifts from live → root cause: status field derived from wall-clock not log at. Fix: replay uses only logged timestamps; debug by diffing live-status vs replay-status field-by-field.
  • Guardrail applied before stabilization/rate-limit → double-clamping inconsistency. Root cause: ordering. Guardrail is the LAST gate before set_scale; per-policy RateLimit runs inside tick, guardrail in actuate.
  • Dry-run still actuates → recommended_only set on Decision but actuate checks only dry_run flag (or vice-versa). Must OR both.
  • Log unbounded growth → JSONL never rotated; disk fills. Mitigate: segment + compact (keep status checkpoint + tail).
  • Freeze races a concurrent tick → freeze read after enforce decision computed. Read freeze atomically at actuate entry; tick is serialized per target so no torn write.
  • Clamped verdict not reflected in status.desired → status shows policy desired, not actuated value → confuses operators. Record clamped to as the effective desired.

Threat Model

Scope & framing

Autoscaler = automated, high-blast-radius capacity authority on a fixed cadence under noisy/missing/forgeable metrics; a wrong/flapping decision = outage or cost incident. Surfaces (from §3): TRUST (untrusted metric inputs + actuation authority over real capacity), CONCURRENCY (scrapers concurrent, tick serialized per target), PERSISTENCE (DecisionLog+AutoscalerStatus = audit-integrity surface). NON-GOAL: not an IDS/SIEM (emits signals for an external correlator).

F1 — Flapping / oscillation (S1, signature failure)

  • Symptoms: replica count oscillates Up↔Down on adjacent/near ticks; ScalingEvent stream alternates direction; downstream latency/cost noise.
  • Root causes: (a) tolerance too narrow (ratio hovers just outside ±tol); (b) down-window too short; (c) a metric that responds to scaling (per-replica CPU: add replicas → CPU drops → scale-down → CPU rises → loop — positive-feedback instability); (d) cooldown disabled; (e) sub-tick spikes un-aggregated (use p90/avg not Max).
  • Detection + auto-recovery: flap_rate = reversals/window, alert > 2 per 10 min; DecisionLog shows the same two to/from alternating. Down-stabilization (max-over-window) + cooldown + rate-limit bound amplitude/frequency but don't eliminate a too-tight tolerance.
  • Manual recovery + operator: widen tolerance (0.1 → 0.15–0.2), raise down-window; for self-responsive metrics switch to a non-feedback metric (queue length) or AverageValue with headroom. asctl history --flap lists reversals; asctl plan --replay --tune tolerance=0.2 previews damping. Forensic: reversal series + per-tick ratio orbiting 1.0±tol.
  • Long-term: flap-rate SLO in Phase 12 ("no flap under stable load"); document the self-responsive-metric anti-pattern as a validation warning.

F9 — Scale-down stranding / disruption-budget violation (S1, gravest cluster failure)

  • Symptoms/root cause: workloads pending after a drain / disruption budget breached / reschedule storm — a ScaleDownCandidate committed without proving every pod can land elsewhere, or a drain ignoring the budget.
  • Invariant (impossible by construction): scale-DOWN ⇔ underutilized AND Simulator proves all workload reschedules onto remaining capacity AND budgets permit — verified before cordon, re-verified after cordon and before each eviction (capacity may have changed).
  • Detection + recovery: pre-commit Simulator infeasible → plan rejected, no cordon; post-cordon recheck failure → uncordon, restore NodeGroup target, S1 Condition (never proceed on partial proof). Manual: asctl cluster plan --dry-run inspects the rejected candidate + placement, repair the budget. Forensic: placement transcript + reason="scale-down-aborted: infeasible".
  • Long-term: Phase 12 chaos "node disappears mid-drain" + property "no pod ever stranded". This class is never auto-recovered by retry — it is prevented.

F3 — Stuck-at-max (S1, cost incident)

  • Symptoms/root cause: desired==max sustained, cost climbs, metric still above target — real overload beyond max, or runaway from a self-responsive metric, or a unit/scale error inflating currentMetricValue, or max too low.
  • Detection + recovery: guardrail "desired==max ≥ N ticks (10)" + metric-still-saturated cross-check; bounds clamp prevents runaway above max, emergency freeze halts further scale-up + pages. Manual: validate the metric via replay (physically plausible?), raise max only after confirming demand, fix the MetricQuery if a unit bug. Forensic: snapshot history at max + reason="clamped-to-max". Long-term: sanity-bounds on metric values + an independent cost-rate alert.
  • Documented precedent: the AWS Kinesis event in US-EAST-1 (25 Nov 2020, public AWS postmortem) — adding front-end fleet capacity pushed servers past an OS thread limit, triggering cascading failure. The canonical lesson: a capacity-increase has real blast radius and must be rate-limited + bounded + guard-railed (ADR-011, P6.10); a scale-up that exhausts a downstream limit (thread/FD/connection/quota) is exactly what RateLimit.max_up_per_period + sane_max bound.

F4 — Stuck-at-min (S1, under-provisioned outage)

  • Symptoms: desired == min while latency/queue saturates; classic under-provision outage masked as "stable".
  • Root cause/detection: min too low / tolerance swallowing a breach / missing scale-UP metric (only a feedback metric); detect = desired==min AND a target metric above target for N ticks. Recovery: none beyond honoring demand (allowed at min); a scheduled floor raises min in known-busy windows; lowering min is not the fix — verify the scale-UP metric exists + isn't stabilization-masked, up-window=0. Long-term: require ≥1 non-feedback (forward) metric in validation.

F5 — Non-convergence (S1, orbits target, never settles)

  • Symptoms/root cause: desired never enters the band, error orbits with non-decaying amplitude (continuous, vs F1's discrete flap) — #1 culprit is the ready-replica accounting bug (including unready double-counts a scale-up); also too-aggressive rate-limit (overshoot↔undershoot) or resolution coarser than system τ. Detection + recovery: convergence-time → never, replay shows a fixed offset around target; tighten max_up_per_period, audit that ScaleStatus.ready drives the divisor not current, align resolution to τ. Long-term: Phase 12 "convergence under step load" + assert ready-only average.

F2 — Metric-source failure / total staleness (S2)

  • Symptoms/cause: fetch errors or returns stale; MetricsSnapshot.stale populated, degraded Condition; backend down/network/timeout/clock-staleness. Detect: last_scrape_age() > 3×Window.resolution. Recover: fail-safe HOLD — NO scale-DOWN on stale (exclusion must never enable a down); resumes on fresh samples; restore backend, Condition clears. Long-term: redundant MetricSource, staleness budget tied to sync_period.

F6 / F7 — Actuation failure & silent no-op (S2)

  • F6: set_scale → TargetError. Recover: retry w/ bounded backoff, ActuationFailing Condition; idempotent set_scale makes retry safe.
  • F7: set_scale returns OK but current never converges (target silently ignores writes). Detect: next-tick re-read shows desired ≠ current persisting. Recover: the level-triggered loop re-issues every tick — never open-loop trusts a prior write (cross-link 268). Forensic: DecisionLog applied=true + status divergence.

F8 — Bad / low-confidence forecast → premature scale (S2)

  • Symptoms/cause: PredictivePolicy scales ahead of demand that never materializes (or misses a spike); Holt-Winters mis-fit / insufficient history / regime change → low confidence. Recover: fallback to reactive when confidence < threshold; blend max(reactive, predicted·gate(confidence)) — prediction only adds lead, never suppresses a reactive scale-up; disable the rule / extend history. Long-term: confidence floor in validation, track forecast-vs-actual.

F10 — Clock skew / jump (S2)

  • Symptoms/cause: wrong window aggregation / corrupted stabilization / ts regression from NTP step, VM pause, non-monotonic source. Detect: ts regression vs the monotonic source; injected control-clock jump. Recover: reject regressed-ts samples; on a large forward jump treat intervening as a gap (HOLD) + reset the window rather than scale on a phantom. Long-term: Phase 12 clock-skew chaos.

F11 — Daemon crash (lost in-memory windows) (S2)

  • Symptoms/cause: restart with empty rings + StabilizationBuffer (windows are intentionally in-memory; PERSISTENCE BOUNDARY = DecisionLog+AutoscalerStatus). Recover: rebuild within one window by re-scraping; until full, HOLD (insufficient history ⇒ no scale-down); persisted AutoscalerStatus (last_scale_time,desired) survives so a crash can't immediately re-scale. Long-term: warm-start replay of recent DecisionLog.

F12 — DecisionLog / replay divergence (S2, bug signal)

  • Symptoms/cause: asctl replay Decision ≠ logged live Decision for the same input — a determinism violation: wall-clock/RNG/float drift, or unrecorded hidden state (stabilization not in the log). Detect: replay-equivalence gate (Phase 12) byte-for-byte. Recover: none automatic (it's a defect); diff field-by-field → the divergent field localizes the impurity. Long-term: CI determinism property test; record full replay-state (snapshot + stabilization ring + cooldown) so replay is hermetic.

Cross-class replay debugging methodology

Uniform: asctl history --target T (locate the tick by direction/reason) → asctl replay --from <log> --at <ts> (reproduce offline) → inspect the frozen snapshot (ratio vs tolerance, stale set, ready vs current divisor) → --tune <param> to A/B a fix against the same history (no prod risk) → promote; the log becomes a Phase-12 regression fixture. For the S1 classes (F1/F9/F3) this is the first responder action, paired with emergency-freeze to stop the bleeding before tuning.

  • Policy change / rollback: versioned Policy; asctl plan previews the Decision against live metrics. POLICY config schema compatibility

  • Every Policy carries apiVersion: autoscaler/vN; loader parses vN/vN-1, vN-2 → hard error + migration hint; no silent reinterpretation. Additive-only within a version: new ScalingRule variants + fields are additive; unknown fields → warn-and-ignore (toggle strict:true to reject).
  • Defaults preserve behavior: every new field defaults to prior behavior. Locked defaults (changing any = break): tolerance=0.1, down-stab=300s, up-stab=0s, sync_period=15s, up-rate=+4 or +100%/60s, down-rate=-100%/60s. Deprecation: PolicyDeprecation warning (CLI + ConfigDeprecated Condition) ≥1 minor before removal; renames ship as alias. Validation (min<=max, sane targets, non-empty rules) is a hard gate at load AND asctl plan; tightening a rule is a vN+1 break.

Trait stability — the primary extension surfaces

MetricSource, ScalableTarget, NodeGroupProvider are the public extension points (third-party impls out-of-tree):

Change Compatible? Mechanism
Add method with default body yes default impl; impls unaffected
Add required method (no default) no — major forces all impls to change
Add param to existing method no — major new defaulted method instead

DecisionLog format stability

  • Append-only framed records [len:u32][format:u16][crc32c][cbor-payload]; old logs always replay on newer asc-api (dispatch on format, fill missing fields with behavior-preserving defaults). Additive-only payload, CBOR keyed by stable integer tags. Replay against the same asc-control version reproduces the identical stream; cross-version replay reproduces recorded decisions verbatim (a record, not a recomputation). Unknown future format on an old reader → skipped + UnknownLogFormat, never crash/truncate.

Control-law behavior stability

The HPA algorithm + defaults are a documented behavioral contract:

desired = ceil( current_replicas * (current_value / target_value) )   over READY replicas
NoOp if |ratio - 1.0| <= tolerance (default 0.1)
multi-metric: desired = MAX over metrics ; missing metric never forces scale-DOWN
scale-DOWN: max-over-down-window(300s) ; scale-UP: min-over-up-window(0s) ; clamp [min,max] then rate-limit
  • Changing any default (tolerance, windows, rate caps, ready-exclusion, ceil-vs-round, MAX-combine) = behavior-break → asc-control major + opt-in behavior_profile: legacy|vN; same input MUST yield the same Decision within a major. Bug fixes that alter decisions pin old behavior behind a behavior_profile. Determinism + fail-safe are permanent, never gated away.

asctl ↔ ascaled + crate semver + MSRV

  • Handshake: asctl sends SemVer, ascaled replies min_compat; same major + asctl.minor <= ascaled.minor+1 supported, else clear error (no partial exec). RPCs (plan/status/history/apply) versioned, additive; removed RPC / newly-required field = protocol major. --output=json is parse-stable (additive only); human/table output is not stable.
  • Each asc-* crate follows Cargo SemVer independently (pre-1.0 may break on minor); re-exported types are part of the re-exporter's API. MSRV = 1.78, edition 2021; raising it = minor bump + CHANGELOG note, CI pins+tests the MSRV toolchain.

Profiling Methodology

  • CPU: perf record + cargo flamegraph on the 10k-series sim — aggregation + snapshot build dominate the flame, control math is a sliver. Allocation: dhat/heaptrack on a 1-hour run assert zero steady-state growth post-warmup (rings pre-allocated, scratch reused), massif for peak RSS vs cardinality. Regression: criterion + iai-callgrind (instruction-count, machine-independent) in CI; ±5% delta fails.

Where Time Goes

real tick wall-time = Σ scrape_latency (concurrent, = max not sum)   ~1–500 ms  ◄── dominates
                    + snapshot_build (aggregation × cardinality)     ~0.2–2 ms
                    + control math (HPA ratio·max·stabilize·clamp)   < 0.05 ms  ◄── negligible
                    + actuation set_scale (idempotent, often no-op)  ~1–50 ms (only on change)

Scrape latency dominates → control math is never the bottleneck. In-process cost = aggregation over windows × cardinality; P50/P90/P99 are costliest (partial sort, select_nth_unstable, O(n)), Avg/Sum/Max/Rate single-pass O(n). Downsampling at ingest caps per-series samples → bounds agg cost regardless of window duration.

Allocation Behavior

Fixed-capacity rings (cap = duration/resolution) pre-allocated at series creation, overwrite-oldest → zero steady-state allocation. MetricsSnapshot.per_metric/stale are reused scratch (cleared, not freed) per tick. P* aggregation borrows a reused Vec<Decimal> sized to ring cap, select_nth_unstable in place — one bounded copy. Decision.reason: String is the only routine per-tick heap alloc on a scaling change; NoOp ticks (the common case) allocate nothing.

Decimal vs f64 (determinism cost)

Decimal over f64 for determinism + replayability (§4): no platform float drift in ceil(current × ratio). Overhead ≈ 8–20× (~3–6 ns → ~40–90 ns/op), but per tick the math is O(metrics) ≈ 1–8 divisions+ceils = a few hundred ns, dwarfed by ~1–500 ms scrape (~10⁻⁸ of a 15–60 s cycle) — determinism >> nanoseconds. Agg accumulators use Decimal to avoid catastrophic-cancellation drift over large windows.

Concurrency & Contention

Scrapers run concurrently (Tokio task per source, bounded join over fetch-timeout) → merged into one frozen snapshot. The control tick is serialized per target (owned &mut Controller): HPA math, stabilization scan, cooldown, rate-limit are single-threaded, no locks in the math path, no contention/false-sharing. Cross-target parallelism = independent Controllers on separate tasks (per-target state, not global) → linear with target count up to core count; StabilizationBuffer is per-target, never shared.

Memory Scaling

mem ≈ S × (R × sizeof(Sample) + labels) + audit_log_window
  S = series cardinality; R = ring capacity = window.duration / window.resolution; sizeof(Sample) = 16–24 B
e.g. S=10k, R=300, 24 B/sample ≈ 72 MB rings + label overhead ≈ ~120 MB total

Linear in cardinality × window-samples; window duration decoupled from cost via downsampling resolution. DecisionLog is bounded (ring/time-windowed retention) → constant durable footprint, off the hot path. High-cardinality mitigation: per-series cap + label-set quota; reject/shed beyond budget rather than grow unbounded.

Tail Latency (a slow source must not stall the loop)

Every fetch runs under a bounded timeout (default 2 s, < sync_period); on timeout the metric is marked stale and the tick proceeds with last-good aggregates — the concurrent join completes at the timeout, not the slow source, so wall-time is bounded by max(timeouts), never Σ. The stale-metric fail-safe (§4) excludes a stale metric from scale-down, so tail-latency degradation is safe (biased toward holding capacity). p99 loop period stays within sync_period + fetch_timeout; a degraded Condition surfaces when fallback fires — slow sources are observable, not silent.

Scalability Analysis

Cost model along five axes: number of targets, metric cardinality, scrape fan-out, cluster size, sync cadence. The dominant in-process axis is metric cardinality (O(series × window/resolution) memory + aggregation); everything else is bounded or horizontally shardable.

  • Per-target state = 1 Controller+StabilizationBuffer+Cooldown+last snapshot (~few KB + rings); tick CPU independent (no shared math lock) → embarrassingly parallel across targets. Horizontal scaling: multi-target sharding

  • Shard targets across ascaled daemons, each authoritative for a disjoint TargetRef set; per-target state (stabilization/cooldown/log) is local → no cross-daemon coordination on the hot path.   • Requires a per-target ownership lease / leader election. Mental Models & First Principles

The compressed insights an expert holds. Each: model · what it predicts · the bug you write without it · where applied (resolving section).

MM1 — Stability is set by the guards, not the gain. The HPA ratio is trivial; stability comes from deadband + stabilization + cooldown + rate-limit. Predicts: incidents are guard-tuning, never the formula. Bug: "fixing flapping" by editing the ratio. Applied: P6.1, Phase 4 (## 16), Failure Modes F1.

MM2 — Absence of a signal is not a signal of absence. A missing/stale metric is unknown, not low; treating it as 0 is the #1 autoscaling outage. Predicts: any gap reaching the math scales to min mid-peak. Bug: "Prometheus blip → util 0 → scaled to min → cascade." Applied: P6.3, Inv-3, Phase 6 (## 18), Threat Model T2.

MM3 — Scaling is asymmetric: slow-up is an outage, slow-down is a cost. Up/down are not mirror ops; windows/cooldowns/rates differ. Predicts: symmetric tuning thrashes (fast down) or wastes (slow up). Bug: a 30 s dip sheds capacity that cold-starts under the returning wave. Applied: P6.6, ADR-009, Phase 4 (## 16).

MM4 — A new replica carries no load yet; count only ready. Dividing by all replicas deflates utilization and double-counts the in-flight scale-up. Predicts: unready-counting → a sawtooth no stabilization removes. Bug: 5→10, 5 new report 0%, avg halves, loop reverses → orbit. Applied: P6.8, Inv-8, ADR-006, §8.1, Phase 3 (## 15), Failure Modes F5.

MM5 — Never trust your own last write. Level-triggered: re-read truth each tick, reconcile observed→desired; edge-triggered diverges the instant a write is dropped/clamped/overridden. Predicts: edge-triggered accumulates silent drift. Bug: a quota-rejected set_scale believed successful → permanent under-capacity. Applied: P6.5, Inv-7, ADR-014, Phase 5 (## 17), Phase 10 (## 22).

MM6 — Determinism is a feature of the math, bought by banishing wall-clock/RNG/float. A pure (snapshot,policy,state,now)→Decision is replayable+testable+fuzzable+auditable; any impurity forfeits all four. Predicts: the first Instant::now()/f64 makes sim and prod disagree. Bug: 0.1+0.2≠0.3 flips a tolerance-edge decision; tests flake. Applied: P6.4, Inv-4, ADR-005/021, Phase 3 (## 15), Phase 12 (## 24).

MM7 — Bounds/guardrails are an outer envelope the math cannot widen. Policy bounds clamp last; global guardrails sit outside policy and hold even when the math is wrong. Predicts: a target ≈0 without an unconditional final clamp requests u32::MAX. Bug: a unit error inflates the ratio 1e6× and the clamp wasn't last → cluster-wide blast. Applied: P6.2/P6.10, Inv-1/11, Phase 11 (## 23).

MM8 — The metric you scale on may be the metric you are changing. Per-replica CPU falls as you add replicas — a self-coupled loop that oscillates regardless of guards. Predicts: some flapping is structural, fixed only by a leading/independent metric (queue depth), not tuning. Bug: endless tuning of a metric that cannot settle. Applied: Failure Modes F1/F5, Operational Readiness runbook, P6.7.

MM9 — Prediction may only add lead, never subtract safety. Blend predicted with reactive by MAX under a confidence gate; a forecast pre-warms but a low-confidence dip never shrinks live capacity. Predicts: any min/replace blend scales down into a real spike on a bad forecast. Bug: HW mis-fits a holiday → pre-scales down → outage. Applied: P6.11, Phase 8 (## 20), Threat Model T12, Failure Modes F8.

MM10 — At the cluster layer, the autoscaler can create the unschedulable demand it removes. Draining a node whose pods can't land, or violating a budget, strands workloads. Predicts: scale-down safety must be proven before cordon and re-proven before each eviction. Bug: a "tidy idle nodes" pass evicts pods with nowhere to go. Applied: P6.12, Inv-12, Phase 9 (## 21), Failure Modes F9.

Alternative Architectures (Roads Not Taken)

Fundamentally different designs for the same problem; each with sketch, the regime where it wins, the real system that embodies it, and why 269 rejected it.

ALT-1 — PID / continuous control loop. Treat replicas as a continuous manipulated variable; run a tuned proportional-integral-derivative controller against the metric error.

error = target - current ─► PID(Kp,Ki,Kd) ─► Δcapacity ─► actuate ─► (loop)
                                   ▲ integral term eliminates steady-state error

Wins: a continuous, real-valued actuator with no quantization and tolerable overshoot — CPU-frequency/thermal governors, admission-rate control. Embodied by: classical control systems (and project 289's PID toolkit). Rejected because: replica counts are discrete and integer; integral windup + derivative noise cause overshoot/oscillation on a quantized actuator with multi-tick actuation lag, and the proportional ratio already reaches target in ~1 step (ADR-004, MM1).

ALT-2 — Edge-triggered, event-sourced scaler. Drop the periodic loop; react to metric-threshold events (alarm crossed → emit a scale command), never re-reading full state.

metric stream ─► threshold alarm ─► scale event ─► command queue ─► actuator
                                            (no periodic reconcile, no re-read)

Wins: very low actuation latency and minimal idle work when events are reliable, totally-ordered, and exactly-once — a single-process in-memory autoscaler on a trusted bus. Embodied by: classic CloudWatch-alarm → ASG step actions (event-driven). Rejected because: on a real distributed target, events are lost/reordered/duplicated; an edge-triggered scaler accumulates silent drift and never self-heals. 269 is level-triggered: re-read truth each tick, reconcile observed→desired (P6.5, Inv-7, MM5).

ALT-3 — Centralized control plane (stateless workers + shared store). One global scheduler owns all autoscaling state in a replicated store; thin stateless workers execute decisions; coordination via the store.

                ┌──────── global decision store (Raft) ────────┐
   workers ───► │ targets · policies · decisions · leases       │ ◄─── workers
                └──────────────────────────────────────────────┘
                 every decision is a transaction on the store

Wins: a very large multi-tenant fleet needing org-wide policy, cross-target coordination, and a single audit plane (thousands of targets across regions). Embodied by: cloud-provider managed autoscaling control planes (AWS Application Auto Scaling shape). Rejected because: it adds consensus on the hot path (latency + operational weight) for a problem that is embarrassingly parallel per target — 269 keeps state per-target-local and shards by target_ref, paying coordination cost only at lease handover (Scalability), not per tick.

ALT-4 — Pure forecast-driven (open-loop) provisioning. Provision entirely from a forecast model; no reactive ratio loop — capacity follows the predicted curve.

history ─► forecaster (ML/seasonal) ─► predicted load(t+h) ─► provision(t) ─► (no feedback on error)

Wins: highly predictable, strongly seasonal load with long warm-up where reacting is always too late, and a mature forecasting/ML team — large consumer services with stable diurnal/weekly patterns. Embodied by: Netflix Scryer / AWS predictive scaling (in their pure form). Rejected because: an open loop has no fail-safe — a regime change or forecast error provisions wrong with nothing to catch it. 269 keeps prediction strictly additive over an authoritative reactive floor with a confidence gate (P6.11, Phase 8 ## 20, MM9).

Glossary

Term Definition (implementation-relevant)
metric A named, labeled signal the autoscaler reacts to (e.g. cpu utilization, queue depth). One of three MetricKinds: Resource, Custom, External. Identified by MetricId.
sample A single Sample { ts, value: Decimal }: one observation at a monotonic Timestamp. Value is Decimal (fixed-point) to avoid float drift in desired-replica math.
series A Series { labels: BTreeMap, ring: RingBuffer<Sample> }: one label-set's time-ordered samples in a fixed-capacity ring buffer. Per-series, not global.
aggregation Aggregation enum reducing a Window of samples to one AggValue: Avg, Sum, Rate, P50, P90, P99, Max. Rate = delta/Δt for counters; percentiles for latency-style metrics.
window Window { duration, resolution }: the look-back span over which an Aggregation runs. duration = how far back; resolution = bucket size.
resolution Bucket/step size inside a Window; samples within one resolution bucket are pre-reduced (downsampled). Trades memory vs fidelity.
downsampling Reducing high-frequency samples to one-per-resolution-bucket on ingest, bounding ring-buffer memory and aggregation cost while preserving the window's shape.
staleness MetricSource::last_scrape_age() exceeding a threshold → metric marked in MetricsSnapshot.stale. Stale metrics are excluded from the tick and trigger fail-safe (no scale-down).
MetricsSnapshot MetricsSnapshot { at, per_metric, stale }: the FROZEN, immutable per-tick input to the control law. Pinning it makes tick() deterministic + replayable.
resource metric MetricKind::Resource: per-replica cpu/mem utilization, averaged over ready replicas. Drives Utilization target type.
custom metric MetricKind::Custom: a per-object application metric (e.g. requests/sec per pod). Drives AverageValue/Value.
external metric MetricKind::External: a metric not tied to a scaled object (queue length, SQS depth, Kafka lag). KEDA-style event-driven scaling input.
target value The desired operating point for a metric; the denominator in the HPA ratio. Encoded by TargetType.
target type TargetType: how a target value is interpreted — Utilization(0..1) (fraction of request), AverageValue (per-ready-replica), Value (absolute, not divided by replicas).
tolerance band TargetTracking.tolerance (default 0.1): if |ratio - 1.0| <= tolerance → NoOp. The primary anti-flap guard against acting on noise.
desired replicas The output of the control law: ceil(currentReplicas * (current/target)), then clamped to [min, max], stabilized, and rate-limited → Decision.to.
current replicas The replica count observed now via ScaleStatus.current. The HPA-ratio multiplier.
ready replicas ScaleStatus.ready: replicas passing readiness. The current-value average is computed over READY replicas only, so warming-up replicas don't double-count a scale-up.
the HPA proportional algorithm desiredReplicas = ceil(currentReplicas * (currentMetricValue / targetMetricValue)) over ready replicas, with tolerance NoOp band, then [min,max] clamp. The core control law.
scaling policy Policy { target_ref, bounds, rules: Vec<ScalingRule>, sync_period }: declarative spec binding metrics+targets to one ScalableTarget.
target-tracking ScalingRule::TargetTracking: hold a metric at a target value via the HPA ratio. The default reactive rule.
step scaling ScalingRule::Step(StepPolicy): breach magnitude → discrete replica delta via Vec<Step>. Larger breach → larger step.
scheduled scaling ScalingRule::Scheduled(ScheduledPolicy { schedule: Cron, bounds }): time-window min/max override (e.g. raise floor before a known peak).
predictive scaling ScalingRule::Predictive(PredictivePolicy): scale ahead of forecasted load (AWS predictive / Netflix Scryer style) using asc-predict forecasts.
bounds (min/max) Bounds { min, max }: hard u32 limits. INVARIANT: min <= desired <= max. Final clamp on every Decision; safety floor/ceiling.
control loop The level-triggered reconciler in asc-control: re-reads metrics + ScaleStatus every sync_period and recomputes from scratch (never trusts its last write).
tick One iteration: Controller::tick(now) -> Decision. Serialized per target. Pure function of MetricsSnapshot + policy + state + stabilization history.
sync period Policy.sync_period: the control-loop cadence (e.g. 15 s). How often a tick runs.
Decision Decision { from, to, direction, reason, metrics, at, recommended_only }: the full, auditable record of one tick's computation and outcome.
scale direction ScaleDirection { Up, Down, None }: classifies a Decision; gates direction-specific cooldown + stabilization + rate limits.
scale-up to > from (ScaleDirection::Up): governed by the up-stabilization window (min-over-window, default 0) + up-cooldown + up-rate-limit.
scale-down to < from (ScaleDirection::Down): governed by the down-stabilization window (max-over-window, default 300 s) + down-cooldown + down-rate-limit. Suppressed on stale/missing metrics.
NoOp ScaleDirection::None: tolerance band satisfied, or stabilization/cooldown/rate-limit blocked the change. to == from. The expected steady-state outcome.
stabilization window StabilizationBuffer: ring of (ts, recommended). Scale-DOWN uses MAX over the down-window (shrink only if even the most aggressive recent rec agreed); scale-UP uses MIN over the up-window.
cooldown Cooldown { scale_up, scale_down, last_scale }: minimum quiet time after a scale before another in the same direction. Blunt thrash guard layered atop stabilization.
rate limit RateLimit { max_up_per_period, max_down_per_period, period }: caps change per period (e.g. +4 pods or +100% / 60 s). Applied AFTER stabilization.
hysteresis Asymmetric scale-up vs scale-down behavior (eager up, reluctant down via longer down-stabilization) so the system doesn't oscillate around the target.
flapping / thrash Rapid up/down oscillation from acting on noise. Prevented by tolerance band + stabilization + cooldown + rate limits + hysteresis. A primary failure mode + test target.
convergence Reaching and holding desired ≈ target within bounds after a load change, without overshoot/oscillation. Property-tested under step load in Phase 12.
idempotent actuation ScalableTarget::set_scale(n): re-applying the same n is a no-op at the target. Controller never assumes its write took effect; re-reads scale_status next tick.
ScalableTarget The actuation abstraction: scale_status(), idempotent set_scale(desired), ref_id(). Drivers: process pool, Deployment adapter (#268), node group.
scale subresource The narrow scale-only interface on a target (read ScaleStatus, write desired) — modeled on Kubernetes /scale; the Deployment adapter (#268) speaks it.
readiness gating Scaling decisions use only ready replicas (ScaleStatus.ready); unready/starting replicas are excluded from the current-value average to avoid double-counting a pending scale-up.
recommend-only / dry-run Decision.recommended_only = true: compute the full Decision + log it but DO NOT call set_scale. The shadow/validation surface (asctl plan).
forecast Forecast { value, confidence, horizon }: a Forecaster's predicted metric value at a future horizon, with a 0..1 confidence used for fallback.
EWMA Ewma { alpha }: exponentially-weighted moving average. Cheap, single-parameter Forecaster; smooths short-term noise.
Holt-Winters HoltWinters: triple-exponential smoothing (level + trend + seasonal). The seasonal Forecaster for diurnal/weekly patterns.
seasonal A repeating periodic pattern (e.g. daily/weekly) the HoltWinters seasonal component models for predictive scaling.
confidence Forecast.confidence (0..1): forecast trustworthiness. Below a threshold → blend falls back to the reactive desired (fail toward proven control).
cluster autoscaler asc-cluster: scales the cluster's NODES (not replicas) by adding node-group capacity for pending demand and draining underutilized nodes.
node group NodeGroup { id, bounds, current, template }: a homogeneous, independently-scalable set of nodes with its own Bounds and NodeTemplate.
pending / unschedulable Workload units that cannot be placed on existing nodes (insufficient capacity). The scale-UP trigger for the cluster autoscaler.
scale-up plan ScaleUpPlan { group, add }: the SMALLEST node-group addition (found via bin-packing simulation) that lets all pending units schedule.
scale-down candidate ScaleDownCandidate { node, utilization }: an underutilized node eligible for removal — only if all its workload can reschedule elsewhere AND disruption budgets allow.
cordon Mark a node unschedulable (no new placements) prior to draining, so it can be safely emptied.
drain Evict and reschedule a cordoned node's workload onto other capacity before removing it. Respects disruption budgets.
disruption budget A constraint on how many replicas of a workload may be voluntarily evicted at once; drains must respect it, else the scale-down candidate is rejected.
decision log / audit DecisionLog: append-only, replayable record of every Decision + ScalingEvent (applied?/error). The durable audit trail; enables deterministic replay.
fail-safe On source failure / total staleness: HOLD — no scale-down (can't prove safe shrink), optionally no action — and surface a degraded Condition, rather than acting on bad data.
guardrail Hard outer safety limits independent of policy math: max scale rate, emergency freeze, sanity bounds. Last line of defense against a runaway or buggy Decision.
