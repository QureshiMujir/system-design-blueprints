Mental Models & First Principles

The compressed insights an expert in build systems holds. Each predicts a bug class. Every cited § resolves to a real heading.

MM1. The action key is a pure function of inputs; the cache is just a memo table. key = hash(command, input digests, env, tool digest); identical key ⇒ identical output, fetchable instead of executed. Predicts: the ≥ 95% warm-cache hit rate. Bug without it: omitting any real input (env var, tool version) from the key → a stale cache hit serving wrong outputs. Applied: §8 (ActionKey), Phase 6–7, §4.3 (cache hit rate), I-correctness.

MM2. Correctness depends on fingerprinting content, not timestamps. mtime is a fast-path hint; the source of truth is the content digest. Predicts: correct rebuilds after touch-without-change or clock skew. Bug without it: trusting mtime alone rebuilds unchanged files (waste) or skips changed-but-same-mtime files (corruption). Applied: §8 (fingerprint), Phase 5, §4.1 (incremental eval / fingerprint throughput).

MM3. Early cutoff is the real speedup: stop when a derived output is unchanged. A node going green means its dependents need not re-run even if an upstream input changed but produced the same output. Predicts: why a comment-only edit rebuilds almost nothing. Bug without it: propagating "dirty" transitively without checking output equality → rebuilding the world for a no-op change. Applied: Phase 6 (early cutoff), §8 (NodeState green/red), §4.3.

MM4. Hermeticity is the precondition for caching: an action must declare all its inputs. An undeclared input (a system header, an env var) makes the cache unsound. Predicts: why sandboxing detects undeclared reads. Bug without it: a cached action that secretly depended on /usr/include serves wrong results on a different machine. Applied: Phase 8 (sandbox), §4.6 (undeclared input detected), MM1.

MM5. The build is a DAG; cycles are a user error to detect, not to tolerate. Topological order is the only valid execution order; a cycle has none. Predicts: the cycle-detection requirement and critical-path scheduling. Bug without it: a cycle causes deadlock or infinite re-eval instead of a clear error. Applied: §8 (graph model), Phase 2–4, §4.1 (graph construction).

MM6. The critical path, not the core count, bounds build time. Once enough cores exist, wall time is the longest dependency chain. Predicts: why scheduling priority should favor critical-path nodes. Bug without it: a naive FIFO scheduler runs cheap leaf nodes first and stalls on the critical path. Applied: §8 (scheduler), ADR-08, §4.3 (scheduler throughput).

MM7. Content addressing makes the cache deduplicating and verifiable for free. A blob is named by its hash, so identical content stored once and integrity is self-checking. Predicts: the ≤ 1.05× storage amplification. Bug without it: storing by path/name duplicates identical outputs and cannot detect corruption. Applied: §8 (CAS), §4.1 (CAS amplification), ADR-04.

MM8. A null build must be nearly free, or incrementality is a lie. With zero dirty nodes the engine should stat inputs and exit in milliseconds, never hash everything. Predicts: the ≤ 50 ms null-build target. Bug without it: re-fingerprinting the whole tree every invocation makes "incremental" builds O(repo size). Applied: §4.1 / §4.3 (null build), Phase 4, MM2.

MM9. Persisted state is a cache of the graph, reconstructable by re-evaluation. If the incremental DB is corrupt, full re-eval is always a correct fallback. Predicts: the ≤ 10 s crash-recovery path. Bug without it: trusting a corrupt persisted state poisons every subsequent build. Applied: §4.6 (corrupt DB → full re-eval), Phase 9, §4.1 (persist read/write).

MM10. Non-determinism is the cache's enemy; detect it before it poisons. An action that produces different outputs from identical inputs breaks MM1; re-exec-and-compare catches it. Predicts: the reproducibility-check design. Bug without it: a non-deterministic action caches one of its outputs and serves it forever, masking real changes. Applied: ADR-25 (repro check), §4.6 (non-deterministic), Phase 13–14.

Glossary · 50 terms · site-wide glossary

Action
Hermetic unit of work: (command, declared inputs, declared outputs, env, tool digest) → produces output files. Abstract; language-agnostic.
ActionKey
Digest = blake3(command ‖ sorted_input_digests ‖ env_hash ‖ tool_digest). Content-addressed cache key for an action invocation. Identical ActionKey → identical outputs (hermeticity requirement).
Action Cache
ActionKey → CacheEntry map (local + remote). Hit: materialize outputs from CAS, skip exec. Miss: execute and populate.
Build Graph
DAG of BuildNodes: sources, actions, globs, groups. Edges encode declared dependency relationships. Acyclicity enforced at construction and at dynamic-dep insertion.
CAS (Content-Addressed Store)
Blob store keyed by Digest. CAS object retrieved only by hash; no mutable keys. Shared between local cache and remote cache. Supports both local-disk and remote (REAPI) backends.
CasObject
{ digest: Digest, bytes: Vec<u8> }. Atomic blob in the CAS. Integrity: stored hash must equal blake3(bytes).
Clean (NodeState)
last_verified == current_revision AND all transitive inputs verified. No rebuild needed. Corresponds to Salsa "green".
Critical Path
Longest weighted path (by estimated or measured exec duration) through the ready DAG. ibg-sched prioritizes tasks on it to minimize wall-clock build time.
Cycle Freedom
Invariant: the build graph is always a DAG. Dynamic dependency insertion that would form a cycle → IbgError::CycleDetected; never deadlocks scheduler.
Declared Inputs
Set of NodeIds an action explicitly declares as inputs at graph-construction time. If an action reads a file NOT in declared inputs → undeclared-input violation, detected by sandbox, build fails loudly.
Declared Outputs
Set of PathBufs an action promises to produce. Enforced post-exec: missing → IbgError::MissingOutput; extra files → undeclared-output warning or error (sandbox policy).
Demand-Driven / Pull-Based Eval
Engine evaluates only nodes required by the build request (targets), pulling dependencies lazily. Unreachable nodes are never evaluated.
Dirty (NodeState)
Node requires re-evaluation: either fingerprint changed, revision counter advanced, or transitive dirty ancestor found. Corresponds to Salsa "red".
Digest
[u8; 32] — blake3 hash of file contents or serialized structures. Canonical fingerprint for change detection and cache keying.
Dynamic Dependency
Edge { kind: Dynamic } discovered at action evaluation time (e.g., depfile or runtime-declared dep). Inserted into graph with discovered_at: Revision. Creates new incremental edges for future builds. Must not form cycles.
Early Cutoff
When a dirty node is re-evaluated and its output Digest is unchanged vs. prior run, dependents remain Clean at current Revision. Propagation stops. Analogous to Shake's "changed" check and Salsa's "verified" shortcut.
Edge
`{ from: NodeId, to: NodeId, kind: Static
Fan-in / Fan-out
Fan-in: a node with many dependents (e.g., a widely-shared library). Fan-out: a node with many dependencies. High fan-in amplifies early-cutoff value; high fan-out amplifies parallelism.
Fingerprint
Content digest of a file or structured value used to detect changes without reading full content where possible (stat fast-path: mtime+size shortcut before blake3).
Glob Node
NodeKind::Glob { pattern }. Represents a file-set matched by a glob pattern. Invalidated when matched file set or contents change. Produces a list of source NodeIds.
Group Node
NodeKind::Group. Aggregates multiple nodes under one logical target. No exec; just a structural alias for a set of deps.
Hermetic Action
Action whose outputs depend only on declared inputs, command, env, and tools — no hidden filesystem reads, no network, no timestamps. Same ActionKey → byte-identical outputs.
ibg-core
Root crate: fundamental types shared across all crates (NodeId, Revision, Digest, ActionKey, NodeState, IbgError, …). No logic, no I/O.
Incremental Computation
Only the minimal subgraph affected by a change is re-evaluated. Based on revision-counter dirtiness propagation, memoized results, and early cutoff.
Invalidation
Marking a node Dirty because its fingerprint changed or a dependency's last_changed advanced. Propagated forward through reverse-dep edges.
IbgError
Top-level error enum covering: CycleDetected, UndeclaredInput, MissingOutput, ExecFailed, CacheCorrupt, PersistCorrupt, RemoteUnavailable, ResourceExhausted, Timeout, SchemaVersionMismatch.
Memoization
Per-node storage of (ActionKey, output Digest, Revision). On next eval: if ActionKey matches stored key, return memoized result without exec. Cache lookup before memoization check.
Merkle Input Tree
Hierarchical content-addressed tree of input file digests, computed by ibg-remote. Used for remote cache keying and remote execution input upload per REAPI spec.
Minimal Rebuild
Property: a node re-executes IFF its ActionKey changed AND no cache hit exists. No spurious rebuilds; no missed rebuilds.
NodeId
u32 — dense integer ID for a BuildNode. Stable within a persisted graph; remapped if the graph is rebuilt from scratch.
NodeKey
Stable human-meaningful identity string for a node (e.g., "//src/lib:compile"). Maps to NodeId via the graph index. Used for persistent state correlation across invocations.
NodeKind
enum { Source { path: PathBuf }, Action(ActionId), Glob { pattern: String }, Group }. Determines eval semantics.
NodeState
`{ last_verified: Revision, last_changed: Revision, output_digest: Option<Digest>, status: Clean
Over-build
Correctness bug: rebuilding a node whose inputs did not actually change. Wastes time; never produces wrong output. Prevented by fingerprint checks + memoization.
Ready Queue
ibg-sched structure: set of actions whose declared inputs are all Clean. Actions dequeued by worker threads. Ordered by critical-path weight.
Red/Green (Revision Counters)
Salsa-derived metaphor. last_changed < last_verified → green (Clean). last_changed == current_revision → red (Dirty). Revision monotonically increases each build cycle.
Remote Cache
REAPI-compatible content-addressed cache reachable over gRPC. ibg-remote uploads (ActionKey, output tree) and queries before local exec. Hit: materialize locally from CAS.
Reproducibility Check
Re-executing a hermetic action with same ActionKey and asserting output digests match prior run. Detects non-deterministic actions. Controlled by --check-determinism policy.
Revision
u64 — monotonically increasing global counter. Incremented once per build invocation (or more finely per change detection cycle). Drives red/green accounting.
Reverse-Dependency Edge
Edge to → from (inverted DAG). Used by ibg-watch and ibg-engine to propagate Dirty forward from a changed source to all transitive dependents.
Running (NodeState)
Transient: action dispatched to ibg-exec, not yet complete. Prevents duplicate scheduling.
Salsa
Red/green revision-based incremental query engine (rust-analyzer). Conceptual model for ibg-engine's last_verified/last_changed revision accounting and early cutoff.
Sandbox
Execution environment enforcing hermeticity: intercepts syscalls or uses OS-level isolation (namespaces/seccomp on Linux, sandbox-exec on macOS) to detect undeclared reads/writes.
Source Node
NodeKind::Source { path }. Leaf node: no dependencies. Digest computed by ibg-fingerprint from file contents. Invalidated by ibg-watch on fs event.
Stat Fast-Path
Before computing blake3 of a file, check (mtime, size, inode). If unchanged vs. stored stat, reuse stored Digest without hashing. Reduces I/O on large unchanged trees.
Topo Sort
Kahn's algorithm over the build DAG; used by ibg-graph for ordering and by ibg-sched for scheduling. Reverse-topo used for invalidation propagation.
Under-build
Correctness bug: serving stale output without detecting that an input changed. Never acceptable. Prevented by exhaustive fingerprint checks + sandbox undeclared-input detection.
Undeclared Input
A file read by an action at exec time but NOT listed in declared inputs. Breaks hermeticity; makes ActionKey non-deterministic. Detected by sandbox; build fails loud, never silently wrong.
Verified (NodeState)
Synonym for Clean. last_verified advanced to current_revision after confirming no fingerprint change — even without re-execution (early-cutoff case).
Work-Stealing Scheduler
ibg-sched model: each worker thread has a local deque of ready tasks; idle threads steal from the back of other deques. Minimizes contention; maximizes CPU utilization on irregular DAGs.
