Decisions (§9) · 30 ADRs

ADR-01

Implementation language

Chosen

Rust 2021, MSRV 1.78

Rejected

Go, Haskell, OCaml, C++

When the rejected choice is right

Go wins for contributor velocity where GC pauses are acceptable; C++ wins to integrate with an existing Bazel/Buck C++ core; Haskell/OCaml win for a research build system emphasizing purity/incrementality (Shake, Nix)

Why: Zero-cost ownership for graph state; no GC pauses on hot incremental path; fearless concurrency for work-stealing; mmap/io_uring access; strong ecosystem (tokio, blake3, dashmap).

ADR-02

Workspace build system

Chosen

Cargo workspace (single Cargo.toml)

Rejected

Bazel-for-Rust, Buck2

When the rejected choice is right

Bazel/Buck2 win for a polyglot monorepo needing hermetic, remote-cached builds across many languages — the very capability this tool reimplements

Why: Cargo is the standard; workspace crates map 1-to-1 to ibg-* crates; cargo test --workspace covers all.

ADR-03

Async runtime

Chosen

Tokio 1.x (multi-thread scheduler)

Rejected

async-std, smol, blocking threads

When the rejected choice is right

Blocking threads win for a purely CPU-bound local builder with no network remote cache or async I/O

Why: Tokio: production-grade, stable API, tokio::process, tokio::fs, tokio::sync; work-stealing built into runtime; broad ecosystem.

ADR-04

Content hashing

Chosen

blake3 crate (SIMD, parallel)

Rejected

SHA-256, SHA-1, xxHash, FNV

When the rejected choice is right

SHA-256 wins when REAPI/remote-cache interop mandates it; xxHash/FNV win for non-cryptographic local-only fingerprinting where raw speed beats collision resistance

Why: blake3: cryptographically sound, fastest general-purpose hash, tree-parallelism for large files, 32-byte output fits Digest([u8;32]).

ADR-05

Serialization (wire + storage)

Chosen

CBOR (ciborium crate)

Rejected

JSON, MessagePack, Protobuf, bincode

When the rejected choice is right

Protobuf wins for the REAPI gRPC wire (mandatory there); bincode wins for local-only state where schema evolution is unneeded; JSON for human-debuggable artifacts

Why: CBOR: self-describing, schema-flexible, compact, no generated code; ciborium is no_std-compatible; easy schema evolution with optional fields.

ADR-06

Incremental state DB

Chosen

SQLite (rusqlite, WAL mode)

Rejected

RocksDB, LMDB, custom B-tree, flat files

When the rejected choice is right

RocksDB wins for very large (>10M node) write-heavy graphs needing LSM throughput; LMDB wins for read-mostly zero-copy mmap access; a custom B-tree wins if SQLite becomes the bottleneck (as the rationale anticipates)

Why: SQLite WAL: atomic multi-table commit, crash-consistent, zero-dependency, portable; WAL fsync strategy tunable; sufficient for <10M node graphs. Phase 9 may introduce custom B-tree if SQLite proves bottleneck.

ADR-07

Concurrent hash map

Chosen

dashmap 5.x

Rejected

std::HashMap + RwLock, chashmap, flurry

When the rejected choice is right

A single RwLock<HashMap> wins for low-parallelism builds where shard overhead isn't justified; flurry wins for lock-free read-heavy workloads

Why: dashmap: shard-striped RwLock, low contention for high-parallelism graph traversal; avoids single global lock.

ADR-08

Work-stealing scheduler

Chosen

Custom deque (Chase-Lev) + crossbeam-deque

Rejected

Rayon, threadpool crate, tokio::spawn unbounded

When the rejected choice is right

Rayon wins when build actions are independent data-parallel tasks with no dependency gating or critical-path priority

Why: Build-graph scheduling requires domain-aware priority (critical path) + dependency gating; rayon's work-stealing is unaware of dep constraints; custom scheduler with crossbeam-deque primitives.

ADR-09

File watching

Chosen

notify crate (inotify/FSEvents/ReadDirChangesW)

Rejected

custom inotify, libuv, watchexec

When the rejected choice is right

A custom inotify/FSEvents layer wins when you need event semantics notify abstracts away, or on a platform notify does not support

Why: notify: cross-platform, active maintenance, debounce built-in; polling fallback for network FS.

ADR-10

Sandboxing (Linux)

Chosen

Linux namespaces + seccomp-bpf (nix crate)

Rejected

Docker, gVisor, bubblewrap

When the rejected choice is right

Docker/gVisor win when full container images or VM-grade isolation are required; bubblewrap wins for an unprivileged-user sandbox without manual namespace setup

Why: Namespaces: lightweight, kernel-native, no daemon; seccomp-bpf: syscall allowlist; nix crate provides safe wrappers.

ADR-11

Sandboxing (macOS)

Chosen

sandbox-exec + Seatbelt profile

Rejected

Docker-on-mac, virtualization

When the rejected choice is right

A VM/Docker-on-mac wins when sandbox-exec's deprecation/limitations bite and full isolation is required

Why: sandbox-exec is OS-native; avoids VM overhead; Seatbelt profile generated per-action from declared inputs.

ADR-12

Remote cache protocol

Chosen

Bazel REAPI v2 (prost-generated gRPC)

Rejected

custom HTTP REST, custom binary protocol

When the rejected choice is right

A custom HTTP/binary protocol wins when Bazel-ecosystem interop isn't needed and a leaner wire tuned to your own cache is preferable

Why: REAPI v2: industry standard; compatible with BuildBuddy, EngFlow, Remote Build Execution; prost + tonic for codegen.

ADR-13

gRPC stack

Chosen

tonic + prost

Rejected

grpcio (C bindings), h2 raw

When the rejected choice is right

grpcio (C core) wins when you need gRPC features tonic lacks or must share the upstream C++ gRPC implementation

Why: tonic: pure-Rust, Tokio-native, no C FFI; prost: fast protobuf codegen; strong type safety.

ADR-14

Logging

Chosen

tracing crate + tracing-subscriber (JSON + human fmt)

Rejected

log crate, slog, env_logger

When the rejected choice is right

log + env_logger wins for a minimal tool not needing per-node span semantics

Why: tracing: structured spans match build-event semantics (per-node, per-action); tokio integration; opentelemetry export.

ADR-15

Distributed tracing

Chosen

opentelemetry-rust + OTLP exporter

Rejected

Jaeger native, Zipkin

When the rejected choice is right

A native Jaeger/Zipkin SDK wins when locked to that backend and needing its specific features

Why: OTLP: vendor-neutral; works with Jaeger, Tempo, Honeycomb; spans for eval/exec/cache per node enable critical-path reconstruction.

ADR-16

Metrics

Chosen

metrics crate + metrics-exporter-prometheus

Rejected

When the rejected choice is right

statsd wins in an existing statsd/Graphite monitoring stack

Why: metrics: facade crate, swappable backend; Prometheus scrape endpoint for build dashboards; counters: cache_hits, cache_misses, exec_count, cutoff_count.

ADR-17

Testing framework

Chosen

cargo test + proptest (property) + criterion (bench) + nextest

Rejected

custom harness, quickcheck

When the rejected choice is right

A custom harness wins for non-Rust integration tests or hardware-specific validation

Why: nextest: parallel test execution, per-test timeout; proptest: stateful model testing for NodeState machine; criterion: stable micro-benchmarks.

ADR-18

Fuzzing

Chosen

cargo-fuzz (libfuzzer) on ibg-fingerprint, ibg-persist deserialize paths

Rejected

afl.rs, honggfuzz

When the rejected choice is right

afl.rs/honggfuzz win for advanced mutators or fuzzing a non-libFuzzer target

Why: cargo-fuzz: first-class Rust support; targets: Digest deserialization, CBOR decode, dep-file parse, ActionKey derivation.

ADR-19

CI/CD

Chosen

GitHub Actions; cargo test --workspace; cargo clippy -- -D warnings; cargo fmt --check

Rejected

Jenkins, CircleCI

When the rejected choice is right

Jenkins wins for complex on-prem pipelines; CircleCI wins for its specific caching/orb ecosystem

Why: GHA: free for open-source; matrix: stable + MSRV (1.78) + nightly (for miri); miri run on ibg-core unsafe.

ADR-20

Miri (UB detection)

Chosen

cargo miri test on ibg-core, ibg-fingerprint unsafe blocks

Rejected

Valgrind, address sanitizer

When the rejected choice is right

Valgrind/ASan win for FFI or non-Rust memory bugs Miri cannot interpret, and for sanitizing production binaries

Why: Miri: interprets MIR; catches UB in raw pointer ops for mmap and CAS paths; run in CI on nightly.

ADR-21

Benchmarking harness

Chosen

Rejected

When the rejected choice is right

Ad-hoc scripts win for one-off profiling not needing a stable regression baseline

Why: Benchmark types: cold-start DAG eval, 1-node-dirty incremental, fan-out 10k-leaf cache-hit; criterion measures wall-clock + CPU cycles.

ADR-25

Reproducibility verification

Chosen

--check-reproducibility flag: re-exec + digest compare

Rejected

When the rejected choice is right

Trusting the first run wins when all actions are known-deterministic and the re-exec cost isn't justified

ADR-30

Memory allocator

Chosen

system allocator default; jemallocator optional feature for ibg-cli

Rejected

mimalloc, snmalloc, tcmalloc

When the rejected choice is right

mimalloc/tcmalloc win when benchmarks show lower fragmentation than jemalloc for the daemon workload; the system allocator wins when avoiding any C dependency entirely

Why: jemalloc: lower fragmentation for long-running daemon mode (watch loop); opt-in to avoid mandatory C dependency in library crates.

Alternative Architectures (Roads Not Taken)

Alt-A — Timestamp-based incremental (Make/Ninja model).

target rebuilt iff any prerequisite mtime > target mtime; depfiles track discovered headers

Wins when: the build is local, single-machine, and speed/simplicity beat cross-machine cache correctness (a low-level executor behind CMake). Embodied by: Make, Ninja. Rejected because: mtime is unsound across machines and clock skew (MM2) and cannot support a shared content-addressed cache (MM1, MM7); content hashing is the price of correctness and remote caching.

Alt-B — Functional/demand-driven build (Shake/Nix model).

build = pure function; outputs demanded lazily; dependencies discovered dynamically during evaluation

Wins when: dependencies are dynamic/data-dependent and a purely functional, monadic build description fits (Haskell ecosystems, Nix derivations). Embodied by: Shake, Nix. Rejected (partly deferred) because: a static-then-incremental DAG (MM5) is simpler to schedule and reason about at this scope; dynamic dependency discovery is a deferred extension.

Alt-C — Remote execution fleet (not just caching).

actions dispatched to a worker farm; inputs uploaded to CAS; outputs downloaded; local machine orchestrates

Wins when: the build is too large for one machine and a worker fleet amortizes compute (huge monorepos). Embodied by: Bazel RBE, BuildBuddy, EngFlow. Rejected (deferred) because: remote caching gives most of the benefit at a fraction of the complexity; the worker fleet is in the Deferred Features Register.

Alt-D — Language-integrated incremental (compiler-internal, Salsa/rustc).

incremental computation inside one process: query system memoizes derived values with red-green tracking

Wins when: incrementality is needed within a single compiler/IDE process at sub-file granularity (rust-analyzer, rustc). Embodied by: Salsa, rustc query system. Rejected because: this is a cross-process build orchestrator at the action/file granularity; in-process query incrementality solves a different (finer) problem, though it shares the early-cutoff idea (MM3).
