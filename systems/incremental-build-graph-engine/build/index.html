⬜ Phase 0 — Skeleton — crates, core types, a tiny static action DAG; topo-evaluate it once unconditionally and run actions; print the order (no caching, no incrementality) §12

Objectives
  • Establish Cargo workspace: 14 crates (ibg-core … ibg-bench) in Cargo.toml; all compile clean on MSRV 1.78 (rust-toolchain.toml); ALL inter-crate API boundaries established even if bodies are todo!(), no circular deps (Cargo-enforced).
  • Define ALL canonical types from the spine in ibg-core (§11), complete not placeholder; ibg-graph implements a minimal static DAG (Source+Action nodes, typed edges, adjacency list, no cycle detection yet).
  • ibg-engine Phase-0 mode: unconditional topological walk (Kahn's), no memoization, no revision counters — runs every node every time; ibg-exec Phase-0 mode: spawn via std::process::Command, capture stdout/stderr/exit, no sandboxing.
  • ibg-cli driver: parse --target <NodeKey> from argv, build graph, run topo-eval, print execution order + per-node exit codes.
  • No caching, no incrementality, no persistence, no file watching, no sandbox — all deferred to later phases (§11 lists the exact type spine reused verbatim here).
Deliverable
  • cargo build --workspace zero warnings (#![deny(warnings)] every crate root); cargo test --workspace passes all Phase-0 tests; cargo doc --workspace --no-deps succeeds (all 14 crates documented).
  • ibg-cli --graph-fixture fixtures/phase0_triangle.json --target C prints topo order + executes 3 echo actions in DAG order, exits 0; Cargo dep graph: ibg-core ← everything, ibg-graph ← ibg-engine, no cycles.

Pitfalls
  • NodeId reuse after removal: SlotMap generational indices prevent stale-ID misreads (naive HashMap<u32,…> would let a removed+re-added node reuse an ID → silent wrong-node lookup, signal: spurious NodeNotFound); fix is the slotmap crate or an embedded generation field.
  • BTreeMap vs HashMap for EnvMap: HashMap iteration order is non-deterministic → ActionKey hash differs run-to-run for the same logical action → false cache misses later; invariant enforced by the EnvMap=BTreeMap type alias (the ActionKey Uniqueness invariant, §7).
  • Kahn's BFS mutable in-degree state: shared across concurrent calls → data race; Phase 0 is serial, but Phase 7's parallel scheduler must clone or snapshot immutably.
  • std::process::Command cwd not inherited: Cmd::cwd=None inherits the CLI process cwd, so actions assuming workspace root fail if invoked from a subdirectory; fix is canonicalizing cwd at CLI entry and passing it explicitly to ProcessExecutor.
  • Rustdoc #![deny(warnings)] + todo!(): emits "unreachable" warnings on stub impls; use #[allow(unreachable_code)] or typed panic strings instead of todo!().
  • Fixture JSON NodeId as u32 vs string: hand-edited string keys silently deserialize to 0 under serde_json; fix is #[serde(transparent)] on NodeId plus a fixture schema-validation test step.

⬜ Phase 1 — Build graph model — nodes (source/action/glob), typed edges, declared inputs/outputs, DAG construction, cycle detection, topological + reverse-dependency indexing §13

Objectives
  • Complete ibg-graph: production DAG with Source/Action/Glob/Group kinds; typed edges (Static at construction, Dynamic at eval time via DynamicDep), both enforced in adjacency structures.
  • Declared inputs/outputs: every Action carries resolved inputs:Vec<NodeId> + declared outputs:Vec<PathBuf>; cycle detection is DFS-based O(V+E), run per-add_edge (incremental) or at explicit validate(), mode selected via CycleCheckMode (the Cycle Freedom invariant, §7).
  • Topological index (cached Vec<NodeId>, Kahn's BFS, invalidated on structural mutation) and reverse-dependency index (rev_deps: HashMap<NodeId,Vec<NodeId>>, built at construction, consumed by ibg-watch in Phase 9) and key_map: HashMap<NodeKey,NodeId> for CLI --target resolution.
  • Glob nodes: pattern → Vec<NodeId> expansion via a GlobExpander trait (default impl uses the glob crate).
  • Architectural constraint: graph is immutable after seal(); dynamic-dep additions go through a separate DynDepRegistry, never graph mutation, to avoid locking the immutable core (§7.11).
Deliverable
  • ibg-graph API usable from ibg-engine/ibg-cli; cargo test -p ibg-graph passes all tests incl. proptest; --graph-fixture fixtures/phase1_large.json loads 1000-node graph, seals, prints GraphStats to stderr.
  • BuildGraph documented with invariants in rustdoc; cycle error messages include the full human-readable cycle path.

Pitfalls
  • DFS cycle check on incremental add_edge: O(V+E) per call, O(E·(V+E)) cumulative on large graphs; mitigate with CycleCheckMode::Deferred (check only at seal()), signaled via tracing::info!("cycle_check_ms=…").
  • OnceCell topo cache invalidation: add_edge after topo_sorted() without re-seal() serves stale topo; fix is topo_cache:Option<Vec<NodeId>> reset to None on every add_edge, and topo_sorted() panics unless sealed.
  • HashMap non-deterministic adjacency order: two runs of the same DAG can yield different (both valid) topo orders, flaking exact-order tests; fix with IndexMap or sorted adjacency, and assert validity not exact equality.
  • Glob expansion race: DefaultGlobExpander snapshots the filesystem at construction time; files added after are stale until ibg-watch (Phase 9) re-expands on the relevant FS event.
  • DynDepRegistry cycle via dynamic edge: a dynamic dep closing a cycle deadlocks the scheduler; add_dynamic_dep validates against sealed-graph reachability and rejects with GraphCycle (full dynamic-cycle detection is Phase 8's concern, per the Cycle Freedom invariant in §7).
  • SlotMap generational overflow: u32 space (2^32) is safe for any realistic graph; guarded by debug_assert!(nodes.len() < u32::MAX as usize). seal() on empty graph: valid, Ok(()), topo_sorted()=&[].

⬜ Phase 2 — Fingerprinting + change detection — file content digests (blake3), stat-based fast path (mtime/size/inode), action key = hash(command + input digests + env), digest cache §14

Objectives
  • Implement ibg-fingerprint: complete content-hash + change-detection subsystem, with NO dependency on ibg-graph/ibg-engine (pure file+hash+cache, §6.12 Minimal Coupling).
  • file_digest(path)->Result<Digest,IbgError> (blake3, chunked streaming); stat fast-path StatEntry{mtime,size,inode,dev} skips re-hash when all fields match a cached entry (P3).
  • DigestCache: in-memory HashMap<PathBuf,(StatEntry,Digest)> behind RwLock, persisted by ibg-persist in Phase 9; action_key(action,input_digests)->ActionKey hashes command||sorted_env||sorted input_digests (P6, Bazel ActionKey model).
  • is_dirty(path,cached_stat,cached_digest)->Dirtiness{StatMismatch|ContentChanged|Clean} drives engine decisions (StatMismatch→re-hash, ContentChanged→propagate dirty, Clean→early-cutoff candidate).
  • tool_digest(path)->Result<Digest,IbgError> hashes the action's tool binary, folded into ActionKey to detect tool upgrades.
Deliverable
  • cargo test -p ibg-fingerprint all passing; ibg-cli --digest <path> prints blake3:<hex>; DigestCache usable via Arc<Fingerprinter>; ActionKey verified deterministic across processes.
  • Bench baseline: cache-hit get_or_compute <1 µs; cache-miss (10 MB) <50 ms.

Malformed: empty file → valid 32-byte digest (not an error); directory path → IoError; null-byte binary → valid (blake3 is byte-agnostic).

Pitfalls
  • mtime resolution: FAT32/HFS+ 1–2s granularity lets two same-second writes share an mtime and return a stale cached digest; fix by also comparing size (force re-hash on mismatch regardless of mtime); modern Linux ext4/btrfs is nanosecond-precise.
  • Symlink vs target digest: policy is always follow symlinks (digest target content); a retarget to same-content file legitimately reports Clean under content-addressable semantics.
  • TOCTOU (file deleted between stat and read): stat_entry succeeds then file_digest gets IoError; treat as ContentChanged (gone = changed), propagate IoError so the engine marks the node Dirty.
  • RwLock write contention: 8+ threads hashing distinct files serialize on the single write-lock insert; mitigate via a 16-shard ShardedDigestCache (path-hash sharded, API-transparent).
  • ActionKey cross-platform non-determinism: normalize all PathBufs to forward-slash strings before hashing (Path::to_string_lossy().replace('\\','/')) so Windows/Unix agree.
  • Silent tool-binary changes: tool_digest=None → tool upgrade keeps the same ActionKey → stale hit; callers MUST set tool_digest, validated at the ibg-sandbox layer (Phase 10). blake3 SIMD: runtime AVX2/NEON detection with scalar fallback — correct either way, no action needed.

⬜ Phase 9 — File watching + invalidation — fs-event watcher, polling fallback, debounce, dirty propagation through reverse edges, watchman-style query, incremental re-eval of affected subgraph §21

Objectives
  • ibg-watch: fs-event watcher (inotify/kqueue/FSEvents) + polling fallback with identical semantics; tracks path→Vec<NodeId> and reverse edges (sourced from ibg-graph) for dirty propagation.
  • Debounce coalescing collapses event bursts into one invalidation signal per path within a configurable window (default 50 ms); exposes WatchHandle::changed_nodes()->Vec<NodeId> for targeted re-eval, no full-rebuild default.
  • Watchman-style query interface subscribes per glob/path set and returns the delta since a Revision (stateless fallback for CI).
  • Invariant: the dirty propagation set is always a superset of actually-changed transitive deps — never a subset (false-negative = correctness bug); false positives (over-build) are acceptable, under-build is not.

Pitfalls
  • Kernel overflow (inotify queue full): silent under-build if unhandled; detected via IN_Q_OVERFLOW/watch.kernel_overflow_count, recovered by a full re-stat of registered paths.
  • Cross-directory rename: split IN_MOVED_FROM/IN_MOVED_TO cookie pairs degrade to unmatched delete+create (acceptable over-build) — always re-register the new path so the create is never missed.

⬜ Phase 10 — Persistence — durable incremental state DB across invocations (graph, node states, revisions, digests), crash-consistent writes, schema-versioned, fall back to full eval on corruption §22

Objectives

  • Write transaction held open too long: blocks GC/inspect readers; flush only at the build-end boundary, never during action execution.
  • Revision written before node states: crash between them leaves a stale revision on reload (safe over-rebuild, never under-rebuild) — validated by checking loaded revision against the max last_changed in node_states.

⬜ Phase 11 — Hermeticity + sandboxing — sandboxed action execution, undeclared-input detection (the #1 cache-correctness bug), declared-output enforcement, reproducibility verification §23

Objectives
  • ibg-sandbox: wrap every exec in a hermetic environment — controlled filesystem view, declared-input-only reads, declared-output-only writes, controlled env, controlled working dir.
  • Undeclared-input detection: any filesystem read outside Action::inputs fails loudly with UndeclaredInput{action,path}; declared-output enforcement fails any write outside Action::outputs with UndeclaredOutput.
  • Reproducibility verification: opt-in double-execution comparing output digests, mismatch → NonDeterministic{action,digest_a,digest_b}, logged and never cached.
