4.4 Concurrency Constraints

  • Worker threads: min(max_jobs, num_cpus) rayon threads for CPU-bound graph work; tokio runtime with max_blocking_threads = 128 for I/O.
  • No global lock on DAG after construction phase; per-node Mutex<NodeState> or atomic CAS.
  • File descriptor limit: inotify watches capped at min(rlimit_nofile/2, 8192); excess paths fall back to polling.
  • NUMA: all arenas allocated on local node; no explicit NUMA binding (OS first-touch policy sufficient for current scope).

Back-of-Envelope Capacity Model

Numbers an expert computes before designing, each derived from §4.

  • C1 — Node arena memory. 1 M nodes × ~200 B (§4.2) = ~200 MB; with adjacency (~160 MB) and NodeState (~64 MB) the graph core is ~424 MB of the 2 GB ceiling (§4.1).
  • C2 — Edge memory. 10 M edges × 16 B (from+to, §4.2) = 160 MB; NodeId(u32) caps the graph at 4 GiB of node-id space (§4.1), far above the 1 M-node target.
  • C3 — Null-build budget. ≤ 50 ms for 1 M nodes (§4.1) ⇒ ≤ 50 ns/node of stat-fast-path work — far too little to hash, which is why mtime is the hint and content hashing is skipped when clean (MM2/MM8).
  • C4 — Fingerprint throughput. ≥ 500 MB/s (§4.1, blake3 SIMD): re-fingerprinting a 1 GB working set on a cold cache takes ≈ 2 s, bounding the corrupt-DB recovery path (§4.6).
  • C5 — Scheduler dispatch rate. ≤ 500 µs/node dispatch (§4.1) and ≥ 50 k actions/s (§4.3) ⇒ a 100 k-action build spends ≈ 2 s purely in scheduling, exclusive of execution.
  • C6 — Cache hit economics. ≥ 95% warm hit (§4.3): for a 1 M-node clean build, ≥ 950 k nodes are fetched/skipped and ≤ 50 k executed — the difference between a 30 s cached build (§4.3) and hours of cold execution.
  • C7 — CAS storage amplification. ≤ 1.05× (§4.1): content addressing means identical outputs across nodes/builds are stored once; the 5% overhead is index + small-blob padding (MM7).
  • C8 — Persist write budget. ≤ 200 ms for 100 k dirty nodes (§4.1) ⇒ ≤ 2 µs/node in a batched transaction with async fsync — batching is mandatory (per-node fsync would be ~1000× slower).
  • C9 — Remote cache RTT vs local exec. RTT p99 ≤ 200 ms/lookup (§4.1): a remote lookup only pays off if it saves more than 200 ms of local execution, so cheap actions should skip remote and execute locally (§4.6 fallback).
  • C10 — File-descriptor budget. ≤ 1024 fds/build (§4.1); inotify watches capped at min(rlimit/2, 8192) (§4.4) — beyond which paths fall back to polling, trading latency for fd headroom.
  • C11 — Incremental 1%-dirty cost. 10 k of 1 M nodes dirty ⇒ ≤ 500 ms eval+schedule excl. exec (§4.3): early cutoff (MM3) keeps re-evaluation proportional to the changed subgraph, not the whole graph.
  • C12 — Daemon heap ceiling. ≤ 2 GB total (§4.2) with jemalloc (ADR-30) to bound fragmentation across long-running watch-loop builds; OOM is a hard ResourceExhausted error, not a swap death-spiral.
