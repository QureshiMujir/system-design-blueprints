3. Architectural Overview

3.1 Canonical Architecture Diagram

Show the original text diagram
    build request (targets)
            |
      [ibg-graph] resolve graph: targets -> actions -> inputs (DAG); cycle check; topo + reverse-dep index
            |
      [ibg-engine] demand-driven eval per node: dirty?  (red/green via Revision counters)
            |   |-- [ibg-fingerprint] input digests changed? (stat fast-path -> content hash) -> recompute ActionKey
            |   |-- EARLY CUTOFF: inputs changed BUT action output digest unchanged -> stop; dependents stay verified
            |
      [ibg-cache] action-cache lookup: ActionKey -> hit? materialize outputs from CAS, skip exec
            |  miss
      [ibg-sched] schedule dirty actions by deps + job slots (work-stealing, critical path)
            |
      [ibg-exec] run action  ( [ibg-sandbox] hermetic: detect undeclared inputs, enforce declared outputs )
            |  output digests -> [ibg-cache] store (+ optional [ibg-remote] upload, Merkle input tree)
            |
      [ibg-persist] save graph + NodeStates + Revisions + digests for the next invocation
      [ibg-watch] fs events -> mark nodes Dirty via reverse edges -> next build re-evaluates only the affected subgraph
      [ibg-telemetry] taps eval / cache / exec / sched

3.2 Subsystem Descriptions

ibg-graph — DAG Model

  • Owns BuildNode arena (slab-allocated, NodeId(u32) index); source, action, glob, group node kinds.
  • Maintains adjacency list (deps) + reverse-dep index (rdeps) for O(1) fan-out lookup.
  • Cycle detection: DFS coloring on every add_edge; returns IbgError::CycleDetected immediately.
  • Topo index: Kahn's algorithm; drives engine evaluation order and scheduler priority.
  • Dynamic edges (Edge::Dynamic) added at runtime; triggers incremental re-topo + cycle re-check.
  • Trust boundary: graph is constructed by the front-end (CLI or DSL layer); ibg-graph validates but does not trust caller to be cycle-free.

ibg-engine — Demand-Driven Evaluator

  • Pull-based: evaluates only the transitive dependencies of requested targets.
  • Per-node NodeState { last_verified: Revision, last_changed: Revision, output_digest, status }.
  • Revision counter: global monotonic Revision(u64); incremented at each build invocation start.
  • Red/green: node is "green" (verified) if last_verified == current_revision; "red" (dirty) otherwise.
  • Memoization: if a node is already green, return its output_digest without re-evaluation.
  • Early cutoff: if inputs changed (ActionKey changed) but exec yields same output_digest → do NOT increment last_changed; dependents remain green.
  • Concurrency boundary: engine coordinates with scheduler via a NodeState lock per node (or epoch-based compare-and-swap); no global lock on the DAG.

ibg-fingerprint — Content Hashing

  • Stat fast-path: compare (mtime, size, inode) to cached values; if unchanged, skip full blake3 read.
  • Full hash: blake3::hash(file_bytes) → Digest([u8; 32]); stored in digest cache keyed by (path, mtime, size).
  • ActionKey computation: blake3(command_bytes || sorted(input_digests) || env_bytes || tool_digest).
  • Glob node: digest of sorted (path, file_digest) pairs matching the pattern.
  • Digest cache: HashMap<(PathBuf, u64 /*mtime*/, u64 /*size*/), Digest>; evicted on file change.

ibg-cache — Action Cache + CAS

  • Action cache: ActionKey → CacheEntry { outputs: Vec<Digest>, metadata: ExecMeta }.
  • CAS store: Digest → bytes; content-addressed, deduplication automatic.
  • Local backend: directory-sharded by first 2 hex bytes of digest; mmap for large blobs.
  • GC: mark-and-sweep; sweep unreferenced CAS objects after action-cache GC; configurable retention window.
  • Cache hit path: fetch CacheEntry, materialize each output from CAS to declared output path → skip exec entirely.
  • Trust invariant: a cache hit is correct IFF all declared inputs were correctly fingerprinted; sandbox enforces this.

ibg-sched — Work-Stealing Scheduler

  • Ready queue: actions whose all deps are green and slot is available.
  • Work-stealing: each worker thread has a local Chase-Lev deque; steals from tail of other queues when idle.
  • Critical-path ordering: nodes annotated with estimated cost (prior exec time from ibg-persist); highest-cost first.
  • Job-slot limits: configurable max_jobs; semaphore-based; resource-tagged actions (RAM, CPU) checked against limits.
  • Backpressure: if exec queue depth > threshold, ibg-engine pauses dispatching new nodes.
  • Concurrency boundary: scheduler communicates with engine via mpsc channels; exec via Arc<Mutex<NodeState>>.

ibg-exec — Action Executor

  • Spawns Command (Tokio async process); captures stdout/stderr; checks exit code.
  • Declared-output capture: after exec, reads each declared output path, computes Digest, stores in CAS.
  • Working-dir isolation: each action runs in a temp directory or sandboxed root.
  • Env control: action's EnvMap used verbatim; no ambient env leakage (hermetic actions strip host env).
  • CAS materialization: on cache hit, writes bytes from CAS to declared output paths with correct permissions.

ibg-sandbox — Hermetic Wrapper

  • Linux: mount namespace + pivot_root; bind-mount only declared inputs; seccomp filter; strace-based open syscall audit.
  • macOS: sandbox-exec profile restricting file access to declared inputs + outputs.
  • Undeclared input: any open/stat of a path outside declared inputs → action fails with IbgError::UndeclaredInput; never silently wrong.
  • Declared-output enforcement: after exec, verify each declared output exists; if missing → IbgError::MissingOutput.
  • Reproducibility check: optional two-run mode; compare output digests of both runs; mismatch → IbgError::NonDeterministic.

ibg-watch — File Watching + Invalidation

  • Uses inotify (Linux) / kqueue (macOS) via notify crate; polling fallback for network filesystems.
  • Debounce: coalesce rapid events within 50 ms window; only emit one invalidation per path.
  • Overflow handling: if event queue overflows → full workspace rescan (conservative; safe).
  • Dirty propagation: on path change, look up path → source node → walk reverse edges → mark all transitive dependents NodeState::Dirty.
  • Trust boundary: watch events come from OS; treated as advisory (engine re-fingerprints before deciding to rebuild).

ibg-persist — Durable State

  • Stores: NodeState per NodeId, Digest per (NodeId, Revision), graph structure snapshot, ActionKey history.
  • Backend: redb (pure Rust ACID embedded DB) or sled; pluggable via trait.
  • Crash consistency: writes via DB transaction; on open, validate last committed revision; corrupt/partial → fallback to full re-eval (never wrong incremental result).
  • Schema versioning: magic header + u32 schema version; migration table; forward-compat sentinel rejects unknown versions.
  • Persistence boundary: written at end of each successful build; read at engine startup.

ibg-remote — Remote Cache / Exec Interface

  • Implements Bazel REAPI client: ContentAddressableStorage + ActionCache + Execution gRPC services.
  • Merkle input tree: recursively hashes input directory tree per REAPI spec; uploads missing blobs.
  • Upload: check-then-upload (FindMissingBlobs → BatchUpdateBlobs / ByteStream).
  • Download: on remote cache hit, stream outputs into local CAS → materialize.
  • Protocol boundary: all remote I/O is async (tokio); timeouts + retry with exponential backoff.
  • Trust: remote cache is trusted for output bytes but NOT for ActionKey validity; engine re-verifies input fingerprints before accepting a remote hit.

ibg-telemetry — Metrics + Tracing

  • OpenTelemetry spans: per-node eval span, per-action exec span, cache-lookup span.
  • Counters: cache_hits, cache_misses, nodes_recomputed, nodes_early_cutoff, nodes_skipped.
  • Critical-path computation: post-build BFS on actual exec times; reports longest chain.
  • Export: OTLP exporter (Jaeger / Tempo compatible); optional JSON flamegraph output.
  • Tap points: ibg-engine emits node lifecycle events; ibg-cache emits hit/miss; ibg-sched emits queue-depth samples.

3.4 Async / Sync Boundary

  • Sync (rayon): graph traversal, fingerprinting, engine eval loop — CPU-bound; no await.
  • Async (tokio): action execution (process spawn + wait), file-watch event loop, remote cache I/O.
  • Bridge: tokio::task::spawn_blocking wraps sync graph/fingerprint work called from async exec path; rayon pool for bulk graph ops.
  • Channel types: tokio::sync::mpsc for watch→engine events; crossbeam::channel for sched↔exec handoff.

8.2 NodeState Machine

States: Dirty | Running | Clean | Failed

          file-watch event /
          input digest changed
  ┌──────────────────────────────┐
  │                              ▼
  │  [Clean] ─── engine eval ──► [Dirty] ─── scheduler picks up ──► [Running]
  │    ▲                                                                 │
  │    │  early cutoff OR cache hit                                      │
  │    │  output_digest unchanged                           exec ok      │
  │    └────────────────────────────────────────────────────────────────►┘
  │                                                            │ exec fail
  │                                                            ▼
  │                                                        [Failed]
  │                                                            │ retry / reset
  └────────────────────────────────────────────────────────────┘

State transitions (normative):

From Event Guard To Side-effect
Clean input digest changed any declared input Digest ≠ stored Dirty last_changed = current_revision
Clean file-watch invalidation reverse edge reachable Dirty propagate via reverse edges
Dirty scheduler dequeues all deps Clean Running slot acquired
Running exec completes, output digest = stored early cutoff check Clean last_verified = current_revision; dependents NOT re-dirtied
Running exec completes, output digest ≠ stored — Clean last_changed = current_revision; propagate dirty upward
Running exec fails — Failed error stored; dependents Failed
Failed build reset / --keep-going — Dirty re-enqueued
Any schema-version mismatch on load ibg-persist detects Dirty full re-eval; state wiped

Invariants:

  • last_verified ≤ current_revision always.
  • last_changed ≤ last_verified for Clean nodes.
  • status = Running only while a scheduler slot holds the node; crash → Dirty on next load.
  • A node in Running is never re-enqueued; scheduler holds exclusive ownership.

8.3 Revision Counter Protocol

Revision: u64, global monotonic, stored in ibg-persist.
Increment: once per build invocation (not per node).

Per-node fields:
  last_verified: Revision  — last revision at which node was proven correct
  last_changed:  Revision  — last revision at which node's output changed

Red/Green (Salsa semantics):
  "green" = last_verified == current_revision  (node verified this build)
  "red"   = last_verified <  current_revision  (needs re-check)

Demand-driven check algorithm (per node N, current revision R):

  1. If N.last_verified == R → return N.output_digest (memoized).
  2. For each dep D in N.deps: recursively check D.
  3. If all D.last_changed ≤ N.last_verified → mark N green (N.last_verified = R); no re-exec.
  4. Else: recompute ActionKey for N; cache-lookup; exec if miss.
  5. If new output_digest == N.output_digest → early cutoff: N.last_changed unchanged; N.last_verified = R.
  6. Else: N.output_digest = new; N.last_changed = R; N.last_verified = R; mark dependents red.

8.4 ActionKey Derivation

ActionKey = blake3(
    len(command_bytes) as u64 LE  ||
    command_bytes                  ||    -- argv + interpreter, normalized
    len(inputs) as u32 LE         ||
    sorted(input_digest_i)...     ||    -- Digest for each declared input, sorted by NodeId
    env_hash                      ||    -- blake3 of sorted (k=v) pairs, null-separated
    tool_digest                         -- digest of the tool binary (optional, may be zero)
)

Failure modes:

  • Undeclared input: action reads file not in inputs → ActionKey misses it → cache hit incorrectly served → sandbox detects at exec time, returns IbgError::UndeclaredInput; cache entry is poisoned (never stored).
  • Non-deterministic action: two execs with same ActionKey yield different output digests → reproducibility check fails; emit telemetry event NonDeterministicAction; cache stores first result; second result is discarded with warning.
  • Env leak: whitelist-only env propagation; unwhitelisted vars raise IbgError::EnvLeak before exec.

8.5 Content-Addressed Store (CAS) Layout

CAS root: $IBG_CACHE_DIR/cas/

File layout (flat, 2-level sharding):
  cas/<aa>/<bb>/<full-64-char-hex>   -- aa = hex[0..2], bb = hex[2..4]

Metadata sidecar (optional):
  cas/<aa>/<bb>/<full-hex>.meta      -- CBOR: {size, mtime_ns, refcount}

Action cache:
  $IBG_CACHE_DIR/ac/<aa>/<bb>/<action-key-hex>
  Content: CBOR-encoded CacheEntry { key, outputs: [Digest], metadata: ExecMeta }

GC strategy:
  Mark-sweep: walk AC entries; mark referenced CAS blobs; sweep unmarked.
  Epoch-based: entries older than --gc-max-age evicted first.
  Refcount sidecar used for concurrent GC safety (decrement before delete).

Storage invariants:

  • CAS objects are write-once; a blob with digest D never changes content.
  • AC entries reference only CAS blobs that exist; GC must delete AC entry before CAS blob.
  • Partial write: write to .tmp then rename (atomic on POSIX); partial file = absent.
  • Digest verification on read: blake3 recomputed, mismatch → IbgError::CasCorruption; entry evicted.

8.6 Graph Construction Protocol

Nodes registered in order: source → glob → action → group. DAG constraint enforced at registration:

  • register_action validates all inputs already registered → no forward references.
  • add_dynamic_dep(from, to, revision) validated: to must be already Clean; cycle check via DFS from to; if cycle detected → IbgError::CyclicDependency.
Graph API (normative call sequence):

  let mut g = BuildGraph::new();
  let src  = g.register_source(path)?;           -- NodeKind::Source
  let hdr  = g.register_source(header_path)?;
  let obj  = g.register_action(action, &[src, hdr])?;  -- NodeKind::Action
  let bin  = g.register_action(link_action, &[obj])?;
  g.finalize()?;  -- computes topo order, reverse-dep index; rejects cycles

Topo order: Kahn's algorithm; tie-break by NodeId (deterministic). Reverse-dep index: HashMap<NodeId, Vec<NodeId>> built once at finalize; used by ibg-watch for dirty propagation and by ibg-engine for early-cutoff upward marking.

Glob expansion:

  • GlobNode evaluated at graph construction time (eager) OR lazily on first demand.
  • Expansion → set of SourceNodes; re-expansion triggered if watch event modifies directory.
  • Glob re-expansion may add/remove nodes → graph re-finalized (incremental topo update via partial Kahn from changed subtree).

8.7 Dynamic Dependencies

Discovered at exec time; ibg-exec parses action stdout/stderr for dep-file format (Makefile .d or custom JSON):

DynamicDep format (JSON, written to declared output __deps.json):
  { "from": <action_id>, "deps": ["path/a.h", "path/b.h"], "revision": <u64> }

Protocol:

  1. ibg-exec captures __deps.json from action declared output (not from filesystem directly).
  2. ibg-engine calls g.add_dynamic_dep(action_node, discovered_source_node, revision) for each.
  3. Cycle check runs; failure → IbgError::CyclicDependency; action marked Failed.
  4. Dynamic dep stored in ibg-persist as Edge { kind: Dynamic, discovered_at: Revision }.
  5. On next build: if dynamic dep's source changed → action is re-dirtied even before re-exec (because it was a declared input in the previous build's stored graph).

Edge cases:

  • Dynamic dep to a node not yet in graph → auto-register as SourceNode; warn if path doesn't exist.
  • Dynamic dep to an ActionNode output → allowed; creates cross-action dep; topological re-sort required.
  • Dynamic dep removed (dep-file no longer lists it) → edge removed; node no longer triggers re-dirty.

8.8 Scheduler Domain Model

Work-stealing scheduler state:

Global state:
  ready_queue: BinaryHeap<(Priority, NodeId)>  -- min-heap by critical-path weight
  running: HashSet<NodeId>
  waiting: HashMap<NodeId, usize>              -- pending dep count
  slots: Semaphore(max_jobs)

Per-worker (N workers, N = --jobs):
  local_deque: WorkStealingDeque<NodeId>       -- chase-lev or similar

Priority = critical_path_estimate(node)
  = max over all ancestor chains: sum of estimated_cost(n) for n in chain
  Estimated cost: last exec duration from ibg-persist; default = 1 for unknown nodes.

Scheduling events (normative sequence):

Show the original text diagram
[engine marks N Dirty, all deps Clean]
  → enqueue(N, priority=critical_path(N)) into ready_queue
  → worker W pops N from local_deque (or steals from peer)
  → acquire slot (Semaphore::acquire)
  → mark N Running; hand off to ibg-exec
  → ibg-exec completes → engine updates NodeState
  → release slot; decrement waiting[M] for each M depending on N
  → enqueue M once its waiting[M] count reaches 0

Backpressure:

  • Semaphore bounds concurrent exec; workers block on acquire, preventing OOM from fan-out.
  • --jobs defaults to logical CPU count; reducible with --jobs=N.
  • Memory limit: optional --mem-limit=GB; exec refuses to start if RSS estimate exceeds limit.

Critical-path scheduling invariant: highest-priority node (longest downstream chain) is always dequeued first; guarantees near-optimal makespan for a given job-count.

Failure handling:

  • Worker panic → slot released; node re-marked Dirty with retry count incremented.
  • Retry limit (default 1): after --retry failures, node → Failed; dependents Failed.
  • --keep-going: scheduler continues building independent nodes even after a Failed node.

8.9 File-Watch Invalidation Protocol

Show the original text diagram
ibg-watch components:
  WatchBackend: inotify (Linux) | FSEvents (macOS) | ReadDirectoryChangesW (Windows) | poll fallback
  Debounce: 50 ms default; configurable --debounce-ms
  Event types: CREATE | MODIFY | DELETE | RENAME

Invalidation pipeline:
  raw event → debounce buffer → deduplicate by path
           → resolve path to NodeId (ibg-graph path index)
           → mark SourceNode Dirty (last_changed = pre-increment Revision)
           → walk reverse-dep index: BFS from dirty source
           → mark each reachable ActionNode Dirty (if currently Clean)
           → wake engine (Condvar / channel notify)

Edge cases:

  • Path not in graph → ignored (external file; no-op).
  • Directory event (inotify IN_CREATE on dir) → re-expand all GlobNodes whose pattern root is affected.
  • Rapid rename (A→tmp, B→A): debounce coalesces; final state resolved by stat at debounce flush.
  • Watch backend unavailable → fallback to stat-based polling at configurable interval (default 1 s).
  • Overflow event (inotify queue full) → conservative: mark ALL source nodes Dirty; full re-eval.

8.10 Persistence Schema

ibg-persist stores to $IBG_STATE_DIR/state.db (SQLite WAL mode, or custom B-tree TBD in Phase 9).

Schema (normative, SQLite DDL as reference):

TABLE nodes (
  node_id      INTEGER PRIMARY KEY,
  node_key     BLOB NOT NULL UNIQUE,   -- serialized NodeKey (CBOR)
  kind         INTEGER NOT NULL,       -- 0=Source,1=Action,2=Glob,3=Group
  last_verified INTEGER NOT NULL,      -- Revision
  last_changed  INTEGER NOT NULL,      -- Revision
  output_digest BLOB,                  -- NULL if no output
  status        INTEGER NOT NULL       -- 0=Clean,1=Dirty,2=Failed
)

TABLE edges (
  from_id   INTEGER NOT NULL,
  to_id     INTEGER NOT NULL,
  kind      INTEGER NOT NULL,         -- 0=Static,1=Dynamic
  discovered_at INTEGER,              -- Revision; NULL for Static
  PRIMARY KEY (from_id, to_id)
)

TABLE actions (
  action_id  INTEGER PRIMARY KEY,
  node_id    INTEGER NOT NULL,
  action_key BLOB NOT NULL,           -- Digest (32 bytes)
  command    BLOB NOT NULL,           -- CBOR Cmd
  env_hash   BLOB NOT NULL            -- blake3 of env
)

TABLE revisions (
  id    INTEGER PRIMARY KEY CHECK (id = 1),
  value INTEGER NOT NULL              -- current global Revision
)

TABLE schema_version (
  version INTEGER NOT NULL            -- bumped on incompatible change
)

Crash consistency:

  • SQLite WAL: write → commit → fsync; incomplete WAL rolled back on open.
  • Schema version mismatch → wipe state.db; fall back to full re-eval (correct, not minimal).
  • Node marked Running in persisted state → on load, forced to Dirty (crash during exec).
  • CAS and AC are independent; crash during CAS write leaves .tmp file; cleaned at startup.

8.11 Sandbox Domain Model

Sandbox backends (per platform):
  Linux:  Linux namespaces (mount + pid + net) via clone(2); seccomp-bpf syscall filter
  macOS:  sandbox-exec(1) + Seatbelt profile; undeclared-input detection via DYLD_INSERT_LIBRARIES shim
  Windows: Job Object + restricted token; directory ACLs

Undeclared-input detection:
  ptrace/eBPF (Linux): intercept open(2)/openat(2); check path against declared input set
  Seatbelt (macOS): deny file-read-data outside declared inputs; log violations
  Violation → IbgError::UndeclaredInput { action_id, path }; exec aborted; output not stored

Declared-output enforcement:
  After exec: walk declared output paths; if absent → IbgError::MissingOutput { path }
  Any file written outside declared outputs (detected via namespace overlay) → IbgError::UndeclaredOutput; treated as correctness bug

Reproducibility check:
  Optional (--check-reproducibility): re-exec action with same ActionKey; compare output digests
  Mismatch → NonDeterministicAction warning; first result stored; metric emitted

8.12 Remote Cache / Execution Protocol (ibg-remote)

Merkle input tree construction:

Directory tree digest = blake3(sorted entries):
  entry = name || type(file|dir) || digest
  File digest = CasObject.digest (blake3 of content)
  Dir digest  = recursive tree digest

Upload protocol:
  1. Build Merkle tree for all declared inputs.
  2. FindMissingBlobs(input_digests) → server replies which are absent.
  3. BatchUpdateBlobs(missing) → upload.
  4. Execute(action_digest, input_root_digest, command) → operation handle.
  5. Poll WaitExecution → ExecResult { output_digests, exit_code, metadata }.
  6. BatchReadBlobs(output_digests) → download → insert into local CAS.

REAPI compatibility: protocol matches Bazel Remote Execution API v2; remote backend is pluggable via RemoteBackend trait (ibg-remote crate).

Failure modes:

  • Remote unavailable → transparent fallback to local exec; no error surfaced unless --remote-only.
  • Partial upload failure → retry with exponential backoff (max 3 attempts); then local exec.
  • Digest mismatch after download → IbgError::RemoteCasCorruption; re-exec locally; log event.
  • Remote returns stale result for ActionKey → impossible if remote is CAS-correct; detected by digest mismatch at materialize step.

8.13 Worked Example — Incremental C Compilation

Setup: src/foo.c and include/foo.h are registered as SourceNodes; A_compile{inputs:[src/foo.c, include/foo.h], outputs:[build/foo.o], command:["cc","-c","src/foo.c","-o","build/foo.o"]}; A_link{inputs:[build/foo.o], outputs:[build/bin], command:["cc","build/foo.o","-o","build/bin"]}.

Build 1 (cold), Revision 1: all nodes start Dirty (no prior state). The engine's demand-driven pull on A_link needs A_compile, which needs src/foo.c — a SourceNode, hashed on demand: fingerprint(src/foo.c)=D1, fingerprint(include/foo.h)=D2. ActionKey(A_compile)=blake3(command‖D1‖D2‖env)=AK1; a cache miss schedules A_compile, which executes and produces output digest D3 for build/foo.o, stored as CAS(D3→content) and AC(AK1→[D3]); A_compile records last_changed=1, last_verified=1, output_digest=D3, status=Clean. ActionKey(A_link)=blake3(link_cmd‖D3‖env)=AK2; a cache miss schedules A_link, which executes and produces D4 for build/bin, stored as AC(AK2→[D4]); state is persisted.

Build 2 (edit src/foo.c, include/foo.h unchanged), Revision 2: a file-watch MODIFY event on src/foo.c sets SourceNode(src/foo.c).last_changed=2, Dirty; reverse-edge propagation marks both A_compile and A_link Dirty. The engine's pull on A_link needs A_compile, which re-fingerprints src/foo.c to D1'≠D1; ActionKey(A_compile)=blake3(cmd‖D1'‖D2‖env)=AK1', a cache miss, so A_compile re-executes, producing a new output digest D3' for build/foo.o. Two outcomes follow depending solely on whether D3' equals D3: when the edit was formatting-only and the compiled output is byte-identical (D3'==D3), early cutoff applies — A_compile.last_changed stays 1 while last_verified advances to 2; because A_link's dependency's last_changed (1) is ≤ A_link.last_verified (1), A_link stays Green and only its last_verified advances to 2, with zero re-execution of A_link. When instead the recompiled output differs (D3'≠D3), A_compile.last_changed advances to 2 and output_digest becomes D3'; ActionKey(A_link)=blake3(link_cmd‖D3'‖env)=AK2' is a cache miss, so A_link re-executes, producing D4', and the new state is persisted.

Failure path — undeclared input: if A_compile reads include/secret.h, which is not in its declared inputs, the sandbox intercepts the open("include/secret.h") call and raises IbgError::UndeclaredInput; the exec is aborted and no output is stored in CAS or the action cache; A_compile transitions to Failed and A_link transitively to Failed (dependency failed). The user's remedy is to add include/secret.h to the declared inputs and re-run.
