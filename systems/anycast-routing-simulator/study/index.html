Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does implementing compare_routes as a total order (via Ord) rather than a partial order matter for catchment correctness? Which invariant does a non-total order violate, and how does the violation manifest in Catchment? (§6 P2, §7 I2, Phase 4)
  2. The BGP best-path ladder has 6 steps. If you only implement steps 1–3 (local-pref, AS-path length, origin type) and skip MED and router-id, in what topologies does catchment remain correct, and in what topologies does it produce a non-deterministic result? (§8.4 (Domain Model), §6 P2, Phase 4, §7 I2)
  3. Under Gao-Rexford policy, a Tier-1 AS has no providers. Why does this guarantee that routes learned by a Tier-1 from a peer will never appear in a provider's RIB? Trace the export policy path through acast-policy::apply_export. (§8.5 (Domain Model), §6 P3, §7 I4, Phase 6)
  4. An operator runs two scenarios: (A) PoP-A with no prepend, PoP-B with no prepend; (B) PoP-A with 2× prepend. Why does PoP-A's catchment shrink in (B) but its routes are still present in ASes near PoP-A? What best-path step causes this, and which catchment metric confirms it? (Phase 12, §8.4 (Domain Model), Phase 8, §6 P4)
  5. What is the difference between path hunting (transient) and oscillation (persistent)? How does the ConvergenceReport distinguish them? What Griffin-Shepherd-Wilfong condition must hold for oscillation to occur, and why does Gao-Rexford policy prevent it? (Phase 9, §7 I8, §2.2 (Why Build This), §6 P5, Paper P2)
  6. The scenario DSL guarantees I10 (replay identity). List the three mechanisms that enforce this and identify the specific code path where each one is enforced. What happens if only two of the three mechanisms are in place? (§6 P1, §7 I10, Phase 1/13, ADR-24)
  7. The link-to-routes index (Phase 10) reduces affected_routes from O(|RIB| × |path_len| × |ASes|) to O(|affected_routes|). Why is the naive scan unacceptable at 50 000-AS scale? Compute the exact event count for a Tier-1 NodeDown without the index and compare against M12. (Phase 10 §10.2, Back-of-Envelope Capacity Model Number 8, §7 I7)
  8. Catchment is derived post-quiescence by reading each AS's Loc-RIB. Why would calling derive_catchment before quiescence produce incorrect results, and which invariant would be transiently violated? (§7 I6, §7 I9, Phase 7 §7.6)
  9. Community (65535, 0) is RFC 1997 NO_EXPORT and (65535, 1) is NO_ADVERTISE. Why must the simulator handle these differently, and what export failure mode occurs if they are conflated? (Phase 6 §6.6, §9 ADR-07, Threat Model)
  10. In a topology where AS-A is a customer of AS-B and also a peer of AS-C, and AS-B and AS-C are peers, why can AS-A's route not propagate from AS-B to AS-C? Draw the route-propagation path and identify which export table cell blocks it. (§8.5 (Domain Model), §7 I4, Phase 6 §6.2)
  11. The EventQueue uses (time, seq) as a composite key where seq is globally monotone. Why is time alone insufficient for total order? Give a concrete example where two events at the same virtual time produce different catchments depending on dispatch order. (§6 P1, §7 I1, §8.7 (Domain Model), Phase 1)
  12. Memory usage scales as O(|AS| × |neighbors| × |prefixes|). For a single anycast prefix, Adj-RIB-In is bounded. What happens to memory if the scenario introduces 500 000 prefixes? Which §4 constraint is violated first, and what design change would allow 500 000 prefixes without exceeding the 8 GB RSS ceiling? (§4, Scalability Analysis, Phase 13, MM4)
  13. Path inflation ratio < 1.0 is mathematically possible in this model. Explain the scenario where it occurs, why it is not an error, and why optimal_latency ≤ bgp_latency is not guaranteed as a hard invariant. (Phase 11 §11.6 (Core Schema), §11.4 (Core Schema))
  14. The oscillation flag in ConvergenceReport is set when the ring buffer detects alternating is_install patterns for the same (AS, prefix). Why is this a sufficient but not necessary condition for detecting all Griffin-Shepherd-Wilfong gadgets? Give a policy configuration where oscillation exists but the ring buffer window W is too small to detect it. (Phase 9 §9.2/9.6, §7 I8)
  15. In fault injection, NodeDown for a Tier-1 AS triggers O(degree) LinkDown events. Why are these processed in seq order rather than simultaneously, and what would go wrong if they were processed truly in parallel? (Phase 10 §10.2, §6 P1, §7 I1)
  16. The scenario DSL requires assert NoOscillation in all non-dispute fixtures. Why is failing to include this assertion in a conformance test a quality defect, even if the test passes? (Phase 14 §14.2, §7 I8, §6 P5)
  17. MOAS (Multi-Origin AS) occurs when the same prefix is originated by multiple ASes. The simulator intentionally uses MOAS for anycast. What distinguishes a legitimate anycast MOAS from a BGP hijack MOAS, and how does the origin_pop field encode this distinction? (§8.6 (Domain Model), Phase 7, §5 RFC 4786)
  18. The ADR table rejects always_compare_med = true as the default. Construct a 5-AS scenario where always_compare_med = false (default) produces a non-deterministic catchment and explain how always_compare_med = true resolves it. (Phase 12 §12.2, §8.4 (Domain Model), §7 I2)
  19. The Deferred Features Register shows iBGP mesh as deferred. Why would adding iBGP sessions to the simulator require structural changes to acast-bgp beyond simply adding a new session type? Which invariant would be most affected, and why? (Deferred Features Register, §7 I4, §8.5 (Domain Model), §11.4 (Core Schema))
  20. Explain why seq must be reset to 0 at scenario start but the PRNG seed is not needed for determinism. What happens if seq is not reset between two scenarios run in the same process? (Phase 13 §13.6, §7 I10, §6 P1)
  21. The Performance Engineering section targets M2 (per-event dispatch ≤ 2 µs p99). If a profiler shows the dominant cost is HashMap lookup in Adj-RIB-In, what two data-structure changes could reduce this cost, and what tradeoff does each introduce relative to §7 I2? (Performance Engineering, §7 I2, §11.4 (Core Schema), Phase 13)
  22. The Back-of-Envelope model derives 375 000 convergence events for a 75 000-AS topology under Gao-Rexford. If a scenario adds a second anycast prefix, how does the event count scale, and which §4 constraint does this test first? (Capacity Model, §4, Scalability Analysis)
  23. Community-based selective export is called "surgical TE" in §12.10. Explain the mechanism that makes it more precise than AS-path prepend: which step in the best-path ladder is affected by each, and at what network location does the effect manifest? (Phase 12 §12.2, §8.4 (Domain Model), §6 P3) ---

Mental Models & First Principles

Expert intuitions that predict behavior before you run any code. Each model names the §/phase where this blueprint applies it.

MM1 — Best-path is a distributed sort, not a consensus protocol. Every AS independently ranks its candidate routes using the same deterministic comparator (compare_routes). Catchment emerges from 75 000 independent elections, each pure functions of local state. Corollary: you cannot "fix" a catchment by adjusting one AS's behavior — you must change the routes that reach that AS. Applied in §6 P4, Phase 7. Bug class without it: operators attempt centralized catchment management, which doesn't exist.

MM2 — VirtualClock is the only causal clock; wall time is irrelevant. An event at (t=100, seq=5) happens-before (t=100, seq=6) regardless of wall-clock order. Reproducibility follows from this: identical inputs → identical (time, seq) assignments → identical dispatch order. Applied in §6 P1, §7 I1, Phase 1. Bug class: injecting any wall-clock read into dispatch breaks I10 (replay diverges).

MM3 — Valley-free is an economic constraint, not a topological one. A route from a peer is suppressed toward another peer not because of a graph cycle, but because of a business rule (free transit). The same topology with different relationships produces different catchment. Applied in §6 P3, §7 I4, Phase 6. Bug class: conflating relationship direction with physical path direction causes silent valley-free violations with wrong catchment.

MM4 — The three-tier RIB is a pipeline, not a cache. Adj-RIB-In → (import policy + best-path) → Loc-RIB → (export policy) → Adj-RIB-Out. Each stage transforms routes with no bypass. Loc-RIB is not a copy of Adj-RIB-In — it is the policy-filtered winner. Applied in §8.3 (Domain Model), §11.4 (Core Schema), Phase 3–5. Bug class: skipping the pipeline (reading Adj-RIB-In as if it were Loc-RIB) produces wrong catchment silently.

MM5 — Withdrawal cascade is depth-first, not breadth-first. When a link fails, each affected AS removes its Adj-RIB-In entries and re-runs best-path; if Loc-RIB changes, it emits WithdrawMsg to downstream ASes who repeat the process. The cascade fans out along the topology DAG. Applied in §7 I7, Phase 10. Bug class: breadth-first withdrawal misses routes that pass through intermediate ASes not directly adjacent to the failure.

MM6 — Oscillation is a policy-graph property, not a transient. Griffin-Shepherd-Wilfong proved that certain 3-AS policy configurations have no stable path — no amount of waiting will resolve them. The oscillation detector (I8) detects these and halts; it is not a timeout. Applied in §7 I8, Phase 9, §2.2 (Why Build This). Bug class: treating oscillation as a convergence timeout rather than a policy-dispute diagnosis leads to operators increasing max_events instead of fixing the policy.

MM7 — Traffic engineering knobs shift traffic entry points, not traffic volume. AS-path prepend makes a PoP look farther away (step 2 in the tie-break ladder). MED signals preferred entry among routes from the same neighbor AS. Neither changes physical traffic volume — only which PoP attracts which client AS's best-path. Applied in §6 P3, Phase 12, §2.3 (Why Build This). Bug class: operators expect prepend to reduce total load rather than redistribute catchment; they prepend indefinitely without achieving balance.

MM8 — Determinism requires structural elimination of nondeterminism, not seeding. The simulator achieves I10 by design: no HashMap iteration in dispatch-critical paths (use BTreeMap or sorted Vec), no wall-clock in engine, no OS randomness. A PRNG seed is irrelevant because no PRNG is used. Applied in §7 I10, Phase 1/13, ADR-24. Bug class: assuming a fixed PRNG seed makes non-determinism "reproducible" — actually the non-determinism is from HashMap ordering, unaffected by any seed.

Glossary · 40 terms · site-wide glossary

Adj-RIB-In
Per-neighbor store of routes received from that neighbor before import policy; keyed (Asn, Prefix) in Rib.
Adj-RIB-Out
Per-neighbor store of routes this AS will advertise after export policy; derived from Loc-RIB at quiescence (I9).
Anycast
Routing technique where a single prefix is announced from multiple geographically distributed origins; clients are routed to the nearest (per BGP) origin.
AS-path
Ordered sequence of ASNs a BGP route has traversed; primary loop-prevention mechanism (I3) and second-tier best-path metric (Phase 4).
AS-path prepending
Artificially repeating the originating ASN in AS-path to inflate apparent path length, deprioritizing a PoP in best-path selection (Phase 12).
Autonomous System (AS)
A network under single administrative control, identified by a 32-bit Asn. Unit of graph node in acast-topology.
BGP (Border Gateway Protocol)
Inter-domain path-vector routing protocol; RFC 4271 is the normative reference. The simulator models eBGP sessions between AS peers.
BGP community
Community(u32, u32) tag attached to a BgpRoute; used for policy signaling between ISPs (selective export, local-pref overrides).
Best-path decision process
The deterministic tie-break ladder that selects one route per prefix for Loc-RIB from Adj-RIB-In candidates (Phase 4).
CAIDA AS-relationships
CAIDA dataset enumerating (AS_a, AS_b, relationship) triples inferred from BGP paths; primary topology input format for acast-topology.
Catchment
Map<Asn, Option<PoPId>> — for a given anycast prefix, the mapping from every client AS to the PoP it reaches; emergent from distributed best-path (P4).
Catchment diff
Set difference between two Catchment maps highlighting ASes that changed serving PoP, used in fault and TE analysis (Phase 8, 10).
Convergence
State reached when no AS has a pending UPDATE or WITHDRAW to send; EventQueue is empty or contains only future fault events (I8).
ConvergenceReport
Struct recording converge_time, events_processed, updates_sent, withdraws_sent, and oscillation flag for a single scenario run.
Customer
Relationship type where neighbor pays this AS for transit; given highest local-pref in Gao-Rexford (I5); routes from customers exported to all neighbors.
Discrete-event simulation
Execution model where system state changes only at scheduled SimEvent timestamps; events processed strictly in (time, seq) order (P1, I1).
eBGP
External BGP session between two ASes with distinct ASNs; all sessions in acast-bgp are modeled as eBGP.
EventQueue
Binary min-heap ordered by (time, seq); the simulator's central scheduling structure in acast-sim.
Gao-Rexford
Policy model (Gao & Rexford 2001) specifying stable routing under customer/peer/provider economics; the normative export constraint (P3).
Local-pref
Unsigned integer preference attached to a route within an AS; determines customer > peer > provider preference hierarchy (I5); highest wins in Phase 4 step 1.
Loc-RIB
Per-AS best-route table: one route per prefix selected by best-path; source of truth for what the AS currently forwards and exports.
Link
Link { a, b, rel_from_a, latency_ms, up } — bidirectional adjacency with asymmetric relationship view and failure state.
MED (Multi-Exit Discriminator)
Optional BGP attribute signaling preferred entry point to an AS from adjacent neighbors; lower MED preferred; compared only between routes from same neighbor AS.
MOAS (Multi-Origin AS)
Condition where a prefix is originated by more than one AS; anycast is an intentional MOAS; unintentional MOAS indicates a routing leak or hijack.
Origin type
BGP route origin: IGP < EGP < INCOMPLETE; third step in best-path ladder (Phase 4); IGP is the preferred origin.
Oscillation
Persistent cycling of Loc-RIB state with no convergence; caused by Stable Paths Problem violations in policy (Griffin et al. 2002); flagged in ConvergenceReport.
Path exploration
Transient state during convergence where an AS installs progressively longer AS-paths while searching for a valid route after withdrawal; observable via UPDATE counts.
Path inflation
Ratio of actual AS-hop count (or latency) to the theoretical optimum; computed per client AS in acast-metrics (Phase 11).
PoP (Point of Presence)
An origin site announcing the anycast prefix; identified by PoPId(u32) and anchored to a specific Asn in the topology.
PoP load
Sum of traffic weights of all ASes in a PoP's catchment; used for hot-PoP detection in Phase 11.
Prefix
Prefix { addr: IpAddr, len: u8 } — the routed IP address block; the key for all RIB lookups.
Provider
Relationship type where this AS pays neighbor for transit; given lowest local-pref in Gao-Rexford (I5); routes from providers exported only to customers.
Route flap
Rapid alternation of a route between announced and withdrawn state; stresses convergence and UPDATE count.
Scenario DSL
Declarative TOML/YAML specification of topology reference, AnycastPrefix announcements, fault timeline, and correctness assertions; fully determines a run (P10, Phase 13).
SimEvent
{ time: u64, seq: u64, kind: BgpEvent } — atomic unit of work scheduled in EventQueue; seq ensures deterministic total order within the same timestamp (I1).
Traffic engineering (TE)
Operator-controlled BGP knobs — AS-path prepend, MED, community-based selective export — used to shift catchment distribution (Phase 12).
UPDATE
BGP message advertising a new or changed route; carries BgpRoute fields including AS-path and communities.
Valley-free
Export constraint: a route received from a peer or provider is never re-exported to another peer or provider; encoded in acast-policy (I4).
VirtualClock
Monotonically advancing timestamp counter in acast-sim; advances only when an event is dequeued; never tied to wall time (P1).
WITHDRAW
BGP message retracting a previously announced route; must cascade through all downstream ASes that were using it (P9, I7).
