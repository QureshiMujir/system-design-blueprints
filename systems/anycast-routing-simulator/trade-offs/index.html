Decisions (§9) · 28 ADRs

ADR-01

Implementation language

Chosen

Rust (stable toolchain)

Rejected

Go, Python, C++

When the rejected choice is right

Python wins for rapid research prototyping on small topologies (< 5k ASes) where developer iteration speed matters more than runtime performance; Go wins when the team's primary runtime expertise is Go and the simulation scale stays < 10k AS with no memory-layout tuning

Why: Memory safety without GC; deterministic drop; BinaryHeap in std; P7 scale

ADR-02

Build system

Chosen

Cargo workspace, one workspace root

Rejected

Bazel, Buck, CMake

When the rejected choice is right

Bazel wins when this simulator is one module in a multi-language monorepo (Rust + C++ topology parsers + Python analysis scripts) where hermetic cross-language builds and remote caching are needed

Why: Native Rust toolchain; workspace dependencies; cargo test covers all crates

ADR-03

Workspace crate layout

Chosen

11 crates (acast-core … acast-cli) per spine

Rejected

Monolith, fewer crates

When the rejected choice is right

Monolith wins during early research prototyping when architectural boundaries are still being discovered and compile-time layering enforcement slows iteration

Why: Enforces layering; acast-policy cannot import acast-sim; compile-time boundary

ADR-04

Dependency policy

Chosen

minimal curated; Cargo.lock checked in

Rejected

unpinned deps

When the rejected choice is right

Unpinned deps win in a library crate published to crates.io that must compose with a wide range of user dependency trees and where Cargo.lock is intentionally excluded

Why: Reproducibility I10; supply-chain minimization; cargo audit in CI

ADR-05

EventQueue implementation

Chosen

std::collections::BinaryHeap<SimEvent> + cancel HashSet

Rejected

custom heap, tokio timer wheel, external priority queue crate

When the rejected choice is right

Tokio timer wheel wins when the simulation is integrated into an async runtime for real-time replay against live BGP feeds (Phase deferred), where wall-clock alignment is required

Why: Zero external dep; deterministic; SimEvent: Ord on (time, seq)

ADR-06

Concurrency model

Chosen

single-threaded synchronous dispatch loop

Rejected

async/Tokio, rayon, actor model

When the rejected choice is right

Rayon parallel dispatch wins when running thousands of small independent scenario batches (each scenario fully isolated) and scenario throughput per wall-clock minute is the primary KPI, not per-run correctness

Why: Simulation correctness requires total event order (I1); parallelism breaks determinism

ADR-07

Serialization

Chosen

serde + serde_json for trace/reports; toml crate for scenario DSL

Rejected

bincode, protobuf, MessagePack

When the rejected choice is right

protobuf wins when trace volume exceeds 1 GB per run and network transport of traces to a remote analytics server is required — binary encoding reduces wire size by ~5–8×

Why: Human-readable trace; scenario DSL hand-editable; TOML: no ambiguous types

ADR-08

Trace format

Chosen

NDJSON (line-delimited JSON)

Rejected

CSV, binary, SQLite

When the rejected choice is right

SQLite wins when trace queries require multi-dimensional filtering (by AS + prefix + time range) and the trace is consumed interactively rather than piped to a streaming analytics tool

Why: Streamable; grep/jq-friendly; no schema migration; works with standard Unix tooling

ADR-09

Scenario DSL format

Chosen

TOML files parsed by acast-scenario

Rejected

YAML, JSON, custom grammar

When the rejected choice is right

Custom grammar wins when scenarios need programmatic generation at scale (e.g., 10k automatically-generated fault scenarios) and a proper AST enables structural validation that flat TOML cannot express

Why: TOML: unambiguous, no implicit types, good Rust crate; YAML rejected (footguns)

ADR-10

Topology input format

Chosen

CAIDA AS-relationships text (asn1|asn2|rel)

Rejected

BGP table dumps, GraphML

When the rejected choice is right

MRT BGP table dumps (RFC 6396) win when the simulation is used as a validation harness against live routing data from RouteViews or RIPE RIS — MRT captures real prefix tables alongside topology

Why: CAIDA dataset canonical for internet AS topology research; matches Required Reading

ADR-11

RIB storage

Chosen

HashMap<(Asn,Prefix), BgpRoute> per tier

Rejected

BTreeMap, flat vec, trie

When the rejected choice is right

Radix trie (patricia tree) wins when the simulator is extended to model IP forwarding with longest-prefix-match semantics (e.g., more-specific prefix injection attacks, deaggregation scenarios)

Why: O(1) lookup; Prefix is small fixed struct; no prefix-longest-match needed (exact match)

ADR-12

Prefix representation

Chosen

Prefix { addr: IpAddr, len: u8 } (acast-core type)

Rejected

string CIDR, ipnet crate as primary

When the rejected choice is right

ipnet crate as primary type wins when the simulator must interoperate with external Rust crates (routing tables, geolocation libraries) that already depend on ipnet types — avoiding conversion overhead

Why: Core type self-contained; ipnet usable as parse helper only

ADR-13

Best-path implementation

Chosen

Ord impl on BgpRoute projection struct

Rejected

runtime comparator, score function

When the rejected choice is right

Score function (weighted integer) wins when the simulator is extended to model non-standard policy (e.g., machine-learning-derived route preferences) where the ladder is not a fixed total order but a learned scoring model

Why: Compile-time correctness; P2; tie-break ladder as cmp chain, not ad-hoc branching

ADR-14

Policy mechanism

Chosen

ImportPolicy / ExportPolicy traits in acast-policy; called via hooks from acast-bgp

Rejected

hard-coded if/else in bgp module, scripting engine

When the rejected choice is right

Embedded scripting engine (Lua/Rhai) wins when operators need to express arbitrary per-AS policy rules at runtime without recompiling the binary — the trade-off is dynamic evaluation overhead and sandboxing complexity

Why: P8 separation; policy swappable per AS; conformance tests inject custom policy

ADR-17

Testing strategy

Chosen

ADR-24

Reproducibility

Chosen

Cargo.lock checked in; RUSTFLAGS pinned; scenario file fully determines run

Rejected

runtime seeds, external RNG

When the rejected choice is right

External PRNG seed wins when the simulator is used for Monte Carlo analysis of random topology variants — the seed is stored in the scenario file, so reproducibility is preserved while enabling diversity

Why: No RNG in simulation core; all nondeterminism eliminated structurally

Rejected

When the rejected choice is right

Box<dyn Error> wins in a pure prototyping phase where typed error hierarchies are premature and the priority is running code quickly; replace with thiserror before stabilization

ADR-26

Integer widths

Chosen

u64 for time and seq in SimEvent

Rejected

u32, i64, f64

When the rejected choice is right

u32 for time wins in an embedded simulation context (microcontroller, FPGA soft-core) where memory is severely constrained and simulated time is bounded to < 4 billion ticks by design

Why: u64: no wrap risk at internet scale; f64 rejected (non-total order, NaN risk)

ADR-27

Newtype wrappers

Chosen

Asn(u32), PoPId(u32) in acast-core

Rejected

When the rejected choice is right

Raw u32 wins in FFI-heavy code where the newtypes require manual From/Into impls at every boundary, adding maintenance burden that outweighs type safety

Why: Prevents Asn/PoPId confusion at call sites; zero runtime cost

Alternative Architectures (Roads Not Taken)

Alt-1 — Parallel Event Dispatch with Actor-per-AS

Show the original text diagram
[EventQueue (global)] --dispatch--> [Actor(AS_1)] [Actor(AS_2)] ... [Actor(AS_N)]
   Each actor holds its own Rib; message-passing for UpdateMsg/WithdrawMsg
   Result aggregator collects Catchment from all actors at quiescence

Regime where it wins: simulation of tens of thousands of ASes with multiple prefixes where per-event wall-clock time matters (interactive TE exploration). The actor model enables real parallelism across cores.

Real system embodying it: GoBGP uses goroutines per BGP session for concurrent session management.

Why rejected: actor concurrency destroys I1 (VirtualClock monotonicity) — two actors can schedule events at the same virtual time but in non-deterministic order, breaking I10 (replay identity). Fixing this requires a global synchronization barrier at every virtual-time tick, eliminating most parallelism benefit. ADR-06 explicitly locks this out.

Alt-2 — Shared-Memory RIB with Epoch-Based Reads

Show the original text diagram
GlobalRib: Arc<RwLock<HashMap<(Asn,Prefix), BgpRoute>>>
   Writer: BGP speaker per AS acquires write lock, updates Loc-RIB
   Reader: Catchment derivation reads snapshot at epoch boundary
   Epoch barrier: all writers drain before epoch transitions

Regime where it wins: read-heavy workloads — many concurrent analytical queries over the same RIB state after a single scenario run (e.g., what-if analysis across 1000 PoP configurations).

Real system: Maglev uses a shared consistent hash table with epoch-based updates for flow routing.

Why rejected: write-lock contention from per-AS RIB updates during convergence serializes all AS dispatch, eliminating parallelism. The simulator's bottleneck is write throughput during propagation, not read throughput. Plus it breaks determinism (lock acquisition order is non-deterministic under thread scheduling). The single-threaded model achieves higher per-event throughput than any lock-contended parallel model for this workload.

Alt-3 — Pure Functional Simulation (Persistent Data Structures)

State(t) = pure function of State(t-1) + Events(t)
   Rib = persistent HashMap (HAMT); each RIB update returns new Rib
   EventQueue = persistent heap; each dispatch returns new (Queue, State)
   No mutation; easy snapshot/replay; referentially transparent

Regime where it wins: formal verification contexts where you need to prove simulator correctness properties about all possible execution paths, or incremental re-computation (only re-simulate ASes affected by a policy change).

Real system: academic BGP analyzers written in Haskell/OCaml use persistent data structures for exhaustive policy verification.

Why rejected: persistent HAMTs have 3–5× memory overhead vs mutable HashMaps and 2–3× allocation overhead per update. At 75 000 ASes × millions of events, this pushes memory above the 8 GB §4 ceiling and reduces event throughput below M1 targets. The determinism guarantee of the functional model is achieved by other means (ADR-24, ADR-06) without the performance cost.

Alt-4 — BGP Table-Dump Replay (MRT-based)

Show the original text diagram
MRT stream (RFC 6396) from RouteViews/RIPE RIS
  --> Offline parser --> BGP route events
  --> acast-sim EventQueue (real timestamps as virtual time)
  --> Catchment derivation at each time slice

Regime where it wins: validation of the simulator against real Internet routing data — replay actual BGP table dumps and compare derived catchment against measured anycast probing results. Also useful for root-cause analysis of real anycast incidents (replay the BGP events around an outage).

Real system: CAIDA BGPStream provides this capability for offline BGP analysis; tools like bgpscanner replay MRT dumps.

Why rejected: MRT timestamps are real-time (seconds resolution) and event arrival is non-deterministic (reordered by BGP convergence). Mapping real timestamps to a deterministic virtual clock requires assumptions about event ordering that violate I1. The simulator is designed to be a ground-truth engine, not a validator against live data — that is a composition use case (run simulator + compare against live data), not a replacement for the deterministic model. Deferred to future integration phase.
