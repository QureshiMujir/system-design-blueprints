355 — Anycast Routing Simulator from Scratch

Project Name: Anycast Routing Simulator from Scratch

Owner: Mujir Qureshi

1. Goal

1.1 Precise Engineering Scope

Build a deterministic, discrete-event simulator of inter-domain (BGP) routing and anycast catchment over a modeled AS graph. The simulator ingests a topology (CAIDA-format AS-relationship data or a scenario-defined graph), propagates BGP routes under Gao-Rexford policy, and for any prefix announced from multiple PoPs computes the per-AS catchment: which PoP each AS is routed to, how catchment shifts under fault injection, and how many events and virtual-clock ticks convergence requires.

1.2 System Boundary

Boundary Inside Outside
Routing plane BGP path selection, RIB management, policy (local-pref, AS-path, MED, community, valley-free export) IS-IS/OSPF, MPLS, IP forwarding, TCP/UDP, actual packet processing

1.3 Non-Goals

  • Not a real BGP speaker; does not open TCP sessions or exchange real BGP packets.
  • No iBGP mesh, route reflectors, or confederation modeling (iBGP is noted deferred; see Goal §1.9 (Deferred Features) and the Deferred Features Register).
  • No MPLS, SR-MPLS, or SD-WAN plane.
  • No simulation of route authentication (RPKI, BGPsec).
  • No simulation of IXP internals (project 356 scope).
  • No simulation of the edge-compute layer that acts on catchment assignments (project 357 scope).
  • No real-time integration with routing infrastructure.

1.4 Language — Rust (locked)

An internet-scale discrete-event BGP simulator must hold tens of thousands of AS nodes with per-AS RIBs and process millions of route events deterministically and fast. Rust gives compact data layout for the topology and RIBs, no GC pauses during convergence runs, and strong enums for the route/event taxonomy that keep BGP semantics honest.

1.6 Deployment Model

  • Single-process CLI tool; statically linked; runs on developer workstation or CI runner.
  • No daemon, no network socket; scenarios are files; outputs are files or stdout.
  • Scale target: tens of thousands of ASes (internet-scale topology), millions of events per run.
  • Reference topologies sourced from CAIDA AS-relationships dataset.

1.7 Phase 0 Deliverables — Locked Crates

  7. acast-anycast — AnycastPrefix; multi-origin propagation; Catchment derivation.
  8. acast-fault — LinkDown/LinkUp/NodeDown/PoP-withdraw injection; convergence measurement; ConvergenceReport.
  9. acast-metrics — catchment maps, convergence time series, UPDATE counts, path inflation, PoP load distribution.
  10. acast-scenario — scenario DSL: topology ref + announcements + fault timeline + assertions; TOML/JSON parse.

2. Why Build This

2.1 Unique Systems Knowledge Acquired

Topic What the implementation forces you to understand
BGP best-path decision process The tie-break ladder is not a heuristic: each step has an exact semantic; implementing it incorrectly yields wrong catchments, a visible and testable failure
Anycast catchment emergence No central authority assigns clients to PoPs; catchment falls out of independent per-AS best-path runs on a multiply-originated prefix — the system property is non-obvious until you build it
Gao-Rexford valley-free policy Export rules are asymmetric by relationship; modeling them correctly requires separating propagation (acast-bgp) from economics (acast-policy) — P8
BGP convergence and path hunting After a failure, ASes may transiently prefer longer paths before settling; counting UPDATE events and measuring converge_time makes the phenomenon concrete
Withdrawal cascade correctness A link failure must remove every route whose AS-path traverses that link; incomplete cascades leave phantom routes — I7 is testable
Discrete-event simulation (time, seq) ordering is the only mechanism that makes multi-node event interleaving deterministic; any nondeterminism is a correctness bug, not a performance tradeoff
RIB three-tier model Adj-RIB-In / Loc-RIB / Adj-RIB-Out mirrors real router architecture; understanding where policy is applied at each tier is essential to debugging wrong paths
Traffic engineering knobs AS-path prepending and MED do not shorten paths — they shift where traffic enters the network; modeling the catchment response makes this concrete

2.2 Historical and Architectural Significance

  • BGP is the inter-domain routing protocol of the internet; it has been the primary mechanism for routing policy since RFC 1771 (1995) and its modern form RFC 4271 (2006).
  • Anycast is the foundational delivery mechanism for DNS root servers, CDN PoPs, DDoS scrubbing, and cloud edge networks; its correctness properties derive entirely from BGP convergence.
  • Gao & Rexford (2001) proved that customer/provider/peer policy guarantees global routing stability under conditions that hold in practice; this result is the theoretical underpinning of commercial inter-domain routing.
  • Griffin, Shepherd, and Wilfong (2002) identified the Stable Paths Problem — the class of policy configurations that can cause non-convergence; any simulator that does not detect oscillation is missing a first-class safety property.
  • CAIDA AS-relationships and AS-rank datasets represent the empirical measurement infrastructure for internet topology; using them grounds simulations in real-world AS graph structure.

2.3 Engineering Muscles Developed

  • Deterministic simulation design — event ordering, virtual clocks, reproducible seeds; applies to any system requiring deterministic replay (databases, distributed systems, compilers).
  • State machine fidelity — BGP's best-path process is a finite state machine over route attributes; implementing it rigorously builds discipline for protocol implementation.
  • Separation of mechanism and policy — acast-bgp knows how to propagate; acast-policy knows the economics; this architectural separation is a transferable principle (kernels, compilers, runtimes).
  • Compact data layout under scale — holding per-AS RIBs for tens of thousands of nodes requires careful memory layout; HashMap hot paths, arc sharing of Vec<Asn> AS-paths, BTreeMap vs HashMap tradeoffs.
  • Graph-structured computation — AS graph traversal, topological reasoning, tier classification (Tier-1 / Tier-2 / stub AS); transferable to compilers (CFG/DFG), kernels (device trees), databases (query plans).
  • Convergence detection — quiescence detection in an event queue is a pattern that appears in many simulation and compilation systems (dataflow fixed points, static analysis).
  • Fault injection discipline — systematic failure scenarios with measurable outcomes; applies to distributed systems testing, chaos engineering.

2.7 What Mastery Looks Like

  • Protocol implementation from first principles (Phase 4). Given only RFC 4271 sec. 9.1 and a set of candidate routes, reproduce the exact best-path winner that a real BGP implementation would select — including the MED same-neighbor guard and the router-id final tiebreak — and explain why each step in the ladder is ordered as it is.
  • Anycast catchment reasoning (Phase 7–8). For any small AS graph with two PoPs, derive by hand which ASes map to which PoP, then verify against derive_catchment output; explain why a change in a single link's relationship flips an AS's catchment.
  • Convergence analysis and oscillation diagnosis (Phase 9). Given a ConvergenceReport with oscillation=true, identify the Griffin-Shepherd-Wilfong gadget in the policy graph, explain why no stable path exists, and propose a policy change that restores convergence.
  • Fault model reasoning (Phase 10). Trace a LinkDown event through the withdrawal cascade: which RIBs are purged, in what order, and why the Gao-Rexford local-pref ordering determines which surviving PoP absorbs the failed one's catchment.
  • Traffic engineering knobs (Phase 12). Given a catchment imbalance (80 % on one PoP), design a prepend + MED configuration that redistributes load to within 60/40 and explain which tier of the best-path ladder each knob influences.
  • Scale and memory layout (Phase 13). Estimate peak RSS for a 50 000-AS topology with a single anycast prefix and justify the estimate from first principles using the per-AS RIB memory model and AS-path interning.
  • Determinism and replay (Phases 1, 13). Explain the three mechanisms that guarantee identical catchment on two runs from the same scenario file, and identify which mechanism is broken when a replay test diverges.

3.2 Subsystem Descriptions

acast-sim — Discrete-Event Engine. Owns the EventQueue (a binary min-heap ordered by (time, seq)) and the VirtualClock. Drives the entire simulation: pops the lowest-keyed event, increments the clock, dispatches the event to the appropriate AsNode handler, and loops until the queue is empty or a quiescence condition is met. Never inspects route semantics; all domain knowledge lives downstream. The seq counter is a monotonically increasing tie-breaker that guarantees a total order even when multiple events share the same virtual time. Data flow in: SimEvent pushes from all other crates. Data flow out: dispatched BgpEvent variants to acast-topology / acast-bgp handlers. Concurrency boundary: single-threaded in Phase 1–13; parallel dispatch is deferred. Persistence boundary: none; the queue is transient per run.

acast-topology — AS Graph. Maintains the set of AsNode instances and Link records. Each AsNode holds its Asn, a neighbor list, a PolicyConfig, and a Rib. Links carry Relationship (from A's perspective), latency_ms, and up flag. The topology loader parses CAIDA AS-rel format (<asn>|<asn>|<rel> lines) and constructs the graph. Validates that every relationship is consistently encoded; computes graph statistics (degree distribution, tier classification). Trust boundary: topology input files are operator-supplied; no validation against live routing data. Data flow in: CAIDA file or scenario DSL topology block. Data flow out: AsNode references to acast-bgp; Link set to acast-fault.

acast-bgp — BGP Speaker (per AS). Implements the three-tier RIB model for every AsNode: Adj-RIB-In (one entry per neighbor per prefix), Loc-RIB (best route per prefix after policy + best-path), Adj-RIB-Out (per-neighbor filtered view of Loc-RIB). On RecvUpdate: install into Adj-RIB-In, apply import policy (acast-policy), re-run best-path (acast-bestpath) over Adj-RIB-In → update Loc-RIB, recompute Adj-RIB-Out per neighbor via export policy, schedule RecvUpdate or RecvWithdraw events for changed neighbors. On RecvWithdraw: remove from Adj-RIB-In, re-run best-path, cascade withdrawals if Loc-RIB entry is removed. AS-path loop check on import rejects any route containing the local ASN (I3). Data flow in: UpdateMsg/WithdrawMsg from neighbors; policy from acast-policy; tie-break from acast-bestpath. Data flow out: UpdateMsg/WithdrawMsg to neighbors via acast-sim event schedule.

acast-policy — Routing Policy. Pure functions over BgpRoute + PolicyConfig + Relationship. Import policy: assigns local_pref (customer → 300, peer → 200, provider → 100 by default per Gao-Rexford; operator-configurable). Export policy: enforces valley-free (I4) — routes learned from a peer or provider are not exported to a peer or provider; only customer-learned routes propagate to peers and providers. Supports AS-path prepend (repeat local ASN N times), MED setting per neighbor, community-based selective export. No side effects; called by acast-bgp during RIB update. Data flow in: BgpRoute, PolicyConfig, neighbor Relationship. Data flow out: modified BgpRoute or None (route filtered out).

acast-bestpath — Best-Path Decision Process. Pure function: given a set of BgpRoute candidates in Adj-RIB-In for a prefix, returns the single best route for Loc-RIB. Implements the BGP tie-break ladder in strict order: (1) highest local_pref, (2) shortest as_path.len(), (3) lowest origin type (IGP < EGP < Incomplete), (4) lowest med (when routes are from the same AS), (5) eBGP > iBGP, (6) lowest next_hop router-id (deterministic tiebreak). Deterministic total order: all ties resolve to a single winner (I2). Data flow in: Vec<BgpRoute> from Adj-RIB-In. Data flow out: Option<BgpRoute> best.

acast-anycast — Anycast Prefix + Catchment. Manages an AnycastPrefix: a single Prefix announced from multiple (Asn, PoPId) origin pairs, each carrying a distinct origin_pop tag in BgpRoute. After propagation quiesces, reads every AsNode's Loc-RIB best route for the anycast prefix; extracts origin_pop to build Catchment: Map<Asn, Option<PoPId>>. ASes with no route map to None. Catchment is an emergent property (P4): no node decides it; it falls out of independent best-path runs. Data flow in: AnycastPrefix definition; quiescent Rib state from acast-topology. Data flow out: Catchment map to acast-metrics and acast-scenario asserts.

acast-fault — Fault Injection + Convergence Measurement. Schedules LinkDown / LinkUp / NodeDown / prefix-Withdraw events at times specified in the scenario fault timeline. On LinkDown: marks Link.up = false; for every route in every AS whose AS-path traverses that link, schedules RecvWithdraw events; initiates withdrawal cascade (I7). On NodeDown: same but for all links of the node. Measures convergence: after the last injected fault event, counts subsequent UPDATE/WITHDRAW events; detects quiescence (queue empty or no route change for N events); records converge_time and event counts in ConvergenceReport. Detects oscillation (P5): if the same prefix flips best-path more than a threshold, flags oscillation: true. Data flow in: fault timeline from acast-scenario; Link and Rib references from acast-topology. Data flow out: BgpEvent variants to acast-sim; ConvergenceReport to acast-metrics.

acast-metrics — Metrics and Reporting. Aggregates post-run data into reports: catchment size per PoP, unreachable AS count, catchment diff between scenarios (before/after fault), per-link UPDATE/WITHDRAW counts, convergence time series, path inflation (actual AS-path length vs. shortest-path length), PoP load distribution (weighted by traffic weight if provided). Serializes to JSON or human-readable text. No simulation logic; pure aggregation over final state. Data flow in: Catchment, ConvergenceReport, Rib snapshots, link latency from acast-topology. Data flow out: report files / stdout.

acast-scenario — Scenario DSL + acast-cli. The scenario DSL is a TOML (or JSON) document specifying: topology reference (CAIDA file path or inline), initial announcements (prefix, origin AS, PoP), fault timeline (event type, target, time), and assertions (expected catchment, max convergence time, specific AS-to-PoP mapping). acast-cli parses the scenario, initializes the simulation, runs it to quiescence, evaluates assertions, and reports pass/fail with diff output on failure. Serves as the conformance harness (Phase 14). Data flow in: scenario file. Data flow out: pass/fail assertion results; catchment dump; convergence report; metrics report.

6. Design Principles

P1 — Deterministic Discrete-Event Simulation

Statement. Every run on identical inputs produces identical event sequences, identical Catchment, and identical ConvergenceReport.

Mechanism. SimEvent is keyed (time: u64, seq: u64); seq is a global monotonic counter assigned at schedule time. EventQueue pops minimum by this composite key. No wall-clock, no thread scheduling, no OS randomness enters dispatch.

Tradeoffs. Seq assignment requires a single dispatch loop (no parallel event processing). Acceptable: BGP simulators are compute-light per event; throughput target is millions of events per second in one thread.

Operational implication. Regression tests compare exact ConvergenceReport fields. A scenario file is a complete run specification (I10). Seed-based topology randomization (Phase 13) is reproducible because the PRNG seed is a required scenario field.

Violation consequence. Non-deterministic ordering produces different Adj-RIB-In insertion order → different best-path tie-breaks → different Catchment. Test results become flaky; conformance fixtures fail intermittently.

P2 — BGP Semantic Fidelity

Statement. The best-path decision process in acast-bestpath follows the real BGP tie-break ladder exactly; no shortcuts, no approximations.

Ladder (Phase 4, in order): highest local-pref → shortest AS-path length → lowest origin type (IGP < EGP < incomplete) → lowest MED (same neighbor AS) → eBGP over iBGP → lowest next-hop IGP metric → lowest router-id (last resort).

Tradeoffs. Full ladder requires per-route attribute storage (BgpRoute carries local_pref, as_path, med, origin type). Memory cost is bounded and acceptable (P7).

Operational implication. When two routes are equal through step N, the simulator must proceed to step N+1, never stop early. acast-bestpath::cmp_routes(a: &BgpRoute, b: &BgpRoute) -> Ordering encodes the full ladder as a chain of comparators.

Violation consequence. Wrong ladder → wrong Loc-RIB winner → wrong Adj-RIB-Out → wrong UPDATE propagated → wrong Catchment. The error is silent and contaminates every downstream metric.

P3 — Policy Over Reachability

Statement. Routes propagate according to Gao-Rexford economics (valley-free export), not shortest-path flooding. A route learned from a peer/provider is not exported to a peer or provider.

Mechanism. acast-policy enforces export rules at Adj-RIB-Out generation time. The Relationship enum encodes the economic direction. Import local-pref defaults: customer 300, peer 200, provider 100 (stored in PolicyConfig).

Tradeoffs. Valley-free makes the AS graph sparser than full-mesh flooding. Some ASes may have no route to a prefix (correctly). Reachability is a derived property, not an input.

Operational implication. Every test checking connectivity must account for valley-free filtering. An AS with only provider neighbors reaching an anycast PoP will not propagate that route to its other providers (I4).

Violation consequence. Exporting a provider route to a peer causes free-riding traffic, inflates Catchment incorrectly, and violates Gao-Rexford stability conditions. The simulator would overcount reachable ASes and report wrong PoP loads.

P4 — Anycast Catchment Is Emergent

Statement. No node decides which PoP serves a client AS. Catchment falls out of every AS independently running best-path on a multiply-originated prefix. The simulator does not assign clients to PoPs; it observes.

Mechanism. AnycastPrefix announces from multiple (Asn, PoPId) origins, each with identical prefix but distinct origin_pop tag. Propagation runs identically per Phase 5. Each AS's Loc-RIB entry carries the winning origin_pop. Catchment = map over all ASes of their Loc-RIB origin_pop.

Tradeoffs. Emergent catchment means operators cannot directly control which AS is served by which PoP — only indirectly via TE knobs (Phase 12). This is faithful to real-world behavior.

Operational implication. Phase 8 catchment analysis is a read-only traversal of Loc-RIBs. No separate "assignment" step. Catchment diffing compares two Catchment maps element-wise.

Violation consequence. A simulator that assigns clients centrally produces incorrect results under asymmetric policy and fails to capture real-world TE effects.

P5 — Convergence Is Observable and Measurable

Statement. Every run produces a ConvergenceReport with events_processed, updates_sent, withdraws_sent, converge_time, and oscillation flag. Non-convergence is detected and reported, never silently hidden.

Mechanism. Phase 9 runs the EventQueue to quiescence (empty queue, no pending announces). converge_time = VirtualClock at quiescence minus start time. oscillation is flagged when the same prefix best-path changes more than a configurable threshold count.

Tradeoffs. An oscillating scenario never reaches quiescence; the engine must have a configurable max-event budget (in scenario DSL) to terminate. Partial Catchment is reported with the oscillation flag set.

Operational implication. Conformance fixtures in Phase 14 assert exact convergence counts for canonical topologies. Regressions in propagation logic appear as changed event counts before catchment changes.

Violation consequence. Hiding non-convergence produces a Catchment map that appears valid but reflects a mid-oscillation state. Operators draw incorrect conclusions about failover behavior.

P6 — AS-Path Is the Loop-Prevention and Metric

Statement. The AS-path attribute serves dual purpose: loop detection (reject any route whose AS-path contains the local ASN on import) and primary post-local-pref metric (shorter is better). No separate loop-detection mechanism exists.

Mechanism. On RecvUpdate, acast-bgp checks as_path.contains(local_asn) before installing into Adj-RIB-In. Phase 4 tie-break step 2 compares as_path.len().

Tradeoffs. AS-path prepending (Phase 12) deliberately inflates path length to deprioritize a PoP. Prepend count must be capped (max 10) to prevent pathological route selection.

Operational implication. AS-path comparison uses length only at step 2; subsequent steps (MED, eBGP/iBGP) break further ties. acast-bestpath must not short-circuit at path length when lengths are equal.

Violation consequence. Omitting the loop check allows routing loops to form — UPDATE storms consume all events and the simulator never converges. Miscomputing path length causes wrong PoP selection and incorrect TE response in Phase 12.

P7 — Scale to Internet Size

Statement. Data structures are sized for tens of thousands of ASes (Phase 13 target: 70 000 ASes, 1M+ events per scenario). Per-AS state is compact; RIBs use memory-efficient representations.

Mechanism. Asn(u32) = 4 bytes. BgpRoute fields are fixed-size value types or compact Vecs. Loc-RIB is HashMap<Prefix, BgpRoute>; Adj-RIB-In is HashMap<(Asn,Prefix), BgpRoute>. No string-keyed maps in the hot path. Vec<Asn> encodes AS-path as Vec<u32>.

Tradeoffs. Full Internet topology (70k ASes x 400k prefixes) would require naive storage exceeding practical limits. Phase 13 mitigates with: single anycast prefix per scenario, compact AS-path encoding, and lazy Adj-RIB-Out (compute on propagation, not stored per-neighbor at rest).

Operational implication. Profile memory at 10k, 30k, 70k ASes before Phase 14. If per-AS RIB exceeds 1 KB average, revisit Adj-RIB-Out storage strategy.

Violation consequence. Fat per-route structures cause OOM on large topologies, making the simulator useless for realistic Internet modeling. Phase 13 conformance fixtures fail with heap exhaustion before convergence.

P8 — Mechanism and Policy Are Separated

Statement. acast-bgp handles route installation, RIB transitions, and UPDATE/WITHDRAW emission. acast-policy holds all economic rules: local-pref assignment, export filtering, prepend, MED, community matching. Neither crate imports the other's policy logic.

Mechanism. acast-bgp calls into acast-policy via two interfaces: apply_import_policy(route, neighbor_rel) -> Option<BgpRoute> and apply_export_policy(route, neighbor_rel) -> Option<BgpRoute>. Returning None drops the route.

Tradeoffs. The interface boundary adds one indirection per route. Acceptable: policy calls are infrequent relative to best-path comparisons.

Operational implication. Unit tests for propagation use a pass-through policy (identity import, unrestricted export). Policy tests are isolated in acast-policy. This decomposition matches RFC 4271's import/export model.

Violation consequence. Entangling policy into propagation makes it impossible to test propagation correctness independently and causes policy changes to ripple through the propagation engine, introducing subtle RIB-consistency bugs.

P9 — Withdrawals Are First-Class

Statement. Route withdrawals are modeled with the same fidelity as announcements. Every RIB tier must correctly remove entries on withdrawal. Failure modeling (Phase 10) depends on withdrawal cascades propagating to all downstream ASes.

Mechanism. WithdrawMsg triggers removal from Adj-RIB-In, re-runs best-path (possibly installing an alternative or removing the prefix from Loc-RIB), then generates Adj-RIB-Out diff and emits WITHDRAW to neighbors that were receiving this route.

Tradeoffs. Withdrawal cascade is O(depth of AS graph) events in the worst case. Correctness requires processing all withdrawals before announcing alternatives; cold-potato re-announcement is immediate.

Operational implication. acast-fault link-down events inject WithdrawMsg for all routes traversing the failed link. Tests must verify that Catchment shifts to an alternative PoP after withdrawal, not that the prefix becomes unreachable.

Violation consequence. Incomplete withdrawal leaves stale routes in Loc-RIB, causing Catchment to still point to a failed PoP. Failover tests in Phase 10 appear correct but are wrong under repeated fault injection.

P10 — Reproducible Scenarios

Statement. A scenario file (acast-scenario DSL) fully determines a run: topology reference, announcements, fault timeline, and asserts. Two runs of the same scenario file produce identical ConvergenceReport and Catchment.

Mechanism. Scenario files encode all Announce and fault events at explicit virtual times. No runtime randomness enters scenario execution. The PRNG seed for synthetic topology generation is a required scenario field.

Tradeoffs. Pre-scheduled fault timelines require the scenario author to reason about virtual time. The DSL provides a helper construct (after_convergence +N_ms) that translates to absolute virtual times during parse.

Operational implication. Phase 14 conformance suite is a directory of scenario files with golden ConvergenceReport and Catchment JSON. CI re-runs each scenario and diffs outputs. Any deviation is a regression.

Violation consequence. Non-reproducible scenarios make regression testing meaningless and prevent debugging from scenario replay. The simulator loses its value as a specification and validation tool.

P11 — Fail Loud on Structural Invariant Violation

Statement. Every detected violation of a structural invariant (I1–I10) causes an immediate, loud failure — panic in debug builds, counter increment + log in release — never silent data corruption.

Mechanism. Each invariant in the §7 table names its enforcement site. Debug-mode assert! macros enforce I1, I2, I3, I6. Release builds use saturating counter increments and structured log events at ERROR level. No invariant is monitored via periodic scrape alone.

Tradeoffs. Panicking on invariant violation in debug builds means tests fail fast but may not pinpoint root cause in large topologies. Mitigation: the event trace (Phase 13) provides a deterministic replay path to the exact event that triggered the violation.

Operational implication. Catching a violation counter > 0 in monitoring (Phase 14) triggers the runbook for that invariant class. The counter namespace mirrors the invariant table (sim.clock_violations, bgp.loop_rejected, etc.).

Violation consequence. Silent invariant violations propagate wrong state (incorrect Loc-RIB, stale Adj-RIB-Out) through the simulation; errors manifest as wrong Catchment silently, which is undetectable without a ground-truth comparison.

P12 — Crate Boundaries Mirror Domain Boundaries

Statement. Each crate in the workspace has a single domain responsibility; cross-domain dependencies are explicit and one-directional (no circular dependencies). Domain boundaries: event engine (acast-sim), topology (acast-topology), BGP protocol (acast-bgp), policy (acast-policy), best-path (acast-bestpath), anycast (acast-anycast), fault (acast-fault), metrics (acast-metrics), scenario (acast-scenario), CLI (acast-cli), core types (acast-core).

Mechanism. Cargo workspace with explicit [dependencies] sections. acast-core has zero internal dependencies. acast-bestpath depends only on acast-bgp and acast-core. Circular dependency fails cargo check. CI enforces via cargo deny or workspace graph lint.

Tradeoffs. Strict boundary enforcement means some types must live in acast-core that conceptually belong to a higher layer (e.g., Community is used by both acast-policy and acast-bgp). Minor layering compromise accepted for usability.

Operational implication. New functionality that crosses two existing crates triggers a design review: either create a new crate or promote the shared type to acast-core. This keeps the dependency graph shallow and the build incremental.

Violation consequence. Circular dependencies break incremental compilation and make the crate graph unreadable. Cross-domain coupling leaks implementation details across boundaries, making future refactoring expensive.

8.4 BGP Best-Path Tie-Break Ladder (Phase 4)

Ordered descending priority; first difference wins. Implements total order on BgpRoute.

Rank Criterion Direction Note
1 local_pref higher wins set by import policy; enforces I5
2 AS-path length shorter wins as_path.len()
3 Origin type IGP < EGP < Incomplete encode as u8 0/1/2
4 MED lower wins only when same neighboring AS; ignored cross-peer
5 eBGP > iBGP eBGP preferred flag on route
6 Lowest next-hop router-id lower Asn wins deterministic total order

Tie at rank 6 → Asn numeric order. No further tiebreaks. Exact model of RFC 4271 sec. 9.1.2.

8.5 Gao-Rexford Policy Model (Phase 6)

Import local-pref assignment:

Relationship (from local AS view) Default local_pref
Customer 300
Peer 200
Provider 100

Export filter (valley-free, I4):

Route learned from Export to Customer Export to Peer Export to Provider
Customer yes yes yes
Peer yes no no
Provider yes no no

Violation: route withheld silently. acast-policy returns None from export_filter(); acast-bgp never schedules the UpdateMsg. Policy logic lives exclusively in acast-policy (P8).

8.6 Anycast Origin and Catchment Derivation (Phase 7)

AnycastPrefix { prefix P, announcing_pops: [(AS_a, PoP_1), (AS_b, PoP_2), (AS_c, PoP_3)] }

Each origin AS announces BgpRoute { prefix: P, as_path: [AS_x], origin_pop: Some(PoP_x), local_pref: 300 } as if self-originated.

Propagation: standard BGP UPDATE cascade. Each receiving AS runs best-path independently. Winner's origin_pop tag carried in Loc-RIB.

Catchment derivation at quiescence:

for each AS k:
    Catchment[k] = Loc-RIB[k][P].origin_pop   // Some(PoPId) or None if unreachable

I6: each AS maps to exactly one PoP or None. No split mapping. Catchment is emergent (P4) — no coordinator, no central assignment.

8.7 Discrete-Event Scheduling Semantics (Phase 1)

SimEvent total order: (time: u64, seq: u64) lexicographic. seq is global monotonic counter; incremented on every schedule() call.

VirtualClock { now: u64, seq: u64 }

schedule(delay: u64, kind: BgpEvent) → SimEvent:
    ev = SimEvent { time: now + delay, seq: fetch_add(seq, 1), kind }
    EventQueue.push(ev)

dispatch_next():
    ev = EventQueue.pop_min()   // (time, seq) order
    now = ev.time
    handle(ev.kind)

run_until_quiescent():
    while !EventQueue.is_empty():
        dispatch_next()

Determinism (I1): identical seed topology + announcement schedule → identical seq assignment → identical dispatch order. No OS threads, no system clocks, no external RNG.

Cancel semantics: cancelled events remain in heap; dispatch_next checks cancelled: HashSet<(u64,u64)> and skips. No heap surgery. Amortized O(log n) dispatch.

8.8 Event Grammar (EBNF)

SimEvent     ::= { time: u64, seq: u64, kind: BgpEvent }
BgpEvent     ::= RecvUpdate(src: Asn, route: BgpRoute)
               | RecvWithdraw(src: Asn, prefix: Prefix)
               | LinkDown(a: Asn, b: Asn)
               | LinkUp(a: Asn, b: Asn)
               | NodeDown(asn: Asn)
               | Announce(origin: Asn, route: BgpRoute)
               | Withdraw(origin: Asn, prefix: Prefix)

UpdateMsg    ::= { src: Asn, dst: Asn, route: BgpRoute }
WithdrawMsg  ::= { src: Asn, dst: Asn, prefix: Prefix }

Propagation: RecvUpdate at AS k → import policy → Adj-RIB-In update → best-path → if Loc-RIB changed → for each eligible neighbor n: schedule RecvUpdate(k,…) or RecvWithdraw(k,…) at now + link_latency(k,n).

8.9 Convergence Measurement (Phase 9)

ConvergenceReport accumulates over one run_until_quiescent() call:

Field Type Semantics
events_processed u64 total dispatch_next() calls
updates_sent u64 UpdateMsg events scheduled
withdraws_sent u64 WithdrawMsg events scheduled
converge_time u64 VirtualClock.now at quiescence minus run start
oscillation bool any (AS, prefix) Loc-RIB winner cycled

Path-hunting detection: per (AS, prefix) count how many times origin_pop changes in Loc-RIB during propagation. High churn = transient route exploration, not necessarily oscillation.

Oscillation (Griffin-Shepherd-Wilfong policy dispute): oscillation = true if same (AS, prefix) winner repeats a cycle. Simulator halts at max_events threshold, sets flag, reports; does not attempt resolution. P5 mandates this is reported, not silently hidden.

8.10 Fault Injection Model (Phase 10)

Fault events scheduled by scenario DSL into EventQueue:

Fault kind BgpEvent Cascade behavior
Link failure LinkDown(a, b) Each of AS a, AS b: purge Adj-RIB-In entries from peer across link → re-run best-path → emit WITHDRAW if no alternate (I7)
Link recovery LinkUp(a, b) Re-establish adjacency; trigger fresh UPDATEs for Loc-RIB routes to peer
Node failure NodeDown(asn) LinkDown for all incident links at same time; cascades independently
PoP withdrawal Withdraw(origin_as, prefix) Origin AS withdraws announcement; cascade WITHDRAW through topology

I7: withdrawal purges every RIB entry whose AS-path traverses the failed element. On LinkDown(a,b): both AS a and AS b iterate Adj-RIB-In for routes received over the link, remove each, re-run best-path.

8.11 Worked Example — Three-AS Anycast

Topology: AS1 (customer of AS2), AS3 (customer of AS2). PoP_A announced from AS1; PoP_B announced from AS3. Link latency = 10 ms.

t Event AS Adj-RIB-In state Loc-RIB[prefix] Action

8.12 Malformed / Failure-Path Example

AS-path loop rejection (I3):

RecvUpdate(src=AS5, route={ as_path:[5, 2, 7, 2], prefix:10.0.0.0/8 })

AS2 import: scan as_path for own ASN 2. Found at index 1 and 3. Reject; route never enters Adj-RIB-In. Silent drop per BGP semantics. No error event emitted.

Valley-free export violation (I4):

AS2 holds 10.0.0.0/8 learned from peer AS4.
AS2 scenario asserts this route is visible at provider AS3.

export_filter(route, neighbor_rel=Provider) returns None. Adj-RIB-Out[AS3] for 10.0.0.0/8 empty. No UpdateMsg scheduled. Scenario assert fails with Catchment[AS3] = None. Expected failure in conformance test.

MED cross-peer comparison (rejected):

AS2 receives {prefix P, MED=50} from AS4 and {prefix P, MED=10} from AS5.

MED compared only within same neighboring AS. Different peers AS4 vs AS5 → MED comparison skipped. Tie resolved at rank 6 (next-hop router-id). Cross-peer MED comparison is a config option, off by default.

8.13 Edge Cases

Case Handling
Two PoPs equidistant at every rank Deterministic by Asn numeric order at rank 6; one PoP wins; never split
AS unreachable from all origin ASes Catchment[asn] = None; counted in unreachable_count metric
PoP failure holding majority catchment NodeDown → cascade WITHDRAWs; surviving PoPs absorb; ConvergenceReport records shift time
Zero-length AS-path Reject on import; valid only for self-originated routes where local AS adds itself
local_pref in eBGP UPDATE Stripped on import; receiver assigns from Relationship; RFC 4271 sec. 5.1.5
Topology island (AS disconnected from origin) No route propagates; Catchment = None
MOAS without PoP tag origin_pop = None; Catchment values are None for these routes; metrics skip pop assignment
Community stripping at AS boundary export_filter clears communities per PolicyConfig.community_strip flag
Simultaneous multi-link failure LinkDown events at same time, different seq; dispatched in seq order; cascades compose
EventQueue empty before scenario asserts Quiescence reached; asserts evaluated against final Catchment snapshot

8.14 Trace / Storage Layout

Simulation trace: NDJSON, one JSON object per line, to stdout or file path.

trace-record fields:
  t       : u64          virtual time
  seq     : u64          event sequence number
  kind    : string       BgpEvent variant name
  asn     : u32          AS processing the event
  prefix  : string       CIDR notation (e.g., "1.2.3.0/24")
  pop     : u32 | null   origin_pop value
  detail  : object       variant-specific fields (neighbor, as_path, etc.)

Catchment snapshot record:

{ "t": u64, "prefix": string, "map": { "<asn>": <pop_id> | null, ... } }

ConvergenceReport serialized as flat JSON; one file per scenario run at reports/<scenario_name>.json.

Scenario DSL: TOML file. Topology: CAIDA AS-relationships text (<asn1>|<asn2>|<rel>, rel ∈ {-1,0,1}).

8.15 Memory / Ownership Model

Structure Owner Lifetime Notes
AsNode collection Topology: HashMap<Asn, AsNode> scenario lifetime mutated in-place during dispatch
Rib per AsNode AsNode same Adj-RIB-In: HashMap<(Asn,Prefix), BgpRoute>
EventQueue SimEngine scenario lifetime owns SimEvent by value; BinaryHeap in std
BgpRoute in Adj-RIB-In Rib until replaced/withdrawn cloned on insert; Arc<BgpRoute> for long as_path
Catchment snapshot AnycastEngine computed on demand ephemeral; not retained across scenarios
Trace writer SimEngine scenario lifetime write-only; buffered; flushed at quiescence

Single-threaded: SimEngine holds &mut Topology; dispatch handler takes &mut AsNode for target AS. No Send requirement on core types. No locks. No async runtime.

Phase 1 — Discrete-event simulation engine

1.1 Objectives

  • Implement acast-sim: EventQueue, VirtualClock, deterministic dispatch loop.
  • Guarantee: identical seed scenario → identical event order → identical catchment (P1, I1).
  • Establish the scheduling substrate that every subsequent phase plugs into; no BGP logic here.
  • Constraint: all time comparisons use u64 microseconds; no floating-point in ordering.

1.2 Detailed Implementation Steps

Applies: P1 (deterministic dispatch), I1 (clock monotonicity), ADR-05 (BinaryHeap), ADR-06 (single-thread), B8 (DES paradigm), B6 (min-heap scheduling).

Module layout (acast-sim/src/):

File Responsibility
engine.rs SimEngine: owns EventQueue, VirtualClock, dispatch loop
queue.rs EventQueue: BinaryHeap<Reverse<SimEvent>>, schedule, cancel, peek, pop
clock.rs VirtualClock: current time, monotonicity guard
dispatch.rs Trait EventHandler; engine calls handler.handle(event, ctx)
lib.rs Re-exports; public API surface

SimEvent ordering: Ord impl on SimEvent sorts by (time, seq) ascending; seq is a global AtomicU64 counter incremented on every schedule() call — ensures FIFO within a single virtual millisecond.

EventQueue operations:

  • schedule(kind, time) -> SimEvent — assign next seq, push to heap, return handle.
  • cancel(seq) — mark seq in a HashSet<u64> cancelled; pop discards cancelled events lazily.
  • pop() -> Option<SimEvent> — drain cancelled events, return first live event or None.
  • run_until_quiescent(handler) — loop pop → dispatch until queue empty; update VirtualClock before each dispatch.

Determinism checklist:

  • Single-threaded dispatch; no Arc<Mutex> in the hot path.
  • seq counter reset to 0 at scenario init; seeded deterministically from scenario id.
  • No OS time calls inside simulation; VirtualClock is the only time source.

1.3 Deliverable

  • acast-sim crate compiles; run_until_quiescent drives a synthetic event trace to empty queue.
  • CLI smoke-test: schedule 1 000 events at random virtual times; verify pop order matches (time,seq) sort.
  • VirtualClock is inspectable; dispatch count is exposed as SimEngine::events_processed().

1.6 Pitfalls

  • Clock regression: handler re-schedules event at time < current_clock — accepted into heap, violates I1. Guard: schedule() panics in debug mode if time < clock.now().
  • Cancelled-event accumulation: large batch-cancel without pops causes HashSet growth; use a generation counter and periodic compaction after pop drains a generation.
  • Seq overflow: u64 seq wraps at 2^64; in practice unreachable, but assert seq != u64::MAX in debug.
  • BinaryHeap re-entrancy: handler must not borrow EventQueue during dispatch; pass queue as &mut only outside the dispatch closure.
  • Quiescence false positive: a handler that schedules no new events but another handler does; ensure the outer loop re-checks after every handle() return.

1.7 Performance Concerns

  • BinaryHeap has O(log n) push/pop; at 100 k simultaneous events the heap stays under 2 MB.
  • Lazy cancel avoids O(n) deletion; HashSet lookup is O(1) amortized.
  • Avoid Box<dyn EventHandler> in the hot path; prefer an enum dispatch or monomorphic handle().
  • Batch-schedule multiple events for one logical step to amortize heap rebalancing.
  • SimEvent size: keep <= 32 bytes to fit two per cache line; avoid embedding large payloads.

1.8 Edge Cases

  • Zero-duration run: run_until_quiescent on empty queue returns immediately without panic.
  • Duplicate seq: impossible if AtomicU64 increments atomically; assert uniqueness in test mode.
  • Handler schedules event at time = clock.now() (zero-delay): valid, inserted with next seq.
  • Re-entrant run_until_quiescent: second call while already running must panic, not silently nest.
  • u64 time wraps in far-future edge test: add overflow check in schedule.

Phase 4 — Best-path decision process

4.1 Objectives

  • Implement the canonical BGP tie-break ladder as a deterministic total order over BgpRoute values.
  • Populate Loc-RIB with the single winner per prefix; replace on change; trigger Phase 5 propagation.
  • Enforce I2: Loc-RIB best path is a pure function of Adj-RIB-In plus PolicyConfig — no side effects.
  • Crate: acast-bestpath; called from acast-bgp after every Adj-RIB-In mutation.

4.2 Detailed Implementation Steps

Applies: P2 (BGP semantic fidelity), I2 (best-path determinism), ADR-13 (Ord impl), B2 Ch.5 (best-path algorithm), B3 Ch.8 (attribute precedence), R6 (bgp_best.c production ladder).

Tie-break ladder (ordered, first difference wins):

Step Criterion Winner Notes
1 local_pref Higher Set by import policy (acast-policy) before reaching bestpath
2 AS-path length Shorter as_path.len()
3 Origin type IGP < EGP < Incomplete Encoded as OriginType: u8 in BgpRoute; lower numeric = preferred
4 MED Lower Only compared when routes arrive from same neighboring AS (same peer ASN)
5 eBGP > iBGP eBGP Determined by next_hop != local_asn; iBGP deprioritized
6 Lowest next-hop (router-id) Numerically lower Asn Final deterministic tiebreak
  • fn compare_routes(a: &BgpRoute, b: &BgpRoute, local_asn: Asn, med_neighbor: Option<Asn>) -> Ordering — no body, returns total order.
  • fn select_best(routes: impl Iterator<Item=&BgpRoute>, local_asn: Asn) -> Option<&BgpRoute> — scans Adj-RIB-In for a prefix, applies ladder, returns winner reference.
  • MED comparison guard: med_neighbor is Some(asn) only when both candidates share the same upstream ASN; otherwise skip MED step.
  • After winner determined, compare against current Loc-RIB entry: if equal (by BgpRoute field equality) skip update; otherwise replace and mark loc_rib_changed = true.
  • OriginType enum added to acast-core: { Igp=0, Egp=1, Incomplete=2 }; BgpRoute carries it.
  • Module layout: acast-bestpath/src/lib.rs exports compare_routes, select_best, BestPathResult { old: Option<BgpRoute>, new: Option<BgpRoute>, changed: bool }.
  • Unit test harness: tests/ladder.rs exercises every rung with synthetic route pairs ensuring correct winner.

4.3 Deliverable

  • acast-bestpath compiles independently; select_best returns correct winner for any Adj-RIB-In snapshot.
  • acast-bgp calls select_best after every Adj-RIB-In write and updates Loc-RIB accordingly.
  • BestPathResult indicates whether Loc-RIB changed, gating Phase 5 propagation.

4.4 Acceptance Criteria

  • All 9 ladder-rung unit tests pass (one test per rung + tie at each step).
  • compare_routes is a strict total order: antisymmetric, transitive, total — verified by property test over 1000 random route triples.
  • MED comparison only fires when both routes share identical upstream ASN (fixture: med_different_peer.ron — MED step must be skipped).
  • Loc-RIB update is idempotent: applying the same Adj-RIB-In twice yields no second loc_rib_changed = true.
  • Benchmark: select_best over 50 candidate routes for one prefix completes in < 2 µs on reference hardware.

4.6 Pitfalls

  • MED scope creep: comparing MED across routes from different upstream ASes violates RFC 4271 sec. 9.1.2.2; symptom is non-deterministic catchment shifts when multiple providers advertise same prefix. Guard: med_neighbor parameter.
  • Partial Ordering bug: implementing PartialOrd without total order causes sort instability; always implement via compare_routes returning Ordering, derive nothing.
  • Stale Loc-RIB after withdrawal: withdrawing one candidate does not automatically re-run best-path over remaining candidates; must re-scan full Adj-RIB-In. Symptom: Loc-RIB retains withdrawn route.
  • iBGP detection by ASN equality: if next_hop == local_asn is used as iBGP signal, ensure local_asn is correctly threaded into compare_routes; wrong value silently inverts step 5.
  • Tie on all six steps: two routes identical on every field except origin_pop; add origin_pop as step 7 tiebreak (lower PoPId u32) to preserve determinism per I2.

4.7 Performance Concerns

  • Adj-RIB-In for a prefix can hold O(degree) routes; full linear scan per prefix update is correct and fast for typical degree <= 10k; no heap needed inside select_best.
  • Avoid cloning BgpRoute during comparison; pass references; clone only when writing winner into Loc-RIB.
  • as_path.len() is O(1) if Vec; do not traverse path during comparison.
  • Cache local_pref and as_path.len() as struct fields populated once at import time to avoid recomputation per comparison.

4.8 Edge Cases

  • Route with as_path = [] (locally originated): length 0, beats all received routes at step 2; ensure this is intended for PoP-originating AS.
  • Two routes with identical as_path containing duplicate ASNs (malformed); AS-path length still computed as Vec::len(); loop check (I3) must reject routes already containing local_asn before they reach best-path.
  • local_pref = 0 is valid (minimum); do not treat as "unset" sentinel; unset local-pref must be initialized to default (100) by acast-policy before reaching acast-bestpath.
  • MED value u32::MAX: valid; no overflow in comparison.
  • All routes withdrawn for a prefix: select_best returns None; Loc-RIB entry must be removed, triggering a WITHDRAW downstream (Phase 5).

4.9 Failure Analysis

  • Wrong winner selected: root cause is ladder step mis-order or missing guard; detection via conformance fixtures in CI; blast radius is entire catchment map; recovery requires correcting compare_routes and re-running scenario.
  • Non-convergence due to ordering cycle: cannot occur if compare_routes is a true total order; detect with property test; postmortem: add assert!(compare_routes(a,b,...) != compare_routes(b,a,...) || a_fields_equal_b).
  • Loc-RIB drift from Adj-RIB-In: missed re-run of best-path after withdrawal; instrument with loc_rib_stale counter in acast-metrics; recovery: forced re-scan on assertion failure.

Phase 5 — Route propagation

5.1 Objectives

  • Propagate Loc-RIB changes to neighbors: recompute Adj-RIB-Out, emit UpdateMsg/WithdrawMsg events into EventQueue.
  • Process RecvUpdate/RecvWithdraw events: install into Adj-RIB-In, invoke Phase 4 best-path, recurse.
  • Implement withdrawal cascade: failure of one route triggers withdrawals to all downstream neighbors.
  • Enforce I9: at quiescence, Adj-RIB-Out[n] equals policy-filtered projection of Loc-RIB.
  • Crates involved: acast-bgp (RIB mutation, event emission), acast-policy (export filter, called here), acast-sim (event scheduling).

5.2 Detailed Implementation Steps

Applies: P2 (BGP fidelity), P8 (mechanism-policy separation), P9 (withdrawals first-class), I7 (withdrawal cascade), I9 (Adj-RIB-Out consistency), ADR-14 (ImportPolicy/ExportPolicy hooks), B9 (loop prevention).

Propagation loop (per AS, per prefix, triggered by Loc-RIB change):

Loc-RIB[prefix] changed (new_best or None)
  for each neighbor n:
    exported = acast-policy::export_filter(new_best, self.asn, rel_to_n)
    prev = Adj-RIB-Out[n][prefix]
    if exported == prev: skip
    if exported.is_some():
      Adj-RIB-Out[n][prefix] = exported
      schedule SimEvent { time: now + link_latency(n), kind: BgpEvent::RecvUpdate(n, prefix, exported) }
    else if prev.is_some():
      Adj-RIB-Out[n][prefix].remove()
      schedule SimEvent { time: now + link_latency(n), kind: BgpEvent::RecvWithdraw(n, prefix) }
  • fn propagate_loc_rib_change(asn, prefix, new_best: Option<BgpRoute>, topology, event_queue, clock) — signature only; no body.
  • RecvUpdate handler: fn recv_update(asn, from_neighbor, route, topology, event_queue, clock) — prepend local ASN to AS-path is NOT done on import; done on export (AS-path is sender's path + self).
  • AS-path prepend on export: before writing to Adj-RIB-Out and emitting UpdateMsg, prepend self.asn to as_path.
  • RecvWithdraw handler: remove from Adj-RIB-In[from_neighbor][prefix]; re-run select_best; if Loc-RIB changes, recurse via propagate_loc_rib_change.
  • Loop-check on import: if as_path contains self.asn, drop silently (I3); increment loop_rejected counter.
  • All emitted events carry virtual time = clock.now() + link_latency_ms(link) — latency from acast-topology.
  • Withdrawal cascade: when new_best = None, export_filter returns None for all neighbors; all neighbors receive RecvWithdraw; they re-run best-path; may withdraw further downstream.
  • Idempotent re-propagation guard: if exported == prev { continue } prevents re-emitting duplicate events.

5.6 Pitfalls

  • AS-path prepend on import vs export: prepending on import causes incorrect path lengths stored in Adj-RIB-In; must prepend only when exporting (writing Adj-RIB-Out). Symptom: AS-path one hop longer than expected at receiver.
  • Missing idempotent guard: without exported == prev check, stable topology generates infinite event stream; simulator never quiesces. Detect via max_events circuit breaker in acast-sim.
  • Cascade miss on partial withdrawal: withdrawing one of two paths from neighbor A does not trigger re-propagation if Loc-RIB winner did not change; correct — only Loc-RIB change drives propagation. Symptom if coded wrong: spurious withdrawals to downstream.
  • RIB inconsistency after crash-recovery: if Adj-RIB-Out is not rebuilt from Loc-RIB on restart, orphaned entries remain; always rebuild Adj-RIB-Out from Loc-RIB + policy at startup.
  • Link latency = 0: valid; events at same virtual time must use seq for ordering (I1); do not assume latency > 0.
  • Withdraw of non-existent route: RecvWithdraw for a prefix not in Adj-RIB-In[from_neighbor]; must be a no-op (not an error); RFC 4271 allows this.

5.7 Performance Concerns

  • Propagation fan-out: each Loc-RIB change triggers O(degree) neighbor evaluations; for high-degree ASes (tier-1, degree ~5000), batch neighbor evaluation.
  • Avoid allocating new BgpRoute per neighbor export; apply AS-path prepend lazily or use a thin wrapper struct to avoid cloning the full route per neighbor.
  • Adj-RIB-Out write per neighbor is O(1) hash map insert; total cost per prefix change: O(degree).
  • Event queue insert per scheduled event: O(log N) heap push; batch if multiple neighbors share same latency.
  • loop_check: O(path_len) linear scan; path length bounded by AS diameter (~10 in practice); negligible.

  • Simultaneous updates from two neighbors arrive at same virtual time; seq ordering in EventQueue determines processing order; result must be deterministic (I1, I10).
  • Route with as_path.len() = 0 imported from neighbor: invalid (neighbor must prepend own ASN); reject with malformed_update counter; do not install.
  • Circular topology (A-B-C-A) without policy dispute: loop-check prevents looping; simulation reaches quiescence.
  • Prefix with no origin AS (no announcement): no entries in any Adj-RIB-In; select_best returns None; Loc-RIB absent; propagation emits nothing.
  • link.up = false (Phase 10): events must not be scheduled across a down link; propagation checks link.up before emitting.

5.9 Failure Analysis

  • Non-quiescence / event storm: missing idempotent guard; detection: events_processed counter exceeds configurable max_events threshold; acast-sim halts run and sets oscillation = true; postmortem: compare Adj-RIB-Out state before/after each event.
  • Silent route black-hole: withdrawal cascade missed because propagate_loc_rib_change not called for new_best = None; detection: catchment map contains stale PoP assignment after fault injection; compare against expected fixture.
  • Wrong AS-path at distant AS: prepend applied on wrong side; detection: path_prepend_verify.ron fixture; blast radius limited to correctness of AS-path-based metrics (path inflation in Phase 11).

6.6 Pitfalls

  • Valley-free inversion: confusing from_rel perspective — Relationship is always "this neighbor's role as seen from the current AS"; a route learned from a provider has from_rel = Provider. Misidentifying peer as customer silently violates I4.
  • LP applied before or after loop check: loop check rejects route before apply_import; if apply_import is called first, rejected routes still modify LP (wasteful but harmless); ordering matters for deny rules — deny in import must precede loop-check bypass.
  • AS-path prepend count overflow: u8 max 255, clamp to 255, do not panic on pathological config; community matching by value only: (u32, u32) equality must compare both halves, not first half alone.
  • MED from different source: MED set by apply_import must remain stable in Adj-RIB-In; do not re-apply apply_import on re-propagation; apply once on RecvUpdate.
  • No-advertise community: (65535, 1) RFC definition — must not be advertised to any external AS; distinct from no-export (65535, 0) which applies to eBGP only. Implement both.

6.7 Performance Concerns

  • apply_import and apply_export are called O(events x degree) times; must be allocation-free on hot path for default policy; return modified BgpRoute by value (copy semantics for small struct).
  • PolicyConfig lookups: HashMap per lookup; for default Gao-Rexford (no overrides), short-circuit with a fast default_lp(rel) -> u32 path before consulting HashMap.
  • Community list scan (Vec<Community> linear, sets typically < 20 entries, no optimization needed unless profiling shows otherwise); AS-path clone for prepend creates a new Vec — use SmallVec<[Asn; 16]> in BgpRoute.as_path to avoid heap allocation for paths <= 16 hops (covers ~99% of internet paths).

6.8 Edge Cases

  • Route with no communities: apply_export community checks must handle empty Vec without panic (no-op); prepend count = 0: no prepend, treat as identity, do not push zero ASNs.
  • Locally-originated route (origin AS = self): from_rel is undefined; treat as Customer for export policy purposes so it propagates to all neighbors.
  • PolicyConfig with conflicting LP overrides (both local_pref_by_rel and lp_community_map match): community-based LP takes precedence (more specific, documented in doc-comment); export to self (iBGP loop, single-AS simulation) — to_asn == self.asn excluded from export loop by acast-bgp before calling apply_export.
  • Route denied by apply_import (returns None): must not be installed in Adj-RIB-In; if a previously accepted route from same neighbor is replaced by a deny, treat as implicit withdrawal (remove from Adj-RIB-In, re-run best-path).

6.9 Failure Analysis

  • Valley-free violation silently breaks catchment: symptom is routes appearing in unexpected ASes, detection via valley_free_diamond.ron fixture, blast radius is full catchment correctness for the affected prefix, recovery is fixing from_rel assignment in topology loader or policy lookup; LP not applied (apply_import skipped for a route type): symptom is best-path using default LP=0 instead of 200, detection gao_rexford_lp.ron fails, blast radius is wrong PoP selected by all downstream ASes.
  • Import policy applied multiple times: if RecvUpdate re-processes already-imported routes, LP escalates; detection: Loc-RIB LP > 200 (above customer ceiling); instrument with lp_out_of_range counter.
  • Community filter over-suppresses: operator misconfigures community_export_filter; route silently not exported; detection: catchment map shows None for prefix (unreachable); alarm on unreachable_ases > 0 metric.

  • Engine hangs (no budget enforced): infinite loop if oscillation budget check not wired, detected by wall-clock watchdog in acast-cli (default 30s, signals TaskStop), root cause is quiescence condition missing a pending-event class (e.g. generator callbacks not counted); false oscillation: true from path exploration: path exploration always terminates with monotonically decreasing path_len while genuine oscillation shows non-monotone alternation — distinguish by requiring alternating is_install flag in ring buffer, not just repeated length.
  • ConvergenceError swallowed by caller: both Err variants include partial: ConvergenceReport; acast-cli must print partial report before exiting non-zero.
  • Postmortem for oscillation: true: identify offending (asn, prefix) from ring buffer last-N entries; check PolicyConfig for Gao-Rexford violations; run acast-cli check-valley-free --topology <file> to enumerate offending export rules.

Phase 10 — Fault Injection

10.1 Objectives

  • Schedule LinkDown, NodeDown, and PoP-withdraw events at arbitrary virtual-clock times via acast-fault.
  • On fault activation, cascade WithdrawMsg for every route whose AS-path traverses the affected element; I7 invariant mandates zero surviving routes via the failed element post-quiescence.
  • Measure catchment shift (delta between pre-fault and post-fault Catchment) and per-PoP failover volume; support multi-failure timelines (concurrent and sequential) plus LinkUp/NodeUp recovery events — scope spans acast-fault (new module), acast-sim (event scheduling), acast-bgp (withdrawal dispatch), acast-metrics (convergence reporting).
  • Constraint: fault events enter the same EventQueue as BGP events, ordered by (time, seq), fully deterministic (I1, I10); depends on Phase 5 (withdrawal propagation), Phase 7 (Catchment derivation), Phase 9 (convergence measurement).
  • Failover time = virtual clock delta from fault injection to post-fault quiescence, measured per fault event; recovery (LinkUp/NodeUp) generates a separate convergence report, pre-fault and post-recovery catchments compared to verify full restoration.

10.2 Detailed Implementation Steps

Applies: P1 (deterministic ordering), P9 (withdrawals first-class), I7 (full withdrawal cascade), I10 (scenario reproducibility), ADR-05 (EventQueue scheduling), P2 paper (Griffin SPP, non-convergence under dispute), P8 paper (Labovitz routing instability).

link-to-routes index (pre-computed in acast-topology):

  • HashMap<(Asn, Asn), Vec<(Asn, Prefix)>> mapping each directed link pair to routes whose as_path contains that adjacent pair.
  • Built incrementally (updated on every Loc-RIB change: route install/replace/remove); used by affected_routes for O(1) lookup, eliminating O(|RIB| × |path_len|) full scan.

Fault activation sequence (LinkDown)

  1. Set Link.up = false in acast-topology.
  2. Call cascade::affected_routes — enumerate all Adj-RIB-Out entries where next_hop == b (from a's view) or vice-versa.
  3. For each affected (neighbor, prefix) pair, inject BgpEvent::RecvWithdraw at (fault_time, next_seq), then trigger best-path recomputation in affected AsNodes and emit further WithdrawMsgs downstream (I7 enforcement).

NodeDown — iterate all neighbors, synthesize LinkDown for each adjacency, mark AsNode.active = false, reject any further RecvUpdate targeting that ASN. PoP-withdraw — find all (Asn, PoPId) in AnycastPrefix.announcing_pops matching pop, inject BgpEvent::Withdraw at origin ASN, cascade normally via Phase 5 propagation.

Recovery (LinkUp) — set Link.up = true, trigger BgpEvent::Announce for each route the AS would originate, re-establish adjacency, record failback convergence time separately from fault convergence time. Convergence measurement — FaultMonitor records Catchment snapshot pre-fault, polls quiescence after each fault, emits ConvergenceReport per fault event.

Multi-fault timelines — FaultScheduler accepts Vec<FaultSpec> sorted by at; each injected as independent SimEvent; overlapping faults handled by idempotent Link.up = false.

10.7 Performance Concerns

  • affected_routes without index: O(|RIB| × avg_path_len × |ASes|) — unacceptable at 50k scale; link-to-routes index reduces to O(|affected_routes|).
  • Batch WithdrawMsg events at same (time, seq+n) rather than enqueuing individually to reduce heap churn; pre-allocate seq range for entire cascade batch.
  • Pre-compute adjacency index neighbor_of[asn] -> Vec<Asn> for O(1) neighbor lookup during cascade; reuse ConvergenceReport struct to avoid per-event heap allocation.
  • For NodeDown on high-degree Tier-1 AS: cascade touches thousands of neighbors; generate all WithdrawMsg events in a single batch with monotonically ascending seq.
  • Catchment snapshot before fault is an O(|ASes|) clone (≈ 400 KB for 50k ASes, one allocation per fault event, acceptable); FaultMonitor quiescence detection polls EventQueue.len() == 0 after each tick, no separate thread, inline with simulation dispatch loop.

10.8 Edge Cases

  • LinkDown on link already up = false: idempotent, no second cascade; LinkDown where neither AS has routes for the prefix produces zero cascade events, link still marked down.
  • PoP-withdraw for PoP not in AnycastPrefix.announcing_pops: error logged, no panic; fault time equal to an in-flight UPDATE delivery time is resolved by (time, seq) ordering — UPDATE processed first if seq is lower.
  • All PoPs withdraw simultaneously: Catchment maps every AS to None, metric reports unreachable_count; LinkUp at same virtual time as another fault — both injected, processed in seq order.

Phase 11 — Latency + Path Inflation + Load

11.1 Objectives

  • Attach per-link latency_ms: u32 to Link and accumulate AS-path latency for each BgpRoute during propagation; compute client-to-serving-PoP latency using best-path AS-path and compare against optimal (Dijkstra on Link.latency_ms graph ignoring BGP policy).
  • Define and measure path inflation ratio: actual_latency / optimal_latency per client AS; captures the latency cost of BGP policy constraints vs physical shortest path.
  • Compute PoP load as weighted sum of client ASes assigned to each PoP (weight = optional traffic_weight: f64 per AS, default 1.0); detect hot-PoP when pop_load_fraction exceeds configurable threshold (default 0.5).
  • Compare anycast vs unicast: unicast routes all clients to single designated PoP; report latency delta and load improvement per AS.
  • Scope: acast-metrics (new computations), acast-topology (latency annotation), acast-anycast (path latency accumulation), acast-core (type extensions); depends on Phase 7 (Catchment + BgpRoute.as_path), Phase 8 (catchment maps), Phase 2 (Link.latency_ms field added here); design constraint: acast-metrics is a pure analytics crate, read-only access to simulation state, safe to run post-quiescence without re-executing simulation.

AS-path prepending (acast-policy / acast-bgp)

  • On export to neighbor n, if PrependSpec matches: append local_asn repeat times to as_path of outbound BgpRoute; receiving AS sees longer AS-path → lower best-path preference (step 2 after local-pref).

MED handling (acast-bestpath)

  • MED compared only between routes from the same neighboring AS (RFC 4271 sec. 9.1.2.2 default); always_compare_med = true enables cross-neighbor MED comparison.
  • Lower MED preferred; position in tie-break ladder is after eBGP>iBGP, before lowest router-id; MedSpec sets outbound MED on export to a provider/peer, influencing inbound traffic from that neighbor.

Community-based selective export (acast-policy)

  • Import: CommunityFilter { action: Deny } drops routes carrying matching community before Adj-RIB-In install; export: strip or tag communities per neighbor in Adj-RIB-Out construction.
  • No-export well-known community (RFC 1997): route not exported to eBGP peers when present, scoped to eBGP sessions only; standard TE pattern is PoP tagging a prefix with no-export toward upstream provider so the provider's customers cannot reach via that path.

Phase 13 — Scenario DSL + Scale

13.1 Objectives

  • Provide a declarative TOML/YAML scenario format consumed by acast-scenario: topology reference, per-PoP announcements, a timestamped fault timeline, and typed assertions on Catchment and ConvergenceReport.
  • Scale the simulator to ≥50 000 AS nodes and ≥10 000 000 events per scenario without heap explosion.
  • Guarantee I10: re-running an identical scenario file reproduces byte-identical catchment and convergence counts.
  • Expose a programmatic Scenario builder API alongside the file format so integration tests construct scenarios in code.

13.2 Detailed Implementation Steps

Applies: P1 (determinism), P10 (reproducible scenarios), I10 (replay identity), ADR-09 (TOML DSL), ADR-24 (reproducibility), P11 paper (Elmokashfi BGP scalability), B8 Ch.6 (seed control for determinism).

acast-scenario / scenario.rs

  • ScenarioFile struct: deserialize via serde from TOML; fields: topology_path, announcements: Vec<AnnounceSpec>, faults: Vec<FaultSpec>, asserts: Vec<AssertSpec>.
  • AnnounceSpec { at: u64, asn: Asn, pop: PoPId, prefix: Prefix } — emits BgpEvent::Announce at at into EventQueue.
  • FaultSpec { at: u64, kind: FaultKind, target: FaultTarget, recover_at: Option<u64> } — FaultKind: LinkDown | NodeDown | PopWithdraw; FaultTarget: Link(Asn,Asn) | Node(Asn) | Pop(PoPId).
  • AssertSpec: enum variants:
    • CatchmentEquals { asn: Asn, pop: Option<PoPId> } — asserts Catchment[asn] == pop after quiescence.
    • CatchmentSize { pop: PoPId, min: usize, max: usize }.
    • ConvergesWithin { max_events: u64, max_time: u64 }.
    • NoOscillation.
    • PathInflationBelow { asn: Asn, ratio: f64 }.
  • ScenarioRunner::run(scenario: &ScenarioFile, engine: &mut SimEngine) -> ScenarioResult — loads topology, schedules events, runs to quiescence, evaluates all asserts, returns pass/fail per assert with diagnostics.
  • AssertionError { spec: AssertSpec, actual: String } for reporting.

Compact RIB for scale (acast-bgp / rib.rs)

  • Replace HashMap<(Asn,Prefix), BgpRoute> in Adj-RIB-In with BTreeMap keyed (Asn, u128, u8) (packed IP+len) to reduce pointer chasing.
  • Loc-RIB: single BTreeMap<(u128,u8), BgpRoute> per AS; 128-bit key covers both IPv4 and IPv6.
  • Adj-RIB-Out: FxHashMap<Asn, SmallVec<[BgpRoute; 4]>> when prefix count per neighbor is low.
  • Arena-allocate AS-path Vec<Asn> using typed-arena; intern common short paths.
  • Per-AS memory budget: Adj-RIB-In ≤ 2 KB × neighbor-count for typical full-table.

Large topology loader (acast-topology / loader.rs)

  • Stream CAIDA AS-rel lines; build AsGraph without buffering full file.
  • AsGraph backed by Vec<AsNode> indexed by ASN via a sorted array + binary-search or FxHashMap<Asn,usize>.
  • Relationship validation: for every Link(a,b,rel), check symmetric: if a sees b as Customer, b must see a as Provider.
  • Graph stats: degree distribution, tier-1 detection (providers only), stub detection.

Determinism at scale

  • EventQueue tie-break: (time: u64, seq: u64) with seq from a global AtomicU64 incremented at schedule time, reset to 0 at scenario start.
  • Topology loader processes lines in sort order (ASN ascending) before building adjacency; eliminates load-order nondeterminism.
  • Scenario TOML has a seed field reserved for future use but currently ignored (determinism is structural, not RNG-based).

13.6 Pitfalls

  • Non-determinism from HashMap iteration order: FxHashMap iteration order is insertion-order-undefined; logic that iterates neighbors and emits events inherits ordering. Fix: sort neighbor list by Asn before iterating in propagation loops.
  • seq counter not reset between runs: if AtomicU64 is process-global and not reset per ScenarioRunner::run, replay diverges. Fix: pass seq_start into engine constructor; reset before each run.
  • Arena path interning cross-scenario contamination: arenas reused across scenarios intern wrong paths. Fix: allocate arena per ScenarioRunner::run invocation.
  • CAIDA symmetric-relationship assumption violated: ~2% of CAIDA lines have asymmetric annotations; loader must not panic, must log and skip with a warning.
  • Assert evaluated before quiescence: assert runs while events still in queue. Fix: run_until_quiescent must drain to zero events; check EventQueue::is_empty after each dispatch cycle including newly scheduled events.
  • Large-topology TOML embedding full adjacency matrix: scenario files must reference external topology file, never inline full adjacency. Validate: reject scenario TOML with inline nodes arrays > 1000 entries.

13.7 Performance Concerns

  • BTreeMap prefix lookup is O(log n) vs HashMap O(1); for 700 000-prefix full table, BTree L3-cache thrashing dominates. Profile: use perf stat for cache-miss ratio; switch inner loop to sorted Vec + binary-search for read-heavy Loc-RIB.
  • Serde TOML deserialization of large fault timelines (> 10 000 entries) allocates many small Strings; pre-allocate with with_capacity based on line count estimate.
  • SmallVec<[BgpRoute; 4]> spills to heap when a neighbor carries > 4 prefixes in Adj-RIB-Out; tune inline size to p95 neighbor prefix count from CAIDA analysis.
  • Topology sort step (ASN-order adjacency) is O(E log E); accept cost at load time, not per-event.

13.8 Edge Cases

  • Scenario with zero announcements: topology loads, quiescence reached immediately; all CatchmentEquals(_, None) pass.
  • Fault scheduled before announcement: FaultTarget not yet active; must not panic; log warning; fault is a no-op.
  • recover_at <= at: invalid; reject at parse time with RecoveryBeforeFailure error.
  • ASN in assert not present in topology: AssertionError with message "ASN not in graph", not a panic.
  • topology_path pointing to a nonexistent file: ScenarioRunner::run returns Err(ScenarioError::TopologyNotFound).
  • Circular fault (LinkDown then LinkUp then LinkDown at same timestamp): seq-ordered dispatch handles correctly; test with explicit fixture.

14.6 Pitfalls

  • Path inflation division by zero: BFS on disconnected AS pair returns no path; optimal_len = 0; guard with if optimal == 0 { f64::INFINITY } and document as unreachable-AS inflation.

  • Soak RSS growth from leaked BgpRoute in Adj-RIB-In: withdrawal removes Loc-RIB entry but not all Adj-RIB-In entries for failed peer; routes accumulate. Fix: on LinkDown(a,b), remove all (b, *) entries from a's adj_rib_in.

14.7 Performance Concerns

  • Path inflation BFS over 50 000-AS graph: O(V + E) per AS = O(V²) total naively. Batch with multi-source BFS from all PoP origins simultaneously; compute shortest distance to any PoP for every AS in one pass.

Memory Scaling

  • Per-AS state: AsNode base ≈ 1 KB; RIB scales with degree × prefixes.
  • Internet-realistic: average degree ≈ 5–10; average prefixes ≤ 5 for simulation (not full DFZ table).
  • Full DFZ (900 000 prefixes) explicitly out of scope; Phase 13 targets single-prefix anycast + selected prefixes.
  • Arc<BgpRoute> sharing: routes in Adj-RIB-Out to multiple neighbors share the same allocation; saves O(degree) copies per AS.

EventQueue Scaling

  • BinaryHeap with N events: O(log N) per push/pop.
  • At 10 000 AS, 5 prefixes, degree 8: peak queue depth ≈ 400 000 events; heap operations remain fast.
  • Batch scheduling: instead of one event per neighbor per prefix change, batch into a single BatchPropagate event per AS tick; reduces queue depth by O(degree × prefixes).

Convergence Scaling and Path Hunting

  • Worst-case path hunting: O(|AS|²) UPDATE events for a single prefix change in a fully-connected graph.
  • Gao-Rexford acyclic policy: eliminates path hunting; convergence is O(|AS| × diameter) events.
  • Policy disputes (Griffin-Shepherd-Wilfong gadgets) cause infinite oscillation; detected by event count threshold.
  • Convergence event count threshold: configurable; default 10 × |AS|²; exceeded → oscillation=true in ConvergenceReport.

Horizontal Scaling

  • Simulator is single-threaded by design (P1: deterministic total event order).
  • Parallelism applies at scenario level only: run N independent scenarios concurrently via rayon::par_iter over scenario list.
  • Per-scenario state is fully isolated (no shared mutable state between scenarios); embarrassingly parallel.
  • Scale-out: orchestration layer distributes scenario batches across machines; each node runs acast-cli independently; results aggregated externally.
  • No inter-scenario coordination overhead.

Sharding and Partitioning

  • Not applicable within a single simulation run: BGP propagation requires global AS graph visibility.
  • Hierarchical approximation (future scope): partition AS graph into tiers; run intra-tier convergence first, then inter-tier. Not faithful to BGP semantics; explicitly out of scope for Phase 13.

Vertical Scaling

  • Simulation is memory-bound at large AS counts; more RAM directly extends scale ceiling.
  • CPU utilization is bursty (propagation phases) with idle periods (quiescence detection).
  • Larger CPU caches reduce RIB lookup latency for high-degree ASes.
  • NUMA awareness: not required at Phase 13 scale; revisit if single-run scale exceeds 50 000 AS.

Storage Scaling

  • .etrace files: one JSON-Lines record per event; at 1 M events ≈ 80–120 MB uncompressed; apply zstd compression (ratio ≈ 10:1).
  • Catchment snapshots: O(|AS|) records; at 50 000 AS ≈ 2 MB per snapshot as JSON.
  • Scenario files: O(1) relative to topology size; topology stored as CAIDA reference + diff.

Mental Models & First Principles

Expert intuitions that predict behavior before you run any code. Each model names the §/phase where this blueprint applies it.

MM1 — Best-path is a distributed sort, not a consensus protocol. Every AS independently ranks its candidate routes using the same deterministic comparator (compare_routes). Catchment emerges from 75 000 independent elections, each pure functions of local state. Corollary: you cannot "fix" a catchment by adjusting one AS's behavior — you must change the routes that reach that AS. Applied in §6 P4, Phase 7. Bug class without it: operators attempt centralized catchment management, which doesn't exist.

MM2 — VirtualClock is the only causal clock; wall time is irrelevant. An event at (t=100, seq=5) happens-before (t=100, seq=6) regardless of wall-clock order. Reproducibility follows from this: identical inputs → identical (time, seq) assignments → identical dispatch order. Applied in §6 P1, §7 I1, Phase 1. Bug class: injecting any wall-clock read into dispatch breaks I10 (replay diverges).

MM3 — Valley-free is an economic constraint, not a topological one. A route from a peer is suppressed toward another peer not because of a graph cycle, but because of a business rule (free transit). The same topology with different relationships produces different catchment. Applied in §6 P3, §7 I4, Phase 6. Bug class: conflating relationship direction with physical path direction causes silent valley-free violations with wrong catchment.

MM4 — The three-tier RIB is a pipeline, not a cache. Adj-RIB-In → (import policy + best-path) → Loc-RIB → (export policy) → Adj-RIB-Out. Each stage transforms routes with no bypass. Loc-RIB is not a copy of Adj-RIB-In — it is the policy-filtered winner. Applied in §8.3 (Domain Model), §11.4 (Core Schema), Phase 3–5. Bug class: skipping the pipeline (reading Adj-RIB-In as if it were Loc-RIB) produces wrong catchment silently.

MM5 — Withdrawal cascade is depth-first, not breadth-first. When a link fails, each affected AS removes its Adj-RIB-In entries and re-runs best-path; if Loc-RIB changes, it emits WithdrawMsg to downstream ASes who repeat the process. The cascade fans out along the topology DAG. Applied in §7 I7, Phase 10. Bug class: breadth-first withdrawal misses routes that pass through intermediate ASes not directly adjacent to the failure.

MM6 — Oscillation is a policy-graph property, not a transient. Griffin-Shepherd-Wilfong proved that certain 3-AS policy configurations have no stable path — no amount of waiting will resolve them. The oscillation detector (I8) detects these and halts; it is not a timeout. Applied in §7 I8, Phase 9, §2.2 (Why Build This). Bug class: treating oscillation as a convergence timeout rather than a policy-dispute diagnosis leads to operators increasing max_events instead of fixing the policy.

MM7 — Traffic engineering knobs shift traffic entry points, not traffic volume. AS-path prepend makes a PoP look farther away (step 2 in the tie-break ladder). MED signals preferred entry among routes from the same neighbor AS. Neither changes physical traffic volume — only which PoP attracts which client AS's best-path. Applied in §6 P3, Phase 12, §2.3 (Why Build This). Bug class: operators expect prepend to reduce total load rather than redistribute catchment; they prepend indefinitely without achieving balance.

MM8 — Determinism requires structural elimination of nondeterminism, not seeding. The simulator achieves I10 by design: no HashMap iteration in dispatch-critical paths (use BTreeMap or sorted Vec), no wall-clock in engine, no OS randomness. A PRNG seed is irrelevant because no PRNG is used. Applied in §7 I10, Phase 1/13, ADR-24. Bug class: assuming a fixed PRNG seed makes non-determinism "reproducible" — actually the non-determinism is from HashMap ordering, unaffected by any seed.

Back-of-Envelope Capacity Model

All numbers derived step-by-step from §4 System Constraints. Formula shown for each.

Number 1 — RIB memory per AS (Adj-RIB-In). From §4: BgpRoute ≤ 128 bytes; avg degree = 10 neighbors; single anycast prefix. Adj-RIB-In per AS = neighbors × routes_per_neighbor × BgpRoute_size = 10 × 1 × 128 B = 1.28 KB/AS.

Number 2 — Total Adj-RIB-In memory (75 000 AS). 75 000 AS × 1.28 KB = 96 MB. Leaves ample headroom in 8 GB budget.

Number 3 — Loc-RIB memory (75 000 AS, 1 prefix). 75 000 AS × 1 route × 128 B = 9.6 MB. Negligible.

Number 4 — EventQueue peak depth (announcement phase). From §4: announcements fan out along all links; avg degree = 10; diameter ≈ 5 hops. Peak events ≈ 75 000 AS × 10 neighbors × 1 prefix = 750 000 events. At 64 B/SimEvent: 750 000 × 64 B = 48 MB.

Number 5 — Convergence event count (Gao-Rexford, no dispute). From P13 paper (Griffin 1999) + §4: convergence = O(|AS| × diameter) = 75 000 × 5 = 375 000 events under Gao-Rexford. At M1 (2M events/s): 375 000 / 2 000 000 = 0.19 s. Consistent with §4 (≤5 min for internet-scale is conservative).

Number 6 — Convergence event count (path hunting worst case). From §4 (System Constraints), corroborated by Scalability Analysis: worst case = O(|AS|²) = 75 000² = 5.6 × 10⁹ events. At 2M events/s: 5.6 × 10⁹ / 2 × 10⁶ = 2 800 s ≈ 47 min. Max-events budget set at 10 × |AS|² = 56 billion — unreachable in practice; Gao-Rexford eliminates path hunting.

Number 7 — Trace file size (1M events). From §4: ≤ 64 bytes/event log entry. 1 × 10⁶ × 64 B = 64 MB uncompressed. With zstd (10:1 ratio): 6.4 MB per run.

Number 8 — Fault cascade width (Tier-1 NodeDown, degree 5 000). NodeDown triggers 5 000 LinkDowns × 1 route each = 5 000 RecvWithdraw events immediately. Each cascades O(diameter) = 5 hops: 5 000 × 5 = 25 000 additional events. Total fault cascade: ~30 000 events. At M12 target (< 10 s): needs 30 000 / 10 = 3 000 events/s dispatch — trivially met by M1 (2M events/s).

Number 9 — Dijkstra runtime (50 000 AS, 10 PoPs). Dijkstra complexity: O((V + E) log V). With V=50 000, E=200 000 (avg degree 4 for CAIDA), log V=16.6. Per PoP: (50 000 + 200 000) × 16.6 ≈ 4.15 × 10⁶ ops. For 10 PoPs: 4.15 × 10⁷ ops. At 10⁹ ops/s: 41 ms. Consistent with M11 target (≤ 5 s — very conservative).

Number 10 — AS-path interning savings. Average AS-path length = 3.5 hops (CAIDA empirical). Without interning: 75 000 AS × 128 B route + 3.5 × 4 B path = 75 000 × 142 B = 10.6 MB. With Arc interning of common short paths: ~40% reduction = 6.4 MB. Marginal for a single prefix; significant for multi-prefix scenarios.

Number 11 — File descriptor budget. From §4: ≤ 10 FDs per run. Actual usage: 1 (scenario TOML) + 1 (CAIDA topology) + 1 (catchment JSON out) + 1 (convergence report JSON) + 1 (trace NDJSON) = 5 FDs. Comfortable margin.

Number 12 — Scenario startup time (1 000 AS). Topology load (1 000 lines): 1 000 / (10 × 10⁶ lines/s) = 0.1 ms. Event scheduling (announcements, 1 prefix): ~1 000 events × 500 ns = 0.5 ms. Total: < 1 ms. Conservative M4 target (≤ 100 ms) has 100× headroom — deliberate for worst-case DSL parse.

Alternative Architectures (Roads Not Taken)

Alt-1 — Parallel Event Dispatch with Actor-per-AS

Show the original text diagram
[EventQueue (global)] --dispatch--> [Actor(AS_1)] [Actor(AS_2)] ... [Actor(AS_N)]
   Each actor holds its own Rib; message-passing for UpdateMsg/WithdrawMsg
   Result aggregator collects Catchment from all actors at quiescence

Regime where it wins: simulation of tens of thousands of ASes with multiple prefixes where per-event wall-clock time matters (interactive TE exploration). The actor model enables real parallelism across cores.

Real system embodying it: GoBGP uses goroutines per BGP session for concurrent session management.

Why rejected: actor concurrency destroys I1 (VirtualClock monotonicity) — two actors can schedule events at the same virtual time but in non-deterministic order, breaking I10 (replay identity). Fixing this requires a global synchronization barrier at every virtual-time tick, eliminating most parallelism benefit. ADR-06 explicitly locks this out.

Alt-2 — Shared-Memory RIB with Epoch-Based Reads

Show the original text diagram
GlobalRib: Arc<RwLock<HashMap<(Asn,Prefix), BgpRoute>>>
   Writer: BGP speaker per AS acquires write lock, updates Loc-RIB
   Reader: Catchment derivation reads snapshot at epoch boundary
   Epoch barrier: all writers drain before epoch transitions

Regime where it wins: read-heavy workloads — many concurrent analytical queries over the same RIB state after a single scenario run (e.g., what-if analysis across 1000 PoP configurations).

Real system: Maglev uses a shared consistent hash table with epoch-based updates for flow routing.

Why rejected: write-lock contention from per-AS RIB updates during convergence serializes all AS dispatch, eliminating parallelism. The simulator's bottleneck is write throughput during propagation, not read throughput. Plus it breaks determinism (lock acquisition order is non-deterministic under thread scheduling). The single-threaded model achieves higher per-event throughput than any lock-contended parallel model for this workload.

Alt-3 — Pure Functional Simulation (Persistent Data Structures)

State(t) = pure function of State(t-1) + Events(t)
   Rib = persistent HashMap (HAMT); each RIB update returns new Rib
   EventQueue = persistent heap; each dispatch returns new (Queue, State)
   No mutation; easy snapshot/replay; referentially transparent

Regime where it wins: formal verification contexts where you need to prove simulator correctness properties about all possible execution paths, or incremental re-computation (only re-simulate ASes affected by a policy change).

Real system: academic BGP analyzers written in Haskell/OCaml use persistent data structures for exhaustive policy verification.

Why rejected: persistent HAMTs have 3–5× memory overhead vs mutable HashMaps and 2–3× allocation overhead per update. At 75 000 ASes × millions of events, this pushes memory above the 8 GB §4 ceiling and reduces event throughput below M1 targets. The determinism guarantee of the functional model is achieved by other means (ADR-24, ADR-06) without the performance cost.

Alt-4 — BGP Table-Dump Replay (MRT-based)

Show the original text diagram
MRT stream (RFC 6396) from RouteViews/RIPE RIS
  --> Offline parser --> BGP route events
  --> acast-sim EventQueue (real timestamps as virtual time)
  --> Catchment derivation at each time slice

Regime where it wins: validation of the simulator against real Internet routing data — replay actual BGP table dumps and compare derived catchment against measured anycast probing results. Also useful for root-cause analysis of real anycast incidents (replay the BGP events around an outage).

Real system: CAIDA BGPStream provides this capability for offline BGP analysis; tools like bgpscanner replay MRT dumps.

Why rejected: MRT timestamps are real-time (seconds resolution) and event arrival is non-deterministic (reordered by BGP convergence). Mapping real timestamps to a deterministic virtual clock requires assumptions about event ordering that violate I1. The simulator is designed to be a ground-truth engine, not a validator against live data — that is a composition use case (run simulator + compare against live data), not a replacement for the deterministic model. Deferred to future integration phase.
