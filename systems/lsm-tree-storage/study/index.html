32. Mental Models & First Principles

  • MM1 — "An SSTable is a frozen fact, not a file." Insight: once installed, treat it as immutable evidence, never mutable storage. Predicts: any code path re-opening an SSTable for writing after finalise() is a bug. Bug class without it: silent corruption from an in-place patch. Applies in §7 I2, §15.2.
  • MM2 — "The manifest is the database; data files are its cache." Insight: file existence is irrelevant without a manifest reference. Predicts: recovery must always start from the manifest, never a directory listing. Bug class without it: phantom-file bugs trusting a directory scan over the VersionSet. Applies in §7 I7, §18.5.
  • MM3 — "A sequence number is a clock, not an identifier." Insight: its only job is total ordering for visibility, not identity. Predicts: reusing or de-monotonizing a seq breaks every snapshot. Bug class without it: stale-read bugs. Applies in §7 I4, §17.2.
  • MM4 — "Compaction is entropy reduction, not cleanup." Insight: it exists to keep the level-size invariant (I3) true; tombstone deletion is a side effect, not the goal. Predicts: a picker tuned purely to "reclaim space" mis-prioritizes and starves read-amp control. Bug class without it: read-amp regressions from a size-only picker. Applies in §19.2, §19.9.
  • MM5 — "A Bloom filter is a probabilistic firewall, not a cache." Insight: it only ever says "definitely not" or "maybe" — never trust "maybe" as "yes." Predicts: code returning a value on filter-hit without checking the data block is wrong. Bug class without it: phantom-read bugs. Applies in §16.2, §34 #3.
  • MM6 — "fsync is a promise about your disk, not the platter." Insight: durability terminates at the device's cache-flush honesty. Predicts: any "fsync = physically durable" claim without qualifying the device over-promises. Bug class without it: false-durability incidents (industry-documented). Applies in §6 P8, §24 T6.
  • MM7 — "A snapshot is a debt against future compaction." Insight: every open snapshot pins bytes that would otherwise be reclaimed. Predicts: long-lived snapshots correlate with rising space-amp. Bug class without it: unbounded disk growth misattributed to "a compaction bug." Applies in §17.5, §25 FM8.
  • MM8 — "The write path and read path are different concurrency universes." Insight: one mutex serializes writes; the read path is designed to need none. Predicts: adding a lock to "fix" a read race is almost always the wrong fix. Bug class without it: read-path latency regressions from over-locking. Applies in §6 P5, §20.2.

5. Required Reading

Books

  • Kleppmann, M., 2017. Designing Data-Intensive Applications, O'Reilly, ISBN 978-1449373320, Ch. 3 (Storage and Retrieval). Best survey-level LSM-vs-B+tree treatment in print. Applied in §3, §8.
  • Petrov, A., 2019. Database Internals, O'Reilly, ISBN 978-1492040347, Ch. 7 (Log-Structured Storage). The single best book-length LSM reference. Applied in §8, §19.
  • Ramakrishnan, R. and Gehrke, J., 2003. Database Management Systems, 3rd ed., McGraw-Hill, ISBN 978-0072465631, Ch. 9 (Storage and Indexing). Buffer-management counterpoint used when designing the block cache. Applied in §20.
  • Silberschatz, A., Korth, H., and Sudarshan, S., 2019. Database System Concepts, 7th ed., McGraw-Hill, ISBN 978-0078022159, Ch. 10 (Storage and File Structure). Record layout background. Applied in §11.
  • Tanenbaum, A. and Bos, H., 2014. Modern Operating Systems, 4th ed., Pearson, ISBN 978-0133591620, Ch. 4 (File Systems). fsync/fdatasync/page-cache semantics. Applied in §13.
  • Hennessy, J. and Patterson, D., 2017. Computer Architecture: A Quantitative Approach, 6th ed., Morgan Kaufmann, ISBN 978-0128119051, Ch. 2 (Memory Hierarchy). Cache-line reasoning behind cache sharding and Bloom-probe cost. Applied in §16, §20.

Papers

  • O'Neil, P., Cheng, E., Gawlick, D., and O'Neil, E., 1996. "The Log-Structured Merge-Tree (LSM-Tree)." Acta Informatica 33(4). Names the data structure; the rolling merge algebra. Applied in §3, §19 (compaction).
  • Dayan, N., Athanassoulis, M., and Idreos, S., 2017. "Monkey: Optimal Navigable Key-Value Store." SIGMOD. Per-level Bloom-filter sizing as a function of per-level read frequency. Applied in §16, §34 #3.
  • Dayan, N. and Idreos, S., 2018. "Dostoevsky: Better Space-Time Trade-Offs for LSM-Tree Based Key-Value Stores via Adaptive Removal of Superfluous Merging." SIGMOD. Names "lazy leveling." Applied in §36, §37 row 5.
  • Sears, R. and Ramakrishnan, R., 2012. "bLSM: A General Purpose Log Structured Merge Tree." SIGMOD. Spring-and-gear merge scheduling to bound write stalls. Applied in §19.
  • Bloom, B., 1970. "Space/Time Trade-offs in Hash Coding with Allowable Errors." Communications of the ACM 13(7). The filter's probability math. Applied in §16, §34 #3, #4.
  • Mohan, C., Haderle, D., Lindsay, B., Pirahesh, H., and Schwarz, P., 1992. "ARIES: A Transaction Recovery Method Supporting Fine-Granularity Locking and Partial Rollbacks Using Write-Ahead Logging." ACM TODS 17(1). Redo-only-vs-redo/undo contrast. Applied in §13, §9 ADR-05.
  • Rosenblum, M. and Ousterhout, J., 1991. "The Design and Implementation of a Log-Structured File System." SOSP / ACM TOCS 10(1). Append-only write path and segment-cleaning lineage. Applied in §3, §31.
  • Pugh, W., 1990. "Skip Lists: A Probabilistic Alternative to Balanced Trees." Communications of the ACM 33(6). The memtable's core data structure. Applied in §14.
  • Lu, L., Pillai, T., Gopalakrishnan, H., Arpaci-Dusseau, A., and Arpaci-Dusseau, R., 2016. "WiscKey: Separating Keys from Values in SSD-Conscious Storage." FAST. Key-value separation trade-off. Applied in §36, §37 row 8.

Reference Implementations

  • LevelDB. db/version_set.cc, db/db_impl.cc, table/block.cc, table/filter_block.cc, table/format.cc. https://github.com/google/leveldb. Lesson: smallest readable production LSM. Pitfall: single global mutex around Version bounds read parallelism at scale — this blueprint uses Arc<Version> swap instead (§18.3). Applied in §15, §16, §18.
  • RocksDB. db/version_set.cc, db/compaction/, table/block_based/, db/memtable.cc, db/db_impl/db_impl_write.cc, util/rate_limiter.cc. https://github.com/facebook/rocksdb. Lesson: column families, pluggable compaction, production rate limiter. Pitfall: 300+ tunables create an operator footgun space — this blueprint keeps DbOptions deliberately smaller (§11). Applied in §19, §20, §23.
  • Apache Cassandra. src/java/org/apache/cassandra/db/compaction/ (SizeTieredCompactionStrategy, LeveledCompactionStrategy). https://github.com/apache/cassandra. Lesson: pluggable per-table compaction strategy. Pitfall: historically, JVM GC pauses under compaction pressure caused read-latency cliffs — motivates ADR-01's rejection of a GC'd runtime. Applied in §9 ADR-03, §33, §36.
  • ScyllaDB. C++/Seastar shard-per-core rewrite of Cassandra's storage engine. https://github.com/scylladb/scylladb. Lesson: shared-nothing per-core sharding eliminates cross-core cache-coherency traffic. Pitfall: requires a shard-aware client or a routing hop. Applied in §31, §33.
  • WiredTiger (MongoDB). https://github.com/wiredtiger/wiredtiger. Lesson: one storage engine exposing both B-tree and LSM configurations behind one API — proof the two are interface-compatible. Pitfall: its LSM mode merges more eagerly than RocksDB, trading write-amp for simpler merge code. Applied in §33, §36.
  • Pebble (CockroachDB). internal/manifest/, sstable/, compact.go. https://github.com/cockroachdb/pebble. Lesson: modern Go re-implementation with an explicit Architecture doc naming every RocksDB divergence. Pitfall: relies on Go GC pressure signals for cache eviction tuning — a different tuning story than this blueprint's manual capacity_bytes. Applied in §18, §20, §33.

RFCs / Specifications

  • Apache HBase HFile v3 Specification, Apache HBase Reference Guide. Pioneered inline Bloom filters and variable-length key encoding this blueprint re-implements. Applied in §8, §15.
  • IEEE Std 1003.1 (POSIX), fsync/fdatasync/open(O_DIRECT) semantics. The durability contract the engine depends on and cannot verify past. Applied in §13, §22.
  • RFC 8878 — Zstandard Compression Format. Applied in §15 (ADR-16 compression choice).
  • LZ4 Frame Format Specification, lz4.org. Applied in §15 (ADR-16 alternative codec).

Glossary (§38) · 59 terms · site-wide glossary

LSM-tree
log-structured merge tree; write-optimized structure absorbing writes in memory, flushing sorted runs, merging via background compaction (§3).
Memtable
in-memory, mutable, single-writer write absorber keyed by InternalKey (§14).
Immutable memtable
a frozen memtable awaiting flush to an SSTable (§14.2).
WAL
write-ahead log; the data-side durability boundary (§13).
SSTable
Sorted String Table; immutable, sorted, on-disk file (§8.1, §15).
Manifest
append-only log of VersionEdits; the metadata-side durability primitive (§18).
VersionSet
in-memory structure tracking the current Version + snapshot table (§18.2).
VersionEdit
one atomic change to the file set (flush or compaction result) (§8.3, §11.5).
Compaction
background merge of SSTables to bound amplification and reclaim space (§19).
Leveled compaction
non-overlapping per-level files, bounded read/space-amp (§9 ADR-03).
Size-tiered compaction
merge N similarly-sized runs; lower write-amp, higher space-amp (§36).
Universal compaction
RocksDB's tiered-at-top, leveled-at-bottom strategy (§37).
Lazy leveling
Dostoevsky's size-tiered-non-bottom, leveled-bottom hybrid (§37).
Write amplification
bytes written to disk per byte of logical write (§34 #1).
Read amplification
block reads per logical read (§34 #3).
Space amplification
on-disk bytes per logical byte stored (§34 #2).
Bloom filter
probabilistic membership structure; false positives allowed, false negatives never (§16, Bloom 1970).
False-positive rate (FPR)
probability a Bloom filter says "maybe" for an absent key (§34 #3).
Block cache
sharded LRU cache of decompressed blocks (§20).
Table cache
cache of open SstReader file handles (§20.2).
LRU
least-recently-used eviction policy (§20.3).
Restart point
a data-block entry storing a full key, anchoring delta-encoded entries after it (§8.1).
Shared-prefix encoding
delta-encoding a key against the prior key via a shared byte count (§9 ADR-18).
Tombstone
a Deletion-kind record marking a key logically deleted (§11.1).
Range tombstone
a RangeDeletion record covering [start,end) (§8.4, §17).
Sequence number
monotonic write-order clock; the sole MVCC mechanism (§11.1, P11).
Snapshot
a pinned SequenceNumber; the read-isolation unit (§17.1).
MVCC
multi-version concurrency control; here, snapshot-based via sequence numbers only (§17).
Checkpoint
a consistent, point-in-time export of the database (§22).
Group commit
batching concurrent writers' fsyncs into one (§13.2).
fsync / fdatasync
POSIX calls flushing data (and, for fsync, metadata) to the storage device (§13.2, §5 RFC/spec).
O_DIRECT
bypasses the OS page cache for predictable I/O latency (§9 ADR-15).
CRC32C
the Castagnoli CRC32 variant; hardware-accelerated checksum (§9 ADR-06).
Footer
the fixed 48-byte trailer of every SSTable naming its index/metaindex handles (§8.1).
Index block
per-SSTable block mapping separator keys to data-block handles (§8.1).
Filter block
per-SSTable Bloom filter bytes (§8.1).
Metaindex block
names auxiliary blocks (filter, range-del) by string key (§8.1).
Data block
the unit of compressed, checksummed key-value storage (§8.1).
Block trailer
5-byte compression-type + CRC32C suffix on every block (§8.1).
InternalKey
user_key || (seq<<8|kind) encoding used everywhere internally (§8.4, §11.2).
UserKey
the caller-supplied key bytes, without seq/kind trailer (§11.2).
FileId
stable identifier for an SSTable file (§11.1).
Level
a tier in the LSM hierarchy; L0 overlapping, L1+ non-overlapping (§11.1, I3).
Level multiplier / fanout
the per-level size ratio T driving amplification (§34 #1).
Write stall
foreground backpressure when L0/immutable-queue limits are exceeded (§19.10).
Vacuum
the process unlinking orphan files not referenced by the current Version (§18.2).
Orphan file
an on-disk file absent from the current Version (§7 I7).
Bulk-ingest
the ingest_external_sst fast path bypassing memtable/WAL (§21.2).
Rate limiter
token-bucket throttle on compaction I/O (§9 ADR-26).
Telemetry
the trait Telemetry metrics/tracing hook surface (§11.10).
Conformance fixture
a named input+expected-output pair gating a phase's N.5 (§28).
Fuzz target
an entry point exercised by cargo-fuzz against arbitrary bytes (§10, §23.2).
Torn write
a write interrupted mid-flight by a crash, leaving a partial record (§8.8).
RecoveryPolicy
StrictRedo vs BestEffort WAL-recovery strictness (§13.2).
CURRENT file
the 1-line file naming the active manifest (§18.2, I11).
Column family
a deferred multi-keyspace-per-engine primitive (§37).
Key-value separation
storing large values in a separate value log (WiscKey, §36).
ARIES
the redo/undo WAL recovery protocol this engine's redo-only design contrasts with (§5, §9 ADR-05).
Page cache
the OS's buffer cache, bypassed by O_DIRECT when enabled (§9 ADR-15).
