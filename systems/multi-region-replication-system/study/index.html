33. Hard Questions (Self-Examination)

  • Q1. If the WAL fsync policy (§13.2) is BatchWindow rather than PerWrite, does the WAL-Before-Visibility principle (§6 P9) still hold, and what does §7 I1's enforcement point have to guarantee for the answer to be yes?
  • Q2. Why does the scheduler's credit-based backpressure (§15.2, §7 I10) need to exist as a separate mechanism from the transport's own QUIC-level flow control (§14.2) instead of relying on QUIC alone?
  • Q3. Under what combination of §16's epoch-fencing design and §18's idempotency window could a fenced-out former leader's in-flight append still reach the WAL, and why does §7 I8 close that gap?
  • Q4. Why is the metadata Raft group (§16.2, ADR-19) kept small and independent of the 32-region data-plane fanout (§4), rather than scaling the same Raft group to cover all regions?
  • Q5. If a snapshot's wal_sequence_at_snapshot (§11) and the local replay cursor (§13.10) drift by exactly one segment, does §7 I9 trigger, and what would segment sizing (§4) have to look like for that boundary to be reachable?
  • Q6. Why does conflict resolution (§20) require a total-order tiebreak on (vector_clock_hash, ReplicaId) rather than wall-clock timestamp, given that §4 already assumes NTP-synced clocks?
  • Q7. What is the actual failure mode if the observability exporter (§19) buffers span data under backpressure and the buffer grows past available memory — does §6 P12's isolation principle prevent this, or only delay it?
  • Q8. Why does §21's chaos suite hook fault injection directly into the transport and WAL layers (§14, §13) instead of tc netem, and what property of §7's invariants would a tc netem-only approach fail to test deterministically?
  • Q9. If two regions simultaneously propose an epoch bump during a partition (§16.4's split-brain fixture), what in the Raft group's commit protocol (§16.2, §5) guarantees exactly one wins, and what breaks if the Raft group itself partitions like the data-plane regions?
  • Q10. Why is the idempotency window (§11 ReplaySession, §7 I11) bounded rather than unbounded, given that an unbounded window would trivially guarantee no duplicate ever re-applies, per §18's tradeoff?
  • Q11. Given the write-amplification derivation in §32 C5, what design change in §17's snapshot-delta strategy would bring the ceiling below 3.5x without violating §7 I5?
  • Q12. Why does §20's deterministic resolver framework explicitly defer a programmable conflict-resolution VM (§35) rather than shipping it in Phase 8, given §1 lists programmable resolvers as a later-phase unlock?
  • Q13. If the scheduler's per-region fairness (§15.2) and the membership layer's per-region quorum weighting (§16.2) both make region-scoped decisions independently, what prevents an inconsistent view of "which region is degraded" during a partial outage (§8.5)?
  • Q14. Why does §28's tail-latency analysis correlate retransmit spikes with p99 apply latency rather than treating them as independent metrics, given §4's separate p95/p99 budgets?
  • Q15. What would have to be true of §11's TransportFrame version field and §25's compatibility matrix for a MINOR release to safely add a new required field, and why does §25 forbid exactly that?
  • Q16. Why does §32 C4's FD-budget derivation assume 6 FDs per stream rather than 1, and what does that reveal about how §14's connection multiplexing actually works?

30. Mental Models & First Principles

  • MM1 — Durability is a return value, not a promise. Compressed insight: an ack is only true once the fsync syscall has returned, never before · predicts: any "optimistic ack" shortcut will eventually lose an acknowledged write · bug class without it: acknowledged-but-lost writes on crash · applies in §13.
  • MM2 — Determinism is a property of the whole pipeline, not one function. Compressed insight: one hidden HashMap iteration or wall-clock read anywhere in the replay path breaks replay for the entire system · predicts: replay bugs cluster around collections and time reads · bug class without it: replay-hash mismatches with no obvious single cause · applies in §18.
  • MM3 — Backpressure must be structural, not advisory. Compressed insight: a queue that can grow unboundedly will, under exactly the WAN-stall condition this system exists to survive · predicts: any unbounded buffer becomes the first OOM under load · bug class without it: memory exhaustion during precisely the incident you were trying to ride out · applies in §15.
  • MM4 — An epoch is a fence, not a timestamp. Compressed insight: epochs order topology changes causally, they do not measure wall-clock time · predicts: comparing epochs across regions with clock skew is always safe, comparing timestamps is not · bug class without it: split-brain from timestamp-based leader-election logic · applies in §16.
  • MM5 — A snapshot is atomic or it does not exist. Compressed insight: there is no valid intermediate state between "no snapshot" and "complete, checksum-verified snapshot" · predicts: any partially-visible snapshot state is a bug, never an acceptable transient · bug class without it: restores from a half-written manifest · applies in §17.
  • MM6 — Observability that can block the system it observes is a liability, not a feature. Compressed insight: telemetry must degrade to sampling/dropping under its own backend's failure · predicts: an unbounded trace-export queue becomes a second incident during the first one · bug class without it: an exporter outage cascading into a replication outage · applies in §19.
  • MM7 — Conflict resolution is a data-visible decision, so it must be reproducible, not clever. Compressed insight: a resolver's cleverness is worthless if two replicas can compute different answers for the same input · predicts: any resolver using a non-total-order tiebreak will eventually diverge · bug class without it: silent, undetected replica divergence · applies in §20.
  • MM8 — Chaos testing must be as deterministic as the system it tests. Compressed insight: a chaos run that cannot be replayed from a seed is not a test, it is an anecdote · predicts: "flaky" chaos failures are almost always a hidden real-time dependency in the injector itself · bug class without it: unreproducible incident reports · applies in §21.

5. Required Reading

Books

  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 5–9: replication topologies, partitioning, consistency tradeoffs, distributed failure models; applied in §3 and §16.
  • Database Internals, Vol. 1–2 — Alex Petrov (2019), ch. 3–4, 7: durability semantics, checkpointing, recovery mechanics; applied in §13 and §17.
  • Systems Performance, 2nd Ed. — Brendan Gregg (2020), ch. 6, 10: flamegraph methodology, latency diagnostics, syscall-level profiling; applied in §28.
  • TCP/IP Illustrated, Vol. 1 — W. Richard Stevens (1994), ch. 20–21: congestion behavior, retransmission timers, connection lifecycle; applied in §14.
  • Distributed Systems, 4th Ed. — Maarten van Steen and Andrew Tanenbaum (2023), ch. 6, 8: consistency models, logical clocks, fault models; applied in §16 and §20.
  • Site Reliability Engineering — Betsy Beyer, Chris Jones, Jennifer Petoff, Niall Murphy, eds. (2016), ch. 6, 15: alerting philosophy, blameless forensics; applied in §24 and §23.

Papers

  • "Spanner: Google's Globally Distributed Database" — Corbett et al., 2012, OSDI: TrueTime-backed external consistency → region-aware ordering without a global lock; applied in §16.
  • "Dynamo: Amazon's Highly Available Key-value Store" — DeCandia et al., 2007, SOSP: quorum reads/writes with vector-clock conflict detection → conflict-resolution version metadata; applied in §20.
  • "In Search of an Understandable Consensus Algorithm" — Ongaro and Ousterhout, 2014, USENIX ATC: leader election and log matching → the metadata-plane epoch manager; applied in §16.
  • "Chain Replication for Supporting High Throughput and Availability" — van Renesse and Schneider, 2004, OSDI: strictly-ordered replication topology → WAL ordering and ack-watermark invariants; applied in §7.
  • "Kafka: a Distributed Messaging System for Log Processing" — Kreps, Narkhede, and Rao, 2011, NetDB: ISR sets and log-segment layout → replication lag handling and segment rotation; applied in §13.
  • "Paxos Made Simple" — Lamport, 2001, ACM SIGACT News: majority-quorum agreement without a distinguished proposer → ack-aggregation quorum semantics; applied in §7.
  • "Viewstamped Replication Revisited" — Liskov and Cowling, 2012, MIT-CSAIL-TR-2012-021: view-change protocol separate from replication protocol → failover FSM's epoch-versus-stream separation; applied in §16.
  • "Conflict-free Replicated Data Types" — Shapiro, Preguiça, Baquero, and Zawirski, 2011, SSS: commutative merge without coordination → deterministic conflict resolver design; applied in §20.
  • "Virtual Time and Global States of Distributed Systems" — Mattern, 1989, Workshop on Parallel and Distributed Algorithms: vector-clock causal ordering → conflict detection's causality check; applied in §20.

Reference Implementations

  • etcd/etcd — study server/storage/wal: segment rotation and CRC-checked WAL entries; pitfall: do not copy its single-writer assumption into a multi-stream scheduler; applied in §13.
  • tikv/tikv — study components/raftstore: region-scoped state machines and snapshot scheduling; pitfall: do not adopt per-region Raft groups wholesale, this system uses one metadata-plane group; applied in §16.
  • apache/kafka — study core/src/main/scala/kafka/server/ReplicaFetcherThread.scala: replica fetcher and ISR shrink/expand logic; pitfall: do not copy Kafka's broker-owned leadership model onto region-scoped streams; applied in §14.
  • apple/foundationdb — study fdbserver/storageserver.actor.cpp: recovery sequencing and storage-server versioned reads; pitfall: do not copy its single global recovery epoch into a per-region topology; applied in §16.
  • cockroachdb/cockroach — study pkg/kv/kvserver/allocator: replication-queue rebalancing and lease-preference scoring; pitfall: do not copy lease-transfer heuristics without the surrounding Raft group they assume; applied in §15.

RFCs / Specifications

  • RFC 9000 — QUIC transport protocol: connection migration, stream multiplexing, and loss detection semantics the transport runtime negotiates over; applied in §14.
  • RFC 8446 — TLS 1.3: 1-RTT handshake and mutual-auth certificate semantics used for east-west encryption; applied in §14 and §22.
  • RFC 5681 — TCP Congestion Control: slow-start and congestion-avoidance behavior the QUIC congestion controller is benchmarked against; applied in §28.
  • OpenTelemetry Tracing Specification v1.x — span/context propagation model pinning the correlation-ID design across process boundaries; applied in §19.

Glossary (§36) · 41 terms · site-wide glossary

WAL
write-ahead log; the durable append-only record every mutation passes through before visibility (§6 P9).
Epoch
monotonically increasing topology generation identifier (§7 I2, §11 EpochId).
Replay Drift
divergence between two replay runs of identical input; a §7 I7 violation.
Snapshot Manifest
immutable metadata describing a checkpoint's chunks and checksums (§11).
Inflight Window
the bounded outstanding-frame budget a stream is permitted (§11 SchedulerQuota).
Replica Watermark
the highest sequence a given replica has acknowledged (§11 AckWatermark).
Failover FSM
the state machine driving coordinator failover decisions (§3.2).
Stream Gap
a missing WalSequence detected during replay validation (§7 I1).
Tombstone
a first-class deletion marker used in conflict resolution (§20.2).
Quorum
the minimum acknowledgment set required to advance the ack watermark (§7 I4).
Backpressure
upstream rate-limiting signal propagated from a saturated downstream queue (§6 P2).
Split Brain
two coordinators simultaneously believing they hold write authority for the same stream; prevented by §7 I2/I8.
Replay Cursor
the per-stream marker of replay progression (§11 ReplicationCursor).
Checkpoint
a transactionally consistent snapshot instant (§7 I5).
Segment Rotation
WAL file rollover at a configured size threshold (§13.2).
Idempotency
the property that re-applying an already-applied entry is a no-op (§7 I11).
Corruption Quarantine
isolating a damaged WAL segment or snapshot chunk from further use (§13.9).
Capability Negotiation
peer feature/version discovery at connection registration (§16.2).
Degraded Mode
a stream state with reduced throughput but preserved correctness (§8.3).
Retry Amplification
a failure mode where retry traffic itself saturates a link (§15.6).
Fencing Token
a value invalidated on epoch bump that prevents a stale writer from acting (§7 I8).
Vector Clock
logical causality metadata used for conflict detection (§11 ConflictRecord, Mattern 1989).
ISR
in-sync replica set, the Kafka concept informing this system's lag-handling design (§5, §13).
RPO
recovery point objective, the maximum acceptable data loss window (§4).
RTO
recovery time objective, the maximum acceptable outage duration (§4).
Credit-Based Flow Control
a backpressure mechanism where senders spend explicitly granted credit rather than reacting to loss (§15.2).
Head-of-Line Blocking
one slow stream stalling unrelated streams sharing a transport connection (§14.6).
Zero-Copy Buffer
a payload-handling technique avoiding a full-frame memory copy per send (§14.2).
Causal Domination
the property that a resolved vector clock must be greater than or equal to both of its inputs (§20.2).
Forensic Bundle
the fault schedule, seed, and telemetry captured from one chaos-suite run (§21.2).
Admission Control
rejecting new work at a queue boundary once capacity is reached (§7 I6).
Anti-Affinity
placement policy preventing quorum members from sharing a failure domain (§24).
Version Skew
the state of two adjacent MINOR versions running simultaneously during a rolling upgrade (§25).
Rename-on-Complete
an atomic-write pattern using filesystem rename to guarantee no partial file is ever visible (§17.2).
Chunked Transfer
splitting a snapshot into independently checksummed, resumable segments (§17.2).
Peer Strike Counter
a per-peer counter of protocol violations gating disconnection (§14.6, §6 P10).
Correlation ID
the identifier carried across every span in one logical mutation's pipeline (§19.2).
Cardinality Budget
a cap on the number of unique label combinations a metric may emit (§19.6).
Deterministic Simulator
the virtual-clock test harness every invariant assertion runs against (§7 closing paragraph, §12).
Differential Testing
comparing replay output across runtime revisions on the same trace (§26).
Canary Channel
the first release channel a build reaches after CI and chaos gating (ADR-18, §27).
