32. Back-of-Envelope Capacity Model

  • C1 — Node Throughput Ceiling. 25 Gbps ÷ 8 = 3.125 GB/s raw link capacity; at ~2 KB average frame size, 3.125 GB/s ÷ 2 KB = 1.56M frames/sec, rounded down to the 1.5M ops/sec §4 ceiling for headroom.
  • C2 — Startup Recovery Bound. 1,000,000 WAL entries ÷ 90 s = 11,111 entries/sec required scan rate, well under the WAL subsystem's ~500K entries/sec sequential-scan floor, leaving margin for checksum validation.
  • C3 — Node Memory Budget. 10,000 streams × 4,096 max inflight frames (§4) × 256 B queued-frame header = 10.5 GB queue memory + 16 GB WAL page-cache target + 4 GB scheduler overhead ≈ 30.5 GB, inside the 32 GB §4 ceiling.
  • C4 — Max Concurrent Streams. 65,536 FD budget ÷ 6 FDs per stream (one shared QUIC connection amortized plus ~5 file/socket handles) = 10,922, rounded down to the 10,000 §4 ceiling for admission-control headroom.
  • C5 — Write Amplification. 1.0x local WAL + 1.0x replicated remote WAL + 0.5x average snapshot-delta overhead during resync = 2.5x baseline, + 1.0x transient checksum-verification buffer during compaction = 3.5x, matching the §4 ceiling exactly.
  • C6 — Scheduler Credit Ledger Size. 10,000 streams × 128 B per SchedulerQuota (§11) = 1.28 MB, negligible against the 32 GB §4 ceiling, confirming the ledger is never the scaling bottleneck named in §29.
  • C7 — Snapshot Restore Time at Scale. 500 GB snapshot ÷ 1 GB/sec restore throughput (§4) = 500 s ≈ 8.3 min per full-state resync — inside the 5-minute RTO budget only when paired with incremental WAL catch-up (§17.2), never as a cold full restore alone.
