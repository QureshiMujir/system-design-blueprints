116 — Model Quantization (INT8 / INT4)

Project Number: 116

Project Name: Model Quantization (INT8 / INT4)

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

Build mq, a model-quantization toolchain that converts fp16/bf16 transformer checkpoints into INT8, INT4, NF4, and FP8 representations under a reproducible calibration + serialization + runtime pipeline, and measures the accuracy/size/speed trade against the fp16 baseline. The system has three engineering surfaces: a quantize surface (Python) that consumes a checkpoint + calibration corpus and emits per-tensor/per-channel/per-group scales and zero-points under a named scheme (PTQ min-max/percentile/MSE/entropy, GPTQ, AWQ, SmoothQuant, LLM.int8(), or QAT with STE/LSQ); a serialize surface (Python + Rust) that packs sub-byte weights into a gguf-compatible Q-file; and a runtime surface (Rust + CUDA, plus a CPU simulation oracle) that loads a Q-file and executes fused dequant-matmul kernels with an fp32 accumulator.

Phase-0 deliverable (numbered modules):

  1. mq.types — QScheme, QTensor, QSchema, CalibrationStats value types (§11).
  2. mq.quantize.ptq — per-tensor symmetric INT8 quantizer (§8, §12).
  3. mq.simulate.kernel — CPU fp32 dequant + matmul simulation runtime (§12).
  4. mq.eval.perplexity — WikiText-2 perplexity oracle (§12).
  5. mq-core (Rust) — QTensor/QScheme mirror types + block layouts (§11).
  6. mq-gguf (Rust) — Q-file reader/writer stub for the Phase-0 subset (§14, §21).

System boundaries. Provides: calibration, scheme selection, quantization (PTQ methods, GPTQ, AWQ, SmoothQuant, LLM.int8(), QAT), serialization to a gguf-compatible Q-file, a CPU simulation runtime, a GPU fused-kernel runtime, and an accuracy/perf eval harness. Delegates: model architecture definition and training (owned by the source checkpoint's framework — transformers); tokenization (delegated to the checkpoint's tokenizer); distributed serving, batching, and KV-cache management (owned by an inference-engine project, e.g. rank 92 Transformer-Inference-Engine). Does not provide: model training from scratch, RLHF/SFT pipelines, or a hosted inference API (that is a downstream integration, not this toolchain).

Non-goals. Not a general tensor-compression research platform (no pruning, no distillation, no low-rank factorization beyond what a scheme's paper defines); not a replacement for torch.compile or kernel autotuning frameworks; not a model-serving system.

Deployment model. Two independent artifacts ship: (a) a Python wheel (mq) installed in a research/ops environment that runs quantize + calibrate + eval offline, batch, on CPU or a single GPU; (b) a set of Rust crates + a CUDA-enabled shared object that a serving process links against to load a Q-file and run inference. The two communicate only through the Q-file on disk — no RPC, no shared memory, no process boundary.

Target users/operators. ML infra engineers converting a checkpoint before deployment; inference-platform engineers integrating the runtime crate into a serving binary; researchers comparing quantization methods against the eval harness.

What later phases unlock. Phase 1 unlocks per-channel INT8 with a real calibration loop; Phase 2 unlocks INT4 per-group packing; Phase 3 unlocks the NF4 grid; Phase 4 unlocks GPTQ; Phase 5 unlocks AWQ; Phase 6 unlocks SmoothQuant (W8A8); Phase 7 unlocks LLM.int8() outlier decomposition; Phase 8 unlocks QAT; Phase 9 unlocks FP8, mixed precision, and the fused CUDA runtime with full gguf interop.

Recommended language: Python (>= 3.11) for calibration/quantize/eval; Rust (edition 2021) + CUDA C++ (>= 11.8) for the runtime. Rationale: the quantize/calibrate surface is research-facing — PyTorch's nn.Module introspection (named_modules, forward hooks), torch.linalg.cholesky for GPTQ, and the Hugging Face datasets/transformers ecosystem are Python-native; reimplementing them in another language before the algorithms are validated is wasted motion. The runtime is deployment-facing — it must run with no GC pause, no interpreter overhead, and direct CUDA/CUTLASS access; Rust gives memory safety without a runtime GC and a real unsafe-scoped FFI boundary to CUDA, which C++ alone does not add over raw CUDA and which Go/Java add a GC pause on top of. Rejected: pure C++ for the whole toolchain (no memory-safety guarantee at the FFI boundary the way Rust's unsafe block scopes it; slower iteration for the calibration research loop); pure Python everywhere including the runtime (the GIL serializes inference, and Python's per-call overhead is incompatible with the < 5 ms p50 dequant-launch budget in §4); Go for the runtime (weak CUDA/CUTLASS FFI ecosystem, GC pauses interact badly with tail-latency budgets); Julia for calibrate/quantize (strong numerics but the transformer/tokenizer ecosystem lives in Python, and pulling researchers off PyTorch is a non-starter). The two languages meet at exactly one contract — the Q-file (§11.6) — never a process or FFI boundary; PyO3 binding Rust back into Python is rejected at ADR-01.

Prerequisites. The Transformer-Inference-Engine project (rank 92) for the runtime call sites the fused kernels replace; the GGUF-Format project (rank 109) for the on-disk container; the Tensor-Library-Backprop project (rank 41) for the autograd traces QAT depends on; the CUDA-Kernel-Authoring project (rank 88) for the WMMA/mma.sync intrinsics the INT8/INT4 GEMM uses. Comfort with nn.Module hooks, two's-complement/IEEE-754 representations, CUDA streams, and the CUTLASS layout vocabulary is assumed.

Estimated timeline. Phase 0: 2 weeks. Full system (Phases 0–9): 7–9 months at one senior engineer full-time, or 4–5 months with a 2-engineer team splitting Python/Rust.

Deferred features (register in full at the Deferred Features Register): a hosted calibration-as-a-service PhaseDeferred("§21"); a Triton-kernel runtime backend PhaseDeferred("§21"); SpQR/SqueezeLLM as first-class schemes PhaseDeferred("§15"); a vLLM/TensorRT-LLM checkpoint-export target PhaseDeferred("§21"); per-layer learned SmoothQuant alpha PhaseDeferred("§18").

2. Why Build This

Quantization is the systems lever between "runs in a paper" and "runs in production." A 70B fp16 model is 140 GB — it does not fit on one contemporary inference GPU. The same model at INT4 group-128 is ≈ 39–42 GB: one 48 GB workstation card, or one 80 GB H100 with KV-cache headroom. Building this toolchain from scratch teaches the reader the exact arithmetic that turns "eight-GPU node" into "one workstation."

  • Numerical representation as a systems lever, not a math exercise: affine quantization (scale + zero-point), the integer-only-inference derivation (Jacob et al. 2018), and why an accumulator's bit width is a correctness invariant, not a performance knob.
  • Why calibration is a distributed-systems problem in miniature: reproducibility (deterministic RNG + data provenance), idempotence, and the same "same input → same output" discipline that a consensus system needs, applied to a statistics-collection loop.
  • The outlier-handling literature as a case study in constraint relaxation: LLM.int8() decomposes; SmoothQuant migrates; AWQ scales in advance — three different answers to the same constraint (a few channels dominate the dynamic range), each with a different runtime/accuracy trade.
  • Kernel-fusion economics: why materializing a dequantized tensor in HBM erases the memory- bandwidth win that is the entire point of quantizing, and how a fused prologue avoids it — the same argument that motivates fused attention kernels (FlashAttention) and fused layernorm kernels elsewhere in this portfolio.
  • Cross-links: the GGUF-Format project (rank 109) for the container this toolchain writes into; the Transformer-Inference-Engine project (rank 92) for the call sites the fused kernel replaces; the CUDA-Kernel-Authoring project (rank 88) for the GEMM tiling this reuses; the Tensor-Library-Backprop project (rank 41) for the autograd trace QAT's STE depends on.
  • Calibration value: after this project, a reader can look at any "we quantized model X to N bits" claim in a paper or a vendor's marketing page and know exactly what was traded — which calibration set, which scheme, what accumulator, what the perplexity delta actually was, and whether the vendor's methodology is even reproducible.

What Mastery Looks Like

  • Derive the affine quantization error bound for a given (bits, layout) pair and predict which layers will fail an accuracy budget before running calibration — cemented in Phase 0 (§12) and Phase 2 (§14).
  • Explain, without notes, why LLM.int8(), SmoothQuant, and AWQ are three different answers to the outlier problem and when each wins — cemented in Phase 5 (§17), Phase 6 (§18), Phase 7 (§19).
  • Debug a Cholesky-decomposition failure in a Hessian-based quantizer from the damping parameter alone — cemented in Phase 4 (§16).
  • Read a gguf file's raw bytes and identify the block type, scale, and packed nibble layout without a parser — cemented in Phase 2 (§14) and Phase 9 (§21).
  • Reason about a fused dequant-matmul kernel's register pressure and HBM traffic and predict its throughput within 20% — cemented in Phase 9 (§21) and Performance Engineering (§28).
  • Design a mixed-precision assignment across a model's layers given an accuracy budget and a size budget, and defend the assignment with a Pareto argument — cemented in Phase 9 (§21).

Five properties hold throughout the document. First, the simulation runtime is the canonical accuracy oracle — the GPU kernel is the deployment surface, never the source of truth for an accuracy number (P1). Second, the Q-file is the only contract between quantize and runtime — no PyO3, no shared memory, no pickle (ADR-01). Third, schemes are data (a QScheme value) and methods are dispatch functions over that data — the runtime dequants on (bits, layout) without knowing which method produced the tensor (P8). Fourth, calibration is reproducible: a (checkpoint, corpus, scheme, seed) tuple is hashed into the Q-file's TLV metadata and re-runs bit-identically (P9, I9). Fifth, every quantized matmul accumulates in fp32 regardless of input precision — an INT32 accumulator overflows the scales this system targets at long sequence lengths (P7, I3, ADR-07).

6. Design Principles

  1. P1 — Simulation-first. Every kernel has an fp32 CPU simulation that matches the GPU kernel bit-for-bit on the rounded output. Tradeoff: the simulation is slower per-token than the GPU kernel. Operational implication: accuracy numbers are always reproducible on a laptop. Violate it and accuracy becomes hardware-dependent and unauditable.
  2. P2 — Accuracy-budgeted. Every method ships a documented perplexity-delta budget against a fixed eval slice (§4). Tradeoff: a method that cannot hit its budget does not land, even if it is faster or smaller. Violate it and the conformance suite silently ships an accuracy regression.
  3. P3 — Weight-only by default. Activations stay fp16/bf16 unless a scheme explicitly quantizes them (SmoothQuant, LLM.int8()). Tradeoff: leaves throughput on the table vs W8A8. Violate it and every scheme inherits activation-outlier fragility by default.
  4. P4 — Outlier-aware. Every scheme either avoids activation quantization or treats outliers explicitly. Tradeoff: outlier-aware schemes cost extra calibration passes. Violate it and per-tensor INT8 silently destroys accuracy at scale (the LLM.int8() finding).
  5. P5 — Format-portable. The Q-file is gguf-compatible; extensions live in a forward-compatible TLV. Tradeoff: constrains block layouts to what gguf readers tolerate. Violate it and the ecosystem interop (llama.cpp) breaks silently.
  6. P6 — Kernel-fused dequant. The runtime never materializes a dequantized weight tensor in HBM; dequant fuses into the matmul prologue. Tradeoff: more complex kernel code than a two-pass dequant-then-matmul. Violate it and the memory-bandwidth win — the entire point of quantizing — evaporates.
  7. P7 — fp32 accumulator everywhere. Every quantized matmul accumulates in fp32. Tradeoff: 5–10% slower than an INT32 accumulator on some Tensor Core paths. Violate it and long sequences overflow the accumulator (ADR-07).
  8. P8 — Scheme-pluggable. A scheme is (bits, layout, symmetry, group_size, grid); the runtime dispatches on (bits, layout) only. Tradeoff: adding a scheme means adding a kernel for a new (bits, layout) pair, not just a Python function. Violate it and method-specific runtime branches proliferate.
  9. P9 — Calibration-reproducible. A (checkpoint, corpus, scheme, seed) tuple produces a bit-identical Q-file. Tradeoff: forces deterministic batch order and RNG seeding through the whole calibration path. Violate it and accuracy comparisons across runs are meaningless.
  10. P10 — Eval-comparable. Every quantized model is scored by the same harness on the same slice. Tradeoff: the harness must run on CPU-only fp32 simulation to stay reproducible across machines (P1). Violate it and cross-method comparisons are apples-to-oranges.
  11. P11 — gguf-compatible layouts. INT4 layouts match Q4_0 (per-32-block, symmetric) and Q4_K (per-256-superblock, asymmetric) exactly. Tradeoff: cannot invent a more storage-efficient layout without breaking interop. Violate it and llama.cpp cannot read our output.
  12. P12 — QAT is opt-in, PTQ is default. PTQ ships first; QAT (Phase 8) is the escape hatch when PTQ cannot hit the accuracy budget. Tradeoff: QAT requires a training loop and GPU time PTQ does not. Violate it and every deployment pays QAT's cost even when PTQ suffices.
  13. P13 — Mixed precision is a first-class per-layer assignment, not a global toggle. Tradeoff: the calibration config grows one row per overridden layer. Violate it and layers with disproportionate accuracy sensitivity (embeddings, lm_head, first/last transformer blocks) get the same treatment as the bulk.
  14. P14 — The Hessian/statistics computation and the packing computation are separate concerns. A quantizer (GPTQ, AWQ) computes a dequantized fp32 reconstruction; the packer (§11.6) converts that reconstruction to the on-disk block layout. Tradeoff: an extra round-trip through fp32 per column. Violate it and every new method must reimplement bit-packing, duplicating the highest-defect-density code in the toolchain.

8. Domain Model

8.1 Affine Quantization Mapping

For a real-valued tensor r, an integer quantized value q, a scale s ∈ ℝ⁺, and a zero-point z ∈ ℤ:

Quantize:    q = clamp( round(r / s) + z, qmin, qmax )
Dequantize:  r_hat = s * (q - z)

round is round-to-nearest-even (IEEE 754 default, ties-to-even) — Overton Ch. 2 (§5). The pair (qmin, qmax) is fixed by bit width and symmetry: INT8 symmetric [-127, 127] (-128 reserved to keep the range mirror-symmetric); INT8 asymmetric [0, 255]; INT4 symmetric [-8, 7]; INT4 asymmetric [0, 15].

8.2 Symmetric vs Asymmetric

Symmetric fixes z = 0; s = max(|r|) / qmax. Cheapest kernel (no zero-point subtraction in the dequant), correct when r's distribution is approximately zero-mean (true of trained weights — Goodfellow et al. Ch. 4 discussion of weight-init statistics generalizes here). Asymmetric computes s = (rmax - rmin) / (qmax - qmin), z = round(qmin - rmin / s); recovers dynamic range for distributions that are not zero-mean (activations after a ReLU/GELU, or narrow-range INT4 weights). Locked at ADR-04: weights symmetric, INT4 layouts asymmetric per Q4_K.

8.3 Per-Tensor / Per-Channel / Per-Group

The granularity of (s, z): one pair for the whole tensor (per-tensor — coarsest, cheapest, least accurate); one pair per output channel (per-channel — one extra scale per row, matches Jacob et al. 2018 §2's per-channel-weight recommendation); one pair per contiguous run of group_size elements along the reduction axis (per-group — the finest granularity this system ships, group_size ∈ {32, 64, 128, 256}, ADR-03).

8.4 PTQ Calibration Methods

Applied in §13. Given a tensor's observed values across a calibration corpus:

  • min-max: s = max(|r|) / qmax (or (rmax-rmin)/(qmax-qmin) asymmetric) — cheapest, most outlier-sensitive.
  • percentile: clip at the Pth percentile (default 99.99) before computing s — trades a small deterministic clipping error for robustness to a single extreme outlier sample.
  • MSE-based: grid-search a clipping threshold t ∈ (0, max(|r|)] minimizing Σ (r_i - dequant(quantize(r_i, t)))² (Banner et al. 2019's analytical form, or a numeric grid search) — most accurate, most expensive.
  • entropy-based: choose the clipping threshold minimizing KL-divergence between the original and quantized histograms (the ONNX Runtime / TensorRT calibrator method) — a distributional alternative to MSE, often cheaper to compute from a running histogram.

8.5 PTQ vs QAT

PTQ (§12–§19) quantizes a trained model once, offline, with no gradient step — cheap, the literature default, ships first (P12). QAT (§20) inserts a fake-quantize op in the forward pass during fine-tuning; the backward pass needs a gradient for round(), which has zero gradient almost everywhere. The straight-through estimator (STE) approximates ∂round(x)/∂x ≈ 1 inside [qmin, qmax] and 0 outside (clip range) — a biased but usable gradient. Learned Step-Size Quantization (LSQ, Esser et al. 2020**)** goes further: the scale s itself is a trainable parameter with a gradient scaled by 1/√(qmax·N) (N = number of elements) to keep its update magnitude comparable to the weight updates — this is what makes QAT recover more accuracy than PTQ at the same bit width, at the cost of a training loop.

8.6 GPTQ (Hessian-Based Error Compensation)

Applied in §16. Treats quantization as a layer-wise reconstruction problem: given input activations X and weight W, minimize ||XW^T - XQ^T||² where Q is the quantized W. The Hessian of this objective is H = 2 X^T X / N. Quantizing column j and propagating its rounding error e_j to not-yet-quantized columns via H⁻¹ (Cholesky-cached, §16.2) is the Optimal Brain Quantization step generalized from LeCun et al.'s Optimal Brain Surgeon.

8.7 AWQ (Activation-Aware Scaling)

Applied in §17. A different question: which weight channels does the quantization error matter most for? Answer: the ones multiplied by high-magnitude activations. Scale those channels up by s = actmax^α before quantizing (protecting their precision), and divide the corresponding activations by s at inference (exactly compensating, folded into the preceding layer's parameters at zero runtime cost) — no Hessian required.

8.8 Dequantization

The inverse affine map (§8.1) applied at runtime, fused into the matmul prologue (P6): read a packed byte, unpack to the integer grid index, apply s/z (or an NF4/FP8 grid lookup), multiply against the activation, accumulate in fp32 (P7, I3).

8.9 Mixed Precision

A QSchema (§11.5) assigns a QScheme per layer name — e.g. INT4 group-128 for attention.qkv, INT8 per-channel for attention.out, fp16 (no entry) for the embedding and lm_head. The runtime dispatch table keys on (bits, layout) per tensor, so a single model can mix schemes without a global toggle (P13).

8.10 Worked Example (INT8 Per-Tensor Symmetric)

Weight row r = [-0.72, 0.14, 0.53, -0.05, 0.31, -0.61]. abs_max = 0.72, s = 0.72 / 127 = 0.0056693.

r_i r_i / s q_i (rounded, clamped) dequant = q_i · s error
-0.72 -127.00 -127 -0.71960 0.00040
0.14 24.70 25 0.14173 -0.00173
0.53 93.49 93 0.52724 0.00276
-0.05 -8.82 -9 -0.05102 0.00102

Max absolute error 0.00276, consistent with the s/2 = 0.00283 half-step rounding bound (I3 discussion, §32 M-derivation).

8.11 Malformed-Input Example

A weight tensor with in_features = 4097 and group_size = 128: 4097 % 128 = 1 ≠ 0 — I2 fires; the quantizer raises a validation error naming the offending layer and the required pad amount (31 zero-columns) rather than silently truncating the last partial group, which would corrupt the reconstructed matmul's output dimension.

8.12 Failure-Path Example

GPTQ's Cholesky decomposition of the damped Hessian fails (torch.linalg.cholesky raises torch.linalg.LinAlgError) on an ill-conditioned layer: detection is the exception itself; recovery escalates damp_percent from 0.01 → 0.05 → 0.1 (three retries), and if all three fail, the layer falls back to plain per-group round-to- -nearest (RTN) quantization with a logged gptq_fallback_total{layer} telemetry event — the job does not abort, but the fallback is visible in the accuracy report (§16.6, FM-4).

The calibration loop must run under model.eval() + torch.no_grad() — train-mode collects post-dropout noise, and a grad-tracking pass leaks memory at scale. 14. Phase 2 — INT4 Per-Group Packing (Symmetric & Asymmetric)

14.1 Objectives

Ship INT4 at the price-performance point of the literature (Dettmers & Zettlemoyer 2023): per-group asymmetric (Q4_K-style, group=128, ADR-03) and per-group symmetric (Q4_0-style, group=32) with gguf-compatible packed sub-byte storage (P11, ADR-05).

14.2 Detailed Implementation Steps

Implement pack_int4/unpack_int4 in mq.schemes.int4 — two 4-bit values per byte, little-endian nibble (ADR-05, Bryant & O'Hallaron Ch. 2 bit-packing technique). Implement the corresponding mq-dequant Rust kernels (DequantInt4SymmetricPerGroup, DequantInt4AsymmetricPerGroup, §11.8) as the simulation oracle's Rust-side twin. Extend mq-gguf's writer/reader to the Q4_0/Q4_K GgmlType values (§11.7).

14.3 Deliverable

mq quantize <model> --scheme int4-group128-asym and --scheme int4-group32-sym both produce Q-files loadable by both the simulation runtime and an unmodified llama.cpp installation (P11 interop check).

14.4 Acceptance Criteria

perplexity_delta < 0.8 on GPT-2 124M and < 1.5 on a 1.3B-class model for group-128 asymmetric (§4). A pack/unpack round-trip test asserts bit-identity for 10,000 random int4 values. A Q-file written by mq and read by llama.cpp's gguf-dump tool reports matching tensor shapes and block types (interop fixture, P11).

14.5 Conformance Fixtures

14.6 Pitfalls

The +8 bias trick for symmetric INT4 (quantize to signed [-8,7], pack as unsigned [0,15] to match gguf's byte layout) is the single most-confusing packing detail — write the round-trip test before trusting the implementation. Common transformer hidden dims (768, 1024, 2048, 4096, 5120) all divide 128 cleanly; uncommon ones need explicit padding instructions, never silent truncation (I2). The simulation dequant produces fp32; the Phase-9 production kernel produces fp16 — the two differ by fp16 rounding on the output, bounded to ≤ 1e-3 relative error and checked by I7's conformance suite.

14.7 Performance Concerns

Packing is O(N/2) bytes written per tensor — negligible. The per-group wmin/wmax reduction is O(N) with a group_size-strided reshape; group_size=32 produces 4× the scale/zero-point metadata of group_size=128, directly trading storage for accuracy (§4 storage-amplification row).

14.8 Edge Cases

A group whose wmax == wmin (constant weights, degenerate but possible on a pruned/frozen layer): guard scale = max((wmax-wmin)/15, eps) to avoid divide-by-zero. A model whose in_features is prime (no valid non-trivial group size divides it): reject with an explicit message rather than silently falling back to per-tensor.

14.9 Failure Analysis

A byte-layout mismatch against llama.cpp's reference (detected by the interop fixture failing): blast radius is total for INT4 interop — no partial compatibility is meaningful for a fixed-size packed block; recovery is re-deriving the byte offsets against ggml-quants.c directly, not guessing. A scale computed as Inf from an unguarded division: caught by a NaN/Inf assertion on every QTensor.scales tensor before serialization (fail fast at quantize time, never at load time).

15.1 Objectives

Ship the QLoRA normal-float-4 grid — a non-uniform 4-bit grid matched to the empirical Gaussian-ish distribution of trained weights, recovering 0.1–0.3 perplexity versus uniform INT4 (Dettmers et al. 2023) — plus the double-quantization trick that quantizes the per-group scales themselves.

Implement quantize_nf4_per_group (mq.quantize.nf4): per group of 64, normalize by abs_max to [-1,1], nearest-neighbor search against the 16-element grid, store the 4-bit index + fp16 abs_max scale (§8.3 layout reuse, packed via Phase 2's pack_int4). Implement optional double quantization (quantize_scales_fp8, §21 FP8 dependency) — quantizes the per-64-group fp16 scales to FP8-E4M3 with one fp16 super-scale per 256 scales, saving ≈ 0.4 bits/weight (deferred to ship alongside Phase 9's FP8 support, PhaseDeferred("§21")).

15.3 Deliverable

mq quantize <model> --scheme nf4-group64 produces a Q-file readable by both the simulation runtime and bitsandbytes' NF4 loader (cross-tool interop, mirroring P11's INT4 guarantee).

15.4 Acceptance Criteria

perplexity_delta < 0.6 on GPT-2 124M (§4), strictly better than plain per-group-asymmetric INT4 (Phase 2's 0.8 budget) on the same corpus. A histogram of assigned NF4 indices over N(0, σ)-distributed synthetic weights is approximately Gaussian-quantile-shaped (distributional sanity fixture). 15.5 Conformance Fixtures

fixtures/nf4_grid_exact.json — the 16 grid constants at full fp32 precision, expected: byte-identical to the QLoRA reference (I8) | fixtures/nf4_gaussian_histogram.json — 10,000 samples from N(0,1), expected: index-9 (center-ish) bucket most populated, monotonic tail falloff | fixtures/nf4_asymmetric_grid_check.json — expected: grid is not mirror-symmetric around index 7 (deliberate, §15.6).

15.6 Pitfalls

The NF4 grid is not symmetric around zero (a single zero-crossing near index 7, but the negative/positive halves are not mirror images) — a quantizer that assumes symmetry rounds correctly on one side and wrong on the other; the nearest-neighbor search must use the published asymmetric grid, no shortcuts. Grid constants must be reproduced to full fp32 precision (I8) — any truncation shifts decision boundaries between adjacent levels. The argmin nearest-neighbor search is O(N × 16) — for a 7B model (≈ 6.5B weights) this is ≈ 100B comparisons; acceptable on CPU (10–30 s/layer) but a bucket-search CUDA variant is 10× faster and ships opt-in.

15.7 Performance Concerns

The 16-way nearest-neighbor search dominates NF4 quantize time (§15.6); batching the search across all groups of a layer in one tensor op avoids a Python-level loop over groups, which would otherwise dominate wall-clock at 7B+ scale.

15.8 Edge Cases

A group whose abs_max = 0 (all-zero weights): guard division, map every value to grid index 7 (the zero-nearest level) rather than dividing by zero. A weight value exactly equidistant between two grid levels (a tie): resolved by argmin's deterministic lowest-index tie-break — documented so replay (I9) is stable.

15.9 Failure Analysis

A grid-constant edit that isn't caught by test_nf4_grid_exact before merge: caught by I8's CI gate rejecting any grid-constant diff without an accompanying ADR; blast radius otherwise would be silent accuracy drift across every NF4-quantized model, the worst class of defect (silent, cumulative, hard to bisect). A double-quantization FP8 scale overflow (scale value exceeding E4M3's dynamic range): detected by an explicit range assertion before packing; recovery falls back to non-double-quantized (plain fp16 scales) for that layer.

16. Phase 4 — GPTQ: Hessian-Based Error Compensation

16.1 Objectives

Implement GPTQ (Frantar et al. 2023) — the Hessian-aware PTQ method that brought INT4 within 0.5 perplexity of fp16 at 175B scale — as the default INT4 PTQ method (ADR-09) for accuracy- critical deployments, generalizing Optimal Brain Surgeon to per-layer, per-column quantization with second-order error compensation.

16.2 Detailed Implementation Steps

Implement GptqInputHook (mq.quantize.gptq) collecting the per-layer Gram matrix X^T X in fp64 (I10 — fp32 accumulation fails Cholesky on 5–10% of ill-conditioned layers, Overton's conditioning discussion, §5 Books). Implement gptq_quantize_layer: damp the Hessian diagonal (damp_percent=0.01, ADR-21 default), compute the Cholesky-cached inverse (torch.linalg.cholesky + cholesky_inverse), then process columns block-wise (block_size=128, ADR-21): quantize column j via the layer's target scheme (GptqState, §11.10), compute the rounding error, propagate it to not-yet-quantized columns via the Cholesky factor row (§8.6 math). Implement the act-order option (argsort(-diag(H)) column permutation before quantization, storing the inverse permutation in the Q-file TLV, §8.6 note). Implement the three-step damping-escalation retry (0.01 → 0.05 → 0.1) with an RTN fallback on repeated Cholesky failure (§8.12 failure path, FM-4).

16.3 Deliverable

mq quantize <model> --scheme int4-gptq --group-size 128 produces a Q-file whose per-layer quantization used the Cholesky-cached OBQ update; mq inspect reports whether act-order was applied and whether any layer fell back to RTN.

16.4 Acceptance Criteria

perplexity_delta < 0.4 on GPT-2 124M and < 1.0 on a 7B-class model (Frantar et al. 2023's reported bar, §4). Per-layer wall-clock < 60 s at hidden=4096 (§4, M-table §28). GPTQ-INT4 beats plain per-group-asymmetric INT4 (Phase 2) by ≥ 0.3 perplexity on the same model (comparative fixture). Two runs with the same seed and corpus produce a bit-identical Q-file (I9).

16.5 Conformance Fixtures

fixtures/gptq_vs_rtn_comparison.json — same model, same group size, expected: GPTQ ≥ 0.3 perplexity better than RTN | fixtures/gptq_cholesky_failure_synthetic.pt — a deliberately ill-conditioned synthetic Gram matrix, expected: damping escalation triggers, RTN fallback logged | fixtures/gptq_actorder_permutation.json — expected: stored permutation inverts cleanly at dequant time | fixtures/gptq_7b_layer_timing.json — expected: < 60s per layer at hidden=4096.

16.6 Pitfalls

damp_percent=0.01 (ADR-21) is the only knob preventing Cholesky failure on ill-conditioned Hessians — lower values (1e-4) fail on 1–5% of layers; higher (0.1) blunts accuracy; 0.01 is the paper's default and has held across the literature. block_size trades memory for accuracy convergence speed — 32 converges marginally better, 256 is faster; 128 is the paper's default (ADR-21). GPTQ on lm_head is unstable on most models (vocab-sized output, rank-deficient Hessian) — skipped by default, ships in fp16, matching literature consensus.

16.7 Performance Concerns

The fp64 Gram matrix costs hidden² × 8 bytes/layer — 128 MB at hidden=4096; a 7B model's 32 layers would need 4 GB resident simultaneously without checkpointing to disk between layers (§4 memory-ceiling row) — per-layer checkpointing keeps peak memory < 2 GB (§4). The Cholesky-cached update reduces per-column cost from O(N²) naive to O(N) amortized (ADR-21) — non-negotiable at 7B+ scale (Kirk & Hwu's tiling-cost reasoning generalizes to why the naive form is intractable).

16.8 Edge Cases

A layer whose Hessian is exactly singular (e.g. a frozen/dead sublayer with zero-variance activations): damping still regularizes it, but if all three escalation steps fail, the RTN fallback fires (§8.12) — this must never silently produce NaN weights. A corpus too small to produce a well-conditioned Hessian for a very wide layer (hidden > corpus×seq_len): detected by a condition-number check before Cholesky, surfaced as an operator warning to enlarge the calibration set.

16.9 Failure Analysis

Repeated Cholesky failures across many layers (a systemic corpus or model issue, not a single ill-conditioned layer): surfaced via gptq_fallback_total exceeding a rate threshold in the accuracy report, escalating from a per-layer log line to a job-level warning; forensic artifact is the per-layer condition-number log, sufficient to diagnose without re-running. The act-order permutation lost or corrupted on load: I4-style length/shape validation catches a malformed permutation array before it silently misassigns weights.

16.10 Operational Notes

Telemetry: gptq_fallback_total{layer}, gptq_layer_duration_seconds, gptq_condition_number (histogram). Runbook docs/runbooks/calibration-divergence.md covers Hessian-conditioning triage. Compatibility: the act-order permutation is a Q-file TLV addition (ADR-23) — Q-files without it are read as non-permuted (backward compatible, §25).

17. Phase 5 — AWQ: Activation-Aware Scaling

17.1 Objectives

Implement AWQ (Lin et al. 2024) as the low-calibration-cost alternative to GPTQ (ADR-09 alternative path) — protect the ≈ 1% of activation-salient weight channels via a per-channel scale search, with zero Hessian computation.

17.2 Detailed Implementation Steps

Implement awq_search_alpha (mq.quantize.awq): for each layer, collect per-channel activation abs_max (reusing Phase 1's hook infrastructure, §13.2), grid-search α ∈ {0, 0.05, ..., 1.0} (AwqScaleTable.grid, ADR-22) computing s = actmax^α, normalized so the matmul scale is preserved, quantizing W·s and measuring reconstruction MSE against the fp32 baseline matmul; select the α minimizing MSE (§8.7 math). Implement the scale-fold transform (smoothquant-adjacent but AWQ-specific): fold 1/s into the preceding LayerNorm's weight/bias, or into a preceding Linear's output rows for non-LayerNorm predecessors. Track folded layers in a set to enforce I12 (fold exactly once). Clip s to [1e-4, 1e4] guarding against pathological activation dynamic range (§17.6). Folding mechanics: the per-channel scale s must apply to the linear's input; folding into the immediately preceding layer makes this zero-cost at inference. For a preceding LayerNorm: LayerNorm.weight /= s, LayerNorm.bias /= s. For a preceding Linear (e.g. up_proj feeding a SwiGLU gate_proj): divide that linear's output rows by s. Non-foldable predecessors (activation functions, residual adds) require a runtime scale tensor recorded in the Q-file metadata instead (ADR-11-adjacent fallback, consumed by the Phase-9 kernel).

17.3 Deliverable

mq quantize <model> --scheme int4-awq produces a Q-file with per-layer folded scales (or an explicit runtime-scale marker for non-foldable layers) and a per-layer chosen α recorded for inspection via mq inspect.

17.4 Acceptance Criteria

AWQ-INT4's perplexity_delta is within 0.3 of GPTQ-INT4 (Phase 4) on the same model (§4, comparative fixture). Per-layer wall-clock < 30 s (no Cholesky, faster than GPTQ's 60 s budget, §4). Two runs with the same corpus/seed choose an identical α per layer (deterministic grid search, I9).

17.5 Conformance Fixtures

fixtures/awq_vs_gptq_comparison.json — expected: within 0.3 perplexity of each other | fixtures/awq_alpha_determinism.json — two runs, expected: identical per-layer α | fixtures/awq_non_foldable_predecessor.pt — a layer preceded by a GELU (not LayerNorm/Linear), expected: runtime-scale marker emitted, not a silent fold | fixtures/ awq_extreme_dynamic_range.pt — activation with 1e5× per-channel range, expected: s clipped to [1e-4, 1e4].

17.6 Pitfalls

The scale fold is where AWQ can silently corrupt a model: an unfoldable predecessor requires the runtime-scale path (§17.2), never a best-effort fold — detect and branch explicitly (I12). The 20-value alpha grid (ADR-22) is a deliberate accuracy/cost tradeoff; a finer grid or a learned α (gradient descent) both cost more calibration time for marginal gain — ADR-22 documents both as viable alternatives, not defaults. Extremely skewed activation distributions (100,000× per-channel range) produce an equally skewed s, and folding it into LayerNorm.weight can push that weight's values to both extremes — the [1e-4, 1e4] clip is the guard; layers needing a larger range fall back to GPTQ.

17.7 Performance Concerns

The alpha grid search re-quantizes and re-measures MSE 21 times per layer — the dominant AWQ cost, still cheaper than GPTQ's Cholesky (ADR-09's rationale). Folding is O(hidden) per layer, negligible.

17.8 Edge Cases

A layer with no preceding LayerNorm/Linear at all (the very first layer in a model, folding into the embedding): treated as a non-foldable case (§17.2), runtime-scale path used. A tie in the alpha grid search (two α values with identical MSE, floating-point-exact): resolved by preferring the lower α (documented, deterministic, I9-compatible).

17.9 Failure Analysis

A folded scale applied to a layer AWQ has already folded (I12 violation, e.g. a re-run over a partially-quantized checkpoint): caught by the folded-set assertion before any weight mutation — blast radius is a rejected job, never a silently double-scaled model. A non-foldable predecessor misclassified as foldable (a new architecture's residual-add pattern not recognized by the predecessor-type check): produces a silently wrong model — the highest- severity AWQ defect class; mitigated by an architecture allowlist that fails closed (rejects quantization) on an unrecognized predecessor type rather than guessing.

17.10 Operational Notes

Telemetry: awq_alpha_search_duration_seconds, awq_non_foldable_layers_total, awq_scale_clip_triggered_total. mq inspect surfaces per-layer α and fold status for operator audit. Compatibility: runtime-scale markers are an additive TLV field (ADR-23); Q-files without AWQ scales are read as plain INT4 by older readers (§25).

18. Phase 6 — SmoothQuant: Per-Channel Outlier Migration (W8A8)

18.1 Objectives

Implement SmoothQuant (Xiao et al. 2023) to make W8A8 (INT8 weights and activations) viable by migrating activation outliers into the weights at PTQ time — the default W8A8 outlier strategy (ADR-10) — unlocking the INT8-GEMM throughput win (§4, 1.6–2.0×) without paying the LLM.int8() fp16 side-path cost.

18.2 Detailed Implementation Steps

Implement smoothquant_compute_scale (mq.quantize.smoothquant): per-channel s_j = actmax_j^α / weightmax_j^(1-α), default α=0.5 (§8's outlier-migration math, ADR-10). Implement smoothquant_apply: rescale X' = X/s, W' = W·s (exact matmul-output identity, §14.1 math box); fold 1/s into the preceding LayerNorm exactly as AWQ's fold (§17.2), tracked against the same I12 folded-set to prevent double-folding when both AWQ and SmoothQuant target the same layer (mutually exclusive per layer, enforced at config-validation time). After migration, quantize W' per-channel INT8 (Phase 1) and X' per-tensor INT8 (collected during calibration, §13). Detect and reject the per-tensor-weight + SmoothQuant pairing (§18.6 config-bug guard).

18.3 Deliverable

mq quantize <model> --scheme w8a8-smoothquant produces a Q-file with migrated per-channel weight scales and per-tensor activation scales, plus a fold-status record per layer.

18.4 Acceptance Criteria

perplexity_delta < 0.5 on a 7B-class model (§4). The pre/post-SmoothQuant matmul output is bit-identical in fp32 (the transform is exact, not approximate — a dedicated equality test, not a tolerance check). SmoothQuant pass wall-clock < 1 min for a 7B model (§4).

18.5 Conformance Fixtures

fixtures/smoothquant_exact_identity.json — expected: X'@W'^T == X@W^T to fp32 machine epsilon | fixtures/smoothquant_w8a8_7b.qfile — expected perplexity_delta < 0.5 | fixtures/smoothquant_pertensor_weight_reject.json — SmoothQuant + per-tensor weight config, expected: quantize job rejects with an explicit config error (§18.6) | fixtures/smoothquant_outlier_reduction_ratio.json — expected: 10–100× reduction in per-channel activation outlier ratio post-migration.

18.6 Pitfalls

The migration is exact only when the preceding layer is LayerNorm-or-Linear — non-foldable predecessors need the same runtime-scale escape hatch as AWQ (§17.2); the Q-file records which layers need it. α is a single model-wide hyperparameter in the shipped default (the paper's choice); per-layer α is a documented, deferred alternative (PhaseDeferred("§18"), Deferred Features Register). Pairing SmoothQuant with per-tensor weight INT8 is a configuration bug: after migration the weight distribution is heavily per-channel-skewed (the columns that absorbed outliers are now far larger), which per-tensor quantization handles badly — detected and rejected at config-validation time (§18.2).

18.7 Performance Concerns

The migration itself is O(hidden) per layer — essentially free; the real cost is the calibration pass collecting actmax/weightmax (shared with Phase 1's hook infrastructure, no duplicate pass needed).

18.8 Edge Cases

A layer where weightmax_j = 0 for some channel (dead weight column): guard the weightmax^(1-α) denominator with an epsilon floor. A model with no LayerNorm at all (a non-standard architecture using RMSNorm exclusively): the fold logic must special-case RMSNorm's lack of a bias term (bias fold step skipped, weight-only fold retained).

18.9 Failure Analysis

A SmoothQuant fold applied to a layer that AWQ also folded (I12 violation): caught by the shared folded-set assertion before any weight mutation — blast radius is a rejected job, never a silently double-scaled model. An α choice that pushes activation outliers into an already-outlier-prone weight distribution (a genuine literature-documented failure mode for badly-chosen α): detected by the pre/post outlier-ratio fixture (§18.5) regressing instead of improving; recovery is per-layer α override (documented alternative, ADR-10 note).

18.10 Operational Notes

Telemetry: smoothquant_fold_applied_total, smoothquant_outlier_ratio_before, smoothquant_outlier_ratio_after. Runbook cross-reference: docs/runbooks/ calibration-divergence.md covers a regressing outlier ratio. Compatibility: W8A8 Q-files require activation-scale TLV fields absent from weight-only Q-files — older weight-only readers must reject a W8A8 file cleanly rather than mis-load it (version-gated, §25).

19. Phase 7 — LLM.int8(): Outlier Decomposition

19.1 Objectives

Implement LLM.int8() (Dettmers et al. 2022) — the parameter-free (no calibration fold) alternative to SmoothQuant (ADR-10 alternative, ADR-11) — decomposing the matmul into an INT8 bulk path and an fp16 outlier-column path, for architectures where SmoothQuant's fold is impossible.

19.2 Detailed Implementation Steps

Implement llm_int8_decompose (mq.quantize.llm_int8): given per-channel activation abs_max and a configurable threshold (default 6.0, I13 — never hard-coded), partition input columns into outlier_cols/inlier_cols; quantize W[:, inlier_cols] per-channel INT8 (Phase 1 reuse); retain W[:, outlier_cols] in fp16 (LlmInt8Decomposition, §11.10). Record outlier_cols and threshold in the Q-file TLV (reproducibility, I5-adjacent). Implement the runtime dispatch split: one INT8 GEMM over inlier columns, one fp16 GEMM over outlier columns, summed — the Phase-9 fused-kernel implementation is the performance-critical version; Phase 7 ships a correctness-first two-GEMM simulation path. The runtime path: Y = Y_inlier + Y_outlier where Y_inlier = X_inlier_int8 @ W_inlier_int8^T (INT8 GEMM, fp32 accumulate per I3) and Y_outlier = X_outlier_fp16 @ W_outlier_fp16^T (fp16 GEMM, fp32 accumulate). The two-GEMM split is correctness-first at Phase 7; a fused single-kernel version for small outlier ratios ships at Phase 9 (§21.9).

19.3 Deliverable

mq quantize <model> --scheme int8-llmint8 --outlier-threshold 6.0 produces a Q-file with a recorded outlier-column decomposition; the simulation runtime executes the two-path matmul and reports perplexity.

19.4 Acceptance Criteria

perplexity_delta < 0.4 on a 7B-class model (§4). Varying the outlier threshold (3.0, 6.0, 12.0) produces a monotonic accuracy curve (higher threshold → fewer extracted outliers → more accuracy lost) — a jagged curve is a defect signal. The fp16 outlier-path inference overhead is < 5% slowdown versus pure INT8 (§4, M-table).

19.5 Conformance Fixtures

fixtures/llmint8_threshold_sweep.json — thresholds {3.0, 6.0, 12.0}, expected: monotonic perplexity curve | fixtures/llmint8_7b_default_threshold.qfile — expected perplexity_delta < 0.4 | fixtures/llmint8_outlier_overhead_benchmark.json — expected < 5% slowdown vs pure INT8 | fixtures/llmint8_zero_outliers_degenerate.pt — a layer whose activations never exceed the threshold, expected: decomposition degenerates cleanly to plain per-channel INT8 (no outlier path invoked).

19.6 Pitfalls

The outlier threshold is genuinely model-dependent (some fine-tunes need 12.0, some need 3.0) — I13 forbids a hard-coded default silently substituting for an unset config; the calibration pass must expose the per-channel-max distribution so an operator can choose. The decomposition shape depends on calibration data — a model calibrated on one corpus can have a different outlier-column set than the same model calibrated on another; the Q-file's provenance record (I5) prevents mixing decompositions across incompatible calibration runs. A naive runtime implementation that materializes the split X/W in HBM before the two GEMMs is bandwidth-bound and erases the INT8 win — the Phase-9 fused kernel exists specifically to fix this (§21.9, P6).

19.7 Performance Concerns

Two-GEMM correctness-first path (Phase 7) pays a real overhead from the gather/scatter of outlier columns — acceptable for validating correctness, explicitly not the shipped performance path (deferred to Phase 9's fusion, PhaseDeferred("§21")).

19.8 Edge Cases

An outlier ratio approaching 100% (a pathological activation distribution where nearly every channel exceeds the threshold): the decomposition degenerates toward plain fp16 — detected via an outlier-ratio telemetry alert rather than silently paying full fp16 cost unnoticed. Zero outliers (§19.5 fixture): must not error, degenerates to plain INT8 cleanly.

19.9 Failure Analysis

An outlier-column set that silently drifts between the calibration run and the inference-time checkpoint (e.g. the checkpoint was fine-tuned after calibration, shifting which channels are salient): the Q-file's provenance hash (I5) mismatches the live checkpoint hash, caught at load time rather than producing a subtly-wrong forward pass. A threshold set so low that the "outlier" path captures the majority of columns (a mis-tuned config, not a model property): surfaced by the outlier-ratio telemetry alert (§19.8) before it silently erases the INT8 throughput win end-to-end.

19.10 Operational Notes

Telemetry: llmint8_outlier_ratio, llmint8_outlier_gemm_duration_seconds. mq inspect surfaces the outlier-column count and threshold per layer. Compatibility: the decomposition TLV record is additive; a Q-file with an LLM.int8() decomposition is unreadable by a plain INT8 reader that doesn't understand the outlier-column split — version-gated (§25).

20. Phase 8 — Quantization-Aware Training (STE / LSQ)

20.1 Objectives

Ship QAT (P12 — opt-in, PTQ remains default) for accuracy budgets PTQ cannot meet: fake- quantize in the forward pass during fine-tuning, using the straight-through estimator (STE) for the base gradient and Learned Step-Size Quantization (Esser et al. 2020, ADR-20) for a trainable, better-converging scale.

20.2 Detailed Implementation Steps

Implement QatObserver (mq.quantize.qat) — a running min/max statistics collector (momentum-based EMA, distinct from CalibrationStats, §11.10) following the torch.ao.quantization Observer/FakeQuantize split (§5 Reference Implementations lesson). Implement the fake-quantize forward: q = clamp(round(r/s)+z, qmin, qmax), r_hat = s(q-z) (§8.1 identical math, now inside a training loop). Implement the STE backward: gradient passes through unchanged for r inside [qmin, qmax]'s corresponding real-value range, zero outside (clip-range gradient masking, Nagel et al. 2021 §5 treatment). Implement LsqParam (§11.10): scale s as a trainable parameter with gradient ∂L/∂s scaled by 1/√(qmax · N) (Esser et al. 2020's normalization, P8 keeps s's update comparable in magnitude to weight updates). Wire the QAT path as a distinct training-loop entry point (mq.quantize.qat.qat_finetune) — NOT a quantize-job CLI flag, since QAT requires a training harness the PTQ paths do not (P12 opt-in boundary).

20.3 Deliverable

A fine-tuning script demonstrates QAT converging on GPT-2 124M at INT4, reporting a perplexity curve over training steps that crosses below the PTQ INT4 (Phase 2) result within a bounded step budget.

20.4 Acceptance Criteria

QAT-INT4 (LSQ) achieves perplexity_delta < 0.3 on GPT-2 124M — strictly better than PTQ INT4's 0.8 budget (§4), justifying QAT's extra training cost. LSQ converges to a lower perplexity than plain-STE QAT on the same step budget (≥ 0.05 improvement, ADR-20's rationale verified empirically). Training completes within a fixed step budget (≤ 2,000 steps on GPT-2 124M) without divergence (loss NaN/Inf).

20.5 Conformance Fixtures

fixtures/qat_ste_vs_lsq_convergence.json — same model/steps, expected: LSQ ≥ 0.05 perplexity better | fixtures/qat_int4_vs_ptq_int4.json — expected: QAT beats PTQ's 0.8 budget | fixtures/qat_divergence_guard.json — a deliberately mis-scaled LSQ gradient, expected: training loss NaN detected and the run halted with a clear diagnostic, not a silent bad checkpoint.

20.6 Pitfalls

STE's zero gradient outside the clip range means a weight that drifts far outside [qmin,qmax]'s real-value range during training receives no corrective gradient (a known QAT failure mode) — LSQ's trainable scale mitigates this by letting the clip range itself adapt, but a too-aggressive learning rate on s can still destabilize training; the 1/√(qmax·N) gradient scaling (ADR-20) is not optional. Fake-quantizing too early in fine-tuning (before the base model has adapted at all) wastes steps on a moving target — the reference implementation lesson (§5, PyTorch quantization) is to warm up in fp32 for a short prefix before enabling fake-quantize.

20.7 Performance Concerns

QAT training cost dominates: an extra fake-quantize forward/backward per batch versus plain fine-tuning, roughly 1.1–1.3× the wall-clock of an unquantized fine-tuning run (bookkeeping overhead, not compute-bound). This cost is the entire reason QAT is opt-in (P12) rather than default.

20.8 Edge Cases

A layer whose scale s drifts to near-zero during LSQ training (an unstable gradient trajectory): guard with a minimum-scale floor identical in spirit to the PTQ clamp(min= 1e-8) guards elsewhere (I2-adjacent numerical floor). A fine-tuning run interrupted mid-training (crash, preemption): checkpoint the LsqParam scales alongside the model weights so resumption doesn't restart the scale-learning from scratch.

20.9 Failure Analysis

Training divergence (loss NaN, §20.5 fixture): detected by a standard loss-NaN guard, halting immediately rather than continuing to corrupt the checkpoint — forensic artifact is the pre-divergence gradient-norm history. A QAT checkpoint that "succeeds" numerically but regresses versus PTQ (a real possible outcome if hyperparameters are wrong): caught by the mandatory comparative fixture (§20.5) gating any QAT checkpoint's promotion to a shipped model.

20.10 Operational Notes

Telemetry: qat_step_loss, qat_scale_value{layer} (gauge, LSQ scale drift monitoring), qat_divergence_total. QAT checkpoints are versioned distinctly from PTQ Q-files in BUILD_PLAN.md tracking — they carry a training-provenance record (step count, learning rate, base checkpoint hash) absent from PTQ Q-files (§25).

21. Phase 9 — Mixed Precision, FP8, Fused Kernels & GGUF Interop

21.1 Objectives

Close the toolchain: per-layer mixed-precision assignment (P13), FP8 (E4M3/E5M2, Micikevicius et al. 2022, ADR-19), the production Rust+CUDA fused dequant-matmul runtime (P6, replacing every prior phase's CPU-simulation-only path), and full gguf round-trip interop with llama.cpp.

21.2 Detailed Implementation Steps

Implement MixedPrecisionPlan (§11.10) resolution: given a QSchema (per-layer overrides, ADR-24) and a size/accuracy budget pair, validate every named layer exists (model.named_modules(), I14) before quantizing. Implement FP8 quantization (mq.quantize.fp8): E4M3 (4-bit exponent, 3-bit mantissa) for weights/activations, E5M2 (5-bit exponent, 2-bit mantissa) for QAT gradients (ADR-19) — direct format cast, no scale/zero-point needed beyond an optional per-tensor scale for dynamic-range matching. Implement the mq-cuda fused kernels (gemm_int8.cu, gemm_int4.cu, gemm_nf4.cu, gemm_fp8.cu): read packed weights, dequant in registers (CUTLASS-templated, ADR-14, Kirk & Hwu tiling patterns), multiply against the activation, accumulate in fp32 (P7, I3), write fp16/bf16 epilogue — never materializing a dequantized weight tensor in HBM (P6). Implement mq-runtime's loader/dispatch (std::thread pool + mpsc, ADR-15): load a Q-file, replace every nn.Linear-equivalent call site with the dispatch-selected fused kernel keyed on (bits, layout). Close the gguf round-trip loop: verify every prior phase's Q-file format loads in an unmodified llama.cpp build and vice versa (P11 final validation).

21.3 Deliverable

An end-to-end demo: a 7B-class checkpoint quantized with a mixed-precision plan (INT4 group-128 for attention/MLP, INT8 per-channel for lm_head, fp16 embedding), served through mq-runtime with the fused CUDA kernel, measured for perplexity and tokens/sec, and cross- loaded into llama.cpp without error.

21.4 Acceptance Criteria

The fused-kernel dequant-launch overhead is < 5 ms p50 per linear layer at batch=1 (§4, M5). The simulation-vs-production-kernel divergence is ≤ 1e-3 relative error per tensor (I7, conformance gate). INT4 weight-only decode throughput is 2.5×–3.8× fp16 baseline at batch=1 (§4, bandwidth-bound regime). The mixed-precision Q-file loads correctly in llama.cpp (gguf-dump reports matching shapes/types for every tensor).

21.5 Conformance Fixtures

fixtures/mixed_precision_7b_plan.json — the per-layer schema, expected: every named layer resolves against the checkpoint (I14) | fixtures/fused_kernel_vs_simulation.json — expected ≤ 1e-3 relative error across 1,000 sampled layers | fixtures/int4_decode_throughput_bench. json — expected 2.5×–3.8× speedup vs fp16 | fixtures/llamacpp_roundtrip_7b.gguf — full-model cross-tool load fixture.

21.6 Pitfalls

FP8's narrow mantissa (3 bits for E4M3) means naive per-tensor FP8 without a dynamic-range- matching scale loses more accuracy than INT8 at the same nominal bit width — a per-tensor scale (analogous to the affine scale, §8.1) is mandatory even though FP8 is "floating," not "fixed" point. A fused kernel that spills registers under high group_size (256) sees a throughput cliff from register pressure (Kirk & Hwu Ch. 5) — profile per group-size variant before shipping a default. The std::thread-pool dispatcher (ADR-15) is request/response, not streaming — a caller expecting async/await ergonomics will misuse it; document the blocking- call contract explicitly.

21.7 Performance Concerns

Q-file load + kernel warm-up must stay < 5s p50 / < 8s p99 for a 7B INT4 model (§4) — the dominant cost is CUDA kernel JIT/cache warm-up on first launch, mitigated by ahead-of-time CUTLASS instantiation for the shipped (bits, layout) combinations. Bandwidth-bound INT4 decode throughput is the headline number (§4) — compute-bound INT8 prefill throughput is capped by Tensor Core FLOPs, a different regime (§28 M-table distinguishes both).

21.8 Edge Cases

A QSchema naming a layer that does not exist in the checkpoint (a typo): I14 rejects at schema-validation time with the closest valid name suggested, never a silent no-op. A mixed-precision plan whose combined size exceeds its stated size_budget_bytes: rejected before quantization begins, not discovered after a multi-hour 70B job completes.

21.9 Failure Analysis

The fused LLM.int8() kernel deferred from Phase 7 (§19.7) ships here: a naive gather-then-GEMM implementation is bandwidth-bound; the fused version combines the split-gather, fp16 GEMM, and INT8-GEMM accumulator into one kernel launch — detected via the same < 5% overhead acceptance bound as Phase 7 (§19.4), now measured against the real kernel instead of the two-GEMM simulation. A CUDA kernel that produces a result diverging > 1e-3 from the simulation oracle (I7 violation): blocks release via the conformance gate; forensic artifact is the per-tensor divergence report naming the exact (layer, bits, layout) tuple.

21.10 Operational Notes

Telemetry: kernel_launch_duration_seconds{bits,layout}, kernel_warmup_duration_seconds, dequant_dispatch_total{bits,layout}. Deployment: the CUDA-enabled mq-cuda crate is feature-gated (ADR-15 note) and excluded from default builds; a CPU-only deployment uses mq-dequant's reference kernels directly (slower, always correct — the same code path that grounds the simulation oracle throughout). Rollback: a production runtime that regresses can fall back to the Phase-0-era simulation path for the affected model as an emergency mitigation while the kernel is fixed.

Canary/rolling-upgrade/ rollback/migration. 25. Compatibility & Versioning

Wire compatibility. The Q-file is gguf version 3 compatible (§11.7); the TLV metadata extension (ADR-23) is additive-only — a reader ignorant of a TLV key skips it and still loads the tensors (P5). Storage compatibility. Block layouts (BlockQ4_0, BlockQ4_K, BlockQ8_0, §11.6) are frozen; a new k-quant format is a new GgmlType value, never a redefinition (ADR-08, I11 discipline extended to format IDs). Schema evolution. Adding a scheme (a new Bits/Layout combination) is additive to the QScheme enum and the runtime dispatch table (P8) — existing Q-files remain readable by a newer mq build; a newer Q-file using a scheme an older reader doesn't recognize fails closed (explicit "unknown scheme" error), never silently misinterpreted as a known one. API stability. mq.types, mq.quantize.* protocols (§11.9), and the CLI surface (mq quantize/eval/inspect) are the stable public API; internal calibration-statistics representations may change between minor versions. Migration. A Q-file written by an older mq is read forward-compatibly by a newer one (TLV additive rule); a Q-file using a scheme newer than the reader understands is rejected with an explicit "upgrade mq" message, never partially loaded. Deprecation policy. A scheme is deprecated with two minor-version notice before removal from the CLI surface; the reader retains the ability to load (never write) a deprecated scheme's Q-files indefinitely, so historical artifacts remain inspectable. SemVer. mq and the mq-* crates follow SemVer; a breaking change to QTensor/QScheme's public fields is a major version bump. Rolling-upgrade guarantees. The runtime crate's N and N-1 versions can load the same Q-file version simultaneously across a fleet during a rolling upgrade — this is why the Q-file format itself, not the runtime binary, is the compatibility boundary (ADR-01).

Unit. One test per invariant (§7) plus one per pack/unpack/dequant function (§11.6, §11.8) — the bulk of the ~40 fixtures named across §12.5–§21.5. Integration. 28. Performance Engineering

Methodology. Benchmark on a fixed reference host (one A100-80GB, one consumer RTX-4090) for every M-table target; profile with nsys/ncu for the CUDA kernels and py-spy for the Python calibration/quantize path. Allocation analysis: the calibration loop must not grow Python-heap allocations linearly with corpus size (streaming, not batch-materializing, §13.2). Lock contention: the runtime's mpsc dispatcher (ADR-15) is profiled for queue depth under concurrent load; a growing queue depth is the first symptom of an undersized thread pool. Cache/syscall analysis: the fused kernel's HBM access pattern is profiled for coalescing (Kirk & Hwu Ch. 5); the Q-file loader's mmap vs read tradeoff is benchmarked for cold-cache load latency (M5/M6). Tail-latency analysis: p99, not just p50, is tracked for every kernel-dispatch and load-time target, since a single slow layer in a mixed-precision model dominates end-to-end p99 (§21.7).

29. Scalability Analysis

Stays constant. Per-tensor quantization cost is O(N) regardless of model size (§12.2); the Q-file format's per-tensor header overhead is constant regardless of tensor size. Grows with model size. GPTQ's Hessian memory (O(hidden²), §16.7 — 512 MB at hidden=8192 for a 70B-class model, derived in §32); calibration wall-clock (O(layers × corpus size), linear in both); Q-file total size (O(total parameters × effective bits/weight), §4). Named bottlenecks in order. (1) GPTQ's per-layer Cholesky decomposition — O(hidden³) — the single most expensive step per layer at large hidden dimensions (ADR-21's Cholesky-caching mitigates but does not eliminate this); (2) the NF4 nearest-neighbor search — O(N × 16) — dominant at 7B+ scale (§15.6); (3) fused-kernel HBM bandwidth — the hard ceiling on INT4 decode throughput (§32's bandwidth derivation); (4) calibration corpus I/O — linear but parallelizable across layers. Horizontal scaling. GPTQ/AWQ quantization is embarrassingly parallel across layers (each layer's Hessian/scale-search is independent given the shared calibration activations) — the natural horizontal-scaling axis for a 70B+ quantize job (§32's parallel- quantize estimate). Vertical scaling. A single GPU with more HBM raises the ceiling on how large a Gram matrix can stay resident without checkpointing (§16.7), directly trading memory for calibration wall-clock. Sharding/partitioning. Not applicable to the quantize pipeline (single-model, single-job); the runtime shards across replicas (ADR-15 — one mq-runtime instance per model copy, no cross-instance state). Coordination overhead. Parallelizing GPTQ across layers requires no cross-layer coordination (each layer's Hessian is independent) but does require a shared, immutable calibration-activation cache read by every worker — the one shared-state surface, read-only, easy to reason about. Practical ceiling. Bandwidth-bound INT4 decode throughput (§32) is the hard ceiling this system cannot engineer past without a smaller effective bits/weight (the entire reason FP8/mixed-precision and SpQR-style hybrids exist as the next lever, §34). Levers beyond the ceiling. Lower average bits/weight (SpQR/SqueezeLLM hybrids, §34); larger batch sizes to amortize weight-read cost across more tokens (shifts the regime from bandwidth-bound toward compute-bound, changing which of M1/M2 governs).

30. Mental Models & First Principles

  • MM1 — A scale is a unit conversion, not a compression trick. Predicts: accuracy loss traces to a badly chosen scale far more often than to too few bits. Bug class without it: adding bits to fix an accuracy problem that a better calibration method (§13) would have fixed at the same bit width. Applied in §8.1, §13.
  • MM2 — Outliers are conserved, not destroyed. Predicts: every outlier-handling method (LLM.int8(), SmoothQuant, AWQ) relocates the cost of an outlier — to a side-path, to the weights, or to a pre-scaled weight — never eliminates it. Bug class without it: expecting a single universal "fix outliers" method rather than picking the relocation that fits the architecture. Applied in §17, §18, §19.
  • MM3 — The accumulator is the actual precision of your matmul. Predicts: input operand precision matters far less than accumulator precision at scale. Bug class without it: picking an INT32 accumulator to save 5–10% throughput and silently overflowing at long sequence lengths. Applied in §8.1, I3, ADR-07.
  • MM4 — Quantization error compounds like floating-point error, not like a discount. Predicts: independent per-column rounding accumulates a whole-layer error far worse than a naive per-weight bound suggests. Bug class without it: assuming a per-weight error bound bounds the whole layer, missing why GPTQ's error-compensation update exists at all. Applied in §16.
  • MM5 — A packed format is a contract, not an implementation detail. Predicts: matching a reference byte layout exactly (gguf's Q4_0/Q4_K) is what makes ecosystem interop possible at all. Bug class without it: "optimizing" a packed layout in a way that silently breaks every downstream reader. Applied in §11.6, P11.
  • MM6 — Calibration is measurement, and measurement needs provenance. Predicts: an accuracy number without a recorded corpus+seed is an anecdote, not a number. Bug class without it: comparing two quantized models whose calibration provenance silently differs and drawing a false conclusion about which method is better. Applied in §13, I5, I9.
  • MM7 — Fusion is what makes a bandwidth reduction real. Predicts: quantizing without fusing dequant into the matmul just relocates the bandwidth cost, it does not remove it. Bug class without it: shipping a "quantized" model that materializes a dequantized fp16 tensor and measures zero speedup, then blaming the quantization scheme. Applied in §21, P6.
  • MM8 — Every scheme is a point on a Pareto frontier, not a strictly-better replacement. Predicts: INT4 is not "better" than INT8 — it is a different, deliberate trade. Bug class without it: assuming a lower bit width is a free lunch and shipping it without checking its accuracy budget (§4). Applied in §4, §32.

32. Back-of-Envelope Capacity Model

Every number below is derived from the §4 System Constraints table.

  1. fp16 checkpoint size, 70B model. 70×10⁹ params × 2 bytes = 140 GB (§4 basis for the size-reduction rows).
  2. INT8 weight-only size, 70B. 70×10⁹ × 1 byte = 70 GB → 50% of (1), matching the ≥48% §4 row.
  3. INT4 (Q4_K, group-128) size, 70B. Effective 4.5 bits/weight (§11.6: 144 B / 256 weights × 8 = 4.5 bits) → 70×10⁹ × 4.5 / 8 = 39.375 GB → 28.1% of (1), a 71.9% reduction — exceeds the §4 ≥ 68% floor.
  4. KV-cache size, 70B, context 4096, batch 1, fp16. 2 (K,V) × 80 layers × 8192 hidden × 4096 tokens × 2 bytes = 10,737,418,240 B ≈ 10 GB.
  5. Total resident memory, INT4 70B inference. (3) + (4) = 39.375 + 10 ≈ 49.4 GB — fits a single 80 GB H100 with headroom, confirming the §1 deployability claim.
  6. Bandwidth-bound INT4 decode throughput, H100 (3.35 TB/s HBM3). Every autoregressive step reads the full weight set once: 3.35×10¹² B/s ÷ 39.375×10⁹ B ≈ 85 tokens/s ceiling.
  7. Bandwidth-bound fp16 decode throughput, same host. 3.35×10¹² ÷ 140×10⁹ ≈ 24 tokens/s.
  8. Derived INT4-vs-fp16 decode speedup. 85 / 24 ≈ 3.5× — inside the §4 2.5×–3.8× M2 target range, self-consistent with the measured-target derivation.
  9. GPTQ Hessian memory, 70B (hidden=8192). 8192² × 8 bytes = 536,870,912 B ≈ 512 MB per layer (fp64, I10) — well under the §4 < 2 GB per-layer ceiling even at 70B scale.
  10. GPTQ total quantize wall-clock, 70B (80 layers, sequential). 80 layers × 60 s/layer (M7) = 4,800 s ≈ 80 min — parallelizable across layers (§29) to reduce further, and well inside the §4 ≤ 2 h RTO budget even run sequentially.
  11. Calibration corpus raw size. 128 sequences × 2048 tokens × 4 bytes/token-id ≈ 1 MB — negligible relative to any checkpoint size.
  12. Storage amplification at small scale (GPT-2 124M, INT4 g128). Fixed per-tensor descriptor overhead (~64 B/tensor × ~150 tensors ≈ 9.6 KB) is a measurable fraction of a ~70 MB quantized 124M checkpoint (≈ 0.01%, negligible) but the TLV metadata block (~2–4 KB fixed cost) is proportionally larger at 124M than at 70B — the basis for the §4 storage-amplification row's 1.28×–1.35× figure applying mainly to small dev-loop models.

34. Alternative Architectures (Roads Not Taken)

Alt 1 — Fully dynamic (runtime-computed) quantization, no offline PTQ/QAT step.

input batch --> [compute scale per-batch, on the fly] --> INT8 matmul --> output
                        (no Q-file, no calibration corpus)

Regime where it wins: rapidly-changing weights (online/continual learning) or no representative calibration corpus exists at all. Real system: PyTorch's torch.quantization.quantize_dynamic, which computes activation scales per forward call. Rejected because per-batch scale computation adds real-time overhead incompatible with the < 5 ms kernel-launch budget (M3) and forfeits calibration reproducibility (P9) entirely — there is no Q-file to record provenance in.

Alt 2 — Sparse + ultra-low-bit hybrid (extract salient weights to an fp16 sparse side- tensor, quantize the rest at 2–3 bits).

weight --> [split: salient (sparse, fp16)] --> add
       \-> [bulk (dense, 2-3 bit)]        --/

Regime where it wins: extreme compression targets (< 3.5 bits/weight average) where a small sparse side-channel absorbs the highest-sensitivity weights. Real system: SpQR (Dettmers et al. 2023) and SqueezeLLM (Kim et al. 2023). Rejected as the Phase-4 default because sparse- tensor GEMM kernels are a separate, less mature kernel-engineering problem than the dense INT4 GEMM this system's ADR-14/CUTLASS investment assumes, and the accuracy gain over GPTQ/AWQ at this system's 4-bit target (§4) is marginal — documented as a deferred first-class scheme (PhaseDeferred("§15"), Deferred Features Register).

Alt 3 — Neural-architecture co-design (train the model to be quantization-native from scratch, e.g. ternary weights).

pretrain(architecture co-designed for {-1,0,+1} weights) --> ternary model, no PTQ/QAT needed

Regime where it wins: greenfield pretraining where architecture and numerics are co-designed from step zero, reaching 1–2 bit weights with no retrofit. Real system: BitNet (ternary-weight transformers) and the earlier Binarized Neural Networks line (Courbariaux et al.). Rejected outright — this system is explicitly a post-hoc toolchain for existing fp16/bf16 checkpoints (§1 scope); co-design requires owning the pretraining loop, abandoning the entire existing library of checkpoints this project targets.

36. Glossary

Affine quantization — mapping q = round(r/s)+z between real and integer domains. Scale (s) — the real-valued step size per quantization level. Zero-point (z) — the integer offset making an asymmetric range's zero representable exactly. Symmetric quantization — z=0; range mirrored around zero. Asymmetric quantization — z≠0; recovers dynamic range for non-zero-mean distributions. Per-tensor quantization — one (s,z) for an entire tensor. Per-channel quantization — one (s,z) per output channel. Per-group quantization — one (s,z) per contiguous run of group_size elements. Group size — the element count sharing one scale in per-group quantization (32/64/128/256 here). PTQ (post-training quantization) — quantizing a trained model with no gradient step. QAT (quantization-aware training) — fine-tuning with a fake-quantize op in the forward pass. Straight-through estimator (STE) — approximates round()'s gradient as identity inside the clip range. LSQ (Learned Step-Size Quantization) — makes the scale a trainable parameter with a normalized gradient. Calibration — the process of observing a corpus to derive scales/zero-points. Calibration corpus — the fixed dataset (here: 128×2048-token C4 sequences) used for calibration. Min-max calibration — scale derived directly from observed abs_max. Percentile calibration — scale derived from a clipped percentile of observed values. MSE calibration — scale chosen to minimize L2 reconstruction error. Entropy calibration — scale chosen to minimize KL-divergence between original/quantized histograms. GPTQ — Hessian-aware, Cholesky-cached PTQ method (Frantar et al. 2023). Hessian — here, 2X^TX/N, the second-order term of the layer-wise reconstruction objective. Optimal Brain Quantization (OBQ) — the column-wise quantize-then-compensate algorithm GPTQ generalizes. Cholesky decomposition — the matrix factorization used to cache the Hessian inverse efficiently. Damping — regularizing the Hessian diagonal to keep Cholesky numerically stable. Act-order — GPTQ's column-processing-order permutation by descending Hessian diagonal. AWQ — activation-aware weight quantization (Lin et al. 2024). Activation salience — the degree to which a weight channel's error matters, driven by its corresponding activation magnitude. Scale folding — absorbing a per-channel scale into a preceding layer's parameters at zero runtime cost. SmoothQuant — outlier migration from activations to weights via a per-channel rescale (Xiao et al. 2023). Outlier migration — SmoothQuant's exact rebalancing transform. LLM.int8() — outlier-column decomposition into an INT8 bulk path + fp16 side path (Dettmers et al. 2022). Outlier decomposition — LLM.int8()'s runtime split. NF4 — the QLoRA 16-level quantile-based non-uniform 4-bit grid. Double quantization — quantizing the per-group scales themselves (to FP8) for additional storage savings. FP8 — 8-bit floating point; E4M3 (4-bit exponent, 3-bit mantissa, weights/activations) and E5M2 (5-bit exponent, 2-bit mantissa, gradients). Mixed precision — a per-layer assignment of different schemes across one model. Q-file — this system's gguf-compatible on-disk quantized-model artifact. GGUF — the llama.cpp container format this system's Q-file extends. Block layout — a fixed-size struct packing N weights + their scale/zero-point (BlockQ4_0/Q4_K/Q8_0). TLV (Type-Length-Value) — the forward-compatible metadata-extension encoding used for calibration provenance. Perplexity — exp(mean cross-entropy), this system's primary accuracy metric. Dequantization — the inverse affine map, r_hat = s(q-z). Fused kernel — a kernel that dequantizes in-register during the matmul, never materializing an intermediate dequantized tensor. Accumulator — the dtype a matmul's partial sums are held in (mandated fp32 here, I3). Round-to-nearest-even — the IEEE-754 default rounding mode used throughout. RTN (round-to-nearest quantization) — plain per-column/group rounding with no error compensation (GPTQ/AWQ's baseline comparator). Calibration provenance — the recorded (corpus hash, seed, scheme) tuple proving a Q-file's reproducibility lineage. Outlier threshold — the per-channel activation-magnitude cutoff selecting LLM.int8()'s outlier columns. Bits per weight — the effective average storage cost per weight including scale/zero-point overhead. Storage amplification — the ratio of actual Q-file size to the theoretical bit-packed minimum.
