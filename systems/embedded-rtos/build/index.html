⬜ Phase 0 — Bootstrap, Toolchain & Correctness Kernel §12

Objectives

Stand up the workspace, the reset-to-main path, the linker/memory map, and a minimal correctness kernel that boots to an idle task in QEMU and on STM32F4. Establish the unsafe allowlist (P4), CI, and the conformance harness so every later phase has a gate. Constraint: boot to first instruction of the idle task ≤ 5 ms (M11).

Deliverable

An ELF that boots in QEMU (make qemu) and on STM32F4 (make flash), reaching the idle task and emitting one RTT trace line; make ci runs clippy + the boot fixture green.

Acceptance

Boot-to-idle ≤ 5 ms measured via DWT cycle counter (M11); .text for the empty kernel ≤ 6 KB; conformance/boot/qemu_boot.yaml passes (RTT emits BOOT_OK); CI unsafe-grep reports unsafe only inside rtos_arch/rtos_boot (P4); zero clippy warnings at -D warnings.

Fixtures
Fixture Purpose Expected output
conformance/boot/qemu_boot.yaml boots mps2-an385 to idle RTT line BOOT_OK, exit 0
conformance/boot/vector_align.yaml vector table 128-byte aligned, VTOR set read-back VTOR == table base
conformance/boot/bss_data_init.yaml .bss zeroed, .data copied (malformed image → fault) checksum match; corrupt image → BOOT_FAIL
conformance/boot/pendsv_prio.yaml (regression) PendSV is lowest priority (I13) SHPR read-back == 0xFF band
Pitfalls

Vector-table misalignment (VTOR requires alignment) → hard fault on first IRQ; debug via SCB dump. .data/.bss init order wrong → garbage statics; signal is nonzero .bss at first read. PendSV not lowest priority (I13) → switch preempts an ISR mid-frame → corrupted stack. Clock misconfig → wrong SysTick reload → all later timing off. Recursive panic in the panic handler → stack blow; guard with a re-entry flag (ADR-18).

⬜ Phase 1 — Context Switching (PendSV/SVC) §13

Objectives

Implement the arch-specific context switch: manufacture task stack frames, save/restore R4–R11 + PSP + FP lazy frame in PendSV (I4, per Yiu §5), start the first task via SVC, and support cooperative yield. Constraint: switch ≤ 200 cycles ≈ 1.2 µs (M2).

Deliverable

Two tasks cooperatively yielding back and forth in QEMU and on-target, verified by trace order; bench_ctx_switch reports cycle count.

Acceptance

Context switch ≤ 200 cycles no-FP, ≤ 300 cycles with FP frame, measured by DWT (M2); conformance/context/basic_switch.yaml shows exact A→B→A trace order; register checksum intact across 10^6 switches (I4); FP task preserves S16–S31 across a switch.

Fixtures
Fixture Purpose Expected output
conformance/context/basic_switch.yaml A/B cooperative yield trace SW A→B, SW B→A repeating
conformance/context/fp_preserve.yaml FP regs survive switch (I4) S16–S31 checksum stable
conformance/context/stack_seed.yaml synthetic frame resumes at entry task hits entry, xPSR Thumb set
conformance/context/exit_trampoline.yaml (malformed) task returns off its entry fn traps to TASK_EXIT, not UB
conformance/context/switch_stress.yaml (regression) 10^6 switches, checksum zero I4 violations
Pitfalls

Forgetting R4–R11 (compiler-clobbered across the switch) → silent register corruption (I4); signal is a wrong value in a callee-save reg after resume. Wrong EXC_RETURN (MSP vs PSP, FP bit) → wrong stack or fault. FP lazy stacking not accounted → S-regs corrupted only when a switch lands between FP use and spill. Seeding xPSR without the Thumb bit → usage fault. Task fn returning (no trampoline) → PC to garbage; the exit trampoline (13.5) is mandatory.

⬜ Phase 2 — Fixed-Priority Preemptive Scheduler §14

Objectives

Build the O(1) bitmap ready list, the scheduler decision point (I2, I3, P11, P13), preemption on wake, an idle task, optional round-robin within equal priority (ADR-24), and runtime accounting. Constraint: select_next ≤ 20 cycles (M3); scheduler overhead ≤ 3% CPU at 1 kHz tick (M7-adjacent).

Deliverable

Three tasks at distinct priorities where the highest always runs and preemption is observable in the trace; a round-robin demo of two equal-priority tasks alternating each quantum.

Acceptance

select_next ≤ 20 cycles (M3, DWT); scheduler CPU overhead ≤ 3% at 1 kHz (M7-adjacent); zero I2 violations over conformance/scheduler/preemption.yaml (highest-prio-ready always running at each decision point); round-robin fixture shows equal quanta ± 1 tick; no lost wakeup over 10^6 randomized events (I12).

Fixtures
Fixture Purpose Expected output
conformance/scheduler/preemption.yaml high-prio preempts low trace: high runs immediately on wake
conformance/scheduler/round_robin.yaml equal-prio quantum share alternating trace, ±1 tick
conformance/scheduler/bitmap_clz.yaml I3 bitmap↔list consistency assert holds, ≤20 cyc
conformance/scheduler/lost_wakeup.yaml (regression) 10^6 random wake/block zero I12 violations
conformance/scheduler/idle_only.yaml (edge) all tasks blocked idle runs, WFI entered
Pitfalls

Lost wakeup: signaling before the waiter is on the wait list → the classic race; root cause is a non-atomic check-then-block; fix with the basepri critical section around block+condition (I6, I12). Priority inversion appears here without a protocol (deferred to Phase 5, P6). Bitmap desync with lists (I3) if push/pop don't update both atomically. Idle task at wrong priority starves nothing but hides bugs. Tick reentrancy if SysTick > PendSV priority (it must be, but PendSV lowest, I13).

⬜ Phase 3 — Memory Management & Stack Protection §15

Objectives

Provide static allocation, fixed-block pools (I15), optional TLSF heap (ADR-06), and MPU-backed stack-overflow detection with canaries (I7, P9). Constraint: pool alloc/free O(1) ≤ 200 ns; kernel static RAM ≤ 4 KB (M10); stack overflow trapped at the guard, never silently.

Deliverable

Pools and (optional) TLSF usable by IPC/sync; a deliberate stack overflow traps to the MPU fault handler with a forensic dump instead of corrupting a neighbor.

Acceptance

Pool alloc/free ≤ 200 ns and O(1) (DWT); TLSF alloc worst-case ≤ 1 µs bounded; kernel static RAM ≤ 4 KB (M10, .map inspection); conformance/memory/stack_overflow.yaml traps at the MPU guard (I7) 100/100 runs; zero cross-pool frees over the pool fuzz target (I15).

Fixtures
Fixture Purpose Expected output
conformance/memory/pool_exhaustion.yaml pool OOM returns error Err(PoolExhausted), no panic
conformance/memory/stack_overflow.yaml MPU guard traps overflow (I7) MemManage fault, forensic dump
conformance/memory/bad_free.yaml (malformed) free wrong-pool block (I15) Err(BadFree), block header flagged
conformance/memory/tlsf_bound.yaml TLSF worst-case latency ≤ 1 µs across fragmentation set
conformance/memory/canary_scan.yaml (regression) canary detects slow overflow canary word mismatch → trap
Pitfalls

MPU region granularity/alignment (ARMv7-M requires power-of-two, aligned regions) → guard misplaced, overflow undetected; debug via MPU_RBAR/RASR read-back. Canary-only checking misses a jump past the canary — MPU guard is the real defense (P9). Fragmentation in a general heap makes latency unbounded (why default is pools, P5). Freeing to the wrong pool corrupts the free list (I15). CCM RAM not DMA-accessible — place DMA buffers in main SRAM (§19).

⬜ Phase 4 — Interrupt Management & Deferred Handling §16

Objectives

Build NVIC abstraction, ISR registration, nested-interrupt support (I5), the top-half/bottom-half deferred-ISR queue (P3, per Bovet&Cesati Ch.4), interrupt-latency accounting, and IRQ-storm detection. Constraint: ISR entry latency 12 cycles arch (M1); deferred wake p99 ≤ 3 µs (M4).

Deliverable

A UART RX interrupt whose byte is captured in the ISR and processed in a task; a demonstrated IRQ storm that is detected and rate-limited rather than starving the system.

Acceptance

ISR-to-first-instruction ≤ 12 cycles (M1, DWT); deferred wake latency p99 ≤ 3 µs (M4); conformance/interrupts/nested_irq.yaml shows correct nesting to depth ≤ 3 (I5); storm fixture masks the source within 100 µs and emits IRQ_STORM; zero data loss for ≤ 64 queued deferred events.

Fixtures
Fixture Purpose Expected output
conformance/interrupts/nested_irq.yaml nesting correctness (I5) depth ≤3, correct return order
conformance/interrupts/deferred_wake.yaml top/bottom-half latency (M4) p99 ≤ 3 µs
conformance/interrupts/irq_storm.yaml storm detection (T3) source masked, IRQ_STORM logged
conformance/interrupts/queue_overflow.yaml (malformed) deferred queue full drop + irq.deferred_drops++
conformance/interrupts/fault_dump.yaml (regression) fault handler dump CFSR/BFAR emitted, reset
Pitfalls

Doing heavy work in an ISR (violates P3) → long interrupt-off, jitter (M8); signal is irq.max_off_cycles spikes. Calling a blocking kernel API from an ISR → deadlock/UB; API has ISR-safe variants only. Priority grouping misconfig → basepri masks the wrong band (P12). Reentrant ISR corrupting shared state without nesting accounting (I5). Real incident to study: the Therac-25 class of concurrent-ISR race — mitigated here by the top/bottom-half split (P3) and ISR-safe API separation.

⬜ Phase 5 — Synchronization & IPC §17

Objectives

Implement counting/binary semaphores, priority-inheritance mutexes (I8, ADR-14, Sha et al. 1990), event-flag groups, bounded copy queues (I11), mailboxes, stream buffers, timeouts, and deadlock detection. Constraint: mutex lock/unlock uncontended ≤ 300 ns (M5); queue send/recv ≤ 500 ns (M6); priority-inversion blocking bounded to one critical section (per Baker SRP, §32).

Deliverable

Producer/consumer over a bounded queue with correct blocking; a demonstrated priority-inversion scenario where inheritance keeps the high-priority task's blocking bounded (contrast: without it, unbounded).

Acceptance

Mutex lock/unlock ≤ 300 ns (M5); queue send/recv ≤ 500 ns for ≤ 32 B (M6); inheritance test shows high-priority blocking ≤ one critical-section length (I8, §32); conformance/ipc/queue_blocking.yaml correct blocking/wakeup; deadlock fixture detected in debug build; zero lost signals over 10^6 randomized give/take (I12).

Fixtures
Fixture Purpose Expected output
conformance/ipc/queue_blocking.yaml block on empty/full, wake on ready correct order, no lost signal
conformance/ipc/priority_inherit.yaml inversion bounded (I8) high-prio blocking ≤ 1 CS
conformance/ipc/ceiling_protocol.yaml ceiling mode single-block (ADR-14) one blocking term
conformance/ipc/deadlock_detect.yaml (malformed) cyclic lock order detector flags cycle
conformance/ipc/timeout_race.yaml (regression) timeout vs signal race exactly one outcome, no double-wake
Pitfalls

Priority inversion without a protocol → unbounded blocking (the Mars Pathfinder 1997 incident: a low-priority task held a mutex the high-priority bus task needed; the fix was enabling priority inheritance — exactly I8/ADR-14, Sha 1990). Nested inheritance chains must propagate transitively. Lost wakeup from non-atomic check-then-block (I12, P12). Queue copy of non-Copy/aliased data — the type system forbids it (ADR-15). Timeout racing a signal → double-wake without I12 discipline.

⬜ Phase 6 — Timers, Tick & Tickless Idle §18

Objectives

Implement the SysTick tick (I10), the sorted delayed/wake list (I14), software timers (one-shot/periodic), delay/delay_until, and tickless idle for low power (per Kopetz sparse-time, RIOT tickless). Constraint: tick cost ≤ 2% CPU at 1 kHz (M7); periodic release jitter ≤ 20 µs p99 (M8); tickless drift ≤ 2 ticks/hour (M12).

Deliverable

Periodic tasks releasing on schedule with measured jitter; a tickless-idle demo cutting idle CPU wakeups while preserving tick accounting.

Acceptance

Tick cost ≤ 2% CPU at 1 kHz (M7); periodic jitter ≤ 20 µs p99 (M8); tickless drift ≤ 2 ticks/hour (M12); conformance/time/jitter.yaml within bound; monotonic counter never regresses across 10^6 ticks (I10); delay_until shows zero cumulative drift over 1 h.

Fixtures
Fixture Purpose Expected output
conformance/time/jitter.yaml periodic release jitter (M8) p99 ≤ 20 µs
conformance/time/delay_until_drift.yaml absolute vs relative delay (P7) zero cumulative drift
conformance/time/tickless_recon.yaml tick counter after tickless (I10) counter == elapsed, drift ≤ 2/h
conformance/time/timer_overflow.yaml (malformed) 64-bit tick near wrap no wrap in device lifetime
conformance/time/soft_timer_order.yaml (regression) many timers same tick fire in insertion order
Pitfalls

Relative delay(n) accumulates drift (jitter of the wake path adds each period) — use delay_until absolute (P7). Tickless reconciliation off-by-one loses/gains a tick (I10). A software timer callback that blocks stalls all timers — callbacks must be bounded (P2). SysTick reload wrong after clock change (Phase 0). 32-bit tick wraps in ~49 days at 1 kHz — use 64-bit (I10). Waking too early wastes power; too late misses deadline (M12).

⬜ Phase 7 — HAL, Drivers & BSP §19

Objectives

Provide embedded-hal trait implementations (ADR-20, per Zephyr device model), interrupt-safe GPIO/UART/ SPI/I2C/timer drivers, DMA support, power-management hooks, and BSP integration for STM32F4 + QEMU (ADR-17). Constraint: driver call overhead ≤ 200 ns above raw MMIO; UART echo round-trip verified; DMA transfers race-free.

Deliverable

UART echo, GPIO blink, and an SPI/I2C sensor read working on QEMU (where modeled) and STM32F4 hardware, plus a DMA UART transfer.

Acceptance

Driver overhead ≤ 200 ns over raw MMIO (DWT); conformance/hal/uart_echo.yaml round-trips bytes with zero loss at 115200 baud; DMA transfer completes with correct data and no race over 10^4 iterations; blink timing within ± 1 tick.

Fixtures
Fixture Purpose Expected output
conformance/hal/uart_echo.yaml UART RX→TX correctness echoed bytes match, zero loss
conformance/hal/dma_transfer.yaml DMA race-freedom data correct, 10^4 iters clean
conformance/hal/gpio_blink.yaml GPIO + timing toggles within ±1 tick
conformance/hal/mmio_order.yaml (malformed) reordered MMIO writes fence enforces order
conformance/hal/sensor_read.yaml (regression) SPI/I2C sensor expected register values
Pitfalls

MMIO reordering by the compiler/CPU → wrong peripheral state; use volatile + compiler_fence (P4). DMA buffer aliased with CPU access → torn data; type-state transfers ownership. Placing a DMA buffer in CCM (not DMA-reachable) → silent no-transfer (§15.6). Peripheral clock not enabled before register access → bus fault. Interrupt-priority conflict between driver IRQ and kernel basepri band (P12).

⬜ Phase 8 — Tracing, Diagnostics & Observability §20

Objectives

Build the lock-free trace pipeline (P8), scheduler/IPC/ISR trace events, runtime statistics, stack high-water tracking, crash/fault dumps, latency histograms, and the CLI diagnostic shell. Constraint: trace overhead ≤ 1% CPU at nominal event rate; trace must not reorder or perturb kernel timing (P8).

Deliverable

A live trace in SystemView showing task switches, ISRs, and IPC; the CLI reporting per-task CPU% and stack high-water; a fault producing a decodable dump.

Acceptance

Trace overhead ≤ 1% CPU at 10k events/s (M7-adjacent, DWT); zero event reordering over conformance/trace/event_order.yaml; overflow drops counted, never blocks (P8); fault dump decodes to the faulting PC/line via defmt; CLI top matches runtime_cycles within 1%.

Fixtures
Fixture Purpose Expected output
conformance/trace/event_order.yaml deterministic ordering (P8) events in causal order
conformance/trace/overflow.yaml (malformed) ring full drop + trace.drops++, no block
conformance/trace/overhead.yaml perturbation bound ≤ 1% CPU at 10k ev/s
conformance/trace/fault_decode.yaml (regression) fault dump decodes PC→source line correct
conformance/trace/stats_accuracy.yaml CPU% accuracy within 1% of runtime_cycles
Pitfalls

A trace path that takes a lock perturbs timing (P8) — must be lock-free SPSC. Formatting in the hot path (use deferred defmt, ADR-09). Recursive panic while logging a panic (re-entry guard, §12.6). Ring overflow blocking the producer → priority inversion via tracing — always drop, never block. Timestamp source drift (use DWT cycle counter, monotonic). Trace changing cache behavior enough to hide a bug.

⬜ Phase 9 — Schedulability Analysis & Conformance Certification §21

Objectives

Ship the offline schedulability toolchain — RMS utilization bound (Liu&Layland 1973), exact response-time analysis (Audsley 1993, Lehoczky 1989), and blocking-term computation (Sha 1990, Baker 1991) — plus the conformance suite and a certification report. This is where the "analyzable timing" property (§4) becomes a decision. Constraint: rta_check verdict matches on-target measured worst case within 10%.

Deliverable

rta_check producing a schedulability verdict for an example control task set; a certification report (docs/performance/schedulability.md) tying measured WCET to the analysis; the full conformance suite green.

Acceptance

rta_check verdict matches on-target measured worst-case response within 10% on the example set; utilization-bound and exact-RTA tests agree with hand computation on conformance/sched_analysis/ fixtures; a deliberately over-subscribed set (U > 1) is reported unschedulable with the failing task named; 100% of prior-phase conformance fixtures pass in CI.

Fixtures
Fixture Purpose Expected output
conformance/sched_analysis/rms_bound.yaml L&L bound (Liu&Layland) schedulable iff U ≤ bound
conformance/sched_analysis/rta_exact.yaml exact RTA (Audsley) R_i matches hand calc
conformance/sched_analysis/blocking_term.yaml PIP/PCP blocking (Sha/Baker, I8) B_i correct
conformance/sched_analysis/oversubscribed.yaml (malformed) U > 1 set unschedulable, task named
conformance/sched_analysis/measured_vs_predicted.yaml (regression) model vs silicon within 10%
Pitfalls

Using average WCET instead of worst-case → optimistic verdict, real deadline miss (P1). Ignoring the blocking term B_i → the priority-inversion class re-appears (P6, §17). RTA fixed-point not converging (set unschedulable if R_i > T_i). Jitter/release delay omitted from the model (add it, §18). Measured WCET on a too-short run misses the true worst case — run the worst-case path deliberately. Cache/flash-wait effects absent on M4 (no data cache) simplify but flash prefetch still varies.
