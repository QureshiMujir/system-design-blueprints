30. Mental Models & First Principles

  • MM1 — A context switch is a manufactured exception return. Insight: you don't "jump" to a task; you build the exact stack frame the CPU's exception-return hardware expects, then let bx EXC_RETURN resume it. Predicts: seeding xPSR/PC/LR correctly is the whole game. Bug class without it: garbage PC on first run of a task. Resolves in §13 (Phase 1).
  • MM2 — The scheduler is a clock's consumer, not its source. Insight: SysTick is the heartbeat; the scheduler only reacts at decision points. Predicts: jitter is bounded by tick granularity + interrupt-off time. Bug class: busy-wait "scheduling" that drifts (P7). Resolves in §14, §18.
  • MM3 — Worst case is the only case that schedules. Insight: hard real-time is decided by WCET and the blocking term, not averages (Liu&Layland; Audsley). Predicts: a set with U ≤ bound can still miss if B_i is ignored. Bug class: "it works on my bench" deadline misses (P1). Resolves in §21, §32.
  • MM4 — Priority inheritance turns unbounded blocking into one critical section. Insight: donating priority prevents a mid-priority task from indefinitely delaying the holder (Sha 1990). Predicts: with inheritance, B_i ≤ longest CS of a lower task. Bug class: the Pathfinder inversion (§17.6). Resolves in §17 (I8, ADR-14).
  • MM5 — An ISR is a thief of time; make the theft O(1). Insight: every cycle in an ISR is stolen from every lower-priority task; defer everything possible (P3). Predicts: heavy ISRs blow jitter (M8). Bug class: dropped high-rate IRQs behind a slow one. Resolves in §16.
  • MM6 — basepri masks by priority; PRIMASK is a sledgehammer. Insight: a real-time kernel masks a band so zero-latency IRQs still fire (P12). Predicts: using PRIMASK for kernel CS raises worst-case IRQ latency for everyone. Bug class: a critical safety IRQ delayed by an unrelated kernel op. Resolves in §13, §16 (I6).
  • MM7 — Fault isolation without an MMU is spatial, via the MPU. Insight: on an MCU you can't page, but you can trap the instant a task touches memory it shouldn't (Tock, seL4 spirit). Predicts: a guard region catches overflow at the boundary, not after corruption (P9). Bug class: silent neighbor-stack corruption. Resolves in §15 (I7).
  • MM8 — Observability must be O(1) and lock-free or it lies. Insight: any trace that blocks or locks changes the timing it reports (P8). Predicts: a locking tracer creates priority inversion in itself. Bug class: Heisenbugs that vanish when tracing is off. Resolves in §20.

Required reading (§5)

Books

  • Buttazzo, Hard Real-Time Computing Systems (3rd ed., 2011) — Ch. 4 (periodic task scheduling: RM/EDF), Ch. 7 (resource access: PIP/PCP/SRP), Ch. 6 (fixed-priority servers). Extract: utilization bounds, blocking-term computation. Applied in §21, §32, §33.
  • Yiu, The Definitive Guide to ARM Cortex-M3/M4 Processors (3rd ed.) — exception model, NVIC, PendSV/SVC, SysTick, MPU, FP lazy stacking chapters. Extract: exception-frame layout, priority grouping. Applied in §13 (Phase 1), §16 (Phase 4), §15 (Phase 3).
  • Kopetz, Real-Time Systems: Design Principles for Distributed Embedded Applications (2nd ed.) — Ch. on temporal firewalls, jitter, sparse time. Extract: time-triggered vs event-triggered. Applied in §6 (P1, P7), §18 (Phase 6).
  • Arpaci-Dusseau, Operating Systems: Three Easy Pieces (2018) — scheduling, locks, condition-variable chapters. Extract: dispatch, sleeping-lock discipline. Applied in §14 (Phase 2), §17 (Phase 5).
  • Bovet & Cesati, Understanding the Linux Kernel (3rd ed.) — Ch. 4 (interrupts/softirqs), Ch. 7 (scheduling). Extract: top-half/bottom-half split. Applied in §16 (Phase 4, P3).
  • Klabnik & Nichols, The Rust Programming Language + Blandy et al., Programming Rust (2nd ed.) — ownership, unsafe, Send/Sync, FFI. Extract: interior mutability discipline for kernels. Applied in §11, §13 (Phase 1, P4).
  • Mahmoud (Ferrous), Rust Atomics and Locks — Mara Bos (2023) — atomics, ordering, SeqCst/Acquire/Release, building locks. Extract: memory ordering for lock-free rings. Applied in §17 (Phase 5), §20 (Phase 8, trace ring).

Papers

  • Liu & Layland, "Scheduling Algorithms for Multiprogramming in a Hard-Real-Time Environment," JACM 20(1), 1973 — RMS optimality, the U ≤ n(2^(1/n)−1) bound, EDF U ≤ 1. Applied in §21 (Phase 9), §32, §33.
  • Sha, Rajkumar, Lehoczky, "Priority Inheritance Protocols: An Approach to Real-Time Synchronization," IEEE Trans. Computers 39(9), 1990 — PIP and priority-ceiling protocol, bounded blocking. Applied in §17 (Phase 5, I8, ADR-14), §22.
  • Audsley, Burns, Richardson, Tindell, Wellings, "Applying New Scheduling Theory to Static Priority Pre-emptive Scheduling," Software Eng. Journal 8(5), 1993 — exact response-time analysis (RTA). Applied in §21 (Phase 9), §32.
  • Baker, "A Stack-Based Resource Allocation Policy for Realtime Processes," Real-Time Systems 3(1), 1991 — Stack Resource Policy (SRP), single-blocking bound. Applied in §17 (Phase 5), §34.
  • Lehoczky, Sha, Ding, "The Rate Monotonic Scheduling Algorithm: Exact Characterization and Average Case Behavior," RTSS 1989 — the exact schedulability test beyond the L&L bound. Applied in §21 (Phase 9), §32.
  • Klein et al., "seL4: Formal Verification of an OS Kernel," SOSP 2009 — machine-checked functional correctness of a microkernel. Applied in §26, §30 (MM7), §34.
  • Levy et al., "Multiprogramming a 64 kB Computer Safely and Efficiently" (Tock OS), SOSP 2017 — a Rust embedded kernel: capsules, grants, fault isolation without an MMU. Applied in §9 (ADR-01), §34.
  • Locke, "Best-Effort Decision Making for Real-Time Scheduling," CMU PhD, 1986 — overload and value-based scheduling. Applied in §29, §34 (EDF/overload).
  • Davis & Burns, "A Survey of Hard Real-Time Scheduling for Multiprocessor Systems," ACM Computing Surveys 43(4), 2011 — partitioned vs global scheduling. Applied in §29, §35 (SMP defer).

Reference Implementations

  • FreeRTOS-Kernel — tasks.c (ready-list pxReadyTasksLists, vTaskSwitchContext), queue.c (copy-queue + waiter lists), portable/GCC/ARM_CM4F/port.c (xPortPendSVHandler). Lesson: O(1) bitmap ready list + PendSV switch. Pitfall not to copy: configASSERT-only stack checking (weak); we add MPU guards (P9). Studied for §14 (Phase 2), §13 (Phase 1).
  • Zephyr RTOS — kernel/sched.c, arch/arm/core/, device model drivers/. Lesson: _kernel.ready_q bitmap, portable driver model. Pitfall: Kconfig combinatorial config surface — we prefer typed compile-time config (ADR-24). Studied for §19 (Phase 7, ADR-20).
  • Azure RTOS ThreadX — preemption-threshold scheduling, event-chaining. Lesson: preemption-threshold to cut context-switch churn. Pitfall: closed conformance suite — we build an open one (§26). Studied for §14 (Phase 2), §31.
  • Micrium µC/OS-III — os_task.c, os_q.c. Lesson: documented priority-inheritance mutex and per-object wait lists. Pitfall: legacy priority-per-task uniqueness constraints — we allow equal priorities (round-robin, ADR-24). Studied for §17 (Phase 5, ADR-14).
  • Tock OS — kernel/src/sched/, arch/cortex-m/. Lesson: Rust #![no_std] kernel, MPU grants, capsule fault isolation. Pitfall: cooperative userland unsuitable for hard deadlines — we keep preemptive tasks (P1). Studied for §9 (ADR-01), §15 (Phase 3), §34.
  • RIOT OS — core/ scheduler, sys/. Lesson: minimal footprint, tickless. Pitfall: dynamic thread creation defaults — we default to static (P5). Studied for §18 (Phase 6, ADR-06).
