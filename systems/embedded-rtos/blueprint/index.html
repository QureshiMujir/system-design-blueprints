186 — Embedded RTOS from Scratch

Project Number: 186

Project Name: Embedded RTOS from Scratch

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

Build a deterministic, fixed-priority preemptive real-time operating-system kernel for single-core ARM Cortex-M microcontrollers (reference part: STM32F407, Cortex-M4F @ 168 MHz, 192 KB SRAM, 1 MB flash), from the reset vector up, in Rust with a small audited unsafe core. The kernel provides tasks, a bitmap O(1) scheduler, PendSV/SVC context switching, counting/binary semaphores, priority-inheritance mutexes, bounded copy message queues, event flags, software timers, MPU-backed stack-overflow detection, tick and tickless idle, and a low-perturbation trace pipeline — with provable worst-case bounds validated by Rate-Monotonic and response-time schedulability tooling. The defining property is bounded, analyzable timing: every kernel operation on a hot path is O(1) or O(log n) with a stated cycle bound, so a task set's schedulability is decidable offline.

Phase-0 deliverable (numbered crates/modules):

  1. rtos_boot — reset handler, .data/.bss init, vector table, linker integration (memory.x).
  2. rtos_arch — Cortex-M port: PendSV/SVC handlers, register save/restore, MPU, basepri critical sections.
  3. rtos_kernel — TCB, task lifecycle, O(1) bitmap ready list, scheduler decision point.
  4. rtos_time — SysTick tick, monotonic tick counter, delayed/wake list, tickless idle.
  5. rtos_sync — semaphores, priority-inheritance mutexes, event flags, wait-list discipline.
  6. rtos_ipc — bounded copy message queues, mailboxes, stream buffers.
  7. rtos_mem — static allocator, fixed-block pools, optional TLSF heap, stack canaries.
  8. rtos_hal — embedded-hal GPIO/UART/timer traits, NVIC abstraction, deferred-ISR API.
  9. rtos_trace — trace ring, defmt/RTT sink, runtime statistics, scheduler diagnostics.
  10. rtos_bsp — STM32F4 + QEMU (mps2-an385, lm3s6965evb) board support, rtos_cli serial shell.

System boundaries. Provides: task scheduling, IPC, synchronization, timing, memory pools, ISR plumbing, trace. Delegates: peripheral electrical detail to the PAC/embedded-hal driver crates; C ABI shims to cortex-m intrinsics; flash programming to probe-rs. Does NOT provide (Phase-0): SMP/multicore, an MMU/virtual memory, a POSIX/userspace boundary, a networking stack, a filesystem, USB, dynamic module loading, or mixed-criticality partitioning.

Non-goals. General-purpose desktop OS features; hard isolation via privilege rings beyond MPU; a stable syscall ABI for third-party binaries; garbage collection; wall-clock/RTC-driven scheduling.

Deployment model. Statically linked single ELF flashed to on-chip flash; boots to the scheduler; no loader, no runtime linking. Ships as a library crate + BSP; the application is compiled with the kernel into one image.

Target users/operators. Firmware engineers building control loops, robotics/motor control, sensor fusion, and industrial controllers who need analyzable latency; the "operator" is a field engineer reading traces over RTT and a serial diagnostic shell.

What later phases unlock. Phase 5 unlocks bounded IPC; Phase 6 unlocks periodic control loops; Phase 7 unlocks portable drivers; Phase 8 unlocks production observability; Phase 9 unlocks offline schedulability certification. Deferred: MPU userspace isolation PhaseDeferred("§35"), SMP scheduling PhaseDeferred("§35"), networking PhaseDeferred("§35"), mixed-criticality PhaseDeferred("§35").

Recommended language: Rust (edition 2021, #![no_std], #![no_main]). Rationale: ownership eliminates the use-after-free and data-race classes that dominate kernel CVEs; the type system encodes send/interrupt-safety (Send/Sync) so a value shared with an ISR is a compile error unless proven safe; unsafe is a lexically bounded, greppable audit surface (context switch, MMIO, canaries, startup); no GC, no hidden allocation, deterministic drop; the embedded ecosystem (cortex-m, cortex-m-rt, embedded-hal, defmt, probe-rs) is mature. Rejected: C — no memory-safety net, informal aliasing rules, macro-driven config that defeats static analysis (still the incumbent, and the ABI we interop with); C++ — RTTI/ exceptions/std weight and template code-size blowup on tiny flash; Zig — safety story and tooling less mature for a certifiable kernel; Ada/SPARK — strongest verification story but a narrow toolchain/ecosystem for MCU hobby-to-industrial reach (revisited in §34).

Prerequisites. ARMv7-M exception model (NVIC, PendSV, SVC, SysTick, basepri/PRIMASK); linker scripts and memory maps; C ABI/AAPCS register conventions; fixed-priority scheduling theory (RMS/EDF); memory ordering and compiler_fence; GDB/OpenOCD/probe-rs debugging; Rust unsafe, #[naked], and interior mutability.

Timeline. Phase 0: 2–3 weeks. Phases 1–9 (full system): 8–14 months full-time. See §38.

2. Why Build This

  • Unique systems knowledge: the software/hardware seam at cycle granularity — how an exception-return frame is manufactured so a bx lr resumes a different task; why PendSV must be the lowest-priority exception; how basepri masks by priority without global IRQ lockout.
  • Analyzable timing: you internalize that "fast on average" is worthless for control — only the worst case schedules. RMS utilization bounds, response-time analysis, and priority-inversion blocking terms become working tools, not trivia.
  • Concurrency correctness under interrupts: the hardest concurrency model — preemption by asynchronous ISRs on a single core — trains you to reason about atomicity, reentrancy, and lock-free wakeups where a mutex is unavailable (you are the mutex).
  • Architectural/historical significance: RTOS design is the lineage of THE-system layering, Liu & Layland's 1973 scheduling result, the 1990 priority-inheritance protocols that fixed the Mars Pathfinder-class inversion bug, and seL4's proof that a microkernel can be verified.
  • Engineering muscles: linker/memory-map fluency; writing correct unsafe with a stated invariant per block; building observability that does not perturb the thing it measures; deriving numbers before writing code (§32).
  • Cross-links (sibling systems): Kernel from Scratch (dispatch, traps), Hypervisor (privilege transitions, trap-and-emulate), Toy Scheduler (dispatch policy), Embedded Database (flash-aware, bounded memory), Network Stack (interrupt-driven I/O, zero-copy buffers), Device-Driver Framework (MMIO, DMA), Robotics Runtime (deterministic control cadence).
  • Calibration value: after this, most systems software reads as "easier" — you have debugged a corrupted exception frame with only four LEDs and a cycle counter.

What Mastery Looks Like

  • Derive the RMS bound and a full response-time analysis for a task set and predict a missed deadline before flashing — cemented in §21 (Phase 9) and §32.
  • Hand-write and debug a PendSV context switch, including FP lazy stacking — cemented in §13 (Phase 1).
  • Choose and justify priority inheritance vs priority ceiling for a given blocking term — cemented in §17 (Phase 5).
  • Build an O(1) bitmap scheduler and prove its per-operation cycle bound — cemented in §14 (Phase 2).
  • Detect and localize a stack overflow from an MPU fault frame — cemented in §15 (Phase 3).
  • Configure tickless idle without losing tick accounting — cemented in §18 (Phase 6).
  • Instrument the kernel with a trace pipeline whose overhead is measured, not guessed — cemented in §20 (Phase 8).
  • Read a task set's schedulability as a decision, not a hope — cemented in §21 (Phase 9), §29, §33.

Application tasks — user code compiled with the kernel; call the API directly (no trap overhead) except where a privilege raise needs SVC. rtos_kernel — owns the TCB table, task state machine (§8), and the O(1) bitmap ready list; the sole authority on "who runs next" (I2, P11). rtos_sync — semaphores, priority-inheritance mutexes, event flags; manages per-object wait lists and inheritance chains (I8). rtos_ipc — bounded copy queues/mailboxes/stream buffers with an explicit backpressure policy (ADR-22). rtos_time — SysTick tick, monotonic tick counter (I10), the delayed/wake list (I14), and tickless idle. rtos_arch — the only architecture-specific crate: PendSV/SVC handlers, register save/restore (I4), MPU programming, and basepri critical sections (I6); all unsafe concentrates here (P4). rtos_hal/rtos_bsp — NVIC and peripheral abstractions plus the deferred-ISR queue (top-half/bottom-half, P3). rtos_trace — a lock-free trace ring drained to defmt/RTT or SEGGER SystemView, plus runtime stats; designed for bounded perturbation (P8). The critical-section boundary (basepri) and the arch/trust boundary (PendSV/SVC/MPU) are the two lines every later section stays consistent with.

6. Design Principles

  • P1 — Worst-case beats average. Rule: every hot-path operation carries a stated WCET bound; optimize the tail, not the mean. Tradeoff: gives up some average throughput. Operational: §28 gates on p99, not p50. Violation: a rare slow path blows a deadline and a motor overshoots.
  • P2 — Bound everything or defer it. Rule: no unbounded loop, list scan, or block on a hot path; unbounded work is explicitly deferred to a task. Tradeoff: more upfront capacity math (§32). Operational: debug_assert! on list length ceilings. Violation: a runaway scan turns a bounded ISR into an unbounded one and jitter explodes (M8).
  • P3 — Interrupts do the minimum (top-half/bottom-half). Rule: an ISR acknowledges hardware, captures data, pends deferred work, and returns; policy runs in a task. Tradeoff: one extra context switch of latency. Operational: deferred-ISR queue (§16). Violation: heavy ISR logic raises interrupt-off time and starves higher-rate IRQs (§22 T3).
  • P4 — unsafe is a bounded, named audit surface. Rule: unsafe only in rtos_arch (+ canaries/MMIO), each block documented with the invariant it upholds. Tradeoff: some ergonomic friction. Operational: CI greps unsafe outside the allowlist (ADR-16). Violation: aliasing bugs leak into safe code and the compiler's guarantees evaporate.
  • P5 — Static allocation by default. Rule: tasks, stacks, queues, and pools are allocated at init from static storage; the heap is opt-in and never on a hot path. Tradeoff: sizes fixed at build. Operational: #[link_section] placement, no allocator in default build (ADR-06). Violation: fragmentation makes allocation latency unbounded (§23 FM-5).
  • P6 — Priority inversion is a first-class hazard. Rule: every shared resource with a mutex uses priority inheritance (default) or ceiling (configured); blocking terms are computed (§32). Tradeoff: inheritance bookkeeping cost. Operational: I8, ADR-14. Violation: an unbounded inversion (the Pathfinder failure) misses a hard deadline.
  • P7 — Monotonic time only for scheduling. Rule: scheduling and timeouts use a monotonic tick counter (I10); wall-clock/RTC is data, never a scheduling input. Tradeoff: no calendar semantics in the kernel. Operational: rtos_time exposes Instant/Duration, no SystemTime. Violation: an RTC step backward reorders wake events and a timer fires twice or never.
  • P8 — Observe without perturbing. Rule: tracing is lock-free, bounded, and its cost is measured and budgeted (M7-adjacent). Tradeoff: trace fidelity vs overhead. Operational: trace ring
    • RTT, overhead benchmarked in §28. Violation: instrumentation changes the timing it measures (a Heisenbug) and the trace lies.
  • P9 — Fail fast on corruption. Rule: stack overflow (MPU guard + canary), double-free, and invariant violations trap immediately with a forensic dump; never limp on. Tradeoff: a crash instead of degraded run. Operational: I7, MPU fault handler (§15). Violation: silent memory corruption produces a delayed, undebuggable fault far from the cause.
  • P10 — Portability lives at one seam. Rule: all architecture code is in rtos_arch; the kernel is arch-agnostic. Tradeoff: an indirection at the port boundary. Operational: adding RISC-V means one new port crate (ADR-03). Violation: arch assumptions leak into rtos_kernel and every port forks the scheduler.
  • P11 — One authority orders the ready set. Rule: the ready-list bitmap in rtos_kernel is the single source of "who runs next" (I2); no subsystem picks tasks. Tradeoff: all wake paths funnel through it. Operational: select_next() is the only picker. Violation: two orderings disagree and a lower-priority task preempts a higher one.
  • P12 — Critical sections are bounded and nesting-counted. Rule: kernel critical sections mask by basepri (not PRIMASK), are nesting-counted (I6), and have a stated max cycle length. Tradeoff: high-priority "zero-latency" IRQs must stay off kernel data. Operational: enter/exit balance asserted. Violation: an unbalanced exit leaves interrupts masked and the system hangs.
  • P13 — Wakeups are O(1) and deterministic. Rule: readying a task is a bitmap set + list push, never a scan; the highest waiter is found by CLZ. Tradeoff: 32-priority ceiling per bitmap word. Operational: I3, M3. Violation: an O(n) wake makes latency depend on task count and analysis breaks.
  • P14 — Configure at compile time, not run time. Rule: kernel limits (max tasks, tick rate, feature flags) are const/typestate, resolved at build; no runtime reconfiguration of invariants. Tradeoff: rebuild to change limits. Operational: const generics + Cargo features (ADR-24). Violation: runtime config paths become untested, unbounded, and a security surface.

Debugging methodology. A #[cfg(feature="sim")] host simulator runs the scheduler and IPC against a deterministic virtual clock with one assertion per invariant (I1–I15) evaluated at every scheduler decision point; property tests (§26) generate random task/IPC event streams and fail on the first violated assertion, printing the event trace that produced it. On-target, the same invariants compile to debug_assert! (debug build) and to telemetry counters (release), so a field failure is localized to the specific invariant it broke.

8.1 Task state machine

             create()              admit / wake
   [nonexistent] ---> DORMANT ---> READY <--------------------+
                         ^           |  select_next() (I2)     |
                         |           v                         |
                     delete()     RUNNING --- yield/preempt -->+
                         |           |                         |
                         |           +-- block(sem/mutex/q) --> BLOCKED
                         |           +-- delay(ticks) --------> DELAYED
                         |           +-- suspend() -----------> SUSPENDED
                         |                                       |
                         +---------------- delete() <------------+
   Wake edges: BLOCKED --signal/timeout--> READY ; DELAYED --tick==wake--> READY ;
               SUSPENDED --resume()--> READY.  Exactly one RUNNING (I1).
From Event To Side effect
DORMANT start READY bitmap set (I3), push ready list
READY select_next RUNNING PendSV pend if preempting (I2)
RUNNING higher-prio readied READY preempted; ctx switch (I4)
RUNNING sem_wait empty BLOCKED push object wait list (I12)
RUNNING delay(n) DELAYED insert delayed list, wake=tick+n (I14)
BLOCKED signal / timeout READY remove wait list, bitmap set
DELAYED tick == wake_tick READY pop delayed list
any delete DORMANT free TCB slot, remove from all lists (I12)

8.2 TCB storage layout (per-task, static)

TCB (target ~64 B):  [ psp: *mut u32 ][ state: u8 ][ base_prio: u8 ][ cur_prio: u8 ]
  [ flags: u8 ][ stack_base: *mut u8 ][ stack_size: u16 ][ wake_tick: u64 ]
  [ wait_link: ListLink ][ ready_link: ListLink ][ held_mutexes: MutexList ]
  [ canary: u32 ][ runtime_cycles: u64 ][ stack_high_water: u16 ]

cur_prio ≥ base_prio only while inheriting (I8); wake_tick valid only in DELAYED (I14).

8.3 Cortex-M exception frame (hardware-stacked, PendSV switch)

Auto-stacked by HW on exception entry (PSP grows down):
  [ R0 ][ R1 ][ R2 ][ R3 ][ R12 ][ LR ][ PC ][ xPSR ]   (+ FP frame if lazy-stacked)
Saved by PendSV software (I4):
  [ R4 ][ R5 ][ R6 ][ R7 ][ R8 ][ R9 ][ R10 ][ R11 ]    (+ S16–S31 if FP active)
Stored PSP written into TCB.psp; next task's PSP loaded; EXC_RETURN selects PSP/FP.

8.4 Queue wire/record layout (bounded copy queue)

QueueHeader: [ cap: u16 ][ item_size: u16 ][ head: u16 ][ tail: u16 ][ count: u16 ]
             [ send_waiters: WaitList ][ recv_waiters: WaitList ][ policy: u8 ]
Storage: cap * item_size bytes, static, item-aligned. count == enq − deq (I11).

8.5 Worked example — periodic control task, one tick

  1. SysTick fires → tick += 1 (I10); scan delayed list head: wake_tick == tick → move control task DORMANT/DELAYED→READY, bitmap bit p set (I3).
  2. Control task prio (5) > current RUNNING (idle, 31) → pend PendSV (I2).
  3. SysTick returns; PendSV (lowest prio, I13) runs: save R4–R11+PSP of idle (I4), load control task PSP, bx EXC_RETURN.
  4. Control task runs its loop, queue_send(cmd) (copy, I11), then delay_until(next) → DELAYED, re-inserted sorted (I14); scheduler picks next READY.

8.6 Malformed-input example

queue_send on a full queue with policy = Fail: returns Err(QueueFull), increments queue.drops (I11 telemetry), never blocks the caller (backpressure ADR-22). A sem_give that would overflow a counting semaphore's max returns Err(Overflow) rather than wrapping.

8.7 Failure-path example

A task calls mutex_lock then busy-waits on an I/O flag while holding it (violates I9): the runtime guard flags blocked-with-mutex, the hold-time watchdog (mutex.hold_ticks_max) expires, the mutex is force-released with Err(HoldTimeout), the inheritance chain is unwound (I8), and a trace event MUTEX_HOLD_TIMEOUT is emitted for postmortem (§23 FM-3).

13. Phase 1 — Context Switching (PendSV/SVC)

13.1 Objectives

Implement the arch-specific context switch: manufacture task stack frames, save/restore R4–R11 + PSP + FP lazy frame in PendSV (I4, per Yiu §5), start the first task via SVC, and support cooperative yield. Constraint: switch ≤ 200 cycles ≈ 1.2 µs (M2).

13.2 Detailed Implementation Steps

Touch rtos_arch/src/context.rs, rtos_kernel/src/tcb.rs. Per AAPCS (ADR-04) and I4, PendSV saves R4–R11 and (if EXC_RETURN bit4 clear) S16–S31, stores PSP into TCB.psp, calls select_next (I2, P11), loads the next PSP, and returns via bx EXC_RETURN. start_first_task uses SVC0 to load the first PSP and set CONTROL to use PSP in thread mode. Task stack frames are pre-seeded with a synthetic exception frame (PC=entry, xPSR=Thumb bit, LR=task-exit trampoline). All blocks are unsafe, each annotated with the invariant it upholds (P4). Add context-switch trace events (P8).

13.3 Deliverable

Two tasks cooperatively yielding back and forth in QEMU and on-target, verified by trace order; bench_ctx_switch reports cycle count.

13.4 Acceptance Criteria

Context switch ≤ 200 cycles no-FP, ≤ 300 cycles with FP frame, measured by DWT (M2); conformance/context/basic_switch.yaml shows exact A→B→A trace order; register checksum intact across 10^6 switches (I4); FP task preserves S16–S31 across a switch.

13.9 Failure Analysis

15.1 Objectives

26. Testing & Verification Strategy

  • Unit — per-crate: bitmap CLZ, list ops, pool alloc, queue counts (I11), inheritance (I8).
  • Integration — multi-task scenarios on QEMU (ADR-17): preemption, IPC, timers.
  • Property tests — randomized scheduler/IPC event streams checked against every invariant I1–I15 (§7 methodology); e.g., no lost wakeup (I12), monotonic tick (I10).
  • Differential — kernel behavior vs a reference model (host simulator) on identical event streams; optionally vs FreeRTOS on shared fixtures for scheduling decisions.
  • Fuzzing — cargo-fuzz targets: queue codec, task-set parser (rta_check), scheduler event API, trace decoder; malformed inputs must error, never UB (§8.6).
  • Chaos / fault injection — inject IRQ storms (T3), pool OOM (FM-5), corrupt frames (FM-7), and assert containment + recovery.
  • Deterministic replay — record a trace of scheduler/ISR events and replay in the simulator to reproduce a field bug bit-for-bit (P8).
  • Soak — 72 h multi-task run on hardware; watch counters (drops, drift, high-water) for slow leaks.
  • Conformance — every phase's N.5 fixtures run in CI (ADR-16); §21 is the schedulability gate.
  • Performance-regression gating — §28 M1–M12 measured in CI (QEMU) and HIL; a regression fails the build.

Each invariant maps to at least one property test; each phase's N.4 maps to at least one conformance fixture. The §21 rta_check verdict is a release gate (§27).

29. Scalability Analysis

  • Stays constant (O(1)) as tasks grow: select_next (CLZ bitmap, M3, P13), wake/block (I3), context switch (M2), tick decision. This is the design's core scaling property (§4).
  • Grows with task count: RAM = tasks × (TCB 64 B + stack), linear (§32 #3); canary scan cost = tasks × tick rate (§15.7); response-time analysis is pseudo-polynomial in task count × hyperperiod (§21).
  • Grows with priority count: one 32-bit bitmap caps at 32 priorities O(1); >32 needs a hierarchical bitmap (O(1) still, more words) — deferred PhaseDeferred("§35").
  • Named bottlenecks, in order: (1) interrupt-off time from basepri critical sections (P12) — caps IRQ responsiveness; (2) single-core CPU — the hard ceiling (no SMP, §1); (3) delayed-list insert O(log n) at high timer counts (§18.7); (4) trace-link bandwidth for high event rates (§32 #7).
  • Horizontal scaling: none within a chip (single core); "scaling out" = more MCUs coordinating over a bus — out of scope (§1). Vertical scaling: faster clock (linear cycle→time), more RAM (more tasks/ stacks), a core with a data cache (changes WCET model).
  • Sharding/partitioning: SMP would partition tasks to per-core run queues (partitioned scheduling, Davis & Burns 2011) PhaseDeferred("§35"); coordination overhead = inter-core locks/IPIs, the reason it is deferred.
  • Coordination overhead: single core → none today; the moment SMP lands, per-core locks and cache-line bouncing appear (§34 alt).
  • Practical ceiling: ~32 hard-real-time tasks at 1 kHz on a 168 MHz M4 with utilization ≤ the RMS bound (§32 #2); levers beyond: raise clock, cut WCET, move to EDF to reclaim utilization (§34), or add a core.

30. Mental Models & First Principles

  • MM1 — A context switch is a manufactured exception return. Insight: you don't "jump" to a task; you build the exact stack frame the CPU's exception-return hardware expects, then let bx EXC_RETURN resume it. Predicts: seeding xPSR/PC/LR correctly is the whole game. Bug class without it: garbage PC on first run of a task. Resolves in §13 (Phase 1).
  • MM2 — The scheduler is a clock's consumer, not its source. Insight: SysTick is the heartbeat; the scheduler only reacts at decision points. Predicts: jitter is bounded by tick granularity + interrupt-off time. Bug class: busy-wait "scheduling" that drifts (P7). Resolves in §14, §18.
  • MM3 — Worst case is the only case that schedules. Insight: hard real-time is decided by WCET and the blocking term, not averages (Liu&Layland; Audsley). Predicts: a set with U ≤ bound can still miss if B_i is ignored. Bug class: "it works on my bench" deadline misses (P1). Resolves in §21, §32.
  • MM4 — Priority inheritance turns unbounded blocking into one critical section. Insight: donating priority prevents a mid-priority task from indefinitely delaying the holder (Sha 1990). Predicts: with inheritance, B_i ≤ longest CS of a lower task. Bug class: the Pathfinder inversion (§17.6). Resolves in §17 (I8, ADR-14).
  • MM5 — An ISR is a thief of time; make the theft O(1). Insight: every cycle in an ISR is stolen from every lower-priority task; defer everything possible (P3). Predicts: heavy ISRs blow jitter (M8). Bug class: dropped high-rate IRQs behind a slow one. Resolves in §16.
  • MM6 — basepri masks by priority; PRIMASK is a sledgehammer. Insight: a real-time kernel masks a band so zero-latency IRQs still fire (P12). Predicts: using PRIMASK for kernel CS raises worst-case IRQ latency for everyone. Bug class: a critical safety IRQ delayed by an unrelated kernel op. Resolves in §13, §16 (I6).
  • MM7 — Fault isolation without an MMU is spatial, via the MPU. Insight: on an MCU you can't page, but you can trap the instant a task touches memory it shouldn't (Tock, seL4 spirit). Predicts: a guard region catches overflow at the boundary, not after corruption (P9). Bug class: silent neighbor-stack corruption. Resolves in §15 (I7).
  • MM8 — Observability must be O(1) and lock-free or it lies. Insight: any trace that blocks or locks changes the timing it reports (P8). Predicts: a locking tracer creates priority inversion in itself. Bug class: Heisenbugs that vanish when tracing is off. Resolves in §20.

32. Back-of-Envelope Capacity Model

All numbers chain from §4 (168 MHz, 1 cyc ≈ 5.95 ns, 192 KB SRAM, tick 1 kHz, 64 B TCB, 512 B stack).

  1. Tick CPU overhead. tick_cost × tick_rate / clock. tick handler ≈ 300 cyc; 300 × 1000 / 168e6 = 0.18% CPU — well under the M7 2% budget; headroom for tick up to ~11 kHz before 2%.
  2. RMS utilization ceiling. For n tasks, U ≤ n(2^(1/n)−1); as n→∞ → ln 2 ≈ 0.693. So a large task set is guaranteed schedulable under RMS only up to ~69% CPU utilization (Liu&Layland); beyond, use exact RTA (§21) or EDF (§34).
  3. RAM for N tasks. N × (TCB + stack) = N × (64 + 512) = N × 576 B. For N = 32: 32 × 576 = 18.4 KB, ~10% of 192 KB SRAM — so ~300 minimal tasks fit RAM-wise before stacks dominate; hard-real-time count is bound by #2, not RAM.
  4. Context-switch budget. At M2 = 200 cyc ≈ 1.19 µs, sustaining X switches/s costs X × 1.19 µs. For 1% CPU: X = 0.01 × 168e6 / 200 = 8,400 switches/s — far above a 1 kHz tick's needs, so switch cost is not the ceiling.
  5. Queue RAM. depth × item_size. A 64-deep queue of 32 B items = 64 × 32 = 2 KB + a ~24 B header. Ten such queues = ~20 KB, ~10% SRAM — bounded by design (ADR-22).
  6. Interrupt bandwidth. Max IRQ rate before deferred-queue overflow = drain_rate. If the server task processes one deferred event in ≈ 500 ns, sustainable ≈ 1/500 ns = 2 M events/s ideal; with 50% CPU left for tasks, budget ~1 M/s — above that, T3/FM-8 drop kicks in.
  7. Trace bandwidth. events/s × bytes/event vs RTT link. 10k ev/s × ~8 B = 80 KB/s; an RTT link at ~1 MB/s absorbs it with 12× headroom, so the ring (§20) only needs to cover bursts, not sustained rate.
  8. Boot budget. .data copy + .bss zero ≈ (data+bss bytes)/(bytes per cyc). For ~16 KB init at ~1 B/cyc ≈ 16k cyc ≈ 95 µs; clock lock ≈ few ms dominates → ≤ 5 ms (M11) is clock-limited, not copy- limited.
  9. Flash budget. kernel ≤ 12 KB (M9) of 1 MB = 1.2%; leaves ~988 KB for application + drivers — flash is not the constraint on an F407.
  10. Stack right-sizing. From stack_high_water (I7), a task using 300 B peak gets 300 + 25% margin ≈ 384 B allocated; over-allocation wastes the §32 #3 budget, so high-water-driven sizing is how N scales toward the RAM ceiling.

34. Alternative Architectures (Roads Not Taken)

A. EDF (dynamic-priority) kernel.

[ready set] --sort by absolute deadline--> [run earliest-deadline task]
                 (dynamic priority per job)

Regime where it wins: soft/firm real-time needing >69% utilization reclaimed — EDF schedules any set with U ≤ 1 (Liu&Layland), vs RMS's ~0.693. Real system embodying it: EDF schedulers in Linux SCHED_DEADLINE. Why rejected here: EDF needs per-job deadline tracking and re-sorting (not O(1) bitmap, M3), harder to analyze under overload (Locke 1986), and its failure mode under transient overload is a domino of misses rather than the predictable "lowest priority suffers" of fixed-priority (P1). Kept as a PhaseDeferred("§35") option.

B. Stack Resource Policy / single-shared-stack kernel.

[all tasks share one stack]  resource ceilings prevent blocking-then-preemption
      -> at most one blocking term per task (Baker 1991)

Regime: extreme RAM scarcity (a few KB) where per-task stacks are unaffordable and a fully static task set is known offline. Real system: SRP-based run-to-completion executors (OSEK/AUTOSAR BCC1-style). Why rejected: run-to-completion within a preemption level forbids blocking mid-task (no queue_recv that sleeps), which our IPC model (§17) relies on; too restrictive for general control loops. Baker's blocking bound informs our ceiling mode (ADR-14).

C. Verified microkernel (seL4-style capabilities).

[user tasks] --syscall--> [tiny verified kernel: capabilities, endpoints]
     isolation + IPC entirely via capability invocations

Regime: safety/security-critical systems that must prove kernel correctness. Real system: seL4 (Klein 2009). Why rejected: full functional-correctness proof is a multi-person-year effort and constrains the feature set; our bar is analyzable timing + Rust safety + property tests (§26), not a machine-checked proof. seL4's isolation model informs MM7 and the deferred userspace-MPU work (PhaseDeferred("§35")).

D. Cooperative/async single-stack executor (async/await).

[tasks as Futures] --poll--> [executor loop] (no preemption, no per-task stack)

Regime: ultra-low-power, I/O-bound firmware where every context switch's energy matters and deadlines are soft. Real system: Embassy (Rust async embedded). Why rejected: cooperative scheduling cannot preempt a long-running computation, so a single misbehaving task blows every deadline (P1); hard real-time needs preemption. Kept in mind for the low-power idle path (§18) but not the core model.

36. Glossary

  1. RTOS — real-time operating system; correctness includes meeting timing deadlines.
  2. Task — the schedulable unit; a function with its own stack and TCB.
  3. TCB (Task Control Block) — per-task kernel state: PSP, priority, state, links (§11).
  4. Priority — fixed scheduling rank, 0 highest .. 31 idle (§4).
  5. Preemption — suspending a running task for a higher-priority ready one (I2).
  6. Context switch — save one task's registers, restore another's (I4, §13).
  7. PendSV — Cortex-M exception used to perform the context switch at lowest priority (I13).
  8. SVC — supervisor call exception; used to start the first task / raise privilege.
  9. SysTick — Cortex-M system timer driving the kernel tick (I10).
  10. NVIC — Nested Vectored Interrupt Controller; manages IRQ priorities/enable.
  11. basepri — Cortex-M register masking interrupts at/below a priority band (P12).
  12. PRIMASK — Cortex-M register masking all maskable interrupts (contrast MM6).
  13. Exception frame — registers auto-stacked by hardware on exception entry (§8.3).
  14. AAPCS — ARM procedure-call standard; defines callee-save registers (I4).
  15. MPU — Memory Protection Unit; region-based access control, no paging (I7).
  16. Canary — sentinel word detecting stack overflow (I7).
  17. ISR — interrupt service routine; the top-half (P3).
  18. Top-half/bottom-half — split of ISR into fast ack + deferred processing (P3, §16).
  19. Deferred-ISR queue — buffer handing ISR work to a server task (§16).
  20. Ready list — per-priority lists of runnable tasks, indexed by a bitmap (I3).
  21. Bitmap scheduler — O(1) pick of highest ready priority via CLZ (M3, P13).
  22. CLZ — count-leading-zeros; finds the highest set priority bit in O(1).
  23. Semaphore — counting/binary synchronization primitive (§17).
  24. Mutex — mutual-exclusion lock with an owner; here with priority inheritance (I8).
  25. Priority inheritance (PIP) — owner temporarily inherits a blocked waiter's priority (Sha 1990).

  35. Jitter — variation in a periodic task's release time (M8).
