30. Mental Models & First Principles

  • MM1 — Speculation is a bet with an undo log. Compressed insight: every speculative update is a wager that must be perfectly reversible. · Predicts: any rollback design that isn't a pure function of epoch state will eventually leak. · Bug class avoided: partial-undo corruption that surfaces epochs later (§14.9, §20.9). · Applies in §14 and §20.
  • MM2 — Aliasing is capacity pressure in disguise. Compressed insight: two branches colliding on one table entry is not a bug, it's the table being too small for the workload's distinct-PC count. · Predicts: aliasing metrics trend with table-size-to-working-set ratio, not with a specific PC. · Bug class avoided: "fixing" aliasing by tweaking the hash function instead of sizing the table (§32's capacity arithmetic). · Applies in §15 and §18.
  • MM3 — History is a compressed bet on recurrence, not a record of the past. Compressed insight: folded/global history exists to predict the future, and its width is a bias-variance tradeoff, not a fidelity requirement. · Predicts: widening history helps only up to the point where indexing aliasing (MM2) dominates. · Bug class avoided: assuming "more history bits = always better" (§18.6's folded-history-aliasing pitfall). · Applies in §14 and §18.
  • MM4 — Determinism is a systems property, not an accident. Compressed insight: byte-identical replay requires every subsystem to forgo a convenience (wall clock, global RNG, unordered concurrency) individually — one leak anywhere breaks it everywhere. · Predicts: nondeterminism bugs cluster around exactly the places P1/P11/ADR-20 explicitly forbid a shortcut. · Bug class avoided: chasing a "flaky test" instead of finding the wall-clock or global-state leak (§21.6). · Applies in §6 and §12.
  • MM5 — Confidence is a second-order prediction. Compressed insight: a predictor's confidence estimate is itself a learned quantity that can be wrong independently of the direction prediction. · Predicts: a hybrid chooser trained only on direction accuracy, ignoring confidence, underperforms one that uses both (§19). · Bug class avoided: treating confidence as a free, always-trustworthy signal. · Applies in §17 and §19.
  • MM6 — The frontend is a pipeline of pipelines. Compressed insight: fetch, predict, speculative- update, retire, and train are each independently-pipelineable stages, and their interaction (not any single stage) determines effective throughput. · Predicts: optimizing one stage in isolation (e.g., only the predictor lookup) plateaus once another stage becomes the bottleneck. · Bug class avoided: chasing predictor-only optimizations after the replay scheduler is already the bottleneck (§29). · Applies in §13 and §28.
  • MM7 — Replay is time-travel debugging built into the architecture, not bolted on. Compressed insight: because every state transition is a deterministic function of trace + checkpoint, any incident is re-runnable exactly, turning "debug in production" into "debug offline." · Predicts: incidents that seem unreproducible are always a P1/ADR-20 violation, never genuine nondeterminism. · Bug class avoided: writing bespoke incident-specific debug instrumentation instead of just re- running the trace. · Applies in §20 and §23.
  • MM8 — Tournament selection is meta-learning over predictors, and inherits all of learning's failure modes. Compressed insight: a chooser table is itself a predictor (of which predictor to trust), subject to the same aliasing, training-rate, and overtraining failure modes as any direction predictor. · Predicts: hybrid instability (§19.6) looks structurally identical to bimodal/gshare instability (§15.6), one level up. · Bug class avoided: treating chooser-table bugs as a distinct category requiring new debugging tools rather than reusing §15's counter-debugging playbook. · Applies in §15 and §19.

5. Required Reading

Books

  • Computer Architecture: A Quantitative Approach — Hennessy & Patterson (2019, 6th ed.), ch. 3 (ILP) and Appendix on branch prediction: predictor accuracy tradeoffs, pipeline penalty arithmetic, speculative-execution economics; applied in §4 and §28.
  • Computer Organization and Design, RISC-V Edition — Patterson & Hennessy (2020), ch. 4 (pipelining and hazards): control-hazard penalty derivation, stall-vs-speculate tradeoff; applied in §3 and §15.
  • Modern Processor Design: Fundamentals of Superscalar Processors — Shen & Lipasti (2005), ch. 3–4 (frontend architecture, branch prediction, speculative execution): tournament predictor structure, frontend/backend decoupling; applied in §16 and §19.
  • Structured Computer Organization — Tanenbaum (2012), ch. 4–5 (microarchitecture level, instruction-set level): baseline CPU-frontend vocabulary, instruction flow and hazards; applied in §8 and §12.
  • Engineering a Compiler — Cooper & Torczon (2011), ch. 9 (instruction scheduling) and CFG chapters: control-flow-graph structures, branch-probability annotation, profile-guided optimization; applied in §2 and §11.
  • Systems Performance: Enterprise and the Cloud — Gregg (2020, 2nd ed.), ch. 6 (CPUs) and ch. 12 (benchmarking): measurement-bias avoidance, statistically valid benchmarking methodology, latency histogram design; applied in §28 and §26.

Papers

  • "A Study of Branch Prediction Strategies" — J. E. Smith, 1981, ISCA: introduces the saturating 2-bit counter and PC-indexed table, direct ancestor of bp-bimodal's counter state machine; applied in §15.
  • "Two-Level Adaptive Training Branch Prediction" — Yeh & Patt, 1991, MICRO: foundational two-level (pattern-history + global-history) predictor design, the GHR/LHR split in bp-history; applied in §14.
  • "Trading Conflict and Capacity Aliasing in Conditional Branch Predictors" — Michaud, Seznec & Uhlig, 1997, ISCA: formal aliasing taxonomy (conflict vs. capacity), the aliasing-metric design in bp-metrics and the gshare XOR-index rationale; applied in §15.
  • "Combining Branch Predictors" — McFarling, 1993, WRL TN-36: tournament/chooser-table predictor combination, the hybrid arbitration logic; applied in §19.
  • "The YAGS Branch Prediction Scheme" — Eden & Mudge, 1998, MICRO: tagged-direction-cache refinement over gshare, motivates tag-based aliasing reduction later generalized by TAGE; applied in §18.
  • "Dynamic Branch Prediction with Perceptrons" — Jiménez & Lin, 2001, HPCA: neural (linear perceptron) branch prediction, weight-vector training semantics in bp-perceptron; applied in §17.
  • "A Case for (Partially) Tagged Geometric History Length Branch Prediction" — Seznec & Michaud, 2006, Journal of Instruction-Level Parallelism: the TAGE predictor family, folded-history compression and tagged-table allocation policy; applied in §18.
  • "A 64-Kbytes ISL-TAGE Branch Predictor" — Seznec, 2011, JILP / CBP-3 championship entry: production-scale TAGE tuning (statistical corrector, loop predictor), basis for the deferred TAGE-SC-L extension; applied in §18.

Reference Implementations

  • gem5/gem5 — study src/cpu/pred/: lesson — clean separation of predictor interface from pipeline timing model; pitfall: do not copy gem5's config-parameter sprawl into bp-config; applied in §12 and §16.
  • ChampSim/ChampSim — study branch/: lesson — trace-driven simulation with pluggable predictor modules loaded by name, exactly the bp-hybrid composition model; pitfall: ChampSim's warmup-then-measure split undercounts cold-start MPKI if copied verbatim; applied in §13 and §15.
  • riscv-boom/riscv-boom — study the frontend predictor logic in the Chisel BPD unit: lesson — speculative update must be applied and rolled back at the same pipeline-stage granularity; pitfall: BOOM's hardware-synchronous update timing does not map onto a software event-driven scheduler; applied in §20.
  • snipersim/snipersim — lesson: interval-simulation-based scalable replay infrastructure trading cycle accuracy for throughput, the same tradeoff bp-sim makes; pitfall: interval models hide misprediction-recovery cost, which bp-sim must model explicitly; applied in §13 and §20.
  • MARSSx86 — lesson: full-system x86 simulator pipeline-integration pattern for predictor hookup at fetch; pitfall: MARSSx86's tight coupling of predictor state to the functional core makes predictor swap-out costly, the opposite of ADR-23's trait isolation; applied in §16.

RFCs / Specifications

  • ELF Specification (System V ABI, generic ABI) — pins down the executable/object layout bp-cli must parse when correlating traces to symbol addresses; applied in §13.
  • Intel 64 and IA-32 Architectures SDM, Vol. 3C, ch. 33 (Intel Processor Trace) — pins down the Intel PT packet format bp-trace decodes for hardware-captured traces; applied in §13.
  • Protocol Buffers Encoding (protobuf) — pins down the wire format used alongside bincode for cross-language checkpoint interchange (ADR-05); applied in §20.
  • OpenTelemetry Specification — pins down the trace-span and attribute model bp-metrics emits through the tracing crate (ADR-12); applied in §21.
  • JSON Schema, draft 2020-12 — pins down the validation schema used for bp-config's TOML-to-JSON validation bridge; applied in §12.
  • Semantic Versioning 2.0.0 — pins down the compatibility contract for every crate's public API and the checkpoint schema-version field; applied in §20 and §25.

Glossary (§36) · 50 terms · site-wide glossary

BTB
Branch Target Buffer; caches predicted taken-branch targets, set-associative and tagged.
RAS
Return Address Stack; predicts function-return targets via speculative push/pop.
GHR
Global History Register; records the taken/not-taken outcome of recent branches globally.
LHR
Local History Register; per-PC analog of GHR.
MPKI
Mispredictions Per Thousand Instructions; the primary predictor-accuracy metric.
TAGE
TAgged GEometric history length predictor family (Seznec & Michaud, 2006).
IPC
Instructions Per Cycle; the throughput metric branch prediction quality gates.
SMT
Simultaneous Multithreading; a CPU frontend-sharing mode this system models as a §4 assumption and partially defers (§35, SMT-aware partitioning).
Replay Epoch
a deterministic replay interval bounded by speculative-state open/close.
Provider Predictor
the component predictor whose output a hybrid/tournament arbiter selects.
Folded History
a compressed (XOR-folded) representation of raw history bits sized to a table's index width.
Saturating Counter
a bounded (clamped, never wrapping) prediction-confidence counter, I5.
Aliasing
multiple distinct branches mapping to the same predictor-table entry.
Frontend Stall
a fetch-starvation event caused by a misprediction or BTB/RAS miss.
Speculative State
predictor/history/BTB/RAS state written before retirement, subject to rollback (I4).
Retirement
the pipeline stage at which a branch's outcome is architecturally committed and predictor training occurs.
Predictor Pollution
destructive interference between unrelated branches sharing table state (a consequence of aliasing).
Confidence Estimator
a model (or field, BranchPrediction.confidence) estimating a prediction's reliability, distinct from the direction prediction itself (MM5).
Trace Normalization
canonical field-ordering and timestamp-rebasing applied at ingest (§13).
Snapshot Epoch
the checkpoint-generation identifier tagging a durable snapshot (I8).
OoO
Out-of-Order (execution); the superscalar CPU class this system's frontend models feed.
ILP
Instruction-Level Parallelism; the resource branch misprediction penalties destroy.
PC
Program Counter; the instruction-pointer value used to index PC-based predictor tables.
Direction Prediction
predicting taken/not-taken for a conditional branch (bimodal/gshare/ perceptron/TAGE).
Target Prediction
predicting the destination address of a taken branch (BTB/RAS).
Tournament Predictor
a predictor that arbitrates between two or more component predictors via a trained chooser table (McFarling, 1993).
Chooser Table
the PC-indexed saturating-counter table a hybrid predictor trains to select a provider.
Usefulness Counter
a TAGE per-entry counter gating replacement priority under allocation pressure (§18).
Geometric History Length
TAGE's design of using exponentially-spaced history lengths across its tagged tables.
Perceptron Weight Vector
the per-PC signed integer vector trained by bp-perceptron (§17).
Speculative Epoch
an identifier tagging one open, not-yet-retired speculative window (I13).
Rollback Checkpoint
an in-memory, epoch-tagged snapshot distinct from a durable bp-checkpoint snapshot, used for cheap speculative rollback (§20).
Replay Sequence ID
the globally monotonic identifier assigned to every replay event (I1).
NUMA
Non-Uniform Memory Access; the memory-topology assumption behind I14's table-locality invariant.
Cache Line
the 64-byte (§4) unit of cache locality this system's table layouts are aligned to.
Set-Associative
a table organization allowing N possible slots ("ways") per index, used by bp-btb.
Tag Matching
comparing a stored tag against a lookup key to confirm a table hit is valid (I3).
LRU Epoch
the replacement-policy timestamp used by bp-btb's eviction logic.
Watchdog Timeout
the detection mechanism for queue deadlock (FM-4).
Backpressure
a bounded producer/consumer discipline that blocks or drops rather than growing unboundedly (P4).
Crash-Only Software
a design discipline where the only recovery path is restart, never in-place repair (P2).
SBOM
Software Bill of Materials; a dependency manifest generated in CycloneDX format (§27).
Sigstore
an artifact-signing system used for release integrity verification (ADR-16, §27).
CycloneDX
the SBOM output format this project standardizes on (§27).
Bisect Tooling
tooling that binary-searches commits to isolate a performance or correctness regression (§21.9).
Branch Storm
a synthetic workload with an unusually high density of taken/mispredicted branches, used for stress-testing (§4).
Warmup Period
the initial replay window during which predictor state has not yet converged, excluded from steady-state MPKI measurement.
ITTAGE
Indirect-Target TAGE; a tagged-geometric predictor variant for indirect branches, deferred past §16 (§35).
YAGS
Yet Another Global Scheme; a tagged-direction-cache refinement over gshare (Eden & Mudge, 1998, §5).
GEHL
Geometric History Length predictor; a related family alongside TAGE referenced in this project's historical-importance framing (§2).
