Access-Method Interface. The single protocol boundary to the host engine; every request (lookup, scan, mutate) enters here as a Predicate and leaves as an AccessPath result. It owns no state of its own and is where request validation and backpressure (ADR-29) live.

Cost-Based Router. Consults the Statistics Collector for the current generation and consults each candidate engine's CostEstimate before choosing a path (P2); its decisions are deterministic given inputs and are themselves emitted as telemetry.

Statistics Collector. Owns histograms and sketches, updated incrementally on the write path (ADR-09) and consulted, never blocked on, by the router; staleness is a bounded, visible quantity (P9, I6).

B+Tree Engine. Provides ordered range access with latch coupling (P7) and prefix compression; the default path for wide-range, update-heavy workloads.

ART Engine. Provides point-lookup-optimized access via adaptive radix nodes with path compression; the default path for sparse, point-lookup-heavy workloads.

Cracking / Adaptive Reorg Engine. The load-bearing subsystem: performs in-place partitioning (cracking) or run-merging (adaptive merging) as a side effect of query execution, never as a standalone job (P1), and is the only engine whose physical layout changes without an explicit build step.

Concurrency-Control Layer. Owns latches, optimistic lock coupling tokens, and the copy-on-crack versioning that lets reorganization proceed without invalidating active readers (P3, I9); every other engine calls through it rather than implementing its own locking.

Scan Accelerator. SIMD-vectorized predicate evaluation over both cracked columns and raw row batches; consumes ScanBatch units from the storage manager.

Buffer / Storage Manager. The persistence boundary: page/segment caching, eviction, and durable writes; every structure above it is volatile until it flushes through here.

Tiered-Compaction Worker. Moves segments between hot/warm/cold storage tiers under a backpressure-throttled, leveled-compaction policy (ADR-15), never competing unbounded with foreground queries (P10).

8. Domain Model

8.1 Database Cracking — Named Steps

  • C1 — Receive predicate. A range predicate lo <= x < hi arrives on column C.
  • C2 — Locate bracketing pieces. Find pieces P_i, P_j in the CrackerIndex whose boundaries bracket lo and hi.
  • C3 — Partition at lo. In-place three-way (Hoare-style) partition of P_i around lo, producing P_i_low (< lo) and P_i_high (>= lo).
  • C4 — Partition at hi. Partition P_j around hi similarly, producing P_j_low (< hi) and P_j_high (>= hi).
  • C5 — Insert boundaries. Insert lo and hi into the sorted boundary array — O(p) where p = current piece count.
  • C6 — Return contiguous run. The now-contiguous sub-range [lo, hi) is returned directly as the scan result — no further sort is required for this exact range again.

Worked example. Column C holds 1,000,000 unsorted values in one piece [.,.). Query 1: C >= 200000 AND C < 400000. Cracking at 200000 and 400000 yields three pieces: [.,200000), [200000,400000), [400000,.). Cost: one O(n) partition pass, n = 1,000,000. Query 2: C >= 250000 AND C < 300000 lands entirely inside the ~200,000-element piece from query 1. Cracking again at 250000 and 300000 subdivides only that piece — cost O(200,000), not O(1,000,000). Each subsequent query in the same neighborhood touches an exponentially smaller piece (P6, P11), converging toward full refinement in O(log n) touches.

8.2 Cracker-Index Structure

Field Type Meaning
boundary key value the partitioning value between two adjacent pieces
piece_id u32 identity of the piece to the right of this boundary
size_estimate u64 approximate element count of the piece (statistics-fed)
refined_generation u32 number of crack operations that have touched this piece

8.3 Adaptive Merging — Named Steps and Contrast with Cracking

  • M1 — Initial run split. Partition the column into k sorted runs (one merge pass).
  • M2 — Identify overlapping runs. On a range query, find runs overlapping [lo, hi).
  • M3 — Partial merge. Merge only the overlapping runs within [lo, hi), producing one run for that sub-range.
  • M4 — Update run index. Replace the merged runs' entries in the RunIndex with the new single run.
  • M5 — Repeat. Subsequent queries touching the same region find fewer, larger runs, until one fully sorted run remains for the touched range (Graefe & Kuno 2010).
Dimension Cracking Adaptive Merging
first-query cost O(n) in-place partition O(n log k) partial merge, higher constant
convergence speed (queries to refine a range) O(log n) cracks, cheap per step fewer queries, each costlier
physical operation in-place swap, not stable run merge, stable, more copying
memory overhead boundary array, O(p) run metadata, O(k)
best-fit workload unpredictable, narrow, shifting ranges stable, wide, repeated ranges
convergence character lazy (P1, P6) eager relative to cracking (P12)

8.4 The RUM Conjecture Framing

The RUM conjecture (Athanassoulis et al. 2016) states that no access method minimizes Read overhead, Update overhead, and Memory overhead simultaneously; improving two forces the third to grow. Framed per structure:

Structure Read (R) Update (U) Memory (M)
B+Tree good (logarithmic) good (in-place, amortized splits) moderate (overflow/fill-factor slack)
ART best (key-length bounded, cache-friendly) moderate (node growth/shrink cost) worst (pointer-heavy nodes, P8)
cracked column best after convergence, worst before cheap (append, lazy re-crack) best (no extra structure, just boundaries)
LSM (contrast, §36.3) worst (read amplification across levels) best (append-only) moderate (write-amplified but compact)

8.5 B+Tree Node Layout

16KB page byte layout:

Offset Field Size
0 page_id 8B
8 lsn 8B
16 level 2B
18 key_count 2B
20 free_space_offset 2B
22 checksum 4B
26 flags 2B
28.. page-level prefix (shared, variable) variable
.. separator-key suffix array (prefix-compressed) variable
.. child-pointer / Rid array variable
tail low fence key, high fence key variable

Latch-coupling sequence (Lehman & Yao 1981 style):

Step Actor Latch Held Before Action Latch Held After
S1 reader none latch root (read mode) root
S2 reader root inspect separator, choose child root
S3 reader root latch child (read mode) root + child
S4 reader root + child release root child
S5 reader child descend, repeat until leaf leaf

Prefix-compression example. Keys customer_10023, customer_10024, customer_10025 share the 12-byte prefix customer_100, stored once per page; each entry then stores only the 2-byte suffix 23/24/25 — a reduction from 14 bytes to 2 bytes per key, 85.7% smaller for this run.

8.6 ART Node Types — Byte Layout and Structure

Node Type Key Array Child Pointers Approx. Size Capacity Lookup
Node4 4 x 1B keys 4 x 8B ptrs ~36B + header 4 linear scan
Node16 16 x 1B keys 16 x 8B ptrs ~144B 16 SIMD-comparable linear scan
Node48 256B byte→slot index 48 x 8B ptrs ~640B 48 indexed lookup, sparse
Node256 none (direct index) 256 x 8B ptrs ~2048B 256 direct array index

Adaptive-node-growth rule (P8): grow Node4→16 on the 5th child; 16→48 on the 17th; 48→256 on the 49th. Shrink is symmetric but hysteresis-gated — a node shrinks only once its fill drops below roughly half the lower tier's capacity, preventing growth/shrink thrashing at the boundary.

Path compression / lazy expansion — worked insert. Insert "10", then "100", then "1000" into an empty ART. Insert "10": a single leaf stores the full path-compressed key "10" with no intermediate nodes (lazy expansion — a unique path needs no branching node). Insert "100": it diverges from "10" at byte position 2 ("10" ends, "100" continues with "0"); this forces expansion — a Node4 is created at the divergence point holding two children: an end-marker leaf for "10" and a continuing leaf for "0". Insert "1000": it diverges further inside "100"'s remaining path, introducing a second Node4 at the new divergence point; the common prefix "10" remains absorbed as the path-compressed prefix on the node above it (I4).

8.7 Cost Model — Display Equations and Worked Comparison

Cost_fullscan            = n * c_scan
Cost_btree_lookup        = c_traverse * log_f(n) + selectivity * n * c_fetch
Cost_cracked_scan(gen)   = touched_piece_size(selectivity, gen) * c_scan + crack_overhead(gen)
crack_overhead(gen)      -> log2(n) * c_partition  as gen -> 0 (first touch)
crack_overhead(gen)      -> 0                      as gen -> converged

Worked comparison. n = 10,000,000 rows, c_scan = 1ns/row, c_fetch = 100ns/row, c_traverse = 50ns, fanout f = 200, selectivity = 0.001 (10,000 matching rows).

  • Cost_fullscan = 10,000,000 * 1ns = 10ms.
  • Cost_btree_lookup = 50ns * log200(10,000,000) ≈ 50ns * 3.1 + 0.001 * 10,000,000 * 100ns ≈ 155ns + 1,000,000ns ≈ 1.0002ms.
  • Cost_cracked_scan (converged) ≈ 10,000 * 1ns = 10µs, crack_overhead ≈ 0.
  • Cost_cracked_scan (first touch) ≈ 10,000 * 1ns + log2(10,000,000) * 1ns * 10,000,000 ≈ dominated by the ≈23ms partition pass.

Router decision: once converged, the cracked scan (10µs) wins over the B+Tree lookup (~1ms) and full scan (10ms); on the very first touch the partition overhead dominates, so the router may still prefer the B+Tree lookup (P2, P11) until convergence is reached.

8.8 Statistics Representation and Incremental-Update Rule

Histogram: equal-depth buckets, bucket i covers [lo_i, hi_i) with count_i. Incremental update rule: on insert of value v, increment the bucket containing v; on bucket overflow (count_i > 2x target depth), locally split that bucket (redistribute only its contents), an amortized O(1) operation per write — never a full histogram recompute (ADR-09).

Sketch: HyperLogLog for cardinality estimation, m = 2^14 registers, standard error ≈ 1.04/√m ≈ 0.8%.

8.9 Concurrency-Control State Machine for Reorganization

Stable query touches unrefined range Cracking —
Cracking partition complete BoundaryInsert ReaderConflict → Deferred (retry later)
Cracking crash mid-partition Abandoned treated as still-Stable per ADR-14 (lazy recovery)
BoundaryInsert boundary committed Stable (new generation) ConcurrentBoundaryRace → Retry (CAS re-read)
Stable compaction trigger Compacting —
Compacting tier move complete Stable (new tier) CrashMidMove → RecoveryReplay (manifest-driven)
RecoveryReplay checksum verified Stable ChecksumFailure → Quarantined

8.10 Tiered-Compaction Model — Amplification Arithmetic

Leveled compaction: level L_i capacity = base_size * fanout^i. Worst-case write amplification WA ≈ fanout * num_levels; for fanout = 10, 4 levels, worst-case WA ≈ 40x, bounded to the < 4x target in §4 by heat-aware skipping of cold levels (only touched levels are rewritten). Worst-case read amplification RA = num_levels if bloom/heat routing misses; bounded to < 2.5x by routing reads directly to the tier the statistics indicate holds the match.

8.11 Malformed / Degenerate Examples

  • Crack on a constant column (all values equal c): the predicate either matches everything or nothing; partitioning would produce a zero-width piece boundary at c — the CrackerIndex must reject a duplicate boundary insert (I3) rather than looping.
  • All-duplicate keys in ART: path compression degenerates to one long chain with no branching; the engine must not allocate a Node256 for a single distinct byte value — it falls back to a leaf carrying a duplicate-key list.
  • Highly-skewed workload defeating convergence: 99% of queries touch a single 0.001%-width range; that range converges immediately, but the router must not "pre-crack" the untouched long tail — doing so violates P6.
  • Concurrent update during a crack: a writer inserts into the exact piece being partitioned; the crack step serializes against the write via the piece latch (the WriterConflict edge implied by §8.9) and either aborts-and-retries or applies the write post-crack against the new boundary.

8.12 Failure-Path Example

A crack on piece P (500,000 elements) begins; partitioning proceeds 60% through; the process receives SIGKILL. On restart, CrackerIndex reload finds P's boundary array unchanged (cracks are not WAL-logged, ADR-13) — P is treated as still fully unrefined at its pre-crack boundaries (ADR-14, lazy recovery). The next query touching P re-executes the crack from scratch. Correctness (I1, I11) is preserved at the cost of repaying the partition once.
