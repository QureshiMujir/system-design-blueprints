32. Mental Models & First Principles

MM1 — An adaptive index is a sorting algorithm amortized across the query stream. Insight: cracking pays for the sort only in the ranges the workload actually touches, never for the rest. What it predicts: total cost across all queries converges to the same O(n log n) a full sort would cost, but distributed unevenly, front-loaded on whichever ranges are queried first. Bug class without it: engineers "optimize" cracking by pre-sorting untouched ranges, silently reintroducing the up-front cost adaptive indexing exists to avoid. Resolving §17, §34.

MM2 — The RUM conjecture says you cannot optimize reads, updates, and memory simultaneously. Insight: every index decision is a choice of which of the three to sacrifice. What it predicts: any structure claiming to dominate on all three is either lying or has moved the cost somewhere unmeasured. Bug class without it: choosing ART everywhere without accounting for its memory cost (P5), or B+Tree everywhere without accounting for its point-lookup cost relative to ART. Resolving §8.4, §9.

MM3 — Cracking turns index maintenance from an up-front cost into an on-demand cost, which only wins when the workload is unpredictable. Insight: the entire value proposition collapses if the workload is actually stable and fully known in advance. What it predicts: on a stable, wide-range, repeated workload, adaptive merging (or even up-front build) beats cracking. Bug class without it: applying cracking universally regardless of workload shape, losing to a classical up-front index on predictable workloads. Resolving §18, P12, §36.1.

MM4 — Latch coupling is a correctness protocol, not a performance optimization. Insight: its purpose is preventing a reader from landing on a structure a concurrent writer has partially modified, not making traversal faster. What it predicts: removing latch coupling "for speed" reintroduces exactly the phantom-traversal bug it was designed to prevent (I5). Bug class without it: subtle, rare, hard-to-reproduce corruption under concurrent split/reader races. Resolving §13, P7.

MM5 — Convergence must be monotonic or the whole algorithm is unsound. Insight: if a crack or merge step can ever increase future cost, there is no guarantee the index ever reaches a useful state, no matter how many queries run. What it predicts: a convergence benchmark that plateaus or regresses indicates an algorithmic bug, not just a performance quirk. Bug class without it: silent, permanent performance degradation that looks like "the index just isn't helping," undiagnosable without the monotonicity framing. Resolving I11, P11, §17, §18.

MM6 — Every access path's cost estimate is a bet, and the router is the bookmaker, not the oracle. Insight: the cost model can be wrong, and the system must degrade gracefully (to a conservative estimate) when its inputs (statistics) are stale, rather than trusting the bet blindly. What it predicts: a system with perfect cost equations but stale statistics still misroutes; the fix is staleness-awareness, not a better equation. Bug class without it: chasing cost-model precision while ignoring the much larger error introduced by stale inputs. Resolving §20, P9.

MM7 — A crash during reorganization must be a safe no-op, not a half-finished state. Insight: because reorganization is not individually logged (ADR-13), the system must treat any unconfirmed reorganization step as if it never started. What it predicts: recovery logic that tries to "resume" a partial crack, rather than discarding it, will eventually corrupt state under an adversarial crash timing. Bug class without it: crash-timing-dependent corruption that only reproduces under specific interrupt points. Resolving ADR-14, §8.12, §21.

MM8 — Node growth without hysteresis is cache thrashing in disguise. Insight: a data structure that grows and shrinks at the exact same threshold will oscillate under any workload that hovers near that threshold. What it predicts: apparently "correct" adaptive growth logic that nonetheless burns CPU and fragments the allocator under realistic, noisy insert/delete patterns. Bug class without it: intermittent performance regressions that vanish under synthetic, non-noisy benchmarks and only appear in production. Resolving P8, §15.

Glossary (§38) · 46 terms · site-wide glossary

Adaptive indexing
index refinement performed incrementally as a side effect of query execution rather than built up front
Database cracking
the specific adaptive-indexing algorithm that in-place partitions a column around query predicate boundaries
Cracker index
the sorted piece-boundary ledger tracking a cracked column's current partition state
Piece
a contiguous physical sub-range of a cracked column between two boundaries
Adaptive merging
an alternative adaptive-indexing algorithm that incrementally merges sorted runs on query-touched ranges
Run
a sorted, disjoint sub-sequence of a column maintained by adaptive merging
Convergence
the process by which repeated queries on a range drive a cracked or merged column toward a fully-refined physical layout
RUM conjecture
the principle that no access method can simultaneously minimize read, update, and memory overhead
Access path
one of the candidate execution strategies (B+Tree, ART, cracked column, full scan) for resolving a query
Access-path selection
the process of choosing among access paths by comparative cost, per Selinger et al. 1979
Selectivity
the fraction of rows matching a given predicate
Cost model
the set of equations estimating execution cost for each access path given selectivity and structure state
B+Tree
a balanced, ordered tree structure supporting logarithmic point lookup and efficient range scan
Latch
a short-duration mutual-exclusion primitive protecting a page or node during a structural operation
Latch coupling
holding a parent and child latch simultaneously across a descent handoff to prevent phantom traversal
Blink tree
a B+Tree variant with right-sibling links tolerating a temporarily-stale separator during concurrent splits
Optimistic lock coupling (OLC)
a concurrency protocol validating a generation counter after an unlatched read rather than holding a latch throughout
Prefix compression
storing a page-level shared key prefix once and only the differing suffix per entry
ART
Adaptive Radix Tree, a main-memory trie structure with four node types sized to their fan-out
Node growth
the ART's transition from a smaller node type to a larger one as its child count increases
Path compression
collapsing a chain of single-child nodes into one node carrying the shared key path
Lazy expansion
deferring the creation of branching nodes until a key's uniqueness is broken by a later insert
Histogram
an equal-depth bucketed summary of a column's value distribution used for selectivity estimation
Sketch
a probabilistic summary structure (e.g. HyperLogLog) estimating cardinality with bounded error
Cardinality estimation
predicting the number of distinct or matching values for a predicate from statistics
Hybrid OLTP/OLAP
an access-method design serving both transactional point access and analytical scan access from shared structures
Tiered storage
organizing data across hot, warm, and cold storage media by access frequency
Compaction
the background process of reorganizing and moving segments across storage tiers or LSM levels
Read amplification
the ratio of physical bytes/levels read to logical bytes needed to answer a query
Write amplification
the ratio of physical bytes written to logical bytes of new data
Space amplification
the ratio of physical storage consumed to logical data size
Column store
a storage layout organizing data by column rather than by row
Learned index
an access method replacing a tree structure with a model predicting approximate record position
Copy-on-crack
the isolation technique of operating a crack step on a private piece copy published atomically
Concurrency token
a monotonically increasing counter used to detect concurrent structural changes during optimistic reads
Fence key
the low/high key bound stored on a B+Tree page delimiting its valid key range
Tombstone
a marker recording a logical deletion pending physical cleanup
Backpressure
an explicit signal that causes upstream producers to slow down when a downstream stage is saturated
Admission control
rejecting or deferring new requests when system capacity is exceeded
Structural verifier
a diagnostic routine walking a structure to confirm its invariants hold
Differential testing
comparing this system's output against a reference implementation's output on shared inputs
Convergence benchmark
the named CI gate measuring queries-to-refinement on standard skewed workloads
Workload-shape detector
the component classifying a query stream as stable/wide or unpredictable/narrow to drive strategy selection
Generation
a version counter on a snapshot (statistics, ART node) indicating how many times it has changed
Staleness bound
the maximum age or write-count a statistics snapshot may reach before it is considered untrustworthy
Access-method interface
the trait-based protocol boundary between the host engine and this project's index engines
