chronodb-server is the trust and process boundary: it authenticates/limits ingestion (cardinality_guard, T1/T3) and terminates the query API. chronodb-wal is the durability boundary — no sample is acknowledged until its WAL record is fsynced (P5, I5). chronodb-storage is the persistence and concurrency boundary: head.rs is the only mutable structure in the system (P1); block.rs/manifest.rs are strictly immutable once written (I10); compactor.rs and retention.rs run as background, throttleable workers (P7) that never hold locks the ingest path needs. chronodb-index is shared, read-mostly state consulted by both ingestion (series lookup/creation) and query (label selection); it is the cardinality-economics chokepoint (P4). chronodb-codec is a pure, allocation-free library with no knowledge of blocks, WAL, or index — it only knows bytes in, bytes out (testable in isolation, §14). chronodb-rollup is a downstream reader/ writer that treats persisted blocks as its only input, guaranteeing rollups never touch the mutable head (P10).

8. Domain Model / Protocol / Data Model

8.1 Ingestion grammar (line-protocol-style, EBNF)

sample      ::= metric labels? SP value SP timestamp
metric      ::= identifier
labels      ::= "{" label ("," label)* "}"
label       ::= identifier "=" quoted_string
value       ::= float
timestamp   ::= int64            (* unix millis, ADR-18 *)
identifier  ::= letter (letter | digit | "_")*

Conforms to the shape of both the OpenMetrics exposition format and InfluxDB line protocol (§5, RFCs/Specifications); chronodb-server::ingest.rs accepts either via a pluggable front-end parser, normalizing into the internal Sample/SeriesRef types (§11).

8.2 Chunk wire layout (Gorilla-style, per series, per chunk)

Field Width Notes
magic 2 B format sentinel
encoding 1 B 0x01 = delta-of-delta+XOR (ADR-03/04)
num_samples varint count in this chunk
first_ts 8 B absolute i64 millis
first_value 8 B absolute f64 bits
ts_stream bitstream delta-of-delta encoded, samples 2..n
val_stream bitstream XOR encoded, samples 2..n
crc32c 4 B trailer, covers all preceding bytes

Worked example (5 samples, 15 s nominal interval, one late sample):

i ts (ms) Δ ΔΔ ts bits written value XOR-vs-prev bits
0 1000000 — — 64 (absolute) 10.0 64 (absolute)
1 1015000 15000 — varint(15000) 10.0 0 (identical)
2 1030000 15000 0 0 (1 bit, "same delta") 10.1 control+meaningful-XOR bits
3 1045200 15200 200 control+varint(200) 10.1 0
4 1060000 14800 -400 control+varint(-400) 9.9 control+meaningful-XOR bits

Malformed-input example: a chunk whose num_samples disagrees with the bit-length implied by decoding the streams to exhaustion — rejected by chunk.rs decode with ChunkError::LengthMismatch, never partially returned (ties to I10).

Failure-path example: process crashes after the WAL fsync for sample i=4 but before head.rs updates its in-memory chunk buffer — on restart, replay.rs re-applies the WAL record for i=4 to a freshly-initialized head, producing the identical chunk buffer state (I14) — no data loss, no duplication.

8.3 WAL record framing

Field Width Notes
len 4 B record body length
type 1 B Series / Samples / Tombstone / Checkpoint
body len B type-specific payload (§11)
crc32c 4 B covers type+body (I4)

8.4 Head-block lifecycle (state machine)

State Entered when Exits to Trigger
Empty process start, no head yet Active first sample appended
Active samples being appended Sealing time range boundary reached or memory ceiling near (P13)
Sealing flush in progress Persisted manifest write completes (I13 atomic swap)
Persisted flush complete Compacting (as input) compactor picks it up (P7)
Compacting selected as compaction input Superseded compaction output sealed (I6)
Superseded replaced by compaction output Reclaimable retention grace period (I7) elapses
Reclaimable grace period elapsed (deleted) janitor physical delete (P14)

blocks/01HK7.../
  meta.json      block time range, series/sample counts, checksums (P11)
  index          label→postings, series→chunk offsets (ADR-07/08)
  chunks         concatenated per-series chunk streams (§8.2)
