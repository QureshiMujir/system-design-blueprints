33. Hard Questions (Self-Examination)

  • Q1. If §17's WAL is the sole source of truth (P12) and §18's ANN graph is derived, why does §18 still need its own corruption validator instead of trusting §17's checksum coverage completely?
  • Q2. §4 sets a 220 GB hard RAM ceiling and §32's C2 shows 4 shards/node fits with headroom — what changes about that arithmetic once §29's 64-shard/collection scaling ceiling is approached across many collections on the same node?
  • Q3. §7's I5 (tenant isolation) is enforced at three independent layers per §21's MM7 — does that redundancy interact badly with §19's query cache, which caches compiled filters that already encode tenant scope?
  • Q4. §15's chunk determinism (I3) assumes a pinned tokenizer version — how does §25's two-major- version WAL-reader compatibility window interact with a tokenizer upgrade that must also stay replay-compatible per §21?
  • Q5. §20's context assembler truncates by reranker score when the token budget is exceeded — if §20.9 says the reranker can fail mid-batch and fall back to hybrid ordering, what score does truncation prioritize by during a fallback, and does §8.7's worked example still hold?
  • Q6. §28's M7 (Recall@10 > 0.93) is a fixed floor from §7's I11 — if §18.6's periodic graph rebuild is the only recovery path, what happens to §4's ANN p95 latency budget during a rebuild window on a live shard?
  • Q7. §13's metadata plane uses optimistic version locking; §17's vector store uses a single shard-local writer — why are these two concurrency models different, and does §7's I2 consistency scanner have to reconcile two different notions of "in-flight write" as a result?
  • Q8. §32's C9 assumes a 10 Gbps replication link for snapshot transfer — if §4's cross-zone RTT budget (5 ms) is exceeded during a multi-AZ snapshot ship, does §17's RTO in §4 still hold, and which of §23's failure classes would that show up as?
  • Q9. §6's P9 (storage correctness before ANN acceleration) gates §18 on §17's exit criteria — but §18.2 says HNSW lives inside vector-storage-engine, not a separate crate; does that make P9's phase gate enforceable in code, or only in process discipline?
  • Q10. §31 compares this system to Weaviate's embedded architecture — if §1.2's boundaries commit to owning storage directly (rejecting ADR-05's external-DB alternative), what §29 scaling ceiling would have to be crossed before that decision should be revisited?
  • Q11. §16's embedding-provider failover mirrors Dynamo's hinted-handoff intuition (§5) — but Dynamo assumes multiple replicas of the same data, while §16's providers are not replicas of each other (different models produce different embeddings) — where does that analogy actually break down in §16.6's drift-detection logic?
  • Q12. §21's canary-comparison mode diffs two EmbeddingVersions on the same query corpus — if §15's tokenizer pinning changed between those two versions, does §21.4's acceptance criterion still isolate the ranking-algorithm change from the tokenization change, or do the two effects get conflated?
  • Q13. §22's T6 (cross-tenant leakage) and §7's I5 name the same failure — why does §23 not list a corresponding FM-# row, and should it?
  • Q14. §27's canary release process reuses §21's evaluation-runner comparison mode — if a canary regresses on §28's M3 (p99) but not on §28's M7 (recall), does §27's promotion gate catch it, or does it only compare ranking quality?
  • Q15. §9's ADR-23 locks HNSW over IVF-PQ for recall reasons — at what point does §32's C2 RAM arithmetic, extrapolated past the 64-shard ceiling in §29, cross into the "beyond 1B vectors/ collection" regime where ADR-23's own rejected-alternative column says IVF-PQ wins?
  • Q16. §6's P3 (immutable lineage) and §13's retention-policy jobs both touch document/chunk deletion — when a tenant issues a compliance-driven hard-delete request, which of these two mechanisms is authoritative, and does §35's deferred-features register need an entry for true hard-delete if it currently only supports tombstoning (I9)?
  • Q17. §18's tombstone-skipping traversal and §17's WAL truncation policy both reference "covered by a verified snapshot" — could a tombstone be truncated from the WAL before the ANN graph has actually applied it during a slow rebuild, and what would §23's forensics reveal if so?
  • Q18. §31's comparison table lists Elasticsearch's near-real-time refresh-interval consistency as a contrast to this system's hybrid coordinator — given §19's deterministic RRF fusion (I8), does a freshly-ingested-but-not-yet-ANN-indexed chunk create an analogous "not yet visible" window here, and which §4 latency budget would that window need to respect?

30. Mental Models & First Principles

  • MM1 — WAL Is Truth, Everything Else Is a View. Compressed insight: the ANN graph, the lexical index, and even query-time caches are all rebuildable projections of the WAL + metadata plane · Predicts: a corrupted derived index is always recoverable without data loss · Bug class avoided: treating index corruption as a data-loss incident instead of a rebuild-time incident · applies in §17 and §18.
  • MM2 — Determinism Is a Debugging Feature, Not a Purity Test. Compressed insight: replayability (P1, P10) exists to make incidents diagnosable, not to satisfy an abstract correctness aesthetic · Predicts: any non-deterministic code path becomes the first place an on-call engineer gets stuck · Bug class avoided: shipping an "obviously fine" random tie-break that later makes a regression unreproducible · applies in §21.
  • MM3 — Backpressure Converts Overload Into Latency, Not Loss. Compressed insight: a bounded queue turns a burst into queuing delay; an unbounded queue turns it into an OOM · Predicts: the system degrades gracefully (slower) under load rather than catastrophically (crashing) · Bug class avoided: an unbounded channel that "worked in testing" because testing never generated a burst · applies in §12 and §20.
  • MM4 — Metadata Authority Makes Corruption Detectable. Compressed insight: if the metadata plane is trusted and the index is derived, any divergence between them is by definition a bug, not an ambiguity · Predicts: consistency scanners (I2) can run continuously without a human deciding what "correct" means each time · Bug class avoided: treating metadata/index disagreement as "eventually consistent, ignore it" · applies in §13 and §18.
  • MM5 — Tail Latency Is a Distribution, Not a Number. Compressed insight: p50 and p99 are answering different engineering questions (typical experience vs. worst-case budget) · Predicts: optimizing only p50 can make p99 worse (e.g. a cache that helps the common case but adds a miss penalty) · Bug class avoided: shipping a "faster on average" change that blows the p99 SLO · applies in §28.
  • MM6 — A Fixed Recall Floor Turns Silent Regressions Into Loud Ones. Compressed insight: recall is not self-evidently visible the way latency is — a system can be "working" (responding fast) while quietly returning worse results · Predicts: any recall regression without I11's floor check ships undetected until a user notices · Bug class avoided: judging retrieval health by latency dashboards alone · applies in §18 and §21.
  • MM7 — Two Independent Enforcement Points Beat One Correct One. Compressed insight: tenant isolation (I5) enforced only at the filter layer is one bug away from a leak; enforcing it redundantly at filter, routing, and cache makes a leak require simultaneous bugs in all three · Predicts: defense-in-depth costs a small constant overhead and buys a large reduction in single-point-of-failure risk · Bug class avoided: a single well-reviewed filter check being treated as sufficient · applies in §21.
  • MM8 — Derived State Should Never Outlive Its Source of Truth's Confidence. Compressed insight: an ANN graph or lexical index that has drifted from its metadata source should be rebuilt, not patched · Predicts: patch-in-place "fixes" for derived-state corruption tend to recur because they treat a symptom · Bug class avoided: a growing pile of one-off index patches instead of a trusted rebuild path · applies in §18 and §19.

5. Required Reading

Books

  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 3, 5, 7, 11: replication, WAL semantics, consistency tradeoffs, stream processing; applied in §17 and §21.
  • Introduction to Information Retrieval — Manning, Raghavan & Schütze (2008), ch. 1–8: inverted indexes, term-at-a-time/document-at-a-time scoring, BM25, postings compression; applied in §19.
  • Database Internals — Alex Petrov (2019), ch. 4, 7–8: storage engines, LSM-style compaction, B-tree vs. log-structured indexing tradeoffs; applied in §17 and §18.
  • Systems Performance, 2nd Ed. — Brendan Gregg (2020), ch. 5–6, 13: flamegraph methodology, Linux syscall/scheduler tracing, USE method; applied in §28.
  • Rust Atomics and Locks — Mara Bos (2023), ch. 3–7: memory ordering, lock-free queues, condition-variable pitfalls; applied in §17 and §12.
  • Distributed Systems, 4th Ed. — Maarten van Steen & Andrew Tanenbaum (2023), ch. 6–8: consistency models, failure detection, coordination without global locks; applied in §22 and §29.

Papers

  • "Efficient and Robust Approximate Nearest Neighbor Search Using Hierarchical Navigable Small World Graphs" — Malkov & Yashunin, 2018, IEEE TPAMI: layered proximity graph construction and greedy-search traversal → informs graph layout and ef_search tuning; applied in §18.
  • "Billion-Scale Similarity Search with GPUs" — Johnson, Douze & Jégou, 2017 (Facebook AI): product quantization and IVF partitioning → informs the rejected-alternative comparison for ADR-23; applied in §18 and §31.
  • "ColBERT: Efficient and Effective Passage Search via Contextualized Late Interaction over BERT" — Khattab & Zaharia, 2020, SIGIR: late-interaction scoring → informs the rerank-vs-ANN cost tradeoff; applied in §20.
  • "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks" — Lewis et al., 2020, NeurIPS: joint retriever/generator training → foundational framing for the retrieval-then-generate pipeline this blueprint implements as infrastructure; applied in §3 and §20.
  • "SPLADE: Sparse Lexical and Expansion Model for First Stage Ranking" — Formal, Piwowarski & Clinchant, 2021, SIGIR: learned sparse term expansion → basis for the deferred learned-sparse retrieval feature; applied in §19 and §35.
  • "Dynamo: Amazon's Highly Available Key-value Store" — DeCandia et al., 2007, SOSP: consistent hashing, quorum reads/writes, hinted handoff → informs shard-routing and partial-availability posture; applied in §29.
  • "Bigtable: A Distributed Storage System for Structured Data" — Chang et al., 2006, OSDI: SSTable immutability and compaction → direct model for the vector store's segment/compaction design; applied in §18.
  • "The Probabilistic Relevance Framework: BM25 and Beyond" — Robertson & Zaragoza, 2009, Foundations and Trends in Information Retrieval: derivation and tuning of BM25's k1/b parameters → applied directly in the lexical scoring implementation; applied in §19.

Reference Implementations

  • quickwit-oss/tantivy — study src/postings and src/indexer/segment_updater.rs: segment lifecycle and postings-list layout; pitfall: do not copy its single-writer-per-index assumption wholesale, this blueprint needs shard-local concurrent writers; applied in §19.
  • apache/lucene — study core/src/java/org/apache/lucene/codecs: segment-merge policy and BM25 similarity implementation; pitfall: Lucene's merge-policy heuristics assume JVM GC pause tolerance this system cannot assume; applied in §19.
  • milvus-io/milvus — study internal/querynode and its segment-loading path: vector lifecycle and index-orchestration separation; pitfall: do not copy its fully-external-metadata-store pattern without the strong-consistency guarantee this blueprint requires (P12); applied in §17 and §18.
  • qdrant/qdrant — study lib/segment/src/index/hnsw_index: payload filtering fused into ANN traversal; pitfall: filter-fused traversal recall degrades under high-selectivity filters without the guardrails in §18.8; applied in §18.
  • vespa-engine/vespa — study searchcore/src/vespa/searchcore/proton: serving-node ranking pipeline and attribute-store design; pitfall: Vespa's rank-profile DSL is more general than this system needs — do not import its full expression language; applied in §20.

  • OpenTelemetry Specification v1.x — trace/span/metric data model and context-propagation rules pin down the correlation-ID contract used across every subsystem; applied in §12 and §24.
  • Prometheus Exposition Format — text-based metric exposition grammar pins down every crate's /metrics endpoint contract; applied in §12.
  • OCI Image Format Specification — container image layer/manifest contract pins down the reproducible-build guarantee behind ADR-16; applied in §27.

Glossary (§36) · 41 terms · site-wide glossary

ANN
approximate nearest-neighbor retrieval; trades exactness for bounded latency.
BM25
the probabilistic lexical-relevance scoring function used by the lexical index engine.
Canonicalization
the deterministic normalization process producing a Document's content hash.
Chunk
a deterministic retrieval fragment derived from a document's byte range.
Chunk lineage
the ancestry metadata linking a chunk back to its source document and hash.
Compaction
the background merge/cleanup process reclaiming space from tombstoned records.
Compaction amplification
the ratio of bytes rewritten during compaction to logical data size.
Correlation ID
see trace_id; the identifier propagated across every span for a request.
Cross-encoder
a reranker architecture scoring a query-document pair jointly, not independently.
Deadline budget
the per-query timeout allocated across the retrieval pipeline's stages.
Deterministic replay
re-executing a captured trace to reproduce identical output.
ef_search
the HNSW traversal-breadth parameter trading latency for recall.
EmbeddingVersion
the versioned identifier tying an embedding to its producing model/tokenizer.
Fanout plan
the per-shard execution plan produced by the retrieval planner.
Hinted handoff
Dynamo's technique for accepting writes during a temporary replica outage.
HNSW
Hierarchical Navigable Small World graph, the ANN index's graph structure.
Hybrid retrieval
combined lexical (BM25) and semantic (ANN) candidate retrieval.
Idempotency key
a deterministic key preventing duplicate effect from a retried operation.
Lease
a time-bounded ownership grant used by the scheduler for job assignment.
Metadata authority
the principle that the metadata plane, not any derived index, is ground truth.
Poison document
a malformed ingestion payload that would otherwise crash or hang a worker.
Postings list
the per-term list of document/chunk occurrences in the lexical index.
Prompt lineage
the provenance chain from an assembled prompt back to its source citations.
Quantization profile
the precision/compression scheme applied to a stored vector.
Recall@K
the fraction of true top-K relevant items actually retrieved.
Reciprocal Rank Fusion (RRF)
a rank-based method for merging heterogeneous ranked lists.
Replay fidelity
the property that replay reproduces identical output for deterministic input.
RPO
Recovery Point Objective; the maximum acceptable data loss window.
RTO
Recovery Time Objective; the maximum acceptable recovery duration.
Segment
an immutable unit of the lexical or vector index subject to compaction.
Shard
a partitioned unit of storage and query routing within a collection.
Snapshot
a checksummed, point-in-time persisted index state.
SPLADE
a learned sparse lexical expansion model, source of the deferred sparse-retrieval feature.
Tail latency
high-percentile (p95/p99/p999) request latency, tracked separately per stage.
Tenant isolation
the guarantee that no retrieval path returns cross-tenant candidates.
Tombstone
a deletion marker preventing a removed vector from reappearing after compaction.
Tombstone dominance
the invariant that tombstoned entries never resurface post-compaction.
top_k
the number of candidates requested from an ANN or lexical query.
Trace ID
the unique identifier propagated across every span of a single request.
WAL
Write-Ahead Log; the append-only durability mechanism preceding query visibility.
WAL amplification
the ratio of physical bytes written to logical bytes committed.
