Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. If you remove the seccomp filter but keep Landlock + user namespaces, what is the new smallest attack surface? What class of syscall-level exploit remains viable, and why does this violate MM3? (§6 P8, Phase 1, I8, ADR-003)
  2. A renderer sends a BrokerRequest with a valid CapHandle but requests rights that are a superset of those in its CapTable entry. Trace the full broker decision pipeline (Appendix D.4). Which check catches this, at which step, and which invariant/principle governs it? (§8.4, I3, I6, P4, ADR-010)
  3. Two frames — https://a.example.com and https://b.example.com — are in the same BrowsingInstance. Should they share a renderer process? Under what condition does sharing them violate I4? What is the exact SiteInstance computation that resolves this? (§8.1, I4, ADR-011, Phase 4)
  4. A renderer's seccomp filter is installed after clone but before Landlock. An attacker triggers a race in the child's setup code between namespace creation and filter installation. What is the attack window, and which ordering rule in Phase 1 closes it? (Phase 1, §1.2, I8, ADR-003, MM3)
  5. The broker's FileOpen handler canonicalizes the path using realpath. An attacker creates a symlink target after the realpath call but before the open call. Which invariant this violates, which phase's implementation note addresses it, and why passing the fd (not the path) eliminates the window entirely. (I9, Phase 2, §8.8, ADR-008, MM6)
  6. COOP same-origin is set on a document but COEP is absent. Can SharedArrayBuffer be enabled? Trace the cross-origin isolation check from §8.6 and the COOP/COEP table (Appendix E.5). Which pitfall in Phase 6 does this exercise? (§8.6, Phase 6, §6.6, Appendix E.5, ADR-014)
  7. A renderer floods the broker with 100 000 well-formed, policy-denied NET_FETCH_REQ frames per second. The broker denies each. Does this violate any invariant? What is the availability risk, and what mechanism from Phase 9 bounds it? (I3, I11, Phase 9, §9.2, §4 broker decision latency)
  8. A capability is minted for FileRead on fd=7. The renderer tab closes; the capability is revoked (epoch bumped). A new renderer tab opens; the broker reuses the same CapId integer for a new FileWrite capability. What happens if the old renderer process (in Dead state but not yet fully reaped) presents the stale CapHandle with the old epoch? Trace the epoch check. (§8.3, I6, Phase 3, Phase 9, MM8)
  9. The network process receives a response with Content-Type: text/html but the CORP header is absent. The requester is cross-origin, mode is no-cors. Which of CORP or ORB fires first? What is the decision, and what is the principle that governs blocking on doubt? (§8.6, Phase 6, Appendix E.3–E.4, I5, P7)
  10. A cross-site navigation is triggered mid-flight by a redirect that changes the destination Site. The commit has not yet occurred. At what exact point does the site isolation allocator re-evaluate the process assignment, and what is the failure mode if it waits until after commit? (Phase 4, §4.6, I4, ADR-013, §8.9)
  11. postMessage is sent from https://evil.example to a same-origin frame. The receiver checks event.origin. An attacker modifies the IPC frame in-transit to claim event.origin = "https://trusted.example". Why does this attack fail structurally? Which principle and invariant govern it, and where does the browser stamp the true origin? (I2, P5, Phase 5, §8.10)
  12. A broker dependency (seccompiler crate) receives a CVE for a privilege-escalation bug in its BPF compilation path. The broker uses it at policy-load time. What is the blast radius? Why does ADR-001 (Rust) reduce but not eliminate the risk, and what is the supply-chain gate that catches it before deployment? (ADR-001, ADR-023, ADR-025, Phase 11, Appendix C.7)
  13. Compare the information available to a Spectre attacker in (a) the pre-2018 single-process-per-tab Chrome model vs (b) this design's process-per-SiteInstance model. Quantify the difference in terms of co-resident data, and name the additional mechanism that closes the SharedArrayBuffer / high-res timer vector. (Phase 4, §4.9, §8.6, ADR-013, ADR-014, MM4)
  14. The policy grammar (§8.2) allows fs rw /tmp. A policy file is loaded that contains fs rw /. Which phase and mechanism ensure this policy fails to load rather than granting root filesystem write access, and what is the "fail closed" invariant at the policy-parse layer? (§8.2, Phase 2, I3, P7, ADR-004, MM2)
  15. An OS kernel version upgrade changes the seccomp BPF ABI: a syscall previously numbered 42 is renumbered 43. The old seccomp filter is still installed. What is the security outcome? Which pitfall from Phase 1 explicitly names this risk, and what process ensures the filter is re-validated on kernel update? (Phase 1, §1.6, I8, ADR-021, ADR-022)
  16. A renderer process exits cleanly (not a crash) while a BrokerRequest is in-flight. The broker has received the frame but not yet responded. Trace the exact cleanup path: which mechanism detects the exit, in what order are the capability and channel teardown operations performed, and what ensures the in-flight request is dropped rather than partially granted? (Phase 9, §9.2, I6, I7, I11)
  17. Site https://pay.example sets Cross-Origin-Opener-Policy: same-origin. A page on https://shop.example calls window.open("https://pay.example"). What happens to the opener reference, which new BrowsingInstance is created, and why does this matter for the process allocation in Phase 4? (Phase 6, §8.6, Phase 4, I4, ADR-013)
  18. Construct a minimal policy (using the §8.2 grammar) that gives a renderer read access to exactly one file (a user-picked temp file) and nothing else, and explain why the seccomp + Landlock layers together mean the renderer cannot act on that policy even if the IPC is bypassed. (§8.2, Phase 1, Phase 2, I8, P8, MM3, MM5)
  19. Why is SOCK_SEQPACKET preferred over SOCK_STREAM for the IPC channel, and over SOCK_DGRAM? What class of parser attack does SOCK_STREAM enable that SEQPACKET closes? (ADR-007, §8.4, Phase 0, §0.6, I7)
  20. A CapHandle is legitimately delegated from renderer R1 to renderer R2 with subset rights READ. R1 then closes its tab, causing its capabilities to be revoked (epoch-bumped). Does R2's delegated handle remain valid? Who holds the authoritative epoch, and what does this imply about the delegation record the broker must maintain? (Phase 3, Phase 9, §8.3, I6, ADR-010, MM8)

Mental Models & First Principles

  1. MM1 — Authority is a token you hold, not an identity you claim. Predicts: whether a compromised process can escalate by lying about who it is. Without it: you trust the renderer's claimed origin/pid/uid and every UXSS and forged-broker-request attack succeeds immediately. Applied: §6 P4/P5, §8.3, Phase 3 (capability model), Phase 5 (SOP at broker-tracked origins, I2).

  2. MM2 — Fail-closed dominates fail-open at every policy decision point. Predicts: the blast radius of a policy bug — a missing deny grants; a spurious deny inconveniences. Without it: any policy-engine bug, malformed-input path, or race condition silently becomes an allow, producing sandbox escapes rather than error messages. Applied: §6 P3/P7, §8.2, Phase 2 (deny-by-default broker, I3), Phase 10 (malformed-policy fuzz).

  3. MM3 — Defense in depth: every layer assumes the prior layer failed. Predicts: the minimum number of independent vulnerabilities an attacker needs to chain for a full escape. Without it: you design a single strong perimeter (e.g., the seccomp filter) and stop; one bypass yields total compromise. Applied: §6 P8, Phase 1 (seccomp + userns + Landlock stacked), Phase 7 (escape battery certifies the chain, Appendix C.2).

  4. MM4 — Address-space separation is the only robust defense against speculative side channels. Predicts: whether a Spectre gadget in one document can exfiltrate data from another. Without it: you rely on software-only gadget suppression (timer jitter, index_mask) and every future speculative-execution variant erodes the protection. Applied: §6 P6, Phase 4 (site isolation: one SiteInstance per process, I4), Phase 6 (COOP+COEP as the SAB gate, §8.6).

  5. MM5 — Complete mediation: every access to every protected resource must go through the policy check, every time. Predicts: whether there is an unguarded path to a resource. Without it: you build a broker but leave an ambient file descriptor, an environment variable, or an implicit channel that bypasses it — the broker is irrelevant. Applied: §6 P3, §8.4 (broker pipeline, Appendix D.4), Phase 2 (I12), Phase 3 (I1 zero ambient authority audit).

  6. MM6 — Parse, don't validate: derive structured data from hostile bytes on the trusted side before any decision. Predicts: whether a canonicalization or type-confusion bug in deserialization can produce a result that bypasses the subsequent policy check. Without it: the policy check sees a different (post-sanitize) value than the one that was acted on — classic TOCTOU of the data plane. Applied: §8.4 (IPC frame validation order), Phase 0 (bounded parse before decode), Phase 10 (origin/IPC/policy fuzz, I7/I9).

  7. MM7 — The trust boundary must be physically enforced, not logically assumed. Predicts: whether a "trusted" check in the renderer is meaningful. Without it: you write a check in the renderer (e.g., same-origin comparison, rate limiting) and congratulate yourself — an attacker with arbitrary code execution simply skips it. Applied: §6 P5, Phase 5 (SOP uses broker-tracked origins, I2), Phase 6 (Sec-Fetch set on trusted side), Phase 7 (all escape tests cross the actual OS boundary).

  8. MM8 — Capability revocation requires an epoch/generation counter, not just deletion. Predicts: whether stale capability handles that were already transmitted can be replayed after the capability is logically revoked. Without it: you delete the CapTable entry but the renderer already has a transmitted CapHandle index; it re-presents the index and the lookup finds nothing (good) — but if the table slot is reused, it hits the new entry (use-after-free of authority). Applied: §8.3 (epoch field in Capability), Phase 3 (stale-epoch tests, I6), Phase 9 (epoch-bump on crash teardown).

  9. MM9 — The isolation key (Site) must be coarser than the identity key (Origin) by exactly the intended scripting boundary. Predicts: whether two origins that can already script each other are needlessly split into separate processes (waste) or two origins that cannot script each other share a process (Spectre exposure). Without it: using Origin for isolation over-fragments memory; using just host for isolation under-isolates (co.uk confusion). Applied: §8.1 (Origin vs Site, ADR-011), Phase 4 (SiteInstance = Site + BrowsingInstance, I4), Phase 5 (SOP uses Origin; isolation uses Site).

  10. MM10 — A deny-by-default policy with an explicit positive grant table is equivalent to capability theory at the policy level. Predicts: whether any untested combination of policy clauses can produce an implicit allow. Without it: you write a deny rule for "bad things" and an allow rule for "good things" — your allow list has gaps, and policy complexity means you missed a path. The empty grant set is the safe state. Applied: §6 P3, §8.2 (policy grammar: every line is a positive grant; empty ⇒ deny-all), Phase 2 (I3), Phase 10 (policy fuzz).

Books / Primary Docs

  • The Chromium Sandbox design docs (sandbox/, "Sandbox" + "LinuxSUIDSandbox"/seccomp-bpf, "Site Isolation" design) — the normative architecture. The project's backbone. → applied in §3, Phase 0, Phase 1, Phase 2
  • Saltzer & Schroeder, "The Protection of Information in Computer Systems" (1975) — least privilege, complete mediation, fail-safe defaults — the principles this system instantiates. → applied in §6, Phase 2, Phase 3, Appendix G
  • Miller, Robust Composition (capability security, 2006) — capability-based security, no ambient authority — the IPC model. → applied in §8.3, Phase 3, Phase 2
  • Reis, Moshchuk, Oskov, "Site Isolation" (USENIX Security 2019) — why + how process-per-site defends against Spectre + UXSS. → applied in §6 principle 6, Phase 4, Appendix C.5
  • Barth, "The Web Origin Concept" (RFC 6454) — origins, the same-origin policy foundation. → applied in §8.1, Phase 5, Appendix E.1
  • Fetch + CORS + CORP/COOP/COEP specs (WHATWG/W3C) — cross-origin resource policies + isolation. → applied in §8.6, Phase 6, Appendix E.3–E.5
  • Kerrisk, The Linux Programming Interface — namespaces, seccomp, capabilities, fd passing (the OS mechanisms). → applied in Phase 1, Phase 3, Appendix D.2
  • Provos, "Improving Host Security with System Call Policies" (Systrace, 2003) — syscall-policy sandboxing lineage. → applied in Phase 1 pitfalls, Phase 2 pitfalls, §1.6
  • Klabnik & Nichols, The Rust Programming Language — ownership/types for capabilities + unsafe for syscalls. → applied in ADR-001, ADR-006, Phase 0

Glossary · 42 terms · site-wide glossary

Renderer
The untrusted process running web content (#305) + attacker JS; assumed compromised (principle 1).
Broker
The privileged trusted process that performs mediated privileged ops on behalf of children (deny-by-default, I3).
Browser process
The top-level trusted process (UI + broker role); the root of authority.
Network process
Semi-trusted process performing fetches + enforcing origin/CORP/ORB/CORS/COOP/COEP (I5).
GPU/Utility process
Role-scoped sandboxed processes for GPU work / misc tasks.
Trust boundary
The renderer↔broker (and renderer↔network) IPC line; every crossing value is hostile (principle 5).
Sandbox
The OS cage confining a process: seccomp-bpf + user namespaces + Landlock (Linux); job/AppContainer (Win); Seatbelt (mac).
seccomp-bpf
A kernel syscall filter; a per-role allowlist denying all else (I8).
User namespace
An unprivileged Linux isolation primitive (uid/pid/net/ipc separation).
Landlock
An unprivileged Linux LSM for per-process filesystem restriction (ADR-004).
Capability
An unforgeable, broker-minted handle = reference + rights; the only authority a renderer has (I6, principle 4).
CapTable
The per-process server-side table mapping CapId→Capability; the source of truth for authority.
CapHandle
The index a renderer holds + passes over IPC (not the Capability itself).
Ambient authority
Authority derived from identity/env (cwd, uid, a path); a renderer has none (I1, principle 4).
IPC
Inter-process communication; here a typed, length-prefixed SEQPACKET channel with fd passing (ADR-007/008/009).
SCM_RIGHTS
The Unix ancillary-data mechanism for passing file descriptors (handles) across a socket (I6).
Origin
The (scheme, host, port) tuple; the Same-Origin-Policy key (RFC 6454).
Site
(scheme, eTLD+1); the isolation key (coarser than Origin).
eTLD+1 / registrable domain
The domain one level below the effective TLD (via the PSL); defines a Site.
PSL
Public Suffix List; the data mapping host → eTLD+1.
SiteInstance
A Site within a BrowsingInstance; one renderer process (I4).
BrowsingInstance
A set of windows that can script each other (window.open/frames).
Site isolation
Process-per-SiteInstance; the structural Spectre defense (no cross-origin co-residency, principle 6).
OOPIF
Out-of-process iframe; a cross-site frame in its own renderer process.
Same-Origin Policy (SOP)
The rule that script/DOM/storage access is allowed only same-origin (I5).
CORP
Cross-Origin-Resource-Policy; gates which renderers may receive a response's bytes (I5).
CORB / ORB
(Cross-Origin Read Blocking) / its successor Opaque Response Blocking; blocks cross-origin no-cors HTML/JSON/XML.
CORS
Cross-Origin Resource Sharing; the opt-in cross-origin read protocol.
COOP
Cross-Origin-Opener-Policy; severs cross-origin opener relationships (new BrowsingInstance).
COEP
Cross-Origin-Embedder-Policy; requires CORP/CORS on subresources (the embedding gate).
Cross-origin isolation
COOP same-origin + COEP require-corp ⇒ crossOriginIsolated ⇒ SharedArrayBuffer/high-res timers (Spectre-safe).
Sec-Fetch
Request-metadata headers (Site/Mode/Dest/User) the browser stamps (a renderer can't forge them, I2).
Spectre
A speculative-execution side channel that reads co-resident memory; defended structurally by site isolation.
UXSS
Universal XSS; a same-origin-policy bypass — what origin/site confusion causes.
TOCTOU
Time-of-check-to-time-of-use race; avoided by open-then-validate + canonicalize-first (I9).
Verdict
The broker's per-request decision: Allow / Deny / Kill (deny-by-default, I3).
Quarantine
The fail-closed state for a misbehaving renderer (stop honoring requests, then kill, principle 7).
Escape
A compromised renderer reaching authority it shouldn't; the project's defining failure (must be 0).
Escape battery
The escape/** suite of attacks that must fail; the primary release gate (ADR-021).
Deny-by-default
No request is allowed unless an explicit grant matches (I3, principle 3).
Fail-closed
On any uncertainty/error/malformed input, deny — never grant (principle 7).
Least authority (POLA)
Each process gets the minimum capability for its role (principle 2).
