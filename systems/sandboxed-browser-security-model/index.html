3. Architectural Overview

                         ┌──────────────────────────────────────────────┐
                         │ BROWSER / BROKER PROCESS  (PRIVILEGED, trusted)│
                         │  bsm-broker: deny-by-default policy engine     │
                         │  owns: real file/net/GPU access, process mgmt, │
                         │        site→process allocation, origin policy  │
                         └───────┬───────────────────────┬────────────────┘
            capability-passing IPC│ (bsm-ipc, typed, fd/handle passing)    │ privileged ops on request
        ┌─────────────────────────▼──────┐   ┌──────────────────────────────▼─────────┐
        │ RENDERER PROCESS (UNTRUSTED)    │   │ NETWORK PROCESS (semi-trusted)          │
        │  runs #305/#266 + attacker JS   │   │  origin checks; CORP/COOP/COEP; fetch    │
        │  SANDBOX: seccomp-bpf + userns  │   │  SANDBOX: narrower (net syscalls only)   │
        │  + Landlock (no fs); no ambient │   │  hands bytes to renderer per policy      │
        │  authority — only IPC handles   │   └──────────────────────────────────────────┘
        │  ONE site-instance per process  │
        └───────┬─────────────────────────┘
                │ all syscalls filtered ──► seccomp denies → broker request via IPC
        ┌───────▼───────────────────────────────────────────────────────────────────────┐
        │ bsm-sandbox  OS SANDBOX POLICY  seccomp-bpf allowlist | userns | Landlock/fs    │
        │  (Os seam: win job-object/AppContainer, mac Seatbelt)                           │
        └───────────────────────────────────────────────────────────────────────────────┘
        ┌───────────────────────────────────────────────────────────────────────────────┐
        │ bsm-origin / bsm-policy  SECURITY POLICY                                        │
        │  Origin + SiteInstance model; Same-Origin Policy; site-isolation process map;   │
        │  CORP/COOP/COEP; capability grants (deny-by-default least authority)            │
        └───────────────────────────────────────────────────────────────────────────────┘
                │ trust boundary (red line) = renderer↔broker ; renderer↔network
        ┌───────▼───────────────────────────────────────────────────────────────────────┐
        │ GPU / UTILITY PROCESSES  (varying trust)  sandboxed per role; brokered access   │
        └───────────────────────────────────────────────────────────────────────────────┘

Per-box: Browser/broker (privileged) — the only process with real authority (files, sockets, GPU, spawning); runs no untrusted content; enforces policy on every child request (deny-by-default). Renderer (untrusted) — runs the web payload (#305) + attacker-controlled JS; assume it is compromised; it has no ambient authority — it can only do what its sandbox allows (compute) + what it can request over IPC (mediated). Network process (semi-trusted) — performs fetches, enforces origin/CORS/CORP/COOP/COEP so cross-origin bytes never reach a renderer that shouldn't see them. Sandbox policy — the OS-level cage: a seccomp-bpf syscall allowlist, user namespaces, and Landlock filesystem restriction (with an Os seam for Windows/macOS). Security policy — the web-platform layer: Origin/SiteInstance model, Same-Origin Policy, the site→process allocation that makes site isolation real, and the cross-origin resource policies. GPU/utility — additional roles, each least-authority + brokered. The trust boundary (renderer↔broker, renderer↔network) is the red line every message crosses and every check defends.

8. Domain Model

The domain has two layers: (a) the web-platform security model — Origin/Site/SiteInstance, Same-Origin Policy, CORP/CORB-ORB/COOP/COEP — enforced on the trusted side; (b) the OS/process security model — ProcessRole, the sandbox cage, and capability-passing IPC across the renderer↔broker trust boundary. The renderer is the adversary; everything below is the containment contract.

8.1 Origin / Site / SiteInstance (the isolation key)

Origin   = (scheme, host, port)                      (RFC 6454 tuple origin)   — SOP key
Site     = (scheme, registrable-domain)              (eTLD+1 via PSL)          — isolation key
SiteInstance = a Site + a BrowsingInstance id        — one renderer process    (I4)
BrowsingInstance = set of windows that can script each other (window.open, frames)
  • Origin is finer than Site: https://a.example.com and https://b.example.com are same-site, cross-origin. SOP uses Origin; site isolation uses Site (so related subdomains can share a process when they can already script each other).
  • One SiteInstance per renderer process (I4). A cross-site iframe ⇒ out-of-process iframe (OOPIF) ⇒ separate process. The SiteInstance→Process map is the broker's allocation table.
  • opaque origin (sandboxed iframe, data:/blob: with no inheritor): a unique, unequal-to-everything origin; never same-origin with any other.

8.2 Policy grammar (EBNF — bsm-policy config that the broker loads)

policy        ::= { rule } ;
rule          ::= role-clause "{" { grant } "}" ;
role-clause   ::= "role" role-name ;
role-name     ::= "browser" | "broker" | "renderer" | "network" | "gpu" | "utility" ;
grant         ::= capability-grant | syscall-grant | fs-grant | net-grant ;
capability-grant ::= "allow" cap-kind [ constraint ] ";" ;     (* deny-by-default: no grant ⇒ deny *)
cap-kind      ::= "file.read" | "file.write" | "net.connect" | "gpu.submit" | "ipc.bind" ;
constraint    ::= "where" predicate ;
predicate     ::= "origin" "==" origin | "path" "under" path | "port" "in" port-set | "site" "==" site ;
syscall-grant ::= "syscall" "{" syscall-name { "," syscall-name } "}" ;   (* seccomp allowlist *)
fs-grant      ::= "fs" ( "ro" | "rw" ) path ;                              (* Landlock ruleset *)
net-grant     ::= "net" "{" addr-family { "," addr-family } "}" ;
origin        ::= scheme "://" host [ ":" port ] ;                        (* canonicalized first, I9 *)
  • Compiles to: a per-role seccomp-bpf program, a Landlock ruleset, and a capability grant table. Every line is a positive grant; the empty set ⇒ deny-all (principle 3, I3).
  • Parser is total: malformed policy ⇒ load fails closed (no process spawns) — never a partial/permissive policy (principle 7).

8.3 Capability model (unforgeable authority)

Capability = (id: u64 nonce, kind: CapKind, resource: ResourceRef, rights: Rights, epoch: u64)
  - minted only by the broker; held as an entry in a per-process CapTable
  - transferred only over IPC by handle index (never by name) — I6
  - backing object: an OS handle (fd on Linux, HANDLE on Windows) passed via SCM_RIGHTS
  - rights: subset-only delegation (a renderer cannot widen rights it was given)
  - epoch: bumped on revoke ⇒ stale capability use ⇒ deny

A capability is a reference + permission that cannot be guessed or forged (the id is a broker-side table index, not a value the renderer chooses). Ambient authority (cwd, env, uid, a path string) is never a capability (principle 4).

8.4 IPC message schema (typed, length-prefixed, fd-carrying)

IpcFrame  = | len: u32 (LE, ≤ MAX_FRAME=64KiB) | channel: u32 | seq: u64 | kind: u16 | nfds: u8 | flags: u8 | payload[len] |
            + ancillary: SCM_RIGHTS array of nfds file descriptors (≤ MAX_FDS=8 per frame)
Request   = BrokerRequest { op, args, requested_rights }                (renderer→broker)
Response  = BrokerResponse { verdict: Verdict, cap?: CapHandle, err? }  (broker→renderer)
Interface = a bound (channel, message-set) pair; binding requires a capability (no ambient channels)
  • Validation order at the broker boundary (every field is hostile, I2/I7): len ≤ MAX_FRAME → nfds ≤ MAX_FDS → kind in role's allowed set → channel bound to caller → decode payload (bounded) → canonicalize args (I9) → policy check (I3) → mediate op. Any failure ⇒ Verdict::Deny (+ optional kill), never grant (I7, principle 7).
  • Wire format is explicit-endian, fixed-layout; no language-native serialization with ambient type confusion. Unknown kind ⇒ deny (forward-compat = additive kinds only).

8.5 Process / trust-boundary state machine

            spawn(role,policy)        sandbox_install (seccomp+userns+Landlock)
  [Unborn] ───────────────────► [Launching] ───────────────────────────────► [Sandboxed]
                                     │ install fails                                │ bind initial cap (IPC chan to broker)
                                     ▼                                              ▼
                                 [Aborted]                                    [Running]
                                                                                   │ malformed IPC / policy violation / crash
                                                                                   ▼
                                                                              [Quarantined] ──kill──► [Dead] ──respawn tab──► [Launching]
  • A renderer can only ever be Sandboxed→Running; it has no path that grants authority outside brokered requests. Quarantined is the fail-closed sink (principle 7): the broker stops honoring its requests and kills it. A [Dead] renderer never affects the broker or siblings (I11, principle 12).
  • Transition Launching→Sandboxed is the point of no return: after seccomp install the child cannot un-sandbox itself (filters are inherited + irrevocable; no_new_privs set).

8.6 SOP / CORP / COOP / COEP decision tables

Same-Origin Policy (DOM/script/storage access):

Subject origin Object origin Access (DOM/storage)
O O (equal tuple) allow
O O′ (diff scheme/host/port) deny (I5)
O opaque deny
opaque anything deny

Cross-Origin-Resource-Policy (response gating in network process):

Cross-Origin-Resource-Policy requester relationship result
same-origin cross-origin block (I5)
same-site cross-site block
same-site same-site cross-origin allow
cross-origin any allow
absent + ORB-eligible type (HTML/JSON/XML) cross-origin no-cors block (ORB)
absent + opaque-safe (image/media) cross-origin no-cors allow (opaque)

COOP (process/browsing-context isolation, top-level):

Cross-Origin-Opener-Policy opener relationship result
same-origin cross-origin opener sever opener; new BrowsingInstance (new process)
same-origin-allow-popups cross-origin popup sever incoming
unsafe-none (default) — keep opener

COEP (embedding gate, enables cross-origin isolation + SharedArrayBuffer):

Cross-Origin-Embedder-Policy subresource CORP/CORS result
require-corp resource lacks CORP/CORS block
require-corp resource has CORP/CORS allow
credentialless no-cors sent without credentials
unsafe-none — normal

Cross-origin isolation = COOP same-origin AND COEP require-corp ⇒ document is isolated ⇒ crossOriginIsolated===true ⇒ SharedArrayBuffer + high-res timers permitted (the Spectre-safe gate, §6 principle 6).

8.7 Worked example — cross-origin fetch blocked

1. Renderer (origin https://app.example) runs attacker JS: fetch("https://bank.example/statement", {mode:"no-cors"})
2. Renderer has NO net capability → issues BrokerRequest{op:NetFetch, url, init, initiator=https://app.example} over IPC
3. Network process (trusted) performs the fetch; response carries Cross-Origin-Resource-Policy: same-origin
4. Origin check: initiator (app.example) ≠ resource origin (bank.example); CORP=same-origin ⇒ BLOCK (I5, table §8.6)
5. Response bytes are DROPPED at the network process; renderer receives an opaque/network error — never the bytes
   ⇒ even a fully-compromised renderer cannot read bank.example's response body (no co-residency, no leak)

8.8 Worked example — brokered file-open (TOCTOU-safe)

1. Renderer needs to read a user-picked file (file chooser handled in browser UI, NOT renderer)
2. Browser shows chooser; user selects /home/u/doc.pdf → browser mints Capability{file.read, fd=open(doc.pdf,O_RDONLY)}
3. Broker passes the fd to the renderer via SCM_RIGHTS (handle, not path) — I6
4. Renderer reads via the fd capability ONLY; it cannot open("/etc/passwd") (seccomp denies open*; no path authority — I8)
   ⇒ the renderer never names a path to the broker for opening; the trusted side opened it. No TOCTOU window (the fd
     is already bound to the inode the user chose; a later rename/symlink-swap cannot redirect it). I9 + principle 10.

8.9 Worked example — site-isolation process split (OOPIF)

1. Tab loads https://news.example (top-level) → SiteInstance A → Process P1
2. Page embeds <iframe src="https://ads.example"> (cross-site)
3. Allocator: ads.example is a different Site ⇒ new SiteInstance B ⇒ new Process P2 (OOPIF) — I4
4. P1 (news) and P2 (ads) share NO address space; cross-frame DOM access mediated by SOP across the process boundary
   ⇒ a Spectre gadget in P2 (ads) can only speculatively read P2's own memory — news.example data is not co-resident
     (principle 6 — the Spectre defense). Compositing of the two frames happens in the trusted GPU/browser process.

8.10 Malformed / attack examples (defense in action)

- Forged origin:     renderer sends BrokerRequest{initiator:"https://bank.example"} (lying about who it is)
                     → broker IGNORES renderer-claimed origin; uses the SiteInstance the broker assigned at spawn
                       (origin is broker-tracked state, never a renderer-supplied value) — I2, principle 5. Deny mismatch.
- Path traversal:    renderer requests file.read where path="../../etc/passwd" or "/home/u/doc/../../../etc/shadow"
                     → broker canonicalizes (realpath, resolve symlinks) BEFORE policy check; result escapes the granted
                       Landlock subtree ⇒ Deny (I9). (And renderers don't even get path-based open — §8.8.)
- Handle forge:      renderer crafts BrokerRequest referencing cap id=0x4141414141414141 it never received
                     → broker CapTable lookup miss (id is a server-side table key, not a guessable value) ⇒ Deny (I6).
                     Stale (revoked) cap: epoch mismatch ⇒ Deny.
- Malformed IPC:     frame len=0xFFFFFFFF (claims 4GiB), or nfds=200, or kind=0xDEAD (unknown), or truncated payload
                     → bounded checks (len≤64KiB, nfds≤8, kind∈role-set) fail ⇒ Deny + drop; repeated ⇒ Quarantine→kill.
                       Parser NEVER allocates from attacker length, NEVER grants on malformed (I7, principle 7).
- Syscall escape:    compromised renderer executes open("/etc/passwd"), socket(), ptrace(), execve()
                     → not in the seccomp allowlist ⇒ SIGSYS / EPERM (I8). It can only compute + use passed capabilities.
- Co-residency:      attacker forces two cross-site documents into one process (e.g., via a redirect race)
                     → allocator re-checks Site on every commit; cross-site commit in a single-site process ⇒ process swap
                       (BrowsingInstance/SiteInstance re-evaluation) before the document is committed (I4).

Design principles (§6)

  • P1 — Assume the renderer is fully compromised. Design every boundary as if attacker code already runs arbitrary instructions in the renderer. Violation: trusting any renderer-supplied value (origin claims, paths, handles) → instant escape/UXSS.
  • P2 — Least authority (POLA). Each process gets the minimum capability for its role; the renderer gets none ambiently. Violation: a renderer with a stray file capability turns a memory bug into file theft.
  • P3 — Deny-by-default, complete mediation. The broker denies every request not explicitly allowed by policy; every privileged op is mediated + checked. Violation: an unmediated path = an open door.
  • P4 — Capabilities, not ambient authority. Authority is an unforgeable handle passed over IPC, not something derived from identity/env. Violation: ambient authority (cwd, env, uid) is reachable by compromised code.
  • P5 — The trust boundary is the renderer↔broker IPC. All security checks live on the broker side; the renderer's claims are untrusted input. Violation: checking in the renderer = no check.
  • P6 — Site isolation: cross-origin data is never co-resident. A renderer process only ever holds data for one site; cross-site content lives in another process. Violation: Spectre/UXSS reads another origin's secrets from the same address space.
  • P7 — Fail safe + fail closed. A policy error, a malformed IPC message, or a broker uncertainty denies the request (and may kill the renderer), never grants. Violation: fail-open turns a bug into a breach.
  • P8 — Sandboxes are layered (defense in depth). seccomp + namespaces + Landlock + capability IPC + site isolation — no single mechanism is the only line. Violation: one bypassed layer = full compromise.
  • P9 — Minimize + audit the privileged surface. The broker is small, simple, and memory-safe; the attack surface a renderer can reach is enumerated + tested. Violation: a fat broker is a fat target.
  • P10 — Validate at the boundary, canonically. IPC messages + origins + paths are parsed/canonicalized on the trusted side before any decision. Violation: path-traversal/origin-confusion via un-canonicalized input.
  • P11 — Determinism + auditability of decisions. Every allow/deny is a pure function of (policy, request) and is logged. Violation: non-reproducible, unauditable security decisions.
  • P12 — A renderer crash is contained, not fatal. Killing/crashing a renderer affects only its tab; the broker + other renderers survive. Violation: one site DoSes the browser.
