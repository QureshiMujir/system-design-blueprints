Hard questions (§36)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does the Singleton bound force d = n − k + 1 for an MDS code, and where in this document is that bound actually exercised rather than merely asserted? (§8.1/§8.2 construction; §13.2 enumeration proof; §7 I1.)
  2. Why is Cauchy preferred over Vandermonde here, and under what regime would that choice reverse? (§9 ADR-01; §14 construction detail.)
  3. What breaks if the irreducible polynomial were changed from 0x11D to any other valid choice, and why does that make cross-library compatibility fragile? (§9 ADR-04; §5 Plank & Xu 2006.)
  4. Why is systematic encoding "free" on the read path, and what would non-systematic cost instead? (§6 P2; §8.4; §9 ADR-02.)
  5. Why is repair explicitly not the same operation as decode, and what would a consumer lose by conflating them? (§6 P5; §19.)
  6. How does LRC trade away the MDS property, and why does that force a different decoder code path than pure RS? (§21.6; §7 I1 vs. I10; §16.6.)
  7. Why does the SIMD shuffle-table approach parallelize GF multiplication when a naive per-byte loop cannot be autovectorized? (§17.2; §5 Plank-Greenan-Miller 2013.)
  8. What guarantees that every SIMD kernel and the scalar kernel produce byte-identical output, and what specific bug class would violate that guarantee undetected? (§7 I12; §17.9.)
  9. Why is the C ABI frozen at v1 rather than allowed to evolve, and what would the opposite choice cost early adopters vs. late ones? (§9 ADR-08; §28.)
  10. How does the Back-of-Envelope Capacity Model's repair-bandwidth chain (§35 items 4–6, 12) justify shipping LRC and Hitchhiker as sequential phases rather than building the hardest option (regenerating codes) first? (§9 ADR-07; §22.3; §37.)
  11. Why does the scrubber's default 14-day cycle exist, and what would halving it cost in bandwidth budget? (§4; §20.4; §35 item 3.)
  12. Why is the streaming encoder "a codec loop, not a codec mode," and what resumability guarantee depends on that framing? (§6 P6; §7 I14; §23.2.)
  13. What is the actual blast radius of a Matrix::invert logic bug, and which two independent tests together (not either alone) would catch it? (§14.9; §16.9; §7 I9.)
  14. Why does bitrot detection live in the codec rather than solely in the storage layer, given that duplicates the storage layer's own CRC? (§6 P7; §9 ADR-20; §7 I6.)
  15. Under what deployment regime would replication beat this entire erasure-coding design, and what real system embodies that choice? (§37 Alternative Architectures; §2.)
  16. Why is Hitchhiker's bandwidth saving conditional on storage-layer cooperation, and what happens if that cooperation silently isn't there? (§22.6; §26 FM-10.)
  17. How does the k+m ≤ 255 bound trace back to the field size, and what would have to change to lift it? (§9 ADR-03; §7 I7; §38 Deferred Register.)
  18. Why does this design freeze on GF(2^8) instead of adopting a rateless code (RaptorQ) that needs no fixed (k,m) at encode time? (§37; §5 RFC 6330.)

33. Mental Models & First Principles

  • MM1 — A GF(2^8) multiply is a shuffle, not a loop. Predicts SIMD throughput ceilings directly from register width. Bug class without it: writing a per-byte scalar loop and being surprised SIMD "doesn't help" because the shuffle-table restructuring was skipped. Applies at §17.
  • MM2 — Systematic code = identity block + parity block. Predicts that uncorrupted reads never touch the decoder. Bug class without it: routing every read through decode "for safety," destroying the entire throughput argument for P2. Applies at §8.4, §15.
  • MM3 — MDS means any k survive, by construction, not by luck. Predicts that correctness is provable by enumeration, not by hoping the matrix "happens to work." Bug class without it: trusting an unproven matrix construction and discovering a singular submatrix in production. Applies at §13.2, §7 I1.
  • MM4 — Repair is not decode. Predicts that a bandwidth-aware consumer needs a separate API. Bug class without it: always paying the full-k-shard-read cost even when LRC/Hitchhiker could have made it cheap. Applies at §19.
  • MM5 — Locality trades parity shards for bandwidth. Predicts the exact storage/bandwidth tradeoff curve LRC sits on. Bug class without it: treating LRC's extra parity shards as pure waste instead of a deliberate bandwidth purchase. Applies at §21.
  • MM6 — The codec has no opinion about storage. Predicts portability to embedded/WASM/any consumer. Bug class without it: accidentally coupling arithmetic code to a specific storage backend, making the library un-reusable. Applies at §11, P11.
  • MM7 — Determinism is the entire premise of conformance. Predicts that any non-deterministic path (a random tie-break, an uninitialized read) poisons every downstream differential test. Bug class without it: a flaky conformance suite that is trusted anyway. Applies at §18, P8.
  • MM8 — The field is exact; only the construction can be singular. Predicts that GF(2^8) arithmetic never has floating-point-style rounding error — every failure is a construction/logic bug, never numerical drift. Bug class without it: adding defensive epsilon-comparison code that has no meaning in an exact field. Applies at §8.6, §14.

Glossary (§39) · 34 terms · site-wide glossary

GF(2^8)
Galois Field of 256 elements; addition is XOR, multiplication is polynomial multiplication modulo an irreducible polynomial.
MDS code
Maximum Distance Separable code; achieves the Singleton bound d = n−k+1; Reed-Solomon is MDS, LRC is not.
Cauchy matrix
matrix with element (i,j) = 1/(x_i⊕y_j) for pairwise-distinct, non-zero sums; the production generator matrix (ADR-01).
Vandermonde matrix
matrix with element (i,j) = x_i^j; the textbook construction, the differential-testing reference here.
Systematic code
a code whose first k shards are the unmodified original data.
Shard
one of the k+m byte-slices an encoder produces.
Data shard
an unmodified original-data shard (indices 0..k).
Parity shard
a computed redundancy shard (indices k..k+m).
LRC (Local Reconstruction Code)
adds local parities so single-shard repair reads r ≪ k shards.
Azure-LRC
the Huang et al. (2012) LRC construction, (k,l,r) parameterized.
XORBAS
the Sathiamoorthy et al. (2013) alternative LRC construction.
Hitchhiker
a code that piggybacks repair traffic on scheduled degraded reads (Rashmi et al. 2014).
Regenerating code
a code achieving optimal repair bandwidth via sub-packetization; MSR and MBR are the two extreme points (Dimakis et al. 2010).
Repair plan
the minimum-cost sequence of reads/arithmetic to reconstruct a missing shard.
Bitrot
silent on-disk byte corruption, detected via per-shard CRC.
Scrubber
a background process verifying every shard's CRC on a schedule.
Singleton bound
the information-theoretic ceiling d ≤ n−k+1 on a code's minimum distance.
GFNI
Galois Field New Instructions; an Intel ISA extension providing native GF(2^8) multiply.
Shuffle table
the 16-entry SIMD lookup table implementing GF multiplication-by-constant via 4-bit-half decomposition.
Gauss-Jordan elimination
the row-reduction algorithm used to invert the decode submatrix over GF(2^8).
Primitive element
a field element (here 0x02) generating the entire multiplicative subgroup.
Irreducible polynomial
the modulus polynomial (0x11D) defining GF(2^8) multiplication.
Conformance bucket
a named group of related conformance tests in the harness.
CRC32C
the Castagnoli CRC-32 variant used for per-shard integrity (naming caveat in §15.6/ADR-20).
Zero-copy encode
the encode_into API writing directly into caller-owned buffers.
Frozen ABI
a C interface guaranteed never to change signatures within a major version (P10).
Locality group
a subset of data shards covered by one local parity in LRC.
Global parity
an LRC parity shard covering all data shards, used when local recovery is insufficient.
Piggyback bytes
Hitchhiker's small auxiliary repair data riding on a degraded-read response.
Chunk (streaming)
a fixed-size (default 4 MiB) unit of a streaming codec invocation.
Present-shard bitmap
the boolean vector indicating which of k+m shards are available at decode/repair time.
Submatrix selection
choosing k present shard indices to build an invertible decode matrix.
Fountain/rateless code
a code producing unbounded symbols where any sufficient subset reconstructs the input (contrast, §37 A4).
Storage amplification
the (k+m)/k overhead factor of an erasure-coded layout vs. raw data size.
