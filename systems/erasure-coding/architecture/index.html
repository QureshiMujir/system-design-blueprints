ec-core — the terminology lock (P1): every crate below imports these types and none redefines them. ec-gf256/ec-matrix — the arithmetic and linear-algebra substrate; pure, no_std-compatible (ADR-09), no I/O. ec-encoder/ec-decoder — the systematic Cauchy codec (P2); the trust boundary is "present-shard bitmap in, recovered bytes out." ec-simd — the sole unsafe boundary (P4); runtime-feature-detected, differentially tested against scalar (I12). ec-lrc/ec-hitchhiker/ec-repair-planner — the repair-bandwidth axis (P5); pluggable planners behind one trait. ec-streaming — a codec loop over chunks, not a new codec (P6). ec-ffi — the frozen v1 C ABI (P10), the only cross-language/cross-process boundary besides the optional ec-proto gRPC surface (PhaseDeferred("§23") for hardening beyond the opt-in stub). ec-cli/ec-bin — the thin operator surface (P11): every flag maps to a library call.

8. Domain Model

8.1 GF(2^8) field arithmetic

Elements are bytes 0..255. Addition/subtraction: XOR (I3). Multiplication: table lookup via discrete log/antilog over the multiplicative group generated by primitive element 0x02, modulo the irreducible polynomial 0x11D (x^8+x^4+x^3+x^2+1, ADR-04). Two 256-entry tables (LOG[0..256], EXP[0..510], doubled to avoid modular wraparound in the lookup) — 512 B total, fits L1 (§4).

mul(a, b):
  a==0 or b==0        -> 0                      (special case, no log entry for 0)
  otherwise            -> EXP[ LOG[a] + LOG[b] ]  (index sum, no explicit mod 255 needed
                                                     given the doubled EXP table)
inv(a):  a==0 -> undefined ;  a!=0 -> EXP[255 - LOG[a]]

The above is a lookup relation, not executable control flow — the actual kernel is a table read, described fully as signatures in §11.

8.2 Cauchy generator matrix

An m × k matrix, element (i,j) = 1 / (x_i ⊕ y_j), x_i = i+k for i∈0..m, y_j = j for j∈0..k, GF(2^8) addition (XOR). Plank's choice (ADR-01); requires all x_i ⊕ y_j pairwise distinct and non-zero (I4).

8.3 Vandermonde reference matrix

(i,j) = x_i ^ j (field exponentiation) — the textbook construction, shipped as a differential-testing reference (P13), never the production default.

8.4 Systematic form

[ I_k ]              [ I_k  ]
[     ]  --invert-->  [       ]   where the top k×k block of the raw
[ P_m ]  top-k block  [ P'_m ]   Cauchy/Vandermonde matrix is inverted and
                                  multiplied through (§14.1).

8.5 Encoding as matrix multiplication

parity[m×L] = P'_m[m×k] · data[k×L] (L = shard length in bytes, GF(2^8) arithmetic throughout). Column-parallel: each output byte position is an independent length-k dot-product (P1, this is exactly what §17's SIMD shuffle parallelizes across bytes).

8.6 Decoding as matrix inversion

Given a present-shard bitmap, select any k present indices, form the k×k submatrix of rows {present indices} × cols 0..k, invert it (Gauss-Jordan, I9), multiply by the present-shard byte columns to recover all k data shards (§16.1).

8.7 State-transition table — codec lifecycle

State Trigger Next State Notes
Idle encode() called Encoding matrix already built at construction
Encoding matrix·data complete Encoded shards + headers emitted
Idle/Encoded decode() called VerifyingCrc I6 check per present shard
VerifyingCrc ≥k verified present SelectingSubmatrix else → Failed(Insufficient)
SelectingSubmatrix invertible found Inverting else → Failed(Singular), retry with new subset
Inverting inversion complete Reconstructing
Reconstructing multiply complete Decoded terminal, success
any unrecoverable error Failed(reason) terminal, DecodeError surfaced

8.8 Worked example — RS(2,1)

Data shards d0 = 0x03, d1 = 0x07. Cauchy row for m=1,k=2: coefficients [1,1] (the degenerate 1-parity case reduces to XOR). parity = (1·d0) ⊕ (1·d1) = 0x03 ⊕ 0x07 = 0x04. Losing d0: d0' = parity ⊕ d1 = 0x04 ⊕ 0x07 = 0x03 — recovered exactly (I1).

8.9 Malformed-input example

A shard header with magic != b"EC01" or payload_bytes > SHARD_PAYLOAD_MAX (§4) is rejected at ShardHeader::parse before any payload byte is read (I13) — this is the fuzz-harness (§18) primary target; a header claiming payload_bytes = u32::MAX must never reach an allocation call.

8.10 Failure-path example

Present bitmap has only k−1 verified shards (one failed CRC, I6, one genuinely absent). Decoder::decode returns DecodeError::Insufficient (I8) without attempting any matrix work — the state machine (§8.7) short-circuits at VerifyingCrc.
