Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why is a delete represented as diff = −1 rather than a tombstone, and what property does that preserve? (MM1 + §8 + Phase 1)
  2. When is it safe to emit an output at time t to a client, and what hangs if you emit too early? (MM3 + Phase 4 + §4.1 peek latency)
  3. Prove that two different arrival orders of the same updates yield identical materialized views. (MM1–MM2 + Phase 2 + I1)
  4. Why must both sides of a join be arranged, and what is the cost if one is not? (MM9 + Phase 8 + Capacity C7)
  5. How does compaction reduce memory without changing query answers, and what breaks if since advances past a live capability? (MM6 + Phase 6 + §4.1 arrangement memory)
  6. After a crash, what guarantees the recovered output equals the pre-crash output at the recovered frontier? (MM8 + Phase 12 + I10)
  7. Why is the dataflow loop single-threaded while the server is multi-threaded, and where is the boundary? (MM7 + §4.1 concurrency + Phase 13)
  8. What is the differential-testing oracle and why is it sufficient to catch operator bugs? (MM4 + Phase 14 + §4.1 correctness budget)
  9. Trace one input delta from WAL append through consolidation, arrangement update, join, to changefeed notification, naming each latency budget. (§3 + §4.1 + Phase 8 + Phase 11)
  10. Why does Noria's partial materialization win for web caches but lose for this engine's latency goals? (Comparative CA-2 + §4.1 + Alternative Architectures)
  11. How large can an arrangement grow transiently before compaction, and what does that imply for provisioning? (MM6 + Capacity C3 + §4.1)
  12. Why is logical time a lattice rather than an integer, and which operators require the partial order? (MM10 + §8.2 + Phase 4)
  13. What determines whether a reduce-heavy or join-heavy plan is the throughput bottleneck? (Capacity C7/C10 + §4.1 throughput)
  14. How does the changefeed avoid busy-spinning while still notifying within 2 ms? (§4.1 peek/changefeed + Phase 11 + Capacity C8)
  15. Why is full SQL and PG-wire compatibility deferred, and what would adding them cost architecturally? (Deferred Features Register + Comparative + §9 ADR)
  16. What is consolidation, and how does it bound memory under a workload that repeatedly inserts and deletes the same key? (MM2 + Phase 2 + §4.1)
  17. How does the WAL amplification factor of 1.5× arise, and what would push it higher? (Capacity C2 + Phase 12 + MM8)
  18. Why can 100 concurrent views exhaust memory even when each view is small, and what is the mitigation? (Capacity C9 + §4.1 max views + Deferred partial state)
  19. How does the frontier of an n-way join stay small, and when could it blow up? (MM3 + Capacity C12 + Phase 8)

Mental Models & First Principles

The compressed insights an expert in incremental view maintenance and differential dataflow holds. Each predicts a bug class. Every cited § resolves to a real heading.

MM1. A change is a value with a sign and a time, not an event. An Update is (data, time, diff) where diff ∈ ℤ; a delete is diff = −1, an update is −1 of the old plus +1 of the new. Predicts: operators are linear functions over a commutative group, so order of arrival is irrelevant. Bug without it: modelling deletes as side-effecting mutations breaks commutativity and makes replay non-idempotent. Applied: §8 (Update/Collection), Phase 1, I1.

MM2. Consolidation is the garbage collector of the difference world. Multiple (d, t, +1)/(d, t, −1) pairs at the same (data, time) cancel to zero and must be dropped. Predicts: memory stays proportional to the net multiset, not the gross update count. Bug without it: unbounded arrangement growth as canceling diffs accumulate. Applied: Phase 2 (consolidation), §4.1 (arrangement ≤ 1.1× after compaction), P7.

MM3. A Frontier is an antichain of times, and progress is its forward movement. The frontier is the set of minimal times that may still arrive; once it passes t, all data at t is final. Predicts: exactly when an output at t is safe to emit (peek fast path, §4.1). Bug without it: emitting results before the frontier closes → retractions visible to clients, or hanging peeks. Applied: §8.3 (Frontier state machine), Phase 4, P5, I-progress invariants.

MM4. Incremental == batch is the only correctness oracle that matters. For any input, feeding it incrementally must produce the exact multiset that re-running the whole computation from scratch would. Predicts: the differential testing strategy (Phase 14 fuzz, 10 M sequences). Bug without it: subtle operator bugs that only manifest after specific retraction interleavings ship undetected. Applied: Phase 14 (incremental==batch conformance), §4.1 (correctness budget), I1.

MM5. An Arrangement is an index shared by readers across logical time. A Trace keeps all versions of a keyed collection; many operators read the same arrangement concurrently without copying. Predicts: join memory is paid once per arrangement, not per consumer. Bug without it: re-indexing the same collection in every join → multiplicative memory blowup. Applied: §8 (Arrangement/Trace), Phase 6, P6, ADR-08.

MM6. Compaction is forgetting the past you can prove no one will ask about. Times below the since frontier can be coalesced to a single representative time. Predicts: the ≤ 1.1× steady-state memory (§4.1) and why advancing since too far breaks historical peeks. Bug without it: compacting below a live capability → wrong answers for in-flight queries. Applied: Phase 6 (logarithmic batch merge), I7, B6.

MM7. The dataflow loop is single-threaded on purpose; parallelism is across partitions. One operator graph runs on one worker; scale-out is by partitioning keys across workers, not by locking shared operator state. Predicts: zero hot-path contention and the work-stealing model (§4.1). Bug without it: sharing mutable operator state across threads → races and nondeterministic frontiers. Applied: Phase 5 (dataflow scheduling), §4.1 (concurrency model).

MM8. The WAL is the source of truth; arrangements are a derived cache. Committed input deltas are durable before ack; all in-memory state is reconstructable by replay. Predicts: I10 recovery equivalence and the ≤ 1.5× WAL amplification (§4.1). Bug without it: checkpointing arrangements without a replayable input log → unrecoverable corruption after a torn write. Applied: Phase 12 (WAL + recovery), P9, I10.

MM9. A join is two arrangements meeting at matching keys, delta-driven from both sides. Each side's new delta probes the other side's arrangement at the appropriate time. Predicts: the 100 K delta-pairs/sec budget and why both inputs must be arranged. Bug without it: re-scanning a full relation per delta → O(n) per update instead of O(matches). Applied: Phase 8 (incremental join), §4.1 (join throughput), Comparative Architecture (CA-1).

MM10. Logical time is a lattice, not a number line. Timestamps support a partial order with meet/join; concurrent times are incomparable, not "equal." Predicts: correct handling of nested scopes/iteration and multi-input operators. Bug without it: forcing a total order collapses concurrent updates and corrupts frontier math. Applied: §8.2 (partial-order timestamps), Phase 4, P4, B9 (Lamport).

Glossary · 37 terms · site-wide glossary

Antichain
A set of timestamps such that no element is less-than-or-equal to any other; a Frontier is an antichain; the minimal description of a progress lower bound.
Arrangement
Indexed, time-versioned shared state built from Batches; keyed by Key, holding (Val, Timestamp, Diff) sorted by key then time; shared read-only across operators (P6).
Batch
An immutable, compacted, time-sorted run of (Key, Val, Timestamp, Diff) records covering a contiguous key range; the unit of arrangement storage and merge.
Capability
A token granting an operator the right to emit updates at times ≥ some Timestamp; dropping all capabilities at a time advances the downstream frontier (P5).
Changefeed
A subscription emitting consolidated output Updates as the output frontier advances; monotonic, gap-free; the streaming interface to a maintained view (ird-query).
Collection
A multiset over D evolving in logical time; represented as a stream of Update<D> triples; the central abstraction of ird-collection.
Common sub-expression (CSE)
Two views sharing an intermediate operator's Arrangement rather than each computing it separately; implemented in ird-server to bound memory (P6).
Compaction
Merging Batches in a Trace below the since-frontier; times that can no longer be distinguished are collapsed, bounding trace size (I7, P7).
Consolidation
Group updates by (data, time), sum their Diffs, drop records where net Diff = 0; produces canonical multiset representation (I2).
Delta-join
The incremental join algorithm: for a new delta on one side, look up matching keys in the other side's Arrangement as-of the delta's time, emit product deltas; symmetric on both sides (Phase 8, I5).
Diff
Diff(i64) — the signed multiplicity of a record in a Collection; +1 = insert, -1 = retraction; multiplicities sum under consolidation (I8).
Differential dataflow
A computation model where operators consume and emit Collections of Update triples; work is proportional to input change, not total data size (P2); see McSherry et al., CIDR 2013.
Distinct
A stateful unary operator that outputs each record with multiplicity 1 whenever its input multiset is non-empty; correct under retractions (I6, Phase 7).
Frontier
An antichain of Timestamps representing the lower bound on future times an edge or operator may still produce; never moves backward (I3).
IVM (Incremental View Maintenance)
Maintaining a materialized view's output current by processing only the changes (deltas) to the base relations rather than recomputing the view from scratch.
InputHandle
The driver for a base relation: exposes send(Update), advance_to(Timestamp), flush; advances the base time frontier after a batch is flushed (ird-input).
Join (delta-join)
See delta-join. The central stateful binary operator; correctness across concurrent updates and retractions is I5.
Lattice
A partial order with join (least upper bound) and meet (greatest lower bound) operations on Timestamps; required for Frontier antichain arithmetic.
Logical time
A Timestamp drawn from a partially ordered set (lattice); not wall-clock; used to version updates and determine frontier completeness (P4).
Materialized view
A named query result stored as a maintained Arrangement; kept correct under input changes by incremental operators; exposed via peek and changefeed (ird-view).
Multiset
A set permitting duplicate elements; membership tracked by net Diff; the semantic domain for all Collections.
Negate
A stateless unary operator that flips the sign of every Diff; used to implement set difference as concat(A, negate(B)) (Phase 3).
Operator
A trait: consumes input Update batches and a Frontier, emits output Update batches and advances its output Frontier; stateless (map, filter) or stateful (arrange, reduce, join).
Peek
A point-in-time consistent read: returns the consolidated multiset of a view at a frontier-complete time t; equivalent to a from-scratch batch recompute (I1, I4, Phase 11).
Plan
An operator tree (Map, Filter, Join, Reduce, Distinct, Union, Negate) compiled from a SQL-subset view definition by ird-plan; the intermediate representation between SQL and ird-dataflow.
Progress protocol
The mechanism by which Capability tokens and ProgressMsg frontier updates propagate through the dataflow graph, allowing downstream operators to know when a time is complete (P5, ird-time).
Reduce
A stateful keyed operator: per-key fold producing output deltas as input deltas arrive; maintains input and output Arrangements; must emit correct retractions when input decreases (I6, Phase 7).
Retraction
An update with Diff = -1 (or negative); represents deletion or correction; every operator — including join and reduce — must process retractions correctly (P3).
Since-frontier
The lower bound on the compacted portion of a Trace; times below the since-frontier have been merged and are no longer distinguishable; queries at or after are unaffected (I7).
Threshold
A stateful unary operator that passes records only when their net input multiplicity meets a threshold; generalisation of distinct; correct under decrements.
Timely dataflow
A dataflow execution model with explicit timestamps and progress tracking via capabilities and frontiers; provides the coordination mechanism for differential dataflow; see Murray et al., SOSP 2013.
Timestamp
A member of the logical time lattice; defines the version of an Update; partially ordered; used to compute frontiers and as-of lookups in Arrangements.
Trace
Synonym for Arrangement in the implementation; an Arrangement's underlying indexed, compactable, time-sorted store of Batches (ird-arrange).
Update
Update<D> = (data: D, time: Timestamp, diff: Diff); the atomic unit of change in the system; all operators consume and emit sequences of Updates.
ViewDef
{ name, sql, plan, output_arrangement }; the registered specification of a materialized view in ird-view; the basis for building a dataflow subgraph and maintaining output state.
WAL (Write-Ahead Log)
Append-only log of input Update triples, written before arrangements are updated; the source of truth (P9); used in recovery to replay deltas from a checkpoint to a consistent frontier (I10).
Z-set
The DBSP formalism for a signed multiset (map D → ℤ); isomorphic to a Collection consolidated at a single time; the algebraic object differential operators act on (see Budiu et al., VLDB 2023).
