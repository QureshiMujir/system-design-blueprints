3. Architectural Overview

3.2 Subsystem Descriptions

ird-plan (SQL subset → differential plan). Accepts a CREATE VIEW SQL string; parses it into a relational AST; validates schema and type correctness; lowers each relational operator to a differential operator node (selection → filter, projection → map, equijoin → join, group-by/aggregate → reduce, distinct → distinct, union → concat); emits an Plan operator tree. Inputs: SQL text + schema catalog. Outputs: Plan (operator tree). No I/O, no state.

ird-input (base relation input handles). Owns one InputHandle per base relation. Accepts (Update, Timestamp) triples from the application or server layer; batches them by time; writes each batch to the WAL before forwarding into the dataflow; calls advance_to(t) to emit a ProgressMsg closing time t on that relation's output edge. Inputs: application delta stream. Outputs: Update batches + ProgressMsg into dataflow channels. Persistence boundary: WAL write happens here before dataflow entry.

ird-dataflow (operator graph + scheduling). Builds the physical operator graph from a Plan. Each Plan node becomes an Operator instance; edges become typed channels carrying (Update batch, ProgressMsg) pairs. A work-stealing or round-robin scheduler drives operators when input is available. Propagates ProgressMsg downstream when an operator's output frontier advances. Deterministic under any scheduling order (I9). Inputs: Plan, InputHandle connections. Outputs: operator instances + channel topology + scheduling loop.

ird-operator (stateless and stateful operators). Stateless: map, filter, flat_map, concat, negate — pure per-Update transforms, no operator state, commute with consolidation. Stateful: distinct, count, reduce, threshold — maintain a keyed Arrangement of input (and output for reduce) accumulated over time; on each input batch compute the delta between old and new output multiset and emit only that delta. Join (Phase 8) is a two-input stateful operator using two arrangements. Inputs: Update batches + frontier from upstream. Outputs: Update batches + frontier downstream.

ird-arrange (arrangements / traces). A Trace is an indexed, time-versioned multiset: a sequence of immutable, merge-sorted Batch objects keyed by Key, each entry (Val, Time, Diff). Supports as_of(t) cursor scans (sum diffs over times <= t) and key-range lookups. Shared across operators via Arc (one arrangement, many readers). Compaction merges batches below the since-frontier: any two times indistinguishable at or after the frontier are merged, bounding arrangement size (P7, I7). Inputs: Update batches from operators. Outputs: immutable Batch objects; cursor API for readers.

ird-time (frontiers + capabilities + progress protocol). Frontier is an antichain of Timestamp values: a compact lower bound on times an operator may still produce. Capability tokens grant the right to emit at times >= a given Timestamp; dropping a capability advances the frontier. ProgressMsg carries frontier updates along dataflow edges. An operator knows a time t is complete when its input frontier has advanced strictly past t on all input edges (I3, I5). Inputs: capability lifecycle events from operators. Outputs: ProgressMsg to downstream edges; frontier queries from operators and ird-query.

ird-view (materialized view manager). Registers ViewDef objects (name, SQL, plan, output arrangement). Builds the dataflow subgraph for each view. Maintains the output Arrangement as the output frontier advances. Multiple views may share upstream arrangements (P6, Phase 13 CSE). Exposes snapshot(view, t) returning the consolidated multiset at frontier-complete time t. Inputs: ViewDef registrations + dataflow output deltas. Outputs: maintained Arrangement; snapshot access API.

ird-storage (WAL + trace durability + recovery). WAL: append-only log of input Update triples (source of truth, I10, P9). Periodic checkpoints serialize arrangement Batch objects to disk. Recovery: load latest checkpoint, identify the consistent frontier, replay WAL tail from that frontier forward through the dataflow graph to reconstruct all arrangements. Recovery time is bounded by checkpoint interval. Inputs: Update triples from ird-input; Batch objects from ird-arrange. Outputs: WAL files + checkpoint files; recovery stream of Update triples.

ird-query (peek + changefeed). peek(view, t) blocks until the output frontier of view has advanced past t, then returns the consolidated multiset as_of(t) from the output arrangement — identical to a from-scratch batch recompute (I1, I4). changefeed(view) subscribes to consolidated output Update batches as the frontier advances: monotonic, gap-free, de-duplicated. Snapshot-to-changefeed boundary: a client may take a snapshot at t and then subscribe to all changes after t without missing updates. Inputs: output arrangement + frontier from ird-view. Outputs: PeekResult or Changefeed stream.

ird-server (define / insert / delete / peek / subscribe). TCP server exposing commands: DEFINE VIEW, INSERT INTO relation, DELETE FROM relation, PEEK view AT time, SUBSCRIBE view. Routes deltas to ird-input, view definitions to ird-plan + ird-view, reads to ird-query. Shares arrangements across overlapping views (CSE, Phase 13). Enforces admission + flow control. Exposes metrics: per-operator frontier lag, arrangement byte size, output-behind-input delta. Inputs: client TCP connections. Outputs: responses to peek/subscribe; metrics endpoint.

ird-cli (command-line driver). Thin binary over ird-server's client interface: define | insert | delete | peek | subscribe | explain subcommands. explain prints the operator plan for a view. Used for smoke tests and interactive development. Inputs: CLI args. Outputs: formatted table results or delta streams.

8. Domain Model

8.1 Update Triple — The Atomic Unit

Every change in the system is an Update<D>:

Field Type Invariant
data D (Row / (Key,Val)) immutable after creation
time Timestamp must be >= capability held by sender
diff Diff(i64) nonzero before consolidation

Semantics: the collection at time t = { d : Σ_{s≤t} diff(d,s) > 0 } with multiplicity equal to that sum. Diff conservation (I8): sum of all diffs for (data, times ≤ t) equals the net multiplicity at t.

Worked example — insert then delete:

Update { data: Row[1,"Alice",30], time: T1, diff: +1 }   // insert
Update { data: Row[1,"Alice",30], time: T3, diff: -1 }   // retract

At T2: multiplicity = 1. At T4: multiplicity = 0. Consolidation at T4 yields no entry (zero diff dropped per I2).

Malformed example:

Update { data: Row[1,"Alice",30], time: T1, diff: 0 }    // INVALID — zero diff; must be rejected at ingestion

8.2 Timestamp and Lattice

Timestamp is a partially ordered type forming a lattice:

Operation Signature Contract
join(a,b) (T,T)->T least upper bound; a ≤ join(a,b)
meet(a,b) (T,T)->T greatest lower bound
less_equal(a,b) (T,T)->bool antisymmetric, transitive, reflexive

For Phase 1–8, Timestamp is a single u64 epoch (total order). From Phase 9 onward, product timestamps (u64, u64) support multi-level time (outer = transaction epoch, inner = operator sub-step).

Lattice laws (tested via property tests in Phase 1):

  • join(a,a) == a (idempotent)
  • join(a,b) == join(b,a) (commutative)
  • join(a, join(b,c)) == join(join(a,b), c) (associative)
  • a ≤ b ↔ join(a,b) == b

8.3 Frontier / Antichain State Machine

States:       OPEN ──advance──> ADVANCED ──advance──> ... ──close──> CLOSED
Invariant:    frontier is always an antichain (no element ≤ another)
              frontier may only advance (I3 — monotone progress)
Event Precondition Postcondition Error
advance_to(t) t > all elements currently in frontier new frontier contains t FrontierRegressionError if t ≤ any current element
join(other_frontier) both valid antichains element-wise join; remove dominated none
close() any state frontier = {} (empty = "all times complete") none

An empty frontier means no future updates will arrive — all times complete.

Edge case — concurrent capability drops: when two capabilities at times T1, T2 are held and T1 is dropped first, the frontier becomes {T2}. If T2 is then dropped, frontier becomes {}. Any intermediate peek at T1 ≤ T2 must wait until frontier passes T1 before returning.

8.4 Collection Semantics

A Collection<D> is a stream of Update<D> triples. It is NOT a snapshot; it is a delta stream. The multiset at time t is computed by accumulation:

multiset(C, t) = { (d, n) | n = Σ_{(d,s,δ) ∈ C, s ≤ t} δ,  n ≠ 0 }

Consolidation: consolidate(batch) groups by (data, time), sums diffs, removes zero entries. Idempotent. Result satisfies I2.

Multiset equality: two collections A, B are equal at time t iff multiset(A,t) == multiset(B,t).

8.5 Operator State Machine and Execution Semantics

Each Operator advances through a fixed cycle:

IDLE ──input_available──> RUNNABLE ──scheduled──> RUNNING ──emit_output──> IDLE
                                                     │
                                                     └──frontier_advance──> FRONTIER_SENT
Operator kind Input state required Output produced Frontier held
Stateless (map, filter, flat_map, negate, concat) none per-update transform passthrough
Threshold / distinct keyed Arrangement of input output delta when net diff crosses 0/1 boundary delayed until input frontier advances
Count / reduce keyed Arrangement of input + output per-key retract-old / emit-new delta delayed
Join two Arrangements + both frontiers delta-join products meet of both input frontiers

Frontier propagation rule: output frontier ≤ min of all held input frontiers. An operator may not emit an update at time t without holding a capability at t.

8.6 Arrangement / Trace Layout

A Trace is the indexed, time-versioned state structure. Its storage layout:

  • Trace
    • ├── since_frontier: Frontier // times below which diffs have been merged
    • ├── upper_frontier: Frontier // upper bound on times present
    • └── batches: Vec<Batch>
  • Batch
    • ├── lower: Frontier
    • ├── upper: Frontier
    • ├── keys: sorted Vec<Key>
    • └── data: sorted Vec<(Key, Val, Timestamp, Diff)>
  • // sort order: (Key ASC, Val ASC, Timestamp ASC)

Cursor semantics: a cursor into a Trace yields (Val, Timestamp, Diff) tuples for a given Key, in (Timestamp ASC, Val ASC) order. Valid only while no compaction advances since_frontier past the cursor's time.

Compaction: merge all Batches whose upper ≤ new since frontier; consolidate diffs at merged times; drop zero entries. I7 guarantees query answers are unchanged at or after the new since frontier.

Shared-reference model: Arc<Mutex<Trace>> or epoch-based reader/writer. Multiple operators hold read handles; one writer (the arrangement operator) holds exclusive write access per epoch.

Batch merge rule (logarithmic merging): maintain O(log N) batches; merge two batches of equal size into one; ensures O(log N) lookup and O(N log N) amortized insert.

8.7 Delta-Join Execution Semantics (Incremental Join)

Given two arrangements A (key -> (val_a, time, diff)) and B (key -> (val_b, time, diff)), and an incoming delta ΔA at time t:

for each update (key, val_a, t, d_a) in ΔA:
    for each (val_b, s, d_b) in B.lookup(key) where s ≤ t:
        emit Update { data: join_fn(val_a, val_b), time: join(t,s), diff: d_a * d_b }

Symmetric for ΔB. The full join output equals A×B + ΔA×B + A×ΔB + ΔA×ΔB; the incremental form processes only the delta terms.

Correctness under retractions (I5): if d_a = -1 (retraction), the emitted products have negative diff, correctly retracting previous join outputs. No special case needed — diff algebra handles it.

Edge case — concurrent deltas on both sides at same time T: both ΔA and ΔB arrive at T. Processing ΔA against B (without ΔB) and ΔB against A (without ΔA) is correct because the ΔA×ΔB cross-term is counted when processing ΔA against the arrangement that already includes ΔB (if flushed first), or is emitted as a separate delta. The arrangement must be locked to a consistent snapshot per operator invocation.

Malformed path — missing retraction: upstream emits +1 at T1 but never emits -1 before re-inserting +1 at T3 → net multiplicity = 2; downstream join doubles output. Detected by I1 oracle (batch recompute yields multiplicity 1). Input handles must enforce: update = retract-old then assert-new.

8.8 Reduce / Distinct Correctness Model

reduce maintains per-key state:

input_arrangement:  Key -> multiset of Val at each time
output_arrangement: Key -> aggregate(Val) at each time

On input delta (key, val, t, d):

  1. Apply delta to input_arrangement[key].
  2. Compute new_output = aggregate_fn(input_arrangement[key].as_of(t)).
  3. Fetch old_output = output_arrangement[key].as_of(t).
  4. If new_output ≠ old_output: emit retraction (key, old_output, t, -1) + assertion (key, new_output, t, +1).

Edge case — aggregate goes to zero: COUNT(*) drops to 0. Must emit retraction of the 0-count row (if present) and suppress emitting a new 0-count row (SQL semantics: groups with count=0 disappear). Tracked by I6.

Distinct semantics: output multiplicity is always 0 or 1; positive input multiset → output +1; zero input multiset → output 0. Threshold at 1 over input arrangement.

8.9 SQL Subset Grammar (EBNF)

view_def    ::= "CREATE" "VIEW" ident "AS" select_stmt
select_stmt ::= "SELECT" proj_list "FROM" table_ref ("WHERE" expr)?
                ("GROUP BY" col_list ("HAVING" expr)?)?
              | select_stmt "UNION" ("ALL")? select_stmt
table_ref   ::= ident ("AS" alias)?
              | "(" select_stmt ")" "AS" alias
              | table_ref "JOIN" table_ref "ON" join_cond
proj_list   ::= "*" | proj_item ("," proj_item)*
proj_item   ::= expr ("AS" alias)?
expr        ::= col_ref | literal | func_call | expr binop expr | "(" expr ")"
func_call   ::= agg_fn "(" ("DISTINCT")? expr ")"
agg_fn      ::= "COUNT" | "SUM" | "MIN" | "MAX" | "AVG"
join_cond   ::= col_ref "=" col_ref
binop       ::= "=" | "<>" | "<" | ">" | "<=" | ">=" | "AND" | "OR" | "+" | "-" | "*" | "/"
col_ref     ::= (ident ".")? ident
literal     ::= integer | float | string | "NULL" | "TRUE" | "FALSE"

Not supported (Phase 9): window functions, lateral joins, recursive CTEs, EXCEPT/INTERSECT, subquery in WHERE (correlated).

8.10 Relational-to-Operator Lowering Table

SQL Construct Differential Operator(s) State Required
SELECT expr (projection) map(row -> eval(expr, row)) none
WHERE pred filter(row -> eval(pred, row)) none
UNION ALL concat(A, B) none
UNION (dedup) concat(A, B) then distinct keyed Arrangement
EXCEPT / set-diff concat(A, negate(B)) then distinct keyed Arrangement
INNER JOIN ON k=k join(A_arranged_by_k, B_arranged_by_k) two Arrangements
GROUP BY / aggregate reduce(key_fn, agg_fn) keyed Arrangement
DISTINCT distinct (threshold at 1) keyed Arrangement
Subquery in FROM lower subquery to plan; treat output Collection as table_ref depends on subquery

8.11 WAL and Storage Layout

WAL record:
  [ magic: u32 | seq: u64 | timestamp: Timestamp | key_len: u16 | key: [u8] |
    val_len: u16 | val: [u8] | diff: i64 | crc32: u32 ]
  // fixed-width header (28 bytes) + variable key + val

Checkpoint record:
  [ magic: u32 | frontier: Frontier (serialized antichain) |
    arrangement_snapshot_ref: u64 (offset in trace file) | crc32: u32 ]

Recovery protocol:

  1. Load latest valid checkpoint; restore arrangements from trace file.
  2. Scan WAL from checkpoint's seq forward; replay each Update triple into dataflow.
  3. Advance frontier to checkpoint's frontier; re-run operators until output frontier catches up.
  4. Signal recovery complete; accept new input.

Edge case — partial WAL record at tail: truncated write detected by CRC mismatch; discard tail and replay only up to last valid record. This may lose the last batch of updates — acceptable if clients use at-least-once delivery with sequence numbers.

8.12 Changefeed and Peek Semantics

Peek (point-in-time read):

peek(view: ViewDef, at: Timestamp) -> PeekResult
  precondition: output_frontier.less_than_equal(at)   // time is complete
  returns: consolidated multiset of view output at `at`
  blocks: until output_frontier advances past `at`

Changefeed (streaming delta):

changefeed(view: ViewDef, since: Frontier) -> Stream<Update<Row>>
  emits: consolidated output Updates as output frontier advances
  guarantees: monotonic, gap-free, no duplicate times
  ordering: frontier-bounded (all updates at time T emitted before frontier advances past T)

Snapshot+changefeed boundary: a client may peek at T0 then open a changefeed from T0 — the union of snapshot + changefeed deltas is a consistent, complete history.

Malformed path — peek before frontier: if output_frontier has not yet passed at, the peek MUST block (not return stale data). Returning early violates I4. Timeout must return PeekError::NotYetAvailable, never a partial result.

8.13 Memory and Ownership Model

Resource Owner Sharing mechanism Lifecycle
Batch Trace Arc<Batch> — shared across operators dropped when no cursor holds it and Trace compacts past its upper
Trace / Arrangement ArrangementOperator Arc<RwLock<Trace>> read handles to downstream dropped when all view users drop; WAL survives
Capability operator that holds it not shared; Clone produces a new capability at same time dropped when operator no longer needs to emit at that time
Update batch (in-flight) channel sender Vec<Update<D>> moved through channel dropped after receiver processes
WAL file handle StorageEngine singleton Arc<Mutex<WalWriter>> held for process lifetime

Back-pressure: each operator channel has a bounded capacity; the scheduler parks a sender when the channel is full, preventing unbounded memory accumulation.

8.14 Scheduling Semantics

Operator scheduling is cooperative and deterministic (P8):

while work_available:
    for each operator O in topological_order:
        if O.has_pending_input() or O.frontier_changed():
            O.run_once()    // process one batch; may emit to output channels
            propagate_frontiers(O)
  • Topological order: operators are sorted by dataflow topology; sources first, sinks last.
  • Determinism: given the same set of input updates, the same outputs are produced regardless of batch sizes or interleaving, because diffs commute under addition and consolidation is idempotent.
  • No preemption: run_once completes atomically per operator invocation; no shared mutable state between concurrent run_once calls on different operators (single-threaded scheduler for Phase 5; async-capable in Phase 13).
