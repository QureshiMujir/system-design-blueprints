Decisions (§9) · 31 ADRs

001

Language

Chosen

Rust 1.78+ (ed. 2021)

Rejected

C, Go, C++

When the rejected choice is right

C when integrating into an existing C kernel-adjacent codebase or shipping a liburing-ABI library others link via C FFI; Go for a service where developer velocity and GC-tolerable p99 outrank zero-syscall throughput.

Why: Native futures; ownership encodes in-flight-buffer lifetime; scoped unsafe; loom. C = manual lifetime bug factory; Go hides rings + GC.

002

io_uring binding

Chosen

raw syscalls via libc::syscall (own urt-sys)

Rejected

liburing FFI, io-uring crate

When the rejected choice is right

liburing/io-uring crate in production where you want battle-tested ABI handling, automatic feature probing, and to not own the syscall layer's maintenance across kernel versions.

Why: Learning value + full control of the ABI; no C dependency; we study liburing, not link it (ADR-001 rationale).

003

Backend abstraction

Chosen

trait IoBackend (uring ∥ epoll-pool)

Rejected

uring-only

When the rejected choice is right

uring-only when the deployment target is fixed at Linux ≥5.6 (e.g., a kernel-bypass appliance) — the trait's dynamic dispatch + lowest-common-denominator semantics are pure overhead.

Why: Portability to non-Linux/sandbox; differential testing (monoio pattern).

004

Portable fallback

Chosen

epoll + blocking worker pool synthesizing CQEs

Rejected

kqueue/IOCP backends

When the rejected choice is right

IOCP when Windows is a first-class target (IOCP is itself completion-based, a closer match than epoll); kqueue for a macOS/BSD-primary product.

Why: epoll covers the realistic fallback; IOCP/kqueue deferred (§1 non-goal).

005

Buffer abstraction

Chosen

owned-buffer (IoBuf/IoBufMut) moved in, returned (res, buffer)

Rejected

borrowed &[u8]

When the rejected choice is right

borrowed &[u8] only on a readiness backend (epoll/kqueue) where the kernel touches the buffer solely inside the synchronous syscall — there the borrow is sound and strictly more ergonomic.

Why: Borrowing is unsound under completion I/O (I2); owned move is the only safe shape (tokio-uring pattern).

006

Async primitives

Chosen

std Future/Pin/Waker + hand-built RawWaker vtable

Rejected

external async lib

When the rejected choice is right

external async lib (e.g., async-task) in production where you want a vetted task allocation + waker implementation and the vtable is not a learning goal.

Why: First-class language support; vtable is core learning (§Phase 3).

007

Executor

Chosen

own minimal executor (run queue + poll loop)

Rejected

tokio, smol

When the rejected choice is right

tokio when you need the mature ecosystem (timers, sync, broad driver support) and tokio-uring's driver already meets your needs — reimplementing is wasted effort.

Why: Own minimal API (§1 non-goal: full tokio compat); learn the task/waker layer.

008

Threading model

Chosen

thread-per-core (one Uring+exec+reactor/core), work-stealing optional

Rejected

global shared scheduler

When the rejected choice is right

global work-stealing scheduler (tokio multi-thread) for bursty, uneven, mostly-CPU workloads where a single hot core would bottleneck and cross-core balancing outweighs the lost SPSC simplicity.

Why: Shared-nothing → ring is SPSC per side (I7/principle 7); Seastar/glommio lineage.

009

Concurrency primitives

Chosen

crossbeam (channels/deque for optional steal), parking_lot

Rejected

std-only

When the rejected choice is right

std-only for a minimal-dependency / #![no_std]-adjacent build, or to keep the supply-chain audit surface (ADR-031 area) as small as possible.

Why: Lock-free deque for steal; faster park/unpark.

010

In-flight tracking

Chosen

slab crate (Slab<OpState>) keyed by user_data

Rejected

HashMap, free-list

When the rejected choice is right

HashMap when user_data must encode external sparse identifiers (e.g., a 64-bit handle from another subsystem) rather than dense slab keys, so a dense array would be mostly empty.

Why: O(1) insert/remove/index, dense keys = compact user_data (I4).

011

Memory ordering

Chosen

core::sync::atomic with explicit Ordering (Acquire/Release/Relaxed)

Rejected

SeqCst everywhere

When the rejected choice is right

SeqCst in an early prototype or a teaching build where ruling out ordering bugs cheaply matters more than the (small) cost, before tightening to Acquire/Release.

Why: Minimal correct ordering (I7); SeqCst is slower + hides intent.

012

Ring mmap

Chosen

libc::mmap/munmap in urt-sys, unsafe-wrapped

Rejected

memmap2 crate

When the rejected choice is right

memmap2 when you want a safe, tested mapping wrapper with cross-platform handling and don't need bespoke MAP_POPULATE/single-mmap control.

Why: Direct control of MAP_SHARED|MAP_POPULATE; one fewer dep; explicit ABI offsets.

013

Time source

Chosen

clock_gettime(MONOTONIC) via __kernel_timespec for TIMEOUT

Rejected

Instant-only

When the rejected choice is right

Instant-only on the emulation backend (no kernel TIMEOUT SQE) where timers are serviced by a userspace timer thread, so no __kernel_timespec is needed.

Why: Kernel timeouts need __kernel_timespec; monotonic for timers (§6).

014

Timer structure

Chosen

hierarchical timing wheel (urt-time) + TIMEOUT SQEs

Rejected

per-timer SQE, BTreeMap

When the rejected choice is right

per-timer TIMEOUT SQE when timers are few and require exact kernel-precision deadlines (e.g., a handful of long sparse timeouts) — the wheel's coarse granularity is then a liability.

Why: O(1) insert/expire for many timers (cross-link #204).

015

Error model

Chosen

thiserror enums; errno→io::Error; no panics on the I/O path

Rejected

anyhow

When the rejected choice is right

anyhow in the urt CLI/example binaries (not the library) where ergonomic error bubbling beats typed recovery and callers don't match on variants.

Why: Typed recovery; panics reserved for invariant breaks.

016

Logging/tracing

Chosen

tracing (spans per op, off hot path)

Rejected

log

When the rejected choice is right

log for a tiny embedding with no span/structured needs, where pulling in the tracing subscriber machinery is overkill.

Why: Structured; span per op; hot path stays counters-only (principle 14).

017

Metrics

Chosen

metrics facade → Prometheus exporter

Rejected

bespoke

When the rejected choice is right

bespoke atomic counters in an embedded/no-network build where a Prometheus endpoint is unwanted and counters are read directly via a debug API.

Why: Standard counters/gauges/histograms (ring depth, inflight, sqpoll syscalls).

018

Testing

Chosen

cargo test, proptest, insta

Rejected

unit-only

When the rejected choice is right

unit-only for a throwaway spike where property/snapshot infrastructure outweighs the value before invariants stabilize.

Why: Property tests for ring/cancel invariants; snapshot op-sequence goldens.

019

Concurrency testing

Chosen

loom (SQ/CQ index + waker races)

Rejected

stress-only

When the rejected choice is right

stress testing when the concurrency model is too large for loom's state space (loom is bounded) — a long randomized stress run is the only feasible coverage above that size.

Why: Exhaustive interleavings for I7/I11 — otherwise untestable.

020

UB checking

Chosen

Miri (slab/waker/scalar paths) + ASan (uring buffer paths on Linux)

Rejected

none

When the rejected choice is right

neither is acceptable only for a pure-safe-Rust component with zero unsafe and no FFI — there is no UB surface to check (not true of this project's three unsafe domains).

Why: Catch UAF (I2/I8); Miri can't run real syscalls → ASan covers the uring path.

021

Differential oracle

Chosen

std blocking I/O + (optional) tokio

Rejected

none

When the rejected choice is right

no differential oracle when the operation has no equivalent reference implementation to compare against (a novel opcode); property tests then carry verification instead.

Why: Cross-check op results + behavior (§12).

022

Fuzzing

Chosen

cargo fuzz (SQE builder + flags + op sequences)

Rejected

AFL raw

When the rejected choice is right

AFL++ when you need persistent-mode + fork-server throughput on a target that resists libFuzzer in-process harnessing, or richer coverage-guided mutators.

Why: libFuzzer; corpus from conformance.

023

Benchmarking

Chosen

criterion + custom echo/file harness

Rejected

ad-hoc

When the rejected choice is right

ad-hoc microbenchmarks during early exploration where criterion's statistical rigor + baseline-comparison overhead slows the design loop.

Why: Stable Mops + p99 + sqpoll-syscall-count gates.

024

CI/CD

Chosen

GitHub Actions (test/clippy/miri/loom-smoke/asan/bench)

Rejected

none

When the rejected choice is right

self-hosted CI (Buildkite/Jenkins) when uring tests need a controlled bare-metal kernel-pinned runner that hosted GitHub runners cannot provide.

Why: Gated merges; nightly soak + fuzz.

025

Packaging

Chosen

crates.io workspace; urt bin

Rejected

container-only

When the rejected choice is right

container-only distribution when the consumer is an operator deploying the example servers, not a developer linking the crate — the library API is then irrelevant.

Why: Library-first embed.

026

Containers

Chosen

Dockerfile (Linux, privileged for uring) + compose (prometheus)

Rejected

host-only

When the rejected choice is right

host-only on a bare-metal performance lab where the container layer adds measurable syscall/perf overhead and the kernel is already pinned.

Why: Reproducible uring runs; kernel-version pin in image label.

027

Lint/format

Chosen

clippy -D warnings, rustfmt

Rejected

none

When the rejected choice is right

relaxed lints win only for machine-generated code (e.g., bindgen output, build-script-emitted files) excluded from the lint gate, where hand-written style rules do not apply.

Why: Consistency.

028

Licensing

Chosen

Apache-2.0

Rejected

MIT, GPL

When the rejected choice is right

MIT for maximum permissiveness when the Apache patent grant is unwanted by downstream; GPL when copyleft reciprocity is a deliberate goal (e.g., a kernel-coupled GPL project).

Why: Matches tokio/glommio ecosystem; patent grant.

029

Reproducibility

Chosen

pinned rust-toolchain.toml, locked deps, SOURCE_DATE_EPOCH

Rejected

floating

When the rejected choice is right

floating deps during active development where you want latest patches automatically and bit-reproducibility is not yet required.

Why: Bit-stable builds.

030

Feature probe

Chosen

io_uring_register(IORING_REGISTER_PROBE) + uname → capability bitset

Rejected

assume-latest

When the rejected choice is right

assume-latest in a single-kernel appliance where the exact kernel build is known at compile time, so runtime probing is dead weight.

Why: ABI safety across kernels (I12).

031

Public API stability

Chosen

SemVer; #[non_exhaustive] on public enums (opcodes/errors)

Rejected

implicit

When the rejected choice is right

implicit (no #[non_exhaustive]) for an internal-only crate with a single in-tree consumer, where exhaustive matching is desired and there is no external API contract.

Why: Additive opcode/feature evolution without breaking.
