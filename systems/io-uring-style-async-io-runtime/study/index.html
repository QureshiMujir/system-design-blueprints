Mental Models & First Principles

The compressed intuitions an expert holds while designing or debugging this runtime. Each states the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

MM1 — The SQ and CQ are SPSC rings; the kernel is the other endpoint. Each ring has exactly one producer and one consumer, and for one of the two endpoints that party is the kernel: on the SQ we produce, the kernel consumes; on the CQ the kernel produces, we consume. Predicts: the same acquire/release reasoning used for a userspace lock-free SPSC queue applies verbatim across the syscall boundary — publish the tail with release after writing the entry, read the tail with acquire before reading the entry. Bug without it: you reach for a mutex or SeqCst everywhere (slow) or, worse, plain loads (torn/missed completions). Applied: §8.4, §Phase 1 (I7), §Phase 12 (loom).

MM2 — A Future is a state machine; the executor is its clock and the reactor is its interrupt controller. poll advances the machine one step; it returns Pending when blocked and registers a Waker; the reactor, on a completion, fires that waker to re-tick the clock. Predicts: a "lost wakeup" is exactly a missed interrupt — the machine stalled because the edge that would advance it was dropped between the poll and the waker store. Bug without it: storing the waker without re-checking the result (the register-then-check race) → permanent hang. Applied: §8.6, §Phase 3 (I11).

MM3 — In completion I/O, ownership is the safety boundary, not borrowing. The kernel touches the buffer after the syscall returns, so the compiler's borrow scope no longer covers the danger window; only ownership (the buffer lives inside the Op until the CQE) does. Predicts: every safe completion API must move the buffer in and return it out — there is no sound borrowed form. Bug without it: freeing/reusing a buffer on future-drop → use-after-free when the op completes (the canonical io_uring bug). Applied: §1 (central safety problem), §6 (P1/P2), §Phase 2, §Phase 11 (I2/I8).

MM4 — Cancellation is a request, not a guarantee; the buffer is hostage until the cancel resolves. ASYNC_CANCEL asks the kernel to stop an op, but the original op still produces a terminating CQE (its real result or -ECANCELED). Predicts: you must wait for that CQE before freeing the buffer — dropping the future cannot synchronously reclaim memory. Bug without it: free-on-drop UAF, and leaked slots from un-reaped cancel CQEs. Applied: §8.5, §Phase 11 (I8), §6 (P2).

MM5 — Throughput is governed by Little's law: in-flight = throughput × latency. To hit a target ops/s at a given per-op latency you must keep that many ops in flight; a shallow queue caps throughput regardless of CPU. Predicts: batching submit and reaping deep raise throughput by raising in-flight depth, up to the device/kernel saturation point; the SQ/CQ depths must be sized to the bandwidth-delay product. Bug without it: submitting one-at-a-time and blaming the kernel for low throughput. Applied: §4 (constraints), §Phase 1 (batching), Performance Engineering.

MM6 — Each SQE yields exactly one terminating CQE; multishot yields many-then-one. One-shot ops complete once; multishot ops deliver a stream of IORING_CQE_F_MORE CQEs then one without it. Predicts: slot lifetime is bounded by the terminating CQE, not the first — freeing on the first multishot CQE corrupts the demux. Bug without it: slot leak (never freed) or double-free (freed early, then a later CQE hits a reused slot). Applied: §8.5, §Phase 2 (I3), §Phase 9 (multishot).

MM7 — The kernel ABI is a moving target; capability is runtime state, not a compile-time constant. Opcodes, flags, SQPOLL, buf_ring, and DEFER_TASKRUN were each introduced in specific kernel versions. Predicts: the only safe design probes at startup and gates each feature behind a real fallback; a feature works on your laptop and -EINVALs on the customer's older kernel otherwise. Bug without it: runtime -EINVAL crashes on deployment. Applied: §Phase 10 (I12), §6 (P8).

MM8 — Thread-per-core turns concurrency into parallelism with no shared state. One ring + reactor + executor per core, connections sharded by SO_REUSEPORT, means the hot path has no cross-core synchronization — the ring stays SPSC because there is exactly one submitter and one reaper per ring. Predicts: scaling is near-linear in cores until the device saturates; adding a global lock or shared scheduler reintroduces the contention you designed away. Bug without it: torn ring indices / data races from cross-thread submission. Applied: §6 (P7), §Phase 3, Scalability Analysis, ADR-008.

MM9 — A dropped completion is unrecoverable; a slow one is merely slow. A CQE that is never delivered (ordering bug, overflow loss, SQPOLL stall) hangs the awaiting task forever; everything else (backpressure, overflow backlog, fallback) degrades gracefully. Predicts: the design must bias toward reaping/draining/retrying over speed, and the single most important production signal is sqe_submitted − cqe_reaped drift. Bug without it: optimizing away a fence or skipping an overflow check to save a cycle, trading a permanent hang for a tiny speedup. Applied: §6 (P15), §Phase 1 (I9), Failure Modes & Recovery.

MM10 — Zero-copy is only zero-copy if the buffer never moves and is never copied. Registered buffers and buf_ring exist so the kernel can DMA directly to/from app memory; a growable Vec that reallocs, or a defensive copy, defeats the entire point. Predicts: hot-path buffers must be pinned (immovable) and drawn from a pool/ring, and the API must not hide a copy. Bug without it: a reallocating buffer dangles the kernel's mapping (-EFAULT/UAF), or a hidden copy caps throughput. Applied: §6 (P9/P10), §Phase 7 (fixed buffers, I14), §Phase 9 (buf_ring).

Books

  • Klabnik & Nichols, The Rust Programming Language — ownership, lifetimes, Send/Sync (Ch. 4, 10, 16). The in-flight-buffer lifetime contract is an ownership story. Applied: §6 (P1/P2), §11 Core Schema (Op/IoBuf), §Phase 2.
  • "Asynchronous Programming in Rust" (Carl Fredrik Samson) + The Async Book (Rust async-wg) — Future/Pin/Waker/executor internals; how poll/RawWaker work. Applied: §Phase 3 (executor/waker), §8.6 (future/waker model).
  • Jon Gjengset, Rust for Rustaceans — unsafe, vtables, Pin, atomics, Send/Sync subtleties. Applied: §Phase 3 (RawWaker vtable), §Phase 0 (ring unsafe), P13.
  • Bryant & O'Hallaron, Computer Systems: A Programmer's Perspective, 3e — Ch. 8 (exceptions/syscalls), Ch. 10 (system-level I/O), Ch. 12 (concurrency). Applied: §Phase 0 (raw syscalls), §Phase 4/5 (I/O lowering).
  • Kerrisk, The Linux Programming Interface — Ch. 4–5 (file I/O), 56–61 (sockets), 63 (alt I/O models: select/poll/epoll/signal-driven). The readiness model io_uring supersedes. Applied: §Phase 5 (sockets), §Phase 12 (epoll emulation backend).
  • Drepper, "What Every Programmer Should Know About Memory" (2007) — cache lines, memory ordering, false sharing. Applied: §Phase 1 (ring index padding/ordering, I7), Performance Engineering (cache analysis).
  • Williams, C++ Concurrency in Action, 2e — Ch. 5 (the C11 memory model), Ch. 7 (lock-free SPSC ring). The acquire/release reasoning is language-independent; maps to Rust's Ordering. Applied: §8.4 (ring index semantics), §Phase 1 (I7).
  • Love, Linux System Programming, 2e — I/O schedulers, O_DIRECT, async I/O history (aio(7)). Applied: §2 (why io_uring exists), §Phase 4 (O_DIRECT alignment), §Phase 7 (fixed buffers).

Glossary · 45 terms · site-wide glossary

io_uring
Linux async I/O interface (Axboe, 2019) using shared submission/completion rings; the model this project rebuilds.
Completion-based I/O
The kernel performs the I/O and signals completion after the syscall returns; the buffer is touched later (vs readiness).
Readiness-based I/O
The kernel signals when an fd is ready; the app does a synchronous syscall (epoll/select); it owns the buffer throughout.
SQ (Submission Queue)
The ring of submission entries the app produces and the kernel consumes.
CQ (Completion Queue)
The ring of completion entries the kernel produces and the app consumes.
SQE
Submission Queue Entry — a 64-byte request (opcode + fd + addr + len + user_data + flags).
CQE
Completion Queue Entry — a 16/32-byte result (user_data + res + flags).
user_data
An opaque u64 the app puts in the SQE; the kernel echoes it in the CQE — the demux key (== OpId).
OpId
The runtime's id for an in-flight op; equals user_data; the slab key.
Ring head/tail
Producer/consumer indices into a ring; advanced with release, read with acquire.
Ring mask
ring_entries − 1 (power-of-two depth) used to index the ring slot from the monotone index.
SQ array
The indirection table mapping a ring slot to an SQE index (array[tail&mask]=sqe_idx).
Acquire/Release
Memory-ordering constraints that establish happens-before across the kernel/user boundary (I7).
In-flight slab
Slab<OpState> keyed by user_data; owns the buffer/fd-ref from submit until CQE (I2).
Buffer-ownership contract
The rule that a submitted buffer/fd is owned by its Op until the CQE; dropping the future cannot free it (I2/I8).
(result, buffer) pattern
Resource ops move the buffer in and return it out on completion, so no borrow escapes the future.
Reactor
The component that reaps CQEs, demuxes by user_data, and wakes the parked tasks.
Executor
The component that owns the run queue and drives Future::poll.
Task
A spawned future + its state + a JoinHandle result channel.
Waker / RawWaker
A handle that re-enqueues a task; built from a hand-written vtable (clone/wake/wake_by_ref/drop).
JoinHandle
A handle that resolves to a spawned task's output.
Thread-per-core
One executor + reactor + ring per core, shared-nothing; the ring is SPSC per side (Seastar/glommio).
Backpressure
Submission blocks/awaits when the SQ is full, never overrunning (I6).
CQ overflow
The CQ fills before the app reaps; the kernel sets a flag + dropped counter; never silently lost (I9).
Registered (fixed) buffers
Buffers pre-mapped via io_uring_register; READ_FIXED/WRITE_FIXED skip per-op page pinning.
Registered (fixed) files
An fd index table; IOSQE_FIXED_FILE skips per-op fd refcount/lookup.
Linked SQE chain
Consecutive SQEs flagged IO_LINK that run in order; a failure cancels the remainder (-ECANCELED).
IO_DRAIN
A barrier SQE that waits for all prior SQEs to complete before it runs.
Provided buffers
A pool of buffers donated to the kernel; ops with BUFFER_SELECT pick one at completion.
buf_ring
The modern provided-buffer ring (REGISTER_PBUF_RING); replenished without a per-buffer syscall.
Multishot
One SQE that yields many CQEs (IORING_CQE_F_MORE) until terminated (accept/recv/poll).
IORING_CQE_F_MORE
A CQE flag meaning more completions will follow for this SQE (multishot not yet terminated).
SQPOLL
A kernel thread that polls the SQ tail so submission needs no syscall.
IORING_SQ_NEED_WAKEUP
A flag the kernel sets when the SQPOLL thread parked; the app must wake it via enter(SQ_WAKEUP) (I13).
COOP_TASKRUN / DEFER_TASKRUN
Setup flags that make completion-side task-work cheaper / deferred to the next enter.
ASYNC_CANCEL
An op that cancels an in-flight op by user_data / fd / all.
-ECANCELED
The result a cancelled op (or a downstream linked op) completes with.
Feature probe
Startup query (REGISTER_PROBE + uname) building a capability mask to gate features (I12).
Capability matrix
The table of which features each kernel version supports; drives gating + fallbacks.
Short read/write
A READ/WRITE that transfers fewer bytes than requested (res < len); success, caller loops.
Emulation backend
The portable epoll + blocking-worker-pool backend that synthesizes CQEs with identical semantics.
Drain (shutdown)
Driving the reactor until all in-flight ops complete and FDs/buffers/slots return to baseline (I1).
Pinning
Keeping a buffer's address stable (immovable) while an op references it.
loom
A tool that exhaustively explores concurrent interleavings to prove the ring/waker ordering (I7/I11).
__kernel_timespec
The kernel's 64-bit timespec used by TIMEOUT SQEs (not libc timespec).
