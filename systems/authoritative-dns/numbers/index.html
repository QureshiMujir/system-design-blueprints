4. System Constraints

The defining property: a single query must never cost more than 5 ms p99, regardless of zone size, because a resolver that times out simply retries against another authoritative server — a slow authoritative server is treated by the internet as a failing one.

32. Back-of-Envelope Capacity Model

Derived from §4's System Constraints table; every number below chains from it explicitly.

  1. Memory for a 1M-record unsigned zone. 120 B/record × 1,000,000 = 114 MiB (§4 "Memory per record").
  2. Memory for the same zone DNSSEC-signed (NSEC). 220 B/record × 1,000,000 = 210 MiB (§4 storage amplification ≈1.8×, applied to the 120 B base).
  3. Memory for the same zone with NSEC3. 252 B/record × 1,000,000 = 240 MiB (§4 storage amplification ≈2.1×).
  4. Memory for a 10M-record TLD-scale zone, NSEC3. 252 B × 10,000,000 = 2.4 GiB — within a single modern node's RAM budget, confirming P2's radix tree needn't spill to disk at this scale.
  5. Bandwidth for a 300k QPS/core UDP workload. Assuming a ~100-byte average unsigned response: 300,000 × 100 B = 28.6 MiB/s per core (§4 M6); with DNSSEC RRSIGs (~200-byte average response): 300,000 × 200 B = 57.2 MiB/s per core.
  6. Amplification factor for a worst-case ANY/DNSKEY query. A ~50-byte query eliciting a ~4,000-byte signed DNSKEY response: 4,000 / 50 = 80× amplification (§20, T2) — the number RRL (§4 default 5 responses/s per bucket) is sized against.
  7. FD budget vs. concurrent TCP ceiling. 65,536 FDs (§4) minus reserved listener/log/metric FDs (≈1,000) leaves headroom consistent with the stated 50,000 concurrent-TCP-connection ceiling (§4).
  8. AXFR duration derivation for 1M records. At an assumed sustained ~40 MiB/s TCP throughput for a ~150-byte average wire-encoded RR: 1,000,000 × 150 B = 143 MiB; 143 MiB / 40 MiB/s ≈ 3.6 s transfer time plus per-record processing overhead, consistent with the ≤30 s p50 target (M11) with margin for the processing side, not just wire transfer.
  9. Signing throughput needed to keep pace with M8/M9. At 300k QPS/core (M6) with online Ed25519 signing (50 µs/op, M8): a fully-online-signed zone caps usable QPS at 1s / 50 µs = 20,000 signs/s/core — an order of magnitude below the unsigned QPS ceiling, quantifying exactly why P5's offline-signing escape valve exists.
  10. Anycast PoP count for global sub-50 ms p99. Given a ~150 ms worst-case single-hop RTT assumption (§4) and a target of serving from within ~25 ms of any client, roughly 8–12 well-distributed PoPs (one per major population-dense region) is the customary industry figure (consistent with the CloudFlare RRDNS comparison, §31) needed to bound tail latency globally.
  11. Key-rotation event rate. ZSK every 60 days + KSK every 365 days (§4) ⇒ per zone, 365/60 + 365/365 ≈ 7 rollover events/year — a number that directly sizes how much rollover-state-machine automation (§18) is worth building versus doing by hand.
  12. RRL bucket memory footprint. At a worst-case 1M distinct (source-net,qtype,size-bucket) keys during an attack, each RrlBucket (§11, two fields ≈16 bytes) costs 1,000,000 × 16 B ≈ 16 MiB — a bounded, acceptable memory cost even under adversarial key-space exhaustion attempts.
