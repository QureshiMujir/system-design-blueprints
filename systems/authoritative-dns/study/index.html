Hard questions (§33)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does a radix tree keyed by label outperform a hash map keyed by FQDN for this workload specifically, and under what zone shape would that stop being true? (§15.2, §31, §32)
  2. Walk the exact sequence of RRSIG/DNSKEY/DS lookups a validator performs from the root to www.example.com, and name the single record whose absence collapses the whole chain. (§8.6, §17.2)
  3. Why does removing an old ZSK too early violate I9 even though the key itself is still cryptographically sound? (§18.2, §18.9, MM7)
  4. Under what circumstances does IXFR fall back to AXFR, and why is serving a partial IXFR worse than an expensive full AXFR? (§8.7, §8.10, §19.6)
  5. Why is a spoofed-source amplification attack structurally defeated by "slip to TCP" but not by simply rate-limiting query volume? (§20.2, MM4, MM5)
  6. Explain why the query path (§3) never blocks on DNSSEC signing even in online mode, and what P12 would be violated if it did. (§17.2, §6 P12)
  7. Why does NSEC leak zone contents but NSEC3 with iteration 0 does not, and why does RFC 9276 recommend against raising iterations further? (§18.2, §22 T8)
  8. Derive the amplification factor of a worst-case DNSKEY query response and explain how the RRL default threshold (§4) was sized against it. (§32, §20.2)
  9. Why must glue records exist only for in-bailiwick NS targets and never for out-of-bailiwick ones? (§8.5, §15.6)
  10. Trace what happens to 10,000 in-flight queries holding a zone snapshot when an operator triggers a reload mid-burst — do any of them see inconsistent data? (§15.2, §7 I1, §3)
  11. Why does this design choose per-connection tokio tasks over thread-per-core, and at what QPS ceiling does that choice reverse? (§9 ADR-08, §29)
  12. Explain the difference between "the query fails closed on malformed input" (P11) and "the query panics on malformed input" (I10), and why conflating them is dangerous. (§6 P11, §7 I10, §13.9)
  13. Why is a TSIG key mismatch after a routine key rotation the most common real-world zone-transfer failure, and what telemetry surfaces it before an operator notices stale data? (§19.9, §23 FM-2)
  14. Why does this design run a 30-day soak canary rather than a shorter fixed-duration test, and what bug class specifically requires that duration? (§21.9, §26)
  15. Compare the storage amplification of NSEC vs. NSEC3 signing and explain why the more private option costs more, not less. (§4, §32, MM6)
  16. Why is "delegation is federation without coordination" true of DNS but not of, say, a sharded key-value store — what makes DNS's coordination cost zero at the query path? (§2, §29, MM8)
  17. Under what real-world regime would PowerDNS's pluggable-backend architecture be the objectively better choice than this design's in-memory radix tree, given the memory footprint this design commits to? (§31, §32)
  18. Why does offline signing turn the query path into "a pure lookup," and what does that cost on the write path in exchange? (§17.2, §32, P5)
  19. Explain why RRL must key on response size and query type, not just source IP, and construct a concrete attack that a source-IP-only limiter would miss. (§20.2, §20.6, MM4)
  20. Why does a KSK double-DS rollover require external (registrar) coordination while a ZSK pre-publish rollover does not? (§18.2, §18.6)

30. Mental Models & First Principles

  1. MM1 — A zone is a federated trie, not a table. Predicts: lookup cost is O(name length), and delegation is just "stop descending, hand off" — not a special case. Bug class without it: treating zones as flat key-value maps and re-deriving wildcard/delegation logic ad hoc. Applies in §15 (Phase 3), §8.5.
  2. MM2 — DNSSEC is a signature chain, not a flag. Predicts: breaking any single link (a missing DS, an expired RRSIG) fails the entire subtree below it, not just one record. Bug class without it: treating "DNSSEC enabled" as a boolean rather than reasoning about chain continuity. Applies in §8.6, §17.
  3. MM3 — RCU trades memory for lock-freedom. Predicts: a hot-reload path will transiently double memory, and the right question is "when does the old snapshot get dropped," not "how do I avoid the copy." Bug class without it: adding locks to "fix" a reload race that RCU already solved structurally. Applies in §15.7, P3.
  4. MM4 — Amplification is a response/query size ratio problem, not a volume problem. Predicts: rate-limiting must key on response characteristics, not just query count. Bug class without it: building a query-rate limiter that misses large-response-small-query abuse entirely. Applies in §20, T2.
  5. MM5 — A spoofed source cannot complete a handshake. Predicts: any defense that nudges toward a stateful protocol (TCP, TLS) defeats pure-UDP spoofing structurally. Bug class without it: building complex spoofing heuristics instead of the simple "slip to TCP" defense. Applies in §20.6, §5 paper #2.
  6. MM6 — Denial-of-existence is a sorted-chain proof, not a database query. Predicts: you can prove a name doesn't exist without querying for it — you prove its neighbors bracket it in sorted order. Bug class without it: trying to "cache negative results" instead of building the NSEC/NSEC3 chain correctly. Applies in §8.6, §18.
  7. MM7 — Key rollover safety is about cache lifetimes, not key lifetimes. Predicts: you cannot remove an old key until every resolver that might have cached it has had time to refresh — a property of the network, not the key itself. Bug class without it: rolling keys "when convenient" rather than on a TTL-derived schedule. Applies in §18, I9.
  8. MM8 — Delegation is federation without coordination. Predicts: DNS scales globally precisely because a parent zone need not know anything about a child zone's internal structure or update cadence. Bug class without it: designing a "notify the whole tree" update-propagation scheme where none is needed. Applies in §2, §29.

Reference Implementations

  • BIND9 (ISC) — github.com/isc-projects/bind9. Study lib/dns/rbtdb.c (red-black-tree zone db). Lesson: interpret-per-query costs an order of magnitude vs. compile-then-serve. Pitfall: do not copy the monolithic named.conf parser's coupling of config and zone data.
  • NSD (NLnet Labs) — github.com/NLnetLabs/nsd. Study zonec.c (compile-then-serve). Lesson: precompiled zone databases are fast at load time. Pitfall: full-recompile-on-reload; we improve on this via RCU (P3).
  • Knot DNS (CZ.NIC) — github.com/CZ-NIC/knot. Study src/knot/zone/. Lesson: run the signer as a separate process for privilege isolation. Pitfall: its event-loop-per-worker complexity is not worth copying wholesale at our scope.
  • PowerDNS Authoritative — github.com/PowerDNS/pdns. Study pdns/backends/. Lesson: separate storage from the query engine via a pluggable backend trait. Pitfall: its backend API is far wider than our dns-zone-store trait needs to be.
  • hickory-dns (formerly trust-dns) — github.com/hickory-dns/hickory-dns. Study crates/proto/src/rr/. Lesson: the pure-Rust wire-codec crate structure this project mirrors. Pitfall: do not replicate its crate-count sprawl without matching per-crate test coverage.

Glossary (§36) · 43 terms · site-wide glossary

AXFR
full authoritative zone transfer (RFC 5936).
Anycast
same IP announced from multiple sites; BGP routes to nearest.
CAA
Certification Authority Authorization record.
CDS/CDNSKEY
child-published records requesting parent DS updates.
CNAME
canonical name (alias) record.
Closest-encloser
the longest name that exists in a zone, ancestor of a queried name.
DANE
DNS-based Authentication of Named Entities (uses TLSA records).
Delegation
a parent zone handing authority for a subtree to child NS records.
DNSKEY
a DNSSEC public key record.
DNSSEC
DNS Security Extensions (RFC 4033–4035).
DoH
DNS over HTTPS (RFC 8484).
DoQ
DNS over QUIC (RFC 9250).
DoT
DNS over TLS (RFC 7858).
DS
Delegation Signer record, at the parent, hashing the child's KSK.
EDNS(0)
Extension Mechanisms for DNS (RFC 6891).
Empty non-terminal
a name with descendants but no records of its own.
FQDN
Fully Qualified Domain Name.
Glue
A/AAAA records for an in-bailiwick NS target, in ADDITIONAL.
IXFR
incremental zone transfer (RFC 1995).
KSK
Key Signing Key, signs the DNSKEY RRset.
MNAME
the SOA field naming the zone's primary nameserver.
NOTIFY
RFC 1996 primary-to-secondary zone-change notification.
NSEC
Next Secure record, proves denial of existence via a sorted chain.
NSEC3
hashed-name variant of NSEC (RFC 5155), privacy-preserving.
NXDOMAIN
response code: name does not exist.
Opt-out
NSEC3 mode skipping signature coverage for insecure delegations.
RCU
Read-Copy-Update, the atomic zone-swap pattern (P3).
RData
the type-specific data portion of a resource record.
RNAME
the SOA field naming the zone's administrative contact.
RRSIG
a DNSSEC signature over one RRset.
RRset
the set of records sharing one (name, type, class).
RRL
Response Rate Limiting.
Radix tree
a trie compressing single-child chains, indexed by label.
SIG(0)
public-key-based transaction signature (RFC 2931).
SOA
Start of Authority record, one per zone apex.
SVCB/HTTPS
service-binding record types (RFC 9460).
TSIG
Transaction Signature, HMAC-based (RFC 8945).
TTL
Time To Live, in seconds.
Wildcard
an owner name beginning with *, matched via closest-encloser synthesis.
Zone
the unit of administrative authority delegated by a parent.
Zone apex
the top name of a zone, where SOA and NS for the zone live.
ZONEMD
Zone Message Digest, a whole-zone integrity checksum (RFC 8976).
ZSK
Zone Signing Key, signs the zone's day-to-day RRsets.
