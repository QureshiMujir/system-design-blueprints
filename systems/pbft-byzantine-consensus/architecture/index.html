Four properties of this architecture recur throughout the document. Safety is independent of timing; liveness is not (P1). The protocol preserves I1 under arbitrary asynchrony and only makes progress when the network is eventually synchronous (DLS 1988); the view-change timer (I11) is the bridge. prepared/committed-local are the spec, not an implementation detail (P4, I3, I4). Implementations that track "messages received" instead of predicate truth produce safety violations during view changes because the P-set (I5) is the set of predicate-true bundles, not a message tally. Authentication is interchangeable; the security model is not (P5, ADR-05). MAC authenticators (Phase 14 §14.1) are fastest on LAN fanout but not third-party-transferable; Ed25519 enables forwarded evidence; BLS aggregates collapse quorum certificates to 96 bytes. The state machine is deterministic and side-effect-free with respect to consensus (P3, I12). Non-determinism is fed in as part of the request, never read from the local environment — a replica that produces a different (state', reply) from identical (state, request) is by definition Byzantine.

Trust boundaries in this diagram: the client↔primary edge crosses an untrusted-client boundary (Threat Model §22, T6); every replica↔replica edge crosses the Byzantine-replica boundary (up to f may be faulty); the log↔WAL edge crosses the crash-durability boundary (Phase 16, Phase 17); the state-machine execution boundary is where non-determinism must not leak in (I12).

8. Domain Model / Protocol / Data Model

8.1 Message grammar (wire schema, EBNF)

Message      ::= Request | PrePrepare | Prepare | Commit | Reply
             |   Checkpoint | ViewChange | NewView
             |   StateTransferRequest | StateTransferResponse
Request      ::= operation:bytes timestamp:u64 client:ClientId sig:ClientSig
PrePrepare   ::= view:u64 seq:u64 digest:Digest primary:ReplicaId auth:Auth
Prepare      ::= view:u64 seq:u64 digest:Digest replica:ReplicaId auth:Auth
Commit       ::= view:u64 seq:u64 digest:Digest replica:ReplicaId auth:Auth
Checkpoint   ::= seq:u64 state_digest:Digest replica:ReplicaId auth:Auth
ViewChange   ::= new_view:u64 stable_seq:u64 checkpoint_proof:Checkpoint*
             |   prepared_set:PreparedProof* replica:ReplicaId auth:Auth
PreparedProof::= pre_prepare:PrePrepare prepares:Prepare{2f}
NewView      ::= new_view:u64 view_changes:ViewChange{2f+1} re_proposed:PrePrepare*
             |   primary:ReplicaId auth:Auth
Auth         ::= MacVector | Ed25519Sig | BlsPartial | BlsAggregate

Every message that participates in a quorum count (Prepare, Commit, Checkpoint, ViewChange) carries (view_or_seq, digest, replica_id, auth) in a fixed field order — helper predicates (I3, I4) accept the tuple as a unit.

8.3 Worked example — normal case, n=4, f=1

Client submits Request<o,t=1,c> to primary r0. r0 assigns seq=1, multicasts PrePrepare<v=0,n=1,d>. r1,r2,r3 each accept (PP1 passes), multicast Prepare<v=0,n=1,d,i>. Once r0 (implicitly, via its own pre-prepare) plus any 2f=2 of {r1,r2,r3} have matching prepares, prepared(m,0,1) is TRUE at each such replica (I3); each multicasts Commit<0,1,d,i>. Once 2f+1=3 matching commits are seen, committed-local(m,0,1) is TRUE (I4); each such replica executes m and replies. Client accepts once f+1=2 matching Replys arrive (I9).

8.4 Malformed-input example

PrePrepare<v=0,n=1,d> where the embedded batch's digest ≠ d: PP1 (Phase 13 §13.1) rejects at the digest-equality check before the message is logged; the replica emits Action::Discard and no Prepare is sent. A PrePrepare with n ≤ stable_seq or n > high_water is discarded under I8's gate without a WAL write (no forensic-relevant state change).

8.5 Failure-path example — view change under primary silence

r0 (primary, view 0) stops emitting PrePrepares. Backups' timers (I11) fire at T_base=1s; each multicasts ViewChange<1, stable_seq, checkpoint_proof, prepared_set>. New primary r1 = 1 mod 4 collects 2f+1=3 matching ViewChanges, builds NewView<1, V, O> per I6, and multicasts it. Backups re-derive O locally (I6); on match, they re-enter PrePrepared per re-proposed entry and continue the normal-case path from Phase 13. If r0 had equivocated on seq=5 before going silent, the O-set entry at seq=5 is forced to whichever digest appears in the highest-view PreparedProof across V — the mechanism that makes the view change safe (I5, I6; full trace in Phase 15 §15.3).

Design principles (§6)

  • P1 — Safety strictly dominates liveness. Under any partition, replica failure, or adversarial schedule, no two correct replicas commit different requests at the same (view, sequence) (I1). Liveness is forfeited the instant safety is at risk; violating this turns a stalled cluster into a forked one. Tradeoff: availability during partitions. Operational implication: a stuck view change is a page, not a safety incident, until proven otherwise.
  • P2 — 3f+1 replicas tolerate f Byzantine faults; no shortcuts. The Lamport-Shostak-Pease bound (I2) is checked at boot; the system refuses to start with n < 3f+1. Violating this converts a liveness bug into a safety bug — the difference matters operationally.
  • P3 — The state machine is deterministic. (state, request) → (state', reply) is a pure function (I12); non-determinism is fed in as part of the request and digested/signed by the client. Violating this makes divergent replicas indistinguishable from Byzantine ones.
  • P4 — Predicates, not message counts. prepared/committed-local (I3, I4) are what the spec is written in terms of; the P-set (I5) is the set of predicate-true bundles, not a tally. Violating this misdefines the view-change boundary and breaks safety silently.
  • P5 — Authenticator is pluggable behind one trait; the security model is not (ADR-05). MAC is fastest on LAN fanout but non-transferable; Ed25519 is transferable; BLS collapses the QC. Tradeoff: transferability vs. per-message cost. Violating this couples protocol logic to a specific backend's security assumptions.
  • P6 — View-change correctness over view-change speed. Optimize correctness against I5/I6 first, monotone timer behavior (I11) second, O(n²)→O(n) (Phase 18) third. A fast but unsafe view change is broken; a slow, correct one is acceptable pre-Phase-18.
  • P7 — Checkpoint-gated garbage collection. GC requires 2f+1 matching checkpoints (I7, I8); a replica cannot prove state to a recovering peer otherwise. Violating this breaks Phase 17 state transfer.
  • P8 — Batching amortizes authentication cost (ADR-16). A 256-request pre-prepare cuts signature cost ~256×. Tradeoff: batch-fill latency vs. throughput (ADR-16's rejected-choice regime).
  • P9 — No probabilistic safety. Safety is deterministic conditional on the f bound; only the deferred asynchronous variant (HoneyBadger, §35) trades in probabilistic liveness, never probabilistic safety.
  • P10 — Equivocation is detected and provably attributable. A primary sending PrePrepare<v,n,d> and PrePrepare<v,n,d'> is caught by PP1 (Phase 13 §13.1); with a transferable authenticator the union of both signed messages is portable proof (Threat Model T1).
  • P11 — The view-change timer is monotone, exponential, and clock-monotonic (ADR-11). It doubles per consecutive failed view, resets only on committed-local advance, and reads tokio::time::Instant, never wall-clock. Violating this admits NTP-based liveness attacks (Threat Model T11).
  • P12 — Authenticated channels need not be encrypted. Consensus messages are integrity-protected and ordered but not necessarily confidential (ADR-15); a passive observer learns nothing a client could not already learn.
  • P13 — The log is append-only and write-ahead. Every signed outbound message is WAL- written before transmission (Phase 16); a crashed replica replays its WAL and resumes without violating safety.
  • P14 — Conformance is the contract, not an aspiration. The conformance suite (Phase 21 §21) gates every phase's Deliverable (N.3); the Castro-Liskov invariants, Twins scenarios, and Jepsen matrix are imported verbatim; a regression is a merge block.
