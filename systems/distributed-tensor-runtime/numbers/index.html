Assumptions: homogeneous ranks (heterogeneous deferred); a flat or 2-level network (topology-aware hierarchical deferred); TCP with reasonable bandwidth/RTT; ranks ≤ ~1024 for P0 targets; per-rank compute via #349 (CPU; GPU deferred).

4.1 Worked collective cost (the ring/RHD crossover)

  • Model: T = α + β·n per message; for N ranks reducing D bytes.
  • Ring allreduce: T_ring ≈ 2(N−1)·α + 2·(N−1)/N·D·β (+ reduce γ). Latency term scales O(N); bandwidth term → 2D·β (N-independent, optimal).
  • RHD allreduce: T_rhd ≈ 2·log₂N·α + 2·(N−1)/N·D·β. Latency term O(log N); same bandwidth term.
  • Crossover: ring and RHD share the bandwidth term, so the choice is driven by the latency term: RHD wins whenever 2log₂N·α < 2(N−1)·α, i.e. essentially always on latency — but ring's simpler pipelining + better cache/overlap behavior makes it win for large D in practice; RHD wins for small D (latency-dominated). The select() function computes the crossover D* from the measured α,β.
  • Numeric example: N=64, α=5 µs, β=1/(10 GB/s). Small D=1 KB: latency dominates → RHD (2·6·5µs=60µs vs ring 2·63·5µs=630µs). Large D=100 MB: bandwidth dominates (≈2·100MB·β≈20ms) → ring (simpler, overlaps better).
  • Implication: the §4 targets are stated against the bandwidth-optimal bound for large D and the log-latency bound for small D — the cost model must be calibrated per cluster (P4), never hardcoded.

4.2 Worked overlap budget (why ≥ 80 % hidden is the target)

  • A step's wall-clock with perfect overlap is max(compute, comm); with no overlap it is compute + comm.
  • Suppose backward compute = 40 ms and gradient allreduce comm = 30 ms. Serial: 70 ms. Fully overlapped: max(40,30)=40 ms → 1.75× speedup; the 30 ms of comm is free.
  • But overlap requires independent work to hide behind: gradients for layer L can allreduce while layer L−1's backward runs (reverse-order availability). The scheduler exploits exactly this (P9).
  • Overlap % = hidden_comm / total_comm. At 80 %, effective comm = 0.2·30 = 6 ms → wall-clock ≈ max(40, 40+6) ≈ 46 ms (vs 70 ms serial).
  • Ceiling: if comm > compute, even perfect overlap leaves comm − compute exposed → the workload is comm-bound, and the only fix is reducing volume (partitioning, P6) or raising bandwidth (topology/transport, P12).
  • This is why §4 targets ≥ 80 % overlap and near-optimal collective bandwidth — the two levers multiply.

4.3 Failure-detection budget (the detection-vs-false-positive tradeoff)

  • Detection time ≈ k · heartbeat_interval (k = suspicion confirmations). Smaller heartbeat/k → faster detection but more false positives (a slow rank wrongly declared dead).
  • Example: heartbeat=200 ms, k=3 → detection ≈ 600 ms (< the §4 "3×heartbeat" bound) with low false-positive rate via SWIM indirect probes.
  • The cost of a false positive is high (the whole job fail-stops), so the default leans conservative; the cost of slow detection is a hung job — both are bounded, never unbounded (principle 8, I12).
  • The bound holds independent of N because heartbeats use the SWIM gossip pattern (O(1) load per rank), so detection time does not grow with world size.

Performance Engineering

  • Cost model first: every collective placed against the α–β model + the bandwidth-optimal bound; the ring/RHD crossover is the canonical tuning artifact.
  • Profiling: distributed timeline (merged per-rank traces), network counters (bandwidth, retransmits), perf on the data plane, flamegraphs.
  • Overlap analysis: measure comm hidden behind compute (overlapped_ns / comm_ns); the headline lever (≥ 80 %).
  • Transport tuning: socket buffers, TCP_NODELAY for control, multiple connections for bandwidth, zero-copy writev.
  • Collective tuning: chunk size, stream count, fusion thresholds, hierarchical (intra/inter-node) topology.
  • Local compute: delegate to #349; per-rank GEMM efficiency is its own lever.
  • Determinism cost: det-mode (fixed reduction order) has a measured overhead — reported. On comm-bound workloads the overhead can be 5–15% (less pipelining freedom); on compute-bound workloads it is negligible. Always benchmark before disabling in production.
  • Roofline model: for each collective, plot achieved bandwidth vs message size against the α–β model prediction. A point far below the roofline indicates a transport bug, a serialization bottleneck, or a miscalibrated NetParams. A point above the roofline indicates measurement error (warmup missing, clock skew).
  • Scaling efficiency: defined as speedup(N) / N; ideal = 1.0. Communication overhead drives this below 1 — the partitioner (P6) and overlap (P9) are the tools to recover it. Track scaling efficiency at N = {2, 4, 8, 16, 32, 64} in the nightly bench suite.
  • Targets: §4 (M1–M12) — enforced by the multi-host bench gate. Regressions ≥ 5% against M1 (bandwidth-%-of-bound) or M4 (overlap%) block merge; a ≥ 10% regression against M9 (failure detection time) or M7 (barrier latency) triggers a mandatory investigation before merge.

Back-of-Envelope Capacity Model

Derived from §4 System Constraints. Symbols: N = world size, D = tensor bytes, α = per-message latency (s), β = 1/bandwidth (s/byte), chunk = ring buffer size (bytes).

1. Ring allreduce bytes/rank Formula: 2·(N−1)/N·D Example: N=64, D=1 GB → 2·63/64·1e9 = 1.969 GB moved per rank. This is essentially 2D for large N, and it is N-independent in the limit — the key bandwidth-optimality result.

2. Ring allreduce time (bandwidth-dominated) Formula: 2·(N−1)/N·D·β Example: N=64, D=1 GB, link=25 GB/s (β=40 ps/byte) → 1.969e9 · 40e-12 = 78.7 ms. At 90% efficiency (§4 target) this is ~87 ms wall-clock.

3. RHD allreduce time (latency-dominated) Formula: 2·log₂N·α Example: N=64, log₂64=6, α=5 µs → 2·6·5e-6 = 60 µs for a small (1 KB) message. Compare ring for the same message: 2·63·5µs = 630 µs — RHD is 10× faster on latency-dominated workloads.

4. Crossover message size D* Ring and RHD share the same bandwidth term; the choice is driven by the latency term. Ring's latency = 2(N−1)·α; RHD's latency = 2·log₂N·α. The practical crossover where ring's bandwidth efficiency starts justifying its higher latency is empirically: D* ≈ α·N / β (ignoring constants). Example: N=64, α=5µs, β=40ps/byte → 5e-6·64 / 40e-12 ≈ 8 MB. Below 8 MB prefer RHD; above prefer ring. This number must be measured per cluster — it varies by 10× between a 1 GbE LAN and a 200 Gb/s InfiniBand fabric.

5. Per-rank tensor memory (sharded) Formula: global_bytes / N Example: 7B parameter model, f32 (4 bytes/param) = 28 GB total; N=64 → 28e9/64 = 437 MB per rank. This is the ZeRO-3 parameter sharding budget. At N=512 it drops to 54 MB/rank — fitting comfortably in CPU DRAM even for large models.

6. Overlap opportunity Formula: min(compute_time, comm_time) / serial_time Example: backward=40 ms, allreduce=30 ms, serial=70 ms → min(40,30)/70 = 42.9% max speedup from overlap; wall-clock floor = max(40,30) = 40 ms (vs 70 ms serial = 1.75× speedup). When comm > compute, say backward=25 ms and allreduce=45 ms: floor = 45 ms, overlap saves only 25/70 = 35.7% — the job is comm-bound and needs less communication, not more overlap.

7. Transport in-flight bytes (flow control window) Formula: window_bytes ≥ 2 × BDP where BDP = link_BW × RTT Example: 25 GB/s link, RTT=200µs → BDP = 25e9·200e-6 = 5 MB; recommended window = 10 MB. Setting the window too small (< BDP) starves the pipe; too large risks OOM under a slow receiver. The JobConfig.window_bytes default is 2×BDP of the expected cluster.

8. Barrier latency (dissemination) Formula: log₂N · (α + small_msg_time) Example: N=64, α=5µs, 8-byte msg at 25 GB/s (negligible) → 6·5µs = 30 µs. This is the §4 "O(log N) rounds" target. Compare a naive all-to-coordinator barrier: N·α = 64·5µs = 320 µs — 10× worse, and it scales O(N).

9. Bootstrap table size Formula: N · (hostname + port) ≈ N · 64 bytes Example: N=1024 → 1024·64 = 65 KB — tiny; the O(N) cost is in the coordinator fan-out (N TCP connections + N×64 bytes broadcast), not in the data volume. For N=1024, a 1 Gbit coordinator link can broadcast the table in 65e3·8 / 1e9 = 0.5 ms — the latency cost (N serial round trips) dominates, motivating the tree-broadcast for large N (§8.13, §4.3).

10. Failure detection latency Formula: k · heartbeat_interval Example: k=3, heartbeat=200ms → 600 ms detection bound. SWIM indirect probes reduce false positives without changing the detection bound — a slow rank is probed via a third party before being declared dead. At N=1024, gossip-style SWIM disseminates failure information in O(log N) = ~10 gossip rounds at heartbeat_interval each → ~2 s for full dissemination at 200 ms intervals. The §4 target of < 3×heartbeat is for detection, not full dissemination.
