In one paragraph

A SAT/SMT solver answers one question about a logical formula: is there an assignment of values that makes it true, and if not, can the solver prove there is none? This design builds one from scratch in Rust, as a library (libhybrid) plus one CLI binary (§1). A search engine that learns from every dead end (a CDCL SAT core) is driven over theories of equality, linear arithmetic, bit-vectors and arrays, and the theories are combined by exchanging equalities (Nelson-Oppen) (§1). It is built for engineers learning constraint solving and for tool authors who need an embeddable solver (§1). One property outranks speed: a wrong answer is a total failure (§4, P1).

The problem, concretely

A verification tool wants to know whether a set of constraints can all hold at once (§1). The blueprint's own script (§8.2) asserts x + y <= 3 and x >= 2, then opens a scope with push and adds y >= 2. The answer is unsat, because the three constraints are jointly impossible. After pop the same solver answers sat with the model x = 2.0, y = 1.0 (§8.2). Industrial instances run to millions of clauses (§2), and four naive approaches fail:

  • Search without learning. Plain backtracking (DPLL) forgets why each branch failed, so it re-explores the same dead ends: "no learning = DPLL = exponential" (P4). The design keeps a deliberately slow DPLL only as a test oracle (Phase 1, Testing Strategy "differential").
  • Floating point. In a yes/no decision procedure one rounding error flips the answer, and 0.1+0.2 ≠ 0.3 can decide a benchmark wrong silently (MM7, Consolidated Pitfalls item 4). The design uses exact fractions (ADR-11).
  • Trusting the answer. A watcher bug that drops a unit clause gives a wrong sat that is "silent, catastrophic" (P1). So a reported model must satisfy the original formula (I8), and an unsat must come with a proof an external checker accepts (I9, §4 "Answer integrity").
  • Solving once. Real clients ask 10³–10⁶ related questions (Scalability Analysis). A solve-once design restarts from scratch each time (P10), which is useless for verification loops.

There is also a modelling gap. The search engine only knows true and false, while the formula talks about arithmetic, arrays and function symbols (§1, §8.3). The architecture exists to bridge that gap without letting theory knowledge leak into the search engine (§1, P12).

How it works, end to end

Follow one SMT-LIB script through the boxes of §3. The diagram below is adapted from §3, with the detail inside each box removed:

 input (.cnf / .smt2)
   │
   ▼
 parse ──────────────────────▶ the only box that touches untrusted text
   │ CNF                │ SMT terms
   ▼                    ▼
 preprocess        smt frontend  (atom ↔ Bool var, assertion stack, combination router)
   │ CNF                │ Boolean skeleton + atoms
   └────────┬───────────┘
            ▼
      CDCL SAT CORE  (decide · BCP · analyze 1-UIP + backjump · clause DB · trail)
            │ T-atoms assigned          ▲ theory lemmas / propagations
            ▼                           │
      DPLL(T) THEORY LAYER:  EUF | LRA/LIA | Bit-vectors | Arrays
                   shared equalities (Nelson-Oppen)
            │
            ▼
   SAT + model   |   UNSAT + DRAT proof / core
  1. parse reads DIMACS or an SMT-LIB 2 command loop (set-logic, declare-fun, assert, check-sat, push, pop, get-*) and builds typed terms. It is the only component that consumes untrusted text; everything downstream sees validated structures (§3 "Boundaries", T1).
  2. preprocess shrinks the formula first: Tseitin encoding of non-clausal formulas, top-level unit propagation, pure-literal elimination, subsumption, bounded variable elimination, blocked-clause elimination (§3, Phase 4).
  3. smt (the "smt frontend") gives each theory atom, such as (<= (+ x y) 3), a fresh Boolean variable, hands the Boolean skeleton to the SAT core and routes atom values back to the right theory (§3, §8.3). It also owns the assertion stack that makes push/pop work (§3, §11).
  4. cdcl on top of core is the engine. decide picks the next literal by activity, BCP (Boolean constraint propagation) forces consequences, analyze turns a conflict into a learnt clause and a backjump level, and the clause database keeps or deletes learnt clauses. The trail, the stack of assignments with levels and reasons, is the single source of truth (§3, P2).
  5. theory defines one trait that every theory implements: assert, check, propagate, explain, push, pop, model (§3, §11). Behind it sit theories/euf (congruence closure), theories/arith (simplex, branch-and-bound, exact rationals), theories/bv (bit-blasting back into cdcl) and theories/arrays (lazy axioms) (§3, §10).
  6. combine purifies mixed terms and exchanges entailed equalities between theories (§3, I13).
  7. proof verifies the model on SAT, writes the DRAT trace and extracts the unsat core on UNSAT (§1, §10, I8, I9).

An incremental session shows the pieces cooperating (Domain Deep Dive D.8). With a named assertion a1: f(x) = f(y) already sat, a push adds x = 2, y = 3 and f(x) != f(y). The EUF theory alone finds the contradiction, get-unsat-core returns (a1 a4) and omits the arithmetic facts, and after pop the learnt clauses that depended on the popped assertions are dropped while the independent ones are reused (Domain Deep Dive D.8, I6, P10).

The core ideas

Conflict-driven clause learning with 1-UIP (P4, I3, ADR-08)

When propagation produces a clause whose literals are all false, the solver does not just back up one step. It walks backwards through the reasons that forced each literal, resolving until exactly one literal of the current decision level is left (the first unique implication point, 1-UIP). That literal becomes the one the new clause asserts, and the solver jumps to the second-highest level in the learnt clause, not just one level up (§1 "non-chronological backjump", Phase 2 "Detailed Implementation Steps", I3, I4). The blueprint's worked trace, copied from Domain Deep Dive D.1, has clauses c1=(¬1∨2), c2=(¬1∨3), c3=(¬2∨¬3∨4), c4=(¬4∨5), c5=(¬4∨6), c6=(¬5∨¬6) and decides variable 1 true at level 1:

BCP: 1 → c1 ⇒ 2@1 (reason c1); c2 ⇒ 3@1 (c2); c3 ⇒ 4@1 (c3); c4 ⇒ 5@1 (c4); c5 ⇒ 6@1 (c5)
c6 = (¬5 ∨ ¬6): both 5,6 true ⇒ CONFLICT
analyze: start from c6 {¬5,¬6}. Both at level 1. Resolve on the last-assigned (6) against its reason c5={¬4,6}:
   {¬5,¬6} ⊗6 {¬4,6} = {¬5,¬4}. Resolve on 5 against c4={¬4,5}: {¬4,¬4}={¬4}.
   Now exactly one literal at level 1 (¬4) → 4 is the 1-UIP.
learnt = (¬4); backjump level = 0 (no other level). Assert ¬4 at level 0.

The one learnt clause (¬4) is stronger than the decision-cut (¬1), since it prunes every future branch where 4 is true, not only this decision (Domain Deep Dive D.2).

Two-watched literals: an invariant, not an algorithm (P3, I2, MM4, ADR-07)

Scanning every clause on every assignment is far too slow (P3). Instead each clause watches two of its literals. Only when a watched literal becomes false does the solver look at that clause: it tries to find a new non-false literal to watch; if none exists and the other watch is unassigned, the clause is unit and propagates; if the other watch is false, it is a conflict (Phase 2 "Detailed Implementation Steps"). Each watch also stores a cached blocker literal so the common satisfied case avoids dereferencing the clause (§11, Phase 2 "Performance Concerns"). The key insight (MM4) is that the watches survive a backjump untouched, because only the trail is truncated, so checking the invariant "each clause's two watches are unassigned, or the clause is satisfied, unit or conflicting" (I2) afterwards is a pure structural audit. Trying to "undo" watch moves on backtrack is the classic killer bug and gives a wrong sat (MM4, Phase 2 "Pitfalls").

DPLL(T): theory atoms as Boolean proxies (P5, P11, P12, MM5)

Each theory atom gets a Boolean variable bA. When the core sets bA true the atom goes to the theory, and when false its negation does; the theory only has to decide whether the asserted atoms are jointly satisfiable (§8.3). The loop is the state table of §8.4, in short: Propagate with BCP; on a conflict, analyze and backjump; at a Boolean fixpoint with everything assigned, run theory.check(FULL), which returns Sat or a conflict whose explanation is learnt as a clause; with variables left, call theory.propagate(), and if it returns nothing, decide (§8.4). The table sends a conflict whose backjump level is 0 to Unsat (§8.4), while D.1 backjumps to level 0 and asserts the learnt literal there, and Phase 2 "Edge Cases" says a conflict at level 0 is UNSAT and a learnt unit clause backjumps to level 0 (Domain Deep Dive D.1, Phase 2). The seam is the point: "theory lemmas are just clauses" (P5), so the core is blind to what atoms mean (MM5, P12). Domain Deep Dive D.3 runs it on proxies b1=(x≥2), b2=(y≥2), b3=(x+y≤3): the simplex finds the three bounds infeasible, explain() returns {b1,b2,b3}, and the clause (¬b1 ∨ ¬b2 ∨ ¬b3) is learnt like any other. Two refinements (Domain Deep Dive D.4): full check runs only at the fixpoint (P11), while cheap propagate runs continuously; after b1 and b3 are assigned, simplex can force b2 false before the core ever decides it, with lazy reason {b1,b3} (MM6).

Congruence closure for equality and functions (ADR-17, I11, I5)

The EUF theory keeps a union-find of terms plus a signature table, so that a=b implies f(a)=f(b), and a proof forest to explain every derived equality (§3, §11, ADR-17). The blueprint's example (§8.5) asserts a=b, b=c and f(a)≠f(c):

  • The structure merges {a,b}, then {a,b,c}; the signatures of f(a) and f(c) collide, so f(a)=f(c) is derived (§8.5).
  • That contradicts f(a)≠f(c), a T-conflict. The explanation is (a=b ∧ b=c) ⟹ f(a)=f(c), learnt as ¬(a=b) ∨ ¬(b=c) ∨ (f(a)=f(c)) over atom proxies, and with the asserted disequality it gives UNSAT (§8.5).

Every explanation must be entailed by the theory (I5), and every merge must leave all applications congruent (I11). A missed congruence gives a wrong sat (Consolidated Pitfalls item 6).

Simplex for satisfiability, with exact numbers (ADR-11, ADR-12, I10)

The arithmetic theory does not optimise anything; it searches for values that respect every variable's bounds. Basic variables are linear combinations of nonbasic ones, and each variable has a current value and optional lower and upper bounds (Domain Deep Dive D.6). The blueprint's trace, copied from D.6, has s1 = x + y, s2 = x − y, bounds s1 ≥ 2, s1 ≤ 4, s2 ≤ 1, x ≥ 0, y ≥ 0, starting from x=y=0:

check: s1=0 violates s1≥2 (lower bound). s1 is basic and too low.
  → need to increase s1. s1 = x + y; increasing a nonbasic with positive coeff raises s1.
  pick nonbasic x (coeff +1), able to increase (x has no upper bound) → pivot x into basis for s1.
  raise s1 to its bound 2 ⇒ x = 2 (y still 0). Now s1=2 ✓.
recheck: s2 = x − y = 2 − 0 = 2, violates s2 ≤ 1 (upper). s2 too high.
  → decrease s2. s2 = x − y; decrease by lowering x (coeff +1) or raising y (coeff −1).
  x is basic now (tied to s1's bound); raise y instead. Raising y lowers s2 and raises s1.
  but s1 is at its lower bound 2 and may rise to ≤4 (slack of 2). Raise y by 1 ⇒ s2=1 ✓, s1=3 ✓ (≤4).
result: x=2, y=1, s1=3, s2=1 — all bounds satisfied ⇒ SAT, model (x=2, y=1).

If s1 ≥ 5 were added, no pivot could satisfy it, and the blocked row yields the explanation {s1≤4, s1≥5}, which becomes the T-conflict clause (Domain Deep Dive D.6). Bland's rule (pick the lowest-index eligible variable) guarantees the pivoting never cycles (I10, Domain Deep Dive D.6). Numbers are arbitrary-precision fractions, so x=7/3 is stored exactly (ADR-11, Domain Deep Dive D.6). Read the trace with care: its first step pivots x into the basis for s1, while its second step keeps x at 2 and lets s1 rise from 2 to 3; the blueprint does not comment on this (Domain Deep Dive D.6).

Nelson-Oppen: theories exchange facts, never guesses (I13, MM9, ADR-16)

Mixed formulas, such as f(x+1), need two theories at once. Purification rewrites them so each atom belongs to one theory, by naming the boundary: f(x+1) becomes w = x+1 for arithmetic and f(w) for EUF (Phase 10 "Detailed Implementation Steps"). Variables used by two or more theories are the shared variables. After each check, a theory reports the equalities between shared variables that it can prove, the others receive them, and this repeats to a fixpoint (Phase 10, I13). Only entailed equalities may travel: one guessed equality produces a wrong UNSAT (MM9, Consolidated Pitfalls item 9). Linear integer arithmetic is non-convex, meaning it can entail a disjunction of equalities without entailing either one, so the disjunction is handed to the SAT core as a case split (Phase 10, MM9, Glossary).

The trade-offs — where engineers disagree

Language: Rust (ADR-01)

Chosen: Rust (stable), for a safe arena and a GC-free hot loop (ADR-01, §1). Rejected: C++ and OCaml (ADR-01). When the rejected choice is right: C++ when reusing a mature C++ codebase such as Z3 or CVC5 internals, or when template-metaprogramming dispatch and the deepest existing solver tooling matter; OCaml for a prototype where theory and AST logic dominate and BCP speed is irrelevant (ADR-01).

Propagation: two-watched literals with a blocker (ADR-07)

Chosen: two-watched literals plus a blocking literal, "the proven fast path" (ADR-07). Rejected: counter or occurrence lists (ADR-07). When the rejected choice is right: when you need every clause touching a literal anyway. Preprocessing (bounded variable elimination, subsumption, vivification) is built on occurrence lists, not watches (ADR-07, Phase 4).

Conflict analysis: 1-UIP with minimization (ADR-08)

Chosen: 1-UIP plus clause minimization, the strongest practical learning (ADR-08). Rejected: last-UIP and decision-cut learning (ADR-08). When the rejected choice is right: the decision-cut wins as the core-extraction mechanism, because it names exactly the responsible decisions or assumptions; last-UIP can win on instance families where it keeps clauses shorter and more reusable than 1-UIP (ADR-08).

Numbers in arithmetic: exact rationals (ADR-11)

Chosen: arbitrary-precision rationals (GMP via rug), for exactness with no overflow or rounding (ADR-11, MM7). Rejected: i64 and f64 (ADR-11). When the rejected choice is right: machine numbers win in an unsound-but-fast pre-filter pass, such as a floating-point simplex that proposes a model later certified exactly, or when the logic is provably small-coefficient and bounded (ADR-11).

Bit-vectors: bit-blast to the SAT core (ADR-14)

Chosen: compile each bit-vector operation to a propositional circuit and let the SAT core solve it, "simplest correct" (ADR-14, MM8). Domain Deep Dive D.7 does it for a 2-bit multiplier. Rejected: a word-level solver (ADR-14). When the rejected choice is right: wide datapaths dominated by structure, such as large multipliers and equalities over 256/512-bit vectors, where bit-blasting explodes (Capacity C7) and word-level or lazy techniques stay small (ADR-14). The blueprint defers word-level reasoning (Stretch Goals).

Combining theories: Nelson-Oppen first (ADR-16)

Chosen: deterministic Nelson-Oppen equality sharing, "classic, debuggable first" (ADR-16, MM9). Rejected: model-based combination, labelled "(Phase 2)" in the ADR row (ADR-16). When the rejected choice is right: in production. Model-based combination (Z3, CVC5) guesses shared equalities from a candidate model and is markedly faster on large mixed instances where exhaustive entailed-equality exchange is the bottleneck (ADR-16, Comparative Architecture). The blueprint also calls it a "Phase-2 optimization" (Phase 10 "Performance Concerns", Comparative Architecture), while Phase 2 is the CDCL core and the Stretch Goals list model-based combination as deferred (Phase 2, Stretch Goals).

Proofs: a DRAT trace for the SAT layer (ADR-18, ADR-19)

Chosen: emit a DRAT trace and check it with DRAT-trim, the de-facto standard (ADR-18, I9). For SMT, unsat cores now and full certificates deferred (ADR-19). Rejected: LRAT, or no proof (ADR-18); Alethe certificates now (ADR-19). When the rejected choice is right: LRAT when the checker itself must be formally verified and fast, since its hint indices let a verified checker validate in near-linear time; Alethe or LFSC when a proof assistant such as Isabelle or Coq must replay the proof, because then a core is insufficient and the proof object is the deliverable (ADR-18, ADR-19).

Roads not taken

Eager SMT (ALT-1): flatten every theory to one SAT call. It wins on pure finite-domain bit-vector problems with bitwise operations and no wide multipliers, as in early Boolector and STP. It is rejected because it explodes on EUF and wide multipliers and discards the theory seam, though bit-blasting is kept inside the lazy framework (Alternative Architectures ALT-1, ADR-14).

Stochastic local search (ALT-2): WalkSAT and probSAT repeatedly flip variables in unsatisfied clauses. It wins on large satisfiable random or loosely structured instances where no UNSAT proof is needed. It is rejected on kind, since it is incomplete, cannot produce a DRAT proof and cannot host DPLL(T) (Alternative Architectures ALT-2).

Parallel portfolio (ALT-3): race diverse configurations and share short clauses. It wins on a multicore machine with a deadline over a diverse benchmark set (ManySAT, Plingeling). It is deferred because it trades away the determinism the debugging method needs and multiplies memory (Alternative Architectures ALT-3, P7, I14).

Cube-and-conquer (ALT-4): a look-ahead splitter feeds many parallel CDCL solvers. It wins on the hardest combinatorial UNSAT instances, such as the Boolean Pythagorean Triples problem. It is deferred as a second search engine plus a parallel harness (Alternative Architectures ALT-4).

The blueprint's own summary: ALT-1, ALT-3 and ALT-4 are rejected on sequencing, and only ALT-2 on kind (Alternative Architectures, "common rejection pattern"). The Stretch Goals also defer quantifier instantiation, nonlinear arithmetic, floating point and full SMT proofs (Deferred Features Register). The register gives every one of its five features, portfolio included, the building phase "post-Phase-12" (Deferred Features Register), while Phase 12 says its optional portfolio "fulfils" that deferral, and ALT-3, Appendix B and M12 put the portfolio in Phase 12 (Phase 12 "Objectives", Alternative Architectures ALT-3, Appendix B, Performance Engineering M12). The Stretch Goals heading says "post-Phase-0", and the section says each of its ten items is gated behind a PhaseDeferred reference, though only five carry one (Stretch Goals). The blueprint does not reconcile these.

What must never be false

  • I1: every assigned literal is on the trail exactly once with a level and reason. Noticed by a trail/assign-map cross-check; telemetry trail_len.
  • I2: each clause's two watches are unassigned, or the clause is satisfied, unit or conflicting. Noticed by a watcher audit pass; bcp_watch_violations.
  • I3: a learnt 1-UIP clause is asserting, with exactly one literal at the conflict level. Noticed by a level histogram of learnt clauses; learnt_not_asserting.
  • I4: a backjump truncates the trail to the asserting level and re-propagates. Noticed by a post-backjump consistency check; backjump_level.
  • I5: theory explanations are entailed by the theory. Noticed by replaying each explanation; explain_unsound_total.
  • I6: theory push/pop restores exactly the state at that level. Noticed by a checkpoint-hash compare; theory_state_mismatch.
  • I7: the atom to theory-literal mapping is a bijection within a solve. Noticed by a map consistency check; atom_map_errors.
  • I8: a reported model satisfies every original assertion. Noticed by re-evaluating all clauses and atoms after SAT; model_check_fail.
  • I9: the DRAT trace checks against an external checker. Noticed by DRAT-trim in CI; proof_check_fail.
  • I10: simplex never cycles. Noticed by a pivot-count bound and cycle guard; simplex_pivots.
  • I11: congruence closure leaves every application congruent. Noticed by a signature-table audit; cc_missing_congruence.
  • I12: bit-blasting preserves meaning. Noticed by differential testing against brute force on small widths; bv_blast_mismatch.
  • I13: Nelson-Oppen exchange propagates only entailed shared equalities. Noticed by an entailment check; no_unsound_eq.
  • I14: decisions are a deterministic function of the formula and seed. Noticed by replay equality; nondeterminism_detected.
  • I15: on a resource limit the result is unknown, never sat or unsat. Noticed by limit-hit accounting; limit_hits_total.

The soundness invariants (I5, I8, I9, I11, I12, I13) each have a "paranoid mode" checker that validates after every conflict, at high cost, to localise a bug to a minimal instance (§7, Operational Readiness).

What breaks in production

  • Wrong SAT. The model fails on the original formula, from a watcher, bit-blast or theory bug. Detected by the model self-check (I8); the solver refuses the answer and returns unknown; a human runs ddmin and a differential (Failure Modes "Wrong SAT").
  • Wrong UNSAT. The proof will not check, from unsound learning or an unsound explanation. Detected by DRAT-trim (I9) and the explanation audit (I5); the instance is quarantined and the theory fixed (Failure Modes "Wrong UNSAT").
  • Hang. No progress, from a simplex cycle or branch divergence. Detected by a budget and pivot cap (I10); the budget turns it into unknown (I15) (Failure Modes "Hang").
  • OOM. The resident set size climbs, from learnt-clause growth or bit-blast blow-up. A memory guard returns unknown and frees memory; a human raises the budget or simplifies (Failure Modes "OOM").
  • Incremental wrong. Wrong answers appear only after a pop, because a stale learnt clause survived. Found by incremental differential testing; recovery is dropping the dependent learnts (Failure Modes "Incremental wrong", Consolidated Pitfalls item 10).
  • Non-determinism. Flaky CI from an unordered tie-break. Found by replay equality (I14); fix by ordering the tie-break (Failure Modes "Non-determinism", MM10).
  • Theory unsoundness. One theory returns wrong answers from a bad explain or propagate (I5). Found by per-theory differential testing against a reference solver; the theory is disabled and the solver returns unknown (Failure Modes "Theory unsoundness").
  • Proof bloat. Multi-GB traces from missing deletion lines. A proof-size monitor catches it; fix by streaming, compressing and emitting d lines (Failure Modes "Proof bloat").

The blueprint notes that the SAT Competition has required machine-checkable UNSAT proofs in its Main Track since 2013, and that proof checking has caught solvers whose UNSAT answers did not certify. It adds that clean public postmortems of solver soundness bugs are rare, so none is invented (Failure Modes "Real-world incident note").

Threats worth knowing (Threat Model): T1 crafted DIMACS or SMT-LIB input crashing the parser, answered by strict validation, depth caps and fuzzing; T2 a wrong answer from a watcher, learning or theory bug, answered by the model self-check (I8), the DRAT proof (I9) and differential testing; T3 out-of-memory from an adversarial or wide-multiply formula, answered by a memory budget that returns unknown (I15); T4 a hang from degenerate simplex or branch divergence, answered by conflict and time budgets and Bland's rule (I10); T7 a forged or incorrect UNSAT proof, answered by the external DRAT-trim check.

The blueprint draws three conclusions (Capacity Model, "What the numbers jointly imply"). Memory is dominated by what you learn, not what you load (C2 against C4), so clause deletion is structural (ADR-10). Throughput is a bandwidth budget (C5), so data layout beats inner-loop cleverness (ADR-04, ADR-05). Blow-up is theory-local: the multiplier (C7) and bignum growth (C8) are the two cliffs.

Two places where the capacity text does not match what it cites. C7 says ten 64-bit multiplies, about 7×10⁵ clauses, are "already 3.5× the entire C1 input budget", but C1 sizes the input at 10×10⁶ clauses (Capacity Model C7, C1). And C6 cites "§4/M4" for the 5 s parse budget, though §4 has no parse row and only M4 states it (Capacity Model C6, §4).

How it compares

All of this is from the Comparative Architecture section; "this" is its Phase-0 design.

  • MiniSat chose radical minimalism: a few thousand lines of CDCL core, no preprocessing, activity-only clause deletion. That is fine as the canonical teaching and embedding reference, and this blueprint mirrors its SatSolver shape (§11).
  • CaDiCaL / Kissat made scheduled inprocessing a first-class citizen, interleaved with search. That is right in the competition regime, where simplifying mid-search beats any single heuristic; this design borrows it in Phase 4 and Phase 12 but keeps it bounded.
  • Z3 chose model-based theory combination and a vast breadth of theories, quantifiers and tactics. That fits general-purpose production SMT, where it is markedly faster on large mixed instances; this design starts with deterministic Nelson-Oppen because it is debuggable (ADR-16, MM9).
  • Boolector / Bitwuzla reason at the word level before lazily bit-blasting. That fits wide datapaths, the exact regime where this design's eager bit-blasting hits its cliff (ADR-14, C7).
  • CVC5 chose a proof-producing, theory-rich architecture with fine-grained proof objects. That fits certified verification, where a proof assistant must replay the proof; this design ships cores and defers full certificates (ADR-19).
  • Yices2 is lean and built around the author's own simplex with exact arithmetic. That fits arithmetic-heavy, latency-sensitive tools; this design follows its simplex lineage (ADR-12) but prefers a teachable multi-theory seam over single-theory peak speed.

Questions to test yourself

  1. Why does deleting a learnt clause never cause a wrong answer, while a single bad theory explain() does — and what does that asymmetry imply for where you spend audit effort? — Hint: MM2 and P5.
  2. Watches survive backjumping untouched, yet the watcher invariant must still hold afterward. Reconcile these two statements and explain why "undoing" watch moves on backtrack is the classic killer bug. — Hint: MM4 and Phase 2 "Pitfalls".
  3. Trace how a theory.check() conflict becomes indistinguishable, to the SAT core, from a propositional learnt clause — and why that indistinguishability is the property that makes new theories pluggable. — Hint: §8.4, Domain Deep Dive D.3, and MM5.
  4. Nelson-Oppen may exchange only entailed shared equalities. Show how exchanging a merely model-true equality (the model-based shortcut) can produce a wrong UNSAT, and what non-convexity (LIA) forces instead. — Hint: MM9, I13, and Phase 10.
  5. Quantify why LBD-based clause deletion is mandatory rather than a tuning knob, using the conflict rate and learnt-clause size. — Hint: Capacity C4 and ADR-10.

If you only remember three things

Everything rests on the trail: the assignment stack is the solver's one source of truth, and watches, theory state and learnt clauses are views that must agree with it at every level (MM1, P2). The seam between the blind SAT core and the theories is "theory lemmas are just clauses", so a new theory only has to produce sound explanations, and an unsound explanation is the one thing that cannot be allowed (P5, MM2, I5). A wrong answer is worse than a slow one, which is why the design uses exact rationals, self-checked models, externally checked proofs and deterministic runs, and builds that scaffolding before chasing speed (P1, I8, I9, I14, Final Notes).

Words used here

  • SAT / SMT: find a true/false assignment satisfying a formula; or the same over theory atoms such as arithmetic (Glossary).
  • CNF / clause / literal: an AND of OR-clauses; a clause is an OR of literals; a literal is a variable or its negation (Glossary).
  • CDCL: conflict-driven clause learning, the modern SAT search (Glossary).
  • DPLL(T): DPLL or CDCL driving theory solvers, the lazy SMT architecture (Glossary).
  • Trail: the assignment stack with levels and reasons (Glossary).
  • BCP: Boolean constraint propagation, forcing unit clauses (Glossary).
  • 1-UIP: first unique implication point, the literal a learnt clause asserts (Glossary).
  • Backjump: backtracking non-chronologically to the asserting level (Glossary).
  • LBD (glue): the number of distinct decision levels in a clause, a quality measure (Glossary).
  • EUF: equality plus uninterpreted functions, solved by congruence closure (Glossary).
  • Simplex / Bland's rule: the feasibility-pivoting method, and its anti-cycling rule (Glossary).
  • Bit-blasting: compiling bit-vector operations into propositional circuits (Glossary).
  • Purification: splitting mixed terms so each atom is single-theory (Glossary).
  • Unsat core: a minimal subset of assumptions or assertions that is already unsatisfiable (Glossary).
  • DRAT: the externally checkable clausal proof format for UNSAT (Glossary).
