Language

Chosen

Rust (stable)

Rejected

C++, OCaml

When the rejected choice is right

C++ wins when reusing a mature C++ codebase (Z3/CVC5 internals, MathSAT) or needing template-metaprogramming dispatch + the deepest existing solver tooling; OCaml wins for a prototype where the theory/AST logic dominates and BCP speed is irrelevant (Alt-Ergo is OCaml)

04

Clause storage

Chosen

contiguous arena, 32-bit ClauseRef

Rejected

boxed clauses

When the rejected choice is right

boxed clauses win when clauses are large, long-lived, and rarely scanned (a proof-object store, an interactive prover's hypothesis DB) so pointer stability + individual free matter more than BCP cache behavior

Why: cache locality, compaction

05

Literal encoding

Chosen

packed u32 (var<<1|sign)

Rejected

struct{var,sign}

When the rejected choice is right

the struct wins past 2³¹ variables (need 64-bit var ids) or when literals carry extra metadata (theory tag, polarity hint) that a packed u32 cannot hold

Why: half the memory, fast neg

06

Var order

Chosen

binary heap keyed by VSIDS activity

Rejected

array scan

When the rejected choice is right

a linear array scan wins on tiny formulas (≤ a few hundred vars: heap overhead > scan) and is exactly right inside a theory's small internal search where n is bounded

Why: O(log n) decide

07

BCP

Chosen

two-watched literals + blocking literal

Rejected

counter/occurrence lists

When the rejected choice is right

occurrence/counter lists win when you need every clause touching a literal anyway — preprocessing (BVE, subsumption, vivification) is built on occurrence lists, not watches (Phase 4)

Why: the proven fast path

08

Conflict analysis

Chosen

1-UIP + clause minimization

Rejected

last-UIP, decision-cut

When the rejected choice is right

the decision-cut (all-decision clause) wins as the core extraction mechanism (it names exactly the responsible decisions/assumptions) and last-UIP can win on instance families where it keeps shorter, more-reusable clauses than 1-UIP

Why: strongest practical learning

09

Restarts

Chosen

Luby + glucose (LBD-based) selectable

Rejected

fixed-interval

When the rejected choice is right

a fixed (or no) restart interval wins on easy, satisfiable, structured instances where restarting throws away a nearly-complete model — many SAT-track instances solve fastest with rare restarts

Why: adaptivity

10

Clause deletion

Chosen

LBD + activity, periodic reduce

Rejected

size-only

When the rejected choice is right

pure size-based deletion wins under a hard memory cap with uniform-quality clauses (no useful LBD signal — e.g. heavily bit-blasted CNF where almost all clauses are short and similar)

Why: keeps "glue" clauses

Arithmetic numbers

Chosen

arbitrary-precision rationals (GMP via rug)

Rejected

i64/f64

When the rejected choice is right

machine i64/f64 wins in an unsound-but-fast pre-filter pass (a floating-point simplex as in many LP solvers/CPLEX) that proposes a model later certified exactly — or when the logic is provably small-coefficient and bounded

LRA engine

Chosen

general simplex (Dutertre–de Moura)

Rejected

Fourier-Motzkin

When the rejected choice is right

Fourier-Motzkin wins for tiny, low-dimension systems and for quantifier elimination (its real job): eliminating a variable symbolically, which simplex cannot do

Why: scales, incremental

13

LIA

Chosen

branch-and-bound + Gomory cuts

Rejected

Omega test only

When the rejected choice is right

the Omega test wins when you need a complete, terminating decision for Presburger/parametric integer constraints with small variable counts (dependence analysis in compilers uses Omega) where branch-and-bound could diverge

14

BV

Chosen

bit-blasting to SAT core

Rejected

word-level solver

When the rejected choice is right

word-level reasoning wins on wide datapaths dominated by structure — large multipliers, equalities over 256/512-bit vectors — where bit-blasting explodes (C7) and algebraic/lazy techniques (Boolector's mcbits, MathSAT) stay small

Why: simplest correct; word-level later

15

Arrays

Chosen

lazy axiom instantiation (rd-over-wr, ext)

Rejected

eager

When the rejected choice is right

eager (full Ackermannization / upfront axioms) wins when nearly every read/write pair interacts anyway (small dense array constraints) so laziness only adds solver round-trips with no pruning benefit

Why: avoids axiom blowup

16

Combination

Chosen

Nelson-Oppen (deterministic eq-sharing)

Rejected

model-based (Phase 2)

When the rejected choice is right

model-based combination (Z3, CVC5) wins in production: it guesses shared equalities from a candidate model and is markedly faster on large mixed instances where exhaustive entailed-equality exchange is the bottleneck

Why: classic, debuggable first

EUF

Chosen

union-find + signature table + proof forest

Rejected

e-graph rewrite

When the rejected choice is right

a full rewriting e-graph wins when the goal is equality saturation / optimization rather than a yes/no decision (egg, #43 AST optimizer) — you want the saturated set of equivalent terms, not one conflict explanation

Why: minimal, explanation-friendly

Proof (SAT)

Chosen

DRAT trace → DRAT-trim

Rejected

LRAT, none

When the rejected choice is right

LRAT wins when the checker must be formally verified and fast: LRAT carries hint indices so a verified checker (cake_lpr) validates in near-linear time without DRAT-trim's expensive unit-propagation search — the regime of certified UNSAT

Why: de-facto standard, external check

Roads not taken

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

ALT-1 — Eager SMT: bit-blast (and Ackermann-encode) everything to a single SAT call

formula ──▶ encode ALL theory atoms ──▶ one giant CNF ──▶ single CDCL solve ──▶ SAT/UNSAT
            (BV→gates, EUF→Ackermann,
             arrays→eager axioms)
  • Regime where it wins: pure, finite-domain QF_BV dominated by bitwise/structural operations with no wide multipliers — the eager flattening is simple, and a single well-tuned SAT solve beats the round-trip overhead of a lazy theory loop.
  • Real system: early Boolector and the eager mode of bit-vector solvers; STP for QF_BV/arrays.
  • Why rejected here: eager encoding explodes on EUF (Ackermann is O(pairs²)) and on wide multipliers (C7), and it discards the clean DPLL(T) seam (MM5/P12) that lets EUF/LRA/LIA/arrays plug in uniformly — the very architecture this project exists to teach.
  • What it would cost here: it collapses Phases 6–10 into one encoder + one SAT call, deleting the Theory trait — a smaller engine that cannot grow new theories. Bit-blasting is therefore kept within the lazy framework (ADR-14), not promoted to the whole engine.

ALT-2 — Stochastic local search (SLS): WalkSAT / probSAT instead of systematic CDCL

random assignment ──▶ pick an unsatisfied clause ──▶ flip a var (greedy + noise) ──▶ repeat
                       (no trail, no learning, no proof; incomplete)
  • Regime where it wins: large, satisfiable, random or loosely-structured instances (random 3-SAT near the phase transition, some hard combinatorial SAT) where local search finds a model far faster than systematic search — and where you do not need an UNSAT proof.
  • Real system: WalkSAT, probSAT, and the SLS components hybridized into modern solvers (SLS phases inside some CDCL solvers).
  • Why rejected here: SLS is incomplete — it can never prove UNSAT, produces no DRAT proof (violating P1/P14, I9), has no trail to anchor theory state (MM1), and cannot host DPLL(T).
  • What it would cost here: it would forfeit the project's core deliverable — checkable UNSAT (Phase 5) and the entire theory layer. It is at best a SAT-only accelerator bolted beside the CDCL core for satisfiable instances, not a foundation.

ALT-3 — Parallel portfolio: race diverse CDCL configurations, share short clauses

   ┌─ solver A (seed1, restart=luby) ─┐
in ─┼─ solver B (seed2, restart=glucose)┼─▶ first to finish wins
   └─ solver C (seed3, branch=LRB) ───┘   (share learnt clauses LBD≤k)
  • Regime where it wins: a multicore machine with a wall-clock deadline on a diverse benchmark set — different configurations win different instance families, so racing them with limited clause sharing beats any single configuration.
  • Real system: ManySAT, Plingeling / Treengeling (Biere), and most parallel SAT-competition entrants.
  • Why rejected for Phase 0: portfolio trades the determinism this blueprint treats as a debugging prerequisite (P7/I14/MM10) for speed, multiplies memory ×N (Capacity note: per-worker clause DBs), and is the most concurrency-bug-prone code (shared arenas — Phase 12 N.9).
  • What it would cost here: reproducibility — every soundness bug would become a heisenbug ddmin cannot shrink. It is therefore deferred (Stretch Goals; Phase 12 implements it behind a non-deterministic flag), not foundational; correctness and reproducibility come first.

ALT-4 — Cube-and-conquer / look-ahead: split into millions of subproblems

look-ahead splitter ──▶ cube₁ ─┐
(march-style)         cube₂ ─┼─▶ each cube solved by a CDCL "conquer" solver
                      ...   │     (in parallel; recombine for global answer)
                      cubeₘ ─┘
  • Regime where it wins: the hardest combinatorial UNSAT instances — pigeonhole-like and Ramsey/Schur problems — where a look-ahead heuristic (expensive per node, but globally informed) splits the space into cubes that CDCL then closes; this is how problems like the Boolean Pythagorean Triples were settled.
  • Real system: march (look-ahead) feeding a CDCL conqueror; the cube-and-conquer methodology (Heule, Kullmann, Biere).
  • Why rejected for Phase 0: it requires a second, fundamentally different search engine (look-ahead) plus a splitting heuristic and a parallel harness — enormous surface for a project whose Phase-0 bar is a correct single-thread CDCL + DPLL(T).
  • What it would cost here: a whole second solver and splitter before the first one is sound. It is deferred (Stretch Goals: parallel cube-and-conquer) and scales hard UNSAT better than the portfolio (Scalability "parallel scaling") when revisited.

The common rejection pattern. Three of the four (ALT-1, ALT-3, ALT-4) are not rejected on merit but on sequencing: each is a legitimate, sometimes superior architecture that this blueprint defers because it presupposes a correct, sound, deterministic single-thread CDCL+DPLL(T) core to build on or race. Only ALT-2 (SLS) is rejected on kind — it cannot produce the checkable UNSAT that is the project's reason to exist. The lesson the design space teaches: pick the architecture that makes the correctness scaffolding cheapest first (this design), then graduate to the production-grade alternative once the core is trustworthy — never the reverse.

Stretch Goals (post-Phase-0, blueprint of deferred surfaces)

  • Quantifier instantiation (PhaseDeferred("Stretch Goals")): e-matching over the e-graph + model-based quantifier instantiation (MBQI) for forall/exists.
  • Nonlinear arithmetic (PhaseDeferred("Stretch Goals")): NRA via cylindrical algebraic decomposition (CAD) or incremental linearization; NIA via bit-blasting bounded integers.
  • Floating-point (PhaseDeferred("Stretch Goals")): IEEE-754 via bit-blasting (rounding modes, NaN/inf) into QF_BV.
  • Full SMT proofs (PhaseDeferred("Stretch Goals")): Alethe/LFSC certificates for theory steps, externally checkable end to end (not just SAT-layer DRAT).
  • Parallel cube-and-conquer (PhaseDeferred("Stretch Goals")): a lookahead splitter generating cubes solved in parallel — scales hard UNSAT better than portfolio.
  • Word-level BV reasoning: avoid full bit-blasting for large widths via algebraic simplification + lazy blasting.
  • Model-based theory combination: replace deterministic N-O equality exchange with model-driven sharing (cheaper in practice).
  • MaxSAT / OMT (optimization modulo theories): minimize/maximize an objective subject to SMT constraints.
  • Strings + datatypes: the remaining mainstream SMT theories.
  • Proof-producing preprocessing: full provenance so even simplified-formula UNSAT is certified.

Each is gated behind its PhaseDeferred reference and tracked in BUILD_PLAN.md §6; none is required for the Phase-0 Done bar (QF_UF/LRA/LIA/BV/ABV, conformance-green, proofs check).

Consolidated Pitfalls (Top 10, cross-phase)

  1. Watcher invariant violated after backjump — dropped propagation → wrong SAT. Example: a clause whose watched literal was falsified at a now-undone level isn't re-watched. Guard: I2 paranoid audit.
  2. Last-UIP instead of 1-UIP — weaker learning, 10–100× slowdown. Example: stopping conflict analysis too late. Guard: stop at the first single-level literal (I3).
  3. Deleting a locked (reason) clause — dangling reason → crash or wrong answer. Example: reduce() removes a clause currently justifying a trail literal. Guard: lock reasons.
  4. Float in arithmetic — rounding → wrong sat/unsat. Example: 0.1+0.2 ≠ 0.3 decides feasibility. Guard: exact rationals only (ADR-11); no float type compiles in arith.
  5. Simplex cycling — nontermination on degenerate bases. Example: repeated pivots among zero-slack rows. Guard: Bland's rule (I10) + pivot cap.
  6. Missed congruence — a=b but f(a)=f(b) not derived → wrong SAT. Example: not re-canonicalizing applications after a merge. Guard: use-lists + I11 audit.
  7. Bit-blast off-by-one / sign error — silent wrong arithmetic. Example: ripple-carry MSB miswired. Guard: exhaustive ≤8-bit differential (I12).
  8. Eager array axioms — exponential blowup / OOM. Example: instantiating rd-over-wr for every select×store pair upfront. Guard: lazy, on-demand instantiation.
  9. Non-entailed equality in N-O exchange — wrong UNSAT. Example: a theory exports x=y it only guessed. Guard: export only proven equalities (I13) + entailment audit.
  10. Stale learnt clause after pop — wrong answer in incremental mode only. Example: keeping a learnt clause derived under a popped assertion. Guard: clause provenance vs assertion level (I6, Phase 11).

Final Notes

This blueprint deliberately layers two solvers: a self-contained CDCL SAT engine (phases 0–5) that is valuable on its own (dependency resolution #135, model checking #279), and a DPLL(T) SMT layer (phases 6–11) built strictly on top of it through one narrow interface (the Theory trait). The seam between them — Boolean abstraction in, theory lemmas out — is the single most important architectural decision; honor it (P12) and new theories are additive, violate it and the engine ossifies.

Three commitments are non-negotiable and recur in every phase: soundness (a wrong sat/unsat is total failure — guarded by model self-check I8, DRAT proofs I9, and differential testing), exactness (bignum rationals, never floats — I10/ADR-11), and determinism (seeded, ordered — I14 — so every bug reproduces). A solver that is fast but occasionally wrong is worthless; build the correctness scaffolding (paranoid audits, the ddmin minimizer, the differential harness) before chasing speed.

The Phase-0 Done bar is concrete: QF_UF, QF_LRA, QF_LIA, QF_BV, QF_ABV and their N-O combinations, conformance-green against an SMT-LIB subset, with checkable DRAT proofs for the SAT layer and self-verified models. Quantifiers, nonlinear arithmetic, floating-point, full SMT proof certificates, and parallelism are explicitly deferred behind typed PhaseDeferred references and tracked in BUILD_PLAN.md §6. Build the core the owner is here to understand; defer only what genuinely needs more weeks, never the algorithm itself.
