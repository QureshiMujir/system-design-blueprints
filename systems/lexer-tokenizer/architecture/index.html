Three properties are referenced throughout this document. First, the runtime crate never depends on the proc-macro crate at runtime (ADR-01, ADR-17); generated code expands into the embedder's own crate and references only mini_lex_runtime types. Second, the hand-written and generated lexers implement the same Lexer trait (P2, §11.5) and pass the same conformance fixtures (§28); an embedder swaps one for the other transparently. Third, the trivia model and span model are owned by the runtime, never duplicated per-backend (P3, P4) — span arithmetic and trivia attachment happen exactly once.

8. Domain Model

The domain model is a token grammar (EBNF, describing what byte sequences form which token classes for the seed language), a DFA state-transition table (how the automaton realises that grammar), one worked example, one malformed-input example, and one failure-path example.

8.1 Token grammar (EBNF, seed language)

token        = trivia | punct | literal | ident_or_kw | error ;
trivia       = whitespace | newline | line_comment | block_comment | shebang ;
whitespace   = ( " " | "\t" )+ ;
newline      = "\n" | "\r\n" ;                      (* bare "\r" is UnknownToken, §13.9 *)
line_comment = "//" , { any_char - newline } ;
doc_comment  = "///" , { any_char - newline } ;
block_comment= "/*" , { block_comment | any_char } , "*/" ;   (* nests, §13.6 *)
ident_or_kw  = xid_start , { xid_continue } ;                  (* UAX#31, promoted via PHF *)
literal      = number | string | template ;
number       = decimal | hex | binary ;
decimal      = digit , { digit | "_" } , [ "." , digit , { digit } ] ,
               [ ("e"|"E") , ["+"|"-"] , digit , { digit } ] , [ "n" ] ;
hex          = "0x" , hex_digit , { hex_digit | "_" } , [ "n" ] ;
binary       = "0b" , ("0"|"1") , { "0" | "1" | "_" } , [ "n" ] ;
string       = "'" , { escape | (any_char - "'" - newline) } , "'"
             | '"' , { escape | (any_char - '"' - newline) } , '"' ;
escape       = "\" , ( "n"|"t"|"r"|"\"|"'"|'"'|"0"
             | "x" , hex_digit , hex_digit
             | "u" , hex_digit , hex_digit , hex_digit , hex_digit
             | "u{" , hex_digit , {hex_digit} , "}" ) ;
template     = "`" , { tmpl_part | ("${" , {token} , "}") } , "`" ;
punct        = "(" | ")" | "{" | "}" | "[" | "]" | "," | ";" | ":" | "."
             | "+" | "-" | "*" | "/" | "%" | "**" | "=" | "==" | "===" | "!"
             | "!=" | "!==" | "<" | ">" | "<=" | ">=" | "<<" | ">>" | ">>>"
             | "&" | "|" | "^" | "~" | "&&" | "||" | "?" | "->" | "=>" ;
error        = ? any byte sequence matching no rule above, recorded as Token::Error ? ;

Disambiguation (I1, I2): longest match wins; on a length tie, higher priority then earlier declaration order wins (the #[token("if")] vs. #[regex("[a-z]+")] fixture in §16.4).

8.2 DFA state-transition fragment (illustrative, if/ident sub-automaton)

State on i on f on [a-hj-z] on [0-9_] on other Accept
S0 (start) → S1 → S3 (via [a-z]) → S3 — dead —
S1 (i) → S3 → S2 → S3 → S3 Accept(Ident) Ident
S2 (if) → S3 → S3 → S3 → S3 Accept(If, priority) If (tie-break I2)
S3 (ident tail) → S3 → S3 → S3 → S3 Accept(Ident) Ident

S2 is simultaneously an accepting state for If (via the #[token("if")] rule) and a prefix of a longer identifier (iffy); the DFA does not resolve this at construction — it resolves it at scan time via longest-match rollback (§16.3): the scanner continues from S2 while a longer match is reachable (S3 accepts Ident), and only commits when the byte stream can no longer extend the match.

8.3 Worked example — template-literal mode-stack trace

Input: `hello ${name + "!"} world`.

Step Mode (top of stack) Bytes consumed Emitted
1 Code → push Template ` (open tick, no token — mode transition only)
2 Template hello TmplPart("hello ")
3 Template → push Code (depth_at_entry=0) ${ TmplExprStart
4 Code name Ident
5 Code + Plus (+ surrounding Whitespace trivia)
6 Code "!" StrDouble
7 Code → pop to Template (depth back to 0) } TmplExprEnd
8 Template world TmplPart(" world")
9 Template → pop to Code ` (close tick)

Mode-stack depth returns to 1 at step 9 (I5). The Code mode entered at step 3 carries depth_at_entry = 0 so a nested ${ {a:1} } is handled: the inner {/} raise local depth to 1 before the matching } at depth 0 pops back to Template (§20.2).

8.4 Malformed-input example — unterminated string

Input: let x = "unterminated (no closing quote, EOF reached mid-string).

Scanner behaviour: lex_str_double consumes bytes looking for " or newline; hits EOF first. Emission: Token::Error(UnterminatedString, span=[8,22)) covering the opening quote through EOF (I9: error is a token, not an exception). Recovery: the scanner treats EOF as the resynchronisation point — no further tokens follow; if the malformed string were instead followed by more source (e.g. \n before EOF), the resynchronisation point is that newline (§Failure Modes FM-2).

8.5 Failure-path example — mixed tabs/spaces off-side violation

Input: three lines — if x:, then y = 1 (four leading spaces), then \ty = 2 (one leading tab). Line 3 is indented with one tab where line 2 used four spaces. IndentStack::feed computes line 2's indent as 4 (byte-count policy, ADR-10-adjacent) and pushes level 4. Line 3's leading tab, under the strict no-tab-in-leading-whitespace policy (§19.5), is itself rejected before indent computation: emission is Token::Error(IndentMismatch, span=[18,19)) covering the tab byte, and IndentStack repairs by treating the line as continuing at the last valid level (4) rather than desynchronising every subsequent line (I6, FM-5).

Design principles (§6)

  • P1 — Ground-Truth Duality. The hand-written reference lexer for the seed language is the conformance baseline; the generated lexer must produce an identical token stream (modulo documented trivia-placement differences resolved by the trivia normaliser). Tradeoff: doubles the implementation surface for the seed language. Operational implication: every conformance fixture is authored once and run against both backends. Violating it: the generator silently diverges and nobody notices until an embedder files a bug.
  • P2 — One Trait, Two Backends. The runtime exposes exactly one Lexer trait; the proc-macro and the hand-written module both implement it; backend selection happens in exactly one place (the embedder's feature flag). Tradeoff: the trait must be conservative enough for both implementation styles. Violating it: downstream code branches on backend identity, defeating the swap guarantee.
  • P3 — Spans Are Mandatory. Every token carries Span{start,end} as byte offsets; line/column is a SourceMap service, not a per-token field. Tradeoff: the hot path always pays one increment per byte for position tracking. Violating it: two lexer configurations ("with spans"/"without") that must be independently maintained.
  • P4 — Trivia Is Recoverable By Default. Whitespace, comments, shebangs are trivia tokens with their own spans; concat(token.bytes) == source_bytes (I3) always holds. Tradeoff: every trivia byte is a token object, not a discarded byte. Violating it: no tool downstream can reformat or diff source losslessly.
  • P5 — Modes Are Explicit. Lexer modes are a runtime-owned stack, not a per-backend hack; rule actions call mode_push/mode_pop. Tradeoff: the mode stack is shared state both backends must thread correctly. Violating it: string interpolation, raw strings, and regex/division disambiguation each reinvent their own ad hoc state machine.
  • P6 — Off-Side Is Explicit. IndentStack is a runtime feature, not a seed-language special case; it injects virtual Indent/Dedent tokens. Tradeoff: every embedder pays for the indent-stack type even if their language has no off-side rule (it is simply unused). Violating it: indentation-significant languages each hand-roll a column counter with no shared correctness argument (I6).
  • P7 — Errors Are Tokens, Not Exceptions. A lex error emits Token::Error(kind, span) and lexing continues; there is no exception out of the hot path. Tradeoff: every consumer must handle Error as an ordinary token kind. Violating it: one malformed byte anywhere in a 10 MB file aborts the entire lex.
  • P8 — The Hot Path Does Not Allocate. (TokenKind, Span) is Copy; string/escape unescaping and identifier interning are the parser's job, not the lexer's. Tradeoff: the lexer returns raw byte slices the consumer must re-scan for semantic content. Violating it: I8 fails and the throughput targets in §4/§31 become unreachable.
  • P9 — Incremental Is First-Class. IncrementalLexer is part of the runtime, not a bolt-on; apply_edit is provably minimal under the single-alignment-region assumption. Tradeoff: the runtime types (SourceMap, Span, mode/indent stacks) must be designed for reuse across edits from day one. Violating it: incremental support requires rewriting the runtime later (Key Pitfall, §Phase 10).
  • P10 — One SourceMap Per File, One Arena Per Session. SourceMap is constructed once, shared by parser/diagnostics/IDE; its only allocation (the line table) is lazy, built on first column query. Tradeoff: the first column query in a session pays an O(n) table-build cost. Violating it: every consumer builds its own redundant line table, quadrupling memory for multi-consumer pipelines.
  • P11 — Determinism Is Non-Negotiable. Same (source bytes, rule set, config) → identical token stream, byte-for-byte, across builds/OS/CPU architectures. Tradeoff: forecloses any nondeterministic optimisation (e.g. unordered hash-based tie-breaking). Operational implication: conformance fixtures and fuzz differential tests (§28) are only meaningful under this guarantee. Violating it: a flaky conformance suite that cannot distinguish a real regression from build noise.
  • P12 — Compile-Time Cost Is A Budget, Not Free. DFA generation (NFA build, subset construction, minimisation, codegen) is bounded by explicit state-count and wall-clock caps (§4) because it runs on every cargo build of every embedder. Tradeoff: very large rule sets (>100k states) hit a hard compile_error! rather than a slow but successful build. Violating it: an unbounded generator becomes an invisible tax that degrades every downstream developer's edit-compile-test loop.
