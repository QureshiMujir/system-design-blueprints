Back-of-Envelope Capacity Model

All numbers derive from §4 System Constraints. Assumptions are stated inline; revisit when §4 changes.

Baseline configuration (from §4)

  • num_threads = P = number of physical cores (e.g., P = 32 on a 2-socket Xeon)
  • Deque depth = D = 1024 slots per worker (Chase-Lev initial buffer)
  • Task body size = S = 64 bytes (Task struct: fn pointer + closure captures, cache-aligned)
  • Steal cost = C_steal = ~200 ns (one CAS + cache-line ping; measured on Xeon E5 class)
  • Task execution time = T_task = target ≥ 2000 ns (10× steal cost, from P6)
  • Max in-flight tasks = M = 64 × P (PoolConfig::max_in_flight default)

Step 1 — Live deque memory (per worker)

D slots × S bytes = 1 024 × 64 = 64 KB per worker deque buffer

At P=32 workers: 32 × 64 KB = 2 MB total deque memory. Negligible.

Step 2 — Peak in-flight task memory

M × S = 64 × 32 × 64 B = 131 072 B ≈ 128 KB task-struct memory

Closures captured on the heap add to this. A 1 KB mean closure: 128 KB × 16 = 2 MB. Acceptable.

Step 3 — Steal rate ceiling (no contention)

steal_rate_max = P / C_steal = 32 / 200 ns = 160 M steals/sec

In practice, steals are rare when task time >> steal cost (target T_task = 2000 ns):

steal_fraction ≈ C_steal / T_task = 200 / 2000 = 10%

At 10% steal fraction and 32 workers: 32 × (1/2 µs) × 0.10 = 1.6 M steals/sec. Well under the CAS bandwidth of a modern cache hierarchy.

Step 4 — Minimum task size for linear speedup

From P-B (Blumofe-Leiserson): E[time] ≤ T1/P + O(T∞). For P-fold speedup, T1/P must dominate T∞:

T∞ < T1/P  →  parallelism = T1/T∞ > P

Granularity constraint (from MM3): each leaf task must run ≥ 10× the steal cost:

T_task_min = 10 × C_steal = 10 × 200 ns = 2 µs

A task doing < 2 µs of work on this configuration will have steal overhead > 10% of task cost.

Step 5 — Memory bandwidth under parallel reduce

Target: 256 MB array, 8-byte doubles, one reduce pass.

BW_required = 256 MB / T_sequential
T_sequential = 256 MB / (8 B/elem × 500 M ops/s) ≈ 64 ms
At P=32: T_parallel ≈ 64 ms / 32 = 2 ms

At 2 ms and 256 MB touched: bandwidth = 256 MB / 2 ms = 128 GB/s. Dual-socket Xeon peak ≈ 120 GB/s. This is bandwidth-bound at P=32; adding more cores does not help. Mitigation: NUMA-local allocation (Phase 9) halves cross-socket traffic.

Step 6 — DAG cycle-check cost at submission

pcs-graph rejects cyclic DAGs at submit time with DFS (O(V + E)):

V = 100 000 nodes, E = 150 000 edges (sparse DAG)
DFS at 10 ns/edge visit = 150 000 × 10 ns = 1.5 ms

For a graph submitted once and executed in hours, 1.5 ms submit latency is acceptable. For graphs resubmitted at > 1 Hz with V > 100 k, consider incremental cycle detection or skip for trusted graphs.

Step 7 — Trace ring buffer overhead and capacity

Default ring size = 1 M spans × 40 bytes = 40 MB. At 10 M tasks/sec, ring fills in 100 ms and begins dropping. For production profiling, reduce to 100 k spans and sample at 1%.

Step 8 — Compensation thread bound

From ADR-27: K = 4× compensation factor. Maximum compensation threads = 4 × P = 128 at P=32. OS thread creation = ~10 µs each; burst cost to inject K compensation threads = 128 × 10 µs = 1.28 ms. Acceptable for blocking outliers; unacceptable if all tasks block simultaneously (design error, not scheduler fault).
