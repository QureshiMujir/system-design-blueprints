⬜ Phase 1 — Thread Pool + Worker Threads + Topology

Objectives
  • Spawn exactly PoolConfig.num_threads OS threads; pin each to a CpuSet derived from hardware topology.
  • Detect cores, physical packages, NUMA nodes via /sys/devices/system/cpu (Linux) or libc::sysconf / mach_vm (macOS).
  • Establish thread-local CURRENT_WORKER: Option<*mut Worker> accessible without synchronization on the hot path.
  • Deliver clean startup (all threads ready before ThreadPool::new returns) and clean shutdown (all threads joined, no dangling handles).
  • Main thread may participate as worker-0 when PoolConfig.main_participates = true.
  • Introduce PoolConfig, ThreadPool, Worker (skeleton), NumaNode, CpuSet, Injector<Task> in pcs-pool and pcs-worker.
Deliverable
  • ThreadPool::new(PoolConfig) compiles and spawns N pinned threads.
  • ThreadPool::shutdown() / Drop joins all handles; returns cleanly.
  • pcs-pool exports: ThreadPool, PoolConfig, Worker (opaque), topology::detect() -> Vec<NumaNode>.
  • CURRENT_WORKER readable from any worker thread; None on external threads.
  • Integration test: spawn pool, verify thread count, verify affinity via /proc/self/status Cpus_allowed.
Acceptance
Criterion Target
Startup latency (N=16) < 20 ms wall time
Thread count Exactly PoolConfig.num_threads threads alive during pool lifetime
Affinity Each thread's sched_getaffinity bitmask matches its assigned CpuSet
Clean shutdown All threads joined, no zombie handles, Drop returns in < 50 ms
CURRENT_WORKER Returns Some on every worker thread; None on main thread (when main_participates = false)
Topology test detect() returns num_threads distinct CPU ids on CI (mocked if bare metal unavailable)

Pitfalls
  • Stealer distribution before barrier release: if workers begin stealing before all Stealer handles are distributed, a worker has a partial stealers array. Fix: distribute stealers before releasing startup barrier.
  • Affinity fallback on macOS: sched_setaffinity absent; silently skip or use pthread_setaffinity_np where available; topology detection must not panic on unsupported syscalls.
  • Stack size mismatch: default Rust thread stack (2 MB) insufficient for deep recursive fork-join. PoolConfig.stack_size must be passed to std::thread::Builder::stack_size.
  • Thread-local raw pointer lifetime: WORKER: Cell<*mut Worker> is valid only during thread body; accessing after thread exit is UB. Clear on thread exit before joining.
  • NUMA node count = 0: some VMs expose no NUMA topology; treat as single node, not a panic.
  • Shutdown while tasks are inflight (Phase 1 skeleton): workers must drain local deques before exiting; stubs must not silently discard tasks. Assert empty in test.

⬜ Phase 2 — Chase-Lev Work-Stealing Deque

Objectives
  • Implement ChaseLevDeque<T> in pcs-deque: lock-free circular buffer; owner push/pop wait-free; thief steal via CAS on top.
  • Implement Stealer<T>: cloneable handle; exposes only steal() -> Steal<T>.
  • Correct C11/Rust memory orderings per Le, Pop, Cohen, Zappa Nardelli (PPoPP 2013) for weak memory models.
  • Monotonic top counter defeats ABA; growable buffer via buffer swap.
  • Replace Phase 1's VecDeque placeholder in Worker with ChaseLevDeque<Task>.
Deliverable
  • pcs-deque compiles with #![forbid(unsafe_code)] disabled (unsafe needed), Miri-clean single-threaded, loom-verified concurrent paths.
  • Stealer<Task> distributed to all workers at pool startup (Phase 1 integration complete).
  • pop() returns None on empty deque; push + pop round-trip is correct LIFO under single-threaded use.
  • Multi-threaded steal-under-contention test passes (≥ 1000 steal races, no item lost or doubled).

loom model check loom::sync::atomic sweep covers push/steal race; no assertion failures

Pitfalls
  • Wrong memory ordering on pop: reading top after decrementing bottom without SeqCst allows a thief to simultaneously succeed the CAS; results in double execution. Must follow Lê et al Table 1 exactly.
  • Freeing buffer while thief holds pointer: thief loads buffer pointer, then owner grows and frees old buffer before thief reads data[top & mask]. Fix: deferred free via prev chain; only free when top has passed the old buffer's last index.
  • Capacity not power-of-two: mask = cap - 1 index trick is undefined for non-power-of-two sizes; validate in Buffer::new.
  • Steal::Retry infinite loop in test: callers must bound retry count; a test that spins forever on Retry will hang CI. Use a retry limit + thread::yield_now().
  • usize overflow of bottom/top: on 64-bit targets, usize::MAX wrap is astronomically unlikely but must be documented; assert in debug builds that bottom - top < isize::MAX.
  • Concurrent grow not possible: only the owner may grow; document that push panics in debug if called concurrently (but this is architecturally enforced by single-owner contract).

⬜ Phase 3 — Task Model + Spawn + Steal Loop

Objectives
  • Define Task, TaskId, TaskState in pcs-core; TaskState transitions via AtomicTaskState.
  • Implement spawn on ThreadPool and Scope (Scope is a stub here; completed in Phase 4): push Task to current worker's local deque; if called from external thread, push to Injector.
  • Implement the worker run loop in pcs-worker: pop-local (LIFO) → steal-victim (round-robin + RNG) → park; unpark on new work; exponential backoff before parking.
  • Integrate ChaseLevDeque<Task> (Phase 2) and ThreadPool (Phase 1) into a functioning end-to-end task execution path.
Deliverable
  • ThreadPool::submit(|| ...) accepted from the main thread; task executes on a worker; result observable via shared AtomicUsize or Future stub.
  • Worker loop runs indefinitely until shutdown; does not busy-spin when idle (parks correctly).
  • Steal path exercised by submitting more tasks than one worker can consume alone.
  • TaskState transitions Ready → Running → Done observable in integration test.

Pitfalls
  • Spin-before-park CPU waste: if MAX_SPIN is too high (e.g., 1M), idle workers consume a full core. Start conservatively at 64–256 spins; tune with idle-CPU test.
  • Injector drain ordering: workers must check Injector after exhausting local deque but before sleeping; if they check only on wake, injector-submitted tasks are delayed until a steal wakes a worker.
  • Unpark storm: submitting N tasks from an external thread calls unpark() N times; if all N workers wake simultaneously and find only one item, N-1 re-park immediately — this is correct but causes unnecessary wakeups. Mitigate by unparking only one worker per submission.
  • catch_unwind on non-unwind panics: panic = "abort" (common in embedded/WASM profiles) makes catch_unwind useless; document that panic = "unwind" is required in Cargo.toml for the pool crate.
  • Box<dyn FnOnce()> size: each Task heap-allocates the closure; many tiny closures → allocator pressure. Future optimization (Phase 6+): task arena or stack-allocated small-task optimization.
  • TaskId counter wrap: AtomicU64::fetch_add wraps at u64::MAX; 0 is sentinel; add debug assertion in TaskId::new that result != 0 after wrap.

⬜ Phase 5 — Task graph / DAG

  • On each task Done, atomically decrement all successor pending_deps; node reaching 0 becomes Ready and is pushed to a worker deque (locality: prefer the completing task's worker).
  • Reject cycles at graph-build time (topological sort or DFS mark).

⬜ Phase 7 — Scheduling Policy + Locality

⬜ Phase 9 — NUMA-Aware Scheduling

Objectives

Deliverable

⬜ Phase 10 — Priority + Fairness + Backpressure

Objectives
  • Add optional priority lanes to pcs-pool and pcs-sched without breaking the common single-priority path.
  • Implement a bounded global Injector<Task> for external submissions; apply backpressure (block caller or return Err) when in-flight count reaches a configurable ceiling.
  • Guarantee no worker starves: any lower-priority task must make progress within a bounded number of high-priority task completions (fairness_quanta).
  • Expose submit() / try_submit() / submit_batch() / submit_from_task() public APIs with explicit backpressure semantics.
  • Constraints: priority logic adds zero synchronization to the hot steal path when lanes == 1; fairness must be verified by automated test, not just by design intent; I6 must hold (no oversubscription from priority lanes).
  • Phase scope: pcs-pool, pcs-sched, pcs-metrics; no changes to pcs-deque, pcs-worker internals, or pcs-graph.
  • Phase dependencies: Phase 1 (thread pool), Phase 2 (deque), Phase 3 (task model + spawn) must be complete.

Priority lane invariant (additional): a task submitted to lane N executes before a task in lane M only if N > M, unless FairnessGuard forces a lower-priority task through — no silent priority promotion/demotion. spawn() (fork-join, pcs-parallel) always uses the highest-priority lane to preserve work-first semantics (Phase 7); only external submit() uses the caller-specified lane.

Deliverable

  • Backpressure test: producer blocks then resumes correctly when slots free; try_submit returns Err with zero parking.
  • Fairness test: low-priority tasks complete within 2 * fairness_quanta high-priority completions.
  • pcs-metrics exports lane_depth{lane=N}, starvation_idle_ns{lane=N}, tasks_run_total{lane=N} gauges.
  • TaskId returned from all submit variants; traceable in pcs-trace spans.
  • spawn_with_priority API available in pcs-parallel for user-controlled priority on fork-join spawns.
  • PoolConfig::priority_lanes validated at construction: 1 ≤ lanes ≤ 8; returns Err(ConfigError::InvalidLanes) otherwise.
  • All single-priority pools (lanes = 1) pass existing Phase 1–9 benchmarks without regression; criterion confirms.
  • Starvation detector background task initializes with pool; stops cleanly at pool shutdown; no orphaned metric threads.

⬜ Phase 11 — Cancellation + Panic Propagation

Objectives
  • Implement structured cancellation: a CancellationToken that long-running tasks poll; cancellation propagates hierarchically through a Scope tree. Implement panic propagation: any panicking child task poisons its owning Scope, re-raising at the scope.wait()/join() boundary with the original payload.
  • Structured shutdown: ThreadPool::shutdown(mode) drains in-flight tasks (DrainThenStop) or aborts them cleanly (AbortInFlight); no detached tasks remain after shutdown, and (I10 extended) every worker thread — including Phase 12 compensation threads — is joined before in_flight == 0 is asserted. Constraints: CancellationToken::is_cancelled() is zero-cost when not cancelled (single Relaxed load); panic propagation must not silently swallow payloads; invariants I7, I8, I10 must hold. A Cancelled task contributes to scope completion exactly as a Done task does — the scope does not re-raise on cancellation alone; a task that begins executing after cancel() transitions to Cancelled immediately (pre-check), while an already-executing task must check is_cancelled() at yield points to stop cooperatively.
  • Phase scope: pcs-sync (CancellationToken, PanicCell, Latch), pcs-pool (shutdown), pcs-worker (catch_unwind), pcs-parallel (Scope lifetime safety). Dependencies: Phase 4 (fork-join Scope), Phase 3 (TaskState), Phase 5 (DAG) must be complete.
Deliverable
  • CancellationToken::cancel() causes all tasks sharing the token to skip execution and reach Cancelled state (verified by test_cancel_skips_tasks); a panicking child task causes scope.wait() to re-raise the panic on the calling thread with the original payload type. ThreadPool::shutdown(DrainThenStop) joins all threads with in_flight == 0 post-shutdown (verified by assertion); shutdown(AbortInFlight) exits promptly (≤ one max-task-duration) with cancelled tasks counted in tasks_cancelled_total; shutdown_with_timeout(mode, duration) auto-escalates DrainThenStop → AbortInFlight on timeout.
  • Scope<'s> lifetime prevents escaped closures at compile time (verified by compile-fail test); CancellationToken::child() and Scope::with_cancellation(token) are available in the pcs-sync public API; all conformance fixtures pass, all loom model checks for I7, I8, I10 pass without violations, and the pcs-cli benchmark parallel-bfs exercises task cancellation at scale, verifying no hung threads after AbortInFlight.

⬜ Phase 12 — Blocking-Task Handling

Objectives
  • Detect when a worker is about to perform a blocking operation (explicit block_in_place(f) API), inject a compensation thread to keep the pool at num_threads active non-blocked workers, bound compensation threads via max_compensation: usize in PoolConfig to prevent unbounded OS thread creation, and prevent deadlock when all num_threads workers are blocked inside join / scope::wait waiting on tasks that have nowhere to run by implementing Latch::wait_with_work that executes tasks while waiting.
  • Constraints: compensation threads are transient — they exit when the blocking worker resumes; total OS threads ≤ num_threads + max_compensation at all times (I6 extended); P4 and P7 must hold. Phase scope: pcs-pool (block_in_place, CompensationPool, shutdown interaction), pcs-sync (Latch::wait_with_work), pcs-worker (WorkerState::Blocking, yield_to_scheduler); dependencies: Phase 1 (thread pool + topology), Phase 4 (join/Scope + Latch), Phase 9 (NUMA domains for affinity) must be complete.

Core invariant (I6 extended): non-blocked active workers ≤ num_threads at all times; compensation threads add up to max_compensation more, each active only while a permanent worker is blocked (P7: wait_with_work keeps waiting workers productive, so blocking callers don't starve other tasks). Full deadlock-prevention mechanism in §12.2 — Latch::wait_with_work keeps waiting workers active as thieves, with block_in_place compensation as fallback capacity; deadlock is only theoretically possible if both are exhausted and the caller's task graph has a dependency cycle (user error). wait_with_work must never be invoked from within a block_in_place context (would run tasks on a "blocked" worker, violating I1) — guarded by the IN_BLOCK_IN_PLACE flag.

  • Latch::wait_with_work is used in all join / Scope::wait paths, with no Latch::wait_os calls in fork-join critical paths; active_compensation_threads gauge exported in pcs-metrics; deadlock sentinel emits ERROR DeadlockSuspected in the constructed deadlock scenario within 5 s; is_worker_thread() returns true inside the pool and false outside, tested in both contexts; pcs-cli benchmark parallel-mergesort uses join recursively to completion on max_comp=0, demonstrating wait_with_work correctness at scale; block_in_place overhead benchmark measures entry/exit overhead (excluding f()) at ≤ 100 ns on the max_comp=0 fast path and ≤ 200 ns on the spawn path.
