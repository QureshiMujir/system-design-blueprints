Decisions (§9) · 22 ADRs

ADR-01

Implementation language

Chosen

Rust

Rejected

Go, Java, Python, C++

When the rejected choice is right

Go/Java win for large existing GC-based codebases; Python wins for a one-off prototype with no state-safety need

Why: Exhaustive enum matching (P8), no GC jitter (P10)

ADR-02

Network layer

Chosen

In-process simulated bus (tpc-sim)

Rejected

Real TCP sockets

When the rejected choice is right

Real sockets win once PhaseDeferred("§12") is un-deferred for multi-host deployment

Why: Determinism (P10), no OS scheduler noise

ADR-03

Abort optimization

Chosen

Presumed abort (Mohan et al. 1986)

Rejected

Plain 2PC (log both outcomes)

When the rejected choice is right

Plain 2PC wins in workloads where commit vastly outnumbers abort and log-write symmetry simplifies audit tooling

Why: Fewer log writes on the (assumed) common abort path

ADR-04

Commit optimization

Chosen

Deferred; presumed abort only in v1

Rejected

Presumed commit (also Mohan et al. 1986)

When the rejected choice is right

Presumed commit wins in workloads where commit vastly dominates abort (inverse of ADR-03's assumption)

Why: Scope control — one optimization is enough to demonstrate the technique

ADR-05

Non-blocking protocol variant

Chosen

Skeen 3PC (1981)

Rejected

Keidar/Dolev-style quorum 3PC variants

When the rejected choice is right

Quorum variants win when partition tolerance (not just fail-stop non-blocking) is the actual requirement

Why: Matches the canonical textbook description this project teaches from

ADR-06

Fault model

Chosen

Fail-stop + omission (crash, drop, delay, duplicate, reorder)

Rejected

Byzantine (arbitrary/malicious)

When the rejected choice is right

Byzantine model wins in adversarial multi-org deployments (§34)

Why: Matches Gray 1978 / Skeen 1981's proof assumptions

ADR-07

Timing model

Chosen

Seeded logical clock, tick-based

Rejected

Wall-clock (SystemTime) timers

When the rejected choice is right

Wall-clock wins once real network latency variance must be measured (post PhaseDeferred("§12"))

Why: Reproducible fixtures (P10)

ADR-08

Log storage

Chosen

In-memory Vec<LogRecord> with force() barrier

Rejected

Real fsync'd file

When the rejected choice is right

Real file wins once PhaseDeferred("§13") (durability across process restart) is un-deferred

ADR-09

Write ordering

Chosen

Log-before-send at both coordinator and participant (P1)

Rejected

Send-before-log ordering

When the rejected choice is right

Send-before-log is only defensible in a deployment that accepts occasional heuristic decisions in exchange for lower per-hop latency, e.g. a best-effort analytics pipeline with no atomicity SLO

Why: Required by P1/I4/I5

ADR-10

Cohort membership

Chosen

Fixed at begin(), immutable (I12)

Rejected

When the rejected choice is right

Dynamic reconfiguration wins in long-lived sagas (§34) where membership legitimately changes over the transaction's life

Why: Simplicity; matches classical 2PC/3PC literature

Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Paxos Commit (Replicated Coordinator)

Participant --Prepared--> [Acceptor1] [Acceptor2] [Acceptor3] (2F+1 acceptors)
                                \_________ Paxos instance per participant vote _________/
                                              |
                                         Learners -> Decision

Wins when: the coordinator itself, not just a single participant, must survive crashes without blocking the transaction (multi-datacenter deployments). Real system: Google Spanner's 2PC-over-Paxos-groups design (Corbett et al. 2012, §31). Rejected here: adds a full consensus implementation per decision — out of scope for a from-scratch teaching artifact whose lesson is the phase-count tradeoff (2PC vs. 3PC), not consensus implementation (PhaseDeferred("§20"), ADR-19).

Sagas (Compensating Transactions)

Step1 --> Step2 --> Step3 --> ... --> StepN   (forward path, no global lock)
  |         |          |                |
  v         v          v                v
Comp1 <-- Comp2 <-- Comp3 <-- ... <-- CompN   (compensation path on failure)

Wins when: transactions are long-lived and span services that cannot afford to hold locks/resources for the duration of a 2PC/3PC round (Garcia-Molina & Salem 1987). Real system: Temporal.io's saga-orchestration pattern for long-running distributed workflows. Rejected here: sagas trade atomicity for availability by design (compensations are not true rollback) — this project's entire purpose is studying atomic commit, so adopting a non- atomic model would erase the thing under study.

Percolator-Style Decentralized 2PC (Lock Table in Shared Storage)

Client A --prewrite(lock,write cols)--> [Shared Storage: Bigtable/TiKV]
Client B --reads lock col, resumes if A stalled-------------^

Wins when: horizontal scale across many concurrent coordinators matters more than a single dedicated coordinator's simplicity (Peng & Dabek 2010). Real system: TiKV/TiDB (§5 R4). Rejected here: requires a strongly-consistent shared storage substrate to host the lock table — this project deliberately has no storage layer beneath its own log (ADR-08), so there is nothing to put the lock table in.

Byzantine Commit (PBFT-Style)

Participant --request--> [Primary] --pre-prepare--> [Backup1..3f]
                              |--prepare (2f+1 quorum)-->|
                              |--commit  (2f+1 quorum)-->| --> reply

Wins when: participants may be malicious or arbitrarily faulty, not merely crash-stop (Castro & Liskov 1999) — adversarial multi-organization deployments (e.g., permissioned blockchains). Real system: Hyperledger Fabric's ordering service uses BFT-family consensus. Rejected here: this project's entire proof structure (§7's invariants, every phase's fixtures) assumes fail-stop/omission faults (I10, ADR-06); adopting Byzantine tolerance would require re-deriving every safety argument from scratch — explicitly deferred (PhaseDeferred("§34")).
