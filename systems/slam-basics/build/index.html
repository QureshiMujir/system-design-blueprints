⬜ Phase 0 — Workspace Skeleton + Governance

Objectives
  • Cargo workspace with the 13 crates (§1.6), CI matrix, governance docs, deterministic-build gate. No SLAM logic yet.
Deliverable
  • cargo build + cargo test green on host; CI passes on empty stubs.
Acceptance
  • All 13 crates compile. Clippy clean. Docs present and cross-linked. slamctl --version stamps git hash. ADR 1–30 stub files exist.
Fixtures
  • conformance/synthetic/{loop3,corridor,grid_world}.spec declared (no golden yet). conformance/g2o/{manhattan,sphere2500}.g2o placed. datasets/README.md lists dataset checksums.
Pitfalls
  • Dependency cycle between slam-graph and slam-solver. Root: bidirectional types. Detect: cargo build. Recovery: keep Factor/Values in slam-graph, solve logic in slam-solver (one-directional).
  • Float-contraction nondeterminism: default codegen may emit FMA → replay/solve hash differs across CPUs. Detect: determinism CI. Recovery: pin target-feature flags, fixed reduction order.
  • Workspace feature unification pulling a heavy dep into the core. Detect: cargo tree. Recovery: default-features=false.

⬜ Phase 1 — Lie-Group Math SE(2)/SE(3) (Exp/Log, Jacobians, ⊞/⊟)

Objectives
  • slam-lie: SO(2)/SO(3), SE(2)/SE(3) with Exp/Log, hat/vee, adjoint, compose/inverse, right ⊞/⊟, right/left Jacobians. Conventions LOCKED (§8.1). Zero-alloc fixed-size, deterministic.
Deliverable
  • Lie-group crate: SE(2)/SE(3) algebra validated against reference (Sophus-style) values; finite-diff Jacobians pass.
Acceptance
  • Log(Exp(ξ))=ξ for ‖ξ‖<π (1e-10 f64). X∘X⁻¹=I (1e-12). SO(3) R orthonormal, det=+1; quaternion |q|=1 after 10⁶ random ⊞ (<1e-9 deviation, I1). adjoint satisfies Exp(Ad_X ξ)=X Exp(ξ) X⁻¹ (1e-9). All Jacobian finite-diff errors <1e-5. No heap alloc.
Fixtures
  • tests/exp_log.rs: near-zero and near-π angles (small-angle branch). adjoint.rs: adjoint identity. boxplus.rs: (X⊞ξ)⊟X = ξ. jac_fd.rs: relative-pose residual Jacobian vs finite diff. Degenerate: ξ=0 (identity), θ=π (sign canonicalization).
Pitfalls
  • Right vs left perturbation drift across modules → inverted/inconsistent Jacobians. Manifestation: solver fails to converge or converges to wrong pose. Detect: boxplus round-trip + differential vs reference. Recovery: single-sourced convention (ADR 8), property test everywhere.
  • Small-angle singularity in V(ϕ)⁻¹/Jr at θ→0. Detect: near-zero fixture. Recovery: Taylor branch.
  • Quaternion double cover (q vs −q) → discontinuous Log. Detect: Log continuity test. Recovery: canonicalize w≥0.
  • SE(2) V(ϕ) form error (off-diagonal sign) → translation error after rotation. Detect: Exp/Log round-trip on pure-rotation+translation. Recovery: re-derive from §8.1.

⬜ Phase 2 — Sensor Model + 2D Scan Representation + Occupancy-Grid Mapping (Known Poses)

Objectives
  • slam-sensor: LaserScan, beam endpoints, beam/likelihood-field model, inverse sensor model. slam-map: occupancy grid (log-odds), Bresenham ray casting, integrate_scan. Build a correct map given known poses (decouples mapping from localization).
Deliverable
  • Given a synthetic trajectory + scans, produce a correct occupancy grid; render to PNG via gridviz.
Acceptance
  • On a synthetic world (known walls, known poses), reconstructed occupied cells match ground-truth walls with ≥95% IoU at 5 cm resolution. Free space correctly cleared along rays. Log-odds clamped (I12). Map round-trips through serialization bit-identically. Ray cast is integer-exact (no gaps/double-counts).
Fixtures
  • tests/occupancy.rs: single beam into empty grid → one occupied + free trail; raycast.rs: Bresenham against analytic line (no missing cells). conformance/synthetic/grid_world.spec: known map + known trajectory → golden grid (IoU threshold). Degenerate: beam shorter than one cell; max-range beam (free only, no hit); beam outside grid (clipped).
Pitfalls
  • Off-by-one in world_to_cell (floor vs round, origin convention) → map shifted by a cell. Manifestation: walls double-thick or offset. Detect: single-beam test. Recovery: documented floor + origin convention.
  • Endpoint marked occupied at max range → phantom walls at sensor horizon. Detect: max-range fixture. Recovery: skip occupied update when range≈range_max.
  • Log-odds not clamped → cells saturate, map can't reflect change. Detect: clamp test (I12). Recovery: clamp every update.
  • Inverse-model double-update when consecutive beams hit the same cell in one scan. Detect: cell-update-count test. Recovery: per-scan update policy (or accept; document).
  • Bresenham gaps on steep lines → uncleared free cells. Detect: analytic-line fixture. Recovery: correct integer DDA.

⬜ Phase 3 — Scan Matching (ICP point-to-point / point-to-line, Correlative, NDT)

Objectives
  • slam-match: three scan matchers behind ScanMatcher, each returning relative SE(2) + information matrix (Principle 10). ICP (point-to-point + point-to-line / PLICP), correlative (multi-resolution likelihood-field search), NDT (cell Gaussians + Newton). KD-tree for correspondences.
Deliverable
  • Three matchers producing relative-pose estimates + information on synthetic and real scan pairs; slamctl can match two scans and report transform + info.
Acceptance
  • On synthetic scan pairs with known transform (≤0.5 m, ≤20° apart): ICP recovers translation within 2 cm, rotation within 0.5° (clean data). Correlative recovers correct cell within window even from a poor init (robust to 0.3 m / 15° initial error). NDT matches ICP accuracy on structured scenes. Information matrix is SPD and reflects geometry (under-constrained directions → low information, e.g. corridor longitudinal axis). Matcher converges within max_iters or reports converged=false.
Fixtures
  • tests/icp.rs: known-transform recovery; correlative.rs: poor-init recovery; ndt.rs: structured-scene accuracy; info.rs: corridor scan → anisotropic information (low along corridor). Degenerate: identical scans (zero transform, high info), featureless scan (low info, slides), 50% overlap (partial), rotation-only.
Pitfalls
  • ICP local minimum from poor init → wrong transform that "looks" converged. Manifestation: jump in trajectory. Detect: residual + score sanity; correlative as init. Recovery: multi-start / correlative-then-ICP; gate by residual.
  • Wrong correspondences (associate across a gap) → biased pose. Detect: correspondence distance gate. Recovery: reject outlier correspondences (trimmed ICP).
  • Information from too-few correspondences → over-confident edge. Detect: correspondence count vs DOF. Recovery: floor information; require minimum overlap.
  • Corridor / aperture degeneracy → matcher slides along the unconstrained axis. Manifestation: longitudinal drift. Detect: information eigenvalue ratio. Recovery: report anisotropic info; back-end weights accordingly (I11).
  • NDT cell discretization artifacts (scan near cell boundary) → score discontinuity. Detect: boundary fixture. Recovery: cell overlap / smoothing.

⬜ Phase 4 — Odometry + Motion Models + Dead Reckoning + Noise Propagation

Objectives
  • slam-odom: odometry model (rot1-trans-rot2) and velocity model (v, ω) with calibrated noise; predicted mean + covariance (for EKF) and sampling (for FastSLAM); dead-reckoning baseline; noise propagation through SE(2).
Deliverable
  • Motion models producing prediction + covariance + samples; dead-reckoning trajectory on a dataset with characterized drift.
Acceptance
  • Dead reckoning on a synthetic loop accumulates drift consistent with injected noise (within 10% of Monte-Carlo expectation). predict covariance matches sampled covariance over 10⁴ samples (within 5%). Motion + noise Jacobians finite-diff <1e-5. Sampling is seeded → deterministic. Straight-line branch (ω→0) is continuous with the arc model.
Fixtures
  • tests/odometry.rs: predicted vs sampled covariance; velocity.rs: arc vs straight-line continuity at ω→0. Fixtures: synthetic/corridor.spec dead-reckon drift. Degenerate: zero motion (covariance unchanged), pure rotation (translation noise coupling), pure translation.
Pitfalls
  • Covariance composition on the wrong side (left vs right Jacobian) → mis-scaled uncertainty. Manifestation: EKF over/under-confident, NEES off. Detect: predict-vs-sample covariance test. Recovery: right Jacobian of SE(2) (§8.1), consistent with ADR 8.
  • δ_rot1 ambiguity when δ_trans≈0 (pure rotation → undefined bearing). Detect: pure-rotation fixture. Recovery: guard small δ_trans, attribute rotation to δ_rot1+δ_rot2 split.
  • Velocity-model singularity at ω=0 (division by ω). Detect: continuity test. Recovery: Taylor/straight-line branch.
  • Unseeded sampling breaks determinism. Detect: replay-hash CI. Recovery: explicit RNG seed (I5).

⬜ Phase 5 — EKF-SLAM (Landmark, Augmentation, Predict/Update, Mahalanobis Data Association)

Objectives
  • slam-ekf: full EKF-SLAM — single Gaussian over robot pose + landmark map; state augmentation on first observation; predict via motion Jacobian; range-bearing update; Mahalanobis nearest-neighbour data association with χ² gating (I10). Establish the filter back-end + consistency monitoring.
Deliverable
  • EKF-SLAM running on a synthetic landmark world (and a small real dataset) producing pose + landmark map with covariances; examples/ekf_slam_landmarks.rs.
Acceptance
  • On synthetic landmark world (known map, range-bearing obs): final landmark RMSE < 0.1 m, pose ATE < 0.2 m after loop. NEES within χ²(3) 95% bounds over 50 Monte-Carlo runs (consistent filter, I4). Covariance SPD throughout (I2). Association false-match rate < 1% at 0.99 gate. Augmentation cross-covariance correct (differential vs batch). Bearing wrap handled (no ±π jumps).
Fixtures
  • tests/predict.rs: covariance growth; update.rs: single-landmark update vs hand-computed; assoc.rs: gated association accept/reject rates; consistency.rs: 50-run NEES. Fixtures: synthetic/grid_world.spec (landmarks). Degenerate: two landmarks within gate (defer), no observations (predict-only growth), first observation of every landmark (all augment).
Pitfalls
  • Wrong augmentation cross-covariance → landmarks uncorrelated with pose → over-confident, NEES collapse. Manifestation: optimistic map then divergence. Detect: NEES; differential vs batch init. Recovery: correct inverse-measurement Jacobian for the cross-covariance block.
  • Data-association error (associate to wrong landmark) → map corruption, slow divergence. Manifestation: landmarks drift/merge. Detect: NEES + association log. Recovery: tighter gate; conservative new-landmark threshold (Principle 5).
  • Non-Joseph update drifts Σ non-PD. Detect: SPD probe (I2). Recovery: Joseph + symmetrize.
  • O(N²) covariance cost ignored → real-time miss at scale. Detect: timing vs landmark count. Recovery: document wall; sparse-information variants / switch to graph back-end (Scalability Analysis).
  • Bearing innovation not wrapped → spurious huge innovation at ±π → rejected valid obs. Detect: heading-crossing fixture. Recovery: wrap to (−π,π].

⬜ Phase 6 — FastSLAM / Rao-Blackwellized Particle Filter (Proposal, Weights, Resampling, Per-Particle Grid)

Objectives
  • slam-pf: grid-based FastSLAM (RBPF) — particles carrying trajectory + per-particle occupancy grid; proposal from improved motion model (scan-match refined, GMapping-style); importance weights from the measurement likelihood; adaptive resampling on effective sample size (I14). Landmark-FastSLAM variant (per-particle landmark EKFs) as an alternative.
Deliverable
  • Grid FastSLAM producing a consistent map + trajectory on a synthetic scan stream and a small real dataset; examples/fastslam_grid.rs; deterministic given seed.
Acceptance
  • On a synthetic loop, the best-particle map matches ground truth (≥90% IoU) and trajectory ATE < 0.3 m after loop, with N≥50 particles. N_eff tracked; resampling occurs and recovers diversity. Deterministic: identical map/trajectory across runs given seed (I5). Improved proposal reduces required particles vs raw motion model by ≥2× for the same accuracy. Weights normalized (|Σw−1|<1e-9).
Fixtures
  • tests/proposal.rs: improved vs raw proposal particle efficiency; resample.rs: systematic resampling preserves Σw and reduces variance; neff.rs: N_eff computed correctly. Fixtures: synthetic/loop3.spec, corridor.spec. Degenerate: all-equal weights (no resample), single dominant particle (depletion → trigger), featureless region (proposal falls back to motion).
Pitfalls
  • Particle depletion (weight collapses to one particle) → map locked, can't recover from error. Manifestation: N_eff→1, no diversity. Detect: N_eff telemetry (I14). Recovery: improved proposal, adaptive resampling, more particles; never resample every step (destroys diversity).
  • Resampling too often → loss of trajectory diversity (sample impoverishment). Detect: trajectory variance collapse. Recovery: resample only on low N_eff.
  • Per-particle grid memory blowup (N grids × extent). Manifestation: OOM at scale. Detect: map_bytes × N. Recovery: copy-on-write / shared ancestry grids; cap N × extent (Scalability Analysis).
  • Weight from wrong sensor model (mismatched p_hit σ) → mis-ranked particles. Detect: weight distribution vs expected. Recovery: calibrate beam model.
  • Non-deterministic resampling (unseeded / unstable sort) → unreproducible. Detect: replay hash. Recovery: seeded systematic resampling, stable tie-break.

⬜ Phase 7 — Factor Graph Representation (Variables, Factors, Residuals, Whitening)

Objectives
  • slam-graph: the graph back-end data model — Variable (Pose2/Pose3/Point2/Point3 on manifolds), Factor trait (residual + on-manifold Jacobians + information), whitening by Ω^{1/2}, Values (current estimate), .g2o import/export. The structure feeding the solver.
Deliverable
  • Factor graph that loads a .g2o file, evaluates total cost + residuals, and exposes the sparse structure (variable↔factor incidence); examples/pose_graph_g2o.rs reports initial cost.
Acceptance
  • .g2o round-trip (read→write→read) is byte-stable (modulo float formatting tolerance). Total cost on a known graph matches a hand/g2o-computed value (1e-6). Every factor's analytic Jacobian matches finite diff <1e-5. Whitening: r̃ᵀr̃ = rᵀΩr (1e-9). Information matrix from .g2o upper-triangular is reconstructed SPD. Bearing residuals wrapped.
Fixtures
  • tests/graph.rs: cost evaluation on loop3; factors_fd.rs: per-factor Jacobian finite-diff; g2o_io.rs: round-trip on manhattan.g2o. Degenerate: graph with no prior (flag gauge-unanchored, I3), duplicate edge, self-loop edge (reject), .g2o with malformed line (parse error, not panic).
Pitfalls
  • Information vs covariance confusion (g2o stores information; using it as covariance squares the weight). Manifestation: wildly over/under-weighted edges. Detect: cost vs reference. Recovery: documented adapter; .g2o = information.
  • Jacobian w.r.t the wrong variable's tangent (left vs right, or i/j swapped). Manifestation: solver diverges/oscillates. Detect: finite-diff per factor (mandatory). Recovery: derive via adjoint (§8.1), test.
  • Whitening with Ω not SPD → Cholesky fails. Detect: SPD probe. Recovery: validate Ω on factor construction.
  • Unwrapped bearing/heading residual → discontinuity at ±π. Detect: heading-crossing factor test. Recovery: wrap.
  • .g2o parser trust (huge indices, NaN info). Detect: fuzz g2o_parse. Recovery: bounds + NaN checks, reject.

⬜ Phase 8 — Sparse Nonlinear Least Squares Solver (Gauss-Newton, LM, Sparse Cholesky, Ordering, Schur)

Objectives
  • slam-solver: the mathematical core — linearize the factor graph, assemble sparse H=JᵀΩJ, b=−JᵀΩr, solve Hδ=b via sparse Cholesky with AMD ordering, iterate with Gauss-Newton and Levenberg-Marquardt (default), optional Schur complement on landmarks; convergence monitoring (I7). Differential-tested against g2o/GTSAM.
Deliverable
  • Sparse NLS solver optimizing a .g2o pose graph to the reference optimum; slamctl optimize graph.g2o reports cost trajectory + converged map; Schur path for pose-landmark graphs.
Acceptance
  • On standard .g2o graphs (manhattan, sphere2500): final cost matches g2o/GTSAM within 1e-3 relative; converges in comparable iteration count. Cost decreases monotonically under LM (I7); GN converges on well-conditioned graphs. Sparse Cholesky with AMD produces materially less fill-in than natural ordering (measured nnz(L) ratio, I8). Schur path matches direct solve (1e-6) and is faster on landmark-heavy graphs. H SPD with gauge prior; rank-deficient (no prior) is detected + reported (I3). Deterministic (fixed reduction order, I5).
Fixtures
  • tests/gn.rs: GN on a well-conditioned graph vs closed form; lm.rs: LM recovers from poor init where GN diverges; cholesky.rs: sparse LLᵀ reconstructs H (1e-10) + PD detection; schur.rs: Schur vs direct equivalence + fill comparison; diff_g2o.rs: final cost vs g2o on manhattan/sphere2500. Deferred: iSAM2 incremental Bayes-tree solve → PhaseDeferred("FINAL_BLUEPRINT §8"). Visual bundle adjustment (camera+points Schur) → PhaseDeferred("FINAL_BLUEPRINT §8.5"). Degenerate: unanchored graph (rank deficiency), single-iteration converged graph, near-singular H (high condition number).
Pitfalls
  • Bad fill-reducing ordering → catastrophic fill-in, O(n³) solve. Manifestation: solve time explodes with loops. Detect: nnz(L) vs nnz(H) (I8). Recovery: AMD/COLAMD; nested dissection (METIS) deferred for huge graphs.
  • Missing gauge anchor → singular H, Cholesky fails. Detect: PD probe → report null-space (I3). Recovery: require a prior; or fix the first variable.
  • GN divergence on poor init (step overshoots). Manifestation: cost increases, oscillation. Detect: cost monitor (I7). Recovery: use LM (damping); good init from frontend.
  • LM λ mistuning → too-small steps (slow) or rejected steps (stall). Detect: iteration/λ log. Recovery: adaptive λ schedule; diag(H) scaling.
  • Schur with non-block-diagonal H_ll (landmarks sharing factors) → H_ll⁻¹ not cheap. Detect: H_ll structure check. Recovery: only Schur truly-independent landmarks; else direct.
  • Float reduction-order nondeterminism in sparse accumulation → solve hash drift. Detect: determinism CI. Recovery: fixed accumulation order (sorted indices), no FMA.

⬜ Phase 9 — Pose-Graph Optimization (2D/3D) + Robust Kernels (Huber/Cauchy/DCS)

Objectives
  • Pose-graph SLAM end-to-end: build a pose graph from frontend constraints (odometry + scan-match between-pose factors), optimize with the Phase-8 solver, and make it robust to outlier (false) loop-closure edges via Huber/Cauchy/DCS kernels (Principle 4). Both SE(2) (primary) and SE(3) (substrate).
Deliverable
  • A pose-graph optimizer producing a globally consistent trajectory from odometry + loop closures, robust to a fraction of false closures; works on 2D and 3D .g2o.
Acceptance
  • On manhattan (2D) and sphere2500 (3D): optimized ATE within reference band (per-graph thresholds). With 10% injected false loop closures: non-robust solve corrupts the map (ATE blows up); robust (DCS/Cauchy) keeps ATE within ~1.5× of the clean optimum. Robust IRLS converges (I7). Gauge anchored (I3). SE(2) and SE(3) both pass. Deterministic.
Fixtures
  • tests/robust.rs: Huber/Cauchy/DCS weight functions vs analytic; false-closure suppression (clean vs poisoned graph, robust vs non-robust ATE). Fixtures: g2o/manhattan.g2o, g2o/sphere2500.g2o, synthetic/loop3.spec with an injected wrong loop. Degenerate: all-outlier loops (robust holds odometry backbone), no loops (chain → odometry only), conflicting loops (consistency).
Pitfalls
  • Robust kernel applied to odometry (not just loops) → backbone under-weighted, drift. Detect: ATE vs kernel scope. Recovery: robustify only loop-closure factors.
  • Kernel threshold mistuned (δ/c/Φ too large → no robustness; too small → rejects valid loops). Detect: false-closure-suppression fixture sweep. Recovery: scale threshold to expected residual / use DCS (self-scaling).
  • IRLS oscillation (weights flip-flop) → non-convergence. Detect: cost/weight oscillation. Recovery: damping, weight smoothing, DCS continuity.
  • Single strong false closure still folds map under Huber (Huber is only mildly robust). Detect: ATE under poisoning. Recovery: Cauchy/DCS (redescending influence) for strong outliers.
  • Gauge drift in 3D (SE(3) 6-DOF null space) without anchor. Detect: PD probe (I3). Recovery: prior on first pose.

⬜ Phase 10 — Loop-Closure Detection (Scan-Context / Appearance + Geometric Verification) + Closing

Objectives
  • slam-loop: detect revisited places from a rotation-invariant scan-context descriptor (appearance), propose candidates via a ring-key KD-tree, verify geometrically (scan match + χ² consistency gate, I6), and — only if verified — insert a robust loop-closure factor into the graph, triggering re-optimization (Principle 13). The highest-risk subsystem.
Deliverable
  • Loop-closure subsystem that proposes, verifies, and closes loops on a real dataset (Intel), measurably improving trajectory consistency; false candidates rejected.
Acceptance
  • On Intel/Killian: true loop closures detected with high recall at high precision (precision ≥ 0.99 after geometric gate — false closures are the danger, so precision is prioritized over recall). A verified closure reduces ATE materially vs no-closure (documented per dataset). Appearance-only false positives are rejected by the geometric gate (I6). Verification scan match returns calibrated info. Deterministic.
Fixtures
  • tests/scan_context.rs: descriptor rotation invariance (rotated scan → same place, near-zero distance after column shift); verify.rs: true loop accepted, perceptual-alias false loop rejected by χ² gate. Fixtures: intel.spec (loop-rich), synthetic/loop3.spec. Deferred: deep learned place recognition → PhaseDeferred("FINAL_BLUEPRINT §10"). Degenerate: symmetric corridor (multiple candidates → require geometric agreement), first traversal (no candidates), self-match (excluded by recency).
Pitfalls
  • Perceptual aliasing (different places look identical) → false candidate. Manifestation: would corrupt map. Detect: geometric verification fails the χ² gate. Recovery: gate (I6); require geometric consistency, not appearance alone (Principle 13).
  • Appearance gate too loose (top-K too large / distance threshold high) → flood of false candidates burdening verification. Detect: candidate count vs accepted. Recovery: tighten ring-key threshold; cap K.
  • Verification scan match converges to a wrong pose (poor init across a large loop) → consistent-looking but wrong closure. Detect: residual + χ² gate + robust kernel (defense in depth). Recovery: correlative/branch-and-bound wide search; verify info.
  • Recency exclusion wrong → matching against just-visited keyframes (trivial self-loop). Detect: closure between adjacent ids. Recovery: exclude a temporal/spatial window.
  • Closing without re-optimization → map shows the loop edge but trajectory not corrected. Detect: pre/post-opt ATE. Recovery: trigger solve + map rebuild on every accepted closure (I9).

⬜ Phase 11 — Full Graph-SLAM Pipeline Integration + Map Management + Relocalization

Objectives
  • slam-pipeline: wire frontend (scan match + keyframing + odometry) → graph back-end (factor graph + solver + loop closure) → map; expose SlamSystem; implement map management (keyframe culling, map rebuild from optimized trajectory, I9) and relocalization (global scan-context match to recover pose after loss/kidnap). Online (incremental) and offline modes.
Deliverable
  • A full graph-SLAM pipeline: ingest a scan+odom stream → produce a consistent optimized map + trajectory, close loops, and relocalize after induced loss; examples/full_pipeline_intel.rs.
Acceptance
  • End-to-end on Intel/Killian: optimized ATE within the conformance band (Phase 12 thresholds); map is globally consistent (loops closed, no doubled walls). Online mode keeps frontend per-scan latency ≤ 30 ms @ 20 Hz (§4); back-end solve async. Relocalization recovers pose within tolerance after an induced kidnap (teleport + scan). Map rebuilt after each optimization reflects the corrected trajectory (I9). Save/load round-trips the full system. Deterministic given seed.
Fixtures
  • tests/integration.rs: full pipeline on synthetic/loop3 + corridor (ATE + map IoU); reloc.rs: induced kidnap → relocalize. Fixtures: intel.spec, killian.spec. Deferred: multi-session / lifelong SLAM, map merging → PhaseDeferred("FINAL_BLUEPRINT §Scalability Analysis"). Visual-inertial pipeline → PhaseDeferred("FINAL_BLUEPRINT §8.5"). Degenerate: no loops (open trajectory, odometry-quality map), continuous featureless region (dead-reckon + relocalize on re-entry), back-end slower than frontend (queue + lag bounded).
Pitfalls
  • Frontend/back-end coupling (frontend blocks on solve) → missed scans in online mode. Manifestation: dropped scans, drift. Detect: per-scan latency. Recovery: async solve worker; publish snapshots (Principle 7).
  • Stale map after optimization (poses corrected, grid not rebuilt) → planner reads an inconsistent map. Detect: map-lag flag (I9). Recovery: rebuild on optimize.
  • Unbounded keyframe/graph growth → solve slows, memory grows. Detect: n_keyframes, solve_ms trend. Recovery: keyframe culling (Principle 9); sliding-window/marginalization (deferred Scalability Analysis).
  • Relocalization false positive (wrong place) → teleports the estimate. Detect: geometric verification (same gate as loop closure). Recovery: verify before relocalize; require strong match.
  • Mode confusion (offline determinism vs online concurrency) → different results. Detect: offline-vs-online consistency test on the same dataset. Recovery: same back-end; online only changes cadence, not math.

⬜ Phase 12 — Benchmarks (Intel, MIT Killian, TUM/KITTI-lite) + ATE/RPE Metrics + Conformance

Objectives
  • slam-bench + slam-cli: dataset loaders (Intel, Killian, TUM, KITTI-lite, CARMEN, .g2o); trajectory evaluation (ATE after SE(2)/SE(3) alignment, RPE drift); criterion benchmarks; conformance gate in CI; deterministic replay.
Deliverable
  • End-to-end: ingest a standard dataset → produce + evaluate (ATE/RPE) an optimized trajectory + map → replay deterministically → prove perf budgets; conformance green in CI.
Acceptance
  • Intel / MIT Killian: optimized pose-graph ATE within the documented per-dataset band (within a few % of trajectory length, after loop closure) and RPE drift bounded. TUM/KITTI-lite: trajectory metrics computed correctly (cross-checked vs TUM evaluate_ate/evaluate_rpe reference values on a known pair). Replay hash identical across two runs and across CI runs (same target/flags, seed, I5). Frontend ≤ 30 ms/scan @ 20 Hz, full graph solve at 10⁴ poses ≤ a few seconds (§4), verified by slam-bench. All prior-phase fixtures pass as regression.
Fixtures
  • conformance/intel/intel.spec + expected/*.json (golden ATE/RPE + tolerance); killian/, tum/, g2o/ (differential cost vs g2o). Degenerate: dataset with no loops (open-trajectory ATE bound), corrupted dataset line (decode error handled), missing ground truth (skip ATE, still run + replay). Replay-equality fixture (seeded FastSLAM + graph) ties Phases 5–11.
Pitfalls
  • Dataset frame/units mismatch (CARMEN frame, laser offset) → large ATE from convention, not algorithm. Manifestation: constant offset/rotation. Detect: ATE before vs after alignment. Recovery: documented per-dataset adapter.
  • ATE alignment masking drift (Umeyama hides systematic bias). Detect: also report RPE (drift rate). Recovery: report both ATE + RPE.
  • Nondeterministic eval (float reduction order, unstable alignment) → flaky conformance. Detect: determinism CI. Recovery: fixed reduction order, deterministic alignment, pinned flags, seed.
  • Benchmark variance on shared CI → false regressions. Detect: criterion confidence intervals. Recovery: statistical thresholds / relative gates / dedicated runner.
  • Map/graph format drift breaks old logs/maps. Detect: round-trip + version test. Recovery: versioned format + migration (Compatibility & Versioning).
