3.2 Per-box detail (one paragraph each)

  • Sensor input (external). 2D LiDAR scans (range/bearing arrays), wheel-encoder odometry (relative SE(2) increments), optional IMU yaw. Out of scope as hardware; represented by dataset readers + mock sources tagged with timestamps. All input is untrusted (malformed/spoofed handled downstream). Interface: ScanSource::next() -> Option<(Timestamp, LaserScan, OdomDelta)>.

  • slam-sensor. Converts raw scan to a canonical LaserScan (angles, ranges, validity mask, sensor pose offset) and computes Cartesian beam endpoints in the sensor frame. Owns the beam/ray sensor model (p_hit/p_short/p_max/p_rand) used by FastSLAM weights and the inverse sensor model used by occupancy mapping. No state mutation; pure transforms + models.

  • slam-odom motion model. Predicts the next pose from a control/odometry increment with calibrated noise: odometry model (rot1–trans–rot2) and velocity model (v, ω). Produces predicted mean + covariance for the EKF predict step and samples for the FastSLAM proposal; provides dead-reckoning baseline. Convention: increments compose on the right (§8.1).

  • slam-match scan matcher. Estimates the relative SE(2) transform between a scan and a reference (previous scan / submap / map). Three matchers behind one trait: ICP (point-to-point and point-to-line, with KD-tree correspondences), correlative (exhaustive/multi-resolution grid search over the likelihood field), NDT (normal-distributions transform, cell Gaussians, Newton step). Returns relative pose + an information matrix. The frontend's accuracy backbone; feeds odometry-grade constraints and loop-closure verification.

  • Data association + keyframe selection (frontend). Associates observed landmarks/cells to existing ones via nearest-neighbour + Mahalanobis χ² gating; decides when to create a keyframe (translation/rotation threshold or information gain). The frontend/backend boundary is here: keyframes + constraints cross into the back-end; raw scans are summarized.

  • slam-ekf (filter path). EKF-SLAM: a single Gaussian over robot pose + all landmark positions; state augmentation on first observation; predict via motion model Jacobian; update via range-bearing measurement Jacobian; Mahalanobis association. Covariance is dense and grows O(n²) in landmarks — the documented scaling wall (Scalability Analysis). Selectable back-end.

  • slam-pf (filter path). FastSLAM / Rao-Blackwellized particle filter: each particle carries a sampled trajectory and its own map (per-particle occupancy grid for grid-FastSLAM, or per-particle EKFs for landmark-FastSLAM). Proposal from the (improved) motion model + scan match; importance weights from the measurement likelihood; adaptive resampling on effective sample size. Seeded RNG → deterministic replay.

  • slam-graph factor graph. The graph back-end's data model: variables (poses, landmarks) on manifolds; factors (odometry, scan-match, landmark, loop-closure, prior) each producing a residual + sqrt-information whitening + analytic/AD Jacobian. Builds the sparse structure (which variables each factor touches) consumed by the solver. Supports .g2o import/export.

  • slam-solver sparse NLS. Sparse nonlinear least squares: linearize all factors → assemble sparse H = JᵀΩJ and b = −JᵀΩr → solve Hδ = b via sparse Cholesky with a fill-reducing ordering (AMD/COLAMD), optionally Schur-complement out landmarks; iterate with Gauss-Newton or Levenberg-Marquardt damping; robust kernels (Huber/Cauchy/DCS) reweight outliers. Anchors gauge freedom with a prior on the first pose. The mathematical core of graph SLAM.

  • slam-loop loop closure. Detects revisited places from a rotation-invariant scan-context ring descriptor (KD-tree on ring keys), proposes candidates, verifies geometrically (scan match between current and candidate keyframe + χ² consistency gate), and — only if verified — inserts a loop-closure factor (robust kernel) into the graph, triggering re-optimization. The single highest-risk subsystem: a false closure corrupts the entire map.

  • slam-map. Map representations: occupancy grid (log-odds, ray-cast updates via Bresenham/inverse sensor model), landmark map (positions + covariances for EKF/landmark-FastSLAM), and the pose graph itself. Rebuildable from the optimized trajectory + stored scans after each optimization.

  • slam-pipeline. Wires frontend → chosen back-end → loop closure → map; exposes the SlamSystem API (submit, query pose/map, save/load); implements relocalization (global scan-context match against the keyframe database to recover pose after loss/kidnap). Owns online/offline mode and the async optimization cadence.

  • slam-bench. Dataset replay (Intel, MIT Killian, TUM/KITTI-lite, .g2o), and trajectory evaluation: ATE (absolute trajectory error after SE(2)/SE(3) alignment) and RPE (relative pose error / drift). The regression + conformance backbone.

3.3 Boundaries summary

  • Frontend/backend boundary: keyframes + constraints (poses, relative transforms, associations) cross; raw scans are summarized/stored by reference. Frontend is soft-real-time per scan; back-end optimization is asynchronous and may lag.
  • Concurrency boundary: online mode runs the frontend on the ingest path and the back-end solve on a worker; the optimized trajectory is published as an atomic snapshot to readers (planner/control).
  • Trust boundary: every scan/odom sample and every loop-closure candidate crosses from untrusted → validated (range/sanity at ingest; χ² geometric gate at loop closure) before it can alter the map.
  • Determinism boundary: the back-end solver and EKF are deterministic given inputs; the particle filter is deterministic given inputs and seed.

8. Domain Model / Math

Conventions (LOCKED). Poses are elements of SE(2)/SE(3). Right perturbation: X⊞ξ = X·Exp(ξ), Y⊟X = Log(X⁻¹·Y). SE(2) tangent order ξ=(ρ_x, ρ_y, ϕ) (translation then rotation). SE(3) tangent ξ=(ρ(3), φ(3)) (translation then rotation); SO(3) via Hamilton quaternion scalar-first q=[w,x,y,z] (matches #285 §8.6). Information form throughout: factor weight Ω = Σ⁻¹, whitening by Ω^{1/2} (Cholesky of Ω). g2o .g2o stores upper-triangular information; adapter handles it.

8.1 Lie groups SE(2)/SE(3)

SE(2): X = [[R(θ), t],[0, 1]], R(θ)=[[cosθ,−sinθ],[sinθ,cosθ]], t∈R². Tangent se(2)≅R³.

hat: ξ=(ρ_x,ρ_y,ϕ) ↦ [[0,−ϕ,ρ_x],[ϕ,0,ρ_y],[0,0,0]]
Exp(ξ): θ=ϕ; t = V(ϕ)·ρ,  V(ϕ)=(1/ϕ)[[sinϕ, −(1−cosϕ)],[(1−cosϕ), sinϕ]]  (ϕ→0: V→I)
Log(X): ϕ=atan2(R21,R11); ρ = V(ϕ)⁻¹ t
Adjoint Ad_X (3×3): rotates/translates a tangent between frames:
  Ad_X = [[R, [[t_y],[−t_x]]],[0(1×2), 1]]   (maps left to right perturbation)

SE(3): X=[[R, t],[0,1]], R∈SO(3), t∈R³. Tangent se(3)≅R⁶, ξ=(ρ,φ).

Exp(ξ): R=Exp_SO3(φ)=I + (sinθ/θ)[φ]_× + ((1−cosθ)/θ²)[φ]_×²  (θ=‖φ‖)
        t = V(φ)ρ,  V(φ)=I + ((1−cosθ)/θ²)[φ]_× + ((θ−sinθ)/θ³)[φ]_×²
Log: φ=Log_SO3(R); ρ=V(φ)⁻¹ t
Ad_X (6×6) = [[R, [t]_× R],[0, R]]
⊞: X·Exp(ξ);  ⊟: Log(X⁻¹ Y);  small-angle Taylor branch for θ<1e-8

Composition X1∘X2, inverse X⁻¹; right-Jacobian Jr(ξ) / left Jl(ξ) used in factor Jacobians and EKF.

8.2 Motion models / odometry

Odometry model (rot1, trans, rot2) — relative motion decomposed; noise on each component (Thrun ch.5):

δ_rot1 = atan2(ȳ'−ȳ, x̄'−x̄) − θ;  δ_trans = ‖(x̄',ȳ')−(x̄,ȳ)‖;  δ_rot2 = θ' − θ − δ_rot1
sample: δ̂ = δ + noise(α·δ²...);  x' = x ⊞ [δ̂_trans·cos(θ+δ̂_rot1), δ̂_trans·sin(θ+δ̂_rot1), δ̂_rot1+δ̂_rot2]

Velocity model (v, ω): arc integration; θ→0 straight-line branch. Both produce predicted mean + covariance Σ_u via the noise model (EKF predict) and samples (FastSLAM proposal). Convention: increments compose on the right (§8.1).

8.4 EKF-SLAM

State μ = [x_R; m_1; … ; m_N] (robot pose + landmark positions); covariance Σ dense (3+2N)².

predict:  x_R⁻ = f(x_R, u);  Σ⁻ = G Σ Gᵀ + V Σ_u Vᵀ   (G = ∂f/∂x on robot block; landmarks unchanged)
augment (new landmark j first seen): μ_j = x_R⁻ ⊕ g(z);  Σ expanded with cross-covariance to all states
update (landmark j):  ẑ = h(x_R⁻, m_j);  y = z ⊟ ẑ (bearing wrapped)
          H = [∂h/∂x_R … ∂h/∂m_j …] (sparse rows, only robot + landmark j columns nonzero)
          S = H Σ⁻ Hᵀ + R;  K = Σ⁻ Hᵀ S⁻¹;  μ⁺ = μ⁻ + K y;  Σ⁺ Joseph
association (Mahalanobis): d²_jk = y_jkᵀ S_jk⁻¹ y_jk; pick min d²; gate d² ≤ χ²_{2,α}; else new/defer (I10)

Cost: update O(N) per landmark via sparse H, but covariance maintenance is O(N²) — the scaling wall (Scalability Analysis).

8.5 FastSLAM (Rao-Blackwellized PF)

Factorization: p(x_{1:t}, m | z_{1:t}, u_{1:t}) = p(x_{1:t}|z,u) · Π_k p(m_k | x_{1:t}, z). Each particle i carries a sampled trajectory and a map (grid-FastSLAM: per-particle occupancy grid; landmark-FastSLAM: per-landmark 2×2 EKFs).

proposal: x_t^i ~ q(x_t | x_{t−1}^i, u_t, z_t)   (motion model, or improved by scan match — GMapping)
weight:   w_t^i ∝ w_{t−1}^i · p(z_t | x_t^i, m^i)  (grid: beam/likelihood-field model; landmark: measurement likelihood w/ landmark EKF)
map update (grid): ray-cast scan into particle i's grid (log-odds);  (landmark): EKF update of observed landmark
normalize weights (Σw=1); N_eff = 1/Σ(w^i)²
resample if N_eff < N_thresh (e.g. N/2): low-variance / systematic resampling → duplicate high-weight particles + maps

Rao-Blackwellization: conditioning on the trajectory makes the per-landmark estimators independent → O(M·N) not O(N²); per-particle grids are the memory cost (Scalability Analysis). Seeded RNG → deterministic (I5).

8.6 Factor graph

Bipartite graph: variable nodes θ = {X_i (poses), m_k (landmarks)} on manifolds; factor nodes f_j (odometry, scan-match, landmark, loop, prior) each a probabilistic constraint over a small subset of variables. MAP estimate:

θ* = argmin_θ  Σ_j  ρ_j( ‖ r_j(θ) ‖²_{Ω_j} )      (ρ = robust kernel, identity for non-robust)
‖r‖²_Ω = rᵀ Ω r ;  whitened residual r̃ = Ω^{1/2} r  (Ω^{1/2} = Cholesky(Ω));  so cost = Σ ‖r̃_j‖²

Each factor exposes residual(θ), whiten(), and jacobian(θ) (∂r/∂ξ for each connected variable's tangent). The bipartite structure = the sparsity pattern of J (hence H=JᵀΩJ). .g2o import builds this graph.

8.7 Nonlinear least squares (the solver)

Linearize at current θ: r_j(θ⊞δ) ≈ r_j(θ) + J_j δ. Stack whitened: minimize ‖J̃ δ + r̃‖² → normal equations:

(JᵀΩJ) δ = −JᵀΩr      ⇔   H δ = b ,   H = Σ_j J_jᵀ Ω_j J_j (sparse, SPD with gauge prior),  b = −Σ_j J_jᵀ Ω_j r_j
Gauss-Newton:  solve H δ = b; update θ ← θ ⊞ δ; repeat until ‖δ‖,Δcost,‖b‖ < tol
Levenberg-Marquardt: solve (H + λ diag(H)) δ = b; if cost decreases accept + λ↓ (e.g. /3), else reject + λ↑ (×... )
sparse Cholesky: H = LLᵀ after fill-reducing permutation P (AMD/COLAMD): (PHPᵀ) = L̃L̃ᵀ; solve via P, L̃, back-subst
variable ordering: order landmarks before poses (or AMD) to control fill-in (I8)
Schur complement (landmark elimination): partition [[H_pp, H_pl],[H_lp, H_ll]] [δ_p; δ_l] = [b_p; b_l]
   reduced (pose) system: (H_pp − H_pl H_ll⁻¹ H_lp) δ_p = b_p − H_pl H_ll⁻¹ b_l   (H_ll block-diagonal → cheap inverse)
   back-substitute: δ_l = H_ll⁻¹ (b_l − H_lp δ_p)

Robust kernel ρ: applied via iteratively-reweighted least squares — weight w(e) = (1/e)·dρ/de scales Ω per factor each iteration.

Huber(δ_H):  ρ=½e² (|e|≤δ_H); =δ_H(|e|−½δ_H) else.  Cauchy(c): ρ=½c²log(1+e²/c²).  DCS(Φ): scales s=min(1, 2Φ/(Φ+e²))²

Design principles (§6)

  • Operate on manifolds, never on Euler/raw matrices. Poses live in SE(2)/SE(3); updates apply by retraction X⊞ξ = X·Exp(ξ); Jacobians are taken w.r.t the tangent ξ, not against (x,y,θ) naively or against a 9-element matrix. Violating it (e.g. averaging angles linearly, optimizing a constrained matrix freely) produces invalid rotations, wrap-around bugs at ±π, and gauge inconsistency. Tradeoff: a Lie-group layer is upfront work; operationally it eliminates an entire class of silent rotation bugs.
  • Exploit sparsity — never dense-solve the graph. The information matrix H = JᵀΩJ is sparse (each factor touches few variables). The solver assembles CSC, uses a fill-reducing ordering (AMD/COLAMD), and factorizes sparsely (and/or Schur-complements landmarks). A dense O(n³) solve at 10⁴ poses is infeasible; treating H as dense is the difference between seconds and never. Violation ⇒ the back-end does not scale past toy graphs.
  • The information/covariance matrix stays SPD. EKF covariance P, innovation covariance S, and the solver's H (with the gauge prior) must be symmetric positive-definite. Enforced via Joseph form (EKF) and Cholesky-with-PD-check (solver). A non-PD H means an unanchored gauge or a degenerate problem; a non-PD P yields NaN gains. Detection: Cholesky failure → regularize / anchor / report.
  • Robust kernels for outlier loop closures. Loop-closure constraints can be wrong (perceptual aliasing). The back-end wraps loop factors in Huber/Cauchy/DCS kernels (iteratively-reweighted least squares) so a single false closure cannot dominate the cost. Violation ⇒ one bad edge folds the map. Tradeoff: robust kernels slow convergence slightly and need a tuned threshold; cheaper than a corrupted map.
  • Data association is the failure point — gate aggressively. Wrong correspondences (landmark↔landmark, scan↔scan) are the dominant cause of divergence. Every association passes a Mahalanobis χ² gate; ambiguous matches are deferred, not guessed. Skipping the gate lets one mis-association cascade. Conservative association (reject when unsure) beats optimistic association every time in SLAM.
  • Deterministic given seed. The EKF and solver are deterministic functions of input; the particle filter is deterministic given input and RNG seed. No wall-clock, no unseeded RNG, fixed float reduction order. Enables replay-based debugging, conformance, and regression. Violation ⇒ unreproducible maps, untestable.
  • Separation of frontend and backend. The frontend (noisy, heuristic: matching, association, keyframing) is isolated from the back-end (deterministic optimization). The interface is keyframes + typed constraints. This lets the back-end be unit-tested against synthetic graphs and the frontend be swapped (ICP↔NDT↔correlative) without touching the solver. Mixing them couples heuristics into the math core and destroys testability.
  • Marginalization preserves consistency. When a variable is removed (sliding window, fixed-lag), it is marginalized (Schur complement), not deleted — its information is folded into the remaining variables, creating fill-in. Deleting a variable discards information and biases the estimate; marginalizing keeps the posterior correct at the cost of denser structure. Track the resulting dense blocks.
  • Keyframe and landmark management is bounded. Keyframes are added on motion/information thresholds, not per scan; redundant keyframes are culled; landmark count is monitored. Unbounded growth makes both filter (O(n²)) and graph (fill-in) intractable. The pipeline enforces a budget and a culling policy.
  • Scan matching reports uncertainty, not just a pose. Every matcher returns a relative transform and an information matrix (from the match Hessian / sampled covariance). The back-end needs the weight; a constraint without a calibrated information matrix is either ignored or over-trusted. Violation ⇒ mis-weighted edges, inconsistent optimization.
  • Occupancy mapping is log-odds and clamped. The grid accumulates log-odds via the inverse sensor model; values are clamped to [l_min, l_max] so the map stays responsive to change and avoids overflow. Linear-probability accumulation is numerically poor; unclamped log-odds make occupied cells un-clearable. The map is always rebuildable from the optimized trajectory + scans.
  • Convergence is monitored, not assumed. The solver tracks cost decrease and gradient norm; GN/LM iterates until ‖Δ‖, cost change, or gradient fall below tolerance, with an iteration cap. A solve that does not decrease cost (LM increases damping; GN may diverge) is reported, not silently returned. A "converged" flag that is wrong yields a confidently inconsistent map.
  • Loop closures must pass geometric + appearance gates before insertion. Appearance proposes; geometry disposes. A scan-context candidate is only inserted as a factor after a successful scan match with a χ² consistency check against the current estimate. No appearance-only closures touch the graph (Principle 4 + 5 combined for the highest-risk path).
  • Fail loud, contain locally. A bad scan degrades that frontend step (reject, dead-reckon, flag); a rejected loop closure is dropped, not forced; a non-convergent solve keeps the previous estimate. No subsystem silently corrupts the shared map/trajectory.
