288 — SLAM (Simultaneous Localization and Mapping) Basics

Goal: A from-scratch SLAM engine spanning both filter-based and graph-based back-ends — SE(2)/SE(3) Lie-group math, a 2D LiDAR frontend (ICP / correlative / NDT scan matching), motion models and odometry, EKF-SLAM, FastSLAM (Rao-Blackwellized particle filter with per-particle occupancy grids), a factor-graph representation, a sparse nonlinear-least-squares solver (Gauss-Newton / Levenberg-Marquardt with sparse Cholesky + Schur complement), pose-graph optimization with robust kernels, loop-closure detection and closing, and a full graph-SLAM pipeline producing a consistent map + trajectory.

1. Goal

1.1 What is built (precise terms)

  • A SLAM engine estimating a robot trajectory {x_0 … x_T} and a map (occupancy grid | landmark set | pose graph) from 2D LiDAR scans + wheel/odometry (+ optional IMU heading), online (incremental) and offline (batch dataset).
  • Two back-end families behind one trait surface: filter (EKF-SLAM landmark, FastSLAM RBPF) and graph (factor graph → sparse NLS solver → pose-graph optimization).
  • Frontend: scan matching (ICP point-to-point / point-to-line, correlative grid search, NDT), keyframe selection, motion-model prediction, data association (nearest-neighbour + Mahalanobis gating).
  • Loop closure: appearance candidate proposal (scan-context-style ring descriptor) + geometric verification (scan match + χ² gate) → relative-pose constraint inserted into the graph with a robust kernel.
  • Map products: consistent occupancy grid (log-odds), landmark map, optimized pose graph; trajectory in SE(2) (SE(3) substrate present, 3D deferred).
  • Conventions LOCKED: SE(2)/SE(3) on-manifold (no Euler in state), Hamilton quaternion for SO(3) (§8.6), right perturbation X⊞ξ = X·Exp(ξ) (§8.1), sqrt-information factors, sparse column-major CSC matrices.

1.2 System boundaries

  • In: Lie-group math, frontend scan matching, occupancy mapping, EKF-SLAM, FastSLAM, factor graph, sparse NLS solver, pose-graph optimization, loop closure, full pipeline, datasets + ATE/RPE evaluation.
  • Out (hard boundaries): path/motion planning (consumes the map) → #287 Motion Planner; trajectory control/actuation → #289 PID/Autonomous Control; multi-sensor low-level fusion / IMU mechanization → #285 Sensor Fusion (its estimate may seed odometry here); learned perception / place recognition (deep nets); raw sensor drivers / HAL (dataset + mock only).

1.3 Explicit non-goals

  • Not a planner (no A*/RRT/lattice) → cross-link #287.
  • Not a controller (no PID/MPC/actuation) → cross-link #289.
  • Not a deep-learning perception stack (no CNN feature/descriptor learning, no learned place recognition).
  • Not a full visual SLAM / bundle-adjustment system (camera frontend, BA over 3D points) — deferred PhaseDeferred("FINAL_BLUEPRINT §8.5").
  • Not a 3D LiDAR system (voxel/surfel, 6-DOF NDT at scale) — substrate present, full 3D deferred PhaseDeferred("FINAL_BLUEPRINT §1.8").
  • No GPU compute; no multi-session / map merging; no deep place recognition.

1.4 Deployment model

  • Primary: embeddable Rust library (workspace of crates) + CLI slamctl.
  • Two modes: offline (process a recorded dataset end-to-end → optimized map + trajectory + metrics) and online incremental (ingest a live/replayed scan+odom stream, maintain estimate at scan rate, run loop closure + optimization asynchronously).
  • Integration surface: SlamSystem API (submit scan/odom → query pose + map), plus .g2o import/export for interop with g2o/GTSAM tooling.

1.5 Target users

  • Robotics / AV / drone / mobile-robot engineers building or debugging a SLAM stack; engineers who must reason about why a map is inconsistent (frontend data association vs back-end optimization vs false loop closure) rather than treat SLAM as a black box.

1.6 Phase-0 deliverable (numbered crate list)

  1. slam-lie — SE(2)/SE(3), SO(2)/SO(3), manifolds, Exp/Log, hat/vee, adjoint, ⊞/⊟, Jacobians.
  2. slam-sensor — scans (LaserScan), sensor/measurement models, ray model, beam endpoints.
  3. slam-map — occupancy grid (log-odds), landmark map, ray casting / Bresenham.
  4. slam-match — ICP (point-to-point / point-to-line), correlative scan matcher, NDT.
  5. slam-odom — motion models (odometry, velocity), dead reckoning, noise propagation.
  6. slam-ekf — EKF-SLAM (state augmentation, predict/update, Mahalanobis association).
  7. slam-pf — FastSLAM / RBPF (proposal, weights, resampling, per-particle grid).
  8. slam-graph — factor graph (variables, factors, residuals, whitening).
  9. slam-solver — sparse NLS (Gauss-Newton, LM, sparse Cholesky, AMD ordering, Schur).
  10. slam-loop — loop-closure detection (scan-context descriptor) + geometric verification.
  11. slam-pipeline — full SLAM system (frontend↔backend wiring) + map management + relocalization.
  12. slam-cli — slamctl runner/visualizer.
  13. slam-bench — datasets (Intel, MIT Killian, TUM/KITTI-lite) + ATE/RPE metrics.

1.7 What later phases unlock

Phases 7–9: graph back-end (factor graph, sparse solver, pose-graph optimization). Phases 10–11: loop closure + full integrated pipeline + relocalization. 1.9 Timeline

  • Phase 0: 1–2 weeks. Full arc (Phases 0–12): 6–14 weeks for one engineer.

1.10 Recommended language + rationale

  • Rust 2021. Rationale: deterministic destruction + no GC → reproducible map/trajectory given seed (Principle: determinism); strong types + const generics for manifold dimensions and fixed-size Jacobian blocks (catches SE(2)=3-DOF vs SE(3)=6-DOF mismatch at compile time); ownership prevents aliasing of the information matrix during a solve; trait objects model Factor/Filter/ScanMatcher cleanly; mature sparse-linear-algebra ecosystem (sprs, nalgebra) or first-party CSC; #![forbid(unsafe_code)] in math/solver cores.

1.11 Prerequisites

  • Probability / recursive Bayesian estimation (Gaussian, Bayes filter, MMSE) — see #285.
  • Linear algebra incl. sparse (factorizations, SPD matrices, fill-in, conditioning).
  • Nonlinear optimization (Gauss-Newton, Levenberg-Marquardt, trust region, robust M-estimation).
  • Lie groups SE(2)/SE(3), SO(2)/SO(3) (Exp/Log, adjoint, tangent spaces).
  • Rigid-body geometry (rigid transforms, composition, 2D/3D rotations).
  • Graph algorithms / sparse structure (adjacency, elimination ordering) — cross-link #84 Graph Database (sparse adjacency intuition).

2.2 Historical / architectural significance

  • EKF-SLAM (Smith, Self, Cheeseman 1986–90; "stochastic map") → quadratic-in-landmarks scaling wall.
  • FastSLAM (Montemerlo et al. 2002): Rao-Blackwellized particle filter breaks the EKF scaling wall; GMapping (Grisetti 2007) makes grid-based RBPF practical.
  • Graph SLAM lineage: Lu & Milios 1997 (pose graphs) → square-root SAM / factor graphs (Dellaert & Kaess 2006) → g2o (Kümmerle 2011), GTSAM, iSAM/iSAM2 (Kaess 2008/2012) — SLAM recast as sparse nonlinear least squares; the modern dominant paradigm.
  • Production systems: Cartographer (Hess 2016, correlative + branch-and-bound loop closure + pose-graph), ORB-SLAM (Mur-Artal 2015, visual; same back-end shape).

2.3 Engineering muscles

  • Translating a probabilistic estimation problem into a sparse linear-algebra problem and back; defending every Jacobian on a manifold; keeping an information matrix SPD and well-conditioned; designing a frontend/backend split that lets the back-end stay deterministic while the frontend deals with noisy association; building loop closure that improves rather than destroys a map.

2.4 Production engineering concepts exercised

  • Deterministic replay (seeded RNG for the particle filter), bounded-growth graph management, structured telemetry of estimator/map health, conformance against standard datasets with ATE/RPE thresholds, semver of map/graph/.g2o formats.

2.5 Cross-links to portfolio

  • #285 Sensor Fusion — shares estimation + Lie math; its fused pose/velocity can seed odometry/motion here.
  • #287 Motion Planner — consumes the occupancy grid + pose graph produced here.
  • #289 PID / Autonomous Control — consumes the localized pose for trajectory tracking.
  • #84 Graph Database — sparse adjacency / elimination-ordering intuition mirrors the factor graph's structure.
  • Linear-algebra kernels echo #181 SIMD (deferred acceleration); sparse Cholesky echoes numerical-storage projects.

2.6 Calibration value

  • After this, an engineer can localize the cause of a broken map to the correct subsystem — frontend association, motion model, solver conditioning, or a single false loop closure — and reason about observability (gauge freedom of the global frame) rather than tuning blindly. A permanent capability lift.

2.7 What Mastery Looks Like

  • Derive and verify any on-manifold Jacobian of a relative-pose residual via the adjoint, then prove it with a finite-difference check — built in Phase 1 (Lie math) and exercised in Phase 7 (factors).
  • Read a sparse Cholesky fill-in trace and an AMD ordering and predict whether a graph will solve in seconds or never — built in Phase 8 (sparse NLS solver).
  • Trace a corrupted map back to its first bad edge — distinguishing a frontend mis-association (Phase 5) from a false loop closure (Phase 10) from a solver that converged confidently to the wrong optimum (Phase 8) — using only telemetry and a deterministic replay.
  • Choose filter vs graph back-end from the numbers: know that EKF-SLAM hits the O(N²) wall near 10³ landmarks (Phase 5) and when a Rao-Blackwellized particle filter (Phase 6) or a sparse pose graph (Phase 9) is the right escape.
  • Design loop closure that improves rather than destroys a map — appearance proposes, geometry disposes, robust kernels backstop — across Phase 9 (robust kernels) and Phase 10 (geometric gate), defense in depth.
  • Reason about gauge freedom and observability — recognise an unanchored pose graph as rank-deficient by exactly its gauge dimension and know why an anchor changes no relative geometry — Phase 8, Phase 9.
  • Keep an estimator honest: read NEES/NIS to tell an over-confident filter from an under-confident one and re-calibrate the noise model — Phase 4 (motion noise), Phase 5 (EKF consistency).
  • Build the whole thing deterministically so any production map is reproducible bit-for-bit from (dataset, params, seed) and any incident is replayable — Phase 0 (determinism gate) through Phase 12 (conformance + replay).

3.2 Per-box detail (one paragraph each)

  • Sensor input (external). 2D LiDAR scans (range/bearing arrays), wheel-encoder odometry (relative SE(2) increments), optional IMU yaw. Out of scope as hardware; represented by dataset readers + mock sources tagged with timestamps. All input is untrusted (malformed/spoofed handled downstream). Interface: ScanSource::next() -> Option<(Timestamp, LaserScan, OdomDelta)>.

  • slam-sensor. Converts raw scan to a canonical LaserScan (angles, ranges, validity mask, sensor pose offset) and computes Cartesian beam endpoints in the sensor frame. Owns the beam/ray sensor model (p_hit/p_short/p_max/p_rand) used by FastSLAM weights and the inverse sensor model used by occupancy mapping. No state mutation; pure transforms + models.

  • slam-odom motion model. Predicts the next pose from a control/odometry increment with calibrated noise: odometry model (rot1–trans–rot2) and velocity model (v, ω). Produces predicted mean + covariance for the EKF predict step and samples for the FastSLAM proposal; provides dead-reckoning baseline. Convention: increments compose on the right (§8.1).

  • slam-match scan matcher. Estimates the relative SE(2) transform between a scan and a reference (previous scan / submap / map). Three matchers behind one trait: ICP (point-to-point and point-to-line, with KD-tree correspondences), correlative (exhaustive/multi-resolution grid search over the likelihood field), NDT (normal-distributions transform, cell Gaussians, Newton step). Returns relative pose + an information matrix. The frontend's accuracy backbone; feeds odometry-grade constraints and loop-closure verification.

  • Data association + keyframe selection (frontend). Associates observed landmarks/cells to existing ones via nearest-neighbour + Mahalanobis χ² gating; decides when to create a keyframe (translation/rotation threshold or information gain). The frontend/backend boundary is here: keyframes + constraints cross into the back-end; raw scans are summarized.

  • slam-ekf (filter path). EKF-SLAM: a single Gaussian over robot pose + all landmark positions; state augmentation on first observation; predict via motion model Jacobian; update via range-bearing measurement Jacobian; Mahalanobis association. Covariance is dense and grows O(n²) in landmarks — the documented scaling wall (Scalability Analysis). Selectable back-end.

  • slam-pf (filter path). FastSLAM / Rao-Blackwellized particle filter: each particle carries a sampled trajectory and its own map (per-particle occupancy grid for grid-FastSLAM, or per-particle EKFs for landmark-FastSLAM). Proposal from the (improved) motion model + scan match; importance weights from the measurement likelihood; adaptive resampling on effective sample size. Seeded RNG → deterministic replay.

  • slam-graph factor graph. The graph back-end's data model: variables (poses, landmarks) on manifolds; factors (odometry, scan-match, landmark, loop-closure, prior) each producing a residual + sqrt-information whitening + analytic/AD Jacobian. Builds the sparse structure (which variables each factor touches) consumed by the solver. Supports .g2o import/export.

  • slam-solver sparse NLS. Sparse nonlinear least squares: linearize all factors → assemble sparse H = JᵀΩJ and b = −JᵀΩr → solve Hδ = b via sparse Cholesky with a fill-reducing ordering (AMD/COLAMD), optionally Schur-complement out landmarks; iterate with Gauss-Newton or Levenberg-Marquardt damping; robust kernels (Huber/Cauchy/DCS) reweight outliers. Anchors gauge freedom with a prior on the first pose. The mathematical core of graph SLAM.

  • slam-loop loop closure. Detects revisited places from a rotation-invariant scan-context ring descriptor (KD-tree on ring keys), proposes candidates, verifies geometrically (scan match between current and candidate keyframe + χ² consistency gate), and — only if verified — inserts a loop-closure factor (robust kernel) into the graph, triggering re-optimization. The single highest-risk subsystem: a false closure corrupts the entire map.

  • slam-map. Map representations: occupancy grid (log-odds, ray-cast updates via Bresenham/inverse sensor model), landmark map (positions + covariances for EKF/landmark-FastSLAM), and the pose graph itself. Rebuildable from the optimized trajectory + stored scans after each optimization.

  • slam-pipeline. Wires frontend → chosen back-end → loop closure → map; exposes the SlamSystem API (submit, query pose/map, save/load); implements relocalization (global scan-context match against the keyframe database to recover pose after loss/kidnap). Owns online/offline mode and the async optimization cadence.

  • slam-bench. Dataset replay (Intel, MIT Killian, TUM/KITTI-lite, .g2o), and trajectory evaluation: ATE (absolute trajectory error after SE(2)/SE(3) alignment) and RPE (relative pose error / drift). The regression + conformance backbone.

3.3 Boundaries summary

  • Frontend/backend boundary: keyframes + constraints (poses, relative transforms, associations) cross; raw scans are summarized/stored by reference. Frontend is soft-real-time per scan; back-end optimization is asynchronous and may lag.
  • Concurrency boundary: online mode runs the frontend on the ingest path and the back-end solve on a worker; the optimized trajectory is published as an atomic snapshot to readers (planner/control).
  • Trust boundary: every scan/odom sample and every loop-closure candidate crosses from untrusted → validated (range/sanity at ingest; χ² geometric gate at loop closure) before it can alter the map.
  • Determinism boundary: the back-end solver and EKF are deterministic given inputs; the particle filter is deterministic given inputs and seed.

6. Design Principles

  1. Operate on manifolds, never on Euler/raw matrices. Poses live in SE(2)/SE(3); updates apply by retraction X⊞ξ = X·Exp(ξ); Jacobians are taken w.r.t the tangent ξ, not against (x,y,θ) naively or against a 9-element matrix. Violating it (e.g. averaging angles linearly, optimizing a constrained matrix freely) produces invalid rotations, wrap-around bugs at ±π, and gauge inconsistency. Tradeoff: a Lie-group layer is upfront work; operationally it eliminates an entire class of silent rotation bugs.

  2. Exploit sparsity — never dense-solve the graph. The information matrix H = JᵀΩJ is sparse (each factor touches few variables). The solver assembles CSC, uses a fill-reducing ordering (AMD/COLAMD), and factorizes sparsely (and/or Schur-complements landmarks). A dense O(n³) solve at 10⁴ poses is infeasible; treating H as dense is the difference between seconds and never. Violation ⇒ the back-end does not scale past toy graphs.

  3. The information/covariance matrix stays SPD. EKF covariance P, innovation covariance S, and the solver's H (with the gauge prior) must be symmetric positive-definite. Enforced via Joseph form (EKF) and Cholesky-with-PD-check (solver). A non-PD H means an unanchored gauge or a degenerate problem; a non-PD P yields NaN gains. Detection: Cholesky failure → regularize / anchor / report.

3b. Anchor the gauge. Pose-graph SLAM has a free global frame (SE(2): 3-DOF, SE(3): 6-DOF gauge freedom). Without a prior fixing the first pose (or a fixed vertex), H is rank-deficient by the gauge dimension and the solve is singular. Always anchor; the choice of anchor does not change relative geometry but must exist.

  1. Robust kernels for outlier loop closures. Loop-closure constraints can be wrong (perceptual aliasing). The back-end wraps loop factors in Huber/Cauchy/DCS kernels (iteratively-reweighted least squares) so a single false closure cannot dominate the cost. Violation ⇒ one bad edge folds the map. Tradeoff: robust kernels slow convergence slightly and need a tuned threshold; cheaper than a corrupted map.

  2. Data association is the failure point — gate aggressively. Wrong correspondences (landmark↔landmark, scan↔scan) are the dominant cause of divergence. Every association passes a Mahalanobis χ² gate; ambiguous matches are deferred, not guessed. Skipping the gate lets one mis-association cascade. Conservative association (reject when unsure) beats optimistic association every time in SLAM.

  3. Deterministic given seed. The EKF and solver are deterministic functions of input; the particle filter is deterministic given input and RNG seed. No wall-clock, no unseeded RNG, fixed float reduction order. Enables replay-based debugging, conformance, and regression. Violation ⇒ unreproducible maps, untestable.

  4. Separation of frontend and backend. The frontend (noisy, heuristic: matching, association, keyframing) is isolated from the back-end (deterministic optimization). The interface is keyframes + typed constraints. This lets the back-end be unit-tested against synthetic graphs and the frontend be swapped (ICP↔NDT↔correlative) without touching the solver. Mixing them couples heuristics into the math core and destroys testability.

  5. Marginalization preserves consistency. When a variable is removed (sliding window, fixed-lag), it is marginalized (Schur complement), not deleted — its information is folded into the remaining variables, creating fill-in. Deleting a variable discards information and biases the estimate; marginalizing keeps the posterior correct at the cost of denser structure. Track the resulting dense blocks.

  6. Keyframe and landmark management is bounded. Keyframes are added on motion/information thresholds, not per scan; redundant keyframes are culled; landmark count is monitored. Unbounded growth makes both filter (O(n²)) and graph (fill-in) intractable. The pipeline enforces a budget and a culling policy.

  7. Scan matching reports uncertainty, not just a pose. Every matcher returns a relative transform and an information matrix (from the match Hessian / sampled covariance). The back-end needs the weight; a constraint without a calibrated information matrix is either ignored or over-trusted. Violation ⇒ mis-weighted edges, inconsistent optimization.

  8. Occupancy mapping is log-odds and clamped. The grid accumulates log-odds via the inverse sensor model; values are clamped to [l_min, l_max] so the map stays responsive to change and avoids overflow. Linear-probability accumulation is numerically poor; unclamped log-odds make occupied cells un-clearable. The map is always rebuildable from the optimized trajectory + scans.

  9. Convergence is monitored, not assumed. The solver tracks cost decrease and gradient norm; GN/LM iterates until ‖Δ‖, cost change, or gradient fall below tolerance, with an iteration cap. A solve that does not decrease cost (LM increases damping; GN may diverge) is reported, not silently returned. A "converged" flag that is wrong yields a confidently inconsistent map.

  10. Loop closures must pass geometric + appearance gates before insertion. Appearance proposes; geometry disposes. A scan-context candidate is only inserted as a factor after a successful scan match with a χ² consistency check against the current estimate. No appearance-only closures touch the graph (Principle 4 + 5 combined for the highest-risk path).

  11. Fail loud, contain locally. A bad scan degrades that frontend step (reject, dead-reckon, flag); a rejected loop closure is dropped, not forced; a non-convergent solve keeps the previous estimate. No subsystem silently corrupts the shared map/trajectory.

  12. Replayability first. Every input (scan, odom), every association decision, every accepted/rejected loop closure, and the RNG seed are loggable; nothing in the core is observable only via a debugger. The dataset replayer reproduces any run bit-for-bit.

8. Domain Model / Math

Conventions (LOCKED). Poses are elements of SE(2)/SE(3). Right perturbation: X⊞ξ = X·Exp(ξ), Y⊟X = Log(X⁻¹·Y). SE(2) tangent order ξ=(ρ_x, ρ_y, ϕ) (translation then rotation). SE(3) tangent ξ=(ρ(3), φ(3)) (translation then rotation); SO(3) via Hamilton quaternion scalar-first q=[w,x,y,z] (matches #285 §8.6). Information form throughout: factor weight Ω = Σ⁻¹, whitening by Ω^{1/2} (Cholesky of Ω). g2o .g2o stores upper-triangular information; adapter handles it.

8.1 Lie groups SE(2)/SE(3)

SE(2): X = [[R(θ), t],[0, 1]], R(θ)=[[cosθ,−sinθ],[sinθ,cosθ]], t∈R². Tangent se(2)≅R³.

hat: ξ=(ρ_x,ρ_y,ϕ) ↦ [[0,−ϕ,ρ_x],[ϕ,0,ρ_y],[0,0,0]]
Exp(ξ): θ=ϕ; t = V(ϕ)·ρ,  V(ϕ)=(1/ϕ)[[sinϕ, −(1−cosϕ)],[(1−cosϕ), sinϕ]]  (ϕ→0: V→I)
Log(X): ϕ=atan2(R21,R11); ρ = V(ϕ)⁻¹ t
Adjoint Ad_X (3×3): rotates/translates a tangent between frames:
  Ad_X = [[R, [[t_y],[−t_x]]],[0(1×2), 1]]   (maps left to right perturbation)

SE(3): X=[[R, t],[0,1]], R∈SO(3), t∈R³. Tangent se(3)≅R⁶, ξ=(ρ,φ).

Exp(ξ): R=Exp_SO3(φ)=I + (sinθ/θ)[φ]_× + ((1−cosθ)/θ²)[φ]_×²  (θ=‖φ‖)
        t = V(φ)ρ,  V(φ)=I + ((1−cosθ)/θ²)[φ]_× + ((θ−sinθ)/θ³)[φ]_×²
Log: φ=Log_SO3(R); ρ=V(φ)⁻¹ t
Ad_X (6×6) = [[R, [t]_× R],[0, R]]
⊞: X·Exp(ξ);  ⊟: Log(X⁻¹ Y);  small-angle Taylor branch for θ<1e-8

Composition X1∘X2, inverse X⁻¹; right-Jacobian Jr(ξ) / left Jl(ξ) used in factor Jacobians and EKF.

8.4 EKF-SLAM

State μ = [x_R; m_1; … ; m_N] (robot pose + landmark positions); covariance Σ dense (3+2N)².

predict:  x_R⁻ = f(x_R, u);  Σ⁻ = G Σ Gᵀ + V Σ_u Vᵀ   (G = ∂f/∂x on robot block; landmarks unchanged)
augment (new landmark j first seen): μ_j = x_R⁻ ⊕ g(z);  Σ expanded with cross-covariance to all states
update (landmark j):  ẑ = h(x_R⁻, m_j);  y = z ⊟ ẑ (bearing wrapped)
          H = [∂h/∂x_R … ∂h/∂m_j …] (sparse rows, only robot + landmark j columns nonzero)
          S = H Σ⁻ Hᵀ + R;  K = Σ⁻ Hᵀ S⁻¹;  μ⁺ = μ⁻ + K y;  Σ⁺ Joseph
association (Mahalanobis): d²_jk = y_jkᵀ S_jk⁻¹ y_jk; pick min d²; gate d² ≤ χ²_{2,α}; else new/defer (I10)

Cost: update O(N) per landmark via sparse H, but covariance maintenance is O(N²) — the scaling wall (Scalability Analysis).

8.5 FastSLAM (Rao-Blackwellized PF)

Factorization: p(x_{1:t}, m | z_{1:t}, u_{1:t}) = p(x_{1:t}|z,u) · Π_k p(m_k | x_{1:t}, z). Each particle i carries a sampled trajectory and a map (grid-FastSLAM: per-particle occupancy grid; landmark-FastSLAM: per-landmark 2×2 EKFs).

proposal: x_t^i ~ q(x_t | x_{t−1}^i, u_t, z_t)   (motion model, or improved by scan match — GMapping)
weight:   w_t^i ∝ w_{t−1}^i · p(z_t | x_t^i, m^i)  (grid: beam/likelihood-field model; landmark: measurement likelihood w/ landmark EKF)
map update (grid): ray-cast scan into particle i's grid (log-odds);  (landmark): EKF update of observed landmark
normalize weights (Σw=1); N_eff = 1/Σ(w^i)²
resample if N_eff < N_thresh (e.g. N/2): low-variance / systematic resampling → duplicate high-weight particles + maps

Rao-Blackwellization: conditioning on the trajectory makes the per-landmark estimators independent → O(M·N) not O(N²); per-particle grids are the memory cost (Scalability Analysis). Seeded RNG → deterministic (I5).

8.6 Factor graph

Bipartite graph: variable nodes θ = {X_i (poses), m_k (landmarks)} on manifolds; factor nodes f_j (odometry, scan-match, landmark, loop, prior) each a probabilistic constraint over a small subset of variables. MAP estimate:

θ* = argmin_θ  Σ_j  ρ_j( ‖ r_j(θ) ‖²_{Ω_j} )      (ρ = robust kernel, identity for non-robust)
‖r‖²_Ω = rᵀ Ω r ;  whitened residual r̃ = Ω^{1/2} r  (Ω^{1/2} = Cholesky(Ω));  so cost = Σ ‖r̃_j‖²

Each factor exposes residual(θ), whiten(), and jacobian(θ) (∂r/∂ξ for each connected variable's tangent). The bipartite structure = the sparsity pattern of J (hence H=JᵀΩJ). .g2o import builds this graph.

8.7 Nonlinear least squares (the solver)

Linearize at current θ: r_j(θ⊞δ) ≈ r_j(θ) + J_j δ. Stack whitened: minimize ‖J̃ δ + r̃‖² → normal equations:

(JᵀΩJ) δ = −JᵀΩr      ⇔   H δ = b ,   H = Σ_j J_jᵀ Ω_j J_j (sparse, SPD with gauge prior),  b = −Σ_j J_jᵀ Ω_j r_j
Gauss-Newton:  solve H δ = b; update θ ← θ ⊞ δ; repeat until ‖δ‖,Δcost,‖b‖ < tol
Levenberg-Marquardt: solve (H + λ diag(H)) δ = b; if cost decreases accept + λ↓ (e.g. /3), else reject + λ↑ (×... )
sparse Cholesky: H = LLᵀ after fill-reducing permutation P (AMD/COLAMD): (PHPᵀ) = L̃L̃ᵀ; solve via P, L̃, back-subst
variable ordering: order landmarks before poses (or AMD) to control fill-in (I8)
Schur complement (landmark elimination): partition [[H_pp, H_pl],[H_lp, H_ll]] [δ_p; δ_l] = [b_p; b_l]
   reduced (pose) system: (H_pp − H_pl H_ll⁻¹ H_lp) δ_p = b_p − H_pl H_ll⁻¹ b_l   (H_ll block-diagonal → cheap inverse)
   back-substitute: δ_l = H_ll⁻¹ (b_l − H_lp δ_p)

Robust kernel ρ: applied via iteratively-reweighted least squares — weight w(e) = (1/e)·dρ/de scales Ω per factor each iteration.

Huber(δ_H):  ρ=½e² (|e|≤δ_H); =δ_H(|e|−½δ_H) else.  Cauchy(c): ρ=½c²log(1+e²/c²).  DCS(Φ): scales s=min(1, 2Φ/(Φ+e²))²

Hand-rolled wins on a tiny MCU target where you can drop the dependency and emit only the 3×3/6×6 kernels you use; ndarray wins if the surrounding code is already array-centric (signal processing).
3 Sparse linear algebra sprs CSC + first-party assembly Eigen-FFI, SuiteSparse-FFI, dense Pure-Rust CSC, deterministic; assemble H in CSC; FFI deps hurt reproducibility/build. SuiteSparse-FFI (CHOLMOD) wins at 10⁵–10⁶-pose graphs where supernodal BLAS-3 factorization is 5–10× the simplicial path; dense wins for graphs under ~50 variables where sparsity bookkeeping costs more than it saves.
4 Sparse Cholesky strategy First-party simplicial LDLᵀ/LLᵀ on CSC + AMD ordering CHOLMOD (SuiteSparse), dense Cholesky Teaches fill-in/ordering; no FFI; supernodal/CHOLMOD deferred perf option (§Performance Engineering). CHOLMOD wins once nnz(L) is large enough that supernodal BLAS-3 dominates (large/dense-loop graphs); dense Cholesky wins for the small reduced pose system after Schur when poses ≪ landmarks.
5 Fill-reducing ordering AMD (Approximate Minimum Degree); COLAMD for least-squares natural, RCM, METIS Standard for sparse Cholesky; controls fill-in (I8); METIS (nested dissection) deferred for huge graphs. Natural ordering wins for a pure chain (no loops) where AMD's overhead buys nothing; METIS/nested-dissection wins for very large, loop-dense graphs (10⁵+ poses) where AMD's greedy heuristic leaves too much fill.
6 Jacobians Analytic on-manifold (right perturbation) + finite-diff check; optional dual-number AD numeric-only, full symbolic Analytic = fast + exact; AD as a cross-check; numeric-only is slow/inaccurate. Numeric-only wins for a one-off factor whose analytic Jacobian is error-prone and not on the hot path; dual-number AD wins when factors change frequently in research and derivation cost dominates runtime (GTSAM Expressions, Ceres autodiff).
7 Manifold representation SE(2)/SE(3) own types, ⊞/⊟ retraction Euler/state-vector, matrix-only Principle 1; avoids wrap/gauge bugs; matches #285 quaternion convention. Euler/state-vector wins for a small-angle planar filter that never approaches gimbal lock and must interop with a legacy (x,y,θ) API; full 4×4-matrix state wins when composing long chains where staying in matrix form avoids repeated Exp/Log.
8 Perturbation convention Right (X·Exp(ξ)) left, mixed Single-sourced (§8.1); consistent Jacobians; mixing flips signs (catastrophic). Left perturbation (Exp(ξ)·X) wins when Jacobians are most naturally expressed in the world/global frame (some IMU-preintegration derivations); the choice is arbitrary — what matters is single-sourcing it.
9 RNG (FastSLAM) seeded rand_chacha (explicit seed in config/log) OS RNG, thread_rng Deterministic replay (I5); reproducible particle runs. OS RNG wins in a deployed system where unpredictability is a security property and replay is not required; thread_rng wins for a throwaway Monte-Carlo sweep where per-run reproducibility does not matter.
10 Scan matcher set ICP (pt-pt, pt-line), correlative, NDT behind ScanMatcher trait single matcher Differential testing + dataset-dependent choice; correlative robust to bad init, ICP precise. A single matcher wins on a tightly resource-constrained target with one well-characterized sensor/environment (e.g. correlative-only on a warehouse AMR) where the extra matchers are dead code and binary size matters.
11 Spatial index KD-tree (kiddo or first-party) for ICP correspondences + scan-context brute force, grid-only O(log n) nearest-neighbour; brute force O(n²) infeasible at scan size. Brute force wins for tiny scans (≤ ~50 points) where the KD-tree build cost exceeds a linear scan; a fixed grid/voxel index wins when points are uniformly dense and a constant-time bucket lookup beats tree descent (the correlative matcher's likelihood field is exactly this).
12 Serialization (graph/map) first-party LE binary + version header; .g2o import/export; TUM/KITTI for trajectories bincode-only, JSON hot path Compact + stable + interop; .g2o for differential tests vs g2o/GTSAM. JSON wins for a human-debuggable config/param-set file read once at startup (not the hot path); bincode alone wins for a closed system needing no cross-tool interop where you control both ends and never import .g2o.
13 Logging tracing (structured spans/levels) log, println Spans for frontend/solve/loop; correlate with replay. log wins for a library that must not impose a span model on its embedder; println/eprintln wins for a throwaway debugging spike where setting up a subscriber is pure overhead.
14 Tracing/spans tracing + tracing-subscriber (optional flamegraph) custom Per-phase timing; flamegraph for solver hot paths. A custom timing harness wins when you need cycle-accurate per-kernel counters (rdtsc) that a general span model cannot capture without distorting the measurement.
15 Metrics metrics crate (counters/gauges) custom global Scrape solver_cost, loop_*, nees, map_lag, timing. A custom global counter set wins on a no-allocation embedded target where the metrics registry's indirection and string keys are too costly; raw atomics suffice.
16 Unit testing cargo test + approx — Float-aware assertions for poses/Jacobians. n/a — approx is dominated for float-aware robotics tests; the only regime favouring bare assert_eq! is exact-integer logic (cell indices, ids), which cargo test already covers.
17 Property testing proptest quickcheck SE(n) round-trip, SPD, cost-decrease, association invariants. quickcheck wins if a shrinking strategy from a different ecosystem is needed, or for a team already standardized on it; the shrinking + stateful-model support of proptest is otherwise preferred.
18 Fuzzing cargo-fuzz/libFuzzer AFL Scan parser, .g2o parser, graph builder — no panic/NaN. AFL/AFL++ wins for deep coverage-guided campaigns on a parser that benefits from its mutation engine and persistent-mode forkserver, especially across non-Rust corpora shared with a C reference.
19 Differential testing vs g2o / GTSAM on .g2o graphs none Validate solver against reference optima; catch Jacobian/Schur errors. "None" wins only if no trusted reference exists for a novel factor type — then property tests + finite-diff Jacobians (Phase 7) are the fallback oracle; for standard pose graphs a reference always exists.
20 Benchmarking criterion (host) + datasets (Intel/Killian/TUM) with ATE/RPE ad hoc Statistical, regression-tracked; per-kernel + end-to-end. Ad-hoc timing wins for a quick one-off "is this 10× faster?" check during development where criterion's warmup + statistics cost more wall-clock than the answer is worth.
21 CI/CD GitHub Actions matrix (build, test, fmt, clippy, conformance, determinism, bench, fuzz) single job Enforce determinism + ATE/RPE thresholds + perf gates. A single job wins for a solo prototype where matrix parallelism adds YAML complexity without payoff; self-hosted runners win when conformance datasets are too large to fetch per-run on hosted CI.
22 Packaging Cargo workspace, 13 crates per §1.6 monolith Clear frontend/backend boundaries; reusable slam-lie/slam-solver. A monolith (single crate, modules) wins for a small closed application that will never reuse slam-lie/slam-solver externally and where 13-crate build-graph overhead and version churn are not worth the boundary.
23 Containers Dockerfile (CI repro) + docker-compose (replay + telemetry) k8s/orchestration Library + CLI, not a service; container only for reproducible runs. k8s/orchestration wins if SLAM is deployed as a fleet of long-lived mapping services (cloud map-building backend) rather than an embedded library — then scheduling, scaling, and rollout machinery earn their keep.
24 Reproducibility Pinned toolchain, Cargo.lock, fixed codegen flags (no FMA contraction), seeded RNG, fixed reduction order floating deps Bit-exact map/trajectory (I5). Floating deps / FMA-on wins when raw throughput matters more than bit-exactness — a production robot that needs the last few percent of FLOPs and validates by ATE bands, not hash equality.
25 Robust kernels Huber, Cauchy, DCS behind RobustKernel trait none, single kernel Outlier loop closures (Principle 4); DCS strong for false closures. No kernel wins when loop closures are pre-validated to be outlier-free (e.g. fiducial-marker constraints with a hard geometric lock) — a redescending kernel can then wrongly down-weight a correct, large-but-valid closure.
26 Loop-closure detection Scan-context ring descriptor + KD-tree bag-of-words (visual), brute-force scan match LiDAR-appropriate, rotation-invariant, cheap; deep place-recognition deferred (§10). Bag-of-words / learned descriptors win for a camera-based (visual) frontend where appearance is rich (ORB-SLAM's DBoW2); brute-force scan match wins for a tiny map where exhaustive comparison is cheaper than maintaining a descriptor index.
27 Map representation Occupancy grid (log-odds) + landmark map + pose graph TSDF, NDT-map only Standard 2D; log-odds clamped (I12); rebuildable from trajectory. TSDF wins for dense 3D surface reconstruction (RGB-D, KinectFusion-style) where a signed-distance field beats binary occupancy; an NDT-map wins for 3D LiDAR registration where Gaussian-per-voxel is the native matching primitive.
28 Solver algorithm default Levenberg-Marquardt (GN available) GN-only, dogleg LM robust to poor init / bad linearization; GN faster near optimum; dogleg deferred. GN-only wins when the initial guess is always near the optimum (incremental online solve with good frontend init) and LM's damping just slows convergence; dogleg wins when an explicit trust-region radius is preferable to LM's implicit λ for very nonlinear problems.
29 Licensing Apache-2.0 OR MIT GPL Permissive for robotics reuse. GPL/AGPL wins when the goal is to force downstream contributions back (a copyleft research consortium) rather than maximize permissive reuse.
30 Visualization slamctl exports PNG/SVG of grid + trajectory + graph (no GUI dep in core) egui/Pangolin runtime Headless-friendly, CI-renderable; interactive viewer is a Phase-1+ tool. A live egui/Pangolin viewer wins for interactive debugging and demos where panning the map and stepping the graph in real time is the whole point, and a GUI dependency in a tool crate (not core) is acceptable.

    const DOF: usize;

}

1.1 Objectives

1.2 Detailed Implementation Steps

  • so2.rs: angle wrap, Exp/Log (trivial), matrix form.
  • so3.rs: Hamilton quaternion (scalar-first), Exp/Log with small-angle Taylor branch (θ<1e-8), to_rotation_matrix, right_jacobian_so3 (Jr) + inverse, renormalize (I1).
  • se2.rs: Exp/Log via V(ϕ) closed form (§8.1), compose, inverse, adjoint (3×3), boxplus/boxminus.
  • se3.rs: Exp/Log via V(φ) (§8.1), adjoint (6×6), composition, boxplus/boxminus.
  • jacobian.rs: right/left Jacobians; helper to build ∂(X⁻¹Y)/∂ξ blocks used by odometry/loop factors.
  • tools/jac_check wired: central finite-difference check of Exp/Log/relative-pose Jacobians.

1.3 Deliverable

  • Lie-group crate: SE(2)/SE(3) algebra validated against reference (Sophus-style) values; finite-diff Jacobians pass.

1.4 Acceptance Criteria

  • Log(Exp(ξ))=ξ for ‖ξ‖<π (1e-10 f64). X∘X⁻¹=I (1e-12). SO(3) R orthonormal, det=+1; quaternion |q|=1 after 10⁶ random ⊞ (<1e-9 deviation, I1). adjoint satisfies Exp(Ad_X ξ)=X Exp(ξ) X⁻¹ (1e-9). All Jacobian finite-diff errors <1e-5. No heap alloc.

1.5 Conformance Fixtures

  • tests/exp_log.rs: near-zero and near-π angles (small-angle branch). adjoint.rs: adjoint identity. boxplus.rs: (X⊞ξ)⊟X = ξ. jac_fd.rs: relative-pose residual Jacobian vs finite diff. Degenerate: ξ=0 (identity), θ=π (sign canonicalization).

1.6 Pitfalls

  • Right vs left perturbation drift across modules → inverted/inconsistent Jacobians. Manifestation: solver fails to converge or converges to wrong pose. Detect: boxplus round-trip + differential vs reference. Recovery: single-sourced convention (ADR 8), property test everywhere.
  • Small-angle singularity in V(ϕ)⁻¹/Jr at θ→0. Detect: near-zero fixture. Recovery: Taylor branch.
  • Quaternion double cover (q vs −q) → discontinuous Log. Detect: Log continuity test. Recovery: canonicalize w≥0.
  • SE(2) V(ϕ) form error (off-diagonal sign) → translation error after rotation. Detect: Exp/Log round-trip on pure-rotation+translation. Recovery: re-derive from §8.1.

1.7 Performance Concerns

  • Exp/Log cost dominated by sin/cos; called per factor linearization. Cache rotation matrices per variable per iteration. SE(2) is cheap (one angle); SE(3) heavier (quaternion + V(φ)). Fixed-size matrices fit L1; no dynamic dispatch in the hot Jacobian path.

1.8 Edge Cases

  • θ=π (rotation by 180°, axis ambiguity). Antipodal quaternions. Very large ξ (gate should prevent, but Exp must stay valid). NaN input → propagate, flagged by callers.

1.9 Failure Analysis

  • A convention/Jacobian bug here is the single most damaging class (silent, plausible drift everywhere downstream). Detection: differential test vs an independent Lie library (CI). Containment: most-tested crate; exhaustive property tests; no per-call convention inference.

Phase 3 — Scan Matching (ICP point-to-point / point-to-line, Correlative, NDT)

3.1 Objectives

  • slam-match: three scan matchers behind ScanMatcher, each returning relative SE(2) + information matrix (Principle 10). ICP (point-to-point + point-to-line / PLICP), correlative (multi-resolution likelihood-field search), NDT (cell Gaussians + Newton). KD-tree for correspondences.

3.2 Detailed Implementation Steps

  • kdtree.rs: 2D KD-tree over target endpoints for nearest-neighbour correspondence.
  • icp.rs: iterate {associate nearest points → solve closed-form SE(2) (point-to-point: centroid + SVD/atan2 of cross-covariance) → apply → check convergence}; reject correspondences beyond a distance gate; information from residual covariance / Hessian at convergence.
  • plicp.rs: point-to-line ICP (Censi) — residual is point-to-line distance using local surface normals; linear least-squares per iteration; better convergence in structured (wall) environments.
  • correlative.rs: build a likelihood field (distance transform) from target; exhaustive search over a translation+rotation window at coarse resolution → refine at fine resolution (multi-resolution / branch-and-bound style); score = sum of beam likelihoods; information from score curvature.
  • ndt.rs: discretize target into cells, fit a 2D Gaussian per cell; score source points against cell Gaussians; Newton/Gauss-Newton step on SE(2); information from the score Hessian.
  • All matchers: match_scan(source, target, init) -> MatchResult{rel_pose, information, score, iters, converged}.

3.3 Deliverable

  • Three matchers producing relative-pose estimates + information on synthetic and real scan pairs; slamctl can match two scans and report transform + info.

3.4 Acceptance Criteria

  • On synthetic scan pairs with known transform (≤0.5 m, ≤20° apart): ICP recovers translation within 2 cm, rotation within 0.5° (clean data). Correlative recovers correct cell within window even from a poor init (robust to 0.3 m / 15° initial error). NDT matches ICP accuracy on structured scenes. Information matrix is SPD and reflects geometry (under-constrained directions → low information, e.g. corridor longitudinal axis). Matcher converges within max_iters or reports converged=false.

3.5 Conformance Fixtures

  • tests/icp.rs: known-transform recovery; correlative.rs: poor-init recovery; ndt.rs: structured-scene accuracy; info.rs: corridor scan → anisotropic information (low along corridor). Degenerate: identical scans (zero transform, high info), featureless scan (low info, slides), 50% overlap (partial), rotation-only.

3.6 Pitfalls

  • ICP local minimum from poor init → wrong transform that "looks" converged. Manifestation: jump in trajectory. Detect: residual + score sanity; correlative as init. Recovery: multi-start / correlative-then-ICP; gate by residual.
  • Wrong correspondences (associate across a gap) → biased pose. Detect: correspondence distance gate. Recovery: reject outlier correspondences (trimmed ICP).
  • Information from too-few correspondences → over-confident edge. Detect: correspondence count vs DOF. Recovery: floor information; require minimum overlap.
  • Corridor / aperture degeneracy → matcher slides along the unconstrained axis. Manifestation: longitudinal drift. Detect: information eigenvalue ratio. Recovery: report anisotropic info; back-end weights accordingly (I11).
  • NDT cell discretization artifacts (scan near cell boundary) → score discontinuity. Detect: boundary fixture. Recovery: cell overlap / smoothing.

3.7 Performance Concerns

  • ICP correspondence search is the cost: KD-tree O(n log n) per iteration; cache the target tree. Correlative is O(window × beams) — the most expensive; multi-resolution / branch-and-bound prunes; this matcher dominates the per-scan budget at 20 Hz (§4). NDT score is O(points) per iteration once cells are built. Precompute distance transform / cell Gaussians once per target.

3.8 Edge Cases

  • No overlap (matcher fails → reject, dead-reckon). Highly dynamic scene (moving objects → outlier correspondences; trimmed ICP). Very large initial error (beyond correlative window → fail + flag). Symmetric scan (multiple equal-score poses → low confidence, report).

3.9 Failure Analysis

  • A silently-wrong match injects a bad odometry/loop edge — the back-end then "trusts" it. Detection: information-weighted residual at the back-end; differential between matchers on the same pair. Containment: matcher returns converged/info; pipeline gates low-confidence matches. Forensic: log source/target/init/result + score.

3.10 Operational Notes

  • Metrics: match_iters, match_score, match_converged_ratio, match_info_cond. Matcher choice is config (per dataset). Correlative window + resolutions are versioned params. Document the correlative→ICP refinement pipeline in a runbook.

4.1 Objectives

  • slam-odom: odometry model (rot1-trans-rot2) and velocity model (v, ω) with calibrated noise; predicted mean + covariance (for EKF) and sampling (for FastSLAM); dead-reckoning baseline; noise propagation through SE(2).

4.2 Detailed Implementation Steps

  • odometry_model.rs: decompose relative motion into (δ_rot1, δ_trans, δ_rot2) (Thrun Probabilistic Robotics ch.5 odometry motion model); predict → new pose + covariance Σ via Jacobian of the composition w.r.t noise (α[0..3] noise params, §8.2); sample → draw noisy components, compose on the right (right perturbation, ADR 8).
  • velocity_model.rs: arc model (v, ω) with θ→0 straight-line branch (Thrun ch.5 velocity motion model); covariance from α[0..6].
  • dead_reckon.rs: integrate odometry only → trajectory + growing covariance (the no-SLAM baseline; used to quantify SLAM improvement).
  • noise.rs: map encoder/odometry noise to α params; covariance composition through ⊞ (right Jacobian of SE(2), §8.1; Principle 1).
  • Finite-diff check of motion Jacobian G=∂f/∂x and noise Jacobian V=∂f/∂w.

4.3 Deliverable

  • Motion models producing prediction + covariance + samples; dead-reckoning trajectory on a dataset with characterized drift.

4.4 Acceptance Criteria

  • Dead reckoning on a synthetic loop accumulates drift consistent with injected noise (within 10% of Monte-Carlo expectation). predict covariance matches sampled covariance over 10⁴ samples (within 5%). Motion + noise Jacobians finite-diff <1e-5. Sampling is seeded → deterministic. Straight-line branch (ω→0) is continuous with the arc model.

4.5 Conformance Fixtures

  • tests/odometry.rs: predicted vs sampled covariance; velocity.rs: arc vs straight-line continuity at ω→0. Fixtures: synthetic/corridor.spec dead-reckon drift. Degenerate: zero motion (covariance unchanged), pure rotation (translation noise coupling), pure translation.

4.6 Pitfalls

  • Covariance composition on the wrong side (left vs right Jacobian) → mis-scaled uncertainty. Manifestation: EKF over/under-confident, NEES off. Detect: predict-vs-sample covariance test. Recovery: right Jacobian of SE(2) (§8.1), consistent with ADR 8.
  • δ_rot1 ambiguity when δ_trans≈0 (pure rotation → undefined bearing). Detect: pure-rotation fixture. Recovery: guard small δ_trans, attribute rotation to δ_rot1+δ_rot2 split.
  • Velocity-model singularity at ω=0 (division by ω). Detect: continuity test. Recovery: Taylor/straight-line branch.
  • Unseeded sampling breaks determinism. Detect: replay-hash CI. Recovery: explicit RNG seed (I5).

4.7 Performance Concerns

  • Cheap (a few SE(2) ops + a 3×3 Jacobian per predict). Sampling cost = n_particles draws per step (FastSLAM). Covariance composition is O(1) (3×3). No bottleneck; correctness-dominated.

4.8 Edge Cases

  • Backward motion (δ_trans<0 sign convention). Wraparound in δ_rot (±π). Huge slip (odometry jump) — flagged to be gated against scan match (Phase 11). Zero-time-delta odometry (duplicate).

4.9 Failure Analysis

  • A mis-calibrated motion noise model silently makes the EKF inconsistent (over-trusting odometry). Detection: NEES (Phase 5) + dead-reckon-vs-truth drift. Forensic: per-step predicted covariance log.

4.10 Operational Notes

  • Metrics: dead_reckon_drift, predict_cov_trace. α noise params are versioned config (per robot). Document calibration of α from wheel-odometry data; cross-link #285 (its fused estimate can seed odometry here).

Phase 5 — EKF-SLAM (Landmark, Augmentation, Predict/Update, Mahalanobis Data Association)

5.1 Objectives

  • slam-ekf: full EKF-SLAM — single Gaussian over robot pose + landmark map; state augmentation on first observation; predict via motion Jacobian; range-bearing update; Mahalanobis nearest-neighbour data association with χ² gating (I10). Establish the filter back-end + consistency monitoring.

5.2 Detailed Implementation Steps

  • ekf_slam.rs: state μ=[x_R; m_1…m_N], dense Σ; SPD enforcement (Joseph + symmetrize, I2).
  • predict.rs: robot-block predict (motion model from Phase 4); Σ⁻=GΣGᵀ+VΣ_uVᵀ with G acting on the robot block only (landmarks static); landmark cross-covariance preserved.
  • augment.rs: on a new (gated-as-new) observation, initialize landmark m_j=x_R⊕g(z); expand Σ with correct cross-covariance to robot + existing landmarks (inverse measurement Jacobian).
  • update.rs: range-bearing h, sparse H (nonzero only on robot + observed landmark columns), S=HΣ⁻Hᵀ+R, K=Σ⁻HᵀS⁻¹ (Cholesky solve, I11), Joseph update; bearing residual wrapped.
  • association.rs: for each observation, compute Mahalanobis d² to each candidate landmark; nearest-neighbour; gate d²≤χ²_{2,α} (e.g. 0.99); below gate → associate, above for all → new landmark, ambiguous (two within gate) → defer (I10).
  • consistency.rs: NEES vs ground truth (test); NIS online; divergence flag (I4).

5.3 Deliverable

  • EKF-SLAM running on a synthetic landmark world (and a small real dataset) producing pose + landmark map with covariances; examples/ekf_slam_landmarks.rs.

5.4 Acceptance Criteria

  • On synthetic landmark world (known map, range-bearing obs): final landmark RMSE < 0.1 m, pose ATE < 0.2 m after loop. NEES within χ²(3) 95% bounds over 50 Monte-Carlo runs (consistent filter, I4). Covariance SPD throughout (I2). Association false-match rate < 1% at 0.99 gate. Augmentation cross-covariance correct (differential vs batch). Bearing wrap handled (no ±π jumps).

5.5 Conformance Fixtures

  • tests/predict.rs: covariance growth; update.rs: single-landmark update vs hand-computed; assoc.rs: gated association accept/reject rates; consistency.rs: 50-run NEES. Fixtures: synthetic/grid_world.spec (landmarks). Degenerate: two landmarks within gate (defer), no observations (predict-only growth), first observation of every landmark (all augment).

5.6 Pitfalls

  • Wrong augmentation cross-covariance → landmarks uncorrelated with pose → over-confident, NEES collapse. Manifestation: optimistic map then divergence. Detect: NEES; differential vs batch init. Recovery: correct inverse-measurement Jacobian for the cross-covariance block.
  • Data-association error (associate to wrong landmark) → map corruption, slow divergence. Manifestation: landmarks drift/merge. Detect: NEES + association log. Recovery: tighter gate; conservative new-landmark threshold (Principle 5).
  • Non-Joseph update drifts Σ non-PD. Detect: SPD probe (I2). Recovery: Joseph + symmetrize.
  • O(N²) covariance cost ignored → real-time miss at scale. Detect: timing vs landmark count. Recovery: document wall; sparse-information variants / switch to graph back-end (Scalability Analysis).
  • Bearing innovation not wrapped → spurious huge innovation at ±π → rejected valid obs. Detect: heading-crossing fixture. Recovery: wrap to (−π,π].

5.7 Performance Concerns

  • Update is O(N) per landmark (sparse H) but covariance maintenance and prediction touch the full (3+2N)² matrix → O(N²) memory and per-step cost. This is the EKF scaling wall (Scalability Analysis). Cache the robot-block Jacobian; exploit H sparsity; batch synchronous observations. Dense Σ is the dominant memory term.

5.8 Edge Cases

  • Landmark observed once then never again (stale, retained). Spurious landmark from noise (culling policy). Robot revisits a landmark after long loop (large but valid innovation — must pass gate). Negative range / NaN observation (reject). All observations are new (mass augmentation).

5.9 Failure Analysis

  • EKF-SLAM's classic failures are association errors and over-confidence (linearization + augmentation). Detection: NEES soak + association decision log. Containment: per-observation gating; degrade not crash. Forensic: log μ,Σ trace, association d², innovation per update; replay.

5.10 Operational Notes

  • Metrics: n_landmarks, assoc_gated/assoc_accepted, nis, nees(test), cov_trace, sigma_bytes. Gate threshold + new-landmark threshold are versioned config. Runbook filter_divergence.md. Document when to prefer the graph back-end (large maps).

Phase 6 — FastSLAM / Rao-Blackwellized Particle Filter (Proposal, Weights, Resampling, Per-Particle Grid)

6.1 Objectives

  • slam-pf: grid-based FastSLAM (RBPF) — particles carrying trajectory + per-particle occupancy grid; proposal from improved motion model (scan-match refined, GMapping-style); importance weights from the measurement likelihood; adaptive resampling on effective sample size (I14). Landmark-FastSLAM variant (per-particle landmark EKFs) as an alternative.

6.2 Detailed Implementation Steps

  • particle.rs: Particle{trajectory, pose, map: OccupancyGrid, weight} (FastSLAM factorization, Montemerlo et al. 2002, §8.5); clone-on-resample (copy-on-write grid where feasible to bound memory).
  • proposal.rs: sample next pose from motion model; improved proposal — scan-match the new scan against the particle's map to focus the proposal around the likelihood peak (Grisetti et al. 2007 GMapping); fall back to raw motion model if match fails.
  • weight.rs: w ∝ p(z|x,m) via the beam/likelihood-field model against the particle's grid; normalize (Σw=1, I14).
  • resample.rs: low-variance / systematic resampling (Thrun Probabilistic Robotics ch.4); trigger when N_eff=1/Σw² < N_thresh (e.g. N/2, GMapping adaptive resampling); duplicate high-weight particles (and their maps).
  • fastslam.rs: step(u, scan) = propose → weight → integrate scan into each particle's grid → normalize → resample-if-needed; best() = max-weight particle; seeded RNG (I5).
  • Landmark variant: per-particle per-landmark 2×2 EKFs (Rao-Blackwellized), weight from landmark measurement likelihood.

6.3 Deliverable

  • Grid FastSLAM producing a consistent map + trajectory on a synthetic scan stream and a small real dataset; examples/fastslam_grid.rs; deterministic given seed.

6.4 Acceptance Criteria

  • On a synthetic loop, the best-particle map matches ground truth (≥90% IoU) and trajectory ATE < 0.3 m after loop, with N≥50 particles. N_eff tracked; resampling occurs and recovers diversity. Deterministic: identical map/trajectory across runs given seed (I5). Improved proposal reduces required particles vs raw motion model by ≥2× for the same accuracy. Weights normalized (|Σw−1|<1e-9).

6.5 Conformance Fixtures

  • tests/proposal.rs: improved vs raw proposal particle efficiency; resample.rs: systematic resampling preserves Σw and reduces variance; neff.rs: N_eff computed correctly. Fixtures: synthetic/loop3.spec, corridor.spec. Degenerate: all-equal weights (no resample), single dominant particle (depletion → trigger), featureless region (proposal falls back to motion).

6.6 Pitfalls

  • Particle depletion (weight collapses to one particle) → map locked, can't recover from error. Manifestation: N_eff→1, no diversity. Detect: N_eff telemetry (I14). Recovery: improved proposal, adaptive resampling, more particles; never resample every step (destroys diversity).
  • Resampling too often → loss of trajectory diversity (sample impoverishment). Detect: trajectory variance collapse. Recovery: resample only on low N_eff.
  • Per-particle grid memory blowup (N grids × extent). Manifestation: OOM at scale. Detect: map_bytes × N. Recovery: copy-on-write / shared ancestry grids; cap N × extent (Scalability Analysis).
  • Weight from wrong sensor model (mismatched p_hit σ) → mis-ranked particles. Detect: weight distribution vs expected. Recovery: calibrate beam model.
  • Non-deterministic resampling (unseeded / unstable sort) → unreproducible. Detect: replay hash. Recovery: seeded systematic resampling, stable tie-break.

6.7 Performance Concerns

  • Cost = N × (proposal scan-match + scan integration into grid); the per-particle scan match dominates (improved proposal). Memory = N × per-particle grid — the dominant term; copy-on-write grids on resample cut copies. Per-particle work is embarrassingly parallel (optional rayon). Cache the likelihood field per particle map.

6.8 Edge Cases

  • First step (all particles at origin, uniform weight). Long featureless stretch (proposal = motion model, weights flat). Loop closure (FastSLAM closes loops implicitly via particle diversity — limited; explicit closure is the graph back-end's job). Resample with degenerate weights (one nonzero).

6.9 Failure Analysis

  • FastSLAM's signature failure is particle depletion (the filter becomes overconfident in a single wrong trajectory). Detection: N_eff + map-divergence-between-particles. Containment: adaptive resampling + improved proposal; bounded particles. Forensic: log N_eff, weight histogram, best-particle id, seed; replay.

6.10 Operational Notes

  • Metrics: n_particles, n_eff, resample_total, best_weight, map_bytes_total. Particle count + N_thresh are versioned config. Seed recorded in every log (reproducibility). Runbook particle_depletion.md. Document grid-vs-landmark FastSLAM tradeoff (memory vs landmark observability).

7.1 Objectives

7.2 Detailed Implementation Steps

  • variable.rs: Variable enum over manifold types; VarId; Values map (current estimate θ).

  • factors/prior.rs: prior (gauge anchor, I3) r=Log(X₀^{prior,−1} X₀).

  • whiten.rs: Ω^{1/2}=Cholesky(Ω); whitened residual r̃=Ω^{1/2} r, whitened Jacobian J̃=Ω^{1/2} J (so the solver minimizes plain Σ‖r̃‖²).
  • g2o.rs: parse/emit VERTEX_SE2, EDGE_SE2, VERTEX_SE3:QUAT, EDGE_SE3:QUAT with upper-triangular information; build FactorGraph+Values.
  • Finite-diff check of every factor's Jacobians (mandatory, CONTRIBUTING).

7.3 Deliverable

  • Factor graph that loads a .g2o file, evaluates total cost + residuals, and exposes the sparse structure (variable↔factor incidence); examples/pose_graph_g2o.rs reports initial cost.

7.4 Acceptance Criteria

  • .g2o round-trip (read→write→read) is byte-stable (modulo float formatting tolerance). Total cost on a known graph matches a hand/g2o-computed value (1e-6). Every factor's analytic Jacobian matches finite diff <1e-5. Whitening: r̃ᵀr̃ = rᵀΩr (1e-9). Information matrix from .g2o upper-triangular is reconstructed SPD. Bearing residuals wrapped.

7.5 Conformance Fixtures

  • tests/graph.rs: cost evaluation on loop3; factors_fd.rs: per-factor Jacobian finite-diff; g2o_io.rs: round-trip on manhattan.g2o. Degenerate: graph with no prior (flag gauge-unanchored, I3), duplicate edge, self-loop edge (reject), .g2o with malformed line (parse error, not panic).

7.6 Pitfalls

  • Information vs covariance confusion (g2o stores information; using it as covariance squares the weight). Manifestation: wildly over/under-weighted edges. Detect: cost vs reference. Recovery: documented adapter; .g2o = information.
  • Jacobian w.r.t the wrong variable's tangent (left vs right, or i/j swapped). Manifestation: solver diverges/oscillates. Detect: finite-diff per factor (mandatory). Recovery: derive via adjoint (§8.1), test.
  • Whitening with Ω not SPD → Cholesky fails. Detect: SPD probe. Recovery: validate Ω on factor construction.
  • Unwrapped bearing/heading residual → discontinuity at ±π. Detect: heading-crossing factor test. Recovery: wrap.
  • .g2o parser trust (huge indices, NaN info). Detect: fuzz g2o_parse. Recovery: bounds + NaN checks, reject.

7.7 Performance Concerns

  • Residual + Jacobian evaluation is per-factor per-iteration — the linearization cost. Cache rotation matrices per variable per iteration (shared across incident factors). The incidence structure (built once unless topology changes) defines J's sparsity. Avoid allocating Jacobian blocks per call (reuse scratch).

7.8 Edge Cases

  • Factor touching a variable not in Values (error). Mixed SE(2)/SE(3) graph (reject or namespace). Empty graph (no-op solve). Single variable + prior (trivial). Very high factor degree on one variable (loop hub — dense H row).

7.9 Failure Analysis

  • A Jacobian or information error here makes the solver (Phase 8) silently converge to a wrong optimum. Detection: mandatory per-factor finite-diff gate + differential vs g2o on .g2o graphs. Containment: factors are pure (residual has no side effects), unit-testable in isolation. Forensic: per-factor residual/Jacobian dump.

7.10 Operational Notes

  • Metrics: n_variables, n_factors, total_cost, gauge_anchored. .g2o format support is a compatibility surface (semver). New factor types are additive (minor). Document the information convention prominently. Graph renderable via graphviz tool for inspection.

Phase 8 — Sparse Nonlinear Least Squares Solver (Gauss-Newton, LM, Sparse Cholesky, Ordering, Schur)

8.1 Objectives

  • slam-solver: the mathematical core — linearize the factor graph, assemble sparse H=JᵀΩJ, b=−JᵀΩr, solve Hδ=b via sparse Cholesky with AMD ordering, iterate with Gauss-Newton and Levenberg-Marquardt (default), optional Schur complement on landmarks; convergence monitoring (I7). Differential-tested against g2o/GTSAM.

8.2 Detailed Implementation Steps

  • linearize.rs: for each factor, evaluate whitened residual + Jacobian; scatter into a sparse J (or directly accumulate H blocks); build b.
  • sparse_cholesky.rs: simplicial LDLᵀ/LLᵀ on CSC; symbolic factorization (elimination tree, fill pattern) + numeric factorization; triangular solves; PD check (I2).
  • ordering.rs: AMD (Approximate Minimum Degree) permutation to reduce fill-in (I8); COLAMD option; cache symbolic factor when topology is unchanged.
  • gauss_newton.rs: solve Hδ=b, update θ←θ⊞δ, repeat until ‖δ‖/Δcost/‖b‖ < tol or max iters; detect cost increase (GN can diverge) → report.
  • levenberg.rs: solve (H+λ·diag(H))δ=b; accept if cost decreases (λ←λ/3), reject + retry with larger λ (×… ) otherwise; trust-region behavior; default solver (ADR 28).
  • schur.rs: partition variables into poses p + landmarks l; form reduced system (H_pp−H_pl H_ll⁻¹ H_lp)δ_p=… (block-diagonal H_ll → cheap inverse), back-substitute δ_l (§8.7).
  • robust.rs: IRLS — per-iteration reweight Ω by w(e²) from the factor's robust kernel (Phase 9 supplies kernels; wiring here).
  • solver.rs: Solver trait; optimize(graph, values)→SolveReport{iters, initial_cost, final_cost, grad_norm, converged}.

8.3 Deliverable

  • Sparse NLS solver optimizing a .g2o pose graph to the reference optimum; slamctl optimize graph.g2o reports cost trajectory + converged map; Schur path for pose-landmark graphs.

8.4 Acceptance Criteria

  • On standard .g2o graphs (manhattan, sphere2500): final cost matches g2o/GTSAM within 1e-3 relative; converges in comparable iteration count. Cost decreases monotonically under LM (I7); GN converges on well-conditioned graphs. Sparse Cholesky with AMD produces materially less fill-in than natural ordering (measured nnz(L) ratio, I8). Schur path matches direct solve (1e-6) and is faster on landmark-heavy graphs. H SPD with gauge prior; rank-deficient (no prior) is detected + reported (I3). Deterministic (fixed reduction order, I5).

8.5 Conformance Fixtures

  • tests/gn.rs: GN on a well-conditioned graph vs closed form; lm.rs: LM recovers from poor init where GN diverges; cholesky.rs: sparse LLᵀ reconstructs H (1e-10) + PD detection; schur.rs: Schur vs direct equivalence + fill comparison; diff_g2o.rs: final cost vs g2o on manhattan/sphere2500. Deferred: iSAM2 incremental Bayes-tree solve → PhaseDeferred("FINAL_BLUEPRINT §8"). Visual bundle adjustment (camera+points Schur) → PhaseDeferred("FINAL_BLUEPRINT §8.5"). Degenerate: unanchored graph (rank deficiency), single-iteration converged graph, near-singular H (high condition number).

8.6 Pitfalls

  • Bad fill-reducing ordering → catastrophic fill-in, O(n³) solve. Manifestation: solve time explodes with loops. Detect: nnz(L) vs nnz(H) (I8). Recovery: AMD/COLAMD; nested dissection (METIS) deferred for huge graphs.
  • Missing gauge anchor → singular H, Cholesky fails. Detect: PD probe → report null-space (I3). Recovery: require a prior; or fix the first variable.
  • GN divergence on poor init (step overshoots). Manifestation: cost increases, oscillation. Detect: cost monitor (I7). Recovery: use LM (damping); good init from frontend.
  • LM λ mistuning → too-small steps (slow) or rejected steps (stall). Detect: iteration/λ log. Recovery: adaptive λ schedule; diag(H) scaling.
  • Schur with non-block-diagonal H_ll (landmarks sharing factors) → H_ll⁻¹ not cheap. Detect: H_ll structure check. Recovery: only Schur truly-independent landmarks; else direct.
  • Float reduction-order nondeterminism in sparse accumulation → solve hash drift. Detect: determinism CI. Recovery: fixed accumulation order (sorted indices), no FMA.

8.7 Performance Concerns

  • Dominant cost = numeric Cholesky O(fill); ordering quality determines it (I8). Symbolic factorization cached across iterations (topology fixed). Linearization is O(factors) and parallelizable. Schur trades a dense reduced pose system for cheap landmark elimination — wins when landmarks ≫ poses. Memory = nnz(H)+nnz(L). Tail latency: a loop closure that re-densifies H spikes the solve; bounded by ordering + window (Scalability Analysis).

8.8 Edge Cases

  • Disconnected graph (multiple components → each needs an anchor). Single huge loop (dense corner block). Numerically near-singular H (regularize / report condition). Zero-residual graph (converged at init). Iteration cap hit without convergence (report converged=false, keep best).

8.9 Failure Analysis

  • The solver returning a confidently wrong optimum (bad Jacobian upstream, bad ordering, undetected non-convergence) is the worst case — the map looks optimized but is wrong. Detection: differential vs g2o/GTSAM; cost + grad monitoring (I7). Containment: keep previous Values on non-convergence; never publish a diverged solve. Forensic: per-iteration cost/grad/λ/nnz(L); replay the graph.

8.10 Operational Notes

  • Metrics: solver_cost (initial/final), grad_norm, iters, lambda, H_nnz, fill_in_ratio, solve_ms, converged. Solver algorithm + tolerances + ordering are versioned config. Runbook solver_nonconvergence.md. Differential test against g2o is a standing CI gate (differential.yml).

Phase 9 — Pose-Graph Optimization (2D/3D) + Robust Kernels (Huber/Cauchy/DCS)

9.1 Objectives

  • Pose-graph SLAM end-to-end: build a pose graph from frontend constraints (odometry + scan-match between-pose factors), optimize with the Phase-8 solver, and make it robust to outlier (false) loop-closure edges via Huber/Cauchy/DCS kernels (Principle 4). Both SE(2) (primary) and SE(3) (substrate).

9.2 Detailed Implementation Steps

  • Assemble a pure pose graph (no landmarks): vertices = keyframe poses, edges = odometry (sequential) + loop-closure (non-sequential) between-pose factors, with information from the scan matcher (Phase 3) — the globally-consistent-pose-graph formulation of Lu & Milios 1997.
  • robust.rs kernels (in slam-solver): Huber{δ}, Cauchy{c}, Dcs{Φ} implementing RobustKernel::weight(e²) for IRLS (§8.7; DCS from Agarwal et al. 2013); applied only to loop-closure factors by default (Principle 4).
  • Wire robust reweighting into the GN/LM iteration: each iteration recompute per-loop-factor weight from current residual, scale Ω, re-solve. Switchable-constraints (Sünderhauf & Protzel 2012) is the alternative outlier model considered.
  • Optimize: anchor gauge (prior on first pose), run LM, monitor cost/convergence (I7).
  • 3D: same factors over SE(3) (6-DOF) — validate on a 3D .g2o (sphere2500).
  • Outlier-robustness experiment: inject false loop closures; confirm robust kernels suppress them (DCS strongest).

9.3 Deliverable

  • A pose-graph optimizer producing a globally consistent trajectory from odometry + loop closures, robust to a fraction of false closures; works on 2D and 3D .g2o.

9.4 Acceptance Criteria

  • On manhattan (2D) and sphere2500 (3D): optimized ATE within reference band (per-graph thresholds). With 10% injected false loop closures: non-robust solve corrupts the map (ATE blows up); robust (DCS/Cauchy) keeps ATE within ~1.5× of the clean optimum. Robust IRLS converges (I7). Gauge anchored (I3). SE(2) and SE(3) both pass. Deterministic.

9.5 Conformance Fixtures

  • tests/robust.rs: Huber/Cauchy/DCS weight functions vs analytic; false-closure suppression (clean vs poisoned graph, robust vs non-robust ATE). Fixtures: g2o/manhattan.g2o, g2o/sphere2500.g2o, synthetic/loop3.spec with an injected wrong loop. Degenerate: all-outlier loops (robust holds odometry backbone), no loops (chain → odometry only), conflicting loops (consistency).

9.6 Pitfalls

  • Robust kernel applied to odometry (not just loops) → backbone under-weighted, drift. Detect: ATE vs kernel scope. Recovery: robustify only loop-closure factors.
  • Kernel threshold mistuned (δ/c/Φ too large → no robustness; too small → rejects valid loops). Detect: false-closure-suppression fixture sweep. Recovery: scale threshold to expected residual / use DCS (self-scaling).
  • IRLS oscillation (weights flip-flop) → non-convergence. Detect: cost/weight oscillation. Recovery: damping, weight smoothing, DCS continuity.
  • Single strong false closure still folds map under Huber (Huber is only mildly robust). Detect: ATE under poisoning. Recovery: Cauchy/DCS (redescending influence) for strong outliers.
  • Gauge drift in 3D (SE(3) 6-DOF null space) without anchor. Detect: PD probe (I3). Recovery: prior on first pose.

9.7 Performance Concerns

  • Robust IRLS adds a reweight + re-solve per iteration (the solve dominates). DCS/Cauchy are O(1) per factor. Loop closures densify H (non-sequential edges) → fill-in (I8); ordering matters most here. 3D doubles DOF per pose (3→6) → larger blocks, more fill.

9.8 Edge Cases

  • A correct loop with large-but-valid residual (down-weighted by an over-aggressive kernel → loop not closed). Many loops to one hub (dense row). Loop between very distant poses (large correction). Conflicting loops (two closures disagree → robust resolves toward majority/odometry).

9.9 Failure Analysis

  • A false loop closure that survives the robust kernel folds the map — the canonical catastrophic SLAM failure. Detection: post-optimization consistency (residual outliers), ATE regression. Containment: robust kernels + the Phase-10 geometric gate (defense in depth, I6). Forensic: log per-loop residual + IRLS weight; the loop that "should have been" down-weighted.

9.10 Operational Notes

  • Metrics: loop_factors, loop_weight_min (IRLS), robust_kernel, ate_post_opt. Kernel type + threshold are versioned config. Runbook false_loop_closure.md. Document defense-in-depth: geometric gate (Phase 10) + robust kernel (here) both guard against false closures.

Phase 10 — Loop-Closure Detection (Scan-Context / Appearance + Geometric Verification) + Closing

10.1 Objectives

  • slam-loop: detect revisited places from a rotation-invariant scan-context descriptor (appearance), propose candidates via a ring-key KD-tree, verify geometrically (scan match + χ² consistency gate, I6), and — only if verified — insert a robust loop-closure factor into the graph, triggering re-optimization (Principle 13). The highest-risk subsystem.

10.2 Detailed Implementation Steps

  • scan_context.rs: build a 2D ring/sector descriptor from a scan (max-range or point-count per (ring, sector) bin); rotation handled by column-shift matching.
  • ring_key.rs: rotation-invariant ring key (per-ring summary) for fast KD-tree candidate retrieval; full scan-context distance (min over column shifts) for ranking.
  • detector.rs: add_keyframe (store descriptor + ring key + pose); detect(scan) → top-K candidates by descriptor distance, excluding temporally-recent keyframes (avoid self-match).
  • verify.rs: LoopVerifier — for each candidate, scan-match current vs candidate keyframe scan (Phase 3, correlative for robustness) → relative pose + info; χ² consistency gate against the current trajectory estimate (is the proposed relative pose consistent with the graph?); accept → LoopConstraint, reject → drop (I6).
  • Pipeline wiring: accepted constraint → robust loop factor (Phase 9) → re-optimize → rebuild map (I9).
  • Branch-and-bound option for the verification scan match (Cartographer-style) for a wide search window.

10.3 Deliverable

  • Loop-closure subsystem that proposes, verifies, and closes loops on a real dataset (Intel), measurably improving trajectory consistency; false candidates rejected.

10.4 Acceptance Criteria

  • On Intel/Killian: true loop closures detected with high recall at high precision (precision ≥ 0.99 after geometric gate — false closures are the danger, so precision is prioritized over recall). A verified closure reduces ATE materially vs no-closure (documented per dataset). Appearance-only false positives are rejected by the geometric gate (I6). Verification scan match returns calibrated info. Deterministic.

10.5 Conformance Fixtures

  • tests/scan_context.rs: descriptor rotation invariance (rotated scan → same place, near-zero distance after column shift); verify.rs: true loop accepted, perceptual-alias false loop rejected by χ² gate. Fixtures: intel.spec (loop-rich), synthetic/loop3.spec. Deferred: deep learned place recognition → PhaseDeferred("FINAL_BLUEPRINT §10"). Degenerate: symmetric corridor (multiple candidates → require geometric agreement), first traversal (no candidates), self-match (excluded by recency).

10.6 Pitfalls

  • Perceptual aliasing (different places look identical) → false candidate. Manifestation: would corrupt map. Detect: geometric verification fails the χ² gate. Recovery: gate (I6); require geometric consistency, not appearance alone (Principle 13).
  • Appearance gate too loose (top-K too large / distance threshold high) → flood of false candidates burdening verification. Detect: candidate count vs accepted. Recovery: tighten ring-key threshold; cap K.
  • Verification scan match converges to a wrong pose (poor init across a large loop) → consistent-looking but wrong closure. Detect: residual + χ² gate + robust kernel (defense in depth). Recovery: correlative/branch-and-bound wide search; verify info.
  • Recency exclusion wrong → matching against just-visited keyframes (trivial self-loop). Detect: closure between adjacent ids. Recovery: exclude a temporal/spatial window.
  • Closing without re-optimization → map shows the loop edge but trajectory not corrected. Detect: pre/post-opt ATE. Recovery: trigger solve + map rebuild on every accepted closure (I9).

10.7 Performance Concerns

  • Descriptor build is O(beams) per keyframe. Candidate retrieval is KD-tree O(log n) on ring keys → scales to many keyframes. Verification scan match is the cost per candidate (correlative is expensive) — bound K and use branch-and-bound. Loop-closure latency budget (§4): proposal ≤ 50 ms, verification ≤ 100 ms; closing → async re-optimization. The closure-triggered solve is the tail-latency event.

10.8 Edge Cases

  • Many simultaneous candidates (rank, verify best, accept multiple if consistent). Loop after a very long traversal (large accumulated drift → wide search window needed). Reverse-direction revisit (scan-context rotation handling). No loops in the dataset (subsystem idle). Repeated identical closure (idempotent / dedup).

10.9 Failure Analysis

  • A single false closure that passes both the geometric gate and the robust kernel corrupts the entire map — the canonical SLAM catastrophe. Detection: post-closure ATE/consistency regression; residual outlier. Containment: defense in depth (geometric χ² gate I6 + robust kernel Principle 4); reject on any doubt (precision over recall). Forensic: log every candidate (descriptor distance), verification (match score, χ², residual), and accept/reject decision; the false closure is reconstructable.

10.10 Operational Notes

  • Metrics: loop_candidates, loop_verified, loop_rejected, loop_precision (vs ground truth in test), verify_ms, reopt_ms. Descriptor params (rings/sectors), K, distance threshold, χ² gate are versioned config. Runbook false_loop_closure.md. The loop-closure decision log is the primary forensic artifact for map-corruption incidents.

Phase 11 — Full Graph-SLAM Pipeline Integration + Map Management + Relocalization

11.1 Objectives

  • slam-pipeline: wire frontend (scan match + keyframing + odometry) → graph back-end (factor graph + solver + loop closure) → map; expose SlamSystem; implement map management (keyframe culling, map rebuild from optimized trajectory, I9) and relocalization (global scan-context match to recover pose after loss/kidnap). Online (incremental) and offline modes.

11.2 Detailed Implementation Steps

  • frontend.rs: per-scan — predict (motion model) → scan match (refine) → keyframe decision (Δtrans/Δrot/information threshold) → emit keyframe + odometry factor.
  • backend.rs: maintain factor graph; on loop closure or every N keyframes, run the solver (async worker in online mode); publish optimized trajectory snapshot atomically (frontend/backend separation, Principle 7).
  • keyframe.rs: keyframe store (pose, scan, descriptor); culling policy (remove redundant keyframes by overlap/information) to bound graph growth (Principle 9; keyframe-graph management as in Mur-Artal et al. 2015 ORB-SLAM).
  • map_manager.rs: after each optimization, rebuild the occupancy grid from the optimized trajectory + stored scans (I9); incremental update between optimizations.
  • reloc.rs: on tracking loss (Lost state), match the current scan against the global keyframe database (scan-context) → verify → relocalize pose; resume from matched keyframe.
  • mode.rs: offline (batch a dataset to completion) vs online (incremental, bounded per-scan latency, async solve).
  • system.rs: SlamSystem::{submit, trajectory, map, relocalize, save, load}.

11.3 Deliverable

  • A full graph-SLAM pipeline: ingest a scan+odom stream → produce a consistent optimized map + trajectory, close loops, and relocalize after induced loss; examples/full_pipeline_intel.rs.

11.4 Acceptance Criteria

  • End-to-end on Intel/Killian: optimized ATE within the conformance band (Phase 12 thresholds); map is globally consistent (loops closed, no doubled walls). Online mode keeps frontend per-scan latency ≤ 30 ms @ 20 Hz (§4); back-end solve async. Relocalization recovers pose within tolerance after an induced kidnap (teleport + scan). Map rebuilt after each optimization reflects the corrected trajectory (I9). Save/load round-trips the full system. Deterministic given seed.

11.5 Conformance Fixtures

  • tests/integration.rs: full pipeline on synthetic/loop3 + corridor (ATE + map IoU); reloc.rs: induced kidnap → relocalize. Fixtures: intel.spec, killian.spec. Deferred: multi-session / lifelong SLAM, map merging → PhaseDeferred("FINAL_BLUEPRINT §Scalability Analysis"). Visual-inertial pipeline → PhaseDeferred("FINAL_BLUEPRINT §8.5"). Degenerate: no loops (open trajectory, odometry-quality map), continuous featureless region (dead-reckon + relocalize on re-entry), back-end slower than frontend (queue + lag bounded).

11.6 Pitfalls

  • Frontend/back-end coupling (frontend blocks on solve) → missed scans in online mode. Manifestation: dropped scans, drift. Detect: per-scan latency. Recovery: async solve worker; publish snapshots (Principle 7).
  • Stale map after optimization (poses corrected, grid not rebuilt) → planner reads an inconsistent map. Detect: map-lag flag (I9). Recovery: rebuild on optimize.
  • Unbounded keyframe/graph growth → solve slows, memory grows. Detect: n_keyframes, solve_ms trend. Recovery: keyframe culling (Principle 9); sliding-window/marginalization (deferred Scalability Analysis).
  • Relocalization false positive (wrong place) → teleports the estimate. Detect: geometric verification (same gate as loop closure). Recovery: verify before relocalize; require strong match.
  • Mode confusion (offline determinism vs online concurrency) → different results. Detect: offline-vs-online consistency test on the same dataset. Recovery: same back-end; online only changes cadence, not math.

11.7 Performance Concerns

  • Online frontend must keep the per-scan budget regardless of back-end state (decoupled). The back-end solve cadence (every N keyframes / on closure) trades freshness vs CPU. Map rebuild is O(keyframes × scan integration) — incremental between optimizations, full on big corrections. Snapshot publication is a pointer swap (lock-free read for #287/#289). Tail latency = closure-triggered solve + map rebuild.

11.8 Edge Cases

  • Very first scan (anchor at origin, single keyframe). Loop closure during relocalization. Back-end queue overflow (bound + drop oldest pending solve, keep latest graph). Save during an in-flight solve (snapshot consistency). Kidnap with no prior map (cannot relocalize → Reinit).

11.9 Failure Analysis

  • Integration failures (coupling, stale map, mode divergence) manifest as a pipeline that works on toy data but drifts/corrupts on real datasets. Detection: end-to-end conformance (Phase 12) + offline/online consistency. Containment: clean frontend/back-end boundary; atomic snapshots; bounded queues. Forensic: full input + decision + seed log → deterministic replay of the whole run.

11.10 Operational Notes

  • Metrics: frontend_ms (p50/p99), solve_cadence, map_lag, reloc_total/reloc_success, n_keyframes, queue_depth, filter_status. Runbook relocalization.md. The optimized trajectory snapshot is the integration surface for #287/#289. Save/load bundle is format-versioned. Online vs offline is a config flag; the back-end is identical.

Mental Models & First Principles

The compressed intuitions an expert carries into SLAM. Each: the insight, what it predicts, the bug you write without it, and where this blueprint applies it.

  • MM1 — SLAM is one big sparse nonlinear least-squares problem; everything else is a frontend or an approximation of it. The "map + trajectory" posterior, under Gaussian noise, is argmin Σ ρ(‖r_i‖²_Ω). Predicts: filter back-ends (EKF, FastSLAM) are just specific marginalization/sampling schedules over the same factors; their differences are scaling tradeoffs, not different physics. Bug without it: treating EKF and graph SLAM as unrelated systems and re-deriving each measurement model twice with inconsistent conventions. Applied: §8.6–8.7, Phase 7, Phase 8.

  • MM2 — The information matrix is the adjacency matrix of the factor graph. H = JᵀΩJ has a nonzero block (i,j) exactly when some factor touches both variable i and j. Predicts: odometry gives a banded H; each loop closure adds an off-diagonal block far from the diagonal; fill-in during elimination is determined by graph topology, not values. Bug without it: choosing a variable ordering blind to topology and getting an O(n³) solve from a graph that should take seconds. Applied: §8.7, Phase 8 (ordering, I8), Comparative Architecture Table.

  • MM3 — A pose lives on a manifold; the update lives in the tangent space. You never add to a rotation — you retract: X⊞ξ = X·Exp(ξ). Predicts: the state dimension (3 for SE(2), 6 for SE(3)) is the tangent dimension, not the matrix element count; Jacobians are ∂r/∂ξ, not ∂r/∂R. Bug without it: optimizing 9 matrix entries freely and drifting off SO(3), or linearly averaging angles and exploding at ±π. Applied: §8.1, Principle 1, Phase 1, Phase 7.

  • MM4 — A pose graph has a free gauge; without an anchor the problem is singular by exactly the gauge dimension. Relative measurements fix everything except the global frame (3-DOF in SE(2), 6 in SE(3)). Predicts: H is rank-deficient by the gauge dimension until a prior or fixed vertex is added; the chosen anchor changes no relative geometry. Bug without it: a Cholesky that fails mysteriously, "fixed" by random regularization that biases the whole map. Applied: Principle 3b, I3, §8.8, Phase 8, Phase 9.

  • MM5 — Appearance proposes, geometry disposes; a single accepted false loop closure destroys the entire map. Loop closure is the one place a local error becomes global. Predicts: recall is cheap and precision is everything; the right architecture is defense-in-depth (geometric χ² gate and a robust kernel), not one perfect detector. Bug without it: an appearance-only closure on perceptual aliasing that folds the map, with no second line of defense. Applied: Principle 13, I6, Phase 9 (robust kernels), Phase 10 (geometric gate).

  • MM6 — Conditioning on the trajectory makes the map factorize (Rao-Blackwellization). Given a known path, landmark/cell estimates become independent. Predicts: FastSLAM can carry an analytic map per particle and scale as O(M·N) instead of EKF's O(N²) — at the cost of one full map per particle (the real ceiling is memory, not compute). Bug without it: sharing one map across particles, or running a joint filter over path+map and hitting the quadratic wall needlessly. Applied: §8.5, Phase 6, Scalability Analysis.

  • MM7 — A scan matcher must return uncertainty, not just a transform; an under-constrained direction is information, not noise. A corridor constrains lateral position but not longitudinal. Predicts: the match Hessian is anisotropic; its small eigenvalue is the corridor axis; the back-end must weight that edge accordingly. Bug without it: feeding an isotropic, over-confident constraint and getting longitudinal drift the optimizer can't see. Applied: Principle 10, I11, Phase 3 (information from Hessian), §8.3.

  • MM8 — Linearization is a lie that's only locally true; trust-region damping is how you survive it. GN assumes the residual is linear over the step; far from the optimum it isn't. Predicts: GN can increase cost and diverge on a poor init; LM's λ interpolates between Gauss-Newton (small λ) and gradient descent (large λ) and rejects bad steps. Bug without it: shipping GN-only, watching it oscillate on real data, and blaming the Jacobians. Applied: §8.7, MM-anchored Principle 12, Phase 8 (LM default, ADR 28).

  • MM9 — Determinism is a feature you architect in, not a property you hope for. Float reduction order, FMA contraction, and unseeded RNG each break bit-reproducibility. Predicts: without fixed reduction order + pinned codegen + seeded RNG, two "identical" runs diverge and no incident is replayable. Bug without it: a heisenbug in the particle filter that vanishes under a debugger and a conformance suite that flakes. Applied: Principle 6, I5, ADR 9, ADR 24, Phase 0, Phase 12.

  • MM10 — Marginalization is not deletion; removing a variable folds its information into its neighbors and creates fill-in. Dropping an old pose in a sliding window must Schur-complement it out. Predicts: a "delete old poses to bound memory" shortcut silently discards information and biases the estimate; correct bounding densifies the remaining block. Bug without it: a lifelong-SLAM window that grows over-confident and inconsistent as it forgets. Applied: Principle 8, §8.7 (Schur), Scalability Analysis (sliding window deferred).

Back-of-Envelope Capacity Model

Numbers an engineer computes before building, each derived from the System Constraints table (§4). Formula shown; inputs are the §4 quantities.

  • B1 — Beam endpoints processed per second (frontend throughput). beams/scan × scan_rate. At the §4 mid-load point (1081 beams, 20 Hz): 1081 × 20 = 21,620 endpoints/s. At the dense ceiling (1081 beams, 40 Hz): ≈ 43,240/s. Sizes the per-scan endpoint-transform + ray-cast budget.

  • B2 — Per-scan frontend time budget. 1 / scan_rate. At 20 Hz: 1/20 = 50 ms wall per scan; §4 allocates ≤ 30 ms of it to scan-match + association + map-update, leaving ~20 ms headroom for ingest/publish. Confirms the frontend deadline is feasible only if the correlative matcher (the dominant cost, Phase 3) stays under ~30 ms.

  • B3 — Occupancy-grid memory (single grid). extent_x/res × extent_y/res × bytes_per_cell. For the §4 example (100 m × 100 m @ 5 cm, i16 log-odds): (100/0.05) × (100/0.05) × 2 = 2000 × 2000 × 2 = 8 MB. The §4 row counts 4·10⁶ cells; at 2 B/cell that is the 8 MB working-set for one map.

  • B4 — FastSLAM total map memory. particles × single-grid-bytes (B3). At the §4 particle band (30–200) with the 8 MB grid: 30 × 8 MB = 240 MB (floor) to 200 × 8 MB = 1.6 GB (ceiling, before copy-on-write). This is why §4 names "particles × per-particle grid" as the dominant FastSLAM term and Phase 6 mandates copy-on-write grids.

  • B5 — EKF-SLAM covariance memory at the wall. (3 + 2N)² × 8 B for dense f64 Σ. At the §4 landmark wall (N = 1000): (3 + 2000)² × 8 = 2003² × 8 ≈ 32 MB, and per-step update cost scales with that ~4·10⁶-entry matrix. Doubling N to 2000 quadruples it to ~128 MB — the O(N²) wall §4 and Phase 5 cite, motivating the switch to FastSLAM/graph.

  • B6 — Pose-graph state-vector size. poses × DOF. At the §4 graph ceiling (10⁵ poses, SE(2) 3-DOF): 10⁵ × 3 = 3·10⁵ unknowns; in 3D (6-DOF): 6·10⁵. Sets the dimension of H (and thus the Cholesky working set) the solver must factor.

  • B7 — Sparse H nonzeros (odometry backbone). A pure chain of P poses each with one between-factor gives a block-tridiagonal H: ≈ (3P − 2) diagonal/off-diagonal d×d blocks, d = DOF. At P = 10⁴, SE(2): ≈ 3·10⁴ blocks × 3×3 = 9 = ~2.7·10⁵ nonzeros — versus a dense (3·10⁴)² ≈ 9·10⁸. The ~3000× gap is exactly why Principle 2 forbids dense solves.

  • B8 — Loop-closure fill-in pressure. Each non-sequential loop edge adds an off-diagonal block at graph distance Δ; naive elimination can fill the band between, adding up to O(Δ × d²) nonzeros. For a loop spanning Δ = 5000 poses (SE(2)): up to 5000 × 9 ≈ 4.5·10⁴ extra nonzeros from one bad ordering — which AMD (I8, Phase 8) exists to suppress. Quantifies why "loops densify H" (Scalability Analysis).

  • B9 — Full-solve time order of magnitude. Sparse Cholesky cost ≈ O(nnz(L)); §4 budgets "full GN/LM solve ≤ a few seconds at 10⁴ poses." With well-ordered nnz(L) on the order of 10⁶ and ~5–10 GN/LM iterations, that is ~10⁷ flops/iter × ~10 iters ≈ 10⁸ flops — sub-second on a host CPU, consistent with the §4 budget; a poor ordering inflating nnz(L) 10–100× is what blows it past "a few seconds."

  • B10 — Loop-closure database size. keyframes × (descriptor_bytes + ring_key_bytes). With scan-context rings×sectors ~ 20 × 60 = 1200 floats (9.6 KB) per keyframe and 10⁵ keyframes: 10⁵ × 9.6 KB ≈ 960 MB of descriptors — bounding when keyframe culling (Principle 9, Phase 11) becomes mandatory and why retrieval uses a compact ring key + KD-tree (O(log n)), not full-descriptor scan.

  • B11 — Map-rebuild cost after optimization. keyframes × beams × avg_ray_cells. At 10³ keyframes, 1081 beams, ~40 cells/ray (≈ 2 m range @ 5 cm): 10³ × 1081 × 40 ≈ 4.3·10⁷ cell updates — tens of ms, so a full rebuild on every loop closure (I9, Phase 11) is affordable; incremental update between closures keeps it off the per-scan path.

  • B12 — Log-odds saturation headroom. With per-hit increment Δl ≈ 0.85 and clamp |l| ≤ 50 (§4): a cell saturates after 50 / 0.85 ≈ 59 consistent observations. Confirms the §4 clamp keeps the map responsive (a previously-occupied cell can be cleared in ~59 contradicting observations rather than never), the quantitative basis for Principle 11 / I12.

Alternative Architectures (Roads Not Taken)

Three fundamentally different ways to build this system, each with the regime where it wins, the real system that embodies it, and why this blueprint rejected it.

ALT-A — Pure submap + branch-and-bound graph (Cartographer-style), no global grid.

 scans ─► local scan-match ─► SUBMAP_k (small prob grid)
                                  │ when full, freeze
                                  ▼
   ┌──────── global pose graph of submap origins ────────┐
   │  scan↔submap constraints found by branch-and-bound  │
   │  (multi-resolution correlative over a wide window)  │
   └───────────────┬─────────────────────────────────────┘
                   ▼  optimize submap poses; map = union of submaps

Wins: building-scale, real-time 2D/3D mapping where local drift must be bounded inside submaps and loop search needs a wide window made tractable by branch-and-bound. Embodied by: Google Cartographer (Hess et al. 2016). Rejected here because: submap lifecycle, freezing, and inter-submap constraint bookkeeping add substantial complexity orthogonal to the teaching goal; this blueprint keeps one global occupancy grid rebuilt from the optimized trajectory (Phase 11, I9) and defers submaps (Scalability Analysis). Its correlative matcher and branch-and-bound verification are adopted (Phase 3, Phase 10).

ALT-B — Rao-Blackwellized particle filter as the sole back-end (no graph optimizer).

 {particle_i: trajectory_i + grid_i} ──propose(motion+scanmatch)──►
        weight_i ∝ p(z | x_i, grid_i) ──normalize──► N_eff?
              │ low                          │ ok
              ▼ resample (duplicate maps)    ▼ keep
        best particle ⇒ trajectory + map (loop closure implicit)

Wins: small-to-medium 2D environments with decent odometry, where a few dozen particles capture the posterior and implicit loop closure via particle diversity suffices — minimal linear algebra, no ordering/fill-in machinery. Embodied by: GMapping (Grisetti et al. 2007). Rejected as the sole back-end because: memory is particles × grid (Back-of-Envelope B4), explicit large loops are handled poorly (diversity collapses over long traversals), and it cannot give a globally optimal trajectory the way a pose graph can. This blueprint ships it as one selectable back-end (Phase 6) but makes the graph back-end (Phase 8–11) primary.

ALT-C — Dense direct (photometric/scan-likelihood) SLAM, no features or explicit data association.

 frame_t ─► align whole scan/image to a dense model by
            minimizing photometric/likelihood residual over SE(2/3)
            (every pixel/beam is a residual; no correspondences)
                       │
                       ▼  fuse into a dense map (grid / TSDF)

Wins: sensor-rich, high-overlap settings (dense LiDAR likelihood fields, or RGB-D) where avoiding explicit feature extraction + association removes the dominant failure point and uses all the data. Embodied by: dense/direct methods (e.g. KinectFusion-style TSDF fusion for RGB-D; whole-scan correlative alignment is its 2D cousin). Rejected as the architecture because: it folds the frontend/back-end boundary (Principle 7) into one dense optimization, is far heavier per step, and obscures the data-association and sparse-solver lessons that are the point of this build. The correlative matcher (Phase 3) captures the useful "align against a likelihood field" idea without committing the whole system to dense fusion (TSDF noted as the win-case in ADR 27's 6th column).

Beam model Mixture sensor model (p_hit/p_short/p_max/p_rand) for range likelihood.
Likelihood field Distance-to-nearest-obstacle field used to score scans (smooth, fast).
