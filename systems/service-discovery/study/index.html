Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does a registration become visible to a local blocking query before that write is confirmed on a majority of Raft followers, and what does P5/I2's "lossy but never wrong" contract actually guarantee in that window? (§8.5, §7 I2, §6 P5)
  2. Under sustained load, which binds first — the 50-probe check-engine ceiling or the single-Raft-leader write throughput — and how would you tell from metrics alone which one is binding? (§4, §16.7, §34.12, §30)
  3. Why is DNS forbidden as a write path (P5), and what specific invariant (not just "bad practice") would a DNS-UPDATE-style mutation violate? (§6 P5, §7 I3, §8.4)
  4. Gossip and Raft both "replicate" something — precisely what does each replicate, and why would merging them into one mechanism break P2? (§6 P2, §18.2, §33)
  5. Why does federation forward reads instead of replicating the catalog across datacenters, and what latency floor does that choice create that no software change can remove? (§21.2, §34.11, §36)
  6. A revoked ACL token still authenticates on one agent for some window — is this a bug or a documented tradeoff, and what bounds the window? (§7 I4, §19.8, §19.9)
  7. Why is the catalog index global rather than per-table or per-row, and what specific blocking-query behavior breaks if you shard it? (§7 I1, §13.2, §13.6)
  8. What does "idempotent apply" (I6/P12) actually protect against operationally, and name the two different scenarios (one client-side, one gossip-side) where duplicate delivery is expected, not exceptional? (§7 I6, §13.2, §18.2)
  9. Why does a TTL check need a grace period at all — what physical phenomenon does TTL/2 actually bound, and what happens at exactly zero grace? (§7 I9, §16.2, §16.8)
  10. Compare this design's watch primitive (blocking query + index) to etcd's gRPC watch stream — what does each buy and cost, and under what load pattern would you prefer the other? (§8.5, §20.2, §33)
  11. Why is the KV forced to share the catalog's Raft log rather than running its own, and name the one operational scenario where that choice visibly costs you? (§9 ADR-08, §17.2, §25 FM6)
  12. What three things would have to be simultaneously true for Alternative C (pure-gossip AP catalog) to actually be the better choice for this system's stated users? (§36, §1, §4)
  13. Why does the memory-per-instance number (§34.1) matter more at 100K instances than at 100, and what §4 constraint would you violate first if the per-instance cost doubled? (§34.1, §34.2, §4)
  14. What specific structural property of SWIM (not Lifeguard) already prevents a single slow node from marking the whole cluster down, and where does Lifeguard's addition sit on top of that? (§18.2, §32 MM3, §5 Papers)
  15. Name the one invariant that both the check engine (§16) and the ACL cache (§19) independently depend on, and explain why violating it in either subsystem produces a similar-looking symptom. (§7 I5, §19.7, §16.6)
  16. Why does auto-deregistration require continuous critical duration rather than a simple counter of critical observations, and what specific flapping scenario does the distinction prevent? (§7 I13, §8.2, §16.9)
  17. If you were asked to add a second datacenter's worth of read traffic without adding a second Raft quorum, which two sections of this blueprint tell you exactly why that request cannot be satisfied as stated? (§21.1, §31, §4)
  18. What would have to change in §11's RaftLogEntry schema to support a genuinely new mutation kind, and why is that change additive rather than breaking under §27's compatibility rules? (§8.6, §11.3, §27)

32. Mental Models & First Principles

  • MM1 — A service instance is a claim, not a fact. Insight: the catalog holds what an agent last reported, not ground truth. Predicts: DNS/HTTP answers can be stale by up to one notification cycle even when "correct." Bug class without it: clients assume a passing instance is reachable right now and skip retry logic. Resolving §: §8.5, §15.6 (I3).
  • MM2 — The index is a logical clock, not a timestamp. Insight: catalog.Index orders events; it does not measure elapsed time (Lamport 1978). Predicts: two agents can disagree on wall-clock time yet agree perfectly on event order. Bug class without it: engineers derive a staleness duration from an index delta, which is meaningless without a separate timestamp. Resolving §: §7 (I1, I11), §13.2.
  • MM3 — Suspicion is a probability, not a verdict. Insight: SWIM's suspect state exists because no failure detector is both accurate and fast in an asynchronous network (Chandra & Toueg 1996). Predicts: some false positives are mathematically unavoidable at any fixed timeout. Bug class without it: engineers chase a "fix" for every false positive instead of tuning the probability/latency tradeoff. Resolving §: §18.9 (P11).
  • MM4 — Consistency is a per-subsystem choice, not a system-wide constant. Insight: this system is CP for the catalog and AP for membership simultaneously (P2). Predicts: "is this system CP or AP" has no single correct answer without naming the subsystem. Bug class without it: engineers apply catalog reasoning to membership data, or vice versa, and are surprised by the mismatch. Resolving §: §6 (P2), §33.
  • MM5 — A blocking query is a subscription with a receipt, not a socket. Insight: the index is the receipt — resuming a watch after a restart means replaying the last known index, no session state required server-side. Predicts: watch clients can be stateless across reconnects. Bug class without it: engineers build session-affinity infrastructure for watches that do not need it. Resolving §: §8.5, §20.2.
  • MM6 — Federation is a WAN-shaped RPC, not a bigger cluster. Insight: cross-DC reads forward, they do not merge, because merging would require one linearizable order across physically separated failure domains. Predicts: federation latency is bounded below by speed-of-light RTT, not by any software optimization (§34.11). Bug class without it: engineers "optimize" federation latency with caching that silently reintroduces the staleness federation was designed to avoid. Resolving §: §21.2 (I12), §36.
  • MM7 — Backpressure is a correctness property, not a performance one. Insight: an unbounded queue does not fail slowly, it fails catastrophically (OOM) at exactly the worst moment (P13). Predicts: a system with no explicit bounds anywhere has an implicit bound equal to available memory, discovered in production. Bug class without it: engineers treat ADR-21-style bounding as an optimization to defer, not a correctness requirement to ship on day one. Resolving §: §9 (ADR-21), §20.7.
  • MM8 — A deferred feature is a decision, not an omission. Insight: every PhaseDeferred entry (§37) carries an explicit un-defer trigger — the absence of script checks, for instance, is a security decision (T10), not an oversight. Predicts: a future session reading this blueprint can distinguish "not built yet, intentionally" from "forgot to build." Bug class without it: a maintainer builds a deferred feature ad hoc, without revisiting the design review the deferral was waiting on. Resolving §: §37.

Glossary (§38) · 45 terms · site-wide glossary

Agent
the discoveryd binary running on one node, in server or client role (§1).
Catalog
the cluster-wide, Raft-replicated map of nodes, services, instances, checks (§7, §13).
Instance
a single addressable copy of a service on a single node (§11.1).
Check
a probe producing a passing/warning/critical status (§11.2, §8.2).
Index
the monotonic uint64 ordering catalog mutations (I1, §13.2).
Datacenter (DC)
a failure-domain unit; one Raft quorum per DC (§4, §21).
Federation
cross-DC forwarding of catalog reads (§21).
Blocking query
a long-poll HTTP request parked on a monotonic index (§8.5).
Coalescing
fanning one notification out to all waiters on the same table (I7, §20.2).
Gossip
SWIM+Lifeguard-based membership dissemination (§18, ADR-06).
LAN pool
the gossip pool within one datacenter (§18.2).
WAN pool
the gossip pool spanning datacenters (§21.2).
Suspicion
SWIM's intermediate state between alive and dead (P11, §18.2).
Raft
the consensus algorithm replicating the catalog/KV log (ADR-07, §8.6).
Leader
the single Raft node serializing writes for a quorum (§4, ADR-07).
RTO
recovery time objective; bounded by ~3× the heartbeat interval here (§4).
RPO
recovery point objective; 0 for committed Raft entries (§4).
Snapshot
a point-in-time encode of the full catalog for Raft compaction (§13.2, §8.6).
ACL
access control list; token/policy/namespace evaluation on every path (§19, I4).
Token
a bearer credential with an AccessorID and policy list (§11.4).
Policy
a named rules document merged by union with deny-overrides (§19.2).
Namespace
a label scoping tokens/instances; isolation itself is deferred (§19, §37).
Sidecar bridge
the Unix-socket local-registration path (§22, ADR-16).
Connect
the mTLS service-mesh stretch layer; scaffolding only in Phase-0 (§22, §37).
SVID
a SPIFFE-style verifiable identity issued by Connect (deferred, §22).
Intention
an allow/deny rule between two services in Connect (deferred, §22).
KV
the embedded flat key-value namespace sharing the catalog's Raft log (§17, ADR-08).
CAS
compare-and-swap; a conditional KV write keyed on ModifyIndex (§17.2).
EDNS0
the DNS extension mechanism for larger UDP buffer sizes (RFC 6891, §15.3).
SRV record
a DNS record carrying priority/weight/port/target (RFC 2782, §8.4).
TTL check
a check driven by a client-refreshed deadline, not an active probe (§16.2).
Hysteresis
the success/failure counter thresholds preventing check flapping (§8.2, I9).
Auto-deregistration
removing an instance after continuous critical duration (I13).
Watch waiter
a parked blocking-query goroutine registered on a notification channel (§13.2, §20).
Notification channel
the per-table channel a waiter blocks on (I7, §13.2).
Dedup key
the RequestID UUID making an apply idempotent (I6, P12).
Apply path
the code path turning a RaftLogEntry into a catalog mutation (§8.6, §13.2).
FSM
the finite-state machine the Raft crate drives via the apply path (ADR-07, §11.5).
Wire compatibility
the contract keeping HTTP/DNS payloads additive-only across versions (§27).
M-table
the quantified performance-targets table (M1–M12, §30).
Conformance fixture
a named YAML test case with an expected result (§7, phase N.5 sections).
PhaseDeferred
the marker anchoring an out-of-scope feature to a real heading and the Register (§37).
Backpressure
bounding queues/pools so overload sheds instead of OOMing (P13, ADR-21).
Self-preservation mode
Eureka's AP-favoring behavior under suspected partition (§33, §36 Alternative C).
Ephemeral znode
ZooKeeper's session-bound coordination primitive (§33, §36 Alternative D).
