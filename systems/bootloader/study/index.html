30. Mental Models & First Principles

  1. MM1 — "The memory map is a lease, not a fact." The firmware's memory map is valid only until the next allocation; treating it as a permanent fact (instead of re-checked immediately before use) is the exact bug class behind ExitBootServices failures. Predicts: any code path that calls an allocating function between "get map" and "use map" will eventually break. Bug class without it: silent memory-ownership desync between loader and kernel. Applied in §15 (Phase 3), I1.
  2. MM2 — "A mode transition is a one-way door." Real→protected→long mode is not reversible mid-sequence; there is no partial state that is both valid and useful. Predicts: any attempt to "check and retry" mid-transition is meaningless — the only correct unit of retry is the whole sequence, from a known-good starting state. Bug class without it: triple-faults from partially-applied CPU state changes. Applied in §14 (Phase 2), P6, I3/I4.
  3. MM3 — "Trust is measured before it is spent." A component must be measured (PCR-extended) before its bytes influence anything, because measurement after execution cannot un-happen the execution. Predicts: any "verify, then optionally measure" ordering has a TOCTOU window. Bug class without it: an attacker wins the race between measurement and use. Applied in §19 (Phase 7), P9, I7, MM3 draws directly on Parno/McCune/Perrig's bootstrapping-trust chain model.
  4. MM4 — "A/B is consensus with two replicas and no network." The BCB ping-pong is a miniature Paxos-adjacent problem: exactly one value must be authoritative even under a crash at any write boundary. Predicts: any single-copy "just write it" design has a crash window with no valid state. Bug class without it: bricked devices on power-loss. Applied in §20 (Phase 8), P10, I5.
  5. MM5 — "The parser is the trust boundary, not the binary." A correctly-signed binary can still contain a parser that is unsafe to run before verification completes — the boundary is bytes not yet verified, not files not yet loaded. Predicts: any lazy/streaming parse-then-verify design reintroduces pre-auth code execution. Bug class without it: BootHole/BootStomp-style pre-auth RCE. Applied in §22 (Threat Model, T1/T2), P3.
  6. MM6 — "Firmware is a foreign, adversarial-quality API, not a trusted subroutine." Firmware bugs (stale map keys, GOP quirks, inconsistent ExitBootServices timing) are common enough to design around defensively, even absent malice. Predicts: any code assuming firmware behaves per spec on every implementation will eventually hit a real-hardware counterexample. Bug class without it: field failures that never reproduce in the reference QEMU/OVMF environment. Applied in §15 (Phase 3), §22 (T7), the Bulygin et al. 2015 literature.
  7. MM7 — "Every retry loop is a bet against an unknown clock." A retry without a bound is a bet that some external condition resolves in finite time — a bet the loader cannot verify. Predicts: unbounded retries eventually manifest as unexplained field hangs. Bug class without it: a device that "just sits there" with no diagnostic. Applied in P13, I13, §23 (FM-2).
  8. MM8 — "The kernel format is an encoding, not an identity." ELF64, Multiboot2, and bzImage are three encodings of the same underlying handoff intent (entry point + memory + cmdline); treating them as fundamentally different problems duplicates logic that should be shared. Predicts: a design with three independent handoff implementations will drift and diverge over time. Bug class without it: a field only populated correctly for one format silently missing in another. Applied in §17/§18 (Phase 5/6), P12.

Required reading (§5)

Books

  • Rootkits and Bootkits — Matrosov, Rodionov, Bratus (No Starch Press, 2019). Ch. 3–5 (UEFI boot process, Secure Boot bypass classes). Applied in Threat Model (§22, T1/T2) and Phase 7 (§19).
  • Operating Systems: Three Easy Pieces — Arpaci-Dusseau & Arpaci-Dusseau (free online, Arpaci-Dusseau Books). Ch. on Address Translation / Paging. Applied in Phase 2 (§14), I3/I4.
  • Modern Operating Systems, 4th ed. — Tanenbaum. Ch. 1 (system boot framing). Applied in §3 Architectural Overview / §1 Goal & Scope.
  • Computer Organization and Design: The Hardware/Software Interface, 5th ed. — Patterson & Hennessy. Ch. on ISA privilege levels. Applied in Phase 2 (§14) mode transitions.
  • Writing an OS in Rust — Philipp Oppermann (free online book; companion to the rust-osdev/bootloader crate). Minimal-kernel and bootloader chapters. Applied in Phase 0 (§12), Phase 1 (§13), ADR-01, ADR-17.
  • Embedded Systems Architecture, 2nd ed. — Daniele Lacamera (Packt, 2018). Ch. on bootloaders and board bring-up. Applied in Phase 8 (§20).

Papers

  • Bootstrapping Trust in Commodity Computers — Parno, McCune, Perrig (IEEE S&P, 2010). Applied in Phase 7 (§19), Mental Model MM3.
  • Flicker: An Execution Infrastructure for TCB Minimization — McCune, Parno, Perrig, Reiter, Isozaki (EuroSys, 2008). Applied in Threat Model (§22, T9) and ADR-16 (SRTM vs DRTM).
  • Terra: A Virtual Machine-Based Platform for Trusted Computing — Garfinkel, Pfaff, Chow, Rosenblum, Boneh (SOSP, 2003). Applied in Comparative Architecture Table (§31).
  • vTPM: Virtualizing the Trusted Platform Module — Berger, Cáceres, Goldman, Perez, Sailer, van Doorn (USENIX Security, 2006). Applied in Phase 7 (§19), N.8 Edge Cases (swtpm under QEMU).
  • BootStomp: On the Security of Bootloaders in Mobile Devices — Redini, Machiry, Wang, Spensky, Continella, Shoshitaishvili, Kruegel, Vigna (USENIX Security, 2017). Applied in Threat Model (§22, T1/T3), P3.
  • OSLO: Improving the Security of Trusted Computing — Kauer (USENIX Security, 2007). Applied in ADR-16 and Alternative Architectures (§34).
  • Copilot: A Coprocessor-Based Kernel Runtime Integrity Monitor — Petroni, Fraser, Molina, Arbaugh (USENIX Security, 2004). Applied in Failure Modes & Recovery (§23, FM-9).
  • Attacking and Defending BIOS in 2015 — Bulygin, Bazhaniuk, Furtak, Loucaides, Matrosov, Zimmer (CanSecWest, 2015). Applied in Phase 3 (§15, N.6 Pitfalls) and Threat Model (§22, T2).

Reference Implementations

  • GNU GRUB2 (grub-core/kern/, grub-core/loader/multiboot2.c, grub-core/loader/i386/linux.c) — the differential-testing reference; lesson: module system decouples firmware from kernel format; pitfall not to copy: grub.cfg parser lacked bounds checks (CVE-2020-10713). Applied Phase 9 (§21), ADR-11.
  • Limine bootloader (limine-bootloader/limine) — multi-protocol design (its own protocol + Multiboot2); lesson: one HandoffState, many wire encodings (P12). Applied Phase 6 (§18), Alternative Architectures (§34).
  • coreboot (src/arch/x86/, payload handoff) — lesson: firmware and payload are separate trust domains behind a thin ABI. Applied Phase 3 (§15), ADR-02.
  • systemd-boot (src/boot/efi/) — lesson: a UEFI boot manager can be minimal by scope discipline, not by cutting correctness. Applied Phase 3 (§15), Comparative Architecture (§31).
  • Das U-Boot (common/board_f.c, common/spl/) — lesson: staged loading (SPL → full U-Boot) is the ancestor of this project's A/B design. Pitfall not to copy: U-Boot's default insecure bootcmd env is user-writable by default. Applied Phase 8 (§20), Comparative Architecture (§31).
  • TianoCore EDK II / OVMF (github.com/tianocore/edk2) — the reference UEFI firmware used as CI's UEFI test target. Applied Phase 0 (§12), Phase 3 (§15).
  • rust-osdev/bootloader (github.com/rust-osdev/bootloader) — Rust BIOS+UEFI bootloader precedent; lesson: a no_std crate can implement both firmware paths behind one BootInfo struct. Applied Phase 0 (§12), ADR-01, ADR-17.
