32. Back-of-Envelope Capacity Model

  1. Raw vector memory footprint: dim=768 * 4 bytes(f32) = 3,072 bytes/vector; at 10,000,000 vectors: 10,000,000 * 3,072 = 30.72 GB.
  2. HNSW graph overhead per node: M_max0=32 layer-0 neighbors plus an expected ml ≈ 1/ln(16) ≈ 0.36 extra layers at M=16 each; (32 + 16*0.36) * 8 bytes(u64) ≈ 302 bytes/node; at 10,000,000 nodes: ≈ 3.02 GB.
  3. Total HNSW working set at 10,000,000 vectors, dim=768: 30.72 GB + 3.02 GB ≈ 33.7 GB, within the §4 64 GiB single-node ceiling with headroom for OS/query buffers.
  4. PQ compression: m_subquantizers=96 (768/8), 8-bit codes ⇒ 96 bytes/vector vs 3,072 bytes/vector raw ⇒ 3,072 / 96 = 32x compression (matches M5); at 10,000,000 vectors: 960 MB compressed vs 30.72 GB raw.
  5. IVF list count: nlist ≈ sqrt(N) = sqrt(10,000,000) ≈ 3,162, rounded to nlist=4,096 (power-of-two convenience); average list size: 10,000,000 / 4,096 ≈ 2,441 vectors/list.
  6. Query fan-out at nprobe=8: 8 * 2,441 ≈ 19,528 vectors scanned via ADC — about 0.2% of the 10,000,000-vector dataset per query.
  7. WAL write amplification: header(16B) + vector(3,072B) + id(8B) = 3,096 bytes/record; at the M4 target of 3,000 inserts/sec: 3,096 * 3,000 ≈ 9.29 MB/s sustained WAL write throughput.
  8. Snapshot write time at sequential disk throughput 500 MB/s: 30.72 GB / 500 MB/s ≈ 61 s — this is the dominant term against the §4 30s save-time target and motivates parallel/striped writes as a lever if the target is missed.
  9. Recall calibration point: HNSW empirically reaches recall@10 ≈ 0.95 at ef_search≈100, M=16 on comparable benchmark corpora (Malkov & Yashunin 2018; Aumuller, Bernhardsson & Faithfull 2020) — used as the M1 target's empirical anchor, not a derived number.
  10. Single-node sharding threshold: at the §29 practical ceiling of ≈200,000,000 vectors/shard (dim=768, ≈600 GB raw before any compression), the mandatory shard count for a collection of size N is ceil(N / 200,000,000).
