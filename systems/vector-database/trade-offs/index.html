Decisions (§9) · 25 ADRs

ADR-01

Implementation language

Chosen

Rust

Rejected

C++, Go, Python

When the rejected choice is right

Python wins for pure research prototyping with no perf constraint

Why: memory safety on untrusted decode paths; ownership model for a shared graph

ADR-02

Distance-ranking representation

Chosen

squared L2 (skip sqrt)

Rejected

true L2 (sqrt), Manhattan

When the rejected choice is right

true L2 wins when the raw distance value is surfaced to callers as an absolute metric

Why: ranking order is invariant under monotonic sqrt; saves a sqrt per comparison

ADR-03

Primary ANN index

Chosen

HNSW graph

Rejected

IVF-only, LSH-only, tree-based (Annoy-style)

When the rejected choice is right

IVF-PQ wins when the memory ceiling forbids storing full-precision vectors plus a graph

Why: best recall/latency tradeoff in-memory at target scale (ANN-Benchmarks corpus)

ADR-04

Vector compression

Chosen

Product Quantization

Rejected

scalar quantization (SQ8), no compression

When the rejected choice is right

SQ8 wins when simplicity matters more than compression ratio and dim is small

Why: 8–32x compression at bounded reconstruction error (Jegou et al. 2011)

ADR-05

HNSW neighbor selection

Chosen

diversity heuristic (heuristic pruning)

Rejected

simple closest-M

When the rejected choice is right

simple closest-M wins on small low-dim datasets where construction speed dominates recall

Why: prevents clustered/redundant neighbor lists, improves navigability (Malkov & Yashunin 2018)

ADR-06

Delete semantics

Chosen

soft-delete plus periodic compaction

Rejected

immediate hard delete

When the rejected choice is right

hard delete wins under strict data-erasure regimes requiring guaranteed non-persistence

Why: avoids costly graph-edge repair on every delete

ADR-07

Snapshot serialization

Chosen

bincode (Rust-native binary)

Rejected

Protocol Buffers, JSON

When the rejected choice is right

Protobuf wins when cross-language, cross-version interop with non-Rust readers is required

Why: zero-copy-friendly, minimal overhead for an internal-only format

ADR-08

Persistence durability model

Chosen

WAL plus periodic snapshot

Rejected

snapshot-only, WAL-only

When the rejected choice is right

WAL-only wins for append-only audit-log use cases without a read-optimized snapshot need

Why: bounded replay time (WAL tail) plus bounded snapshot size

ADR-09

In-memory vector storage layout

Chosen

contiguous row-major arena

Rejected

per-vector heap allocation, mmap columnar

When the rejected choice is right

mmap columnar wins once the dataset exceeds RAM and OS page cache manages residency

Why: avoids per-vector allocation and pointer chasing on scan

ADR-10

Metadata filtering strategy

Chosen

hybrid pre/post filter by selectivity estimate

Rejected

always pre-filter, always post-filter

When the rejected choice is right

always-post-filter wins when predicates are cheap and selectivity is uniformly high

Why: avoids over-filtering underflow (FM-8) and wasted traversal on low-selectivity predicates

ADR-11

Sharding strategy

Chosen

consistent-hash partitioning

Rejected

range partitioning, random placement

When the rejected choice is right

range partitioning wins when queries commonly restrict to a contiguous id range

Why: uniform load without a centralized range directory

ADR-12

Query routing (sharded)

Chosen

scatter-gather with per-shard top-k merge

Rejected

centroid-routed (query only likely shards)

When the rejected choice is right

centroid-routed wins at very high shard counts where fan-out dominates latency

Why: guarantees exact global top-k regardless of shard skew

ADR-13

ef_search tunability

Chosen

per-query override with a global default

Rejected

fixed global constant only

When the rejected choice is right

a fixed global constant wins in a locked-down multi-tenant API where per-query tuning is a noisy-neighbor risk

Why: lets latency-sensitive callers trade recall down without a redeploy

ADR-14

HNSW level assignment

Chosen

exponential distribution (-ln(U) * ml)

Rejected

fixed layer count, uniform distribution

When the rejected choice is right

a fixed layer count wins for deterministic test fixtures needing exact level counts

Why: matches the theoretical small-world degree distribution (Malkov & Yashunin 2018)

ADR-15

Clustering algorithm (PQ/IVF training)

Chosen

Lloyd's k-means with k-means++ init

Rejected

random-init k-means, hierarchical k-means

When the rejected choice is right

hierarchical k-means wins at very large nlist where flat k-means training time dominates

Why: k-means++ init reduces empty-cluster risk and convergence variance

ADR-16

Vector id scheme

Chosen

user-supplied u64 with server-side uniqueness check

Rejected

auto-increment only, content-hash id

When the rejected choice is right

content-hash id wins for pure deduplication / content-addressed storage use cases

Why: callers commonly already have a stable external key (document id)

ADR-17

Recall correctness oracle

Chosen

vecdb-flat brute force over held-out queries

Rejected

held-out ground-truth file only, no live oracle

When the rejected choice is right

a fixture-only ground truth wins at benchmark scale where brute force can't run in test-suite time

Why: the oracle recomputes exactly on the live dataset, catching drift a static file misses

ADR-18

API surface

Chosen

embeddable library, network server optional

Rejected

network service only, library only

When the rejected choice is right

network-service-only wins in a managed multi-tenant SaaS deployment

Why: matches the widest set of RAG/embedding use cases without forcing an RPC hop

ADR-19

Concurrency model

Chosen

single global RwLock (read-many/write-one)

Rejected

lock-free epoch-based graph, per-shard fine-grained locks

When the rejected choice is right

lock-free epoch-based wins once single-writer throughput becomes the bottleneck at very high insert rates

Why: correctness-first: simplest model giving readers a consistent snapshot

ADR-20

Distance-kernel acceleration

Chosen

scalar Rust across Phases 0–9

Rejected

explicit SIMD intrinsics, GPU kernels

When the rejected choice is right

explicit SIMD wins once §28 profiling shows the distance kernel dominates CPU cost

Why: keeps the correctness kernel portable and auditable before optimizing

ADR-21

Persistence write atomicity

Chosen

write-tmp, fsync, then rename

Rejected

direct in-place overwrite

When the rejected choice is right

in-place overwrite wins only on filesystems lacking atomic rename support

Why: guarantees no reader ever observes a half-written snapshot

ADR-22

Duplicate-id insert semantics

Chosen

reject with DuplicateId

Rejected

silent overwrite, silent ignore

When the rejected choice is right

silent overwrite wins when the caller's workflow is explicitly an upsert API

Why: prevents silent data loss disguised as an update (FM-9)

ADR-23

LSH probing strategy

Chosen

multi-probe LSH

Rejected

single-probe LSH, many independent hash tables only

When the rejected choice is right

single-probe wins when hash-table memory is the binding constraint over CPU

Why: higher recall per unit memory by probing perturbed buckets (extends Datar et al. 2004)

ADR-24

Cross-implementation correctness testing

Chosen

differential testing vs vecdb-flat plus ANN-Benchmarks recall curves

Rejected

formal proof of a recall bound only

When the rejected choice is right

a formal proof-based bound wins only for the exact-search flat path, where recall is provably 1.0

Why: no closed-form recall bound exists for HNSW; empirical differential testing is the practical oracle (Aumuller et al. 2020)

ADR-25

Compaction / tombstone reclamation

Chosen

periodic full rebuild triggered by tombstone-ratio threshold

Rejected

continuous incremental edge repair, no scheduled compaction pass

When the rejected choice is right

continuous incremental repair wins under sustained high delete/insert churn where full-rebuild pauses are unacceptable

Why: bounded, predictable rebuild cost versus unpredictable per-delete repair cost

Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

AA1 — Tree-Based Random-Projection Forest

       root (random hyperplane split)
      /                              \
   left subtree                  right subtree
  (recurse: new random          (recurse: new random
   hyperplane per node)          hyperplane per node)
      ...                             ...
  [leaf: small vector bucket]    [leaf: small vector bucket]

  Query: descend all trees in the forest, union leaf buckets, re-rank exactly.

Regime where it wins: read-mostly, low-to-moderate dimensionality (<100), simplicity and lock-free mmap deployment matter more than recall ceiling. Real system: Annoy (Spotify). Why rejected: recall degrades sharply at dim=768 versus HNSW at equal memory (§31); no incremental insert without a full retree.

AA2 — Pure LSH-Only System (No Graph)

  Query --> [Hash Table 1] --> bucket candidates --\
        --> [Hash Table 2] --> bucket candidates ---+--> union --> re-rank --> top-k
        --> [Hash Table N] --> bucket candidates --/

Regime where it wins: streaming/high-churn workloads needing cheap O(1) insert and no graph-edge maintenance. Real system embodying it: production ANN engines built directly on Datar, Immorlica, Indyk & Mirrokni 2004's p-stable LSH family without a graph layer. Why rejected: recall-per-memory is dominated by HNSW at the target recall floor (M8 vs M1); kept as a Phase (§17) rather than the primary index.

AA3 — GPU Brute-Force Batch Search

  Query batch (GPU) --> dense matrix multiply against all stored vectors
                     --> top-k via GPU-resident partial sort
                     --> exact result, zero recall loss

Regime where it wins: offline batch recomputation, moderate dataset sizes fitting GPU memory, zero recall loss required. Real system: FAISS-GPU (Johnson, Douze & Jegou 2019). Why rejected: introduces a hard GPU-hardware dependency that conflicts with the embeddable-library deployment model (§1); deferred to §35.

AA4 — Disk-Resident Graph Index (DiskANN-style)

  In-memory: compressed (PQ) navigation layer over all nodes
  On-disk:   full-precision vectors + adjacency lists, paged in per query
  Query: navigate compressed layer --> page in full-precision candidates from SSD
         --> exact re-rank

Regime where it wins: dataset far exceeds RAM (§29's ceiling); cost-sensitive deployments unwilling to pay for all-RAM capacity. Real system: DiskANN (Subramanya, Devvrit, Simhadri, Krishnaswamy & Kadekodi 2019, Microsoft Research). Why rejected: adds SSD I/O scheduling and a second on-disk format on top of Phase 7's persistence design; deferred to §35 pending a dataset that actually exceeds the §29 in-memory ceiling.
