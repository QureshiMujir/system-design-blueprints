vecdb-server is the process boundary and the only network-trust boundary (§22). vecdb-shard fans a query out to independently-owned collections and merges per-shard top-k into a global top-k (P10); it is absent in single-shard embedded deployments. Each Collection owns exactly one active index type (HNSW, IVF/IVF-PQ, or LSH) plus the always-present vecdb-flat oracle used only in conformance/testing, never on the production query path at scale. vecdb-filter sits between index candidate generation and result return, applying metadata predicates in pre- or post-filter mode (ADR-10). vecdb-core supplies the shared Vector/Metric/distance-kernel foundation every index type calls into. vecdb-storage is the sole durability boundary: every mutating operation above it is only "committed" once the WAL records it (P7, I5).

8. Domain Model / Protocol / Data Model

Snapshot Binary Layout

Header {
  magic:      [u8; 4]   = "VDB1"
  version:    u32
  dim:        u32
  metric:     u8        // 0=L2, 1=Cosine, 2=DotProduct
  index_kind: u8        // 0=Flat, 1=Hnsw, 2=IvfPq, 3=Lsh
  count:      u64
}
VectorRecord[count] {
  id:      u64
  vector:  f32[dim]
}
IndexTrailer  // one of: HnswGraphSnapshot | IvfPqSnapshot | LshSnapshot

WAL Record Layout

WalRecord {
  seq:    u64          // strictly monotonic per segment (I14)
  op:     u8           // 1=Insert, 2=Delete, 3=Checkpoint
  id:     u64
  dim:    u32           // 0 for Delete/Checkpoint
  vector: f32[dim]      // absent for Delete/Checkpoint
  crc32:  u32           // covers all preceding bytes of this record
}

Metadata Predicate Grammar (EBNF)

predicate  ::= term ( ("AND" | "OR") term )*
term       ::= "NOT" term | "(" predicate ")" | comparison
comparison ::= field op value
op         ::= "=" | "!=" | "<" | "<=" | ">" | ">=" | "IN"
field      ::= identifier
value      ::= number | string | "[" value ("," value)* "]"

From Event To

Worked Example

Insert three vectors v1=(1,0), v2=(0,1), v3=(0.9,0.1) under Metric::Cosine into an HNSW collection with M=2. Query q=(1,0), k=2. Expected: v1 (distance 0) ranks first, v3 (near-parallel to v1) ranks second, v2 (orthogonal) ranks last — vecdb-flat confirms this ordering exactly; HNSW must reproduce it at ef_search≥2 (I3).

Malformed-Input Example

A snapshot file whose Header.magic is "VDB0" (wrong version family) is rejected at load with VecDbError::CorruptSnapshot before any VectorRecord is read (I15); the loader never attempts a "best-effort" partial parse of a foreign format.

Failure-Path Example

A WAL segment whose final record has a crc32 that does not match its bytes (disk corruption mid-write) is truncated at the last valid seq on replay; all earlier records replay normally, and the collection resumes from that point with the corrupt tail discarded (I14, FM-3).
