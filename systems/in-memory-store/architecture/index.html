Clients — any RESP2 or RESP3 speaker; no client-side changes required versus talking to real Redis (Principle P1).

Listener — one tokio listener task per bound (address, protocol) pair; accepts connections and hands each to a shard chosen by a fixed hash of the connection's file descriptor (round-robin at startup, sticky thereafter) so that a connection's commands always execute on the same dispatcher.

Connection — owns the per-client parse/encode buffers and all client-local state (auth, transaction, watch set, subscriptions); this is the trust boundary between an unauthenticated byte stream and an ACL-checked command.

Dispatcher — the sole mutation path into a shard's databases (I2); every command passes through lookup → arity → ACL → cluster-slot check → execute, in that order, never re-ordered.

Database — the keyspace and its cross-cutting indices (expires, watch, blocked-client, keyspace-notification matrix); one instance per SELECT-able database index, 16 per shard by default.

Persistence — reads the dispatcher's already-validated write commands; never reads the database directly outside of a snapshot handoff (P4, P8).

Replication — the same command stream persistence sees, replayed to replicas instead of a file; PSYNC2's partial-resync path is what makes short disconnects cheap (P5).

Data-type encodings — every collection type exposes exactly two encodings behind a vtable; the dispatcher never branches on encoding, only on ObjectType (P3).

Background tasks — active-expire and eviction never hold the dispatcher mutex for more than their configured budget (I2, Pitfall in §18.6).

Cluster — a slot map, not a hash ring (P6); gossip converges slot ownership across nodes without an external coordinator (ADR-10).

Three properties recur throughout this document. First, the dispatcher is single-threaded per shard; concurrency comes from sharding, not from locking (P2, ADR-05) — this is the choice antirez made in 2009 and the one this project re-makes, and it is what removes every reader-writer-lock bug class from the codebase. Second, the data path is one-way: bytes flow up from the listener into the dispatcher, mutate the database, and flow back down through the encoder; persistence and replication read the dispatcher's command stream, never the database directly. Third, every data type has exactly two encodings, and the conversion threshold is part of the type's invariant (I3); the dispatcher never reasons about encodings, it asks the type's vtable.

8. Domain Model / Protocol / Data Model

8.1 RESP2 Wire Grammar (EBNF)

frame        = simple-string | error | integer | bulk-string | array ;
simple-string = "+" , text , CRLF ;
error         = "-" , text , CRLF ;
integer       = ":" , [ "-" ] , digit+ , CRLF ;
bulk-string   = "$" , length , CRLF , [ length*OCTET , CRLF ] ;
array         = "*" , count , CRLF , frame* ;
length        = "-1" | digit+ ;        (* "-1" = nil bulk string *)
count         = "-1" | digit+ ;        (* "-1" = nil array *)
text          = OCTET* - (CR | LF) ;
CRLF          = %x0D.0A ;

A client request is always an array of bulk-strings (the "multi-bulk" request form); a server reply may be any frame. Applied in Phase 1 (§13.1).

8.2 RESP3 Extensions (EBNF delta)

map      = "%" , pair-count , CRLF , (frame , frame)* ;
set      = "~" , count , CRLF , frame* ;
boolean  = "#" , ("t"|"f") , CRLF ;
double   = "," , float-text , CRLF ;
bignum   = "(" , digit+ , CRLF ;
verbatim = "=" , length , CRLF , 3OCTET , ":" , (length-3)*OCTET , CRLF ;
push     = ">" , count , CRLF , frame* ;
null     = "_" , CRLF ;
streamed = "$?" , CRLF , ( ";" , chunk-len , CRLF , chunk-len*OCTET )* , ";0" , CRLF ;

A RESP2 connection parsing any of these tags is a protocol error; the connection's negotiated protocol field (set by HELLO) gates acceptance. Applied in Phase 1 (§13.2).

8.3 Worked Examples

SET foo bar EX 10, wire request (RESP2): *5\r\n$3\r\nSET\r\n$3\r\nfoo\r\n$3\r\nbar\r\n$2\r\nEX\r\n$2\r\n10\r\n → reply +OK\r\n.

ZADD leaderboard 100 alice, wire request: *4\r\n$4\r\nZADD\r\n$11\r\nleaderboard\r\n$3\r\n100\r\n$5\r\nalice\r\n → reply :1\r\n (one new member added).

HELLO 3 reply (RESP3 map form) vs the RESP2-flattened equivalent of the same logical map — this is the P1/I11 dual-mode encoding in miniature: RESP3 emits %7\r\n$6\r\nserver\r\n$5\r\nredis\r\n...; RESP2 emits the same 14 elements as *14\r\n$6\r\nserver\r\n$5\r\nredis\r\n... — one flat array, alternating key/value.

8.4 Storage Record Layouts

RedisObject header (fixed 12 bytes + pointer): kind: u8 (ObjectType) | encoding: u8 | lru_or_lfu: u32 (24-bit LRU clock or 8-bit logc + 16-bit decr-time, mode selected by maxmemory-policy) | refcount: u32 | ptr: ObjectPtr (8 bytes, tagged pointer/inline union).

Listpack (compact encoding for list/hash/set/zset): header total-bytes: u32 LE, num-elements: u16 LE (0xFFFF sentinel means "count by scan"), then a sequence of {encoding-byte, payload, backlen} entries (backlen enables O(1) reverse traversal), terminated by a single 0xFF byte.

Quicklist node (full encoding for lists ≥ threshold): a doubly-linked list of nodes, each holding one listpack of up to list-max-listpack-size entries; each node carries count: u16, sz: u32 (compressed byte size), compressed: bool (LZF compression of cold nodes, PhaseDeferred("Deferred Features Register")).

Intset (compact encoding for all-integer sets): header encoding: u32 LE (2, 4, or 8 — narrowest width that fits every member), length: u32 LE, then a sorted array of fixed-width signed integers; insertion upgrades the width in place if a new member exceeds the current one.

Skiplist node (full encoding for sorted sets, keyed by (score, member)): see §11.5 for the exact field signatures; span at each level is the exact node count skipped — the value this document's I13 protects.

8.8 Failure-Path Example

An AOF rewrite child (§17.2) crashes after writing 60% of the new file. The dispatcher continues appending to the old AOF and to the in-memory rewrite buffer throughout — the old file is never truncated until the new one is confirmed complete via a trailing checksum record. On restart, the loader (§17.4) detects the new file's missing/short checksum trailer, discards it, and loads the old AOF instead — zero data loss, one skipped rewrite (telemetry: store_aof_rewrite_failures_total increments; Pitfall cross-reference: §17.8).

Design principles (§6)

  • P1 — Wire compatibility is the contract. Every byte the engine emits is the byte real redis-cli and client libraries expect. Tradeoff: forecloses inventing a cleaner protocol. Operational implication: the conformance suite (§28) replays recorded traces and asserts byte-identical responses. Violation: any deviation silently breaks every client library in the wild, not just ours.
  • P2 — One dispatcher per shard. Concurrency comes from sharding, never fine-grained locking. Tradeoff: no intra-shard parallelism. Operational implication: throughput scales with shard count up to core count (§4). Violation: introducing a lock inside a shard reintroduces the entire reader-writer-lock bug class this design exists to avoid.
  • P3 — Two encodings per data type. Compact (listpack/intset) for small collections, full (hashtable/skiplist/quicklist) otherwise; conversion is one-way. Tradeoff: a key that shrinks below threshold never reverts, wasting some memory. Operational implication: OBJECT ENCODING is a supported introspection surface operators rely on. Violation: skipping compact encodings inflates per-key memory 3–8× on small-collection-heavy workloads (I3).
  • P4 — Persistence is asynchronous; durability is configurable. AOF buffers and flushes on a cadence (always/everysec/no); RDB snapshots never block the dispatcher. Tradeoff: everysec accepts up to 1s of data loss. Operational implication: the durability knob is a documented SLA, not an implementation detail. Violation: a synchronous fsync on the dispatcher thread freezes every shard client (§17.8).
  • P5 — The command log is the source of truth for replication. AOF and replication share one serialization path. Tradeoff: replication cannot diverge from persisted state by design. Operational implication: PSYNC2 partial resync reuses the same backlog format as AOF framing. Violation: a second, independent replication encoding doubles the surface for wire-format bugs.
  • P6 — The cluster is a slot map, not a hash ring. 16,384 fixed slots, gossiped ownership. Tradeoff: re-sharding is coarser-grained than ring rebalancing. Operational implication: MOVED/ASK redirection is deterministic and inspectable via CLUSTER SLOTS. Violation: substituting consistent hashing breaks wire compatibility with every real Redis Cluster client (I7, I8).
  • P7 — No silent fallbacks. A command's documented edge-case behavior is exact, never approximated. Tradeoff: more branches per command. Operational implication: the conformance suite encodes every documented distinction (e.g. LPOP nil vs empty-array). Violation: client libraries that pattern-match on exact reply shapes break silently.
  • P8 — Determinism is the default for anything touching persistence. AOF/RDB replay is bit-deterministic given a starting point and a command log; non-deterministic commands (SRANDMEMBER, SPOP) are seeded and the seed is recorded. Tradeoff: extra bookkeeping per random command. Operational implication: replay-based debugging is possible. Violation: a replica or AOF-replay that samples independently diverges from the leader silently (I4).
  • P9 — Eviction policy is the store's; the algorithm is delegated. The store owns the trigger (maxmemory watermark) and candidate-set construction; the LRU/LFU cache engine (project 59) owns the algorithm. Tradeoff: a crate boundary between trigger and algorithm. Operational implication: eviction policies are swappable without touching the dispatcher. Violation: inlining eviction logic into the dispatcher couples two independently-evolving concerns (ADR-12).
  • P10 — Strings are bytes. Never validated as UTF-8, never interpreted except in the documented numeric-conversion commands. Tradeoff: no built-in encoding safety net for application bugs. Operational implication: binary-safe keys and values are a first-class guarantee. Violation: any UTF-8 validation on the write path silently corrupts binary payloads (image blobs, protobuf, etc.).
  • P11 — Backpressure over unbounded buffering. A slow client is bounded and eventually disconnected, never allowed to grow the server's memory without limit. Tradeoff: a legitimately slow-but-valid subscriber can be dropped. Operational implication: client-output-buffer-limit is a tunable, documented SLA (ADR-22). Violation: unbounded per-connection buffers turn one slow subscriber into a cluster-wide OOM (T5, FM-6).
  • P12 — Fail closed on ambiguity. ACL and auth decisions default-deny when a rule set is partial or conflicting. Tradeoff: a misconfigured ACL rejects more than a permissive default would. Operational implication: ACL LIST/ACL GETUSER must always show the effective, fully-resolved rule set, not just the configured deltas. Violation: default-allow on ambiguity is the root cause class of most real-world ACL privilege-escalation incidents.
  • P13 — Observability is not optional. Every subsystem emits a trace span and a metric; a subsystem that cannot be measured cannot be operated. Tradeoff: instrumentation overhead on the hot path (bounded, see M-table §30). Operational implication: the dashboards in §26 are buildable from day one, not retrofitted. Violation: an uninstrumented subsystem is undebuggable in production by construction, not by accident.
  • P14 — Configuration is versioned and reloadable without full data loss. CONFIG SET applies at runtime where safe (maxmemory, appendfsync); restart is required only where correctness cannot otherwise be guaranteed (cluster-enabled). Tradeoff: a two-tier config model (hot-reloadable vs restart-required) is more complex than "everything requires restart." Operational implication: CONFIG GET/CONFIG SET/CONFIG REWRITE must agree with the running process, not just the file on disk. Violation: a config surface that silently ignores a runtime CONFIG SET produces the exact "why didn't my change take effect" incident class operators hate most.
