Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does PSYNC2's secondary replication ID matter more than the backlog size itself when a leader fails over? (§19.2, §19.6)
  2. Under what write-rate/disconnect-tolerance combination does the default 1 MiB backlog force a full resync, and how would you recompute the right size for your own workload? (§19.4, §34)
  3. Why is "single-threaded per shard" not the same claim as "single-core"? What breaks if an implementer conflates the two? (§3, §6 P2, §31)
  4. Trace what happens to a MULTI/EXEC transaction whose keys span two cluster slots, and why the store cannot simply execute it as two separate multi-key operations. (§20.2, §22.2, I8)
  5. Why does the ASKING flag exist, and what transactional correctness property breaks during a live slot migration without it? (§20.2, §2, I8)
  6. Why is the AOF rewrite implemented as data-structure-level COW rather than fork(), and what would break if tokio's reactor were forked naively? (§17.2, ADR-21, §5 Books item 5)
  7. What is the actual difference between a corrupted RDB preamble and a corrupted AOF tail in the hybrid format, and why must the loader treat them independently? (§17.5, §8.8, FM-2)
  8. Why does I13 (skiplist span correctness) surface as a ZRANK/ZRANGE bug but never a ZSCORE bug — what does that asymmetry reveal about how span is used versus how score is stored? (§7 I13, §15.9, §11.5)
  9. Why is "fail closed on ambiguity" (P12) specifically about ACL evaluation order, and what real incident class does getting this backwards create? (§6 P12, §21.2, §21.9)
  10. What is the actual mechanism by which a slow pub/sub subscriber threatens a whole shard's memory, and why does dropping the subscriber (rather than blocking the publisher) preserve P2's guarantees? (§6 P11, §18.7, T5/FM-6)
  11. Why does the active-expire cycle need a per-iteration time budget rather than a per-cycle key-count budget, given both bound total work? (§18.2, §18.6, I2)
  12. Compare this design's slot-map partitioning (§20) to a consistent-hash ring (§36 Alternative 4) — under what specific operational scenario does each become the wrong choice? (§20, §36, ADR-09)
  13. Why is determinism (P8) a debugging technique, not just a data-integrity guarantee — walk through how AOF replay would actually root-cause a production incident. (§6 P8, §17, MM6)
  14. What does "two encodings, one-way conversion" (P3) cost in the worst case, and where is the memory-amplification scenario when the listpack threshold is wrong? (§6 P3, §8.5, §34)
  15. Why does this design reject a global lock even though it would be simpler to implement, and what benchmark result (§30) would have to change for that tradeoff to reverse? (§6 P2, ADR-05, §30)
  16. Trace the exact sequence, invariant by invariant, that lets a client observe a write later lost after a leader crash — why is this possible even though I12 holds? (§7 I6/I12, §19.6, FM-3)
  17. Why is Redis Cluster's fixed 16,384 slots "coarser-grained" than a hash ring, and what does that cost in migration flexibility versus what it buys in gossip-payload predictability? (§20.7, §34, §36 Alternative 4)
  18. What would have to change in this design's persistence model (§17) to adopt an io_uring-based alternative (§36 Alternative 1), and why doesn't the current tokio choice (ADR-02) permit that directly?
  19. Why does the module ABI placeholder (ADR-14, §9) explicitly avoid binary compatibility with real Redis modules, and what does the Deferred Features Register (§37) reveal about the actual cost of closing that gap?
  20. Using the Comparative Architecture Table (§33) and Alternative Architecture 2's disk-tiered hybrid log (§36), explain why Aerospike's hybrid memory/flash model is not a "just add a disk tier" extension of this design, but a different point in the design space entirely.

32. Mental Models & First Principles

  1. MM1 — A shard is a single-threaded event loop; concurrency is a property of the cluster of shards, not of any one shard. Predicts the throughput ceiling is shard-count × per-shard throughput, never more. Bug class without it: reintroducing locks "for safety" inside a shard, silently re-admitting the entire reader-writer-lock class P2 exists to remove. Resolving: §3, Phase 1 (§13).
  2. MM2 — Encoding is data layout, chosen once, converted once. Predicts memory footprint given a workload's key-size distribution. Bug class without it: encoding thrash (converting back and forth) or a conversion check that misses the byte-size dimension (§15.6). Resolving: §8.5, Phase 3 (§15).
  3. MM3 — A command log is the same source of truth for durability, replication, and time-travel debugging. Predicts that AOF-replay-based root-causing works uniformly. Bug class without it: a second, independently-encoded replication path that can diverge from what AOF persists. Resolving: Phase 5 (§17), Phase 7 (§19).
  4. MM4 — A slot map is a partition function frozen at a grain coarse enough to gossip cheaply. Predicts migration granularity and gossip-payload growth with node count. Bug class without it: assuming re-partitioning is free, or that slot count should scale with node count. Resolving: Phase 8 (§20), §31.
  5. MM5 — Backpressure is a policy decision, not an emergent property. Predicts you must explicitly choose what breaks under overload (drop the slow client, never let the buffer grow unbounded). Bug class without it: FM-6's slow-consumer OOM. Resolving: P11 (§6), §18.7, §25.
  6. MM6 — Determinism is what makes distributed debugging tractable. Predicts that replaying a recorded command log reproduces a production incident exactly. Bug class without it: unseeded randomness (SPOP, SRANDMEMBER) diverging silently between a leader and its own replayed history. Resolving: P8 (§6), Phase 5 (§17), Phase 7 (§19).
  7. MM7 — Copy-on-write trades memory for time by deferring a snapshot's cost to the first mutation after it. Predicts rewrite memory cost is workload-shaped (proportional to churn during the rewrite window), not a fixed function of dataset size. Resolving: §17.2, §17.7.
  8. MM8 — A gossip protocol converges eventually, never instantly; every consumer of cluster state must tolerate a stale view. Predicts a burst of MOVED redirections immediately after any topology change, tapering as gossip converges. Bug class without it: a client or an internal subsystem that assumes CLUSTER SLOTS is always immediately authoritative. Resolving: §20.3, I7.

Reference Implementations

  • Redis (redis/redis, GitHub) — src/server.c (event loop), src/networking.c (connection I/O), src/db.c (generic key ops), src/t_string.c/t_list.c/t_hash.c/ t_set.c/t_zset.c/t_stream.c (per-type commands), src/aof.c, src/rdb.c, src/replication.c, src/cluster.c, src/dict.c, src/listpack.c, src/rax.c. Lesson: the canonical answer to "what does this command do." Pitfall: do not copy the unsafe-laden C directly — re-derive the invariant, not the pointer arithmetic. Applied throughout Phases 0–11.
  • Valkey (valkey-io/valkey, GitHub) — the Linux Foundation BSD-licensed fork post-2024 license change; the most current reference for the 8.x-era command surface. Lesson: which commands are genuinely community-maintained going forward. Pitfall: do not assume perfect parity with proprietary Redis 8+ features. Applied in Phase 2–4 (§14–§16) command-surface selection.
  • KeyDB (Snapchat/KeyDB, GitHub) — src/networking.cpp multi-threaded dispatcher patches. Lesson: what a multi-threaded-per-shard redesign costs in lock complexity. Pitfall: do not adopt its global-lock write fallback verbatim — it re-admits the lock-contention class P2 exists to avoid. Applied in Alternative Architecture 1 (§36) and ADR-06.
  • Dragonfly (dragonflydb/dragonfly, GitHub) — src/core/dash.h (the Dash hash table), src/core/compact_object.h, its io_uring event loop. Lesson: a from-scratch 2022-era redesign of the hash table and encoding layer. Pitfall: io_uring-only transport is Linux-only — do not adopt without accepting that constraint. Applied in §33, Alternative Architecture 1 (§36), ADR-02.
  • Microsoft Garnet (microsoft/garnet, GitHub) — libs/server (RESP surface), libs/storage (Tsavorite/FASTER hybrid log). Lesson: a C#/.NET from-scratch Redis-compatible server's published benchmark bar. Pitfall: Tsavorite's hybrid log tiers to disk — a fundamentally different storage model than this project's pure in-memory-plus-snapshot approach; do not conflate the two when comparing numbers. Applied in Performance Engineering (§30) and Alternative Architecture 2 (§36).
  • Memcached (memcached/memcached, GitHub) — slabs.c (slab allocator), items.c (LRU list). Lesson: the slab allocator is the simplest possible answer to fragmentation-bounded memory management. Pitfall: its LRU is coarser-grained (per-slab-class) than this project's per-key approximated-LRU sampling — do not assume equivalent eviction precision. Applied in Comparative Architecture Table (§33) and Phase 6 (§18.2).

Glossary (§38) · 53 terms · site-wide glossary

RESP
REdis Serialization Protocol; the wire format (RESP2 and RESP3 variants) this engine speaks (§8.1–8.2).
RESP2
the original request/reply wire protocol: simple strings, errors, integers, bulk strings, arrays.
RESP3
the extended protocol adding maps, sets, booleans, doubles, big numbers, verbatim strings, push messages, and streamed strings, negotiated via HELLO.
AOF
Append-Only File; the persistence mechanism that logs every mutating command for replay-based durability (§17.2).
RDB
a binary point-in-time snapshot of the dataset (§17.3).
Hybrid persistence
an RDB preamble followed by an AOF tail; combines RDB's load speed with AOF's low data-loss window (ADR-07).
PSYNC2
the replication handshake/resync protocol supporting both full and partial resync, including the secondary-replication-ID mechanism for failover continuity (§19.2).
Replication backlog
a fixed-size ring buffer of recent replicated commands, enabling partial resync (§11.7, §34).
MOVED
the redirection reply a cluster node sends when a key's slot is owned elsewhere (§20.2).
ASK
the redirection reply used during live slot migration, requiring the client to send ASKING before its retry is honored on the destination node (§20.2).
Hash slot
one of 16,384 fixed partitions of the cluster keyspace, computed via CRC16 over the key or its {...} hash-tag (§8.4, ADR-18).
Gossip
the peer-to-peer protocol by which cluster nodes converge on a shared view of slot ownership and node health (§20.3).
Listpack
the compact, single-allocation encoding used for small lists, hashes, sets, and sorted sets (§8.4).
Quicklist
the full encoding for lists above the listpack threshold: a doubly-linked list of listpack nodes (§8.4).
Skiplist
the probabilistic ordered data structure (Pugh 1990) backing large sorted sets, paired with a hashtable for O(1) score lookup (§11.5).
Intset
the compact all-integer set encoding: a sorted array of fixed-width integers (§8.4).
Embstr
an embedded short string (≤44 bytes) stored inline with the RedisObject header, sharing its cache line (§8.4, §14.2).
Encoding conversion
the one-way promotion of a collection type from its compact to its full encoding once a documented threshold is crossed (§8.5, P3).
Incremental rehash
the Dict's technique of growing its hash table in small, bounded steps per operation rather than all at once, keeping worst-case per-op latency bounded (§11.2).
Active expiration
the background cycle that samples and deletes expired keys without waiting for a client read (§18.2).
Lazy expiration
deleting an expired key at the moment it is looked up by a command (§14.2).
TTL
time-to-live; the remaining lifetime of a key before automatic expiration.
Eviction policy
the configured strategy (noeviction, allkeys-lru, etc.) for reclaiming memory under the maxmemory watermark (§18.2, delegated per P9).
LRU/LFU
least-recently-used / least-frequently-used; the two families of eviction/candidate scoring this engine supports via the delegated cache-engine crate.
maxmemory
the configured memory ceiling that triggers eviction once exceeded (§4, §18.2).
WATCH/dirty CAS
the optimistic-concurrency-control mechanism aborting a queued transaction if a watched key changes before EXEC (§22.2, I9).
MULTI/EXEC
the transaction-queueing and atomic-commit command pair (§22.2).
ACL
Access Control List; the per-user rule set governing command and key-pattern permissions (§21.2).
AUTH
the command/handshake step establishing a connection's authenticated user.
mTLS
mutual TLS; both client and server present certificates, used here to map a verified client CN to an ACL username (§21.2).
Keyspace notification
a pub/sub event published on key mutation/expiration, gated by notify-keyspace-events (§18.2).
Pub/sub
the publish/subscribe messaging primitive, independent of the keyspace (§22.2).
Lua sandbox
the restricted Lua environment (os/io/loadfile/dofile stripped) that EVAL scripts execute within (ADR-13, T8).
EVAL/EVALSHA
execute a Lua script verbatim or by its cached SHA-1 (§22.2).
Module ABI
the extern "C" extension-point surface for loadable command modules, not binary-compatible with real Redis modules in this specification (ADR-14).
Cluster bus
the dedicated inter-node port (client port + 10000) carrying gossip traffic (§20.2).
Config epoch
a monotonically increasing per-node version number used to resolve slot- ownership conflicts during cluster convergence (§11.6, I7).
Slot migration
the live process of moving a hash slot's keys from one node to another, using the MIGRATING/IMPORTING state pair (§20.2).
Failover election
the epoch-based voting protocol by which a replica is promoted after its leader becomes unreachable (§20.2).
HyperLogLog (HLL)
a probabilistic cardinality estimator with bounded error, sparse/dense encodings (§16.2, Heule et al. 2013).
Geohash
the 52-bit interleaved-bit encoding used to represent geospatial coordinates as a sortable integer score (§16.2).
Bitmap
a string interpreted as a bit array for SETBIT/GETBIT/BITCOUNT/etc. (§16.2).
Radix tree (rax)
the prefix-tree structure backing stream storage, keyed by entry ID (§16.2).
Consumer group
a named, stateful reader group over a stream, tracking per-consumer pending entries (§16.2).
PEL (Pending Entries List)
the per-consumer-group record of delivered-but-unacknowledged stream entries (§16.2).
COW (Copy-on-Write)
the technique of deferring a data clone until the first mutation after a snapshot point, used for AOF-rewrite snapshotting without fork() (ADR-21, MM7).
fsync
the syscall that forces buffered writes to durable storage; the basis of the appendfsync durability tiers (§17.2).
Backpressure
the policy of bounding a slow consumer's resource cost rather than letting it grow unbounded (P11, ADR-22).
SLOWLOG
the ring buffer recording commands exceeding a configured latency threshold (§23.2).
OpenTelemetry span
a single traced unit of work in the distributed-tracing model (ADR-15, §23.2).
Prometheus metric
a named, labeled time series exposed at :9121/metrics for pull-based scraping (ADR-16, §23.2).
Dispatcher
the single-threaded command-execution loop owning one shard's databases (§11.3, P2).
Shard
one of N independent partitions of the keyspace and its own dispatcher, connections, and databases (§11.3).
