Hard questions (§33)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why is the DAG runner's crash-recovery correct even though it only replays the last StepOutput, not full event history like Temporal? — §8.3, §29 (MM6).
  2. Under what load does the single-Postgres-lock model (I1) stop scaling, and what is the first lever pulled? — §29, §32 item 5.
  3. Why does a Reviewer timeout resolve to block rather than approve, and what principle does this encode? — §17.8, P11, I3.
  4. Trace the exact path a hardcoded secret takes from Coder output to being blocked — which two independent mechanisms both catch it, and why is that duplication deliberate? — §17.2, §22 T3, MM8.
  5. Why is terraform plan a mandatory precondition for apply even when the Reviewer has already approved the plan artifact? — §16, §18.6, MM5.
  6. What specifically prevents the Monitor agent's own auto-fix pipeline from becoming an incident itself, and how is that detected in production, not just in simulation? — §21.2, §21.9, FM-9.
  7. Why does content-addressing (ADR-13) make idempotent retries "free," and what would break if artifact IDs were sequential instead? — §11, I5, MM6.
  8. Compare the failure-visibility difference between a blocked Run and a failed Run — why does the design distinguish them at all instead of one terminal "not succeeded" state? — §8.3, §17.3, §18.4.
  9. Why is one Terraform state scoped per pipeline run rather than one shared state per customer account, and what real-world Terraform footgun does this avoid? — §16.6, §31 (Terraform Cloud comparison).
  10. What would have to change in the Agent Contract (§11) to add a fifth pipeline role without touching the DAG schema? — §11, ADR-02, §21.
  11. Why does the sandbox egress allow-list differ per agent role rather than per org, and what threat does per-org scoping fail to catch? — I13, T3, T6.
  12. Explain why a 5-column ADR table (without "when the rejected choice wins") would have hidden the real regime under which LangGraph or Argo should be chosen instead — §9 ADR-02, §31.
  13. Why does the stack-adapter maturity ladder gate at "DevOps-plan green" before "Deploy green," and what does skipping that rung risk? — §20.2.
  14. Derive, from §4's constraints alone, the worker-node count needed to sustain 20 concurrent pipelines per org — do not just quote §32; show the division. — §4, §32 item 2.
  15. Why is the audit hash chain "tamper-evident," not "tamper-proof," and what operational process compensates for that gap? — §22 T10, §23 FM-6, I7.
  16. What is the concrete difference between the Coder retry-on-tsc-failure policy (§14) and the Tester retry-on-flaky-test policy (§15), and why do they have different retry counts? — §14.2, §15.2, ADR-15.
  17. Why does Phase 8 forbid any diff to apps/orchestrator, and what CI mechanism actually enforces that rather than relying on code review alone? — §20.4, §20.6.
  18. If the LLM provider used by ModelClient suffers a full outage, trace exactly which invariant prevents pipelines from silently hanging forever. — I6, §11, §23 FM-7.
  19. Why would a fully event-driven (push-based) Monitor trigger be worse at small scale but better at very large scale than the fixed 15-minute poll? — §9 ADR-20, §29.
  20. What single design choice would need to change first if AIDO had to support a second cloud provider (GCP) as a deploy target, and why is it deferred rather than built now? — §1, §35, §34 Alternative 4.

30. Mental Models & First Principles

ID Insight Predicts Bug Class Without It Applied In
MM1 A Run is a state machine; the DAG runner is its reconciliation loop, not its author The runner can always be restarted and will converge to the same state (Kubernetes controller model, Burns/Beda/Hightower) "Restart logic" that special-cases resume instead of just re-deriving ready-set from stored state §13, §8.3
MM2 An agent is a bounded, budgeted function call chain, not an autonomous being Every "agent decision" is attributable to a specific ModelClient call with a specific budget Unbounded cost/latency from treating an agent as if it "decides" outside any budget §21, §32
MM3 Sandboxes are the trust boundary; the egress allow-list is the actual security control, not the LLM's good behaviour Security holds even if the model is fully adversarial Relying on prompt instructions ("don't leak secrets") as a security control §13, §22 T3
MM4 The Reviewer is a policy gate, not a second opinion A binding verdict changes the failure mode from "silent bad deploy" to "observable block" — the goal is observability, not perfect judgment Treating a Reviewer block as a bug to route around instead of a signal to investigate §17
MM5 terraform plan/apply is optimistic concurrency control over infrastructure A plan computed against state that has since drifted must be re-computed, never blindly applied Applying a stale plan against drifted state (classic Terraform footgun) §16, §18
MM6 Content-addressing turns idempotency into a property of storage, not of code Re-running a step against the same inputs is a cache hit, not a re-execution, without any code-level idempotency check Hand-rolled idempotency keys that drift from what was actually stored §11, I5, I14
MM7 Cost budgets are watchdog timers generalised to dollars and tokens A budget-bounded loop cannot become an unbounded incident regardless of what the LLM decides to do The Monitor agent's own auto-fix pipeline becoming the incident (loop, FM-9) §21, §32
MM8 Defense in depth means the prompt is a suggestion, the post-processor is the control A model paraphrase or drift never removes a mechanically-enforced check A dependency allow-list bypassed because "the prompt said not to" §14.6, T4

Required reading (§5)

Books

  • Humble, J. & Farley, D. — Continuous Delivery (Addison-Wesley, 2010), ch. 2 ("Configuration Management"), ch. 10 ("Deployment Pipeline"). Extract: the deployment-pipeline-as-a-first-class-artifact idea. Applied in §12–§18 (the DAG is the deployment pipeline, made executable).
  • Beyer, B., Jones, C., Petoff, J., Murphy, N. (eds.) — Site Reliability Engineering (O'Reilly, 2016), ch. 4 ("SLOs"), ch. 6 ("Monitoring Distributed Systems"). Extract: error budgets and the symptom-vs-cause monitoring split. Applied in §24, §28.
  • Beyer, B. et al. — The Site Reliability Workbook (O'Reilly, 2018), ch. 5 ("Alerting on SLOs"). Extract: multi-window burn-rate alerting. Applied in §24.
  • Kim, G., Humble, J., Debois, P., Willis, J. — The DevOps Handbook (IT Revolution, 2016), Part III ("The Technical Practices of Flow"). Extract: the deployment-pipeline + feedback-loop pattern generalised beyond humans. Applied in §21 (Monitor agent as the automated feedback loop).
  • Kleppmann, M. — Designing Data-Intensive Applications (O'Reilly, 2017), ch. 7 ("Transactions"), ch. 9 ("Consistency and Consensus"). Extract: idempotency keys and exactly-once-effect semantics under at-least-once delivery. Applied in §8.3, §13.
  • Newman, S. — Building Microservices, 2nd ed. (O'Reilly, 2021), ch. 11 ("Microservices at Scale"). Extract: the bulkhead pattern for blast-radius containment. Applied in §13, §22.
  • Burns, B., Beda, J., Hightower, K. — Kubernetes: Up and Running, 3rd ed. (O'Reilly, 2022), ch. 1 ("Introduction"), ch. 15 ("Extending Kubernetes"). Extract: the controller/reconciliation-loop model. Applied in §30 (MM1), §34.

Papers

  • Yao, S. et al. — "ReAct: Synergizing Reasoning and Acting in Language Models" (ICLR 2023). The interleaved reason-act-observe loop. Applied in §8.2 (the observe→plan→act→verify loop), §12.
  • Schick, T. et al. — "Toolformer: Language Models Can Teach Themselves to Use Tools" (NeurIPS 2023). Structured tool-invocation as a first-class model output. Applied in §11 (StepInput/StepOutput as the tool contract).
  • Wu, Q. et al. — "AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation" (2023, arXiv:2308.08155). Multi-agent conversational orchestration. Applied in §34 (Alternative Architecture 2, and why it was rejected).
  • Wei, J. et al. — "Chain-of-Thought Prompting Elicits Reasoning in Large Language Models" (NeurIPS 2022). Decomposing a single call into explicit plan steps. Applied in §8.2 (the Coder/DevOps agents' internal plan stage).
  • Chen, M. et al. — "Evaluating Large Language Models Trained on Code" (2021, arXiv:2107.03374 — HumanEval). Functional-correctness evaluation of generated code. Applied in §15.4 (conformance corpus design), §26.
  • Jimenez, C. E. et al. — "SWE-bench: Can Language Models Resolve Real-World GitHub Issues?" (ICLR 2024). Repo-scale, test-gated evaluation of agent code changes. Applied in §21 (Monitor's auto-fix pipeline acceptance test).
  • Burns, B. & Oppenheimer, D. — "Design Patterns for Container-Based Distributed Systems" (USENIX HotCloud 2016). The sidecar and per-instance-agent patterns. Applied in §13 (per-step sandbox as a disposable sidecar), §9 ADR-06.
  • Verma, A. et al. — "Large-Scale Cluster Management at Google with Borg" (EuroSys 2015). Resource-bounded scheduling under multi-tenant contention. Applied in §4 (sandbox-pool capacity), §29.

Reference Implementations

  • Kubernetes controller-manager (github.com/kubernetes/kubernetes, pkg/controller/). Lesson: reconcile-to-desired-state loops with exponential backoff. Pitfall not to copy: unbounded requeue without a budget (we cap retries — ADR-15). Applied in §30 MM1.
  • Temporal (github.com/temporalio/temporal, service/history/). Lesson: durable workflow execution via event-sourced replay. Pitfall not to copy: full event-sourcing is heavier than our resumability needs — we replay only the last StepOutput, not the full history (§8.3). Applied in §13, §31.
  • Argo Workflows (github.com/argoproj/argo-workflows, workflow/controller/). Lesson: DAG-shaped CI/CD with per-node retry/timeout. Pitfall not to copy: template sprawl (Argo's YAML templating grows unwieldy) — we keep the DAG schema in typed TS, not YAML (§11). Applied in §9 ADR-02, §31.
  • HashiCorp Terraform Core (github.com/hashicorp/terraform, internal/plans/). Lesson: plan-then-apply as optimistic concurrency control over infrastructure. Pitfall not to copy: state-file locking races under concurrent applies — we scope one Terraform state per pipeline run (§16). Applied in §16, §30 MM5.
  • BullMQ (github.com/taskforcesh/bullmq, src/classes/worker.ts). Lesson: Redis-backed job queue with stalled-job recovery. Pitfall not to copy: relying on Redis alone for durability — we make Postgres the durability source of truth and BullMQ purely the dispatch mechanism (§8.3, ADR-03). Applied in §13.
  • Google gVisor (github.com/google/gvisor, runsc/). Lesson: user-space kernel interception as a stronger sandbox boundary than seccomp alone. Pitfall not to copy: gVisor's syscall-interception overhead is real — budget for it (M4). Applied in §13, §22.

Glossary (§36) · 35 terms · site-wide glossary

Agent
a modular component performing one DAG role (Coder, Tester, DevOps, Reviewer, Monitor); implements Agent<I,O> (§11).
Agent Contract
the TypeScript interface every agent implements: id, version, inputs, outputs, retry, budget, escalation, execute (§11).
Artifact
a content-addressed bundle of bytes produced by a step; immutable, stored in S3 (§11, I5).
Audit hash chain
the append-only sequence H_n = sha256(H_{n-1}‖event_n) giving tamper-evidence over every step transition (I7).
Baseline (Monitor)
the rolling 7-day per-metric reference window used to classify healthy/attention/regression (§21.2).
Blast radius
the scope of damage a single failure can cause; bounded to one sandboxed step by design (P2).
Change-correlation detector
the Monitor subsystem that halts repeated auto-fix attempts on the same service within 24 h (§21.2, FM-9).
Conformance suite
the mandatory reference-spec + adversarial-spec test pack every agent/stack adapter must pass before release (§14.5, §17.5, §20.2).
Content-addressing
deriving an artifact's ID from the SHA-256 of its bytes, giving free dedup and idempotency (ADR-13, I5, MM6).
CostBudget
the per-step token/wall-time/dollar ceiling type (§11, I6).
DAG (Directed Acyclic Graph)
the shape of every AIDO pipeline (§8.1, §11).
DAG runner
the orchestrator subsystem that materialises the ready-set and enqueues steps (§13, MM1).
Deploy gate
the human-or-policy checkpoint between Reviewer approve and DevOps apply (I4, §18.2).
DevOps agent
generates Dockerfile/Terraform/CI workflow; runs plan then, post-gate, apply (§16, §18).
Egress allow-list
the per-agent-role network policy scoping what a sandbox may reach (I13, T3).
EscalationPolicy
the rule set determining when a step pauses for human approval, fails hard, or retries with a different model (§11).
Idempotent re-enqueue
the property that re-running a step after a crash with the same content-addressed inputs produces an equivalent result (P12, I14).
ModelClient
the single abstraction fronting every LLM provider; enforces budgets, redacts secrets, hashes prompts (§11, ADR-05).
Monitor agent
the post-deploy agent watching metrics and proposing auto-fix or auto-PR remediation (§21).
Observe→Plan→Act→Verify loop
the four-stage cycle every agent executes inside its sandbox (§8.2, Yao et al. 2023).
PipelineDAG
the materialised, topologically-sorted node/edge plan derived from a PipelineSpec (§11, §8.1).
PipelineSpec
the user-supplied paragraph intent plus structured metadata that initiates a pipeline (§11).
Reference implementation
a real, publicly inspectable system studied for a specific lesson (not copied wholesale); see §5.
RetryPolicy
the bounded-backoff rule set governing step re-attempts (ADR-15, §11).
Reviewer agent
the binding-veto gate ingesting all upstream artifacts before deploy (§17, P3, I3).
Reviewer trip-wire
an adversarial-corpus spec designed to trigger a Reviewer block; catch-rate is a phase gate (§17.4, M7).
RLS (Row-Level Security)
Postgres-enforced per-org data isolation (T9).
Run
a live execution of a Pipeline; the only mutable record among the four core entities (§11, §8.3).
Sandbox
a per-step, ephemeral, untrusted Docker (or gVisor) container (P2, I2, §13).
Stack adapter
a bundle of Coder/Tester/DevOps/Reviewer prompt templates and post-processors specialised to one tech stack (§20).
Stack Adapter Maturity Ladder
the five-stage gate (Coder→Tester→DevOps-plan →Reviewer→Deploy green) an adapter climbs before shipping past its cleared rung (§20.2).
StepInput / StepOutput
the typed envelope crossing the orchestrator↔sandbox boundary on every step execution (§11).
STS AssumeRole
the short-lived, external-ID-pinned AWS credential delegation mechanism used for every customer-cloud action (ADR-08, P4).
ULID
sortable, opaque identifier type used for all entity IDs (§11, I5 companion convention).
Warm pool
the pre-pulled per-stack sandbox image cache keeping cold-start under M4 (ADR-19, §13.7).
