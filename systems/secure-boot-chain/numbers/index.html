32. Back-of-Envelope Capacity Model

  • C1 — Concurrent attestation session memory. 10,000 sessions × 8 KB per-session evidence-cache entry (nonce + quote + trust-score state) = 80 MB working set, well inside a single attestation-service worker's memory budget.
  • C2 — Stage0 flash footprint. 256 KB Stage0 budget (§4) + 4 MB Stage1 budget (§4) = 4.25 MB reserved boot-partition flash, leaving headroom on a typical 16 MB boot-flash part for two kernel slots.
  • C3 — Manifest worst-case parse cost. 64 stage entries × ~80 B canonical CBOR each = 5.12 KB manifest body; at the 5 ms p99 budget (§4) that is ≥ 1 MB/s effective parse throughput required, comfortably below commodity CPU CBOR-decode rates.
  • C4 — TPM quote throughput vs. fleet size. 1,000 ms / 500 ms quote latency (§4) = 2 quotes/s per TPM; a 10,000-host fleet polling once per hour = 10,000 / 3,600 s ≈ 2.8 quotes/s aggregate demand, so the bottleneck is per-host TPM latency, not attestation-service fanout.
  • C5 — Telemetry ingestion bandwidth. 10,000 hosts × 1 event/s × 256 B/event = 2.56 MB/s aggregate ingestion, inside typical single-node ingestion ceilings without sharding.
  • C6 — Recovery partition storage. 4.25 MB primary image (C2) × 2 (A/B, ADR-13) = 8.5 MB reserved recovery-capable storage, plus event-log headroom.
  • C7 — File descriptor budget vs. concurrent sessions. 4,096 FD budget (§4) ÷ 10,000 target sessions = 0.41 FDs/session, so attestation-service must multiplex sessions over a shared connection pool, not one FD per session.
  • C8 — Peak RAM during boot. Stage0 ring buffer (64 KB) + Stage1 working set (≈ 32 MB manifest/context) + kernel decompression buffer (≈ 64 MB) = 96.06 MB, inside the 128 MB §4 ceiling with margin.
  • C9 — Rollback counter storage. 16-byte RollbackCounter record (§11) × 2 (active + journal shadow copy) = 32 B per host, negligible relative to any flash budget.
  • C10 — Signature verification CPU budget. 50 ms p95 (§4) × 64 possible stage-entry signatures worst case = 3.2 s theoretical worst case, mitigated by batching (§28) to keep real-world verification an order of magnitude below this ceiling.
  • C11 — Fleet-wide event-store growth. 10,000 hosts × 10 boot attempts/day × 1 KB event-log delta = 100 MB/day fleet-wide, ≈ 36.5 GB/year before the §25 retention window prunes it.
  • C12 — Cold-boot timeline budget. 250 ms verification (§4) + 500 ms TPM quote (§4) + 4.25 s kernel/initramfs (M10) = 5.0 s, exactly at the §4 cold-boot ceiling — any regression in one term must be offset elsewhere.
