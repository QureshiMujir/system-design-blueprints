3. Architectural Overview

Two paths share the CONTROL PLANE and the flux-core access-unit representation. Box names below are canonical and used verbatim in every later section.

Per-box detail (one paragraph each):

  • CONTROL PLANE — owns session lifecycle, RoomId/PeerId registry, publish/subscribe wiring, configuration, the auth seam, and observability fan-in. It resolves a signaling-negotiated RtpParameters (codecs, header-extension IDs, RID/MID map) into wired Producer/Consumer objects. It never touches media bytes; it builds and tears down the pipelines the media paths run on.
  • RTMP INGEST — terminates an inbound RTMP/TCP connection: completes the C0/C1/C2↔S0/S1/S2 handshake, demuxes the chunk stream into RTMP messages, decodes AMF connect/publish, and demuxes FLV tags into coded audio/video access units (H.264 reframed AVCC→Annex-B, AAC ASC→ADTS). Emits onto the AU bus. Untrusted: every length and index is bounds-checked; a malformed chunk yields a typed IngestError, never a panic.
  • ABR LADDER ORCHESTRATOR — owns the rendition ladder (rungs: resolution × bitrate). It issues a LadderSpec (rungs + GOP cadence + forced-IDR-at-segment-boundary policy) across the EncoderBoundary to the external encoder (#291), ingests the resulting RenditionTrack[], and verifies IDR/GOP alignment before any rendition is packaged. It is the enforcement point for the cross-rendition alignment invariant.
  • EncoderBoundary — a trait seam, not an implementation. flux never encodes. In pass-through mode the single ingested rendition is the only rung; in ladder mode the boundary represents an external transcode farm. Output access units are assumed already coded; the boundary only declares timing and keyframe contracts.
  • fMP4/CMAF PACKAGER — converts an aligned RenditionTrack into ISO-BMFF: one init segment (ftyp+moov with trak/mvex/trex) per rendition, then media segments (styp+moof+mdat, with tfdt base-decode-time, trun sample table, optional sidx). CMAF-conformant so one segment set feeds both HLS and DASH. Single-pass, zero-copy over the AU payloads.
  • MPEG-TS PACKETIZER — the legacy HLS container path: wraps access units in PES, multiplexes into 188-byte transport packets with PAT/PMT, carries PCR for timing, sets the random-access indicator on IDR. Emitted only for HLS clients that require TS; CMAF is preferred. Shares the segmenter's boundaries.
  • SEGMENTER — decides segment and (LL) part boundaries. A segment closes on an IDR at/after the target duration (segment-on-IDR), guaranteeing each media segment is independently decodable; a part closes every part-target interval within a segment. It stamps durations and notifies the manifest generators and the origin store atomically with publication.
  • DRM / CENC — optional subsample AES encryption of mdat sample data using cenc (AES-CTR) or cbcs (AES-CBC pattern); writes senc/saiz/saio and a pssh box with system IDs and key IDs into the init/media segments. Keys arrive via the KeyProvider seam (license servers deferred).
  • HLS MANIFEST GENERATOR — emits the master playlist (#EXT-X-STREAM-INF per rung, #EXT-X-MEDIA for alt audio) and per-rendition media playlists (#EXTINF, #EXT-X-TARGETDURATION, #EXT-X-MEDIA-SEQUENCE, #EXT-X-MAP for the init segment; #EXT-X-PART/#EXT-X-PRELOAD-HINT/#EXT-X-RENDITION-REPORT for LL-HLS; #EXT-X-ENDLIST for VOD). Never advertises a segment the store has not yet published.
  • DASH MPD GENERATOR — emits the MPD XML: Period → AdaptationSet (per media type) → Representation (per rung) with a SegmentTemplate ($Number$/$Time$) or SegmentTimeline. type="static" for VOD, type="dynamic" with availabilityStartTime/minimumUpdatePeriod/availabilityTimeOffset for live/LL-DASH.
  • ORIGIN / SEGMENT STORE — the publication boundary and HTTP origin. Holds init + media segments + current manifests in a per-rendition ring bounded by the DVR window; serves them over HTTP/1.1+2 with range and conditional requests; implements LL-HLS blocking playlist reload (hold the response until the requested media-sequence/part exists or a timeout fires). It is the single source of the "segment exists before it is referenced" invariant.
  • RTP/RTCP DEMUX — the SFU entry point. Receives decrypted RTP/RTCP from the transport adapter (the SRTP seam), demultiplexes by SSRC/payload-type into the owning Producer, parses RTP header extensions (abs-send-time, TWCC sequence, MID, RID), and routes RTCP (SR/RR/feedback) to the right control object.
  • PRODUCER — one inbound media source (one per simulcast RID / SVC SSRC). Owns the NACK RESPONDER / JITTER BUFFER: a sequence-ordered packet cache for retransmission and reordering, simulcast-layer demux, and parameter-set tracking. It hands packet/AU references (not copies) to the ROUTER.
  • ROUTER — the per-room forwarding fabric. Maintains the producer→consumer subscription graph; for each inbound packet, fans a reference out to every subscribed CONSUMER. It is policy-free mechanism; what to forward (which layer) is the LAYER SELECTOR's decision.
  • CONSUMER — one outbound forwarded stream to one subscriber. Rewrites SSRC (to a stable per-consumer value), rewrites RTP sequence numbers and timestamps to remain continuous across layer switches and dropped packets, fixes the marker bit on frame boundaries, and applies the abs-send-time/TWCC extensions for the egress path.
  • LAYER SELECTOR — per consumer, maps the BWE estimate to a discrete forwarded layer (simulcast spatial rung and/or SVC temporal/spatial layer; AV1 via dependency descriptor). On an up-switch it requests a keyframe through the KEYFRAME MANAGER; on a down-switch it drops the higher layer at a clean boundary. Enforces keyframe-before-delta for the new layer.
  • BWE / CONGESTION CONTROLLER — Google Congestion Control: a delay-based estimator (arrival-time/trendline filter over TWCC feedback) and a loss-based AIMD controller over RR/NACK loss reports, fused to a single target send rate per consumer, with periodic probing. Output is a bitrate the LAYER SELECTOR discretizes.
  • PACER — a leaky/token-bucket shaper that smooths the forwarded packet egress to the BWE target, preventing the bursts that delay-based BWE would misread as congestion. Sits between consumers and transport.
  • KEYFRAME MANAGER — issues PLI/FIR upstream (toward the producer's source) on new-subscriber join and layer up-switch, rate-limited (≤ 1 request per stream per ~500 ms) to prevent keyframe storms when many consumers switch at once.

8. Domain Model / Protocols

8.1 Media primitives and timing model

The shared currency of both paths is the access unit (AU): one coded frame (a video picture or an audio frame) with timing. flux never decodes it.

struct Timescale(u32);                 // ticks per second; video 90_000 (MPEG) or codec-clock; audio = sample rate (48_000)
struct MediaTime { ticks: i64, ts: Timescale }   // a point on a track timeline
struct AccessUnit {
  track: TrackId, rendition: RenditionId, kind: MediaKind, codec: Codec,
  dts: i64, pts: i64, duration: i64, ts: Timescale,   // dts<=pts (I19); ticks in `ts`
  keyframe: bool,                        // video: IDR/recovery point; audio: every frame
  data: Bytes,                           // AVCC (length-prefixed NAL) internally; reframed per container
  params: Option<ParameterSets>          // SPS/PPS (H.264) / VPS+SPS+PPS (HEVC) / sequence header (AV1)
}
enum MediaKind { Video, Audio, Data }
enum Codec { H264, H265, Av1, Vp8, Vp9, Aac, Opus }

Timing rules: per track, dts is non-decreasing and pts >= dts (I19); pts - dts is the composition offset (B-frame reordering). Each rendition track owns a Timescale; presentation-time alignment across renditions (I3) compares pts/ts as rationals, never raw ticks. The composition offset arrives from FLV CompositionTime (RTMP) or trun sample_composition_time_offset (BMFF).

Coded framing: internally H.264/HEVC are held as AVCC (4-byte length-prefixed NAL units, parameter sets out-of-band in params). The packager reframes to Annex-B (00 00 00 01 start codes, in-band parameter sets) only for MPEG-TS. NAL unit types (H.264): 1=non-IDR slice, 5=IDR, 6=SEI, 7=SPS, 8=PPS, 9=AUD. HEVC: 32=VPS, 33=SPS, 34=PPS, 19/20=IDR. AAC is held as raw frames + an AudioSpecificConfig (ASC); reframed to ADTS (7-byte header) for TS.

8.2 RTMP ingest protocol

Handshake (3-way, 1+1536+1536 bytes each side)

client                         server
  C0 (1B: version=0x03) ----->
                          <----- S0 (1B: 0x03)
  C1 (1536B) ------------->      S1 (1536B)  [time(4) | zero/version(4) | random(1528)]
                          <----- S2 (1536B = echo of C1)
  C2 (1536B = echo of S1) ----->

State machine: Uninit → VersionSent(C0/S0) → AckSent(C1/S1 exchanged) → HandshakeDone(C2/S2 echoed). Baseline = the simple handshake (random + echo). The Flash complex/HMAC-SHA256 digest handshake is detected by a nonzero version field and validated against the FP/FMS key; supported but not required.

Chunk stream

Each RTMP message is split into chunks (default chunk size 128 bytes, raised by SetChunkSize).

Chunk = BasicHeader MessageHeader [ExtendedTimestamp] ChunkData
BasicHeader: fmt(2 bits) csid(6 bits)
  csid==0 -> +1 byte  (csid = 64 + byte)
  csid==1 -> +2 bytes (csid = 64 + u16le)
MessageHeader by fmt:
  fmt=0 (11B): timestamp(3) msg_length(3) msg_type_id(1) msg_stream_id(4, LITTLE-endian)
  fmt=1 (7B):  timestamp_delta(3) msg_length(3) msg_type_id(1)
  fmt=2 (3B):  timestamp_delta(3)
  fmt=3 (0B):  inherit all from previous chunk of this csid
ExtendedTimestamp(4B): present iff timestamp or delta field == 0xFFFFFF

Message type ids: 1 SetChunkSize, 2 Abort, 3 Acknowledgement, 4 UserControlMessage, 5 WindowAckSize, 6 SetPeerBandwidth, 8 Audio, 9 Video, 15/18 AMF3/AMF0 Data, 17/20 AMF3/AMF0 Command, 22 Aggregate.

AMF0 / AMF3 command encoding

AMF0 type markers: 0x00 number (f64 BE), 0x01 boolean, 0x02 string (u16 len + UTF-8), 0x03 object (key/value until 0x00 0x00 0x09), 0x05 null, 0x06 undefined, 0x08 ECMA-array (u32 count hint), 0x0A strict-array, 0x0B date, 0x0C long-string (u32 len). AMF3 (used when a command is type 17): 0x04 integer (U29 var-int), 0x06 string (U29 len, ref table), 0x0A object (traits), 0x09 array. Commands carry (name: String, transaction_id: f64, command_object, ...args).

Ingest command sequence: connect(txid 1, {app, flashVer, tcUrl, ...}) → server _result(NetConnection.Connect.Success) + WindowAckSize/SetPeerBandwidth/SetChunkSize; createStream(txid 2) → _result(stream id); publish(streamName, "live"|"record"|"append") → onStatus(NetStream.Publish.Start). After publish, Audio/Video/Data messages flow.

FLV demux

FLVHeader(9B): "FLV" version(1) flags(1: bit0 audio, bit2 video) data_offset(4)=9
then: PreviousTagSize0(4)=0, [ FLVTag PreviousTagSize ]*
FLVTag: tag_type(1) data_size(3) timestamp(3) timestamp_ext(1) stream_id(3)=0 data[data_size]
  tag_type: 8=Audio, 9=Video, 18=ScriptData
VideoTagHeader: frame_type(4b: 1=key,2=inter) codec_id(4b: 7=AVC, 12=HEVC)
  AVC: avc_packet_type(1: 0=seqhdr(AVCDecoderConfigurationRecord), 1=NALU, 2=EOS)
       composition_time(3, signed)  // pts - dts, in ms*timescale
AudioTagHeader: sound_format(4b: 10=AAC) rate(2b) size(1b) type(1b)
  AAC: aac_packet_type(1: 0=ASC, 1=raw frame)
ScriptData: onMetaData ECMA-array {width,height,videocodecid,audiocodecid,framerate,...}

The avc_packet_type=0 payload is the AVCDecoderConfigurationRecord (SPS/PPS + NAL-length-size) → becomes params. aac_packet_type=0 is the ASC → params. Timestamps are milliseconds; converted to a 90 kHz video / sample-rate audio Timescale. RTMP DTS == FLV timestamp; PTS = DTS + composition_time.

8.3 ISO BMFF / CMAF box model

Box:     size(4) type(4) [largesize(8) if size==1] payload    // size==0 => extends to EOF
FullBox: Box + version(1) flags(3)

CMAF init segment (one per rendition) and media segment (fragment) box trees:

init.cmfv : ftyp[major=cmfc, compat=iso6,cmfc,dash]
            moov
              mvhd(timescale, duration=0 for fragmented)
              trak  tkhd  mdia[ mdhd(track timescale) hdlr  minf[ vmhd/smhd  dinf
                    stbl[ stsd[ avc1/hvc1/av01 -> avcC/hvcC/av1C ; or mp4a -> esds(ASC) ]
                          stts(0) stsc(0) stsz(0) stco(0) ] ] ]
              mvex  trex(track_id, default_sample_flags)        // declares fragments follow
seg-N.cmfv : styp[compat=msdh,msix]   [prft(ntp, media_time)]   // prft = ProducerReferenceTime (LL)
            moof
              mfhd(sequence_number = N)
              traf[ tfhd(track_id, tf_flags, [default_sample_duration/size/flags])
                    tfdt(baseMediaDecodeTime)                    // I10
                    trun(sample_count, data_offset,
                         per-sample{ duration?, size?, flags?, composition_time_offset? }) ]
            mdat[ concatenated sample payloads ]
            [sidx(reference_id, timescale, earliest_pts, [ref{type,size,subseg_dur,SAP}])]  // DASH index

Key box byte layouts:

Box Notable fields Bytes (after size+type[+ver/flags])
ftyp major_brand(4), minor_version(4), compatible_brands(4×N) variable
mvhd (v1) creation/modification(8 each), timescale(4), duration(8), rate(4), volume(2)… 108
tkhd (v1) track_id(4), duration(8), width/height(4 each, 16.16 fp) 92
mdhd (v1) timescale(4), duration(8), language(2) 32
tfhd track_id(4), [base_data_offset(8)], [sample_description_index(4)], [default_sample_duration(4)], [default_sample_size(4)], [default_sample_flags(4)] — presence per tf_flags variable
tfdt (v1) baseMediaDecodeTime(8) 8
trun sample_count(4), [data_offset(4, i32)], [first_sample_flags(4)], per-sample fields per tr_flags variable
sidx (v1) reference_id(4), timescale(4), earliest_presentation_time(8), first_offset(8), reference_count(2), refs(12 each) variable

CMAF constraints (DP7): one track per traf; moof+mdat pairs are self-contained; styp present on each segment; tfdt mandatory; sample durations sum exactly to the fragment duration (I10). The same .cmfv/.cmfa segments are referenced by both HLS (#EXT-X-MAP → init, #EXTINF → media) and DASH (Initialization/media templates).

8.4 MPEG-TS packet model (legacy HLS container)

TSPacket (188B): sync_byte(0x47) | TEI(1b) PUSI(1b) priority(1b) PID(13b)
                 | scrambling(2b) adaptation_field_control(2b) continuity_counter(4b)
                 | [adaptation_field] [payload]
AdaptationField: length(1) flags(1: discontinuity, random_access, ES_priority, PCR_flag, ...)
                 [PCR(48b = base 33b + reserved 6b + ext 9b)] [stuffing 0xFF]

PID assignment: 0x0000 PAT, chosen PMT PID (e.g. 0x1000), elementary PIDs (e.g. video 0x0100, audio 0x0101). PAT maps program_number → PMT_PID. PMT lists PCR_PID + streams: stream_type 0x1B (H.264), 0x24 (HEVC), 0x0F (AAC-ADTS), 0x15 (metadata). Access units are wrapped in PES packets: start_code(00 00 01) + stream_id + PES_packet_length(2) + flags + PTS/DTS (33-bit, 90 kHz, marker-bit interleaved) + payload (Annex-B NALs / ADTS frames). Invariants: continuity_counter increments per PID per payload-bearing packet (I11); PCR monotonic and spaced ≤ 100 ms; the random_access_indicator + the PES with the IDR mark a segment boundary; the first TS packet of a segment carries PAT+PMT so each segment self-describes.

Master playlist (one per stream; lists rungs + alternate renditions):

#EXTM3U
#EXT-X-VERSION:9
#EXT-X-MEDIA:TYPE=AUDIO,GROUP-ID="aud",NAME="en",DEFAULT=YES,AUTOSELECT=YES,URI="a/en.m3u8"
#EXT-X-STREAM-INF:BANDWIDTH=5300000,RESOLUTION=1920x1080,CODECS="avc1.640028,mp4a.40.2",AUDIO="aud"
v/1080.m3u8
#EXT-X-STREAM-INF:BANDWIDTH=2900000,RESOLUTION=1280x720,CODECS="avc1.64001f,mp4a.40.2",AUDIO="aud"

... (240/360/480) ...

Media playlist — VOD (#EXT-X-PLAYLIST-TYPE:VOD, ends with #EXT-X-ENDLIST), EVENT (append-only, no rewind of MEDIA-SEQUENCE), or LIVE (sliding window):

#EXTM3U
#EXT-X-VERSION:9
#EXT-X-TARGETDURATION:4                 ; >= ceil(max EXTINF)  (I12)
#EXT-X-MEDIA-SEQUENCE:1207              ; monotonic non-decreasing (I2)
#EXT-X-MAP:URI="init.cmfv"             ; init segment (I18)
#EXTINF:4.000,
seg-1207.cmfv
#EXTINF:4.000,
seg-1208.cmfv
#EXT-X-ENDLIST                          ; VOD only

LL-HLS additions inside a media playlist:

#EXT-X-PART-INF:PART-TARGET=0.333
#EXT-X-SERVER-CONTROL:CAN-BLOCK-RELOAD=YES,PART-HOLD-BACK=1.0,CAN-SKIP-UNTIL=24.0
#EXT-X-PART:DURATION=0.333,URI="seg-1209.0.cmfv",INDEPENDENT=YES   ; first part has a keyframe
#EXT-X-PART:DURATION=0.333,URI="seg-1209.1.cmfv"
#EXT-X-PRELOAD-HINT:TYPE=PART,URI="seg-1209.2.cmfv"               ; next, not-yet-complete part
#EXT-X-RENDITION-REPORT:URI="../720/index.m3u8",LAST-MSN=1209,LAST-PART=1

Blocking reload: the client requests ?_HLS_msn=1209&_HLS_part=2; the origin holds the response until that part is published or a timeout fires (I13). INDEPENDENT=YES marks a part that begins with a keyframe (so it is independently usable). CODECS strings follow RFC 6381 (avc1.PPCCLL, mp4a.40.2, av01.0.08M.08).

HLS playlist grammar (condensed EBNF):

playlist   = "#EXTM3U" line* 
line       = tag | uri | comment
tag        = "#EXT-X-" name [ ":" attr-list | ":" decimal | ":" duration ]
attr-list  = attr ( "," attr )*
attr       = NAME "=" ( decimal | hex | quoted-string | enum | resolution )
EXTINF     = "#EXTINF:" float "," [ title ]

8.6 DASH MPD (ISO/IEC 23009-1)

<MPD type="dynamic" minBufferTime="PT2S" profiles="urn:mpeg:dash:profile:isoff-live:2011"
     availabilityStartTime="2026-06-07T00:00:00Z" minimumUpdatePeriod="PT2S"
     timeShiftBufferDepth="PT30S" availabilityTimeOffset="3.5">     <!-- ATO: LL-DASH -->
  <Period start="PT0S">
    <AdaptationSet mimeType="video/mp4" segmentAlignment="true" startWithSAP="1">
      <Representation id="1080" codecs="avc1.640028" bandwidth="5300000" width="1920" height="1080">
        <SegmentTemplate timescale="90000" duration="360000"
                         initialization="v/$RepresentationID$/init.cmfv"
                         media="v/$RepresentationID$/seg-$Number$.cmfv" startNumber="1"/>
      </Representation>
      <Representation id="720" codecs="avc1.64001f" bandwidth="2900000" width="1280" height="720"> ... </Representation>
    </AdaptationSet>
    <AdaptationSet mimeType="audio/mp4"> <Representation id="aud" codecs="mp4a.40.2" bandwidth="128000"> ... </Representation> </AdaptationSet>
  </Period>
</MPD>

type="static" (VOD): fixed Periods, no minimumUpdatePeriod. type="dynamic" (live): wall-clock availabilityStartTime + $Number$ or $Time$ addressing; SegmentTimeline (explicit <S t= d= r=> runs) is used when durations vary. availabilityTimeOffset advertises a segment as available ATO seconds before its nominal completion (LL-DASH chunked transfer). The publishTime and availabilityStartTime are the only wall-clock leaks (DP11), isolated to the MPD.

8.7 Low-latency state machines

LL-HLS part lifecycle (per part): Open → Appending(chunks streamed via HTTP chunked transfer) → Complete(committed to store) → Advertised(in playlist). A part is Advertised only after Complete (I13); the PRELOAD-HINT always names the single Open/Appending part. Blocking-reload waiter states: Waiting(msn,part) → Satisfied(part Complete) | TimedOut.

LL-DASH chunked-CMAF: each segment is delivered in moof+mdat chunks via HTTP/1.1 chunked transfer; the client begins playback availabilityTimeOffset seconds before the segment completes. The prft (ProducerReferenceTime) box and <ProducerReferenceTime> MPD element anchor wall-clock to media time for the client's latency control; <Latency target= min= max=> and <ServiceDescription> advertise the target. Resync points (<Resync>) mark chunk boundaries a client can join at after a stall.

|V=2|P|X| CC  |M|   PT (7)    |       sequence number (16)      |

|                       timestamp (32)                          |

|                   synchronization source SSRC (32)            |
+---------------------------------------------------------------+
|                  contributing source CSRC[0..CC] (32 each)    |
+---------------------------------------------------------------+
| (if X) profile-defined (16) | extension length in words (16)  |
| extension data ...                                            |
+---------------------------------------------------------------+
| payload ...                                                   |

Header extensions (RFC 8285): one-byte profile id 0xBEDE, each element id(4) len-1(4) data[len]; two-byte profile 0x100x, each id(8) len(8) data. Extensions flux parses/rewrites:

Extension URI (short) Wire SFU use
abs-send-time abs-send-time 3 bytes, 6.18 fixed-point seconds delay-based BWE arrival-time model
transport-cc (TWCC) transport-wide-cc-01 2 bytes, transport sequence number sender-side BWE feedback loop
MID sdes:mid UTF-8 string demux to the right Producer (RFC 8843 bundle)
RID sdes:rtp-stream-id UTF-8 string identify a simulcast layer (RFC 8852)
repaired-RID sdes:repaired-rtp-stream-id UTF-8 RTX stream's source RID

Payload formats: H.264 (RFC 6184) — single-NAL, STAP-A aggregation (multiple NALs in one packet), FU-A fragmentation (one NAL across packets); the SFU reads only the NAL header byte to find IDR. VP8/VP9 — payload descriptors carry picture id + temporal/spatial layer + keyframe markers. AV1 — an aggregation header + OBUs, with the Dependency Descriptor header extension (§8.10) supplying layer/decode-target info so the SFU forwards selectively without parsing OBUs. RTX (RFC 4588) — retransmissions on a separate SSRC/PT with the original sequence number prefixed.

SeqNum arithmetic is 16-bit modular: a is "after" b iff 0 < (a - b) mod 2^16 < 2^15. RtpTimestamp is 32-bit modular in the codec clock. All comparisons use wraparound-safe helpers (I5/I6); naive < is a defect.

8.9 RTCP packet model (RFC 3550 / 4585 / 5104)

RTCP header: V=2(2b) P(1b) RC|FMT(5b) | PT(8) | length(16, in 32-bit words minus 1)
Compound packet = SR/RR first, then SDES, then feedback, ... (padded to 4B)
PT Name Carries
200 SR (Sender Report) sender SSRC, NTP ts(64), RTP ts(32), packet count, octet count, report blocks
201 RR (Receiver Report) report blocks: fraction_lost(8), cumulative_lost(24), ext_highest_seq(32), interarrival_jitter(32), LSR(32), DLSR(32)
202 SDES CNAME and other source descriptions
203 BYE leaving SSRCs + reason
205 RTPFB (transport feedback) FMT=1 NACK (PID + BLP bitmask); FMT=15 TWCC (transport-cc)
206 PSFB (payload-specific feedback) FMT=1 PLI; FMT=2 SLI; FMT=4 FIR (RFC 5104, SSRC + seq); FMT=15 REMB

Feedback payload layouts:

NACK (PT=205, FMT=1): [sender SSRC][media SSRC] then FCI* { PID(16) | BLP(16) }
   BLP bit i set => packet (PID + i + 1) also lost.  Up to 17 packets per FCI.
PLI  (PT=206, FMT=1): [sender SSRC][media SSRC]   (no params; "send a keyframe")
FIR  (PT=206, FMT=4): [sender SSRC][media SSRC] then FCI { SSRC(32) | seq_nr(8) | reserved(24) }
REMB (PT=206, FMT=15): [sender SSRC][media SSRC=0] "REMB"(4) num_ssrc(8) BR_exp(6) BR_mantissa(18) SSRC[num]
TWCC (PT=205, FMT=15): base_seq(16) packet_status_count(16) reference_time(24) fb_pkt_count(8)
                       packet_chunks* { run-length | status-vector } then receive_deltas*

TWCC reference_time is in 64 ms units; receive deltas are signed multiples of 250 µs; the SFU times each transport-sequence-numbered packet's arrival and reports it back to the sender's GCC. NACK BLP encodes a 16-packet window after the PID. PLI and FIR both request a keyframe (PLI = "picture lost", FIR = "full intra request, even if no loss"); the KEYFRAME MANAGER coalesces and rate-limits both (I/§4).

8.10 SFU forwarding, SSRC remapping, simulcast and SVC

Forwarding model: a Producer exposes one or more source layers; a Consumer subscribes and is fed exactly one selected layer's packets at a time, rewritten to a single stable egress SSRC + continuous sequence/timestamp (DP6, I5–I7).

struct LayerId { spatial: u8, temporal: u8 }       // simulcast: spatial=rung, temporal from codec; SVC: both from codec
struct ForwardDecision { consumer: ConsumerId, target: LayerId, request_keyframe: bool }
struct RewriteState { ssrc_out: Ssrc, seq_offset: i32, ts_offset: i64, last_seq_out: u16, last_ts_out: u32 }
  • Simulcast (RFC 8853, RID-tagged): the producer uploads N independent encodings as N SSRCs/RIDs (e.g. q=180p, h=360p, f=720p). Each has its own timestamp base and keyframes. Switching rungs requires a keyframe on the target and a timestamp/sequence realignment at the switch point.
  • SVC (VP9/AV1, one SSRC): a single layered bitstream; the SFU forwards a prefix of layers. Dropping the top spatial or temporal layer is a per-packet decision and needs no keyframe (the base layer is self-sufficient). Temporal layers (T0/T1/T2) let the SFU halve/quarter frame rate by dropping higher-T packets.
  • AV1 Dependency Descriptor (DD): an RTP header extension carrying, per packet, the frame number, spatial/temporal layer id, the frame's dependencies, decode-target indications, and chains. The SFU reads the DD to decide which packets a chosen decode target needs — enabling selective forwarding of an AV1 scalability structure (e.g. L1T3, L3T3) without OBU parsing. Forwarding a decode target requires its chain to be intact (no missing referenced frame).

Switch sequencing (simulcast up-switch q→f): (1) LAYER SELECTOR picks f; (2) request keyframe on f via KEYFRAME MANAGER (rate-limited); (3) continue forwarding q until the f keyframe arrives; (4) at the f keyframe, splice: compute new ts_offset/seq_offset so egress stays continuous (I5/I6), set the marker bit correctly, stop q, start f (I8 holds throughout). Down-switch is immediate at a frame boundary (no keyframe needed for a lower simulcast rung if it has a recent keyframe; otherwise request one).

8.11 Bandwidth estimation (Google Congestion Control)

Two estimators fused to one target send rate per Consumer (or per transport):

Delay-based (over abs-send-time or TWCC arrival times): for packet groups i, inter-group delay variation d(i) = (t_recv(i) − t_recv(i−1)) − (t_send(i) − t_send(i−1)). A trendline/Kalman filter estimates the slope m(i); an adaptive threshold γ(i) classifies the over-use detector signal as {overuse, underuse, normal}. The delay-rate controller is a state machine:

Signal \ State Hold Increase Decrease
normal → Increase stay (multiplicative/additive ramp) → Hold
overuse → Decrease → Decrease stay
underuse → Hold → Hold → Hold

Increase: A_r = η·A_r (η≈1.08, multiplicative when far from last estimate) or additive near it. Decrease: A_r = α·R_recv (α≈0.85 of measured receive rate).

Loss-based (over RR fraction_lost or TWCC-derived loss): loss < 2% → A_l ×= 1.08; 2% ≤ loss ≤ 10% → hold; loss > 10% → A_l ×= (1 − 0.5·loss).

Target A = min(A_delay, A_loss), clamped to [min,max] (I15). Probing: periodic padding/duplicate bursts to test for headroom above the current send rate. The LAYER SELECTOR discretizes A: pick the highest layer set whose cumulative bitrate ≤ A · (1 − margin); hysteresis prevents oscillation (up-switch needs sustained headroom; down-switch is prompt). REMB (receiver-estimated max bitrate) is the legacy receiver-side signal; TWCC (sender-side) is preferred and primary.

8.13 Worked examples

(a) RTMP ingest → CMAF segment → HLS+DASH (pass-through, single rung). OBS pushes 1080p H.264 + AAC over RTMP. Handshake completes; connect/createStream/publish("live"). FLV video tags: first avc_packet_type=0 → AVCDecoderConfigurationRecord → params (SPS/PPS); subsequent =1 → AVCC NALs with DTS=ts, PTS=ts+composition_time. The SEGMENTER closes a segment at the first IDR ≥ 4 s of media; the PACKAGER writes init.cmfv (ftyp+moov, avcC from params) once, then seg-1.cmfv (styp+moof{mfhd=1,tfdt=0,trun}+mdat). ORIGIN STORE commits the segment (I1), then HLS appends #EXTINF:4.000,seg-1.cmfv (MEDIA-SEQUENCE=1, I2) and DASH bumps $Number$. A player fetching the master picks a rung and pulls media segments.

(b) ABR ladder with alignment. LadderSpec = {1080p@5M, 720p@2.8M, 480p@1.4M} with forced IDR every 2 s. The external encoder returns three RenditionTracks. The LADDER ORCHESTRATOR verifies that every rung has an IDR at presentation times 0, 2s, 4s, … (I3); if 720p's IDR lands at 2.04 s, the rendition is rejected and re-requested. Once aligned, each rung is packaged independently; a client can switch 1080p→480p at any segment boundary and the first frame of the new rung's segment is an IDR (I4).

(c) LL-HLS blocking reload. Part target 333 ms. As seg-1209 is produced, the origin holds the playlist response for a client requesting _HLS_msn=1209&_HLS_part=2. When part 2 commits (I13), the held response returns the playlist now listing parts 0–2 and a PRELOAD-HINT for part 3. Latency ≈ one part + network ≈ ~0.7–1.0 s.

(d) SFU subscribe + keyframe. Peer B subscribes to peer A's video. The CONSUMER is created with a fresh egress SSRC; the LAYER SELECTOR picks the h (360p) simulcast layer from B's BWE (1.2 Mbps). KEYFRAME MANAGER sends a PLI upstream toward A for h. A's encoder emits an IDR on h; the PRODUCER caches and the ROUTER forwards it; the CONSUMER rewrites SSRC/seq/ts (first egress packet = the IDR, I8) and B begins decoding within ~1 RTT + 1 keyframe interval.

(e) Congestion → layer down-switch. B's TWCC feedback shows rising inter-group delay; the over-use detector flags overuse; the delay controller drops A_delay to 0.85·receive-rate (~0.9 Mbps). The LAYER SELECTOR, with hysteresis, down-switches h→q (180p@0.3M) at the next frame boundary — immediately, no keyframe needed (q has a recent keyframe). Egress stays continuous (I5/I6); B sees lower resolution, never a freeze (DP4).

(f) Simulcast up-switch. B's bandwidth recovers to 3 Mbps and holds for the hysteresis window. LAYER SELECTOR picks f (720p); KEYFRAME MANAGER PLIs f (rate-limited — coalesced with other consumers switching to f); at f's IDR the CONSUMER splices with recomputed offsets (I6) and B steps up to 720p.

Design principles (§6)

  • DP1 — Coded-frame agnosticism. flux moves and frames coded access units; it never inspects pixels or entropy-decodes. It reads only what packaging/forwarding require (NAL type, IDR flag, parameter sets, timestamps). Tradeoff: cannot make rate decisions from picture content (we use layers instead). Operational: a new codec needs only a payload/parameter-set adapter, not a decoder. Violation: embedding a decoder couples the server to codec licensing + CPU, and inflates the trusted computing base with a pixel pipeline.
  • DP2 — Segment-before-manifest. A media segment or part is fully written and published to the ORIGIN STORE before any manifest advertises it (I1). Tradeoff: a small extra latency hop between write and advertise. Operational: publication is atomic; manifest generation reads only committed state. Violation: a player fetches a 404 / partial segment → stall, error, abandoned session — the single most common live-streaming bug.
  • DP3 — Forward, never transcode. The SFU forwards existing encodings and selects among them; it never re-encodes. Tradeoff: adaptation granularity is limited to the layers the producer uploaded (simulcast/SVC). Operational: CPU per stream is O(packets), not O(pixels); a node scales to thousands of streams. Violation: transcoding turns an SFU into an MCU — CPU explodes, latency rises, the topology stops scaling.
  • DP4 — Drop early, drop clean. Under congestion the SFU drops layers at frame boundaries, never mid-frame and never by disconnecting. Tradeoff: the subscriber sees lower quality, not failure. Operational: degradation is graceful and reversible as bandwidth recovers. Violation: mid-frame drops corrupt the decoder; disconnects destroy sessions that a layer-drop would have preserved.
  • DP5 — Keyframe-before-delta. A consumer never forwards a delta frame for a (layer of a) decode context before delivering that context's keyframe (I8). Tradeoff: a new subscriber or up-switch waits for the next keyframe (mitigated by PLI). Operational: every decode context starts decodable. Violation: green/garbled video, decoder error concealment, or a hard decode failure on the client.
  • DP6 — Continuity under rewrite. Each consumer sees strictly continuous RTP sequence numbers, monotonic timestamps, and a single stable SSRC, regardless of upstream layer switches, drops, or producer changes (I5/I6/I7). Tradeoff: the consumer must maintain rewrite offset state. Operational: the client's jitter buffer and decoder never see the seams. Violation: a sequence gap looks like loss (spurious NACK); an SSRC change resets the client pipeline (visible glitch).
  • DP7 — CMAF once, deliver twice. One CMAF-conformant fMP4 segment set serves both HLS and DASH; TS is emitted only for clients that demand it. Tradeoff: CMAF constraints (one track per fragment, specific box order) restrict the packager. Operational: storage and origin cache are halved; one conformance surface. Violation: maintaining divergent HLS-TS and DASH-MP4 doubles storage, cache, and bug surface.
  • DP8 — Alignment is a server obligation. GOP/IDR boundaries are aligned across all renditions at identical presentation times, enforced by the LADDER ORCHESTRATOR before packaging (I3). Tradeoff: the encoder must accept forced-IDR cadence (a contract on EncoderBoundary). Operational: a client can switch rungs at any segment boundary seamlessly. Violation: misaligned IDRs make a rung switch land on a non-decodable point → stall or artifact at every adaptation.
  • DP9 — Backpressure everywhere. Every queue (AU bus, jitter buffer, NACK cache, pacer, blocking-reload waiters) is bounded; under overload the system sheds (drop layer, drop oldest, time out the reload) rather than buffering without limit (DP13). Tradeoff: shedding loses data deliberately. Operational: memory is provably bounded; no unbounded-queue OOM. Violation: an unbounded jitter buffer or AU bus turns transient congestion into an OOM crash that takes the whole node (and every room/stream on it) down.
  • DP10 — Total, bounded parsers. Every parser (RTMP chunk, AMF, FLV, ISO-BMFF, RTP, RTCP, manifest) handles all byte sequences: valid → value, invalid → typed error, with allocation bounded by validated lengths. Tradeoff: no unwrap/panic on input paths; more error plumbing. Operational: fuzzers must find zero panics. Violation: a crafted RTMP chunk or RTP extension panics or OOMs the daemon — a trivial remote DoS on an internet-facing port.
  • DP11 — Deterministic packaging. Given the same access-unit sequence and LadderSpec, the packager emits byte-identical segments and (static) manifests; wall-clock leaks only into clearly isolated dynamic-MPD fields. Tradeoff: timing must come from media timestamps, not the system clock. Operational: segments are content-addressable and cacheable; bugs reproduce from inputs. Violation: nondeterministic bytes break CDN caching (same URL, different bytes) and make incidents unbisectable.
  • DP12 — Observability of timing. Correctness here is mostly timing; every segment, part, packet, and estimate carries enough structured telemetry (decode time, media sequence, seq/ts, layer, BWE target) to reconstruct when things happened. Tradeoff: telemetry volume and care. Operational: a stall or glitch is diagnosable from logs/metrics without a packet capture. Violation: timing bugs become irreproducible "sometimes it stutters" tickets.
  • DP13 — Bounded resource usage. DVR window, NACK cache, jitter buffer, held blocking-reloads, per-room/per-consumer memory all have hard caps tied to §4. Tradeoff: old data is evicted; very deep DVR needs explicit configuration. Operational: capacity planning is arithmetic, not hope. Violation: a long-running live event or a slow subscriber grows memory without limit → eventual OOM.
  • DP14 — Wire-format stability. Emitted manifests, boxes, and RTP/RTCP conform to their specs and validate against independent oracles; output grammars are versioned and changes are deliberate. Tradeoff: no convenient nonstandard extensions. Operational: any conformant player/CDN interoperates. Violation: a near-spec manifest that one player tolerates and another rejects produces field failures that never reproduce in the lab.
