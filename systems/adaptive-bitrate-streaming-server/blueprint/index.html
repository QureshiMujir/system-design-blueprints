414 — Adaptive-Bitrate Streaming Server + SFU

Project Number: 414

Project Name: Adaptive-Bitrate Streaming Server + SFU

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

Build the server tier for adaptive media delivery — two delivery models over one ingest path and one coded-frame representation. Correctness-first, observability-second, maintainability-third, performance-fourth.

  • (a) HTTP Adaptive Streaming (HAS) — HLS + DASH; one-to-many; live + VOD; pull-based; CDN-scalable; multi-second latency; client-side ABR switching.
  • (b) WebRTC SFU (Selective Forwarding Unit) — real-time many-to-many; push-based; sub-500 ms glass-to-glass; per-subscriber layer selection; no transcoding.

Codename flux: a Rust workspace of crates + one server daemon fluxd + control CLI fluxctl + offline inspector flux-probe.

Core capability surface:

  • RTMP ingest — RTMP 1.0 handshake (C0/C1/C2 ↔ S0/S1/S2), chunk-stream demux (chunk basic + message header fmt 0–3), AMF0/AMF3 command decode (connect/publish/createStream), FLV tag demux (audio/video/script-data), H.264 AVCC↔Annex-B reframing, AAC ASC→ADTS.
  • ABR ladder orchestration — declare per-rendition rungs (e.g. 240p…1080p); enforce IDR/GOP alignment across all renditions for seamless client switching; keyframe-cadence policy; an EncoderBoundary abstraction (transcode is external, project #291).
  • Packager / segmenter — CMAF/fMP4 over ISO BMFF (ftyp/moov/moof/mdat/sidx/styp/tfdt/trun); MPEG-TS packetizer (188-byte packets, PAT/PMT/PES/PCR); init + media segments; segment-on-IDR.
  • Manifest generation — HLS m3u8 (master #EXT-X-STREAM-INF; media #EXTINF/#EXT-X-TARGETDURATION/#EXT-X-MEDIA-SEQUENCE/#EXT-X-MAP; VOD/EVENT/LIVE); DASH MPD (Period/AdaptationSet/Representation/SegmentTemplate/SegmentTimeline; static vs dynamic; $Number$/$Time$).
  • Low latency — LL-HLS (#EXT-X-PART, partial segments, blocking playlist reload, #EXT-X-PRELOAD-HINT, #EXT-X-RENDITION-REPORT); LL-DASH (chunked CMAF, availabilityTimeOffset, resync).
  • SFU core — RTP/RTCP routing without transcoding; Producer→Router→Consumer forwarding; SSRC remapping; RTP header extensions (abs-send-time, transport-cc/TWCC, MID, RID); RTCP SR/RR/SDES/BYE + feedback NACK/PLI/FIR/REMB/transport-cc.
  • Simulcast & SVC — producer multi-encoding via RID; per-consumer layer selection driven by bandwidth estimate; SVC temporal/spatial layers; AV1 dependency descriptor; selective layer forwarding.
  • Jitter buffer / retransmission — RTP reorder, NACK responder packet cache, adaptive depth, packet-loss-concealment notes.
  • Congestion control / BWE — Google Congestion Control (delay-based arrival-time/trendline + loss-based AIMD), TWCC feedback, REMB, bitrate probing; estimate→forwarded-layer mapping; leaky/token-bucket pacer.
  • Keyframe management — PLI/FIR on new subscriber or layer switch; request rate-limiting.
  • DRM — CENC common encryption (cenc vs cbcs), key IDs, PSSH boxes; Widevine/PlayReady/FairPlay key-delivery abstraction (license servers deferred).

1.1 System boundaries

This is the origin / packager / SFU forwarding tier — the server that sits above transport and above the codec. In scope: RTMP termination, packaging, manifest generation, the origin segment store, RTP/RTCP demux + routing, layer selection, BWE, NACK/keyframe management, CENC packaging. Out of scope (cross-linked, never rebuilt here):

  • #161 — WebRTC transport — ICE/STUN/TURN, DTLS-SRTP, SCTP data channels. The SFU path begins at decrypted RTP and ends at plaintext RTP handed back to transport; the SRTP boundary is a typed seam, not an implementation.
  • #291 — A/V processing pipeline — capture, scale, filter, encode/decode. flux never encodes or decodes media. The ABR ladder commands an external encoder via EncoderBoundary and verifies its output; it does not transcode.
  • A CDN edge / cache tier — flux is the origin; horizontal edge caching is an HTTP-semantics consumer of the origin, not built here.
  • A player/client, a signaling server, a license/KMS server — all are typed adapters or deferred.

1.2 Explicit non-goals

  • NOT a video/audio codec — encoding/decoding is external (EncoderBoundary → PhaseDeferred("§16") for the transcode-farm driver; flux consumes coded access units only).
  • NOT a WebRTC transport stack — ICE/DTLS/SRTP/SCTP are project #161; the SRTP seam is PhaseDeferred("§21") for the decrypt/encrypt body, modeled as a trait.
  • NOT a signaling protocol — SDP offer/answer negotiation, room join semantics are an adapter; flux consumes a resolved RtpParameters → PhaseDeferred("§21").
  • NOT a DRM license/key server — flux packages CENC and maps key IDs; license issuance (Widevine/PlayReady/FairPlay) is behind KeyProvider → PhaseDeferred("§24").
  • NOT SRT/RIST ingest in Phase 0 — modern reliable-UDP ingest noted as an alternative to RTMP; IngestSource trait reserved → PhaseDeferred("§13").
  • NOT a player-side ABR algorithm — flux publishes the ladder; rate selection is the client's (out of scope).
  • NOT analytics/QoE aggregation, ad insertion (SCTE-35 markers noted only), or subtitle rendering (timed-text pass-through only).

1.3 Deployment model

  • fluxd — a single async (tokio) daemon, two listeners: an RTMP TCP listener (ingest) + an HTTP listener (origin: manifests + segments). The SFU consumes already-decrypted RTP/RTCP frames from the transport adapter (#161) over an in-process channel and emits frames back.
  • Stateless HTTP origin — segments + manifests live in the in-memory ORIGIN / SEGMENT STORE (ring + DVR window) with an optional object-store spill; multiple origin replicas front a CDN.
  • Sticky SFU — a RoomId is pinned to one fluxd ROUTER instance; cross-node rooms (cascade) are deferred.
  • Embeddable crates — flux-core, flux-rtp, flux-fmp4 are usable as libraries independent of the daemon.

1.4 Target users

Streaming-platform engineers, live-event infrastructure teams, real-time-comms (RTC) backend engineers, and media-tooling authors who need a trustworthy, observable server substrate rather than a black-box appliance.

C++ carries the historical CVE class this project exists to avoid; Go's GC pauses are incompatible with a hard real-time forwarding tail.

1.10 Prerequisites

  • Media containers — ISO BMFF box model, MPEG-TS, FLV; the elementary-stream vs container distinction.
  • Video-coding literacy (not coding ability) — NAL units, parameter sets (SPS/PPS/VPS), IDR vs delta frames, GOP structure, AVCC vs Annex-B framing, AAC ASC/ADTS — enough to packetize and align, never to encode.
  • RTP/RTCP — sequencing, timestamps, SSRC, jitter, the feedback loop; SRTP at the boundary.
  • Congestion control — delay-based vs loss-based estimation, AIMD, pacing, the TWCC/REMB feedback formats.
  • Async networking — epoll/kqueue, backpressure, zero-copy IO, TCP vs UDP semantics.
  • Binary parsing under adversarial input — length-prefixed records, big-endian fields, bounded allocation.
  • HTTP semantics — caching, conditional/range requests, long-poll/blocking responses, HTTP/2 push vs pull.
  • Applied cryptography (consumer) — AES-CTR/CBC subsample encryption for CENC; key/IV management (not primitive design).

2. Why Build This

Unique systems knowledge taught:

  • The container/codec/transport separation — flux is exactly the layer that orchestrates coded frames without understanding their pixels. Building it teaches the precise contract between an encoder, a packager, and a transport — the seam most engineers conflate.
  • Two latency regimes from one ingest — the same access-unit stream feeds a 6–30 s pull pipeline and a sub-500 ms push pipeline. The project forces an explicit reckoning with why HAS is segment-quantized (cache-scalable, latency-costly) and why SFU is packet-granular (latency-cheap, fan-out-costly).
  • Selective forwarding — an SFU is "a router that understands media enough to drop the right packets." Implementing per-consumer layer selection from a bandwidth estimate is a masterclass in policy-over-mechanism and in the RTP/RTCP feedback control loop.
  • Adaptive bitrate as a server obligation — GOP/IDR alignment across renditions is invisible until it breaks (a switch that stalls). Enforcing it teaches cross-stream temporal coordination.
  • Manifest as a published state machine — an HLS/DASH manifest is a consistency contract: it must never advertise a segment that does not yet exist, never regress its media sequence, and (LL) must block precisely until the next part is ready.
  • Congestion control without owning the socket — GCC over TWCC feedback estimates a path the SFU does not directly measure, then maps the estimate to a discrete layer. Delay-based + loss-based fusion is the same machinery as BBR/QUIC, in a media frame.

Historical / architectural significance:

  • RTMP — Adobe Flash's ingest protocol; despite Flash's death, RTMP remains the dominant first-mile contribution protocol (OBS, hardware encoders) into 2020s live platforms.
  • HLS (Apple, 2009) and MPEG-DASH (2012) — the two HTTP adaptive standards that displaced RTMP/RTSP for last-mile delivery; CMAF (2017) unified their segment format.
  • The SFU model (mediasoup/Janus/Jitsi/LiveKit) — replaced the MCU (mix-and-re-encode) and the mesh (N² uploads) as the scalable topology for group RTC; selective forwarding is the idea that made large WebRTC calls feasible.

Engineering muscles: binary protocol parsing under adversarial input; cross-stream temporal alignment; control-loop design (BWE); cache-consistency reasoning (manifest/segment ordering); zero-copy high-throughput forwarding; differential conformance against ffprobe/mp4dump/Shaka/spec validators.

Production concepts exercised: backpressure across a fan-out, graceful degradation under congestion (layer drop, not disconnect), DVR/window memory management, versioned wire formats (manifest + box + RTP), supply-chain pinning of the tzdb-equivalent here being codec/parameter-set assumptions, and observability of a process whose correctness is mostly timing.

Cross-links:

  • #161 WebRTC transport — supplies the ICE/DTLS/SRTP/SCTP layer below the SFU; flux consumes its decrypted RTP.
  • #291 A/V pipeline — supplies the encoder behind EncoderBoundary; flux consumes its coded renditions.
  • HTTP/2 + QUIC servers — the origin's delivery substrate; LL-HLS leans on HTTP/2 prioritization.
  • Object storage / CDN — the DVR spill target and the edge that fronts the origin.
  • Congestion-control / transport projects (BBR, QUIC) — share GCC's delay-gradient machinery.

Calibration value: media servers look like "move bytes from A to B" and are in fact a parsing + temporal-alignment + control-loop + cache-consistency problem with two incompatible latency budgets sharing one ingest. Building one recalibrates an engineer's instinct for where latency actually comes from and instills the habit of validating every byte emitted against an independent spec oracle.

What Mastery Looks Like

  • Parse adversarial binary protocols without panicking — RTMP/AMF/FLV, ISO-BMFF, MPEG-TS, RTP/RTCP all total and bounded (DP10) — earned in §13 (Phase 1) and §21 (Phase 9).
  • Reason about cross-stream temporal alignment as a first-class invariant — GOP/IDR alignment across an ABR ladder (I3/DP8), not an afterthought — earned in §16 (Phase 4).
  • Treat a published manifest as a consistency contract — segment-before-manifest, monotonic sequence numbers, blocking reload as a bounded long-poll (DP2/I1/I2/I13) — earned in §17 (Phase 5) and §19 (Phase 7).
  • Design and implement a delay+loss congestion-control fusion (GCC) from first principles — trendline filter, over-use detector, AIMD, TWCC feedback — earned in §23 (Phase 11).
  • Implement selective forwarding as policy-over-mechanism — an SFU that never transcodes, switching layers only at decodable boundaries (DP3/DP5/I8) — earned in §21–§22 (Phases 9–10).
  • Build zero-copy, high-fan-out packet forwarding with provably bounded memory under backpressure (DP9/DP13, Bytes refcounting) — earned in §21 and validated in §25 (Phase 13 benchmarks).
  • Validate every emitted byte against an independent spec oracle (ffprobe/mp4dump/Shaka/DASH-IF/real players), never trusting self-consistency alone (DP14) — earned in §25 (Phase 13).
  • Reason about two incompatible latency budgets sharing one ingest — segment-quantized HAS vs packet-granular SFU — and articulate exactly why each shape is correct for its regime — earned across §3, §33 (Back-of-Envelope Capacity Model), and §38 (Alternative Architectures).

Per-box detail (one paragraph each):

  • CONTROL PLANE — owns session lifecycle, RoomId/PeerId registry, publish/subscribe wiring, configuration, the auth seam, and observability fan-in. It resolves a signaling-negotiated RtpParameters (codecs, header-extension IDs, RID/MID map) into wired Producer/Consumer objects. It never touches media bytes; it builds and tears down the pipelines the media paths run on.
  • RTMP INGEST — terminates an inbound RTMP/TCP connection: completes the C0/C1/C2↔S0/S1/S2 handshake, demuxes the chunk stream into RTMP messages, decodes AMF connect/publish, and demuxes FLV tags into coded audio/video access units (H.264 reframed AVCC→Annex-B, AAC ASC→ADTS). Emits onto the AU bus. Untrusted: every length and index is bounds-checked; a malformed chunk yields a typed IngestError, never a panic.
  • ABR LADDER ORCHESTRATOR — owns the rendition ladder (rungs: resolution × bitrate). It issues a LadderSpec (rungs + GOP cadence + forced-IDR-at-segment-boundary policy) across the EncoderBoundary to the external encoder (#291), ingests the resulting RenditionTrack[], and verifies IDR/GOP alignment before any rendition is packaged. It is the enforcement point for the cross-rendition alignment invariant.
  • EncoderBoundary — a trait seam, not an implementation. flux never encodes. In pass-through mode the single ingested rendition is the only rung; in ladder mode the boundary represents an external transcode farm. Output access units are assumed already coded; the boundary only declares timing and keyframe contracts.
  • fMP4/CMAF PACKAGER — converts an aligned RenditionTrack into ISO-BMFF: one init segment (ftyp+moov with trak/mvex/trex) per rendition, then media segments (styp+moof+mdat, with tfdt base-decode-time, trun sample table, optional sidx). CMAF-conformant so one segment set feeds both HLS and DASH. Single-pass, zero-copy over the AU payloads.
  • MPEG-TS PACKETIZER — the legacy HLS container path: wraps access units in PES, multiplexes into 188-byte transport packets with PAT/PMT, carries PCR for timing, sets the random-access indicator on IDR. Emitted only for HLS clients that require TS; CMAF is preferred. Shares the segmenter's boundaries.
  • SEGMENTER — decides segment and (LL) part boundaries. A segment closes on an IDR at/after the target duration (segment-on-IDR), guaranteeing each media segment is independently decodable; a part closes every part-target interval within a segment. It stamps durations and notifies the manifest generators and the origin store atomically with publication.
  • DRM / CENC — optional subsample AES encryption of mdat sample data using cenc (AES-CTR) or cbcs (AES-CBC pattern); writes senc/saiz/saio and a pssh box with system IDs and key IDs into the init/media segments. Keys arrive via the KeyProvider seam (license servers deferred).
  • HLS MANIFEST GENERATOR — emits the master playlist (#EXT-X-STREAM-INF per rung, #EXT-X-MEDIA for alt audio) and per-rendition media playlists (#EXTINF, #EXT-X-TARGETDURATION, #EXT-X-MEDIA-SEQUENCE, #EXT-X-MAP for the init segment; #EXT-X-PART/#EXT-X-PRELOAD-HINT/#EXT-X-RENDITION-REPORT for LL-HLS; #EXT-X-ENDLIST for VOD). Never advertises a segment the store has not yet published.
  • DASH MPD GENERATOR — emits the MPD XML: Period → AdaptationSet (per media type) → Representation (per rung) with a SegmentTemplate ($Number$/$Time$) or SegmentTimeline. type="static" for VOD, type="dynamic" with availabilityStartTime/minimumUpdatePeriod/availabilityTimeOffset for live/LL-DASH.
  • ORIGIN / SEGMENT STORE — the publication boundary and HTTP origin. Holds init + media segments + current manifests in a per-rendition ring bounded by the DVR window; serves them over HTTP/1.1+2 with range and conditional requests; implements LL-HLS blocking playlist reload (hold the response until the requested media-sequence/part exists or a timeout fires). It is the single source of the "segment exists before it is referenced" invariant.
  • RTP/RTCP DEMUX — the SFU entry point. Receives decrypted RTP/RTCP from the transport adapter (the SRTP seam), demultiplexes by SSRC/payload-type into the owning Producer, parses RTP header extensions (abs-send-time, TWCC sequence, MID, RID), and routes RTCP (SR/RR/feedback) to the right control object.
  • PRODUCER — one inbound media source (one per simulcast RID / SVC SSRC). Owns the NACK RESPONDER / JITTER BUFFER: a sequence-ordered packet cache for retransmission and reordering, simulcast-layer demux, and parameter-set tracking. It hands packet/AU references (not copies) to the ROUTER.
  • ROUTER — the per-room forwarding fabric. Maintains the producer→consumer subscription graph; for each inbound packet, fans a reference out to every subscribed CONSUMER. It is policy-free mechanism; what to forward (which layer) is the LAYER SELECTOR's decision.
  • CONSUMER — one outbound forwarded stream to one subscriber. Rewrites SSRC (to a stable per-consumer value), rewrites RTP sequence numbers and timestamps to remain continuous across layer switches and dropped packets, fixes the marker bit on frame boundaries, and applies the abs-send-time/TWCC extensions for the egress path.
  • LAYER SELECTOR — per consumer, maps the BWE estimate to a discrete forwarded layer (simulcast spatial rung and/or SVC temporal/spatial layer; AV1 via dependency descriptor). On an up-switch it requests a keyframe through the KEYFRAME MANAGER; on a down-switch it drops the higher layer at a clean boundary. Enforces keyframe-before-delta for the new layer.
  • BWE / CONGESTION CONTROLLER — Google Congestion Control: a delay-based estimator (arrival-time/trendline filter over TWCC feedback) and a loss-based AIMD controller over RR/NACK loss reports, fused to a single target send rate per consumer, with periodic probing. Output is a bitrate the LAYER SELECTOR discretizes.
  • PACER — a leaky/token-bucket shaper that smooths the forwarded packet egress to the BWE target, preventing the bursts that delay-based BWE would misread as congestion. Sits between consumers and transport.
  • KEYFRAME MANAGER — issues PLI/FIR upstream (toward the producer's source) on new-subscriber join and layer up-switch, rate-limited (≤ 1 request per stream per ~500 ms) to prevent keyframe storms when many consumers switch at once.

6. Design Principles

Fourteen non-negotiable principles. Each: tradeoff, operational implication, breakage-on-violation. Referenced by id (DP1…DP14) throughout.

  1. DP1 — Coded-frame agnosticism. flux moves and frames coded access units; it never inspects pixels or entropy-decodes. It reads only what packaging/forwarding require (NAL type, IDR flag, parameter sets, timestamps). Tradeoff: cannot make rate decisions from picture content (we use layers instead). Operational: a new codec needs only a payload/parameter-set adapter, not a decoder. Violation: embedding a decoder couples the server to codec licensing + CPU, and inflates the trusted computing base with a pixel pipeline.

  2. DP2 — Segment-before-manifest. A media segment or part is fully written and published to the ORIGIN STORE before any manifest advertises it (I1). Tradeoff: a small extra latency hop between write and advertise. Operational: publication is atomic; manifest generation reads only committed state. Violation: a player fetches a 404 / partial segment → stall, error, abandoned session — the single most common live-streaming bug.

  3. DP3 — Forward, never transcode. The SFU forwards existing encodings and selects among them; it never re-encodes. Tradeoff: adaptation granularity is limited to the layers the producer uploaded (simulcast/SVC). Operational: CPU per stream is O(packets), not O(pixels); a node scales to thousands of streams. Violation: transcoding turns an SFU into an MCU — CPU explodes, latency rises, the topology stops scaling.

  4. DP4 — Drop early, drop clean. Under congestion the SFU drops layers at frame boundaries, never mid-frame and never by disconnecting. Tradeoff: the subscriber sees lower quality, not failure. Operational: degradation is graceful and reversible as bandwidth recovers. Violation: mid-frame drops corrupt the decoder; disconnects destroy sessions that a layer-drop would have preserved.

  5. DP5 — Keyframe-before-delta. A consumer never forwards a delta frame for a (layer of a) decode context before delivering that context's keyframe (I8). Tradeoff: a new subscriber or up-switch waits for the next keyframe (mitigated by PLI). Operational: every decode context starts decodable. Violation: green/garbled video, decoder error concealment, or a hard decode failure on the client.

  6. DP6 — Continuity under rewrite. Each consumer sees strictly continuous RTP sequence numbers, monotonic timestamps, and a single stable SSRC, regardless of upstream layer switches, drops, or producer changes (I5/I6/I7). Tradeoff: the consumer must maintain rewrite offset state. Operational: the client's jitter buffer and decoder never see the seams. Violation: a sequence gap looks like loss (spurious NACK); an SSRC change resets the client pipeline (visible glitch).

  7. DP7 — CMAF once, deliver twice. One CMAF-conformant fMP4 segment set serves both HLS and DASH; TS is emitted only for clients that demand it. Tradeoff: CMAF constraints (one track per fragment, specific box order) restrict the packager. Operational: storage and origin cache are halved; one conformance surface. Violation: maintaining divergent HLS-TS and DASH-MP4 doubles storage, cache, and bug surface.

  8. DP8 — Alignment is a server obligation. GOP/IDR boundaries are aligned across all renditions at identical presentation times, enforced by the LADDER ORCHESTRATOR before packaging (I3). Tradeoff: the encoder must accept forced-IDR cadence (a contract on EncoderBoundary). Operational: a client can switch rungs at any segment boundary seamlessly. Violation: misaligned IDRs make a rung switch land on a non-decodable point → stall or artifact at every adaptation.

  9. DP9 — Backpressure everywhere. Every queue (AU bus, jitter buffer, NACK cache, pacer, blocking-reload waiters) is bounded; under overload the system sheds (drop layer, drop oldest, time out the reload) rather than buffering without limit (DP13). Tradeoff: shedding loses data deliberately. Operational: memory is provably bounded; no unbounded-queue OOM. Violation: an unbounded jitter buffer or AU bus turns transient congestion into an OOM crash that takes the whole node (and every room/stream on it) down.

  10. DP10 — Total, bounded parsers. Every parser (RTMP chunk, AMF, FLV, ISO-BMFF, RTP, RTCP, manifest) handles all byte sequences: valid → value, invalid → typed error, with allocation bounded by validated lengths. Tradeoff: no unwrap/panic on input paths; more error plumbing. Operational: fuzzers must find zero panics. Violation: a crafted RTMP chunk or RTP extension panics or OOMs the daemon — a trivial remote DoS on an internet-facing port.

  11. DP11 — Deterministic packaging. Given the same access-unit sequence and LadderSpec, the packager emits byte-identical segments and (static) manifests; wall-clock leaks only into clearly isolated dynamic-MPD fields. Tradeoff: timing must come from media timestamps, not the system clock. Operational: segments are content-addressable and cacheable; bugs reproduce from inputs. Violation: nondeterministic bytes break CDN caching (same URL, different bytes) and make incidents unbisectable.

  12. DP12 — Observability of timing. Correctness here is mostly timing; every segment, part, packet, and estimate carries enough structured telemetry (decode time, media sequence, seq/ts, layer, BWE target) to reconstruct when things happened. Tradeoff: telemetry volume and care. Operational: a stall or glitch is diagnosable from logs/metrics without a packet capture. Violation: timing bugs become irreproducible "sometimes it stutters" tickets.

  13. DP13 — Bounded resource usage. DVR window, NACK cache, jitter buffer, held blocking-reloads, per-room/per-consumer memory all have hard caps tied to §4. Tradeoff: old data is evicted; very deep DVR needs explicit configuration. Operational: capacity planning is arithmetic, not hope. Violation: a long-running live event or a slow subscriber grows memory without limit → eventual OOM.

  14. DP14 — Wire-format stability. Emitted manifests, boxes, and RTP/RTCP conform to their specs and validate against independent oracles; output grammars are versioned and changes are deliberate. Tradeoff: no convenient nonstandard extensions. Operational: any conformant player/CDN interoperates. Violation: a near-spec manifest that one player tolerates and another rejects produces field failures that never reproduce in the lab.

8. Domain Model / Protocols

8.1 Media primitives and timing model

The shared currency of both paths is the access unit (AU): one coded frame (a video picture or an audio frame) with timing. flux never decodes it.

struct Timescale(u32);                 // ticks per second; video 90_000 (MPEG) or codec-clock; audio = sample rate (48_000)
struct MediaTime { ticks: i64, ts: Timescale }   // a point on a track timeline
struct AccessUnit {
  track: TrackId, rendition: RenditionId, kind: MediaKind, codec: Codec,
  dts: i64, pts: i64, duration: i64, ts: Timescale,   // dts<=pts (I19); ticks in `ts`
  keyframe: bool,                        // video: IDR/recovery point; audio: every frame
  data: Bytes,                           // AVCC (length-prefixed NAL) internally; reframed per container
  params: Option<ParameterSets>          // SPS/PPS (H.264) / VPS+SPS+PPS (HEVC) / sequence header (AV1)
}
enum MediaKind { Video, Audio, Data }
enum Codec { H264, H265, Av1, Vp8, Vp9, Aac, Opus }

Timing rules: per track, dts is non-decreasing and pts >= dts (I19); pts - dts is the composition offset (B-frame reordering). Each rendition track owns a Timescale; presentation-time alignment across renditions (I3) compares pts/ts as rationals, never raw ticks. The composition offset arrives from FLV CompositionTime (RTMP) or trun sample_composition_time_offset (BMFF).

Coded framing: internally H.264/HEVC are held as AVCC (4-byte length-prefixed NAL units, parameter sets out-of-band in params). The packager reframes to Annex-B (00 00 00 01 start codes, in-band parameter sets) only for MPEG-TS. NAL unit types (H.264): 1=non-IDR slice, 5=IDR, 6=SEI, 7=SPS, 8=PPS, 9=AUD. HEVC: 32=VPS, 33=SPS, 34=PPS, 19/20=IDR. AAC is held as raw frames + an AudioSpecificConfig (ASC); reframed to ADTS (7-byte header) for TS.

8.2 RTMP ingest protocol

Handshake (3-way, 1+1536+1536 bytes each side)

client                         server
  C0 (1B: version=0x03) ----->
                          <----- S0 (1B: 0x03)
  C1 (1536B) ------------->      S1 (1536B)  [time(4) | zero/version(4) | random(1528)]
                          <----- S2 (1536B = echo of C1)
  C2 (1536B = echo of S1) ----->

State machine: Uninit → VersionSent(C0/S0) → AckSent(C1/S1 exchanged) → HandshakeDone(C2/S2 echoed). Baseline = the simple handshake (random + echo). The Flash complex/HMAC-SHA256 digest handshake is detected by a nonzero version field and validated against the FP/FMS key; supported but not required.

Chunk stream

8.4 MPEG-TS packet model (legacy HLS container)

TSPacket (188B): sync_byte(0x47) | TEI(1b) PUSI(1b) priority(1b) PID(13b)

                 | [adaptation_field] [payload]
AdaptationField: length(1) flags(1: discontinuity, random_access, ES_priority, PCR_flag, ...)

PID assignment: 0x0000 PAT, chosen PMT PID (e.g. 0x1000), elementary PIDs (e.g. video 0x0100, audio 0x0101). PAT maps program_number → PMT_PID. 8.10 SFU forwarding, SSRC remapping, simulcast and SVC

Forwarding model: a Producer exposes one or more source layers; a Consumer subscribes and is fed exactly one selected layer's packets at a time, rewritten to a single stable egress SSRC + continuous sequence/timestamp (DP6, I5–I7).

struct LayerId { spatial: u8, temporal: u8 }       // simulcast: spatial=rung, temporal from codec; SVC: both from codec
struct ForwardDecision { consumer: ConsumerId, target: LayerId, request_keyframe: bool }
struct RewriteState { ssrc_out: Ssrc, seq_offset: i32, ts_offset: i64, last_seq_out: u16, last_ts_out: u32 }
  • Simulcast (RFC 8853, RID-tagged): the producer uploads N independent encodings as N SSRCs/RIDs (e.g. q=180p, h=360p, f=720p). Each has its own timestamp base and keyframes. Switching rungs requires a keyframe on the target and a timestamp/sequence realignment at the switch point.
  • SVC (VP9/AV1, one SSRC): a single layered bitstream; the SFU forwards a prefix of layers. Dropping the top spatial or temporal layer is a per-packet decision and needs no keyframe (the base layer is self-sufficient). Temporal layers (T0/T1/T2) let the SFU halve/quarter frame rate by dropping higher-T packets.
  • AV1 Dependency Descriptor (DD): an RTP header extension carrying, per packet, the frame number, spatial/temporal layer id, the frame's dependencies, decode-target indications, and chains. The SFU reads the DD to decide which packets a chosen decode target needs — enabling selective forwarding of an AV1 scalability structure (e.g. L1T3, L3T3) without OBU parsing. Forwarding a decode target requires its chain to be intact (no missing referenced frame).

Switch sequencing (simulcast up-switch q→f): (1) LAYER SELECTOR picks f; (2) request keyframe on f via KEYFRAME MANAGER (rate-limited); (3) continue forwarding q until the f keyframe arrives; (4) at the f keyframe, splice: compute new ts_offset/seq_offset so egress stays continuous (I5/I6), set the marker bit correctly, stop q, start f (I8 holds throughout). Down-switch is immediate at a frame boundary (no keyframe needed for a lower simulcast rung if it has a recent keyframe; otherwise request one).

8.11 Bandwidth estimation (Google Congestion Control)

Two estimators fused to one target send rate per Consumer (or per transport):

Delay-based (over abs-send-time or TWCC arrival times): for packet groups i, inter-group delay variation d(i) = (t_recv(i) − t_recv(i−1)) − (t_send(i) − t_send(i−1)). A trendline/Kalman filter estimates the slope m(i); an adaptive threshold γ(i) classifies the over-use detector signal as {overuse, underuse, normal}. The delay-rate controller is a state machine:

Signal \ State Hold Increase Decrease
normal → Increase stay (multiplicative/additive ramp) → Hold
overuse → Decrease → Decrease stay
underuse → Hold → Hold → Hold

Increase: A_r = η·A_r (η≈1.08, multiplicative when far from last estimate) or additive near it. Decrease: A_r = α·R_recv (α≈0.85 of measured receive rate).

Loss-based (over RR fraction_lost or TWCC-derived loss): loss < 2% → A_l ×= 1.08; 2% ≤ loss ≤ 10% → hold; loss > 10% → A_l ×= (1 − 0.5·loss).

Target A = min(A_delay, A_loss), clamped to [min,max] (I15). Probing: periodic padding/duplicate bursts to test for headroom above the current send rate. The LAYER SELECTOR discretizes A: pick the highest layer set whose cumulative bitrate ≤ A · (1 − margin); hysteresis prevents oscillation (up-switch needs sustained headroom; down-switch is prompt). REMB (receiver-estimated max bitrate) is the legacy receiver-side signal; TWCC (sender-side) is preferred and primary.

8.13 Worked examples

(a) RTMP ingest → CMAF segment → HLS+DASH (pass-through, single rung). OBS pushes 1080p H.264 + AAC over RTMP. Handshake completes; connect/createStream/publish("live"). FLV video tags: first avc_packet_type=0 → AVCDecoderConfigurationRecord → params (SPS/PPS); subsequent =1 → AVCC NALs with DTS=ts, PTS=ts+composition_time. The SEGMENTER closes a segment at the first IDR ≥ 4 s of media; the PACKAGER writes init.cmfv (ftyp+moov, avcC from params) once, then seg-1.cmfv (styp+moof{mfhd=1,tfdt=0,trun}+mdat). ORIGIN STORE commits the segment (I1), then HLS appends #EXTINF:4.000,seg-1.cmfv (MEDIA-SEQUENCE=1, I2) and DASH bumps $Number$. A player fetching the master picks a rung and pulls media segments.

(b) ABR ladder with alignment. LadderSpec = {1080p@5M, 720p@2.8M, 480p@1.4M} with forced IDR every 2 s. The external encoder returns three RenditionTracks. The LADDER ORCHESTRATOR verifies that every rung has an IDR at presentation times 0, 2s, 4s, … (I3); if 720p's IDR lands at 2.04 s, the rendition is rejected and re-requested. Once aligned, each rung is packaged independently; a client can switch 1080p→480p at any segment boundary and the first frame of the new rung's segment is an IDR (I4).

(c) LL-HLS blocking reload. Part target 333 ms. As seg-1209 is produced, the origin holds the playlist response for a client requesting _HLS_msn=1209&_HLS_part=2. When part 2 commits (I13), the held response returns the playlist now listing parts 0–2 and a PRELOAD-HINT for part 3. Latency ≈ one part + network ≈ ~0.7–1.0 s.

(d) SFU subscribe + keyframe. Peer B subscribes to peer A's video. The CONSUMER is created with a fresh egress SSRC; the LAYER SELECTOR picks the h (360p) simulcast layer from B's BWE (1.2 Mbps). KEYFRAME MANAGER sends a PLI upstream toward A for h. A's encoder emits an IDR on h; the PRODUCER caches and the ROUTER forwards it; the CONSUMER rewrites SSRC/seq/ts (first egress packet = the IDR, I8) and B begins decoding within ~1 RTT + 1 keyframe interval.

(e) Congestion → layer down-switch. B's TWCC feedback shows rising inter-group delay; the over-use detector flags overuse; the delay controller drops A_delay to 0.85·receive-rate (~0.9 Mbps). The LAYER SELECTOR, with hysteresis, down-switches h→q (180p@0.3M) at the next frame boundary — immediately, no keyframe needed (q has a recent keyframe). Egress stays continuous (I5/I6); B sees lower resolution, never a freeze (DP4).

(f) Simulcast up-switch. B's bandwidth recovers to 3 Mbps and holds for the hysteresis window. LAYER SELECTOR picks f (720p); KEYFRAME MANAGER PLIs f (rate-limited — coalesced with other consumers switching to f); at f's IDR the CONSUMER splices with recomputed offsets (I6) and B steps up to 720p.

8.15 State-transition tables

Segment lifecycle (per media segment):

State Trigger Next Side effect
Forming AUs accumulating, < target duration Forming append to open mdat (or part)
Forming IDR at/after target (segment-on-IDR) Closing finalize moof/trun/tfdt (I10)
Closing bytes flushed Committed publish to ORIGIN STORE (I1)
Committed publish ack Advertised manifest references it (I2/I18)
Advertised age > DVR window Evicted remove from ring; remove from playlist

Consumer lifecycle (SFU):

State Trigger Next Side effect
New created from subscribe WaitKeyframe request PLI on target layer
WaitKeyframe target keyframe arrives Active first egress packet = keyframe (I8)
Active up-switch decision SwitchingUp PLI target; keep current layer
SwitchingUp target keyframe arrives Active splice with new offsets (I5/I6)
Active down-switch decision Active drop higher layer at frame boundary (DP4)
Active producer pause / BYE Paused stop forwarding; hold SSRC
any unsubscribe / peer leave Closed release rewrite state; free SSRC

Producer simulcast-layer state (per RID): Inactive → KeyframeWaiting(PLI sent) → Active(forwarding eligible) → Stale(no packets > timeout) → Inactive. The LAYER SELECTOR only targets Active layers.

11. Core Schema & Types

Normative APIs. Signatures only; no bodies (CRITICAL RULE 10). Each entry states ownership / mutation / concurrency / persistence / serialization semantics. Conventions: value types are Send + Sync; immutable shared media is Arc<…>; per-room state is single-writer (one tokio task); Bytes is refcounted COW; all parse fns are (&[u8]|Bytes) -> Result<T, …> (total, DP10); all box/manifest emit is &self -> Result<Bytes|String, …>.

11.1 Media primitives (flux-core)

struct Timescale(u32);                                  // Copy; ticks/sec; non-zero invariant
struct MediaTime { ticks: i64, ts: Timescale }          // Copy; rational compare across timescales (I3)
impl MediaTime { fn rescale(self, to: Timescale) -> Result<MediaTime, ArithError>; }  // checked (I20)

struct AccessUnit {                                     // owns a Bytes slice (refcounted)
  track: TrackId, rendition: RenditionId, kind: MediaKind, codec: Codec,
  dts: i64, pts: i64, duration: i64, ts: Timescale,     // dts<=pts (I19)
  keyframe: bool, data: Bytes, params: Option<Arc<ParameterSets>>,
}                                                        // Clone = refcount bump; immutable post-construction
enum MediaKind { Video, Audio, Data }
enum Codec { H264, H265, Av1, Vp8, Vp9, Aac, Opus }
struct ParameterSets { sps: Bytes, pps: Bytes, vps: Option<Bytes>, nal_length_size: u8 }  // Arc-shared; immutable
  • AccessUnit — ownership: owns data (a Bytes view into the ingest buffer; refcounted, never copied). Mutation: none after construction (frozen). Concurrency: Send + Sync; shared via Arc<AccessUnit> on the AU bus to packager + (separately) the SFU is RTP-native and does not use AU. Persistence: not persisted as a record; its bytes flow into segments. Serialization: container-specific (AVCC internal → CMAF/TS). Compatibility: adding a Codec variant is additive; downstream match is exhaustive and gated.

  • Emulation-prevention bytes (00 00 03) inside RC-BSP — when reading SPS fields you must unescape 0x03 after 00 00; forgetting it corrupts width/height parsing.
  • Cropping math — display width = (pic_width − crop)·subsampling; chroma format changes the multiplier; getting this wrong mislabels RESOLUTION.
  • SEI recovery point — some streams signal a recovery point (open GOP) not an IDR; decide whether it counts as a segment-startable keyframe (it does not for closed-GOP HLS).
  • AAC SBR/PS (mp4a.40.5/.29) — implicit vs explicit signaling changes the codec string and the sample-rate doubling; detect from ASC.

14.7 Performance Concerns

  • NAL splitting is one pass over the AU; SPS parse is per-parameter-set (rare), not per-frame.
  • Avoid re-parsing params per AU — cache derived width/height/codec-string on first SPS, invalidate on reconfig.
  • BitReader over a small Bytes window; no allocation.

14.8 Edge Cases

  • Mid-stream resolution change (new SPS) → new params, discontinuity signal for the segmenter. Multiple SPS/PPS ids. Open-GOP / recovery-point-only streams. AAC with explicit 24-bit frequency (index 15). Fragmented NAL across FLV tags (rare; reassemble). Audio sample-rate change mid-stream.

14.9 Failure Analysis

  • A mis-detected keyframe → non-decodable segment start (violates I4) downstream → player stall. Caught here against ffprobe truth. Detection: differential test in CI. Blast radius: one rendition. Recovery: re-derive from params; quarantine the AU for flux-probe.

14.10 Operational Notes

  • Metrics: flux_es_keyframes_total, flux_es_param_reconfig_total, non_idr_segment_start_total (surfaced at P3). Logs carry TrackId/RenditionId. Compatibility: a new codec is a new nal/payload adapter, not a decoder (DP1). No deployment surface; library phase feeding P3.

15. Phase 3 — Segmenter + Packagers (fMP4/CMAF + MPEG-TS)

15.1 Objectives

  • GOP-aligned segmentation (segment-on-IDR, I4) + part splitting (LL prep).
  • flux-fmp4 (§11.3): CMAF init segment (ftyp+moov) + media segments (styp+moof+mdat+tfdt+trun, optional sidx); flux-ts (§11.4): 188-byte PAT/PMT/PES/PCR muxer.
  • Constraints: single-pass zero-copy box build (DP11); CMAF once, TS on demand (DP7); byte-deterministic output (I9/I10).

15.2 Detailed Implementation Steps

  • flux-fmp4/box_writer.rs: BoxWriter writes size(placeholder)+type, records the patch offset, fills payload, back-patches size; largesize when >4 GiB (guarded). FullBox version/flags helper.
  • init_segment.rs: build ftyp(major cmfc, compat iso6,cmfc,dash) + moov(mvhd,trak{tkhd,mdia{mdhd,hdlr,minf{vmhd/smhd,dinf,stbl{stsd→avc1/hvc1/av01→avcC/hvcC/av1C, or mp4a→esds(ASC); empty stts/stsc/stsz/stco}}},mvex{trex}}). Width/height from P2.
  • media_segment.rs: styp + moof(mfhd=seq, traf{tfhd,tfdt=baseMediaDecodeTime,trun(sample durations/sizes/flags/cts-offsets, data_offset into mdat)}) + mdat(concatenated AVCC payloads). sidx.rs for DASH on-demand single-file indexing.
  • Self-check (selfcheck.rs): after build, re-parse own output — every box size==serialized length (I9); Σ trun durations == fragment duration and tfdt == cumulative prior durations (I10). Debug-fail; release counts.
  • flux-ts: ts_packet.rs (188 B, sync 0x47, PUSI, PID, CC, adaptation field), pat_pmt.rs, pes.rs (PTS/DTS 33-bit marker-interleaved), pcr.rs (48-bit, ≤100 ms spacing, monotonic, I11); muxer.rs reframes AVCC→Annex-B (P0) + ASC→ADTS, sets random-access-indicator on IDR, writes PAT+PMT at each segment start.
  • flux/src/segmenter (in flux-cli/flux-origin boundary): SegState machine (§8.15) — close a segment on the first IDR at/after target duration; split parts at part-target intervals; stamp MediaTime.

15.3 Deliverable

flux packages a live/file AU stream into CMAF init+media segments and (on demand) TS segments, written to a directory or the origin store. flux-probe boxes <seg> dumps the box tree; segments play in VLC/ffplay.

15.4 Acceptance Criteria

  • mp4dump/ffprobe parse every emitted CMAF segment with no errors; box tree diff vs a Shaka-packaged reference matches structurally.
  • Each video segment's first sample is an IDR (I4); tfdt equals cumulative prior durations (I10, asserted).
  • Byte-identical output for the same AU sequence across runs (DP11; insta snapshot gate).
  • TS: continuity counters gap-free per PID (I11); PCR monotonic ≤100 ms; ffprobe parses; CC=AAC/H.264 stream types correct.
  • fuzz_bmff_parse (self-parse) + fuzz_ts: zero panics.

15.5 Conformance Fixtures

  • conformance/fixtures/bmff/ref_init_1080p.cmfv + ref_seg_*.cmfv (Shaka/ffmpeg origin) → structural box-tree match.
  • conformance/fixtures/ts/ref_seg_*.ts → ffprobe frame parity.
  • conformance/fixtures/malformed/{trun_offset_overflow,box_size_mismatch}.bin → OffsetOverflow/BoxSizeMismatch (I9/I20).

15.6 Pitfalls

  • trun data_offset is signed i32 relative to the moof start — off-by-the-mdat-header is the classic bug; compute after the moof is sized.
  • tfdt version 0 (32-bit) vs 1 (64-bit) — long live streams overflow 32-bit decode time; always use v1.
  • mdhd/mvhd timescale mismatch — sample durations are in mdhd (track) timescale; mixing with mvhd (movie) drifts A/V sync.
  • TS PES length 0 for video — video PES may set length 0 (unbounded); the muxer must not write a wrong nonzero length.
  • CMAF box order — styp before moof; tfdt before trun; a wrong order parses in ffmpeg but fails strict players (DP14).
  • Default-flags vs per-sample flags — non-keyframe samples need sample_is_non_sync_sample=1; the first sample's first_sample_flags marks the IDR; getting this wrong makes seeking land on non-keyframes.

15.7 Performance Concerns

  • One BytesMut per segment, pre-sized from Σ sample sizes + header estimate; sample payloads are Bytes slices appended by reference where the writer supports scatter (else one copy into mdat).
  • Box self-check is cfg(feature="invariant-checks") in release to avoid a second parse pass on the hot path.
  • TS 188-byte framing is memcpy-heavy; batch writes; avoid per-packet syscalls (P8 handles IO).

15.8 Edge Cases

  • Audio-only segment (smhd, no vmhd). Mid-stream params change → new init segment + discontinuity. Very short final segment (stream end) — still IDR-started or flagged. B-frame cts_offset negative (HEVC allows negative composition offset → trun v1). Single-sample segment. Empty GOP (no frames before IDR target — wait).

15.9 Failure Analysis

  • A malformed box reaches a player → parse failure / no playback. Self-check (I9) + differential mp4dump catch it pre-publish. Blast radius: one rendition's segments. Containment: fail packaging in debug; in release, count box_size_mismatch_total and quarantine. Recovery: re-package from the AU buffer.

15.10 Operational Notes

  • Metrics: flux_segments_built_total, flux_segment_build_ns, box_size_mismatch_total, tfdt_drift_total, ts_cc_gap_total, pcr_discontinuity_total. flux-probe is the on-call box inspector. Compatibility: CMAF is the canonical format; TS is opt-in per stream config. Determinism enables byte-for-byte CDN caching.

16. Phase 4 — ABR Ladder + Transcode Orchestration

16.1 Objectives

  • flux-ladder (§11.5): declare rungs (resolution×bitrate), enforce IDR/GOP alignment across all renditions (I3) for seamless switching, drive the EncoderBoundary (transcode) or pass-through.
  • Per-title / convex-hull ladder design notes; bitrate monotonicity.
  • Constraints: flux never encodes (DP3); the orchestrator commands and verifies (DP8). Transcode-farm driver → PhaseDeferred("§16").

16.2 Detailed Implementation Steps

  • ladder_spec.rs: LadderSpec/Rung/LadderMode; default 5-rung ladder (240p/360p/480p/720p/1080p at 0.4/0.8/1.4/2.8/5.0 Mbps, §4); GOP cadence = segment duration or integer divisor; force_idr_at_segment.
  • encoder_boundary.rs: EncoderBoundary trait (§11.5). passthrough.rs: single ingested rendition = the only rung (no transcode). Transcode mode: a stub adapter that issues LadderSpec to an external farm and ingests RenditionTrack[] (the farm itself is deferred §16).
  • alignment.rs: verify_alignment (I3) — for each rung, confirm an IDR exists at each segment-boundary presentation time (compare pts/ts as rationals across timescales); reject a rung whose IDR drifts (IdrMisaligned), re-request. Enforce bitrate strictly increasing across rungs (BitrateNotMonotonic).
  • Codec-string + RESOLUTION propagation from P2 into per-rung manifest metadata.
  • Keyframe-cadence policy object the SEGMENTER consumes so all rungs segment at identical media times → switchable segments.

16.3 Deliverable

Given an aligned multi-rung input (or a real transcode farm later), flux produces N independently-packaged, segment-aligned renditions; a player can switch rungs at any segment boundary onto an IDR (I4). Pass-through mode works with a single ingested rendition today.

16.4 Acceptance Criteria

  • verify_alignment rejects a deliberately misaligned fixture (IDR at 2.04 s vs 2.00 s) with IdrMisaligned (I3).
  • All rungs' segment N covers the identical presentation interval; segment N's first sample is an IDR on every rung (I4).
  • Bitrate monotonicity enforced; non-monotonic ladder rejected.
  • Manual switch test across all adjacent rungs shows no decode discontinuity at the boundary.

16.5 Conformance Fixtures

  • conformance/fixtures/bmff/ladder_aligned_{240,360,480,720,1080}.au → pass alignment.
  • conformance/fixtures/bmff/ladder_misaligned_720.au → IdrMisaligned.
  • examples/ladder_config.toml → parsed LadderSpec.

16.6 Pitfalls

  • Timescale-relative IDR comparison — rungs may use different mdhd timescales; comparing raw ticks is wrong (I3); compare rationals.
  • Encoder honoring forced-IDR — many encoders place an IDR near but not at the requested time (GOP-size rounding); the verify step is non-negotiable, and the EncoderBoundary contract must demand exact placement.
  • Audio alignment — audio frames (1024 samples) rarely align to video segment boundaries; segment on video IDR and let audio span; do not force audio splits mid-frame.
  • Per-title ladders — a fixed ladder wastes bits on simple content; note convex-hull/per-title as a future optimization, but keep the alignment contract identical.

16.7 Performance Concerns

  • Alignment verification is O(segments × rungs), cheap; runs once per segment boundary, not per frame.
  • The orchestrator holds references to per-rung AU streams (Bytes), not copies.
  • Transcode (external) is the CPU cost; flux's overhead is verification + packaging dispatch only (DP3).

16.8 Edge Cases

  • A rung drops out (encoder failure) mid-stream → continue with remaining rungs, mark the variant unavailable in the manifest. New rung added mid-stream (rare) → new init segment. Single-rung (pass-through) → trivially aligned. Variable-GOP source in pass-through → segment-on-IDR may yield variable segment durations (TARGETDURATION = ceil(max), I12).

16.9 Failure Analysis

  • Misaligned IDRs ship a ladder where switching stalls — the invisible-until-it-breaks bug (DP8). Caught by verify_alignment before packaging. Blast radius: one stream's switchability. Detection: idr_misalign_total. Recovery: reject + re-request the rung; do not package the misaligned rendition.

16.10 Operational Notes

  • Metrics: idr_misalign_total, flux_ladder_rungs_active, flux_rung_dropped_total. Runbook: a stalling-on-switch report → check idr_misalign_total + the encoder's GOP config. Compatibility: ladder is per-stream config; EncoderBoundary keeps the transcode farm swappable/deferred. Deployment: pass-through needs no encoder; transcode mode needs the (deferred) farm.

17. Phase 5 — HLS Manifests (Master + Media; VOD/EVENT/LIVE)

17.1 Objectives

  • flux-hls (§11.6): master playlist (#EXT-X-STREAM-INF per rung, #EXT-X-MEDIA alt audio) + per-rendition media playlists (#EXTINF, #EXT-X-TARGETDURATION, #EXT-X-MEDIA-SEQUENCE, #EXT-X-MAP, #EXT-X-PLAYLIST-TYPE, #EXT-X-ENDLIST).
  • VOD (immutable, ENDLIST), EVENT (append-only), LIVE (sliding window); discontinuities (#EXT-X-DISCONTINUITY/-SEQUENCE).
  • Constraints: never advertise an unpublished segment (DP2/I1); monotonic media-sequence (I2); TARGETDURATION ≥ max EXTINF (I12).

17.2 Detailed Implementation Steps

  • master.rs: emit_hls_master — one #EXT-X-STREAM-INF per Variant (BANDWIDTH, RESOLUTION, CODECS RFC 6381, AUDIO group); #EXT-X-MEDIA for alternate audio renditions.
  • media.rs: emit_hls_media — header (#EXT-X-VERSION:9, #EXT-X-TARGETDURATION, #EXT-X-MEDIA-SEQUENCE, #EXT-X-MAP:URI), per-segment #EXTINF + URI; #EXT-X-PLAYLIST-TYPE (VOD/EVENT) or none (LIVE); #EXT-X-ENDLIST (VOD). On emit: assert media-sequence monotonic (I2) and TARGETDURATION ≥ ceil(max EXTINF) (I12) → ManifestError on violation.
  • Sliding window (LIVE): pop oldest SegRef when older than DVR window; bump #EXT-X-MEDIA-SEQUENCE (I2); never rewind.
  • Discontinuities: on params/timeline change, insert #EXT-X-DISCONTINUITY and bump #EXT-X-DISCONTINUITY-SEQUENCE.
  • writer.rs: deterministic text emission (stable attribute order, DP11/DP14); the model is rebuilt from committed origin state only (DP2).

17.3 Deliverable

A playable HLS stream: hls.js and Safari play VOD and LIVE off flux's manifests + P3 segments. flux-probe hls-validate <m3u8> checks invariants offline.

17.4 Acceptance Criteria

  • Apple mediastreamvalidator (or hls.js + Safari) accept master + media playlists with no errors.
  • VOD plays start-to-finish; LIVE plays with a stable sliding window; rung switching works (alignment from P4).
  • #EXT-X-TARGETDURATION ≥ every #EXTINF (I12); #EXT-X-MEDIA-SEQUENCE never decreases across reloads (I2).
  • A segment URI never appears before its bytes are committed (I1) — verified by the manifest-vs-store audit.
  • fuzz_m3u8 round-trip: parse(emit(model)) == model on valid fixtures.

17.5 Conformance Fixtures

  • conformance/fixtures/hls/{master,media_vod,media_event,media_live}.m3u8 → expected emitted text (snapshot).
  • conformance/fixtures/hls/discontinuity.m3u8 → expected DISCONTINUITY-SEQUENCE handling.
  • conformance/fixtures/malformed/{media_seq_regress,targetdur_violation}.json → MediaSeqRegression/TargetDurationViolation.

17.6 Pitfalls

  • TARGETDURATION is an integer (ceil) — emitting the float max EXTINF is a spec violation many validators flag.
  • #EXT-X-MAP placement — must precede the first #EXTINF it applies to; on a discontinuity with a new init, a new #EXT-X-MAP is required.
  • CODECS string accuracy — a wrong avc1.PPCCLL makes a player reject a variant it could play; derive from the SPS (P2), do not hardcode.
  • Window too small for buffer — a LIVE window shorter than the player's buffer causes the player to fall off the start (MEDIA-SEQUENCE jumps past its position) → stall; window ≥ player buffer + margin.
  • #EXT-X-VERSION mismatch — using a tag (e.g. #EXT-X-PART) below its required version makes strict players reject the playlist.

17.7 Performance Concerns

  • Media playlist regeneration is O(segments in window); cache the rendered Arc<str> and only re-render on change.
  • For high reload QPS, serve the cached string (P8); never re-render per request.
  • Master is rendered once per ladder change.

17.8 Edge Cases

  • Zero segments yet (pre-roll) → minimal valid playlist or hold (LL P7). Single-segment VOD. EVENT→VOD transition at stream end (append ENDLIST). Variant with a dropped rung (P4) → omit or mark. Audio-only master. Very long VOD (tens of thousands of segments) → playlist size; consider #EXT-X-I-FRAME-STREAM-INF and trick-play (noted, not built).

17.9 Failure Analysis

  • Advertising an unpublished segment (I1 violation) is the #1 live bug → 404/partial → stall. Prevented by DP2 (model reads committed state). Detection: manifest_ahead_of_store_total, player segment_404_total. Blast radius: one rendition. Recovery: hold the manifest update until commit; never emit ahead. Runbook: player-stall.md.

17.10 Operational Notes

  • Metrics: media_seq_regression_total (I2), targetdur_violation_total (I12), manifest_ahead_of_store_total (I1), flux_manifest_emit_ns. Logs carry RenditionId. Compatibility: #EXT-X-VERSION pinned; new tags are gated by version. The media playlist is a published state machine (DP2/DP14) — its consistency is the contract.

19. Phase 7 — Low-Latency (LL-HLS + LL-DASH)

19.1 Objectives

  • LL-HLS: #EXT-X-PART partial segments, blocking playlist reload, #EXT-X-PRELOAD-HINT, #EXT-X-RENDITION-REPORT, #EXT-X-SERVER-CONTROL (PART-HOLD-BACK, CAN-BLOCK-RELOAD, CAN-SKIP-UNTIL).
  • LL-DASH: chunked CMAF (moof+mdat chunks via HTTP chunked transfer), availabilityTimeOffset, ProducerReferenceTime/prft, <Resync>.
  • Target: sub-3 s glass-to-glass (2–5 s LL-HLS, 2–4 s LL-DASH, §4).
  • Constraint: a part/segment is advertised only when fully written (DP2 for LL, I13).

19.2 Detailed Implementation Steps

  • flux-hls/ll_parts.rs: PartRef emission; #EXT-X-PART:DURATION=...,URI=...,INDEPENDENT=YES (INDEPENDENT iff the part starts on an IDR); #EXT-X-PART-INF:PART-TARGET; #EXT-X-SERVER-CONTROL; #EXT-X-PRELOAD-HINT:TYPE=PART naming the single open part; rendition_report.rs: #EXT-X-RENDITION-REPORT (LAST-MSN/LAST-PART) for fast cross-rendition switching.
  • flux-origin/blocking_reload.rs: await_reload(msn, part, timeout) — park a BlockingWaiter on a oneshot; wake it when the requested part/segment commits (I13) or the deadline fires (ReloadTimeout); parse _HLS_msn/_HLS_part/_HLS_skip query params; CAN-SKIP-UNTIL delta playlists (#EXT-X-SKIP).
  • LL part lifecycle (§8.7): Open→Appending→Complete→Advertised; advertise only on Complete (I13); the PRELOAD-HINT always names the Open/Appending part.
  • flux-dash/ll_dash.rs: chunked-CMAF delivery — stream moof+mdat chunks via HTTP/1.1 chunked transfer-encoding as samples arrive; availabilityTimeOffset advertises a segment ATOs before completion; prft.rs (ProducerReferenceTime box) + <ProducerReferenceTime>/<Latency target= min= max=>/<ServiceDescription> MPD elements; <Resync> chunk-join points.
  • Origin chunked transfer in flux-origin/http_server.rs: write segment chunks to the response as they commit; HTTP/2 for LL-HLS part prioritization.

19.3 Deliverable

Sub-3 s glass-to-glass on hls.js (LL mode) and dash.js (low-latency mode). flux-probe latency <stream> measures ingest→available; the LL state machine (parts, preload hint, blocking reload) is observable.

19.4 Acceptance Criteria

  • LL-HLS: measured glass-to-glass 2–5 s; blocking reload holds until the part commits then returns within one part interval; hls.js LL mode + Safari LL play.
  • LL-DASH: 2–4 s; chunked transfer verified (response begins before segment completes); dash.js low-latency mode plays.
  • A part is never advertised before Complete (I13); PRELOAD-HINT names exactly the open part.
  • Held connections bounded (≥20,000/replica, §4) with a hard timeout — never an indefinite hold.

19.5 Conformance Fixtures

  • conformance/fixtures/hls/ll_media.m3u8 (parts + preload-hint + server-control) → snapshot.
  • conformance/fixtures/hls/blocking_reload_seq.json — request _HLS_msn/_HLS_part timeline → expected hold/return behavior.
  • conformance/fixtures/dash/ll_chunked.mpd (ATO + ProducerReferenceTime) → DASH-IF LL validation.

19.6 Pitfalls

  • PART-HOLD-BACK too small — must be ≥ 3× part-target (Apple rule); too small makes the player request parts that don't exist → stall.
  • Indefinite blocking reload — a missing timeout on a future _HLS_msn exhausts file descriptors; always bound the wait (§4) and return the current playlist on timeout.
  • INDEPENDENT misuse — marking a non-IDR part INDEPENDENT lets a player start on a non-decodable part → garbled video; gate on actual IDR (I8-analog).
  • Chunked-transfer + Content-Length — for LL-DASH chunked transfer you must NOT send Content-Length; mixing them breaks the chunked encoding.
  • HTTP/1.1 head-of-line — LL-HLS part fan-out benefits from HTTP/2 multiplexing; on HTTP/1.1, many parallel part fetches stall behind each other.
  • Thundering-herd wake — when a part commits, all parked waiters wake at once; coalesce the render (one Arc<str>) and hand the same snapshot to all.

19.7 Performance Concerns

  • Held connections are cheap (parked oneshot + a timer), not threads; the cost is fd budget + the wake fan-out — render once, share Arc<str>.
  • Chunked-CMAF writes must flush per chunk (small writes); batch within a chunk; TCP_NODELAY on the origin socket to avoid Nagle adding latency.
  • Part granularity (333 ms) multiplies segment metadata 12–18×; keep the part list compact and evict promptly.

19.8 Edge Cases

  • Client requests a part already evicted → return current playlist + report (don't hold). Part target not an integer divisor of segment duration → last part shorter. Clock skew between producer-reference-time and client → latency control oscillates; clamp. A stall mid-segment (no chunks) → the held reload times out gracefully. Mixing LL and non-LL clients on one stream → both must work (server-control advertises capability).

19.9 Failure Analysis

  • Premature part advertisement (I13 violation) → player fetches an incomplete part → stall/error. Detection: ll_part_premature_total. Blast radius: LL clients of one rendition. Containment: advertise only on part-commit. A blocking-reload fd leak → origin-wide DoS; bounded waits + a held-connection gauge prevent it. Runbook: ll-latency-regression.md, origin-oom.md.

19.10 Operational Notes

  • Metrics: ll_part_premature_total (I13), flux_blocking_reload_held (gauge), flux_blocking_reload_timeout_total, flux_glass_to_glass_ms (histogram), flux_part_publish_lag_ms. Dashboards track held-connection count vs fd budget. Compatibility: LL tags require #EXT-X-VERSION:9+; capability advertised via SERVER-CONTROL so legacy players ignore them. Deployment: HTTP/2 strongly recommended; tune fd limits and timeouts to §4.

  • The publication boundary enforcing I1/I18 (segment/init before reference) for the whole HAS path.

  • Cross-link #64 (HTTP/2/3), #159 (CDN edge), #82 (reverse proxy).

20.2 Detailed Implementation Steps

  • http_server.rs: hyper service routing /<stream>/<rendition>/{init.cmfv,seg-N.cmfv,index.m3u8} and /<stream>/manifest.mpd; HTTP/1.1+2 (rustls ALPN, A09); OPTIONS/CORS preflight; method/path validation.
  • segment_store.rs + dvr_ring.rs: SegmentStore/RenditionRing; commit_segment (I1) transitions Committed→available; eviction past the DVR window (DP13); Arc<Bytes> shared zero-copy to every responder.
  • range.rs: parse Range: bytes=a-b; emit 206 Partial Content + Content-Range; 416 on unsatisfiable; suffix/open ranges.
  • cache_headers.rs: segments Cache-Control: public, max-age=<DVR or immutable> + strong ETag (content hash, deterministic from DP11); manifests no-cache/short max-age (LIVE) or long (VOD ENDLIST); Last-Modified; conditional → 304.
  • spill.rs: optional async spill of evicted-from-RAM-but-still-in-DVR segments to an object store (S3-compatible); a cache-miss serve fetches from spill. Spill is opt-in; default is RAM-only DVR.
  • Wire P5/P6/P7 manifest generators + the blocking-reload waiter (P7) into the server; the served manifest is the cached Arc<str> snapshot.
  • Backpressure: per-connection write backpressure; a slow client cannot stall the store (it holds an Arc<Bytes>); bounded held-reload waiters (DP9/DP13).

20.3 Deliverable

A complete, CDN-frontable HTTP origin: a CDN or a browser pulls manifests + segments with correct caching, range, and CORS; LL blocking reload works end-to-end; the full HAS pipeline (ingest→package→manifest→deliver) is live.

20.4 Acceptance Criteria

  • ≥10,000 concurrent segment GETs and ≥50,000 manifest req/s per replica (§4) in the load harness.
  • Range requests return correct 206/Content-Range; conditional requests return 304.
  • A CDN (or curl honoring cache headers) caches immutable segments; ETag stable across replicas for the same segment (DP11).
  • Init/segment never served before commit (I1/I18); player 404 rate ≈ 0 under steady state.
  • CORS lets a cross-origin hls.js/dash.js play.

20.5 Conformance Fixtures

  • conformance/fixtures/http/range_requests.json — range specs → expected 206/416 + bytes.
  • conformance/fixtures/http/conditional.json — ETag/If-None-Match → 304.
  • conformance/oracles/player_interop/ — headless hls.js/dash.js against the live origin.

20.6 Pitfalls

  • Weak vs strong ETag — segments are immutable → strong ETag from content; a per-replica random ETag breaks CDN revalidation across replicas (use the deterministic content hash, DP11).
  • Range on a still-forming segment (LL chunked) — a range request on a chunked-transfer segment is ill-defined; return the committed prefix or refuse.
  • CORS preflight for byte-range — Range is not a CORS-safelisted header; preflight must allow it or players fail silently.
  • max-age on LIVE manifests — too long caches a stale playlist at the CDN → players stuck behind live; LIVE manifests are no-cache/very short.
  • Eviction vs in-flight serve — evicting a segment a slow client is still reading; the Arc<Bytes> keeps it alive for that reader even after ring removal (DP13 memory accounted).

20.7 Performance Concerns

  • sendfile/writev scatter-gather from Arc<Bytes>; zero-copy to the socket; sendmmsg not applicable (TCP) but batch writes.
  • The manifest cache (Arc<str>) means reload QPS is a refcount clone + write, not a render.
  • HTTP/2 server-push is deprecated; rely on #EXT-X-PRELOAD-HINT + HTTP/2 prioritization for LL.
  • Connection/accept rate: tune the accept loop, fd budget, and TLS handshake cost (rustls session resumption).

20.8 Edge Cases

  • Slow-loris client → connection timeout + bounded read. Segment evicted between manifest emit and fetch (window edge) → 404 with a clear signal (player should refetch the manifest). Object-store spill latency on a cache miss → bounded fetch timeout. HTTP/1.0 client → no chunked transfer (no LL). HEAD requests → headers only. Conditional + range together → 304 or 206 per RFC precedence.

20.9 Failure Analysis

  • Origin OOM from unbounded held reloads or DVR growth → node down, all streams on it lost. Prevented by DP9/DP13 (bounded waiters, bounded ring) + a held-connection gauge. Detection: origin-oom.md runbook, RAM + held-reload gauges. Blast radius: one origin replica (stateless → others serve). Recovery: the CDN + sibling replicas absorb; restart the replica; sessions reconnect.

20.10 Operational Notes

  • Metrics: flux_http_requests_total{path,code}, segment_404_total (I1), init_after_media_total (I18), flux_http_inflight, flux_dvr_bytes (gauge), flux_origin_concurrency. Deployment: N stateless replicas behind a CDN/LB (#159/#82); sticky not required for HAS. Rollback: stateless → rolling restart; the CDN masks brief unavailability. Compatibility: stable URL scheme is part of the public contract.

21. Phase 9 — WebRTC SFU Core (RTP/RTCP Forwarding)

21.1 Objectives

  • The real-time path: flux-rtp (§11.8) RTP/RTCP parse/serialize + jitter buffer; flux-sfu (§11.9) Router/Producer/Consumer with SSRC demux + reference fan-out + SSRC/seq/ts rewrite.
  • Packet forwarding only — NO transcode (DP3); publisher↔subscriber fan-out.
  • SRTP boundary is a trait seam (path begins at decrypted RTP, ends at plaintext RTP back to transport #161); SDP/signaling deferred → PhaseDeferred("§21") (the control plane consumes resolved RtpParameters).
  • Constraint: per-consumer continuity under rewrite (DP6, I5/I6/I7); keyframe-before-delta (I8); <10 ms node forward latency (§4).

21.2 Detailed Implementation Steps

  • flux-rtp/rtp.rs/rtcp.rs/header_ext.rs: parse_rtp/serialize_rtp (RFC 3550), one-byte/two-byte header extensions (RFC 8285) for abs-send-time/TWCC/MID/RID; parse_rtcp_compound (SR/RR/SDES/BYE/RTPFB/PSFB); seqnum.rs wraparound-safe SeqNum/RtpTimestamp math (I5/I6).
  • flux-rtp/payload_h264.rs: read only the NAL header to find IDR (single-NAL/STAP-A/FU-A); payload_vpx.rs picture-id/layer descriptors; (AV1 DD in P10).
  • flux-rtp/jitter_buffer.rs: JitterBuffer (§11.8) — BTreeMap<SeqNum,_> reorder, adaptive depth 20–200 ms (cap 500 ms), playout-clocked pop_ready; overflow → drop to keyframe (DP4/DP9).
  • flux-sfu/router.rs: per-room single-writer task; on_rtp fans an Arc/Bytes-shared packet reference to every subscribed Consumer (policy-free mechanism).
  • flux-sfu/producer.rs: one inbound source; owns jitter buffer + parameter-set tracking + (P11) NACK cache; demuxes by SSRC.
  • flux-sfu/consumer.rs + rewrite.rs: rewrite_for — stable egress SSRC (I7), continuous seq via seq_offset (I5), monotonic ts via ts_offset (I6), marker-bit fix at frame boundaries; gate deltas until the first keyframe (I8) → ConsumerState::WaitKeyframe→Active (§8.15).
  • flux-sfu/rtp_parameters.rs: the resolved RtpParameters (codecs, ext-map, encodings) the control plane hands in (signaling deferred); SrtpContext trait (decrypt-in/encrypt-out bodies deferred §21).
  • Wire into fluxd: an in-process channel carries decrypted RTP/RTCP from the transport adapter (#161) to the room task and plaintext RTP back.

21.3 Deliverable

Two peers (transport stubbed with a plaintext-RTP adapter) publish and subscribe through the SFU; B receives A's forwarded RTP with continuous seq/ts and a stable SSRC, decodable from the first keyframe. tools/pcap_replay feeds a captured RTP stream into the router for repro.

21.4 Acceptance Criteria

  • A forwarded stream decodes in a browser (or pcap_replay + ffprobe) with no seq gaps (I5), monotonic ts (I6), one SSRC (I7).
  • First egress packet to a new consumer is a keyframe (I8); no delta leaks before it.
  • Node forward latency (demux→route→rewrite) < 10 ms p99 in the bench (§4).
  • fuzz_rtp/fuzz_rtcp: zero panics over malformed packets (§8.14).
  • Jitter buffer reorders out-of-order fixtures correctly; overflow drops to keyframe, not OOM (DP9).

21.5 Conformance Fixtures

  • conformance/fixtures/rtp/h264_fua_stapa.bin → expected NAL/IDR detection + reframe.
  • conformance/fixtures/rtcp/{sr,rr,sdes,bye}.bin → parsed structs.
  • conformance/fixtures/rtp/reorder_seq.pcap → expected jitter-buffer output order.
  • conformance/fixtures/malformed/{rtp_short,rtp_bad_ext,rtp_bad_csrc,rtcp_bad_len}.bin → typed drops (§8.14).

21.6 Pitfalls

  • Seq/ts rewrite offset across a producer restart — when the source SSRC changes, the consumer must keep its egress seq/ts continuous (recompute offsets), or the client sees a pipeline reset (DP6 violation, I7).
  • Marker-bit semantics — the marker bit ends a frame (video) or marks talk-spurt start (audio); copying it wrong fragments frames at the client jitter buffer.
  • Wraparound < — comparing SeqNum/RtpTimestamp with naive < is a defect near the 16/32-bit wrap (I5/I6); always use the wraparound helpers.
  • STAP-A timestamp — aggregated NALs share one RTP timestamp; splitting them for forwarding must preserve it.
  • Jitter-buffer-induced latency — too deep a buffer adds latency (violates <500 ms); adaptive depth must shrink under low jitter.

21.7 Performance Concerns

  • The forward path is the hot path: zero-copy Bytes fan-out, O(subscribers) per packet, no allocation per forward; rewrite mutates a small header copy, not the payload.
  • Per-room single-writer task → lock-free forward (§4, A02); cross-room parallelism via separate tasks.
  • sendmmsg batches egress to transport; the pacer (P11) sits before it.
  • Avoid HashMap lookups on the hot path where a SmallVec subscriber list suffices.

21.8 Edge Cases

  • Subscriber joins before the producer's first keyframe → hold (forward nothing) + PLI until keyframe (I8). Producer BYE → consumers Paused, SSRC held. SSRC collision → remap to a fresh SSRC (I7). RTX packet (P11) on a separate SSRC/PT. Duplicate packet (retransmit) → jitter buffer dedups. A consumer slower than the source → the pacer/queue sheds (P11), never unbounded.

21.9 Failure Analysis

  • A malformed RTP packet panicking a room task kills every stream in that room. Prevented by DP10 + fuzz_rtp/fuzz_rtcp. Blast radius: scoped to one room (one task); other rooms unaffected. Detection: rtp_error_total{kind}, consumer_seq_discontinuity_total (I5). Recovery: drop the packet, count; a poisoned consumer is closed, not the room. Runbook: sfu-room-degraded.md.

21.10 Operational Notes

  • Metrics: flux_sfu_forward_ns (histogram), consumer_seq_discontinuity_total (I5), consumer_ts_regression_total (I6), ssrc_collision_total (I7), delta_before_keyframe_total (I8), flux_jitter_depth_ms. Spans: subscribe→keyframe→active per consumer (DP12). Deployment: a RoomId is pinned to one fluxd (sticky, §1.3); cross-node cascade deferred. Rollback: rooms are ephemeral; drain by stopping new subscribes.

22. Phase 10 — Simulcast + SVC (Layer Selection)

22.1 Objectives

  • Simulcast: producer sends N independent encodings (RID-tagged, RFC 8852/8853); per-consumer spatial-rung selection.
  • SVC: layered single stream (VP9/AV1), temporal/spatial layers; forward a prefix; AV1 Dependency Descriptor for selective forwarding.
  • Layer switching ONLY at keyframe/decodable boundaries (I8); per-consumer LAYER SELECTOR (the core SFU value).
  • Constraint: switch sequencing preserves continuity (DP6, I5/I6); the SFU still never transcodes (DP3).

22.2 Detailed Implementation Steps

  • flux-sfu/simulcast.rs: demux a producer's RIDs (q/h/f) to per-RID source layers (§8.10); each has its own ts base + keyframes; Producer simulcast-layer state machine (Inactive→KeyframeWaiting→Active→Stale, §8.15).
  • flux-sfu/svc.rs: parse VP9 SS / temporal-layer descriptors; forward a temporal prefix (drop higher-T packets → halve/quarter frame rate, no keyframe needed); spatial-layer prefix.
  • flux-rtp/payload_av1_dd.rs: parse the AV1 Dependency Descriptor header extension (frame number, spatial/temporal id, dependencies, decode-target indications, chains); decide which packets a chosen decode target needs without OBU parsing; forward a decode target only if its chain is intact.
  • flux-sfu/layer_selector.rs: select_layer maps a target LayerId to forwarding decisions; simulcast up-switch sequencing (§8.10): pick target → PLI target (rate-limited, P11) → keep current until target keyframe → splice with recomputed seq_offset/ts_offset (I5/I6), fix marker (I8 throughout); down-switch immediate at a frame boundary (no keyframe for a lower rung with a recent keyframe).
  • Hysteresis hooks (the BWE drive lands in P11): up needs sustained headroom, down is prompt.

22.3 Deliverable

A consumer subscribed to a simulcast/SVC producer is fed one selected layer; a manual layer-switch API (fluxctl) up/down-switches with continuous egress and a clean keyframe boundary on up-switch. Temporal SVC frame-rate drop works with no keyframe.

22.4 Acceptance Criteria

  • Up-switch (q→f) splices exactly at the f keyframe; egress seq/ts stay continuous (I5/I6); first f packet is the keyframe (I8).
  • Down-switch happens at the next frame boundary with no keyframe (simulcast, recent keyframe present) and no decode break.
  • SVC temporal drop (T2→T1→T0) reduces frame rate cleanly; base layer alone decodes.
  • AV1 DD: forwarding a decode target with a missing chain dependency is refused (no undecodable forward).
  • Switch never emits a delta before the target's keyframe (I8); layer_switch_invalid_total increments on an invalid target.

22.5 Conformance Fixtures

  • conformance/fixtures/rtp/simulcast_qhf.pcap → per-RID demux + switch sequence.
  • conformance/fixtures/rtp/vp9_svc.pcap → temporal/spatial prefix forwarding.
  • conformance/fixtures/rtp/av1_dd_l3t3.pcap → DD-driven decode-target selection.
  • conformance/fixtures/malformed/layer_switch_bad_rid.json → layer_switch_invalid_total.

22.6 Pitfalls

  • Simulcast ts realignment — each RID has an independent timestamp base; the splice must compute ts_offset so the consumer's egress ts is continuous across the q→f boundary (I6) — the canonical simulcast bug.
  • SVC vs simulcast confusion — SVC layer drop needs NO keyframe (the base is self-sufficient); requesting one wastefully triggers a keyframe storm. Simulcast rung switch DOES need a target keyframe.
  • AV1 chain integrity — forwarding a frame whose referenced frame (per the DD chain) was dropped produces an undecodable target; the chain check is mandatory.
  • Temporal-layer marker bits — dropping higher-T packets must not orphan a frame's marker bit; track frame boundaries per temporal layer.
  • Stale layer targeting — the LAYER SELECTOR must only target Active layers; a Stale RID (no recent packets) needs a keyframe request first.

22.7 Performance Concerns

  • Layer demux + DD parse is per-packet but tiny (header-only); no payload copy.
  • A keyframe storm (many consumers up-switching to f at once) is mitigated by KEYFRAME MANAGER coalescing (P11); without it, the producer is flooded with PLIs.
  • The forward decision is O(1) per consumer per packet given the target; keep the per-consumer state cache-resident.

22.8 Edge Cases

  • Target RID disappears mid-stream → fall back to a lower layer + request keyframe. Producer changes simulcast config (RID set) → re-resolve. SVC stream with only a base layer → no drop possible. Up-switch requested but the keyframe never arrives (encoder ignored PLI) → stay on current, retry within the rate limit. Down-switch to a rung with a stale keyframe → request one before switching. Mixed simulcast+SVC (e.g. AV1 spatial simulcast + temporal SVC).

22.9 Failure Analysis

  • A switch that emits a delta before the target keyframe (I8) → green/garbled video at the client. Detection: delta_before_keyframe_total. Blast radius: one consumer. Containment: the WaitKeyframe/SwitchingUp gate. A keyframe storm degrades the whole producer (CPU + bitrate) → mitigated by coalescing/rate-limit. Runbook: sfu-room-degraded.md.

22.10 Operational Notes

  • Metrics: flux_layer_switches_total{dir}, layer_switch_invalid_total, delta_before_keyframe_total (I8), flux_active_layers per producer. Logs carry ConsumerId/Ssrc/LayerId. The manual fluxctl switch API is for ops/testing; production switching is BWE-driven (P11). Compatibility: per-codec layer model (simulcast/SVC/AV1-DD) is pluggable; new scalability structures are additive.

23. Phase 11 — Jitter Buffer Resilience + Congestion Control

23.1 Objectives

  • flux-nack (§11.10): NACK responder over the producer packet cache (RTX, RFC 4588); KEYFRAME MANAGER (PLI/FIR, RFC 4585/5104) rate-limited.
  • flux-bwe (§11.10): Google Congestion Control — delay-based (trendline/over-use detector over abs-send-time/TWCC) + loss-based AIMD, fused to a per-consumer target; TWCC feedback, REMB (legacy), probing; leaky/token-bucket pacer.
  • Drive the P10 LAYER SELECTOR from the estimate (the closed loop); RED/FEC notes.
  • Constraints: forwarded bitrate never exceeds the estimate (I15); pacer honest over any window (I16); NACK never resends an evicted packet (I14); BWE converges <1 s (§4).

23.2 Detailed Implementation Steps

  • flux-nack/nack_cache.rs/nack_responder.rs: NackCache (ring, ≥500 ms / cap 2 MB or 2048 pkts, §4); handle_nack → Resend (RTX SSRC/PT, RFC 4588) within the retransmit window (≤200 ms / 1×RTT) else RequestKeyframe (I14).
  • flux-nack/keyframe_manager.rs: request_keyframe — coalesce concurrent requests per (Ssrc,LayerId), rate-limit ≤1/stream/500 ms (§4); emit PLI (RFC 4585) or FIR (RFC 5104).
  • flux-bwe/delay_based.rs + trendline.rs + overuse_detector.rs: inter-group delay variation d(i) (§8.11); trendline/Kalman slope m(i); adaptive threshold γ(i) → {overuse,underuse,normal}; the delay-rate state machine (Hold/Increase/Decrease, §8.11 table).
  • flux-bwe/loss_based.rs + aimd.rs: RR/TWCC loss → loss<2%×1.08 / 2–10% hold / >10%×(1−0.5·loss).
  • flux-bwe/twcc_feedback.rs: time each transport-sequence-numbered packet's arrival; build/parse TWCC feedback (RFC 8888 / transport-cc draft); remb.rs legacy receiver estimate.
  • flux-bwe/pacer.rs: TokenBucket shaping egress to the target (I16); probe.rs periodic padding/duplicate bursts for headroom.
  • target = min(A_delay, A_loss) clamped to [min,max] (I15) → LAYER SELECTOR discretizes (highest layer set ≤ target·(1−margin), hysteresis).
  • RED/FEC: notes + a payload hook (full FEC deferred); the SFU forwards FEC packets it receives.

23.3 Deliverable

The SFU adapts: under emulated congestion (tc netem/Mahimahi) a consumer down-switches and recovers; lost packets are retransmitted (RTX) within the window or a keyframe is requested; egress is paced. bwe_step bench shows convergence.

23.4 Acceptance Criteria

  • BWE converges to within 10% of available bandwidth in <1 s after a step change (§4, RMCAT-style scenarios).
  • Forwarded bitrate never exceeds the estimate (I15); pacer never exceeds target over any sliding window (I16).
  • NACK resends a cached packet; a NACK for an evicted packet falls back to PLI (I14), never stalls.
  • Keyframe requests coalesced + rate-limited ≤1/stream/500 ms (§4); no storm under mass switch.
  • Under 5% loss, RTX recovers; under 20% loss, the system down-switches + requests keyframes, never disconnects (DP4).

23.5 Conformance Fixtures

  • conformance/fixtures/rtcp/twcc_feedback.bin → parsed deltas + estimate step.
  • conformance/fixtures/netem/{step_down,step_up,loss5,loss20,reorder}.profile → expected estimate/layer trajectory.
  • conformance/fixtures/rtcp/nack_blp.bin → expected resend set.
  • conformance/fixtures/malformed/twcc_unknown_seq.bin → twcc_unknown_seq_total, ignored.

23.6 Pitfalls

  • TWCC reference-time units — 64 ms reference time, 250 µs deltas; mixing units corrupts the delay model (§8.9).
  • Over-use detector threshold adaptation — a static γ mis-detects on different paths; γ(i) must adapt (the GCC paper's key detail, P1/P2), or BWE oscillates or never reacts.
  • Pacer starving the queue — too-tight a bucket queues packets and adds latency (violates <500 ms); the bucket refill must track the target and shed, not buffer unboundedly (DP9/I16).
  • NACK amplification — answering every NACK during a burst can worsen congestion; bound RTX rate and prefer a keyframe past the window (I14).
  • Probe misread as congestion — a probing burst raises delay; the estimator must attribute probe-induced delay correctly or it down-switches on its own probe.
  • Loss vs delay disagreement — taking max instead of min(A_delay,A_loss) overcommits (I15); always the min.

23.7 Performance Concerns

  • The estimator runs per feedback (50–100 ms), not per packet; cheap. The pacer runs per egress tick.
  • Float filter math is the only float in the system (§4); keep it off the per-packet path.
  • NACK cache is a ring of Bytes (no copy); eviction is O(1). Keyframe-manager coalescing is a small map keyed by (Ssrc,LayerId).
  • Tail latency: a down-switch must be prompt (one frame boundary); an up-switch is deliberate (hysteresis) — asymmetric by design.

23.8 Edge Cases

  • Bandwidth oscillating around a layer boundary → hysteresis prevents flapping; if it still flaps, widen the margin (bwe-oscillation.md). Sudden bandwidth collapse → immediate down-switch to base + PLI. TWCC feedback gap (lost feedback) → hold last estimate, decay. Clock skew in abs-send-time → the trendline tolerates a constant offset (it's delta-based). RTT spike → retransmit window shrinks. Receiver sends both REMB and TWCC → prefer TWCC.

23.9 Failure Analysis

  • BWE overcommit (I15 violation) → the SFU sends faster than the path → self-induced congestion → cascading loss for that consumer. Detection: bwe_overcommit_total, pacer_overrun_total (I16). Blast radius: one consumer (per-consumer estimate). Containment: clamp + down-switch. A keyframe storm (no coalescing) degrades a whole producer. Runbook: bwe-oscillation.md, sfu-room-degraded.md.

23.10 Operational Notes

  • Metrics: flux_bwe_estimate_bps (gauge/consumer), bwe_overcommit_total (I15), pacer_overrun_total (I16), nack_cache_miss_total (I14), flux_rtx_sent_total, flux_keyframe_requests_total (rate-limited), flux_loss_fraction. Spans tie an estimate change to the resulting layer switch (DP12). Tuning knobs: hysteresis margin, pacer bucket, NACK window, keyframe rate-limit — all in config. Compatibility: TWCC is primary; REMB fallback keeps legacy clients working.

  • cbcs constant IV — cbcs uses a constant per-sample IV + pattern encryption; cenc uses a per-sample counter IV; swapping them yields undecryptable output.

24.7 Performance Concerns

  • Encryption is per-sample AES (ring, hardware-accelerated); subsample mode encrypts only slice data; cost is bounded and parallelizable across renditions.
  • Metric updates are atomic counter increments (cheap); histograms use bounded buckets. Tracing is sampled in production to bound overhead.
  • DVR eviction is O(1) ring pops; spill IO is async and off the publish path.

24.8 Edge Cases

  • Key rotation mid-stream → new KID + new pssh/tenc (discontinuity). DVR window shrink at runtime → evict immediately. Encrypted audio + clear video (or vice versa) → per-track scheme. A viewer seeking past the evicted window edge → 404 + manifest refetch. Telemetry backend down → metrics buffered/dropped bounded, never blocks the media path.

24.9 Failure Analysis

  • An unmapped encrypted sample (I17) → undecryptable segment → playback failure on encrypted streams. Detection: cenc_sample_unmapped_total; fail packaging pre-publish. Blast radius: one rendition's encrypted output. A telemetry-induced slowdown must never affect the media path (observability is best-effort). Recovery: re-package; the unencrypted path is unaffected.

24.10 Operational Notes

  • Metrics/dashboards are the deliverable; alerting philosophy + SLOs land in Operational Readiness. Compatibility: cenc/cbcs selectable per stream; the KeyProvider keeps license servers swappable/deferred. Deployment: DVR depth + spill threshold are capacity-planning knobs (DP13); the observability stack ships in docker-compose for local + as k8s manifests for prod.

29. Compatibility & Versioning

  • Wire compatibility (output). Emitted HLS/DASH manifests, ISO-BMFF/TS boxes, and RTP/RTCP packets conform to their specs and validate against independent oracles (DP14). Output grammar is the public contract; any conformant player/CDN interoperates. Breaking the grammar is a major-version event.
  • URL / storage scheme. The origin URL layout (/<stream>/<rendition>/{init,seg-N,index}) and segment immutability are stable; segments are content-addressable and CDN-cacheable (DP11). A scheme change is major-version + a deprecation window.
  • Schema evolution. New Codec/scalability-structure/box support is additive and feature-gated; match sites are exhaustive so a new variant is a compile error until handled. Manifest tags are gated by #EXT-X-VERSION / MPD profiles.
  • Protocol versioning. RTMP wire is fixed (Adobe 1.0); the IngestSource trait keeps SRT/RIST additive (§13). SFU RtpParameters are negotiated by the control plane (signaling deferred §21); the SFU consumes a resolved form, decoupling it from SDP churn.
  • API stability. flux-core/flux-rtp/flux-fmp4 public types (§11) are semver-governed; the EncoderBoundary/KeyProvider/SrtpContext/IngestSource seams are stable trait contracts.
  • Deprecation policy. Deprecate a wire/URL feature for ≥1 minor version with a metric tracking residual use before removal in the next major; CHANGELOG flags every wire-affecting change.
  • SemVer. Pre-v1.0.0: phase deliverables, minors may break. Post-v1.0.0 (P13): patch = fixes; minor = additive/back-compatible; major = wire/URL/API break with migration notes.
  • Rolling-upgrade guarantee. Two adjacent versions interoperate at the origin (a CDN/player sees identical bytes) and at the SFU seam (same RtpParameters contract), so a mixed-version fleet is safe during a roll.

33. Scalability Analysis

  • Bottlenecks. HAS: origin manifest-reload QPS (esp. LL blocking reloads holding fds) and segment egress bandwidth. SFU: per-node forwarded pkt/s and egress Gbps; per-room fan-out is O(producers × consumers).
  • Horizontal scaling — HAS. Stateless origins scale linearly behind a CDN (#159); immutable cacheable segments (DP11) mean the CDN absorbs most segment load; origins serve manifests + cache-miss segments. Add replicas; no coordination.
  • Horizontal scaling — SFU. A RoomId is pinned to one node (sticky); scale by spreading rooms across nodes. Cross-node rooms (cascade) — relaying a producer to a sibling node's consumers — is deferred (§22); until then a single room is bounded by one node's pkt/s + egress.
  • Vertical scaling. More cores → more concurrent rooms (one task per room) + more origin connections (tokio work-stealing). NIC + sendmmsg/offload bound egress Gbps; CPU bounds pkt/s.
  • Sharding / partitioning. Rooms shard by RoomId across SFU nodes; streams shard by origin replica (any replica serves any stream from its store/spill). No central state to partition.
  • Replication pressure. None on the HAS hot path (stateless); deep-DVR spill to object storage is the only replicated/durable artifact, and it is async + off-path.
  • Coordination overhead. Minimal: the control plane wires pipelines but never touches media bytes; per-room single-writer avoids lock coordination; cross-room is embarrassingly parallel.
  • Network fan-out. The SFU's core scaling concern — N consumers per producer means N× egress for one ingest; the pacer + zero-copy fan-out bound per-packet cost; beyond one node's capacity needs cascade (deferred).
  • Scheduler saturation. Tokio work-stealing saturates cores; a hot room can monopolize a worker — mitigate by bounding room size (≥500 peers, §4) and, at scale, pinning large rooms to dedicated nodes.
  • Storage growth. DVR window × bitrate × renditions bounds RAM (DP13); deep DVR spills to object storage (grows with retention, planned). HAS has no other durable growth.
  • Metadata scaling. LL part granularity (333 ms) multiplies manifest metadata 12–18×; compact part lists + prompt eviction keep manifests small; long VOD playlists may need I-frame/trick-play indices (noted).

  • MM2 — Cross-rendition alignment is a distributed invariant, not a per-track detail. Predicts: comparing presentation times as raw ticks across renditions with different timescales silently passes misaligned ladders. Bug class without it: a client stalls on exactly one rung switch, reproducible only under specific GOP timing. Applied in §8.1 (rational comparison), §16 (Phase 4 verify_alignment).
  • MM3 — An SFU is a router with codec literacy, not a media processor. Predicts: any code path in the forwarding tier that decodes pixels is an architectural smell, not an optimization. Bug class without it: CPU cost silently becomes O(participants × pixels), turning the SFU into an accidental MCU under load. Applied in §9 (ADR A01 rationale), §21–§22 (Phases 9–10).
  • MM4 — Continuity under rewrite is the SFU's central promise. Predicts: client-visible symptoms (spurious NACK storms, decoder resets) map one-to-one to specific rewrite-invariant violations, not vague "network issues". Bug class without it: naive seq/ts copy-through across a layer switch corrupts every subscriber's jitter buffer simultaneously. Applied in §21.2 (rewrite.rs), §22 (layer-switch splice sequencing).
  • MM5 — Congestion control is a control loop closed over a delayed, noisy signal, never an instantaneous truth. Predicts: any threshold-crossing switch without hysteresis oscillates under real network jitter, even in a correct implementation. Bug class without it: a layer selector that flaps every few seconds under stable-but-noisy bandwidth. Applied in §8.11 (GCC model), §23 (Phase 11 hysteresis).
  • MM6 — Determinism is a debugging multiplier, not a nicety. Predicts: byte-identical output from byte-identical input turns every packaging bug into a bisectable unit test instead of a "sometimes" production incident. Bug class without it: wall-clock leaking into segment bytes breaks CDN caching and reproducibility in the same commit. Applied in §9 (ADR A13), §15 (Phase 3 snapshot gate).
  • MM7 — Backpressure is the only legitimate response to a queue that cannot drain. Predicts: any queue without an explicit cap (AU bus, jitter buffer, NACK cache, blocking-reload waiters) is a future OOM incident, not a "should be fine" assumption. Bug class without it: a slow subscriber or a network partition grows one buffer until the whole node falls over. Applied in §9 (DP9/DP13), §20 (Phase 8), §23 (Phase 11).
  • MM8 — Two independent latency regimes cannot share one buffering strategy. Predicts: attempting a "unified" pipeline for HAS and SFU collapses one regime's cost structure into the other — segment quantization added to the SFU destroys its latency budget, or packet-granular delivery added to HAS destroys its cache-scalability. Applied in §3 (Architectural Overview), §36 (Back-of-Envelope Capacity Model), §38 (Alternative Architectures).

36. Back-of-Envelope Capacity Model

Every number below is derived from §4 System Constraints, formula shown — never asserted standalone.

  1. SFU room egress bandwidth. peers/room (≥500) × mid-ladder bitrate (1.4 Mbps, 480p rung, §4) = 500 × 1.4 Mbps ≈ 700 Mbps per fully-subscribed room at one rung — the floor a single room can demand of a node.
  2. Rooms per SFU node. node egress budget (10–40 Gbps, §4) ÷ per-room egress (#1) = 10,000 Mbps ÷ 700 Mbps ≈ 14 to 40,000 ÷ 700 ≈ 57 fully-subscribed rooms per node at the low/high end of the egress budget.
  3. SFU packet rate per forwarded stream. bitrate ÷ (RTP payload cap × 8 bits, §4) = 1.4×10⁶ ÷ (1200 × 8) ≈ 146 pkt/s per forwarded stream at the 480p rung.
  4. Concurrently forwardable streams per node (pkt/s-bound). node pkt/s budget (≥2,000,000, §4) ÷ per-stream pkt/s (#3) = 2,000,000 ÷ 146 ≈ 13,700 concurrently forwarded streams — the packet-rate ceiling, independent of bandwidth.
  5. Memory ceiling check. assumed node RAM budget (32 GB) ÷ per-consumer memory (<256 KB, §4) = 32×10⁹ ÷ 256×10³ ≈ 125,000 consumers — an order of magnitude above the pkt/s ceiling (#4), confirming memory is never the SFU bottleneck; pkt/s and Gbps are (Scalability Analysis, §33).
  6. Origin DVR RAM per stream. DVR window (30 s default, §4) × aggregate ladder bitrate (0.4+0.8+1.4+2.8+5.0 = 10.4 Mbps, §4) ÷ 8 bits = 30 × 10.4×10⁶ ÷ 8 ≈ 39 MB per live stream's full ladder held in the ring — the number that drives the spill-to-object-store threshold.
  7. LL manifest reload load. manifest req/s budget (≥50,000/replica, §4) ÷ LL poll rate (1 per part-target ≈ 1/0.333 s ≈ 3/s) = 50,000 ÷ 3 ≈ 16,700 concurrent LL viewers a replica can serve from reload traffic alone — cross-checks against the held-connections budget (≥20,000/replica, §4).
  8. Origin-facing segment GETs under CDN offload. segment-GET budget (≥10,000/replica, §4) × (1 − assumed 99% CDN hit ratio, DP11) = 10,000 × 0.01 = 100 origin-facing GETs/replica in steady state — showing manifest/LL-reload traffic (#7), not segment bytes, dominates origin sizing.
  9. LL cold-start bound. PART-HOLD-BACK (≥3 × part-target, §19.6) + one RTT ≈ 3 × 333 ms + ~50 ms ≈ ~1.05 s to first playable LL content after the first IDR — chained from the §4 part-duration target.
  10. NACK cache byte-vs-packet cap crossover. packet cap (2048 pkts, §4) × RTP payload cap (1200 B, §4) = 2048 × 1200 ≈ 2.46 MB — just above the byte cap (2 MB, §4), confirming the packet-count cap binds first at high bitrate/small-packet video and the byte cap binds first at low packet-rate/large-payload audio.
  11. BWE full-ladder ramp time. ladder rungs (5, §4) × convergence window (<1 s to 10%, §4) ≈ ~4 s worst-case bound to ramp from the lowest to the highest rung under sustained-headroom hysteresis (asymmetric up-switch, §23.7).
  12. Held-reload fd pressure. held-connection budget (≥20,000/replica, §4) + concurrent segment-GET budget (≥10,000/replica, §4) ≈ 30,000 file descriptors per replica minimum, requiring ulimit/fd-limit tuning above the common 65,536 default's comfortable headroom once TLS and control connections are added.

38. Alternative Architectures (Roads Not Taken)

Four fundamentally different architectures for the same problem space — not parameter tweaks.

(A) MCU (Multipoint Control Unit) — server-side composite + re-encode.

producers --> [ DECODE + COMPOSITE + RE-ENCODE ] --> one mixed stream --> every subscriber
                        (server-side pixel pipeline)

Regime where it wins: very low-power/low-bandwidth clients (feature phones, PSTN gateways) that can decode only one incoming stream and cannot handle simulcast negotiation. Real system: legacy hardware MCUs (Polycom/Cisco conference bridges) and early enterprise video-bridge products. Rejected because: CPU cost is O(participants × pixels) instead of O(packets) (violates DP3), doesn't scale past small rooms, and the encode hop adds latency that breaks the <500 ms glass-to-glass budget (§4).

(B) Full mesh — no server-side media component at all.

peer A <--> peer B
  ^  \      /  ^
  |   \    /   |
  v    \  /    v
peer D <--> peer C     (every peer sends to every other peer directly)

Regime where it wins: 2–3 participant calls, or a deployment with zero appetite for media-server operational burden. Real system: early WebRTC group calls in P2P mode (small Jitsi Meet rooms, early appear.in). Rejected because: N² uplink cost on each participant's home connection is precisely the problem selective forwarding was invented to solve (§2); one participant's poor uplink degrades everyone; it stops scaling past ~4 peers (§33).

(C) Per-consumer transcoding SFU — re-encode a personalized bitrate for every subscriber.

one high-quality source --> [ per-consumer TRANSCODE ] --> consumer 1 (custom bitrate)
                                                       --> consumer 2 (custom bitrate)
                                                       --> consumer N (custom bitrate)

Regime where it wins: a publisher that can't or won't send multiple simulcast layers (a legacy or bandwidth-constrained encoder) but a downstream population with precisely heterogeneous bandwidths that simulcast's discrete rungs approximate too coarsely. Real system: some cloud/webinar transcoding-bridge products. Rejected because: it violates DP3, multiplies CPU by O(consumers) instead of O(packets), and adds an encode-latency hop that defeats the SFU's core forwarding-latency advantage (§4); simulcast/SVC (§22) gets acceptable quality diversity at near-zero marginal CPU.

(D) Codec/transport co-designed pipeline — one adaptive loop spanning encode and network.

[ ENCODER <-- rate/loss feedback --> NETWORK STACK ]  (one integrated control loop, one team owns both ends)

Regime where it wins: a single-hop, single-vendor deployment where one team controls both the codec and the transport end-to-end and can co-adapt frame-level encode decisions to instantaneous network state. Real system: Salsify (Fouladi et al., NSDI 2018 research prototype). Rejected because: flux must interoperate with arbitrary third-party encoders (OBS, hardware encoders) over a standard ingest protocol (RTMP) and standard SFU/signaling surfaces — a codec/transport co-design requires owning both ends, which breaks DP1 (coded-frame agnosticism) and the project's interoperability goal (§2).

40. Glossary

  • Access Unit (AU) — one coded frame (video picture / audio frame) with timing (dts/pts/duration); flux's media currency; never decoded (DP1).
  • ABR (Adaptive Bitrate) — client picks among server-published renditions by bandwidth; the server's job is to publish an aligned, switchable ladder.
  • HAS (HTTP Adaptive Streaming) — pull-based, segment-quantized delivery (HLS/DASH); cache-scalable, multi-second latency.
  • SFU (Selective Forwarding Unit) — a media-aware router that forwards (never transcodes) RTP among peers, dropping the right packets/layers per subscriber.
  • HLS — Apple's HTTP Live Streaming; m3u8 master + media playlists; TS or CMAF segments; LL-HLS adds parts + blocking reload.
  • DASH — MPEG-DASH; an MPD describing Periods/AdaptationSets/Representations; static (VOD) or dynamic (live); LL-DASH adds chunked CMAF + ATO.
  • CMAF — Common Media Application Format; a constrained fMP4 profile that lets one segment set serve both HLS and DASH (DP7).
  • fMP4 / ISO-BMFF — fragmented MP4 / ISO Base Media File Format; ftyp/moov init + styp/moof/mdat media fragments.
  • MPEG-TS — Transport Stream; 188-byte packets, PAT/PMT/PES, PCR clocking; the legacy HLS container.
  • RTMP — Real-Time Messaging Protocol; Adobe's chunked TCP ingest protocol (handshake + AMF commands + FLV tags); still the dominant first-mile contribution path.
  • FLV — Flash Video container; the tag format RTMP carries (audio/video/script-data).
  • AMF0/AMF3 — Action Message Format; RTMP's command serialization.
  • NAL unit — Network Abstraction Layer unit; the packetization unit of H.264/HEVC (IDR/non-IDR slice, SPS/PPS/VPS, SEI).
  • AVCC vs Annex-B — length-prefixed NAL framing (BMFF, params out-of-band) vs start-code framing (00 00 00 01, params in-band; used for TS).
  • IDR / GOP — Instantaneous Decoder Refresh frame (a clean keyframe) / Group of Pictures (frames between IDRs); a segment starts on an IDR (I4).
  • SPS/PPS/VPS — Sequence/Picture/Video Parameter Sets; decoder configuration carried in params.
  • ADTS / ASC — Audio Data Transport Stream framing / AudioSpecificConfig; AAC's TS framing vs out-of-band config.
  • PTS / DTS — Presentation / Decode Time Stamp; pts ≥ dts (I19); their difference is the composition (B-frame reorder) offset.
  • Timescale — ticks per second for a track timeline (90 kHz video, sample-rate audio); cross-track alignment compares rationals (I3).
  • Segment / Part — a media chunk (2–6 s) / a sub-chunk (200–500 ms) for low latency; advertised only after fully written (DP2, I1/I13).
  • Init segment — the ftyp+moov header (per rendition) referenced by #EXT-X-MAP / MPD Initialization before any media (I18).
  • Media sequence — monotonic per-rendition segment counter (#EXT-X-MEDIA-SEQUENCE / MPD $Number$); never regresses (I2).
  • DVR / time-shift window — the catch-up buffer a player can seek back into; bounded by timeShiftBufferDepth (DP13).
  • Blocking playlist reload — LL-HLS long-poll: the origin holds the reload until the requested msn/part exists or a timeout fires (I13).
  • RTP / RTCP — Real-time Transport Protocol / its Control Protocol (SR/RR/SDES/BYE + feedback); the SFU's wire (RFC 3550).
  • SSRC — Synchronization Source; an RTP stream's 32-bit id; unique per active stream, stable per consumer (I7).
  • Simulcast — a producer uploads N independent encodings (RID-tagged); the SFU picks one spatial rung per consumer; switching needs a target keyframe.
  • SVC (Scalable Video Coding) — a single layered bitstream (temporal/spatial); the SFU forwards a prefix; dropping a layer needs no keyframe.
  • Dependency Descriptor (DD) — an AV1 RTP header extension encoding per-packet layer/decode-target/chain info for selective forwarding without OBU parsing.
  • Jitter buffer — reorders/playout-clocks out-of-order RTP; adaptive depth 20–200 ms; overflow drops to keyframe (DP9).
  • NACK / RTX — Negative ACK (request a lost packet) / the retransmission payload format (RFC 4588); falls back to a keyframe past the window (I14).
  • PLI / FIR — Picture Loss Indication / Full Intra Request; both request a keyframe upstream; coalesced + rate-limited by the KEYFRAME MANAGER.
  • BWE (Bandwidth Estimation) / GCC — Google Congestion Control: delay-based (trendline/over-use) + loss-based AIMD fused to a per-consumer send rate.
  • TWCC / REMB — Transport-Wide Congestion Control feedback (sender-side, primary) / Receiver Estimated Max Bitrate (legacy receiver-side).
  • Pacer — a token/leaky bucket smoothing egress to the BWE target so bursts aren't misread as congestion (I16).
  • Over-use detector — the GCC component classifying inter-group delay slope as overuse/underuse/normal against an adaptive threshold.
  • Layer selector — the per-consumer policy mapping a BWE estimate to a discrete forwarded layer; up-switch needs a keyframe, down-switch is prompt (I8).
  • Keyframe-before-delta — the rule that a decode context's keyframe is forwarded before any of its delta frames (I8/DP5).
  • CENC — Common Encryption (ISO 23001-7): cenc (AES-CTR) / cbcs (AES-CBC pattern) subsample encryption; pssh/senc/saiz/saio boxes.
  • KID / PSSH — Key Identifier / Protection System Specific Header box (per DRM system, carrying init data + KIDs).
  • EncoderBoundary — the trait seam to an external transcode farm; flux commands + verifies but never encodes (DP3, §16).
  • SRTP seam — the typed boundary where decrypted RTP enters and plaintext RTP leaves; the cipher body lives in transport (#161, §21).
  • Glass-to-glass latency — capture-to-display end-to-end latency; the SFU target is <500 ms, LL-HAS <3 s (§4).
  • Origin — the publication boundary + HTTP server holding segments/manifests; stateless, CDN-frontable (#159).
  • Invariant counter — a metric (Ixx_total) incremented on an invariant violation; any nonzero value is a defect signal (§7, DP12).
