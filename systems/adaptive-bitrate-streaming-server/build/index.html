⬜ Phase 0 — Repository Bootstrap + Core Types §12

Objectives
  • Stand up the 14-crate flux Cargo workspace (§1.5); #![forbid(unsafe_code)] except the documented bytes/socket2 seam.
  • Define flux-core load-bearing primitives (§11.1): AccessUnit, MediaTime/Timescale, Codec, id newtypes, BitReader/BitWriter, bounded byte readers, NAL/ADTS reframe helpers, error roots.
  • Establish CI: fmt, clippy -D warnings, test, cargo-audit, cargo-deny, doc, fuzz-smoke skeleton.
  • Constraint introduced: total, bounded parsers (DP10) and integer-tick discipline (I20) from line one.
Deliverable

Compilable workspace, zero warnings, CI green. flux --version prints. cargo test passes core primitive tests. cargo fuzz list shows registered (empty-body) targets. No runtime media path yet.

Acceptance
  • cargo clippy -- -D warnings clean; cargo audit/cargo deny check pass.
  • Zero unsafe outside the documented seam; #![forbid(unsafe_code)] present per crate.
  • MediaTime::rescale overflow returns ArithError, proven by test at i64::MAX ticks (I20).
  • avcc_to_annexb ∘ annexb_to_avcc round-trips on fixtures (idempotent).
  • 30+ unit tests pass; doc builds with no broken intra-doc links.
Fixtures
  • conformance/fixtures/bmff/avcc_params.bin — a real AVCDecoderConfigurationRecord → expected ParameterSets.
  • conformance/fixtures/malformed/au_pts_lt_dts.json — expected I19 rejection.
  • conformance/fixtures/malformed/rescale_overflow.json — expected ArithError::Overflow.
  • conformance/fixtures/rtp/codec_strings.json — SPS bytes → expected RFC 6381 codec string.
Pitfalls
  • Timescale=0 → division traps; enforce NonZeroU32 at the type level. Detect: construction test. Signal: compile error, not runtime.
  • Exp-Golomb over-read on truncated SPS → must return BufError, never index-panic. Debug: fuzz fuzz_bmff_parse early.
  • Signed 24-bit composition time mis-sign-extended → PTS wrong by ±16 ms; assert sign on the i24 reader.
  • #[repr] assumptions — AccessUnit is not wire-serialized; do not add #[repr(C)] cargo-culted from a record DB.

⬜ Phase 1 — RTMP Ingest §13

Objectives
  • Terminate inbound RTMP/TCP: handshake → chunk demux → AMF command decode → FLV tag demux → AccessUnit emission onto the bounded AU bus.
  • Implement flux-rtmp (§11.2) end-to-end for H.264+AAC publish.
  • Constraint: every byte bounds-checked (DP10); message length capped before allocation; AU bus bounded (DP9).
  • Reserve IngestSource trait for SRT/RIST → PhaseDeferred("§13").
Deliverable

fluxd accepts an OBS/ffmpeg -f flv push on TCP 1935 and emits a verifiable AccessUnit stream (logged/counted). flux-probe rtmp-dump <pcap> prints the handshake + command + tag timeline.

Acceptance
  • OBS and ffmpeg both publish successfully (interop).
  • Captured handshake bytes match flux's S0/S1/S2 on the simple path; complex handshake validates against a captured Flash client.
  • AU stream: dts non-decreasing, pts>=dts on all fixtures (I19); first video AU carries params.
  • Fuzz fuzz_rtmp_chunk/fuzz_amf/fuzz_flv find zero panics in 10M execs.
  • Message > cap (e.g. 8 MB) → MessageTooLarge before allocation.
Fixtures
  • conformance/fixtures/rtmp/obs_1080p_h264_aac.flv + captured chunk stream → expected AU sequence (DTS/PTS/keyframe).
  • conformance/fixtures/rtmp/complex_handshake.bin → expected digest validation.
  • conformance/fixtures/malformed/{set_chunk_size_zero,orphan_fmt3,msg_50mb,amf_no_objend,nalu_before_seqhdr}.bin → expected typed errors (§8.14).
Pitfalls
  • msg_stream_id is little-endian while everything else in RTMP is big-endian — the canonical first-bug; assert on a fixture.
  • fmt=3 timestamp-delta continuation — the extended-timestamp presence is inherited from the chunk being continued, not re-read; mis-handling drifts every timestamp.
  • Chunk-size change mid-message — SetChunkSize applies to subsequent chunks; reassembly must use the size in force when each chunk arrived.
  • Composition-time units — FLV is milliseconds; converting to 90 kHz needs *90, and the field is signed (B-frames).
  • Window-ack deadlock — failing to send Acknowledgement after WindowAckSize bytes makes some encoders stall.

⬜ Phase 2 — Elementary-Stream Parsing §14

Objectives
  • Parse coded access units enough to packetize and align (DP1): H.264/HEVC NAL classification (SPS/PPS/VPS/IDR/SEI/AUD), AAC ADTS framing, PTS/DTS extraction, GOP/keyframe detection — never entropy-decode.
  • Produce the verified AccessUnit stream that P3 packages, with params resolved and keyframe flags authoritative.
  • Constraint: read-only bitstream inspection; bounded Exp-Golomb; no pixel/coefficient parsing.
Deliverable

A correct AccessUnit stream with authoritative keyframe flags, resolved params, validated timing, and derived resolution/duration. flux-probe es-dump <flv|au> matches ffprobe -show_frames on key fields.

Acceptance
  • Keyframe detection matches ffprobe (key_frame=1) on every video fixture.
  • Derived width/height match ffprobe width/height.
  • AAC frame boundaries + durations match ffprobe; audio AU duration = 1024/sample_rate ticks.
  • fuzz_* over NAL/ADTS parsers: zero panics.
  • Per-track DTS strictly non-decreasing, PTS≥DTS (I19) on all fixtures.
Fixtures
  • conformance/fixtures/bmff/h264_gop_*.au — known GOP structure (IDR cadence) → expected keyframe map + GOP durations.
  • conformance/fixtures/bmff/hevc_*.au — HEVC VPS/SPS/PPS classification.
  • conformance/fixtures/bmff/aac_adts_*.bin → expected frame offsets/durations.
  • conformance/fixtures/malformed/{nal_zero_len,sps_truncated,adts_bad_sync,sps_crop_overflow}.bin.
Pitfalls
  • Emulation-prevention bytes (00 00 03) inside RC-BSP — when reading SPS fields you must unescape 0x03 after 00 00; forgetting it corrupts width/height parsing.
  • Cropping math — display width = (pic_width − crop)·subsampling; chroma format changes the multiplier; getting this wrong mislabels RESOLUTION.
  • SEI recovery point — some streams signal a recovery point (open GOP) not an IDR; decide whether it counts as a segment-startable keyframe (it does not for closed-GOP HLS).
  • AAC SBR/PS (mp4a.40.5/.29) — implicit vs explicit signaling changes the codec string and the sample-rate doubling; detect from ASC.

⬜ Phase 3 — Segmenter + Packagers (fMP4/CMAF + MPEG-TS) §15

Objectives
  • GOP-aligned segmentation (segment-on-IDR, I4) + part splitting (LL prep).
  • flux-fmp4 (§11.3): CMAF init segment (ftyp+moov) + media segments (styp+moof+mdat+tfdt+trun, optional sidx); flux-ts (§11.4): 188-byte PAT/PMT/PES/PCR muxer.
  • Constraints: single-pass zero-copy box build (DP11); CMAF once, TS on demand (DP7); byte-deterministic output (I9/I10).
Deliverable

flux packages a live/file AU stream into CMAF init+media segments and (on demand) TS segments, written to a directory or the origin store. flux-probe boxes <seg> dumps the box tree; segments play in VLC/ffplay.

Acceptance
  • mp4dump/ffprobe parse every emitted CMAF segment with no errors; box tree diff vs a Shaka-packaged reference matches structurally.
  • Each video segment's first sample is an IDR (I4); tfdt equals cumulative prior durations (I10, asserted).
  • Byte-identical output for the same AU sequence across runs (DP11; insta snapshot gate).
  • TS: continuity counters gap-free per PID (I11); PCR monotonic ≤100 ms; ffprobe parses; CC=AAC/H.264 stream types correct.
  • fuzz_bmff_parse (self-parse) + fuzz_ts: zero panics.
Fixtures
  • conformance/fixtures/bmff/ref_init_1080p.cmfv + ref_seg_*.cmfv (Shaka/ffmpeg origin) → structural box-tree match.
  • conformance/fixtures/ts/ref_seg_*.ts → ffprobe frame parity.
  • conformance/fixtures/malformed/{trun_offset_overflow,box_size_mismatch}.bin → OffsetOverflow/BoxSizeMismatch (I9/I20).
Pitfalls
  • trun data_offset is signed i32 relative to the moof start — off-by-the-mdat-header is the classic bug; compute after the moof is sized.
  • tfdt version 0 (32-bit) vs 1 (64-bit) — long live streams overflow 32-bit decode time; always use v1.
  • mdhd/mvhd timescale mismatch — sample durations are in mdhd (track) timescale; mixing with mvhd (movie) drifts A/V sync.
  • TS PES length 0 for video — video PES may set length 0 (unbounded); the muxer must not write a wrong nonzero length.
  • CMAF box order — styp before moof; tfdt before trun; a wrong order parses in ffmpeg but fails strict players (DP14).
  • Default-flags vs per-sample flags — non-keyframe samples need sample_is_non_sync_sample=1; the first sample's first_sample_flags marks the IDR; getting this wrong makes seeking land on non-keyframes.

⬜ Phase 4 — ABR Ladder + Transcode Orchestration §16

Objectives
  • flux-ladder (§11.5): declare rungs (resolution×bitrate), enforce IDR/GOP alignment across all renditions (I3) for seamless switching, drive the EncoderBoundary (transcode) or pass-through.
  • Per-title / convex-hull ladder design notes; bitrate monotonicity.
  • Constraints: flux never encodes (DP3); the orchestrator commands and verifies (DP8). Transcode-farm driver → PhaseDeferred("§16").
Deliverable

Given an aligned multi-rung input (or a real transcode farm later), flux produces N independently-packaged, segment-aligned renditions; a player can switch rungs at any segment boundary onto an IDR (I4). Pass-through mode works with a single ingested rendition today.

Acceptance
  • verify_alignment rejects a deliberately misaligned fixture (IDR at 2.04 s vs 2.00 s) with IdrMisaligned (I3).
  • All rungs' segment N covers the identical presentation interval; segment N's first sample is an IDR on every rung (I4).
  • Bitrate monotonicity enforced; non-monotonic ladder rejected.
  • Manual switch test across all adjacent rungs shows no decode discontinuity at the boundary.
Fixtures
  • conformance/fixtures/bmff/ladder_aligned_{240,360,480,720,1080}.au → pass alignment.
  • conformance/fixtures/bmff/ladder_misaligned_720.au → IdrMisaligned.
  • examples/ladder_config.toml → parsed LadderSpec.
Pitfalls
  • Timescale-relative IDR comparison — rungs may use different mdhd timescales; comparing raw ticks is wrong (I3); compare rationals.
  • Encoder honoring forced-IDR — many encoders place an IDR near but not at the requested time (GOP-size rounding); the verify step is non-negotiable, and the EncoderBoundary contract must demand exact placement.
  • Audio alignment — audio frames (1024 samples) rarely align to video segment boundaries; segment on video IDR and let audio span; do not force audio splits mid-frame.
  • Per-title ladders — a fixed ladder wastes bits on simple content; note convex-hull/per-title as a future optimization, but keep the alignment contract identical.

⬜ Phase 5 — HLS Manifests (Master + Media; VOD/EVENT/LIVE) §17

Objectives
  • flux-hls (§11.6): master playlist (#EXT-X-STREAM-INF per rung, #EXT-X-MEDIA alt audio) + per-rendition media playlists (#EXTINF, #EXT-X-TARGETDURATION, #EXT-X-MEDIA-SEQUENCE, #EXT-X-MAP, #EXT-X-PLAYLIST-TYPE, #EXT-X-ENDLIST).
  • VOD (immutable, ENDLIST), EVENT (append-only), LIVE (sliding window); discontinuities (#EXT-X-DISCONTINUITY/-SEQUENCE).
  • Constraints: never advertise an unpublished segment (DP2/I1); monotonic media-sequence (I2); TARGETDURATION ≥ max EXTINF (I12).
Deliverable

A playable HLS stream: hls.js and Safari play VOD and LIVE off flux's manifests + P3 segments. flux-probe hls-validate <m3u8> checks invariants offline.

Acceptance
  • Apple mediastreamvalidator (or hls.js + Safari) accept master + media playlists with no errors.
  • VOD plays start-to-finish; LIVE plays with a stable sliding window; rung switching works (alignment from P4).
  • #EXT-X-TARGETDURATION ≥ every #EXTINF (I12); #EXT-X-MEDIA-SEQUENCE never decreases across reloads (I2).
  • A segment URI never appears before its bytes are committed (I1) — verified by the manifest-vs-store audit.
  • fuzz_m3u8 round-trip: parse(emit(model)) == model on valid fixtures.
Fixtures
  • conformance/fixtures/hls/{master,media_vod,media_event,media_live}.m3u8 → expected emitted text (snapshot).
  • conformance/fixtures/hls/discontinuity.m3u8 → expected DISCONTINUITY-SEQUENCE handling.
  • conformance/fixtures/malformed/{media_seq_regress,targetdur_violation}.json → MediaSeqRegression/TargetDurationViolation.
Pitfalls
  • TARGETDURATION is an integer (ceil) — emitting the float max EXTINF is a spec violation many validators flag.
  • #EXT-X-MAP placement — must precede the first #EXTINF it applies to; on a discontinuity with a new init, a new #EXT-X-MAP is required.
  • CODECS string accuracy — a wrong avc1.PPCCLL makes a player reject a variant it could play; derive from the SPS (P2), do not hardcode.
  • Window too small for buffer — a LIVE window shorter than the player's buffer causes the player to fall off the start (MEDIA-SEQUENCE jumps past its position) → stall; window ≥ player buffer + margin.
  • #EXT-X-VERSION mismatch — using a tag (e.g. #EXT-X-PART) below its required version makes strict players reject the playlist.

  • dash.js/ExoPlayer play VOD and live; rung adaptation works.
  • The identical CMAF segment files serve both HLS (#EXT-X-MAP/#EXTINF) and DASH (Initialization/media) (DP7).
  • Segment numbers/times monotonic (I2); @duration/timeline consistent (I12-analog).
  • fuzz_mpd round-trip on valid fixtures.
Fixtures
  • conformance/fixtures/dash/{mpd_static,mpd_dynamic,mpd_timeline}.mpd → snapshot + DASH-IF validation.
  • conformance/fixtures/dash/multi_period.mpd → multi-Period handling.
  • conformance/fixtures/malformed/mpd_number_regress.json → segment-number regression rejected.

  • presentationTimeOffset — needed when the first segment's tfdt isn't zero (live join, trimmed VOD); omitting it shifts the timeline.

⬜ Phase 7 — Low-Latency (LL-HLS + LL-DASH) §19

Objectives
  • LL-HLS: #EXT-X-PART partial segments, blocking playlist reload, #EXT-X-PRELOAD-HINT, #EXT-X-RENDITION-REPORT, #EXT-X-SERVER-CONTROL (PART-HOLD-BACK, CAN-BLOCK-RELOAD, CAN-SKIP-UNTIL).
  • LL-DASH: chunked CMAF (moof+mdat chunks via HTTP chunked transfer), availabilityTimeOffset, ProducerReferenceTime/prft, <Resync>.
  • Target: sub-3 s glass-to-glass (2–5 s LL-HLS, 2–4 s LL-DASH, §4).
  • Constraint: a part/segment is advertised only when fully written (DP2 for LL, I13).
Deliverable

Sub-3 s glass-to-glass on hls.js (LL mode) and dash.js (low-latency mode). flux-probe latency <stream> measures ingest→available; the LL state machine (parts, preload hint, blocking reload) is observable.

Acceptance
  • LL-HLS: measured glass-to-glass 2–5 s; blocking reload holds until the part commits then returns within one part interval; hls.js LL mode + Safari LL play.
  • LL-DASH: 2–4 s; chunked transfer verified (response begins before segment completes); dash.js low-latency mode plays.
  • A part is never advertised before Complete (I13); PRELOAD-HINT names exactly the open part.
  • Held connections bounded (≥20,000/replica, §4) with a hard timeout — never an indefinite hold.
Fixtures
  • conformance/fixtures/hls/ll_media.m3u8 (parts + preload-hint + server-control) → snapshot.
  • conformance/fixtures/hls/blocking_reload_seq.json — request _HLS_msn/_HLS_part timeline → expected hold/return behavior.
  • conformance/fixtures/dash/ll_chunked.mpd (ATO + ProducerReferenceTime) → DASH-IF LL validation.
Pitfalls
  • PART-HOLD-BACK too small — must be ≥ 3× part-target (Apple rule); too small makes the player request parts that don't exist → stall.
  • Indefinite blocking reload — a missing timeout on a future _HLS_msn exhausts file descriptors; always bound the wait (§4) and return the current playlist on timeout.
  • INDEPENDENT misuse — marking a non-IDR part INDEPENDENT lets a player start on a non-decodable part → garbled video; gate on actual IDR (I8-analog).
  • Chunked-transfer + Content-Length — for LL-DASH chunked transfer you must NOT send Content-Length; mixing them breaks the chunked encoding.
  • HTTP/1.1 head-of-line — LL-HLS part fan-out benefits from HTTP/2 multiplexing; on HTTP/1.1, many parallel part fetches stall behind each other.
  • Thundering-herd wake — when a part commits, all parked waiters wake at once; coalesce the render (one Arc<str>) and hand the same snapshot to all.

⬜ Phase 8 — Origin HTTP Delivery §20

Objectives
  • flux-origin (§11.7): serve segments + manifests over HTTP/1.1+2; byte-range requests; cache-control/ETag/conditional (If-None-Match/If-Modified-Since); CORS; the DVR ring + optional object-store spill.
  • The publication boundary enforcing I1/I18 (segment/init before reference) for the whole HAS path.
  • Constraints: stateless horizontally-scalable origin; immutable cacheable segments (DP11); bounded DVR memory (DP13).
  • Cross-link #64 (HTTP/2/3), #159 (CDN edge), #82 (reverse proxy).
Deliverable

A complete, CDN-frontable HTTP origin: a CDN or a browser pulls manifests + segments with correct caching, range, and CORS; LL blocking reload works end-to-end; the full HAS pipeline (ingest→package→manifest→deliver) is live.

Acceptance
  • ≥10,000 concurrent segment GETs and ≥50,000 manifest req/s per replica (§4) in the load harness.
  • Range requests return correct 206/Content-Range; conditional requests return 304.
  • A CDN (or curl honoring cache headers) caches immutable segments; ETag stable across replicas for the same segment (DP11).
  • Init/segment never served before commit (I1/I18); player 404 rate ≈ 0 under steady state.
  • CORS lets a cross-origin hls.js/dash.js play.
Fixtures
  • conformance/fixtures/http/range_requests.json — range specs → expected 206/416 + bytes.
  • conformance/fixtures/http/conditional.json — ETag/If-None-Match → 304.
  • conformance/oracles/player_interop/ — headless hls.js/dash.js against the live origin.
Pitfalls
  • Weak vs strong ETag — segments are immutable → strong ETag from content; a per-replica random ETag breaks CDN revalidation across replicas (use the deterministic content hash, DP11).
  • Range on a still-forming segment (LL chunked) — a range request on a chunked-transfer segment is ill-defined; return the committed prefix or refuse.
  • CORS preflight for byte-range — Range is not a CORS-safelisted header; preflight must allow it or players fail silently.
  • max-age on LIVE manifests — too long caches a stale playlist at the CDN → players stuck behind live; LIVE manifests are no-cache/very short.
  • Eviction vs in-flight serve — evicting a segment a slow client is still reading; the Arc<Bytes> keeps it alive for that reader even after ring removal (DP13 memory accounted).

⬜ Phase 9 — WebRTC SFU Core (RTP/RTCP Forwarding) §21

Objectives
  • The real-time path: flux-rtp (§11.8) RTP/RTCP parse/serialize + jitter buffer; flux-sfu (§11.9) Router/Producer/Consumer with SSRC demux + reference fan-out + SSRC/seq/ts rewrite.
  • Packet forwarding only — NO transcode (DP3); publisher↔subscriber fan-out.
  • SRTP boundary is a trait seam (path begins at decrypted RTP, ends at plaintext RTP back to transport #161); SDP/signaling deferred → PhaseDeferred("§21") (the control plane consumes resolved RtpParameters).
  • Constraint: per-consumer continuity under rewrite (DP6, I5/I6/I7); keyframe-before-delta (I8); <10 ms node forward latency (§4).
Deliverable

Two peers (transport stubbed with a plaintext-RTP adapter) publish and subscribe through the SFU; B receives A's forwarded RTP with continuous seq/ts and a stable SSRC, decodable from the first keyframe. tools/pcap_replay feeds a captured RTP stream into the router for repro.

Acceptance
  • A forwarded stream decodes in a browser (or pcap_replay + ffprobe) with no seq gaps (I5), monotonic ts (I6), one SSRC (I7).
  • First egress packet to a new consumer is a keyframe (I8); no delta leaks before it.
  • Node forward latency (demux→route→rewrite) < 10 ms p99 in the bench (§4).
  • fuzz_rtp/fuzz_rtcp: zero panics over malformed packets (§8.14).
  • Jitter buffer reorders out-of-order fixtures correctly; overflow drops to keyframe, not OOM (DP9).
Fixtures
  • conformance/fixtures/rtp/h264_fua_stapa.bin → expected NAL/IDR detection + reframe.
  • conformance/fixtures/rtcp/{sr,rr,sdes,bye}.bin → parsed structs.
  • conformance/fixtures/rtp/reorder_seq.pcap → expected jitter-buffer output order.
  • conformance/fixtures/malformed/{rtp_short,rtp_bad_ext,rtp_bad_csrc,rtcp_bad_len}.bin → typed drops (§8.14).
Pitfalls
  • Seq/ts rewrite offset across a producer restart — when the source SSRC changes, the consumer must keep its egress seq/ts continuous (recompute offsets), or the client sees a pipeline reset (DP6 violation, I7).
  • Marker-bit semantics — the marker bit ends a frame (video) or marks talk-spurt start (audio); copying it wrong fragments frames at the client jitter buffer.
  • Wraparound < — comparing SeqNum/RtpTimestamp with naive < is a defect near the 16/32-bit wrap (I5/I6); always use the wraparound helpers.
  • STAP-A timestamp — aggregated NALs share one RTP timestamp; splitting them for forwarding must preserve it.
  • Jitter-buffer-induced latency — too deep a buffer adds latency (violates <500 ms); adaptive depth must shrink under low jitter.

⬜ Phase 10 — Simulcast + SVC (Layer Selection) §22

Objectives
  • Simulcast: producer sends N independent encodings (RID-tagged, RFC 8852/8853); per-consumer spatial-rung selection.
  • SVC: layered single stream (VP9/AV1), temporal/spatial layers; forward a prefix; AV1 Dependency Descriptor for selective forwarding.
  • Layer switching ONLY at keyframe/decodable boundaries (I8); per-consumer LAYER SELECTOR (the core SFU value).
  • Constraint: switch sequencing preserves continuity (DP6, I5/I6); the SFU still never transcodes (DP3).
Deliverable

A consumer subscribed to a simulcast/SVC producer is fed one selected layer; a manual layer-switch API (fluxctl) up/down-switches with continuous egress and a clean keyframe boundary on up-switch. Temporal SVC frame-rate drop works with no keyframe.

Acceptance
  • Up-switch (q→f) splices exactly at the f keyframe; egress seq/ts stay continuous (I5/I6); first f packet is the keyframe (I8).
  • Down-switch happens at the next frame boundary with no keyframe (simulcast, recent keyframe present) and no decode break.
  • SVC temporal drop (T2→T1→T0) reduces frame rate cleanly; base layer alone decodes.
  • AV1 DD: forwarding a decode target with a missing chain dependency is refused (no undecodable forward).
  • Switch never emits a delta before the target's keyframe (I8); layer_switch_invalid_total increments on an invalid target.
Fixtures
  • conformance/fixtures/rtp/simulcast_qhf.pcap → per-RID demux + switch sequence.
  • conformance/fixtures/rtp/vp9_svc.pcap → temporal/spatial prefix forwarding.
  • conformance/fixtures/rtp/av1_dd_l3t3.pcap → DD-driven decode-target selection.
  • conformance/fixtures/malformed/layer_switch_bad_rid.json → layer_switch_invalid_total.
Pitfalls
  • Simulcast ts realignment — each RID has an independent timestamp base; the splice must compute ts_offset so the consumer's egress ts is continuous across the q→f boundary (I6) — the canonical simulcast bug.
  • SVC vs simulcast confusion — SVC layer drop needs NO keyframe (the base is self-sufficient); requesting one wastefully triggers a keyframe storm. Simulcast rung switch DOES need a target keyframe.
  • AV1 chain integrity — forwarding a frame whose referenced frame (per the DD chain) was dropped produces an undecodable target; the chain check is mandatory.
  • Temporal-layer marker bits — dropping higher-T packets must not orphan a frame's marker bit; track frame boundaries per temporal layer.
  • Stale layer targeting — the LAYER SELECTOR must only target Active layers; a Stale RID (no recent packets) needs a keyframe request first.

⬜ Phase 11 — Jitter Buffer Resilience + Congestion Control §23

Objectives
  • flux-nack (§11.10): NACK responder over the producer packet cache (RTX, RFC 4588); KEYFRAME MANAGER (PLI/FIR, RFC 4585/5104) rate-limited.
  • flux-bwe (§11.10): Google Congestion Control — delay-based (trendline/over-use detector over abs-send-time/TWCC) + loss-based AIMD, fused to a per-consumer target; TWCC feedback, REMB (legacy), probing; leaky/token-bucket pacer.
  • Drive the P10 LAYER SELECTOR from the estimate (the closed loop); RED/FEC notes.
  • Constraints: forwarded bitrate never exceeds the estimate (I15); pacer honest over any window (I16); NACK never resends an evicted packet (I14); BWE converges <1 s (§4).
Deliverable

The SFU adapts: under emulated congestion (tc netem/Mahimahi) a consumer down-switches and recovers; lost packets are retransmitted (RTX) within the window or a keyframe is requested; egress is paced. bwe_step bench shows convergence.

Acceptance
  • BWE converges to within 10% of available bandwidth in <1 s after a step change (§4, RMCAT-style scenarios).
  • Forwarded bitrate never exceeds the estimate (I15); pacer never exceeds target over any sliding window (I16).
  • NACK resends a cached packet; a NACK for an evicted packet falls back to PLI (I14), never stalls.
  • Keyframe requests coalesced + rate-limited ≤1/stream/500 ms (§4); no storm under mass switch.
  • Under 5% loss, RTX recovers; under 20% loss, the system down-switches + requests keyframes, never disconnects (DP4).
Fixtures
  • conformance/fixtures/rtcp/twcc_feedback.bin → parsed deltas + estimate step.
  • conformance/fixtures/netem/{step_down,step_up,loss5,loss20,reorder}.profile → expected estimate/layer trajectory.
  • conformance/fixtures/rtcp/nack_blp.bin → expected resend set.
  • conformance/fixtures/malformed/twcc_unknown_seq.bin → twcc_unknown_seq_total, ignored.
Pitfalls
  • TWCC reference-time units — 64 ms reference time, 250 µs deltas; mixing units corrupts the delay model (§8.9).
  • Over-use detector threshold adaptation — a static γ mis-detects on different paths; γ(i) must adapt (the GCC paper's key detail, P1/P2), or BWE oscillates or never reacts.
  • Pacer starving the queue — too-tight a bucket queues packets and adds latency (violates <500 ms); the bucket refill must track the target and shed, not buffer unboundedly (DP9/I16).
  • NACK amplification — answering every NACK during a burst can worsen congestion; bound RTX rate and prefer a keyframe past the window (I14).
  • Probe misread as congestion — a probing burst raises delay; the estimator must attribute probe-induced delay correctly or it down-switches on its own probe.
  • Loss vs delay disagreement — taking max instead of min(A_delay,A_loss) overcommits (I15); always the min.

⬜ Phase 12 — Observability + DVR/Time-Shift + CENC §24

Objectives
  • Full observability: metrics (startup latency, rebuffer ratio proxy, bitrate distribution, segment publish lag), tracing, structured logging across both paths (DP12).
  • DVR/time-shift sliding window (the configurable HAS catch-up buffer); timeShiftBufferDepth/HLS window management at scale.
  • CENC packaging (flux-drm, §11.11): cenc/cbcs, PSSH, key-id mapping, KeyProvider seam (license servers deferred §24).
  • Constraint: every encrypted sample mapped by senc (I17); telemetry sufficient to debug a timing bug without a packet capture (DP12).
Deliverable

A fully observable server: Grafana dashboards for both paths; a configurable DVR window a player can seek back into; CENC-encrypted CMAF segments that a (test-key) player decrypts and plays. flux-probe inspects encrypted boxes + DVR state.

Acceptance
  • Every §4 SLO has a metric + dashboard panel; every invariant (I1–I20) has a counter.
  • DVR: a player seeks back to the window start and forward to live; eviction keeps memory bounded (DP13) at the configured depth.
  • CENC: mp4dump shows correct encv/sinf/tenc/senc/pssh; a Shaka/test-key player decrypts and plays both cenc and cbcs.
  • Every encrypted sample has a valid senc entry (I17); a deliberately unmapped sample fails packaging (cenc_sample_unmapped_total).
  • A simulated stall is diagnosable from metrics/logs alone (DP12) — no pcap needed.
Fixtures
  • conformance/fixtures/cenc/{cenc_seg,cbcs_seg}.cmfv + KIDs → mp4dump box parity + test-key decrypt.
  • conformance/fixtures/cenc/pssh_widevine.bin → expected system-id/KID parse.
  • conformance/fixtures/malformed/cenc_subsample_overflow.json → DrmError::SubsampleRange (I17).
  • conformance/fixtures/dvr/seek_window.json — seek positions → expected segment availability.
Pitfalls
  • cbcs constant IV — cbcs uses a constant per-sample IV + pattern encryption; cenc uses a per-sample counter IV; swapping them yields undecryptable output.
  • Clear NAL header bytes — the NAL length prefix + header must stay clear (subsample clear count) so the depacketizer can parse; encrypting them breaks playback.
  • saio offset base — saio offsets are relative to a base (often the moof or mdat); a wrong base makes the client read garbage IVs.
  • Metric cardinality — per-stream/per-consumer labels can explode Prometheus; bound cardinality (aggregate per rendition, not per viewer).
  • DVR memory underestimate — deep DVR × high bitrate × many renditions = large RAM; force the spill path past a RAM threshold (DP13).

⬜ Phase 13 — Conformance + Benchmarking + Production Hardening §25

Objectives
  • Differential conformance: manifest validators + player interop (hls.js/dash.js/Safari/ExoPlayer) as fixtures; box/packet validators (ffprobe/mp4dump/Shaka/DASH-IF).
  • Benchmarking: throughput (concurrent viewers/streams, forwarded pkt/s, egress Gbps), latency (glass-to-glass, forward latency), BWE convergence — all gated against §4.
  • Production hardening: the fuzz gate (zero panics, DP10), soak tests, the full CI/CD + supply-chain pipeline.
  • Constraint: every emitted byte validated against an independent oracle (DP14); §4 targets met under load.
Deliverable

A production-bar release: every format validated against independent oracles + real players; all §4 throughput/latency targets met under load; zero fuzz panics; a 24 h soak passes; signed, SBOM'd, containerized artifacts. v1.0.0.

Acceptance
  • ffprobe/mp4dump/Shaka/DASH-IF accept all emitted segments/manifests; hls.js/dash.js/Safari/ExoPlayer play all fixtures (the automatable subset green in CI).
  • §4 met: ≥10k segment GETs, ≥50k manifest req/s, ≥500 peers/room, ≥2M pkt/s/node, 10–40 Gbps, SFU forward <10 ms p99, glass-to-glass <500 ms SFU / <3 s LL-HAS, BWE <1 s convergence.
  • Fuzz: zero panics across all targets (PR smoke + nightly long).
  • 24 h soak: flat memory (DP13), zero seq/ts discontinuities (I5/I6), no fd leak.
  • Bench-regression gate: no >10% regression vs the committed baseline.
  • Release: signed binaries + container; SBOM present; reproducible build (--locked).
Fixtures
  • The full conformance/fixtures/ corpus (Appendix A): rtmp, bmff, ts, hls, dash, rtp, rtcp, cenc, netem, malformed.
  • conformance/oracles/player_interop/results.json — per-player/per-fixture expected outcomes.
  • benchmarks/baseline.json — committed throughput/latency baselines for the regression gate.
Pitfalls
  • Oracle disagreement — ffmpeg tolerates near-spec output another player rejects (DP14); the conformance bar is the strictest oracle + real players, not the most lenient.
  • Load-harness as bottleneck — flux-loadgen itself can be the limiter; verify the harness can generate the target load (separate machine / multiple processes).
  • Flaky player-interop in CI — headless browsers + media are flaky; pin versions, retry with quarantine, and treat real-device runs as a release gate, not a per-PR gate.
  • Soak masking slow leaks — a leak below the noise floor over 24 h needs a longer soak or explicit allocation accounting (docs/performance/allocation-budget.md).
  • Bench variance — tail-latency benches are noisy; run multiple iterations, report p50/p99, and gate on a robust statistic.
