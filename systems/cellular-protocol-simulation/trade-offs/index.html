ADR-01

Primary language

Chosen

Rust

Rejected

C++, Go

When the rejected choice is right

wrapping an existing vendor PHY library written in C++ directly

ADR-02

Simulation paradigm

Chosen

discrete-event

Rejected

time-stepped

When the rejected choice is right

replaying a fixed-rate RF fading trace where ticks map to trace samples

Why: events are sparse relative to wall-clock, so time-stepping wastes cycles

ADR-03

Chosen

When the rejected choice is right

Roads not taken (§36)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Full System-Level Simulator with a Detailed OFDM PHY

[UE PHY: OFDM waveform] <-- fading/channel --> [gNB PHY: OFDM waveform]
        |                                             |
   [MAC / RLC / PDCP / RRC]                   [MAC / RLC / PDCP / RRC]
        |                                             |
      [NAS]  <----------- N2 / S1 ------------->  [Core NFs]

Winning regime: PHY-layer research — scheduler algorithms under realistic fading, link-adaptation studies — where waveform-level accuracy is the actual research question. REAL embodying system: ns-3 with the 5G-LENA module. Why rejected: this project's load-bearing concern is call-flow/state-machine fidelity (P1), and OFDM-level detail multiplies simulation cost by orders of magnitude for no benefit to the message-sequence questions this simulator answers (§1 non-goals).

Real-Radio SDR Stack

[UE: SDR + srsUE stack] == real RF over the air == [gNB: SDR + srsENB stack]
                                    |
                              [Core: EPC / 5GC]

Winning regime: interoperability testing against real commercial UEs/networks, lab validation, spectrum research. REAL embodying system: srsRAN, OpenAirInterface. Why rejected: requires SDR hardware and real-time constraints, precludes the 100,000-UE/ 2,000-cell scale target (§4) and the deterministic-replay guarantee (I11) this project depends on — real RF is inherently non-repeatable bit-for-bit.

Time-Stepped Engine (Fixed-Tick Simulation)

tick 0 -> update all UEs/cells -> tick 1 -> update all UEs/cells -> tick 2 -> ...

Winning regime: workloads where events are dense relative to the tick granularity, e.g. replaying a fixed-rate RF fading trace where ticks map directly to trace samples (ADR-02's rejected-alternative note). REAL embodying system: fixed-TTI-loop system-level simulators (ns-3's own PHY sublayer ticks per-TTI inside its outer discrete-event loop). Why rejected: this project's events (attach, handover, paging) are sparse relative to any tick fine enough to resolve them, so fixed-tick stepping wastes cycles idling through empty ticks at the 100,000-UE scale target (ADR-02).

Emulation: Real NF Software in Containers with Simulated UEs

[simulated UE stack] --N1/N2 (real HTTP/2 SBI)--> [Open5GS AMF container] -- [SMF] -- [UPF]

Winning regime: core-network integration testing, validating a real core's behavior against synthetic UE load, operational rehearsal for a real 5G-core deployment. REAL embodying system: Open5GS/free5GC run in Docker/Kubernetes with a synthetic UE-simulator front end. Why rejected: real SBI/HTTP-2 wire encoding and NF process orchestration are exactly the fidelity layer ADR-18 explicitly excludes (typed message-passing abstraction, not byte-accurate wire encoding), and container-orchestration overhead precludes the deterministic single-process replay guarantee (I11, ADR-17) this project's correctness claim depends on.
