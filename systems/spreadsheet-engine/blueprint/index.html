Project Name: Spreadsheet Engine from Scratch

Owner: Mujir Qureshi

Status: specification — locked

1. Goal

Build a deterministic, embeddable spreadsheet calculation engine in Rust: a library that owns a workbook of sheets, parses cell formulas, builds a dependency graph, and recalculates values incrementally and (optionally) in parallel, with Excel/Calc-compatible semantics. Not a GUI — a calculation core + thin CLI/server.

Precise scope. Engine ingests cell writes (literals or =formula), tokenizes + parses formulas to AST, resolves references (A1/R1C1, absolute/relative/mixed, cross-sheet, named ranges), builds a directed dependency graph (precedents → dependents), topologically orders dirty cells, evaluates with IEEE-754 arithmetic and an Excel-compatible error/coercion model, detects cycles (SCC), supports iterative calculation, dynamic-array spilling, structural edits with reference fixup, undo/redo, and CSV import/export. xlsx import/export is a bounded subset; full OOXML is deferred.

System boundaries.

  • In: value model, formula language (lexer→parser→AST), reference model, dependency graph, recalc engine (full + incremental + parallel), cycle handling, function library (~120 functions, P0 set ~40), dynamic arrays/spilling, structural edits + ref rewriting, persistence (op-log, snapshot), undo/redo, number formatting/locale, date serials, CSV I/O, xlsx subset, CLI, headless server (gRPC/JSON-RPC), conformance + differential harness, fuzzing.
  • Out (non-goals): rendering/UI/layout/charts/pivot tables/conditional-formatting visuals; collaborative OT/CRDT multi-user editing; macros/VBA/scripting; full OOXML fidelity (styles, drawings, themes); database-backed sheets; cell comments/threads; real-time streaming data feeds. Each gated below.

Explicit non-goals (gated).

  • Charts / sparklines / drawings → PhaseDeferred("Deferred Features Register").
  • Pivot tables / GETPIVOTDATA → PhaseDeferred("Deferred Features Register").
  • VBA / macro / LAMBDA-helper full suite → PhaseDeferred("Deferred Features Register").
  • Real-time collaborative editing (OT/CRDT) → PhaseDeferred("Deferred Features Register").
  • Full OOXML styles/themes/conditional-format round-trip → PhaseDeferred("Deferred Features Register").
  • GPU/SIMD-accelerated bulk recalc → PhaseDeferred("Deferred Features Register").
  • Distributed/sharded multi-machine workbook → PhaseDeferred("Deferred Features Register").

Deployment model. Primary: #![no_std]-friendly embeddable library crate (sheetcalc-core) linked into host apps (desktop, web via WASM, server). Secondary: sheetcalc-cli (load CSV/xlsx, set cells, recalc, dump). Tertiary: sheetcalc-server (headless, JSON-RPC + gRPC, one workbook per session, snapshot isolation for reads). FFI: C ABI (sheetcalc-ffi) + WASM (sheetcalc-wasm).

Target users. (1) App developers embedding a calc engine (BI tools, low-code, finance apps). (2) Engineers learning interpreter/dependency-graph/incremental-computation internals. (3) Tooling that needs headless Excel-formula evaluation (server-side report generation, data validation).

What later phases unlock. P0 store+value → P1 parse → P2 references → P3 graph → P4 eval → P5 cycles → P6 incremental → P7 functions → P8 arrays/spill → P9 edits → P10 parallel → P11 persistence → P12 formatting → P13 conformance/fuzz. Each phase consumes the prior; the engine becomes "usable" at P4 (single-shot recalc), "production-shaped" at P10, "shippable" at P13.

Timeline. Phase-0 (P0–P4 core slice: store, lexer, parser, refs, single-shot eval): 8–12 weeks for one engineer. Full P0–P13: 9–14 months. Per-phase durations in Appendix B.

Recommended language: Rust. Rationale (exact): (a) deterministic, no-GC — no GC pauses skew recalc latency p99; bit-stable floats with explicit ordering. (b) algebraic enums + exhaustive match — model CellValue, ErrorKind, FormulaAst, Reference precisely; compiler forces handling every error variant (error precedence cannot silently drop a case). (c) fearless concurrency — Send/Sync + ownership lets parallel subgraph recalc (rayon) be data-race-free by construction; snapshot isolation expressed as Arc<Snapshot>. (d) zero-cost abstractions + cache control — sparse columnar storage with #[repr] control, arena allocation, minimal indirection for 1M-cell workbooks. (e) first-class WASM target — same core ships to browser. (f) fuzzing + property testing mature (cargo-fuzz/libfuzzer, proptest). Rejected alternatives in ADR-001.

Prerequisites.

  • Compilers/interpreters: lexing, Pratt/precedence parsing, AST evaluation, tree-walking interpreters, error recovery.
  • Algorithms: topological sort (Kahn), strongly-connected components (Tarjan/Kosaraju), graph incremental update, memoization, fixed-point iteration.
  • Numerics: IEEE-754 (rounding, NaN/Inf, subnormals, comparison pitfalls), decimal vs binary float, date serial arithmetic.
  • Concurrency: work-stealing pools, snapshot isolation, lock-free vs RwLock, false sharing, deterministic parallel reduction.
  • Data structures: sparse matrices, columnar/interval storage, interned strings, generational arenas.
  • Spreadsheets domain: A1/R1C1 addressing, Excel error taxonomy, volatile functions, dynamic arrays/spilling, 1900/1904 date systems.

2. Why Build This

Unique systems knowledge. A spreadsheet engine is a demand-driven incremental compiler+interpreter over a sparse mutable graph. It forces mastery of three normally-separate disciplines at once: (1) language front-end (lex/parse/AST), (2) graph algorithms under mutation (topo-order, SCC, dirty propagation), (3) numeric/semantic fidelity (IEEE-754, error algebra, locale). Few systems combine all three with hard determinism + latency requirements.

Historical/architectural significance. VisiCalc (1979) and Lotus 1-2-3 defined the recalculation problem; modern engines (Excel, LibreOffice Calc, Google Sheets, HyperFormula, IronCalc) all reimplement the same core: cell dependency graph + incremental recompute. Sestoft's Spreadsheet Implementation Technology (MIT Press 2014) is the canonical text. The dependency graph is the spreadsheet's "CPU"; getting minimal-recompute + cycle handling right is the entire game.

Engineering muscles developed.

  • Incremental computation (dirty marking, minimal recompute) — same theory behind build systems (Bazel, Salsa, Adapton), reactive UIs, query engines.
  • Parser engineering with operator precedence + error recovery.
  • Graph algorithms under continuous mutation (not the textbook one-shot case).
  • Numerical correctness + differential testing against reference oracles.
  • Concurrency with snapshot isolation + deterministic parallel reduction.

Production engineering concepts exercised. Determinism/reproducibility, bounded resource usage (cell/edge caps), backpressure (recalc queue), observability (recalc traces, dirty-set metrics), crash recovery (op-log replay), compatibility (formula/file format), fuzzing (parser/eval hardening), differential conformance.

Cross-links to portfolio.

  • Compilers / interpreters: shares lexer/parser/AST/eval with any language project; Pratt parsing reused.
  • Databases / query engines: dependency graph ≈ query DAG; columnar cell store ≈ column storage; incremental recalc ≈ incremental view maintenance.
  • Build systems: dirty propagation + topo rebuild is identical to Make/Bazel/Salsa.
  • Reactive runtimes: spilling + dependency tracking ≈ signal graphs (SolidJS/MobX).
  • Storage engines: op-log + snapshot ≈ WAL + MVCC.
  • Observability stacks: recalc tracing ≈ span graphs.

Calibration value. After this, "incremental recomputation over a mutable dependency graph" becomes a reusable mental model. You will never again hand-roll an O(n) full rebuild where a dirty-set O(affected) recompute suffices. You internalize that correctness in numerics is differential, not unit (you test against an oracle). The cycle/SCC + fixed-point machinery transfers directly to dataflow, constraint solvers, and reactive systems.

What Mastery Looks Like

  • Incremental-computation design (P3/P6): given any mutable computation graph, you can specify a dirty-set propagation protocol, prove its completeness, and bound its worst-case recompute cost — transferable to build systems, reactive runtimes, and query engines.
  • Pratt parsing with error recovery (P1): you can hand-write a complete operator-precedence parser for any expression language with precedence tables, right-associativity, postfix operators, and structured error recovery yielding diagnostic spans.
  • Graph algorithms under mutation (P3/P5/P9): topological sort with incremental in-degree updates, iterative Tarjan SCC on explicit stacks, and SCC-condensation-based evaluation order — skills usually taught in isolation, here exercised simultaneously under continuous edit.
  • Deterministic parallel evaluation (P10): you know how to partition an evaluation DAG into independent layers, execute them under work-stealing, merge results in a fixed order, and mechanically verify determinism via byte-diff CI harness.
  • Numerical fidelity via differential testing (P4/P7/P12): you build and operate a differential oracle harness (engine vs LibreOffice/formulajs), catalog documented divergences, and understand where IEEE-754 binary64 diverges from decimal expectation.
  • Crash-only persistence with op-log replay (P11): you can design a snapshot + append-only WAL system, prove its recovery invariants, and implement grouped-commit + snapshot-before-truncate to guarantee RPO/RTO bounds.
  • Snapshot isolation without a database (P10/P11): you implement reader/writer isolation using Arc<Snapshot> + COW staging, achieving lock-free reads from an in-process mutable store.
  • Conformance and fuzz engineering (P12): you operate a multi-oracle differential harness, maintain a fuzz corpus, and gate releases on zero unexplained divergences — industrializing correctness rather than relying on unit tests alone.

Box-by-box (one paragraph each).

Front ends (cli/server/ffi/wasm). Thin adapters that translate external requests (set_cell, get_value, recalc, insert_rows) into core API calls. The server holds one Workbook per session; reads serve from an immutable Arc<Snapshot> (snapshot isolation) so a long read never blocks a write and never sees a half-finished recalc. No business logic here; all semantics live in core. WASM/FFI expose the same Workbook API across an ABI.

Workbook (owner). The single owner of all sheets, the named-range table, the dependency graph, the function registry, and the op-log. All mutation funnels through it (&mut self); it is the concurrency root. It enforces invariants (no dangling refs, acyclic-or-flagged graph, dirty-set ⊇ all affected). It produces snapshots for readers and applies/undoes ops atomically.

Lexer (sheetcalc-lex). Converts formula text into a token stream: numbers, strings, booleans, errors, operators, references, function names, separators, parens, braces, ranges. Locale-aware on argument separator (, vs ;) and decimal point. Pure, allocation-light, streaming; produces precise spans for diagnostics. No semantics — just lexical structure.

Parser (sheetcalc-parse). Pratt / precedence-climbing parser producing a FormulaAst. Encodes the full operator precedence/associativity table, unary +/-/%, range :, intersection (space), union ,, comparison, concat &, exponent (right-assoc). Emits structured parse errors (→ #NAME?/#ERROR! paths). ASTs are interned/shared so identical formulas reuse one tree.

Reference model (sheetcalc-ref). Resolves textual references against the current sheet/cell context: relative A1, absolute $A$1, mixed, cross-sheet Sheet1!A1, quoted 'My Sheet'!A1, named ranges, R1C1 (R[1]C[-2]). Produces canonical CellId/RangeRef. Owns the named-range table. Critical for reference fixup on structural edits (the offset math lives here).

Cell store (sparse columnar). The data plane: stores per-cell value/formula/format sparsely (most of a 1M×16K grid is empty). Columnar layout (column → sorted run/interval map) for cache-friendly column scans (SUM(A:A)) and cheap row/col insert. Holds CellValue, optional FormulaAst handle, cached evaluated result, format id, spill metadata. Mutated only via Workbook; readable from snapshots.

Dependency graph (sheetcalc-graph). Bidirectional graph: precedents (cells/ranges a formula reads) and dependents (cells whose formula reads this cell). Supports topo order via Kahn, SCC via Tarjan for cycle detection. Edge cardinality can be huge (a range precedent = one edge to a range node, not N edges) — range nodes avoid O(N²) blowup. Rebuilt incrementally as formulas change.

Function registry (sheetcalc-fn). Maps function name → metadata (arity, arg coercion rules, volatility, array-awareness) + evaluator. ~120 functions across math/stat/logical/lookup/text/date/info/financial. Tracks the volatile set (NOW/TODAY/RAND/RANDBETWEEN/OFFSET/INDIRECT/CELL/INFO) so recalc always re-evaluates them. Pluggable: hosts can register custom functions.

Recalc engine (sheetcalc-recalc). The orchestrator. On dirty cells: compute affected set (forward closure over dependents), topo-order them, evaluate in order, handle spills (re-anchor, detect #SPILL!), run cycle/iterative loop for SCCs, and (P10) farm independent subgraphs to a work-stealing pool under snapshot isolation. Emits recalc traces + metrics.

Evaluation engine (sheetcalc-eval). Tree-walks one cell's AST against an EvalContext (snapshot of precedent values + sheet context + registry). Implements type coercion (text↔number↔bool), the error model + first-error propagation, comparison semantics, array broadcasting, implicit intersection. Pure w.r.t. a snapshot — same inputs → same output (determinism invariant).

Dynamic arrays (sheetcalc-array). Handles array results that spill into neighboring cells (Excel 365 dynamic arrays). Owns spill anchors, spill ranges, collision detection (#SPILL!), implicit intersection (@), and array broadcasting rules. Interacts tightly with the store (reserve spill region) and graph (spill region becomes precedent-affecting).

Number formatting (sheetcalc-fmt). Display layer: number format codes (#,##0.00, 0.00%, date/time patterns), locale (decimal/thousands/date order), date serials (1900 vs 1904 epoch, the Lotus 1900 leap-year bug). Separates stored value (canonical f64/serial) from displayed string. Never affects computation (formatting is presentation-only).

Undo log / op-log. Records every mutation as a reversible op (set-cell, edit, define-name). Powers undo/redo (in-memory ring) and durability (append-only WAL .scwal). On crash, replay log over last snapshot to recover. Ops are the unit of compatibility + the audit trail.

Persistence (sheetcalc-persist). Snapshot files (.scbk, full workbook image) + op-log (.scwal, incremental). CSV import/export (lossy, values only). xlsx subset (sheets, cells, formulas, basic formats; no charts/styles). Recovery = load snapshot + replay tail of op-log. Format versioning + migration handled here.

CPU/cache assumptions. x86-64 + aarch64; 64-byte cache lines; column scans must be cache-friendly (sequential interval map). Avoid false sharing in parallel recalc (per-thread result buffers, aligned). NUMA: single-node, pin pool to one node for large workbooks; cross-socket recalc not optimized (deferred).

Network (server). Local/LAN RTT assumed < 1 ms; engine is CPU-bound not network-bound. One workbook per connection; no cross-connection coordination.

6. Design Principles

  1. Determinism over convenience. Same workbook + same inputs ⇒ bit-identical results across runs, machines, thread counts. Tradeoff: forbids unordered float reductions and HashMap iteration in compute paths. Operational: enables differential testing + replay debugging. Violation: parallel SUM with non-deterministic add order → results differ run-to-run → conformance + replay both break, bug becomes irreproducible.

  2. Demand-bounded recompute (minimal recalc). Never recompute more than the forward closure of dirty cells. Tradeoff: must maintain an accurate dependents graph (memory + bookkeeping). Operational: edit latency scales with affected cells, not workbook size. Violation: full rebuild on every keystroke → 1M-cell workbook becomes unusable (seconds per edit).

  3. Correctness before performance. Match reference-engine semantics (errors, coercion, edge cases) first; optimize later behind a stable oracle. Tradeoff: slower initial delivery. Operational: conformance suite is the gate. Violation: a "fast" coercion that mis-handles "" → 0 diverges from Excel → silently wrong financial models, worse than slow.

  4. Errors are values, propagated first-error-wins. Excel errors (#DIV/0!, #VALUE!, …) are first-class CellValue variants with a fixed precedence; they short-circuit. Tradeoff: every operator/function must thread error checks. Operational: errors are observable, never panics. Violation: treating an error as 0 → cascading wrong results with no signal.

  5. Explicit ownership; single mutation root. The Workbook owns everything; all mutation is &mut Workbook. Tradeoff: no ad-hoc shared mutability. Operational: snapshots are trivially safe (immutable Arc). Violation: two paths mutating the store concurrently → data race / torn graph → UB or corrupt dependents.

  6. Snapshot isolation for reads. Readers (server, undo preview, formatting) see an immutable snapshot, never a mid-recalc state. Tradeoff: snapshot cost + memory (mitigated by structural sharing). Operational: long reads never block writes. Violation: a reader observing half-applied recalc → returns inconsistent cross-cell values (A updated, B not).

  7. Volatility is explicit and minimized. Volatile functions (NOW/RAND/OFFSET/INDIRECT/…) are tagged; they always re-evaluate. Tradeoff: volatile cells defeat incrementality. Operational: warn when volatile count high; expose volatile-cell metric. Violation: forgetting to tag OFFSET as volatile → stale results after edits that should have re-fired it.

  8. Range nodes, not edge explosion. A formula reading A1:A1000 creates one edge to a range node, not 1000 edges. Tradeoff: range/precedent intersection logic is more complex. Operational: keeps graph O(formulas), not O(cells touched). Violation: per-cell edges → 1M-cell SUM over a column = 1M edges → memory + topo blowup.

  9. Reference fixup is arithmetic, not text. On insert/delete/move, references are rewritten by coordinate math on the structured Reference, never by string surgery. Tradeoff: every reference kind needs precise offset rules (absolute pins, relative shifts, cross-sheet). Operational: edits stay correct + fast. Violation: regex rewriting A1→A2 corrupts $A$1, NAMED, 'Sheet'!A1, strings containing "A1".

  10. Stored value ≠ displayed value. Computation uses canonical f64/serial; formatting is a pure presentation transform. Tradeoff: two representations to keep in sync. Operational: changing a number format never triggers recalc. Violation: computing on the formatted string ("1,234.50") → parse errors, locale-dependent math.

  11. Crash-only + replayable persistence. State = last snapshot + op-log tail; recovery = load + replay. No clean-shutdown assumptions. Tradeoff: must make ops idempotent + ordered. Operational: RTO < 5 s; no fsck-style repair. Violation: relying on in-memory-only state → crash loses everything since last save.

  12. Bounded everything. Formula depth, cells, edges, iterations, spill size all capped; over-limit ⇒ a defined error, never OOM/hang. Tradeoff: some legitimate giant inputs rejected. Operational: predictable resource ceilings. Violation: unbounded recursion in a self-referential INDIRECT → stack overflow / hang.

  13. Observability by default. Recalc emits traces (cells evaluated, dirty-set size, cycle count, duration) + metrics. Tradeoff: trace overhead (gated/sampled). Operational: "why is recalc slow?" answerable from telemetry. Violation: opaque recalc → cannot diagnose a runaway volatile chain in production.

  14. Stable formula + file compatibility. Formula syntax + persisted format are versioned; old files load, parse forward-compatibly. Tradeoff: migration code accumulates. Operational: upgrades don't corrupt workbooks. Violation: silently changing operator precedence → existing formulas compute differently after upgrade.

  15. Pure evaluation against a snapshot. Cell evaluation is a pure function of (AST, snapshot, registry); no hidden global state, no in-eval mutation. Tradeoff: must pre-gather precedent values into the context. Operational: enables parallelism + memoization + replay. Violation: eval mutating the store mid-pass → order-dependent results, races, non-determinism.

8.2 EBNF grammar

formula        = "=" , expr ;
expr           = compare ;
compare        = concat , { ( "=" | "<>" | "<" | "<=" | ">" | ">=" ) , concat } ;
concat         = additive , { "&" , additive } ;
additive       = multiplicative , { ( "+" | "-" ) , multiplicative } ;
multiplicative = exponent , { ( "*" | "/" ) , exponent } ;
exponent       = unary , { "^" , exponent } ;                 (* right-assoc *)
unary          = { "+" | "-" } , postfix ;
postfix        = primary , { "%" } ;                          (* percent postfix *)
primary        = number
               | string
               | bool
               | errorlit
               | array
               | "@" , primary                                 (* implicit intersection *)
               | funccall
               | reference
               | "(" , expr ")" ;
funccall       = funcname , "(" , [ arglist ] , ")" ;
arglist        = arg , { argsep , arg } ;
arg            = [ expr ] ;                                     (* empty arg allowed: ",,," *)
array          = "{" , arrayrow , { ";" , arrayrow } , "}" ;
arrayrow       = expr , { "," , expr } ;
reference      = refrange , { ( " " | "," ) , refrange } ;     (* intersection/union *)
refrange       = refprimary , [ ":" , refprimary ] ;
refprimary     = [ sheetprefix ] , ( cellref | r1c1ref | name ) ;
sheetprefix    = ( sheetname | quotedsheet ) , [ ":" , ( sheetname | quotedsheet ) ] , "!" ;
cellref        = [ "$" ] , col , [ "$" ] , row ;
col            = letter , { letter } ;                          (* A..XFD *)
row            = digit , { digit } ;                            (* 1..1048576 *)

8.6 Array literals & broadcasting

  • {1,2;3,4} → 2×2 inline array (rows by ;, cols by ,).
  • Broadcasting: scalar ⊕ array → elementwise; array ⊕ array of differing shape → broadcast if a dimension is 1, else #VALUE! (Excel) / #N/A per rules.
  • Array result spills (P8): writing to anchor, occupying a rectangle; collision ⇒ #SPILL!.

8.7 Error model (precedence + propagation)

Error values, precedence high→low (first encountered in evaluation order wins; for operands, the leftmost highest-precedence policy follows Excel — typically first-error-in-eval-order):

Error Trigger Precedence rank
#NULL! empty intersection of ranges 1
#DIV/0! divide by zero / MOD 0 2
#VALUE! wrong type / uncoercible operand 3
#REF! reference to deleted/invalid cell 4
#NAME? unknown name/function 5
#NUM! numeric overflow / invalid arg (SQRT(-1)) 6
#N/A value not available (lookup miss, NA()) 7
#SPILL! spill blocked 8
#CALC! array calc error (empty array, nested) 9
#CIRCULAR! circular ref (non-iterative mode) 10
#GETTING_DATA async (not used here) — (deferred)

Propagation rule. Any operand that is an error makes the result that error (short-circuit), except functions explicitly error-tolerant: IFERROR, IFNA, ISERROR, ISERR, ISNA, ISBLANK, N, TYPE, ERROR.TYPE, AGGREGATE, COUNT* (skip errors per spec). First-error-wins: in =A1+B1 where both error, the result is A1's error (eval order left→right).

Context Rule
Arithmetic (+ - * / ^ %) TRUE→1, FALSE→0; numeric text "3.5"→3.5; empty cell→0; non-numeric text→#VALUE!; blank string ""→#VALUE! in arithmetic

11. Core Schema and Core Types

All signatures are normative API shapes. No implementation bodies (CRITICAL RULE 10).

CellValue — the value model.

enum CellValue {
    Blank,
    Number(f64),            // canonical numeric; dates are serials
    Bool(bool),
    Text(StringId),         // interned (ADR-013)
    Error(ErrorKind),
}
  • Ownership: by-value, Copy-ish except interned Text (id is Copy). Owned by store cell.
  • Mutation: replaced wholesale on recalc/write; never mutated in place.
  • Concurrency: Send + Sync; safe to clone into EvalContext/snapshot.
  • Persistence: tag + payload; Text resolves interner on serialize. Compatibility: tag space versioned; new variants append-only.
  • Serialization: [tag:u8][payload]; Number=8 bytes IEEE-754; Text=interned string index resolved to bytes.

ErrorKind — Excel error taxonomy with precedence.

enum ErrorKind { Null, DivZero, Value, Ref, Name, Num, NA, Spill, Calc, Circular }
fn precedence(&self) -> u8;     // 1..=10 per §8.7
  • Compat: fixed numeric ranks; never reorder (Invariant I5). Display strings stable (#DIV/0!).

CellId / coord.

struct CellId { sheet: SheetId, row: u32, col: u32 }     // 0-based internal
fn a1_to_id(s: &str, ctx: SheetId) -> Result<CellId, RefError>;
fn id_to_a1(id: CellId) -> String;
fn col_to_index(letters: &str) -> u32;   // bijective base-26
fn index_to_col(i: u32) -> String;
  • Persistence: packed (u16 sheet, u32 row, u16 col); bounds enforced (I14/I15).

Reference — structured reference with fixup flags.

struct Reference {
    sheet: SheetTarget,     // Current | Id(SheetId) | Range(SheetId,SheetId) | Name(NameId)
    col: Axis, row: Axis,   // Axis = { Abs(u32) | Rel(i32) }  (Rel stored as offset for R1C1/relative)
}
struct RangeRef { start: Reference, end: Reference }
  • Mutation: rewritten by fixup.rs arithmetic on structural edits (Invariant I10) — Abs pinned, Rel shifted.
  • Concurrency: immutable once in AST; AST shared via interning.
  • Persistence: stored inside serialized AST; sheet targets resolve by id.

FormulaAst — interned formula tree.

struct FormulaAst { root: AstId, arena: Arc<AstArena> }   // arena-allocated nodes, shared
enum Ast { Lit(CellValue), Ref(Reference), Range(RangeRef), Name(NameId),
           Unary(UnOp, AstId), Binary(BinOp, AstId, AstId),
           Call(FuncId, SmallVec<AstId>), Array(Vec<Vec<AstId>>),
           ImplicitIsect(AstId), Error(ErrorKind) }
  • Ownership: Arc<AstArena> shared; identical source → same arena (dedup).
  • Mutation: immutable; structural edits build a new AST (COW).
  • Concurrency: Arc → freely shared across recalc threads.
  • Persistence: serialized as flattened node list + root index; version-tagged.

DependencyGraph.

struct DependencyGraph {
    precedents: SecondaryMap<CellId, SmallVec<DepEdge>>,   // what a formula reads
    dependents: SecondaryMap<NodeRef, SmallVec<CellId>>,   // who reads a cell/range
    range_nodes: HashMap<RangeRef, RangeNodeId>,           // range-node compression (ADR-006)
}
enum DepEdge { Cell(CellId), Range(RangeNodeId), Name(NameId) }
fn add_formula(&mut self, c: CellId, ast: &FormulaAst);
fn remove_formula(&mut self, c: CellId);
fn dependents_of(&self, c: CellId) -> impl Iterator<Item=CellId>;   // for dirty propagation
fn topo_order(&self, dirty: &DirtySet) -> Result<Vec<CellId>, Cycle>;  // Kahn
fn sccs(&self, sub: &[CellId]) -> Vec<Scc>;                          // Tarjan
  • Ownership: owned by Workbook.
  • Mutation: &mut; updated on every formula add/remove + structural edit.
  • Concurrency: read-shared during parallel eval via snapshot; mutation single-threaded.
  • Persistence: derived — rebuilt from formulas on load (not serialized), keeping format compact + avoiding stale graph.

RecalcEngine.

struct RecalcEngine { mode: CalcMode, max_iter: u32, epsilon: f64, pool: Option<ThreadPool> }
enum CalcMode { Automatic, Manual, Iterative }
fn recalc_full(&self, wb: &mut Workbook) -> RecalcReport;
fn recalc_dirty(&self, wb: &mut Workbook, dirty: DirtySet) -> RecalcReport;
struct RecalcReport { cells_evaluated: u64, dirty_size: u64, scc_count: u32,
                      iterations: u32, duration: Duration, errors: u64 }
  • Concurrency: parallel mode partitions topo layers; per-thread result buffers; deterministic merge.

FunctionRegistry.

struct FunctionRegistry { table: HashMap<FuncId, FnEntry>, volatile: BitSet }
struct FnEntry { id: FuncId, name: &'static str, arity: Arity,
                 coercions: ArgCoercions, volatile: bool, array_aware: bool,
                 eval: fn(&mut EvalContext, &[Value]) -> Value }
fn lookup(&self, name: &str) -> Option<FuncId>;
fn is_volatile(&self, f: FuncId) -> bool;
fn register(&mut self, entry: FnEntry);     // host custom functions
  • Concurrency: immutable after init (read-shared); registration only at setup.

EvalContext.

struct EvalContext<'a> {
    snapshot: &'a Snapshot,     // immutable read view (Invariant I9)
    current: CellId,            // for relative refs / implicit intersection anchor
    registry: &'a FunctionRegistry,
    depth: u16,                 // recursion guard (Invariant I13)
    volatile_seen: &'a Cell<bool>,
}
fn read(&self, r: &Reference) -> Value;
fn read_range(&self, r: &RangeRef) -> ArrayView;
  • Purity: never mutates store (Principle 15); reads only the snapshot.

SpillRange.

struct SpillRange { anchor: CellId, rows: u32, cols: u32 }
enum SpillState { Anchor(SpillRange) | Spilled { anchor: CellId } | Blocked }
fn reserve(&mut self, sr: SpillRange) -> Result<(), SpillCollision>;  // Invariant I7

Workbook / Sheet.

struct Workbook { sheets: SlotMap<SheetId, Sheet>, names: NameTable,
                  graph: DependencyGraph, registry: FunctionRegistry,
                  interner: Interner, oplog: UndoLog, version: FormatVersion }
struct Sheet { id: SheetId, name: String, store: CellStore, dims: GridDims }
fn set_cell(&mut self, id: CellId, input: CellInput) -> Result<RecalcReport, EditError>;
fn get_value(&self, id: CellId) -> CellValue;
fn snapshot(&self) -> Arc<Snapshot>;          // structural-sharing COW (Invariant I9)
fn insert_rows(&mut self, sheet: SheetId, at: u32, n: u32) -> RecalcReport;  // → fixup + recalc
  • Ownership: sole owner / mutation root (Principle 5).
  • Concurrency: &mut for writes; snapshot() yields Arc<Snapshot> for Send + Sync reads.
  • Persistence: snapshot+oplog (Phase P11, §23).

UndoLog.

struct UndoLog { ops: Vec<Op>, cursor: usize, wal: Option<WalWriter> }
enum Op { SetCell{id, before: CellValue, after: CellInput},
          InsertRows{sheet, at, n}, DeleteRows{..}, InsertCols{..}, DeleteCols{..},
          DefineName{..}, Move{..}, Sort{..} }
fn push(&mut self, op: Op);     // also append to WAL if durable
fn undo(&mut self, wb: &mut Workbook); fn redo(&mut self, wb: &mut Workbook);
  • Invariant I8: totally ordered, each Op reversible (carries before); undo∘redo = identity.
  • Persistence: WAL append-only; replay on recovery.

13.2 Detailed Implementation Steps

  1. token.rs: Token{ kind: TokKind, span: Span }; TokKind per §8.1; span.rs byte offsets for diagnostics. (Nystrom "Scanning" — token types + spans; Cooper & Torczon Ch 2)
  2. lexer.rs: streaming scanner — numbers (incl. .5,1e3), ""-escaped strings, bool/error literals, operators (maximal-munch <=,<>,>=), refs/names/funcnames (lookahead ( → func), braces/;/@. Strip leading =. (Dragon Book Ch 3 — maximal-munch DFA; ADR-002)
  3. Reference vs name disambiguation deferred to parser/ref-resolve; lexer emits raw Ident+classification hint. (ADR-002 — Pratt parses context-sensitive refs)
  4. prec.rs: binding-power table (lbp/rbp) for §8.3; ^ right-assoc (rbp=lbp-1); reference ops (: ,) bind tighter than arithmetic. (Pratt 1973 — top-down operator precedence; ADR-002)
  5. pratt.rs: parse_expr(min_bp); null-denotation (literals, unary, (, {, @, refs); left-denotation (binary, postfix %, range/union/isect). Depth counter → Ast::Error(Num/Value) past cap (I13, §4 ≤256). (Nystrom "Parsing Expressions" — Pratt nud/led; MM4 — errors as values)
  6. ast.rs: Ast enum (§11); AstArena (generational/Vec), intern_ast hashes subtree → dedup; FormulaAst{root,arena:Arc}. (Cooper & Torczon Ch 5 — IR/AST; ADR-003 — AST vs RPN)
  7. Array literal {r;c} parse → Ast::Array(Vec<Vec<AstId>>); ragged rows → #VALUE! at parse. (Sestoft Ch 6 — array formulas)
  8. Empty args ,, → Ast::Lit(Blank) placeholder (§8.2 arg=[expr]). (OpenFormula spec — optional arguments)
  9. Error recovery: on unexpected token, synthesize Ast::Error, record span; never panic. (MM4 — errors as values, not exceptions; I13)
  10. astdump tool: formula → AST JSON for conformance + debugging. (ADR-022 — fuzz from P1; §6 Principle 13 — observability)

15. Phase P3 — Dependency Graph Build + Topological Order (Kahn) + Precedents/Dependents

15.1 Objectives

  • sheetcalc-graph: build bidirectional graph from formulas — precedents (reads) + dependents (readers); range-node compression (ADR-006, Principle 8).
  • Kahn topological order over a dirty subgraph; precedents/dependents queries. Establishes I2 (acyclic-or-flagged) substrate + I3 closure foundation.

15.2 Detailed Implementation Steps

  1. graph.rs: DependencyGraph (§11) — precedents: SecondaryMap<CellId,SmallVec<DepEdge>>, dependents: SecondaryMap<NodeRef,SmallVec<CellId>>, range_nodes: HashMap<RangeRef,RangeNodeId>. (Sestoft Ch 4 — support/dependents graph; MM1 — graph IS the computation)
  2. rangenode.rs: range precedent → single RangeNodeId edge (not N cell edges); a cell write inside a range marks the range node dirty → its dependents. Reverse index: cell → containing range nodes (interval lookup). (ADR-006; MM5 — range-node compression; §6 Principle 8)
  3. add_formula(c, ast): walk AST, collect DepEdges (Cell/Range/Name), insert into precedents[c], push c into each precedent's dependents. (Sestoft Ch 4 — adding a formula to the support graph; I1/I3)
  4. remove_formula(c): drop precedents[c], remove c from each precedent's dependents (clean delete — no orphan edges, I1). (§6 Principle 5 — single mutation root; MM1)
  5. dependents_of(c): iterate direct dependents incl. via range-node membership (cell ∈ range nodes → their dependents). (I3; MM2 — forward BFS is dirty propagation direction)
  6. kahn.rs: in-degree map over subgraph; queue zero-in-degree; pop→emit→decrement; leftover nodes ⇒ cycle (returned for P5 SCC). Stable order: process in deterministic key order (sorted CellId) for I4. (Kahn 1962 CACM; ADR-007; MM7 — determinism requires total order)
  7. topo_order(dirty): restrict to forward closure of dirty; Kahn within; return Vec<CellId> or Cycle{remaining}. (Sestoft Ch 4 — dirty-set topo; CLRS Ch 22.4)
  8. Incremental in-degree update on edit (avoid full recompute of in-degrees). (ADR-009 — incremental recompute; MM2 — dual traversal)
  9. Edge cap enforcement (edge_count vs MAX_EDGES, I14) → EditError::EdgeLimit. (§6 Principle 12 — bounded everything; I14)
  10. graphviz export: graph → DOT (debug/observability). (ADR-019; §6 Principle 13)

  • topo_order of a DAG yields a valid linear extension; deterministic across runs (I4).
  • Cyclic input → Cycle{remaining} returned (not infinite loop), handed to P5.
  • Edge count > cap → EdgeLimit, graph unchanged.

17. Phase P5 — Cycle Detection (Tarjan SCC) + Iterative Calculation Mode

17.1 Objectives

  • sheetcalc-graph::tarjan + sheetcalc-recalc::iterative: detect strongly-connected components in the affected subgraph; classify SCC>1 (or self-edge) as a cycle (I2).
  • Non-iterative mode → mark every cell in a cyclic SCC #CIRCULAR! (I5 rank 10). Iterative mode → fixed-point loop with max_iter/epsilon (§4: 100 / 1e-7), else converge-or-last-value per CalcMode::Iterative.
  • Establish that recalc never infinite-loops on cycles (Principle 12) and cycle membership is precise (no false positives that stall acyclic chains).

17.2 Detailed Implementation Steps

  1. tarjan.rs: iterative (explicit-stack) Tarjan SCC over the affected subgraph (forward closure of dirty, P3) — recursion would blow stack on 1M chains (I13). Per node: index, lowlink, on-stack flag; emit SCCs in reverse-topo order (free byproduct: condensation order for evaluation). (Tarjan 1972 SIAM — linear SCC; ADR-008; MM3; I13 — bounded recursion)
  2. Scc{ members: SmallVec<CellId>, is_cycle: bool }; is_cycle = members.len()>1 || self_edge(member). (CLRS §22.5 — SCC definition; MM3)
  3. Condensation: build DAG of SCCs; topo-order the condensation (Kahn over super-nodes) → evaluation order where each acyclic SCC is one cell, each cyclic SCC is an iterate-to-fixpoint block. (MM3 — condensation turns cyclic graphs into DAGs; ADR-007/008)
  4. iterative.rs: for a cyclic SCC under CalcMode::Iterative: seed members with prior cached value (or 0 if blank); loop: snapshot members, eval all, compute max abs delta vs prior; stop when delta < epsilon or iter == max_iter. Determinism: fixed member iteration order (sorted CellId) each pass (I4). (§4 iterative calc constraint; MM7 — determinism requires total order; ADR-014)
  5. Non-iterative (Automatic/Manual): every cyclic-SCC member → CellValue::Error(Circular); dependents outside the SCC then see #CIRCULAR! (propagates per I5). Do not poison the whole sheet — only the SCC + its forward closure. (MM4 — errors as values; §8.7 error precedence; I2/I5)
  6. Convergence reporting: RecalcReport.iterations, scc_count, cyclic_cells. Non-convergence at max_iter → keep last iterate (Excel behavior) and set converged=false telemetry, not an error (configurable: strict mode → #NUM!). (MS Docs "How Excel computes" — iterative calc behavior; ADR-020)
  7. Distinguish intended iteration (e.g. solver, depreciation) from accidental self-reference: both are cycles; only CalcMode::Iterative tolerates; default rejects. (§6 Principle 12 — bounded; §4 iterative calc)
  8. Guard against SCC churn: if structural edit changes SCC membership, recompute SCCs only for the affected closure (incremental, not whole graph). (ADR-009 — incremental recompute; MM2)
  9. volatile inside a cycle: volatile re-fires each recalc, which re-enters the iterative loop — bounded by max_iter regardless (I11 × I13 interaction). (§6 Principle 7 — volatility explicit; MM7)
  10. Wire metrics scc_count, cyclic_cells, iterative_passes, iterative_nonconvergence. (ADR-020; §6 Principle 13)

17.3 Deliverable

sccs(sub) returns precise SCCs over any subgraph; condensation topo-order drives recalc; CalcMode::Iterative converges or stops at max_iter; Automatic marks cycles #CIRCULAR! without hanging.

17.4 Acceptance Criteria

  • A1=A1 (self) → #CIRCULAR! (Automatic); converges to fixpoint if linear + iterative (e.g. A1 = A1*0 + 1 → 1).
  • 3-cycle A→B→C→A → all three #CIRCULAR! (Automatic); SCC size 3 reported.
  • Convergent iterative x = (x + n/x)/2 (Newton sqrt) → converges < max_iter within epsilon.
  • Divergent iterative (x = x + 1) → stops at max_iter, converged=false, last value retained.
  • Acyclic chain of 100k cells → SCCs all size 1, no false cycle, < full-recalc target (§4).
  • Tarjan over 1M-node chain does not overflow stack (iterative impl).

17.6 Pitfalls

  • Recursive Tarjan overflows on deep chains — must be explicit-stack iterative (manifestation: stack-overflow crash on a 100k-row column; root cause: native recursion; debug: backtrace depth; fix: worklist).
  • Self-loop detection: a single node with an edge to itself is a 1-member SCC that is a cycle — Tarjan's "size>1" test misses it; add explicit self-edge check.
  • Convergence false-positive: epsilon compare on values that oscillate within epsilon but never settle — cap by max_iter always (do not trust epsilon alone).
  • Float non-determinism in iterative loop: differing add order across passes → different convergence path; fix evaluation order per pass (sorted), Principle 1.
  • Cycle that includes a volatile (RAND) never converges by construction — detect volatile-in-cycle, warn, bound by max_iter.
  • Marking the entire workbook #CIRCULAR! instead of just the SCC closure (blast-radius bug) — scope poisoning to SCC + forward dependents only.

17.7 Performance Concerns

  • Run SCC only on the affected subgraph, not the whole graph, per recalc batch (§4 O(V+E) of affected).
  • Iterative loop cost = passes × |SCC| evaluations — bound passes (max_iter); large SCC × many passes is the worst case (warn metric).
  • Condensation reuse: cache SCC structure across recalcs when graph topology unchanged (only values changed) — recompute SCCs only on structural/formula edits.
  • Explicit-stack Tarjan: pre-size the worklist to closure size to avoid reallocation.

  • Iterative with zero max_iter → immediate stop, last value (or 0).
  • Nested cycles sharing a node — Tarjan merges into one SCC (correct).

  1. dirty.rs: DirtySet = ordered set of CellId (sorted for determinism, I4). mark_dirty(c) + forward_closure(graph, seeds) -> DirtySet: BFS/DFS over dependents (incl. range-node membership, P3) from seeds; dedup; bounded by MAX_DIRTY warn. (MM2 — forward BFS = dirty direction; Acar et al. — self-adjusting computation; ADR-009)
  2. set_cell path: write value/formula → mark_dirty(c) → if formula changed, update graph edges (P3 add/remove) → enqueue recalc. (Sestoft Ch 4 — recalc on cell write; §6 Principle 2)
  3. schedule.rs: recalc_dirty(wb, dirty): (a) expand closure, (b) add volatile set (I11), (c) topo-order the closure (Kahn over induced subgraph, P3), (d) SCC-check (P5), (e) eval each in order (P4), writing cached values. (Sestoft Ch 4 — minimal recalc algorithm; MM2; ADR-009)
  4. Clean/dirty flags per cell (CellSlot.flags bit). After eval, mark clean. A precedent change re-dirties dependents transitively. (I3; §6 Principle 2)
  5. Avoid re-dirtying already-queued cells (idempotent mark). Coalesce multiple edits in a batch before recompute (bulk paste = one closure pass). (§6 Principle 2 — minimal recompute; ADR-009)
  6. Range-dependent dirty: writing a cell inside a range precedent dirties the range node → its dependents (P3 reverse index). Critical for SUM(A:A) correctness under single-cell edits. (MM5 — range nodes; I3; ADR-006)
  7. Manual mode (CalcMode::Manual): edits mark dirty but defer eval until explicit recalc(); track pending dirty across edits. (MS Docs "How Excel computes" — calc mode; §4 calc-mode constraint)
  8. Post-recalc audit (debug build): verify no dependent of a changed cell remains clean (I3) — fail loud in tests. (I3; Demers, Reps, Teitelbaum 1981 — incremental evaluation correctness)
  9. Value-equality short-circuit: if a recomputed cell's new value == old (bit-equal), do not propagate further dirty (cut closure early) — major win for stable subgraphs. (Acar et al. — self-adjusting / change propagation pruning; ADR-009)
  10. Metrics dirty_set_size, recompute_count, closure_cut_savings, recalc_duration. (ADR-020; §6 Principle 13)

18.3 Deliverable

recalc_dirty recomputes exactly the affected closure (+ volatiles) in topo order; single-cell edits in a large workbook complete within §4 incremental targets; value-equality cutoff prunes unaffected dependents.

18.4 Acceptance Criteria

  • Edit one input feeding 1k dependents → exactly ~1k cells recomputed (recompute_count ≈ closure size), not whole workbook.
  • Editing a cell whose value is unchanged (re-enter same number) → dependents not recomputed (closure cut), unless volatile.
  • Volatile cells (NOW) recompute on every recalc regardless of edit locus (I11).
  • Incremental recalc (1 edit, ~1k affected) p95 ≤ 2 ms (§4).
  • Post-recalc audit passes: ∀ changed c, all dependents clean⇒recomputed (I3).
  • Batch of 10k edits coalesces into one closure pass (not 10k passes).

18.6 Pitfalls

  • Missed range-node dirty: writing inside a range precedent without dirtying the range node → stale aggregate (manifestation: SUM(A:A) doesn't update; root cause: P3 reverse index gap; debug: I3 audit; fix: interval membership).
  • Closure-cut on error transitions: value bit-equal but error-state flipped (e.g. was #DIV/0!, now still error of different kind) — compare full CellValue, not just number.
  • Volatile forgotten in seed → stale NOW/RAND (manifestation: clock frozen; fix: always union volatile set, I11).
  • Dirty-set ordering non-deterministic (HashSet) → non-deterministic recompute order within independent cells (I4) — use sorted/ordered set.
  • Re-entrancy: an edit during recalc (e.g. from a callback) corrupts the in-flight closure — forbid nested recalc (mutation root, Principle 5).
  • Coalescing window too greedy: holding edits indefinitely starves readers of fresh values — bound batch, flush on read/timer.

18.7 Performance Concerns

  • Closure computation = BFS over dependents; cost O(affected edges). Use bitset/visited-stamp (generation counter) instead of HashSet for visited (cache + no alloc).
  • Sorted dirty-set: maintain insertion into a BTreeSet or sort once before topo — amortize.
  • Value-equality cutoff is the highest-leverage optimization for "stable workbook, one tweak" — measure closure_cut_savings.
  • Avoid re-topo of the whole closure if only values (not topology) changed across consecutive recalcs — cache topo order keyed by graph epoch.

18.8 Edge Cases

  • Edit creates a new dependency (formula referencing a previously-empty cell) → graph edge added, closure includes new path.
  • Edit removes a dependency → stale dependent must be recomputed once (now reads blank) then drops from closure.
  • Deleting a cell's formula (→ literal/blank) → its old dependents recompute.
  • Volatile-only recalc (no edit, timer-driven) → dirty-set = volatile set ∪ their closure.
  • Cycle introduced by edit → closure hits SCC (P5) mid-pass.
  • Empty closure (edit to a cell with no dependents) → recompute just that cell.

20. Phase P8 — Dynamic Arrays, Spilling, Implicit Intersection, Broadcasting

20.1 Objectives

  • sheetcalc-array: array-valued results that spill into neighboring cells (Excel 365 dynamic arrays); spill anchors, spill ranges, collision → #SPILL! (I7).
  • Implicit intersection (@), array broadcasting (§8.6), array-aware functions (SEQUENCE, FILTER, SORT, UNIQUE, TRANSPOSE, array CSE).
  • Spill region participates in dependency graph (spill cells are derived; downstream refs to them must dirty correctly).

20.2 Detailed Implementation Steps

  1. spill.rs: SpillRange{ anchor, rows, cols }, SpillState = Anchor(SpillRange) | Spilled{anchor} | Blocked. Anchor cell holds the formula; spilled cells hold derived values + back-pointer to anchor.
  2. reserve(sr): check rectangle anchor..anchor+(rows,cols) is empty (or only previously owned by same anchor) → reserve; collision (non-empty foreign cell) → anchor result #SPILL!, no cells written (I7).
  3. Spill recompute: when anchor formula recomputes to a new shape, free old region, reserve new; shrink/grow handled; freed cells become blank (and dirty their dependents).
  4. broadcast.rs: scalar⊕array elementwise; array⊕array broadcast if a dim is 1 else #VALUE!/#N/A (§8.6); shape inference for results.
  5. intersect.rs: implicit intersection @A1:A10 — in a single-value context, pick the cell on the same row/col as the formula (legacy Excel behavior); @ operator forces it; absence in dynamic-array Excel spills instead.
  6. Array-aware functions: SEQUENCE, RANDARRAY (volatile), FILTER, SORT, SORTBY, UNIQUE, TRANSPOSE, array forms of existing functions; declared array_aware in registry (P7).
  7. Spill anchor as precedent: a downstream =B1# (spill-range reference) depends on the whole spill region; # spill operator resolves to the current spill rectangle.
  8. Graph integration: spill cells are outputs of the anchor; a write into a spilled cell is illegal (it is derived) → blocked / #SPILL!-adjacent error; edits that would collide re-trigger collision check.
  9. Legacy CSE array formulas (Ctrl+Shift+Enter, {=...}) — supported as explicit array entry over a fixed range (distinct from dynamic spill); document mode difference.
  10. Metrics spill_collisions, spill_cells_total, max_spill_area.

20.3 Deliverable

Array results spill into a rectangle; collisions → #SPILL! with no partial write (I7); # spill-ref + @ implicit-intersection work; broadcasting per §8.6; array-aware functions (SEQUENCE/FILTER/SORT/UNIQUE/TRANSPOSE) evaluate.

20.4 Acceptance Criteria

  • =SEQUENCE(3) in A1 spills A1:A3 = 1,2,3; A2/A3 marked Spilled{anchor:A1}.
  • Blocking cell in spill target → anchor = #SPILL!, no spilled writes (I7); clearing the blocker re-spills.
  • ={1,2;3,4}+10 broadcasts to {11,12;13,14}.
  • =@A1:A10 returns the same-row cell (implicit intersection); =A1# references the live spill range.
  • Editing the anchor formula to a smaller shape frees the vacated cells (they blank + dirty dependents).
  • =FILTER(A1:A10, B1:B10>0) returns variable-length spill; empty result → #CALC!.

  • Partial spill on collision: must be all-or-nothing — never leave half a rectangle written (I7); reserve-then-write, not write-then-check (manifestation: ghost values after a blocked spill; fix: two-phase reserve).
  • Spill resize churn: a volatile-driven spill changing size every recalc thrashes reservations + dirties large regions (perf); detect stable shape, cache.

  • Implicit intersection ambiguity: @ legacy vs dynamic-array spill behavior differ between Excel versions — pin to one model (dynamic-array default), document.
  • Broadcasting NaN/error in one element — element-wise error placement, not whole-array error (unless function aggregates).
  • Spill-range reference (A1#) when anchor errors (#SPILL!) → propagates #REF!/#SPILL! to dependents.

20.7 Performance Concerns

  • Reservation map: per-sheet interval/rect index for collision check O(log + overlaps), not O(cells in rectangle).
  • Large spills (e.g. SEQUENCE(1e6)) — bound by MAX_SPILL_AREA (I14-adjacent) → #SPILL!/#NUM!; do not materialize unbounded.
  • Spill cells stored compactly (derived; share anchor's format; may use run-encoding for repeated values).
  • Re-spill on resize: free + reserve is O(area); avoid per-recalc resize for stable shapes.

  • Empty FILTER result → #CALC! (Excel) / configurable.
  • Two anchors racing for overlapping region (recalc order) — topo order determines winner deterministically; loser #SPILL!.
  • Implicit intersection on a multi-area reference → #VALUE!.

21. Phase P9 — Structural Edits (Insert/Delete/Move Row-Col) + Reference Rewriting + Undo/Redo

21.1 Objectives

  • sheetcalc-edit: insert/delete rows/cols, move/cut-paste, sort; rewrite all affected references by coordinate arithmetic (Principle 9, I10), not text.
  • sheetcalc-persist::undo: every mutation is a reversible Op; undo/redo via op-log (I8). Structural edits trigger graph rebuild + recalc of affected closure (P6).
  • Reference integrity after edits (I1, I15): refs to deleted region → #REF!; refs shift correctly.

21.2 Detailed Implementation Steps

  1. structural.rs: insert_rows(sheet, at, n), delete_rows, insert_cols, delete_cols — shift the sparse store (columnar: insert = renumber rows ≥ at by +n; delete = drop range, shift down). Spill regions + merged ranges adjusted.
  2. rewrite.rs: for every formula whose references touch the edited axis, rewrite Reference via fixup.rs (P2) math:
    • Insert rows at r, count n: relative/mixed rows ≥ r shift +n; absolute rows ≥ r also shift (absolute pins position, still moves on structural insert per Excel); refs into deleted region → #REF!.
    • Delete: rows in [r, r+n) → #REF! for refs to them; rows ≥ r+n shift −n.
    • Range endpoints adjust independently (a range straddling a delete shrinks; fully-deleted range → #REF!).
  3. move.rs: cut/paste a block — references to moved cells follow the move (Excel: moved refs track), references within the moved block stay relative; refs from outside into moved block update to new location.
  4. Fill/copy translation: copying =A1 from B1 to C1 → =B1 (relative shift by copy delta); absolute parts unchanged — pure Reference delta arithmetic.
  5. sort.rs: sort a range by key column — permute rows; rewrite references within sorted region to follow rows (or keep, per Excel's "expand selection" semantics); document chosen model.
  6. Graph rebuild: after edit, removed formulas' edges dropped, rewritten formulas' edges re-added (P3); changed cells seed dirty-set (P6) → recalc closure.
  7. undo.rs: Op enum (§11) carries before state; push appends to in-memory ring (+ WAL P11). undo applies inverse (restore before, reverse shift); redo re-applies. Structural ops store enough to invert (deleted cell contents captured in before).
  8. Cross-sheet ref fixup: editing Sheet1 rewrites refs in Sheet2 that point into Sheet1 (workbook-global scan of dependents into edited region, via graph).
  9. Named-range fixup: a name pointing into edited region shifts/#REF!s; name table updated (P2).
  10. Metrics ref_fixup_errors, structural_edits_total, undo_redo_mismatch.

21.3 Deliverable

22.1 Objectives

  • sheetcalc-recalc::parallel + snapshot: evaluate independent cells in a topo layer concurrently across a work-stealing pool (rayon-style, ADR-010), with deterministic results regardless of thread count (I4) under snapshot isolation (Principle 6, I9).
  • Scale full recalc of 1M formula cells to < 1.5 s on 8 cores (§4) without sacrificing determinism or reader isolation.

22.2 Detailed Implementation Steps

  1. snapshot.rs: Snapshot = immutable COW view of the cell store at recalc start (Arc); readers + parallel evaluators read it; writes accumulate into a staging buffer applied atomically at layer/batch boundary (I9). (MM6 — snapshot isolation is structural sharing; ADR-011; §6 Principle 6)
  2. Layered topo execution: partition the topo order into layers (cells whose precedents are all in earlier layers); cells within a layer are mutually independent → evaluate in parallel. (ADR-010; MM2 — topo layers; Klabnik & Nichols Ch 16 — Rust concurrency)
  3. Work-stealing: rayon parallel iterator over a layer's cells; each task evaluates one cell against the snapshot + staged prior-layer results; result → per-thread buffer. (ADR-010; Klabnik & Nichols Ch 16)
  4. Deterministic merge: after a layer completes, merge per-thread result buffers into the staging store in a fixed (sorted CellId) order (I4) — float results are per-cell (no cross-cell reduction), so order affects only write order, not values; reductions inside one cell (SUM) stay single-threaded + left-to-right (§6 Principle 1). (MM7 — determinism requires total order; ADR-014; I4)
  5. Snapshot publication: at batch end, swap the staging buffer into the live store (atomic pointer swap / COW commit); readers holding the old Arc<Snapshot> finish unaffected (I9). (MM6; §6 Principle 6/15; ADR-011)
  6. SCC handling under parallelism: cyclic SCCs (P5) evaluated as atomic single-threaded blocks within their condensation layer (iterative loop is inherently sequential). (MM3 — condensation order; §17 Phase P5)
  7. Volatile + parallel: volatile cells seeded (I11) and scheduled like any cell; RNG (RAND) must be deterministic per cell (seed = f(cell, recalc epoch)) to preserve I4 across thread counts. (MM7 — determinism; §6 Principle 7; I11/I4)
  8. False-sharing avoidance: per-thread result buffers cache-line aligned; no shared mutable counters on the hot path. (Drepper §3 — CPU caches + false sharing; ADR-005 columnar-locality context)
  9. Granularity control: small layers (< threshold) evaluated single-threaded to avoid task-spawn overhead; large layers parallelized. (ADR-010; Back-of-Envelope item 4 — parallel speedup)
  10. Determinism harness (ADR-027): run recalc 1-thread vs N-thread, byte-diff all cells (I4) in CI. (MM7; ADR-027; Testing Strategy — determinism test layer)

22.3 Deliverable

Parallel recalc_full/recalc_dirty over independent topo layers; deterministic byte-identical results 1-thread vs N-thread (I4); snapshot isolation for concurrent readers (I9); 1M-cell recalc < 1.5 s / 8 cores (§4).

22.4 Acceptance Criteria

  • 1M independent formula cells: parallel recalc < 1.5 s / 8 cores; near-linear speedup vs single-thread on independent subgraphs.
  • Determinism (I4): 1-thread vs 2/4/8-thread results bit-identical for all fixtures (including RAND with deterministic per-cell seed).
  • Reader holding a snapshot during recalc sees a consistent pre-recalc image, never a half-updated state (I9).
  • Cyclic SCC under parallel mode → evaluated sequentially, same result as single-thread.
  • No data races (verified under cargo test + loom/TSan where applicable).
  • Parallel overhead on tiny workbooks ≤ single-thread (granularity guard).

22.6 Pitfalls

  • Non-deterministic cross-cell reduction: parallelizing a single SUM across threads changes float add order → I4 break; keep intra-cell reductions sequential left-to-right (Principle 1) — only parallelize across independent cells.
  • HashMap iteration in the parallel path → non-deterministic scheduling/order; use sorted layer order (I4).
  • Data race on the live store: evaluators must read the snapshot, write the staging buffer — never the live store mid-batch (Principle 6/15) (manifestation: torn reads, UB; fix: snapshot/stage discipline).
  • RAND/NOW non-determinism across threads: must derive from a deterministic per-cell seed + recalc epoch, not a shared global RNG/clock (I4 vs I11).
  • False sharing on result buffers → cache-line thrash, no speedup (perf, not correctness); pad/align buffers.
  • Over-parallelization of tiny layers → task overhead dominates; granularity threshold needed.
  • A layer mis-partitioned (a cell scheduled before a precedent) → reads stale/blank → wrong result; layer assignment must respect topo strictly.

22.7 Performance Concerns

  • Layer partition cost vs parallel gain — amortize partition (cache topo layers per graph epoch, reuse across value-only recalcs, P6).
  • Snapshot COW cost: structural sharing keeps it < 5 ms for 1M cells (§4); avoid deep-copying the store.
  • Task granularity: batch many small cells per task to amortize spawn; tune threshold via parallel_scaling bench.
  • Memory bandwidth bound at high core counts (1M-cell scan) — columnar layout + sequential access mitigate.
  • Staging-buffer merge: sorted merge O(cells in layer); avoid global lock (per-layer barrier instead).

22.8 Edge Cases

  • Single huge layer (fully independent) — max parallelism; ensure load balancing via work-stealing.
  • Deep narrow chain (each layer 1 cell) — no parallelism available; falls back to single-thread (correct, not faster).
  • Volatile-heavy workbook — volatiles in many layers; still deterministic via per-cell seed.
  • Reader count high during recalc — many Arc<Snapshot> clones; refcount overhead; bounded.
  • Thread pool exhaustion / panic in a task — must not corrupt store; task panic → batch abort, store unchanged (crash-only, Principle 11).
  • Recalc requested while another in flight (single mutation root, Principle 5) — serialize batches.

SLOs (single-node server). Availability 99.9%; incremental recalc p95 ≤ 2 ms; single-cell eval p99 ≤ 50 µs; RTO < 5 s; determinism 100% (any I4 violation = SLO breach / release block). Error budget tracked monthly.

Alerting philosophy. Page on: SLO-latency breach (sustained), recalc-storm (dirty_set_size sustained high), determinism violation, CRC/persistence failure, OOM-approach (mem near cap). Warn (no page) on: rising volatile_count/cyclic_cells, fuzz nightly findings, bench regressions.

Incident response + runbooks (docs/runbooks/): recalc-storm.md, recalc-cycle.md, ref-corruption.md, recovery.md, oom.md, determinism-violation.md. Each: symptom → telemetry to check → DOT/trace to pull → mitigation → root-cause → prevention.

Backup/restore. Periodic .scbk checkpoint + WAL archive (offsite optional). Restore-test in CI: load backup → recompute → compare to expected (gate). RPO = last fsync'd batch; RTO < 5 s.

Deployment topology. Single-node server, one workbook/session, snapshot-isolated reads. Horizontal scale = independent sessions across nodes (no cross-node coordination; shared multi-user is Appendix C (C-4) deferred). Canary: deploy to a subset of sessions/nodes, watch correctness + latency dashboards. Rolling upgrade: drain sessions, snapshot, upgrade, reload (format-compatible). Rollback: redeploy prior binary, load snapshot (format back-compat, Compatibility Guarantees).

Scalability Analysis

  • Cell-count ceiling: sparse store + caps (I14) target ≥ 1M populated (grid addressable 16M/sheet). Beyond → memory-bound; per-cell ≤ ~1.5 KB amortized drives the ceiling.
  • Dependency-graph memory: range-node compression (ADR-006, Principle 8) keeps edges O(formulas) not O(cells); edge_count × bytes/edge is the second memory driver — SmallVec inline + arena overflow.
  • Recalc fan-out: closure size bounds incremental latency (Principle 2); extreme fan-out (1→1M) handled but warned; volatile/range deps are the fan-out risk.
  • Parallel scaling ceiling: near-linear on independent subgraphs; bound by memory bandwidth at high core counts + by graph shape (deep narrow chains have no parallelism). NUMA cross-socket not optimized (deferred).
  • Sheet/partition scaling: workbook-global graph; very large workbooks could partition by sheet for locality (future). Multi-machine sharding deferred (Appendix C (C-7)).
  • Server horizontal scaling: independent sessions across nodes (no coordination); scales with session count. Shared multi-user editing (OT/CRDT) is the coordination-heavy path, deferred (Appendix C (C-4)).
  • Persistence growth: WAL grows with edits → periodic snapshot+truncate compaction bounds it; snapshot size ∝ populated cells.
  • Coordination overhead: none in single-node (one mutation root); the moment multi-writer is added (deferred), coordination becomes the bottleneck — explicitly out of P0–P12 scope.

Mental Models & First Principles

MM1 — The dependency graph IS the computation. A spreadsheet is not a bag of cells with formulas; it is a directed graph where edges are reads, nodes are computations, and values flow source→sink. The formula text is merely the edge declaration. Prediction: any correctness problem in recalc traces back to a missing or wrong edge. Bug class without it: updating cell values directly and forgetting to propagate — implementors patch values instead of fixing the graph, creating ghost staleness. Applied in: §3 (dependency graph box), §6 (Principle 2), §7 (I3), Phase P3.

MM2 — Dirty propagation is a forward BFS; evaluation is a backward traversal of the same graph. Marking dirty flows forward (source → dependents); evaluation flows in the reverse topological order (precedents before dependents). These are dual traversals of one graph; confusing their direction produces either missed dirty or wrong eval order. Prediction: any "stale value" bug is a forward-BFS gap; any "evaluated before its input" bug is a topo-sort gap. Bug class without it: evaluating cells in arbitrary order, reading stale precedents. Applied in: §6 (Principles 2, 15), Phase P6 (dirty.rs, schedule.rs), §7 (I3).

MM3 — SCC condensation turns cyclic graphs into DAGs. Tarjan's SCC collapses every cycle into a super-node; the condensation is always a DAG. Topological evaluation then operates on the condensation: each acyclic super-node is one cell, each cyclic super-node is an iterative-to-fixpoint block. Prediction: any cycle-handling strategy reduces to (a) detect SCCs, (b) condense, (c) topo-order the condensation. Bug class without it: treating cycles as errors without attempting condensation — correctly cyclic iterative models (solver, depreciation) rejected. Applied in: Phase P5 (tarjan.rs, iterative.rs), §7 (I2), ADR-008.

MM4 — Errors are values in the lattice, not exceptions. Excel's error model is a total order (§8.7) over a set of error values. Every operation must be defined on error inputs: either short-circuit (most ops) or inspect (IFERROR). Treating errors as exceptions causes two classes of bug: (a) an error swallowed and replaced with 0/blank (silent wrong result), (b) a panic propagating up the call stack. Prediction: any unwrap on a CellValue in the eval path is a latent panic bug. Bug class without it: =IFERROR(1/0, "x") panics instead of returning "x". Applied in: §8.7, §6 (Principle 4), §7 (I5), Phase P4 (eval.rs, coerce.rs).

MM5 — Range nodes avoid O(N²) graph blow-up. A formula =SUM(A1:A1000) has one semantic dependency (the range), not 1000. Materializing per-cell edges gives O(formulas × cells-per-range) = O(N²) in the worst case. Range nodes compress this to O(formulas) edges. The interval-membership reverse index maps cell writes back to owning range nodes in O(log + k) without materializing the full range. Prediction: any spreadsheet without range-node compression will OOM or stall on a model with one SUM over a large column. Bug class without it: inserting a row in a column with SUM(A:A) spawns 1M new edges. Applied in: §6 (Principle 8), §7 (I14), Phase P3 (rangenode.rs), ADR-006.

MM6 — Snapshot isolation is structural sharing, not copying. Immutable Arc<Snapshot> over a COW store means readers and parallel evaluators see a consistent point-in-time image without locking or copying the entire store. The key insight: if the store is structured as a persistent data structure (structural sharing of unchanged columns), the snapshot is O(modified cells) not O(all cells) to create. Prediction: any lock-based reader/writer scheme will either block reads during recalc or see torn state. Bug class without it: a read of cell B during recalc sees B from the new pass but A from the old — cross-cell inconsistency. Applied in: §6 (Principle 6), §7 (I9), Phase P10 (snapshot.rs), ADR-011.

MM7 — Determinism requires a total order on every non-deterministic operation. Parallel evaluation, hash-map iteration, and float reduction are the three sources of non-determinism in a spreadsheet engine. Each requires a discipline: (a) evaluate across independent cells in parallel but within one cell left-to-right; (b) sort all hash-map keys before any compute-affecting iteration; (c) never reduce a range across threads (each cell's SUM is single-threaded). The mechanical check is a byte-diff of 1-thread vs N-thread output. Bug class without it: RAND returns different values run-to-run; SUM(A1:A1000) diverges across thread counts on boundary values. Applied in: §6 (Principle 1), §7 (I4), ADR-014, ADR-027, Phase P10.

MM8 — Reference fixup is coordinate arithmetic, never string surgery. A structured Reference carries per-axis Abs|Rel flags and integer offsets. Structural edits (insert/delete/move) are applied by arithmetic: Rel axes shift by the edit delta, Abs axes shift on structural inserts but are pinned against fill/copy. Text-based substitution (s/A1/A2/g) fails on $A$1, named ranges, cross-sheet refs, and string literals containing "A1". Prediction: any regex-based ref rewriting will produce wrong results for at least one of the reference kinds in §8.5. Bug class without it: =$A$1 silently becomes =$A$2 under a copy delta (should be pinned). Applied in: §6 (Principle 9), §7 (I10), Phase P9 (fixup.rs, rewrite.rs), ADR-003.

MM9 — Correctness in numerics is differential, not unit. IEEE-754 binary64 is deterministic but not intuitive: 0.1+0.2 ≠ 0.3, ROUND(2.5,0)=2 in some modes. The only way to validate numeric semantics against Excel is to run the same input through both engines and compare. Unit tests that assert abs(result - expected) < 1e-10 mask systematic biases. A differential oracle harness (LibreOffice headless / formulajs) surfaces them. Prediction: any engine that does not run differential tests will ship at least one systematic coercion divergence within the first 100 functions. Bug class without it: ROUND uses banker's rounding instead of Excel's round-half-away → financial models off by 0.5 in edge cases. Applied in: §6 (Principle 3), §7 (I12), ADR-012, Phase P4, Phase P12 (differential.rs).

MM10 — Crash-only persistence via op-log replay eliminates clean-shutdown reasoning. The engine never assumes it shut down cleanly. State = last durable snapshot + WAL tail. Recovery = load snapshot + replay. This makes every write path trivially crash-safe: append to WAL (fsync grouped), swap snapshot atomically. No flush-on-close, no in-progress markers. Prediction: any "flush on shutdown" scheme will silently lose data on kill-9 or power loss. Bug class without it: a snapshot written mid-recalc (not at a consistent boundary) + WAL truncated before snapshot durable = data loss. Applied in: §6 (Principle 11), §7 (I8), Phase P11 (oplog.rs, snapshot.rs), ADR-016.

Google Sheets. Made the decision to run all recalc server-side in a distributed Bigtable-backed store, enabling real-time collaborative editing (OT/CRDT) for thousands of concurrent users. That wins in the multi-user SaaS niche where recalc latency can be up to ~1s and network round-trips are acceptable. The sheetcalc design rejects this because it targets embeddable, offline, low-latency use cases where a server round-trip per formula change is unacceptable.

Excel (desktop). Made the decision to use a token-array (RPN) formula representation and an in-process "broadcaster" (dependents) model with a tight single-threaded recalc loop, prioritizing minimal overhead for the common case. Token arrays save memory (no AST heap) and JIT-compile more naturally. The sheetcalc design rejects RPN (ADR-003) because ASTs are easier to rewrite on structural edits and to transform for array/spill semantics.

HyperFormula. Made the decision to implement in TypeScript/JavaScript with per-cell dependency edges (no range-node compression), prioritizing accessibility to web developers and ease of embedding in browser apps. This wins when the consumer is a JavaScript team building a grid UI and Rust/WASM is not in scope. The edge-explosion risk is mitigated by limiting workbook sizes to tens of thousands of cells.

IronCalc. Made the same language choice (Rust) as sheetcalc but uses a HashMap-based sparse store (not columnar) and per-cell edges (not range-node compressed). This wins when column scans are rare and the formula graph is dense/small, but degrades on SUM(A:A) over large columns and on large range-dependency workbooks. IronCalc is a useful reference for Rust idioms (ADR-001) and xlsx I/O patterns.

Back-of-Envelope Capacity Model

All formulas derived from §4 System Constraints.

1. Per-cell memory budget.

Target: ≤ 1.5 GB for 1M populated cells  (§4)
⇒ 1.5 × 10⁹ B / 10⁶ cells = 1,500 B/cell amortized
Breakdown: CellSlot ≤ 48 B (value+formula ref+format+flags, §4)
           + dependency edges: see item 2
           + cached eval result (already in CellSlot)
           + interner string storage (amortized)
Remaining per-cell budget for graph+interner: 1500 − 48 = 1,452 B/cell

2. Dependency graph edge budget.

Max edges: 4,000,000  (§4)
Memory/edge (SmallVec<DepEdge>): ~24 B/edge (CellId=10B + tag=2B + padding)
Total edge memory: 4 × 10⁶ × 24 B = 96 MB
At 1M formula cells: 96 MB / 10⁶ = 96 B/cell for the graph — well within the 1,452 B remaining

3. Recalc throughput requirement (single-thread).

Target: full recalc 100k formula cells p99 ≤ 250 ms  (§4)
⇒ 100,000 cells / 0.250 s = 400,000 cells/s minimum throughput
Single-cell eval p99 ≤ 50 µs (§4) → 1/50µs = 20,000 cells/s worst-case
Implication: the p99 single-cell target applies to complex formulas;
             simple arithmetic must be well under 50 µs to average to 400k/s.
At p50 = 2 µs/cell: 500,000 cells/s → 100k in 200 ms ✓ within 250 ms

4. Parallel recalc speedup requirement.

Target: 1M cells on 8 cores < 1.5 s  (§4)
Single-thread at p50 2 µs/cell: 1M × 2 µs = 2 s
Required speedup: 2 s / 1.5 s = 1.33×  (modest — a 25% efficiency gain from 8 cores)
Amdahl: if 70% of work is parallelizable, 8 cores → speedup ~3.1× → well above target
Implication: even moderate parallelization (30% serial fraction) exceeds the target.

5. Incremental recalc latency budget.

Target: 1 edit, ~1k affected cells, p95 ≤ 2 ms  (§4)
At p50 2 µs/cell: 1,000 cells × 2 µs = 2 ms → barely meets p95 ≤ 2 ms
⇒ Hot-path eval must be closer to p50 = 1 µs for p95 to clear 2 ms with overhead
Closure computation overhead: BFS over ~1k edges at ~50 ns/edge = ~50 µs → negligible
Topo sort of 1k nodes: O(k) ≈ 100 µs → 5% of budget → acceptable

6. File descriptor budget (server mode).

Target: ≤ 64 FDs/session  (§4)
Breakdown: 1 snapshot file (.scbk) + 1 WAL (.scwal) + 1 gRPC socket + 1 JSON-RPC socket
           + 2 prometheus + misc: ~8 FDs/session → well within 64
At 64 sessions on a server: 8 × 64 = 512 FDs << typical ulimit of 65,536

7. WAL write throughput.

Target: op-log fsync < 2 ms/batch  (§4)
Typical op size: 64 B (SetCell: IDs + before + after)
At 10k ops/batch: 10,000 × 64 B = 640 KB/batch
Sequential write bandwidth (NVMe): ~2 GB/s → 640 KB / 2 GB/s = 0.32 ms << 2 ms ✓
fdatasync on NVMe: ~0.1–0.5 ms → total ~0.5–1 ms/batch ✓
HDD: ~5–10 ms/fsync → exceeds target; requires async WAL or SSD requirement.

8. Snapshot creation time.

Target: < 5 ms for 1M cells (in-memory COW snapshot)  (§4)
COW snapshot = Arc clone of store structure: O(modified since last snapshot)
If 10k cells modified: 10k × 48 B = 480 KB to COW-copy → ~0.2 ms ✓
Full on-disk snapshot: 1M × 48 B = 48 MB → at 2 GB/s = 24 ms (background, not on critical path)
In-memory structural sharing makes the critical-path snapshot < 5 ms ✓

9. Parser throughput.

Target: ≥ 1M formulas/sec (Performance Engineering)
Average formula: 40 chars; 1M × 40 B = 40 MB text to lex/parse per second
Lexer: streaming, allocation-free → ~10 ns/char → 40 B × 10 ns = 400 ns/formula
Pratt parser: 10–20 nodes/formula × 20 ns/node = 200–400 ns/formula
Total: ~600–800 ns/formula → 1.25–1.67M formulas/sec ✓
Interning overhead: FNV hash ≈ 5 ns/char for the formula text → +200 ns → still > 1M/sec ✓

10. Spill area cap.

Memory cap: 1.5 GB / 1M cells budget means spill cells share the 1,500 B/cell envelope
A spill of 1M cells: 1M × 48 B (value only, no formula) = 48 MB → 3.2% of budget → acceptable
MAX_SPILL_AREA policy: cap per-anchor at 1M cells; workbook-wide spill cells counted in I14
Unbounded SEQUENCE(1e9) rejected → #SPILL! (§4, P8)

11. Iterative calculation cost.

Max iterations: 100 (§4 default); epsilon: 1e-7
SCC size worst case: all 1M cells in one cycle (degenerate)
Cost: 100 iterations × 1M cells × 2 µs/cell = 200 s → unacceptable
∴ large SCCs with iterative mode must emit a warning and cap by max_iter
Typical SCC: 1–10 cells; 100 × 10 × 2 µs = 2 ms → acceptable
Boundary: warn when SCC × max_iter > 10,000 cell-evaluations/batch

12. Recovery time (RTO).

Target: < 5 s (load snapshot + replay 10k ops)  (§4)
Snapshot load: 48 MB (1M cells) at 2 GB/s sequential read = 24 ms → negligible
WAL replay: 10k ops × 64 B = 640 KB; parse + apply at 1M ops/s = 10 ms → negligible
Graph rebuild from formulas: 1M formulas × 400 ns/formula = 400 ms
Full recalc (dirty): 1M cells × 2 µs = 2 s
Total: 24 + 10 + 400 + 2000 ≈ 2.4 s << 5 s ✓ (with margin for I/O variance)

Alternative Architectures (Roads Not Taken)

Alt-1: Pull-Based (Lazy / Recompute-on-Read) with Memoization

[Cell Store] ── on read ──▶ [Evaluator] ──── reads ──▶ [Precedent cells (lazy)]
                                 │ memoize result
                                 ▼
                          [Memo Cache (invalidated on write)]

Regime where it wins. Workloads with many writes and few reads (ETL pipelines, batch transforms) where deferring evaluation until read time avoids computing cells that are never read. Self-adjusting computation (Adapton) uses this model for incremental functional programs.

Real system. Adapton (Hammer et al., 2015); also Excel's pre-2007 "manual recalc" mode is a degenerate form (recalc only on user request). Salsa (the Rust incremental query framework used in rust-analyzer) uses pull-based memoization with fine-grained dependency tracking.

Why rejected. Spreadsheet UX is edit-driven: every cell write must produce updated displays synchronously (or near-synchronously). A pull model makes reads expensive (potentially full recompute on every read of a stale cell) and makes cross-cell consistency hard to enforce (two reads of dependent cells may see different recalc states). The dirty-set push model (ADR-009) matches the UX contract directly.

Alt-2: RPN Token-Array Evaluation (LibreOffice / Excel internal model)

Formula text ──lex──▶ [Token Array (RPN)] ──eval──▶ [Stack Machine]
                              │
                         stored per cell
                         (no AST heap)

Regime where it wins. Memory-constrained environments (< 64 MB heap, millions of cells) where the per-cell cost of an AST tree on the heap is prohibitive. RPN maps naturally to a stack-based bytecode interpreter and is trivially JIT-compiled. LibreOffice Calc and the Excel binary formats use this model.

Real system. LibreOffice Calc (sc/source/core/tool/compiler.cxx); Apache POI formula evaluation; the Excel binary format (.xls) stores RPN token streams.

Why rejected. RPN complicates every structural-edit fixup (references are embedded as tokens in a stream; rewriting them requires deserializing the stream, patching tokens, and re-serializing). Dynamic array / spill rewriting is even harder on a token stream. AST interning (ADR-003) recovers the memory efficiency via deduplication. The added complexity of RPN is not justified given this engine's emphasis on edit correctness (Phase P9).

Alt-3: Demand-Driven Collaborative (OT/CRDT + Server-Side Recalc)

[Client A] ──op──▶ [OT/CRDT Transform Server] ──▶ [Server-Side Recalc Engine]
[Client B] ──op──▶      (conflict resolution)       ──▶ [Broadcast results]
                                                          ──▶ [Client A, B, ...]

Regime where it wins. Multi-user collaborative editing where > 1 user edits concurrently and all users must see a consistent, converging view. Google Sheets, Notion, and collaborative BI tools (Mode, Retool) use variants of this architecture. The OT/CRDT layer handles concurrent edit merging; the centralized recalc engine prevents divergent results.

Real system. Google Sheets (server-side recalc over Bigtable-backed cell store, OT for collaborative edits). ShareDB + custom formula server. Apache Wave (historical).

Why rejected. This architecture requires: (a) a centralized recalc server (no offline/WASM embedding), (b) an OT/CRDT layer (significant additional complexity; deferred, see Deferred Features Register C-4), (c) network round-trips on every edit (defeats < 2 ms incremental recalc target, §4). The sheetcalc design targets embeddable, offline, single-user-session engines. Multi-user collaboration is explicitly deferred.

Alt-4: GPU-Parallel / SIMD Bulk Evaluation Engine

[Dependency Graph] ──topo layers──▶ [GPU Kernel / SIMD Lanes]
                                          │ vectorized eval
                                          ▼
                                   [Result Buffers]

Regime where it wins. Financial risk engines, simulation models, or scientific workbooks with millions of cells performing the same arithmetic formula over columnar data arrays (e.g., =A1*B1 repeated 1M times). GPU evaluation of uniform operations achieves orders-of-magnitude throughput over CPU work-stealing. Excel 365 has experimental GPU acceleration for some functions (MMULT on large arrays).

Real system. Apache Arrow Compute (SIMD-accelerated columnar evaluation); Pandas/NumPy (vectorized CPU eval); specialized quant systems (KDB+/q for vector eval).

Why rejected. The spreadsheet formula language is heterogeneous (each cell may have a different formula), making GPU kernel dispatch impractical for the general case. SIMD works only for uniform operations over dense columns — a minor fraction of real workbooks. GPU memory transfer overhead dominates for sparse, formula-diverse workbooks. This is explicitly deferred as PhaseDeferred("Deferred Features Register"). The CPU work-stealing model (ADR-010) covers the 99th-percentile workload.

Glossary

Term Definition
Precedent A cell/range a formula reads (its inputs).
Dependent A cell whose formula reads a given cell (downstream).
Dirty A cell whose cached value is stale and must be recomputed.
Forward closure Transitive set of all dependents reachable from changed cells.
Minimal recompute Recomputing only the forward closure of changes, not the whole workbook (Principle 2).
Topological order Linear ordering of a DAG s.t. every precedent precedes its dependents (Kahn).
SCC Strongly-connected component; a maximal set of mutually reachable nodes — a cycle if size>1 or self-edge (Tarjan).
Condensation DAG formed by contracting each SCC to a super-node; gives evaluation order over cyclic blocks.
Volatile function A function that must recompute every recalc (NOW/RAND/OFFSET/INDIRECT/…) (I11).
Spill An array result occupying a rectangle of cells from a single anchor formula (dynamic arrays).
Spill anchor The cell holding the array formula; owns the spill range.
#SPILL! Error when a spill region is blocked by existing content (I7).
Implicit intersection (@) Reducing a range/array to a single value on the formula's row/col.
Spill reference (#) A1# — references the live spill range anchored at A1.
A1 notation Column-letter + row-number addressing ($ pins).
R1C1 notation Row/Column-number addressing; [] = relative offset.
Absolute reference $A$1 — pinned against fill/copy (but shifts on structural insert/delete).
Relative reference A1 — shifts with fill/copy and structural edits.
Named range A name bound to a reference/range/formula/constant.
Structured reference Table-column reference (Table1[Amount]) (subset; full deferred).
Range node A single graph node representing a range precedent, avoiding per-cell edge explosion (Principle 8).
Reference fixup Coordinate-arithmetic rewriting of references on structural edits (Principle 9, I10).
Op-log / WAL Append-only reversible operation log for undo/redo + crash recovery (I8).
Snapshot Immutable COW view of the store for isolated reads + parallel eval (I9).
Snapshot isolation Readers see a consistent point-in-time image, never a mid-recalc state (Principle 6).
Iterative calculation Fixed-point loop for circular refs, bounded by max-iter/epsilon (P5).
Coercion Type conversion between number/text/bool per context (§8.8).
First-error-wins Error propagation: first error in eval order surfaces (§8.7, I5).
Error value A first-class CellValue variant (#DIV/0! etc.), not an exception (Principle 4).
Date serial Numeric encoding of dates (1900/1904 epoch); time = fractional day.
1900 leap bug Excel's fictitious 1900-02-29 (serial 60), replicated for parity.
Determinism Bit-identical results across runs/threads (Principle 1, I4).
Recalc storm Excessive recompute from volatile chains / huge closures (a failure mode).
Anchor (eval) The current cell, basis for relative refs + implicit intersection.
Interning Deduplicating strings/ASTs to stable ids (ADR-013/003).
Broadcasting Element-wise combination of arrays/scalars with shape rules (§8.6).
CSE array formula Legacy Ctrl+Shift+Enter fixed-range array formula (vs dynamic spill).
Calc mode Automatic / Manual / Iterative recalculation policy.
