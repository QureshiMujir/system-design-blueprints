CPU/cache assumptions. x86-64 + aarch64; 64-byte cache lines; column scans must be cache-friendly (sequential interval map). Avoid false sharing in parallel recalc (per-thread result buffers, aligned). NUMA: single-node, pin pool to one node for large workbooks; cross-socket recalc not optimized (deferred).

Network (server). Local/LAN RTT assumed < 1 ms; engine is CPU-bound not network-bound. One workbook per connection; no cross-connection coordination.

Back-of-Envelope Capacity Model

All formulas derived from §4 System Constraints.

1. Per-cell memory budget.

Target: ≤ 1.5 GB for 1M populated cells  (§4)
⇒ 1.5 × 10⁹ B / 10⁶ cells = 1,500 B/cell amortized
Breakdown: CellSlot ≤ 48 B (value+formula ref+format+flags, §4)
           + dependency edges: see item 2
           + cached eval result (already in CellSlot)
           + interner string storage (amortized)
Remaining per-cell budget for graph+interner: 1500 − 48 = 1,452 B/cell

2. Dependency graph edge budget.

Max edges: 4,000,000  (§4)
Memory/edge (SmallVec<DepEdge>): ~24 B/edge (CellId=10B + tag=2B + padding)
Total edge memory: 4 × 10⁶ × 24 B = 96 MB
At 1M formula cells: 96 MB / 10⁶ = 96 B/cell for the graph — well within the 1,452 B remaining

3. Recalc throughput requirement (single-thread).

Target: full recalc 100k formula cells p99 ≤ 250 ms  (§4)
⇒ 100,000 cells / 0.250 s = 400,000 cells/s minimum throughput
Single-cell eval p99 ≤ 50 µs (§4) → 1/50µs = 20,000 cells/s worst-case
Implication: the p99 single-cell target applies to complex formulas;
             simple arithmetic must be well under 50 µs to average to 400k/s.
At p50 = 2 µs/cell: 500,000 cells/s → 100k in 200 ms ✓ within 250 ms

4. Parallel recalc speedup requirement.

Target: 1M cells on 8 cores < 1.5 s  (§4)
Single-thread at p50 2 µs/cell: 1M × 2 µs = 2 s
Required speedup: 2 s / 1.5 s = 1.33×  (modest — a 25% efficiency gain from 8 cores)
Amdahl: if 70% of work is parallelizable, 8 cores → speedup ~3.1× → well above target
Implication: even moderate parallelization (30% serial fraction) exceeds the target.

5. Incremental recalc latency budget.

Target: 1 edit, ~1k affected cells, p95 ≤ 2 ms  (§4)
At p50 2 µs/cell: 1,000 cells × 2 µs = 2 ms → barely meets p95 ≤ 2 ms
⇒ Hot-path eval must be closer to p50 = 1 µs for p95 to clear 2 ms with overhead
Closure computation overhead: BFS over ~1k edges at ~50 ns/edge = ~50 µs → negligible
Topo sort of 1k nodes: O(k) ≈ 100 µs → 5% of budget → acceptable

6. File descriptor budget (server mode).

Target: ≤ 64 FDs/session  (§4)
Breakdown: 1 snapshot file (.scbk) + 1 WAL (.scwal) + 1 gRPC socket + 1 JSON-RPC socket
           + 2 prometheus + misc: ~8 FDs/session → well within 64
At 64 sessions on a server: 8 × 64 = 512 FDs << typical ulimit of 65,536

7. WAL write throughput.

Target: op-log fsync < 2 ms/batch  (§4)
Typical op size: 64 B (SetCell: IDs + before + after)
At 10k ops/batch: 10,000 × 64 B = 640 KB/batch
Sequential write bandwidth (NVMe): ~2 GB/s → 640 KB / 2 GB/s = 0.32 ms << 2 ms ✓
fdatasync on NVMe: ~0.1–0.5 ms → total ~0.5–1 ms/batch ✓
HDD: ~5–10 ms/fsync → exceeds target; requires async WAL or SSD requirement.

8. Snapshot creation time.

Target: < 5 ms for 1M cells (in-memory COW snapshot)  (§4)
COW snapshot = Arc clone of store structure: O(modified since last snapshot)
If 10k cells modified: 10k × 48 B = 480 KB to COW-copy → ~0.2 ms ✓
Full on-disk snapshot: 1M × 48 B = 48 MB → at 2 GB/s = 24 ms (background, not on critical path)
In-memory structural sharing makes the critical-path snapshot < 5 ms ✓

9. Parser throughput.

Target: ≥ 1M formulas/sec (Performance Engineering)
Average formula: 40 chars; 1M × 40 B = 40 MB text to lex/parse per second
Lexer: streaming, allocation-free → ~10 ns/char → 40 B × 10 ns = 400 ns/formula
Pratt parser: 10–20 nodes/formula × 20 ns/node = 200–400 ns/formula
Total: ~600–800 ns/formula → 1.25–1.67M formulas/sec ✓
Interning overhead: FNV hash ≈ 5 ns/char for the formula text → +200 ns → still > 1M/sec ✓

10. Spill area cap.

Memory cap: 1.5 GB / 1M cells budget means spill cells share the 1,500 B/cell envelope
A spill of 1M cells: 1M × 48 B (value only, no formula) = 48 MB → 3.2% of budget → acceptable
MAX_SPILL_AREA policy: cap per-anchor at 1M cells; workbook-wide spill cells counted in I14
Unbounded SEQUENCE(1e9) rejected → #SPILL! (§4, P8)

11. Iterative calculation cost.

Max iterations: 100 (§4 default); epsilon: 1e-7
SCC size worst case: all 1M cells in one cycle (degenerate)
Cost: 100 iterations × 1M cells × 2 µs/cell = 200 s → unacceptable
∴ large SCCs with iterative mode must emit a warning and cap by max_iter
Typical SCC: 1–10 cells; 100 × 10 × 2 µs = 2 ms → acceptable
Boundary: warn when SCC × max_iter > 10,000 cell-evaluations/batch

12. Recovery time (RTO).

Target: < 5 s (load snapshot + replay 10k ops)  (§4)
Snapshot load: 48 MB (1M cells) at 2 GB/s sequential read = 24 ms → negligible
WAL replay: 10k ops × 64 B = 640 KB; parse + apply at 1M ops/s = 10 ms → negligible
Graph rebuild from formulas: 1M formulas × 400 ns/formula = 400 ms
Full recalc (dirty): 1M cells × 2 µs = 2 s
Total: 24 + 10 + 400 + 2000 ≈ 2.4 s << 5 s ✓ (with margin for I/O variance)
