⬜ Phase P0 — Workspace / Crate Skeleton + Sparse Cell Store + Value Model §12

Objectives
  • Stand up Cargo workspace (20 crates per §1 / §10); sheetcalc-core compiles, re-exports value/error/coord/store/workbook/interner/ids.
  • CellValue, ErrorKind (+ precedence), CellId/coord bijection, Interner (FNV), sparse columnar CellStore, Sheet, Workbook shell.
  • No formulas yet — literals only: set_cell(literal) / get_value round-trips. Establishes I6, I12, I14 substrate.
Deliverable

Workspace builds (cargo build --workspace); sheetcalc-core exposes value/coord/store/workbook for literals; cargo test -p sheetcalc-core green. astdump/server/wasm stubs compile (empty).

Acceptance

  • col_to_index("XFD")==16383; index_to_col(16383)=="XFD"; round-trip ∀ col∈0..16384.
  • intern("x")==intern("x") (same id); resolve round-trips UTF-8 incl. multibyte.
  • Over-cap write → EditError::CellLimit, store unchanged.
  • Empty workbook construct < 1 ms (constraint §4).

⬜ Phase P1 — Formula Lexer + Pratt/Precedence Parser + AST §13

Objectives
  • sheetcalc-lex: text → token stream (§8.1) with spans; locale arg-sep (,/;).
  • sheetcalc-parse: Pratt parser → Ast (§8.4) honoring full precedence/assoc table (§8.3); structured parse errors → Ast::Error(ErrorKind).
  • AST interning (AstArena, Arc) so identical formulas dedup (ADR-003). Establishes I13 (depth cap).
Deliverable

parse(&str, locale) -> FormulaAst for full grammar (§8.2); astdump emits stable JSON; identical formulas share arena. Parser/lexer fuzz target builds.

Acceptance
  • Precedence: =1+2*3 → Binary(Add,1,Binary(Mul,2,3)); =2^3^2 right-assoc; =-3^2 → (-3)^2 (§8.9).
  • =10% → Unary(Percent,10); ="a"&"b"&1 left-assoc concat.
  • =SUM(A1:A3, B1) → Call(SUM,[Range, Ref]); ={1,2;3,4} 2×2 array.
  • Depth > 256 → Ast::Error; never stack-overflows (fuzz-verified).
  • Identical formula text → identical AstId (dedup).

⬜ Phase P3 — Dependency Graph Build + Topological Order (Kahn) + Precedents/Dependents §15

Objectives
  • sheetcalc-graph: build bidirectional graph from formulas — precedents (reads) + dependents (readers); range-node compression (ADR-006, Principle 8).
  • Kahn topological order over a dirty subgraph; precedents/dependents queries. Establishes I2 (acyclic-or-flagged) substrate + I3 closure foundation.
Deliverable

add_formula/remove_formula/dependents_of/topo_order over cell + range edges; range-node compression keeps edges O(formulas); DOT export.

Acceptance
  • =A1+A2 adds edges A1→cell, A2→cell; removing the formula leaves zero residual edges (I1).
  • =SUM(A1:A1000) adds one range edge, not 1000 (Principle 8); writing A500 marks the formula dirty via range-node membership.
  • topo_order of a DAG yields a valid linear extension; deterministic across runs (I4).
  • Cyclic input → Cycle{remaining} returned (not infinite loop), handed to P5.
  • Edge count > cap → EdgeLimit, graph unchanged.

⬜ Phase P4 — Evaluation Engine + Type Coercion + Error Model / Propagation §16

Deliverable

eval(ast,ctx) for all non-function nodes + arithmetic/compare/concat; recalc_full computes a static (no edits) workbook to fixpoint of the DAG; error precedence enforced.

  • Two-error operand: =#DIV/0! + #N/A → #DIV/0! (left-first / precedence per §8.7).
  • =TRUE+1→2; ="3.5"*2→7; blank-cell +1→1.
  • Bit-identical numeric results across runs (I12, I4) for golden fixtures.

⬜ Phase P5 — Cycle Detection (Tarjan SCC) + Iterative Calculation Mode §17

Objectives
  • sheetcalc-graph::tarjan + sheetcalc-recalc::iterative: detect strongly-connected components in the affected subgraph; classify SCC>1 (or self-edge) as a cycle (I2).
  • Non-iterative mode → mark every cell in a cyclic SCC #CIRCULAR! (I5 rank 10). Iterative mode → fixed-point loop with max_iter/epsilon (§4: 100 / 1e-7), else converge-or-last-value per CalcMode::Iterative.
  • Establish that recalc never infinite-loops on cycles (Principle 12) and cycle membership is precise (no false positives that stall acyclic chains).
Deliverable

sccs(sub) returns precise SCCs over any subgraph; condensation topo-order drives recalc; CalcMode::Iterative converges or stops at max_iter; Automatic marks cycles #CIRCULAR! without hanging.

Acceptance
  • A1=A1 (self) → #CIRCULAR! (Automatic); converges to fixpoint if linear + iterative (e.g. A1 = A1*0 + 1 → 1).
  • 3-cycle A→B→C→A → all three #CIRCULAR! (Automatic); SCC size 3 reported.
  • Convergent iterative x = (x + n/x)/2 (Newton sqrt) → converges < max_iter within epsilon.
  • Divergent iterative (x = x + 1) → stops at max_iter, converged=false, last value retained.
  • Acyclic chain of 100k cells → SCCs all size 1, no false cycle, < full-recalc target (§4).
  • Tarjan over 1M-node chain does not overflow stack (iterative impl).
Fixtures
Dir Case Expected
cycles/self_ref A1=A1 #CIRCULAR! (auto) / fixpoint (iter)
cycles/three_cycle A↔B↔C SCC{3}, all #CIRCULAR!
cycles/converge_newton sqrt iteration converges, value within 1e-7
cycles/diverge x=x+1 stop at max_iter, last value
cycles/mixed cycle feeding acyclic tail tail sees #CIRCULAR! (auto)
cycles/scc_precision DAG + one embedded cycle only cycle nodes flagged

Pitfalls
  • Recursive Tarjan overflows on deep chains — must be explicit-stack iterative (manifestation: stack-overflow crash on a 100k-row column; root cause: native recursion; debug: backtrace depth; fix: worklist).
  • Self-loop detection: a single node with an edge to itself is a 1-member SCC that is a cycle — Tarjan's "size>1" test misses it; add explicit self-edge check.
  • Convergence false-positive: epsilon compare on values that oscillate within epsilon but never settle — cap by max_iter always (do not trust epsilon alone).
  • Float non-determinism in iterative loop: differing add order across passes → different convergence path; fix evaluation order per pass (sorted), Principle 1.
  • Cycle that includes a volatile (RAND) never converges by construction — detect volatile-in-cycle, warn, bound by max_iter.
  • Marking the entire workbook #CIRCULAR! instead of just the SCC closure (blast-radius bug) — scope poisoning to SCC + forward dependents only.

⬜ Phase P6 — Incremental Recalculation (Dirty-Set Propagation + Minimal Recompute Scheduler) §18

Objectives
  • sheetcalc-recalc::dirty + schedule: on a cell write, compute the forward closure of affected cells (transitive dependents) and recompute only those, in topo order (Principle 2, I3).
  • Seed dirty-set with the changed cell(s) + all volatile cells (I11). Replace the P4 full-recalc default with incremental recalc_dirty.
  • Establish edit latency proportional to affected-set size, not workbook size (§4 incremental targets).
Deliverable

recalc_dirty recomputes exactly the affected closure (+ volatiles) in topo order; single-cell edits in a large workbook complete within §4 incremental targets; value-equality cutoff prunes unaffected dependents.

Acceptance
  • Edit one input feeding 1k dependents → exactly ~1k cells recomputed (recompute_count ≈ closure size), not whole workbook.
  • Editing a cell whose value is unchanged (re-enter same number) → dependents not recomputed (closure cut), unless volatile.
  • Volatile cells (NOW) recompute on every recalc regardless of edit locus (I11).
  • Incremental recalc (1 edit, ~1k affected) p95 ≤ 2 ms (§4).
  • Post-recalc audit passes: ∀ changed c, all dependents clean⇒recomputed (I3).
  • Batch of 10k edits coalesces into one closure pass (not 10k passes).
Fixtures
Dir Case Expected
recalc/minimal edit 1 of 100k, 1k dependents recompute ≈1k
recalc/closure_cut re-enter identical value dependents skipped
recalc/volatile_refire NOW + edit elsewhere NOW recomputed
recalc/range_dirty write inside SUM(A:A) range SUM recomputed
recalc/batch_coalesce 10k edits then recalc one closure pass
recalc/audit_complete random edits I3 audit passes
Pitfalls
  • Missed range-node dirty: writing inside a range precedent without dirtying the range node → stale aggregate (manifestation: SUM(A:A) doesn't update; root cause: P3 reverse index gap; debug: I3 audit; fix: interval membership).
  • Closure-cut on error transitions: value bit-equal but error-state flipped (e.g. was #DIV/0!, now still error of different kind) — compare full CellValue, not just number.
  • Volatile forgotten in seed → stale NOW/RAND (manifestation: clock frozen; fix: always union volatile set, I11).
  • Dirty-set ordering non-deterministic (HashSet) → non-deterministic recompute order within independent cells (I4) — use sorted/ordered set.
  • Re-entrancy: an edit during recalc (e.g. from a callback) corrupts the in-flight closure — forbid nested recalc (mutation root, Principle 5).
  • Coalescing window too greedy: holding edits indefinitely starves readers of fresh values — bound batch, flush on read/timer.

Registry with ~40 P0 functions evaluable end-to-end; arity + coercion enforced; volatility tagged; error-tolerant functions correct; criteria + lookup match modes implemented; host custom-function registration works.

⬜ Phase P8 — Dynamic Arrays, Spilling, Implicit Intersection, Broadcasting §20

Objectives
  • sheetcalc-array: array-valued results that spill into neighboring cells (Excel 365 dynamic arrays); spill anchors, spill ranges, collision → #SPILL! (I7).
  • Implicit intersection (@), array broadcasting (§8.6), array-aware functions (SEQUENCE, FILTER, SORT, UNIQUE, TRANSPOSE, array CSE).
  • Spill region participates in dependency graph (spill cells are derived; downstream refs to them must dirty correctly).
Deliverable

Array results spill into a rectangle; collisions → #SPILL! with no partial write (I7); # spill-ref + @ implicit-intersection work; broadcasting per §8.6; array-aware functions (SEQUENCE/FILTER/SORT/UNIQUE/TRANSPOSE) evaluate.

Acceptance
  • =SEQUENCE(3) in A1 spills A1:A3 = 1,2,3; A2/A3 marked Spilled{anchor:A1}.
  • Blocking cell in spill target → anchor = #SPILL!, no spilled writes (I7); clearing the blocker re-spills.
  • ={1,2;3,4}+10 broadcasts to {11,12;13,14}.
  • =@A1:A10 returns the same-row cell (implicit intersection); =A1# references the live spill range.
  • Editing the anchor formula to a smaller shape frees the vacated cells (they blank + dirty dependents).
  • =FILTER(A1:A10, B1:B10>0) returns variable-length spill; empty result → #CALC!.

⬜ Phase P9 — Structural Edits (Insert/Delete/Move Row-Col) + Reference Rewriting + Undo/Redo §21

Objectives
  • sheetcalc-edit: insert/delete rows/cols, move/cut-paste, sort; rewrite all affected references by coordinate arithmetic (Principle 9, I10), not text.
  • sheetcalc-persist::undo: every mutation is a reversible Op; undo/redo via op-log (I8). Structural edits trigger graph rebuild + recalc of affected closure (P6).
  • Reference integrity after edits (I1, I15): refs to deleted region → #REF!; refs shift correctly.
Deliverable

Insert/delete/move/sort with correct reference rewriting (absolute pins, relative shifts, #REF! on deletion); undo/redo restores exact prior state (I8); cross-sheet + named-range refs fixed up; recalc of affected closure after edit.

Acceptance

  • Delete row 5: =A5 → #REF!; =A10 → =A9; range =SUM(A3:A8) → =SUM(A3:A7).
  • Copy =A1+B1 from C1 to C2 → =A2+B2 (relative); =$A$1+B1 → =$A$1+B2.
  • Move block A1:B2 to D1 → external refs to A1 follow to D1; internal =A1 (now D1) stays relative-consistent.
  • Undo any edit → exact prior CellValue + formula + graph; redo re-applies; undo∘redo = identity (I8).
  • Cross-sheet: deleting a sheet → all refs into it #REF! (I15); editing rows in Sheet1 fixes Sheet2 refs.

⬜ Phase P10 — Parallel Recalculation (Work-Stealing over Independent Subgraphs, Snapshot Isolation) §22

Objectives
  • sheetcalc-recalc::parallel + snapshot: evaluate independent cells in a topo layer concurrently across a work-stealing pool (rayon-style, ADR-010), with deterministic results regardless of thread count (I4) under snapshot isolation (Principle 6, I9).
  • Scale full recalc of 1M formula cells to < 1.5 s on 8 cores (§4) without sacrificing determinism or reader isolation.
Deliverable

Parallel recalc_full/recalc_dirty over independent topo layers; deterministic byte-identical results 1-thread vs N-thread (I4); snapshot isolation for concurrent readers (I9); 1M-cell recalc < 1.5 s / 8 cores (§4).

Acceptance
  • 1M independent formula cells: parallel recalc < 1.5 s / 8 cores; near-linear speedup vs single-thread on independent subgraphs.
  • Determinism (I4): 1-thread vs 2/4/8-thread results bit-identical for all fixtures (including RAND with deterministic per-cell seed).
  • Reader holding a snapshot during recalc sees a consistent pre-recalc image, never a half-updated state (I9).
  • Cyclic SCC under parallel mode → evaluated sequentially, same result as single-thread.
