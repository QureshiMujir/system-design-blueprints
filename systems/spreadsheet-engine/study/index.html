Hard questions

  1. A user inserts a row in Sheet1 at row 5. List every subsystem that must execute, in order, and every invariant that could be violated if any step is skipped. (§21 Phase P9, §7 I1/I10/I15, §6 Principle 9)
  2. A formula =SUM(A1:A1000000) exists in cell B1. A user writes a value to cell A500000. Trace the complete recalc path: which data structures are consulted, which edges are traversed, what is the complexity, and what happens if the recompute_count equals the cell_count metric? (§15 Phase P3, §18 Phase P6, §6 Principle 8, §7 I3/I14)
  3. Explain why =RAND()+RAND() can produce different results from =2*RAND() without violating the determinism invariant I4, and what design decision in Phase P10 controls the specific behavior. (§22 Phase P10, §7 I4/I11, §6 Principles 1/7, ADR-027)
  4. The recalc engine produces different floating-point results on a 4-core run vs an 8-core run for a workbook with =SUM(A1:A1000). Diagnose the root cause, name the invariant violated, and explain the fix using the architecture. (§7 I4/I12, §22 Phase P10, §6 Principle 1, ADR-014)
  5. A workbook has a 3-cell iterative cycle (A1→B1→C1→A1) and CalcMode::Iterative. After 100 iterations =C1 is within epsilon of the prior value but =A1 is not. What does the engine do, and how does the convergence check interact with epsilon vs max_iter? (§17 Phase P5, §4 iterative calc constraint, §7 I2/I13, §6 Principle 12)
  6. A VLOOKUP in approximate mode returns a wrong result because the lookup column is unsorted.   7. Describe exactly how the snapshot isolation model (§7 I9) prevents a server reader from observing a half-computed recalc.   8. A user pastes 10,000 cells at once. Explain how the recalc_dirty path handles this as a single batch (not 10,000 sequential recalcs), what the complexity is, and how the op-log records it for undo/redo. (§18 Phase P6, §21 Phase P9, §7 I8/I3, §6 Principle 2)
  9. A cross-sheet formula in Sheet2 references a cell in Sheet1. Sheet1 is then deleted. Describe the complete reference-integrity enforcement path from the delete operation through the graph to the final #REF! value, naming every invariant enforced. (§14 Phase P2, §21 Phase P9, §7 I1/I15, §6 Principles 9/12)
  10. Compare the memory cost of a workbook with 1M cells where every cell contains =SUM(A:A) vs one where every cell contains a unique single-cell reference. Use the capacity model numbers to derive both scenarios. (Back-of-Envelope Capacity Model items 1–2, §15 Phase P3, §7 I14, ADR-005/006)
  11. A formula =INDIRECT("A"&ROW()) is in cells B1:B10000. How many times is this formula re-evaluated on a recalc triggered by a single edit to cell Z99? Explain using the volatile model and the dirty-set propagation. (§18 Phase P6, §19 Phase P7, §7 I11, §6 Principle 7)
  12. Describe the complete failure mode if the WAL is fsynced after a snapshot is written during compaction (reversed order vs the correct snapshot-then-truncate discipline). Trace the crash scenario step by step and explain what data is lost. (§23 Phase P11, §7 I8, §6 Principle 11, Failure Modes and Recovery row "Persistence corruption")
  13. A =FILTER(A1:A100, B1:B100>0) formula produces a spill of 50 rows. Then cell B25 is edited to 0. Trace the full path: spill resize, reservation update, dependency graph update, dirty propagation, and which cells receive #SPILL! or blank. (§20 Phase P8, §18 Phase P6, §7 I7/I3, §6 Principle 8)
  14. Explain why the Pratt parser is chosen over LALR for the formula grammar (ADR-002), then construct a concrete example where LALR would produce better or worse diagnostic output, and a case where Pratt's operator table is harder to maintain than a BNF grammar in a parser-generator. Mental Models & First Principles

MM1 — The dependency graph IS the computation. A spreadsheet is not a bag of cells with formulas; it is a directed graph where edges are reads, nodes are computations, and values flow source→sink. The formula text is merely the edge declaration. Prediction: any correctness problem in recalc traces back to a missing or wrong edge. Bug class without it: updating cell values directly and forgetting to propagate — implementors patch values instead of fixing the graph, creating ghost staleness. Applied in: §3 (dependency graph box), §6 (Principle 2), §7 (I3), Phase P3.

MM2 — Dirty propagation is a forward BFS; evaluation is a backward traversal of the same graph. Marking dirty flows forward (source → dependents); evaluation flows in the reverse topological order (precedents before dependents). These are dual traversals of one graph; confusing their direction produces either missed dirty or wrong eval order. Prediction: any "stale value" bug is a forward-BFS gap; any "evaluated before its input" bug is a topo-sort gap. Bug class without it: evaluating cells in arbitrary order, reading stale precedents. Applied in: §6 (Principles 2, 15), Phase P6 (dirty.rs, schedule.rs), §7 (I3).

MM3 — SCC condensation turns cyclic graphs into DAGs. Tarjan's SCC collapses every cycle into a super-node; the condensation is always a DAG. Topological evaluation then operates on the condensation: each acyclic super-node is one cell, each cyclic super-node is an iterative-to-fixpoint block. Prediction: any cycle-handling strategy reduces to (a) detect SCCs, (b) condense, (c) topo-order the condensation. Bug class without it: treating cycles as errors without attempting condensation — correctly cyclic iterative models (solver, depreciation) rejected. Applied in: Phase P5 (tarjan.rs, iterative.rs), §7 (I2), ADR-008.

MM4 — Errors are values in the lattice, not exceptions. Excel's error model is a total order (§8.7) over a set of error values. Every operation must be defined on error inputs: either short-circuit (most ops) or inspect (IFERROR). Treating errors as exceptions causes two classes of bug: (a) an error swallowed and replaced with 0/blank (silent wrong result), (b) a panic propagating up the call stack. Prediction: any unwrap on a CellValue in the eval path is a latent panic bug. Bug class without it: =IFERROR(1/0, "x") panics instead of returning "x". Applied in: §8.7, §6 (Principle 4), §7 (I5), Phase P4 (eval.rs, coerce.rs).

MM5 — Range nodes avoid O(N²) graph blow-up. A formula =SUM(A1:A1000) has one semantic dependency (the range), not 1000. Materializing per-cell edges gives O(formulas × cells-per-range) = O(N²) in the worst case. Range nodes compress this to O(formulas) edges. The interval-membership reverse index maps cell writes back to owning range nodes in O(log + k) without materializing the full range. Prediction: any spreadsheet without range-node compression will OOM or stall on a model with one SUM over a large column. Bug class without it: inserting a row in a column with SUM(A:A) spawns 1M new edges. Applied in: §6 (Principle 8), §7 (I14), Phase P3 (rangenode.rs), ADR-006.

MM6 — Snapshot isolation is structural sharing, not copying. Immutable Arc<Snapshot> over a COW store means readers and parallel evaluators see a consistent point-in-time image without locking or copying the entire store. The key insight: if the store is structured as a persistent data structure (structural sharing of unchanged columns), the snapshot is O(modified cells) not O(all cells) to create. Prediction: any lock-based reader/writer scheme will either block reads during recalc or see torn state. Bug class without it: a read of cell B during recalc sees B from the new pass but A from the old — cross-cell inconsistency. Applied in: §6 (Principle 6), §7 (I9), Phase P10 (snapshot.rs), ADR-011.

MM7 — Determinism requires a total order on every non-deterministic operation. Parallel evaluation, hash-map iteration, and float reduction are the three sources of non-determinism in a spreadsheet engine. Each requires a discipline: (a) evaluate across independent cells in parallel but within one cell left-to-right; (b) sort all hash-map keys before any compute-affecting iteration; (c) never reduce a range across threads (each cell's SUM is single-threaded). The mechanical check is a byte-diff of 1-thread vs N-thread output. Bug class without it: RAND returns different values run-to-run; SUM(A1:A1000) diverges across thread counts on boundary values. Applied in: §6 (Principle 1), §7 (I4), ADR-014, ADR-027, Phase P10.

MM8 — Reference fixup is coordinate arithmetic, never string surgery. A structured Reference carries per-axis Abs|Rel flags and integer offsets. Structural edits (insert/delete/move) are applied by arithmetic: Rel axes shift by the edit delta, Abs axes shift on structural inserts but are pinned against fill/copy. Text-based substitution (s/A1/A2/g) fails on $A$1, named ranges, cross-sheet refs, and string literals containing "A1". Prediction: any regex-based ref rewriting will produce wrong results for at least one of the reference kinds in §8.5. Bug class without it: =$A$1 silently becomes =$A$2 under a copy delta (should be pinned). Applied in: §6 (Principle 9), §7 (I10), Phase P9 (fixup.rs, rewrite.rs), ADR-003.

MM9 — Correctness in numerics is differential, not unit. IEEE-754 binary64 is deterministic but not intuitive: 0.1+0.2 ≠ 0.3, ROUND(2.5,0)=2 in some modes. The only way to validate numeric semantics against Excel is to run the same input through both engines and compare. Unit tests that assert abs(result - expected) < 1e-10 mask systematic biases. A differential oracle harness (LibreOffice headless / formulajs) surfaces them. Prediction: any engine that does not run differential tests will ship at least one systematic coercion divergence within the first 100 functions. Bug class without it: ROUND uses banker's rounding instead of Excel's round-half-away → financial models off by 0.5 in edge cases. Applied in: §6 (Principle 3), §7 (I12), ADR-012, Phase P4, Phase P12 (differential.rs).

MM10 — Crash-only persistence via op-log replay eliminates clean-shutdown reasoning. The engine never assumes it shut down cleanly. State = last durable snapshot + WAL tail. Recovery = load snapshot + replay. This makes every write path trivially crash-safe: append to WAL (fsync grouped), swap snapshot atomically. No flush-on-close, no in-progress markers. Prediction: any "flush on shutdown" scheme will silently lose data on kill-9 or power loss. Bug class without it: a snapshot written mid-recalc (not at a consistent boundary) + WAL truncated before snapshot durable = data loss. Applied in: §6 (Principle 11), §7 (I8), Phase P11 (oplog.rs, snapshot.rs), ADR-016.

Glossary · 38 terms · site-wide glossary

Precedent
A cell/range a formula reads (its inputs).
Dependent
A cell whose formula reads a given cell (downstream).
Dirty
A cell whose cached value is stale and must be recomputed.
Forward closure
Transitive set of all dependents reachable from changed cells.
Minimal recompute
Recomputing only the forward closure of changes, not the whole workbook (Principle 2).
Topological order
Linear ordering of a DAG s.t. every precedent precedes its dependents (Kahn).
SCC
Strongly-connected component; a maximal set of mutually reachable nodes — a cycle if size>1 or self-edge (Tarjan).
Condensation
DAG formed by contracting each SCC to a super-node; gives evaluation order over cyclic blocks.
Volatile function
A function that must recompute every recalc (NOW/RAND/OFFSET/INDIRECT/…) (I11).
Spill
An array result occupying a rectangle of cells from a single anchor formula (dynamic arrays).
Spill anchor
The cell holding the array formula; owns the spill range.
#SPILL!
Error when a spill region is blocked by existing content (I7).
Implicit intersection (@)
Reducing a range/array to a single value on the formula's row/col.
Spill reference (#)
A1# — references the live spill range anchored at A1.
A1 notation
Column-letter + row-number addressing ($ pins).
R1C1 notation
Row/Column-number addressing; [] = relative offset.
Absolute reference
$A$1 — pinned against fill/copy (but shifts on structural insert/delete).
Relative reference
A1 — shifts with fill/copy and structural edits.
Named range
A name bound to a reference/range/formula/constant.
Structured reference
Table-column reference (Table1[Amount]) (subset; full deferred).
Range node
A single graph node representing a range precedent, avoiding per-cell edge explosion (Principle 8).
Reference fixup
Coordinate-arithmetic rewriting of references on structural edits (Principle 9, I10).
Op-log / WAL
Append-only reversible operation log for undo/redo + crash recovery (I8).
Snapshot
Immutable COW view of the store for isolated reads + parallel eval (I9).
Snapshot isolation
Readers see a consistent point-in-time image, never a mid-recalc state (Principle 6).
Iterative calculation
Fixed-point loop for circular refs, bounded by max-iter/epsilon (P5).
Coercion
Type conversion between number/text/bool per context (§8.8).
First-error-wins
Error propagation: first error in eval order surfaces (§8.7, I5).
Error value
A first-class CellValue variant (#DIV/0! etc.), not an exception (Principle 4).
Date serial
Numeric encoding of dates (1900/1904 epoch); time = fractional day.
1900 leap bug
Excel's fictitious 1900-02-29 (serial 60), replicated for parity.
Determinism
Bit-identical results across runs/threads (Principle 1, I4).
Recalc storm
Excessive recompute from volatile chains / huge closures (a failure mode).
Anchor (eval)
The current cell, basis for relative refs + implicit intersection.
Interning
Deduplicating strings/ASTs to stable ids (ADR-013/003).
Broadcasting
Element-wise combination of arrays/scalars with shape rules (§8.6).
CSE array formula
Legacy Ctrl+Shift+Enter fixed-range array formula (vs dynamic spill).
Calc mode
Automatic / Manual / Iterative recalculation policy.
