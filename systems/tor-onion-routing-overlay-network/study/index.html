30. Mental Models & First Principles

  • MM1 — Stateless Fast Path. The forwarding hot path (Listener→CryptoLayer) must never touch persistent storage; predicts that any "just persist this for debugging" change to that path silently blows the p99 latency budget; the bug class you write without it is a slow, hard-to-bisect latency regression that only appears under load; applies in §16.

  • MM2 — Fail Closed at Every Trust Boundary. Malformed input terminates the session that produced it rather than being tolerantly parsed; predicts that "lenient parsing" changes reintroduce exactly the parser-confusion bug class the fail-closed design retired; the bug class you write without it is a remote-exploitable parser-confusion vulnerability; applies in §15.

  • MM3 — Determinism Is a Debugging Multiplier, Not a Purity Test. Every replay-relevant transition reading only injected inputs (no wall clock, no hashmap iteration order) predicts that any production incident can be reconstructed bit-for-bit from its WAL trace; the bug class you write without it is an unreproducible "worked in staging" failure; applies in §19.

  • MM4 — Bound Every Queue, Then Decide What to Shed. An unbounded queue predicts memory exhaustion under sustained overload, not graceful degradation; the bug class you write without it is a cascading relay collapse from one slow consumer; applies in §17.

  • MM5 — Separate Key Domains Bound Blast Radius. Splitting transport, identity, and session keys predicts that any single key-domain compromise stays contained to that domain; the bug class you write without it is a single leaked key cascading into full relay compromise; applies in §13.

  • MM6 — Quorum Size Is a Tradeoff, Not a Constant. A larger authority quorum predicts slower consensus convergence but higher Byzantine tolerance; the bug class you write without reasoning about it explicitly is picking a quorum threshold that looks safe on paper but never converges under real network partition rates; applies in §14.

  • MM7 — Anonymity Sets Shrink Under Timing Correlation, Not Just Content Leakage. Congestion-control decisions leak information through latency variance even with perfect encryption; predicts that an unpaced scheduler is a traffic-analysis vulnerability even though it never touches plaintext; the bug class you write without it is "cryptographically sound but analytically deanonymizable"; applies in §17.

  • MM8 — Observability Must Degrade Gracefully, Never Become a Dependency. Telemetry-pipeline outages must never affect forwarding correctness; predicts that coupling correctness logic to a metrics exporter's availability is itself a production outage waiting to happen; the bug class you write without it is an observability outage becoming a traffic outage; applies in §20.

5. Required Reading

Books

  • Network Security: Private Communication in a Public World — Kaufman, Perlman & Speciner (2002), ch. on TLS/PKI and secure channels: authenticated key exchange and cert-based trust anchoring; applied in §13.
  • TCP/IP Illustrated, Volume 1 — W. Richard Stevens (1994), ch. on the TCP state machine and congestion behavior: retransmission and socket-lifecycle semantics that bound relay reconnect timing; applied in §13 and §17.
  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 5 (Replication) and ch. 9 (Consistency and Consensus): quorum and failure-semantics reasoning behind the directory-authority split-brain defenses; applied in §14.
  • Rust Atomics and Locks — Mara Bos (2023), ch. 2–4 (memory ordering, atomics, locks): the lock-partitioning and message-passing discipline behind the scheduler's queue isolation; applied in §17.
  • Linux Kernel Networking: Implementation and Theory — Rami Rosen (2014), ch. on socket internals and epoll: buffering and edge-triggered readiness behind the transport runtime; applied in §12.
  • Serious Cryptography — Jean-Philippe Aumasson (2017), ch. on AEAD and key exchange: replay-resistant AEAD framing and X25519/Ed25519 usage; applied in §13 and §15.
  • Systems Performance — Brendan Gregg (2nd ed., 2020), ch. on flame graphs and scheduler latency analysis: the profiling methodology; applied in §28.

Papers

  • "Tor: The Second-Generation Onion Router" — Dingledine, Mathewson & Syverson, 2004, USENIX Security: the original three-hop onion-routing design, circuit-extend cell protocol, and directory-authority trust model → this blueprint's Circuit Manager and Directory Authority split; applied in §14 and §15.
  • "KIST: Kernel-Informed Socket Transport for Tor" — Jansen, Traudt & Hopper, 2014, NDSS: kernel-socket-buffer-aware scheduling to avoid relay-side queue bloat → informs the token-bucket/congestion-window design; applied in §17.
  • "Users Get Routed: Traffic Correlation on Tor by Realistic Adversaries" — Johnson, Wacek, Jansen, Sherr & Syverson, 2013, CCS: quantifies guard-relay compromise and path-selection bias under a partial adversary → informs relay-diversity constraints; applied in §15.
  • "Locating Hidden Servers" — Øverlier & Syverson, 2006, IEEE S&P: demonstrates rendezvous-side timing attacks against hidden-service location → informs anti-enumeration and rendezvous-cookie design; applied in §18.
  • "Low-Cost Traffic Analysis of Tor" — Murdoch & Danezis, 2005, IEEE S&P: shows a passive relay-side observer can fingerprint circuits by latency correlation → informs the scheduler pacing and congestion-isolation invariants; applied in §17 and §22.
  • "Scalable Onion Routing with Torsk" — McLachlan, Tran, Hopper & Kim, 2009, CCS: DHT-based directory alternative and its trust-tradeoffs versus centralized authorities → informs the rejected-alternative analysis of a DHT-based directory; applied in §34.
  • "HORNET: High-speed Onion Routing at the Network Layer" — Chen, Asoni, Perrig, Barrera & Danezis, 2015, CCS: stateless per-hop forwarding via embedded session state → informs the stateless-fast-path design principle (P11); applied in §16.
  • "Improving Tor Using a TCP-over-DTLS Tunnel" — Reardon & Goldberg, 2009, USENIX Security: single-transport multiplexing of many circuits to avoid TCP-over-TCP meltdown → informs the stream-multiplexer's flow-control isolation from the underlying TLS transport; applied in §16.

Reference Implementations

  • torproject/tor — study src/core/or/, src/lib/, src/app/: mature relay-lifecycle logic and descriptor propagation; pitfall: do not copy the legacy configuration sprawl or implicit global state that made the C codebase hard to audit; applied in §14.
  • torproject/arti — study crates/tor-proto, crates/tor-netdir, crates/tor-circmgr: modular Rust crate boundaries that map cleanly onto libprotocol/libcrypto/clientd; pitfall: do not copy its async-trait-heavy API surface wholesale, it complicates the no-code-in-spec signature style used here; applied in §12 and §15.
  • i2p/i2p.i2p — study the tunnel-pool lifecycle manager: unidirectional tunnel pairing versus Tor's bidirectional circuits; pitfall: do not adopt I2P's longer default tunnel lifetimes without re-deriving the churn budget in §4; applied in §15.
  • WireGuard/wireguard-linux — study the Noise-derived handshake state machine: minimal, auditable cryptographic state with no negotiation flexibility; pitfall: do not copy its single-hop assumption directly into a multi-hop layered design; applied in §13.
  • envoyproxy/envoy — study the listener/filter-chain observability model and the admin interface: cardinality-bounded metrics and a live introspection HTTP surface; pitfall: do not copy Envoy's xDS dynamic-config complexity into Phase 0; applied in §20.

RFCs / Specifications

  • RFC 8446 — TLS 1.3: pins the relay-to-relay and client-to-entry transport handshake, 0-RTT prohibited for replay safety; applied in §13.
  • RFC 1928 — SOCKS5: pins the client ingress protocol used by clientd's Client API; applied in §16.
  • RFC 5116 — AEAD interface: pins the authenticated-encryption contract used by the onion transform and transport framing; applied in §15.
  • RFC 7748 — Elliptic curves for security (X25519): pins the session-key Diffie-Hellman primitive; applied in §13.
  • RFC 8032 — EdDSA (Ed25519): pins the relay-identity and descriptor-signature primitive; applied in §14.

Glossary (§36) · 41 terms · site-wide glossary

Circuit
a multi-hop encrypted relay path between a client and an exit or hidden-service endpoint.
Relay
an overlay forwarding node participating in circuit construction.
Authority
a trusted consensus signer in the directory-authority quorum.
Hidden Service
a destination service reachable only through rendezvous, never by direct address.
Rendezvous
the relay-mediated connection point joining a client's and a hidden service's circuits.
Onion Layer
one AEAD encryption layer, removable by exactly one relay in traversal order.
Replay Window
the sequence-tracking bitmap structure preventing cell replay (I4).
Exit Relay
the relay bridging overlay traffic into the external, non-overlay internet.
Introduction Point
a relay a hidden service registers to receive connection requests.
Descriptor
signed relay or hidden-service metadata published to the directory authority.
Consensus Epoch
a versioned, monotonically increasing network-state snapshot (I2).
Flow Window
the per-stream flow-control budget bounding unacknowledged data in flight.
Cell
the fixed-header overlay protocol frame defined in §8.
Stream ID
the identifier multiplexing a logical TCP stream onto a circuit.
Relay Fingerprint
the stable hash of a relay's identity key (I8).
AEAD
authenticated encryption with associated data; the onion transform's cryptographic mode.
WAL
write-ahead log; the append-only durability substrate under P2/I5.
Backpressure
bounded-queue admission throttling preventing memory amplification (P3).
Scheduler Queue
one of the three prioritized forwarding-queue classes (control/data/teardown).
Circuit Extension
the protocol exchange adding one additional hop to an in-progress circuit.
Guard Relay
a client's stable first-hop relay, chosen to reduce path-selection bias exposure.
Path Selection
the relay-diversity-constrained algorithm choosing a circuit's three hops.
Congestion Window
the per-circuit pacing budget bounding in-flight unacknowledged cells.
Token Bucket
the rate-limiting primitive pacing outbound frames per circuit (§17).
Quorum
the N-of-M authority-signature threshold required to accept a consensus snapshot.
Byzantine Fault
a fault where a component actively deviates from protocol rather than merely failing.
Forward Secrecy
the property that compromising a current session key does not expose past traffic.
ntor Handshake
the authenticated Diffie-Hellman handshake style used for per-hop key agreement.
SOCKS5
the client-ingress proxy protocol (RFC 1928) implemented by clientd::socks.
Exit Policy
the rule set gating which destinations an exit relay will egress traffic toward.
Consensus Snapshot
the signed, published relay-set state for one epoch.
Descriptor Signature
the Ed25519 signature binding a descriptor to its issuing identity key.
Circuit Teardown
the protocol exchange tearing down all hops of a circuit.
Session Key
a per-transport-session symmetric key, distinct from identity and circuit keys (P9).
Identity Key
a relay's long-lived Ed25519 keypair, stable across sessions (I8).
Fail Closed
the design discipline of terminating on malformed input rather than tolerating it (P12).
Crash-Only
the design discipline assuming abrupt termination is always possible (P2).
Determinism
the property that identical inputs always produce identical outputs (P1).
Watchdog
the timer-based detector that triggers a crash dump on stalled scheduler progress.
Compaction
the WAL-maintenance process removing records superseded by a later checkpoint.
Checkpoint
a periodic full-state snapshot bounding WAL replay time on startup.
