3.2 Subsystem Descriptions

Application Layer — consumes send capacity, receives delivery notifications; never mutates congestion state directly.

Transport Integration API — the sole crossing point between protocol code and recovery internals; exposes packet registration, ACK notification, pacing availability, retransmission eligibility (I2, P3).

Packet Assembly Layer — packet-number assignment, encryption-space separation, immutable per-packet metadata snapshots (SentPacket, §11) consumed later by loss detection.

Congestion + Recovery Core — the decision engine: RTT update, PTO scheduling, cwnd transitions, ACK processing, loss declaration, ECN state, pacing decisions. Single-threaded per connection (ADR-08) — this is the concurrency boundary that makes replay deterministic.

Send Budget Engine — authoritative source for "may I send now": inflight bytes vs. cwnd, pacing-token balance (P2, P3).

Runtime Event Scheduler — timer wheel (ADR-23) driving PTO/pacing wakeups; jitter is measured, not assumed away.

UDP Socket Layer — batched syscalls (ADR-06), ECN codepoint marking, GSO segmentation; the external interface to the kernel network stack.

Telemetry/Replay path — every state transition emits a structured, replay-log-serializable event (P6); this is the persistence boundary.

Simulation path — quic-sim drives the same Transport Integration API as production, injecting deterministic loss/delay/reorder/duplication/ECN faults (Phase 8, §20).

3.3 Explicit Boundaries

  • Trust boundary: the Transport Integration API — everything below it trusts only validated, RFC-conformant data; everything above it is caller-controlled, untrusted input.
  • Concurrency boundary: the Congestion + Recovery Core is single-writer per connection (ADR-08); no lock is held across the ACK/loss/pacing decision path.
  • Persistence boundary: the Telemetry Path — nothing before it is durable, everything after it (the replay log, §20) is.
  • Protocol boundary: the Packet Assembly Layer — RFC 9000/9002 wire semantics live below it; algorithmic decisions (which packets to send, when) live above it.
  • External interface: the UDP Socket Layer — the only point where this subsystem touches the kernel network stack directly.

8. Domain Model — QUIC Packet Number Spaces, RTT, and Loss State Machines

8.1 Packet Number Spaces

Space Purpose
Initial handshake bootstrap, discarded once Handshake keys install
Handshake TLS progression, discarded once Application keys confirm
Application steady-state traffic, lives for the connection lifetime

Each space independently tracks: largest_acked, its own send-history slab region, its own loss-detection timer, and its own ACK-range state (I1, I8).

8.2 RTT Model

Core variables: latest_rtt, smoothed_rtt, rttvar, min_rtt, max_ack_delay.

Update sequence (RFC 9002 §5): (1) reject sample if ambiguous retransmission (I3) — (2) compute raw sample from send-time to ACK-receive-time — (3) adjusted_rtt = max(latest_rtt - min(ack_delay, max_ack_delay), min_rtt) — (4) update min_rtt = min(min_rtt, latest_rtt) — (5) rttvar = 3/4·rttvar + 1/4·|smoothed_rtt - adjusted_rtt| — (6) smoothed_rtt = 7/8·smoothed_rtt + 1/8·adjusted_rtt — (7) recompute PTO = smoothed_rtt + max(4·rttvar, kGranularity) + max_ack_delay, kGranularity = 1 ms.

8.3 Loss Detection State Machine

SENT ---ack-eligible frame acked---> ACKED
SENT ---packet or time threshold---> LOST
SENT ---no ACK before PTO fires----> PTO_PENDING
PTO_PENDING ---probe response acked--> ACKED
PTO_PENDING ---still unacked, rearm--> PTO_PENDING

Loss declared on: packet threshold (kPacketThreshold = 3 higher-numbered packets acked), time threshold (kTimeThreshold = 9/8 × max(latest_rtt, smoothed_rtt)), or persistent-congestion detection (I9).

8.4 Congestion States

SLOW_START --loss or ECN CE--> RECOVERY
SLOW_START --cwnd >= ssthresh--> CONGESTION_AVOIDANCE
CONGESTION_AVOIDANCE --loss/CE--> RECOVERY
RECOVERY --one RTT elapsed, no new loss--> CONGESTION_AVOIDANCE
RECOVERY --persistent congestion (I9)--> PERSISTENT_CONGESTION
PERSISTENT_CONGESTION --successful send at min cwnd--> SLOW_START

8.5 ACK Processing Worked Example

Sent packet numbers: 100 101 102 103 104 105. Received ACK ranges: [105-103], [101-100]. Packet 102 is not covered by any range and lies below largest_acked (105) by more than kPacketThreshold's implied gap once packet 105 is acked three-higher — it is an implied loss. Recovery consequences: inflight reduction by bytes_sent(102), a congestion event dispatched to the active CongestionController, and pacing-rate recalculation from the new cwnd (§17, §18).

8.6 Persistent Congestion Duration

RFC 9002's persistent-congestion duration formula: pc_duration = (smoothed_rtt + max(4·rttvar, kGranularity) + max_ack_delay) × kPersistentCongestionThreshold, with kPersistentCongestionThreshold a small integer constant. A run of consecutive PTO-triggered probes spanning at least pc_duration with zero intervening ACKs on that packet-number space triggers I9. Boundary conditions the fixtures in §16.5 and §19.5 must cover:

  • Exactly one probe short of pc_duration — must not trigger.
  • Exactly at pc_duration — must trigger.
  • The window spanning a packet-number-space discard (Initial→Handshake) — must not falsely combine probes from two spaces (I15).
