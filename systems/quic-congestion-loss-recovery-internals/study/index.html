30. Mental Models & First Principles

  • MM1 — ACK Clock. Compressed insight: transmission cadence is derived from ACK arrival, not from a local timer · predicts: bursty ACK arrival (compression) causes bursty sending even with a perfect pacer upstream · bug class without it: blaming the pacer (§18) for a burst actually caused by the network path compressing ACKs · applies in §14 and §18.
  • MM2 — Bandwidth-Delay Product. Compressed insight: the amount of data "in the pipe" at full utilization is rate × RTT · predicts: a token bucket sized for low-RTT paths starves high-RTT paths · bug class without it: under-provisioning pacing-token capacity for the §4 600 ms RTT ceiling · applies in §18 and §32.
  • MM3 — Retransmission Ambiguity. Compressed insight: an ACK for a retransmitted packet cannot tell you which transmission it acknowledges · predicts: naive RTT sampling on retransmissions systematically biases the estimate · bug class without it: RTT/PTO instability traced to "network jitter" that is actually a sampling bug · applies in §15 and §7.
  • MM4 — Fail-Closed Beats Best-Effort at Scale. Compressed insight: at 250k connections, a rare silent-corruption bug multiplies into an unattributable fleet-wide incident · predicts: fail-open designs accumulate corrupted state invisibly until a much larger failure surfaces · bug class without it: "the system recovered on its own" masking an accounting bug that will resurface under load · applies in §7 and §23.
  • MM5 — Congestion Signals Are Probabilistic, Not Certain. Compressed insight: loss, ECN CE marks, and delay are all noisy proxies for congestion, never direct measurements of it · predicts: treating any single signal as authoritative overreacts to noise · bug class without it: ECN promoted to authoritative (rejected in §11/P13) causing false congestion collapse · applies in §17 and §19.
  • MM6 — Determinism Is a Design Constraint, Not a Testing Nicety. Compressed insight: replayability must be designed into the data model (§11), not bolted on via logging · predicts: any wall-clock read or unordered iteration silently breaks replay months later · bug class without it: "flaky" simulation failures that are actually real nondeterminism bugs · applies in §12 and §20.
  • MM7 — Backpressure Must Be Structural. Compressed insight: a system that can be told "no" at every layer cannot collapse from one misbehaving input source · predicts: any layer that queues without a bound becomes the next incident's root cause · bug class without it: an unbounded retransmission queue absorbing a burst until it OOMs · applies in §6 and §29.
  • MM8 — Loss and Delay Are Different Failure Signals. Compressed insight: a packet-threshold loss (reordering) and a time-threshold loss (real congestion or a dropped packet) demand different responses even though both end in the same Lost state · predicts: collapsing the two into one code path loses the information needed to tune reordering tolerance independently of RTT-based timeout tolerance · bug class without it: a fix for spurious loss under reordering accidentally weakens genuine-congestion responsiveness · applies in §16.
  • MM9 — Telemetry Cardinality Is a Capacity Dimension. Compressed insight: an unbounded label (e.g. per-packet or per-connection granularity) turns a metrics system into the next bottleneck, independent of the transport logic being measured · predicts: a dashboard that looks fine in a 100-connection test environment can take down the telemetry pipeline at the §4 250k-connection ceiling · bug class without it: shipping a well-intentioned new metric that silently becomes T9 · applies in §24 and §29.
  • MM10 — A Deferred Feature Is a Design Decision, Not a TODO. Compressed insight: deferring BBR/multipath/hardware pacing (§35) with an explicit un-defer trigger forces the current design to be complete and correct without them, rather than half-built around a feature that never lands · predicts: a codebase with silent TODOs instead of registered deferrals accumulates dead partial implementations · bug class without it: a half-wired BBR code path that neither works nor is removed · applies in §35 and §9.

5. Required Reading

Books

  • TCP/IP Illustrated, Volume 1 — Stevens (1994), ch. 21 (TCP Timeout and Retransmission): retransmission ambiguity and Karn's algorithm; applied in §14 and §15.
  • Computer Networks — Tanenbaum & Wetherall (2010), ch. 6 (The Transport Layer): congestion-control fairness models; applied in §17.
  • Understanding Linux Network Internals — Benvenuti (2005), ch. 24–25 (socket buffers, packet queues): kernel-side queueing context for batched syscalls; applied in §12.
  • Systems Performance — Gregg (2020), ch. 6 and 10 (CPUs, Networking): flamegraph-driven latency triage methodology; applied in §28.
  • Designing Data-Intensive Applications — Kleppmann (2017), ch. 11 (Stream Processing): log-based replayability and determinism; applied in §20 and §21.
  • Computer Networking: A Top-Down Approach — Kurose & Ross (2020), ch. 3 (Transport Layer): sliding-window and ACK-clocking intuition; applied in §14.

Papers

  • "QUIC Loss Detection and Congestion Control" — Iyengar & Swett, 2021, RFC 9002: normative recovery behavior specified directly as an implementation contract; applied in §16.
  • "BBR: Congestion-Based Congestion Control" — Cardwell et al., 2016, ACM Queue: delivery-rate estimation → bandwidth-estimator interface shape; applied in §17.
  • "CUBIC: A New TCP-Friendly High-Speed TCP Variant" — Ha, Rhee, Xu, 2008, ACM SIGOPS Operating Systems Review: nonlinear cwnd growth function → CUBIC module design; applied in §17.
  • "The Tail at Scale" — Dean & Barroso, 2013, CACM: tail-latency amplification under fan-out → p99 ACK-processing budget; applied in §4 and §28.
  • "Congestion Avoidance and Control" — Jacobson, 1988, SIGCOMM: AIMD foundation → Reno module and slow-start exit; applied in §17.
  • "Random Early Detection Gateways for Congestion Avoidance" — Floyd & Jacobson, 1993, IEEE/ACM ToN: queue-based congestion signaling → ECN validation design; applied in §19.
  • "An Argument for Increasing TCP's Initial Congestion Window" — Chu, Dukkipati, Cheng, Mathis, 2013, Google/IETF: initial-cwnd sizing tradeoffs → slow-start entry constants; applied in §17.
  • "A Comparison of Mechanisms for Improving TCP Performance over Wireless Links" — Balakrishnan, Padmanabhan, Seshan, Katz, 1996, SIGCOMM: retransmission ambiguity under lossy links → RTT-sample-validity invariant; applied in §14 and §7.
  • "Sizing Router Buffers" — Appenzeller, Keslassy, McKeown, 2004, SIGCOMM: bottleneck-buffer sizing relative to bandwidth-delay product → pacing burst-limiter sizing rationale; applied in §18.

Reference Implementations

  • quiche — study quiche/src/recovery/ and quiche/src/congestion/: practical pacing and packet-metadata handling; pitfall: do not copy its monolithic recovery struct wholesale, this blueprint splits it across crates; applied in §18.
  • quic-go — study internal/congestion/: RTT accounting and ACK-processing structure; pitfall: its RTT sampler couples ACK-delay correction to an internal clock type not portable here; applied in §14 and §15.
  • lsquic — study src/liblsquic/lsquic_senhist.c: send-history bitmask optimization; pitfall: bitmask sizing assumes bounded reordering, revalidate against the §4 32-packet assumption; applied in §13.
  • ngtcp2 — study lib/ngtcp2_rtb.c: retransmission-buffer bookkeeping; pitfall: does not separate packet-number spaces as cleanly as required here, keep the §13 separation; applied in §13.
  • msquic — study src/core/congestion_control.c and bbr.c: pluggable congestion-control vtable pattern; pitfall: its BBR constants are production-tuned, re-derive from Cardwell et al. rather than porting blind; applied in §17.

RFCs / Specifications

  • RFC 9000 §13 — packet-number-space and ACK-frame wire semantics; applied in §13.
  • RFC 9002 — normative loss-detection thresholds (kPacketThreshold=3, kTimeThreshold=9/8), PTO formula, persistent congestion; applied in §16.
  • RFC 8312 — CUBIC window-growth function and fast-convergence behavior; applied in §17.
  • RFC 3168 — ECN codepoints and validation requirements; applied in §19.
  • RFC 8899 — PLPMTUD interaction with loss recovery and probe packets; applied in §12.
  • RFC 6937 — Proportional Rate Reduction informing recovery-phase cwnd reduction; applied in §17.
  • RFC 8085 — UDP usage guidelines and congestion-control obligations for UDP-based protocols; applied in §17.
  • RFC 9221 — QUIC unreliable-datagram extension boundary, motivating this subsystem's scope exclusion; applied in §1.
  • RFC 8888 — RTP/media congestion-control feedback, cross-referenced for delivery-rate-feedback design patterns; applied in §17.

Glossary (§36) · 58 terms · site-wide glossary

ACK Clock
transmission cadence derived from ACK arrival rather than a local timer (MM1).
PTO
probe timeout; the deadline after which an unacknowledged ack-eliciting packet triggers a probe.
cwnd
congestion window; the byte budget of data allowed inflight.
ECN
explicit congestion notification; IP-layer congestion signaling (RFC 3168).
Inflight
bytes sent but not yet acknowledged or declared lost.
Pacing
rate-controlled transmission spreading a cwnd's worth of sends across time.
RTT
round-trip time; send-to-ACK latency.
rttvar
RTT variance estimator, smoothed exponentially (§15).
Persistent congestion
sustained network collapse detected via consecutive PTO failures (I9).
Spurious loss
a packet incorrectly declared lost that was, in fact, delivered.
Recovery epoch
one congestion-recovery interval bounded by entry into and exit from the Recovery state.
Packet threshold
reordering-based loss heuristic (kPacketThreshold = 3, RFC 9002).
Time threshold
RTT-based loss heuristic (kTimeThreshold = 9/8, RFC 9002).
Tail loss
loss of the last packet(s) in a burst, typically requiring a PTO probe rather than threshold detection.
ACK compression
bursty ACK arrival caused by network-path buffering, distorting perceived cwnd headroom.
GSO
generic segmentation offload; kernel-assisted batching of outbound UDP datagrams.
GRO
generic receive offload; kernel-assisted coalescing of inbound UDP datagrams.
Replay log
the durable, sequence-continuous stream of ReplayEvents (§11) enabling deterministic re-execution.
Pacing debt
the delayed transmission budget accrued when tokens are unspent past their ideal release time.
Transport epoch
a monotonic per-connection timeline used to correlate telemetry across recovery-state transitions.
Slow start
the initial CongestionState in which cwnd grows exponentially until ssthresh.
Congestion avoidance
the steady-state CongestionState with additive (Reno) or cubic (CUBIC) cwnd growth.
Recovery (state)
the CongestionState entered on loss/CE detection, exited after one clean RTT.
min_rtt
the lowest RTT sample observed over the connection's lifetime, used for ACK-delay correction bounds.
smoothed_rtt
the exponentially smoothed RTT estimate (RFC 9002 §5 formula).
max_ack_delay
the transport-parameter-negotiated ceiling on peer-reported ACK delay.
Token bucket
the pacing primitive holding a capped balance of send-eligible bytes, refilled at pacing_rate().
Burst limiter
the cap on token-bucket capacity preventing large instantaneous sends.
Packet number space
one of {Initial, Handshake, Application}, each with independent packet-number and loss-timer state.
Send history
the per-connection record of sent, unacknowledged packets and their metadata.
Slab arena
a fixed-slot allocator used for SentPacket storage, chosen for cache locality (ADR-27).
DeliveryState
the exhaustive per-packet state enum {Sent, Acked, Lost, PtoPending} (I14).
AckRange
a decoded, validated [start, end] inclusive range of acknowledged packet numbers.
CongestionController
the pluggable trait implemented by Reno, CUBIC, and (deferred) BBR.
RttEstimator
the trait owning RTT sampling, smoothing, and PTO-base computation.
CE mark
a Congestion Experienced ECN codepoint observed on a received packet.
ECN validation
the state machine confirming a path's ECN marking is trustworthy before acting on it.
Path degradation
a sustained shift in loss/RTT/ECN behavior attributable to the network path rather than a transient blip.
Timer wheel
the hierarchical, bucketed-by-deadline structure scheduling PTO and pacing wakeups (ADR-23).
Replay determinism
the property that identical inputs and seed produce byte-identical replay-log output (P1).
Fixed seed
the deterministic random-number seed driving quic-sim fault injection.
Conformance vector
a named fixture encoding an RFC 9002 expected input/output pair.
Bandwidth-delay product (BDP)
the data volume "in flight" at full path utilization, rate × RTT (MM2).
ACK eliciting
a packet whose receipt obligates the peer to send an ACK within a bounded delay.
Idle restart
resumption of sending after a silence period exceeding one RTT, requiring cwnd/pacing re-derivation.
kInitialRtt
the RFC 9002 bootstrap RTT value (333 ms) used before any real sample exists.
kGranularity
the RFC 9002 timer-granularity constant (1 ms) added to the PTO computation.
ssthresh
slow-start threshold; the cwnd value at which growth switches from exponential to additive/cubic.
AIMD
additive-increase/multiplicative-decrease; Reno's core growth/backoff discipline (Jacobson 1988).
Fast convergence
CUBIC's mechanism for accelerating cwnd reduction when a flow's own W_max recently decreased.
Hybrid Slow Start
a slow-start-exit heuristic using delay increase as an early signal; out of scope for CUBIC v1 (§17).
Delivery rate
bytes delivered divided by the time interval over which they were delivered; BBR's core signal (Cardwell et al. 2016).
App-limited
a sending period where the application, not the network, is the throughput bottleneck; must be excluded from bandwidth samples.
W_max
CUBIC's remembered pre-reduction window size, anchoring the cubic growth curve's inflection point.
NUMA
non-uniform memory access; cross-socket memory latency that motivates §4's NUMA-aware socket-placement recommendation.
Shard
a partition of connections assigned to one worker thread for lock-free, single-writer processing (ADR-08).
OTLP
OpenTelemetry Protocol; the span-export format chosen in ADR-10.
SBOM
software bill of materials; the per-release dependency manifest required by §27.
