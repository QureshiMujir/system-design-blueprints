3. Architectural Overview

                     +-------------------+
                     |  osv.dev / GHSA   |
                     +---------+---------+
                               | poll (advisories)
                               v
                     +-------------------+        +----------------+
                     | Advisory Ingester |------->|  Event Store   |
                     +---------+---------+        +--------+-------+
                               | Advisory                   ^
                               v                             | append-only
                     +-------------------+                   |
                     | Dependency-Graph  |-------------------+
                     |     Builder       |
                     +---------+---------+
                               | DependencyGraph
                               v
                     +-------------------+
                     | Risk Prioritizer  |
                     +---------+---------+
                               | RiskScore + Advisory
                               v
                     +-------------------+
                     |    Fix Planner    |
                     +---------+---------+

                               v
                     +-------------------+

                     +---------+---------+
                               | PatchSet
                               v
      +----------------------------------------------+
      |   Sandboxed Validator (build + test runner)   |
      |  gVisor container: apply patch, build, test   |
      +----------------------+-------------------------+
                               | ValidationRun (pass/fail)
                               v
                     +-------------------+
                     | Justification Gen |
                     +---------+---------+
                               | Justification (signed)
                               v
                     +-------------------+       +----------------+
                     |    PR Emitter     |------>| Forge Adapter  |---> GitHub
                     +-------------------+       +----------------+
                               |
                               v
                     +-------------------+
                     |     Telemetry     |  <- all boxes emit metrics/traces
                     +-------------------+

Advisory ingester — polls osv.dev and GitHub Security Advisories on a bounded schedule, normalizes payloads into the internal Advisory schema, deduplicates by (advisory ID, ecosystem, repo SHA), and appends a Detected event to the event store. It is the only component with outbound network access to public advisory feeds.

Dependency-graph builder — parses the repo's lockfile at the SHA under evaluation into a DependencyNode graph (direct and transitive edges), joins it against incoming advisories to find affected nodes, and emits a DependencyGraph keyed to (repo, SHA).

Risk prioritizer — scores each (advisory, affected node) pair using CVSS v3.1 base metrics plus graph position (direct vs transitive), producing a RiskScore that orders the fix queue.

Fix planner — given a prioritized advisory and the dependency graph, computes a FixPlan: the minimal semver-compatible version bump satisfying the advisory's fixed-in range, or a PhaseDeferred marker if no such bump exists.

Patch applier — materializes the FixPlan into a concrete PatchSet (lockfile and manifest diff), never touching working-tree state outside a scratch checkout.

Sandboxed validator (build + test runner) — spawns a gVisor-backed OCI container per validation, applies the PatchSet to a disposable checkout, runs the repo's declared build and test command, and enforces CPU, memory, and wall-clock ceilings; it has no network egress and no access to forge credentials.

Justification generator — assembles a Justification document binding advisory ID, repo SHA, patch diff hash, and ValidationRun ID, signs it via Sigstore keyless signing, and stores the attestation alongside the event.

PR emitter — turns an accepted FixPlan plus its Justification into a PullRequestDraft and hands it to the forge adapter.

Forge adapter — the only component holding forge credentials; translates a PullRequestDraft into forge-specific API calls (GitHub REST/GraphQL in Phase 0), isolating the rest of the system from forge-specific detail.

Event store — an append-only log of every EventRecord (Detected, Planned, Patched, Validating, Justified, Proposed, Merged, Abandoned) keyed by (repo, SHA, advisory ID); the single source of truth for idempotency and audit.

Telemetry — collects metrics, traces, and structured logs from every component via OpenTelemetry, feeding the dashboards and alerts described in Performance Engineering.

8. Domain Model

Advisory (OSV-shaped). Fields: id (string, e.g. GHSA-xxxx or OSV-2024-xxxx), ecosystem (enum: npm, PyPI, ...), package (string), affected (list of AffectedRange), severity (CVSS v3.1 vector string), summary, references (list of URL), withdrawn (nullable timestamp), modified (timestamp). AffectedRange: introduced (version), fixed (nullable version), last_affected (nullable version), events (ordered list mirroring the OSV ranges[].events structure).

Dependency-graph model. DependencyNode: name, ecosystem, resolved_version, requested_range, depth (0 = direct), parents (list of node IDs), children (list of node IDs). The graph is a DAG keyed by (repo, SHA); cycles are rejected at build time as a malformed-manifest condition.

Fix-plan IR. FixPlan: advisory_id, target_node, from_version, to_version, strategy (enum: SemverBump, SourcePatch [Phase 7], Backport [Phase 7]), planner_version, constraint_check (proof that to_version satisfies both the advisory's fixed-in range and the repo's declared semver range).

Patch/diff representation. PatchSet: files (list of unified-diff hunks), base_sha, diff_hash (content hash of the concatenated unified diff), manifest_ deltas (structured before/after version pairs, redundant with the diff for fast-path verification).

Justification format. Fields: advisory_id, repo_sha, patch_diff_hash, validation_run_id, planner_version, risk_score, issued_at, signature (Sigstore bundle), verification_steps (ordered list: recompute diff hash, recheck CVSS vector against advisory, re-verify signature against Rekor transparency log). A verifier consumes only these fields — no prose is authoritative.

Forge/PR contract. PullRequestDraft: repo, base_branch, head_branch (named deterministically from advisory ID + repo SHA), title, body_summary (human-readable, generated from Justification, never authoritative), justification_ ref (attached artifact), labels. The forge adapter guarantees idempotent PR creation: re-submitting an identical draft for the same (repo, SHA, advisory ID) is a no-op if an open PR already exists.

Worked end-to-end example. Advisory GHSA-example-1234 (npm, package left-pad, affected <1.3.0, fixed 1.3.0) is detected for repo acme/web at SHA abc123. Graph join finds left-pad@1.2.0 at depth 2 (transitive). Planner computes FixPlan{from: 1.2.0, to: 1.3.0, strategy: SemverBump}. Patch applier produces a PatchSet touching package-lock.json. Sandbox validator applies the patch, runs npm test, exits 0 in 4m12s. Justifier signs a Justification binding all four IDs. PR emitter opens acme/web#4821 titled "Bump left-pad to 1.3.0 (fixes GHSA-example-1234)".

Malformed-advisory example. An OSV record missing affected[].events entirely (no introduced and no fixed) fails schema validation at ingest; the ingester emits Detected with a malformed: true flag and routes to Abandoned (MalformedAdvisory) without ever reaching graph join — see fixture fixtures/advisories/malformed_missing_events.json (§12, Phase 0).

Malformed-manifest example. A package-lock.json with a dependency cycle (package A requires B requires A at identical resolved versions with no version-based tie-break) fails graph construction; the builder emits GraphBuildFailed and the advisory is routed to Abandoned (MalformedManifest) — see fixture fixtures/manifests/cyclic_lockfile.json (§13, Phase 1).

Failure-path example. A validation run exceeds the 15-minute test-suite budget (§4) due to a genuinely slow but passing test suite (not a hang); Timeout fires at 20 minutes wall-clock, the run is marked Abandoned (ValidationTimeout), and a distinct telemetry counter (sandbox.timeout.slow_suite_suspect) is incremented separately from a hang-suspect counter, disambiguated by CPU-utilization trace during the run (§15, Phase 3, Pitfalls).
