Objectives

Cargo workspace compiles; cargo test --all passes; CI green; smoke test returns Verdict::Hold.

  • cargo clippy --all -- -D warnings zero warnings.

  • Smoke: Verdict::Hold on stub latency experiment.

⬜ Phase 3 — chaos-target: Selectors, Blast Radius, Sampling, Dry-Run §15

Objectives
  • Label-based selection against TargetRegistry.
  • BlastRadiusEnforcer caps by count AND percent before injection.
  • Deterministic sampling (seed-stable).
  • Dry-run returns exact plan without calling injector.
Deliverable

BlastRadiusEnforcer tested with 500-target list; dry-run matches enforce output.

Acceptance
  • 500 targets, max_percent=10 → 50; max_targets=30 → 30 (min wins).
  • Excluded targets never appear in enforced set.
  • Dry-run = identical target list as enforce would produce; no apply called.
  • Same seed + targets = same sample (deterministic).
  • max_targets=0 → BlastRadiusError::TooRestrictive.
Fixtures
  • conformance/blast_radius.rs: 10 parametrized cases (percent cap, count cap, exclusion, scope, zero result).
  • Fuzz: fuzz_blast_radius.rs → never panics.
Pitfalls
  • max_percent ceiling: (total as f64 × percent / 100.0).ceil() as usize.
  • f32 precision at boundary: test 33.33% of 10 → ceil(3.333) = 4.
  • Empty selector matches ALL targets — document.
  • HttpTargetRegistry: TTL cache; never block enforcement on slow fetch.

⬜ Phase 4 — chaos-fault Network: Latency/Loss/Partition/Bandwidth/Corrupt/Reorder §16

Objectives
  • NetworkFaultInjector for all 7 network fault types via tc/netem (netlink) + iptables/nftables.
  • Idempotent apply (REPLACE semantics) and revert (existence check before delete).
  • Apply latency p95 < 100 ms.
  • All tested in Linux network namespace (no host side-effects in CI).
Deliverable

All 7 network faults apply + revert in netns; idempotent; apply latency < 100 ms.

Acceptance
  • apply(NetworkLatency{ms:100}) → tc qdisc show shows netem delay 100ms.
  • revert(handle) → qdisc absent; second revert → RevertNoOp.
  • Partition → DROP rules present; revert → absent.
  • Bandwidth → TBF qdisc present; revert → absent.
  • Apply latency p95 < 100 ms (criterion bench).
Fixtures
  • Latency experiment in netns: verify HTTP probe latency increases by ~100 ms.
  • Property test: random NetworkLatency { ms: 1..=10000 } → apply+revert never panics.
Pitfalls
  • tc qdisc add NOT idempotent (EEXIST): use NLM_F_REPLACE.
  • Stacking netem + TBF: netem inner, TBF outer; apply order matters.
  • Partition on loopback: loopback has no separate in/out; use veth pair in tests.
  • iptables -D requires exact rule string; store at apply time.
  • iptables vs nftables: detect active backend at agent startup.

⬜ Phase 5 — chaos-fault Resource + Process: CPU/Mem/IO/Fork, Kill/Stop/Signal §17

Objectives
  • ResourceFaultInjector: cgroup v2 + worker threads for CPU, mem, IO, fork pressure.
  • ProcessFaultInjector: SIGSTOP/SIGCONT + arbitrary signal delivery via nix.
  • All revert idempotently; no cgroup leaks after revert.
  • Agent RSS < 64 MB with 5 concurrent resource faults active.
Deliverable

CPU/mem/IO/fork stress + process kill/stop apply + revert; cgroup cleanup verified; soak shows no leaks.

Acceptance
  • CpuStress{workers:2, load_percent:80}: ~80% CPU; revert → baseline.
  • MemStress{bytes:512MB}: free shows 512 MB less; revert → restored.
  • ProcessStop: state T; after revert state S/R.
  • Cgroup leak check: empty after revert.
  • Agent RSS < 64 MB with 5 concurrent resource faults.
Fixtures
  • Soak: 100 inject/revert cycles CpuStress; no cgroup leak; RSS < 64 MB.
  • ProcessStop + ProcessKill integration: spawn dummy process; apply + revert; assert state.
Pitfalls
  • cgroup v2: create under agent-controlled slice, not root cgroup.
  • CgroupHandle::remove(): kill members first — rmdir on non-empty fails.
  • mlock needs CAP_IPC_LOCK or ulimit -l unlimited.
  • ProcSelector by name: /proc/<pid>/comm ≤ 15 chars; use cmdline for full match.

⬜ Phase 6 — chaos-fault Application + Clock: HTTP/gRPC Proxy, Clock Skew §18

Objectives
  • AppFaultInjector: HTTP fault proxy (abort/delay/error%) + gRPC fault filter.
  • ClockSkewFaultInjector: clock_adjtime(2) offset + drift; idempotent revert.
  • FsFaultInjector: FUSE overlay (stretch; skip if /dev/fuse absent).
Deliverable

HTTP abort/delay verified; clock skew applied + reverted; gRPC filter wired.

Acceptance
  • HttpFault{abort:503, fault_percent:100}: all requests 503; revert → 200.
  • HttpFault{delay:200ms, fault_percent:50}: ~50% requests ≥200 ms.
  • ClockSkew{offset_ms:500}: clock ~500 ms ahead; revert → < 5 ms of NTP.
  • GrpcFault{status:Unavailable, fault_percent:100}: all gRPC → UNAVAILABLE.
Fixtures
  • Combined network latency + HTTP abort experiment: both faults active simultaneously; both reverted cleanly.
  • Clock skew test: --test-threads=1 (clock is process-global).
Pitfalls
  • clock_adjtime offset unit: microseconds (not ms) when ADJ_NANO not set.
  • FUSE in container: --cap-add SYS_ADMIN + --device /dev/fuse required.
  • HTTP proxy iptables REDIRECT: scope to specific dest IP+port; avoid broad redirect.
  • Envoy xDS propagation: eventual-consistent (~100–500 ms); test must wait for propagation.

⬜ Phase 7 — chaos-agent: Privileged Daemon, Signed Directives, Dead-Man's Switch §19

Objectives
  • chaos-agent binary: production-ready privileged daemon.
  • JWT-signed FaultDirective protocol: validate before any apply.
  • TTL watchdog + dead-man's-switch auto-revert (survives controller death).
  • Idempotent apply_directive + clear_handle; clear_all() on dead-man trigger.
  • AgentFaultState machine persisted to local file for postmortem.
Deliverable

Agent daemon: JWT-validated directives, TTL watchdog, dead-man's switch fires within 2 s of heartbeat loss.

Acceptance
  • ApplyFault with invalid JWT signature → rejected; no fault applied.
  • ApplyFault + stop heartbeat for 2× interval → clear_all() fires; all handles in state = Cleared.
  • TTL expiry: handle with ttl=5s → TtlWatchdog fires revert within 5.5 s.
  • Idempotent clear_handle: second call → RevertNoOp, no error.
  • state.json persisted after every transition; readable after agent restart.
  • Agent RSS < 64 MB with 10 active handles.
Fixtures
  • Chaos-on-chaos fixture (Phase 12): kill agent mid-experiment → dead-man fires; restart orchestrator → status query shows handles cleared.
  • JWT tamper test: flip one byte in signature → AgentError::InvalidSignature.
Pitfalls
  • JWT exp claim: clock skew between controller and agent (ironic) — allow ±30 s leeway.
  • state.json atomic write: use tempfile + rename — avoid partial writes on agent crash.
  • gRPC stream teardown: ensure HeartbeatWatchdog resets on any heartbeat RPC, not just successful ones.
  • clear_all() must be async-safe: called from watchdog task; don't block on slow reverts — spawn per-handle revert tasks.

⬜ Phase 8 — chaos-orchestrator: Full Run Loop + Method Sequencing + Abort Path §20

Objectives
  • ExperimentRunner drives the complete state machine: validate→before→inject→monitor→rollback→after→verdict.
  • MethodExecutor sequences Actions (Inject/Probe/Pause/Rollback) serially.
  • ContinuousMonitor runs concurrently during Running/Monitoring states.
  • Abort path: on deviation or kill-switch → revert all handles in reverse order → AfterSteadyState.
  • Report emitted with full event timeline.
Deliverable

Full orchestrator run loop: end-to-end experiment from YAML file → Report with Verdict::Hold or Verdict::Deviated.

Acceptance
  • Normal run: before Passing → inject → after Passing → Verdict::Hold.
  • Deviation during monitoring: inject → continuous check fails → RollingBack → handles reverted → Verdict::Deviated.
  • Kill-switch engage mid-run: abort triggered; all handles reverted within 2 s.
  • Method with Pause{30s}: abort signal received mid-pause → pause cancelled; rollback starts.
  • Report.timeline contains all events in chronological order.
Fixtures
  • conformance/experiment_semantics.rs: golden-file test — run examples/latency_experiment.yaml; assert Report.verdict = Hold.
  • Deviation golden file: inject partition; probe fails at T+8 s; assert Verdict::Deviated + rollback events.
Pitfalls
  • Abort signal during Pause: tokio::select! on abort_rx + tokio::time::sleep — must cancel sleep.
  • Reverse-order rollback: handles pushed in apply order; revert in reverse (LIFO); critical for nested resource faults.
  • revert_all errors: log + continue; never skip remaining handles due to one revert failure.
  • ExperimentContext shared across tasks: use Arc<Mutex<Vec<FaultHandle>>> for handle list.

⬜ Phase 9 — chaos-safety: Guardrails, Kill Switch, Halt-on-Deviation, Blast Guard §21

Objectives
  • SafetyMonitor with pluggable GuardRail conditions running concurrently.
  • KillSwitch: global engage/disengage; broadcasts halt to all agents.
  • DeadManSwitch (orchestrator-side): heartbeat tracking per agent.
  • Halt-on-deviation: any probe deviation → immediate abort signal.
  • Runtime blast-radius re-check: prevent scope creep during run.
Deliverable

KillSwitch reverts all agents' faults in < 2 s; SafetyMonitor aborts on guardrail trip; halt-on-deviation wired to orchestrator.

Acceptance
  • KillSwitch::engage with 5 active experiments: all abort + all handles reverted within 2 s.
  • MaxDurationGuardRail: experiment exceeding max_duration → aborted automatically.
  • MinAvailableGuardRail: drops below threshold mid-run → abort + rollback.
  • halt_on_deviation = true (default): deviation → immediate abort; false → continue (collect evidence only).
  • Kill switch requires explicit disengage — does not auto-clear.
Fixtures
  • Kill-switch integration test: 3 concurrent experiments; engage kill switch; assert all Verdict::Aborted + all handles cleared.
  • MaxErrorRateGuardRail: inject errors into probe mock → guardrail trips → experiment aborts.
Pitfalls
  • Kill switch broadcast: broadcast::Sender — receivers must be pre-subscribed before engage; late subscribers miss signal. Use watch::Sender instead (holds last value; new subscriber sees current state).
  • Guardrail polling interval vs probe frequency: guardrail check must be faster than experiment duration; default 1 s.
  • abort_tx.send when no receiver: experiment already done; ignore SendError.

⬜ Phase 10 — chaos-schedule + chaos-report: Scheduling, Game Days, Verdicts, Postmortem §22

Objectives
  • Scheduler: cron + one-shot dispatch; game-day campaign sequencing; monkey mode.
  • MaintenanceWindow: block scheduling during excluded windows.
  • ReportAssembler: build Report from events; SQLite persistence.
  • Exporters: JSON, YAML, HTML postmortem.
Deliverable

Cron-scheduled experiments fire correctly; game-day campaign runs sequentially; reports persisted + exported.

Acceptance
  • Cron "*/5 * * * *": experiment fires at each 5-min boundary (mock clock test).
  • Maintenance window: experiment scheduled during window → skipped; fires after window ends.
  • Game day: 3 experiments run with gap; all reports collected in GameDayReport.
  • Monkey mode: random experiment fired; next scheduled after random interval in [min, max].
  • Report → JSON → Report (round-trip serde).
  • HTML postmortem renders without error.
Fixtures
  • examples/game_day_campaign.yaml: run full game day; assert all 3 reports present; no experiment started during window.
  • SQLite: insert 100 reports; list(filter) paginates correctly.
Pitfalls
  • cron scheduler and maintenance windows: cron fires even during window — check window INSIDE the fire callback.
  • GameDayRunner gap: tokio::time::sleep(gap) between experiments — cancellable.
  • MonkeyMode random interval: use ChaCha RNG with deterministic seed for reproducible test sequences.
  • SQLite blocking I/O: use sqlx async runtime with tokio; don't block Tokio thread pool.

  • Structured metrics (Prometheus), distributed tracing (OTel), audit log.
  • Kill-switch surface in API + CLI.

chaosd API + chaos CLI fully functional; metrics scraped by Prometheus; traces in OTel; audit log populated.

Acceptance

  • chaos validate bad_experiment.yaml → non-zero exit + error list.
  • chaos dry-run experiment.yaml → prints DryRunPlan (no faults applied).
  • chaos kill-switch engage --reason "test" → all experiments abort; Prometheus counter incremented.
  • Audit log entry for every mutating API call.
  • /metrics endpoint scraped by Prometheus (docker-compose dev stack).
Fixtures
  • API integration: POST /experiments → GET /experiments/:id/report end-to-end.
  • CLI: assert_cmd tests for run, validate, dry-run, abort.
Pitfalls
  • Axum + tonic on same port: use hyper with tower::steer to route by content-type (application/grpc).
  • CLI streaming status: use SSE or long-poll; avoid blocking single HTTP request for long experiments.
  • Audit log: fsync on each write; never buffer (risk of loss on crash).
  • OTel trace context in gRPC: pass as tracing-opentelemetry context in metadata.

⬜ Phase 12 — Conformance, Chaos-on-Chaos, Fuzz, Soak, Bench §24

Objectives
  • Experiment-semantics conformance suite: golden-file verdict truth tables.
  • Chaos-on-chaos: kill agent mid-experiment → dead-man's switch reverts; partition control plane → no orphaned faults.
  • Fuzz: fault param deserialization, directive parser, tolerance evaluator.
  • Soak: 1000 inject/revert cycles; no fault leakage; no memory growth.
  • Bench: probe throughput, fault apply/revert latency, orchestrator overhead.
Deliverable

Full conformance suite green; chaos-on-chaos scenarios pass; fuzz finds no panics (corpus clean); soak shows zero fault leakage; bench within targets.

Acceptance
  • Conformance: all 20 golden experiments match expected verdict + event-type sequence.
  • Chaos-on-chaos A: agent killed → dead-man fires → handles cleared; no orphaned qdisc/cgroup.
  • Chaos-on-chaos B: control-plane partition → agent reverts in ≤ 2 s; no orphaned faults.
  • Fuzz: after 1 h corpus run, zero panics; sanitizer clean (ASAN + UBSAN).
  • Soak: 1000 cycles; zero cgroup/qdisc leaks; agent RSS < 64 MB.
  • Bench: probe throughput > 100/s; apply p99 < 100 ms; revert p99 < 100 ms.
Fixtures
  • conformance/golden/ directory: 20 YAML experiments + 20 golden Report JSON fixtures.
  • Verdict truth table: 20 rows covering all Verdict variants + edge cases.
  • Blast radius: 15 enforcement cases with expected output.
Pitfalls
  • Chaos-on-chaos test: process kill of agent requires root in CI → use Docker --privileged; isolate in separate test container.
  • Fuzz panic vs error: fuzz harness must distinguish Err (expected) from panic! (bug); only panics fail the harness.
  • Soak test leak detection: check kernel state (qdisc/cgroup) not just process memory; add scripts/verify-invariants.sh hook.
  • Bench regression: set --significance-level 0.05; < 5% regression allowed before CI fails.
