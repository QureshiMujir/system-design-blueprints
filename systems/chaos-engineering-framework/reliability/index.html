7. System Invariants

I-1: Steady-State Precondition

  • Statement: Fault injection NEVER starts if the before-steady-state check fails.
  • Why: Adding chaos to an already-unhealthy system produces invalid results.
  • Enforced: chaos-orchestrator state machine; BeforeSteadyState → Running transition gated on HypothesisResult::Passing.
  • Detection: HypothesisResult::Failing emits Event::SteadyStateFailed { phase: Before }.
  • Telemetry: metric chaos_experiment_aborted_before_injection_total.
  • Recovery: Abort → Verdict::Aborted; no faults issued.
  • Debugging: Report includes full probe results for the before phase.

I-2: Every Active FaultHandle Has a TTL

  • Statement: No FaultHandle exists without a finite ttl: Duration and a RevertSpec.
  • Why: Unbounded fault duration = production incident if controller dies.
  • Enforced: FaultHandle type fields ttl and revert are non-optional; agent watchdog tracks each handle.
  • Detection: Agent TTL watchdog fires at applied_at + ttl; emits Event::TtlExpired.
  • Telemetry: chaos_agent_ttl_expired_total per fault type.
  • Recovery: Agent reverts unconditionally on TTL expiry, regardless of control-plane state.
  • Debugging: chaos status shows TTL remaining per handle.

I-3: Dead-Man's Switch (Cardinal Safety Invariant)

  • Statement: Agent MUST auto-revert all active faults within 2× heartbeat_interval of losing control-plane contact, even if the orchestrator/control-plane is completely dead.
  • Why: Controller crash must not leave production in a degraded state.
  • Enforced: Agent HeartbeatWatchdog task; last-seen timestamp compared against 2 × heartbeat_interval; if exceeded → revert_all_handles().
  • Detection: Event::DeadManSwitchTriggered { reason: HeartbeatLost | TtlExpired }.
  • Telemetry: chaos_agent_dead_man_switch_total; alertable.
  • Recovery: Unconditional idempotent revert of all handles; agent transitions to Isolated state; keeps retrying heartbeat.
  • Debugging: Agent logs full handle list at revert time; persists to local file for postmortem.

I-4: Blast Radius Never Exceeded

  • Statement: Actual targets injected ≤ min(blast_radius.max_targets, ceil(total_eligible × blast_radius.max_percent / 100)), excluding all blast_radius.exclude selectors.
  • Why: Unintended scope = uncontrolled production impact.
  • Enforced: BlastRadiusEnforcer::enforce() called and logged before first FaultInjector::apply(); returns Err if enforcement would be violated.
  • Detection: Event::BlastRadiusEnforced { selected, capped, excluded }.
  • Telemetry: chaos_blast_radius_enforced_total; chaos_blast_radius_cap_applied_total.
  • Recovery: If cap is triggered, proceed with capped list or abort (configurable).
  • Debugging: Dry-run always shows the enforcement result before game day.

I-5: Idempotent Revert Convergence

  • Statement: Calling revert(handle) any number of times converges to "no fault active" without error.
  • Why: Partial rollback, duplicate signals, or retry storms must not leave inconsistent state.
  • Enforced: Each fault-type revert implementation checks current state first (e.g., tc qdisc show before del; cgroup existence check before removal).
  • Detection: Second revert() call emits Event::RevertNoOp { handle_id }, not an error.
  • Telemetry: chaos_revert_noop_total per fault type.
  • Recovery: N/A — idempotency is the recovery.
  • Debugging: Handle state machine tracks applied | reverting | cleared.

I-6: Kill Switch Is Global and Immediate

  • Statement: Engaging KillSwitch broadcasts Halt to all agents; all active FaultHandles reverted; no new experiments start; all in-progress experiments abort.
  • Why: Emergency stop for runaway faults or unexpected production impact.
  • Enforced: chaos-safety maintains KillSwitch state; orchestrator polls it; agents receive broadcast via agent-control channel.
  • Detection: Event::KillSwitchEngaged { operator, reason, timestamp }.
  • Telemetry: chaos_kill_switch_engaged_total; chaos_kill_switch_pending_reverts.
  • Recovery: Kill switch must be manually disengaged (chaos kill-switch disengage).
  • Debugging: All experiments blocked until disengaged; audit log records engagement.

I-7: Verdict Is Deterministic

  • Statement: Verdict::Hold iff before=Passing AND all_during_intervals=Passing AND after=Passing; Deviated iff any-during fails; Aborted iff experiment was halted before completion; Error iff infrastructure failure.
  • Why: Automated pipelines depend on unambiguous pass/fail signal.
  • Enforced: Verdict::compute(before, during, after, abort_reason) pure function in chaos-model.
  • Detection: Wrong verdict = bug in compute(); covered by property-based tests.
  • Telemetry: chaos_verdict_total{result} counter.

I-8: No Fault Applied Without Successful Before-Check

  • Statement: Reinforces I-1 at the type level: inject_method() is only callable from the Running state, reachable only after BeforeSteadyState → Passing.
  • Enforced: State machine enum ExperimentState — inject_method takes Running not BeforeSteadyState.

I-9: Signed-Directive Gate

  • Statement: No Fault reaches a FaultInjector on the agent without a FaultDirective whose JWT signature and claims (handle_id, fault type, exp, jti) validate first.
  • Why: an agent that applies unsigned or tampered directives is an open injection point for any client on the gRPC port.
  • Enforced: directive.rs::validate_signature runs before LocalFaultExecutor::apply_directive is ever called; failure short-circuits with no side effect.
  • Detection: AgentError::InvalidSignature returned to caller; no FaultHandle created.
  • Telemetry: chaos_agent_directive_rejected_total{reason}.
  • Recovery: N/A — rejection is terminal for that directive; caller must resubmit with a valid signature.
  • Debugging: audit log correlates the rejected jti/claims with the originating gRPC peer for forensic review (Threat Model: forged directive replay).

I-10: Dry-Run/Enforce Equivalence

  • Statement: dry_run_plan(targets, br) and enforce(targets, br) compute target selection through the identical BlastRadiusEnforcer core; for the same (targets, br) input they return the same selected/excluded/capped result.
  • Why: operators sign off on a dry-run plan before a game day; if the real run could select a different set, the sign-off protects nothing.
  • Enforced: both entry points delegate to one internal selection function (Phase 3, §15); no separate code path exists for "preview" selection.
  • Detection: property test (§15, 3.7) asserts equality of dry_run_plan and enforce output across randomized (targets, br) pairs.
  • Telemetry: chaos_dry_run_mismatch_total (should remain zero for the life of the project; any nonzero value is a release blocker).
  • Recovery: N/A at runtime — this is a build-time correctness property verified in CI, not something to recover from in production.
  • Debugging: a mismatch report includes the full DryRunPlan and EnforcedTargets diff for root-cause.

I-11: Capability Minimality

  • Statement: The agent process never holds a Linux capability that no configured fault type requires; capabilities are the union of only the fault families enabled on that host.
  • Why: a blanket-root or blanket-capability agent turns one memory-safety bug into full host compromise (Threat Model: privilege escalation via agent).
  • Enforced: install-agent.sh sets capabilities via setcap from the enabled fault-family list (Phase 7, §19), never cap_full/root.
  • Detection: agent startup logs its granted capability set; CI asserts it is a subset of the enabled-fault-family requirement map.
  • Telemetry: chaos_agent_capability_set (label per capability, exported at startup).
  • Recovery: if a fault requiring an ungranted capability is dispatched, apply fails fast with a capability error rather than silently escalating.
  • Debugging: chaos-agent GetStatus RPC reports the live capability set for operator audit.

I-12: Audit-Log Completeness

  • Statement: Every mutating API call (submit, abort, kill-switch engage/disengage) produces exactly one append-only audit record before the call returns success.
  • Why: non-repudiation of who ran or stopped what is a compliance requirement for a tool with production blast radius, not an optional log line.
  • Enforced: chaos-api::audit.rs wraps every mutating route handler; the response is only sent after the audit write completes (fsync, Pitfall 11.6).
  • Detection: a mutating call that returns success with no matching audit entry is a CI-caught regression (audit/response-count parity test).
  • Telemetry: chaos_audit_write_total vs chaos_api_mutating_requests_total — the two counters must stay equal.
  • Recovery: on audit-write failure, the API call itself fails (5xx) rather than proceeding without a record (Failure Analysis 11.9: "Audit log disk full").
  • Debugging: audit log is JSON lines; operator, action, experiment_id, result, at fields make every mutation traceable end-to-end.
