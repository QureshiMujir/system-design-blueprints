⬜ Phase 1 — Core numeric substrate + RNG + errors §12

Objectives

Lock float64 policy, the Rng abstraction with spawnable independent streams, log-space primitives (logsumexp, log1mexp), from-scratch special functions (gammaln, betaln, erf, digamma), finite-guards, and the typed error hierarchy. Everything stochastic and numerically delicate funnels through here.

Deliverable

Importable ppl.core; python -c "from ppl.core import logsumexp, Rng" works; special functions match NumPy/known values to 1e-12.

Acceptance
  • logsumexp matches naive computation for moderate inputs, no overflow for inputs up to ±700.
  • gammaln/erf within 1e-10 of reference table values.
  • Rng.spawn(4) yields 4 streams with no detectable cross-correlation on 10⁶ draws.
  • mypy --strict ppl/core clean; pytest tests/core green.
Fixtures
Fixture Purpose Expected
core/logsumexp_extreme.json overflow safety finite for [1e3,1e3,1e3]
core/special_values.json gammaln/erf/digamma reference to 1e-10
core/rng_independence.json stream independence |corr| < 3e-3
Pitfalls
  • logsumexp over an all--inf slice → NaN; guard returns -inf.
  • Lanczos gammaln loses precision near poles (non-positive ints); document domain.
  • Reusing one Generator across processes (fork) duplicates streams — always spawn.

⬜ Phase 2 — Reverse-mode autodiff engine §13

Objectives

Build a dynamic-tape reverse-mode AD that differentiates exactly the operations used in log-densities, exposing grad / value_and_grad, validated by central finite differences (I4). This is the single source of truth for grad_U (P6).

Deliverable

value_and_grad(f)(x) returns correct (value, grad) for composite functions of the registered ops; grad_check passes on a battery.

Acceptance
  • grad_check passes (rtol 1e-5) for: quadratic, log-Gaussian density, logistic NLL, softmax cross-entropy, MvNormal log_prob.
  • Reverse pass cost ≤ 3× forward eval on a 1000-dim log-density.
  • No memory growth across repeated value_and_grad (tape released).
Fixtures
Fixture Purpose Expected
ad/gradcheck_suite.json analytic grads match central diff 1e-5
ad/broadcast_cases.json broadcast vjp correct shapes/sums
ad/tape_release.json no leak RSS stable over 10⁴ calls
Pitfalls
  • Broadcasting in mul/add requires summing the adjoint over broadcasted axes; forgetting yields wrong-shaped grads.
  • In-place NumPy mutation of a node's value corrupts the tape; ops must be pure.
  • log/sqrt at 0 → inf grad; rely on support transforms (P4) to keep args positive.

⬜ Phase 3 — Distribution library §14

Objectives

Implement distributions with differentiable log-space log_prob, RNG sample, declared support, batch/event shapes, and a conjugacy registry for Gibbs. These are the building blocks of every model.

Deliverable

All listed distributions: log_prob differentiable, sample shaped correctly, support enforced; conjugate updates available.

Acceptance
  • log_prob integrates/sums to 1 numerically (grid for continuous, exact for discrete) within 1e-4.
  • Sample moments match analytic mean/var within 3·MCSE over 10⁶ draws.
  • grad_check passes on every continuous log_prob wrt params and value.
  • SupportError raised on out-of-support log_prob value where defined (I10).
Fixtures
Fixture Purpose Expected
dist/normalization.json ∫/Σ log_prob 1.0 ± 1e-4
dist/moments.json sample moments analytic ± 3 MCSE
dist/logprob_gradcheck.json param grads match 1e-5
dist/conjugate_updates.json Gibbs conditionals closed-form match
Pitfalls
  • Beta/Gamma log_prob needs stable gammaln/betaln; naive log(gamma()) overflows.
  • Categorical from logits must subtract logsumexp (P5); from probs must validate simplex.
  • Gamma sampler (Marsaglia-Tsang) needs the squeeze step or rejection rate balloons for small shape.

⬜ Phase 4 — Constraint transforms (bijectors) §15

Objectives

Implement bijectors mapping constrained supports to unconstrained ℝⁿ with correct log_abs_det_jacobian, enabling gradient sampling on ℝⁿ (P4) while keeping the target the true posterior (I3).

Deliverable

For each constrained dist, sampling on ℝⁿ then forward-ing yields valid constrained values; transformed log-density (+logdetJ) equals base log-density.

Acceptance
  • forward(inverse(y))==y and inverse(forward(x))==x to 1e-10 (round-trip).
  • Numeric log_abs_det_jacobian matches AD-log|det ∂forward/∂x| to 1e-6 (I3).
  • Transformed density integrates to 1 on ℝⁿ for Beta/Gamma/Dirichlet test cases.
Fixtures
Fixture Purpose Expected
transforms/roundtrip.json bijectivity 1e-10
transforms/logdetj.json Jacobian AD match 1e-6
transforms/pushforward.json density preservation ∫=1
Pitfalls
  • Sigmoid saturates → logdetJ underflow; compute via -softplus(-x)-softplus(x).
  • StickBreaking order-dependence; document the canonical ordering and keep it fixed.
  • LowerCholesky must exp the diagonal (positivity) and account for it in logdetJ; off-diagonals are free.

⬜ Phase 5 — Trace runtime + effect handlers §16

Objectives

Implement sample/observe primitives and the composable handler stack (trace, replay, condition, substitute, block, seed) so a model program can be executed to read its log-joint and structure (P11), deterministically under a seed (I5).

Deliverable

trace(seed(model, rng))(data) returns a Trace with all sites and a finite log_joint; replay reproduces it deterministically.

Acceptance
  • Re-running under seed with the same Rng yields identical traces (I5).
  • replay of recorded values reproduces log_joint exactly.
  • Handler composition order is well-defined and documented; nested handlers compose.
  • Duplicate site name raises TraceError.
Fixtures
Fixture Purpose Expected
trace/determinism.json seeded replay identical sites/log_joint
trace/handler_compose.json stack order documented outcome
trace/name_collision.json safety TraceError
Pitfalls
  • Forgetting to pop a handler on exception leaks state; use context managers with finally.
  • observe must not draw from RNG (it has data); mixing this corrupts determinism.
  • Mutable default args in messages cause cross-call bleed.

⬜ Phase 6 — Model abstraction: packing + potential §17

Objectives

Wrap a model fn into a Model that discovers free latents, builds constrained↔unconstrained packing, and exposes potential_fn(q) -> (U, grad_U) (P6, I3, I7) — the sole interface gradient kernels consume.

Deliverable

model.potential_fn()(q) returns finite (U, grad_U) of correct dimension; unpack(pack(c))==c.

Acceptance
  • grad_check(U, q) passes (rtol 1e-5) on Beta-Bernoulli, eight-schools, linear regression (I4).
  • pack/unpack round-trip to 1e-10.
  • U equals -log posterior up to constant verified on conjugate Normal.
  • Non-finite U/grad raises NonFiniteError with site context.
Fixtures
Fixture Purpose Expected
model/potential_gradcheck.json U gradient AD vs FD 1e-5
model/pack_roundtrip.json packing 1e-10
model/logpost_constant.json U correctness matches analytic + const
Pitfalls
  • Site ordering must be stable across calls or q indices scramble between steps.
  • Forgetting the log|det J| term (Phase 4) reappears here as a biased U (I3).
  • AD through replay requires the trace to be differentiable wrt forced values — observed sites are constants, latents are variables.

⬜ Phase 7 — Metropolis–Hastings + Gibbs (first posterior) §18

Objectives

Implement RW-MH, Independent-MH, and conjugate Gibbs — the first end-to-end posterior, requiring only log_prob/U (no gradients) — and validate detailed balance (I1) against analytic posteriors.

Deliverable

run_mcmc(model, kernel=RandomWalkMH(...)) produces draws whose moments match analytic posteriors for Beta-Bernoulli and conjugate Normal; Gibbs matches exactly.

Acceptance
  • Beta-Bernoulli posterior mean recovered to 0.625 ± 3·MCSE (§8.10).
  • Conjugate-Normal Gibbs draws match closed-form N(m,s²) (KS test p>0.01).
  • Accept rate stabilizes near target after scale tuning.
  • Detailed-balance unit test on a 2-state toy passes.
Fixtures
Fixture Purpose Expected
mh/beta_bernoulli.json RW-MH correctness mean 0.625 ± 3 MCSE
gibbs/conjugate_normal.json Gibbs exactness KS p>0.01
mh/detailed_balance_2state.json I1 stationary = target
Pitfalls
  • Dropping the proposal-ratio in Indep-MH (asymmetric) silently biases the posterior (P2).
  • RW scale too large → ~0 accept; too small → high autocorrelation; both look "converged" briefly.
  • Gibbs site-update order matters for mixing (document; not for correctness).

⬜ Phase 8 — HMC: leapfrog + Metropolis correction §19

Objectives

Implement Hamiltonian Monte Carlo: sample momentum, simulate Hamiltonian dynamics with the leapfrog integrator (reversible, volume-preserving, I2), and Metropolis-correct on total energy (§8.6). Gradient-driven proposals that move far with high accept.

Deliverable

HMC samples standard Normal, correlated MvNormal, Beta-Bernoulli (on logit) with high accept (>0.6) and low autocorrelation; reversibility test passes.

Acceptance
  • MvNormal(Σ) draws recover Σ within 3·MCSE for dim up to 50.
  • Reverse-trajectory test: leapfrog forward then backward returns to start within 1e-8 (I2).
  • Accept rate ≈ target for tuned ε; energy error small.
  • ESS/gradient-eval beats RW-MH by ≥10× on a 20-dim Gaussian.
Fixtures
Fixture Purpose Expected
hmc/mvnormal_cov.json covariance recovery Σ ± 3 MCSE
hmc/leapfrog_reversible.json I2 round-trip 1e-8
hmc/energy_conservation.json integrator ΔH=O(ε²)
Pitfalls
  • Using grad_U with wrong sign flips the dynamics (climbs the potential) → 0 accept.
  • ε too large → integrator unstable → divergences/oscillation; too small → tiny moves, high cost.
  • Dense M needs Cholesky; non-SPD M (bad adaptation) breaks M⁻¹ (I6).

⬜ Phase 9 — NUTS: recursive tree building §20

Objectives

Implement the No-U-Turn Sampler: build a binary trajectory by recursive doubling, stop on a U-turn (or max depth), and select the next state preserving detailed balance via multinomial sampling over the trajectory (I11, §8.7). Removes the trajectory-length hyperparameter.

Deliverable

NUTS samples eight-schools (non-centered), funnel (with documented divergences), and high-dim Gaussians without manual L; matches HMC moments.

Acceptance
  • On standard Gaussians, NUTS draws match analytic moments within 3·MCSE; ESS/grad-eval ≥ tuned HMC.
  • No-U-turn termination verified on a toy where U-turn time is known.
  • Detailed-balance / exchangeability check on a 1-D target passes (I11).
  • Tree depth distribution reasonable (rarely hits cap on well-behaved targets).
Fixtures
Fixture Purpose Expected
nuts/gaussian_moments.json correctness analytic ± 3 MCSE
nuts/uturn_termination.json stopping rule stops at known depth
nuts/funnel_divergences.json geometry divergences flagged
Pitfalls
  • Recursion must check U-turn at every subtree level, not just the root, or trajectories run too long.
  • Numerical overflow in multinomial weights → use log-weights + logsumexp (P5).
  • Off-by-one in left/right endpoint tracking corrupts the U-turn dot products.
  • Forgetting to stop on divergence inside a subtree inflates cost and bias.

⬜ Phase 10 — Warmup adaptation (dual averaging + mass matrix) §21

Objectives

Make NUTS turnkey: adapt step size via dual averaging to a target accept (0.8) and the mass matrix via Welford windowed estimation (§8.8–8.9), freezing both after warmup (P7, I9).

Deliverable

NUTS with default warmup=1000 fits eight-schools / regression with no manual ε or M; post-warmup kernel is fixed.

Acceptance
  • Post-warmup accept rate within ±0.05 of target (0.8).
  • Adapted diagonal M⁻¹ ≈ posterior marginal variances (within 30%) on a correlated Gaussian; dense M⁻¹ ≈ posterior covariance.
  • No adaptation occurs after warmup (asserted, I9).
  • find_reasonable_epsilon terminates for all example models.
Fixtures
Fixture Purpose Expected
adapt/dual_avg_target.json accept targeting ±0.05 of 0.8
adapt/mass_recovery.json metric estimate ≈ posterior cov
adapt/frozen_after_warmup.json I9 identical kernel across draws
Pitfalls
  • Adapting M and ε simultaneously without re-finding ε at window close destabilizes; follow Stan's schedule.
  • Estimating dense M with too few samples → non-SPD; regularize toward I (§8.9).
  • Letting adaptation leak into the sampling phase silently biases draws (I9) — the subtlest correctness bug here.

⬜ Phase 11 — Diagnostics §22

Objectives

Implement the trust gate (P10): rank-normalized split-R̂, bulk/tail ESS, MCSE, energy-based BFMI, and divergence summaries (Vehtari 2021), emitting numeric summary tables.

Deliverable

Posterior.summary() returns a table matching ArviZ values within tolerance on shared draws; divergence/BFMI surfaced.

Acceptance
  • split-R̂, ESS_bulk, ESS_tail match ArviZ to 3 significant figures on a committed reference draw set.
  • R̂→1 as chains→identical; R̂>1.1 on deliberately non-mixed chains.
  • MCSE consistent with empirical chain-to-chain mean variability.
Fixtures
Fixture Purpose Expected
diag/rhat_ess_reference.json vs ArviZ 3 sig figs
diag/nonconverged.json sensitivity R̂>1.1 detected
diag/bfmi_divergence.json HMC health flags bad energy
Pitfalls
  • Computing R̂ without splitting hides within-chain trends.
  • ESS without rank-normalization is fragile for heavy tails; follow Vehtari.
  • FFT autocovariance needs zero-padding to avoid circular-correlation artifacts.

⬜ Phase 12 — Inference driver + posterior container §23

Objectives

Orchestrate multi-chain sampling (independent spawned seeds, I8), warmup/sampling split, thinning, and assemble a serializable Posterior (draws in constrained space by name + per-step stats + metadata).

Deliverable

run_mcmc(...) returns a Posterior; round-trips through npz; summary() reports diagnostics; reproducible under fixed seed.

Acceptance
  • 4-chain run reproducible to identical draws given same seed/build (P9).
  • Chains independent (R̂ meaningful; seed provenance recorded).
  • from_npz(to_npz(p)) equals p (arrays + meta).
  • Thinning reduces stored draws by factor thin without changing moments beyond MCSE.
Fixtures
Fixture Purpose Expected
driver/reproducible.json determinism identical draws
driver/npz_roundtrip.json serialization exact
driver/multichain_independent.json seeds independent streams
Pitfalls
  • Process fork without seed spawn duplicates RNG → correlated chains (I8) → invalid R̂.
  • Storing draws in unconstrained space confuses users; always present constrained.
  • Pickling the model fn across processes can fail for closures; document module-level model requirement.

⬜ Phase 13 — Conformance, hardening, fuzzing, benchmarks §24

Objectives

Validate the engine against analytic posteriors and external references (Stan/NumPyro committed draws), fuzz model inputs for finite-density safety, benchmark ESS/sec, and harden error paths. Close the deferred-feature list or re-gate it.

Deliverable

Green conformance report (Pass/Deferred per bucket), fuzz run clean over the corpus, committed benchmark baselines, runbooks.

Acceptance
  • All analytic-posterior buckets Pass within MCSE.
  • Eight-schools / logistic posteriors match reference draws (moment + KS) within tolerance.
  • Fuzz: ≥10⁴ random models produce finite densities or typed errors; zero uncaught exceptions.
  • Benchmarks within ±20% of committed baseline; no regression.
Fixtures
Fixture Purpose Expected
conf/analytic_suite.json closed-form within MCSE
conf/reference_draws/*.npz vs Stan/NumPyro KS/moment pass
fuzz/corpus/* robustness finite or typed error
bench/results/*.json perf within ±20% baseline
Pitfalls
  • Comparing to reference draws without accounting for their MCSE → false failures; use statistical tests, not equality.
  • Fuzz models with improper posteriors → non-convergence, not a bug; filter or document.
  • Benchmark noise from BLAS threading; pin threads for stable numbers.
