1. Goal

1.1 Precise Engineering Scope

Build a self-contained probabilistic programming language (PPL) and Markov-chain Monte Carlo inference engine in Python with NumPy-only numerics (no SciPy, Stan, PyMC, NumPyro, JAX, or any external PPL/autodiff dependency). A user writes a generative model as an ordinary Python function that calls sample(name, dist) for latent random variables and conditions on data via observe/condition. The engine traces that program, builds the unnormalized log-joint density, derives gradients via a from-scratch reverse-mode autodiff tape, maps constrained parameters to an unconstrained real space, and draws posterior samples with Metropolis–Hastings (random-walk + independent), Gibbs (conjugate), Hamiltonian Monte Carlo (leapfrog + Metropolis correction), and the No-U-Turn Sampler (NUTS) with Stan-style dual-averaging step-size adaptation and windowed mass-matrix adaptation. Output: multi-chain posterior draws plus convergence diagnostics (split-R̂, ESS, MCSE, divergence count, energy/BFMI).

The contract is seed-deterministic single-platform reproducibility: the same model + data + seed + kernel config yields identical draws on the same NumPy/BLAS build. Bit-exact cross-platform reproduction is an explicit non-goal (float reduction order, BLAS threading).

1.3 Non-Goals

  • No variational inference (ADVI/SVI), no SMC/particle filters, no ABC — PhaseDeferred("FINAL_BLUEPRINT §Phase 13").
  • No nonparametric/open-universe models (Dirichlet process, stick-breaking of unbounded dimension).
  • No GPU/TPU/SIMD-vectorized log-density; CPU + NumPy only.
  • No symbolic graph compiler; the model is the trace, re-executed each step.
  • No automatic discrete-variable marginalization (enumeration) beyond documented Gibbs/MH paths.
  • No plotting library; diagnostics emit numeric tables + arrays, not figures.
  • No cross-platform bit-exactness; only single-platform seed determinism.
  • No reverse-mode-through-control-flow guarantees for data-dependent unbounded loops (trace must be finite).

1.4 Intended Deployment Model

  • Importable library (import ppl) used from scripts/notebooks: define model fn, call ppl.sample(model, data, kernel=NUTS(), chains=4, seed=...), receive a Posterior object.
  • CLI tool (ppl-cli): run model.py --data d.json --kernel nuts --chains 4 --draws 1000 --warmup 1000 --seed 7 --out draws.npz; summary draws.npz; diagnose draws.npz.
  • Single process, single host. Multi-chain via multiprocessing pool, one chain per worker, independent seeds via SeedSequence.spawn.
  • No server, no daemon, no network surface. Input model code is trusted (runs in-process).

1.10 Language Selection — Python (NumPy only)

A PPL's defining feature is model-as-program: latent structure is expressed by ordinary control flow, and inference re-executes the program under different handlers. Tracing via effect handlers / coroutine interception is idiomatic and legible in a dynamic language; the same in a static language demands a graph IR that obscures the pedagogy. The numeric hot path (log-density + gradient) is array-shaped and delegates to NumPy/BLAS, so the interpreter overhead lands on orchestration, not arithmetic. Float64 throughout. Reproducibility is seed-based, not bit-exact. Rust was rejected: building a tracing PPL + reverse-mode AD over dynamic models in Rust triples the surface area for no pedagogical gain on the algorithms (MH/HMC/NUTS), which are the point. C++ rejected for the same reason plus tooling friction. The autodiff, distributions, transforms, kernels, adaptation, and diagnostics are all hand-written Python over NumPy arrays.

2. Why Build This

2.1 Unique Systems Knowledge Taught

  • How a probabilistic program becomes an unnormalized density over a flat real vector through tracing + constraint transforms + Jacobian corrections.
  • Why detailed balance makes an arbitrary proposal yield correct posterior draws, and exactly which term in the MH ratio enforces it.
  • Why HMC turns a sampling problem into a physics simulation, and why the leapfrog integrator's reversibility + volume-preservation is non-negotiable for correctness.
  • How NUTS removes the trajectory-length hyperparameter via a recursive doubling scheme with a no-U-turn stopping rule and detailed-balance-preserving sampling from the trajectory.
  • How Stan-style warmup (dual averaging + windowed mass-matrix estimation) makes gradient samplers usable without manual tuning.
  • How reverse-mode AD is built from a tape and why it gives the log-density gradient at the cost of roughly one extra forward pass.

2.2 Historical and Architectural Significance

Metropolis (1953) and Hastings (1970) made Bayesian computation tractable; Hamiltonian/Hybrid Monte Carlo (Duane 1987) imported molecular-dynamics integrators into statistics; NUTS (Hoffman & Gelman 2014) and Stan made HMC turnkey and launched the modern PPL era (Stan, PyMC, Pyro, NumPyro, TFP). This project reconstructs that lineage from first principles: the same engine that fits a 2-parameter model fits a hierarchical regression, because the inference is decoupled from the model by the trace abstraction.

2.3 Engineering Muscles Developed

  • Numerical robustness in log-space; defensive handling of NaN/Inf gradients.
  • Building and validating a reverse-mode AD tape against finite differences.
  • Reasoning about invariants (detailed balance, symplecticity, Jacobian correctness) and turning each into an executable test.
  • Designing a small effect-handler interpreter (the trace layer) and keeping handlers composable.
  • Diagnostics-driven validation: trusting a sampler only after R̂/ESS/divergence checks pass.

2.4 Production Engineering Concepts Exercised

  • Determinism + seed management across parallel chains (SeedSequence.spawn).
  • Adaptation as a control loop (dual averaging is a stochastic-approximation controller targeting a 0.8 accept rate).
  • Observability: per-step stats (accept prob, tree depth, energy, step size) as first-class telemetry.
  • Conformance harness: analytic posteriors and conjugate updates as golden references.
  • Graceful degradation: divergence detection, max-tree-depth caps, finite-guards that fail loud, not silent.

2.6 Calibration Value

After this project, "fit a Bayesian model" stops being a library call and becomes a transparent pipeline: trace → log-joint → gradient → unconstrain → simulate Hamiltonian → accept/reject → diagnose. The engineer can debug a stuck sampler by reading energy plots and divergence locations, and can defend why a posterior is trustworthy with R̂ and ESS rather than faith.

  • Build and operate an effect-handler trace runtime: compose trace/replay/condition/seed to read a model's log-joint and gradient without inspecting its source (Phase 5, Phase 6).

3.2 Subsystem Descriptions

ppl.core — Owns the numeric contract: float64 everywhere, the RNG abstraction (a thin wrapper over numpy.random.Generator seeded by SeedSequence), and numerically stable primitives (logsumexp, log1mexp, finite-guards). All randomness flows through this layer so chains are reproducible and independent. Defines the exception hierarchy (SupportError, NonFiniteError, NotPositiveDefiniteError, TraceError). No statistics logic.

ppl.autodiff — Reverse-mode AD over Python floats and NumPy arrays via a dynamically recorded tape (Wengert list). Each primitive op records inputs, output, and a vector-Jacobian-product closure. grad/value_and_grad seed the output adjoint with 1.0 and sweep the tape in reverse. Scope is exactly the ops needed for log-densities; it is not a general tensor framework. Validated against central finite differences.

ppl.dist — The distribution library. Each Distribution exposes log_prob (differentiable, log-space), sample (RNG-driven), support (constraint object), and batch/event shapes. log_prob is written in terms of ppl.autodiff ops so gradients flow through parameters and latent values. Conjugate pairs are tagged for Gibbs.

ppl.transforms — Bijectors mapping constrained supports (positive reals, simplex, intervals, PD matrices) to unconstrained ℝⁿ, each providing forward, inverse, and log_abs_det_jacobian. These are the bridge that lets HMC/NUTS operate on unconstrained space while the model is written in natural parameterization; the log-Jacobian term is added to the log-joint to keep the target correct.

ppl.trace — The effect-handler runtime. sample(name, dist) and observe(name, dist, value) are effectful primitives interpreted by a stack of handlers: trace (record sites), replay (force values), condition/substitute (inject data/params), seed (thread RNG), block (hide sites). Re-executing the model under different handler stacks is how the engine reads the log-joint and its gradient. A Trace is an ordered map of Sites plus the accumulated log-joint.

ppl.model — Wraps a model fn into an inference-ready object: discovers free latent variables by a trace run, builds constrained↔unconstrained pack/unpack (flat real vector q), and exposes potential_fn(q) -> (U, grad_U) where U = -log_joint(unpack(q)) - log|det J|. This is the sole interface the gradient kernels need.

ppl.mcmc — The kernels. Each implements init(q0) -> state and step(state, rng) -> (state', stats). RW-MH/Indep-MH/Gibbs need only log_prob/potential; HMC/NUTS need grad_U. Warmup adapters (dual averaging, Welford windowed mass matrix) wrap kernels during the warmup window and freeze afterward.

ppl.diagnostics — Post-hoc validation over multi-chain draws: rank-normalized split-R̂, bulk/tail ESS (autocorrelation via FFT), MCSE, energy-based BFMI, and divergence summaries. Emits numeric summary tables; never mutates draws.

ppl.inference — The driver. Splits warmup/sampling, runs chains independent chains (process pool, spawned seeds), applies thinning, assembles a Posterior (draws keyed by site name in constrained space + sampler stats), and serializes to npz/json. The only object most users touch.

6. Design Principles

P1. Correctness Before Speed

The target distribution must be exactly the posterior. Every optimization (caching, fusion) is rejected if it perturbs the stationary distribution. Tradeoff: slower than fused frameworks. Violation example: caching a log-prob across a changed parameter silently biases the chain.

P2. Detailed Balance Is Sacred

Every MH-family kernel satisfies π(x)q(x→x')α(x,x') = π(x')q(x'→x)α(x',x). The acceptance term carries the full proposal-asymmetry + Jacobian correction. Violation: dropping the proposal-density ratio in a non-symmetric proposal → wrong posterior that looks converged.

P3. Symplectic, Reversible Integration

HMC/NUTS use leapfrog only: it is time-reversible and volume-preserving, so the Metropolis correction restores exactness despite discretization error. Violation: a non-symplectic integrator (e.g., RK4 on the Hamiltonian) breaks volume preservation and the accept ratio no longer corrects it.

P4. Sample in Unconstrained Space

All gradient sampling happens on ℝⁿ; constrained parameters are mapped via bijectors with log-Jacobian added to the log-joint. Violation: HMC on a positivity-constrained variable walks across the boundary, hits log(negative)=NaN, and the chain dies.

P5. Log-Space Everywhere

Densities, weights, accept ratios live in log-space; combine via logsumexp. Violation: multiplying probabilities underflows to 0 for moderate dimension, making every accept ratio 0/0.

P6. Gradients From One Source of Truth

grad_U comes only from the AD tape over the same log_prob code used for U. No hand-derived gradients that can drift. Violation: a hand-coded gradient inconsistent with the density makes HMC sample a different (wrong) distribution while every unit test on U passes.

P7. Adaptation Is Warmup-Only

Step size + mass matrix adapt during warmup, then freeze. Post-warmup the kernel is a fixed, π-invariant transition. Violation: adapting during sampling breaks the Markov property and detailed balance → biased draws that diagnostics may not catch.

P8. Fail Loud on Non-Finite

NaN/Inf in U or grad_U aborts the step with a typed error and context (site, value, q), never a silent reject. Violation: silently rejecting NaN proposals masks model mis-specification and produces a stuck chain that looks "low accept."

P9. Determinism Through Explicit RNG

No global RNG. Every stochastic op takes an explicit Generator; chains get independent spawned seeds. Violation: shared global RNG across processes correlates chains, invalidating R̂.

P10. Diagnostics Gate Trust

A posterior is not "done" until split-R̂ < 1.01 and bulk-ESS ≥ 400 and divergences ≈ 0 are reported. Numbers, not vibes. Violation: reporting a mean from a chain with R̂=1.3 reports noise.

P11. The Trace Is the Model

Inference never inspects model source; it only runs the program under handlers and reads the trace. This decouples kernels from model structure. Violation: a kernel that special-cases a model shape cannot be reused.

P12. Observability by Default

Every step emits stats (accept prob, step size, tree depth, energy, n_leapfrog, divergence flag). These are not debug-only; they are the operational telemetry. Violation: a sampler with no per-step stats is undebuggable when it stalls.

8.2 Model Execution as a Trace

A model is an ordinary function whose body declares sites in sequence — the eight-schools hierarchical model declares four:

Order Site call Site name Distribution Role
1 sample("mu", Normal(0., 5.)) mu Normal(0, 5) latent
2 sample("tau", HalfNormal(5.)) tau HalfNormal(5) latent
3 sample("theta", Normal(mu, tau), shape=(J,)) theta Normal(mu, tau), vectorized over J latent (vectorized)
4 observe("y", Normal(theta, data.sigma), value=data.y) y Normal(theta, sigma) observed

Executing under the trace handler records four sites; log_joint = Σ site.log_prob. Under replay(values) the sample sites return forced values (used to evaluate log_joint at a proposed q). Under condition(data) the observe value is injected. The model never imports a kernel; the kernel never reads the model body.

8.5 MH Transition (State Machine)

state q  --propose--> q'   (q' ~ Q(.|q))
   |                    |
   |             compute log α = min(0, logπ(q') - logπ(q) + logQ(q|q') - logQ(q'|q))
   |                    |
   +----accept (u<e^α)--+--> q'      [I1 detailed balance]
   |                    |
   +----reject----------+--> q       (stay; still a valid draw)

For symmetric Q (random walk) the proposal terms cancel. For Indep-MH, Q(·|q)=g(·) and the ratio includes importance weights. For Gibbs, α=1 by construction (exact conditional).

8.6 HMC Trajectory (Sequence)

Stage Quantity Formula Note
Start momentum draw p ~ N(0, M) M = mass matrix
Start initial energy H0 = U(q) + 0.5 pᵀM⁻¹p total energy
Leapfrog sub-step (×L, size ε) half kick p → p − (ε/2)·grad_U(q) first half-step of momentum
Leapfrog sub-step (×L, size ε) drift q → q + ε·M⁻¹p position update
Leapfrog sub-step (×L, size ε) half kick p → p − (ε/2)·grad_U(q) second half-step, closes one leapfrog iteration
End final energy H1 = U(q*) + 0.5 pᵀM⁻¹p total energy after L leapfrog iterations
End accept accept q* w.p. min(1, exp(H0 − H1)) Metropolis correction on energy [I2]

Energy is conserved up to O(ε²) discretization error, so accept rate is high when ε is tuned. Large energy error ⇒ divergence (geometry too sharp for step size).

8.7 NUTS Tree (Recursion Sketch)

Case Behavior Carries forward Stop condition
Base (depth j = 0) one leapfrog step of size ε·v (v ∈ {−1,+1} is the direction) leaf subtree of size 1, weight exp(−H), divergence flag —
Recursive (depth j > 0) build the left subtree then the right subtree in direction v; combine into a subtree of size 2ʲ combined multinomial weight, valid-state count, divergence flag no-U-turn: (q⁺−q⁻)·p⁻ < 0 OR (q⁺−q⁻)·p⁺ < 0
Outer doubling alternate direction v randomly each iteration, extending the trajectory full trajectory tree U-turn, max_tree_depth, or divergence
Selection sample the next q from the full trajectory ∝ exp(−H) — detailed balance [I11]

Doubling continues until a U-turn or max-tree-depth. Removes the trajectory-length L hyperparameter; ε still adapted by dual averaging.

8.8 Dual Averaging (Step-Size Adaptation)

Targets accept statistic δ (0.8). Stochastic-approximation update (Nesterov-style):

H̄_m = (1 - 1/(m+t0)) H̄_{m-1} + (1/(m+t0))(δ - α_m)
log ε_m = μ - (√m/γ) H̄_m
log ε̄_m = m^{-κ} log ε_m + (1-m^{-κ}) log ε̄_{m-1}     # averaged, used post-warmup

Constants (Stan defaults): γ=0.05, t0=10, κ=0.75, μ=log(10·ε0). Final ε = exp(log ε̄). Frozen after warmup (P7, I9).

8.9 Windowed Mass-Matrix Adaptation

Warmup = init buffer (75) + expanding estimation windows (25,50,100,…) + term buffer (50). In each window, Welford accumulates sample variance of q; at window close, set M⁻¹ = diag(var) (or dense covariance for small dim), regularized toward identity: Σ̂ = (n/(n+5))Σ + (5/(n+5))·1e-3·I. Step size re-found at each window boundary. M must stay SPD (I6).

8.10 Worked Example: Beta–Bernoulli (Analytic Check)

Model: θ ~ Beta(2,2), yᵢ ~ Bernoulli(θ), data = [1,1,0,1]. Posterior is Beta(2+3, 2+1)=Beta(5,3), mean=5/8=0.625. Any kernel (RW-MH on logit θ, or NUTS) must recover posterior mean 0.625 ± MCSE and var of Beta(5,3). This is golden fixture conf/beta_bernoulli.json (I1/I11 validation).

8.11 Worked Example: Conjugate Normal (Gibbs)

μ ~ N(0,10²), yᵢ ~ N(μ,σ²) (σ known). Conjugate posterior N(m,s²) with closed form. Gibbs draws μ directly from the conditional (α=1). Used to validate Gibbs exactness and as a fast reference for the driver.

13. Phase 2 — Reverse-mode autodiff engine

13.1 Objectives

Build a dynamic-tape reverse-mode AD that differentiates exactly the operations used in log-densities, exposing grad / value_and_grad, validated by central finite differences (I4). This is the single source of truth for grad_U (P6).

13.2 Detailed Implementation Steps

  • autodiff/tape.py: Node wrapping a value; an active-Tape stack records (output, parents, vjp) per op. (Margossian 2019 reverse-mode for log-densities; P6)
  • autodiff/ops.py: implement each primitive op forward + register a vjp (vector-Jacobian product) closure: mul → (g·b, g·a); exp → g·exp(x); log → g/x; sum → broadcast g; matmul/dot → transposes; logsumexp → softmax·g; gammaln → digamma·g; where, clip, square. (Neal 2011 gradient cost ~1 pass; I4; ADR-3)
  • autodiff/grad.py: forward pass builds tape; seed output adjoint 1.0; reverse-sweep accumulating adjoints (handle broadcasting by summing over broadcast axes). value_and_grad returns both. grad_check does central differences. (Margossian 2019 Wengert list; P6; I4)
  • Array-aware: nodes hold NumPy arrays; reductions and broadcasts handled in vjps. (ADR-4 dynamic Wengert tape; I4)

13.3 Deliverable

value_and_grad(f)(x) returns correct (value, grad) for composite functions of the registered ops; grad_check passes on a battery.

13.4 Acceptance Criteria

  • grad_check passes (rtol 1e-5) for: quadratic, log-Gaussian density, logistic NLL, softmax cross-entropy, MvNormal log_prob.
  • Reverse pass cost ≤ 3× forward eval on a 1000-dim log-density.
  • No memory growth across repeated value_and_grad (tape released).

13.5 Conformance Fixtures

Fixture Purpose Expected
ad/gradcheck_suite.json analytic grads match central diff 1e-5
ad/broadcast_cases.json broadcast vjp correct shapes/sums
ad/tape_release.json no leak RSS stable over 10⁴ calls

13.6 Pitfalls

  • Broadcasting in mul/add requires summing the adjoint over broadcasted axes; forgetting yields wrong-shaped grads.
  • In-place NumPy mutation of a node's value corrupts the tape; ops must be pure.
  • log/sqrt at 0 → inf grad; rely on support transforms (P4) to keep args positive.

13.7 Performance Concerns

  • Python-object tape has overhead; keep ops coarse (array-level, not element-level).
  • Avoid retaining intermediate arrays beyond the reverse sweep.

13.8 Edge Cases

  • Constant inputs (no parents) contribute zero adjoint. Re-used subexpressions accumulate adjoints correctly (DAG, not tree).

13.9 Failure Analysis

A wrong vjp makes HMC sample a subtly wrong distribution while U tests pass (I4). Detection: mandatory grad_check in CI on every density. This is the highest-leverage test in the project.

13.10 Operational Notes

Expose grad_check as a tools/ CLI so model authors can validate custom densities. Emit a one-line AD profile (ops recorded, peak tape size) under debug logging.

15. Phase 4 — Constraint transforms (bijectors)

15.1 Objectives

19. Phase 8 — HMC: leapfrog + Metropolis correction

19.1 Objectives

Implement Hamiltonian Monte Carlo: sample momentum, simulate Hamiltonian dynamics with the leapfrog integrator (reversible, volume-preserving, I2), and Metropolis-correct on total energy (§8.6). Gradient-driven proposals that move far with high accept.

19.2 Detailed Implementation Steps

  • mcmc/hmc.py: init stores potential, fixed step_size ε, num_steps L, mass matrix M (diag or dense via Cholesky of M⁻¹). (Duane et al. 1987; Neal 2011; P3; I2)
  • Momentum draw p ~ N(0,M); kinetic K(p)=0.5 pᵀM⁻¹p.
  • leapfrog(q,p,ε): half momentum kick p -= (ε/2)grad_U(q); drift q += ε M⁻¹ p; half kick. Repeat L times. (Neal 2011 leapfrog; P3; I2; ADR-8 default kernel)
  • Energy H=U+K; accept with min(1,exp(H0−H1)); on accept return q*, else q. Negate p post-trajectory for formal reversibility (irrelevant to next step since p resampled). (Duane et al. 1987 Metropolis on energy; I2; P2)
  • Divergence: if |H1−H0|>threshold flag diverging=True and reject (geometry too sharp for ε). (Betancourt 2017 divergence geometry; P8; I7)

19.3 Deliverable

HMC samples standard Normal, correlated MvNormal, Beta-Bernoulli (on logit) with high accept (>0.6) and low autocorrelation; reversibility test passes.

19.4 Acceptance Criteria

  • MvNormal(Σ) draws recover Σ within 3·MCSE for dim up to 50.
  • Reverse-trajectory test: leapfrog forward then backward returns to start within 1e-8 (I2).
  • Accept rate ≈ target for tuned ε; energy error small.
  • ESS/gradient-eval beats RW-MH by ≥10× on a 20-dim Gaussian.

19.5 Conformance Fixtures

Fixture Purpose Expected
hmc/mvnormal_cov.json covariance recovery Σ ± 3 MCSE
hmc/leapfrog_reversible.json I2 round-trip 1e-8
hmc/energy_conservation.json integrator ΔH=O(ε²)

19.6 Pitfalls

  • Using grad_U with wrong sign flips the dynamics (climbs the potential) → 0 accept.
  • ε too large → integrator unstable → divergences/oscillation; too small → tiny moves, high cost.
  • Dense M needs Cholesky; non-SPD M (bad adaptation) breaks M⁻¹ (I6).

19.7 Performance Concerns

  • Cost = L × (one grad_U); choose L vs ε to balance distance vs cost; NUTS (Phase 9) automates L.
  • Cache M⁻¹ (or its Cholesky factors); avoid solving each drift step.

19.8 Edge Cases

  • L=1 → Langevin (MALA-like). High curvature regions → divergences expected; surfaced, not hidden.
  • Momentum resampling each iteration ensures ergodicity (partial-momentum variant deferred).

19.9 Failure Analysis

Non-symplectic integration or wrong M silently changes the stationary distribution. Detection: reversibility + energy-conservation + covariance fixtures. Blast radius: all draws. Recovery: revert to leapfrog; re-validate M SPD.

19.10 Operational Notes

20. Phase 9 — NUTS: recursive tree building

20.1 Objectives

Implement the No-U-Turn Sampler: build a binary trajectory by recursive doubling, stop on a U-turn (or max depth), and select the next state preserving detailed balance via multinomial sampling over the trajectory (I11, §8.7). Removes the trajectory-length hyperparameter.

20.2 Detailed Implementation Steps

  • mcmc/nuts.py: build_tree(q,p,log_u,v,j,ε) recursion. Base (j=0): one leapfrog of v·ε; return leaf state, its exp(-H) weight, validity, divergence flag. (Hoffman & Gelman 2014 NUTS; I11; P3)
  • Recursive (j>0): build subtree, then a second subtree in the same direction; combine weights (multinomial: pick proposal from subtree ∝ weight); propagate no-U-turn criterion: (q⁺−q⁻)·p⁻<0 or (q⁺−q⁻)·p⁺<0. (Hoffman & Gelman 2014 doubling; I11; ADR-8) (Betancourt 2017 geometric stopping; Hoffman & Gelman 2014)
  • Outer loop doubles direction v∈{−1,+1} randomly until U-turn / max_tree_depth (default 10, I-cap) / divergence; choose final q by multinomial across the full tree (modern variant, not slice).
  • Divergence if subtree energy error exceeds threshold; record tree_depth, n_leapfrog. (Betancourt 2017 energy diagnostics; P8; I11)

20.3 Deliverable

NUTS samples eight-schools (non-centered), funnel (with documented divergences), and high-dim Gaussians without manual L; matches HMC moments.

20.4 Acceptance Criteria

  • On standard Gaussians, NUTS draws match analytic moments within 3·MCSE; ESS/grad-eval ≥ tuned HMC.
  • No-U-turn termination verified on a toy where U-turn time is known.
  • Detailed-balance / exchangeability check on a 1-D target passes (I11).
  • Tree depth distribution reasonable (rarely hits cap on well-behaved targets).

20.6 Pitfalls

  • Recursion must check U-turn at every subtree level, not just the root, or trajectories run too long.
  • Numerical overflow in multinomial weights → use log-weights + logsumexp (P5).
  • Off-by-one in left/right endpoint tracking corrupts the U-turn dot products.
  • Forgetting to stop on divergence inside a subtree inflates cost and bias.

20.7 Performance Concerns

  • Cost grows with tree depth (2^depth leapfrogs); cap at max_tree_depth. Memory O(depth) with the standard "keep one proposal" trick — do not store the whole trajectory.
  • Hitting the depth cap frequently signals ε too small (post-adaptation) — surfaced as telemetry.

20.8 Edge Cases

  • Immediate U-turn (depth 0 valid) → single leapfrog. Pathological funnels → many divergences; recommend non-centered reparam (fixture).
  • Max-depth saturation → warn; not an error.

20.9 Failure Analysis

A buggy U-turn check yields biased draws that pass naive eye tests. Detection: moment fixtures + exchangeability test + cross-check vs NumPyro draws (Phase 13). Blast radius: all gradient-sampled draws.

20.10 Operational Notes

Telemetry: tree depth histogram, divergence count + locations, n_leapfrog/iter. Runbook "many divergences" → reparameterize or raise target_accept (smaller ε); "depth saturation" → check mass matrix.

21. Phase 10 — Warmup adaptation (dual averaging + mass matrix)

21.1 Objectives

Make NUTS turnkey: adapt step size via dual averaging to a target accept (0.8) and the mass matrix via Welford windowed estimation (§8.8–8.9), freezing both after warmup (P7, I9).

21.2 Detailed Implementation Steps

  • mcmc/adaptation.py: DualAveraging(mu,γ=0.05,t0=10,κ=0.75) per §8.8; find_reasonable_epsilon(q) doubles/halves ε until accept ≈0.5 to seed μ. (Hoffman & Gelman 2014 dual averaging; Carpenter et al. 2017 Stan constants; P7; I9)
  • WelfordVar accumulates mean/M2 per dimension (diag) or full covariance (dense, small dim). (Neal 2011 mass-matrix tuning; ADR-10; I6)
  • WarmupSchedule(warmup): init buffer (75) — only step adapts; expanding windows (25,50,100,…) — step + mass adapt, re-find ε at each boundary; term buffer (50) — only step adapts; then freeze. (Carpenter et al. 2017 Stan window schedule; P7; I9)
  • Wrap the NUTS kernel: during warmup, step updates adapters; at warmup end, set ε = averaged value, M = final covariance (regularized, SPD-checked I6). (P7; I9; ADR-9 dual averaging freezes post-warmup)

21.3 Deliverable

NUTS with default warmup=1000 fits eight-schools / regression with no manual ε or M; post-warmup kernel is fixed.

21.4 Acceptance Criteria

  • Post-warmup accept rate within ±0.05 of target (0.8).
  • Adapted diagonal M⁻¹ ≈ posterior marginal variances (within 30%) on a correlated Gaussian; dense M⁻¹ ≈ posterior covariance.
  • No adaptation occurs after warmup (asserted, I9).
  • find_reasonable_epsilon terminates for all example models.

21.6 Pitfalls

  • Adapting M and ε simultaneously without re-finding ε at window close destabilizes; follow Stan's schedule.
  • Estimating dense M with too few samples → non-SPD; regularize toward I (§8.9).

21.7 Performance Concerns

  • Warmup is often the bulk of wall-clock; window sizes trade adaptation quality vs cost.

21.8 Edge Cases

  • Very short warmup → poor adaptation, low ESS; warn if warmup<100. Constant-variance dims → fine. Zero-variance (unidentified) dim → flagged via singular M.

21.9 Failure Analysis

Bad adaptation → low ESS, depth saturation, or divergences (not bias, if frozen correctly). Detection: post-warmup accept + ESS telemetry. Recovery: longer warmup, dense mass, reparameterization.

21.10 Operational Notes

Mental Models & First Principles

  1. MM1 — Every MCMC kernel is a way to explore a level set of U(q). Predicts: whether a kernel will mix across modes (crossing level sets) or within them (tunneling). Without it: you mistake a stuck chain for a multi-modal posterior and diagnose incorrectly. Applied: §8.5, §Phase 7 (MH stays near one mode), §Phase 8-9 (HMC traverses with momentum).

  2. MM2 — Detailed balance is the only thing that makes a chain's stationary distribution equal to the target. Predicts: whether dropping or approximating the acceptance correction term will bias the posterior. Without it: you implement an "approximately correct" accept step that produces draws from the wrong distribution while every MH-ratio unit test passes because the test checks the formula, not the invariant. Applied: §8.5, §7 (I1), §Phase 7, §Phase 9 (I11 multinomial selection).

  3. MM3 — The leapfrog integrator's reversibility + volume preservation is what allows the Metropolis correction to be exact despite discretization error. Predicts: whether any other ODE integrator (e.g., RK4) can replace leapfrog without biasing the chain. Without it: you swap leapfrog for a higher-order but non-symplectic integrator; energy drift makes the accept ratio systematically reject correct states. Applied: §8.6, §Phase 8 (I2), §Phase 3 (HMC vs RK4 in alt-arch).

  4. MM4 — The log-Jacobian term in U is not optional; it is the change-of-variables correction that keeps the unconstrained target's stationary distribution equal to the constrained posterior. Predicts: whether sampling in unconstrained space after applying a bijector will yield draws from the right posterior. Without it: the posterior mode shifts toward whatever transformation compresses or expands volume the most; the bug passes all log-joint unit tests because those tests check U at fixed q, not the induced density. Applied: §8.4, §Phase 4 (I3), §Phase 6.

  5. MM5 — The reverse-mode AD tape is a way to trade memory for time: store the forward-pass computation graph, then sweep it in reverse accumulating adjoints. Predicts: gradient cost as a function of forward-pass cost (approximately 3× at tape replay, §4). Without it: you write hand-derived gradients that may be inconsistent with U and HMC silently samples a different distribution. Applied: §Phase 2 (I4, P6), §Phase 6 (potential_fn).

  6. MM6 — Dual averaging is a stochastic-approximation controller targeting a desired accept rate, not a grid search. Predicts: how the step size ε converges and what happens when the controller constants (γ, t0, κ, §8.8) are poorly chosen. Without it: you tune ε by hand or implement a simpler halving/doubling rule that oscillates rather than converges, leading to poor post-warmup ESS. Applied: §8.8, §Phase 10, ADR-9.

  7. MM7 — ESS and R̂ are not redundant: ESS measures how much information is in the chain; R̂ measures whether multiple chains have reached the same distribution. Predicts: which diagnostic catches which failure mode (a single stuck chain has low ESS but near-1 R̂; two divergent chains have high ESS/chain but R̂≫1). Without it: you declare convergence because one metric looks good, missing the orthogonal failure. Applied: §Phase 11 (P10, I1, I8), §Phase 13.

  8. MM8 — HMC's energy error (H1−H0) is a direct readout of posterior geometry relative to step size ε. Predicts: whether a divergence is caused by a too-large ε or by an inherently sharp curvature that no ε can handle (a funnel). Without it: you respond to every divergence by decreasing ε, missing that funnels require reparameterization. Applied: §8.6, §8.13, §Phase 8 (BFMI), §Phase 9 (telemetry), §Phase 13.

  9. MM9 — Effect-handler composition is a stack: the innermost handler runs last, so handler ordering determines which interpretation a sample site receives. Predicts: whether composing replay over condition over seed will produce the right log-joint for gradient evaluation. Without it: you compose handlers in the wrong order and one handler's action is overridden by another, silently computing the wrong density. Applied: §8.3, §Phase 5 (P11, I5), §Phase 6.

  10. MM10 — The mass matrix M is an approximation to the posterior's inverse covariance; when it is well-estimated, leapfrog integrates in a whitened space and the U-turn time is equalized across dimensions. Predicts: how many leapfrog steps are needed for a given posterior geometry and how sensitive ESS is to a bad diagonal-vs-dense mass choice. Without it: you leave M at identity for a correlated posterior and spend most steps fighting correlation, achieving low ESS/gradient. Applied: §8.9, §Phase 10 (ADR-10, I6), §Phase 8.

Stan — the only decision made fundamentally differently is compiling the model to C++ at sampling time; this wins for production workflows with large data and repeated fits, eliminating Python interpreter overhead at the cost of a separate language and toolchain.

PyMC — routes differentiation through PyTensor's C++ graph rather than a Python tape; this wins when the model benefits from PyTensor's graph rewrites (common subexpression elimination, fused elementwise kernels) on large batched log-densities.

TFP — treats samplers as composable kernel objects on top of TensorFlow's bijector API; this wins in TF-native production stacks where the model, data pipeline, and sampler all share the same TF graph, enabling end-to-end compilation.

NumPyro — uses JAX vmap to run all chains in a single JIT-compiled call on one device; this wins for GPU-resident posteriors where the per-step cost is dominated by linear algebra and the Python overhead of process-level parallelism would be prohibitive.

Back-of-Envelope Capacity Model

  1. Latent dimension d from §4 ("Model size ceiling Phase 0: latent dim ≤ ~10³ dense, ≤ ~10⁴ diagonal"). Dense mass matrix cost per Cholesky decomp: O(d³). At d=10³: (10³)³ = 10⁹ FLOPs per window close. At 1 GFLOP/s Python/NumPy overhead: ~1 s per window. With 10 windows in 1000-iter warmup: ~10 s adaptation overhead. Consequence: diagonal mass is the correct default for d≳500; dense mass reserved for d≤~200.

  2. Memory for draws array from §4 ("draws array O(chains × draws × dim) float64 in RAM"). Default run: 4 chains × 1000 draws × d=100 parameters × 8 bytes = 3.2 MB. At d=1000: 32 MB. At d=10³ with 4 chains × 10⁴ draws: 320 MB. At d=10⁴ (diagonal only): 3.2 GB — hits practical RAM limits; thin needed. Consequence: thinning by 10× at d=10⁴ keeps resident size ≤320 MB.

  3. Leapfrog cost per iteration from §4 ("per-leapfrog cost: O(1) log-joint + O(1) grad sweep"). One gradient eval = 1 forward + 1 reverse ≈ 3× forward (§4 "reverse pass ≤ ~3× forward"). NUTS max tree depth 10 → up to 2^10=1024 leapfrog steps. At 1 ms/grad-eval: worst-case 1024 ms ≈ 1 s/iteration. Typical depth 4–6 → 16–64 leapfrog steps → 16–64 ms/iter. Consequence: max_tree_depth=10 cap (§4) bounds per-iteration cost; typical ESS/sec computation assumes median depth ≈5.

  4. Target accept rate and implied ε from §4 ("target accept 0.8 NUTS, 0.65 static HMC"). For a d-dimensional standard Gaussian, optimal ε ∝ d^{-1/4} (Neal 2011). At d=100: ε0.1; at d=1000: ε0.056. The dual-averaging controller (§8.8) finds this automatically; this formula predicts the warm-start μ=log(10·ε₀) ballpark. Consequence: initializing ε₀ too far from optimal (e.g., ε₀=1 at d=1000) requires more warmup iterations to converge the controller.

  5. ESS target and required draws from §4 ("bulk ESS ≥ 400 across chains before summary is trustworthy"). With 4 chains × 1000 draws = 4000 raw draws, bulk ESS ≥ 400 requires effective sample fraction ≥ 10%. For NUTS on a well-adapted posterior, ESS/raw ~ 0.5–1.0 (low autocorrelation), so 400 ESS is easily satisfied. For MH on a high-dim posterior with ESS/raw ~ 0.02, achieving 400 ESS requires 4000/0.02 = 200 000 draws. Consequence: the §4 target of bulk-ESS ≥ 400 is a practical gate that distinguishes gradient from non-gradient samplers.

  6. Gradient overhead budget from §4 ("gradient overhead: reverse pass ≤ ~3× forward log-joint eval"). If the forward pass (re-execute model under replay handler) takes T_fwd, then T_grad ≤ 3·T_fwd, and one leapfrog step costs T_fwd + T_grad ≤ 4·T_fwd. For 1000-iter warmup × median 30 leapfrog steps/iter: 30 000 gradient evals × 4·T_fwd total. At T_fwd=0.1 ms for a 100-parameter model: warmup ≈ 12 s. Consequence: models should aim for T_fwd < 1 ms; AD tape overhead should never exceed the 3× bound — grad_check CI enforcement is essential.

  7. R̂ convergence iteration requirement from §4 ("split-R̂ < 1.01"). Gelman & Rubin (1992) show R̂ converges at rate 1/√(draws). To distinguish R̂=1.00 from R̂=1.01 requires roughly (1/0.01)²=10 000 draws per chain (Vehtari et al. 2021, rank-normalized R̂ analysis). The §4 default of 1000 draws/chain is sufficient for R̂<1.05 detection; reaching R̂<1.01 reliably for pathological chains may require additional draws. Consequence: the Phase 11 acceptance criterion "R̂>1.1 on deliberately non-mixed chains" is conservative (easily achieved); 1.01 as a gate is stringent and requires genuinely converged multi-chain runs.

  8. Warmup window schedule from §4 ("warmup default: 1000 iters, init buffer 75, term buffer 50"). Expanding windows cover 1000 - 75 - 50 = 875 iterations. First window: 25 draws (minimal Welford estimate). Second: 50, third: 100, ..., pattern doubles. Sum 25+50+100+200+400=775 < 875; one partial window fills the remaining 100. Consequence: mass-matrix adaptation has ≥5 full windows by default; increasing warmup to 2000 doubles the final window size (400→800), improving the mass estimate substantially for high-d models.

  9. Tree-depth cap and divergence threshold interaction from §4 ("NUTS max tree depth 10; divergence threshold energy error > 1000"). At max_tree_depth=10 and ε=0.05 (typical), the longest trajectory covers 1024 × 0.05 = 51.2 units in q-space. A posterior with correlation length > 51.2 will saturate the depth cap. The divergence threshold of 1000 energy units is deliberately generous to fire only on catastrophic geometry; reducing it (e.g., to 100) flags more borderline divergences. Consequence: saturated-depth telemetry (not divergences) is the primary signal for "ε too small + bad mass" in Phase 9.

Hard Questions (Self-Examination)

  1. In potential_fn, the log-Jacobian and the log-joint are both summed into U. If the replay handler forces latent values from a constrained dict but the AD tape differentiates through the inverse transform applied during unpack, can the gradient of U with respect to q be biased by a shared-node aliasing bug in the tape? Which invariant detects this, and in which phase? (§Phase 6, §Phase 2, I4, ADR-4)

  2. NUTS selects the next state by multinomial sampling over the trajectory weighted by exp(−H). If the log-weights are computed as differences from the initial H rather than absolute H, can floating-point cancellation when H is very large cause multinomial probabilities to not sum to 1, violating detailed balance (I11)? How does P5 apply here, and at which phase is this validated? (§Phase 9, §8.7, P5, I11)

  3. The warmup schedule has three phases: init buffer, expanding windows, term buffer (§8.9). If a worker process crashes and is restarted mid-schedule, the WelfordVar accumulation is lost but the WarmupSchedule counter continues. What invariant is violated, which ADR governs the recovery path, and what does Phase 12 need to do to detect this? (§Phase 12, §Phase 10, I9, ADR-13)

  4. A user writes a model where a sample site's shape depends on the value of a previously sampled discrete variable (data-dependent trace structure). The pack/unpack functions freeze the latent-site layout at model-build time. Under which conditions does this produce a TraceError versus silently building a wrong q-vector, and what change to Phase 5 or Phase 6 would make the failure loud rather than silent? (§Phase 5, §Phase 6, §8.13, P8, I5)

  5. The dual-averaging controller uses a fixed μ=log(10·ε₀) (§8.8). If find_reasonable_epsilon returns a pathologically small ε₀ (e.g., 1e-10 due to a near-singular mass), the controller anchors to log(10·1e-10)≈−21 and may never recover to a useful ε. Which phase is responsible for the ε₀ initialization, and how does the lack of a lower-bound guard interact with the divergence threshold from §4? (§Phase 10, §8.8, ADR-9, P7)

  6. WelfordVar accumulates sample covariance online. If the expanding window includes warmup draws from a chain that has not yet mixed (still near the initial q₀), the mass estimate is contaminated by the prior rather than the posterior. The init buffer (75 steps) is intended to mitigate this, but for a slow-mixing model it may not be enough. What ADR-10 regularization term prevents a contaminated M from being non-SPD, and at what Phase is the "frozen-after-warmup" invariant (I9) verified? (§Phase 10, §8.9, ADR-10, I6, I9)

  7. For the eight-schools hierarchical model (§8.2, centered parameterization), the funnel geometry makes divergences structurally unavoidable at any finite ε. NUTS detects them via energy threshold (§8.6). Is the energy threshold a sufficient diagnostic to distinguish "ε too large" from "funnel geometry"? What additional telemetry from Phase 9 or Phase 11 would allow a user to distinguish these two causes, and which principle (P8, P12) requires it to be emitted? (§Phase 9, §Phase 11, §8.13, P8, P12, ADR-8)

  8. log_abs_det_jacobian for StickBreaking is a sum of correction terms across K−1 breaking steps (§8.4). If K=1 (degenerate simplex), the transform has zero free parameters and the logdetJ sum is empty. Does this edge case propagate correctly through pack/unpack to produce an empty q slice, or does it produce a shape mismatch that manifests only during the gradient sweep? Which Phase and fixture cover this? (§Phase 4, §Phase 6, §8.13, I3, ADR-7)

  9. The seed handler threads RNG through the model; the replay handler forces sample values. If both are active simultaneously (e.g., inside potential_fn where replay overrides sample draws but seed is still on the stack), does the RNG advance deterministically or non-deterministically for the observe sites? What property of observe (§8.3) ensures this is deterministic, and which invariant does it protect? (§Phase 5, §8.3, I5, P9, ADR-12)

  10. The diagnostics in Phase 11 compute rank-normalized split-R̂ by splitting each chain in half. For short runs (draws<100), the halves have too few samples for stable rank transformation. The §4 default of 1000 draws/chain is safe, but the run_mcmc API allows draws=10. Which acceptance criterion in Phase 11 gates this, and should a hard minimum on draws be an invariant (I-level) or a warning-only check? (§Phase 11, §Phase 12, §4, P10, ADR-15)

  11. The multiprocessing.Pool spawns one process per chain. If the model function uses a closure over a mutable Python object (e.g., a NumPy array that is modified in-place), the fork-based spawn may share state across chains on some platforms (macOS vs Linux fork vs spawn start method). Which ADR governs the start method, which invariant (I8) would be violated, and what Phase 12 test would catch the correlation? (§Phase 12, ADR-13, I8, P9)

  12. NUTS records a divergence when energy error exceeds 1000 (§4, configurable). A model with very large U values (e.g., a 1000-dim posterior with U~O(d)) may produce large-but-normal ΔH just from numerical accumulation across 1024 leapfrog steps, triggering false divergences. How should the divergence threshold be calibrated relative to U magnitude, and which Phase 13 conformance fixture would distinguish false from true divergences? (§Phase 9, §Phase 13, §4, I7, P1)

  13. The Posterior.to_npz stores draws in constrained space with schema-versioned json metadata. If a new transform is added in a future version that changes the unpack bijector for an existing distribution, an old npz file loaded with the new code will silently return draws under the wrong transform. Does the schema-version check in from_npz catch transform-API changes, or does it require the transform name/version to be embedded in meta? What Phase and ADR govern this? (§Phase 12, ADR-17, ADR-26, §4)

  14. grad_check in Phase 2 uses central finite differences with rtol=1e-5. For log-densities with nearly-zero gradients (e.g., a very flat prior far from data), the absolute difference may be negligibly small even if the relative error is large. Does the grad_check implementation use both rtol and atol, and does it test specifically at points near the posterior mode rather than at the initialization? Which Phase gates this and which invariant depends on it? (§Phase 2, §Phase 6, I4, P6, ADR-3)

  15. The NUTS no-U-turn criterion uses (q⁺−q⁻)·p⁻<0 OR (q⁺−q⁻)·p⁺<0 (§8.7). In the original Hoffman & Gelman 2014 paper, only the forward-endpoint condition is used at the outer level; the bivariate check was introduced later (Betancourt 2017 "Identifying the Optimal Integration Time in Hamiltonian Monte Carlo"). If the stricter bivariate check is not applied at every subtree level, the sampler may fail to stop on some U-turns. Which Phase 9 acceptance criterion validates the stopping rule, and which paper is the normative reference for the bivariate check? (§Phase 9, §20.4, Hoffman & Gelman 2014, Betancourt 2017, I11)

  16. The logsumexp in NUTS is used to combine multinomial weights across trajectory states (§8.7, §20.6). If the trajectory has a single state with very negative H (sharply peaked), all weight collapses onto it and the multinomial degenerates to a deterministic selection. Is this a correctness problem for detailed balance, or is it the intended behavior under the multinomial scheme? Which invariant (I11) governs this, and what is the difference from the original slice-variable NUTS? (§Phase 9, §8.7, I11, P5, ADR-8)

  17. Phase 13 compares draws to committed Stan/NumPyro reference draws using KS/moment tests (§24.2). Both the reference and the test draws have MCSE; a test that uses a fixed tolerance rather than MCSE-adjusted tolerance will produce false failures as draws increase (more power → stricter test). Does the conformance runner use MCSE-adjusted tolerance, and which §4 constraint governs what "within MCSE" means for the comparison? (§Phase 13, §24.6, §4, P1, ADR-27)

  18. The block handler hides sites from exposure (§8.3). If a model uses block to marginalize an auxiliary variable, the hidden site's log_prob is not added to log_joint. If that site has a non-trivial transform (e.g., a positive constrained variable), its Jacobian is also not added. Is this a bug or intended behavior for block, and what constraint in Phase 5 or Phase 6 must the user satisfy to avoid biasing U? (§Phase 5, §Phase 6, §8.3, I3, P4)

Alternative Architectures (Roads Not Taken)

Random-Walk Metropolis–Hastings (No Gradients)

  +-----------+    propose q' = q + ε·N(0,I)    +-----------+
  |  state q  | ---------------------------------> | state q'  |
  +-----------+                                   +-----------+
        |                                               |
        |    log α = min(0, U(q) - U(q'))               |
        |    u ~ Uniform(0,1)                           |
        +--- u < exp(α) ? accept q' : stay q -----------+
             (one U eval / step; no gradient needed)

Wins when: low-dimensional posteriors (d ≤ ~10), discrete or non-differentiable targets, debugging a new distribution before investing in gradient plumbing, or any model where log_prob is available but grad_U is not (simulator-based, implicit likelihoods).

Embodied by: the original Metropolis et al. 1953 algorithm; BUGS/JAGS for conjugate models; the RandomWalkMH kernel in this codebase (§Phase 7).

Why rejected here: accept rate degrades exponentially with d for a fixed proposal scale; at d=100 optimal RW-MH accept ≈ 0.234 achieves ESS/raw ~ 0.01–0.1, requiring 100–1000× more samples than NUTS for the same ESS. HMC/NUTS dominates on every target this codebase is designed for.

Variational Inference / ADVI (Optimization, Not Sampling)

  +-------------------+    minimize KL(q(z;λ) || p(z|x))    +-------------------+
  |  variational dist |  <---------------------------------  |   target p(z|x)   |
  |  q(z;λ) (Gaussian)|    gradient ascent on ELBO           |   (unnormalized)  |
  +-------------------+                                      +-------------------+
        |                                                          |
        |   ELBO = E_q[log p(x,z)] - E_q[log q(z;λ)]             |
        |   stochastic gradient via reparameterization trick       |
        v                                                          |
  +--------------+                                                 |
  | λ* (mean,cov)|  <- converged parameters; draw samples from q  |
  +--------------+

Wins when: the posterior is approximately Gaussian and speed matters more than exactness; when the model has millions of parameters (e.g., deep generative models) where MCMC is computationally intractable; or for initializing an MCMC run near the posterior mode (warm-starting).

Embodied by: Stan ADVI, Pyro SVI (stochastic variational inference), mean-field and structured VI in TFP.

Why rejected here: ADVI produces a biased approximation — the variational posterior is the best-fitting Gaussian, not the true posterior. For a project whose defining goal is exact posterior inference (P1, P2), a biased approximation is not a valid sampler. Deferred as an alternative inference path (§1.8, §1.3).

Gibbs Sampling on Conjugate Conditionals

  +----------+   draw z1 | z2,...,x ~ conjugate conditional   +----------+
  |  z1,z2,  | ------------------------------------------------> |  z1',z2, |
  |  z3,...  |   draw z2 | z1',z3,...,x ~ conjugate conditional|  z3,...  |
  +----------+ ------------------------------------------------> (cycle)  |
        ^                                                           |
        |              each draw is exact (α = 1)                  |
        +-----------------------------------------------------------+

Wins when: the model is fully conjugate (Beta-Bernoulli, Normal-Normal, Gamma-Poisson) and every full conditional is available in closed form; Gibbs is exact (acceptance=1), has zero divergences, and requires no gradient computation.

Embodied by: BUGS, JAGS, and the Gibbs kernel in this codebase for conjugate sites (§Phase 7, dist/conjugacy.py).

Why rejected here: as the default for general continuous posteriors. Non-conjugate conditionals require Metropolis-within-Gibbs steps, which degrades to RW-MH quality per variable; mixing is poor for correlated variables because each variable is updated conditioned on others staying fixed. HMC/NUTS moves all variables jointly with gradient information, dramatically outperforming Gibbs on correlated high-dimensional continuous posteriors.
