In one paragraph

A probabilistic programming engine lets you write a statistical model as an ordinary Python function and then draws samples from what the data say about the model's unknowns (§1.1). This design builds one in Python with NumPy only: a model tracer, a hand-made gradient engine, transforms for constrained parameters, and the samplers Metropolis–Hastings, Gibbs, HMC and NUTS with automatic tuning, plus convergence diagnostics (§1.1, ADR-2). It is a library and a command-line tool on one host, with one process per chain (§1.4). Its users are learners, inference researchers and test-harness authors (§1.5). The contract is identical draws for the same model, data, seed and settings on the same NumPy/BLAS build (§1.1, ADR-27).

The problem, concretely

A Bayesian model says which unknowns, with which prior beliefs, could have produced the data. What you want is the spread of plausible unknowns given the data, and all you can compute is that spread up to a constant (the unnormalized log-joint density) (§1.1, Glossary). The engine's job is to turn a Python function into that density and then draw from it (§1.1, §2.6).

The blueprint's own running example is the eight-schools hierarchical model, which declares four sites: mu, tau (a HalfNormal), theta vectorized over J and the observed y (§8.2). The design principles name the ways an obvious sampler for a model like this fails:

  • Run a gradient sampler directly on a positivity-constrained variable. It walks across the boundary, hits the log of a negative number, gets NaN and the chain dies (P4).
  • Multiply probabilities instead of adding logs. For moderate dimension the product underflows to 0 and every accept ratio becomes 0/0 (P5).
  • Hand-code the gradient. If it drifts from the density, HMC samples a different distribution while every unit test on the density still passes (P6).
  • Drop the proposal-density ratio in a non-symmetric proposal. The chain converges to a wrong posterior that looks converged (P2).
  • Use a plain random walk in high dimension. At d=100 the optimal accept rate is about 0.234 with ESS/raw of about 0.01–0.1, needing 100–1000× more samples than NUTS for the same ESS (Alternative Architectures, "Random-Walk Metropolis–Hastings").
  • Sample the centered eight-schools model with a gradient sampler. Its funnel geometry makes divergences unavoidable at any finite step size, so the fix is a different parameterization, not a smaller step (§8.13, MM8, Hard Questions 7).

The last trap is trusting the result: a mean from a chain with R̂=1.3 reports noise (P10).

How it works, end to end

Follow one ppl-cli run model.py --data d.json --kernel nuts --chains 4 --draws 1000 --warmup 1000 --seed 7 --out draws.npz (§1.4) through the boxes of §3.1, adapted here:

 ppl-cli   (run | summary | diagnose | example)
    |
 ppl.inference    run_mcmc(...) -> Posterior    process pool, SeedSequence.spawn
    | per chain
 ppl.mcmc         RandomWalkMH | IndependentMH | Gibbs | HMC | NUTS + warmup adapters
    | needs U(q), grad_U(q)                        | needs log_prob
 ppl.model        pack/unpack flat q ; potential_fn: q -> (U, grad_U)
    | replays model under handlers
 ppl.trace        sample()/observe(), trace/replay/condition/substitute/seed --> ppl.dist
    | constrained <-> real                                                       |
 ppl.autodiff     Tape, Node, ops, grad, value_and_grad <------------ ppl.transforms
    |
 ppl.core         RNG (PCG64/Philox), float64, logsumexp, finite-guards, errors
 ppl.diagnostics  split-R^, ESS, MCSE, BFMI, divergence summary (after sampling)
  1. CLI and driver. ppl.cli parses arguments and loads the model module and data JSON (§1.6). ppl.inference splits warmup from sampling, runs the chains in a process pool with seeds from SeedSequence.spawn, thins, and assembles a Posterior (§3.2, ADR-13, ADR-14).
  2. Kernel. ppl.mcmc holds RandomWalkMH, IndependentMH, Gibbs, HMC and NUTS. Each has init(q0) -> state and step(state, rng) -> (state', stats). The warmup adapters wrap the kernel during warmup and freeze afterwards (§3.2, P7).
  3. Model. ppl.model finds the free latent variables by one trace run, packs them into one flat real vector q, and exposes potential_fn(q) -> (U, grad_U) with U = -log_joint(unpack(q)) - log|det J|. It is the only interface the gradient kernels need (§3.2, §17.2).
  4. Trace, distributions, transforms, autodiff. ppl.trace re-runs the user's function under a stack of handlers to read the log-joint, ppl.dist supplies each log_prob, ppl.transforms maps constrained supports to the real line with Jacobian terms, and ppl.autodiff sweeps a recorded tape backwards to get grad_U (§3.2, §8.3).
  5. Core and diagnostics. ppl.core owns float64, the RNG wrapper, logsumexp and the typed errors, and all randomness flows through it (§3.2, P9). ppl.diagnostics reads the finished draws and never changes them (§3.2). The CLI diagnose prints PASS if all R̂<1.01, ESS_bulk≥400 and divergences=0 (§22.10); Operational Readiness also lists BFMI<0.3 and depth saturation as WARN reasons, which §22.10 does not (§22.10, Operational Readiness).

The core ideas

A program becomes a density and a gradient (§8.2, §8.3, P11)

Plain words: the model is just a function, and the engine runs it under different interpreters (effect handlers) to read off what it needs (§8.3, P11). trace records each call as a Site, replay forces the unknowns to chosen values and recomputes log probabilities, condition injects data, seed threads the RNG and block hides sites (§8.3). Handlers form a stack and the innermost runs last (§8.3). Running eight-schools under trace records its four sites in order: sample("mu", Normal(0., 5.)), sample("tau", HalfNormal(5.)), a vectorized sample("theta", Normal(mu, tau), shape=(J,)) and observe("y", Normal(theta, data.sigma), value=data.y) (§8.2). The log-joint is the sum of the site log-probabilities (§8.2). The model is re-executed on every kernel step with no graph caching, which the blueprint calls the cost of generality (§8.3).

The gradient comes from a reverse-mode autodiff tape. Each primitive op records its inputs, its output and a vector-Jacobian-product closure. grad seeds the output adjoint with 1.0 and sweeps the tape backwards (§3.2). It is the only source of grad_U (P6), and it is checked against central finite differences at rtol 1e-5 (I4, §17.4).

Sampling on the whole real line (§8.4, P4, I3)

Plain words: gradient samplers need smooth, unbounded space, so each constrained unknown is replaced by a free number and a mapping back (bijector) (§8.4, ADR-7). The mapping changes how volume is counted, so a correction term (log-Jacobian, log|det J|) is added to the target (§8.4).

Support Free number x maps to log|det J|
ℝ x 0
ℝ₊ (positive) exp(x) x
(a,b) interval a+(b−a)·σ(x) log(b−a)+log σ(x)+log(1−σ(x))

So for a positive unknown, the sampler moves x freely, the model sees exp(x), and x is added to the log-joint (§8.4). Skip that term and the posterior mode shifts toward whatever the transform compresses or expands most, yet every test of U at a fixed q still passes (MM4).

Metropolis–Hastings: propose, then accept or stay (§8.5, P2, I1)

Plain words: propose a nearby point, accept it with a probability that favors higher density and corrects for any unevenness in the proposal. This is Metropolis–Hastings. The rule is log α = min(0, logπ(q') − logπ(q) + logQ(q|q') − logQ(q'|q)) (§8.5):

state q  --propose--> q'   (q' ~ Q(.|q))
   |                    |
   |             compute log α = min(0, logπ(q') - logπ(q) + logQ(q|q') - logQ(q'|q))
   |                    |
   +----accept (u<e^α)--+--> q'      [I1 detailed balance]
   |                    |
   +----reject----------+--> q       (stay; still a valid draw)

For a symmetric random walk the two Q terms cancel. For IndependentMH the ratio includes importance weights. For Gibbs sampling, α=1 because each variable is drawn from its exact conditional (§8.5). Detailed balance is what makes the long-run distribution the target (MM2).

A check from the blueprint: θ ~ Beta(2,2), data [1,1,0,1], posterior Beta(5,3), mean 5/8 = 0.625, which any kernel must recover to within 3·MCSE (§8.10, §18.4).

HMC: roll a ball down the density (§8.6, P3, I2)

Plain words: treat −log density as a landscape, give the point a random push and simulate rolling, so proposals travel far yet are still accepted often. This is Hamiltonian Monte Carlo. The stages are (§8.6):

Stage Formula
Draw momentum p ~ N(0, M), M = mass matrix
Initial energy H0 = U(q) + 0.5 pᵀM⁻¹p
Leapfrog sub-step (×L, size ε) half kick p → p − (ε/2)·grad_U(q); drift q → q + ε·M⁻¹p; half kick again
Final energy, then accept H1 = U(q*) + 0.5 pᵀM⁻¹p; accept w.p. min(1, exp(H0 − H1))

Only this leapfrog integrator is allowed, because it is reversible and volume-preserving, which makes the accept step exact despite discretization error (P3, I2). The test is to run forward, then backward, and return to the start within 1e-8 (§19.4). Energy is conserved up to O(ε²), and a large energy error flags a divergence (geometry too sharp for ε) (§8.6).

NUTS: stop when the path turns back (§8.7, I11)

Plain words: HMC needs a trajectory length L. The No-U-Turn Sampler removes it by doubling the path, forward or backward at random, until it starts to curl back on itself (§8.7). A subtree built at depth j has size 2ʲ. The stop rule is (q⁺−q⁻)·p⁻ < 0 or (q⁺−q⁻)·p⁺ < 0, and the next point is picked from the whole tree with probability proportional to exp(−H) (§8.7). The default depth cap is 10, so at most 1024 leapfrog steps per iteration (§4).

Implementation traps the blueprint lists: check the U-turn at every subtree level, keep weights as logs combined with logsumexp, and stop on a divergence inside a subtree (§20.6). The tree keeps one proposal, so memory is O(depth) (§20.7). §20.2 passes a log_u argument to build_tree while also saying the final choice is multinomial, "not slice", and I11 says "multinomial/slice selection" (§20.2, I11). The blueprint does not settle which applies.

Warmup: tuning that stops before sampling starts (§8.8, §8.9, P7, I9)

Plain words: step size ε and the mass matrix are tuned automatically during the first stretch of the run and then frozen, because tuning while sampling breaks the Markov property (P7, I9). Two controllers do the work.

  • Dual averaging nudges log ε so the accept statistic reaches a target δ (0.8 for NUTS). It is a stochastic-approximation controller, not a grid search, with constants γ=0.05, t0=10, κ=0.75 and μ=log(10·ε0) (§8.8, MM6, §4). Each step, H̄_m = (1 − 1/(m+t0))·H̄_{m−1} + (1/(m+t0))·(δ − α_m) and log ε_m = μ − (√m/γ)·H̄_m; the averaged log ε̄ is the ε kept after warmup (§8.8).
  • Windowed mass-matrix estimation uses Welford's online variance on q. At the close of each window, M⁻¹ is set to the diagonal of the variance, or a covariance for small dimension, pulled toward the identity by Σ̂ = (n/(n+5))Σ + (5/(n+5))·1e-3·I. ε is re-found at each window boundary (§8.9).

The default 1000-iteration warmup is split as follows, and then everything is frozen, asserted by I9 (§4, §8.9, §21.2):

Segment Length What adapts
Init buffer 75 step size only
Expanding windows 25, 50, 100, … step size and mass matrix
Term buffer 50 step size only

Capacity item 8 works the windows: 875 iterations remain after the buffers, and 25+50+100+200+400 = 775 leaves one partial window of 100 (Capacity item 8).

The trade-offs — where engineers disagree

A hand-built reverse-mode tape (ADR-3)

Chosen: a hand-built reverse-mode tape, since the gradient costs about one pass and matches log-density adjoints (§9). Rejected: numeric differentiation, forward-mode, JAX (§9). When the rejected choice is right: low-dimensional posteriors where finite-difference cost is negligible, or symbolic engines such as SymPy where analytic gradients are derivable (§9).

Sample on unconstrained space (ADR-7)

Chosen: unconstrained ℝⁿ plus bijectors, because HMC needs smooth unbounded space (§9, P4). Rejected: staying constrained with reflection (§9). When the rejected choice is right: discrete-only models (Ising, HMM) where a reflecting boundary or direct enumeration avoids the transform overhead (§9).

NUTS as the default kernel (ADR-8)

Chosen: NUTS: turnkey, with no trajectory length L to tune (§9). Rejected: static HMC and plain MH (§9). When the rejected choice is right: posteriors with known correlated structure and a well-chosen fixed L, where static HMC gets more ESS per gradient by avoiding the U-turn overhead (§9).

Processes, not threads, for chains (ADR-13)

Chosen: a multiprocessing pool, because the CPU-bound work is limited by the GIL (§9). Rejected: threads and async (§9). When the rejected choice is right: models needing fine-grained inter-chain communication, such as replica exchange or parallel tempering, where shared-memory threads beat process serialization (§9).

Single-platform seed determinism (ADR-27)

Chosen: the same draws on the same NumPy/BLAS build; BLAS reduction order is out of scope (§9, §1.1). Rejected: bit-exact cross-platform reproduction (§9). When the rejected choice is right: publishing numerical results that must be reproduced on another machine or OS, where bit-exactness is a scientific reproducibility requirement (§9).

Roads not taken (Alternative Architectures, Deferred Features Register)

Random-walk Metropolis–Hastings wins in low dimension (d ≤ ~10), on discrete or non-differentiable targets, when debugging a new distribution before gradient plumbing exists, and when only log_prob is available. It loses here because accept rate degrades with d for a fixed scale, which is the 100–1000× gap above. The RandomWalkMH kernel still ships (Alternative Architectures, §18).

Variational inference (ADVI) wins when the posterior is roughly Gaussian and speed matters more than exactness, when parameters number in the millions, or to warm-start MCMC. It loses here because it yields a best-fitting Gaussian, not the true posterior, which conflicts with exact inference (P1, P2), and it is deferred (Alternative Architectures, §1.3).

Gibbs on conjugate conditionals wins when every full conditional is closed-form (Beta-Bernoulli, Normal-Normal, Gamma-Poisson), with acceptance 1 and no gradients. It loses as a general default because non-conjugate steps degrade to RW-MH quality and correlated variables mix poorly. It ships for conjugate sites (Alternative Architectures, §18).

Deferred features each wait for a trigger: variational inference for validated posterior sampling, SMC for a hardened core engine, GPU work for a green CPU conformance suite, Riemannian HMC for stable HMC/NUTS conformance, enumeration for validated MH/Gibbs, nonparametric priors for a stable trace runtime, and forward-mode for validated reverse-mode (Deferred Features Register).

What must never be false

  • I1: the MH accept probability is in [0,1] and uses the full proposal and Jacobian ratio. Noticed by an assert plus a unit test against a conjugate posterior.
  • I2: leapfrog is reversible and volume-preserving. Noticed by a reverse-trajectory test.
  • I3: log|det J| is added for every constrained variable. Noticed by a transformed-density versus base-density test; packing is refused without it.
  • I4: grad_U matches finite differences of U (rtol 1e-5). Noticed by the grad-check harness.
  • I5: trace replay under a fixed seed is deterministic. Noticed by a replay equality test.
  • I6: the mass matrix is symmetric positive-definite. Noticed by Cholesky success or an eigenvalue check. Recovery is a diagonal fallback plus regularization in I6, Failure Modes & Recovery ("Non-SPD mass") and Threat Model ("Mass-matrix singularity"), but §8.12 regularizes toward identity and raises NotPositiveDefiniteError if that fails, and the Failure Modes recovery philosophy lists non-SPD among the correctness failures that fail loud and abort. The blueprint does not reconcile them.
  • I7: U and grad_U are finite at every accepted state. Noticed by the finite-guard (NonFiniteError).
  • I8: per-chain RNG seeds are independent. Noticed by a seed provenance log.
  • I9: adaptation is frozen after warmup. Noticed by a flag check before sampling.
  • I10: samples respect the distribution's support. Noticed by a membership test (SupportError).
  • I11: NUTS keeps detailed balance through multinomial or slice selection. Noticed by an exchangeability test on a toy target.
  • I12: logsumexp is stable against overflow and underflow. Noticed by an extreme-value unit test.

What breaks in production

These are rows of the Failure Modes & Recovery table, cited by name. Correctness failures fail loud and abort; quality failures surface as diagnostics and runbook guidance, not silent fixes (P8, P10).

Divergences. Symptom: biased tails and energy errors. Cause: sharp curvature such as a funnel. Detection: the divergence flag. The step is rejected automatically; manual recovery is reparameterization or a higher target_accept, with the q locations as forensics (§19.10, §20.10).

Stuck chain. Symptom: accept rate near 0. Cause: scale too big for MH, ε too big for HMC, or NaN. Detection: accept rate. Warmup re-tunes automatically; otherwise check the NaN guards and scale.

NaN density. Symptom: the run aborts. Cause: log(0) or overflow. Detection: NonFiniteError with site and value context. There is no automatic recovery; fix the model, the data or the transforms (P8, I7).

Non-SPD mass matrix. Symptom: a Cholesky error. Cause: unidentified or collinear parameters. Detection: the SPD check (I6). Automatic recovery is a diagonal fallback plus regularization; manual is reparameterizing or dropping a redundant parameter (see the I6 note above).

Depth saturation. Symptom: high cost per iteration. Cause: ε too small after adaptation. Detection: depth equal to the cap, seen in the depth histogram. No automatic recovery; use a dense mass matrix or a longer warmup (§20.7, §20.10).

Bad diagnostics. Symptom: a false PASS. Cause: a bug in a diagnostic. Detection: a reference fixture compared against ArviZ. Recovery: fix the diagnostic and re-validate (§22.9).

Threats worth knowing. Model code is trusted, so the realistic threats are robustness and resource exhaustion, not privilege escalation (Threat Model):

  • Infinite or huge trace from a data-dependent unbounded loop is stopped by a per-execution site cap, raising TraceError (Threat Model, §8.12).
  • NaN/Inf poisoning from log(0) or overflow is met by finite-guards and log-space, and aborts the step loudly (I7, P5, P8).
  • Divergence storm from pathological geometry such as a funnel is met by the divergence threshold and reparameterization guidance (Threat Model, §8.13).
  • Untrusted pickle from loading a malicious file is avoided by storing arrays only in npz with no code pickling, and by rejecting non-conforming files (Threat Model, ADR-17).

Where the blueprint disagrees with itself (stated, not resolved):

  • Cost of a gradient. §2.1 says "roughly one extra forward pass" and the glossary says "~1 extra pass", while §4 and M3 bound it at ≤ ~3× the forward cost and MM5 says approximately 3× (§2.1, §4, M3, MM5).

  • Dense versus diagonal. §4 allows dense up to ~10³, Scalability Analysis and §21.7 say diagonal for d above ~500, and Capacity item 1 reserves dense for d ≤ ~200 (§4, §21.7, Capacity item 1).
  • R̂ with 1000 draws. §4 gates on R̂ < 1.01 and the default run is 1000 draws per chain (§4, §11.8), but Capacity item 7 says about 10 000 draws per chain are needed to separate 1.00 from 1.01 and that 1000 suffice for R̂ < 1.05 detection (Capacity item 7).
  • The ESS example. Capacity item 5 calls 4000 the raw-draw count of a default run and 400 the ESS target, then gives "4000/0.02 = 200 000" as the draws needed to reach 400 ESS (Capacity item 5, §4).

How it compares

Each line summarizes one column of the Comparative Architecture Table and the paragraph under it.

  • Stan compiles the model to C++ with C++ autodiff, where this design stays in Python. That is right for production workflows with large data and repeated fits, at the cost of a separate language.
  • PyMC differentiates through a PyTensor graph with a C++ backend, not a Python tape. That is right when graph rewrites and fused elementwise kernels pay off on large batched log-densities.
  • TFP builds samplers as composable kernels on TensorFlow's bijector API. That is right in TF-native stacks where model, data pipeline and sampler share one graph.
  • NumPyro runs all chains in one JIT-compiled call with JAX vmap. That is right for GPU-resident posteriors dominated by linear algebra, where process-level parallelism would be prohibitive.

Questions to test yourself

  1. NUTS selects the next state by multinomial sampling over the trajectory weighted by exp(−H). If the log-weights are computed as differences from the initial H rather than absolute H, can floating-point cancellation when H is very large cause multinomial probabilities to not sum to 1, violating detailed balance (I11)? How does P5 apply here, and at which phase is this validated? — Hint: §8.7 and §20.6.
  2. The dual-averaging controller uses a fixed μ=log(10·ε₀) (§8.8). If find_reasonable_epsilon returns a pathologically small ε₀ (e.g., 1e-10 due to a near-singular mass), the controller anchors to log(10·1e-10)≈−21 and may never recover to a useful ε. Which phase is responsible for the ε₀ initialization, and how does the lack of a lower-bound guard interact with the divergence threshold from §4? — Hint: §21.2 and §8.8.
  3. For the eight-schools hierarchical model (§8.2, centered parameterization), the funnel geometry makes divergences structurally unavoidable at any finite ε. NUTS detects them via energy threshold (§8.6). Is the energy threshold a sufficient diagnostic to distinguish "ε too large" from "funnel geometry"? What additional telemetry from Phase 9 or Phase 11 would allow a user to distinguish these two causes, and which principle (P8, P12) requires it to be emitted? — Hint: MM8, §8.13 and §20.10.
  4. The diagnostics in Phase 11 compute rank-normalized split-R̂ by splitting each chain in half. For short runs (draws<100), the halves have too few samples for stable rank transformation. The §4 default of 1000 draws/chain is safe, but the run_mcmc API allows draws=10. Which acceptance criterion in Phase 11 gates this, and should a hard minimum on draws be an invariant (I-level) or a warning-only check? — Hint: §22.4 and §22.8.
  5. The block handler hides sites from exposure (§8.3). If a model uses block to marginalize an auxiliary variable, the hidden site's log_prob is not added to log_joint. If that site has a non-trivial transform (e.g., a positive constrained variable), its Jacobian is also not added. Is this a bug or intended behavior for block, and what constraint in Phase 5 or Phase 6 must the user satisfy to avoid biasing U? — Hint: §8.3, §8.4 and I3.

If you only remember three things

The sampler must target exactly the posterior, so every accept step carries the full proposal and Jacobian correction, and leapfrog is the only integrator allowed (P1, P2, P3, I1, I2). Constrained unknowns are sampled on the real line with their log-Jacobian added, and the gradient comes from one tape over the same code that computes the density (P4, P6, I3, I4). Tuning stops after warmup, and a posterior is trusted only when R̂, ESS and the divergence count say so (P7, I9, P10).

Words used here

  • Log-joint: the sum of the log-probabilities of every latent prior and observed likelihood, an unnormalized log target (§8.2, Glossary).
  • Effect handler: an interpreter that changes what sample/observe do, such as trace or replay (§8.3).
  • Bijector: an invertible map with a tractable log-Jacobian, used to move to unconstrained space (§8.4).
  • Leapfrog: the reversible, volume-preserving integrator used by HMC and NUTS (P3, I2).
  • Mass matrix: the metric on momentum; approximates the posterior's inverse covariance once adapted (§8.9, MM10).
  • Divergence: a large Hamiltonian energy error that signals geometry the step size cannot resolve (§8.6).
  • Dual averaging: the controller that adapts the step size to a target accept rate (§8.8, MM6).
  • Warmup: the opening phase where adaptation runs and the draws are discarded (§8.9, Glossary).
  • R̂ (split, rank-normalized): a convergence score comparing chains and halves of chains; below 1.01 passes (§4, §22.2).
  • ESS: effective sample size, the number of independent-equivalent draws after autocorrelation (§22.2, MM7).
