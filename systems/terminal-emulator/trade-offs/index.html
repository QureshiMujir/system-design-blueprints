Decisions (§9) · 24 ADRs

ADR-01

Language

Chosen

Rust 1.78+ (MSRV pinned in rust-toolchain.toml)

Rejected

C, C++, Go

When the rejected choice is right

C/C++ win when FFI-zero-overhead with an existing huge codebase is the constraint (e.g. patching xterm itself); Go wins for a quick internal tool where GC pauses are tolerable and dev speed dominates

Why: Memory safety in an adversarial-input parser without GC pauses in the render path

ADR-02

Parser algorithm

Chosen

Paul Williams DEC state machine, verbatim

Rejected

Recursive-descent, regex-based line parser

When the rejected choice is right

A regex/line-based parser wins for a quick scripting-language terminal emulator (e.g. pyte) where correctness under malformed input is not a priority

Why: State machine handles overlapping byte classes (ESC/CSI/C1) correctly under adversarial input

ADR-03

Alt-screen model

Chosen

Two backing stores, swap pointer

Rejected

Single grid + alt-mode flag

When the rejected choice is right

The flag approach wins in memory-constrained embedded consoles where 2× grid memory is unaffordable and alt-screen is rarely used

Why: Structurally byte-perfect restore; flag-based rebuild is a known bug class

ADR-04

Scrollback structure

Chosen

Ring buffer (VecDeque-backed fixed slabs)

Rejected

Growable Vec<Line>

When the rejected choice is right

Vec<Line> wins for a one-shot batch log-replay tool that never needs bounded memory or steady-state insert cost

Why: Amortised O(1) push vs. O(n) shift-on-overflow

ADR-05

Default charset

Chosen

UTF-8; ISO 2022 SCS supported, not default

Rejected

ISO 2022 default

When the rejected choice is right

ISO 2022-default wins when targeting legacy mainframe/serial-console fleets still running pre-UTF-8 locales

Why: Modern shells assume UTF-8; legacy charset support exists for compatibility only

ADR-06

Ambiguous-width default

Chosen

UAX #11 narrow

Rejected

Wide-by-default

When the rejected choice is right

Wide-by-default wins in East-Asian-locale-only deployments where narrow-default misaligns box-drawing characters routinely

Why: Matches xterm/Alacritty/kitty/WezTerm consensus

ADR-07

GPU rendering

Chosen

wgpu + FreeType/CPU fallback

Rejected

Direct Vulkan/Metal/DX12 per-platform, OpenGL-only

When the rejected choice is right

Direct Vulkan wins when squeezing the last microsecond of latency on one fixed target platform (e.g. a game-console-embedded terminal)

Why: One shader pipeline across platforms via wgpu's abstraction

ADR-08

Ligature shaping

Chosen

HarfBuzz (FFI)

Rejected

Reimplement OpenType shaping in Rust

When the rejected choice is right

A pure-Rust shaper (e.g. rustybuzz) wins when avoiding a C FFI boundary entirely is a hard organizational requirement

Why: HarfBuzz is the industry-standard shaping engine; reimplementing risks subtle GSUB/GPOS bugs

ADR-09

Keyboard protocol

Chosen

Kitty keyboard protocol + legacy CSI fallback

Rejected

Legacy CSI only

When the rejected choice is right

Legacy-only wins for an emulator that must work identically to a 1990s xterm with zero new escape sequences (a compatibility-testing harness, e.g.)

Why: Legacy encoding cannot disambiguate Ctrl-Tab from Ctrl-I; kitty protocol is lossless

ADR-10

OSC 52 clipboard policy

Chosen

Reads require explicit per-window consent; writes allowed

Rejected

Both allowed by default

When the rejected choice is right

Allow-both-by-default wins in a fully sandboxed, single-user, air-gapped environment where the clipboard threat model does not apply

Why: Closes the dominant clipboard-exfiltration CVE surface (T3)

ADR-11

Parser resource limits

Chosen

max_params=16, max_osc_bytes=4096, max_dcs_bytes=65536

Rejected

No caps (xterm's historical unbounded params)

When the rejected choice is right

Uncapped wins only for a trusted, closed, non-adversarial embedded console (e.g. a factory-floor serial display with no attacker model)

Why: Closes the historical OSC/DCS heap-exhaustion CVE class

ADR-12

Cross-platform PTY

Chosen

openpty/forkpty (Unix) + ConPTY (Windows)

Rejected

WSL-only on Windows, no native Windows support

When the rejected choice is right

WSL-only wins for a Linux-first project explicitly scoping out native Windows support to cut maintenance cost

Why: Native Windows users get a first-class experience

ADR-13

Workspace structure

Chosen

When the rejected choice is right

A single crate wins for a small prototype where compile-time crate-boundary overhead outweighs the enforced-boundary benefit

Why: Enforces the parser/performer/grid/renderer module boundaries at the compiler level

ADR-14

Packaging/release

When the rejected choice is right

ADR-21

Build reproducibility

Chosen

Cargo.lock committed; cargo vendor for release builds

Rejected

Floating dependency versions

When the rejected choice is right

Floating versions win during early prototyping where dependency churn is expected and desired

ADR-22

Time source

Chosen

Monotonic clock (Instant) for frame pacing and timeouts

Rejected

Wall-clock (SystemTime) for pacing

When the rejected choice is right

Wall-clock wins when the value must be human-displayed (e.g. a status-bar timestamp), never for pacing

Why: Wall-clock jumps (NTP step, DST) would corrupt frame-pacing and watchdog logic

ADR-23

Backpressure

Chosen

Rely on the kernel PTY pipe buffer (64 KB); no internal write queue

Rejected

An internal unbounded write queue

When the rejected choice is right

An internal bounded queue wins when a host needs to buffer writes across brief PTY-write EAGAIN spikes (e.g. mid-resize) — the 4 KB paste-chunking (§21) is exactly this narrow case

Why: An internal queue would hide backpressure and let a hung child process leak memory

Licensing

Chosen

Dual MIT/Apache-2.0

Rejected

GPL-family copyleft

When the rejected choice is right

Copyleft wins when the project's goal is to force downstream contributions back upstream (not a goal here)

Why: Matches the Rust ecosystem convention (vte, wgpu, winit are all MIT/Apache-2.0) and eases embedding by proprietary hosts

37. Alternative Architectures (Roads Not Taken)

Alt-1 — Regex/line-based parser (no state machine).

byte stream ──▶ [line buffer] ──▶ [regex match against known sequences] ──▶ grid

Regime where it wins: a scripting-language terminal emulator whose users value readability of the parser source over correctness under malformed/adversarial input (quick prototyping, teaching tools). Real embodying system: pyte (the Python terminal emulator library). Rejected here because line-buffering cannot handle a control byte arriving mid-sequence without unbounded lookahead, and regex matching against overlapping sequence shapes (ESC vs CSI vs 8-bit C1) is provably ambiguous in exactly the cases §8.2's state machine resolves cleanly (MM1, MM7).

Alt-2 — Single grid with an alternate-screen flag.

┌─────────────┐   if (alt_flag) { apply-with-offset() }  else { apply-direct() }
│  One Grid   │◀──────────────────────────────────────────────────────────────
└─────────────┘

Regime where it wins: a minimal embedded serial-console emulator where alternate-screen mode is rarely or never exercised and memory is scarce enough that a second backing store is unaffordable. Real embodying system: many minimal embedded console emulators (e.g. BusyBox's microcom) that skip alt-screen entirely rather than implement it half-heartedly. Rejected here because the flag approach's restore-on-exit path is a well-documented bug class (MM5) the moment alt-screen is a first-class, frequently-used feature (vim, less, tmux — the majority of real-world terminal usage).

Alt-3 — Immediate-mode full repaint (no damage tracking).

every frame: for row in 0..rows { for col in 0..cols { draw(cell) } }   // no dirty check

Regime where it wins: a small, fixed, low-resolution grid (e.g. an IoT device's 16×2 character display, or an early low-bandwidth SSH client with a tiny window) where the total cell count is small enough that full repaint costs less than dirty-bitmap bookkeeping. Real embodying system: many early serial-terminal emulators and simple SSH-client "terminal views" that redraw the whole visible buffer per update. Rejected here because a 500×500-cell grid (§4's max) at 60 Hz makes full repaint the dominant cost (MM3), directly violating the M3/M4 latency budgets.

Alt-4 — A structured buffer API instead of a byte-stream escape protocol.

App ──▶ WriteCellAPI(row,col,attrs,glyph) ──▶ Console buffer (no parser needed at all)

Regime where it wins: a fully vendor-controlled, single-ecosystem stack where every program targeting the console is recompiled against the same API and cross-shell/Unix compatibility is not a goal. Real embodying system: the pre-ConPTY Windows Console API (direct WriteConsoleOutput buffer manipulation), which Microsoft itself moved away from via ConPTY specifically to gain Unix-shell compatibility (§5 Required Reading, ConPTY docs). Rejected here because this project's entire value proposition (§1, §2) is interoperating with the forty-year installed base of shells and TUIs that emit ECMA-48/xterm byte sequences — a structured API forecloses exactly that compatibility.
