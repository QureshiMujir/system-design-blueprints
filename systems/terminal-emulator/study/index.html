Hard questions (§36)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why must the parser be pure (no grid access) even though it would be simpler to let it call directly into the grid? (§7 I7, §8.2, MM2)
  2. Trace the exact sequence of states and actions for ESC [ 38 : 2 : : 255 : 0 : 0 m and explain why the missing color-space subparameter does not abort the sequence. (§8.2, §16.2)
  3. Why is alternate-screen mode implemented as two backing stores rather than a conditional flag, and what specific bug class does the flag approach introduce? (§7 I4, §15.6, MM5)
  4. Derive the scrollback memory ceiling for a 50,000-line, 200-column configuration and state which System Constraint it would violate. (§4, §35 item 1)
  5. Why does a false-positive dirty cell cost less than a false-negative one, and where in the codebase is that asymmetry enforced? (§7 I3, §19.6, §20.2)
  6. What is the concrete difference between max_osc_bytes truncation behaviour and simply dropping the whole malformed sequence, and why does the design choose truncation? (§8.4, ADR-11, Threat Model T1)
  7. Why does OSC 52 have an asymmetric policy (writes default-allow, reads default-deny) instead of gating both identically? (P12, ADR-10, Threat Model T3)
  8. Explain the race between a window resize and an in-flight PTY read, and name every phase section that references the same mutex. (§13.8, §15.8, §20.8, Threat Model T10)
  9. Why is the renderer forbidden from re-parsing input even for a "quick fix" to a rendering bug, and what invariant would that violate? (§7 I6, §3)
  10. Compare this design's single-parser-thread-per-session model (P13) to a hypothetical design that shards one session's byte stream across multiple parser threads — what specifically breaks? (§32, P13, MM7)
  11. Using the Back-of-Envelope Capacity Model, compute how many concurrent sessions a host with ulimit -n 4096 could support, and identify the next bottleneck after FDs. (§35 item 5, §32)
  12. Why does the kitty keyboard protocol need to exist at all — what specific ambiguity in the legacy CSI encoding does it resolve, and for which class of application does it matter? (§21.2, ADR-09, §2 "What Mastery Looks Like")
  13. Explain why HarfBuzz-based ligature shaping must run per-attribute-run rather than per-line, using a concrete bold/non-bold boundary example. (§22.2, §22.6)
  14. What would break if UAX #29 grapheme clustering were skipped and the grid instead stored one char per cell? (§7 I9, §17.2, MM1)
  15. Compare the Comparative Architecture Table's account of Alacritty's GPU-only choice against this design's CPU+GPU dual-backend choice — under what deployment constraint does Alacritty's choice dominate? (§34, ADR-07)
  16. Why is the 30-day canary necessary given that the 21-bucket conformance suite already runs on every PR — what bug class does only the canary catch? (§24.9, FM-10, §35 item 6)
  17. Trace how a single HyperlinkId could become a stale reference, and name the invariant and data structure that prevent it. (§7 I13, §23.2)
  18. Using the ADR table's sixth column, identify a regime where this design's own locked choice (Rust, ADR-01) would lose to C++, and explain what capability gap remains even then. (§9 ADR-01, §1)
  19. Why does the differential fuzzer's discovery of a "divergence" not automatically mean a bug — walk through the triage procedure and the specific fixture-marker mechanism that closes the loop. (§8.5, §24.8)

33. Mental Models & First Principles

  1. MM1 — A terminal is a compiler for a byte stream into a 2D data structure. The parser is the front end (lexer+parser fused, §8.2), the performer is the code generator, the grid is the object code. Predicts: any "just regex the escape codes" design will hit the same overlapping-grammar wall a hand-rolled tokenizer hits on a real language. Bug class avoided: ambiguous-sequence misparses (ESC vs CSI vs 8-bit C1, §14.6). Applied in §8, §14.
  2. MM2 — State belongs to exactly one owner; everyone else is a read-only view. The performer owns grid state (I7); the renderer is a view (I6); the parser owns none. Predicts: any bug where "two things can both write X" traces back to a violation of this rule. Bug class avoided: torn writes, renderer-induced corruption. Applied in §7 (I6, I7), §15.
  3. MM3 — Dirty tracking trades a small constant cost per mutation for a large win at render time. Every mutation marks its cell(s) dirty (O(1) amortised); render only visits the dirty set. Predicts: a system without this either over-renders (wasted cycles) or under-renders (visible corruption) — there is no free third option. Bug class avoided: full-repaint-every-frame performance cliffs at scale. Applied in §7 (I3), §19, §20.
  4. MM4 — A resource budget converts an unbounded-input DoS into a bounded-degradation event. Every parser accumulator has a cap (ADR-11); exceeding it truncates, never crashes or hangs. Predicts: any "attacker controls the input, no cap exists" design is a live DoS/CVE waiting for a fuzzer to find it. Bug class avoided: the entire historical OSC/DCS-overflow CVE lineage. Applied in §8.4, §14, Threat Model T1/T2.
  5. MM5 — Two backing stores beat one store plus a flag whenever "restore" must be exact. A flag-conditioned code path accumulates subtle asymmetries between the "normal" and "flagged" cases over time; two independent stores cannot leak into each other by construction. Predicts: any single-store-plus-flag design will eventually corrupt the non-active state. Bug class avoided: alt-screen restore bugs (P5). Applied in §7 (I4), §15.
  6. MM6 — Logical order and visual order are different coordinate systems; conflating them breaks the moment either RTL or reflow enters the picture. The grid stores logical order always; BiDi and (eventually) reflow are view-time transforms with an explicit mapping cache. Predicts: any renderer that "just draws cells left to right" is only correct for LTR-only content. Bug class avoided: RTL cursor-placement and selection bugs. Applied in §22.
  7. MM7 — A protocol's "final byte determines meaning" design (CSI's dispatch-on-final- byte) trades ambiguity during accumulation for certainty at completion. Predicts: any premature interpretation of an in-progress CSI sequence (before the final byte arrives) is necessarily wrong for some parameter count. Bug class avoided: partial- sequence misdispatch. Applied in §8.2, §14.
  8. MM8 — Security in a byte-stream parser is a robustness property, not a policy property, until the very last mile (the clipboard). Parsing-robustness (bounded accumulators, no panics) closes most terminal CVEs structurally; only the OSC 52 clipboard-read case additionally needs a policy decision, because it crosses a trust boundary (arbitrary program output → the user's system clipboard). Predicts: a threat model that only reasons about "policy" and ignores parser robustness will miss T1/T2/ T9/T11/T12. Applied in §25.

5. Required Reading

Books

  • DEC VT100/VT220 Programmer's Reference Manuals. The VT102/VT220 behaviour description every terminfo entry assumes as baseline. Applied in §8 (Domain Model) and §14 (Phase 2 — DEC Parser).
  • ECMA-48 (5th ed., 1991) — Control Functions for Coded Character Sets. The C0/C1 control tables, CSI parameter syntax, and SGR parameter list. Applied in §8 and §16 (Phase 4 — SGR, Palette & Cursor).
  • XTerm Control Sequences (Dickey), invisible-island.net/xterm/ctlseqs/ctlseqs.html. The most-referenced extension surface in shell scripting. Applied in §8, §9 (ADR Table), and §21 (Phase 9 — Input Encoder).
  • The Unicode Standard, core chapters on character encoding model. Applied in §17 (Phase 5 — Character Sets, UTF-8 & Cell Width).
  • The OpenType Specification, GSUB/GPOS tables. Applied in §22 (Phase 10 — Ligatures & BiDi).
  • Microsoft ConPTY design documentation (Windows Command-Line team). The pseudoconsole API replacing the legacy console subsystem. Applied in §13 (Phase 1 — PTY Layer).

Papers

  • Paul Williams, A Parser for DEC's ANSI-compatible Video Terminals (VT500-series state machine), vt100.net. The canonical eleven/thirteen-state machine. Applied in §8 and §14.
  • UAX #11 — East Asian Width. Cell-width resolution for CJK/ambiguous characters. Applied in §17.
  • UAX #29 — Unicode Text Segmentation. Grapheme-cluster boundaries. Applied in §17.
  • UAX #9 — Unicode Bidirectional Algorithm. RTL/LTR reordering at render time. Applied in §22.
  • Egmont Koblinger, OSC 8 Hyperlinks (2017). The hyperlink escape-sequence spec. Applied in §23 (Phase 11 — Image Protocols, Hyperlinks & Clipboard).
  • Davis, Coghlan, Servant, Lee, The Impact of Regular Expression Denial of Service (ReDoS) in Practice (ESEC/FSE 2018). The unbounded-CPU-on-adversarial-input pattern; substitute "ANSI escape sequence" for "regex" and the budgeting argument (ADR-11) transfers directly. Applied in §25 (Threat Model) and P11.
  • WHATWG Encoding Standard. UTF-8 error-handling (replacement-character-and-resync) used for malformed byte sequences. Applied in §17 and §8 (malformed-input example).
  • DEC Sixel Format Description (DEC technical manual). The six-vertical-pixel bitmap encoding. Applied in §23.

Reference Implementations

  • alacritty/alacritty, esp. alacritty_terminal/src/term/mod.rs and the vte crate. The cleanest production Rust implementation of the parser/performer split. Applied in §8, §14, §15. Pitfall not to copy: Alacritty's early scrollback used a VecDeque<Vec<Cell>> with per-line heap churn — the ring-of-fixed-slabs design here (ADR-04) avoids that allocator pressure.
  • The xterm source tree, xterm/charproc.c, xterm/screen.c. Forty years of corner-case fixes; the reference for ambiguous xterm-extension behaviour. Applied in §14, §16.
  • wez/wezterm, the termwiz crate. Cross-platform parity, the cleanest Windows-side Rust implementation. Applied in §13, §21.
  • kovidgoyal/kitty, kitty/parser.c, kitty/screen.c. The de-facto reference for the keyboard protocol and the image protocol. Applied in §21, §23.
  • vte / libvterm (the C library underlying neovim's terminal buffer). A second, independent state-machine implementation useful for differential testing. Applied in §14, §24 (Phase 12 — differential fuzzing).

RFCs / Specifications

  • ECMA-48 / ANSI X3.64 (control functions) — applied in §8, §16.
  • XTerm Control Sequences (Dickey) — applied in §9, §21.
  • Kitty Graphics Protocol specification — applied in §23.
  • iTerm2 Image Protocol specification (OSC 1337) — applied in §23.
  • OSC 52 clipboard specification (xterm docs + kitty security notes) — applied in §23, Threat Model T3.

The literature on terminal emulators predates most other systems-software sub-fields; most corner cases are known and documented above. If a post-2026 source supersedes one of these, an ADR records the change.

Glossary (§39) · 46 terms · site-wide glossary

Action
one of the eleven side effects the parser emits to the Performer (§8.2).
Alternate screen
the second backing store activated by CSI ?1049h, restored on ?1049l; carries no scrollback (P5, P6, I4).
APC
Application Program Command; an ECMA-48 sequence whose body is application-defined; used by the kitty graphics protocol (§23).
Atlas (glyph atlas)
a large GPU texture holding pre-rasterised glyphs, consumed by the GPU renderer (§20, ADR-07).
Bracketed paste
a mode wrapping pasted text in ESC[200~/ESC[201~ so an application can distinguish paste from typed input (§21, Threat Model T8).
C0
the lower 32 ASCII control bytes (0x00–0x1F).
C1
a parallel set of single-byte control codes (0x80–0x9F), rarely seen as raw bytes in modern 8-bit-clean-disabled practice (§14.6).
Cell
the typed value at a (row, col) grid position (§11).
ConPTY
Microsoft's pseudoconsole API on Windows 10+ (§13, ADR-12).
CSI
Control Sequence Introducer, the ESC [ prefix to the most common escape sequences (§8.1).
Damage tracking
the general term for dirty-region tracking that lets a renderer skip unchanged cells (I3, §19, §20).
DA1/DA2/DA3
Device Attributes responses; the terminal identifies itself to the application (P10, §11).
DCS
Device Control String, the ESC P prefix to sequences whose body is consumed verbatim until ST (§8.1, §23 for sixel).
DEC
Digital Equipment Corporation, whose VT100/VT102/VT220 terminals standardised the modern terminal protocol (§5).
DECCKM
DEC Cursor Keys Mode; toggles whether cursor keys emit CSI A or SS3 A.
DECRQSS
DEC Request Status String; asks the terminal to report its state (Threat Model T5).
DECSLRM
DEC Set Left and Right Margins (§15.2).
DECSTBM
DEC Set Top and Bottom Margins (§15.2, §15.6).
Dirty bitmap
the per-row (or per-cell) tracking structure recording which cells changed since the last render (I3).
DSR
Device Status Report, a status query (Threat Model T5).
ECMA-48
the standard documenting ANSI/ISO control functions underlying escape codes (§5).
ESC
the byte 0x1B, the prefix to most multi-byte sequences (§8.1).
G0/G1/G2/G3
the four character-set slots designated via ISO 2022 SCS (§17.2).
Grapheme cluster
a UAX #29 user-perceived character, possibly multiple codepoints (I9, §17.2).
Grid
the two-screen, dirty-tracked data structure holding all visible and scrolled-back cell state (§11, §15).
Hyperlink
an OSC 8-attached URI associated with a range of cells via a HyperlinkId (I13, §23).
Kitty keyboard protocol
a modern, lossless keyboard encoding originated by the kitty terminal project (ADR-09, §21).
Ligature
a multi-codepoint glyph produced by OpenType shaping, e.g. == rendering as one glyph (§22).
modifyOtherKeys
an xterm keyboard-encoding extension disambiguating Ctrl-letter from the C0 control byte (§21.2).
OSC
Operating System Command, the ESC ] prefix to sequences terminated by BEL or ST (§8.1, §23).
Parser state machine
the Paul Williams DEC state machine implemented verbatim by tem-parser (P1, §8.2, §14).
Pending wrap
the cursor flag marking "at the right margin, the next print will wrap" (§11 Cursor, §15.6).
Performer
the trait/component consuming parser actions and mutating the grid (I7, §11).
PTY
Pseudo-TTY, a kernel-mediated pair of file descriptors mimicking a serial terminal (§13).
Ring buffer
the fixed-capacity FIFO structure backing scrollback (ADR-04, §18).
Scroll region
the row (and optionally column) range within which scroll operations apply (ScrollRegion, §11, §15).
Scrollback
lines that have scrolled off the top of the main screen, held in the ring buffer (P6, §18).
SGR
Select Graphic Rendition, the CSI Pm m sequence setting cell attributes (§16).
Sixel
a DEC bitmap image format encoding six vertical pixels per byte (§23).
SOS
Start of String, a rarely used ECMA-48 sequence (§8.2 SosPmApcString).
ST
String Terminator, ESC \ (§8.1).
Surrogate pair
a pair of UTF-16 code units jointly encoding one codepoint outside the BMP (relevant to host-side text APIs, not this system's internal UTF-8 model).
Synchronized output
DEC private mode 2026, buffering renderer updates between BSU/ESU to avoid multi-step-redraw flicker (§18.2, §20.2).
UAX #9
the Unicode annex defining the Bidirectional Algorithm (§22).
UAX #11
the Unicode annex defining East Asian Width (§17).
UAX #29
the Unicode annex defining grapheme-cluster boundaries (§17).
