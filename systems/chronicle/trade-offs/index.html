ADR-01

Core language

Chosen

Rust

Rejected

Go, C++, Python

When the rejected choice is right

Go wins once GC pause tuning is proven safe for the capture path and prototyping speed outweighs the risk

Why: predictable latency, memory safety on untrusted-file parsing, single static binary

ADR-02

CFS version scheme

Chosen

SemVer-aligned major.minor in header

Rejected

date-based versioning, single incrementing integer

When the rejected choice is right

date-based versioning wins for consumer-facing release trains driven by marketing cadence, not wire formats

Why: aligns wire-format compatibility rules with widely understood semantics

ADR-03

Record encoding

Chosen

CBOR (RFC 8949)

Rejected

JSON, Protobuf, MessagePack

When the rejected choice is right

JSON wins for a human-diffable config file where text-editability outweighs size

Why: compact binary, schema-less enough for forward-compat unknown-field skip

ADR-04

Content digest algorithm

Chosen

SHA-256

Rejected

BLAKE3, MD5, SHA-1

When the rejected choice is right

BLAKE3 wins when hashing throughput is the binding constraint and no compliance regime mandates SHA-2

Why: wide tooling support, acceptable throughput, no known practical collision

ADR-05

Blob compression

Chosen

zstd

Rejected

gzip, lz4, brotli

When the rejected choice is right

lz4 wins when decompression latency alone dominates, e.g. a live-tail viewer over a slow link

Why: best ratio/speed tradeoff at Chronicle's chunk sizes, dictionary training support

ADR-06

Chunking algorithm

Chosen

FastCDC (gear hash)

Rejected

fixed-size chunking, Rabin-fingerprint CDC

When the rejected choice is right

fixed-size chunking wins for pure append streams with no interior edits, e.g. terminal-only capture

Why: faster boundary computation at comparable dedupe quality (Xia et al. 2016)

ADR-07

Index storage engine

Chosen

embedded SQLite page image

Rejected

custom B-tree, LMDB, in-memory-only index

When the rejected choice is right

LMDB wins once the protocol server must serve lock-free reads at multi-tenant QPS beyond single-developer scale

Why: mature single-file transactional format (Hipp 2017), ubiquitous read tooling

ADR-08

Local IPC transport

Chosen

Unix domain socket / named pipe

Rejected

TCP loopback, gRPC over HTTP/2, shared memory

When the rejected choice is right

TCP loopback wins when daemon and IDE run in separate container/VM namespaces without a shared socket path

Why: lowest-latency same-host transport with filesystem-permission access control

ADR-09

Wire framing

Chosen

length-prefixed CBOR frames

Rejected

newline-delimited JSON, Protobuf varint framing

When the rejected choice is right

newline-delimited JSON wins for ad-hoc manual inspection via nc/curl, not production capture

Why: binary-safe, no escaping needed for arbitrary payload bytes

ADR-10

DAP integration model

Chosen

passive proxy/observer

Rejected

active DAP client replacing the IDE's own, custom per-language debugger plugin

When the rejected choice is right

a custom per-language plugin wins only for a debugger with no DAP implementation at all

Why: never interferes with the IDE's own debugging session (I10, Phase 6 pitfalls)

ADR-11

Cross-tool protocol shape

Chosen

custom local RPC, LSP-shaped capability negotiation

Rejected

REST over HTTP, GraphQL

When the rejected choice is right

REST wins once a browser-based dashboard is a first-class consumer needing standard HTTP caching

Why: matches adapter capability-negotiation model already used for IDE/DAP (P10)

ADR-12

Concurrency model

Chosen

async single-writer daemon with message-passing scheduler

Rejected

shared-memory multi-writer, thread-per-connection blocking

When the rejected choice is right

thread-per-connection wins for a low-connection internal tool where async runtime overhead isn't justified

Why: one writer keeps CFS append ordering trivially correct (I7)

ADR-13

Redaction engine

Chosen

rule-set regex + Shannon-entropy heuristic scan

Rejected

ML-based secret classifier, allow-list only

When the rejected choice is right

an ML classifier wins once a large labeled false-negative/positive corpus exists to train against

Why: deterministic, auditable, no training corpus dependency at launch

ADR-14

Export encryption

Chosen

asymmetric envelope (X25519 + ChaCha20-Poly1305, age-style)

Rejected

When the rejected choice is right

password-only symmetric wins for a single-user local backup with no key-distribution need

Why: no shared-secret distribution problem, recipient-scoped keys (I11)

ADR-15

Terminal capture encoding

Chosen

When the rejected choice is right

ADR-16

Snapshot diff algorithm

Chosen

When the rejected choice is right

ADR-17

Session rotation policy

Chosen

Rejected

When the rejected choice is right

size-only rotation wins in a storage-constrained embedded target where wall-clock boundaries are irrelevant

ADR-18

Keyframe cadence

Chosen

dual threshold: 2 min or 200 deltas

Rejected

When the rejected choice is right

no keyframes wins for sessions guaranteed under 5 minutes, e.g. a CI-triggered capture with a hard timeout

ADR-19

Frame checksum algorithm

Chosen

Rejected

When the rejected choice is right

36. Alternative Architectures (Roads Not Taken)

(a) Full deterministic syscall-level record/replay, Chronicle as a viewer atop it.

[app process]--syscalls-->[rr/Pernosco-style tracer]--trace-->[trace store]
                                                          |
                                                    [Chronicle viewer]
                                                    (queries trace via
                                                     its own index, no
                                                     independent capture)

Winning regime: post-mortem debugging of a crash where instruction-level determinism is the entire point. Real embodying system: rr / Pernosco (§33, §5's O'Callahan citation). Rejected here: overhead and platform-coupling (ptrace-based syscall interception) are incompatible with §4's ≤2% CPU / any-language-IDE goal (§1's non-goal boundary) — Chronicle targets tool-level developer questions (Ko & Myers, §5), not instruction-level ones.

(b) Screen recording plus OCR.

[screen capture]--video frames-->[OCR pass]--text-->[searchable index]

Winning regime: capturing a workflow with no programmatic access to the tool at all (a closed proprietary app with no extension API). Real embodying system: various screen-recording-plus-search tools in the QA/support-ticket space (no single canonical named project reaches reference-implementation status here). Rejected here: no structural fidelity (no BufferState, no EditDelta, no digest-addressable content, P6 inapplicable), OCR error rate makes redaction (P5) unreliable at the pixel level, and replay determinism (I4) is meaningless over lossy video.

(c) A git-commit-per-checkpoint model, no custom format.

[editor event]--debounced-->[git commit to a shadow branch]
                                        |
                                  [git log / git diff
                                   as the "replay" UI]

Winning regime: a team already fluent in git tooling wanting checkpoint-granularity history with zero new format to learn. Real embodying system: git itself (§33). Rejected here: commit granularity (seconds-to-minutes) cannot meet §4's 250 ms/512-event capture cadence; git has no first-class terminal-output, debugger-state, or cursor-position record kinds; and P2's append-only guarantee would fight git's mutable-ref/rebase-capable object model constantly.

(d) A cloud-streamed session with no local file.

[capture agent]--stream-->[cloud ingest]--store-->[cloud session store]
                                                          |
                                                   [any client, query
                                                    over network]

Winning regime: a team-wide, always-shareable, no-local-storage session model where cross-developer query (§31's deferred lever) is the primary goal, not local debugging speed. Real embodying system: no single reference implementation matches this shape precisely for developer-session capture; closest conceptually is a hosted logging/APM pipeline. Rejected here: violates P12 (telemetry never leaves the machine by default) outright as an architecture, not just a default; also reintroduces the T5/T8 shared-machine and unauthorized-read threat surface at cloud scale instead of local-socket scale.
