IDE adapter: subscribes to the host editor's document and selection change events, buffer open/close, and VCS HEAD movement; translates host-native events into CFS record drafts; never blocks the editor's UI thread (P1).

DAP adapter: attaches as a passive DAP middleman/observer, capturing stack frames, scope variables, watch expressions, and breakpoint state on each stop event; never issues evaluate requests that could have side effects (Pitfall in Phase 6).

Terminal/PTY tap: wraps the integrated terminal's pseudo-terminal, capturing raw byte output and timing, modeled after the asciinema cast v2 event stream.

Capture scheduler: the single choke point all three sources feed into; owns the bounded event queue, batches events into frames at the configured cadence (§4), and applies backpressure by coalescing rather than blocking (P1, P3).

Redaction/scrubber: scans every record's payload against the active RedactionRule set before any byte reaches the chunker (P9); a record that fails to scan cleanly within budget is quarantined, never silently dropped (I5).

Chunker + content-addressed store: splits blob payloads into content-defined chunks (FastCDC, Xia et al. 2016) and stores each chunk once, addressed by digest, feeding the CFS writer only new digests.

CFS writer: appends frames to the open session file, sealing each frame with a checksum before the next is started (I1); never rewrites a previously sealed byte range.

Index: a side table (SQLite-backed, per ADR-11) mapping timestamps, record kinds, and digests to byte offsets, rebuildable from the frame stream if it is lost or stale (I6).

Snapshot differ: computes structural deltas between two snapshots on demand, using an O(ND) core (Myers 1986) generalized to non-text state.

Replay engine: reconstructs a BufferState/debugger/terminal view at an arbitrary timestamp by walking keyframes forward, exposing a seekable ReplayCursor.

Protocol server: exposes query/replay/subscribe RPCs over the local socket so non-Chronicle tools can consume a session without linking cfs-core.

Export/share: packages a session (optionally a redacted, time-bounded slice) into a portable, optionally encrypted archive for cross-machine transfer.

Telemetry: local-only counters and structured logs (capture latency, queue depth, dedupe ratio) consumed by Chronicle's own operators, never transmitted by default.

Content-Defined Chunking + Dedupe Model

Chunk boundaries are determined by a FastCDC-style gear hash (Xia et al. 2016) over blob payload bytes, target average chunk size 8 KiB, minimum 2 KiB, maximum 64 KiB. Each chunk is digested (content address, P6); the store holds one copy per unique digest per session, with an optional cross-session shared pool gated by Threat Model row T2. Dedupe ratio (§4) is measured as raw-bytes-referenced ÷ unique-bytes-stored.

Snapshot Model

A Snapshot is either Full (every tracked buffer, debugger frame, and terminal cursor state, self-contained) or Delta (references a prior snapshot digest plus a set of EditDelta/state-change records). Keyframe cadence: one Full snapshot per 2 minutes of active session time, or every 200 accumulated delta records, whichever first — this bounds replay-seek cost (§4) independent of session length (P8).

Timeline / Index Model

The index footer maps: (a) sequence number → byte offset, (b) timestamp range → nearest keyframe sequence number, (c) content digest → blob byte offset, (d) record kind → sequence number list (for filtered queries, e.g. "all TestResult records"). The index is a derived, rebuildable projection (I6) stored as an embedded SQLite page image (ADR-11, Hipp 2017) for query convenience, never as the sole record of truth.

Diff Semantics

diff(SnapshotA, SnapshotB) produces a DiffResult: a per-buffer text diff (Myers 1986, O(ND) core) plus structural diffs for non-text state (debugger scope tree, terminal cursor, VCS position) expressed as add/remove/modify triples keyed by stable field identifiers. Diff is symmetric per P11: applying the inverse diff to B reproduces A's digest exactly.

Worked Example

A developer opens main.rs, types for 40 seconds, hits a breakpoint, inspects a variable, and saves. Records emitted, in sequence: BufferOpen(main.rs) → several coalesced BufferEdit (P3) → DebuggerAttach → DebuggerStop (breakpoint) → DebuggerVariable (inspected var) → BufferEdit (save-triggered formatting) → periodic Keyframe (2-minute cadence) → eventually SessionEnd/Seal on workspace close.

Malformed-File Examples

  • Truncated header length field (declares 4096 bytes, file ends at byte 1200): reader rejects the file at open with a byte-offset error (P13), refuses to guess a shorter header.
  • Frame with payload length exceeding remaining file size: reader treats this frame as the crash boundary (I1) if it is the last frame; treats it as corruption if frames follow it (P13, contradicts I1's crash-tolerance so it is a hard reject with byte offset named).
  • Digest mismatch on a referenced blob: reader marks the specific blob corrupt (I2), continues serving other blobs, flags the session as partially untrustworthy rather than refusing the whole file.

Torn-Write / Crash-Mid-Frame Failure Path

Writer crashes after writing frame magic, sequence number, and record kind, but before the payload and checksum are flushed. On next open, the reader walks the frame stream forward; the last frame's checksum fails to validate against its (incomplete) bytes; per I1, the reader truncates its read cursor to the end of the last fully checksummed frame and reports the session as readable up to that point. The writer, on restart, does not attempt to complete the torn frame — it begins a new frame at the next sequence number, per P2's append-only rule.
