385 — TrueType Font Rasterizer from Scratch

Project Number: 385 Project Name: TrueType Font Rasterizer from Scratch Owner: Mujir Qureshi Document: FINAL_BLUEPRINT.md Status: specification — locked

1. Goal

1.1 What is built

A library + CLI that turns untrusted sfnt font bytes (TrueType glyf/OpenType, .ttf/.otf/.ttc) into anti-aliased glyph bitmaps plus metrics. Pipeline: parse table directory → parse required tables → extract glyph outlines (simple + composite) → scale funits→device (26.6 fixed) → optionally grid-fit via TrueType hinting VM → flatten quadratic/cubic Béziers to polylines → scan-convert with non-zero winding + signed-area coverage AA → emit 8-bit alpha bitmap + advance/lsb/bbox metrics → cache.

  • Single canonical artifact: GlyphBitmap (8-bit coverage) + GlyphMetrics.
  • Pure-Rust, zero-dependency no_std core; std only in CLI + cache file IO.
  • Deterministic: identical input bytes + size + transform + hint-mode → byte-identical bitmap on every platform.

1.3 Explicit non-goals

  • NOT a text shaper / layout engine. No cluster formation, no mark positioning beyond kern/pair-pos. Unicode shaping lives above → cross-ref #398 Unicode shaping.
  • NOT a full OpenType layout engine. GSUB ignored; GPOS limited to PairPos (kerning) subset. Everything else PhaseDeferred("FINAL_BLUEPRINT §Phase 9").
  • NOT a PDF / browser / compositor. Rendering surface composition → #384 compositor/display; PDF embedding consumer → #386 PDF renderer.
  • NOT a WOFF/WOFF2 decoder. Assumes already-decompressed sfnt; transport compression → #397 compression.
  • NOT a hint authoring / autohint tool. Default render path is unhinted AA; the bytecode interpreter is for existing hints, not generating them. Autohint → PhaseDeferred("FINAL_BLUEPRINT §11.10").
  • NOT a color-font (COLR/CPAL/sbix/SVG) renderer. Monochrome coverage only; color → deferred.
  • NOT a bitmap-strike (EBDT/CBDT) consumer. Outline-only; embedded bitmaps deferred.

1.4 Deployment model

  • Embeddable library (ttfr-core crate, no_std) linked into renderers/engines. Re-entrant, allocation-bounded, panic-free on malformed input.
  • CLI demo (ttfr-cli, std): ttfr render --font X.ttf --char 'A' --size 16 --out a.png; ttfr inspect (ttx-style table dump); ttfr metrics; ttfr atlas.
  • Distributed as a crate (dual Apache-2.0/MIT), optional C ABI shim (deferred).

1.5 Target users

Engine authors, renderer authors, terminal/editor authors, PDF/SVG renderer authors, graphics researchers needing a small auditable rasterizer. Operators = integrators embedding it in a long-running service that ingests arbitrary user-supplied fonts (adversarial input is the norm).

1.10 Recommended language — Rust (locked)

Criterion Rust Rejected: C Rejected: Go
Memory safety on adversarial bytes bounds checks + Result, no UB manual bounds → CVE class (heap OOB on bad offsets) safe but
Determinism fixed-point, no UB float reorder OK GC pauses break latency SLO
no_std embeddability first-class first-class runtime mandatory
Fuzzing cargo-fuzz/libFuzzer mature libFuzzer but unsafe baseline go-fuzz weaker, GC noise
SIMD coverage→alpha core::simd portable intrinsics OK weaker SIMD story
Zero-cost abstraction yes yes interface dispatch + GC

Rationale: font parsing is the canonical "parse hostile binary" problem; the FreeType/stb CVE history is dominated by out-of-bounds reads on malformed offset/length fields. Rust's bounds-checked slices + typed Result make the safe path the default path; no_std keeps the core embeddable; cargo-fuzz makes adversarial-input testing routine. C rejected: every offset read is an unguarded foot-gun. Go rejected: GC pauses violate per-glyph p99 latency, mandatory runtime blocks no_std embedding.

1.11 Prerequisites

  • Computational geometry: point-in-polygon, winding number, segment intersection, AABB.
  • Bézier math: quadratic + cubic, de Casteljau subdivision, flatness metrics.
  • Fixed-point arithmetic: 26.6 (device, 6 fractional bits), 16.16 (transforms), F2Dot14 (component scales), rounding modes, overflow analysis on i32/i64.
  • Scan conversion: active edge table, coverage/area accumulation, non-zero vs even-odd fill.
  • Binary format parsing: big-endian, offset tables, length-prefixed records, defensive bounds checking.
  • Stack-VM mental model: for TrueType hinting (operand stack, graphics state, jumps, loops).

2.2 Historical / architectural significance

  • TrueType (Apple, ~1991): quadratic outlines + a programmable hinting VM — the font ships a bytecode program that grid-fits its own outlines. A font format containing a Turing-ish interpreter is a singular design.
  • OpenType (MS+Adobe, 1996): sfnt wrapper unifying TrueType glyf and Adobe CFF (Type2 charstrings, cubic). One container, two outline technologies.
  • FreeType: the reference open rasterizer; its smooth (signed-area coverage) algorithm is the canonical analytic AA scan converter studied here.
  • stb_truetype.h: single-file public-domain rasterizer; proof that a usable subset fits in ~5k lines — the scoping model for Phase 0–8.
  • ClearType: Microsoft's subpixel-AA + hinting integration; the LCD/gamma work in Phase 12.

2.3 Engineering muscles

  • Writing a parser that never trusts its input and never panics.
  • Reasoning about fixed-point overflow with pen-and-paper bounds.
  • Implementing a non-trivial numerical algorithm (coverage rasterizer) that must be both correct and fast.
  • Building a bytecode interpreter with bounded resources against adversarial programs.
  • Differential testing against FreeType/stb to pin correctness.
  • Reproducible, deterministic output as a hard contract.

2.5 Production engineering concepts

Bounded resource usage on hostile input; typed error taxonomy; observability of rejections (a parser that silently mis-renders is worse than one that loudly refuses); cache key design; semver of a binary output artifact (bitmap stability); fuzzing as CI gate; differential conformance corpora.

2.6 Calibration value

Permanently raises capability in: hostile-binary parsing, numerical rasterization, fixed-point reasoning, and interpreter construction — four skills that transfer to compilers, codecs, network protocol parsers, and GPU pipelines. After this, "parse a binary format safely and render it deterministically" is a solved reflex.

2.7 What Mastery Looks Like

After building this system you hold, demonstrably:

  • Hostile-binary parsing as reflex — you funnel every byte through one bounds-checked gate and cross-validate length fields before trusting them; you can name the OOB-read CVE class on sight (Phase 0, Phase 2's cmap format-4 idRangeOffset).
  • Analytic anti-aliasing from first principles — you can derive the signed-area (cover, area) cell accumulation, explain why it is 1× memory vs N× supersampling, and debug a sign inversion in it (Phase 8).
  • Fixed-point overflow reasoning with pen and paper — you bound funit · ppem · 64 / upem in i64 and prove the 26.6 result never wraps i32 across the size range (Phase 5, invariant I9).
  • Bytecode-interpreter construction against adversarial programs — you build a stack VM with a graphics-state machine, bound it with an instruction + loop budget, and degrade gracefully to unhinted on any fault (Phase 11, invariants I11–I13).
  • Curve mathematics in production — you implement adaptive de Casteljau flattening with a squared-distance flatness test and a recursion cap, trading tessellation against tail latency (Phase 6).
  • Differential testing as a correctness anchor — you pin your rasterizer to FreeType/stb_truetype by SSIM over a font × size grid and make pixel drift a CI failure (Phase 8, Phase 11, Phase 12).
  • Cache-identity discipline — you design a key that captures every pixel-affecting input and can prove collision-freedom, the precondition for sharing bitmaps across threads (Phase 10, invariant I19).
  • Determinism as a hard contract — you keep the fill path integer-only and verify byte-identical output across x86-64 and aarch64 in CI (Phase 8, invariant I21).

3.2 Per-box responsibilities

sfnt::reader — bounds-checked big-endian cursor over &'a [u8]. Reads u8/u16/u32/i16/i16/Tag/F2Dot14/Fixed. Every read returns Result; out-of-range offset → FontError::OutOfBounds. Invariant: never reads past slice; never panics. Input: &[u8] + offset. Output: scalars / sub-slices. Zero allocation; the single trust gate — all parsers funnel through it.

sfnt::loader — detects container: 0x00010000/'true'/'typ1' (TrueType), 'OTTO' (CFF), 'ttcf' (collection). For ttcf exposes N font offset tables. Output: OffsetTable { sfnt_version, num_tables, search params } + directory slice. Invariant: rejects unknown magic with BadMagic.

sfnt::table_directory — parses num_tables × TableRecord{tag,checkSum,offset,length}; builds tag→record map (sorted/binary search or small linear). Verifies each offset+length ≤ file_len. Output: TableDirectory. Invariant: every table region within file bounds before any table parser runs.

sfnt::checksum — per-table 32-bit sum-of-u32 (big-endian, zero-padded); head.checkSumAdjustment whole-file check. Soft-fail (warn telemetry) — many real fonts have wrong checksums; never reject solely on checksum. Output: validity flags.

tables::head/maxp/hhea/hmtx/post/os2 — scalar metadata. head→unitsPerEm,indexToLocFormat,bbox,flags. maxp→numGlyphs,maxPoints,maxComponentDepth. hhea+hmtx→numberOfHMetrics,per-glyph advanceWidth/lsb. post→glyph names (format 1/2/3). OS/2→typo metrics, weight/width class. Invariants in §7.

tables::cmap — character map subtables; selects best (prefer (3,10) format 12 → (3,1) format 4 → (0,*) → (1,0)). Maps char→GlyphId; unmapped → glyph 0 (.notdef). Output: Cmap with chosen subtable. Invariant: returned gid < numGlyphs.

tables::loca — glyph offset array; short (×2, u16) or long (u32) per head.indexToLocFormat. loca[i],loca[i+1] bound glyph i in glyf. Invariant: monotonic non-decreasing; all within glyf length; len == numGlyphs+1.

tables::glyf — raw glyph data; numberOfContours ≥ 0 simple, < 0 composite. Parsed lazily by outline::builder. Empty glyph (loca[i]==loca[i+1]) = whitespace, valid.

tables::cvt/fpgm/prep — hinting inputs. cvt= Control Value Table (i16 funit array, scaled at use). fpgm= font program (defines functions, run once at face load). prep= control-value program (run once per size change). Consumed by hint::vm.

tables::kern / gpos — kern format 0 (h-pair adjustments); GPOS PairPos (format 1/2) subset for kerning only. Output: kern(left,right)->i16 delta. Everything else in GPOS deferred.

outline::builder — extracts Outline from glyf. Simple: decode flag run-length, then x/y delta-coded coords, split by endPtsOfContours; on/off-curve points. Composite: read components, apply 2×2 + offset transform, recurse (depth ≤ maxComponentDepth, hard cap 8), union bboxes; optionally inherit instructions. Output: Outline in funits. Invariants §7.

scale::transform / fixed — device = funit · ppem / unitsPerEm where ppem = pointSize · DPI / 72. Applies user affine (16.16). Produces 26.6 device coords. F2Dot14 used for composite component scales. Invariant: no i32 overflow (use i64 intermediates).

hint::vm — optional grid-fitting interpreter. Runs fpgm (once), prep (per ppem), then the glyph's instruction stream. State: operand stack, GraphicsState (freedom/projection vectors, round state, zone pointers), CVT, storage area, twilight zone. Mutates point coordinates. Bounded: instruction budget + loop cap → HintBudgetExceeded. Output: hinted Outline. Disabled by default (HintMode::None).

raster::flatten — adaptive subdivision (de Casteljau) of quadratic/cubic Béziers to line segments within flatness tolerance (≤ 0.25 px device). Output: monotone line segments → EdgeList. Bounded recursion depth.

raster::edges / scanline / coverage — the rasterizer. Build edges (y-sorted), active edge table per scanline, accumulate signed-area + cover per Cell, integrate across each row → coverage. Non-zero winding fill. Output: CoverageBuffer (per-pixel area ∈ [0,1] in fixed). Invariant: coverage clamped [0,1].

raster::lcd / gamma — optional. LCD = 3× horizontal supersample + FIR filter (FreeType-style) → RGB coverage triplet. Gamma = linear-space blending LUT. Deferred to Phase 12.

cache::glyph_cache / atlas — GlyphCacheKey{gid,size,transform,hint_mode}→GlyphBitmap. LRU + memory budget (MB). Atlas = shelf/skyline bin-pack of bitmaps into a texture sheet for GPU consumers. Shared read (interior mutability / sharding). Invariant: key uniquely determines bitmap.

api::* — public surface: FontRef::new(&[u8]), font.glyph_index(char), font.outline(gid), font.render(gid, size, transform, hint_mode), font.metrics(gid). All return Result; never panic on malformed input.

4.2 Determinism constraints

  • Fill path (flatten + coverage) uses integer/fixed-point only — no f32/f64. Float allowed only in pre-scale transform composition if the result is rounded to 26.6 deterministically (prefer fixed throughout).
  • No HashMap iteration order in any output path (use sorted/BTreeMap or arrays where order is observable).
  • No platform libm; any needed transcendentals via fixed-point tables or rejected.

6. Design Principles

  1. Determinism over convenience. Identical (bytes, size, transform, hint-mode) → byte-identical bitmap on every platform/arch. Tradeoff: forgoes fast float fill paths. Operational: enables snapshot/golden testing and reproducible bug reports. Violation: golden tests flap; cross-platform renders diverge; cache becomes unsafe to share.

  2. Bounded resource usage — fonts are adversarial input. Every loop, recursion, and allocation has a static cap (points, contours, recursion depth, hint instructions, atlas size). Tradeoff: rejects a few pathological-but-valid fonts. Operational: a malformed font can never hang or OOM a service. Violation: loca/composite/hint bombs → DoS.

  3. Correctness before speed. Phase 7 (monochrome, simple, slow) lands before Phase 8 (AA) before any SIMD. Each optimization must preserve byte-identical output (or a versioned, documented change). Violation: subtle coverage drift that only differential tests catch ships silently.

  4. Fixed-point where determinism matters. 26.6 device, 16.16 transform, F2Dot14 scale; the fill path is integer-only. Tradeoff: manual overflow reasoning. Operational: reproducible across CPUs. Violation: float reassociation → per-platform pixel diffs.

  5. Separate outline extraction from rasterization. outline::* knows nothing about pixels; raster::* knows nothing about glyf. Tradeoff: an intermediate Outline/EdgeList copy. Operational: hinting, flattening, and rasterizing are independently testable/swappable (e.g., SDF backend later). Violation: parsing bugs masquerade as raster bugs; cannot unit-test in isolation.

  6. Coverage is first-class (analytic AA). Use signed-area cell coverage, not post-hoc supersampling, as the default AA. Tradeoff: more intricate accumulation code. Operational: 1× memory, exact edge coverage, sharp results. Violation: supersampling costs N× memory/time and still aliases at low N.

  7. Defensive parsing — every offset/length is hostile. All access via sfnt::reader bounds checks; cross-validate loca/maxp/numGlyphs. Tradeoff: a bounds check per read. Operational: OOB reads become typed errors, not CVEs. Violation: the entire FreeType/stb CVE class.

  8. No panics on malformed input. Malformed fonts yield Err(FontError::…), never panic!/unwrap/array-index-panic in the core. Tradeoff: pervasive Result plumbing. Operational: a library embedded in a server cannot crash the host on bad input. Violation: one bad font kills the process.

  9. Cache by full identity. Key = (glyph_id, size, transform, hint_mode); any input that changes pixels is in the key. Tradeoff: more keys, lower hit rate if transforms vary. Operational: cache correctness is trivially provable. Violation: stale/wrong bitmap served for a different size/transform.

  10. Observability of rejection. Every refusal emits a typed error + metric + trace event naming the table/offset. Tradeoff: instrumentation overhead. Operational: "why is this glyph blank?" is answerable from telemetry. Violation: silent .notdef everywhere, undiagnosable.

  11. Pixel-grid conventions fixed once. Y-axis direction, pixel center sampling (sample at pixel center, integer pixel = lower-left), rounding of bbox to device pixels, and 26.6 origin are defined in raster:: once and never re-litigated. Tradeoff: must be chosen carefully up front. Operational: metrics (left,top) are consistent across glyphs. Violation: 1-px drift / off-by-one seams in atlases.

  12. Lazy table loading. Parse the directory eagerly; parse each table on first use, cache the view in FontRef. Tradeoff: first-use latency spike. Operational: fast face open; pay only for tables you touch. Violation: opening a font parses CFF/hinting you never render.

  13. Soft-fail on non-fatal anomalies. Bad checksums, missing post names, unusual but in-bounds values → warn telemetry + continue. Hard-fail only on safety/correctness violations (OOB, bad magic, loca out of range). Tradeoff: renders some technically-broken fonts. Operational: matches real-world font sloppiness (matches FreeType leniency). Violation: rejecting fonts the rest of the world renders fine.

  14. Single trust gate. All byte access flows through sfnt::reader; no parser indexes raw slices directly. Tradeoff: minor ceremony. Operational: one place to audit/fuzz for bounds safety. Violation: an un-audited raw index becomes the one OOB bug.

  15. Versioned, stable output. GlyphBitmap byte layout + cache file format are versioned; an intentional rasterizer change bumps the version and is documented in CHANGELOG. Tradeoff: can't silently "improve" pixels. Operational: downstream golden images stay valid until a known version bump. Violation: invisible regressions break consumers' visual tests.

Short: offsets[numGlyphs+1] : u16, actual byte offset = 2 × value. Long: offsets[numGlyphs+1] : u32. Glyph i bytes in glyf = [off(i), off(i+1)). off(i)==off(i+1) ⇒ empty glyph (whitespace, no outline). Selected by head.indexToLocFormat.

8.9 Quadratic Bézier reconstruction

TrueType outlines are quadratic B-splines defined by alternating on/off-curve points. Rule: between two consecutive off-curve points there is an implied on-curve midpoint. Segment types after inserting implied points:

  • on→on : straight line.
  • on→off→on : quadratic with the off point as control.
  • off→off : implied on-curve at midpoint splits into two quadratics.

If a contour starts off-curve, the start point = midpoint of last and first off-curve points (or use the last on-curve point). Contour is cyclic (wraps end→start).

Worked example (one contour, 4 stored points): points [A(on), B(off), C(off), D(on)], cyclic.

  • A→B→? : B,C both off ⇒ insert implied M = midpoint(B,C). Quadratic A–B–M.
  • M→C→D : quadratic M–C–D.
  • D→A : both on? A on, wrap to A on ⇒ check next stored after D is A(on) ⇒ line D–A. Result: 2 quadratics + 1 line, closed.

8.10 Coordinate spaces + scaling

ppem        = pointSize * DPI / 72            // pixels per em
deviceScale = ppem / unitsPerEm               // funit → pixel
x_device    = funit_x * pointSize * DPI / (72 * unitsPerEm)

Stored in 26.6: x_26_6 = round( funit_x * ppem * 64 / unitsPerEm ) using i64 intermediate. User affine (rotation/skew/scale) applied in 16.16 after em-scale, before rounding to 26.6. Fill rule = non-zero winding (default; even-odd available for SVG-style if ever needed, but TrueType uses non-zero). Y convention: font space y-up; device buffer top-left origin → flip y during scale (y_dev = (ascent_or_bbox_top − funit_y)·scale); fixed once in scale::transform.

8.11 Worked glyph examples

  • 'O' — two contours: outer ellipse + inner ellipse (counter). Non-zero winding requires opposite orientations: outer CW, inner CCW (or vice versa) so the hole's winding cancels. If both same orientation, the counter fills solid → visual bug → I8/winding test catches.
  • 'é' (composite) — component 0 = 'e' (glyphIndex of e), identity transform, offset (0,0); component 1 = acute accent, offset (dx,dy) placing it above. MORE_COMPONENTS set on component 0. bbox = union. May carry WE_HAVE_INSTRUCTIONS.
  • space — loca[sp]==loca[sp+1] ⇒ empty glyph, advance from hmtx, no outline, bitmap is 0×0 with nonzero advance.

8.13 Flag run-length decoder state table

11.2 Container / directory

struct FontRef<'a> {               // zero-copy view over font bytes
  data: &'a [u8],
  dir: TableDirectory,             // parsed once
  head: OnceCell<Head>, maxp: OnceCell<Maxp>, ...   // lazy table views (interior mut)
}

struct Reader<'a> { data: &'a [u8], pos: usize }        // bounds-checked cursor
impl Reader<'a> {
  fn u8/u16/u32/i16/tag/f2dot14/fixed(&mut self) -> Result<_, FontError>;
  fn slice(&mut self, len: usize) -> Result<&'a [u8], FontError>;
  fn seek(&mut self, pos: usize) -> Result<(), FontError>;

Ownership: FontRef borrows the byte buffer ('a); caller owns bytes. Mutation: only interior OnceCell table caches (single-init). 0.6 Pitfalls

  • Trusting searchRange/binary-search params from file → use them and you read OOB; recompute.
  • ttcf offsets pointing mid-file/overlapping → validate each offset table independently.
  • Integer overflow in offset+length (u32+u32) → compute in u64.
  • Assuming tables are 4-byte aligned in code paths that read u32 directly → Reader is alignment-agnostic (byte-wise), keep it so.
  • Forgetting padding when checksumming the last table → pad to 4 with zeros.

0.7 Performance Concerns

Directory parse is O(numTables); binary-search lookup O(log n). Avoid parsing tables eagerly. Reader per-read branch is predictable; inline hot accessors. No allocation beyond the records Box<[_]>.

0.8 Edge Cases

numTables=0 (valid-ish empty font → later MissingTable); duplicate tags (keep first, warn); tables overlapping each other (allowed by spec for shared data; do not reject); offset==0 length==0 table; file exactly == directory end (no table bodies) → defer to per-table errors.

0.9 Failure Analysis

Break: OOB read in directory → typed error, blast radius = single font open, no host crash. Detection: fuzz + miri. Containment: error returned before any table touched. Forensics: error carries {table,at,need,have}.

0.10 Operational Notes

Metric font.open.{ok,err} by error variant. Trace span sfnt.load with num_tables, sfnt_version. Log warn on checksum mismatch (do not alarm). Rollback: pure read path, no state.

Phase 8 — anti-aliased coverage rasterizer (signed-area cells)

8.1 Objectives

Production AA path: analytic coverage via signed-area cells (FreeType smooth-style), accumulation sweep → 8-bit alpha. Default render mode. Constraint: I14 (coverage∈[0,1]), determinism (integer only), 1× memory.

8.2 Detailed Implementation Steps

Applies: ADR-9 (signed-area coverage), Principle 6 (coverage first-class), Principle 4 (integer-only), invariant I14 (coverage∈[0,1]) and I21 (no float); the algorithm is FreeType smooth/ftgrays.c (paper P4, ref R3); coverage origins in P2/P5; MM3.

  • Coverage/ClassDef parsing is shared and bug-prone (binary search ranges) → OOB risk; bound it.
  • ValueRecord field presence is bitfield-driven (ValueFormat) → reading wrong field count desyncs.
  • kern vs GPOS double-application → pick one source.
  • format 0 kern pair key packing (left<<16|right) sort assumption.
  • Signed kern value scaling sign error.

9.7 Performance Concerns

Kern lookup O(log pairs) or O(log classes). Cache ClassDef lookups. GPOS parse lazy (only if kern requested). Metrics are O(1) (+bbox from cached outline). Avoid re-parsing GPOS per pair.

9.8 Edge Cases

Glyph with zero advance (combining mark); negative lsb; kern pair absent (0); class 0 (default) in ClassDef; GPOS present but no PairPos lookup; both kern and GPOS present (precedence).

9.9 Failure Analysis

Break: wrong ValueFormat parse → garbage kern → mis-spaced text. Detection: kern golden test. Blast radius: spacing (not glyph shape). Recovery: bound parsing; ignore malformed lookups; telemetry gpos.lookup.skipped.

9.10 Operational Notes

Metric metrics.kern.{applied,zero}, gpos.lookup.{used,skipped}. Note: full shaping is #398; this is kerning-only. Trace metrics{advance,kern}.

Phase 10 — glyph cache + atlas packing

10.1 Objectives

Cache rendered bitmaps keyed by full identity (I19); LRU eviction under MB budget; atlas bin-packing for GPU consumers. Constraint: shared-read concurrency (interior mutability); cache correctness provable.

10.2 Detailed Implementation Steps

Applies: Principle 9 (cache by full identity), Principle 15 (versioned output), invariant I19 (key uniquely determines bitmap); §11.9 (cache types); book B4 (atlas packing); ref R9 (CoreText cache API ergonomics).

  • cache/glyph_cache.rs: GlyphCache{ map: LruMap<GlyphCacheKey,Arc<GlyphBitmap>>, budget_bytes, current_bytes }; get_or_render(key, render_fn); LRU touch on hit; evict LRU until under budget on insert. Interior lock (Mutex or sharded by key hash for less contention).
  • GlyphCacheKey includes glyph_id,size(ppem),transform(quantized exact bits),hint_mode (I19) — any pixel-affecting input.
  • cache/atlas.rs: shelf (or skyline) bin-pack: place glyph bitmaps into a growing texture sheet; track AtlasSlot{x,y,w,h}; padding (1px) to avoid bleed; grow/add new sheet when full.
  • ttfr-cli cmd_atlas: render a glyph set, pack, emit atlas PNG + JSON slot map.
  • Optional persistence: versioned serialize of cache/atlas (CLI/std).

10.3 Deliverable

ttfr atlas --chars "A-Za-z0-9" --size 24 → atlas.png + atlas.json (slots, metrics). Cache hit ratio reported.

10.4 Acceptance Criteria

  • Cache returns byte-identical bitmap on hit vs fresh render (I19).
  • Eviction keeps memory ≤ budget; hit ratio > 95% on repeated text workload.
  • Atlas has no bleed (1px pad verified); all glyphs placed; growth correct when full.
  • Concurrent get_or_render from N threads is race-free (loom/stress test).

10.6 Pitfalls

  • Forgetting transform/hint_mode in key → wrong bitmap served for different transform (I19 violation).
  • Float size in key → non-deterministic hashing; quantize to exact bits / ppem integer.
  • Atlas without padding → texture bleed at glyph edges when sampled bilinearly.
  • LRU accounting drift (bytes not decremented on evict) → unbounded growth.
  • Lock held during render (slow) → contention; render outside lock, insert after.

10.7 Performance Concerns

10.8 Edge Cases

Zero-size glyph (cache empty bitmap with advance); identical glyph at two transforms (two entries); cache budget smaller than one glyph (evict-immediately / bypass); atlas slot larger than sheet (grow sheet or reject); thundering herd (two threads miss same key → render once, dedupe).

10.9 Failure Analysis

Break: key collision → wrong glyph rendered (data corruption, silent). Detection: I19 collision counter (must be 0) + golden. Blast radius: visual correctness across cache. Recovery: key includes all inputs by construction; collision is a bug, alarmed.

10.10 Operational Notes

Phase 11 — TrueType hinting VM

11.1 Objectives

Interpret TrueType bytecode (fpgm → prep → glyph program) to grid-fit outlines at small ppem (sharper stems, consistent weights). Bounded by instruction + loop budget (I13) and stack/jump/index safety (I11/I12/I20). Default OFF; opt-in via HintMode::Bytecode. Many sub-instructions PhaseDeferred.

11.2 Detailed Implementation Steps

Applies: Principle 2 (bounded instruction/loop budget), Principle 8 (no panics → unhinted fallback), invariants I11/I12/I13/I20; §11.6 (HintVm/GraphicsState types); book B10 + Apple TrueType Reference Manual (instruction set); paper P1 (grid-fitting theory); ref R2 (FreeType ttinterp.c); MM5.

  • hint/instructions.rs: opcode table + operand decode (push variants NPUSHB/NPUSHW/PUSHB/PUSHW, arithmetic, logic, stack ops, graphics-state setters, point movers, control flow).
  • hint/gstate.rs: GraphicsState (§11.6) — freedom/projection/dual vectors, round_state (RTG/RTHG/RTDG/ROFF/SROUND/S45ROUND), rp0/1/2, zp0/1/2, loop, cut-ins, min_distance.
  • hint/cvt_program.rs: scale cvt values to 26.6; run fpgm once at face load (defines FDEFs); run prep per ppem (sets up gstate, twilight).
  • hint/vm.rs: interpreter loop with InstrBudget (decrement per op → HintBudgetExceeded; loop cap → abort); execute key instructions:
    • MDAP/MDRP move point (absolute/relative) along freedom vector, round per state.
    • MIRP move indirect relative point (uses CVT distance) — the stem-control workhorse.
    • IUP[x]/IUP[y] interpolate untouched points (preserve outline between hinted points).
    • SHP/SHC/SHZ/SHPIX shift point/contour/zone.
    • IP interpolate point; ALIGNRP; MIAP.
    • ROUND/SROUND; SCANCTRL/SCANTYPE (dropout control — partial).
    • Function calls CALL/LOOPCALL/FDEF/ENDF; control flow IF/ELSE/EIF/JROT/JMPR/JROF.
  • Mutate zone1 (glyph) and zone0 (twilight) points; mark points "touched" in x/y for IUP.
  • On any fault (stack, jump, index, budget): abort hinting, return original (unhinted) outline (fallback), emit telemetry. Never crash.
  • Defer rare/complex ops (DELTA exceptions tables beyond basic, some SROUND modes, projection on dual vectors edge cases) → PhaseDeferred("FINAL_BLUEPRINT §11.2").

11.3 Deliverable

ttfr render --char m --size 11 --hint vs --no-hint: hinted version has even stem weights / sits on pixel grid. gasp table consulted for hint/AA ranges.

11.4 Acceptance Criteria

  • Hinted output for a hinted font (e.g. system font) matches FreeType bytecode-hinted render by SSIM ≥ 0.95 at 8–14 ppem on a sample set.
  • Budget/loop caps enforced: hint_loop_bomb.ttf → HintBudgetExceeded, falls back to unhinted, no hang.
  • Stack/jump/index faults → unhinted fallback, no panic (fuzz fuzz_hint).
  • Determinism: hinted bitmap byte-identical cross-arch.

11.6 Pitfalls

  • IUP after partial point touching is subtle → wrong IUP corrupts whole glyph outline; test against reference.
  • Freedom/projection vector math (dot products in fixed-point) overflow/precision → use careful 16.16/i64.
  • Rounding state machine (SROUND period/phase/threshold) is intricate → table-driven, tested.
  • Forgetting fpgm runs once but prep runs per ppem → re-running fpgm corrupts FDEFs / wastes budget.
  • Infinite loops via JMPR/LOOPCALL → budget + loop cap are mandatory, not optional.
  • Twilight zone vs glyph zone pointer (zp0/1/2) confusion → moves wrong points.

11.7 Performance Concerns

Hinting is the most expensive path (interpreter overhead per instruction). Budget cap bounds worst case. Cache hinted results (cache key includes hint_mode). prep runs once per ppem (cache per-size gstate). Only enable when sharpness at small ppem matters; default unhinted AA is faster and deterministic.

11.8 Edge Cases

Font with fpgm but no prep; glyph with no instructions (no hinting, unhinted); ppem where prep disables hinting (gasp); SCANCTRL dropout at tiny sizes; composite with WE_HAVE_INSTRUCTIONS (run composite program on assembled points); CVT index OOB (I20 → fallback).

11.9 Failure Analysis

Break: interpreter bug → distorted glyph (worse than unhinted). Detection: SSIM vs FreeType hinted; A/B vs unhinted. Blast radius: hinted renders only (fallback path safe). Recovery: any fault → unhinted fallback (graceful degradation); telemetry names failing op. Forensics: instruction trace dump (debug feature).

11.10 Operational Notes

Metric hint.{run,fallback,budget_trip,stack_fault,bad_jump}, hint.instrs histogram. Default HintMode::None. Autohinting → PhaseDeferred("FINAL_BLUEPRINT §11.10"). Runbook "garbled glyphs (hinted only)" → disable hinting to confirm interpreter as cause. Trace hint{gid,ppem,instrs,fallback}.

Phase 12 — subpixel/LCD + gamma + CFF/Type2 cubic + conformance/fuzz hardening

12.1 Objectives

Optional enhancements + second outline technology + hardening: LCD subpixel rendering, gamma-correct blending, CFF/Type2 (cubic) outline extraction, expanded conformance + fuzz corpus. Several items PhaseDeferred. Constraint: keep grayscale path default; CFF behind module; LCD behind feature.

12.2 Detailed Implementation Steps

Applies: ADR-13 (LCD deferred/feature), ADR-14 (CFF as extension), Principle 2 (subr depth cap), Principle 5 (CFF feeds the shared raster path); papers P6 (ClearType subpixel), P10 (gamma); spec = Adobe Type2/CFF (5177/5176); book B4 (gamma/subpixel); MM7.

  • raster/lcd.rs (feature lcd): horizontal 3× supersample → per-channel coverage; apply FIR filter (e.g. FreeType default [0x08 0x4D 0x56 0x4D 0x08] normalized) to reduce color fringing (P6); output Lcd24 (RGB triplet per pixel).
  • raster/gamma.rs: gamma LUT; blend coverage in linear space (decode→blend→encode) for correct stem weight; document gamma value (e.g. 2.2 / sRGB).
  • cff module (new, mirrors outline path): parse CFF header, INDEX structures (Name/TopDICT/String/GlobalSubr), CharStrings INDEX, Private DICT + LocalSubrs, charset/encoding; interpret Type2 charstrings (rmoveto/rlineto/rrcurveto/hstem/vstem/hintmask/callsubr/callgsubr/endchar...) → cubic Bézier Outline; feed into flatten_cubic (Phase 6) → existing raster path. CID-keyed CFF (FDSelect/FDArray) subset.
  • Conformance: expand conformance/fonts (DejaVu, Noto, Roboto, system fonts, CFF fonts); malformed/ one per failure path; golden/ per (font,glyph,size,hint).
  • Fuzz hardening: per-table + whole-font + per-charstring targets; commit minimized corpora; OSS-Fuzz-style continuous run.
  • Deferred: COLR/CPAL/sbix/SVG color → PhaseDeferred("FINAL_BLUEPRINT §12.10"); variable fonts gvar/fvar → deferred; SDF/MSDF → deferred; embedded bitmaps EBDT/CBDT → deferred; C FFI → deferred.

12.3 Deliverable

12.4 Acceptance Criteria

  • LCD render matches FreeType LCD (with same filter) SSIM ≥ 0.95; gamma blending visibly correct stem weight (golden).
  • CFF/Type2: rendered CFF glyph matches FreeType CFF render SSIM ≥ 0.98; cubic flattening within tol.
  • Fuzz: ≥ 24h continuous, zero crashes across all targets; corpus minimized + committed.
  • All malformed fixtures produce typed errors; differential corpus passes.

12.6 Pitfalls

  • Type2 charstring subr recursion (callsubr/callgsubr) unbounded → depth cap (like composites/hints). Documented incident: the jailbreakme.com v3 ("Star", 2010) iOS exploit weaponized CVE-2010-1797, a stack buffer overflow in FreeType's CFF/Type-2 charstring interpreter, to achieve remote code execution from a malicious font in a PDF. This is the canonical reason CFF subr handling is treated as adversarial: bound depth (Principle 2) and bounds-check every charstring stack op (I11-analogue).
  • hintmask byte-count depends on declared stem count → desync mis-parses charstring.
  • CFF subr bias offset (107/1131/32768 by count) miscomputed → wrong subr called.
  • LCD filter not normalized → brightness shift; energy must sum to 1.
  • Gamma applied in wrong direction (encode/decode swapped) → too thin/thick.
  • CID FDSelect format 0 vs 3 parse difference.

12.7 Performance Concerns

LCD triples horizontal work (3× columns) + filter pass; feature-gated. Gamma LUT is O(1) per pixel. CFF interpreter analogous cost to glyf parse + subr calls; cache decoded outlines (cache key already covers it). SIMD coverage→alpha and LCD filter (feature simd).

12.8 Edge Cases

CFF with no subrs; deeply nested subrs (cap); seac-like accent composition in CFF (endchar with args / legacy); LCD at 90° rotation (subpixel order changes — document/limit to upright); gamma=1.0 (no-op); empty CFF charstring.

12.9 Failure Analysis

Break: CFF subr loop → hang without cap; LCD fringing if filter wrong. Detection: subr depth cap + fuzz; LCD SSIM. Blast radius: CFF fonts / LCD mode only (defaults safe). Recovery: caps + feature gating; fallback to grayscale on LCD error.

Why this severity matters (documented incidents). Font parsers are a proven remote-code-execution surface: the jailbreakme.com v3 exploit (2010) used CVE-2010-1797, a FreeType CFF/Type-2 charstring stack overflow, to jailbreak iOS from a malicious PDF font; Google's Project Zero and OSS-Fuzz have since filed a long stream of FreeType OOB-read/write bugs against malformed glyf/cmap/CFF inputs. The structural defenses here — the single Reader trust gate (I2), up-front loca/maxp cross-validation (I1/I3), and #![forbid(unsafe_code)] in the core — exist specifically to make this CVE class unreachable rather than merely patched.

  • Availability of render path: 99.99% (a malformed font must not take down the service — it returns an error).

Dashboards

Per-font reject rate (spot a bad font deployed); latency heatmap by glyph complexity; cache hit ratio + memory; hint fallback rate (rising = a font's hints are failing); fuzz crash count (CI).

Alerting philosophy

Alert on: reject-rate spike (bad font shipped), cache.collision > 0 (correctness bug), p99 latency breach (perf regression / adversarial input), hint fallback surge. Do not alert on: individual rejects, checksum warnings (noise).

  • Allocator analysis: confirm no per-glyph allocation on hot path (buffers pooled/reused, §4.1); dhat/heaptrack to verify.
  • Cache analysis: Cell packed to 12 bytes for cache-line density; access pattern (y,x) sorted for locality; coverage buffer row-major sequential.
  • Branch analysis: branchless coverage→alpha in row sweep (clamp via min/max, not branch); predictable Reader bounds branch.
  • Syscall analysis: library does zero syscalls on render path (pure compute); CLI IO only.

Optimization levers (in order, each must preserve output bytes)

  1. Buffer reuse (edges, cells, coverage) — no realloc per glyph.
  2. Branchless coverage integration + clamp.
  3. Banding for large glyphs (cache footprint).
  4. core::simd for coverage→alpha and LCD filter (feature simd, scalar canonical fallback).
  5. Cache (Phase 10) — the biggest real-world win (skip render entirely).
  6. Lazy/precomputed Scaler factor (16.16) per size.

Tail latency

Driven by point/segment count (complex CJK glyphs) and hinting. Mitigate via: per-glyph caps, cache, optional hint disable. Measure p99/p999 separately for Latin vs CJK; alert on regression. Flamegraph the worst 1% glyphs.

Mental Models & First Principles

The compressed insights an expert carries while building this system. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

MM1 — A font is a hostile program, not a document. A .ttf literally ships a Turing-ish bytecode interpreter and a graph of self-referential offsets; treat every length/offset field as attacker-chosen. Predicts: the parser's threat surface equals its entire input; the dangerous code is wherever a field indexes memory. Bug without it: the classic OOB-read CVE (e.g. fmt-4 idRangeOffset indexing past glyphIdArray). Applied: §Phase 0 (single Reader gate), §Phase 2 (cmap bounds), §Threat Model, invariants I1/I2.

MM2 — Offsets are edges in a graph that may have cycles. loca→glyf, composite→component, CFF subr→subr, hint CALL→FDEF are all pointers; the input controls the graph shape, including back-edges. Predicts: any pointer-following loop can be made to recurse forever or revisit nodes. Bug without it: stack-overflow / hang on a cyclic composite or self-calling subr. Applied: §Phase 4 (depth cap + cycle guard, I5/I6), §Phase 11 (CALL/LOOPCALL budget), §Phase 12 (subr depth cap).

MM3 — Coverage is an integral, computed by sweeping a derivative. Per-pixel alpha = the area of the glyph inside that pixel; the signed-area cell method accumulates a derivative (cover, area deltas as edges cross pixels) and integrates left-to-right per row to recover coverage in 1× memory. Predicts: AA quality and cost come from exact area math, not sample count; a sign error flips or doubles coverage. Bug without it: inverted/blotchy glyphs, or N× memory from supersampling. Applied: §Phase 8, ADR-9, invariant I14.

MM4 — Determinism is a property of the arithmetic, not the test suite. Float addition is non-associative and the compiler/CPU may reorder it; identical bitmaps across machines require an integer-only fill path. Predicts: any f32 in flatten/coverage produces per-platform pixel diffs that goldens will eventually catch as flakes. Bug without it: "works on my machine" golden-image flapping; an unsafe shared cache. Applied: §Phase 5 / §Phase 8 (fixed-point), invariant I21, Principle 4.

MM5 — Hinting is grid-fitting, and grid-fitting is a constrained move of points toward the pixel grid. The VM moves control points along a freedom vector by distances measured along a projection vector, snapping to the grid via a round state, then IUP drags the untouched points along. Predicts: hinting helps most where the grid is coarse (small ppem) and is nearly a no-op at large ppem; a bad IUP corrupts the whole contour, not one point. Bug without it: distorted hinted glyphs worse than unhinted. Applied: §Phase 11, paper P1, §11.6.

MM6 — The pixel grid has exactly one convention, chosen once. Sample point (pixel center), integer-pixel origin (lower-left vs top-left), y-direction (font y-up vs raster y-down), and bbox rounding must be fixed in one place; every metric (left,top,advance) inherits it. Predicts: any per-stage re-derivation introduces a 1-px shift or atlas seam. Bug without it: off-by-one seams, glyphs that don't sit on the baseline together. Applied: §Phase 7 (conventions), Principle 11, §8.10.

MM7 — There are two outline technologies under one container, and they meet at the rasterizer. TrueType glyf is quadratic with an integer hint VM; CFF/Type-2 is cubic with a charstring interpreter and subrs. Both reduce to an Outline of segments that flatten into the same edge/coverage path. Predicts: you can add CFF as a front-end module without touching the raster core; the boundary is the Outline/EdgeList type. Bug without it: a CFF path that re-implements rasterization and drifts from glyf. Applied: §Phase 12 (CFF feeds Phase 6/8), Principle 5, §3.1.

MM8 — The cache key is the rendering function's full input signature. A GlyphBitmap is a pure function of (glyph, ppem, transform-bits, hint-mode); the key must equal that tuple exactly, or two distinct renders collide. Predicts: any pixel-affecting input omitted from the key serves a wrong-but-plausible bitmap, silently. Bug without it: a 12-px 'A' served for a 13-px request after a transform change. Applied: §Phase 10, invariant I19, Principle 9.

MM9 — Soft-fail vs hard-fail is a safety/compatibility tradeoff, decided per anomaly. A wrong checksum or missing post names are cosmetic (the rest of the world renders the font) → warn + continue; an OOB offset or upem==0 is unsafe/incorrect → reject. Predicts: rejecting on cosmetic anomalies makes you incompatible with real-world sloppy fonts; soft-failing on unsafe ones reintroduces CVEs. Bug without it: either over-strict (blank text everyone else shows) or unsafe (renders a malformed glyph). Applied: Principle 13, §Phase 0 (checksum soft), §Phase 1 (upem hard).

MM10 — Tail latency is set by the worst glyph, not the average. Per-glyph cost scales with point/segment/cell count and hint instructions; a single complex CJK or adversarial glyph dominates p99/p999. Predicts: average throughput is a poor SLO; you must cap per-glyph work and measure Latin vs CJK tails separately. Bug without it: a service that meets p50 but blows p99 on one font's ideographs, or hangs on an instruction bomb. Applied: §Performance Engineering (tail latency), §4.1 (per-glyph caps), §Phase 11 (instruction budget, I13).

FreeType made the decision to be everything for everyone — every outline format, color tables, autohinter, its own cache subsystem — in portable C. That breadth wins where you must render the long tail of real-world fonts (browsers, Linux desktops) and cannot dictate the input; the cost is a large C surface with a long CVE history that ttfr deliberately narrows by scope + Rust safety.

stb_truetype made the decision to fit a usable subset in one trust-the-caller single file (~5k lines, no hinting, limited cmap). That wins for a game or tool that controls its own bundled fonts and wants zero-dependency drop-in rendering; it is the scoping model for this blueprint's Phases 0–8, but ttfr diverges by treating input as hostile rather than trusted.

DirectWrite + ClearType made the decision to put subpixel rendering and OS-integrated shaping/layout first, tuned per-display. That wins on fixed RGB-stripe Windows desktops where small-size on-screen sharpness is the product; ttfr rejects subpixel-first (ADR-13) because grayscale is the deterministic, display-agnostic baseline and LCD is a display-specific feature.

Skia (SkScalerContext) made the decision to be a cross-platform 2D engine that delegates font parsing/hinting to a backend (often FreeType) and focuses on integrating raster + atlas + GPU upload + HarfBuzz shaping. That wins for a full graphics stack (Chrome, Flutter); ttfr is intentionally the narrow backend that such an engine would consume (cf. #384 compositor), not the whole engine.

Back-of-Envelope Capacity Model

The numbers an expert computes before designing, each derived step-by-step from the System Constraints (§4). Figures are order-of-magnitude design budgets, not measurements.

  1. Single-glyph coverage buffer (16 px Latin). bbox ≈ ppem × ppem ≈ 16 × 16 = 256 px; Gray8 = 1 byte/px → 256 B/glyph. Pitch padding negligible. Confirms per-glyph alloc is tiny → pool one reusable buffer (§4.1).

  2. Worst-case single-glyph buffer (guard). bbox dim cap = 8192 px (I18, §4.3) → 8192 × 8192 × 1 B = 64 MiB. This is why a per-render bbox guard exists and why banding (§Phase 8) is needed for large glyphs — a naive full-bbox buffer is unacceptable.

  3. ASCII atlas RAM @24 px. 95 printable glyphs × (≈24 × 24 = 576 px) × 1 B ≈ 53 KiB ink, + 1-px padding ≈ 95 × (26 × 26) ≈ 64 KiB packed. A 256 × 256 Gray8 sheet (64 KiB) holds the ASCII set → one sheet suffices (§Phase 10).

  4. Glyph cache occupancy at default budget. Default budget = 8 MB (§4.1). Avg cached bitmap @16 px ≈ 256 B + Arc/key overhead ≈ 320 B → 8 MB / 320 B ≈ 26,000 glyph entries. Far exceeds a single script's glyph count → near-100% hit rate for steady Latin text (SLO ≥95%, §Operational Readiness).

  5. Cache entries for full CJK at 16 px. A large CJK font ≈ 30,000 glyphs × ≈ (bbox 16² = 256 B + 320 B overhead) ≈ 30,000 × 576 B ≈ 17 MB to cache every glyph once → exceeds 8 MB default; either raise budget to ~24 MB or accept LRU churn (§Scalability Analysis, cache memory row).

  6. Throughput vs latency cross-check. Target ≥200k glyphs/s on 1 core (§4.1) ⇒ ≤ 5 µs/glyph average compute. p50 target is ≤3 µs (cache miss, §4.1) → consistent: 1e6 µs/s ÷ 5 µs ≈ 200k. Confirms the throughput and p50 targets are not mutually contradictory.

  7. Edge buffer sizing. Per-glyph edge buffer cap ≤ 64 KB (§4.1); Edge ≈ 4×i32 + dir ≈ 20 B → 64 KB / 20 B ≈ 3,200 edges. A 16-px Latin glyph flattens to tens of segments; 3,200 is ample headroom and bounds adversarial tessellation.

  8. Cell array footprint (16 px). Cell = 12 B (§11.7 / §Performance Engineering). A 16² glyph touches ≤ ~16 × 32 ≈ 512 cells worst-case → 512 × 12 B ≈ 6 KB → fits L1/L2; reused across glyphs, no per-glyph alloc.

  9. Hinting CPU budget ceiling. Instruction budget ≤ 1,000,000 instr/glyph (§4.1). At a generous ~1 ns/instr interpreter step → ≤ 1 ms/glyph absolute worst case before HintBudgetExceeded. This is 250× the 4-µs render budget → hinting must be opt-in and cached (ADR-11), and the budget exists to bound a bomb, not to be hit normally.

  10. Font open cost. Open ≤ 200 µs for a 200 KB font (§4.1), parsing only directory + head/maxp/hhea (lazy, Principle 12). Directory = numTables × 16 B; a 20-table font = 320 B scanned → microseconds. Confirms lazy loading keeps open well under budget; eager full-table parse would blow it.

  11. Service RAM at scale. N worker threads each need 1 Raster (edges 64 KB + cells 6 KB ≈ 70 KB) + shared read-only FontRef (font bytes, ~200 KB) + shared cache (8 MB). 16 threads → 16 × 70 KB + 200 KB + 8 MB ≈ 9.3 MB working set → trivially fits a container; the cache, not the per-thread state, dominates.

  12. Determinism cross-check cost. Cross-arch CI renders a corpus on x86-64 + aarch64 and byte-compares (I21). At ~50 fonts × ~200 glyphs × 5 µs ≈ 50 ms of render per arch → negligible CI time; determinism verification is cheap, so gate it always.

Alternative Architectures (Roads Not Taken)

Three fundamentally different designs for the same problem — glyph → bitmap — each with the regime where it wins, the real system that embodies it, and why this blueprint rejected it.

Alt-A — GPU implicit-curve rendering (resolution-independent, no flattening).

   outline ──▶ classify quads/cubics ──▶ upload control points + curve
              into triangles            type to GPU ──▶ fragment shader
                                         evaluates implicit f(x,y)≷0 per
                                         pixel ──▶ AA via screen-space
                                         derivatives (fwidth)

Wins when: rendering at many scales/rotations every frame on a GPU (3D text, maps, zoomable UI) — curves stay exact, no per-size re-flatten. Embodied by: Loop & Blinn (paper P7); Slug library; aspects of modern GPU text. Rejected because: this is a CPU, no_std, deterministic-byte-output rasterizer (ADR-9, Principle 4) feeding a glyph cache/atlas (§Phase 10); a GPU shader path is non-deterministic across drivers and assumes a GPU the embedder may not have. Kept as the informational alternative behind paper P7.

Alt-B — Signed-distance-field (SDF) glyph atlas.

   outline ──▶ render once at high res ──▶ compute per-texel signed
              distance to nearest edge ──▶ store low-res SDF in atlas
              ──▶ GPU samples + alpha-tests with smoothstep at any scale

Wins when: one bake, then cheap re-scale/outline/glow effects on GPU at arbitrary size (game UIs, AR/VR HUDs). Embodied by: Green 2007 (paper P8); Valve's in-game text; many engines. Rejected because: SDFs blur sharp corners and are inexact at small sizes — the opposite of this system's small-size sharpness goal (§Phase 11) and byte-exact grayscale contract (Principle 15). SDF/MSDF is logged as a possible future output mode in the §Deferred Features Register, not the core.

Alt-C — Pure supersampling rasterizer (N×N coverage by counting samples).

   outline ──▶ scan-convert at N× resolution (e.g. 4×4) into a bilevel
              oversampled buffer ──▶ box-downsample blocks ──▶ 8-bit alpha

Wins when: you want the simplest possible correct AA, already have a fast bilevel scan converter, and memory/throughput are not constrained (offline rendering, a teaching baseline). Embodied by: many early/simple rasterizers; the conceptual baseline in books B1/B2. Rejected because: N×N supersampling costs N²× memory and time and still aliases at low N, versus the 1×-memory exact signed-area method (ADR-9, MM3, §Phase 8). The monochrome Phase 7 path is a correctness baseline, deliberately not promoted to the production AA path for exactly this reason.
