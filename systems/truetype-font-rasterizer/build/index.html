⬜ Phase 0 — Repo skeleton + sfnt container loader + table directory + checksum + bounds-checked reader

Objectives

Establish no_std core, the single trust gate (Reader), container detection, table directory parse with bounds validation, checksum verify, typed errors, CI, fuzz harness. Scope: read-only container parsing; no glyph data yet. Constraint introduced: all byte access via Reader; #![forbid(unsafe_code)] in core.

Deliverable

ttfr inspect font.ttf prints the table directory; library opens a font and exposes table records; fuzz target runs clean.

Acceptance
  • FontRef::new on 20 real fonts succeeds; directory matches fonttools ttx -l output exactly (tag/offset/length).
  • All malformed-container fuzz inputs (1M execs) → Err, zero panics, zero UB (miri/ASAN-clean).
  • 100% of reads go through Reader (grep audit: no raw slice index in sfnt/).
  • Open time < 50 µs for a 200 KB font (directory only).
Fixtures
Fixture Expected
DejaVuSans.ttf directory: head,maxp,...,glyf,loca present
collection.ttc numFonts ≥ 2; each offset table parses
malformed/bad_magic.bin Err(UnsupportedSfntVersion)
malformed/truncated_dir.ttf Err(OutOfBounds) on directory parse
malformed/table_oob.ttf Err(OutOfBounds{table=...}) (I1)
Pitfalls
  • Trusting searchRange/binary-search params from file → use them and you read OOB; recompute.
  • ttcf offsets pointing mid-file/overlapping → validate each offset table independently.
  • Integer overflow in offset+length (u32+u32) → compute in u64.
  • Assuming tables are 4-byte aligned in code paths that read u32 directly → Reader is alignment-agnostic (byte-wise), keep it so.
  • Forgetting padding when checksumming the last table → pad to 4 with zeros.

⬜ Phase 1 — head / maxp / hhea / hmtx / post / OS-2 parsing

Objectives

Parse scalar metadata tables → expose unitsPerEm, numGlyphs, indexToLocFormat, font bbox, ascent/descent, per-glyph advance/lsb, glyph names, weight/width. Constraint: enforce I17 (unitsPerEm range), I15 (advance ≥0).

Deliverable

ttfr metrics font.ttf --char A prints unitsPerEm, numGlyphs, advance, lsb, ascent/descent, glyph name.

Acceptance
  • unitsPerEm, numGlyphs, ascent/descent match fonttools for 20 fonts.
  • advance(gid) matches hmtx for first, last, and a monospaced-tail glyph.
  • BadUnitsPerEm returned for upem=0 fixture; MissingTable(maxp) if maxp absent.
Fixtures
Fixture Expected
Roboto-Regular.ttf upem=2048, advances match
monospace.ttf tail glyphs reuse last advance
malformed/upem_zero.ttf Err(BadUnitsPerEm)
no_post.ttf name(gid)=None, render still works
os2_v0.ttf parses without reading missing later fields
Pitfalls
  • numberOfHMetrics > numGlyphs (malformed) → clamp, warn, else OOB in lsb tail.
  • post format 2 string index out of range → return None, do not panic.
  • Treating unitsPerEm non-power-of-2 as error → it is legal (e.g. 1000 for CFF-derived).
  • OS/2 absence → must not block render (only metadata).
  • Signed vs unsigned: advanceWidth is u16, lsb is i16; mixing them silently mis-scales.

⬜ Phase 2 — cmap (formats 0/4/6/12/14); codepoint → GlyphId; .notdef

Objectives

Map Unicode codepoints to glyph ids; pick best subtable; guarantee I16 (gid<numGlyphs); unmapped → glyph 0. Constraint: defensive parse of every subtable (offsets, segment arrays).

Deliverable

ttfr inspect --cmap lists subtables; glyph_index('A') returns correct gid; unmapped → 0.

Acceptance
  • glyph_index matches fonttools cmap for ASCII + a supplementary-plane char (e.g. U+1F600 if present) across fonts with fmt4 and fmt12.
  • Unmapped codepoint → 0 (.notdef), never panic.
  • Subtable with OOB offset is skipped; if all unusable → only .notdef resolvable, UnsupportedCmap only when zero subtables.
Fixtures
Fixture Expected
DejaVuSans.ttf fmt4 selected; 'A'→known gid
NotoSansCJK-subset.otf fmt12; CJK codepoint resolves
emoji-subset.ttf fmt12; U+1F600 resolves (if present)
malformed/cmap_offset_oob.ttf subtable skipped; fallback or UnsupportedCmap
malformed/cmap_seg_bad.ttf fmt4 lookup bounded, no OOB
Pitfalls
  • Format 4 idRangeOffset arithmetic is the classic OOB bug → compute index in i64, bounds-check against glyphIdArray slice.
  • Forgetting idDelta mod 65536 wraparound → wrong gid for high-delta segments.
  • Selecting a Mac (1,0) subtable over a Unicode one → wrong mapping; enforce preference order.
  • Format 12 unsorted/overlapping groups → binary search misbehaves; validate ascending non-overlapping or linear-fallback.
  • Treating PUA / unmapped as error → must map to 0 silently.

⬜ Phase 3 — loca + simple glyf parsing

Objectives

Parse loca (short/long), validate I3; decode simple glyphs (flag RLE, delta coords, contour endpoints) into Outline in funits. Constraint: I4 (point/contour index validity), caps (≤1024 contours, ≤20000 points).

Deliverable

ttfr inspect --outline A dumps contour count + points (funits, on/off). examples/dump_outline.rs → SVG path.

Acceptance
  • Point counts + coordinates match fonttools glyf dump for 'A','O','g' across fonts.
  • Empty glyph (space) → Glyph::Empty, no points.
  • Malformed (loca_oob, truncated_glyf, bad endpoints) → typed Err, no panic.
  • Contour/point caps enforced (reject beyond).
Fixtures
Fixture Expected
DejaVuSans.ttf 'A' N contours, point set matches ttx
*.ttf space glyph Empty
malformed/loca_oob.ttf Err(BadLoca::OutOfRange)
malformed/truncated_glyf.ttf Err(OutOfBounds)
malformed/endpts_bad.ttf Err(BadGlyph)
malformed/points_bomb.ttf (1e6 pts) Err(BadGlyph) (cap)
Pitfalls
  • Delta decode is two separate passes (all x then all y); interleaving corrupts coords.
  • X_IS_SAME_OR_POSITIVE dual meaning depending on X_SHORT (§8.7) — mis-handling flips signs / zeros.
  • REPEAT_FLAG count overrunning numPts → bound it.
  • Forgetting first delta is relative to 0 (absolute origin).
  • Reading instruction bytes as coordinates (must skip instructionLength first).

⬜ Phase 4 — composite glyphs

Objectives

Decode composite glyphs: component transforms (uniform/x,y/2×2 F2Dot14), offsets vs point-match, recursion with depth cap (I5), cycle detection (I6), bbox union, optional inherited instructions. Constraint: total expanded points ≤ 100000.

Deliverable

é, Å, accented + CJK composites build into a single merged Outline; bbox correct.

Acceptance
  • Composite glyph point set == union of transformed components, matches fonttools-rendered outline (SVG diff < epsilon).
  • composite_cycle.ttf → Err(CompositeCycle); depth>cap → Err(CompositeTooDeep).
  • Component gid≥numGlyphs → Err(OutOfBounds).
Fixtures
Fixture Expected
DejaVuSans.ttf 'é' 2 components (e + acute), merged outline
*.ttf 'Å' ring over A
malformed/composite_cycle.ttf Err(CompositeCycle)
malformed/composite_deep.ttf (depth 9) Err(CompositeTooDeep)
malformed/composite_badref.ttf Err(OutOfBounds)
Pitfalls
  • F2Dot14 sign/scale conversion: 0x4000=1.0, 0xC000=−1.0; mis-scale shears glyphs.
  • Point-match (!ARGS_ARE_XY_VALUES) is rarely used and easy to get wrong → align child point to parent point.
  • SCALED vs UNSCALED component offset differs Apple/MS → default MS (unscaled) unless flag set.
  • Forgetting recursion can nest composites of composites.
  • Reusing parent's point indices for child without offsetting after merge → corrupt contours.

⬜ Phase 5 — outline model + quadratic reconstruction + funit→device affine scaling

Objectives

Convert raw on/off-curve points into renderable quadratic segments (implied midpoints, §8.9); apply scaling (device=funit·ppem/upem) + user affine + y-flip into 26.6 (§8.10). Constraint: I9 (no i32 overflow, i64 intermediates), I10 (positive ppem), I14 prep (clamp later).

Deliverable

Scaled device-space outline as quadratic/line segments; dump_outline shows pixel-space path; bbox in device px.

Acceptance
  • Scaling formula verified: a glyph at ppem=upem renders 1:1 with funits (within rounding).
  • Implied-midpoint reconstruction matches a hand-worked contour (§8.9 example) exactly.
  • No overflow for max coords at max ppem (property test on i64 bounds).
  • Device bbox matches scaled funit bbox (± rounding).
Fixtures
Fixture Expected
unit_square.ttf (1 contour) scales linearly with ppem
all_offcurve.ttf implied midpoints reconstructed
offcurve_start.ttf correct start point synthesis
property: random coords × random ppem no i32 overflow, bbox consistent
Pitfalls
  • Rounding mode drift (round-half-up vs even) → 1-px instability; pick one, enforce (Principle 11).
  • Scaling before vs after reconstruction changes hinting; document and stay consistent.
  • y-flip reference point wrong → glyph upside-down or vertically shifted.
  • Multiplying funit·ppem in i32 overflows for large fonts → must use i64.
  • Off-curve-start contour mishandled → first segment wrong.

⬜ Phase 6 — adaptive Bézier flattening → polylines

Objectives

Flatten quadratic (and later cubic) segments into line segments within flatness tolerance (≤0.25 px device) via adaptive de Casteljau; bound recursion; emit monotone-friendly edges. Constraint: bounded subdivision depth; deterministic segment count.

Deliverable

EdgeList of line segments approximating the outline within tolerance; segment count reasonable (e.g. tens per glyph at 16 px).

Acceptance
  • Max deviation of polyline from true Bézier ≤ tol (measured on test curves).
  • Segment count bounded (no explosion at high curvature); depth cap respected.
  • Flattening deterministic (same input → same segments).
  • Visual: flattened 'O' renders smooth at 16–64 px (no faceting visible).
Fixtures
Fixture Expected
quarter-circle quad deviation ≤ tol, N segments stable
high-curvature cusp depth cap engaged, no infinite recursion
straight "quad" (degenerate) emitted as single line
'O' at 12/24/48 px smooth, segment count grows sub-linearly
Pitfalls
  • Using sqrt in flatness test → slow + nondeterministic; use squared distance.
  • Tolerance in wrong space (em vs device) → over/under-tessellation; tol is device px.
  • No depth cap → near-cusp curves recurse forever.
  • Re-flattening shared component edges twice in composites → dedupe at segment stage.
  • Tolerance too tight → segment explosion → slow raster; too loose → faceting.

⬜ Phase 7 — monochrome scanline rasterizer (active edge table, non-zero winding)

Objectives

Bilevel correctness baseline: scan-convert flattened edges into a 1-bpp bitmap using an active edge table and non-zero winding fill. Establishes pixel-grid conventions (Principle 11). Constraint: I7/I8 (closed contours, defined winding).

Deliverable

ttfr render --char A --size 32 --mono → 1-bpp PGM/PNG; recognizable letterform.

Acceptance
  • Rendered 'A','O','g','é' at 32 px are correct letterforms (visual + golden mono bitmaps).
  • 'O' counter is hollow (non-zero winding works with opposing contour orientation).
  • Self-intersecting / overlapping contours fill correctly (non-zero).
  • left/top/advance consistent across glyphs (baseline aligns).
Fixtures
Fixture Expected
DejaVuSans.ttf 'A'@32 mono golden bitmap match
*.ttf 'O'@32 mono hollow counter
overlap.ttf overlapping contours fill (no holes)
same_orient_O.ttf counter fills solid (documents winding requirement)
Pitfalls
  • Sampling at pixel corner vs center → consistent 1-px shift; fix center sampling once.
  • Forgetting horizontal edges contribute no winding but must be dropped (not double-counted).
  • Even-odd instead of non-zero → counters wrong for overlapping/same-orientation contours.
  • Edge endpoints exactly on scanline (top/bottom inclusivity) → double count or gaps; use half-open [y0,y1) rule.
  • Bit packing order (MSB vs LSB first) mismatched with consumer.

⬜ Phase 8 — anti-aliased coverage rasterizer (signed-area cells)

Objectives

Production AA path: analytic coverage via signed-area cells (FreeType smooth-style), accumulation sweep → 8-bit alpha. Default render mode. Constraint: I14 (coverage∈[0,1]), determinism (integer only), 1× memory.

Deliverable

ttfr render --char A --size 16 → smooth 8-bit alpha PNG; edges anti-aliased.

Acceptance
  • AA bitmaps differ from FreeType reference by SSIM ≥ 0.98 and max per-pixel |Δ| ≤ small threshold (e.g. ≤ 8/255) across a corpus (differential test).
  • Coverage values within [0,255]; no overflow/wrap in cell accumulation (i32, proven bounds).
  • Deterministic: identical bytes on x86-64 and aarch64 (CI cross-check).
  • Throughput ≥ 200k glyphs/sec @16 px Latin (criterion).
Fixtures
Fixture Expected
DejaVuSans.ttf 'A'@16 golden gray8 + SSIM vs FreeType ≥0.98
*.ttf 'g'@13 (odd size) smooth, golden match
diagonal-stem glyph even AA along diagonal
property: coverage ∈[0,255] for random outlines always holds
cross-arch render byte-identical
Pitfalls
  • Sign errors in cover/area accumulation → inverted or doubled coverage (most common smooth-rasterizer bug).
  • Pixel boundary clipping of edges off-by-one → seams/over-coverage at integer x.
  • Not clamping winding>1 regions (overlaps) → coverage >255 wrap; clamp.
  • Forgetting to flush the last cell row.
  • Float in accumulation → cross-platform diffs (forbidden, I21).

⬜ Phase 9 — metrics + kerning (kern + GPOS PairPos subset)

Objectives

Complete metrics: advance/lsb/bbox per glyph (device); kerning via kern format 0 and GPOS PairPos (format 1/2) subset. Constraint: kerning only — no full GPOS (deferred); I15 advance≥0.

Deliverable

ttfr metrics --pair A V prints advance + kern; rendered "AV" shows reduced spacing.

Acceptance
  • Advance/lsb/bbox match fonttools/FreeType for sampled glyphs.
  • Kern pair (e.g. "AV","To") matches reference value (kern or GPOS) within rounding.
  • GPOS class-based (format 2) kerning resolves for a class-kerned font.
  • Unsupported GPOS lookups ignored without error.

⬜ Phase 10 — glyph cache + atlas packing

Objectives

Cache rendered bitmaps keyed by full identity (I19); LRU eviction under MB budget; atlas bin-packing for GPU consumers. Constraint: shared-read concurrency (interior mutability); cache correctness provable.

Deliverable

ttfr atlas --chars "A-Za-z0-9" --size 24 → atlas.png + atlas.json (slots, metrics). Cache hit ratio reported.

Acceptance
  • Cache returns byte-identical bitmap on hit vs fresh render (I19).
  • Eviction keeps memory ≤ budget; hit ratio > 95% on repeated text workload.
  • Atlas has no bleed (1px pad verified); all glyphs placed; growth correct when full.
  • Concurrent get_or_render from N threads is race-free (loom/stress test).
Fixtures
Fixture Expected
repeated render same key second is hit, identical bytes
budget-overflow workload memory ≤ budget, LRU evicts
atlas ASCII set @24 all placed, no overlap/bleed
atlas overflow set second sheet allocated
concurrent stress no data race (sanitizer/loom)
Pitfalls
  • Forgetting transform/hint_mode in key → wrong bitmap served for different transform (I19 violation).
  • Float size in key → non-deterministic hashing; quantize to exact bits / ppem integer.
  • Atlas without padding → texture bleed at glyph edges when sampled bilinearly.
  • LRU accounting drift (bytes not decremented on evict) → unbounded growth.
  • Lock held during render (slow) → contention; render outside lock, insert after.

⬜ Phase 11 — TrueType hinting VM

Objectives

Interpret TrueType bytecode (fpgm → prep → glyph program) to grid-fit outlines at small ppem (sharper stems, consistent weights). Bounded by instruction + loop budget (I13) and stack/jump/index safety (I11/I12/I20). Default OFF; opt-in via HintMode::Bytecode. Many sub-instructions PhaseDeferred.

Deliverable

ttfr render --char m --size 11 --hint vs --no-hint: hinted version has even stem weights / sits on pixel grid. gasp table consulted for hint/AA ranges.

Acceptance
  • Hinted output for a hinted font (e.g. system font) matches FreeType bytecode-hinted render by SSIM ≥ 0.95 at 8–14 ppem on a sample set.
  • Budget/loop caps enforced: hint_loop_bomb.ttf → HintBudgetExceeded, falls back to unhinted, no hang.
  • Stack/jump/index faults → unhinted fallback, no panic (fuzz fuzz_hint).
  • Determinism: hinted bitmap byte-identical cross-arch.
Fixtures
Fixture Expected
hinted_system.ttf 'm'@11 hinted SSIM ≥0.95 vs FreeType hinted
malformed/hint_loop_bomb.ttf HintBudgetExceeded → unhinted fallback
malformed/hint_stack_underflow.ttf HintStackFault → fallback
malformed/hint_bad_jump.ttf HintBadJump → fallback
no_prep.ttf hinted renders (no prep = identity setup)
Pitfalls
  • IUP after partial point touching is subtle → wrong IUP corrupts whole glyph outline; test against reference.
  • Freedom/projection vector math (dot products in fixed-point) overflow/precision → use careful 16.16/i64.
  • Rounding state machine (SROUND period/phase/threshold) is intricate → table-driven, tested.
  • Forgetting fpgm runs once but prep runs per ppem → re-running fpgm corrupts FDEFs / wastes budget.
  • Infinite loops via JMPR/LOOPCALL → budget + loop cap are mandatory, not optional.
  • Twilight zone vs glyph zone pointer (zp0/1/2) confusion → moves wrong points.

⬜ Phase 12 — subpixel/LCD + gamma + CFF/Type2 cubic + conformance/fuzz hardening

Objectives

Optional enhancements + second outline technology + hardening: LCD subpixel rendering, gamma-correct blending, CFF/Type2 (cubic) outline extraction, expanded conformance + fuzz corpus. Several items PhaseDeferred. Constraint: keep grayscale path default; CFF behind module; LCD behind feature.

Deliverable

ttfr render --char a --size 13 --lcd --gamma 2.2 → RGB subpixel PNG; CFF .otf renders via --font X.otf through the same pipeline; expanded golden + fuzz corpora committed.

Acceptance
  • LCD render matches FreeType LCD (with same filter) SSIM ≥ 0.95; gamma blending visibly correct stem weight (golden).
  • CFF/Type2: rendered CFF glyph matches FreeType CFF render SSIM ≥ 0.98; cubic flattening within tol.
  • Fuzz: ≥ 24h continuous, zero crashes across all targets; corpus minimized + committed.
  • All malformed fixtures produce typed errors; differential corpus passes.
Fixtures
Fixture Expected
*.ttf 'a'@13 lcd SSIM ≥0.95 vs FreeType LCD
gamma on/off stem weight differs per golden
SourceSerif.otf (CFF) glyph SSIM ≥0.98 vs FreeType
cid_cff.otf FDSelect resolves, renders
malformed/cff_subr_loop.otf bounded (subr depth cap), no hang
fuzz corpus (all targets) zero crash 24h
Pitfalls
  • Type2 charstring subr recursion (callsubr/callgsubr) unbounded → depth cap (like composites/hints). Documented incident: the jailbreakme.com v3 ("Star", 2010) iOS exploit weaponized CVE-2010-1797, a stack buffer overflow in FreeType's CFF/Type-2 charstring interpreter, to achieve remote code execution from a malicious font in a PDF. This is the canonical reason CFF subr handling is treated as adversarial: bound depth (Principle 2) and bounds-check every charstring stack op (I11-analogue).
  • hintmask byte-count depends on declared stem count → desync mis-parses charstring.
  • CFF subr bias offset (107/1131/32768 by count) miscomputed → wrong subr called.
  • LCD filter not normalized → brightness shift; energy must sum to 1.
  • Gamma applied in wrong direction (encode/decode swapped) → too thin/thick.
  • CID FDSelect format 0 vs 3 parse difference.
