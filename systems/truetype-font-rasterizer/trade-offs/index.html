Alternative Architectures (Roads Not Taken)

Three fundamentally different designs for the same problem — glyph → bitmap — each with the regime where it wins, the real system that embodies it, and why this blueprint rejected it.

Alt-A — GPU implicit-curve rendering (resolution-independent, no flattening).

   outline ──▶ classify quads/cubics ──▶ upload control points + curve
              into triangles            type to GPU ──▶ fragment shader
                                         evaluates implicit f(x,y)≷0 per
                                         pixel ──▶ AA via screen-space
                                         derivatives (fwidth)

Wins when: rendering at many scales/rotations every frame on a GPU (3D text, maps, zoomable UI) — curves stay exact, no per-size re-flatten. Embodied by: Loop & Blinn (paper P7); Slug library; aspects of modern GPU text. Rejected because: this is a CPU, no_std, deterministic-byte-output rasterizer (ADR-9, Principle 4) feeding a glyph cache/atlas (§Phase 10); a GPU shader path is non-deterministic across drivers and assumes a GPU the embedder may not have. Kept as the informational alternative behind paper P7.

Alt-B — Signed-distance-field (SDF) glyph atlas.

   outline ──▶ render once at high res ──▶ compute per-texel signed
              distance to nearest edge ──▶ store low-res SDF in atlas
              ──▶ GPU samples + alpha-tests with smoothstep at any scale

Wins when: one bake, then cheap re-scale/outline/glow effects on GPU at arbitrary size (game UIs, AR/VR HUDs). Embodied by: Green 2007 (paper P8); Valve's in-game text; many engines. Rejected because: SDFs blur sharp corners and are inexact at small sizes — the opposite of this system's small-size sharpness goal (§Phase 11) and byte-exact grayscale contract (Principle 15). SDF/MSDF is logged as a possible future output mode in the §Deferred Features Register, not the core.

Alt-C — Pure supersampling rasterizer (N×N coverage by counting samples).

   outline ──▶ scan-convert at N× resolution (e.g. 4×4) into a bilevel
              oversampled buffer ──▶ box-downsample blocks ──▶ 8-bit alpha

Wins when: you want the simplest possible correct AA, already have a fast bilevel scan converter, and memory/throughput are not constrained (offline rendering, a teaching baseline). Embodied by: many early/simple rasterizers; the conceptual baseline in books B1/B2. Rejected because: N×N supersampling costs N²× memory and time and still aliases at low N, versus the 1×-memory exact signed-area method (ADR-9, MM3, §Phase 8). The monochrome Phase 7 path is a correctness baseline, deliberately not promoted to the production AA path for exactly this reason.
