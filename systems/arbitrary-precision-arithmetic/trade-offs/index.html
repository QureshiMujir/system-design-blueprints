Decisions (§9) · 30 ADRs

ADR-01

Implementation language

Chosen

Rust (stable toolchain)

Rejected

C, C++, Zig, Go

When the rejected choice is right

C/C++ when per-microarchitecture hand-written assembly is required to reach GMP-class throughput; Go when GC-managed simplicity and fast compile outrank raw speed

Why: Memory safety without GC; zero-cost abstractions; ownership enforces I3 (no silent carry drop); u128 native for DoubleLimb; cargo ecosystem

ADR-02

Build system

Chosen

Cargo (workspace with [workspace])

Rejected

Bazel, CMake, Meson

When the rejected choice is right

Bazel in a large polyglot monorepo with remote caching; CMake/Meson when embedding into an existing C/C++ build

Why: Native Rust; crate-level incremental compilation; workspace unifies all bn-* crates under one Cargo.lock

ADR-03

Workspace structure

Chosen

12 crates in single workspace

Rejected

Monorepo with independent manifests, single mega-crate

When the rejected choice is right

A single mega-crate when the library always ships as one unit and per-crate dependency slicing is never needed

Why: Per-crate compile isolation; downstream can depend on bn-uint without bn-fftmul; compile-time boundary enforcement

ADR-04

Dependency policy

Chosen

num-traits for Zero/One/Num traits only; otherwise zero external dependencies in library crates

Rejected

num-bigint as substrate, rug/GMP bindings

When the rejected choice is right

rug/GMP bindings when production-grade speed is the only goal and the from-scratch mandate does not apply

Why: From-scratch educational goal; GMP bindings would bypass the implementation; num-traits is interface-only, no algorithm code

ADR-05

Limb word width

Chosen

u64 (Limb); u128 for double-limb

Rejected

u32/u64 mixed (GMP style), u32 only

When the rejected choice is right

u32 limbs on 32-bit targets lacking a 64-bit multiplier or where u128 intrinsics are unavailable

Why: x86-64 and AArch64 have 64-bit multiply; u128 in Rust is compiler-intrinsic, not a dependency; halving limb count halves loop iterations

ADR-06

Limb endianness

Chosen

Little-endian Vec<Limb> (index 0 = least significant)

Rejected

Big-endian, mixed

When the rejected choice is right

Big-endian when interoperating with a big-endian wire format where avoiding byte-swap on I/O outweighs arithmetic scan convenience

Why: Add/sub/mul naturally scan low-to-high; resize (push/pop) touches the high end (cheap); matches GMP mpn convention

ADR-07

Serialization / wire format

Chosen

None in library crates (bn-core through bn-rational); bn-convert owns Display / from_str

Rejected

serde derive in library

When the rejected choice is right

serde in core when the dominant use is (de)serialization-heavy and every consumer already accepts the dependency

Why: Serialization policy belongs to consumers; no mandatory serde dep avoids compile-time bloat in constrained environments

ADR-08

bn-cli I/O format

Chosen

Plain text: newline-separated decimal/hex; --base N flag

Rejected

JSON, binary packed

When the rejected choice is right

JSON when the CLI feeds a structured tooling pipeline; binary packed for high-throughput operand transfer between processes

Why: Human-readable for a calc/bench tool; JSON adds serde_json dep unnecessarily

ADR-09

Error handling

Chosen

thiserror-derived typed errors (ParseError, DivByZero) returned as Result<T, E>; no panic on arithmetic

Rejected

anyhow everywhere, panic-on-error

When the rejected choice is right

anyhow in an application binary where error kinds are never matched; panic-on-error only in a throwaway script

Why: Library code must not panic on user input (I5); thiserror zero-cost, no runtime overhead; anyhow appropriate only in binaries (bn-cli)

ADR-10

Multiplication dispatch

Chosen

Compile-time constants for thresholds; runtime branch in bn_mul::mul

Rejected

Trait objects / dynamic dispatch, proc-macro dispatch

When the rejected choice is right

Dynamic dispatch when algorithms must be pluggable at runtime by users (a research/experimentation harness comparing variants)

Why: Branch is a single integer compare; trait objects add vtable indirection per call; constants tunable by benchmarks in Phase 14

ADR-11

NTT prime selection

Chosen

Three hard-coded NTT-friendly primes (≡ 1 mod 2^k) with product > max coefficient

Rejected

Dynamic prime search at runtime

When the rejected choice is right

Dynamic prime search when operand sizes exceed what the fixed prime product supports and the range must extend at runtime

Why: Deterministic, reproducible; verified once offline; dynamic search adds startup cost and complexity

ADR-12

Montgomery context caching

Chosen

Montgomery struct holds precomputed n_prime and r2; caller constructs once per modulus

Rejected

Recompute per operation

When the rejected choice is right

Recompute-per-op when each modulus is used exactly once, making precomputation pure overhead

Why: Modular exponentiation calls REDC O(log e) times per exponentiation; amortized precomputation is mandatory (P6)

ADR-13

Constant-time modpow

Chosen

Optional feature flag ct-modpow; default is variable-time; ct path uses constant-time table lookup

Rejected

Always variable-time, always constant-time

When the rejected choice is right

Always-constant-time when the library is crypto-only and any variable-time path is a liability; always-variable-time when no secret ever flows through it

Why: Variable-time is faster for non-crypto use; ct required for crypto consumers (P9); feature flag lets callers opt in without overhead

ADR-14

Concurrency / async

Chosen

None — library crates are fully synchronous; Send + Sync derived where Vec<u64> allows

Rejected

rayon parallelism in NTT, async API

When the rejected choice is right

rayon when huge-operand multiply is wall-clock-bound on many cores; an async API when the bignum is wrapped behind a network service

Why: Correctness-first (P1); parallel NTT is a Phase 14 extension if benchmarks justify; library is not an async executor

ADR-15

Testing framework

Chosen

#[test] + proptest (property-based) + cargo-fuzz (libFuzzer)

Rejected

quickcheck, custom harness

When the rejected choice is right

quickcheck in a codebase already standardized on it; a custom harness when inputs need domain generation proptest cannot express

Why: proptest has richer shrinking; cargo-fuzz is de-facto Rust fuzzing standard; no bespoke framework maintenance

ADR-16

Differential / conformance testing

Chosen

Compare against num-bigint (Rust) and Python int via subprocess

Rejected

GMP via C FFI in test harness

When the rejected choice is right

GMP FFI oracle when matching GMP's exact behaviour (not just correctness) is the goal and a C toolchain in CI is acceptable

Why: num-bigint is pure Rust, no C FFI in CI; Python subprocess is portable; GMP FFI adds C toolchain dependency and unsafety

ADR-17

Benchmarking

Chosen

criterion (statistical, HTML reports)

Rejected

iai, hyperfine, custom timing

When the rejected choice is right

iai (instruction-count) for noise-free CI regression detection on shared runners; hyperfine for whole-binary CLI timing

Why: Criterion is the Rust standard; wall-clock statistical with noise reduction; needed to tune MulAlgo thresholds (Phase 14)

ADR-18

Logging / tracing

Chosen

None in library crates; tracing (with tracing-subscriber) in bn-cli only

Rejected

log crate, env_logger

When the rejected choice is right

The log facade when consumers are standardized on log and structured spans add no value

Why: tracing is structured and composable; library crates must not emit to stderr/stdout (consumer decides); log is a lesser alternative

ADR-19

Metrics / observability

Chosen

None in library; bn-cli bench subcommand emits JSON timing to stdout

Rejected

Prometheus metrics, OpenTelemetry

When the rejected choice is right

Prometheus/OpenTelemetry when the bignum runs inside a long-lived service needing live metrics, not a one-shot CLI

Why: Library has no daemon; bench output is machine-parseable for CI regression detection without a telemetry stack

ADR-20

CI/CD

Chosen

GitHub Actions: cargo test --workspace, cargo clippy, cargo fmt --check, cargo fuzz (short duration), criterion regression check

Rejected

CircleCI, Jenkins, bare Makefile

When the rejected choice is right

Self-hosted Jenkins for private repos needing custom hardware or air-gapped builds

Why: GitHub Actions free for public repos; native Rust caching (sccache); fuzz in CI catches regressions before merge

ADR-21

Fuzz targets

Chosen

cargo-fuzz targets: fuzz_parse, fuzz_divmod, fuzz_modpow, fuzz_from_to_base

Rejected

Only unit tests, AFL

When the rejected choice is right

Unit-only for a frozen, fully-covered API with no untrusted input; AFL for whole-binary, file-driven fuzzing

Why: Fuzz covers the parser (I9), division (I5, I6), modpow (I7), and conversion (I9) — highest-risk code surfaces

ADR-22

Packaging / distribution

Chosen

crates.io for each bn-* crate; [workspace.package] for unified version

Rejected

Single crate with feature flags, private registry

When the rejected choice is right

A single feature-flagged crate when consumers always want the whole library and partial dependency is never a use case

Why: Per-crate publishing lets consumers depend on bn-uint alone; feature flags would entangle compile graph

ADR-23

MSRV (minimum supported Rust version)

Chosen

Rust 1.79 stable (for u128 carry ops, core::hint::black_box)

Rejected

nightly for intrinsics, oldest stable

When the rejected choice is right

Nightly when unstable carry intrinsics are needed for peak speed; oldest-stable when supporting very conservative downstreams

Why: u128 stable since 1.26; black_box stable since 1.66; 1.79 gives carry_add / borrowing_sub on nightly-stabilized paths if desired

ADR-24

Licensing

Chosen

MIT OR Apache-2.0 (dual)

Rejected

GPL, MIT-only, proprietary

When the rejected choice is right

GPL when copyleft reciprocity is a goal; MIT-only when Apache's explicit patent grant is undesirable for a particular downstream

Why: Standard Rust crate dual-license; compatible with GMP-derived ideas (ideas, not code); permissive for downstream embedding

ADR-25

Reproducible builds

Chosen

Cargo.lock committed; workspace pins all deps; CI builds use locked deps (--locked)

Rejected

Floating deps, no lockfile

When the rejected choice is right

Floating deps for a library meant to ride upstream fixes (applications pin the lockfile; libraries float)

Why: Ensures bit-identical artifacts across machines; prevents supply-chain surprises in dependencies

ADR-26

Unsafe code policy

Chosen

#![forbid(unsafe_code)] in all library crates; unsafe permitted only in bn-cli for black_box benchmark helper

Rejected

Unsafe limb kernels for performance

When the rejected choice is right

Unsafe limb kernels when a profiled hot loop needs SIMD intrinsics the safe optimizer won't emit and the audit cost is accepted

Why: Correctness over micro-optimizations (P1); Rust's optimizer handles u128 arithmetic without unsafe; unsafe adds audit burden

ADR-27

Feature flags

Chosen

bn-mod: ct-modpow for constant-time path; bn-fftmul: ntt-parallel (Phase 14 extension placeholder); no other flags

Rejected

Pervasive feature flags per algorithm

When the rejected choice is right

Pervasive per-algorithm flags when binary-size minimization for embedded targets dominates over build simplicity

Why: Minimize conditional compilation complexity; two well-defined flags cover the known use-case split

ADR-28

Documentation

Chosen

cargo doc + #[doc] on all public items; examples in doc-tests; ADR decisions referenced in module-level docs

Rejected

Separate wiki, mdBook

When the rejected choice is right

An mdBook/wiki when there is a large conceptual narrative (tutorials, theory) beyond the API reference

Why: Doc-tests are compile-tested; no drift between docs and code; cargo doc --open gives immediate browsable API

ADR-29

Containers

Chosen

Docker image for CI (rust:1.79-slim); no runtime container required for the library

Rejected

Alpine, distroless, none

When the rejected choice is right

distroless/alpine for a minimal production runtime image when the bignum is deployed as a service rather than source

Why: rust:slim avoids musl cross-compilation issues for criterion benchmarks; library ships as source, not container

ADR-30

Algorithm cross-check strategy

Chosen

In #[test]: for each of Karatsuba/Toom3/NTT, generate random inputs, verify result == schoolbook (I4); Newton divrem == Knuth (I6); Montgomery roundtrip (I7)

Rejected

Runtime assertions, debug-only checks

When the rejected choice is right

Debug-only runtime assertions when shipping a debug build to a consumer who wants in-production self-checks and accepts the slowdown

Why: Tests run in CI; runtime assertions in hot path violate P4 (paid even in production); separation keeps kernels fast

Alternative Architectures (Roads Not Taken)

A1 — Fixed-width / stack-inlined limbs (small-size optimization).

[u64; K]  ── on stack, no heap ── add/mul over fixed K limbs

Wins for crypto with known modulus sizes (256/4096-bit) where heap allocation dominates and operands never grow. Embodied by fixed-width crates (crypto-bigint, EVM U256). Rejected because bn is arbitrary-precision by mandate (§1); a fixed cap defeats the purpose (an SSO fast path could be added later, not as the core).

A2 — Schönhage–Strassen FFT over Z/(2ⁿ+1) (single transform, no CRT).

operands → negacyclic transform mod 2^n+1 → pointwise mul → inverse

Wins at extreme sizes (millions of digits) where SS's O(n log n log log n) and the absence of CRT recombination pay off. Embodied by GMP's FFT path. Rejected because three-prime NTT is simpler to keep exact and target sizes (≤ 1M limbs) sit below the SS advantage (Phase 6).

A3 — Residue Number System (RNS).

x → (x mod p1, x mod p2, … )  ── add/mul fully parallel per channel

Wins when add/mul are the only operations and they can run parallel/SIMD per residue (DSP, some FHE backends). Embodied by RNS-CKKS. Rejected because comparison, division, and base conversion are expensive in RNS, and this library must support all of them (Phases 7, 12).

A4 — GMP FFI wrapper (link libgmp, safe Rust facade).

Rust API → unsafe FFI → libgmp (mpz_*) → result

Wins when you only need the fastest possible bignum and don't care how it's built. Embodied by the rug crate. Rejected because the project's purpose is from-scratch mastery (§1, ADR-04); wrapping GMP bypasses every lesson.
