3.2 Subsystem Descriptions

bn-core — The zero-dependency foundation. Defines Limb = u64, DoubleLimb = u128, SignedDoubleLimb = i128, Sign { Minus, NoSign, Plus }, MulAlgo, NttPlan, ParseError, DivByZero, Base. No heap allocation, no I/O. All other crates depend on it; it depends on nothing in the workspace. Data flows out only: type definitions and constants are consumed everywhere.

bn-uint — The unsigned magnitude layer. BigUint { limbs: Vec<Limb> } stores the little-endian magnitude. Enforces I1 (no trailing zeros) on every mutation via normalize(). Provides comparison (length-then-high-limb-descending), from/to u64/u128, shift-left/right by bit count, bit-length, count_ones, trailing_zeros, set_bit, test_bit. All unsigned algorithms operate on BigUint or borrowed Limbs<'a> slices. No sign semantics here. Data in: raw Vec<Limb> construction or primitive casts. Data out: normalized BigUint references consumed by all arithmetic crates.

bn-add — Carry/borrow propagation kernels. add_assign(a, b) loops limb-by-limb accumulating carry in a u128; result may grow by one limb. sub_assign(a, b) requires a >= b (unsigned contract); borrows via i128. add_mul_1(a, b, c: Limb) computes a += b * c — the inner kernel consumed by schoolbook multiply and Newton iteration. All functions operate in-place on LimbsMut<'a> to avoid allocation. Data in/out: mutable limb slice pairs.

bn-mul — Multiplication dispatch. mul(a, b) -> BigUint selects MulAlgo from a.limbs.len() and b.limbs.len() against locked threshold constants. Schoolbook is the correctness oracle (Phase 4). Karatsuba splits at the midpoint, recurses on three half-sized products. Toom-Cook-3 evaluates at five points, interpolates with exact integer arithmetic. For operands above the NTT threshold, delegates to bn-fftmul. Squaring has a dedicated path (~2× faster). Data in: two BigUint references. Data out: owned BigUint product.

bn-fftmul — NTT-based multiplication (Phase 6). Constructs an NttPlan (prime set, primitive roots, transform length). Forward-transforms both operands into frequency domain over each NTT prime, pointwise-multiplies, inverse-transforms, then CRT-recombines to recover the exact integer product. No floating-point at any step (I8). Used only above the NTT threshold; the plan is reusable for equal-length operands. Data in: two BigUint references + NttPlan. Data out: exact BigUint product.

bn-div — Division algorithms. divrem_knuth(a, b) -> DivRem normalizes the divisor (shift so top bit set), estimates quotient digits from top two numerator limbs, corrects by multiply-subtract, applies add-back on over-estimate (I5). divrem_newton(a, b) -> DivRem computes floor(base^k / b) by Newton iteration using bn-mul, then derives the quotient by a single large multiply plus a small correction (I6). Selects Knuth for small operands; Newton for large. Single-limb divmod is a separate fast path. Data in: two BigUint. Data out: DivRem { quotient, remainder }.

bn-mod — Modular reduction contexts. Barrett { modulus, mu } precomputes mu = floor(base^{2k} / m) once; barrett_reduce(x, ctx) uses two multiplications and two subtractions (I7). Montgomery { modulus, n_prime, r2 } transforms operands into Montgomery form; redc(t, ctx) performs a carry-free reduction (I7). modpow(base, exp, modulus) uses sliding-window exponentiation over Montgomery form; the constant-time path (P9) uses a fixed window and avoids secret-dependent branches. Data in: BigUint operands + context. Data out: reduced BigUint in [0, m).

bn-gcd — GCD and extended GCD. Binary (Stein) GCD: replace subtractions with shifts using trailing_zeros (Phase 3 dependency). Lehmer GCD: extract the top 2×LIMB_BITS bits, run single-precision Euclidean steps in i64, apply resulting 2×2 matrix to the full limb vectors — reduces limb-level work from O(n) to O(1) per Euclidean step. Extended GCD returns Bezout coefficients as BigInt. Modular inverse via extended GCD; Fermat inverse (base^{m-2} mod m) as an alternative for prime moduli. Data in/out: BigUint pairs; extended GCD returns signed BigInt coefficients.

bn-int — Signed arithmetic. BigInt { sign: Sign, mag: BigUint } delegates all magnitude work to bn-uint and bn-add/bn-mul/bn-div. Sign rules: add/sub dispatch on sign comparison; negation flips sign; multiply/divide signs multiply. Two's-complement bitwise ops (AND, OR, XOR, NOT) operate on conceptually sign-extended infinite representations; implemented via case analysis on sign pairs. Enforces I2 (NoSign iff magnitude is zero). Data flow: wraps BigUint; used by bn-rational and bn-cli.

bn-convert — Base conversion and string I/O. Small-number path: repeated divrem by base^chunk accumulating digits (O(n²) acceptable below threshold). Large-number path: divide-and-conquer — split by base^{2^k}, recurse, concatenate with zero-padding (O(M(n) log n)). Parse validates input characters, errors on invalid via ParseError (I9). Format pads to full digit width within each chunk. Supports Base10, Base16, BaseN(u32). Data in: BigUint + Base. Data out: String or BigUint.

bn-rational — Exact rationals. BigRational { sign: Sign, num: BigUint, den: BigUint } maintains gcd(num, den) = 1, den > 0, sign on numerator (I10). Construction always reduces via bn-gcd. Arithmetic: a/b + c/d = (a*d + b*c) / (b*d) followed by reduction; multiply/divide similarly. Comparison by cross-multiply. Canonical sign: numerator carries the sign, denominator is always positive. Conversion to decimal string via divmod with configurable precision. Data in/out: pairs of BigInt or BigUint; used by bn-cli.

bn-cli — The end-to-end exerciser. Four subcommands: calc (REPL-style expression evaluator over BigInt/BigRational), bench (prints per-size timing for mul/div/modpow, used to tune thresholds), convert (base conversion with arbitrary radix), factorial (large-factorial via divide-and-conquer tree). No library logic lives here; all dispatch is through the public API surface. Acts as the integration test harness and the primary demonstration artifact.

8. Domain Model

8.1 Core Value Taxonomy

Entity Canonical Form Invariant Zero Representation
BigUint Vec<Limb>, little-endian, no trailing zeros I1 empty Vec or vec![0] normalized away
BigInt (Sign, BigUint) I2: NoSign iff mag.is_zero() (NoSign, BigUint{limbs:[]})
BigRational (Sign, num: BigUint, den: BigUint) I10: gcd=1, den>0, sign on num (NoSign, 0, 1)
Limb u64 scalar never aliased with carry state 0u64
DoubleLimb u128 transient never stored, only in register/stack —

8.2 Limb Buffer Layout

 index:  0          1          2      ...  n-1
 value: least-significant limb  ...  most-significant limb
 bits:  [63:0]    [127:64]  [191:128]  ... [64n-1 : 64(n-1)]
  • Storage: Vec<u64> heap-allocated; capacity managed by Rust allocator.
  • Normalization: strip trailing (highest-index) limbs that are zero; zero value → limbs.len() == 0.
  • Bit length: (limbs.len() * 64) - limbs.last().leading_zeros() (edge: 0 → bit_len = 0).
  • Endianness boundary: only the in-memory Vec is little-endian; Display/parse produce big-endian strings (I9).

8.3 Arithmetic State Machines

8.3.1 Addition State (carry propagation)

State: { result_limbs: Vec<Limb>, carry: u64 }
Transition per limb pair (a_i, b_i):
  sum = (a_i as u128) + (b_i as u128) + (carry as u128)
  result_limbs.push(sum as u64)
  carry = (sum >> 64) as u64
Post: if carry != 0 → append carry limb; normalize (I1)

State table:

carry_in a_i b_i carry_out result_limb
0 0 0 0 0
0 MAX MAX 1 MAX-1
1 MAX 0 1 0
1 MAX MAX 1 MAX
  • Length after add: at most max(len_a, len_b) + 1.
  • I3: carry_out captured in u128; never dropped.

8.3.2 Subtraction State (borrow propagation, requires a >= b)

State: { result_limbs: Vec<Limb>, borrow: i64 }
Transition per limb pair (a_i, b_i):
  diff = (a_i as i128) - (b_i as i128) - (borrow as i128)
  result_limbs.push(diff as u64)
  borrow = if diff < 0 { 1 } else { 0 }
Post: borrow must be 0 (a >= b precondition); normalize (I1)
  • Panic/error if borrow != 0 at end (unsigned underflow — caller must ensure a >= b).
  • BigInt layer: dispatches to magnitude add or sub based on Sign comparison (P7).

8.3.3 Multiplication Dispatch State Machine

           limb_count(a) + limb_count(b)
                  |
         ┌────────▼────────┐
         │ <= SCHOOL_THRESH │──── Schoolbook
         └────────┬────────┘
                  │
         ┌────────▼────────┐
         │ <= KARA_THRESH   │──── Karatsuba
         └────────┬────────┘
                  │
         ┌────────▼────────┐

MulAlgo enum encodes the path; thresholds are tunable constants (Phase 14 benchmarks confirm them).

MulAlgo Threshold (limbs, approx) Asymptotic Invariant

Karatsuba 33–256 O(n^1.585) == Schoolbook result (I4)
Toom3 257–2048 O(n^1.465) == Schoolbook result (I4)
Ntt > 2048 O(n log n) integer-exact via CRT (I5, I8)

8.3.4 Division State Machine (Knuth Algorithm D)

Precondition: b != 0
Normalize: shift = b.leading_zeros_in_top_limb(); a' = a << shift; b' = b << shift
Loop over quotient digits j from high to low:
  q̂ = (a'[j+n]*BASE + a'[j+n-1]) / b'[n-1]   -- two-limb estimate
  Correct q̂ down (at most 2 corrections per step)
  Multiply-subtract: a' -= q̂ * b'  (shifted)
  If underflow: add-back b', q̂ -= 1
Unnormalize remainder: r = a' >> shift
Post: DivRem { quotient, remainder } satisfying I5

Error path: b == 0 → DivByZero error (typed, never UB per P3, I5).

8.3.5 Newton-Reciprocal Division State

Input: divisor d (n limbs)
Goal: reciprocal r ≈ floor(BASE^(2n) / d)
Iteration (quadratic convergence):
  r_{k+1} = 2*r_k - r_k^2 * d >> (2n * LIMB_BITS)
Termination: |error| < 1 (proven in O(log n) steps)
Quotient: q = (a * r) >> (n * LIMB_BITS), then small correction (+/- 1)
Invariant I6: result equals Algorithm D result
  • Reuses bn-mul for multiplication within the Newton loop (P4).
  • Amortized cost when dividing many values by the same divisor: compute r once, reuse.

8.4 Montgomery / Barrett Modular Arithmetic Model

8.4.1 Barrett Reduction

Context Barrett { modulus: m, mu: BigUint, k: usize }
  mu = floor(BASE^(2k) / m)   precomputed once
Reduce(x):
  q̂ = (x * mu) >> (2k * LIMB_BITS)
  r  = x - q̂ * m
  while r >= m: r -= m         -- at most 2 corrections
  Invariant I7: result in [0, m)

8.4.2 Montgomery REDC

Context Montgomery { modulus: m, n_prime: Limb, r2: BigUint }
  R = BASE^n where n = limb count of m
  n' = (-m^{-1}) mod BASE          -- precomputed once
  r2 = R^2 mod m                   -- precomputed once

MontMul(ā, b̄):           -- ā = a*R mod m, b̄ = b*R mod m
  t = ā * b̄              -- full product
  u = (t mod R) * n' mod R
  result = (t + u*m) / R
  if result >= m: result -= m
  Invariant I7: result = a*b*R^{-1} mod m

Transform in:   ā = a * r2 mod m   (one MontMul with r2)
Transform out:  a = REDC(ā, 1)
Roundtrip:      out(in(x)) == x mod m   (I7)

8.4.3 Modular Exponentiation (windowed)

Window w (default 4 bits):
  Precompute table: g^1, g^3, g^5, ..., g^(2^w - 1) in Montgomery form
  Scan exponent from MSB in w-bit windows
  For each window:
    square w times
    multiply by precomputed table entry if window != 0
Constant-time option (P9): use constant-time table lookup (no branch on secret bits)

8.5 GCD State Machines

8.5.1 Binary (Stein) GCD

Inputs: a, b (BigUint)
State: { a, b, shift }
  1. shift = min(trailing_zeros(a), trailing_zeros(b)); a >>= shift; b >>= shift
  2. while b != 0:
       if a < b: swap(a, b)
       a -= b
       a >>= trailing_zeros(a)
  3. result = a << shift
  • Each iteration: at least one operand halved → O(n²) bit operations total.

8.5.2 Lehmer GCD (for large operands)

Extract top ~64 bits of a, b as â, b̂
Run Euclidean steps on scalars â, b̂; accumulate 2x2 matrix M
Apply M to full-precision (a, b): (a', b') = M * (a, b)  -- one multi-precision step
Recurse until b small enough for binary GCD
  • O(n log²n log log n) for n-limb inputs.

8.5.3 Extended GCD

Bezout coefficients: gcd(a,b) = s*a + t*b
State: (old_r, r, old_s, s, old_t, t)
  while r != 0:
    q = old_r / r
    (old_r, r) = (r, old_r - q*r)
    (old_s, s) = (s, old_s - q*s)
    (old_t, t) = (t, old_t - q*t)
Output: gcd = old_r; coeff_a = old_s; coeff_b = old_t
Use: modular inverse of a mod m = s mod m (when gcd == 1)

8.6 NTT Model

NttPlan { primes: [p0, p1, p2, ...], roots: [ω0, ω1, ...], len: usize }
  Each p_i is a prime where p_i ≡ 1 (mod len) so that a primitive len-th root of unity exists.
  Primes chosen: product of all p_i > max possible product coefficient (guarantees no wrap).

Forward NTT over p_i:
  bit-reverse permutation → butterfly stages (Cooley-Tukey)
  each butterfly: (a, b) → (a + ω^k * b, a - ω^k * b) mod p_i

Pointwise multiply: for each frequency bin j: C_j = A_j * B_j mod p_i

Inverse NTT, then CRT recombination:
  For each output index j: recover c_j via CRT from (c_j mod p0, c_j mod p1, ...)
  c_j is the exact integer coefficient.
Invariant I8: no floating-point; all arithmetic in Z_{p_i}.

8.7 Base Conversion Model

8.7.1 Schoolbook (small numbers)

To base B from BigUint x:
  digits = []
  while x != 0:
    (x, r) = divrem(x, B)
    digits.push(r)
  reverse(digits)
Cost: O(n * d) where d = output digit count, n = limb count per divmod.

8.7.2 Divide-and-Conquer (large numbers)

Power = B^(2^k) where 2^k >= ceil(n/2)  (precomputed powers table)
Split: x = x_hi * Power + x_lo
  x_hi = x / Power;  x_lo = x mod Power
Recurse on x_hi and x_lo independently
Concatenate digit strings with zero-padding for x_hi part
Cost: O(M(n) * log n) where M(n) = multiply cost
Threshold: switch from schoolbook when output > ~1000 digits

8.8 Sign-Magnitude Arithmetic (BigInt Layer)

Operation Sign rule
(+a) + (+b) +add_mag(a,b)
(+a) + (-b) sign(a-b) * sub_mag(max,min)
(-a) + (-b) -add_mag(a,b)
(+a) * (+b) +mul_mag(a,b)
(+a) * (-b) -mul_mag(a,b)
(-a) * (-b) +mul_mag(a,b)
(+a) / (-b) result sign from I5 convention; doc'd
any * 0 NoSign
  • Two's-complement bitwise: AND/OR/XOR/NOT on BigInt extend sign bit conceptually to infinity before applying limb-wise operations; internally handled by sign-aware dispatch without allocating infinite buffers.
  • NOT(x) = -(x+1) for BigInt (Python semantics).

8.9 BigRational Model

Canonical invariants (I10):
  gcd(num, den) == 1
  den > 0
  sign carried on num; den always Plus
  zero → (NoSign, 0, 1)

Construction: reduce(n, d):
  g = gcd(|n|, |d|)
  num = |n| / g
  den = |d| / g
  sign = sign(n) * sign(d)

Arithmetic:
  a/b + c/d = (a*d + c*b) / (b*d) → reduce
  a/b * c/d = (a*c) / (b*d)       → reduce
  a/b / c/d = (a*d) / (b*c)       → reduce (c != 0)

Comparison:
  a/b < c/d  iff  a*d < c*b  (cross-multiply, compare with sign)

8.10 Worked Examples

8.10.1 Addition: a = 2^64 - 1, b = 1

a.limbs = [0xFFFFFFFF_FFFFFFFF]  (1 limb)
b.limbs = [0x0000000000000001]   (1 limb)
i=0: sum = (0xFFFF...FFFF as u128) + 1 = 0x1_0000_0000_0000_0000
  result_limb[0] = 0x0000000000000000; carry = 1
post-loop: carry=1 → append limb 1
result.limbs = [0, 1]  == 2^64  ✓

8.10.2 Schoolbook Multiply: a = [3], b = [5]

acc: u128 = 0
i=0, j=0: prod = 3 * 5 + acc[0] = 15; result[0] = 15; carry = 0
result.limbs = [15]; normalize → [15] ✓  (== 15 in base 2^64)

8.10.3 Failure Path: Division by Zero

Input: divrem(BigUint::from(42), BigUint::zero())
Path: bn-div entry check: b.is_zero() == true → return Err(DivByZero)
No UB; no panic; typed error (I5).

8.10.4 Malformed Parse Input

parse("12XF9", Base10)
  At char 'X': not in '0'..'9' → return Err(ParseError::InvalidDigit { pos: 2, ch: 'X' })
parse("", Base10) → Err(ParseError::EmptyString)
parse("-0", Base10) → normalize to (NoSign, 0) after parse (I2)

8.10.5 Montgomery Roundtrip Edge Case: a = 0

in(0): ā = 0 * r2 mod m = 0
REDC(0, 1): t = 0*1 = 0; u = 0; result = 0 / R = 0; 0 < m → 0
out(0) = 0 mod m = 0 ✓   (I7 holds for zero)

8.10.6 Normalization Edge Case: BigUint after subtraction

a = [5, 3]  (== 3*2^64 + 5)
b = [5, 3]
sub(a, b):
  i=0: diff = 5-5-0 = 0; borrow=0
  i=1: diff = 3-3-0 = 0; borrow=0
result.limbs = [0, 0] → normalize → [] (I1)
sign → NoSign (I2)
