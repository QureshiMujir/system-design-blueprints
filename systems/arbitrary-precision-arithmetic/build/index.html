⬜ Phase 1 — core types + magnitude representation

Objectives
  • Define the entire shared vocabulary in bn-core: Limb, DoubleLimb, SignedDoubleLimb, Sign, ParseError, DivByZero.
  • Define BigUint in bn-uint as { limbs: Vec<Limb> } little-endian, canonical (no trailing zero limbs).
  • Implement normalization, comparison, and From/TryFrom conversions for primitive widths up to u128.
  • Establish Limbs<'a> / LimbsMut<'a> borrowed-slice views for in-place kernel use.
  • Constraint: no arithmetic beyond comparison and scalar conversion in this phase; all higher operations depend on this baseline.
Deliverable
  • bn-core crate compiles; all types exported.
  • bn-uint crate compiles; BigUint::zero(), From<u64/u128>, Ord, normalize, bit_len, to_u64, to_u128 all functional.
  • Unit tests and property tests pass (see 1.4).

Pitfalls
  • Trailing-zero normalization omitted after mutation: a caller extends limbs via push, forgets normalize; equality and hash diverge from value. Detection: run is_normalized on every BigUint returned from public API in debug mode.
  • bit_len off-by-one for exact powers of two: u64::BITS - leading_zeros() = 64 when limb = 0, but the top limb should never be zero after normalization; if normalization is skipped, bit_len overcounts by 64. Root cause: accepting an un-normalized BigUint. Recovery: assert normalization.
  • from(0u64) producing limbs = [0] instead of []: violates I1 and I2; affects comparison and zero-test. Fix: normalize in every From impl.
  • Endianness confusion: mistaking big-endian for little-endian when indexing limbs. Manifestation: comparisons and multi-limb arithmetic produce wrong answers. Use index 0 = least-significant throughout; document in every array access.
  • to_u64 returning None for canonical representations of small values: if a two-limb BigUint has limbs [x, 0], normalize should collapse it to one limb; failing to do so causes to_u64 to return None for a small value.

⬜ Phase 2 — addition + subtraction

Objectives
  • Implement all carry/borrow arithmetic in bn-add: limb-wise addition with carry via u128, in-place add_assign, subtraction with borrow (requires a >= b for BigUint), and the add_mul_1 primitive (a += b * limb).
  • Invariant I3 (carry conservation): no carry or borrow may be dropped; result length grows by at most 1 on addition.
  • Subtraction contract: only valid when self >= rhs; caller must check before calling; returns exact magnitude.
  • add_mul_1 is the inner loop of schoolbook multiplication; it must be allocation-minimal.
Deliverable

  • BigUint supports +, -, +=, -= operators.
  • add_mul_1 usable by Phase 4 schoolbook multiply.
  • Carry/borrow never lost for inputs up to 10 000-limb operands (stress test passes).

Pitfalls
  • Carry dropped at boundary: when b is longer than a, iteration stops before propagating carry from b's high limbs. Root cause: loop terminates at min(len_a, len_b). Fix: continue iterating b's remaining limbs adding carry.
  • add_mul_1 accumulator overflow: a[i] + b[i]*c + carry can reach u64::MAX * u64::MAX + u64::MAX + u64::MAX ≈ 2^128 - 1; a u128 accumulator is tight but sufficient — only correct if no extra addition is added.
  • sub_assign produces non-normalized result: subtraction may leave zero high limbs; normalize must be called after. Symptom: subsequent length-based comparisons are wrong.
  • Borrow sign extension: if diff is computed as u64 with wrapping subtraction, borrow extraction differs from i128 path; mixing the two produces incorrect borrow. Lock on the i128 path throughout.
  • Length not reserved before add_mul_1: the output slice must be pre-sized; if a.len() < b.len(), index-out-of-bounds in release (UB if using get_unchecked). Caller contract must be documented and enforced.

Pitfalls
  • shl by multiple of 64: bit_shift = 0; the bit-shift loop must be skipped entirely; if it runs with 64 - 0 = 64, Rust panics on u64::overflowing_shr(64) (shift amount equals word size). Fix: guard the inner loop with if bit_shift > 0.

  • set_bit on index beyond current length without extending: panics via index-out-of-bounds in debug; UB with get_unchecked in release. Fix: limbs.resize(limb_idx + 1, 0) before ORing.
  • trailing_zeros returning 0 for zero-valued BigUint: should return None; returning Some(0) causes binary GCD to spin on a zero input. Root cause: loop exits early on limbs.is_empty().
  • Off-by-one in shl carry: carry = limb >> (64 - bit_shift) when bit_shift == 0 must be 0, not garbage. The guard if bit_shift > 0 prevents the shift by 64.
  • High-to-low vs low-to-high iteration order: shl must propagate carry from low to high; iterating high-to-low drops carry. shr must propagate from high to low.

⬜ Phase 7 — Division: Knuth Algorithm D

Objectives
  • Implement multi-precision division in bn-div producing DivRem { quotient: BigUint, remainder: BigUint } satisfying I5: a == q*b + r, 0 <= r < b, b != 0 (typed error on zero); primary algorithm is Knuth Vol 2 Algorithm D — normalize divisor/dividend by left-shifting until the divisor's MSB is set, then estimate one quotient digit per step from the top two limbs of the working dividend.
  • Single-limb fast path: O(n) pass with u128 carry, no normalization overhead, used whenever b.limbs.len() == 1; two-limb divisor shortcut routes the common 128-bit-modulus crypto case to a specialized path.
  • Public surface: div_rem, div_rem_1, divides, and derived div / rem / mod_floor / div_floor.
  • Constraint: no dependency on bn-mul in this phase; Phase 8 adds the Newton path that uses multiplication.
Deliverable
  • bn-div compiles; div_rem, div_rem_1, div_rem_2, divides, div_floor, mod_floor exported; CLI bn-cli calc handles / and % for arbitrary operands including multi-limb.
  • cargo test -p bn-div passes all unit + property tests; fixture suite in bn-div/tests/conformance.rs loads all 8 JSON fixture files and passes.
  • Benchmark binary bn-div/benches/knuth.rs runs without error, producing Criterion timing data at 64/256/1024/4096-bit sizes.
  • DivRem fields satisfy a = q*b + r verified in every test via an inline assertion helper; assert_canonical passes for both quotient and remainder on all fixture inputs.

Pitfalls
  • Missing second correction: q̂ can be off by 2, not just 1; a single conditional decrement is wrong. Root cause: ignoring Knuth's two-test loop rule. Detect: fixtures/divrem_addback.json with known double-decrement case; add assert decrements <= 2.
  • Off-by-one in normalization shift: computed from wrong limb (e.g., second-highest instead of highest), producing a dividend shifted by the wrong amount. Symptom: quotient wrong in MSB digit. Debug: assert d_norm.last() >= (1<<63) immediately after normalization.
  • Remainder not denormalized: returning the shifted remainder without applying the inverse shift yields a remainder scaled by 2^shift. Caught immediately by a == q*b + r check; root cause is forgetting the final right-shift.
  • Trailing zero limbs in quotient: not stripping zeros after quotient assembly corrupts BigUint canonical form (I1). All downstream operations assume canonical form; hashing and equality silently break. Fix: call normalize_limbs (strip trailing zeros) before constructing quotient BigUint.
  • u128 overflow in q̂ computation: if the two-limb estimate is formed in u64 arithmetic before widening, it silently truncates. Always use DoubleLimb (u128) for the intermediate numerator u[j+n]*BASE + u[j+n-1].
  • Single-limb path skipped for b == 0: must check before branching to fast path; div_rem_1(a, 0) must return Err(DivByZero).
  • Quotient buffer sized incorrectly: should be exactly a.limbs.len() - b.limbs.len() + 1; over-sizing produces extra zero limbs; under-sizing is a bounds error. Pre-compute and assert.

⬜ Phase 8 — Newton-Reciprocal Division + Fast Divrem

Objectives
  • Implement Newton-iteration reciprocal in bn-div/src/newton.rs: given normalized d of n limbs, compute recip = floor(B^(2n)/d) to full n-limb precision via doubling iteration, replacing the O(n^2) inner multiply-subtract loop of Algorithm D with O(M(n)) reciprocal-multiply (M(n) = Phase 5/6 multiplication cost).
  • Barrett-style precomputation DivRecip { divisor, recip } is computed once per divisor and reused for repeated divisions — key for modular arithmetic (Phase 10); enforce I5 (DivRem contract) and I6 (Newton == Knuth D for all valid inputs).
  • Threshold dispatch: sizes ≤ NEWTON_THRESHOLD limbs use Algorithm D; larger use Newton.
Deliverable

  • Correction loop exceeds 2 iterations: indicates multiplication (bn-mul) or the reciprocal iteration has a bug. Symptom: q_approx is off by more than 2 from the true quotient. Action: debug_assert!(corrections < 3); log a_limbs, d_limbs, recip_limbs, q_approx, r_initial to stderr and panic.
