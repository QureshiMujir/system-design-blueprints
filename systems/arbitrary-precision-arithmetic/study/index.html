Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why must the multiply path switch algorithms with operand size (§4.2, MM2), and how do you derive the Karatsuba-beats-schoolbook crossover (Capacity Model)?
  2. NTT uses three primes + CRT (Phase 6, ADR-11). What silently breaks if their product is below the max coefficient (I8), and how does §4 bound operand size to prevent it?
  3. Why is Newton-reciprocal division (Phase 8) asymptotically better than Knuth D (Phase 7) yet slower below 64 limbs (§4.2, MM4)?
  4. Quantify the cost blow-up if the Montgomery context were rebuilt per REDC inside modpow (Capacity Model, P6, Phase 11).
  5. Why does unsigned subtraction return Err(Underflow) rather than wrap (§4.4, MM6), and how does the signed layer (Phase 9) build on that?
  6. What exactly makes the ct-modpow path constant-time (P9, ADR-13, MM7), and which two leak channels does the default variable-time path expose?
  7. Why is #![forbid(unsafe_code)] compatible with GMP-class performance on the dominant paths (ADR-26, MM8, P4)?
  8. At what operand size do the 8 MB single-operand ceiling and the 6×-transform-length NTT scratch bound collide (§4, Capacity Model)?
  9. Why are limbs little-endian (ADR-06), and how does that interact with add/sub scan direction and Vec resize cost (MM1, Phase 2)?
  10. Why is differential testing against num-bigint and Python int (ADR-16, §4 gate) the right oracle, and what bug class would a hand-written unit test miss?
  11. Derive the limb count and modmul count for RSA-4096 exponentiation (Capacity Model) and show why it fits the 50 ms budget (§4).
  12. Why does the library forbid serde in core crates (ADR-07) yet expose Display/from_str in bn-convert (Phase 12) — what compile-graph property is protected?
  13. Why does Toom-Cook-3's setup cost push its crossover above Karatsuba's (Phase 5, §4.2, Capacity Model)?
  14. Why must NTT be integer-exact rather than a floating FFT (I8, MM3), and what does choosing primes ≡ 1 (mod 2ᵏ) buy you (ADR-11)?
  15. Why are all contexts Send + Sync by value-copy with no interior mutability (§4, ADR-14), and what concurrency hazard does that eliminate?
  16. Why is schoolbook-oracle agreement for ≤ 512 limbs (§4, I4) the load-bearing invariant of the entire multiply ladder (Phases 4–6)?
  17. Where does precision/cancellation risk appear in a pure integer library (contrast #401 soft-float, §2.5), and why does its absence simplify NTT correctness vs a float FFT?
  18. Why is the limb width u64 with u128 carry (ADR-05, MM1) rather than u32, and how does that halve loop iteration counts (Capacity Model)?
  19. What is the un-defer trigger for parallel (Rayon) multiply (Deferred Register, §4 scaling model), and why is it deferred rather than core?
  20. Why does constant-time modpow ship behind a feature flag rather than as the default (ADR-13, P9), and what does the non-crypto consumer save?

Mental Models & First Principles

  • MM1 — A bignum is a positional number in base 2⁶⁴; a limb is one digit. Add/sub/mul are grade-school algorithms whose load-bearing detail is carry capture in u128. Predicts: correctness ≡ never dropping the high half of a limb×limb product. Bug without it: truncating the carry word → silently wrong high digits. Applied: §8, I3, Phase 2/4.
  • MM2 — Multiplication cost is superlinear, so the algorithm must change with size. Schoolbook O(n²) → Karatsuba O(n¹·⁵⁸⁵) → Toom-3 O(n¹·⁴⁶) → NTT O(n log n). Predicts: any single fixed algorithm is wrong somewhere on the size axis. Bug without it: schoolbook for 100K-limb operands → quadratic blow-up. Applied: §4.2 thresholds, Phases 4–6, ADR-10.
  • MM3 — NTT is the FFT done in a finite field, so the transform is exact. Convolution becomes pointwise multiply in the transform domain; CRT recombines three prime channels. Predicts: the prime product must exceed the max coefficient or digits wrap silently. Bug without it: prime product too small → wrong result with no error. Applied: I8, Phase 6, ADR-11.
  • MM4 — Division is multiplication's expensive inverse; Newton converts it back into multiplications. A reciprocal iteration doubles its correct digits each step. Predicts: above a threshold, divide via reciprocal, not subtract-and-shift. Bug without it: O(n²) Knuth D on huge quotients. Applied: Phases 7–8, §4.2, MM2.
  • MM5 — Modular reduction is crypto's hot loop: precompute once, reduce many times. Barrett μ or Montgomery (n′, r²) is built per modulus and reused. Predicts: recomputing per operation dominates modpow cost. Bug without it: rebuilding the Montgomery context inside the exponentiation loop. Applied: P6, ADR-12, Phases 10–11.
  • MM6 — Sign and magnitude are separable. Do all hard arithmetic on unsigned magnitudes; layer sign rules on top. Predicts: unsigned subtraction where a < b must be detected, not wrapped. Bug without it: silent wraparound on underflow. Applied: §4.4, Phase 9.
  • MM7 — Constant-time is a property of control flow and memory access, not of the math. A data-dependent branch or table index leaks the secret. Predicts: variable-time modpow is faster but unsafe for keys. Bug without it: secret-dependent window lookup leaks exponent bits. Applied: P9, ADR-13, Phase 11.
  • MM8 — #![forbid(unsafe_code)] + u128 lets the optimizer emit carry instructions without hand-written unsafe. Predicts: GMP-class speed is reachable on the dominant paths without unsafe. Bug without it: introducing UB in a hand-rolled limb kernel for marginal gain. Applied: ADR-26, P1/P4.

Glossary

45 terms. Alphabetical. Each entry: term, precise implementation-relevant definition, cross-references to crate/module, phase, invariant, or principle. Prefer a definition list for line-density.

Add-back Correction in Knuth Algorithm D (Phase 7, bn-div/src/knuth_d.rs): after multiply-subtract, if the subtraction underflows, add the divisor back once and decrement the quotient digit by one.

  • Frequency: ≤ 2/b per digit step; rare but mandatory to handle.
  • Omitting it produces an incorrect quotient with no other error signal.

Arbitrary precision Integer magnitude bounded only by heap memory; BigUint limb count (Vec<Limb>) grows on demand.

  • Contrast: fixed-width u64/u128; BigUint has no ceiling on representable value.

Asymptotic threshold Limb count at which a faster-asymptotic algorithm crosses below the simpler one in wall-clock cost.

  • KARATSUBA_THRESHOLD, TOOM3_THRESHOLD in bn-mul/src/thresholds.rs; tuned by benches/mul_bench.rs (Phase 5, P4).
  • NTT threshold in bn-fftmul/src/lib.rs; tuned by benches/mul_bench.rs for the NTT crossover (Phase 6).

Barrett reduction Precomputed modular reduction: mu = floor(R^(2k) / m) computed once per modulus.

  • Reduction: a mod m ≈ a - m * floor(a * mu / R^(2k)); at most two correction subtractions.
  • No trial division; suitable for repeated mod with the same modulus (bn-mod/src/barrett.rs, Phase 10, I7).
  • Reference: Barrett 1986 (CRYPTO '86).

Bezout coefficients Integers u, v satisfying a*u + b*v = gcd(a,b).

  • Produced by extended GCD (bn-gcd/src/ext_gcd.rs); u and v may be negative → typed as BigInt.
  • Direct use: mod_inv when modulus is composite (Phase 11).

Bignum Variable-length integer representation; here: BigUint (unsigned magnitude) or BigInt (sign + magnitude).

  • Lineage: GMP mpz_t, Java BigInteger, Python int; this library re-implements from scratch in Rust.

Binary GCD (Stein's algorithm) GCD computation using shifts and subtractions instead of multi-precision division.

  • Step: factor out common powers of 2; alternate halving the even operand and subtracting (bn-gcd/src/binary.rs, Phase 11).
  • Complexity: O(n^2) bit operations; simpler but slower than Lehmer for large inputs.

Borrow Signed underflow in limb-wise subtraction; captured in SignedDoubleLimb = i128; propagated to the next limb.

  • sub in bn-add requires a >= b as a stated precondition; borrow never dropped (I3).

Canonical form Uniqueness invariant: equal values have bit-identical representations.

  • BigUint: no trailing zero limbs; zero is the empty or single-zero limb vector (I1).
  • BigInt: Sign == NoSign iff magnitude is zero (I2); never Plus or Minus for zero.
  • BigRational: gcd(num, den) == 1; den > 0; sign carried on the Sign field (I10).
  • Consequence: equality and hashing are O(n) limb comparisons, not algebraic normalization.

Carry Unsigned overflow on limb addition or multiply-accumulate; high 64 bits of a u128 intermediate.

  • Propagated to the next limb index in the loop; never dropped (I3).
  • Result length increases by at most one limb on add (Phase 2).

Chinese Remainder Theorem (CRT) Reconstruction from residues in bn-fftmul/src/crt.rs (Phase 6).

  • NTT multiplies modulo several independent primes; CRT recovers the unique integer in [0, prod(primes)).
  • Enables integer-exact large multiplication without floating-point (P5, I8).

Constant-time Execution time and branch pattern independent of secret data values.

  • Required for modular exponentiation path used in cryptographic contexts (P9).
  • Implementation: non-branching conditional selection; fixed-size window scan; table-based power lookup in bn-mod/src/modpow.rs.
  • Timing independence verified by test comparing constant-time vs. variable-time output; absence of secret-dependent branches checked by inspection.

Cooley-Tukey butterfly NTT algorithm in bn-fftmul/src/ntt.rs (Phase 6): recursively splits length-n transform into two length-n/2 sub-transforms; combines with twiddle factors (powers of the root of unity).

  • Preceded by bit-reversal permutation; O(n log n) multiplications in Z_p.

Differential testing Primary correctness strategy (P1, P10, Phase 14): compare two algorithm implementations over random operands across all size classes; slow-but-correct variant is the oracle.

  • Karatsuba, Toom-Cook, NTT each compared against schoolbook (I4).
  • Newton-reciprocal compared against Knuth D (I6).
  • Full library compared against num-bigint crate and Python int in Phase 14 conformance.

Divide-and-conquer base conversion Algorithm in bn-convert/src/dc_conv.rs (Phase 12): split at cached power B = base^(2^k), recurse on x div B and x mod B, combine as high * B + low.

  • Reduces base-10 conversion from O(n^2) repeated-divmod to O(M(n) log n); I9 roundtrip required.

DoubleLimb u128; holds one full Limb * Limb + carry_in product without arithmetic overflow.

  • Strictly a computation type; never stored in a BigUint limb array.
  • Used as the accumulator in schoolbook multiply's inner loop.

Extended GCD Euclidean algorithm extended to track Bezout pair (u, v).

  • bn-gcd/src/ext_gcd.rs; outputs (gcd, u, v) as (BigUint, BigInt, BigInt).
  • Basis for mod_inv in the composite-modulus case (Phase 11).

FFT (floating-point) Classic fast Fourier transform using complex f64 arithmetic; explicitly NOT used here (P5).

  • Rounding errors accumulate and can corrupt large products; replaced entirely by NTT.

In-place operation Kernel operating on borrowed LimbsMut<'a> slices, mutating output without heap allocation.

  • Mandatory for hot paths (bn-add, bn-mul, bn-div) to avoid per-iteration allocation (P6).
  • LimbsMut<'a> defined in bn-uint/src/view.rs.

Karatsuba multiplication O(n^1.585) divide-and-conquer multiply in bn-mul/src/karatsuba.rs (Phase 5).

  • Split: x = x1*B + x0; three sub-products z0=x0*y0, z2=x1*y1, z1=(x0+x1)*(y0+y1)-z0-z2.
  • Reconstruct: z0 + z1*B + z2*B^2; base case → schoolbook below KARATSUBA_THRESHOLD; I4 verified.

Knuth Algorithm D Multi-precision normalized long division (Phase 7, bn-div/src/knuth_d.rs; TAOCP Vol 2 §4.3.1).

  • Normalize divisor (left-shift so top bit is set); estimate quotient digit from top two dividend limbs.
  • Correct by at most 2 via compare-subtract; multiply-subtract; add-back on rare over-estimate.
  • Exactly satisfies I5 (a == q*b + r, 0 <= r < b).

Lehmer GCD Accelerated GCD for large inputs in bn-gcd/src/lehmer.rs (Phase 11).

  • Approximate both operands by their top one or two limbs; run multiple Euclidean steps in 64-bit arithmetic.
  • Accumulate results into a 2×2 matrix; apply once to full-precision values.
  • More efficient than binary GCD above ~4 limbs; reduces number of expensive multi-precision divisions.

Limb u64; the unit of magnitude storage; index 0 is the least-significant word (little-endian).

  • A BigUint is Vec<Limb>; index k stores bits [64k, 64k+64) of the magnitude.

Little-endian limb order Limb index 0 = bits 0..63 (least significant); index n-1 = most significant.

  • Matches natural carry-propagation loop direction (for i in 0..n); enables in-place growth by appending.

Magnitude Unsigned absolute value of a BigInt; stored as a BigUint.

  • Sign is a separate Sign field (P7); all limb-level arithmetic is sign-agnostic.

Modular inverse Integer x with a*x ≡ 1 (mod m), existing when gcd(a, m) == 1.

  • General case: extended GCD (bn-gcd/src/ext_gcd.rs).
  • Prime modulus: Fermat's little theorem (a^(p-2) mod p).
  • Returns None/error when gcd(a,m) != 1; result always in [1, m) (Phase 11).

Montgomery form Represent a mod m as aR mod m for R = 2^(64*k), the smallest limb-base power exceeding m.

  • Multiplication via REDC; no trial division in the inner loop.
  • Context Montgomery { modulus, n_prime, r2 } in bn-mod/src/montgomery.rs (Phase 10, I7).

MulAlgo Enum {Schoolbook, Karatsuba, Toom3, Ntt}; dispatch in bn-mul/src/lib.rs by limb-count vs. thresholds.

  • Observable via public accessor for testing; supports P4 and P10 (algorithm selection traceable).

Newton-reciprocal division Compute floor(R^k / d) by Newton-Raphson iteration from a single-word seed (bn-div/src/newton.rs, Phase 8).

  • Each iteration doubles the number of correct bits; convergence quadratic.
  • Quotient: q = (a * recip) >> shift plus a bounded correction; turns large division into multiplication; verified I6.

Normalization Strip all trailing zero limbs from a Vec<Limb> after any mutating operation (I1).

  • normalize() in bn-uint/src/normalize.rs; called by every mutating public entry point.
  • No-op on already-canonical values; idempotent (property-tested in Phase 1).

NTT (Number-Theoretic Transform) Discrete transform over Z_p for a Proth prime p = c*2^k + 1; exact integer arithmetic, no rounding.

  • Forward NTT, pointwise product, inverse NTT, CRT recombination yield the exact integer product (bn-fftmul, Phase 6, P5, I8).

NTT prime Prime p = c * 2^k + 1 ensuring existence of a primitive n-th root of unity in Z_p for n | (p-1).

  • Table in bn-fftmul/src/primes.rs; multiple primes used in parallel for CRT coverage.

NttPlan Struct {primes: &'static [u64], roots: Vec<u64>, len: usize} built by bn-fftmul/src/plan.rs.

  • Encapsulates prime selection and transform length for a given operand-size pair.
  • Immutable once constructed; shared between forward-transform and CRT-recombination passes.

Oracle The trusted reference implementation against which a faster algorithm is differentially verified.

  • Schoolbook multiplier (Phase 4) is the oracle for Karatsuba/Toom3/NTT (I4).
  • Knuth D is the oracle for Newton-reciprocal division (I6).
  • num-bigint crate and Python int are external oracles for Phase 14 conformance (P1, P10).

REDC Montgomery Reduction: given T < m*R, computes T * R^-1 mod m without expensive division.
