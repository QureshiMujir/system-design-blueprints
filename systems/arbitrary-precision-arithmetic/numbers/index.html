Back-of-Envelope Capacity Model

All inputs are taken from §4 (System Constraints / Memory Layout / Dispatch Thresholds); arithmetic is shown.

  1. Limbs for a k-bit number. limbs = ceil(k/64). RSA-4096 → 4096/64 = 64 limbs (matches §4 "64-limb (4096-bit)").
  2. BigUint heap bytes. 24 (Vec header) + 8n (§4.3). 1M limbs → 24 + 8e6 ≈ 8 MB (matches §4 memory ceiling).
  3. Schoolbook 64×64 mul. n·m = 64·64 = 4096 u128 partial products; at ~1 product/ns → ~4 µs ≈ §4 p50 ≤ 5 µs.
  4. Schoolbook scratch. ≤ 2(n+m) = 2·128 = 256 limbs × 8 = 2 KB → L1-resident (§4 cache row).
  5. Karatsuba crossover. schoolbook n² vs Karatsuba ≈ 3(n/2)^1.585; equal near n ≈ 32 limbs (matches §4.2 threshold).
  6. 1024-limb NTT. O(n log n) × 3 primes × (fwd+inv) ≈ 6 · 1024 · log₂2048 ≈ 6·1024·11 ≈ 67.6K butterflies × tens of ns → ~5 ms (matches §4 p50).
  7. NTT scratch. ≤ 6 × padded length (§4). 1024 → pad 2048 → 6·2048·8 = 98 KB → L2/L3 resident depending on size.
  8. modpow REDC count. e-bit exponent, window w=5 → ≈ e squarings + e/(w+1) muls = 4096 + 683 ≈ 4779 modmuls; each 64-limb modmul ≈ 5 µs → ≈ 24 ms < 50 ms budget (§4).
  9. Montgomery context size. ≈ 48 + 16k for k-limb modulus (§4.3). k=64 → ≈ 1.1 KB, built once, amortized over ~4779 REDCs (P6).
  10. Toom-3 vs Karatsuba. Toom-3 = 5 sub-products of n/3 limbs vs Karatsuba 3 of n/2; setup (5-point eval + interpolation) pushes crossover to 128 limbs (§4.2).
  11. Decimal length. n-limb number ≈ n · log₁₀(2⁶⁴) ≈ n · 19.27 decimal digits; D&C base-convert is O(M(n) log n) above 128 limbs (§4.2).
  12. Binary size. monomorphized on Limb=u64 only → no generic explosion → ≤ 2 MB stripped library (§4).
