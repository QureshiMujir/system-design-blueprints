3. Architectural Overview

canaryctl / declarative Rollout (spec)
        |
canary-api : CRUD + commands (promote/abort/pause/resume) + watch
        |  desired state
        v
canary-controller (canaryd)  [leader-elected, single writer]
        |
canary-reconcile : LEVEL-TRIGGERED loop  (desired vs observed -> actions)
   |             |                |               |
   v             v                v               v
canary-workload  canary-traffic   canary-analysis  canary-store
(scale stable/   (weighted shift   (metric queries  (revisions,
 canary RS,       via TrafficRouter, -> verdict)      history, events,
 readiness)       mirror/header)                       observedGeneration)
        \              |                /
         \             v               /
          canary-model (Rollout/Step/Status state machine)
                       |
                  canary-events (audit, notifications/webhooks)

canary-api: Axum HTTP server exposing Rollout CRUD, imperative command endpoints (/rollouts/{name}/promote, /abort, /pause, /resume, /undo), and a watch/SSE stream. Validates spec on write; rejects illegal strategy combinations. Writes desired state to canary-store.

canary-controller (canaryd): Binary entry point. Acquires leader lease; starts reconcile loop over all Rollouts; fans out per-Rollout reconcile tasks via Tokio; drains workqueue on shutdown. Single-writer invariant enforced here — no other process may mutate provider state.

canary-reconcile: Core reconcile function reconcile(rollout, store, providers) → ActionSet. Computes diff between desired spec + current status and observed provider state. Emits idempotent Action variants (ScaleWorkload, SetWeight, StartAnalysis, AdvanceStep, Promote, Abort). Applies actions; writes updated status. Requeueing + exponential backoff on transient errors.

canary-workload: WorkloadProvider trait: create_revision, scale, ready_count, pod_template_hash. Manages stable RS + canary RS lifecycle. Enforces maxSurge/maxUnavailable arithmetic. Readiness-gates traffic admission.

canary-traffic: TrafficRouter trait: set_weights(stable, canary), set_header_route, set_mirror, get_weights. Providers: in-memory (test), SMI-like, Gateway-API-like, configurable-ingress. Weight drift detection + correction each reconcile.

canary-analysis: MetricProvider trait: query(metric, window) → Measurement. AnalysisRun executor: schedules measurement intervals, evaluates success_condition/failure_condition CEL-like expressions, tracks failureLimit/inconclusiveLimit, emits verdict (Successful | Failed | Inconclusive | Error).

canary-store: Durable map of Rollout desired + status; revision history ring (revisionHistoryLimit GC); optimistic concurrency via resourceVersion; event log (append-only); snapshot/restore for replay.

canary-model: All domain types + transition tables. Canary phase machine, blue-green phase machine, step sequencer. Illegal transitions rejected at type level (exhaustive enum match).

canary-events: Structured event recorder (type/reason/message/timestamp); notification dispatcher (webhook POST, configurable retry); audit trail queryable by rollout/step/time.

8. Domain Model — Rollout State Machines, Steps, and Analysis

8.1 Canary Phase State Machine

From Event To Guard Side-Effects
Progressing step advance (SetWeight/Pause complete) Progressing next step exists current_step_index++, weight updated
Progressing all steps complete + analysis Successful Healthy canary_weight == 100 promote: stable_rs = canary_rs; reset canary
Progressing status.abort == true OR analysis Failed Aborted — weight → 0; canary RS → 0 replicas
Progressing spec.paused == true OR Pause step Paused — freeze step index
Paused promote command OR pause duration elapsed Progressing — unset paused; advance step
Paused abort command Aborted — weight → 0; canary RS → 0
Aborted promote/retry command Progressing operator explicit reset step index; unset abort
Healthy new template detected Progressing new pod-template-hash create new canary RS; step index = 0
Progressing progressDeadline exceeded Degraded condition no progress within deadline condition appended; no phase change

8.2 Blue-Green Phase State Machine

From Event To Guard Side-Effects
Progressing new template Progressing preview RS created preview_rs = new RS; active_rs unchanged
Progressing prePromotionAnalysis Successful Progressing analysis complete proceed to promotion
Progressing promote (auto or command) Progressing active_service selector switched active_rs = preview_rs; scaleDownTimer starts
Progressing postPromotionAnalysis Successful + scaleDownDelay elapsed Healthy — old RS scaled to 0; GC history
Progressing any analysis Failed Aborted — revert active_service selector; preview RS → 0
Aborted retry command Progressing — new preview RS; reset

From Event To Guard Side-Effects
Progressing new template Progressing — surge pods up; drain old pods honoring maxUnavailable
Progressing all pods updated + ready Healthy ready == replicas promote; GC old RS
Progressing progressDeadline exceeded Degraded cond — condition set

8.4 CanaryStep Sequencing

steps: [SetWeight(10), Pause{60s}, Analysis(ref), SetWeight(50), Pause{∞}, SetWeight(100)]
         idx=0          idx=1       idx=2           idx=3          idx=4     idx=5
  • current_step_index advances on completion of each step.
  • SetWeight(w): emit SetWeight action; complete immediately after provider confirms.
  • Pause{duration}: record pause_start_time; complete when now - pause_start > duration; duration == None → manual gate (wait for promote command).
  • Analysis(ref): spawn AnalysisRun; hold until verdict; Successful → advance; Failed/Error-at-limit → abort.
  • SetCanaryScale: set canary RS replica count independently of traffic weight.
  • Experiment: spawn ephemeral workload; complete on experiment conclusion.

8.5 AnalysisRun Verdict Semantics

Metric Result Effect Counter
success_condition true Successful measurement success_count++
failure_condition true Failed measurement failure_count++
Neither Inconclusive measurement inconclusive_count++
Provider error Error measurement failure_count++ (counts toward failureLimit)
failure_count > failureLimit AnalysisRun → Failed → abort —
inconclusive_count > inconclusiveLimit AnalysisRun → Inconclusive → hold —
All measurements done, no failure/inconclusive over limit AnalysisRun → Successful —

8.6 Traffic Weight Model

  • Weights expressed as integers 0–100 (percent).
  • stable_weight = 100 - canary_weight always.
  • Weight transitions: one SetWeight action per reconcile; provider applies atomically.
  • Verification: after apply, read back weights from provider; if drift > 1% → emit correction action + traffic_weight_drift metric.
  • Header routing: additional route rule, does not affect weight accounting.
  • Mirroring: shadow traffic, not counted in weight model.

8.7 Worked Example — 5-Step Canary with Analysis

spec.strategy.canary.steps:
  [SetWeight(20), Pause{300s}, Analysis(slo-check), SetWeight(80), SetWeight(100)]

t=0:  reconcile → create canary RS (2 pods, maxSurge=1), stable=8 → weight set 20/80
t=5m: Pause 300s elapsed → advance to Analysis step → spawn AnalysisRun
t=6m: AnalysisRun running: query error_rate{job="canary"} every 60s × 5 counts
t=11m: 5 measurements, all success_condition true → AnalysisRun Successful
t=11m: advance → SetWeight(80) → stable=2 pods, weight 80/20 (canary heavy)
t=12m: SetWeight(100) → promote: stable_rs=canary_rs; weight reset; old RS GC'd
Status: Phase::Healthy

8.8 Worked Example — Abort / Rollback

t=0:  SetWeight(20) applied
t=5m: AnalysisRun running; measurement 3: error_rate=4.2% > 1% threshold
      failure_count=1 > failureLimit=0 → AnalysisRun Failed
t=5m: reconcile reads verdict → emit Abort action
      canary_weight=0, stable_weight=100; canary RS scaled to 0
      status.abort=true; Phase::Aborted
      event: reason=AnalysisFailed, message="error_rate exceeded threshold"
t=5m: webhook notification dispatched
Stable RS unchanged; users see no degradation from t=0 onward.

8.9 Worked Example — Blue-Green Swap

t=0:  new template detected → create preview RS (10 pods)
      active_service → stable RS (10 pods); preview_service → preview RS
t=2m: prePromotionAnalysis Successful
      auto_promotion_enabled=true → emit Promote action
      active_service selector patched to preview RS pod-template-hash label
      scaleDownTimer = now + scaleDownDelay(30s)
      status.phase = Progressing (post-promotion analysis running)
t=2m: postPromotionAnalysis running (synthetic checks)
t=3m: postPromotionAnalysis Successful
t=2m+30s: scaleDownTimer elapsed → old RS scaled to 0 → GC
Status: Phase::Healthy; old RS gone.
