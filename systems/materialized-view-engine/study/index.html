Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. If ForceCheckpoint (AdminCommand, §22) is issued mid-burst (C6, §4) while every operator must drain to the barrier (I9, §18) under backpressure delay, where exactly is queue memory (I10) charged during that drain, and does credit accounting (ADR-21, §20) actually prevent the ceiling from being exceeded — walk the credit path end to end.
  2. Under P1 Determinism Over Throughput (§6) and the rule-based-only optimizer commitment (§14), what specifically breaks in PlanHash stability (I7, §11) if DF2's adaptive rewrite (§37, anchored §33) is un-deferred without a plan-hash versioning scheme — trace the effect into CheckpointManifest invalidation (§18).
  3. Watermarks never regress (I2, §7), yet the timer subsystem claims pure LogicalTime advancement (P9, §20) — reconcile this with exactly-once SourceOffset commit (I6) when a CDC source restarts and replays already-acked offsets: which layer suppresses the watermark artifact, and what telemetry (§26) proves it never regressed?
  4. Compaction may not delete state an active replay range still needs (I11, §7); if DF3 cloud tiering (§37, anchored §31) is later un-deferred, does I11 still hold verbatim once state can live in a slower remote tier, or does it require a second, tier-aware invariant — justify from §31's own ceiling analysis.
  5. ADR-04 locks RocksDB and ADR-24 locks the SSTable-bundle snapshot format (§9) — if the state backend were ever swapped, what in §27 Compatibility & Versioning and §18 Checkpointing would have to change simultaneously to avoid invalidating every checkpoint taken under the old backend?
  6. P11 Persistence Before Acknowledgment (§6) requires ack only after WAL durability — under burst ingress (C6) with fsync batching (ADR-05, §17), what is the worst-case ack-latency contribution, and where in CM10's (§34) p99 budget split is that batching window actually charged against C10/M5 (§30)?
  7. I4 (idempotent operator execution) and I6 (exactly-once source offset commit) each hold in isolation — but §19 Replay and §22 Network APIs are built in different phases; what test in §28 Testing & Verification Strategy proves the two invariants compose correctly across a CDC- source-restart boundary, rather than merely proving each alone?
  8. Cooperative budgeted polling (ADR-08, §15) and single-NUMA-node scheduling (C20, C21, §4) are both locked — what structural guarantee (not a metric) stops one misbehaving operator from starving the entire worker pool, and which invariant (§7) plus which phase (§15) actually enforces it?
  9. Schema versions advance monotonically (I8) and schema evolution must be observable (P14) — walk through what happens to Delta records already enqueued under schema version N when DDL for N+1 commits mid-ingest (§13 catalog, §20 backpressure queues): which component blocks, for how long, before C8/C9 (§4) are violated?
  10. DF6 (multi-tenant RBAC/ACL hierarchy, §37, anchored §24) is deferred, yet ADR-18 already locks mTLS+RBAC interceptor as the Phase-0 auth model (§9) — reconcile what "RBAC" means before DF6 is un-deferred, and name the specific threat surface (§24) that remains open until it is.
  11. The blueprint rejects distributed execution (§36, DF1) for vertical scaling (C33, §31) — given the WAL is a single-writer total order (I1, §17), which ceiling is hit first as active-views (C17) climbs toward 512: WAL fsync bandwidth (CM1/CM2, §34), aggregation cardinality (CM7, §34), or scheduler core count (C19, §4)? Justify the ordering.
  12. Snapshot manifests are checksum-verified (I13) and checkpoints only reference durable WAL offsets (I3) — on the failure edge BarrierAligned → RecoveryAbort → ReplayResume (§18), which invariant is re-validated, and does M8's 100 GB / <90s recovery target (C13, §30) survive re-verifying both against a 100 GB state?
  13. Runtime task cancellation never leaks state handles (I14) — under which N.8 Edge Case does a ForceCheckpoint racing a PauseView command (§22) actually exercise this invariant, and what does the ownership model (P6, §11 StateHandle) guarantee that a naive Drop impl would not?
  14. P10 Backpressure Everywhere and P12 Isolation Between Runtime and Storage can conflict: when mv-storage stalls (compaction I/O contention against C26's FD ceiling), how does credit-based backpressure (ADR-21, §20) prevent that stall from deadlocking the scheduler (§15) without breaking P12's isolation promise — name the boundary component.
  15. CM3 (§34) shows burst ingress (C6) plus compaction amplification (C28) nearly saturating NVMe write bandwidth when they overlap — what admission-control policy, and which ADR or invariant specifies it, is supposed to prevent that overlap from ever reaching the modeled worst case in production?
  16. Replay barriers serialize checkpoint transitions (I9) — if two ForceCheckpoint commands are issued back-to-back before the first reaches Durable (§18 state machine), what is the correct behavior, and which invariant or ADR prevents a second barrier from being requested mid- alignment?
  17. DF4 (GPU aggregation) and DF5 (SIMD execution) are both deferred and anchored §30 — given AVX2 is already a Phase-0 CPU floor (C19), which mv-runtime operator work is scalar-only today, and which M-series target (§30) most directly makes the un-defer trigger concrete rather than aspirational?
  18. For DF7 cross-region geo-replication (§37, anchored §36), which §4 constraint (C22 intra-RTT, C23 CDC-RTT) or §31 scalability ceiling would have to be measured and exceeded before geo- replication becomes the correct next step rather than premature complexity, per §36's own rejection rationale for AA1?
  19. Watermarks (I2) and the mv-scheduler timer wheel both claim LogicalTime-only semantics (P9, I12) — if RefreshPolicy::Interval(u64) (§21) is expressed in wall-clock units at the API layer, where does the wall-clock-to-LogicalTime translation happen, and what happens to its determinism under replay (§19)?

32. Mental Models & First Principles

Ten compressed heuristics an engineer must internalize before touching mv-runtime, mv-wal, or mv-checkpoint. Each predicts a class of bug that unit tests alone will not surface.

ID Compressed Insight Predicts Bug Class Without It Resolving §
MM1 Correctness is a replay invariant, not a runtime property — two runs fed the same WAL range must produce byte-identical output regardless of "looked right" live. Any divergence between a live run and its replay is a real defect, never noise. Patching live operator state directly to "fix" a symptom, creating primary/replay drift that only surfaces on the next crash. §19
MM2 State is a materialized fold over the WAL, not the source of truth — Arrangement = fold(WAL, checkpoint). Recovery is always "replay WAL since last durable CheckpointEpoch," never "trust in-memory state." Mutating an Arrangement without a preceding WAL append; checkpoint restores stale/rolled-back state silently. §18
MM3 A Watermark is a lower bound on future arrivals, not a clock tick — it only ever expresses "nothing older than this remains." Any operator may safely discard state below the watermark; anything that depends on wall time to fire is already wrong. Firing window aggregation on wall-clock timers instead of LogicalTime, producing nondeterministic output under replay (violates I12). §20
MM4 Backpressure is conservation of memory, not flow control — every unbounded queue is a phantom OOM with a delayed timer. A bounded system requires end-to-end credit accounting; any hop without a ceiling becomes the ceiling. Queue growth that looks fine at C5 sustained load and OOM-kills the process the first time C6 burst ingress hits. §20
MM5 A checkpoint is a single-node Chandy–Lamport cut — barrier alignment must precede persistence, or the "snapshot" is not a snapshot. Skipping barrier alignment produces a torn cut: some operators reflect post-barrier state, others pre-barrier. Recovery loads a manifest whose snapshot_files disagree on epoch boundary, surfacing as ReplayDivergence weeks later. §18
MM6 Idempotency is what makes crash-only recovery legal — an operator must be safe to re-execute the same DeltaBatch after a crash mid-apply. Retry-after-crash is a correctness requirement, not a convenience. Crash between WAL append and ack; retry double-applies a (+row), aggregation drifts by exactly 2x on affected keys. §19
MM7 Plans are data, not control flow — a PlanHash is a promise that a fixed deterministic program exists behind it forever. Any DDL that changes a running view's semantics must mint a new PlanHash, never mutate the old one in place. Hot-patching a live LogicalPlan on schema change invalidates checkpoints taken under the old hash without saying so. §13
MM8 Compaction is a temporal-permission problem, not a disk-space problem — you may only delete what no active replay range still needs. Compaction's low-water mark is min(active replay cursor), never oldest WAL segment alone. GC deletes state a slow consumer's replay still requires; that consumer's next replay hits SnapshotMismatch. §31
MM9 Observability is the debugger for a system you cannot single-step — every invariant needs a counter or it is invisible until an SLO breach. If an invariant (I1–I14) has no telemetry, its first violation report is a customer ticket, not an alert. A watermark regression corrupts a view for days before p99 freshness (C10) finally trips a dashboard threshold. §26
MM10 The WAL's single global append order is the ceiling, not the floor — one writer, one total order, one place all durability serializes through. Throughput at scale is bounded by fsync bandwidth × 1 writer long before CPU or network limits bind. Assuming WAL writes can later be sharded per-source without a merge step, then discovering replay has no total order to reconstruct. §17

Required reading (§5)

Books

  • Designing Data-Intensive Applications — Kleppmann (O'Reilly, 2017). Ch. 3, 5, 7, 9, 11: replication semantics, transactions, consistency/consensus, stream processing. Extract: the replication/consistency vocabulary this blueprint reuses for watermarking. Applied in Phase 8.
  • Database Internals — Petrov (O'Reilly, 2019). Part I (B-Tree/LSM storage engines), Part II (distributed transaction logs). Extract: WAL and LSM layout discipline. Applied in Phase 5.
  • Transaction Processing: Concepts and Techniques — Gray & Reuter (Morgan Kaufmann, 1992). Ch. 8–9: logging, ARIES recovery. Extract: redo/undo recovery correctness invariants. Applied in Phase 6.
  • Principles of Distributed Database Systems, 3rd ed. — Özsu & Valduriez (Springer, 2011). Ch. 5–6: distributed query processing and optimization. Extract: join-reordering theory later gated by the deferred cost-based optimizer. Applied in Phase 2.
  • Rust Atomics and Locks — Mara Bos (No Starch Press, 2023). Ch. 2–4, 8: memory ordering, lock-free queues, condition variables. Extract: the ingress-queue and scheduler wakeup design. Applied in Phase 3.
  • Streaming Systems — Akidau, Chernyak, Lax (O'Reilly, 2018). Ch. 2–3: watermarks, windowing, triggers. Extract: the watermark-never-regresses discipline (I2). Applied in Phase 8.
  • Compilers: Principles, Techniques, and Tools, 2nd ed. — Aho, Lam, Sethi, Ullman (Addison-Wesley, 2006). Ch. 4–5: syntax-directed translation, AST construction. Extract: deterministic, replay-stable AST canonicalization. Applied in Phase 1.
  • The Art of Multiprocessor Programming, rev. ed. — Herlihy & Shavit (Morgan Kaufmann, 2012). Ch. 10: concurrent queues. Extract: bounded-channel correctness proofs. Applied in Phase 3.

Papers

  • McSherry, Isaacs, Isard, Murray — "Differential Dataflow" (CIDR 2013). Incremental multiset-diff computation formalism. Applied in Phase 4.
  • Murray, McSherry, Isaacs, Isard, Barham, Abadi — "Naiad: A Timely Dataflow System" (SOSP 2013). Frontier-based progress tracking. Applied in Phase 3.

  • O'Neil, Cheng, Gawlick, O'Neil — "The Log-Structured Merge-Tree (LSM-Tree)" (Acta Informatica, 1996). Persistent append/compaction layout. Applied in Phase 5.
  • Thomson, Diamond, Weng, Ren, Shao, Abadi — "Calvin: Fast Distributed Transactions for Partitioned Database Systems" (SIGMOD 2012). Deterministic execution scheduling. Applied in Phase 7.
  • Kreps, Narkhede, Rao — "Kafka: A Distributed Messaging System for Log Processing" (NetDB Workshop, 2011). Log-based offset and dedup semantics. Applied in Phase 10.

Reference Implementations

  • Materialize (github.com/MaterializeInc/materialize) — study src/compute, src/storage, src/adapter. Lesson: arrangements as shared, indexed incremental state. Pitfall: do not copy its full SQL surface before single-node incremental correctness is solid. Applied in Phase 4.
  • RisingWave (github.com/risingwavelabs/risingwave) — study src/stream, src/storage/hummock. Lesson: barrier-based checkpoint alignment across the dataflow graph. Pitfall: do not copy its distributed shared-storage design before the single-node WAL is solid. Applied in Phase 6.
  • Timely Dataflow (github.com/TimelyDataflow/timely-dataflow) — study timely/src/progress, timely/src/dataflow/operators. Lesson: frontier/progress tracking for watermark advancement. Pitfall: its arbitrary-worker-topology generality is overkill for a single node; do not import it wholesale. Applied in Phase 8.
  • PostgreSQL (github.com/postgres/postgres) — study src/backend/access/transam (xlog/WAL), src/backend/utils/cache/relcache. Lesson: WAL record format and redo-point discipline. Pitfall: do not copy MVCC visibility machinery wholesale; single-writer WAL semantics differ. Applied in Phase 5.
  • CockroachDB (github.com/cockroachdb/cockroach) — study pkg/kv/kvserver/rangefeed, pkg/ccl/changefeedccl. Lesson: resolved-timestamp change streams. Pitfall: do not copy its distributed range-splitting before the scheduler is stable. Applied in Phase 10.
  • Apache Flink (github.com/apache/flink) — study flink-runtime/.../checkpoint/CheckpointCoordinator.java. Lesson: checkpoint barrier injection and alignment protocol. Pitfall: do not copy unaligned checkpoints before aligned barriers work. Applied in Phase 6.

Glossary (§38) · 47 terms · site-wide glossary

Arrangement
indexed, incrementally-maintained materialized relation backing an operator's state (mv-state).
ArrangementSpec
declarative key/value layout description for an arrangement prior to instantiation.
ArrangementSnapshot
point-in-time durable image of an arrangement's contents at a CheckpointEpoch.
Backpressure
upstream throttling triggered when a downstream bounded queue nears capacity (P10, ADR-21).
Barrier
checkpoint-coordination marker injected into every operator's input to align a consistent cut (BarrierRequested→BarrierAligned).
CDC (Change Data Capture)
mechanism for consuming ordered/partially-ordered upstream mutation streams via mv-network.
CheckpointEpoch
u64 checkpoint generation identifier; never wall time.
CheckpointManifest
durable record of a checkpoint's WAL range and snapshot file set, checksum-verified (I13).
Compaction
reclamation of obsolete state in mv-storage that respects the active replay range (I11).
Credit Flow Control
bounded-MPSC backpressure scheme (ADR-21) granting downstream consumers explicit send credits.
Delta
a single signed row mutation, (+row)/(-row), carrying a timestamp and diff.
DeltaBatch
a batch of Delta records propagated atomically between operators.
Deterministic Execution
property that identical WAL input always yields identical operator output (P1).
EngineError
the closed error taxonomy: WalCorruption, SnapshotMismatch, WatermarkRegression, SchedulerStarvation, StateConflict, QueueOverflow, ProtocolViolation, SchemaIncompatible, ReplayDivergence.
Epoch
see CheckpointEpoch.
ExecutionBudget
bounded (max_rows, max_runtime_ns) slice granted to a SchedulerTask per poll.
Fsync
durable flush primitive; the point after which a mv-wal write is crash-safe.
IdempotencyKey
dedup token letting a re-delivered ingestion frame be safely discarded (I6 support).
LogicalPlan
immutable relational-algebra graph produced by mv-logical-plan, identified by a PlanHash.
LogicalTime
monotonic, replay-deterministic time domain used by timers and watermarks; never wall clock (ADR-22).
LogicalType
catalog-level type tag for a FieldDef within a RelationSchema.
Materialized View
a persisted, incrementally-maintained result of a registered ViewDefinition.
OperatorId
immutable u32 identity of a runtime operator, globally unique within an execution graph.
PlanHash
stable content hash of a LogicalPlan; immutable post-registration (I7).
PredicateExpr
filter-expression IR node evaluated inside Filter/Join operators.
AggExpr
aggregation-expression IR node driving arrangement bucket accumulation.
Queue Saturation
state where a bounded channel reaches its configured ceiling, triggering backpressure.
RefreshPolicy
view refresh cadence variant: Continuous, Interval(u64), Manual, OnCommit.
RefreshTask
scheduled unit of work executing a RefreshPolicy tick for one ViewId.
Replay
deterministic reconstruction of operator state from WAL plus checkpoint (P2).
ReplayCursor
durable (wal_offset, epoch, checksum) position marking replay progress.
ReplayDivergence
EngineError variant raised when a replayed run's output disagrees with the recorded one.
ReplayFrame
the wire/on-disk envelope carrying one operator's replay payload plus checksum.
Retract
a negative diff that removes a previously emitted row from downstream aggregation.
RocksDB
the locked (ADR-04) embedded LSM key-value state backend for mv-storage.
SnapshotManifest
see CheckpointManifest; enumerates a checkpoint's snapshot_files.
SourceOffset
mv-network dedup key marking a CDC source's ingestion position.
SSTable Bundle
the locked (ADR-24) on-disk snapshot format: a manifest referencing a set of sorted-string-table files.
StateHandle
trait exposing begin_txn() over a durable operator state region.
StateTxn
transactional handle returned by StateHandle::begin_txn, scoping atomic mutation.
Starvation
scheduler failure mode where a task's poll requests are indefinitely delayed by others.
Timer Wheel
mv-scheduler structure scheduling logical-time-ordered timer callbacks (window/refresh firing).
Watermark
(source_id, logical_time) monotonic lower bound below which no further updates are expected (I2).
Watermark Regression
invariant violation where a watermark decreases; detected via watermark_regression_total.
WAL (Write-Ahead Log)
append-only durable mutation log; the sole source of truth for replay (ADR-05).
WAL Segment
a rotated, bounded WAL file unit; capped at C25's 2048-segment budget.
Write Amplification
ratio of physical bytes written to logical bytes written; bounded <2.5× by C27.
