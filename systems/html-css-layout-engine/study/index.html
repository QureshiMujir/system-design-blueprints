  8. What is the exact difference between a stacking context established by opacity<1 and one established by a non-identity transform, in terms of paint-order consequences? (§21.2, §21.6)
  9. Why does hit-testing walk the display list instead of the box tree, and what bug would result from testing the box tree directly? (§21.2 — P11, I10)
  10. Derive the incremental-reflow cost floor for a single-paragraph edit from the §4 constraint table, showing the formula. (§34 item 3, §4 — M4)
  11. Why is style sharing's predicate conservative (allows false negatives, forbids false positives), and what would a false positive corrupt? (§15.6 — P4, I13)

  15. Trace the two-pass sizing model (min-content/max-content) through both flexbox (§18) and grid (§19) — what data structure do they share, and why? (§8.4, §11 — IntrinsicSizeCache)
  16. Why is the softbuffer rasteriser explicitly out of the performance target set (§30), and what would change if it were promoted to a production target? (§9 ADR-10)
  17. Explain why margin collapsing never crosses a BFC boundary using the invariant, not the rule list, as your explanation. (§7 I7, §17.2, §17.6)

32. Mental Models & First Principles

MM1 — "The box tree is a compiled artefact of the DOM, not a view of it." Predicts: any bug where a script mutation "should" instantly reflect in layout without a regeneration step is a misunderstanding, not a bug. Bug class without it: engineers reach for direct DOM-to-pixel shortcuts and reinvent anonymous-box logic ad hoc. Resolves in §16 (P1, ADR-02).

MM2 — "Computed style is a pure function boundary." Predicts: given the same (DOM subtree, matching rules), the computed style is always the same — a property the sharing cache (P4) depends on for soundness. Bug class without it: a "style leaks layout state" bug where computed values differ across otherwise-identical elements for no cascadable reason. Resolves in §15 (P3, I2, I13).

MM3 — "Invalidation is a graph-coloring problem solved once, not re-solved per mutation." Predicts: the cost of a mutation is O(1) hash lookup, never O(rules). Bug class without it: full re-style on every keystroke, a 30×+ regression (P8). Resolves in §15 (P6, ADR-08, I4).

MM4 — "A formatting context is a pluggable strategy, not an inheritance layer." Predicts: adding a new layout mode (e.g. subgrid) should touch one dispatch arm, not a class hierarchy. Bug class without it: the Blink LayoutObject maintenance burden this project explicitly avoids (ADR-03). Resolves in §16, §19 (P2).

MM5 — "Text layout is Unicode substrate wearing a CSS costume." Predicts: bidi and line-breaking bugs are almost always UAX #9/#14 conformance bugs, not CSS bugs. Bug class without it: engineers "fix" a bidi bug in the CSS layer instead of the Unicode layer, papering over the real defect. Resolves in §17 (I8, ADR-12).

MM6 — "The display list is the only thing paint order can be reasoned about in." Predicts: any hit-testing or stacking bug must be diagnosed against the display list, never the box tree. Bug class without it: hit-testing implemented against the box tree silently mis-orders overlapping stacking contexts. Resolves in §21 (P11, I10).

MM7 — "Reentrancy is a phase, not a lock." Predicts: the right primitive for "is it safe to flush layout right now" is a small state machine (LayoutPhase), not a mutex — because the question is about logical phase, not thread contention (P9: one writer thread already). Bug class without it: deadlock-prone lock-based reentrancy guards, or silent reentrant corruption if no guard exists at all. Resolves in §22 (P7, I11).

MM8 — "Every asserted performance number must be an amortized cost, not a peak cost." Predicts: a target like M9 (< 1 ms incremental reflow) is only meaningful because it is the steady-state cost after invalidation-set construction (a one-time O(rules) cost, §15.2) — quoting it without that context invites an apples-to-oranges comparison against a full-relayout engine. Resolves in §34 (Back-of-Envelope Capacity Model), §30 (M-table).

5. Required Reading

Books

  • Bert Bos, Håkon Wium Lie — Cascading Style Sheets: Designing for the Web, 3rd ed. Historical intent behind the cascade; applied in §8 (cascade rationale), §9 (ADR-06 layers).
  • Eric Meyer — CSS: The Definitive Guide, 4th ed. Positioning and float semantics; applied in §17 (BFC/floats), §20 (positioned layout).
  • Ilya Grigorik — High Performance Browser Networking, ch. 10 ("Rendering Pipeline"). Applied in §3 (architectural overview boundaries), §30 (performance engineering).
  • Tali Garsiel, Paul Irish — How Browsers Work (the browser-internals essay collection, book-length treatment). Applied in §16 (box tree), §21 (paint order).
  • Steve Souders — High Performance Web Sites. Applied in §30 (rendering-cost budgeting).
  • Brian Kernighan, Rob Pike — The Practice of Programming, ch. 5 ("Debugging"). Applied in §26 (operational readiness debugging methodology), §7 (invariant-driven debugging).

Papers

  • Meyerovich, Bodik — "Fast and Parallel Webpage Layout," WWW 2010. Constraint-based parallel layout; applied in §19 (grid track-sizing parallelism), §30.4.
  • Häkkinen et al., 2008 — "Improving the Performance of CSS Selector Matching." The bloom-filter ancestor accelerator; applied in §15.1 (stylist), P5.
  • Grosskurth, Godfrey, 2005 — "A Reference Architecture for Web Browsers." Applied in §2 (why-build framing), §33 (comparative architecture).
  • Baker et al. (Mozilla) — "Quantum CSS: The Rust-Based Styling Engine." Applied in §15 (stylist/rule-tree design), ADR-07.
  • Meyerovich, Torlak, Bodik, 2011 — "Parallel Data-Race-Free Web Page Layout." Applied in §30.4 (layout parallelism boundaries).
  • W3C TAG — "Web Platform Design Principles." Applied in P15 (API-shape principle).
  • Ousterhout, "A Philosophy of Software Design" (talk/paper form). Applied in P1/P2 module boundaries.
  • Unicode Technical Committee — "UAX #9: Unicode Bidirectional Algorithm." Applied in §17.3 (bidi), I8.

Reference Implementations

  • Servo style crate (github.com/servo/stylo) — selectors/, style/properties/, style/stylist.rs, style/invalidation/. Lesson: predicate-gated sibling sharing, applied in §15.6. Pitfall not to copy: early Stylo integration coupled style to Gecko's frame tree too tightly.
  • Servo layout_2020 (github.com/servo/servo/tree/main/components/layout_2020) — the BFC/IFC reference. Lesson: formatting-context-as-enum-tag, applied in P2 and Phase 5 (§17). Pitfall: intrinsic-size caching was added late; build it in from Phase 5.
  • WebKit Source/WebCore/layout/ (LFC) — BlockFormattingContext, InlineFormattingContext, FormattingContext. Lesson: sub-routine dispatch over class hierarchy, applied in ADR-03 and Phase 4 (§16). Pitfall: LFC coexisted with legacy RenderObject for years — do not plan a dual-hierarchy migration.
  • Mozilla layout/ (nsBlockFrame, nsLineLayout, nsTextFrame) — the battle-tested edge cases, applied in Phase 5 (§17) as the post-WPT-green second-pass reference. Lesson: consult only after your own BFC/IFC is green on WPT. Pitfall: frame-tree naming conventions do not map cleanly onto a box-tree design; do not port names literally.
  • Chromium LayoutNG design docs (chromium.org design-docs area) — the two-pass constraint/fragment model, applied in §16 (box-vs-DOM split) and Phase 6/7 (§18–§19, two-pass sizing). Lesson: fragment trees separate "what was computed" from "the DOM node it came from," the same split as P1. Pitfall: NG's incremental migration off legacy layout took years — plan a clean-room box tree from Phase 4, not a shim.

Glossary (§38) · 36 terms · site-wide glossary

Anonymous box
A box generated by box generation (§16) with no corresponding DOM element — e.g. an anonymous block wrapping a run of inlines inside a block container.
Atomic inline
An inline-level box treated as a single rectangle by the IFC: inline-block, inline-table, or a replaced element.
Bidirectional algorithm (bidi)
UAX #9; translates a logical character sequence to a visual order given the paragraph's embedding level (§17, I8).
Block formatting context (BFC)
A region of layout in which block-level boxes stack vertically and float positioning is computed (§17.2, I7).
Bloom filter
A probabilistic ancestor-feature cache short-circuiting descendant-selector matching (§15.1, ADR-05).
Box tree
The layout-internal tree of LayoutBox values, structurally distinct from the DOM tree (§8.4, P1, ADR-02).
Cascade
The algorithm resolving a property to its specified value from matching declarations, per a total order (§15, P5).
ComputedStyle
The immutable, #[non_exhaustive] value produced after cascade + computed- value transform; the boundary between style and layout (§11, P3, I2).
Dirty bits
Per-box flags (needs_style needs_box_regenerate needs_layout needs_paint) forming a monotonic lattice within a frame (§11, I6).
Display list
A flat, typed, Send + Sync list of paint commands; the deliverable of the paint pass (§21, P10).
Engine
The value-typed root object of the public API; Send, not Sync (§11, P9, I11).
Flex formatting context
The region of layout implementing CSS Flexbox Level 1 (§18).
FormattingContext
The enum tag selecting a LayoutBox's layout sub-routine (§8.4, P2, ADR-03).
Fragment
The positioned, sized output of a layout pass for one box (§8.4, §11).
Grid formatting context
The region of layout implementing CSS Grid Layout Level 2 (§19).
Inline formatting context (IFC)
The region of layout in which inline-level boxes lay out into line boxes (§17.2).
Initial value
A property's value in the absence of any matching declaration (§15.3).
Intrinsic size cache
Per-formatting-context cache of min-/max-content sizes, shared in shape between flexbox and grid's two-pass sizing (§35 Q15, §11).
Invalidation set
The set of selectors whose match status depends on a given feature; consulted on mutation (§15.7, P6, I4).
LayoutBox
The box-tree node type: id, style, formatting context, fragments, intrinsic cache, dirty bits (§11).
LayoutPhase
The reentrancy-guard enum (Idle Style Box Layout Paint) enforcing P7/I11.
Line box
A horizontal slice of an IFC; the unit of line-breaking (§17.2).
Margin collapsing
CSS 2.1's rule merging adjacent in-flow block margins within a BFC (§17.2, I7).
PaintCommand
A tagged union of typed paint operations forming the display list (§11, §21).
Painting
The pass emitting a display list from the box tree's computed geometry (§21, P10).
Pseudo-element
A box generated by ::before/::after/::marker/::first-line/ ::first-letter (§16.2).
Reentrancy guard
The LayoutPhase-based mechanism blocking layout-flushing calls from a non-Idle phase (§22, P7, I11).
Replaced element
An element whose rendering delegates to an external resource — image, video, canvas, iframe (§16.2).
Rule tree
The interned tree of (rule, source) pairs; the canonical representation of an element's matching-rule list and the style-sharing key (§15.2, I5).
Sibling style sharing
A cache reusing a ComputedStyle across siblings gated by a 12-item predicate (§15.6, P4, I13).
Stacking context
A self-contained painting region with its own z-index ordering (§21.2).
Static position
The position an absolutely positioned box would occupy in normal flow, consulted when its offset properties are auto (§20.2).
Sticky positioning
A hybrid positioning scheme flowing normally until a scroll threshold, then offsetting to remain within the scrollport (§20.2).
Stylist
The per-document index of stylesheets and their rules, bucketed for fast matching (§15.1, ADR-05).
Track-sizing algorithm
CSS Grid's four-phase column/row-size resolution (§19.2).
WPT
Web Platform Tests, the cross-browser conformance corpus (§5, P13, ADR-13).
