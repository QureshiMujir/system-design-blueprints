Decisions (§9) · 24 ADRs

ADR-01

Dispatch technique

Chosen

match/switch dispatch on opcode byte

Rejected

computed goto (labels-as-values); direct/indirect threading; subroutine threading

When the rejected choice is right

Hand-tuned C/C++ interpreter on GCC/Clang where computed goto measurably beats switch by 10-20% (Ertl & Gregg 2003)

Why: portable on stable Rust; LLVM lowers a dense match to a jump table

ADR-02

Operand model

Chosen

stack-based

Rejected

register-based (Lua-style)

When the rejected choice is right

Production runtime optimizing instruction count/dispatch overhead (Lua 5.0, Ierusalimschy et al. 2005)

Why: simpler single-pass codegen, no register allocator needed at this scope

ADR-03

Opcode width

Chosen

1-byte opcode + fixed-width immediate operands

Rejected

LEB128 variable-length encoding; superinstructions

When the rejected choice is right

Size-constrained portable binary format needing dense encoding (WebAssembly Core Spec)

Why: simple, fast decode, matches §11 opcode table

ADR-04

Constant pool structure

Chosen

per-module flat Vec<Constant>, u16-indexed

Rejected

per-function pools; separate string-intern table

When the rejected choice is right

Large multi-module program where per-function pools reduce cross-module coupling (JVM per-class pool, Lindholm et al.)

Why: single lookup path, dedup at compile time (P4)

ADR-05

Calling convention

Chosen

caller-pushes-args, callee-owns-frame, shared operand stack

Rejected

separate per-frame stacks; register-window passing (SPARC ABI)

When the rejected choice is right

Hardware with native register windows (SPARC) or cross-frame isolation requirement (capability VMs)

Why: matches seed draft convention, minimal copying (P5)

ADR-06

Local variable addressing

Chosen

u8 slot index into Frame.locals

Rejected

named-variable hash lookup; closure-captured cells

When the rejected choice is right

Language requiring first-class closures over captured variables (Lua upvalues)

Why: O(1) fixed-size access, arity-checked at compile time

ADR-07

Value representation

Chosen

tagged enum Value { Int, Float, Bool, Null, Ref }

Rejected

NaN-boxing; tagged-pointer packing

When the rejected choice is right

Throughput-critical dynamic-language VM where NaN-boxing halves Value size (JS engines, Lua tables)

Why: safe-by-construction ADT, no unsafe bit tricks in scope

ADR-08

Heap object memory management

Chosen

mark-sweep tracing GC (Phase 6)

Rejected

reference counting; arena/region allocation without reclamation

When the rejected choice is right

Short-lived, request-scoped VM instance where an arena reset is cheaper than tracing

Why: handles reference cycles correctly (Bacon et al. 2004); matches Smalltalk-80 object-memory model

ADR-09

Bytecode verification

Chosen

static verifier pass before execution (stack-effect, jump-target, index-bounds)

Rejected

trust-the-compiler (no verifier); runtime-only checks

When the rejected choice is right

Closed pipeline where compiler and VM share one trust boundary with no persistence or transmission step in between

Why: separates untrusted bytecode ingestion from trusted execution (Leroy 2003)

ADR-10

Disassembler format

Chosen

one canonical textual disassembly (offset, mnemonic, operand, resolved constant)

Rejected

binary-only tooling; DWARF-style separate debug sections

When the rejected choice is right

Production VM shipping stripped release binaries needing separate debug-info sections to avoid bloat

Why: matches vm-cli tooling scope, human-auditable (P10)

ADR-11

Implementation language

Chosen

Rust (stable channel)

Rejected

C; C++; Zig

When the rejected choice is right

Project needs computed-goto dispatch or manual memory-layout control unavailable in stable Rust

Why: memory safety without unsafe bit tricks; matches seed-draft crate boundaries

ADR-12

Parser scope

Chosen

AST accepted directly as VM input; textual parser deferred

Rejected

full parser front-end in Phase 0

When the rejected choice is right

End-user-facing language product where a textual surface syntax ships on day one

Why: isolates VM correctness from grammar/parsing concerns

ADR-13

Error handling in execution loop

Chosen

Result<Value, VmError> from Vm::run, no panics on user-code faults

Rejected

process abort on fault; C-style errno/out-param

When the rejected choice is right

Single-tenant CLI demo tool where abort-on-fault is acceptable and simpler

Why: embeddable VM must not crash the host process (P6)

ADR-14

Numeric semantics

Chosen

checked integer arithmetic (overflow → VmError), IEEE-754 double float

Rejected

wrapping/unchecked arithmetic

When the rejected choice is right

Performance-critical numeric kernel post-verification where checked-arith overhead is unacceptable

Why: deterministic, debuggable, reproducible fixtures (P12)

ADR-15

Concurrency model

Chosen

single-threaded execution loop per Vm; no shared mutable interpreter state across threads

Rejected

green-thread/fiber scheduler inside vm-core

When the rejected choice is right

Concurrent actor-style VM needing per-process schedulers (Erlang BEAM)

Why: keeps Phase 0-9 scope bounded (P11)

ADR-16

Function call resolution

Chosen

direct u16 index into Module.functions, resolved at compile time

Rejected

name-based dynamic lookup table; vtable/trait-object dispatch

When the rejected choice is right

Late-bound plugin system or dynamic FFI callback table needing runtime name resolution

Why: O(1) call resolution, no hashing on hot path

ADR-17

Conformance test strategy

Chosen

per-opcode JSON fixture pairs checked in CI

Rejected

hand-written assert-only unit tests without fixtures

When the rejected choice is right

Rapidly prototyped internal tool where fixture-authoring overhead exceeds the tool's lifetime

Why: fixtures are reusable across compiler/VM boundary, regression-proof

ADR-18

Build system

Chosen

Cargo workspace, per-crate manifests

Rejected

single monolithic crate; Bazel/Buck

When the rejected choice is right

Multi-language monorepo needing Bazel's cross-language build graph

Why: matches seed-draft crate boundaries (vm-core/vm-compiler/vm-stdlib/vm-cli)

ADR-19

Bytecode persistence

Chosen

in-memory Module only for Phase 0-9

Rejected

custom binary file format in Phase 0; reuse WebAssembly binary container

When the rejected choice is right

Distribution scenario requiring a shippable compiled artifact (.wasm, .class, .pyc)

Why: keeps persistence concerns out of the correctness kernel

ADR-20

Inline caching for calls

Chosen

deferred past Phase 9; Phase 9 measures without caches

Rejected

monomorphic inline caches implemented in Phase 9

When the rejected choice is right

Dynamically-typed OO language with polymorphic call sites (Smalltalk, JS) where ICs yield 2-10x

Why: fixed, statically-arity call model here gets little benefit from Deutsch & Schiffman (1984) ICs

ADR-21

GC algorithm family

Chosen

non-moving mark-sweep with free-list

Rejected

copying/compacting GC; generational GC

When the rejected choice is right

Allocation-heavy workload with high garbage-to-live ratio where copying/generational GC improves throughput

Why: simpler root-scanning story for Phase 6 scope, no forwarding-pointer bookkeeping

ADR-22

GC safepoint placement

Chosen

safepoints only at Call/Return/backward-Jump (P8)

Rejected

safepoint on every instruction

When the rejected choice is right

Hard real-time system needing sub-instruction preemption guarantees

Why: bounds worst-case pause latency without per-instruction overhead

ADR-23

Stdlib function boundary

Chosen

native Rust functions called via a fixed table, panics caught at the boundary

Rejected

allow native panics to propagate into the execution loop

When the rejected choice is right

Trusted, single-binary CLI tool where a native panic terminating the whole process is acceptable

Why: embeddable VM must not corrupt its own state on a native fault (ADR-13)

ADR-24

Telemetry integration

Chosen

counters/gauges emitted via a lightweight internal Metrics trait

Rejected

full tracing-crate spans per instruction; no telemetry at all

When the rejected choice is right

Embedding context with an existing tracing subscriber already wired in — spans win there

Why: per-instruction spans would dominate dispatch cost (M1); zero telemetry blocks §24

34. Alternative Architectures (Roads Not Taken)

Register-based bytecode.

[Stack VM]                    [Register VM]
LoadLocal 0  ; push a         ADD r2, r0, r1   ; r2 = a + b, one instruction
LoadLocal 1  ; push b
IAdd         ; pop,pop,push
StoreLocal 2 ; pop, store

Wins in throughput-sensitive embedded/scripting deployments where dispatch-cycle count dominates — the real system embodying it is Lua 5.0+ (Ierusalimschy, de Figueiredo & Celes 2005), which halved average instruction count versus its own prior stack-based design. Rejected here (ADR-02) because this project's scope (§1) prioritizes a codegen pass with no register allocator over raw dispatch throughput — the pedagogical value of a simple compiler outweighs the performance win at this project's scale.

Template/JIT interpreter (generated machine code per opcode).

dispatch table: [opcode] -> pointer to generated native code stub
execution: jump directly into generated code, no interpretive decode step

Wins in high-install-base production runtimes where per-architecture assembly maintenance cost is justified by aggregate throughput gains across billions of executions — the real system is OpenJDK HotSpot's template interpreter. Rejected here (§9 ADR-01/ADR-11) because it requires per-target assembly generation entirely out of a from-scratch, portable, stable-Rust teaching project's scope.

Direct AST-walking tree interpreter (no bytecode at all).

eval(node):
  match node { BinaryOp(op, l, r) -> apply(op, eval(l), eval(r)), ... }

Wins in implementation simplicity and fast time-to-first-execution for small scripting embeddings — the real system is pre-1.9 CRuby (MRI), which walked the AST directly. Rejected here because CRuby's own history is the counter-argument: Ruby 1.9 replaced the tree-walker with YARV, a compiled stack-bytecode VM, precisely because AST-walking could not compete on performance and because this project's explicit purpose (§2) is to teach bytecode design, which a tree-walker has none of.

Indirect/subroutine-threaded code (Forth-style, GNU-extension-dependent).

handler table: [opcode] -> code-address; NEXT: fetch, indirect-jump to handler, handler ends with
                                          a jump back to NEXT (no central switch)

Wins on architectures/compilers without good switch-to-jump-table optimization, where a labels-as- values / computed-goto extension turns dispatch into a data-driven jump chain — the real systems are classic Forth implementations and Smalltalk-80's original virtual machine (Goldberg & Robson 1983). Rejected here (ADR-01, ADR-11) because it relies on the GNU C "labels as values" extension with no equivalent in stable Rust, directly conflicting with §1's language rationale.
