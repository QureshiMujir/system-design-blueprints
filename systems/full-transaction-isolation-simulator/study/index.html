30. Mental Models & First Principles

MM1. Isolation is a phenomenon-avoidance contract, not a mechanism. Predicts: different mechanisms (2PL, MVCC, OCC) can satisfy the same isolation level. Bug class without it: conflating "uses MVCC" with "is Serializable" (SI ≠ Serializable, write-skew). Resolving: §8, §18.

MM2. Snapshot visibility is a pure timestamp-range predicate. Predicts: visibility bugs are always begin_visibility_ts/end_visibility_ts off-by-one errors. Bug class: phantom stale reads from a mis-set end_visibility_ts. Resolving: §11, §15.

MM3. A cycle in the serialization graph is necessary and sufficient for a non-serializable history (Papadimitriou 1979). Predicts: SSI only needs to detect potential cycles (dangerous structures), not full cycles, to be conservative. Bug class: under-detection that misses G2-item anomalies. Resolving: §17.

MM4. Determinism is a closure property of the whole causal history, not any single component. Predicts: one nondeterministic HashMap iteration anywhere breaks global replay. Bug class: "mostly deterministic" replay hashes that pass 99/100 runs. Resolving: §12, I2.

MM5. Deadlock is a liveness property, not a correctness property. Predicts: a system can be always-correct (no anomalies admitted) yet always-live-locked. Resolving: §14, §23.

MM6. WAL is the source of truth; in-memory state is a cache of it. Predicts: recovery equals WAL replay, nothing more. Bug class: recovery logic that reconstructs state from something other than the WAL. Resolving: §13, §19.

MM7. Optimistic concurrency shifts conflict detection from acquisition-time to commit-time. Predicts: OCC has zero blocking but unbounded abort-and-retry under contention. Resolving: §16, §29.

MM8. Replication lag is a bounded-staleness read anomaly, structurally identical to a stale MVCC snapshot. Predicts: the same visibility-horizon reasoning used for snapshots (§15) applies to replicas (§20). Resolving: §15, §20.

Reference Implementations

  • PostgreSQL — src/backend/storage/lmgr (lock manager), src/backend/access/transam (transaction-ID visibility), src/backend/storage/lmgr/predicate.c (SSI/SIREAD locks). Lesson: production SSI predicate-lock granularity. Pitfall: predicate-lock false positives causing spurious serialization failures. Applied in §14 / Phase 2, §17 / Phase 5.
  • CockroachDB — pkg/kv (transaction coordinator), pkg/storage (MVCC storage engine). Lesson: hybrid-logical-clock timestamp allocation for external consistency. Pitfall: clock-skew-induced uncertainty intervals. Applied in §15 / Phase 3, §20 / Phase 8.
  • FoundationDB — deterministic simulation test mode. Lesson: whole-cluster deterministic fault injection under a single simulated clock. Pitfall: simulation/production behavioral divergence ("the simulation gap"). Applied in §12 / Phase 0, §19 / Phase 7.
  • SQLite — pager subsystem (src/pager.c, WAL-mode reader/writer coordination). Lesson: single-writer WAL-mode snapshotting. Pitfall: writer starvation under long readers. Applied in §13 / Phase 1, §15 / Phase 3.
  • TiDB — Percolator-derived two-phase-commit + timestamp-oracle transaction model. Lesson: a centralized timestamp oracle is a clean serialization point. Pitfall: the oracle becomes a single point of contention at scale. Applied in §16 / Phase 4, §20 / Phase 8.

Glossary (§36) · 60 terms · site-wide glossary

2PL
: Two-Phase Locking — growing phase (acquire only) followed by shrinking phase (release only).
ADR
: Architecture Decision Record.
Adya anomaly (G0–G2)
: generalized isolation anomalies per Adya (1999), defined over dependency graphs rather than lock behavior.
ARIES
: Algorithm for Recovery and Isolation Exploiting Semantics (Mohan et al. 1992).
Backpressure
: refusing/blocking new work when a bounded resource is full, rather than silently dropping it (P11).
Cascading abort
: an abort that forces the abort of dependent transactions.
Compatibility matrix
: table of which lock modes may be held concurrently on one resource.
Conflict graph / serialization graph
: directed graph of transactions with an edge for each ww/wr/rw conflict; acyclicity implies conflict-serializability (Papadimitriou 1979).
Conformance fixture
: a versioned input/expected-output pair used to gate correctness.
Correlation ID
: an identifier threading a logical operation across spans/events.
Dangerous structure
: the two-consecutive-rw-edge pattern SSI rejects (Cahill et al. 2008).
Deadlock
: a cycle in the wait-for graph; a liveness failure, not a correctness failure (MM5).
Determinism
: identical (seed, input history) always produces an identical execution trace.
Dirty read (P1)
: reading an uncommitted write.
Dirty write (P0)
: overwriting an uncommitted write.
Elle
: black-box isolation-anomaly inference tool/technique (Kingsbury & Alvaro 2020).
Escalation
: promoting a lock's granularity (e.g., row → table) under contention.
Fixture poisoning
: tampering with a conformance fixture to corrupt its expected verdict.
G0 (write cycle)
: a cycle among only write-write dependencies (Adya 1999).
G1a/b/c
: Adya's aborted-read, intermediate-read, and circular-information-flow anomalies.
G2 / G2-item
: Adya's anti-dependency-cycle anomaly, generalizing write-skew.
HLC
: Hybrid Logical Clock.
Isolation level
: a named contract (RU/RC/RR/SI/Serializable) bounding which phenomena a system permits.
Lost update
: two transactions read-modify-write the same key, and one overwrite is lost.
MVCC
: Multi-Version Concurrency Control.
Non-repeatable read (P2)
: a value read twice by the same transaction differs.
OCC
: Optimistic Concurrency Control (Kung & Robinson 1981).
P0–P3
: Berenson et al. (1995) phenomena — dirty write, dirty read, non-repeatable read, phantom.
Phantom (P3)
: a repeated range query returns a different row set.
Predicate lock
: a lock over a query predicate rather than a specific row (Eswaran et al. 1976).
Read-only anomaly
: a read-only transaction observes a non-serializable state despite every individual writer being serializable (Fekete et al. 2005).
Read skew
: a transaction's reads are individually valid but mutually inconsistent.
Replay divergence
: two runs of the same (seed, input) produce different replay hashes.
RTO
: Recovery Time Objective.
RU/RC/RR/SI
: Read Uncommitted / Read Committed / Repeatable Read / Snapshot Isolation.
Serializability
: equivalence to some serial (non-interleaved) execution order.
SIREAD lock
: PostgreSQL's SSI read-tracking lock (Ports & Grittner 2012).
Snapshot horizon / visibility horizon
: the maximum commit timestamp visible to a snapshot.
Split brain
: two replicas independently diverge from a shared history.
SSI
: Serializable Snapshot Isolation.
Starvation
: indefinite delay of a transaction despite the system remaining live overall.
Tombstone
: a marker for a deleted version, retained until vacuum-eligible.
Torn write
: a partially-written record observable after a crash mid-write.
TSO
: Timestamp Oracle (centralized timestamp allocator, e.g., TiDB/Percolator-derived).
Vacuum
: reclamation of version-chain entries no longer visible to any active snapshot.
Victim (deadlock)
: the transaction chosen to abort to break a detected cycle.
Wait-for graph
: directed graph of "transaction A waits for transaction B" edges.
WAL
: Write-Ahead Log.
Write skew
: two transactions each read a value the other writes, both commit under SI, violating an invariant that spans both rows.
Anti-dependency
: a rw-conflict edge, i.e., transaction A reads a value that transaction B later overwrites; the raw material of Adya's G2/G2-item anomalies.
Checkpoint
: a WAL marker recording the set of active transactions at a point in time, bounding replay's redo scan range.
Commit dependency
: a transaction's commit is contingent on another transaction's prior commit outcome (used to reason about cascading aborts).
Conformance matrix
: the isolation-level × anomaly × engine cross-product table (§18) used as the release-gating correctness oracle.
Degrees of consistency
: Eswaran et al.'s (1976) predecessor terminology to modern isolation levels.
Logical clock
: a monotonic counter used in place of wall-clock time to establish a happens-before order (Lamport 1978).
Timestamp oracle (TSO)
: a centralized service issuing globally ordered timestamps, as used in Percolator-derived designs (§31).
Correlation ID scope
: a correlation ID is scoped to one logical transaction's lifetime (§8), never reused across a retry — a retried transaction is issued a fresh txn_id and a fresh correlation ID, keeping forensics (§23) unambiguous per attempt.
Fixture corpus
: the union of every fixtures/**/*.json and fixtures/**/*.bin file referenced across §12–§21's N.5 subsections plus §18's isolation matrix and §21's elle corpus.
AnomalyVerdict
: the shared enum (§11) returned by both the white-box (§18) and black-box (§21) conformance oracles, making their outputs directly diffable.
MetricsSink
: the one-way telemetry trait (§11) that P8 forbids from feeding back into any scheduling decision.
