3.2 Box Narratives

  • gtrd control-plane facade. Entry points: author/load policies + pools, run the decision engine in compute-the-plan mode, aggregate health from probers, drive propagation to edges. Owns the authoritative config + the global health view. Thin orchestration over the crates below; regionally replicated with a leader (§22).
  • gtr-core. The vocabulary every crate speaks. Endpoint = a steerable target (IP/addr, location, weight, pool membership). Pool = a set of endpoints with a policy + health-check config. HealthCheck = a probe spec (protocol, interval, thresholds). HealthState = the consensus health of an endpoint (Healthy/Degraded/Unhealthy + score). Policy = a routing-policy AST (failover/weighted/latency/geo/multi-value/composite). SteeringDecision = the resolved set of endpoints to return + why. ClientContext = the per-query inputs (source IP, ECS subnet, resolved location, requested record type).
  • health. The distributed health subsystem. Active probers (HTTP/HTTPS status+body, TCP connect, ICMP echo) run from N vantage points; passive signals (edge-observed errors/latency) feed in too. The consensus layer fuses per-vantage verdicts into one HealthState (quorum / weighted by vantage reliability) — one broken vantage cannot flap an endpoint. Flap damping suppresses oscillation (penalty accrues on each flip, decays over time; an endpoint must "earn back" UP). The most operationally subtle subsystem: the false-positive/reactivity dial lives here.
  • geo. IP→location via a prefix trie over a geo DB (longest-prefix-match on the client subnet). Parses + applies ECS: if the query carries a client subnet, that subnet (not the resolver IP) drives geo; the answer is scoped to a returned SCOPE PREFIX-LENGTH. Computes geoproximity distance (great-circle + a per-endpoint bias) for geo-routing policies.
  • latencymap. The RUM / latency database. Ingests real-user-measurement samples (client-network → endpoint latency) and aggregates them into a client_network → endpoint → latency_estimate table (the "latency map"). Lookup powers latency-based routing: steer a client's network to its lowest-latency healthy endpoint. Handles sparse/missing data (fall back to geoproximity) and staleness (decay old samples).
  • policy. The decision engine. Evaluates a Policy AST against a ClientContext + the current HealthState + latency/geo data → a SteeringDecision. Policy kinds: failover (primary, then secondaries by health), weighted RR (distribute by weight), latency (latencymap lookup), geolocation (continent/country/subdivision match), geoproximity (nearest by distance + bias), multi-value answer (return up to N healthy, client picks), and composite/nested (a geo policy whose leaves are failover pools, etc.). Deterministic: same inputs → same decision (modulo the seeded weighted/MV shuffle) — the oracle property.
  • dns. Authoritative answer generation: assemble the A/AAAA/CNAME RRset for the decided endpoints, encode ECS in the response (echo subnet + SCOPE), set the TTL per the TTL strategy, handle negative answers (NXDOMAIN/NODATA). Produces the per-query RRset that the authoritative server (#162) serializes onto the wire — we own the answer, not the zone/server.
  • anycast. Announcement steering: from per-PoP health, decide which PoPs should announce vs withdraw an anycast prefix (a dead PoP withdraws → BGP convergence steers clients to the next-nearest live PoP). Emits announce/withdraw intents to a BGP control sink (a real BGP-4 speaker is deferred — §22.2; we ship a file/simulated sink + the decision logic). Coarse-grained (per-PoP, not per-client) but reacts at routing speed, not TTL speed.
  • http-redirect. A minimal HTTP responder that answers with 302/307 + Location pointing at the decided endpoint. Per-request precise (no caching, no resolver in the loop) at the cost of a full RTT + a TCP/TLS setup to the redirector. Used where DNS granularity is too coarse and anycast control too blunt.
  • propagate. Distributes the control plane's decisions (resolved pool→endpoint plans + HealthState) to all edge responders. Versioned by a monotonic generation number; edges apply generations in order and report their applied generation; staleness bounds define how far behind an edge may be before it is flagged. The eventual-consistency engine — its correctness (ordered, bounded-stale, no split decision) is what makes a global failover safe.
  • runtime. Process/role lifecycle: control-plane (with regional leader + epoch fencing so two leaders never propagate conflicting generations), edge responder, prober agent; config loading; the control→edge channel setup; health/propagation membership.
  • bench / conformance. Answer-latency + propagation-latency harness; the deterministic policy oracle (a reference evaluator — given inputs, the one correct decision); ECS/DNS conformance (wire-format + scope correctness vs the relevant RFCs); fault injection (kill vantages, flap endpoints, partition propagation, stale edges, malformed ECS).

3.3 Boundaries

  • Trust boundary: the public DNS/HTTP query path (untrusted clients/resolvers — malformed packets, spoofed ECS, query floods), the health-probe responses (an endpoint can return anything), the BGP control sink (announcements affect global routing — privileged), and the C ABI. All wire input is length-checked + bounds-validated; ECS is sanity-checked (subnet length caps, address-family).
  • Concurrency boundary: control plane (probers, aggregation, decision-plan compute, propagation fan-out) vs edge (per-query answer generation — read-mostly against a snapshot of propagated state). The edge hot path is lock-free against an atomically-swapped state generation; the control plane is sharded by pool.
  • Consistency boundary: propagation is the one eventual-consistency seam — the control plane is the source of truth, edges are eventually-consistent replicas bounded by a staleness target (I-class invariant). Within an edge, a single query reads one consistent generation snapshot (no torn reads across generations).
  • Coordination boundary: the regional leader + epoch is the only coordination point (who is allowed to advance the propagation generation); the data plane (edge answers) is fully local once state is propagated.

3.4 Data-flow walk — one DNS query steered by geo + health (the canonical path)

  1. A client behind resolver R asks R for app.example.com; R (a recursive resolver, #65) forwards to the authoritative server (#162) which invokes gtr-edge at the nearest PoP (anycast-routed to the edge).
  2. gtr-edge builds a ClientContext: source = R's IP; if R sent ECS, the client subnet (e.g. 203.0.113.0/24) overrides R's IP for geo (I-ECS); geo::locate does a longest-prefix lookup → client location = "EU/DE".
  3. policy::decide evaluates the pool's policy (say geolocation: EU→eu-pool, US→us-pool, default→us-pool) against the location → selects eu-pool; eu-pool's inner policy is failover(primary=eu-west-1, secondary=eu-central-1).
  4. The current propagated HealthState (generation G, staleness < bound, I-PROP) says eu-west-1 = Unhealthy (consensus across vantages, I-CONS), eu-central-1 = Healthy → failover picks eu-central-1.
  5. dns::answer assembles an A record for eu-central-1's IP, sets TTL per the TTL strategy (short during an active failover — §8.7), echoes the ECS subnet with SCOPE = /24, and returns the RRset to #162 to serialize.
  6. R caches the answer for the TTL and serves all its clients in 203.0.113.0/24 that endpoint until the TTL expires (eventual consistency — Consequence 1, §2.7); a DecisionTrace recorded policy path, location, chosen endpoint, health, generation, ECS scope.
  7. When eu-west-1 recovers, the prober vantages re-reach consensus (after flap-damping confirms stability), the control plane advances the generation, propagation pushes G+1 to edges, and new queries (after TTL) steer back — the failover RTO is detect + damp + propagate + TTL (§4).

3.5 Per-role concurrency model (control plane, edge, prober)

  • Prober agent: an async pool of probe tasks (one per (endpoint, check) scheduled at its interval); results batched + reported upstream over a control channel; isolated per-vantage so a slow probe never blocks others.
  • Control plane: sharded by pool — a health-aggregation task per pool fuses vantage reports into HealthState (consensus + damping); a decision-plan compute task recomputes resolved plans on health/config change; a propagation task fans generations out to edges; a regional-leader task holds the epoch lease. No global lock; shards are independent.
  • Edge responder: the hot path is read-mostly — each query reads an Arc-swapped immutable EdgeState snapshot (current generation's pools + health + latency/geo data) → answer generation touches no locks (principle 9). State updates from propagation build a new snapshot and atomically swap the Arc (RCU-style); in-flight queries finish on the old snapshot (no torn reads).
  • Synchronization: the only cross-task coordination is the generation epoch (leader) and the atomic snapshot swap at edges. The answer path is allocation-light and lock-free, which is what permits the sub-ms tail (§4).
  • This separation (probe ≠ aggregate ≠ decide ≠ propagate ≠ answer) is what lets the data plane stay fast and lock-free while the control plane does the heavy stateful work.

8. Domain Model — Endpoints, Health, Policy, ECS/DNS, Propagation

8.1 Endpoint / pool model

  • An Endpoint is a steerable target: { id, addr (IPv4/IPv6 or CNAME target), location (lat,lon,country,continent), weight, healthcheck_ref, pool_ref }.
  • A Pool groups endpoints under one Policy + one HealthCheck spec: { id, name, endpoints: Vec<EndpointId>, policy: Policy, healthcheck: HealthCheck, ttl }.
  • A PolicySet (Route-53-"traffic-policy"-style) is the top-level: a name → a (possibly nested) Policy whose leaves resolve to pools/endpoints.
  • Endpoints can be shared across pools; health is computed once per endpoint (per its check), not per pool (I-PROBE-BUDGET).

8.2 Health-check model + consensus

  • A HealthCheck = { kind: Http{path,expect_status,expect_body?} | Tcp{port} | Icmp, interval, timeout, k_fail, k_pass }.
  • Each vantage point runs the check independently → a per-vantage verdict {Up|Down, rtt, ts}.
  • Consensus: the control plane fuses vantage verdicts into one HealthState ∈ {Healthy, Degraded, Unhealthy} using a quorum (≥ ⌈(V+1)/2⌉ agree) optionally weighted by per-vantage reliability (I-CONS). Degraded = quorum-Up but elevated RTT / partial failures → eligible but de-preferred.
  • State transitions require k_fail consecutive failing intervals to go Up→Down and k_pass to go Down→Up (hysteresis), and quorum at each step.

8.3 Flap damping (the stability mechanism)

Event Effect
Endpoint flips state (Up↔Down) penalty += flip_cost
Each interval with no flip penalty *= decay (exponential decay)
penalty ≥ suppress_threshold endpoint damped: held in current (usually Down) state, not eligible to re-steer
penalty < reuse_threshold (after decay) damping released; endpoint re-eligible
  • Borrowed from BGP route-flap damping. Prevents an oscillating endpoint from re-steering global traffic every interval (I-DAMP). The thresholds are the reactivity-vs-stability dial (§4.3); too aggressive → a recovering endpoint is held down too long; too lax → thrash.

8.4 The routing-policy AST (EBNF sketch)

Policy   := Failover | Weighted | Latency | Geolocation | Geoproximity | MultiValue | Composite
Failover := "failover" "{" "primary" Target ("secondary" Target)* "}"
Weighted := "weighted" "{" (Target "weight" INT)+ "}"
Latency  := "latency" "{" Target+ "}"                          // pick lowest-latency healthy (latencymap)
Geolocation := "geolocation" "{" (Region "->" Target)+ ("default" "->" Target)? "}"
Geoproximity := "geoproximity" "{" (Target "bias" INT)+ "}"     // nearest by distance + bias
MultiValue := "multivalue" "{" Target+ "max" INT "}"            // return up to N healthy
Composite := <any Policy whose Target is itself a Policy or a Pool>   // nesting
Target   := EndpointRef | PoolRef | Policy
Region   := "continent" STR | "country" STR | "subdivision" STR
  • Evaluation (policy::decide) is a deterministic AST walk against (ClientContext, HealthSnapshot, LatencyMap, GeoDb) → SteeringDecision (I-DET). Health filters first (unhealthy targets removed); then the policy selects among healthy; fallback (I-FAILSAFE) if none.

8.6 ECS handling + scope (RFC 7871)

  • The OPT pseudo-RR (EDNS0) may carry an ECS option: { FAMILY (1=IPv4,2=IPv6), SOURCE PREFIX-LENGTH, SCOPE PREFIX-LENGTH, ADDRESS }.
  • On query: SCOPE = 0; SOURCE PREFIX-LENGTH + ADDRESS carry the client subnet the resolver chose to reveal (e.g. /24).
  • We validate (I-ECS-SAFE): family ∈ {1,2}; SOURCE ≤ caps (default 24 for v4, 56 for v6); address bits beyond SOURCE zeroed.
  • Geo uses that subnet for LPM (I-ECS) instead of the resolver IP.
  • On response: echo the option with SCOPE PREFIX-LENGTH = the granularity at which the answer is valid (the coarsest prefix that still yields this answer — §4.2 cache-vs-accuracy). SCOPE 0 = answer applies to all subnets (no ECS tailoring).
  • Caching: the resolver keys its cache on (name, type, ECS scope) → the scope we return controls cache fragmentation (principle 10).

8.7 TTL + negative-caching strategy

  • Steady-state TTL: configurable per pool (default 300 s) — balances reactivity vs resolver/auth load (principle 7).
  • During an active failover / unstable health: TTL is shortened (default 30 s) so the eventual-consistency window narrows when it matters (§4.1).
  • TTL floor: a minimum (e.g. 5 s) to prevent pathological re-query storms (I-TTL).
  • Negative caching (RFC 2308): NXDOMAIN/NODATA carry the SOA-minimum TTL (we supply it to #162); a transient all-unhealthy must not be cached as NXDOMAIN long — we prefer I-FAILSAFE (return last-known) over an NXDOMAIN that resolvers cache.
  • Anycast vs DNS reactivity: for latency-critical pools, pair a longer DNS TTL with anycast withdrawal (routing-speed reaction) so the TTL floor does not gate failover (§8.8).

8.8 Anycast / BGP announcement control

  • A set of PoPs announce the same anycast prefix; the routing fabric (modeled by #355, real session by #157) delivers each client to its nearest-by-BGP PoP (catchment).
  • Steering = announce/withdraw: an unhealthy PoP withdraws the prefix → BGP converges → its catchment shifts to the next-nearest live PoP. Reacts at convergence speed (seconds), no TTL floor, but per-PoP, not per-client/per-endpoint (coarse).
  • We emit Announce(prefix, pop) / Withdraw(prefix, pop) intents to a BGP control sink. A real BGP-4 speaker is deferred (§22.2, PhaseDeferred); P8 ships the decision logic + a file/simulated sink + a hook to #157.
  • Hazards: withdrawing a PoP shifts its load onto neighbors → a thundering herd / cascade if a large PoP withdraws (a neighbor now over-capacity). The control plane models catchment load (coarsely) and supports gradual/partial withdrawal.

8.9 Steering-mechanism comparison (the core tradeoff, §2.7)

Mechanism Granularity Reactivity Cost Use when
DNS answer per-resolver / per-ECS-subnet TTL-floored (slow) cheap; cache-amplified by ECS default geo/latency/weighted steering
Anycast withdraw per-PoP (coarse) BGP convergence (~s); no TTL floor needs BGP control; load-shift hazard latency-critical failover; DDoS shedding
HTTP 3xx redirect per-request (precise) instant per request +1 RTT + TCP/TLS to redirector fine control when DNS too coarse
  • No single best mechanism (principle 1). Many real systems layer them: DNS for coarse geo, anycast for fast regional failover, redirect for per-request precision.

8.10 Worked example — latency-based routing via the latency map

  • Goal: steer client network 198.51.100.0/24 to its lowest-latency healthy endpoint among {us-east-1, us-west-2, eu-west-1}.
  • The latencymap holds RUM-aggregated estimates: 198.51.100.0/24 → {us-east-1: 22 ms, us-west-2: 65 ms, eu-west-1: 95 ms} (decayed real-user samples).
  • policy::decide (Latency policy): filter by health (all Healthy) → look up the client network in the latency map → pick us-east-1 (22 ms).
  • Sparse-data fallback: if the client network has no RUM samples, fall back to geoproximity (nearest by great-circle distance) → and emit latency_fallback=geoproximity in the trace.
  • Staleness: samples decay (an endpoint that got slower must lose its old low estimate) → the map is re-aggregated on a window; stale entries below a confidence threshold trigger the geoproximity fallback.
  • Contrast with §8.5 geolocation: geolocation is a static region→pool map (no measurement); latency is measured and adapts to real network conditions — but needs data and is noisier.

8.12 Propagation + consistency model

  • The control plane is the source of truth: it computes a ResolvedPlan (pools, endpoints, current HealthState, latency-map deltas, policy versions) and stamps it with a monotonic generation number G (advanced only by the leader, I-LEADER).
  • Propagation: push G (full or delta) to all edges; each edge applies in order (I-ORDER), atomically swaps its snapshot (I-SNAP), and acks its applied generation.
  • Staleness: the control plane tracks leader_gen − edge_gen per edge; an edge beyond N generations / T seconds is stale (I-PROP) → flagged, re-pushed, possibly quarantined (stop sending it new clients via anycast).
  • Eventual consistency: edges converge to G; during a push, edges may transiently be at G or G−1 (a query reads one consistent snapshot, never a mix — I-SNAP). A split (some edges at a generation that steers away from a dead region, others still at a generation that steers to it) is bounded by the staleness window and observable via per-edge generation telemetry.
  • Why ordered + bounded: an unordered apply could overwrite fresh health with stale (I-ORDER prevents); an unbounded lag could leave an edge steering to a long-dead region (I-PROP bounds it) — both are the difference between a safe failover and a dangerous one (principle 5).

8.13 State machines

  • Endpoint health: Unknown → (k_pass) Healthy ⇄ Degraded ⇄ (k_fail) Unhealthy; any rapid oscillation → Damped(held) (I-DAMP) → decays back.
  • Edge: Booting → Syncing(catching up to leader gen) → Live(within staleness) → {Stale(flagged) | Quarantined}; Live ↔ Stale by the staleness monitor.
  • Control-plane leader: Follower → Candidate → Leader(epoch e) → {Stepped-down | Fenced(stale epoch)} (I-LEADER).
  • Anycast PoP: Announcing ⇄ Withdrawing(unhealthy) ⇄ Drained.

Design principles (§6)

  • Steering is a decision, not a mechanism; mechanisms are pluggable. The policy engine computes which endpoint; DNS/anycast/redirect are interchangeable ways to deliver it. Violation: policy logic baked into the DNS path → can't reuse it for anycast/redirect, can't test it in isolation.
  • The data plane is read-mostly and lock-free; the control plane does the stateful work. Edges answer from an atomically-swapped immutable snapshot (principle 9). Violation: taking a lock per query → tail-latency collapse under QPS, the sub-ms SLO is gone.
  • Stale-but-available beats fresh-but-unavailable. An edge with lagging propagation answers from its last-good snapshot rather than failing. Violation: refusing to answer when behind → a propagation hiccup becomes a global DNS outage (the worst failure mode).
  • Health must be stable, not just fast: consensus + flap damping are mandatory. A single vantage cannot re-steer traffic; an oscillating endpoint is damped. Violation: per-vantage instant re-steer → one broken probe path or a flapping endpoint thrashes global traffic (self-inflicted outage).
  • Propagation is ordered and bounded-stale; never split. Generations apply in order; staleness is bounded + observable; a partial failover is detectable. Violation: unordered/unbounded propagation → some edges steer to a dead region while others don't (split steering — worse than slow).
  • Determinism: same inputs → same decision (modulo a seeded shuffle). The decision engine is a pure function of (policy, context, health, generation, seed) — the oracle property. Violation: nondeterministic decisions → untestable, undebuggable steering ("why did this client get that endpoint?").
  • The TTL is a first-class, policy-controlled output — and an honest one. TTL trades reactivity for cache load; it shortens during failover. Violation: a fixed long TTL → failovers take the full TTL; a fixed short TTL → resolver/auth overload. Pretending TTL doesn't gate reactivity → wrong RTO expectations.
  • Fail-safe, not fail-open or fail-closed blindly: a steering failure defaults to the safest available answer. No health data → return all-configured (last-known) rather than empty. Violation: empty answer on uncertainty → clients get NXDOMAIN/SERVFAIL → total outage from a control-plane wobble.
  • The answer hot path is allocation-light and touches no shared mutable state. Geo/latency/policy lookups read immutable structures; the answer buffer is from a per-task pool. Violation: per-query allocation + shared mutation → GC-like pauses, contention, tail blowup.
  • ECS is honored, sanity-checked, and scope-minimized. Echo the client subnet, validate it (length caps, family), return the coarsest correct SCOPE. Violation: trusting ECS blindly → spoofed-subnet steering abuse + cache poisoning; over-fine scope → cache explosion (§4.2).
  • Observability of every steering decision. Each answer can emit a DecisionTrace: policy path, client location, ECS scope, chosen endpoint, health state, generation, TTL. Violation: opaque steering → "why did this client hit that region?" is unanswerable in an incident.
  • The control plane has one writer per generation (leader + epoch). Only the regional leader advances the propagation generation; epoch fencing rejects a stale leader. Violation: two leaders advancing generations → conflicting global state, split steering (principle 5 broken at the source).
  • Probe load on endpoints is bounded and respectful. A capped probe rate per (endpoint, vantage, interval); shared health, not per-pool re-probing. Violation: unbounded health checks → the GSLB DDoSes its own endpoints (a real outage cause).
  • Correctness anchored to the deterministic policy oracle + RFC conformance. Every decision is checkable against a reference evaluator; every ECS/DNS wire output against the RFC. Violation: no oracle → steering bugs ship silently and manifest as mysterious regional imbalance in production.
