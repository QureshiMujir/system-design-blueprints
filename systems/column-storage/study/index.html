Mental Models & First Principles

MM1 — Arrow buffers are the unit of ownership; record batches are the unit of work. Predicts: every API either takes/returns a batch or operates on a buffer pointer — there is no third granularity. Bug class without it: mixing row-at-a-time and batch-at-a-time code, which boxes values and defeats SIMD. Applied: P1, P3, Phase 4, Phase 6.

MM2 — Memory bandwidth, not instruction count, is the scan bottleneck. Predicts: the win from AVX-512 is bounded by how few bytes you touch, so zero-copy decode and pushdown matter more than clever kernels. Bug class: optimising the kernel while eagerly copying every page. Applied: P2, P5, Scalability Analysis, Phase 5/6.

MM3 — A Parquet file is a structured access path, not a blob. Predicts: the column index, offset index, and Bloom pages let you read the matching data, not the whole file; bytes-read is predictable. Bug class: whole-file scans when the index would have pruned 90% of it. Applied: P5, Phase 5, Phase 9, PF19.

MM4 — Late materialisation turns a query into selection-vector propagation. Predicts: only ProjectOp touches column bytes; filters move bitmaps. Bug class: materialising intermediate tables and burning cache. Applied: P6, Phase 7, Phase 8.

MM5 — Determinism is a property you design in, not test in. Predicts: lock the float summation order once (pairwise) and every lane agrees; you never chase a lane-dependent diff. Bug class: AVX2 and AVX-512 producing different sums on the same input. Applied: P10, I7, I8, Phase 6.

MM6 — The page cache budget and the operator budget are different budgets. Predicts: you can size the cache for I/O amortisation and the operators for working set independently, and neither starves the other. Bug class: OOM under concurrency from conflating them. Applied: P11, Phase 2, §4, PF4.

MM7 — A Bloom "no" is information; a Bloom "yes" is not. Predicts: you prune on "no" and always verify on "yes" — the index never short-circuits a correctness check. Bug class: skipping a page because the Bloom said "yes". Applied: I9, Phase 9, PF33.

MM8 — Statistics are a write-path artefact you trust on read. Predicts: the read path never scans to estimate; it trusts the file (with a hash check) and only recomputes when the file declares stats absent. Bug class: every scan degenerating into a full scan. Applied: P8, I12, Phase 5, Phase 9.

MM9 — Dispatch in one place; the call site is blind to the backend. Predicts: adding a GPU backend is a registry change, not an operator change. Bug class: SIMD-level branches scattered across call sites, making parity untestable. Applied: P4, Phase 6, Stretch (GPU).

MM10 — The smallest engine that teaches the full surface is the right scope. Predicts: dropping transactions, SQL, and distributed joins is what makes the 5–7 month timeline real. Bug class: scope creep into a database. Applied: §1, §2, P9, ADR-23.

Required reading (§5)

general

  • Abadi, Boncz, Harizopoulos, Idreos, Madden — The Design and Implementation of Modern Column-Oriented Database Systems (Foundations and Trends in Databases, 2013). The single best survey; every operator in Phase 5 traces to a paragraph. Applied: Phase 3, Phase 5, Phase 7.
  • Hennessy & Patterson — Computer Architecture: A Quantitative Approach. Cache hierarchy, SIMD, memory bandwidth. Applied: §4 capacity model, Phase 5 kernels.
  • Pavlo — CMU 15-721: Advanced Database Systems (lecture series, treated as a text). Lectures 5–10: storage models, compression, execution, vectorisation. Applied: Phase 2, Phase 5.
  • Graefe — Query Evaluation Techniques for Large Databases (ACM Computing Surveys). The operator-model canon; iterator vs. vectorised. Applied: Phase 6, Phase 7.
  • Drepper — What Every Programmer Should Know About Memory. Alignment, prefetch, NUMA. Applied: §7 invariants (alignment), Phase 1 (page cache), Phase 5.
  • Warren — Hacker's Delight. Bit-packing, zigzag, popcount tricks. Applied: Phase 2 (encodings), Phase 5 (bitmap kernels).
  • Stonebraker et al. — C-Store: A Column-oriented DBMS (VLDB 2005). Read/write store split; projection as physical design. Applied: §2, Phase 4.
  • Boncz, Zukowski, Nes — MonetDB/X100: Hyper-Pipelining Query Execution (CIDR 2005). The "1024-tuple" vector-size finding. Applied: ADR-05, Phase 5.
  • Lemire — Roaring Bitmaps (SP&E 2017). Selection-vector representation above a selectivity threshold. Applied: ADR-06, Phase 6.
  • Pirk, Moerkotte, Madden — Voodoo: A Vector Algebra for Portable Database Performance (VLDB 2017). An algebra below the operator level. Applied: Phase 5, Phase 6.
  • Behm et al. — Photon: A Fast Query Engine for Lakehouse Systems (SIGMOD 2022). Row-to-columnar transition; ablations on vectorisation and prefetch. Applied: Phase 5, Phase 7.
  • Pham et al. — Velox: Meta's Unified Execution Engine (VLDB 2022). Kernel engineering; vector representation; merge-tiny-reads. Applied: Phase 1, Phase 5.
  • Raasveldt & Mühleisen — DuckDB: an Embeddable Analytical Database (SIGMOD 2019). Radix-partitioned hash aggregate. Applied: Phase 5.
  • Apache Arrow — Columnar Format Specification. Validity bitmap, offset buffers, dictionary layout. Applied: Phase 3 (normative).
  • Apache Parquet — File Format Specification + the .thrift schemas. Page index, column index, offset index, Bloom-filter page, dictionary page, statistics. Applied: Phase 4 (normative).
  • Apache ORC — File Format Specification. Streams-of-streams design. Applied: Phase 4 (read-only).
  • arrow-rs (arrow + parquet crates) — the conformance ground truth for Arrow and Parquet. Applied: Phase 3, Phase 4, Phase 12.
  • parquet-mr (Java) and parquet-cpp — cross-implementation Parquet round-trip references. Applied: Phase 4, Phase 12.
  • DuckDB source (src/execution/operator, src/storage) — radix hash aggregate, storage model. Applied: Phase 5, Phase 7.
  • Polars source (polars-core, polars-arrow) — Rust buffer-ownership patterns. Applied: Phase 3.
  • Velox source — operator and vector design. Applied: Phase 5, Phase 7.

Glossary · 44 terms · site-wide glossary

Arrow
: the Apache Arrow columnar format; the in-memory layout used end to end.
Parquet
: the Apache Parquet file format; the on-disk layout read and written.
ORC
: the Apache ORC file format; read-only here.
Record batch
: a contiguous slice of rows across a fixed schema, materialised as a vector of arrays.
Row group
: a horizontal partition of a Parquet file, default ~128 MiB.
Column chunk
: the bytes of a single column within a single row group.
Page
: a sub-unit of a column chunk (~1 MiB); the granularity of compression and the column index.
Dictionary page
: the first page of a dictionary-encoded column chunk, holding the distinct values.
Bloom filter page
: an optional page holding a Bloom filter over the column chunk's values.
Zone map
: per-row-group min / max / null-count statistics in the Parquet footer.
Column index
: per-page min / max statistics; the fast pushdown path.
Offset index
: per-page byte offsets; the prefetch and seek path.
Selection vector
: a bitmap (dense or Roaring) over row indices that survive a filter.
Late materialisation
: producing selection vectors before materialising columns.
Vector size
: rows processed per kernel call; default 4096.
Pushdown
: pushing predicates below the operator boundary into scan, page index, and Bloom filter.
Zero-copy decode
: producing an Arrow array directly over page bytes without copying.
HyperLogLog (HLL)
: a probabilistic distinct-count sketch; here p=14.
Equi-height histogram
: a partition of the value domain into equal-row-count buckets.
Frame-of-reference (FOR)
: encode values as deltas from a per-page reference.
Delta-binary-packed
: Parquet's second-order delta encoding for monotone keys.
Zigzag-varint
: signed→unsigned mapping then LSB-first 7-bit varint packing.
Bit-packing
: packing n values of b bits into a contiguous buffer; LSB-first in Parquet.
RLE/hybrid
: Parquet's run-length / bit-packed hybrid for booleans and dictionary indices.
Radix-partitioned hash aggregate
: partition rows by hash bits, aggregate per partition, spill, merge.
Spill
: writing a partition to disk (Arrow IPC) when it exceeds a memory threshold.
Three-valued logic (Kleene)
: AND/OR/NOT semantics over nullable booleans.
Selectivity
: the fraction of rows surviving a filter.
Arrow IPC
: the Arrow stream/file serialisation; the spill and Flight wire format.
Arrow Flight
: the Arrow gRPC surface for streaming record batches.
DoGet / DoPut / GetFlightInfo
: the Flight RPCs the engine implements.
Iceberg
: a table-format metadata layer over Parquet providing snapshots and schema evolution.
Delta Lake
: an alternative table-format metadata layer over Parquet.
CDC
: change-data-capture; a stream of (op, key, before, after) records.
Physical-plan IR
: the operator-tree input the engine executes (no SQL).
Kernel registry
: the single place runtime SIMD dispatch is decided.
Kernel level
: scalar / AVX2 / AVX-512 / NEON, detected at startup.
Zone-map prune
: skipping a row group whose min/max cannot match the predicate.
Page-index prune
: skipping a page whose min/max cannot match.
Conformance bucket
: a named group of fixtures verified against a reference implementation.
Verdict
: a bucket's outcome: Pass / Fail / Deferred / Empty.
PhaseDeferred
: the typed error marking a legibly-deferred surface.
TPC-H
: the canonical analytical benchmark; targets Q1, Q3, Q6, Q12.
Scatter-gather scan
: the only distributed primitive — split a scan across nodes and merge.
