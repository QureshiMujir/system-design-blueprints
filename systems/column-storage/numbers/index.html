Back-of-Envelope Capacity Model

Derived step-by-step from the §4 System Constraints table.

BE1 — Pages per 256 MiB Parquet file. page_size = 1 MiB ⇒ 256 MiB / 1 MiB = 256 pages per file (per column chunk it is fewer; per file across columns ≈ 256).

BE2 — Row groups per file. row_group = 128 MiB ⇒ 256 MiB / 128 MiB = 2 row groups per 256 MiB file.

BE3 — Rows per row group (lineitem, ~150 B/row uncompressed, 10:1 compressed → 15 B/row on disk). 128 MiB / 15 B ≈ 8.9 M rows per row group on disk.

BE4 — Scan time, Phase-0 (200 MB/s). 256 MiB / 200 MB/s ≈ 1.34 s to read the file body cold; Phase-1 at 1 GB/s ⇒ 0.26 s (M1).

BE5 — Page-decode budget per file. 256 pages × p50 1.5 ms = 0.38 s decode at p50; at p99 12 ms the tail page costs 12 ms — so decode overlaps I/O via prefetch (depth 4).

BE6 — Pushdown win. If a filter matches 7% of pages (Appendix B.1), bytes read ≈ 0.07 × 256 MiB = 17.9 MiB ⇒ scan time ≈ 17.9 MiB / 200 MB/s ≈ 94 ms, under the §4 time-to-first-row 100 ms target.

BE7 — Page cache residence. 256 MiB cache / 1 MiB page = 256 hot pages if all hot, or more cold compressed pages (≈ 2,560 at 10:1) — the cache holds roughly one full file hot or ten files cold.

BE8 — HLL state per file. p=14 ⇒ 2^14 registers × 6 bits ≈ 12 KB/chunk × (columns); for 16 columns × 2 row groups = ≈ 384 KB of HLL state per file (ADR-09).

BE9 — Concurrent scan memory. 64 scans × 256 MiB ceiling = 16 GiB worst case ⇒ a 64-scan node needs ≥ 16 GiB just for operators (the §4 concurrency × M10 ceiling); this is why 64 is the cap.

BE10 — Hash aggregate partitions. 256 radix partitions; spill at 16 MiB/partition ⇒ in-memory aggregate holds up to 256 × 16 MiB = 4 GiB before everything spills — within the per-scan budget only for low cardinality, hence the spill path (Phase 6).

BE11 — FD budget headroom. ≤ 1024 FDs; 64 Flight streams + object-store handles (pooled) leaves ≈ 900 FDs for open files — comfortable for a 2-row-group-per-file layout.

BE12 — Vector dispatch count for a Q6 scan. 8.9 M rows/row group ÷ 4096 vector = ≈ 2,173 kernel dispatches per row group per column — amortising dispatch cost across the batch (ADR-05).
