Subsystem Descriptions

CLI / SDK Clients — untrusted callers. Never touch persistence or crypto internals directly. Every command is versioned and sequence-numbered; SDKs must preserve replay determinism through canonical (deterministic-field-order) serialization.

Transport / RPC Gateway (grpc-control-plane) — terminates transport sessions, validates framing, enforces per-session quotas, normalizes requests into internal command envelopes. This is the primary trust boundary between untrusted callers and trusted runtime components (marked TRUST BOUNDARY in the diagram).

Command Validation Layer (tpm-command-engine) — replay prevention, policy pre-check, authorization checking, command sequencing, session validation, bounded resource enforcement. Rejects malformed or ambiguous requests before any state mutation reaches the trust kernel.

TPM Command Engine — the canonical TPM-inspired command state machine. Commands are deterministic; side-effect ordering is serialized through explicit transaction boundaries in tpm-persistence.

PCR Manager (tpm-pcr) — PCR banks, extension semantics, reset semantics, hashing invariants, replay-safe measurement ordering.

Policy Evaluator (tpm-policy) — composable authorization: PCR predicates, locality constraints, command lineage, session assertions, evaluated fail-closed.

Key Hierarchy Manager (tpm-crypto) — endorsement keys, storage root keys, sealing keys, transient handles, hierarchy ownership, lifecycle transitions.

Secure Persistence Layer (tpm-persistence) — encrypted crash-safe persistence: append-only WAL, integrity-verification trees, monotonic sequence guarantees, replay validation. Marks the persistence boundary: nothing below this line is visible to a client without going through integrity verification.

Crypto Execution Engine (tpm-crypto) — all cryptographic operations, isolated worker pool, deterministic audit instrumentation.

Enclave Runtime Scheduler (enclave-runtime) — software-defined isolation contexts, cooperative scheduling, memory quotas, execution accounting, cancellation. Marks the concurrency boundary: task state for one enclave context is never visible to another.

Event Log / Replay (eventlog-engine, replay-engine) — deterministic execution records for replay-based debugging and conformance validation. The system's only queue that is explicitly unbounded-in-retention (bounded by disk, not by count) because forensic replay depends on it.

Telemetry Stack (telemetry-stack) — metrics, traces, structured logs, crash dumps, replay snapshots, queue-depth statistics, latency histograms. An external interface consumed by Prometheus/OTel collectors outside the trust boundary.

Attestation / Verification (attestation-service) — signed attestation evidence, trust-chain validation, PCR-lineage verification, quote API. The system's other external interface: remote verifiers call in over gRPC and receive only signed, replayable evidence — never raw state.

8. Domain Model — TPM Trust State & Command Protocol

Core Entities

struct TPMContext
  hierarchy_roots: HierarchyRoots,
  pcr_banks: Vec<PCRBank>,
  nv_indexes: BTreeMap<NvIndex, NvSlot>,
  monotonic_counters: BTreeMap<CounterId, u64>,
  active_sessions: BTreeMap<SessionId, PolicySession>,
  transient_handles: BTreeMap<TPMHandle, HandleRecord>,
  replay_metadata: ReplayMetadata,

Represents the global mutable trust state, owned exclusively by the command-execution actor in tpm-core (P3). Never cloned; snapshots serialize a point-in-time view, they do not alias it.

struct EnclaveContext
  enclave_id: EnclaveId,
  scheduler_state: SchedulerState,
  memory_quota: QuotaBytes,
  execution_lineage: ExecutionLineage,
  attestation_state: AttestationState,

Represents isolated execution state for one enclave (I9). One EnclaveContext per scheduled tenant; never shared across contexts.

PolicySession — composable authorization evaluation state (§17); EventRecord — append-only immutable mutation record (§16, I7).

TPM Command Envelope (wire layout)

struct CommandEnvelope
  version: u16,
  sequence_number: u64,
  command_code: CommandCode,
  authorization_area: AuthArea,
  payload: Bytes,
  checksum: [u8; 32],

version gates decode compatibility (P6, P12). sequence_number is the replay-ordering key (I1, I4). checksum is CRC32C for framing integrity, separate from any cryptographic MAC inside payload.

Command Lifecycle

Client -> Gateway -> Validation -> Policy Evaluation
       -> Command Execution -> Persistence Commit
       -> Event Emission -> Response Serialization

Every arrow is a synchronous handoff within one command's causal chain; no stage may reorder past another for the same sequence_number (I1, I4).

PCR Extension Flow

new_pcr = HASH(old_pcr || digest) — append-only lineage, replay-deterministic, collision- resistant lineage tracking (I2). HASH is the PCR bank's configured algorithm (SHA-256 or SHA-384 bank, §15); banks never mix algorithms mid-lineage.

State Machine

State Meaning Exit Conditions
INIT bootstrap, integrity verification running integrity verification complete → READY
READY accepting commands shutdown signal → INIT (next boot); corruption → QUARANTINED
RECOVERY WAL replay in progress replay success → READY; replay divergence → QUARANTINED
DEGRADED partial subsystem failure, reduced command set operator recovery → READY
QUARANTINED corruption detected manual intervention only; no automatic exit

Failure Path Example — Malformed Command

  1. framing validation fails at the Command Validation Layer;
  2. event logged (EventRecord, immutable, I7);
  3. replay artifact generated (P4);
  4. metrics incremented (protocol_frame_rejected_total);
  5. connection quota adjusted (repeated malformed frames tighten the session's quota);
  6. response rejected with a structured error code, never a partial response.
