Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — Hardware-Backed Enclave Instead of Software Simulation

+--------------------+       +---------------------------+
| CLI / SDK Clients  | ----> | Hardware Enclave (SGX/SEV)|
+--------------------+       | page-table isolation      |
                             | CPU-attested measurement  |
                             +---------------------------+

Wins in: production confidential computing where the isolation guarantee must survive a fully compromised host OS/hypervisor. Real system: Intel SGX (via Gramine) / AWS Nitro Enclaves. Rejected here because §1 explicitly scopes this project as a software simulation for portability across dev machines without SGX/SEV hardware and to keep the trust-boundary reasoning teachable without a hardware dependency (§2) — the entire point is reproducing the semantics in software, per §1's non-goals.

Alt B — OS-Process-Per-Enclave Instead of Cooperative Scheduling

+------------------+     fork/seccomp    +------------------+
| Scheduler        | ------------------> | Sandboxed Process |
| (dispatch only)  |                     | (1 per enclave)   |
+------------------+     <-- IPC -->     +------------------+

Wins in: workloads needing true CPU-level fault isolation (a crashing enclave cannot corrupt another's memory even via a scheduler bug). Real system: seccomp-sandboxed worker-process models (e.g. Chromium's process-per-site-instance architecture). Rejected here because 512 concurrent OS processes cannot hit the §4 250,000 context-switches/sec target (§28 M8) — process-level context switches cost orders of magnitude more than the in-process cooperative switches ADR-08 requires.

Alt C — Consensus-Replicated Persistence Instead of Single-Writer WAL

+--------+     Raft log replication     +--------+
| Node A | <---------------------------> | Node B |
+--------+                               +--------+
     \                                       /
      \--------------- Node C --------------/
      (majority-write quorum before commit ack)

Wins in: deployments needing horizontal write scaling and multi-region durability beyond a single persistence volume's failure domain. Real system: TiKV / etcd (Raft-based replicated log). Rejected here because §29 fixes persistence as single-writer by design (ADR-06) — a Raft round trip adds one-to-several RTTs to every commit, which would blow the §4 40 ms p99 command-latency budget for this project's intra-datacenter deployment model (§1); §35 tracks distributed attestation federation, the one place multi-node coordination is deferred rather than rejected outright.
