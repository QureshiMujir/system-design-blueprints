3.2 Trust Boundary

  • Attacker-controlled keys/node names: crafted keys can pin one node under a fixed-seed XxHash64 → mitigate with SipHasher64 { k0, k1 } (random seed, externally unpredictable, still deterministic per seed).
  • Concurrency boundary: reads (locate/locate_n) lock-free over an arc-swap snapshot; writes (add/remove) serialized under RwLock — readers never block writers, writers never block readers.
  • No-persistence invariant: ring is fully derived from the node+weight list; crash-restart replays membership (no WAL/disk I/O).

3.3 Component Descriptions

chr-core — Placement + Hasher64. Defines the uniform Placement trait (all four strategies impl it) and Hasher64 (XxHash64 default, SipHasher64 keyed). NodeId(u64) opaque identity, Weight(u32) capacity, PlacementError {NoNodes,BadWeight,CapacityExceeded} (locate returns None, never panics). Zero deps beyond alloc; every strategy crate depends on it. (Types: §11.1.)

HashRing (chr-ring). BTreeMap<u64,NodeId> over [0,2⁶⁴); each node contributes V·weight tokens hash(name++replica_idx). locate = range(key_token..).next().or first(), O(log nV). Add/remove splice V·weight tokens incrementally. Invariant ring.len() == Σ weight_i·V (INV-11). Phases 2/3/5.

PreferenceList walk (chr-ring). locate_n walks clockwise dedup'ing physical nodes (and optionally zones via HashMap<NodeId,ZoneId>); first-N replicas span N distinct zones. Always distinct physical NodeIds (INV-3/INV-4). Phase 4.

BoundedRing (chr-ring). Wraps HashRing + per-node load counter; if successor ≥ ceil(c·avg) forward clockwise to next non-full node (c≈1.25; CapacityExceeded if all full). Guarantee max_load ≤ ceil(c·total/n) (INV-5). Phase 6.

Rendezvous / WeightedRendezvous / SkeletonHrw (chr-rendezvous). Flat HRW: score = hash(node++key), owner=argmax, ties by NodeId; removing X re-homes only X's keys (argmax monotone) — perfectly minimal but O(n). Weighted: -w/ln(h01) routes proportionally. Skeleton: fanout-f hierarchy → O(log_f n) (PhaseDeferred("§8.4") for n>10k tuning). Phases 7/8.

JumpHash (chr-alt). jump_hash(key,num_buckets)->u32, Lamping-Veach, O(ln n) time/O(1) memory. Ordinal buckets 0..n-1, tail-only add/remove. No NodeId — chr-cli adapter maps ordinals. Phase 9.

Maglev (chr-alt). Maglev { lookup: Vec<i32>, table_size }, prime M; per-backend offset=hash(b)%M, skip=hash2(b)%(M-1)+1 permutation-fill; lookup[hash(key)%M] O(1). Near-perfect balance, ~1/n disruption per backend change. Phase 10.

ModuloHash (chr-alt). hash(key)%n; O(1)/O(1)/zero-build baseline. ~(n-1)/n remapped per change — chr-sim baseline only, never production.

chr-sim — analysis harness. Drives any Placement over synthetic keys → DistributionReport (peak-to-mean/Gini/std-dev) + DisruptionReport (moved vs theoretical 1/N); churn simulator + hot-spot detector + cross-strategy Markdown table. Phase 11.

chr-cli — chring binary. Subcommands locate/add/remove/distribute/churn/compare/bench; --strategy ring|hrw|jump|maglev|bounded; --format json|table|csv; bench runs Criterion. Phases 12/13.

8. Domain Model — Placement Algorithms, Ring Geometry, Disruption Math

8.1 Placement Problem Statement

Objectives: ownership locate(k)->NodeId (deterministic, total); replication locate_n(k,N) (N distinct, preference-ordered); balance load ≈ K/n (min peak-to-mean/Gini/std-dev); minimal disruption (fewest keys move per change); monotonicity (surviving-node keys never move to another surviving node); spread (uniform, no hot shard). Metrics hierarchy: disruption fraction → peak-to-mean → Gini → std-dev, all on one corpus via chr-sim.

8.2 Ring Model — [0, 2⁶⁴) Token Circle

HashRing.ring: BTreeMap<u64, NodeId> over a circle wrapping at 2⁶⁴. token = hash(name ++ replica_idx_le). locate(key): t=hash(key); ring.range(t..).next().or_else(ring.first_key_value) (first token ≥ t, wrapping to min).

Worked — 3 nodes, 1 token each (N1=0x1A00, N2=0x5500, N3=0xCC00): "foo"→0x3F00 → first ≥ is 0x5500 → N2; "bar"→0xEE00 → wraps → 0x1A00 → N1.

8.3 Virtual Nodes — Load Smoothing

V tokens/node (default 150) cut load variance: token gaps are exponential, sum of V gaps → variance ∝ 1/V → std-dev ∝ 1/sqrt(V). Normalized std-dev / peak-to-mean (n=10): V=1 → ~1.0 / 3–10×; V=50 → ~0.14 / 1.3×; V=150 → ~0.08 / 1.1×; V=500 → ~0.045 / 1.05×. Weighted: Weight(w) → V·w tokens (hash(name ++ replica_idx), i∈0..V·w) = proportional load share.

8.4 Preference List Walk — Replication with Zone Awareness

Goal: locate_n(key, N=3) returns N distinct physical nodes for fault-isolated replication.

Algorithm (clockwise walk from key's primary token):

Iterate ring.range(key_token..).chain(ring.range(..)) (clockwise wrap). Per candidate token → physical node: skip if node ∈ seen_nodes; skip if zone(node) ∈ seen_zones AND unused zones remain (zone-aware mode); otherwise push to result, mark node+zone seen. Stop when result.len() == N or ring exhausted. Split: result[0] → primary, rest → replicas.

Step Condition Action
Visit token → node node already in result Skip (vnode of chosen physical node)
Visit token → node zone already covered AND unused zones remain Skip (rack-aware dedup)
Visit token → node node/zone both new Append to result; mark seen
result.len() == N — Return PreferenceList
Ring exhausted result.len() < N Return partial list (INV-3)

Worked — 6 nodes / 3 zones, N=3, sorted tokens 0x10 N1(A), 0x20 N3(B), 0x30 N1(A)·skip, 0x40 N5(C), 0x50 N4(B)·skip, 0x60 N2(A)·skip, 0x70 N6(C)·skip. From key_token 0x05 → [N1, N3, N5] (one per zone) → PreferenceList { primary: N1, replicas: [N3, N5] }. If zones < N, fall back to node-distinct-only.

8.5 Disruption Math — Modulo vs Consistent Hashing

Modulo (hash(k)%n, n→n+1): a key stays iff hash(k)%n == hash(k)%(n+1), probability ≈ 1/(n+1) → fraction moved = n/(n+1) ≈ 1 − 1/n (near-total reshuffle).

Consistent hashing: adding node M between tokens A,B reassigns only keys in arc (A,B] (former owner of B → M); expected arc = 1/n of ring → fraction moved ≈ 1/n (the minimum). Theoretical floor: any K→n mapping must move ≥ K/(n+1) on add (pigeonhole); consistent hashing achieves it.

Before/after — adding N4 (3-node ring above): key 0x0500 moves N1→N4 (new token 0x0300); 0x2000/0x5800/0xDD00 stay on N1/N2/N3. Only the arc (0xCC00, 0x0300] (wrapping) moves to N4. DisruptionReport fields: §11.5.

8.6 HRW (Rendezvous) — Score Function and Top-N

score(node, key) = hash(node.0.to_le_bytes() ++ key); locate = argmax (ties by lower NodeId); locate_n(N) = partial-sort top-N.

Worked — 4 nodes, "session-xyz" with scores N1=0xF3.._0001, N4=0xD1.._0004, N2=0xA8.._0002, N3=0x55.._0003 → locate→N1, locate_n(2)→[N1, N4].

Disruption on remove(N1): only keys where N1 was argmax reassign (to next-highest score); fraction = load(N1)/K ≈ 1/n — perfectly minimal. Tradeoff: O(n) per lookup; SkeletonHrw for n > ~1000.

8.7 Weighted Rendezvous + Skeleton

WeightedRendezvous: h01 = hash_to_unit_f64(node,key) ∈ (0,1); score = -weight / h01.ln(). Higher weight → larger expected score → proportional keys; maximizing -w/ln(U) gives load ∝ w (Thaler-Ravishankar).

SkeletonHrw: fanout-f virtual hierarchy (f=8); score the f children of the winning parent per level, depth log_f(n) → O(f·log_f n) ≈ O(log n) vs flat O(n). Slight imbalance; fanout trades accuracy vs speed.

8.8 Jump Consistent Hash — Lamping-Veach

O(1) memory, O(ln n) time; the LCG recurrence is in §5.4. Worked trace — key=42, num_buckets=5: b walks −1→0 (j=1), →1 (j=3), →3 (j=4), exits when j=7>5 → bucket 3.

Constraint — ordinal buckets 0..n-1: add = increment n (append bucket n); remove = only the last bucket. No arbitrary middle removal, no non-contiguous ids. Use: stateless LB indexed 0..n-1 with tail-only append/trim.

8.9 Maglev Hashing — Lookup Table Construction

n backends, prime M (default 65537, M ≫ n). Per-backend: offset=hash(name)%M, skip=hash(name++"#")%(M-1)+1, perm(i,j)=(offset+j·skip)%M. Round-robin fill (illustrative):

lookup=[-1;M]; next=[0;n]; filled=0
while filled<M: for i in 0..n:
    c=perm(i,next[i]); while lookup[c]!=-1 { next[i]+=1; c=perm(i,next[i]) }
    lookup[c]=i; next[i]+=1; filled+=1; if filled==M break

Worked — M=7, 3 backends B0:(3,4), B1:(0,2), B2:(1,5): round 1 claims 3,0,1; round 2 (skipping taken) 4,2,6; round 3 fills 5 → [B1,B2,B1,B0,B0,B0,B2]; lookup[hash%7] O(1). Disruption per backend change: ~M/n slots → ≈ 1/n.

8.10 Bounded-Load Consistent Hashing

Capacity cap per node: max_load(node) <= ceil(c * avg_load) where c = capacity_factor (default 1.25), avg_load = total_keys / num_nodes.

BoundedRing forwarding (algorithm): Compute the clockwise successor as in plain HashRing::locate. If that node's load < ceil(c * avg), increment its counter and return it. Otherwise walk to the next distinct physical node clockwise and repeat. A circuit-breaker terminates the walk when all ring nodes have been visited once, returning PlacementError::CapacityExceeded. Signature: fn locate(&mut self, key: &[u8]) -> Result<NodeId, PlacementError> — &mut self because locate increments the load counter.

Guarantee: max_load ≤ ceil(c·total/n) — if all were full, total load would exceed c·total (contradiction). Disruption: ~c·(1/n), slightly above plain ring (some keys forward past their successor). c tradeoff: 1.0 = perfect balance / many hops; 1.25 = 25% over avg / rare forwarding; 2.0 = 2× avg / very rare.

8.11 Edge and Degenerate Cases

  • Single node (ring/HRW/bounded): locate→that node; locate_n(N>1)→[node] (no panic). All keys on one token (ring): bad hasher/degenerate keys, Gini→1.0. Remove last node: empty → None/NoNodes. Weight(0): BadWeight, node invisible. N > num_nodes: return all distinct, shorter list. Jump num_buckets=0: NoNodes. Maglev M<n: CapacityExceeded (M prime, ≫ n). Same-zone only: walk falls back to node-distinct. Token collision (~n²/2⁶⁴): PlacementError or last-write-wins by NodeId. Concurrent add+locate (BoundedRing): load is a per-epoch snapshot, stale ≤ one epoch; arc-swap keeps readers consistent.
