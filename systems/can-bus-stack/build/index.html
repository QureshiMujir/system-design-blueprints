⬜ Phase 1 — Frame model + CAN IDs + DLC/length mapping + field layouts §13

Objectives
  • Implement can-frame: CanId (11/29-bit), Frame, FrameKind, FrameFormat, Dlc with exact classical + FD length mapping.
  • Encode/decode the logical field layout of standard and extended frames (field order + widths), independent of bit-level stuffing/CRC (those land in Phase 2).
Deliverable
  • can-frame constructs/validates classical + FD frames; emits canonical field layout + can-utils text form; unit tests pass.
Acceptance
  • 16/16 DLC codes map correctly for both formats (vector-checked).
  • Illegal frames rejected with the precise FrameError.
  • can-utils-format string round-trips (parse(format(f)) == f) for a fixture set.
  • no_std build clean.
Fixtures
  • dlc_classical.json, dlc_fd.json — DLC↔len for all codes; expected lengths.
  • id_boundary.json — min/max/over-range IDs; expected accept/reject.
  • frame_text_roundtrip.json — 123#ABCD, 12345678#... (extended), FD 123##1... forms.
  • Malformed: frame_bad_len.json (classical 9, FD 13), remote_with_data.json.
Pitfalls
  • CAN FD DLC table off-by-one — DLC 9→12 bytes, not 9; manifests as wrong payload length downstream; debug by asserting FD_LEN against the spec table; signal: data truncation/overrun in Phase 2.
  • Extended ID bit-split (ID-A 11 / ID-B 18) — composing 29 bits in the wrong order breaks arbitration; verify against worked example; signal: arbitration picks wrong winner.
  • RTR vs SRR confusion in extended frames — SRR sits at the standard-RTR position and is recessive; mixing them inverts arbitration tie-break; debug with bit-layout diff.
  • Signedness/endianness of ID — IDs are unsigned MSB-first on the wire; a little-endian copy corrupts arbitration; assert byte order.

⬜ Phase 2 — Bit encoding: NRZ, dynamic bit stuffing/destuffing, CRC15/CRC17/CRC21 §14

Objectives
  • Implement can-phys encoding: serialize a Frame's field layout into a BitBuffer, apply NRZ + dynamic bit stuffing, compute and append the correct CRC, and the inverse (destuff + verify) on RX.
  • Provide CRC15 (classical), CRC17/CRC21 (FD) primitives with verified bit order.
Deliverable
  • Frame ⇄ stuffed bit-stream round-trip with correct CRC for classical + FD; CRC primitives pass known-answer vectors.
Acceptance
  • stuff∘unstuff identity holds over ≥1e6 proptest cases.
  • CRC15/17/21 match generated known-answers and python-can/can-utils for shared frames (differential).
  • ≤5 consecutive identical bits in stuffed output (property-checked).
  • Decode rejects corrupted CRC and malformed stuffing with precise errors.
Fixtures
  • crc15_kat.json, crc17_kat.json, crc21_kat.json — known-answer (input bits → CRC).
  • stuff_roundtrip.json — inputs with 4/5/6-run boundaries; expected stuffed bits.
  • fd_stuffcount.json — data lengths → (count, parity).
  • Malformed: stuff_six_identical.json (expect StuffError), crc_corrupt.json (expect CrcError), truncated_frame.json.
Pitfalls
  • CRC bit order / reflection — CAN CRC is MSB-first, non-reflected; using a reflected/table-driven CRC from another protocol yields wrong values; debug with single-bit input KATs; signal: every frame fails CRC against oracle.
  • Stuffing the wrong region — stuffing must cover SOF→CRC sequence but NOT CRC delimiter/ACK/EOF; over/under-stuffing desynchronizes the decoder; debug by marking field boundaries in the trace.
  • Off-by-one in stuff run length — inserting after 6 not 5 (or counting the stuff bit toward the next run incorrectly); manifests as occasional 6-identical on wire; property test the boundary.
  • FD fixed stuff vs dynamic stuff overlap — FD uses dynamic stuffing up to the stuff-count field, then fixed stuff bits in the CRC; mixing rules corrupts FD CRC; isolate by frame format.
  • Stuff-count parity/Gray coding — wrong Gray code or parity bit fails FD form check; verify against fd_stuffcount.json.
  • CRC computed over stuffed vs unstuffed bits — classical CRC is over de-stuffed bits; FD CRC includes fixed stuff bits; getting the inclusion wrong fails interop; assert per format.

⬜ Phase 3 — Bit-timing engine §15

Objectives
  • Implement can-phys::timing: compute nominal bit time from prescaler + segments, the sample point, SJW resync windows, hard sync on SOF, and resynchronization on edges — all in integer time quanta.
Deliverable
  • A timing engine that yields correct NBT/sample-point for standard configs and resynchronizes a skewed node back into lock within SJW; default tables for 125k/250k/500k/1M.
Acceptance
  • Computed sample points match CiA tables within rounding for the default configs (vector-checked).
  • A node with ±max-tolerance skew stays synchronized over a long frame (no bit error) in the simulator.
  • validate() rejects sjw>ps2 and out-of-range segments.
Fixtures
  • timing_defaults.json — (rate, clock) → (BRP, prop, ps1, ps2, sjw, sample_point).
  • sample_point.json — segment sets → expected permille.
  • resync.json — edge positions → expected PS1/PS2 adjustment.
  • Malformed: timing_invalid.json (sjw>ps2, zero phase seg).
Pitfalls
  • Sample-point miscalculation — integer rounding errors shift the sample point; sampling too early/late causes intermittent bit errors only at certain bit patterns; debug by logging sample TQ vs edge; signal: errors correlate with data content.
  • Resync direction sign error — lengthening PS2 instead of PS1 (or vice versa) drives nodes out of lock; verify against resync.json.
  • SJW clamp omitted — applying full phase error instead of min(e, sjw) over-corrects and oscillates; assert clamp.
  • Hard sync vs resync confusion — hard-syncing mid-frame on a stuff-bit edge corrupts timing; only SOF/idle edges hard-sync; gate by controller state.
  • TQ granularity mismatch — stepping the bus at bit granularity while modeling resync hides timing bugs; run timing-sensitive vectors at TQ granularity.

⬜ Phase 4 — Virtual bus simulator (bit-accurate, multi-node, non-destructive arbitration) §16

Objectives
  • Implement can-bus: a deterministic, bit-accurate, multi-node medium where bus_bit = AND(all node drives), reproducing real non-destructive bitwise arbitration, the ACK slot, error-frame globalization, and providing error-injection + bit-trace + replay.
Deliverable
  • A simulator that runs ≥2 controllers on a shared bus, resolves arbitration correctly, lets a winner transmit while losers receive, supports fault injection, and produces a replayable bit-trace.
Acceptance
  • Two-node arbitration: lower ID always wins; loser receives the winner's frame; matches arbitration/*.json outcomes.
  • N-node (≥8) arbitration: exactly one winner = global min priority key, deterministic across runs with same seed.
  • Replay of a recorded trace reproduces every bus bit exactly.
  • Fault injection produces the expected error frames downstream (validated in Phase 6).
Fixtures
  • arbitration/two_node.json, arbitration/n_node.json — node IDs → winner, loser set, per-bit bus trace.
  • arbitration/std_vs_ext_same_base.json — standard wins over extended at SRR/IDE.
  • arbitration/data_vs_remote.json — data wins over remote at RTR (same ID).
  • replay/golden_run.jsonl — a recorded multi-frame session for replay regression.
  • Malformed/injection: inject/force_bit.json, inject/drop_ack.json.
Pitfalls
  • Inverted wired-AND — using OR or mapping dominant=1; arbitration picks the highest ID; debug by asserting bus_bit(dominant,recessive)=dominant; signal: every arbitration outcome inverted.
  • Reading vs sampling order — a node must sample the resolved bus bit, not its own drive; feeding back the wrong value lets a loser think it won; debug with per-node sampled-vs-drove trace.
  • Nondeterministic node iteration — using a HashMap for nodes randomizes order and, with any tie in scheduling, breaks reproducibility; use an ordered Vec.
  • Off-by-one in fault step scheduling — fault applied one bit early/late; verify against inject/*.json expected step.
  • Idle detection threshold — stopping at <11 recessive bits can cut a frame's EOF/IFS; require the spec idle run before declaring idle.

⬜ Phase 5 — Data-link controller FSM (TX/RX pipeline, ACK, IFS) §17

Objectives
  • Implement can-ctrl: the controller state machine that drives/samples bits via the HAL, runs TX (arbitrate→data→CRC→ACK-wait→EOF→IFS) and RX (SOF→sample→destuff→decode→CRC→ACK) pipelines, performs bit-monitoring during arbitration, asserts the ACK slot on valid RX, and enforces inter-frame space.
Deliverable
  • Controllers that transmit, win/lose arbitration, receive and ACK valid frames, retransmit on ACK error, and honor IFS — end-to-end over the virtual bus.
Acceptance
  • TX→RX delivery: a frame transmitted by node A is received intact (RxComplete) by node B with matching Frame.
  • Arbitration loss handled: loser emits ArbitrationLost, then RxComplete of the winner, then auto-retransmits.
  • ACK: a frame with ≥1 receiver gets a dominant ACK; sender sees no ACK error. Single-node (no receiver) → ACK error + retransmit.
  • IFS enforced: no SOF within <3 recessive bits post-EOF.
Fixtures
  • ctrl/tx_rx_basic.json — frame in → frame out + events.
  • ctrl/arb_loss_retransmit.json — two TXers; loser's retransmit observed.
  • ctrl/ack_error_single_node.json — no receiver → ACK error → retransmit count.
  • ctrl/ifs_gap.json — measured inter-frame gap ≥3 recessive.
  • Malformed: ctrl/form_error_eof.json (corrupted EOF), ctrl/rx_during_arb.json (mid-frame RX switch).
Pitfalls
  • Bit-monitoring enabled in ACK slot — the transmitter drives recessive in the ACK slot expecting receivers to override with dominant; treating that as a bit error is wrong; exempt arbitration + ACK slot from bit-error checks; signal: spurious bit errors on every successful frame.
  • Field-width tracking after dynamic destuff — counting stuff bits toward field widths slices fields wrong; track raw (destuffed) bit position separately; debug with field-boundary trace.
  • Arbitration window boundary — bit-monitoring for arbitration must stop exactly at the end of the arbitration field (after IDE/RTR per format); mis-bounding lets data bits be treated as arbitration; verify per format.
  • Auto-retransmit storm — retransmitting immediately without IFS or on a permanently-NAKing bus floods; enforce IFS + respect error-passive suspend; signal: bus saturated by one node.
  • RX-mid-frame switch state — when losing arbitration, the controller must reuse already-sampled arbitration bits as the start of the received frame, not restart at SOF; debug by checking the decoded winner ID equals the actual winner.
  • DLC>data desync — using DLC code directly as byte count for FD (9≠9 bytes) slices data wrong; use Dlc::len(format).

⬜ Phase 6 — Error management (error frames, TEC/REC, error states, recovery) §18

Objectives
  • Implement can-err: TEC/REC counters with exact ISO 11898-1 increments/decrements, the Error-Active/Error-Passive/Bus-Off state machine, active/passive error-frame and overload-frame generation, error-frame globalization through the bus, and bus-off recovery after 128×11 recessive bits.
Deliverable
  • A fault-confinement subsystem: nodes count errors, transition Active→Passive→Bus-Off exactly per spec, emit correct error/overload frames that globalize, and recover from bus-off after the mandated idle.
Acceptance
  • Counter math matches spec for a scripted error sequence (vector-checked at each event).
  • State thresholds exact: 127→128 enters Passive; 255→256 enters Bus-Off.
  • Active error flag globalizes: all receivers bump REC on the injected error.
  • Bus-off recovery occurs after exactly 128×11 recessive bits; counters zeroed.
Fixtures
  • fault/tec_sequence.json — events → TEC/REC after each, expected state.
  • fault/enter_passive.json, fault/enter_busoff.json — threshold crossings.
  • fault/error_frame_globalize.json — injected error → all-node REC deltas + bus trace.
  • fault/busoff_recovery.json — recovery timing (128×11 recessive).
  • fault/overload_frame.json — dominant in IFS → overload frame.
  • Malformed: fault/passive_error_flag.json (passive node's recessive flag).
Pitfalls
  • TEC/REC edge transitions off-by-one — using >128 instead of ≥128, or decrementing below 0; manifests as state flapping at boundaries; debug by logging counter+state each event; verify against tec_sequence.json.
  • Error flag not violating stuffing — if the error flag is treated as normal data and stuffed, it won't globalize; the error flag must be 6 identical dominant bits that intentionally break the stuffing rule; signal: errors stay local.
  • Receiver REC over-increment — incrementing REC by 8 in cases that warrant +1 (or vice versa) drives nodes passive too fast/slow; encode the specific spec cases precisely.
  • Bus-off recovery counter resets — any dominant bit resets the 11-recessive run; forgetting to reset means premature recovery; debug with recessive-run trace.
  • Passive vs active flag selection — an error-passive node emitting a dominant (active) flag is a spec violation and can dominate the bus; gate flag type strictly on state; signal: a faulty node never softens.
  • Overload vs error frame confusion — overload frames don't change TEC/REC; counting them as errors drives false bus-off; separate the paths.

⬜ Phase 7 — CAN FD extensions (FDF/EDL, BRS, ESI, FD CRC, fixed stuff bits, extended DLC) §19

Objectives
  • Implement can-fd: FD frame fields (FDF/EDL, res, BRS, ESI), the extended DLC table, fixed stuff bits + stuff-bit count, CRC17/CRC21 selection, and the bit-rate switch at BRS — integrated into the controller and simulator.
Deliverable
  • FD frames (0–64 bytes) encode/decode with correct DLC, fixed stuffing, stuff count, CRC17/21, and BRS bit-rate switching; coexist with classical nodes per configured tolerance.
Acceptance
  • All FD DLC codes (9–15 → 12..64 bytes) round-trip; 64-byte frame correct.
  • CRC17 used ≤16 bytes, CRC21 >16; matches FD KAT vectors + python-can.
  • Stuff-bit count + parity correct for every length (vector-checked).
  • BRS frame: data phase runs at data-rate TQ; nominal restored at CRC delimiter; deterministic timing.
  • ESI set correctly per transmitter state.
Fixtures
  • fd/dlc_table.json — all codes → bytes.
  • fd/crc17_kat.json, fd/crc21_kat.json — FD CRC known-answers (incl. fixed stuff bits).
  • fd/stuffcount.json — length → (count, parity, Gray code).
  • fd/brs_switch.json — BRS frame bit-timing transitions (TQ-level).
  • fd/esi.json — error-passive transmitter → ESI recessive.
  • Malformed: fd/bad_stuffcount.json (parity error), fd/classical_node_on_fd.json (classical errors on FD).
Pitfalls
  • CRC17/CRC21 boundary at 16 bytes — using CRC17 for 20 bytes; off-by-one on the ≤16 boundary; verify with 16- and 17-byte vectors; signal: FD frames >16B fail CRC.
  • Fixed vs dynamic stuff overlap — dynamic stuffing must end before the CRC field's fixed stuffing begins; overlapping rules corrupt the CRC region; mark the transition bit explicitly.
  • Stuff-count Gray/parity — wrong Gray sequence or parity bit; the receiver rejects valid frames; verify against stuffcount.json.
  • BRS switch timing point — switching at the BRS bit start vs its sample point; the spec switches after the sample point; mis-timing shifts the whole data phase; debug with TQ-level trace.
  • CRC includes fixed stuff bits (FD) but classical CRC does not — applying classical's rule to FD fails interop; gate by format.
  • ESI semantics — ESI reflects the transmitter's error state at transmission, not the receiver's; setting it from the wrong node corrupts diagnostics.

⬜ Phase 8 — Acceptance filtering + mailboxes + Transceiver HAL trait §20

Objectives
  • Implement can-filter (mask/range/list filters, RX FIFO mailboxes, TX priority queue, overrun policy) and can-hal (the Transceiver trait with the virtual impl bound to can-bus; SocketCAN/hardware impl stubbed PhaseDeferred).
Deliverable
  • A filter bank + mailbox layer routing received frames and ordering transmissions, plus a clean Transceiver seam with a working virtual impl and a documented deferred SocketCAN stub.
Acceptance
  • Mask/range/list filters accept/reject exactly per filter/*.json.
  • Mailbox overrun policies behave correctly (drop-oldest/newest/overflow flag) under burst.
  • TX priority ordering: lower-ID frame transmitted before higher-ID when both queued.
  • Controller compiles/runs generically over Transceiver; virtual impl drives the bus identically to Phase 5.
  • SocketCAN stub returns the PhaseDeferred marker; no real socket used.
Fixtures
  • filter/mask.json, filter/range.json, filter/list.json — id → accept/reject.
  • filter/extended_vs_standard.json — IDE-aware matching.
  • mailbox/overrun_dropoldest.json, mailbox/overrun_overflow.json.
  • txqueue/priority_order.json — queued IDs → transmission order.
  • Malformed: filter/empty_bank.json (accept-all vs reject-all policy documented).
Pitfalls
  • Mask polarity — 1 = "must match" vs "don't care" varies by hardware convention; pick one (1=care), document, and test; signal: filters accept everything or nothing.
  • Standard/extended ID width in mask — applying an 11-bit mask to a 29-bit ID (or vice versa); separate by extended flag; debug with mixed-format vectors.
  • TX priority inversion — FIFO instead of priority-ordered TX queue lets a low-priority frame block a high-priority one inside the node (the bus arbitrates between nodes, but intra-node order matters); use the priority queue.
  • Overrun silent drop — dropping frames without a counter hides loss; always increment overrun_count and expose it.
  • Filter ordering ambiguity — overlapping filters routing to different mailboxes; define first-match-wins and test.

⬜ Phase 9 — ISO-TP transport (ISO 15765-2) §21

Objectives
  • Implement can-isotp: SingleFrame/FirstFrame/ConsecutiveFrame/FlowControl PDUs, block size (BS) + separation time (STmin) flow control, normal/extended/mixed addressing, the N_As/N_Bs/N_Cs (sender) and N_Ar/N_Br/N_Cr (receiver) timers, padding, and fixed-capacity reassembly with strict sequence checking.
Deliverable
  • A transport that segments/reassembles payloads up to 4095 B (classical) with correct flow control, addressing, padding, sequence checking, and timeout behavior — verified against vectors and a python oracle.
Acceptance
  • SF/FF/CF/FC encode/decode match isotp/*.json byte-for-byte.
  • A 100-byte transfer with BS=8, STmin=20ms completes with correct FC cadence and CF pacing (tick-accurate).
  • Sequence gap → wrong-sequence abort; buffer overflow → FC OVFLW.
  • All six timers fire correctly on injected stalls (N_Bs/N_Cr etc. → abort).
  • STmin units honored (ms vs 100µs) — no 10× pacing error.
Fixtures
  • isotp/sf.json, isotp/ff_cf.json, isotp/fc.json — PDU encodings.
  • isotp/transfer_100b.json — full multi-frame sequence + FC cadence + timing ticks.
  • isotp/bs_blocks.json — BS>0 multi-block with interleaved FCs.
  • isotp/stmin_units.json — STmin 0x14 (20ms) vs 0xF1 (100µs) pacing.
  • isotp/addressing_extended.json, isotp/addressing_mixed.json.
  • isotp/escape_ff.json — >4095-byte length via 32-bit escape.
  • Malformed: isotp/wrong_sequence.json, isotp/overflow.json, isotp/timeout_ncr.json, isotp/unexpected_pdu.json.
Pitfalls
  • STmin unit confusion (ms vs 100µs) — 0xF1..0xF9 are 100–900 µs, not ms; misreading them as ms over-delays by ~10×, breaking timing-sensitive ECUs; encode StMin as a typed enum; verify with stmin_units.json; signal: transfers far slower than expected.
  • CF sequence number wrap — SN wraps mod 16 (…15→0→1…); treating wrap as a gap aborts long transfers at the 16th CF; debug with a >16-CF vector.
  • First CF SN value — FF is implicitly SN 0; the first CF is SN 1, not 0; off-by-one here desyncs immediately.
  • Payload-per-frame after addressing byte — extended/mixed addressing consumes 1 data byte, so SF holds ≤6 (classical) not 7; FF first-frame data shrinks too; mis-sizing overruns or underfills.
  • BS counting — BS counts CFs between FCs; off-by-one sends one too many/few before awaiting FC; verify with bs_blocks.json.
  • N_Bs vs N_Cr confusion — sender's wait-for-FC (N_Bs) vs receiver's wait-for-CF (N_Cr); swapping them mis-times aborts; map each timer to its exact role.
  • FC WAIT infinite loop — repeated WAIT frames must be bounded (max WAIT count) or N_Bs eventually aborts; otherwise a peer stalls forever.

⬜ Phase 10 — UDS diagnostics (ISO 14229) §22

Objectives
  • Implement can-uds: a client and a server over ISO-TP — request/response encoding, the service set (0x10/0x11/0x14/0x19/0x22/0x27/0x2E/0x31/0x34–0x37/0x3E), the full NRC table, session and security-access state machines, P2/P2* response timing (incl. NRC 0x78 pending), sub-functions, and the suppressPosRspMsgIndicationBit.
Deliverable
  • A UDS client and server exchanging the supported services over ISO-TP with correct positive/negative responses, session and security state, response suppression, and P2/P2* timing.
Acceptance
  • Each supported SID: positive response SID = request +0x40; payloads match uds/*.json.
  • NRC paths return 0x7F sid nrc with the correct NRC for malformed/unauthorized/out-of-range requests.
  • Security access: seed→key unlocks; wrong key → 0x35; N failures → 0x36 + lockout.
  • Session switching alters which services/sub-functions are allowed (0x7F otherwise).
  • P2 exceeded → 0x78 then final response before P2*; client waits accordingly.
  • suppressPosRsp suppresses the positive response but not negatives.
Fixtures
  • uds/session_control.json (0x10), uds/ecu_reset.json (0x11), uds/read_did.json (0x22), uds/write_did.json (0x2E), uds/routine_control.json (0x31), uds/tester_present.json (0x3E).
  • uds/security_access.json — seed/key handshake + failure lockout.
  • uds/transfer_sequence.json — 0x34/0x36/0x37 with block counter.
  • uds/p2_pending.json — 0x78 then response (timing ticks).
  • uds/suppress_posrsp.json.
  • Malformed: uds/nrc_length.json (0x13), uds/nrc_subfn.json (0x12), uds/nrc_range.json (0x31), uds/nrc_session.json, uds/nrc_security.json (0x33/0x35/0x36).
Pitfalls
  • Positive response SID arithmetic — +0x40 not |0x40 (they coincide for these SIDs but encode intent); assert against a vector; signal: client rejects valid responses.
  • suppressPosRspMsgIndicationBit handling — must mask bit 7 off the sub-function before processing, and suppress only the positive response; forgetting to mask treats 0x80|subfn as an unknown sub-function (0x12); debug by checking masked sub-fn.
  • P2 vs P2* state — after sending 0x78, the deadline extends to P2*; failing to extend the client's wait causes a spurious timeout; map the timer transition explicitly.
  • Security attempt counter / delay — not enforcing the post-failure delay (0x37 requiredTimeDelayNotExpired / 0x36) lets brute-forcing continue; persist attempts + lockout time.
  • Session-dependent service availability — returning 0x11 (serviceNotSupported) instead of 0x7F (serviceNotSupportedInActiveSession) when a service exists but not in this session; pick the session-specific NRC.
  • Length validation per service — each service has a fixed/min length; missing the check yields out-of-bounds reads (must be a 0x13 NRC, never a panic).

⬜ Phase 11 — J1939 higher layer §23

Objectives
  • Implement can-j1939: 29-bit ID ↔ PGN/SPN decomposition (priority/EDP/DP/PF/PS/SA), PDU1 vs PDU2 semantics, TP.CM/TP.DT multi-packet transport + BAM broadcast, and address claiming (PGN 0xEE00, 64-bit NAME contention).
Deliverable
  • A J1939 layer decoding/encoding PGNs and SPNs for standard messages, transporting multi-packet messages via TP.CM/TP.DT and BAM, and performing address claiming with NAME-based contention resolution.
Acceptance
  • ID↔PGN decomposition correct for PDU1 and PDU2 (vector-checked), including the PF=240 boundary.
  • SPN decode yields correct engineering values for sampled standard PGNs.
  • TP.CM/TP.DT destination-specific transfer (e.g. 20 bytes) completes with correct CTS cadence; BAM broadcast (e.g. 17 bytes) completes with the fixed-interval packets.
  • Address claiming: lower NAME wins; loser re-claims or signals Cannot Claim.
Fixtures
  • j1939/id_pdu1.json, j1939/id_pdu2.json — ID → (priority, pgn, sa, dest/group-ext).
  • j1939/spn_decode.json — PGN bytes → SPN values.
  • j1939/tp_cm_dt.json — RTS/CTS/DT/EndOfMsgAck sequence for a multi-packet message.
  • j1939/bam.json — BAM announce + DT packets (broadcast).
  • j1939/addr_claim.json — two NAMEs contending for one address → winner.
  • Malformed: j1939/tp_abort.json (abort reason), j1939/tp_seq_gap.json, j1939/addr_cannot_claim.json.
Pitfalls
  • PDU1/PDU2 boundary at PF=240 — PF<240 uses PS as a destination address (PGN low byte forced 0); PF≥240 folds PS into the PGN; misclassifying corrupts the PGN; verify with PF=239/240 vectors; signal: wrong PGN for destination-specific messages.
  • PGN PS-byte zeroing — for PDU1, the PGN's low byte must be 0 (destination is separate); leaving PS in the PGN yields a wrong PGN; assert.
  • TP.DT vs ISO-TP CF confusion — J1939 TP is a different protocol from ISO-TP (different PGNs, SN range 1..255, BAM has no flow control); don't route J1939 multi-packet through can-isotp; keep them separate.
  • BAM fixed timing — BAM packets use a fixed 50ms (50–200ms) inter-packet interval, no CTS; sending too fast overruns slow listeners; pace per spec.
  • Address-claim NAME comparison — NAME is compared as a 64-bit value (lower wins); byte-order or field-order errors pick the wrong winner; verify with addr_claim.json.
  • SPN scaling/offset — applying the wrong scale/offset/byte-order to an SPN yields plausible-but-wrong values; data-drive from J1939-71 and test against known samples.

⬜ Phase 12 — Conformance + fuzzing + benchmarks + bus monitor §24

Objectives
  • Build can-conformance (vector runner + differential harness), wire up fuzzing for all parsers, benchmark the simulator and stack, and complete canctl (live monitor + injector + protocol decoders). This phase hardens and validates everything from Phases 1–11.
Deliverable
  • A green conformance suite across all protocol areas, fuzzers running clean, committed benchmark baselines, and a usable canctl monitor/injector/replayer.
Acceptance
  • 100% of conformance vectors pass; differential checks match python-can/can-isotp for the shared corpus.
  • Fuzzers run ≥4 CPU-hours per PR smoke run and ≥100 CPU-hours nightly soak (M12) with zero panics / sanitizer findings.
  • Benchmarks meet M1–M5 and M7 (Performance Engineering): bit-step ≤ 5 ns/node-bit (M1); classical throughput ≥ 3,900/7,800 fps at 500k/1M (M3/M4); FD throughput ≥ 5,800 fps (M5); ISO-TP 4095 B transfer ≤ 12 s p99 (M7); perf-regression gate active (>10% regression fails).
  • Property tests pass ≥1e6 cases each.
  • canctl monitor displays live frames with correct protocol decoding; replay reproduces a recorded run bit-for-bit.
Fixtures
  • Aggregate of all prior phases' vectors under conformance/vectors/.
  • conformance/manifest.json — index of all vectors with kind + expected-outcome summary.
  • replay/*.jsonl — recorded golden runs for regression replay.
  • fuzz/corpus/* — seed corpora derived from vectors.
  • Cross-protocol scenario: scenario/diag_over_isotp_over_can.json — a UDS ReadDID over ISO-TP over classical CAN, end-to-end.
Pitfalls
  • Vector drift — vectors not updated when behavior legitimately changes; either a real regression or stale vectors; require a documented reason + reviewer sign-off for any vector change; signal: a vector flips pass/fail without a code reason.
  • Fuzzer finds a panic in no_std — a parser panics on malformed input = a DoS on real hardware; every fuzz finding must become a typed-error regression test; debug with the minimized crash input.
  • Differential false mismatch — python-can timing/format quirks differ from spec; only compare byte-level outputs, not timing; document known oracle limitations.
  • Benchmark noise — host scheduling jitter inflates variance; pin CPU, run criterion with enough samples, compare medians; signal: flaky perf gate.
  • Replay nondeterminism — any unseeded randomness or HashMap iteration breaks bit-for-bit replay; assert determinism in the replay test; debug by diffing two runs.
