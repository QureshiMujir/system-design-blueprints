Decisions (§9) · 30 ADRs

1

Core language

Chosen

Rust 2021, #![no_std] core

Rejected

C, C++, Zig, Go

When the rejected choice is right

C wins when the target MCU has only a vendor C toolchain / no Rust target, or you must link into an existing AUTOSAR Classic C codebase.

Why: Safety + determinism + no_std + strong test tooling.

2

Simulator model

Chosen

Bit-accurate synchronous stepping

Rejected

Event-driven discrete-event sim

When the rejected choice is right

Event-driven (DES) wins for large fleet/network-level studies (hundreds of nodes, many buses) where per-bit fidelity is unnecessary and only frame-level latency distributions matter.

Why: Faithful arbitration + reproducibility outweigh speed.

3

Buffer strategy

Chosen

Fixed-capacity (heapless) in core

Rejected

alloc/Vec everywhere

When the rejected choice is right

alloc/Vec wins on a host-only gateway/router handling arbitrary-size ISO-TP transfers up to 2^32-1 bytes where fixed ceilings would force rejection.

Why: No heap in hot path; embeddable; bounded memory.

Controller API

Chosen

Rejected

When the rejected choice is right

async wins on a host application multiplexing many CAN buses + sockets where Embassy/Tokio task ergonomics outweigh the determinism cost.

Why: Deterministic stepping; no_std async is heavy.

Alternative Architectures (Roads Not Taken)

Fundamentally different architectures for the same goal (deterministic, robust multi-node messaging). Each: sketch, winning regime, real system embodying it, why this blueprint rejected it.

ALT-1 — Time-triggered scheduling (TDMA) instead of priority arbitration.

Show the original text diagram
   global time base
        |
  +-----+-----+-----+-----+   each slot pre-assigned to one node
  |slot0|slot1|slot2|slot3|   no contention; transmit only in your slot
  +-----+-----+-----+-----+
  node A node B node C node A

Winning regime: hard-real-time control where every message needs a guaranteed latency bound and jitter must be near-zero — no low-priority starvation because slots are reserved, not contended. Real system: TTCAN (ISO 11898-4) and FlexRay (its static segment). Why rejected: CSMA/CR bitwise arbitration (the core of this stack, §8.11, Invariant 1) is event-triggered and far simpler — no global clock synchronization, no slot configuration — and CAN's priority model already serves the automotive/robotics buses targeted in §1.5. Time-triggered determinism is explicitly out of scope (§1.3 non-goals: "no TTCAN, time-triggered scheduling").

ALT-2 — Larger payload + dual bitrate (the CAN FD direction) as the primary model rather than a layered extension.

 classical:  [arb @ 1M][ 0..8 B data @ 1M ][crc]
 FD (BRS):   [arb @ 1M][ 0..64 B data @ 5M..8M ][crc]   <- switch rate after BRS

Winning regime: bandwidth-bound buses (large sensor payloads, firmware flashing) where 8 bytes at 1 Mbit/s is the bottleneck — FD's ~12× payload throughput (Capacity Model item 5) is the answer. Real system: Bosch CAN FD (§5.4), shipping across modern vehicles. Why rejected as the base: this blueprint keeps classical CAN as the correctness kernel and adds FD as a separate, optional crate (ADR 29, Phase 7) so the simpler classical framing/arbitration is mastered and conformance-locked first; making FD primary would entangle dual-rate timing into every layer before the basics are proven.

ALT-3 — Switched / point-to-point networking (automotive Ethernet + TSN) instead of a shared multi-drop bus.

Show the original text diagram
  node A --\            /-- node C
            [ SWITCH ] -
  node B --/            \-- node D
  full-duplex links; switch arbitrates; TSN adds time-aware shaping

Winning regime: high-bandwidth, many-talker topologies (cameras, ADAS, zonal architectures) needing 100 Mbit/s–10 Gbit/s and where a shared 1 Mbit/s wire cannot scale; switching removes the single-collision-domain ceiling entirely. Real system: Automotive Ethernet with TSN (IEEE 802.1 Qbv/Qav). Why rejected: it abandons CAN's defining property — a single wired-AND domain where priority falls out of the identifier with no switch or central scheduler — and is far heavier (PHY, switch, configuration) than the cheap, robust, deterministic field bus this project teaches. Explicitly a non-goal (§1.3: "no automotive Ethernet").
