4.3 Determinism contract

No floating point in encode/decode/timing decisions (TQ are integers); no wall-clock reads inside protocol logic; all randomness (seeds, jitter, error injection) drawn from an explicit seeded RNG so any run replays bit-for-bit.

Back-of-Envelope Capacity Model

Numbers an engineer computes before building, each derived step-by-step from the System Constraints (§4). Formulas shown; every input names its §4 source.

  1. Bits per worst-case classical 8-byte frame. Fixed-form overhead = SOF + 11-bit ID + RTR + IDE + r0 + 4-bit DLC + 15-bit CRC + CRCdel + ACK + ACKdel + 7-bit EOF = 44 bits (from the §8.1 layout). Data = 8 B × 8 = 64 bits (§4.2 classical 0–8 B). Pre-stuff total = 44 + 64 = 108 bits. Stuffing applies to the ≤ 98 stuff-eligible bits (SOF→CRC); worst case ≈ ⌊98/4⌋ ≈ 24 inserted, but the spec-typical worst case cited for an 11-bit frame is ≈ 19 → ≈ 127 bits on the wire.

  2. Max classical frame rate at 500 kbit/s (default rate). bus bitrate ÷ bits-per-frame = 500,000 ÷ 127 ≈ 3,937 frames/s worst-case 8-byte; for a 0-byte frame (44 + ~10 stuff ≈ 54 bits) → 500,000 ÷ 54 ≈ 9,259 frames/s. (Input: §4.1 rate 500k; §4.2 byte range.)

  3. Max classical frame rate at 1 Mbit/s (ceiling rate). 1,000,000 ÷ 127 ≈ 7,874 frames/s (8-byte) up to ≈ 18,500 frames/s (0-byte). (Input: §4.1 rate 1M.)

  4. Effective bus load with stuffing overhead. frame rate × bits-per-frame ÷ bitrate = bus-load fraction. At 4,000 × 127 ÷ 500,000 = 1.016 → ~100% (saturated); the stuffing overhead (127/108 ≈ 1.18×, i.e. ~18% inflation) is why a CAN bus saturates below its nominal bitrate (Scalability Analysis "bus-load ceiling"). (Input: §4.1 rate; §8.3 stuffing.)

  5. CAN FD 64-byte frame throughput gain (BRS). Arbitration phase (header ≈ 30 bits) runs at 500k; data+CRC (≈ 64×8 + ~40 = 552 bits) runs at, say, 5 Mbit/s (§4.1 FD data phase). Time ≈ 30/500k + 552/5M = 60 µs + 110 µs = 170 µs → ≈ 5,880 FD frames/s carrying 64 B each = 376 KB/s payload, versus classical 8-byte at 500k ≈ 3,937 × 8 = 31 KB/s — a ~12× payload-throughput gain. (Input: §4.1 dual rates; §4.2 FD 64 B.)

  6. Simulator cost per bit-step at max nodes. arbitration is O(nodes) per bit (§4.2). At 128 default nodes (256 max), one bit-step does ≤ 256 drive reads + one AND reduction. Over a worst-case 127-bit frame that is 127 × 256 ≈ 32,512 node-bit operations per frame — the dominant per-frame cost the bit-step benchmark (M1, Phase 12.2) must keep to ≤ 5 ns per node-bit operation. (Input: §4.2 max nodes, arbitration O(nodes).)

  7. TQ-granular simulation multiplier. bit time = 8–25 TQ, typ 16–20 (§4.2). Stepping at TQ granularity instead of bit granularity multiplies scheduler iterations by ≈ 16–20× (Phase 3.7 Performance Concerns) — why TQ stepping is opt-in only for timing-sensitive vectors. (Input: §4.2 bit-time budget.)

  8. Bus-off recovery time. recovery needs 128 × 11 = 1,408 consecutive recessive bits (§8.6, Invariant 5). At 500 kbit/s that is 1,408 / 500,000 = ≈ 2.82 ms of idle bus minimum before a bus-off node may rejoin; at 1 Mbit/s ≈ 1.41 ms. (Input: §4.1 rate; §8.6 recovery rule.)

  9. TEC climb to bus-off under sustained TX errors. each TX error = +8 TEC; bus-off at TEC ≥ 256 (§8.6). From 0, that is 256 / 8 = 32 consecutive TX errors to force a node off; from the Error-Passive boundary (128) it is (256−128)/8 = 16 errors. Mapping to wall time via the §4.1 rate: at 500 kbit/s a failed 8-byte frame + error frame ≈ 150 bits → 32 × 150 / 500,000 ≈ 9.6 ms to drive a node bus-off in the worst case. (Inputs: §8.6 increments/thresholds; §4.1 bit rate.)

  10. ISO-TP max single-transfer reassembly RAM. classical FF length is 12-bit → max 4095 B per active receive context (§4.2 ISO-TP max payload). A pool sized for, e.g., 4 concurrent contexts = 4 × 4095 ≈ 16 KB of fixed reassembly buffer — the figure to budget against the no_std memory ceiling (§4.2). (Input: §4.2 ISO-TP payload + concurrency note.)

  11. ISO-TP multi-frame transfer latency under STmin. a 4095-byte classical transfer = 1 FF (6 B) + ⌈(4095−6)/7⌉ = 585 CFs (§8.8 7-B CFs). At STmin = 20 ms pacing (§4.2 example), wall time ≈ 585 × 20 ms ≈ 11.7 s — latency is dominated by STmin, not CPU (Phase 9.7). With STmin = 0 it is bounded only by bus arbitration. (Input: §4.2 ISO-TP payload + STmin units.)

  12. UDS response-pending budget. P2 = 50 ms default; after NRC 0x78 the deadline extends to P2* = 5000 ms (§4.2). A server may legitimately keep a tester waiting up to 5 s per pending operation, and a long routine may emit multiple 0x78 frames within that window — the client timeout must track the P2→P2* transition or it false-aborts (Phase 10.6). (Input: §4.2 P2/P2* defaults.)
