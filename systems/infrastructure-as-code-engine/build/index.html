⬜ Phase 4 — iac-graph: dependency DAG, cycle detection, bounded-parallel Walker §16

Objectives
  • Extract references() (Vec<Addr>) from evaluated config by walking Expression::ScopeTraversal → resolve leaf+traversal to a ResourceAddress; ignore self-refs, vars/locals already inlined by iac-eval.
  • Build Graph<N> with edge direction dependency → dependent; add_node/add_edge per GraphNode::references().
  • detect_cycles() via Tarjan SCC → Err(Vec<Vec<NodeId>>); report each SCC (len>1, or self-loop) as a Diagnostic with the offending address cycle path.
  • transitive_reduction() for clean iac graph DOT render (drop redundant edges, preserve reachability).
  • Walker: reverse-topological, bounded by -parallelism; independent nodes concurrent; a node's error defers (skips) its transitive dependents; aggregate all Diagnostics, never panic. DOT export.
Deliverable

cargo test -p iac-graph green; build → validate (cycle/dangling) → walk an arbitrary evaluated config; iac graph emits DOT to stdout. Walker honors -parallelism and reverse-topo order.

Acceptance
  • 3-node chain a→b→c: walk order respects deps; with parallelism=8, two independent leaves start within same scheduling tick (observed via timestamped visit log).
  • Self-loop and 3-cycle → detect_cycles Err; each emits one Diagnostic listing addresses in cycle order; build_graph does not hang.
  • transitive_reduction on a→b, b→c, a→c drops a→c; reachability of c from a preserved.
  • 10k-node random DAG: detect_cycles < 50 ms; walk visited == 10000; aggregated diagnostics empty.
  • Failing node defers exactly its transitive-dependent set; siblings still visited.

  • Provider installer/registry: resolve+cache binaries by name+version under SemVer constraint; .iac/providers/<host>/<ns>/<name>/<ver>/<os_arch>/.

Acceptance

⬜ Phase 8 — Apply engine: execute the plan, incremental state, partial failure §20

Objectives
  • Load saved Plan -> walk graph reverse-topological with -parallelism -> for each non-NoOp ResourceChange call Provider::apply_resource(ty, prior, planned) -> resolve Unknown -> write ResourceInstance into State incrementally + atomically.
  • Honor create_before_destroy (CBD) ordering; Replace = create-new-deposed then destroy-old (or destroy-then-create).
  • Partial failure: failed node -> instance Tainted; defer dependents (transitive skip); aggregate Diagnostics, never panic.
  • Graceful SIGINT: stop scheduling new RPCs, finish in-flight, flush State, exit nonzero. Crash-consistent recovery: fresh plan reconciles exactly what was written.
  • Headline invariant: apply(plan) then fresh plan against new state = all-NoOp (idempotency).
Deliverable

iac apply [plan.bin | -auto-approve]: realizes a saved (or freshly computed) Plan, calling providers in graph order, writing incremental valid State, redacting Sensitive, printing per-resource progress + final tally (N added, M changed, K destroyed); exit 0 success / nonzero on aggregated diagnostics.

Acceptance
  • Idempotency: apply then plan (reality unchanged) -> applyable=false, 0 changes.
  • Ordering: dependency apply_resource completes before any dependent's begins (assert via reference-provider event log).
  • Partial failure: node X fails -> X Tainted, all transitive dependents skipped+reported, all independent nodes still applied, State valid + reflects every success.
  • CBD: replaced resource's new instance Ready before old destroyed; on create failure old stays Ready, new absent.
  • Crash mid-apply (kill -9 after K commits): re-plan reconciles exactly the remaining N-K, never re-applies committed ones; state file never torn.
  • Parallelism: with -parallelism=P, ≤P concurrent apply_resource in flight (gauge ≤ P).

Pitfalls
  • Writing state only at end -> crash loses all progress; root cause: not incremental. Fix: commit per resource; debug via serial gaps in .backup.

⬜ Phase 11 — Concurrency, locking, and consistency hardening §23

Objectives
  • Precise -parallelism semantics: one global semaphore across the iac-graph Walker (default 10); per-provider concurrency caps layered beneath it.
  • State-lock lifecycle: acquire before any state mutation; heartbeat to detect dead holder; stale-lock detection; force-unlock gated on operator confirmation.
  • Provider-call timeouts + bounded retries (exponential backoff) on transient/retryable Diagnostics only — never on deterministic errors.
  • SIGINT/SIGTERM graceful shutdown: stop scheduling new nodes, drain in-flight apply_resource, flush State, exit non-zero.
  • Crash-consistent partial applies: every written ResourceInstance durable; next plan reconciles. Consistency self-checks: serial monotonicity, lineage match, no orphaned instances.
Deliverable

  • Heartbeat vs clock skew — hb_at from holder's clock; comparing to local now mis-flags stale across hosts. Root cause: no monotonic shared time. Debug: log both clocks; use generous 3× margin, store skew hint.
