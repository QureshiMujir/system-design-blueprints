Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. A plan shows null_thing.b as Update every time it runs, even after a clean apply. The provider's apply_resource returns {id: "abc", label: "x", tags: ["b","a"]} but the config has tags = ["a","b"]. Identify the invariant being violated, the root cause, and the exact fix in iac-core/src/diff.rs. (§7 I7/INV-IDEMPOTENT, §8.5 Value lattice Set semantics, §19 diff, §20 partial-failure)
  2. Terraform uses go-cty with Unknown values that can propagate through expressions. Our iac-eval uses Value::Unknown(Type). What is the one behavioral difference in how Unknown && false evaluates, why does our choice matter for plan correctness, and which invariant does it protect? (§8.4 Unknown lattice rules, §7 I8/INV-UNKNOWN-NEQ, §6.5 Unknown principle, §14 Phase 2)
  3. A provider's apply_resource call completes successfully (returns a concrete Value), but the iac process receives SIGKILL 50 ms later, before StateBackend::write completes. The operator runs iac plan next. What does the plan show, why, and what is the operator action? What invariant guarantees the state file is not torn? (§7 I3/INV-STATE-ATOMIC, §7 I12/INV-PARTIAL-VALID, §17 atomic write, §22 partial apply, Failure Modes and Recovery Modes F4/F5)
  4. Two CI pipelines run iac apply concurrently against the same workspace. The second acquires the lock 2 s after the first but the lock file was written with O_CREAT without O_EXCL. Explain the TOCTOU race, the exact point in §17 where this is called out, and how the StateBackend::lock implementation must differ from a naive open(O_CREAT). (§17 lock.rs, §17 pitfalls, §7 I5/INV-LOCK-HELD, Threat Model T9/concurrent operators)
  5. A config uses count = length(var.zones) where var.zones is a list(string). At plan time var.zones is known. At apply time, upstream resource random_shuffle.a writes a new var.zones value to a local file that a subsequent plan reads. Between plan and apply, var.zones changes from ["a","b","c"] to ["a","b"].   6. The transitive_reduction function in iac-graph is documented as O(V·E) worst-case.   7. Value::Sensitive is a propagating mark. A provider attribute has sensitive: true.   9. The three-way diff detects drift by comparing prior State value P to refreshed reality R.   11. A module calls another module with count = aws_subnet.main[*].id. At plan time, aws_subnet.main is a new resource whose id is Unknown(String). Mental Models & First Principles

Six compressed expert models that predict behavior, explain bugs, and anchor every phase.

# Model What it predicts Bug class without it Resolving §
MM1 The three-way diff is the frame — every Action comes from comparing exactly three inputs: prior State (P), refreshed reality R = read_resource(P), desired config C. When all three agree, it's NoOp; when P≠R, it's drift; when C≠R, it's a planned change. If you conflate any two legs, you mis-categorize Actions. Drift detection accuracy; "spurious Update" vs "missed Replace" Two-way diff (config vs state) that ignores out-of-band changes → NoOp when reality has drifted; or a "planned == prior" shortcut that skips refresh → phantom idempotency §8 (Action table), §19 (Plan engine), §20 (Apply)
MM2 Unknown is a monotone lattice element, not a flag — Unknown(T) is the top of the knownness partial order over concrete values of type T. Any operation touching Unknown returns Unknown (join). Unknown ≠ concrete is always Unknown(Bool), not false. An expression tree touching an Unknown leaf must propagate Unknown to every ancestor. "(known after apply)" placement; plan applyability gating Treating Unknown as a sentinel string "" or null → a downstream diff sees "" vs config value → perpetual spurious Update → broken idempotency (MM1 fails) §8.4 (Value lattice), §14 (Phase 2), §19
MM3 Atomic rename is the commit point — the only durable commit in StateBackend::write is the POSIX rename(2) call (same-filesystem). Before rename: no change is visible. After rename: the new state is visible. Everything before (serialize, fsync(file)) prepares the new version; the dir fsync after rename makes the metadata durable. The .backup must be written BEFORE the rename to guarantee a recovery copy always exists. Crash-consistency window analysis Writing .backup after rename → a crash between rename and backup copy leaves the new state without a backup → unrecoverable if new state is also corrupt. OR: rename without prior fsync(file) → OS can reorder → torn file survives reboot. §17 (State write), §17 (Pitfalls), §7 I3
MM4 The walker is a topological processor with a semaphore — graph execution is not "run nodes concurrently"; it is "a reverse-topological BFS where each node's readiness is its in-degree reaching zero, bounded by a semaphore(P)". The ready-queue is populated by decrementing in-degree on each completed node; the semaphore caps concurrent inflight. A deferred (failed) node must also decrement its dependents' in-degree (as "skipped") or the queue deadlocks. Correct -parallelism modeling; partial-failure deadlock analysis Not decrementing deferred-node dependents' in-degree → queue drain stalls → apply hangs with some nodes never visited (observed symptom: apply exits 1 but never reports N of the expected nodes) §16 (Phase 4), §20 (Apply), §7 I2
MM5 Sensitive is a monotone privacy mark, not encryption — Sensitive(v) means "this value must not appear in any output sink". It is monotone: any expression combining a Sensitive operand produces a Sensitive result. It propagates through collection ops, functions, templates. It is NOT at-rest encryption. The state file stores the raw value wrapped in Sensitive; redaction happens only at the output boundary (plan render, log formatter, RPC response). A new output sink that bypasses the redaction boundary leaks all marks at once. Leak-free output design; new sink threat model Adding a diagnostic serializer that formats Value via Display (not the redaction-aware formatter) → a Sensitive password appears in a structured log line. The symptom doesn't appear in any existing test because the new sink is untested. §6.9 (Sensitive invariant), §14 Phase 2, T5 (Threat T5)
MM6 Idempotency is an emergent property, not a single assertion — apply(plan) → fresh plan = all-NoOp holds iff three independent sub-properties all hold simultaneously: (1) the diff is stable (same inputs → same Action, every time — DETERMINISM); (2) every successful mutation is recorded in state before the run ends (PARTIAL-VALID); (3) read_resource then plan_resource round-trips through the engine's convert/normalize losslessly (PROVIDER NORMALIZATION). Any one failure breaks idempotency. Debugging an idempotency violation requires determining which of the three sub-properties failed first. Root-cause isolation for idempotency violations Debugging "phantom Update after apply" by only checking the diff logic (sub-property 1) while the real cause is provider returning a reordered set that the diff sees as changed (sub-property 3 normalization failure) §7 I7, §19 (Plan), §20 (Apply), §24 (Phase 12 gate)

MM1 and MM6 are interdependent: MM1 defines the three-way diff frame; MM6 explains why that frame must be stable and complete. MM2–MM5 are the four implementation mechanisms (unknown lattice, atomic commit, walker model, sensitive monotonicity) that give MM1+MM6 their concrete meaning.

Glossary · 52 terms · site-wide glossary

configuration / config
The *.iac source: blocks + attributes parsed by iac-hcl into a Body, then evaluated by iac-eval. The desired leg of the three-way diff. Untrusted input — crosses the trust boundary.
resource
A provider-managed real-world object (ResourceMode::Managed) declared by a resource "ty" "name" {} block. Has lifecycle: Create/Read/Update/Delete via the Provider CRUD methods.
data source
A read-only external lookup (ResourceMode::Data); never mutates infra. Refreshed via read_resource, contributes values to other resources, produces only Action::Read.
managed resource
A resource whose lifecycle the engine owns (vs a data source it merely reads). Eligible for Create/Update/Delete/Replace.
provider
An out-of-process plugin implementing the Provider trait; orchestrated, not implemented, by the engine (non-goal: being a cloud). Exposes a ProviderSchema; runs as a child process over the plugin RPC.
provider schema
ProviderSchema { provider, resources, data_sources } — declares each type's Schema (attributes + blocks), driving validation, type checking, and the diff. Negotiated at handshake.
attribute
A typed field of a resource: Attribute { ty, required, optional, computed, sensitive, force_new }. Also iac-hcl's config Attribute { name, expr, span }.
nested block
A NestedBlock schema entry — a repeatable/structural sub-block within a resource (e.g. ingress {}), distinct from a scalar/collection attribute.
computed attribute
An Attribute with computed: true — the provider fills the value, so it is Value::Unknown(ty) during planning ("known after apply").
force_new / requires-replace
Attribute.force_new: true — changing it cannot be done in place; the diff must Replace (delete+create). PlannedChange.requires_replace: Vec<Path> / ResourceChange.requires_replace carry the offending paths.
plan
Plan { changes, output_changes, prior_state, variables, applyable } — the minimal ordered set of actions to reconcile reality to config. Output of the Plan engine (Phase 7); input to Apply (Phase 8).
the diff
The per-resource comparison producing an Action; the engine-wide diff is the three-way diff.
three-way diff
Compares (a) prior state, (b) refreshed reality (read_resource), (c) desired config. NoOp if all agree; Update if changed attrs are non-force_new; Replace if any changed attr is force_new; Create if no prior; Delete if in state but not config.
ResourceChange
{ address, action, before, after, requires_replace, deposed } — one resource's planned transition; the unit of the Plan and the unit Apply executes.
Action
enum Action { NoOp, Read, Create, Update, Delete, Replace { create_before_destroy: bool } } — exhaustive set of per-resource operations.
create-before-destroy
A Replace ordering: provision the new instance before destroying the old to avoid downtime. The old becomes deposed until the new is healthy. Flag on Action::Replace.
deposed
InstanceStatus::Deposed(DeposedKey) — an old instance kept alive during a create-before-destroy Replace, destroyed after the replacement succeeds; tracked so a crash can still clean it up.
tainted
InstanceStatus::Tainted — an instance whose Apply partially failed or is user-marked bad; the next plan forces its Replace.
refresh
Calling read_resource(ty, prior) to update prior state with observed reality before diffing; the (b) leg of the three-way diff. Phase 7 / refresh-only plan (Phase 10).
drift
Divergence between state and refreshed reality (out-of-band change). Surfaced by refresh; the diff plans corrective actions.
state
State { version, serial, lineage, resources, outputs } — the only durable artifact; the single source of truth, written atomically and behind a lock by iac-state.
serial
State.serial: u64 — monotonically increasing write counter; a stale serial signals a lost update; bumped on every successful write.
lineage
State.lineage: Uuid — identity stamp created with the state; a mismatch means "wrong state file" and aborts the operation.
state lock
StateLock / StateBackend::lock(LockInfo) -> LockId — mutual exclusion guarding a write; held with heartbeat; unlock/force-unlock release it. State is single-writer.
backend
StateBackend implementer (local; remote-stub) abstracting state read/write/lock; write is atomic (temp + fsync + rename + .backup).
ResourceAddress
{ module: ModulePath, mode, ty, name } — canonical identity of a resource (plus IndexKey for instances); printed as module.x.aws_s3_bucket.y["k"]; used by state, targeting, and state mv/rm.
module
A reusable config unit (its own Body + variables/outputs) instantiated via a module-call block; expanded by iac-core's loader into the module-call graph.
module instance
One expansion of a module call (a count/for_each index); contributes a ModulePath segment to descendant ResourceAddresses.
count
Meta-arg producing N indexed instances keyed by integer IndexKey; expanded by the NodeExpander. Under Unknown count → expansion deferred.
for_each
Meta-arg producing instances keyed by map/set string IndexKey; NodeExpander materializes one node per key; stable, order-independent addressing.
index key
Option<IndexKey> on a ResourceInstance — the count integer or for_each string distinguishing instances of one address.
NodeExpander
The iac-core component turning a single configured node into 0..N graph nodes per count/for_each, assigning ResourceAddress index keys (Phase 9).
dependency graph
Graph<N> (iac-graph) of resource nodes; edges = dependency→dependent extracted from references; cycle-checked (Tarjan SCC) and transitively reduced.
reverse-topological walk
Graph::walk(parallelism, visit) order: dependencies before dependents on apply (from leaves), reversed on destroy. Independent nodes run concurrently; errors defer dependents and aggregate.
-parallelism
CLI flag bounding concurrent provider RPCs in the Walker; the concurrency boundary. State remains single-writer regardless.
reference
An expression pointing at another object's attribute (e.g. aws_vpc.main.id); the reference extractor mines these to build graph edges.
traversal
enum Traversal { Attr(String), Index(Expression), LegacyIndex(u64) } — the steps of a ScopeTraversal expression (a.b[0].c) navigated during evaluation.
Value lattice
The Value sum type (Null/Bool/Number/Str/List/Set/Map/Object/Tuple/Unknown/Sensitive) ordered by knowledge: a concrete value refines Unknown; Sensitive wraps and propagates.
Unknown value / known-after-apply
Value::Unknown(Type) — a not-yet-computed value during planning; any expression touching it yields Unknown; rendered "(known after apply)"; never compares equal to a concrete value; resolved top-down at apply.
Sensitive value
Value::Sensitive(Box<Value>) — a privacy mark (from sensitive attrs/vars) that propagates through expressions and is redacted in plan output and logs.
type conversion / unification
convert(v, &Type) coerces a Value to a target Type (cty convert); unify(&[Type]) -> Option<Type> finds a common type (e.g. for tuple→list, conditional arms).
EvalContext
EvalContext<'a> — the evaluation scope: variables, locals, each/count scope, the Function registry, and path; passed to evaluate.
Function
The Function trait (name, call, param_types, return_type) — a registered callable (string/numeric/collection/encoding/hash/filesystem) invoked by Expression::FunctionCall.
for-expression
Expression::ForExpr — [for k,v in coll : expr if cond] (and object form); evaluated deterministically with sorted iteration over maps/objects.
dynamic block
A meta-construct generating zero+ nested blocks from a collection at eval time; expanded in Phase 3 before graph build.
provider plugin protocol
The typed RPC (iac-provider) over a child process: handshake → schema negotiation → framed protobuf-ish messages carrying validate/plan/apply/read/import.
handshake
The startup negotiation establishing protocol version + transport with a freshly launched provider child process before any CRUD RPC.
idempotency
The headline property: apply(plan) then a fresh plan against the new state yields an all-NoOp plan when reality is unchanged. Gated in Phase 12.
target (-target)
CLI flag pruning the graph to a chosen ResourceAddress (and its dependencies) for a partial plan/apply (Phase 10).
import
import_resource(ty, id) -> Vec<ImportedResource> — adopting pre-existing infra into state without recreating it (Phase 10).
output
A State.outputs entry / OutputChange in the plan — a named, exported computed value; may be Sensitive.
Diagnostic
Diagnostic { severity, summary, detail, span } — the structured error/warning carrier from lexing through apply; aggregated (never panicked) across the pipeline.
