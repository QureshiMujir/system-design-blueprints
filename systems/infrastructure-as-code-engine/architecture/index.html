3. Architectural Overview

   Operator / CI :  iac init | validate | fmt | plan | apply | destroy | refresh | import | output | graph | state ...
                                  |  *.iac config + CLI flags + -var / -var-file
                                  v
   iac-cli  ────────────────────────────────────────────────────────────────────────────────────
                                  |  load + parse
                                  v
   iac-hcl : Lexer -> Parser -> config AST (Body / Block / Attribute / Expression) + Diagnostics
                                  |  AST (parsed, unevaluated)
                                  v
   iac-eval : Value/Type lattice · EvalContext · Function registry · for/cond/splat · convert/unify
                                  |  evaluated config (with Unknown / Sensitive marks)
                                  v
   iac-core : module expand · NodeExpander(count/for_each) · graph build · PLAN · APPLY
       |  build graph             |  refresh + 3-way diff -> ResourceChange/Action            |  walk + RPC
       v                          v                                                           v
   iac-graph : DAG +        iac-state : versioned State · StateBackend ·               iac-provider : Provider
   cycle detect (Tarjan) +  StateLock · serial / lineage ·                             trait · ProviderSchema ·
   transitive reduction +   atomic write (temp+fsync+rename) + .backup                 installer/registry ·
   bounded Walker           <----------- read prior State / write new State ---------- plugin RPC / child process
                                                                                             |  CRUD
                                                                                             v
   ╔══════════════════════════════════════════════════════════════════════════╗      real infrastructure
   ║ TRUST BOUNDARY ──── untrusted *.iac config  +  untrusted provider responses ║      (AWS/GCP/... — NOT us)
   ╚══════════════════════════════════════════════════════════════════════════╝
   CONCURRENCY BOUNDARY ── Walker runs provider RPCs in parallel up to -parallelism; State is single-writer.
   PERSISTENCE BOUNDARY ── iac-state is the only durable artifact; written atomically under lock.

Data flows top-down through a strict pipeline; each crate owns one transformation and a single invariant. iac-core is the only orchestrator — it is the sole crate that fans out to iac-graph, iac-state, and iac-provider, and it holds the single write capability for State.

3.1 iac-cli — the iac binary

Thin presentation/orchestration shell. In: argv (subcommand + flags), env, *.iac files on disk, stdin (for state push). Out: exit code, human-rendered diagnostics/plan/apply progress to stderr, machine output (-json) to stdout, output values. Subcommands init validate fmt plan apply destroy refresh import output graph state{list,show,mv,rm,pull,push} each translate to one iac-core entry point; no business logic lives here. Invariant: a non-zero exit ⇔ at least one error Diagnostic; plan exits 0/2 (0=empty, 2=non-empty diff, -detailed-exitcode). Owns flag parsing, -var/-var-file collection, TTY detection for color/progress, and SIGINT capture forwarded to the Apply executor's cancel token. Built Phase 0 (shell) then wired per subcommand across Phases 7–10.

3.2 iac-hcl — configuration language front end

Turns bytes into a typed but unevaluated config AST. In: UTF-8 source + filename. Out: Body (root), or Vec<Diagnostic> with byte-accurate Spans. Pipeline: Lexer (tokens, here-doc <<EOT / <<-EOT, #/////* */ comments, template ${/%{ interpolation lexing) → recursive-descent Parser (blocks with labels, attributes, the full Expression grammar incl. precedence-climbed BinaryOp/UnaryOp, Conditional, ForExpr, Splat, Index, FunctionCall{expand_final}, Template). Invariant: never panics on adversarial input — every malformed byte sequence yields a recoverable Diagnostic, and parsing is total. No evaluation, no I/O beyond the provided source, no provider knowledge. Built Phase 1; fmt reuses its lossless token/span info.

3.3 iac-eval — value/type lattice + evaluator

Evaluates an AST Expression against an EvalContext to a Value. In: AST + scopes (variables, locals, each/count, function registry, current module path). Out: Value or EvalError. Implements the cty-like lattice: concrete kinds (Null/Bool/Number(Decimal)/String/List/Set/Map/Object/Tuple) plus the two lattice marks Unknown(Type) (computed, not-yet-known) and Sensitive(Box<Value>). convert(v,to) and unify(types) give type coercion/common-supertype; the Function trait registry supplies builtins. Invariants: Unknown never compares equal to a concrete value and is contagious (any op touching Unknown → Unknown); Sensitive propagates through every operation and is never silently dropped; evaluation order is deterministic (sorted map/object iteration, no wall-clock/RNG). Built Phases 2 (lattice + core evaluator) and 3 (Functions, for/cond/splat/dynamic, var/local/output scopes).

3.4 iac-core — the orchestration engine

Owns the end-to-end lifecycle; depends on all of 1–5. Sub-components:

  • Module expander / config loader — discovers *.iac, loads module calls recursively, resolves source addresses, builds the module tree, evaluates variables/locals/outputs per module instance. Invariant: a module instance is a closed scope; cross-module refs flow only through declared variable/output. Built Phase 9.
  • NodeExpander — expands count (→ integer IndexKey) and for_each (→ string IndexKey) into per-instance ResourceAddresses. Invariant: expansion under an Unknown count/for_each is deferred ("known after apply" instance set), never guessed. Built Phase 9.
  • Graph builder — extracts references from evaluated config, emits nodes (resources, data sources, modules, var/local/output) and dependency edges into an iac-graph Graph<N> where N: GraphNode. Invariant: every references() edge present before walk. Built Phase 4.
  • Plan engine — the three-way diff: refresh prior State via Provider::read_resource, compare (a) prior, (b) refreshed reality, (c) desired config, call Provider::plan_resource for computed/requires_replace, and emit ResourceChange{action,before,after,requires_replace}. Action rule: NoOp if all agree; Update if non-force_new attrs differ; Replace if any force_new attr differs (ordered by create_before_destroy); Create if no prior; Delete if in State but absent from config. Propagates Unknown top-down; renders human-readable plan with Sensitive redaction. Invariant: plan is byte-identical given identical config+vars+prior+provider responses. Built Phase 7.
  • Apply executor — walks the graph at -parallelism, calls Provider::apply_resource, resolves Unknowns in dependency order, and writes State incrementally after each instance. Invariant: partial failure leaves a valid, partially-advanced State (failed/interrupted instances marked Tainted/Deposed, dependents deferred), and apply is idempotent — a fresh plan against the new State is all-NoOp when reality is unchanged. Built Phase 8; CBD/cancel hardening Phase 11.

refresh, destroy, import, and -target are thin operations over these components (Phase 10).

3.5 iac-graph — dependency graph engine

Generic Graph<N> over node payload; edges directed dependency → dependent. In: nodes + add_edge. Out: a WalkResult{diagnostics, visited}. detect_cycles() runs Tarjan SCC (returns the offending node lists), transitive_reduction() drops redundant edges for a minimal walk, walk(parallelism, visit) performs the reverse-topological traversal (dependencies before dependents on apply; reversed on destroy). Invariants: cycles are a hard error before any walk; a node's error defers its dependents and is aggregated, never panicked — independent subgraphs continue. Pure graph algorithms, no domain knowledge of resources/providers. Built Phase 4.

3.6 iac-state + StateBackend — durable reality

Holds desired-vs-actual reality across runs and is the only durable artifact. State{version, serial, lineage, resources: Vec<ResourceStateBucket>, outputs}; each ResourceInstance carries attributes: Value, schema_version, dependencies, and status (Ready/Tainted/Deposed). StateBackend trait: lock/unlock (advisory StateLock with LockInfo), read, write. In: a State to persist or a lock request. Out: State or BackendError. Invariants: single-writer (a write requires the held lock); atomic write = temp file + fsync + rename, with .backup of the prior serial; serial increments monotonically; lineage (a Uuid) detects a wrong/forked state file; a crash mid-write leaves the old or new file, never torn. Local backend ships now; remote is a stub. State schema upgrade/migration bridges version. Built Phase 5; lock heartbeat/force-unlock Phase 11.

3.7 iac-provider + plugin RPC — the provider boundary

Defines the Provider trait and the out-of-process plugin protocol; the engine orchestrates providers, it is not a cloud (NON-GOAL). ProviderSchema{provider, resources, data_sources} describes each resource's Attributes (required/optional/computed/sensitive/force_new) and NestedBlocks. CRUD surface: configure, validate_resource, read_resource (refresh), plan_resource (→ PlannedChange{planned, requires_replace}, Unknown for computed), apply_resource, import_resource. Transport: launch provider as a child process, perform a version handshake, then exchange framed protobuf-ish messages for schema negotiation + CRUD; an installer/registry resolves/pins provider binaries. Invariant: provider responses are untrusted (across the TRUST boundary) — every response is type-checked against the negotiated schema and force_new/computed claims are validated, never blindly persisted. A built-in reference provider ("null"/"local") backs tests without external infra. Built Phase 6; timeouts/retries Phase 11.

3.8 The provider process — real infrastructure

A separate executable (child of iac) that actually performs read/plan/apply/import against real APIs (AWS/GCP/etc.). Lives entirely outside the trust boundary and outside this codebase (NON-GOAL: we do not implement any cloud). It crashes, times out, returns malformed or eventually-consistent data — all of which iac-provider must contain. The Walker's -parallelism bounds how many such processes run CRUD concurrently; each is single-purpose per RPC and stateless between calls (all durable truth lives in iac-state). Exercised end-to-end via the reference provider from Phase 6 onward and in the Phase 12 conformance/idempotency gate.

8. Domain Model — Config Language, Value Lattice, and Plan

The domain model is the contract every later phase compiles against: tokens → AST (iac-hcl) → Value/Type lattice (iac-eval) → dependency graph (iac-graph) → the three-way diff producing ResourceChange/Action (iac-core). This section pins lexical grammar, configuration grammar (EBNF), block schemas, the value lattice, conversion/unification, the diff decision table, one end-to-end worked example, the malformed-input → Diagnostic catalogue, and a plan→apply sequence diagram.

8.1 Lexical model — tokens

iac-hcl Lexer emits a token stream with byte-offset Span (start, len, line, col) on every token; never panics, emits Diagnostic{severity:Error} on illegal bytes and resyncs.

Token class Lexeme rule Notes
Ident [A-Za-z_][A-Za-z0-9_-]* block types, attr names, traversal leafs; - allowed mid-ident (HCL2)
Number [0-9]+(\.[0-9]+)?([eE][-+]?[0-9]+)? parsed to Decimal (exact base-10; no binary float drift in plans)
QuotedStr " … " with ${/%{ interp, \n \t \" \\ \uXXXX escapes becomes Expression::Template if it contains interp, else Str
Heredoc <<TAG\n…\nTAG and <<-TAG (indent-stripped) body is template-scanned; closing TAG must be alone on its line
Interp open/close ${ } (value), %{ } (directive: if/for/endif/endfor) nesting tracked by a brace-depth stack in the lexer
Operators == != < <= > >= && || ! + - * / % ?: ... ... is the splat/expand-final marker
Punctuation { } [ ] ( ) , . : = => => only inside object literals
Comments # …, // … (line), /* … */ (block) attached as trivia; dropped from AST, retained for fmt

Whitespace/newlines are insignificant except: newline terminates a single-line attribute; closing heredoc TAG must own its line. LegacyIndex (foo.0) tokenizes as Ident "." Number and is folded to Traversal::LegacyIndex(u64) by the parser.

8.2 Configuration grammar (EBNF)

config-file  = body ;
body         = { attribute | block } ;
block        = IDENT { label } "{" body "}" ;
label        = IDENT | STRING ;
attribute    = IDENT "=" expr NEWLINE ;

expr         = conditional ;
conditional  = logic_or [ "?" expr ":" expr ] ;
logic_or     = logic_and { "||" logic_and } ;
logic_and    = equality  { "&&" equality } ;
equality     = compare   { ( "==" | "!=" ) compare } ;
compare      = additive  { ( "<" | "<=" | ">" | ">=" ) additive } ;
additive     = multiply  { ( "+" | "-" ) multiply } ;
multiply     = unary     { ( "*" | "/" | "%" ) unary } ;
unary        = [ "!" | "-" ] postfix ;
postfix      = primary { index | getattr | splat } ;
index        = "[" expr "]" ;
getattr      = "." IDENT | "." NUMBER ;          (* NUMBER -> LegacyIndex *)
splat        = "." "*" { getattr | index } ;     (* attr.*.id *)

primary      = literal | tuple | object | template | scope_traversal
             | func_call | for_expr | "(" expr ")" ;
literal      = "null" | "true" | "false" | NUMBER | STRING ;
tuple        = "[" [ expr { "," expr } [ "," ] ] "]" ;
object       = "{" [ objelem { ( "," | NEWLINE ) objelem } ] "}" ;
objelem      = ( IDENT | "(" expr ")" | STRING ) ( "=" | ":" ) expr ;
template     = QUOTED_WITH_INTERP | HEREDOC ;     (* -> Expression::Template *)
scope_traversal = IDENT { getattr | index } ;     (* -> Variable | ScopeTraversal *)
func_call    = IDENT "(" [ expr { "," expr } [ "," ] ] [ "..." ] ")" ;  (* "..." -> expand_final *)
for_expr     = "[" "for" IDENT [ "," IDENT ] "in" expr ":" expr [ "if" expr ] "]"   (* tuple/list *)
             | "{" "for" IDENT [ "," IDENT ] "in" expr ":" expr "=>" expr [ "..." ] [ "if" expr ] "}" ; (* object *)

Parser is recursive-descent with the precedence ladder above (Pratt-style for binary ops). A bare IDENT with no following getattr/index → Expression::Variable; with a traversal tail → Expression::ScopeTraversal(Vec<Traversal>). Dynamic blocks are surface sugar: dynamic "ingress" { for_each = … content { … } } parses as an ordinary Block ty=dynamic, expanded in Phase 3.

8.3 Block schemas (top-level)

Top-level Blocks recognized by iac-core's loader; arity = label count.

Block ty Labels Body shape Maps to
resource 2 (<type> <name>) provider attrs + nested blocks; meta: count, for_each, depends_on, lifecycle{ create_before_destroy, prevent_destroy, ignore_changes }, provider managed ResourceAddress (mode Managed)
data 2 (<type> <name>) provider attrs; meta: count, for_each, depends_on, provider ResourceAddress (mode Data); planned as Read
provider 1 (<name>) provider config attrs (validated by Provider::configure) ProviderAddress
variable 1 (<name>) type, default, description, sensitive, nullable, validation{condition,error_message} input → EvalContext.variables
locals 0 arbitrary name = expr EvalContext.locals (lazy, memoized)
output 1 (<name>) value, description, sensitive, depends_on State.outputs / OutputChange
module 1 (<name>) source, version, input attrs; meta: count, for_each, providers, depends_on module instance; ModulePath prefix
terraform 0 required_version, required_providers, backend engine config (not graph nodes)

count and for_each are mutually exclusive on one block (else Diagnostic Error). Validation: required attrs present, no unknown attrs vs ProviderSchema, type-checkable via convert.

8.4 Value lattice + Type system

Value (iac-eval) is the cty-like dynamic value. Each Value has a Type; Unknown(Type) carries its type even when the concrete value is not yet known; Sensitive(Box<Value>) is a privacy mark that propagates through every operation.

Type lattice (⊑ = "convertible-to", convert widens upward):

                      Dynamic            (top: accepts/produces any; "any")
            ┌────────────┼─────────────┬───────────┐
        Object{..}   Tuple[..]     Map(T)        Set(T)/List(T)
            │            │            │              │
          String  ◄──  Number  ◄──  Bool          (elements recurse)
            │
         (leaf)

Mark lattice (orthogonal):   concrete ⊑ Unknown(T)        (knownness)
                             plain    ⊑ Sensitive(plain)  (sensitivity, monotone)

Rules:

  • Knownness: Unknown(T) is the join of all concrete values of type T. Unknown != concrete is always Unknown(Bool) (never false) — Unknown never compares equal to a known value (KEY FACT).
  • Sensitivity: monotone — any operation touching a Sensitive input yields a Sensitive output; redacted in plan render/logs as (sensitive value). Removing the mark requires explicit nonsensitive().
  • Ordering for determinism: Set/Map/Object use BTreeSet/BTreeMap ⇒ sorted iteration ⇒ byte-identical plans (DETERMINISM invariant).

convert(v, to) — cty conversion (subset shown):

from \ to Bool Number String List(T) Set(T) Map(T) Object{..}
Bool id err "true"/"false" err err err err
Number err id decimal str err err err err
String "true"/"false"→Bool else err parse Decimal else err id err err err err
List(A) err err err elem-convert A→T dedup→Set(T) err err
Tuple[..] err err err unify→List unify→Set err by-position→Object
Object{..} err err err err err unify vals→Map(T) attr-convert (missing optional ok)
Null →Null →Null →Null →Null →Null →Null →Null
Unknown(A) Unknown(Bool) Unknown(Number) … propagates Unknown(target) … … …

unify(types) → least common Type (lattice join): all-equal→that type; numeric+string→String only if explicitly forced (else None); mixed structurals→Dynamic; empty→Dynamic. Used for tuple→list/set element typing and conditional-branch result typing. convert failure → EvalError::TypeMismatch{ from, to, span } → Diagnostic.

8.5 The three-way diff + Action computation

A plan diffs three inputs per resource instance: P = prior State value, R = refreshed reality (Provider::read_resource(prior)), C = desired config (evaluated Value, possibly Unknown). Drift = P ≠ R. The provider's plan_resource(prior=R, proposed=C) returns PlannedChange{ planned, requires_replace }; iac-core computes the Action.

In prior? In config? R vs C force_new attr changed? → Action
no yes — — Create
yes no — — Delete
yes (data) yes — — Read (data sources always re-read)
yes yes R == C — NoOp
yes yes R ≠ C no Update
yes yes R ≠ C yes Replace{ create_before_destroy }
yes yes drift P≠R, C==R — NoOp (state reconciled to R; recorded)
yes yes drift P≠R, C≠R per-attr Update/Replace as above, diff vs R

Rules: comparison is against refreshed reality R, not stale prior P, so drift is healed. Replace ordering: create_before_destroy=true → new instance created, dependents re-pointed, old Deposed(DeposedKey) then destroyed; false → destroy-then-create (default). Any operand Unknown ⇒ changed attrs that are Unknown render (known after apply) and the instance is applyable but not fully diffable until apply resolves them top-down. lifecycle.prevent_destroy=true + Delete/Replace ⇒ Diagnostic Error, plan rejected. ignore_changes masks listed attrs from the diff.

8.6 Worked example: variable + two resources, B references A

Config (main.iac):

variable "name" { type = string  default = "web" }

resource "null_thing" "a" {
  label = var.name                 # A.id is computed
}

resource "null_thing" "b" {
  label   = "child-of-${null_thing.a.id}"   # references A.id (Unknown at plan)
  upstream = null_thing.a.id
}

Tokens (excerpt for B.label): Ident("resource") QuotedStr("null_thing") QuotedStr("b") { Ident("label") = QuotedStr-with-interp[ Str("child-of-") ${ Ident("null_thing") . id-traversal } ] …

AST (B.label): Attribute{ name:"label", expr: Template([ Lit(Str "child-of-"), ScopeTraversal([Attr"null_thing",Attr"a",Attr"id"]) ]) }. upstream expr = ScopeTraversal([Attr"null_thing",Attr"a",Attr"id"]).

Evaluation (var.name="web"; provider marks id computed):

Address attr evaluated Value
null_thing.a label Str("web")
null_thing.a id Unknown(String) (computed)
null_thing.b label Unknown(String) (template touches Unknown ⇒ Unknown)
null_thing.b upstream Unknown(String)

Reference extraction → edges (iac-graph): b → a (B references null_thing.a.id), and both a,b → var.name (resolved at eval; not a graph node). DAG: a then b. Reverse-topo walk order on apply: a, then b.

Resulting Plan:

  + null_thing.a
      label = "web"
      id    = (known after apply)

  + null_thing.b
      label    = (known after apply)        # "child-of-${a.id}", a.id unknown
      upstream = (known after apply)

Plan: 2 to add, 0 to change, 0 to destroy.   applyable = true

ResourceChange{ address: null_thing.a, action: Create, before: Null, after: Object{label:Str"web", id:Unknown(String)} }; likewise B. Apply resolves a.id first (provider returns e.g. "a-7f3"), then re-evaluates B's template to "child-of-a-7f3" before apply_resource(b).

8.7 Malformed input → Diagnostic catalogue

Every failure path yields a Diagnostic{severity, summary, detail, span}; the engine emits all collectable diagnostics per pass (not fail-fast), then aborts the affected phase.

Failure Detected in summary Detail / handling
Cyclic reference a→b→a iac-graph detect_cycles "Cycle in resource dependencies" Tarjan SCC lists the cycle members; plan rejected
Unknown function frobnicate(x) iac-eval registry lookup "Call to unknown function" suggest nearest by edit-distance; EvalError::NoSuchFunction
Type mismatch count = "x" iac-eval convert "Invalid value for input" from=String, to=Number; span on the expr
Dangling traversal var.nope iac-eval scope resolution "Reference to undeclared variable" lists in-scope names; EvalError::UnknownSymbol
force_new attr changed Phase 7 diff "Resource must be replaced" names triggering attr(s) from PlannedChange.requires_replace; Action=Replace
Drift detected Phase 7 refresh "Objects have changed outside of …" shows P≠R per attr; reconciles state to R
count+for_each both set loader "count and for_each are mutually exclusive" one block, two meta-args
prevent_destroy + Delete Phase 7 diff "Instance cannot be destroyed" plan rejected with the lifecycle span
Parse error (unclosed {) iac-hcl parser "Unterminated block" span at open brace; parser resyncs to next top-level block
Heredoc TAG mismatch iac-hcl lexer "Unterminated heredoc" span at <<TAG; expected closing TAG

8.8 Sequence: plan then apply

 Operator    iac-cli   iac-core      iac-eval   iac-graph   iac-state   iac-provider
    │  plan     │          │             │           │           │            │
    ├──────────►│  load    │             │           │           │            │
    │           ├─parse───►│ (iac-hcl AST)│          │           │            │
    │           │          ├─evaluate────►│          │           │            │
    │           │          │◄─values+Unknown─────────│           │            │
    │           │          ├─build graph──────────────►│         │            │
    │           │          │◄─DAG (cycle-checked)──────│         │            │
    │           │          ├─read prior State──────────────────►│            │
    │           │          │◄─prior (P)────────────────────────│            │
    │           │          ├─refresh: read_resource──────────────────────────►│
    │           │          │◄─reality (R)───────────────────────────────────│
    │           │          ├─plan_resource(R,C)──────────────────────────────►│
    │           │          │◄─PlannedChange(planned, requires_replace)───────│
    │           │  Plan    │  (three-way diff → ResourceChange/Action)        │
    │◄──render──┤◄─────────┤                                                  │
    │  apply    │          │                                                  │
    ├──────────►│  lock────────────────────────────────────────►│            │
    │           │          ├─walk reverse-topo, ≤ -parallelism                │
    │           │          ├─apply_resource (per node, deps first)───────────►│
    │           │          │◄─new Value (Unknowns resolved)──────────────────│
    │           │          ├─write State incrementally (atomic+serial++)─────►│
    │           │          │  … repeat per node; defer dependents on error    │
    │           │  unlock──────────────────────────────────────►│            │
    │◄──summary─┤                                                             │

Plan is read-only (no mutation, no state write — only refresh reads). Apply holds the StateLock for its whole duration, walks dependencies-before-dependents, resolves Unknowns top-down, and writes State incrementally (atomic temp+fsync+rename, .backup of prior serial, serial++) so a crash leaves old-or-valid state — never torn (STATE SAFETY invariant). apply(plan) then a fresh plan against the new state ⇒ all-NoOp (IDEMPOTENCY invariant).
