Failure Modes & Recovery

Taxonomy

F1 — Validation Rejection (expected, benign path)

  • Symptom: decode() returns Err(SerError::*) on a message from a peer.
  • Root causes: wire corruption; version mismatch; malicious input; framing bug in sender.
  • Detection: validation_rejections_total counter incremented per error variant.
  • Automatic recovery: caller drops the message; no state mutation occurred.
  • Manual recovery: capture raw bytes via ser-tool wire-diff; identify sender crate version.
  • Forensic artifacts: rejection variant + segment id + byte offset logged at WARN; raw bytes optionally snapshotted.
  • Mitigation: upgrade sender; fix framing; add fuzz corpus entry.

F2 — Schema Incompatibility

  • Symptom: SerError::IncompatibleSchema; field reads return wrong defaults or fail.
  • Root causes: reader schema newer than writer schema (missing required field); field id reuse (evolution violation); incorrect schema hash.
  • Detection: schema_mismatch_total; ser-evolve compat check in CI.
  • Automatic recovery: decode aborts before any accessor is called; no partial read.
  • Manual recovery: run ser-tool schema-diff <old.szs> <new.szs>; identify conflicting field ids.
  • Forensic artifacts: both schema hashes logged at ERROR; stored schema bytes in registry.
  • Mitigation: enforce append-only field ids via ser-evolve gate in CI/CD.

F3 — Arena / Builder OOM

  • Symptom: Builder returns Err(SerError::OutOfBounds) when arena limit reached.
  • Root causes: encoding larger message than arena capacity; nested struct loops in builder code (application bug).
  • Detection: encode_arena_exhausted_total; encode latency spike.
  • Automatic recovery: builder drops all segments; error propagated to caller.
  • Manual recovery: increase ArenaConfig::max_bytes; profile message size distribution.
  • Forensic artifacts: arena high-water-mark metric; stack trace in WARN log.
  • Mitigation: set max_bytes = 2x p99 message size; add size budgets in schema definitions.

F4 — Segment Framing Corruption (persistent store or transport)

  • Symptom: SerError::Truncated; CRC-32C mismatch; partial segment.
  • Root causes: disk bit-flip; network truncation; writer crash mid-write; off-by-one in framing code.
  • Detection: crc_failures_total; truncated_messages_total; framing unit tests.
  • Automatic recovery: message discarded; caller receives error.
  • Manual recovery: ser-tool inspect --raw <bytes> to identify intact segments; reconstruct from replica.
  • Forensic artifacts: segment id, declared length, actual length logged; raw bytes snapshotted (configurable).
  • Mitigation: write-ahead pattern: write to temp file, fsync, rename; CRC verification on read.

F5 — Layout Nondeterminism (platform/compiler divergence)

  • Symptom: message encoded on platform A rejected/misread on platform B; integration tests fail across targets.
  • Root causes: ser-layout bug allowing platform-dependent padding; endianness error; word-size assumption.
  • Detection: cross-platform integration test: encode on x86-64, decode on aarch64 (CI matrix); golden-byte fixtures.
  • Automatic recovery: none; layout bugs are silent data corruption.
  • Manual recovery: compare ser-tool inspect output on both platforms; diff layout dump.
  • Forensic artifacts: Layout struct logged at schema load time; golden fixture files in ser-bench/fixtures/.
  • Mitigation: layout determinism tests in CI; fuzz layout with property-based tests; explicit little-endian read/write helpers.

F6 — Codegen Drift (generated accessors out of sync with schema)

  • Symptom: generated Reader accessor reads wrong field offset; silent wrong-value reads.
  • Root causes: schema updated, codegen not re-run; codegen template bug; schema hash not embedded in generated file.
  • Detection: generated file embeds SCHEMA_HASH: u64; runtime checks hash at startup; mismatch → panic or error.
  • Automatic recovery: runtime refuses to use accessor set with wrong hash.
  • Manual recovery: re-run ser-cli codegen; verify hash matches.
  • Forensic artifacts: hash mismatch logged at ERROR with both hashes.
  • Mitigation: CI step: re-run codegen after any .szs change and verify no diff.

F7 — Panic in Unsafe Accessor (validation soundness bug)

  • Symptom: process crash (segfault / panic) during Reader field access after validation passed.
  • Root causes: validation pass missed an OOB case; UB in cast; platform alignment assumption wrong.
  • Detection: MIRI in CI; cargo fuzz targets for decode; crash dumps.
  • Automatic recovery: process restarts (supervised); message not re-processed (dead-letter queue).
  • Manual recovery: reproduce with minimal fuzz corpus entry; file P0 bug; hotfix unsafe cast.
  • Forensic artifacts: crash dump; fuzz corpus entry; backtrace.
  • Mitigation: MIRI, sanitizers (ASAN/UBSAN via -Zsanitizer), property tests, fuzzing; strict unsafe code review.

F8 — Schema Registry Unavailability

  • Symptom: ser-tool or ser-evolve cannot fetch schema; compat checks skipped.
  • Root causes: registry service down; network partition; file system full.
  • Detection: schema_registry_errors_total; health-check endpoint.
  • Automatic recovery: cached schema used if present (TTL configurable); degrade to hash-only check.
  • Manual recovery: restore registry from backup; re-register schemas from .szs files.
  • Forensic artifacts: registry access log; last-known-good schema cache.
  • Mitigation: local schema cache; registry replicated; ser-tool embeds schema hash in generated code.

F9 — Encode/Decode Latency Regression

  • Symptom: p99 encode or decode latency exceeds SLO threshold; throughput drops.
  • Root causes: memory allocation regression; validation O(N²) bug; pointer-chasing cache miss.
  • Detection: encode_duration_seconds / decode_duration_seconds histograms; ser-bench differential harness.
  • Automatic recovery: none (performance, not correctness).
  • Manual recovery: run ser-bench against prior baseline; profile with perf/flamegraph; bisect commits.
  • Forensic artifacts: ser-bench reports; pprof flame graphs in CI artifacts.
  • Mitigation: ser-bench gate: PR blocked if p50/p99 regresses > 5% vs baseline.

F10 — Evolution Invariant Violation (field id reuse)

  • Symptom: reader misinterprets field as different type; silent data corruption after schema change.
  • Root causes: developer reused a deleted field id; reserved hole not marked in IDL; ser-evolve gate bypassed.
  • Detection: ser-evolve compat-check compares old and new schema; field-id registry in schema hash.
  • Automatic recovery: ser-evolve blocks schema publish if violation detected.
  • Manual recovery: revert schema change; assign new field id; re-publish.
  • Forensic artifacts: ser-evolve diff report; schema version history in registry.
  • Mitigation: ser-evolve required in CI for any .szs change; field id monotonically increasing, stored in IDL.

F11 — Stale Cached Schema (registry cache divergence)

  • Symptom: reader uses outdated schema; new optional fields silently read as defaults even when sender writes real values.
  • Root causes: schema registry cache TTL too long; registry update not propagated; cache invalidation bug.
  • Detection: schema_registry_cache_age_seconds gauge; alert if age > TTL * 2.
  • Automatic recovery: cache miss forces synchronous fetch; stale cache returns warning metric.
  • Manual recovery: ser-tool schema flush-cache; force registry sync.
  • Forensic artifacts: cache hit/miss ratio metric; last-fetch timestamp logged.
  • Mitigation: short TTL (60 s default); schema hash checked on every decode; mismatch triggers re-fetch.

F12 — Benchmark Regression False Positive

  • Symptom: CI blocks PR due to reported latency regression; actual code is correct and fast.
  • Root causes: noisy CI runner; CPU frequency scaling; GC in benchmark harness (not applicable — Rust; but system noise applies); benchmark isolation failure.
  • Detection: ser-bench reports confidence interval; CI gate requires regression > 5% AND p-value < 0.05.
  • Automatic recovery: re-run benchmark 3 times; median used.
  • Manual recovery: run ser-bench locally on dedicated hardware; compare against pinned baseline.
  • Forensic artifacts: ser-bench raw timing CSV committed to CI artifacts.
  • Mitigation: pin benchmark runner to isolated CPU; disable turbo boost; use criterion with 100-sample minimum.
