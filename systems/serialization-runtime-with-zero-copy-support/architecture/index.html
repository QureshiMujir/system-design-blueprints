3. Architectural Overview

3.1 Canonical Architecture Diagram

    schema IDL (.szs)
            |
      [ser-schema] parse -> Schema (TypeDefs, Fields, evolution rules) -> SchemaHash
            |
      [ser-layout] assign offsets, data-section vs pointer-section, alignment/padding, list/union layout (deterministic)
            |
            +--> [ser-codegen] emit per-type Reader/Builder accessors (target lang) | reflective fallback
            |
    BUILD:  app --Builder--> [ser-encode] arena/segment alloc -> write data words + pointers -> [ser-runtime] Message (framing)
            |                                                                                          |
            |                                                                         wire bytes (segments + frame header)
            |                                                                                          |
    READ:   wire bytes --> [ser-decode] VALIDATION PASS (bounds, alignment, pointer targets, recursion/segment limits)  <== trust boundary
            |                                  | on success -> Reader<'a, T>
            |                       zero-copy: accessors cast directly into buf, NO parse, NO alloc, lazy field reads
            |                                  app reads fields
      [ser-evolve] forward/backward compat check (schema vs schema)     [ser-telemetry] taps encode/decode/validate
      [ser-tool] inspector / wire-diff / schema registry

3.2 ser-schema — IDL Parser + Schema Model

  • Input: .szs source text; output: Schema { types, root, schema_hash }.
  • Responsibilities: tokenize, recursive-descent parse, build TypeDef/Field AST, resolve names → TypeIds, assign FieldIds, compute SchemaHash (deterministic hash over canonical type/field ordering), run schema-level validation (no duplicate ids, no forward-reference cycles, union exhaustiveness).
  • Data flow: .szs text → token stream → AST → resolved Schema → SchemaHash.
  • Trust boundary contribution: schema validity (not wire validity) — malformed schemas are rejected here, before layout or encode begins.
  • Failure modes: SerError::SchemaInvalid on parse error, duplicate field id, unresolvable type reference, cyclic struct (non-list).
  • External interface: parse_schema(src: &str) -> Result<Schema, SerError>.

3.3 ser-layout — Deterministic Layout Computer

  • Input: Schema; output: Schema with all TypeDef.layout fields populated.
  • Responsibilities: assign Field.offset (byte offset within data section), split fields into data-section scalars vs pointer-section references, compute Layout { data_words, ptr_words, align }, handle list element layout, union discriminant + arm layout, padding/alignment rules.
  • Invariant: layout is a pure function of schema — identical schema → byte-identical layout on every platform; no host-layout influence.
  • Failure modes: overflow if data_words or ptr_words exceeds u16::MAX; SerError::SchemaInvalid.
  • Performance implication: layout runs once at build time (code-gen) or once per schema load (reflective path); O(|fields|) per type.

3.4 ser-codegen — Accessor Code Generator

  • Input: Schema + target language tag; output: generated source file(s) with per-type Reader<'a, T> / Builder<'a, T> accessor impls.
  • Responsibilities: emit fn get_<field>(&self) -> <WireType> for each field (Reader), fn set_<field>(&mut self, v: <WireType>) (Builder); embed offset constants and default values; emit From<&'a [u8]> for Reader.
  • Reflective fallback: ser-runtime exposes a reflective accessor path using Schema at runtime; no generated code required, ~3× slower.
  • Build integration: invoked from build.rs; generated files placed in $OUT_DIR; hermetic (no network, no disk side-effects beyond $OUT_DIR).

3.5 ser-encode — Builder + Arena

  • Input: Schema + app data via Builder API; output: Message { segments, root }.
  • Responsibilities: bump-allocator arena for segment bytes; Builder<'a, T> assigns field slots by offset, writes scalars into data section, allocates child structs/lists into arena, writes pointer words, handles segment overflow via new-segment alloc, canonical-mode zeroing of padding.
  • Concurrency boundary: Builder is single-threaded per message; multiple independent messages may be built concurrently (arena per message).
  • Data flow: app calls → Builder methods → arena writes → Message ownership transfer → framing in ser-runtime.
  • Failure modes: SerError::OutOfBounds if segment limit exceeded; alloc failure (OOM) propagated as error, not panic.

3.6 ser-decode — Validation Pass + Reader (Trust Boundary)

  • Input: raw wire bytes (&'a [u8]), Schema; output: Reader<'a, RootType> on success, SerError on failure.
  • THE TRUST BOUNDARY: every safety invariant is established here. Post-validation, no check is needed.
  • Validation pass checks (in order): frame header parse, segment count ≤ limit, total bytes ≤ limit, each pointer target within declared segment, alignment of every pointer target, recursion/nesting depth ≤ limit, list element count × element size does not overflow.
  • Zero-copy read: Reader<'a, T> { buf: &'a [u8], base: Offset } — accessor methods compute base + field_offset, cast &buf[range] to scalar or sub-Reader; NO heap alloc, NO copy.
  • Absent field: if base + field_offset is beyond the message's declared data section (older writer), accessor returns Field.default.
  • Failure modes: SerError::{OutOfBounds, Misaligned, BadPointer, DepthExceeded, Truncated}.
  • Security invariant: amplification attack impossible — validation is O(message bytes), bounded recursion; no quadratic fan-out.

3.7 ser-runtime — Public API + Message Framing

  • Input/output: app-facing; bridges encode/decode, owns segment buffers, provides framing.
  • Responsibilities: encode(builder: Builder) -> Bytes, decode<'a, T>(buf: &'a [u8], schema: &Schema) -> Result<Reader<'a, T>, SerError>, validate(buf: &[u8], schema: &Schema) -> Result<(), SerError>; message frame header (segment table: count + per-segment byte length); SchemaHash embedding in frame.
  • Persistence boundary: runtime hands opaque Bytes to caller; caller owns transport/storage.
  • Protocol boundary: frame header format is the external wire contract (versioned, layout-stable).
  • Concurrency: encode and decode are stateless functions over owned/borrowed data; safe to call from multiple threads without synchronization.

3.8 ser-evolve — Schema Evolution Checker

  • Input: two Schema values (old, new); output: CompatResult { forward_ok, backward_ok, violations: Vec<CompatViolation> }.
  • Responsibilities: enforce append-only field id rule (no id reuse, no id removal below max), verify optional-field default presence, flag union-arm removal, detect type-change violations (WireType mismatch on same FieldId).
  • Integration points: CI gate (build.rs or test), ser-cli schema diff, runtime schema-mismatch handling (SchemaHash comparison in frame).
  • Failure modes: returns violations list; does not panic; caller decides policy (warn vs abort).

3.9 ser-tool — Inspector / Wire-Diff / Registry

  • Input: wire bytes + schema (inspect/diff); schema files (registry).
  • Responsibilities: pretty-print a message to human-readable form (reflective decode path), byte-level hex dump with field annotations, wire-diff (two messages → field-by-field delta), schema registry (store/retrieve/version schema by SchemaHash, flat-file or SQLite backend).
  • Operational importance: primary debugging surface for wire corruption, field default issues, evolution regressions.

3.10 ser-telemetry — Metrics + Tracing

  • Input: tap points at encode entry/exit, validation entry/exit, decode entry/exit.
  • Responsibilities: record encode/decode/validate wall-clock latency (histogram), byte counts, validation rejection counts (by SerError variant), tracing span integration (compatible with tracing crate).
  • Failure modes: telemetry must be infallible; metric emission errors are silently dropped, never propagated to caller.
  • No-overhead path: tap API uses #[inline] + cfg(feature = "telemetry"); zero cost when feature disabled.

8. Domain Model — Serialization Wire Format & Zero-Copy Runtime

8.1 Overview: Core Entities and Relationships

Schema ──owns──> TypeDef* ──owns──> Field*
   |                |                  |
SchemaHash      Layout             FieldId, Offset, WireType, DefaultVal, since_version
   |
   └──> evolution rules (append-only, reserved holes)

Message ──owns──> Segment* ──contains──> raw bytes (words, pointers)
    |                                        |
  root: Pointer                   data-section | pointer-section
    |
  Reader<'a, T> ──borrows──> Segment.bytes (lifetime-tied, zero-copy)
  Builder<'a, T> ──writes──> Arena (segment allocator)

Entity inventory:

Entity Cardinality Invariant
Schema 1 per wire format version Identified by SchemaHash; immutable once published
TypeDef N per Schema id unique within Schema; layout is pure fn of TypeDef
Field N per TypeDef FieldId unique within TypeDef; offset non-overlapping
Layout 1 per TypeDef data_words * 8 + ptr_words * 8 = total struct size
Segment 1..N per Message SegmentId contiguous 0..N-1; max count bounded
Pointer embedded in segment Resolves within declared segment; far ptr stays in-message
Reader<'a,T> 0..1 per access path buf lifetime ≥ Reader lifetime; no internal allocation
Builder<'a,T> 1 per encode session Backed by Arena; finalized to Message on seal()

8.2 Wire Format: Segment Layout

MESSAGE FRAMING (little-endian):
 ┌────────────────────────────────────────────────────────────┐
 │ frame header (8 bytes):                                    │
 │   [0..4] segment_count: u32  (number of segments, 1-based) │
 │   [4..8] reserved: u32 = 0                                 │
 ├────────────────────────────────────────────────────────────┤
 │ segment_sizes table: segment_count * 4 bytes               │
 │   each entry: size in words (u32, little-endian)           │
 │   pad to 8-byte boundary if segment_count is even          │
 ├────────────────────────────────────────────────────────────┤
 │ Segment[0] bytes  (size_words[0] * 8 bytes)                │
 │ Segment[1] bytes  ...                                      │
 │ ...                                                        │
 └────────────────────────────────────────────────────────────┘
root pointer: first word of Segment[0] (always a Struct pointer)

Frame header invariants:

  • segment_count ≥ 1; max enforced limit: 512 segments (amplification defense).
  • Each segment size: max 512 MiB (words = 67,108,864); sum of all segments ≤ 1 GiB per message.
  • Framing is NOT part of zero-copy path — framing header is parsed into Message metadata.
  • Segment bytes after framing are never copied; Reader borrows directly from transport buffer.

8.3 Pointer Encoding

Three pointer kinds, all 8 bytes (one word), little-endian:

STRUCT POINTER (bits [1:0] = 00):
 ┌────────────────┬──────────────┬──────────────┐
 │  [63:32] B:u16 │ [31:16] A:u16│ [1:0]=00 off │
 │  ptr_words     │  data_words  │  word offset  │
 └────────────────┴──────────────┴──────────────┘
 bits [31:2]: signed offset in words from end-of-pointer to target struct
 bits [47:32]: data section size in words (A = data_words)
 bits [63:48]: pointer section size in words (B = ptr_words)

LIST POINTER (bits [1:0] = 01):
 ┌──────────┬───────────────┬────────────┐
 │ elem_type│  element_count│ [1:0]=01   │
 │  [2:0]   │  [63:35] u29  │  offset    │
 └──────────┴───────────────┴────────────┘
 bits [31:2]: signed offset in words from end-of-pointer to list data
 bits [34:32]: element size tag (0=void, 1=1-bit, 2=1-byte, 3=2-byte, 4=4-byte, 5=8-byte, 6=ptr, 7=composite)
 bits [63:35]: element count (for composite: total words in list, then per-element tag word)

FAR POINTER (bits [1:0] = 10):
 ┌──────────────────────┬──────────────┐
 │   [63:32] segment_id │ [31:3] off   │
 │                      │ [2]=landing  │
 │                      │ [1:0]=10     │
 └──────────────────────┴──────────────┘
 landing=0: far ptr -> struct/list ptr in target segment at offset
 landing=1: double-far ptr -> two consecutive words in target segment (far-ptr + tag)
 segment_id: SegmentId of target; must be in-message (0..segment_count-1)

NULL POINTER: all 64 bits = 0 → field absent; read returns default value

Pointer invariants:

  • Struct pointer: data_words and ptr_words match TypeDef.layout exactly — validated in pass.
  • List pointer: element_count * elem_size ≤ segment bytes remaining.
  • Far pointer: segment_id < segment_count; offset within segment bounds.
  • Double-far: two target words within same segment, both within bounds.
  • Circular pointers: caught by recursion depth counter (max 64 frames).
  • Self-referential segment[0]→segment[0] cycles: detected by tracking visited (seg, offset) pairs.

8.4 Data Section and Pointer Section Layout

STRUCT MEMORY LAYOUT in segment:
 ┌─────────────────────────────────────────────┐
 │  data section: data_words * 8 bytes          │
 │  Field values by WireType:                   │
 │    Scalar (Bool..F64, Enum): at bit/byte off │
 │    Union: tag word + active arm field        │
 ├─────────────────────────────────────────────┤
 │  pointer section: ptr_words * 8 bytes        │
 │  One 8-byte pointer slot per reference field │
 │  (Struct, List, Text, Bytes, Pointer)        │
 └─────────────────────────────────────────────┘

FIELD PLACEMENT RULES:
  Bool         → 1 bit; packed into data word, bit offset = field.offset
  I8/U8        → 1 byte at byte offset (8-aligned within word)
  I16/U16      → 2 bytes, 2-byte aligned
  I32/U32/F32  → 4 bytes, 4-byte aligned
  I64/U64/F64  → 8 bytes (full data word), 8-byte aligned
  Enum         → 2 bytes (u16 discriminant), 2-byte aligned
  Union        → 2-byte tag (Enum discriminant) + active arm field in same or next position
  Text/Bytes   → pointer section; points to list-of-U8 + NUL for Text
  Struct/List  → pointer section; struct or list pointer

Alignment padding rules:

  • Data section size rounded up to multiple of 8 bytes (1 word).
  • Pointer section size always in words (8-byte multiples).
  • No padding between data and pointer sections beyond word alignment.
  • Intra-word field packing: smaller scalars share a word, packed low-to-high by FieldId.
  • Bool packing: up to 64 bools in one data word; bit offset = FieldId % 64.

8.5 List Encoding

COMPOSITE LIST (structs or unions):
 ┌──────────────────────────────────────────────┐
 │  tag word: Struct pointer with offset=−1     │
 │    data_words=X, ptr_words=Y, count=N        │
 ├──────────────────────────────────────────────┤
 │  element[0]: data section (X words)          │
 │              pointer section (Y words)       │
 │  element[1]: ...                             │
 │  ...                                         │
 └──────────────────────────────────────────────┘

PACKED SCALAR LIST (non-composite):
 element_count * element_size bytes, no padding between elements
 (elem_size from list pointer element tag)

VOID LIST:
 element_count > 0 legal; zero bytes stored; accessor returns ()

TEXT LIST / BYTES LIST:
 List of pointer; each pointer → a list-of-U8 (Text has trailing NUL, counted in length)

List invariants:

  • Composite: tag word data_words/ptr_words match element TypeDef.layout.
  • element_count * (data_words + ptr_words) * 8 ≤ remaining segment bytes from list start.
  • Nested list max depth: 64 (shared with struct recursion counter).
  • Empty list: element_count=0; tag word present; zero bytes follow.
  • Text: UTF-8 enforced at validation; trailing NUL byte present but not counted in user-visible length.

8.6 Schema State Machine

States of a Schema through its lifecycle:

  [DRAFT] ──parse(.szs)──> [PARSED] ──layout()──> [LAID_OUT] ──hash()──> [PUBLISHED]
     |                        |                       |                       |
  parse err              field conflict          alignment err           SchemaHash stable
  -> Err(SchemaInvalid)  -> Err(SchemaInvalid)  -> Err(SchemaInvalid)   -> immutable

  [PUBLISHED] ──evolve(new_schema)──> [COMPAT_CHECK]
                                           |
                              compat? ──> [EVOLVED] (new SchemaHash)
                              incompat? -> Err(IncompatibleSchema)

Schema state transitions (normative):

From Event To Guard
DRAFT parse() success PARSED All TypeIds unique, all FieldIds unique per type
DRAFT parse() failure ERROR Lex/parse error; schema unusable
PARSED layout() success LAID_OUT No overlapping offsets; alignment satisfied
PARSED layout() failure ERROR Field id collision or alignment impossible
LAID_OUT hash() PUBLISHED SchemaHash = xxhash3(canonical schema bytes)
PUBLISHED evolve(new) COMPAT_CHECK New schema provided
COMPAT_CHECK compat pass EVOLVED New fields are append-only, old ids/offsets unchanged
COMPAT_CHECK compat fail ERROR Err(IncompatibleSchema) with diagnostic

8.7 Validation Pass State Machine

The validation pass is the single trust boundary. Operates on raw bytes, produces Reader or error.

INPUT: &[u8] (wire bytes) + Schema

  START
    │
    ▼
  [PARSE_FRAME] — extract segment_count, segment sizes, verify sum ≤ limit
    │ err → Err(Truncated | OutOfBounds)
    ▼
  [VALIDATE_SEGMENTS] — verify each segment: size matches frame table, non-overlapping
    │ err → Err(OutOfBounds | Truncated)
    ▼
  [READ_ROOT_PTR] — word[0] of segment[0]; must be Struct pointer
    │ err → Err(BadPointer)
    ▼
  [VALIDATE_NODE(ptr, depth)] — recursive; depth counter starts at 0
    │
    ├─ struct ptr: check data_words/ptr_words vs schema layout
    │              check target range in segment
    │              recurse each pointer-section slot (depth+1)
    │
    ├─ list ptr:   check element_count * size ≤ segment remaining
    │              if composite: validate tag word; recurse each element (depth+1)
    │              if pointer: recurse each pointer (depth+1)
    │
    ├─ far ptr:    segment_id < segment_count; offset in bounds
    │              if double-far: validate two landing words
    │              continue validation at resolved location
    │
    └─ null ptr:   OK; field will read default
    │
    ▼ (all nodes validated)
  [EMIT_READER] — Reader<'a, T> { buf: &'a [u8], base: root_offset }
    │
  DONE — zero-copy access is now safe

Validation failure modes and error mapping:

Failure SerError Detail
Frame too short Truncated segment_count * 4 + 8 > buf.len()
Segment size overflow OutOfBounds sum of segment words * 8 > buf.len()
Segment count > 512 OutOfBounds amplification guard
Struct range OOB OutOfBounds ptr_target + (data+ptr)*8 > segment end
Misaligned pointer target Misaligned target % 8 ≠ 0
data_words mismatch BadPointer ptr.data_words ≠ schema layout.data_words
ptr_words mismatch BadPointer ptr.ptr_words ≠ schema layout.ptr_words
Far seg_id ≥ count BadPointer segment does not exist
Depth > 64 DepthExceeded recursion/cycle guard
List count overflow OutOfBounds count * size > segment remaining
Unknown union discriminant BadPointer value not in schema enum
Text missing NUL SchemaInvalid UTF-8 list without trailing 0
Far loop (circular) DepthExceeded (seg, offset) revisit detected

8.8 Reader Access Model (Zero-Copy)

Reader<'a, T> borrows buf: &'a [u8]. Accessors perform:
  1. Compute field byte offset: base + data_section_start + field.offset
  2. Cast &buf[off..off+size] to &T directly (valid because validation guarantees alignment + bounds)
  3. Return reference (scalar) or new Reader<'a, SubT> (sub-struct/list)

NO allocation. NO parse. NO copy. One memory access per field.
Absent field (null pointer): returns field.default as DefaultVal (no buffer access).

Reader operations by WireType:

WireType Accessor returns Implementation
Bool bool buf[word_off] >> bit_off & 1
I8..I64 i8..i64 ptr::read_unaligned (LE) or direct cast if aligned
U8..U64 u8..u64 same
F32/F64 f32/f64 bit-cast from u32/u64
Enum EnumType read u16 discriminant; map to variant
Struct Reader<'a, SubT> resolve pointer; return new Reader at target
List ListView<'a, ElemT> resolve list pointer; return slice or iterator
Union UnionReader<'a> read tag word; dispatch to active arm Reader
Text &'a str resolve list-of-U8; cast to str (UTF-8 validated)
Bytes &'a [u8] resolve list-of-U8; return slice
Pointer AnyReader<'a> opaque; caller downcasts with schema type

Lifetime rules:

  • Reader<'a, T> lifetime 'a tied to the original buffer slice.
  • Nested Readers share the same 'a — no sub-lifetime introduced.
  • Compiler enforces: buffer cannot be freed while any Reader alive.
  • Explicit deep-copy: reader.to_owned() → allocates; not zero-copy. Opt-in only.

8.9 Builder / Encode Model

Builder<'a, T> writes into Arena:
  Arena { segments: Vec<Segment>, current: usize, cursor: usize }

  alloc_struct(layout) → Builder<'a, T>:
    if cursor + size ≤ segment.capacity → bump cursor, return builder at offset
    else → alloc new Segment (next SegmentId), write far pointer in current segment

  set_field(field_id, value):
    compute byte offset from layout
    write value at offset (little-endian)

  init_struct(field_id) → Builder<'a, SubT>:
    alloc SubT in current/new segment
    write Struct pointer into parent pointer section

  init_list(field_id, count) → ListBuilder<'a, ElemT>:
    alloc count * elem_size bytes
    write List pointer in parent pointer section

  seal() → Message:
    finalize all segments; fix up far pointers; emit framing header

Builder invariants:

  • Arena never reallocates existing segments (pointers remain valid).
  • Segment growth: new segment allocated when current segment would overflow.
  • Far pointer written immediately when crossing segment boundary.
  • Default field values: zero for scalars (XOR-encoded default: write field.default ^ value).
  • Canonical mode: all padding zeroed; fields written in FieldId order; no dead space.
  • Non-canonical mode: padding unspecified (may contain garbage for performance).

8.10 Union Encoding

UNION in data section:
 ┌──────────────────────────────────────────────┐
 │  tag word (2 bytes): u16 discriminant         │
 │    offset = union.offset (from layout)        │
 ├──────────────────────────────────────────────┤
 │  active arm field: at arm.offset              │
 │    (may overlap with other union arms;        │
 │     only active arm is valid)                 │
 └──────────────────────────────────────────────┘

Unnamed union (top-level): tag at data_words[0] bits [15:0]
Named union: tag at layout-assigned offset; arm fields follow

Validation: discriminant value must be in schema enum; unknown arm → BadPointer
Reader: read tag → match arm → dispatch accessor
Builder: set discriminant; zero out overlapping arm bytes before writing active arm
Evolution: new arms added at end; old readers see unknown tag → return default/error

8.11 Schema Evolution Worked Example

Scenario: UserProfile v1 → v2 adding an optional field.

v1 IDL:
  struct UserProfile {   # TypeId = 42
    @0 id:    U64;       # FieldId=0, offset=word0, since_version=1
    @1 name:  Text;      # FieldId=1, ptr_slot=0,  since_version=1
  }
  Layout v1: data_words=1, ptr_words=1

v2 IDL (evolved):
  struct UserProfile {
    @0 id:    U64;       # unchanged
    @1 name:  Text;      # unchanged
    @2 score: F64 = 0.0; # FieldId=2, offset=word1, since_version=2, default=0.0
  }
  Layout v2: data_words=2, ptr_words=1

Forward compatibility (v1 reader, v2 wire):

  • v1 reader: data_words=1 → reads only word0 (id); ignores word1 (score).
  • Pointer: v2 struct pointer has data_words=2; v1 reader treats extra words as padding → safe.
  • v1 reader accesses name (ptr_slot=0) → ptr_words=1 still; offset unchanged → correct.

Backward compatibility (v2 reader, v1 wire):

  • v2 reader: data_words=2; v1 wire has data_words=1.
  • Struct pointer in v1 wire has data_words=1 < schema's 2 → score field absent.
  • Accessor for score: field.offset > actual data section → return field.default (0.0).
  • No error; v2 reader gracefully reads default.

ser-evolve checks (compile-time/registration):

  • All v1 FieldIds present in v2 with same type + offset → OK.
  • New fields have since_version > v1.schema_version → OK.
  • No field removed without reserved hole → OK.
  • IncompatibleSchema if: field type changed, offset changed, id reused for different type.

8.14 DefaultVal Encoding

DefaultVal per WireType:
  Scalar  → field.default XOR wire_value (XOR-encoded to allow zero-default = zero-wire)
  Text    → null pointer → return "" (empty str)
  Bytes   → null pointer → return &[]
  Struct  → null pointer → return "default struct" (all fields default recursively)
  List    → null pointer → return empty ListView
  Enum    → field.default = discriminant u16
  Bool    → field.default = 0 or 1 (bit)

XOR encoding invariant: zero bytes on wire = field holds its default value.
  e.g. default=5 (U8): write (5 XOR value) at offset; read (5 XOR wire_byte)

8.15 Canonical Encoding

Canonical mode properties:

  • All padding bytes = 0x00.
  • Fields written in ascending FieldId order within each struct.
  • No dead/unreachable segments.
  • List elements in original order (list ordering is app-defined; canonical does not sort).
  • Far pointers minimized: prefer same-segment when possible.
  • Result: SHA-256(canonical_bytes) is stable identity for dedup/caching.
  • Canonical encode is ~10–15% slower than non-canonical (extra zeroing pass).
  • Non-canonical encode: default; padding unspecified; faster.
  • Conversion: Message::canonicalize() → allocates new Arena, re-encodes.
