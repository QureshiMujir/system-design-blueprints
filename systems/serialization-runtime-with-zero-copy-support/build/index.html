⬜ Phase 2 — Layout computation — assign field offsets, data-section vs pointer-section split, alignment/padding, list + union layout, deterministic layout-from-schema §14

Objectives
  • Implement ser-layout: fn compute_layout(schema: &Schema) -> Result<Schema, SerError> — returns a new Schema with all TypeDef::layout and Field::offset fields populated.
  • Layout rules (normative): data section holds all scalar fields + union discriminant + bool fields (byte-aligned, not bit-packed — documented simplicity choice); pointer section holds all non-scalar fields (WireType::Struct, List, Text, Bytes, Pointer), appended after the data section; word = 8 bytes, data section padded to word boundary, pointer section always word-aligned (1 pointer = 1 word); data fields sorted by descending alignment to minimize padding, pointer fields assigned sequentially; union discriminant (u16) occupies the first 2 bytes with arms sharing an overlay sized to the largest arm; list element stride = wire_size(elem).unwrap_or(8), total bytes = stride * count; Layout{data_words,ptr_words,align} set per TypeDef, Field::offset set as byte offset (scalars) or word index (pointers).
  • Determinism invariant: compute_layout is a pure function of Schema; same schema bytes → byte-identical Layout on every platform; no randomness, no hash-map iteration order dependency.
  • Scope constraints: no encoding (Phase 3), no decoding (Phase 4); layout only; layout must be stable once set (no recompute during encode/decode).
Deliverable
  • ser-layout crate compiles; compute_layout(schema: &Schema) -> Result<Schema, SerError> is public API.
  • All 7 test files pass.
  • ser-layout + ser-schema integration: parse .szs → compute_layout → print field offsets; examples/show_layout.rs.
  • Layout of any schema is reproducible across platforms: CI runs on x86-64 and aarch64 with identical fixture assertions.
  • ser-encode and ser-decode stubs updated to accept Arc<Schema> with populated layouts (no-op bodies).

Pitfalls
  • Offset sign extension: struct/list pointer offset is i30 (signed 30-bit); naively casting bits [31:2] as i32 without sign-extending bit 29 yields wrong negative offsets. Debug: compare decoded offset with hand-computed expected; sign-extend explicitly with ((bits >> 2) as i32) << 2 >> 2.
  • Far pointer double-far indirection: double-far landing pad is two words (far ptr + struct ptr) in target segment; single-far is one pointer directly targeting data. Confusing them silently miscomputes base address. Debug: ser-tool wire-dump --verbose shows ptr chain.
  • List count field only 29 bits: passing count > 536_870_911 silently truncates. Validate in encode_list_ptr; return SerError::SchemaInvalid on overflow. Signal: ser-telemetry counter encode.list_count_overflow.
  • Segment table padding: header must be padded to word (8-byte) boundary; odd segment count leaves 4-byte gap. Missing pad shifts all segment offsets by 4, causing global misparse. Test: odd-count framing fixture.
  • Composite list tag-word counted in element words: the tag word is included in the count field (as word count), not as a separate prefix. Misinterpreting it as element count inflates element count by 1 and shifts all element offsets. Reference: Cap'n Proto encoding spec, sec. list composite.
  • Union data clobbering: two union arms both writing to the same data-section word at different byte offsets can corrupt each other if writes are not isolated. The builder must zero the entire union word before writing the active arm's payload.
  • Little-endian on big-endian hosts: tests must explicitly verify byte order; u64::to_le_bytes is a no-op on little-endian but non-trivial on BE. CI matrix must include a big-endian target (or qemu cross-test).

Pitfalls
  • Pointer offset computation: struct pointer offset is in WORDS relative to the word AFTER the pointer word. Off-by-one (using the pointer word address instead of next-word address) shifts all child data by one word, silently corrupting layout. Debug: ser-tool wire-dump --verbose shows computed vs expected offsets.
  • Bool bit packing clobber: set_bool uses read-modify-write on a byte shared with other bool fields; if two adjacent bool fields are set in wrong order without re-reading, a race (or encode-path bug) clears a previously-set bit. Enforce single-threaded Builder usage; debug_assert byte value pre/post.
  • Composite list tag word miscounted: tag word encodes count = total words in list body (not element count); writing element count instead causes Phase-5 to misparse element boundaries. Test: decode immediately after encode; check element stride.
  • Text field not NUL-terminated: set_text must append \0; forgetting causes out-of-bounds read in C FFI or language bindings expecting C strings.
  • Far pointer allocation order: when a struct crosses segment boundary, the far pointer must be allocated in the OLD segment's pointer section, pointing to the landing pad in the NEW segment; allocating in reverse order produces a circular reference. Enforce: Arena::alloc returns prior segment's pointer slot before bumping to new segment.
  • Canonical mode with multi-segment: canonical encoding promises single-segment; silently emitting multi-segment produces non-canonical bytes and breaks hash/dedup. Return SerError::SchemaInvalid if canonical mode triggers segment overflow (unless allow_multi_segment_canonical).
  • Over-allocated list (count mismatch): allocating 100 elements but writing 90 leaves 10 uninitialized (zeroed) elements visible to decoder. ListBuilder::finish must assert cur == count; in debug builds, panic; in release, zeroed elements decode as default values (may be acceptable but must be documented).

⬜ Phase 5 — Zero-copy decode + validation pass — bounds/alignment/pointer-target validation as the trust boundary, then accessor Readers that cast directly into the buffer (no copy/alloc), lazy field access §17

Objectives
  • Implement ser-decode crate: single validation pass over raw &[u8] that enforces ALL safety invariants before any field is accessed; post-validation field access is infallible at runtime (no alloc, no copy, no OOB possible).
  • Validation pass checks: buffer bounds, word alignment at every pointer dereference, pointer-target within declared segment, far-pointer chain depth ≤ 2, recursion/nesting depth ≤ MAX_NESTING_DEPTH (default 64), total traversed words ≤ MAX_TRAVERSAL_WORDS (amplification defense), no pointer cycles.
  • Implement StructReader<'a> and ListReader<'a, E>: lifetime-checked views into the validated buffer; field access via direct slice cast (no memcpy, no heap alloc).
  • Implement Reader<'a, T> newtype for typed access; codegen emits concrete accessor methods wrapping StructReader.
  • Implement lazy access: reading field F only touches the words for F; unrequested fields are never touched (cache-friendly partial reads).
  • Constraint: post-validation, all unsafe pointer casts are encapsulated in ser-decode internals behind public safe APIs; caller sees only &'a str, &'a [u8], scalar values, and nested StructReader<'a> / ListReader<'a, E>.

Pitfalls
  • Cycle detection via BitSet: visited_words must track ALL word ranges visited during traversal; if only struct-root words are marked (not pointer-section words), a cycle through list elements escapes detection. Mark every word range entered during validation.
  • Far pointer double-hop depth counting: a double-far pointer constitutes TWO pointer resolutions; if depth counter increments only once, deep double-far chains can exceed nesting limit undetected. Increment depth TWICE for double-far.
  • from_utf8_unchecked safety: safe only if validation pass explicitly validated UTF-8 of the text bytes; if validation only checked bounds + NUL, the unchecked path is UB for non-UTF-8 bytes. Fix: validate UTF-8 in validation pass (std::str::from_utf8), store result as "text validated" in ValidationState; OR use from_utf8 in accessor (small cost). Document which approach is chosen.
  • Composite list tag-word misparse: tag word in composite list looks like a struct pointer (same bit layout); if validation code tries to decode_struct_ptr on it, the tag bits = 0b00 and the "offset" field is actually the element count — produces wildly wrong recursion target. Composite list validation must read tag word as struct tag (offset field interpreted as element word count, not pointer offset).
  • Accessor lifetime unsoundness: StructReader<'a> must hold 'a tied to the original buffer slice; if ValidatedMessage is dropped while a StructReader is live, the borrow checker catches this in safe Rust — but if unsafe transmutes or raw pointers are used to extend lifetime, UB results. Enforce: no unsafe lifetime extension outside unsafe_cast.rs; review gate on all unsafe blocks.
  • Default value for absent field (evolution): when decoder sees a data section smaller than schema's declared data_words (old writer, new schema), it must return the field's DefaultVal rather than reading out-of-bounds. Validation pass must record actual data_words from struct pointer; accessor checks field.offset.word() < actual_data_words before reading.
  • Amplification via deeply nested pointers: a message with 64 levels of nesting where each level points to a 1-word struct uses only 64 words total — but if traversal counter is per-pointer-type not per-word, a pathological structure with shared sub-trees (not cycles, just shared far-pointer targets) can re-visit words O(2^depth) times. Fix: the visited_words BitSet prevents re-visiting, capping total traversal at buffer size.
