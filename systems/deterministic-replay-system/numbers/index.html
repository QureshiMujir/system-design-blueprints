4.2 Failure Budget and Recovery Objectives

Scenario Behavior Recovery
Supervisor killed mid-record (SIGKILL) Trace truncated at last fsynced frame dret replay replays up to last valid EventId

perf_event_open fails (PMU busy) Record startup fails with diagnostic User must free PMU counters; no fallback clock
sched_setaffinity fails (container) Replay continues on multiple CPUs (degraded) Divergence detection will catch any resulting nondeterminism
gdbserver client disconnect Replay session paused; resumable on reconnect Session held until timeout (30 s default) or explicit kill

4.3 Storage Amplification Model

Amplification = (trace size) / (tracee-written bytes)

Components:
  events.log  : N_events × 192 B        (fixed per event)
  data.log    : sum(mem_effect_bytes)   (1:1 with kernel writes into tracee)
  mmap.log    : N_mmap_events × 128 B  (sparse)
  ckpt/       : N_checkpoints × (dirty_pages × 4096 B)

Typical workload (1M syscalls, 100 MB data written):
  events.log  ≈ 192 MB
  data.log    ≈ 100 MB
  mmap.log    ≈ 1 MB
  ckpt/       ≈ 50 checkpoints × 10 MB avg dirty = 500 MB
  Total       ≈ 793 MB for 100 MB application writes (~8× amplification)

With Phase 14 compression (zstd data.log + ckpt pages):
  Compressed data.log ≈ 20–50 MB (typical 2–5× for memory data)
  Compressed ckpt     ≈ 100–200 MB
  Effective amplification: 2–3× compressed

Back-of-Envelope Capacity Model

All numbers derived from the System Constraints table (§4.1) and a baseline workload: 1 M syscalls, 100 MB total data written, 256 MB tracee RSS, 50 checkpoints, 4 threads.

1. events.log bandwidth:

events.log frame size = 192 B (§4.1)
syscall rate = 100 000 syscalls/s (I/O-intensive workload assumption)
events.log write rate = 192 B × 100 000 /s = 19.2 MB/s
For 1 M syscall events: 192 B × 1 000 000 = 192 MB

2. data.log bandwidth (mem effects):

average mem effect per syscall = 100 MB / 1 000 000 = 100 B/syscall
data.log write rate = 100 B × 100 000 /s = 10 MB/s
For 1 M syscalls: 100 MB total

3. Checkpoint dirty-page storage:

checkpoint interval = 10 M RCB ticks ≈ 50 000 events (§4.1 default)
checkpoints = 1 000 000 / 50 000 = 20 checkpoints
dirty-page fraction per interval = 10% of RSS (typical write-intensive workload)
dirty bytes per checkpoint = 256 MB × 0.10 = 25.6 MB
total checkpoint storage = 20 × 25.6 MB = 512 MB

4. Total trace storage:

events.log    = 192 MB
data.log      = 100 MB
mmap.log      ≈ 1 MB  (few thousand mmap events × 128 B)
checkpoints   = 512 MB
Total         = 805 MB
Storage amplification = 805 MB / 100 MB = 8× (within ≤10× target in §4.1)

5. Checkpoint write time:

dirty bytes per checkpoint = 25.6 MB
/proc/pid/mem pread throughput ≈ 1 GB/s (§4.1 benchmark)
checkpoint write time = 25.6 MB / 1 GB/s = 25.6 ms  (well within 200 ms target)

6. Seek latency (reverse-continue worst case):

checkpoint interval = 50 000 events
replay throughput = 50 000 events/s (§4.1 replay overhead target)
seek forward distance = 50 000 events
replay-forward time = 50 000 / 50 000 = 1.0 s
checkpoint restore time = 25.6 ms
total seek latency = 1.0 s + 0.026 s ≈ 1.03 s  (within ≤2 s target in §4.1)

7. Supervisor RSS ceiling:

In-flight MemDelta buffer = 64 KB (max, one large read syscall buffer)
Per-task state = 1 KB × 4 threads = 4 KB
Checkpoint page buffer = 25.6 MB peak (streamed to disk, not retained)
Index (event.idx) = 1 000 000 × 16 B = 16 MB
Peak supervisor RSS ≈ 16 MB + 25.6 MB + small buffers ≈ 45 MB  (well within 256 MB target)

8. perf_event_open fd consumption:

perf fds = 1 per task = 4 fds (4 threads)
/proc/pid/mem fds = 1 per task = 4 fds
ptrace = no fd
Total extra fds = 8 (trivial vs. default limit of 1024)

9. ptrace round-trip overhead:

ptrace round-trip latency = 1–3 µs/syscall (§4.1)
at 100 000 syscalls/s: overhead = 100 000 × 3 µs = 300 ms/s = 30% of wall time
plus mem capture: 100 000 × 2 µs = 200 ms/s
Total instrumentation overhead ≈ 50% of CPU → 2× wall-clock (lower bound)
Combined with single-step + scheduler: 2–20× (§4.1 recorded target range)

10. Divergence hash overhead:

pages touched per syscall = 1 (average for simple read/write)
Blake3 hash rate = ~10 GB/s (AVX-512 SIMD; Phase 12 uses xxHash3 at similar speed)
4 KB page hash time = 4 096 B / 10 GB/s = 0.4 µs per page
at 100 000 events/s with page hashing: 0.4 µs × 100 000 = 40 ms/s overhead = 4%
Well within ≤5% divergence detection overhead target (§4.1)
