⬜ Phase 1 — ptrace supervisor skeleton

Objectives
  • Establish dret-ptrace as the safe, low-level ptrace(2) boundary; expose typed Rust wrappers, no raw libc beyond this crate.
  • Implement fork/exec of tracee under PTRACE_TRACEME; supervisor attaches at first SIGSTOP.
  • Set PTRACE_SETOPTIONS: PTRACE_O_EXITKILL | PTRACE_O_TRACESYSGOOD | PTRACE_O_TRACECLONE | PTRACE_O_TRACEFORK | PTRACE_O_TRACEEXEC | PTRACE_O_TRACEVFORK.
  • Build waitpid demultiplex loop mapping raw (pid, status) to typed StopEvent; handle all ptrace-stop flavors.
  • Provide single-step harness (PTRACE_SINGLESTEP); clean detach (PTRACE_DETACH) and EXITKILL safety.
  • No syscall recording yet; no trace I/O; just the supervisor event loop skeleton.
Deliverable
  • dret-ptrace compiles with all wrappers; dret-record binary can spawn /bin/true, /bin/ls, a simple loop program.
  • Supervisor loop runs to tracee exit without hang or panic.
  • dret ps subcommand prints TaskId → (pid, status) for all tracked threads at any stop.

Pitfalls
  • Double-stop on exec: kernel sends SIGTRAP | (PTRACE_EVENT_EXEC << 8) AND a SIGSTOP; demux must consume both or supervisor deadlocks.
  • __WALL missing: waitpid without __WALL misses thread stops; manifests as supervisory loop stall.
  • PTRACE_SETOPTIONS timing: must be called before first PTRACE_CONT after SIGSTOP; if called late, clone/fork events are missed.
  • Signal injection confusion: on a signal-delivery stop, resuming with PTRACE_CONT, 0 suppresses the signal; resuming with the real signo delivers it. Wrong choice silently changes tracee behavior (P3 violation).
  • Group-stop vs signal-delivery stop: both arrive as WIFSTOPPED; distinguish by (status >> 16) and by checking PTRACE_GETSIGINFO for si_code == SI_TKILL.
  • EXITKILL scope: only kills the thread group leader by default; surviving threads from pthread_create may escape if the option is set after clone events.

⬜ Phase 2 — syscall interception + ABI tables

Objectives
  • Intercept every syscall entry/exit via PTRACE_SYSCALL stop pairs; no injection yet.
  • Build dret-syscall: x86-64 syscall number → SyscallSig table; argument/return marshalling from RecordedRegs.
  • Classify each syscall argument as scalar, pointer-in, pointer-out, or pointer-inout; derive MemDelta descriptors for every pointer-out/inout arg and for kernel writes into tracee memory.
  • record-passthrough: at entry, note args; let real syscall execute; at exit, read ret + errno + all mem_effects; construct SyscallRecord.
  • I1 (EventId), I2 (Ticks) not yet enforced; done in Phase 3–4.
Deliverable
  • dret record /path/to/binary runs; supervisor prints per-syscall log lines with nr, args, ret.
  • dret dump (no trace file yet) prints decoded SyscallRecord structs to stdout.
  • All syscalls for /bin/ls, /bin/cat, a threaded hello binary are decoded without panics.

Pitfalls
  • Restarted syscalls (ERESTART*): kernel returns ERESTARTSYS/ERESTARTNOINTR as ret at exit stop; supervisor must re-enter state machine, not record a false failure; detect by ret < 0 && -ret in {512..516}.
  • clone arg layout: clone3 uses a clone_args struct (PtrIn, not registers); table must special-case it; naively reading rdi..r9 gives wrong childstack.
  • recvmsg scattered buffers: msghdr.msg_iov is an array of iovec; pread must walk each iov segment; single PtrOut(Ret) is insufficient.
  • mmap with file backing: must record the fd + offset + path so replay can recreate the mapping; pure bytes capture not sufficient; AddressSpace entry stores MmapProvenance::File { dev, ino, offset }.
  • TOCTOU on /proc/pid/mem: read mem effects at syscall exit, after kernel wrote them; read before PTRACE_CONT for next stop; never read after PTRACE_CONT.
  • Large write pointer arg: do not capture PtrIn bytes for writes — they are tracee input, not nondeterminism; capturing them inflates trace and is wrong.

⬜ Phase 3 — trace container format

Objectives
  • Define and implement the on-disk trace format: events.log, data.log, mmap.log, ckpt/ inside a trace directory.
  • Implement TraceWriter (append-only, framed, CRC-protected) and TraceReader (seekable by EventId and Ticks).
  • Enforce I1 (EventId strictly increasing), I7 (checkpoints on event boundaries).
  • Forward-compatible: unknown frame tags skipped by older readers; newer writers never break a trace prefix.
  • No computation here; pure I/O and framing contracts.
Deliverable
  • dret-trace crate: TraceWriter and TraceReader compile; round-trip test passes.
  • dret record /bin/ls writes a valid trace dir; dret dump <trace> prints all TraceFrames with decoded fields.
  • CRC failures on truncated file detected and reported.

Pitfalls
  • Non-atomic append on crash: partial frame write at end; reader must detect truncated CRC and treat as "replayable prefix" (P7); close() must write a sentinel end-of-log frame.
  • Index drift: if event.idx is written lazily, a crash leaves index incomplete; replay must rebuild index by scanning events.log linearly if index is missing or shorter than log.
  • bincode field order: adding a field to TraceFrame without a version bump silently misaligns all subsequent fields; always bump version on any schema change; use tagged/length-prefixed encoding for extension.
  • data.log offset overflow: DataRef(u64) supports 16 EB; but (offset, len) packed in 2×u32 limits payload to 4 GB each; use explicit u64 pairs in v1 schema.
  • ticks.idx sparse granularity: if too sparse (e.g., one entry per 100 K events), seek_ticks forward-scan window is large; target ≤1000-event window; emit ticks index entry at every checkpoint.

⬜ Phase 4 — Deterministic Clock (RCB Ticks)

Objectives
  • Assign every event an addressable position in the execution via Ticks(u64) — retired-conditional-branch count, per-task, monotonic.
  • Open one perf_event_open fd per tracee task configured for PERF_COUNT_HW_BRANCH_INSTRUCTIONS (or PERF_COUNT_HW_BRANCH_MISSES fallback) in user-only mode, interrupt-on-overflow disabled.
  • Read current tick value at each ptrace stop and embed it in every TraceFrame.
  • Apply overcount/skid correction so that the recorded tick at a syscall entry equals the true RCB count the tracee had when the syscall instruction executed.
  • Expose dret-time as the single source of clock truth; prohibit wall-clock usage in any event record.
  • Constraint: Ticks are per-TaskId; TaskId must be stable across record and replay (not the OS tid). I2 enforced here.
Deliverable
  • dret-time compiles; PerfCounter::open/read/reset round-trips against a live tracee.
  • dret record embeds non-zero, strictly increasing Ticks in every TraceFrame for a single-threaded C program (e.g., md5sum /dev/urandom).
  • dret dump prints EventId, TaskId, Ticks, EventKind columns; operator can visually verify monotonicity; dret-divergence tick comparison passes on a replayed single-threaded trace (Phase 6 prerequisite).

Pitfalls
  • Counter multiplexing: if pinned=1 is not set, the kernel may time-multiplex the counter across multiple events, returning a scaled value. Symptom: ticks jump by thousands at random stops. Fix: assert PERF_FORMAT_ID scale == 1.0 or fail.
  • rdtsc vs RCB confusion: using rdtsc (wall-ish) as backup silently breaks P5. Enforce at type level — Ticks is only ever populated from PerfCounter::read().
  • clone() counter inheritance: inherit=0 ensures child does NOT inherit parent's counter; if set to 1, child tick starts at parent value, breaking monotonicity across tasks. Verify inherit=0 in every PerfCounter::open call.
  • Counter not enabled after exec: if PTRACE_EVENT_EXEC fires before PERF_EVENT_IOC_ENABLE, first events have tick=0. Fix: enable in on_exec_stop(), not on task creation.
  • Kernel vs user branch counting: if exclude_kernel=0, kernel branch instructions pollute the count. Symptom: tick values far exceed expected for simple programs. Fix: always exclude_kernel=1.
  • VM/container environments: KVM guests may not expose PERF_COUNT_HW_BRANCH_INSTRUCTIONS; manifest as ENOENT or EINVAL. Detection: explicit probe at recorder startup; emit DRET_WARN_NO_RCB.

⬜ Phase 5 — Memory Capture

Objectives
  • Record every byte a syscall writes into tracee address space as a MemDelta attached to the SyscallRecord.
  • Capture full COW page snapshots at Checkpoint events for seekable replay (Phase 11 dependency introduced here).
  • Track the tracee's AddressSpace continuously via mmap/munmap/mremap/brk/mprotect interception; emit mmap.log events.
  • Provide dret-mem as the abstraction layer over /proc/pid/mem (no other crate reads tracee memory directly); constraint I10 — address-space layout at event E is identical in record and replay.
Deliverable
  • dret-mem compiles with MemAccess::read/write and snapshot_pages passing unit tests against /proc/self/mem.
  • dret record captures non-empty mem_effects for read(2) and recvmsg(2) syscalls; dret dump --mem prints DataRef offsets and byte lengths for each event's MemDeltas.
  • AddressSpace correctly reflects a 50-syscall trace of a program that calls mmap/munmap, verified by diffing against /proc/pid/maps snapshots taken at each stop; snapshot_pages produces a byte-identical re-read of all writable segments.

Pitfalls
  • TOCTOU on pointer args: reading arg pointer at syscall exit instead of entry means the tracee may have already overwritten the buffer. Fix: for IN args (data sent to kernel), read at entry; for OUT args (kernel wrote result), read at exit.
  • Lazy mmap vs eager snapshot: mmapping a file with MAP_PRIVATE adds a segment but the pages are not yet resident; snapshot of unpopulated pages returns zeros, not file content. Fix: for file-backed read-only segments, record the file path + offset, not the page content. Reconstruct on replay by re-mmap'ing the same file.
  • Shared memory segments: MAP_SHARED segments are visible to other processes; reading them at syscall exit captures a snapshot that may already be stale. Document as a known limitation for Phase 5; full shared-memory replay is deferred.
  • /proc/pid/mem vs PTRACE_PEEKDATA: PTRACE_PEEKDATA reads 8 bytes per call (200k+ calls for a 64 KB iov); /proc/pid/mem pread is O(1) overhead. Always use MemAccess (pread path).
  • Segment split on partial munmap: munmap(addr+4096, 4096) in the middle of a 3-page segment splits it into two; BTreeMap must handle range-split correctly.
  • vDSO/vsyscall regions: these are kernel-mapped pages; attempting to snapshot them via /proc/pid/mem returns zeros or EFAULT; skip them in snapshot_pages based on SegmentKind::Vdso.

⬜ Phase 6 — Single-Threaded Replay Engine

Objectives
  • Re-execute the recorded binary under dret-replay without any real syscall side effects; use PTRACE_SYSEMU to intercept every syscall before kernel execution.
  • At each syscall stop: inject the recorded ret/errno into tracee registers and write all recorded MemDelta bytes into tracee address space.
  • Validate registers and ticks at each event against the TraceFrame; emit DivergenceReport on any mismatch (I9 enforced here).
  • Replace non-deterministic mmap calls with deterministic remaps that reproduce the recorded AddressSpace layout.
  • Constraint: single-threaded trace only (Phase 7/8 extend to multi-thread); I6, I3, I4, I5 fully enforced.
Deliverable
  • dret replay <trace_dir> -- <binary> re-executes a single-threaded program deterministically.
  • A 1000-event trace of sha256sum /dev/urandom replays without divergence from the recorder; dret dump --divergence shows zero divergences on a correctly recorded trace.
  • DRET_REPLAY_VERBOSE=1 prints per-event: EventId, syscall nr, injected ret, tick comparison result.
  • Any manually corrupted ret field in events.log produces a DivergenceReport at that exact EventId.

Pitfalls
  • PTRACE_SYSEMU vs PTRACE_SYSCALL confusion: PTRACE_SYSCALL executes the real syscall then stops at exit; PTRACE_SYSEMU stops before execution. Mixing them causes real syscalls to escape. Symptom: network packets sent, files created. Fix: assert PTRACE_SYSEMU is used exclusively in replay; gated by a compile-time mode enum.
  • rax sign extension for errno: Linux ABI returns -errno as a negative i64 in rax; if stored/retrieved as u64, sign extension breaks. Store ret as i64 in SyscallRecord; cast carefully.
  • mmap MAP_FIXED collision: recorded mmap address may already be mapped in the replayed process (e.g., vDSO placed by kernel at replay exec). Fix: at replay launch, after exec stop, parse /proc/pid/maps, unmap any segment that conflicts with a to-be-replayed MAP_FIXED region.
  • Replay binary exec ASLR: kernel ASLR places stack, vDSO, loader at random addresses even if binary is non-PIE. The replay exec must set ADDR_NO_RANDOMIZE (via personality(ADDR_NO_RANDOMIZE) in child before exec) to match recorded layout. Omitting this causes immediate address-space divergence.
  • orig_rax vs rax: after a syscall stop, rax is overwritten by the kernel with the return value; orig_rax holds the syscall nr. On replay with PTRACE_SYSEMU, the kernel never executes the syscall, so rax == orig_rax at entry. Validation must read orig_rax for syscall nr, not rax.
  • Signal during replay syscall stop: if an asynchronous signal arrives while the supervisor is processing a PTRACE_SYSEMU stop, waitpid delivers it separately; replay loop must handle WIFSIGNALED and WSTOPSIG non-syscall stops without consuming a TraceFrame.

⬜ Phase 7 — Deterministic User-Space Scheduler

Objectives
  • Force all tracee threads onto a single logical CPU via sched_setaffinity(2); ensure no two threads run simultaneously at any point during record or replay.
  • Implement tick-bounded cooperative preemption: supervisor reads RCB tick count at each ptrace stop, compares to per-task budget, and decides the next thread to run.
  • Produce a deterministic, fully-ordered run-queue sequence captured as SchedSwitch frames in events.log; replay re-applies identical switch points by consuming those frames.
  • Define SchedPoint { tid: TaskId, ticks: Ticks } as the canonical preemption boundary; encode in EventKind::SchedSwitch.
  • Constraints: scheduler state lives entirely in the supervisor, no in-process synchronization primitives are used, and the tracee is never aware of preemption. Scope: dret-sched owns run-queue logic; dret-record calls into it at every ptrace stop; dret-replay drives replay-side switch injection.
Deliverable
  • dret record ./mt_pingpong produces events.log with interleaved SchedSwitch + Syscall frames from two threads.
  • dret replay ./mt_pingpong exits with identical return code; 0 DivergenceReports; dret dump --switches prints event_id | from_tid | to_tid | ticks_used.
  • /proc/{tid}/status confirms Cpus_allowed_list: 0 during record for all threads; SchedPolicy::RoundRobin exercised, with tick budget log showing no thread exceeded budget + skid.

Pitfalls
  • Affinity inheritance gap: threads born via clone before supervisor installs affinity inherit parent's CPU mask; fix: apply sched_setaffinity in PTRACE_EVENT_CLONE handler before first PTRACE_CONT of child.
  • SIGSTOP delivery latency: issuing PTRACE_CONT + SIGSTOP is not atomic; tracee executes additional instructions before the stop arrives; correct by re-reading ticks at the resulting stop, not at the signal-send time; log delta as preempt_overshoot.
  • Spurious external SIGSTOP: a debugger or external kill -STOP may deliver SIGSTOP to tracee; differentiate by tagging each in-flight supervisor SIGSTOP with a bool pending_sched_stop flag per TaskId; unexpected stops are logged and treated as asynchronous events.
  • Futex-blocked thread blocking the scheduler: a thread sleeping in futex(FUTEX_WAIT) never reaches a ptrace stop; it must be removed from the active RunQueue and tracked in SchedState.blocked = Some(BlockReason::Futex(uaddr)); failure to do so causes the scheduler to attempt PTRACE_CONT on a stopped thread → ESRCH.
  • Empty active queue deadlock: if all tasks are Futex-blocked and no FUTEX_WAKE is pending, the supervisor's waitpid blocks forever; detect by checking RunQueue.is_empty() && all_states == Blocked; emit SchedulerStall error and flush trace to last good checkpoint.
  • Tick read overhead in hot path: read(perf_fd) per ptrace stop adds ~2–5 µs; batch with PTRACE_GETREGSET in the same trap window to amortize kernel transitions.

⬜ Phase 8 — Multi-Threaded Record + Replay

Objectives
  • Intercept clone(2)/clone3(2) via PTRACE_EVENT_CLONE; register each new thread as a distinct TaskId with its own tick counter, regs, ThreadRecord.

  • Record futex ops (FUTEX_WAIT, FUTEX_WAKE, FUTEX_REQUEUE, FUTEX_WAKE_BITSET) with full woken_tids[] so replay reproduces identical wakeup order.
  • Atomics determinism by serialization (I6): one thread runs at a time, so CAS/fetch-add are sequentially consistent, no instrumentation needed. Constraint: state captured only via ptrace//proc; no code injection, no compiler instrumentation.
Deliverable

  • dret replay reproduces final output identically; per-thread tick counts match at every event.
  • dret dump --thread <tid> filters to single thread; dret dump --futex shows FUTEX_WAIT/WAKE pairs with woken_tids.
  • fs_base values in replay match recorded values at every thread's first event.

  • CLONE_THREAD vs fork: CLONE_THREAD shares address space/fd table; fork creates a new AddressSpace; abort loudly on CLONE_NEWNS/CLONE_NEWPID (unsupported namespaces) via RecordError::UnsupportedCloneFlags.
  • fs_base stale after set_thread_area/inline wrmsr: glibc uses arch_prctl exclusively on x86-64; raw wrmsr from kernel modules is unreachable from user space; no workaround needed.
  • Futex uaddr in shared memory (MAP_SHARED): two tasks may hold different virtual addresses mapping the same page; record physical page offset (/proc/pid/pagemap) alongside uaddr for divergence-check verification.
  • Kernel wakeup ordering non-determinism: kernel futex-waiter wake order may differ between record and replay kernels; record woken_tids[] explicitly; replay enforces the recorded list regardless of kernel behavior.
  • TaskId exhaustion: u32 counter; 4B threads/trace before overflow, unreachable in practice; debug-assert counter != u32::MAX.
  • vfork child not yet exec'd when parent re-enters ptrace: PTRACE_EVENT_VFORK_DONE not yet received; supervisor must not PTRACE_CONT parent until it arrives; add BlockReason::VforkWait.

⬜ Phase 9 — Signal Capture + Deterministic Delivery

Objectives

  • Signal-delivery-stop vs syscall-stop confusion: ptrace overloads WSTOPSIG; syscall-stop has (status >> 8) == (SIGTRAP | 0x80) when PTRACE_O_TRACESYSGOOD set; a signal-delivery-stop has WSTOPSIG == signo without the 0x80 modifier; misclassification causes a signal to be treated as a syscall or vice versa.
  • Async signal arriving during PTRACE_CONT gap: the signal is queued by the kernel until tracee runs; ptrace intercepts at delivery-stop before the tracee executes the handler; tick read immediately after stop is the correct delivery tick; no race exists here.
  • Scheduler SIGSTOP vs user SIGSTOP: Phase 7 uses SIGSTOP for preemption; an external kill -STOP is also SIGSTOP; differentiate by the pending_sched_stop: bool flag per TaskId; unexpected SIGSTOP = external signal, log as WARN unexpected_sigstop.
  • Skid exceeding threshold on replay: single-step mode is slower than normal execution; RCB counter may overshoot target tick by more than 50 RCB; common causes: branch-heavy signal-delivery paths; tune SKID_THRESHOLD to 100–200 if needed; expose --skid-threshold CLI flag.
  • rt_sigreturn register misread: after signal handler, rt_sigreturn restores the pre-signal RecordedRegs from the signal frame; if supervisor snapshots regs at this stop, it will record the restored values as if they were a new event baseline; must mark this stop as NoRegSnapshot; resume normal snapshotting at subsequent stops.
  • Real-time signal ordering: POSIX guarantees SIGRTMIN+N delivered in send order with si_value; if replay delivers them out of order (e.g., due to queue reordering on a different kernel), divergence will occur; enforce delivery from the recorded PendingSignals queue in exact recorded order.
  • Signals sent to the process group (negative pid in kill): kernel delivers to one thread arbitrarily; record the receiving tid explicitly; replay must deliver to the same tid.
