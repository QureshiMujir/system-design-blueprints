3.2 Subsystem Descriptions

vc-color (raw YUV → encoder input / decoder output) Converts RGB24 to YUV 4:2:0 via BT.601 or BT.709 matrix; performs 2:1 chroma downsample (luma-aligned) and upsample. Manages Plane allocation with configurable stride for SIMD alignment. Data flows in as raw byte buffers; flows out as Frame{planes: [Plane;3]}. No codec logic; pure color math. Trust boundary: all pixel values are clamped to [0,255] before leaving this crate.

vc-intra (intra prediction) Computes prediction pixels for all 4x4 luma modes (DC, Vertical, Horizontal, Diagonal Down-Left, Diagonal Down-Right, Vertical-Right, Horizontal-Down, Vertical-Left, Horizontal-Up) and 16x16 luma modes (DC, Horizontal, Vertical, Plane), plus 8x8 chroma. Reads only already-decoded neighbor samples (left column, top row) — I4 enforced structurally by requiring a DecodedNeighbors argument. Outputs a prediction block; does not modify the Frame. The encoder calls this speculatively for mode decision; the decoder calls it once, committed.

vc-motion (motion estimation) Consumes a source macroblock and a reference Frame from the DPB; returns the best integer-pel MotionVector and its RD cost. Implements full-search and diamond/EPZS patterns. SAD is the primary distortion measure; SATD (Hadamard-transformed SAD) approximates frequency-weighted distortion. Lambda parameter from vc-encoder weights bit cost against distortion. No pixel modification; pure search. Concurrency: stateless, safe to run per-macroblock without coordination.

vc-inter (motion compensation / sub-pixel interpolation) Takes a MotionVector (quarter-pel precision) and a reference Frame; produces a prediction block. Half-pel positions generated via the H.264 6-tap luma filter (coefficients [1,-5,20,20,-5,1]/32); quarter-pel by bilinear averaging of adjacent half-pel samples. Chroma uses 1/8-pel bilinear. Edge extension (replicate) handles out-of-frame MVs. Outputs a Plane-sized prediction; used by both encoder (reconstruction) and decoder (prediction).

vc-transform (integer DCT) Forward and inverse 4x4 integer DCT derived from the H.264/AVC specification (Cf/Ci matrices, integer butterfly, shift-and-round). 8x8 variant for profile-High macroblocks. Hadamard 4x4 for the 16x16 luma DC block. The critical invariant I3 holds at this layer: inverse_dct(forward_dct(b)) reproduces b exactly within the defined integer precision. No float arithmetic anywhere.

vc-quant (quantization + dequantization) Maps QP ∈ [0,51] to a multiply-shift pair (forward: (coeff * MF + f) >> qbits; inverse: coeff_q * V << qp/6). Dead-zone offsets for intra vs inter block classification. Chroma QP is remapped via the standard 6-entry table. Enforces I5: dequantized output within one step size of original coefficient. Inputs: TransformBlock of integer coefficients + Qp. Outputs: quantized TransformBlock.

vc-entropy (CAVLC + CABAC) Two sub-modules sharing the BitWriter/BitReader from vc-bitstream. CAVLC: encodes/decodes quantized residual via the standard coeff_token (nC-indexed), trailing_ones, levels (suffix_length), total_zeros, run_before tables; also encodes MB type, intra modes, MVDs via exp-Golomb or mapped VLC. CABAC: binary arithmetic coder with context initialization (cabac_init_idc), context-adaptive probability update (MPS/LPS tables), renormalization loop, bypass mode for equiprobable symbols. Invariant I6 enforced by roundtrip tests.

vc-bitstream (NAL / RBSP / bit I/O) BitWriter: MSB-first bit packing into Vec<u8>; emits NAL unit start codes (0x000001) and emulation-prevention bytes (0x000003) in RBSP. BitReader: inverse parsing. Exp-Golomb ue(v)/se(v) encode/decode. Slice header, macroblock header, and partition syntax serialization. Invariant I7: parse(serialize(x)) == x for all valid syntax elements. This crate has no codec logic; it is a pure bitstream I/O substrate.

vc-deblock (in-loop deblocking filter) Computes boundary strength (BS 0–4) for each 4x4 edge from macroblock type, coded-block-pattern, and motion-vector differences. Applies the H.264 adaptive edge filter using QP-derived thresholds alpha/beta/tC0 (luma) and equivalent chroma thresholds. Applied inside the reconstruction loop in both encoder and decoder — not as post-processing — because reference frames must be identical (I9). Inputs: reconstructed Frame, Macroblock array with BS data, QP map. Outputs: filtered Frame in place.

vc-encoder (encode driver) Schedules the GOP (IDR → P → B cadence); calls vc-intra and vc-motion/vc-inter for mode decision; selects the mode minimizing lambda * bits + distortion; calls vc-transform, vc-quant, vc-entropy, vc-bitstream in sequence; runs the reconstruction loop (dequant + inverse DCT + prediction + vc-deblock) after each macroblock; stores reconstructed frames in the DPB. QP-stepping rate control adjusts QP per-frame toward a target bitrate. Emits NAL units. The reconstruction loop is the most critical correctness constraint (I2).

vc-decoder (decode driver) Parses NAL units via vc-bitstream; entropy-decodes coefficients and MVs via vc-entropy; dequantizes via vc-quant; inverse-transforms via vc-transform; applies prediction (vc-intra or vc-inter) using the DPB; runs vc-deblock in-loop; stores output frames in DPB and emits display-order frames. Must produce pixel-identical output to the encoder's reconstruction loop (I1, I2).

vc-cli (command-line driver) Subcommands: encode (YUV file → NAL bytestream, configurable QP/GOP/profile), decode (bytestream → YUV file), psnr (compare two YUV files, report per-component PSNR in dB), inspect (parse and print NAL/slice/macroblock structure without full decode). No codec logic; coordinates vc-encoder or vc-decoder with file I/O. Observability: prints per-frame bits, PSNR, QP, and mode distribution.

DPB (decoded picture buffer, in vc-encoder + vc-decoder) In-memory ring of decoded Frame objects used as motion-compensation references. Manages reference list (RefList) construction: list0 (past frames for P/B), list1 (future frames for B). POC-ordered insertion; sliding-window or explicit MMCO frame marking. Capacity bounded by the configured reference frame count (default 4). Shared between encoder reconstruction loop and inter predictor.

8. Domain Model

8.1 Entity Taxonomy

Entity Crate Cardinality Lifecycle

Frame vc-core 1 per coded picture input → encoded → reconstructed → stored in DPB → evicted
Macroblock vc-core W/16 × H/16 per Frame scratch during encode/decode; not persisted

8.2 Frame State Machine

State transitions (encoder path):
  RAW_INPUT --> COLOR_CONVERT --> MACROBLOCK_PARTITION --> MODE_DECISION
  MODE_DECISION --> INTRA_PREDICT | INTER_PREDICT
  INTRA_PREDICT | INTER_PREDICT --> RESIDUAL_COMPUTE --> TRANSFORM --> QUANTIZE
  QUANTIZE --> ENTROPY_CODE --> BITSTREAM_EMIT
  QUANTIZE --> DEQUANTIZE --> INV_TRANSFORM --> RECONSTRUCT --> DEBLOCK --> DPB_STORE

State transitions (decoder path):
  BITSTREAM_IN --> NAL_PARSE --> SLICE_PARSE --> MB_PARSE
  MB_PARSE --> ENTROPY_DECODE --> DEQUANTIZE --> INV_TRANSFORM
  INV_TRANSFORM --> INTRA_PREDICT | INTER_COMPENSATE
  INTRA_PREDICT | INTER_COMPENSATE --> RECONSTRUCT --> DEBLOCK --> DPB_STORE --> OUTPUT

Encoder and decoder share DEQUANTIZE → INV_TRANSFORM → RECONSTRUCT → DEBLOCK → DPB_STORE (the reconstruction loop). Any divergence between these paths violates I2.

8.3 Frame Type and GOP Semantics

FrameType state within GOP:
  IDR (I) → P → P → B → B → P → B → B → P → ... (configurable cadence)

Constraints:
  - IDR resets DPB; no frame after IDR may reference across it.
  - B-frames reference frames with lower AND higher POC (bi-directional, I4).
  - POC (Picture Order Count) governs display order; frame_num governs decode order.
  - DPB size limited to max_ref_frames (default 4); eviction by marking (short/long-term).
FrameType Ref lists DPB sources MB modes allowed
I none none IntraNxN, Intra16x16
P list0 (past) 1–4 decoded frames Intra*, Inter*, Skip
B list0 (past) + list1 (future) 1–4 each direction Intra*, Inter*, BiPred, Skip

mb_data        ::= intra_data | inter_data
intra_data     ::= (intra4x4_pred_mode* cbp) | intra16x16_data
inter_data     ::= (ref_idx_l0? mv_l0?)* (ref_idx_l1? mv_l1?)* cbp residual?

residual       ::= luma_residual chroma_residual
MbType Partitions Reference lists Residual
IntraNxN 16 × 4x4 blocks none 16 × 4x4 DCT + DC Hadamard
Intra16x16(mode) 1 × 16x16 none 1 Hadamard DC + 16 × 4x4 AC
Inter(16x16) 1 list0 [+ list1 for B] 1 × 16x16 (4 × 8x8 sub-blocks)
Inter(16x8) 2 × 16x8 per-partition 2 × 8x8 sub-partitions
Inter(8x16) 2 × 8x16 per-partition 2 × 8x8 sub-partitions

4x4 Luma (9 modes)

Mode ID Name Prediction direction
0 Vertical top samples extrapolated down
1 Horizontal left samples extrapolated right
2 DC mean of available top + left
3 Diagonal_Down_Left 45° toward bottom-left
4 Diagonal_Down_Right 45° toward bottom-right
5 Vertical_Right ~26.6° from vertical toward right
6 Horizontal_Down ~26.6° from horizontal toward bottom
7 Vertical_Left ~26.6° from vertical toward left

Mode Prediction

Horizontal (1) replicate left column
Vertical (2) replicate top row
Plane (3) linear plane fit through border (H.264 sec. 8.3.3.4)

Availability rule (I4): a neighbor sample is available iff its macroblock has been decoded (scanning order: left, top, top-left, top-right). At frame/slice boundaries, unavailable samples are substituted with 128 (midgray for 8-bit).

8.6 Motion Vector Model

MotionVector { x: i16, y: i16 }  -- quarter-pel units
  integer-pel offset = (x / 4, y / 4)
  fractional part    = (x % 4, y % 4), values 0|1|2|3 → full|quarter|half|three-quarter

MV range: [-512, 511] quarter-pel = [-128, 127.75] luma pixels (conformant constraint)
Chroma MV: scaled x/2 and y/2 in chroma quarter-pel units (one chroma pel = 2 luma pel)

MV prediction (median of A, B, C neighbors):

A = left MB/partition MV
B = above MB/partition MV
C = above-right MB/partition MV (above-left if C unavailable)
MVP = (median(A.x, B.x, C.x), median(A.y, B.y, C.y))
MVD = MV_coded - MVP  -- transmitted; decoded: MV_decoded = MVP + MVD

Sub-pixel interpolation stages:

Fractional Luma filter Chroma filter
Integer direct copy direct copy
Half-pel 6-tap [ 1,-5,20,20,-5,1 ] / 32 bilinear 1/2
Quarter-pel bilinear average of adj. integer/half bilinear 1/4

8.7 Integer DCT and Quantization Layout

H.264 4x4 integer forward DCT (matrix form, scaled):

Cf = Hf * C * Hf^T  (applied to 4x4 residual block C)
Hf = [[ 1, 1, 1, 1],
      [ 2, 1,-1,-2],
      [ 1,-1,-1, 1],
      [ 1,-2, 2,-1]]
Post-multiply by scaling matrix Ef element-wise, then >> 1 to get Cf.

Quantization (forward):

level = (|coeff| * MF[qp%6][i][j] + f) >> (15 + qp/6)
  MF[qp%6][i][j] — per-position multiply factor from H.264 Table 8-15
  f = (qp < 24) ? (1<<(qp/6+15))/3 : (1<<(qp/6+15))/6  -- dead-zone
sign(level) = sign(coeff)

Dequantization:

coeff_dq = level * V[qp%6][i][j] << (qp/6)   (if qp/6 >= 2)
         = level * V[qp%6][i][j] >> (2 - qp/6) (otherwise)
  V[qp%6] — per-position rescale table

QP ladder: step doubles every 6 QP increments. Chroma QP = chroma_qp_table[luma_qp] (capped at 39 for standard profiles).

Hadamard DC block (16x16 intra luma): 4x4 Hadamard over the 16 DC coefficients from 4x4 sub-blocks before main quantization step.

8.8 CAVLC Encoding Layout

Context per 4x4 block: nC (number of coefficients, derived from left/top neighbors).

Encoding order per 4x4 block:
  1. coeff_token(totalCoeff, trailingOnes) — VLC from Table 9-5 indexed by nC
  2. trailing_ones_sign_flag[i]            -- 1 bit each, most-recent first
  3. levels[i]                             -- suffix_length-coded, remaining non-zero coeffs
  4. total_zeros                           -- VLC from Table 9-7
  5. run_before[i]                         -- VLC from Table 9-10, scanning reverse zigzag

Zigzag scan order (4x4):

 0  1  5  6
 2  4  7 12
 3  8 11 13
 9 10 14 15

CAVLC roundtrip invariant (I6): for any sequence of integer coefficients in range [−512, 511], cavlc_decode(cavlc_encode(coeffs)) == coeffs.

8.9 Simplified CABAC Model

Binary arithmetic coder state:

CabacState { range: u16, low: u32, context_models: [CtxModel; N_CTX] }
CtxModel   { pStateIdx: u8, valMps: u1 }  -- 64-state LPS probability table

Encode step (one bin). qCodIRangeIdx = (range >> 6) & 3 selects rLPS = rangeTabLPS[pStateIdx][qCodIRangeIdx] from the state table, and range is reduced by rLPS. On the LPS branch, low += range and range is replaced by rLPS, then the LPS state-transition table updates pStateIdx/valMps; on the MPS branch only the MPS state-transition table updates pStateIdx. Both branches renormalize afterward, shifting range left (and emitting bits with carry propagation) until range >= 256.

Binarization schemes used:

Syntax element Scheme
mb_type truncated unary + suffix
MVD exp-Golomb order 3
coded_block_flag FL (1 bit)
coeff_abs_level_minus1 unary + EG0
end-of-slice FL (1 bit)

CABAC context count: ~460 contexts (simplified implementation may use subset).

8.10 NAL Unit and Bitstream Wire Format

NAL stream layout (Annex B byte stream):
  start_code := 0x000001 | 0x00000001 (4-byte for first, 3-byte otherwise)
  nal_unit   := forbidden_zero_bit(1) nal_ref_idc(2) nal_unit_type(5) rbsp_bytes

nal_unit_type values (relevant subset):
  1 = coded_slice_non_IDR
  2 = coded_slice_data_partition_A
  5 = coded_slice_IDR
  6 = SEI
  7 = SPS (sequence parameter set)
  8 = PPS (picture parameter set)

Emulation prevention: pattern 0x000001 or 0x000002 within RBSP replaced by
  0x000003 0x00 / 0x000003 0x01 / 0x000003 0x02 during write;
  0x000003 byte removed during parse. Applies inside RBSP, not start codes.

RBSP trailing bits: append 1-bit, then 0-bits to byte boundary.

Exp-Golomb code (ue):

x       code
0     → 1
1     → 010
2     → 011
3     → 00100
k     → [log2(k+1)] zeros + (k+1) in binary

Signed exp-Golomb (se): map k → (k > 0) ? 2k-1 : -2k before ue encoding.

8.11 DPB and Reference List Semantics

Dpb { frames: Vec<DpbEntry>, max_size: usize }
DpbEntry { frame: Frame, frame_num: u32, poc: i32, ref_type: ShortTerm | LongTerm | Unused }

Reference list construction (simplified, P-slice):
  list0 = sort(short_term frames, descending poc) ++ sort(long_term, ascending long_term_idx)
  list0 truncated to num_ref_idx_l0_active

B-slice: list1 = frames with poc > current_poc (ascending) ++ frames with poc <= current_poc (descending)
  list0 = frames with poc < current_poc (descending) ++ frames with poc >= current_poc (ascending)

Marking (MMCO):
  end_of_sequence → mark all unused
  mark_short_as_long_term → promote DpbEntry
  adaptive_memory_control_command → MMCO sequence in slice header
  sliding_window (default) → evict oldest short-term when DPB full

Invariant I8: the RefList presented to motion compensation must exactly match what a conformant decoder would construct from the same slice header and DPB state.

8.12 Deblocking Filter Model

Boundary strength (BS) decision table:

Condition BS
MB boundary; either side intra 4
MB boundary; neither intra 3
Sub-MB boundary; coded coefficients on either side 2
Sub-MB boundary; MV diff ≥ 1 integer pel or different ref frame 1
Otherwise 0

Filter application (BS ≥ 1). Thresholds α = α_table[clip3(0,51, QP_avg + α_offset)] and β = β_table[clip3(0,51, QP_avg + β_offset)] are looked up per edge. For each 4-sample edge [p2,p1,p0 | q0,q1,q2], the filter applies only when |p0-q0| < α AND |p1-p0| < β AND |q1-q0| < β; when that condition holds, BS=4 (intra boundary) selects the strong 5-tap filter and BS=1..3 selects the normal 3-tap or 4-tap filter (chosen by the dp, dq thresholds).

Chroma deblocking: same BS, separate α/β from chroma QP, 2-tap filter only.

Invariant I9: filter is applied after reconstruction, before DPB storage, in both encoder and decoder identically. Applying it only to display output (not reference) violates I2.

8.13 Reconstruction Loop Data Flow (Sequence Diagram)

Encoder                              Decoder (must mirror)
  source_block
      |
      v
  prediction = intra/MC(DPB)          prediction = intra/MC(DPB)
      |                                    |
  residual = source - prediction          (MV / mode from bitstream)
      |
  T = fwd_dct(residual)
  Tq = quantize(T, QP)
      |--- entropy encode --> bitstream --> entropy decode ---|
                                                              |
                                                         Tq (decoded)
      |                                                       |
  Tq_dq = dequantize(Tq, QP)                    Tq_dq = dequantize(Tq,QP)
  residual_rec = inv_dct(Tq_dq)                 residual_rec = inv_dct(Tq_dq)
  recon = clip(prediction + residual_rec)        recon = clip(prediction + residual_rec)
  deblock(recon) --> DPB                         deblock(recon) --> DPB

Encoder and decoder paths are identical from dequantize onward. The encoder runs both paths; the left branch feeds entropy coding, the right branch feeds the DPB.

8.14 Worked Example: Intra 4x4 Block Encode

Input residual block (after subtracting DC-predicted neighbors):

R = [[ 10, -3,  2,  0],
     [ -2,  5, -1,  1],
     [  0,  2,  3, -2],
     [ -1,  0,  1,  4]]
  1. Forward DCT → Cf (integer butterfly, exact).
  2. Quantize Cf at QP=28: MF[28%6=4], f dead-zone applied → Tq.
  3. CAVLC encode Tq in zigzag order: e.g., totalCoeff=5, trailingOnes=2, emit coeff_token + signs + levels + total_zeros + run_before.
  4. Decoder: parse → Tq recovered exactly (I6). Dequantize → Cf_dq (within step of Cf, I5). Inverse DCT → R_rec (within rounding of R, I3).
  5. recon = clip(prediction + R_rec, 0, 255).

Reconstruction error bounded by QP=28 step size ≈ 6 luma values per coefficient (I5).

8.15 Malformed / Failure-Path Examples

Malformed input Expected behavior
Missing emulation-prevention byte parse() returns Err(EmulationByte) before any state mutation
CAVLC totalCoeff > 16 Err(CavlcOverflow), slice parsing aborted
MV pointing outside reference frame + 8-pel border edge-extension clamps to border; no out-of-bounds read
B-frame referencing a frame not in DPB Err(DpbRefMissing), frame dropped
QP > 51 rejected at SPS/PPS parse; Err(QpOutOfRange)
Inverse DCT overflow (coefficients > defined range) saturate to i32 bounds, mark frame as corrupted
Slice header frame_num gap (lost frames) insert "gaps_in_frame_num_value_allowed" frames per H.264 sec. 8.2.5
End-of-stream mid-macroblock Err(UnexpectedEos), partial frame discarded

8.16 Edge Cases

Scenario Handling
Frame width or height not multiple of 16 pad to next multiple of 16 during encode; crop on display
First macroblock in first slice (no left/top neighbors) all unavailable → DC intra uses 128; inter MVP = (0,0)
Top-right neighbor unavailable at row end use top-left neighbor for 4x4 mode 4/5/7/8 availability
QP=0 (quantization step ~1) no overflow; level values fit i16; CAVLC VLC tables valid
All-zero residual block after quantization CBP bit = 0; no coefficients written; skip CAVLC for that block
IDR mid-sequence flush DPB; reset frame_num; reset POC counters
B-frame reordering (display ≠ decode order) POC used for reorder; DPB holds unreleased frames until display
Long-term reference promotion MMCO op in slice header; DpbEntry.ref_type updated
Chroma-only CBP set (luma all-zero) emit luma residual block count = 0; chroma blocks coded
