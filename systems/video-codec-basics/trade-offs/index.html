Decisions (§9) · 28 ADRs

ADR-01

Implementation language

Chosen

Rust (stable toolchain)

Rejected

C/C++, Go, Zig

When the rejected choice is right

C/C++ wins when integrating into an existing FFmpeg/x264 codebase or when mature hand-tuned assembly intrinsics dominate; Zig wins for fine-grained manual memory control with simpler C interop

Why: Memory safety without GC; zero-cost abstractions; unsafe boundary isolates unsafe SIMD/bit-manipulation; H.264 integer transforms fit naturally in integer Rust

ADR-02

Build system

Chosen

Cargo workspace (single Cargo.toml at root, per-crate members)

Rejected

CMake + cbindgen, Buck, Bazel

When the rejected choice is right

CMake+cbindgen wins when shipping a C ABI library consumed by C/C++ projects; Bazel wins in a polyglot monorepo needing hermetic remote caching

Why: Native Rust; workspace features for conditional compilation; reproducible lockfile; no external build orchestration needed at this scale

ADR-03

Workspace structure

Chosen

13 crates (vc-core … vc-cli) matching spine

Rejected

monolith single crate, 3-4 coarse crates

When the rejected choice is right

A single crate wins for a tiny prototype where cross-crate API churn outweighs separation; coarse 3-4 crates win for a small team avoiding boundary bureaucracy

Why: Enforces P9 separation; each crate independently testable; compile times parallelized by Cargo

ADR-04

Dependency policy

Chosen

Minimal: clap (CLI), byteorder (bit I/O endianness), log/env_logger, criterion (bench), proptest (property tests), arbitrary + libfuzzer-sys (fuzz)

Rejected

heavy-dep approach (ffmpeg-sys, openh264-sys)

When the rejected choice is right

ffmpeg-sys/openh264-sys win when you need production-grade, patent-licensed codecs immediately rather than an educational from-scratch implementation

Why: Avoids GPL/patent encumbrance; keeps codec logic fully in-crate; no bindgen complexity

ADR-05

Test vector / storage format

Chosen

Raw YUV4MPEG2 (.y4m) for input; raw .yuv 4:2:0 planar for unit fixtures; custom binary .vc NAL stream (Annex B byte stream) for bitstream output

Rejected

container formats (MP4/MKV), IVF

When the rejected choice is right

MP4/MKV/IVF win when interoperating with real players or streaming pipelines that expect a standard container with timing/muxing metadata

Why: No container parsing complexity; byte-exact comparison of decode output; standard tools (ffmpeg) can read y4m/yuv

ADR-06

Serialization (bitstream)

Chosen

Hand-rolled BitWriter/BitReader + exp-Golomb (vc-bitstream)

Rejected

serde + bincode, protobuf, nom

When the rejected choice is right

serde+bincode wins for byte-aligned sidecar/application metadata; it does not apply to sub-byte NAL syntax but does for an out-of-band stats file

Why: NAL/RBSP syntax requires sub-byte bit packing; serde cannot express this; hand-rolled is auditable against H.264 spec

ADR-07

Floating-point policy

Chosen

Forbidden in transform/quant/prediction hot paths; f32/f64 permitted only in PSNR metric computation and rate-control heuristics

Rejected

float DCT, float motion vectors

When the rejected choice is right

Float DCT wins for offline quality research where cross-platform bit-exactness is irrelevant and float SIMD throughput matters

Why: P1/P3: bit-exactness requires integer-only transforms; float results are platform-dependent

ADR-08

Concurrency model

Chosen

Single-threaded encode/decode by default; frame-level parallelism via rayon (optional feature flag, not in Phase 1–13)

Rejected

async/tokio, thread-per-macroblock

When the rejected choice is right

Thread-per-MB / wavefront (WPP) parallelism wins for HEVC/AV1-scale encoders where intra-frame parallelism is essential to hit real-time at 4K

Why: Frame-level dependencies (DPB, intra borders) require sequential MB order within a frame; rayon parallelism across independent frames is safe

ADR-09

Async model

Chosen

None (sync codec pipeline); async only in CLI I/O if needed

Rejected

tokio runtime throughout

When the rejected choice is right

async/tokio wins when the codec is embedded in a network streaming server where socket I/O multiplexing dominates the workload

Why: Codec is CPU-bound, not I/O-bound; async adds overhead without benefit

ADR-10

SIMD / intrinsics

Chosen

Optional #[cfg(target_feature)] modules behind a simd feature flag; fallback pure-Rust always present

Rejected

mandatory SIMD (breaks portability), no SIMD ever

When the rejected choice is right

Mandatory SIMD wins for a production encoder targeting fixed hardware where portability is irrelevant and every cycle counts

Why: Phase 1–13 target correctness; SIMD is Phase 14 optimization; pure-Rust fallback ensures CI portability

ADR-11

Integer transform implementation

Chosen

H.264 integer butterfly (Malvar et al. 2003 TCSVT) exact tables; fixed-point with defined shift counts

Rejected

float DCT, AAN algorithm, lookup-table DCT

When the rejected choice is right

Float/AAN DCT wins for a JPEG-style still-image codec where the transform is not normatively integer-specified

Why: Normatively specified; bit-exact across platforms; matches reference H.264 behavior

ADR-12

Entropy coding choice

Chosen

CAVLC primary (Phase 7); simplified CABAC secondary (Phase 13)

Rejected

Huffman-only, range coder (HEVC-style), arithmetic-only

When the rejected choice is right

An HEVC/AV1-style range coder wins when targeting those standards' compression efficiency rather than H.264 conformance

Why: H.264 specifies both; CAVLC simpler to implement and debug first; CABAC gives higher compression; both must roundtrip (I6)

ADR-13

Motion search algorithm

Chosen

Diamond search + EPZS as fast path; full exhaustive search as reference/verification path

Rejected

hierarchical search only, PDE optical flow

When the rejected choice is right

Hierarchical/pyramid search wins for large-motion 4K content where coarse-to-fine search escapes local minima diamond search falls into

Why: Diamond/EPZS matches H.264 encoder practice (x264 lineage); full search validates fast path output; SATD cost for accurate half-pel prediction

ADR-14

Sub-pixel interpolation

Chosen

H.264-normative 6-tap luma half-pel filter + bilinear quarter-pel; H.264 chroma 1/8-pel bilinear

Rejected

bicubic (HEVC), nearest-neighbor

When the rejected choice is right

Bicubic / 8-tap (HEVC) interpolation wins when implementing HEVC or AV1, where the longer filters are normative

Why: Normatively specified; required for conformant motion compensation (P4)

ADR-15

Rate-distortion mode decision

Chosen

Lambda * bits + SSE/SATD distortion; lambda from QP (sqrt formula); Lagrangian RD

Rejected

throughput-first greedy, VBSME only

When the rejected choice is right

Throughput-first greedy mode decision wins for real-time low-latency encoding (video calls) where RD-optimal search blows the latency budget

Why: P5: correct RD tradeoff; lambda from QP matches H.264 standard practice

ADR-16

Rate control

Chosen

Frame-level CBR approximation: QP step from (actual_bits / target_bits) ratio; no complex buffer model in Phase 13

Rejected

two-pass VBR, no rate control, full CPB buffer model

When the rejected choice is right

Two-pass VBR wins for offline file encoding where quality-per-bit is paramount; a full CPB buffer model wins for hardware-decoder (HRD) compliance

Why: Sufficient for the educational scope; complex rate control is out-of-scope Phase 14+

ADR-17

Logging

Chosen

log facade + env_logger; per-frame log at TRACE; per-MB at DEBUG disabled by default

Rejected

tracing/tokio-tracing, custom ring buffer

When the rejected choice is right

tokio-tracing wins when the codec runs inside an async service needing span-based distributed tracing

Why: Lightweight; standard ecosystem; structured per-frame output sufficient for P10 observability

ADR-18

Metrics / observability

Chosen

Per-frame: bits, PSNR (Y/U/V/avg), QP, mode histogram, MB-type distribution; emitted as structured log lines (JSON key=value) at INFO level

Rejected

Prometheus metrics server, InfluxDB

When the rejected choice is right

A Prometheus endpoint wins when the encoder is a long-running transcoding service scraped by monitoring infrastructure

Why: No service runtime; structured log lines parseable by standard tools (jq, awk); satisfies P10

ADR-19

Testing framework

Chosen

cargo test (unit/integration); proptest (property-based for transforms, entropy, color); manual .yuv golden-file comparison for end-to-end

Rejected

pytest via FFI, custom test harness

When the rejected choice is right

A pytest/FFI harness wins when QA engineers author conformance tests in Python against a C ABI

Why: Standard Rust; proptest for I3/I6/I7 invariant testing; golden files for regression

ADR-20

Fuzz testing

Chosen

cargo-fuzz + libfuzzer-sys; fuzz targets for vc-bitstream (NAL parse), vc-entropy (CAVLC decode), vc-decoder (full decode)

Rejected

AFL++ via ffi, honggfuzz

When the rejected choice is right

AFL++ wins when fuzzing the binary end-to-end with its advanced mutators, or fuzzing a non-libFuzzer target

Why: Phase 14 hardening requirement; libfuzzer integrates with cargo fuzz; no unsafe needed in fuzz driver

ADR-21

Benchmarking

Chosen

criterion crate; per-phase micro-benchmarks (transform, quant, MB encode, motion search, deblock); end-to-end frame throughput (fps)

Rejected

custom timing harness, perf-stat scripts

When the rejected choice is right

perf-stat / custom timing wins when profiling cache/branch hardware counters rather than statistical wall-clock benchmarking

Why: Statistical rigor; HTML reports; CI regression detection via criterion's threshold

ADR-22

CI/CD

Chosen

GitHub Actions: cargo test --workspace, cargo clippy -- -D warnings, cargo fmt --check, golden-file decode comparison, criterion bench (non-blocking)

Rejected

Jenkins, GitLab CI, local Makefile only

When the rejected choice is right

GitLab CI wins on self-hosted GitLab; Jenkins wins for complex on-prem matrix builds with custom hardware runners

Why: Standard for Rust OSS; matrix over stable + beta Rust; clippy enforces code quality

ADR-23

Conformance testing

Chosen

Decoder output (raw YUV) compared byte-for-byte against known-good decode of in-house–generated bitstreams; PSNR >= 30 dB at QP=28 on standard sequences

Rejected

JM reference decoder comparison (would require JM license)

When the rejected choice is right

JM reference-decoder comparison wins when formal H.264 conformance certification is required and the JM license is acceptable

Why: Avoids GPL dependency; in-house generated bitstreams + known decode output provide bit-exact regression; JM comparison as manual spot-check

ADR-24

Packaging / distribution

Chosen

cargo install from crate; single vc-cli binary; no C FFI ABI exposed in Phase 1–14

Rejected

shared library (.so/.dll), WASM target

When the rejected choice is right

A shared library wins when embedding the codec into another application; a WASM target wins for in-browser decoding

Why: CLI tool scope; C ABI is future work; WASM target conflicts with SIMD feature flag

ADR-25

Licensing

Chosen

MIT OR Apache-2.0 (Rust ecosystem dual-license)

Rejected

GPL-2 (x264/JM), LGPL

When the rejected choice is right

GPL wins when deriving directly from x264/JM source, where the viral license is unavoidable and acceptable

Why: Patent-free implementation; dual-license maximizes reuse; avoids viral GPL

ADR-26

Reproducibility

Chosen

Cargo.lock committed; pinned toolchain via rust-toolchain.toml (stable channel, pinned version); no non-deterministic codegen flags

Rejected

no lockfile, nightly-only features

When the rejected choice is right

Nightly-only features win when a critical portable_simd intrinsic is unstable and the perf gain justifies the reproducibility risk

Why: Bit-exact CI: same inputs produce same output on any CI runner; required for golden-file testing

ADR-27

Error handling

Chosen

thiserror-derived error enums per crate (e.g., BitstreamError, EntropyError); ? propagation; no panics in library code (only in test assertions)

Rejected

anyhow throughout, raw Box<dyn Error>, panics for codec errors

When the rejected choice is right

anyhow wins at the CLI binary boundary where ergonomic context chaining beats typed recovery

Why: Typed errors enable caller recovery (e.g., skip malformed frame); no panics in fuzz targets

ADR-28

Memory model

Chosen

Owned Vec<u8> buffers in Plane; no Arc/Rc in hot paths; DPB owns Frame values; clone on reference-list construction

Rejected

arena allocator, GC, shared-ptr graph

When the rejected choice is right

An arena allocator wins for a massively parallel encoder where per-frame allocation churn dominates; Arc wins when frames are shared read-only across many parallel slice workers

Why: Ownership clarity; no aliasing in transform hot paths; DPB eviction is explicit Vec::remove; clone cost is one frame (bounded by max_ref_frames)

Alternative Architectures (Roads Not Taken)

Alt-A — Wavelet / subband codec (no block transform).

frame --> [ whole-frame discrete wavelet transform ] --> quantize subbands --> entropy code

Wins when: blocking artifacts must be avoided and resolution/quality scalability is first-class (cinema, archival). Embodied by: JPEG 2000, Dirac/VC-2. Rejected because: the target is the block-based H.264 hybrid model; wavelets lack the motion-compensated macroblock structure this project teaches and have far less hardware decode support.

Alt-B — All-intra (Motion-JPEG style, no temporal prediction).

each frame coded independently: intra predict --> transform --> quantize --> entropy

Wins when: frame-accurate editing, lowest latency, and error resilience dominate (studio mezzanine, capture). Embodied by: Motion JPEG, ProRes, DNxHD. Rejected because: discarding inter-frame prediction forfeits the bulk of video compression (MM3); temporal prediction is the core lesson of the codec.

Alt-C — Learned / neural codec (autoencoder + entropy model).

frame --> [ neural encoder ] --> latent --> learned entropy model --> bitstream --> [ neural decoder ]

Wins when: maximum compression at any compute cost is the goal and a GPU is available (research, some streaming). Embodied by: DVC, neural-codec research stacks. Rejected because: it is non-deterministic across hardware, has no normative bitstream/conformance, and needs orders of magnitude more compute — incompatible with the bit-exact, CPU-only educational scope.

Alt-D — Next-generation block codec (HEVC/AV1).

frame --> quadtree/superblock partition (64×64+) --> CABAC/arithmetic --> in-loop filters (deblock+SAO/CDEF)

Wins when: ~50% better compression than H.264 justifies much higher encoder complexity (modern streaming). Embodied by: x265 (HEVC), SVT-AV1. Rejected (deferred) because: the quadtree, larger transforms, and mandatory arithmetic coding are a substantially larger project; H.264's fixed macroblock keeps the reconstruction loop and entropy roundtrip teachable.
