1. Goal

1.1 Precise Engineering Scope

Build a self-contained state-vector (Schrödinger) quantum circuit simulator in Rust. The system represents an n-qubit pure state as a dense complex amplitude vector of length 2ⁿ (complex128), applies quantum gates as in-place strided unitary updates over the vector without ever materializing a 2ⁿ×2ⁿ matrix, parses a subset of OpenQASM 2.0, samples computational-basis measurements (with collapse and mid-circuit measurement), computes Pauli/Hamiltonian expectation values, and exposes statevector analysis (fidelity, partial trace, entanglement entropy, Bloch vectors). It runs canonical algorithms — Bell/GHZ state preparation, quantum Fourier transform (QFT), Grover search, quantum teleportation — and validates against analytic results and an external reference simulator.

The contract is seed-deterministic single-platform reproducibility: identical gate sequences produce bit-identical statevectors on the same build, and measurement sampling is reproducible under a fixed seed. Gate application is exact float arithmetic (no stochasticity); only measurement consumes the RNG. Cross-platform bit-exactness is a non-goal (float reduction order, SIMD/threading reassociation).

1.3 Non-Goals

  • No density-matrix backend; pure state only. Noise is via stochastic trajectories — PhaseDeferred("FINAL_BLUEPRINT §Phase 10").
  • No GPU/accelerator path; CPU only — PhaseDeferred("FINAL_BLUEPRINT §Phase 9").
  • No tensor-network / matrix-product-state / Schrödinger–Feynman simulation; dense only.
  • No distributed (multi-node) statevector beyond a single host's RAM.
  • No full OpenQASM 3.0 (classical control flow, custom gate defs beyond subset).
  • No fermionic encodings, VQE/QAOA optimizers, or transpilation/routing to hardware topologies.
  • No cross-platform bit-exact amplitudes (only single-build determinism).

1.4 Intended Deployment Model

  • Library crates consumed by Rust code: build a Circuit, run on a Simulator, read statevector / samples / expectations.
  • CLI tool (qsim-cli): run circuit.qasm --shots 1024 --seed 7; expect circuit.qasm --observable "ZZ"; inspect circuit.qasm (statevector dump); sample/probs.
  • Single process, single host. Gate application optionally multithreaded (rayon) within a host; no network surface; input QASM is trusted (parsed, not executed as code).

1.10 Language Selection — Rust

State-vector simulation is a memory-bandwidth-bound loop: applying a single-qubit gate touches all 2ⁿ amplitudes in strided pairs, and the simulator's performance and correctness both live in that inner kernel. Rust provides exact control over memory layout (Vec<Complex64> contiguous), zero-cost abstractions for the strided index arithmetic, exhaustive enum gate types that make match-completeness a compile-time guarantee, fearless data-parallelism (rayon) over disjoint amplitude pairs, and no GC pauses on the hot loop. num-complex supplies Complex<f64>. SIMD intrinsics are available later without changing the model. C++ was rejected for memory-safety and tooling friction at equal performance; Python rejected because the inner loop is the project and interpreter overhead would force delegation to a C extension, defeating "from scratch"; Julia rejected because GC pauses and JIT warm-up sit on the hot loop and runtime dispatch weakens the exhaustive-gate-enum guarantee (ADR-6). All crates — core, gates, kernels, circuit, QASM, measurement, observables, analysis, noise, simulator — are Rust.

2. Why Build This

2.1 Unique Systems Knowledge Taught

  • Why a single-qubit gate is not a 2ⁿ×2ⁿ matmul but a strided pass touching amplitude pairs (i, i|bit) — the central performance and correctness insight.
  • How qubit-index ordering (endianness) maps logical qubits to bit positions in the amplitude index, and why a single convention must be enforced everywhere.
  • How the Born rule turns amplitudes into a sampling distribution, and how measurement collapse renormalizes the post-measurement state.
  • Why unitarity (norm preservation) is the invariant that makes the simulation physical, and how floating-point drift threatens it.
  • How entanglement shows up structurally (non-product amplitude vectors) and is quantified via reduced density matrices and von Neumann entropy.
  • Why memory (2ⁿ) is the hard ceiling and how fusion/threading push the bandwidth-bound kernel.

2.2 Historical and Architectural Significance

Feynman (1982) argued classical computers cannot efficiently simulate quantum systems — this simulator is that exponential cost made concrete (2ⁿ amplitudes). State-vector simulators (QuEST, qHiPSTER/Intel-QS, Qiskit Aer, Google qsim, Cirq) are the workhorses of quantum algorithm development and hardware verification. Reconstructing one from scratch demystifies "quantum simulation" into dense complex linear algebra with a clever in-place update pattern, and grounds the gate model in executable, testable kernels.

2.3 Engineering Muscles Developed

  • Bit-manipulation-heavy index arithmetic and its testing.
  • Designing an inner kernel for memory bandwidth (stride, locality, fusion).
  • Enforcing numerical invariants (unitarity, normalization) under float drift.
  • Building a small lexer/parser for a real format (OpenQASM).
  • Data-parallel decomposition of an in-place mutation (disjoint amplitude pairs).

2.4 Production Engineering Concepts Exercised

  • Resource estimation + guardrails (refuse circuits exceeding RAM).
  • Determinism + seeded sampling for reproducible experiments.
  • Observability: per-run gate counts, depth, peak memory, sample statistics.
  • Conformance against analytic + reference results as the trust gate.
  • Graceful failure on malformed QASM, non-unitary custom gates, qubit-index errors.

The engineer can predict memory cost (2ⁿ·16 bytes), explain why 30 qubits is a laptop ceiling, and debug a wrong amplitude by reading the gate kernel and endianness convention.

3.2 Subsystem Descriptions

qsim-core — Owns the state representation: a contiguous Vec<Complex64> of length 2ⁿ with the qubit-ordering convention (little-endian: logical qubit q occupies bit q of the amplitude index). Provides allocation, |0…0⟩ initialization, normalization check/repair tolerance, inner products, and the error hierarchy. The normalization invariant (Σ|aᵢ|²=1) is defined and asserted here. No gate logic, no I/O.

qsim-gates — The gate catalog: an exhaustive Gate enum with concrete 2×2 (single-qubit) and 4×4 (two-qubit) unitary matrices, parametric constructors (Rx/Ry/Rz/U3/phase), adjoint() for inverse circuits, and is_unitary(tol) validation (U†U≈I). Custom(matrix) supports arbitrary unitaries with a unitarity check at construction. Pure data + matrix math; does not touch the statevector.

qsim-apply — The performance heart: applies gates in place without forming the full operator. apply_1q iterates over the 2ⁿ⁻¹ index pairs differing in the target bit and applies the 2×2 update; apply_controlled masks on control bits; apply_2q/apply_kq enumerate the 2ᵏ-amplitude subspaces. A fusion buffer combines adjacent small gates on the same qubits into one matrix before the strided pass. This crate defines the simulator's bandwidth profile.

qsim-circuit — The circuit IR: an ordered list of Op { gate, targets, controls, params }, quantum + classical registers, optional moment/layer grouping, a builder API (h(0); cx(0,1); …), depth computation, and validation (qubit indices in range, no duplicate target/control, register sizes). Decoupled from how ops are executed.

qsim-qasm — A lexer + recursive-descent parser for an OpenQASM 2.0 subset (OPENQASM 2.0; include "qelib1.inc"; qreg/creg; standard gates; measure; barrier). Maps parsed statements to Circuit ops. Reports precise parse errors with line/column.

qsim-measure — Implements the Born rule: marginal probability of a qubit/subset by summing |amplitude|² over matching indices; sampling shots from the full distribution (alias/CDF method); collapse (project onto the measured outcome subspace + renormalize) for mid-circuit measurement; classical-register binding so subsequent gates can be classically controlled (subset).

qsim-observable — Pauli strings (tensor products of I/X/Y/Z) and weighted sums (Hamiltonians); computes ⟨ψ|O|ψ⟩ by applying the Pauli operator to a copy of the state and taking the inner product (or by the efficient per-Pauli expectation), plus variance for shot-noise estimates.

qsim-analysis — Statevector diagnostics: inner product and state fidelity |⟨φ|ψ⟩|² (global-phase-invariant), reduced density matrix via partial trace (reshape the 2ⁿ vector into a tensor and contract out traced qubits), von Neumann entanglement entropy from RDM eigenvalues, single-qubit Bloch vectors, and full probability tables.

qsim-noise — (Late phase, partly deferred) Kraus-operator channels (depolarizing, amplitude/phase damping) applied via the trajectory (quantum-jump) method on the pure statevector: at each noisy location, stochastically select a Kraus branch weighted by its norm and renormalize. Density-matrix noise is out of scope.

qsim-sim — The driver: takes a Circuit, estimates RAM (refuse if 2ⁿ·16 bytes exceeds budget), initializes the state, applies ops in order (optionally with fusion/threading), and returns the requested result (statevector, samples, probabilities, expectation). Manages the RNG seed and optional snapshots between ops.

qsim-cli — Thin front end over qsim-sim: run | sample | probs | expect | inspect subcommands (clap, ADR-24), QASM file input, seed/shots/budget flags, JSON/npy output (ADR-25). Owns no simulation logic; every result it prints is produced by the library crates.

6. Design Principles

P1. Unitarity Is the Physical Invariant

Every gate is unitary; the statevector norm stays 1. Built-in gates are validated (U†U≈I); Custom gates are checked at construction. Tradeoff: a validation cost per custom gate. Violation: a non-unitary "gate" makes amplitudes unphysical and every downstream probability wrong.

P2. One Endianness Convention, Everywhere

Little-endian: logical qubit q ↔ bit q of the amplitude index. Gates, QASM mapping, measurement, observables, and analysis all obey it. Violation: a CX with swapped roles or a measurement reading the wrong bit silently produces a different circuit's result.

P3. Apply Gates In Place, Never Materialize 2ⁿ×2ⁿ

A k-qubit gate updates the 2ᵏ-amplitude subspaces by strided iteration; the global operator is never formed. Tradeoff: index arithmetic complexity. Violation: forming the full matrix is O(4ⁿ) memory and makes n>~13 impossible.

P4. Memory Is the Hard Ceiling

State is 2ⁿ·16 bytes; the simulator estimates and refuses circuits exceeding the RAM budget before allocating. Violation: a naive run OOM-kills the process mid-circuit with no diagnosis.

P5. Measurement Obeys the Born Rule Exactly

Sampling uses |amplitude|²; collapse projects + renormalizes. Probabilities sum to 1 within tolerance. Violation: biased sampling or un-renormalized collapse corrupts mid-circuit-measurement results.

P6. Determinism Through Explicit Seeding

Gate math is deterministic per build; only measurement consumes the RNG, which is explicit and seeded. Violation: a global/implicit RNG makes shot results irreproducible and experiments unrepeatable.

P7. Global Phase Is Unobservable

Fidelity and state comparisons are global-phase-invariant (|⟨φ|ψ⟩|²). Violation: asserting raw amplitude equality flags physically identical states as different, breaking conformance.

P8. Gate Math Is Separate From Gate Application

qsim-gates holds matrices; qsim-apply holds the strided kernels. Adding a gate is a matrix; optimizing application is a kernel. Violation: entangling the two makes both fusion and new-gate addition risky.

P9. Fail Loud, Before Execution

Qubit-index out of range, non-unitary custom gate, register mismatch, or OOM are detected at validation/estimation time, not mid-run. Violation: a half-applied circuit leaves an unphysical state and an unclear error.

P10. Observability by Default

Every run reports gate counts by type, depth, peak memory, and (for sampling) shot statistics. Violation: a slow or wrong run with no telemetry is undebuggable.

P11. Reversibility Is Testable

Applying a circuit then its adjoint returns to the initial state (within tolerance). This is a free, powerful correctness probe. Violation: a kernel bug that breaks reversibility indicates a non-unitary application path.

P12. Conformance Is Earned in Two Independent Steps: Analytic, Then Reference

A claimed-correct algorithm must match both its closed-form analytic prediction and an independently-computed reference statevector (QuEST/Qiskit) before it is trusted; passing only one is insufficient. Tradeoff: doubles the fixture-authoring cost per algorithm. Violation: a shared-convention bug (e.g. endianness) can make the implementation agree with a wrong analytic derivation, or two implementations sharing the same bug agree with each other while both are wrong — a single-source "it matches" claim hides exactly this class of error.

8.2 Qubit Indexing and Endianness

Convention (locked, P2): logical qubit q occupies bit q of the integer amplitude index i. For n=3, basis state |q₂ q₁ q₀⟩ maps to index i = q₂·4 + q₁·2 + q₀. A gate on target t pairs indices (i, i ^ (1<<t)) that differ only in bit t. Controlled gates require the control bits set in i. This mapping is the single source of truth; QASM q[0] is logical qubit 0 = bit 0.

8.4 Single-Qubit Gate Application (Strided Kernel)

apply_1q(amps, n, t, U) — pairwise update rule, U = [[U00,U01],[U10,U11]]
  Pair set:    { (i0, i1) : i1 = i0 XOR 2^t, bit t of i0 = 0 }   — 2ⁿ⁻¹ disjoint pairs, covers all 2ⁿ indices once (I3, §8.2)
  Update:      amps'[i0] = U00·amps[i0] + U01·amps[i1]
               amps'[i1] = U10·amps[i0] + U11·amps[i1]
  Unmodified:  no amplitude outside the pair set is touched

Touches all 2ⁿ amplitudes in 2ⁿ⁻¹ disjoint pairs (parallelizable, P3). No global matrix formed.

8.5 Controlled / Multi-Qubit Application

apply_controlled(amps, n, controls, t, U) — masked pairwise update rule
  Control mask:  cmask = bitwise-OR of 2^c over c in controls
  Pair set:      { (i0, i1) : i1 = i0 XOR 2^t, bit t of i0 = 0, (i0 AND cmask) = cmask }   (I8)
  Update:        same 2×2 rule as apply_1q, applied only within this masked pair set
  Unmodified:    every amplitude outside the masked pair set, in particular all control=0 amplitudes (I8)

General apply_kq enumerates the 2ᵏ amplitudes whose k target bits vary while others are fixed, gathers them, applies the 2ᵏ×2ᵏ matrix, scatters back. CX is the controlled-X special case.

8.6 Measurement (Born Rule + Collapse)

prob_one(amps, q) = Σ over { i : bit q of i = 1 } of |amps[i]|²                       — Born rule, §8.6
sample(amps, q, rng) → outcome ∈ {0,1}, distributed as Bernoulli(prob_one(amps, q))   — P5, I11
collapse(amps, q, outcome) — projection + renormalization rule, mid-circuit (I7):
  Projected:      amps'[i] = amps[i] · 𝟙[bit q of i = outcome]   (indicator function; zero elsewhere)
  Renormalized:   amps'' = amps' / sqrt(prob(outcome))

Full-register sampling builds the CDF over 2ⁿ probabilities once, then draws shots. Marginals trace out unmeasured qubits. Classical outcomes bind to a ClassicalRegister (P5, I6).

8.7 Observables and Expectation

⟨ψ|O|ψ⟩ for a PauliString P: apply P to a copy ψ' = Pψ (X/Y/Z are cheap strided ops), then ⟨ψ|ψ'⟩ (real for Hermitian O). For a Hamiltonian Σ wₖPₖ: sum wₖ⟨ψ|Pₖ|ψ⟩. Variance ⟨O²⟩−⟨O⟩² estimates shot noise. Used to verify algorithms (e.g., ⟨ZZ⟩=1 on a Bell state).

8.8 State Analysis (Entanglement)

Partial trace: reshape the 2ⁿ vector into a tensor over (subsystem A, subsystem B), form ρ_A = Tr_B(|ψ⟩⟨ψ|) by contracting B indices. Eigenvalues λᵢ of ρ_A give von Neumann entropy S = −Σ λᵢ log λᵢ (entanglement entropy across the A|B cut). Bell state → S=1 bit (maximally entangled); product state → S=0. Bloch vector (rx,ry,rz)=(⟨X⟩,⟨Y⟩,⟨Z⟩) for single qubits.

Phase 9 — Performance: fusion, threading, SIMD

9.1 Objectives

Make the bandwidth-bound kernel fast: gate fusion (P8), rayon multithreading over disjoint amplitude pairs (ADR-8), optional SIMD; raise the practical qubit ceiling. GPU remains deferred.

9.2 Detailed Implementation Steps

Applies P8 (gate math separate from application, so fusion is a kernel concern), P3 (in-place strided apply), and ADR-8 (rayon over disjoint pairs); fusion + SIMD strategy follows the QuEST and Qulacs papers.

  • apply/fusion.rs: fuse runs of adjacent gates acting on the same (small) qubit set into one matrix, reducing the number of 2ⁿ passes (P8).
  • Parallelize apply_1q/apply_controlled: partition the outer index range across rayon threads; pairs are disjoint so no synchronization (ADR-8).
  • Optional SIMD (std::simd or intrinsics behind a feature flag) for the complex mul-add in the inner update — PhaseDeferred("FINAL_BLUEPRINT §Phase 9") for hand-tuned AVX.
  • Cache-blocking for high-bit targets (large stride) to improve locality.

9.3 Deliverable

9.4 Acceptance Criteria

  • Fusion preserves the statevector bit-for-bit vs unfused (within float tol) — correctness first (P1).
  • Threaded result equals single-threaded within tolerance (reassociation only, ADR-26).
  • ≥2× fusion speedup on a layered circuit; near-linear thread scaling to physical cores.
  • No data races (verified under cargo test + sanitizer where available).

  • Seeded trajectories reproducible bit-for-bit (I11), verified by fixture noise/trajectory_repro.json.

IBM (Pednault et al., 2019, "Leveraging Secondary Storage to Simulate Deep 54-qubit Sycamore Circuits", arXiv:1910.09534) published that an improved classical simulation using secondary storage could reproduce the task in ~2.5 days — and later tensor-network methods cut estimates further. Engineering lesson for this simulator: never hard-code a "max simulable n" as physics; the dense statevector wall is real (§ Scalability Analysis), but the classical-simulation frontier depends on method (secondary storage, tensor networks — § Alternative Architectures) and is an active research target, not a constant. A conformance claim of "no classical simulator can reproduce X" is out of scope and would be a fabrication if asserted.

Mental Models & First Principles

The compressed intuitions an expert holds about this system. Each predicts behavior and forecloses a bug class; the cited §/Phase is where this blueprint acts on it.

MM1 — The state vector is 2ⁿ complex numbers; every qubit doubles your RAM. A pure n-qubit state is a dense array of 2ⁿ amplitudes at 16 B each (complex128). Predicts: memory is the wall, not flops; 30→31 qubits doubles 16 GiB to 32 GiB. Without it: you size a machine by core count and OOM-kill mid-circuit. Applied: §4 (state size), § Back-of-Envelope Capacity Model, P4, I10 / Phase 1.

MM2 — A single-qubit gate is not a 2ⁿ×2ⁿ matmul; it is one streaming pass over disjoint amplitude pairs. Gate on target t touches every index (i, i⊕2ᵗ) exactly once. Predicts: cost is O(2ⁿ) per gate and the whole simulator is bandwidth-bound, not compute-bound. Without it: you form the full operator, pay O(4ⁿ) memory, and cap out near n=13. Applied: §8.4, P3, ADR-7 / Phase 2.

MM3 — The amplitude index is the bit string; one endianness choice fixes the entire machine. Logical qubit q lives in bit q of the integer index (little-endian, P2). Predicts: gate addressing, measurement bit, QASM mapping, and reference comparison all derive from this one convention. Without it: a CX with swapped control/target "looks right" but computes a different circuit. Applied: §8.2, P2, I5 / Phase 1, Phase 3, Phase 11.

MM4 — Unitarity is the conservation law; norm is the gauge you watch. Every gate preserves ‖ψ‖²=1; drift away from 1 is the symptom of any kernel or matrix bug. Predicts: a reversibility round-trip (circuit∘adjoint=I) is a near-free, total correctness probe. Without it: non-unitary "gates" silently make every downstream probability wrong. Applied: P1, P11, I1, I9 / Phase 2, Phase 11.

MM5 — Performance is bytes ÷ bandwidth, not flops ÷ FLOPS. The 1q kernel does ~14 flops per 32 B moved (≈0.44 flop/B), far below the machine balance, so wall-time ≈ (2ⁿ·32 B) ÷ sustained bandwidth. Predicts: fusion (fewer passes) helps; adding cores past bandwidth saturation does not. Without it: you chase SIMD/flop tuning and miss that the bus is the limit. Applied: §4 (arithmetic intensity), §9.7, § Back-of-Envelope Capacity Model / Phase 9.

MM6 — Measurement is the only stochastic step; gate math is exact and deterministic. The Born rule turns |amplitude|² into a distribution; only sampling consumes the RNG. Predicts: a fixed seed reproduces every shot; gate sequences are bit-identical per build. Without it: an implicit/global RNG makes experiments unrepeatable and "flaky" tests un-debuggable. Applied: §8.6, P5, P6, I11 / Phase 6.

MM7 — Collapse renormalizes; a measured state is a new normalized state. Projecting onto an outcome zeroes inconsistent amplitudes and rescales by 1/√p. Predicts: mid-circuit measurement is correct only if you renormalize before the next gate. Without it: subsequent gates act on an unnormalized state and joint statistics are wrong though marginals look fine. Applied: §8.6, I6, I7 / Phase 6.

MM8 — Entanglement is non-product structure; entropy of a reduced state quantifies it. A non-factorizable amplitude vector has S(ρ_A)=−Σλ log λ > 0 across a cut. Predicts: a Bell pair gives exactly 1 bit; a product state gives 0. Without it: you can compute amplitudes but cannot say how entangled, nor when a tensor-network method would be cheap. Applied: §8.8, MM10 / Phase 8, § Alternative Architectures.

MM9 — Global phase is unobservable; compare states up to a phase. ψ and e^{iθ}ψ are physically identical. Predicts: state equality must be fidelity |⟨φ|ψ⟩|², never raw-amplitude equality. Without it: conformance falsely fails QFT/Grover whose reference differs only by a phase. Applied: §8.8, P7, I12 / Phase 8, Phase 11.

MM10 — The dense statevector pays for entanglement you may not have. It stores all 2ⁿ amplitudes regardless of circuit structure, so a shallow / low-entanglement circuit is wastefully expensive here. Predicts: when bond dimension stays low, a tensor-network/MPS representation is exponentially smaller. Without it: you conclude "n=40 is impossible" when it is impossible only for this representation. Applied: § Scalability Analysis, § Alternative Architectures (tensor-network road), MM8.

QuEST made distribution a first-class decision: the same strided kernel runs under MPI across many nodes, partitioning the 2ⁿ amplitudes so the per-node slice fits local RAM and gates exchange "halo" amplitudes between ranks. That wins when a single circuit genuinely needs >1 host of RAM (40–45 qubits on a cluster) — the regime this single-host design explicitly defers (§ Scalability Analysis, ADR-8).

Qiskit Aer made method polymorphism the central choice: one front end dispatches to statevector, density-matrix, matrix-product-state, or stabilizer backends per circuit. That wins in a production SDK serving heterogeneous workloads — a user runs a noisy mixed-state job and a large Clifford job through the same API — at the cost of a far larger, multi-representation codebase than this focused statevector core (ADR-3, § Alternative Architectures).

Stim made a representational bet: restrict to Clifford circuits and store a stabilizer tableau (O(n²) bits) instead of amplitudes, simulating millions of qubits in polynomial time (Gottesman–Knill; Aaronson & Gottesman 2004). That wins overwhelmingly for stabilizer/error-correction circuits and exactly where this design is weakest — but it cannot represent a generic superposition like a T-gate output, so it is not universal (ADR-27, § Alternative Architectures).

NVIDIA cuStateVec made the hardware bet: the identical dense-statevector math, but kernels and memory live on the GPU, trading CPU DRAM bandwidth (~40 GB/s here) for HBM bandwidth (~1–3 TB/s) and offering fp32 to double the qubit ceiling in VRAM. That wins whenever a GPU is present and the state fits VRAM — the accelerator path this blueprint defers (ADR-4, ADR-9, deferred GPU feature).

Intel-QS / qHiPSTER (Smelyanskiy et al. 2016) made the distributed-memory + SIMD bet on commodity clusters: it partitions the 2ⁿ amplitudes across MPI ranks and vectorizes the per-rank strided kernel, so the gate's pair-update sometimes straddles a rank boundary and becomes an inter-node amplitude exchange. That wins for 40+ qubit circuits on an HPC cluster with fast interconnect — the same multi-node regime this single-host design defers (ADR-8, § Scalability Analysis) — but it inherits MPI's operational weight (rank placement, NUMA pinning, network tuning) that a single-process library deliberately avoids.

Where this design sits. Reading the table top-down, this simulator deliberately occupies the universal, exact, single-host, double-precision, pedagogically-legible corner: it keeps QuEST's clean strided kernel (§8.4) but drops MPI; it stays universal where Stim restricts to Clifford; it commits to one representation where Qiskit Aer multiplexes four; and it runs on the CPU bus where cuStateVec runs on HBM. Every one of those is a deliberate narrowing whose escape hatch is documented — distribution (Intel-QS/QuEST regime), method-polymorphism (Aer regime), and acceleration (cuStateVec regime) are not absent by oversight but deferred with explicit un-defer triggers (§ Deferred Features Register). The teaching payoff is that the reader sees the whole design space from the one point that makes the core mechanism — 2ⁿ amplitudes, one streaming pass per gate — maximally visible (MM1, MM2, MM5).

Back-of-Envelope Capacity Model

Every number derived from the System Constraints table (§4): reference host = 8 physical cores, 16 GiB DRAM, 40 GB/s sustained streaming bandwidth, ≈13 GB/s single-core; complex128 = 16 B; 1q kernel = 14 flops/amplitude over 32 B traffic (read 2 + write 2 amplitudes per pair). Compute before designing.

  1. Amplitude size. complex128 = 2 × f64 = 2 × 8 B = 16 B per amplitude. (§4: amplitude precision.)
  2. State RAM at n qubits. bytes(n) = 2ⁿ × 16 B. n=20 → 2²⁰·16 = 16 MiB; n=25 → 512 MiB; n=30 → 2³⁰·16 = 16 GiB. (§4: state size; I10.)
  3. Max n under the 16 GiB cap. Solve 2ⁿ·16 B ≤ 16 GiB ⇒ 2ⁿ ≤ 16·2³⁰/16 = 2³⁰ ⇒ n_max = 30 (state only). With one scratch buffer (fusion/observables, §4 memory overhead), 2·2ⁿ·16 ≤ 16 GiB ⇒ n_max = 29. (§4: qubit ceiling; ADR-16.)
  4. fp32 ceiling (deferred GPU path). complex64 = 8 B ⇒ 2ⁿ·8 ≤ 16 GiB ⇒ 2ⁿ ≤ 2³¹ ⇒ n_max = 31 — one extra qubit per precision halving (ADR-4, MM1).
  5. Per-gate memory traffic. One 1q gate streams the whole state once, read + write: traffic(n) = 2ⁿ·16 B × 2 = 2ⁿ·32 B. n=30 → 2³⁰·32 = 32 GiB moved per gate. (§4: 1q-gate cost; MM2.)
  6. Single-gate wall-time floor (bandwidth-bound). t_gate ≈ traffic ÷ bandwidth. n=30: 32 GiB ÷ 40 GB/s ≈ 34 GiB/(40·10⁹ B/s) ≈ 0.86 s per gate; single-core (13 GB/s) ≈ 2.6 s. n=25: 1 GiB·2 ÷ 40 GB/s ≈ 54 ms. (§4: reference host, threading; MM5.)
  7. Arithmetic intensity confirms memory-bound. 14 flops ÷ 32 B = 0.44 flop/B; the host balance is ~ (8 cores × few GFLOP/s) ÷ 40 GB/s ≫ 0.44, so the kernel is firmly memory-bound — adding cores past bandwidth saturation buys nothing (§4: arithmetic intensity; MM5).
  8. Thread saturation point. Bandwidth 40 GB/s ÷ single-core 13 GB/s ≈ 3 cores saturate the bus; beyond ≈3 threads the 1q kernel stops scaling (§4: threading; ADR-8, Phase 9 acceptance).
  9. Depth/circuit cost. A circuit of G gates costs ≈ G × t_gate (each gate one pass). A 100-gate circuit at n=28: t_gate ≈ (2²⁸·32 B)/40 GB/s = 8 GiB/40 GB/s ≈ 0.21 s ⇒ ≈ 21 s unfused; fusion targeting ≥2× (§4) → ≈ 10 s (§4: fusion target; Phase 9).
  10. Sampling CDF scratch. Building the CDF over 2ⁿ probabilities at 8 B (f64) each = 2ⁿ·8 B = half a state buffer; n=30 → 8 GiB extra, counted against the budget (§4: sampling scratch; I10).
  11. Shot sampling cost. Build CDF once = O(2ⁿ); each shot = O(log 2ⁿ)=O(n) binary search. 1024 shots at n=30 ≈ one 2³⁰ pass + 1024·30 comparisons ≈ dominated by the single CDF pass (~0.4 s), shots negligible (§4: sampling; ADR-12).
  12. Trajectory-noise budget. Estimating a Pauli ⟨O⟩ to ±0.01 at 95% CI needs N ≈ (1.96/0.01)² ≈ 3.8×10⁴ trajectories, each a full circuit sim — i.e. ~4×10⁴× the single-run cost, embarrassingly parallel across seeds (§4: trajectory budget; Phase 10, ADR-15).

Alternative Architectures (Roads Not Taken)

Three fundamentally different architectures for simulating quantum circuits — not parameter tweaks of the dense statevector. Each: sketch, regime where it wins, the real system that embodies it, why rejected here.

Alt-1 — Stabilizer / Clifford simulation (tableau)

   Circuit (Clifford: H, S, CX, Pauli, measure)
        |
        v
  +-----------------------------+
  | Stabilizer tableau          |   n generators × (2n+1) bits
  |  [ X-part | Z-part | phase ] |   -> O(n^2) storage, NOT 2^n
  +-----------------------------+
        | gate = row/column update (O(n) / O(n^2))
        v
   Measurement = Gaussian elimination over GF(2)

Regime where it wins: Clifford-only circuits — quantum error correction, stabilizer codes, randomized benchmarking — where it runs millions of qubits in polynomial time (Gottesman–Knill theorem; Aaronson & Gottesman 2004). Real system: Stim (Craig Gidney); also CHP. Why rejected here: not universal — it cannot represent a generic superposition (a single T gate leaves the stabilizer formalism), so it fails this project's universality goal (ADR-3, ADR-27). The dense statevector pays 2ⁿ precisely to be universal. Cost to add here later: a parallel qsim-stabilizer backend with its own tableau type and a circuit classifier that routes Clifford-only circuits to it — large, but the integer arithmetic eliminates float tolerances entirely (ADR-27); un-defer when stabilizer/QEC workloads dominate.

Alt-2 — Tensor-network / matrix-product-state contraction

   |psi> as a network of rank-≤χ tensors (one per qubit)
   q0   q1   q2   q3
   [T]--[T]--[T]--[T]      bond dimension χ caps entanglement
    |    |    |    |
   gate = local tensor update; readout = contract the network
   cost ~ poly(n) * χ^O(1)   (χ small for shallow/low-entanglement)

Regime where it wins: low-entanglement or shallow circuits, where bond dimension χ stays small and storage is poly(n)·χ instead of 2ⁿ — enabling 40–100+ qubits a dense statevector can never hold (MM10). Real system: quimb, ITensor, NVIDIA cuTensorNet; theory from Markov & Shi 2008. Why rejected here: cost is exponential in entanglement (χ blows up for deep/highly-entangling circuits like random supremacy circuits), it gives compressed/approximate access rather than every exact amplitude, and the contraction-order problem is its own research area — outside a from-scratch dense-statevector teaching scope (ADR-3, § Scalability Analysis). Cost to add here later: a new Circuit→tensor-network lowering plus a contraction-order optimizer — it shares the IR (§8) and gate matrices (§8.3) but replaces the entire apply/measure stack; un-defer when target circuits are provably low-bond-rank (MM10).

Alt-3 — Schrödinger–Feynman hybrid (path-sum / circuit cutting)

   Split circuit into low-entanglement blocks A | B
   +---------+        +---------+
   | block A | --few-- | block B |    cut the few entangling gates
   +---------+ gates   +---------+
   amplitude = sum over cut-edge paths of (A-amp * B-amp)
   memory ~ 2^(n/2) per block; time ~ exponential in #cut gates

Regime where it wins: many-qubit circuits under a hard RAM wall where you need only a few output amplitudes/samples, not the whole vector — it trades the 2ⁿ memory wall for time exponential in the number of cut (entangling) gates. This is the method behind the classical pushback on Sycamore (§ Phase 11.6). Real system: Google qsimh (the qsim hybrid Schrödinger–Feynman simulator); Pednault et al. 2017/2019. Why rejected here: it is an algorithm for escaping the memory wall at the cost of exponential recomputation and intricate path bookkeeping — a specialization layered on top of statevector simulation, not the foundational dense kernel this blueprint builds first (ADR-3, ADR-7, § Scalability Analysis). Cost to add here later: a circuit-cutting pass plus a path-sum driver that reuses the existing dense kernel (§8.4) per block — it builds on this design rather than replacing it, which is exactly why it comes after the foundation; un-defer when n exceeds single-host RAM but only few amplitudes/samples are needed.

Alt-4 — Density-matrix simulation (exact mixed states)

   State is rho (2^n x 2^n complex), NOT a 2^n vector
   +-----------------------------+
   | rho   (Hermitian, tr=1)     |   4^n complex entries
   +-----------------------------+
   gate:    rho -> U rho U^dagger          (two-sided multiply)
   noise:   rho -> sum_k K_k rho K_k^dag   (Kraus, EXACT, no sampling)
   readout: <O> = tr(O rho)  ; entropy from eigenvalues of rho

Regime where it wins: exact open-system / noisy simulation — when you need the true mixed state rather than a Monte-Carlo estimate, and n is small enough (≈half the pure-state ceiling) that 4ⁿ entries fit. One density-matrix evolution replaces the ~4×10⁴ trajectories item 12 of the capacity model budgets, and it represents decoherence exactly (MM7). Real system: Qiskit Aer density_matrix method; the formalism is Nielsen & Chuang Ch 8 / Watrous. Why rejected here: it squares the memory cost — 4ⁿ·16 B caps near n=15 on 16 GiB versus n=30 for the pure state (MM1) — and this project's noise goal is met more cheaply by trajectories on the pure state (ADR-15). Cost to add here later: a qsim-density backend whose state is 4ⁿ and whose gate is a two-sided multiply; it reuses gate matrices (§8.3) and Kraus channels (§ Phase 10) but doubles the index arithmetic and halves the qubit ceiling; un-defer when exact mixed-state fidelity is required (§ Deferred Features Register).

Choosing among the roads (decision sketch). The four alternatives are not ranked; each owns a regime, and a mature simulator dispatches per circuit (the Qiskit Aer lesson, § Comparative Architecture Table):

  • Circuit is Clifford-only → Alt-1 stabilizer (polynomial; millions of qubits).
  • Circuit is shallow / low-entanglement → Alt-2 tensor-network (poly·χ; 40–100+ qubits).
  • Circuit is deep, many-qubit, few outputs needed, RAM-bound → Alt-3 Schrödinger–Feynman (trade memory for recomputation).
  • Circuit needs exact mixed state / strong noise, small n → Alt-4 density matrix (4ⁿ, no sampling).
  • Otherwise — universal, exact, every amplitude, n≤30 on one host → this dense statevector design.

This blueprint builds the last bullet first because it is the foundation the others either specialize (Alt-3 reuses the dense kernel, §8.4) or contrast against (Alt-1/2/4 replace the representation) — mastering it is the prerequisite for reasoning about any of them (§2.7, MM10).
