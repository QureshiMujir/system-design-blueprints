In one paragraph

A quantum circuit simulator is a program that runs a quantum circuit on an ordinary computer so you can see the exact amplitudes a real quantum machine would be working with. This design is a Rust workspace of eleven crates, one of them a command-line tool (§1.6, §1.4). It holds the whole quantum state as one dense list of 2ⁿ complex numbers, updates it one gate at a time without ever building a 2ⁿ×2ⁿ matrix, and samples measurements from it (§1.1). Its defining property is that memory, not arithmetic, is the limit: the state costs 2ⁿ·16 bytes and every gate is one streaming pass over it (§4.1, MM5). A learner or prototyper runs it on one host (§1.5, §1.4).

The problem, concretely

You want to check that a three-qubit entangling circuit really produces the state a textbook says it does. The obvious approach is to write every gate as a full matrix over all n qubits and multiply the matrices into the state. The cost is O(4ⁿ) memory, which makes anything above roughly 13 qubits impossible (P3, MM2). So the design never forms that matrix. A gate on one qubit only ever mixes pairs of amplitudes, so it becomes one pass over the vector (§2.1, §8.4).

The second trap is silent wrongness. Suppose a controlled-NOT (CX, a gate that flips a target qubit only when a control qubit is 1) has its control and target swapped. Every gate can still be perfectly unitary (norm-preserving), so no unitarity check fires, yet the circuit computes a different result (MM3, P2, Hard Question 3). The design answers this with one fixed qubit-ordering rule everywhere and with checks against known answers (I5, P12).

The third trap is running out of memory halfway through. The state for 30 qubits is about 16 GiB (§2.6, §4.1), and a naive run is killed by the operating system mid-circuit with no useful message (P4). So the simulator estimates the bytes first and refuses before allocating (I10).

How it works, end to end

Follow one run of run bell.qasm --shots 1024 --seed 7 (§1.4, with the examples/bell.qasm file of §10) through the boxes of §3.1:

 qsim-cli (run | sample | probs | expect | inspect)
      -> qsim-sim      (Simulator::run: seed, RAM estimate, applies ops in order)
           builds from:  qsim-qasm (lexer + parser) -> qsim-circuit (Op list, validation)
           applies with: qsim-apply (apply_1q, apply_controlled, apply_2q, apply_kq, fusion)
                         uses matrices from qsim-gates, mutates qsim-core (StateVector)
           reads out via: qsim-measure | qsim-observable | qsim-analysis
           late phase:    qsim-noise (stochastic Kraus channels)
  1. qsim-cli is a thin front end with no simulation logic of its own. It takes a QASM file and seed, shots and budget flags, and prints what the library crates produced (§3.2, ADR-24).
  2. qsim-qasm is a hand-written parser for a subset of OpenQASM 2.0 (recursive descent, a parser written as one function per grammar rule). It turns each statement into a Circuit and reports line and column on a syntax error (§3.2, §8.10, ADR-11).
  3. qsim-circuit holds the circuit as an ordered list of Op { gate, targets, controls, params }. validate() rejects an out-of-range qubit, a repeated target or control, and bad register sizes before anything runs (§3.2, §11.4, I4, P9).
  4. qsim-sim estimates 2ⁿ·16 bytes via estimate_bytes and refuses if that exceeds the budget (I10, §11.7). It then allocates the state, owns the seeded random number generator and applies the ops in order (§3.2).
  5. qsim-core owns StateVector { amps: Vec<Complex64>, n }, the index convention and the norm check. It contains no gate logic and no I/O (§3.2, §11.1).
  6. qsim-gates is pure data: the Gate enum with its 2×2 and 4×4 matrices, adjoint() and is_unitary(tol). It never touches the state (§3.2, P8).
  7. qsim-apply is the performance heart. apply_1q walks the index pairs, apply_controlled masks on control bits, and apply_kq handles k-qubit gates (§3.2, §8.4, §8.5).
  8. qsim-measure, qsim-observable, qsim-analysis read the finished state: shots and collapse, Pauli expectations, and fidelity/partial trace/entropy/Bloch vectors (§3.2).
  9. qsim-noise applies noise by picking one random branch per noisy location, weighted by its norm, and renormalizing (a quantum-jump or trajectory method). It comes in a late phase and is partly deferred (§3.2, ADR-15).

The result comes back as a statevector, a list of counts, or one number (RunResult, §11.7). Gate application is exact float arithmetic, and only measurement consumes the random number generator (§1.1, P6).

The core ideas

One gate is one pass over disjoint pairs (§8.4, MM2, P3)

The state is a list of 2ⁿ amplitudes. A gate on target qubit t pairs each index i0 (whose bit t is 0) with i1 = i0 XOR 2^t, and replaces the two numbers using the gate's 2×2 matrix U:

amps'[i0] = U00·amps[i0] + U01·amps[i1]
amps'[i1] = U10·amps[i0] + U11·amps[i1]

There are exactly 2ⁿ⁻¹ such pairs, they never overlap, and together they cover every index once (§8.4, I3). Nothing outside a pair is touched, so the pairs can run on different threads with no locks (§4.1, P3). For n=1 the whole state is one pair (§8.12). Applying H (§8.3) to the pair of amplitudes (1, 0) gives the equal superposition that Phase 2 expects from H(0) on |0⟩ (Phase 2 deliverable).

One endianness rule decides everything (§8.2, P2, ADR-5)

Logical qubit q is bit q of the integer index (little-endian). For three qubits the basis state |q₂ q₁ q₀⟩ sits at index q₂·4 + q₁·2 + q₀, and QASM q[0] is bit 0 (§8.2). Gate addressing, measurement, QASM lowering, observables and analysis all read this one rule (P2, MM3). If one layer disagreed, a CX would still look plausible but compute another circuit (P2). The convention is frozen: changing it is a major-version event (Compatibility & Versioning).

Controlled gates are the same update with a mask (§8.5, I8)

For a controlled gate, build cmask, the bitwise OR of 2^c for each control c. The pair set is the single-qubit pair set restricted to indices where i0 AND cmask = cmask. The same 2×2 rule is applied inside that set, and every amplitude with a control at 0 is untouched (§8.5, I8). CX is the special case of controlled-X. A k-qubit gate gathers the 2ᵏ amplitudes whose target bits vary, applies a 2ᵏ×2ᵏ matrix, and scatters them back (§8.5). The CX truth table is a Phase 3 fixture: |10⟩ goes to |11⟩ exactly (Phase 3 acceptance).

Measurement picks an outcome, then collapses (§8.6, P5, MM6, MM7)

The Born rule says an outcome's probability is the squared size of its amplitude. For one qubit, prob_one sums |amps[i]|² over indices whose bit q is 1 (§8.6). To measure in the middle of a circuit, draw the outcome from that probability, zero every amplitude inconsistent with it, then divide by sqrt(prob(outcome)) (collapse, §8.6). Skipping the divide leaves a state whose marginals look right but whose joint statistics are wrong (MM7, Hard Question 5). For many shots, build the cumulative distribution once over all 2ⁿ probabilities, then draw each shot by binary search (§4.1, Capacity Model item 11). Only this step uses the random number generator, and it is explicitly seeded, so a fixed seed repeats every shot (P6, I11, MM6).

Expectations and entanglement come from the same vector (§8.7, §8.8, MM8)

To get the expected value of a Pauli string (a tensor product of I, X, Y, Z), apply it to a copy of the state and take the inner product with the original (§8.7). A Hamiltonian is a weighted sum of such strings and its expectation is the weighted sum of theirs. To measure entanglement, reshape the vector into a tensor over two groups of qubits A and B and contract B away to get ρ_A (the partial trace); its eigenvalues λᵢ give the von Neumann entropy S = −Σ λᵢ log λᵢ (§8.8). The blueprint's checks: a Bell state has ⟨ZZ⟩=1 and S(A)=1 bit, and a product state has S=0 (§8.9, §8.8, MM8).

Speed is bytes divided by bandwidth (§4.1, MM5, Capacity Model items 5 to 9)

One single-qubit gate reads and writes every amplitude once, so it moves 2ⁿ·32 bytes. The kernel does 14 flops per 32 bytes, about 0.44 flop per byte, so the memory bus, not the arithmetic units, sets the speed (§4.1, items 5 and 7). Two levers follow. Gate fusion merges adjacent small gates on the same qubits into one matrix, so there are fewer passes (§3.2, Phase 9.2). More threads help only until the bus saturates, about three cores on the reference host (item 8, M3). Fusion must stop at a measurement boundary because collapse intervenes (Phase 9.6).

The trade-offs — where engineers disagree

State representation: dense vector (ADR-3)

Chosen: a dense pure-state vector, which matches the title's scope (§9, ADR-3). Rejected: density matrix, matrix-product state (MPS), Schrödinger–Feynman. When the rejected choice is right: a density matrix for mixed states or hardware-faithful noise; an MPS for shallow, low-entanglement circuits; Schrödinger–Feynman when only a few output amplitudes of a deep many-qubit circuit are needed under a RAM wall (§9, ADR-3).

Precision: complex128 (ADR-4)

Chosen: two 64-bit floats per amplitude, for norm and expectation precision (§9, ADR-4). Rejected: complex64. When the rejected choice is right: on GPUs, and at n≥34 where halving the per-amplitude size is the difference between fitting and running out of memory, provided the circuit is shallow enough that rounding stays under the measurement noise (§9, ADR-4). The blueprint's own count: one extra qubit on 16 GiB (Capacity Model item 4).

Qubit order: little-endian (ADR-5)

Chosen: qubit q is bit q, matching the Qiskit textbook convention (§9, ADR-5, P2). Rejected: big-endian. When the rejected choice is right: when conforming to a reference whose published statevectors are big-endian, so the comparison layer avoids a per-amplitude bit-reversal remap (§9, ADR-5, Phase 11.6).

Gate application: in-place strided kernels (ADR-7)

Chosen: strided pair updates, O(2ⁿ) work and no big matrix (§9, ADR-7, P3). Rejected: full Kronecker matrix multiplication. When the rejected choice is right: at very small n (about 12 or less), where a fused full operator applied by a tuned matrix-multiply library beats many strided passes, and for dense many-qubit gates whose operator is unavoidably full (§9, ADR-7).

Parallelism: rayon over disjoint pairs (ADR-8)

Chosen: the rayon data-parallel library over disjoint index ranges, with no locks (§9, ADR-8, Performance Engineering). Rejected: raw threads, or no threading. When the rejected choice is right: single-threaded for n around 16 or below, where spawn and join cost more than the work; raw threads or MPI at the distributed boundary, where ranks are pinned to NUMA nodes and halo exchange is overlapped (§9, ADR-8).

Noise: trajectories on the pure state (ADR-15)

Chosen: stochastic quantum-jump runs on the pure vector, which stays cheap (§9, ADR-15). Rejected: a density matrix, which is exact but sized 4ⁿ (Alternative Architectures, Alt-4). When the rejected choice is right: when you need the exact mixed state rather than a Monte-Carlo estimate, at small n with strong noise where trajectory variance is large and 4ⁿ memory is affordable (§9, ADR-15). The Monte-Carlo price is about 3.8×10⁴ runs for ±0.01 at 95% confidence (Capacity Model item 12).

Memory policy: estimate and refuse (ADR-16)

Chosen: estimate bytes and refuse over budget before allocating (§9, ADR-16, P4, I10). Rejected: best-effort allocation. When the rejected choice is right: when a swap-backed or out-of-core path exists. Refusing up front rules out a degraded-but-completing run, as in secondary-storage simulation (§9, ADR-16).

Determinism: per build, not across platforms (ADR-26)

Chosen: bit-identical results for the same build, with seeded sampling (§9, ADR-26, §1.1). Rejected: cross-platform bit-exact results. When the rejected choice is right: a regulated or audited reproducibility requirement. You pin a fixed reduction order, switch off SIMD and threading reassociation, and accept a large throughput loss (§9, ADR-26). Threaded runs may differ in low-order bits (Phase 9.6, Compatibility & Versioning).

Roads not taken (Alternative Architectures, Deferred Features Register)

Stabilizer/Clifford tableau (Alt-1): store O(n²) bits instead of amplitudes. It wins for Clifford-only circuits such as error-correction codes, where it handles millions of qubits in polynomial time (Stim is the real example). It is rejected because it is not universal: one T gate leaves the formalism (ADR-27, Alternative Architectures).

Tensor-network / MPS (Alt-2): store poly(n)·χ numbers, where χ is the bond dimension that caps entanglement. It wins for shallow or low-entanglement circuits, reaching 40 to 100+ qubits. It is rejected because χ blows up for deep, highly entangling circuits and it gives compressed access, not every exact amplitude (MM10, Alternative Architectures).

Schrödinger–Feynman hybrid (Alt-3): split the circuit into blocks, cut the few entangling gates, and sum over paths. It trades the memory wall for time that grows with the number of cuts, so it wins when only a few output amplitudes are needed. It is rejected as a specialization built on top of the dense kernel, which this blueprint builds first (Alternative Architectures).

Density matrix (Alt-4): exact mixed states at 4ⁿ·16 bytes, which caps near n=15 on 16 GiB against n=30 for the pure vector. It wins when exact noise is needed at small n (Alternative Architectures).

The Deferred Features Register lists seven items (density matrix, GPU, SIMD-fused AVX kernels, tensor-network, OpenQASM 3.0, distributed multi-node, VQE/QAOA), each with an un-defer trigger such as "single-host RAM exhausted". The register's "Building Phase" column puts the density-matrix backend at Phase 10 and tensor-network at Phase 11, while Appendix B defines those phases as trajectory noise and conformance, Phase 10.1 says density-matrix noise "stays deferred", and §1.2 and §1.3 put those backends outside scope. The blueprint does not reconcile the two readings.

What must never be false

  • I1: the squared norm of the state is 1 within 1e-10 after every non-measurement op. Noticed by a norm check (debug or periodic); recovery is to renormalize or fail (§7).
  • I2: every gate matrix is unitary (U†U≈I). Noticed by is_unitary at build or construction; the gate is rejected (§7, §4.1).
  • I3: the amplitude vector has length exactly 2ⁿ. A length assert fires, and allocation fails (§7).
  • I4: every qubit index is below n, and targets and controls are distinct. Range and duplicate checks in circuit validation raise QubitIndexError (§7).
  • I5: one endianness convention is used by every crate. Noticed by conformance circuits (Bell, GHZ, CX truth table) with analytically known amplitudes (§7, Invariant Enforcement Summary).
  • I6: probabilities sum to 1 within 1e-10. A probability-sum check renormalizes (§7).
  • I7: the state is renormalized after a collapse. A post-collapse norm check catches it (§7).
  • I8: a controlled gate changes only amplitudes whose control bits are set. A masked-update test catches it (§7, §8.5).
  • I9: a circuit followed by its adjoint returns the start state within 1e-9. A round-trip test catches it, and recovery is to bisect the kernel (§7, P11).
  • I10: the RAM estimate is within budget before allocation. A pre-run check refuses (§7).
  • I11: the measurement random number generator is explicit and seeded. Noticed by seed provenance recorded in the run metadata (§7, Threat Model, Nondeterministic results).
  • I12: fidelity ignores global phase. A phase-shift test checks it, and comparisons use |⟨φ|ψ⟩|² (§7, P7).

What breaks in production

The simulator is a library and CLI, not a network service, and runs on a single host (Threat Model; Operational Readiness). The most instructive failures:

  • Wrong amplitude (Failure Modes & Recovery). The result differs from the analytic answer. Cause: a gate matrix, endianness or index bug. Detected by conformance against known results (I5). Recovery is manual: check the matrix and the convention, using statevector-diff (§2.7).
  • Norm drift (Failure Modes & Recovery). The squared norm drifts away from 1 as float errors accumulate over a long circuit. Detected by the norm check (I1); the system renormalizes automatically, and the operator investigates which gate caused it.
  • Biased sampling (Failure Modes & Recovery). Counts do not match the expected distribution. Cause: a bug in the cumulative-distribution build or in the random number generator. Detected by a counts fixture (I6). Recovery is manual: check the CDF and the seed.
  • Collapse corruption (Failure Modes & Recovery). A mid-circuit measurement gives wrong statistics. Cause: the renormalization step was skipped. Detected by the post-collapse norm check (I7), and recovery is to renormalize and verify the collapse path.
  • Fusion/thread mismatch (Failure Modes & Recovery). Results differ by execution mode. Cause: a kernel race or fusion bug. Detected by equivalence fixtures. The automatic recovery is to disable the flag; manual recovery is to isolate the kernel (Phase 9.9).
  • OOM refusal (Failure Modes & Recovery). The run is rejected because n is too large for RAM. Detected by estimate_bytes before allocation (I10). There is no automatic recovery: use fewer qubits or more RAM, and the error reports the needed bytes (Threat Model, Memory exhaustion).
  • Noise wrong (Failure Modes & Recovery). The decay curve is wrong. Cause: a Kraus operator or renormalization error. Detected by checking that ΣK†K = I and by a decay fixture (Phase 10).
  • Parse failure (Failure Modes & Recovery). QASM is rejected for bad syntax or an unsupported construct. Detected as QasmParse with line and column. Recovery is to fix the file.

The blueprint's recovery philosophy: correctness and resource failures fail loudly before or at execution; numerical drift is repaired or flagged; algorithm mismatches surface through conformance (Failure Modes & Recovery, P9).

Threats worth knowing (Threat Model; the attack surface is untrusted QASM and circuit data, never executed as code). §1.4, by contrast, says "input QASM is trusted (parsed, not executed as code)"; the blueprint does not reconcile the two.

  • Memory exhaustion from a huge n, answered by refusing before allocation (I10, P4).
  • Parser denial of service from a deeply nested or huge file, answered by an input size cap and bounded recursion (Threat Model, Parser DoS).
  • Integer overflow at n of 64 or more, answered by requiring n<64 plus a budget and checked shifts (Threat Model, Integer overflow).
  • Supply chain: a malicious dependency (rand, num-complex, nalgebra), answered by a pinned Cargo.lock and cargo audit (Threat Model, Supply chain).
  • Reference mismatch from endianness or phase differences, answered by a documented convention and a remap (P2, P7, Threat Model, Reference mismatch).

How it compares

  • QuEST runs the same strided kernel but distributes it with MPI across nodes, so each node holds a slice and gates exchange halo amplitudes. That wins when one circuit needs more than one host of RAM (40 to 45 qubits on a cluster); this design defers that regime (Comparative Architecture Table, ADR-8).
  • Qiskit Aer dispatches one front end to statevector, density-matrix, MPS or stabilizer backends per circuit. That suits an SDK serving mixed workloads, at the cost of a much larger codebase than one focused statevector core (Comparative Architecture Table, ADR-3).
  • Stim stores a stabilizer tableau of O(n²) bits instead of amplitudes. That wins overwhelmingly for Clifford and error-correction circuits, and fails for generic superpositions such as a T-gate output (Comparative Architecture Table, ADR-27).
  • NVIDIA cuStateVec runs the same dense math on the GPU, trading about 40 GB/s of DRAM bandwidth for roughly 1 to 3 TB/s of HBM, and offers fp32 to double the qubit ceiling. It wins whenever a GPU is present and the state fits in VRAM, the path this blueprint defers (Comparative Architecture Table, ADR-4, ADR-9).
  • Intel-QS / qHiPSTER partitions the amplitudes across MPI ranks and vectorizes each rank's kernel, so a gate pair can straddle a rank boundary and become a network exchange. It wins for 40+ qubit circuits on an HPC cluster, with the operational weight of rank placement and NUMA pinning (Comparative Architecture Table).

The table itself has columns for four systems; Intel-QS appears only in a paragraph below it (Comparative Architecture Table). This design sits at the universal, exact, single-host, double-precision corner (Comparative Architecture Table, MM1, MM2, MM5).

Questions to test yourself

  1. Why is a single-qubit gate O(2ⁿ) time but O(1) extra memory, and why does that make the simulator memory-bandwidth-bound rather than compute-bound? — Hint: §8.4, §4.1 and MM5.
  2. A CX produces the wrong entangled state but every gate passes is_unitary. Which two invariants/conventions would you check first, and why does unitarity not catch this? — Hint: §8.2, §8.5 and MM3.
  3. After a mid-circuit measurement, marginals look right but joint statistics are wrong. What step was skipped, and which invariant detects it? — Hint: §8.6 and MM7.
  4. Why does the project refuse a circuit before allocating rather than catching an allocation failure, and which principle + invariant encode that? — Hint: §4.1 and ADR-16 in §9.
  5. When is the rejected full-Kronecker-matmul gate application actually the right call, and at what n does it cross over? — Hint: ADR-7 in §9 and the Capacity Model.

If you only remember three things

A quantum state is a list of 2ⁿ numbers, and a gate is one in-place pass over disjoint pairs of them, so memory and bandwidth set the limit, not arithmetic (MM1, MM2, MM5). One qubit-ordering rule and unitarity checks, backed by tests against known answers and a reference simulator, are what keep a wrong circuit from looking right (MM3, MM4, P12). Only measurement is random, and it is seeded, so the same build and seed reproduce the same shots (MM6, P6).

Words used here

  • Amplitude: the complex number attached to one basis state; the state is a list of 2ⁿ of them (§8.1).
  • Unitary: a gate that preserves the state's total size, U†U=I (§8.3, I2).
  • Little-endian: qubit q is bit q of the amplitude index (§8.2).
  • Strided pair update: changing amplitude pairs whose indices differ only in the target bit (§8.4).
  • Born rule: the probability of an outcome is its amplitude squared in size (§8.6).
  • Collapse: after a measurement, zero the inconsistent amplitudes and renormalize (§8.6).
  • Global phase: an overall factor that cannot be observed, so states are compared by fidelity (P7).
  • Fidelity: |⟨φ|ψ⟩|², the overlap of two states that ignores global phase (Glossary).
  • Pauli string: a tensor product of I, X, Y, Z over qubits, used as an observable (§8.7).
  • Partial trace: contracting away part of the system to leave a reduced density matrix (§8.8).
  • Entanglement entropy: von Neumann entropy of that reduced matrix; 1 bit for a Bell state (§8.8).
  • Gate fusion: merging adjacent gates into one matrix to save passes over the state (§3.2).
  • Kraus operators: the matrices that describe a noise channel, with ΣK†K=I (Glossary).
  • Trajectory (quantum jump): simulating noise by random pure-state runs, then averaging (§3.2).
  • Clifford / stabilizer circuit: a restricted circuit family that can be simulated in polynomial time (Glossary).
