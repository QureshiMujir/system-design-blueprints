30. Mental Models & First Principles

  • MM1 — "A phi node is a proof obligation, not a value selector." Insight: a phi's correctness depends entirely on the renaming walk resolving each incoming value from its predecessor's exit state (§15.2), not from treating it as a simple runtime "pick one of N" operation. Predicts: any implementation that tries to evaluate a phi "in place" during construction, rather than deferring resolution to the predecessor's DFS-exit moment, will miscompile diamond merges. Bug class without it: the renaming-walk miscompile named in §15.6/T6. Applied in §15, §8.
  • MM2 — "Dominance is a promise about every path, not the common path." Insight: I2's dominance invariant must hold for every control-flow path from entry to a use, not merely the paths an author tested. Predicts: any optimization that reasons "this is probably always true" instead of proving dominance via the DominatorTree will eventually miscompile an untested path. Bug class without it: the LICM trapping-load hoist (§20, FM-5). Applied in §14, §20, §7 (I2).
  • MM3 — "An analysis result is a loan, not a gift." Insight: a cached analysis is borrowed under the condition that the pass consuming it has not been told the loan is void (PreservedAnalyses); using it past that point is a use-after-invalidation bug structurally identical to a dangling reference. Predicts: any pass architecture without an explicit invalidation contract will eventually consume stale data. Bug class without it: T1/FM-3, the single most common production-optimizer bug class (P3). Applied in §16, §7 (I9).
  • MM4 — "SSA trades write-locality for read-locality." Insight: a non-SSA variable is cheap to write (redefine in place) but expensive to reason about (which definition reaches this use?); SSA inverts this — each value has exactly one, statically-known definition, making every optimization's soundness argument local to the def-use edge rather than global to the whole function. Predicts: any pass that tries to "help" by mutating a value in place post-construction (rather than defining a new ValueId) breaks I1 and every analysis built on it. Bug class without it: I1 violations, the foundational invariant every other one is built atop. Applied in §8, §15, §7 (I1).
  • MM5 — "The verifier bounds structure; the interpreter bounds meaning." Insight: no structural checker, however exhaustive, can prove semantic equivalence — I1–I14 are necessary but not sufficient for correctness (§8's failure-path example makes this concrete). Predicts: any correctness argument resting solely on "the verifier passed" is incomplete; a differential oracle is structurally required, not optional polish. Bug class without it: every semantic-only miscompile in §22 (T2, T4, T6, T7, T8). Applied in §8, §26, P10.
  • MM6 — "Congruence is an equivalence relation until interference proves otherwise." Insight: out-of-SSA destruction starts by assuming every phi-connected value could share one location, then subtracts the pairs that are simultaneously live — the interference check is a refinement, not the primary construction. Predicts: an implementation that tries to build interference-freedom "up front" per value rather than per congruence-class-then- split will over- or under-count copies relative to the §4 1.15× bound. Bug class without it: the swap and lost-copy problems (§21, T7/T8). Applied in §21.
  • MM7 — "A fixed pipeline is a promise you can audit; a DSL is a promise you must trust." Insight: P7's locked-sequence design trades runtime flexibility for the specific property that "what ran" is fully determined by one enum value, never a parsed string that could silently differ between two invocations. Predicts: any system exposing a stringly-typed pipeline configuration will eventually need a separate "what actually ran" audit mechanism bolted on after the fact (LLVM's own experience, §5). Applied in §16, §9 (ADR-10).
  • MM8 — "Compile-time budget is a correctness-adjacent constraint, not a nice-to-have." Insight: in a JIT-embedding context, a compile-time regression is observably indistinguishable from a correctness bug to the end user (the interpreter fallback stalls visibly) — treating §4's budgets as advisory rather than gated is a category error about what "correct" means for this system. Predicts: any pass added without a companion M-target (§28) will eventually regress compile time silently until a user-visible stall is reported as a "bug." Applied in §4, §28, P13.

Glossary (§36) · 49 terms · site-wide glossary

ADCE
: Aggressive Dead Code Elimination — backward-liveness-marking DCE variant (§19).
ADR
: Architecture Decision Record — a locked, rejected-alternatives-documented choice (§9).
Alias analysis
: the query interface determining whether two memory operations may reference the same address (§9 ADR-14).
AnalysisManager
: the cache + invalidation-graph system mediating every pass's analysis requests (§16).
Back edge
: a CFG edge whose target dominates its source; the defining condition of a natural loop (I14).
Congruence class
: a set of SSA values that may share one physical location post-SSA- destruction (§21).
CFG
: Control-Flow Graph — the block-and-edge structure a Function is built from (§8).
Copy propagation
: eliminating a trivial phi or copy instruction by rewriting its uses directly to its source value (§18).
Critical edge
: a CFG edge from a multi-successor block to a multi-predecessor block, requiring splitting before certain transformations (§21).
CHK
: Cooper-Harvey-Kennedy — the iterative dominance algorithm used as this project's primary implementation (§14, ADR-32).
DCE
: Dead Code Elimination — worklist-based removal of unused, side-effect-free instructions (§19).
Dominance
: block a dominates block b if every path from entry to b passes through a (I2).
Dominance frontier
: the set of blocks where a block's strict dominance "ends" — the precise set where phi placement is required (§8, §15).
DominatorTree
: the analysis structure recording each block's immediate dominator (§11).
GCM
: Global Code Motion — Click's scheduling discipline plus physical dead-block removal (§19).
GVN
: Global Value Numbering — hash-based congruence detection eliminating redundant computations (§18).
Iterated dominance frontier (DF+)
: the fixpoint closure of the dominance-frontier operator, the exact set where phi placement is required for pruned SSA (§8, §15).
I1…I14
: this document's numbered System Invariants, the correctness contract every pass must uphold (§7).
IrBuilder
: the cursor-style API used to construct a Module (§11, §13).
Lengauer-Tarjan
: the O(E α(E,N)) dominance algorithm used as this project's cross-check implementation (§14, ADR-32).
LICM
: Loop-Invariant Code Motion — hoisting safe, invariant instructions out of a loop body (§20).
LoopInfo
: the analysis structure recording a function's natural-loop nest (§20).
Lost-copy problem
: the SSA-destruction bug where an interfering congruence-class member is silently dropped instead of copied (§21).
M1…M12
: this document's numbered Performance Engineering targets, each CI-gated (§28).
MM1…MM8
: this document's numbered Mental Models, the compressed expert insights of §30.
Natural loop
: the set of blocks reachable from a back edge's source without passing through its target, per Tarjan's algorithm (§20, ADR-17).
Opcode
: the tagged-union instruction operation kind (Add, Phi, Load, …) defined in ssa-ir (§11).
P1…P14
: this document's numbered Design Principles (§6).
Phi node
: an SSA instruction selecting a value based on the control-flow predecessor that was taken (§8, P2).
PipelineReport
: the structured per-pass timing/memory-delta record emitted by a pipeline run (§11, ADR-28).
PreservedAnalyses
: the set of analysis types a pass declares it has not invalidated (§11, I9).
Pruned SSA
: SSA form in which phi nodes are inserted only where the variable is actually live, not at every dominance-frontier block regardless of liveness (I5, P6).
RPO
: Reverse Postorder — the DFS-derived block ordering that gives CHK its fast-in- practice convergence (§14).
SCCP
: Sparse Conditional Constant Propagation — Wegman-Zadeck's reachability-coupled constant-propagation algorithm (§17).
Sea-of-nodes
: an IR representation with no explicit basic blocks, control expressed as data dependence, used by V8 TurboFan (§31, §34).
SlotMap
: the generational-index arena collection used for every ID-keyed IR structure (§11, ADR-04).
SSA
: Static Single Assignment — the IR form in which every value has exactly one static definition (I1, §8).
SSA construction
: the phi-placement-plus-renaming process converting non-SSA IR into pruned SSA (§15).
SSA destruction (out-of-SSA)
: the phi-elimination process producing virtual-register-form IR for backend handoff (§21).
Swap problem
: the SSA-destruction bug where naive simultaneous-assignment lowering overwrites one of two values being exchanged via parallel phis (§21).
TBAA
: Type-Based Alias Analysis — a lightweight alias-analysis technique using static type information (§9 ADR-14).
Terminator
: the mandatory, unique, last instruction in a basic block controlling successor selection (I6).
Translation validation
: proving (here, via a bounded smoke check) that a specific transformation's output is semantically equivalent to its input (§21, §2).
Trivial phi
: a phi whose every incoming value already resolves to the same value, eligible for elimination by copy propagation (§18).
Use-def graph
: the bipartite graph of Instructions and the Values they read/define, queried directly by every optimization pass (§8).
ValueId
: the u32-indexed handle identifying an SSA value within a Function (§11, §4).
Verifier
: the linear-time structural/dominance/type invariant checker gating every pipeline stage (§7, ADR-01 rationale in §1).
Volatile
: the flag marking a memory operation as externally-observable, exempting it from merging/reordering/elimination (I8).
Worklist
: an explicit queue-based algorithm-driving structure used by DCE, SCCP, and liveness computation to avoid re-processing converged state (§17, §19).
