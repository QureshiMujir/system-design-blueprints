4. System Constraints

Binding non-functional contract. Prime directive: a malformed or malicious input file MUST NEVER panic, hang, or OOM bndl. Every parse/resolve/transform path returns Result or recovers (Invalid token / ParseError); no unwrap/expect/panic!/unreachable! on the input-driven hot path (bndl-lexer, bndl-parser, bndl-resolver, bndl-graph, bndl-transform). Unbounded recursion → iterative or depth-capped. All limits below are caps, not assertions: hitting one is a typed error, never a crash.

Modules are immutable + Send+Sync once built → shared by & across the thread pool, zero clone. Arena (bump) for parse means allocation is pointer-bump; whole-AST drop is O(1) region free.

4.3 Determinism

Identical (inputs, options, bndl version) → byte-identical output chunks + manifest + maps, across runs, machines, OSes, and core counts. Enforced by:

  • Stable module ordering: by resolved absolute path, not fs-enumeration / thread-completion order.
  • Stable identifier-rename order in Renamer: scope-tree pre-order, deterministic short-name sequence.
  • Stable chunk hashing: BLAKE3 of final chunk content; cross-chunk hash references resolved via a fixed-point pass (hash → rewrite import URLs → re-hash until stable, cap 8 iterations → else NonConvergentHash error).
  • No wall-clock, no PID, no RNG, no HashMap iteration order in output paths (use sorted keys / IndexMap).
  • Parallelism affects only speed, never bytes: results merged in deterministic order regardless of completion order.

Determinism is required for bndl-cache correctness and long-term CDN caching (content-hashed filenames).

4.4 Concurrency Assumptions

  • Thread pool sized cores−1; orchestrator coordinates, workers do resolve/parse/transform per module.
  • Parallel unit = one module; bndl-graph load is a fan-out of independent parse+scan jobs joined at edge-wiring.
  • Shared state is read-mostly: Resolver caches behind concurrent maps; Cache behind a sharded lock; Atom interner lock-free read / locked insert.
  • No data races by construction: immutable Module, no &mut aliasing across threads (Rust borrow checker is the enforcement).
  • bndl-server HMR + watcher run off the request path; invalidation is message-passed, not shared-mutex on the graph.

4.5 Input Assumptions, Hard Caps, and Rationale

Defaults; some overridable via config but ALL have a hard ceiling (DoS + memory bound). Exceeding → typed error, clean abort, no panic.

Parser recursion is explicitly depth-counted (not relying on native stack); deep input yields NestingTooDeep, never SIGSEGV. Lexer always terminates: every code path advances the byte cursor or emits Eof/Invalid (no zero-progress loop).

4.6 Cache & Incremental Targets

  • Warm incremental rebuild cache hit rate > 95% (unchanged modules served from bndl-cache by CacheKey = BLAKE3(content + options)).
  • Invalidation is content-driven + transitive: a changed module invalidates its Artifacts and dependents whose resolved graph shape changed; pure leaf edits invalidate only that module + downstream chunks.
  • On-disk store survives process restart; cold start with populated store ≈ warm (re-validate by hash, skip recompute).

4.7 I/O, FD, and Network Budget

  • No network at runtime. Resolution is registry-less: filesystem only (no installs/fetches; package install is #135). External/builtin specifiers are marked external, not fetched.
  • Dev server: localhost HTTP + WebSocket only (HMR). No outbound connections.
  • Watcher FD budget: native recursive fs-watch where available (FSEvents/inotify/ReadDirectoryChangesW); fall back to a polling watcher above an open-handle cap. Hard cap ≤ 8,192 watched paths/handles → beyond it, watch parent dirs coarsely (WatchBudgetExceeded downgrade, not abort).
  • File reads go through Resolver/Cache fs layer (stat+realpath cached) → bound syscall count; symlink realpath cached to avoid repeat lstat walks.

4.8 Robustness Invariants (cross-cutting)

  • No panic on any input — fuzzed (lex/parse/roundtrip, Phase 13); fuzz target = "process N MB of arbitrary bytes, assert no panic/hang/leak."
  • Bounded time + space for any single input ≤ caps above; no input drives super-linear blowup without hitting a cap first.
  • Graceful degradation: unparseable module → ParseError collected, module marked errored, build reports + continues (or fails fast per config) — never takes down the process.
  • Type stripping is not type checking (#42): malformed TS types are discarded/recovered, never block bundling of valid runtime code.
