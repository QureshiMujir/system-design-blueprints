3. Architectural Overview

bndl is a 12-crate Cargo workspace. Data flows one direction on the build path (entries → resolve+load → graph → shake → chunk → emit); the dev path (bndl-server) re-enters the same pipeline on-demand per request and per fs event. The content-addressed cache (bndl-cache) wraps the three expensive memoizable stages (parse, transform, codegen). Three boundaries — trust, concurrency, persistence — partition the system and are referenced by every later phase.

3.3 bndl-lexer

ECMAScript/TS/JSX tokenizer. In: &str source + SourceId. Out: Token stream (TokenKind, Span, had_newline_before). Owns the code-point classifier (ID_Start/ID_Continue, whitespace, line terminators), template-literal state stack, regex-vs-divide disambiguation (resolved with parser-fed context flag), numeric/bigint literal scanning, JSX text/ident modes. Invariant: total — every byte sequence yields a finite token run ending in Eof; lexical errors surface as Invalid tokens, never panics. had_newline_before is the sole ASI signal the parser consumes. Referenced by Phase 1 (impl), Phase 2 (parser pulls tokens), Phase 3 (JSX/TS token shapes).

3.4 bndl-parser

Recursive-descent (statements/decls) + Pratt (expressions, binding powers) parser. In: token stream via parse_program(src, id, syntax) -> (Program, Vec<ParseError>). Out: ESTree-shaped Program with Span+NodeId on every node, plus a Vec<ParseError> (ParseErrorKind). Syntax{typescript, jsx} gates grammar extensions. Invariant: always returns a Program (error-recovery panic mode re-syncs at statement boundaries) so downstream stages and the IDE/dev server get a best -effort tree; spans are byte-accurate (source-map + diagnostics correctness). Reads bndl-lexer + bndl-ast. Referenced by Phase 2 (core grammar), Phase 3 (TS/JSX), and the differential parser-conformance gate (Phase 13, Test262).

3.5 bndl-ast

The ESTree-shaped AST + Visit/VisitMut visitor traits. In/Out: pure data — Program, ModuleItem, Stmt, Expr, Pat, Ident{sym:Atom}, NodeId, Span; no parsing logic. Identifiers carry interned Atoms (cheap eq/hash, dedup). Holds scope-id placeholders filled later by bndl-codegen's ScopeTree. Invariant: the single shared node vocabulary — lexer/parser produce it, transform/treeshake/codegen consume and rewrite it; NodeId is stable across passes for source-map provenance and cache keying. VisitMut is the only sanctioned in-place rewrite path (Phase 6 driver builds on it).

3.6 bndl-resolver

Module resolution implementing both Node algorithms: ESM (PACKAGE_RESOLVE, PACKAGE_EXPORTS_RESOLVE with conditional + pattern matching, ESM_FILE_FORMAT) and CJS (LOAD_AS_FILE/LOAD_AS_DIRECTORY/LOAD_NODE_MODULES). In: Specifier (Relative/Absolute/Bare{pkg,sub}) + importer path + ResolveOptions. Out: ResolveResult{path, kind, side_effects, from_node_modules} or ResolveError. Matches Conditions against exports/imports; honors main/module/browser main-fields; resolves tsconfig paths/baseUrl before node_modules; does extension + index probing; canonicalizes via symlink realpath. Caches fs stats, parsed package.json, and realpath. Invariant: resolution is a deterministic pure function of (specifier, importer, options, fs snapshot) — same inputs → same ResolveResult. Feeds absolute paths to bndl-graph; Phase 4 owns it.

3.7 bndl-graph

Builds the module graph. In: entry paths + the resolver. Out: ModuleGraph (Vec<Module>, entries, edges, recorded cycles). Each Module holds ast, ImportRecords (Static/Dynamic/Require/ExportStar), ExportRecords (local symbol or reexport:(ModuleId,Atom)), Symbols, and has_side_effects. Classifies ModuleKind (Esm/Cjs/Json/Css/Asset/Builtin/External); scans ESM import/export + CJS require/module.exports; detects cycles; models live bindings (an import is a read-only view of the exported binding — identity preserved), re-exports, and export-star expansion. Loads modules in parallel on the thread pool. Invariant: every resolved edge points to a real ModuleId; Module is immutable + Send+Sync after construction. Reads bndl-parser + bndl-resolver. Consumed by treeshake (Phase 7), chunk (Phase 9), codegen, and the dev server.

3.8 bndl-transform

AST rewrite pipeline. In: &mut Program + TransformContext{target, defines, syntax, jsx_runtime}. Out: rewritten Program (same NodeId lineage for maps). Passes, ordered: TypeStrip (erase TS annotations/interfaces/enums/decorators — no type checking, that is #42) → JsxTransform (Classic createElement or Automatic jsx-runtime) → Lowering (optional chaining, nullish, class fields, logical-assignment, async per Target) → Define (constant replacement from DefineMap, enabling later DCE). Driven by a VisitMut driver. Invariant: transforms are semantics-preserving and target-correct; ordering is fixed (e.g. type-strip before JSX before lowering). Implements TransformPass. Reads bndl-ast; Phase 6 owns it; the dev server runs it per-module on-demand.

3.9 bndl-treeshake

Symbol-level reachability. In: &mut ModuleGraph + entry ModuleIds via shake(graph, entries) -> ReachableSet. Out: the set of live (module, symbol), with dead statements/exports/imports eliminated and re-exports pruned. Builds a SymbolGraph (per-symbol dependency edges + side-effect markers); worklist reachability from entry exports; side-effect analysis honoring sideEffects:false and /*#__PURE__*/ (SideEffect::Pure/Impure/Unknown). Invariant — soundness: never remove code with observable side effects unless proven pure; top-level effectful statements pin their module; over-removal is a correctness bug, not an optimization. Reads bndl-graph; output drives bndl-chunk. Phase 7.

3.10 bndl-chunk

Code splitting via esbuild/Rollup module groups. In: split(graph, reachable, fmt) -> ChunkGraph. Out: ChunkGraph (Vec<Chunk>) + manifest. A module's chunk is fixed by the set of entry points (static + dynamic) that can reach it: single-entry → that entry's chunk; multi-entry → a shared chunk. import() creates a chunk boundary (is_dynamic). Wires cross-chunk imports (Chunk.imports); names chunks deterministically; content-hashes (Chunk.hash) with a fixed-point pass so cross-chunk hash references converge. Invariant — determinism: identical (graph, reachable, options) → byte-identical chunk set, stable order + names + hashes (long-term CDN caching). Reads bndl-graph + bndl-treeshake. Phase 9; consumed per-chunk by codegen.

3.11 bndl-codegen

Emits final code; owns four subsystems. In: emit_chunk(chunk, graph, fmt, opts) -> OutputChunk{file_name, code, map}. (1) ScopeTree + Renamer — scope analysis binds every reference; the cross-module Renamer produces collision-free names (also short names for minify). (2) Scope hoisting / module concatenation — hoist ESM modules into one shared scope (Rollup/esbuild-style); wrapped lazy-init fallback (a runtime function with first-call memoization) for CJS, cyclic, or eval-bearing modules. (3) Module runtime + OutputFormat wrappers — inject __require/__esm/ __commonJS/__toESM/__export interop helpers; wrap as Esm/Cjs/Iife; rewrite imports/exports incl. CJS↔ESM interop (CJS = value snapshot at require-time, ESM = live binding). (4) Minifier — scope-aware mangle + DCE + constant fold + dead-branch removal (Phase 11). Source maps composed across all stages via the #265 codec (never hand-rolls VLQ). Invariant: output is semantics-preserving and deterministic; live- binding identity + mutation-visibility survive renaming/hoisting. Reads bndl-ast + bndl-chunk. Phases 8, 10, 11.

3.12 bndl-cache

Content-addressed incremental store. In: content + options → CacheKey([u8;32]) = BLAKE3(content ‖ options). Out: memoized Artifact (Parsed/Transformed/ Emitted). In-memory layer over a persistent on-disk CAS; change-driven invalidation (a changed source → new key → miss → recompute; unchanged deps hit). Invariant: an artifact is a pure function of its key → cache hits are observationally identical to recompute; eviction is always safe. Wraps the three expensive stages (parse/transform/ codegen) and underpins incremental rebuild + the dev server (Phase 13).

3.13 bndl-server

Vite-style ESM dev server + HMR. In: entries + config; HTTP/WS clients; fs events via Watcher. Out: per-request transformed ESM modules; WS HMR updates. Owns DevServer (http + ws + transform pipeline + cache + watcher), HmrEngine (boundary computation + accepted-modules set), HmrBoundary{module, accepts}, ModuleRunner. Serves modules on-demand (ESM-native, no bundling in dev) with dependency pre-bundling of node_modules; on change, computes the HMR boundary, propagates up the graph to the nearest accepting module, and falls back to full reload when no boundary accepts. Invariant: dev transform output is byte-consistent with the build path's per-module transform (same bndl-transform + cache). Reads bndl-graph + bndl-transform + bndl-codegen + bndl-cache. Phase 12.

3.14 bndl-cli

The bndl binary + plugin host. In: run(args: CliArgs) -> ExitCode — subcommands build, serve, transform, analyze, graph. Loads config; hosts the Plugin trait (resolve/load/transform/render_chunk hooks) — plugins extend each pipeline stage. Out: orchestration of the whole pipeline; written OutputChunks + manifest (build), the dev server (serve), a single transformed file (transform), graph/size reports (analyze/graph). Invariant: the orchestration layer — the only crate depending on all others; the plugin host is the single extension surface and runs inside the trust boundary (plugin code is treated as untrusted config). Phase 0 scaffolds it; every later phase wires its stage in.

3.15 Determinism Contract

A cross-cutting invariant verified in Phase 13: identical inputs + options ⇒ byte-identical output, independent of thread schedule. Enforced by (1) stable module ordering (by resolution order, not completion order), (2) stable identifier-rename order (Renamer keyed on NodeId/scope position), (3) stable chunk hashing with a fixed-point pass over cross-chunk hash references, (4) deterministic chunk naming. Required for cache correctness and long-term CDN caching; any nondeterminism is a release-blocking bug.

8. Domain Model — JS/TS Modules, Grammar, and the Module Graph

The domain is four layered models, each a lowering of the prior: bytes → tokens → AST → module graph → reachable/chunk model. Every layer is span-tagged (Span{start,end} byte offsets into one SourceId) so positions compose into the final source map via the #265 codec. Identifiers are interned Atom. All Module records are immutable + Send+Sync once built, enabling fearless parallel processing.

8.1 Tokenization model (bndl-lexer)

The lexer maps ECMAScript code points → TokenKind. It never panics: any unclassifiable sequence yields TokenKind::Invalid (parser recovers). had_newline_before is set when ≥1 LineTerminator precedes a token → feeds ASI.

Code-point classes (per ECMAScript lexical grammar §12.1–12.9):

Class Members Produces
WhiteSpace TAB, VT, FF, SP, NBSP, ZWNBSP (U+FEFF), Zs skipped
LineTerminator LF, CR, LS (U+2028), PS (U+2029) sets had_newline_before
IdentStart $ _ UnicodeIDStart, \u-escape Ident / Keyword
IdentPart IdentStart + UnicodeIDContinue + ZWNJ/ZWJ continues ident
DecimalDigit / 0x/0o/0b numeric Num(f64) / BigInt (trailing n)
" ' string body, escapes, line-continuation Str
` template — stateful (see below) NoSubTemplate/TemplateHead/Middle/Tail
/ divide or regex (context-dependent) Punct(Slash..) / Regex
# private name (#x) PrivateName
punctuators per §12.8 maximal-munch Punct(Punct)

Token kinds (TokenKind): Ident, PrivateName, Keyword(Keyword), Num(f64), BigInt, Str, NoSubTemplate, TemplateHead, TemplateMiddle, TemplateTail, Regex, Punct(Punct), JsxText, JsxIdent, Eof, Invalid.

Keywords are lexed as Ident then reclassified Keyword(_); contextual keywords (async, let, of, as, from, get, set, yield, await, TS type/interface/enum/declare) stay Ident and are resolved by the parser via position (avoids mode-dependent lexing).

Template-literal state machine — a template-stack of brace depths tracks nested ${...}:

            `...`                 `...${              }...${            }...`
   Start ──NoSubTemplate──▶ Done   ──TemplateHead──▶ InExpr ──TemplateMiddle──▶ InExpr ──TemplateTail──▶ Done
                                        │  push depth        ▲ on `}` at depth==tpl-brace re-enter tpl
                                        ▼                    │
                                   (normal token stream; `{`/`}` adjust depth)

A } only closes a template substitution when brace-depth returns to the template's recorded depth; otherwise it is Punct(RBrace). Unterminated ` → Invalid + ParseErrorKind::UnterminatedTemplate.

Regex-vs-divide disambiguation — / is ambiguous: regex literal vs division. The lexer holds a regex-context flag fed by the parser's expected-token state. Rule: a / begins a Regex when an expression is not yet in operand position (preceded by (, ,, =, :, [, !, &, |, ?, {, ;, return, typeof, keyword operators, or line start). It is Slash when preceded by an Ident, ), ], Num, Str, template tail, or this/literal (operand just closed). Invalid regex body → Invalid + ParseErrorKind::InvalidRegex.

ASI inputs — the lexer supplies had_newline_before; the parser inserts a virtual ; per the three ASI rules: (1) offending token on a new line; (2) } or EOF reached; (3) restricted productions (return/throw/break/continue/yield/post-++/--/arrow) where a LineTerminator forbids continuation.

8.2 Load-bearing grammar (EBNF)

Recursive descent for statements/declarations + Pratt for expressions. Syntax{typescript,jsx} gates TS/JSX productions. Representative subset (terminals in ''):

Program        ::= ( ModuleItem )* EOF ;
ModuleItem     ::= ImportDeclaration | ExportDeclaration | Statement ;

ImportDeclaration
  ::= 'import' ImportClause 'from' ModuleSpecifier ';'
    | 'import' ModuleSpecifier ';'                          (* side-effect import *)
    | 'import' 'type' ImportClause 'from' ModuleSpecifier ';'   (* TS, erased *) ;
ImportClause   ::= DefaultBinding ( ',' NameSpaceImport | ',' NamedImports )?
                 | NameSpaceImport | NamedImports ;
NameSpaceImport::= '*' 'as' Ident ;
NamedImports   ::= '{' ( ImportSpec ( ',' ImportSpec )* ','? )? '}' ;
ImportSpec     ::= ( Ident | String ) ( 'as' Ident )? ;
ModuleSpecifier::= String ;

ExportDeclaration
  ::= 'export' '*' ( 'as' Ident )? 'from' ModuleSpecifier ';'   (* export-star / export-as-namespace *)
    | 'export' NamedExports ( 'from' ModuleSpecifier )? ';'
    | 'export' 'default' ( AssignmentExpression | FuncDecl | ClassDecl ) ';'
    | 'export' Declaration ;
NamedExports   ::= '{' ( ExportSpec ( ',' ExportSpec )* ','? )? '}' ;
ExportSpec     ::= ( Ident | String ) ( 'as' ( Ident | String ) )? ;

ImportExpression ::= 'import' '(' AssignmentExpression ( ',' AssignmentExpression )? ')'  (* dynamic *)
                   | 'import' '.' 'meta' ;
ClassDeclaration ::= 'abstract'? 'class' Ident TypeParams? Heredity? '{' ClassElement* '}' ;  (* 'abstract','implements',TypeParams: TS, erased *)

(* Pratt expression core — driven by binding powers, not nested BNF *)
Expression       ::= AssignmentExpression ( ',' AssignmentExpression )* ;
AssignmentExpression ::= ArrowFunction | YieldExpression
                       | ConditionalExpression
                       | LeftHandSide AssignmentOperator AssignmentExpression ;
PrattExpr(rbp)   ::= NUD ( while lbp(peek) > rbp : LED )* ;   (* see binding-power table 8.2.1 *)

8.4 Module-resolution decision model (bndl-resolver)

Specifier is classified first: Relative (./, ../), Absolute (/, drive), or Bare{pkg,sub}. ResolveResult{path, kind, side_effects, from_node_modules}. tsconfig paths/baseUrl run before node_modules.

resolve(spec, importer):
  ┌─ tsConfig.paths match? ──yes──▶ rewrite to candidates ──▶ probe ──hit─▶ ResolveResult
  │                          no
  ▼
  Relative|Absolute? ──yes──▶ join(importer_dir, spec) ──▶ LOAD_AS_FILE ─miss─▶ LOAD_AS_DIRECTORY ─miss─▶ ResolveError::NotFound
  │ no (Bare)
  ▼
  ESM importer (type:module / .mjs)?
     ├─ yes ▶ PACKAGE_RESOLVE → PACKAGE_EXPORTS_RESOLVE (if "exports")  else legacy main/module
     └─ no  ▶ LOAD_NODE_MODULES (CJS)

CJS LOAD_NODE_MODULES — walk ancestor node_modules/:

Step Probe path Hit → Miss →
1 <ancestor>/node_modules/<pkg> (exact) realpath → ResolveResult next probe
2 <ancestor>/node_modules/<pkg>.{js,json,node,…extensions} realpath → ResolveResult next probe
3 <ancestor>/node_modules/<pkg>/package.json#main_fields (["browser"?,"module"?,"main"] in order) LOAD_AS_FILE(main_field_value) → ResolveResult probe index
4 <ancestor>/node_modules/<pkg>/index.{js,json,node} realpath → ResolveResult next ancestor dir
— no ancestor node_modules/ matched — ResolveError::PackageNotFound

All hits pass through realpath(symlink) → canonical path (symlink realpath cache); symlink cycles detected and capped.

ESM PACKAGE_EXPORTS_RESOLVE — condition + pattern matching against package.json#exports:

exports == string                     → that target (only sub == ".")
exports == { ".": …, "./sub": … }     → exact key, else pattern key "./*" (capture * = sub-tail)
target == string                      → must start "./", forbid "../"/abs escapes → InvalidExports
target == { import|require|browser|node|development|production|default : … }
        → match Condition list LEFT→RIGHT in ResolveOptions.conditions (first match wins; recurse)
target == [ a, b ]                    → first that resolves
no key/condition matches              → ResolveError::NotExported
"imports" (#-prefixed)                → same algorithm, internal specifiers

Condition ordering (ResolveOptions.conditions, build default): ["import","module","browser"?,"node"?,"production"|"development","default"]. Condition::Custom(Atom) allows user keys. "browser" field/condition active when targeting browser; flips Node builtins → ModuleKind::External/polyfill.

ResolveError Trigger
NotFound relative path + no extension/index hit
PackageNotFound bare pkg absent from all ancestor node_modules
InvalidExports exports target escapes package root / not ./-prefixed
NotExported subpath not in exports map (encapsulation)
BadTsPaths tsconfig paths pattern malformed / no baseUrl

8.5 Module-graph + live-binding model (bndl-graph)

ModuleGraph{modules: Vec<Module>, entries, edges, cycles}. Each Module{id: ModuleId, path, kind: ModuleKind, ast, imports, exports, symbols, has_side_effects}. ModuleKind ∈ {Esm, Cjs, Json, Css, Asset, Builtin, External}.

Records:

ImportRecord { specifier: Atom, resolved: Option<ModuleId>, kind: ImportKind }   // Static|Dynamic|Require|ExportStar
ExportRecord { name: Atom, local: Option<SymbolId>, reexport: Option<(ModuleId, Atom)> }
Symbol       { name: Atom, kind: SymbolKind, local: bool }                       // SymbolId interned per module
Binding      // (scope-level link from a reference to its defining Symbol)

Live bindings — an ESM import is a live, read-only view of the exporter's binding, not a value copy. Invariant: rename/tree-shake/concatenate must preserve (a) binding identity (all importers + exporter alias the same storage) and (b) mutation visibility (an exporter reassigning export let x is observed by importers). After scope hoisting (Phase 8) the binding becomes one shared variable; in wrapped mode it is a getter on the namespace object. Default export = synthetic export named default.

export-star flattening — export * from 'm' (ExportDecl::All{alias:None}) re-exports all of m's named exports except default and any name explicitly bound by the importer (local exports + earlier stars shadow). Resolved by a fixed-point walk across transitive stars; an ambiguous name (two stars export same name) is silently excluded (per spec), not an error, unless directly imported → then BadImport/missing-export. export * as ns (alias:Some) instead binds a single namespace symbol.

Cycle handling — Tarjan SCC over static-import edges records cycles. ESM cycles are legal: bindings are hoisted/TDZ-checked; the graph keeps them and Phase-8 forces the wrapped lazy-init fallback for any module in a cycle that needs ordering. CJS require cycle → partial module.exports snapshot returned (the in-progress object), matching Node; not an error.

CJS↔ESM interop —

Direction Bridge Helper (Phase 10)
ESM imports CJS CJS module.exports value snapshot wrapped as ESM namespace; default = whole exports __toESM
CJS requires ESM ESM namespace materialized eagerly into a value object __commonJS wrapper + __esm
named import from CJS best-effort static keys; unknown → runtime getter __export

ImportKind::Require marks CJS edges (always wrapped, never concatenated). Dynamic marks import() edges → chunk boundary (Phase 9).

8.6 Worked example — 3 modules: tokens → AST → graph → reachable → chunks → ESM

Project: entry.ts (entry) imports local util.ts + bare pkg lib (conditional exports). Build target ESM, tree-shaking on.

entry.ts

// entry.ts — module surface (import declarations + reference notes; not runnable)
import { used } from "./util";   // referenced via call site used()
import { hello } from "lib";     // referenced as a value
// entry body references: used(), hello  → both symbols reachable from entry

util.ts

// util.ts — exported declarations (arrow bodies elided, shown as type)
export const used: () => number;   // body returns 41 + 1; referenced → KEPT
export const dead: () => string;   // body returns "tree-shaken"; unreferenced + Pure + sideEffects:false → ELIMINATED

lib/package.json: { "exports": { ".": { "import": "./esm/index.js", "require": "./cjs/index.js" } }, "sideEffects": false } lib/esm/index.js: export const hello = "hi";

(1) Tokens (entry.ts, abbreviated): Keyword(import) Punct({) Ident(used) Punct(}) Ident(from)* Str("./util") Punct(;) … (*from lexed as Ident, parser-reclassified). () => 41 + 1 in util.ts: Punct(() Punct()) Punct(=>) Num(41) Punct(+) Num(1).

(2) AST — entry: [Import(ImportDecl{spec:[used], source:"./util"}), Import(ImportDecl{spec:[hello], source:"lib"}), Stmt::Expr(Call(console.log, [Call(used), Ident(hello)]))]. util: two ExportDecl::Decl(Var(const …)), each a Expr::Arrow. TS : number / (): number erased by TypeStrip.
