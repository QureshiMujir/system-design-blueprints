Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why can't the lexer decide regex-vs-divide unilaterally, and what breaks if you assume / always starts a regex? Resolving: §13 (Phase 1 lexer), §15 (Phase 2 parser). Synthesis: the lexer/parser coupling (§13) + the spec's goal-symbol mechanism (S1 §12.9) + what a DFA-based lexer cannot express (ADR-03).
  2. If you add a new ES2024 syntax node to bndl-ast, list every file across every crate that must change, and why each change is load-bearing. Resolving: §14 (AST), §15 (parser), §18 (transform), §22 (codegen emit). Synthesis: the crate DAG (§10), the Visit/VisitMut exhaustive-match invariant (ADR-08), and the printer's precedence table (§22).
  3. A user reports that editing a file in dev mode sometimes triggers a full reload instead of an HMR update. Walk through compute_update and name every condition that causes FullReload. Resolving: §24 (Phase 12 HMR), §17 (module graph importers). Synthesis: HmrBoundary propagation logic (§24), the importer-graph walk (§17), and the "reached root without boundary" condition.
  4. Explain why sideEffects:false in package.json does NOT mean "this module has no side effects" in general — it means "you are allowed to drop this module if none of its exports are used." Give a concrete example where the distinction matters. Resolving: §19 (Phase 7 tree-shaking), §6.4 (Design Principle). Synthesis: SideEffect::Pure vs SideEffect::Unknown (§19), the polyfill-as-side-effect case, and the package-author's liability.
  5. Walk through the BLAKE3 cache key for a TypeScript file. If a developer changes only a comment (no AST change), does the cache miss? Why or why not? Resolving: §25 (Phase 13 cache), §14 (bndl-ast), §18 (transform). Synthesis: CacheKey = BLAKE3(content + CanonOpts) (§25) + the fact that comment-stripping happens in the lexer before the AST is produced → comment change = content change = cache miss, even if the resulting AST is identical.
  6. Why does the minifier run after the Renamer, not before? What correctness property would be violated if you mangled names before scope hoisting? Resolving: §20 (Phase 8 scope/hoist), §23 (Phase 11 minify), §22 (Phase 8 rename). Synthesis: the BindingMap produced by hoisting (§20) is keyed on pre-mangle names; mangling first would produce a BindingMap that maps wrong names and break cross-module live-binding references.
  7. Describe how a cross-chunk ESM import becomes a runtime import {...} statement in the output. Trace the data from ModuleGraph → ChunkGraph → emit_chunk → OutputChunk. Resolving: §17 (graph), §21 (chunking/wire), §22 (emit/formats). Synthesis: wire() records cross-chunk symbol refs (§21), formats.rs rewrites them as top-level import {...} from './shared.js' (§22), and manifest.json maps the chunk filename (§21).
  8. If two ESM modules form a cycle (A imports B, B imports A), which one gets WrapKind::EsmWrapped and why does the first-to-execute module see TDZ-safe bindings? Resolving: §20 (Phase 8 eligibility), §22 (codegen wrap), §17 (cycles/SCC). Synthesis: Tarjan SCC marks both in_cycle (§17); eligibility assigns EsmWrapped (§20); __esm lazy-init ensures the body runs only after both modules' exports are assigned (§22).
  9. The Scalability Analysis says the serial fraction is ~15–25%. Identify the three most expensive serial operations and explain why each cannot be parallelized. Resolving: Scalability Analysis, §17 (graph-link), §19 (tree-shake), §21 (hash fixpoint). Synthesis: (a) symbol binding coordination (single ModuleId interner), (b) global reachability worklist (shared BitSet), (c) cross-chunk hash fixed-point (convergence requires all chunks' final content).
  10. A new bundler contributor wants to add support for import.meta.glob (like Vite). Which ADRs constrain the design, and what is the minimum-risk extension path through the Plugin trait? Resolving: §9 (ADRs), §12 (Phase 0 plugin), §16 (resolver). Synthesis: ADR-22 (Plugin resolve/load/transform hooks), ADR-03 (never extend the lexer for new syntax), ADR-09 (resolver must handle the virtual module), and the "no code in Phase 0" constraint.
  11. Explain the fixed-point hash algorithm. Why is it bounded? What is the maximum number of iterations and how does the maxChunks cap interact with it? Resolving: §21 (Phase 9 hash fixpoint), Scalability Analysis. Synthesis: each iteration resolves one level of hash-reference depth; DAG depth ≤ #chunks (acyclic); ESM chunk graph is acyclic; maxChunks=1000 bounds both chunk count and iteration count.
  12. A property of bndl is that build(x) == build(x) byte-for-byte. List every component that could break this if it behaved non-deterministically, citing the mitigation for each. Resolving: §6.3 (Design Principle), §21 (chunk hash), §20 (rename order), §9 ADR-14. Synthesis: HashMap iteration (sorted), thread completion order (merge by sorted ModuleId), fs readdir order (sorted), clock/RNG in output (forbidden), CanonOpts map-sort (§25).
  13. Explain why export * from "x" must be resolved to concrete named exports at graph-build time, not at emit time. What correctness failure occurs if you defer it? Resolving: §17 (Phase 5 export-star fixpoint), §19 (tree-shaking), §22 (emit). Synthesis: tree-shaking must know which symbols a module re-exports to determine which are live; deferring to emit means the shaker prunes re-exported symbols that are actually live → over-removal correctness bug.
  14. A user runs bndl build twice on an unchanged project and gets different output hashes. Describe the diagnostic process, naming which crate and which data structure is the likely culprit. Resolving: §25 (Phase 13 cache/determinism), §21 (chunk hash), §6.3. Synthesis: diff the per-stage output at each stage (parse → transform → emit → chunk-hash) to find the first stage where content diverges; likely culprit is HashMap in ModuleGraph::modules or SymbolGraph::edges — replace with IndexMap/sorted Vec.
  15. Explain why the differential oracle compares observable runtime behavior (executed stdout/exports) rather than comparing emitted bytes to esbuild/Rollup output. Resolving: §9 ADR-24, §25 (Phase 13 differential). Synthesis: esbuild and Rollup legitimately differ in whitespace, identifier names, helper phrasing, and interop wrapper style; byte-equality would be a false oracle. Observable behavior (stdout, exported binding values) is the actual spec; byte-diff would produce thousands of false positives.
  16. How does bndl handle a dynamic import with a non-literal specifier (e.g., import('./' + name))? What is the conservative safe choice and what optimization is sacrificed? Resolving: §17 (Phase 5 scan CJS/dynamic), §21 (Phase 9 chunking). Synthesis: non-literal dynamic import recorded as ImportKind::Dynamic with Unknown flag (§17); the module cannot be statically resolved or chunked; conservative choice is to mark it as external-safe and not attempt splitting → no lazy chunk for this call, possible runtime failure if the user loads from an unexpected path.
  17. Describe the full ASI decision tree for a\n++b. Does bndl parse it as a++; b or a; ++b? Cite the spec rule that governs it. Resolving: §13 (Phase 1 lexer ASI), §15 (Phase 2 parser ASI). Synthesis: ++/-- as postfix are restricted productions (S1 sec. 12.9.2); the rule: if LineTerminator appears before ++/--, they cannot be postfix → a is a statement, ++b is the next statement. bndl must parse it as a; ++b or signal a diagnostic.
  18. Why must Atom interning be global (not per-module) for scope hoisting to work correctly? Resolving: §14 (Phase 2 bndl-ast Atom), §20 (Phase 8 hoisting BindingMap). Synthesis: the BindingMap maps (ModuleId, Atom) → renamed Atom; if two modules have different Atom ids for the string "x", the map lookup fails after concatenation → unresolved references.
  19. A minified bundle produced by bndl --minify has a broken source map: all identifiers in the debugger show ? instead of original names. What is wrong and how do you fix it? Resolving: §23 (Phase 11 minifier), §22 (Phase 10 emit), ADR-18. Synthesis: mangle.rs records (mangled_span → original Atom) and feeds names[] to the #265 builder; if the names[] array is empty, the map segments lack the names index field → all symbols show ?. Fix: assert every renamed Span emits a names entry in the #265 codec call.
  20. Explain the "chunk explosion" problem. When does M=100 modules with N_e=30 entries produce more than 1000 chunks, and what is bndl's mitigation? Resolving: §21 (Phase 9 chunking), Scalability Analysis. Synthesis: worst case = 2^N_e distinct entry-sets → 2^30 = 10^9 chunks (impossible); practical explosion: many distinct (small) reaching-sets → many tiny chunks. Mitigation: minChunkSize=20 KB merges tiny chunks into their importer; maxChunks=1000 cap emits a warning and falls back to larger chunks.
  21. If a user's project has "sideEffects": ["./polyfill.js"] in package.json, explain exactly what happens to a bare import "./polyfill.js" in bndl-treeshake. Resolving: §19 (Phase 7 tree-shaking), §17 (Phase 5 resolve side_effects). Synthesis: ResolveResult.side_effects = Some(glob_list) → analyze_module checks the resolved path against the glob → polyfill.js matches → SideEffect::Impure → top-level stmt pinned → module kept despite zero referenced exports.
  22. Walk through what happens when the same symbol is exported by two export * from "x" chains and a consumer imports that symbol by name. Resolving: §17 (Phase 5 export-star ambiguity), §19 (Phase 7 tree-shaking). Synthesis: star.rs detects the name collision across two star-export sources and marks it ambiguous; it is excluded from the re-exporter's export table; if a consumer tries to import the ambiguous name, the resolution fails at ResolveExport → ImportRecord records an error, not a silent wrong binding.
  23. bndl targets ≥ 1 M LOC/s/core for the lexer. Describe two specific code-level choices in bndl-lexer that contribute to this target and the alternative that was rejected. Resolving: §13 (Phase 1 lexer), §9 ADR-03. Synthesis: (a) byte-at-a-time cursor over &[u8] (not char iterator, avoiding UTF-8 decode cost on ASCII-dominant JS); (b) maximal-munch punctuator trie (not regex match). Rejected: logos DFA generator (cannot express parser-fed regex_context).
  24. Explain why bndl never persists raw NodeId or Atom integer values in the on-disk cache. What would go wrong if it did? Resolving: §25 (Phase 13 cache codec), §14 (bndl-ast Atom). Synthesis: Atom indices are assigned by a global interner at parse time; the interner is not stable across process runs → the same string "foo" may get Atom(17) in run 1 and Atom(23) in run 2; a cached artifact with Atom(17) loaded in run 2 would reference the wrong string → silent identifier corruption. Fix: serialize strings, re-intern on load.
  25. What is the maximum safe number of modules before Atom interning overhead exceeds the memory benefit? Derive the crossover. Resolving: §4 (System Constraints), Scalability Analysis, §14 (Atom). Synthesis: interner overhead = one hash-table slot per unique string ≈ 40 bytes; benefit = deduplication of repeated idents; crossover = when average occurrences per string × 8 bytes (pointer) < 40 bytes → break-even at ~5 occurrences/string. In JS identifiers repeat many more times than 5× on average → interning always wins above a few thousand LOC.

Mental Models & First Principles

Expert-compressed insights. Each entry: what the model predicts, the bug class that forms when it is absent, and the resolving phase/§ where it is applied.

# Mental Model What It Predicts Bug Class Without It Resolving §
MM1 Import = live read-only view, not a value copy Mutations to an exported binding are visible at every import site after concatenation and renaming, not just before. After scope hoisting, an importer reads a stale value because the renamer copied the binding value instead of routing through the same slot. Silent "counter doesn't increment" bug in production. §22 (Phase 8) Renamer + Concatenator; §7 (Design Principle 6.5)
MM2 Over-removal is a correctness bug, not an optimization Removing a call with sideEffects:false that actually polyfills a global causes a silent runtime crash in the consumer's environment, not a build error. Treating SideEffect::Unknown as Pure and dropping the call → Object.entries undefined in the target runtime. §19 (Phase 7) TreeShaker; §6.4 Design Principle
MM3 Determinism is a contract, not a property Any source of iteration-order non-determinism (HashMap, thread-completion order, fs readdir) makes the content hash non-stable, poisoning the cache for every consumer. Two incremental rebuilds with identical inputs produce different hashes; the CDN treats both as new content → unbounded cache invalidation. §21 (Phase 9) hash fixed-point; §6.3 Design Principle; ADR-14
MM4 The chunk = the set of entry points that reach a module (not the module itself) A module shared by two entries belongs in a shared chunk; a module uniquely reached by one entry belongs in that entry's chunk. The set-key is the canonical chunk identity. Grouping by entry-ID instead of entry-SET → same module emitted in N chunks → double side-effects, size bloat, TDZ at runtime on circular shared imports. §21 (Phase 9) assign_groups; ADR-13; P2
MM5 Arena allocation = module lifetime = O(1) free An entire module's AST (lexed, parsed, transformed) lives in one bump arena. When the module is evicted from cache or discarded post-codegen, one free call releases all nodes. This makes the module trivially Send+Sync because it has no shared mutable state. Per-node Box allocation → Drop churn on large modules; Rc cycles → memory leak; non-Send nodes → cannot ship to thread pool without cloning. §14 (Phase 2) bndl-ast arena; ADR-07
MM6 CJS require() returns a value snapshot; ESM import is a live view The two semantics are observable and incompatible without bridging. __toESM + __commonJS model the exact boundary where a CJS snapshot is wrapped into an ESM namespace object with a synthetic live default. Treating all modules as ESM and concatenating a CJS module → module.exports reads stale after first require; treating all as CJS → live bindings break, TDZ lost. §22 (Phase 8) interop helpers; ADR-10; P12
MM7 Source maps are a composition, not a rewrite Each stage (lex→parse→transform→print→minify) emits a position delta mapping generated positions back to the previous stage's positions. The final map is the composition of all deltas, not a new computation against the original source. Forgetting one stage collapses the chain and silently maps debugger breakpoints to wrong lines. A transform stage that rewrites spans without emitting deltas → debugger maps to the post-transform position, not the original TypeScript source. §18 (ADR-18) #265 codec; §22 Phase 8 emit; §23 Phase 11 mangle names[]
MM8 Regex-vs-divide disambiguation requires parser context, not lexer state alone A / character is a regex start after return, (, [, =, operators, or start-of-input; it is a divide after an operand (ident, ), ], number, string, template-tail). The decision is made by feeding regex_context from the parser back to the lexer on each /. A stateless DFA lexer always treats / one way → either every divide is misidentified as a regex (hanging on a/b/c) or no regex is recognized after return /pattern/. §13 (Phase 1) Lexer.regex_context; ADR-03
MM9 Scope hoisting is correct only when the module is "safe" (no eval, no CJS, not in a lazy-init cycle) A module that contains eval can look up any name by string at runtime; renaming its bindings breaks this. A module in a cycle must be wrapped to break the TDZ. A CJS module cannot be hoisted because module.exports is a value snapshot. Hoisting a module containing eval → mangled names are invisible to eval lookups → subtle dynamic reference bugs that only appear with specific eval arguments. §22 (Phase 8) WrapKind eligibility; ADR-12
MM10 Content addressing makes the cache correct across branch switches, where mtime caching does not Checking out an older branch restores old file content with a new mtime. A mtime-keyed cache sees a "newer" file and treats the old content as a cache miss (correct) or, worse, uses an artifact from a different content if the mtime happens to match a cached entry. Content-addressed keying is immune to clock artifacts. mtime cache + branch switch → stale artifact with new-looking mtime → silently reuses the wrong compiled output → runtime behavior diverges from source. §25 (Phase 13) CacheKey = BLAKE3(content + opts); ADR-19

Glossary · 49 terms · site-wide glossary

module specifier
The raw string in import x from "<spec>" / require("<spec>") / import("<spec>"). Classified by bndl-resolver into Specifier::{Relative, Absolute, Bare}; fed to Resolver::resolve with active Condition set. Never a resolved path until → resolution runs.
relative specifier
Specifier starting ./ or ../. Resolved against the importer's directory; no node_modules walk. Specifier::Relative(String). Subject to extension + index probing.
absolute specifier
Specifier that is an absolute filesystem path (or file://). Specifier::Absolute(String). Bypasses package lookup; still extension/index-probed + realpath'd.
bare specifier
Specifier not starting with .// (e.g. react, lodash/fp). Specifier::Bare{pkg, sub}. Triggers node_modules walk + package.json exports/main/module/browser resolution; pkg may be scoped (@scope/name). tsconfig paths matched before the walk.
conditional exports
package.json exports/imports map keyed by Condition (import/require/browser/node/default/development/production/custom). First matching condition in declaration order wins; supports * pattern subpaths. PACKAGE_EXPORTS_RESOLVE. Mis-ordering → wrong file; failure → ResolveError::{NotExported, InvalidExports}.
module graph
The DAG (with recorded back-edges for cycles) of all reachable modules. ModuleGraph{ modules: Vec<Module>, entries: Vec<ModuleId> }. Built by bndl-graph from entries via parallel resolve+load+scan; the central data structure consumed by shake/chunk/codegen.
module record
One node of the graph: Module{ id, path, kind, ast, imports, exports, symbols, has_side_effects }. Immutable + Send+Sync after construction → enables fearless parallel processing. Identified by ModuleId(u32).
import record
One import edge: ImportRecord{ specifier: Atom, resolved: Option<ModuleId>, kind: ImportKind } where kind ∈ {Static, Dynamic, Require, ExportStar}. resolved=None until → resolution; external/builtin stay None or point at an External/Builtin module.
export record
One export binding: ExportRecord{ name: Atom, local: Option<SymbolId>, reexport: Option<(ModuleId, Atom)> }. local=Some → defined here; reexport=Some → forwarded from another module (→ re-export). Drives tree-shaking + namespace assembly.
live binding
An ESM import is a read-only view of the exporter's binding, not a copy: later mutations of the exported variable are observable at the import site. Tree-shaking, renaming, scope hoisting, and concatenation MUST preserve identity + mutation-visibility. Contrast → CommonJS interop (snapshot).
re-export
export { x } from "m" / export { x as y } from "m" — forwards a binding without importing it locally. Modeled by ExportRecord.reexport. Tree-shaker prunes re-exports whose target symbol is unreachable (re-export pruning).
export-star
export * from "m" (and export * as ns from "m"). ExportDecl::All{ source, alias }, ImportKind::ExportStar. Re-exports all of m's named exports (excluding default); name collisions across multiple stars resolve to ambiguous → omitted. Requires transitive export-set computation.
namespace import
import * as ns from "m" — binds an object exposing all named exports of m as live getters. Forces materialization of m's full export object; limits dead-export elimination unless property accesses are statically analyzable.
default export
export default <expr/decl> ↔ import x from "m". ExportDecl::Default. Distinct slot named default; excluded from export-star. CJS interop synthesizes a default from module.exports via → interop helper.
CommonJS interop
Bridging CJS ↔ ESM. CJS module.exports is a value snapshot read at require time (not a live binding). Helpers: __toESM wraps a CJS value as an ESM namespace (adds default, __esModule handling); __commonJS wraps a module body for lazy first-call execution; __require is the runtime require. ModuleKind::Cjs.
tree shaking
Symbol-level dead-code elimination: keep only exports/statements reachable from entry exports. bndl-treeshake: SymbolGraph + worklist Reachability from entries → ReachableSet; shake(&mut ModuleGraph, &[ModuleId]). Soundness rule: NEVER drop observable → side effects unless proven → pure. Over-removal = correctness bug.
side effect
Any observable effect of evaluating code (I/O, mutation of external state, throws, getters). SideEffect::{Pure, Impure, Unknown}. A top-level statement with effects pins its module (cannot be shaken). Unknown is treated conservatively as Impure.
pure annotation
/*#__PURE__*/ before a call/new marks it side-effect-free → removable if its result is unused. An explicit contract from the author; combined with package.json sideEffects:false to license aggressive shaking. Misuse → silently dropped effects.
scope hoisting
a.k.a. → module concatenation. Inlining multiple ESM modules into a single shared scope (Rollup/esbuild-style) instead of one runtime-wrapped function each → smaller output, faster init, better minification. Sound only for ESM modules needing no → wrapper.
module concatenation
Synonym for scope hoisting; the act of merging module bodies into one lexical scope, with a cross-module → renamer resolving identifier collisions. Driven by bndl-codegen after ScopeTree construction.
wrapper / lazy init
Fallback to scope hoisting: wrap a module body in a runtime function (__esm/__commonJS) executed once with first-call memoization. Required for CJS, modules using eval, and modules in a cycle that forces ordered lazy init. Preserves evaluation-order semantics.
chunk
An output unit: Chunk{ id, modules, entry, is_dynamic, hash, imports }. One emitted file. ChunkId(u32); imports: Vec<ChunkId> are cross-chunk edges. Hash = content hash of final bytes (→ determinism).
code splitting
Partitioning the module graph into multiple → chunks so shared deps are emitted once and dynamic imports load on demand. bndl-chunk::split(&ModuleGraph, &ReachableSet, OutputFormat) -> ChunkGraph. Driven by → module groups.
module group
esbuild/Rollup splitting key: the set of entry points (static + dynamic) that can reach a module. Modules with identical reach-sets share a chunk; multi-entry reach → a shared chunk; single-entry → that entry's chunk. Deterministic given the graph.
dynamic import
import("<spec>") — an async, possibly runtime-computed import returning a Promise of the namespace. Expr::Import, ImportKind::Dynamic. Creates a → chunk boundary (async chunk) and a code-split point. Specifier may be non-literal (→ unanalyzable → external/runtime-resolved).
entry point
A root module the bundle is built for. ModuleGraph.entries: Vec<ModuleId>. Each entry yields an entry chunk; entries seed both reachability (→ tree shaking) and → module-group computation.
module runtime
Injected helper code that emulates module semantics in the output. Helpers: __require, __esm, __commonJS, __toESM, __export. Emitted by bndl-codegen once per bundle (or per chunk), tree-shaken to only the helpers used. Format-dependent (ESM/CJS/IIFE).
interop helper
An individual → module-runtime function bridging formats/semantics — __toESM (CJS→ESM ns), __export (define live getters on an export object), __commonJS/__esm (lazy-init wrappers). Emitted on demand.
define replacement
Compile-time substitution of identifiers/member chains with constant expressions (e.g. process.env.NODE_ENV → "production"). DefineMap; Define pass in bndl-transform. Enables downstream dead-branch removal during → minify. Applied before lowering.
syntax lowering
Rewriting newer syntax to an older Target (optional chaining, nullish coalescing, class fields, logical-assignment, async scope). Lowering pass. Lowers syntax only — never type checks. Target gates which lowerings run.
target
The output ECMAScript level: Target::{Es5, Es2015, Es2017, Es2020, Es2022, EsNext}. Controls → syntax lowering, helper injection, and minifier transforms. Field of TransformContext.
type-stripping
Parsing TypeScript type syntax then discarding it (annotations, interfaces, enums-as-types, generics, decorators-as-types) — producing valid JS. TypeStrip pass. Explicitly NOT type checking (→ project #42). Erasable-only by default; enum/namespace/param-props need emit.
jsx-runtime (automatic) vs createElement (classic)
Two JSX lowering modes. Automatic: emit jsx/jsxs/Fragment imports from a configured jsx-runtime. Classic: emit React.createElement/Fragment calls. JsxRuntime::{Classic, Automatic} in TransformContext; JsxTransform pass.
mangle
Renaming identifiers to short, scope-correct names to shrink output. Scope-aware via Renamer over ScopeTree; deterministic name-allocation order (→ determinism). Optional property mangling is opt-in (semantics-risky). Part of Minifier.
minify
Size-reduction pass set in bndl-codegen::Minifier: → mangle + DCE + constant folding + dead-branch removal + whitespace removal. MUST preserve runtime semantics + source-map composition.
renamer
Renamer — scope-aware rename map producing collision-free identifiers for → module concatenation and → mangle. Operates over ScopeTree; must respect → live-binding identity and reserved words.
scope tree
ScopeTree — the lexical-scope hierarchy with bindings + references + scope ids, built during scope analysis. Foundation for Renamer, scope hoisting, and DCE. Every reference is bound to a declaration (or flagged global/unresolved).
content-addressed cache
bndl-cache: artifacts keyed by CacheKey([u8;32]) = BLAKE3 of (content + options). Cache (in-memory + on-disk); Artifact::{Parsed, Transformed, Emitted}. Identical input+options → cache hit → skip recompute. Enables → incremental rebuild.
incremental rebuild
Recomputing only the artifacts whose CacheKey changed after a file edit; reusing cached parse/transform/codegen for unchanged modules. Change-driven invalidation propagates along graph edges. Powers fast dev rebuilds + bndl-server.
HMR
Hot Module Replacement — swap an updated module into a running app without full reload, preserving state. bndl-server::HmrEngine; websocket protocol + client ModuleRunner. Falls back to full reload when no accepting → HMR boundary exists.
HMR boundary
HmrBoundary{ module, accepts } — a module that calls import.meta.hot.accept, stopping update propagation. On change, the engine walks importers upward until a boundary accepts; no boundary up to an entry → full reload.
module runner
The dev-server client runtime (ModuleRunner) that fetches + evaluates on-demand-transformed ESM, maintains the live module registry, and applies HMR updates. Counterpart to the production → module runtime.
dependency pre-bundling
Vite-style: ahead-of-time bundle node_modules deps (esp. CJS → ESM) into a few cached ESM files so the dev server serves few, fast requests instead of thousands of tiny ones. Cached via bndl-cache; invalidated on lockfile/dep change.
ASI
Automatic Semicolon Insertion — ECMAScript rule inserting virtual ; at line breaks/}/EOF. bndl-lexer records Token.had_newline_before; the parser applies ASI on restricted productions (return, throw, ++/--, etc.). Mishandling → wrong parse, not an error.
Pratt parsing
Precedence-climbing expression parser using per-operator binding powers; resolves associativity + precedence without a separate grammar level per operator. Used in bndl-parser for Expr. Pairs with lexer-fed context for → regex-vs-divide.
ESTree
The de-facto JS AST shape standard the bndl-ast node set mirrors (Program, Stmt, Expr, Pat, Ident, …), extended with Span + NodeId + TS/JSX nodes. Eases mapping reference parsers (SWC/OXC/Babel) 1:1.
Atom
An interned string (cheap Copy/Eq/hash; deduplicated). Used for identifiers, specifiers, export/import names (Ident.sym, ImportDecl.source, ExportRecord.name). Interning shrinks memory + speeds symbol comparison on the hot path.
Span
Span{ start: u32, end: u32 } — byte-offset range into a SourceFile, paired with SourceId(u32). Attached to every token + AST node. Threaded through all stages → enables → source-map composition (lex→parse→transform→print→minify).
manifest
The build output index: per-chunk file_name, entry mapping, imports (cross-chunk edges), dynamic-import → chunk map, and asset references. Emitted alongside OutputChunks by bndl-chunk/bndl-codegen; consumed by HTML injection + runtime chunk loading.
