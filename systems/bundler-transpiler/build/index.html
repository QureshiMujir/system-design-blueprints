⬜ Phase 0 — Skeleton, workspace, and the "bundle two files into one" smoke test §12

Objectives
  • Stand up the Cargo workspace (12 bndl-* members, edition 2021, MSRV 1.78) with a green pipeline: fmt + clippy -D warnings + build + test.
  • Define compiling type shells only (no logic): Token/TokenKind/Span/SourceId; AST Program/ModuleItem/Stmt/Expr/Ident; ParseError/ParseErrorKind; ResolveError; ModuleId/Module/ModuleGraph; Chunk/OutputFormat; TransformContext; Plugin trait.
  • Ship one end-to-end vertical slice: bndl build entry.js where entry.js does import {x} from "./b.js" and b.js does export const x = ... → single ESM OutputChunk that runs under Node and prints the expected value.
  • Establish the differential-oracle scaffold: esbuild/Rollup invoked behind a dev-oracle cargo feature, never a runtime dep.
  • Lock determinism scaffolding: identical inputs+opts → byte-identical output (assert in smoke test).
Deliverable

bndl build tests/fixtures/smoke/entry.js -o dist/ produces dist/entry.<hash>.js (single ESM chunk) that, run via node dist/entry.<hash>.js, prints 42. Workspace compiles; make lint test is green; oracle scaffold runs under --features dev-oracle.

Pitfalls
  • Workspace resolver="2" omitted → feature unification leaks dev-oracle into release builds; symptom: oracle deps in cargo tree --no-default-features. Fix: resolver 2 + audit cargo tree.
  • Cyclic crate deps (e.g. graph↔transform via convenience re-export) → workspace won't compile. Root cause: shoving helpers in wrong crate. Keep the locked dep DAG; debug with cargo-depgraph.
  • Atom as String clone-everywhere baked into shells → costly to swap for interner in Phase 1. Use type Atom alias now so the change is one line.
  • Span as usize → non-portable map offsets, breaks #265 codec contract. Lock u32 byte offsets from day 1; assert source <4 GiB.
  • Oracle as normal dependency → ships node toolchain into the binary, bloats Docker, breaks cargo install. Must be #[cfg(feature)] + dev-only; CI gate that default build has zero oracle symbols.
  • Smoke test asserts byte-equality vs esbuild → false failures (cosmetic differences). Phase 0 oracle compares runtime stdout, not bytes.

⬜ Phase 1 — ECMAScript / TS / JSX lexer §13

Objectives
  • Cover ES2022 lexical grammar: IdentifierName, Keyword, PrivateName (#x), NumericLiteral (dec/hex/oct/bin + _ separators + legacy octal), BigInt (n suffix), StringLiteral, template tokens (NoSubTemplate/Head/Middle/Tail), RegularExpressionLiteral, all punctuators.
  • Track had_newline_before on every Token → feeds parser ASI (Phase 2). Resolve regex-vs-/ via parser-fed regex_context flag (lexer cannot decide alone).
  • Emit TS-relevant tokens (?, !, </>, type punct reuse existing kinds) and JSX shapes (JsxText, JsxIdent) gated by parser mode, not lexer config.
Deliverable

bndl-lexer crate: Lexer::new(src,id) -> Lexer, Lexer::next_token() -> Token, iterator tokens(); round-trips (concat of token source-slices + trivia == input); cargo test -p bndl-lexer green; fuzz target fuzz_lex builds.

Pitfalls
  • } ambiguity in templates — } may close a ${...} substitution OR an object literal inside it. Root cause: shared } token. Fix: brace-depth counter per Expr frame; only depth-0 } pops to TplString. Debug: dump template_stack on each }.
  • Regex context staleness — parser forgets to update regex_context after a token → /=/ mis-lexed. Symptom: Punct where Regex expected. Debug: assert on transition table in tests; log (prev_kind, regex_context).
  • Unicode-escape in identifiers — abc is identifier abc; escape must decode to a valid IdStart/IdContinue, else Invalid (not silent accept). Root cause: skipping escape validation. Debug: fixture unicode_id.js.
  • Legacy octal vs separator — 0o17 (modern) vs 017 (legacy octal, sloppy-only) vs 0_1 (illegal). Conflating → wrong value/strict-mode bug. Lexer tags legacy-octal so parser can reject in strict mode.
  • CR-LF newline double-count — \r\n is ONE line terminator for ASI; counting two corrupts column maps. Treat \r\n atomically.
  • Maximal munch on ?. — a?.5 is a ? .5 (cond + number) NOT optional-chain (?. not followed by digit). Lexer peeks: ?. only if next not a digit.

⬜ Phase 2 — Recursive-descent + Pratt parser (ES2022 core) §14

Objectives
  • Statements/declarations via recursive descent; expressions via Pratt (binding powers, associativity, comma/assignment/conditional ladder).
  • Patterns + destructuring (array/object, defaults, rest); cover-grammar reparse Expr -> Pat.
  • Classes: fields, private members (#x), static blocks, computed keys, getters/setters, super.
  • async/await, generators (function*, yield/yield*), async arrows.
  • ES modules: import/export (named/default/namespace/* as ns), import() dynamic, import.meta.
  • Attach Span (lexer-byte-accurate) + monotonically-increasing NodeId to every node.
  • ParseError recovery: synchronize at ;/}/statement-start keyword; emit Vec<ParseError>, return best-effort AST. Non-goal: type checking, TS/JSX bodies (Phase 3).
Deliverable

parse_program parses arbitrary ES2022 modules + scripts into a correct ESTree-shaped Program (every node Span+NodeId), returning (Program, Vec<ParseError>) — never panics. Round-trip: AST printed by a debug pretty-printer re-parses to an equal AST (modulo spans). Passes hand-built suite + subset-Test262 (pass/+fail/).

Acceptance
  • All hand-built fixtures parse to expected AST shape (snapshot-tested); 0 panics across fuzz corpus.
  • Subset-Test262: ≥99% of curated pass/ accepted, ≥99% fail/ rejected with a ParseError (not panic/hang).
  • Spans byte-exact: &src[node.span.lo..node.span.hi] re-tokenizes to that node for 100% of sampled nodes.
  • NodeId unique + monotonic; ASI matches V8 on the ASI fixture set (≥40 cases).
  • Throughput ≥ 5 MB/s single-thread parse on the 50 KB React-build fixture; recovery yields ≥1 valid stmt after each injected error.

⬜ Phase 3 — TypeScript + JSX parsing (parse-and-discard types) §15

Objectives
  • Parse TS surface syntax: type annotations, interface, type aliases, enum/const enum, generics (<T> decls + call/type args), parameter properties, decorators, as/satisfies/<T>x, import type/export type, ambient declare, namespace/module.
  • Parse JSX: elements, fragments, attributes, spread attrs, expression containers, member/namespaced tag names; resolve the < JSX-vs-less-than/type-arg ambiguity; honor @jsxRuntime/@jsx/@jsxFrag pragma comments.
  • Strip all type-only constructs → AST identical in shape to a plain-JS parse (types collapse to Spans only; runtime nodes survive).
  • Gate every production behind Syntax{typescript,jsx}; mis-enabled syntax → ParseError, never a panic.
  • File-ext → default Syntax mapping for .ts/.tsx/.mts/.cts/.d.ts/.jsx; .d.ts parses then yields zero runtime items.
Deliverable

parse_program(src, id, Syntax{typescript:true,jsx:true}) returns a JS-only Program for any .ts/.tsx/.mts/.cts/.d.ts/.jsx input. cargo run -p bndl-cli -- transform foo.tsx --syntax ts,jsx prints the type-stripped AST. enum and decorators survive as runtime; everything type-only is gone. .d.ts → empty items.

Acceptance
  • 100% of the TS+JSX fixture suite parses with byte-identical post-strip AST vs the SWC oracle (span-normalized, node_id-erased compare).
  • Round-trip: strip-and-print of a TS file ≡ print of the same file with types hand-removed (DefinitelyTyped sample N≥200 .d.ts → 0 runtime items).
  • < ambiguity: 30-case table (JSX / type-arg-call / relational) all resolve correctly.
  • Mis-enabled: JSX with jsx:false → JsxNotEnabled; TS annotation with typescript:false → TrailingTsType; 0 panics under fuzz (10M iters).

Pitfalls
  • < trilemma (a < b vs f<T>() vs <div>): root cause = unbounded lookahead. Fix: JSX wins when jsx set + next is ident/>; else tentative type-arg parse with checkpoint+backtrack; debug via --dump-token-context.
  • .tsx arrow generic: <T>()=>{} is JSX in .tsx; require <T,> or <T extends U>. Forgetting → spurious JSX parse. Debug: compare .ts vs .tsx Syntax flag.
  • ASI vs JSX/type: newline before < must not insert ; mid-JSX-child; had_newline_before only governs statement boundaries. Symptom: truncated JSX children.
  • enum is NOT pure-strip: it emits runtime; deleting it (like an interface) loses values. Reverse-mapping + const enum inlining are runtime semantics.
  • Decorators are runtime, types are not: stripping a decorator silently breaks frameworks. Keep Decorator nodes; only strip their type args.
  • import type elision: must remove from ImportRecord so bndl-graph doesn't pull a type-only dep (dead edge / wrong tree-shake). Inline { type X } filters per-specifier.

⬜ Phase 5 — Module graph construction + live bindings §17

Objectives
  • Build bndl-graph: lift each parsed Program into a Module with scanned ImportRecord/ExportRecord/Symbol tables; assemble the ModuleId-keyed ModuleGraph.
  • Classify ModuleKind (Esm/Cjs/Json/Css/Asset/Builtin/External) per module; resolve every edge via bndl-resolver (Phase 4) to a ModuleId or external marker.
  • Model ESM live bindings, re-exports, export-star flattening, dynamic import(), and the CJS↔ESM interop boundary (no codegen yet — metadata only).
  • Detect + record import cycles (SCCs); designate entries; load the transitive graph in parallel (thread pool, immutable Send+Sync Module).
  • NON-GOAL: transforms (Phase 6), tree-shaking (Phase 7), emit (Phase 10). Graph is read-only after build.
Deliverable

ModuleGraph::build(entries,&Resolver) returns a complete graph for a multi-entry project: every reachable module loaded once, ModuleKind classified, ImportRecord/ExportRecord/Symbol tables populated, edges resolved to ModuleId, export-star flattened, cycles recorded, entries tagged. bndl graph <entries> prints the dot/JSON graph (ids, kinds, edges, cycles, live-binding flags).

Acceptance
  • Diamond import (A→B, A→C, B→D, C→D) yields 4 modules; D has exactly one ModuleId (dedup).
  • export * flattening matches Rollup: re-exporter exposes target's named exports, excludes default + locally-shadowed + ambiguous names.
  • Cycle a↔b recorded as one SCC; both in_cycle=true; build terminates (no infinite frontier).
  • Mixed graph (ESM entry → CJS dep → ESM dep) classifies each ModuleKind correctly; interop boundary flags set.
  • Parallel build is deterministic: ModuleId assignment + module order identical across runs and thread counts (BFS order seeded by sorted resolved specifiers).
  • bndl graph on a 1k-module fixture completes < 400 ms warm; graph output byte-identical run-to-run.

⬜ Phase 6 — Transform pipeline (TypeStrip, JSX, lowering, define) §18

Objectives
  • TransformPass trait + VisitMut driver; LOCKED order: Define → TypeStrip → JsxTransform → Lowering. Define-before-shake so dead branches collapse; TypeStrip before JSX so <T>x casts gone before <jsx>; lowering last (operates on fully-desugared JS).
  • TypeStrip: drop TS-only ModuleItem/Stmt/Expr/type-annotation nodes; keep value spans intact for source maps; collapse enum/namespace/param-properties to JS.
  • JsxTransform: classic createElement + automatic jsx/jsxs/Fragment (JsxRuntime::Classic|Automatic); key extraction, spread children, <>…</>.
  • Lowering: only what Target lacks — optional chaining, nullish coalescing/assign, logical assign, class fields/private, numeric separators, exponent, etc.
  • Define: inline process.env.NODE_ENV-style globals → literal Expr; produce statically-foldable conditions feeding the shaker (Phase 7).
  • Determinism: identical (AST, opts) → identical output AST + span deltas.

⬜ Phase 7 — Tree-shaking (symbol reachability + side effects) §19

Objectives
  • Build SymbolGraph: per-SymbolId def + use edges, intra- and cross-module, threaded through ImportRecord/ExportRecord/re-exports.
  • Reachability worklist from entry exports → minimal live SymbolId set; mark live statements/exports/imports.
  • SideEffect analysis: top-level effectful stmts, sideEffects:false package contract, /*#__PURE__*/, getters/proxies treated Unknown→Impure.
  • Eliminate: dead statements, unused named/default exports, unused imports, dead re-export specifiers, unreachable export-star members.
  • Invariant: every observable effect (assignments to globals, calls, throws, getters) preserved; over-removal is a correctness bug, not a win.
Deliverable

TreeShaker removing provably-dead code over the fixture suite; bndl build --analyze prints a RemovalReport; a soundness harness proving identical runtime observable behavior pre/post-shake; removal-ratio table vs Rollup.

Acceptance
  • Soundness fixtures: post-shake bundle output (executed under #126 oracle / Node) emits byte-identical stdout/effect-trace to unshaken — zero divergence across the suite.
  • Removal ratio within ±5% of Rollup on the shared fixture set (fixtures/treeshake/*).
  • Unused export export const x with no importer ⇒ removed; sideEffects:false lib import of one fn ⇒ siblings dropped.
  • Determinism: identical ReachableSet.live bitset bytes across 100 runs.
  • Performance: shake ≤ 8 ms per 1k modules single-thread.
