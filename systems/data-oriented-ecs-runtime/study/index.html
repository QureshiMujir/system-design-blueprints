Mental Models & First Principles

The compressed insights an expert in data-oriented ECS design holds. Each predicts a bug class. Every cited § resolves to a real heading.

MM1. An ECS is a column database for game state, not an object graph. Components are columns; entities are rows; systems are queries. Predicts: why iteration is fast (sequential column scans) and why you design around access patterns. Bug without it: modelling entities as objects-with-methods reintroduces pointer-chasing and cache misses the ECS exists to avoid. Applied: §8 (storage model), Phase 1–3, P1, ADR-06.

MM2. Struct-of-arrays exists to feed the cache, not for elegance. Storing each component type in its own contiguous column means iterating one component streams cache lines with zero waste. Predicts: the ≥ 2 GB/s/core iteration throughput. Bug without it: AoS layout drags unused components through cache on every iteration, collapsing throughput. Applied: §8 (SoA table), §4.1 (column throughput), §4.2 (cache), MM1.

MM3. An entity handle is an index plus a generation; the generation is what makes it safe. Reusing a slot bumps its generation, so a stale handle fails the generation check instead of aliasing a new entity. Predicts: safe O(1) entity validity checks. Bug without it: a recycled index lets a dangling handle read a different entity's data (the ABA problem). Applied: §8 (Entity), Phase 1, P5, ADR-04.

MM4. An archetype is the set of component types an entity has; changing composition moves the entity. Adding/removing a component migrates the row to a different archetype table. Predicts: why structural changes are expensive and batched. Bug without it: mutating composition mid-iteration invalidates the table you're scanning. Applied: §8 (archetype), Phase 3–4, MM5, ADR-08.

MM5. Structural mutation during iteration is forbidden; defer it. Spawns, despawns, and component add/remove are recorded in a command buffer and applied at sync points. Predicts: iteration safety (I6). Bug without it: despawning an entity mid-query shifts the column under the iterator → skipped or double-processed rows. Applied: Phase 11 (CommandQueue/apply_deferred), §4.3, ADR-14, I6.

MM6. Parallelism is a static disjointness proof, not runtime locking. Each system declares its read/write access; the scheduler runs two systems concurrently only if their access bitsets don't conflict. Predicts: lock-free parallel execution and the ≥ 3.5× speedup. Bug without it: runtime locks add overhead and risk deadlock; bypassing the check is UB. Applied: Phase 9–10 (Access accumulation/analysis), Phase 12 (scheduler), §4.3 (access conflict), P4, ADR-15.

MM7. Queries are monomorphized at compile time, so there is no per-entity dispatch. WorldQuery derives the exact component access and generates a tight typed loop. Predicts: zero-cost iteration vs reflection. Bug without it: runtime type lookup per entity adds a branch/indirection to the hottest loop in the engine. Applied: §8 (WorldQuery), Phase 7, P6, ADR-10.

MM8. Change detection is a monotonic clock compared per component, not a dirty flag. A Tick advances each frame; a component's changed tick vs the system's last-run tick decides "changed since I last looked." Predicts: per-component precision with wrap-aware comparison. Bug without it: a single global dirty bit over-runs systems on unrelated changes. Applied: Phase 8 (Tick/ComponentTicks), §4.1 (change-detection overhead), ADR-11, P10.

MM9. Type erasure is the price of a generic store, and Miri is how you pay it safely. BlobVec holds bytes + a Layout + a drop fn; every raw-pointer operation is unsafe and must be UB-checked. Predicts: where memory-safety bugs hide. Bug without it: an unchecked BlobVec mis-drops or mis-aligns a column → UB that only Miri catches. Applied: §8 (BlobVec/Column), §4.1 (Miri scope), ADR-05/ADR-23, P9.

MM10. Archetype fragmentation is the silent throughput killer. Too many rarely-shared component combinations create many tiny archetypes, so iteration touches many small columns instead of a few big ones. Predicts: the ≤ 1000-archetype guidance for sustained throughput. Bug without it: per-entity unique component sets fragment storage and destroy SoA locality (MM2). Applied: §4.4 (fragmentation), §8 (archetype), Scalability Analysis.

Glossary · 44 terms · site-wide glossary

ABA problem
Bug where a recycled slot appears valid because the index matches a prior occupant; defeated by Entity.generation (P5, I1).
Access set
Access<T> { reads: FixedBitSet, writes: FixedBitSet } representing all component/resource access declared by a system; the scheduler uses this to detect conflicts (Phase 10, Phase 12).
Added tick
ComponentTicks.added: the Tick value at which a component was first inserted onto an entity; never decremented (I7).
apply_deferred
Schedule sync point that drains CommandQueue in strict enqueue order (I8), flushing all pending structural mutations (P2).
Archetype
The canonical storage unit for entities sharing an identical component set; uniquely identified by ArchetypeId and backed by one Table (P3, I2).
ArchetypeId
u32 index into the Archetypes registry; stable for the World's lifetime.
Archetype graph
DAG of Edges on each Archetype; each edge is a ComponentId -> ArchetypeId transition memoizing the result of adding or removing one component (Phase 4).
BlobVec
Type-erased contiguous store holding items of a single Layout; carries a drop pointer; the primitive behind Column and resource storage (Phase 2, I10, P9).
Change detection
Tick-based mechanism comparing ComponentTicks.changed to a system's last_run tick; observable and deterministic, never heuristic (P10, Phase 8).
Changed tick
ComponentTicks.changed: set to World.change_tick on every DerefMut through Mut<T> (I7).
Column
BlobVec of component values plus parallel Vec<Tick> for added and changed ticks; one per ComponentId per Table (Phase 3, I4).
CommandQueue
Type-erased queue of deferred mutations; holds closures/records that each carry their own vtable; drained by apply_deferred (Phase 11, I8).
ComponentId
Dense usize index assigned at registration time; stable for the World's lifetime; keys into Components registry.
ComponentInfo
Descriptor tuple: { id, name, layout: Layout, drop: Option<unsafe fn(*mut u8)>, storage: StorageType }; registered once per type (Phase 2).
ComponentTicks
Pair { added: Tick, changed: Tick } stored in Column's parallel tick vectors, one per row (I7).
Conflict
Two systems conflict iff their Access sets intersect on a write, or one writes what the other reads; conflict forbids concurrent execution (I5, Phase 12).
Edges
Per-archetype hash maps ComponentId -> ArchetypeId for add and remove transitions; lookup is O(1) amortized; memoized on first structural move (Phase 4).
Entity
{ index: u32, generation: NonZeroU32 } — 64-bit generational handle; index identifies the slot, generation detects stale reuse (I1, P5).
EntityLocation
{ archetype_id, table_id, table_row, archetype_row } — precise four-coordinate address of an entity's data; stored in EntityMeta and updated on every migration (I2, I9).
EntityMeta
Per-slot record { generation, location: EntityLocation } in the dense entity array; authoritative source for liveness and location (Phase 1).
Exclusive system
System taking &mut World; cannot run concurrently with any other system; used for operations requiring unrestricted World access (Phase 14).
Fetch
Trait parameterised on a lifetime; fetch() extracts the typed value for one entity from pre-fetched column pointers (Phase 7, P6).
Fragmentation
Pathological state where many archetypes each hold few entities, degrading iteration cache efficiency; mitigated by component set design and sparse-set policy for volatile components (Phase 6, doecs-bench).
FunctionSystem
Blanket wrapper converting a Rust fn(P0..Pn) -> () into a System by calling SystemParam::init/fetch for each param (Phase 10).
Generational index
Index-plus-generation pattern used in Entity and free-list allocators to distinguish reused slots without pointer identity (P5, Phase 1).
IntoSystem
Conversion trait; implemented for FunctionSystem and exclusive-system wrappers; entry point for registering any callable as a system.
Observer / hook
Callback triggered on component add/remove; registered per ComponentId; runs synchronously within World; introduced in Phase 14.
QueryFilter
Trait sub-family of WorldQuery returning a boolean per archetype/entity without producing data (With<T>, Without<T>, Or, Added<T>, Changed<T>).
QueryState
Cached per-World state for a Query: list of matched ArchetypeIds, fetch init state; updated lazily when new archetypes are created (Phase 7).
Resource
Singleton value stored outside archetypes; keyed by ResourceId (analogous to ComponentId); accessed via Res<T> / ResMut<T> system params (Phase 9).
Row
The horizontal cross-section of a Table at a given index; conceptually one entity's component values across all columns; never a concrete struct.
Schedule
Ordered collection of systems and SystemSets with explicit ordering edges; compiled into a dependency DAG; executed by MultiThreadedExecutor (Phase 12).
SoA (struct-of-arrays)
Layout where each component type occupies its own contiguous array; enables SIMD-friendly iteration with unit-stride memory access (P1, Phase 3).
SparseSet
dense: Vec<V> + sparse: Vec<u32> index; O(1) insert/remove/lookup; used for components with high churn to avoid archetype migrations (Phase 6).
StorageType
Enum { Table, SparseSet } per ComponentInfo; controls whether a component lives in a Table column or a SparseSet (Phase 6).
Sync point
Schedule position where apply_deferred runs, draining all pending CommandQueues before subsequent systems execute (I6, P2, Phase 12).
SystemMeta
Metadata accumulated during system construction: component_access, resource_access, is_send, last_run tick; input to conflict analysis (Phase 10).
SystemParam
Trait with init_state and get_param methods; implemented by Query, Res<T>, ResMut<T>, Local<T>, Commands, EventReader<T>, EventWriter<T> (Phase 9).
SystemSet
Logical grouping of systems with shared ordering constraints; a node in the schedule DAG at the set level (Phase 12).
Table
ComponentId -> Column sparse array plus entities: Vec<Entity>; the primary SoA storage for one archetype (Phase 3, I4).
TableId
u32 index into Storages.tables; one table shared by exactly one archetype.
Tick
u32 logical clock incremented each schedule run; wrap-aware comparison via is_newer_than; used by ComponentTicks and system last_run (Phase 8, I7).
Topological order
Linear ordering of schedule nodes consistent with all before/after edges; cycle detection must fail at schedule build time (Phase 12).
WorldQuery
Root trait family unifying QueryData and QueryFilter; specifies ReadOnly marker, Fetch associated type, archetype-match predicate, and iteration safety rules (Phase 7).
