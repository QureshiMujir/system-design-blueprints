Decisions (§9) · 30 ADRs

ADR-01

Implementation language

Chosen

Rust (stable, 2021 edition)

Rejected

C++, Zig, Go

When the rejected choice is right

C++ wins to integrate with an existing engine (Unreal/Unity native) or reuse EnTT; Zig wins for comptime-heavy data-layout control; Go wins for a GC'd gameplay-scripting layer where raw throughput is secondary

Why: Ownership model enforces aliasing rules; unsafe is auditable; zero-cost abstractions; ecosystem (Criterion, Miri, rayon)

ADR-02

Build system

Chosen

Cargo workspace (virtual manifest)

Rejected

Bazel, CMake, Buck

When the rejected choice is right

Bazel/CMake win when the ECS is one module of a larger C++/polyglot engine build

Why: Native Rust toolchain; workspace-level [profile]; no wrapper needed

ADR-03

Dependency policy

Chosen

Minimal: rayon, fixedbitset, hashbrown, criterion only

Rejected

heavy framework deps

When the rejected choice is right

Heavy framework deps win when you want a batteries-included engine (full Bevy) rather than a teachable core

Why: Each dep auditable; avoids transitive unsafety; lock file checked in

ADR-04

Entity handle representation

Chosen

Entity { index: u32, generation: NonZeroU32 } — 8 bytes

Rejected

32-bit packed, 64-bit opaque u64

When the rejected choice is right

A 64-bit opaque handle wins when you need >4 B live entities or want to pack extra metadata; 32-bit packed wins on memory-constrained targets

Why: NonZeroU32 enables Option<Entity> niche; generation defeats ABA (P5)

ADR-05

Component storage primitive

Chosen

BlobVec — type-erased Vec<u8> with Layout + drop

Rejected

Vec<Box<dyn Any>>, Vec<*mut u8> per-alloc

When the rejected choice is right

Vec<Box<dyn Any>> wins for a tiny prototype where per-element boxing simplicity beats cache locality

Why: Single contiguous allocation per column; SoA access pattern; no per-element heap alloc

ADR-06

Primary storage model

Chosen

SoA table (archetype columns)

Rejected

AoS, hash-map-per-entity, ECS slots

When the rejected choice is right

AoS wins when most accesses touch all of one entity's components together (rare in ECS); hash-map-per-entity wins for very sparse, heterogeneous entities

Why: Cache-line locality on component-type iteration; P1 directly supported

ADR-07

Secondary storage model

Chosen

SparseSet per component

Rejected

single storage type

When the rejected choice is right

A single archetype storage wins when component churn is low and the dual-storage complexity isn't justified

Why: High-churn components skip archetype graph movement; O(1) add/remove

ADR-08

Archetype identity

Chosen

Sorted Box<[ComponentId]> + HashMap key

Rejected

bitmask (limited to 64 components), ordered set tree

When the rejected choice is right

A 64-bit bitmask wins when component count is provably ≤ 64 and O(1) archetype set-ops are wanted

Why: Supports unlimited component count; deterministic equality

ADR-09

Archetype graph memoization

Chosen

Edges { add, remove }: HashMap<ComponentId, ArchetypeId>

Rejected

re-scan archetypes per transition

When the rejected choice is right

Re-scanning wins for a tiny world where the edge-map memory isn't justified

Why: O(1) structural transition lookup; paid once on first transition

ADR-10

Query access model

Chosen

WorldQuery / QueryData / QueryFilter traits; compile-time access derivation

Rejected

runtime type strings, reflection

When the rejected choice is right

Runtime reflection/type-strings win for a scripting/modding layer where queries are authored at runtime, not compile time

Why: Monomorphized; no dynamic dispatch per entity; P6 (zero-cost queries)

ADR-11

Change detection mechanism

Chosen

Tick(u32) monotone clock + ComponentTicks {added, changed} per row

Rejected

dirty bits, version per archetype, pointer equality

When the rejected choice is right

Per-archetype version or dirty bits win when per-component change precision isn't needed and lower memory is preferred

Why: Per-component precision; wrap-aware 32-bit; P10 (explicit semantics)

ADR-12

Parallelism model

Chosen

rayon work-stealing thread pool via MultiThreadedExecutor

Rejected

tokio, std::thread manual pool, crossbeam

When the rejected choice is right

A manual thread pool wins when you need control rayon doesn't expose (thread affinity, custom stealing); tokio wins if systems are I/O-bound (they aren't here)

Why: Rayon work-stealing matches irregular per-system load; P4

ADR-13

Async / futures

Chosen

None (no async runtime)

Rejected

tokio, async-std

When the rejected choice is right

An async runtime wins when systems perform real I/O (asset streaming, networking) rather than pure compute

Why: ECS systems are synchronous; async overhead unneeded; !Send pin suffices

ADR-14

Deferred mutation

Chosen

CommandQueue byte buffer; apply_deferred at sync points

Rejected

immediate mutation with read/write locks, transactional copy-on-write

When the rejected choice is right

Immediate mutation with locks wins for a single-threaded simple world where deferred-apply complexity isn't worth it

Why: Eliminates mid-iteration structural mutation (I6); P2

ADR-15

Access conflict analysis

Chosen

Access<T> FixedBitSet read/write per component/resource; conflicts_with at schedule build

Rejected

runtime lock acquisition, optimistic concurrency

When the rejected choice is right

Runtime locking wins when the system set is dynamic/unknown at schedule-build time (plugin-loaded systems)

Why: Static analysis at schedule compile time; no runtime lock overhead (P4)

ADR-16

Conflict bitset implementation

Chosen

fixedbitset::FixedBitSet

Rejected

bit_vec, roaring, manual Vec<u64>

When the rejected choice is right

roaring wins for a very sparse, huge component-id space where compression matters

Why: Proven crate; fast set-intersection; grows dynamically with component count

ADR-17

Serialization format

Chosen

None built-in; serde feature-gated on component types

Rejected

MessagePack, Protobuf, CBOR

When the rejected choice is right

Mandatory built-in serialization wins for a save-game-centric engine where every component must persist by default

Why: Core runtime has no mandatory serialization dependency; users opt-in via serde derive

ADR-18

Wire / snapshot format

Chosen

Bincode (feature-gated, for save/load examples in doecs-cli)

Rejected

JSON, RON, BSON

When the rejected choice is right

JSON/RON win for human-editable save files or debugging; BSON for MongoDB interop

Why: Compact binary; serde-compatible; only in examples, not core crates

ADR-19

Logging

Chosen

tracing (spans for schedule execution, system dispatch)

Rejected

log, println!, slog

When the rejected choice is right

log/println wins for a minimal prototype not needing structured spans across rayon threads

Why: Structured; zero-cost when disabled; compatible with rayon threads

Unit / integration testing

Chosen

Rust 1.76 (stable; NonZeroU32 const, Layout stable APIs)

Alternative Architectures (Roads Not Taken)

Alt-A — Sparse-set-primary ECS (EnTT model).

each component = sparse array (entity->dense index) + dense value array; entities are intersections of sparse sets

Wins when: component add/remove churn is very high and you want O(1) structural changes without archetype migration. Embodied by: EnTT, Shipyard. Rejected (as primary) because: archetype tables give better multi-component iteration locality (MM2); we keep sparse sets as the secondary store (ADR-07) for high-churn components, getting both.

Alt-B — Object-oriented entity hierarchy (scene-graph / GameObject).

Entity = object with a Vec<Box<dyn Component>>; systems call virtual methods per entity

Wins when: the game is logic-heavy with few entities and developer familiarity matters more than throughput (classic OOP engines). Embodied by: Unity GameObject/MonoBehaviour, Unreal AActor. Rejected because: per-entity boxing and virtual dispatch reintroduce the pointer-chasing and cache misses the ECS exists to eliminate (MM1, MM7).

Alt-C — Relational/database-backed entity store.

entities + components in an in-memory relational DB; systems are SQL-like queries with a planner

Wins when: complex ad-hoc queries, joins, and persistence dominate over per-frame iteration speed (simulation/strategy with rich queries). Embodied by: some MMO server backends, flecs's query engine leans this way. Rejected because: a query planner adds per-query overhead unacceptable in a 60 Hz hot loop; compile-time monomorphized queries (MM7) are faster for the fixed query set.

Alt-D — Immediate-mode parallel jobs over chunks (Unity DOTS model).

archetype chunks dispatched to a job system; Burst-compiled jobs vectorize over chunk arrays with a runtime safety layer

Wins when: you have a mature vectorizing compiler (Burst) and a runtime safety system, shipping AAA-scale C# games. Embodied by: Unity DOTS. Rejected (partly deferred) because: we encode disjointness in Rust's type system at schedule build (MM6) rather than a runtime safety layer, and SIMD/Burst-equivalent chunk vectorization is in the Deferred Features Register.
