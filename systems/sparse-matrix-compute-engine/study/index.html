34. Mental Models & First Principles

The compressed insights an expert in sparse compute carries. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — A sparse matrix is a graph wearing numbers. The sparsity pattern is an adjacency structure; factorization is vertex elimination; fill is edge creation; an ordering is a vertex permutation. Predicts: fill, parallelism (independent etree subtrees), and separator quality all follow from graph structure, not values. Bug class without it: treating ordering as a numerical tweak and missing that natural ordering on a 3D mesh is an OOM, not a slowdown. Applied: §15 (graph + ordering), §16 (etree), §8.4.
  • MM2 — SpMV lives on the left of the roofline; GEMM lives on the right. Arithmetic intensity ≈ 0.16 flop/byte pins SpMV to bandwidth/bytes-per-nz; no amount of FLOP tuning helps. Predicts: the only SpMV levers are bytes moved (index width, format, blocking) and gather locality (reordering) — never FLOP count. Bug class without it: optimizing the inner multiply, reporting "% of FLOP peak," and being puzzled by 10 % utilization. Applied: §4.1, §13, §8.3.
  • MM3 — Compute where before what: the symbolic/numeric split. The pattern of L is a function of the pattern of A and the ordering alone — knowable before any floating-point work. Predicts: you can allocate the factor exactly once, reject a too-large factorization before doing it, and reuse the plan across many numeric refactorizations (time-stepping/Newton). Bug class without it: growing the factor during numeric → realloc thrash, fragmentation, OOM surprises. Applied: §16 (symbolic), principle 2/3, I4.
  • MM4 — Sparse performance is the art of finding dense substructure. Supernodes (consecutive columns with nested structure) turn sparse factorization into a sequence of dense GEMM/TRSM/SYRK calls. Predicts: the level-3 fraction (share of flops in dense BLAS) is the throughput metric; bigger (relaxed) supernodes trade a little fill for much more BLAS efficiency. Bug class without it: element-wise numeric factorization that never touches BLAS and runs 10× slow. Applied: §17, §8.5, I7, the #349 bridge (§9.1).
  • MM5 — Ordering pays via two unrelated mechanisms. For SpMV it pays via locality (the x-gather hits cache); for factorization it pays via fewer fill nonzeros (less memory and fewer flops). Predicts: RCM helps SpMV bandwidth; ND/AMD help direct-solve fill — and these are different goals, so the best ordering depends on what you are about to do. Bug class without it: using a bandwidth-reducing ordering and expecting it to minimize fill (or vice versa). Applied: §22 (auto-select), §15, §2.7.
  • MM6 — Direct vs iterative is a memory decision as much as a time decision. Direct costs O(fill) memory (super-linear in 3D); iterative costs O(nnz) memory but needs a preconditioner to converge. Predicts: on a fine 3D mesh, direct OOMs and you must go iterative; the cheap symbolic fill estimate is what lets analyze decide before committing. Bug class without it: always-direct (OOM on 3D) or always-iterative (non-convergence on ill-conditioned without a preconditioner). Applied: §4.2, §8.7, §22, principle 8.
  • MM7 — A preconditioner is a cheap approximate inverse you re-apply every iteration. M ≈ A with M⁻¹ cheap; the win is fewer Krylov iterations, the cost is setup + per-iteration apply. Predicts: stronger M (ILUT vs IC(0)) cuts iterations but raises apply cost — you must report setup and iteration-reduction together to judge it. Bug class without it: shipping a preconditioner that "reduces iterations" while making each iteration so expensive the wall-clock gets worse. Applied: §21, principle 9, I12.
  • MM8 — The recursively-updated residual is a lie you must periodically check. Krylov methods track ‖r‖ by recurrence; rounding makes it drift from the true ‖b−Ax‖. Predicts: near convergence the recurrence can report success while the true residual is large — you must recompute the true residual periodically. Bug class without it: declaring false convergence and returning a wrong x that "passed" the stopping test. Applied: §20, §8.12, I11, the false-convergence failure class (§27).
  • MM9 — Validate at the boundary so the inner loop can be blind. Untrusted index arrays are checked once in O(nnz) (in-range, sorted, dedup); after that the SpMV/factorization inner loops index without bounds checks. Predicts: exactly one place can produce an OOB, and it is the validator — so safety and speed coexist. Bug class without it: either an OOB read deep in a hot loop (no validation) or a bounds check on every nonzero (validation in the wrong place). Applied: §12, §23, I1/I13, principle 10.
  • MM10 — Pivoting and fill pull in opposite directions. Numerical stability wants the largest pivot; fill-minimization wants a structurally cheap pivot; threshold pivoting accepts a near-largest pivot to buy much less fill. Predicts: the pivot_tol knob is the central unsymmetric-direct tradeoff, and ordering (Q) and pivoting (P) interact dynamically in LU (unlike Cholesky's clean split). Bug class without it: a static fill-optimal ordering that pivoting then destroys, or max-pivot LU that fills catastrophically. Applied: §19, §8.12, I8.

Required reading (§5)

5.1 Books

  • Davis, Direct Methods for Sparse Linear Systems (SIAM 2006) — the reference. Ch.2 (CSparse basics), 4 (Cholesky + etree), 5 (orderings), 6 (LU/Gilbert–Peierls), 8 (QR). The spec for the direct path. Applied: §16 (etree/colcount), §17 (Cholesky), §19 (G–P LU), §8.4.
  • Saad, Iterative Methods for Sparse Linear Systems (2e, SIAM 2003) — ch.6 (Krylov: CG/GMRES), 7 (BiCGSTAB), 9–10 (preconditioning: ILU/IC). The spec for the iterative path. Applied: §20 (CG/GMRES/BiCGSTAB), §21 (IC/ILU/ILUT), §8.8.
  • George & Liu, Computer Solution of Large Sparse Positive Definite Systems (1981) — nested dissection, elimination tree, the foundational sparse-Cholesky theory. Applied: §15.2 (ND), §16.2 (etree), §8.10.
  • Golub & Van Loan, Matrix Computations (4e, 2013) — ch.10–11 (sparse + iterative), conditioning, Krylov convergence. Applied: §20.4 (√κ convergence), §8.12 (conditioning), §4.1.
  • Duff, Erisman & Reid, Direct Methods for Sparse Matrices (2e, OUP 2017) — Markowitz, fill, the classical treatment. Applied: §8.4 (fill), §19.6 (pivot-vs-fill), §8.12.
  • Higham, Accuracy and Stability of Numerical Algorithms (2e, SIAM 2002) — error bounds for sparse factorization, IC/ILU stability. Applied: §17.4 / §19.4 (residual bounds), §21.6 (IC stability).
  • Kepner & Gilbert (eds.), Graph Algorithms in the Language of Linear Algebra (SIAM 2011) — the matrix↔graph duality (SpGEMM as graph ops). Applied: §14 (SpGEMM), §15.1 (matrix-as-graph), the Comparative Architecture CombBLAS row (§35).

5.2 Papers

  • Gilbert & Peierls, "Sparse partial pivoting in time proportional to arithmetic operations" (SISC 1988) — the left-looking sparse-LU symbolic-per-column DFS. Core of our unsymmetric path. Applied: §19.2 (G–P), I8.
  • Amestoy, Davis & Duff, "An Approximate Minimum Degree Ordering Algorithm" (SIMAX 1996) — the workhorse ordering. Applied: §15.2 (amd), ADR-11.
  • Liu, "The role of elimination trees in sparse factorization" (SIMAX 1990) — etree theory, the backbone of symbolic. Applied: §16.2 (etree), I5/I6.
  • George, "Nested dissection of a regular finite element mesh" (SIAM J. Numer. Anal. 1973) — the asymptotically optimal ordering. Applied: §15.2 (ND), §8.10, P4.
  • Gustavson, "Two fast algorithms for sparse matrices: multiplication and permuted transposition" (TOMS 1978) — SpGEMM row-merge + transpose. Our SpGEMM. Applied: §14.2, ADR-7.
  • Bell & Garland, "Implementing sparse matrix-vector multiplication on throughput-oriented processors" (NVIDIA, SC 2009) — SpMV formats (ELL/HYB) + the bandwidth analysis. Applied: §13.2 (SpMV formats), §8.1, the Alternative-Architecture ELLPACK road (§38).
  • Williams, Oliker, Vuduc, Shalf, Yelick & Demmel, "Optimization of sparse matrix–vector multiplication on emerging multicore platforms" (SC 2007) — SpMV blocking, reordering, the roofline. Applied: §13.7, §4.1, the roofline mental model MM2 (§34).
  • Kreutzer, Hager, Wellein, Fehske & Bishop, "A unified sparse matrix data format for efficient general sparse matrix-vector multiplication on modern processors with wide SIMD units (SELL-C-σ)" (SISC 2014) — the SIMD-friendly format we implement. Applied: §13.2 (SELL-C-σ), ADR-15.
  • Davis, Rajamanickam & Sid-Lakhdar, "A survey of direct methods for sparse linear systems" (Acta Numerica 2016) — the modern map of the whole field. Applied: §8.7 (direct-vs-iterative), the Comparative Architecture table (§35).
  • Saad & Schultz, "GMRES: a generalized minimal residual algorithm for solving nonsymmetric linear systems" (SISC 1986) — the restarted Krylov method. Applied: §20.2 (gmres), ADR-13.
  • Buluç & Gilbert, "The Combinatorial BLAS: design, implementation, and applications" (IJHPCA 2011) — 2D-distributed SpGEMM / sparse-as-graph primitives. Applied: the Comparative Architecture CombBLAS row (§35) and the 2D-distributed Alternative Architecture (§38).
  • Vuduc, Demmel & Yelick, "OSKI: A library of automatically tuned sparse matrix kernels" (SciDAC/J. Phys. Conf. 2005) — runtime autotuning / register blocking of SpMV. Applied: §22.2 (auto-format), §24.2 (tuning), the OSKI row in §35.

5.3 Reference Implementations

  • SuiteSparse / CSparse (Tim Davis, Texas A&M) — cs_* functions; read cs_lu, cs_chol, cs_amd, cs_etree, cs_sqr. Study; do not copy. Lesson: minimal, complete sparse algorithms. Pitfall: terse C, unchecked indices. Applied: §16, §17, §19; the C-vs-Rust contrast in ADR-1.
  • CHOLMOD (SuiteSparse) — supernodal Cholesky calling dense BLAS. Lesson: the supernode→BLAS bridge. Pitfall: huge; extract the supernodal idea only. Applied: §17.2 (left-looking supernodal), I7, ADR-9.
  • UMFPACK / KLU (SuiteSparse) — multifrontal / circuit-specialized LU. Lesson: unsymmetric strategies. Pitfall: multifrontal is deferred; we ship supernodal/G–P. Applied: §19 (LU), the circuit fixture (§5.5), the multifrontal Alternative Architecture (§38).
  • Eigen SparseCore / SparseCholesky — C++ formats + simplicial/supernodal. Lesson: API design. Pitfall: template depth. Applied: §11 (type design), §8.1, ADR-1.
  • scipy.sparse — format taxonomy + conversions (our format menu mirrors it). Lesson: the canonical format set + when to use each. Applied: §8.1 (format menu), §12.2 (conversions), ADR-3.
  • PETSc (KSP + PC) — iterative solver + preconditioner API. Lesson: solver/preconditioner composition. Applied: §20–§21, the PETSc row in §35.
  • Ginkgo (numerical-linear-algebra C++ library) — modern portable SpMV/SpTRSV with executor abstraction. Lesson: clean kernel/executor separation. Pitfall: GPU-first design we defer. Applied: §13 (SpMV), §18 (SpTRSV), §24.2 (GPU deferral), the Ginkgo row in §35.

Glossary (§40) · 50 terms · site-wide glossary

AMD
approximate minimum degree ordering.
Arithmetic intensity
flops/byte; SpMV ≈ 0.16 (bandwidth-bound).
Arnoldi
orthogonalization building the Krylov basis (GMRES).
Bandwidth (matrix)
max |i−j| over nonzeros; (memory) bytes/s moved.
BiCGSTAB
stabilized bi-conjugate gradient (general matrices).
BSR
block sparse row (CSR of small dense blocks).
CG
conjugate gradient (SPD only).
Cholesky
A = LLᵀ factorization (SPD).
CSR / CSC
compressed sparse row / column (CSC = CSR of Aᵀ).
COO
coordinate (triplet) format.
COLAMD
column approximate minimum degree (Q-ordering for unsymmetric LU; AMD on the column-intersection / AᵀA structure).
DIA
diagonal storage format (diagonals + offsets; for banded/stencil matrices).
Elimination tree (etree)
dependency tree of factorization columns; parent[j] > j.
Equilibration / scaling
row/column scaling (e.g. to unit ∞-norm) before factorization to reduce growth and improve conditioning.
ELL
ELLPACK padded format (uniform row length).
Extend-add
scatter of a supernode's update into its ancestors.
Fill-in
nonzeros created by factorization where A had zeros.
Frontal / update matrix
the dense submatrix a multifrontal method assembles and eliminates at an etree node; its Schur complement is the update passed to the parent.
Gilbert–Peierls
proportional-time left-looking sparse LU (DFS symbolic per column).
GMRES(m)
restarted generalized minimal residual.
Growth factor (ρ)
ratio of the largest entry magnitude arising during elimination to that of A; bounds the backward error of LU.
Gustavson
row-merge SpGEMM / permuted transpose.
IC(0) / ILU(0)
incomplete Cholesky / LU with no fill (A's pattern only).
ILUT
threshold incomplete LU (drop small entries, cap fill per row).
Krylov subspace
span{r, Ar, A²r, …}.
Level-3 fraction
share of numeric factorization flops done in dense BLAS (#349).
Manteuffel shift
a diagonal shift A + αI applied to make an incomplete Cholesky pivot positive (recovery for IC breakdown, I12).
Matrix Market (.mtx)
the corpus interchange format.
M-matrix
a matrix with non-positive off-diagonals and a non-negative inverse; IC(0)/ILU(0) are breakdown-free on M-matrices.
Multifrontal method
direct factorization organizing work into dense frontal matrices up an assembly tree (MUMPS/UMFPACK); deferred here (§38.3).
Nested dissection
separator-based ordering (asymptotically optimal mesh fill).
nnz
number of nonzeros.
Postorder
an etree traversal ordering that makes column counts and numeric factorization cache-friendly (§16.2).
Preconditioner
M ≈ A with M⁻¹ cheap; accelerates Krylov convergence.
Quotient graph
the compressed graph representation AMD uses so degree updates are near-linear (element absorption, mass elimination).
RCM
reverse Cuthill–McKee (bandwidth/profile reduction).
Relaxed supernode
merge near-identical structures (extra fill) for bigger dense blocks.
Roofline
the (arithmetic-intensity, attainable-FLOP/s) performance model; SpMV sits left of the ridge (bandwidth-bound).
Schur complement
the trailing-block update D − C A⁻¹ B left after eliminating a block; the quantity scattered in extend-add.
SELL-C-σ
sliced ELLPACK, SIMD-friendly, σ-sorted rows.
Separator
a vertex set whose removal disconnects the graph; ordered last in nested dissection.
Skeleton
the reduced set of row-subtree edges used to compute exact column counts efficiently (§16.2).
SPA
sparse accumulator (dense scratch for row-merge).
STREAM
the standard sustainable-memory-bandwidth benchmark; the SpMV roofline ceiling is derived from it (M1).
SpGEMM / SpMM / SpMV
sparse×sparse / sparse×dense / sparse×vector products.
SpTRSV
sparse triangular solve (level-scheduled).
SPD
symmetric positive-definite.
Supernode
consecutive columns with nested structure → a dense block.
SuiteSparse
the standard sparse codebase + matrix collection.
Symbolic factorization
computing the exact fill pattern before any numeric value.
