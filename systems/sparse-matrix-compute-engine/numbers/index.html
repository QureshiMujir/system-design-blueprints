Assumptions: shared-memory multicore; matrices fit in RAM (out-of-core deferred); index arrays sorted within rows (canonical CSR); reuse of #349 for dense blocks; SuiteSparse corpus available for conformance.

4.1 Worked SpMV roofline (why the headline target is bandwidth, not FLOPs)

  • Bytes per nonzero (CSR, f64, i32 index): val 8 B + colind 4 B = 12 B streamed, plus one x[colind] gather (4–8 B, cache-dependent), plus amortized rowptr (≈ 0). Call it ≈ 12–16 B/nz.
  • Flops per nonzero: 1 multiply + 1 add = 2.
  • Arithmetic intensity: 2 / 12 ≈ 0.17 flop/byte → far left of the roofline ridge → bandwidth-bound.
  • Achievable SpMV rate: STREAM_bandwidth / bytes-per-nz. At 40 GB/s and 12 B/nz ⇒ ≈ 3.3 G-nz/s ⇒ ≈ 6.6 GFLOP/s — orders of magnitude below the f64 FLOP peak (#349 ≈ 56 GFLOP/s/core).
  • Implication: the §4 SpMV target is "≥ 80 % of bandwidth/bytes-per-nz," never "% of FLOP peak." Every SpMV optimization (format, reordering for x-locality, index compression) targets bytes moved, not arithmetic. This is the central contrast with #349 GEMM.

4.2 Worked memory budget (why index width and fill matter)

  • CSR footprint: nnz·(8 + idx) + (n+1)·idx bytes (idx = 4 for i32, 8 for i64). For nnz=10⁸, i32: ≈ 1.2 GB; i64: ≈ 1.6 GB — index width is ~25 % of memory at high nnz (motivates i32 default, i64 only when needed, I14).
  • Factor footprint: nnz(L) dominates and is ordering-dependent. On a 3D mesh, natural ordering gives nnz(L) ≈ O(n^{5/3}), nested dissection ≈ O(n^{4/3}) — for n=10⁶ that is the difference between ~tens of GB (OOM) and a few GB (fits).
  • Symbolic predicts this exactly (I4): the engine reports predicted factor memory before numeric, so a too-large factorization can be rejected and the solve switched to iterative (O(nnz) memory) — the direct-vs-iterative decision is a memory decision as much as a flop decision.
  • SpGEMM: output size is unknown a priori → the symbolic count pass sizes C exactly (no over-allocation, no realloc).

36. Back-of-Envelope Capacity Model

Numbers an expert computes before designing, each derived from the System Constraints (§4) and the worked roofline/budget (§4.1/§4.2). T = scalar bytes (8 for f64), idx = index bytes (4 for i32).

  • C1 — CSR footprint. bytes = nnz·(T + idx) + (nrows+1)·idx. For nnz=10⁸, f64, i32: 10⁸·12 + (10⁶+1)·4 ≈ 1.20 GB + 4 MB ≈ 1.2 GB. (Matches §4.2.)
  • C2 — i32 vs i64 index tax. i64 makes it nnz·16 + …: 10⁸·16 ≈ 1.6 GB. Delta = nnz·4 ≈ 400 MB ≈ 25 % more — the reason i32 is the default (I14, ADR-4).
  • C3 — SpMV bytes per nonzero. T(val) + idx(colind) = 8 + 4 = 12 B streamed + one x[colind] gather (4–8 B, cache-dependent) ⇒ ≈ 12–16 B/nz. (§4.1.)
  • C4 — SpMV arithmetic intensity. AI = 2 flops / 12 B ≈ 0.17 flop/byte ⇒ far left of the roofline ridge ⇒ bandwidth-bound. (§4.1, MM2.)
  • C5 — Achievable SpMV rate (roofline). rate = STREAM_BW / bytes-per-nz. At 40 GB/s, 12 B/nz: 40e9 / 12 ≈ 3.3 G-nz/s ⇒ ×2 flops ≈ 6.6 GFLOP/s — orders below f64 FLOP peak. The §4 headline target M1 is 0.8 × 3.3 ≈ 2.6 G-nz/s.
  • C6 — Cache lines touched per SpMV row. A row of r nonzeros touches ⌈r·12/64⌉ lines for vals+colind (contiguous) plus up to r separate lines for the x-gather (one per distinct cache line of x hit). Gather lines dominate when x does not fit in cache — the locality lever (MM5).
  • C7 — x/y vector cost. Dense vectors are nrows·T each: 10⁶·8 = 8 MB per vector — bigger than L2, so x reuse across rows depends on column-index locality (why RCM helps, §22).
  • C8 — Factor fill, 2D 5-point Laplacian (n=k²). Natural ordering: nnz(L) ≈ n·k = n^{1.5}; ND: nnz(L) ≈ O(n log n). For k=1000 (n=10⁶): natural ≈ 10⁹ nonzeros (×12 B ≈ 12 GB); ND ≈ ~2×10⁷ (×12 B ≈ 0.24 GB) — the ≥10× M4 target made concrete (§8.10).
  • C9 — Factor fill, 3D 7-point (n=k³). Natural ≈ O(n^{5/3}); ND ≈ O(n^{4/3}). For n=10⁶: natural ≈ 10^{10} (×12 B ≈ 120 GB, OOM on a workstation); ND ≈ 10^{8} (×12 B ≈ 1.2 GB, fits). This is why 3D forces ND-or-iterative (MM6, §4.2).
  • C10 — Direct factorization flops. ≈ Σ_j colcount[j]² (dense work per supernode). 2D natural ≈ O(n²); 2D ND ≈ O(n^{1.5}). At n=10⁶, ND ≈ 10⁹ flops ⇒ at 56 GFLOP/s/core (the §4.1 #349 figure) ≈ 18 ms/core if level-3 fraction is high (M7).
  • C11 — Iterative memory & cost. PCG memory ≈ O(nnz) + ~6 work vectors = nnz·12 + 6·n·8. For n=10⁶, nnz=5×10⁶: 60 MB + 48 MB ≈ 108 MB — vs C9's 120 GB direct: iterative is ~1000× lighter on 3D.
  • C12 — Iteration count. Unpreconditioned CG ≈ O(√κ) iterations; a 3D Poisson mesh has κ ≈ O(k²) = O(n^{2/3}), so ≈ O(n^{1/3}) iterations (≈ 100 at n=10⁶). IC(0) shrinks the constant; AMG (deferred, ADR-14) would make it O(1) — the asymptotic reason AMG is the un-defer target for huge elliptic problems.
