31. Mental Models & First Principles

MM1 — Politeness is a per-host serialization lock, not a global rate. Think of each host as a single-lane road: throughput is bounded by 1/crawl_delay regardless of how many workers you have. Predicts: adding workers never speeds up a single domain. Bug class without it: engineers "tune" worker count to crawl one slow site faster and get IP-banned. Applied: §15 scheduler, Invariant I1.

MM2 — The frontier is a database, not a queue. Durability, not ordering, is the hard part. Predicts: an in-memory queue is a toy; the real cost is fsync on the enqueue path. Bug class: "fast" in-memory frontiers lose the crawl on crash. Applied: §18, P2, Invariant I2.

MM3 — BFS is an emergent quality signal. High-PageRank pages are reachable in few hops from seeds, so shallow-first ordering surfaces quality early. Predicts: a next_fetch_at/depth-ordered frontier beats DFS on early page quality. Bug class: DFS crawlers tunnel into low-value link farms. Applied: §18 ordering, Najork & Wiener (§5), MM tie to What Mastery.

MM4 — Dedup is asymmetric: false negatives are fatal, false positives are free. Skipping an unseen URL costs one page; re-inserting a seen URL costs an infinite loop. Predicts: size the Bloom for an acceptable FP rate and guarantee zero FN by construction. Bug class: a "clever" optimization that occasionally drops an insert creates a re-crawl loop. Applied: §13, P6, Invariant I7.

MM5 — Importance can be computed online without the global graph. OPIC-style cash propagation approximates importance incrementally. Predicts: you can prioritize without a finished link graph. Bug class: blocking the crawl on a global PageRank pass. Applied: §11 score, OPIC (§5).

MM6 — Every remote byte is hostile until proven otherwise. Servers send malformed everything; redirects point inward. Predicts: parsers must be total and connectors must validate IPs. Bug class: a panic on a malformed header takes down the pool; an SSRF redirect exfiltrates internal services. Applied: §16/§17, Invariants I5, I8.

MM7 — Back-pressure must be end-to-end or it is nowhere. A bounded input channel with an unbounded output channel just moves the overflow. Predicts: you need bounded channels and separate select arms to avoid deadlock. Bug class: the coordinator-worker deadlock in §20.6 pitfall 1. Applied: §20.

MM8 — Storage is append-only so readers never need a lock. Immutability turns concurrency into a non-problem. Predicts: CDX indexers can read sealed WARCs while the crawl writes new ones. Bug class: mutating a sealed file corrupts in-flight readers. Applied: §19, P10, Invariant I10.

MM9 — DNS is the hidden bottleneck. At scale the stub resolver, not bandwidth, caps throughput (IRLbot, §5). Predicts: you must cache by TTL and resolve async. Bug class: synchronous resolution blocks the runtime and silently throttles the crawl. Applied: ADR-22, Scalability Analysis, Capacity Model.

RFCs and Specifications

  • RFC 9309 — Robots Exclusion Protocol (2022). The normative standard. Specifies path matching rules, User-agent group selection, Allow/Disallow precedence, Crawl-delay, and Sitemap directives.
  • RFC 3986 — Uniform Resource Identifier: Generic Syntax. URL normalization rules: scheme case-folding, percent-encoding normalization, default port removal, path dot-segment resolution.
  • RFC 7230–7235 — HTTP/1.1. All six documents covering message syntax, semantics, conditional requests, authentication, and range requests.
  • RFC 7540 — HTTP/2. Multiplexing, HPACK header compression, flow control — all relevant for efficient fetching.
  • RFC 6265 — HTTP State Management Mechanism (Cookies). Crawlers must parse Set-Cookie to follow session-scoped redirects.
  • RFC 2616 §14.31 — Max-Forwards and Via headers for proxy-awareness in the fetcher.
  • ISO 28500:2009 — WARC File Format. The normative archival storage standard; all WARC record types, header fields, and digest algorithms.
  • HTML Living Standard — WHATWG. Specifically the "parsing" and "tree construction" sections; html5ever implements this standard and deviating from it produces incorrect link extraction.
  • IANA Media Types Registry — Gate content-type matching against this registry, not a hardcoded list.
  • sitemap.org Protocol (0.9) — XML Sitemap format; Phase 1 seed ingestion reads sitemaps.

Glossary (§37) · 32 terms · site-wide glossary

ALPN
Application-Layer Protocol Negotiation. The TLS extension by which the fetcher negotiates HTTP/2 vs. HTTP/1.1 during the handshake.
Back-pressure
A flow-control mechanism where a slow consumer slows the producer; here, bounded mpsc channels block the coordinator when all workers are busy.
BFS
Breadth-first search. The crawl traversal order that visits all depth-1 pages before depth-2 pages; empirically yields higher-quality pages than DFS.
Bloom filter
A space-efficient probabilistic data structure that tests set membership. Zero false negatives; configurable false positive rate.
CDX index
Content Data eXchange index. A line-oriented text index of WARC records, enabling fast lookup by URL or timestamp.
Consistent hashing
A distributed hashing scheme that maps keys to nodes such that re-sharding requires moving only K/N keys on average. Used in Phase 1 for domain-to-node assignment.
OPIC
Online Page Importance Computation. An incremental alternative to PageRank for crawl prioritization that needs no completed global link graph.
SSTable
Sorted String Table. The immutable on-disk file produced by an LSM-tree (RocksDB) during memtable flush and compaction.
Crawl-delay
A directive in robots.txt specifying the minimum delay in seconds between successive requests to the domain.
Crawl frontier
The set of discovered but not-yet-fetched URLs. Also called the "URL queue" or "work queue".
DashMap
A concurrent HashMap implementation in Rust using sharded RwLocks. Used for the robots cache and domain scheduler state.
Domain affinity
The property that all fetches for a given domain are processed by the same worker or coordinator node. Enables per-domain rate limiting without cross-worker synchronization.
Double-hashing
A technique for generating k independent hash values from two base hash values: h_i(x) = h1(x) + i * h2(x). Used to implement the Bloom filter efficiently.
HPACK
Header compression algorithm used in HTTP/2. Reduces header overhead for repeated requests to the same server.
Idempotency
A property of an operation such that applying it multiple times has the same effect as applying it once. URL normalization must be idempotent.
IDN
Internationalized Domain Name. Domain names containing non-ASCII characters, encoded as Punycode in DNS.
LSM-tree
Log-structured merge-tree. The storage engine underlying RocksDB and LevelDB. Optimizes for write throughput by buffering writes in memory and merging to disk in batches.
mmap
Memory-mapped file. A mechanism that maps a file's contents into the process's virtual address space, enabling byte-level access without explicit read/write syscalls.
Near-duplicate
Two web pages with substantially identical content but minor differences (formatting, timestamps, ad variations). Detected using SimHash.
Percent-encoding
The encoding of special characters in URLs as %XX where XX is the hexadecimal ASCII code. Also called URL encoding.
Politeness
The property of a web crawler that respects server-imposed rate limits, robots.txt directives, and crawl delays.
REP
Robots Exclusion Protocol. The standard governing robots.txt syntax and semantics. Formalized in RFC 9309 (2022).
SSRF
Server-Side Request Forgery. An attack where a crawler is manipulated into fetching internal network resources by returning redirect responses to internal IP addresses.
SimHash
A locality-sensitive hashing algorithm that produces a 64-bit fingerprint of a document such that similar documents have similar fingerprints (low Hamming distance).
Shingling
The process of generating overlapping N-gram subsequences (shingles) from a document for use in SimHash or MinHash computation.
Token bucket
A rate-limiting algorithm that allows bursts up to the bucket capacity and refills at a constant rate. Used for per-domain fetch rate limiting.
WARC
Web ARChive format. An ISO standard (28500:2009) for storing crawled web content. Each WARC file contains one or more WARC records.
WriteBatch
A RocksDB API for grouping multiple write operations into an atomic batch. Ensures that enqueue operations are written atomically to multiple column families.
User-Agent
An HTTP header field identifying the requesting client. The crawler declares itself honestly as MujirBot/1.0 (+https://github.com/mujirq/web-crawler).
URL canonicalization
The process of converting a URL into a standard form (normalized URL) to ensure equivalent URLs are treated as identical.
Redirect chain
The sequence of URLs traversed when following HTTP 3xx redirects. Recorded for WARC provenance and loop detection.
Column family
A RocksDB concept equivalent to a "table" — an independent namespace within a single RocksDB database with its own memtable and SST files.
