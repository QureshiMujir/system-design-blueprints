Box explanations:

  • CLI / Coordinator: The crawl binary and the single-node coordinator struct. Reads configuration (TOML), injects seed URLs into the frontier, starts the scheduler loop, spawns the metrics server, and handles SIGTERM for graceful shutdown.
  • URL Frontier: The heart of the crawler. A priority queue (min-heap by next_fetch_at timestamp) backed by RocksDB for durability. Stores URL records with associated metadata: depth, score, domain, last-seen, crawl status. Dequeues are domain-affine: the scheduler only pulls a URL from domain D when domain D's token bucket has a token.
  • Scheduler / Dispatcher: Maintains one token bucket per active domain. Respects Crawl-delay from robots.txt. Assigns fetches to workers using a domain-to-worker shard map (consistent hash in Phase 1; round-robin in Phase 0). Prevents a fast domain from starving slow ones by interleaving.
  • Fetcher Pool: N async workers, each with a private hyper connection pool. Workers are long-lived; they do not spawn per-fetch tasks. Each worker receives a FetchTask from the scheduler, executes the HTTP fetch, and returns a FetchResult on a channel.
  • Robots Cache: A concurrent DashMap<Host, RobotsRecord> with TTL-based expiry. On a cache miss, the fetcher fetches /robots.txt (obeying a 10-second timeout), the robots parser evaluates it, and the result is stored. A domain blocked by robots.txt is demoted in the frontier, not dropped (in case robots.txt changes).
  • Response Handler: Validates HTTP status codes, gates on Content-Type: text/html, follows redirects (up to max_redirects), decodes character sets (UTF-8 default, ISO-8859-1 via charset parameter), and hands the response body to both the WARC writer and the HTML parser.
  • HTML Parser: Uses html5ever for spec-compliant parsing. Extracts all outbound links, resolves relative URLs against the document base URL (accounting for <base href>), and emits a Vec<Url> for the dedup engine.
  • WARC Writer: Appends application/http; msgtype=response WARC records to rotating .warc.gz files. Each record has a WARC-Record-ID, WARC-Date, WARC-Target-URI, Content-Length, and a SHA-256 WARC-Block-Digest. Rotation triggers at 1 GB or 100k records.
  • Dedup Engine: Two-stage: (1) exact-URL Bloom filter — sub-microsecond lookup, ~1% false positive rate at 100M URLs with 10 bits/element; (2) SimHash — 64-bit fingerprint of content tokens, Hamming-distance threshold of 3 bits for near-duplicate detection. URL normalization (lowercase host, sort query params, strip fragment, remove default port) runs before Bloom lookup.
  • Storage Layer: Three on-disk structures: WARC files (compressed raw pages), SQLite (crawl metadata: URL, fetch timestamp, status, content hash, depth, outlink count), and the serialized Bloom filter (MMapped binary file, reloaded on restart).

robots.txt Semantics

The REP (RFC 9309) defines the following evaluation rules, all of which the robots crate implements:

  1. Group selection: Select all groups where User-agent matches the crawler's declared agent (case-insensitive). Fall back to User-agent: * if no specific match.
  2. Rule precedence: Among matching Allow and Disallow rules, the longest matching prefix wins. If equal length, Allow wins.
  3. Path encoding: Paths in robots.txt are URL-encoded. The crawler's request path must be compared after percent-decoding both sides.
  4. Crawl-delay: If present, the crawler must wait at least Crawl-delay seconds between successive requests to the same host. This is the per-domain token bucket interval.
  5. Sitemap: A hint to the crawler that the domain has a sitemap. Phase 1 ingests these.

Example robots.txt evaluation:

User-agent: *
Disallow: /private/
Allow: /private/public.html
Crawl-delay: 2

User-agent: MujirBot
Allow: /
Crawl-delay: 5

For User-agent: MujirBot fetching /private/secret.html: the MujirBot group matches; the only rule is Allow: /; result: allowed. Crawl-delay: 5 seconds.

For User-agent: Googlebot (no matching group) fetching /private/secret.html: fall back to * group; Disallow: /private/ (length 9) beats Allow: /private/public.html (length 22) — wrong; correct evaluation: Allow: /private/public.html is 22 chars, Disallow: /private/ is 9 chars; the Allow rule (22) is longer and matches; result: allowed for /private/public.html; but for /private/secret.html, only Disallow: /private/ matches (the Allow rule does not); result: disallowed.

SimHash Algorithm Sketch

Given a document body:

  1. Tokenize into 3-shingles (overlapping trigrams of words).
  2. For each shingle, compute a 64-bit hash (SipHash-1-3).
  3. For each of the 64 bit positions, maintain a running integer counter.
  4. For each shingle's hash, for each bit: if bit is 1, add +1 to counter; if bit is 0, add -1.
  5. Final SimHash: bit i = 1 if counter[i] > 0, else 0.
  6. Two documents are near-duplicates if popcount(hash_a XOR hash_b) <= 3.
