3.2 Subsystem Descriptions

tss-cli. Entry point for all human interaction and integration testing. Parses subcommands, constructs ThresholdParams, instantiates simulated participant objects, drives protocol rounds in sequence, serializes/deserializes shares and signatures. No cryptographic logic; delegates entirely to library crates. Trust boundary: untrusted CLI input; all inputs are validated by library types before use. No persistent state between runs unless the caller supplies key files.

tss-shamir. Implements split (sample a random degree-(t-1) polynomial with coeffs[0] = secret, evaluate at n distinct non-zero ShareIds via Horner's method) and reconstruct (Lagrange interpolation at x=0 over any t distinct shares). The dealer's polynomial and all intermediate evaluations are zeroized after use. Data flow in: (secret: Scalar, params: ThresholdParams, rng); data flow out: Vec<Share>. Reconstruction in: Vec<Share> (length ≥ t); out: Scalar. No I/O; no EC operations. Trust boundary: the caller is responsible for secure share distribution; this crate is purely algebraic.

tss-vss. Lifts the plain Shamir sharing into the group to enable public verifiability. Feldman: dealer publishes Commitment = Vec<Point> where C_j = g^{a_j}; recipient verifies g^{s_i} == product C_j^{i^j}. Pedersen: dealer publishes PedersenCommitment = Vec<Point> where C_j = g^{a_j} h^{b_j} using a secondary blinding polynomial; recipient verifies with both sub-shares. Data flow in (verify): (Share, Commitment, params); out: Result<(), VssError>. Dependency: tss-group for EC ops, tss-field for exponent arithmetic. Feldman is binding but not hiding (g^secret is exposed in C_0); Pedersen is both.

tss-dkg. Each of n parties acts as a Pedersen VSS dealer and broadcasts their commitments and encrypted sub-shares. Each party verifies received sub-shares, broadcasts complaints for invalid ones; the qualified set is the set of dealers whose shares passed all verifications. Each party's final KeyShare.secret_share = sum of received sub-shares from qualified dealers. KeyShare.group_public = sum of C_0 commitments from qualified dealers. No party ever holds or computes the joint secret scalar. State machine transitions: DkgRound::Commit → Share → Complaint → Finalize. Trust boundary: authenticated but potentially Byzantine peers; complaint round provides identifiable abort.

tss-schnorr / FROST. Two-round threshold Schnorr per RFC 9591. Round 1: each signer samples hiding nonce d_i, binding nonce e_i, publishes NonceCommitment = (D_i = g^{d_i}, E_i = g^{e_i}). Binding factor: rho_i = H(i, msg, commitment-list). Group nonce: R = sum(D_i + rho_i * E_i). Round 2: each signer computes PartialSignature z_i = d_i + rho_i*e_i + lambda_i*share_i*c where c = H(R, Y, msg) and lambda_i is its Lagrange coefficient over the signing set. Aggregate: z = sum(z_i). Verify: g^z == R * Y^c. Partial-sig verification enables identifiable abort before aggregation. Nonces d_i, e_i are zeroized immediately after use.

tss-bls. Each signer computes PartialSignature sigma_i = H(m)^{share_i} (hash-to-curve, then scalar mul with the share scalar). Aggregation: sigma = prod(sigma_i^{lambda_i}) where lambda_i is the Lagrange coefficient for signer i over the signing set — equivalent to H(m)^{secret} by linearity of the exponent. Verify: e(sigma, g) == e(H(m), Y) via bilinear pairing. The pairing backend is a declared dependency (e.g., bls12_381 crate); if unavailable, the verify step is gated behind PhaseDeferred("Phase 11"). Partial signature verification: e(sigma_i, g) == e(H(m), Y_i) where Y_i = g^{share_i} from the DKG public share.

tss-proactive. Periodic refresh: each party i samples a fresh degree-(t-1) polynomial r_i with r_i(0) = 0 (zero constant term), VSS-deals it, and sends sub-shares to all parties. Each party j's refreshed share = old_share_j + sum(r_i(j)). The joint secret is unchanged (sum of zero-constant-term polynomials adds zero). Lost-share recovery: a party with no share requests Lagrange interpolation assistance from t other parties; those parties each compute and send lambda_i * share_i (blinded by the refresh); recipient reconstructs. All intermediate values are zeroized. Epoch boundary: refresh must complete before the next epoch begins; partial refresh is not accepted.

tss-field + tss-group. Foundation layer. tss-field: constant-time F_p with explicit rejection of zero-inverse, prime = curve scalar order. All operations use the subtle crate for conditional assignment; no secret-dependent branching. tss-group: wraps a prime-order EC group (reusing portfolio #90 curve25519-dalek or equivalent); exposes scalar_mul(Point, Scalar) → Point, point_add, generator() → Point, alt_generator() → Point (independent h for Pedersen), hash_to_scalar, hash_to_point. Neither crate performs I/O or protocol logic.

tss-protocol. Typed message envelopes: each round message carries sender ShareId, round tag, and serialized payload. Transcript: a running hash of all public values broadcast (commitments, nonces, partial sigs) in canonical order; used to bind the protocol session and prevent replay. Identifiable abort: if a partial signature or VSS share fails verification, the transcript + evidence is retained and the bad actor's ShareId is recorded. Round orchestration: drives a Vec<Box<dyn ParticipantState>> through rounds, collecting messages and dispatching them, without performing any cryptographic operations itself.

8.3 DKG State Machine

States: Init → Commit → Share → Complaint → Finalize → Done | Aborted

Transitions:
  Init        --[broadcast VSS commitments]-->    Commit
  Commit      --[all n commitments received]-->   Share
  Share       --[distribute encrypted shares]-->  Complaint
  Complaint   --[verify all shares; flag bad]--> Finalize  (qualified set agreed)
  Complaint   --[too few honest parties]-------> Aborted
  Finalize    --[sum sub-shares; derive key]---> Done

ASCII state table:

Current State Trigger Next State Side Effect
Init party broadcasts VSS commitment Commit store own Pedersen commitment
Commit all n commitments received Share send encrypted shares to each party
Share receive n-1 shares Complaint verify each share; queue complaints
Complaint broadcast complaint list Finalize disqualify accused if complaint valid
Complaint honest set < t Aborted error: insufficient qualified parties
Finalize all rounds settled Done compute KeyShare; derive group_public
Done — Done terminal; key is live
Aborted — Aborted terminal; restart required

8.3.1 DKG Complaint Resolution Detail

When party j sends a complaint against dealer i:

  • j reveals the blinding value r_ij from the Pedersen share pair (s_ij, r_ij)
  • All parties verify: g^{s_ij} * h^{r_ij} == prod_k C_k^{id_j^k}
  • If the equation fails: dealer i is disqualified; i is excluded from qualified set
  • If the equation holds: j is the liar; j is disqualified
  • Result: at most one of {i, j} joins the qualified set

Qualified set Q formed after complaint round:

  • Q = {parties that (a) broadcast a valid commitment, (b) sent valid shares to all recipients, (c) received no upheld complaint}
  • Finalization proceeds only if |Q| >= t; otherwise abort

8.4 FROST Two-Round Signing State Machine

States: Idle → Round1 → Round2 → Signed | SignAborted

  Idle      --[sign request; pick signing set S, |S|=t]-->  Round1
  Round1    --[each signer samples (d_i,e_i); publish (D_i,E_i)]-->  Round2
  Round2    --[compute rho_i, c, z_i; publish z_i]-->  Signed (if all valid)
  Round2    --[invalid partial sig detected]-->  SignAborted (identifiable abort)

Transition table:

State Actor Input Output Guard
Idle Coordinator sign(msg, signing_set) Round1 init msg
Round1 Each signer sign request NonceCommitment(D_i, E_i) fresh nonces only
Round2 Coordinator all D_i,E_i binding_factor list + c all n commitments present
Round2 Each signer binding factors + c PartialSignature z_i verify own NonceCommitment
Signed Coordinator all z_i valid AggregateSignature(R,z) partial verify passes for all i
SignAborted Coordinator z_i fails verify error(bad_signer: id) identifiable abort

8.4.1 Binding Factor Derivation (FROST, RFC 9591 §4.3)

commitment_list = encode_group_commitment_list(S, {(id_i, D_i, E_i) for i in S})
  -- sorted by id_i, big-endian; length-prefixed

for each i in S:
  rho_i = H1(i || commitment_list)    -- H1 = SHA-512 domain-separated
  -- rho_i binds party i's nonce to the full commitment set and signing group

R_i = D_i + rho_i * E_i               -- per-signer effective nonce point
R   = sum_{i in S} R_i                 -- group nonce

c   = H2(R || group_public || msg)     -- challenge scalar

This construction prevents the Drijvers et al. attack: an adversary cannot grind rho_i without knowing the full commitment set, which is fixed before any partial signature is computed.

8.4.2 Partial Signature Verification (identifiable abort)

Before aggregation, coordinator verifies each z_i:

for i in S:
  R_i_check = z_i * g - c * lambda_i * public_share_i - rho_i * (D_i, E_i terms)
  -- precise form per RFC 9591 sec. 5.3
  assert R_i_check == R_i     (fail → identifiable abort for party i)

Passing individual checks guarantees the aggregate will verify; skipping exposes the coordinator to a denial-of-service from a single malicious signer.

8.5 BLS Partial-Sign and Aggregate Sequence

Signing set S ⊆ parties, |S| = t:

  for i in S:
    sigma_i = H(msg)^{share_i}         -- partial sig (Point)
    verify: e(sigma_i, g) == e(H(msg), public_share_i)  -- optional pre-aggregate check

  Lagrange coefficients lambda_i over {x_j : j in S} at x=0 (exact field arithmetic)
  sigma = prod(sigma_i^{lambda_i})      -- aggregate in group (Lagrange exponent interpolation)

  Verify: e(sigma, g) == e(H(msg), group_public)

8.5.1 BLS Pairing Verification Detail

Pairing check: e(sigma, g2) == e(H(m), pk)
  where e: G1 x G2 -> GT (bilinear map over BLS12-381)
        sigma in G1 = aggregated BLS point
        g2 in G2 = fixed generator
        H(m) in G1 = hash-to-curve output
        pk in G2 = group_public (joint key)

Sub-group membership check required on all G1/G2 inputs before pairing. An invalid point (not in prime-order subgroup) gives wrong pairing output silently; always check.

8.6 Polynomial Evaluation and Lagrange Reconstruction

EBNF for the sharing procedure:

split(secret: Scalar, t: usize, n: usize) -> Vec<Share>
  coeffs[0] = secret
  coeffs[1..t-1] = sample_random_scalars(t-1)   // CSPRNG, zeroize after
  for id in 1..=n:
    share_value = horner_eval(coeffs, Scalar::from(id))  // f(x) = c0 + c1*x + ... + c_{t-1}*x^{t-1}
    shares.push(Share { id: ShareId(id), value: share_value })
  zeroize(coeffs)

reconstruct(shares: &[Share]) -> Result<Scalar>
  // require: shares.len() >= t; all ids distinct; each id != 0
  result = 0
  for i in shares:
    lambda_i = prod_{j != i} ( (0 - x_j) / (x_i - x_j) )  in F_p  // exact, constant-time
    result += lambda_i * share_i.value
  return result   // = f(0) = secret

Worked example (t=2, n=3):

Step Value
secret 42 (mod p)
random c_1 7
poly f(x) = 42 + 7x
Share(1) f(1) = 49
Share(2) f(2) = 56
Share(3) f(3) = 63
reconstruct(S1,S2) lambda_1=(0-2)/(1-2)=2; lambda_2=(0-1)/(2-1)=-1; 249-156=42
reconstruct(S1,S3) lambda_1=(0-3)/(1-3)=3/2; lambda_3=(0-1)/(3-1)=-1/2; = 42

Failure-path example — fewer than t shares:

Input Outcome
t=3, shares=[S1,S2] (only 2) Error::InsufficientShares(have=2, need=3)
duplicate ids [S1,S1,S3] Error::DuplicateShareId(id=1)
id=0 in share Error::ZeroShareId
value out of range Error::InvalidScalar
tampered share (fails VSS) Error::CommitmentMismatch(id=i)

8.6.1 Lagrange Coefficient Computation (constant-time)

lambda_i(S) = prod_{j in S, j != i} (0 - x_j) * inv(x_i - x_j)  mod p

CT requirements:
  - All multiplications: standard field mul (CT)
  - inv(x_i - x_j): Fermat: a^{p-2} mod p (CT exponentiation) or const-time ext-gcd
  - No early exit on zero difference (that case is an error, checked beforehand)
  - No branching on any coefficient value

Pitfall: if any x_i == x_j (duplicate ids), the denominator is zero. This MUST be detected before entering Lagrange computation and rejected with DuplicateShareId. Do not rely on field inverse returning zero for the zero input — reject explicitly.

8.6.2 Horner Evaluation

f(x) = c[0] + x*(c[1] + x*(c[2] + ... + x*c[t-1]))

Horner loop (degree t-1, n evaluations):
  for id_i in 1..=n:
    val = c[t-1]
    for j in (0..t-1).rev():
      val = val * x_i + c[j]   -- each mul/add: F_p constant-time
    shares[i] = Share { id: ShareId(id_i), value: val }

Cost: O(t) field ops per share; O(n*t) total. For t=10, n=20: 200 field multiplications.

8.7 Feldman VSS Layout

Dealer publishes: Commitment = [C_0, C_1, ..., C_{t-1}] where C_j = g^{a_j}

Recipient i verifies share s_i:
  lhs = g^{s_i}
  rhs = prod_{j=0}^{t-1} C_j^{(id_i)^j}   in the group
  assert lhs == rhs  (fail → CommitmentMismatch)

Wire layout (Feldman VSS message):

Offset Size Field
0 4 dealer_id (u32 LE)
4 4 t (u32 LE)
8 t*33 commitment points (compressed, ordered j=0..t-1)

8.8 Pedersen VSS Layout

Dealer publishes: PedersenCommitment = [C_0, ..., C_{t-1}] where C_j = g^{a_j} * h^{b_j}
Dealer sends to recipient i: (s_i, r_i) — main share and blinding share

Verify: g^{s_i} * h^{r_i} == prod_{j=0..t-1} C_j^{id_i^j}
Offset Size Field
0 4 dealer_id
4 4 t
8 t*33 commitment points
8+t*33 32 s_i (encrypted to recipient)
8+t*33+32 32 r_i (encrypted blinding)

8.12 Wire/Serialization Format

All types serialized with canonical little-endian encoding (no padding, no versioning except explicit version byte at message header):

Message header (every network message):
  [0]     u8   version = 1
  [1]     u8   message_type (enum tag)
  [2..5]  u32  payload_len LE

8.13 Storage / Key-Share File Format

KeyShare file (tss-cli export): CBOR or binary sequential layout

  [0..3]   magic  = 0x54535348  ("TSSH")
  [4]      version = 1
  [5..8]   share_id (u32 LE)
  [9..40]  secret_share (Scalar, 32 bytes)
  [41..73] public_share (Point, 33 bytes)
  [74..106] group_public (Point, 33 bytes)
  [107..110] t (u32 LE)
  [111..114] n (u32 LE)
  [115..]  optional AEAD envelope (ChaCha20Poly1305, 12-byte nonce + tag)

Share files at rest: AEAD-encrypted with caller-supplied key; authenticated tag covers all fields.

8.13.1 Share File Access Semantics

  • Read: decrypt AEAD envelope, validate magic+version, deserialize fields, check public_share == g^secret_share
  • Write: serialize, AEAD-encrypt with caller key + random nonce, write atomically (write to .tmp, fsync, rename)
  • Share files must never be logged or printed; CLI uses Display trait that redacts secret_share to [redacted]
  • Multiple shares for the same group: distinct files distinguished by share_id; no combined file

8.14.1 Zeroization Sequence (FROST signing session lifecycle)

1. Round1: sample (d_i, e_i) from OsRng
2. Compute D_i = d_i*g, E_i = e_i*g; publish (D_i, E_i)
3. Round2: receive binding factors + challenge c
4. Compute z_i = d_i + rho_i*e_i + lambda_i*share_i*c
5. IMMEDIATELY after step 4: zeroize(d_i); zeroize(e_i)
   -- do NOT keep nonces alive past their use; leaked nonce reveals share_i
6. Publish z_i; clear z_i from memory after coordinator confirms receipt

Critical: nonce d_i must never be used for two different messages. Nonce reuse in Schnorr exposes the signing share via z_i - z_i' = d_i*(msg-msg') terms cancel, revealing share_i*c difference. The FROST transcript binds (D_i, E_i) to the specific message; reuse detection via transcript uniqueness.

8.16 Proactive Refresh Domain Model

Epoch-based refresh changes all shares without changing the secret:

Refresh protocol (parties P_1..P_n, current threshold t):
  Each party i:
    1. Sample zero-polynomial z_i(x): degree t-1, z_i(0) = 0, random higher coeffs
    2. Run Feldman VSS on z_i: publish commitments A_ij = g^{z_ij_coeff}
    3. Send sub-share z_i(x_k) to each party k
  Each party k:
    4. Verify received sub-shares against Feldman commitments
    5. New share: share_k' = share_k + sum_{i in qualified} z_i(x_k)
    6. New public: group_public unchanged (sum of zero-polys' constant terms = 0)
    7. Zeroize share_k and all z_i(x_k) sub-shares

Key properties:

  • share_k' interpolates to the same secret at x=0 (sum of zero-polys has zero constant term)
  • An adversary who corrupted t-1 parties in epoch e and t-1 different parties in epoch e+1 still cannot reconstruct the secret (no overlap in epoch, sub-threshold each)
  • I8 invariant: reconstruct(new_shares) == secret

Lost share recovery:

  • Party j missing its share can receive t valid shares from honest parties
  • Honest parties interpolate a sub-polynomial sharing of share_j over a fresh t-of-t scheme
  • j assembles t sub-shares, sums them to recover share_j
  • Recovery requires t willing parties; they reveal nothing about the secret (only about share_j, which j already holds legitimately)
