⬜ Phase 1 — Core Types + Prime-Field Arithmetic

Objectives
  • Establish tss-core and tss-field as the foundation crates; all other crates depend on them.
  • Define canonical types: Scalar, FieldElement, ShareId, Share, Polynomial, ThresholdParams.
  • Implement constant-time F_p: add, sub, mul, inv (Fermat's little theorem or extended-GCD); enforce I9.
  • Provide a secure CSPRNG wrapper (SecureRng) that sources from OsRng; expose sample_scalar().
  • Enforce ThresholdParams validity: reject t=0, t>n, n=0 at construction time (I10, P10).
  • Property-test field axioms: associativity, commutativity, identity, inverse, Fermat's identity.
Deliverable
  • cargo test -p tss-core -p tss-field passes with zero failures.
  • Property tests exercise 1000+ random field element triples per axiom.
  • Scalar drops zero its memory on scope exit (verified by valgrind/miri).
  • ThresholdParams::new(0,5), new(6,5) both return Err(InvalidThreshold).

⬜ Phase 6 — Feldman VSS

Objectives
  • Implement Feldman VSS in tss-vss: dealer publishes commitments C_j = g^{a_j} for each polynomial coefficient a_j; recipients verify shares via g^{s_i} == prod_{j=0}^{t-1} C_j^{i^j}.
  • Commitments are binding (collision resistance of DLP) but NOT hiding: C_0 = g^secret is published, leaking g^secret to all parties.
  • Detect an inconsistent or malicious dealer: a recipient whose share fails the check can broadcast a complaint.

  • Rely on tss-group::GroupOps for all EC operations (I5, P2).
Deliverable
  • tss-vss compiles; commit and verify_share exported.
  • split_with_commitment API available in tss-shamir with Feldman integration.
  • Honest shares always verify; tampered share values fail verification.
  • Commitments serialize/deserialize round-trip.
  • cargo test -p tss-vss passes all positive and negative cases.

⬜ Phase 8 — distributed key generation (DKG)

Objectives
  • Implement tss-dkg: a multi-round DKG where every party acts as both dealer and recipient, no trusted dealer.
  • Each party i runs Pedersen VSS to deal a sub-secret s_i; distributes sub-shares to all parties.
  • Complaint round: parties broadcast complaints against dealers whose shares fail verification.
  • Qualified set: parties who receive no valid complaints advance; their constant-term commitments define the joint public key.
  • Final share for party i = sum of sub-shares from all qualified dealers; joint public key = sum of constant-term commitments C_{0,j} over qualified dealers.
  • Invariant I6: no single party learns the joint secret; I7: joint key aggregation is correct.
  • State machine type DkgRound drives protocol; tss-protocol will orchestrate in Phase 13.
Deliverable
  • tss-dkg compiles; DkgParty drives 4-round protocol for n simulated parties.
  • Honest run: all parties output matching group_public keys.
  • Complaint handling: bad dealer disqualified; honest majority produces valid joint key.
  • cargo test -p tss-dkg green.

⬜ Phase 9 — threshold Schnorr (FROST) round 1

Objectives
  • Implement tss-schnorr Round 1: nonce generation, commitment publication, and binding factor derivation per FROST (RFC 9591).
  • Each signer i samples two nonces (d_i, e_i), computes hiding/binding commitments (D_i, E_i) = (g^{d_i}, g^{e_i}).
  • Coordinator collects all (D_i, E_i) pairs into a commitment list; each signer derives per-signer binding factor rho_i = H("rho" || i || msg || commitment_list).
  • Compute group nonce R = sum_i (D_i + rho_i * E_i).
  • Thwarts rogue-nonce (Wagner/Drijvers) attacks: binding factors tie nonces to message and full commitment set.
  • Types: NonceCommitment, BindingFactor; functions: round1_commit, compute_binding_factors, compute_group_nonce.
Deliverable
  • tss-schnorr::round1 compiles; round1_commit, compute_binding_factors, compute_group_nonce callable.
  • RFC 9591 test vector for Round 1 passes.
  • Nonce values zeroized on drop.
  • cargo test -p tss-schnorr green (round 1 tests only; round 2 added in Phase 10).

⬜ Phase 10 — FROST Partial Signing + Aggregation

Objectives
  • Complete the FROST round-2 signing flow in tss-schnorr: partial signature computation, aggregation, final verification, and identifiable abort.
  • Each signing party i computes z_i = d_i + rho_i*e_i + lambda_i * share_i * c using its Lagrange coefficient lambda_i over the signing set S.
  • Aggregator sums z = sum_{i in S}(z_i) and outputs signature (R, z).
  • Final verification: g^z == R + c*Y where Y is the joint DKG public key, c = H(R, Y, msg).
  • Per-partial verification: g^{z_i} == D_i + rho_i*E_i + c*lambda_i*Y_i to identify a misbehaving signer before aggregation (I-abort).
  • Enforce RFC 9591 wire format for (R, z) and for PartialSignature; cross-reference spine type names throughout.
  • Constraints: |S| >= t; signer ids must be a subset of those who committed in round 1; nonces consumed exactly once.
Deliverable
  • partial_sign, aggregate, verify_aggregate compile; all RFC 9591 test vectors pass.

  • identify_culprit returns the injected bad signer's ShareId in the injected-fault test.
  • SignerState machine prevents nonce reuse; second partial_sign call returns Err(NonceAlreadyConsumed).
