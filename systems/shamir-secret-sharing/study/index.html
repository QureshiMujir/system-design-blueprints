Hard questions

  3. Explain why the Pedersen blinding polynomial b(x) must have a random b(0), not b(0) = 0. What security property is lost if b(0) = 0? Name the §P and §I that formalize this. (§P2 + §P3 + §I5 + Phase 7.6 pitfalls)

Mental Models & First Principles

These are the compressed insights an expert holds before writing a single line. Each entry names the bug class it prevents and the section of this blueprint where it is applied.

MM1 — A degree-(t-1) polynomial is uniquely fixed by any t points; t-1 or fewer points reveal nothing. Any t evaluations over a field uniquely determine the degree-(t-1) polynomial through them (Lagrange uniqueness theorem). Fewer than t evaluations leave one or more degrees of freedom, so every value in the field is equally likely as the constant term — information-theoretic perfect secrecy. Bug class without it: treating t-1 shares as "almost enough" and building a feature that hints at the secret when shares approach t. Applied in: §P1, §I1–I2, Phase 2–3, §8.6.

MM2 — The constant term is the secret; evaluation at x=0 is reconstruction. The sharing polynomial is f(x) with f(0) = secret. Share i = f(i). Lagrange interpolation at x=0 computes the polynomial's value at x=0 from any t distinct non-zero evaluations. The zero point is sacred and must never be a share ID. Bug class without it: using x=0 as a valid share ID, handing the secret directly to a party. Applied in: §I3, §I4, §8.6, Phase 2–3.

MM3 — Feldman commitments are binding but not hiding; Pedersen commitments add hiding. In Feldman VSS, the constant-term commitment is C_0 = g^secret. Every party sees g^secret. This is fine for share verification but catastrophic as a DKG round-1 broadcast because it leaks the sub-secret before the qualified set is determined. Pedersen adds a blinding polynomial so C_0 = g^{a_0} h^{b_0} — perfectly hiding under the discrete-log relation between g and h. Bug class without it: using Feldman in DKG round 1 and leaking each party's sub-secret commitment, allowing an adversary who controls the qualified-set decision to bias the joint key. Applied in: §P2, §P3, Phase 6–8, §I5–I6.

MM4 — Lagrange coefficients over a prime field are exact; they must be computed constant-time. Lagrange interpolation over F_p involves no floating-point; every division is a modular inverse; every result is an element in {0, …, p-1}. The inverse computation (Fermat's little theorem: a^{p-2} mod p, or constant-time extended-GCD) must run in data-independent time because the Lagrange coefficient is multiplied by the share value — a secret. Bug class without it: a variable-time modular inverse leaking the denominator product via timing, from which the share value can be extracted by lattice analysis. Applied in: §P4, §I9, Phase 3, Phase 10, Phase 14.

MM5 — FROST binding factors prevent rogue-nonce forgery; without them two-round Schnorr is broken. In a naive two-round multi-sig, an adversary runs k signing sessions simultaneously, extracts k rows of nonce commitments, and solves the ROS linear system to produce a forged aggregate signature. FROST's per-signer rho_i = H(i, msg, all-commitments) ties each nonce to the full commitment list and the message, making cross-session manipulation impossible. Bug class without it: omitting or truncating the commitment list in the binding-factor hash, allowing the Drijvers attack. Applied in: §P5, §I7, Phase 9–10, §T2 threat, §8.4.1.

MM6 — Proactive refresh is resharing zero; the secret is invariant because zero polynomials add zero. Each party samples a fresh degree-(t-1) polynomial with constant term exactly 0 and adds its evaluations to the existing shares. Since sum of zero-constant-term polynomials has constant term 0, the joint polynomial's constant term — the secret — is unchanged. The adversary must now compromise t parties within one epoch to win, not across all time. Bug class without it: allowing a refresh polynomial with a non-zero constant term, silently changing the secret and making all existing signatures unverifiable. Applied in: §P7, §I8, Phase 12, §8.16.

MM7 — The joint public key is the sum of constant-term commitments; no party holds the joint secret. After DKG, Y = g^{sum of qualified dealers' a_0} = sum of {g^{a_0} from each qualified dealer}. This sum is computed publicly from Feldman/Pedersen constant-term commitments. The joint secret a_0 (the sum of sub-secrets) is never assembled in any memory location. Bug class without it: implementing a helper function reconstruct_joint_secret that combines sub-secrets for performance — this function is a single point of compromise that voids the threshold guarantee. Applied in: §P3, §I6, Phase 8, §§11.5 KeyShare API.

MM8 — Nonces in Schnorr are one-time secrets; reuse with two different messages yields the key. If the same (d_i, e_i) are used in sessions for messages m1 and m2, the two equations z_i = d_i + rhoe_i + lambdas_ic1 and z_i' = d_i + rho'e_i + lambdas_ic2 yield z_i - z_i' = lambdas_i(c1-c2) + (rho-rho')e_i. With both partial signatures visible, the share s_i is recoverable in one field division. Bug class without it: persisting nonces for "resume" functionality across crashes. Applied in: §P9, §I9, Phase 9, §T9 threat, §8.14.1.

MM9 — Identifiable abort requires per-partial-signature verification BEFORE aggregation. If the aggregator sums all z_i into z = sum(z_i) first and then verifies g^z == R·Y^c, a single bad z_i causes opaque failure with no attribution. Verifying each z_i individually against g^{z_i} == R_i·(Y_i)^c before summing pins the blame to the offending party. Bug class without it: aggregating first and failing opaquely — the session must restart but no party can be excluded, enabling indefinite denial-of-service. Applied in: §P6, §I7, Phase 10, §8.4.2, §T7 threat.

Glossary · 50 terms · site-wide glossary

Additive resharing
Each current shareholder splits their share into new sub-shares of the same value; recipients sum sub-shares from all holders to obtain a new valid sharing of the original secret under a possibly different (t', n') threshold. Preserves I8.
Aggregate signature
Combined output of threshold signing: (R, z) for FROST/Schnorr, or a single BLS curve point for threshold BLS. Verifies under the joint public key with the standard verification equation. Indistinguishable from a single-signer signature by a verifier (P8). Corresponds to AggregateSignature.
Binding commitment
A commitment scheme property: no PPT adversary can open a commitment to two distinct values. Feldman VSS commitments are computationally binding under the discrete-log assumption but not hiding.
Binding factor (rho_i)
Per-signer scalar rho_i = H(i, msg, all-commitment-list) in FROST. Ties each signer's nonce contribution to the message and all other signers' commitments, so a malicious signer cannot grind nonces to cancel honest contributions. Computed in tss-schnorr/src/binding.rs. Corresponds to BindingFactor.
BLS signature
Signature scheme (Boneh, Lynn, Shacham 2001) using bilinear pairings: sign = H(m)^{sk} in G1; verify via e(sign, g2) == e(H(m), pk2). Output is a single short group element. Naturally aggregatable: product of signatures verifies against product of public keys. Threshold variant aggregates partial signatures via Lagrange interpolation in the exponent.
Commitment (VSS)
A vector of EC points committing to the coefficients of the dealer's sharing polynomial. Feldman: C_j = g^{a_j}. Pedersen: C_j = g^{a_j} h^{b_j}. Published once by the dealer; used by all recipients for share verification. Corresponds to Commitment and PedersenCommitment.
Complaint round
DKG round 3 (in tss-dkg/src/round_complaint.rs) in which a recipient who received a share failing VSS verification broadcasts a signed complaint identifying the misbehaving dealer and the disputed share. Honest participants resolve disputes; bad dealers are excluded from the qualified set. Underpins I6, P6.
Constant-time arithmetic
Implementation discipline: all field inversions, Lagrange coefficient computations, scalar multiplications involving secrets, and share comparisons run in time independent of secret operands. Prevents timing side-channels. Enforced by subtle/ct_option crates and validated with dudect in Phase 14. Required by I9, P4.
Dealer
The party in basic Shamir SSS that holds the plaintext secret, samples the sharing polynomial uniformly at random with the secret as constant term, evaluates it at n distinct non-zero share IDs, and distributes shares. In DKG every party acts as its own dealer, removing single-point trust.
Discrete-log assumption (DL)
Hardness assumption: given g, g^x in a prime-order group, computing x is computationally infeasible. Underpins Feldman VSS binding, FROST unforgeability, and BLS security. Shamir SSS security is information-theoretic and does NOT rely on DL.
Distributed key generation (DKG)
Protocol (GJKR 1999) where n parties each run a Pedersen/Feldman VSS as dealer; cross-verify received shares; run a complaint round to exclude cheaters; and sum qualified sub-shares to obtain individual KeyShare values. The joint public key Y = g^(sum of constant terms) is known to all; the joint secret key is never reconstructed. Implemented in tss-dkg.
Domain separation
Distinct hash prefixes or DST strings distinguishing hash invocations (hash-to-scalar, hash-to-point, challenge, binding factor, transcript). Prevents cross-protocol collisions. Required at every point H(...) appears in tss-schnorr, tss-bls, tss-group.
Epoch
The interval between proactive refresh protocol executions. An adversary must compromise t or more parties within one epoch to reconstruct the secret. Shorter epochs reduce the exposure window at the cost of refresh overhead. See Phase 12, P7.
Evaluation point
The non-zero field element x_i at which the sharing polynomial f is evaluated to produce share_i = f(x_i). Encoded as ShareId(u32). The secret is the polynomial at x=0; zero is never a valid share ID (I10). Points must be distinct across all n participants.
Feldman VSS
VSS scheme (Feldman FOCS 1987): dealer publishes commitments C_j = g^{a_j} for each coefficient a_j of the polynomial. Recipient with share s_i and ID x_i verifies: g^{s_i} == product_{j=0}^{t-1} C_j^{x_i^j}. Computationally binding under DL; not hiding — the constant-term commitment C_0 = g^{secret} leaks information about the secret. Used in DKG round 1 commit broadcast.
Field element
An element of the prime field F_p over which the sharing polynomial is defined. In the EC instantiation F_p equals the curve scalar field. Addition, subtraction, multiplication, and inversion are closed in F_p. Corresponds to FieldElement (aliased as Scalar in tss-core).
FROST
Flexible Round-Optimized Schnorr Threshold Signatures (Komlo & Goldberg SAC 2020; standardised as RFC 9591). A two-round threshold Schnorr protocol with per-signer binding factors. Round 1: nonce commitments. Round 2: partial signatures. Aggregation: sum partial z_i with Lagrange weighting. Verification: standard Schnorr under joint key.
Generator (nothing-up-my-sleeve)
An EC group element used as a base for commitments or public keys, chosen by hashing a public constant to a curve point (hash-to-curve). The discrete-log relationship between two independent generators g and h must be unknown, ensuring Pedersen hiding. Implemented in tss-group/src/generators.rs.
Hash-to-point
A uniform, collision-resistant map from an arbitrary byte string to an EC group element. Used for BLS message hashing (H(m) in G1) and to derive the second Pedersen generator h. Must follow a standardised hash-to-curve spec (e.g., RFC 9380).
Hash-to-scalar
A domain-separated, uniform map from bytes to a non-zero element of F_p. Used for Schnorr challenges (c = H(R, Y, msg)), FROST binding factors, and transcript derivations. Implemented in tss-group/src/hash.rs.
Hiding commitment
A commitment scheme property: the commitment reveals no (statistical or computational) information about the committed value. Pedersen commitments are perfectly hiding — given C = g^a h^b, every value a' has a valid opening (a', b') for a known h. Required for secure DKG so that the dealer's g^secret is not revealed during the commit phase.
Horner's method
Efficient polynomial evaluation: f(x) = a_0 + x(a_1 + x(a_2 + ... + x*a_{t-1})) — evaluates a degree-(t-1) polynomial in t-1 multiplications and t-1 additions. Used in tss-shamir/src/split.rs to evaluate the sharing polynomial at each share ID.
Identifiable abort
Protocol property: if any party misbehaves (submits an invalid VSS share, a bad partial signature, or a complaint without proof), all honest parties can identify the misbehaving party by index. The protocol can then restart excluding the identified party. Distinct from "abort" (protocol stops without blame assignment). Implemented in tss-protocol/src/abort.rs. See P6.
Information-theoretic security
Security that holds against computationally unbounded adversaries; relies purely on probability theory, not computational hardness. Shamir SSS achieves information-theoretic perfect secrecy: any t-1 shares are uniformly distributed regardless of the secret (I2). Pedersen VSS provides information-theoretic hiding.
Joint public key
The group element Y = g^(sum of qualified dealers' constant terms) produced by DKG. No single party holds the corresponding secret scalar. All threshold signatures produced by the qualified participant set verify under Y with the standard single-key verification equation. Corresponds to KeyShare.group_public. See I6.
Lagrange coefficient
lambda_i = prod_{j in S, j != i} (x_j / (x_j - x_i)) mod p, computed over the set S of t share IDs used in reconstruction. Weights each party's contribution to the interpolated polynomial value at x=0. All arithmetic is exact in F_p; no approximation. Must be computed in constant time when inputs are secret shares.
Lagrange interpolation
The unique degree-(t-1) polynomial passing through t given points (x_i, y_i) is recovered; its value at x=0 is the sum of y_i * lambda_i. In a prime field this is exact with no rounding error (I4). Any t-subset from the same polynomial yields the same constant term (I1).
Montgomery ladder
A constant-time algorithm for scalar multiplication on elliptic curves that processes each bit with the same sequence of field operations regardless of bit value. Prevents timing and simple power-analysis side-channels on secret scalars. Used or referenced in tss-group/src/scalar_mul.rs.
Nonce commitment
Per-round, per-signer pair of EC points (D_i, E_i) committing to a signer's hiding nonce d_i and binding nonce e_i before they are revealed. Broadcast in FROST round 1. Prevents a signer from adaptively choosing nonces after seeing others' commitments. Corresponds to NonceCommitment.
Pairing
A bilinear map e: G1 × G2 → GT satisfying e(aP, bQ) = e(P, Q)^{ab}. Enables BLS verification: e(H(m)^{sk}, g2) = e(H(m), g2)^{sk} = e(H(m), pk2). Computationally expensive; used only in tss-bls. Marked optional via a Cargo feature flag; if unavailable, tss-bls/src/stub.rs returns Err(PairingNotAvailable).
Partial signature
A single party's contribution to a threshold signature before aggregation. In FROST: z_i = d_i + rho_ie_i + lambda_ishare_i*c. In threshold BLS: sigma_i = H(m)^{share_i}. Each partial signature can be individually verified against the party's public share to support identifiable abort. Corresponds to PartialSignature.
Pedersen commitment
Commitment C = g^a h^b where g, h are EC generators with no known discrete-log relationship. Perfectly hiding (any value a' can be opened with blinder b' = (a - a')·log_h(g) + b, which is unknown). Computationally binding under DL. Used in Pedersen VSS and as the basis for secure DKG.
Pedersen VSS
VSS scheme (Pedersen CRYPTO 1991): dealer uses two parallel degree-(t-1) polynomials f(x) and f'(x); commits as C_j = g^{a_j} h^{b_j}; sends (f(x_i), f'(x_i)) to each recipient. Verification: g^{f(x_i)} h^{f'(x_i)} == prod C_j^{x_i^j}. Provides information-theoretic hiding (the commitment reveals nothing about the secret) and computational binding. Required for secure DKG.
Perfect secrecy
The property of a scheme where the posterior distribution of the secret given the observed shares is identical to the prior distribution; i.e., the shares carry zero information about the secret. Shamir SSS achieves perfect secrecy for any t-1 or fewer shares (I2).
Polynomial (sharing)
Univariate polynomial f(x) = a_0 + a_1·x + ... + a_{t-1}·x^{t-1} over F_p where a_0 = secret and a_1, ..., a_{t-1} are sampled uniformly at random. Corresponds to Polynomial { coeffs: Vec<Scalar> }. Zeroized immediately after share generation (P9). Degree is exactly t-1 (I3).
Proactive refresh
Protocol (Herzberg et al. CRYPTO 1995): at each epoch boundary, parties jointly secret-share zero using random polynomials with zero constant term and add the resulting sub-shares to their existing shares. This re-randomizes shares while preserving the shared secret. Limits adversary to one epoch of compromise. Implemented in tss-proactive/src/refresh.rs. See I8, P7.
Qualified set
The set of DKG participants Q whose VSS shares were accepted without unresolved complaints. The joint public key and final shares are derived exclusively from dealers in Q. If a party is not in Q, its contribution is discarded. Computed in tss-dkg/src/round_complaint.rs and tss-dkg/src/finalize.rs.
Resharing
Redistribution of existing shares into a new sharing of the same secret under possibly different parameters (t', n'). Implemented via additive reshare in tss-shamir/src/reshare.rs. The secret never leaves F_p^t form. Required for participant rotation and threshold parameter changes. See Phase 4, I8.
Rogue-nonce attack
An attack on naive multi-party Schnorr where a malicious signer chooses its nonce commitment after seeing honest signers' commitments, grinding it to cancel their contributions or forge a valid aggregate signature. FROST's per-signer binding factors rho_i prevent this by tying each signer's nonce to the message and the full commitment list before nonces are revealed. See P5, Phase 9.
Scalar
An element of the elliptic-curve prime-order scalar field F_p, identical to FieldElement in the EC instantiation. All secret values (shares, nonces, keys), Lagrange coefficients, and challenges are represented as Scalar. Operations are constant-time.
Secret sharing
A method of distributing a secret s among n parties such that any t parties can reconstruct s, but any t-1 or fewer parties learn absolutely nothing about s. Shamir's scheme (1979) achieves this information-theoretically via polynomial evaluation over a prime field.
Share
The evaluation of the dealer's secret polynomial at a party's share ID: share_i = f(x_i) in F_p. Corresponds to Share { id: ShareId, value: Scalar }. Must never be transmitted over an unencrypted channel and is zeroized after use.
Share ID (ShareId)
A non-zero element of F_p identifying a participant; the evaluation point x_i for that party's share. Encoded as ShareId(u32). The secret resides at x=0, which is therefore never a valid share ID. Duplicate or zero IDs are rejected with an error (I10, P10).
Share recovery
Reconstruction of a lost or corrupted share by t or more honest helpers each computing a sub-share via additive reshare of their own share; the recovering party interpolates. Implemented in tss-proactive/src/recovery.rs. Does not expose any helper's full share.
t-of-n threshold
A scheme parameterised by ThresholdParams { t, n } with 1 ≤ t ≤ n: exactly t (or more) parties are required to reconstruct the secret or produce a valid threshold signature; any t-1 (or fewer) learn nothing and cannot forge.
Threshold BLS
A combination of BLS signing with Shamir sharing: each party i computes partial signature sigma_i = H(m)^{share_i}; any t partial signatures can be aggregated via Lagrange interpolation in the exponent to yield sigma = H(m)^{joint_secret}; verified by pairing: e(sigma, g2) == e(H(m), Y2). Implemented in tss-bls.
Threshold Schnorr
Multi-party Schnorr signature scheme where any t of n parties jointly produce (R, z) that verifies under the joint public key with the standard Schnorr equation g^z == R · Y^c. FROST is the state-of-the-art two-round protocol, now standardised as RFC 9591.
Transcript
An ordered, domain-separated cryptographic accumulator of all public values broadcast during a protocol run (commitments, public keys, messages, round identifiers). Binds all parties to the same protocol context, preventing replay and cross-session attacks. Implemented in tss-protocol/src/transcript.rs.
VSS (Verifiable Secret Sharing)
An extension of Shamir SSS where the dealer publishes public commitments to polynomial coefficients, allowing each recipient to verify its share independently without trusting the dealer. Two main variants: Feldman VSS (binding, not hiding) and Pedersen VSS (perfectly hiding and binding). Implemented in tss-vss.
Zeroization
Secure overwriting of memory regions holding secret data (polynomial coefficients, sub-shares, nonces) immediately after use and before deallocation, using compiler-barrier-safe writes that cannot be optimised away. Implemented via the zeroize crate's Zeroize and ZeroizeOnDrop traits. Required by P9 for all types in tss-core/src/zeroize.rs.
