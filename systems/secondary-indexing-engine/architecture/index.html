3.2 Subsystem Responsibilities

Client Applications — untrusted external producers/consumers over gRPC, embedded FFI, or a binary protocol. Every payload crosses a validation boundary before entering a runtime state machine.

Query API — query decoding, authentication hooks (mTLS + scoped token, §22), timeout propagation, request shaping, protocol negotiation. Never touches storage directly; every read goes through Request Coordination.

Admin API — compaction control, runtime metrics, replication topology, segment diagnostics, repair tooling. Isolated into a separate thread/task pool from query execution (I6, §7) so an admin storm cannot starve queries.

Request Coordination — the single concurrency-isolation boundary: snapshot acquisition, scheduler assignment, cancellation propagation, admission control, token-bucket rate limiting. All backpressure signals (P4, §6) originate or terminate here.

Query Runtime — point lookups, range/prefix/compound scans, merge iteration, MVCC visibility filtering, bloom prefiltering. Designed for O(1) bounded memory per in-flight query (§4).

Mutation Runtime — index mutation application, write sequencing, WAL append ordering, visibility timestamp (sequence ID) assignment. Guarantees deterministic mutation ordering (P1, §6).

Snapshot Manager — epoch-based reference tracking for consistent visibility windows: snapshot pinning, compaction-visibility safety, replay determinism. The sole authority for "what generation is visible now."

WAL Manager — append-only durability, segment rotation, checksum validation, replay scanning. Defines the crash-recovery boundary (I1, §7): nothing crosses it un-fsynced.

Memtable Engine — mutable in-memory indexing: lock-free skiplist writes, lock-free reads via epoch reclamation, immutable freeze transition on flush trigger.

Iterator Engine — one iterator trait (§11) implemented uniformly over memtables, frozen memtables, and persistent segments; the query runtime never special-cases a storage tier.

Segment Manager — SSTable-style lifecycle: file descriptors, mmap ownership, segment metadata, publication/retirement.

Compaction Scheduler — merge compactions, tombstone pruning, level balancing, rewrite prioritization, all snapshot-safe (never rewrites a segment a pinned snapshot still needs).

Bloom Filter Runtime — probabilistic existence checks that cut disk IO for point lookups on absent keys (ADR-04-adjacent design driver, §28).

Manifest Runtime — the canonical storage-topology log. Every segment-visibility transition is serialized through a manifest commit (I2, §7) — this is the atomicity boundary for the whole storage layer.

Persistent Segments — immutable, disk-backed, mmap-read files: sorted key blocks, sparse block index, bloom filter, checksum trailer, metadata footer (§8.4).

Replication Runtime — Raft integration, log shipping, snapshot replication, follower synchronization, replay-order verification.

Peer Nodes — remote members of the Raft replication group; the network trust boundary (§22) starts here.

Trust boundaries: Client Applications → Query/Admin API (untrusted input validation); Replication Runtime → Peer Nodes (mutually authenticated, still subject to term/sequence replay checks). Concurrency boundaries: Request Coordination (admission), Memtable Engine (epoch reclamation), Compaction Scheduler (IO isolation from query pool). Persistence boundary: WAL Manager and Manifest Runtime, the only two places an fsync is load-bearing for correctness. Protocol boundary: Query/Admin API (gRPC framing) and Replication Runtime (Raft RPC framing). Queues: the append-entries pipeline between WAL Manager and Replication Runtime, and the compaction job queue between Segment Manager and Compaction Scheduler.

8. Domain Model — Mutation, Segment & Snapshot State Machine

8.1 Core Concepts

Concept Meaning
Primary Key Source record identifier owned by the upstream system
Secondary Key Indexed projection derived from the primary record
Sequence ID Monotonic mutation-ordering counter, one per shard
Visibility Epoch Snapshot generation boundary
Segment Immutable, sorted, disk-backed file
Tombstone Deletion marker that dominates all older writes for its key

8.5 Segment/Memtable State Machine

State Meaning
Mutable Active memtable accepting writes
Frozen Immutable, flush-pending memtable
Flushing Segment file under construction
Published Query-visible segment (post manifest commit)
Compacting Rewrite in progress; still visible until swap
Obsolete Superseded; awaiting safe deletion

8.6 Query Lifecycle

Client -> Query API -> Snapshot Acquire -> Iterator Planning
       -> Bloom Prefilter -> Segment Merge -> MVCC Filter
       -> Response Encode

8.7 Replication Sequencing (leader guarantee order)

  1. WAL append
  2. fsync
  3. replication enqueue
  4. quorum acknowledgment
  5. visibility publication

8.8 Representative Failure Path

Scenario: crash during compaction's manifest swap. Expected behavior: orphan-segment detection on restart (§17), manifest rollback to the last committed generation, and WAL/manifest replay recovery (§12, §23) — never a partially-visible segment set.
