47 — PageRank (Link Analysis) Engine

Project Number: 47

Project Name: PageRank (Link Analysis) Engine

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

A from-scratch, in-core, single-node link-analysis engine in Rust that computes the stationary distribution of the Google matrix (PageRank) and a family of related link-structure rankings (HITS, SALSA, Personalized PageRank, TrustRank) over directed graphs up to ~10⁹ edges, via parallel sparse matrix–vector multiply (SpMV) over compressed adjacency, with mass-conserving dangling-node handling, configurable damping/teleportation, and L1/L2 convergence gating. The engine is a batch computation kernel, not a graph database and not a crawler: it ingests an edge list / WebGraph BV file, builds CSR/CSC, iterates to a fixed point, and emits a ranked node vector. Optimization priority is fixed: correctness → observability → maintainability → performance.

Phase-0 deliverable — the crates that ship (a Cargo workspace):

  1. graph-io — parse SNAP edge-list, WebGraph BV binary, adjacency-list text; intern labels → dense u32; detect dangling nodes.
  2. graph-repr — CsrGraph (out-links) and CscGraph (in-links); DanglingBitVec; out-degree reciprocals; mmap binary format.
  3. pagerank-core — sequential power iteration: dangling-mass pre-pass, pull SpMV, damping, teleportation, L1/L2 convergence.
  4. pagerank-parallel — Rayon column-partitioned SpMV; parallel dangling reduction; cache-aware chunking.
  5. hits — Kleinberg hub/authority co-iteration with L2 normalization.
  6. salsa — Lempel–Moran bipartite stochastic link analysis.
  7. personalized-pr — ExactPpr (seed-set teleport) and LocalPushPpr (Andersen–Chung–Lang push).
  8. trust-rank — TrustRank + AntiTrustRank over trusted/spam seed sets.
  9. cli — prank binary: rank | hits | ppr | trust subcommands; JSON/TSV output; structured convergence log.
  10. bench — Criterion micro-benchmarks for SpMV, convergence wall-time, parse bandwidth, PPR.
  11. Conformance suite: hand-computed tiny fixtures + SNAP samples (web-BerkStan, web-Google, soc-LiveJournal).

System boundaries. Provides: in-memory ranking of a directed graph from a parsed edge set; deterministic output under a documented float-ordering model. Delegates: crawling, URL canonicalization beyond NFC, persistence/serving of ranks, and graph storage to other systems (see sibling links, §2). Does NOT provide: a distributed runtime, a query API, incremental/streaming updates, or weighted-edge semantics in Phase 0 — each is PhaseDeferred("§35") and registered in §35.

Non-goals. No general graph algorithms (shortest path, community detection) beyond what link analysis needs; no GPU backend in Phase 0; no on-disk graph engine (out-of-core is a deferred scaling lever, §29); no multi-tenant service. The engine is a correctness oracle and performance kernel, deliberately narrow.

Deployment model. A statically-linked CLI binary + library crates, distributed as a multi-stage Docker image and a cargo install artifact. Single process, single host; threads scale to physical cores. Operators run it as a batch job and consume JSON/TSV.

Target users / operators. (a) IR / web-science engineers computing ranks over crawl graphs; (b) graph-ML practitioners needing PPR proximity vectors; (c) anti-spam teams using TrustRank; (d) the blueprint reader, who builds it to acquire the competencies in §2.

What later phases unlock. Distributed Pregel SpMV, Monte-Carlo PPR, topic-sensitive teleportation, streaming incremental updates, an HTTP serving layer, GPU SpMV, and spectral diagnostics — all deferred, all in §35.

Recommended language — Rust (stable ≥ 1.78), and why. The hot path is a memory-bandwidth-bound SpMV over arrays that must be laid out, aliased, and parallelized with surgical control; the rest is parsing untrusted binary formats. Rust gives (1) C-level control of memory layout and zero-copy mmap casts (bytemuck), (2) data-race freedom for the parallel SpMV checked at compile time (rayon over disjoint par_chunks_mut), and (3) no GC pauses to perturb per-iteration timing. Rejected: C/C++ — equivalent speed but aliasing/UB make a correct parallel SpMV and a fuzz-hardened BV decoder far costlier to get right (ADR-01); Go — GC jitter and weaker numeric/SIMD story; Java — the LAW WebGraph reference is Java, but JIT warmup and object headers bloat billion-edge arrays; Python/NumPy — fine as the reference oracle (§5) but cannot hold a 10⁹-edge graph in process. See ADR-01 and Alternative Architectures (§34) for when these win.

Prerequisites the reader must already hold. Rust (ownership, traits, iterators, unsafe, rayon); sparse linear algebra (SpMV, L1/L2 norms, eigen-intuition); Markov-chain basics (stationary distribution, irreducibility, aperiodicity, Perron–Frobenius); graph theory (adjacency, SCC, dangling/bipartite); Unix systems (mmap, NUMA, perf, cachegrind); one of the SNAP/WebGraph datasets on disk.

Estimated timeline. Phase 0 (Phases 0–9 herein): 10–11 weeks for one engineer. Full system incl. deferred phases (§35): 6–9 months. Per-phase durations in Appendix B.

2. Why Build This

PageRank is a one-line eigenproblem (r = G·r) wrapped in a mountain of systems engineering. The blueprint exists to teach the mountain, not the line.

  • Mass conservation under dangling nodes. Zero-out-degree pages drain probability; the dangling-mass pre-pass (d·dmass/n redistributed before each SpMV, P2/I2) is the single most-omitted correctness step. Build it once, internalize conservation laws forever.
  • Direction of flow vs. direction of links. Rank flows into a page from its predecessors, so the kernel iterates the transpose (CSC), not the link adjacency (CSR). Choosing storage by access pattern (P3, ADR-04) is the transferable lesson.
  • SpMV is memory-bandwidth-bound, not FLOP-bound. The teaching is that the bottleneck is the random rank_in[row_idx[k]] gather, not arithmetic — so layout, prefetch (src_out_deg_recip co-array), and node reordering by degree matter more than vectorizing multiplies (P3, P10, §28).
  • Numerical determinism under parallel reduction. Tree-reduction reorders float adds; the engine documents a bounded non-determinism (≤ n·ε, P5/I5) instead of pretending bits are stable. This is the calibration every parallel-numerics engineer needs.
  • Sublinear local computation. Andersen–Chung–Lang push computes PPR in O(1/ε) independent of n — a different complexity class from global power iteration. Builds the instinct that "touch only the support you need."
  • Adversarial graph structure. Link farms and TKC cliques are attacks on the spectrum; TrustRank and SALSA are spectral defenses. Teaches that ranking is a security surface.

What Mastery Looks Like

After building this, the reader can:

  • Derive and defend the Google matrix G = d·S + (1−d)/n·11ᵀ from the random-surfer model and prove why teleportation guarantees a unique stationary vector (Phase 2, §8).
  • Choose a sparse layout from an access pattern — explain why PageRank uses CSC and HITS needs both CSR and CSC, and predict the cache behavior of each (Phase 1, Phase 4).
  • Parallelize a reduction without locks and reason about its float non-determinism, stating the exact error bound a reviewer should accept (Phase 3, §28).
  • Implement a sublinear graph algorithm (local push) and state its O(1/ε) bound and the ε·m L1 error it trades for it (Phase 5).
  • Harden a binary parser against adversarial input — bounded allocation, checked arithmetic, fuzz corpus — and articulate the threat model (Phase 0, Phase 9, §22).
  • Run a defensible performance investigation — flamegraph → perf counters → cachegrind — and tie a regression to an LLC-miss number, not a vibe (Phase 8, §28).
  • Recognize and defeat spectral attacks (link farms, TKC) with TrustRank/SALSA and say precisely when each defense fails (Phase 4, Phase 6, §22).

cli — parses args (ADR-12), detects input format, orchestrates load→build→rank→emit, and streams a structured per-iteration convergence log to stderr (I9). It owns exit codes (§19) and never holds graph invariants — it delegates to the library crates.

graph-io — the only code that touches untrusted bytes; everything downstream trusts its output. Parses SNAP/BV/adjacency, interns labels to dense NodeId, and computes the dangling set. All failure is a typed GraphIoError (no panics; fuzzed in Phase 9).

graph-repr — owns the in-memory graph. CsrGraph holds out-links (row = source); CscGraph holds in-links (column = destination) and carries the co-located src_out_deg_recip array so the SpMV inner loop reads reciprocals sequentially. DanglingBitVec (Roaring, ADR-07) answers is_dangling in O(1) and reduces dangling mass.

pagerank-core — the mathematical heart. One iteration = dangling-mass pre-pass → pull SpMV over CSC → scale by d → add teleportation → L1/L2 convergence check → renormalize. Hosts the RankAlgorithm trait that every variant implements (P8).

pagerank-parallel — swaps the sequential SpMV for a Rayon par_chunks_mut over disjoint destination ranges; dangling mass becomes a parallel tree-reduction (documented non-determinism, P5/I5). No locks; correctness checked against the sequential oracle.

hits / salsa / personalized-pr / trust-rank — algorithm crates behind the common trait. HITS needs both CSR and CSC (two SpMVs/iter); SALSA walks the bipartite hub/authority graph; personalized-pr offers exact and sublinear-push PPR; trust-rank is PPR over a trusted seed teleportation vector.

bench — Criterion harness; the only crate allowed to read data/. Emits GFLOP/s, MB/s, and wall-time JSON that the CI regression gate (§27) compares against a baseline.

6. Design Principles

P1 — Correctness before performance. Every optimization is validated against the reference sequential implementation on the same input to within 1e-10 L1 after normalization. Tradeoff: slower to ship. Operational: the sequential kernel is the oracle in CI (§26). Violation: a faster SpMV with reordered sums that shifts ranks is a defect, not a trade — silent ranking drift downstream.

P2 — Dangling nodes are first-class. The dangling-mass pre-pass (sum r[i] over the dangling set, redistribute (d·dmass + (1−d))/n) runs before every SpMV. Tradeoff: one O(|dangling|) pass/iter. Operational: dangling_mass is emitted per iteration (I9). Violation: probability leaks, ‖r‖₁ < 1, ranks biased toward non-dangling sinks.

P3 — Layout follows access pattern. Rank flows into a node, so the kernel iterates CSC (in-links); HITS keeps CSR too. Nodes are reordered by descending degree to front-load hot rows; reciprocals are co-located in the CSC. Tradeoff: a permutation + an extra m-length array. Operational: ADR-04. Violation: random gathers across the CSR blow the LLC (§28).

P4 — Iteration count is a correctness guard, not a tunable. max_iter (default 200) bounds non-convergent graphs; convergence is declared by ε-delta, never by hitting the cap. Violation: treating max_iter as "good enough N" ships unconverged ranks silently.

P5 — Determinism is specified, not assumed. Sequential output is bit-identical across runs/platforms; parallel output may differ by ≤ n·f64::EPSILON from float-add reordering, and that bound is documented (I5). Tradeoff: gives up bit-stability under threads. Operational: tests compare parallel↔sequential within 1e-12. Violation: flaky CI or false regression alarms.

P6 — Zero-copy I/O for large graphs. CSR/CSC binaries load via mmap + bytemuck cast; no byte-wise parse above ~1 GB. Tradeoff: host-endianness coupling (I12). Violation: parsing a 10 GB graph by hand triples load time and RSS.

P7 — Convergence criteria are explicit and configurable. --epsilon, --norm{L1,L2}, --max-iter are surfaced; the default norm (L1 of the rank delta) is documented as the PageRank standard. Violation: comparing runs under different norms yields incomparable "converged" claims.

P8 — One algorithm interface. PageRank, HITS, SALSA, PPR, TrustRank implement RankAlgorithm (assoc. Output/Config/Error). Tradeoff: a slightly abstract trait. Operational: CLI selects by name; benchmarks are uniform. Violation: algorithm-specific code leaks into I/O/output layers and the variants diverge.

P9 — Failure is observable. Non-convergence emits a structured JSON warning to stderr, writes the best-available vector, and exits non-zero (code 2, §19). Violation: silent divergence looks like success.

P10 — No heap allocation in the hot loop. Rank buffers, accumulators, and the teleport scalar are pre-allocated and reused; the teleport+dangling terms fold into one scalar add per node. Tradeoff: explicit buffer management. Violation: per-iteration Vec churn destroys cache locality and makes latency non-deterministic.

P11 — Format independence. graph-io emits a RawEdgeList; the kernel never learns how bytes were parsed. Tradeoff: one indirection at load. Operational: a new format = a new parser only. Violation: a WebGraph quirk leaking into pagerank-core couples the layers.

P12 — Reproducible benchmarks. Each bench record pins dataset, n, m, d, ε, threads, and host; results are committed JSON; >5% regression fails CI (§27). Violation: perf claims become anecdotes and regressions slip in unnoticed.

8. Domain Model

8.1 The web graph as a Markov chain

G = (V,E), |V| = n, |E| = m, directed. PageRank r ∈ ℝⁿ is the stationary distribution of a random surfer: r[i] = long-run probability of being at page i. The link-transition matrix H is column-stochastic:

H[i][j] = 1 / outdeg(j)   if (j → i) ∈ E     (mass leaves j, split over its out-links)
        = 0               otherwise

So H·x pushes mass backward along links — rank arrives at i from its in-neighbors. This is why the kernel stores and iterates the in-link structure (CSC), not CSR (P3, MM2).

8.2 Dangling correction and the Google matrix

A node j with outdeg(j)=0 makes column j all-zero — mass vanishes. Patch with the dangling indicator a (a[j]=1 iff dangling):

S = H + (1/n) · 1 · aᵀ          (dangling columns become uniform)

S is column-stochastic. Make it irreducible+aperiodic (a unique, reachable stationary vector — Perron–Frobenius) by mixing in teleportation with damping d:

G = d·S + (1−d)·(1/n)·1·1ᵀ      Google matrix; r = G·r, ‖r‖₁ = 1

8.3 Power iteration (recurrence, not a loop)

Start r⁽⁰⁾ = (1/n)·1. The iterate is defined by the recurrence (computed as: dangling pre-pass → SpMV → scalar fold):

r⁽ᵏ⁺¹⟩ = d·H·r⁽ᵏ⁾ + [ d·(aᵀ·r⁽ᵏ⁾)/n + (1−d)/n ]·1
         └── SpMV ──┘   └──── one uniform scalar added to every node ────┘

The bracket is a single scalar (P10): c = (d·dmass + (1−d))/n, dmass = aᵀr⁽ᵏ⁾. Stop when ‖r⁽ᵏ⁺¹⟩ − r⁽ᵏ⁾‖₁ < ε.

8.4 Worked example (the tiny-4node fixture)

Edges A→B, A→D, B→C, C→A; D is dangling. outdeg = {A:2, B:1, C:1, D:0}, d=0.85, n=4, r⁽⁰⁾ = 0.25 each.

Step dmass =r[D] scalar c r[A] r[B] r[C] r[D]
k=0 0.250 (0.85·0.25+0.15)/4 = 0.0906 0.250 0.250 0.250 0.250
k=1 0.250 0.0906 0.303 0.197 0.197 0.197
k=2 0.197 0.0794 0.270 0.208 0.247 0.196
… … … converges ≈ A:0.275 B:0.198 C:0.230, D:0.166

The hand-check: A gains from C (A's only in-link) plus dangling+teleport; D, with no in-links beyond teleport, settles lowest. Σr = 1 at every step (I1). The .expected file is the NumPy/NetworkX value at ε=1e-12.

8.5 Convergence rate

The asymptotic rate equals the subdominant eigenvalue modulus |λ₂|, and for the Google matrix |λ₂| ≤ d (Haveliwala–Kamvar bound). Hence to reach ε:

dᵏ < ε  ⇒  k > ln(ε)/ln(d).   d=0.85, ε=1e-6 ⇒ k > 85.   (graph-independent upper bound)

Strong block/community structure can converge faster (Kamvar et al. 2003, §5). Larger d (→1) ranks "more faithfully" but converges slower and conditions worse — the core tradeoff a reader must feel (§32 #4, HQ3 §33).

8.7 Personalized PageRank — local push (Andersen–Chung–Lang)

Maintain estimate p and residual res; init p=0, res[s]=1. While some u has res[u] ≥ ε·outdeg(u), push u (these are mathematical updates, applied per popped u):

p[u]      += (1−d)·res[u]
res[w]    += d·res[u]/outdeg(u)      ∀ w : u→w  (out-neighbors)
res[u]     = 0

Terminates in O(1/ε) pushes, independent of n (MM5); L1 error ≤ ε·m (Phase 5, §17). A max-priority frontier keyed on res[u]/outdeg(u) orders the work.

8.8 WebGraph BV wire format (decode schema)

Successors of node v are encoded as fields (no logic — a layout the decoder consumes):

outdeg            : ζ₃ or γ integer
copy_ref_gap      : γ        (reference node v−ref, window W=7); present iff copy block used
copy_block_runs   : γ*       (alternating include/exclude run-lengths over ref's successors)
interval_count t  : γ
intervals         : t × (start_gap : γ, length : γ)   starts gap-coded from prev interval end
residuals         : γ*       remaining successors, gap-coded from last interval end or from v

All integers are γ (gamma) or ζ₃ (zeta, k=3); ζ₃ matches the ~1/x^{1+1/k} degree law of web graphs (§5 Boldi–Vigna, glossary). The decoder keeps a window buffer of the last W lists.

8.9 Malformed-input and failure-path examples

  • Malformed edge ("12\tfoo"): non-numeric dst → GraphIoError::MalformedEdge{line,detail}, exit 1 — never a partial graph.
  • Crafted CSR binary (header.m ≫ file length): rejected by I12 length+checksum check before any bytemuck cast — defeats the OOB read (Threat T4, §22).
  • All-dangling graph: dmass=1 every step ⇒ r = teleport vector, converges in one iteration (I1 holds; valid degenerate, §14 edge cases).
  • d=1.0: rejected at parse (I7) — without teleport the chain may be reducible/periodic and power iteration need not converge.

    pub fn get(&self, node: NodeId) -> Prob;

12. Phase 0 — Graph I/O and Node Remapping

12.1 Objectives

Turn untrusted bytes (SNAP / WebGraph BV / adjacency text) into a trusted RawEdgeList with dense u32 ids and a sorted dangling set. Establish the trust boundary (§3) and the no-panic parsing contract that Phase 9 fuzzes.

12.2 Detailed Implementation Steps

  • snap.rs::parse_snap(impl BufRead) -> Result<RawEdgeList, GraphIoError> — skip #/blank lines; parse src\tdst as u64 (raw ids exceed u32 pre-remap); carry line number into MalformedEdge (P9, I-error path). Use an 8 MB BufReader (ADR-08).
  • remapper.rs::NodeRemapper — HashMap<String,NodeId>; intern NFC-normalizes (UAX #15, §5) then insert-or-get. String keys (not u64) so URL inputs work later (P11).
  • dangling.rs — after all edges, outdeg[i]=#{e: e.src=i}; emit nodes with outdeg=0 as a sorted Vec<NodeId> (deterministic Roaring build, ADR-07; feeds I2).
  • webgraph.rs — BitReader over an mmap slice (ADR-08) decoding γ and ζ₃ integers, copy lists (window W=7), interval lists, residuals per the §8.8 schema (Boldi–Vigna, §5); maintain the last-W window buffer. Bounds + checked_add on every decoded gap (I10, T2 §22).
  • lib.rs — optional BFS validation: warn if reachable < n/2 (disconnected ⇒ teleport matters, I3). Diagnostic only, never an error.

12.3 Deliverable

cargo test -p graph-io green; prank --help lists subcommands; prank rank --input conformance/fixtures/tiny-4node.edges emits a JSON rank vector.

12.4 Acceptance Criteria

All 5 conformance parse fixtures load with exact (n,m); tiny-4node output matches .expected within 1e-9 L1 (run_conformance.sh exit 0); SNAP parse ≥ 100 MB/s (M6); zero panics over a 100k-run fuzz_snap_parser (Phase 9).

12.5 Conformance Fixtures

tiny-4node.edges (§8.4); dangling-chain.edges (D sinks, I2); self-loop.edges (node not dangling); disconnected.edges (two 3-cliques, I3); web-berkstan-sample.edges (1000-node realistic density). Each ships a .expected.

12.6 Pitfalls

(1) SNAP ids are sparse/non-dense — indexing by raw id over-allocates or panics; always NodeRemapper. (2) Comment lines vary — skip any first-non-WS #. (3) γ off-by-one: γ encodes k via the length of k+1; dropping the +1 shifts every adjacency list (passes smoke, fails conformance). (4) NodeRemapper keys must stay String for URL inputs. (5) Dangling status is computed after remap (a dst-only node is dangling).

12.7 Performance Concerns

Text parse is I/O-bound — the 8 MB buffer (ADR-08) cuts syscalls; web-Google (5.1M edges) parses < 2 s on NVMe. BV decode is CPU-bound on next_bit(); profile with perf stat, vectorize the γ path only if it dominates (§28).

12.8 Edge Cases

Zero-edge graph (all dangling, rank=1/n); single node no edges (n=1,m=0); self-edges retained (out-edge ⇒ not dangling); duplicate edges retained (multigraph; raises outdeg, dilutes per-edge mass) unless --dedup.

12.9 Failure Analysis

NodeIdOverflow ⇒ > 2³² labels (corrupt input or a graph needing u64, ADR-17); blast radius = the load only; recovery = enable a u64 feature build. Truncated BV ⇒ WebGraphDecode; forensic artifact = byte offset + partial window buffer dumped to stderr.

12.10 Operational Notes

Metric graphio.parse_mb_per_s, graphio.dangling_frac; tracing span per file with {n,m,format}; runbook adding-a-new-graph-format.md. Format is auto-detected by extension, overridable with --format-in.

13. Phase 1 — Graph Representation (CSR/CSC)

13.1 Objectives

Build the immutable in-core structures the kernel iterates: CsrGraph (out-links), CscGraph (in-links + co-array), DanglingBitVec; an mmap binary cache; optional degree-sort. Establish I4/I6/I10/I11.

13.2 Detailed Implementation Steps

  • csr.rs — two-pass build: count outdeg, exclusive prefix-scan to row_ptr (Sanders et al. ch.9, §5), scatter dst into col_idx, restore row_ptr by right-shift; compute out_deg_recip finite per I4; sort each row segment (determinism, P5).
  • csc.rs::from_raw — transpose: count indeg, prefix-scan to col_ptr, scatter src into row_idx, and co-write out_deg_recip[src] into src_out_deg_recip at the same index (P3, MM2). Assert Σindeg = Σoutdeg = m (I11).
  • dangling_bitvec.rs — RoaringBitmap from the sorted dangling Vec (ADR-07); expose accumulate_mass (I2).
  • sort_order.rs — optional permutation by descending degree (P3); store perm/perm⁻¹.
  • binary_format.rs — magic b"CSRG0001", header {n:u64,m:u64,format:u8}, arrays, footer SHA-256; load via mmap+bytemuck::cast_slice (ADR-08/09) after I12 length+checksum.

13.3 Deliverable

cargo test -p graph-repr green; CscGraph::from_raw yields a CSC whose col_ptr sums to m; binary save→reload round-trips bit-identically on all fixtures.

13.4 Acceptance Criteria

tiny-4node ⇒ csr.row_ptr == [0,2,3,4,4] (A→B,A→D;B→C;C→A;D dangling); dangling.is_dangling(D); round-trip equality on row_ptr/col_idx/out_deg_recip; CSR build of web-BerkStan (7.6M edges) in ≤ 100 ms (M7); I6/I10/I11 assertions pass.

13.5 Conformance Fixtures

tiny-4node structural assert; dangling-chain dangling-bit assert; a save/reload round-trip fixture; a crafted-binary fixture (m ≫ file len) that must be rejected by I12 (links to T4, §22).

13.6 Pitfalls

(1) Forgetting the row_ptr right-shift corrupts every row. (2) Unsorted rows ⇒ non-deterministic traversal (P5). (3) src_out_deg_recip index drift — must use the same col_ptr[j] offset as row_idx. (4) Endianness: cast_slice is host-endian — document it; cross-endian load needs byteswap (I12, ADR-08). (5) Full-file SHA-256 on mmap forces a page-fault scan of GBs — checksum the header only; full check is opt-in --verify-checksum.

13.7 Performance Concerns

Build is O(m+n); the scatter pass is random writes into col_idx keyed by src — power-law hubs stay hot in L3 (Newman ch.8, §5). Degree-sort cuts cold SpMV gathers 15–30% on web graphs (P3, §28). Prefix-scan is trivially parallelizable later (Phase 3 lever).

13.8 Edge Cases

n=1,m=0 ⇒ row_ptr=[0,0], dangling={0}; mutual edge A↔B ⇒ row_ptr=[0,1,2]; m=0 ⇒ all dangling, dmass=1; m > 2³² ⇒ lengths are usize, ids stay u32 — guard length math against overflow.

13.9 Failure Analysis

I11 mismatch ⇒ parser bug (CSR/CSC disagree) — abort build with the three counts in the message; blast radius = build stage; forensic artifact = the diff of outdeg/indeg histograms. Binary checksum failure ⇒ reject (never cast), Class-1 (§23).

13.10 Operational Notes

Metrics repr.build_ms, repr.bytes_per_edge (target ≈ 24, §32); span build_csr/build_csc; the binary cache lets a re-run skip parse (RTO = reload, §24). Runbook running-on-large-graphs.md covers RSS budgeting (§4).

14. Phase 2 — Sequential PageRank Core

14.1 Objectives

Implement the correctness oracle: one mass-conserving power-iteration step (§8.3) with damping, dangling redistribution, teleportation, and L1/L2 convergence — the reference all later optimizations are validated against (P1).

14.2 Detailed Implementation Steps

  • power_iter.rs — realize the §8.3 recurrence (Langville–Meyer Eq. 4.8, §5): per iteration compute dmass = dangling.accumulate_mass(r) (P2,I2), pull-SpMV into r', then fold the single scalar c = (d·dmass + (1−d))/n over every node (P10), renormalize (I1), test ‖r'−r‖₁ < ε (P7). Double-buffer r/r', swap roles each step (no realloc, P10).
  • spmv.rs::spmv_sequential(csc, rank_in, rank_out) — signature only (§4): zero rank_out; for each dst j, accumulate Σ_{i→j} rank_in[i]·src_out_deg_recip (pull form, McSherry §5, MM2). Distinct buffers (I8).
  • teleport.rs — apply_uniform(out, d, dmass, n) and apply_custom(out, d, v, dmass, n) (I14) as signatures; both fold damping once (the §14.6 double-damp pitfall).
  • convergence.rs — ConvergenceState transitions; emit IterationReport to tracing (I9). rank_vec.rs — assert Σr ≈ 1 within 1e-10; warn! + renormalize on drift > 1e-8; abort on > 1e-6 twice (Class-4, §23).

14.3 Deliverable

prank rank --input tiny-4node.edges --damping 0.85 --epsilon 1e-9 emits a vector matching .expected within 1e-9 L1; run_conformance.sh exits 0 on all fixtures.

14.4 Acceptance Criteria

All 5 fixtures within 1e-9 L1 of NumPy/NetworkX ground truth; iteration count within ±1 of the ln(ε)/ln(d) estimate (§8.5); Σr = 1 ± 1e-10 every iteration (I1); sequential SpMV ≥ 1.0 GFLOP/s on web-BerkStan (M1).

14.5 Conformance Fixtures

Phase-0 set plus d_sweep.sh (d∈{.5,.7,.85,.9,.95} — iter count rises as d→1, §8.5) and epsilon_sweep.sh (ε∈{1e-4,1e-6,1e-8} — monotonically closer to the ε=1e-12 reference).

14.6 Pitfalls

(1) Buffer aliasing — comparing r' to itself gives Δ=0 and false convergence (I8). (2) Double damping — applying d in both SpMV and teleport injects a phantom d²; apply once. (3) Emitting an un-normalized vector breaks downstream PPR/TrustRank (I1). (4) On max_iter still emit best + exit 2, never panic (I15,§19). (5) Dangling term must carry d (d·dmass/n, Eq. 4.8) — dropping it mis-conserves mass.

14.7 Performance Concerns

~20 ms/iter on web-BerkStan (7.6M edges); ~85 iters ⇒ ~1.7 s. Bandwidth-bound on reading row_idx+src_out_deg_recip per edge (MM2); align CSC arrays to 64 B cache lines; the scalar fold is one FMA/node (P10).

14.8 Edge Cases

d=1.0 rejected (I7); d=0.0 rejected (I7) — though mathematically it is the teleport vector in one step; all-dangling ⇒ converge in 1 iter; n=1 ⇒ [1.0], no divide-by-zero (I4).

14.9 Failure Analysis

Non-convergence (near-degenerate spectrum / d→1) ⇒ TimedOut, exit 2, best vector emitted (I15); operator visibility = the per-iteration L1 trace; remedy = raise --max-iter or relax --epsilon. Numerical divergence ⇒ Class-4 (§23).

14.10 Operational Notes

Metrics pr.iterations, pr.final_l1, pr.dangling_mass; --verbose streams IterationReport JSON; runbook debugging-convergence-failures.md. This crate is the CI oracle for P1 — never optimized in place.

15. Phase 3 — Parallel PageRank (Rayon SpMV)

15.1 Objectives

Replace the sequential SpMV with a lock-free Rayon version that matches the oracle within float-reorder tolerance (P5,I5) and scales to physical cores (ADR-03).

15.2 Detailed Implementation Steps

  • par_spmv.rs::spmv_parallel(csc, rank_in, rank_out, chunk) — signature only (§4): partition rank_out with par_chunks_mut(chunk); each worker owns a disjoint dst range and reads shared rank_in immutably — the borrow checker proves no data race (ADR-03, Ligra-style chunking, Shun–Blelloch §5). No two chunks write the same entry (P3,I8).
  • Dangling reduction — dangling.par_iter().map(|i| rank_in[i]).sum() as a tree-reduction; document the ≤ n·ε non-determinism (P5,I5).
  • chunk_policy.rs::optimal_chunk_size(n, threads, l2_bytes) — max(1000, n/(threads·4)), rounded to a multiple of 8 f64 (cache-line, §15.6).
  • thread_config.rs — init Rayon with num_cpus::get_physical() (hyperthreads don't help a BW-bound kernel, P3); honor --threads / RAYON_NUM_THREADS.

15.3 Deliverable

prank rank --input data/web-BerkStan.txt --threads 8 finishes < 500 ms and matches the sequential vector within 1e-12 L1.

15.4 Acceptance Criteria

Parallel↔sequential L∞ < 1e-14 on fixtures (I5); ≥ 6.0 GFLOP/s at 8 threads (M2); thread sweep {1,2,4,8,16} agrees within 1e-10 and converges within ±1 iteration; single-thread Rayon == sequential exactly.

15.5 Conformance Fixtures

parallel_vs_sequential.sh (diff at 8 dp on every fixture); thread_count_sweep.sh (equal convergence ±1, equal ranks within 1e-10).

15.6 Pitfalls

(1) Chunk boundaries off cache lines ⇒ false sharing — make chunk a multiple of 8. (2) rayon::scope per iteration adds overhead — use the global pool. (3) rank_in/rank_out aliasing silently corrupts (I8 debug assert). (4) threads > physical thrashes — warn. (5) Treating the ±1-iter parallel/sequential difference as a failure (it is documented determinism, P5).

15.7 Performance Concerns

Speedup ceilings at memory bandwidth, not cores: ~10× on a 16-core box for web-BerkStan. perf stat -e LLC-load-misses localizes the random rank_in[row_idx] gather — the irreducible cost of sparse SpMV (MM2, §28).

15.8 Edge Cases

n < chunk ⇒ one chunk (parallel overhead > gain) — switch to sequential below n=10_000 (configurable); 1-thread path must equal the oracle bit-for-bit.

15.9 Failure Analysis

A par/seq L∞ > 1e-14 means a real bug (not reordering) — likely a chunk-boundary index error; forensic artifact = the first divergent node index and its in-neighbor list. Blast radius = the parallel crate; fall back to pagerank-core (P1).

15.10 Operational Notes

Metrics pr.spmv_gflops, pr.threads, pr.par_seq_linf; emit the effective chunk and thread count in the run header; runbook benchmark-regression-investigation.md ties slowdowns to LLC-miss deltas (§28).

16. Phase 4 — HITS Algorithm

16.1 Objectives

Implement Kleinberg HITS (hub/authority co-iteration) using both CSR and CSC, with L2 normalization and dual convergence — and a TKC diagnostic that motivates SALSA.

16.2 Detailed Implementation Steps

  • update.rs — per iteration (Kleinberg §3, §5): auth[j] = Σ_{i→j} hub[i] (pull via CSC), then hub[i] = Σ_{i→j} auth[j] (push via CSR) — HITS is the one variant needing both structures (P3, ADR-04). Signatures only (§4).
  • normalize.rs — L2-normalize auth then hub each half-iteration (I13); unlike PageRank's L1 (P7) the eigenvector interpretation requires L2.
  • convergence.rs — converge only when both ‖Δhub‖₂ < ε and ‖Δauth‖₂ < ε; report both deltas (I9). Init hub=auth=1, L2-normalized before iter 1.
  • TKC diagnostic — warn! if > 95% of hub/auth mass concentrates on < log n nodes (Lempel–Moran §4, §5) — suggests SALSA (Phase 4 sibling, §22 TKC threat).

16.3 Deliverable

prank hits --input tiny-4node.edges emits hub and authority scores; the highest-in-degree node has top authority, the highest-out-degree node top hub.

16.4 Acceptance Criteria

Hub/auth match a NumPy eigenvector of AAᵀ/AᵀA within 1e-8 L2; the 3×3 bipartite-hits fixture converges in ≤ 2 iterations; all scores non-negative (Perron–Frobenius sign check, §16.6).

16.5 Conformance Fixtures

tiny-4node-hits.expected (NumPy eigenvector ground truth); bipartite-hits.edges (3 hubs ×3 authorities; 2-iteration convergence assert).

16.6 Pitfalls

(1) Half-iteration order: compute auth_{k+1} from hub_k, then hub_{k+1} from the new auth_{k+1} (standard order). (2) L1 instead of L2 converges to the wrong fixpoint (I13). (3) On disconnected graphs HITS concentrates on the top-eigenvalue component — correct, document it. (4) Any negative score ⇒ a sign/init bug (Perron–Frobenius).

16.7 Performance Concerns

Two SpMVs/iter ≈ 2× PageRank wall time; convergence is often faster (10–20 iters) for well-structured graphs. Both CSR and CSC resident ⇒ ~1.5× the RAM of PageRank — fold into the §4 working-set budget.

16.8 Edge Cases

No edges ⇒ hub=auth=1/√n, no structure; DAG ⇒ sources high hub, sinks high authority; single dominant clique ⇒ TKC warning fires.

16.9 Failure Analysis

Oscillation without convergence ⇒ a periodic substructure; detect via non-decreasing dual delta over a window; remedy = cap iters (I15) and report. Blast radius = hits crate only; PageRank unaffected.

16.10 Operational Notes

Metrics hits.hub_delta, hits.auth_delta, hits.tkc_flagged; emit both convergence curves under --verbose; HITS shares the RankAlgorithm trait so CLI and bench treat it uniformly (P8).

17. Phase 5 — Personalized PageRank

17.1 Objectives

Provide proximity-to-seed rankings two ways: ExactPpr (global power iteration, seed-set teleport) and LocalPushPpr (Andersen–Chung–Lang, sublinear) — and report the approximation bound the user is buying.

17.2 Detailed Implementation Steps

  • exact.rs — reuse pagerank-core with TeleportMode::Custom(v) where v[i]=1/|S| on the seed set, 0 elsewhere (I14); identical iteration otherwise.
  • local_push.rs — the §8.7 push process (Andersen–Chung–Lang Alg. 1, §5, MM5): init p=0, res[s]=1; a max-priority frontier keyed on res[u]/outdeg(u); pop while res[u] ≥ ε·outdeg(u), apply the three §8.7 updates, enqueue affected neighbors. Signatures
    • the §8.7 math only (§4). Dangling u (outdeg=0) handled separately (§17.6).
  • seed_set.rs::SeedSet::new — validate ids in range; uniform or custom weights summing to 1 (I14); PprError::SeedNotFound/EmptySeedSet otherwise.
  • approx_error.rs — report the L1 bound ε·m alongside output so users calibrate ε.

17.3 Deliverable

prank ppr --seed 0 --epsilon 1e-5 --input tiny-4node.edges emits a PPR vector from node 0; node 0 has the highest self-affinity.

17.4 Acceptance Criteria

ExactPpr vs LocalPushPpr agree within ε·m L1 at ε=1e-6; LocalPushPpr single-seed query ≤ 50 ms (M8) on web-Google; PPR vector sums to 1 (I1); all seeds above mean PPR.

17.5 Conformance Fixtures

ppr-exact-vs-local.sh (L1 diff < ε·m); ppr-seed-set-3.edges (3-seed; vector sums to 1; seeds above-average).

17.6 Pitfalls

(1) Push threshold is res[u] ≥ ε·outdeg(u), not ≥ ε — wrong form breaks the O(1/ε) bound. (2) Dangling u: ε·0 is always satisfied ⇒ infinite loop; absorb p[u]+=(1−d)res[u] and either redistribute d·res[u]/n or accept documented mass loss. (3) Seed not in graph ⇒ typed error, never a panic.

17.7 Performance Concerns

LocalPushPpr is O(1/ε) pushes — independent of n (MM5): ≈ 10⁴ pushes at ε=1e-5, avg-degree 10; ExactPpr is O(n·k) and infeasible at billion-node scale (use push). Frontier ops dominate — a BinaryHeap keyed on push urgency.

17.8 Edge Cases

Seed = dangling node (still seeds via teleport, no out-push); whole-graph seed set ⇒ reduces to standard PageRank; ε very small ⇒ push count → exact, latency rises.

17.9 Failure Analysis

Push frontier never empties ⇒ a dangling/threshold bug (§17.6); detect via a push-count ceiling = c/ε; on breach, abort with the offending residual. ExactPpr OOM on huge graphs ⇒ Class-3 (§23), recommend push.

17.10 Operational Notes

Metrics ppr.pushes, ppr.l1_bound (=ε·m), ppr.latency_ms; both impls behind PprAlgorithm; the push variant is the default for n > 10⁶.

18. Phase 6 — TrustRank

18.1 Objectives

Implement TrustRank (PPR from a trusted seed set) and AntiTrustRank (from a spam seed set), with manual and inverse-PageRank seed selection, and a combined spammicity score — a spectral defense against link farms (§22).

18.2 Detailed Implementation Steps

  • seed_select.rs — (a) manual: read trusted labels, map via NodeRemapper; (b) inverse-PR (Gyöngyi et al. §3, §5): run PageRank on the reverse graph (separate reverse-CSC, never mutate the original, §18.6), rank candidates by forward_rank/reverse_rank, take top k.
  • propagate.rs — TrustRank = ExactPpr with teleport v[i]=1/|S| on the trusted set, 0 else (I14), d=0.85; output is the trust score.
  • anti_trust.rs — same machinery on a spam seed set; spammicity spam[i] = anti[i]/(trust[i]+anti[i]).
  • Output: sorted (node_id, trust, anti_trust, spam) tuples (reuses cli/output.rs).

18.3 Deliverable

prank trust --seed-file trusted_seeds.txt --input data/web-BerkStan.txt emits a trust-scored list; seeds score ≥ 0.5.

18.4 Acceptance Criteria

On trust-smoke.edges the 2 trusted nodes rank highest and trust propagates exactly one hop; a planted link-farm node scores low trust / high anti-trust; output sums and ordering validated.

18.5 Conformance Fixtures

trust-smoke.edges (6 nodes, 2 trusted; one-hop propagation assert; one planted spam node for the anti-trust assert).

18.6 Pitfalls

(1) Inverse-PR needs a separate reverse-CSC — never mutate the original (P11). (2) Empty trusted set ⇒ all-zero teleport (invalid, I14) ⇒ TrustRankError::EmptySeedSet listing unmatched labels. (3) Trusting too small a seed set over-concentrates trust — document the seed-size/coverage tradeoff.

18.7 Performance Concerns

TrustRank cost ≈ one PageRank run (it is PPR); inverse-PR seed selection doubles it (a second reverse-graph run). Reuse the parallel SpMV (Phase 3) for both.

18.8 Edge Cases

Trusted seed is dangling — still propagates trust via teleport (trust is pulled from the seed vector, not pushed along out-links); seed overlaps spam set ⇒ warn, spammicity → 0.5.

18.9 Failure Analysis

All-low trust scores ⇒ seed set disconnected from the bulk graph; detect via trusted-set reachability; remedy = broaden seeds. Reverse-CSC build OOM ⇒ Class-3 (§23).

18.10 Operational Notes

Metrics trust.seed_count, trust.unmatched_labels, trust.spam_flagged; runbook reuse of convergence debugging; trust/anti-trust share the RankAlgorithm+PPR path (P8).

20. Phase 8 — Benchmarking Suite

20.1 Objectives

25. Compatibility & Versioning

Wire/CLI surface. The stable contracts are: the CLI flags + exit-code semantics (§19), the JSON output schema, and the TSV column order. SemVer applies to the workspace: breaking any of these = a major bump.

Storage format. The CSR/CSC binary carries magic CSRG0001; the trailing 4 digits are the format version. A reader must reject unknown majors (I12) and ship a converter for minor upgrades (e.g. adding the endianness field — §13.6). Datasets themselves are external (ADR-24).

Schema evolution. JSON output is additive-only within a major: new fields may appear; existing fields never change type or meaning. Consumers must ignore unknown fields. TSV gains columns only at the end.

API stability (library crates). graph-io/graph-repr/pagerank-core public types (§11) follow SemVer; pub(crate) internals (e.g. RankVec::inner) are not API. Trait RankAlgorithm is sealed against external impls until 1.0 to keep room for associated-type changes.

Deprecation policy. A flag/field is deprecated for one minor (warned on stderr) before removal in the next major. The exit-code meanings (§19) never change within a major — they are the automation contract.

Rolling-upgrade guarantee. Because runs are independent batch jobs, mixed-version fleets are safe as long as the binary format major matches; the canary diff (§24) gates promotion.

28. Performance Engineering

Methodology. Bench on a dedicated host: cpupower frequency-set --governor performance, turbo disabled (no_turbo=1), isolcpus for the worker cores, threads pinned to physical cores. Every number is reproducible (P12) and gated in CI (§27).

Profiling ladder. (1) cargo flamegraph --bin prank -- rank … — find the hot function (expect 80%+ in the SpMV inner loop). What stays constant vs grows.

Quantity Scaling Note
Iterations to converge O(1) in n,m ≈ ln ε/ln d ≈ 85 (§8.5); graph-independent upper bound

Named bottlenecks, in order. (1) Memory capacity — the in-core ceiling (~32 GB ⇒ ~10⁹ edges, §4/§32) is the first wall. (2) Memory bandwidth — SpMV's random rank_in gather caps single-node throughput; cores saturate BW before compute (MM2). (3) Coordination — only in the deferred distributed design: cross-partition messaging per superstep.

Vertical scaling. More RAM raises the graph ceiling; more cores help only until BW saturates (≈ physical-core count, P3). Effective to ~1–4 TB / single-host graphs.

Horizontal scaling (deferred, §35). Partition the CSC column space across k machines (each owns n/k destinations); one message-exchange round per iteration ships boundary rank_in values — the Pregel/BSP model (Malewicz et al., §5; Alt-Arch §34). Coordination overhead grows with edge-cut, so partition to minimize cross-edges (the practical ceiling lever beyond a single host).

Practical ceiling and the levers beyond it. Single node: ~10⁹ edges in 32 GB. Beyond that, in order: (a) f32 ranks + 64-bit-packed u32 ids (constant-factor), (b) WebGraph BV in-core to cut adjacency 3–5× (§5), (c) out-of-core edge-centric streaming (X-Stream, Alt-Arch §34), (d) distributed Pregel SpMV (§35). Each is registered with an un-defer trigger in §35.

30. Mental Models & First Principles

MM1 — PageRank is a Markov chain's stationary vector; the Google matrix just makes that chain well-behaved. Predicts: a unique, positive r exists and power iteration finds it (Perron–Frobenius). Bug without it: inventing ad-hoc "fixes" for dangling mass instead of seeing them as restoring stochasticity. Applied: §8.1–8.2.

MM2 — SpMV is a memory-bandwidth problem in an arithmetic costume. The cost is the random gather rank_in[row_idx[k]], not the multiply–add. Predicts: cores saturate bandwidth before FLOPs; layout/prefetch beat vectorization. Bug without it: hand-tuning the multiply while the LLC thrashes. Applied: §28, P3, ADR-04.

MM3 — Rank flows opposite to links, so you iterate the transpose. Predicts: PageRank wants CSC (in-links); HITS needs both CSR and CSC. Bug without it: building only CSR and writing a push that mis-attributes mass. Applied: §8.1, §11.3, §16.

MM4 — Damping is a fidelity/conditioning knob: |λ₂| ≤ d. Predicts: d→1 ranks more faithfully but converges slower and conditions worse. Bug without it: setting d=0.99, then blaming the solver for 1000 iterations. Applied: §8.5, §32 #4.

MM5 — Local computation touches only the support it needs. Push-PPR is O(1/ε), independent of n. Predicts: a single-seed PPR is cheap even on a billion-node graph. Bug without it: running global power iteration once per seed. Applied: §8.7, §17.

MM6 — Probability is conserved or the ranking is wrong. Σr = 1 is a hard invariant. Predicts: any leak (dangling, drift) biases every score. Bug without it: skipping the dangling pre-pass and shipping a sub-stochastic vector. Applied: I1/I2, §8.2.

MM7 — A parallel kernel is only correct relative to a sequential oracle. "Correct" means "agrees with the reference within a stated float bound," not "looks plausible." Predicts: you can ship parallelism safely only behind a diff test (I5). Bug without it: trusting the fast path and shipping reordered, wrong ranks. Applied: P1, §15, §26.

MM8 — Untrusted bytes are hostile until validated; the parser is the security perimeter. Predicts: every decoded length/index is a potential OOB or overflow. Bug without it: an unwrap() in the BV decoder that a crafted file turns into a crash. Applied: §22, Phase 9.

MM9 — Teleportation is a regularizer that makes the chain ergodic, not a hack. Predicts: removing it can break convergence on real (reducible/periodic) web graphs. Bug without it: allowing d=1 and getting non-convergence or a non-unique fixpoint. Applied: §8.2, I7.

NetworkX chose developer ergonomics over scale: pure-Python, dict-backed, O(n²) dense paths exist. It wins as the ground-truth oracle (§5) and for graphs that fit in a notebook; it cannot hold a web crawl. This engine borrows its formula, not its data model.

Ligra (Shun–Blelloch, §5) made the one decision this design most resembles: shared-memory CSR with a frontier that switches between sparse (push) and dense (pull) by threshold. It wins when you want maximum single-node throughput across many graph algorithms; we specialize to the PageRank family and bake the pull direction in (ADR-04), trading generality for a tighter kernel.

Spark GraphX embraced the cluster: vertex/edge RDDs and a Pregel API over BSP supersteps. It wins when the graph is part of a larger distributed ETL pipeline and already lives in Spark; it pays JVM/serialization/shuffle overhead that dominates below ~10⁹ edges — exactly the range we target in-core, which is why we defer distribution (§35, Alt-Arch §34).

PowerGraph/GraphLab (Gonzalez et al.) made the decision tuned to natural graphs: vertex-cut partitioning to balance power-law degree skew, with a gather-apply-scatter model and optional async execution. It wins on skewed billion-edge graphs across a cluster; its async path sacrifices determinism, which our correctness-first kernel (P1/MM7) refuses. (WebGraph/LAW, §5, is the compression point of comparison: 3–5 bits/edge — our deferred in-core-BV lever, §29.)

32. Back-of-Envelope Capacity Model

The numbers an expert computes before writing code, each derived from §4 / §8. Avg web-graph degree d̄ = m/n ≈ 10; f64::EPSILON ≈ 2.2e-16.

  1. Structural bytes/edge. CSR col_idx (4) + CSC row_idx (4) + CSC src_out_deg_recip (8) = 16 B/edge. Per-node: row_ptr(4)+col_ptr(4)+out_deg_recip(8) = 16 B/node.
  2. Rank buffers. Double-buffered f64: 2·n·8 = 16 B/node. Node total = 16+16 = 32 B/node.
  3. RAM for 10⁹ edges (n = m/d̄ = 10⁸): 16·10⁹ + 32·10⁸ = 16 GB + 3.2 GB = ≈ 19.2 GB → fits the 32 GB ceiling (§4); HITS (+CSR side) ≈ +8 GB still fits.
  4. Iterations to ε. ⌈ln(1e-6)/ln(0.85)⌉ = ⌈−13.816/−0.1625⌉ = ⌈85.0⌉ = 85 (§8.5, M11) — independent of graph size.
  5. SpMV read traffic / iter (web-BerkStan, m=7.6M): per edge read row_idx(4)+recip(8)+ gathered rank_in(8) ≈ 20 B ⇒ 7.6e6·20 ≈ 152 MB/iter. At ~25 GB/s usable BW ⇒ ≈ 6 ms/iter → matches p50 (M3).
  6. Throughput sanity. 2m FLOP = 1.52e7 FLOP/iter; at 6 ms ⇒ 2.5 GFLOP/s one-core class; 8-thread target 6 GFLOP/s ⇒ ~2.5 ms/iter (BW-bound, M2).
  7. End-to-end (web-BerkStan, 8t). parse ~1.2 s (#9) + build ~0.1 s (M7) + 85·~3 ms ≈ 0.26 s ⇒ ≈ 1.6 s ≤ M5 (2 s). The binary cache removes the parse term on re-runs.
  8. FD budget. 1 mmap graph + 1 output + 3 std = ~5 FDs, O(1) in n (§4) — no per-node descriptors.
  9. SNAP parse time. web-BerkStan text ≈ 120 MB / 100 MB/s (M6) ≈ 1.2 s — the end-to-end long pole, motivating the CSR cache (§28 tail note).
  10. WebGraph BV size. 7.6M edges · 4 bits / 8 ≈ 3.8 MB vs ~120 MB text ⇒ ~30× smaller; in-core BV is the §29 adjacency-compression lever.
  11. Local-push PPR work. O(1/ε) at ε=1e-5 ⇒ ~10⁵ pushes · d̄ ≈ 10⁶ edge-touches ⇒ sub-ms to tens of ms ≤ M8 (50 ms), independent of n (MM5).
  12. Parallel determinism bound. worst-case float error ≤ n·f64::EPSILON = 1e8·2.2e-16 ≈ 2.2e-8 (I5) — two orders below ε=1e-6, so the convergence decision is never flipped by reordering.

34. Alternative Architectures (Roads Not Taken)

Four fundamentally different designs for the same ranking problem — not parameter tweaks.

A1 — Vertex-centric BSP (Pregel/Giraph/GraphX).

 [partition 1]──msgs──▶[partition 2]      each vertex: recv → compute → send
       ▲   superstep barrier   │          PageRank = sum incoming, scale, broadcast
       └───────msgs◀───────────┘

Wins when: the graph exceeds a single host's RAM (≫10⁹ edges). Real system: Pregel (Malewicz et al., §5), Apache Giraph, Spark GraphX. Rejected here: Phase 0 is single-host; BSP barriers + serialization dominate below 10⁹ edges, where in-core CSC is far faster. It is the §35 distributed lever.

A2 — Edge-centric streaming (X-Stream).

 disk edge stream ─scatter→ per-vertex updates ─gather→ new ranks   (sequential disk passes)

Wins when: the graph is far larger than RAM and sequential disk bandwidth ≫ random; turns SpMV's random gather into streaming scatter-gather. Real system: X-Stream (Roy et al. SOSP 2013, §5). Rejected here: in-core CSC beats streaming whenever the graph fits; this is an out-of-core lever (§29), not the Phase-0 design.

A3 — Linear-algebra / GraphBLAS backend.

 PageRank = repeated (+,×)-semiring mxv over a sparse matrix object (library-provided)

Wins when: you want many graph operations, portability, or a GPU SpMV "for free." Real system: SuiteSparse:GraphBLAS; the GraphBLAS C API (§5). Rejected here: one hand-tuned pull-SpMV with a co-array (P3) beats a general semiring library for this single kernel, and keeps layout control (ADR-04). GraphBLAS is the natural §34→§35 GPU path.

A4 — Monte-Carlo random-walk PageRank (Fogaras).

 simulate R short random walks/node ─▶ rank[i] ∝ visits[i]   (embarrassingly parallel, approx)

Wins when: you need fully-personalized PPR for all sources, streaming/edge-arrival updates, or trivially-parallel approximate ranks. Real system: Fogaras et al. (§5) and several streaming-PPR systems. Rejected here: power iteration is exact and faster for a single full-graph batch rank; MC's O(log n/ε²) samples only pay off for fully-personalized or streaming regimes — the §35 MC-PPR deferral.

36. Glossary

Adjacency matrix — n×n matrix A, A[i][j]=1 iff edge j→i; for web graphs extremely sparse. Aperiodicity — a Markov-chain property (no fixed return period); guaranteed by teleportation, required for a unique stationary vector. Authority score — HITS score of a node as a destination; principal eigenvector of AᵀA. Bipartite graph — nodes split into two sets with all edges between them; SALSA's model. BSP / superstep — Bulk-Synchronous-Parallel; computation in barrier-separated rounds (the Pregel/distributed model, §34). Co-array (src_out_deg_recip) — the reciprocal array laid parallel to row_idx so the SpMV reads it sequentially (P3, MM2). Column-stochastic matrix — every column sums to 1; H is column-stochastic except dangling columns. Convergence — successive iterates differing by < ε in the chosen norm. CSR (Compressed Sparse Row) — row_ptr+col_idx; row i = out-neighbors of i. CSC (Compressed Sparse Column) — transpose of CSR; column j = in-neighbors of j; the PageRank kernel's structure. Damping factor d — probability of following a link vs teleporting; standard 0.85; |λ₂|≤d (MM4). Dangling node — out-degree zero; leaks mass without the pre-pass (P2). Dangling mass — total rank on dangling nodes, redistributed each iteration (I2). Determinism (parallel) — bit-stability up to a documented ≤ n·ε float-reorder bound (I5, §32 #12). Eigenvector — A·v=λ·v; PageRank is the principal eigenvector (λ=1) of the Google matrix. Ergodicity — irreducible + aperiodic ⇒ a unique reachable stationary distribution. GFLOP/s — 10⁹ float ops/s; SpMV does 2m FLOP/iteration. Google matrix G — d·S + (1−d)/n·11ᵀ; primitive; PageRank is its principal eigenvector. Hub score — HITS score as a source; principal eigenvector of AAᵀ. Irreducibility — every state reachable from every other; given by teleportation. L1 norm — Σ|xᵢ|; PageRank convergence/normalization. L2 norm — √Σxᵢ²; HITS normalization (I13). Local push (Andersen–Chung–Lang) — residual-driven sublinear PPR, O(1/ε) (MM5). Markov chain — memoryless stochastic process; the random surfer. mmap — memory-mapped file I/O; zero-copy CSR/CSC load (ADR-08). NodeId — dense u32 post-remap identifier (ADR-17). Out-degree reciprocal — 1/outdeg(i) (0 if dangling), precomputed, finite (I4). PageRank — stationary distribution of the Google matrix (Brin–Page 1998). Perron–Frobenius — theorem guaranteeing a positive principal eigenvector for a non-negative primitive matrix (I3). Personalized PageRank (PPR) — PageRank with seed-concentrated teleportation; proximity to the seed. Power iteration — r⁽ᵏ⁺¹⟩=G·r⁽ᵏ⁾; converges to PageRank at rate |λ₂|≤d. Pull vs push SpMV — pull: destination gathers from in-neighbors (this kernel); push: source scatters to out-neighbors (McSherry, MM2). Roaring bitmap — hybrid array/bitset set; the DanglingBitVec (ADR-07). SALSA — Lempel–Moran bipartite stochastic link analysis; TKC-robust HITS variant. Seed set — teleportation target nodes for PPR/TrustRank (I14). Spammicity — anti_trust/(trust+anti_trust); combined spam signal (§18). Spectral gap — 1−|λ₂|; larger ⇒ faster convergence. SpMV — sparse matrix–vector multiply; the core kernel (MM2). Stationary distribution — π=G·π; PageRank. Teleportation — (1−d) jump to a (seed or uniform) vector; the ergodicity regularizer (MM9). TKC (Tightly-Knit-Community) effect — a dense clique hijacking HITS hub/authority mass (T9). TrustRank — PPR from a trusted seed set; spam defense (§18). Vertex-cut — edge-partitioning for power-law graphs (PowerGraph, §31). WebGraph BV format — compressed graph encoding (copy lists, intervals, residuals); 3–5 bits/edge (§8.8). ζ (zeta) coding ζₖ — universal integer code tuned to ~1/x^{1+1/k}; ζ₃ suits web-graph degrees. γ (gamma) coding — universal code: unary length of k+1 then its low bits.
