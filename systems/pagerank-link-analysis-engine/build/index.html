✅ Phase 0 — Graph I/O and Node Remapping §12

Objectives

Turn untrusted bytes (SNAP / WebGraph BV / adjacency text) into a trusted RawEdgeList with dense u32 ids and a sorted dangling set. Establish the trust boundary (§3) and the no-panic parsing contract that Phase 9 fuzzes.

Deliverable

cargo test -p graph-io green; prank --help lists subcommands; prank rank --input conformance/fixtures/tiny-4node.edges emits a JSON rank vector.

Acceptance

All 5 conformance parse fixtures load with exact (n,m); tiny-4node output matches .expected within 1e-9 L1 (run_conformance.sh exit 0); SNAP parse ≥ 100 MB/s (M6); zero panics over a 100k-run fuzz_snap_parser (Phase 9).

Fixtures

tiny-4node.edges (§8.4); dangling-chain.edges (D sinks, I2); self-loop.edges (node not dangling); disconnected.edges (two 3-cliques, I3); web-berkstan-sample.edges (1000-node realistic density). Each ships a .expected.

Pitfalls

(1) SNAP ids are sparse/non-dense — indexing by raw id over-allocates or panics; always NodeRemapper. (2) Comment lines vary — skip any first-non-WS #. (3) γ off-by-one: γ encodes k via the length of k+1; dropping the +1 shifts every adjacency list (passes smoke, fails conformance). (4) NodeRemapper keys must stay String for URL inputs. (5) Dangling status is computed after remap (a dst-only node is dangling).

✅ Phase 1 — Graph Representation (CSR/CSC) §13

Objectives

Build the immutable in-core structures the kernel iterates: CsrGraph (out-links), CscGraph (in-links + co-array), DanglingBitVec; an mmap binary cache; optional degree-sort. Establish I4/I6/I10/I11.

Deliverable

cargo test -p graph-repr green; CscGraph::from_raw yields a CSC whose col_ptr sums to m; binary save→reload round-trips bit-identically on all fixtures.

Acceptance

tiny-4node ⇒ csr.row_ptr == [0,2,3,4,4] (A→B,A→D;B→C;C→A;D dangling); dangling.is_dangling(D); round-trip equality on row_ptr/col_idx/out_deg_recip; CSR build of web-BerkStan (7.6M edges) in ≤ 100 ms (M7); I6/I10/I11 assertions pass.

Fixtures

tiny-4node structural assert; dangling-chain dangling-bit assert; a save/reload round-trip fixture; a crafted-binary fixture (m ≫ file len) that must be rejected by I12 (links to T4, §22).

Pitfalls

(1) Forgetting the row_ptr right-shift corrupts every row. (2) Unsorted rows ⇒ non-deterministic traversal (P5). (3) src_out_deg_recip index drift — must use the same col_ptr[j] offset as row_idx. (4) Endianness: cast_slice is host-endian — document it; cross-endian load needs byteswap (I12, ADR-08). (5) Full-file SHA-256 on mmap forces a page-fault scan of GBs — checksum the header only; full check is opt-in --verify-checksum.

✅ Phase 2 — Sequential PageRank Core §14

Objectives

Implement the correctness oracle: one mass-conserving power-iteration step (§8.3) with damping, dangling redistribution, teleportation, and L1/L2 convergence — the reference all later optimizations are validated against (P1).

Deliverable

prank rank --input tiny-4node.edges --damping 0.85 --epsilon 1e-9 emits a vector matching .expected within 1e-9 L1; run_conformance.sh exits 0 on all fixtures.

Acceptance

All 5 fixtures within 1e-9 L1 of NumPy/NetworkX ground truth; iteration count within ±1 of the ln(ε)/ln(d) estimate (§8.5); Σr = 1 ± 1e-10 every iteration (I1); sequential SpMV ≥ 1.0 GFLOP/s on web-BerkStan (M1).

Fixtures

Phase-0 set plus d_sweep.sh (d∈{.5,.7,.85,.9,.95} — iter count rises as d→1, §8.5) and epsilon_sweep.sh (ε∈{1e-4,1e-6,1e-8} — monotonically closer to the ε=1e-12 reference).

Pitfalls

(1) Buffer aliasing — comparing r' to itself gives Δ=0 and false convergence (I8). (2) Double damping — applying d in both SpMV and teleport injects a phantom d²; apply once. (3) Emitting an un-normalized vector breaks downstream PPR/TrustRank (I1). (4) On max_iter still emit best + exit 2, never panic (I15,§19). (5) Dangling term must carry d (d·dmass/n, Eq. 4.8) — dropping it mis-conserves mass.

✅ Phase 3 — Parallel PageRank (Rayon SpMV) §15

Objectives

Replace the sequential SpMV with a lock-free Rayon version that matches the oracle within float-reorder tolerance (P5,I5) and scales to physical cores (ADR-03).

Deliverable

prank rank --input data/web-BerkStan.txt --threads 8 finishes < 500 ms and matches the sequential vector within 1e-12 L1.

Acceptance

Parallel↔sequential L∞ < 1e-14 on fixtures (I5); ≥ 6.0 GFLOP/s at 8 threads (M2); thread sweep {1,2,4,8,16} agrees within 1e-10 and converges within ±1 iteration; single-thread Rayon == sequential exactly.

Fixtures

parallel_vs_sequential.sh (diff at 8 dp on every fixture); thread_count_sweep.sh (equal convergence ±1, equal ranks within 1e-10).

Pitfalls

(1) Chunk boundaries off cache lines ⇒ false sharing — make chunk a multiple of 8. (2) rayon::scope per iteration adds overhead — use the global pool. (3) rank_in/rank_out aliasing silently corrupts (I8 debug assert). (4) threads > physical thrashes — warn. (5) Treating the ±1-iter parallel/sequential difference as a failure (it is documented determinism, P5).

✅ Phase 4 — HITS Algorithm §16

Objectives

Implement Kleinberg HITS (hub/authority co-iteration) using both CSR and CSC, with L2 normalization and dual convergence — and a TKC diagnostic that motivates SALSA.

Deliverable

prank hits --input tiny-4node.edges emits hub and authority scores; the highest-in-degree node has top authority, the highest-out-degree node top hub.

Acceptance

Hub/auth match a NumPy eigenvector of AAᵀ/AᵀA within 1e-8 L2; the 3×3 bipartite-hits fixture converges in ≤ 2 iterations; all scores non-negative (Perron–Frobenius sign check, §16.6).

Fixtures

tiny-4node-hits.expected (NumPy eigenvector ground truth); bipartite-hits.edges (3 hubs ×3 authorities; 2-iteration convergence assert).

Pitfalls

(1) Half-iteration order: compute auth_{k+1} from hub_k, then hub_{k+1} from the new auth_{k+1} (standard order). (2) L1 instead of L2 converges to the wrong fixpoint (I13). (3) On disconnected graphs HITS concentrates on the top-eigenvalue component — correct, document it. (4) Any negative score ⇒ a sign/init bug (Perron–Frobenius).

⬜ Phase 5 — Personalized PageRank §17

Objectives

Provide proximity-to-seed rankings two ways: ExactPpr (global power iteration, seed-set teleport) and LocalPushPpr (Andersen–Chung–Lang, sublinear) — and report the approximation bound the user is buying.

Deliverable

prank ppr --seed 0 --epsilon 1e-5 --input tiny-4node.edges emits a PPR vector from node 0; node 0 has the highest self-affinity.

Acceptance

ExactPpr vs LocalPushPpr agree within ε·m L1 at ε=1e-6; LocalPushPpr single-seed query ≤ 50 ms (M8) on web-Google; PPR vector sums to 1 (I1); all seeds above mean PPR.

Fixtures

ppr-exact-vs-local.sh (L1 diff < ε·m); ppr-seed-set-3.edges (3-seed; vector sums to 1; seeds above-average).

Pitfalls

(1) Push threshold is res[u] ≥ ε·outdeg(u), not ≥ ε — wrong form breaks the O(1/ε) bound. (2) Dangling u: ε·0 is always satisfied ⇒ infinite loop; absorb p[u]+=(1−d)res[u] and either redistribute d·res[u]/n or accept documented mass loss. (3) Seed not in graph ⇒ typed error, never a panic.

⬜ Phase 6 — TrustRank §18

Objectives

Implement TrustRank (PPR from a trusted seed set) and AntiTrustRank (from a spam seed set), with manual and inverse-PageRank seed selection, and a combined spammicity score — a spectral defense against link farms (§22).

Deliverable

prank trust --seed-file trusted_seeds.txt --input data/web-BerkStan.txt emits a trust-scored list; seeds score ≥ 0.5.

Acceptance

On trust-smoke.edges the 2 trusted nodes rank highest and trust propagates exactly one hop; a planted link-farm node scores low trust / high anti-trust; output sums and ordering validated.

Fixtures

trust-smoke.edges (6 nodes, 2 trusted; one-hop propagation assert; one planted spam node for the anti-trust assert).

Pitfalls

(1) Inverse-PR needs a separate reverse-CSC — never mutate the original (P11). (2) Empty trusted set ⇒ all-zero teleport (invalid, I14) ⇒ TrustRankError::EmptySeedSet listing unmatched labels. (3) Trusting too small a seed set over-concentrates trust — document the seed-size/coverage tradeoff.

⬜ Phase 7 — CLI Integration and Output §19

Objectives

Wire the crates into the prank binary: subcommands, format detection, orchestration, JSON/TSV output, structured progress, and a precise exit-code contract.

Deliverable

prank rank --input data/web-BerkStan.txt --format tsv --output ranks.tsv runs to completion and writes a sorted TSV; prank [sub] --help is informative.

Acceptance

JSON node count = n and score sum = 1 ± 1e-9; TSV header/columns correct, scores in {:.10e}; exit codes exact — 0 converged, 1 I/O/parse, 2 non-convergence (I15), 3 bad args.

Fixtures

cli-json-roundtrip.sh (parse JSON; verify count, sum≈1, ordering); cli-tsv-format.sh (header, column count, numeric format).

Pitfalls

(1) Default float formatting flips between fixed/scientific by magnitude — pin {:.10e}. (2) For integer-ID inputs the remapped id ≠ original; carry node_labels through to output, else print the remapped id as the label.

⬜ Phase 8 — Benchmarking Suite §20

Objectives

Stand up reproducible Criterion benchmarks (P12) and a CI regression gate (§27) that turn the §28 targets (M1–M12) into automated checks.

Deliverable

cargo bench -p bench runs clean; benchmarks/results/ holds ≥ 1 committed JSON; benchmarks/README.md records the bench host.

Acceptance

Each of M1–M12 (§28) is measured and asserted on the pinned host; regression gate active and proven by a deliberately-slow PR test; results reproducible within Criterion's noise band.

Fixtures

Benchmarks read data/ (fetched + SHA-256-verified by make data, ADR-24); a tiny synthetic graph provides a fast smoke benchmark for PR CI.

Pitfalls

(1) Benchmarking a debug build — enforce --release. (2) Frequency scaling skews wall-time — pin governor + disable turbo (§28). (3) Including parse in an SpMV benchmark conflates two metrics — isolate the kernel.

⬜ Phase 9 — Fuzzing and Security §21

Objectives

Harden the untrusted-input parsers (§3 trust boundary) so no input panics or reads out of bounds; make I4/I6/I10/I12 the fuzzers' explicit targets.

Deliverable

cargo fuzz run fuzz_snap_parser -- -runs=100000 completes crash-free; crash findings recorded in SECURITY.md.

Acceptance

100k runs each target, zero crashes; the crafted-binary fixture (T4) is rejected by I12 before any cast; checked_add proven to stop a BV gap overflow (I10); #[deny(clippy::unwrap_used)] passes on library crates.

Fixtures

The crafted-binary fixture (§13.5); a truncated-BV corpus entry; a degenerate rank-vector input (NaN/Inf) for fuzz_rank_vec.

Pitfalls

(1) unwrap() in parsers ⇒ libFuzzer crashes — propagate with ?. (2) node_id + gap overflowing u32 on hostile BV input — checked_add, return WebGraphDecode (I10). (3) Unbounded allocation from a huge declared outdeg/m — cap before allocating (T1 §22).
