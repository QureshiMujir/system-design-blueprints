32. Back-of-Envelope Capacity Model

The numbers an expert computes before writing code, each derived from §4 / §8. Avg web-graph degree d̄ = m/n ≈ 10; f64::EPSILON ≈ 2.2e-16.

  1. Structural bytes/edge. CSR col_idx (4) + CSC row_idx (4) + CSC src_out_deg_recip (8) = 16 B/edge. Per-node: row_ptr(4)+col_ptr(4)+out_deg_recip(8) = 16 B/node.
  2. Rank buffers. Double-buffered f64: 2·n·8 = 16 B/node. Node total = 16+16 = 32 B/node.
  3. RAM for 10⁹ edges (n = m/d̄ = 10⁸): 16·10⁹ + 32·10⁸ = 16 GB + 3.2 GB = ≈ 19.2 GB → fits the 32 GB ceiling (§4); HITS (+CSR side) ≈ +8 GB still fits.
  4. Iterations to ε. ⌈ln(1e-6)/ln(0.85)⌉ = ⌈−13.816/−0.1625⌉ = ⌈85.0⌉ = 85 (§8.5, M11) — independent of graph size.
  5. SpMV read traffic / iter (web-BerkStan, m=7.6M): per edge read row_idx(4)+recip(8)+ gathered rank_in(8) ≈ 20 B ⇒ 7.6e6·20 ≈ 152 MB/iter. At ~25 GB/s usable BW ⇒ ≈ 6 ms/iter → matches p50 (M3).
  6. Throughput sanity. 2m FLOP = 1.52e7 FLOP/iter; at 6 ms ⇒ 2.5 GFLOP/s one-core class; 8-thread target 6 GFLOP/s ⇒ ~2.5 ms/iter (BW-bound, M2).
  7. End-to-end (web-BerkStan, 8t). parse ~1.2 s (#9) + build ~0.1 s (M7) + 85·~3 ms ≈ 0.26 s ⇒ ≈ 1.6 s ≤ M5 (2 s). The binary cache removes the parse term on re-runs.
  8. FD budget. 1 mmap graph + 1 output + 3 std = ~5 FDs, O(1) in n (§4) — no per-node descriptors.
  9. SNAP parse time. web-BerkStan text ≈ 120 MB / 100 MB/s (M6) ≈ 1.2 s — the end-to-end long pole, motivating the CSR cache (§28 tail note).
  10. WebGraph BV size. 7.6M edges · 4 bits / 8 ≈ 3.8 MB vs ~120 MB text ⇒ ~30× smaller; in-core BV is the §29 adjacency-compression lever.
  11. Local-push PPR work. O(1/ε) at ε=1e-5 ⇒ ~10⁵ pushes · d̄ ≈ 10⁶ edge-touches ⇒ sub-ms to tens of ms ≤ M8 (50 ms), independent of n (MM5).
  12. Parallel determinism bound. worst-case float error ≤ n·f64::EPSILON = 1e8·2.2e-16 ≈ 2.2e-8 (I5) — two orders below ε=1e-6, so the convergence decision is never flipped by reordering.
