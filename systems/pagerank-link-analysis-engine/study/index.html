Hard questions (§33)

  1. Why CSC and not CSR for the PageRank kernel, and what changes for HITS? (§8.1 + §11.3 + §16)

  3. Show how the dangling pre-pass preserves Σr=1, and what specific bias appears if you drop it. (§8.2 + I1/I2 + §23 C4)
  4. Why is parallel output allowed to differ from sequential, and by how much — and why doesn't that break the convergence test? (P5 + I5 + §32 #12)

  6. When does LocalPushPpr beat ExactPpr, and what error do you accept for the speedup? (§8.7 + §17 + MM5)
  7. How does the co-located src_out_deg_recip change the SpMV's cache behavior, and what does it cost in memory? (§11.3 + P3 + §32 #1)
  8. Trace a crafted CSR binary with m ≫ file length through the load path; which invariant stops the OOB and where? (I12 + §22 T4 + §13.2)
  9. Why reject d=1.0 and d=0.0, in Markov-chain terms? (§8.2 + I7 + MM9)
  10. What is the TKC effect, why is HITS vulnerable, and why is SALSA less so? (§16 + §22 T9 + §5 Lempel–Moran)
  11. Give the memory budget for a 10⁹-edge graph and the first scaling wall you hit. (§4 + §32 #3 + §29)
  12. How does TrustRank turn PageRank into a spam defense, and how are trusted seeds chosen? (§18 + §22 T8 + §5 Gyöngyi)

  14. Which floating-point pitfalls flip a "converged" verdict, and how does the engine bound them? (P5 + §14.6 + §32 #12)

  16. Distinguish the convergence rate's dependence on d vs on the graph spectrum. (§8.5 + MM4 + §5 Kamvar)

  18. If asked to scale past one host, which architecture would you pick and what coordination cost does it add? (§29 + §34 A1 + §35)

30. Mental Models & First Principles

MM1 — PageRank is a Markov chain's stationary vector; the Google matrix just makes that chain well-behaved. Predicts: a unique, positive r exists and power iteration finds it (Perron–Frobenius). Bug without it: inventing ad-hoc "fixes" for dangling mass instead of seeing them as restoring stochasticity. Applied: §8.1–8.2.

MM2 — SpMV is a memory-bandwidth problem in an arithmetic costume. The cost is the random gather rank_in[row_idx[k]], not the multiply–add. Predicts: cores saturate bandwidth before FLOPs; layout/prefetch beat vectorization. Bug without it: hand-tuning the multiply while the LLC thrashes. Applied: §28, P3, ADR-04.

MM3 — Rank flows opposite to links, so you iterate the transpose. Predicts: PageRank wants CSC (in-links); HITS needs both CSR and CSC. Bug without it: building only CSR and writing a push that mis-attributes mass. Applied: §8.1, §11.3, §16.

MM4 — Damping is a fidelity/conditioning knob: |λ₂| ≤ d. Predicts: d→1 ranks more faithfully but converges slower and conditions worse. Bug without it: setting d=0.99, then blaming the solver for 1000 iterations. Applied: §8.5, §32 #4.

MM5 — Local computation touches only the support it needs. Push-PPR is O(1/ε), independent of n. Predicts: a single-seed PPR is cheap even on a billion-node graph. Bug without it: running global power iteration once per seed. Applied: §8.7, §17.

MM6 — Probability is conserved or the ranking is wrong. Σr = 1 is a hard invariant. Predicts: any leak (dangling, drift) biases every score. Bug without it: skipping the dangling pre-pass and shipping a sub-stochastic vector. Applied: I1/I2, §8.2.

MM7 — A parallel kernel is only correct relative to a sequential oracle. "Correct" means "agrees with the reference within a stated float bound," not "looks plausible." Predicts: you can ship parallelism safely only behind a diff test (I5). Bug without it: trusting the fast path and shipping reordered, wrong ranks. Applied: P1, §15, §26.

MM8 — Untrusted bytes are hostile until validated; the parser is the security perimeter. Predicts: every decoded length/index is a potential OOB or overflow. Bug without it: an unwrap() in the BV decoder that a crafted file turns into a crash. Applied: §22, Phase 9.

MM9 — Teleportation is a regularizer that makes the chain ergodic, not a hack. Predicts: removing it can break convergence on real (reducible/periodic) web graphs. Bug without it: allowing d=1 and getting non-convergence or a non-unique fixpoint. Applied: §8.2, I7.

  • Leskovec, Rajaraman & Ullman — Mining of Massive Datasets (3rd ed., Cambridge). Ch. 5 (PageRank, dangling "spider traps/dead ends", topic-sensitive, link spam). Applied: Phase 2 (§14), Phase 5 (§17), Phase 6 (§18), and the spam discussion in §22.

Glossary (§36) · 46 terms · site-wide glossary

Adjacency matrix
n×n matrix A, A[i][j]=1 iff edge j→i; for web graphs extremely sparse.
Aperiodicity
a Markov-chain property (no fixed return period); guaranteed by teleportation, required for a unique stationary vector.
Authority score
HITS score of a node as a destination; principal eigenvector of AᵀA.
Bipartite graph
nodes split into two sets with all edges between them; SALSA's model.
BSP / superstep
Bulk-Synchronous-Parallel; computation in barrier-separated rounds (the Pregel/distributed model, §34).
Co-array (src_out_deg_recip)
the reciprocal array laid parallel to row_idx so the SpMV reads it sequentially (P3, MM2).
Column-stochastic matrix
every column sums to 1; H is column-stochastic except dangling columns.
Convergence
successive iterates differing by < ε in the chosen norm.
CSR (Compressed Sparse Row)
row_ptr+col_idx; row i = out-neighbors of i.
CSC (Compressed Sparse Column)
transpose of CSR; column j = in-neighbors of j; the PageRank kernel's structure.
Damping factor d
probability of following a link vs teleporting; standard 0.85; |λ₂|≤d (MM4).
Dangling node
out-degree zero; leaks mass without the pre-pass (P2).
Dangling mass
total rank on dangling nodes, redistributed each iteration (I2).
Determinism (parallel)
bit-stability up to a documented ≤ n·ε float-reorder bound (I5, §32 #12).
Eigenvector
A·v=λ·v; PageRank is the principal eigenvector (λ=1) of the Google matrix.
Ergodicity
irreducible + aperiodic ⇒ a unique reachable stationary distribution.
GFLOP/s
10⁹ float ops/s; SpMV does 2m FLOP/iteration.
Google matrix G
d·S + (1−d)/n·11ᵀ; primitive; PageRank is its principal eigenvector.
Hub score
HITS score as a source; principal eigenvector of AAᵀ.
Irreducibility
every state reachable from every other; given by teleportation.
L1 norm
Σ|xᵢ|; PageRank convergence/normalization.
L2 norm
√Σxᵢ²; HITS normalization (I13).
Local push (Andersen–Chung–Lang)
residual-driven sublinear PPR, O(1/ε) (MM5).
Markov chain
memoryless stochastic process; the random surfer.
mmap
memory-mapped file I/O; zero-copy CSR/CSC load (ADR-08).
NodeId
dense u32 post-remap identifier (ADR-17).
Out-degree reciprocal
1/outdeg(i) (0 if dangling), precomputed, finite (I4).
PageRank
stationary distribution of the Google matrix (Brin–Page 1998).
Perron–Frobenius
theorem guaranteeing a positive principal eigenvector for a non-negative primitive matrix (I3).
Personalized PageRank (PPR)
PageRank with seed-concentrated teleportation; proximity to the seed.
Power iteration
r⁽ᵏ⁺¹⟩=G·r⁽ᵏ⁾; converges to PageRank at rate |λ₂|≤d.
Pull vs push SpMV
pull: destination gathers from in-neighbors (this kernel); push: source scatters to out-neighbors (McSherry, MM2).
Roaring bitmap
hybrid array/bitset set; the DanglingBitVec (ADR-07).
SALSA
Lempel–Moran bipartite stochastic link analysis; TKC-robust HITS variant.
Seed set
teleportation target nodes for PPR/TrustRank (I14).
Spammicity
anti_trust/(trust+anti_trust); combined spam signal (§18).
Spectral gap
1−|λ₂|; larger ⇒ faster convergence.
SpMV
sparse matrix–vector multiply; the core kernel (MM2).
Stationary distribution
π=G·π; PageRank.
Teleportation
(1−d) jump to a (seed or uniform) vector; the ergodicity regularizer (MM9).
TKC (Tightly-Knit-Community) effect
a dense clique hijacking HITS hub/authority mass (T9).
TrustRank
PPR from a trusted seed set; spam defense (§18).
Vertex-cut
edge-partitioning for power-law graphs (PowerGraph, §31).
WebGraph BV format
compressed graph encoding (copy lists, intervals, residuals); 3–5 bits/edge (§8.8).
ζ (zeta) coding ζₖ
universal integer code tuned to ~1/x^{1+1/k}; ζ₃ suits web-graph degrees.
γ (gamma) coding
universal code: unary length of k+1 then its low bits. ---
