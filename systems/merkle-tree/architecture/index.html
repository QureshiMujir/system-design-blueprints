Bindings layer. PyO3 and wasm-bindgen marshal types across an FFI seam into a no_std verifier subset; Solidity helpers consume the same canonical proof bytes (§8.2) directly. No tree-construction logic lives in a host language (P10).

High-Level Tree APIs. Four independent tree types share the Tree trait (§11.3) but never share mutable state; each specializes the Core Tree Engine for its own indexing scheme (u64 for binary/CT, [u8; 32] for sparse/Patricia keys).

Proof System. Inclusion, exclusion, and consistency proofs are cross-variant concepts implemented once per tree family but sharing one canonical wire format (§8.2) and one verification discipline (constant-time, §7 I2).

Concurrent Build. Rayon-backed parallel leaf-hashing and internal-level hashing that must produce bit-identical roots to the serial path (I3) — the one place performance and correctness are jointly gated.

Anti-Entropy Diff. A protocol layered over any two trees implementing Diffable (§11.10), independent of tree family, consumed by sibling replication projects (§2).

Core Tree Engine. The shared node/level/index model and the domain-separated hashing discipline (§7 I1) that every tree family specializes rather than reimplements.

Storage Backend Trait. Three backends (§17) implement one trait; tree code never branches on backend identity (I6) — this is the single seam where persistence is selected.

Hash Trait. The bottom of the stack; every layer above takes a Hasher type parameter, never a concrete hash function (P4).

8. Domain Model / Protocol / Data Model

8.1 Grammar — Hex-Prefix Nibble Encoding (EBNF)

nibble        = %x00-0F
nibble-path   = *nibble
hex-prefix    = flag-byte payload
flag-byte     = leaf-even / leaf-odd / ext-even / ext-odd
leaf-even     = %x20                    ; leaf, even nibble count
leaf-odd      = %x30 nibble             ; leaf, odd count: nibble packed low
ext-even      = %x00                    ; extension, even nibble count
ext-odd       = %x10 nibble             ; extension, odd count: nibble packed low
payload       = *( nibble nibble )      ; remaining nibbles, 2 packed per byte

Yellow paper Appendix C. Every quirk of the Patricia trie's node encoding (§19) traces to this four-way flag-byte split.

8.2 Canonical Wire Layout — Proof Bytes

Field Size Notes
magic 4 bytes ASCII "MPRF"
proof_kind 1 byte 0x01 inclusion / 0x02 consistency / 0x03 exclusion / 0x04 batch
hash_family 1 byte 0x01 SHA-256 / 0x02 Blake3 / 0x03 Poseidon (deferred) / 0x04 Keccak-256
tree_size 8 bytes, BE tree size at proof generation
leaf_index 8 bytes, BE leaf index authenticated
sibling_count 2 bytes, BE N
siblings N × digest-width bytes leaf-to-root order
crc32 4 bytes transport-corruption check

Decoders reject unknown magic, proof_kind, or hash_family with typed errors (I4, I7).

8.3 State Machine — CT Log Append (Spine, §15)

State Trigger Action Next State Invariant Checked
spine[level] empty append(leaf), level = 0, node = hash_leaf(leaf) write node to spine[level] size += 1, done I3, I8
spine[level] occupied node arrives at level node' = hash_internal(spine[level], node); clear spine[level] level += 1, retry at new level with node' I3, I8
all levels exhausted level ≥ spine.len() grow spine by one slot write node at new top level I3

The "spine" is a base-2 accumulator of unfinished subtree hashes — MM5 (§31).

8.4 Worked Example — Four-Leaf SHA-256 Trace

Leaves a, b, c, d. h(x) = SHA256(0x00‖x). n(x,y) = SHA256(0x01‖x‖y).

root = n( n(h(a), h(b)), n(h(c), h(d)) ).

An inclusion proof for leaf b (index 1) is [h(a), n(h(c), h(d))]; verification recomputes n(h(a), h(b)) then n(n(h(a),h(b)), n(h(c),h(d))) and constant-time-compares against the published root (I2). This trace is recorded bit-for-bit in conformance/corpora/smoke/four_leaf_sha256.json (§12.5). The empty-log root (0 leaves) is SHA256(""), not the all-zero digest — RFC 6962 section 2.1 defines it explicitly (§15.6).

8.5 Malformed-Input Example

A proof whose sibling_count field (§8.2) disagrees with the actual number of trailing 32-byte groups present: the decoder returns ProofError::LengthMismatch before touching any hash function. Fixture: conformance/corpora/batch/forged.jsonl (§20.5).

8.6 Failure-Path Example

A consistency-proof verifier recomputes root_old successfully but the recomputed root_new fails the constant-time comparison against the published new root: verify() returns false; merkle_proof_verifications_total{outcome="fail"} increments; no state is mutated; the caller's runbook (runbook/proof-rejection.md, §22.3) triages hash-family mismatch, tree-size drift, and root-snapshot rotation, in that order.

Design principles (§6)

  • P1 — The verifier is the ground truth. Every tree variant ships a verifier first, prover second. The verifier is no_std, allocation-minimal, and the only code a downstream contract or browser embeds. Tradeoff: prover ergonomics come second. Operational implication: verifier code gets 10× the fuzz/review budget (§27). Violated: an incorrect verifier accepts forged proofs — a safety failure, not just a liveness one.
  • P2 — Domain separation is non-negotiable. Leaves hashed with 0x00, internal nodes with 0x01 (RFC 6962 section 2.1.2), enforced identically across all four tree families. Tradeoff: one extra byte per hash call. Operational implication: a CI lint (no_raw_hash.rs, §13) blocks any bypass. Violated: opens the second-preimage substitution attack (§23 T1).
  • P3 — Constant-time where it counts. Every proof-bytes comparison gating authentication uses subtle::ConstantTimeEq; no == on a digest anywhere in a verifier path. Tradeoff: marginal CPU cost. Operational implication: a clippy disallowed_methods lint enforces it. Violated: opens a timing side-channel (§23 T11).
  • P4 — Hashing is the tree's property, not the engine's. A tree's hash type is a generic parameter and metadata field; it never silently switches. Tradeoff: one more generic parameter threaded everywhere. Operational implication: mismatched hash families are a typed error, never a coercion (I4). Violated: silent cross-hash verification produces meaningless "passes" (§23 T5).
  • P5 — One library, four trees, three backends. Backends never leak into tree code; trees talk only to the Storage trait (§11.4). Tradeoff: one dynamic-dispatch seam. Operational implication: swapping backends requires zero tree-code changes (§17). Violated: backend-specific branches make the conformance "same suite, any backend" property (§27) false.
  • P6 — Proofs are bytes, not structs over the wire. The canonical proof form (§8.2) is fixed binary; the struct is in-memory ergonomics only. Tradeoff: a codec layer. Operational implication: conformance compares bytes, not structs (I7). Violated: a serde-derived struct dump drifts silently across Rust versions.
  • P7 — Determinism is the default. Same leaves, same order ⇒ bit-identical root on every host/backend/thread-count (I3). Tradeoff: parallel reduction must preserve input order, costing a reassembly step. Operational implication: --paranoid CI mode compares serial vs. parallel roots on every push. Violated: two replicas of "the same" tree disagree, breaking every proof exchanged between them.
  • P8 — No silent fallbacks. An unsupported proof request returns a typed error, never a best-effort output (I5). Tradeoff: callers must handle more error variants. Operational implication: API surface stays honest about what each tree family can prove. Violated: a "best-effort" proof looks valid but authenticates nothing.
  • P9 — The diff API owns its semantics. The anti-entropy diff (§20) ships a written exactness/determinism/symmetry contract (docs/anti-entropy.md). Tradeoff: the contract constrains future optimizations. Operational implication: two sibling replication projects (§2) depend on this contract holding. Violated: silently incomplete reconciliation corrupts replicated state.
  • P10 — Bindings are drivers, not hosts. Python/JS bindings marshal types; they never implement tree logic in the host language. Tradeoff: ergonomics-first APIs need extra wrapper code. Operational implication: a drift check (.pyi/.d.ts regenerated from Rust, FM10) runs in CI. Violated: two divergent implementations of the same algorithm exist, doubling the audit surface.
  • P11 — no_std first for the verifier; std for the prover. The verifier crate enables #![no_std] unconditionally (I14). Tradeoff: two crates instead of one. Operational implication: enables browser-WASM and on-chain-bridge embedding (§21). Violated: the verifier cannot compile for wasm32-unknown-unknown, closing off two of the library's three target contexts.
  • P12 — Endian discipline. Hash inputs are big-endian where the spec is big-endian (RFC 6962, Bitcoin) and per-context for Ethereum RLP integers; documented at every call site. Tradeoff: no single blanket endian rule. Operational implication: debug-build layout assertions catch drift before release (I15). Violated: cross-architecture root mismatches that only manifest on non-x86 hosts (§23, FM-class).
