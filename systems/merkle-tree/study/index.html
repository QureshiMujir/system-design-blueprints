31. Mental Models & First Principles

  • MM1 — A Merkle root is a recursive commitment, not a checksum. Predicts: two trees with the same leaf multiset in different order produce different roots. Bug without it: assuming order-independence, enabling a permutation attack. Resolving: §8.4, §14.
  • MM2 — Domain separation is a type, not a convention. Predicts: any construction without a prefix byte is vulnerable to a specific leaf/internal substitution. Bug without it: the general class of second-preimage bugs the literature keeps re-discovering. Resolving: §6 (P2), §7 (I1), §23 (T1).
  • MM3 — A proof is a claim plus a recomputation contract. Predicts: any verifier trusting an embedded root field instead of recomputing from siblings is broken. Bug without it: accepting attacker-supplied roots. Resolving: §11.5, §23 (T2).
  • MM4 — Default-subtree caching turns an intractable tree into a lazy one. Predicts: a naive sparse-tree implementation that materializes nodes OOMs. Bug without it: FM5. Resolving: §18, §33 (item 12).
  • MM5 — Append-only logs trade mutability for provable history. Predicts: append cost concentrates near power-of-two boundaries (amortized O(log N), worst-case per-append O(log N)). Bug without it: assuming O(1) append and being surprised by tail latency at power-of-two boundaries. Resolving: §15, §29.
  • MM6 — Anti-entropy is binary search over a hash tree. Predicts: divergence cost is O(D log N) bytes, not O(N). Bug without it: a naive full-tree diff at O(N). Resolving: §20, §33 (item 10).
  • MM7 — A trie node's encoding is data-dependent, not fixed-size. Predicts: small value changes can cascade re-encoding up the path. Bug without it: caching inline/hash decisions without invalidation (FM4). Resolving: §19.
  • MM8 — The verifier is the security boundary; the prover is a convenience. Predicts: verifier code deserves far more review/fuzz budget than prover code. Bug without it: teams under-fuzz the verifier while over-investing in the prover. Resolving: §6 (P1), §27, §29.

5. Required Reading

Books

  • Katz, J., Lindell, Y. — Introduction to Modern Cryptography, 3rd ed. (CRC Press, 2020). Ch. 8 "MACs and Collision-Resistant Hash Functions" — formal collision-resistance definitions underlying the second-preimage argument. Applied in §7 I1, §23 T1.
  • Boneh, D., Shoup, V. — A Graduate Course in Applied Cryptography, v0.6 (free, 2023). Ch. 8.5 "Merkle trees", Ch. 24 "Commitment schemes" — the tree-as-commitment framing and the accumulator generalization. Applied in §8, §35.
  • Antonopoulos, A. — Mastering Bitcoin, 3rd ed. (O'Reilly, 2023). Ch. 9 block-header Merkle-root section — the odd-leaf duplication convention and CVE-2012-2459. Applied in §9 ADR-08, §14 (Phase 2).
  • Antonopoulos, A., Wood, G. — Mastering Ethereum (O'Reilly, 2018). Ch. 4 "Cryptography", Ch. 13 state-trie discussion — the modified Merkle Patricia trie and eth_getProof shape. Applied in §19 (Phase 7).

Reference Implementations

  • google/certificate-transparency-go + google/trillian — study trillian/merkle/. Lesson: a production RFC 6962 log at scale. Pitfall: Trillian's storage abstraction is heavier than this library needs — study the proof math, not the storage layer. Applied in §15 (Phase 3).
  • go-ethereum — study trie/, core/state/, crypto/. Lesson: the canonical Patricia encoding and eth_getProof shape. Pitfall: years of pruning/caching complexity accreted on top — read the algorithm, not the cache heuristics. Applied in §19 (Phase 7).
  • Diem/Aptos Jellyfish Merkle Tree — study storage/jellyfish-merkle/src/lib.rs. Lesson: a production sparse tree with extension-node compression. Pitfall: its version-pruning model assumes a specific blockchain-state lifecycle — do not copy it wholesale. Applied in §18 (Phase 6).
  • Bitcoin Core — study src/consensus/merkle.cpp. Lesson: the historical odd-leaf duplication rule and CVE-2012-2459. Pitfall: never adopt duplication as the default — ship it opt-in only. Applied in §9 ADR-08, §14 (Phase 2).
  • rs_merkle crate (crates.io). Lesson: an idiomatic Rust binary-Merkle API surface. Pitfall: its default hasher does not enforce domain separation — do not copy that gap. Applied in §13 (Phase 1).
  • OpenZeppelin contracts/utils/cryptography/MerkleProof.sol. Lesson: the reference on-chain verifier shape and gas-optimized loop. Pitfall: its keccak256 concatenation order differs from RFC 6962's prefix convention — the Solidity helpers (§21.4) document which convention they implement. Applied in §21 (Phase 9).

Glossary (§37) · 57 terms · site-wide glossary

Merkle root
the single digest at the top of a Merkle tree committing to every leaf.
Merkle tree
a hash tree where every internal node is a hash of its children.
Leaf hash
H(0x00‖leaf_bytes); domain-separated from internal hashes (I1).
Internal hash
H(0x01‖left‖right); domain-separated from leaf hashes (I1).
Domain separation
using distinct prefix bytes so leaf and internal hash inputs can never collide in interpretation.
Second-preimage attack
forging a different input that hashes to an existing digest; the specific risk domain separation defends against here.
Inclusion proof
sibling hashes from a leaf to the root, proving that leaf's membership.
Exclusion (non-membership) proof
proof that a key is not present in a tree.
Consistency proof
proof that one tree snapshot is an append-only extension of an earlier one (RFC 6962 section 2.1.4).
Audit path
synonym for the sibling list in an inclusion proof.
Tree size
the count of leaves committed to by a given root (CT semantics).
Snapshot
a durable (size, root) pair identifying a tree at a point in time.
Spine
the CT log's base-2 accumulator of unfinished subtree hashes (§8.3).
Append-only log
a data structure that only grows; no leaf is ever rewritten.
Certificate Transparency (CT)
the RFC 6962 public append-only log system for TLS certificates.
SCT (Signed Certificate Timestamp)
a CT log's promise to include a certificate.
Sparse Merkle tree (SMT)
a Merkle tree over a huge (e.g. 2^256) mostly-empty keyspace, using default-subtree compression.
Default subtree
the precomputed hash of an all-empty subtree at a given level (I9).
Bitset (proof)
a bitmap recording which sibling levels are present in a compressed sparse-tree proof.
Patricia trie
a radix trie with path compression; Ethereum's variant uses hex-prefix encoding (§8.1).
Hex-prefix encoding
the one-byte-flag nibble-path encoding distinguishing leaf/extension and odd/even nibble counts (yellow paper App. C).
RLP (Recursive Length Prefix)
Ethereum's canonical byte-serialization format.
Nibble
a 4-bit half-byte; the Patricia trie's path unit.
Branch node
a Patricia node with up to 16 children, one per nibble value.
Extension node
a Patricia node compressing a run of single-child path segments.
NodeRef
either an inline (< 32-byte) RLP encoding or a 32-byte hash reference.
Account proof
an eth_getProof-shaped Patricia inclusion proof for an account.
Storage proof
a Patricia inclusion proof rooted at an account's storage root.
Batch (multi-)proof
a single proof authenticating multiple leaves with shared siblings sent once.
Range proof
a batch proof specialized to a contiguous index range, with a boundary leaf proving tightness.
Anti-entropy
a protocol reconciling two replicas' divergent state via hash comparison (Demers et al. 1987).
Diff protocol
this library's anti-entropy implementation (§20), producing an exact, deterministic, symmetric Diff.
Epidemic algorithm
the general family anti-entropy/gossip protocols belong to.
Accumulator (cryptographic)
a commitment to a set supporting membership proofs in size independent of set size.
Vector commitment
a commitment to a vector of values supporting position-binding openings; Merkle trees are one instance.
KZG commitment
a pairing-based polynomial commitment scheme used in Verkle trees.
IPA (Inner Product Argument)
a pairing-free polynomial-commitment alternative to KZG, also usable for Verkle trees.
Poseidon
a ZK-circuit-friendly hash function (Grassi et al. 2021), deferred here.
Constant-time comparison
a comparison whose execution time is independent of where the first mismatching byte occurs (I2).
WAL (Write-Ahead Log)
a durability mechanism recording intent before mutating the primary structure.
mmap
mapping a file into a process's virtual address space for direct read/write.
LSM-tree
a write-optimized storage structure using sorted, merged levels; one of this library's two KV-backend options.
B-tree
a balanced, disk-friendly tree structure; the other KV-backend option.
RTO (Recovery Time Objective)
the maximum acceptable time to recover after a crash.
SLO (Service-Level Objective)
a target value or range for a measured service metric.
Strong scaling
the speedup achieved by adding more cores at fixed problem size.
Tail latency
the latency of the slowest (e.g. p99) requests, as distinct from the average.
Gas (Ethereum)
the unit of computational cost charged for EVM execution.
Calldata
the read-only input byte array passed to an EVM contract call.
SemVer
Semantic Versioning: MAJOR.MINOR.PATCH with defined compatibility meaning.
SBOM (Software Bill of Materials)
a machine-readable manifest of a build's dependencies.
Provenance / attestation
a cryptographically verifiable record of how an artifact was built.
Fuzzing
feeding a program pseudo-random or mutated input to find crashes/UB.
Property-based testing
testing that a property holds across many generated inputs, rather than fixed examples.
Conformance suite
this library's bit-exact test harness against reference vectors and other implementations (§27).
no_std
a Rust crate attribute excluding the standard library, required for bare-metal/WASM/embedded targets.
MSRV (Minimum Supported Rust Version)
the oldest Rust toolchain version a crate guarantees to build under.
