30. Mental Models & First Principles

  • MM1 — The Observer Must Not Move the Needle. Compressed insight: any metrics or tracing path that can influence scheduling decisions has silently become part of the system under test · Predicts: heisenbug-class failures that vanish under instrumentation · Bug class without it: "it only reproduces without the profiler attached" · applies in §17, §20.
  • MM2 — Determinism Is a Closed-World Property. Compressed insight: a system is deterministic only if every input to every decision is accounted for, including ambient ones (wall clock, hash-map iteration order, thread scheduling) · Predicts: one un-audited entropy source eventually causes a replay divergence · Bug class without it: intermittent, unreproducible CI failures · applies in §12, §13.
  • MM3 — Backpressure Must Be Visible at Every Hop, Not Just the Edge. Compressed insight: a bounded queue at ingress with unbounded queues downstream just moves the collapse point, it does not remove it · Predicts: where in a pipeline a load spike will actually manifest as latency · Bug class without it: mysterious mid-pipeline queue growth despite a "protected" front door · applies in §14, §15.
  • MM4 — A Fair Scheduler Under Typical Load Can Still Starve Under Adversarial Load. Compressed insight: fairness must be proven against worst-case arrival patterns, not validated against typical traces · Predicts: a scheduler that passes every normal benchmark can still starve a class of work under a crafted pattern · Bug class without it: production starvation incidents with no matching pre-release test · applies in §14.
  • MM5 — Replay Equivalence Is the Only Trustworthy Debugging Oracle Here. Compressed insight: in a deterministic simulator, "it worked when I re-ran it" is not evidence of anything — either replay matches bit-for-bit or the bug is still present and merely unobserved · Predicts: any debugging approach relying on re-running under load will waste time · Bug class without it: chasing a bug that "goes away" under a debugger · applies in §18, §26.
  • MM6 — Every Distributed Aggregation Must Be Associative and Commutative. Compressed insight: if merge order can ever matter, a network delay or a coordinator restart will eventually expose it · Predicts: distributed aggregation bugs that correlate with network jitter, not with load · Bug class without it: aggregate metrics that differ from a single-node equivalent run for no apparent reason · applies in §17, §19.
  • MM7 — A Structural Cycle and a Resource Deadlock Are Different Bugs With Different Detectors. Compressed insight: conflating "the graph has a cycle" with "execution is permanently blocked" produces both false positives and false negatives · Predicts: a deadlock detector built as a cycle detector will misfire on legitimate backpressure · Bug class without it: false-positive deadlock alarms during normal saturation · applies in §15.
  • MM8 — Capacity Numbers Without Arithmetic Are Just Opinions. Compressed insight: every constraint in §4 must be derivable from a smaller set of physical facts (cache line size, syscall cost, network RTT), not asserted from intuition · Predicts: which constraints will actually hold up under a real workload versus which were guesses · Bug class without it: capacity-planning decisions built on numbers nobody can defend · applies in §4, §32.

5. Required Reading

Books

  • The Art of Computer Systems Performance Analysis — Raj Jain (1991), ch. 1–5 and 10–16: queueing metrics, simulation methodology, confidence-interval construction; applied in §17 and §26.
  • Queueing Systems, Volume 1: Theory — Leonard Kleinrock (1975), ch. 2–7: M/M/1 analysis, Jackson-network product-form solutions, Little's Law; applied in §15 and §32.
  • Performance Modeling and Design of Computer Systems — Mor Harchol-Balter (2013), ch. 1–12: scheduling fairness, tail-latency theory, SRPT optimality; applied in §14 and §28.
  • Designing Data-Intensive Applications — Martin Kleppmann (2017), reliability/consistency/stream-processing chapters: crash-only design and log-structured storage reasoning; applied in §18.
  • Systems Performance — Brendan Gregg (2nd ed., 2020), CPU/memory/I/O analysis and observability chapters: the USE method behind §20's diagnostics; applied in §20.
  • Discrete-Event Simulation: A First Course — Lawrence Leemis and Stephen Park (2006), event-list management and output-analysis chapters: theoretical basis for the heap design and warm-up exclusion; applied in §13 and §17.

Papers

  • "MapReduce: Simplified Data Processing on Large Clusters" — Dean & Ghemawat, 2004, OSDI: batch-execution partitioning model informs Monte Carlo work partitioning; applied in §19.
  • "The Tail at Scale" — Dean & Barroso, 2013, CACM: tail-latency amplification across fan-out hops drives the §28 p99/p99.9 targets; applied in §28.
  • "Dapper, a Large-Scale Distributed Systems Tracing Infrastructure" — Sigelman et al., 2010, Google technical report: trace-context propagation model behind trace_context; applied in §20.
  • "Disruptor: High Performance Alternative to Bounded Queues" — Thompson, Farley, Barker, Gee, Stewart, 2011, LMAX whitepaper: mechanical-sympathy ring-buffer design informs event-heap cache locality; applied in §13.
  • "Scheduling Algorithms for Multiprogramming in a Hard-Real-Time Environment" — Liu & Layland, 1973, JACM: EDF optimality proof underlies the EarliestDeadlineFirst discipline; applied in §14.
  • "Kafka: a Distributed Messaging System for Log Processing" — Kreps, Narkhede, Rao, 2011, NetDB: append-only durable log design behind the WAL segment model; applied in §18.
  • "Virtual Time" — David Jefferson, 1985, ACM TOPLAS (the Time Warp mechanism): optimistic-execution rollback semantics; applied in §34.
  • "A Proof for the Queuing Formula: L = λW" — J.D.C. Little, 1961, Operations Research: the conservation check used in the convergence validator; applied in §17.

Reference Implementations

  • ns-3 — study src/core/model/simulator.cc and default-simulator-impl.cc: event scheduling correctness and cancellation semantics; pitfall: do not copy its non-deterministic multi-threaded scheduler variant; applied in §13.
  • SimPy — study simpy/events.py and simpy/core.py: minimal event-list simplicity; pitfall: its single-process generator model does not scale past one core, do not inherit that ceiling; applied in §13.
  • OMNeT++ — study its cSimpleModule scheduler and message-scheduling core: strong modularity boundary between model and kernel; pitfall: its GUI-coupled event inspector adds overhead unsuitable for a 5M ev/s budget; applied in §15.
  • Tokio — study tokio/src/runtime/scheduler and its timer-wheel implementation: cooperative-scheduling and hierarchical-timer design; pitfall: do not adopt work-stealing for the deterministic single-shard event loop, it reintroduces ordering nondeterminism; applied in §13.
  • Aeron — study its ring-buffer and UnsafeBuffer IPC transport: lock-free single-producer/single-consumer messaging; pitfall: its unsafe-buffer aliasing tricks are unsafe outside Aeron's own invariants, do not port them verbatim; applied in §18.

RFCs / Specifications

  • RFC 8949 — Concise Binary Object Representation (CBOR): pins down the canonical deterministic-encoding mode used for qts-core's canonical serialization; applied in §12.
  • RFC 3339 — Date and Time on the Internet: timestamp format for operator-facing logs and artifact metadata, never used as a simulation time source (P3); applied in §20.
  • Semantic Versioning 2.0.0 — pins down MAJOR/MINOR/PATCH compatibility semantics for wire and storage format evolution; applied in §25.

Glossary (§36) · 35 terms · site-wide glossary

SimTime
logical, deterministic simulation timestamp; never derived from wall clock (P3).
Replay Divergence
a measured difference between canonical and replay execution (I5); any occurrence is FM-1.
Saturation Ratio
queue occupancy divided by declared capacity (QueueMetrics, §11).
Service Discipline
the queue-scheduling algorithm governing dispatch order within a QueueNode (§8.3).
Tail Latency
high-percentile (p99/p99.9) latency, the primary subject of §28's performance methodology.
WAL
write-ahead log; the append-only durability mechanism underlying crash-only recovery (P4, §18).
Warm-Up Window
the initial, statistically unstable interval of a simulation run excluded from convergence analysis (§17).
Backpressure
downstream saturation propagating visibly to upstream admission decisions (P2).
Queue Collapse
unrecoverable latency amplification from sustained over-admission relative to service capacity.
Work Conservation
a scheduler property: never idle while admissible work is pending.
Starvation
indefinite postponement of a work item's service, bounded probabilistically under I6.
Lease
a time-bounded worker-ownership contract over a seed partition (WorkerLease, §11, I11).
Fanout
replication of a single event or work item to multiple downstream targets (broadcast routing, §8.4).
Replay Hash
the deterministic execution fingerprint chained through ReplayJournalRecord (§11).
Admission Control
the policy gating whether a WorkItem may enter a queue at all (I9).
Processor Sharing (PS)
a discipline simulating fair concurrent service among all queued items rather than strict sequential dispatch (§8.3).
Monte Carlo Run
one independent, seeded stochastic simulation replica within a campaign (§17).
Deterministic RNG
a random source whose every draw derives from an explicit seed lineage (qts-rng, I3, P12).
Conformance Fixture
a canonical validation artifact under fixtures/ (§10, §37) exercising a specific behavior or invariant.
Snapshot
a persisted, WAL-offset-paired runtime checkpoint (I10, §18).
Jackson Network
an open queueing network satisfying product-form solution assumptions (Kleinrock, §5); used as an analytical cross-validation fixture (§15.5).
Little's Law
L = λW, the conservation identity used as a convergence sanity check (§17, Little 1961, §5).
SRPT
Shortest Remaining Processing Time; a mean-response-time-optimal preemptive discipline (Harchol-Balter, §5).
EDF
Earliest Deadline First; optimal for deadline-feasibility under the Liu & Layland (1973) conditions (§5, §14).
Fencing Token
a monotonically increasing value preventing a stale lease holder from acting after reassignment (I11, §19).
Trust Boundary
an architectural line (§3 diagram) across which input must be validated because the far side is not fully controlled by this system.
Isolation Boundary
the P10/I8 architectural guarantee that observation cannot mutate the observed system.
Canonical Encoding
a serialization scheme guaranteeing byte-identical output for semantically equivalent structures (P9).
Divergence Analyzer
the qts-replay component comparing canonical and replay hash chains (§18).
Dead-Letter Queue
a terminal holding queue for WorkItems exceeding retry_count (§14).
Congestion-Adaptive Routing
a routing policy consulting live saturation metrics through the P10-isolated read view (§8.4, §15).
Batch Means
a variance-reduction technique for confidence-interval estimation from correlated simulation output (Jain, §5, §17).
Product-Form Solution
a closed-form joint-distribution result for certain queueing networks (Jackson networks, §5), used as an analytical sanity check, not as a runtime assumption.
Fuzz Corpus
the seed-input set (fixtures/conformance/fuzz_corpus_seed.bin) bootstrapping continuous fuzzing (§21).
Crash-Only Recovery
a design discipline where the only recovery path is restart from durable state, never in-place repair (P4).
