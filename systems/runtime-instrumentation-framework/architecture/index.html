Per-box: Process control — spawn the target stopped, ptrace it, inject the engine dylib; or attach to a running pid. Dispatcher — the heart: on entry, translate the current tag (block start) if not cached, then jump into the cache; blocks return to the dispatcher (or are linked directly, Phase 1). Translator — decode via #334, copy instructions into the cache verbatim except control flow (redirected to exits) and rip-relative operands (fixed up), with tool-requested probes inserted. IBL — indirect branches (ret/jmp reg/call reg) can't be statically linked → a fast hash lookup keeps execution in the cache. Code cache — executable memory holding translated blocks; direct branches between cached blocks are linked (patched to jump directly) to avoid dispatcher round-trips; hot sequences promote to traces (Phase 4). Probe API — what the tool calls to insert instrumentation; supports efficient inline updates and full clean calls (save state → call tool → restore). State save/restore — preserve the target's registers/flags across tool calls so transparency holds. Transparency + signals + SMC — keep the engine invisible (the target sees its own addresses, not cache addresses), forward signals, detect self-modifying code via write-protection and invalidate stale cache, support clean detach.

8. Domain Model

8.1 Core concepts

Tag         := original code address (block start) — the cache key
Block       := translated copy of one basic block (from #334 CFG), ending in a controlled exit
Trace       := a hot sequence of blocks stitched into one straight-line cache fragment (Phase 4)
CodeCache   := per-thread RX mmap region holding Blocks + Traces; tag→addr map
Exit stub   := code at a block's end that returns control to the dispatcher (or is linked)
Link        := a direct-branch exit patched to jump straight to the target block (no dispatch)
IBL         := indirect-branch lookup: hash(app_target)→cache_addr, taken in-cache
CleanCall   := save context → call tool analysis fn (ABI) → restore context
InsPoint    := where a probe attaches: RoutineEnter/Exit | BblEnter | InsBefore/After | MemRead/Write | BranchTaken

8.2 Translation rules (copy-and-patch)

for each insn in block (decoded by #334):
  - non-control, no rip-rel        → copy bytes verbatim
  - rip-relative operand           → rewrite disp so it resolves to the ORIGINAL address (I4)
  - direct jcc/jmp/call            → replace target with an EXIT stub (later LINKED, I5)
  - indirect jmp/call/ret          → replace with IBL sequence (I6)
  - insn matching a tool InsPoint  → emit probe (inline update or clean call, Phase 2)
block terminator → exit stub(tag = fallthrough/target)

8.3 Dispatcher state machine (per thread)

ENTER(tag) → lookup(tag):
   hit  → jump into cache block
   miss → translate(tag) → install in cache → (link predecessor if direct) → jump in
block runs → reaches exit:
   direct exit  → if target cached: LINK (patch to jump direct, future native) ; else dispatch(target)
   indirect exit→ IBL: hash app_target; hit→jump; miss→dispatch(app_target)
   tool/flush/signal → return to dispatcher with saved context

8.4 Clean-call ABI (transparency, I3)

on probe (clean call):
  push volatile + (if needed) all GPRs, RFLAGS, XMM (per ABI + what tool clobbers)
  align stack to 16; set args (InsPoint context: regs snapshot, mem addr, etc.)
  call tool_fn ; on return: restore saved state exactly ; continue in cache
inline probe (fast): e.g. `inc qword [counter]` with only RFLAGS save/restore — no full spill

8.5 Worked example — BBL-count tool

target loop block @0x4011a0 (3 insns, ends `jl 0x4011a0`):
translate → cache block @C: [insn0;insn1;insn2_cmp; INLINE: inc [bbl_count]; exit(jl→0x4011a0)]
first run: dispatch miss → translate → run; exit jl target 0x4011a0 cached? yes → LINK exit to C
subsequent iterations: stay in cache, jump direct C→C, inc counter inline → near-native + count
result: exact basic-block execution count with ~1 inc/block overhead (≤10×, §4)

8.6 Failure / hard-case examples

  • Indirect ret to a not-yet-translated address → IBL miss → dispatcher translates on demand (I6); never returns to original code (I1).
  • rip-relative lea/load → if copied verbatim, reads the cache address (wrong) → must fix disp to original (I4).
  • Target writes to a page holding code we cached (JIT/packer) → write-fault → invalidate that cache region (I7).
  • Signal arrives while in a cache block → must build a siginfo/ucontext with the original PC (I9), not the cache PC.
  • Two threads hit the same cold tag → per-thread caches translate independently (I10) (or shared cache with locking — deferred).
  • Tool callback clobbers a target register without declaring it → context save/restore must cover it (I3); declared clobbers optimize the spill.
  • A block ends mid-page at a permission boundary → translator stops the block at the boundary; next block on fault.

Design principles (§6)

  • Transparency above all. The instrumented target must behave identically (addresses, signals, timing-insensitivity aside) to the uninstrumented one. Violation: the target reads a cache address or sees the engine's memory → behavior diverges; "Heisenbug" instrumentation.
  • Never execute the target's original code. All execution happens in the code cache (translated copies); originals are read-only sources. Violation: a missed branch escapes the cache → uninstrumented execution, lost events, possible crash.
  • Preserve all register + flag state around analysis. Clean calls spill/refill the full context per the ABI. Violation: clobbering a target register → silent corruption.
  • Minimize overhead; make the common path native. Direct-branch linking + traces + inline probes keep hot code at near-native speed; the dispatcher is the slow fallback. Violation: a dispatcher round-trip per block → 100× slowdown.
  • Decode is authoritative (#334). All translation uses #334's decoder + CFG; no ad-hoc parsing. Violation: a mis-decode corrupts the translated block.
  • Self-modifying / generated code is handled, not ignored. Write-protect translated regions; on write fault, invalidate the affected cache. Violation: the target rewrites code we cached → we run stale instructions.
  • Thread-local by default. Each thread owns its code cache + scratch; shared structures are explicitly synchronized. Violation: two threads patching one cache → torn code, crash.
  • Determinism of instrumentation. Given the same target execution, the same probes fire in the same order. Violation: non-reproducible traces → undebuggable analysis.
  • Bounded, evictable cache. The code cache has a capacity; it evicts/flushes safely rather than growing unbounded. Violation: OOM on a long-running target.
  • Signals + exceptions are faithfully forwarded. A fault in cached code is reported with the original fault address/context. Violation: the target's signal handler sees a cache address → wrong behavior.
  • Isolated unsafe. Raw memory, ptrace, and code patching live in audited modules (ri-attach/ri-cache/ri-context); the rest is safe Rust. Violation: UB sprayed across the codebase.
  • Clean attach + detach. Detaching restores the target to native execution with no residual patches/traps. Violation: a half-removed detour crashes the target after detach.
