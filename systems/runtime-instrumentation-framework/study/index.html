Mental Models & First Principles

The compressed insights an expert holds about a DBI engine. Each: the model, what it predicts, the bug class you write without it, and the resolving section.

  • MM1 — The code cache is a write-back cache over the target's .text; the dispatcher is its miss handler. Predicts: every transition is either a cache hit (in-cache jump/link) or a miss (dispatch → translate → install); steady-state cost ≈ miss-rate × translate-cost, so the entire optimization story is miss elimination (link, IBL, trace). Without it: you treat translation as a one-time setup and never budget the cold-miss tail, then watch a phase-changing program (new code regions) stall periodically. Resolves in: §3 Architectural Overview, Phase 0, Phase 1.
  • MM2 — The target's address space is the ground truth; the cache is a hidden shadow that must never leak. Predicts: any value the target can observe (a PC via lea/call, a return address on the stack, a /proc/self/maps line, a signal ucontext) must read the original address, while execution silently happens in the shadow. Without it: the classic Heisenbug — a self-checking program (PIC base computation, stack unwinder, GC) diverges only under instrumentation. Resolves in: Phase 5 (transparency, I4), Phase 6 (signal context, I9), Appendix H.
  • MM3 — Instrumentation is a function inserted at translate time, not execute time. Predicts: the cost of a probe is paid once at translation (code-size growth) plus per-execution (the inserted op); a clean call's expense is the spill frame, not the call. Without it: you reach for per-instruction traps (Pin's rejected int3 path) and eat microseconds per probe instead of nanoseconds. Resolves in: Phase 2 (probe API), ADR-004.
  • MM4 — Direct branches can be resolved (linked) but indirect branches can only be looked up. Predicts: a direct jcc/jmp/call has a statically known target → patch it once to a cache address (link); a ret/jmp reg/call reg has a runtime target → it needs a per-execution hash probe (IBL) that verifies the tag. Without it: you either try to "link" an indirect branch (impossible, wild jump) or dispatch every direct branch (100× slowdown). Resolves in: Phase 1 (linking, I5), Phase 3 (IBL, I6).
  • MM5 — Verify the tag, not the hash. Predicts: an IBL hash collision returns a plausible but wrong cache address; only comparing the stored app-target tag to the requested one keeps correctness; the hash is just a bucket index. Without it: a collision sends execution into the wrong function — silent corruption that fuzzing surfaces only probabilistically. Resolves in: Phase 3 (I6), Appendix G.4.
  • MM6 — Page protection is the only cheap SMC tripwire you have. Predicts: you cannot watch every store; you remove write permission from pages backing cached code and let the MMU fault tell you when the target rewrites code — at page granularity, so code+data on one page over-invalidates. Without it: a JIT or packer patches a function and the engine keeps running the stale cached copy — a behavior-changing bug with no crash (Appendix O is built around this). Resolves in: Phase 7 (I7).
  • MM7 — Freeing cached code is a concurrent-reclamation problem, not a free(). Predicts: another thread may be executing inside the block you want to flush; you must first repoint all incoming links (reverse-link map) to the dispatcher, then reach a quiescent state where no thread's PC is in the region, then free. Without it: use-after-free on the hottest possible memory — executable code another core is running. Resolves in: Phase 7 (flush), Phase 8 (quiescence, I8).
  • MM8 — A call pushes a return address, and that address is read by ret, by unwinders, and by the program itself — so it must be the app address, not the cache address. Predicts: you cannot naively let the translated call push the cache-side return PC; you push the app return address and rely on the IBL/return-cache to map it back to a cache block on ret. Without it: ret escapes the cache (or returns to the wrong place) and stack walks see cache addresses (I4 violation). Resolves in: Phase 3 (return cache), Phase 5 (return-address transparency).
  • MM9 — The engine always has a correct slow path; every optimization is an accelerator with a fallback. Predicts: linking falls back to dispatch, IBL miss falls back to dispatch, a trace side-exit falls back to a block, SMC falls back to re-translate — so a bug in any accelerator degrades performance, not correctness, if the fallback is wired. Without it: an optimization with no fallback turns a perf bug into a correctness bug (a wild jump). Resolves in: Failure Modes and Recovery, Phase 4 (side exits).
  • MM10 — Per-thread isolation converts a concurrency problem into a memory-cost problem. Predicts: giving each thread its own cache + IBL + scratch removes almost all cross-thread synchronization (the remaining shared state is read-mostly: module map), trading RAM (×threads) for the absence of locks on the hot path. Without it: you share one cache and pay a lock on every install/link, or worse, race and tear live code. Resolves in: Phase 8 (I10), Scalability Analysis.

Required reading (§5)

Books

  • Bruening, Efficient, Transparent, and Comprehensive Runtime Code Manipulation (PhD thesis, MIT, 2004). Extract: code cache, fragment linking, trace building (NET), the transparency taxonomy. Applied: Phase 0 (cache/dispatch), Phase 1 (linking), Phase 4 (traces), Phase 5 (transparency) — the project's backbone.
  • Intel® 64 and IA-32 Architectures Software Developer's Manual, Vol. 1–3. Extract: register/flag (RFLAGS) semantics, instruction side effects, exception classes. Applied: Phase 2 (which flags inc sets → save/restore), §8 Domain Model (translation rules), Phase 6 (fault classes).
  • Smith & Nair, Virtual Machines: Versatile Platforms for Systems and Processes (2005). Extract: process-VM theory, code caching, binary-translation chaining. Applied: §3 Architectural Overview (cache+dispatch model), Phase 0, Comparative Architecture Table.
  • Eilam, Reversing: Secrets of Reverse Engineering (2005) / Eagle, The IDA Pro Book (2nd ed., 2011). Extract: practical hooking/detour patterns, anti-instrumentation tricks targets use. Applied: Phase 5 (transparency adversaries), Threat Model (self-aware targets).
  • Love, Linux System Programming (2nd ed., 2013). Extract: ptrace, signals, mmap/mprotect, /proc. Applied: Phase 0 (spawn/inject), Phase 9 (attach), Phase 5 (/proc/self/maps).
  • Kerrisk, The Linux Programming Interface (2010). Extract: process control, threads (clone), signal delivery + sigaction/sigaltstack. Applied: Phase 6 (signal forwarding), Phase 8 (thread creation), Appendix L.
  • Klabnik & Nichols, The Rust Programming Language (2nd ed., 2023). Extract: unsafe, raw pointers, FFI, ownership for manual memory. Applied: §11 Core Schema (unsafe-confined types), Phase 0/7 (cache allocator), P11 (isolated unsafe).

Glossary · 46 terms · site-wide glossary

DBI
Dynamic Binary Instrumentation: rewriting a program's machine code as it runs.
Code cache
Executable memory holding translated copies of the target's code.
Tag
An original code address; the code-cache key.
Block
A translated copy of one basic block, ending in a controlled exit.
Trace
A stitched hot sequence of blocks executed as one fragment.
Dispatcher
The engine loop that finds/creates the cache block for a tag and jumps in.
Exit stub
Code at a block's end that returns control to the dispatcher.
Linking
Patching a direct-branch exit to jump straight to the target's cached block.
IBL
Indirect-Branch Lookup: hash app target → cache address, taken in-cache.
Return cache
A specialized predictor for the common call/ret pattern.
Clean call
Saving full context, calling a tool fn, restoring — for arbitrary analysis.
Inline probe
A small instrumentation op emitted directly (e.g., counter increment).
Clobber declaration
A tool stating which registers it modifies, to minimize spills.
Context
A snapshot of the target's registers/flags/PC exposed to a probe.
Transparency
The property that instrumentation does not change observable behavior.
PC transparency
The target seeing its original program counter, not a cache address.
SMC
Self-Modifying Code: the target writing code the engine has cached.
Invalidation / flush
Discarding cache entries (after SMC or capacity pressure).
Quiescence
A safe state where no thread executes a block before it is freed (I8).
Trampoline / detour
A patched jump redirecting execution to instrumentation.
W^X
Write-xor-execute: memory is never writable and executable at once.
Probe / InsPoint
An instrumentation hook and the location it attaches to.
Tool (pintool)
A user plugin implementing the analysis (the Tool trait).
Attach / detach
Bringing a running process under, or releasing it from, the engine.
Injection
Loading the engine into the target's address space.
ptrace
The Linux syscall for tracing/controlling another process (attach, read/write regs, mem, signals).
Escape
Execution leaving the code cache into original (uninstrumented) code.
Translation
Decoding (#334) and copy-and-patching a block into the cache.
rip-relative fixup
Rewriting PC-relative operands to resolve to original addresses.
NET
Next-Executing-Tail: the trace-selection heuristic.
Coverage (drcov)
A per-block hit map, the canonical DBI fuzzing output.
Shadow memory
Per-byte metadata mirroring target memory (for taint/Memcheck-like tools).
Overhead
The slowdown factor instrumentation adds vs native execution.
Side table
The cache-address ↔ app-address map used for faults/signals/detach.
YAMA ptrace_scope
Kernel policy restricting who may ptrace whom (operational gate).
mmap / mprotect
Map memory / change page permissions (used for the RX code cache, W^X).
VDSO
Kernel-mapped shared object providing fast syscalls (translated + cached like any module).
PLT / GOT
Procedure Linkage Table / Global Offset Table — lazy dynamic binding, resolved via IBL.
ld.so
The dynamic loader/resolver — itself instrumented like target code.
ucontext / siginfo
Signal-delivery state structures; must reflect original (app) PC, not cache PC (I9).
sigaltstack
Alternate stack for signal handlers.
TLS
Thread-Local Storage; the engine keeps its own, separate from the target's.
clone
The syscall behind thread/process creation; intercepted to bring new threads under the engine (Phase 8).
Red zone
128 bytes below rsp usable without adjustment; must not be clobbered by a probe spill (Phase 2).
Bump allocation
Sequential, pointer-bump cache allocation (fast install, no free-list search).
RCU
Read-copy-update; the synchronization discipline for shared read-mostly engine maps (Phase 8).
