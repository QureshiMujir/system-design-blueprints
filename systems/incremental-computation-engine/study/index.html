34. Mental Models & First Principles

Compressed expert intuitions. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

MM1 — A memo is a dated claim, not a value. A Memo asserts "this value was current as of verified_at, and last changed at changed_at." Predicts: you can reuse a value at a new revision without recomputing iff you can prove nothing it read changed since verified_at. Bug without it: you treat the cache as a plain HashMap<Key,Value>, return a value at the wrong revision, and corrupt every downstream cutoff (the stale-read class). Applied: §8 Domain Model; Phase 5 (§16); INV-3.

MM2 — Two clocks, not one: verified_at and changed_at. Validation answers "is it still current?" (verified_at); cutoff answers "did the value move?" (changed_at). They advance independently — backdating advances verified_at alone. Predicts: deep cutoff is possible only because a revalidated-unchanged node keeps its old changed_at. Bug without it: one timestamp → either re-flood every revision or serve stale. Applied: P8; Phase 5 (§16); Phase 6 (§17); INV-4.

MM3 — Dependencies are discovered, not declared. The dep set is whatever the body read this run, captured by tracing — so deps are dynamic and can differ run to run (a conditional read). Predicts: a branch that reads B only when A>0 records B only when taken; tests must not assume static deps. Bug without it: you hard-code an edge that a run did not take (phantom → waste) or miss one a run did take (missed → stale). Applied: Phase 2 (§13); P7; INV-5.

MM4 — Maybe-dirty is a hypothesis; demand is the experiment. Marking is cheap and conservative (push); proving is lazy and exact (pull). A node is maybe dirty until a demand validates it. Predicts: sparse demand (an IDE showing one file) does work proportional to observed-and-affected, not all-affected. Bug without it: you eagerly recompute the whole frontier (eager-dirty), wasting work on never-observed nodes. Applied: P3; Phase 4 (§15); Phase 5 (§16); INV-6.

MM5 — Cost is the distance of the change, not the size of the graph. Incremental cost is bounded by the transitively-affected-and-demanded set; the firewall (cutoff) shrinks it further. Predicts: a whitespace edit in a 10^6-node graph costs O(firewall), not O(10^6). Bug without it: you reason about absolute graph size and over-provision / mis-set caps. Applied: Acar (P2); P5; §33 Scalability; M8.

MM6 — Equality is the firewall; identity is irrelevant. Cutoff fires on Eq, so a freshly-allocated value that is structurally equal to the old one stops propagation. Predicts: returning a new Vec with identical contents cuts off; a lying Eq silently serves stale. Bug without it: you compare by pointer/identity (never cuts off) or trust a broken Eq (silent wrong results). Applied: P4; Phase 6 (§17); INV-4; T2.

MM7 — Durability gates work, never truth. A durability tier can only let validation skip a walk; a real change always bumps the clock map so the skip is not taken. Predicts: turning all durability to Low changes performance only, never a result. Bug without it: you let "this input is constant" decide a value, and a durable-but-changed input serves stale. Applied: P9; Phase 7 (§18); INV-12.

MM8 — The engine is a cache; only inputs are truth. Any memo may be dropped and recomputed identically. Predicts: eviction, persistence-miss, and cold-start all reduce to "recompute on demand"; a side effect hidden in a query body breaks this. Bug without it: you treat a recompute's side effect as load-bearing, and eviction silently changes behavior. Applied: P14; Phase 9 (§20); P2; INV-10.

MM9 — A graph cycle is single-thread re-entry; a cross-thread wait is a deadlock. They look alike (a stuck demand) but have different causes and fixes. Predicts: the on-stack check must fire before the per-key lock, or a self-cycle deadlocks instead of erroring. Bug without it: you conflate them, "fix" a cycle with lock ordering, and still hang. Applied: Phase 8 (§19); Phase 10 (§21); P12; INV-7.

MM10 — Reuse is invisible until you instrument it. An incrementality regression manifests only as latency unless every reuse/recompute/cutoff decision is counted. Predicts: a reuse-ratio gate catches a broken changed_at before users feel it. Bug without it: silent over-recompute ships and is debugged from latency graphs with no signal. Applied: P10; Phase 12 (§23); §27 Failure Modes.

Required reading (§5)

Books

  • Umut Acar — "Self-Adjusting Computation" (PhD thesis, CMU, 2005). Chapters on the dynamic dependency graph, change propagation, and the cost semantics. Extract: the foundational model (modifiables, reads, propagation) and the notion that incremental cost is bounded by the distance of the change. Applied: §8 Domain Model; Phase 5 (§16) change propagation; §33 Scalability cost story.
  • Engineering a Compiler (Cooper & Torczon), 2nd ed. Chapters on intermediate representations and analysis frameworks. Extract: why a compiler is a graph of derived facts — motivates query-based architecture and what the engine's biggest client looks like. Applied: §1 Goal (target users); the mini-compiler example (Appendix A); cross-link 242.
  • Crafting Interpreters (Nystrom). The tree-walking and resolution chapters. Extract: concrete sense of the small derived computations (resolve, type, lower) that become #[query]s; calibration for fixture design. Applied: Phase 2 (§13) query model; Phase 6 (§17) whitespace-cutoff fixture.
  • The Art of Multiprocessor Programming (Herlihy & Shavit), 2nd ed. Chapters on locking, linearizability, and concurrent hash maps. Extract: how to reason about the sharded memo cache and the per-key compute lock; linearizability as the bar for "no stale read across a revision." Applied: Phase 10 (§21) concurrency; P13/INV-3.
  • Rust for Rustaceans (Gjengset). Chapters on Send/Sync, interior mutability, and unsafe abstractions. Extract: the exact ownership patterns for a shared, internally-mutable cache. Applied: §11 Core Schema (Database, MemoCache); Phase 10 (§21); ADR-23.
  • Programming Rust (Blandy, Orendorff, Tindall), 2nd ed. Chapters on traits, closures, and concurrency. Extract: Eq/Hash trait bounds for cutoff and interning; closure capture for query descriptors. Applied: §11 Query/Input traits; Phase 6 (§17) Eq bound (P4).
  • Designing Data-Intensive Applications (Kleppmann). Ch. 3 (storage/indexing), Ch. 11 (stream processing / derived data). Extract: the line between materialized derived data and recomputation; intuition for revisions as versions. Applied: P14 (cache, not source of truth); Phase 13 (§24) collections; §33 Scalability.
  • Database Internals (Petrov). Chapters on MVCC and versioning. Extract: revision-as-version model; how readers see a consistent snapshot — analogous to a query seeing a consistent revision. Applied: P6 revision clock; Phase 1 (§12); Phase 10 (§21) Snapshot.
  • Purely Functional Data Structures (Okasaki). Chapters on persistence and memoization. Extract: structural sharing and memoized lazy evaluation — the functional roots of incremental computation. Applied: Phase 3 (§14) memoization; ADR-11 value sharing.

Glossary (§40) · 38 terms · site-wide glossary

Backdating
advancing a memo's verified_at to the current revision while leaving changed_at unchanged, after proving its value did not change; the mechanism that makes early cutoff transitive (P8/INV-4).
Change propagation
the process of validating/recomputing the transitively-affected portion of the DDG after an input change.
changed_at
the revision at which a node's value last actually changed; drives downstream cutoff decisions.
Cold build
full evaluation with an empty memo cache (no reuse).
Cutoff (early cutoff)
stopping propagation when a recomputed value equals (Eq) the prior value; the firewall against needless downstream recompute (P4).
CycleError
typed recoverable error returned when a demand re-enters a key already on the compute stack (INV-7).
DCG / DDG
Dynamic (Demanded) Computation/Dependency Graph; the runtime graph of inputs and derived queries discovered by execution tracing.
Demand (pull)
requesting a query's value; the only trigger for (re)computation (P3).
Dependency capture
recording the exact set of inputs/queries a query reads, by tracing its execution via the thread-local DependencyStack (INV-5).
Dependency edge
a (NodeId, changed_at_when_read) record linking a query to something it read; versioned for precise validation.
DependencyStack
the per-thread stack of frames accumulating read edges for the currently-executing queries.
Derived query
a pure function execute(db, key) -> value whose result is memoized (#[query]).
Durability
an advisory class (Low/Medium/High) on inputs; gates a validation short-circuit but never affects a result (P9/INV-12).
Early cutoff
see Cutoff.
Firewall
a node where cutoff fires, halting an otherwise-cascading downstream recompute.
Fixpoint recovery
optional iteration to a stable value for a recoverable query-graph cycle, instead of erroring (Phase 8).
From-scratch consistency
the property that incremental results always equal a fresh rebuild from the same inputs (INV-1); the engine's correctness contract.
Green hit
returning a cached value because verified_at == current_rev (no work).
Input cell
a leaf node holding (value, changed_at, durability); mutated by set_input (#[input]).
Interning
mapping a QueryKey to a dense, recyclable NodeId(u32) (INV-11).
MaybeDirty
the conservative state of a node transitively reachable from a changed input, pending validation (INV-6) — not committed to recompute.
Memo
the cached record for a derived query: {value, verified_at, changed_at, durability, deps, state}.
Memoization
caching a pure function's result keyed by its inputs to avoid recomputation.
Minimality
recomputing only the transitively-affected set, never the whole graph (P5; the O(affected) target).
NodeId
interned dense identifier {index:u32, generation:u16} for a node (INV-11).
NodeState
Unverified | Verifying | Verified(R) | MaybeDirty | Computing.
Oracle
the from-scratch reference Database used in differential testing (INV-1).
Provider hash
a per-query semantic-version hash persisted with a memo; a mismatch (changed query logic) forces recompute on load (Phase 11).
Pull vs push
pull = recompute on demand (this engine); push = eagerly propagate changes (the dual, project 300).
Reachability sweep
GC pass collecting memos reachable only from evicted/undemanded nodes (Phase 9).
Red-green algorithm
the salsa-style validation scheme using verified_at/changed_at/durability to decide reuse vs recompute (Phases 5–7).
Reuse ratio
fraction of demanded nodes served without recompute; the headline incrementality metric (target ≥ 0.95).
Reverse edge (dependents index)
NodeId → dependents; used to mark the MaybeDirty frontier and for GC reachability.
Revision
a monotonic global u64 logical clock value; orders all state (P6/INV-2).
Single-writer model
mutations (set_input) are serialized (exclusive); reads/recomputes run concurrently against a pinned snapshot (Phase 10).
Snapshot
a read-only handle pinned to a revision for lock-free concurrent reads (Phase 10).
Stale read
returning a value computed against an older revision without revalidation; forbidden (P13/INV-3).
verified_at
the revision at which a memo was last confirmed current (possibly via backdating).
