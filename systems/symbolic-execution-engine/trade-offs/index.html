Decisions (§9) · 24 ADRs

ADR-01

Language

Chosen

Rust

Rejected

C++, Go

When the rejected choice is right

C++ wins when integrating unmodified vendor codebases (Triton, QEMU TCG) whose FFI surface is C++-native and a rewrite is unfunded; Go wins for a thin orchestration layer with no shared mutable hot-path state

Why: ownership model eliminates use-after-free/data races in a hash-consing arena shared across worker threads, without GC pauses that would perturb p99 solver latency

ADR-02

Build system

Chosen

Cargo (workspace)

Rejected

Bazel

When the rejected choice is right

Bazel wins once the workspace spans multiple languages (C++ solver vendoring, Python tooling) needing one hermetic remote-cacheable graph

Why: workspace-native incremental builds match the crate boundaries in §10

ADR-03

Dependency policy

Chosen

pinned lockfile + cargo vendor + cargo-deny

Rejected

floating semver ranges

When the rejected choice is right

floating ranges win in early single-maintainer prototyping repos with no reproducibility requirement

Why: reproducible builds (ADR-18) require byte-identical dependency trees across CI and operator machines

ADR-04

Storage engine

Chosen

RocksDB (LSM)

Rejected

LMDB

When the rejected choice is right

LMDB wins for read-dominated workloads with rare writes needing zero-copy mmap reads and no compaction thread

Why: write-heavy WAL/checkpoint workload favors LSM sequential writes over LMDB's mmap read optimization

ADR-05

Serialization

Chosen

Prost (protobuf, RPC) + Cap'n Proto (snapshot pages)

Rejected

JSON

When the rejected choice is right

JSON wins for the CLI's human-facing config/report output where grep/diff-ability outweighs encoding cost

Why: deterministic binary encoding avoids float/key-order nondeterminism that breaks replay hash stability (I9)

ADR-06

Networking

Chosen

gRPC (Tonic)

Rejected

When the rejected choice is right

raw TCP wins on a single machine where coordinator and workers share a Unix socket and protobuf schema overhead is pure tax

Why: built-in streaming, deadline propagation, and codegen reduce protocol drift across crates/scheduler/crates/executor

ADR-07

Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — Whole-System Snapshot Forking

+--------+     +-------------------+     +------------------+
| Guest  | --> | QEMU Full-System  | --> | Snapshot-Level    |
| Kernel |     | Emulation + TCG   |     | Fork on Branch    |
+--------+     +-------------------+     +------------------+

Regime where it wins: full-system analysis needing kernel/userspace/device fidelity in one model. Real system: S2E (Chipounov et al., 2011). Rejected here because full CPU/device emulation overhead is incompatible with the p50 < 3 µs instruction budget (§4) for this blueprint's userspace-only target scope (§1).

Alt B — Source-Level Bitcode Symbolic Execution

+--------+     +--------------+     +----------------------+
| Source | --> | LLVM Bitcode | --> | Bitcode Interpreter + |
| (C/C++)|     | (clang -emit)|     | STP/Z3 Solver         |
+--------+     +--------------+     +----------------------+

Regime where it wins: source available, unit-test-generation and coverage-maximization workloads. Real system: KLEE (Cadar et al., 2008). Rejected here because this blueprint's target users (§1) include vulnerability researchers without source access — binary-only lifting (§14) is a hard requirement, not a nice-to-have.

Alt C — In-Process Interactive Analysis Library

+---------------------------------------------------+
| Single Python Process                              |
| Loader | pyvex Lifter | simuvex Memory | claripy AST|
+---------------------------------------------------+

Regime where it wins: rapid interactive research/CTF iteration where analysis-tooling agility beats raw throughput. Real system: angr (Shoshitaishvili et al., 2016). Rejected here because Python's GIL and object overhead cannot meet the distributed 500-worker fairness/throughput budgets (§4, §19); this blueprint is a batch/CI platform, not an interactive REPL (§1 non-goal).

Alt D — Concolic/Whitebox-Fuzzing-First Design

+-----------+     +---------------+     +-------------------+
| Concrete  | --> | Taint-Guided  | --> | Symbolic Follow-Up |
| Execution |     | Generational  |     | on Selected Bytes  |
| + Seed    |     | Search (SAGE) |     | (Mayhem-style)      |
+-----------+     +---------------+     +-------------------+

Regime where it wins: security-testing pipelines where raw coverage throughput matters more than exhaustive path enumeration. Real system: SAGE (Godefroid et al., 2012) / Mayhem (Cha et al., 2012). Rejected for the Phase 0-8 core: this blueprint prioritizes exhaustive, deterministic path exploration with replay guarantees (P6) before adding a concolic front-end. Hybrid fuzzing is deferred (§35, anchor §21), not rejected outright — it is a Phase 9+ extension once the exploration core is proven.
