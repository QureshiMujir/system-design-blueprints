30. Mental Models & First Principles

  • MM1 — Path Explosion Is Multiplicative. Fork count compounds across branch forking (Phase 6) and pointer-driven forking (Phase 4) as independent multipliers, not a single additive rate. Predicts a binary with both symbolic branches and symbolic pointers explodes faster than either alone. Without it: engineers budget worker RSS from branch count only and are blindsided by pointer-driven OOM. Applies in §16 and §18.
  • MM2 — Determinism Is a Type, Not a Testing Practice. If a wall-clock read or unordered-map iteration is reachable from the hot path, no test-suite discipline restores replay. Predicts replay bugs cluster around "happens to be nondeterministic" APIs, not logic errors. Without it: engineers chase a Heisenbug in the executor when the real bug is three crates away. Applies in §12 and §20.
  • MM3 — A Lease Is a Timeout, Not an Assignment. Any leasing protocol must assume the leaseholder is dead until proven otherwise by heartbeat. Predicts naive "assign and wait forever" designs double-execute under partition. Without it: coordinator code has no missed-heartbeat path because "it shouldn't happen." Applies in §19.
  • MM4 — Incrementality Trades Memory for Latency, Never Removes the Tradeoff. Reused solver contexts save re-assertion cost but pin memory across the reuse window. Predicts aggressive incrementality without epoch invalidation leaks solver RSS over long campaigns. Without it: a slow OOM over days gets misdiagnosed as a solver bug instead of a pooling-policy bug. Applies in §17.
  • MM5 — WAL-Then-Publish Is the Only Honest Order. A crash-safety claim untested by real crashes is untested by definition. Predicts skipping fsync-before-publish "for performance" fails only under real outages, never clean-shutdown tests. Without it: a system passes every graceful-shutdown test and loses data on every real one. Applies in §20.
  • MM6 — A Verifier Is Cheaper Than the Bugs It Prevents, Amortized. IR verification is paid once per lift; an unverified semantic bug is paid by every downstream path forever. Predicts skipping the verifier "for speed" looks free until path count crosses into the hundreds. Without it: a wrong flags-register model is discovered only after months of unexplained divergence. Applies in §14.
  • MM7 — Fail-Closed Beats Fail-Open When Silent Wrongness Costs More Than Availability. In a correctness tool, a false "no bug found" is worse than a crash. Predicts any best-effort recovery path converts a detectable failure into an undetectable one. Without it: an operator trusts a "clean" campaign that silently dropped a corrupted lineage. Applies in §16 and §20.
  • MM8 — Backpressure Is a Correctness Mechanism Here, Not Just a Performance One. Without bounded queues/caches, resource exhaustion and correctness failure become the same event. Predicts unbounded growth eventually corrupts state, not just slows it. Without it: an OOM-adjacent corruption gets attributed to "bad luck" instead of a missing bound. Applies in §18 and §19.

5. Required Reading

Books

  • Engineering a Compiler — Cooper & Torczon (2nd ed., 2011), ch. 5, 9, 13: CFG construction, SSA form, dataflow analysis and optimization-pass safety; applied in §11 and §14.
  • Linkers and Loaders — John R. Levine (1999), ch. 3–5: relocation semantics, ELF section layout, symbol resolution; applied in §13.
  • Computer Systems: A Programmer's Perspective — Bryant & O'Hallaron (3rd ed., 2015), ch. 3, 9: machine-level execution semantics, virtual memory, the process image; applied in §14 and §16.
  • The Art of Multiprocessor Programming — Herlihy & Shavit (rev. ed., 2012), ch. 9–10: lock-free structures, memory ordering, contention reduction; applied in §19.
  • Decision Procedures: An Algorithmic Point of View — Kroening & Strichman (2nd ed., 2016), ch. 2–4: bitvector/array decision procedures, incremental SAT/SMT solving; applied in §17.
  • Practical Binary Analysis — Dennis Andriesse (2018), ch. 2, 7: ELF internals, disassembly and lifting pitfalls, binary instrumentation; applied in §13 and §14.
  • Linux Kernel Development — Robert Love (3rd ed., 2010), ch. 4, 14–15: process scheduling fairness, memory management, syscall semantics; applied in §18 and §19.
  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 3, 5, 11: log-structured storage, replication, WAL-based recovery; applied in §20.

Papers

  • "KLEE: Unassisted and Automatic Generation of High-Coverage Tests" — Cadar, Dunbar & Engler, 2008, OSDI: coverage-driven path scheduling and search heuristics on LLVM IR, informing the path-scheduler fairness design; applied in §19.
  • "EXE: Automatically Generating Inputs of Death" — Cadar, Ganesh, Pawlowski, Dill & Engler, 2006, CCS: constraint exploration directly over compiled code, the lineage the constraint-set model descends from; applied in §11.
  • "S2E: A Platform for In-Vivo Multi-Path Analysis of Software Systems" — Chipounov, Kuznetsov & Candea, 2011, ASPLOS: selective symbolic execution and concrete/symbolic mode switching, informing the concretization policy; applied in §16.
  • "Unleashing Mayhem on Binary Code" — Cha, Avgerinos, Rebert & Brumley, 2012, IEEE S&P: hybrid concolic/symbolic exploit-generation pipeline, informing crash-triage and minimization; applied in §21.
  • "SOK: (State of) The Art of War: Offensive Techniques in Binary Analysis" — Shoshitaishvili et al., 2016, IEEE S&P (angr): platform-agnostic lifting and layered symbolic memory architecture, informing the loader/lifter/memory crate split; applied in §14 and §16.
  • "Symbolic Execution for Software Testing: Three Decades Later" — Cadar & Sen, 2013, CACM: taxonomy of path-explosion mitigations (merging, pruning, hybrid concolic); applied in §19 and §35.
  • "SAGE: Whitebox Fuzzing for Security Testing" — Godefroid, Levin & Molnar, 2012, CACM: whitebox/blackbox hybridization and generational search; applied in §21.
  • "Java PathFinder: A Model Checker for Java" — Visser, Havelund, Brat, Park & Lerda, 2003, ASE/STTT: state-exploration model checking over a managed VM, informing the path state machine; applied in §8.

Reference Implementations

  • klee/klee — study lib/Core/Executor.cpp: coverage-driven path scheduling and forking; pitfall: do not copy its unbounded state cache, it assumes single-machine memory limits; applied in §19.
  • angr/angr — study angr/state_plugins/symbolic_memory.py (formerly simuvex): layered symbolic-memory page abstraction; pitfall: its Python object overhead is not a model for a latency-budgeted Rust core; applied in §16.
  • JonathanSalwan/Triton — study src/libtriton/ast: symbolic AST node design and hash-consing; pitfall: its shared mutable AST context assumes single-threaded use, do not port that assumption; applied in §15.
  • qemu/qemu — study tcg/: tiny-code-generator IR lifting from native instructions; pitfall: TCG targets JIT dispatch speed, not verifiability, do not copy its lack of an IR verifier; applied in §14.
  • llvm/llvm-project — study llvm/lib/IR: SSA construction, IRBuilder API shape, dominance tree computation; pitfall: LLVM IR is optimizer-oriented, not replay-oriented, canonical ordering must be added; applied in §14.
  • rr-debugger/rr — study src/ReplaySession.cc: deterministic record/replay of a live process via ptrace; pitfall: rr's determinism relies on kernel-level syscall interception, this project relies on interpretive execution instead, do not assume ptrace-level guarantees; applied in §20.
  • facebook/rocksdb — study db/db_impl/db_impl_write.cc: WAL-then-memtable write path and checkpoint semantics; pitfall: RocksDB's compaction stalls are a tail-latency source, budget for them explicitly; applied in §20.

RFCs / Specifications

  • System V ABI (generic + AMD64 supplement) — pins ELF header/section/relocation layout and calling convention that crates/parser and crates/lifter must match byte-for-byte; applied in §13.
  • DWARF Debugging Information Format, v5 — pins the debug-info layout consumed for symbol and line-table recovery used in crash-triage output; applied in §21.
  • SMT-LIB v2 — pins the standard AST/command surface that crates/solver canonicalizes onto before dispatching to Z3/Bitwuzla; applied in §17.
  • OpenTelemetry Specification (OTLP v1) — pins the trace/span/metric wire format emitted by crates/telemetry; applied in §21.
  • OCI Image Format Specification v1.0 — pins the distroless container layout built in Build & Release Engineering; applied in §27.
  • SPDX Specification v2.3 — pins the SBOM document format generated at release time (ADR-24); applied in §27.

Glossary (§36) · 47 terms · site-wide glossary

Symbolic State
execution state whose registers/memory contain symbolic variables rather than only concrete values.
Path Explosion
exponential growth in the number of execution branches under exploration.
Concretization
converting a symbolic value to a concrete witness, typically via a solver query.
Constraint Set
the ordered collection of assertions accumulated along one execution path.
Replay Divergence
a mismatch between a recorded execution and its deterministic replay.
SSA
Static Single Assignment, an IR form where each variable is assigned exactly once.
WAL
Write-Ahead Log, an append-only durability mechanism written before state is published.
Unsat Core
the minimal contradictory subset of constraints proving unsatisfiability.
Path Fork
the branching of one symbolic state into two or more descendant states.
Snapshot Lineage
the parent-child chain of checkpoints leading to a given state.
Solver Epoch
a versioned generation counter for a path's incremental solver context.
IR
Intermediate Representation, the canonical architecture-independent instruction form.
AST
Abstract Syntax Tree, the hash-consed symbolic expression representation.
Lease
a time-bounded scheduler ownership token granting exclusive execution rights.
Trace ID
a correlated observability identifier spanning coordinator, worker, and storage.
Guard Page
an unmapped memory page that traps on access, used for bounds detection.
Work Stealing
dynamic redistribution of queued work from busy to idle workers.
Symbolic Pointer
a memory address represented as a symbolic expression rather than a concrete value.
Checkpoint
a persisted, durable copy of an execution state.
Deterministic Replay
re-execution that reproduces an identical AST-hash sequence.
Hash-Consing
a technique for structurally deduplicating equal expressions into one shared node.
Copy-on-Write (COW)
a memory-sharing scheme that defers copying a page until it is written.
Dominance Tree
the CFG structure recording which basic blocks always execute before others.
Basic Block
a maximal straight-line instruction sequence with one entry and one exit.
CFG
Control Flow Graph, the graph of basic blocks and their branch edges.
Incremental Solving
reusing a solver context across related queries via push/pop.
Push/Pop Context
the SMT-LIB mechanism for entering/exiting a nested assertion scope.
Fairness Skew
the deviation from equal worker time-share in the scheduler.
Backpressure
a bounded-resource signal that slows or rejects new work under saturation.
Fencing Token
a monotonically increasing token preventing a stale leaseholder from acting.
Differential Validation
cross-checking a result across two independent implementations (e.g. Z3 vs. Bitwuzla) to detect implementation-specific bugs.
Crash Triage
the process of classifying and prioritizing discovered crashes.
Testcase Minimization
reducing a crashing input to its smallest reproducing form.
Split-Brain
a state where two coordinator replicas both believe they hold sole authority.
Torn Write
a partially completed disk write left inconsistent by a crash mid-write.
Page Deduplication
storing one copy of identical memory pages shared across states.
Relocation
a directive adjusting an address reference at load time.
Symbol Table
the ELF structure mapping names to addresses and metadata.
ELF
Executable and Linkable Format, the binary format parsed in Phase 1.
SMT-LIB
the standard input language/format for SMT solvers.
Bitvector Theory
the SMT theory modeling fixed-width binary integers.
Model Witness
a concrete satisfying assignment returned by a solver for a SAT query.
Flags Register
the CPU register holding condition codes (ZF, CF, OF, SF) after arithmetic.
Concolic Execution
hybrid concrete-plus-symbolic execution used to guide input generation.
Coverage-Guided Fuzzing
fuzzing that prioritizes inputs expanding observed code coverage.
RTO/RPO
Recovery Time Objective / Recovery Point Objective, the availability budget terms used in §4 and §24.
NUMA Pinning
binding a thread/process to CPU cores local to a specific memory node.
