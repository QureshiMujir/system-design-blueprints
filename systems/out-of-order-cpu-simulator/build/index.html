⬜ Phase 1 — RV64IM decode, architectural state, and the functional golden model §13

Objectives
  • decode(raw: u32) -> DecodedInst total over all 2^32 words; unknown → Opcode::Illegal (no panic).
  • Full RV64I base (incl. *W 32-bit ops) + M-extension (MUL/MULH/MULHU/MULHSU/DIV/DIVU/REM/REMU + W variants).
  • execute_functional() = single architectural step: read ArchState, mutate xregs/pc/CSR, return/raise Trap. Bit-exact vs Spike.
  • Precise trap conditions: illegal-inst, ecall/ebreak, misaligned load/store/fetch, div-by-zero + signed overflow (RISC-V: no trap, defined results).
  • no_std + alloc; deterministic, side-effect-free except &mut ArchState + a Memory trait.
Deliverable

ooo-isa crate + a thin in-crate harness run_functional(elf|hex, &mut Memory) -> ArchState: decodes + executes in program order to a halt sentinel (ecall with riscv-tests tohost convention). Drives riscv-tests rv64ui-p-* + rv64um-p-* to completion, reporting pass (tohost==1) or failing test number. Wired into oooc cosim later as the oracle.

Acceptance
  • 100% of rv64ui-p-* (~40 tests) + rv64um-p-* (~8 tests) PASS (tohost==1).
  • decode() round-trips: never panics on any of 1M random u32; ≥ matched cases byte-identical to a reference decode table.
  • Differential vs Spike on 10k random valid instructions: post-state xregs/pc identical.
  • x0 invariant: after any write to RegId::ZERO, xregs[0]==0.
  • Functional throughput ≥ 20M inst/s single-thread (no timing model overhead).

Pitfalls
  • B/J imm bit-scramble: branch/jump immediates are bit-permuted, not contiguous; off-by-one in B-imm[12:1] reconstruction → wrong target, passes simple tests, fails taken branches. Debug: unit-test each imm extractor vs known encodings.
  • *W not re-sign-extending: forgetting to sign-extend the 32-bit result to 64 bits → high garbage; ADDIW/SLLW silently wrong. Debug: assert bit63==bit31 post-op.
  • Shift amount width: RV64 uses 6-bit shamt; masking with &0x1f (RV32) truncates SLLI x,x,32. Use &0x3f for 64-bit, &0x1f for *W.
  • MULHSU signedness: mixed signed×unsigned — wrong cast (i128*i128 vs i128*u128 as i128) gives wrong upper word. Compare against Spike on negative operands.
  • x0 as source vs dest: x0 reads 0 always; writes discarded — but reading rs1=x0 then writing rd=x0 must still advance pc + retire (NOP). Forgetting commit path → hang.
  • Div-by-zero / overflow = no trap: RISC-V defines results, does NOT trap (unlike x86). A panic! on a/0 is a bug; must return -1 / dividend.

⬜ Phase 2 — In-order pipeline scaffold and the reverse-order tick §14

Objectives
  • Build OooCore clocked engine in ooo-core: stage structs, pipeline latches, Cycle counter, Stats.
  • Implement tick() advancing stages in REVERSE order (Commit→WB→Execute→Mem→Decode→Fetch) — the load-bearing determinism rule (result in cycle C visible only at C+1).
  • Working 5-stage in-order baseline (F/D/EX/MEM/WB) with stall + bubble logic; no OoO, no rename, no ROB yet — these are the timing skeleton that later phases bolt onto.
  • Drive functional execution via ooo-isa::execute_functional; the in-order pipe is pure timing — committed arch state MUST match the golden model bit-for-bit.
  • Produce real IPC via Stats { cycles, committed } for straight-line + branch programs.
Deliverable

In-order cycle-accurate timing model: oooc run --inorder prog.hex executes RV64IM, prints final arch regs + Stats{cycles, committed, ipc}; committed state == golden; reproducible cycle counts.

Acceptance
Metric Target
Golden equivalence committed arch state bit-exact vs execute_functional on all fixtures
IPC, no-hazard straight-line → 1.00 ± 0 (steady state, ignoring fill/drain)
RAW stall cost back-to-back dependent ALU = +2 cycles (no forwarding)
Determinism identical cycles across 100 reruns, same seed/config
Throughput ≥ 5 M sim-cycles/sec single-thread (release)

sum1toN.hex x10=N(N+1)/2; cycles ≈ 5 + 6·iters (loop branch penalty)

Pitfalls
  • Same-cycle teleport: running stages in FORWARD order lets a value produced in EX feed Decode same cycle → IPC inflated, non-deterministic. Root: forgot reverse order. Debug: trace shows result consumed in cycle of production.
  • Double-advance latch: calling advance() inside a stalled stage drops an instruction (silent loss → committed < expected). Debug: assert committed == golden_step_count.
  • Bubble vs stall confusion: inserting a bubble AND advancing the stalled latch skips the held inst. Keep "hold input" and "emit NOP output" as the single stall action.
  • x0 writeback: writing WB result to x0 corrupts golden equivalence. Guard if rd.0 != 0.
  • Branch squash off-by-one: squashing the branch itself (not just younger) loses the branch's own retire → committed undercount.

⬜ Phase 4 — Decode/rename (RAT, free list, physical register file) §16

Objectives
  • Map arch regs → PhysReg via Rat; allocate dst from FreeList; record old_phys (for commit-time free + recovery).
  • Eliminate WAR/WAW false deps → only true RAW remain, tracked by PhysRegFile::ready[].
  • x0 never renamed: reads → fixed P0 (always-ready, value 0); writes → discarded (no alloc, no free).
  • Capture RenameCheckpoint at every branch (snapshot RAT + free-list head) for Phase 10 recovery.
  • Stall (no bubble corruption) when FreeList empty; deterministic, allocation order = program order.
Deliverable

ooo-rename crate compiling + a rename stage integrated into OooCore::tick() that converts the in-order decoded stream to a PhysReg-renamed stream with old_phys recorded and per-branch checkpoints. CLI oooc trace --stage=rename <prog> dumps per-cycle arch→phys mappings + free-list occupancy. No commit/free yet (PRF grows until Phase 10 frees old_phys).

Acceptance
  • WAR/WAW: in a hand-crafted WAW chain (add x1..; add x1..) the two writes get distinct PhysReg dsts; no false dep edge appears.
  • x0: every rd==x0 write yields dst==P0, no FreeList::alloc call (assert alloc count unchanged); every rs==x0 read yields src==P0.
  • Allocation is in program order + 1:1 with non-x0 dst-producing insts; free_list.len() decreases monotonically pre-commit.
  • Checkpoint count == branch count; each ckpt.free_head == free-list head at that branch.
  • RAT invariant: ∀ arch i, rat.map[i] points to the phys reg holding the most recent definition (verified vs a reference shadow map).

Pitfalls
  • Source-after-dest remap (self-WAR): renaming dst before reading srcs breaks add x1,x1,x2 (src1 would see new phys). Root cause: ordering. Fix: srcs first (step 1 < step 3). Debug: trace shows src1 phys == dst phys.
  • Freeing dst at rename instead of commit: returns phys reg still live → corruption on later read. old_phys is freed at commit (Phase 10), never at rename. Symptom: cosim divergence on a value reused after a WAW.
  • x0 entering FreeList: if P0 ever recycled, a real value overwrites zero. Pin P0: never in free queue, prf.regs[0] immutable. Debug: assert prf.read(P0)==0 each cycle.
  • Checkpoint = shallow ref not snapshot: storing &rat instead of a value copy → restore sees post-branch state. Use [PhysReg;32] by-value snapshot. Symptom: recovery (Phase 10) restores wrong map.
  • Stall mutates state: partial alloc on a stall double-allocs on retry → free-list leak/double-use. Make rename() fully idempotent; allocate last, after the ? early-return.
  • Sizing phys_regs < 32: must be ≥ 32 + rob_size to never deadlock single-wide; assert at config load.

⬜ Phase 5 — Dispatch into the reorder buffer §17

Objectives
  • Allocate one RobEntry per inst per cycle (up to issue_width) in program order into the circular ReorderBuffer (head/tail); record pc, dst_arch, dst_phys, old_phys, is_store, done=false.
  • Co-allocate RsEntry into Scheduler for all ops; co-allocate LsqEntry (load or store) for mem ops.
  • Enforce atomic, all-or-nothing structural-hazard stall: ROB full ∨ FreeList empty ∨ RS full ∨ LSQ full ⇒ stall this inst + all younger (in-order).
  • Maintain ROB occupancy invariants; expose is_full()/is_empty()/alloc()/free_head() API.
  • Deliverable: finite ROB with correct stalls, proven by a ROB-full stall test.
Deliverable

oooc run advances a program through fetch→decode→rename→dispatch; oooc trace --stage dispatch dumps per-cycle ROB occupancy + each allocated RobIdx. ROB/RS/LSQ are finite and stall correctly. cargo test -p ooo-rob + -p ooo-core green; ROB-full stall test passes.

Acceptance
  • Allocation is strictly in program order: RobIdx sequence == fetch order (modulo wrap).
  • ROB occupancy ≤ rob_size always; is_full() true ⇒ zero allocs that cycle, stall propagates to all younger insts (no out-of-order admission).
  • A tight dependent chain longer than rob_size insts produces a ROB-full stall (dispatch IPC drops, Stats.cycles rises) without panic or overwrite.
  • old_phys correctly threaded: post-commit (Phase 10) FreeList returns to steady state — checked here by asserting each RobEntry.old_phys matches rename's pre-mapping.
  • RS-full and LSQ-full independently trigger identical atomic stalls.

Pitfalls
  • head==tail ambiguity (full vs empty): root cause — using only two pointers. Fix: explicit count. Debug: assert count == (tail-head) mod cap.
  • Partial allocation leak: RS full discovered after ROB slot taken → orphaned ROB entry / lost PhysReg at commit. Root cause: mutate-before-probe. Fix: two-phase probe. Debug: FreeList size monotonically shrinks across a steady loop.

⬜ Phase 6 — Out-of-order issue scheduler (wakeup + select) §18

Objectives
  • ooo-schedule crate: Scheduler/ReservationStation, RsEntry, IssueQueue, IssuePort; depends on ooo-rename.
  • Wakeup: completing PhysReg broadcast → set src1_ready/src2_ready on matching unissued entries (CAM match).
  • Select: per FuKind, pick oldest ready (!issued, both srcs ready) up to issue_width; mark issued, free slot at issue.
  • Reorder: independent ops issue ahead of a multi-cycle-stalled producer's dependents; out-of-program-order issue order recorded.
  • Determinism preserved: wakeup this cycle → eligible for select next cycle (no same-cycle teleport), wired into reverse-order tick().
  • Goal: IPC strictly above the in-order baseline on a chosen reorder kernel; zero golden-cosim divergence.

oooc run --ooo-issue <kernel.hex> issues out of program order; oooc trace shows issue cycle < an older instruction's issue cycle when the older one is source-stalled. Scheduler integrated; cargo test -p ooo-schedule green; cosim clean.

⬜ Phase 7 — Execute: functional units, latencies, and the bypass network §19

Objectives
  • FunctionalUnit set: FuKind::{Alu, Mul, Div, Branch, Agu, LoadStore}; per-kind latency table (Alu 1, Mul 3, Div ~20 iterative, Branch 1, Agu 1).
  • Model pipelined (accept 1 op/cycle, busy_until = issue+1) vs iterative/unpipelined (Div blocks port until issue+latency).
  • ExecResult writeback: write PhysRegFile.regs[dst], set ready[dst]=true, broadcast for Scheduler wakeup.
  • BypassNetwork: forward producer value to dependent's issue same/next cycle so back-to-back dependent Alu chain runs at 1 cyc/op, not full WB latency.
  • Branch FU computes taken/target, sets ExecResult.mispredict, carries resolved target to redirect (consumed in Phase 10).
  • x0 writes squashed (never written to its phys reg's arch view; dst still allocated but value discarded on commit).
Deliverable

ooo-execute integrated into OooCore.tick(): selected entries execute on typed FUs with realistic latencies; BypassNetwork forwards; PhysReg.ready set on WB; Branch FU flags mispredict. oooc trace shows per-FU occupancy + bypass hits.

⬜ Phase 8 — Memory pipeline: LSQ, disambiguation, store-to-load forwarding §20

Objectives
  • AGU effective-address: addr = xreg[rs1] + imm computed on FuKind::Agu; produces addr_ready for the LsqEntry.
  • Split LoadStoreQueue (separate loads/stores vecs) age-ordered vs ROB; allocate at dispatch, in program order.
  • Memory disambiguation: a load scans older stores (rob_idx < load.rob_idx); resolve forward / wait / stall.
  • Store-to-load forwarding: exact addr+size match from youngest older store with known value → bypass, no cache access.
  • Conservative wait on unknown older-store addr (baseline); optional speculate + commit-time violation detect (PhaseDeferred toggle).
  • Stores write cache only at commit (in-order); loads non-speculative wrt older known stores. Invariant: committed mem state == golden ArchState.
Deliverable

ooo-mem LSQ integrated into OooCore: loads/stores allocate, AGU generates addresses, disambiguation + STLF operate per cycle, stores commit in order. oooc run executes load/store programs with correct values; oooc cosim matches golden on store-heavy programs; oooc stats reports forwards, lsq_stalls, disambig_waits.
