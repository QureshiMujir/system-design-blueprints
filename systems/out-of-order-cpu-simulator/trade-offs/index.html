Each card is one row of the blueprint's decision table: what was locked in, what was rejected, and — the column that matters most — the situation in which the rejected choice is the right one.

Decisions (§9) · 26 ADRs

1

Implementation language

Chosen

Rust, edition 2021, MSRV 1.78

Rejected

C/C++; Python; Go

When the rejected choice is right

C++ wins when the team owns a large gem5/SystemC ecosystem with existing timing models and must integrate with it directly; Python wins for <10K-cycle educational demos where throughput is irrelevant and script-edit cycles dominate (proj 188 use case).

Why: Tight #[repr] structs for per-cycle state; sum types + exhaustive match model Opcode/FuKind/pipeline-stage state with zero cost; ownership kills aliasing bugs endemic to large mutable timing models (gem5's class of bug). C/C++ memory-unsafe at this mutable-state scale; Python <1M cyc/s (proj 188 already Python); Go has weaker sum types + GC pauses perturb deterministic stepping.

2

Repo structure

Chosen

Cargo workspace, nine ooo-* member crates (ooo-isa, -frontend, -rename, -schedule, -execute, -mem, -rob, -core, -cli)

Rejected

Single monolithic crate; two crates (lib+bin); one crate per pipeline latch

When the rejected choice is right

A monolithic crate wins for a prototype or a solo weekend project where compilation-unit build times matter more than architectural boundaries and the codebase is <5K LoC total. One crate per latch wins in a research group where each PhD student owns exactly one stage and merge conflicts must be minimized.

Why: Crate boundary == architectural boundary; enforces the dependency DAG (isa→frontend/rename→…→core); each stage independently testable + benchable; prevents back-edges (e.g. ooo-isa cannot see timing). Monolith would let timing leak into the golden model.

3

Target ISA

Chosen

RV64IM (RV64I base + M mul/div)

Rejected

Full RV64GC (FD float, A atomic, C compressed); x86-64; ARMv8

When the rejected choice is right

Full RV64GC wins when the simulation must run real Linux workloads or an OS kernel (floating-point, atomics, and compressed encoding are then mandatory). x86-64 wins when the target audience is studying x86 microarchitecture (Intel/AMD pipeline modeling research).

Why: Open, fixed-length 32-bit encoding → trivial superscalar fetch/decode; smallest ISA that exercises every OoO mechanism (long-latency Div, Mul, loads, branches). FD/A/C are PhaseDeferred (decode-trap stubs). x86 variable-length defeats wide fetch; ARM license + complexity unjustified for a model.

4

Func ↔ timing separation

Chosen

ooo-isa golden model is authoritative for values; timing crates own only scheduling

Rejected

Fuse semantics into the timing path; recompute values during execute

When the rejected choice is right

Fusing wins for a trace-driven simulator where instructions' values are pre-recorded in the trace and the timing model never needs to recompute them; the oracle comparison overhead is then zero and the code is simpler. Also wins when targeting maximum throughput on very long traces with a trusted value model.

Why: execute_functional(&DecodedInst, &mut ArchState) is the single source of architectural truth; timing pipeline reorders when not what. Enables co-sim oracle (ADR 8) + lets a timing bug never corrupt correctness. Fusing them couples two hard problems.

5

Register management

Chosen

Explicit PhysRegFile + Rat + FreeList renaming

Rejected

ROB-based value storage (P6 style); Tomasulo CDB-only (values live in RS)

When the rejected choice is right

ROB-value storage (P6 style) wins when modeling an original Pentium Pro–class microarchitecture historically or studying its energy-inefficiency. Tomasulo CDB-only wins for modeling very small in-order-ish cores (embedded, RISC-V E-class) where the RS is tiny and a PRF abstraction adds unnecessary indirection.

Why: Physical-register-file renaming is the modern (gem5 O3, modern x86/ARM) design; removes WAR+WAW false deps leaving only RAW via PhysReg.ready. RobEntry stores dst_phys/old_phys (pointers), not values → cheap commit (free old_phys). ROB-value scheme bloats RobEntry; CDB-only scheme can't model a separate PRF read port.

6

Scheduler topology

Chosen

Unified Scheduler (single shared issue queue) with per-FuKind select

Rejected

Per-FU distributed reservation stations; separate INT/MEM/FP queues

When the rejected choice is right

Per-FU distributed RS wins when modeling a design that physically implements separate integer/load-store/FP RS banks with different capacities (ARM Cortex-A76, MIPS R10000 style) and the research question is specifically about queue-size asymmetry or port-specific stall behavior. Separate INT/MEM queues win when memory-order-constraint modeling must be decoupled from integer scheduling for performance at large RS sizes.

Why: One Vec<RsEntry> + wakeup CAM is simpler to make cycle-accurate + easier to validate; IssuePort/FuKind partitioning captured at select, not by physical RS banks. RsEntry.fu tags the destined unit. Distributed RS is more HW-faithful but multiplies state + complicates the wakeup broadcast for marginal model fidelity.

7

Time advancement

Chosen

Reverse-pipeline-order tick() (Commit→WB→Execute→Issue→Dispatch→Rename→Decode→Fetch)

Rejected

Event-driven discrete-event queue (gem5 native); forward-order stage stepping

When the rejected choice is right

An event-driven DES queue wins when the simulation contains long periods of empty pipeline (the core is mostly idle) and skipping empty cycles in simulation time is critical for throughput on OS/application workloads measured in billions of cycles. Forward-order stepping wins for a simple in-order pipeline prototype where all stages are guaranteed to have no feedback edges (no bypass, no speculative wakeup).

Why: Load-bearing determinism rule: stepping consumers before producers means a value made in cycle C is visible only in C+1, modeling latches with zero explicit latch-copy bookkeeping. DES adds a scheduler + nondeterministic tie-break risk; forward order teleports same-cycle results, breaking timing.

8

Correctness oracle

Chosen

Lock-step golden co-simulation at commit

Rejected

Trust the timing model; end-of-run state compare only; unit tests only

When the rejected choice is right

End-of-run state compare wins when co-sim overhead (2–4× slowdown) is unacceptable for long-running throughput benchmarks (>100M cycles) where the correctness confidence already comes from extensive regression suites; only the final arch state diff matters. Unit tests only wins during a first-pass prototype phase where the timing model is barely functional and full pipeline interaction co-sim is premature.

Why: At every commit, the retired architectural delta MUST equal execute_functional on the same instruction stream; divergence aborts with cycle + instruction. Catches reorder/rename/forwarding bugs the cycle they manifest. End-of-run compare can't bisect; unit tests miss emergent interactions.

9

Determinism / RNG

Chosen

Single seeded PRNG (ConfigParams.seed); no wall-clock, no thread nondeterminism

Rejected

std::HashMap default-seeded; ambient rand::thread_rng; OS entropy

When the rejected choice is right

Non-determinism wins for a production cache-replacement simulator where a random eviction policy is the research subject and reproducibility of individual eviction decisions is not the goal — only the aggregate miss-rate distribution matters statistically.

Why: Deterministic replay from (seed, config, program) is mandatory for bisection (ADR 8) + reproducible benchmarks. Use BTreeMap/indexed Vec over HashMap in any iteration that touches timing. Default-seeded hashing or thread_rng makes runs irreproducible.

10

Microarch parameterization

Chosen

Runtime ConfigParams (fetch_width, issue_width, commit_width, rob_size, rs_size, lsq_size, phys_regs, predictor)

Rejected

Compile-time const/generics; cargo features per width

When the rejected choice is right

Compile-time generics win when the simulation must achieve maximum throughput on a single fixed configuration (e.g. a production silicon validation harness where the RTL spec is frozen) and the ~20% Rust const-generic specialization speedup is worth the build complexity.

Why: One binary sweeps design space (oooc config/bench) without recompiling; enables CI matrices + Pareto studies. Compile-time constants would force N binaries; const-generic widths explode monomorphization + hurt build time.

11

Default direction predictor

Chosen

Gshare default; TageLite selectable via PredictorKind

Rejected

TAGE-lite mandatory default; static (always-taken/BTFNT); perceptron

When the rejected choice is right

TAGE-lite as mandatory default wins when the simulation is targeting IPC fidelity on real workloads against a modern core (SPEC CPU2017, server benchmarks) where gshare's ~8–12% MPKI unacceptably inflates mispredict penalties relative to silicon. A perceptron predictor wins for long-history workloads (complex loops, indirect-heavy server code) where geometric-history correlation fails and the dot-product advantage is measurable.

Why: Gshare (global history XOR pc → 2-bit counters) is the simplest predictor that beats static + is the validation baseline; TageLite opt-in for accuracy studies. Mandatory TAGE complicates Phase 3 bring-up; perceptron adds dot-product cost without pedagogical/fidelity gain here.

12

Branch target + returns

Chosen

Btb (set-assoc) + Ras

Rejected

BTB only; indirect-branch predictor (ITTAGE)

When the rejected choice is right

ITTAGE wins when the workload is a virtual-machine interpreter, JIT compiler, or OOP dispatch-heavy C++ binary where computed indirect branches (not call/return) constitute >15% of branches and BTB aliasing causes chronic front-end bubbles.

Why: Btb predicts direct targets; Ras handles Jal/Jalr call/return pairs (the dominant indirect case). ITTAGE deferred — general indirect targets are rare in RV64IM micro-bench corpus.

13

Memory hierarchy fidelity

Chosen

Set-associative Cache (L1/L2) + MSHRs + Tlb

Rejected

Fixed single-cycle memory; perfect cache; trace-driven latency

When the rejected choice is right

A perfect-cache (single-cycle) model wins for studying pure instruction-level parallelism — rename/ROB/RS sizing, predictor accuracy, or widening sensitivity — where memory is intentionally removed as a confounding variable. A trace-driven latency model wins when the research team has validated hardware traces and wants to decouple cache-hierarchy modeling from microarchitecture modeling for independent publication.

Why: Real OoO IPC is dominated by memory stalls; MSHRs model miss overlap (the whole point of an OoO load schedule). Miss latency feeds back into Scheduler wakeup timing. Fixed latency hides the behavior the simulator exists to study.

14

Memory disambiguation

Chosen

Conservative LSQ default (load waits on any older unknown-address store); aggressive speculation opt-in

Rejected

Aggressive-by-default (speculate + violation-detect); store-set predictor; no disambiguation

When the rejected choice is right

Aggressive-by-default wins when the workload has high memory-level parallelism and few genuine store-load conflicts (e.g. a streaming compute kernel where virtually all loads are independent of nearby stores) — conservative waiting serializes memory-level parallelism that could be safely exploited. Store-set prediction wins when the research question is specifically about memory-dependence prediction accuracy and its IPC impact.

Why: Conservative default is always-correct + simple to validate first; LsqEntry.addr: Option<u64> (None = unresolved) drives the wait. Aggressive mode (speculate, detect at commit, squash) is a Phase-8/10 opt-in measured against the conservative baseline. Store-set predictor is future work.

15

Store-to-load forwarding

Chosen

Exact-address match in LSQ forwards store value to younger load

Rejected

No forwarding (always go to cache); partial/overlap forwarding

When the rejected choice is right

No forwarding wins when modeling a simple in-order pipeline (where the store commits before the load issues by construction) or a non-blocking store buffer where forwarding logic is not present in the modeled hardware. Partial-overlap forwarding wins when modeling x86 scalar sub-register writes followed by wider reads (a common pattern in x86 ABI code) and the research goal is x86 memory-subsystem fidelity.

Why: Eliminates the common producer→consumer memory dependency stall. Exact-match only (full-width) keeps it simple + correct; partial-overlap forwarding (sub-word/misaligned) deferred — flagged as a stall instead.

16

Index/handle safety

Chosen

Newtypes RobIdx(u16), PhysReg(u16), RegId(u8), Cycle(u64)

Rejected

Bare usize/u16 integers everywhere

When the rejected choice is right

Bare integers win in a throwaway prototype or a C port where the overhead of defining newtypes adds more lines than the codebase has bugs, or where the programmer can guarantee via code review that index-kind confusion will never occur.

Why: Type system forbids mixing a ROB index with a phys-reg id with a cycle count — the exact confusion class that silently corrupts a mutable timing model. Zero runtime cost (#[repr(transparent)]).

17

no_std policy

Chosen

ooo-isa, -rename are no_std + alloc; upper crates std

Rejected

Everything std; everything no_std

When the rejected choice is right

Full std wins when the project has no embedded deployment target and the team wants unrestricted standard-library access throughout (filesystem, threads, networking for a remote-cosim use case). Full no_std wins when ooo-isa must be deployed as a firmware component or in a WASM sandbox where std is unavailable.

Why: Keeps the golden model + rename core portable + dependency-light (could embed/reuse elsewhere); std confined to I/O-bearing crates (-core, -cli, cache stats). Full no_std would needlessly fight -cli ergonomics.

18

Benchmark harness

Chosen

criterion (statistical) + oooc bench for sim-throughput + IPC

Rejected

#[bench] (nightly, unstable); ad-hoc Instant timing

When the rejected choice is right

Nightly #[bench] wins in a research context where stable API compatibility is irrelevant, the team always uses nightly Rust (e.g., for async/const-generic features), and the lightweight harness suffices for rough throughput checks. Ad-hoc Instant wins for a one-time measurement in an experiment script where criterion's warmup/sampling overhead is disproportionate to the measurement duration.

Why: Criterion gives stable-toolchain, noise-robust regression detection; report both model speed (target ≥1M simulated cycles/s single-thread) and modeled IPC. Nightly #[bench] violates MSRV/stable policy.

19

Fuzzing

Chosen

Random RV64IM program generator → co-sim must not diverge

Rejected

cargo-fuzz on raw decode() only; no fuzzing

When the rejected choice is right

Raw-byte cargo-fuzz on decode() only wins when the primary threat model is a malformed ELF/binary input crashing the simulator rather than a subtle pipeline correctness bug — i.e., when correctness is assumed and availability/robustness is the target.

Why: Structured generator emits valid RV64IM sequences (legal regs, terminating loops, mixed FUs); any commit-state divergence vs golden = bug. Raw-byte fuzzing of decode is a useful add-on but can't exercise the OoO pipeline interactions.

20

Differential conformance oracle

Chosen

riscv-tests suite + differential vs Spike (golden ISA sim)

Rejected

Self-checking tests only; hand-written vectors

When the rejected choice is right

Self-checking tests only win when the project is a new ISA extension prototype where riscv-tests and Spike do not yet cover the new instructions and hand-written vectors for those instructions are the only available ground truth.

Why: riscv-tests is the ISA reference corpus; Spike is the canonical RV64 golden — oooc cosim diffs committed state against both. Authoritative external truth beyond our own golden model.

21

CI

Chosen

GitHub Actions: fmt + clippy -D warnings + test + cosim + bench-smoke on the MSRV + stable matrix

Rejected

No CI; local pre-commit hooks only

When the rejected choice is right

No CI / local-only hooks win for a single-developer research artifact with <100-line change frequency where CI setup overhead exceeds the lifetime benefit, or for an air-gapped environment where GitHub Actions is unavailable.

Why: Enforces every gate (build, lint, golden co-sim, conformance subset) per push; MSRV pinned in matrix so 1.78 floor never silently breaks.

22

MSRV policy

Chosen

Pin 1.78; bump only via an ADR + CI matrix update

Rejected

Track latest stable; no MSRV pin

When the rejected choice is right

Tracking latest stable wins when the team actively uses new Rust features (async, const-generic, SIMD intrinsics) as they stabilize and has no downstream consumers that constrain their compiler version.

Why: Reproducible builds + a stable contract for downstream reuse of the no_std cores. Edition 2021 features suffice; no need to chase new toolchains.

23

Dependency posture

Chosen

Minimal, audited deps (criterion dev-only; a small seeded-PRNG; ELF/hex parse; clap for oooc)

Rejected

Heavy frameworks; a discrete-event-sim crate; an existing ISA-decoder crate

When the rejected choice is right

A DES framework wins when the simulation must model a heterogeneous SoC (CPU + GPU + interconnect + DRAM controller) where a shared event queue across components is necessary and the complexity is justified. An existing ISA-decoder crate wins for a time-constrained prototype where ISA correctness is needed immediately and the decoder crate has a verified conformance record.

Why: Fewer deps → faster builds, smaller audit surface, full control of the timing-critical inner loop. Decoder is hand-written in ooo-isa (we own the golden semantics); no external DES crate (ADR 7 rejects DES).

24

Licensing

Chosen

MIT OR Apache-2.0 (dual)

Rejected

GPL; proprietary; single license

When the rejected choice is right

GPL wins when the project is academic-research infrastructure meant to prevent commercial enclosure of the simulator without contribution back. Proprietary wins for an industrial timing model where the competitive advantage lies in the accuracy of the timing model itself and the organization does not wish to disclose it.

Why: Standard permissive Rust-ecosystem dual license; maximizes reuse + matches riscv-tests/RISC-V tooling norms.

25

Trap / privilege scope

Chosen

Minimal trap model + small CsrFile; no full privileged spec

Rejected

Full M/S/U privilege + virtual memory + interrupts

When the rejected choice is right

A full privileged spec wins when the simulation must boot Linux or an RTOS — any real OS workload requires M/S/U privilege, a page-table walker, and interrupt delivery. The full spec is necessary when modeling OS scheduling or virtualization overhead.

Why: Precise exceptions at commit need a Trap enum + a CSR subset (mcause/mepc-class), not a full OS-capable privilege stack. Privileged mode + page-table walks are explicit NON-GOALS.

26

Multi-core / coherence

Chosen

Single-core only

Rejected

SMP + MESI coherence

When the rejected choice is right

SMP + MESI wins when the research question is specifically cache coherence traffic, memory-consistency-model violations, false sharing, or NUMA effects — which require at minimum two cores and a coherence protocol to observe. Project 187 covers this scope.

Why: MESI/coherence is project 187's charter; single-core keeps the OoO model focused. Stated NON-GOAL.

Roads not taken

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt-A — Event-Driven Discrete-Event Simulation (DES)

 Instructions
     │
     ▼
┌─────────────┐    schedule(event, T+latency)
│ Event Queue │◄───────────────────────────────────┐
│  (min-heap) │                                    │
└──────┬──────┘                                    │
       │  dequeue earliest event                   │
       ▼                                           │
┌──────────────┐  process:                         │
│ Event Handler│  FETCH_DONE, DECODE_DONE,         │
│  (per event  │  EXECUTE_DONE, COMMIT_DONE        │
│   type)      │──────────────────────────────────►│
└──────────────┘                                   │
                         emit next event(s)────────┘

Real system that took this path: gem5 (full-system, memory subsystem events), MARSSx86, PTLsim's event-queue mode.

Winning regime: Long-latency pipelines with many idle cycles (e.g., DRAM-bound or I/O-bound simulations, network-on-chip timing, full-system simulation where the CPU stalls on hundreds of memory cycles at a time). Event-driven simulation skips idle cycles in O(1) (next event may be 200 cycles away) rather than executing 200 no-op tick() calls.

Rejection reason: For a compute-bound OoO pipeline exercising integer workloads, the pipeline is nearly always active (IPC ≥ 1 on a 4-wide machine means most cycles have ≥1 issue). The event-queue overhead (heap push/pop per FU latency, per cache miss, per branch resolution) costs more than the empty-cycle savings. The tick-driven model's determinism is also harder to achieve with an event queue (two events in the same simulated cycle can race on the priority queue ordering). The tick() discipline (ADR-7) wins for this workload class.

Alt-B — Interval Simulation

 Phase 1: Functional execution (fast)
 ─────────────────────────────────────────►
 Every instruction executes in Spike/golden model.
 Collect: branch count, load/store count, cache miss rate.

 Phase 2: Interval model (analytic)
 ─────────────────────────────────────────►
 IPC = f(issue_width, mispredict_rate, cache_miss_rate, mem_latency)
      using closed-form Eyerman-Eeckhout interval model.

 Output: estimated IPC, estimated cycle count.
 No cycle-by-cycle state maintained.

Real system that took this path: Sniper (Carlson et al., SC 2011), McSimA+, ZSim (partial).

Winning regime: Multi-core scalability studies where absolute cycle-accuracy is less important than relative performance comparison (e.g., "does doubling L3 cache help workload X?"). Interval simulation achieves 10–100× faster simulation speed than cycle-accurate at the cost of ≈5–15% IPC error on well-calibrated benchmarks.

Rejection reason: The project goal is cycle-accurate, not interval-approximate. Co-simulation against Spike requires a cycle-by-cycle committed-instruction stream to compare; the interval model produces aggregate statistics, not per-instruction commit records. Interval simulation also cannot produce the wakeup/select/bypass timing data required by Phase 11 performance counters. Cited as the rejected abstraction level in ADR-5 and ADR-13.

Alt-C — Trace-Driven Simulation (no execution engine)

 Pre-recorded trace file
 (PC, opcode, src/dst regs, mem addr, branch outcome)
         │
         ▼
 ┌───────────────┐
 │  Trace Reader │ — replays instructions in order
 └───────┬───────┘
         │  per-instruction record
         ▼
 ┌───────────────────────────┐
 │  Timing Model             │
 │  (OoO scheduler, caches,  │
 │   branch predictor)       │
 │  No ISA semantics needed  │
 └───────────────────────────┘
         │
         ▼
 IPC, cache miss rates, branch accuracy

Real system that took this path: ChampSim (default mode), DineroIV, Valgrind's cachegrind, Intel's Pin-based simulators.

Winning regime: Predictor and prefetcher research where the focus is on timing model accuracy for a fixed workload and the ISA semantics are irrelevant. Trace-driven simulation eliminates the cost of functional execution; a 10-billion-instruction SPEC trace can drive a timing model faster than execution-driven re-simulation.

Rejection reason: Traces are pre-recorded with a fixed execution path. They cannot model value-dependent branches (a predictor that changes the program path changes the trace itself, making the trace invalid). Our simulator is execution-driven: the branch predictor's decision determines which instructions are fetched next, and the functional engine executes them. This is essential for studying mispredict recovery (the simulator must execute the wrong path, then squash it). Co-simulation with Spike is also impossible in trace-driven mode because the trace IS the execution. Cited in ADR-8 (execution-driven vs trace-driven).

Alt-D — RTL Simulation (Chisel/Verilog)

 Chisel/Verilog RTL
       │
       ▼
 Verilator / VCS / Questa
       │  (cycle-accurate, clock-edge driven)
       ▼
 ┌──────────────────────────────────┐
 │  Synthesized netlist simulation  │
 │  Every flip-flop, every wire     │
 │  Timing-accurate to gate level   │
 └──────────────────────────────────┘
       │
       ▼
 Waveform (.vcd), coverage, formal proofs

Real system that took this path: Berkeley BOOM (Chisel + Verilator), CVA6 (SystemVerilog + Verilator), RISC-V Rocket Core.

Winning regime: Tape-out preparation, PPA (power/performance/area) optimization, DFT, timing closure. RTL simulation is the ground truth for what will actually run on silicon; it is cycle-accurate at gate level and can be formally verified.

Rejection reason: RTL simulation is 10–1000× slower than architectural simulation (Verilator-compiled BOOM runs at ~2 MHz vs our target ≥1 M cycles/sec for a simple model; complex RTL is slower). The project goal is architectural insight (IPC sensitivity, branch predictor accuracy, cache hierarchy interaction) — not PPA or tape-out readiness. Writing RTL also requires hardware description language expertise (Chisel/Verilog) that is orthogonal to the software engineering and computer architecture skills this project teaches. Cited as a non-goal in §1 and ADR-25.
