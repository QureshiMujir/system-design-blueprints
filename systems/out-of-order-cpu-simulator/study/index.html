Mental Models & First Principles

These distilled models are the mental shortcuts that separate engineers who understand the pipeline from engineers who merely implement it. Each is a falsifiable claim, a debugging lens, or a design invariant you can hold in your head while staring at a waveform or a regression failure.

# Model Expert insight What it predicts Bug class it catches Blueprint §
MM1 Tomasulo's invariant: the register file is a renaming checkpoint, not a value store Architectural registers are aliases; the real value is in PhysRegFile[pN]. Every incorrect result trace reduces to a broken alias — either the RAT wrote the wrong pN, the wrong pN was freed, or two instructions share a pN. Rename bugs are the root cause of ≈60% of OoO simulation divergences. If cosim diverges, check the RAT snapshot at the offending instruction. Silent value corruption that survives writeback but produces wrong commit values §16, §24
MM2 Wakeup is a distributed broadcast, not a pull When a PhysReg becomes ready, every RS entry that depends on it must know immediately (same cycle or +1 at most). Any "check on issue" approach introduces false stalls. The wakeup CAM is conceptually a SELECT WHERE src = completed_tag. Issue slot starvation in schedules that have fine-grained dependencies; correct but slow IPC numbers on dependent chains. Instructions that wake one cycle late, producing IPC lower than a scalar in-order core on dependent micro-benchmarks §18
MM3 The ROB is the serialisation point; all speculation lives below it Every out-of-order action that the external world must not see (mispredicted path, faulting instruction, wrong-path stores) is invisible as long as the ROB has not committed it. Commit is the only moment reality advances. This is why branch recovery squashes above the mispredicting ROB entry, not below. Any observable side-effect before ROB commit is an architectural violation. Stores that update the cache before commit (premature store retirement); interrupts serviced on speculative paths §22, §6.5
MM4 Load–store ordering is the weakest link in precise semantics RV64I specifies a relaxed memory model (RVWMO). Within a single-thread execution-driven simulator, observed ordering is total (one LSQ, no other threads). The trap is disambiguating whether a younger load overlaps an older store's address before that address is known. This is the forwarding problem: forward when known, stall or speculate when not. Any memory-order violation (younger load read stale value) manifests as a cosim delta exactly at the load's commit, not at its issue. Store-to-load forwarding that forwards from the wrong store entry; partial-overlap forwarding that reads stale bytes §20, §24
MM5 Speculation cost is asymmetric: free to start, expensive to unwind Branch prediction buffers a series of fetched instructions with zero stall; a miss costs branch_resolve_cycle − fetch_cycle bubbles (typically 10–20 cycles for a deep fetch buffer). Accurate prediction is a free-lunch amplifier; misprediction is a multiplicative stall penalty that dominates IPC on branch-heavy code. IPC on integer workloads is dominated by mispredict penalty × mispredict rate, not by structural hazards on a wide machine. Predictor state that is not flushed on squash (leaking speculative history), producing ghost correlations and inflated accuracy metrics §15, §22
MM6 Deterministic simulation is a property of tick order, not of single-threading An OoO pipeline with a deterministic tick() discipline (Commit→WB→Execute→Issue→Dispatch→Rename→Decode→Fetch, reverse pipeline order, no events, no callbacks) produces bit-identical results for the same binary on the same config. Nondeterminism enters through OS scheduling, not hardware parallelism. The tick order encodes the "forwarding axiom": a stage sees results from stages that conceptually precede it. Removing any callbacks or observer patterns from the tick loop and replacing with a fixed-order function call sequence eliminates an entire class of ordering bugs. "Heisenbug" divergences that vanish under --release, appear under --debug, or depend on thread scheduling §6.3, §4.4
MM7 Cosim is a membership test, not a correctness proof Lock-step golden cosim (compare committed arch state per instruction) proves that the simulator's observable behavior matches Spike's for all instructions in this test binary. It does not prove the simulator is correct for untested instruction sequences. The gap closes with a fuzzer (random instruction generation). A cosim miss is almost always a rename, writeback, or forwarding bug; rarely an ISA decode bug if ooo-isa is tested separately. A 100% cosim-passing simulator can still have latent bugs in untested instruction sequences. The right metric is "fuzzer-hours without a cosim delta." Any divergence between simulated committed state and the Spike oracle — value corruption, PC miscalculation, wrong exception target §24, §25
MM8 IPC attribution is a causal chain, not a number Reporting "IPC = 3.2" is nearly useless for engineering. The useful form is: IPC = theoretical maximum − stall fraction due to fetch bubbles − stall fraction due to rename hazards − stall fraction due to issue starvation − stall fraction due to memory latency − stall fraction due to branch mispredictions. Each term names a hardware structure and a workload property. Only then does optimization become mechanical. On any given workload, exactly one term dominates; tuning anything else gives ≤5% improvement. Performance regressions that appear in a commit but have no root-cause — counters expose which stage's stall fraction increased §23, §28.1

Glossary · 47 terms · site-wide glossary

Out-of-order (OoO) execution
Instructions issue/execute as soon as their operands ready, not in fetch order; reordering hidden by in-order commit. This sim's defining property.
Superscalar
>1 instruction per stage per cycle; widths set by ConfigParams.fetch_width/issue_width/commit_width (Phase 11).
Cycle-accurate
Models per-cycle state transitions, not just functional results; each tick() = one clock. Distinct from functional-only golden model.
ISA vs microarchitecture
ISA = RV64IM contract (regs/mem/PC, in ooo-isa); microarchitecture = how it's realized (ROB/RS/LSQ/renaming). Sim implements one µarch of the ISA.
Architectural register
ISA-visible x0..x31 in ArchState.xregs; what commit must reproduce. x0 hardwired 0.
Physical register
PhysReg(u16) in PhysRegFile; renaming target. #phys = ConfigParams.phys_regs > 32, enabling in-flight versions.
Register renaming
Map arch→phys (Rat) to eliminate WAR/WAW false deps; only true RAW remain. RenameUnit, Phase 4. x0 never renamed.
RAT (register alias table)
Rat { map: [PhysReg; 32] }; current arch→phys mapping. Snapshotted into RenameCheckpoint per branch.
Free list
FreeList; queue of unallocated PhysReg. Pop on rename-dst; push old_phys on commit. Empty → rename stall.
Reorder buffer (ROB)
ReorderBuffer circular entries/head/tail; RobEntry per in-flight inst. Allocated in-order at dispatch, retired in-order at commit.
In-order commit
CommitUnit retires up to commit_width head entries/cycle in program order; only point arch state mutates. Guarantees preciseness.
Precise exception
On trap (RobEntry.exception), state reflects all older insts committed, none younger. Squash younger ROB/RS/LSQ at head. Phase 10.
Reservation station (RS)
RsEntry buffer holding waiting ops + operand-ready bits until issued. Here a unified Scheduler.entries.
Unified scheduler
Single shared Scheduler (vs per-FU RS); holds all RsEntry, does wakeup + select across issue ports. Phase 6.
Wakeup
Completing FU broadcasts its dst PhysReg; matching RsEntry.src1/src2 set *_ready. CAM-style match.
Select
Per issue port, pick oldest ready RsEntry (!issued, both srcs ready), mark issued. Age-ordered arbitration.
Issue width
Max insts issued to FUs/cycle = ConfigParams.issue_width; bounded by #IssuePort.
Dispatch
Post-rename insertion of inst into ROB (RobEntry) + RS (RsEntry) in-order. Stalls on ROB/RS full (structural). Phase 5.
Functional unit (FU)
FunctionalUnit { kind: FuKind, latency, pipelined, busy_until }. FuKind: Alu/Mul/Div/Branch/Agu/LoadStore.
Bypass / forwarding network
BypassNetwork forwards ExecResult to dependent issue same/next cycle, so back-to-back dependent ALU ops skip full writeback latency.
Writeback (WB)
FU result written to PhysRegFile.regs, ready[dst]=true; triggers wakeup. Distinct from commit.
Load/store queue (LSQ)
LoadStoreQueue { loads, stores } of LsqEntry; tracks addr/value/ready/committed for memory ordering. Phase 8.
Memory disambiguation
Determine load↔store address aliasing. Unknown older-store addr → load waits (conservative) or speculates + checks at commit.
Store-to-load forwarding
Load with exact-address match to older in-flight store reads that store's value directly, bypassing cache.
Speculation
Execute past unresolved branches / speculative loads; results held in phys regs/LSQ, squashed if wrong. Never mutates arch state pre-commit.
Branch prediction
Predict direction + target at fetch to avoid stall. BranchPredictor trait: predict/update. Phase 3.
BTB (branch target buffer)
Btb; set-associative pc→target cache for taken branches/jumps. Supplies target before decode.
RAS (return address stack)
Ras; LIFO of return addresses; push on Jal(call), pop on Jalr(return) for accurate return prediction.
gshare
Gshare; global history XOR pc indexes 2-bit saturating counters for direction. Default predictor.
TAGE
TageLite; tagged geometric-history-length predictor; multiple tables, longest-matching-tag wins. Higher accuracy alt to gshare.
Misprediction penalty
Cycles lost from wrong-path fetch until redirect after branch resolves in execute; cost = pipeline depth + recovery. Counted in Stats.mispredicts.
Squash / flush
Discard wrong-path / post-trap entries: invalidate ROB/RS/LSQ younger than offending inst, redirect fetch.
Checkpoint / recovery
RenameCheckpoint { rat, free_head } captured at branch rename; on mispredict, restore RAT + roll back FreeList, then squash.
Structural hazard
Resource exhaustion (ROB/RS/LSQ full, FU busy_until busy, free list empty) forcing a stall/bubble.
Data hazard (RAW/WAR/WAW)
RAW = true dep (tracked via PhysReg readiness); WAR/WAW = false deps eliminated by renaming.
IPC (instructions per cycle)
Stats.committed as f64 / Stats.cycles. Primary perf metric; >1 only achievable superscalar.
Pipeline latch
Inter-stage register; modeled by reverse-order tick() so a value produced cycle C is consumed only C+1.
Stall / bubble
Stall = stage holds (no advance); bubble = injected no-op slot. Caused by hazards; reduce IPC.
Golden model
ooo-isa functional execute_functional; reference architectural behavior, timing-independent.
Co-simulation
Lock-step compare committed ArchState (timing model) vs golden every commit; mismatch = divergence. Phase 12.
Deterministic replay
Same seed/ConfigParams ⇒ bit-identical cycle-by-cycle run; enables divergence bisection.
Cache
Cache; set-associative L1/L2 with MSHRs + miss latency; feeds memory latency into issue/wakeup. Phase 9.
MSHR (miss status holding register)
Tracks outstanding cache misses; enables hit-under-miss / multiple in-flight misses (non-blocking cache).
TLB (translation lookaside buffer)
Tlb; set-associative VA→PA cache; miss adds latency to AGU/load path.
CSR (control/status register)
CsrFile in ArchState; minimal subset for traps; full privileged mode is a non-goal.
Trap
RobEntry.exception: Option<Trap>; precise fault/interrupt resolved at commit, triggering squash + handler redirect.
Tick (reverse-order)
OooCore::tick() advances stages Commit→WB→Execute→Issue→Dispatch→Rename→Decode→Fetch; load-bearing determinism rule preventing same-cycle teleporting.
