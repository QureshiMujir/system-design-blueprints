3. Architectural Overview

3.1 Canonical pipeline

    +--------+   +---------+   +--------+   +----------+   +-----------+   +---------+   +--------+
    | Fetch  |-->| Decode  |-->| Rename |-->| Dispatch |-->| Issue/Sch |-->| Execute |-->| Commit |
    | +BPred |   |         |   | RAT/FL |   |  ->ROB    |   |  RS/wakeup|   |  FUs    |   |  ROB   |
    +--------+   +---------+   +--------+   +----------+   +-----------+   +---------+   +--------+
       ^  BTB/RAS                  PhysRegFile           select  ^  bypass     | WB        | precise
       |  Gshare/TAGE                                            |  network    v           v  exceptions
       +<--------------------- mispredict flush / checkpoint restore ----------+   free old_phys
                                                          LSQ <-> Cache/TLB (ooo-mem) hangs off Execute/Mem
    [ ooo-core drives Tick() in reverse stage order; Stats tracks IPC; golden ArchState co-sim checks commit ]

Crate-to-box map: Fetch+BPred → ooo-frontend; Decode → ooo-isa; Rename → ooo-rename; Dispatch→ROB alloc → ooo-rename+ooo-rob; Issue/Sched → ooo-schedule; Execute+bypass → ooo-execute; LSQ<->Cache/TLB → ooo-mem; Commit → ooo-rob; clock/wiring/Stats/cosim → ooo-core.

3.2 System boundaries

Boundary Location Discipline
Trust guest ELF/hex bytes loaded into modeled memory untrusted input; decoder must total-decode (illegal→Trap, never panic); all guest loads/stores bounds-checked against modeled address space; no host escape — guest cannot read/execute host memory
Concurrency none (single-threaded) one deterministic clocked model; no threads, no async, no shared mutable host state; Tick() reverse-order traversal IS the synchronization discipline — a value written in cycle C is visible only at C+1 (latch semantics), so there is no data race to reason about, only stage-ordering
Persistence none pure in-memory model; outputs = Stats report (stdout/JSON) + optional per-cycle trace dump; no DB, no checkpoint files; RenameCheckpoint is in-memory recovery state, NOT durable persistence; deterministic replay reconstructs a run from (seed, ConfigParams, program), not from a saved snapshot

Reverse-order tick() (Commit→Writeback→Execute→Issue→Dispatch→Rename→Decode→Fetch) is the load-bearing invariant for the entire model: it guarantees no same-cycle teleporting of results, making the simulator deterministic and order-independent within a cycle. Every stage below assumes this discipline.

3.3 Stage-by-stage

Fetch + BranchPredictor (ooo-frontend)

Responsibilities: drive fetch PC, read up to fetch_width instructions/cycle from modeled instruction memory (via I-TLB / L1-I in ooo-mem once Phase 9 lands), consult BranchPredictor (Btb for target, Ras for returns, Gshare/TageLite for direction) to pick the next-fetch PC speculatively, and push entries into FetchBuffer. Inputs: current fetch PC, predictor state, redirect requests from branch resolve / commit. Outputs: FetchBuffer of DecodedInst + Prediction{taken,target} tag per fetched branch. Key invariant: fetch is purely speculative — it may run far ahead down a wrong path; every fetched instruction carries enough provenance (its predicted target + the predictor snapshot needed for update) so that a later flush can roll the front-end back exactly. Predictor accuracy target: gshare ≥90%, TageLite ≥95% on riscv-tests branch-heavy kernels. Referenced by: Phase 3 builds this; Phase 10 wires the mispredict-redirect edge; Phase 13 measures MPKI / accuracy.

Decode (ooo-isa)

Responsibilities: turn Inst{raw:u32} into DecodedInst{op,rd,rs1,rs2,imm,is_branch,is_load, is_store,fu} via decode(); classify FuKind; extract + sign/zero-extend immediates per RV64IM format (I/S/B/U/J). Also home of the golden model: ArchState{xregs,pc,csr} and execute_functional(&DecodedInst,&mut ArchState) — the architectural truth the timing model is validated against. Inputs: raw 32-bit words from FetchBuffer. Outputs: DecodedInst stream to Rename; for golden cosim, a one-instruction architectural step. Key invariant: decode is a total function — every 32-bit pattern maps to either a legal Opcode or an illegal-instruction Trap; x0 decodes normally but is hardwired-zero downstream. Referenced by: Phase 1 (full RV64IM semantics + golden model); every later phase consumes DecodedInst; Phase 12 cosim calls execute_functional.

RenameUnit (ooo-rename)

Responsibilities: map each architectural RegId to a PhysReg to eliminate WAR/WAW false dependencies, leaving only true RAW deps tracked via PhysRegFile.ready. Per instruction: look up rs1/rs2 in Rat (→ source PhysRegs), pop a fresh PhysReg from FreeList for rd, record the previous mapping (old_phys) for later reclaim, install the new mapping in Rat. Captures a RenameCheckpoint{rat,free_head} at each branch for recovery. Inputs: in-order DecodedInst. Outputs: renamed instruction (phys sources + phys dst + old_phys) into Dispatch. Key invariant: x0 is never renamed (always reads physical zero, never allocated); the RAT is always a consistent arch→phys snapshot recoverable from the nearest younger-than-branch checkpoint. Stalls when FreeList empty (insufficient phys_regs). Referenced by: Phase 4 builds RAT/FreeList/checkpoint; Phase 10 restores checkpoints on mispredict; Phase 11 widens to issue_width-wide rename.

Dispatch + ReorderBuffer (ooo-rob + ooo-rename)

Responsibilities: allocate one RobEntry{pc,dst_arch,dst_phys,old_phys,done,exception,is_store, mispredict} per renamed instruction at the ROB tail (in program order), allocate the matching RsEntry (and LsqEntry for loads/stores), and stall on structural hazards (ROB full, RS full, LSQ full). Inputs: renamed instruction from Rename. Outputs: live RobEntry (in-order list) + RsEntry handed to the Scheduler + LsqEntry to the LSQ. Key invariant: ROB allocation is strictly in program order on a circular buffer (head/tail); rob_size bounds in-flight instructions; the ROB is the single source of program-order truth used by commit and squash. Referenced by: Phase 5 (allocation + structural stalls); Phase 10 (commit + squash walk the ROB); Phase 11 multi-wide dispatch.

Scheduler / ReservationStation (ooo-schedule)

Responsibilities: hold not-yet-issued RsEntrys; wakeup — when an FU broadcasts a completing PhysReg, set src1_ready/src2_ready on every matching entry; select — each cycle pick the oldest ready entry per FU / IssuePort (age-ordered), mark issued, and route to Execute. Inputs: RsEntrys from Dispatch, wakeup broadcasts from Execute/bypass, ready bits from PhysRegFile. Outputs: up to issue_width issued instructions/cycle to FunctionalUnits. Key invariant: an entry issues exactly once and only when both sources are ready and a matching FU port is free; out-of-order issue is permitted but select is age-priority to avoid starvation. Referenced by: Phase 6 (wakeup/select, OoO issue); Phase 9 (memory latency feeds back into wakeup timing); Phase 11 (multiple IssuePorts + port contention).

FunctionalUnits + BypassNetwork (ooo-execute)

Responsibilities: execute issued ops on FunctionalUnit{kind,latency,pipelined,busy_until} — Alu(1c), Mul(3c, pipelined), Div(iterative, ~20–40c, non-pipelined), Branch(resolve + flag mispredict), Agu(address gen for LSQ), LoadStore; produce ExecResult{dst,value, rob_idx,mispredict} at writeback. BypassNetwork forwards a producer's result to a dependent's issue the same/next cycle so back-to-back dependent ALU ops don't pay full writeback latency. Inputs: issued RsEntry + operand values. Outputs: ExecResult → writeback (sets PhysRegFile.ready, marks RobEntry.done) + wakeup broadcast. Key invariant: latency model honors busy_until (pipelined FUs accept 1/cycle; iterative FUs block until free); writeback drives exactly the wakeup that lets dependents issue at the right cycle. Referenced by: Phase 7 (FU set + latency table + bypass); Phase 11 (replicated FUs per port).

LoadStoreQueue + Cache/Tlb (ooo-mem)

Responsibilities: order memory ops via LoadStoreQueue{loads,stores} of LsqEntry{rob_idx,is_load, addr,value,addr_ready,committed}; compute addresses (via Agu); memory disambiguation — a load checks older stores: exact-address hit → store-to-load forwarding of the store value; unknown older-store address → load waits (conservative) or speculates + detects violation at commit. Backed by Cache(set-assoc L1/L2, MSHRs, miss latency) + Tlb(va→pa) via MemRequest/MemResponse. Inputs: Agu addresses, store data, cache/TLB responses. Outputs: load values (forwarded or from cache) back to writeback/wakeup; ordering constraints to ROB. Key invariant: stores write memory only at commit (architectural state never updated speculatively); loads observe a correct value-ordering vs older stores. Referenced by: Phase 8 (LSQ + disambig + forwarding); Phase 9 (Cache/TLB latency → wakeup feedback); Phase 10 (LSQ squash on flush).

CommitUnit (ooo-rob)

Responsibilities: retire up to commit_width RobEntrys/cycle from the ROB head in program order only when done; on commit, copy result to architectural state, free old_phys back to the FreeList, let committed stores drain to memory; on exception at head, take a precise trap (architectural state reflects all older instructions, none younger); on mispredict at head (or resolve), trigger flush. Inputs: ROB head entries. Outputs: architectural-state updates, freed PhysRegs, trap/flush signals, Stats.committed++. Key invariant: commit is the only place architectural state changes, and always in program order → precise exceptions for free. Referenced by: Phase 10 (commit + precise exceptions + recovery: free old_phys, RenameCheckpoint restore, ROB/RS/LSQ squash, fetch redirect); Phase 12 (cosim compares committed state).

OooCore (ooo-core)

Responsibilities: own all stage units + ROB/RS/LSQ + ConfigParams + Stats + the golden ArchState; drive tick() (advance all stages in reverse pipeline order) and run(max_cycles) -> Stats; maintain the global Cycle counter; wire inter-stage latches; run golden cosim — each commit, lock-step the just-committed architectural delta against execute_functional and assert exact equivalence. Inputs: program image + ConfigParams (+ seed for replay). Outputs: Stats{cycles,committed,mispredicts,cache_misses}, ipc = committed as f64 / cycles, optional trace. Key invariant: reverse-order tick makes the model deterministic and replayable from (seed, config, program); the golden cosim guarantees the committed architectural-state sequence EXACTLY matches the functional model regardless of timing. Referenced by: Phase 0 (tick stub + Cycle/Config/Stats shells); Phase 2 (reverse-order loop + latches); Phase 11 (full Stats set); Phase 12 (determinism + divergence bisection); Phase 13 (IPC/perf benchmarks). Sim-throughput target: ≥1M simulated cycles/sec single-thread.

8. Domain Model — RV64IM, Pipeline State, and Timing

The model has two layers that must stay in agreement: the architectural layer (RV64IM ISA state — what software sees) and the microarchitectural layer (pipeline + physical state — how the OoO core computes it). The golden execute_functional defines the meaning; the timing model defines the cycle cost. Co-sim asserts they commit identical architectural states.

8.1 RV64IM Instruction Encoding → DecodedInst

Fixed 32-bit instructions (no compressed C — PhaseDeferred). Six base formats; decode(raw: u32) -> DecodedInst selects format by opcode[6:0], then funct3/funct7, and emits the canonical fields.

Fmt Bits laid out (MSB→LSB) Has rd Has rs1 Has rs2 Imm bits assembled Example ops
R funct7 / rs2 / rs1 / funct3 / rd / op ✓ ✓ ✓ — Add Sub Mul Div
I imm[11:0] / rs1 / funct3 / rd / op ✓ ✓ — sext imm[11:0] Lw Jalr addi
S imm[11:5] / rs2 / rs1 / funct3 / imm[4:0] / op — ✓ ✓ sext {imm[11:5],imm[4:0]} Sw
B imm[12 10:5] / rs2 / rs1 / funct3 / imm[4:1 11] / op — ✓ ✓
U imm[31:12] / rd / op ✓ — — imm<<12 lui auipc
J imm[20 10:1 11 19:12] / rd / op ✓ —

decode() fill rules (one fact per row):

Field Source
op: Opcode (opcode, funct3, funct7) lookup; unknown → Trap::IllegalInstr flagged, op set to a poison sentinel
rd/rs1/rs2: RegId raw bitfields; formats lacking a field set it to RegId(0)
imm: i64 per-format reassembly + sign extension to 64 bits
fu: FuKind Add/Sub→Alu, Mul→Mul, Div→Div, Beq/Jal/Jalr→Branch, Lw/Sw→Agu(addr) then LoadStore(mem)
is_branch op ∈ {Beq, Jal, Jalr} (conditional + unconditional control transfer)
is_load op ∈ {Lw, …loads}
is_store op ∈ {Sw, …stores}

RV64 width notes: 64-bit xregs; *W ops (addw/subw/mulw/divw) operate on low 32 bits then sign-extend bit 31 → bit 63. RegId(0) (x0) is hardwired zero: reads return 0, writes discarded.

8.2 Architectural vs Physical Register Model

Layer State Owner Cardinality
Architectural ArchState{ xregs[32], pc, csr } ooo-isa (golden) 32 logical regs
Physical PhysRegFile{ regs: Vec<u64>, ready: Vec<bool> } ooo-rename ConfigParams.phys_regs (default 128)
Map Rat{ map: [PhysReg;32] } ooo-rename arch→phys, current speculative map
Recycle FreeList ooo-rename phys regs not in any live RAT/in-flight mapping

Renaming removes WAR/WAW (false deps); only true RAW survives, tracked by PhysRegFile.ready[p]. Per renamed instruction with dst rd:

  1. p_new = FreeList.pop(); ready[p_new] = false.
  2. old_phys = Rat.map[rd] (saved into RobEntry.old_phys for rollback/freeing).
  3. srcs read current Rat.map[rs1], Rat.map[rs2].
  4. Rat.map[rd] = p_new.
  5. x0 special-case: never allocate; Rat.map[0] permanently → a phys reg pinned to value 0, ready=true; rd==x0 instructions get a dummy dst that is never freed.

Worked RAT example (initial Rat.map[i] = Pi for i=0..31, free list = P32..P127):

Step Inst rd reads (phys) allocs new RAT entry old_phys
1 add x1,x2,x3 x1 P2,P3 P32 x1→P32 P1
2 mul x4,x1,x5 x4 P32,P5 P33 x4→P33 P4
3 lw x6,0(x4) x6 P33 P34 x6→P34 P6
4 beq x6,x0,L — P34,P0 — — —

Step 2 src1 already points to producer P32 → the dependency chain is captured purely in phys names, no name-matching at issue.

8.3 Pipeline-Stage State Machine + Reverse-Order Tick()

Per-instruction lifecycle (states stored across stage latches + ROB):

FETCHED -> DECODED -> RENAMED -> DISPATCHED(in ROB+RS) -> ISSUED -> EXECUTING
       -> COMPLETED(writeback, ready set) -> [waits at ROB head] -> COMMITTED | SQUASHED

OooCore::tick() advances stages in REVERSE pipeline order so a value produced in cycle C is visible to consumers only in C+1 (modeling latches — load-bearing determinism rule):

Order Stage Reads Writes
1 Commit ROB head(s), done flags ArchState (golden compare), free old_phys, detect trap/mispredict-at-head
2 Writeback FU outputs (ExecResult) PhysRegFile.ready[dst]=true, ROB done, broadcast dst to scheduler wakeup
3 Execute issued ops, BypassNetwork FU busy_until, produce ExecResult, compute mispredict
4 Issue/Select RS ready entries mark RsEntry.issued, bind IssuePort, start FU
5 Dispatch rename output allocate RobEntry + RsEntry; stall if ROB/RS full
6 Rename decode output RAT update, FreeList pop, checkpoint on branch
7 Decode FetchBuffer decode(raw) → DecodedInst
8 Fetch PC, BranchPredictor enqueue into FetchBuffer, predict next PC

After all 8, Cycle.0 += 1, Stats.cycles += 1. Wakeup broadcast in step 2 sets src_ready so the dependent can be selected in step 4 of the same tick only when bypass allows (back-to-back ALU); otherwise next tick.

8.5 Branch Misprediction — Checkpoint, Squash, Restore

At rename of a branch, capture RenameCheckpoint{ rat: Rat (clone of map), free_head }. The branch carries its checkpoint id + predicted target. On resolve in Execute, ExecResult.mispredict set when actual ≠ predicted.

Worked: beq predicted not-taken at fetch (PC+4), wrong-path I5,I6 fetched/renamed speculatively. Branch resolves taken at cycle R:

Step (cycle R, Commit/WB stage detects at ROB head or at resolve) Action
1 Branch RobEntry.mispredict=true; identified as squash point
2 Squash all ROB/RS/LSQ entries younger than branch (rob_idx > branch)
3 RAT restore from the branch's RenameCheckpoint.rat
4 FreeList rollback to checkpoint.free_head (reclaim wrong-path phys regs)
5 Flush FetchBuffer + Decode/Rename latches
6 Redirect Fetch PC = branch target; BranchPredictor.update(pc, taken, target)

Penalty = cycles from branch fetch to redirect-refill = front-end depth. Default config: Fetch→Resolve ≈ 6–8 cycles; Stats.mispredicts++. First useful instruction enters at R+1 (fetch), reaches issue at R+ front-end depth.

8.6 Store-to-Load Forwarding + Disambiguation Violation

LoadStoreQueue holds LsqEntry{ rob_idx, is_load, addr: Option, value: Option, addr_ready, committed }. Program order via rob_idx. AGU produces address → addr_ready=true.

Forwarding (hit):

S: sw  x7, 0(x10)   ; rob 5, addr=0x2000 known, value=V
L: lw  x8, 0(x11)   ; rob 8, addr=0x2000 known

L scans older stores (rob_idx<8) with addr_ready; exact match rob 5 → forward value=V directly, no cache access, value filled, L completes. Partial/size-mismatch overlap → conservative stall (treat as unknown).

Disambiguation (unknown older store) — two policies:

Policy Behavior
Conservative older store addr_ready=false → load waits until that store's address resolves
Speculative load issues, gets cache value; at the store's address resolve, if it matches the speculated load → violation: squash load + younger (re-fetch from load), Stats mem-order-violation++

Stores write memory only at commit (in-order, head of ROB), so a squash before commit never corrupts memory.

8.7 Malformed / Edge Inputs — Modeled Response

Input / condition Detected at Modeled response
Illegal opcode decode() DecodedInst poison + Trap::IllegalInstr; flows to ROB; at commit head → precise trap, squash younger, set CSR cause
Misaligned load/store (addr % size ≠ 0) AGU/LSQ Trap::LoadAddrMisaligned/StoreAddrMisaligned attached to RobEntry.exception; precise at commit
Divide by zero Execute (Div FU) RV64IM spec: no trap — div → all-ones (-1), rem → dividend; FU completes normally
Signed overflow INT_MIN / -1 Execute (Div FU) spec result: quotient = INT_MIN, rem = 0; no trap
ROB full at dispatch Dispatch (step 5) structural-hazard stall: Rename/Decode/Fetch back-pressure freeze; Stats rob-full-stall cycle++
RS full Dispatch same structural stall (whichever resource is exhausted)
FreeList empty (no phys reg) Rename rename stall until a commit frees old_phys
Infinite loop / no progress run() bounded by run(max_cycles); returns Stats when Cycle.0 == max_cycles; co-sim still valid up to last commit
Access to unmapped VA Tlb Trap::LoadPageFault (minimal model); precise at commit

Precise-exception invariant: a trap is raised to architectural state only when the faulting instruction reaches the ROB head; all younger work is squashed, ensuring ArchState exactly matches the golden model's trap point.

8.8 IPC + Counter Definitions

Counter (Stats) Definition
cycles total ticks executed (Cycle.0 at end)
committed instructions retired in-order by CommitUnit (excludes squashed)
mispredicts branches with ExecResult.mispredict resolved
cache_misses L1 (and per-level) misses recorded by ooo-mem
IPC (derived) committed as f64 / cycles

Derived/auxiliary metrics reported by oooc stats: branch prediction accuracy = (branches − mispredicts)/branches; MPKI = mispredicts*1000/committed; cache MPKI = cache_misses*1000/committed; rob-full-stall %, rs-full-stall %, mem-order-violation count, average issue width = committed/active_cycles. Golden co-sim guarantee (§ Phase 12): the sequence of committed architectural states equals the functional model's, independent of any timing parameter — IPC varies with config, correctness does not.
