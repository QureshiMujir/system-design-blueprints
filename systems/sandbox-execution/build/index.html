⬜ Phase 0 — Skeleton, Governance & Correctness Kernel §12

Objectives
  • Stand up the repository at §10 in one commit; make make bootstrap && make build && make test return zero on a clean checkout.
  • Land the correctness kernel: sandbox-core's types (§11.1-11.4) with zero logic, compiling and lint-clean under cargo clippy -- -D warnings.
  • Ship a "Hello, sandbox" smoke test: Tier::Process with no isolation enabled (no seccomp, no cgroups) running /bin/echo hello end to end.
Deliverable

A repository at the §10 scaffold; make test passes with one integration test that runs /bin/echo hello under Tier::Process (no isolation) and reads back Outcome::stdout == b"hello\n".

Acceptance
  • make bootstrap && make build && make test exits 0 on a clean Ubuntu 24.04 / kernel 6.6 checkout, measured in CI (ci.yml).
  • cargo clippy --workspace -- -D warnings and go vet ./... both exit 0.
  • ADR files for ADR-01, ADR-02, ADR-03, ADR-04, ADR-05, ADR-12, ADR-13 exist under docs/adr/ (7 of the 24 rows, the ones this phase's decisions depend on).
  • Named fixture conformance/corpora/api/hello_process.json passes.
Fixtures
Fixture Purpose Expected Output
api/hello_process.json end-to-end smoke: no-isolation Tier::Process run exit=0, stdout="hello\n"
api/image_not_found.json exec of a nonexistent binary Error::ImageNotFound, no panic
api/preexec_failure.json a pre-execve setup error (bad cwd) errno ferried via CLOEXEC pipe, no zombie
Pitfalls
  • clone3 is not uniformly wrapped by libc crates yet — call the raw syscall via libc::syscall(SYS_clone3, ...) and pin the flag set explicitly; a nix crate version mismatch here is a common silent-flag-drop bug.
  • kernel.unprivileged_userns_clone=0 disables CLONE_NEWUSER for non-root on some distros — surface Error::UnprivilegedUsernsDisabled (§11.9), not a bare EPERM.
  • A pre-execve failure in the child that is not ferried over the CLOEXEC pipe is silent from the parent's point of view — this is exactly the class of bug the pipe exists to prevent (ADR-01 rationale).

⬜ Phase 1 — Process Tier: Namespaces, Seccomp, Capabilities §13

Objectives
  • Land the full seven-namespace Tier::Process sandbox: a Run with Budget::strict(), the default seccomp allowlist, and an empty capability set runs an arbitrary statically linked binary against an OCI-style rootfs and cannot reach outside it.
  • Enforce I1-I5 (no_new_privs ordering, namespace ordering, setgroups-before-gid_map, capability ceiling, no ambient capabilities) as compiled-in, not best-effort.
Deliverable

A Tier::Process run with Budget::evaluation() and the default seccomp policy runs a Python "hello world" against an OCI rootfs and is measurably contained (§13.5 corpus green).

Acceptance
  • Cold start ≤ 50 ms p99 (M1), warm reuse ≤ 10 ms p99 (M5), measured by benchmarks/cold_start_process.py over 1,000 runs.
  • 100 % of conformance/corpora/namespaces/ and conformance/corpora/seccomp/ fixtures pass (§13.5); zero escapes from the 11-script chaos/escapes/ corpus against Tier::Process (§22.3, M2).
Fixtures
Fixture Purpose Expected Output
namespaces/entry_order.json asserts I2 order construction fails if reordered
namespaces/pid_leak.json host PID visibility from sandbox /proc zero host PIDs visible (I12)
namespaces/ambient_caps.json ambient capability probe empty ambient set (I5)
seccomp/no_new_privs_order.json seccomp load before/after no_new_privs load only succeeds in I1 order
seccomp/denylist_probe.json mount/pivot_root/ptrace from inside KillProcess, audited (I6)
Pitfalls
  • setgroups write ordering. Writing the GID map before setgroups deny is rejected by the kernel with EPERM; fix by reordering per I3. Debug signal: the specific EPERM on the GID-map write, not a generic namespace failure.
  • pivot_root over a non-fresh mount. Silently succeeds and leaves the host root reachable if the new root is not on its own mount point; always pivot into the fresh tmpfs sandbox-fs creates, never a bind mount of an existing directory.
  • PID 1 reaping. CLONE_NEWPID's PID 1 must reap orphans; use prctl(PR_SET_CHILD_SUBREAPER, 1) as a belt-and-braces measure against zombies.
  • Wrong-ABI filter (ADR-04) and KILL_THREAD vs. KILL_PROCESS. A filter built for the wrong syscall ABI silently no-ops rather than erroring — the architecture check at filter entry (§13.2) catches it; separately, KillThread leaves the rest of a multi-threaded victim alive as zombies — always use KillProcess (§11.6).

⬜ Phase 2 — Resource Budgets: cgroups v2, rlimits, Timers, Signals §14

Objectives
  • Enforce every field of Budget (§11.3) with two independent layers where the literature shows one alone fails (I8): cgroups v2 as primary, rlimit as backstop.
  • Make budget-triggered kills classify correctly as KilledByBudget(BudgetReason), never a bare Signaled (I7).
Deliverable

A fork-bomb, a memory-bomb, and a wall-clock-runaway workload are each killed within their respective budgets with the correct BudgetReason, measured against the chaos/escapes/ corpus.

Acceptance
  • chaos/escapes/fork_bomb.py: killed by pids.max within 50 ms of the budget (I8); zero host-visible process-table pressure.
  • chaos/escapes/memory_bomb.py: killed by the cgroup OOM (memory.max), not the host OOM killer — verified by the audit record's BudgetReason::Memory.
  • Wall-clock-runaway: ExitStatus::KilledByBudget(WallClock) within Budget::wall_clock + 200 ms (§8.1), 100 % over 1,000 trials.
Fixtures
Fixture Purpose Expected Output
cgroups/fork_bomb.json I8 double-backstop killed, BudgetReason::Pids
cgroups/budget_kill_reason.json I7 classification never a bare Signaled
cgroups/memory_high_without_max.json regression guard for the §14.6 pitfall construction rejects a Budget missing memory.max
Pitfalls
  • memory.high without memory.max. A soft throttle alone lets a sandbox blow host memory; §14.2's construction-time check rejects a Budget that sets one without the other.
  • pids.max without RLIMIT_NPROC. Some workloads fork between the cgroup check and the rlimit check; I8 requires both layers, not either alone.
  • Hierarchical cpu.max surprises. Some kernels do not honour a child's cpu.max when the parent slice has a tighter limit; pin the parent to the superset of all children's limits.
  • RLIMIT_AS measures virtual address space, not RSS — a 4 GB mmap that is never touched is not caught by RLIMIT_AS alone; memory.max is ground truth.

⬜ Phase 3 — Filesystem Isolation & Image Format §15

Objectives
  • Generalize §13.2's filesystem builder into sandbox-fs's full mount-kind set (§11.5 MountSpec) and the content-addressed image format.
  • Layer AppArmor/Landlock defense-in-depth (ADR-17, ADR-18, P12) on top of the primary namespace/overlay boundary.
Deliverable

A Tier::Process sandbox mounts a signed, content-addressed image with a writable overlay scratch and a read-only rootfs; conformance/corpora/filesystem/ passes at 100 %.

Acceptance
  • Image signature verification (I14) rejects a tampered manifest 100 % of the time in filesystem/signature_mismatch.json.
  • Storage amplification ≤ 1.3x uncompressed layer size (§4), measured by benchmarks/overhead_per_tier.py.
  • Zero escapes from chaos/escapes/procfs_traversal.py and chaos/escapes/proc_self_exe_overwrite.py.
Fixtures
Fixture Purpose Expected Output
filesystem/signature_mismatch.json tampered manifest, valid hash Error::ImageSignatureInvalid (I14)
filesystem/overlay_on_old_kernel.json overlayfs-on-tmpfs on kernel < 5.11 Error::OverlayUnsupported, no silent fallback
filesystem/landlock_scope.json write attempt outside /tmp denied at Landlock layer even if seccomp allowed the syscall
filesystem/readonly_remount.json bind-mount read-only flip `MS_REMOUNT
Pitfalls
  • overlayfs on tmpfs requires kernel ≥ 5.11. Older kernels need lowerdir on a real filesystem; surface Error::OverlayUnsupported, never a silent fallback to a weaker layout.
  • Read-only bind-mount flip. MS_BIND|MS_RDONLY in one call is silently ignored; the correct sequence is bind, then MS_REMOUNT|MS_BIND|MS_RDONLY.
  • Bind-mounting the host's /proc. An immediate escape (CVE-class mistake, §23); always mount a fresh procfs, never bind the host's.
  • Bind-mounting a directory containing setuid binaries. MS_NOSUID on the bind itself is mandatory; relying on the underlying filesystem's nosuid flag is wrong if that filesystem is also used elsewhere without it.

⬜ Phase 4 — Network Isolation §16

Objectives
  • Build sandbox-net's five NetworkSpec variants (§11.5); default is None.
  • Enforce egress policy and DNS mediation without granting the sandbox any host-network-namespace capability directly (P3).
Deliverable

A Tier::Process sandbox with NetworkSpec::Slirp reaches an allowlisted egress host and is denied a non-allowlisted one, with both outcomes in the audit chain.

Acceptance
  • Default (NetworkSpec::None) sandboxes: zero non-loopback interfaces present, 100 % over conformance/corpora/network/no_network.json.
  • Egress allowlist: 100 % of denied-destination attempts logged with a DNS-query audit trail, verified against network/egress_denylist.json.
  • Network RTT budget: host RTT + ≤ 2 ms NAT-hop overhead (§4), measured via benchmarks/overhead_per_tier.py.
Fixtures
Fixture Purpose Expected Output
network/no_network.json default isolation only lo, no route to host bridge
network/egress_allowlist.json allowed destination connection succeeds, audited
network/egress_denylist.json denied destination connection refused, audited
network/vsock_only.json Tier::MicroVm boundary no interface but vsock present
Pitfalls
  • veth requires host-netns CAP_NET_ADMIN. The runtime daemon holds it; a sandbox must never be granted it (P3) — a regression here is a direct namespace escape vector for network configuration.
  • Network-namespace teardown order. The veth end must be moved back to the host netns before the sandbox netns is destroyed, or the veth end is orphaned and leaks a host-side interface per sandbox lifecycle.
  • In-process SLIRP re-implementation risk. Reimplementing a TCP/IP+NAT stack in Rust (rather than shelling to slirp4netns) is a correctness surface of its own; the conformance corpus (§16.5) exists specifically to exercise it exhaustively.

⬜ Phase 5 — Wasm Tier (WASI snapshot1) §17

Objectives
  • Land Tier::Wasm (ADR-06) as a structurally isolated alternative to Tier::Process — a module cannot express a raw syscall at all, unlike Native Client's verified-instruction-stream approach (Yee et al., §5 Papers #3).
  • Enforce WASI snapshot1's preopen-only filesystem model and a dual budget mechanism: fuel (CPU) and epoch interruption (wall clock).
Deliverable

A WASI snapshot1 module compiled from Rust or C runs under Tier::Wasm with a preopen-scoped filesystem view and a calibrated fuel budget; conformance is measured against the upstream WASI test suite where importable.

Acceptance
  • Cold start ≤ 30 ms p99 (M2), measured over 1,000 runs.
  • 100 % WASI snapshot1 conformance on the imported upstream test suite (conformance/corpora/wasm/).
  • A module attempting to import an undeclared host function fails instantiation 100 % of the time — zero silent stub-linking.
Fixtures
Fixture Purpose Expected Output
wasm/wasi_snapshot1_suite.json upstream conformance import 100 % pass
wasm/preopen_escape.json path traversal outside preopen ENOENT/trap, never a host path hit
wasm/fuel_exhaustion.json CPU budget breach trap mapped to KilledByBudget(Cpu), never Crashed
wasm/unresolved_import.json module importing an undeclared host fn instantiation fails closed
Pitfalls
  • Fuel exhaustion is a trap, not a kill signal — a naive implementation that treats every trap as Crashed misclassifies every CPU-budget kill (I7).
  • Cranelift/Winch parity. The fast-baseline Winch compiler's semantics must match Cranelift's exactly for determinism (P7); test both as a parity exercise, not just the default codegen.
  • Floating-point determinism. The relaxed-SIMD flag changes cross-host FP determinism; document the flag state in the ADR rather than leaving it implicit.

⬜ Phase 6 — MicroVM Tier (Firecracker) §18

Objectives
  • Land Tier::MicroVm (ADR-07): the tier that answers threats Tier::Process structurally cannot (Spectre-class cross-domain speculation, §23 T7) by giving each sandbox its own kernel.
  • Hold the minimal-device-model discipline (Agache et al., §5 Papers #1) that makes cold start dominated by kernel boot, not device probing.
Deliverable

A Tier::MicroVm run boots a tiny initramfs, executes a command over vsock, and returns an Outcome within the M3 cold-start budget; conformance green on conformance/corpora/microvm/.

Acceptance
  • Cold start ≤ 250 ms p99 (M3, no snapshot), measured over 1,000 runs (benchmarks/cold_start_microvm.py).
  • Boot-time variance ≤ 30 ms over 1,000 runs given the same kernel/initramfs/spec (determinism invariant, §19.4 analog).
  • Max concurrent sandboxes > 200 per reference host (M12, §33 derivation).
Fixtures
Fixture Purpose Expected Output
microvm/boot_lifecycle.json full boot→exec→teardown Outcome within M3 budget
microvm/kvm_unavailable.json no /dev/kvm Error::KvmUnavailable (§8.6), no partial VM left running
microvm/socket_isolation.json Firecracker API socket placement per-sandbox directory, never a shared path
microvm/vsock_only_net.json Phase-0 network surface no virtio-net device present
Pitfalls
  • Firecracker API socket exposure. A stray socket in a shared /tmp is a cross-sandbox leak; the socket must live in a per-sandbox directory the runtime daemon owns exclusively.
  • Rootfs block device permissions. The Firecracker subprocess must be able to read the staged rootfs image; the runtime daemon owns the staging directory and its permission bits explicitly, not via an ambient umask.
  • PhaseDeferred("§18.6"): Cloud Hypervisor as an alternate Tier::MicroVm backend is deferred (ADR-07's rejected alternative) — relevant once vhost-user or GPU passthrough device support is required (§35 Alternative Architectures).

⬜ Phase 7 — Usermode-Kernel Tier (Sentry/Gofer) §19

Objectives
  • Land Tier::UserKernel (ADR-08, ADR-09): a Sentry/Gofer split modeled on gVisor (§5 Papers #2) that mediates every syscall in a fixed 350-entry table, delegating filesystem access to a separate Gofer process the way Ostia delegates system-call interposition to a trusted agent (Garfinkel et al., §5 Papers #5) rather than interposing in-line in the Sentry itself.
  • Understand, by building it, the specific tradeoff (breadth vs. review surface) gVisor took — not to replace gVisor in production (§2 "Why Build This").
Deliverable

A Tier::UserKernel sandbox running the ptrace platform mediates the full documented syscall table with a measured, honestly reported overhead multiplier (§19.4).

Acceptance
  • Syscall-heavy workload overhead ≤ 5.0x baseline on the ptrace platform (M9), measured by benchmarks/overhead_per_tier.py; CPU-bound workload overhead is documented separately as negligible.
  • 100 % of the 350-entry SyscallTable produces a defined result (success, errno, or signal) — zero undefined-behavior escapes in conformance/corpora/userkernel/.
  • Path-containment violations at the Gofer are audited within the I6 200 ms bound.
Fixtures
Fixture Purpose Expected Output
userkernel/syscall_table_completeness.json every entry in the 350-table defined result for each
userkernel/undefined_syscall.json a syscall nr outside the table process killed, audited
userkernel/gofer_path_containment.json path traversal via the Gofer denied at the Gofer, not the Sentry
userkernel/ptrace_overhead.json M9 overhead measurement ≤ 5.0x on the named syscall-heavy corpus
Pitfalls
  • ptrace is slow and detectable. The systrap platform is faster but needs a more intricate signal-handler trick; shipped later behind PhaseDeferred("§19.7"), not a Phase-0 requirement.
  • Gofer trust placement. Enforcing path containment in the Sentry instead of the Gofer defeats the delegation model's entire purpose (§19.2) — the Sentry is part of the boundary under test, not a place to put the defense.
  • Sentry-local servicing correctness. A syscall wrongly marked "serviceable Sentry-local" (e.g. one whose semantics actually depend on host state) produces a subtly wrong result rather than a crash — the completeness fixture (§19.5) exists to catch exactly this class before it ships.

⬜ Phase 8 — Language Runtimes §20

Objectives
  • Wrap the four most common code-eval workloads (Python, JavaScript, R, Shell) as pre-built RunSpec templates plus image manifests — not new tiers, compositions over the existing TierImpls (P1: the tier is still chosen by the caller).
Deliverable

sandbox run --lang python --code 'print(1+1)' (and the JS/R/shell equivalents) each execute end to end against the default Tier::Process budget.

Acceptance
  • All four language templates pass their conformance/corpora/api/ fixture with the documented default budget, zero escapes against the shared chaos/ corpus.
  • Python's subprocess/ctypes/socket denial is enforced 100 % of the time under the default template (verified against the seccomp allowlist, §13.4).
  • Ruby is explicitly out of scope for Phase 0-10's default templates despite appearing in the repository layout's placeholder (sandbox-langs::ruby) — its acceptance criteria are deferred alongside PhaseDeferred("§21.8")'s broader multi-tenant template work.
Fixtures
Fixture Purpose Expected Output
api/lang_python_hello.json Python default template stdout="2\n", exit 0
api/lang_python_subprocess_denied.json denylist enforcement import/call denied, audited
api/lang_js_ses_lockdown.json isolate-vm SES lockdown prototype-pollution probe denied
api/lang_shell_restricted_builtin.json disabled shell builtin denied, non-zero exit, audited
Pitfalls
  • Template drift from the underlying tier's defaults. A language template that hand-rolls its own seccomp policy instead of composing the shared allowlist (§13.4) reintroduces the tier-local-fork risk P4 exists to prevent.
  • SES lockdown ordering. lockdown() must run before any user code executes in the isolate; a template that defers it is not actually providing the isolation it claims.

⬜ Phase 9 — Control Plane, API Surface & Warm Pool §21

Objectives
  • Land sandboxd's gRPC/REST surface (P8: the only network-exposed component) and sandbox-pool's warm-reuse manager (P14).
Deliverable

sandboxd accepts a gRPC Run and a REST POST /v1/run, both producing an Outcome; a warm pool measurably reduces p99 latency for repeat (tier, image) pairs.

Acceptance
  • gRPC Run end-to-end (Tier::Process): p50/p95/p99 = 15/45/80 ms (M8), measured under sustained load.
  • Warm-pool hit rate ≥ 80 % for a workload replaying the same (tier, image) pair at a Poisson-distributed 100 req/s, sandbox-pool reuse fixture.
  • Quota rejection at the control-plane layer completes in < 5 ms p99 (fail-fast, before any runtime-daemon resource is touched).
Fixtures
Fixture Purpose Expected Output
api/grpc_run_roundtrip.json gRPC Run happy path Outcome within M8
api/rest_sse_stream.json REST SSE event stream ordered stdout/stderr/lifecycle events
api/quota_rejection.json over-quota tenant rejected before runtime-daemon dispatch
api/pool_reuse_identity.json warm-pool byte-identity check (P14) reuse denied on budget/image mismatch
Pitfalls
  • Capability-token leakage to logs. The control plane MUST redact tokens before any log line is emitted — a documented pitfall carried forward from the original design review; a redaction-bypass here is a direct tenant-impersonation vector.
  • Warm-pool identity laxity. Granting reuse across differing budgets or images "close enough" is a cross-tenant data-leakage vector (§23 T3) — P14's byte-identity rule has no fuzzy-match exception.

⬜ Phase 10 — Audit, Observability & Chaos Engineering §22

Objectives
  • Close the loop: every sandbox produces a verifiable audit chain (P6, P13, I9), every daemon emits standard telemetry, and the 11-script escape corpus runs as a release gate, not a manual exercise.
Deliverable

The full escape corpus runs against all four tiers with zero escapes; an audit chain for any completed run verifies offline via sandbox-cli inspect --verify-audit.

Acceptance
  • Zero escapes across the 11-script corpus × 4 tiers = 44 combinations (M2).
  • Audit signing throughput > 100K records/sec (M10), measured under sustained load.
  • A 1M-record audit chain verifies offline with zero false positives/negatives (M8 milestone analog, Appendix B).
Fixtures
Fixture Purpose Expected Output
escape/runc_cve_2019_5736.json fd re-exec CVE class contained, audited, zero host impact
escape/cgroup_release_agent.json CVE-2022-0492 class denied by seccomp + cgroup delegation
escape/userns_overflow.json UID/GID map overflow probe rejected at construction (I3/I4)
escape/time_travel.json clock-manipulation probe CLOCK_BOOTTIME budget accounting unaffected (I13)
Pitfalls
  • Audit-record size for truncated output. Logging a full (truncated) stdout inline blows the audit chain's per-record size budget; cap and reference by offset instead of embedding.
  • Chaos-suite flakiness masking a real escape. A flaky chaos script that is "usually" green hides a real regression; chaos scripts must be deterministic (P7) — a flaky one is itself a defect to fix, never to retry-and-ignore.
