Control Plane — the only network-exposed surface (P8); terminates mTLS, resolves a capability token to a tenant, applies the quota engine, and forwards over the Unix socket. Never opens a socket on a sandbox's behalf.

Runtime Daemon — owns tier dispatch through the single TierImpl trait (§11.7, P1), the warm-pool (sandbox-pool, §21.3), and the signed audit chain (sandbox-audit, §22.1). Runs as a bounded service account holding exactly the capabilities in I5.

Tier 1-4 boxes — each implements TierImpl (§11.7) against the Common Substrate; none contains its own filesystem, network, or budget code (P4).

Common Substrate — sandbox-fs, sandbox-net, sandbox-cg, sandbox-ns, sandbox-seccomp; written once, consumed by every tier that needs the primitive (Tier 2 and Tier 3 skip sandbox-seccomp; Tier 3 skips sandbox-ns since Firecracker supplies its own VM boundary).

Every later section stays consistent with this diagram; a mismatch between this diagram, the Repository Layout (§10), and Appendix A (§38) is a defect.

8.3 Validation (malformed-input example)

A RunSpec{tier: MicroVm, budget.memory_bytes: 0} is malformed: Tier::MicroVm's floor is 128 MiB (§4). The validator (sandbox-core::run) rejects it before any namespace or VM is constructed, returning Error::BudgetBelowTierFloor{tier, floor, requested} over gRPC as INVALID_ARGUMENT; no audit LifecycleStart record is emitted because the sandbox was never admitted to Preparing (§8.1).

8.6 Failure-path example — KVM unavailable (Tier::MicroVm)

Prepare() opens /dev/kvm; ENOENT/EACCES surfaces as Error::KvmUnavailable before Firecracker is spawned. Per P2 the sandbox transitions Preparing→Failed, an PrepareFailed{stage: "kvm_open"} audit record is emitted, and sandboxd returns FAILED_PRECONDITION with a link to docs/runbook/kvm-unavailable.md (§25).

Design principles (§6)

  • P1 — Tiers are a workload property, never a hidden default. The caller picks Tier::{Process,Wasm,MicroVm,UserKernel} per Run; the runtime never silently demotes a stronger tier to a weaker one. Tradeoff: a caller can request a tier the host cannot serve (no /dev/kvm) and must handle a closed failure. Operational implication: capacity planning is per-tier (§33). Violated: a "just make it work" demotion turns a security decision into an accident (§23 T4).
  • P2 — Fail closed on every isolation hop. A namespace, cgroup attach, or seccomp load that fails is fatal for the sandbox under construction. Tradeoff: availability drops during host misconfiguration instead of degrading silently. Operational implication: Error::UnprivilegedUsernsDisabled-class errors must have runbooks (§25). Violated: a workload runs with fewer isolation layers than the caller believes (I2).
  • P3 — The host is an authority; the sandbox is a subject. The daemon holds exactly the capabilities in I5; no sandbox inherits ambient capabilities; no_new_privs is unconditional. Tradeoff: some workloads that "just need CAP_NET_BIND_SERVICE" require an explicit RunSpec::capabilities grant, never an ambient one. Operational implication: capability grants are auditable per-run. Violated: an ambient-capability leak is a privilege-escalation primitive.
  • P4 — One filesystem/network/budget builder. sandbox-fs, sandbox-net, sandbox-cg are written once and consumed by every tier that needs the primitive (P4 is why the Architectural Overview §3 has one Common Substrate box). Tradeoff: a tier-specific optimization must first be justified as a substrate change. Violated: tier-local forks of mount/network logic drift and reintroduce the bugs the shared code already fixed.
  • P5 — No dynamic policy at runtime. Seccomp policy, AppArmor profile, capability set, and cgroup limits are resolved at construction and never mutated. Tradeoff: a long-running sandbox cannot be re-budgeted in place; it must be torn down and recreated. Operational implication: budget changes are a new Run, not a PATCH. Violated: a mutable policy is a TOCTOU window (§23 T6).
  • P6 — Audit is a first-class output, not a side channel. Every sandbox produces a signed, append-only audit log (I9); it is part of the Outcome, not a best-effort log line. Tradeoff: audit-chain signing (M10) is on the critical path of every teardown. Operational implication: audit verification is a supported CLI command (sandbox-cli inspect --verify-audit). Violated: an unsigned or best-effort log cannot support a postmortem (§27).
  • P7 — Determinism is the default. Same image, command, input, budget produces the same exit code, the same stdout up to scheduling interleavings, and the same audit shape (I10). Tradeoff: stochastic inputs (/dev/urandom, wall clock) must be explicitly opted into. Violated: a flaky conformance suite (§28) cannot distinguish a regression from noise.
  • P8 — The control plane never speaks to user code. sandboxd hands a RunSpec to the runtime daemon over the Unix socket and reads an Outcome; it never opens a channel directly into a sandbox. Tradeoff: streaming output must be relayed, not proxied, adding one hop of latency (§4, gRPC Run p99 = 80 ms, M8 budget already includes this hop). Violated: a network-exposed process would gain a direct path into privileged code (§23 T5).
  • P9 — Performance is a budget, not a goal. Cold-start targets are §4/§29 numbers; a regression > 10 % on any cold-start budget is a release blocker (ADR-24 in CI). Tradeoff: a correctness fix that regresses cold start needs an explicit budget-exception sign-off. Violated: unbounded performance drift erodes the product's viable workload set (interactive code-eval, §1) without anyone noticing until users complain.
  • P10 — The runtime is one binary. All four tiers ship inside sandbox-runtime; operators install one binary and upgrade in one motion. Tradeoff: the binary is larger and a Tier 4-only deployment still links Tier 2/3 code. Violated: a daemon-per-tier topology reintroduces the "four things to upgrade in lockstep" operational burden this project exists to remove.
  • P11 — Capability-oriented, not ambient, everywhere. The Capability bitflag type (§11.2) is the only way a sandbox gains a privilege; there is no path from "runs as root" to a privilege. Tradeoff: some legacy binaries that assume ambient root (e.g. binding port 80 without CAP_NET_BIND_SERVICE) require an explicit grant or fail. Violated: ambient capabilities are exactly the class of bug behind the 2019-era container-escape wave (§23 T2).
  • P12 — Defense-in-depth layers are additive, never substitutive for the primary boundary. AppArmor and Landlock (§15.3) hardens Tier::Process; neither ever replaces the seccomp filter or the namespace boundary as the primary control. Tradeoff: policy authoring cost is paid twice (seccomp policy + AppArmor profile). Violated: treating a defense-in-depth layer as sufficient on its own reintroduces single points of failure the layering was meant to eliminate.
  • P13 — The audit chain is append-only and externally verifiable. Every audit record chains the previous record's hash (I9); verification does not require trusting the runtime daemon that produced the chain, only the signing key. Tradeoff: a compromised signing key invalidates the trust model retroactively — key rotation (§26) must be planned for, not improvised. Violated: a mutable audit log cannot support a forensic reconstruction after A4 (§23).
  • P14 — Warm reuse requires byte-identical provenance. A pooled sandbox is reused only if the new RunSpec is byte-identical to the one it was warmed for, modulo argv/env (§21.3). Tradeoff: warm-pool hit rate drops for workloads with high RunSpec cardinality. Violated: reusing a sandbox across differing budgets or images is a cross-tenant data-leakage vector (§23 T3).
