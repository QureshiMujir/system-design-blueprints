31. Mental Models & First Principles

  1. MM1 — A namespace virtualizes a kernel identifier table; it is not a security boundary by itself. Predicts: a namespace-only sandbox (no seccomp filter) is escapable via any syscall the namespaced table doesn't cover. Bug class without it: engineers treat "namespaced" as a synonym for "secure" and skip the seccomp layer. Resolving: §13 (Phase 1), I1-I5.
  2. MM2 — A capability is the only legitimate path to privilege; ambient anything is a bug. Predicts: any code path that asks "am I root?" instead of "do I hold capability X?" is eventually wrong under this model. Bug class without it: privilege checks written against UID instead of the Capability bitflags (P11). Resolving: §11.2, §13.2, T2/T9.
  3. MM3 — Fuel meters instructions; epochs meter time; conflating the two misclassifies every CPU-vs-wall-clock kill. Predicts: an implementation that maps fuel exhaustion to a wall-clock BudgetReason will silently misreport "looped too long" as "took too long." Bug class without it: an incorrect ExitStatus::KilledByBudget reason in Outcome (I7). Resolving: §17.2, §17.6.
  4. MM4 — Delegated interposition: the process that decides is never the process with authority over the resource. The Ostia/Sentry-Gofer principle (§5 Papers #5). Predicts: any redesign folding Gofer logic into the Sentry silently loses the containment guarantee. Bug class without it: path-containment bypass (T12). Resolving: §19.2.
  5. MM5 — A hypervisor's larger interface is not automatically a smaller attack surface than a narrower usermode kernel (Garfinkel & Rosenblum, HotOS 2005). Predicts: choosing a VM tier "because VMs are more secure" without counting its actual device-model surface can be wrong — Firecracker's minimal device model, not "it's a VM," is why ADR-07 holds. Bug class without it: assuming any hypervisor gives Tier::MicroVm's properties, including ones with large device surfaces. Resolving: §18.2, §32.
  6. MM6 — Determinism is what makes an escape reproducible, and reproducibility is what makes an escape fixable. Predicts: flaky conformance tests correlate with real, not spurious, escape risk over time. Bug class without it: "we can't reproduce it" becomes a permanent excuse not to fix a reported escape. Resolving: I10, §22.6.
  7. MM7 — Fail-closed trades a silent security hole for a visible availability incident — almost always the correct trade for a sandbox. Predicts: an operator who "fixes" a fail-closed error by loosening the check has reintroduced exactly the bug class P2 exists to catch. Bug class without it: silently relaxing a check to make an alert stop firing. Resolving: §12.9, §13.9.
  8. MM8 — An audit chain's value is proportional to how independent its verification is from the thing it audits. Predicts: any "audit log" stored as a mutable, UPDATE-able database row provides zero forensic value against a compromised-daemon adversary (A4). Bug class without it: designing the audit store as a normal CRUD table instead of an append-only signed hash chain. Resolving: §11.9, T8.

Required reading (§5)

Books

  • "The Linux Programming Interface" — Michael Kerrisk, No Starch Press, 2010. Read the process-creation/execve chapters and the capabilities chapter. Extract: exact fork/clone/execve fd-inheritance and capability-transition semantics that I3/I5 codify. Applied in Phase 1 §13.
  • "Linux Kernel Development," 3rd ed. — Robert Love, Addison-Wesley, 2010. Ch. 3 (Process Management), Ch. 4 (Process Scheduling). Extract: task_struct and the CFS scheduler that cpu.weight (§14) rides on top of. Applied in Phase 2 §14.
  • "Container Security" — Liz Rice, O'Reilly, 2020. The namespaces, control-groups, syscall-filtering, and capabilities chapters. Extract: the production posture Tier::Process converges on. Applied in Phase 1 §13, Phase 3 §15.
  • "Virtual Machines: Versatile Platforms for Systems and Processes" — James E. Smith & Ravi Nair, Morgan Kaufmann, 2005. The process-VM and system-VM trap-and-emulate chapters. Extract: the vocabulary (trap-and-emulate, binary translation) separating Tier::MicroVm from Tier::UserKernel. Applied in §32, §35.
  • "Operating System Concepts," 10th ed. — Silberschatz, Galvin, Gagne, Wiley. Ch. 17 (Protection), Ch. 18 (Virtual Machines). Extract: the protection-domain formalism behind I1-I5. Applied in §7.
  • "Hacking: The Art of Exploitation," 2nd ed. — Jon Erickson, No Starch Press,
  • The shellcode, memory-corruption, and networking chapters. Extract: the attacker's-eye view the Threat Model (§23) is written against. Applied in §23.

Papers

  • Agache et al., "Firecracker: Lightweight Virtualization for Serverless Applications," NSDI 2020. The minimal-device-model argument. Applied in Phase 6 §18, ADR-08.
  • The gVisor design documents (gvisor.dev/docs/architecture_guide/). The Sentry/Gofer split and the platform abstraction (ptrace, kvm, systrap). Applied in Phase 7 §19, ADR-09.
  • Yee et al., "Native Client: A Sandbox for Portable, Untrusted x86 Native Code," IEEE S&P 2009. Software-fault-isolation via instruction-stream verification. Applied in Phase 5 §17 (contrast with WASI's structural, not verified-stream, isolation).
  • Drewry, W., "Introducing seccomp-bpf," LWN.net, 2012 (with the kernel Documentation/userspace-api/seccomp_filter.rst). The BPF-classifier action table. Applied in Phase 1 §13.4, ADR-04.
  • Garfinkel, T. et al., "Ostia: A Delegating Architecture for Secure System Call Interposition," NDSS 2004. Delegating syscall mediation to a trusted agent process rather than interposing in-line. Applied in Phase 7 §19.1 (the Gofer is an Ostia-style delegate).
  • Watson, R. et al., "Capsicum: Practical Capabilities for UNIX," USENIX Security
  • Capability-mode process confinement as an alternative to MAC labels. Applied in §35 Alternative Architectures, P1.
  • Kocher, P. et al., "Spectre Attacks: Exploiting Speculative Execution," IEEE S&P
  • Cross-domain speculative side channels. Applied in §23 T7; the reason ADR-19 routes the Spectre-class threat to Tier::MicroVm rather than Tier::Process.
  • Lipp, M. et al., "Meltdown: Reading Kernel Memory from User Space," USENIX Security 2018. Rogue-data-cache-load side channel. Applied in §23 T7.
  • Garfinkel, T. & Rosenblum, M., "When Virtual Is Harder than Real," HotOS 2005. Why a hypervisor's larger interface is not automatically a smaller attack surface. Applied in §32 (row: MicroVm vs. UserKernel attack surface).
  • Manco, F. et al., "My VM is Lighter (and Safer) than your Container," SOSP 2017. Unikernel-per-request as an alternative to both containers and general VMs. Applied in §35 Alternative Architectures (the unikernel road not taken).

Reference Implementations

  • gVisor (google/gvisor) — study pkg/sentry/kernel/ (syscall table dispatch) and runsc/boot/ (platform selection). Lesson: the platform abstraction that lets one Sentry run over ptrace, kvm, or systrap. Pitfall not to copy: gVisor's syscall table is ~250 KLoC; Tier::UserKernel's Phase-0 table is intentionally a fixed 350-entry subset (§19.2), not a path to full Linux-syscall parity. Applied in Phase 7 §19.
  • Firecracker (firecracker-microvm/firecracker) — study src/vmm/src/device_manager/ (the minimal device model) and src/api_server/ (the control protocol). Lesson: a boot path with 5 devices, not 50, is why cold start is dominated by kernel init and not device probing. Pitfall: do not add a device "for convenience" (virtio-gpu, virtio-9p) without re-measuring the cold-start budget (M3). Applied in Phase 6 §18.
  • runc (opencontainers/runc) — study libcontainer/specconv/ (OCI-spec → namespace/cgroup translation) and the CVE-2019-5736 fix (libcontainer/nsenter/nsexec.c, the /proc/self/exe re-exec pattern). Lesson: the fd-handling discipline that closes the CVE-2019-5736/CVE-2024-21626 class. Pitfall: runc's plugin-shaped hook system is a stretch goal we explicitly defer, not a Phase-0 requirement. Applied in Phase 1 §13.6, §23 T2.
  • bubblewrap (containers/bubblewrap, bubblewrap.c) — the cleanest single-file reference for namespace-and-mount choreography. Lesson: the exact pivot_root sequencing (I3). Pitfall: bubblewrap assumes a single-shot exec, not a long-lived daemon managing thousands of concurrent sandboxes — sandbox-ns must add the lifecycle bookkeeping bubblewrap has no need for. Applied in Phase 1 §13.2.
  • Wasmtime (bytecodealliance/wasmtime, crates/wasmtime/src/runtime/) — study the ResourceLimiter trait and the fuel mechanism. Lesson: wall-clock budgets are epoch-interruption based, not fuel-based (fuel meters instructions, not time). Pitfall: do not conflate the two budget mechanisms in RunSpec::budget (§11.3). Applied in Phase 5 §17.

Glossary (§37) · 47 terms · site-wide glossary

Tier
the caller-selected isolation backend (Process/Wasm/MicroVm/UserKernel, §11.1).
TierImpl
the trait every tier backend implements (prepare/run/shutdown, §11.8).
RunSpec
the immutable, fully-resolved request describing one sandboxed execution (§11.5).
Outcome
the terminal result of a Run, including the audit chain (§11.7).
Budget
the quantified resource ceiling set (memory/CPU/wall/pids/fds/io/net, §11.3).
Capability
the bitflag type gating every privileged operation a sandbox may perform (§11.2).
Namespace
a Linux kernel mechanism virtualizing one identifier table (PID, mount, net, …); not a security boundary alone (MM1).
cgroup v2
the unified control-group hierarchy enforcing resource ceilings (§14, ADR-05).
seccomp-BPF
the Linux syscall-filtering mechanism compiled from a SeccompPolicy (§11.6, ADR-04).
no_new_privs
the process flag that must be set before a seccomp filter loads (I1).
Ambient capability
a capability inherited without an explicit grant; forbidden everywhere in this design (P11, I5).
Bounding set
the ceiling capability set a process (and its children) may ever hold.
pivot_root
the syscall that swaps a process's root filesystem, used to enter the sandbox rootfs (§13.2).
overlayfs
a union filesystem layering a read-only lower directory under a writable upper directory (§15.2).
Landlock
an unprivileged Linux LSM for per-process filesystem scoping, used as Tier::Process defense-in-depth (ADR-17).
AppArmor
a path-based Linux MAC system generating per-sandbox profiles from the mount tree (ADR-18).
Sentry
the usermode kernel process in Tier::UserKernel that mediates syscalls (§19.1).
Gofer
the delegate process holding filesystem authority for Tier::UserKernel (§19.2, MM4).
ptrace
the Linux syscall-tracing mechanism used as the Phase-0 Tier::UserKernel platform (ADR-09).
systrap
the deferred, faster Tier::UserKernel platform using signal-handler interception (§19.7).
vsock
a virtio socket address family used as the control channel between host and microVM guest (§18.2).
virtio
the paravirtualized device model Firecracker exposes to guests (virtio-blk, virtio-net, §18.2).
Firecracker
the microVM hypervisor backing Tier::MicroVm (ADR-07).
WASI
the WebAssembly System Interface; snapshot1 is the import surface Tier::Wasm conforms to (§17.2).
Wasmtime
the Wasm engine backing Tier::Wasm (ADR-06).
Fuel
Wasmtime's instruction-metering CPU-budget mechanism (§17.2, MM3).
Epoch interruption
Wasmtime's time-metering wall-clock-budget mechanism (§17.2, MM3).
Warm pool
the set of pre-constructed sandboxes reused across requests under strict byte-identity (§21.2, P14).
Cold start
the latency from Run request to first user instruction with no warm sandbox available (§4, M1-M4).
TOCTOU
time-of-check-to-time-of-use; the race class P5's static-policy rule exists to prevent (T6).
BLAKE3
the hash function chaining audit records (§8.4, ADR-22).
ed25519
the signature scheme securing the audit chain and release artifacts (ADR-15).
xxh3
the non-cryptographic hash used for content-addressed image identity (ADR-16).
Content-addressed
identified by the hash of one's own content, not a mutable name (§15.2).
SBOM
Software Bill of Materials; generated per release (§28).
SLSA
Supply-chain Levels for Software Artifacts; the provenance model §28 follows.
OTel span
an OpenTelemetry trace unit wrapping one phase of sandbox construction or execution (§22.2, ADR-13).
nftables
the Linux packet-filtering framework enforcing egress allowlists (§16.2).
SLIRP
a usermode TCP/IP+NAT stack providing network access without host-netns privilege (§16.2).
NUMA
Non-Uniform Memory Access; the reference host's node topology bounds Tier::MicroVm concurrency (§33 item 4).
RTO
Recovery Time Objective; the bound on how fast service resumes after a failure (§4, §25).
Fail-closed
the design stance that any isolation-hop failure aborts construction rather than degrading silently (P2, MM7).
TCB
Trusted Computing Base; the set of components whose compromise breaks the security guarantee (§32, MM5).
Ostia delegation
the pattern of routing syscall interposition decisions to a separate trusted agent process (§5 Papers #5, MM4).
Spectre/Meltdown
cross-domain speculative-execution side channels; the reason Tier::MicroVm exists as an escape valve from Tier::Process (T7, §5 Papers #7-8).
CRIU
Checkpoint/Restore In Userspace; the deferred snapshot mechanism for Tier::Process (§13.7).
Oversubscription ratio
the number of lightweight guest workloads scheduled per physical vCPU beyond 1:1 (§33 item 5).
