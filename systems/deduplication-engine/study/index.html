Hard questions (§37)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does mark-and-sweep GC require a writer-pin (I6) instead of a simpler ref-count, and under what ingest-concurrency regime would ref-counting actually be safer? (§9 ADR-04, §18, §38)
  2. Derive the RAM ceiling for a 500 M-chunk single-host index and show why sharding is the only lever past it. (§4, §36, §23)
  3. Why is compress-then-encrypt fixed, and name the one regime where the reverse order is defensible. (§9 ADR-03, §21)
  4. Trace how a torn container append cannot corrupt the index, using I7 and the ingest pipeline ordering. (§15, §16, §7)
  5. Per-chunk AEAD with HKDF and a pool-wide key would both preserve cross-tenant dedup — what's the actual reason per-chunk keys are chosen? (§9 ADR-06, §21, §35)
  6. Contrast FastCDC's gear-hash mixing with Rabin's polynomial mod — why is edit- invariance preserved in both but throughput differs by ~2.5×? (§13, §20, §5)
  7. Why does the writer-pin GC-epoch defense scale worse than a WAL-tail-offset check under very high manifest concurrency, and what deferred feature would help? (§9 ADR-21, §18, §39)
  8. Why is dedup ratio (I10) guaranteed ≥1.0 but the compression ratio is not similarly guaranteed — what pipeline stage breaks the guarantee and how is it caught? (§7 I9/ I10, §17)
  9. Show the arithmetic for why 16 MiB containers were chosen over 128 MiB. (§9 ADR-22, §36, §15)
  10. Why does Venti's SHA-1 addressing no longer meet this blueprint's collision-safety bar, and what's the operator escape hatch if SHA-256 is ever broken? (§9 ADR-02, §7 I2, §26)
  11. Explain why the scrubber is necessary even though the chunk-header CRC32C already exists — what failure mode does CRC32C alone miss? (§15, §19)
  12. Derive the compaction write-amplification for a pool compacting weekly at 50% live ratio, and connect it to the SSD-endurance constraint. (§22, §36, §4)
  13. Why can a distributed pool not simply run N independent single-host pools — what does cross-shard manifest resolution require that independence would break? (§23, §16, §7 I3)
  14. Contrast this blueprint's manifest recursion with perkeep's permanode model — what's the practical difference in GC reachability tracing? (§8, §35, §18)
  15. Why does the blueprint reject convergent encryption in favor of HKDF-from-pool-key — what confirmation-of-file attack does convergent encryption alone permit? (§38, §21, §26)
  16. Trace the failure path when a manifest commits before all its chunks are indexed — what does fsck detect, and what is the unrecoverable data-loss boundary? (§7 I3, §25.2, §27)
  17. Why is BLAKE3 deferred rather than adopted now, given it is faster than SHA-256 — what does ADR-02's rationale actually weigh? (§9 ADR-02, §39, §32)
  18. Show why the B-tree index beats an LSM-tree for this workload, and name the ingest regime where that reverses. (§9 ADR-08, §14, §4)
  19. Why must the AEAD nonce be deterministic (fingerprint-derived) rather than random, and what invariant would break under a random nonce? (§9 ADR-23, §7 I8, §21)
  20. Using the Comparative Architecture Table, explain why Windows Server Dedup's post-process-only model would be the wrong default for this blueprint's primary use case, and where post-process is still selected here. (§35, §1, §16.3)

34. Mental Models & First Principles

  • MM1 — A fingerprint is not a name, it's a proof. Insight: content-addressing means the address is a claim about the content. Predicts: any two chunks with equal fingerprints are safely interchangeable. Bug class without it: engineers treating fingerprints as opaque IDs reintroduce location-addressing aliasing bugs. Resolving: §7 (I1), §11.
  • MM2 — The index is the pool's only expensive resource. Insight: disk is cheap; RAM for fingerprints is the binding constraint. Predicts: every scaling decision (sharding, sparse indexing) is really an index-RAM decision. Bug class without it: optimizing chunk-store throughput while ignoring index RAM hits an OOM wall at scale. Resolving: §4, §36.
  • MM3 — GC is a distributed-consensus problem in miniature. Insight: mark-and-sweep concurrent with writers is the same reachability-under-concurrent-mutation problem as a language runtime's concurrent GC. Predicts: writer-pin/epoch mechanisms mirror GC write-barriers. Bug class without it: naive GC that does not pin in-flight manifests loses just-written data. Resolving: §18, I6.
  • MM4 — Append-only turns crash recovery into arithmetic. Insight: an append-only container reduces "what got corrupted?" to "where did writing stop?" Predicts: recovery is always a forward scan to the first bad CRC, never a global repair. Bug class without it: in-place stores need a full-structure fsck; this design needs only a tail scan. Resolving: §15.4, §27.
  • MM5 — Compression and encryption commute in cost, not in effectiveness. Insight: pipeline order doesn't affect whether both operations succeed, but drastically changes the ratio. Predicts: any pipeline analysis must check operation order first. Bug class without it: silent ratio regressions from a reordered pipeline. Resolving: I9, §17.
  • MM6 — A manifest is a chunk about chunks. Insight: recursion is the same mechanism at every layer — a fingerprint addresses bytes, whether those bytes are file data or a list of fingerprints. Predicts: GC, storage, and versioning treat manifests uniformly with chunks. Bug class without it: special-casing manifest storage duplicates the store/index code path and doubles the bug surface. Resolving: §8, §16.2.
  • MM7 — Dedup ratio measures data, compression ratio measures entropy. Insight: the two ratios answer different questions and multiply, they don't add. Predicts: an operator dashboard must report both, never collapse them into one number. Bug class without it: support tickets from operators confused why "the one ratio" doesn't match. Resolving: §17.6, §28.
  • MM8 — Content-defined chunking trades determinism for boundary stability. Insight: CDC accepts unpredictable per-chunk sizes in exchange for boundaries that survive edits. Predicts: any workload with globally-shifting content must never use fixed-size chunking. Bug class without it: "optimizing" by switching to fixed blocks silently destroys dedup ratio on edited files. Resolving: I11, §13, ADR-07.

5. Required Reading

Books

  • Kleppmann, Designing Data-Intensive Applications (O'Reilly, 2017), ch. 3 "Storage and Retrieval" (Hash Indexes, SSTables, B-Trees). Extract: why a B-tree beats a hash index when durable range-scan is required. Applied in §9 (ADR-08), §14 (Phase 2).
  • Petrov, Database Internals (O'Reilly, 2019), ch. 2–4 (B-Tree structures), ch. 7 (WAL). Extract: page layout, node split/merge, checkpoint protocol. Applied in §14 (Phase 2), §22 (Phase 10 compaction CAS).
  • Jones, Hosking, Moss, The Garbage Collection Handbook (CRC Press, 2011), ch. 2–3 (tracing collectors, mark-sweep). Extract: soundness/completeness of tracing, concurrent-marking write barriers. Applied in §18 (Phase 6), I6.
  • Arpaci-Dusseau & Arpaci-Dusseau, Operating Systems: Three Easy Pieces (2018), "Crash Consistency" chapter. Extract: write-ahead logging and the crash-consistency proof technique. Applied in §14 (Phase 2), §15 (Phase 3 torn-append recovery).
  • Gregg, Systems Performance, 2nd ed. (Pearson, 2020), ch. 6 (CPU), ch. 9 (Disk). Extract: the USE method for diagnosing throughput/latency bottlenecks. Applied in §32 (Performance Engineering), §13.7 (Phase 1).
  • Aumasson, Serious Cryptography, 2nd ed. (No Starch Press, 2024), AEAD/HKDF chapters. Extract: nonce-reuse catastrophe analysis, HKDF domain separation. Applied in §21 (Phase 9), I8.

Papers

  • Zhu, Li, Patterson, "Avoiding the Disk Bottleneck in the Data Domain Deduplication File System," FAST 2008. Stream-Informed Segment Layout + locality-preserving cache. Applied in §16.6 (Phase 4 pitfalls), §36, §35 (Comparative Architecture Table).
  • Muthitacharoen, Chen, Mazières, "A Low-Bandwidth Network File System," SOSP 2001. Rabin-fingerprint CDC. Applied in §20 (Phase 8), P2.
  • Quinlan, Dorward, "Venti: a New Approach to Archival Storage," FAST 2002. Write-once content-addressed storage. Applied in §8 (Domain Model), §35.
  • Manber, "Finding Similar Files in a Large File System," USENIX Winter 1994. Anchor/ fingerprint-sampling prehistory of CDC. Applied in §8, §13 (Phase 1).
  • Rabin, "Fingerprinting by Random Polynomials," Harvard TR-15-81, 1981. The polynomial-fingerprint algebra over GF(2). Applied in §20 (Phase 8).
  • Xia, Jiang, Feng, Tian, Fu, Zhou, "FastCDC: a Fast and Efficient Content-Defined Chunking Approach for Data Deduplication," USENIX ATC 2016. Gear hash + normalized chunking. Applied in §13 (Phase 1), P2/P3.
  • Meyer, Bolosky, "A Study of Practical Deduplication," FAST 2011. Chunk-level vs. whole-file dedup-ratio study across real file systems. Applied in §36, §33 (Scalability Analysis).
  • Lillibridge, Eshghi, Bhagwat, Deolalikar, Trezise, Camble, "Sparse Indexing: Large Scale, Inline Deduplication Using Sampling and Locality," FAST 2009. RAM-bounded index via sampling + locality. Applied in §14 (Phase 2), §36, P13.
  • Bhagwat, Eshghi, Long, Lillibridge, "Extreme Binning: Scalable, Parallel Deduplication for Chunk-based File Backup," MASCOTS 2009. File-similarity bin routing for parallel dedup. Applied in §23 (Phase 11 sharding).

Reference Implementations

  • restic — internal/repository/, internal/pack/. Lesson: chunk-store + manifest design in a modern, tested Go codebase. Pitfall: do not copy its per-repo master-key wrapping scheme blindly into a multi-tenant HKDF design (§21). Applied in §16 (Phase 4), §24 (Phase 12 import).
  • BorgBackup — src/borg/chunker.pyx, src/borg/archive.py. Lesson: Buzhash chunker
    • per-chunk compression negotiation. Pitfall: Borg's single coarse repository lock is not a model for concurrent multi-writer GC (§18). Applied in §20 (Phase 8 contrast), §24.
  • OpenZFS — module/zfs/ddt.c, module/zfs/dsl_scan.c. Lesson: fixed-block DDT (dedup table) design. Pitfall: the DDT's unconditional RAM residency is the canonical cautionary tale behind §4/§36. Applied in §4, §36, §35.
  • bup — lib/bup/hashsplit.py, lib/bup/vfs.py. Lesson: git-pack-file as a chunk container. Pitfall: bup has no independent GC (rides on git gc) — not a model for §18. Applied in §15 (Phase 3 contrast), §35.
  • perkeep (Camlistore) — pkg/blob/, pkg/schema/. Lesson: permanode / content-addressed schema recursion. Pitfall: unbounded schema recursion depth without a cycle guard. Applied in §16 (Phase 4 manifest recursion), I3.
  • Plan 9 venti/vac source. Lesson: the original write-once CAS reference implementation. Pitfall: SHA-1 addressing is now below the collision-safety margin this blueprint requires — contrast for ADR-02. Applied in §9 (ADR-02), §8.

RFCs / Specifications

  • **NIST FIPS 180-4, Secure Hash Standard (SHS).** SHA-256 specification. Applied in §11 (Fingerprint type), ADR-02.
  • NIST SP 800-38D, Recommendation for Block Cipher Modes of Operation: GCM. Background AEAD-mode analysis. Applied in §21 (Phase 9), ADR-14.
  • RFC 8439, ChaCha20 and Poly1305 for IETF Protocols. The AEAD construction used. Applied in §21 (Phase 9), ADR-14.
  • **RFC 5869, HMAC-based Extract-and-Expand Key Derivation Function (HKDF).** Per-chunk key derivation. Applied in §21 (Phase 9), I8.

Glossary (§40) · 47 terms · site-wide glossary

Chunk
a variable-size slice of an input stream, identified by its SHA-256 fingerprint.
Container
a 16 MiB on-disk file holding a sequence of chunks; sealed and immutable once full.
Fingerprint
the SHA-256 over a chunk's bytes; the chunk's address (P1).
Manifest
an ordered list of fingerprints reconstructing a stream; itself stored as a chunk (informally, a "recipe").
Pool
the collection of containers, index, and manifests forming one deduplication context.
Cut point
a stream offset at which the chunker declares a chunk boundary.
Dedup ratio
bytes_in / bytes_stored; always ≥ 1.0 (I10); higher is better.
Tombstone
a logical delete; the index entry is flagged, bytes remain until compaction.
GC (garbage collection)
the mark-and-sweep process reclaiming tombstoned chunks.
Scrub
the background re-fingerprint loop that detects bit-rot.
Content-Defined Chunking (CDC)
chunking by rolling-hash cut points rather than fixed offsets.
Fixed-size chunking
chunking at constant byte offsets; rejected by ADR-07 for edit-instability.
Gear hash
FastCDC's per-byte mixing function: h = (h << 1) + gear[byte].
Normalized chunking
biasing cut-point probability toward the average size via asymmetric masks.
Rabin fingerprint
a polynomial-modular rolling fingerprint over GF(2) (Rabin 1981).
Rolling hash
a hash function updatable in O(1) as a window slides over a stream.
Chunk store
the append-only container-based subsystem holding chunk bytes.
Index
the fingerprint → location (ChunkRef) mapping, backed by a B-tree + WAL.
B-tree
the balanced tree structure (rank-67 project) used as the index substrate.
WAL (Write-Ahead Log)
the durability primitive (rank-71 project) logging index mutations before they apply.
Checkpoint
a full snapshot of the index tree, truncating the WAL to post-checkpoint entries.
Sealed container
a container that has reached its size limit and become immutable.
Active container
the currently-appendable container accepting new chunk writes.
Compaction
rewriting a container's live chunks into a fresh container, reclaiming tombstoned space.
Live ratio
the fraction of a container's bytes belonging to non-tombstoned chunks.
Mark phase
the GC phase tracing reachability from live manifests.
Sweep phase
the GC phase tombstoning unreached index entries.
Writer pin
a registered in-flight manifest that the GC treats as live regardless of mark-phase timing (ADR-21).
GC epoch
the point-in-time snapshot of live manifests a mark phase traces from.
Inline dedup
fingerprinting and indexing a chunk before it is written.
Post-process dedup
writing a stream first, then chunking/indexing it from staging.
AEAD (Authenticated Encryption with Associated Data)
an encryption mode providing both confidentiality and integrity (e.g. ChaCha20-Poly1305).
HKDF
HMAC-based key derivation function (RFC 5869), used to derive per-chunk keys.
Nonce
the AEAD's per-message unique value; derived deterministically from the fingerprint here (ADR-23).
Domain separator
a fixed salt/label ensuring one HKDF use cannot be confused with another.
Convergent encryption
deriving an encryption key from the plaintext itself (rejected, §38 Alt 3).
Locality-preserving cache
a cache exploiting the tendency of a stream's chunks to reference recently-seen fingerprints (Zhu et al. 2008, sec. 3.1).
Sparse index
a RAM-bounded index technique sampling a subset of fingerprints (Lillibridge et al. 2009).
Shard
one independent, host-local index+store partition of a distributed pool.
Shard router
the component routing a fingerprint to its owning shard.
fsck
the operator tool auditing pool consistency against I1–I14.
Torn append
a chunk write interrupted by a crash before its fsync completed.
CRC32C
the Castagnoli CRC variant used for chunk-header and container-footer integrity checks.
Poisoning (chunk poisoning)
a malicious producer attempting to insert crafted bytes under a forged or colliding fingerprint (T2).
Collision (hash collision)
two distinct byte sequences sharing a fingerprint (T3, I2).
Byte-compare fallback
the opt-in insert-time verification distinguishing a true duplicate from an observed collision.
Segment
Data Domain's term for what this blueprint calls a chunk (§35).
