Firmware / Hardware Layer. The hardware trust boundary. All bytes crossing it — ACPI tables, ECAM MMIO reads, interrupt-fabric metadata — are untrusted input (P7); firmware bugs and malformed hardware are production realities, not hypotheticals.

pcie-platform-abstraction. Isolates x86_64/ARM64 differences: page attributes, ordering barriers, cache behavior, alignment, fault containment. The only crate permitted unsafe blocks outside a narrow audited allowlist (ADR-19, P13).

pcie-acpi. Parses RSDP → XSDT → MCFG. Validates segment ranges, ECAM boundaries, bus windows, root-complex metadata. Rejects malformed firmware state before enumeration starts (fail-closed, P7).

pcie-ecam. The sole path for configuration-space access. Owns alignment enforcement (I1), retry bounding (I11), timeout detection, and per-device quarantine on repeated fault.

pcie-enumerator. Recursive traversal: bridges, endpoints, functions, multi-function devices, subordinate buses. Deterministic ordering (P1) — the same firmware topology always yields the same scan order.

pcie-capabilities. Standard-list (offset 0x34) and extended-chain (offset 0x100) parsing with mandatory cycle detection (I5). A malformed vendor chain degrades one device, not the boot (P11).

pcie-resource. BAR probing/sizing, interval-tree allocation, non-overlap enforcement (I3), alignment enforcement (I8), rollback on partial failure.

pcie-topology. The single writer of canonical device state (P5). Stable IDs across rescans (I4), generation-counter snapshot publication (I10) so readers never observe a torn mutation.

pcie-tracing. Mandatory structured telemetry: spans keyed by DeviceAddress, Prometheus metrics, replay checkpoints. Bounded producers (P9).

pcie-hotplug-core. Owns the only path that mutates topology after initial scan: event queue, debounce, insert/remove, bridge-window rebalance, generation swap.

pcie-replay. Append-only, checksum-validated, deterministically replayable event log (I7, P6). The forensic and CI-regression backbone of the whole stack.

pcie-conformance. Fixture replay, fuzzing (ACPI/capability/replay decoders), and differential testing against Linux drivers/pci/ and FreeBSD sys/dev/pci topology output.

8. Domain Model — PCIe Address Space, Capability Protocol & Enumeration State Machine

Canonical address tuple. (segment, bus, device, function) — printed conventionally as 0000:3b:00.0 (segment:bus:device.function, hex). Segment is a PCI domain (multiple host bridges on large systems); bus/device/function together select one configuration-space register file.

ECAM address derivation (PCI Express Base Specification): given a per-segment ECAM base address from MCFG,

ecam_address = ECAM_BASE
             + (bus      << 20)
             + (device   << 15)
             + (function << 12)
             + register_offset

Bus occupies 8 bits, device 5 bits, function 3 bits, register offset 12 bits (4 KB extended config space per function) — the field widths that directly justify the §4 topology-size budgets.

Device state machine:

State Meaning
Undiscovered no scan performed yet
Probing a config access is in flight
Identified vendor/device ID read and validated non-0xFFFF
CapabilityParsing capability chain walk in progress
ResourceAssigned BAR allocation complete for this device
Active published in the topology snapshot, visible to consumers
Failed malformed or inaccessible; quarantined, not retried
Removed hotplug removal processed, node retired

Enumeration sequence (Phase 3, §15): Root Complex → Scan Bus → Read Vendor ID → Identify Header Type → Parse BARs → Parse Capabilities → if Header Type 1 (bridge): Assign Secondary/Subordinate Bus → Recurse into the new bus. Header Type 0 is an endpoint function; Header Type 2 (CardBus) is explicitly out of scope for Phase 0 and is rejected, not silently skipped.

Capability parsing rules (Phase 4, §16): the standard capability linked list starts at config offset 0x34, is 4-byte aligned, and terminates on a null next-pointer. The PCIe extended capability chain starts at offset 0x100, is 4-byte aligned, and uses a 12-bit next-pointer field with next-pointer semantics enforced against I5 (loop detection). Failure path: a malformed cycle (capability A → capability B → capability A) is detected by a bounded-size visited-offset bitmap, parsing aborts, the device is marked Failed/degraded, and topology enumeration continues past it — per P11, isolation of a malformed device must never abort the whole scan.

BAR sizing sequence (Phase 5, §17): save the original BAR value; write all-1s; read back the size mask; restore the original value; compute the required alignment from the mask; reserve the allocation against pcie-resource's interval tree before ever touching hardware state again.

Hotplug mutation sequence (Phase 7, §19): Event Interrupt → Hotplug Queue (debounced, bounded per P4) → Topology Lock (I6 order) → Remove/Insert → Resource Rebalance → Publish new generation snapshot (I10). Readers mid-traversal against the prior generation are unaffected.
