  • Q2. If P1 (determinism, §6) and P4 (bounded resources, §6) conflict during a hotplug storm, which principle wins, and where in §19 is that tradeoff actually encoded?
  • Q3. Trace through why an I6 lock-ordering violation (§7) surfaces first as a §21 soak-test flake rather than a §18/§19 unit-test failure, and what that implies about unit-test coverage of concurrency invariants.
  • Q4. §31 shows Zircon using a coarser-grained bus lock than this design's I6 (§7) four-level order. Under what device-count regime (§4, §32) would Zircon's simpler model actually outperform this one?
  • Q5. The ADR-04 Cap'n Proto replay format (§9) and the I7 byte-identical replay invariant (§7) are both satisfied today. Which specific ADR-26 reproducible-build guarantee is I7 secretly depending on?

  • Q7. Given the §4 32 MB bootstrap ceiling and §32's C1 topology-node arithmetic, at what device count does the replay buffer (I12, P4, both in §7/§6), not the topology graph itself, become the binding memory constraint?
  • Q8. §22's "Malicious Devices" threat and §16's P11 isolation principle both assume a malformed capability chain is worse than a missing one — construct the case where a missing MSI-X capability is more dangerous, and identify which §23 row would catch it.
  • Q9. MM1's "topology as published state" model (§30, informed by Barrelfish per §5) and P5's single-writer discipline (§6) together imply readers never block — under what §19 hotplug condition does a reader still experience unbounded latency?

  • Q11. §26's differential-testing strategy compares this stack against Linux and FreeBSD; if both references agree with each other but disagree with this stack, which §7 invariant should be checked first before assuming the references are right?
  • Q12. §28's targets table and §4's constraints table are required to carry identical numbers — which single §32 derivation would break both simultaneously if the §4 device-per-segment figure changed from 4096 to 65536?
  • Q13. ADR-19's unsafe-isolation policy (§9) and the §11 ConfigAccessor trait both gate raw MMIO access — if a capability-parsing bug needed direct hardware access to fix efficiently, which would have to be violated, and what §22 threat surface would that reopen?

30. Mental Models & First Principles

  • MM1 — Topology Is Published State, Not Shared Memory. Compressed insight: treat the device graph as a versioned artifact a writer publishes and readers pull, not memory readers reach into live · Predicts: readers never need a lock to be correct, only to be current · Bug class avoided: torn reads during concurrent hotplug · applies in §18 and §19.
  • MM2 — Firmware Is an Adversary, Not a Collaborator. Compressed insight: every firmware byte is untrusted input until validated, symmetrically with how a network parser treats a socket · Predicts: a "trusted" firmware table can still be malformed by a real BIOS bug, not just an attacker · Bug class avoided: ECAM address derivation running off the end of mapped MMIO · applies in §13.
  • MM3 — Isolation Radius Determines Blast Radius. Compressed insight: the unit you quarantine on failure (one device, one bridge subtree, one segment) is a design choice, not a consequence · Predicts: choosing "device" as the isolation unit bounds a malformed capability's damage to exactly one node · Bug class avoided: one bad device taking down the entire enumeration pass · applies in §16.
  • MM4 — Determinism Is a Property of the Whole Pipeline, Not One Stage. Compressed insight: a deterministic scan order plus a nondeterministic hash-map iteration downstream still yields a nondeterministic result end to end · Predicts: I7 violations trace back to the first nondeterministic operation, not necessarily the replay layer itself · Bug class avoided: chasing replay bugs in the wrong crate · applies in §20.
  • MM5 — Bounded Beats Fast Under Adversarial Load. Compressed insight: an unbounded structure that is fast in the common case is a denial-of-service surface in the adversarial case · Predicts: every queue/cache/buffer needs an explicit ceiling before it needs an optimization · Bug class avoided: a hotplug flap storm or fuzz run exhausting the bootstrap heap · applies in §19 and §21.
  • MM6 — A Lock Order Is a Global Invariant, Not a Local Convention. Compressed insight: I6's four-level order only prevents deadlock if every lock-holding path obeys it, including ones written months later by someone who never read this document · Predicts: a deadlock introduced far from the original design will surface only under concurrent load, matching FM-6's soak-only symptom · applies in §7 and §21.
  • MM7 — Replay Determinism Is Free Only If Designed In From the Start. Compressed insight: retrofitting I7 onto a system with hidden nondeterminism (wall clocks, hash-map iteration) costs far more than avoiding those sources up front · Predicts: every crate added after Phase 8 (§20) must independently justify why it introduces no new nondeterminism · Bug class avoided: silent replay divergence discovered only in production · applies in §20.
  • MM8 — The Rejected Alternative Is Load-Bearing Documentation. Compressed insight: an ADR's 6th column (the regime where the rejected choice wins) is what lets a future engineer safely revisit the decision without re-deriving the whole design space · Predicts: an ADR without that column will be silently violated the first time someone hits its regime · Bug class avoided: re-litigating settled decisions from scratch under time pressure · applies in §9 and §34.

5. Required Reading

Books

  • PCI Express System Architecture — Budruk, Anderson & Shanley (2003), all chapters: config space layout, capability structures, BAR semantics; applied in §11 and §15.
  • PCI Express Technology 3.0 — Jackson & Budruk (2012), topology and capability chapters: switch/bridge enumeration mechanics; applied in §16.
  • Intel 64 and IA-32 Architectures Software Developer's Manual, Vol. 3 — Intel (2023), memory ordering and APIC chapters: interrupt-capability integration semantics; applied in §14 and §16.
  • AMD64 Architecture Programmer's Manual — AMD (2022), MMIO and ordering chapters: platform barrier behavior on the secondary target architecture; applied in §12 and §14.
  • Operating Systems: Three Easy Pieces — Arpaci-Dusseau & Arpaci-Dusseau (2018), concurrency and persistence chapters: lock-ordering and crash-consistency discipline; applied in §19 and §20.
  • Linux Device Drivers, 3rd ed. — Corbet, Rubini & Kroah-Hartman (2005), PCI subsystem chapters: production enumeration lessons and quirk-handling tradeoffs; applied in §15.
  • Systems Performance — Gregg (2020), observability and performance chapters: latency percentile methodology reused directly in §28; applied in §28.
  • Database Internals — Petrov (2019), WAL and invariant-checking chapters: append-only log design reused for the replay format; applied in §20.

Papers

  • "The Multikernel: A New OS Architecture for Scalable Multicore Systems" — Baumann et al., 2009, SOSP: models hardware topology as message-passing state rather than shared memory, informing TopologyGraph as an explicitly-versioned published artifact; applied in §18.
  • "seL4: Formal Verification of an OS Kernel" — Klein et al., 2009, SOSP: invariant-oriented kernel design methodology → the I1–I12 table and its one-assertion-per-invariant discipline; applied in §7.
  • "Dynamic Instrumentation of Production Systems" — Cantrill, Shapiro & Leventhal, 2004, USENIX ATC: always-on structured observability without recompilation → mandatory tracing posture (P2); applied in §24 and §28.
  • "The Design and Implementation of a Log-Structured File System" — Rosenblum & Ousterhout, 1991, SOSP: append-only sequential write with checksum-validated recovery → the replay log's storage model; applied in §20.
  • "K42: Building a Complete Operating System" — Appavoo et al., 2006, EuroSys: fine-grained lock scaling under high core counts → lock-ordering discipline for hotplug under contention; applied in §19 and §29.
  • "Exokernel: An Operating System Architecture for Application-Level Resource Management" — Engler, Kaashoek & O'Toole, 1995, SOSP: delegate raw resource control instead of abstracting it away → BAR/window allocation exposes raw intervals, not opaque handles; applied in §17.
  • "Introduction and Overview of the Multics System" — Corbato & Vyssotsky, 1965, AFIPS: ring-based hierarchical trust boundaries → treats firmware/device input as an untrusted outer ring relative to the enumerator; applied in §22.
  • "Mach: A New Kernel Foundation for UNIX Development" — Rashid et al., 1986, USENIX: driver isolation via user-level servers → the road-not-taken comparison for a userspace enumerator; applied in §34.

Reference Implementations

  • torvalds/linux — study drivers/pci/: mature enumeration, quirk handling, AER integration; pitfall: do not copy its decades of accumulated per-device quirk tables wholesale, start with a minimal quirk registry grown from real fixtures; applied in §15.
  • freebsd/freebsd-src — study sys/dev/pci/: architecture-portable enumeration; pitfall: do not copy its #ifdef-heavy platform branching, use the trait-based pcie-platform-abstraction boundary instead; applied in §12.
  • google/fuchsia — study zircon/kernel/dev/pci (bus driver): capability-parsing structure in a modern kernel; pitfall: do not copy its coarse-grained single bus lock, apply the I6 ordered multi-lock model instead; applied in §16.
  • qemu/qemu — study hw/pci/ and hw/i386/pc_q35.c: emulation semantics and the q35 chipset topology used as the CI oracle; pitfall: do not rely on emulator-only relaxed MMIO timing as a latency baseline for §4's real-hardware targets; applied in §26.
  • tianocore/edk2 — study MdeModulePkg/Bus/Pci: firmware-side enumeration ordering that runs before the OS ever sees the bus; pitfall: do not inherit its unbounded recursion depth, enforce the 16-level bound from §4; applied in §13.
  • redox-os/redox — study the pcid daemon: Rust ownership tradeoffs for a userspace PCI driver; pitfall: do not copy its single-threaded assumption, this stack must survive SMP transition; applied in §17.

RFCs / Specifications

  • PCI Express Base Specification (PCI-SIG) — defines TLP-adjacent config-space layout, the capability linked-list format, and the BAR write-all-1s sizing algorithm; applied in §14 and §16.
  • ACPI Specification (UEFI Forum), MCFG table definition — defines the MCFG table format used to derive ECAM windows per PCI segment group; applied in §13.
  • PCI Firmware Specification (PCI-SIG) — defines OS/firmware handoff semantics (_OSC negotiation) relevant to who owns config space at boot; applied in §13.
  • PCI-to-PCI Bridge Architecture Specification (PCI-SIG) — defines bridge secondary/subordinate bus-number rules and MMIO/IO window forwarding; applied in §15 and §17.
  • UEFI Specification — defines the boot-services window during which firmware and the early enumerator can both hold config-space access; applied in §12.

Glossary (§36) · 41 terms · site-wide glossary

ECAM
Enhanced Configuration Access Mechanism; MMIO-based access to PCIe configuration space.
BAR
Base Address Register; a device config register describing an MMIO or IO address window.
MCFG
the ACPI table describing per-segment ECAM base addresses and bus ranges.
Root Complex
the CPU-to-PCIe bridge; the topology's root node(s).
Endpoint
a terminal PCIe device with no downstream ports.
MSI
Message Signaled Interrupt; interrupt delivery via a memory write rather than a pin.
MSI-X
an extended MSI mechanism supporting a per-vector table of address/data pairs.
AER
Advanced Error Reporting; a PCIe extended capability for link/protocol error reporting.
MMIO
memory-mapped IO; device registers addressed within the CPU's physical address space.
Segment
a PCI domain; a group of buses sharing one ECAM base address.
Topology Snapshot
an immutable, generation-versioned image of the device graph.
Replay Artifact
a deterministic, checksum-validated capture of enumeration events.
Bridge Window
the MMIO/IO aperture a bridge forwards to its downstream (secondary) bus.
Hotplug
runtime insertion or removal of a device without a reboot.
Capability Chain
a linked list of capability structures within configuration space.
Function
a PCI logical sub-device; up to 8 per device, addressed by the function field.
Device ID
a vendor-defined 16-bit identifier for a specific product.
Vendor ID
a PCI-SIG-assigned 16-bit identifier for a device manufacturer.
Bus Number
an 8-bit routing identifier within a segment's hierarchy.
Prefetchable BAR
an MMIO region safe for read-caching/speculation by the CPU.
Header Type
the config-space field distinguishing endpoint (0), bridge (1), CardBus (2, unsupported).
Subordinate Bus
the highest bus number reachable downstream of a given bridge.
Secondary Bus
the bus number a bridge assigns to its immediately downstream segment.
DeviceAddress
the canonical (segment, bus, device, function) tuple identifying a function.
DeviceId
a stable, epoch-scoped topology identifier surviving rescans (I4).
Generation
a monotonically increasing counter identifying one published topology version.
Quarantine
marking a device Failed and excluding it from further access without aborting the scan.
Debounce
collapsing a rapid sequence of hotplug events into one net event.
Interval Allocator
the data structure enforcing non-overlapping BAR/window assignment (I3).
Fail-Closed
rejecting untrusted or ambiguous input rather than proceeding optimistically (P7).
Crash-Only
a design discipline where restart, not graceful shutdown, is the only recovery path (P3).
Backpressure
a producer slowing or dropping output in response to a bounded consumer (P9).
Lock Order
the fixed acquisition sequence (I6) preventing deadlock across subsystems.
Differential Testing
comparing this stack's output against an independent reference implementation.
Soak Test
a long-duration (72h) stress test surfacing rare, load-dependent failures.
SBOM
Software Bill of Materials; a manifest of all dependencies in a released artifact.
TLP
Transaction Layer Packet; the PCIe protocol-layer unit this stack does not itself implement.
ASPM
Active State Power Management; a link power-saving feature explicitly out of Phase 0 scope.
CXL
Compute Express Link; a PCIe-electrical protocol for memory/accelerator coherency, deferred (§13).
RSDP
Root System Description Pointer; the ACPI entry point located at boot.
XSDT
Extended System Description Table; the ACPI table-of-tables walked to find MCFG.
