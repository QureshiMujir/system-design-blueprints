Pitfalls
# Failure mode Root cause Debug
1 -0.0f64 and 0.0f64 encode identically both have bits 0x0000… and 0x8000… after IEEE; must produce distinct bytes verify: -0.0f64.to_bits() = 0x8000000000000000; after flip-all-bits = 0x7FFF… vs 0.0 → 0x8000… — they ARE distinct; test explicitly
2 "foo\0bar" embedded null collides with terminator UTF-8 strings cannot contain 0x00, but &[u8] can document: KeyEnc for &[u8] requires no embedded nulls; callers with binary blobs must escape (not in scope)
3 Composite key components not length-delimited encode([&"a", &"bc"]) == encode([&"ab", &"c"]) if both omit terminators the 0x00 string terminator prevents this for strings; integers have fixed width — no collision possible
4 i64 sign-bit flip applied after to_be_bytes() must XOR the integer value, not the byte slice always XOR the integer, THEN call to_be_bytes()
5 f32 using u64 bit width copy-paste error from f64 impl f32 uses to_bits() -> u32; the transform operates on u32
6 NaN encoded differently across platforms f64::NAN bit pattern is not uniquely specified document policy; use f64::NAN.to_bits() which is 0x7FF8000000000000 on all Rust targets; quiet NaN sorts last
