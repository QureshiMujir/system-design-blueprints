Mental Models & First Principles

  • MM1 — Hydration is adoption, not creation. The server already built the DOM; the client only attaches behavior to nodes it did not create. Predicts: any createElement/innerHTML= on an island root is a bug, not an optimization. Without it: "re-render to be safe" → flash, lost focus/scroll, doubled paint, DomMismatch masked not surfaced. Applied: §6.2, §8.7, Phase 7 (## 19).
  • MM2 — Props are data; chunks are code; the two never cross the seam. decode(PropBlob)→PropValue is a total parser yielding inert values; the only executable bytes arrive as integrity-checked chunks. Predicts: a malicious prop is at worst wrong data in one island, never code execution. Without it: eval/JSON-with-functions → RCE. Applied: §8.3, Threat Model T1/T2/T9, Phase 3 (## 15).
  • MM3 — One type definition, two compile targets, drift impossible. Encoder (std) and decoder (wasm) agree by sharing one PropValue/PropBlob type, not by testing. Predicts: SSR/client prop mismatch is a compile error, not a runtime surprise; divergence can only come from nondeterministic render, never the wire. Without it (two hand-kept schemas): silent prop corruption fuzzing barely catches. Applied: §6.1, ADR-04, INV-3/INV-4, Phase 1/3 (## 13/## 15).
  • MM4 — JS executed is a function of triggered islands, not page bytes. Cost = Σ over islands whose strategy fired, each paying decode+adopt+mount. Predicts: a 100 KB article with one client:load button costs one chunk; islanding the layout wrapper silently reintroduces whole-page hydration. Without it: every interactive bit becomes client:load and TTI collapses to a monolith's. Applied: §2.2, §6.3/§6.4, INV-5, Scalability Analysis.
  • MM5 — The main thread is the one true scheduler; the network is concurrent, the CPU is not. Chunk fetches overlap; decode/adopt/mount are serial main-thread work. Predicts: a blocking sweep janks input even with every chunk cached; the win is yielding between islands + deferring untriggered ones, not parallelism. Without it: a tight for island { hydrate() } ships 200 ms long tasks. Applied: §6.7, INV-11, Phase 8 (## 20).
  • MM6 — A deferred island still owes the user their first interaction. "Hydrate later" must not "drop the click that happened before hydration": a capture-phase listener records the event, hydrates, then replays it into the adopted tree. Predicts: Interaction needs a pre-hydration listener + replay + INV-2 idempotence against double-apply. Without it: the first click is silently lost — a defect that throws no error. Applied: §6.10, INV-10, ADR-16, Phase 11 (## 23).
  • MM7 — TTFB belongs to the shell; data latency belongs to the island. Streaming decouples them: flush head+bootstrap immediately, placeholder each async-data island, late-insert+swap on resolve. Predicts: one slow source delays only its own swap, never first paint; buffering the page ties TTFB to max(data_latency). Without it: in-order streaming gates the first byte on the slowest island. Applied: §6.12, §8.6, ADR-13, Phase 10 (## 22).
  • MM8 — A shared dependency is one node with two parents, not two copies. A module's chunk home = its set of reaching island roots, so a module used by ≥2 islands hoists to one shared chunk loaded once. Predicts: dedup keys on the reaching-set, not a single owner; a cycle in the chunk DAG has no safe load order → CycleInChunkGraph. Without it: key-by-"first owner" duplicates 3-way deps, or ships a load deadlock. Applied: §8.5, INV-6/INV-7, ADR-11, Phase 5 (## 17).
  • MM9 — Determinism is the precondition for adoption; effects are the leak. Adoption works only if the client's pre-effect render equals the SSR DOM byte-for-structure; SSR thus runs effects in no-op mode and never touches wall-clock/RNG/window. Predicts: any Date.now()/Math.random()/locale branch in render seeds a DomMismatch cascade; the cure is serialize-the-value-as-a-prop. Without it: SSR≠client intermittently → "works on my machine" hydration bugs. Applied: §6.6, INV-1/INV-8, Failure F1/F9.
  • MM10 — Isolation turns "a broken island" into "a non-interactive island." Each island hydrates in its own error boundary + Scope; the static SSR HTML is the recovery floor. Predicts: containment wraps decode+mount (incl. catch_unwind across the wasm task); the worst case is "static, not blank." Without it: one island's panic aborts boot and every island below stays dead. Applied: §6.5, INV-9, ADR-15, Phase 9 (## 21).

Glossary · 52 terms · site-wide glossary

island
An interactive component subtree marked with a client: directive; its own IslandId, chunk, HydrationStrategy, serialized props, IslandMarker. Everything outside any island is static HTML shipped with ZERO JS.
islands architecture
Page-construction model: mostly-static SSR HTML + a sparse set of independently-hydrating islands. Total JS executed scales with island count, not page size. Refs: Astro, patterns.dev (Jason Miller).
partial / incremental / progressive hydration
Hydrating islands selectively and over time rather than the whole page at once. "Partial" = subset of DOM; "incremental/progressive" = staggered per strategy/priority. Our model is all three.
hydration
Attaching listeners + reactive bindings to existing SSR DOM so it becomes interactive. In this system hydration = ADOPTION (see DOM adoption), never re-render.
resumability** (contrast)
Qwik's alternative: serialize execution state so the client resumes with near-zero upfront JS, no hydration walk. We do NOT implement it; we hydrate. Cited for contrast only.
SSR
Server-Side Rendering: isle-ssr renders a Component tree to HTML (render_to_string / render_streaming) per request, with effects in no-op mode.
CSR
Client-Side Rendering: browser builds DOM from scratch. Only HydrationStrategy::Only islands are pure CSR; the rest are SSR-then-hydrated.
hydration strategy
HydrationStrategy enum deciding WHEN/WHETHER an island hydrates: Load, Idle, Visible{root_margin}, Media{query}, Interaction{events}, Only, Never. Travels in the marker as data-strategy.
client: directive
Author-facing annotation (e.g. client:load) on a component that (a) marks a Module as is_island_root at build, (b) maps to a HydrationStrategy. Bad/unknown directive → BuildError::BadDirective.
client:load
Load: hydrate immediately on runtime boot. Highest priority; for above-the-fold interactivity.
client:idle
Idle: hydrate via requestIdleCallback (with setTimeout fallback). Deferred, non-blocking.
client:visible
Visible{root_margin}: hydrate when the island intersects the viewport via IntersectionObserver(root_margin).
client:media
Media{query}: hydrate when matchMedia(query) matches (e.g. desktop-only widgets).
client:interaction
Interaction{events}: pre-hydration listener for named events; on first event, hydrate THEN replay that event into the island.
client:only
Only: no SSR HTML emitted; client renders from scratch (CSR). No DOM adoption, no mismatch possible.
island marker / boundary
IslandMarker: DOM boundary (<isle-island> custom element OR comment pair) carrying data-isle-id, data-strategy, data-chunk, data-props, data-adapter. The sole SSR→client handoff per island.
props serialization
Converting an island's props to/from a transport form across the SSR→client boundary via isle-serialize: SSR encode → decode client. Same crate both sides ⇒ no type drift.
structured clone
The HTML structured-clone value model that PropValue mirrors: primitives, arrays, objects, bytes, Date, plus shared/cyclic Ref. Bounds what may be a prop.
PropValue
isle-serialize enum: Null/Bool/Int/Float/Str/Bytes/Array/Object/Ref/Date. The decoded, structured prop value mounted into an island.
PropBlob
{ version: u16, bytes: Vec<u8> }: the compact versioned wire form of encoded props embedded in data-props. Version mismatch → HydrateError::PropDecodeFailed.
chunk
Chunk { id: ChunkRef, modules, deps }: a separately loadable JS/WASM unit. Each island root's dependency closure → one chunk; shared modules → a shared chunk.
chunk graph
ChunkGraph { modules, chunks }: build-time DAG mapping modules→chunks and chunk→chunk deps. A cycle → BuildError::CycleInChunkGraph.
module graph
Vec<Module> where Module { id, deps, is_island_root }: the import graph from which the chunk graph is computed by build_graph.
Manifest
Manifest { islands: Map<IslandId,IslandEntry>, chunks: Map<ChunkRef,ChunkEntry> }: build output consumed by SSR + runtime boot. Maps island → chunk(+deps), strategy, prop schema, integrity.
integrity hash
IntegrityRef-style content hash (ChunkEntry.integrity, IslandEntry.integrity) for subresource-integrity verification of a lazily imported chunk.
lazy / dynamic import
Runtime-time import() of an island's chunk, triggered only when its strategy fires. In-flight loads are deduped; failure → HydrateError::ChunkLoadFailed (retry/fallback).
code splitting
Partitioning the module graph into per-island chunks so the client downloads only the islands it needs. The core build deliverable of isle-graph.
tree shaking
Eliminating modules unreachable from any island root before chunk assignment. Reachability is the dependency-closure walk; dead modules are dropped.
dependency closure
Transitive set of modules reachable from one island root; becomes (minus shared/hoisted modules) that island's chunk.
shared-chunk dedup
Hoisting any module in ≥2 islands' closures into a separate shared chunk listed in ChunkEntry.deps, so it loads once and is cached.
DOM adoption
Hydration mechanism: walk the island's template/vdom against the EXISTING SSR DOM, attaching listeners + bindings WITHOUT replacing nodes. The defining "hydrate not re-render" invariant.
reconciliation
The diff/match step inside adoption (and later updates) aligning expected vdom to actual DOM nodes. During hydration it must find a match for every node or raise DomMismatch.
hydration mismatch / DomMismatch
HydrateError::DomMismatch: SSR markup ≠ client expectation during adoption. Gravest correctness bug; dev = warn + client-render fallback, prod = log + contain (island isolated).
fine-grained reactivity
isle-signal model where updates propagate per dependency (signal→effect/memo) rather than re-rendering a component tree. Minimizes post-hydration work.
Signal
Signal<T>: readable/writable reactive cell tracking its dependents; set schedules dependent effects/memos.
Effect
Effect: side-effecting reaction re-run on dependency change. No-op in SSR mode; runs only client-side after hydration.
Memo
Memo<T>: cached derived value recomputed only when its tracked deps change.
Scope
Scope: arena owning an island's reactive nodes (signals/effects/memos); dropped to dispose. One per hydrated island, held by its IslandHandle.
Store
Store: cross-island shared, keyed signals — the bus letting separately-hydrated islands share/observe state.
HydrationScheduler
isle-runtime priority queue + per-strategy trigger registration deciding hydration order and firing Load/Idle/Visible/Media/Interaction triggers.
requestIdleCallback
Browser API backing Idle; hydrate during idle time, setTimeout fallback where unsupported.
IntersectionObserver
Browser API backing Visible{root_margin}; fires hydration when the island scrolls into the margin-expanded viewport.
matchMedia
Browser API backing Media{query}; hydrate when the media query matches (and may defer until then).
event delegation / replay
Interaction mechanism: one lightweight pre-hydration listener for named events; first event triggers hydration, then is REPLAYED into the now-live island so no interaction is lost.
error isolation / error boundary
Each island hydrates inside its own boundary + Scope; a chunk-load fail, prop-decode fail, or mount panic is caught, logged, and confined — other islands and the static page survive.
streaming SSR
render_streaming writing HTML incrementally through an HtmlSink (push/flush) so the browser receives + paints the shell before the full tree is rendered. Improves TTFB.
out-of-order streaming
Emit a placeholder for an async-data island immediately, flush head + bootstrap early, then stream the island's HTML + a swap marker once data resolves. Backpressure via HtmlSink.
placeholder
The temporary shell node emitted for a not-yet-resolved out-of-order island, later replaced by a late-inserted real island fragment + swap script.
time-to-interactive (TTI)
Primary perf target: time until islands are hydrated and responsive. Islands minimize it by shipping/executing JS only per fired strategy. Tracked in Phase 13 benchmarks.
Adapter
Adapter trait (id, mount(el, comp, props) -> IslandHandle) abstracting the UI framework; the bundled reference adapter drives isle-signal. Unknown id → HydrateError::AdapterMissing / BuildError::UnknownAdapter.
IslandHandle
IslandHandle: owns a hydrated island's Scope + listeners; dropping it disposes the island (unmount). Returned by hydrate/Adapter::mount.
runtime bootstrap shim
The tiny (<2 KB) JS loader inlined by SSR that calls boot(manifest), loads the wasm isle-runtime, and hands off marker scanning + scheduling.
