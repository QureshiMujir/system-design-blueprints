⬜ Phase 1 — Component model and minimal reactivity (isle-signal) §13

Objectives
  • Build isle-signal (module reactive): Scope, Signal<T>, Memo<T>, Effect, cross-island Store; no_std + alloc → compiles to server (std) AND wasm32. Fine-grained tracking: read = subscribe, write = notify dependents only (no vdom diff), cost ∝ dependency-edge count not tree size. Dual-mode: Mode::Ssr (effects no-op, single initial render, no scheduling) vs Mode::Client (effects run, re-run on dep change) — same types both sides. Lock the Component::render(&self, ctx: &mut RenderCtx) -> Html contract against a Scope borrowed from RenderCtx (Phase 2 consumes it).
  • Constraints: no global mutable static (wasm single-thread + server reuse); Scope arena-owns nodes, drop = dispose; no leaking Rc<RefCell> cycles; determinism — SSR effect no-op MUST equal client first-run DOM.
Deliverable

cargo build -p isle-signal --target wasm32-unknown-unknown AND host cargo test -p isle-signal both green. A reactivity core where Signal::set re-runs only dependent Effect/Memo; Mode::Ssr proves effects never fire; Component::render contract compiles against a Scope. Measurable: dep-edge count, effect-run count per write.

  • Stale subscriptions (effect re-run must clear prior deps before re-tracking, else dead edges fire forever): Scope::stats().edges monotonic-growing ⇒ leak. Box<dyn Any> downcast panic (type-confused Store key reuse, differing T): signal::<T> checks TypeId on existing key (dev panic). ⬜ Phase 3 — Island detection and props serialization (isle-serialize) §15

Objectives
  • Define the client: directive model on the Component tree (mark interactive subtrees Module::is_island_root; unmarked = static HTML, zero JS). Build isle-serialize (no_std + alloc): PropValue value model (structured-clone superset), versioned compact PropBlob wire format, encode (SSR)/decode (client). Prove SSR-encode → client-decode round-trip on the SAME shared crate → props can't drift (kills the #1 islands bug by construction).
  • Scope: value model + wire codec only (NOT marker embedding Phase 4, chunk graph Phase 5, adoption Phase 7). Constraints: deterministic byte-identical encode for equal PropValue; bounded recursion (no stack overflow on adversarial nesting); decode treats bytes as UNTRUSTED.
Deliverable
  • isle-serialize compiles std AND wasm32 (no_std+alloc); detect_island_roots returns the correct IslandId set for a mixed client:*+static fixture tree; structured-clone serializer passes round-trip + cycle + version-skew tests, encode/decode inverse on all non-NaN Float values.
Acceptance
  • Round-trip ∀ generated PropValue v (10k proptest, NaN by bit-pattern) decode(encode(v))==v, 0 failures; encode(v).bytes byte-identical across 1000 repeats + std-vs-wasm; a 3-node cycle encodes in ≤ N+refs tags, decodes with Ref resolving to the original node (pointer-identity preserved).

⬜ Phase 4 — Island boundary emission §16

Two syntaxes: <isle-island> custom element (default; valid HTML, no display side effects) + a comment-pair fallback for void/table/<select> contexts. A markers inspector dumps (IslandId, strategy, chunk, props_bytes) per island.

⬜ Phase 5 — Build-time chunk graph (isle-graph) §17

Objectives
  • isle-graph (std): Module/ModuleId, ChunkGraph/Chunk, ChunkRef; island-root detection from client: directives; dep-closure → chunk assignment; shared-dep dedup (module in ≥2 islands → shared chunk); CycleInChunkGraph detection; emit_manifest (island → chunk+deps+strategy+prop_schema+integrity). Scope: graph topology + Manifest emission ONLY — transpile/minify behind Transpiler (default PhaseDeferred), ChunkEntry.url/bytes placeholders until Phase 12.
  • Constraints: deterministic output (stable ChunkRef/ModuleId ordering); Manifest = the contract isle-ssr (Phase 4) + isle-runtime (Phase 6) consume, schema frozen here; no JS shipped (build-time). Invariant: every island root → exactly one own chunk; shared modules never duplicated; chunk DAG acyclic.
Deliverable

build_graph(entries) → ChunkGraph + emit_manifest(g) → Manifest for a multi-island app. Runnable via isle build --graph-only (prints ChunkGraph + Manifest JSON). Interop: Manifest.islands[id] keys match Phase 4 IslandMarker.data-chunk; consumed by Phase 6 boot(manifest). Measurable: chunk count, shared-chunk count, per-chunk module count.

Acceptance
  • 3-island app, 2 sharing util → exactly 3 own + 1 shared chunk, util in one chunk only (dedup). Cyclic input (A→B→A) → Err(CycleInChunkGraph), never panics/loops. Determinism: 100 runs → byte-identical Manifest JSON (golden hash).
  • Every IslandEntry has non-empty chunk, valid prop_schema: SchemaId, 64-hex integrity. build_graph for 1k modules / 50 islands < 50 ms (host), allocations O(V+E).

⬜ Phase 6 — Client runtime bootstrap (isle-runtime) §18

Objectives
  • isle-runtime (wasm32) boot path: JS shim → wasm boot(manifest) → marker scan → in-memory island registry → log a hydration plan. No hydration/chunk-loading/adoption (Phases 7–9). Scope: discovery + registration only — parse every <isle-island> in the live DOM, cross-reference Manifest, build a registry keyed by IslandId.
  • Constraints: shim JS < 2 KB min+gz; isle-runtime wasm (boot+scan) < 18 KB gz; boot() idempotent (double-call no-ops); all web-sys DOM access in one dom boundary module so the shared crates stay no_std; scan must NOT mutate the DOM (read-only).
Deliverable

A wasm isle-runtime that, loaded by shim.js on an SSR page, boots, scans all <isle-island> markers, builds the IslandRegistry against the Manifest, logs a HydrationPlan, and exposes __isle.stats(). Compiles wasm32-unknown-unknown; the marker-scan test passes in a headless browser (wasm-pack/Chrome).

Acceptance

Phase 6 supplies scan+registry+web-sys boundary; this phase consumes one resolved marker. Constraint: adoption walk allocates O(1)/node beyond the handle, no full vdom-diff buffer.
Deliverable

Compiles wasm32-unknown-unknown, runs under wasm-pack test --headless. Measurable: per-island hydration latency, listener count, allocation bytes, mismatch counter.

⬜ Phase 9 — Lazy chunk loading and error isolation §21

Objectives
  • Every strategy trigger drives a lazy/dynamic import of the island's chunk (total JS executed ∝ hydrated islands, not page size); dedup — a chunk shared by ≥2 islands loads once, concurrent triggers share one in-flight promise.
