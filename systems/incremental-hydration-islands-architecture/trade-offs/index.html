Decisions (§9) · 26 ADRs

ADR-01

Implementation language

Chosen

Rust, edition 2021, MSRV 1.78

Rejected

TypeScript end-to-end (no alloc control, no shared typed core across SSR/client, weak exhaustiveness); Go (weak sum types, weak fine-grained-DOM WASM); C/C++ (memory-unsafe decode of untrusted SSR props)

When the rejected choice is right

TS wins when the team is JS-native and shipping a meta-framework (Astro/Next): one language, npm ecosystem, no wasm toolchain, hot author iteration outweighs a typed SSR↔client seam.

Why: Sum types model HydrationStrategy/PropValue/chunk graph exactly; exhaustiveness + ownership make SSR/client prop+markup mismatch a compile/decode error, not a runtime surprise.

ADR-02

Client runtime target

Chosen

wasm32-unknown-unknown via wasm-bindgen + web-sys

Rejected

Hand-written JS runtime; asm.js; Emscripten

When the rejected choice is right

A hand-written JS runtime wins below the ~20 KB wasm-instantiate floor — a tiny site where the wasm module + bindgen glue costs more than the JS it replaces (Preact-class footprint).

Why: Sandboxed, controllable runtime; lets the SAME isle-core/isle-serialize/isle-signal crates compile to client; Rust→WASM islands pattern is real + citable (Leptos/Sycamore/Dioxus).

ADR-03

Workspace shape

Chosen

Cargo workspace, 7 members isle-core/serialize/signal/graph/ssr/runtime/cli

Rejected

One monolithic crate; per-side mega-crates (build vs client)

When the rejected choice is right

A single crate wins for a prototype/spike where compile-graph simplicity beats boundary enforcement, and no one yet ships the wasm target separately.

Why: Crate boundary = trust + target boundary (no_std core vs std host vs wasm client); enforces that build/SSR/client share types only through isle-core.

ADR-04

Shared typed core across server + wasm

Chosen

isle-core + isle-serialize + isle-signal are no_std + alloc; compile for BOTH std server and wasm32

Rejected

std-only core duplicated per side; JSON schema as the only contract

When the rejected choice is right

A JSON-schema contract wins when SSR and client are different languages (e.g. a Go server + JS client) — no shared type is possible, so a versioned schema + codegen is the only seam.

Why: A single typed core eliminates the #1 islands bug class — SSR/client prop+markup drift — by construction: encode and decode share one PropValue/PropBlob definition.

ADR-05

UI-framework coupling

Chosen

Adapter trait + bundled minimal isle-signal reference framework

Rejected

Bundle React/Vue/Svelte; hard-wire one framework

When the rejected choice is right

Hard-wiring one framework wins for a product team standardized on React — the adapter indirection is dead weight, and React's island libs (preact/compat) already exist.

Why: NON-GOAL = ship a full framework; Adapter::mount lets any framework plug in while the reference signals runtime keeps the demo path and tests self-contained.

ADR-06

Hydration timing model

Chosen

HydrationStrategy enum: Load/Idle/Visible{root_margin}/Media{query}/Interaction{events}/Only/Never

Rejected

Hydrate-everything-on-load; string config; per-island bespoke callbacks

When the rejected choice is right

Per-island bespoke callbacks win when authors need a trigger the enum lacks (e.g. "hydrate after analytics consent"); a closed enum cannot express open-ended scheduling policy.

Why: Closed enum maps 1:1 to a browser trigger (boot / rIC / IO / matchMedia / replay / CSR / static); exhaustive match guarantees every strategy has a scheduler arm.

ADR-07

Island boundary DOM encoding

Chosen

<isle-island> custom element carrying data-isle-id/strategy/chunk/props/adapter

Rejected

Comment-pair markers only; data on a generic <div>

When the rejected choice is right

Comment-pair-only wins when markup must survive contexts that forbid custom elements wholesale (legacy table/select-heavy pages, strict sanitizers that strip unknown elements).

Why: Custom element is a stable, queryable, non-paint-affecting host (Astro astro-island precedent); IslandMarker may fall back to a comment pair where a custom element is illegal (e.g. inside <table>).

ADR-08

Prop value model

Chosen

PropValue structured-clone-like enum (incl. Bytes, Date, Ref for shared/cyclic)

Rejected

JSON-only props; serde_json::Value

When the rejected choice is right

JSON-only wins when props are guaranteed flat, acyclic, and JSON-native (config blobs); then serde_json is simpler, human-readable in DevTools, and skips a bespoke codec.

Why: Structured clone is the web's real prop semantics; Ref preserves shared/cyclic graphs JSON drops; typed variants avoid lossy number/Date coercion across the boundary.

ADR-09

Wire format

Chosen

Compact versioned binary PropBlob{version:u16, bytes}

Rejected

JSON text in data-props; bincode without a version field

When the rejected choice is right

JSON text wins for debuggability-first builds and props small enough that gzip erases the size gap — operators can read data-props directly without an inspect decoder.

Why: Smaller bytes-on-marker (lower TTFB/HTML weight); explicit version:u16 lets decode reject/upgrade old blobs; binary side-steps HTML-attribute escaping of JSON.

ADR-10

Client reactivity model

Chosen

Fine-grained reactivity Signal/Effect/Memo/Scope (isle-signal)

Rejected

VDOM diff/reconciliation; dirty-checking

When the rejected choice is right

VDOM wins when the target framework is already VDOM-based (React/Preact) and authors expect its mental model + ecosystem; reconciliation also tolerates looser SSR/client markup.

Why: DOM ADOPTION needs surgical listener+binding attach, not tree re-diff; fine-grained updates touch only changed nodes → less JS executed, the islands win metric.

ADR-11

Build-time code splitting

Chosen

Chunk graph: each island root's dep-closure → one Chunk; module shared by ≥2 islands hoisted to a shared chunk (dedup)

Rejected

One bundle per page; one chunk per module; manual chunk config

When the rejected choice is right

One bundle wins for a tiny app (1–2 islands) where HTTP request overhead and waterfall depth dominate over the bytes saved by splitting; manual chunks win when an operator knows the access pattern better than the closure heuristic.

Why: JS executed scales with interactive islands, not page size; shared-chunk dedup means a common dep loads once; cycle in chunk graph = BuildError::CycleInChunkGraph.

ADR-12

Transpile / minify

Chosen

Transpiler trait, default = PhaseDeferred (own the module/chunk GRAPH + Manifest, not the minifier)

Rejected

Build-in JS minifier/transpiler; vendor swc/terser as a hard dep

When the rejected choice is right

Vendoring swc/terser wins for a turnkey product that must minify out-of-the-box; the deferral only pays off when a host already owns its JS toolchain.

Why: NON-GOAL = a production minifier; trait keeps the graph/Manifest logic testable and lets a real transpiler be injected without coupling the core to a JS toolchain.

ADR-13

SSR output + streaming

Chosen

HtmlSink trait + render_streaming with out-of-order (placeholder → late insert), early head/bootstrap flush

Rejected

String-only render_to_string; in-order streaming only

When the rejected choice is right

String-only wins for fully static pages (no async data) or SSG, where there is nothing to stream and buffering the whole page is simpler and equally fast.

Why: Early-flush shell + bootstrap improves TTFB; out-of-order lets async-data islands emit a placeholder, flush, then swap on resolve; render_to_string retained for static/test paths.

ADR-14

Hydration semantics

Chosen

DOM adoption (walk template/vdom vs existing SSR nodes, attach without replacing)

Rejected

Re-render then replace; full client re-mount

When the rejected choice is right

Re-render-then-replace wins for client:only islands (no SSR DOM to adopt) and as the fallback when adoption hits DomMismatch — correctness over byte-thrift.

Why: Re-render wastes the SSR HTML and flashes; adoption preserves nodes + scroll/focus; a markup mismatch is the gravest bug → HydrateError::DomMismatch.

ADR-15

Failure containment

Chosen

Per-island error boundary + Scope; one island's chunk-load/decode/mount failure is caught + confined

Rejected

Page-global try/catch; let one failure abort hydration

When the rejected choice is right

A page-global handler wins for a single-island app (a calculator widget) where there is nothing to isolate from — per-island bookkeeping is pure overhead.

Why: Islands are independent units; isolation keeps the static page + sibling islands interactive when one island fails (logged in prod, warn+CSR-fallback in dev).

ADR-16

Pre-hydration interaction

Chosen

Interaction{events} attaches a lightweight listener, then on first event HYDRATE + REPLAY the event (event delegation/replay model, per project 261)

Rejected

Hydrate-on-load to "feel" interactive; drop the first event

When the rejected choice is right

Hydrate-on-load wins for an above-the-fold CTA where the first interaction is near-certain and must be instant — the deferred-then-replay latency is a worse UX than paying boot cost upfront.

Why: Zero JS until the user actually interacts; replaying the captured event makes the first click/keypress feel native, matching Qwik/Astro interaction semantics.

ADR-17

Client bootstrap shim

Chosen

Tiny (< 2 KB) JS loader shim → boot(manifest) → wasm entry

Rejected

Pure-JS runtime; large JS bootstrap

When the rejected choice is right

A pure-JS runtime wins when wasm is unavailable (locked-down WebViews, no-wasm CSP) — the shim's wasm dependency is fatal there, so a JS fallback runtime is the only path.

Why: The shim only fetches+instantiates wasm and calls boot; keeping it < 2 KB protects the islands promise of minimal JS shipped before any island hydrates.

ADR-18

Browser bindings

Chosen

wasm-bindgen + web-sys for DOM/IO (querySelector, IntersectionObserver, matchMedia, requestIdleCallback)

Rejected

Raw JS interop strings; stdweb

When the rejected choice is right

Raw JS interop wins when shaving the last KB of bindgen-generated glue matters more than type safety, or to call an API web-sys has not yet bound.

Why: web-sys gives typed, audited bindings for exactly the trigger APIs the HydrationScheduler needs; avoids ad-hoc unsafe JS glue.

ADR-19

Chunk integrity

Chosen

Subresource Integrity (SRI) hash per ChunkEntry.integrity + IslandEntry.integrity in the Manifest

Rejected

No integrity; trust URL only

When the rejected choice is right

Trusting the URL wins on a first-party same-origin deploy with no CDN, where the integrity compute + manifest bloat buy nothing because the transport is already trusted.

Why: Lazily imported chunks are executed code; SRI lets the loader verify a chunk's bytes match the build, blocking tampered/stale CDN payloads.

ADR-20

Dev server + reload

Chosen

isle-cli serve with HMR-lite (reload affected island/chunk, re-emit Manifest)

Rejected

No dev server; full-page reload only; full HMR with state preservation

When the rejected choice is right

Full state-preserving HMR wins for a large app where losing form/route state on every edit destroys iteration speed — worth owning a stateful HMR runtime there.

Why: serve+build+inspect+trace cover the dev loop; HMR-lite (reload changed chunk) is enough to iterate without owning a full stateful HMR runtime.

ADR-21

Error surface

Chosen

Result<_, BuildError> (build) and Result<_, HydrateError> (client); panic only for invariant bugs

Rejected

Panic-based control flow; stringly-typed errors

When the rejected choice is right

Panic-based control flow wins in a throwaway script/bench where unwinding to a top-level handler is fine and exhaustive typed errors are ceremony.

Why: Typed enums (CycleInChunkGraph, DomMismatch, ChunkLoadFailed, …) make every failure mode explicit + matchable; panics reserved for true impossibilities.

ADR-22

Fuzzing

Chosen

cargo-fuzz targets on isle-serialize::decode and the IslandMarker parser

Rejected

Hand-written adversarial cases only

When the rejected choice is right

Hand-written cases win pre-MVP, before the wire format stabilizes — a fuzzer against a churning grammar mostly finds bugs in code you're about to rewrite.

Why: decode consumes untrusted SSR/network bytes; fuzzing the round-trip + marker parse guards against PropDecodeFailed/MarkerMalformed on malformed/hostile input.

ADR-23

Differential oracle

Chosen

Compare emitted HTML + marker/Manifest shape against Astro output (islands + client:* directives, astro-island)

Rejected

No external oracle; self-consistency only

When the rejected choice is right

Self-consistency wins once the format intentionally diverges from Astro (custom strategies/markers) — pinning to an external oracle then generates noise, not signal.

Why: An independent, well-known reference catches structural divergence in marker/strategy/chunk emission that a self-test would miss.

ADR-24

Benchmarks

Chosen

Track TTI, JS KB shipped (pre/post first hydration), TTFB (streaming), hydration latency, SSR throughput

Rejected

Wall-clock anecdotes; micro-bench only

When the rejected choice is right

Micro-bench-only wins when isolating a single hot path's regression (e.g. decode ns/op) where end-to-end TTI noise would drown the signal.

Why: The islands thesis is quantitative ("minimum JS at the right time"); these metrics are the acceptance bar for the architecture, asserted in Phase 13 (## 25).

ADR-25

CI

Chosen

GitHub Actions: build all crates (std + wasm32), cargo test, clippy, fmt, fuzz smoke, bench-regression gate, MSRV 1.78 check

Rejected

No CI; local-only gating

When the rejected choice is right

Local-only gating wins for a solo author on a private spike where CI setup cost exceeds the value before the first external contributor.

Why: Cross-target build matrix is essential because the no_std core MUST compile for server AND wasm; CI enforces the shared-core invariant continuously.

ADR-26

Dependency policy + license

Chosen

Lean deps (wasm-bindgen, web-sys, hashing/SRI, fuzz tooling only); dual-license MIT OR Apache-2.0

Rejected

Heavy transitive trees; GPL/copyleft; single-license

When the rejected choice is right

GPL/copyleft wins for a project that wants share-alike enforcement (a reference impl meant to keep forks open); heavy deps win when a vetted batteries-included framework beats hand-rolling.

Why: Minimal surface keeps the < 2 KB shim + small wasm achievable and audit-friendly; MIT OR Apache-2.0 matches the Rust ecosystem default for frictionless reuse.

Alternative Architectures (Roads Not Taken)

Three fundamentally different approaches to the same problem — not parameter tweaks. Each: sketch, winning regime, real system, why rejected here.

ALT-1 — Resumability (no hydration, serialize execution state).

  BUILD/SSR                          CLIENT
  render + serialize listeners,      tiny global loader (no per-island
  closures, reactive graph into  →   hydration walk); on first event,
  HTML attributes (qwik/json)        deserialize ONLY the needed state
                                     + handler, run it, "resume"
  no client hydration step           JS executed ∝ interactions, not islands

Regime: very large, mostly-idle apps where even per-island hydration (decode+adopt+mount over every visible island) is too much upfront CPU — resumability defers to the individual listener, paying nothing until interaction. Real system: Qwik (resumability; Hevery et al.). Rejected: heavier, more invasive serialization (must serialize closures + reactive graph + listener wiring, not just props), constrains authoring, and sidesteps the very thing this blueprint teaches — adoption + scheduling + replay. We borrow its "never lose the first event" lesson for Interaction (§6.10) without its model.

ALT-2 — Full-page hydration with selective/progressive priority (one app, prioritized).

  SSR whole app → HTML              CLIENT
  one client bundle (the whole  →   hydrate the entire tree, but in
  component tree)                    PRIORITY order: visible/interacted
  one root, one reconciler          first, rest progressively; Suspense
                                     boundaries gate streaming
  JS shipped ∝ app size             JS executed ∝ app size (just reordered)

Regime: a genuinely app-like surface (dashboard, editor) where most of the page is interactive anyway — islanding buys little and one coherent tree + shared state beats a bus across isolated islands. Real system: React 18 Server Components + selective/progressive hydration (Next.js App Router). Rejected: ships+executes JS proportional to app size, not interactive-island count — violating the islands thesis (§2.2, MM4); the win metric is minimum JS executed, unreachable by a single-tree model on content-heavy pages. Cited as contrast (P8); informs out-of-order streaming (Phase 10 ## 22).

ALT-3 — Compiler-inferred islands (no author directives).

  BUILD (compiler)                   SSR + CLIENT
  static analysis of components:     server renders all; client ships JS
  which are stateful / interactive →  ONLY for compiler-flagged stateful
  auto-mark island boundaries        subtrees; boundaries are inferred,
  (no client: directives)            not authored

Regime: teams that should never reason about hydration boundaries — the compiler infers what's interactive from the code, killing "I forgot client:" / "I islanded the layout" mistakes. Real system: Marko (compiler-driven automatic partial hydration, eBay). Rejected: inference makes hydration timing invisible/un-tunable, whereas this design makes strategy a first-class data-carried property (HydrationStrategy in marker + Manifest, §6.4) so an operator moves an island Load→Visible without touching code; explicit directives also make the differential-vs-Astro oracle (ADR-23) meaningful. We keep build-time island-root detection (Phase 5 ## 17) but key it on explicit client: directives.
