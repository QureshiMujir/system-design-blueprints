263 — Incremental Hydration / Islands Architecture

Project Number: 263

Project Name: Incremental Hydration / Islands Architecture

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal

Build a from-scratch islands-architecture web framework in Rust+WASM that server-renders HTML, ships near-zero JS, and hydrates interactive "islands" independently and lazily — total JS executed scales with the number of interactive islands, not page size.

1.1 Precise engineering definition

A three-sided framework over one typed core. An island = an interactive subtree marked with a client: directive; everything else ships as static HTML with zero JS.

Side Crate Function
BUILD isle-graph Find island roots from client: directives → module graph → dep-closure chunks → shared-dep dedup → emit Manifest (island→chunk URL + strategy + prop schema + integrity hash).
SERVER (SSR) isle-ssr Render Component tree → HTML (string + streaming/out-of-order); emit IslandMarker carrying serialized props + chunk + strategy; inline runtime bootstrap.
CLIENT (runtime) isle-runtime Scan markers → HydrationScheduler per strategy → lazy chunk import → prop decode → adopt SSR DOM (hydrate, not re-render) → mount isle-signal → per-island error isolation + cross-island Store.

The SSR/client boundary is bridged by isle-serialize: SSR encode(props) → versioned PropBlob in data-props; client decode → PropValue. isle-core + isle-serialize + isle-signal are no_std + alloc and compile to both server (std host) and wasm32, so prop types and markup expectations cannot drift — eliminating the #1 islands bug class (SSR/client mismatch → DomMismatch) by construction.

1.2 System boundaries & non-goals

Non-goal What we ship instead
A full React/Vue/Svelte A minimal signals runtime (isle-signal) + an Adapter trait so any framework plugs in.
A production JS minifier/transpiler We own the module/chunk graph + Manifest; minify/transpile sits behind the Transpiler trait (default = PhaseDeferred).
A CSS engine Out of scope; markup attributes only.
A network stack We consume browser fetch/dynamic-import; no HTTP client.
A bundler's full plugin ecosystem Graph + Manifest contract only.
A deploy platform An SSR library + a dev server; no hosting/CDN.

1.3 Deployment model & target users

  • Artifacts: isle CLI/dev server (build/serve/inspect/trace) + SSR library (isle-ssr) + wasm runtime (isle-runtime) + < 2 KB JS loader shim. Consumers: content-heavy sites / meta-frameworks wanting minimal JS at the right time. Target users: framework, build-tool, and web-performance engineers.

1.4 Phase-0 deliverable — the seven isle-* crates

  1. isle-core — normative types: Island, IslandId, HydrationStrategy, IslandMarker, Manifest, ChunkRef, IslandEntry, ChunkEntry; Component/Island/Adapter traits; Html; BuildError/HydrateError. no_std.
  2. isle-serialize — PropValue, PropBlob, versioned wire format, refs/cycles, schema; encode/decode round-trip. no_std.
  3. isle-signal — Signal/Effect/Memo/Scope + cross-island Store; SSR mode (effects no-op) vs client mode. no_std.
  4. isle-graph — ModuleId/Module, ChunkGraph/Chunk, island-root detection, dep-closure → chunk, dedup, Manifest emission + integrity; Transpiler trait. std.
  5. isle-ssr — RenderCtx/HtmlSink, render_to_string/render_streaming, marker emission, bootstrap inlining, out-of-order streaming. std.
  6. isle-runtime — HydrationScheduler, boot(manifest), marker scan + registry, lazy import, DOM adoption, error isolation, Store bus. wasm32.
  7. isle-cli — the isle binary / dev server. std.

Phase-0 smoke test: render <Counter client:load/> → HTML + IslandMarker + encoded props.

1.5 What later phases unlock

Reactivity (P1) → SSR renderer (P2) → island detection + prop round-trip (P3) → marker emission (P4) → chunk graph + Manifest (P5) → runtime bootstrap (P6) → DOM-adoption hydration (P7) → scheduler/strategies load/idle/visible/media/interaction/only (P8) → lazy load + error isolation (P9) → streaming/out-of-order (P10) → cross-island state + replay (P11) → CLI/dev server (P12) → conformance/differential/fuzz/bench (P13).

1.7 Recommended language & rationale — Rust 2021, MSRV 1.78, + WASM

  • One typed core shared SSR↔client → prop+markup mismatch impossible by construction; exhaustive enums model HydrationStrategy, the PropValue structured-clone value, and the chunk graph precisely; Rust→WASM islands is real + citable (Leptos islands, Sycamore, Dioxus) so reference reading maps 1:1, WASM = a controllable sandbox decoding untrusted SSR props.
  • Rejected: TypeScript end-to-end (no alloc control, no shared typed core, weaker exhaustiveness); Go (weaker sum types, weaker fine-grained-DOM WASM); C/C++ (memory-unsafe decode of untrusted props).

1.8 Prerequisites

SSR/hydration model; WASM + wasm-bindgen + web-sys; module bundling / code splitting / tree shaking; fine-grained reactivity; browser scheduling APIs (requestIdleCallback, IntersectionObserver, matchMedia); the HTML structured-clone algorithm.

1.9 Targets & timeline

  • Quantified: static (zero-island) page 0 KB JS; runtime shim < 2 KB; per-island hydration < 16 ms p50; differential markup-shape parity vs Astro astro-island; measured TTI, JS KB shipped, SSR throughput, streaming TTFB in Phase 13. Timeline: Phase-0 6–14 weeks; full 14-phase system in months.

2. Why Build This

2.1 Unique systems knowledge

Concept What it teaches Where in this blueprint

2.2 The TTI / JS-shipped performance model

  • Full hydration: JS_shipped ∝ page size, TTI blocks on whole-bundle parse+exec. Islands: JS_executed ∝ Σ(interactive islands triggered). Static-page floor = 0 KB JS for Never/no-island routes, bootstrap shim < 2 KB. Visible/Idle/Media defer parse+exec off the critical path ⇒ TTI ≈ shell paint, not full-page hydrate. Targets quantified Phase 13 (## 25): TTI, JS KB shipped/executed, hydration latency, SSR throughput, streaming TTFB.

2.3 Why islands matter — historical + architectural

  • JS-bloat crisis: full-hydration SPAs re-ship+re-execute the tree the server already rendered ("pay twice"), TTI degrades linearly with app size. Prior art (cite consistently): Astro (client:load/idle/visible/media/only, astro-island), Marko partial hydration, Eleventy is-land, Preact preact-iso, Leptos islands + Sycamore + Dioxus (Rust→WASM SSR+hydrate), patterns.dev "Islands Architecture". Contrast (non-goals): Qwik resumability (serialize listeners, no hydration) and React Server Components + selective hydration — we do partial/progressive hydration, not resumability/RSC.

2.4 Engineering muscles

Cross-compile design (one core, two targets) · exhaustive enum modeling · versioned wire format + structured-clone semantics (refs/cycles) · graph algorithms (closure, dedup, cycle detection, integrity hashing) · streaming + backpressure + out-of-order assembly · async scheduling against browser primitives · fault isolation (per-island error boundary + Scope) · determinism (render = pure fn of tree+props; SSR effects no-op).

2.6 Calibration value

Touches build-time graph tooling, server streaming, AND a sandboxed wasm client runtime in ONE typed system — the hardest integration in the portfolio. Mastery signal: shipping a server-rendered page that becomes interactive island-by-island with the minimum JS executed at the right time, mismatch-free by construction.

2.7 What Mastery Looks Like

  • Make SSR/client prop drift impossible by construction — share one no_std typed core across two compile targets so encode/decode cannot disagree (Phase 1 ## 13, Phase 3 ## 15).
  • Implement DOM adoption, not re-render — walk a template against live SSR nodes attaching listeners without replacing them, and classify every DomMismatch precisely (Phase 7 ## 19).
  • Map a declarative timing model to browser primitives — turn a HydrationStrategy enum into rIC / IntersectionObserver / matchMedia / capture-replay triggers on a cooperative, never-jank scheduler (Phase 8 ## 20).
  • Build a code-splitting chunk graph with shared-dep dedup + cycle detection — dep-closure → chunk, hoist multi-root modules, Tarjan SCC for CycleInChunkGraph (Phase 5 ## 17).
  • Lose zero interactions on deferred islands — capture the first event pre-hydration and replay it into the adopted tree after mount (Phase 11 ## 23).
  • Stream HTML out of order — early-flush shell+bootstrap, placeholder, late-insert swap, all under HtmlSink backpressure, with TTFB decoupled from the slowest data source (Phase 10 ## 22).
  • Contain failure to one island — per-island error boundary + Scope so a chunk-load/decode/mount fault never blanks the page (Phase 9 ## 21).
  • Gate a quantitative thesis in CI — prove "JS executed scales with island count, not page size" via differential-vs-Astro, fuzzing, and TTI/JS-KB perf budgets (Phase 13 ## 25).

Manifest is the cross-boundary contract: emitted at BUILD, consumed by SSR (marker data-chunk / data-strategy / prop_schema) and by CLIENT (boot(manifest) -> chunk URLs + integrity). isle-serialize bridges the SSR/CLIENT prop seam: SSR encode(props) -> PropBlob; CLIENT decode(PropBlob) -> PropValue. Same isle-core+isle-serialize+isle-signal compiled to std (server) AND wasm32 (client) -> prop/markup types cannot drift.

3.2 Boundaries

Boundary Build (isle-graph) Server / SSR (isle-ssr) Client (isle-runtime)
Trust author-trusted source props author-trusted; encode emits versioned blob untrusted: decode runs in WASM/browser sandbox; every PropBlob validated -> HydrateError::PropDecodeFailed; marker shape validated -> MarkerMalformed; no unsafe decode
Concurrency offline, single pass, deterministic per-request; streamable via HtmlSink; out-of-order placeholder + late insert; no shared mutable state across requests async-scheduled on main thread; HydrationScheduler priority queue + microtasks/rIC/IO/matchMedia callbacks; no worker threads
Persistence writes immutable artifacts: Manifest JSON + content-addressed chunks (integrity hash) stateless; reads Manifest; holds nothing across requests reads Manifest + lazily fetched chunks; no runtime DB; Store is in-memory per page
  • Trust seam = the data-props blob (author-trusted at write, untrusted at read); decoder total (never panics on adversarial bytes), malformed input contained per-island, never aborts the page. WASM sandbox: runtime touches DOM only via web-sys (DomEl), no ambient host capability. Immutability: chunk bytes == integrity hash, cache-forever + SRI verify on import, Manifest the only mutable-per-build file.

3.3 Components (one box each)

isle-graph (BUILD, std). In: entry ModuleIds + parsed client: directives. Out: ChunkGraph + Manifest (+ content-hashed chunk artifacts). Builds the Module graph, marks is_island_root from directives, computes each root's dependency closure -> a Chunk, hoists any module shared by >= 2 islands into a shared chunk (dedup, load-once), assigns integrity per chunk, emit_manifest. Transpile/minify deferred behind Transpiler (default = PhaseDeferred); graph/Manifest are owned here. Invariant: acyclic chunk graph (a cycle -> BuildError::CycleInChunkGraph); every island has exactly one root chunk + a transitively-closed dep set. Phases: 5 (## 17) primary; feeds 4 (## 16) markers, 9 (## 21) lazy import, 12 (## 24) CLI.

isle-ssr (SERVER, std). In: a &dyn Component root + (build) Manifest. Out: (String, Manifest) via render_to_string, or a stream via render_streaming(root, sink). Walks the Component tree to escaped Html, allocates island uids in RenderCtx, emits one IslandMarker per island carrying encode(props) + chunk + strategy, inlines the runtime bootstrap once, drives streaming + out-of-order (early-flush shell, placeholder, late insert + swap script). Runs isle-signal in SSR (no-op effects) mode. Invariant: render is pure over (tree, props); emitted DOM is byte-stable so the client can ADOPT it; every island subtree wrapped by exactly one marker. Phases: 2 (## 14), 4 (## 16), 10 (## 22); consumed for adoption in 7 (## 19).

isle-serialize (SHARED, no_std+alloc). In: &PropValue (SSR) / &PropBlob (client). Out: PropBlob (encode) / Result<PropValue, HydrateError> (decode). Structured-clone-like value model (Null/Bool/Int/Float/Str/Bytes/Array/Object/Ref/Date), compact versioned wire format (version: u16), shared/cyclic refs via Ref(u32), per-island prop schema. Invariant: lossless encode->decode round-trip; total decoder (adversarial bytes -> PropDecodeFailed, never panic/UB); version mismatch is a typed error. Phases: 3 (## 15) primary; the bridge used by 4 (## 16) embed, 6/7 (## 18/19) decode, 9 (## 21) error isolation.

isle-core (SHARED, no_std+alloc). In/Out: none at runtime — it is the normative type vocabulary. Defines Island/IslandId, HydrationStrategy (Load/Idle/Visible/Media/Interaction/Only/Never), IslandMarker, Manifest/IslandEntry/ChunkEntry/ChunkRef, Html, the Component/Island/Adapter traits, and the BuildError/HydrateError enums. Compiles to BOTH server and wasm. Invariant: single source of truth for every cross-boundary type; the strategy + PropValue enums are exhaustively matched (compiler-enforced) so no side adds an unhandled case. Phases: 0 (## 12) onward — every phase references it.

isle-signal (SHARED, no_std+alloc). In: a Scope + initial values; closures for memo/effect. Out: reactive Signal<T>/Memo<T>/Effect/Scope + cross-island Store. Fine-grained dependency tracking; Scope is an arena dropped to dispose. Invariant: SSR mode -> effect is a no-op (initial render only), client mode -> effects run; the initial client render therefore equals the SSR DOM (precondition for adoption). Phases: 1 (## 13) primary; mounted during hydration in 7 (## 19); cross-island Store bus in 11 (## 23).

isle-runtime (CLIENT, wasm32 + < 2 KB JS shim). In: Manifest (via boot) + the live SSR DOM + markers. Out: hydrated, interactive islands (IslandHandle each). JS shim -> wasm boot(manifest): scan markers -> island registry, HydrationScheduler registers per-strategy triggers (Load=boot, Idle=rIC+timeout, Visible=IntersectionObserver(root_margin), Media=matchMedia(query), Interaction=pre-hydration listener then hydrate+replay, Only=client render, Never=skip), lazily dynamic-imports the chunk (load dedup + retry/fallback), decode props, ADOPTS existing DOM via Adapter.mount/Island.hydrate, mounts isle-signal, isolates each island in its own error boundary + Scope, wires the cross-island Store bus. Invariant: hydration = adoption not re-render (no node replacement on match; mismatch -> DomMismatch = dev warn+fallback, prod log+contain); per-island faults (ChunkLoadFailed/PropDecodeFailed/mount panic) are confined — other islands + static page keep working; hydration idempotent. Phases: 6 (## 18), 7 (## 19), 8 (## 20), 9 (## 21), 11 (## 23).

isle-cli (HOST, std). In: project sources + CLI args. Out: the isle binary / dev server. Subcommands: build (drive isle-graph -> Manifest + chunks), serve (dev server: SSR via isle-ssr, serve runtime wasm + chunks, HMR-lite), inspect (dump Manifest / chunk graph / island table), trace (per-island hydration timeline + TTI). Depends on all other crates. Invariant: inspect/trace are read-only over build + runtime artifacts; serve reuses the exact production SSR + runtime paths (no dev-only divergence). Phases: 12 (## 24); the harness for benchmarks/conformance in 13 (## 25) (TTI, JS KB shipped, hydration latency, SSR throughput, streaming TTFB).

4.8 Correctness invariants (LOCKED — verified in Phase 13)

  • Idempotent hydration: re-running hydrate_island on a hydrated marker no-ops; double-boot() safe. Never panic: all decode/scan/adopt paths return Result, adversarial markup/props → typed HydrateError, never panic!/unwrap (fuzzed PropBlob/IslandMarker). Adoption equality: [ssr] SSR DOM == [client] first render (effects no-op on SSR); inequality → DomMismatch (dev warn+CSR fallback, prod log+contain).
  • Error isolation: one island's failure (ChunkLoadFailed/PropDecodeFailed/DomMismatch/mount panic) confined to its boundary; siblings + static page unaffected. No prop drift: identical isle-core+isle-serialize types compile std+wasm, encode→decode total + version-checked (PropBlob.version). Determinism: render = pure fn of (tree, props); no wall-clock/RNG in the render path.

4.9 Compatibility & portability

  • Browsers: evergreen Chrome/Firefox/Safari/Edge (wasm-bindgen + web-sys baseline); IntersectionObserver/requestIdleCallback/matchMedia required (rIC has setTimeout fallback). Targets: build/SSR/graph crates std (host), isle-runtime wasm32-unknown-unknown, isle-core+-serialize+-signal no_std+alloc (server AND wasm). Rust edition 2021, MSRV 1.78; no-network at runtime (SSR lib + dev server only, deploy out of scope).

6. Design Principles

Twelve non-negotiable principles. Each is referenced by name in later phases (## 12–## 25). Ordering is significance, not dependency. Violation column states the concrete failure mode.

6.1 One typed core across SSR + client

  • Rule. isle-core+isle-serialize+isle-signal are no_std + alloc, compile to BOTH server (std) and wasm32 (client); Island/HydrationStrategy/PropValue/IslandMarker have exactly one definition. Why: eliminates the #1 islands bug (SSR/client prop+markup drift) by construction — encoder and decoder share the type, not a hand-kept schema.
  • Tradeoff. No server-only deps in the shared core (std::fs/tokio live in isle-ssr/-graph/-cli). Operational: a PropValue variant added once is seen by encode (SSR) + decode (client) the same compile. Violation: two divergent definitions → encode/decode disagree → silent PropDecodeFailed/wrong props the type system can't catch.

6.2 Hydration is adoption, not re-render

  • Rule. hydrate_island walks the island template against EXISTING SSR DOM, attaching listeners + reactive bindings WITHOUT replacing nodes (Adapter.mount/Island.hydrate adopt, never innerHTML=). Why: re-render discards the server's work (flash, lost focus/scroll/input, double cost); adoption = zero extra paint. Idempotent (Phase 7): a 2nd boot over a hydrated marker no-ops.
  • Tradeoff. Requires SSR DOM == client expectation → strict determinism (§6.6) + versioned marker (§6.12). Violation: node-shape divergence = DomMismatch (gravest bug; dev warn+CSR fallback, prod log+contain); re-rendering masks the bug and burns the SSR payload.

6.3 Ship zero JS for static content

  • Rule. Only client:-marked subtrees become islands; everything else is static HTML, ZERO JS; Never = static forever. Why: total JS executed scales with interactive-island count, not page size — the core islands thesis. Operational: isle inspect reports JS KB/route; budget gate fails the build if a static page ships any island chunk.
  • Tradeoff. Static subtrees can't become interactive without a rebuild — accepted, it's the contract. Violation: accidentally islandizing layout/wrappers reintroduces whole-page hydration → JS KB + TTI regress to a monolith.

6.4 Hydrate at the right time, not all at once

  • Rule. HydrationScheduler triggers per HydrationStrategy: Load(boot)/Idle(rIC)/Visible(IO root_margin)/Media(matchMedia query)/Interaction(replay)/Only/Never. Why: off-screen/low-priority islands defer; the page is interactive where it matters first → lower TTI. Operational: strategy is data (data-strategy+Manifest), not code — tunable per island without recompiling.
  • Tradeoff. Deferred islands have a pre-hydration window without rich interaction (mitigated by Interaction replay, §6.10). Violation: every island as Load = whole-page hydration on boot → main-thread saturation, TTI collapse.

6.5 Each island is isolated

  • Rule. Each island hydrates in its own error boundary + Scope; a chunk-load fail, PropDecodeFailed, or mount panic is caught, logged, confined. Why: one faulty island can't break the static page or siblings — partial interactivity beats total failure. Operational: failed island stays inert SSR HTML; trace records HydrateError variant + island id.
  • Tradeoff. Per-island boundary+Scope bookkeeping (one IslandHandle each) — acceptable vs blast radius. Violation: a shared/global hydration loop lets one panic abort boot → every island below stays dead; the page silently loses all interactivity.

6.6 Render is a pure, deterministic function

  • Rule. Output HTML = pure fn of (Component tree, props); SSR runs Effects NO-OP (initial render only), client runs them; render_to_string has no ambient state beyond RenderCtx. Why: adoption (§6.2) needs hydrated DOM == SSR DOM byte-for-structure — only deterministic render guarantees it. Operational: same uid allocator + ssr-mode Scope → reproducible marker ids; differential tests (Phase 13) diff SSR vs client.
  • Tradeoff. No side effects/RNG/wall-clock in render — such values arrive as serialized props. Violation: nondeterministic render (Date.now/Math.random/effect mutation) → SSR≠client → DomMismatch cascade.

6.7 The scheduler never blocks the main thread

  • Rule. HydrationScheduler = a priority queue that yields to idle: batches work, honors rIC deadlines, never runs a long synchronous sweep. Why: keeps the page responsive during hydration — input latency stays low even with many islands. Operational: Load first, Idle fills idle time, Visible/Media are event-driven.
  • Tradeoff. Cooperative scheduling adds a few ms dispatch overhead/slice vs a tight loop. Violation: a blocking sweep = long task > 50 ms → jank, dropped input, TTI/INP regression — defeats §6.4.

6.8 Minimal prop payloads

  • Rule. data-props carries only what an island needs as a compact versioned PropBlob (refs dedup shared/cyclic, no whitespace, no inline schema). Why: props ship in HTML per island instance; payload directly inflates TTFB + bytes-to-interactive. Operational: Ref(u32) collapses repeats to one copy; prop_schema: SchemaId lives in the Manifest, not per-marker.
  • Tradeoff. Compact binary-ish encoding is less readable than JSON (mitigated by inspect/trace decoders). Violation: dumping full component state or re-serializing shared graphs per island → marker bloat, parse cost, TTFB regression.

6.9 Lazy by default

  • Rule. Island chunks load on their strategy trigger via dynamic import; each root's dependency closure is a chunk, modules shared by ≥2 islands hoist to a shared chunk (dedup, load-once). Why: network+parse follows interaction, not page weight; shared deps never download twice. Operational: loads deduped at runtime (one in-flight promise per ChunkRef); retry/fallback on failure (Phase 9).
  • Tradeoff. Many tiny chunks add request overhead; the chunk graph balances closure vs dedup (Phase 5). Violation: eager-loading all chunks at boot or duplicating shared deps per chunk → defeats code-splitting, regresses bytes-to-interactive.

6.10 No lost interactions

  • Rule. Interaction attaches a lightweight pre-hydration listener for the named events; the first match HYDRATES the island then REPLAYS that exact event into the hydrated tree. Why: a user clicking a not-yet-hydrated island must not lose the click — perceived == real interactivity. Operational: pre-hydration listeners removed after adoption; replay dispatches against the adopted node.
  • Tradeoff. First interaction pays hydration latency inline; replay must reconstruct the event faithfully. Violation: dropping the initiating event → the first click does nothing → the island feels broken despite "working".

6.11 Observable hydration

  • Rule. Every lifecycle edge — marker scan, schedule, chunk load, decode, adopt, mount, error — emits a timeline trace hook surfaced by isle trace. Why: timing + HydrateError causes are otherwise invisible; you can't tune §6.4/§6.7 or debug §6.2 without a timeline. Operational: trace records id, strategy, chunk bytes, latency, outcome → feeds TTI/JS-KB benchmarks (Phase 13).
  • Tradeoff. Trace hooks cost a small constant/event; gated to dev/trace builds on the hot path. Violation: opaque hydration → DomMismatch/ChunkLoadFailed diagnosed by guesswork; perf regressions ship unnoticed.

6.12 Generic over the framework + versioned wire + streaming-first

  • Generic. Components plug in via the Adapter trait (mount(el,comp,props)->IslandHandle); the bundled isle-signal runtime is the reference adapter. Violation: hard-coding one UI library couples the runtime to it, blocking the pluggability non-goal.
  • Versioned wire. PropBlob{version:u16,..} + the IslandMarker schema are explicitly versioned; decode rejects unknown versions as PropDecodeFailed. Tradeoff: version check per decode. Violation: build/runtime skew silently misreads bytes → corrupt props not a clean error.
  • Streaming-first. SSR is out-of-order by default: shell+placeholder, early-flush head+bootstrap, stream each island's HTML + swap marker as data resolves; backpressure via HtmlSink. Tradeoff: swap-marker/late-insert complexity. Violation: buffering the page before first byte → TTFB tied to the slowest async island, negating streaming.

8. Domain Model — Islands, Strategies, Props, and Hydration

The normative vocabulary shared across BUILD (isle-graph) / SERVER (isle-ssr) / CLIENT (isle-runtime). All types home in isle-core unless noted. An island = an interactive subtree marked with a client: directive; everything else is static HTML shipped with ZERO JS. Total JS executed scales with island count, not page size.

8.1 Island model + client: directive grammar (EBNF)

directive   = "client:" strategy ;
strategy    = "load"
            | "idle"
            | "visible" [ "=" "{" root_margin "}" ]      (* root_margin -> IntersectionObserver rootMargin, default "0px" *)
            | "media"   "=" "{" media_query "}"          (* media_query MANDATORY; e.g. "(max-width:600px)" *)
            | "interaction" [ "=" "{" event_list "}" ]   (* event_list default ["click"] *)
            | "only"                                       (* client-only; no SSR HTML *)
            | "never" ;                                    (* static; never hydrated; emits NO marker *)
event_list  = event { "," event } ;
event       = "click" | "pointerdown" | "focusin" | "keydown" | "submit" | ident ;
root_margin = (* CSS margin string: 1-4 lengths, px|% *) ;
media_query = (* CSS media query, unquoted braces-delimited *) ;

HydrationStrategy (LOCKED, isle-core::island) is the parsed form; a BadDirective BuildError is raised on unknown strategy, missing mandatory media={…}, or malformed margin/query.

8.2 IslandMarker DOM format

IslandMarker is a <isle-island> custom-element boundary (comment-pair fallback for adoption inside tables/<select>). Carries: data-isle-id, data-strategy, data-chunk, data-adapter, data-props (base64url PropBlob). One marker per island; nested islands nest as child <isle-island>.

<isle-island data-isle-id="7" data-strategy="visible:0px 200px" data-chunk="c3"
              data-adapter="signals" data-props="AQAEbgJxAGsCdjI=">
  <button>count: <!--isle:txt 0-->0<!--/isle:txt--></button>   <!-- SSR DOM, adopted not replaced -->
</isle-island>

Comment-pair form (for HTML-parser-restricted contexts):

<!--isle:7 strategy=load chunk=c1 adapter=signals props=AQ...--> …SSR DOM… <!--/isle:7-->

MarkerMalformed if data-isle-id/data-chunk/data-strategy absent, or comment-pair open/close ids mismatch.

8.3 PropValue structured-clone model + wire format

pub enum PropValue { Null, Bool(bool), Int(i64), Float(f64), Str(String), Bytes(Vec<u8>),
    Array(Vec<PropValue>), Object(Vec<(String,PropValue)>), Ref(u32), Date(f64) }
pub struct PropBlob { version: u16, bytes: Vec<u8> }   // version = 1 (current)

Subset of the HTML structured clone algorithm: no functions/DOM/closures. Ref(u32) = back-reference into a value-index table → encodes shared subgraphs and cycles. Date(f64) = epoch ms (round-trips Date).

Wire format (versioned, little-endian, varint lengths):

PropBlob := u16 version | u32 node_count | node{node_count}
node     := tag:u8 payload
tag 0x00 Null      (no payload)        tag 0x05 Bytes  varint len | bytes
tag 0x01 Bool      u8(0|1)             tag 0x06 Array  varint len | node-index*  (refs into table)
tag 0x02 Int       varint zigzag       tag 0x07 Object varint len | (varint keyidx | node-index)*
tag 0x03 Float     f64 LE              tag 0x08 Ref    varint -> existing node index
tag 0x04 Str       varint len | utf8   tag 0x09 Date   f64 LE

Encoder assigns each distinct heap node an index (DAG flattening); a second visit emits Ref(idx). Decoder rebuilds the table then resolves Refs, tolerating forward refs for cycles.

Worked encode/decode (shared + cyclic): obj = { self: <obj>, tag: "x" } (object references itself).

encode -> nodes: [0]=Object{ self->Ref(0), tag->1 }, [1]=Str("x")
PropBlob{ version:1, bytes: 01 00 | 02 00 00 00 |          # ver=1, count=2
          07 02  00 08 00  01 01  |  04 01 78 }            # node0 Object{key0->Ref0, key1->n1}; node1 Str"x"
decode -> allocate 2 placeholders, fill node0 Object, node0.self = &node0 (cycle), node1="x"

fn encode(v:&PropValue)->PropBlob (SSR) / fn decode(b:&PropBlob)->Result<PropValue,HydrateError> (client). version != 1 → PropDecodeFailed; truncated/out-of-range index → PropDecodeFailed.

8.7 DOM ADOPTION algorithm

HYDRATION = ADOPTION, not re-render: walk the island template/vdom and the existing SSR DOM in lockstep, attach listeners + reactive bindings WITHOUT creating/replacing nodes; isle-signal text/attr bindings latch onto <!--isle:txt-->-delimited SSR ranges.

adopt(tmpl_node, dom_node, scope):
  assert tag/nodeType match            # else DomMismatch
  bind dynamic attrs -> Signals; attach event listeners to dom_node
  zip(tmpl.children, dom.children): recurse adopt(child_t, child_d, scope)
  text bindings -> latch onto SSR comment-delimited text range (no re-set)
  surplus/missing child -> DomMismatch

Mismatch = SSR markup ≠ client expectation (differing tag, attr the runtime treats as structural, child count, or marker shape). Result: HydrateError::DomMismatch. Dev: warn (log expected vs found node) + fall back to full client render of that island. Prod: logged + contained to the island (error boundary); siblings + static page unaffected. Adoption is idempotent — re-running on an already-hydrated marker is a no-op (handle present in registry).

A hand-written JS runtime wins below the ~20 KB wasm-instantiate floor — a tiny site where the wasm module + bindgen glue costs more than the JS it replaces (Preact-class footprint).

A single crate wins for a prototype/spike where compile-graph simplicity beats boundary enforcement, and no one yet ships the wasm target separately.
ADR-04 Shared typed core across server + wasm isle-core + isle-serialize + isle-signal are no_std + alloc; compile for BOTH std server and wasm32 std-only core duplicated per side; JSON schema as the only contract A single typed core eliminates the #1 islands bug class — SSR/client prop+markup drift — by construction: encode and decode share one PropValue/PropBlob definition. A JSON-schema contract wins when SSR and client are different languages (e.g. a Go server + JS client) — no shared type is possible, so a versioned schema + codegen is the only seam.
ADR-05 UI-framework coupling Adapter trait + bundled minimal isle-signal reference framework Bundle React/Vue/Svelte; hard-wire one framework NON-GOAL = ship a full framework; Adapter::mount lets any framework plug in while the reference signals runtime keeps the demo path and tests self-contained. Hard-wiring one framework wins for a product team standardized on React — the adapter indirection is dead weight, and React's island libs (preact/compat) already exist.
ADR-06 Hydration timing model HydrationStrategy enum: Load/Idle/Visible{root_margin}/Media{query}/Interaction{events}/Only/Never Hydrate-everything-on-load; string config; per-island bespoke callbacks Closed enum maps 1:1 to a browser trigger (boot / rIC / IO / matchMedia / replay / CSR / static); exhaustive match guarantees every strategy has a scheduler arm. Per-island bespoke callbacks win when authors need a trigger the enum lacks (e.g. "hydrate after analytics consent"); a closed enum cannot express open-ended scheduling policy.
ADR-07 Island boundary DOM encoding <isle-island> custom element carrying data-isle-id/strategy/chunk/props/adapter Comment-pair markers only; data on a generic <div> Custom element is a stable, queryable, non-paint-affecting host (Astro astro-island precedent); IslandMarker may fall back to a comment pair where a custom element is illegal (e.g. inside <table>). Comment-pair-only wins when markup must survive contexts that forbid custom elements wholesale (legacy table/select-heavy pages, strict sanitizers that strip unknown elements).
ADR-08 Prop value model PropValue structured-clone-like enum (incl. Bytes, Date, Ref for shared/cyclic) JSON-only props; serde_json::Value Structured clone is the web's real prop semantics; Ref preserves shared/cyclic graphs JSON drops; typed variants avoid lossy number/Date coercion across the boundary. JSON-only wins when props are guaranteed flat, acyclic, and JSON-native (config blobs); then serde_json is simpler, human-readable in DevTools, and skips a bespoke codec.
ADR-09 Wire format Compact versioned binary PropBlob{version:u16, bytes} JSON text in data-props; bincode without a version field Smaller bytes-on-marker (lower TTFB/HTML weight); explicit version:u16 lets decode reject/upgrade old blobs; binary side-steps HTML-attribute escaping of JSON. JSON text wins for debuggability-first builds and props small enough that gzip erases the size gap — operators can read data-props directly without an inspect decoder.
ADR-10 Client reactivity model Fine-grained reactivity Signal/Effect/Memo/Scope (isle-signal) VDOM diff/reconciliation; dirty-checking DOM ADOPTION needs surgical listener+binding attach, not tree re-diff; fine-grained updates touch only changed nodes → less JS executed, the islands win metric. VDOM wins when the target framework is already VDOM-based (React/Preact) and authors expect its mental model + ecosystem; reconciliation also tolerates looser SSR/client markup.
ADR-11 Build-time code splitting Chunk graph: each island root's dep-closure → one Chunk; module shared by ≥2 islands hoisted to a shared chunk (dedup) One bundle per page; one chunk per module; manual chunk config JS executed scales with interactive islands, not page size; shared-chunk dedup means a common dep loads once; cycle in chunk graph = BuildError::CycleInChunkGraph. One bundle wins for a tiny app (1–2 islands) where HTTP request overhead and waterfall depth dominate over the bytes saved by splitting; manual chunks win when an operator knows the access pattern better than the closure heuristic.
ADR-12 Transpile / minify Transpiler trait, default = PhaseDeferred (own the module/chunk GRAPH + Manifest, not the minifier) Build-in JS minifier/transpiler; vendor swc/terser as a hard dep NON-GOAL = a production minifier; trait keeps the graph/Manifest logic testable and lets a real transpiler be injected without coupling the core to a JS toolchain. Vendoring swc/terser wins for a turnkey product that must minify out-of-the-box; the deferral only pays off when a host already owns its JS toolchain.
ADR-13 SSR output + streaming HtmlSink trait + render_streaming with out-of-order (placeholder → late insert), early head/bootstrap flush String-only render_to_string; in-order streaming only Early-flush shell + bootstrap improves TTFB; out-of-order lets async-data islands emit a placeholder, flush, then swap on resolve; render_to_string retained for static/test paths. String-only wins for fully static pages (no async data) or SSG, where there is nothing to stream and buffering the whole page is simpler and equally fast.
ADR-14 Hydration semantics DOM adoption (walk template/vdom vs existing SSR nodes, attach without replacing) Re-render then replace; full client re-mount Re-render wastes the SSR HTML and flashes; adoption preserves nodes + scroll/focus; a markup mismatch is the gravest bug → HydrateError::DomMismatch. Re-render-then-replace wins for client:only islands (no SSR DOM to adopt) and as the fallback when adoption hits DomMismatch — correctness over byte-thrift.
ADR-15 Failure containment Per-island error boundary + Scope; one island's chunk-load/decode/mount failure is caught + confined Page-global try/catch; let one failure abort hydration Islands are independent units; isolation keeps the static page + sibling islands interactive when one island fails (logged in prod, warn+CSR-fallback in dev). A page-global handler wins for a single-island app (a calculator widget) where there is nothing to isolate from — per-island bookkeeping is pure overhead.
ADR-16 Pre-hydration interaction Interaction{events} attaches a lightweight listener, then on first event HYDRATE + REPLAY the event (event delegation/replay model, per project 261) Hydrate-on-load to "feel" interactive; drop the first event Zero JS until the user actually interacts; replaying the captured event makes the first click/keypress feel native, matching Qwik/Astro interaction semantics. Hydrate-on-load wins for an above-the-fold CTA where the first interaction is near-certain and must be instant — the deferred-then-replay latency is a worse UX than paying boot cost upfront.
ADR-17 Client bootstrap shim Tiny (< 2 KB) JS loader shim → boot(manifest) → wasm entry Pure-JS runtime; large JS bootstrap The shim only fetches+instantiates wasm and calls boot; keeping it < 2 KB protects the islands promise of minimal JS shipped before any island hydrates. A pure-JS runtime wins when wasm is unavailable (locked-down WebViews, no-wasm CSP) — the shim's wasm dependency is fatal there, so a JS fallback runtime is the only path.
ADR-18 Browser bindings wasm-bindgen + web-sys for DOM/IO (querySelector, IntersectionObserver, matchMedia, requestIdleCallback) Raw JS interop strings; stdweb web-sys gives typed, audited bindings for exactly the trigger APIs the HydrationScheduler needs; avoids ad-hoc unsafe JS glue. Raw JS interop wins when shaving the last KB of bindgen-generated glue matters more than type safety, or to call an API web-sys has not yet bound.
ADR-19 Chunk integrity Subresource Integrity (SRI) hash per ChunkEntry.integrity + IslandEntry.integrity in the Manifest No integrity; trust URL only Lazily imported chunks are executed code; SRI lets the loader verify a chunk's bytes match the build, blocking tampered/stale CDN payloads. Trusting the URL wins on a first-party same-origin deploy with no CDN, where the integrity compute + manifest bloat buy nothing because the transport is already trusted.
ADR-20 Dev server + reload isle-cli serve with HMR-lite (reload affected island/chunk, re-emit Manifest) No dev server; full-page reload only; full HMR with state preservation serve+build+inspect+trace cover the dev loop; HMR-lite (reload changed chunk) is enough to iterate without owning a full stateful HMR runtime. Full state-preserving HMR wins for a large app where losing form/route state on every edit destroys iteration speed — worth owning a stateful HMR runtime there.
ADR-21 Error surface Result<_, BuildError> (build) and Result<_, HydrateError> (client); panic only for invariant bugs Panic-based control flow; stringly-typed errors Typed enums (CycleInChunkGraph, DomMismatch, ChunkLoadFailed, …) make every failure mode explicit + matchable; panics reserved for true impossibilities. Panic-based control flow wins in a throwaway script/bench where unwinding to a top-level handler is fine and exhaustive typed errors are ceremony.
ADR-22 Fuzzing cargo-fuzz targets on isle-serialize::decode and the IslandMarker parser Hand-written adversarial cases only decode consumes untrusted SSR/network bytes; fuzzing the round-trip + marker parse guards against PropDecodeFailed/MarkerMalformed on malformed/hostile input. Hand-written cases win pre-MVP, before the wire format stabilizes — a fuzzer against a churning grammar mostly finds bugs in code you're about to rewrite.
ADR-23 Differential oracle Compare emitted HTML + marker/Manifest shape against Astro output (islands + client:* directives, astro-island) No external oracle; self-consistency only An independent, well-known reference catches structural divergence in marker/strategy/chunk emission that a self-test would miss. Self-consistency wins once the format intentionally diverges from Astro (custom strategies/markers) — pinning to an external oracle then generates noise, not signal.
ADR-24 Benchmarks Track TTI, JS KB shipped (pre/post first hydration), TTFB (streaming), hydration latency, SSR throughput Wall-clock anecdotes; micro-bench only The islands thesis is quantitative ("minimum JS at the right time"); these metrics are the acceptance bar for the architecture, asserted in Phase 13 (## 25). Micro-bench-only wins when isolating a single hot path's regression (e.g. decode ns/op) where end-to-end TTI noise would drown the signal.
ADR-25 CI GitHub Actions: build all crates (std + wasm32), cargo test, clippy, fmt, fuzz smoke, bench-regression gate, MSRV 1.78 check No CI; local-only gating Cross-target build matrix is essential because the no_std core MUST compile for server AND wasm; CI enforces the shared-core invariant continuously. Local-only gating wins for a solo author on a private spike where CI setup cost exceeds the value before the first external contributor.

GPL/copyleft wins for a project that wants share-alike enforcement (a reference impl meant to keep forks open); heavy deps win when a vetted batteries-included framework beats hand-rolling.

11. Core Schema and Core Types

Normative APIs all phases build against, grouped by crate; signatures only (illustrative bodies ≤ 2 lines). Three contexts: SSR (std, per-request, single-thread, no shared mutable state), client (wasm32, single-threaded main + cooperative HydrationScheduler), shared core (isle-core/-serialize/-signal = no_std + alloc, compile to BOTH server + wasm → SSR-encode and client-decode use the same type, drift impossible). Versioned wire forms (round-trip across the SSR→client boundary, may evolve): PropBlob (version:u16), Manifest (JSON schema_version), IslandMarker (DOM attr set, additive-only). Compat: server + client built from one workspace pin → wire versions match per deploy; readers reject unknown major (PropDecodeFailed/MarkerMalformed), tolerate unknown additive fields.

11.1 isle-core — module island (normative shared types)

/// Stable per-page island identity (RenderCtx uid alloc, SSR); echoed in data-isle-id, Manifest+registry key. Copy, Eq, Hash.
pub struct IslandId(u32);
/// Manifest key for a loadable chunk (island closure or shared dep). Copy, Eq, Hash.
pub struct ChunkRef(u32);

/// One interactive subtree. OWNED by RenderCtx during SSR, serialized into its IslandMarker; not sent whole — client reconstructs from marker attrs (id, strategy, chunk, decoded props, adapter).
pub struct Island {
    id: IslandId, component: ComponentName, strategy: HydrationStrategy,
    props: PropBlob,            // encode()d at render; placed in data-props
    chunk: ChunkRef, adapter: AdapterId, ssr_marker: IslandMarker,
}

/// WHEN to hydrate -> exactly one browser trigger. Exhaustive, no_std; serialized into data-strategy + IslandEntry. Adding a variant = wire-major bump.
pub enum HydrationStrategy {
    Load,                              // hydrate on runtime boot
    Idle,                             // requestIdleCallback (+ setTimeout fallback)
    Visible { root_margin: String }, // IntersectionObserver(root_margin)
    Media   { query: String },       // matchMedia(query), hydrate when it matches
    Interaction { events: Vec<String> }, // pre-hydration listener -> hydrate + replay event
    Only,                            // client-only: no SSR HTML, render from scratch
    Never,                          // static, never hydrated (zero JS)
}

/// DOM boundary delimiting an island in SSR output: `<isle-island>` custom element or a comment pair; carries the versioned attribute wire form below.
pub struct IslandMarker { /* data-isle-id, -strategy, -chunk, -props, -adapter */ }

/// Build-time island routing table. Emitted by emit_manifest, consumed by boot(); JSON wire form (schema_version), immutable post-build, shared &Manifest on client.
pub struct Manifest { islands: Map<IslandId, IslandEntry>, chunks: Map<ChunkRef, ChunkEntry> }
/// Per-island routing row: which chunk, when, prop schema, integrity to verify on load.
pub struct IslandEntry { chunk: ChunkRef, strategy: HydrationStrategy, prop_schema: SchemaId, integrity: String }
/// Per-chunk row: fetch URL, transitive chunk deps (load first), size budget, SRI hash.
pub struct ChunkEntry { url: String, deps: Vec<ChunkRef>, bytes: u64, integrity: String }
  • Ownership/concurrency/compat: Island owned by RenderCtx for the request, dropped at flush, never mutated after marker emit; Manifest build-time-immutable, client holds &Manifest page-lifetime (no interior mutability). All Send-able plain data built per request (no cross-request sharing); on wasm Manifest is single-owner read-only (no sync). IslandId/ChunkRef are page-local (not build-stable); ChunkEntry.integrity is SRI, fetch mismatch → ChunkLoadFailed.
/// SSR side: render self to escaped Html within a RenderCtx (uid alloc, sink, ssr scope).
pub trait Component { fn render(&self, ctx: &mut RenderCtx) -> Html; }
/// Client side: adopt the existing SSR DOM subtree el (hydrate, NOT re-render), bind props.
pub trait Island: Component { fn hydrate(&self, el: DomEl, props: &PropValue) -> IslandHandle; }
/// Pluggable UI framework: id() keys the registry, mount() drives hydration for non-reference frameworks; bundled reference adapter wraps isle-signal (non-goal: full React/Vue/Svelte).
pub trait Adapter {
    fn id(&self) -> AdapterId;
    fn mount(&self, el: DomEl, comp: &dyn Island, props: &PropValue) -> IslandHandle;
}

/// Escaped, attributed markup buffer. Output of Component::render; APPEND-ONLY.
/// Construct via escaping constructors so injection is impossible by type.
pub struct Html(/* escaped markup buffer */);

/// Build-time failures (isle-graph / directive parse). std side only.
pub enum BuildError { CycleInChunkGraph, UnknownAdapter, BadDirective }
/// Client hydration failures — each is caught + confined to one island's error boundary.
pub enum HydrateError { ChunkLoadFailed, PropDecodeFailed, MarkerMalformed, AdapterMissing, DomMismatch }
  • Component is the only SSR-required trait; Island extends it with hydrate (client). A static node implements Component only → ships zero JS. Adapter indirection makes the framework UI-agnostic.
  • Html: ownership = owned buffer moved into the HtmlSink; escaping enforced at construction → no raw-string injection path. HydrateError::DomMismatch is the gravest correctness bug (SSR markup ≠ client expectation): dev = warn + client-render fallback; prod = log + contain.

IslandMarker wire form (versioned, additive-only)

<isle-island data-isle-id="7" data-strategy="visible:0px 200px"
  data-chunk="c3" data-adapter="signals"
  data-props="AQ.."><!-- SSR HTML --></isle-island>

data-props = base64 PropBlob; data-strategy = tag[:arg]; comment-pair form <!--isle:7 ...-->…<!--/isle:7--> is equivalent for fragments. Unknown data-* ignored; malformed required attr → MarkerMalformed.

11.2 isle-serialize — module value (SSR↔client prop bridge)

/// Structured-clone-like value: the ONLY type crossing the SSR/client boundary as props. no_std+alloc → identical server (encode)/wasm (decode); owned tree, Refs model shared/cyclic subgraphs by index. Adding a variant = PropBlob major bump.
pub enum PropValue {
    Null, Bool(bool), Int(i64), Float(f64), Str(String), Bytes(Vec<u8>),
    Array(Vec<PropValue>), Object(Vec<(String, PropValue)>),
    Ref(u32) /* shared/cyclic node index */, Date(f64) /* ms epoch */,
}
/// Compact versioned wire envelope embedded in data-props. version gates the byte layout.
pub struct PropBlob { version: u16, bytes: Vec<u8> }
pub fn encode(v: &PropValue) -> PropBlob;                       // SSR: serialize once per island
pub fn decode(b: &PropBlob) -> Result<PropValue, HydrateError>; // client: PropDecodeFailed on bad/unknown version

3.2 Detailed Implementation Steps

Theory anchors: ADR-08 (PropValue structured-clone model); ADR-09 (versioned binary PropBlob wire format); INV-3/INV-4 (round-trip identity + version gate); MM2/MM3 (props are data, not code; one shared type kills drift); P12 (structured clone algorithm).

  • Files: isle-serialize/src/lib.rs, value.rs (PropValue, PropBlob), wire.rs (varint + tag codec), schema.rs (SchemaId, shape hash), directive.rs (in isle-core::island), graph_detect.rs.
  • Directive grammar (parsed at build, attached to component node):
directive   = "client:" strategy [ ":" arg ] ;
strategy    = "load" | "idle" | "visible" | "media" | "interaction" | "only" ;
arg         = string ;                 (* root_margin | media query | event list *)
  • Map directive → HydrationStrategy enum (LOCKED in isle-core): visible→Visible{root_margin}, media→Media{query}, interaction→Interaction{events: split(',')}. Bad directive → BuildError::BadDirective.
  • Island-root detection: fn detect_island_roots(tree: &ComponentNode) -> Vec<IslandId> — post-order DFS; a node bearing client:* becomes a root; descendants inherit nothing (separate island only if re-marked). Nested islands allowed; emit one IslandId per directive.
  • PropValue (LOCKED): Null,Bool,Int(i64),Float(f64),Str,Bytes,Array,Object(Vec<(String,PropValue)>),Ref(u32),Date(f64). Object = ordered Vec (insertion-stable → deterministic bytes).
  • Wire format PropBlob{ version:u16, bytes }:
PropBlob.bytes := MAGIC(0x49 0x53) | version:u16le | tag_stream
tag = u8: 0=Null 1=False 2=True 3=Int(zigzag-varint) 4=Float(f64le)
      5=Str(len-varint+utf8) 6=Bytes(len+raw) 7=Array(len+elems)
      8=Object(len+(keyStr+val)*) 9=Ref(varint id) 10=Date(f64le)
  • encode(&PropValue)->PropBlob: single pass; intern shared/cyclic subgraphs — maintain IdentityMap<*const node, u32>; first sighting emits inline + assigns id, repeat emits Ref(id). Cycle ⇒ forward Ref to an id not yet fully written (decoder back-patches).
  • decode(&PropBlob)->Result<PropValue,HydrateError>: validate MAGIC + version; unknown major version → HydrateError::PropDecodeFailed. Build Vec<Slot> for ids; Ref to unseen id = lazy Rc/index handle resolved post-pass. Depth counter, cap 256 → PropDecodeFailed.
  • SchemaId = FNV-1a over the structural shape (tag sequence sans values), carried in IslandEntry::prop_schema, mismatch detectable pre-hydration. Sync: pure, no shared state, encode/decode Send-safe, identity map per-call. Observability: encode returns (PropBlob, EncodeStats{nodes,refs,bytes,max_depth}) behind feature="stats", trace serialize.encode{schema,bytes}. Harness: tests/{roundtrip.rs (proptest arbitrary→encode→decode→struct-eq), cycles.rs, version_skew.rs} + CI cargo build --target wasm32 -p isle-serialize (no_std/wasm parity).

5.6 Pitfalls

  • Owner-not-set dedup bug: keying shared chunks by a single "owner" root, not the full reaching-root set → duplication when 3+ roots fan in; fix = set key, assert |distinct keys|==|chunks|. Diamond double-count: DFS w/o a visited set re-walks shared subtrees → inflated ref-count → false "shared"; fix memoized reachability bitsets (ref-count ≤ root count). Module vs chunk cycle: a module DAG can still yield a chunk cycle if hoisting mis-routes edges → run cycle check twice (steps 2+6), emit SCC members.
  • HashMap-iteration non-determinism: chunk ids drift → broken integrity/golden tests; fix BTreeMap + sorted reaching-set keys, never HashMap for id alloc. Integrity over pre-transpile bytes: hash the graph-input content_hash now; Phase 12 re-hashes emitted chunk bytes (documented). Island root not in entries: a transitively-reachable client: module → silently un-chunked; scan ALL modules for is_island_root, warn on orphans.

5.7 Performance Concerns

  • JS shipped zero (build-time host tool); win measured downstream as chunk count == island count (+ shared), not page size. Tail: all-shared graph (every module reaches every root) → one giant shared chunk, O(R·V) compares; cap via early-exit when reaching-set == full root set (sorted-key alloc adds O(C log C), negligible).

19. Phase 7 — Hydration core (DOM adoption)

7.1 Objectives

  • hydrate_island(marker: &IslandMarker) -> Result<IslandHandle, HydrateError> in isle-runtime (module hydrate): adopt existing SSR DOM, never re-render — walk template/vdom in lockstep against SSR nodes, bind listeners + reactive bindings without node replacement (no createElement/replaceChild on the adopted subtree); mount island Scope (client mode → effects run), call Adapter.mount/Island.hydrate, return a droppable IslandHandle.     fn add_listener(&self, cb: TriggerId, el: DomEl, events: &[String]); // pre-hydration capture listeners

}
pub struct HydrationScheduler { hooks: Rc<dyn HostHooks>, queue: BinaryHeap<Pending>,

struct Pending { prio: u8, id: IslandId }                 // Ord by (prio, IslandId) — deterministic tie-break

Registration algorithm (boot → after marker scan & registry build):

  1. Per island, read data-strategy; for Only → enqueue immediately at prio=Load, skip adoption (set only=true).
  2. Load → enqueue at boot (prio=0). Idle → request_idle(timeout=200ms) (prio=3). Visible → observe_visible(root_margin) (prio=2). Media → match_media(query); if already matches enqueue now else arm change listener (prio=2). Interaction → add_listener(events), store the captured event for replay (prio=1).
  3. Trigger callback → mark_ready(IslandId) → push Pending → hooks.cancel(trigger) (one-shot) → drain via driver.

Driver (yield.rs): pop highest-prio Pending; hydrated.contains(id) → skip (idempotent), else hydrate_island(marker) (Phase 7) + set bit; after each island, now_ms()-slice_start > BUDGET_MS (5ms) → yield_to_main, resume next microtask (long tasks ≤ 5 ms). Interaction replay: a capture-phase listener records (type, target_path, key/button); first event → mark_ready (prio bumped to 0, user waiting) → after hydrate, synthesize + dispatch the stored event into the adopted DOM (project 261 model) so the click/keypress isn't lost.

21. Phase 9 — Lazy chunk loading and error isolation

9.1 Objectives

  • Every strategy trigger drives a lazy/dynamic import of the island's chunk (total JS executed ∝ hydrated islands, not page size); dedup — a chunk shared by ≥2 islands loads once, concurrent triggers share one in-flight promise. Decode props via decode then mount via Adapter.mount; any error CONFINED to a per-island error boundary so siblings + static page survive.
  • Load-failure: retry with backoff → fallback (placeholder/SSR HTML retained). Emit a hydration lifecycle event stream (scheduled→chunk-loaded→decoded→mounted | failed) for isle-cli trace/observability.
  • Constraints introduced: loader shim stays < 2 KB; chunk import never blocks the main thread synchronously; one island's failure costs O(1) (no cascade).

9.2 Detailed Implementation Steps

Theory anchors: §6.5/§6.9 (per-island isolation; lazy by default); ADR-15 (per-island failure containment); INV-9 (error confinement, no cross-contamination); MM10 (a broken island becomes a non-interactive island, not a broken page); Threat T3 / Failure F2 (chunk integrity + load failure).

// events.rs

Algorithm hydrate_island(marker):

  1. parse marker -> ChunkRef, data-props, AdapterId; emit Scheduled.
  2. loader.load(deps then chunk) (dedup); ChunkLoaded. On reject -> retry path (9.2 backoff).
  3. decode(PropBlob) -> PropValue; PropsDecoded. Decode err -> PropDecodeFailed.
  4. inside ErrorBoundary::run (catches wasm panic via catch_unwind/JS try): Adapter.mount(el, comp, &props) -> IslandHandle; Mounted.
  5. any err -> boundary logs (IslandId, HydrateError), emits Failed, leaves SSR DOM intact, marks marker data-isle-state="failed".
  • Backoff: delay = min(base*2^n, cap) with base=200 ms, cap=2 s, 3 attempts, ±20% jitter; only retry transient (ChunkLoadFailed), never PropDecodeFailed/DomMismatch. After last attempt -> FellBack (Visible/Idle keep static HTML; Only shows fallback slot).
  • Sync: cache mutated only on the single wasm thread (no locks); shared future cloned for concurrent waiters.
  • Observability: every step -> EventSink; boot installs a ring-buffer sink, isle-cli trace drains it.

  • Dedup race (two triggers before cache insert → double import, insert-after-await): insert Loading(shared) BEFORE awaiting (fetch count in network log). Deserialization & XSS analysis (deep dive)

  • PropBlob format (isle-serialize): version:u16 | tag-prefixed values; every Str/Bytes/Array/Object carries a varint length validated before allocation; Ref(u32) indices bounds-checked against the already-decoded table → acyclic-by-construction on the wire (a forged back-ref can't build an infinite structure). No opcode/function/class tag exists in the grammar → decode is provably non-Turing-complete. Props can't become code: decode: PropBlob → Result<PropValue, HydrateError> returns inert data, consumed only by Island::hydrate(el, &PropValue)/Adapter::mount (field reads); no path from PropValue → script, the only executable bytes are integrity-checked chunks (T3).
  • XSS containment: Html(escaped buffer) is the sole SSR markup channel, escaped on construct → a prop "<script>" round-trips as text, never a tag. IslandMarker attrs (data-isle-id/-strategy/-chunk/-props/-adapter) attribute-escaped; data-chunk URLs scheme-allowlisted (https/relative only — no javascript:/data:).

Compatibility Guarantees

Primary compatibility surfaces (semver-governed): Component/Island/Adapter traits (isle-core), Manifest+IslandEntry+ChunkEntry, the IslandMarker DOM format, the PropBlob wire format (isle-serialize), HydrationStrategy. The marker + blob are a versioned wire format spanning BUILD→SSR→runtime; a mismatched runtime refuses to hydrate (returns HydrateError::MarkerMalformed/PropDecodeFailed) rather than corrupt the DOM.

Versioned surfaces & gates

Surface Version field Bump on Mismatch behavior

Crate API SemVer (Cargo) per rules below compile-time

SemVer rules (per isle-* crate)

  • Major: remove/rename a trait method (Component::render/Island::hydrate/Adapter::mount), change a signature, remove a HydrationStrategy/PropValue/error variant, change PropBlob/marker/Manifest layout incompatibly. Minor: add a #[non_exhaustive] enum variant, defaulted trait method, additive IslandEntry/ChunkEntry/Manifest field (ver-bumped), new Adapter impl. Patch: impl-internal (chunking heuristic, scheduler tuning, escaping perf), no surface change. Workspace crates version in lockstep major (shared isle-core types); minor/patch independent.

#[non_exhaustive] on: HydrationStrategy, PropValue, BuildError, HydrateError, Manifest/IslandEntry/ChunkEntry → external match/struct-literal must have wildcard, so adding variants/fields is minor not major.

Adding a new strategy without breaking

New HydrationStrategy variant (e.g. Hover) = minor (enum is #[non_exhaustive]); requires Manifest.schema_ver bump. Old runtime meets unknown strategy in marker → unknown ⇒ treat as Load fallback OR static (configurable), logged — never crash. Trigger registration in HydrationScheduler is table-driven: unknown strategy id → no trigger registered, island stays static.

MSRV policy

MSRV = Rust 1.78, edition 2021. MSRV raise = minor bump, documented in CHANGELOG. CI gates on 1.78 + stable + nightly (wasm32). wasm-bindgen/web-sys/js-sys pinned to a tested range (isle-runtime); their bump ⇒ minor. No nightly-only features in published crates.

Adapter API stability

Adapter trait (id, mount) is frozen across a major; AdapterId namespaced (reverse-DNS-ish string). New adapter capabilities added via new defaulted methods (minor), never by changing mount. IslandHandle is opaque (no field stability promised). Reference signals adapter is versioned with isle-signal; third-party adapters depend only on isle-core.

Differential parity (vs pinned Astro)

Parity is a shape, not byte-identity: pinned Astro reference = astro@X.Y. We assert marker semantics map 1:1 — our data-strategy∈{load,idle,visible,media,interaction,only} ↔ Astro client:*; data-props ⊇ Astro's serialized props (superset incl. Ref/Date/Bytes). Astro version pin lives in conformance fixtures (Phase 13, ## 25); Astro upgrade that diverges → fixture update, NOT a semver event for isle-*.

Chunk-hash cache-busting & rolling deploy

  • Chunk URLs content-hashed (ChunkEntry.url=chunk.<integrity>.wasm/.js, integrity=SRI), immutable cache (Cache-Control: immutable), Manifest short-TTL/no-cache. Stale-HTML hazard (cached old SSR HTML + CDN now serving new chunks): Manifest.schema_ver + per-marker data-isle-fmt pin the page to a compatible runtime, mismatch ⇒ degrade to static + soft-reload prompt — never load an incompatible chunk into stale markers.
  • Rolling deploy: serve N + N+1 chunk sets simultaneously (content-hash names never collide), old HTML resolves old hashed chunks until TTL lapses; version pinning makes a request's HTML+Manifest+runtime a coherent triple. Determinism: identical module graph ⇒ identical ChunkRef + hashes ⇒ stable cache keys (no spurious bust).

Manifest / chunk-stream growth under churn

  • Manifest size = O(I + C); each IslandEntry=chunk+strategy+SchemaId+integrity, each ChunkEntry=url+deps+bytes+integrity. New islands add islands not chunks if deps shared.
  • Code churn → re-hash changed chunks only (content-addressed integrity); unchanged chunks keep URL → client cache hits survive deploys. Shared-chunk dedup keeps C sublinear in I as the dep graph saturates.

Mental Models & First Principles

  • MM1 — Hydration is adoption, not creation. The server already built the DOM; the client only attaches behavior to nodes it did not create. Predicts: any createElement/innerHTML= on an island root is a bug, not an optimization. Without it: "re-render to be safe" → flash, lost focus/scroll, doubled paint, DomMismatch masked not surfaced. Applied: §6.2, §8.7, Phase 7 (## 19).
  • MM2 — Props are data; chunks are code; the two never cross the seam. decode(PropBlob)→PropValue is a total parser yielding inert values; the only executable bytes arrive as integrity-checked chunks. Predicts: a malicious prop is at worst wrong data in one island, never code execution. Without it: eval/JSON-with-functions → RCE. Applied: §8.3, Threat Model T1/T2/T9, Phase 3 (## 15).
  • MM3 — One type definition, two compile targets, drift impossible. Encoder (std) and decoder (wasm) agree by sharing one PropValue/PropBlob type, not by testing. Predicts: SSR/client prop mismatch is a compile error, not a runtime surprise; divergence can only come from nondeterministic render, never the wire. Without it (two hand-kept schemas): silent prop corruption fuzzing barely catches. Applied: §6.1, ADR-04, INV-3/INV-4, Phase 1/3 (## 13/## 15).
  • MM4 — JS executed is a function of triggered islands, not page bytes. Cost = Σ over islands whose strategy fired, each paying decode+adopt+mount. Predicts: a 100 KB article with one client:load button costs one chunk; islanding the layout wrapper silently reintroduces whole-page hydration. Without it: every interactive bit becomes client:load and TTI collapses to a monolith's. Applied: §2.2, §6.3/§6.4, INV-5, Scalability Analysis.
  • MM5 — The main thread is the one true scheduler; the network is concurrent, the CPU is not. Chunk fetches overlap; decode/adopt/mount are serial main-thread work. Predicts: a blocking sweep janks input even with every chunk cached; the win is yielding between islands + deferring untriggered ones, not parallelism. Without it: a tight for island { hydrate() } ships 200 ms long tasks. Applied: §6.7, INV-11, Phase 8 (## 20).
  • MM6 — A deferred island still owes the user their first interaction. "Hydrate later" must not "drop the click that happened before hydration": a capture-phase listener records the event, hydrates, then replays it into the adopted tree. Predicts: Interaction needs a pre-hydration listener + replay + INV-2 idempotence against double-apply. Without it: the first click is silently lost — a defect that throws no error. Applied: §6.10, INV-10, ADR-16, Phase 11 (## 23).
  • MM7 — TTFB belongs to the shell; data latency belongs to the island. Streaming decouples them: flush head+bootstrap immediately, placeholder each async-data island, late-insert+swap on resolve. Predicts: one slow source delays only its own swap, never first paint; buffering the page ties TTFB to max(data_latency). Without it: in-order streaming gates the first byte on the slowest island. Applied: §6.12, §8.6, ADR-13, Phase 10 (## 22).
  • MM8 — A shared dependency is one node with two parents, not two copies. A module's chunk home = its set of reaching island roots, so a module used by ≥2 islands hoists to one shared chunk loaded once. Predicts: dedup keys on the reaching-set, not a single owner; a cycle in the chunk DAG has no safe load order → CycleInChunkGraph. Without it: key-by-"first owner" duplicates 3-way deps, or ships a load deadlock. Applied: §8.5, INV-6/INV-7, ADR-11, Phase 5 (## 17).
  • MM9 — Determinism is the precondition for adoption; effects are the leak. Adoption works only if the client's pre-effect render equals the SSR DOM byte-for-structure; SSR thus runs effects in no-op mode and never touches wall-clock/RNG/window. Predicts: any Date.now()/Math.random()/locale branch in render seeds a DomMismatch cascade; the cure is serialize-the-value-as-a-prop. Without it: SSR≠client intermittently → "works on my machine" hydration bugs. Applied: §6.6, INV-1/INV-8, Failure F1/F9.
  • MM10 — Isolation turns "a broken island" into "a non-interactive island." Each island hydrates in its own error boundary + Scope; the static SSR HTML is the recovery floor. Predicts: containment wraps decode+mount (incl. catch_unwind across the wasm task); the worst case is "static, not blank." Without it: one island's panic aborts boot and every island below stays dead. Applied: §6.5, INV-9, ADR-15, Phase 9 (## 21).

Qwik. The fundamental contrast (P3): resumes rather than hydrates — serializes execution state + listeners into HTML so the client "wakes up" where the server left off, no hydration walk. Marko. Deno Fresh. A Preact islands framework where islands/ is a literal directory convention, everything else zero-JS SSR, no dev build step. Back-of-Envelope Capacity Model

The numbers an expert computes before designing, each derived step-by-step from the System Constraints (§4). Formula shown; inputs cite §4.

  • B1 — Client JS before any island hydrates. shim + runtime wasm = 2 KB + 60 KB (§4.1) = 62 KB gz, loaded once and cached. A static (zero-island) route fetches 0 KB (§4.1, no shim injected). Implication: the fixed cost is one-time; per-route marginal JS is island chunks only.
  • B2 — Marginal bytes per interactive island. per-island chunk avg ≤ 15 KB (§4.1) + PropBlob ≤ 16 KB (§4.1) embedded in HTML. So N islands add ≈ N × 15 KB JS (minus shared-dep dedup) + ≤ N × 16 KB HTML. A 10-island page: ≈ 150 KB chunk JS (pre-dedup) + ≤ 160 KB props in markup. Implication: prop size, not chunk count, can dominate HTML weight → §6.8 prop minimization matters.
  • B3 — Page interactive-JS ceiling at the island cap. max islands/page = 256 (§4.6) × 15 KB avg chunk = 3.84 MB JS if all hydrate eagerly — which is why strategy-gating (§6.4) and the ≤ 6 concurrent-load cap (Threat Model hard caps) exist: only triggered islands pay. Implication: the cap protects the main thread, not the network.
  • B4 — Hydration latency budget per island. cold path < 50 ms p50 = chunk import (network) + decode < 1 ms (16 KB blob, §4.2) + adopt + mount. With the 5 ms main-thread slice (§4.3), an island's CPU share is decode + adopt + mount ≈ ≤ 5 ms; the rest is network. Implication: to hit < 50 ms p50 the chunk must be small enough to arrive in ~45 ms on the target link — reinforces the 25 KB chunk cap (§4.1).
  • B5 — Long-task safety for a many-island page. budget = 5 ms/slice, target 0 tasks > 50 ms (§4.3). At ≤ 5 ms CPU/island, the scheduler can hydrate ⌊50/5⌋ = 10 islands per 50 ms window without a single long task — if it yields between them. Implication: BUDGET_MS = 5 (Phase 8) is derived, not arbitrary; a 0 ms budget would serialize to one-island-per-task and balloon TTI.
  • B6 — SSR throughput vs island count. ≥ 5 000 pages/s for a 50-island page on 1 vCPU (§4.4) ⇒ ≈ 200 µs/page ⇒ ≈ 4 µs of render+marker+encode work per island. Implication: marker emission and encode must stay O(prop nodes) with no per-island heap churn (§4.4) or throughput falls below target.
  • B7 — Streaming memory under backpressure. SSR streaming hwm ≤ 256 KB (§4.7) and the design holds ≤ 1 resolved-island buffer per pending placeholder (Phase 10). At ≤ 16 KB props + island HTML per buffer, 256 KB / ~20 KB ≈ 12 concurrently-pending async islands fit before backpressure stalls the producer. Implication: pages with > ~12 simultaneous slow data sources need data batching, not more buffer.
  • B8 — wasm steady-state heap vs live islands. wasm heap ≤ 8 MB steady (§4.7); per-island Scope arena ≤ 32 KB (§4.7). So 8 MB / 32 KB = 256 live hydrated islands fit in the steady budget — exactly matching the 256 islands/page cap (§4.6). Implication: the memory budget and the island cap are co-designed; dropping an IslandHandle (dispose) is what keeps heap ∝ live islands, not visited markers.
  • B9 — Chunk cache turnover. decoded-module LRU ≤ 4 MB (§4.7). At ~15 KB/chunk that caches ≈ 270 distinct chunks before eviction — more than the 256-island cap, so a single page never thrashes its own chunk cache. Implication: eviction only matters across SPA navigations, not within one page.
  • B10 — Build time vs module count. build_graph ≤ 50 ms / 1 000 modules, O(N+E) (§4.5), and reachability is O(R·(V+E)) (Scalability). For R=50 islands, V=1 000 modules: 50 × (1 000 + E) bitset ops — at ~ns/op this stays well under the 50 ms target as long as the dep graph isn't near-complete. Implication: the all-shared pathological graph (every module reaches every root) is the only case that approaches quadratic — capped by early-exit (§5.7).
  • B11 — Prop-blob DoS ceiling. max PropBlob 64 KB (§4.6) × 256 islands = 16 MB worst-case props in one page's HTML before caps fire. Against the streaming hwm (B7) this confirms props must be capped per-island (MaxPropBlob → BuildError) or a single page could blow the SSR buffer. Implication: the 64 KB hard cap (§4.6) is the load-bearing DoS guard, not the 16 KB soft target.
  • B12 — Interaction replay queue bound. max replay queue/island = 32 events (§4.6). A user mashing a not-yet-hydrated button at ~10 events/s saturates the queue in ~3.2 s — beyond the < 50 ms perceived interaction target (Performance Engineering), so in practice replay holds 1–2 events and the cap only matters under pathological input (drop-oldest). Implication: the queue is a safety bound, not a steady-state structure.

Alternative Architectures (Roads Not Taken)

Three fundamentally different approaches to the same problem — not parameter tweaks. Each: sketch, winning regime, real system, why rejected here.

ALT-1 — Resumability (no hydration, serialize execution state).

  BUILD/SSR                          CLIENT
  render + serialize listeners,      tiny global loader (no per-island
  closures, reactive graph into  →   hydration walk); on first event,
  HTML attributes (qwik/json)        deserialize ONLY the needed state
                                     + handler, run it, "resume"
  no client hydration step           JS executed ∝ interactions, not islands

Regime: very large, mostly-idle apps where even per-island hydration (decode+adopt+mount over every visible island) is too much upfront CPU — resumability defers to the individual listener, paying nothing until interaction. Real system: Qwik (resumability; Hevery et al.). Rejected: heavier, more invasive serialization (must serialize closures + reactive graph + listener wiring, not just props), constrains authoring, and sidesteps the very thing this blueprint teaches — adoption + scheduling + replay. We borrow its "never lose the first event" lesson for Interaction (§6.10) without its model.

ALT-2 — Full-page hydration with selective/progressive priority (one app, prioritized).

  SSR whole app → HTML              CLIENT
  one client bundle (the whole  →   hydrate the entire tree, but in
  component tree)                    PRIORITY order: visible/interacted
  one root, one reconciler          first, rest progressively; Suspense
                                     boundaries gate streaming
  JS shipped ∝ app size             JS executed ∝ app size (just reordered)

Regime: a genuinely app-like surface (dashboard, editor) where most of the page is interactive anyway — islanding buys little and one coherent tree + shared state beats a bus across isolated islands. Real system: React 18 Server Components + selective/progressive hydration (Next.js App Router). Rejected: ships+executes JS proportional to app size, not interactive-island count — violating the islands thesis (§2.2, MM4); the win metric is minimum JS executed, unreachable by a single-tree model on content-heavy pages. Cited as contrast (P8); informs out-of-order streaming (Phase 10 ## 22).

ALT-3 — Compiler-inferred islands (no author directives).

  BUILD (compiler)                   SSR + CLIENT
  static analysis of components:     server renders all; client ships JS
  which are stateful / interactive →  ONLY for compiler-flagged stateful
  auto-mark island boundaries        subtrees; boundaries are inferred,
  (no client: directives)            not authored

Regime: teams that should never reason about hydration boundaries — the compiler infers what's interactive from the code, killing "I forgot client:" / "I islanded the layout" mistakes. Real system: Marko (compiler-driven automatic partial hydration, eBay). Rejected: inference makes hydration timing invisible/un-tunable, whereas this design makes strategy a first-class data-carried property (HydrationStrategy in marker + Manifest, §6.4) so an operator moves an island Load→Visible without touching code; explicit directives also make the differential-vs-Astro oracle (ADR-23) meaningful. We keep build-time island-root detection (Phase 5 ## 17) but key it on explicit client: directives.

Glossary

Terms are normative; definitions bind the rest of this blueprint. Crate/type names match the canonical spine exactly. "(contrast)" marks a concept we deliberately do NOT implement, cited only for positioning.

Term Definition (implementation-relevant)
island An interactive component subtree marked with a client: directive; its own IslandId, chunk, HydrationStrategy, serialized props, IslandMarker. Everything outside any island is static HTML shipped with ZERO JS.
islands architecture Page-construction model: mostly-static SSR HTML + a sparse set of independently-hydrating islands. Total JS executed scales with island count, not page size. Refs: Astro, patterns.dev (Jason Miller).
partial / incremental / progressive hydration Hydrating islands selectively and over time rather than the whole page at once. "Partial" = subset of DOM; "incremental/progressive" = staggered per strategy/priority. Our model is all three.
hydration Attaching listeners + reactive bindings to existing SSR DOM so it becomes interactive. In this system hydration = ADOPTION (see DOM adoption), never re-render.
resumability (contrast) Qwik's alternative: serialize execution state so the client resumes with near-zero upfront JS, no hydration walk. We do NOT implement it; we hydrate. Cited for contrast only.
SSR Server-Side Rendering: isle-ssr renders a Component tree to HTML (render_to_string / render_streaming) per request, with effects in no-op mode.
CSR Client-Side Rendering: browser builds DOM from scratch. Only HydrationStrategy::Only islands are pure CSR; the rest are SSR-then-hydrated.
hydration strategy HydrationStrategy enum deciding WHEN/WHETHER an island hydrates: Load, Idle, Visible{root_margin}, Media{query}, Interaction{events}, Only, Never. Travels in the marker as data-strategy.
client: directive Author-facing annotation (e.g. client:load) on a component that (a) marks a Module as is_island_root at build, (b) maps to a HydrationStrategy. Bad/unknown directive → BuildError::BadDirective.
client:load Load: hydrate immediately on runtime boot. Highest priority; for above-the-fold interactivity.
client:idle Idle: hydrate via requestIdleCallback (with setTimeout fallback). Deferred, non-blocking.
client:visible Visible{root_margin}: hydrate when the island intersects the viewport via IntersectionObserver(root_margin).
client:media Media{query}: hydrate when matchMedia(query) matches (e.g. desktop-only widgets).
client:interaction Interaction{events}: pre-hydration listener for named events; on first event, hydrate THEN replay that event into the island.
client:only Only: no SSR HTML emitted; client renders from scratch (CSR). No DOM adoption, no mismatch possible.
island marker / boundary IslandMarker: DOM boundary (<isle-island> custom element OR comment pair) carrying data-isle-id, data-strategy, data-chunk, data-props, data-adapter. The sole SSR→client handoff per island.
props serialization Converting an island's props to/from a transport form across the SSR→client boundary via isle-serialize: SSR encode → decode client. Same crate both sides ⇒ no type drift.
structured clone The HTML structured-clone value model that PropValue mirrors: primitives, arrays, objects, bytes, Date, plus shared/cyclic Ref. Bounds what may be a prop.
PropValue isle-serialize enum: Null/Bool/Int/Float/Str/Bytes/Array/Object/Ref/Date. The decoded, structured prop value mounted into an island.
PropBlob { version: u16, bytes: Vec<u8> }: the compact versioned wire form of encoded props embedded in data-props. Version mismatch → HydrateError::PropDecodeFailed.
chunk Chunk { id: ChunkRef, modules, deps }: a separately loadable JS/WASM unit. Each island root's dependency closure → one chunk; shared modules → a shared chunk.
chunk graph ChunkGraph { modules, chunks }: build-time DAG mapping modules→chunks and chunk→chunk deps. A cycle → BuildError::CycleInChunkGraph.
module graph Vec<Module> where Module { id, deps, is_island_root }: the import graph from which the chunk graph is computed by build_graph.
Manifest Manifest { islands: Map<IslandId,IslandEntry>, chunks: Map<ChunkRef,ChunkEntry> }: build output consumed by SSR + runtime boot. Maps island → chunk(+deps), strategy, prop schema, integrity.
integrity hash IntegrityRef-style content hash (ChunkEntry.integrity, IslandEntry.integrity) for subresource-integrity verification of a lazily imported chunk.
lazy / dynamic import Runtime-time import() of an island's chunk, triggered only when its strategy fires. In-flight loads are deduped; failure → HydrateError::ChunkLoadFailed (retry/fallback).
code splitting Partitioning the module graph into per-island chunks so the client downloads only the islands it needs. The core build deliverable of isle-graph.
tree shaking Eliminating modules unreachable from any island root before chunk assignment. Reachability is the dependency-closure walk; dead modules are dropped.
dependency closure Transitive set of modules reachable from one island root; becomes (minus shared/hoisted modules) that island's chunk.
shared-chunk dedup Hoisting any module in ≥2 islands' closures into a separate shared chunk listed in ChunkEntry.deps, so it loads once and is cached.
DOM adoption Hydration mechanism: walk the island's template/vdom against the EXISTING SSR DOM, attaching listeners + bindings WITHOUT replacing nodes. The defining "hydrate not re-render" invariant.
reconciliation The diff/match step inside adoption (and later updates) aligning expected vdom to actual DOM nodes. During hydration it must find a match for every node or raise DomMismatch.
hydration mismatch / DomMismatch HydrateError::DomMismatch: SSR markup ≠ client expectation during adoption. Gravest correctness bug; dev = warn + client-render fallback, prod = log + contain (island isolated).
fine-grained reactivity isle-signal model where updates propagate per dependency (signal→effect/memo) rather than re-rendering a component tree. Minimizes post-hydration work.
Signal Signal<T>: readable/writable reactive cell tracking its dependents; set schedules dependent effects/memos.
Effect Effect: side-effecting reaction re-run on dependency change. No-op in SSR mode; runs only client-side after hydration.
Memo Memo<T>: cached derived value recomputed only when its tracked deps change.
Scope Scope: arena owning an island's reactive nodes (signals/effects/memos); dropped to dispose. One per hydrated island, held by its IslandHandle.
Store Store: cross-island shared, keyed signals — the bus letting separately-hydrated islands share/observe state.
HydrationScheduler isle-runtime priority queue + per-strategy trigger registration deciding hydration order and firing Load/Idle/Visible/Media/Interaction triggers.
requestIdleCallback Browser API backing Idle; hydrate during idle time, setTimeout fallback where unsupported.
IntersectionObserver Browser API backing Visible{root_margin}; fires hydration when the island scrolls into the margin-expanded viewport.
matchMedia Browser API backing Media{query}; hydrate when the media query matches (and may defer until then).
event delegation / replay Interaction mechanism: one lightweight pre-hydration listener for named events; first event triggers hydration, then is REPLAYED into the now-live island so no interaction is lost.
error isolation / error boundary Each island hydrates inside its own boundary + Scope; a chunk-load fail, prop-decode fail, or mount panic is caught, logged, and confined — other islands and the static page survive.
streaming SSR render_streaming writing HTML incrementally through an HtmlSink (push/flush) so the browser receives + paints the shell before the full tree is rendered. Improves TTFB.
out-of-order streaming Emit a placeholder for an async-data island immediately, flush head + bootstrap early, then stream the island's HTML + a swap marker once data resolves. Backpressure via HtmlSink.
placeholder The temporary shell node emitted for a not-yet-resolved out-of-order island, later replaced by a late-inserted real island fragment + swap script.
time-to-interactive (TTI) Primary perf target: time until islands are hydrated and responsive. Islands minimize it by shipping/executing JS only per fired strategy. Tracked in Phase 13 benchmarks.
Adapter Adapter trait (id, mount(el, comp, props) -> IslandHandle) abstracting the UI framework; the bundled reference adapter drives isle-signal. Unknown id → HydrateError::AdapterMissing / BuildError::UnknownAdapter.
IslandHandle IslandHandle: owns a hydrated island's Scope + listeners; dropping it disposes the island (unmount). Returned by hydrate/Adapter::mount.
runtime bootstrap shim The tiny (<2 KB) JS loader inlined by SSR that calls boot(manifest), loads the wasm isle-runtime, and hands off marker scanning + scheduling.
