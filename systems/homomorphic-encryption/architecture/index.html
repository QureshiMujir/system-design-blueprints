3.2 Subsystem Descriptions

he-bignum — The arithmetic floor. Big-integer modular operations: modexp (square-and-multiply, sliding-window), modinv (extended Euclid / Fermat), gcd/lcm, CRT combine, and reduction contexts — Montgomery (for repeated mul mod a fixed odd modulus, as in Paillier's Z_{n²}) and Barrett (for arbitrary modulus reduction). Either hand-built or a thin wrapper over crypto-bigint/num-bigint (ADR 2). Provides constant-time variants (subtle) for secret-dependent paths (e.g. Paillier decryption). No scheme logic.

he-numtheory — Number theory on top of bignum: Miller–Rabin probabilistic primality (with a configurable round count → error ≤ 4⁻ᵏ), optional Baillie–PSW, safe-prime generation (p prime and (p−1)/2 prime, required for Paillier's structure), Jacobi/Legendre symbols, uniform sampling of Z_n* / coprime elements, and the L-function L(u)=(u−1)/n used in Paillier decryption. Pure number theory; no NTT/lattice content.

he-rng — Randomness. A CSPRNG abstraction seeded from the OS (getrandom → ChaCha20), rejection sampling for uniform integers in a range (no modulo bias), a discrete Gaussian sampler (cumulative-distribution-table or Karney) for RLWE error, and a ternary sampler ({−1,0,1}) for secret/error distributions. A strictly separated --insecure-deterministic mode (fixed seed) exists only for reproducible tests/fixtures and is never used for real keys (I11).

he-paillier — The PHE scheme. Keygen: choose safe primes p,q, n=pq, λ=lcm(p−1,q−1), generator g (often n+1), μ=(L(g^λ mod n²))⁻¹ mod n. Encrypt E(m)=g^m·rⁿ mod n² with fresh r∈Z_n*. Decrypt m=L(c^λ mod n²)·μ mod n. Homomorphic add = ciphertext multiply mod n²; plaintext-mul = ciphertext exponentiation; re-randomization multiplies by r'ⁿ. Signed plaintexts via the [−n/2, n/2) convention. IND-CPA under DCRA.

he-ring — The polynomial ring R_q = Z_q[x]/(x^n+1), n a power of two. A Poly type (coefficient vector mod q), add/sub, negacyclic schoolbook multiply (the x^n=−1 wrap introduces sign flips), coefficient reduction, and sampling polynomials from uniform/Gaussian/ternary distributions into R_q. The schoolbook multiply is the correctness reference for the NTT path.

he-ntt — The negacyclic Number-Theoretic Transform: precomputed tables of a primitive 2n-th root of unity ψ mod each NTT prime (negacyclic via ψ twisting), forward NTT, inverse NTT (INTT, with n⁻¹ scaling), and pointwise multiply so that INTT(NTT(a)∘NTT(b)) = a·b in R_q. Montgomery-form butterflies (Cooley–Tukey forward, Gentleman–Sande inverse). Round-trip identity INTT∘NTT = id is the core invariant (I7).

he-rns — RNS/CRT representation. The ciphertext modulus q = q₀·q₁·…·q_{k−1} is a product of distinct NTT-friendly primes (qᵢ ≡ 1 mod 2n); a polynomial is stored as k independent residue polynomials, each with native-word coefficients, so all coefficient arithmetic is u64. Provides per-residue add/mul, base conversion (fast/approximate via floating or integer, plus an exact CRT reconstruction) used in BFV multiplication and mod-switching. RnsContext holds the moduli, NTT tables per prime, and precomputed CRT constants. The base-conversion correctness (I8) is the subtlest part of the system.

he-bfv — The leveled scheme. BfvParams fixes plaintext modulus t, ring degree n, and the modulus chain. SK keygen samples a ternary secret s; PK is (−(a·s+e), a). Relinearization keys and (deferred) Galois keys are encryptions of s²/permuted s under a special modulus. Encrypt: (c0,c1)=(Δ·m + a·s + e ... ) form (FV scaling Δ=⌊q/t⌋). Decrypt: ⌊(c0+c1·s) · t/q⌉ mod t. Add: componentwise. Multiply: tensor (c0,c1)⊗(c0',c1') → 3-component, scale by t/q, then relinearize the c2·s² term back to 2 components via the relin key, then optional mod-switch down the chain to control noise. Noise budget tracked via he-noise.

he-noise — The noise model. Closed-form (and empirical) bounds for fresh-encryption noise and the growth per add (additive), per mul (multiplicative + relin/mod-switch terms), and per mod-switch (reduction). Computes a noise budget in bits (log2(q/(2·‖noise‖))-style), exposes remaining_budget(ct), and the abort-before-exhaustion guard (I2/I3): refuse an operation that would drive the budget below the decryption-correctness threshold rather than silently returning garbage.

he-params — Parameter selection. Given a target multiplicative depth L and security level (128/192/256-bit), choose (n, q, t, σ): n a power of two large enough that RLWE at modulus q and error σ meets the security bound (per the LWE estimator's published tables, e.g. Albrecht et al.), q (a product of primes) large enough to hold L multiplications' noise, t the plaintext modulus (with t ≡ 1 mod 2n for batching). Validates the chosen params against tabulated attack costs and emits a parameter report.

he-encode — The encoding layer. Integer encoding (plaintext as a constant or base-t polynomial), batch encoding (CRT slots: when t ≡ 1 mod 2n, R_t factors into n slots, packing n integers into one plaintext for SIMD-style homomorphic ops), and scalar encoding. CKKS-style approximate/fixed-point encoding is explicitly out of scope (deferred).

he-cli — The driver. paillier subcommands (keygen/enc/dec/add/mul) and bfv subcommands (params/keygen/enc/dec/eval/noise). JSON I/O for keys and ciphertexts; bfv eval runs a small circuit description (a DAG of add/mul/scale) and reports the final noise budget; bfv noise prints remaining budget for a ciphertext.

8.2 Paillier Algebra

Z_{n²}* has order n·φ(n); with g=n+1, (n+1)^m = 1 + m·n mod n² (binomial), so L((n+1)^m mod n²)=m. Keygen, encrypt, decrypt (normative definitions, Paillier 1999):

Step Definition Note
Keygen — primes p,q two random safe primes (~bits/2 each) I6
Keygen — modulus n = p·q
Keygen — Carmichael value λ = lcm(p−1, q−1)
Keygen — generator g = n + 1 standard choice, ADR 3
Keygen — private multiplier μ = modinv(L(g^λ mod n²), n) L(u)=(u−1)/n
Keygen — output pk=(n,g), sk=(λ,μ)
Encrypt c = (g^m mod n²)·(r^n mod n²) mod n² m∈[0,n); fresh r=random in Z_n* (P4, I10)
Decrypt m = (L(c^λ mod n²)·μ) mod n constant-time exponentiation (I9)

Homomorphic operations:

Operation Ciphertext computation Plaintext effect
Add c1 * c2 mod n² m1 + m2 mod n (I4)
Add constant k c * g^k mod n² m + k
Multiply by scalar k c^k mod n² k·m
Re-randomize c * r'^n mod n² m (new randomness)

Signed integers: encode m∈(−n/2, n/2] as m mod n; decode > n/2 → m−n.

8.3 The Polynomial Ring R_q

R_q = Z_q[x]/(x^n+1), n=2^k. Multiplication is negacyclic convolution: (a·b)_k = Σ_{i+j=k} a_i b_j − Σ_{i+j=k+n} a_i b_j (the wrap is subtracted because x^n=−1). Schoolbook is O(n²); the NTT reduces it to O(n log n). Elements: ternary (secret), discrete-Gaussian (error), or uniform (mask a).

8.4 The Number-Theoretic Transform (NTT)

For an NTT prime qᵢ ≡ 1 mod 2n, let ω be a primitive n-th root and ψ a primitive 2n-th root (ψ²=ω). Negacyclic NTT pre-multiplies coefficients by powers of ψ so ordinary cyclic convolution computes the negacyclic product:

Step Formula Meaning
Forward NTT â_j = Σ_i (a_i · ψ^i) · ω^{ij} mod q twist + DFT (Longa & Naehrig 2016)
Pointwise multiply ĉ = â ∘ b̂ elementwise product in transformed domain
Inverse NTT c_k = n⁻¹ · ψ^{-k} · Σ_j ĉ_j · ω^{-kj} mod q DFT⁻¹ + untwist
Result c = a · b in R_q negacyclic convolution holds exactly (I7)

Forward via Cooley–Tukey (decimation-in-time), inverse via Gentleman–Sande, butterflies in Montgomery form. Bit-reversal permutation between natural/transformed order. Round-trip INTT(NTT(a))=a exactly (P5).

8.5 RNS / Double-CRT Representation

The coefficient modulus q = q₀·q₁·…·q_{k−1} (distinct primes, each ≡1 mod 2n). A polynomial is stored as k residue polys; coefficient x ↔ (x mod q₀, …, x mod q_{k−1}). Combined with the per-prime NTT, this is the double-CRT form: every coefficient op is a native u64 op, all multiplies are NTT-pointwise.

Operation Definition Meaning
To RNS to_rns(x) = (x mod q₀, …, x mod q_{k−1}) forward residue map
From RNS from_rns(residues) → x mod q exact CRT reconstruction (I8)
Base convert base_convert({mod q} → {mod q'}) fast (approximate, corrected) or exact CRT

Base conversion (changing the modulus set) underlies BFV multiply scaling and mod-switching; its correctness (I8) is the system's subtlest property.

8.6 BFV Scheme (FV Variant)

Δ=⌊q/t⌋. Secret s ternary. Public key (b,a)=(−(a·s+e), a), a uniform, e Gaussian.

Step Definition Note
Encrypt c0 = b·u + e0 + Δ·m (mod q); c1 = a·u + e1 (mod q) m∈R_t; fresh u ternary, e0,e1 Gaussian (P4)
Decrypt m = round((t/q)·(c0 + c1·s mod q)) mod t correct within budget (I1)
Add (c0+c0', c1+c1') noise adds (I5)
Multiply — tensor (d0,d1,d2) = (c0c0', c0c1'+c1c0', c1c1') pre-relinearization, 3 components
Multiply — scale + relin scale (d0,d1,d2) by t/q (round); relinearize d2 via relin key → (c0'',c1'') back to 2 components (ADR 14)
Mod-switch mod_switch(ct, q→q') = scale ct by q'/q (round) drops a prime, reduces noise

Relinearization: d2 would decrypt with s²; the relin key is an encryption of s² (in a decomposed/RNS basis to control noise), used to fold d2·s² back into a 2-component ciphertext. Mod-switch divides out a prime of q, shrinking both ciphertext and (proportionally less) noise → net budget gain that extends depth.

8.7 Noise Growth Model

Operation Noise effect (informal) Budget impact
Fresh encrypt ‖noise‖ ≈ Δ·(small) + Gaussian full budget (e.g. ~log2(q)−log2(t)−ε bits)
Add noises add (v1+v2) ~ −1 bit
Add plaintext small negligible
Multiply (pre-relin) noises multiply (≈ v·v'·n·t) large drop (~half remaining)
Relinearization additive key-switch noise small extra drop
Mod-switch noise scaled by q'/q + rounding net budget gain (extends depth)

he-noise computes budget_bits ≈ log2(q) − log2(2·t·‖noise‖) (scheme-specific constant); when a planned op's predicted post-budget < 0, abort (I3). Multiplicative depth L is "how many multiplies before budget hits 0", set by q (bigger → more depth) at fixed n, t.

8.8 Encoding and Batching

Encoding Mapping Use
Scalar/integer m → Δ·m constant poly (or base-t digits) single integer
Batch (CRT slots) when t≡1 mod 2n, R_t ≅ (Z_t)^n; pack n ints into n slots SIMD-style: one hom-op acts on all n slots
Signed m∈(−t/2,t/2] via centered representative signed arithmetic

Batch encode = inverse-NTT-like map over Z_t; decode = forward map. Add/mul on a batched ciphertext act slot-wise (componentwise on the n packed integers). CKKS-style approximate (reals) is deferred.

8.11 State / Lifecycle (BFV Ciphertext)

[encode] Plaintext(R_t) --enc--> BfvCt(level=top, 2 comp, full budget)
   --add--> BfvCt(2 comp, budget-1)
   --mul--> BfvCt(3 comp) --relin--> BfvCt(2 comp, budget-Δmul)
   --mod-switch--> BfvCt(2 comp, level-1, budget+gain)
   ... repeat until budget≈0 ...
   --dec--> Plaintext(R_t)   (correct iff budget>0, I1)

State transitions tracked in the ciphertext header (component count, level, noise estimate) for telemetry (P10) and the abort guard (I3).
