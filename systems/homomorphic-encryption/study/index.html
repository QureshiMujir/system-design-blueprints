Mental Models & First Principles

The compressed intuitions an expert carries into HE work. Each model states the insight, what it lets you predict, the bug class you write without it, and where this blueprint applies it.

MM1 — A ciphertext is a budget, not a value. Every RLWE ciphertext carries noise that grows with each operation; you are spending a finite noise budget, and (since bootstrapping is deferred) there is no refill. Predicts: depth is bounded; a circuit either fits the budget or it does not, set before keygen. Bug without it: designing an "unbounded" homomorphic loop that silently returns garbage past the budget. Applied: §8.7 (noise growth), Phase 9 (budget model), I1/I2/I3.

MM2 — Homomorphism is a ring homomorphism, so the map is the contract. Paillier sends plaintext + to ciphertext × (Dec(E(a)·E(b))=a+b); BFV preserves + and × within budget. Correctness is defined by these identities, never by the byte layout. Predicts: any kernel change is correct iff the identity still holds — so the identity is the test oracle. Bug without it: "optimizing" a kernel while breaking Dec(mul)=a·b and trusting unit tests that never check the identity. Applied: §8.2, P2, I4/I5, Phase 3 / Phase 8.

MM3 — The NTT is the modular FFT; multiply is pointwise in the frequency domain. Convolution (polynomial multiply) becomes elementwise multiply after an NTT, turning O(n²) schoolbook into O(n log n). Predicts: the NTT, not the multiply, dominates the BFV profile, and exact integer roots (not floats) keep it error-free. Bug without it: a missing n⁻¹ scale or a cyclic-instead-of-negacyclic twist that corrupts every product silently. Applied: §8.4, P5, I7, Phases 4–5.

MM4 — A big modulus is a tuple of small ones (RNS/CRT). A coefficient mod q=Πqᵢ is the same information as its residues (x mod q₀,…,x mod q_{k−1}); arithmetic is independent per residue, so every coefficient op is a native u64 multiply. Predicts: per-op cost and ciphertext size scale linearly in the limb count k, and limbs are embarrassingly parallel. Bug without it: treating base conversion as a no-op rather than the subtlest correctness trap in the system. Applied: §8.5, P6, I8, Phase 6.

MM5 — Multiplication is the expensive, noisy, structure-breaking op. Tensoring two 2-component ciphertexts yields a 3-component one whose c2 term needs s²; relinearization (key switching) folds it back to 2 components, and noise grows multiplicatively there. Predicts: depth, key sizes, and latency are all driven by multiply, not add — so add is "free," multiply is the budget line. Bug without it: forgetting relinearization and watching ciphertexts grow a component per multiply until decryption is impossible. Applied: §8.6, Phase 8, I5.

MM6 — Parameters are a trilemma: security ↔ depth ↔ performance. Bigger q buys depth but lowers security at fixed n, so n must grow, which slows everything. Predicts: you cannot have deep circuits, strong security, and small fast ciphertexts at once — pick the corner the workload needs. Bug without it: choosing q for depth and shipping sub-128-bit parameters without rechecking security. Applied: §4, Phase 9 (select iterates n until security holds), I12, ADR 16.

MM7 — Fresh randomness per encryption is what makes encryption encryption. Each Paillier r and each BFV (u,e) is drawn fresh; reuse makes equal plaintexts produce linkable ciphertexts and destroys IND-CPA. Predicts: deterministic encryption is trivially distinguishable, and a seeded RNG must never reach real keygen. Bug without it: a "cache the randomness" optimization that silently breaks semantic security. Applied: P4, P11, I10/I11, Phases 3 and 7.

MM8 — Exactness is a security property, not just a convenience. BFV decryption returns the plaintext with no residual noise; CKKS returns plaintext plus noise, and sharing those noisy decryptions leaks the key (Li & Micciancio 2021, the IND-CPA^D gap). Predicts: an approximate scheme needs noise-flooding before any decryption is disclosed; an exact scheme does not. Bug without it: deploying CKKS-style approximate HE and releasing decryptions, leaking the secret key. Applied: Failure Modes & Recovery, ADR 4, Alternative Architectures B, I1.

MM9 — Secret-dependent timing is a side channel; constant-time is mandatory on secret paths only. Decryption and keygen touch the secret (λ, s); branching or indexing on it leaks bits through timing. The bulk eval kernels (NTT/RNS over public ciphertexts) need no such protection. Predicts: exactly which paths must be branch-free, and where constant-time costs buy nothing. Bug without it: an early-exit or secret-indexed table in decrypt that recovers the key (the Brumley–Boneh 2003 attack class). Applied: P7, I9, Phase 11, ADR 13.

MM10 — Fail before you compute, not after. Composite "primes," insecure parameters, depth overflow, and parameter mismatch are all detectable before producing output; a half-valid key or over-budget circuit yields unfalsifiable garbage. Predicts: the right place for every guard is keygen/parameter/pre-op validation, and a refused op is a success while a garbage plaintext is a failure. Bug without it: discovering a composite modulus only by a wrong decryption in production. Applied: P9, I3/I6/I12, Phases 2 / 9 / 11.

Required reading (§5)

Books

  • Katz & Lindell — Introduction to Modern Cryptography (3e). Ch 11–13 (public-key, RSA, security definitions, IND-CPA). Extract: semantic security, reductions, the formal IND-CPA game used to argue both schemes. Applied: §6 P4, §Phase 11 (IND-CPA reductions in docs/threat-model.md).
  • Hoffstein, Pipher, Silverman — An Introduction to Mathematical Cryptography. Ch 2–3, 6–7 (modular arithmetic, lattices, lattice cryptography). Extract: number theory, lattice problems (SVP/CVP), LWE framing. Applied: §8.3 ring model, §Phase 4 (he-ring), §Phase 9 hardness framing.
  • Galbraith — Mathematics of Public Key Cryptography. Ch on integer factorization, RSA/Paillier algebra, lattices. Extract: DCRA, safe primes, group structure of Z_{n²}*. Applied: §8.2 Paillier algebra, §Phase 3 keygen/decrypt.
  • Menezes, van Oorschot, Vanstone — Handbook of Applied Cryptography. Ch 2 (number theory), Ch 4 (primality, Miller–Rabin), Ch 14 (efficient arithmetic, Montgomery). Extract: exact primality + modular-arithmetic algorithms. Applied: §Phase 1 (he-bignum algorithms), §Phase 2 (primality.rs).
  • Crandall & Pomerance — Prime Numbers: A Computational Perspective. Ch on primality and fast arithmetic. Extract: Miller–Rabin/Baillie–PSW, FFT/NTT multiplication. Applied: §Phase 2 (Baillie–PSW option), §Phase 5 (transform-based multiply background).
  • von zur Gathen & Gerhard — Modern Computer Algebra. Ch on FFT, fast multiplication, CRT. Extract: the NTT, negacyclic convolution, Chinese remaindering. Applied: §8.4–§8.5, §Phase 5 (NTT), §Phase 6 (CRT reconstruction).
  • Peikert — A Decade of Lattice Cryptography (monograph). Extract: LWE/RLWE definitions, hardness, error distributions, parameter intuition. Applied: §Phase 9 (he-params rationale), §Phase 11 (security analysis).
  • (Optional) Aumasson — Serious Cryptography. Ch on RSA and on "the future" (HE). Extract: practical pitfalls, side channels, why "don't roll your own crypto for production." Applied: §Phase 11 (constant-time discipline, "educational, not audited" boundary, P12).

Recommended Reading Order

  • Katz & Lindell Ch 11–13 + HAC Ch 2,4 before Phases 1–3 (bignum, primality, Paillier).
  • Paillier (1999) + Galbraith (Z_{n²}*) before Phase 3.
  • von zur Gathen Ch FFT/CRT + Longa–Naehrig before Phases 4–6 (ring, NTT, RNS).
  • Lyubashevsky–Peikert–Regev + Fan–Vercauteren before Phases 7–8 (BFV).
  • Bajard et al. + Halevi–Polyakov–Shoup before Phase 8 (RNS multiply).
  • Albrecht et al. + HE Standard before Phase 9 (parameters); Peikert monograph before Phase 11 (security).

Glossary · 34 terms · site-wide glossary

Homomorphic encryption (HE)
encryption permitting computation on ciphertexts that maps to computation on plaintexts
PHE / SHE / FHE
partially / somewhat / fully homomorphic encryption (one op / bounded ops / unbounded ops)
Paillier
additively-homomorphic public-key scheme over Z_{n²}* (DCRA)
DCRA
Decisional Composite Residuosity Assumption (Paillier's hardness)
Safe prime
prime p with (p−1)/2 also prime
L-function
L(u)=(u−1)/n, used in Paillier decryption
BFV
Brakerski–Fan–Vercauteren RLWE leveled scheme (integer-exact)
RLWE
Ring Learning With Errors; BFV's hardness assumption
Noise / error
the small random term in an RLWE ciphertext that grows with operations
Noise budget
bits of headroom before accumulated noise breaks decryption
Leveled FHE
bounded multiplicative depth without bootstrapping
Bootstrapping
homomorphically refreshing noise to enable unlimited depth (deferred)
Multiplicative depth L
number of sequential multiplications before noise exhausts the budget
R_q = Z_q[x]/(x^n+1)
the polynomial ring of BFV; n a power of two
Negacyclic convolution
polynomial multiply with x^n=−1 (sign-flipped wrap)
NTT / INTT
Number-Theoretic Transform; the modular FFT for O(n log n) poly-mul
Twiddle / root of unity
ψ (primitive 2n-th root) powers used in the NTT
RNS / CRT representation
a number stored as residues across coprime moduli (q=Πqᵢ)
Double-CRT
RNS residues each in NTT (evaluation) form — BFV's working layout
Base conversion
changing the modulus set of an RNS-represented value (exact or fast)
Δ = ⌊q/t⌋
the FV plaintext scaling factor
Plaintext modulus t
modulus of the message space R_t
Batching / CRT slots
packing n integers into one plaintext when t≡1 mod 2n
Relinearization
key-switching a 3-component product back to 2 components (folds s²)
Key switching
re-encrypting under a different/derived key using a switching key
Modulus switching
dividing out a modulus prime to reduce noise / extend depth
Relin / Galois key
switching keys for relinearization / slot rotations (Galois deferred)
IND-CPA
indistinguishability under chosen-plaintext attack (semantic security)
LWE estimator
tool/tables giving the concrete security (bits) of LWE/RLWE parameters
Montgomery reduction
division-free modular multiplication for a fixed modulus
Barrett reduction
modular reduction via a precomputed reciprocal
Discrete Gaussian
the error distribution sampled for RLWE noise
Ternary distribution
secret/error coefficients in {−1,0,1}
Constant-time
execution time independent of secret data (no timing leak)
