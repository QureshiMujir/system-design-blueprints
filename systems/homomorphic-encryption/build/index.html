⬜ Phase 1 — Big-integer modular arithmetic + Montgomery/Barrett

Objectives

Establish the arithmetic floor: modexp, modinv, gcd/lcm, CRT combine, and Montgomery + Barrett reduction contexts, on a vetted big-integer backend (ADR 2). Constant-time variants for secret-dependent modexp (I9). Everything above depends on this.

Deliverable

modexp/modinv/gcd/crt correct on test vectors; Montgomery mul/pow match schoolbook; Barrett reduces correctly; CT modexp matches non-CT result. cargo test -p he-bignum green.

Acceptance
  • modexp(g,e,m) matches a reference (Python pow) on 1000 random triples.
  • modinv(a,m)·a ≡ 1 mod m whenever gcd(a,m)=1; None otherwise.
  • Montgomery pow == modexp for fixed odd modulus.
  • CRT reconstructs the unique residue mod the product for coprime moduli.
  • CT modexp: no secret-dependent branch (audit) + equal output to plain.
Fixtures
Fixture Purpose Expected
bignum/modexp_vectors.json modexp reference matches
bignum/modinv_vectors.json inverse a·a⁻¹≡1 / None
bignum/montgomery_equiv.json REDC == schoolbook
bignum/crt_recon.json CRT unique residue
Pitfalls
  • Montgomery requires an odd modulus; Z_{n²} is odd (n odd) — assert.
  • n' computation (−n⁻¹ mod r) sign/width bugs corrupt every REDC silently.
  • Non-constant-time modexp leaks the exponent (secret λ) via timing; the CT path must be branch- and index-independent (I9).
  • CRT with non-coprime moduli is undefined; validate coprimality.

⬜ Phase 2 — Number theory: primality, safe primes, sampling

Objectives

Implement Miller–Rabin primality (configurable rounds, I6), safe-prime generation, uniform Z_n*/coprime sampling, Jacobi symbol, the L-function, and the CSPRNG + discrete-Gaussian + ternary samplers in he-rng — including the quarantined deterministic test mode (I11, P11).

Deliverable

Safe primes generated at 1024/1536 bits; Miller–Rabin matches a reference on known primes/composites; samplers produce correct distributions; deterministic mode reproducible and quarantined.

Acceptance
  • Miller–Rabin: 0 false negatives on known primes; composite-detection on Carmichael numbers; k-round error bound documented.
  • gen_safe_prime(bits): both p and (p−1)/2 pass primality; correct bit length.
  • Discrete Gaussian: empirical mean ≈ 0, std ≈ σ over 10⁶ samples (χ² within tolerance).
  • Uniform sampler: no modulo bias (statistical test).
  • DetRng refuses real keygen path; CSPRNG is default (I11).
Fixtures
Fixture Purpose Expected
numtheory/mr_known.json primality correct prime/composite verdicts
numtheory/carmichael.json strong pseudoprimes detected composite
rng/gaussian_stats.json distribution mean/std within tol
rng/det_quarantine.json I11 seeded keygen refused
Pitfalls
  • Too few Miller–Rabin rounds → composite accepted as prime → broken key (I6); default high k.
  • Modulo bias in naive rand()%n skews r; must use rejection sampling.
  • A biased/low-σ Gaussian weakens RLWE security; validate the sampler statistically.
  • Letting DetRng leak into real keygen makes "secret" keys public (I11) — structurally prevent.

⬜ Phase 3 — Paillier: keygen, encrypt, decrypt, homomorphic ops

Objectives

Implement the full Paillier PHE scheme: keygen (n=pq, λ, μ), encrypt (g^m r^n mod n², fresh r, I10/P4), decrypt (L-function, constant-time, I9/P7), homomorphic add (I4), plaintext-scalar multiply, re-randomization, and signed-integer encoding. First working homomorphic computation.

Deliverable

E(7)·E(5) decrypts to 12; E(6)^4→24; signed E(−3)·E(10)→7; re-randomized ciphertext decrypts unchanged but is byte-different. End-to-end he-cli paillier works.

Acceptance
  • Dec(E(m))=m for 1000 random m∈[0,n) at n=3072 bits (correctness, paillier/roundtrip.json).
  • Dec(E(a)·E(b))=a+b mod n (I4); Dec(E(a)^k)=k·a mod n (paillier/hom_add.json, paillier/scalar_mul.json).
  • Signed arithmetic correct across zero (paillier/signed.json).
  • Two encryptions of the same m differ (fresh r, I10); both decrypt to m (paillier/ind_cpa_distinct.json).
  • Decryption timing independent of key bits within a 5% coefficient-of-variation bound (CT audit + timing harness, I9).
Fixtures
Fixture Purpose Expected
paillier/roundtrip.json enc/dec Dec(E(m))=m
paillier/hom_add.json I4 a+b mod n
paillier/scalar_mul.json pt-mul k·a
paillier/signed.json encoding correct across 0
paillier/ind_cpa_distinct.json I10 two cts differ, same plaintext
paillier/vs_phe.json P12 matches python-paillier
Pitfalls
  • Forgetting fresh r per encryption → deterministic, IND-CPA broken (I10, P4).
  • μ undefined if gcd(L(g^λ),n)≠1; with g=n+1 it is invertible — assert and document.
  • Plaintext m≥n wraps silently; range-check (PlaintextOutOfRange).
  • Secret-exponent modexp in decrypt must be constant-time (I9); a fast non-CT path leaks λ.
  • Overflow: all arithmetic mod n² (twice the bit-length); ensure the bignum width is sufficient.

⬜ Phase 4 — Polynomial ring R_q + schoolbook negacyclic multiply

Objectives

Implement the ring R_q = Z_q[x]/(x^n+1): the Poly type, add/sub, negacyclic schoolbook multiply (the correctness reference for the NTT, P5/P8), coefficient reduction, and sampling polynomials from uniform/Gaussian/ternary into R_q. The lattice substrate beneath BFV.

Deliverable

poly_add/poly_mul_schoolbook correct on hand-computed examples; negacyclic wrap verified (x^{n−1}·x = −1 constant term); samplers fill polynomials with correct distributions.

Acceptance
  • poly_add componentwise mod q.
  • poly_mul_schoolbook: (x^{n−1})·(x) → −1 (i.e. q−1) constant term, rest 0 (negacyclic).
  • Multiply matches a hand-computed small example (n=4).
  • Sampled polynomials have correct coefficient distributions.
Fixtures
Fixture Purpose Expected
ring/add.json addition componentwise mod q
ring/negacyclic_wrap.json x^n=−1 sign-flipped wrap
ring/mul_small.json multiply hand-computed n=4
Pitfalls
  • Forgetting the sign flip on the wrap turns negacyclic into cyclic convolution — a silent, scheme-breaking bug (P5).
  • Coefficient overflow before reduction: products of two <q values need a u128 accumulator when q is near 62 bits.
  • Off-by-one in degree indexing during the wrap.

⬜ Phase 5 — NTT / INTT (negacyclic) + pointwise multiply

Objectives

Implement the negacyclic NTT/INTT (§8.4): primitive-2n-th-root tables per NTT prime, forward (Cooley–Tukey) and inverse (Gentleman–Sande) transforms with Montgomery butterflies, and pointwise multiply, so INTT(NTT(a)∘NTT(b)) = a·b in R_q (I7, P5). The performance heart of BFV.

Deliverable

INTT(NTT(p))=p exactly for random p; INTT(NTT(a)∘NTT(b)) equals poly_mul_schoolbook(a,b) in R_q; transforms run for n up to 32768.

Acceptance
  • Round-trip identity INTT∘NTT = id exact (I7) for 10⁴ random polys.
  • NTT-multiply == schoolbook multiply in R_q (P5) across random pairs.
  • Negacyclic property: result respects x^n=−1 (matches Phase 4 wrap).
  • Works for every NTT prime in a parameter set (I14).
Fixtures
Fixture Purpose Expected
ntt/roundtrip.json I7 INTT(NTT(p))=p exact
ntt/vs_schoolbook.json P5 == negacyclic schoolbook
ntt/negacyclic.json wrap x^n=−1 respected
ntt/bad_prime.json I14 q≢1 mod 2n → BadNttPrime
Pitfalls
  • Missing n⁻¹ scaling in INTT → result off by a factor of n (silent for a·1 if n=1).
  • Wrong root order (ω vs ψ) or forgetting the negacyclic twist → cyclic instead of negacyclic convolution.
  • Bit-reversal permutation mismatch between forward and inverse → scrambled output.
  • Montgomery butterfly using non-Montgomery roots → wrong values; keep tables in Montgomery form consistently.
  • q² overflow in the butterfly product — use u128 (or 62-bit primes with care).

⬜ Phase 6 — RNS / double-CRT representation + base conversion

Objectives

Implement the RNS representation (§8.5): ciphertext modulus q=Πqᵢ of NTT-friendly primes, per-residue polynomial arithmetic (each prime carries its own NttCtx), exact CRT reconstruction, and base conversion between modulus sets — the subtlest correctness property in the system (I8, P6). The double-CRT layout that makes BFV practical.

Deliverable

from_rns(to_rns(x))=x mod q exactly; per-residue NTT-multiply matches single-modulus result; base conversion between two prime sets is exact (validated against the exact-CRT path).

Acceptance
  • CRT reconstruction exact for 10⁴ random x<q (I8, rns/crt_recon.json).
  • RNS multiply (per-residue NTT) == reconstruct-then-single-modulus multiply for k=3–8 limbs (rns/rns_mul_equiv.json).
  • base_convert fast variant == exact-CRT variant, correction term verified to 0 reconstruction error (rns/base_convert.json).
  • Parallel per-limb arithmetic == serial, bit-for-bit, across 100 randomized limb counts (reassociation-free; integer exact, rns/parallel_equiv.json).
Fixtures
Fixture Purpose Expected
rns/crt_recon.json I8 exact reconstruction
rns/rns_mul_equiv.json per-residue == single-modulus
rns/base_convert.json I8 fast == exact
rns/parallel_equiv.json ADR 27 == serial
Pitfalls
  • Base conversion is the classic FHE bug source: the fast variant's correction term (handling the q-overflow ambiguity) is easy to get wrong and fails only for some inputs — always cross-check vs exact CRT (I8).
  • Forgetting a prime must be ≡1 mod 2n breaks its NTT (I14).
  • Mixing Montgomery and normal form across residues.
  • Integer overflow in CRT constants (q/qᵢ is large — keep as BigUint or reduce per modulus).

⬜ Phase 7 — BFV keygen, encrypt, decrypt, homomorphic add

Objectives

Implement BFV up to additions: parameter-bound encoding (BfvParams), ternary secret-key keygen, public key (−(a·s+e), a), encryption (FV scaling Δ=⌊q/t⌋, fresh u,e, I10/P4), decryption (round(t/q·(c0+c1·s)), I1), and homomorphic add (I5). SHE without multiplication.

Deliverable

Dec(Enc(m))=m; Dec(Enc(3)+Enc(4))=7 (I5); fresh encryptions of the same m differ (I10); noise budget reported and decreases on add.

Acceptance
  • Dec(Enc(m))=m for 1000 random m∈R_t at n=8192, t≈20-bit (correctness, I1, full budget, bfv/roundtrip.json).
  • Dec(add)=a+b mod t (I5, bfv/hom_add.json).
  • Two encryptions of m differ (I10, P4); both decrypt to m (bfv/ind_cpa_distinct.json).
  • Noise budget after add drops by ≤1 bit and stays >0 → correct (I2, bfv/add_budget.json).
  • Decryption uses s in constant-time-aware paths (I9).

  • Δ=⌊q/t⌋ rounding: the FV scaling and the round(t/q·…) decrypt must be exact inverses up to noise; a wrong direction corrupts decryption.

⬜ Phase 8 — BFV multiply: tensoring, relinearization, modulus switching

Objectives

Implement homomorphic multiplication (§8.6): tensor two ciphertexts into a 3-component product, scale by t/q (RNS base conversion, I8), relinearize the c2·s² term back to 2 components using the relin key (key switching), and modulus-switch down the chain to extend depth. The core of leveled FHE; bounded-depth Dec(mul)=a·b (I5, within budget, I1/I3).

Deliverable

Dec(Enc(3)·Enc(4))=12 with budget>0 (I5,I1); a depth-L multiply chain stays correct until the budget runs out; mod_switch extends achievable depth; mul past budget aborts with NoiseExhausted (I3).

Acceptance
  • Dec(mul)=a·b mod t for random a,b at depth 1 (I5).
  • Depth-L chain (L per params) decrypts correctly; L+1 aborts (I3).
  • Relinearized ciphertext is 2-component and decrypts correctly (key-switch noise within budget).
  • mod_switch lowers level, reduces ciphertext size, and increases or preserves budget headroom for further mults.
  • Matches SEAL BFV multiply vectors (P12).
Fixtures
Fixture Purpose Expected
bfv/mul_depth1.json I5 a·b mod t, budget>0
bfv/relin_correct.json relinearization 2-comp, correct
bfv/depth_chain.json leveled correct to depth L
bfv/depth_overflow.json I3 NoiseExhausted abort
bfv/modswitch.json mod-switch level↓, budget extends depth
bfv/vs_seal_mul.json P12 matches SEAL
Pitfalls
  • The t/q scaling after tensoring is a base conversion — the #1 BFV bug; cross-check vs exact CRT (I8).
  • Relin key with too-coarse decomposition injects too much noise → unexpected depth loss; tune the decomposition base.
  • Forgetting the abort guard → a multiply past budget returns a valid-looking but garbage ciphertext (I3, P3).
  • Mod-switching at the bottom of the chain (no prime to drop) must error (ModSwitchAtBottom), not panic.
  • Mismatched levels in mul (one ciphertext switched, the other not) → wrong result; align levels first.

⬜ Phase 9 — Noise model + parameter selection

Objectives

Make depth predictable: implement the he-noise growth model (fresh/add/mul/relin/mod-switch bounds), the noise budget in bits (I2), the abort guard (I3/P3), and he-params selection of (n,q,t,σ) for a target depth L and security level via the LWE-estimator tables (I12/P9). Closes the loop between "what circuit" and "what parameters."

Deliverable

For a requested depth L and 128-bit security, select returns parameters that (a) pass the security check (I12) and (b) actually support L multiplications (verified by running a depth-L chain and confirming budget>0 throughout, then 0 at L+1).

Acceptance
  • Predicted noise budget after each op matches the measured budget (decrypt-succeeds boundary) within a small margin.
  • select(L, 128) params support exactly ≥L multiplications (chain conformance) and meet ≥128-bit security (I12).
  • guard aborts precisely when (and only when) the next op would make decryption fail (no false aborts at budget>0; no false passes at budget≤0) (I3).
  • validate rejects insecure / malformed params (I12/I13/I14) loudly (P9).
Fixtures
Fixture Purpose Expected

noise/budget_vs_measured.json model accuracy predicted ≈ measured
noise/guard_boundary.json I3 abort iff next op fails

Pitfalls
  • Worst-case noise bounds are conservative; pure worst-case wastes depth. Document the chosen model (worst vs average) and its failure probability.
  • A too-optimistic model passes the guard but decryption fails — worse than a conservative one (silent garbage, P1/P3). Calibrate against measured boundaries.
  • Security tables are version-specific (estimator updates); pin the source + date.
  • Picking q for depth without rechecking security (bigger q lowers security at fixed n) — select must iterate n up until security holds (I12).

⬜ Phase 10 — Encoding layer: integer + batch (CRT slots)

Objectives

Implement the encoding layer (§8.8): integer/scalar encode-decode and batch encoding (CRT slots, available when t≡1 mod 2n) that packs n integers into one plaintext for SIMD-style slot-wise homomorphic operations. CKKS-style approximate encoding remains deferred. (Optional) Galois keys / rotations are introduced as a partially-deferred extension.

Deliverable

encode/decode_int round-trips signed integers; batch-encode of [1,2,3,4] + [5,6,7,8] then homomorphic add decrypts+decodes to [6,8,10,12] (slot-wise); slot-wise multiply works within budget.

Acceptance
  • decode_int(encode_int(m))=m for 1000 signed m∈(−t/2,t/2] (encode/int_roundtrip.json).
  • Batch round-trip: decode_batch(encode_batch(v))=v for length-n=8192 v (encode/batch_roundtrip.json).
  • Slot-wise homomorphic add/mul: [1,2,3,4]+[5,6,7,8]=[6,8,10,12] and componentwise product, independently per slot (I5 per slot, encode/batch_add.json, encode/batch_mul.json).
  • Batching unavailable (graceful) when t≢1 mod 2n; falls back to scalar encode with 0 batching-related failures (encode/no_batch_fallback.json).
Fixtures
Fixture Purpose Expected
encode/int_roundtrip.json scalar signed round-trip
encode/batch_roundtrip.json slots vector round-trip
encode/batch_add.json slot-wise add [6,8,10,12]
encode/batch_mul.json slot-wise mul componentwise product
encode/no_batch_fallback.json t≢1 mod 2n scalar-only, documented
Pitfalls
  • Batch encoding requires t≡1 mod 2n (so Z_t has the needed roots); choosing t without this disables batching — he-params must coordinate.
  • The slot permutation (which coefficient ↔ which slot) follows a specific index map; getting it wrong silently permutes results.
  • Decoding without centering mod t flips negative slots.
  • Rotations (deferred) need Galois keys sized like relin keys — noise + storage cost.

⬜ Phase 11 — Security analysis + constant-time hardening

Objectives

Validate and document security: the IND-CPA argument (DCRA for Paillier, RLWE for BFV), parameter selection against known attacks (the LWE estimator), and constant-time hardening of all secret-dependent paths (decryption, key generation) per the subtle discipline (I9/P7). Affirm the "educational, not audited" boundary (P12).

Deliverable

A written threat model + IND-CPA argument; secret paths pass a constant-time audit and timing test; params rejects insecure parameters; a prominent "NOT FOR PRODUCTION SECRETS" notice in README/SECURITY.

Acceptance
  • Decryption timing shows no statistically significant dependence on secret bits: Welch's t-test p > 0.05 over 10⁵ timed trials (timing test, I9, security/ct_timing.json).
  • subtle audit: 0 secret-dependent branches or table indices found in decrypt/keygen (manual review + lint scan).
  • check_security matches pinned estimator values within 1 bit; select never returns below the requested 128/192/256-bit target (I12, security/param_levels.json).
  • IND-CPA argument documented for both schemes with explicit assumptions (security/indcpa_notes.md).
Fixtures
Fixture Purpose Expected
security/ct_timing.json I9 no secret-timing correlation
security/param_levels.json I12 128/192/256 params validated
security/insecure_reject.json P9 below-target rejected
security/indcpa_notes.md documentation reductions present
Pitfalls
  • A "harmless" optimization (early-exit, secret-indexed table) reintroduces a timing leak — re-audit after every change to secret paths (I9).
  • Compiler may reintroduce branches; verify on the emitted assembly for the hottest secret path, or rely on subtle's vetted primitives.
  • Treating the educational implementation as production-safe — the loud disclaimer (P12) is part of the deliverable.
  • RLWE security depends on the secret/error distributions actually being sampled correctly (Phase 2); a weak sampler silently lowers security.

⬜ Phase 12 — Performance: NTT/RNS optimization, threading

Objectives

Make the kernels fast: optimize the NTT butterfly (Montgomery, cache-blocking, optional SIMD), parallelize over RNS limbs and NTT strata (rayon, ADR 27), reduce allocations, and raise the practical (n, k, depth) ceiling. GPU remains deferred.

Deliverable

NTT throughput within target for n up to 32768; per-limb parallel multiply scales with cores; documented bandwidth/throughput model; committed benchmarks.

Acceptance
  • Optimized NTT result == reference NTT (integer-exact; no tolerance) — correctness first (P5).
  • Parallel per-limb == serial (integer exact, no reassociation issue, ADR 27).
  • Near-linear thread scaling over RNS limbs up to core count.
  • Benchmarks within ±20% of committed baseline; no correctness regression.
Fixtures
Fixture Purpose Expected

perf/parallel_equiv.json ADR 27 == serial (exact)
bench/ntt_scaling.json throughput within ±20% baseline
bench/bfv_mul.json mul cost within target
Pitfalls
  • A SIMD butterfly with a wrong lane layout corrupts only some coefficients — equivalence fixtures catch it (P5).
  • Over-parallelizing small n (thread overhead > work) regresses performance; single-thread fallback below a size threshold.
  • False sharing at RNS-limb chunk boundaries; align/chunk per limb.
  • Allocator pressure from per-op transforms; reuse scratch.
