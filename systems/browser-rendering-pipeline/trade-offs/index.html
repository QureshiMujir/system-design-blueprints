Decisions (§9) · 25 ADRs

01

Language + edition

Chosen

Rust 2021, MSRV 1.78, std (threads, timing)

Rejected

C/C++; Go; TypeScript

When the rejected choice is right

C/C++ when integrating an existing C++ engine (Blink/WebKit) where FFI cost dominates safety gain. Go for a non-realtime server-side rasterizer with no frame budget.

Why: Compositor races = what Send/Sync prevent; C/C++ ship them. Go GC blows 16.6ms; TS no thread/cache control. Servo+WebRender precedent.

02

Crate decomposition

Chosen

6-member workspace: rp-style/rp-boxtree/rp-paint/rp-composite/rp-pipeline/rp-cli

Rejected

Monolith crate; per-stage repos

When the rejected choice is right

Monolith for a <5k-LOC prototype where cross-crate API churn outweighs the firewall. Per-stage repos when stages ship on independent release trains/teams.

Why: Crate = stage boundary → compile firewall, owned types, no cyclic deps.

03

Stage execution model

Chosen

Staged lifecycle: update_lifecycle(doc, target) runs dirty stages, skips clean

Rejected

Recompute-everything per frame; observer callbacks

When the rejected choice is right

Recompute-all when every frame is a full repaint anyway (a fullscreen video/game canvas) — dirty tracking is pure overhead. Observers for sparse, event-driven UIs with no per-frame loop.

Why: Skip clean → partial frames cheap; forward-only walk; deterministic, traceable.

04

Geometry/paint decoupling

Chosen

PropertyTrees + PropertyTreeState per chunk

Rejected

Recompute geometry in paint; transforms baked into items

When the rejected choice is right

Baked transforms for static print/PDF/screenshot rendering (content does not animate or scroll): the tree machinery is dead weight, immediate transform is simpler.

Why: RenderingNG core: scroll/transform mutates one PaintPropertyNode, no repaint. Enables NEEDS_COMPOSITE-only frames.

05

Display representation

Chosen

Retained DisplayList (Vec<DisplayItem>+PaintChunk) + retained Tiles

Rejected

Immediate-mode per frame; retained scene graph

When the rejected choice is right

Immediate-mode (skia-style) for a canvas/game UI repainting fully every frame — no diff to amortize, lower memory. Scene graph for editor tools needing per-node mutation handles.

Why: Retained list → chunk-level invalidation + visual_rect culling.

06

Concurrency topology

Chosen

2-thread: main=style/layout/paint; compositor=raster/composite/scroll/anim

Rejected

Single-thread; thread-per-stage; tokio

When the rejected choice is right

Single-thread for a headless screenshot/PDF service with no live interaction (determinism > responsiveness). Thread-per-stage / pipeline parallelism when each stage is independently CPU-saturated (server farm).

Why: Off-main raster/scroll = jank-free NEEDS_COMPOSITE (Blink/cc model).

07

Main↔compositor handoff

Chosen

Commit = immutable snapshot, single sync point

Rejected

Arc<Mutex> shared trees; lock-free shared; delta channels

When the rejected choice is right

Delta channels when commits are huge and mostly-unchanged (stream incremental diffs, not whole snapshot) — Flutter's approach. Shared lock-free for a single-writer/many-reader telemetry layer.

Why: One synchronized handoff; no locks on hot path, no torn reads.

08

Selector matching

Chosen

Consume 258 via Matcher trait: StyleResolver<'m, M: Matcher>

Rejected

Reimplement matches_selector; clone 258

When the rejected choice is right

Reimplement when the selector model must co-design with style sharing (Stylo fused matching+cascade for cache locality).

Why: 258 owns matching; 260 owns orchestration. Trait = test doubles + version isolation.

09

Rasterizer backend

Chosen

Consume 169 software rasterizer for RasterTasks

Rejected

New rasterizer; hard GPU-driver dep

When the rejected choice is right

A real GPU rasterizer (WebRender) when the workload is GPU-bound, large viewports, animation-heavy, and a driver is guaranteed present.

Why: 169 does tile raster; software default = deterministic reftests, no GPU env.

10

Layout output

Chosen

Immutable per-frame FragmentTree (Fragment+LayoutRect)

Rejected

Mutable render objects with live geometry; in-place mutation

When the rejected choice is right

Mutable render objects (legacy WebKit RenderObject) when memory is tight and incremental in-place layout edits beat full rebuilds on huge static documents.

Why: Immutable snapshot = safe Commit; supports fragmentation. No cross-frame aliasing.

11

Box vs fragment tree

Chosen

Separate BoxTree (input, mutable build) + FragmentTree (output, immutable)

Rejected

Single tree carrying structure + geometry

When the rejected choice is right

Single tree when memory-constrained and layout rarely re-runs without a structural change (the split's reuse benefit fails to materialize).

Why: Box=display/FC resolution; fragment=laid-out result. Split → relayout without rebuilding boxes.

12

Tile size

Chosen

256×256 px tiles

Rejected

512×512; full-layer bitmap; variable

When the rejected choice is right

512×512 on high-DPI/4K where per-tile fixed cost dominates and re-raster locality is coarse. Full-layer bitmap for tiny always-fully-dirty layers (small icons).

Why: 256² balances raster-task granularity vs per-tile overhead (cc default).

13

Layer squashing

Chosen

Squash overlapping non-composited content into nearest backing layer

Rejected

Layer-per-element; no squashing

When the rejected choice is right

Layer-per-element when layer count is naturally tiny (a few composited overlays) and squashing's overlap analysis costs more than it saves.

Why: Bounds CompositorLayer count → bounds tile/composite memory.

14

Compositing reasons

Chosen

Closed CompositingReason enum (Transform3D/WillChange/Animation/ScrollDependent/Overlap/Video/IFrame)

Rejected

Open registry; heuristic-only

When the rejected choice is right

Open/heuristic registry in a research engine experimenting with novel promotion signals (ML-driven layerization) where exhaustiveness is a straitjacket.

Why: Closed enum = exhaustive match, predictable layerization.

15

Invalidation repr

Chosen

InvalidationFlags bitflags + dirty-bit propagation

Rejected

Per-node dirty objects; observer graph; full recompute

When the rejected choice is right

Observer/dependency graph (Salsa/incremental-DB) when invalidation dependencies are dynamic and data-driven, not a fixed pipeline order.

Why: Bitflags = O(1) set/test/clear, cache-friendly, mergeable.

16

Invalidation semantics

Chosen

Hierarchical: NEEDS_STYLE⊇LAYOUT⊇PAINT⊇COMPOSITE

Rejected

Independent flags; manual cascade per call site

When the rejected choice is right

Independent flags when stages are genuinely decoupled (a paint-only or layout-only standalone tool) — the hierarchy would force spurious downstream work.

Why: Implication encodes lifecycle dependency once; coarse bit subsumes finer.

17

Property identity

Chosen

PropertyId(u16) interned + property DB

Rejected

&str/String keys; enum-per-property

When the rejected choice is right

&str keys for a CSS linter/devtool prioritizing readability/debuggability over hot-path indexing. Enum-per-property when the property set is tiny and fixed.

Why: u16 → dense array indexing, cheap copy/compare.

18

Computed-style ownership

Chosen

Arc<ComputedStyle> via style-sharing cache

Rejected

Per-element owned; copy-on-resolve

When the rejected choice is right

Per-element owned when nearly every element has a unique style (heavily-randomized content) — sharing-cache lookups miss and add pure overhead.

Why: Identical styles share one Arc → cut memory + cascade work.

19

Raster/compositor abstraction

Chosen

Software (169) default + abstract GPU-compositor model

Rejected

Real GPU backend now; software-only

When the rejected choice is right

A real GPU backend from day one when shipping to a fixed GPU target (console, embedded SoC) where the abstraction layer only adds indirection.

Why: NON-GOAL = GPU driver; abstract model is portable + testable; swappable later.

20

Conformance oracle

Chosen

Reftests (PNG vs ref, pixel tolerance) + differential vs reference pipeline

Rejected

Per-pixel asserts; DOM-structure-only

When the rejected choice is right

Structural/DOM checks when raster output is non-deterministic (GPU AA variance) and only the tree/order matters, not exact pixels.

Why: Pixel reftests catch order/geometry end-to-end; differential pins behavior.

21

Benchmark + perf gates

Chosen

criterion + per-stage timing + 16.6ms budget gate

Rejected

Wall-clock println!; no perf CI

When the rejected choice is right

Wall-clock spot-checks for a one-off prototype with no CI and no regression-protection requirement.

Why: Statistical stability; gate fails CI on jank.

22

Robustness testing

Chosen

Fuzz style/layout/paint: never panic on arbitrary DOM

Rejected

Manual edge cases only

When the rejected choice is right

Manual-only when input is fully trusted and internally generated (an offline build tool fed validated IR) — fuzzing yields little.

Why: Must degrade, not crash, on hostile input.

23

MSRV policy

Chosen

Pin 1.78, CI-verified

Rejected

Latest-stable floating; nightly

When the rejected choice is right

Floating latest/nightly for an internal-only tool chasing new language features with no external MSRV consumers.

Why: Reproducible builds; needs nothing newer.

24

Dependency budget

Chosen

Minimal: bitflags, criterion(dev), 258, 169; std else

Rejected

Heavy frameworks; tokio/rayon

When the rejected choice is right

Pull in rayon when parallel style/raster scaling is the bottleneck and a proven work-stealing pool beats a hand-rolled one (Servo uses Rayon).

Why: Hand-rolled on std = control/auditability, small attack/MSRV surface.

25

License

Chosen

MIT OR Apache-2.0

Rejected

GPL; proprietary; single-license

When the rejected choice is right

GPL/copyleft when the goal is to force downstream contributions back (a reference engine meant to stay open). Proprietary for a closed commercial product.

Why: Rust-ecosystem standard; max downstream compat incl. siblings.

Alternative Architectures (Roads Not Taken)

Fundamentally different designs for the same problem — given styled DOM + viewport, produce frames and re-render incrementally. Each: sketch, winning regime, the real system that embodies it, why 260 rejected it.

ALT-1 — Immediate-mode, recompute-every-frame (no lifecycle, no retained trees).

 each vsync:
   styled DOM + viewport ──> [full Style] ──> [full Layout]
              ──> [full Paint into a fresh frame buffer] ──> blit
   (no dirty bits, no DisplayList diff, no tile cache; rebuild all)
  • Wins when: every frame is fully dirty anyway — fullscreen <canvas>, game UI, 60fps dataviz; dirty tracking is then pure overhead and the simpler model is faster, lower-memory. Embodied by: Dear ImGui / game-engine UI; Skia immediate-mode draw. Rejected here: 260 targets documents that mostly don't change frame-to-frame (MM5); recompute-all forfeits the entire skip-clean + property-tree + tile-cache value (DP-1, DP-8) — a static page would burn >10ms/frame for nothing.

ALT-2 — GPU-driven retained scene (no CPU tile cache; submit the whole frame to the GPU).

 main: Style ─> Layout ─> Paint ─> retained display list
   Commit ──> GPU: [scene graph upload] ─> [GPU builds & batches] ─> [draw] ─> frame
   geometry/scroll/transform ──> GPU shader params, no CPU raster at all
  • Wins when: a capable GPU is guaranteed, viewports large/high-DPI, content animation-heavy — GPU rasterizes + composites far faster than CPU tiles, with very few layers. Embodied by: Mozilla WebRender (and Servo). Rejected here: GPU driver is a NON-GOAL (ADR-19); 260 consumes the 169 software rasterizer for deterministic env-independent reftests (DP-12, ADR-09). GPU is the deferred path behind the same LayerTree/CompositorFrame contract (Compatibility N.9), not the Phase-0 design.

ALT-3 — Single-threaded synchronous pipeline (no compositor thread, no Commit).

 vsync ─> update_lifecycle(Composite) on ONE thread:
          Style ─> Layout ─> Paint ─> Layerize ─> Raster ─> Composite ─> display
   (scroll/anim re-run inline on the same thread; no handoff, no Send boundary)
  • Wins when: no live interaction to keep smooth — a headless screenshot/PDF/print service — where determinism + simplicity beat responsiveness and there is no main-thread contention to hide. Embodied by: headless rendering modes; pre-WebRender Gecko's largely main-thread model. Rejected here: the whole point is jank-free scroll/animation while main is busy (DP-5, MM6) — one thread means a slow script stalls scrolling; 260 keeps single-thread only as a debug/reftest fallback (--no-compositor-thread, Phase 10 ## 22 N.10), not production.
