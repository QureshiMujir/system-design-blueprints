  15. Why must em resolve after font-size in the cascade, and what bug appears if the order is reversed? (Phase 1 ## 13 N.6 + Phase 2 ## 14 N.2)

Mental Models & First Principles

The compressed intuitions an expert renderer engineer holds. Each: the model, what it predicts, the bug class you write without it, and where this doc applies it.

  • MM1 — The lifecycle is a monotone clock; invalidation is the only thing that can wind it back. A frame is a forward sweep Clean → … → Composite; the only backward motion is a mutation setting a NEEDS_* bit. Predicts: any "re-render loop" is a stage that re-dirties an earlier stage mid-walk — forbidden by construction. Without it: Style re-entered from Layout → non-termination (DP-2, I1, I4). Applied: §8.2, Phase 11 (## 23).
  • MM2 — Coarser dirt subsumes finer; the only question per mutation is the smallest correct bit. NEEDS_STYLE ⊇ LAYOUT ⊇ PAINT ⊇ COMPOSITE. Predicts: mis-sizing the bit has two failure directions — too low = silent stale (F1), too high = jank (F2); there is no third. Without it: NEEDS_PAINT after a width change drops a needed relayout → stale geometry. Applied: §8.3, DP-3, the Invalidation Responsibility Table (Failure Modes N.3).
  • MM3 — Paint order is a property of the stacking tree, not the DOM tree. CSS 2.2 sec. 9.9 layering (neg-z → block → float → inline → pos-z) is computed per stacking context. Predicts: a late-DOM z-index:-1 paints first; correctness lives in the order, and hit-testing is exactly its reverse. Without it: painting in DOM order → wrong occlusion + wrong hit target (DP-6, I7, F3). Applied: §8.4, Phase 5 (## 17).
  • MM4 — Property trees are an indirection that turns geometry edits into cheap node writes. A DisplayItem carries no absolute coords; position = compose the chunk's TransformId chain. Predicts: scroll / composited transform / opacity touch one node and re-composite — no repaint; anything that changes which items exist does not. Without it: repaint-per-scroll-tick (DP-4, I12). Applied: §8.5, Phase 6 (## 18), Phase 10 (## 22).
  • MM5 — Retained + diffed beats recomputed when frames are mostly-unchanged. DisplayList, PropertyTrees, and tiles persist; each frame diffs and re-does only the delta. Predicts: the win scales with frame-to-frame similarity → near-total for scroll, near-zero for a full-page restyle. Without it: rebuilding the LayerTree/tiles every frame defeats retained compositing (DP-8, ADR-05). Applied: Phase 7 (## 19) raster-invalidation, Performance Engineering X.4.
  • MM6 — A handoff you move cannot be raced; a handoff you share must be locked. Commit transfers ownership of an immutable snapshot to the compositor. Predicts: the entire main↔compositor data-race class disappears at compile time — not by discipline but by Send + the borrow checker. Without it: compositor reads a live Box/ComputedStyle → UB (DP-10, I9, F6; the core reason for choosing Rust, ADR-01). Applied: §8.9, Phase 10 (## 22), Threat Model T3.
  • MM7 — Immutability per frame is what makes the snapshot free. FragmentTree/DisplayList are built once, never mutated. Predicts: the compositor can read them lock-free, and Commit is an Arc-clone (O(1)), not a deep copy. Without it: in-place fragment edits → torn reads across the thread boundary (DP-7, I5, I6). Applied: §11.2–11.3, Phase 4 (## 16).
  • MM8 — A frame is a fixed time budget, not a fixed amount of work; over-budget is dropped, never torn. 16.6ms @ 60Hz, split per stage. Predicts: the correct response to overrun is shed/defer (drop a frame, keep last good CompositorFrame), and the dirty bits survive so the next vsync finishes the work. Without it: a synchronous full raster stalls one frame to >100ms (DP-9, F7). Applied: §4.1, Phase 12 (## 24), Performance Engineering X.2.
  • MM9 — Content is the adversary; every untrusted number gets a cap before it reaches geometry. DOM size, nesting depth, z-index, lengths are hostile. Predicts: the defense is a clamp/saturate at the type boundary plus a per-stage budget, so the failure mode is degraded output, never a panic. Without it: i32::MAX z-index or 10⁶-deep nesting → overflow/stack-overflow DoS (I19, I20, Threat Model T1/T6). Applied: §4.4, Threat Model Caps table.
  • MM10 — An incremental engine is only trustworthy against a brute-force oracle. Fast paths (skip-clean, sharing cache, tile cache) can be self-consistently wrong. Predicts: the only sound gate compares the incremental result to a naive recompute (differential) + golden pixels (reftest) + the shadow re-render audit. Without it: a missed invalidation produces a stale frame that every internal check agrees is correct (F1, the gravest class). Applied: Phase 13 (## 25), Failure Modes N.2 assert_clean_is_clean.

Glossary · 42 terms · site-wide glossary

document lifecycle
DocumentLifecycle (rp-pipeline) state machine over LifecycleStage; update_lifecycle(doc, target) runs dirty stages in order up to target, skips clean.
lifecycle stage
LifecycleStage variant: Clean, Style, Layout, CompositingInputs, Prepaint, Paint, Commit, Composite; monotone forward per frame.
invalidation
Marking an earlier stage dirty via InvalidationFlags; only ever moves lifecycle backward, never forward.
dirty bit
One bit in InvalidationFlags (NEEDS_STYLE/LAYOUT/PAINT/COMPOSITE) on a RenderObjectId; hierarchical -> dirtying stage N dirties N..Composite.
restyle
Re-run of the Style stage for elements with NEEDS_STYLE; produces fresh ComputedStyle, may reuse via style sharing.
render object
Persistent per-element node identified by RenderObjectId(u32); carries dirty bits + property-node ids across frames.
box tree
BoxTree of Box{kind, style, children} (rp-boxtree); display-resolved render tree input to layout; distinct from immutable fragment output.
formatting context
FormattingContext{Block,Inline,Flex,Grid}; layout regime a box establishes for its in-flow children (BFC/IFC).
fragment tree
FragmentTree{root: Fragment} (rp-boxtree); immutable per-frame geometry output of layout; one box -> >=1 fragment (fragmentation).
fragment
Fragment{rect: LayoutRect, style, kind, children}; a single laid-out box piece with absolute-ish geometry.
cascade
Cascade (rp-style): per-property winner selection sorting by Origin, then !important, then Specificity, then source order.
origin
Origin{UserAgent, User, Author}; outermost cascade sort key (with !important flipping User/Author precedence).
specificity
Per-rule weight from the 258 matcher; cascade tiebreak after origin/!important, before source order.
computed value
Resolved per-PropertyId value in ComputedStyle after inheritance + initial/relative resolution; pre-layout (no used/actual values).
style sharing
sharing_cache in StyleResolver; reuses an Arc<ComputedStyle> across elements with equal match+parent signature -> skips cascade.
stacking context
StackingContext{z_index, establishes}; established by z-index!=auto on positioned, opacity<1, transform, etc.; root of a paint-order subtree.
paint order
CSS 2.2 sec. 9.9 layered order (not DOM order) governing DisplayList item sequence + reverse hit-test order.
display list
DisplayList{items, chunks} (rp-paint); flat retained item buffer emitted by walking fragments in paint order.
display item
DisplayItem enum: Rect/Text/Image/Border/BoxShadow + BeginClip/EndClip/BeginEffect/EndEffect bracket pairs.
paint chunk
PaintChunk{items: Range, property_state, visual_rect}; contiguous item run sharing one PropertyTreeState; unit of raster/replay + invalidation.
property tree
One of four (PropertyTrees) decoupling geometry from paint; node updates re-applied by compositor without repaint.
transform/clip/effect/scroll tree
TransformTree/ClipTree/EffectTree/ScrollTree; parented PaintPropertyNodes holding transform, clip, opacity/filter, scroll-offset state.
paint property node
PaintPropertyNode{parent_id, local state}; one node per property tree; boxes reference node ids assigned in prepaint.
prepaint
Stage (## 18) building PropertyTrees, assigning node ids to boxes, computing PropertyTreeState per chunk; precedes Paint.
layerization
CompositingInputs stage (## 20): partition DisplayList/chunks into CompositorLayers by CompositingReason; includes squashing.
compositing reason
CompositingReason{Transform3D,WillChange,Animation,ScrollDependent,Overlap,Video,IFrame}; why a subtree gets its own layer.
layer tree
LayerTree{layers} (rp-composite); layerization output; ordered CompositorLayers consumed by raster + frame assembly.
compositor layer
CompositorLayer{transform_node, content: Range, reasons, tiles}; references a chunk range + a TransformId; tiled for raster.
tile
Tile{rect, state}; fixed-grid raster subdivision of a layer (e.g. 256x256); cached + invalidated independently.
raster task
RasterTask{layer, tile, chunk}; compositor-thread unit replaying a PaintChunk via the 169 rasterizer into a tile bitmap.
compositor frame
CompositorFrame{layers, transforms}; final assembled output applying TransformTree to layers -> display.
commit
Commit (rp-pipeline); the single synchronized main->compositor snapshot handoff; post-commit compositor must not touch main state.
main thread
Runs Style, Layout, Prepaint, Paint stages; produces the Commit snapshot.
compositor thread
Runs raster, composite, scroll, composited animation off-main; consumes Commit; keeps NEEDS_COMPOSITE-only updates jank-free.
requestAnimationFrame
RafCallbacks in FrameScheduler, driven by a host hook (no JS engine); fired in the "update the rendering" step before lifecycle.
vsync
Display refresh tick; FrameScheduler.vsync_interval aligns frame production to the cadence.
frame budget
16.6ms (60Hz) wall-clock target for rAF + full lifecycle up to Composite.
jank
Missed frame budget -> dropped/late frame; main-thread-bound stages are the usual cause; compositor-only paths avoid it.
raster invalidation
RasterInvalidation (rp-paint): chunk/visual-rect diff between frames marking which tiles need re-raster.
hit testing
Reverse-paint-order traversal mapping a point -> topmost render object; uses the same stacking/paint order.
PropertyTreeState
Tuple of (transform, clip, effect, scroll) node ids defining a chunk's geometry/visual context; carried on PaintChunk.
RasterState
Tile.state enum: Missing | Rastering | Ready; drives raster-on-demand scheduling + readiness checks at assembly.
