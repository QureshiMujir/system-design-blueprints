3. Architectural Overview

3.1 Pipeline Topology

 FrameScheduler  (rAF callbacks + vsync, 16.6ms budget)  --update_lifecycle(doc, target)-->
 rp-pipeline: DocumentLifecycle (LifecycleStage) --- gates each stage by InvalidationFlags; skips Clean, runs forward only
==== TRUST BOUNDARY: untrusted DOM/CSS sizes (host/124) =======================
  viewport, lengths, z-index, child counts -> all geometry/recursion clamped + saturating; no panic on adversarial input
        |
+------------------------ MAIN THREAD --------------------------+
|  rp-style    match(258)+Cascade ----> ComputedStyle (Arc)     |  NEEDS_STYLE
|  rp-boxtree  BoxTree+layout ---------> FragmentTree            |  NEEDS_LAYOUT
|  rp-paint    Prepaint:PropertyTrees ->[retained]              |  NEEDS_PAINT
|              Paint:walk paint order -> DisplayList(+chunks)    |
+-------------------------------------------|--------------------+
==== CONCURRENCY BOUNDARY: Commit (snapshot) = the ONLY main<->compositor sync ; after Commit, compositor touches NO main state
+--------------------- COMPOSITOR THREAD ----v------------------+
|  rp-composite                                                  |
|    layerize: CompositingReason -> LayerTree                    |  NEEDS_COMPOSITE
|    raster:   RasterTask replays DisplayList chunks via 169     |
|              -> Tile bitmaps  [tile cache retained]            |
|    assemble: apply TransformTree -> CompositorFrame -> display |
+----------------------------------------------------------------+
==== PERSISTENCE BOUNDARY (retained across frames): PropertyTrees (prepaint) + Tile cache (raster)
  -> NEEDS_COMPOSITE-only frame re-applies nodes, re-rasters dirty tiles only

 data flow:  ComputedStyle -> FragmentTree -> DisplayList -> LayerTree -> CompositorFrame

3.2 Component Responsibilities

  • rp-style (P1/P2) — Style stage, main thread. In: styled Elements + stylesheets + 258 matcher. Out: one Arc<ComputedStyle>/element. Gathers MatchedRules (decls+Origin+Specificity+source order), runs Cascade (origin → !important → specificity → source order), applies inheritance + initial/computed-value resolution via PropertyId/property DB; StyleResolver consults the sharing cache. Invariant: each PropertyId → exactly one computed value; identical input subtrees share one Arc<ComputedStyle>.
  • rp-boxtree (P3/P4) — Box/Render tree + layout driver. In: Arc<ComputedStyle> tree + viewport. Out: immutable FragmentTree. P3 resolves display, generates Anonymous boxes, assigns FormattingContext, collects Replaced/OutOfFlow; P4 runs block (margins+collapsing, widths/heights, BFC) + inline (line boxes, text runs) layout (flex/grid minimal, prod=124) → Fragments with LayoutRect. Invariant: FragmentTree immutable per frame; one Box → ≥1 Fragment (fragmentation).
  • rp-paint (P5/P6/P7) — Prepaint + Paint. In: FragmentTree. Out: PropertyTrees + DisplayList. P5 establishes StackingContexts + CSS 2.2 sec. 9.9 paint order; P6 builds Transform/Clip/Effect/Scroll trees, assigns PaintPropertyNode ids, stamps PropertyTreeState/chunk; P7 walks fragments in paint order emitting DisplayItems grouped into PaintChunks with visual_rect culling + RasterInvalidation. Invariant: DisplayList order = paint order (≠ DOM order); each item carries a PropertyTreeState.
  • property trees (P6, retained) — TransformTree/ClipTree/EffectTree/ScrollTree of PaintPropertyNodes decoupling paint from geometry. In: fragment geometry + style. Out: node ids referenced by PaintChunk/CompositorLayer. Core RenderingNG idea: scroll/composited transform mutates one node WITHOUT re-paint; compositor re-applies. Invariant: retained across frames; structural change dirties paint, value-only change stays NEEDS_COMPOSITE.
  • rp-composite (P8/P9/P10) — Compositor thread, post-Commit. In: Commit snapshot (DisplayList+PropertyTrees). Out: CompositorFrame. P8 layerizes via CompositingReason (Transform3D/WillChange/Animation/ScrollDependent/Overlap/…) + squashing → LayerTree; P9 tiles layers, schedules RasterTasks replaying chunks through 169 → Tile bitmaps (cache + invalidation); P10 applies TransformTree → CompositorFrame, runs off-main scroll + composited animation. Invariant: touches no main-thread state post-Commit; only invalidated tiles re-raster.
  • rp-pipeline (P0/P11/P12) — Orchestrator. Owns DocumentLifecycle/LifecycleStage, InvalidationFlags, FrameScheduler, Commit, RenderObjectId. update_lifecycle(doc, target) runs only dirty stages in order, skipping clean. Hierarchical invalidation NEEDS_STYLE⊇layout⊇paint⊇composite; NEEDS_COMPOSITE alone → compositor only (cheap/jank-free). FrameScheduler drives rAF + vsync ("update the rendering"), produces the Commit. Invariant: invalidation moves lifecycle backward; a frame walks forward; Commit is the single sync handoff.
  • rp-cli (P0) — The rpipe binary (std): frame, dump-stage (ComputedStyle/FragmentTree/DisplayList/LayerTree), trace-lifecycle (transitions + dirty bits), raster (PNG via 169), bench (stage timing + budget). In: scene+viewport; out: PNG/JSON/trace. Invariant: thin driver — orchestration lives in rp-pipeline.

8. Domain Model — Stages, Trees & the Lifecycle

A staged lifecycle: each stage consumes the prior stage's immutable output, gated by an InvalidationFlags dirty bit. update_lifecycle(doc, target) walks forward skipping clean stages; invalidation only ever moves lifecycle backward.

8.1 Stage data model (the spine)

Each stage = pure function prev_output → output, gated by one dirty bit, pinned to one thread.

stage             | input                          | output            | dirty bit       | thread       | owning crate
------------------|--------------------------------|-------------------|-----------------|--------------|-------------
Style             | styled DOM + stylesheets (124) + matcher(258)->MatchedRules | ComputedStyle/elt | NEEDS_STYLE     | main       | rp-style
Box/Render tree   | ComputedStyle tree             | BoxTree           | NEEDS_LAYOUT    | main         | rp-boxtree
Layout            | BoxTree                        | FragmentTree      | NEEDS_LAYOUT    | main         | rp-boxtree
CompositingInputs | FragmentTree                   | StackingContext + paint-order list | NEEDS_PAINT | main      | rp-paint
Prepaint          | FragmentTree + stacking        | PropertyTrees + PaintPropertyNode ids | NEEDS_PAINT | main   | rp-paint
Paint             | FragmentTree + PropertyTrees (paint order) | DisplayList (+ PaintChunks) | NEEDS_PAINT | main  | rp-paint
Commit            | DisplayList + PropertyTrees    | Commit (snapshot) | NEEDS_COMPOSITE | main->comp   | rp-pipeline
Layerize/Raster   | DisplayList + chunks           | LayerTree + Tiles (RasterTask via 169) | NEEDS_COMPOSITE | compositor | rp-composite
Composite         | LayerTree + TransformTree      | CompositorFrame   | NEEDS_COMPOSITE | compositor   | rp-composite

Data ownership: ComputedStyle Arc-shared (sharing cache); FragmentTree immutable per frame (one box → N fragments); DisplayList.items: Vec<DisplayItem> flat, sliced into PaintChunk ranges; Commit = the only main→compositor handoff (compositor must not touch main state after).

8.2 DocumentLifecycle state machine

LifecycleStage totally ordered; forward edges advance one stage iff its gating bit is set (else skipped); backward edges = invalidation (DOM/style mutation), clearing stage to the dirtied point.

forward walk: Clean -> Style -> Layout -> CompositingInputs -> Prepaint -> Paint -> Commit -> Composite -> Clean
  (each edge: run iff gate set, else skip)  gate: ->Style/Layout/CIn/Prepaint/Paint by NEEDS_STYLE|LAYOUT|PAINT (hierarchical, 8.3); ->Commit/Composite by NEEDS_COMPOSITE
backward invalidation edges (mutation -> set bit -> reset stage):
  trigger                                  | sets            | reset to
  attr/class/inline-style/sheet mutation   | NEEDS_STYLE     | Style
  geometry-affecting computed-value change | NEEDS_LAYOUT    | Layout
  color/bg/shadow (no geometry) change     | NEEDS_PAINT     | CompositingInputs
  scroll/composited transform/opacity tick | NEEDS_COMPOSITE | Commit (main stays Clean)

Invariant: target clamps the walk; e.g. hit-testing requests update_lifecycle(doc, Paint) (no compositor work), a vsync frame requests Composite.

8.3 Hierarchical invalidation

Setting a bit implies all downstream bits — strictly nested supersets:

NEEDS_STYLE      => + NEEDS_LAYOUT + NEEDS_PAINT + NEEDS_COMPOSITE   (full main + comp)
NEEDS_LAYOUT     =>                + NEEDS_PAINT + NEEDS_COMPOSITE
NEEDS_PAINT      =>                              + NEEDS_COMPOSITE
NEEDS_COMPOSITE  => compositor-only             (Style/Layout/Paint stay Clean -> cheap, jank-free)

This is why scroll/composited-animation are cheap: they set only NEEDS_COMPOSITE, skipping all main-thread stages.

8.4 CSS painting order & stacking contexts

A StackingContext { z_index, establishes } is established by: root; positioned + z_index != auto; opacity < 1; any transform/filter/will-change/clip-path; isolation:isolate. Paint order is per-context, recursive, NOT DOM order (CSS 2.2 sec. 9.9):

paint_stacking_context(ctx):                  // emit DisplayItems in this order
  1. ctx background + borders
  2. child stacking contexts with z-index < 0   (ascending z, then source order)
  3. in-flow, non-inline, non-positioned block-level descendants
  4. non-positioned floats
  5. in-flow inline-level descendants (line boxes)
  6. child stacking contexts z-index == 0/auto + positioned non-context descendants (source order)
  7. child stacking contexts with z-index > 0    (ascending z, then source order)

Hit testing = the reverse traversal (front-to-back: 7->1), first opaque hit wins. Tie-break within a z-bucket = source order (stable). z_index clamped to i32; equal z falls to source order — no ambiguity.

8.5 Property-tree model

Four trees decouple paint from geometry (the RenderingNG core idea). Each tree is a flat Vec<PaintPropertyNode>; a node = parent_id + local state; effective value = compose(parent..root).

tree           | PaintPropertyNode local state         | node id type   | mutated by (composite-only)
---------------|---------------------------------------|----------------|-----------------------------
TransformTree  | local affine (translate/scale/rotate) | TransformId    | composited transform anim, scroll
ClipTree       | clip rect / rounded-rect              | ClipId         | overflow clip changes
EffectTree     | opacity, blend, filter, isolation     | EffectId       | composited opacity anim
ScrollTree     | scroll offset + bounds                | ScrollId       | scroll (off-main)

PaintChunk.property_state: PropertyTreeState = 4-tuple (TransformId, ClipId, EffectId, ScrollId), the "current node" in each tree at emit. A DisplayItem references geometry indirectly — no absolute coords beyond its chunk's visual_rect; the compositor resolves position by composing the chunk's TransformId chain; BeginClip{node:ClipId}/BeginEffect{node:EffectId} push/pop inline. Consequence: scroll/composited transform updates one TransformTree/ScrollTree node and re-composites — no repaint.

8.6 Worked example — one frame

Input: <div style="transform:translateX(10px)"><p>hi</p></div>, viewport 800x600.

Style:    div -> ComputedStyle{display:block, transform:translateX(10px)}; p -> {display:block}; "hi" inherits color
Box tree: Box{Block, div} -> Box{Block, p} -> Box{Inline/Text "hi"}
Layout:   FragmentTree: Fragment{div, 0,0,800,18} > Fragment{p, 0,0,800,18} > Fragment{Text "hi", 0,0,14,18}
          (transform does NOT affect layout rect — it is a paint/composite property)
Stacking: div establishes a stacking context (has transform)
Prepaint: TransformTree[T0=identity(root), T1=translate(10,0) parent=T0]; ClipTree[C0=viewport] EffectTree[E0=root] ScrollTree[S0=root]; div+descendants chunk.property_state=(T1,C0,E0,S0)
Paint:    DisplayList.items=[Text{"hi", visual_rect 0,0,14,18}]; chunks=[PaintChunk{items:0..1, state:(T1,C0,E0,S0), visual_rect:0,0,14,18}]
Commit:   snapshot{DisplayList, PropertyTrees} -> compositor
Layerize: div has transform => CompositingReason::Transform3D; LayerTree.layers=[CompositorLayer{transform_node:T1, content:0..1, reasons:[Transform3D]}]
Raster:   tile 256x256 covering visual_rect; RasterTask replays chunk via 169 -> tile bitmap (Ready)
Composite:CompositorFrame{layers, transforms}; apply T1 => "hi" drawn at x=10

8.7 Worked example — invalidation

Three mutations on a clean document; each sets the minimal bit:

mutation                          | bit set         | reset to | stages re-run                          | cost
----------------------------------|-----------------|----------|----------------------------------------|--------
toggle class -> color:red (no geom)| NEEDS_PAINT    | CIn      | CIn,Prepaint,Paint,Commit,Layerize,Raster,Composite | ~paint
toggle class -> width:50%->80%     | NEEDS_LAYOUT    | Layout   | Layout..Composite (Style stays Clean)  | ~layout
scroll composited overflow container| NEEDS_COMPOSITE| Commit   | update ScrollTree node only; re-composite, NO repaint | <1ms, no jank

The scroll case is the payoff: update_lifecycle(doc, Composite) finds Style/Layout/Paint clean, skips them, bumps one ScrollTree.PaintPropertyNode.offset, and the compositor thread re-applies it — well under the 16.6ms budget with zero main-thread work.

8.8 Malformed / edge cases

case                        | handling
----------------------------|-----------------------------------------------------------------
deep nesting (>10k boxes)   | layout/paint explicit-stack iterative (no recursion); depth cap returns Err, never panics
huge z_index (e.g. i32::MAX)| clamped to i32; ordering by total Ord (well-defined), ties -> source order, no overflow in sort
0-area fragment (w=0/h=0)   | LayoutRect kept (hit-test/box-tree integrity), culled in Paint (empty visual_rect -> no emit, no RasterTask)
offscreen tile              | Tile outside viewport stays RasterState::Missing (raster-on-demand); scheduled on scroll-in -> bounded raster memory
cyclic-ish style ref / loop | trees acyclic by construction (parent_id < self in flat Vec); builder asserts monotonic ids -> cycle unrepresentable
empty DisplayList           | LayerTree has 0 content layers; CompositorFrame = clear frame (valid)

8.9 Main -> Commit -> Compositor handoff

 MAIN THREAD                                 COMPOSITOR THREAD
 -----------                                 -----------------
 FrameScheduler: vsync tick / rAF
 update_lifecycle(doc, Composite); run dirty Style..Paint
 build Commit{DisplayList, PropertyTrees}
      |====== Commit (snapshot, sync) ======>  receive Commit
   (main free: next rAF, input)                 Layerize -> LayerTree
                                                 schedule RasterTasks (tiles); replay chunks via 169
                                                 CompositorFrame{layers, transforms}
                                                 apply TransformTree -> display (vsync)
      <............ ack / damage region ..........|
 (scroll/anim while main busy: compositor mutates Scroll/Transform node, re-composites alone)

Commit = the single sync point: a handoff of DisplayList + PropertyTrees. Post-Commit the compositor owns its snapshot, main begins the next frame; the two never share mutable state — the data-race class Rust eliminates at compile time.
