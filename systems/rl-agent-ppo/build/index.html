⬜ Phase 0 — Repo Skeleton + Single Deterministic Env + CI §12

Objectives
  • Stand up the src/-layout package (ADR-24), pyproject.toml, and CI (ADR-23).
  • Construct one deterministic environment (CartPole-v1) through EnvSpec (§11); Phase 0 is intentionally single-env to validate the seam before batching begins in Phase 7 (P2 applies from Phase 2 onward).
  • Establish the seeding contract (P3) end to end: config seed -> env seed -> RNG.
  • Land the run-manifest writer (P11) before any training logic exists.
Deliverable

A pip-installable package that constructs one seeded CartPole-v1 instance via EnvSpec, resets and steps it under a random policy for a fixed number of steps, and writes a run manifest — with CI green on lint, unit tests, and the Phase 0 smoke fixture.

Acceptance
  • pytest tests/unit passes, 0 failures, on Python 3.11.
  • Two runs with seed=0 produce byte-identical sequences of 100 env-step observations (I9).
  • Run manifest file exists and contains all fields enumerated in P11 before step 1 begins.
  • CI nightly.yml completes the Phase 0 smoke fixture in under 30 seconds.
Fixtures
  • tests/fixtures/tiny_envs.py::seeded_cartpole_100_steps — golden file of 100 (obs, reward, terminated, truncated) tuples for seed=0; regression target for I9.
  • tests/unit/test_seeding.py::test_malformed_seed — negative-int and non-int seeds raise EnvContractError at config load, not deep inside EnvSpec.make().
  • tests/unit/test_seeding.py::test_seed_replay — seeded-replay case: re-running with the manifest's recorded seed reproduces the golden file exactly.
Pitfalls
  • Forgetting to seed action_space/observation_space alongside env.reset(seed=...) — Gymnasium's space sampling has its own RNG stream; manifests as flaky tests that pass locally, fail in CI.
  • A module-level logging.basicConfig() call that silently becomes global mutable state — violates P12; debug by constructing two loggers in one test process and checking for cross-talk.
  • Writing the run manifest after the first training step instead of before — breaks ADR-27's guarantee; detect via a crash-mid-step test that checks the manifest still exists.

⬜ Phase 1 — Space/Env API Contract + Conformance Harness §13

Objectives
  • Formalize the Gymnasium env/VecEnv API contract as an executable conformance suite (P1, ADR-03).
  • Land space taxonomy dispatch for Discrete (§8 taxonomy table), ahead of Phase 9's Gaussian head.
  • Guarantee the terminated/truncated distinction is observable and tested (I4) before any bootstrap math exists.
Deliverable

An executable conformance harness that any gymnasium.Env-compatible instance can be run through, plus Discrete-only action-distribution dispatch and a verified terminated/truncated contract.

Acceptance
  • conformance/env_api_contract.py passes against CartPole-v1 and the custom TwoStateMdp with 0 failures across all six Env API Contract rows (§8).
  • test_two_state_mdp.py hand-verifies 3 episodes — one terminated, one truncated, one neither — with exact expected reward sums.
  • Malformed-input fixtures (out-of-range action, NaN reward, shape mismatch) each raise EnvContractError, never a bare AssertionError or silent pass.
Fixtures
  • conformance/fixtures/cartpole_contract.json — golden expected shapes/dtypes per §8 table row.
  • tests/fixtures/malformed_configs/action_out_of_range.yaml — malformed case; expected output: EnvContractError at VecEnv.step (not at agent forward pass).
  • tests/unit/test_two_state_mdp.py::test_seeded_replay — seeded-replay regression across 3 episode types.
Pitfalls
  • Trusting Gymnasium's own TimeLimit wrapper to always fire truncated and never accidentally also set terminated — verify explicitly rather than assume, since a custom env's own logic can violate this.
  • Treating a Discrete action tensor's dtype (int64 from torch.distributions.Categorical.sample()) as directly compatible with env.action_space (int64 numpy) without an explicit cast — silent dtype mismatches surface only in stricter env implementations.
  • Building the conformance harness against one specific env's quirks instead of the general contract table — makes it useless for the next env added in Phase 9.

⬜ Phase 2 — Random-Policy Rollout Loop + Buffer §14

Objectives
  • Implement RolloutBuffer (§11) as pre-allocated (T,N,...) arrays, N=1 in this phase (P2's N=1 case).
  • Implement env_runner.collect_rollout driving a uniform-random policy through T steps.
  • Establish I1/I3/I5 (buffer lifecycle invariants) with unit tests before any learning exists.
Deliverable

A working COLLECT state (§8 state machine) that fills a RolloutBuffer from a uniform-random policy over CartPole-v1, with the buffer lifecycle invariants (I1, I3, I5) enforced and tested.

Acceptance
  • collect_rollout fills a (T=128, N=1) buffer in under 20 ms wall clock on the reference 8-core CPU (a looser bound than §4's N=8 target, since N=1 pays full per-step Python overhead per transition).
  • test_rollout_buffer.py asserts buffer array base-pointer identity is unchanged across 128 add() calls (proves pre-allocation, I5).
  • RolloutBuffer.reset() followed by an attempted read before any add() raises BufferStateError (I3).
Fixtures
  • tests/fixtures/synthetic_rollouts.py::random_policy_128_steps — golden 128-step buffer dump for seed=0, uniform-random policy; regression target.
  • tests/unit/test_rollout_buffer.py::test_overfull_buffer — malformed case: a 129th add() call on a T=128 buffer raises BufferStateError, never silently overwrites index 0.
  • tests/unit/test_rollout_buffer.py::test_seeded_replay — same seed, two runs, byte-identical buffer contents.
Pitfalls
  • Allocating buffer arrays inside collect_rollout instead of RolloutBuffer.__init__ — reintroduces the OOM-on-step-N growth bug I5 exists to prevent.
  • Confusing "buffer full" (t == T) with "buffer valid for reading" — a buffer can be full but not yet finalized (no GAE run yet, Phase 4); as_flat_tensors() must not be callable until finalize() has run (enforced starting Phase 4).
  • Using Python's built-in random module anywhere in the rollout loop instead of the agent-owned Generator — violates P3/I6 even though no learning exists yet in this phase.

⬜ Phase 3 — Policy/Value Networks + Forward Contracts §15

Objectives
  • Implement ActorCritic (separate policy/value networks, ADR-10) satisfying the PolicyNetwork / ValueNetwork protocols (§11).
  • Apply orthogonal initialization with the exact gains of ADR-11.
  • Replace Phase 2's uniform-random policy with a real forward pass, still with no gradient update (that is Phase 5).
Deliverable

An ActorCritic network wired into the rollout loop, producing real (distribution, value, log_prob) outputs per step, with orthogonal initialization and a tested forward contract.

Acceptance
  • test_distributions.py matches hand-computed Categorical log_prob/entropy to within 1e-6 absolute error.
  • A freshly initialized ActorCritic on CartPole-v1's 4-dim observation produces a value estimate with abs(value) < 5.0 for at least 95% of 1,000 sampled observations (a sanity bound on init scale, not a learning claim).
  • Forward-contract test passes for both B=1 and B=128 without code-path branching (P2).
Fixtures
  • tests/unit/test_distributions.py::test_categorical_closed_form — golden closed-form log_prob/entropy for a fixed 4-logit vector.
  • tests/unit/test_distributions.py::test_malformed_action_shape — malformed case: an action tensor with the wrong trailing dimension raises EnvContractError at make_distribution, not deep in .log_prob().
  • tests/integration/test_forward_contract.py::test_seeded_init_replay — seeded-replay: identical init seed produces byte-identical first-forward-pass outputs across two runs.
Pitfalls
  • Using PyTorch's default Kaiming/Xavier init because it "should be fine" — Huang et al. 2022 documents measurable final-return degradation from this exact substitution (ADR-11).
  • Sharing a single trunk "for parameter efficiency" without reading Andrychowicz et al. 2021 first — the paper's finding that separate networks win on most swept tasks is the basis for ADR-10, not a default assumption.
  • Computing log_prob from a re-sampled action rather than the action actually taken and stored in the buffer — a subtle mismatch that silently corrupts every downstream ratio computation from Phase 5 onward.

⬜ Phase 4 — GAE + Advantage Normalization §16

Objectives
  • Implement compute_gae (§11) exactly per the §8 backward recursion, satisfying I4 and I7.
  • Wire RolloutBuffer.finalize() to call compute_gae and populate advantages/returns in place.
  • Implement per-rollout advantage normalization (P4, ADR-07) as a config-gated step applied once per finalized batch.
Deliverable

A RolloutBuffer.finalize() that produces mathematically verified GAE advantages and returns, with advantage normalization as an explicit, tested, toggleable step.

Acceptance
  • test_gae.py's 5-step fixture matches the §8 worked example's A_t/R_t values to 1e-4 absolute tolerance for all t in {0..4}.
  • test_gae.py's lambda=0 fixture matches 1-step TD residuals exactly (1e-6 tolerance); lambda=1 fixture matches Monte-Carlo-return-minus-value exactly.
  • With normalize_advantages=True, the flattened advantage batch has abs(mean) < 1e-6 and abs(std - 1.0) < 1e-3 post-normalization.
  • gae_compute_ms for a (T=128, N=8) rollout is under the §4 rollout-collection latency budget's contribution (sub-millisecond; GAE itself is O(T*N), not the bottleneck).
Fixtures
  • tests/unit/test_gae.py::test_five_step_worked_example — the §8 table, encoded as exact expected floats.
  • tests/unit/test_gae.py::test_lambda_zero_boundary — property fixture: GAE reduces to 1-step TD (I7 regression target).
  • tests/unit/test_gae.py::test_lambda_one_boundary — property fixture: GAE reduces to Monte-Carlo return.
  • tests/unit/test_gae.py::test_malformed_shape_mismatch — malformed case: rewards.shape != values.shape raises BufferStateError, never a silent NumPy broadcast.
  • tests/unit/test_gae.py::test_terminated_vs_truncated — seeded-replay regression proving I4: a truncated episode's A_t differs from an otherwise-identical terminated episode's A_t by exactly the bootstrap term gamma * V(s_{t+1}).
Pitfalls
  • Using 1 - dones[t] instead of 1 - dones[t+1] as the bootstrap mask — an off-by-one that silently shifts every advantage by one timestep; caught only by the hand-computed fixture, never by a shape check.
  • Merging terminated and truncated into dones for the recursion's mask term but then also using the merged flag for the bootstrap-source decision — violates I4; the recursion's zeroing mask and the bootstrap-source rule are two different uses of two different flags.
  • Normalizing advantages before finalize() has fully populated the returns array — silently normalizes a zero-filled or partially-filled array on a code path that races finalize()'s two sub-steps.

⬜ Phase 5 — PPO Clipped-Surrogate Learner §17

Objectives
  • Implement the clipped surrogate objective, pessimistic value loss, entropy bonus, and their combination into a single scalar loss (§8 equations).
  • Implement the K-epoch, M-minibatch update loop with the T-major-then-N flatten order and agent-owned shuffle RNG (I6).
  • Implement KL-budget early stopping (P7, I14) and LR annealing (ADR-14).
Deliverable

A complete PPO update step: given a finalized RolloutBuffer, produces UpdateStats (§11) and mutates network parameters exactly once per minibatch step, with KL-budget early stopping and LR annealing active.

Acceptance
  • CartPole-v1 mean episodic return reaches >= 475 (over 100 consecutive eval episodes) within 30,000 env steps, matching the §4 wall-clock target of <= 90 s on the 8-core reference CPU.
  • test_clipped_surrogate.py matches hand-computed L_CLIP values at the four boundary ratios to 1e-6.
  • kl_early_stop_epoch (I14 telemetry) is logged every update; across the CartPole acceptance run it fires on fewer than 5% of updates (a well-tuned run rarely needs it, per §5 citation 9's Huang et al. finding).
  • clip_fraction telemetry (ADR-21) is nonzero but below 0.3 by the final 10% of training (proof the clip is active but not dominating).
Fixtures
  • tests/unit/test_clipped_surrogate.py::test_clip_boundary — the four-ratio hand-computed fixture.
  • tests/unit/test_value_loss.py::test_pessimistic_clip — fixture with V_old, V_new, return chosen so the clipped and unclipped terms disagree, asserting the max() selects correctly.
  • tests/integration/test_cartpole_smoke.py::test_return_threshold — regression: 30,000-step run hits return >= 475; seeded-replay across two CI runs must match within +/- 5 return (float nondeterminism tolerance on GPU only; CPU must match exactly per I9).
  • tests/unit/test_clipped_surrogate.py::test_malformed_ratio — malformed case: a NaN ratio (from a degenerate log-prob) raises before entering the min()/clip() chain, never silently propagating NaN into the optimizer.
Pitfalls
  • Computing the surrogate loss to maximize rather than minimize by forgetting the sign flip in the total objective L(theta) = -L_CLIP + ... — trains a policy that anti-optimizes, producing a return curve that goes down instead of up, easily mistaken for "not learning" rather than "learning the opposite." cross-ref: §8 total-objective equation.
  • Flattening (T,N) in N-major-then-T order instead of T-major-then-N — every array remains internally consistent but silently mismatched against any external tool (e.g. a differential test against CleanRL, Phase 11) that assumes the canonical order.
  • Checking the KL early-stop condition inside the minibatch loop instead of between epochs — violates I14 and produces inconsistent behavior depending on minibatch count.
  • Using PyTorch's default Adam eps=1e-8 instead of 1e-5 — a one-character diff (ADR-13) that measurably slows convergence on the CartPole acceptance benchmark.

⬜ Phase 6 — Observation/Reward Normalization §18

Objectives
  • Implement RunningMeanStd (§11) and wire it as observation_normalize.py and reward_scale.py wrappers (ADR-08, ADR-09).
  • Enforce I2 (frozen statistics at eval) and I5-adjacent checkpoint inclusion (I10) for normalizer state.
  • Validate empirically that normalization improves LunarLander-v2 convergence over the un-normalized Phase 5 baseline.
Deliverable

Observation and reward normalization wrappers with checkpointed running statistics, frozen at evaluation, validated to improve LunarLander-v2 convergence over the Phase 5 unnormalized baseline.

Acceptance
  • LunarLander-v2 mean episodic return reaches >= 200 within 1,000,000 env steps with normalization enabled, matching the §4 wall-clock target (<= 35 min CPU / <= 12 min GPU).
  • The same config with normalize_observations=False either fails to reach return 200 within the same step budget or reaches it measurably later — recorded as an ablation data point feeding Phase 8 (§20).
  • test_running_stats.py Welford-vs-batch comparison passes at 1e-6 tolerance.
  • A checkpoint saved mid-training and reloaded produces identical RunningMeanStd.mean/var to the pre-save values (I10 regression).
Fixtures
  • tests/unit/test_running_stats.py::test_welford_matches_batch — numeric parity fixture.
  • tests/unit/test_running_stats.py::test_frozen_at_eval — I2 regression: 1,000 normalize() calls with training=False leave mean/var bit-identical.
  • tests/unit/test_running_stats.py::test_malformed_batch_shape — malformed case: a batch whose trailing dimension mismatches the normalizer's configured shape raises EnvContractError.
  • tests/integration/test_checkpoint_resume.py::test_normalizer_stats_roundtrip — seeded-replay: save, reload, re-run 100 steps, compare against a no-reload control run.
Pitfalls
  • Updating reward-normalizer statistics during the eval harness's episodes — a direct I2/I11 violation that inflates eval numbers by leaking eval-time reward distribution into future training-time scaling.
  • Clipping observations to +/- obs_clip before computing the running mean/var instead of after normalizing — silently biases the statistics toward the clip bounds rather than the true distribution.
  • Forgetting to include normalizer_stats in the checkpoint (I10) — produces the exact P5-named failure: a policy that trained well but evaluates poorly because the loaded checkpoint has no running stats and falls back to identity normalization.

Objectives
  • Implement SyncVectorEnv (ADR-04) satisfying VecEnvProtocol (§11), generalizing every prior phase's N=1 code path to arbitrary N (P2).
  • Meet the §4 vectorized throughput targets for N=8 and validate the N=128 sync ceiling.
  • Prove that no training-loop code required an N=1-specific branch (P2's central claim).
Deliverable

A SyncVectorEnv implementation meeting the §4 throughput targets at N=8, validated for parity against independent single-env runs, with the training loop unmodified from Phase 2 onward except for shape.

Acceptance
  • N=8 sync vectorized throughput measures 35,000 - 45,000 steps/s on the reference 8-core CPU (§4).
  • N=128 measures at or below the 120,000 steps/s ceiling (§4); a config requesting N > 128 logs a throughput-ceiling warning per ADR-04's ceiling note.
  • test_vector_env_parity.py shows byte-identical per-env-index observation trajectories between the vectorized run and 8 independent single-env runs sharing the same per-env seed.
  • CartPole-v1 wall clock to return >= 475 at N=8 matches or improves on the Phase 5 N=1 wall-clock baseline (§4's <= 90 s target).
Fixtures
  • benchmarks/cartpole_results.jsonl::vec_env_throughput_N8_N64_N128 — recorded steps/second at each N, regression-checked against the §4 table on every release (ADR-26).
  • tests/integration/test_vector_env_parity.py::test_per_env_seed_isolation — seeded-replay: env index 3 under N=8 produces the identical trajectory to a standalone N=1 run seeded seed+3.
  • tests/integration/test_vector_env_parity.py::test_malformed_action_batch — malformed case: an action batch of shape (N-1, ...) (one short) raises EnvContractError at SyncVectorEnv.step, never a silent NumPy broadcast that drops the last env.
Pitfalls
  • Autoreset that reuses the pre-reset observation in the batched output instead of the fresh post-reset observation — silently feeds the agent one stale observation per episode boundary, at every env, for the entire training run.
  • Deriving per-env seeds as seed * idx instead of seed + idx — collapses to identical seeds for idx=0 regardless of seed, silently reducing effective diversity across envs.
  • Assuming SyncVectorEnv's sequential inner loop preserves wall-clock determinism identically to AsyncVectorEnv — it does, but only because sync is the chosen default (ADR-04); do not generalize this assumption to the deferred async backend without re-deriving I9's guarantee.

⬜ Phase 8 — Implementation-Details Ablation Matrix §20

Objectives
  • Build a config-driven ablation harness toggling every Huang et al. 2022 "37 details" flag already present in this codebase's config surface (§11's PPOConfig) without code changes.
  • Reproduce, on CartPole-v1 and LunarLander-v2, the qualitative direction (not necessarily the exact magnitude) of each Andrychowicz et al. 2021 finding cited in §5.
  • Produce a written ablation report feeding future ADR reconsideration (§9's living-decision framing).
Deliverable

A repeatable, config-only ablation sweep runner plus a written report (docs/hyperparameters.md) confirming or refuting each cited paper's finding against this codebase's own benchmarks.

Acceptance
  • At least 8 flag pairs (16 total runs x 5 seeds = 80 runs) complete on both CartPole-v1 and LunarLander-v2 within the sweep runner's total wall-clock budget of 6 hours on the reference 8-core CPU.
  • The normalize_advantages on/off pair reproduces Andrychowicz et al. 2021's qualitative direction (on beats off) on at least 4 of 5 seeds for LunarLander-v2.
  • The adam_eps=1e-5 vs 1e-8 pair reproduces Huang et al. 2022's finding of measurably faster convergence with 1e-5 on at least 4 of 5 seeds.
  • docs/hyperparameters.md names, for every ablated flag, the winning setting and the specific benchmarks/*.jsonl run IDs supporting it.
Fixtures
  • benchmarks/cartpole_results.jsonl::ablation_normalize_advantages — 5-seed on/off pair, regression target.
  • benchmarks/lunarlander_results.jsonl::ablation_adam_eps — 5-seed on/off pair, regression target.
  • tests/integration/test_ablation_sweep.py::test_malformed_flag_combo — malformed case: a config requesting shared_trunk=True together with a not-yet-existent recurrent flag combination raises EnvContractError at config validation (ADR-18), never silently ignoring the unsupported combination.
  • tests/integration/test_ablation_sweep.py::test_seeded_replay — one flag pair's 5-seed sweep reproduces identical final returns across two independent CI runs (I9, CPU-only).
Pitfalls
  • Running each ablation arm on a single seed and treating the result as conclusive — RL return curves have high seed variance (Henderson et al. 2018); the 5-seed minimum in 20.4 exists specifically to guard against this.
  • Ablating a flag whose effect is confounded with another already-toggled flag in the same run (e.g. disabling normalize_advantages while also disabling clip_value_loss) — the sweep runner must vary exactly one flag per pair, holding all others at their ADR-locked default.
  • Treating a qualitative-direction match as a magnitude match — this phase's acceptance criteria (20.4) deliberately require only direction agreement, not exact percentage reproduction of the cited papers' numbers, since hardware and env-version differences shift magnitudes.

⬜ Phase 9 — Continuous-Action Support (Gaussian Policy) §21

Objectives
  • Extend make_distribution (P6) to Box action spaces via a diagonal Gaussian with state-independent log-std (ADR default per Andrychowicz et al. 2021's finding, cited §5).
  • Validate on LunarLanderContinuous-v2 without modifying compute_gae, PpoUpdater, or RolloutBuffer (proving P6's single-dispatch-point claim).
  • Extend the conformance harness (Phase 1) to cover the Box row of §8's space taxonomy table.
Deliverable

Gaussian-policy continuous-action support validated end-to-end on LunarLanderContinuous-v2, with zero modifications to the GAE, PPO-update, or buffer core (only the single make_distribution dispatch point and the policy head extended).

Acceptance
  • LunarLanderContinuous-v2 mean episodic return reaches >= 200 within 1,000,000 env steps, matching the §4 wall-clock target adjusted for the continuous action head's marginally larger parameter count (<= 40 min CPU / <= 14 min GPU).
  • git diff between Phase 8's final state and this phase's buffer/, agent/ppo_update.py, and agent/ losses.py shows zero changes (P6 structural-isolation proof).
  • Gaussian closed-form log_prob/entropy test passes at 1e-6 tolerance.
  • The Box-space conformance fixture passes all six §8 Env API Contract rows.
Fixtures
  • conformance/fixtures/lunarlander_continuous_contract.json — golden expected shapes/dtypes for the Box space row.
  • tests/unit/test_distributions.py::test_gaussian_closed_form — closed-form Gaussian log_prob/entropy fixture.
  • tests/unit/test_distributions.py::test_malformed_box_bounds — malformed case: an action space with low > high on any dimension raises EnvContractError at agent construction, not at first step().
  • tests/integration/test_lunarlander_continuous_smoke.py::test_seeded_replay — 1,000,000-step seeded regression (CPU determinism, I9).
Pitfalls
  • Clamping the sampled action before computing log_prob, silently introducing a density mismatch between the action actually executed in the env and the log-probability the clipped surrogate assumes.
  • Making log_sigma state-dependent (a function of the observation) as a "more expressive" default without reading Andrychowicz et al. 2021 first — the paper's finding motivating the state-independent default is task-dependent, and state-dependent log-std has a documented tendency to collapse to near-zero variance early in training on low-dimensional control tasks.
  • Reusing the Discrete-space entropy formula's shape assumptions (entropy() returning a scalar per sample) without checking that Independent(Normal(...), 1)'s entropy correctly sums across action dimensions rather than returning a per-dimension vector.

⬜ Phase 10 — Checkpointing, Resume, Seeded Reproducibility §22

Objectives
  • Implement CheckpointRecord (§11) persistence via safetensors + JSON sidecar (ADR-17), bundling all five I10 fields.
  • Implement resume-from-checkpoint that reproduces I9's bitwise-determinism guarantee across a process-restart boundary, not just within a single process.
  • Implement format_version compatibility checking (§27) and CheckpointCompatibilityError.
Deliverable

A checkpoint/resume subsystem meeting the <= 2 MiB checkpoint-size and <= 10 s RTO targets (§4), with bitwise-identical resumed training curves versus an uninterrupted control run.

Acceptance
  • Checkpoint file size <= 2 MiB for the MLP(64,64) CartPole/LunarLander configs (§4).
  • Resume-from-checkpoint completes in <= 10 s from cold process start to the first resumed training step (§4 RTO).
  • test_checkpoint_resume.py's interrupted-vs-control comparison matches byte-for-byte on CPU across the post-checkpoint 15,000 steps.
  • Loading a checkpoint with a deliberately corrupted format_version field raises CheckpointCompatibilityError, never a downstream KeyError/ValueError from a partially-parsed sidecar.
Fixtures
  • tests/integration/test_checkpoint_resume.py::test_interrupted_vs_control — the core seeded-replay regression described in 22.2 step 5.
  • tests/integration/test_checkpoint_resume.py::test_malformed_checkpoint — malformed case: a truncated safetensors file raises a clear I/O error at load, not a silent zero-filled weight tensor.
  • tests/integration/test_checkpoint_resume.py::test_version_mismatch — malformed case: format_version newer than supported raises CheckpointCompatibilityError with the specific version numbers in the message.
  • conformance/fixtures/checkpoint_v1_golden.safetensors — a golden fixed-seed checkpoint used to catch accidental format drift across releases (ADR-26).
Pitfalls
  • Checkpointing model weights without the PpoUpdater's shuffle-RNG state — a resumed run's minibatch order diverges from the control run from the very first post-resume update, silently breaking I9 while every other field matches.
  • Using torch.save for convenience "just for the sidecar" — reintroduces the pickle attack surface ADR-17 specifically rejected (T1, §24), even if the main weights are safetensors.
  • Bumping format_version for a non-breaking addition (e.g. a new optional metadata field) — needlessly triggers CheckpointCompatibilityError for otherwise-loadable old checkpoints; §27 reserves major-version bumps for genuinely breaking schema changes.

  • tests/integration/test_differential_cleanrl.py::test_cartpole_fixed_seed — the CleanRL differential regression, pinned to a specific CleanRL commit SHA.
  • fuzz/fuzz_config_parser.py::corpus/ — seeded fuzz corpus, regenerable but versioned for reproducible fuzzing regressions.
  • tests/integration/test_eval_harness.py::test_disjoint_seed_isolation — malformed/edge case: an eval config accidentally reusing a training seed range raises EnvContractError at eval-harness construction.
Pitfalls
  • Running the differential test against an unpinned CleanRL main branch — CleanRL's own defaults drift over time, making a "divergence" finding meaningless without a pinned commit SHA.
  • Treating every fuzz-discovered crash as a fuzz-harness bug rather than triaging each one — Henderson et al. 2018's broader point about RL fragility applies equally to config/space parsing robustness.
  • Reusing a training env instance for eval "to save construction cost" — directly violates P10/I11 even if the seed is reset first, because normalizer wrapper state may still be attached to the same instance.
