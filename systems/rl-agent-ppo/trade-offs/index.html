Decisions (§9) · 28 ADRs

ADR-01

Language

Chosen

Python 3.11

Rejected

Rust; Julia; C++

When the rejected choice is right

Rust wins when the env-runner itself must run allocation-free above 1M steps/s/core (deferred Phase-12 gRPC bridge, §36)

Why: Reference impls (CleanRL/SB3/Tianshou) are Python; fastest iteration for ablations

ADR-02

Framework

Chosen

PyTorch >= 2.1

Rejected

TensorFlow 2.x; JAX/Flax

When the rejected choice is right

JAX wins when training needs vmap/pmap-batched simulation across thousands of parallel envs on TPU (Brax/PureJaxRL regime)

Why: torch.distributions gives correct Categorical/Normal log_prob/entropy out of the box

ADR-03

Env API

Chosen

Gymnasium >= 0.29

Rejected

legacy OpenAI Gym (4-tuple); PettingZoo

When the rejected choice is right

legacy Gym wins only when maintaining an unmodifiable pre-2021 codebase that cannot absorb the 5-tuple migration

Why: terminated/truncated split fixes the bootstrap-at-time-limit bug (I4)

ADR-04

Vectorization strategy (default)

Chosen

SyncVectorEnv, single process

Rejected

AsyncVectorEnv (subprocess); single-env loop

When the rejected choice is right

AsyncVectorEnv wins once env-step cost exceeds ~1ms and num_envs > 64, e.g. Atari-class pixel envs (deferred, §36)

Why: deterministic, debuggable, fast enough for CartPole/LunarLander (I9)

ADR-05

Vectorization backpressure

Chosen

blocking synchronous step, bounded by slowest env

Rejected

unbounded async queue with worker pool

When the rejected choice is right

unbounded async queue wins in a production inference-serving context where per-request latency variance must be hidden

Why: a slow/hanging env stalls the rollout visibly rather than building a silent backlog

ADR-06

Advantage estimator

Chosen

GAE-lambda (lambda=0.95)

Rejected

n-step returns (n=5); 1-step TD; full Monte-Carlo

When the rejected choice is right

n-step wins when episodes are shorter than n, e.g. single-step bandit-style tasks

Why: continuous bias-variance knob (Schulman ICLR 2016); dominates n-step empirically

ADR-07

Advantage normalization scope

Chosen

per-rollout (T*N) batch

Rejected

per-minibatch; running cross-rollout normalizer

When the rejected choice is right

a running cross-rollout normalizer wins in continual, near-stationary-policy settings where variance reduction outweighs freshness

Why: Andrychowicz 2021: per-rollout consistently better; per-minibatch introduces scale-inconsistent gradients (P4)

ADR-08

Observation normalization

Chosen

running mean/std per-env-vector, clipped +/-10, frozen at eval (I2)

Rejected

none; min-max scaling; first-layer LayerNorm

When the rejected choice is right

min-max wins when observation bounds are exactly known and stationary, e.g. a synthetic unit-test MDP

Why: standard practice (CleanRL/SB3); LayerNorm alone does not fix cross-episode reward-scale drift

ADR-09

Reward processing

Chosen

running-std scaling of discounted return

Rejected

sign-clipping to {-1,0,1}; raw reward

When the rejected choice is right

sign-clipping wins on rewards spanning many orders of magnitude, i.e. the deferred Atari regime (§36)

Why: preserves magnitude ordering for MLP-scale rewards (CartPole/LunarLander)

ADR-10

Actor-critic architecture

Chosen

separate policy/value networks

Rejected

shared trunk + two heads; shared trunk + auxiliary losses (PPG)

When the rejected choice is right

shared trunk wins under tight parameter/memory budgets, e.g. edge deployment of one small policy+value blob

Why: Andrychowicz 2021: separate nets ease reasoning, slightly outperform on swept tasks

ADR-11

Network initialization

Chosen

orthogonal, gain sqrt(2) hidden / 0.01 policy head / 1.0 value head

Rejected

PyTorch default (Kaiming/Xavier); zero-init last layer

When the rejected choice is right

Kaiming default wins when transferring a pretrained CNN encoder whose init is already fixed

Why: Huang 2022 details #4-6; canonical Baselines/SB3 setting

ADR-12

Activation function

Chosen

tanh (MLP)

Rejected

ReLU everywhere; GELU; SiLU

When the rejected choice is right

ReLU wins for CNN encoders on pixel input (deferred Atari regime, §36)

Why: bounded output pairs well with the Gaussian log-std parameterization

ADR-13

Optimizer

Chosen

Adam, lr=3e-4, eps=1e-5

Rejected

SGD+momentum; AdamW; RMSProp

When the rejected choice is right

SGD+momentum wins in extremely compute-constrained embedded training where Adam's per-parameter state doubles memory

Why: eps=1e-5 (Huang 2022 #11) stabilizes PPO's near-zero gradients

ADR-14

LR schedule

Chosen

linear anneal to 0 over total_env_steps

Rejected

constant; cosine; warmup+constant

When the rejected choice is right

cosine wins when total_env_steps is unknown in advance, e.g. open-ended curriculum training

Why: canonical SB3/CleanRL default

ADR-15

Dtype

Chosen

float32 throughout (obs, buffer, network)

Rejected

float64; bfloat16/mixed precision

When the rejected choice is right

bfloat16/mixed precision wins once a CNN encoder (deferred) makes the forward/backward pass GPU-compute-bound

Why: matches Gymnasium's float32 obs convention; avoids fp16's noise floor on small MLPs

ADR-16

RNG / determinism

Chosen

per-component seeded Generator objects, no global RNG (P3, I6)

Rejected

a single global np.random/torch.manual_seed

When the rejected choice is right

a single global seed wins only in a single-threaded teaching script with no cross-component reproducibility requirement

Why: isolates randomness sources so one component's change cannot perturb another's draw sequence

ADR-17

Checkpoint format

Chosen

safetensors weights + JSON sidecar (config, RNG state, normalizer stats)

Rejected

raw torch.save (pickle); ONNX export

When the rejected choice is right

torch.save/pickle wins only in a fully trusted, single-operator local loop where monolithic-blob load speed matters most

Why: avoids arbitrary code execution on load (T1, §24)

ADR-18

Config system

Chosen

frozen dataclass + YAML loader with schema validation

Rejected

argparse-only flags; Hydra

When the rejected choice is right

Hydra wins once the project needs multirun sweeps composed from many override groups

Why: the dataclass is the single reproducibility contract (I9); validates divisibility at load

ADR-19

Logging

Chosen

structured JSONL + TensorBoard scalars

Rejected

When the rejected choice is right

W&B-only wins once a multi-operator team needs shared dashboards and cross-run comparison at scale

Why: JSONL is diffable/greppable in CI; TensorBoard gives the entropy/KL curves engineers read

ADR-20

Tracing

When the rejected choice is right

36. Alternative Architectures (Roads Not Taken)

Design 1 — Off-policy replay-based learning (SAC/DQN) instead of on-policy PPO.

+---------+  step   +--------+  (s,a,r,s') +----------------+
| Env     |<------->| Agent  |------------>| Replay Buffer  |
+---------+         +--------+             | (large, FIFO)  |
                          ^                +-------+--------+
                          |     sample minibatch (off-policy) |
                          +------------------------------------+

Winning regime: sample-efficiency-critical continuous control (MuJoCo/DeepMind Control Suite) or discrete control with cheap, replayable transitions (Atari at fixed compute budgets). Embodying system: Stable- Baselines3's SAC/DQN implementations (same repo, different algorithm family, §5 citation 4/13). Rejected because: this blueprint's non-goals (§1) explicitly target the on-policy family reusable across A2C/IMPALA/ PPG (§2); a replay buffer's data-freshness and target-network machinery is a fundamentally different set of invariants than I1/I3, not an incremental extension of them.

Design 2 — Distributed actor-learner with off-policy correction (IMPALA V-trace).

+--------+   +--------+   +--------+
| Actor 1|   | Actor 2|   | Actor N|   (many machines, slightly stale policy)
+---+----+   +---+----+   +---+----+
    |            |            |
    +------------+------------+
                 v
         +---------------+     V-trace off-policy
         | Central Learner|<--- correction for staleness
         +---------------+

Winning regime: massive-scale training where actor throughput must scale past a single process's ceiling (M12) across many machines. Embodying system: DeepMind's IMPALA / Acme framework (Espeholt et al. 2018, §5). Rejected because: this blueprint's deployment model (§1) is explicitly single-process; V-trace's importance-weighted correction is a different trust-region mechanism than PPO's clip (MM1), and adopting it would replace, not extend, the §17 learner core.

Design 3 — Evolution strategies / random search as a gradient-free alternative.

+------------------+    perturb theta    +------------------+
| Population of N   |-------------------->| Evaluate return  |
| perturbed policies|                     | per perturbation |
+------------------+<--------------------+------------------+
         weighted-average update toward higher-return perturbations

Winning regime: reward signals too sparse or non-differentiable for policy-gradient methods, or when massive embarrassingly-parallel compute is cheaper than careful gradient engineering. Embodying system: OpenAI's Evolution Strategies as a scalable alternative to RL (Salimans et al. 2017 lineage). Rejected because: this blueprint's mastery goal (§2) is specifically the policy-gradient/advantage-estimation skillset (GAE, clipped surrogate); ES requires no backward pass at all, which would eliminate rather than exercise the domain model of §8.

Design 4 — Model-based rollouts in a learned world model.

+--------+  real   +------------+  imagined rollouts  +-------------+
| Env    |-------->| World Model|-------------------->| Policy Update|
+--------+  data    +------------+   (cheap, no env)   +-------------+

Winning regime: environments where real interaction is expensive or dangerous (robotics, some sim-to-real pipelines), trading model-bias risk for sample efficiency. Embodying system: Dreamer-family world-model agents. Rejected because: this blueprint's Phase-0-through-11 arc (§12-§23) is scoped to model-free on-policy learning; a learned world model introduces an entirely separate component (with its own training loop, loss function, and failure modes) that would roughly double the invariant surface (§7) for a benefit this project's named benchmarks (CartPole/LunarLander) do not need.
