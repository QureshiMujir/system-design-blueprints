⬜ Phase 0 — Workspace Bootstrap & Correctness Kernel §12

Objectives

  • Stand up the cargo workspace with all ten crates (§10) building on x86_64 and aarch64 CI targets (ADR-09).

  • Implement the scalar reference backend inside simd-core — the correctness kernel and conformance oracle (ADR-17).

  • Seed docs/adr/ with ADR-01, ADR-02, ADR-09, ADR-11, ADR-19.

  • Stand up the conformance/ harness runner wired only to the scalar backend.

Deliverable

Cross-platform cargo workspace; scalar-only Simd/Mask types compiling and passing self-consistency fixtures on both CI targets.

Acceptance

  • cargo nextest run --workspace green on both CI targets.

  • scalar_self_consistency.rs fixture passes 100% of 200 randomized cases.

  • Zero unsafe blocks outside simd-core::scalar (grep-gated in CI).

Fixtures
Fixture Assertion
scalar_self_consistency.rs scalar backend agrees with itself across 200 randomized cases
ci_smoke.rs workspace builds on both CI targets
alignment_construct.rs AlignedVec refuses misaligned raw construction
Pitfalls

  • Feature-flag conflicts across the ten crates — mitigated by ADR-19's workspace-locked minors.

  • Treating the scalar backend as unoptimized filler instead of the conformance oracle it is (ADR-17) — it must be written with the same care as a fast backend.

  • Skipping the aarch64 CI target "for now" — reintroducing it later surfaces cross-arch bugs late.

⬜ Phase 1 — Core Vector Abstractions §13

Objectives

  • Define the full SimdOps<T,LANES> trait surface (arithmetic, comparisons, min/max, bitwise) and lane accessors against which every future backend implements identically (P1, P4).

  • Define slice/array conversion contracts (I4).

Deliverable

Portable Simd<T,LANES>/Mask<T,LANES> trait surface, scalar-implemented, no_std-compatible, documented as the contract every backend must satisfy.

Acceptance

  • cargo test -p simd-core --no-default-features (no_std) green.

  • arithmetic.rs fixture passes on ≥6 (T,LANES) combinations: f32x4, f32x8, i32x4, i32x8, u8x16, u8x32.

  • Zero backend-specific #[cfg] inside simd-core.

Fixtures
Fixture Assertion
arithmetic.rs arithmetic laws hold across ≥6 (T,LANES) combinations
masks.rs mask propagation via comparisons matches canonical bits
reductions.rs sum/product/min/max/all/any correctness
conversions.rs slice↔vector round-trip is lossless
Pitfalls

  • Lane-width mismatch at trait-impl call sites.

  • Incorrect reduction identity elements (product identity must be 1, not 0).

  • Mask/bool conversion ambiguity — locked by P6 to all-ones canonical bits, never a raw 1.

Deliverable

Backend-agnostic Mask<T,LANES> with canonical bit conversion, boolean algebra, and select, ready for Phase 3+ backends to implement against.

Acceptance

  • masks_equivalence.rs passes 100% of a 500-case comparison-vs-literal corpus.

  • to_bits/from_bits round-trips losslessly for all LANES <= 64.

Fixtures
Fixture Assertion
masks_equivalence.rs comparison-built mask equals literal-built mask
select_blend.rs select matches per-lane ternary semantics
mask_boolean_algebra.rs &/`
Pitfalls

  • Assuming bool lane storage matches a specific backend's k-mask bit order — I2 forbids leaking representation.

  • Off-by-one in to_bits for LANES not a multiple of 8.

⬜ Phase 3 — x86 Backend I: SSE2/SSE4.2/AVX2 §15

Objectives
  • Implement simd-x86's SSE2 baseline, SSE4.2 opportunistic ops, and AVX2 256-bit backend against the Phase 1/2 trait surface — first real intrinsics.
Deliverable

SSE2-baseline + AVX2 x86_64 backend passing full conformance differential against the scalar oracle.

Acceptance

  • sse2_add.rs/avx2_shuffle.rs/avx2_reduce.rs pass 100%.

  • M1 (AVX2 vector-add throughput > 40 GB/s) met on reference CI hardware.

  • Zero disassembly-diff violations of P4.

Fixtures
Fixture Assertion
sse2_add.rs SSE2 arithmetic matches scalar oracle
avx2_shuffle.rs AVX2 shuffle/permute matches expected lane order
avx2_reduce.rs AVX2 reduction matches the pairwise-tree order (I7)
alignment_x86.rs aligned-load API rejects misaligned pointers at construction
Pitfalls

  • Alignment faults from _mm256_load_ps on an unaligned pointer (FM-3).

  • Undefined-feature UB if the #[target_feature] gate is missing (I6, T3).

  • Lane-ordering bugs in shuffle immediate-control-byte encoding.

⬜ Phase 4 — x86 Backend II: AVX-512 §16

Objectives
  • Extend simd-x86 with an AVX-512F/BW/VL baseline (512-bit vectors, native k-mask registers), reconciling ADR-05's mask model.
Deliverable

AVX-512F/BW/VL backend with native k-mask predication, passing conformance and the M2 throughput gate.

Acceptance

  • avx512_mask_native.rs/avx512_reduce.rs/avx512_gather.rs pass 100%.

  • M2 met on the self-hosted AVX-512 runner.

  • I8 verified with an ASAN guard-page fixture (zero out-of-bounds touches).

Fixtures
Fixture Assertion
avx512_mask_native.rs native k-mask round-trips through canonical bits (I2)
avx512_reduce.rs single-instruction reduce matches pairwise-tree order or is rejected (ADR-15)
avx512_gather.rs masked gather touches only active lanes (I8)
Pitfalls

  • Assuming _mm512_reduce_add_ps matches the pairwise-tree order without verifying (ADR-15's explicit exception clause).

  • The AVX-512 downclock cliff on mixed light/heavy instruction streams misread as a code bug instead of a documented microarchitecture behavior.

  • k-mask register exhaustion — only 8 available — when a kernel needs more live masks than registers.

⬜ Phase 5 — ARM Backend: NEON & SVE §17

Objectives
  • Implement simd-arm's NEON 128-bit fixed backend and SVE scalable (VLA) backend behind ADR-06's feature flag.
Deliverable

NEON fixed-width backend (baseline on all aarch64) plus SVE scalable backend (feature-flag opt-in), both passing conformance against the scalar oracle.

Acceptance

  • neon_eq.rs/sve_eq.rs pass 100%.

  • sve_vl_sweep.rs passes across ≥4 distinct VLs (128/256/512/2048-bit).

  • M3 (NEON throughput) met.

Fixtures
Fixture Assertion
neon_eq.rs NEON matches scalar oracle
sve_eq.rs SVE matches scalar oracle at the runtime-queried VL
sve_vl_sweep.rs identical result across ≥4 distinct hardware/emulated VLs (I9)
gather_emulation_neon.rs NEON gather emulation matches masked-touch contract (I8)
Pitfalls

  • Assuming SVE VL is a compile-time constant like NEON — I9's most common porting bug per Arm's own guide.

  • NEON gather-emulation cost dominating a hot path unnoticed — ADR-16's exception clause exists precisely for this.

  • Semantic drift between NEON and SVE predicate conventions.

⬜ Phase 6 — Runtime CPU Feature Detection & Dispatch §18

Objectives
  • Implement simd-dispatch: CpuFeatures probe, Backend enum, cached dispatch table, fallback chain, multiversioning glue.
Deliverable

simd-dispatch resolving the correct backend once per process, cached, with a validated acyclic fallback chain and simd-cli inspection support.

Acceptance

  • dispatch.rs/fallback.rs pass 100%.

  • M4 < 200 ns and M5 < 2 ns met on reference hardware.

  • dispatch_race.rs passes under a 1000-thread concurrent-first-use stress with zero races (T4).

Fixtures
Fixture Assertion
dispatch.rs highest-capability backend is selected for a given CpuFeatures snapshot
fallback.rs fallback chain terminates at Backend::Scalar
dispatch_race.rs 1000-thread concurrent first-use converges to one cached value
cpu_features_probe.rs detected features match a known-reference CPU's feature list
Pitfalls

  • Invalid/reserved cpuid leaf handling on virtualized hosts (hypervisor may mask or misreport leaves).

  • Dispatch recursion if a fallback table is misconfigured (T12).

  • Cold-start overhead exceeding M4 due to unmemoized repeated cpuid calls (I13 violation).

⬜ Phase 7 — Shuffles, Swizzles, Blends, Gather/Scatter, Reductions §19

Objectives
  • Complete the lane-rearrangement and reduction surface across every backend landed so far (SSE2/SSE4.2/AVX2/AVX-512/NEON/SVE), enforcing I7 and I8 uniformly.
Deliverable

Complete, cross-backend-consistent shuffle/swizzle/blend/gather/scatter/reduction surface satisfying I7 and I8 uniformly.

Acceptance

  • reductions_cross_backend.rs and gather_masked_touch.rs pass 100% across every landed backend.

  • M8 < 15 cycles, M9 < 25 cycles met on AVX2 reference hardware.

Fixtures
Fixture Assertion
reductions_cross_backend.rs bit-identical reduction result across backends (I7)
gather_masked_touch.rs zero memory touches for inactive lanes (I8)
shuffle_equivalence.rs shuffle output matches scalar-oracle lane mapping
blend_equivalence.rs blend matches per-lane ternary semantics
Pitfalls

  • A backend's "free" single-instruction reduction silently using a different order than the pairwise tree (ADR-15's core risk).

  • Shuffle immediate-control-byte off-by-one errors.

  • Scatter to overlapping masked lanes producing backend-dependent write order when two active lanes target the same address — implementation-defined per the SDM, not a bug.

⬜ Phase 8 — Vectorized Math Kernels & Memory Primitives §20

Objectives
  • Implement simd-math (polynomial transcendentals, FMA) and simd-memory (memcpy/memcmp/memset/ scan) atop the completed backend + dispatch + shuffle/reduction surface.
Deliverable

simd-math transcendental kernel set with documented ULP bounds; simd-memory vectorized memcpy/memcmp/memset/scan with alignment-aware tail handling.

Acceptance

  • sin.rs/exp.rs meet M10 (≤2 ULP) over the full boundary corpus.

  • memcpy.rs/memcmp.rs pass 100% correctness including overlap-rejection (T10).

  • M6/M7 throughput gates met.

Fixtures
Fixture Assertion
sin.rs ≤2 ULP error over [-π, π] boundary corpus (M10)
exp.rs documented ULP bound over full dynamic range
fma_precision.rs fused vs unfused error bound within I11's tolerance
memcpy.rs byte-identical copy, overlap rejected (T10)
memcmp.rs early-exit result matches libc contract
scan.rs pattern-search correctness on tail-length haystacks
denormal_isolation.rs ambient FPCR/MXCSR restored on scope exit (I14)
Pitfalls

  • Catastrophic precision loss near a polynomial's range-reduction boundary (FM-5).

  • Silent global MXCSR/FPCR mutation leaking denormal mode to unrelated code (FM-10).

  • Overlapping-copy corruption if memcpy's non-overlap contract is violated by the caller (T10).

  • Page-crossing faults in unaligned tail loops.

Objectives
  • Finish simd-bench, simd-profiler, and the conformance/fuzz harness to full-matrix differential coverage; wire §26/§28 CI gating end to end.
Deliverable

Full differential-conformance plus 24-hour-soak fuzzing plus regression-gated benchmarking plus profiling pipeline; a release-ready v1.0 candidate.

Acceptance

  • diff_backend.rs passes 100% across the full backend matrix.

  • M11 < 10 min and M12 ≥ 24 CPU-hours/backend/release met.

  • Zero unresolved cargo-fuzz crashes at tag time.

Fixtures
Fixture Assertion
diff_backend.rs every backend agrees with the scalar oracle and each other
fuzz_masks no crash, no I8/I2 violation, over the soak duration
fuzz_alignment no unhandled fault over the soak duration
fuzz_shuffle no OOB or panic on malformed shuffle indices
fuzz_dispatch no cycle, no race, over concurrent-stress soak

Pitfalls

  • Undefined-intrinsic UB surfacing only under fuzzing's malformed-input corpus, not hand-written fixtures.
