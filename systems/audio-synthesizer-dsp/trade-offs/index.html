Decisions (§9) · 28 ADRs

ADR-01

Language & numeric-core strategy

Chosen

Python control layer + nopython-JIT (Numba) compiled RT kernel, Cython fallback

Rejected

pure Python; pure C++; pure Rust; NumPy-vectorized-only

When the rejected choice is right

pure C++/Rust wins when shipping a production VST3/CLAP binary with no Python runtime at all (§37)

Why: balances iteration speed with a proven real-time-safe compiled hot path

ADR-02

Sample format

Chosen

float32 in the graph; float64 for coefficient computation at low cutoffs

Rejected

int16 fixed-point; float64 everywhere

When the rejected choice is right

float64-everywhere wins in an offline mastering-precision renderer where CPU is unconstrained

Why: float32 halves memory/bandwidth and matches native SIMD width; float64 avoids precision loss near DC

ADR-03

Block size policy

Chosen

configurable power-of-two, fixed for the stream's lifetime (default 128)

Rejected

fixed 64-only; variable per callback

When the rejected choice is right

variable-per-callback wins on host APIs that legitimately vary block size, handled via the largest-block ceiling

Why: fixed block simplifies pre-allocation sizing (P1)

ADR-04

Graph representation & scheduling

Chosen

explicit DAG, topo order recomputed only on patch-commit

Rejected

FAUST-style whole-graph AOT compilation; per-block re-sort

When the rejected choice is right

whole-graph AOT wins when the patch is fixed for the product's lifetime and max throughput matters more than patchability

Why: keeps the graph runtime-patchable while avoiding per-block scheduling cost

ADR-05

Oscillator antialiasing method

Chosen

PolyBLEP default, minBLEP for hard-sync/FM-heavy patches

Rejected

oversampling-only; naive (none)

When the rejected choice is right

oversampling-only wins for custom waveforms whose discontinuity isn't analytically tractable for BLEP/BLAMP

Why: PolyBLEP meets the -80 dBFS floor cheaply; minBLEP trades a table for a lower floor

ADR-06

Filter topology

Chosen

TPT/zero-delay-feedback SVF for modulated filters; direct-form biquad for static EQ

Rejected

direct-form biquad everywhere; state-space (A,B,C,D) everywhere

When the rejected choice is right

direct-form biquad wins for a fixed mastering EQ chain with no modulation

Why: TPT keeps modulated filters provably stable (I2); biquad is cheaper when cutoff never moves

ADR-07

Reverb algorithm

Chosen

feedback delay network (FDN) with an orthogonal matrix

Rejected

convolution reverb (measured IR); plain Schroeder comb/allpass

When the rejected choice is right

convolution reverb wins when faithfully reproducing one specific measured space is the product's value — deferred (§37)

Why: FDN gives a provable stability condition (I9) and parametric, tunable decay

ADR-08

Voice-allocation policy

Chosen

oldest-first stealing + mandatory fast-release ramp + same-note reuse

Rejected

quietest-voice stealing; no-stealing (drop note); random stealing

When the rejected choice is right

quietest-voice stealing wins in a mix-critical patch where perceptual loudness beats allocation-order predictability

Why: oldest-first is O(1) with an age-ordered free list and easy to reason about

ADR-09

Parameter-smoothing strategy

Chosen

per-parameter one-pole exponential smoother + sample-accurate ParamEvent scheduling

Rejected

linear ramp only; block-rate-only (no smoothing)

When the rejected choice is right

linear ramping wins for a UI-visible fade whose exact finish time must be user-predictable

Why: exponential smoothing has no audible derivative corner; linear ramps click at the end

ADR-10

Modulation architecture

Chosen

centralized modulation matrix (source×destination×depth)

Rejected

freeform patch-cable graph identical to the audio graph; hardwired per-voice routing

When the rejected choice is right

freeform patch cables win when the product's identity is modular/Eurorack-style routing (§36)

Why: bounded route count for CPU budgeting; matches most hardware-synth mental models

ADR-11

MIDI parsing

Chosen

strict MIDI 1.0-conformant parser + running status, plus a UMP adapter

Rejected

permissive/lenient parsing that guesses intent

When the rejected choice is right

lenient parsing wins only for a consumer product prioritizing "never refuses input" over correctness

Why: strictness makes I11 provable and fuzzable

ADR-12

Device I/O binding

Chosen

PortAudio callback contract via a thin Python binding

Rejected

direct ALSA/CoreAudio/WASAPI per-platform; JACK-only

When the rejected choice is right

JACK-only wins in a professional Linux studio deployment prioritizing JACK's graph-level routing

Why: most portable, stable, well-documented cross-platform abstraction

ADR-13

Denormal mitigation

Chosen

FTZ/DAZ CPU flags at stream-open

Rejected

per-sample denormal branch check; DC-bias injection

When the rejected choice is right

DC-bias injection wins on a platform/CPU lacking FTZ/DAZ support

Why: one-time, zero-per-sample-cost hardware flag

ADR-14

Threading model & RT/non-RT handoff

Chosen

exactly two thread classes: one audio (RT) thread, a pool of non-RT control/IO threads, SPSC queues + atomic snapshot swaps

Rejected

multiple RT threads with a lock-based scheduler; single-threaded, no control thread

When the rejected choice is right

multiple RT threads win when polyphony exceeds a single core's per-block deadline (§4)

Why: keeps the RT-safety argument tractable (P9)

ADR-15

Buffer ownership

Chosen

node-owned static output buffers allocated at graph-commit

Rejected

per-block dynamic allocation; shared global scratch pool with bounds-checked borrowing

When the rejected choice is right

a shared scratch pool wins when node count would blow the cache-residency budget (§4)

Why: static ownership structurally guarantees P1's zero-allocation claim

ADR-16

Plug-in format targeting

Chosen

none built now; VST3/CLAP named as future export ABI targets (deferred, §37)

Rejected

building a VST3/CLAP host or plugin binary now

When the rejected choice is right

building the shim now wins if the immediate deployment target is a DAW-hosted instrument

Why: plug-in ABI work is a separate, large engineering surface orthogonal to the DSP core

ADR-17

File I/O

Chosen

from-scratch WAV/RIFF reader/writer, 16/24/32-bit int and float PCM

Rejected

depending on libsndfile; supporting compressed codecs (MP3/AAC/OGG)

When the rejected choice is right

libsndfile wins when broad format compatibility matters more than dependency minimalism

Why: small, spec-conformant, dependency-free; compressed codecs are an explicit non-goal

ADR-18

Logging

Chosen

audio thread never logs directly; writes fixed-size records into a lock-free queue drained by a non-RT consumer

Rejected

direct logging calls from the audio thread; no RT-thread logging at all

When the rejected choice is right

no-RT-logging-at-all wins in a maximally paranoid safety-critical variant where even the handoff cost is unacceptable

Why: preserves P1/P9 while surfacing RT-thread events

ADR-19

Tracing

Chosen

span-style tracing only on non-RT threads; RT thread emits lightweight counters/timestamps into the telemetry queue

Rejected

full distributed-tracing spans directly in the callback

When the rejected choice is right

full in-callback tracing wins only in a debug build with guard rails disabled, never in production

Why: full tracing's per-span allocation is incompatible with P1

ADR-20

Metrics

Chosen

fixed-size lock-free counters/histograms, atomic increments on the RT thread, drained by a non-RT exporter

Rejected

a full metrics client library instantiated on the RT thread

When the rejected choice is right

a full metrics client wins entirely on the non-RT side (control thread, offline renderer)

Why: client libraries typically allocate on label/metric creation

ADR-21

Testing

Chosen

pytest with property-based (Hypothesis) parameter-range sweeps, differential tests vs. scipy.signal, golden-file regression

Rejected

unit tests only, no property/differential coverage

When the rejected choice is right

unit-tests-only wins for a throwaway prototype where the property/differential harness isn't justified

Why: DSP bugs concentrate at parameter-range extremes example-based tests miss

ADR-22

Fuzzing

Chosen

coverage-guided fuzzing targeting the MIDI parser, WAV/RIFF parser, preset loader

Rejected

no fuzzing, manual malformed-input cases only

When the rejected choice is right

hand-written cases only win for a small, exhaustively-enumerable grammar — not true of MIDI/WAV/presets

Why: parser attack surfaces (T1/T5/T6) need automated exploration

ADR-23

CI/CD

Chosen

GitHub Actions: lint, unit/property/differential tests, numeric- and perf-regression gates on every PR; nightly soak + fuzz

Rejected

CI running only lint+unit tests

When the rejected choice is right

ADR-24

Packaging

Chosen

pyproject.toml sdist/wheel with a compiled-extension build step per target platform

Rejected

pure-Python-only package; monolithic single-file script

When the rejected choice is right

pure-Python-only wins for the non-RT control/graph layer alone, distributed separately from the kernel extension

ADR-25

Release

Chosen

SemVer with a documented compatibility policy (§27) and signed artifacts (§29)

Rejected

rolling/unversioned releases; calendar-only versioning with no compatibility guarantee

When the rejected choice is right

ADR-26

Reproducibility of renders

Chosen

deterministic, bit-exact given same patch/events/version, fixed seed for stochastic nodes

Rejected

allowing platform-dependent float reduction order to vary output silently

When the rejected choice is right

relaxed, tolerance-bounded reproducibility wins across differing BLAS/compiler versions (documented, §29)

Why: required for regression fixtures (I13) and archival/mastering use

ADR-27

Backpressure

Chosen

fixed-capacity control->RT queue; oldest non-critical event dropped first on overflow, NoteOn/NoteOff never silently dropped

Rejected

unbounded queue growth; blocking the control thread until space available

When the rejected choice is right

blocking-with-backpressure wins on the non-RT control thread for guaranteed-delivery batch automation import

Why: unbounded growth risks unbounded memory; blocking risks stalling MIDI/UI responsiveness

Licensing

When the rejected choice is right

36. Alternative Architectures (Roads Not Taken)

Sample-at-a-time processing instead of block processing.

for each sample n:
    for each node in topo_order:
        node.process_one(ctx, n)   // one sample in, one sample out
    output[n] = mix(...)

Winning regime: feedback-heavy topologies needing true zero-delay per-sample feedback without an implicit solver (e.g. certain analog-modeled circuits). Real embodying system: SuperCollider's UGen graph, which partly supports per-sample audio-rate calculation for exactly this reason. Rejected here because per-sample Python-level dispatch (even into a compiled kernel) multiplies call overhead by the sample count instead of the block count, and this blueprint's TPT/SVF approach (Phase 4) already solves the zero-delay-feedback problem within block processing without paying that overhead (ADR-04, ADR-06).

A compiled DSP-language approach, à la FAUST, compiling the graph to a specialized kernel.

patch.dsp  --[FAUST compiler]-->  specialized_kernel.cpp  --[C++ compiler]-->  kernel.so
                                          (one static topology, maximum throughput)

Winning regime: a fixed-topology product (an embedded effects pedal, a single-purpose plugin) where the patch never changes after build time and maximum throughput matters more than runtime patchability. Real embodying system: FAUST itself, and products built by compiling FAUST programs to embedded targets. Rejected here (ADR-04) because this blueprint's explicit goal is a runtime-patchable graph (a modular-synth-like authoring experience), which a whole-graph ahead-of-time compilation model structurally forecloses.

Wavetable/sample-playback synthesis instead of computed band-limited synthesis (PhaseDeferred, anchor "36. Alternative Architectures (Roads Not Taken)").

table[0..N-1]  (one or more cycles, band-limited per octave/mip-level)
read position += phase_increment ; output = interpolate(table, read position)

Winning regime: reproducing specific, complex, non-parametric timbres (real instrument samples, captured analog waveforms) cheaply at playback time. Real embodying system: most commercial samplers and many hardware/software synths' "wavetable" oscillator banks. Rejected here because this blueprint's goal is a from-scratch computed-synthesis library whose correctness is provable from first principles (Moore 1977's table-lookup-noise analysis is exactly the kind of tradeoff this blueprint's computed BLIT/PolyBLEP/minBLEP approach was chosen to avoid needing).

Physical-modeling/waveguide synthesis as the primary engine (PhaseDeferred, anchor "36. Alternative Architectures (Roads Not Taken)").

[excitation] -> [delay line (string/tube)] -> [loss filter] -> feedback -> [pickup/output]
                (Karplus-Strong / digital waveguide topology)

Winning regime: physically-inspired instruments (plucked strings, wind instruments) where the delay-line-plus-loss-filter topology directly models the physical system, per Karplus & Strong 1983 and Smith & Angell 1982. Real embodying system: waveguide synthesizers and much of the physical-modeling literature built on this pair of papers. Rejected here as the primary engine because this blueprint's scope centers on the oscillator/filter/envelope/effects-graph model common to subtractive/FM/effects-processing work; a waveguide engine is a fundamentally different signal-flow primitive (a delay line is the instrument, not an effect on one) that would double the domain-model surface (§8) rather than extend it.
