Per-box detail (one paragraph each):

  • Root CA (offline): Air-gapped, the trust origin. Its key signs intermediates and emits the top-level CRL/dbx. Never online; used only in ceremonies (§11). The hash of its public key (or the PK itself) is what gets fused into device OTP — the single immutable anchor.
  • Intermediate Signing CA (HSM): Day-to-day issuer of leaf signing keys; HSM-resident so the offline root rarely activates. Has its own CRL. pathLen constrains it from minting further CAs. Rotatable and cross-signable without re-fusing devices (§11).
  • Leaf Signing Key (HSM): Signs manifests. EKU = code-signing only. Short-lived; high rotation; the unit revoked first on compromise.
  • Manifest + image: The release artifact. Manifest is a compact binary structure (detached signature over a canonical digest of itself + payload), carrying SVN, key id, cert-chain reference, flags (§8).
  • Trust Anchor store: On device, the fused PK-hash plus (optionally) a small mutable allowlist of cross-signed anchors for migration. Read-only post-provision; the verifier roots all chains here.
  • CRL / dbx denylist + OCSP responder: Revocation surfaces. CRL = signed list of revoked serials; dbx = explicit hash/key denylist usable offline; OCSP = online per-cert status, optionally stapled into the manifest for offline use.
  • Boot ROM (RoT, immutable): First code to run; mask-fixed; reads the fused PK-hash, verifies+measures SPL, jumps only on Accept. Cannot be updated — bugs here are unrecoverable, so it is minimal.
  • SPL / 1st-stage loader / 2nd-stage bootloader / Kernel: Each stage links/calls sbpki-verify to validate the next image's manifest and extends a PCR before transfer. Order is invariant (§7).
  • sbpki-verify (no_std TCB): The pipeline codec → x509 → revoke → rollback → crypto, returning Verdict::Accept or Verdict::Reject(reason). Single point where fail-closed is enforced; zero heap in hot path; deterministic.
  • OTP fuses / NV counter store: OTP holds PK-hash + minimum-SVN (write-once); NV holds the monotonic rollback counter (write-many, monotone). Modeled by sbpki-nv.
  • sbpki-tpm (PCR): PCR bank, extend, TCG-style event log, quote (signed PCR snapshot), seal/unseal of secrets to a PCR policy. Modeled deterministically.
  • sbpki-ab (A/B + recovery): Slot selection, boot-attempt counter, watchdog, fallback to other slot or signed recovery image; commits SVN only after a successful boot ("mark good").
  • Attestation Verifier (remote): Off-device service that checks a quote + event log against expected PCR values and policy, then releases a secret / admits the device to a fleet.

8. Domain Model / Formats / State Machines

8.1 Signed Manifest — byte layout

All multi-byte integers big-endian. Fixed header then TLV body then signature trailer. Signature covers header ‖ body (the signed region), NOT the trailer.

offset  size  field                description
0x00    4     magic                "SBPK" = 0x53 0x42 0x50 0x4B
0x04    1     format_version       0x01 (bump = incompatible layout)
0x05    1     header_version       minor, additive fields only
0x06    2     flags                bit0 RECOVERY, bit1 AB_SLOT_B, bit2 OCSP_STAPLED,
                                   bit3 DEBUG_UNLOCK_OK, bit4 DUAL_SIGNED, bits5-15 reserved=0
0x08    2     sig_alg              1=Ed25519, 2=ECDSA-P256, 3=RSA-PSS-3072
0x0A    2     hash_alg             1=SHA-256, 2=SHA-384
0x0C    4     svn                  monotonic security version number (anti-rollback)
0x10    4     image_id             stage role: 1=SPL,2=BOOTLOADER,3=KERNEL,4=INITRD,5=RECOVERY
0x14    8     payload_len          length of the payload image in bytes
0x1C    32/48 payload_digest       SHA-256(32) or SHA-384(48) of payload (hash_alg)
...     20    key_id               SHA-1/“SKI”-style 160-bit id of leaf signing key
...     2     chain_ref_len        length of cert-chain-reference TLV body
...     N     chain_ref            TLV: DER cert chain OR a URI/serial reference (see 8.4)
...     2     tlv_count            number of optional TLV records following
...     M     tlv_body             optional TLVs: STAPLED_OCSP, BUILD_META, MIN_SVN_HINT,
                                   DUAL_SIG (second signature for cross-sign migration)
====   ----   END OF SIGNED REGION ====
...     2     sig_len              signature length (Ed25519=64, P256≈70-72 DER, RSA-PSS=384)
...     L     signature            detached sig over SHA-x(signed_region) by key_id

8.2 Manifest grammar (EBNF)

manifest      = header , body , sig_trailer ;
header        = magic , fmt_ver , hdr_ver , flags , sig_alg , hash_alg ,
                svn , image_id , payload_len , payload_digest , key_id ;
magic         = 0x53 0x42 0x50 0x4B ;
body          = chain_ref_len , chain_ref , tlv_count , { tlv } ;
chain_ref     = der_chain | uri_ref ;            (* tag-discriminated, 8.4 *)
tlv           = tlv_tag , tlv_len , tlv_value ;
tlv_tag       = STAPLED_OCSP | BUILD_META | MIN_SVN_HINT | DUAL_SIG ;
sig_trailer   = sig_len , signature ;
signed_region = header , body ;                  (* signature input *)

Parsing rules (normative): bounded total length (≤ 64 KB header+body for SPL stage; payload streamed/hashed separately); tlv_len must not exceed remaining buffer; unknown tlv_tag with critical-bit set ⇒ Reject, else skip; duplicate critical TLV ⇒ Reject; trailing bytes after signature ⇒ Reject; payload_len must equal actual streamed length or Reject.

8.3 Verification pipeline — sequence

Stage_N                sbpki-verify                    sbpki-nv / sbpki-tpm
  │  load manifest(N+1) into arena                          │
  │ ───────────────▶ parse_header() ── bad? ─▶ Reject(MALFORMED)
  │                  parse_body()  ── noncanon? ─▶ Reject(NONCANONICAL)
  │                  resolve_chain(chain_ref) ── ◀── trust_anchor (OTP PK-hash)
  │                  x509_path_validate() ── fail? ─▶ Reject(PATH/EXPIRED/EKU/...)
  │                  revoke_check(dbx,CRL,OCSP) ── revoked? ─▶ Reject(REVOKED)
  │                  read min_svn ◀───────────────────────── sbpki-nv
  │                  if svn < min_svn ─▶ Reject(ROLLBACK)
  │                  stream payload → hash → cmp payload_digest (CT) ── ne? ─▶ Reject(DIGEST)
  │                  verify_sig(signed_region, key) (CT) ── bad? ─▶ Reject(SIGNATURE)
  │ ◀─────────────── Verdict::Accept
  │  extend PCR[image_id_bank] ───────────────────────────▶ sbpki-tpm (record event)
  │  lock region / quiesce DMA
  │  (only on later "mark good") commit min_svn ◀──────────▶ sbpki-nv (monotone CAS)
  │  JUMP →

8.4 Cert-chain reference TLV

chain_ref_tag : 0x01 = DER_CHAIN  → value = concat(DER leaf, DER intermediate[, ...])
                0x02 = URI_REF     → value = utf8 URI + 4-byte CRC (offline: must be cached/stapled)
                0x03 = ANCHOR_IDX  → value = 1-byte index into device cross-sign allowlist

On device offline boot, only DER_CHAIN (self-contained) and ANCHOR_IDX are usable; URI_REF requires a cache.

8.5 X.509 path-validation state (per RFC 5280 sec. 6.1)

State tuple advanced cert-by-cert (leaf→root):

{ working_public_key, working_issuer_name, max_path_len,
  permitted_subtrees, excluded_subtrees, explicit_policy, valid_eku_set }

Transition checks per cert: signature(prev_key) → validity(now) → issuer==prev.subject → basicConstraints(CA=true for non-leaf) → pathLen decrement (Reject if 0) → keyUsage(keyCertSign for CAs / digitalSignature for leaf) → EKU ⊇ codeSigning (leaf) → name-constraints permit subject/SAN → revocation status. Terminal: working_issuer == trust_anchor AND anchor key matches OTP PK-hash.

8.6 Anti-rollback NV model

OTP (write-once):   pk_hash[32], min_svn_floor[u32]   (factory floor)
NV  (monotone):     rollback_ctr[u32]  (== effective min_svn; CAS: new ≥ old or fault)
SVN decision:       effective_min = max(min_svn_floor, rollback_ctr)
                    accept iff manifest.svn ≥ effective_min
commit (mark-good): rollback_ctr ← max(rollback_ctr, booted.svn)  // only after WDT-confirmed boot

8.7 A/B + recovery state machine

states: { TRY_A, TRY_B, ACTIVE_A, ACTIVE_B, RECOVERY, BRICK_GUARD }
vars:   slot_tries[A], slot_tries[B] (decrement on attempt), active_slot, recovery_present

POWER_ON ─▶ pick highest-priority slot with tries>0
  TRY_x: verify(slot_x)
     Accept  ─▶ boot; set bootonce; start WDT
        WDT_kick_before_timeout ─▶ mark slot_x good (tries reset, commit SVN) ─▶ ACTIVE_x
        WDT_timeout/crash       ─▶ tries[x]-- ; reboot
     Reject  ─▶ tries[x]=0 ; try other slot
  both tries==0 ─▶ RECOVERY: verify(recovery_image)
     Accept ─▶ boot recovery (re-provision/repair)
     Reject ─▶ BRICK_GUARD: halt, surface fault, await external recovery (out of scope to auto-fix)

8.8 Measured boot — PCR assignment + event log

PCR Measures
0 Boot ROM / RoT firmware identity
1 RoT config / fuse state digest
2 SPL / 1st-stage loader image
3 SPL config (DTB, env)
4 2nd-stage bootloader image
5 Bootloader config / GPT
6 (reserved)
7 Trust-anchor + dbx state digest
8 Kernel image
9 initramfs / cmdline

Event log entry (TCG_PCR_EVENT2-shaped):

{ pcr_index:u32, event_type:u32, digest_count:u32,
  digests:[ {alg_id:u16, digest:[u8;N]} ], event_size:u32, event_data:[u8] }

event_data carries the human/machine reason (e.g. image_id, key_id, verdict reason). Log is append-only, persisted to NV, replayable: recompute PCR[i] by folding entries.

8.9 Worked examples

  • Happy path: valid Ed25519 leaf, chain to fused anchor, dbx clean, svn=7 ≥ min 5 → Accept; PCR8 extended; WDT kicked; min_svn→7.
  • Rollback attempt: valid signature, svn=3 < effective_min 5 → Reject(ROLLBACK{img=3,min=5}); no PCR commit of acceptance; A/B tries other slot.
  • Revoked leaf: signature valid, but leaf key_id in dbx → Reject(REVOKED).
  • Malformed: trailing bytes after signature → Reject(MALFORMED_TRAILING).
  • Failure path: OCSP unreachable, no stapled OCSP, dbx clean, flag not requiring online → policy decides; if policy=strict → Reject(REVOCATION_UNKNOWN), else accept on dbx-clean (configurable, default strict for kernel, lenient for recovery).

Design principles (§6)

  • Fail-closed, always. Any error — parse, signature, expiry, revocation, rollback, OOM, timeout — yields Verdict::Reject. There is no "warn and continue." Tradeoff: a transient OCSP outage can refuse a valid boot → mitigated by stapled-OCSP + dbx offline path, never by skipping. Violation breaks: a single permissive branch = full bypass.
  • Verify before execute (no TOCTOU). The bytes verified MUST be the bytes executed: hash the image in the buffer you will jump to, lock/quiesce it (no concurrent DMA), then transfer. Violation breaks: attacker swaps flash/RAM between check and use.
  • Constant-time on secret-dependent paths. Signature verify, digest compare, and key-id match use constant-time compares (subtle::ConstantTimeEq). Violation breaks: timing oracle leaks which byte of a forged signature/digest is wrong → forgery acceleration.
  • Minimal TCB. Verifier is #![no_std], #![forbid(unsafe_code)] (except a reviewed crypto/FFI shim), ≤ 96 KB .text. Every dependency is a liability. Tradeoff: re-implement vs import — import only audited crypto; re-implement parsers to control attack surface.
  • Zero heap in the hot path. Manifest/X.509 parsing runs over a caller-supplied scratch arena; no global allocator at SPL stage. Violation breaks: heap fragmentation/OOM in 256 KB SRAM = unbootable or DoS.
  • Canonical-only parsing. Accept only canonical DER and one manifest byte layout; reject non-canonical/ambiguous encodings (BER indefinite-length, redundant length forms). Violation breaks: parser differentials → signature-bypass via re-encoding.
  • Roots fused, not configured. The trust anchor is the OTP PK-hash; mutable trust state (cross-sign allowlist) is additive only and itself signed. Violation breaks: a writable root = evil-maid replaces trust.
  • Monotonicity is hardware-anchored. SVN/min-SVN and the rollback counter live in OTP/NV with monotone semantics enforced by the model; software cannot decrement them. Violation breaks: rollback to a vulnerable signed image.
  • Measure everything you load, even if you also verify it. PCR-extend each stage + its config before transfer; the event log records what and why. Tradeoff: measured ≠ enforced — attestation/sealing decides later. Violation breaks: no forensic/attestation record of a tampered-but-rejected attempt.
  • Determinism + replayability. Same inputs (images, certs, fuses, NV, time) → identical verdict, identical PCR sequence, identical event log; the simulator is seeded. Violation breaks: non-reproducible attestation; un-debuggable boot failures.
  • Explicit, total error taxonomy. VerifyError is a closed enum; every reject path carries a machine-readable reason code persisted to the event log. Violation breaks: "it just won't boot" with no diagnosis.
  • Anti-bricking is a first-class invariant. Every flash/commit step is power-loss-atomic; A/B + recovery + watchdog guarantee some signed image boots. Violation breaks: a failed update bricks the device permanently.
  • Revocation must reach the offline path. Online OCSP is best-effort; dbx (hash/key denylist) is the authoritative offline kill-switch shipped with images. Violation breaks: a revoked-but-still-trusted key boots indefinitely on disconnected devices.
  • Separation of signing and verifying. Signing infra (keys, ceremonies, HSM) is a distinct trust domain from the device verifier; the device holds no signing capability. Violation breaks: device compromise = ability to forge.
  • Observability before the OS. The verifier records verdicts + measurements to an NV-backed event log readable post-boot/by attestation; nothing security-relevant is silent. Violation breaks: incidents are invisible until userspace, by which point trust may already be lost.
