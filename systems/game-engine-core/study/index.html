Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why must structural changes go through a CommandBuffer instead of mutating archetypes directly during iteration, and what specifically fails if the sync point is skipped? (§8.5, §17)
  2. How does the archetype-graph edge cache turn a transition lookup into O(1), and what invalidates that cache? (§8.2, §13)
  3. Using the accumulator algebra, derive why the renderer must interpolate rather than the simulation adapting its own timestep. (§8.6, §16)
  4. Why does per-column change-tick comparison dominate full value diffing as component count grows, and what false positive does it accept in exchange? (§8.3, §6 ADR-06 rationale is in §9)
  5. Why is the scheduler's conflict analysis bounded to O(systems × accessed components) rather than O(systems²), and what data structure makes that possible? (§18, §5)
  6. Why is generation-bump-then-swap the only safe hot-reload sequence, and what breaks under swap-then-bump? (§8.8, §20)
  7. Why must scene-graph propagation run after every system that could move a Transform in the same frame, and what regression class does violating this produce? (§8.9, §21, §25 FM-8)
  8. Why does this blueprint reject archetype storage's theoretical worst case (2^component-types archetypes) as a practical concern, and what actually bounds the real number? (§31, §34)
  9. Given Amdahl's law and the declared serial sync points, what is the maximum speedup a future native parallel executor could achieve for an 80%-conflict-free stage, and why does v1 realize none of it? (§31, §9 ADR-08)
  10. Why is a stale Entity handle detected by a generation mismatch rather than a runtime crash, and what would go wrong if Entity were a raw pointer instead? (§8.1, §7 I1)
  11. Walk the archetype-migration worked example and explain which invariant breaks if the swap-remove step is skipped. (§8.2, §7 I2)
  12. Why does event backpressure choose drop-oldest over an unbounded queue, and what failure mode does the unbounded alternative actually produce? (§8.7, §25 FM-11, §34)
  13. Why must deterministic replay's state hash be computed in canonical per-archetype row order rather than component-value order? (§22, §25 FM-10)
  14. Compare the archetype and sparse-set storage models' add/remove-vs-iterate tradeoff, and state the regime where each wins. (§36, §9 ADR-03)
  15. Why does the scheduler's grouping algorithm remain valuable even though v1's executor never actually parallelizes anything? (§18, §9 ADR-08)
  16. Derive the per-entity memory number in §34 from the component-count and average-size assumptions in §4, and state what would change it. (§4, §34)
  17. Why is a prefab load's failure semantics ("abort the whole load") deliberately stronger than a single command's failure semantics ("skip just that command"), and what breaks if a prefab load used the weaker guarantee? (§17, §22)
  18. Why does the physics integration seam give Physics-Engine sole write access to Transform during the PhysicsSync stage rather than sharing it with gameplay systems, and what scheduler mechanism enforces that? (§8, §9 ADR-18, §7 I3)

32. Mental Models & First Principles

MM1 — An ECS is a column-store database with a frame-rate deadline. Queries, indexes, and locality reasoning transfer directly from database engineering. Predicts: a query's cost model is "which columns does this touch," not "how big is the world." Without it, engineers treat components as a random-access object graph and are surprised cache misses dominate. Resolved in §8.3, §14, P4.

MM2 — A fixed timestep makes simulation a pure function of tick count, not of the machine it ran on. Predicts: determinism and lockstep replay are achievable only when the timestep is fixed and the render rate never feeds back into it. Without it: physics that behaves differently on a 240 Hz monitor than a 60 Hz one. Resolved in §8.6, §16, P2.

MM3 — An entity handle is a foreign key with a generation column, not a pointer. Predicts: detecting a dangling reference is a version compare, never a segfault. Without it: use-after-free- class bugs that manifest as silent data corruption instead of a crash. Resolved in §8.1, I1, P3.

MM4 — A scheduler is a static analysis of declared effects, not a runtime race detector. Predicts: safe parallelism must be provable before any system runs, not discovered by testing under load. Without it: races that "usually don't happen" in CI and then happen in production. Resolved in §8.4, I3, P6.

MM5 — Dirty-flag propagation is incremental recomputation — the same principle behind spreadsheet recalculation and reactive UI diffing. Predicts: cost tracks the changed subtree size, never total graph size. Without it: O(everything) recompute code that works in a demo and falls over at real scene sizes. Resolved in §8.9, I6, P11.

MM6 — A resource handle decouples "the game holds a reference" from "the bytes exist" — the same separation a file descriptor makes from an inode. Predicts: hot reload is safe exactly when code holds handles, never raw pointers/bytes. Resolved in §8.8, P9, §20.

MM7 — Backpressure is a choice of failure mode, not the absence of one. An "unbounded" queue doesn't avoid failure, it just moves it to an OOM crash instead of a bounded, telemetred drop. Predicts: every queue in the system needs an explicit cap and an explicit drop policy. Resolved in §8.7, ADR-31, FM-11.

MM8 — Determinism is a system-wide discipline, not a single mechanism. Fixed timestep, stable system order, seeded RNG, and floating-point-associativity discipline all have to hold simultaneously; one non-deterministic component anywhere breaks replay everywhere. Resolved in §22, §27, FM-10.

Reference Implementations

  • Bevy — crates/bevy_ecs/src/ — archetype storage + change detection + schedule graph; lesson: typed query fetch via associated types; pitfall not to copy: its schedule-v3 rewrite churned plugin APIs across versions (§27 compatibility rationale) — applied in Phase 1–3 (§13–§15).
  • EnTT — src/entt/entity/ — sparse-set storage as the alternative to archetypes; lesson: O(1) add/remove cost model; pitfall not to copy: multiple iteration strategies with silently different costs, undocumented at the call site — applied in §36 Alternative Architectures.
  • Unity DOTS/Entities — chunk-based archetype storage, IJobEntity scheduling; lesson: chunk capacity as a tuning knob distinct from archetype identity; pitfall not to copy: the DOTS/ GameObject dual-model split confused adoption for years — applied in §33 Comparative Architecture.
  • Flecs — src/ — query caching and cascading hierarchies; lesson: cached queries amortize archetype-matching cost; pitfall not to copy: its relationship/traits API grew large before the core query semantics stabilized — applied in Phase 2 (§14) query-cache design.
  • Godot — servers/, scene/ — the servers/scene-tree split (an OOP scene graph, not ECS); lesson: a server-thread boundary decoupling gameplay from rendering; pitfall not to copy: deep node inheritance for behavior — applied in §36 Alternative Architectures.
  • esper — a minimal Python ECS — lesson: what a straightforward Python sparse-dict-of-components implementation costs at scale; pitfall not to copy: dict-of-dicts storage has no cache locality — applied in §36 and ADR-03 (rejected-alternative rationale).

Glossary (§38) · 50 terms · site-wide glossary

Entity
an opaque 64-bit handle (32-bit index + 32-bit generation) identifying a row across archetype storage (§8.1).
Component
a plain-data type stored in a dense column per archetype; never carries methods (P1).
System
a scheduled function with a statically-declared Access set (P6).
Archetype
a unique component-set signature; entities sharing one share dense column storage (§8.2).
Archetype graph
the memoized add/remove transition edges between archetypes (I7).
Sparse set
an alternative component-storage model, entity-id-to-dense-index per component type; rejected here for archetype storage (ADR-03, §36).
Dense column
contiguous per-component storage within one archetype (P4).
Generational index
an index+generation pair used to detect stale references (I1).
Query
a typed, cached iteration request over archetypes matching a QueryFilter (§8.3).
Query filter
a With/Without/Optional/Changed/Added matching predicate (§8.3).
Change detection
per-column tick comparison flagging writes since a system's last run (ADR-06).
Command buffer
a per-system queue of deferred structural changes (§8.5).
Sync point
the stage boundary at which command buffers are applied (I4).
Structural change
spawn, despawn, insert, remove, or reparent — anything altering archetype membership.
Fixed timestep
a constant simulation tick duration, decoupled from render rate (P2).
Accumulator
the real-time-to-simulation-time buffer driving fixed ticks (§8.6).
Interpolation alpha
the fractional position between two simulation ticks used for rendering (§8.6).
Spiral of death
unbounded accumulator growth when simulation cost exceeds the tick budget (I5).
Scene graph
the parent/child transform hierarchy expressed via components (ADR-14).
Dirty flag
a per-node marker triggering incremental transform recomputation (P11).
Transform propagation
recomputing GlobalTransform from Transform along a dirty scene-graph subtree (§8.9).
Prefab
a data-driven, versioned entity template referencing components by name (ADR-17).
Resource handle
a refcounted, generational reference to an asset's bytes (§8.8).
Hot reload
swapping an asset's bytes behind a stable handle via a generation bump (ADR-13).
Data-oriented design
organizing storage by access pattern rather than by object identity (P4).
False sharing
two logically-independent writers contending for the same cache line (FM-5).
Amdahl's law
the bound on parallel speedup imposed by a computation's serial fraction (§31).
Determinism
same inputs producing bit-identical outputs across runs (P7).
Replay divergence
a state-hash mismatch between a recorded and replayed run (FM-10).
Zero-sized type (ZST)
a marker component with no data, stored as presence-only (§13).
Event bus
the typed, double-buffered inter-system message channel (§8.7).
Double buffering
maintaining "current" and "previous" copies to give a bounded visibility window.
Backpressure
a bounded queue's explicit drop/reject policy under overload (ADR-31).
Refcounting
tracking live references to an asset to decide eviction timing (I9).
LoadState
an asset's lifecycle stage: Unloaded/Loading/Loaded/HotReloadPending/Failed/ Evicting (§8.12).
FrameStats
the always-on per-frame profiling ring buffer (§23).
Tick rate
the fixed simulation frequency, e.g. 60 Hz (§4).
GIL (Global Interpreter Lock)
CPython's single-thread-executes-bytecode-at-a-time constraint (ADR-08).
Work stealing
a scheduling strategy where idle workers pull tasks from busy ones' queues (§5, Cilk).
Topological sort
ordering a DAG's nodes so every edge points forward, used in Schedule.build (§15, §18).
Conflict graph
the graph of systems whose declared Access sets conflict (§8.4).
Parallel group
a set of systems provably safe to run concurrently (§18).
Extract stage
the snapshot step producing an immutable RenderFrame for the render seam (ADR-19).
RenderFrame
the immutable, interpolated-state package handed to Software Rasterizer (#169).
PhysicsSync
the stage synchronizing Transform with Physics-Engine's (#171) rigid-body state (ADR-18).
RigidBodyHandle
the opaque component linking an entity to Physics-Engine's body store.
SemVer
Semantic Versioning 2.0.0, the version-number contract (§27).
MessagePack
the binary serialization format used for prefabs/saves (ADR-16).
glTF
the Khronos scene/mesh interchange format used at the render seam (ADR-12).
Canonical order
the fixed, deterministic per-archetype row iteration order required for replay bit-equality (§22).
