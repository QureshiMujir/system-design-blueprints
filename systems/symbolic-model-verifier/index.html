3.3 Boundaries

Boundary Location Rule
Trust boundary smv-cli ↔ smv-syntax/smv-logic Model .smv text + spec text are UNTRUSTED. Lexer/Parser are the only components touching raw bytes; every malformed input maps to a typed ParseError/ParseErrorKind (UnexpectedToken, UnknownVar, BadType, TypeMismatch, CircularDefine, OutOfRange) — never a panic, never UB. Past this boundary the AST is well-typed; downstream crates assume validated structure.
Concurrency boundary inside smv-bdd BddManager is a single-threaded mutable arena (&mut self on ithvar/ite/and/or/restrict/exists/forall/and_exists/rename). One model-check = one sequential thread driving one manager; the unique table + computed cache are not shared across threads. No Send/Sync on live Bdd handles across managers — a Bdd(u32) is an index valid only for its owning manager. Parallelism (if ever) is between independent managers, never within one.
Persistence boundary none at runtime The verifier is a pure batch transform: read model.smv + specs once, hold all BDD state in RAM, emit verdict/Trace/stats, exit. No DB, no on-disk index, no checkpointing of the node table. Only optional output artifacts: dot graph files (dot subcommand) and a textual Trace. Re-running re-encodes from source — deterministic given fixed var order.
Module boundary (encode) smv-syntax ↔ smv-model AST carries no BDD handles; VarEncoding/EncodedFsm are the first artifacts to reference Bdd. Variable→level assignment is fixed here and frozen for the manager's lifetime (canonicity prerequisite).

3.4 Per-Box Responsibilities

3.4.1 smv-bdd — the ROBDD engine

Responsibility: the shared boolean-function representation under every other crate; owns BddManager, the Bdd(u32) handle, the unique table (hashcons on (level,low,high)), the computed cache, and the fixed total variable order. In: levels (via ithvar), existing Bdd handles, cubes. Out: canonical Bdd handles; satcount(f,nvars)->u128; node_count(f)->usize; dot export. Primitive surface: ite (the one primitive); not/and/or/xor/imp as ite specializations; restrict (cofactor); exists/forall over a cube; and_exists (relational product, the image workhorse); rename (present↔next swap); mark-sweep GC of dead nodes. Key invariant: canonicity — fixed var order + two reduction rules (delete any node with low==high; merge isomorphic nodes via hashcons) ⇒ structural handle equality iff boolean-function equality, so equality + fixpoint-convergence tests are O(1). This is the load-bearing invariant: any breach silently corrupts equality and fixpoints, yielding wrong verdicts with no crash. no_std + alloc. Phases: 0 (handle/manager shells), 1 (node+unique table, reduction, ite, terminals, canonicity property test), 2 (restrict/exists/forall/and_exists/rename/satcount/node_count/cache/GC/dot), tuned in 12 (sifting, cache tuning).

3.4.2 smv-syntax — the SMV modeling language front end

Responsibility: turn untrusted .smv source into a validated SmvModule AST. In: UTF-8 source bytes. Out: SmvModule { vars, defines, assigns, trans, invar, specs }; on failure a typed ParseError. Components: Lexer/Token; a recursive-descent Parser; AST nodes VarDecl/VarType(Boolean/Enum(Vec<Atom>)/Range(i64,i64)), AssignDecl/AssignKind(Init/Next/Plain), DefineDecl, InvarDecl, TransDecl, SpecDecl(Ctl(String)/Ltl(String)/InvarSpec(Expr)), and the Expr tree (Var/Const/Not/Bin/Case/Next). Performs name resolution + type checking + CircularDefine detection on the DEFINE dependency graph. Key invariant: no panic on adversarial input — every lexical/syntactic/semantic error is reported as a precise ParseErrorKind; a returned SmvModule is guaranteed well-typed and name-resolved, so smv-model may encode it without re-validating. no_std + alloc. Phases: 0 (AST shells, error types), 3 (full Lexer+Parser, name/type checking, CircularDefine).

3.4.3 smv-model — flattening + boolean encoding (Encoder / EncodedFsm)

Responsibility: flatten the typed AST and boolean-encode finite-domain state variables onto BDD levels, then build the symbolic FSM. In: SmvModule + a BddManager. Out: VarEncoding { levels, ty } per variable and EncodedFsm { present, next, init, trans, invar, fairness, ap }. Encoding rules: Boolean→1 level; Enum/scalar→ceil(log2 |domain|) bits + an out-of-range constraint BDD; Range(lo,hi)→bounded binary. Builds two VarMaps (present, next), compiles each Expr to a Bdd over present levels (and over next when wrapped in Next), assembles init = init() ∧ INVAR, trans = next() ∧ TRANS ∧ next-INVAR (stored conjunctively partitioned), and fairness Bdds. Key invariant: level assignment is total, injective, and frozen for the manager's lifetime, and present/next are disjoint level ranges related only by rename — the prerequisite that makes downstream image/pre-image and canonicity sound. Depends: smv-bdd + smv-syntax. Phases: 0 (type shells), 4 (VarEncoding, present/next VarMap, Expr→Bdd), 5 (init/trans/invar/fairness, conjunctive partitioning).

3.4.4 smv-logic — temporal logic front end

Responsibility: parse property text into typed temporal formulas and bind atomic propositions to BDDs. In: SpecDecl strings (Ctl/Ltl) + the EncodedFsm.ap table [(Atom,Bdd)]. Out: CtlFormula (Ap/Not/And/Or/Ex/Eg/Eu; AX/AU/AG/AF/EF derived) and LtlFormula (Ap/Not/And/Or/X/U/R/F/G), each in NNF with Ap leaves carrying a resolved Bdd. Components: the CTL and LTL property parsers, NNF/normalization (push negations to leaves; reduce derived operators to the EX/EU/EG and X/U primitives), and AP→Bdd binding against the model's ap. Key invariant: AP closure + NNF normal form — every atomic proposition resolves to exactly one model Bdd, and every formula handed to smv-check is in NNF over the primitive operator set, so the checker dispatches on a small fixed set of cases. Depends: smv-bdd + smv-model. no_std + alloc. Phases: 0 (formula shells), 7 (CTL parse + derived expansion path used by CtlChecker), 9 (LTL parse + NNF feeding the Buchi build).

3.4.5 smv-check — the symbolic engine (CtlChecker / LtlChecker)

Responsibility: decide whether the FSM satisfies a temporal property, entirely by BDD set operations (state SETS as BDDs; never enumerates states). In: &mut BddManager + &EncodedFsm + a CtlFormula/LtlFormula. Out: a SAT state-set Bdd (CtlChecker::check), reachable()->Bdd, and counterexample(...)->Option<Trace>. CTL: EX p=preimage(p)=and_exists(trans,p,next-cube) then rename; E[p U q]=lfp Z. q OR (p AND EX Z); EG p=gfp Z. p AND EX Z; spec HOLDS iff init AND not sat(f) == bdd_false (i.e. init ⊆ sat(f)). reachable=lfp Z. init OR Img(Z) where Img(S)=(exists present.(trans AND S))[next->present]. LTL: build a (generalized) Buchi automaton for ¬φ, take the symbolic product with EncodedFsm, then Emerson-Lei nested gfp/lfp fair-cycle detection over EX and the acceptance/fairness sets; A φ holds iff no fair cycle is reachable from init. Witnesses: onion-ring backward sets for shortest CTL counterexamples, lasso witnesses for EG/LTL, cubes mapped back to readable StateAssignment; Trace { states, loopback }. Key invariant: fixpoint soundness rides on canonicity — convergence is detected by O(1) handle equality, so a correct BddManager makes lfp/gfp termination and the subset test exact. Depends: smv-bdd + smv-model + smv-logic. Phases: 6 (reachability/image/pre-image fixpoint framework), 7 (CtlChecker), 8 (counterexamples/witnesses/StateAssignment), 9–10 (LtlChecker: product + Emerson-Lei), 12 (fairness, early-quantification schedule).

3.4.6 smv-bmc — Bounded Model Checking (Unroller / SatBackend)

Responsibility: the SAT-based path — find a length-≤k counterexample by unrolling the transition relation into CNF (no BDDs). In: EncodedFsm { init, trans }, an LtlFormula/InvarSpec, and a bound k. Out: CnfFormula { clauses, nvars } (DIMACS literals), then a Trace. Components: Unroller builds I(s0) AND conj_{i<k} T(si,si+1) AND or_{i<=k} not-prop(si) via a Tseitin transform (fresh variables per gate, linear-size CNF); the SatBackend trait (solve(&CnfFormula)->SatResult, DIMACS in / SatResult::Sat(Vec<bool>)|Unsat out) so the bundled simple DPLL/CDCL or #277 plugs in interchangeably; on Sat, each step's bits decode to a StateAssignment, yielding the counterexample Trace. NON-GOAL: smv-bmc does not implement a competitive SAT core — that is #277; it only consumes a SatBackend. Key invariant: unrolling fidelity + completeness threshold — the CNF is SAT iff a k-step counterexample exists, and safety checking is complete once k reaches the reachability/recurrence diameter. Depends: smv-model + smv-logic. Phases: 11 (Unroller, Tseitin CNF, SatBackend, bundled DPLL/CDCL, incremental k, model→Trace), 12 (completeness threshold).

3.4.7 smv-cli — the "smv" binary

Responsibility: the user-facing orchestrator wiring source+spec through the pipeline and rendering results. In: CLI args, model.smv, CTLSPEC/LTLSPEC. Out: process exit code + textual verdict/Trace/stats/dot. Subcommands: check (CTL/LTL via smv-check), bmc (smv-bmc), reachable (lfp reachable set + satcount), simulate (step the FSM), bdd-stats (node_count/unique-table/cache metrics), encode (dump VarEncoding/EncodedFsm), dot (export BDDs). Key invariant: it is glue only — owns no verification logic; all decisions live in smv-check/smv-bmc, all encoding in smv-model, all parsing in smv-syntax/smv-logic. It is the sole std crate and the sole holder of the trust boundary at its input edge. Depends: all six library crates. Phases: 0 (binary skeleton, smoke test: ithvar(0); parse a 1-var model; assert bdd_true != bdd_false), incrementally extended each phase as subcommands light up, finalized in 13 (validation/differential-testing harness vs NuSMV).

8. Domain Model — SMV Language, BDDs, and Temporal Logic

The domain has four interlocking models: (1) the ROBDD as a canonical representation of boolean functions over a fixed variable order; (2) the SMV modeling language that describes a finite-state machine; (3) the Kripke structure semantics that SMV denotes and that the symbolic engine manipulates as BDDs; (4) the CTL/LTL temporal logics that state properties over Kripke paths. This section pins down each model precisely — structure, invariants, grammar, semantics, encoding — and ties them together with a worked example. All names are LOCKED per the canonical spine.

8.1 The BDD model — node structure, reduction, canonicity

A BDD is a rooted DAG over a fixed total order of boolean variables, where each non-terminal node tests one variable and branches to its low child (variable = 0) and high child (variable = 1). An ROBDD is a BDD that is reduced and ordered.

Node structure (conceptual; physical layout in §10):

Field Type Meaning Invariant
level u32 index in the global variable order (0 = top, deepest = bottom) level(node) < level(low) and level(node) < level(high) — strictly increasing toward leaves
low Bdd (u32) cofactor with this var = 0 (the "else"/0-edge) points to a node of strictly greater level, or a terminal
high Bdd (u32) cofactor with this var = 1 (the "then"/1-edge) points to a node of strictly greater level, or a terminal

Terminals: two leaves, bdd_false (0) and bdd_true (1), with a sentinel level (u32::MAX) so the ordering invariant holds uniformly. Bdd(u32) is a handle = index into the manager node table; it is the only thing callers hold.

Ordering. A single global total order on variables is fixed for the manager. Every root-to-leaf path visits levels in strictly increasing order; no variable is tested twice on a path; a variable may be skipped on a path (its value is irrelevant there — that skip is the compression).

Reduction rules (the two Bryant 1986 rules; both enforced at construction by the unique table, never as a post-pass):

Rule Statement Effect
R1 — no redundant test If low == high for a node, the node is useless (the variable does not affect the function): return the child directly, never create the node. deletes redundant decision nodes
R2 — no duplicate node If a node with identical (level, low, high) already exists, return the existing handle instead of allocating a new one (hashcons via the unique table). merges isomorphic subgraphs

Canonicity invariant (load-bearing). Fixed total order + R1 + R2 ⇒ for a given boolean function there is exactly one ROBDD. Therefore:

two functions are equal  <=>  their BDD handles (u32) are equal      // O(1) equality
a function is the constant false  <=>  its handle == bdd_false       // O(1) validity/UNSAT test
a function is a tautology          <=>  its handle == bdd_true

This is THE invariant the whole engine rests on: fixpoints terminate because successive BDDs become handle-equal when the set stops changing; CTL init ⊆ sat(f) is decided by one handle comparison (init AND not sat(f)) == bdd_false. Any bug that breaks canonicity silently corrupts equality and fixpoint convergence, yielding wrong verdicts with no crash — the gravest failure class (Threat Model). Property test: build the same function by structurally different expressions; assert identical handle (Phase 1 acceptance).

ASCII picture — ROBDD of f = (a ∧ b) ∨ c with order a < b < c (levels a=0,b=1,c=2). Solid edge = high (var=1), dashed = low (var=0):

                 ┌─────┐
                 │  a  │ level 0
                 └┬───┬┘
            low(0) ┊   │ high(1)
                   ┊   │
              ┌────▼┐  └──┐
              │  c  │     │
              └┬──┬─┘     │
         low(0)┊  │high(1)│
               ┊  │       │
            ┌──▼┐ │   ┌───▼┐
            │ 0 │ │   │  b │ level 1
            └───┘ │   └┬──┬┘
                  │low ┊  │ high
                  │    ┊  │
                  └────┤  │
                       │  │
                  ┌────▼┐ │      (the c-node is SHARED: reached
                  │  c  │◄┘       from a=0 directly, and from a=1,b=0)
                  └┬──┬─┘
             low(0)┊  │high(1)
                   ▼  ▼
                 ┌──┐┌──┐
                 │0 ││1 │      level 2 terminals
                 └──┘└──┘

Reading: a=1,b=1 → 1 (independent of c); else the value is c. The single c node is shared by R2; no node has low==high by R1. (Schematic — exact child wiring depends on the chosen edge convention; with complement edges only the constant 1 terminal exists, 0 = not 1.)

ite — the Shannon expansion (the single primitive). Every BDD operation is built from ite. For the top variable x (smallest level among the operands):

ite(f, g, h) = (f ∧ g) ∨ (¬f ∧ h)
             = x · ite(f_x,  g_x,  h_x)  +  ¬x · ite(f_¬x, g_¬x, h_¬x)      // Shannon on x

where f_x is the high cofactor (restrict x=1), f_¬x the low cofactor. Recursion bottoms out at terminals; results are memoized in the computed cache keyed by the triple (f,g,h). With the cache, ite is O(|f|·|g|·|h|) nodes. Derived ops are special cases:

Op as ite
and(f,g) ite(f, g, bdd_false)
or(f,g) ite(f, bdd_true, g)
not(f) ite(f, bdd_false, bdd_true) (or O(1) complement edge)
xor(f,g) ite(f, not(g), g)
imp(f,g) ite(f, g, bdd_true)

8.2 The SMV modeling language — EBNF

A model is a single MODULE main (this engine: flat, no module instantiation — a NON-GOAL). Grammar (EBNF; terminals quoted; maps directly to SmvModule and Expr in smv-syntax):

module        ::= "MODULE" ident moduleBody ;
moduleBody    ::= { section } ;
section       ::= varSection | assignSection | defineSection
                | invarSection | transSection | spec ;

varSection    ::= "VAR" { varDecl } ;
varDecl       ::= ident ":" varType ";" ;
varType       ::= "boolean"                              (* VarType::Boolean *)
                | "{" atom { "," atom } "}"              (* VarType::Enum   *)
                | intLit ".." intLit ;                   (* VarType::Range(lo,hi) *)

assignSection ::= "ASSIGN" { assignDecl } ;
assignDecl    ::= "init" "(" ident ")" ":=" expr ";"     (* AssignKind::Init  *)
                | "next" "(" ident ")" ":=" expr ";"     (* AssignKind::Next  *)
                | ident ":=" expr ";" ;                  (* AssignKind::Plain *)

defineSection ::= "DEFINE" { defineDecl } ;
defineDecl    ::= ident ":=" expr ";" ;                  (* DefineDecl: macro, substituted *)

invarSection  ::= "INVAR"  expr ";" ;                    (* InvarDecl: state constraint *)
transSection  ::= "TRANS"  expr ";" ;                    (* TransDecl: relational constraint *)

spec          ::= "CTLSPEC"  ctlExpr ";"                 (* SpecDecl::Ctl(String)  *)
                | "LTLSPEC"  ltlExpr ";"                 (* SpecDecl::Ltl(String)  *)
                | "INVARSPEC" expr ";" ;                 (* SpecDecl::InvarSpec(Expr) -> AG expr *)

expr          ::= orExpr ;
orExpr        ::= andExpr   { ("|" | "xor") andExpr } ;
andExpr       ::= relExpr   { "&" relExpr } ;
relExpr       ::= addExpr   { ("=" | "!=" | "<" | "<=" | ">" | ">=") addExpr } ;
addExpr       ::= unaryExpr { ("+" | "-" | "mod") unaryExpr } ;
unaryExpr     ::= "!" unaryExpr | primary ;
primary       ::= ident                                  (* Expr::Var *)
                | const                                  (* Expr::Const *)
                | "next" "(" expr ")"                    (* Expr::Next — only legal in TRANS / next() RHS *)
                | caseExpr
                | "(" expr ")" ;
caseExpr      ::= "case" { expr ":" expr ";" } "esac" ;  (* Expr::Case(Vec<(guard,val)>); first-match *)

const         ::= "TRUE" | "FALSE" | intLit | atom ;     (* Value: Bool | Int | EnumAtom *)
ident, atom   ::= letter { letter | digit | "_" } ;
intLit        ::= [ "-" ] digit { digit } ;

Notes / pitfalls baked into the grammar:

  • Expr::Next (next(e)) is only meaningful inside TRANS or on the RHS of a next(x) := e assignment — it refers to the next-state value. next() nested inside next() is a parse/type error.
  • case … esac is first-match: guards evaluated top to bottom; the value of the first true guard wins. An un-exhaustive case (no guard provably true) is a model error for an assignment target; convention requires a final TRUE : …; arm.
  • ASSIGN is the functional style (init/next/plain); INVAR/TRANS are the relational style. Both compile to the same symbolic FSM (§8.6, Phase 5).
  • INVARSPEC e is sugar for the CTL spec AG e.

8.3 Kripke-structure semantics and the SMV→Kripke map

The denotation of an SMV model is a Kripke structure M = (S, S₀, R, L):

Component Definition SMV source
S — states all type-valid valuations of the declared VARs VAR section (the variable domains)
S₀ — initial states states satisfying the initial predicate init(x):=e conjuncts ∧ INVAR
R ⊆ S×S — transition relation (s,s') allowed pairs next(x):=e ∧ TRANS ∧ INVAR(s')
L : S → 2^AP labeling: which atomic props hold in s evaluation of DEFINEs / atomic relations over s

Key modeling facts:

  • A state is a complete assignment to all state variables; S is finite because every VarType is finite (boolean=2, Enum=|atoms|, Range(lo,hi)=hi−lo+1 values). |S| can be astronomically large (10^20+) — symbolic methods (BDDs) represent sets of states, never enumerate them (the core distinction from explicit-state #279).
  • R is total in NuSMV semantics (every state must have a successor) unless restricted; a model with a deadlock state (no successor) makes that branch's CTL semantics subtle — flagged as a failure mode, optionally completed by a self-loop.
  • The initial predicate init and transition relation trans are both built as BDDs (Phase 5): init: Bdd over present-state vars; trans: Bdd over present and next-state vars.
  • An atomic proposition is a boolean expression over present-state vars (e.g. pc = critical); each binds to a state-set Bdd in EncodedFsm.ap : Vec<(Atom, Bdd)>.

8.4 CTL — grammar and semantics (state formulas, branching time)

CTL formulas are state formulas (true/false at a state), interpreted over the branching tree of all paths. Each temporal operator is a path quantifier (A=all paths, E=some path) immediately followed by a path operator (X,F,G,U). Internal representation: CtlFormula (LOCKED) with primitives Ap, Not, And, Or, Ex, Eg, Eu; the rest are derived.

ctlExpr ::= "!" ctlExpr | ctlExpr ("&"|"|"|"->"|"<->") ctlExpr | "(" ctlExpr ")"
          | "EX" ctlExpr | "AX" ctlExpr | "EF" ctlExpr | "AF" ctlExpr
          | "EG" ctlExpr | "AG" ctlExpr
          | "E" "[" ctlExpr "U" ctlExpr "]" | "A" "[" ctlExpr "U" ctlExpr "]"
          | ap ;                                  (* ap = boolean state expr -> Expr -> Bdd *)

Semantics — s ⊨ φ ("state s satisfies φ"); sat(φ) = { s | s ⊨ φ } is the state-set Bdd the CtlChecker returns:

Formula Meaning Fixpoint (computed in smv-check)
EX φ some successor satisfies φ sat(EX φ) = preimage(sat φ)
EG φ some path where φ holds forever gfp Z. sat(φ) ∧ EX Z (greatest fixpoint)
E[φ U ψ] some path: φ until ψ (ψ eventually) lfp Z. sat(ψ) ∨ (sat(φ) ∧ EX Z) (least fixpoint)
EF φ E[TRUE U φ] lfp Z. sat(φ) ∨ EX Z
AX φ ¬EX ¬φ dual of EX
AG φ ¬EF ¬φ — invariant ¬(lfp Z. ¬sat(φ) ∨ EX Z)
AF φ ¬EG ¬φ dual of EG
A[φ U ψ] derived from EU + EG (NuSMV identity) ¬(E[¬ψ U (¬φ∧¬ψ)] ∨ EG¬ψ)

LFP vs GFP — why. EU/EF (reachability-style, "eventually") are least fixpoints: start from false, add states, converge upward. EG/AG-invariants ("forever") are greatest fixpoints: start from true (or sat φ), remove states, converge downward. Both iterate the preimage operator until the BDD handle stops changing (canonicity ⇒ exact termination test). Monotone operator over the finite lattice 2^S ⇒ Knaster–Tarski guarantees a unique fixpoint reached in ≤ |S| (in practice ≤ BDD-diameter) iterations.

Verdict. Spec φ HOLDS on M iff every initial state satisfies it: S₀ ⊆ sat(φ), decided by (init AND not sat(φ)) == bdd_false. Many tools intersect sat(φ) with the reachable set first (avoids spurious counterexamples in unreachable states); the engine restricts to reachable states for counterexample generation (Phase 8).

8.5 LTL — grammar and semantics (path formulas, linear time)

LTL formulas are path formulas (true/false of a single infinite path π = s₀ s₁ s₂ …). M ⊨ φ means every path from every initial state satisfies φ (implicit universal/A). Internal type: LtlFormula (LOCKED): Ap, Not, And, Or, X, U, R, F, G.

ltlExpr ::= "!" ltlExpr | ltlExpr ("&"|"|"|"->"|"<->") ltlExpr | "(" ltlExpr ")"
          | "X" ltlExpr | "F" ltlExpr | "G" ltlExpr
          | ltlExpr "U" ltlExpr | ltlExpr "R" ltlExpr
          | ap ;

Semantics — π,i ⊨ φ (path π at position i); write π ⊨ φ for π,0 ⊨ φ:

Op Reading Definition
X φ next π,i ⊨ Xφ iff π,i+1 ⊨ φ
φ U ψ until (strong: ψ must occur) ∃ j≥i. π,j ⊨ ψ ∧ ∀ i≤k<j. π,k ⊨ φ
φ R ψ release (dual of U) ∀ j≥i. π,j ⊨ ψ ∨ ∃ i≤k<j. π,k ⊨ φ
F φ eventually = TRUE U φ ∃ j≥i. π,j ⊨ φ
G φ globally = ¬F¬φ = FALSE R φ ∀ j≥i. π,j ⊨ φ

Checking strategy (Phase 9–10). M ⊨ A φ iff M has no path satisfying ¬φ. Procedure: translate ¬φ to a (generalized) Büchi automaton A_¬φ (GPVW/tableau); form the synchronous product M × A_¬φ (BDD of product states); then M ⊨ Aφ iff the product has no fair (accepting) cycle reachable from an initial state. The fair states are computed by Emerson-Lei, a nested gfp/lfp over EX and the acceptance/fairness sets; a counterexample is a lasso (finite stem + accepting cycle).

CTL vs LTL — incomparable, both kept: CTL can express branching properties (AG EF reset — "reset is always reachable") that LTL cannot; LTL can express fairness/path properties (GF req → GF ack) awkwardly or not at all in CTL. The engine implements both front ends sharing the BDD/fixpoint machinery.

8.6 Boolean encoding of finite-domain variables

smv-model's Encoder maps each finite VarType to a contiguous run of boolean BDD levels (VarEncoding { levels: Vec<u32>, ty: VarType }), and allocates a paired present and next copy (present: VarMap, next: VarMap) so the transition relation can relate s to s'. rename swaps present↔next.

VarType bits encoding extra constraint
Boolean 1 level ↔ value none
Enum(atoms) `⌈log2( atoms )⌉`
Range(lo,hi) ⌈log2(hi−lo+1)⌉ offset binary: encode (value − lo) out-of-range constraint excludes codes > hi−lo

Worked sizing: a var with 5 enum atoms → 3 bits (8 codes), 3 illegal codes excluded; a Range(0,9) (mod-10 counter) → 4 bits (16 codes), 6 illegal codes excluded. Total BDD vars = Σ bits over all vars, ×2 for present+next. Variable interleaving of present/next copies of the same variable (s, s', t, t', …) is the canonical order that keeps trans BDDs small (Phase 4/12). Arithmetic (+,-,mod,<) compiles to ripple structures of ite over the bit BDDs (Phase 4). =/!= against a constant compiles to a cube/conjunction over the bits.

EncodedFsm (LOCKED) is the handoff record:

pub struct EncodedFsm {
    pub present: VarMap, pub next: VarMap,     // present/next level maps
    pub init: Bdd,                             // initial predicate (over present)
    pub trans: Bdd,                            // transition relation (present & next)
    pub invar: Bdd,                            // state invariant (over present)
    pub fairness: Vec<Bdd>,                    // fairness state-sets (generalized Büchi)
    pub ap: Vec<(Atom, Bdd)>,                  // atomic prop -> state-set
}

8.7 Worked example — a 2-bit modulo-4 counter with reset

A small, exhaustively checkable model showing SMV source → encoding → init/trans BDDs (conceptually) → a CTL spec and its fixpoint evaluation → a counterexample. (A mutual-exclusion variant appears in §8.8's malformed cases.)

SMV source:

MODULE main
VAR
  v     : 0 .. 3;          -- Range, 2 bits  (b1 b0)
  reset : boolean;
ASSIGN
  init(v) := 0;
  next(v) := case
               reset      : 0;
               v = 3      : 0;          -- wrap-around (mod 4)
               TRUE       : v + 1;
             esac;
DEFINE
  at_max := (v = 3);
CTLSPEC AG (at_max -> AX (v = 0));      -- from max, next state is 0
CTLSPEC AG AF at_max;                   -- max is reached infinitely often
CTLSPEC AG EF (v = 0);                  -- 0 is always reachable

Encoding. v → 2 present bits {b1,b0} (offset 0, full range so no out-of-range constraint), reset → 1 bit. Next-state copies {b1',b0'}, reset'. Total: 3 present + 3 next BDD levels, interleaved b1,b1',b0,b0',reset,reset'. |S| = 4 × 2 = 8 states.

Symbolic predicates (conceptual — these are BDDs, shown as boolean formulas):

init  ≡  (b1=0) ∧ (b0=0)                                  -- v=0; reset unconstrained (free)
                                                          -- (8 states collapse: 2 satisfy init: reset∈{0,1})
trans ≡  ( reset' arbitrary )
       ∧ case-encoded:
           reset      → v'=0                              -- (b1'=0 ∧ b0'=0)
           ¬reset ∧ v=3 → v'=0
           ¬reset ∧ v≠3 → v' = v+1   (2-bit incrementer over b1,b0 → b1',b0')
at_max ≡ (b1=1) ∧ (b0=1)                                  -- the DEFINE, as a state-set Bdd

node_count(trans) here is tiny (well under 30 nodes); satcount(reachable, 3) = 8 (every counter value × every reset value is reachable).

Fixpoint evaluation of CTLSPEC AG EF (v = 0) = ¬EF¬EF(v=0):

inner = sat(EF (v=0)) = lfp Z. sat(v=0) ∨ preimage(Z)
  iter0: Z0 = false
  iter1: Z1 = {v=0}                              (4 states: v=0, reset∈{0,1}, but counted over all bits)
  iter2: Z2 = Z1 ∪ preimage(Z1) = {v=0} ∪ {v=3} ∪ {reset=1}   (predecessors of v=0)
  iter3: Z3 = Z2 ∪ preimage(Z2) = ALL states     (every state can reach v=0)
  iter4: Z4 == Z3  -> handle-equal -> FIXPOINT.  inner = TRUE (all states)
outer = sat(EF ¬inner) = sat(EF false) = false
AG EF(v=0)  holds  iff  init AND not(¬outer) == false  ->  outer=false -> sat = ¬false = TRUE
verdict: init ⊆ sat  ->  (init AND not TRUE) = (init AND false) = bdd_false  ->  HOLDS ✔

CTLSPEC AG AF at_max likewise HOLDS (AF = ¬EG¬; the counter always advances toward 3 unless reset, and even reset paths re-reach 3 — the gfp EG ¬at_max over fair behavior is empty). CTLSPEC AG (at_max -> AX (v=0)) HOLDS: from any at_max state, every successor sets v'=0 (both reset and v=3 arms of the case force 0).

Counterexample shape. Replace the spec with a FALSE one, CTLSPEC AG (v != 3) (claims the counter never reaches 3). sat(¬spec) = sat(EF (v=3)) includes init ⇒ FAILS. The CtlChecker extracts a shortest counterexample by onion-ring backward sets (Phase 8): v=0 → v=1 → v=2 → v=3, mapping each BDD cube to a readable StateAssignment:

Trace { loopback: None, states: [
  StateAssignment { v: 0, reset: 0 },     // s0  (initial)
  StateAssignment { v: 1, reset: 0 },     // s1
  StateAssignment { v: 2, reset: 0 },     // s2
  StateAssignment { v: 3, reset: 0 },     // s3  -- violates (v != 3)
]}

For an EG/AF-style witness the Trace is a lasso: loopback: Some(i) marks the start of the repeating cycle (e.g. the 0→1→2→3→0 loop witnessing AG AF at_max).

8.8 Malformed models — diagnostics

smv-syntax/smv-model reject ill-formed input with a precise ParseErrorKind (LOCKED). Each example below is minimal and shows the variant emitted:

# Malformed snippet Diagnosis ParseErrorKind
1 next(v) := w + 1; where w never declared in VAR/DEFINE reference to undeclared name UnknownVar
2 VAR p:boolean; ASSIGN next(p) := v + 1; (v:0..3) boolean target assigned an integer expr TypeMismatch
3 VAR x:0..3; INVAR x = wibble; (wibble not an enum atom / not in domain) comparing range var to an unknown/incompatible literal TypeMismatch (or UnknownVar if wibble is a bare ident)
4 `DEFINE a := b & c; b := a c;` a depends on b depends on a — cyclic macro
5 VAR v:0..3; ASSIGN init(v) := 7; 7 ∉ [0,3] OutOfRange
6 VAR s : {idle running done (missing }) enum type list not closed UnexpectedToken
7 VAR v : 3 .. 0; empty/inverted range (lo > hi) BadType
8 CTLSPEC EX EX ; (no operand) / CTLSPEC A[p]; (missing U) malformed CTL — operand or U missing UnexpectedToken (surfaced by smv-logic's CTL parser)
9 LTLSPEC G (a U ); (U missing right operand) / LTLSPEC X X malformed LTL UnexpectedToken
10 ASSIGN next(v) := next(next(v)); next() nested inside next() UnexpectedToken (or TypeMismatch — illegal next-of-next)
11 next(v) := case v = 0 : 1; esac; with v:0..3 (no TRUE: arm; not exhaustive) partial case for a functional assignment ⇒ unconstrained successor model warning → completeness error (NuSMV: leaves v' free; engine flags)
12 two assigns next(v):=0; and next(v):=1; (double-assign) variable assigned twice in the same frame TypeMismatch-class consistency error (multiple next-defs)

Diagnostic requirements: every error carries source span (line:col), the offending token/identifier, and (for TypeMismatch) the expected vs found type; for CircularDefine, the dependency cycle (a → b → a); for OutOfRange, the value and the declared bounds. These diagnostics are conformance-tested in Phase 3/4 against a fixture corpus of malformed models (one fixture per ParseErrorKind).
