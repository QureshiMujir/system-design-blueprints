Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does fixing a total variable order make the BDD canonical? What breaks if you allow two nodes at the same level to use different orderings of their descendants? (resolves in §6 P1 + §13 Phase 1 canonicity test.)
  2. The two reduction rules (R1: eliminate nodes with low==high; R2: merge identical triples) are stated as simplifications. Prove that both are necessary — construct a BDD that is canonical under R1 but not R2, and vice versa. (resolves in §8 Domain Model reduction rules + §13 Phase 1 implementation.)
  3. Why is ite(f,g,h) sufficient as the sole primitive? Give a step-by-step derivation showing that and_exists(f,g,cube) can be expressed purely as nested ite calls (without using a separate and + exists). (resolves in §6 P3 + §14 Phase 2 BDD operations.)
  4. How does the computed cache interact with GC? Why must the cache be entirely purged on every GC sweep rather than just removing entries referencing dead nodes? What would go wrong if you tried the partial approach? (resolves in §7 INV-4 + §14 Phase 2 GC.)
  5. Explain the satcount formula for a non-terminal node n: count(n) = 2^(skip_low) * count(low(n)) + 2^(skip_high) * count(high(n)) where skip_x = level(child_x) - level(n) - 1. What does "skip" represent physically? What is the base case for terminals? (resolves in §11 Core Schema satcount signature + §14 Phase 2 satcount.)
  6. Write out the full lfp characterization of sat(E[f U g]) in terms of preimage and BDD operations. Why is this a least fixpoint (not greatest)? What initial set does the iteration start from, and what is the termination condition? (resolves in §18 Phase 6 fixpoint framework + §19 Phase 7 CTL.)
  7. What is the difference between the forward-image formula Img(S) = ∃V . T(V,V') ∧ S(V) and the pre-image formula PreImg(S) = ∃V' . T(V,V') ∧ S(V')? Which is used for reachability, and which for CTL EX? Why? (resolves in §18 Phase 6 reachability + §19 Phase 7 CTL EX.)
  8. The and_exists operation is described as "fused" conjunction-quantification. What is the concrete BDD-size advantage of fusion over the two-step exists(and(f,g), cube)? Give an example where the intermediate and(f,g) would be exponentially larger than and_exists(f,g,cube). (resolves in §14 Phase 2 and_exists + §18 Phase 6 image usage.)
  9. CTL EG p requires a greatest fixpoint. What would happen if you implemented it as a least fixpoint starting from p (same as EU)? Construct a 3-state Kripke structure where the lfp and gfp give different results for EG p, and show which is correct per the semantics. (resolves in §18 Phase 6 fixpoint framework + §19 Phase 7 CTL EG.)
  10. For LTL G(p → F q), negate and apply GPVW. What does the resulting generalized Büchi automaton look like? How many acceptance sets does it have? How does Emerson-Lei find the fair cycles in the product? (resolves in §21 Phase 9 LTL front end + §22 Phase 10 Emerson-Lei.)
  11. You run your engine on the Peterson mutual exclusion model and get "AG(¬(critical_1 ∧ critical_2)) HOLDS", but NuSMV reports "VIOLATED" with a counterexample. Describe your triage process. What is the first thing you check, and why? (resolves in §25 Phase 13 differential testing + Failure Modes and Recovery F5/F11.)
  12. Your BDD node count explodes by 10× after adding variable reordering. What are the three most likely causes, and how do you diagnose each? (resolves in §9 ADR-08 variable-ordering policy + §24 Phase 12 sifting.)
  13. The Tseitin transform produces equisatisfiable CNF. What exactly does "equisatisfiable" mean here? Is the resulting CNF equivalent to the original formula? Why does the distinction matter for BMC (specifically for the "no bug up to depth k" result)? (resolves in §8 Domain Model Tseitin transform + §23 Phase 11 BMC.)
  14. You observe that satcount returns a value that is 2× too large on one specific fixture. What is the most likely cause, and what does the fix look like in the code? (resolves in §11 Core Schema satcount signature + §14 Phase 2 satcount.)
  15. A fuzz campaign on BddManager::ite finds an input that causes node_count to return a different value from two structurally equivalent builds of the same formula. Which invariant has been violated, how would you detect it in CI without fuzzing, and what is the root cause in the implementation? (resolves in §7 INV-1 canonicity + §25 Phase 13 fuzzing.)
  16. ADR-03 chose u32 index handles over Rc<Node>. A colleague argues that Rc<Node> would make the code simpler by removing the need for a GC. Rebut this argument with at least three concrete failure modes of the Rc approach for a BDD manager. (resolves in §9 ADR-03 + §11 Core Schema Bdd/BddManager.)
  17. ADR-12 chose and_exists (fused relational product) over separate and + exists. For a model with 50 state bits and a conjunctively partitioned transition relation with 10 conjuncts, estimate the intermediate BDD size difference between the two approaches. (resolves in §9 ADR-12 + §18 Phase 6 image computation.)
  18. The SatBackend trait (ADR-16) is a seam between the Tseitin encoder and the SAT solver. What would you need to change in smv-bmc if you wanted to support incremental SAT solving (adding clauses one at a time across BMC depths)? Would the current trait signature support this, or would you need to extend it? (resolves in §9 ADR-16 + §23 Phase 11 BMC.)
  19. The project uses conjunctive partitioning of the transition relation (ADR-11). When would you switch to disjunctive partitioning? Give a concrete model class where disjunctive is strictly better, and explain why. (resolves in §9 ADR-11 + §24 Phase 12 partitioning.)
  20. Why does the LTL checker negate φ (building Büchi(¬φ)) rather than checking φ directly? What logical relationship makes this valid, and what would go wrong if you forgot the negation? (resolves in §21 Phase 9 LTL front end + §22 Phase 10 LTL checking.)
  21. A user reports that smv check hangs indefinitely on their 200-variable model. What resource-limit configuration knobs exist in the engine, and what is the correct user-facing advice? What verdict/error should the engine return when it hits the node limit? (resolves in §4 System Constraints caps + Threat Model T1.)
  22. The Phase 13 differential harness reports a verdict match but the counterexample traces differ in length. Is this a bug? What are the conditions under which a shorter trace from our engine is valid, and when would it be a bug? (resolves in §25 Phase 13 + Failure Modes and Recovery F10.)
  23. You are adding a new LTL operator (e.g., W (weak until), not currently in the grammar). List every file and section in the blueprint that must change, in dependency order. (resolves in §8 Domain Model grammar + §21 Phase 9 LTL front end.)
  24. A downstream user wants to embed smv-bdd as a no_std library in a real-time OS kernel with a fixed memory pool (no heap allocator). What would need to change in the BddManager implementation to support a fixed-size arena instead of Vec<Node>? (resolves in §9 ADR-19 + §11 Core Schema BddManager.)
  25. The Emerson-Lei algorithm computes fair states as a nested greatest fixpoint. On a model with 30 state bits and 5 fairness sets, estimate the worst-case number of BDD operations. Is there a case where a simpler algorithm (single-set Buchi) would give the same result? When exactly? (resolves in §18 Phase 6 fixpoint framework + §22 Phase 10 Emerson-Lei.)

Mental Models & First Principles

The following first-principles mental models underpin every design decision in this blueprint. When a performance or correctness question arises during implementation, trace it back to the applicable model below before reaching for an optimization.

MM1 — The Canonical DAG Principle (P1). Any two Boolean functions that are equal must share the exact same DAG node in the manager, and any two functions that are unequal must have different handles. This is not an optimization — it is the load-bearing invariant of the entire system. Every other operation (image computation, fixpoint iteration, CTL evaluation) depends on f == g iff handle(f) == handle(g). Violate this once and all downstream verdicts are silently wrong.

MM2 — Symbolic = Working with Predicates, Not States. The entire point of symbolic model checking (P3) is that we never enumerate the 10^20 reachable states. Instead, init, trans, and every intermediate set is a BDD representing a predicate over state bits. When you feel the urge to "loop over all states", that is a signal you have left the symbolic regime. The fix is always: encode the selection as a BDD constraint and use and_exists or restrict.

MM3 — ite as the Universal Primitive (P2). All Boolean operations, quantifiers, image steps, and fixpoint iterations reduce to recursive calls on ite(f,g,h). There is one place where correctness can fail (the ite recursion + cache logic), and there is one place to audit. This is not a limitation — it is the source of the engine's simplicity. When adding a new derived operation, always ask: "can I express this as one or more ite calls?" The answer is almost always yes.

MM4 — The Cache Is Lossy; Canonicity Is Not. The computed cache (memoized ite results) can be evicted at any time without changing correctness — a cache miss merely causes recomputation. The unique table (hashcons) can NEVER be incomplete or wrong: if a node (level, low, high) exists, it must be in the unique table, and if it is in the table, it must be the unique representative. The GC protocol follows from this: the cache is purged at GC time (cheap, safe), but the unique table is rebuilt from survivors only (expensive, mandatory).

MM5 — Fixpoints Are Monotone Sequences on a Finite Lattice. Every lfp/gfp used in this system (reachable, EX, EU, EG, Emerson-Lei fair states) is a monotone function on the finite lattice of BDDs over a fixed set of state-bit levels, ordered by implication. Kleene's theorem guarantees convergence in at most 2^n iterations (where n = number of state bits). In practice, convergence is typically 5–50 iterations on real models. If a fixpoint does not converge, it is a bug — assert on non-monotonicity rather than hanging.

MM6 — Variable Order Is the Dominant Complexity Driver. The same Boolean function can have a BDD of size O(n) or O(2^n) depending solely on the variable order (P1). No amount of algorithmic cleverness compensates for a catastrophically bad order. The practical heuristic (interleave present/next levels, keep related bits adjacent) works on most synchronous models. For anomalous models (multipliers, XOR-heavy), dynamic sifting (P7) is the escape valve. Always report node_count alongside verdicts so order quality is observable.

MM7 — Counterexamples Are First-Class (I-P8). A FAIL verdict without a concrete Trace is forensically worthless — you cannot validate the model or the spec. The onion-ring backward-reachability technique for CTL (Phase 8) and lasso extraction for LTL (Phase 10) are not optional polish; they are required output of any FAIL result. The Trace is also the primary artifact for the NuSMV differential oracle (Phase 13): a mismatch in verdict OR in trace validity is a bug.

MM8 — The SAT Backend Is a Seam, Not an Optimizer (ADR-16). BMC (Phase 11) depends on a SatBackend trait, not a concrete solver. The bundled DPLL is a "does it work" baseline — #277 (the companion project) is the real solver. The Tseitin encoder and unroller must produce correct DIMACS regardless of which SAT backend is plugged in. Never let BMC performance concerns leak into the CNF encoding; CNF correctness (equisatisfiability) is the non-negotiable invariant.

MM9 — The NuSMV Oracle Is the Truth Gate (I-P11). This project's "done" condition is not unit tests passing — it is NuSMV-agreement on a corpus of real models. The differential oracle (Phase 13) is the only external reality check. Any verdict mismatch is a bug in THIS implementation (NuSMV is the ground truth by project definition), until proven otherwise by examining the NuSMV source. Design every checker with oracle-comparability in mind: same semantics, same acceptance conditions, comparable trace lengths.

MM10 — no_std Is an Architectural Constraint, Not a Feature Flag. The core crates (smv-bdd through smv-logic) must build on embedded targets (thumbv7em-none-eabi) from day zero. Discovering a std dependency in Phase 10 means a rewrite of Phase 1 data structures. The discipline is: anything that uses alloc:: is permitted; anything that uses std:: must be behind a feature gate or moved to smv-check/smv-bmc/smv-cli. CI enforces this with a no_std build job (ADR-19, ADR-24).

Glossary · 58 terms · site-wide glossary

ROBDD (Reduced Ordered Binary Decision Diagram)
rooted DAG over a fixed total variable order representing a Boolean function; "reduced" = both reduction rules applied. The data structure smv-bdd builds; the entire engine represents state sets and the transition relation as ROBDDs, never as enumerated states (vs #279). Synonym "BDD" used interchangeably; no other diagram variant (ZDD/ADD) in scope.
BDD / Bdd
pub struct Bdd(u32): an opaque index handle into the node table of one BddManager. Not an Rc; no per-node refcount cycles. Two Bdd are function-equal iff u32-equal (see canonicity). Never share a Bdd across managers.
BddManager
owner of node table, unique table, computed cache, and the variable order; &mut self for any operation that may allocate a node (ite, and, restrict, …), &self for pure reads (not, satcount, node_count). All Bdds are interpreted only relative to their manager.
node
one decision vertex: (level, low child, high child); the two terminals are the constants. node_count(f) = reachable nodes from f (a function-size measure / blow-up signal).
level
u32 rank of a variable in the fixed total order (0 = topmost/root-most). ithvar(level) returns the projection BDD for that level. Lower level number = nearer the root = tested earlier. Present/next pairing is encoded by adjacent levels (see VarMap, rename).
low child / high child
the two successors of a node: edge taken when the level's variable is 0 (low / else) vs 1 (high / then). ite(var, high, low) reconstructs the node.
reduction rules
(1) no duplicate node: never two structurally identical (level,low,high) nodes (enforced by the unique table); (2) no redundant node: delete any node with low == high (its variable is irrelevant). Together with the fixed order they yield canonicity.
unique table (hashcons)
hash map (level, low, high) -> Bdd consulted on every node creation; returns the existing handle if present, else allocates one. The mechanism that enforces the reduction rules at construction time. Hashconsing = "create node only if not already interned." Load-bearing: a miss that should have hit silently breaks canonicity.
computed cache
memo table keyed by operation operands (e.g. (f,g,h) for ite) -> result Bdd. Turns the otherwise exponential recursion of apply/ite into O(|f|*|g|*|h|). May be lossy (entries evictable) without affecting correctness, only speed. Distinct from the unique table (which must be exact).
canonicity
THE load-bearing invariant: fixed total order + both reduction rules => exactly one ROBDD per Boolean function, hence structural handle equality iff function equality and O(1) equality. Any bug breaking canonicity corrupts equality and fixpoint convergence -> wrong verdict with no crash (the gravest failure class).
ite / apply
ite(f,g,h) = (f AND g) OR (NOT f AND h): the single primitive of smv-bdd. "apply" = the general binary-operation algorithm; here every binary op is a special case of ite. and(f,g)=ite(f,g,⊥), or(f,g)=ite(f,⊤,g), xor, imp, not likewise. Memoized in the computed cache.
not / complement
not(f): logical negation, &self (pure), O(1) via a complement edge or a cache lookup (no full traversal).
cofactor / restrict
restrict(f, level, val): substitute a variable by a constant (f|_{x=val}), i.e. the Shannon cofactor. Building block of quantification and image.
cube
a BDD that is a conjunction of literals (one variable per level, each fixed to 0 or 1), representing a set of variables to quantify or a single assignment. Passed to exists/forall/and_exists to name the variable block; also the form a StateAssignment decodes from.
existential quantification
exists(f, cube) = ∃ vars(cube). f = OR of cofactors over those vars. Used to project away present (or next) variables in image/pre-image.
universal quantification
forall(f, cube) = ∀ vars(cube). f = AND of cofactors; dual of exists.
relational product (and_exists)
and_exists(f, g, cube) = ∃ vars(cube). (f AND g): conjoin then existentially quantify in one fused pass, never materializing the full f AND g. The hot kernel of image computation; pairs with early quantification to keep intermediates small.
rename
rename(f, map: &VarMap): relabel variables present<->next via a VarMap (level permutation). Used to convert an image expressed over next variables back to present variables (the [next->present] step).
VarMap
a level permutation/substitution table mapping present variable levels to their next-state counterparts (and back); fields present/next of EncodedFsm are VarMaps consumed by rename.
satcount
satcount(f, nvars) -> u128: number of satisfying assignments (models) of f over nvars variables; used as a reachable-state count / state-space-size metric (reported by bdd-stats).
node_count
node_count(f) -> usize: reachable node count of f; the per-function size metric for blow-up detection and benchmarks.
mark-sweep GC
reclamation of dead nodes (unreferenced Bdds) from the node table + unique table; mark live roots, sweep the rest, rehash. Triggered by table pressure; must preserve every externally held handle.
dot export
render a Bdd to Graphviz .dot for inspection/debugging (smv-cli dot); not on any verification hot path.
dynamic variable reordering (sifting)
runtime permutation of the variable order to shrink total node count (Rudell's sifting: slide each variable to its best level via adjacent swaps). Preserves the function (and thus all verdicts); only changes representation size. Optional, Phase 12.
Kripke structure
the finite-state semantic model (S, S₀, R, L): states, initial states, transition relation, AP-labeling. The SMV model denotes one; CTL/LTL are interpreted over it. Realized symbolically as EncodedFsm.
SmvModule
parsed SMV AST (smv-syntax): vars, defines, assigns, trans, invar, specs. Pre-encoding; finite-domain, not yet Boolean.
VarType
Boolean | Enum(Vec<Atom>) | Range(i64,i64): the finite domains a state variable may take.
VarEncoding
{ levels: Vec<u32>, ty: VarType }: maps one finite-domain variable to its assigned Boolean BDD levels. Enum/scalar uses ceil(log2(|domain|)) bits plus an out-of-range constraint BDD; bounded Range similarly. Produced by smv-model's Encoder.
initial predicate
init: Bdd in EncodedFsm: the characteristic function of the set of initial states (init() assignments AND INVAR). A spec holds from the states satisfying this.
transition relation
trans: Bdd over present+next variables: characteristic function of R ⊆ S×S, built as next() AND TRANS AND next-INVAR. The relation image/pre-image quantify against. Stored monolithically or conjunctively partitioned.
EncodedFsm
the symbolic Kripke structure: { present: VarMap, next: VarMap, init: Bdd, trans: Bdd, invar: Bdd, fairness: Vec<Bdd>, ap: Vec<(Atom,Bdd)> }. The single object every checker (CtlChecker, LtlChecker, Unroller) consumes.
conjunctive partitioning
represent trans as a list of cluster BDDs whose conjunction is the full relation, instead of one monolithic BDD, so and_exists can apply early quantification per cluster. Keeps intermediate BDDs small; the standard scaling lever for the image step. (Disjunctive partitioning is the dual for asynchronous models.)
early quantification
interleave existential quantification with the conjunction order so each present variable is quantified as soon as no remaining trans cluster mentions it, minimizing peak node_count during image. Scheduled in Phase 12.
image
Img(S) = ( ∃ present. ( trans(present,next) AND S(present) ) )[next->present]: the set of successors of state set S; computed via and_exists + rename. Forward step of reachability.
pre-image
dual of image: predecessors of S, quantifying next variables; preimage(S) = ∃ next. (trans AND S[present->next]). sat(EX p) = preimage(p).
reachable set
reachable() -> Bdd = lfp Z. init OR Img(Z): least set closed under image containing initial predicate; iterate image until the state-set Bdd stops changing (handle-equal to previous). Computed once, reused; reported by reachable/bdd-stats.
least fixpoint (lfp)
smallest set closed under a monotone BDD operator, reached by iterating from ⊥ upward to convergence (equality of consecutive Bdd handles). Used by reachable and CTL EU.
greatest fixpoint (gfp)
largest such set, iterated from ⊤ downward. Used by CTL EG and Emerson-Lei fair-state computation.
frontier simplification
restrict the next iterate to newly reached states (the frontier) rather than the whole set before the next image, shrinking the operand BDD; an optimization of the reachability loop.
CTL (Computation Tree Logic)
branching-time logic; modalities pair a path quantifier (A/E) with a temporal op (X/U/G/F). CtlFormula core = Ap/Not/And/Or/Ex/Eg/Eu; AX/AU/AG/AF/EF are derived. Each subformula evaluates to a state-set Bdd.
CtlChecker
smv-check engine: check(&CtlFormula) -> Bdd returns the SAT state-set; sat(EX p)=preimage(p), sat(E[p U q])=lfp Z. q OR (p AND EX Z), sat(EG p)=gfp Z. p AND EX Z. A spec holds iff init ⊆ sat(f), checked as (init AND not sat(f)) == bdd_false.
LTL (Linear Temporal Logic)
linear-time logic over single paths; LtlFormula = Ap/Not/And/Or/X/U/R/F/G. Checked via automata, not direct fixpoint, hence the Buchi path.
Buchi automaton
ω-automaton accepting infinite words that visit an accepting set infinitely often. smv-logic translates ¬φ (LTL) to one (GPVW/tableau or VWAA); M ⊨ Aφ iff M × Buchi(¬φ) has no reachable fair cycle.
generalized Buchi
Buchi with several acceptance sets, each visited infinitely often (the natural output of LTL translation, e.g. one set per Until). Either degeneralized to a single set or fed directly to Emerson-Lei.
LtlChecker
smv-check engine: builds the symbolic product of EncodedFsm and the Buchi automaton (automaton state bits + transition Bdd), then runs Emerson-Lei; counterexample = a fair lasso.
fair cycle
a reachable cycle (strongly connected, infinite path) that intersects every fairness/acceptance set infinitely often. Its existence = an accepting run = an LTL counterexample.
fairness
constraints forcing certain conditions to hold infinitely often along admitted paths; fairness: Vec<Bdd> in EncodedFsm. Buchi (visit set infinitely often) and Streett (response: □◇p → □◇q) variants supported (Phase 12).
Emerson-Lei
the fixpoint procedure computing the set of states on a fair cycle: a nested gfp/lfp over EX (pre-image) and the acceptance/fairness sets. Empty intersection with reachable initials => no fair cycle => spec holds.
counterexample / witness
a concrete computation demonstrating a verdict: counterexample refutes a universal/safety claim (e.g. AG p), witness confirms an existential one (e.g. EF p, EG p). Extracted by walking onion-ring backward sets; rendered as a Trace.
lasso
a finite "stem" path to a cycle plus the cycle ("loop"), i.e. an ultimately-periodic infinite path; the shape of LTL / EG counterexamples. Encoded in Trace by loopback: Option<usize> (index where the loop closes).
Trace
{ states: Vec<StateAssignment>, loopback: Option<usize> }: an executable counterexample/witness path; loopback = Some(i) marks a lasso looping to state i, None = finite prefix.
StateAssignment
one state of a Trace decoded from a BDD cube back to original SMV variables (VarType-typed values), not raw Boolean bits; the human-readable output unit.
bounded model checking (BMC)
smv-bmc: search for a counterexample of length ≤ k by unrolling the transition relation into a single propositional formula and asking a SAT solver. Finds shallow bugs fast; complete only at the completeness threshold.
unrolling
instantiating the transition relation over k time-indexed copies s0..sk: I(s0) AND conj_{i<k} T(si,si+1) AND (¬property over k); built by the Unroller. For G p, a length-k counterexample exists iff this is SAT.
Tseitin transform
linear-size conversion of an arbitrary Boolean formula to equisatisfiable CNF by introducing one fresh variable per subformula; how Unroller produces a CnfFormula without exponential blow-up.
CNF / DIMACS
Conjunctive Normal Form (AND of OR-of-literals); DIMACS = the standard integer-literal clause encoding. CnfFormula { clauses: Vec<Vec<i32>>, nvars: u32 } carries it; positive/negative i32 = literal polarity, 0 = clause terminator in serialized DIMACS.
SatBackend
trait fn solve(&mut self, cnf: &CnfFormula) -> SatResult: DIMACS in / assignment out boundary so #277 (or a bundled DPLL/CDCL) plugs in. smv-bmc does not implement a competitive solver. SatResult = Sat(Vec<bool>) | Unsat; a Sat model decodes to a Trace.
completeness threshold
the smallest k at which BMC becomes complete for a safety property: once k reaches the reachability/recurrence diameter, UNSAT at k proves the property for all depths. Computed/bounded in Phase 12; until reached, UNSAT only means "no counterexample of length ≤ k."
