4. System Constraints

Hard, quantified envelope for the symbolic engine. All numbers are targets/ceilings, enforced or asserted somewhere downstream (config defaults, debug_assert!, conformance Phase 13 ## 25). A symbolic checker's cost is dominated by live BDD node count, not by reachable-state count — 10^20 states can fit in 10^4 nodes, or blow past 10^7 nodes for a badly-ordered 10^6-state model. Constraints therefore bound nodes, ops, and cache behavior, with reachable-state scale as a derived capability.

4.2 Memory model notes

  • Node table = index arena of u32 handles (Bdd(u32)); no Rc, no cycles, no pointers → kills use-after-free/double-free that plague C BDD libs. Max 2^32−2 addressable nodes; C1 cap (1e7) is the operational ceiling, far below the type limit.
  • Layout (C2): one node = { level: u32, low: u32, high: u32, next: u32 (unique-table chain), refcount: u16, flags: u16 } = 20 B; pad to 24 B for alignment. Terminals (bdd_true/bdd_false) are reserved indices 0/1, never GC'd.
  • Two arenas only: node table (the DAG) + unique table (hashcons buckets, Vec<u32> heads). Computed cache (C5) is a separate fixed Vec of (key, result) slots — lossy, never grows, so it cannot cause OOM.
  • Memory ceiling (C3) counts nodes only; cache + unique-table buckets add ≤ (2^22·12 B ≈ 48 MiB cache) + (buckets·4 B). Total resident default budget ≈ 320 MiB; configurable upward for large verifications.

4.3 Throughput & latency notes

  • ite complexity is O(|f|·|g|·|h|) only with the computed cache (C5/C6); a cold or thrashing cache degrades toward exponential. C6 (≥90% hit) is the load-bearing performance invariant for fixpoints.
  • Forward image (and_exists + rename) is the hot inner op of reachability/CTL; conjunctive partitioning + early quantification (Phase 6 ## 18, Phase 12 ## 24) keep intermediate BDD node counts bounded so C10/C24 hold.
  • Fixpoint latency (C10) scales with peak intermediate node count and iteration count (C11 = ~diameter), not with reachable-state count (C7) — this is why 10^20 states is feasible.

4.4 Correctness, recovery & isolation notes

  • Canonicity is the gravest invariant (see Threat Model): a reduction/hashcons bug breaks O(1) equality → fixpoints "converge" to wrong sets → wrong verdict, no crash. C19 (determinism) is the primary detector; C11 (FixpointDiverged) is the safety net.
  • Recovery contract: every fallible boundary returns a typed enum (ParseError/ParseErrorKind, BddError, CheckError, BmcResult::Inconclusive). A cap overflow (C1) returns Err(NodeCapExceeded), it does not abort/OOM-kill the process — the CLI prints the cap and exits non-zero cleanly.
  • No global init (C18) + single-thread (C21) ⇒ the engine is a deterministic pure function of (model, variable_order, caps); reproducibility (C19) is verifiable bit-for-bit, which is mandatory for differential testing vs NuSMV (Phase 13 ## 25).
  • Ordering sensitivity (C20) is a performance envelope, never a correctness one: any valid total order yields the same verdict, only different node counts and times. Default order = SMV declaration order; dynamic sifting is opt-in (Phase 12 ## 24).
