Hard questions (§36)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does HTTP/2 need CONTINUATION but HTTP/3 does not, and what does that say about the relationship between framing and transport reliability? (§3, §15, §21)
  2. Trace exactly what happens to in-flight HPACK dynamic-table state if a connection-level GOAWAY arrives mid-header-block. (§13, §14, §26 FM4)
  3. Why is the amplification-limit factor exactly 3×, and how does that number interact with the minimum Initial-packet size? (§4, §18, §35 #9)
  4. If RACK declares a packet lost that was merely reordered, what protocol-level and application-level costs does that false positive impose? (§19, §35)
  5. Why does 0-RTT anti-replay require an application-level idempotency contract instead of a transport-level sequence-number check? (§20, I8, §25 T6)
  6. What specific invariant would break if the connection state machine and stream state machines shared mutable memory instead of message-passing? (§6 P2, §11, I1/I2)
  7. Explain why QPACK's Required Insert Count mechanism exists but HPACK has no equivalent — what property of QUIC streams makes it necessary? (§8, §14, §22)
  8. Why is validated-paths-only migration strictly slower to fully utilize a new path than optimistic migration, and under what real-world network condition does that tradeoff reverse? (§20, ADR-18, §34)
  9. Derive, from the System Constraints table alone, why HTTP/3's idle-connection memory ceiling is higher than HTTP/2's despite QUIC being "more efficient." (§4, §35 #3/#5)
  10. What would have to change in the Repository Layout and Core Schema if BBR were pulled forward into Phase 7 instead of deferred? (§9 ADR-19, §10, §11)
  11. Why does the Threat Model list "amplification-limit stall" as a failure mode (FM10) rather than purely a security mitigation success? (§25 T5, §26 FM10)
  12. Compare the blast radius of an HPACK table desync (FM4) to a QUIC packet-number-space confusion (FM5) — why is one connection-fatal and structurally unrecoverable while the other is merely an error condition with a defined response? (§26, I3/I5)
  13. Using the Comparative Architecture Table, explain why quinn's sans-I/O design was adopted for this project's QUIC layer but not extended to the HTTP/2 layer. (§6 P2, §34)
  14. Why does the Capacity Model derive the FD-vs-memory crossover (§35 #6) instead of just asserting "memory is the bottleneck" — what would change the answer? (§32, §35)
  15. If Multipath QUIC (ADR-20) were built today instead of deferred, which System Invariant (§7) would need a new clause, and why? (§7 I7, §20, §37)
  16. Why is alt-svc trust conditioned on the transport it arrived over (§24.6, T11) rather than on the content of the header itself? (§25, §24)
  17. Explain the causal chain from RFC 9002's PTO formula to the specific max_ack_delay default in the System Constraints table. (§4, §19.2)
  18. Why does the design put qlog emission always-on (ADR-22) rather than behind a flag, given that observability itself can become a failure mode (FM12)? (§9, §26 FM12, §31)
  19. What is the precise mechanism by which a CRIME-class attack succeeds against a naive HPACK/QPACK implementation, and why does marking three specific headers Literal-never-indexed fully close it? (§14.6, §25 T3)
  20. Using the Alternative Architectures section, argue for and against choosing TCP+TLS 1.3 over QUIC for a new HTTP-only protocol project today, citing at least one real ossified middlebox scenario. (§37, §34)

33. Mental Models & First Principles

  1. MM1 — A stream is a state machine, the connection is its scheduler. Predicts: any bug that looks like "wrong data on the wrong stream" is a scheduler/dispatch bug, not a state-machine bug (the state machine per I1 cannot itself misroute bytes). Bug class without it: debugging HEADERS reassembly and flow control as one undifferentiated blob. Applied in §8, §11.3, §16.
  2. MM2 — QUIC is TLS 1.3 wearing a transport-layer costume. Predicts: every QUIC key-management bug (§26 FM9) is really a TLS state-machine bug surfacing through the TlsConnection seam (§11.10). Bug class without it: chasing a "QUIC bug" that is actually an upstream TLS provider defect. Applied in §18, MM2's source paper Langley et al. 2017.
  3. MM3 — Every congestion controller is AIMD with a different growth function. Predicts: Cubic and BBR both still obey "additive increase, multiplicative decrease" at the loss-response boundary (Jacobson 1988); the difference is when they decide to back off. Bug class without it: treating BBR as "smarter" rather than "differently modeled," leading to wrong operator expectations during the ADR-19 migration. Applied in §19.
  4. MM4 — Header compression trades table state for bytes-on-wire; QPACK trades table state for latency too. Predicts: any compression-ratio tuning knob (reference-blocking vs. reference-free, §22.2) is really a latency/bandwidth dial, not a pure compression dial. Bug class without it: maximizing compression ratio and being surprised by RIC-wait tail latency (§23.7). Applied in §14, §22, §35.
  5. MM5 — A connection ID is an address, not an identifier. Predicts: migration (§20) is "the address the peer uses changed," and multiplexing many connections on one UDP socket (ADR-21) is "many addresses share one physical destination." Bug class without it: treating connection IDs as opaque session tokens and missing why path validation (I7) is mandatory before using a new one. Applied in §20, §25 T12.
  6. MM6 — Backpressure not expressed as a number is backpressure that will OOM. Predicts: every unbounded buffer in the design (there should be none, per P12/I13) is a future incident. Bug class without it: an application-level slow consumer silently growing a receive buffer until the process is killed. Applied in §16, §20, §27.
  7. MM7 — Conformance suites encode the bugs everyone already made. Predicts: a h2spec/ qifs/interop-matrix failure almost always maps to a documented historical implementation mistake, not a novel one. Bug class without it: re-discovering, slowly, bugs the ecosystem already has a named regression test for. Applied in §17, §22, §29.
  8. MM8 — The three PN spaces exist because the threat model at each handshake stage is different. Predicts: Initial-space traffic is from an unauthenticated peer (hence the amplification limit, I10); 1-RTT space traffic is from an authenticated peer. Bug class without it: applying the same trust level to Initial and 1-RTT packets, missing why I5's space isolation is a security boundary, not just a bookkeeping convenience. Applied in §18, §19, §25 T5/T9.
