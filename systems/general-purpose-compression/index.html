3. Architectural Overview

3.1 Canonical Pipeline Diagram

Application (zc CLI / library user)   --bytes in / compressed out (and reverse)
                   |  raw bytes                              ^  raw bytes
                   v                                         |
===== COMPRESS path =====                       ===== DECOMPRESS path =====
comp-lz : Window + MatchFinder (HashChain|Bt)    comp-format : decode_frame
  + Parser (Greedy|Lazy|Optimal) + RepeatOffsets    parse FrameHeader + BlockHeaders
             |  Vec<Sequence>                                |
             v                                               v
comp-format : split -> Literals + (LL,ML,OF) codes   SequencesSection (FSE decode)
             |                                         + LiteralsSection (Huffman decode)
             v                                               |
comp-entropy : Huffman(literals) + FSE(seq symbols)          v  Sequences -> execute copies
  + RangeCoder (alt) ; Histogram + NormalizeCounts     comp-lz : copy matches from Window
             |  block bytes                                  |
             v                                               v
comp-format : FrameHeader + Blocks + Checksum         reconstructed bytes (xxhash verified)
comp-dict : Dictionary (prefix content + entropy tables) feeds BOTH paths

3.2 Trust and Boundary Model

Boundary Description Risk / Mitigation
Untrusted decode input Any byte of a compressed frame is adversarial Every BitReader read returns Result; window size + output size capped from FrameHeader before allocation; DecompressError taxonomy; never panic
Encode path trust Encoder generates its own bytes; output is trusted No adversarial concern; only correctness + ratio + throughput matter
Streaming / concurrency Block-parallel compress is an opt-in Phase-11 feature; decoder is sequential within a frame No shared mutable state in the single-threaded decoder path; streaming API holds exclusive &mut to its state
No persistence All state is in-memory; the Dictionary is the sole artifact that crosses process boundaries Dictionary is loaded from a validated byte slice at startup
no_std boundary comp-core/lz/entropy/format/dict are no_std + alloc; comp-cli is std No std::io in the codec; BitWriter owns its Vec<u8>

3.3 Component Descriptions

Window + MatchFinder (comp-lz)

  • Window<'a> holds a pointer to the current input slice and tracks current_pos; size = 1 << window_log (max window_log = 27).
  • MatchFinder trait: insert(pos) indexes a new position; find(pos, max_len) returns the best Match { length, offset } within search_depth chain steps.
  • Invariant: offset returned by find is always <= current_pos and <= 1 << window_log; length >= min_match = 3.
  • HashChainFinder: hash min_match bytes → head[hash] → walk prev[pos] chain. Phase-2.
  • BtFinder: binary tree per position — left[pos] / right[pos] subtrees; used by OptimalParser. Phase-3.

Parser + RepeatOffsets (comp-lz)

  • GreedyParser: take the first match >= min_match; emit Sequence { literal_length, match_length, offset }. O(n * search_depth).
  • LazyParser: after match at p, probe p+1; if longer, emit literal at p, take later match. +~3–5% ratio at ~15% speed cost.
  • OptimalParser: price-based DP over a block; cost(literal) = -log2(p_literal) bits; cost(match) = offset_code_bits + length_code_bits; picks minimum-cost cover. Requires BtFinder.
  • RepeatOffsets { recent: [u32; 3] }: the last three distinct offsets; LRU update per zstd rep-code rules. Repeat-offset codes 1/2/3 map into the OF symbol stream as special values <= 3.
  • parse_block(input, finder, strat, reps) -> Vec<Sequence>: dispatcher; called per block by comp-format.

Sequence / Stream Split (comp-format)

  • Sequence { literal_length, match_length, offset } is the unit of the LZ→entropy interface.
  • The format layer splits a Vec<Sequence> into: (a) a concatenated literals byte array; (b) three parallel symbol streams: LL (literal-length code), ML (match-length code), OF (offset code), each with extra bits appended per zstd baseline tables.
  • Offset encoding: values 1–3 → repeat-offset codes; values > 3 → log2-bucketed OF code + extra bits.
  • Invariant: re-interleaving the three symbol streams + extra bits + literals must exactly reconstruct the original Vec<Sequence> and input bytes.

HuffmanEncoder / HuffmanDecoder (comp-entropy)

  • build_huffman(hist, max_len=11) -> HuffmanTable: package-merge assigns code lengths <= 11; canonical codes derived from (length, symbol) sort.
  • HuffmanEncoder: symbol → (code: u16, len: u8) lookup; write via BitWriter.
  • HuffmanDecoder: single 2^11 = 2048-entry fast table; code → (symbol: u8, len: u8); BitReader peeks max_len bits then advances by len.
  • Kraft inequality is enforced: sum(2^(max_len - li)) <= 2^max_len.
  • Weight serialization: code-lengths written as FSE-coded (or direct 4-bit when small alphabet) header in LiteralsSection.

RangeEncoder / RangeDecoder (comp-entropy)

  • State: low: u64, range: u32, output buffered in BitWriter.
  • Renormalize when range < 2^24: emit one byte, shift. Carry propagation via deferred-byte counting.
  • Decoder mirrors: code: u32, range: u32; reads initial bytes on construction.
  • Used as an alternative entropy backend (selectable via CompressParams) and for teaching; not the default sequence-symbol coder.
  • Termination: flush by emitting enough bytes so decoder can reconstruct final state.

FseTable + FseEncoder / FseDecoder (comp-entropy)

  • normalize_counts(hist, table_log) -> Box<[i16]>: scale counts to sum exactly 2^table_log; symbols with count < 1 get 1 (the "-1 marker" written as -1 in the normalized table).
  • build_fse_decode(norm, table_log) -> FseTable: spread symbols across 2^table_log states via step (5/8 * size + 3); each cell: (symbol, nb_bits, new_state_base).
  • Encode is LIFO: process sequences in reverse; each step consumes nb_bits from the current state, transitions state down.
  • Decode is forward: read state → emit symbol → pull nb_bits to form next state.
  • Interleaved 2-stream FSE for LL and OF, independent stream for ML (mirrors zstd layout).
  • FseTable encode side: symbol → (state_begin, num_states, delta_state) transform.

comp-format Frame / Block Layer

  • FrameHeader: magic (u32), window descriptor (window_log: u8), optional content_size: Option<u64>, optional dict_id: Option<u32>, has_checksum: bool.
  • BlockHeader: 3-byte; fields: last: bool, block_type: BlockType, size: u32 (21 bits).
  • BlockType::Compressed → LiteralsSection + SequencesSection. Encoder picks smallest of Raw / Rle / Compressed.
  • LiteralsSection layout: [type(2b) | size_format(2b) | ...size... | Huffman_weights | 4-stream_jump_table | streams]. 1-stream for small literals; 4-stream (jump table) for >= 1 KiB.
  • SequencesSection layout: [num_seqs | LL_mode | ML_mode | OF_mode | FSE_tables | interleaved_FSE_bitstreams].
  • encode_frame / decode_frame: top-level entry points; split input into blocks (default 128 KiB), call parse_block, compress each block, assemble frame, append Checksum if has_checksum.
  • Key decoder invariant: content_size from FrameHeader caps output allocation before any block is decoded.

comp-dict Dictionary Layer

  • Dictionary { id: u32, entropy: EntropyTables, content: Box<[u8]> }: magic, pre-built HuffmanTable + FseTable x3, up to 32 KiB prefix content.
  • Compress path: prime MatchFinder with content (virtual history before position 0); use entropy tables instead of building fresh per-frame.
  • Decompress path: load same Dictionary by dict_id; prime Window with content; use stored entropy tables.
  • DictTrainer (COVER-lite): segment samples into k-mers; select high-coverage segments; suffix-sort for deduplication; assemble content; build entropy from aggregated histogram over all samples.
  • train(samples, dict_size) -> Dictionary: public entry point; dict_size typical 64 KiB–1 MiB.

Streaming Layer (comp-format + comp-core)

  • Push API: StreamingCompressor::write(&mut self, buf: &[u8]) -> Result<&[u8], CompressError> — accumulates until block boundary, then compresses and returns a block slice. flush() emits partial block + frame trailer.
  • Pull API: StreamingDecompressor::read(&mut self, out: &mut [u8]) -> Result<usize, DecompressError> — drives decode_frame block by block; holds Window across block boundaries.
  • Frame chaining: after a frame's last block, decoder resets per-frame state but retains the Dictionary if dict_id matches.
  • Content-size-unknown: FrameHeader.content_size = None; output grows dynamically up to the configured output-size cap.
  • Memory invariant: compress memory ~= window + finder tables; decompress memory ~= window + one output block; both bounded by CompressParams / FrameHeader.

8. Domain Model — Compression Pipeline, Bitstreams, Frame Format

8.1 Data-Flow Model

raw bytes
    │
    ▼ comp-lz: Window + MatchFinder + Parser
Vec<Sequence>          { literal_length: u32, match_length: u32, offset: u32 }
    │
    ├─► literals stream    ──► HuffmanEncoder  ──► LiteralsSection bytes
    │   (literal_length bytes concatenated)
    ├─► LL symbol stream   ─┐
    ├─► ML symbol stream   ─┼─► FseEncoder (3 interleaved) ──► SequencesSection bytes
    └─► OF symbol stream   ─┘
         │
         ▼ comp-format
BlockHeader (last/type/size) + LiteralsSection + SequencesSection = CompressedBlock
         │
         ▼
FrameHeader + Block* + optional xxhash64 content checksum = Frame bytes

Sequence semantics (LOCKED):

Field Type Meaning
literal_length u32 # literal bytes preceding this match
match_length u32 match length in bytes; 0 = literals-only tail
offset u32 1..=3 → repeat-offset code; >3 → offset - 3 = distance back in window
  • Tail sequence: match_length == 0, carries only trailing literals.
  • RepeatOffsets.recent[3]: LRU ring; offset=1 reuses recent[0], =2 reuses recent[1], =3 swaps recent[0]/recent[1] then reuses. Update on every real-distance match.
  • min_match = 3; maximum match length bounded by window size (≤ 1 << window_log).

8.2 FRAME Format — Byte-by-Byte

Offset  Width   Field
──────  ──────  ──────────────────────────────────────────────────────────
0       4 B     Magic: 0xFD2F_B528 (our own magic; not zstd's)
4       1 B     Frame_Header_Descriptor (FHD)
                  [7:6] FCS_Field_Size: 0→absent, 1→1B, 2→2B, 3→8B
                  [5]   Single_Segment_Flag
                  [4]   Unused (must be 0)
                  [3]   Reserved (must be 0)
                  [2]   Content_Checksum_Flag
                  [1:0] DID_Field_Size: 0→absent, 1→1B, 2→2B, 3→4B
4+      0/1 B   Window_Descriptor (absent if Single_Segment_Flag=1)
                  [7:3] Mantissa (M), [2:0] Exponent (E)
                  window_size = (1 + M/8) * 2^(10 + E)
var     0/1/2/4 B Dict_ID (width per DID_Field_Size)
var     0/1/2/8 B Content_Size (width per FCS_Field_Size; 2B stores val+256)
─── repeated blocks ───────────────────────────────────────────────────────
var     3 B     Block_Header (24 bits little-endian)
                  [0]    Last_Block flag
                  [2:1]  Block_Type: 0=Raw, 1=RLE, 2=Compressed, 3=Reserved
                  [23:3] Block_Size (21 bits; max 128 KiB - 1 for Compressed)
var     *       Block_Content (Raw: literal copy; RLE: 1 byte; Compressed: see §8.3)
─── trailer ────────────────────────────────────────────────────────────────
var     0/4 B   Content_Checksum (xxhash64 lower 32 bits; present iff flag set)
  • Max content size in a single frame: 2^63 - 1 bytes (field is u64).
  • Window size cap enforced by decoder: reject if > DECODER_WINDOW_MAX (e.g., 128 MiB default, configurable).

8.3 CompressedBlock Layout

CompressedBlock = LiteralsSection | SequencesSection

LiteralsSection:

Byte 0  [1:0] Literals_Block_Type
              0 = Raw        (uncompressed literals, size follows)
              1 = RLE        (1 byte repeated, size follows)
              2 = Compressed (Huffman; 1-stream or 4-stream)
              3 = Treeless   (reuse last block's Huffman table)
        [3:2] Size_Format  (encodes regenerated + compressed sizes; 1B/2B/3B header)

── Compressed/Treeless only ──────────────────────────────────────────────
Huffman_Header:
  if Compressed: weight stream for Huffman table (FSE-compressed or direct)
    [0:5] = header byte: if < 128 → FSE-compressed weights (value = compressed size);
                          else     → direct weights, (value - 127) = number of symbols
  Weights: max_symbol many 4-bit weights (pairs packed); or FSE-decoded weights
    weight → code_length via: 0 → absent; w → 2^(w-1) gives rank

Jump_Table (4-stream only, absent for 1-stream):
  3 × uint16_le  → byte offsets to starts of streams 2, 3, 4
  (stream 1 starts immediately after jump table; stream 4 ends at LiteralsSection end)

Bitstreams (1 or 4 × independent Huffman bitstreams, each read MSB-first, padded):
  last byte has leading 1-bit padding sentinel; bit-reverse within each stream byte

SequencesSection:

Number_of_Sequences:
  if first byte  = 0x00:            0 sequences (no SequencesSection body)
  elif first byte in [0x01, 0x7F]:  value = that byte
  elif first byte in [0x80, 0xFF]:  value = ((byte - 0x80) << 8) | next_byte

Symbol_Compression_Modes (1 byte):
  [7:6] LL_mode   [5:4] OF_mode   [3:2] ML_mode   [1:0] reserved=0
  mode: 0=Predefined, 1=RLE, 2=FSE_Compressed, 3=Repeat

FSE table headers (present only when mode=FSE_Compressed):
  LL table, then OF table, then ML table
  each encoded as bitstream: header = (accuracy_log - 5), then normalized counts
  using "less than 1 probability" = -1 marker encoding

Sequences bitstream (read BACKWARD, interleaved LL/ML/OF states):
  Initialize: OF state, ML state, LL state (each from initial_state_bits)
  Per sequence (decode in reverse order of encoding):
    OF_symbol = FSE decode (state); of_code = OF_symbol; extra_of_bits read
    ML_symbol = FSE decode (state); ml_code = ML_symbol; extra_ml_bits read
    LL_symbol = FSE decode (state); ll_code = LL_symbol; extra_ll_bits read
    Update states: OF_state, ML_state, LL_state (each pulls nb_bits from bitstream)
  Final sequence: no state update after last decode

8.5 Canonical Huffman — State Machine + Worked Example

Build process:

Histogram → package-merge(max_len=11) → code_lengths[] → canonical codes

Package-merge: treats symbols as packages; merges level by level to stay within max_len (11 bits) while satisfying Kraft: Σ 2^(-len[s]) ≤ 1.

Canonical derivation (Deflate §3.2.2): symbols are ordered by (code-length ASC, symbol-value ASC); a running code value starts at 0 and is assigned to each symbol in that order, incremented by 1 after each assignment; whenever the next symbol's length grows by Δ bits, code is left-shifted by Δ before assignment. The prefix-free code is then fully reconstructible from the per-symbol lengths alone — no explicit code table is transmitted.

Worked example — histogram {a:5, b:2, c:1, d:1} (9 total):

Symbol  Count  Length  Code (canonical)
a       5      2       00
b       2      3       010
c       1      3       011
d       1      3       100   ← wait: only 3 of 4 codes used at len-3 under 2-bit root

Corrected (valid Kraft):

Symbol  Count  Length  Code
a       5      1       0
b       2      2       10
c       1      3       110
d       1      3       111

Kraft check: 1/2 + 1/4 + 1/8 + 1/8 = 1.0 ✓

Decoder fast table (max_len=3, table size=8):

Index  Bits  → (symbol, length)
0b000  →  (a, 1)   0b001 → (a, 1)   0b010 → (a, 1)   0b011 → (a, 1)
0b100  →  (b, 2)   0b101 → (b, 2)   0b110 → (c, 3)   0b111 → (d, 3)

Decode: peek max_len bits → table lookup → consume length bits, emit symbol.

8.6 FSE State Machine + Worked Example

Build (table_log = 2, 4 states):

Histogram {A:3, B:1} → normalize to sum=4: {A:3, B:1}. Step = (4*5/8)+3 = 5; positions mod 4: 1,2,3,0 for A,A,A; pos 3+5=8 mod 4=0 for B... but adjust to avoid collision. Simplified spread:

State table (size=4):
  slot 0: B    slot 1: A    slot 2: A    slot 3: A

FSE decode table (symbol, nb_bits, baseline):

State  Symbol  nb_bits  next_state_base
0      B       1        2              (B has norm_count=1; next = (1<<1)=2 base, adds 0 or 1)
1      A       0        1              (A occupies 3 slots; next for slot 1 = ...)
2      A       0        2
3      A       0        3

Decode 2 symbols from state=1:

  1. state=1 → symbol A, nb_bits=0, next_state = base + bits_read(0) = 1 → emit A
  2. state=1 → symbol A again → emit A

Encode (LIFO): encode last symbol first, transitioning state DOWN by emitting nb_bits; decoder reads forward.

8.7 End-to-End Worked Example

Input: "abracadabra abracadabra" (22 bytes)

LZ parse (greedy, window=22, offset > window = impossible so all real):

Pos  Action              Sequence emitted
0    literal 'a'
1    literal 'b'
2    literal 'r'
3    literal 'a'
4    literal 'c'
5    literal 'a'
6    literal 'd'
     match @ pos=0 len=4 off=7   → Sequence{ll=7, ml=4, off=10}  (offset=7+3=10 encoded)
10   literal ' '
11   literal 'a' → match @ pos=0 len=11 off=11 → Sequence{ll=1, ml=11, off=14}

Sequences:

Seq 0: ll=7, ml=4, off=10   literals="abracad"
Seq 1: ll=1, ml=11, off=14  literals=" "
Tail:  ll=0, ml=0, off=0    (no trailing literals)

Streams:

  • Literals = "abracad " (8 bytes)
  • LL codes: code[7]=7 (baseline=7, extra=0), code[1]=1 (baseline=1, extra=0)
  • ML codes: code[4-3=1]=1 (baseline=1+3=4, extra=0), code[11-3=8]=8 (baseline=8+3=11, extra=0)
  • OF codes: real_offset=7 → code 4 (baseline=1, extra_bits=1, value=6→ baseline+extra? recalc: offset=7, stored=7, code = floor(log2(7))+1=3, extra=7-4=3 extra bits 3→ ... see §8.4)

Block encoding:

  • LiteralsSection: Huffman-compress "abracad " (8 bytes; likely Raw at this size → Raw literals, 1-byte header)
  • SequencesSection: 2 sequences; FSE tables predefined (small input); interleaved LL/OF/ML bitstream
  • BlockHeader: last=1, type=Compressed, size = total_section_bytes

Frame:

FD2FB528  (magic)
FHD: FCS=1B, SSF=1, checksum=1, DID=0
Content_Size: 22 (1 byte)
[Block: last=1 Compressed ...]
Content_Checksum: xxhash64("abracadabra abracadabra") lower 32 bits

Malformed Input Exact Error Variant
