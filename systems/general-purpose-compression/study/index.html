Mental Models & First Principles

# Expert Insight What It Predicts Bug Class Without It Resolving §
MM1 Entropy is a hard floor. A codec can never compress below H(X) bits/symbol for a source with distribution X; every bit below entropy requires knowing the distribution perfectly. normalize_counts rounding incurs overhead ≤ 1/table_size above entropy — measurable in Phase 7. Huffman's 1-bit/symbol overhead above entropy is predictable. Engineers try to "squeeze" entropy coding past the theoretical limit — no amount of table-log tuning helps once you're within 0.1 bit of entropy. §7 (normalize_counts target ≤ 0.1 bit/sym, Phase 7, §19)
MM2 A match finder is a shortest-path problem. The optimal LZ parse is a DAG relaxation over block positions, not a greedy scan; cost(literal) = -log2(p_lit) bits, cost(match) = code_bits + extra_bits. Lazy parse gains +1–2% ratio over greedy; Optimal gains +3–5%. Ratio improves strictly as more parse paths are explored. Engineers assume "find the longest match" is optimal. It isn't — a shorter match at lower offset code cost can be cheaper. Greedy-only parsers leave bits on the table. §5 Required Reading (CLRS DAG shortest-path), Phase 3 (OptimalParser, §15)
MM3 FSE encodes in reverse because ANS is a stack. The tANS state machine transitions in LIFO order; encode must push symbols onto the state stack (reverse), decode pops them forward. If encoding processes symbols in forward order, decode will produce the mirror-image symbol sequence. Encode/decode symmetry is irreversible without reordering. Forgetting LIFO produces silent data corruption: round-trip fails only after the first FSE-encoded sequence is decoded — the bug is not obvious at the table-build stage. Phase 7 (FseEncoder LIFO discipline, §19), INV-01 (round-trip identity)
MM4 Repeat offsets are LRU cache hits. The three recent offsets in RepeatOffsets.recent[3] form a tiny LRU cache; a repeat-offset hit costs zero extra bits for the offset field (code 1/2/3) vs. 5–32 bits for a real distance. Structured data (JSON, source code, binary records) exhibit high repeat-offset hit rates (≥20%); random data approaches 0%. The cache pays for itself on the first repeated stride pattern. Without repeat offsets, every back-reference pays the full offset code cost. The ~0.5–2% ratio gain on realistic data is entirely missed. Phase 3 (RepeatOffsets, §15), ADR-09, INV-07
MM5 The decoder is the only attack surface. Encoders compress trusted data they produced; decoders parse untrusted data from the network/disk. Every field read from a compressed stream is adversarial input. Validation must happen before allocation (window_log → alloc), before state initialization (FSE table sums), and before memory access (offset validity). Late validation = exploitable window. Engineers write a "safe encoder, fast decoder" design and skip validation on the decode hot path. A forged content_size then triggers a 4 GiB Vec::with_capacity. Phase 12 (decoder hardening, §24), P-02, P-03, INV-09, T1–T9
MM6 Carry propagation is the arithmetic coder's fragile invariant. The range coder's interval can carry into the previously emitted byte; the deferred-byte algorithm holds a cache byte until it is known not to carry further. Any sequence of high-probability symbols (probability near 1.0) produces long carry chains; carry_count can reach n/8. Flushing the wrong byte value propagates silently to decode output. Engineers emit bytes as soon as the interval narrows, missing the carry case. The resulting decoder sees a different symbol sequence — corruption is silent and hard to bisect. Phase 6 (RangeEncoder carry algorithm, §18), INV-06
MM7 normalize_counts must preserve rare symbols. FSE's state table has 2^table_log slots; a symbol with count > 0 must occupy at least one slot, or it becomes undecodable. The "-1 marker" forces count = 1 for these symbols. Low-frequency symbols (count = 1 in a large corpus) get norm count = 1, not 0. The state table covers the full alphabet. Bits/symbol overhead rises slightly for very rare symbols but correctness is preserved. Rounding rare symbols to zero removes them from the decode table. Any stream containing those symbols produces CorruptData — reproducible only on specific rare inputs, hard to catch in unit tests. Phase 7 (normalize_counts -1 marker, §19), INV-05, ADR-13
MM8 Block-type election is a measurement, not a heuristic. The encoder must measure Raw, RLE, and Compressed sizes for each block and emit the smallest; "this looks compressible" guesses result in bloated output. Incompressible random input (entropy ≈ 8.0 bits/byte) always elects Raw; single-byte runs elect RLE; text elects Compressed. The Compressed path is never allowed to make output larger than the input. Omitting the Raw fallback causes the codec to bloat random data by ≥ 5% (Huffman + FSE table overhead). This breaks the invariant "compressed ≤ raw" and fails the Phase 13 conformance gate. Phase 5 (LiteralsSection Raw fallback, §17), Phase 8 (BlockType election, §20), P-05, INV-10

Glossary · 51 terms · site-wide glossary

LZ77
Lempel-Ziv 1977 compression: encode data as back-references (offset, length) into a sliding window of previously seen bytes; literals fill gaps.
LZSS
LZ77 variant: emits either a raw literal byte OR a (offset, length) match pair, never a literal wrapped in a match; flag bit distinguishes them.
Sliding window
Fixed-size circular buffer (size = 1 << window_log) of the most recently processed bytes; the match finder searches this history.
History
The valid region of the Window behind the current encode/decode position; bounded by window_log and the bytes emitted so far.
Match finder
Component that scans history for the longest/best match at the current input position; abstracted by MatchFinder trait in comp-lz.
Hash chain
HashChainFinder structure: head[hash(next 3 bytes)] → most recent position; prev[pos] chains older collisions; walk bounded by search_depth.
Binary-tree match finder
BtFinder: maintains per-hash two child pointers (greater/less) to form a sorted tree of previous occurrences; finds all match lengths efficiently; used by OptimalParser.
Greedy parse
GreedyParser: accept the first (longest) match found at each position; advance by match length; O(1) decision per position.
Lazy parse
LazyParser: after finding a match at position p, also probe p+1; if the p+1 match is longer, emit a literal at p and take the better match; one-step lookahead.
Optimal parse
OptimalParser: price-based shortest-path (Dijkstra/DP) over all possible match/literal choices in a block; cost = entropy bits of resulting symbols; highest ratio, highest cost.
Repeat offset
One of the three most-recently-used match offsets tracked in RepeatOffsets { recent: [u32; 3] }; encoded in Sequence.offset as codes 1..=3 instead of a raw distance; saves bits on recurring offsets (e.g., stride patterns).
Literal
A raw unmatched input byte passed through without back-reference; grouped in Sequence.literal_length preceding a match.
Match
A back-reference (offset, length) where offset is distance into the window and length >= min_match; captured in Match { length, offset }.
Sequence
Sequence { literal_length, match_length, offset }: the unit of LZ output; a run of literal_length literals followed by one match of match_length at offset; match_length=0 = literals-only tail.
Literal length (LL)
The literal_length field of a Sequence; entropy-coded via FSE in the SequencesSection using a code table with baseline+extra-bits.
Match length (ML)
The match_length field of a Sequence; encoded via FSE ML code table; min_match=3.
Offset (OF)
The offset field of a Sequence; encodes either a repeat-offset code (1..=3) or a real window distance; entropy-coded via FSE OF code table.
Minimum match
min_match = 3; a back-reference is only emitted when match_length >= 3, otherwise a literal is cheaper.
Entropy
Shannon information content of a symbol distribution; lower entropy = more compressible; build_huffman and FSE exploit redundancy in the Histogram.
Canonical Huffman
Prefix-free code where code lengths alone determine codes (assigned by sorted (length, symbol) order); enables compact weight serialization; used in HuffmanTable.
Length-limited code
Huffman variant capping code lengths at a maximum (e.g., 11 bits) to keep the fast decode table at bounded size (2^max_len entries); Kraft inequality preserved.
Package-merge
Optimal length-limited Huffman algorithm (Larmore-Hirschberg); produces minimum-redundancy codes under a max-length constraint; used in build_huffman.
Kraft inequality
Σ 2^{-len_i} ≤ 1; necessary and sufficient for a valid prefix-free code; violated lengths → invalid HuffmanTable.
Arithmetic coding
Entropy coder that maps a symbol sequence to a sub-interval of [0,1); achieves near-Shannon entropy; implemented as RangeEncoder/RangeDecoder.
Range coder
Integer arithmetic coding variant: maintains low: u64, range: u32; narrows interval by symbol cumulative frequency; emits bytes on renormalization; carry-safe.
Renormalization
Step in range coding when range < 2^24: emit a byte of low, shift low and range left by 8; keeps precision without arbitrary precision.
Carry propagation
Arithmetic coder artifact: incrementing low can carry into previously emitted bytes; deferred-byte counting (0xFF buffering) handles this without unbounded buffering.
ANS
Asymmetric Numeral Systems (Duda): integer-based entropy coding; bijective state machine; tANS is the table-based variant used in FSE.
tANS
Table-based ANS; the variant used by FseTable; state transitions encoded in lookup tables built from normalized counts; LIFO: encode reversed, decode forward.
FSE
Finite State Entropy — zstd's name for its tANS implementation; encodes LL/ML/OF symbols in the SequencesSection; FseEncoder/FseDecoder in comp-entropy.
State table
The FseTable decode array of (symbol, nb_bits, new_state_base) tuples of length 2^table_log; built by build_fse_decode.
Normalized counts
Integer counts summing to 2^table_log produced by normalize_counts; low-probability symbols rounded to 1 (marked -1 before rounding); fed to build_fse_decode.
Symbol spreading
Step in build_fse_decode: distributes symbol occurrences across the state table using the step (5/8 * size + 3) walk to ensure a uniform spread for good mixing.
Table log
FseTable.log; table_size = 2^table_log; controls FSE precision vs. table memory; typical range 6..=12.
Block
Independently decodable unit within a frame; typed by BlockType: Raw (stored), Rle (one byte repeated), or Compressed (LiteralsSection + SequencesSection).
Frame
Top-level container: FrameHeader + one or more blocks + optional xxhash64 content checksum; self-described by magic number.
Frame header
FrameHeader { window_log, content_size, dict_id, has_checksum, magic }; parsed first by decode_frame; caps window allocation before any block is read.
Window descriptor
Compact window_log encoding in the FrameHeader; decoder allocates 1 << window_log bytes for history; must be validated against size caps before allocation.
Block header
BlockHeader { last, block_type, size }; 3-byte field preceding each block; last=true signals the final block; size is the compressed payload length.
Raw block
BlockType::Raw: payload copied verbatim; used when data is incompressible or for Phase-0 smoke-test round-trips.
RLE block
BlockType::Rle: single byte + repeat count; optimal for long runs of identical bytes.
Compressed block
BlockType::Compressed: LiteralsSection (Huffman-coded literals) + SequencesSection (FSE-coded LL/ML/OF + extra bits).
Literals section
Sub-region of a compressed block holding the concatenated literal bytes, Huffman-compressed; supports 1-stream and 4-stream (jump-table) layouts; falls back to Raw/RLE when incompressible.
Sequences section
Sub-region of a compressed block holding the FSE-interleaved LL/ML/OF symbol streams + extra bits; fully describes all back-references in the block.
4-stream layout
Literals section variant splitting the Huffman-coded literal stream into 4 independent sub-streams with jump-table offsets; enables parallel decode.
Dictionary
Dictionary { id, entropy, content }: pre-agreed data augmenting both paths; content primes the Window; entropy pre-loads HuffmanTable/FseTable; identified by dict_id in the FrameHeader.
Dictionary id
u32 in FrameHeader.dict_id; links a frame to a specific Dictionary; decoder returns an error if the required dict is absent.
Content checksum
Optional trailing xxhash64 digest of the decompressed content; verified by decode_frame when FrameHeader.has_checksum=true; computed by Checksum.
Compression ratio
uncompressed_size / compressed_size; target ≥ zlib at CompressionLevel::Default; benchmarked on Silesia/Calgary corpora.
