397 — General-Purpose Compression

Goal: Implement, from scratch in Rust, a general-purpose lossless compression library structured as a zstd-style pipeline — an LZ77/LZSS match finder (sliding window, hash chains, lazy + optimal parsing, repeat offsets) producing a stream of Sequences, three entropy coders (canonical length-limited Huffman, a range/arithmetic coder, and table-based ANS/tANS "FSE"), a self-describing frame/block container that codes literals with Huffman and the LL/ML/OF sequence symbols with FSE, trained dictionaries, and a streaming API plus the zc CLI. The pipeline is self-consistent (its own magic) and lossless round-trip is sacred; decoding upstream zstd frames is a documented stretch goal, not a Phase-0 requirement.

1. Goal

Build a production-quality, from-scratch general-purpose lossless compression library in Rust (edition 2021, MSRV 1.78): a zstd-style pipeline (LZ77/LZSS match finding → sequence model → Huffman + FSE entropy coding → self-describing frame/block container) plus dictionaries, a streaming API, and a "zc" CLI.

1.1 Precise Engineering Definition

The pipeline, left to right on the compress path:

Stage Component Input → Output
Match finding comp-lz: Window, HashChainFinder / BtFinder raw bytes → Vec<Sequence>
Parsing strategy GreedyParser / LazyParser / OptimalParser + RepeatOffsets bytes + finder → Vec<Sequence> (min_match=3)
Sequence model comp-format: LL/ML/OF split + extra-bits table Vec<Sequence> → literals stream + symbol streams
Literal entropy comp-entropy: HuffmanEncoder / HuffmanDecoder literals bytes → Huffman bitstream
Sequence entropy comp-entropy: FseEncoder / FseDecoder (tANS) LL/ML/OF symbol streams → FSE bitstreams
Container comp-format: encode_frame / decode_frame entropy blocks → framed bytes with FrameHeader, BlockHeader, checksum
Dictionary comp-dict: Dictionary, DictTrainer shared entropy tables + prefix content fed to both paths
Streaming comp-format + comp-core streaming layer push/pull across block and frame boundaries

The entropy layer exposes three coders: canonical length-limited Huffman (literals), tANS/FSE (sequence symbols), and arithmetic/range coder (alternative backend + teaching). All three live in comp-entropy.

2.3 Engineering Muscles Exercised

  • Bit-exact stream design: every bit has a defined position; the decoder must reproduce the encoder's choices exactly or produce garbage. Mistakes are immediate and measurable.
  • Cache-aware data structures: HashChainFinder head array fits L1; prev-chain walk is the bottleneck — chain_log tuning is a cache experiment.
  • Entropy math: normalize_counts must preserve relative probability order while summing to exactly 2^table_log; the "-1 marker" for low-probability symbols requires careful integer arithmetic.
  • API design under no_std: no dynamic dispatch beyond the MatchFinder trait; no std::io — BitWriter / BitReader own their buffer.
  • Security engineering: the decoder is the only public attack surface on untrusted data; every field from the stream is an adversarial input.

What Mastery Looks Like

  • Phase 1–2 (match finder + Huffman): Given an arbitrary byte histogram, you can derive canonical code lengths by hand using the package-merge algorithm, state the Kraft-inequality constraint as an integer equation, and explain why max_len=11 keeps the decode table in L1 cache. You can trace a HashChainFinder chain walk step-by-step and identify the exact condition that breaks chain locality.
  • Phase 3 (parsing quality): You can explain the price function used by OptimalParser — specifically how cost(literal) = -log2(p_lit) bits and cost(match) = OF_bits + ML_bits + extra_bits — and derive why repeat-offset codes cost fewer bits than equivalent real-distance matches. You can hand-simulate the LRU update for a sequence of three consecutive repeat-offset matches and verify encoder/decoder state agree.
  • Phase 4–5 (sequence model + Huffman literals section): You can reconstruct the LL/ML/OF code tables from first principles (baseline + extra-bits encoding), explain why the 4-stream jump-table layout enables instruction-level parallelism, and identify which combination of literals.len() and entropy triggers the Raw vs Huff1 vs Huff4 fallback chain.
  • Phase 6–7 (range coder + FSE): You can explain the deferred-byte carry-propagation algorithm in the range coder step by step, derive the FSE symbol-spreading step formula (size>>1)+(size>>3)+3, and state why FSE encode must process symbols in reverse order while decode processes forward.
  • Phase 8–9 (frame/block + dictionaries): You can draw the FrameHeader + BlockHeader bit layout from memory, explain why dict_id mismatch is a hard error rather than a soft fallback, and derive the exact memory working set at window_log=23 using the constraints table.
  • Phase 10–11 (streaming + optimization): You can explain why cross-block window history is critical for compression ratio on large inputs, design a RingBuf that avoids reallocation while supporting overlap-safe match copies, and identify the SIMD vectorization opportunity in the histogram accumulation loop.
  • Phase 12–13 (hardening + conformance): You can enumerate the five decompression-bomb attack vectors (content_size inflation, window_log overflow, block_size overflow, FSE table_log forge, sequence count overflow) and identify the exact decoder line that must validate each one before any allocation occurs. You can interpret a fuzz crash as a DecompressError variant and trace it to the specific invariant it violated.

3.3 Component Descriptions

Window + MatchFinder (comp-lz)

  • Window<'a> holds a pointer to the current input slice and tracks current_pos; size = 1 << window_log (max window_log = 27).
  • MatchFinder trait: insert(pos) indexes a new position; find(pos, max_len) returns the best Match { length, offset } within search_depth chain steps.
  • Invariant: offset returned by find is always <= current_pos and <= 1 << window_log; length >= min_match = 3.
  • HashChainFinder: hash min_match bytes → head[hash] → walk prev[pos] chain. Phase-2.
  • BtFinder: binary tree per position — left[pos] / right[pos] subtrees; used by OptimalParser. Phase-3.

Parser + RepeatOffsets (comp-lz)

  • GreedyParser: take the first match >= min_match; emit Sequence { literal_length, match_length, offset }. O(n * search_depth).
  • LazyParser: after match at p, probe p+1; if longer, emit literal at p, take later match. +~3–5% ratio at ~15% speed cost.
  • OptimalParser: price-based DP over a block; cost(literal) = -log2(p_literal) bits; cost(match) = offset_code_bits + length_code_bits; picks minimum-cost cover. Requires BtFinder.
  • RepeatOffsets { recent: [u32; 3] }: the last three distinct offsets; LRU update per zstd rep-code rules. Repeat-offset codes 1/2/3 map into the OF symbol stream as special values <= 3.
  • parse_block(input, finder, strat, reps) -> Vec<Sequence>: dispatcher; called per block by comp-format.

Sequence / Stream Split (comp-format)

  • Sequence { literal_length, match_length, offset } is the unit of the LZ→entropy interface.
  • The format layer splits a Vec<Sequence> into: (a) a concatenated literals byte array; (b) three parallel symbol streams: LL (literal-length code), ML (match-length code), OF (offset code), each with extra bits appended per zstd baseline tables.
  • Offset encoding: values 1–3 → repeat-offset codes; values > 3 → log2-bucketed OF code + extra bits.
  • Invariant: re-interleaving the three symbol streams + extra bits + literals must exactly reconstruct the original Vec<Sequence> and input bytes.

HuffmanEncoder / HuffmanDecoder (comp-entropy)

  • build_huffman(hist, max_len=11) -> HuffmanTable: package-merge assigns code lengths <= 11; canonical codes derived from (length, symbol) sort.
  • HuffmanEncoder: symbol → (code: u16, len: u8) lookup; write via BitWriter.
  • HuffmanDecoder: single 2^11 = 2048-entry fast table; code → (symbol: u8, len: u8); BitReader peeks max_len bits then advances by len.
  • Kraft inequality is enforced: sum(2^(max_len - li)) <= 2^max_len.
  • Weight serialization: code-lengths written as FSE-coded (or direct 4-bit when small alphabet) header in LiteralsSection.

RangeEncoder / RangeDecoder (comp-entropy)

  • State: low: u64, range: u32, output buffered in BitWriter.
  • Renormalize when range < 2^24: emit one byte, shift. Carry propagation via deferred-byte counting.
  • Decoder mirrors: code: u32, range: u32; reads initial bytes on construction.
  • Used as an alternative entropy backend (selectable via CompressParams) and for teaching; not the default sequence-symbol coder.
  • Termination: flush by emitting enough bytes so decoder can reconstruct final state.

FseTable + FseEncoder / FseDecoder (comp-entropy)

  • normalize_counts(hist, table_log) -> Box<[i16]>: scale counts to sum exactly 2^table_log; symbols with count < 1 get 1 (the "-1 marker" written as -1 in the normalized table).
  • build_fse_decode(norm, table_log) -> FseTable: spread symbols across 2^table_log states via step (5/8 * size + 3); each cell: (symbol, nb_bits, new_state_base).
  • Encode is LIFO: process sequences in reverse; each step consumes nb_bits from the current state, transitions state down.
  • Decode is forward: read state → emit symbol → pull nb_bits to form next state.
  • Interleaved 2-stream FSE for LL and OF, independent stream for ML (mirrors zstd layout).
  • FseTable encode side: symbol → (state_begin, num_states, delta_state) transform.

comp-format Frame / Block Layer

  • FrameHeader: magic (u32), window descriptor (window_log: u8), optional content_size: Option<u64>, optional dict_id: Option<u32>, has_checksum: bool.
  • BlockHeader: 3-byte; fields: last: bool, block_type: BlockType, size: u32 (21 bits).
  • BlockType::Compressed → LiteralsSection + SequencesSection. Encoder picks smallest of Raw / Rle / Compressed.
  • LiteralsSection layout: [type(2b) | size_format(2b) | ...size... | Huffman_weights | 4-stream_jump_table | streams]. 1-stream for small literals; 4-stream (jump table) for >= 1 KiB.
  • SequencesSection layout: [num_seqs | LL_mode | ML_mode | OF_mode | FSE_tables | interleaved_FSE_bitstreams].
  • encode_frame / decode_frame: top-level entry points; split input into blocks (default 128 KiB), call parse_block, compress each block, assemble frame, append Checksum if has_checksum.
  • Key decoder invariant: content_size from FrameHeader caps output allocation before any block is decoded.

comp-dict Dictionary Layer

  • Dictionary { id: u32, entropy: EntropyTables, content: Box<[u8]> }: magic, pre-built HuffmanTable + FseTable x3, up to 32 KiB prefix content.
  • Compress path: prime MatchFinder with content (virtual history before position 0); use entropy tables instead of building fresh per-frame.
  • Decompress path: load same Dictionary by dict_id; prime Window with content; use stored entropy tables.
  • DictTrainer (COVER-lite): segment samples into k-mers; select high-coverage segments; suffix-sort for deduplication; assemble content; build entropy from aggregated histogram over all samples.
  • train(samples, dict_size) -> Dictionary: public entry point; dict_size typical 64 KiB–1 MiB.

Streaming Layer (comp-format + comp-core)

  • Push API: StreamingCompressor::write(&mut self, buf: &[u8]) -> Result<&[u8], CompressError> — accumulates until block boundary, then compresses and returns a block slice. flush() emits partial block + frame trailer.
  • Pull API: StreamingDecompressor::read(&mut self, out: &mut [u8]) -> Result<usize, DecompressError> — drives decode_frame block by block; holds Window across block boundaries.
  • Frame chaining: after a frame's last block, decoder resets per-frame state but retains the Dictionary if dict_id matches.
  • Content-size-unknown: FrameHeader.content_size = None; output grows dynamically up to the configured output-size cap.
  • Memory invariant: compress memory ~= window + finder tables; decompress memory ~= window + one output block; both bounded by CompressParams / FrameHeader.

4.3 Key Sizing Derivations

compress_memory_bytes = (1 << window_log)           // Window history
                      + (1 << hash_log) * 4         // head[] array (u32)
                      + input_buffer_size            // HashChainFinder: prev[] ~ window
                      + block_size * 2               // literals + sequence scratch

decompress_memory_bytes = (1 << window_log)          // reconstructed history
                        + block_size                 // current output block
                        // no additional chain tables needed
  • At window_log=23 (8 MiB window), hash_log=17 (512 KiB head table): compress ~= 9 MiB working set — fits in L3 on most x86-64.
  • At window_log=10 (1 KiB): suitable for embedded / no_std targets with tight SRAM.

6. Design Principles

P-01 — Round-Trip Is Sacred

Statement: decompress(compress(x, params), params) == x for all x, all CompressionLevel, all block types, with and without a Dictionary.
Tradeoff: None. This is a lossless codec; correctness is non-negotiable.
Operational: Every phase introduces a round-trip test. Property-test via proptest / quickcheck from Phase 0 onward; fuzz (compress→decompress identity) from Phase 12.
Violating it breaks: Everything — the codec is useless if data is corrupted.

P-02 — The Decoder Never Trusts Its Input

Statement: Every length field, offset, block size, and table entry parsed from a compressed stream is validated against declared bounds before use. No speculative memory access.
Tradeoff: Branch overhead on the decode hot path (~2–5 ns/block); acceptable vs. a memory-safety exploit.
Operational: BitReader returns Err on over-read (never panics). decode_frame caps allocation to FrameHeader.window_log and content_size. Offsets validated against current window before copy.
Violating it breaks: Memory safety + security (arbitrary write / OOB read on malformed input).

P-03 — No Panic, No Unbounded Allocation on Malformed Input

Statement: The decoder path (comp-format, comp-entropy, comp-lz on decode) must not panic!, unwrap, expect, or allocate beyond the caps derived from FrameHeader when fed adversarial bytes.
Tradeoff: All fallible operations return Result<_, DecompressError>; hot paths use ? propagation (zero-cost on success).
Operational: #![deny(clippy::unwrap_used)] in comp-core/comp-lz/comp-entropy/comp-format. Allocation budget = min(window_size, content_size.unwrap_or(MAX_SAFE)) checked at frame entry.
Violating it breaks: Decoder hardening (Phase 12); fuzzing will surface panics as bugs.

P-04 — Separate Concerns: Parse → Model → Entropy → Container

Statement: The four stages (LZ match finding in comp-lz, sequence modeling/splitting in comp-format, entropy coding in comp-entropy, frame framing in comp-format) are independent modules with typed interfaces (Vec<Sequence>, Histogram, FseTable, BlockHeader).
Tradeoff: Small interface-crossing cost (Vec allocations between stages); pays back in testability and swappability.
Operational: Each crate has its own unit tests exercising the stage in isolation. comp-entropy knows nothing about LZ; comp-lz knows nothing about Huffman codes.
Violating it breaks: Phase testability; the range-coder swap (Phase 6) becomes impossible if entropy is entangled with the container.

P-05 — Pick the Smallest Block

Statement: For each block, the encoder measures the size of Raw, RLE, and Compressed encodings and emits whichever is smallest. No heuristic short-circuit without measurement.
Tradeoff: Adds one pass to evaluate Raw/RLE candidates (O(block_size)); insignificant vs. LZ + entropy cost.
Operational: encode_frame delegates to a block_type_selector that returns BlockType + size estimate. Tests include incompressible random data (must emit Raw), single-byte repeated (must emit RLE).
Violating it breaks: Compression ratio on adversarial inputs (random data bloated by Compressed overhead).

P-06 — Entropy Coder Is Swappable Behind a Clear Interface

Statement: The literals section can use HuffmanEncoder or RangeEncoder; the sequences section uses FseEncoder or RangeEncoder; the frame format records which was used. Callers use a common EntropyBackend abstraction.
Tradeoff: Slight indirection; the enum dispatch is compile-time (monomorphized in practice).
Operational: Phase 6 adds RangeEncoder/Decoder without touching comp-lz or comp-format block dispatch. The FseEncoder and HuffmanEncoder share the Histogram input type.
Violating it breaks: Phase 6 and Phase 7 implementation; also prevents future ANS variant experimentation.

P-07 — Bit Layout Is Normative and Versioned

Statement: Every bit field in FrameHeader, BlockHeader, LiteralsSection, and SequencesSection has a single canonical definition in comp-format (cross-referenced to RFC 8878 §3–6). Any format change bumps a FORMAT_VERSION constant and is documented as a breaking change.
Tradeoff: Rigidity; old compressed files may not decode with a future version if FORMAT_VERSION differs.
Operational: Format layout is covered by golden-file tests (known bytes in → known bytes out). The magic u32 in FrameHeader identifies the format.
Violating it breaks: Cross-version interoperability and the Phase 13 conformance suite.

P-08 — Determinism: Same Input + Params → Same Bytes

Statement: compress(x, params) produces identical output bytes for identical (x, params) on any run, any platform (within the same FORMAT_VERSION).
Tradeoff: No randomized tie-breaking in match selection or table construction.
Operational: HashChainFinder + BtFinder walk chains in insertion order (deterministic); normalize_counts uses a deterministic rounding rule. Tests compare compressed output to a stored golden byte vector.
Violating it breaks: Reproducible builds, content-addressed caching, and differential testing against a reference compressor.

P-09 — Speed and Ratio Are a Tunable Pareto, Not a Single Point

Statement: CompressionLevel (Fast → Default → Max, plus Custom(CompressParams)) maps to distinct (Strategy, window_log, search_depth, chain_log) tuples. No single "best" setting exists.
Tradeoff: Level table maintenance; each new strategy must be benchmarked against the Pareto frontier.
Operational: Phase 11 defines the level table. CI benchmarks (Calgary + Silesia) track ratio + MB/s per level; regressions > 2% flag as failures.
Violating it breaks: User expectations for CompressionLevel::Fast (throughput) vs. Max (ratio).

P-10 — Dictionaries Are a First-Class Artifact

Statement: A Dictionary (comp-dict) carries its own entropy tables (EntropyTables) and prefix content. It is applied symmetrically on both compress and decompress paths. The dict_id is written into FrameHeader and verified on decode.
Tradeoff: Dictionary mismatch is a hard error (DecompressError::DictIdMismatch), not a soft fallback.
Operational: Round-trip tests with a trained dictionary are mandatory from Phase 9. The DictTrainer produces deterministic output for a fixed sample set.
Violating it breaks: Dictionary-compressed streams are silently misread if dict is applied inconsistently.

P-11 — Measure, Don't Guess

Statement: All performance claims (ratio, MB/s) are produced by benchmarks against standard corpora (Calgary, Canterbury, Silesia, enwik8 slice). No optimization is merged without a criterion benchmark proving improvement.
Tradeoff: CI benchmark time (~2–5 min); justified by catching regressions before merge.
Operational: comp-cli bench subcommand wraps the criterion harness. Baseline stored in bench/baseline.json. SIMD histogram (Phase 11) must show ≥20% throughput gain on a 1 MiB random text corpus before merge.
Violating it breaks: Phase 13 Pareto table; "optimization" commits that regress ratio or speed go undetected.

P-12 — RepeatOffsets Symmetry Is an Invariant, Not a Convention

Statement: The RepeatOffsets.recent[3] LRU state must update identically on the encoder (comp-lz, during parse_block) and the decoder (comp-format, during sequence execution). Any divergence corrupts every subsequent back-reference.
Tradeoff: The update rule (per RFC 8878 §4.3.2.2) is non-trivial for offset == 0 with match_length == 1; it must be unit-tested independently for all edge cases.
Operational: A dedicated test table covers all RepeatOffset edge cases (offset = rep[0], rep[1], rep[2], rep[1] when rep[1]=rep[0], literal-only sequences). Fuzz confirms encoder and decoder state always agree.
Violating it breaks: Round-trip identity (P-01) the moment any repeat-offset sequence appears.

P-13 — Streaming Produces Byte-Identical Output to One-Shot

Statement: Given the same (input, CompressionLevel, Dictionary), the streaming API (Phase 10) and encode_frame / decode_frame (one-shot) produce identical output bytes.
Tradeoff: Streaming must buffer enough history (window_size) across block boundaries; forces explicit history management.
Operational: Parameterized tests run the same corpus through both paths and assert ==. Frame chaining is tested with flush points at multiple offsets.
Violating it breaks: Library reliability guarantee; users who switch from one-shot to streaming get different compressed artifacts.

raw bytes
    │
    ▼ comp-lz: Window + MatchFinder + Parser
Vec<Sequence>          { literal_length: u32, match_length: u32, offset: u32 }
    │
    ├─► literals stream    ──► HuffmanEncoder  ──► LiteralsSection bytes
    │   (literal_length bytes concatenated)
    ├─► LL symbol stream   ─┐
    ├─► ML symbol stream   ─┼─► FseEncoder (3 interleaved) ──► SequencesSection bytes

         │
         ▼ comp-format

         │
         ▼

Sequence semantics (LOCKED):

Field Type Meaning
literal_length u32 # literal bytes preceding this match
match_length u32 match length in bytes; 0 = literals-only tail
offset u32 1..=3 → repeat-offset code; >3 → offset - 3 = distance back in window
  • Tail sequence: match_length == 0, carries only trailing literals.
  • RepeatOffsets.recent[3]: LRU ring; offset=1 reuses recent[0], =2 reuses recent[1], =3 swaps recent[0]/recent[1] then reuses. Update on every real-distance match.
  • min_match = 3; maximum match length bounded by window size (≤ 1 << window_log).

─── repeated blocks ───────────────────────────────────────────────────────
var     3 B     Block_Header (24 bits little-endian)
                  [0]    Last_Block flag
                  [2:1]  Block_Type: 0=Raw, 1=RLE, 2=Compressed, 3=Reserved

8.3 CompressedBlock Layout

CompressedBlock = LiteralsSection | SequencesSection

LiteralsSection:

Byte 0  [1:0] Literals_Block_Type
              0 = Raw        (uncompressed literals, size follows)
              1 = RLE        (1 byte repeated, size follows)
              2 = Compressed (Huffman; 1-stream or 4-stream)
              3 = Treeless   (reuse last block's Huffman table)
        [3:2] Size_Format  (encodes regenerated + compressed sizes; 1B/2B/3B header)

── Compressed/Treeless only ──────────────────────────────────────────────
Huffman_Header:
  if Compressed: weight stream for Huffman table (FSE-compressed or direct)
    [0:5] = header byte: if < 128 → FSE-compressed weights (value = compressed size);
                          else     → direct weights, (value - 127) = number of symbols
  Weights: max_symbol many 4-bit weights (pairs packed); or FSE-decoded weights
    weight → code_length via: 0 → absent; w → 2^(w-1) gives rank

Jump_Table (4-stream only, absent for 1-stream):
  3 × uint16_le  → byte offsets to starts of streams 2, 3, 4
  (stream 1 starts immediately after jump table; stream 4 ends at LiteralsSection end)

Bitstreams (1 or 4 × independent Huffman bitstreams, each read MSB-first, padded):
  last byte has leading 1-bit padding sentinel; bit-reverse within each stream byte

SequencesSection:

Number_of_Sequences:
  if first byte  = 0x00:            0 sequences (no SequencesSection body)
  elif first byte in [0x01, 0x7F]:  value = that byte
  elif first byte in [0x80, 0xFF]:  value = ((byte - 0x80) << 8) | next_byte

Symbol_Compression_Modes (1 byte):
  [7:6] LL_mode   [5:4] OF_mode   [3:2] ML_mode   [1:0] reserved=0
  mode: 0=Predefined, 1=RLE, 2=FSE_Compressed, 3=Repeat

FSE table headers (present only when mode=FSE_Compressed):
  LL table, then OF table, then ML table
  each encoded as bitstream: header = (accuracy_log - 5), then normalized counts
  using "less than 1 probability" = -1 marker encoding

Sequences bitstream (read BACKWARD, interleaved LL/ML/OF states):
  Initialize: OF state, ML state, LL state (each from initial_state_bits)
  Per sequence (decode in reverse order of encoding):
    OF_symbol = FSE decode (state); of_code = OF_symbol; extra_of_bits read
    ML_symbol = FSE decode (state); ml_code = ML_symbol; extra_ml_bits read
    LL_symbol = FSE decode (state); ll_code = LL_symbol; extra_ll_bits read
    Update states: OF_state, ML_state, LL_state (each pulls nb_bits from bitstream)
  Final sequence: no state update after last decode

8.5 Canonical Huffman — State Machine + Worked Example

Build process:

Histogram → package-merge(max_len=11) → code_lengths[] → canonical codes

Package-merge: treats symbols as packages; merges level by level to stay within max_len (11 bits) while satisfying Kraft: Σ 2^(-len[s]) ≤ 1.

Canonical derivation (Deflate §3.2.2): symbols are ordered by (code-length ASC, symbol-value ASC); a running code value starts at 0 and is assigned to each symbol in that order, incremented by 1 after each assignment; whenever the next symbol's length grows by Δ bits, code is left-shifted by Δ before assignment. The prefix-free code is then fully reconstructible from the per-symbol lengths alone — no explicit code table is transmitted.

Worked example — histogram {a:5, b:2, c:1, d:1} (9 total):

Symbol  Count  Length  Code (canonical)
a       5      2       00
b       2      3       010
c       1      3       011
d       1      3       100   ← wait: only 3 of 4 codes used at len-3 under 2-bit root

Corrected (valid Kraft):

Symbol  Count  Length  Code
a       5      1       0
b       2      2       10
c       1      3       110
d       1      3       111

Kraft check: 1/2 + 1/4 + 1/8 + 1/8 = 1.0 ✓

Decoder fast table (max_len=3, table size=8):

Index  Bits  → (symbol, length)
0b000  →  (a, 1)   0b001 → (a, 1)   0b010 → (a, 1)   0b011 → (a, 1)
0b100  →  (b, 2)   0b101 → (b, 2)   0b110 → (c, 3)   0b111 → (d, 3)

Decode: peek max_len bits → table lookup → consume length bits, emit symbol.

8.6 FSE State Machine + Worked Example

Build (table_log = 2, 4 states):

Histogram {A:3, B:1} → normalize to sum=4: {A:3, B:1}. Step = (4*5/8)+3 = 5; positions mod 4: 1,2,3,0 for A,A,A; pos 3+5=8 mod 4=0 for B... but adjust to avoid collision. Simplified spread:

State table (size=4):
  slot 0: B    slot 1: A    slot 2: A    slot 3: A

FSE decode table (symbol, nb_bits, baseline):

State  Symbol  nb_bits  next_state_base
0      B       1        2              (B has norm_count=1; next = (1<<1)=2 base, adds 0 or 1)
1      A       0        1              (A occupies 3 slots; next for slot 1 = ...)
2      A       0        2
3      A       0        3

Decode 2 symbols from state=1:

  1. state=1 → symbol A, nb_bits=0, next_state = base + bits_read(0) = 1 → emit A
  2. state=1 → symbol A again → emit A

Encode (LIFO): encode last symbol first, transitioning state DOWN by emitting nb_bits; decoder reads forward.

/// Accumulates bits into a byte stream; LSB of each byte first.

/// Hash-chain match finder: head[hash(3 bytes)] -> most-recent pos;
/// prev[pos & mask] chains older occurrences. Walk bounded by search_depth + window.
pub struct HashChainFinder {

}

}

<!-- Theory anchors: Huffman (1952) bottom-up tree; Larmore & Hirschberg (1990) package-merge O(nL); ADR-10 (max_len=11, L1 table); Cover & Thomas Ch. 5 (entropy lower bound for bits/symbol gate) -->

Package-merge length assignment (huffman.rs) — Lawrence-Larmore algorithm for optimal length-limited prefix codes:

  1. Sort symbols by count descending; seed a priority queue of (weight, item) pairs for each of max_len lists.
  2. Merge: at level l, pair adjacent items into packages; iterate max_len - 1 times; count symbol appearances → code lengths.
  3. Symbols with count 0 excluded; equal-count symbols get equal length.
  4. Post-condition: Σ 2^(-len_i) ≤ 1 (Kraft); symbols with len > 0 = alphabet_size.

Canonical derivation: sort by (length ASC, symbol ASC); code[0]=0; code[i]=(code[i-1]+1) << (len[i]-len[i-1]). Result: HuffmanTable { code_lengths: Box<[u8; 256]> } (0 = absent).

pub struct HuffmanEncoder { table: [(u32, u8); 256] }              // (code, len) per symbol
pub struct HuffmanDecoder { table: Box<[(u8, u8); 1 << MAX_HUFF_LEN]>, max_len: u8 } // (symbol, len)
impl HuffmanEncoder { pub fn encode_sym(&self, w: &mut BitWriter, sym: u8); }        // w.write_bits(code, len)
impl HuffmanDecoder { pub fn decode_sym(&self, r: &mut BitReader) -> Result<(u8,u8), DecompressError>; }

Decoder build: for each (symbol, len), replicate the entry into all 1 << (max_len - len) slots sharing the low len bits. Decode: peek max_len bits, look up, consume code_len bits; code_len==0 → MalformedHuffman.

Weight serialization (interface only here; comp-format consumes it in Phase 5): serialize_weights(table, w) / deserialize_weights(r, num_symbols) -> Result<HuffmanTable, DecompressError>. Format: direct 4-bit weight per symbol for ≤128 symbols; FSE-compressed weights deferred to Phase 5.

    Raw   { data: Box<[u8]> },

Weights header: Direct = 1-byte count prefix + 1 byte per symbol weight (≤127 symbols); FSE-compressed = FseEncoder-encoded weight sequence as a byte blob, signaled by a header flag bit.

1-stream (Huff1): build Histogram from literals; build_huffman(&hist, max_len=11); serialize weights (Direct vs FSE-compressed, whichever shorter); HuffmanEncoder encodes all literals into one BitWriter stream; if encoded_len >= literals.len() fall through to Raw.

4-stream (Huff4): split literals into 4 equal segments (last absorbs remainder); encode each independently with the same HuffmanTable; jump[0..3] = byte offsets to streams 1–3 (stream 0 starts at 0 implicitly); concatenate; use Huff4 only if smaller than both Huff1 and literals.len().

Decode: Raw copies bytes; Rle fills count bytes with byte; Huff1 deserializes weights → HuffmanDecoder, decodes the stream; Huff4 reads 3 jump offsets, splits the blob into 4 sub-slices, decodes each with the same HuffmanDecoder, concatenates.

encode(sym, cum_freq, sym_freq, total) narrows [low, low+range) to the symbol's cumulative slice: range /= total; low += cum_freq*range; range = sym_freq*range; then renorm(). renorm: while range < 2^24, isolate the top byte of low, handle carry via cache+carry_count (emit carry_count bytes of cache XOR 0xFF on carry then pending cache; else cache then carry_count×0xFF), shift low <<= 8, range <<= 8.

Flush: emit 5 final bytes — range >>= 1 once (prevents decoder over-read ambiguity), then renorm until all bits written; byte count is deterministic.

Decoder: init reads 4 bytes into code, range=0xFFFF_FFFF. decode(cum_freq[], total): step = range/total; recover sym via bounded lookup of code/step in cum_freq[]; code -= cum_freq[sym]*step; range = freq[sym]*step; renorm_decode while range < 2^24: range<<=8, code = (code<<8)|read_byte().

StaticModel: fixed cum_freq[256] built once from Histogram, passed by reference, no mutation after build. AdaptiveBitModel { prob: u16 } (Q15 probability of bit=0, init 1<<14); update(bit, shift): prob += (bit==0 ? normalize_counts (normalize.rs): fn normalize_counts(hist: &Histogram, table_log: u8) -> Box<[i16]>. Algorithm: (1) counts[s]==0 → output 0; (2) counts[s]>0 but would round to 0 → force to 1, marked -1 in the i16 output (zstd convention); (3) scale remaining: norm[s] = max(1, round(counts[s]*2^table_log/total)); (4) correct the largest-count symbol by Δ = 2^table_log - sum(norm) so the sum is exact; (5) validate table_log ∈ [5,12] and total_norm == 2^table_log.

22.2 Detailed Implementation Steps

<!-- Theory anchors: ADR-19 (ring-buffer window for cross-block history); ADR-20 (128 KiB default block size); P-13 (streaming == one-shot byte identity); INV-11 (streaming output byte-identical to one-shot); INV-07 (RepeatOffsets carry across block boundaries) --> 
pub struct StreamCompressor { /* params, finder, reps, history: RingBuf, pending_literals, block_buf, checksum, frame_started */ }

    pub fn write(&mut self, input: &[u8], out: &mut Vec<u8>) -> Result<StreamResult, CompressError>;
    pub fn flush(&mut self, out: &mut Vec<u8>) -> Result<(), CompressError>;   // emit block, continue frame
    pub fn finish(&mut self, out: &mut Vec<u8>) -> Result<(), CompressError>;  // emit last block, frame end

    pub fn new() -> Self;

RingBuf — fixed-size [u8; 1 << window_log] circular buffer replacing Vec growth: write_byte(b), read_back(offset) -> u8 (bounds-checked), copy_match(offset, length, out); invariant capacity == 1<<window_log, head wraps mod capacity, never reallocates after construction.

Block boundary logic (StreamCompressor::write): accumulate into pending_literals; when ≥ block_size_max (default 1<<17=128 KB), call flush_block(out), which runs parse_block on the accumulated data using a MatchFinder seeded from RingBuf history, encodes the CompressedBlock, updates RingBuf+Checksum. First call emits FrameHeader{content_size: None}. flush() calls flush_block even under the threshold (last=false); finish() calls it with last=true, appends the xxhash64 trailer if has_checksum, resets state for the next frame.

Frame chaining (StreamDecompressor::write): after consuming a frame (last block + checksum), attempt to parse the next FrameHeader from remaining input rather than returning Finished; only returns Finished when input is exhausted with no pending frame data. FrameState::{AwaitingFrameHeader, InFrame{header, blocks_done}, Done}.

History across blocks: after each decoded block, copy output bytes into RingBuf (wrap if needed); the next block's MatchFinder is seeded from current RingBuf content. On a chained frame boundary, preserve history if window_log matches, else reset.

Dict integration: StreamCompressor::new_with_dict(params, dict) calls prime_match_finder + prime_entropy_encoder before the first write. Files: comp-format/src/stream.rs (new); lib.rs re-exports; comp-cli/src/cmd_compress.rs + cmd_decompress.rs use the streaming path for stdin/large files.

24.6 Pitfalls

  • with_capacity(field) before validation — a 4-byte length field can request 4 GiB; always validate against max_output_bytes first. Root cause: trusting frame-declared size. Debug: wrap in checked_reserve with an explicit cap.
  • Off-by-one in BitReader refill — reading exactly 64 bits when 63 remain. Root cause: >>64 is 0 in Rust but the refill branch is skipped. Debug: test read_bits(64) on exactly 8 bytes.
  • FSE state machine underflow — table_log forged lower than the table actually built with. Debug: assert!(state < (1<<table.log)) at every step.
  • Huffman weight stream overread — a forged weight-stream length reads past the block boundary into the next block. Fix: pass a sub_slice of exactly the block bytes.
  • Repeat-offset on the first sequence — recent[0..2] are zero-initialized; offset 0 wraps on subtraction. Root cause: missing prior-use check.
  • checksum flag ignored on decode — a bit-misparsed has_checksum=false lets a corrupted frame pass. Root cause: flag bit position must match the frame header descriptor byte exactly.
  • Interleaved 4-stream Huffman partial-decode — out-of-bounds jump-table offsets let one stream overread into another. Validate every jump offset < block end before decoding.

24.7 Performance Concerns

  • Bounds checks in the hot decode loop add ~2–4% overhead vs. an unsafe baseline; acceptable for correctness, profile before removing any.
  • checked_reserve runs once per block, not per byte; overhead negligible.
  • Sanitizer (Asan) builds run only in nightly CI, never gate release perf.
  • Fuzz builds use opt-level=1; cargo fuzz cmin keeps the seed corpus under 500 files.

24.8 Edge Cases

  • Zero-length input: decode_frame(&[], …) → UnexpectedEof (never panic, never Ok).

Threat Model

Trust Boundary

Actor / Surface Trust Level Rationale
Encoder input (encode_frame caller) Trusted Library user controls plaintext
Compressed bytes fed to decode_frame Hostile Network / disk / untrusted peer
Dictionary fed to decoder Hostile External dict file = attacker-controlled
Dictionary fed to encoder Trusted User provides their own dict
CompressParams Trusted Caller controls; validated at entry

The decoder is the sole security-critical surface. Every invariant below targets decode_frame and streaming decompress paths.

T1 — Decompression-Bomb / Amplification

  • Vector: content_size field in FrameHeader claims 1 GB; compressed payload is 10 KB.
  • Amplification ratio is unbounded in the format absent a cap; a 1-byte RLE block type can produce 2^31 identical bytes.
  • Mitigation: decode entry-point accepts max_output: usize; decode_frame + streaming API return DecompressError::OutputLimitExceeded the moment accumulated output would exceed cap.
  • Ratio guard: if content_size_decoded / compressed_bytes_consumed > 4096, raise DecompressError::SuspiciousRatio (configurable).
  • Detection: content_size header field pre-checked; RLE block size field validated against remaining output budget before allocating.

T2 — Memory Exhaustion via Field Inflation

  • Vectors: window_log = 31 → 2 GB allocation; block_size field = u32::MAX.
  • Mitigation: window_log capped at WINDOW_LOG_MAX = 27 (128 MB); block size validated ≤ 1 << window_log and ≤ BLOCK_SIZE_MAX = 128 KiB by default.
  • Validate-before-allocate: all length fields parsed + range-checked before any Vec allocation; Vec::try_reserve used, Err → DecompressError::AllocationFailed.
  • Dict content: content.len() capped at DICT_CONTENT_MAX; entropy table sizes validated before build.

T3 — Out-of-Bounds Read via Corrupt Offset / Length

  • Vectors: offset in a Sequence points before the start of the decompressed history; match_length extends past current output buffer.
  • Mitigation: every (offset, length) pair validated: offset ≤ decoded_so_far + dict_content.len(), decoded_so_far + length ≤ max_output; offset = 0 is invalid (reserved); repeat-offset codes 1–3 validated against RepeatOffsets state (see T7).
  • Implementation: checked get(range) on output slice; None → DecompressError::OffsetOutOfBounds.
  • No unsafe indexing in the decode hot path; #[cfg(debug_assertions)] asserts redundantly.

T4 — Corrupt FSE / Huffman Table

  • Vectors: normalized_counts sum ≠ 2^table_log; max code length > cap (11 for Huffman); symbol count > 256; negative counts on non-sentinel positions.
  • Mitigation: normalize_counts validates: sum == 1 << table_log, each count ≥ -1 (the -1 sentinel), no count > 1 << table_log.
  • Huffman: sum of 2^(max_len - code_len) over all symbols ≤ 2^max_len (Kraft check); weight stream length bounds-checked before parsing.
  • All table builds gated on validation; build_fse_decode / build_huffman return Err on invalid input; decoder never calls them with unchecked data.

T5 — Infinite Loop / Non-Terminating Decoder

  • Vector: malformed block-header stream where last=false always; BitReader never exhausted.
  • Mitigation: structurally bounded — each block's header contains its byte size; decoder advances input cursor by exactly block_size bytes; loop terminates when cursor reaches frame end OR last=true; consumed-bytes check after each block (must be > 0).
  • FSE state machine: table_log ≤ FSE_LOG_MAX = 12; state always in [0, 1 << table_log); each step consumes ≥ 1 bit; bounded by compressed-block byte count.

T6 — Malicious Dictionary

  • Vectors: dict magic mismatch; negative or overflow entropy table entries; prefix content references forged offsets.
  • Mitigation: dict magic validated (DICT_MAGIC = 0xEC30A437); entropy tables in the dict go through the same T4 validation path; dict content length bounded; dict treated as unverified historical data — offset checks (T3) cover into the dict prefix.
  • dict_id mismatch: decode_frame returns DecompressError::DictMismatch if frame's dict_id ≠ supplied dict's id; no silent fallback.

T7 — Repeat-Offset Desync → Arbitrary-Offset Read

  • Vector: encoder and decoder maintain different RepeatOffsets.recent LRU state → decoder interprets repeat-offset code as a large raw offset → out-of-bounds copy.
  • Mitigation: repeat-offset codes 1–3 are only valid when recent[i] > 0; validated before use; RepeatOffsets initialized identically on both sides (all zeros → only raw offsets valid initially).
  • Cross-check: offsets derived from repeat codes pass the same T3 bound check.

T8 — Checksum Bypass / Silent Corruption

  • Vector: frame checksum field absent (flag clear) or attacker strips it; bit-flip in payload undetected.
  • Mitigation: has_checksum flag respected; when present, Checksum (xxhash64) computed over decompressed output and verified; mismatch → DecompressError::ChecksumMismatch.
  • Note: checksum is optional by format design (small frames, RPC pipelines skip it); library cannot enforce presence, but DecodeOptions::require_checksum = true forces rejection of frames without it.

T9 — Panic-as-DoS

  • Vector: attacker feeds input that triggers unwrap() / out-of-bounds index panic → process abort.
  • Mitigation: #[forbid(clippy::unwrap_in_result)] in comp-format/comp-entropy/comp-lz decode paths; index[] replaced with .get()?; array access in FSE state machine uses % table_size with pre-validated table_size (power-of-two); #[no_panic] annotation via no_panic crate on hot decode functions (compile-time verification).
  • Fuzz harness (libfuzzer via cargo-fuzz): fuzz_target!(|data| { let _ = decode_frame(data, None); }) — any panic is a bug.

T10 — Supply-Chain / Dependency

  • Mitigation: deny.toml (cargo-deny) enforces license allowlist + vulnerability advisory checks in CI; Cargo.lock committed; comp-core/lz/entropy/format/dict have zero runtime dependencies beyond core + alloc; comp-cli deps audited.

FM1 — Round-Trip Mismatch (S1)

  • Symptom: decode_frame(encode_frame(input)) != input; checksum mismatch OR silent byte difference.
  • Root cause: encoder and decoder bitstream disagreement — wrong extra-bits count for LL/ML/OF code, off-by-one in FSE state transition, Huffman code assigned in wrong canonical order, or Sequence executed in wrong order.
  • Detection: round_trip_test(corpus) in CI (Calgary/Canterbury/Silesia + enwik8 slice); any mismatch fails immediately.
  • Bisection methodology:
    1. Dump Vec<Sequence> from encoder; re-encode from those sequences and decode — if match restores, the LZ stage is clean.
    2. Dump raw literals byte-stream + LL/ML/OF symbol streams; hand-decode with a reference FSE/Huffman impl — isolates entropy stage.
    3. Compare FSE encode-table state transitions vs decode-table on a fixed seed; mismatch narrows to build_fse_decode vs encode.
    4. Binary-search the block: split at block N, compress + decompress sub-range, identify first diverging block.
  • Forensic artifacts: --inspect subcommand in zc dumps per-block byte counts, sequence counts, literal/sequence section sizes.
  • Recovery: no auto-recovery (data loss class); fix the bitstream bug; re-compress affected data.

FM2 — Repeat-Offset Desync (S1)

  • Symptom: decoded output contains wrong data, or DecompressError::OffsetOutOfBounds at a position that looks valid; often triggered at block boundaries.
  • Root cause: RepeatOffsets.recent LRU updated in different order on encode vs decode (e.g. a "repeat-offset for a match of length 0" edge case, or an off-by-one in LRU promotion).
  • Detection: property test — encode 1000 random blocks with repeats; decode; compare sequences; check recent state after each block.
  • Bisection: dump RepeatOffsets state after each Sequence in encoder; replay decode and compare state per sequence.
  • Mitigation: lock the LRU update rule to the zstd spec (rep0 match of length 0 is a special literal, not a repeat); regression test that specific case.

FM3 — Checksum Mismatch (S2)

  • Symptom: DecompressError::ChecksumMismatch; content decoded successfully but xxhash64 disagrees.
  • Root cause: bit-flip in compressed or uncompressed payload (storage/network); or encoder computing checksum over wrong byte range (e.g. excluding the last flush segment).
  • Detection: automatic — xxhash64 computed over all output bytes, compared to frame trailer.
  • Recovery: re-fetch / re-read source; do not use the decoded data.
  • Forensic: log the expected vs actual checksum and the byte offset where checksum field was read.

FM4 — Decompression-Bomb Cap (S2)

  • Symptom: DecompressError::OutputLimitExceeded; legitimate large payload rejected.
  • Root cause: max_output set too low for the workload; or adversarial input.
  • Detection: content_size in FrameHeader vs max_output checked at frame-start (fail-fast before decompressing).
  • Recovery: operator raises DecodeOptions::max_output; verify the content_size is legitimate before doing so.

FM5 — Decode Error on Valid-Looking Input (S3)

  • Symptom: DecompressError::MalformedBlock or UnexpectedEof on a frame the operator believes is correct.
  • Root cause: version skew (frame uses a feature flag the decoder doesn't recognize); truncated write; encoding bug that produced a structurally valid but semantically wrong bitstream.
  • Detection: zc inspect <file> to dump FrameHeader flags, block count, per-block types + sizes.
  • Recovery: capture the raw frame bytes for forensics; attempt re-compress from source.
  • Long-term: version field in FrameHeader; new feature bits are reserved; decoder returns DecompressError::UnsupportedFeature for unknown flags.

FM6 — FSE / Huffman Table Build Failure (S3)

  • Symptom: DecompressError::InvalidEntropyTable; frame abandoned mid-decode.
  • Root cause: corrupt compressed header section; normalized counts don't sum to 2^table_log; Kraft inequality violated.
  • Detection: validation in normalize_counts / build_fse_decode / build_huffman (all return Result).
  • Forensic: log which table (LL/ML/OF/literals Huffman) failed + the raw normalized-count slice.

FM7 — Window Underflow (S3)

  • Symptom: DecompressError::OffsetOutOfBounds; offset references bytes before history start.
  • Root cause: encoder emitted an offset > available history (first block without dict, or stream-start); or dict not supplied to decoder when it was to encoder.
  • Detection: offset check offset ≤ decoded_so_far + dict_prefix_len.
  • Recovery: ensure dict is consistently supplied; check encoder RepeatOffsets initialization.

FM8 — Streaming Boundary Bug (S4)

  • Symptom: correct single-shot encode/decode but streaming push/pull produces wrong output at flush boundaries or frame-chain seams.
  • Root cause: Window history not correctly carried across flush() calls; RepeatOffsets reset at wrong boundary.
  • Detection: streaming fuzz target — random chunk sizes feeding the same input; compare to single-shot output.
  • Recovery: reset streaming state; re-compress from scratch.

FM9 — Ratio Regression vs Oracle (S4)

  • Symptom: compression ratio significantly worse than a previous build or than zlib on the same corpus.
  • Root cause: CompressionLevel → CompressParams mapping changed; HashChainFinder search_depth reduced; LazyParser disabled; FSE table_log suboptimal.
  • Detection: CI benchmark gate — ratio on Calgary corpus must be within 2% of baseline.
  • Runbook: compare CompressParams via zc bench --verbose; inspect per-block literal vs sequence share via zc inspect.

FM10 — Range-Coder Carry Propagation Bug (S4)

  • Symptom: RangeDecoder returns wrong symbols or DecompressError::MalformedBlock; only triggered on the arithmetic backend.
  • Root cause: carry not correctly propagated through deferred-byte buffer; renormalization threshold wrong.
  • Detection: unit tests with known carry-trigger values (probability boundary inputs); cross-check encode + decode on synthetic symbols.

  • A Dictionary is identified by dict_id: u32 (CRC32 of the dict content).
  • A frame's FrameHeader.dict_id binds it to a specific dict.

  • Phase-0 commitment: zero; our magic, our format, our semantic.

Profiling Workflow

  • perf record -g → cargo flamegraph; annotate hot symbols; re-run after each optimization.
  • perf stat -e cache-misses,cache-references on HashChainFinder: head array fits L1 at hash_log ≤ 17; prev array is L2/L3 → main cache-miss source; mitigation: prefetch prev[pos + 8] in chain walk.
  • FSE/Huffman decode tables: fit decode table (2^table_log entries × 8 bytes) in L1/L2; table_log ≤ 11 for Huffman (~16 KiB), table_log ≤ 12 for FSE (~32 KiB).

Hot Loops

Match-finder chain walk:

  • Inner loop: load prev[pos % window], compare min_match bytes, update best; branch on depth counter.
  • Avoid: function call per compare; use memcmp-equivalent unrolled or SIMD compare for match length extension.
  • Cache behavior: prev array random-access → 1 miss per chain hop at large windows; search_depth is the primary knob.

FSE decode inner loop:

  • state -> (symbol, nb_bits, baseline) — single table lookup per symbol; pull nb_bits from BitReader.
  • Three interleaved states (LL/ML/OF) hide BitReader latency via OOO execution.
  • Branch-free: all three states decode in round-robin; no conditional symbol dispatch.

Huffman decode fast table:

  • Peek max_len bits; table entry gives (symbol, actual_len); consume actual_len bits.
  • 100% L1 hit rate at max_len = 11 (4 KiB table); near-zero branch mispredicts on typical text.

Allocation Analysis

  • Compress path: Window (1 << window_log bytes), HashChainFinder::prev (Vec<u32>, same size), head array ([u32; 1 << hash_log]). All allocated once per CompressParams, reused across blocks.
  • Decode path: output Vec<u8> (bounded by content_size or window_log cap); decode table allocated once per FseTable/HuffmanTable; no per-symbol allocation.
  • No per-block allocator calls on the hot path; Vec<Sequence> reused via clear() + reserve().

4-Stream Literals Layout (decode ILP)

  • Literals section split into 4 equal streams with a jump table header (offsets to each stream start).
  • Decoder runs 4 independent HuffmanDecoder instances; OOO CPUs overlap BitReader refills.
  • ILP gain: ~1.5–2× throughput vs single-stream on superscalar cores.
  • Fallback: 1-stream layout for literals blocks < 1 KiB (overhead not worth 4-stream framing).

Scalability Analysis

Compression Cost vs Input Size

  • LZ pass: O(n × search_depth) — each position does at most search_depth chain hops; search_depth ∈ {4..256} by level; linear in n for fixed depth.
  • Entropy pass: O(n) — one FSE/Huffman symbol per sequence element; histogram build O(n).
  • Block split: O(n / block_size) frame overhead; block_size = 128 KiB default → negligible.
  • Memory: fixed at window allocation + finder tables regardless of total input length (streaming).

Decode Cost

  • Strictly O(n): one FSE state transition + one Huffman table lookup per symbol; one copy per match.
  • Entropy decode dominates for high-ratio files; match copy dominates for low-ratio (long matches).
  • No decode path depends on search_depth or strategy — decoder is symmetric regardless of encoder level.

Block-Parallel Compression

Input stream
  ├─ Block 0 (128 KiB) → thread 0 → CompressedBlock 0
  ├─ Block 1 (128 KiB) → thread 1 → CompressedBlock 1
  └─ Block N (≤128 KiB) → thread N → CompressedBlock N
                  ordered reassembly → Frame
  • Each block is independent (no cross-block LZ backreferences by default at window_log ≤ 17).
  • Thread pool (Rayon) under multithread feature; near-linear throughput in cores up to ~8 (I/O bound beyond).
  • Ordered output: blocks buffered and emitted in sequence; last flag on final block.
  • Memory: N threads × 128 KiB window each; cap thread count if window_log > 20 to avoid OOM.

Decode Parallelism

  • Within a frame: sequential — each block's LZ output depends on the preceding history window; cannot parallelize unless cross-block references disabled.
  • Across frames (multi-frame file): frames are independent units → parallel decode in O(frames) threads; requires frame index (optional skip table in the format).
  • Dictionary usage does not add serial dependency beyond the initial prefix load.

Mental Models & First Principles

# Expert Insight What It Predicts Bug Class Without It Resolving §
MM1 Entropy is a hard floor. A codec can never compress below H(X) bits/symbol for a source with distribution X; every bit below entropy requires knowing the distribution perfectly. normalize_counts rounding incurs overhead ≤ 1/table_size above entropy — measurable in Phase 7. Huffman's 1-bit/symbol overhead above entropy is predictable. Engineers try to "squeeze" entropy coding past the theoretical limit — no amount of table-log tuning helps once you're within 0.1 bit of entropy. §7 (normalize_counts target ≤ 0.1 bit/sym, Phase 7, §19)
MM2 A match finder is a shortest-path problem. The optimal LZ parse is a DAG relaxation over block positions, not a greedy scan; cost(literal) = -log2(p_lit) bits, cost(match) = code_bits + extra_bits. Lazy parse gains +1–2% ratio over greedy; Optimal gains +3–5%. Ratio improves strictly as more parse paths are explored. Engineers assume "find the longest match" is optimal. It isn't — a shorter match at lower offset code cost can be cheaper. Greedy-only parsers leave bits on the table. §5 Required Reading (CLRS DAG shortest-path), Phase 3 (OptimalParser, §15)
MM3 FSE encodes in reverse because ANS is a stack. The tANS state machine transitions in LIFO order; encode must push symbols onto the state stack (reverse), decode pops them forward. If encoding processes symbols in forward order, decode will produce the mirror-image symbol sequence. Encode/decode symmetry is irreversible without reordering. Forgetting LIFO produces silent data corruption: round-trip fails only after the first FSE-encoded sequence is decoded — the bug is not obvious at the table-build stage. Phase 7 (FseEncoder LIFO discipline, §19), INV-01 (round-trip identity)
MM4 Repeat offsets are LRU cache hits. The three recent offsets in RepeatOffsets.recent[3] form a tiny LRU cache; a repeat-offset hit costs zero extra bits for the offset field (code 1/2/3) vs. 5–32 bits for a real distance. Structured data (JSON, source code, binary records) exhibit high repeat-offset hit rates (≥20%); random data approaches 0%. The cache pays for itself on the first repeated stride pattern. Without repeat offsets, every back-reference pays the full offset code cost. The ~0.5–2% ratio gain on realistic data is entirely missed. Phase 3 (RepeatOffsets, §15), ADR-09, INV-07
MM5 The decoder is the only attack surface. Encoders compress trusted data they produced; decoders parse untrusted data from the network/disk. Every field read from a compressed stream is adversarial input. Validation must happen before allocation (window_log → alloc), before state initialization (FSE table sums), and before memory access (offset validity). Late validation = exploitable window. Engineers write a "safe encoder, fast decoder" design and skip validation on the decode hot path. A forged content_size then triggers a 4 GiB Vec::with_capacity. Phase 12 (decoder hardening, §24), P-02, P-03, INV-09, T1–T9
MM6 Carry propagation is the arithmetic coder's fragile invariant. The range coder's interval can carry into the previously emitted byte; the deferred-byte algorithm holds a cache byte until it is known not to carry further. Any sequence of high-probability symbols (probability near 1.0) produces long carry chains; carry_count can reach n/8. Flushing the wrong byte value propagates silently to decode output. Engineers emit bytes as soon as the interval narrows, missing the carry case. The resulting decoder sees a different symbol sequence — corruption is silent and hard to bisect. Phase 6 (RangeEncoder carry algorithm, §18), INV-06
MM7 normalize_counts must preserve rare symbols. FSE's state table has 2^table_log slots; a symbol with count > 0 must occupy at least one slot, or it becomes undecodable. The "-1 marker" forces count = 1 for these symbols. Low-frequency symbols (count = 1 in a large corpus) get norm count = 1, not 0. The state table covers the full alphabet. Bits/symbol overhead rises slightly for very rare symbols but correctness is preserved. Rounding rare symbols to zero removes them from the decode table. Any stream containing those symbols produces CorruptData — reproducible only on specific rare inputs, hard to catch in unit tests. Phase 7 (normalize_counts -1 marker, §19), INV-05, ADR-13
MM8 Block-type election is a measurement, not a heuristic. The encoder must measure Raw, RLE, and Compressed sizes for each block and emit the smallest; "this looks compressible" guesses result in bloated output. Incompressible random input (entropy ≈ 8.0 bits/byte) always elects Raw; single-byte runs elect RLE; text elects Compressed. The Compressed path is never allowed to make output larger than the input. Omitting the Raw fallback causes the codec to bloat random data by ≥ 5% (Huffman + FSE table overhead). This breaks the invariant "compressed ≤ raw" and fails the Phase 13 conformance gate. Phase 5 (LiteralsSection Raw fallback, §17), Phase 8 (BlockType election, §20), P-05, INV-10

Per-System Paragraph

zstd (Yann Collet, Facebook/Meta, 2016–present). The direct algorithmic ancestor of this blueprint. zstd made the key decision to use FSE/tANS for sequence symbols instead of Huffman, achieving near-entropy coding of the LL/ML/OF streams at near-zero decode cost. Its niche is the best ratio/speed tradeoff in the 2–3× ratio range for modern hardware; it wins on any workload that can afford 100–500 MB/s compress throughput and needs dictionary support for small-file compression (e.g., CDN serving, database blocks).

zlib / DEFLATE (Jean-loup Gailly, Mark Adler, 1995–present). zlib chose to use a combined Huffman tree encoding both literals and match-length tokens, which simplifies the format at the cost of coupling two distinct symbol distributions under one table. This wins when decoder simplicity and format ubiquity matter most: DEFLATE is mandated by PNG, ZIP, HTTP, TLS compression — the installed base is so large that correctness and portability outweigh ratio. It loses on ratio at equal throughput versus FSE-based codecs.

LZMA / 7-zip (Igor Pavlov, 2001–present). LZMA chose a range coder (arithmetic) with a rich context model: each bit of each match/literal field is predicted by a distinct probability model updated adaptively. This produces the best ratio of any practical codec (typically 10–20% better than zstd at comparable speed), winning on archival workloads where encode time is unconstrained and ratio is the sole metric. The cost is slow encode (BtFinder + adaptive probability models), high decoder complexity, and a non-trivial range-coder carry implementation. This blueprint includes a RangeEncoder as an alternative backend but does not implement LZMA's context model.

Brotli (Jyrki Alakuijärvi, Evgenii Kliuchnikov, Google, 2013–present). Brotli's differentiating decision was to include a large static dictionary (11 MB of common web content) and a context-map entropy model where different byte contexts use different Huffman tables. This wins decisively on web assets (HTML, CSS, JS) where the static dictionary recognizes common tokens without training, and where the fine-grained context entropy reduces bits/symbol. It loses on non-web workloads (binary, scientific data) where the static dictionary provides no benefit and the context-map overhead adds latency.

Alternative Architectures (Roads Not Taken)

Alt-1: Context-Adaptive Range Coder (LZMA-style)

Input bytes
    │
    ▼ LZMA BtFinder (4-byte hash)
Match candidates
    │
    ▼ Adaptive probability models (per bit, per context)
      literal contexts: 256×3 models
      match/rep bit:    32+ models
    │
    ▼ Range coder (arithmetic) with per-model updates
    │
    ▼ .lzma / .xz frame

Regime where it wins: archival compression where encode time is unconstrained, ratio is the sole metric, and input is text or structured binary. LZMA achieves 10–20% better ratio than FSE-based codecs because adaptive context models track local statistics that a static per-block histogram misses.

Real system: LZMA2 (7-zip, Igor Pavlov, 2001), XZ Utils (Lasse Collin, 2009), used in Linux kernel tarballs, Debian packages, and .xz format.

Why rejected: encode throughput of ~5–15 MB/s is incompatible with the ≥300 MB/s Fast-level target. Per-bit probability updates add O(n × context_count) state transitions on the encode path. The range coder is included as RangeEncoder for teaching, but the full LZMA context model (256-tree literal models, length/distance models) is out of scope.

Alt-2: Purely Byte-Oriented Huffman + LZ77 (DEFLATE-style)

Input bytes
    │
    ▼ Hash-chain match finder (single pass)
Literal + match tokens (combined stream)
    │
    ▼ Combined literal/length Huffman tree (288 symbols)
       + separate distance Huffman tree (32 symbols)
    │
    ▼ DEFLATE block (RFC 1951)

Regime where it wins: format ubiquity. When the compressed output must be decodable by any device on Earth (PNG, ZIP, HTTP, TLS), DEFLATE is the only option. The combined literal/length tree simplifies the format at the cost of coupling two different symbol distributions. Decoder complexity is lower (one tree format, no FSE state machine).

Real system: zlib (Gailly/Adler, 1995), DEFLATE (Deutsch, RFC 1951), used in every browser, OS, and network stack.

Why rejected: FSE achieves ~5–10% better ratio than Huffman on the LL/ML/OF streams at equal or higher decode throughput (decode table lookup is O(1) for both). Separating literal coding (Huffman) from sequence-symbol coding (FSE) is strictly more flexible. DEFLATE's combined tree is a legacy artifact of wanting one wire format for both.

Alt-3: Block-Independent Compression (LZ4-style)

Input bytes
    │
    ▼ Hash table (1 entry per 4-byte hash, no chain)
Match candidates (max 1 per position)
    │
    ▼ Token stream: literal_length | match_length | offset
       encoded as fixed-width fields (no entropy coding)
    │
    ▼ LZ4 block format

Regime where it wins: ultra-low-latency and hardware simplicity. LZ4's decoder is a simple copy loop with no entropy decoding state machine, achieving 2–5 GB/s decode throughput on commodity hardware. This wins for in-memory caching tiers (Redis RDB compression, RocksDB kLZ4Compression), real-time log pipelines, and any setting where decode latency dominates over ratio.

Real system: LZ4 (Yann Collet, 2011), used by Redis, Kafka, RocksDB, Hadoop, and many in-memory stores.

Why rejected: LZ4 achieves only ~2:1 compression ratio on text (vs. 3:1+ for this design at Default). Omitting entropy coding forfeits the entire entropy-coding gain. For the portfolio goal of building a complete entropy-aware codec from first principles, skipping FSE would omit the most technically interesting component.

Alt-4: Asymmetric Shared-Format (Brotli-style)

Input bytes
    │
    ▼ Hash + context model match finder
Literals + matches
    │
    ▼ Context map (64 context clusters × per-cluster Huffman trees)
    │
    ▼ 11 MB static web dictionary lookup
    │
    ▼ Brotli frame (RFC 7932)

Regime where it wins: web content delivery. The 11 MB static dictionary recognizes common HTML/CSS/JS tokens without training, and the context map routes different byte contexts through different Huffman tables (e.g., ASCII lower vs upper half, after < vs after >). This achieves the best ratio on homogeneous web assets at the cost of an 11 MB bundled dictionary and higher decode complexity.

Real system: Brotli (Alakuijärvi/Kliuchnikov, Google, 2013–present), mandatory in HTTP/2 Accept-Encoding: br, used by all major CDNs.

Why rejected: The 11 MB static dictionary is domain-specific to web content and provides zero benefit for binary, scientific, or log data. The context-map entropy model requires 64× more Huffman tables per block, making the decoder ~3× slower than zstd/FSE for non-web workloads. The comp-dict COVER-lite trainer provides an equivalent trained-dictionary capability for domain-specific data without the static-dictionary lock-in.

Glossary

Term Definition
LZ77 Lempel-Ziv 1977 compression: encode data as back-references (offset, length) into a sliding window of previously seen bytes; literals fill gaps.
LZSS LZ77 variant: emits either a raw literal byte OR a (offset, length) match pair, never a literal wrapped in a match; flag bit distinguishes them.
Sliding window Fixed-size circular buffer (size = 1 << window_log) of the most recently processed bytes; the match finder searches this history.
History The valid region of the Window behind the current encode/decode position; bounded by window_log and the bytes emitted so far.
Match finder Component that scans history for the longest/best match at the current input position; abstracted by MatchFinder trait in comp-lz.
Hash chain HashChainFinder structure: head[hash(next 3 bytes)] → most recent position; prev[pos] chains older collisions; walk bounded by search_depth.
Binary-tree match finder BtFinder: maintains per-hash two child pointers (greater/less) to form a sorted tree of previous occurrences; finds all match lengths efficiently; used by OptimalParser.
Greedy parse GreedyParser: accept the first (longest) match found at each position; advance by match length; O(1) decision per position.
Lazy parse LazyParser: after finding a match at position p, also probe p+1; if the p+1 match is longer, emit a literal at p and take the better match; one-step lookahead.
Optimal parse OptimalParser: price-based shortest-path (Dijkstra/DP) over all possible match/literal choices in a block; cost = entropy bits of resulting symbols; highest ratio, highest cost.
Repeat offset One of the three most-recently-used match offsets tracked in RepeatOffsets { recent: [u32; 3] }; encoded in Sequence.offset as codes 1..=3 instead of a raw distance; saves bits on recurring offsets (e.g., stride patterns).
Literal A raw unmatched input byte passed through without back-reference; grouped in Sequence.literal_length preceding a match.
Match A back-reference (offset, length) where offset is distance into the window and length >= min_match; captured in Match { length, offset }.
Sequence Sequence { literal_length, match_length, offset }: the unit of LZ output; a run of literal_length literals followed by one match of match_length at offset; match_length=0 = literals-only tail.
Literal length (LL) The literal_length field of a Sequence; entropy-coded via FSE in the SequencesSection using a code table with baseline+extra-bits.
Match length (ML) The match_length field of a Sequence; encoded via FSE ML code table; min_match=3.
Offset (OF) The offset field of a Sequence; encodes either a repeat-offset code (1..=3) or a real window distance; entropy-coded via FSE OF code table.
Minimum match min_match = 3; a back-reference is only emitted when match_length >= 3, otherwise a literal is cheaper.
Entropy Shannon information content of a symbol distribution; lower entropy = more compressible; build_huffman and FSE exploit redundancy in the Histogram.
Canonical Huffman Prefix-free code where code lengths alone determine codes (assigned by sorted (length, symbol) order); enables compact weight serialization; used in HuffmanTable.
Length-limited code Huffman variant capping code lengths at a maximum (e.g., 11 bits) to keep the fast decode table at bounded size (2^max_len entries); Kraft inequality preserved.
Package-merge Optimal length-limited Huffman algorithm (Larmore-Hirschberg); produces minimum-redundancy codes under a max-length constraint; used in build_huffman.
Kraft inequality Σ 2^{-len_i} ≤ 1; necessary and sufficient for a valid prefix-free code; violated lengths → invalid HuffmanTable.
Arithmetic coding Entropy coder that maps a symbol sequence to a sub-interval of [0,1); achieves near-Shannon entropy; implemented as RangeEncoder/RangeDecoder.
Range coder Integer arithmetic coding variant: maintains low: u64, range: u32; narrows interval by symbol cumulative frequency; emits bytes on renormalization; carry-safe.
Renormalization Step in range coding when range < 2^24: emit a byte of low, shift low and range left by 8; keeps precision without arbitrary precision.
Carry propagation Arithmetic coder artifact: incrementing low can carry into previously emitted bytes; deferred-byte counting (0xFF buffering) handles this without unbounded buffering.
ANS Asymmetric Numeral Systems (Duda): integer-based entropy coding; bijective state machine; tANS is the table-based variant used in FSE.
tANS Table-based ANS; the variant used by FseTable; state transitions encoded in lookup tables built from normalized counts; LIFO: encode reversed, decode forward.
FSE Finite State Entropy — zstd's name for its tANS implementation; encodes LL/ML/OF symbols in the SequencesSection; FseEncoder/FseDecoder in comp-entropy.
State table The FseTable decode array of (symbol, nb_bits, new_state_base) tuples of length 2^table_log; built by build_fse_decode.
Normalized counts Integer counts summing to 2^table_log produced by normalize_counts; low-probability symbols rounded to 1 (marked -1 before rounding); fed to build_fse_decode.
Symbol spreading Step in build_fse_decode: distributes symbol occurrences across the state table using the step (5/8 * size + 3) walk to ensure a uniform spread for good mixing.
Table log FseTable.log; table_size = 2^table_log; controls FSE precision vs. table memory; typical range 6..=12.
Block Independently decodable unit within a frame; typed by BlockType: Raw (stored), Rle (one byte repeated), or Compressed (LiteralsSection + SequencesSection).
Frame Top-level container: FrameHeader + one or more blocks + optional xxhash64 content checksum; self-described by magic number.
Frame header FrameHeader { window_log, content_size, dict_id, has_checksum, magic }; parsed first by decode_frame; caps window allocation before any block is read.
Window descriptor Compact window_log encoding in the FrameHeader; decoder allocates 1 << window_log bytes for history; must be validated against size caps before allocation.
Block header BlockHeader { last, block_type, size }; 3-byte field preceding each block; last=true signals the final block; size is the compressed payload length.
Raw block BlockType::Raw: payload copied verbatim; used when data is incompressible or for Phase-0 smoke-test round-trips.
RLE block BlockType::Rle: single byte + repeat count; optimal for long runs of identical bytes.
Compressed block BlockType::Compressed: LiteralsSection (Huffman-coded literals) + SequencesSection (FSE-coded LL/ML/OF + extra bits).
Literals section Sub-region of a compressed block holding the concatenated literal bytes, Huffman-compressed; supports 1-stream and 4-stream (jump-table) layouts; falls back to Raw/RLE when incompressible.
Sequences section Sub-region of a compressed block holding the FSE-interleaved LL/ML/OF symbol streams + extra bits; fully describes all back-references in the block.
4-stream layout Literals section variant splitting the Huffman-coded literal stream into 4 independent sub-streams with jump-table offsets; enables parallel decode.
Dictionary Dictionary { id, entropy, content }: pre-agreed data augmenting both paths; content primes the Window; entropy pre-loads HuffmanTable/FseTable; identified by dict_id in the FrameHeader.
Dictionary id u32 in FrameHeader.dict_id; links a frame to a specific Dictionary; decoder returns an error if the required dict is absent.
Content checksum Optional trailing xxhash64 digest of the decompressed content; verified by decode_frame when FrameHeader.has_checksum=true; computed by Checksum.
