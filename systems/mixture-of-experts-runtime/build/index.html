Pitfalls
  • Arena alignment: Arena::alloc must guarantee 64-byte alignment; naive bump misaligns SIMD loads. Signal: SIGBUS on AVX load in Phase 4. Debug: assert_eq!(ptr as usize % 64, 0) in alloc.
  • TensorId collision: two arenas using separate counters produce non-unique IDs if Arc<AtomicU64> is not shared at workspace level. Signal: combine mistakenly aliases input/output. Debug: assert distinct IDs before combine write.
  • Dtype widening silently: gemm_stub reads Tensor.dtype but Phase 0 only handles F32; passing F16 tensor silently reinterprets bytes. Signal: NaN outputs. Fix: assert_eq!(a.dtype, DType::F32) guard at top of stub.
  • Combine weight sum drift: gate weight=1.0 in top-1 trivial case passes, but floating-point sum assertion fires when weights computed from real softmax (Phase 1). Loosen tolerance to 1e-4 now to avoid false failures later.
  • SmallVec shape overflow: shapes with > 4 dims spill to heap, unexpected alloc in arena-only forward (signal: allocator counter mismatch; fix: cap SmallVec<[usize;4]>, reject 5-D at GateLogits ctor). MSRV 1.78 breakage: accidental std::simd (1.89+) or LazyLock (1.80+) fails CI; fix: rust-toolchain.toml pins 1.78.0, CI runs cargo +1.78.0 check.

⬜ Phase 1 — Gating network — dense top-k router, softmax-over-topk, deterministic tie-break, router logits §13

Objectives
  • Replace stub argmax with full gating: linear projection W_g (d_model→num_experts), top-k selection, softmax-over-topk normalization, deterministic tie-break.
  • Implement noisy_topk: add N(0,1)·softplus(W_noise·x) noise per expert before selection (Shazeer 2017).
  • Compute GateLogits = x·W_g^T; return RoutingDecision with gate weights summing to 1 over top-k per token.
  • Enforce routing determinism invariant: identical input+seed → identical RoutingDecision/DispatchPlan bit-for-bit.
  • Compute AuxLossState{importance, load} (GShard/Switch aux loss) and router z-loss mean(log²(Σexp(logits))) (ST-MoE, Zoph 2022).
  • Expose logits + routing decisions via telemetry spans; compute routing entropy per token.
  • Constraints: CPU-only, no EP, capacity=inf (no dropping yet), k≥1, num_experts≥k.
Deliverable
  • DenseRouter::route operational for arbitrary n_tokens/num_experts/k, CPU only; weights sum to 1.0 per token (test-verified).
  • AuxLossState (importance, load, aux_loss, z_loss) computed and emitted via telemetry; routing entropy readable via Telemetry::snapshot().
  • Noisy top-k reproducible: same seed → same routing for any input shape. moe-cli run prints entropy+aux_loss to stderr under RUST_LOG=moe_gate=debug.

Pitfalls
  • Softmax overflow: forgetting row-max subtraction before exp overflows to inf (signal: NaN weights; fix: always max-subtract, verify with large-logit fixture). Tie-break platform drift: bare f32::partial_cmp orders differently ARM vs x86 (fix: explicit (neg_val, idx) tuple sort).
  • Noise PRNG state leak: Xorshift64 state persisting across batches breaks reproducibility (signal: determinism test fails after batch 2; fix: reseed from (layer_idx XOR batch_token) each route() call).
  • Full softmax for importance: softmax_all(logits) for importance loss adds O(n·E) work, easy to forget and cause 2× slowdown — fuse with logit-computation loop.
  • Z-loss overflow: naive log(Σexp(logits)) overflows past logit 80 — use logsumexp = max + log(Σexp(logits-max)).
  • Weight tensor aliasing: w_g shared across threads when DenseRouter is Arc-wrapped — matmul must take &self, never &mut self.
  • k=0: RouterConfig must reject at construction; otherwise zero-length per-token arrays make combine silently output zeros.

⬜ Phase 2 — Token dispatch + combine (single device) — permutation/scatter-gather, per-expert contiguous buffers, weighted combine (un-permute + gate-weighted sum) §14

Objectives
  • Implement full DispatchPlan construction: token→expert assignment from RoutingDecision, permutation array, capacity enforcement, deterministic lowest-weight drop, dropped: BitSet.

Pitfalls
  • Combine += without zero-init: unzeroed output[t,:] accumulates onto garbage (signal: non-deterministic large error; fix: Arena zero-on-alloc + memset guard). Dropped-token overwrite: combine processing dropped tokens with weight 0 clobbers residual (fix: skip dropped in assignment loop, apply residual in separate final pass).
  • Sort instability in drop selection: unstable sort changes which tokens drop on identical input (signal: bitset differs across runs; fix: stable sort on full (weight, token_idx, expert_idx) key).
  • Off-by-one in Capacity: floor instead of ceil underestimates capacity by 1, inflating drop_rate at boundary (fix: integer ceiling (num+den-1)/den).
  • Expert buffer shape mismatch: if expert forward reorders rows internally, slot→row mapping breaks combine — invariant: expert FFN must preserve row order (assert shape + integration test).
  • Empty expert forward: per_expert_counts[e]==0 must still yield a valid empty [0,d_model] tensor, not a null handle (signal: combine crashes on lookup; fix: pre-fill zero-row tensors).
  • Weight normalization post-drop: token assigned {0.3,0.4,0.3} with one expert over-capacity combines to 0.7, not 1.0 — spec deliberately does NOT re-normalize; fractional output for partially-dropped tokens is accepted and documented in ADR.
