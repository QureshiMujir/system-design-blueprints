⬜ Phase 0 — DDPM on CIFAR-10 to FID < 50 in One Hour §12

Objectives
  • Stand up diffuse.schedules/precond/backbones.unet/train.loop/samplers.ancestral/eval.fid/ ckpt/cli as a runnable vertical slice (§1 Phase-0 deliverable list).
  • Prove the closed-form forward process (§8 q(x_t|x_0)) and ε-prediction loss end to end on CIFAR-10 32×32; reach FID < 50 (Heusel et al. NeurIPS 2017) in ≤ 1h, single A100 (§4).
  • Establish the safetensors checkpoint contract (I12, ADR-15) before any other phase depends on it.
  • Constraint: linear β-schedule only (ADR-04 rejected alt, kept for exact DDPM-paper parity); no EMA, no guidance, no fast sampler in scope until Phase 1–3.
Deliverable
  • diffuse train --config configs/phase0_cifar.yaml runs to convergence and emits a safetensors checkpoint inspectable via diffuse ckpt inspect.
  • diffuse sample --ckpt <path> --n 16 produces a 4×4 PNG grid via the ancestral sampler.
  • diffuse eval --ckpt <path> reports FID over 50k samples.
Acceptance
  • FID < 50 on 50k CIFAR-10 samples, ancestral sampler, within ≤ 60 min wall clock, single A100 (§4).
  • Training throughput ≥ 1,200 img/s fp32 (the pre-AMP floor; bf16's 2,200 img/s target is Phase 1's).
  • Step time p50 ≤ 180 ms at batch 256, fp32 (tightens to 92 ms p50 once bf16 lands, §4).
  • Checkpoint round trip: diffuse ckpt inspect reports identical CheckpointRecord.train_config fields as written (I4 precursor).
  • Zero NaN training steps over a 10k-step smoke run (I9).
  • tests/test_schedule_identity.py: alpha_bar(t) matches the closed-form analytic value to 1e-6 (I1).
Fixtures
  • fixtures/phase0/schedule_analytic.json — 20 hand-computed (t, ᾱ_t) pairs, T=1000 linear β; expected: alpha_bar(t) within 1e-6.
  • fixtures/phase0/malformed_t_out_of_range.json — t=1000 (outside [0,1000)); expected: ScheduleError.
  • fixtures/phase0/seeded_16_grid.pt — seed=42, 16-sample ancestral grid; expected: bit-identical PNG grid on repeat run, same device class (I4).
  • fixtures/phase0/regression_fid_baseline.json — FID=48.7 at 40k training steps, seed=42; expected: FID within ±1.5 on re-run (regression gate, Phase 11).
Pitfalls
  • Sinusoidal timestep-embedding frequency mismatch — manifestation: loss plateaus above 0.05 and never drops; root cause: embedding frequency range not matching Ho et al. 2020; debug: plot embedding norm vs t; signal: train.nan_steps=0 but loss flat; recovery: match reference openai/guided-diffusion unet.py embedding formula exactly.
  • Uniform-t-sampling bias — manifestation: FID stalls ~80; root cause: uniform-over-t under-weights the high-information SNR≈1 region (§8 worked example); debug: histogram loss-per-t bucket; signal: high per-t loss variance mid-range; recovery: documented known limitation, resolved by Phase 1's loss reweighting.
  • Ancestral sampler variance explosion at low t — manifestation: salt-and-pepper noise in samples; root cause: wrong posterior variance β̃t; debug: compare against Ho et al. 2020 eq.7; signal: I13 shape check passes but FID check fails; recovery: fix β̃_t = β_t·(1-ᾱ{t-1})/(1-ᾱ_t).
  • fp32-only OOM at batch 512 — manifestation: CUDA OOM at batch_size=512; root cause: no AMP yet (Phase 1), fp32 activation memory 2× (§34); debug: torch.cuda.memory_summary(); signal: allocator OOM at step 1; recovery: cap batch_size ≤256 for Phase 0.

⬜ Phase 1 — Cosine Schedule, EMA, bf16 to FID < 20 §13

Objectives
  • Replace linear β with the cosine schedule (Nichol & Dhariwal ICML 2021), fixing the low-noise over-weighting diagnosed in Phase 0's N.6.
  • Introduce EmaState (P4, I2, ADR-08) as the default sampling-time weight source.
  • Switch to bf16 autocast (ADR-03) to hit the §4 throughput target (≥2,200 img/s) and 92ms p50 step time.
  • Reach FID < 20 on CIFAR-10, still ancestral sampling, still ε-prediction (ADR-05 pre-Phase-4 default).
  • Constraint introduced: NoiseSchedule selected by name at config time (ADR-04's versioned-by-name compatibility).
Deliverable
  • diffuse train --config configs/phase1_cosine_ema_bf16.yaml reproduces the cosine+EMA+bf16 run.
  • diffuse eval --ckpt <path> --weights ema vs --weights raw both runnable, both reported.
Acceptance
  • FID < 20 on 50k samples using EMA weights (§4 quality target this phase).
  • EMA FID improves over raw-weight FID by ≥ 3 points at the same step count (quantifies P4).
  • Training throughput ≥ 2,200 img/s bf16, batch 256, single A100 (§4, met for the first time).
  • Step time p50/p95/p99 = 92ms/110ms/145ms (§4 exact match — regression-gate input for Phase 11).
  • tests/test_ema_no_grad.py: ema_param.grad is None after every backward, 100% of sampled steps (I2).
Fixtures
  • fixtures/phase1/cosine_analytic.json — 20 hand-computed cosine ᾱ_t vs Nichol & Dhariwal 2021 eq.17; expected: match to 1e-6.
  • fixtures/phase1/ema_grad_leak.json — synthetic forced ema_param.requires_grad=True; expected: assertion caught before optimizer.step(), ema.grad_leak_count increments.
  • fixtures/phase1/seeded_ema_vs_raw.pt — seed=42, matched-step EMA/raw checkpoints; expected: EMA FID ≤ raw FID − 3.
  • fixtures/phase1/bf16_overflow_probe.json — synthetic extreme-activation batch; expected: no inf/NaN in bf16 forward (contrast fp16, N.6).
Pitfalls
  • EMA decay mis-set for step count — manifestation: EMA FID worse than raw early in training; root cause: decay=0.9999 needs ~10k+ steps to converge, applied to a <2k-step run; debug: plot EMA-vs-raw FID over steps; signal: gap negative before ~5k steps; recovery: lower decay (0.999) for short runs, documented per-run.
  • bf16 underflow in the schedule tail — flagged forward to Phase 5 N.6 (not yet triggered here since preconditioning is still DDPM-identity).
  • Warmup double-counting — manifestation: LR-warmup steps also feed EMA, corrupting the shadow copy; root cause: WARMUP exit condition wired wrong; debug: log EMA-update calls tagged by training state; signal: ema.grad_leak_count=0 but FID still degrades; recovery: gate EmaState.update() behind state == TRAINING.
  • Schedule-name drift between train and sample config — manifestation: sampler silently uses LinearSchedule against a CosineSchedule-trained checkpoint; root cause: schedule_cfg not read back from CheckpointRecord; debug: assert name equality at load; signal: FID regresses sharply with no code change; recovery: I3 rejects at load on name mismatch.
  • autocast dtype leaking into the loss reduction — manifestation: loss precision loss near convergence; root cause: forgetting to upcast before .backward(); debug: inspect loss dtype in the autograd graph; signal: FID plateaus above target despite throughput hitting target; recovery: force loss.float() before backward.

⬜ Phase 2 — Classifier-Free Guidance & Class-Conditional Sampling §14

Objectives
  • Add class-conditional training: Batch.labels (§11) consumed by the backbone.
  • Implement classifier-free guidance (Ho & Salimans 2022) via joint conditional/unconditional training (CFG-dropout).
  • Constraint: guidance is sampling-time only (P8, I7) — never baked into stored weights beyond the dropout training convention.
  • Extend GuidanceConfig (§11) from a declared-but-unused type into a live sampling-time parameter.
Deliverable
  • diffuse sample --ckpt <path> --class-id 3 --guidance-scale 4.0 produces class-conditional samples.
  • Guidance-scale sweep report (reports/phase2_cfg_sweep.json).
Acceptance
  • FID ≤ 15 at w=1 (near-Phase-1 parity — conditioning must not regress unconditional-equivalent quality).
  • FID ≤ 12 at the FID-optimal guidance scale (empirically w≈3–4).
  • CFG-dropout rate p_uncond=0.1 exactly, tests/test_cfg_dropout_rate.py within ±1% over 100k samples.
  • guidance.scale_applied fires on 100% of guided calls, 0% of w=1 calls (I7 fixture).
  • Rescale trick reduces the saturation-artifact metric (clipping fraction) by ≥ 50% at w=8 vs no-rescale (Lin et al. 2024, quantified locally).
Fixtures
  • fixtures/phase2/cfg_dropout_rate.json — 100k label draws; expected: ∅-frequency 0.10 ± 0.01.
  • fixtures/phase2/guidance_identity_w1.json — w=1 guided vs conditional-only forward; expected: bit-identical (I7).
  • fixtures/phase2/malformed_negative_scale.json — GuidanceConfig(scale=-1.0); expected: rejected, I7 recovery resets w=1.0.
  • fixtures/phase2/seeded_class3_grid.pt — seed=42, class_id=3, w=4.0; expected: bit-identical replay (I4).
  • fixtures/phase2/regression_fid_by_scale.json — FID at w∈{1,2,3,4,6,8}; expected: each within ±1.0 of baseline curve.
Pitfalls
  • CFG over-saturation at high w — manifestation: blown-out contrast/color at w≥6; root cause: guided ε diverges from the trained manifold's expected norm (Lin et al. 2024); debug: histogram output pixel values vs w; signal: clipping-fraction rises sharply; recovery: rescale trick (14.2), cap w in operator config.
  • Class-embedding leak into the unconditional branch — manifestation: w=1 output subtly differs from a genuinely unconditional model; root cause: ∅-token embedding not truly distinct; debug: I7 identity fixture; signal: fixture fails; recovery: distinct, zero-initialized ∅ embedding row.
  • p_uncond mis-set — manifestation: guidance has no effect (→0) or unconditional quality collapses (→1); debug: 14.5 dropout-rate fixture; signal: frequency outside ±1%; recovery: fix the Bernoulli draw.
  • Guidance-scale sweep cost — manifestation: eval wall-clock balloons 6×; root cause: naive per-scale full 50k-sample re-run; recovery: share sampled noise across scales (N.7).

⬜ Phase 3 — DDIM and DPM-Solver Fast Sampling §15

Objectives
  • Add deterministic fast samplers, cutting NFE from 1000 (ancestral) to 20–100 (DDIM) and 10–20 (DPM-Solver++), per §8 sampler catalogue.
  • Prove sampler hot-swappability (P2, I13) — one checkpoint, three samplers, no reload.
  • Constraint: samplers must not mutate DiffusionModel (P2); each is a fresh instance per call (I13).
Deliverable
  • diffuse sample --sampler ddim --steps 50 and --sampler dpm_solver --steps 15 both runnable against any Phase-0+ checkpoint.
  • NFE-vs-FID/latency report (reports/phase3_sampler_curve.json).
Acceptance
  • DDIM 50-step latency ≤ 210ms, batch 1, 32×32 (§4).
  • DDIM 50-step FID within 2.0 of ancestral 1000-step FID.
  • DPM-Solver++ 15-step FID within 3.0 of ancestral FID at ≥ 60× latency reduction.
  • Every sampler passes tests/test_sampler_contract.py (I13), 100% pass rate.
  • Cross-sampler portability: tests/test_sampler_hotswap.py — one checkpoint, all three samplers, zero reload (I3, P2).
Fixtures
  • fixtures/phase3/ddim_analytic_step.json — one hand-computed DDIM step vs §8 eq.; expected: match to 1e-5.
  • fixtures/phase3/sampler_contract_all.json — shape/dtype per §11 tensor table; expected: all three samplers conform.
  • fixtures/phase3/seeded_ddim50.pt — seed=42, DDIM 50-step; expected: bit-identical replay (I4).
  • fixtures/phase3/malformed_nfe_mismatch.json — DPM-Solver steps=0; expected: ScheduleError, never a silent 1-step fallback.
  • fixtures/phase3/regression_nfe_fid_curve.json — FID at NFE∈{10,15,20,50,1000}; expected: each within ±1.0 of baseline.
Pitfalls
  • DDIM's non-Markovian assumption violated by a schedule change — manifestation: output degrades sharply after a mid-experiment schedule swap; root cause: DDIM's η=0 derivation assumes the train-time ᾱ_t; debug: compare schedule_cfg between checkpoint and sampler; signal: ckpt.sampler_compat_fail; recovery: I3 rejects the mismatched load.
  • DPM-Solver instability below ~8 steps — manifestation: NaN or extreme values; root cause: local truncation error grows superlinearly at very low step counts (Lu et al. 2022 §4); debug: monitor x_t norm across steps; signal: SamplerDivergenceError; recovery: enforce a minimum-steps floor per solver order.
  • Non-uniform t-subsequence off-by-one — manifestation: first/last DDIM step skips t=0 or t=T; root cause: linspace instead of the paper's exact index formula; debug: unit-test against Song, Meng & Ermon 2021 Appendix; signal: 15.5 analytic fixture fails; recovery: fix index generation.
  • Shared trajectory buffer across concurrent calls — manifestation: two concurrent sample() calls corrupt each other's x_t; root cause: a Sampler instance reused across calls, violating I13; debug: concurrency stress test; signal: intermittent contract-fixture failure; recovery: fresh Sampler() per call at the CLI/API boundary.

⬜ Phase 4 — v-Prediction and the Zero-SNR Fix §16

Objectives
  • Switch default prediction target from ε to v (Salimans & Ho ICLR 2022, ADR-05), addressing ε-prediction instability at high noise.
  • Fix terminal-SNR leakage (Lin et al. WACV 2024) via a zero-SNR schedule variant.
  • Constraint: prediction target is a config axis only (P6) — the Phase 0 U-Net is reused unchanged, only the conversion layer (§8 identities) changes.
Deliverable
  • diffuse train --config configs/phase4_vpred_zerosnr.yaml trains v-prediction under zero-SNR.
  • Brightness-histogram diagnostic (reports/phase4_terminal_snr.json).
Acceptance
  • FID ≤ 12 under v-prediction + zero-SNR, matching or beating Phase 1's FID<20 baseline.
  • Zero-SNR histogram reaches full dynamic range (min/max within 2% of [-1,1]) vs non-zero-SNR's ≥15%-compressed washout (Lin et al. 2024).
  • tests/test_prediction_conversion.py: ε→v→ε and x0→v→x0 round trips match to 1e-6 (§8).
  • Zero NaN over a 10k-step v-prediction bf16 smoke run (I9).
  • No sampler-specific subclass added this phase — verified by a repo-structure check (P6 enforcement, machine-checkable).
Fixtures
  • fixtures/phase4/conversion_roundtrip.json — 50 (x_0, ε, t) triples; expected: round trip within 1e-6.
  • fixtures/phase4/zero_snr_terminal.json — ᾱ_T for zero-SNR; expected: exactly 0.0 (vs cosine's ~1e-3, §8 table).
  • fixtures/phase4/seeded_vpred_grid.pt — seed=42, v-pred + zero-SNR, ancestral; expected: bit-identical replay (I4).
  • fixtures/phase4/malformed_target_mismatch.json — ε-pred checkpoint sampled as v-pred; expected: PreconditionMismatchError (I3).
  • fixtures/phase4/regression_brightness_histogram.json — baseline histogram both schedules; expected: within ±3% bucket-mass.
Pitfalls
  • ε-prediction instability at high σ — manifestation: intermittent loss spikes late in training even under bf16; root cause: poor SNR at high noise amplifies backbone error (Salimans & Ho 2022 §2); debug: bucket loss by t; signal: train.nan_steps concentrated at high t; recovery: switch to v-prediction (this phase's motivating fix, ADR-05).
  • Terminal-SNR leakage washing out samples — manifestation: unconditional samples trend to mid-gray, never reach true black/white; root cause: nonzero ᾱ_T means the model never trains on truly pure-noise input, a train/inference mismatch (Lin et al. 2024); debug: 16.5 histogram fixture; signal: compressed histogram vs zero-SNR baseline; recovery: ZeroSNRSchedule.
  • v-conversion sign error — manifestation: samples degrade to pure noise immediately; root cause: v := α_t·ε − σ_t·x_0 sign flipped; debug: 16.5 round-trip fixture fails; recovery: fix sign per §8, re-verify.
  • Reusing an ε-pred checkpoint's EMA state under a v-pred config — manifestation: FID far worse than either target's baseline; root cause: EmaState load not checked against prediction_target; debug: compare CheckpointRecord.train_config.prediction_target at load; recovery: extend I3's compatibility check to include prediction target.

⬜ Phase 5 — EDM Preconditioning and the Heun Sampler §17

Objectives
  • Replace DDPM-identity preconditioning with the full EDM table (§8, Karras et al. NeurIPS 2022).
  • Implement the 2nd-order Heun sampler (Karras et al. 2022 Algorithm 1).
  • Constraint: σ-space replaces t-space as the primary schedule axis; I6's finite-c_skip/c_out/c_in guard becomes load-bearing for the first time.
Deliverable
  • diffuse train --config configs/phase5_edm.yaml trains under full EDM preconditioning.
  • diffuse sample --sampler heun --steps 30 produces EDM-preconditioned samples.
  • Preconditioning comparison report (reports/phase5_edm_vs_vpred.json).
Acceptance
  • FID ≤ 8 under EDM + Heun 30-step sampling (approaching the Phase-11 FID<10 target early).
  • Heun 30-step latency ≤ 260ms batch-1, 32×32.
  • I6 guard: zero false negatives over a 1M-sample σ-sweep, precond.nan_count=0.
  • tests/test_edm_identity.py: c_skip/c_out/c_in/c_noise match §8 to 1e-6 across 50 sampled σ.
  • σ_data recomputed per-dataset, verified by a config-diff test vs the paper's ImageNet constant.
Fixtures
  • fixtures/phase5/edm_table_analytic.json — 50 (σ,c_skip,c_out,c_in,c_noise) tuples; expected: match §8 to 1e-6.
  • fixtures/phase5/precond_nan_guard.json — σ sweep incl. σ=0, σ=1e-9; expected: I6 clamps, zero NaN/Inf.
  • fixtures/phase5/heun_analytic_step.json — one hand-computed Heun step; expected: match Algorithm 1 to 1e-5.
  • fixtures/phase5/seeded_heun30.pt — seed=42, Heun 30-step; expected: bit-identical replay (I4).
  • fixtures/phase5/regression_fid_edm.json — FID=7.6 baseline; expected: within ±1.0 on re-run.
Pitfalls
  • σ→0 division by zero in c_noise — manifestation: log(0)=-inf propagates into the noise conditioning; root cause: sampler's final step approaches σ=0 unfloored; debug: log σ across last 3 steps; signal: precond.nan_count>0; recovery: I6's clamp to σ_min=0.002.
  • Copying the paper's ImageNet σ_data uncritically — manifestation: FID plateaus 5–10 points worse than expected; root cause: σ_data is per-dataset empirical, not universal (NVlabs/edm pitfall); debug: compute CIFAR-10's actual pixel std vs the hardcoded constant; recovery: recompute σ_data from the training set.
  • bf16 overflow in c_out(σ) at σ=80 — manifestation: precond.nan_count spikes at high-σ steps under bf16, absent under fp32; root cause: bf16 mantissa precision loss on the σ·σ_data product; debug: cast the probe to fp32; recovery: compute preconditioning coefficients in fp32 even when the backbone runs bf16.
  • Heun's 2nd evaluation missing re-applied c_in — manifestation: Heun FID worse than a 1st-order-equivalent sampler; root cause: predictor output fed to the corrector without re-preconditioning; debug: 17.5 analytic-step fixture; recovery: apply full preconditioning at both predictor and corrector evaluations.

⬜ Phase 6 — VAE and Latent Diffusion §18

Objectives
  • Introduce AutoencoderKL (§11, Rombach et al. CVPR 2022) — f=8 KL-regularized VAE, enabling latent-space diffusion.
  • Establish the versioned scale-factor contract (P9, I8) before any latent training begins.
  • Move the training target from CIFAR-10 32×32 to 256×256 pixel / 32×32 latent, unlocking the memory reduction quantified in §34.
  • Constraint: VAE is frozen and read-only once training starts (§11) — no joint VAE+diffusion training in scope.
Deliverable
  • diffuse train --config configs/phase6_latent.yaml trains a latent U-Net against a pretrained, frozen VAE.
  • diffuse sample --ckpt <path> decodes latents to pixels via the pinned VAE.
  • VAE round-trip calibration report (reports/phase6_scale_factor.json).
Acceptance
  • VAE round-trip reconstruction PSNR ≥ 24 dB on held-out validation images.
  • Latent std within 5% of 1.0 post-scale-factor calibration (I8's exact threshold).
  • GPU memory ceiling, 256×256 latent (64×64 lat.), training ≤ 24 GB (§4).
  • FID ≤ 10 on decoded 256×256 samples at matched compute to Phase 5's pixel-space budget.
  • tests/test_vae_scale_drift.py: a checkpoint whose vae_ref scale factor differs from the loaded VAE's by >5% raises PreconditionMismatchError, 100% detection over 20 synthetic fixtures (I8).
Fixtures
  • fixtures/phase6/vae_roundtrip.json — 50 validation images; expected: PSNR ≥ 24 dB each.
  • fixtures/phase6/scale_factor_calibration.json — computed factor on a fixed 10k-image sample; expected: within ±0.005 of the recorded baseline.
  • fixtures/phase6/malformed_scale_mismatch.json — vae_ref.scale_factor=0.15 vs a 0.182-calibrated VAE; expected: PreconditionMismatchError (I8).
  • fixtures/phase6/seeded_latent_grid.pt — seed=42, latent sampling + decode; expected: bit-identical replay (I4).
  • fixtures/phase6/regression_fid_latent.json — FID baseline decoded 256×256; expected: within ±1.5.
Pitfalls
  • VAE scale-factor mismatch — manifestation: FID degrades 5–15 points with no visible code bug (P9); root cause: diffusion model trained against one scale factor, sampled against a differently-calibrated VAE; debug: 18.5 malformed-mismatch fixture, compare vae_ref fields; signal: vae.scale_drift (I8); recovery: recompute + persist the new scale factor, block latent training until resolved.
  • VAE encode accidentally differentiable (freeze not applied) — manifestation: VAE parameters show nonzero gradients; root cause: missing requires_grad_(False)/no_grad() boundary; debug: assert zero trainable VAE params before each train_step; recovery: enforce the freeze at construction (mirrors I11's text-encoder freeze, reused in Phase 7).
  • FID computed in latent space instead of pixel space — manifestation: implausible FID numbers that don't correlate with visual quality; root cause: forgetting the VAE-decode step before InceptionV3; debug: inspect the eval pipeline's tensor shape before feature extraction; recovery: hard-code the decode step, not an optional flag.
  • Stale pre-encoded latent cache after a VAE re-calibration — manifestation: training silently uses latents under an old scale factor; root cause: offline cache not invalidated; debug: compare cache timestamp vs VAE checkpoint id; recovery: key the cache by VAE id + scale factor.

⬜ Phase 7 — Text Conditioning §19

Objectives
  • Add frozen CLIP text-tower conditioning (ADR-12) via cross-attention (P12) into the latent U-Net from Phase 6.
  • Enable prompt-driven generation, the first point in the capability arc where a text string drives sampling.
  • Constraint: text encoder weights frozen during diffusion training (I11) — no joint fine-tuning in scope.
Deliverable
  • diffuse sample --ckpt <path> --prompt "a photo of a red bicycle" --guidance-scale 7.5.
  • EvalReport reports both FID and CLIP score for the first time.
Acceptance
  • CLIP score ≥ 0.28 (ViT-B/32 cosine similarity) over a 5k-prompt held-out set.
  • FID ≤ 12 on decoded text-conditional samples (a bounded, quantified regression vs Phase 6's class-conditional FID<10).
  • Zero trainable CLIP parameters at every training step (I11, 100% of sampled steps).
  • Text-CFG dropout rate within ±1% of configured p_uncond (mirrors 14.4).
  • tests/test_dual_conditioning.py: class + text guidance apply simultaneously with no code fork (P12 composability made concrete).
Fixtures
  • fixtures/phase7/clip_freeze_check.json — per-step trainable-param count for the CLIP tower; expected: 0 at every step (I11).
  • fixtures/phase7/text_cfg_dropout_rate.json — 100k caption draws; expected: null-frequency within ±1%.
  • fixtures/phase7/malformed_empty_prompt.json — empty-string prompt; expected: falls back to the null embedding cleanly, no tokenizer crash.
  • fixtures/phase7/seeded_prompt_grid.pt — seed=42, fixed prompt, w=7.5; expected: bit-identical replay (I4).
  • fixtures/phase7/regression_clip_fid.json — baseline CLIP score + FID; expected: CLIP within ±0.01, FID within ±1.5.
Pitfalls
  • Accidental CLIP fine-tuning — manifestation: embeddings drift over training; root cause: requires_grad_(False) applied to the wrong module scope; debug: enumerate all CLIP submodules and assert zero-grad on each; signal: 19.5's freeze-check fails partway through a run, not just at step 0; recovery: apply the freeze recursively, add to the training loop's periodic invariant sweep.
  • Pixel-concatenated text conditioning creeping in — manifestation: input channel count silently changes, breaking checkpoint compatibility; root cause: a "just concat the embedding" shortcut instead of cross-attention; debug: diff backbone input channels vs §11; signal: I3's architecture-id check fails when loading a Phase-6 checkpoint; recovery: P12's explicit cross-attention-only rule.
  • CLIP tokenizer truncation silently dropping content — manifestation: long prompts ignore described tail content; root cause: CLIP BPE's fixed 77-token context (ADR-13); debug: log token count vs prompt length; recovery: document the 77-token ceiling in CLI help and EvalReport, never silently truncate without visibility.
  • Text- and class-CFG dropout draws correlated — manifestation: 19.4's dual-conditioning test fails intermittently; root cause: shared RNG stream for both dropout decisions; debug: check RNG call sequence; recovery: separate RNG streams per conditioning axis (I4 discipline).

⬜ Phase 8 — DiT Backbone §20

Objectives
  • Swap the convolutional U-Net for a transformer denoiser, DiTBackbone (§11, Peebles & Xie ICCV 2023), proving P7's backbone-agnostic training-loop claim at scale.
  • Adopt FlashAttention (Dao et al. NeurIPS 2022, ADR-07) now that token counts justify it (deferred from Phase 0 per ADR-07).
  • Constraint: diffuse.train must touch zero lines to support this swap (P7) — verified structurally, not just functionally.
Deliverable
  • diffuse train --config configs/phase8_dit_b.yaml and configs/phase8_dit_xl.yaml both train against diffuse/train/loop.py with zero modification.
  • Scaling-law report (reports/phase8_dit_scaling.json).
Acceptance
  • Training throughput ≥ 340 img/s bf16, DiT-B, 256×256 latent, single A100 (§4).
  • GPU memory ceiling: DiT-B batch 64 bf16 ≤ 24 GB; DiT-XL batch 32 bf16 ≤ 55 GB (§4).
  • FID ≤ 9 at matched compute to Phase 6's U-Net latent baseline.

⬜ Phase 9 — Progressive Distillation to 10 NFE §21

Objectives
  • Halve sampler NFE per distillation round against a frozen teacher trajectory (Salimans & Ho ICLR 2022, P11), from a ~1000-NFE-equivalent teacher toward 10 NFE.
  • Constraint: distillation targets a teacher trajectory, never an invented objective (P11) — each student matches the teacher's N-step ODE output with an N/2-step approximation.
  • Precondition: the teacher must already pass its own FID gate (Phase 8 N.4) before any round begins (I10).
Deliverable
  • diffuse distill --teacher <ckpt> --rounds 7 runs the full halving chain to 10 NFE.
  • Distillation lineage report (reports/phase9_distillation_lineage.json).
Acceptance
  • Final-round (10 NFE) FID ≤ 15 (bounded, quantified cost vs the Phase 8 teacher's FID≤9).
  • Each round's NFE exactly half its teacher's, I10 verified over 100% of rounds (distill.nfe_ratio=0.5 ± 0).
  • Distillation wall clock ≤ 45 min per round on single A100 at DiT-B scale.
  • tests/test_distillation_lineage.py: 0 orphaned/misattributed rounds over a 7-round chain.
  • FID-vs-NFE curve monotonically non-decreasing as NFE decreases (a sanity property per P3).
Fixtures
  • fixtures/phase9/nfe_halving_contract.json — 7-round NFE sequence; expected: exact halving (1280→640→...→10).

  • fixtures/phase9/malformed_wrong_teacher.json — teacher that failed its own FID gate; expected: rejected at round-config validation (P11).
  • fixtures/phase9/seeded_10nfe_grid.pt — seed=42, final 10-NFE student; expected: bit-identical replay (I4).
  • fixtures/phase9/regression_fid_vs_nfe_curve.json — FID at each round's NFE; expected: each within ±1.5, monotonic.
Pitfalls
  • Distilling before the teacher passes its own gate — manifestation: the chain compounds an already-bad teacher's error; root cause: P11's violation directly; debug: check the teacher's recorded FID against Phase 8's N.4 before round 1; signal: 21.5's malformed-wrong-teacher fixture; recovery: hard-gate round-1 construction on a validated teacher FID.
  • NFE-ratio drift (student trained at teacher's full step count) — manifestation: no speedup observed; root cause: round-config bug; debug: I10's assertion; signal: assertion failure at construction; recovery: reject the round config, require explicit override.
  • Lineage misattribution across parallel distillation experiments — manifestation: a round's parent reference is wrong when chains run concurrently; root cause: shared checkpoint-id namespace; debug: 21.5's lineage-chain fixture; recovery: namespace by chain-id + round number.

⬜ Phase 10 — Multi-GPU Scale-Out and Throughput §22

Objectives
  • Scale training from single-GPU (Phase 0–9) to single-node multi-GPU via DDP (ADR-16) and, for DiT-XL, FSDP for optimizer-state sharding.
  • Keep the EMA shadow copy exactly synchronized across ranks (P4/I2's concurrency note, now load-bearing under real multi-rank execution).
  • Constraint: single-node only in scope — multi-node (>1 host) training is PhaseDeferred("Deferred Features Register").
Deliverable

Acceptance
  • Aggregate throughput scaling efficiency ≥ 85% at 8 GPUs vs single-GPU baseline (≥6.8× img/s).
  • EMA consistency: all ranks bit-identical after each synchronized update, 100% of sampled steps (tests/test_ema_ddp_sync.py).
  • FSDP DiT-XL stays within the 55GB per-GPU ceiling (§4) at the configured batch size.
  • Zero corrupted/partial checkpoint files over 100 synchronized write events (I12).
  • Gradient all-reduce overhead ≤ 15% of total step time at 8 GPUs.
Fixtures
  • fixtures/phase10/ema_ddp_sync.json — simulated 4-rank EMA update; expected: bit-identical shadow copies post-broadcast across all ranks.

Pitfalls
  • EMA divergence across ranks — manifestation: sampling from rank 0's EMA vs rank 3's EMA gives different outputs; root cause: EMA update computed locally per-rank instead of a true rank-0-aggregate-then-broadcast; debug: 22.5's sync fixture, compare shadow-copy hashes; signal: tests/test_ema_ddp_sync.py failure; recovery: enforce single-writer-then-broadcast explicitly (P4/I2's concurrency note made concrete under real multi-rank execution).

  • Rank-0-only checkpoint write race under a crash mid-write — manifestation: a torn checkpoint loaded by RESUMING (§8); root cause: missing atomic fsync/rename before releasing the barrier; debug: injected crash-during-write fault (Testing & Verification Strategy); signal: CheckpointCorruptionError (I12) on resume; recovery: write-to-temp, fsync, rename before releasing other ranks.
  • FSDP sharding boundary splitting a normalization layer incorrectly — manifestation: DiT-XL produces NaN losses specific to the FSDP config, absent under single-GPU DDP; root cause: the auto-wrap policy shards a norm layer's parameters, breaking its statistics; debug: compare FSDP vs single-GPU loss curves at matched steps on a small model; recovery: adjust the auto-wrap policy to keep normalization-layer parameters unsharded.
