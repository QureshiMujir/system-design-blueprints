121 — Diffusion Model from Scratch

Project Number: 121

Project Name: Diffusion Model from Scratch

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

Build, in Python 3.11 + PyTorch 2.x, a denoising diffusion generative-model system starting from the closed-form Gaussian forward-process math up to a working text-to-image latent diffusion pipeline with fast few-step sampling. The system trains and samples image generators across an explicit capability arc: unconditional 32×32 CIFAR-10 DDPM (Sohl-Dickstein et al. ICML 2015; Ho et al. NeurIPS 2020) to FID < 10 (Heusel et al. NeurIPS 2017) on a single A100 in under 12h, then layers cosine schedule + EMA + v-prediction + EDM preconditioning (Karras et al. NeurIPS 2022) + classifier-free guidance (Ho & Salimans 2022) + DDIM (Song, Meng & Ermon ICLR 2021) / DPM-Solver (Lu et al. NeurIPS 2022) fast sampling + VAE latent space (Rombach et al. CVPR 2022) + text conditioning + DiT backbone (Peebles & Xie ICCV 2023) + progressive distillation (Salimans & Ho ICLR 2022) — until the same codebase produces a 256×256 class-conditional ImageNet sample in 10 NFE and a 512×512 latent text-conditional sample.

Phase-0 deliverable, numbered packages:

  1. diffuse.schedules — noise schedule catalogue (linear, cosine, zero-SNR, EDM σ-space).
  2. diffuse.precond — Preconditioning interface unifying DDPM/score-SDE/EDM.
  3. diffuse.backbones — U-Net denoiser backbone (DiT deferred to Phase 8).
  4. diffuse.train — training loop + EMA manager.
  5. diffuse.samplers — ancestral sampler (DDIM/DPM-Solver/Heun deferred to Phase 3/5).
  6. diffuse.eval — FID harness (50k-sample, InceptionV3 features).
  7. diffuse.ckpt — safetensors checkpoint store.
  8. diffuse.cli — train / sample / eval entrypoints.

Boundaries: provides — training loop, sampler registry, eval harness, checkpoint format, distributed launcher. Delegates — GPU driver/CUDA runtime (vendor), object storage (S3-compatible, operator-provisioned), experiment-tracking UI (W&B/TensorBoard, optional). Does NOT provide — dataset licensing/curation, content moderation beyond a documented hook point (Threat Model T4), a production inference/serving API gateway.

Non-goals: not a general ML framework (built atop PyTorch, not replacing it); not a from-scratch autograd/tensor library (Autograd-Engine is a sibling project, referenced not duplicated); not a multi-tenant production inference server (no request batching, no autoscaling — a separate later system).

Deployment model: single-node single-GPU for Phase 0–5; single-node multi-GPU (DDP/FSDP) for Phase 6 onward; checkpoints portable to a single-GPU inference host. Users/operators: ML research engineers running training jobs, and operators running batch sampling/eval jobs from checkpoints; no interactive multi-tenant serving in scope (PhaseDeferred("Deferred Features Register")).

What later phases unlock: Phase 6 unlocks latent-space training (4–8× memory reduction via VAE downsampling); Phase 7 unlocks prompt-driven generation; Phase 8 unlocks transformer-backbone scaling laws; Phase 9 unlocks real-time-adjacent sampling (10 NFE); Phase 10 unlocks dataset sizes beyond single-GPU memory; Phase 11 unlocks CI-gated regression detection.

Language: Python 3.11 + PyTorch 2.x. Rationale — PyTorch owns the reference-checkpoint ecosystem for every cited paper (NVlabs/edm, openai/guided-diffusion, CompVis/latent-diffusion, facebookresearch/DiT, huggingface/diffusers are all PyTorch), enabling differential testing against ground truth (Testing & Verification Strategy); torch.compile + AMP give competitive throughput with no hand-written kernels; the Python ecosystem (safetensors, einops, timm) covers every remaining need. Rejected: JAX — faster XLA fusion and native pmap for TPU pods, but no equivalent-fidelity reference checkpoints exist for the cited papers, forcing re-derivation of numerics instead of differential testing; rejected because the calibration goal (§2) is bit-level parity with published work, not raw throughput. Rejected: C++/LibTorch — inference-only, no training ergonomics, wrong scope. Rejected: Julia/Flux.jl — smaller ecosystem, no FlashAttention-equivalent fused kernel.

Prerequisites: Gaussian conditionals, KL divergence, change-of-variables calculus; SDE/ODE intuition (not full measure theory); CNN/transformer architecture familiarity; PyTorch autograd, nn.Module, AMP; distributed data-parallel basics.

Timeline: Phase 0 — 1 week (repo skeleton, closed-form forward process, U-Net, ancestral sampler). Full system (Phase 0–11) — 5–6 months at one engineer full time, given ≥1 A100-class GPU for Phase 0–5 and ≥4 for Phase 6+.

Deferrals: PhaseDeferred("Deferred Features Register") for an interactive serving API, a content-safety classifier beyond the documented hook, non-CUDA accelerator backends (ROCm/TPU), video-diffusion extension, audio-diffusion extension, multi-node (>1 host) training beyond Phase 10's single-host multi-GPU scope, and single-step consistency-model training (only distillation to 10 NFE is in scope — see Alternative Architectures).

2. Why Build This

  • probabilistic generative modeling — forward/reverse Markov chains, ELBO, score matching
  • SDE/ODE duality of diffusion — stochastic and deterministic samplers from one process
  • numerical stability across extreme dynamic range — SNR spans ~9 orders of magnitude in t
  • preconditioning as an abstraction discipline — one interface, three historical formulations
  • perceptual/latent representation learning — VAE bottleneck, scale-factor calibration
  • attention-based conditioning — cross-attention text injection, classifier-free guidance
  • distillation as compression-of-computation — trading sample quality for NFE
  • distributed training mechanics — DDP/FSDP gradient sync, EMA shadow-copy consistency
  • rigorous quantitative evaluation — FID/CLIP as the only acceptance currency, never a vibe
  • calibration against a live research field — every choice traceable to a named paper/year

Architecturally this is the generative-modeling analogue of Autograd-Engine (compute-graph mechanics) crossed with BLAS Linear Algebra Runtime (throughput-bound kernels) crossed with Approximate Nearest Neighbor Index (large-batch numerical pipelines) — it teaches how one mathematical object (a denoiser) becomes, through reparameterization and conditioning, an entire generative-modeling product line.

What Mastery Looks Like

  • derive the DDPM ELBO and simplified loss from the forward process, and explain why the simplification is a reweighting, not a hack (Phase 1).
  • explain from the EDM preconditioning table why c_skip/c_out/c_in solve a variance-normalization system, not arbitrary constants (Phase 5).
  • reason about classifier-free guidance as an implicit classifier gradient without a classifier, and predict its over-saturation failure mode (Phase 2).
  • explain why zero-SNR terminal timesteps are required for correct unconditional generation, and reproduce the schedule fix (Phase 4).
  • convert a checkpoint between ε/x0/v prediction targets and state when each is numerically preferable (Phase 4, Phase 5).
  • distill a 1000-step teacher to a 10-step student and articulate the quality/speed tradeoff curve (Phase 9).
  • scale a training job across GPUs while keeping the EMA shadow copy exactly synchronized (Phase 10).
  • design and defend a 50k-sample FID eval harness other engineers can trust as a promotion gate (Phase 11).

Data Pipeline — loads CIFAR-10/ImageNet-1k/LAION shards, applies augmentation, yields Batch records; owns dataset-boundary trust (Threat Model T3).

Noise Schedule — pure query interface over t/σ; produces ᾱ_t/σ_t for any timestep in O(1); never simulates the chain stepwise (P5, P14).

Preconditioning — collapses DDPM/score-SDE/EDM into one c_skip/c_out/c_in/c_noise object wrapping the raw network output (P1).

Denoiser Backbones — U-Net (Phase 0) and DiT (Phase 8) implement one DenoiserBackbone protocol; the training loop is backbone-agnostic (P7).

Training Loop — AMP-mixed-precision train_step, gradient sync under DDP/FSDP, loss/grad-norm guards (I9).

EMA Manager — read-only exponential-average shadow copy of weights, never trained (P4, I2).

Sampler Registry — ancestral/DDIM/DPM-Solver/Heun, each a hot-swappable Sampler touching only its own trajectory state (P2).

Guidance Module — applies the CFG interpolation at sampling time only (P8).

VAE Encoder/Decoder — f=8 KL-regularized autoencoder producing the versioned latent contract (P9) consumed by Phase 6+.

Text Encoder — frozen CLIP tower (I11) supplying cross-attention conditioning tokens (P12) to the backbone.

Eval Harness — computes FID (Heusel et al. 2017) and CLIP score over 50k samples; the only acceptance currency (P3).

Distillation Pipeline — halves sampler NFE per round against a frozen teacher trajectory (P11).

Checkpoint Store — safetensors-only persistence (P13, I12) referenced by every other box; carries the VAE/text-encoder version pins (P9).

6. Design Principles

P1 — One preconditioning interface, three formulations collapse. Preconditioning unifies DDPM/score-SDE/EDM behind (c_skip, c_out, c_in, c_noise). Tradeoff: one extra indirection per forward call. Operational implication: switching parameterization is a config change, not a rewrite. Violation: hardcoding ε-prediction math in the backbone forces a second backbone class for v-prediction (Phase 4) — doubled maintenance, drift.

P2 — Samplers are hot-swappable and never touch model weights. Sampler receives a frozen DiffusionModel handle, mutates only its own trajectory state. Tradeoff: no in-the-loop fine-tuning. Operational implication: one checkpoint serves ancestral/DDIM/DPM-Solver/Heun with no reload. Violation: a sampler that mutates the model object breaks I3 and leaks state across samplers.

P3 — Every number is an FID or a step time, never a vibe. Every N.4 acceptance criterion is numeric. Tradeoff: slower phase sign-off (must run eval, not eyeball). Gain: CI-automatable promotion gates (Phase 11). Violation: "samples look good" hides regressions until a downstream phase fails loudly.

P4 — EMA weights are a read-only shadow, never trained. EmaState updates by exponential average only; the optimizer never sees EMA parameters. Tradeoff: a full extra parameter copy in memory (M8). Gain: sampling always defaults to EMA (ADR-08). Violation: backpropagating through EMA parameters irreversibly corrupts the shadow copy (I2, FM-3).

P5 — The forward process is a pure function of t, never simulated stepwise. q(x_t|x_0) is closed-form (§8); never chain single-step corruptions. Tradeoff: none — closed form is strictly cheaper. Gain: training samples any t in O(1). Violation: stepwise simulation costs O(t) per sample and compounds float error (I1).

P6 — Prediction target is a config axis, not an architecture fork. ε/x0/v/EDM targets are conversions of one network output (§8), not four backbones. Tradeoff: a small conversion layer at loss/sampling time. Gain: switching ε→v (Phase 4) reuses the Phase 0 U-Net unchanged. Violation: a v-prediction-specific subclass duplicates UNetBackbone, breaking terminology lock.

P7 — The training loop is backbone-agnostic. train_step depends only on the DenoiserBackbone protocol. Tradeoff: the protocol must cover both conv and transformer conditioning paths. Gain: Phase 8's DiT swap-in touches zero lines of diffuse.train. Violation: an isinstance branch on backbone type couples Phase 8 to Phase 0 internals.

P8 — Guidance is a sampling-time decision. GuidanceConfig is read by the sampler, never baked into stored weights beyond the CFG-dropout training convention (I7). Tradeoff: every sampling call must supply a scale. Gain: guidance-scale sweeps (Phase 2 N.5) need no retraining. Violation: a hardcoded guidance scale forces a retrain per desired scale.

P9 — The latent-space contract is versioned, not assumed. Every latent tensor carries the VAE checkpoint id + scale factor it was produced under (CheckpointRecord.vae_ref). Tradeoff: extra metadata per latent batch. Gain: mismatched VAE/diffusion pairs fail loudly at load. Violation: an unversioned latent silently degrades FID by 5–15 points (ref-impl 3 pitfall).

P10 — Determinism is a first-class config knob. Seed + sampler + checkpoint + device class reproduces bit-identical output (I4); RNG state is explicit, never ambient. Tradeoff: some fused nondeterministic CUDA kernels must be disabled (perf cost, M-table). Gain: regression tests (Phase 11) run in deterministic mode. Violation: ambient global RNG makes replay-based regression testing impossible.

P11 — Distillation targets a teacher trajectory, not an invented objective. Each progressive-distillation round (Phase 9) halves NFE by matching the teacher's N-step ODE output with an N/2-step student (Salimans & Ho ICLR 2022). Tradeoff: distillation quality is bounded above by teacher quality. Gain: distillation is a post-hoc compression phase. Violation: distilling before the teacher passes its own FID gate (Phase 8 N.4) compounds undetected teacher error into the student.

P12 — Text conditioning is injected via cross-attention, never pixel-concatenation. Text embeddings enter as cross-attention keys/values (Phase 7). Tradeoff: an extra attention block per denoiser layer. Gain: composes cleanly with class-conditioning. Violation: pixel-concatenated text conditioning couples input channels to embedding dimension, breaking every earlier phase's tensor contract (§11).

P13 — A checkpoint's format is inspectable without executing it. Checkpoints are safetensors, never pickle. Tradeoff: optimizer state needs explicit flattening (safetensors cannot serialize arbitrary Python objects). Gain: a downloaded checkpoint cannot achieve remote code execution (T2). Violation: a pickle-based loader is an automatic deserialization RCE surface (T2, FM-9).

P14 — Every schedule is queried, never iterated to build. NoiseSchedule.alpha_bar(t) is an O(1) closed-form query (P5's sibling); never walk t=0..T to answer a query at one t. Tradeoff: closed-form derivation must be re-verified per new schedule (Phase 4 zero-SNR fix). Gain: sampler step cost is independent of T. Violation: an iterative schedule makes DPM-Solver's non-uniform t-selection (Phase 3) O(T) per step instead of O(1).

8. Domain Model

Forward process (Sohl-Dickstein et al. 2015; Ho et al. 2020):

q(x_t | x_{t-1}) = N(x_t; sqrt(1-β_t)·x_{t-1}, β_t·I)

Closed-form reparameterization (I1). Let α_t = 1-β_t, ᾱ_t = ∏_{s=1..t} α_s:

q(x_t | x_0) = N(x_t; sqrt(ᾱ_t)·x_0, (1-ᾱ_t)·I) x_t = sqrt(ᾱ_t)·x_0 + sqrt(1-ᾱ_t)·ε, ε ~ N(0,I)

ELBO (Ho et al. 2020, via Sohl-Dickstein et al. 2015):

L = E_q[ D_KL(q(x_T|x_0) ‖ p(x_T)) + Σ_{t>1} D_KL(q(x_{t-1}|x_t,x_0) ‖ p_θ(x_{t-1}|x_t)) − log p_θ(x_0|x_1) ]

Simplified training loss (Ho et al. 2020, eq. 14):

L_simple(θ) = E_{t,x_0,ε}[ ‖ε − ε_θ(x_t,t)‖² ]

Prediction-target conversion identities. Let α_t = sqrt(ᾱ_t), σ_t = sqrt(1-ᾱ_t) (note x_t = α_t·x_0 + σ_t·ε):

  • ε-pred: network outputs ε_θ(x_t,t) directly.
  • x0-pred: x̂_0 = (x_t − σ_t·ε_θ) / α_t.
  • v-pred (Salimans & Ho 2022): v := α_t·ε − σ_t·x_0; recover x_0 = α_t·x_t − σ_t·v, ε = σ_t·x_t + α_t·v.
  • EDM (Karras et al. 2022): denoiser D_θ(x;σ) = c_skip(σ)·x + c_out(σ)·F_θ(c_in(σ)·x; c_noise(σ)).

EDM preconditioning table (σ_data = per-dataset empirical std, ADR-06 note):

Term Formula
c_skip(σ) σ_data² / (σ² + σ_data²)
c_out(σ) σ·σ_data / sqrt(σ² + σ_data²)
c_in(σ) 1 / sqrt(σ² + σ_data²)
c_noise(σ) (1/4)·ln(σ)

CFG interpolation (Ho & Salimans 2022):

ε̃_θ(x_t,t,c) = ε_θ(x_t,t,∅) + w·( ε_θ(x_t,t,c) − ε_θ(x_t,t,∅) )

(w=1 → conditional-only, no amplification; w>1 → amplified guidance; w=0 → unconditional; I7 governs where w is applied.)

DDIM update, deterministic η=0 (Song, Meng, Ermon 2021, eq. 12):

x_{t-1} = sqrt(ᾱ_{t-1})·x̂_0(x_t) + sqrt(1-ᾱ_{t-1})·ε_θ(x_t,t), where x̂_0(x_t) = (x_t − sqrt(1-ᾱ_t)·ε_θ(x_t,t)) / sqrt(ᾱ_t).

Worked numeric example (cosine schedule, T=1000, t=500): per Nichol & Dhariwal 2021, ᾱ_500 ≈ 0.399. Given x_0 with per-pixel value 0.6 (in [-1,1]) and drawn ε=0.2: x_500 = sqrt(0.399)·0.6 + sqrt(0.601)·0.2 ≈ 0.632·0.6 + 0.775·0.2 ≈ 0.379 + 0.155 = 0.534. SNR(t=500) = 0.399/0.601 ≈ 0.664 — near the schedule's SNR=1 crossover, the highest- information training region (Karras et al. 2022 §3.1 loss-weighting motivation).

Malformed-input examples: t outside [0,T) → ScheduleError; NaN in Batch.images → rejected at data-pipeline boundary, never reaches train_step (I9's upstream guard); Batch.images.shape[0] != Batch.labels.shape[0] → shape-contract AssertionError at Batch construction, never silently broadcast.

Failure-path example: σ→0 (numerical underflow near sampler's final step) drives c_noise(σ) = 0.25·ln(σ) → -inf; guarded by I6's clamp to σ_min=0.002, converting an undefined log(0) into a bounded, tested edge value (Phase 5 N.8).

12.1 Objectives

  • Stand up diffuse.schedules/precond/backbones.unet/train.loop/samplers.ancestral/eval.fid/ ckpt/cli as a runnable vertical slice (§1 Phase-0 deliverable list).
  • Prove the closed-form forward process (§8 q(x_t|x_0)) and ε-prediction loss end to end on CIFAR-10 32×32; reach FID < 50 (Heusel et al. NeurIPS 2017) in ≤ 1h, single A100 (§4).
  • Establish the safetensors checkpoint contract (I12, ADR-15) before any other phase depends on it.
  • Constraint: linear β-schedule only (ADR-04 rejected alt, kept for exact DDPM-paper parity); no EMA, no guidance, no fast sampler in scope until Phase 1–3.

12.2 Detailed Implementation Steps

  • diffuse/schedules/linear.py: LinearSchedule(NoiseSchedule) — closed-form alpha_bar(t) per §8 reparameterization (P5, P14, I1); β_t linear 1e-4→0.02 over T=1000 (Ho et al. NeurIPS 2020).
  • diffuse/precond/base.py: identity Preconditioning (P1) — c_skip=0, c_out=1, c_in=1, c_noise=t/T — the DDPM special case of the general interface, not a separate code path.
  • diffuse/backbones/unet.py: UNetBackbone(DenoiserBackbone) — sinusoidal timestep embedding, 4 resolution levels, residual blocks, self-attention at 16×16 (Ho et al. 2020 architecture; ADR-07 defers FlashAttention until Phase 8).
  • diffuse/train/loop.py: train_step — sample tUniform[0,T), εN(0,I), form x_t via the §8 closed form (P5), MSE L_simple (§8 eq.), grad-norm + NaN guard (I9).
  • diffuse/samplers/ancestral.py: AncestralSampler(Sampler) — 1000-step stochastic reverse chain (Ho et al. 2020 Algorithm 2; P2 — read-only model handle, mutates only its own trajectory buffer).
  • diffuse/eval/fid.py: 50k-sample FID against InceptionV3 pool3 features (Heusel et al. 2017; P3 — the only acceptance currency).
  • diffuse/ckpt/store.py + record.py: safetensors write/read of CheckpointRecord (I12, ADR-15).

12.6 Pitfalls

  • Sinusoidal timestep-embedding frequency mismatch — manifestation: loss plateaus above 0.05 and never drops; root cause: embedding frequency range not matching Ho et al. 2020; debug: plot embedding norm vs t; signal: train.nan_steps=0 but loss flat; recovery: match reference openai/guided-diffusion unet.py embedding formula exactly.
  • Uniform-t-sampling bias — manifestation: FID stalls ~80; root cause: uniform-over-t under-weights the high-information SNR≈1 region (§8 worked example); debug: histogram loss-per-t bucket; signal: high per-t loss variance mid-range; recovery: documented known limitation, resolved by Phase 1's loss reweighting.
  • Ancestral sampler variance explosion at low t — manifestation: salt-and-pepper noise in samples; root cause: wrong posterior variance β̃t; debug: compare against Ho et al. 2020 eq.7; signal: I13 shape check passes but FID check fails; recovery: fix β̃_t = β_t·(1-ᾱ{t-1})/(1-ᾱ_t).
  • fp32-only OOM at batch 512 — manifestation: CUDA OOM at batch_size=512; root cause: no AMP yet (Phase 1), fp32 activation memory 2× (§34); debug: torch.cuda.memory_summary(); signal: allocator OOM at step 1; recovery: cap batch_size ≤256 for Phase 0.

12.7 Performance Concerns

  • 8 data-loader workers (§4) saturate a single A100 for 32×32; more workers add CPU contention with no GPU-util gain.
  • U-Net attention at 16×16 is O(N²) but N=256 tokens — negligible vs conv cost at this resolution; FlashAttention (ADR-07) deferred to Phase 8 where N is large.
  • fp32 activation memory dominates at batch>256 — bf16 (Phase 1, ADR-03) is the primary lever, not architecture changes.
  • Synchronous checkpoint write blocks the loop ~1.5s at 560MB (§4) — acceptable at Phase 0's cadence, revisited if cadence tightens.

12.8 Edge Cases

  • t=0 exactly — ᾱ_0=1, x_0 unchanged, ε has zero training signal; downstream code must not divide by 1-ᾱ_0=0 (generalized in Phase 5's I6 guard).
  • Batch of all-identical images (degenerate augmentation bug) — loss collapses to a trivial ε-fit; caught by the N.5 malformed-fixture class, not silently trained on.
  • Resume mid-epoch after crash — RESUMING state (§8) must restore optimizer + scheduler step count exactly, not just model weights.
  • Disk-full during checkpoint write — partial safetensors file; I12 loader must sniff and reject a truncated file.

12.9 Failure Analysis

  • NaN loss at any step → I9 guard skips the optimizer step, logs the offending batch id, continues training.
  • CUDA OOM → CRASHED state (§8) → operator consults docs/failure-analysis/ → resumes from last CheckpointRecord (RTO ≤120s, §4).
  • Ancestral sampler produces all-noise output → SamplerDivergenceError distinguishes a genuine divergence from an I13 contract violation.

12.10 Operational Notes

  • Metrics: train.step_ms, train.loss, train.nan_steps, schedule.query_ms (I1), ADR-20 Prometheus client. Logging: structured JSON per step (ADR-18). No tracing yet (ADR-19 arrives Phase 8+).
  • Deployment: single-process, single-GPU, foreground diffuse train; no orchestration layer.
  • Migration: none — first checkpoint format; every later phase must remain loadable (I3/ADR-15).

13. Phase 1 — Cosine Schedule, EMA, bf16 to FID < 20

13.1 Objectives

  • Replace linear β with the cosine schedule (Nichol & Dhariwal ICML 2021), fixing the low-noise over-weighting diagnosed in Phase 0's N.6.
  • Introduce EmaState (P4, I2, ADR-08) as the default sampling-time weight source.
  • Switch to bf16 autocast (ADR-03) to hit the §4 throughput target (≥2,200 img/s) and 92ms p50 step time.
  • Reach FID < 20 on CIFAR-10, still ancestral sampling, still ε-prediction (ADR-05 pre-Phase-4 default).
  • Constraint introduced: NoiseSchedule selected by name at config time (ADR-04's versioned-by-name compatibility).

13.2 Detailed Implementation Steps

  • diffuse/schedules/cosine.py: CosineSchedule(NoiseSchedule) — ᾱ_t = cos²((t/T+s)/(1+s)·π/2), s=0.008 (Nichol & Dhariwal 2021); registered by name per P14/I1 (O(1) query, never iterated).
  • diffuse/train/ema.py: EmaState — decay=0.9999 (ADR-08), update() mutates only the shadow copy, requires_grad=False enforced (I2); single-writer under DDP (forward-compatible with Phase 10, applied there).
  • diffuse/train/loop.py: add WARMUP state (§8 state machine) — 1,000-step LR linear warmup, no EMA update during warmup (P4 tradeoff: shadow copy must not average pre-warmup noise).
  • Wrap train_step in torch.autocast(dtype=bfloat16) (ADR-03); no grad-scaler needed for bf16 (unlike fp16, N.6).
  • diffuse/samplers/ancestral.py: sampler defaults to EmaState.shadow_params() (ADR-08) rather than raw training weights.
  • diffuse/eval/fid.py: add EMA-vs-raw comparison mode quantifying P4's FID gain.

13.3 Deliverable

  • diffuse train --config configs/phase1_cosine_ema_bf16.yaml reproduces the cosine+EMA+bf16 run.
  • diffuse eval --ckpt <path> --weights ema vs --weights raw both runnable, both reported.

13.4 Acceptance Criteria

  • FID < 20 on 50k samples using EMA weights (§4 quality target this phase).
  • EMA FID improves over raw-weight FID by ≥ 3 points at the same step count (quantifies P4).
  • Training throughput ≥ 2,200 img/s bf16, batch 256, single A100 (§4, met for the first time).
  • Step time p50/p95/p99 = 92ms/110ms/145ms (§4 exact match — regression-gate input for Phase 11).
  • tests/test_ema_no_grad.py: ema_param.grad is None after every backward, 100% of sampled steps (I2).

13.5 Conformance Fixtures

  • fixtures/phase1/cosine_analytic.json — 20 hand-computed cosine ᾱ_t vs Nichol & Dhariwal 2021 eq.17; expected: match to 1e-6.
  • fixtures/phase1/ema_grad_leak.json — synthetic forced ema_param.requires_grad=True; expected: assertion caught before optimizer.step(), ema.grad_leak_count increments.
  • fixtures/phase1/seeded_ema_vs_raw.pt — seed=42, matched-step EMA/raw checkpoints; expected: EMA FID ≤ raw FID − 3.
  • fixtures/phase1/bf16_overflow_probe.json — synthetic extreme-activation batch; expected: no inf/NaN in bf16 forward (contrast fp16, N.6).

13.6 Pitfalls

  • EMA decay mis-set for step count — manifestation: EMA FID worse than raw early in training; root cause: decay=0.9999 needs ~10k+ steps to converge, applied to a <2k-step run; debug: plot EMA-vs-raw FID over steps; signal: gap negative before ~5k steps; recovery: lower decay (0.999) for short runs, documented per-run.
  • bf16 underflow in the schedule tail — flagged forward to Phase 5 N.6 (not yet triggered here since preconditioning is still DDPM-identity).
  • Warmup double-counting — manifestation: LR-warmup steps also feed EMA, corrupting the shadow copy; root cause: WARMUP exit condition wired wrong; debug: log EMA-update calls tagged by training state; signal: ema.grad_leak_count=0 but FID still degrades; recovery: gate EmaState.update() behind state == TRAINING.
  • Schedule-name drift between train and sample config — manifestation: sampler silently uses LinearSchedule against a CosineSchedule-trained checkpoint; root cause: schedule_cfg not read back from CheckpointRecord; debug: assert name equality at load; signal: FID regresses sharply with no code change; recovery: I3 rejects at load on name mismatch.
  • autocast dtype leaking into the loss reduction — manifestation: loss precision loss near convergence; root cause: forgetting to upcast before .backward(); debug: inspect loss dtype in the autograd graph; signal: FID plateaus above target despite throughput hitting target; recovery: force loss.float() before backward.

13.7 Performance Concerns

  • bf16 autocast removes the fp16 grad-scaler entirely — no dynamic loss-scaling state (ADR-03).
  • EMA update is O(params) per step, one extra full parameter copy in memory (§34 M8).
  • Cosine schedule's alpha_bar query remains O(1) (P14) — no throughput regression vs linear.
  • p99/p50 gap (145ms/92ms) driven by periodic EMA-update + logging overhead, not autocast.

13.8 Edge Cases

  • EMA state absent on a Phase-0-format checkpoint — must initialize a fresh EmaState from current weights, not crash (Compatibility & Versioning).
  • Warmup step count exceeding total training steps — clamp min(warmup_steps, max_steps // 10), never deadlock in WARMUP.
  • Concurrent EMA read during sampling while training writes it — sampler must snapshot, not hold a live reference (P4/I2 concurrency note).

13.9 Failure Analysis

  • EMA corruption (accidental gradient path) → I2 catches it same-step; recovery reloads EMA from last checkpoint, bounded loss = one checkpoint interval.
  • Cosine-schedule config typo → caught by the analytic fixture (13.5) before any training run, not discovered 40 minutes into a failed FID gate.
  • bf16 silent precision loss → gradual FID degradation, no crash; detected only by the regression fixture (13.5) — a silent-degradation class requiring proactive gating.

13.10 Operational Notes

  • New metrics: ema.grad_leak_count, ema.decay (config echo), train.warmup_active (gauge).
  • Dashboard: EMA-vs-raw FID divergence over steps, catching the mis-set-decay pitfall visually.
  • Rollback to linear schedule is a config change only (schedule_name: linear), no path removed (P14).
  • Migration: CheckpointRecord.schedule_cfg carries {"name":"cosine","s":0.008} from this phase onward (ADR-04).

14. Phase 2 — Classifier-Free Guidance & Class-Conditional Sampling

14.1 Objectives

  • Add class-conditional training: Batch.labels (§11) consumed by the backbone.
  • Implement classifier-free guidance (Ho & Salimans 2022) via joint conditional/unconditional training (CFG-dropout).
  • Constraint: guidance is sampling-time only (P8, I7) — never baked into stored weights beyond the dropout training convention.
  • Extend GuidanceConfig (§11) from a declared-but-unused type into a live sampling-time parameter.

14.2 Detailed Implementation Steps

  • diffuse/backbones/unet.py: label-embedding path, added to the timestep embedding (Dhariwal & Nichol NeurIPS 2021 conditioning pattern; ADR-06 backbone note).
  • diffuse/train/loop.py: CFG-dropout — replace labels with a null/∅ token with probability p_uncond=0.1 during training (Ho & Salimans 2022; enables the unconditional branch I7 needs).
  • diffuse/guidance/cfg.py: GuidanceConfig(scale, rescale) (§11) — interpolation identity ε̃ = ε_∅ + w·(ε_c − ε_∅) (§8 CFG eq.).
  • diffuse/samplers/ancestral.py: step() accepts guidance: GuidanceConfig | None (already in the Sampler protocol, §11) and applies it per I7 — computed inside the sampler, never inside DiffusionModel.backbone.forward.
  • Rescale trick (Lin et al. WACV 2024) added to cfg.py to counter guidance over-saturation (N.6) — interpolates between guided and variance-corrected output.
  • diffuse/eval/fid.py: sweep guidance scale w∈{1,2,3,4,6,8}, report FID/diversity tradeoff table (P3).

14.3 Deliverable

  • diffuse sample --ckpt <path> --class-id 3 --guidance-scale 4.0 produces class-conditional samples.
  • Guidance-scale sweep report (reports/phase2_cfg_sweep.json).

14.4 Acceptance Criteria

  • FID ≤ 15 at w=1 (near-Phase-1 parity — conditioning must not regress unconditional-equivalent quality).
  • FID ≤ 12 at the FID-optimal guidance scale (empirically w≈3–4).
  • CFG-dropout rate p_uncond=0.1 exactly, tests/test_cfg_dropout_rate.py within ±1% over 100k samples.
  • guidance.scale_applied fires on 100% of guided calls, 0% of w=1 calls (I7 fixture).
  • Rescale trick reduces the saturation-artifact metric (clipping fraction) by ≥ 50% at w=8 vs no-rescale (Lin et al. 2024, quantified locally).

14.5 Conformance Fixtures

  • fixtures/phase2/cfg_dropout_rate.json — 100k label draws; expected: ∅-frequency 0.10 ± 0.01.
  • fixtures/phase2/guidance_identity_w1.json — w=1 guided vs conditional-only forward; expected: bit-identical (I7).
  • fixtures/phase2/malformed_negative_scale.json — GuidanceConfig(scale=-1.0); expected: rejected, I7 recovery resets w=1.0.
  • fixtures/phase2/seeded_class3_grid.pt — seed=42, class_id=3, w=4.0; expected: bit-identical replay (I4).
  • fixtures/phase2/regression_fid_by_scale.json — FID at w∈{1,2,3,4,6,8}; expected: each within ±1.0 of baseline curve.

14.6 Pitfalls

  • CFG over-saturation at high w — manifestation: blown-out contrast/color at w≥6; root cause: guided ε diverges from the trained manifold's expected norm (Lin et al. 2024); debug: histogram output pixel values vs w; signal: clipping-fraction rises sharply; recovery: rescale trick (14.2), cap w in operator config.
  • Class-embedding leak into the unconditional branch — manifestation: w=1 output subtly differs from a genuinely unconditional model; root cause: ∅-token embedding not truly distinct; debug: I7 identity fixture; signal: fixture fails; recovery: distinct, zero-initialized ∅ embedding row.
  • p_uncond mis-set — manifestation: guidance has no effect (→0) or unconditional quality collapses (→1); debug: 14.5 dropout-rate fixture; signal: frequency outside ±1%; recovery: fix the Bernoulli draw.
  • Guidance-scale sweep cost — manifestation: eval wall-clock balloons 6×; root cause: naive per-scale full 50k-sample re-run; recovery: share sampled noise across scales (N.7).

14.7 Performance Concerns

  • Guidance needs two forward passes per step (conditional + unconditional) — doubles per-step compute vs Phase 1's single-pass step, the dominant Phase 2 cost.
  • Batching conditional/unconditional together (concatenated batch dim) amortizes kernel-launch overhead vs two separate calls.
  • Guidance-scale sweep shares sampled noise across w to avoid 6× redundant cost.

14.8 Edge Cases

  • class_id out of range (10 classes, id=15 given) — reject at CLI validation, never clamp.
  • w=0 (pure unconditional despite conditional training) — must degrade gracefully, not error.
  • Concurrent class-conditional and unconditional calls sharing one DiffusionModel handle — P2's read-only sharing must hold, no cross-call leak.
  • CFG-dropout applied at sample time by mistake — guarded by an explicit training: bool flag.

14.9 Failure Analysis

  • Over-saturated samples at high w → quality regression, not a crash; detected by the clipping-fraction metric, contained to the affected run.
  • Guidance misapplied to stored weights (violating P8/I7) → absent guidance.scale_applied telemetry flags the defect before it reaches an operator report.
  • Dropout-rate drift on a long run → caught by periodic re-sampling of the 14.5 fixture during training, not only at the end.

14.10 Operational Notes

  • New metrics: guidance.scale_applied, cfg.dropout_rate_observed, cfg.clipping_fraction.
  • Runbook: docs/runbooks/guidance-saturation.md.
  • Deployment: no new service boundary; guidance remains a CLI/config parameter (P8).
  • Migration: pre-Phase-2 checkpoints (no CFG-dropout) must reject w≠1 requests (ckpt.sampler_compat_fail, I7).

15.1 Objectives

  • Add deterministic fast samplers, cutting NFE from 1000 (ancestral) to 20–100 (DDIM) and 10–20 (DPM-Solver++), per §8 sampler catalogue.

  • diffuse/eval/fid.py: NFE-vs-FID curve across ancestral/DDIM/DPM-Solver++ at matched budgets.
  • diffuse/cli/sample.py: --sampler {ancestral,ddim,dpm_solver}, default per ADR-09.

15.3 Deliverable

15.4 Acceptance Criteria

  • DDIM 50-step latency ≤ 210ms, batch 1, 32×32 (§4).
  • DDIM 50-step FID within 2.0 of ancestral 1000-step FID.
  • DPM-Solver++ 15-step FID within 3.0 of ancestral FID at ≥ 60× latency reduction.
  • Every sampler passes tests/test_sampler_contract.py (I13), 100% pass rate.
  • Cross-sampler portability: tests/test_sampler_hotswap.py — one checkpoint, all three samplers, zero reload (I3, P2).

15.5 Conformance Fixtures

  • fixtures/phase3/ddim_analytic_step.json — one hand-computed DDIM step vs §8 eq.; expected: match to 1e-5.
  • fixtures/phase3/sampler_contract_all.json — shape/dtype per §11 tensor table; expected: all three samplers conform.
  • fixtures/phase3/seeded_ddim50.pt — seed=42, DDIM 50-step; expected: bit-identical replay (I4).
  • fixtures/phase3/malformed_nfe_mismatch.json — DPM-Solver steps=0; expected: ScheduleError, never a silent 1-step fallback.
  • fixtures/phase3/regression_nfe_fid_curve.json — FID at NFE∈{10,15,20,50,1000}; expected: each within ±1.0 of baseline.

15.6 Pitfalls

  • DDIM's non-Markovian assumption violated by a schedule change — manifestation: output degrades sharply after a mid-experiment schedule swap; root cause: DDIM's η=0 derivation assumes the train-time ᾱ_t; debug: compare schedule_cfg between checkpoint and sampler; signal: ckpt.sampler_compat_fail; recovery: I3 rejects the mismatched load.
  • DPM-Solver instability below ~8 steps — manifestation: NaN or extreme values; root cause: local truncation error grows superlinearly at very low step counts (Lu et al. 2022 §4); debug: monitor x_t norm across steps; signal: SamplerDivergenceError; recovery: enforce a minimum-steps floor per solver order.
  • Non-uniform t-subsequence off-by-one — manifestation: first/last DDIM step skips t=0 or t=T; root cause: linspace instead of the paper's exact index formula; debug: unit-test against Song, Meng & Ermon 2021 Appendix; signal: 15.5 analytic fixture fails; recovery: fix index generation.
  • Shared trajectory buffer across concurrent calls — manifestation: two concurrent sample() calls corrupt each other's x_t; root cause: a Sampler instance reused across calls, violating I13; debug: concurrency stress test; signal: intermittent contract-fixture failure; recovery: fresh Sampler() per call at the CLI/API boundary.

15.7 Performance Concerns

  • Dominant cost remains backbone forward passes (NFE × step-ms) — algorithmic step overhead is negligible (§34).
  • DPM-Solver's higher order costs more per-step compute — the latency win holds only at the reported 10–20-step regime.
  • Batch-1 latency (§4) is kernel-launch-dominated at 32×32; throughput-oriented eval always batches.

15.8 Edge Cases

  • steps=1 requested for DDIM — must produce a defined output, not divide-by-zero in the t-subsequence generator.
  • Duplicate t values in a misconfigured non-uniform subsequence — reject at construction.
  • Sampler requiring an internal x0-pred conversion against a raw ε-pred checkpoint — handled via §8 identities explicitly, not an implicit guess.
  • Extremely small σ near the final DDIM step — same underflow class as Phase 0's t=0 edge case.

15.9 Failure Analysis

  • Sampler divergence (NaN trajectory) → SamplerDivergenceError, distinct from an I13 shape/dtype AssertionError, narrowing operator triage.
  • Cross-sampler contract violation → caught in CI by I13's per-sampler fixture (Phase 11 gate).
  • NFE-vs-FID regression → caught only by the regression fixture (15.5), a silent-degradation class requiring ADR-22's CI gate.

15.10 Operational Notes

  • New metrics: sampler.nfe, sampler.wall_clock_ms, sampler.contract_violation (I13).
  • Runbook: docs/runbooks/sampler-divergence.md.
  • Deployment: --sampler becomes a first-class CLI/config axis, documented in README.
  • Migration: none required — samplers are additive; ancestral remains available (ADR-09).

  • ε-prediction instability at high σ — manifestation: intermittent loss spikes late in training even under bf16; root cause: poor SNR at high noise amplifies backbone error (Salimans & Ho 2022 §2); debug: bucket loss by t; signal: train.nan_steps concentrated at high t; recovery: switch to v-prediction (this phase's motivating fix, ADR-05).

  • v-prediction's conversion layer adds O(1) elementwise ops — negligible vs backbone cost, no step-time regression from §4's Phase-1 targets.

  • Preconditioning comparison report (reports/phase5_edm_vs_vpred.json).

17.4 Acceptance Criteria

  • FID ≤ 8 under EDM + Heun 30-step sampling (approaching the Phase-11 FID<10 target early).
  • Heun 30-step latency ≤ 260ms batch-1, 32×32.
  • I6 guard: zero false negatives over a 1M-sample σ-sweep, precond.nan_count=0.
  • tests/test_edm_identity.py: c_skip/c_out/c_in/c_noise match §8 to 1e-6 across 50 sampled σ.
  • σ_data recomputed per-dataset, verified by a config-diff test vs the paper's ImageNet constant.

17.5 Conformance Fixtures

  • fixtures/phase5/edm_table_analytic.json — 50 (σ,c_skip,c_out,c_in,c_noise) tuples; expected: match §8 to 1e-6.
  • fixtures/phase5/precond_nan_guard.json — σ sweep incl. σ=0, σ=1e-9; expected: I6 clamps, zero NaN/Inf.
  • fixtures/phase5/heun_analytic_step.json — one hand-computed Heun step; expected: match Algorithm 1 to 1e-5.

  • fixtures/phase5/regression_fid_edm.json — FID=7.6 baseline; expected: within ±1.0 on re-run.

17.6 Pitfalls

  • σ→0 division by zero in c_noise — manifestation: log(0)=-inf propagates into the noise conditioning; root cause: sampler's final step approaches σ=0 unfloored; debug: log σ across last 3 steps; signal: precond.nan_count>0; recovery: I6's clamp to σ_min=0.002.
  • Copying the paper's ImageNet σ_data uncritically — manifestation: FID plateaus 5–10 points worse than expected; root cause: σ_data is per-dataset empirical, not universal (NVlabs/edm pitfall); debug: compute CIFAR-10's actual pixel std vs the hardcoded constant; recovery: recompute σ_data from the training set.
  • bf16 overflow in c_out(σ) at σ=80 — manifestation: precond.nan_count spikes at high-σ steps under bf16, absent under fp32; root cause: bf16 mantissa precision loss on the σ·σ_data product; debug: cast the probe to fp32; recovery: compute preconditioning coefficients in fp32 even when the backbone runs bf16.
  • Heun's 2nd evaluation missing re-applied c_in — manifestation: Heun FID worse than a 1st-order-equivalent sampler; root cause: predictor output fed to the corrector without re-preconditioning; debug: 17.5 analytic-step fixture; recovery: apply full preconditioning at both predictor and corrector evaluations.

17.7 Performance Concerns

  • Heun's 2nd-order correction means 2× backbone evaluations per step vs a 1st-order sampler at the same step count (already reflected in §8's 20–40 NFE, not "steps").
  • EDM's extra elementwise ops (§8 table) are O(1) per forward, dominated by backbone cost — no measurable throughput regression vs Phase 4.
  • Recomputing σ_data is a one-time O(dataset size) pass at config-build time.

17.8 Edge Cases

  • σ exactly at σ_min/σ_max — must be included, not excluded (I6 is a floor/ceiling, not an open interval).
  • Odd NFE budget not cleanly halving into predictor/corrector pairs — document the boundary step's Euler-fallback behavior, never silently drop a step.
  • EDM preconditioning applied to a Phase-0 DDPM-identity checkpoint — I3 rejects.
  • log-uniform σ draw equal to σ_data (c_skip=c_out crossover) — covered by 17.5's σ grid.

17.9 Failure Analysis

  • σ→0 NaN propagation → contained by I6 before reaching the backbone; precond.nan_count gives immediate operator visibility.
  • σ_data miscalibration → quality regression, not a crash; detected via the regression fixture (17.5) and config-diff test (17.4) — a silent-degradation class alongside 13.6/16.6.
  • Heun corrector bug → caught immediately by the analytic-step fixture in CI.

17.10 Operational Notes

18. Phase 6 — VAE and Latent Diffusion

18.1 Objectives

  • Introduce AutoencoderKL (§11, Rombach et al. CVPR 2022) — f=8 KL-regularized VAE, enabling latent-space diffusion.
  • Establish the versioned scale-factor contract (P9, I8) before any latent training begins.
  • Move the training target from CIFAR-10 32×32 to 256×256 pixel / 32×32 latent, unlocking the memory reduction quantified in §34.
  • Constraint: VAE is frozen and read-only once training starts (§11) — no joint VAE+diffusion training in scope.

18.2 Detailed Implementation Steps

  • diffuse/vae/autoencoder.py: AutoencoderKL(VAEEncoder, VAEDecoder) (§11) — f=8 encoder/ decoder, KL bottleneck (Rombach et al. 2022 §3; contrast VQGAN's discrete codebook, ADR-11).
  • diffuse/vae/scale_calibration.py: compute + persist scale_factor so encoded-latent std ≈ 1 (I8) — recomputed per trained VAE, never hardcoded (§5 ref-impl 3 pitfall directly addressed).
  • diffuse/backbones/unet.py: retarget input/output channels 3→4 (latent) — a config change per P6/P1, not a new backbone class.
  • Batch.latents (§11) populated via AutoencoderKL.encode() at load time or pre-cached offline (N.7).
  • CheckpointRecord.vae_ref (§11) pins the exact VAE checkpoint id + scale factor (P9); I8 enforces the round-trip check at load.
  • diffuse/eval/fid.py: FID computed on decoded pixel-space samples, never on latents directly — documented explicitly to avoid a metric-space mismatch.

18.3 Deliverable

  • diffuse train --config configs/phase6_latent.yaml trains a latent U-Net against a pretrained, frozen VAE.
  • diffuse sample --ckpt <path> decodes latents to pixels via the pinned VAE.
  • VAE round-trip calibration report (reports/phase6_scale_factor.json).

18.4 Acceptance Criteria

  • VAE round-trip reconstruction PSNR ≥ 24 dB on held-out validation images.
  • Latent std within 5% of 1.0 post-scale-factor calibration (I8's exact threshold).
  • GPU memory ceiling, 256×256 latent (64×64 lat.), training ≤ 24 GB (§4).
  • FID ≤ 10 on decoded 256×256 samples at matched compute to Phase 5's pixel-space budget.
  • tests/test_vae_scale_drift.py: a checkpoint whose vae_ref scale factor differs from the loaded VAE's by >5% raises PreconditionMismatchError, 100% detection over 20 synthetic fixtures (I8).

18.5 Conformance Fixtures

  • fixtures/phase6/vae_roundtrip.json — 50 validation images; expected: PSNR ≥ 24 dB each.
  • fixtures/phase6/scale_factor_calibration.json — computed factor on a fixed 10k-image sample; expected: within ±0.005 of the recorded baseline.
  • fixtures/phase6/malformed_scale_mismatch.json — vae_ref.scale_factor=0.15 vs a 0.182-calibrated VAE; expected: PreconditionMismatchError (I8).
  • fixtures/phase6/seeded_latent_grid.pt — seed=42, latent sampling + decode; expected: bit-identical replay (I4).
  • fixtures/phase6/regression_fid_latent.json — FID baseline decoded 256×256; expected: within ±1.5.

18.6 Pitfalls

  • VAE scale-factor mismatch — manifestation: FID degrades 5–15 points with no visible code bug (P9); root cause: diffusion model trained against one scale factor, sampled against a differently-calibrated VAE; debug: 18.5 malformed-mismatch fixture, compare vae_ref fields; signal: vae.scale_drift (I8); recovery: recompute + persist the new scale factor, block latent training until resolved.
  • VAE encode accidentally differentiable (freeze not applied) — manifestation: VAE parameters show nonzero gradients; root cause: missing requires_grad_(False)/no_grad() boundary; debug: assert zero trainable VAE params before each train_step; recovery: enforce the freeze at construction (mirrors I11's text-encoder freeze, reused in Phase 7).
  • FID computed in latent space instead of pixel space — manifestation: implausible FID numbers that don't correlate with visual quality; root cause: forgetting the VAE-decode step before InceptionV3; debug: inspect the eval pipeline's tensor shape before feature extraction; recovery: hard-code the decode step, not an optional flag.
  • Stale pre-encoded latent cache after a VAE re-calibration — manifestation: training silently uses latents under an old scale factor; root cause: offline cache not invalidated; debug: compare cache timestamp vs VAE checkpoint id; recovery: key the cache by VAE id + scale factor.

18.7 Performance Concerns

  • Latent-space training reduces activation memory by f²=64× at the spatial dimension (§34) — the primary lever unlocking 256×256-equivalent training in Phase 0's memory ceiling.
  • Pre-encoding the dataset offline trades disk for training throughput, recommended for repeated-epoch training (ADR-14-adjacent tradeoff).
  • VAE decode at sample time is a fixed per-sample cost, amortized against the dominant sampling cost at any reasonable NFE.

18.8 Edge Cases

  • Resolution not divisible by f=8 — reject or pad explicitly, never crop asymmetrically.
  • VAE reconstruction of an out-of-distribution input (e.g. pure noise) — low PSNR, not a crash.
  • Latent dtype mismatch (bf16 compute vs fp32 storage, §11) at encode/decode — explicit upcast/downcast, never implicit promotion.
  • Concurrent training and offline cache regeneration — P9's versioned contract prevents silent corruption of the in-flight run.

18.9 Failure Analysis

  • Scale-factor drift → I8 catches it at load, before a single step runs against the mismatched pair.
  • VAE freeze violation → caught by the params-with-grad assertion before the first optimizer step, one-line fix, no data loss.
  • Latent/pixel FID confusion → a reporting-layer bug, contained to the eval harness, no checkpoint corruption.

18.10 Operational Notes

  • New metrics: vae.scale_drift, vae.roundtrip_psnr, vae.encode_ms, vae.decode_ms.
  • Runbook: docs/runbooks/vae-scale-mismatch.md.
  • Deployment: the frozen VAE becomes a second versioned artifact type alongside the diffusion checkpoint (Compatibility & Versioning).
  • Migration: pixel-space checkpoints (Phase 0–5) remain valid; latent training is strictly additive, gated behind an explicit vae_ref config.

19. Phase 7 — Text Conditioning

19.1 Objectives

  • Add frozen CLIP text-tower conditioning (ADR-12) via cross-attention (P12) into the latent U-Net from Phase 6.
  • Enable prompt-driven generation, the first point in the capability arc where a text string drives sampling.
  • Constraint: text encoder weights frozen during diffusion training (I11) — no joint fine-tuning in scope.

19.2 Detailed Implementation Steps

  • diffuse/text/clip_encoder.py: frozen CLIP text tower, CLIP BPE tokenized (ADR-13); output populates Batch.text_embeds (§11, shape (B,L,D_text), bf16).
  • diffuse/backbones/unet.py: cross-attention blocks consuming text_embeds as keys/values (P12) — text enters via cross-attention, never pixel-concatenation.
  • Freeze enforcement: requires_grad_(False) on the CLIP tower at assembly (I11), same trainable-param-count-zero pattern established for the VAE (18.6).
  • Text-CFG: Phase 2's CFG-dropout mechanism extended — with probability p_uncond, text_embeds replaced by a null embedding, composing with class-conditional CFG per P12.
  • diffuse/eval/clip_score.py: CLIP score (image-text alignment) as a second acceptance metric (§11 EvalReport.clip_score, already declared).

19.3 Deliverable

  • diffuse sample --ckpt <path> --prompt "a photo of a red bicycle" --guidance-scale 7.5.
  • EvalReport reports both FID and CLIP score for the first time.

19.4 Acceptance Criteria

  • CLIP score ≥ 0.28 (ViT-B/32 cosine similarity) over a 5k-prompt held-out set.
  • FID ≤ 12 on decoded text-conditional samples (a bounded, quantified regression vs Phase 6's class-conditional FID<10).
  • Zero trainable CLIP parameters at every training step (I11, 100% of sampled steps).
  • Text-CFG dropout rate within ±1% of configured p_uncond (mirrors 14.4).
  • tests/test_dual_conditioning.py: class + text guidance apply simultaneously with no code fork (P12 composability made concrete).

19.5 Conformance Fixtures

  • fixtures/phase7/clip_freeze_check.json — per-step trainable-param count for the CLIP tower; expected: 0 at every step (I11).
  • fixtures/phase7/text_cfg_dropout_rate.json — 100k caption draws; expected: null-frequency within ±1%.
  • fixtures/phase7/malformed_empty_prompt.json — empty-string prompt; expected: falls back to the null embedding cleanly, no tokenizer crash.
  • fixtures/phase7/seeded_prompt_grid.pt — seed=42, fixed prompt, w=7.5; expected: bit-identical replay (I4).
  • fixtures/phase7/regression_clip_fid.json — baseline CLIP score + FID; expected: CLIP within ±0.01, FID within ±1.5.

19.6 Pitfalls

  • Accidental CLIP fine-tuning — manifestation: embeddings drift over training; root cause: requires_grad_(False) applied to the wrong module scope; debug: enumerate all CLIP submodules and assert zero-grad on each; signal: 19.5's freeze-check fails partway through a run, not just at step 0; recovery: apply the freeze recursively, add to the training loop's periodic invariant sweep.
  • Pixel-concatenated text conditioning creeping in — manifestation: input channel count silently changes, breaking checkpoint compatibility; root cause: a "just concat the embedding" shortcut instead of cross-attention; debug: diff backbone input channels vs §11; signal: I3's architecture-id check fails when loading a Phase-6 checkpoint; recovery: P12's explicit cross-attention-only rule.
  • CLIP tokenizer truncation silently dropping content — manifestation: long prompts ignore described tail content; root cause: CLIP BPE's fixed 77-token context (ADR-13); debug: log token count vs prompt length; recovery: document the 77-token ceiling in CLI help and EvalReport, never silently truncate without visibility.
  • Text- and class-CFG dropout draws correlated — manifestation: 19.4's dual-conditioning test fails intermittently; root cause: shared RNG stream for both dropout decisions; debug: check RNG call sequence; recovery: separate RNG streams per conditioning axis (I4 discipline).

19.7 Performance Concerns

  • Cross-attention costs O(L·N) per block (L=text tokens ≤77, N=image tokens) — small relative to self-attention at typical N.
  • Frozen CLIP forward is a fixed per-batch cost, cacheable if captions repeat.
  • Dual CFG (class + text) can require up to 4 forward passes per sampling step if both axes are guided independently — an explicit NFE multiplier, distinct from Phase 2's 2×.

19.8 Edge Cases

  • Stopword-only prompt — still encoded, not special-cased as "empty" (contrast the true empty-string case, 19.5).
  • Corrupt/missing text field in the dataset — reject at the data-pipeline boundary, never substitute a placeholder that pollutes CFG-dropout statistics.
  • Multilingual prompt against an English-trained CLIP — degraded, not crashing, behavior (Deferred Features Register candidate).
  • Conflicting class + text conditioning (class="airplane", prompt="a photo of a cat") — the system composes both per P12, not a validation error.

19.9 Failure Analysis

  • CLIP drift from an unenforced freeze → detected by the periodic in-loop sweep (19.6), bounded blast radius to steps between sweep intervals.
  • Pixel-concatenation regression → caught by I3's architecture-id check the moment an old checkpoint fails to load.
  • Truncated-prompt regression → a documented, bounded limitation surfaced via CLI warning, not a hidden failure.

19.10 Operational Notes

  • New metrics: text.clip_score, text.cfg_dropout_rate, text.token_truncation_count.
  • Runbook: docs/runbooks/clip-drift-detection.md.
  • Deployment: text conditioning is opt-in via config (text_encoder_ref populated); earlier checkpoints remain fully valid.
  • Migration: CheckpointRecord.text_encoder_ref (§11, already declared) populated from this phase forward; None for all earlier checkpoints, explicit not implicit.

20. Phase 8 — DiT Backbone

20.1 Objectives

  • Swap the convolutional U-Net for a transformer denoiser, DiTBackbone (§11, Peebles & Xie ICCV 2023), proving P7's backbone-agnostic training-loop claim at scale.
  • Adopt FlashAttention (Dao et al. NeurIPS 2022, ADR-07) now that token counts justify it (deferred from Phase 0 per ADR-07).
  • Constraint: diffuse.train must touch zero lines to support this swap (P7) — verified structurally, not just functionally.

20.2 Detailed Implementation Steps

  • diffuse/backbones/dit.py: DiTBackbone(DenoiserBackbone) (§11) — patchify latent input, transformer blocks with AdaLN-Zero conditioning (Peebles & Xie 2023 §3; zero-init modulation per facebookresearch/DiT ref-impl, §5).
  • Patchify layer: latent (B,4,H/8,W/8) → patch-token sequence, patch size p∈{2,4,8} (Peebles & Xie 2023 scaling-law convention).
  • Attention kernel: FlashAttention (ADR-07) replaces naive softmax attention now that N (patch count) is large enough to justify the O(N) memory win (Hennessy & Patterson ch.4, ADR-07).
  • AdaLN-Zero: timestep + class/text conditioning modulates scale/shift/gate per block, zero-initialized so each block starts as identity (facebookresearch/DiT pitfall: non-zero-init destabilizes early training, §5 ref-impl 4).
  • Training-loop verification: run diffuse/train/loop.py from Phase 7 unchanged against DiTBackbone — the deliverable is the absence of a diff in that file (P7 structural proof).
  • diffuse/eval/fid.py: FID/throughput at multiple DiT sizes (DiT-B, DiT-XL, §4) to characterize the transformer scaling-law curve.

20.3 Deliverable

  • diffuse train --config configs/phase8_dit_b.yaml and configs/phase8_dit_xl.yaml both train against diffuse/train/loop.py with zero modification.
  • Scaling-law report (reports/phase8_dit_scaling.json).

20.4 Acceptance Criteria

  • Training throughput ≥ 340 img/s bf16, DiT-B, 256×256 latent, single A100 (§4).
  • GPU memory ceiling: DiT-B batch 64 bf16 ≤ 24 GB; DiT-XL batch 32 bf16 ≤ 55 GB (§4).
  • FID ≤ 9 at matched compute to Phase 6's U-Net latent baseline.
  • git diff on diffuse/train/loop.py between Phase 7 and Phase 8 is empty (P7, machine- checkable).
  • tests/test_adaln_zero_init.py: all modulation-gate parameters exactly 0.0 at construction, 100% of gate parameters (facebookresearch/DiT pitfall guard).

20.5 Conformance Fixtures

  • fixtures/phase8/adaln_zero_init.json — full gate-parameter listing at construction; expected: all exactly 0.0.
  • fixtures/phase8/patchify_roundtrip.json — patchify then unpatchify a known latent; expected: bit-identical round trip.
  • fixtures/phase8/train_loop_diff.json — hash of diffuse/train/loop.py, Phase 7 vs Phase 8; expected: identical hash.
  • fixtures/phase8/seeded_dit_grid.pt — seed=42, DiT-B, DDIM 50-step; expected: bit-identical replay (I4).
  • fixtures/phase8/regression_scaling_curve.json — FID at DiT-S/B/L/XL matched-compute; expected: each within ±1.5.

20.6 Pitfalls

  • Non-zero-init AdaLN destabilizing early training — manifestation: loss spikes/diverges in the first few hundred steps; root cause: modulation params not zero-initialized, blocks not identity at start (facebookresearch/DiT, this phase's primary risk); debug: 20.5 init fixture, plot loss for the first 500 steps; signal: loss variance far higher than Phase 6's baseline; recovery: zero-init the gate parameters explicitly, verified before training starts.
  • Naive-attention OOM at large patch-token counts — manifestation: OOM at DiT-XL batch sizes that fit for DiT-B; root cause: O(N²) attention memory without FlashAttention; debug: torch.cuda.memory_summary() isolating the attention block; signal: OOM correlates with token count, not batch alone; recovery: verify FlashAttention is actually dispatched, not silently falling back to naive.
  • Patch-size mismatch between train and sample config — manifestation: shape mismatch or PreconditionMismatchError at sample time; root cause: patch size p not persisted in CheckpointRecord; debug: compare configured p at train vs sample; recovery: extend the architecture-id pin (ADR-06) to include patch size.
  • bf16 overflow in attention at high patch-token counts — manifestation: intermittent NaN specific to DiT-XL, absent in DiT-B; root cause: softmax numerator overflow under bf16's reduced mantissa at large N; debug: isolate attention output dtype/range; signal: train.nan_steps>0 correlating with DiT-XL; recovery: FlashAttention computes softmax in fp32 internally — verify that code path is actually taken.

20.7 Performance Concerns

  • FlashAttention's O(N) memory is the single largest lever enabling DiT-XL's 55GB ceiling (§4) — without it, DiT-XL exceeds single-A100 memory at any useful batch size.
  • Patch size trades sequence length for per-token capacity — the tradeoff the scaling-law report (20.3) characterizes directly.
  • DiT's per-image step time is worse than U-Net's at small scale but the scaling-law curve (Peebles & Xie 2023) shows DiT overtaking at larger compute — a named crossover, not asserted.

20.8 Edge Cases

  • Resolution not evenly divisible by patch size p — reject or pad explicitly (mirrors Phase 6's f=8 divisibility case).
  • AdaLN-Zero applied to an all-zero conditioning signal (unconditional generation) — must degrade to a well-defined identity-like modulation, not NaN.
  • DiT-XL batch size at the exact 55GB ceiling — must fail predictably (clean OOM), not silently corrupt with partial allocation.
  • FlashAttention kernel unavailable on older GPU architectures — must fall back explicitly and loudly, never silently use naive attention while claiming the FlashAttention memory budget.

20.9 Failure Analysis

  • AdaLN-Zero misinit → caught by the init fixture (20.5) before training starts; if missed, manifests within 500 steps (20.6), a bounded detection window.
  • FlashAttention OOM at DiT-XL → CRASHED state (§8), RTO ≤120s (§4); forensics include the memory_summary snapshot at crash time.
  • Patch-size checkpoint incompatibility → I3 rejects at load, before any GPU compute on a nonsensical shape.

20.10 Operational Notes

  • New metrics: dit.patch_size (config echo), dit.adaln_gate_norm, attn.kernel_dispatch (flash vs naive audit trail).
  • Runbook: docs/runbooks/dit-training-instability.md.
  • Deployment: DiT recommended for resolution ≥256px latent; U-Net remains default for CIFAR-10-scale workflows (ADR-06).
  • Migration: U-Net checkpoints remain fully valid; diffuse.cli gains --backbone {unet,dit}, defaulting per resolution.

21. Phase 9 — Progressive Distillation to 10 NFE

21.1 Objectives

  • Halve sampler NFE per distillation round against a frozen teacher trajectory (Salimans & Ho ICLR 2022, P11), from a ~1000-NFE-equivalent teacher toward 10 NFE.
  • Constraint: distillation targets a teacher trajectory, never an invented objective (P11) — each student matches the teacher's N-step ODE output with an N/2-step approximation.
  • Precondition: the teacher must already pass its own FID gate (Phase 8 N.4) before any round begins (I10).

21.2 Detailed Implementation Steps

  • diffuse/distill/progressive.py: halving-round loop (Salimans & Ho 2022 Algorithm 1) — each round trains a student to match a frozen teacher's deterministic trajectory at half the teacher's step count.
  • I10 enforcement: distill.nfe_ratio assertion — student NFE ≤ teacher NFE / 2, validated at round-config construction.
  • Teacher freezing: loaded read-only, mirroring the VAE/text-encoder freeze pattern (I8/I11's sibling pattern, generalized here).
  • Distillation loss: student output at N/2 steps matched against teacher output at N steps via L2 on the predicted x_0 (§8 x0-pred identity, reusing P6's conversion layer regardless of native target).
  • Round scheduling: round k+1's teacher is round k's student; CheckpointRecord tracks a distillation lineage (round number, parent checkpoint id).
  • diffuse/eval/fid.py: FID-vs-NFE curve across all rounds, extending Phase 3's reporting to distilled checkpoints, labeled by round.

21.3 Deliverable

  • diffuse distill --teacher <ckpt> --rounds 7 runs the full halving chain to 10 NFE.
  • Distillation lineage report (reports/phase9_distillation_lineage.json).

21.4 Acceptance Criteria

  • Final-round (10 NFE) FID ≤ 15 (bounded, quantified cost vs the Phase 8 teacher's FID≤9).
  • Each round's NFE exactly half its teacher's, I10 verified over 100% of rounds (distill.nfe_ratio=0.5 ± 0).
  • Distillation wall clock ≤ 45 min per round on single A100 at DiT-B scale.
  • tests/test_distillation_lineage.py: 0 orphaned/misattributed rounds over a 7-round chain.
  • FID-vs-NFE curve monotonically non-decreasing as NFE decreases (a sanity property per P3).

21.5 Conformance Fixtures

  • fixtures/phase9/nfe_halving_contract.json — 7-round NFE sequence; expected: exact halving (1280→640→...→10).
  • fixtures/phase9/lineage_chain.json — full parent-checkpoint chain; expected: unbroken.
  • fixtures/phase9/malformed_wrong_teacher.json — teacher that failed its own FID gate; expected: rejected at round-config validation (P11).
  • fixtures/phase9/seeded_10nfe_grid.pt — seed=42, final 10-NFE student; expected: bit-identical replay (I4).
  • fixtures/phase9/regression_fid_vs_nfe_curve.json — FID at each round's NFE; expected: each within ±1.5, monotonic.

21.6 Pitfalls

  • Distilling before the teacher passes its own gate — manifestation: the chain compounds an already-bad teacher's error; root cause: P11's violation directly; debug: check the teacher's recorded FID against Phase 8's N.4 before round 1; signal: 21.5's malformed-wrong-teacher fixture; recovery: hard-gate round-1 construction on a validated teacher FID.
  • NFE-ratio drift (student trained at teacher's full step count) — manifestation: no speedup observed; root cause: round-config bug; debug: I10's assertion; signal: assertion failure at construction; recovery: reject the round config, require explicit override.
  • Lineage misattribution across parallel distillation experiments — manifestation: a round's parent reference is wrong when chains run concurrently; root cause: shared checkpoint-id namespace; debug: 21.5's lineage-chain fixture; recovery: namespace by chain-id + round number.
  • Quality cliff at very low NFE — manifestation: a much larger FID jump at the final rounds than earlier ones; root cause: ODE trajectory curvature at few steps exceeds one halving's capacity (a known limit distinguishing progressive distillation from consistency models, §36); debug: 21.4's monotonicity check plus curve-slope inspection; recovery: document the practical NFE floor (~8–10, Salimans & Ho 2022), defer sub-10-NFE to §36's consistency-model discussion.

21.7 Performance Concerns

  • Distillation cost per round is bounded by the student's forward/backward at halved NFE plus one frozen teacher forward pass per step — cheaper per-step than full pretraining (teacher needs no gradient).
  • The chain's total compute is geometric — a 7-round chain costs ≈2× round 1 alone, not 7×.
  • Teacher inference runs in eval mode with no gradient tracking — lower memory footprint despite two resident models.

21.8 Edge Cases

  • rounds=0 (no-op request) — reject explicitly, never silently relabel the teacher as "distilled."
  • Student architecture differing from teacher's — must be explicit in config, documented as a supported-but-distinct variant.
  • Resuming an interrupted distillation round — must resume the correct round, not restart at round 0 (reuses the RESUMING state machine, §8, plus the lineage field).
  • Distilling a CFG-trained teacher — this blueprint targets the unguided teacher output, since guidance scale is a sampling-time free parameter (P8) that should not be baked into a specific student; documented explicitly as the chosen tradeoff.

21.9 Failure Analysis

  • Unvalidated-teacher distillation → blocked at round-config construction (P11), zero wasted compute if the gate is enforced pre-launch.
  • NFE-ratio violation → I10's assertion fails before any GPU-hours are spent.
  • Quality cliff at low NFE → not a crash, a documented, bounded curve; escalation path is "stop distilling further, ship the last acceptable round."

21.10 Operational Notes

  • New metrics: distill.nfe_ratio (I10), distill.round_number, distill.wall_clock_s, distill.teacher_fid_at_start.
  • Runbook: docs/runbooks/distillation-quality-cliff.md.
  • Deployment: distilled checkpoints are tagged distinctly (lineage fields) so operators never confuse a 10-NFE student with a full teacher.
  • Migration: none required — distillation is purely additive.

  • Scale training from single-GPU (Phase 0–9) to single-node multi-GPU via DDP (ADR-16) and, for DiT-XL, FSDP for optimizer-state sharding.
  • Keep the EMA shadow copy exactly synchronized across ranks (P4/I2's concurrency note, now load-bearing under real multi-rank execution).
  • Constraint: single-node only in scope — multi-node (>1 host) training is PhaseDeferred("Deferred Features Register").

22.2 Detailed Implementation Steps

  • diffuse/train/distributed.py: DDP wiring (ADR-16) — gradient all-reduce after each backward, rank-0-owns-checkpoint-write convention.
  • FSDP variant for DiT-XL (§4's 675M-parameter, 55GB-ceiling model): shards optimizer state + gradients, unlocking training beyond single-GPU memory (§34 optimizer-memory derivation).
  • EMA under DDP: EmaState.update() (P4) becomes a rank-0 aggregate, broadcast back after each update (§11 EmaState comment: "single-writer (rank 0 aggregate under DDP)").
  • Data pipeline: distributed sharding so each rank sees a disjoint subset per epoch, preserving the LR-schedule's effective-batch-size assumptions (WARMUP state, §8, unchanged).
  • Throughput instrumentation: per-rank and aggregate train.step_ms, train.img_per_s, all-reduce wall-clock — isolates communication overhead from compute.
  • Checkpoint write path: only rank 0 writes safetensors (ADR-15/I12 unchanged), other ranks block on a barrier.

22.3 Deliverable

  • diffuse train --config configs/phase10_ddp_8gpu.yaml --nproc 8 scales Phase 8's DiT-B run across 8 GPUs.
  • diffuse train --config configs/phase10_fsdp_dit_xl.yaml trains DiT-XL under FSDP within the §4 55GB-per-GPU ceiling.

22.4 Acceptance Criteria

  • Aggregate throughput scaling efficiency ≥ 85% at 8 GPUs vs single-GPU baseline (≥6.8× img/s).
  • EMA consistency: all ranks bit-identical after each synchronized update, 100% of sampled steps (tests/test_ema_ddp_sync.py).
  • FSDP DiT-XL stays within the 55GB per-GPU ceiling (§4) at the configured batch size.
  • Zero corrupted/partial checkpoint files over 100 synchronized write events (I12).
  • Gradient all-reduce overhead ≤ 15% of total step time at 8 GPUs.

22.5 Conformance Fixtures

  • fixtures/phase10/ema_ddp_sync.json — simulated 4-rank EMA update; expected: bit-identical shadow copies post-broadcast across all ranks.
  • fixtures/phase10/scaling_efficiency.json — throughput at 1/2/4/8 GPUs; expected: ≥85% efficiency at 8 GPUs.
  • fixtures/phase10/malformed_concurrent_ckpt_write.json — simulated non-rank-0 write attempt; expected: rejected/blocked.
  • fixtures/phase10/seeded_multirank_grid.pt — seed=42, 4-rank DDP then single-GPU sampling; expected: bit-identical to a seed=42 single-GPU-only run (I4 extended across rank count).
  • fixtures/phase10/regression_fsdp_memory.json — DiT-XL FSDP peak-memory baseline; expected: within ±2GB, always ≤ 55GB.

22.6 Pitfalls

  • EMA divergence across ranks — manifestation: sampling from rank 0's EMA vs rank 3's EMA gives different outputs; root cause: EMA update computed locally per-rank instead of a true rank-0-aggregate-then-broadcast; debug: 22.5's sync fixture, compare shadow-copy hashes; signal: tests/test_ema_ddp_sync.py failure; recovery: enforce single-writer-then-broadcast explicitly (P4/I2's concurrency note made concrete under real multi-rank execution).
  • Effective batch-size drift breaking the LR/warmup schedule — manifestation: loss-curve shape differs from single-GPU baselines at "the same" configured batch; root cause: per-rank vs global effective batch confusion; debug: log both explicitly; signal: comparison against a known single-GPU baseline at matched global batch; recovery: document that Phase 0–9 hyperparameters assumed global batch size, scale per-rank accordingly.
  • Rank-0-only checkpoint write race under a crash mid-write — manifestation: a torn checkpoint loaded by RESUMING (§8); root cause: missing atomic fsync/rename before releasing the barrier; debug: injected crash-during-write fault (Testing & Verification Strategy); signal: CheckpointCorruptionError (I12) on resume; recovery: write-to-temp, fsync, rename before releasing other ranks.
  • FSDP sharding boundary splitting a normalization layer incorrectly — manifestation: DiT-XL produces NaN losses specific to the FSDP config, absent under single-GPU DDP; root cause: the auto-wrap policy shards a norm layer's parameters, breaking its statistics; debug: compare FSDP vs single-GPU loss curves at matched steps on a small model; recovery: adjust the auto-wrap policy to keep normalization-layer parameters unsharded.

22.7 Performance Concerns

  • Gradient all-reduce is the dominant communication cost at 8 GPUs — overlapping communication with backward-pass compute is the primary lever for the 85% efficiency target.
  • FSDP trades communication overhead (parameter all-gather before each forward) for memory savings — accepted for DiT-XL because single-GPU doesn't fit at all, not because FSDP is faster at small scale.
  • Checkpoint write barrier stalls all ranks for the write duration (scaled from §4's ~1.5s/560MB estimate, §34) — acceptable at existing cadence, revisited if cadence tightens.

22.8 Edge Cases

  • Uneven GPU count (e.g. 7 GPUs) — must handle non-power-of-2 world size without dropping a rank's data shard.
  • A rank crashing mid-training — must trigger a coordinated CRASHED state (§8) across all ranks, not leave survivors hung on a barrier.
  • Resuming at a different world size than crashed at — must reject explicitly or document the required effective-batch-size renormalization.
  • Heterogeneous multi-GPU (mixed generations in one host) — out of scope, rejected at launch-time validation, not silently run at the slowest GPU's pace.

22.9 Failure Analysis

  • EMA divergence across ranks → detected by the sync-check fixture in CI; recovery reloads EMA from the last synchronized checkpoint (I2 column).
  • Torn checkpoint from a write-race crash → CheckpointCorruptionError (I12) on next load, not a silent partial load; forensics include the atomic-write log.
  • FSDP-specific NaN → isolated to the FSDP config path by the comparison methodology, preventing a false "architecture is broken" diagnosis.

22.10 Operational Notes

  • New metrics: train.scaling_efficiency, train.allreduce_ms, ema.sync_broadcast_ms, fsdp.peak_memory_per_rank.
  • Runbook: docs/runbooks/multi-gpu-scaling-degradation.md.
  • Deployment: single-node topology only (§1); launcher documented in README; multi-node is the PhaseDeferred("Deferred Features Register") boundary.
  • Migration: single-GPU checkpoints (Phase 0–9) remain fully loadable for continued multi-GPU training or single-GPU inference.

23.6 Pitfalls

  • CI gate-threshold drift (a --gate fid:X value loosened to unblock a PR) — manifestation: FID silently creeps upward release over release; root cause: threshold edited casually alongside unrelated changes; debug: git-blame the threshold history against FID history; signal: 23.5's regression baseline itself changes suspiciously often; recovery: require a separate, reviewed PR for any gate-threshold change with FID/throughput justification stated explicitly.
  • Differential-test drift as diffusers evolves upstream — manifestation: the fixture fails after an unrelated diffusers version bump; root cause: loosely-pinned dependency; debug: check pinned version against the fixture's last-known-good date; recovery: pin diffusers to an exact version (ADR-23), bump deliberately with re-verification.
  • Soak test masking a slow leak below its detection threshold — manifestation: a 3%/24h leak passes the gate but compounds over a week-long real run; root cause: 24h window too short for very slow leaks; recovery: add a weekly extended-soak job distinct from the per-PR 24h gate.
  • Fault-injection fixtures going stale after refactors — manifestation: injected-fault fixtures all pass but a real incident's failure mode wasn't covered; root cause: scenarios written once, never revisited; debug: cross-reference the Failure Modes & Recovery register against the fixture list for gaps; recovery: add a fixture for every newly-discovered failure mode.

23.7 Performance Concerns

  • Running the full 12-phase matrix on every PR is expensive — tiered CI (fast unit/property tests on every push, full matrix on merge-to-main) balances feedback latency vs thoroughness.
  • Differential testing against diffusers adds CI image weight/build time, justified by the numerical-parity guarantee.
  • The 24h soak test cannot run per-PR — it runs on a schedule against main, decoupled from PR latency.

23.8 Edge Cases

  • A PR changing both model code and a conformance fixture in the same diff — code-review policy must flag fixture changes for extra scrutiny, since a fixture edit can defeat the regression gate's purpose.
  • CI gate threshold exactly at the boundary (FID exactly 10.0 vs --gate fid:10) — define strict-less-than vs less-than-or-equal explicitly.
  • Differential test with misaligned RNG-consumption order vs diffusers — must align the consumption order explicitly for the comparison to be meaningful.
  • Soak test interrupted by an infrastructure event — must distinguish infra-caused interruption from a genuine soak failure in the dashboard.

23.9 Failure Analysis

  • CI gate silently loosened → detected retroactively via git-blame audit (23.6), a process failure mitigated by the reviewed-PR-required policy.
  • Differential-test drift from an upstream bump → contained to CI red, never reaches a shipped checkpoint (the differential test blocks merge under ADR-22).
  • Fault-injection coverage gap discovered via a real incident → logged in the Failure Modes & Recovery register, the new fixture derived from it, closing the test/incident loop.

27. Compatibility & Versioning

  • Checkpoint format: safetensors only (ADR-15, I12); CheckpointRecord (§11) is the single versioned envelope — every field addition (VAE ref, text-encoder ref, sigma_data, distillation lineage) is additive and optional-typed, never a breaking rename (mirrors P6/P9's parameterization-is-a-config-axis discipline applied to the schema itself).
  • Schedule-parameter compatibility: NoiseSchedule is versioned by name (ADR-04) — schedule_cfg persists the exact name + parameters (§11 NoiseSchedule comment); I3 rejects a load whose stored schedule name/params mismatch the requested sampler's assumption.
  • Sampler contract stability: I13's shape/dtype output contract (§11 tensor table) is the one thing every sampler (ancestral/DDIM/DPM-Solver/Heun) must never break across a release — a contract-breaking sampler change requires a major version bump (SemVer below) and a new registered sampler name, never an in-place behavior change under the same name.
  • Prediction-target compatibility: PredictionTarget (§11 enum) is a closed, versioned set (EPS/X0/V/EDM); adding a new target is additive; CheckpointRecord.train_config.prediction_target pins which one a given checkpoint was trained under (I3 enforcement, extended in Phase 4 N.6).
  • API stability: diffuse.cli (train/sample/eval/distill) follows SemVer — a flag rename or removal is a major bump; new flags with sensible defaults are minor bumps.
  • Migration: pre-Phase-N checkpoints remain loadable by post-Phase-N code via explicit compatibility shims (documented per-phase: EPS-default in Phase 4, vae_ref=None pre-Phase-6, text_encoder_ref=None pre-Phase-7) — never an implicit guess.
  • Deprecation policy: a deprecated schedule/sampler/backbone name stays loadable for at least one major version with a logged deprecation warning before removal; removal itself is a major bump documented in CHANGELOG.md.
  • Rolling-upgrade guarantees: mid-training-job code upgrades are not supported — a running job pins its code version for its lifetime (via the container image, §10 Dockerfile); only a fresh RESUMING launch picks up new code, and I3's compatibility checks are exactly what make that safe.

28. Testing & Verification Strategy

  • Property tests (Hypothesis, ADR-21): schedule identities (I1, I5 — alpha_bar monotonicity and closed-form correctness across randomly sampled t); prediction-target conversions (§8 identities — round-trip ε↔v↔x0 for randomly sampled (x_0, ε, t) triples, Phase 4 N.5); EDM preconditioning finiteness (I6 across randomly sampled σ, Phase 5 N.5).
  • Differential tests: this codebase's ancestral/DDIM sampler vs huggingface/diffusers' reference scheduler on fixed seeds (ADR-21, Phase 11 §23.2) — ≤1e-3 max-abs pixel difference, the tightest correctness bound in the whole test suite.
  • Seeded replay: I4's determinism claim, exercised per-phase (every phase's seeded_*.pt fixture, §12.5 through §22.5) and consolidated into one nightly sweep (tests/test_determinism_suite.py, Phase 11 §23.2).
  • Soak: 24h continuous training (Phase 11 §23.2/§23.4) — throughput-degradation and memory-leak detection, distinct from the per-PR fast test tier.
  • Fault injection: crash-during-checkpoint-write (22.6/23.2), NaN-poisoned batch (I9), OOM (CRASHED state, §8) — each with a documented expected recovery path, verified mechanically, not just described.
  • Conformance: every phase's N.5 fixtures collected under conformance/ (§10), run as one tagged pytest session gating merge to main (ADR-22).
  • Performance-regression gating: the M-table (§30) is CI-enforced per Phase Gate column — a PR that regresses a gated metric beyond its stated tolerance fails CI (ADR-22, .github/workflows/perf-regression.yml).
  • Every test class above ties back to a named invariant (I1–I13) or a named phase fixture (N.5) — no test exists that doesn't trace to a specific correctness or performance claim made elsewhere in this document.

29. Build & Release Engineering

  • Reproducible builds: pyproject.toml + hatchling, pinned exact dependency versions (ADR-23) — a build from a given lockfile hash is bit-reproducible modulo hardware nondeterminism (I4's deterministic-CUDA-flags carve-out).
  • Artifact signing: release-channel checkpoints and container images are signed; the signature is verified at load only for release-channel artifacts (T8's mitigation, §24), not for ad-hoc local development checkpoints (a documented scope boundary, not an oversight).
  • SBOM: generated per release (.github/workflows/release.yml, §10) — a full dependency manifest feeding the supply-chain audit (T6, §24).
  • Release channels: main (bleeding-edge, unsigned), stable (signed, SBOM-attached, differential-tested against diffusers per release, §23.2).
  • CI/CD topology: ci.yml (lint + unit + property tests, every push) → perf-regression.yml (M-table gate, every PR) → release.yml (signing + SBOM + differential test, tag-triggered) — three tiers of increasing cost and increasing pre-merge/pre-release confidence.
  • Version stamping: every checkpoint's CheckpointRecord embeds the exact code version (git SHA) it was produced under, enabling exact reproduction of a training run's environment.
  • Provenance/attestation: dataset hash (ADR-24) + code SHA + dependency lockfile hash together form the full provenance chain for any released checkpoint — the same chain T3/T9 (§24) rely on for poisoning/contamination detection.
  • Dependency auditing: ci.dependency_audit_fail_count (T6, §24) runs on every PR touching pyproject.toml; a failed audit blocks merge, not just release.

30. Performance Engineering

Methodology: every step-time/throughput number in §4 and below is measured, not assumed — torch.profiler traces isolate kernel-level time (conv/attention/all-reduce/checkpoint-IO); torch.cuda.memory_summary() isolates allocator peaks; tail-latency (p95/p99) is sampled over ≥1,000 steps, never inferred from a mean. Allocation profiling flags any per-step Python-side tensor allocation outside the expected reuse pool (a common source of unexplained p99 tails, Phase 0 N.7). Lock/queue-pressure analysis applies specifically to the multi-GPU data-loader (8 workers, §4) and the DDP all-reduce path (Phase 10 N.7).

31. Scalability Analysis

Constant regardless of scale: per-image forward-pass cost of a fixed backbone at fixed resolution (O(1) in dataset size); the schedule query cost (O(1) in T, P14); the checkpoint format's read/write contract (I12) — a 35M-parameter and a 675M-parameter checkpoint use the same safetensors envelope, just more bytes.

Grows with scale, named bottlenecks in order:

  1. Backbone parameter count / activation memory — the first bottleneck hit (Phase 0→5→8): O(params) memory, O(H·W·C·layers) activation memory. Lever: latent-space training (§34, f²=64× reduction).
  2. Attention cost at high resolution/patch count — O(N²) naive, O(N) with FlashAttention (ADR-07). Bottleneck emerges once N (patch tokens) crosses the point where kernel-launch overhead stops dominating (Phase 8 N.7). Lever: FlashAttention, larger patch size (fewer tokens, coarser resolution tradeoff).
  3. Optimizer state memory at large parameter counts — O(params) with a 4–5× multiplier (weights+grads+2 Adam moments+EMA, §34). Bottleneck hit at DiT-XL scale (Phase 10). Lever: FSDP sharding across ranks.
  4. Gradient all-reduce communication — O(params) per step, grows with world size's coordination overhead (not with model size alone). Bottleneck at high GPU counts (Phase 10 N.7). Lever: gradient bucketing/overlap with backward compute.
  5. Sampling latency (NFE × step-ms) — orthogonal to training scale entirely; the fast-sampling arc (Phase 3/5/9) attacks this axis independently via fewer, higher-order, or distilled steps.

Horizontal scaling: DDP across GPUs (Phase 10) — near-linear up to communication-bound crossover (~85% efficiency at 8 GPUs, M11); multi-node is PhaseDeferred("Deferred Features Register"), the next horizontal lever beyond single-node.

Vertical scaling: larger single-GPU memory (A100 80GB vs 40GB) directly raises the DiT-XL batch-size ceiling (§4) without any code change — the memory-ceiling numbers in §4 are per-SKU, not architectural limits.

Sharding/partitioning: FSDP shards optimizer state + gradients (not activations) — the practical reason DiT-XL needs it while DiT-B doesn't (§34 #9).

Coordination overhead: EMA's rank-0-aggregate-then-broadcast pattern (Phase 10 N.2) is the one place coordination cost scales with world size independent of gradient all-reduce — a second, smaller communication tax layered on top of DDP's primary cost.

Practical ceiling and levers beyond it: single-node multi-GPU (Phase 10) tops out at whatever GPU count one host supports (typically 8) and whatever the highest-memory single GPU SKU offers for DiT-XL's 55GB-per-rank floor; the lever beyond that ceiling is multi-node training (deferred, §37) — a fundamentally different coordination regime (cross-host network RTT replaces intra-host NVLink/PCIe bandwidth as the dominant communication cost, not modeled in this blueprint's single-node §4 constraints).

32. Mental Models & First Principles

MM1 — A diffusion model is one denoiser evaluated on a noise-level curriculum; the sampler is just an ODE/SDE integrator over that curriculum. Predicts: ε/x0/v/EDM targets are reparameterizations of the same denoiser (§8, P6), never separate models. Bug class without it: writing a separate backbone per prediction target (the exact violation P6/§16 guards against). Resolving §: §8, §16 (Phase 4).

MM2 — Preconditioning is variance bookkeeping, not modeling. c_skip/c_out/c_in exist purely to keep the network's effective input/output variance near 1 across noise levels spanning ~9 orders of magnitude (§4's defining property). Predicts why σ_data must be recomputed per dataset, never copied from a paper. Bug class without it: copying EDM's ImageNet constants onto CIFAR-10 (the exact §17 N.6 pitfall). Resolving §: §8, §17.

MM3 — EMA is a low-pass filter over the optimization trajectory, not a second model. Predicts sampling should prefer EMA once training has run past the decay's effective time constant, and that EMA-worse-than-raw early in a short run is expected, not a bug. Bug class without it: mis-diagnosing a too-short run's EMA underperformance as an implementation defect (13.6). Resolving §: §7 (I2), §13.

MM4 — Classifier-free guidance is an implicit, un-trained classifier-gradient extrapolation. Predicts over-saturation at high w as an extrapolation artifact, not a training-quality problem. Bug class without it: trying to "fix" over-saturated samples by retraining instead of tuning w or applying the rescale trick (14.6). Resolving §: §8, §14.

MM5 — Terminal SNR must be exactly zero for the reverse process's boundary condition to match training. Predicts washed-out unconditional generations under any nonzero-ᾱ_T schedule, independent of model capacity or training duration. Bug class without it: chasing a "sample quality" bug that is actually a schedule-boundary defect (16.6). Resolving §: §8, §16.

MM6 — Latent diffusion relocates the modeling problem; it does not create information. The VAE delegates high-frequency pixel detail to a separately-trained perceptual compressor; the scale-factor contract (P9, I8) is therefore load-bearing metadata, not an incidental constant. Bug class without it: treating a VAE scale mismatch as training instability rather than a metadata bug (18.6). Resolving §: §18, §34.

MM7 — Progressive distillation compresses the sampling trajectory, not the model's capacity. Predicts a quality cliff at very low NFE distinct from any capacity-limited quality ceiling — the teacher's capacity is unchanged, only how many ODE steps approximate its trajectory. Bug class without it: "fixing" a distillation quality cliff by enlarging the student (21.6). Resolving §: §21, §36.

MM8 — The training loop must not know which backbone or prediction target it drives — only the conversion layer and preconditioning object should. Predicts a backbone swap (U-Net→DiT) or target swap (ε→v) produces a zero-diff in diffuse/train/loop.py. Bug class without it: an isinstance branch coupling the training loop to one backbone, breaking P7 (20.4's machine- checkable acceptance criterion exists precisely to catch this). Resolving §: §11, §20 (P7).

34. Back-of-Envelope Capacity Model

  1. Optimizer memory, CIFAR U-Net (35M params, fp32). params × bytes × (weights + grads + 2 Adam moments + EMA) = 35,000,000 × 4B × 5 = 700 MB. Consistent with §4's 560MB stored checkpoint size (stored form omits transient gradient buffers, keeping only weights+EMA+ optimizer-state-for-resume).

  2. Activation memory, CIFAR U-Net training, batch 256, fp32. batch × C_avg × H × W × layers × bytes ≈ 256 × 128 × 32 × 32 × 20 × 4B = ≈ 2.68 GB. Leaves headroom under §4's ≤6GB fp32 ceiling for the ≈700MB optimizer footprint (#1) plus framework overhead.

  3. Sampling latency, DDIM 50-step, batch 1, 32×32. NFE × step-ms = 50 × 4.2ms = 210 ms, matching §4's measured value exactly — implying a per-NFE backbone-forward cost of ≈4.2ms at batch 1, 32×32.

  4. Sampling latency, Heun 30-step, EDM, batch 1, 32×32. Heun is 2nd-order (2 backbone evals per step, §8 sampler catalogue) → effective NFE = 30×2 = 60. 60 × 4.2ms (from #3) = 252 ms, within §4's ≤260ms target (M7).

  5. Sampling latency, ancestral 1000-step, batch 1, 32×32. 1000 × 4.2ms (from #3) = 4,200 ms ≈ 4.2s, matching §4's stated 4.1s to within rounding.

  6. FID eval wall clock, 50k-sample, 32×32, 1000-step ancestral. wall_clock = n_batches × NFE × per-step-batched-ms. Given §4's measured 38 min (2,280s) and an eval batch of 512 (n_batches = 50,000/512 ≈ 98): per-step-batched-ms = 2,280s / (98 × 1,000) ≈ 23.3 ms — the implied batched-forward cost at batch 512, roughly 5.5× the batch-1 rate (#3) for a 128× larger batch, consistent with strong (not perfect) GPU batching efficiency.

  7. Latent-space memory saving, f=8 VAE. Spatial downsample factor f=8 → f² = 64× reduction in H×W at matched channel count and batch — the activation-memory formula's H×W term (from #2) drops 64×, which is why 256×256-pixel-equivalent training (32×32 latent) fits the same memory envelope as Phase 0's native 32×32-pixel training despite a 3→4 channel increase (a far smaller multiplier than the spatial saving).

  8. Dataset bytes, CIFAR-10. 60,000 images × 32×32×3 bytes (uint8) = 60,000 × 3,072 = ≈ 176 MB, matching §4's stated 170MB within compression/format overhead.

  9. Checkpoint size, DiT-XL (675M params, fp32 + EMA). params × bytes × (weights + EMA) = 675,000,000 × 4B × 2 = 5.4 GB, matching §4 exactly.

  10. FSDP per-rank optimizer-memory saving, DiT-XL, 8 ranks. Unsharded optimizer state (weights

    • grads + 2 Adam moments, excluding EMA which is replicated) = 675M × 4B × 4 = 10.8GB; sharded across 8 ranks = 10.8GB / 8 = ≈ 1.35 GB/rank — leaving the bulk of the §4 55GB-per-rank ceiling (M10) for activation memory, which FSDP does not shard.

36. Alternative Architectures (Roads Not Taken)

(a) GAN-based single-step generation

z ~ N(0,I) ---> [ Generator G ] ---> image
                       ^
                       | adversarial signal
      image (real/fake) <---[ Discriminator D ]

Winning regime: real-time-adjacent single-step generation with no multi-step sampler at all. Embodying system: Karras et al.'s StyleGAN2/3. Rejected here: no ELBO/likelihood objective (§8 has no GAN analogue), well-documented training instability (mode collapse) versus diffusion's stable MSE-regression training (P5), and no natural home for the schedule/preconditioning abstraction (P1) this blueprint's entire capability arc is built around.

(b) Autoregressive discrete-token modeling (VQGAN + Transformer)

image -> [VQ Encoder] -> discrete tokens -> [causal Transformer] -> logits -> [VQ Decoder] -> image

Winning regime: exact likelihood, simple prompt-token-concatenation conditioning, strong compositional generation. Embodying system: Esser, Rombach & Ommer's VQGAN+Transformer (Taming Transformers, CVPR 2021, §5 paper 17); the original DALL-E. Rejected here: sampling is O(sequence length) sequential, not parallelizable the way a diffusion denoiser's O(NFE) is (breaks §4's sampling-latency story); discrete codebook collapse is a hard failure mode this design's continuous KL-latent (ADR-11) avoids by construction.

(c) Flow matching / rectified flow instead of the diffusion SDE

x_0 (data) ---straight-line ODE path---> x_1 (noise)
   learn velocity field v_θ(x_t,t) = x_1 - x_0  (no schedule/preconditioning bookkeeping)

Winning regime: simpler training objective, no terminal-SNR concept to get wrong, fewer numerically-tricky corners. Embodying system: Lipman et al.'s Flow Matching; Liu et al.'s Rectified Flow; Stable Diffusion 3's backbone. Rejected here: this blueprint's Phase 0–5 arc (§8's diffusion SDE, EDM preconditioning, zero-SNR fix) is built around the score/diffusion formulation specifically because it has the deepest catalogue of existing reference checkpoints for differential testing (§1 language rationale, ADR-02) — flow matching is a legitimate alternative foundation, not a parameter swap on top of this one.

(d) Consistency models trained directly for few-step sampling

x_t (any noise level) ---[ consistency function f_θ ]---> x_0, in one step
   trained for self-consistency along the PF-ODE trajectory, not distilled post-hoc

Winning regime: single-step or few-step (2–4 NFE) generation trained end-to-end for that regime from the start. Embodying system: Song, Dhariwal, Chen & Sutskever's Consistency Models (2023). Rejected here: Phase 9 explicitly chooses progressive distillation (Salimans & Ho 2022, P11) targeting a teacher trajectory rather than an invented self-consistency objective (P11's explicit rule); consistency models are this blueprint's documented next step past its ~10-NFE floor (§21 N.6) — the PhaseDeferred single-step-training item in §37, not built here because P11 restricts this phase to trajectory-matching distillation only.

38. Glossary

  • Forward process — the fixed Markov chain that progressively adds Gaussian noise to data (§8).
  • Reverse process — the learned Markov chain that progressively removes noise, the sampler's target (§8).
  • ᾱ_t (alpha-bar) — cumulative signal-retention coefficient at step t; x_t = sqrt(ᾱ_t)·x_0 + sqrt(1-ᾱ_t)·ε (§8).
  • SNR (signal-to-noise ratio) — ᾱ_t/(1-ᾱ_t); the single number governing a noise level's training-information content (§8).
  • Terminal SNR — the SNR at t=T; must be exactly zero for correct unconditional sampling (Lin et al. 2024, §16).
  • ε-prediction — the network predicts the added noise directly (Ho et al. 2020).
  • x0-prediction — the network's output is converted to a predicted clean image (§8).
  • v-prediction — a signal/noise-balanced reparameterization, v := α_t·ε − σ_t·x_0 (Salimans & Ho 2022).
  • EDM preconditioning — the c_skip/c_out/c_in/c_noise wrapper unifying prediction targets (Karras et al. 2022, §8).
  • NFE (number of function evaluations) — the count of backbone forward passes a sampler performs; the primary sampling-latency currency (§4).
  • Ancestral sampling — the original stochastic 1000-step DDPM reverse chain (Ho et al. 2020).
  • DDIM — deterministic, non-Markovian sampler enabling large step skips (Song, Meng & Ermon 2021).
  • DPM-Solver — a high-order ODE solver reaching near-parity quality in 10–20 steps (Lu et al. 2022).
  • Heun sampler — a 2nd-order predictor-corrector ODE integrator (Karras et al. 2022).
  • Classifier-free guidance (CFG) — sampling-time interpolation between conditional and unconditional predictions using one jointly-trained model (Ho & Salimans 2022).
  • Guidance scale (w) — the CFG interpolation strength; w=1 is unguided, w>1 amplifies conditioning (§8).
  • EMA (exponential moving average) — a read-only shadow copy of weights used for sampling (P4, I2).
  • Latent diffusion — running the diffusion process in a VAE's compressed latent space rather than pixel space (Rombach et al. 2022).
  • VAE scale factor — the per-checkpoint constant normalizing encoded-latent variance to ≈1 (P9, I8).
  • DiT patchify — splitting a latent tensor into a sequence of transformer input tokens (Peebles & Xie 2023).
  • Progressive distillation — halving sampler NFE per round by matching a frozen teacher's trajectory (Salimans & Ho 2022).
  • FID (Fréchet Inception Distance) — the primary sample-quality metric, comparing Inception feature statistics (Heusel et al. 2017).
  • CLIP score — image-text alignment metric using a CLIP embedding's cosine similarity.
  • Cosine schedule — a β_t schedule shaped to avoid over-weighting low-noise steps (Nichol & Dhariwal 2021).
  • Zero-SNR fix — forcing ᾱ_T=0 to eliminate terminal-SNR leakage (Lin et al. 2024).
  • c_skip/c_out/c_in/c_noise — the four EDM preconditioning coefficients (§8 table).
  • σ_data — the empirical per-dataset pixel-value standard deviation anchoring EDM preconditioning (§17).
  • AdaLN-Zero — zero-initialized adaptive layer-norm conditioning in DiT blocks (Peebles & Xie 2023).
  • Cross-attention conditioning — injecting text/class tokens as attention keys/values rather than pixel-concatenation (P12).
  • CFG-dropout — randomly replacing the conditioning signal with a null token during training to enable the unconditional branch CFG needs (Ho & Salimans 2022).
  • safetensors — a checkpoint format storing only flat tensor buffers, no arbitrary code execution on load (ADR-15).
  • Checkpoint lineage — the parent-checkpoint chain tracked across distillation rounds (§21).
  • FSDP (Fully Sharded Data Parallel) — a distributed strategy sharding optimizer state and gradients across ranks (ADR-16, Phase 10).
  • DDP (Distributed Data Parallel) — gradient all-reduce-based multi-GPU training (ADR-16).
  • Rank-0 aggregate — the pattern of computing a shared value (e.g. EMA update) on one rank and broadcasting it, avoiding divergent per-rank state (Phase 10).
  • All-reduce — the collective communication operation summing/averaging gradients across ranks.
  • Warmup — an initial LR ramp-up period during which EMA updates are suppressed (§8 state machine).
  • Grad-norm guard — the inline check skipping an optimizer step on a NaN/Inf loss (I9).
  • Sampler contract — the fixed shape/dtype output guarantee every registered sampler must satisfy (I13).
  • PreconditionMismatchError — raised when a checkpoint's preconditioning/schedule metadata disagrees with the requested load (§11, I3).
  • SamplerDivergenceError — raised when a sampler's trajectory numerically diverges, distinct from a contract violation (§11).
  • Patch token — one spatial unit of a patchified latent fed to a transformer block (Phase 8).
  • Backbone — the trainable denoiser network (U-Net or DiT) behind the DenoiserBackbone protocol (§11).
  • Denoiser — the function predicting a clean (or noise, or velocity) signal from a noisy input at a given noise level.
  • Score matching — estimating the gradient of the log data density, the theoretical ancestor of the diffusion reverse process (Song & Ermon 2019).
  • ELBO (evidence lower bound) — the variational training objective diffusion's simplified loss derives from (§8).
  • KL divergence — the statistical distance minimized between forward-process posteriors and the learned reverse process (§8).
  • Teacher / student — the frozen reference model and the trainable model in a distillation round (Phase 9).
  • Rescale trick — a guidance-output variance correction reducing over-saturation at high w (Lin et al. 2024).
  • Differential testing — comparing this codebase's output against a reference implementation (diffusers) on fixed seeds for numerical parity (Phase 11).
  • Soak test — a long-duration (24h) continuous run checking for leaks/degradation (Phase 11).
  • Fault injection — deliberately triggered failures (crash, NaN, OOM) verifying documented recovery paths (Phase 11).
