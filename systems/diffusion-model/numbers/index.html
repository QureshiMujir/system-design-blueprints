34. Back-of-Envelope Capacity Model

  1. Optimizer memory, CIFAR U-Net (35M params, fp32). params × bytes × (weights + grads + 2 Adam moments + EMA) = 35,000,000 × 4B × 5 = 700 MB. Consistent with §4's 560MB stored checkpoint size (stored form omits transient gradient buffers, keeping only weights+EMA+ optimizer-state-for-resume).

  2. Activation memory, CIFAR U-Net training, batch 256, fp32. batch × C_avg × H × W × layers × bytes ≈ 256 × 128 × 32 × 32 × 20 × 4B = ≈ 2.68 GB. Leaves headroom under §4's ≤6GB fp32 ceiling for the ≈700MB optimizer footprint (#1) plus framework overhead.

  3. Sampling latency, DDIM 50-step, batch 1, 32×32. NFE × step-ms = 50 × 4.2ms = 210 ms, matching §4's measured value exactly — implying a per-NFE backbone-forward cost of ≈4.2ms at batch 1, 32×32.

  4. Sampling latency, Heun 30-step, EDM, batch 1, 32×32. Heun is 2nd-order (2 backbone evals per step, §8 sampler catalogue) → effective NFE = 30×2 = 60. 60 × 4.2ms (from #3) = 252 ms, within §4's ≤260ms target (M7).

  5. Sampling latency, ancestral 1000-step, batch 1, 32×32. 1000 × 4.2ms (from #3) = 4,200 ms ≈ 4.2s, matching §4's stated 4.1s to within rounding.

  6. FID eval wall clock, 50k-sample, 32×32, 1000-step ancestral. wall_clock = n_batches × NFE × per-step-batched-ms. Given §4's measured 38 min (2,280s) and an eval batch of 512 (n_batches = 50,000/512 ≈ 98): per-step-batched-ms = 2,280s / (98 × 1,000) ≈ 23.3 ms — the implied batched-forward cost at batch 512, roughly 5.5× the batch-1 rate (#3) for a 128× larger batch, consistent with strong (not perfect) GPU batching efficiency.

  7. Latent-space memory saving, f=8 VAE. Spatial downsample factor f=8 → f² = 64× reduction in H×W at matched channel count and batch — the activation-memory formula's H×W term (from #2) drops 64×, which is why 256×256-pixel-equivalent training (32×32 latent) fits the same memory envelope as Phase 0's native 32×32-pixel training despite a 3→4 channel increase (a far smaller multiplier than the spatial saving).

  8. Dataset bytes, CIFAR-10. 60,000 images × 32×32×3 bytes (uint8) = 60,000 × 3,072 = ≈ 176 MB, matching §4's stated 170MB within compression/format overhead.

  9. Checkpoint size, DiT-XL (675M params, fp32 + EMA). params × bytes × (weights + EMA) = 675,000,000 × 4B × 2 = 5.4 GB, matching §4 exactly.

  10. FSDP per-rank optimizer-memory saving, DiT-XL, 8 ranks. Unsharded optimizer state (weights

    • grads + 2 Adam moments, excluding EMA which is replicated) = 675M × 4B × 4 = 10.8GB; sharded across 8 ranks = 10.8GB / 8 = ≈ 1.35 GB/rank — leaving the bulk of the §4 55GB-per-rank ceiling (M10) for activation memory, which FSDP does not shard.
