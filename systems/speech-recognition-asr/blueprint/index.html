388 — Speech Recognition (ASR) Pipeline from Scratch

Goal: Implement, from scratch in Rust, an end-to-end automatic speech recognition pipeline: a PCM waveform enters, a transcription exits (UTF-8 + word timings + confidence). The pipeline is the spine: audio I/O → front-end (pre-emphasis, framing, windowing, FFT, mel filterbank, MFCC/log-mel, CMVN, deltas) → acoustic model → pronunciation lexicon → language model → decoder → text. Two interchangeable acoustic models sit behind one trait: a classical GMM-HMM (diagonal-covariance Gaussian mixtures, Baum-Welch training, monophone→triphone with decision-tree state tying, Viterbi decoding) and a neural CTC model (CNN/BiLSTM encoder + CTC head, trained via #112). Decoding fuses the acoustic model with an n-gram LM via token-passing Viterbi / WFST-lite beam search. Crates: asr-core / audioio / frontend / gmm / hmm / lexicon / lm / am-neural / ctc / decoder / align / metrics / train / cabi / bench / conformance. It is a speech-recognition system modeling HTK and Kaldi (GMM-HMM + WFST), DeepSpeech/wav2letter (CTC) — not an FFT library (#369, a dependency), not an autograd framework (#112, a dependency), not a TTS or speaker-ID system, not a generic DSP toolkit. Correctness is validated by differential WER against Kaldi/HTK on a TIMIT-like fixture set, by forced-alignment sanity (synthetic TTS-aligned audio with known boundaries), by HMM/CTC invariants (forward=backward probability, scaled-likelihood consistency, monotone alignment, LM normalization), and by deterministic-seed reproducibility; performance by real-time factor (RTF) and WER vs SNR.

1. Goal

1.1 Engineering Definition

From-scratch ASR pipeline: decode audio → Signal (mono PCM, f32, 16 kHz) → front-end (pre-emphasis → framing 25 ms/10 ms → Hamming window → FFT (#369) → power spectrum → mel filterbank → log → DCT → MFCC / log-mel + deltas + CMVN) → acoustic model (GMM-HMM classical OR CNN/BiLSTM+CTC neural) → pronunciation lexicon (word → phone sequences) → n-gram LM → decoder (token-passing Viterbi / WFST-lite beam, LM-fused) → word sequence + timings + confidence. FFT from #369; neural training from #112; matrix ops from #349; GMM/k-means/clustering from #372.

1.2 System Boundaries

  • In scope: mono 8/16 kHz PCM; WAV/raw I/O + resampling; front-end (pre-emphasis, framing, windowing, FFT power spectrum, mel filterbank, MFCC + log-mel, liftering, delta/delta-delta, CMVN, dithering); diagonal-covariance GMMs + EM; HMM (left-to-right, forward-backward with scaling, Baum-Welch, Viterbi, embedded training); monophone → context-dependent triphone with decision-tree state tying; pronunciation lexicon + simple G2P; n-gram LM (counts, backoff, Kneser-Ney, perplexity); neural acoustic model (CNN/BiLSTM encoder + CTC, via #112); CTC loss + greedy/beam decode; token-passing Viterbi decoder + WFST-lite (HCLG composition) + LM shallow fusion; word lattice; forced alignment; WER/CER (edit-distance alignment); model serialization; C ABI; CLI.
  • Out of scope (non-goals): FFT/DFT → #369 (dependency); autograd/backprop → #112 (dependency); dense linear algebra → #349 (dependency); GMM/k-means internals → #372 (dependency, reused); GPU train/infer → PhaseDeferred("§39"); speaker diarization / speaker-ID / verification → PhaseDeferred("§39"); text-to-speech (the inverse) → out of scope; end-to-end attention/transformer (LAS/Conformer) — CTC only Phase-0 → PhaseDeferred("§39"); RNN-Transducer (RNN-T) → PhaseDeferred("§39"); full WFST library (OpenFst-class determinization/minimization) — HCLG-lite only → PhaseDeferred("§39"); discriminative training (MMI/sMBR/LF-MMI) → PhaseDeferred("§39"); speaker adaptation (fMLLR/i-vector/x-vector) → PhaseDeferred("§39"); far-field/multichannel/beamforming → PhaseDeferred("§39"); large-corpus training (LibriSpeech 960 h) → PhaseDeferred("§39"); streaming/online endpointing — batch Phase-0 → PhaseDeferred("§39").

1.3 Deployment Model

Shipped as (a) Rust library crate (asr facade), (b) cdylib/staticlib C ABI (asr_*), (c) CLI asrc (recognize/align/train/decode/eval/bench over WAV → text/CTM/JSON). Single process, in-memory utterances, shared-memory thread pool (per-utterance parallel). No service, no persistence beyond model files + transcripts.

1.4 Target Users

Engineers who want to understand why MFCCs are 13 cepstral coefficients, what Baum-Welch actually re-estimates, how a triphone decision tree ties states, what CTC aligns when there are no phone boundaries, how a WFST composes acoustic/lexicon/LM into one decodable graph; downstream consumers (a voice-command system, a captioning pipeline, a search-over-speech index feeding #177).

1.9 Recommended Language & Rationale

Rust. (a) reuse #369 (FFT — the front-end's core transform), #112 (autograd → CNN/BiLSTM/CTC), #349 (BLAS → GMM/HMM matrix ops, neural GEMM), #372 (GMM/k-means EM, the classical-clustering substrate); (b) ownership makes the staged pipeline (Signal → Features → Lattice → Text) a compile-checkable state machine and the GMM-HMM train↔decode state explicit; (c) zero-cost hot loops (the Baum-Welch forward-backward, the Viterbi token-passing beam, the CTC forward-backward) with no GC pauses mid-utterance; (d) extern "C" clean engine ABI; (e) Send+Sync → per-utterance parallel decode + parallel EM accumulation. Rejected: C++ (HTK/Kaldi's language — studied as the oracle; rejected for ABI instability, weaker ownership over the accumulator/lattice lifecycle, harder differential tooling); Python (research-prototyping; hot loops are C/CUDA and "from scratch" forbids leaning on librosa/torchaudio/NumPy); C (HTK-style — too little type safety for the lattice/lexicon graphs); Julia (calls FFTW/LAPACK — defeats "from scratch").

1.10 Prerequisites

Digital signal processing (sampling, windowing, the DFT/FFT from #369, filterbanks, cepstrum); probability/statistics (Gaussians, mixtures, EM, MAP/ML); HMM theory (forward-backward, Viterbi, Baum-Welch — the classical core); information theory (entropy, perplexity, mutual-information state clustering); machine learning (gradient descent #112, k-means #372); sequence modeling (CTC, beam search, WFST composition); linguistics (phonetics, pronunciation, G2P); concurrency (parallel EM/decoding). Helpful: #369 (FFT), #112 (autograd), #372 (GMM/k-means), #387 (OCR — shares CTC/beam/LM/edit-distance), #177 (index — downstream).

2. Why Build This

2.1 Unique Knowledge Taught

  • The cepstral front-end. Why we frame at 25 ms/10 ms, why the mel scale, why a log, why a DCT (decorrelation → diagonal-covariance GMMs become viable), what deltas and CMVN buy. MFCC is the canonical "turn a waveform into a sequence of feature vectors" recipe.
  • EM as a fixed-point on a latent variable. GMM EM (responsibilities → re-estimate) and its lift to Baum-Welch (the HMM's forward-backward occupancy → re-estimate transitions + emissions). The single deepest classical-ML idea, built twice.
  • Decoding as shortest-path on a composed graph. The WFST insight: the acoustic model (H), context (C), lexicon (L), and grammar (G) are weighted transducers; HCLG composition makes recognition a single Viterbi search. Even the lite version teaches why Kaldi looks the way it does.
  • Context-dependent modeling + state tying. Why monophones underfit, why triphones explode (|phones|³), and how a phonetic decision tree ties acoustically-similar states to share data — the bias-variance lever of classical ASR.
  • Alignment-free training (CTC). The same idea as #387: you have audio + a transcript but no phone boundaries; CTC marginalizes alignments. Built once, shared with OCR — proving the concept is modality-independent.
  • The LM rescues the acoustic model. A weak per-frame acoustic posterior + a strong n-gram prior, fused in beam search, is the canonical "noisy sensor + language prior" architecture (shared shape with #387).

2.2 Why It Matters

ASR is one of the defining applied-AI problems: HTK (Cambridge, 1990s) and Kaldi (2011) defined the GMM-HMM→WFST era; DeepSpeech (2014) and CTC opened the neural era. The pipeline underlies voice assistants, captioning, dictation, and call analytics. It exercises the full signal→symbol arc — DSP, probabilistic graphical models, weighted-automata search, and sequence learning — in one system, and is the direct sibling of OCR (#387) in architecture.

2.3 Engineering Muscles

Numerical DSP (FFT use, filterbanks, log-domain stability); dynamic programming at scale (forward-backward, Viterbi token-passing, CTC); EM optimization; graph/automata algorithms (WFST composition, lattice generation); search under a probabilistic model (beam, LM fusion, pruning); differential testing vs a mature reference (Kaldi/HTK); deterministic reproducibility; staged-pipeline + train/decode API design.

2.4 Production Concepts Exercised

Real-time factor (RTF) budgets; streaming-vs-batch tradeoffs (batch Phase-0); model versioning + serialization; confidence + lattice posteriors (knowing when the ASR is unsure); WER measurement methodology (sclite-style alignment); reproducible training recipes; robustness to SNR/channel; graceful failure on silence/noise.

2.7 What Mastery Looks Like

After building this, you can:

  • Derive the MFCC pipeline from first principles and justify every parameter (25/10 ms framing, mel spacing, the log, the DCT-to-13-coefficients, deltas, CMVN) — and predict the WER consequence of mis-pinning any of them against an oracle (built in Phase 2, §14; deepened in MM1).
  • Implement EM as a fixed point twice — GMM responsibilities (Phase 3, §15) and its lift to Baum-Welch occupancy/transition re-estimation (Phase 4, §16) — and prove monotonic likelihood (I6), debugging a sign/accumulator bug from the likelihood curve alone.
  • Build context-dependent acoustic modeling end to end — clone monophones to triphones and tie states with a phonetic decision tree maximizing ML gain (Phase 6, §18) — and reason quantitatively about the bias-variance lever (leaf budget vs occupancy, MM4).
  • Decode as shortest-path on a composed weighted graph — token-passing Viterbi over HCLG with explicit beam/max-active pruning, LM fusion, and lattice generation (Phase 9, §21) — and disentangle search errors from model errors using oracle-WER + a beam sweep (MM5).
  • Implement and prove the CTC objective — blank-augmented log-space forward-backward with finite-difference-verified gradients (Phase 11, §23) — and explain why it is the alignment-free dual of Baum-Welch, shared verbatim with OCR #387 (MM6).
  • Quantify a recognizer's operating point — compute frames/sec, real-time factor, feature/lattice memory, and beam-search cost from constraints before writing code (Back-of-Envelope Capacity Model, §36) — and set a defensible RTF/WER budget (Phase 13, §25).
  • Redesign the system knowing the tradeoffs — choose HMM-GMM vs DNN-HMM hybrid vs CTC vs RNN-T/attention for a given latency/data/accuracy regime (Alternative Architectures, §38) — and name the real system (Kaldi, Whisper, DeepSpeech, RNN-T on-device) that embodies each.

3.2 Box Narratives

  • Public API / asr facade. Re-exports the staged entry points; recognize(&Signal,&Config,&Model) -> (Transcript, Lattice). Thin — validates sample rate/dtype, selects AM (classical|neural), orchestrates stages, holds no learning logic. Enforces stage ordering at the type level (§3.4).
  • cabi ABI. #[repr(C)] opaque AsrEngine*/AsrResult*; marshals a float*+len+sample-rate into a Signal; walks the result (1-best text, word CTM timings, lattice density, confidence) via index accessors; never unwinds across the boundary (catch → code).
  • asr-core. The vocabulary. Signal (mono f32 + sample rate); FeatureMatrix (T frames × D dims); Phone/Word/Token; Lattice (word graph with acoustic + LM weights); Confidence∈[0,1]; AsrError; seeded Rng (no global RNG, I7). No algorithms.
  • audioio. WAV (PCM 16/24-bit + float) read/write; raw PCM; resampling (polyphase to the model's rate); mono mixdown; optional dithering. Produces the canonical Signal (16 kHz mono f32) the front-end expects.
  • frontend. Signal → FeatureMatrix. Pre-emphasis (high-pass) → framing (25 ms window, 10 ms hop) → window (Hamming/Hann) → FFT (#369) → power/magnitude spectrum → mel filterbank (triangular, mel-spaced) → log → DCT → MFCC (keep 13) + liftering, OR log-mel (for neural); append delta + delta-delta; CMVN (per-utterance/global mean-variance normalization). The fixed, tested "waveform → vectors" contract.
  • gmm. Classical AM emission. Diagonal-covariance Gaussians + mixtures (reuse #372); EM (responsibilities → re-estimate means/vars/weights); log-likelihood log p(x|state); mixture splitting (1→2→4… components). Each HMM state's emission is a GMM.
  • hmm. Classical AM. Left-to-right topology (3 states/phone typical); scaled forward-backward (avoid underflow); Baum-Welch re-estimation (occupancy γ, transition ξ → update A, emissions); Viterbi (best path); embedded training (concatenate phone HMMs per utterance transcript, no boundaries needed — the EM that learns from un-segmented audio).
  • lexicon. Word → phone-sequence dictionary; a simple rule/seq2seq G2P fallback for OOV words; the phone set + silence/optional-silence handling. The bridge from sub-word acoustics to words.
  • lm. n-gram language model: counts → backoff / Kneser-Ney smoothing; perplexity; ARPA format I/O. The decode-time word prior (the LM-rescue, principle 6).
  • am-neural. Neural AM. CNN (spectral) + BiLSTM (temporal context) encoder → linear → softmax → T×(|phones∪chars|+1) CTC posteriors; trained via #112. The segmentation-free alternative to GMM-HMM.
  • ctc. The alignment-free bridge (shared verbatim with #387). Training: blank-augmented forward-backward → −log p(label|posteriors) + gradient (to #112). Inference: greedy + prefix-beam (with LM fusion).
  • decoder. Fuses AM + lexicon + LM. Token-passing Viterbi beam over the HMM/lexicon/LM graph (classical) OR WFST-lite: compose H (HMM) ∘ C (context) ∘ L (lexicon) ∘ G (grammar/LM) into HCLG, then Viterbi-search the composed graph. Emits a word lattice + 1-best + word timings + confidence; beam + LM-weight + word-insertion-penalty tunable.
  • align. Forced alignment: Viterbi against a known transcript → phone/word time boundaries (for training data prep, evaluation, and timing output). Uses the same HMM/CTC machinery constrained to one path.
  • metrics. WER/CER via Levenshtein alignment (the edit-distance shared with #387, here over words); sentence accuracy; substitution/insertion/deletion breakdown; sclite-style alignment report.
  • train. Builds models. GMM-HMM recipe: feature stats → flat start (uniform segmentation) → monophone Baum-Welch → mixture splitting → triphone + decision-tree state tying → re-train. Neural recipe: CTC SGD on #112 (LR schedule, validation WER, early stop). All deterministic per seed (I7).
  • bench. Real-time factor (RTF = decode-time / audio-duration), per-stage latency, WER vs SNR, classical-vs-neural A/B, decoder beam/RTF tradeoff. Pinned, median-of-k.
  • conformance. Synthetic-alignment ground truth (TTS-rendered audio with known phone times), the Kaldi/HTK differential harness (offline golden WER), pipeline-invariant asserts, fuzzing (silence/noise/clipping/huge audio).

3.3 Boundaries

  • Trust boundary: C ABI (untrusted len/pointer/sample-rate/config → validated) + untrusted audio (NaN/Inf/clipped/huge → bounded, never UB) + untrusted model files (version/checksum-checked, I14).
  • Concurrency boundary: utterances are independent; EM accumulation is per-utterance then reduced; decode is per-utterance → data-parallel by construction (I11).
  • Numerical boundary: everything probabilistic is in log-space (forward-backward, Viterbi, GMM likelihood, CTC, LM); FP reductions are order-dependent → match Kaldi/HTK within WER tolerance, not bit-for-bit (ADR-15).
  • Time-frame boundary: features, alignments, and lattice arcs share one frame index → time map (frame → seconds via hop); timings emitted in seconds (I1).
  • Stage-ordering boundary: the type system forbids decoding un-featurized audio or training a triphone system before a monophone one (typed stage handles, I3).

3.4 Data-flow walk — one recognize (classical GMM-HMM + WFST-lite)

  1. audioio reads utt.wav → mono f32 → resample to 16 kHz → Signal.
  2. frontend: pre-emphasis → frame (25/10 ms) → Hamming → FFT (#369) → power → mel → log → DCT → 13 MFCC + Δ + Δ² → CMVN → FeatureMatrix T×39.
  3. Acoustic scoring: per frame, per tied-state GMM log p(xₜ|s) (#372/#349 batched).
  4. decoder (WFST-lite): Viterbi token-passing over HCLG (H∘C∘L∘G); beam-prune; LM weight + word-insertion penalty applied on word arcs.
  5. Backtrace → word sequence; generate a lattice; per-word confidence from lattice posteriors (I10); word timings from frame indices (I1).
  6. Assemble Transcript (words + times + conf) + Lattice; output::ctm emits utt chan start dur word conf.
  7. Optional UttTrace (per-stage ms, RTF, active tokens, beam, AM/LM scores, lattice density).

3.5 Data-flow walk — one recognize (neural CTC path)

  1. audioio reads utt.wav → mono f32 → resample to 16 kHz → Signal (identical to §3.4 step 1 — the front of the pipeline is shared).
  2. frontend: pre-emphasis → frame → window → FFT (#369) → power → mel → log-mel (skip the DCT — neural nets don't need decorrelation, MM1) + Δ + CMVN → FeatureMatrix (e.g. T×120 log-mel+Δ).
  3. am-neural: CNN (over the time×mel image) → BiLSTM (whole-utterance temporal context) → linear CTC head → softmax (log-space) → Posteriors T'×(|A|+1) over phones/chars + blank (#112 forward, #349 GEMM; I4).
  4. ctc decode: greedy (argmax→collapse repeats→strip blank, I5) for a fast 1-best, or prefix_beam fused with the n-gram LM (shallow fusion, MM7) for the accurate path.
  5. Word sequence from the collapsed label stream; timings from encoder time-step → input frame → seconds (the documented frame-rate map, I1); confidence from posterior mass.
  6. Assemble Transcript; output::ctm emits timed words. The decoder/lattice machinery (§3.4 steps 4–6) is bypassed — CTC is alignment-free and needs no HCLG.
  7. UttTrace (encode ms, CTC ms, beam, LM score, mean word conf, RTF). Contrast with §3.4: same audio/front-end front, but the GMM-HMM emission + WFST search is replaced by a learned encoder + CTC collapse — the two acoustic models are interchangeable behind one trait (P4).

4.1 Worked complexity derivation

T frames, D feature dims, S HMM (tied) states, M GMM components, A alphabet (CTC), B beam:

  • Front-end: T frames × (window O(N) + FFT O(N log N) #369 + mel O(N·mel) + DCT O(mel·ceps)) ⇒ O(T·N log N) dominated by FFT.
  • GMM likelihood: per frame, per state, per component O(D) ⇒ O(T·S·M·D); batched as GEMM via #349.
  • Forward-backward / Baum-Welch: O(T·S²) (dense) or O(T·S·fanout) (sparse left-to-right ≈ O(T·S)); scaled per frame.
  • Viterbi token-passing: O(T · active-tokens · arc-fanout); beam keeps active-tokens ≪ |HCLG states|.
  • WFST composition (HCLG): offline graph build O(|H|·|C|·|L|·|G|) with on-the-fly composition to bound memory.
  • CTC forward-backward: lattice 2|label|+1 × T ⇒ O(T·|label|), log-space (shared with #387).
  • CTC prefix-beam: O(T·B·A) + LM lookups. Constants dominated by #369 FFT (front-end) and #349 GEMM (GMM/neural); decode is beam-bound at scale.

6. Design Principles

  1. Correctness before speed; Kaldi/HTK + synthetic alignment are the oracles. Gate every stage on WER vs the reference and forced-alignment vs known boundaries before optimizing. Violation: tuning RTF on an uncalibrated decoder → fast wrong transcripts.
  2. Everything probabilistic lives in log-space. Forward-backward, Viterbi, GMM likelihood, CTC, LM — log-domain with log-sum-exp; scaled where needed (HMM). Violation: linear-domain products → underflow to zero → NaN/garbage on any real utterance.
  3. Stages are typed and ordered; you cannot skip one. Signal → FeatureMatrix → (likelihoods|posteriors) → Lattice → Transcript, and Monophone → Triphone as distinct trained types. Violation: training triphones before a monophone alignment exists → garbage tree.
  4. The acoustic model is pluggable behind one trait; classical and neural are interchangeable at the decoder. GMM-HMM and CNN/BiLSTM+CTC both produce per-frame scores the decoder consumes. Violation: a decoder welded to GMMs → can't compare or swap the neural path.
  5. EM/Baum-Welch monotonically increases (data) likelihood; assert it. Each re-estimation iteration cannot decrease the training likelihood (modulo numerics). Violation: a sign/accumulator bug → oscillating likelihood, silently bad models.
  6. CTC is the alignment contract (shared with #387): blank-augmented forward-backward, log-space, deterministic collapse. Violation: ad-hoc per-frame argmax without blank semantics → duplicated/dropped tokens.
  7. The language model is a separable, tunable decode-time prior, never baked into the AM. LM weight + word-insertion penalty are beam-search terms. Violation: hard-coding the grammar → can't tune or swap the LM, can't do open-vocabulary.
  8. Deterministic given a seed (and thread count + model). All randomness (EM init, flat-start, augmentation, beam ties) from an explicit seeded Rng. Violation: irreproducible training/decoding → untestable.
  9. Decoding is shortest-path on a weighted graph; pruning is explicit and tunable. Token-passing/WFST Viterbi with an explicit beam + max-active; pruning never silently changes the model. Violation: implicit pruning → irreproducible, undebuggable search errors.
  10. Numerical behavior is a WER-tolerance contract, not bit-equality. Promise per-AM WER bounds vs the oracle; reductions order-deterministic per config. Violation: promising bits → broken by any GEMM/FFT order change.
  11. Reuse #369/#112/#349/#372; never reimplement a dependency. FFT, autograd, BLAS, GMM/k-means go through their owning projects. Violation: a private FFT → numeric drift + duplicated maintenance.
  12. Bounded memory; stream utterances, parallelize across them. O(T·D) features + O(active tokens), not O(utts·…) materialized. Violation: whole-corpus buffering → OOM on a long recording.
  13. Validate inputs and config at the boundary. Zero-length audio, absurd sample rate, NaN config, clipped samples, incompatible model version → typed error pre-compute. Violation: trusting inputs → panics, OOB, garbage transcripts.
  14. Observability by default. Every utterance can emit per-stage timings, RTF, active-token counts, AM/LM scores, lattice density, confidence, WER on a labeled eval set. Violation: opaque failures → can't localize "which stage produced garbage."

Determinism: ties (equal score reaching a state) break to the lowest state index (I5/I7), so the same (audio, seed, beam, model) yields the same lattice.

8.10 Worked recognition trace (prose, classical path)

Utterance "yes" (≈0.4 s, 16 kHz). audioio decodes → 6 400 samples → Signal. frontend: 25 ms/10 ms framing ⇒ T = floor((6400−400)/160)+1 = 38 frames; each → 13 MFCC + Δ + Δ² ⇒ a 38×39 FeatureMatrix after CMVN. decoder builds HCLG-lite from the lexicon entry yes → /j/ /ɛ/ /s/ (3 phones × 3 HMM states = 9 emitting states) ∘ the trigram G. Token passing: frame 0 seeds a token at the start state; each frame adds the tied-state GMM log p(x_t|s) (batched GEMM, #349) plus transition log-probs; at the /s/→</s> word arc the LM adds lmwt·log P(yes|<s>) and the word penalty. Beam pruning (beam=12, max_active=2000) keeps active tokens ≈ tens. At t=38 the best Final token backtraces to the word "yes" with frame range [2,36] ⇒ timing t_beg = 2×0.01 = 0.02 s, dur = 0.34 s (I1). Lattice forward-backward gives arc posterior ⇒ conf = 0.93 (I10). output::ctm emits utt1 1 0.02 0.34 yes 0.93. UttTrace: front_end_ms≈0.4, am_score, lm_score, peak_active≈40, lattice_density≈1.1, rtf≈0.3.

13. Phase 1 — Front-end I (pre-emphasis, framing, windowing, FFT, power spectrum)

13.1 Objectives

  • Pre-emphasis → framing (25 ms/10 ms) → windowing (Hamming/Hann) → FFT (#369) → power/magnitude spectrum.
  • The spectral representation P2 turns into MFCC/log-mel.

13.2 Detailed Implementation Steps

  • frontend::preemphasis — y[n]=x[n]−a·x[n−1] (a≈0.97); the high-pass that boosts high formants (Davis & Mermelstein 1980; MM1).
  • frontend::framing — overlapping frames (win=400, hop=160 @16k); edge handling (pad/drop last partial); the frame index is the single time map (I1).
  • frontend::window — Hamming/Hann coefficients (precomputed); apply per frame; pin periodic-vs-symmetric to match the oracle (ADR-31, P1).
  • frontend::spectrum_369 — FFT each windowed frame via #369 (no private DFT, P11/ADR-3); |X[k]|² power (or magnitude); keep N/2+1 bins.

13.3 Deliverable

  • frontend (spectrum) green vs a hand-computed reference + librosa golden (pinned params); spectrogram emitted.

13.4 Acceptance Criteria

  • Power spectrum matches a reference within rtol=1e-5 on a sinusoid (single-bin energy) and on speech.
  • Framing count = floor((len−win)/hop)+1; window applied correctly (DC/Nyquist handling).
  • FFT via #369 (no private DFT, principle 11).

13.5 Conformance Fixtures

  • frontend/{preemphasis,framing_count,hamming_window,power_spectrum_sinusoid,spectrogram_speech}.

13.6 Pitfalls

  • Frame count off-by-one (partial last frame) — pin the convention (drop or pad), match the oracle.
  • Window normalization / periodic-vs-symmetric Hamming differs by library → pin ours, document (ADR-31).
  • FFT size vs window size (zero-pad win 400 → N=512) — pad explicitly; bins map to Hz via N.
  • Power vs magnitude vs log inconsistency downstream — fix "power spectrum" here.

13.7 Performance Concerns

  • FFT dominates the front-end (O(T·N log N) #369); reuse a planned FFT; batch frames.
  • Pre-emphasis/window are O(T·N) trivial passes.

13.8 Edge Cases

  • Audio shorter than one window (zero-pad to one frame); DC-only / silence; full-scale sinusoid; very long audio (stream frames).

13.9 Failure Analysis

  • Wrong spectrum → every downstream feature wrong → the sinusoid fixture (known single-bin energy) localizes it.
  • Blast: the front-end feeds every acoustic model.

13.10 Operational Notes

  • UttTrace: n_frames, FFT size, front-end ms.
  • docs/performance/frontend-fft.md: FFT cost + batching.

14. Phase 2 — Front-end II (mel filterbank, MFCC, deltas, CMVN, log-mel)

14.1 Objectives

  • Mel filterbank → log → DCT → MFCC (13) + liftering; log-mel (neural); delta + delta-delta; CMVN.
  • The final FeatureMatrix (e.g. 39-dim MFCC+Δ+Δ²) both AMs consume.

14.2 Detailed Implementation Steps

  • frontend::melbank — triangular mel filters (mel-spaced center freqs); apply to power spectrum → n_mel energies; pin HTK vs Slaney mel (ADR-31; Davis & Mermelstein 1980).
  • frontend::mfcc — log mel energies → DCT-II → keep n_ceps=13 → sinusoidal liftering; the DCT decorrelates so diagonal-covariance GMMs become valid (MM1; ADR-10).
  • frontend::logmel — log mel energies directly (neural input; skip DCT — neural nets don't need decorrelation, MM1; ADR-10).
  • frontend::delta — regression deltas (±2 frames) + Δ² of Δ; append; the dynamic features the HMM emission can't capture (Rabiner & Juang).
  • frontend::cmvn — per-utterance (and/or global) mean-variance normalization (channel/speaker robustness, P1); stats per dim over time, never per frame (the classic axis bug, §14.6).

14.3 Deliverable

  • frontend (MFCC/log-mel) green vs librosa/HTK golden (pinned params); 39-dim features.

14.4 Acceptance Criteria

  • MFCC matches the pinned-param oracle within rtol=1e-4 (DCT/lifter/mel conventions exact, ADR-31).
  • Deltas match the regression-window reference; CMVN zero-mean/unit-var per utterance.
  • log-mel matches mel-energy log (neural path).

14.5 Conformance Fixtures

  • frontend/{melbank_triangular,mfcc_13,lifter,delta_deltadelta,cmvn_zeromean,logmel}.

14.6 Pitfalls

  • Mel formula variant (HTK 2595·log10(1+f/700) vs Slaney) — pin one, document (ADR-31); mismatches the oracle otherwise.

15. Phase 3 — GMM (diagonal-covariance Gaussians + EM via #372)

15.1 Objectives

  • Diagonal-covariance Gaussians + mixtures (reuse #372); EM training; log-likelihood; mixture splitting.

  • gmm::gaussian_diag — N(x;μ,diagΣ) log-density; precompute log_det + inverse-variance; diagonal assumes decorrelated features (why the DCT, MM1; ADR-7).

15.8 Edge Cases

  • Single component (= one Gaussian); 1-dim features; identical training points (variance floor); empty component after E-step (reinit).

15.9 Failure Analysis

  • Non-monotone EM → accumulator/sign bug → likelihood-monotone fixture (I6).

15.10 Operational Notes

16. Phase 4 — HMM I (scaled forward-backward + Baum-Welch)

16.1 Objectives

  • Left-to-right HMM topology; scaled forward-backward (I2, no underflow); Baum-Welch re-estimation (occupancy γ, transition ξ → update A + emissions, I6).
  • The training engine for the classical AM.

16.2 Detailed Implementation Steps

  • hmm::topology — 3-state left-to-right per phone (the Bakis topology); self-loop + forward transitions only (no skips Phase-0); log_a the log transition matrix (Rabiner 1989).
  • hmm::scaling/forward_backward — scaled α/β with the per-frame scale c_t = 1/Σ_s α_t(s) recorded so P(O) = Π_t (1/c_t) is recoverable (I2), OR a pure log-domain α/β with log-sum-exp; the two paths must agree (§16.4). β scaled by the same c_t to keep γ consistent.
  • hmm::baum_welch — occupancy γ_t(s) = α_t(s)β_t(s)/P(O); transition ξ_t(s,s'); for GMM-HMM the per-component occupancy γ_t(s,m) (state × mixture) is the emission-update statistic, not the state γ (the coupling bug, §16.6); accumulate sufficient stats (Σγ, Σγ·x, Σγ·x², Σξ) into BwAccum in f64 (parallel-reducible across utterances, I11); re-estimate Â, and μ̂/Σ̂/ŵ of each GMM (this is the M-step that reuses #372's re-estimation, MM2).
  • train glue — one EM iteration = E-step (forward-backward over every utterance, accumulate) → reduce → M-step (re-estimate) → assert ℒ↑.
  • Assert training likelihood non-decreasing across iterations (I6); a decrease beyond numeric tolerance halts with likelihood_drop (MM2).

16.3 Deliverable

  • hmm forward-backward + Baum-Welch green vs a hand-computed small HMM; likelihood monotone.

16.4 Acceptance Criteria

  • Forward P(O) == backward P(O) within ε (I2 consistency); scaled and log paths agree.
  • On a 2–3 state toy HMM, α/β/γ/ξ match hand-computed values within rtol=1e-6.
  • Baum-Welch likelihood non-decreasing (I6); converges on a synthetic source HMM (recovers parameters).

16.5 Conformance Fixtures

  • hmm/{forward_backward_toy,alpha_beta_consistency,baum_welch_monotone,recover_synthetic_hmm}.

16.6 Pitfalls

  • Underflow without scaling/log → α→0 on long T → NaN; scale per frame and record scales (I2).
  • ξ accumulation across the wrong transition pair → wrong A; test on the toy HMM.
  • Mixing scaled and unscaled quantities in re-estimation → wrong γ; keep the domain consistent.
  • Re-estimating emissions on the wrong occupancy (state vs mixture-component γ) — the GMM-HMM coupling bug.

16.7 Performance Concerns

  • Forward-backward O(T·S²) dense → O(T·S) for left-to-right (sparse transitions); exploit sparsity.
  • BwAccum reduction across utterances is the parallel win (I11); accumulate in f64.

16.8 Edge Cases

  • Single-state HMM; T < states (infeasible left-to-right path → guard); all-silence; one-frame utterance.

16.9 Failure Analysis

  • α/β inconsistency or non-monotone likelihood → the toy-HMM + monotone fixtures localize (I2/I6); em-nonmonotone.md.
  • Blast: Baum-Welch trains the entire classical AM.

16.10 Operational Notes

  • train log: per-iteration total log-likelihood, scale statistics.
  • tools/align_viz overlays the γ occupancy heatmap (state × frame).

21. Phase 9 — Decoder (token-passing Viterbi / WFST-lite HCLG + LM fusion; first LVCSR)

21.1 Objectives

21.2 Detailed Implementation Steps

23. Phase 11 — CTC loss + decode (the alignment-free neural path; shared with #387)

23.1 Objectives

23.2 Detailed Implementation Steps

  • train::ctc_train — CTC SGD on #112 (ADR-4): Adam, warmup + LR schedule, gradient clipping (divergence guard, §23.6), validation-WER early stop; deterministic per seed (I7).

  • ctc/{forward_backward_small,grad_finite_diff,alpha_beta_consistency,greedy_collapse,logspace_stable_longT}; am-neural/ctc_train_overfit.

Structural defenses the design provides for free. Several whole threat classes are eliminated by the architecture, not patched by checks: (a) the typed stage handles (I3) make "decode un-featurized audio" or "use an untrained model" a compile error, not a runtime exploit; (b) Rust ownership + #![forbid(unsafe_code)] outside the thin cabi shim removes the entire memory-safety class (use-after-free, double-free, data races) that dominates HTK/Kaldi's C/C++ attack surface — the only unsafe is the FFI marshalling, audited and catch_unwind-wrapped (I12); (c) log-space everywhere (P2/I4) structurally bounds scores away from the underflow that turns a crafted utterance into NaN-propagation; (d) per-utterance isolation (I11) means one malicious input cannot corrupt another utterance's state — there is no shared mutable decode state to attack; (e) crash-only design (§27) means there is no long-lived state for a fault to leave half-written. The residual surface the table covers is therefore narrow: arithmetic bounds (I13), resource caps, serialization integrity (I14), and pathological-audio DoS — exactly the classes a pure compute library cannot design away.

Forensic methodology — localize the stage before blaming the model. A mis-recognition is debugged top-down through the pipeline (§3.4), using the per-stage UttTrace (§28) to bisect: (1) is the front-end right? — diff the FeatureMatrix against the pinned-param oracle (rules in/out front-end skew, the most common silent killer, MM1); (2) is the acoustic model right? — force-align the utterance against its true transcript and inspect the alignment likelihood + boundaries (rules in/out an undertrained AM); (3) is the search right? — compute lattice oracle-WER (the best path in the lattice vs the reference) and sweep the beam: if oracle-WER is low but 1-best WER is high, it's a search error (widen beam), else a model error (MM5, MM10); (4) is the LM right? — inspect the WER S/I/D breakdown: excess insertions ⇒ LM weight too low or penalty wrong, excess deletions ⇒ the reverse (MM7/MM9). Every step maps to a named runbook (§28) and a telemetry field, so "the transcript is wrong" becomes a four-question decision tree, not a guess.

29. Compatibility Guarantees

  • C ABI: asr_* signatures + params/error-code + result-accessor layout frozen — changing them is SemVer-major. SONAME tracks ABI. Params additive-only.
  • Model serialization: model_version + feature-spec hash checked on load; format change bumps it; old models load via migration or reject with IncompatibleVersion (I14) — never silently mis-decode. Schema documented.
  • Numeric behavior: per-AM WER tolerance vs oracle is the contract, not bit-reproducibility across thread counts. A within-tol change = minor + CHANGELOG (ADR-30); deterministic mode (ASR_DETERMINISTIC, ADR-26) is itself a stable contract.
  • Feature conventions: the MFCC/log-mel parameter set is pinned (ADR-31); changing it is a model-incompatible change (new model_version).
  • Formats: WAV (RIFF), ARPA (LM), CTM (output) conform to their specs; ARPA is interoperable with #387's LM.
  • API (Rust): SemVer; #[non_exhaustive] on AsrError/AmKind/CmvnMode; the stage types + AM trait stable.
  • Kaldi/HTK parity: against a pinned version + recipe; bumping it (may shift golden WER) is deliberate.
  • Config defaults: a default change that alters output (beam, lmwt, AM) = minor + CHANGELOG.
  • Deprecation: one minor-version warning cycle before removal.

33. Scalability Analysis

  • Audio-length scaling (T): front-end O(T·N log N); forward-backward/Viterbi O(T·S); decode O(T·active-tokens) — long utterances are decode-bound; lattice memory ∝ T.
  • Vocabulary/LM scaling: HCLG size ∝ |L|·|G|; on-the-fly composition + pruning bound memory; larger LM ⇒ bigger G ⇒ more arcs.
  • Tied-state scaling (S): decode cost ∝ active tied states; the decision tree's leaf budget is the lever.
  • Utterance scaling: utterances are embarrassingly parallel (independent decode; EM accumulate-reduce) → near-linear across cores (≥0.8×, I11).
  • Memory: O(T·D) features + O(active tokens + lattice) per utterance; models O(params) mmap-shared; EM stats reduced in f64.
  • Does NOT scale (by design): GPU train/infer (§39); multi-node training (→ #115); streaming/online (§39); full OpenFst-scale WFST ops (§39).
  • Coordination: none (no metadata service); pure in-process compute; corpus decode/train is a local map(-reduce) over utterances.

Named bottlenecks, in the order they bite (single-utterance decode at the §4 scale): (1) decoder beam search — the RTF driver; active-token count, not graph size, dominates (the lever: beam/max-active, MM5; §36 #6/#8); (2) acoustic scoring — GMM GEMM (#349) or BiLSTM matmuls (#349), GEMM-bound (the lever: batching, precomputed constants; §36 #4/#10); (3) HCLG memory — fully-composed graph is ∝|L|·|G| (the lever: on-the-fly composition, §39); (4) lattice memory — ∝ active×T (the lever: lattice_beam); (5) front-end FFT — last to bite, ~5 ms/s (§36 #3). Practical ceiling and the levers beyond it: single-core CPU caps at RTF ~1.0 (classical) / ~1.5 (neural); within a node, per-utterance parallelism scales near-linearly to core count (M9). Beyond that, the levers are out of scope by design — GPU acoustic scoring (§39), a statically-compiled+minimized HCLG for repeated large-LM decode (§39), or multi-node corpus sharding (→ #115). The single-utterance latency floor (you cannot parallelize one short utterance below its critical path) is the hard wall streaming (§39) addresses by emitting partial results, not by going faster.

34. Mental Models & First Principles

The compressed insights a principal ASR engineer holds. Each: the model, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — The front-end is a lossy, deliberate projection: waveform → a sequence of decorrelated, perceptually-warped, log-compressed vectors. Every step discards information on purpose (phase, fine spectral detail, channel mean) so the acoustic model sees only what distinguishes phones. Predicts: changing any front-end parameter (mel formula, DCT norm, lifter, CMVN axis) shifts WER systematically with no crash; the front-end caps achievable accuracy. Bug class without it: "my model trains fine but WER is 8% worse than the paper" — silent train/serve feature skew or an oracle-mismatched convention. Applied: Phase 1–2 (§13–§14), ADR-10/ADR-31, I1.
  • MM2 — EM is coordinate ascent on a lower bound; the E-step fills in the latent variable, the M-step re-fits, and the data likelihood never decreases. GMM responsibilities and HMM occupancy γ are the same idea at two scales. Predicts: a correct implementation's training likelihood is monotone non-decreasing; any drop is a bug, not bad luck. Bug class without it: treating an oscillating likelihood as "needs more iterations" instead of finding the sign/accumulator error. Applied: Phase 3–4 (§15–§16), I6, P5.
  • MM3 — Baum-Welch over a concatenated transcript-HMM learns phone models from un-segmented audio: the alignment is a hidden variable you marginalize, not data you need. Embedded training is why you never hand-label phone boundaries. Predicts: given only audio + word transcripts + a lexicon, the system can bootstrap from a flat (uniform) start. Bug class without it: building a pipeline that demands phone-level labels (which don't exist at scale). Applied: Phase 5 (§17), MM2.
  • MM4 — Context explodes combinatorially; tying is the bias-variance dial that buys it back. |phones|³ triphones can't each get data; a phonetic decision tree pools acoustically-similar states to share parameters. Predicts: too-fine a tree (low min-occupancy) overfits; too-coarse underfits; there is a leaf budget that minimizes held-out WER. Bug class without it: either monophone-only (underfit, leaves accuracy on the table) or untied triphones (most contexts unseen → garbage). Applied: Phase 6 (§18), I15, ADR-8.
  • MM5 — Decoding is single-source shortest-path on a weighted graph that is the composition of four transducers (H∘C∘L∘G). The acoustic model, context, lexicon, and grammar are all weighted automata; recognition is one Viterbi search over their product. Predicts: every decode decision (beam, LM weight, word penalty, token recombination) is a graph-search parameter, not a model parameter; pruning trades search errors for speed but never changes the model. Bug class without it: welding the LM into the AM, or "fixing" deletions by retraining instead of widening the beam. Applied: Phase 9 (§21), I8, ADR-12.
  • MM6 — CTC is the alignment-free dual of Baum-Welch: a blank symbol turns "no boundaries" into a sum over all monotonic alignments, computed by the same forward-backward DP. Predicts: CTC and HMM forward-backward share numerics (log-space, scaling) and failure modes (underflow); the gradient is posterior − expected-occupancy. Bug class without it: doing per-frame argmax without blank semantics → duplicated/dropped tokens; or computing CTC in the linear domain → NaN on any real utterance. Applied: Phase 11 (§23, shared with #387), I4/I5, MM2.
  • MM7 — A weak per-frame sensor plus a strong sequence prior beats either alone: the LM rescues the acoustic model. The acoustic posterior is noisy and locally confusable ("yes"/"yas"); the LM supplies global plausibility, fused as an additive log-score in beam search. Predicts: an LM-weight sweep has a WER minimum; too little LM → acoustic noise dominates (substitutions), too much → the LM hallucinates (deletions/insertions imbalance). Bug class without it: tuning the AM to fix errors the LM should fix, or shipping with an untuned acoustic scale. Applied: Phase 8–9 (§20–§21), P7, the WER-reduction gate (§4).
  • MM8 — Everything probabilistic lives in log-space, and the only honest correctness promise is a WER tolerance, not bit-equality. Products of thousands of small probabilities underflow; log-sum-exp + per-frame scaling keep them finite, but FP reduction order then makes bit-reproducibility impossible across thread counts. Predicts: a parallel decode will differ from a serial one in the last ULP but not in WER; promising bits is a contract you'll break on any GEMM/FFT reorder. Bug class without it: linear-domain underflow to zero → NaN; or a flaky CI that fails on a legitimate numeric reorder because it asserted bit-equality. Applied: §4 numeric boundary, P2/P10, ADR-14/ADR-15, I2/I4.
  • MM9 — Acoustic and LM scores live on different scales; the acoustic scale is the knob that makes them commensurable. Acoustic log-likelihoods (summed over ~100 frames/word) dwarf LM log-probs (one per word), so they must be reweighted (acoustic_scale, or equivalently lmwt) before they can be added in beam search. Predicts: the WER-vs-lmwt curve is U-shaped with a single minimum; the word-insertion penalty trades insertions against deletions orthogonally. Bug class without it: "the LM does nothing" (scale wrong) or "the decoder only outputs short utterances" (penalty wrong) — tuning the AM to fix a scale bug. Applied: Phase 9 (§21), §21.2 lm_fusion, MM7, the M3 gate.
  • MM10 — The lattice is the hypothesis space; the 1-best is one path through it, and confidence is its posterior mass. Decoding doesn't produce an answer, it produces a weighted graph of plausible answers; keeping it enables rescoring with a stronger LM, N-best extraction, and per-word confidence — all without re-decoding. Predicts: a word whose lattice posterior is spread across competitors is low-confidence even if it's the 1-best; rescoring only helps if the true word is in the lattice (so lattice oracle-WER lower-bounds achievable WER). Bug class without it: shipping 1-best-only then discovering you can't add confidence or rescore; or trusting a 1-best word the model was 51/49 on. Applied: Phase 9 (§21), ADR-13, I8/I10, §8.9.

36. Back-of-Envelope Capacity Model

Numbers an expert computes before designing, each derived from the System Constraints table (§4). Baseline: 16 kHz mono f32, 25 ms window (N=400, zero-padded to n_fft=512), 10 ms hop, 39-dim MFCC+Δ+Δ².

  1. Frame rate. frames/sec = 1000 ms / hop_ms = 1000 / 10 = 100 frames/s. A 10 s utterance ⇒ T = 100 × 10 = 1000 frames. (Drives every per-frame cost below.)
  2. Feature-vector size. D × 4 bytes = 39 × 4 = 156 B/frame. One second = 100 × 156 ≈ 15.6 KB; a 10 s utterance feature matrix = 1000 × 156 ≈ 156 KB — trivially in RAM (confirms the O(T·D) memory ceiling, §4).
  3. Front-end FFT cost. Per frame ≈ n_fft·log2(n_fft) = 512 × 9 ≈ 4 608 butterfly ops; × 100 frames/s ≈ 4.6×10⁵ ops/s of audio. Negligible vs decode ⇒ justifies the ≤5 ms/s front-end target (§4).
  4. GMM acoustic scoring. Cost ≈ T × S × M × D mults. With S = 2000 tied states, M = 16 components, D = 39, T = 1000: 1000 × 2000 × 16 × 39 ≈ 1.25×10⁹ mults per 10 s utterance ⇒ ≈ 1.25×10⁸ mults/s of audio. At ~10 GFLOP/s effective single-core GEMM (#349) ⇒ ≈ 12 ms/s of audio ⇒ well under RTF 1.0 (§4), confirming AM scoring is GEMM-bound not decode-bound at this scale.
  5. Forward-backward / Baum-Welch. Left-to-right sparsity ⇒ ≈ T × S × fanout with fanout ≈ 2 (self-loop + advance): 1000 × 2000 × 2 = 4×10⁶ state updates/utterance. Dense O(T·S²) would be 1000 × 2000² = 4×10⁹ — the 1000× sparsity win (§16.7) that makes training tractable.
  6. Viterbi beam memory. beam_tokens × token_bytes. A token ≈ {state:4, score:4, back:4, lm_state:8} ≈ 20 B. With max_active = 10 000 tokens: 10 000 × 20 = 200 KB live; lattice arcs ≈ active × T bounded by pruning. Confirms O(active tokens) not O(|HCLG states|) (§4, I8).
  7. HCLG / WFST size. Static graph ∝ |L| × |G| states. A 5k-word lexicon × a pruned trigram (say 10⁶ n-grams) ⇒ order 10⁶–10⁷ arcs ⇒ tens–hundreds of MB if fully composed — the reason we do on-the-fly composition (§39) to bound memory rather than materialize HCLG.
  8. Real-time factor. RTF = compute_time / audio_time. Budget per 1 s audio: front-end ≈5 ms + GMM scoring ≈12 ms + decode (beam-bound) ≈ the balance. For RTF ≤ 1.0 (§4), decode must stay under ≈ 1000 − 17 ≈ 983 ms/s ⇒ generous; the beam is set so peak active tokens keep decode in budget.
  9. CTC forward-backward. Lattice (2|label|+1) × T. For |label| = 50 phones, T = 1000: 101 × 1000 ≈ 10⁵ cells/utterance, × 4 B ≈ 400 KB α (and β) — pooled, log-space (§23.7).
  10. Neural AM compute. A BiLSTM with hidden H = 320/direction, L = 4 layers dominates as ≈ T × L × 8 × H² (4 gates × 2 mat-muls): 1000 × 4 × 8 × 320² ≈ 3.3×10⁹ mults/utterance ⇒ ≈ 3.3×10⁸ mults/s ⇒ ~33 ms/s at 10 GFLOP/s ⇒ consistent with the RTF ≤ 1.5 neural-CPU target (§4).
  11. Model size (neural). Params ≈ BiLSTM L × 8 × H² ≈ 4 × 8 × 320² ≈ 3.3M + CNN + head ≈ a few M params × 4 B ≈ 15–30 MB — confirms the ≤30 MB neural model ceiling (§4).
  12. Corpus-decode throughput. Utterances are independent ⇒ aggregate_RTF ≈ single_RTF / cores × (1/efficiency). With RTF 1.0 single-core and ≥0.8× scaling efficiency (I11) on 8 cores ⇒ effective ≈ 1.0 / (8 × 0.8) ≈ 0.16 ⇒ a 1 h recording decodes in ≈ 9.4 min. (Confirms the embarrassingly-parallel claim, §33.)

38. Alternative Architectures (Roads Not Taken)

Four fundamentally different designs for the same waveform→text problem (not parameter tweaks). Each: sketch, regime where it wins, the real system that embodies it, why this blueprint rejected it as the default.

R1 — Pure HMM-GMM, no neural path (the HTK/Sphinx era).

 audio → MFCC+Δ → [GMM-HMM triphones, tree-tied] → token-passing Viterbi (+n-gram LM) → text
                         every emission is a diagonal-GMM; trained by Baum-Welch

Wins: tiny data, no GPU, full transparency, fast CPU decode; small/medium vocab. Embodied by: HTK, CMU Sphinx. Rejected as default: the neural CTC path reaches materially lower WER on read speech (§4), and a portfolio teaching both eras is worth more — but we keep the GMM-HMM path in full (Phase 3–6, 9) precisely because it is the right call in the low-data regime (ADR-7, §35).

R2 — DNN-HMM hybrid (replace the GMM with a DNN posterior).

 audio → log-mel → [DNN] → per-frame tied-state posteriors → ÷prior → scaled likelihoods
                                  → HMM/WFST (HCLG) Viterbi (+LM) → text
        (HMM topology + tree-tied states kept; only the emission model changes)

Wins: the dominant pre-2018 production recipe — lower WER than GMM-HMM while reusing the entire WFST decoder and tree; abundant supervised data + GPU. Embodied by: Kaldi nnet3/chain (TDNN-F, LF-MMI); Hinton et al. (IEEE SPM 2012). Rejected as default: it needs frame-level alignments from a bootstrap GMM-HMM and the full WFST stack; CTC reaches comparable accuracy end-to-end without forced alignment, so CTC is our neural default (ADR-9). The hybrid is the natural §39 (discriminative-training) extension.

R3 — Attention encoder-decoder (Listen, Attend and Spell / Whisper / Conformer).

 audio → log-mel → [encoder: Conformer/Transformer] ── attention ──► [autoregressive decoder]
                                                                         → text (token by token)
   no HMM, no lexicon, no CTC alignment; the decoder attends over the whole encoded sequence

Wins: highest accuracy for offline, full-context transcription at large data scale; implicit LM in the decoder; multilingual. Embodied by: Chan et al. "Listen, Attend and Spell" (2015/2016), Gulati et al. "Conformer" (Interspeech 2020), OpenAI Whisper (Radford et al., 2022). Rejected as default: quadratic attention + autoregressive decode is not low-latency streamable; it needs very large data/compute and teaches less of the classical signal→symbol arc. Deferred as §39; contrasted in §35.

R4 — RNN-Transducer (RNN-T), the streaming default.

 audio → log-mel → [encoder (LSTM/Conformer)] ─┐
                                               ├─► [joint network] → softmax over (label ∪ blank)
              previous labels → [prediction net]┘        monotonic, frame-synchronous emission

Wins: on-device, low-latency streaming recognition with an internal LM and monotonic alignment — the modern phone-dictation default. Embodied by: Graves "Sequence Transduction with RNNs" / RNN-Transducer (2012); production on-device assistants. Rejected as default: the joint-network training is heavier and the streaming machinery is out of Phase-0 scope (batch only); CTC is the simpler segmentation-free objective to build first and shares code with #387. Deferred as §39.

  • ARPA text format for n-gram LMs (log-prob + backoff).
  • Backoff / Kneser-Ney n-gram smoothing: redistribute probability to unseen n-grams via lower orders / continuation counts.
  • Baum-Welch the HMM EM: forward-backward occupancy → re-estimate transitions + emissions.
  • Beam search pruned best-first/Viterbi search keeping the top hypotheses.
  • CMVN Cepstral Mean (and Variance) Normalization of features.
  • CTC Connectionist Temporal Classification; alignment-free sequence loss with a blank label (shared with #387).
  • CTM time-marked output format (utt chan tbeg dur word conf).
  • Decision-tree state tying clustering acoustically-similar triphone states to share a GMM (Young 1994).
  • DCT Discrete Cosine Transform; decorrelates log-mel energies → MFCC.
  • Embedded training training HMMs from un-segmented utterances by concatenating phone models along the transcript.
  • Forced alignment Viterbi against a known transcript to get phone/word time boundaries.
  • Forward-backward the DP computing α (forward) and β (backward) occupancy in an HMM/CTC.
  • GMM Gaussian Mixture Model; the diagonal-covariance HMM-state emission.
  • HCLG the composed WFST H∘C∘L∘G (HMM ∘ context ∘ lexicon ∘ grammar) searched at decode.
  • HMM Hidden Markov Model; left-to-right states with transition + emission probabilities.
  • Lattice word graph of competing hypotheses with acoustic + LM weights.
  • Log-mel / MFCC log mel-filterbank energies / their DCT (the front-end features).
  • Mel scale perceptual frequency warping for the filterbank.
  • Perplexity exp(−avg log P); the LM-quality metric.
  • Pre-emphasis a high-pass filter boosting high frequencies before framing.
  • RTF Real-Time Factor = decode time ÷ audio duration.
  • Scaling (forward-backward) per-frame normalization to avoid underflow in α/β.
  • Token passing the HMM/WFST Viterbi decode where tokens propagate along arcs carrying score + backpointer.
  • Triphone a phone in its left/right context (context-dependent model).
  • Viterbi the max-probability path DP (decoding/alignment).
  • WER / CER Word / Character Error Rate = edit distance ÷ reference length.
  • WFST Weighted Finite-State Transducer; the algebra unifying AM/lexicon/LM for decoding.
  • G2P grapheme-to-phoneme; predicts pronunciations for OOV words.
  • Senone / tied state a clustered context-dependent HMM state sharing a GMM (a decision-tree leaf).
  • Monophone / triphone a context-independent / left-right-context-dependent phone model.
  • Flat start uniform-segmentation initialization for the first monophone training pass.
  • Spectrogram the time × frequency power representation from the framed, windowed FFT.
  • Windowing tapering each frame (Hamming/Hann) before the FFT to reduce spectral leakage.
  • Cepstrum / liftering the transform of the log spectrum (MFCCs are mel-cepstral) / scaling its coefficients.
  • Frame / hop the analysis window (≈25 ms) and its advance step (≈10 ms).
  • Dithering adding tiny noise before quantization to decorrelate quantization error.
  • Acoustic scale the weight balancing acoustic vs LM scores during decoding.
  • Token recombination merging decoder tokens that reach the same state, keeping the best (bounds the beam).
  • Shallow fusion adding the LM log-prob to the acoustic score during beam search (CTC path).
  • Sufficient statistics the accumulated occupancy (γ) and transition (ξ) counts re-estimation needs.
  • OOV out-of-vocabulary word (absent from the lexicon/LM); handled via G2P / backoff / ⟨unk⟩.
  • VAD voice activity detection — speech vs silence/noise segmentation.
  • Lattice rescoring re-weighting a decoded lattice with a stronger (e.g. larger-order or neural) LM.
  • Endpointing detecting utterance start/end for streaming recognition (deferred §39).
  • Real speech vs synthetic gap the accuracy drop from training on synthetic/clean audio and testing on real recordings.
  • Bakis topology the standard left-to-right HMM with self-loops and single-step forward transitions (no skips).
  • Senone a tied context-dependent HMM state (a decision-tree leaf); synonym for tied state (Kaldi pdf-id).
  • PDF id the integer index of a tied-state probability density function (the GMM/posterior the state shares).
  • LVCSR Large-Vocabulary Continuous Speech Recognition — the unconstrained-vocabulary decoding the decoder targets.
  • Tropical (log) semiring the (min, +) algebra in which WFST weights combine for Viterbi shortest-path.
  • Epsilon (ε) arc a WFST transition consuming no input/output symbol (silence, backoff) requiring an ε-filter in composition.
  • Blank (CTC) the extra output symbol separating repeated labels and absorbing non-emitting frames; the key to alignment-free training.
  • Prefix beam search CTC decoding that tracks blank/non-blank prefix probabilities to merge alignments mapping to the same label string.
  • Shallow vs deep LM fusion adding LM log-prob during beam search (shallow) vs integrating the LM into the network (deep); this design uses shallow.
  • Acoustic scale / LM weight the multiplier reconciling per-frame acoustic scores with per-word LM scores in decoding (MM9).
  • Word-insertion penalty a per-word decode bias trading insertions against deletions.
  • Lattice beam the (≤ search-beam) threshold deciding which competing arcs are retained in the output lattice.
  • Mixture splitting (mixing up) doubling GMM components (μ ± ε·σ) then re-training, growing model capacity (HTK recipe).
  • Variance flooring clamping GMM variances to a minimum to prevent a component collapsing onto one frame (→ ∞ likelihood).
  • Forward variable α / backward variable β the partial probabilities of the prefix/suffix observations in the forward-backward DP.
