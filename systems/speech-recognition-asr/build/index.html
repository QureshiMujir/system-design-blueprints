⬜ Phase 0 — Skeleton: audio core, signal/feature types, I/O, harness + oracle §12

Objectives
  • Cargo workspace (ADR-2) with asr-core/audioio/conformance skeletons; wire #369/#112/#349/#372 deps.
  • Define Signal, FeatureMatrix, Lattice, Transcript, the typed stage handles (I3), seeded Rng.
  • Ship one trivial end-to-end path (WAV read → identity "features" → null AM → empty transcript) to prove the harness.
  • Stand up the synthetic-audio generator (TTS-rendered with known boundaries) + the differential scaffolding every later phase reuses.
Deliverable
  • asrc recognize utt.wav --am null runs read→identity-features→null-AM→empty transcript.
  • cargo test runs signal/feature/stage/rng unit tests + WAV round-trip + synthetic generator (boundaries within audio length).
Acceptance
  • WAV read/write round-trips PCM16/24/float bit-exactly (within quantization); resample preserves duration ±1 sample.
  • Rng identical stream per seed across reruns (I7 golden test).
  • Stage types enforce ordering at compile time (I3) — a test that decodes before front-end fails to compile (doc-tested).
  • Synthetic generator emits boundaries that round-trip (0 ≤ t_beg < t_end ≤ duration, I1); Miri clean.
Fixtures
  • synth_align/hello_world_tts (audio + phone/word boundaries + transcript); asr-core/{frame_time_map,rng_stream_seed{1,2}}; audioio/wav_roundtrip.
Pitfalls
  • Global/implicit RNG → non-reproducibility (I7); thread Rng explicitly.
  • WAV endianness / bit-depth / float-vs-int confusion → silent garbage audio; test all variants.
  • Sample-rate mismatch silently skipped → features wrong; always resample to model rate or error (I12).
  • Frame→time off-by-half-window → every alignment shifted; pin the convention now (I1).

⬜ Phase 1 — Front-end I (pre-emphasis, framing, windowing, FFT, power spectrum) §13

Objectives
  • Pre-emphasis → framing (25 ms/10 ms) → windowing (Hamming/Hann) → FFT (#369) → power/magnitude spectrum.
  • The spectral representation P2 turns into MFCC/log-mel.
Deliverable
  • frontend (spectrum) green vs a hand-computed reference + librosa golden (pinned params); spectrogram emitted.
Acceptance
  • Power spectrum matches a reference within rtol=1e-5 on a sinusoid (single-bin energy) and on speech.
  • Framing count = floor((len−win)/hop)+1; window applied correctly (DC/Nyquist handling).
  • FFT via #369 (no private DFT, principle 11).
Fixtures
  • frontend/{preemphasis,framing_count,hamming_window,power_spectrum_sinusoid,spectrogram_speech}.
Pitfalls
  • Frame count off-by-one (partial last frame) — pin the convention (drop or pad), match the oracle.
  • Window normalization / periodic-vs-symmetric Hamming differs by library → pin ours, document (ADR-31).
  • FFT size vs window size (zero-pad win 400 → N=512) — pad explicitly; bins map to Hz via N.
  • Power vs magnitude vs log inconsistency downstream — fix "power spectrum" here.

⬜ Phase 2 — Front-end II (mel filterbank, MFCC, deltas, CMVN, log-mel) §14

Objectives
  • Mel filterbank → log → DCT → MFCC (13) + liftering; log-mel (neural); delta + delta-delta; CMVN.
  • The final FeatureMatrix (e.g. 39-dim MFCC+Δ+Δ²) both AMs consume.
Deliverable
  • frontend (MFCC/log-mel) green vs librosa/HTK golden (pinned params); 39-dim features.
Acceptance
  • MFCC matches the pinned-param oracle within rtol=1e-4 (DCT/lifter/mel conventions exact, ADR-31).
  • Deltas match the regression-window reference; CMVN zero-mean/unit-var per utterance.
  • log-mel matches mel-energy log (neural path).
Fixtures
  • frontend/{melbank_triangular,mfcc_13,lifter,delta_deltadelta,cmvn_zeromean,logmel}.
Pitfalls
  • Mel formula variant (HTK 2595·log10(1+f/700) vs Slaney) — pin one, document (ADR-31); mismatches the oracle otherwise.
  • DCT-II normalization (ortho vs not) and which coefficients kept (drop/keep c0) — pin, match.
  • Liftering off → different MFCC scale → AM mismatch.
  • CMVN computed on the wrong axis (per-dim over time, not per-frame) — the classic bug.
  • Delta window edges (frame 0..2) — pad/replicate consistently.

⬜ Phase 3 — GMM (diagonal-covariance Gaussians + EM via #372) §15

Objectives
  • Diagonal-covariance Gaussians + mixtures (reuse #372); EM training; log-likelihood; mixture splitting.
  • The HMM-state emission model (P4 consumes it).
Deliverable
  • gmm green vs #372/a hand-computed reference; EM likelihood monotone (I6).
Acceptance
  • Log-likelihood matches a hand-computed diagonal-Gaussian within rtol=1e-6.
  • EM training likelihood non-decreasing each iteration (I6 fixture).
  • Variance floor prevents collapse (a component on one point doesn't → −∞).
  • Mixture splitting increases likelihood after re-training.
Fixtures
  • gmm/{diag_gaussian_loglike,em_likelihood_monotone,variance_floor,mixture_split}.
Pitfalls
  • Variance collapse (a Gaussian on a single frame → 0 variance → ∞ likelihood) → variance flooring (essential).
  • Forgetting log-space → underflow on D=39 dims → log-sum-exp (I4).
  • EM local optima → seeded init (k-means via #372), n_init (I7).
  • Diagonal vs full covariance: diagonal assumes decorrelated features (why the DCT in MFCC matters).

⬜ Phase 4 — HMM I (scaled forward-backward + Baum-Welch) §16

Objectives
  • Left-to-right HMM topology; scaled forward-backward (I2, no underflow); Baum-Welch re-estimation (occupancy γ, transition ξ → update A + emissions, I6).
  • The training engine for the classical AM.
Deliverable
  • hmm forward-backward + Baum-Welch green vs a hand-computed small HMM; likelihood monotone.
Acceptance
  • Forward P(O) == backward P(O) within ε (I2 consistency); scaled and log paths agree.
  • On a 2–3 state toy HMM, α/β/γ/ξ match hand-computed values within rtol=1e-6.
  • Baum-Welch likelihood non-decreasing (I6); converges on a synthetic source HMM (recovers parameters).
Fixtures
  • hmm/{forward_backward_toy,alpha_beta_consistency,baum_welch_monotone,recover_synthetic_hmm}.
Pitfalls
  • Underflow without scaling/log → α→0 on long T → NaN; scale per frame and record scales (I2).
  • ξ accumulation across the wrong transition pair → wrong A; test on the toy HMM.
  • Mixing scaled and unscaled quantities in re-estimation → wrong γ; keep the domain consistent.
  • Re-estimating emissions on the wrong occupancy (state vs mixture-component γ) — the GMM-HMM coupling bug.

⬜ Phase 5 — HMM II (Viterbi, embedded monophone training; first decoding) §17

Objectives
  • Viterbi (best-path) decoding + backtrace (state/phone alignment); embedded training (concatenate phone HMMs along a transcript — train without phone boundaries); the flat-start monophone bootstrap.
  • First end-to-end (constrained) recognition + forced alignment.
Deliverable
  • Monophone GMM-HMM trains from flat start; Viterbi forced-alignment green vs synthetic boundaries; constrained decode runs.
Acceptance
  • Viterbi path matches a hand-computed toy decode; forced-alignment phone boundaries within 20 ms of synthetic ground truth (≥80%, §4).
  • Flat-start monophone training converges (likelihood ↑, I6); decode of training utterances is sane.
  • Determinism: same seed ⇒ same alignment/model (I7).
Fixtures
  • hmm/{viterbi_toy,backtrace_alignment}; align/forced_phone_boundaries; train/flat_start_converges.
Pitfalls
  • Viterbi vs forward (max vs sum) — separate, tested; mixing them silently wrong.
  • Flat-start sensitivity → bad init → bad model; iterate + split carefully.
  • Embedded-training transcript-to-HMM concatenation (silence handling, optional silence) — the recipe detail that breaks alignment.
  • Backtrace off-by-one (frame vs transition index) → boundaries shifted.

⬜ Phase 6 — Triphones + decision-tree state tying §18

Objectives
  • Context-dependent triphone models; phonetic decision-tree state tying (Young 1994) to share data across acoustically-similar contexts (I15).
  • The accuracy lever of classical ASR (bias-variance).
Deliverable
  • Triphone GMM-HMM with tree-tied states trains; WER improves vs monophone; tree is deterministic (I15).
Acceptance
  • Triphone WER < monophone WER on the eval set (the context-modeling win).
  • Decision tree is a deterministic function of questions + min-occupancy (I15 fixture: same stats ⇒ same tree).
  • Tied-state count within the configured budget; each leaf meets min-occupancy.
  • Differential vs Kaldi tree statistics (leaf count, gain) within tolerance.
Fixtures
  • hmm/triphone_clone; train/{tree_tying_determinism,tree_min_occupancy,triphone_beats_monophone_wer}.
Pitfalls
  • Unseen triphone contexts at decode → must map via the tree (back off to a seen context), never crash (I9/I15).
  • Question set design (phonetic classes) drives quality — start from a standard set, document.
  • Min-occupancy too low → overfit leaves; too high → underfit → tune on held-out.
  • ML gain computation (pooled vs split Gaussian likelihood) sign/accounting bug → wrong splits.

⬜ Phase 7 — Pronunciation lexicon + G2P §19

Objectives
  • Word → phone-sequence dictionary; G2P fallback for OOV; phone set + silence handling.
  • The bridge from sub-word acoustics to words (decoder needs it).
Deliverable
  • lexicon green: word lookups + G2P for OOV; feeds the decoder's L (lexicon) graph.
Acceptance
  • Dictionary lookup correct; multi-pronunciation handled; G2P phone-error-rate ≤ target on a held-out word list.
  • OOV words get a pronunciation (G2P) or ⟨unk⟩ (I9), never a crash.
  • Phone set matches the AM's modeled phones (no orphan phones).
Fixtures
  • lexicon/{dict_lookup,multi_pron,g2p_oov,silence_insertion,phoneset_consistency}.
Pitfalls
  • Phone-set mismatch between lexicon and AM → decoder references unmodeled phones → crash/garbage; validate consistency (I9).
  • Multi-pronunciation weighting (which pronunciation wins) — handle in the lexicon FST weights.
  • G2P on names/foreign words is hard → bound expectations; ⟨unk⟩ fallback.
  • Silence handling (mandatory vs optional) affects alignment + decode.

⬜ Phase 8 — Language model (n-gram, backoff/Kneser-Ney, ARPA) §20

Objectives
  • n-gram LM: counts → backoff / Kneser-Ney smoothing; perplexity; ARPA I/O.
  • The decode-time word prior (the LM-rescue, principle 7); shared design with #387.
Deliverable
  • lm green: trains an n-gram, writes/reads ARPA, computes perplexity matching a reference.
Acceptance
  • Perplexity matches KenLM/SRILM within tolerance on a fixed corpus (the smoothing-correctness gate).
  • ARPA round-trips (write→read→same probabilities).
  • Backoff query is normalized (Σ over vocab ≈ 1 per history, within ε).
Fixtures
  • lm/{counts,kneser_ney_perplexity,arpa_roundtrip,backoff_normalized}.
Pitfalls
  • Kneser-Ney continuation counts vs raw counts — the classic implementation error; test perplexity vs a reference.
  • Unknown-word (<unk>) handling + sentence boundaries (<s>/</s>) — match the reference convention.
  • Backoff weight computation (leftover mass) — must normalize.
  • Numeric: log10 (ARPA) vs ln (internal) — convert consistently.

⬜ Phase 9 — Decoder (token-passing Viterbi / WFST-lite HCLG + LM fusion; first LVCSR) §21

Objectives
  • Token-passing Viterbi beam over HMM+lexicon+LM, OR WFST-lite: compose HCLG (H∘C∘L∘G), Viterbi-search it; LM fusion (weight + word-insertion penalty); lattice + confidence (I8/I10).
  • First full large-vocabulary continuous speech recognition.
Deliverable
  • Full GMM-HMM decoder green: WAV → words; LM-fused beam; lattice + confidence; examples/recognize_wav --am gmmhmm.
Acceptance
  • WER within ±2% absolute of Kaldi on the golden set (§4); LM fusion gives ≥25% relative WER reduction vs no-LM.
  • 1-best ⊆ lattice (I8); pruning never improves a path; beam/max-active explicit + tunable.
  • Determinism: same (seed, beam, model) ⇒ same transcript incl. ties (I7).
  • Confidence calibrated (high-conf words error-rate ≪ low-conf).
Fixtures
  • decoder/{token_passing_toy,hclg_compose,lm_fusion_wer,one_best_in_lattice,beam_determinism,confidence_calibration}.
Pitfalls
  • Beam too tight → deletions (search errors); too wide → slow → tune RTF/WER (I8); beam-tuning.md.
  • LM weight / word-insertion penalty untuned → insertions/deletions imbalance → tune on dev.
  • On-the-fly composition bugs (epsilon arcs, weight pushing) → wrong scores; test vs a tiny pre-composed HCLG.
  • Token recombination (same state, keep best) — forgetting it explodes the search.
  • Mixing AM/LM score scales (acoustic scale) — pin the acoustic-weight convention.

⬜ Phase 10 — Neural acoustic model (CNN/BiLSTM encoder via #112/#349) §22

Objectives
  • CNN (spectral) + BiLSTM (temporal) encoder mapping log-mel features → a per-frame hidden sequence (CTC head added in P11), via #112 autograd + #349 GEMM.
Deliverable
  • Neural encoder forward/backward green vs #112 finite-difference gradient checks; emits a T×H sequence.
Acceptance
  • Gradients match #112 finite-difference within 1e-4 (the autograd contract).
  • Encoder output T deterministic from input frames + stride (documented map, I1).
  • Forward uses #349 GEMM (near-peak); eval-mode (no dropout) at inference.
Fixtures
  • am-neural/{cnn_grad_finite_diff,bilstm_grad_finite_diff,encoder_output_shape,frame_rate_map}.
Pitfalls
  • Time downsampling vs CTC label length (T must be ≥ label length) — keep enough frames.
  • BiLSTM needs the whole utterance (not streaming) — batch Phase-0; streaming deferred (§39).
  • Train/serve feature skew (CMVN, Δ) → share one feature path.
  • Forgetting eval-mode → dropout at inference → nondeterminism.

⬜ Phase 11 — CTC loss + decode (the alignment-free neural path; shared with #387) §23

Objectives
  • Linear+softmax CTC head → T×(|A|+1) posteriors (I4); CTC loss (blank-augmented forward-backward, log-space, gradient to #112, I5); greedy + prefix-beam decode with LM fusion.
  • The neural recognizer (the alignment-free alternative to GMM-HMM); CTC machinery shared verbatim with #387.
Deliverable
  • Neural CTC AM trains; examples/recognize_wav --am neural; WER vs SNR curve; CTC grad matches finite-diff.
Acceptance
  • CTC loss + gradient match finite-difference within 1e-4 (I5); α/β consistency (forward==backward).
  • Trained neural WER ≤ 15% on the TIMIT-like set (§4); ≥25% relative reduction with LM (shared decode).
  • Greedy collapse deterministic (I5); beam=1==greedy.
  • Determinism per seed (I7); log-space stable on long T.
Fixtures
  • ctc/{forward_backward_small,grad_finite_diff,alpha_beta_consistency,greedy_collapse,logspace_stable_longT}; am-neural/ctc_train_overfit.
Pitfalls
  • Not log-space → underflow → NaN (I4); the #1 CTC bug (shared with #387).
  • Lattice off-by-one (blank between distinct labels only) → wrong loss; hand-computed 2–3 symbol fixture.
  • Label longer than T → infeasible → loss=∞ guard (data/downsampling bug).
  • LR too high → divergence; warmup + grad clipping.
  • Repeated symbols ("oo") need the blank-separation case — test it.

⬜ Phase 12 — Alignment + metrics + serialization + C ABI §24

Objectives
  • Forced alignment (phone/word timings); WER/CER (Levenshtein, sclite-style); versioned model serialization (round-trip, I14); stable C ABI (asr_*).
Deliverable
  • C example (examples/asr_from_c.c) links libasr, recognizes a WAV, reads words+timings; alignment + WER green.
Acceptance
  • WER/CER match an sclite reference exactly on alignment fixtures (the metric is exact, not tol).
  • Forced-alignment boundaries within 20 ms (≥80%, §4) of synthetic ground truth.
  • Model round-trips: load(save(m)).recognize == m.recognize within WER tol (I14).
  • No unwinding across FFI (catch_unwind test); bad args → negative code (I12).
Fixtures
  • metrics/{levenshtein,wer_sclite,cer}; align/forced_boundaries; serialization/roundtrip_{gmmhmm,neural} (I14); cabi/{c_integration,bad_param_codes}.
Pitfalls
  • WER alignment tie-breaking (multiple min-edit paths) → match sclite's convention exactly.
  • Model schema drift → IncompatibleVersion (I14); never silently mis-load.
  • Panic across FFI = UB → catch_unwind everywhere.
  • Result lifetime (caller frees via asr_free) — document ownership.
  • Float weight serialization (exact bit round-trip) — canonical encoding.

⬜ Phase 13 — Conformance (vs Kaldi/HTK), fuzzing, benchmarks (WER/RTF) §25

Objectives
  • Lock correctness with synthetic-alignment ground truth + a Kaldi/HTK differential suite + pipeline-invariant asserts; fuzz the audio/decode/model paths; benchmark RTF + WER/SNR reproducibly.
  • Define "Phase-0 done" for the future coding contract.
Deliverable
  • make conformance green; make bench emits a report; make fuzz runs N iterations clean.
Acceptance
  • Synthetic WER ≤ §4 targets; alignment ≥80% within 20 ms; Kaldi/HTK differential within ±2% absolute WER.
  • All invariants (I1–I15) asserted and green.
  • Fuzz clean ≥ 10⁷ iterations/target (30-day canaries deferred); bench meets §4 (RTF, LM-WER-reduction).
  • Determinism hashes stable.
Fixtures
  • Full conformance/ corpora (frontend/ … metrics/); synth_align/ (TTS + boundaries); kaldi_golden/ (pinned version); golden/ determinism hashes.
Pitfalls
  • WER tolerance vs the oracle: too tight (false fails on float-order AM differences) or too loose — derive per-AM from theory + variance.
  • Kaldi/HTK version + recipe drift → golden WER shifts → pin, regenerate deliberately, version fixtures.
  • Fuzz not hitting silence/noise/clipping/huge — seed the corpus.
  • Determinism hash breaks on a legit numeric change → version the golden set (ADR-30).
  • Bench noise → pin governor, median-of-k; warmup excluded.
