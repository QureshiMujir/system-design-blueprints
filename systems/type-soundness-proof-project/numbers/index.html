4. System Constraints

Hard, quantified bounds the build is measured against. Soundness of tsp-kernel is non-negotiable (a soundness bug invalidates every proof); the object-language scope is bounded (STLC + naturals/booleans/products/sums/refs; System F a stretch). Single-process, single-threaded; no network, no persistent state. Targets below are the gate, not aspirations — Phase 13 (## 25) benchmarks against this table.

4.2 The TCB constraint (C1, C2) — load-bearing

  • Trusted base = tsp-kernel only. tsp-syntax/tsp-term/tsp-rules/tsp-meta/tsp-test/tsp-cli are untrusted: a bug there yields a wrong proposition or a rejected proof, never a falsely accepted one — the kernel re-checks every Proof.term at its goal KType.
  • < 1500 LOC (C1) is a design constraint, not a measurement after the fact: every kernel addition is budgeted. whnf+equal (conversion) are the largest sub-budget (~400 LOC); infer_type/check_type (bidirectional) ~600 LOC; KTerm/Ctx/Sort + de Bruijn ops ~300 LOC; errors ~100 LOC.
  • C2 dominates all perf targets: correctness before speed. If C2 conflicts with C3/C7, C2 wins (slower, sound).
  • TCB excludes: parsing, generation, shrinking, CLI, the statements progress_statement/preservation_statement (untrusted producers — the kernel still type-checks their output KTerm).

4.3 Determinism & purity (C10–C12)

  • infer_type, check_type, whnf, equal, shift, subst, alpha_eq, infer, step, check_deriv are pure total functions of their inputs — no clock, no RNG, no I/O, no global state. -> C10.
  • de Bruijn representation removes name choice -> alpha_eq is structural -> identical verdict regardless of source naming. Off-by-one in shift breaks the substitution lemma (C2 risk), not determinism.
  • Tester randomness is confined to Generator/Shrinker, seeded explicitly (--seed); seed in -> run out is a pure function. -> C11. Default seed is fixed + logged.
  • No lazy statics in the TCB (C12) — laziness would introduce first-touch order dependence; the strict kernel forbids it (one rationale for Rust over Haskell).

4.4 Resource & size discipline (C4–C9, C14, C15)

  • All sizes counted on KTerm/Term/Derivation node counts (not bytes) — the relevant cost driver for recursive checking.
  • Recursion is bounded, not unbounded: check_deriv and infer_type carry an explicit depth budget (C5/C4) and convert overflow to KernelError/DerivError rather than blowing the native stack (C13). Large terms may use an explicit work-stack to keep RSS under C9.
  • whnf/equal carry a reduction-step cap (C14): well-typed object-language proofs normalize fast; the cap guards adversarial KTerm fed via fuzzing (C13) — divergence -> KernelError::Diverged, never a hang or a false accept.
  • usize de Bruijn indices: binder depth bound (C6, < 1024) keeps shift/subst arithmetic far from usize overflow; an index >= context length is a KernelError/TypeError, never UB.

4.6 Non-negotiable vs. negotiable

  • Non-negotiable (ABSOLUTE): C2 (no false accept), C10/C11 (determinism), C13 (no kernel panic). These define correctness; failing any one fails the project.
  • Hard budgets: C1, C3–C6, C8, C9, C12, C14 — CI gates; a breach blocks the Phase 13 "done" gate until fixed or formally re-budgeted.
  • Soft targets: C7, C15, C16 — performance/ergonomics; regressions tracked, tolerated short-term, not release-blocking.
  • Trade-off rule of record: when budgets collide, ordering is soundness (C2) > determinism (C10/C11) > safety/no-panic (C13) > hard perf (C3) > throughput (C7) > size (C15).
