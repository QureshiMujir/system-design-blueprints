3. Architectural Overview

A seven-crate Rust workspace forming a layered pipeline from an untrusted front end (parse a language definition + object terms) down through two parallel assurance paths — tsp-meta machine-checked proofs validated by the trusted tsp-kernel (lambda-Pi / LF), and tsp-test empirical falsification. Data, not callbacks, flows between layers: judgments and derivations are values; proofs are KTerms; the kernel is the single arbiter of truth.

3.2 Data Flows (LOCKED)

Edge Producer -> Consumer Payload Form
1 tsp-cli -> tsp-syntax .lang file + proof script + object program byte stream / &str
2 tsp-syntax -> tsp-term parsed object terms Term, Type (de Bruijn)
3 tsp-syntax -> tsp-rules LangDef { sorts, grammar, judgments, rules } data
4 tsp-term -> tsp-rules term reps + shift/subst/alpha_eq/is_value function calls
5 tsp-rules -> tsp-meta Judgment, Rule, Derivation (judgments-as-data) data
6 tsp-rules -> tsp-test infer, step, Rule set function calls + data
7 tsp-meta -> tsp-kernel Proof { goal: KTerm, term: KTerm } proof terms
8 tsp-test (self) Generator -> well-typed Term -> check_progress/check_preservation -> Shrinker TestResult
  • Proof obligation: tsp-meta emits Proof { term, goal }; "valid" iff check_type(ctx, term, goal) accepts (edge 7) — the ONLY definition of proof validity.
  • Empirical edge 8 is NOT a proof: a Pass(u64) is evidence, a CounterExample(Term, Witness) is a falsification; neither is consumed by the kernel.

3.3 Trust Boundary (TCB)

Region Crates Status If buggy
Trusted computing base tsp-kernel ONLY audited; target <= ~1500 LOC GRAVEST: accepts ill-typed proof term -> false theorem silently validated
Checked-by-the-kernel tsp-meta untrusted; every Proof re-checked by kernel proof simply fails check_type -> caught
Untrusted input LangDef, proof scripts, object programs adversarial bad rule -> proof fails to check AND/OR tester finds counterexample
Supporting (not in TCB) tsp-syntax, tsp-term, tsp-rules, tsp-test, tsp-cli untrusted; bugs surface as failed kernel checks or test disagreement none can validate a false theorem; only the kernel can
  • Invariant TCB-1 (load-bearing): infer_type/check_type NEVER accept an ill-typed KTerm and NEVER panic on adversarial input. Fuzzed in Phase 13.
  • Trust is asymmetric: a tsp-meta lemma is believed only because the kernel re-derives it from first principles; the kernel trusts nothing below it.
  • Dual-guard: a deliberately broken typing rule (Phase 12) must be rejected by BOTH the kernel (proof no longer checks) AND tsp-test (shrunk counterexample) — independent failure detectors.

3.4 Persistence Boundary (NONE)

  • No database, no on-disk state, no caches, no network. Pure batch transform: (.lang + proof + program) -> {Ok / KernelError / TypeError / TestResult}. Files are read-only inputs; the only outputs are exit codes + diagnostics on stdout/stderr. Determinism: same inputs (and same RNG seed for tsp-test) -> same verdict; reproducibility is a conformance requirement (Phase 13).

3.5 Component Responsibilities (one box = one crate)

tsp-syntax — The untrusted metalanguage front end. In: &str of a .lang file (sort declarations, term/type grammars with binding annotations, judgment forms, inference rules) and object-term text. Out: LangDef { sorts, grammar, judgments, rules } + Term/Type values, or ParseError { ParseErrorKind: UnexpectedToken | UnknownSort | BadBinder | MalformedRule }. Components: Lexer, Token, Parser. no_std + alloc. Invariant: every emitted Term is well-scoped (de Bruijn indices in range for declared binders) and every Rule references only declared sorts/judgments — a parser bug can only yield a malformed program/proof that a downstream check rejects, never a false theorem. Built in: Phase 0 (shells), Phase 2 (full LangDef + object-term parser + diagnostics).

tsp-term — Object-term representation + binding; the computational core the substitution lemma mirrors. In: AST from tsp-syntax. Out: Type (Base | Arrow | Prod | Sum | Ref | All | TyVar), Term (Var(usize) | Lam | App | TmTrue | TmFalse | If | Zero | Succ | ...), and the total functions shift(t,d,cutoff), subst(t,j,s) (capture-avoiding [s/j]t), alpha_eq(a,b) (structural), is_value(t). no_std + alloc. Invariant SUBST-1 (crux-adjacent): shift/subst implement the exact de Bruijn discipline the machine-checked substitution lemma encodes — capture-avoidance is automatic from correct cutoff arithmetic; an off-by-one in shift breaks the substitution lemma proof in tsp-meta. alpha_eq is plain structural equality because de Bruijn nameless terms quotient alpha-equivalence by construction. Built in: Phase 0 (Term/Type shells), Phase 1 (shift/subst/alpha_eq/is_value).

tsp-rules — Inductive relations + executable judgments. In: LangDef (rules) + Term/Type (+ tsp-term substitution functions). Out: Judgment { form, args }, Rule { name, premises, conclusion }, Derivation { rule, subderivations, conclusion }; check_deriv(d, rules) -> Result<(), DerivError> (is the derivation tree a valid instance of the rules?); infer(ctx, e) -> Result<Type, TypeError> / check (executable type checker, STLC then extensions); step(e) -> Option<Term> (small-step; None = value or stuck). Invariant RULES-1: check_deriv accepts a Derivation iff each node matches some Rule whose premises are recursively valid — it is the executable, data-level analogue of the kernel's proof-term check, and infer agrees with the typing relation it encodes. Invariant RULES-2: step realizes the small-step relation e --> e' via evaluation contexts / congruence; (optional) determinism. Built in: Phase 0 (Judgment/Rule/Derivation shells), Phase 3 (infer/check + check_deriv), Phase 4 (step + evaluation contexts).

tsp-kernel — THE trusted base: a lambda-Pi (LF) proof-term checker, deliberately tiny + audited. In: a KTerm and (for check_type) an expected KType in a Ctx. Out: infer_type(ctx,t) -> Result<KTerm, KernelError>, check_type(ctx,t,ty) -> Result<(), KernelError>, whnf(t) -> KTerm, equal(ctx,a,b) -> bool. KTerm = Var | Sort(Sort) | Pi | Lam | App; Sort = Type | Kind with Type : Kind. no_std + alloc. Curry-Howard: a Prop is a KType, a Proof is a KTerm that check_type accepts at that KType; conversion uses whnf + definitional equal (beta, optionally eta). Invariant KERNEL-1 (the project's foundation): infer_type/check_type are sound — they accept a KTerm at a type only if that typing genuinely holds in lambda-Pi; soundness of the entire metatheory reduces to this one checker being correct. Invariant KERNEL-2: total + panic-free on all KTerm inputs (no overflow, no unbounded recursion that escapes a depth guard) — fuzzed adversarially in Phase 13. Smallness is a design constraint, not an accident: nothing above it is trusted, so the audit surface must stay minimal. Built in: Phase 0 (KTerm/KType/Ctx shells), Phase 5 (bidirectional infer_type/check_type + whnf + equal).

tsp-meta — The metatheory layer; untrusted, every output re-checked by the kernel. In: Rule/Judgment/Derivation from tsp-rules + the kernel API. Out: object judgments encoded as kernel inductive signatures (propositions-as-types, LF-style) with their induction/elimination principles; the lemma library canonical_forms, inversion, weakening, and the substitution lemma; progress_statement(lang) -> KTerm and preservation_statement(lang) -> KTerm; Proof { goal: KTerm, term: KTerm } for each. Invariant META-1: every theorem ships as a Proof whose term check_types at goal — tsp-meta asserts nothing the kernel has not re-validated. Invariant META-2 (crux): the substitution lemma (Gamma,x:S |- e:T and Gamma |- v:S imply Gamma |- [v/x]e:T) is proved by mirroring tsp-term::subst/shift exactly; it is reused by Preservation at the beta/elimination step, while Progress consumes canonical_forms. Built in: Phase 6 (propositions-as-types encoding + derivation-as-proof-term), Phase 7 (structural lemmas + substitution), Phase 8 (Preservation), Phase 9 (Progress), Phase 10 (type-soundness corollary + re-establish on the extended language), Phase 12 (extend to references/System F + broken-rule: proof fails to check).

tsp-test — A PLT-Redex-style falsifier; empirical, never a proof. In: infer/step + the Rule set from tsp-rules. Out: Generator (size-bounded well-typed Term generation), Shrinker, check_progress(e) -> bool / check_preservation(e) -> bool, and TestResult = Pass(u64) | CounterExample(Term, Witness) (Witness = which property failed + how). Invariant TEST-1: the Generator emits only well-typed closed terms (so a failure is a genuine soundness violation, not a generation bug), and check_progress/check_preservation directly test the locked theorem statements. Invariant TEST-2 (dual-guard agreement): on a sound language tsp-test yields only Pass; on a deliberately broken rule it must produce a CounterExample shrunk to a minimal Term, agreeing with the kernel's rejection. Built in: Phase 11 (Generator/Shrinker + property checks + cross-validation against the proofs), Phase 12 (catch the broken rule), Phase 13 (throughput targets + tester-vs-proof agreement gate).

tsp-cli — The tsp binary; orchestrates, holds no metatheory logic. In: command-line args + files. Out: subcommands check (run a LangDef + its soundness Proof through the kernel), test (randomized soundness via tsp-test), typecheck (object infer), step (object step); exit code + diagnostics. std (only crate using std: argv, file IO, stderr). Invariant CLI-1: a non-zero exit on any KernelError/TypeError/DerivError/CounterExample; check succeeds only when the kernel accepts every Proof. Invariant CLI-2: deterministic for fixed inputs + RNG seed (no hidden state, per 3.4). Built in: Phase 0 (skeleton + smoke test: typecheck of Lam(Bool, Var 0) : Bool->Bool; step of (Lam x. x) true --> true), wired progressively as each lower crate lands.

8. Domain Model — Object Calculi, Judgments, and the Proof Kernel

The domain has two strata: the object level (textbook calculi — STLC + extensions — whose soundness we prove, lives in tsp-term/tsp-rules) and the meta level (the lambda-Pi logical framework in tsp-kernel that checks the proofs about the object level, glued by tsp-meta). Every object-level artifact (term, type, typing judgment, derivation, lemma) is reflected into a KTerm/KType and re-validated by the trusted kernel. This section pins the grammars, the index arithmetic, the inference rules, the metalanguage that defines a calculus, the kernel's own type theory, the propositions-as-types bridge, and the worked examples that fix semantics with zero ambiguity.

8.1 Object Syntax — EBNF (STLC + locked extensions)

Concrete surface grammar parsed by tsp-syntax into tsp-term::{Term, Type}. Greek written ASCII; -> is the type arrow, --> is reduction (never in surface syntax).

Type  ::= Atom                          (* Base(Atom): Bool, Nat, ... *)
        | Type "->" Type                (* Arrow; right-assoc *)
        | Type "*"  Type                (* Prod *)
        | Type "+"  Type                (* Sum *)
        | "Ref" Type                    (* Ref; references stretch *)
        | "All" "." Type                (* All; System F stretch, binder over TyVar *)
        | TyIdx                         (* TyVar(usize); de Bruijn type var *)
        | "(" Type ")"
Term  ::= Ident                         (* surface name; elaborated to Var(index) *)
        | "\\" ":" Type "." Term        (* Lam(Type, body); 1 binder *)
        | Term Term                     (* App; left-assoc *)
        | "true" | "false"              (* TmTrue / TmFalse *)
        | "if" Term "then" Term "else" Term      (* If *)
        | "0"                           (* Zero *)
        | "succ" Term                   (* Succ *)
        | "(" Term "," Term ")" | "fst" Term | "snd" Term     (* Prod ctors/dtors *)
        | "inl" Term | "inr" Term | "case" Term "of" Term "|" Term  (* Sum *)
        | "ref" Term | "!" Term | Term ":=" Term              (* Ref stretch *)
        | "(" Term ")"

Precedence (tight→loose): application > succ/ref/!/fst/snd/inl/inr > * > + > -> > \./if/case. Atom = interned identifier (a u32 symbol; Type::Base / Judgment::form reuse the same intern table).

8.2 De Bruijn Representation — Index Arithmetic (the computational core)

Var(n) = the binder n levels out; n counts intervening Lam (term) binders (and All for TyVar). Lam binds index 0 in its body; subst/shift are the exact arithmetic the substitution lemma must mirror — an off-by-one here breaks Phase 7's machine-checked proof.

shift(t, d, c) adds d (may be negative) to every free index (index >= c); c (cutoff) counts binders crossed so it never touches bound indices.

shift(Var n, d, c)        = Var n               if n <  c     (bound -> unchanged)
                          = Var (n + d)         if n >= c     (free  -> shifted; n+d >= 0 required)
shift(Lam ty b, d, c)     = Lam ty (shift(b, d, c+1))         (entering binder bumps cutoff)
shift(App f a, d, c)      = App (shift f d c) (shift a d c)
shift(If c1 t e, d, c)    = If (shift c1 ..) (shift t ..) (shift e ..)   (* every subterm, same c *)
shift(Succ e, d, c)       = Succ (shift e d c)                (* TmTrue/TmFalse/Zero: no recursion *)

subst(t, j, s) = [s/j] t: replace Var j by s, with s shifted up by the binder depth so its free variables stay free under the binders of t.

subst(Var n, j, s)        = s                   if n == j
                          = Var n               otherwise
subst(Lam ty b, j, s)     = Lam ty (subst(b, j+1, shift(s, 1, 0)))   (j bumped; s shifted under binder)
subst(App f a, j, s)      = App (subst f j s) (subst a j s)
(structural recursion through If/Succ/pairs/sums identically, j unchanged at non-binders)

Beta-reduction (the redex (\:T.b) v) uses the standard substitute-then-shift-down idiom so the consumed binder's slot vanishes:

beta(Lam _ b, v)  =  shift( subst(b, 0, shift(v, 1, 0)), -1, 0 )

alpha_eq(a,b) is then structural == on the Term trees (de Bruijn makes alpha-equivalence syntactic — no name comparison; capture-avoidance is automatic given correct shift). is_value(t): Lam | TmTrue | TmFalse | Zero | Succ(v if is_value v) | (v1,v2) | inl v | inr v (+ Ref locations in the stretch).

8.2.1 Worked substitution example (capture-avoidance via shift)

Reduce (\:Bool. \:Bool. 1) true — outer \ binds index 0, inner body Var 1 refers *past* the inner binder to the outer one. Must yield a term where the surviving free reference is preserved, **not** captured by the inner \.

Reducing the redex App (Lam Bool (Lam Bool (Var 1))) TmTrue: beta sets b = Lam Bool (Var 1) and v = TmTrue. Since TmTrue carries no free variables, shift(v,1,0) leaves it unchanged. Substituting into b, entering the inner Lam bumps the target index to j=1; Var 1 matches exactly and is replaced, giving Lam Bool TmTrue. The closing down-shift shift(_,-1,0) has no free index left to lower, so the result is Lam Bool TmTrue — the constant-true function of type Bool -> Bool.

Contrast the naive (no-shift) bug: substituting a v containing Var 0 into Lam's body without shift(v,1,0) would let the inner binder capture it — exactly the defect the substitution lemma forbids and the kernel proof would fail to discharge.

8.3 Typing Rules — Gamma |- e : T (inference-rule notation)

Gamma = de Bruijn Context (a Vec<Type>, index 0 = innermost binding). Gamma |- e : T is an inductive Judgment with form = Has-Type. tsp-rules::infer is the executable, syntax-directed reading; check_deriv validates an explicit Derivation tree against these Rules.

            x:T in Gamma  (Gamma[x] = T)
T-Var       ----------------------------                 (de Bruijn lookup at index x)
                  Gamma |- Var x : T

            Gamma, S |- e : T
T-Abs       --------------------------                   (push S; body typed under extended ctx)
            Gamma |- Lam S e : S -> T

            Gamma |- f : S -> T     Gamma |- a : S
T-App       ---------------------------------------
                    Gamma |- App f a : T

T-True   ------------------- Gamma |- true : Bool      T-False ----- ... |- false : Bool

            Gamma |- c : Bool   Gamma |- t : T   Gamma |- e : T
T-If        ----------------------------------------------------
                       Gamma |- If c t e : T

T-Zero  --------------- Gamma |- 0 : Nat        T-Succ  (Gamma |- e:Nat) / Gamma |- Succ e : Nat

            Gamma |- e1 : S   Gamma |- e2 : T            Gamma |- p : S * T
T-Pair      -------------------------------    T-Fst    -------------------    (T-Snd symmetric: snd p : T)
            Gamma |- (e1,e2) : S * T                     Gamma |- fst p : S

            Gamma |- e : S                               Gamma |- s : S+T  Gamma,S |- l:R  Gamma,T |- r:R
T-Inl       ---------------------   (T-Inr -> S+T)  T-Case ----------------------------------------------
            Gamma |- inl e : S + T                                Gamma |- case s of l | r : R

Refs stretch (Phase 12) adds a store typing Sigma (judgment Gamma | Sigma |- e : T): T-Ref : (..|-e:T)/ ref e : Ref T, T-Deref : (..|-e:Ref T)/ !e : T, T-Assign : (..|-e1:Ref T, ..|-e2:T)/ e1:=e2 : Unit. System F stretch adds T-TAbs/T-TApp over All/TyVar with type-level shift/subst.

8.4 Small-Step Semantics — e --> e', Values, Evaluation Contexts

Call-by-value, left-to-right. tsp-rules::step(e) -> Option<Term> (None = value-or-stuck). Computation rules (redexes) + congruence via evaluation contexts E.

Values v ::= Lam S e | true | false | 0 | succ v | (v,v) | inl v | inr v

E ::= []                                       (* the hole *)
    | E a | v E                                (* App: function before argument *)
    | If E t e
    | succ E | (E, a) | (v, E) | fst E | snd E
    | inl E | inr E | case E of l | r          (* + ref E | ! E | E := a | v := E  (stretch) *)

           e --> e'
E-Ctx   --------------                         (* congruence: reduce inside the unique hole *)
        E[e] --> E[e']

E-AppAbs   (App (Lam S b) v) --> beta(Lam S b, v)            (v a value; see 8.2 beta)
E-IfTrue   If true  t e --> t        E-IfFalse  If false t e --> e
E-FstPair  fst (v1,v2) --> v1        E-SndPair  snd (v1,v2) --> v2
E-CaseInl  case (inl v) of l|r --> beta(l, v)    E-CaseInr  case (inr v) of l|r --> beta(r, v)

E decomposition is unique for any non-value closed e (the redex position is determined) → step is deterministic (optional Phase 4 theorem step is a partial function). A closed, well-typed e is either a value or E[redex] with a matching computation rule — this is progress (Section 8.5(ii) / Phase 9). A stuck term is a non-value with no rule (e.g. If 0 t e, fst true) — soundness states these are unreachable from well-typed terms.

8.5 The Metalanguage — LangDef (defining a calculus as data)

A .lang file declares a calculus; tsp-syntax parses it into LangDef { sorts, grammar, judgments, rules }. This is how an object language is specified once and consumed by every downstream crate (checker, stepper, kernel encoder, tester).

LangDef    ::= { SortDecl | Production | JudgmentForm | RuleDef }
SortDecl   ::= "sort" Atom { "," Atom }                       (* -> Vec<Atom> sorts: Term, Type, Ctx *)
Production ::= "grammar" Atom "::=" Alt { "|" Alt }           (* -> Production; per-sort grammar *)
Alt        ::= Ctor { SortRef | "(" Binder ")" }
Binder     ::= "binds" Atom "in" SortRef                      (* binding annotation -> de Bruijn arity *)
JudgmentForm ::= "judgment" Atom "(" SortRef { "," SortRef } ")"   (* e.g. Has-Type(Ctx,Term,Type) *)
RuleDef    ::= "rule" Atom ":" { Judgment } "----" Judgment   (* premises ---- conclusion *)

Maps directly onto the locked types:

.lang construct parses to consumed by
sort LangDef.sorts: Vec<Atom> scope/arity checks in tsp-syntax
grammar + binds LangDef.grammar: Vec<Production> de Bruijn elaboration in tsp-term
judgment LangDef.judgments: Vec<JudgmentForm> Judgment.form validation
rule .. ---- .. LangDef.rules: Vec<Rule> (premises,conclusion) check_deriv; kernel encoding

ParseErrorKind: UnexpectedToken, UnknownSort (sort used before sort-declared), BadBinder (binds over a non-binding position / arity mismatch), MalformedRule (no ----, or conclusion form not a declared judgment). The locked STLC .lang declares sort Term, Type, Ctx; the grammar of 8.1; judgment Has-Type(Ctx,Term,Type) and judgment Step(Term,Term); and the rules of 8.3–8.4.

8.6 The Proof Kernel — lambda-Pi (LF) Core: Grammar + Typing

The trusted computing base. A dependently-typed lambda-Pi calculus with two sorts Type : Kind (Sort::Type, Sort::Kind). Prop = KType, Proof = KTerm; "valid" means check_type accepts. Target TCB size <= 800 LOC (Section targets / Phase 13 gate).

KTerm s,t,A,B ::= Var n            (de Bruijn, into Ctx)
                | Sort Type | Sort Kind
                | Pi A B           (dependent function type; B under one binder)   (* Box<KTerm>,Box<KTerm> *)
                | Lam A b          (abstraction; domain A, body b under binder)
                | App f a
Ctx Gamma     ::= .  |  Gamma, A           (de Bruijn list of KTerm "types"; shift on lookup)

KType is the subset of KTerm inhabiting a Sort. Kernel shift/subst on KTerm are the same de Bruijn arithmetic as 8.2 (one binder per Pi/Lam). Bidirectional checker: infer_type synthesizes, check_type checks against an expected type (drives App argument checking and Lam under a Pi).

            Gamma(n) = A
K-Var       --------------                      (de Bruijn context lookup, shifted)
            Gamma |- Var n : A

K-Type   ------------------------ Gamma |- Sort Type : Sort Kind        (Type : Kind, no Kind : _)

            Gamma |- A : Sort s1     Gamma, A |- B : Sort s2
K-Pi        --------------------------------------------------         (s1,s2 in {Type,Kind}; PTS-style)
                     Gamma |- Pi A B : Sort s2

            Gamma, A |- b : B
K-Lam       ---------------------------                                (well-formed Pi presupposed)
            Gamma |- Lam A b : Pi A B

            Gamma |- f : Pi A B     Gamma |- a : A
K-App       ----------------------------------------                   (result = subst(B, 0, a) up to shift)
                  Gamma |- App f a : [a/0] B

            Gamma |- t : A     Gamma |- B : Sort s     A == B  (defeq)
K-Conv      ---------------------------------------------------         (the conversion rule)
                          Gamma |- t : B

A == B in K-Conv is equal(ctx, A, B) — definitional equality, not syntactic. K-App's dependency [a/0]B is what makes propositions-as-types expressive (a typing judgment indexed by a term).

8.6.1 whnf + Definitional Equality

whnf(t): reduce only the head redex until the outermost former is exposed (a Var/Sort/Pi/Lam head, or a stuck App). One rule — head beta — applied repeatedly; no reduction under binders or in arguments (that is the weak, head discipline → cheap, terminating on well-typed terms).

On an App f a head, whnf recurses on f; if that yields a Lam _ b, it fires the head redex (beta) and continues from the result, otherwise it stops with the stuck application App (whnf f) a. Var/Sort/Pi/Lam heads are already in weak-head normal form and return unchanged.

equal(ctx,a,b) = type-directed / structural conversion with beta (and optional eta): both sides are first reduced to whnf, then compared head-by-head — Vars by index equality, Sorts by equality, Pi A B/Pi A' B' by equal-ing domains and (under the shared binder) codomains, Lam A b/Lam A' b' likewise on domain and body, and two stuck Apps by equal-ing both the head and the argument. If eta is enabled, a Lam compared against a non-Lam g is equal when b equals App (shift g 1 0) (Var 0) (the eta-expansion of g). Any other head shape mismatch is unequal.

Decidability rests on whnf termination for well-typed KTerms; equal is the only place conversion happens, so it is small and heavily audited (a bug here = unsoundness — see 8.8).

8.7 Propositions-as-Types — Encoding Judgments & Derivations (Curry-Howard)

tsp-meta reflects the object level into the kernel: each object Judgment becomes a KType (an LF type family indexed by encoded terms), each Rule becomes a Pi-typed constructor, each Derivation becomes a KTerm proof term. The logical reading:

Logic / metatheory lambda-Pi former kernel API
implication P => Q Pi P (shift Q) (non-dependent Pi) K-Pi
universal forall x:A. P Pi A P (dependent) K-Pi
atomic prop `Gamma - e : T` KType: App(App(App HasType g) e) t
conjunction P /\ Q encoded pair type (Church/sigma) derived
a Rule's validity Pi-chain: premises → conclusion progress_statement/preservation_statement
a Derivation applied constructors = a KTerm check_type
"proof is valid" check_type(ctx, term, goal) = Ok the kernel

Locked statements (Phases 8–9), as KTerm props built by tsp-meta:

preservation_statement(lang)  ==  Pi e:Term. Pi T:Type. Pi e':Term.
                                    HasType nil e T  ->  Step e e'  ->  HasType nil e' T
progress_statement(lang)      ==  Pi e:Term. Pi T:Type.
                                    HasType nil e T  ->  ( Value e  \/  Exists e':Term. Step e e' )

Proof { goal: KTerm, term: KTerm }: the proof obligation is discharged iff check_type(&Ctx::empty(), &proof.term, &proof.goal) == Ok(()). The object-level Rules of 8.3–8.4 become the inductive type family constructors; tsp-meta also emits the eliminator / induction principle for Has-Type (the dependent recursor) — this is what the preservation/progress proof terms apply to do induction on the typing derivation (8.8(ii)).

8.8 Worked Examples

(i) Typecheck + step a concrete STLC term

(\:Bool. if 0 then false else true) true — apply the boolean-negation function to true.

Let term = App (Lam Bool (If (Var 0) TmFalse TmTrue)) TmTrue. Typing by T-App needs both subterms: the Lam pushes Bool onto the context and, inside, T-If types Var 0 as Bool (T-Var lookup) with both branches Bool, so the Lam has type Bool -> Bool; TmTrue types as Bool by T-True. Matching S -> T = Bool -> Bool against argument type S = Bool yields result T = Bool. Stepping term fires E-AppAbs (the argument TmTrue is a value): the beta result is shift(subst(If (Var 0) TmFalse TmTrue, 0, TmTrue), -1, 0) = If TmTrue TmFalse TmTrue, which itself steps by E-IfTrue to the value TmFalse (step then returns None).

infer before and after gives Bool (preservation holds on this trace); final term is a value (progress terminated correctly).

(ii) Canonical forms + a slice of preservation, as a kernel-checked proof term

Canonical forms (Bool): if |- v : Bool and Value v then v in {true,false}. As a KType and its proof:

canon_bool : Pi v:Term. HasType nil v Bool -> Value v -> ( Eq v TmTrue \/ Eq v TmFalse )

Its proof term abstracts over v, the typing witness, and the value witness, then applies the Has-Type eliminator to that pair — inversion leaves only the T-True/T-False constructor cases live, each directly yielding the disjunct (invalid constructors at Bool, e.g. from If or App, are ruled out because no Rule concludes Has-Type _ _ Bool for them at a value).

Preservation slice — the E-AppAbs case (where the substitution lemma is invoked). The proof term applies the typing eliminator; at the beta step it feeds the substitution lemma subst_lemma (Phase 7) — itself a kernel term mirroring tsp-term::subst:

subst_lemma : Pi G:Ctx.Pi S:Type.Pi T:Type.Pi e:Term.Pi v:Term.
                 HasType (cons S G) e T -> HasType G v S -> HasType G (subst e 0 v) T

For the E-AppAbs case, inversion of T-App recovers f = Lam S b with HasType nil (Lam S b) (S->T) and HasType nil v S; the preservation proof term applies subst_lemma to the inverted abstraction typing and the argument typing to produce HasType nil (subst b 0 v) T — exactly the type of beta (Lam S b) v. check_type(&empty, pres_appabs_term, preservation_statement) returns Ok(()) iff the index arithmetic in the stated subst matches the kernel's subst — i.e. the proof type-checks exactly when tsp-term::subst is correct. This is the load-bearing coupling.

(iii) Redex-style counterexample for a DELIBERATELY broken rule

Break T-App to ignore the argument type (the classic POPLmark-style bug):

T-App-BAD    Gamma |- f : S -> T     Gamma |- a : ANY      (* premise "a : S" dropped *)
             ------------------------------------------
                      Gamma |- App f a : T

tsp-test::Generator produces a well-typed-under-BAD term; check_preservation/check_progress falsify it; Shrinker minimizes:

The Generator (size ≤ 4) yields a well-typed-under-BAD candidate such as App (Lam Bool (If (Var 0) ..)) Zero — Zero : Nat fed where the (unchecked) argument position expected Bool. check_progress finds it neither a value nor able to step: step reduces to If Zero TmFalse TmTrue, which is STUCK (no E-If rule matches a Nat guard), so the property is FALSE. The Shrinker reduces this to the minimal witness App (Lam Bool (Var 0)) Zero, reported as TestResult::CounterExample with a Witness naming the failed property (Progress) and the stuck subterm.

Dual guard: simultaneously, tsp-meta cannot build a checking proof term under T-App-BAD — progress_statement's proof needs canonical_forms at Bool, but Zero is not a Bool canonical form, so check_type returns Err (the proof fails to check). The kernel and the tester agree the language is unsound (Phase 12).

Invariant (gravest failure class): infer_type/check_type must never return Ok for an ill-typed KTerm and must never panic on adversarial input — accepting one bad proof term silently validates a false theorem and collapses the entire project's guarantee. Every malformed object-level artifact is caught at its own layer; anything that slips through is the kernel's last-line responsibility, which is why the TCB is kept <= 800 LOC and audited (8.6, Phase 13).
