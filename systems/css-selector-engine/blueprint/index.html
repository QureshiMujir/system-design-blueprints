258 — CSS Selector Engine

Goal: Implement, from scratch in Rust, a complete CSS selector engine — a CSS Syntax Level 3 tokenizer, a Selectors Level 4 grammar parser producing an immutable AST, exact specificity computation, a right-to-left matching engine generic over any host tree via an Element trait, the DOM selector APIs (matches / querySelector / querySelectorAll / closest), ancestor Bloom-filter rejection + selector bucketing for sub-linear matching, :has() relational matching, and a minimal invalidation engine. Pass the WPT selectors + querySelector suites and differential-test against the Servo selectors crate. It is a selector engine, not a cascade/layout engine (that is #124).

Project Number: 258

Project Name: CSS Selector Engine

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal

Goal: A from-scratch Rust library that parses a CSS Selectors Level 4 string into a typed immutable AST, computes specificity, and answers "does this node match / which nodes match" against an arbitrary host tree — fast, memory-safe, no_std-friendly — plus the selq CLI.

1.1 Engineering definition (what is built)

Pipeline: selector string + host tree -> match verdict / matched node set.

1.10 Language: Rust (edition 2021, MSRV 1.78)

Core crates no_std + alloc; std only in sel-dom + sel-cli.

Why Rust Detail
Untrusted hot path parses untrusted strings + walks untrusted trees -> memory safety non-negotiable
Sum types enums + exhaustive match model AST (Component) + matching state machine, zero-cost
Zero-cost generics E: Element monomorphizes -> no vtable on the match hot path; cache layout controlled for BloomFilter/SelectorMap

Rejected: C/C++ (memory-unsafe on untrusted-input hot path); Go (no sum types, weaker zero-cost generics for Element); TypeScript (no control over allocation / cache layout for Bloom / SelectorMap fast paths).

  • Rust trait objects vs generics (why E: Element is generic, not dyn).

  • Counting Bloom filter (no false negatives invariant; ancestor fast-reject).

2. Why Build This

2.1 Unique systems knowledge

Concept What it teaches Where it lives
Sub-linear tree matching Answer "which of N nodes match S" without O(N· S
Right-to-left evaluation Counter-intuitive: start at candidate, match rightmost compound first — most selectors fail there, so RTL rejects fastest; LTR would explore exponential descendant fan-out Phase 7
Combinator backtracking Bounded (Child/NextSibling = no backtrack) vs unbounded (Descendant/LaterSibling = backtrack) walks; a hand-written matching state machine, not regex Phase 7
Bloom ancestor rejection AncestorHashes (3×24-bit) vs counting BloomFilter (4096 buckets) — invariant: zero false negatives, false positive = slow path only Phase 10
Specificity algebra (a,b,c) triple packed to one u32, 8-bit saturating fields; :is/:not/:has take most-specific arg, :where = 0 Phase 6
Forgiving vs non-forgiving grammar Error-recovery as a typed property: :is()/:where() drop invalid args, :not()/:has()/top-level querySelector raise SyntaxError Phase 5, 9
Privacy engineering :visited cannot leak history: compute both states under VisitedHandlingMode, API collapses them so timing/style probing can't distinguish Phase 8, 9
Generic host abstraction Element trait = decouple engine from any tree (DOM, JSX, syntax tree); OpaqueElement identity without exposing nodes Phase 0, 7
Incremental invalidation DependencySet/InvalidationSet built at insert time -> RestyleHint from a mutation = re-match minimal node set, not full tree Phase 12

2.2–2.5 Context and calibration

Why it matters: hot path of every browser style recalc and every querySelectorAll — millions of times per page load. Canonical prior art: jQuery Sizzle (RTL matching + bucketing in JS, 2009), Servo selectors crate (model for this engine), WebKit/Blink SelectorChecker + RuleSet + RuleFeatureSet. Architecturally: the same shape as a DB query planner (index = Bloom filter, predicate pushdown = RTL rejection).

Engineering muscles: spec reading (3 normative specs) → typed AST (Rust sum types, exhaustive match); hand-written tokenizer/parser → state-machine matching with backtracking; cache-aware data layout (Bloom) → micro-opt under no_std+alloc; fuzzing (adversarial safety); differential testing vs reference; :visited non-leak as an invariant, not a patch.

Cross-links: 124 HTML/CSS Layout Engine (downstream cascade consumer, explicit non-goal here); 260 Browser Rendering Pipeline (style-recalc stage, RestyleHint gates relayout/repaint); 126 JavaScript Engine (hosts DOM, querySelector* boundary); 259 JS Parser (sibling parser discipline); 127 Tree-Sitter (conceptual mirror of invalidation); 61 Regex Engine (RTL state machine); 62 Lexer (sel-tokenizer specialization); 63 Parser Combinators (contrast: hand-written vs combinator ergonomics).

Calibration: RTL matching + Bloom rejection permanently changes how you read any "match items against a structure" problem. The Element trait pattern is a reusable blueprint for a library that must run against trees you don't own. :visited teaches that some correctness requirements are adversarial — the answer is indistinguishability, not best-effort.

2.6 What Mastery Looks Like

  • Phase 1 (§13): Given any CSS Syntax L3 input, trace exact tokenization: which code-point class fires, why an escape upgrades CowRcStr from Borrowed to Owned, what IDHash vs Hash means for the parser.
  • Phase 2 (§14): Read a Selector's Box<[Component]> slice and recite exactly which element each index matches against and in which tree direction — without running the code.
  • Phases 3–6 (§15–§18): Derive the specificity (a,b,c) for any nested :is()/:where()/:not()/:has() combination, including saturation cases, entirely by inspection.
  • Phase 7 (§19): Given a selector and a tree, hand-trace the RTL walk: which compound fires, which combinator direction, when backtracking triggers, where it exits — and predict whether BloomFilter fast-rejects before the walk starts.
  • Phase 10 (§22): Explain why a counting Bloom (not bitset) is required, size AncestorHashes to ≤12 B, and bound the false-positive rate analytically from bucket count and typical ancestor depth.
  • Phase 11 (§23): Design the :has() complexity guards from first principles: what makes relational matching O(subtree), how cap + visited-set prevent DoS, and what the correctness tradeoff of bailing to false is.
  • Phase 12 (§24): Trace a class-toggle mutation through DependencySet → InvalidationSet → RestyleHint, explain why under-invalidation is fatal and over-invalidation is merely slow, and size the over-invalidation ratio from selector structure.
  • Phase 13 (§25): Design the differential test harness from scratch: oracle choice, corpus seeding, adapter strategy, and why WPT alone is insufficient to catch Bloom false-negatives.

3. Architectural Overview

                 Host application / CSSOM / style system
            querySelector   querySelectorAll   matches   closest
                                  |  selector string (UNTRUSTED) + Element tree (UNTRUSTED)
   ===== TRUST BOUNDARY ======================================================
                                  v
   sel-query : query_selector / _all · matches · closest · :scope · SyntaxError · :visited gate
        | parse                                              | match
        v                                                    v
   sel-parser : grammar -> AST                          sel-matching : matches_selector (right-to-left)
     SelectorList / Selector / Component / Combinator      MatchingContext · AncestorHashes · BloomFilter
     Specificity · ToCss serialization  -------AST------>   SelectorMap · NthIndexCache · invalidation
        | tokens                                            | Element trait (host-tree abstraction)
        v                                                    v
   sel-tokenizer : Syntax L3 Token stream               sel-dom : reference tree (NodeRef) impl Element

   selq (sel-cli) drives: parse · specificity · serialize · match · query · bench  (std harness over all)

   DATA FLOWS:  selector &str --tokenize--> Token<'i> --parse--> Selector (immutable AST)
                Element tree  --walk (read-only)--> matches_selector -> bool / Vec<E>
   CONCURRENCY: post-parse Selector/SelectorList = immutable, Send+Sync -> share across threads;
                matching is read-only over the tree (&E) -> querySelectorAll parallelizes by subtree;
                MatchingContext is per-thread, &mut (caches/bloom) -> NOT shared.
   PERSISTENCE: none at runtime; compiled Selector + AncestorHashes + SelectorMap MAY be cached/
                memoized by the host across calls (pure fn of selector string). No I/O on hot path.

The boundary at the top is the only place untrusted bytes enter: a selector &str and a host tree reachable through Element. Everything below the boundary is total (no panics on adversarial input — malformed selectors become ParseError/SyntaxError, cyclic/deep trees are bounded by nesting_level). Left pipeline = compile (string -> AST); right pipeline = match (AST + tree -> answer). The two pipelines meet only at the immutable Selector value, which is the serialization point for caching and the unit shared across threads.

3.1 sel-tokenizer

CSS Syntax L3 tokenization. Input: &'i str. Output: pull stream of Token<'i> via CowRcStr<'i> (zero-copy by default; owns only on escape-forced materialization). Emits IDHash/Hash, BadString/BadUrl error tokens, all An+B-relevant shapes. no_std + alloc. (Phase 1 §13)

3.2 sel-parser

Selectors L4 grammar (simple→compound→complex→list) to typed immutable AST. Load-bearing invariant: Components in matching order (rightmost compound first, Combinators interleaved). Computes Specificity during construction; owns ToCss serialization and ParseError/ParseErrorKind. Never panics. no_std + alloc. (Phases 2–6, 11, 13)

3.3 sel-matching — Element trait + MatchingContext + SelectorChecker

Matching engine. Element trait = host-tree abstraction (navigation, identity opaque()→OpaqueElement, predicates, match_non_ts_pseudo_class, add_element_unique_hashes). Entry point: matches_selector(sel, offset, hashes, el, ctx)→bool. RTL walk: rightmost compound first, Combinator components leftward; unbounded combinators backtrack, bounded ones do not. MatchingContext threads bloom_filter, nth_index_cache, VisitedHandlingMode, QuirksMode, scope_element, nesting_level. no_std + alloc, generic over E: Element. (Phases 7–12)

3.4 AncestorHashes + BloomFilter

Ancestor-based fast reject. AncestorHashes { packed: [u32;3] } stores ≤3 hashes (ids/classes/local-names left of a descendant/child combinator), 3×24-bit + overflow bits. BloomFilter: counting Bloom, 4096 8-bit buckets, 2 hash slots/insert, built from all candidate ancestors via add_element_unique_hashes. Zero false negatives invariant — a real match is never rejected; FP only costs the slow path. Counting allows push/pop on traversal stack. (Phase 10 §22; reused in Phases 11–12)

3.5 SelectorMap

Rule bucketing by rightmost simple selector. SelectorMap<T>: id_hash / class_hash / local_name_hash / namespace_hash buckets + other: Vec<T> fallback. For each element, retrieves only candidate selectors matching its id/class/local-name. Union of buckets is a superset of all matching selectors (lossless). (Phase 10 §22; feeds Phase 12 dependency indexing)

3.6 NthIndexCache

Memoizes (parent, of-type?) → child-index maps; turns repeated :nth-* index computation from O(siblings) to O(1) amortized. 1-based. Valid only for an unmutated MatchingContext; scoped to one matching pass, discarded or invalidated on structural mutation. (Phase 4 §16, Phase 10 §22, Phase 12 §24)

3.7 Invalidation subsystem

At insert: build DependencySet (per-selector) + InvalidationSets (class/id/attr/local-name keys). On mutation: compute RestyleHint bitflags (RESTYLE_SELF, RESTYLE_DESCENDANTS, RESTYLE_LATER_SIBLINGS). Invariant: soundness over minimality — hint must cover every element whose match result could change; over-invalidation is slow, under-invalidation is a correctness bug. Modeled on Blink RuleFeatureSet. (Phase 12 §24)

3.8 sel-dom

Reference tree (NodeRef/RcDom) implementing Element for tests, CLI, conformance, fuzzing. Faithful but minimal: correct navigation, case-sensitivity, namespace — no layout/style/cascade. Only crate (besides sel-cli) using std. (Phases 0, 7, 13)

3.9 sel-query

DOM selector API: matches/query_selector/query_selector_all/closest, :scope resolution, SyntaxError on invalid input, :visited security gate. Non-forgiving top-level parsing; collapses VisitedHandlingMode visited/unvisited before returning. Generic over E: Element, no_std + alloc. (Phase 9 §21)

3.10 sel-cli (selq)

selq binary: subcommands parse, specificity, serialize, match, query, bench. Thin orchestration over public APIs, zero matching logic of its own. std harness exercising the whole stack. Used throughout as manual repro and debugging front door. (Phases 6, 13)

4.2 Complexity Caps (DoS Bounds)

Untrusted selector strings + untrusted trees → every recursive/unbounded dimension MUST be hard-capped at parse time; exceeding a cap returns ParseError, never a panic or unbounded work.

Dimension Cap Failure Why
Combinator depth (complex selector length) 1024 Components ParseErrorKind::UnexpectedToken bound backtracking work in matches_selector
:has() nesting depth 4 BadPseudo relational match is O(subtree) per level; nesting multiplies subtree walks
:is() / :where() / :not() argument count 256 selectors EmptySelector/UnexpectedToken forgiving lists still allocate one Selector each
Functional pseudo nesting (any) 32 BadPseudo bound parser recursion → no stack overflow on untrusted input
An+B coefficient magnitude fits i32 BadNthExpression reject overflowing literals

MatchingContext.nesting_level tracks runtime relational/logical recursion; :has() forward/backward matching (Phase 11, ## 23) consults it against the depth cap and bails to false rather than recurse without bound.

4.3 CPU / Cache Assumptions and Out-of-Scope Budgets

CPU/cache: hot path (matches_selector RTL loop + BloomFilter lookup) sized to L1/L2. AncestorHashes (12 B) = one cache line; BloomFilter (4096 B) L1-resident across a query_selector_all sweep. No SIMD; no hot-path atomics; Specificity is a one-integer compare. No false negatives: FP costs only a slow path.

Out-of-scope (N/A): NUMA/thread affinity (caller concern); network/disk/RPC (no I/O on parse or match); GC pauses (Rust ownership, no runtime); std only in sel-dom/sel-cli.

4.5 Recovery & Availability

  • Parsing never panics. Every malformed / oversized / unsupported input → ParseError { ParseErrorKind } (UnexpectedToken, EmptySelector, DanglingCombinator, BadPseudo, UnsupportedPseudo, BadAttributeSelector, UnclosedBlock, BadNthExpression, NamespaceUnknown). No unwrap/panic!/unreachable! reachable from untrusted input on parse or match paths.
  • Matching never panics: a parsed Selector is already validated; matches_selector is total over any E: Element tree.
  • API boundary: query_selector / query_selector_all / closest surface invalid input as SyntaxError (non-forgiving top level); valid-but-unmatchable → Ok(None) / Ok(vec![]).
  • Availability invariant: a malformed selector can never take down the host. Worst case = bounded ParseError or bounded-work false; no crash, no hang, no unbounded allocation.
  • Fuzzing (Phase 13, ## 25) enforces the no-panic and bounded-work invariants on parse / roundtrip / match corpora.

6. Design Principles

Twelve non-negotiable principles. Each is load-bearing: violating it produces a concrete, named failure mode. Phases 0–13 (## 12–## 25) cite these by number.

# Principle Statement Key Tradeoff Violation → Failure
6.1 Spec is the oracle Selectors L4 + CSS Syntax L3 + WHATWG DOM are normative; disagreement = bug, full stop. Spec fidelity > intuitive behavior. Invent "tidy" semantics for :nth-child(0) → silently mis-match real pages.
6.2 Parsing never panics Every fallible path returns Result<_, ParseError>/SyntaxError; never panic!, unwrap, OOB. More ?-plumbing vs. terse code. One unwrap on malformed escape → attacker crashes host with 6-byte selector (DoS); in no_std an unwind is UB.
6.3 Right-to-left, reject early Match rightmost compound first; most selectors fail there → fewest tree steps. RTL needs combinator backtracking for unbounded combinators. Backtracking complexity vs. LTR pathological cost on deep trees. LTR: div span visits every descendant before failing on subject → O(n) per candidate, latency targets blown.
6.4 Bloom filter: zero false negatives BloomFilter (4096 8-bit counting buckets, 2 slots/insert) built from all ancestors. A real match must NEVER be rejected; FP only costs the slow path. Correctness asymmetry deliberate: FN = correctness bug, FP = perf cost. Hash class case-sensitively, match case-insensitively → filter rejects genuine match → querySelectorAll silently drops nodes.
6.5 Selectors are immutable after parse SelectorList/Selector frozen: Box<[Component]>, no interior mutability, Send+Sync. All mutable match state in MatchingContext. Rebuild-on-change vs. in-place edit. Stash per-match state in AST → two threads race on shared selector → data race / UB.
6.6 Generic over the host tree Engine accesses trees only through trait Element: Sized+Clone. sel-matching/sel-query are generic over E: Element with no concrete DOM dep. Monomorphization / code-size cost. Hard-code sel-dom::NodeRef in matcher → can't embed in project 124 or Servo.
6.7 Forgiving where spec says forgiving :is()/:where() use forgiving lists (drop invalid args). :not()/:has()/top-level querySelector are non-forgiving (SyntaxError). Per-context forgiving: bool flag vs. one uniform mode. Make :not() forgiving → :not(:unsupported) matches everything → wrong nodes selected, invisibly.
6.8 Specificity computed once, at parse time Specificity{id,class,element} packed u32 (8-bit fields, saturating) stored in Selector. Matching never recomputes it. Parse does more work; benefit = O(1) per cascade query. Recompute at match time → hot querySelectorAll re-walks AST per candidate. Or compute :where() nonzero → cascade wrong in project 124.
6.9 No history leaks (:visited privacy) Engine computes both visited/unvisited under VisitedHandlingMode; API collapses to unvisited so timing/probing can't distinguish. Dual evaluation cost vs. exploitable fast path. querySelectorAll(":visited") returns real visited links → any script reads user's history.
6.10 Bounded complexity Hard caps on selector length, nesting depth (logical-pseudo 32, :has() 8), total components (8192). Exceeding = ParseError or bounded reject, never unbounded work. Reject pathological-but-legal selectors vs. accept exponential blowup. No :has() guard → :has(:has(:has(...))) on a wide tree → O(n²)+ → single query stalls host.
6.11 Deterministic serialization ToCss is canonical + stable: parse→serialize→parse is a fixed point. Same AST serializes identically. Normalization (whitespace, escapes, namespaces) vs. echoing input. Non-deterministic escape ordering → cache keyed on serialized form thrashes; differential diffs show phantom mismatches.
6.12 Observable matching + zero-copy tokens Opt-in trace hooks (zero-cost in release, behind feature flag) explain why a selector did/didn't match. CowRcStr<'i> borrows input; only allocates on escape-forced materialization. Lifetime plumbing. No hooks → debugging requires re-deriving RTL state by hand. Eager String allocation → per-query allocation storm defeats Phase 10 fast-reject targets.

8.1 Tokenization model (CSS Syntax Level 3)

8.2 Selector grammar (EBNF)

Normative grammar parsed by sel-parser. <ws> = optional WhiteSpace/Comment run; S = one required whitespace run (significant → descendant combinator). Terminals in UPPER are Token variants.

selector-list       ::= complex-selector ( <ws> COMMA <ws> complex-selector )*
relative-sel-list   ::= relative-selector ( <ws> COMMA <ws> relative-selector )*   (* :has() arg *)
relative-selector   ::= combinator? <ws> complex-selector                          (* leading combinator allowed *)

complex-selector    ::= compound-selector ( combinator compound-selector )*
combinator          ::= <ws> ">" <ws>          (* Child *)
                      |  <ws> "+" <ws>          (* NextSibling *)
                      |  <ws> "~" <ws>          (* LaterSibling / subsequent-sibling *)
                      |  S                      (* Descendant: required whitespace, no symbol *)

compound-selector   ::= ( type-selector subclass-selector* )
                      |  ( subclass-selector+ )
                      |  ( type-selector subclass-selector* pseudo-element-selector* )
type-selector       ::= ( ns-prefix? element-name ) | ns-prefix? "*"
ns-prefix           ::= ( IDENT | "*" )? "|"
element-name        ::= IDENT
subclass-selector   ::= id-selector | class-selector | attribute-selector | pseudo-class-selector
id-selector         ::= IDHASH
class-selector      ::= "." IDENT
attribute-selector  ::= "[" <ws> ns-prefix? IDENT <ws>
                          ( attr-operator <ws> ( IDENT | STRING ) <ws> attr-case-flag? <ws> )? "]"
attr-operator       ::= "=" | INCLUDEMATCH | DASHMATCH | PREFIXMATCH | SUFFIXMATCH | SUBSTRINGMATCH
attr-case-flag      ::= IDENT("i") | IDENT("s")

pseudo-class-selector   ::= ":" IDENT | ":" FUNCTION <ws> functional-args <ws> ")"
pseudo-element-selector ::= ":" ":" IDENT | ":" ":" FUNCTION <ws> functional-args <ws> ")"

functional-args     ::= selector-list                  (* :is :where :not *)
                      |  relative-sel-list              (* :has *)
                      |  An-plus-B ( S "of" S selector-list )?   (* :nth-child / :nth-last-child *)
                      |  An-plus-B                      (* :nth-of-type / :nth-last-of-type *)
                      |  IDENT ( <ws> COMMA <ws> IDENT )*  (* :lang *)
                      |  ( "ltr" | "rtl" | IDENT )       (* :dir *)

An-plus-B           ::= "even" | "odd"
                      |  INTEGER
                      |  [ "+" | "-" ]? ( INTEGER )? N-IDENT ( <ws> SIGN <ws> INTEGER )?
N-IDENT             ::= IDENT("n") | IDENT("-n") | DIMENSION(unit="n") | DIMENSION(unit="n-")
SIGN                ::= "+" | "-"

<ws> around >/+/~ is discarded; a whitespace run with no symbol between two compounds is the Descendant combinator. A whitespace-only gap followed by >/+/~ collapses to the symbol combinator (whitespace not double-counted).

8.4 <An+B> parse state machine

1-based index microsyntax. Inputs arrive as Number, Dimension(unit), Ident, Delim('+'/'-'). Goal: NthData{ a, b, ty }. States:

START --"even"-------------------> ACCEPT (a=2,  b=0)
START --"odd"--------------------> ACCEPT (a=2,  b=1)
START --INTEGER b---------------> ACCEPT (a=0,  b)            (* e.g. :nth-child(3) *)
START --IDENT "n" / "-n" -------> AFTER_N (a=±1)
START --INTEGER "n" (DIM unit=n)-> AFTER_N (a=int)            (* 2n, -3n *)
START --SIGN -------------------> EXPECT_N (carry sign)
EXPECT_N --IDENT "n" -----------> AFTER_N (a=±1)
AFTER_N --(end)-----------------> ACCEPT (b=0)                (* "2n" *)
AFTER_N --SIGN INTEGER ---------> ACCEPT (b=±int)             (* "2n + 1" / "2n-1" *)
AFTER_N --DIM unit="n-" b ------> ACCEPT (split "n-1" form)
any unexpected / trailing token-> ERROR (BadNthExpression)

Edge cases: whitespace permitted only around the inner SIGN (2n + 1 ok; 2 n is ERROR — Number then Ident is two tokens with no n-attach). n alone → a=1,b=0. -n+3 → a=-1,b=3. of S tail: after ACCEPT, optional S "of" S selector-list → promotes Nth to NthOf; a forgiving-style but actually non-forgiving inner list (invalid → BadNthExpression). ty (Child/LastChild/OfType/LastOfType) is fixed by which pseudo-class function wraps the An+B, not by the microsyntax.

8.7 Right-to-left matching (sequence diagram)

Sample tree and selector ul.nav > li a matched against candidate <a>:

ul.nav
 └─ li
     └─ span
         └─ a   <-- candidate (subject)
Checker            <a>            <span>          <li>           <ul.nav>
   |  match LocalName("a") on candidate -> ✓
   |  Combinator(Descendant): walk ancestors looking for [li]
   |----parent()------>|
   |  [span] match LocalName("li")? ✗  (descendant = unbounded -> keep climbing, backtrack point)
   |---------------- parent() -------------->|
   |  [li] match LocalName("li")? ✓
   |  Combinator(Child): parent MUST match [ul.nav] (bounded, no backtrack)
   |------------------------------ parent() ------------------->|
   |  [ul] match LocalName("ul") ✓ AND Class("nav") ✓
   |  no more components -> MATCH

Right-to-left + rightmost-first rejects fastest (most selectors fail on the subject's simple selector). Three separate u32 if a spec extension raises specificity field sizes beyond 8 bits (e.g. a new Selectors L5 with deeper id-counts per rule).
ADR-11 Ancestor-reject hashing AncestorHashes{ packed:[u32;3] } — 3x 24-bit hashes + overflow bits 4+ hashes; full 32-bit hashes; no ancestor hashing 3 hashes of id/class/local-name left of descendant/child combinator cover most reject cases; 24-bit fits + overflow bits in 3 u32 (12B). More hashes -> diminishing reject gain, more memory; none -> always walk tree. 4+ hashes if profiling shows that selectors with 4+ distinct left-of-combinator keys are common (e.g. a very class-heavy framework like Tailwind at massive scale).
ADR-12 Ancestor membership filter Counting BloomFilter, 4096 8-bit buckets, 2 hash slots/insert Bitset Bloom (no counting); 1024 buckets; HashSet of ancestors Counting buckets allow removal as the stack pops (push/pop ancestors). 4096x8b = 4KB fits L1; 2 slots balances FP rate. Invariant: zero false negatives. Bitset can't decrement; HashSet too heavy on hot path. Bitset Bloom (non-counting) if the tree is fully static (no push/pop on subtrees, rebuild entire filter per element) and halving the filter size to 2KB is worth the rebuild cost.
ADR-13 Rule bucketing SelectorMap<T> keyed by rightmost simple selector (id/class/local-name/namespace hash maps + other: Vec<T>) Linear scan of all rules; trie on full selector Bucket by rightmost simple selector -> candidate element retrieves only plausibly-matching rules. Linear scan O(rules) per element; full-selector trie complex with combinators/:is(). Linear scan when the ruleset is < 20 rules (bucket overhead exceeds linear-scan benefit) or when all rules have universal * rightmost (everything lands in other).
ADR-14 nth-index memoization NthIndexCache memoizing (parent, of-type?) -> child index Recompute index each match; cache on the node :nth-*(An+B) over many siblings is O(n^2) naive; cache makes it O(n) per parent. Caching on node mutates host tree (forbidden). Recompute each match when the subtree mutates between every query (cache invalidation cost exceeds memoization gain), or when sibling count is always small (< 20).
ADR-15 :has() complexity guard Cap relative-selector traversal: bounded recursion depth + subtree-node budget; abort -> no-match Unbounded relational matching; disallow :has() :has() is O(subtree) per candidate; cap bounds CPU on adversarial selectors/trees. Unbounded = DoS; disallowing fails L4 conformance. Unbounded if the engine runs in a fully trusted environment (no user-supplied selectors, all selectors are authored and audited) and :has() performance on deep trees is critical.
ADR-16 Forgiving-list policy :is()/:where() forgiving; :not() non-forgiving; :has() non-forgiving; top-level query* non-forgiving -> SyntaxError Forgiving everywhere; non-forgiving everywhere Matches Selectors L4 + WHATWG DOM exactly. 22. Phase 10 — Optimization: ancestor Bloom hashing, selector bucketing, caches

10.1 Objectives

  • Reject non-matching selectors before any tree walk -> AncestorHashes + counting BloomFilter (4096 buckets). Invariant: zero false negatives.
  • Bucket selectors by rightmost simple selector -> SelectorMap<T>; a query tests only candidate rules, not all rules.
  • Fast-reject filter (Bloom + bucket) as front gate to matches_selector; memoize child indices -> NthIndexCache.
  • Hit section-4 throughput targets; measured speedup vs Phase 7 baseline (no opt path) on the benchmark corpus.
  • NON-GOAL: change match semantics. Opt path MUST be result-identical to brute force (differential gate).

10.2 Detailed Implementation Steps

Files (sel-matching): bloom.rs (BloomFilter), ancestor_hashes.rs (AncestorHashes), selector_map.rs (SelectorMap<T>), nth_cache.rs (NthIndexCache); wired via MatchingContext.bloom_filter/nth_index_cache.

Component Data structure Algorithm

23. Phase 11 — :has() relational selector (Selectors Level 4)

11.1 Objectives

24. Phase 12 — Invalidation engine (minimal re-match on mutation)

12.1 Objectives

  • Build per-selector DependencySet/InvalidationSet at SelectorMap insert time -> map mutation feature (class/id/attr/state/structure) to affected nodes.

Threat Model

Attack surface = two untrusted inputs: (1) the selector string (parsed by sel-tokenizer/sel-parser); (2) the host tree walked via the Element trait. Engine is a library on the style-system hot path; an attacker who controls page CSS, JS calling query_selector*, or DOM contents must not be able to wedge, OOM, panic, or exfiltrate browsing history.

T.4 Backtracking Budget and Privacy

Backtracking: Child/NextSibling = bounded (1 step, no backtrack). Descendant/LaterSibling = unbounded → Bloom ancestor-reject + per-call step budget (~100k element-visits). Exceed → return false + match_budget_exceeded. NO false negatives — Bloom only costs the slow path on FP.

:visited privacy (T.5): :visited styling leaks user history via timing/style probing. Gate: VisitedHandlingMode at sel-query boundary. AllLinksUnvisited (query API default): :visited matches as never visited. RelevantLinkVisited / AllLinksVisitedAndUnvisited for paint-path only (results collapsed by host). matches/query_selector/_all/closest MUST run AllLinksUnvisited; engine contract: never expose a distinguishable result to the query API. Full computed-style collapse lives in project 124.

Tokenizer hardening (T.6): preprocessing before tokenization — U+0000/surrogates/codepoints > U+10FFFF → U+FFFD; \r\n/\r/\f → \n. Tokenizer<'i> on &'i str (UTF-8 guaranteed). Escapes: hex-digit bound (max 6), EOF-in-escape → U+FFFD. Unterminated string → BadString; unterminated url → BadUrl (error tokens, not panics).

Residual risk (T.7): DoS via large-but-legal trees is the host's responsibility. Side channels in host Element impl are outside the trust boundary — host contract: trait methods must be pure, total, panic-free. Spectre-class :visited leakage is mitigated at the browser-process level.

N.2 F1 — Matcher False Negative (gravest)

Should-match Selector returns false. Silently hides nodes. Root causes: (1) Bloom false negative — hash mismatch or counting-bucket underflow in add_element_unique_hashes; (2) matching-order bug — Component slice not rightmost-compound-first; (3) missing combinator backtracking for Descendant/LaterSibling; (4) nth off-by-one.

Invariant: BloomFilter has ZERO false negatives. Detection: differential oracle (Servo says match, we say no); MatchingContext trace hook (feature="trace") emitting BloomReject/SimpleResult/CombinatorMove/NthEval; CI double-run bloom=Some vs bloom=None. Bisect: reproduce (selector, element) → toggle bloom; if result flips → dump AncestorHashes.packed vs filter buckets; else → matching-order / backtracking trace. Mitigation: disable_bloom → ctx.bloom_filter=None.

N.3 F2 — Matcher False Positive

Non-matching node returned. Root cause: missing simple-selector check (attr_matches ignoring never_matches:true); Bloom false positive is benign (slow path, never wrong). Detection: WPT + oracle. Mitigation: exhaustive match on Component (no _ => arm) so a new variant fails to compile rather than silently match.

N.4 F3 — Forgiving-list silent drop

:is() / :where() drop invalid complex selectors per spec → author typo silently never matches. ParseMode: Forgiving (default, spec-conformant) | Warn (drop + push to diagnostics: Vec<ParseError>) | Strict (invalid arg → whole-list ParseError, CI gate). :not()/:has() are NON-forgiving. Forensic: diagnostics carries byte-offset span. selq parse --strict exits nonzero on any drop.

N.5 F4 — Specificity miscalculation

Wrong (a,b,c) reported. Root causes: :is()/:not()/:has() not taking most-specific arg; :where() adding > 0; 8-bit field overflow not saturating. Detection: golden table + oracle. Saturation golden fixtures: "#a #b #c"→(3,0,0), ":is(#a,.b)"→(1,0,0), ":where(#a)"→(0,0,0), 256x"#id"→(255,0,0).

N.6 F6 — Nth-index cache staleness

NthIndexCache memoizes (parent, of-type?) → child index. After structural mutation with no invalidation, :nth-child returns stale index → F1 or F2. Detection: cache-disable A/B run (cached vs uncached; diff). Recovery: host calls NthIndexCache::clear() on child-list mutation; Phase 12 emits RESTYLE_LATER_SIBLINGS which must also drop the cache slice for that parent.

N.7 F5, F7, F8, F9

F5 (:has() cap reject): O(subtree) guard aborts on budget exhaust → semi-silent no-match. Operator raises cap or rewrites selector; cap tested at boundary, cap value documented in Phase 11 §23.

F7 (stack overflow): adversarial nesting_level exhausts native stack if depth guard absent. Guard returns ParseErrorKind::UnsupportedPseudo (parse) or capped reject (match). Any crash = DoS P0; fuzz corpus retains every crasher as a regression seed.

F8 (ToCss drift): parse → ToCss → parse not stable. Fuzz target asserts parse(s).to_css() == parse(parse(s).to_css()).to_css(). Causes: escape/namespace/An+B canonicalization gaps.

F9 (oracle divergence): meta-detector for F1/F2/F4/F8. CI runs shared corpus through this engine and Servo selectors; any mismatch = fail. Every confirmed divergence → frozen regression fixture in sel-dom conformance; oracle runs pre-merge, blocking.

Operational Readiness

Framing: sel-* is an embeddable library, not a service. No process to monitor, no uptime, no on-call rotation that the engine owns. "Operational readiness" = the observability surface, SLOs, and runbooks the host gets from us so the host's own dashboard/on-call can diagnose selector-engine behavior. We expose counters + opt-in traces + rich errors; the host owns aggregation, alerting, and incident response.

25.1 Logging philosophy — the library does not log

No log/tracing/eprintln! in any core sel-* crate (no_std + alloc; no ambient logger). Errors are returned (ParseError{kind, location}, SyntaxError with byte offset); host decides severity/sink. Diagnostics are pull, not push — host reads counters or enables a trace hook; zero cost when off. panic = bug: never on untrusted input; caught only at sel-cli/test boundary. sel-cli is the one std consumer that may write to stderr.

25.3 Match-trace hooks (structured "why")

Opt-in behind feature trace. MatchingContext holds Option<&mut dyn MatchTrace>; matches_selector emits one step per Component walked right-to-left. Zero cost when None (monomorphized away). MatchTrace::step receives TraceEvent: Compound{matched}, SimpleFail{comp, reason:FailReason}, CombinatorMove{kind,to}, BloomReject{hashes}, NthEval{data,index,matched}, HasAbort{reason}. FailReason covers: LocalName, Id, Class, Attr, Namespace, PseudoClass, PseudoElement, NoAncestor, NoSibling.

Example trace for div.card > a:visited failing on <a>: enter → Compound(a,:visited→unvisited, matched=true) → CombinatorMove(Child, span#7) → SimpleFail(LocalName, want=div got=span) → leave(false). The trace identifies the exact component and element where the RTL walk dies.

25.8 Compiled-selector cache

Scalability Analysis

Symbols: N = tree nodes, S = rules in SelectorMap, C = candidates surviving bucket lookup, D = combinator depth, H = :has() nesting, A = ancestor-chain length, k = mean compound-match cost.

Tree size (N): naive O(N · S · k). SelectorMap reduces to O(N · C · k) by bucketing on rightmost simple selector (C << S for typical CSS). BloomFilter + AncestorHashes collapse unbounded O(A^D) combinator backtracking to O(1) pre-check. Right-to-left ordering: rightmost fails first → per-node cost ~k_reject (1–3 compares). NthIndexCache: :nth-child index from O(siblings) first walk to amortized O(1) thereafter.

Selector list (S): SelectorMap insert O(S); query O(1) bucket + O(C) verify. other: Vec<T> (universal-keyed rules) is the one O(S_other) term per element — warn in bench when other.len() > 64.

Combinators and :has(): bounded (>, +) = straight-line (no backtrack). Unbounded ( , ~) = Bloom-gated backtrack, practical O(D · A). :has() worst O(N^H); capped by nesting_level + per-:has() visited-node budget (Phase 11 §23) → exceeding cap = no-match, never unbounded.

Parallelism: Selector/SelectorList/SelectorMap<T> are immutable + Send + Sync — one shared read-only. Per-thread mutable state: BloomFilter, NthIndexCache, MatchingContext. query_selector_all partitions subtrees across workers → near-linear O(N/P · C · k).

Memory: BloomFilter 4 KB fixed (independent of N); AncestorHashes 12 B per Selector; SelectorMap O(S); Specificity 4 B; NthIndexCache O(distinct parents, cleared per query).

Invalidation (Phase 12 §24): DependencySet/InvalidationSet reduce re-match from O(N · C · k) to O(affected · C · k). A class used by descendant-combinator rules escalates to RESTYLE_DESCENDANTS — correct conservative bound.

Mental Models & First Principles

# Expert Insight What It Predicts Bug Class Without It Resolving §
MM1 Right-to-left = fail-fast on the hardest constraint first. The rightmost simple selector is the tightest discriminator (it targets the candidate directly); failing there costs zero tree traversal. A selector like div span will reject ≥ 95% of candidates at the span test before ever walking up to check div. Implementors match left-to-right: every div in a 10k-node tree spawns a descendant walk → O(N × descendants) instead of O(N × 1) per failing candidate. §6.3, Phase 7 §19
MM2 A Bloom filter is not an index — it is a one-sided certificate of absence. might_contain=false is a proof of no-match; might_contain=true is only a hint. The engine's correctness rests entirely on zero false negatives (never reject a real match). Bloom reject rate on miss-heavy corpora should be ≥ 90%; FP rate < 5%. Any FP merely adds a slow-path match that returns false — never wrong. Engineer treats FP as a correctness issue and lowers the bucket count to "fix" it → increases FP further, no change in correctness, AND reduces fast-reject benefit. §3.4, §6.4, Phase 10 §22
MM3 Matching order storage makes iteration direction equal to semantic direction. Component slice index 0 = rightmost compound means "iterate forward" = "evaluate right-to-left" — a single invariant eliminates all index arithmetic at match time. Any slice-walk bug that advances an index produces RTL evaluation; any off-by-one in matching maps directly to an off-by-one in semantic evaluation. Stored in source order → matcher must reverse or index with len-1-i → one pointer offset error silently matches a different selector. §3.2, §6.5, I1, ADR-05
MM4 Specificity is a saturating packed integer, not a triple comparison. Packing (a,b,c) into one u32 at parse time turns cascade ordering into a single integer compare at use time. Saturation (clamp to 255) is a spec requirement, not an implementation choice. Any :is() / :not() / :has() argument must contribute its whole packed value (max over args), not per-field max → field-wise max produces wrong ordering when argument specificities differ across fields. Per-field max on functional pseudo: :is(#a, .b.c) yields (1,2,0) instead of correct (1,0,0) (max packed = #a's (1,0,0)). §6.8, Phase 6 §18, ADR-10
MM5 Forgiving vs non-forgiving is a typed parse-mode, not a recovery heuristic. :is()/:where() drop invalid args by spec; :not()/:has()/top-level query* propagate errors. Conflating these either silently eats author errors or rejects valid :is() lists. parse_selector_list(Forgiving) on :is(.a, !!!) yields [.a]; parse_selector_list(Strict) on the same input yields ParseError. The parse-mode flag is the single branching point. Applying forgiving mode at top-level querySelector → div > returns Ok([]) instead of SyntaxError → the WHATWG DOM contract is violated, detectable only by explicit API-boundary tests. §6.7, I6, Phase 5 §17, Phase 9 §21
MM6 :visited indistinguishability is an invariant, not a feature. The API surface must collapse visited/unvisited results so that timing and result-set probing cannot distinguish. The engine computes both; the boundary discards the visited branch. querySelector(":visited") must return the same nodes regardless of actual visit history. Any branching on real visit state at the API layer is a privacy regression. Returning real visited nodes from querySelector enables any script to enumerate the user's browsing history by testing link elements against :visited — a well-known browser attack class. §6.9, I8, Phase 8 §20, Phase 9 §21
MM7 Counting Bloom (vs bitset Bloom) is required by the tree-descent use pattern. Ancestor filter must be push-on-descent / pop-on-backtrack. Counting (8-bit) buckets allow O(1) decrement; a bitset Bloom cannot decrement → requires O(ancestor-count) rebuild on every backtrack step. Push/pop symmetry is provable from the counting invariant: net insertions == current ancestor depth. Any underflow → false negative. Using a bitset Bloom and rebuilding on pop → O(depth²) per combinator-backtrack step for Descendant chains → defeats the fast-reject purpose on deep trees. §3.4, §6.4, ADR-12, Phase 10 §22
MM8 The Element trait is a query interface, not an ownership model. The engine holds &E, never E; OpaqueElement is the only identity that crosses the trust boundary. This separates match correctness from host-tree lifecycle. matches_selector is pure over the tree (I5); parallel query_selector_all is correct because there is no write to any host-owned state. Storing a host node reference inside the AST or MatchingContext → host tree mutation during match corrupts engine state → data race or use-after-free if the host drops the node. §3.3, §6.6, ADR-04, I5

Alternative Architectures (Roads Not Taken)

Alt-A: Left-to-Right Descendant-Walk Engine

             query_selector_all(root, "div span")
                        |
              LTR: find all "div" first (type-bucket)
                        |
               for each div -> walk ALL descendants
                        |
                find "span" descendants -> emit

Regime where it wins: When the leftmost selector is extremely selective (e.g. #unique-id span) and the right-hand candidates are numerous. LTR avoids building ancestor-hash infrastructure and is simpler to implement. Also wins when the tree is shallow (depth ≤ 3) and descendant fan-out is small.

Real system: Early jQuery (pre-Sizzle, v1.2), which walked descendants left-to-right. Sizzle's RTL rewrite in jQuery 1.3 was motivated by the pathological LTR cost on CSS-class selectors over large DOMs.

Why rejected: On typical CSS (compound selectors, descendant combinators, class-heavy rules) the rightmost simple selector is the most selective discriminator. LTR forces visiting O(tree) descendants per leftmost-compound match before failing, whereas RTL fails at the candidate's own compound test with zero tree traversal. The 10M match/s throughput target (§4.1) is unreachable LTR on real-world selector corpora.

Alt-B: Finite Automaton / Compiled Bytecode Matcher

  Selector string
       |
   Compile (offline)
       |
   Bytecode: [CHECK_LOCAL_NAME, WALK_ANCESTOR, CHECK_CLASS, ...]
       |
   Interpreter / JIT over host tree

Regime where it wins: Long-lived style systems that apply the same rule set millions of times (browser layout engine at 60 fps). Compiling each selector to native bytecode amortizes parse cost, enables constant folding, and can specialize Bloom lookups into register comparisons. Wins for throughput; loses for startup latency and code complexity.

Real system: Blink's SelectorChecker is hand-optimized C++ that approximates this (inlined templates, PGO), and proposals for a CSS-bytecode VM have been explored in WebKit/Blink issues (not shipped). The Stylo team at Mozilla considered AOT-compiled selectors but deferred in favor of Rust's monomorphized generics.

Why rejected: The blueprint targets an embeddable Rust library with no_std + alloc. A bytecode compiler adds a significant implementation surface (compiler pass + interpreter or JIT), non-trivial code size, and is incompatible with the no-proc-macro / no-build-script core crate policy (ADR-25). The matches_selector generic monomorphization already achieves near-zero-overhead dispatch via LLVM inlining without a custom VM.

Alt-C: Pull-Model / Lazy-Match Iterator (streaming without tree materialization)

  querySelector(".card > p") over a streaming HTML parser
        |
  Push tokens to a stateful selector automaton
        |
  Emit matched element references as they arrive
  (no full tree materialized in memory)

Regime where it wins: Streaming HTML parsing (SAX-style) where materializing the DOM is too expensive (large documents, constrained memory). A finite push automaton can match element > child in O(1) per token. Used in CSS streaming extractors for web scraping and search indexing.

Real system: lxml's iterparse in Python; CSS streaming selectors in html5-parser architectures; some XPath streaming evaluators. The cssselect library's streaming mode is a partial example.

Why rejected: Descendant (unbounded) and subsequent-sibling combinators require knowledge of arbitrary ancestor or sibling history — not O(1) per token, requiring a stack bounded by tree depth. More critically, :has(), :nth-child(), and stateful pseudo-classes require backward references into already-parsed subtrees. Full selector conformance is not achievable in a single-pass streaming model; this architecture is valid only for a strict subset. This engine targets full Selectors L4 conformance (§13 Phase 13).
