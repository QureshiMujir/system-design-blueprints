⬜ Phase 1 — CSS Syntax Level 3 tokenizer §13

Objectives
  • Implement sel-tokenizer fully per CSS Syntax Module Level 3 §4 (tokenization). Owns Token<'i>, Tokenizer<'i>, code-point classifier, all consumers, CowRcStr<'i>.
  • Total function: ANY byte string -> Token stream; never panics, never loops forever, round-trips (concatenated token reprs reproduce input modulo §3.3 normalization).
  • no_std + alloc. Zero-copy where possible (CowRcStr borrows input slice; owns only when escapes/normalization force a rewrite).
  • NON-GOAL: no grammar, no selector semantics, no @-rule/property/URL-fetch logic — pure lexical layer feeding sel-parser.
Deliverable
  • cargo test -p sel-tokenizer green; selq parse --tokens "<input>" prints one Token per line (Debug form).
  • Public API: Tokenizer::new, next, position, reset, Token, CowRcStr re-exported from crate root.
  • A tokenize(&str) -> Vec<Token> convenience + round-trip helper serialize_tokens(&[Token]) -> String.
Acceptance
  • Every byte accounted for: sum(consumed) == input.len() (debug invariant). Round-trip: serialize_tokens(tokenize(s)) re-tokenizes to equal vector for all corpus + fuzz inputs.
  • Throughput ≥ 30 MB/s single-thread; 0 heap alloc for escape-free ASCII (counting allocator). cargo +nightly fuzz run tokenize 10M execs, 0 panics/OOM/timeout.

⬜ Phase 6 — Specificity computation and selector serialization §18

Objectives
  • Compute Specificity(a,b,c) exactly per Selectors L4; once at parse time; stored as 2nd field of Selector.
  • a=#id; b=class+attr+pseudo-class; c=type+pseudo-element. Universal/combinators/:where() = 0.
  • Functional max-rule: :is(), :not(), :has() take specificity of their MOST-specific argument; :where() always 0.
  • Pack into one u32, 8 bits/field, saturating at 255 (L4 overflow note); ordering preserved by packed compare.
  • ToCss for every Component/Combinator/Selector/SelectorList -> canonical normalized form.
  • Prove invariant: parse -> ToCss -> parse is idempotent (specificity + AST equal after first reserialize).
Deliverable
  • selq specificity '<sel>' prints (a,b,c) + packed hex per complex selector in the list.
  • selq serialize '<sel>' prints canonical form; --roundtrip reparses and asserts stability, exit 0/1.
  • Library: Specificity::to_u32, Selector::specificity, ToCss impls; round-trip property test in sel-parser/tests/roundtrip.rs.

⬜ Phase 7 — Core matching engine (right-to-left with backtracking) §19

Objectives
  • Implement matches_selector<E: Element>(sel, offset, hashes, el, ctx) -> bool in sel-matching — the right-to-left SelectorChecker core.
  • Match rightmost compound first (fastest reject), then walk Combinator components leftward through host tree via Element methods.
  • Backtracking ONLY for unbounded combinators (Descendant, LaterSibling); bounded (Child, NextSibling) match exactly one step, no retry.
  • Thread MatchingContext (nth-index cache, quirks, scope, nesting_level, case-sensitivity) through all recursion; wire to sel-dom NodeRef impl Element.
  • NON-GOAL this phase: AncestorHashes/Bloom fast-reject (Phase 10), :has() (Phase 11), stateful pseudo-classes (Phase 8) — hashes param accepted, ignored.
Deliverable
  • matches_selector returning correct bool for every combinator + compound shape, wired to sel-dom; sel-query::matches delegates to it.
  • selq match '<sel>' <file.html-ish> prints matched node paths; hand-built fixture suite green; runs no_std core + std sel-dom.
Acceptance
  • ≥120-case fixture matrix (each combinator × {match, near-miss, boundary-None}): 100% pass. RTL verified: tree-access counter = 0 parent calls when rightmost fails. Bounded Child/NextSibling: no climb on mismatch.
  • cargo test -p sel-matching + hand-computed truth table parity; 0 panics under --release.

⬜ Phase 12 — Invalidation engine (minimal re-match on mutation) §24

Objectives
  • Build per-selector DependencySet/InvalidationSet at SelectorMap insert time -> map mutation feature (class/id/attr/state/structure) to affected nodes.
  • Compute RestyleHint from a mutation; re-match only RESTYLE_SELF | RESTYLE_DESCENDANTS | RESTYLE_LATER_SIBLINGS candidate set.
  • Invariant: NEVER under-invalidate (no missed match-result change); minimize over-invalidation. Correctness > tightness.
  • :has() inverts dependence: rightmost-subject mutation invalidates ANCESTORS -> ancestor-walking dependency.
  • NON-GOAL: cascade/specified-value recompute (project 124); we emit "which nodes to re-match", host re-runs matches.
Deliverable
  • process_mutation(root, el, mutation, &DependencySet) -> Vec<E> (affected nodes) exposed via sel-query; selq gains no subcommand (library API + bench harness only).
  • InvalidationMap built from a SelectorList at construction; reused across mutations.
  • Bench/test harness driving a 50k-node RcDom, applying a mutation log, comparing invalidation set vs ground-truth full re-match.
