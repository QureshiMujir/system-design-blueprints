Boundary summary:

Boundary Edge Rule
Trust model bytes + input tensors Untrusted. Importer enforces op-allowlist (ONNX-subset), size caps, no unbounded recursion; shape inference rejects ill-typed graphs before any codegen. cc-invoked C source is generated by us, never from the model.
Concurrency compile vs run Compilation single-threaded over Arena-backed IR (typed ids, no aliasing). Runtime parallelizes kernel execution (thread pool, parallel axis → tiles) + async op dispatch; Storage refcount is atomic so zero-copy NDArray views cross threads safely.
Persistence Module The compiled Module (kernels + graph + MemoryPlan) is the on-disk artifact; constant weights (GraphOp::Const(TensorData)) persist embedded; loading rehydrates without recompilation.

3.2 Per-Box Responsibilities

tc-graph — high-level Graph IR (Relay-like)

Responsibility: the functional dataflow graph of whole-tensor operators and the import surface. Owns Graph { nodes: Arena<GraphNode>, outputs, inputs }, GraphNode { op, args: Vec<NodeId>, ty }, the GraphOp enum (Input/Const/Add/Mul/MatMul/Conv2d/Relu/Reshape/Transpose/Reduce/Call), TensorType { shape, dtype }, Shape(Vec<Dim>) with Dim::Static|Dynamic, DType, the extensible op registry, and the two importer entry points (textual graph format + ONNX-subset). no_std + alloc. Input: untrusted model bytes. Output: a typed-once-inferred Graph. Key invariant: nodes are SSA-like dataflow values referenced by NodeId into the arena — no cycles, single-assignment, args reference only earlier-defined nodes; ty is None until shape inference fills it. Later phases: Phase 1 builds the IR + importers; every downstream crate consumes Graph; the final Module carries the post-pass Graph for the executor.

tc-pass — pass infrastructure + graph passes

Responsibility: PassManager + Pass trait driving an ordered sequence of analysis and transform passes. Owns shape inference, type checking, constant folding, CSE, DCE, algebraic simplification (canonicalization), layout transform, and the verifier. Depends on tc-graph + tc-ir. Input: a Graph (possibly untyped). Output: a typed, optimized, canonical Graph. Key invariant: shape inference runs to a FIXED POINT propagating TensorType forward; the verifier guarantees every reachable node is typed before fusion; transform passes preserve graph semantics (numerically equivalent dataflow). Pass ordering is fixed and documented (Phase 2 establishes infra + inference; Phase 3 the optimization set; Phase 5 layout). Later phases: tc-fuse and tc-codegen assume a fully typed, simplified graph; dynamic dims (Dim::Dynamic) survive as symbolic, resolved at runtime by tc-vm.

tc-fuse — operator fusion

Responsibility: FusionPass + FusionGroup + the dominator-based fusion analysis. Groups an injective/elementwise chain plus at most one reduce into a single kernel, eliminating intermediate tensor materialization (the dominant CPU win). Depends on tc-graph + tc-ir. Input: typed optimized Graph. Output: a set of FusionGroups, each lowered to one PrimFunc. Key invariant: a fusion group has a single dominator boundary — every internal value is consumed only within the group except the group output; fusion never crosses a non-injective multi-consumer boundary that would force recompute beyond the cost threshold. Later phases: Phase 4 implements it; Phase 6 lowers each group; the executor dispatches one kernel per group.

tc-ir — low-level tensor/loop IR (TIR-like)

Responsibility: the imperative loop-nest IR. Owns PrimFunc { params: Vec<Buffer>, body: Stmt }, Stmt (For/Store/Block/IfThenElse/Allocate), Expr (Load/Var/Const/Bin/Call), Buffer { id, shape: Vec<Expr>, dtype, scope }, IterVar { var, kind } (Data/Reduce/Thread-deferred), Scope (Global/Local/Shared-deferred), TensorExpr, and the IR builder. no_std + alloc. Input: a FusionGroup. Output: a default naive nested-loop PrimFunc realizing the group's TensorExpr. Key invariant: the TensorExpr defines WHAT is computed and is the immutable semantic anchor; the loop nest is a faithful realization; buffer indices are affine in IterVars. Later phases: Phase 6 builds it; tc-schedule transforms the loop structure over it without touching the TensorExpr; tc-codegen emits from it.

tc-schedule — the schedule space

Responsibility: Schedule { func: PrimFunc, stages: Vec<Stage> }, Stage, and the primitives split/reorder/fuse/tile/vectorize/unroll/parallel/compute_at/inline (signatures over AxisId/StageId). Depends on tc-ir. Input: a PrimFunc. Output: a Schedule (scheduled TIR) with transformed loop nests. Key invariant (compute/schedule separation, Halide model): applying ANY schedule primitive MUST NOT change the numerical result — only loop order, tiling, lane assignment, and parallelism. split(ax,factor) -> (outer,inner), fuse(a,b) -> axis, tile = split×2 + reorder. Later phases: Phase 7 (split/reorder/fuse/tile/compute_at/inline), Phase 8 (vectorize/unroll/parallel + buffer-scope interaction), Phase 12 (auto-tuner searches this space).

tc-codegen — lowering scheduled TIR to target code

Responsibility: Target { arch, features }, the CodeGen trait (fn emit(&self, sched, target) -> Kernel), the CBackend (portable C source emission), the SimdBackend (portable SIMD path), Kernel { name, source, signature: KernelSig }, and Module { kernels, graph, plan }. Depends on tc-ir + tc-schedule. Input: a Schedule + Target. Output: a Kernel per fused group, packaged into a Module. Key invariant: each Kernel exposes a stable KernelSig (data pointers + shapes + strides) so the runtime binds NDArrays positionally; vectorize maps an axis to SIMD lanes, parallel maps an axis to thread-pool tiles. Emitted C is an OUTPUT artifact compiled via the system cc. Example emitted signature:

void k_fused_add_relu(const float* a, const float* b, float* out,
                      int64_t n0, int64_t s_a0, int64_t s_b0, int64_t s_out0);

Later phases: Phase 9 builds both backends + cc integration; tc-runtime loads the Module; Phase 13 validates emitted kernels vs the oracle.

tc-runtime — the runtime (static path)

Responsibility: NDArray { storage, shape, strides, dtype, offset } (strided, zero-copy slices/reshape), Storage { ptr, bytes, device } (ref-counted), Device (Cpu/Gpu-deferred), Allocator trait (alloc/free), MemoryPlan (liveness-based buffer reuse), and GraphExecutor (topological op dispatch over a Module + NDArray bindings) plus async dispatch. Depends on tc-codegen. Input: a Module + input NDArrays (untrusted, shape-validated against the graph). Output: result NDArrays. Key invariants: NDArray views never copy unless materialization is required; Storage refcount governs lifetime; MemoryPlan reuses one buffer for two tensors only when their liveness intervals are disjoint over the executor's topological order (register-allocation-on-tensors). GraphExecutor requires STATIC shapes. Later phases: Phase 10 builds it; Phase 12 measures kernels through it; Phase 13 benchmarks GFLOP/s.

tc-vm — the bytecode VM (dynamic path)

Responsibility: VmInstruction (LoadConst/AllocTensor/InvokeKernel/If/Goto/Call/Ret), VmFunc { instrs, num_regs }, the Interpreter (register file of NDArray/objects + call stack), Closure, and the register/object model. Depends on tc-runtime. Input: a Module whose graph has control flow / dynamic dims + runtime inputs. Output: result NDArrays. Key invariant: the VM dispatches the SAME compiled Kernels as the GraphExecutor — it differs only by allocating at runtime (AllocTensor resolves Dim::Dynamic) and branching (If/Goto/Call). Numerical results must match the static path where both apply. Later phases: Phase 11 builds it; handles models the GraphExecutor's static assumption rejects.

tc-cli — the tcc binary

Responsibility: the user-facing driver. Subcommands: compile (model → Module), run (execute on inputs), dump (graph/tir/scheduled/c/module), tune (schedule search), check (vs oracle), bench. Depends on all crates. Input: CLI args + model + input files. Output: Module files, result tensors, dump text, tuning logs, pass/fail + benchmark reports. Key invariant: each subcommand is a thin orchestration over the library crates — no compiler logic lives in the binary; dump exposes every IR stage for inspection/conformance. Later phases: present from Phase 0 (smoke) and extended each phase as new capabilities land; check/bench drive Phase 13 conformance + performance gates.

8. Domain Model — Graph IR, TIR, and the Schedule

This is the semantic core: two IRs (tc-graph, tc-ir), the compute/schedule separation (Halide model), fusion (TVM dominator model), shape inference, memory planning. Every transform below preserves numerical result; only performance moves. Invariant NUM-INVARIANT: for any schedule S, eval(apply(S, primfunc)) == eval(primfunc) within tolerance (f32 rtol 1e-5, atol 1e-6) — see §13 oracle.

8.1 Graph IR (tc-graph) — the functional dataflow layer

Whole-tensor dataflow DAG. Nodes are values (SSA-like), edges are args. No mutation, no aliasing at this layer — that appears only after lowering to TIR.

Type Role Key fields
Graph the DAG nodes: Arena<GraphNode>, inputs: Vec<NodeId>, outputs: Vec<NodeId>
GraphNode one value op: GraphOp, args: Vec<NodeId>, ty: Option<TensorType>
GraphOp operator tag Input/Const/Add/Mul/MatMul/Conv2d/Relu/Reshape/Transpose/Reduce(ReduceKind)/Call(String)
TensorType value type shape: Shape, dtype: DType
Shape dims Vec<Dim>; Dim::Static(i64) | Dim::Dynamic(String)
DType scalar F32/F64/I32/I64/I8/Bool
  • NodeId = arena index (typed u32 newtype); Arena is generational, no dangling, O(1) deref. DAG is acyclic by construction — add_node only references already-inserted ids → topological order = insertion order.
  • ty starts None; shape-inference (§8.6) fills it to a fixed point.
  • Const(TensorData) carries an owned host buffer (folded constants live here).
  • Call(String) = named subfunction / external op; resolved by op registry.

8.1.1 Op-registry contract

Each GraphOp variant (and each Call name) registers an OpDef:

OpDef {
  name:        &'static str,
  n_inputs:    Arity,                 // Fixed(n) | Variadic
  infer_type:  fn(&[TensorType], &Attrs) -> Result<TensorType, TypeError>,
  lower:       fn(&[TensorExpr], &Attrs) -> TensorExpr,   // -> TIR compute
  fuse_pattern: FusePattern,          // Injective | Elementwise | Reduce | Opaque
}

Registry invariants:

  • R1 every GraphOp constructible in a Graph has an OpDef (verifier checks).
  • R2 infer_type is pure + monotone (never narrows a resolved Static to Dynamic).
  • R3 lower emits exactly one TensorExpr output; multi-output ops are modeled as a tuple-producing op + projections (deferred ops note this).
  • R4 fuse_pattern drives §8.5; Opaque = a hard fusion boundary.

FusePattern taxonomy: Elementwise (Add/Mul/Relu, shape-preserving, 1:1), Injective (Reshape/Transpose, index-remap, no reduce), Reduce (Reduce/MatMul/Conv2d, contracts an axis — a fusion group has ≤1 reduce), Opaque (Call to unknown extern).

8.1.2 Textual graph format (importer + tcc dump graph)

A .tcg round-trippable textual form (the non-ONNX frontend). EBNF:

graph     ::= "graph" ident "{" sig stmt* "}"
sig       ::= "in"  "(" binding ("," binding)* ")"
              "out" "(" ident   ("," ident)*   ")"
binding   ::= ident ":" tensortype
stmt      ::= "%" ident "=" op "(" arglist? ")" (":" tensortype)?
op        ::= ident attrs?
attrs     ::= "[" attr ("," attr)* "]"
attr      ::= ident "=" literal
arglist   ::= ("%" ident) ("," "%" ident)*
tensortype::= dtype "[" dim ("," dim)* "]"
dim       ::= int | "?" ident          (* "?n" = Dim::Dynamic("n") *)
dtype     ::= "f32"|"f64"|"i32"|"i64"|"i8"|"bool"

Example (a fused-conv corpus fixture):

graph net {
  in(x: f32[1,3,224,224], w: f32[64,3,7,7], b: f32[64])
  out(y)
  %c = Conv2d[stride=2, pad=3](x, w) : f32[1,64,112,112]
  %d = Add(%c, b)                     : f32[1,64,112,112]
  %y = Relu(%d)                       : f32[1,64,112,112]
}

Types after : are optional in source; the importer leaves them None and shape-inference fills them. On re-dump they are always printed (canonical form).

8.2 TIR (tc-ir) — the imperative loop-nest layer

After fusion, each FusionGroup lowers to one PrimFunc: an imperative loop nest over Buffers. This is where loop order, indexing, and storage become explicit and schedulable.

8.2.1 TIR grammar (EBNF)

primfunc  ::= "primfn" "(" buffer ("," buffer)* ")" "{" stmt "}"
stmt      ::= for | store | block | ifte | alloc
for       ::= "for" itervar "in" "[" expr "," expr ")" "{" stmt "}"   (* min, extent *)
store     ::= buffer_id "[" expr "]" "=" expr ";"
block     ::= "{" stmt* "}"
ifte      ::= "if" "(" expr ")" stmt ("else" stmt)?
alloc     ::= "alloc" buffer_id ";"
expr      ::= load | var | const | bin | call
load      ::= buffer_id "[" expr "]"
var       ::= var_id
const     ::= float
bin       ::= expr binop expr
binop     ::= "+"|"-"|"*"|"/"|"%"|"<"|"=="|"max"|"min"
call      ::= intrin "(" (expr ("," expr)*)? ")"        (* exp, sqrt, fma, ... *)
buffer    ::= buffer_id ":" dtype "<" expr ("," expr)* ">" scope
itervar   ::= var_id ":" iterkind                       (* Data | Reduce *)
scope     ::= "global"|"local"|"shared"                 (* shared = GPU-deferred *)

Maps 1:1 to the LOCKED Rust enums: Stmt::{For,Store,Block,IfThenElse,Allocate}, Expr::{Load,Var,Const,Bin,Call}, Buffer{id,shape,dtype,scope}, IterVar{var,kind} (IterKind::{Data,Reduce}; Thread deferred).

TIR invariants:

  • T1 every Buffer referenced by Load/Store is a param or appears in an enclosing Allocate.
  • T2 a Store index expression is affine in enclosing IterVars (required for schedule legality + bounds proofs); non-affine → Opaque, not scheduled.
  • T3 a Reduce IterVar may only index Loads on the RHS, never the store axis of its own output (else the reduction is ill-formed).
  • T4 Scope::{Shared} and IterKind::Thread are reserved (GPU-deferred); the CPU codegen rejects them.

8.2.2 TensorExpr and default-PrimFunc lowering

TensorExpr = the declarative compute (Halide "what"): an output shape + a pure lambda over output indices. Lowering = wrap each output axis in a For (Data kind) and each contracted axis in a For (Reduce kind), innermost, emitting the body as a Store.

TensorExpr {
  name:   String,
  shape:  Vec<Expr>,                 // output extents
  axes:   Vec<IterVar>,              // Data axes (output) + Reduce axes
  body:   fn(indices) -> Expr,       // pure; reads input Buffers via Load
}

lower_default(te) -> PrimFunc rule: nest Data axes outer→inner in declared order, then Reduce axes, init the store cell before the reduce loop, accumulate inside. Result is the naive nested-loop baseline; all performance comes from the schedule (§8.3).

8.3 Compute/schedule separation — worked matmul

Compute (C[i,j] = Σ_k A[i,k]*B[k,j], M=N=K=1024, f32) as TensorExpr:

te_matmul = TensorExpr {
  name: "matmul",
  shape: [M, N],
  axes:  [i:Data, j:Data, k:Reduce],
  body:  |i,j| reduce(k, A[i,k] * B[k,j], init=0.0),
}

Naive PrimFunc from lower_default — matmul(A: f32<M,K> global, B: f32<K,N> global, C: f32<M,N> global): a 3-deep loop nest over i ∈ [0,M), j ∈ [0,N), k ∈ [0,K); each output C[i,j] is zero-initialized then accumulated as the reduction Σ_k A[i,k]·B[k,j]. Row-major index algebra: C[i*N+j], A[i*K+k], B[k*N+j]. No tiling, vectorization, or parallelism yet.

Schedule — identical numerics, optimized loops; built from Schedule::new(primfn):

# Directive Effect
1 split i, 64 → (i_o, i_i) tile rows
2 split j, 64 → (j_o, j_i) tile cols
3 split k, 256 → (k_o, k_i) tile contraction
4 reorder [i_o, j_o, k_o, i_i, k_i, j_i] cache-blocked iteration order
5 vectorize j_i innermost → 8× f32 AVX2 SIMD lanes
6 unroll k_i unroll the reduce tail
7 parallel i_o thread-pool over row tiles

Transformed loop nest (schedule applied → scheduled TIR): a parallel outer loop over i_o ∈ [0,M/64), nested j_o ∈ [0,N/64) and k_o ∈ [0,K/256) tiles, then i_i ∈ [0,64), an unrolled k_i ∈ [0,256), and a vectorized j_i ∈ [0,64) mapped to 8-lane SIMD FMA/store. The accumulation C[(i_o·64+i_i)·N + j_o·64+j_i] += A[(i_o·64+i_i)·K + k_o·256+k_i] · B[(k_o·256+k_i)·N + j_o·64+j_i] reuses the naive nest's index algebra.

Index algebra unchanged → NUM-INVARIANT holds; only iteration order + vector/parallel mapping differ. Targets: naive ~1–2 GFLOP/s; scheduled ≥30 GFLOP/s single-thread avx2, ≥60% of OpenBLAS sgemm multi-thread (§13 bench).

Schedule legality (checked by tc-schedule before apply):

  • L1 split(ax,f) requires extent(ax) % f == 0 OR emits a guarded tail loop (IfThenElse); never silently truncates.
  • L2 reorder must keep every Reduce axis inside the Data axes that index its output cell (else partial sums leak across cells).
  • L3 vectorize(ax) requires ax is the innermost axis and the Store index is unit-stride in ax; otherwise Err(IllegalSchedule::NotInnermost).
  • L4 compute_at(stage,ax)/inline must not move a producer below a consumer that reads it (dependency-preserving).

8.4 (Schedule primitives summary)

Primitive Signature Effect Legality
split split(ax,f)->(o,i) one loop → two L1
reorder reorder(&[ax]) permute loop order L2
fuse fuse(a,b)->ax two loops → one adjacency, same body
tile tile(ax,ay,fx,fy) split+split+reorder L1×2
vectorize vectorize(ax) axis → SIMD lanes L3
unroll unroll(ax) replicate body static extent
parallel parallel(ax) axis → thread pool no loop-carried dep
compute_at compute_at(st,ax) move producer inward L4
inline inline(st) fold producer into consumer expr producer used once-affine

8.5 Operator fusion via dominator analysis

Goal: eliminate intermediate materialization. A FusionGroup is a connected subgraph fusable into one PrimFunc. Rule: an Elementwise/Injective chain plus at most one Reduce at the group head can fuse iff each member is dominated by the group's exit in the reverse dataflow (every path to outputs passes through it → safe to inline, no external reader of the intermediate).

Algorithm (FusionPass):

  1. build dominator tree over the dataflow DAG (Lengauer-Tarjan, O(E·α)).
  2. seed groups at Reduce/Opaque boundaries.
  3. greedily absorb a node n into its dominated Elementwise/Injective successors while fuse_pattern compatible and group has ≤1 reduce.
  4. emit each FusionGroup → composed TensorExpr → lower_default → PrimFunc.

Worked subgraph — Conv2d -> Add(bias) -> Relu:

BEFORE (3 GraphNodes, 2 intermediate tensors materialized):
  %c = Conv2d(x,w)   -> f32[1,64,112,112]   (~3.2 MB)
  %d = Add(%c,b)     -> f32[1,64,112,112]   (~3.2 MB)   <- materialized
  %y = Relu(%d)      -> f32[1,64,112,112]               <- materialized

dominators: %y dom-by %d dom-by %c; %d,%c have no external reader
-> FusionGroup{ reduce: Conv2d, elemwise: [Add, Relu] }

AFTER fusion (1 PrimFunc, 0 intermediate tensors): a single loop nest over output coordinates (oc, oh, ow) with an inner reduction over (ic, kh, kw) accumulating acc += x[..]·w[..] (the conv reduce); the bias add (acc + b[oc]) and ReLU (max(acc, 0)) are fused into the same nest, before the lone store to y[oc,oh,ow].

Win: 2 fewer 3.2 MB writes + reads + 2 fewer kernel launches; the bias/relu ride the conv's already-hot accumulator. Fusion is the dominant CPU speedup. Boundary: a second consumer of %c (a residual add) → %c is not dominated by %y → fusion stops, %c materializes.

8.6 Shape inference to a fixed point

infer_shapes (a tc-pass analysis) propagates TensorType forward in topological order, calling each OpDef::infer_type. Iterate until no ty changes (a fixed point); a pure-monotone lattice (R2) → terminates in one pass for a DAG, ≤2 for graphs with Reshape back-constraints.

Worked example (.tcg fixture above, conv branch):

iter 0:  x:f32[1,3,224,224]✓  w:f32[64,3,7,7]✓  b:f32[64]✓  c,d,y: None
iter 1:  c = Conv2d.infer(x,w; stride=2,pad=3)
            -> [1,64, (224+2*3-7)/2+1=112, 112] = f32[1,64,112,112] ✓
         d = Add.infer(c,b)  -> broadcast b[64]->[1,64,1,1] -> f32[1,64,112,112] ✓
         y = Relu.infer(d)   -> f32[1,64,112,112] ✓
iter 2:  no change -> FIXED POINT. verifier: every node.ty == Some(_).

Dynamic dims: Dim::Dynamic("n") stays symbolic; arithmetic keeps it (n*2, n+pad) and the node is marked dynamic → routed to the VM (§8.7g), not the static GraphExecutor.

8.7 MemoryPlan — liveness-based buffer reuse

After fusion + lowering, the GraphExecutor runs kernels in topological order. MemoryPlan computes per-tensor live ranges [first_def, last_use] and reuses storage for non-overlapping tensors — register allocation on tensors.

Worked example (5 intermediates, topo order t1..t5):

tensor  bytes   live range        assigned slot
t1      4 MB    [0, 2]            S0
t2      4 MB    [1, 3]            S1
t3      2 MB    [2, 2]            S2   (dies at 2)
t4      2 MB    [3, 4]            S2   (reuses S0? no: S0 live till 2; reuse S2: free at 2) -> S2
t5      4 MB    [4, 4]            S0   (S0 free after t1 dies at 2) -> S0
peak: max simultaneously-live = slots {S0,S1,S2} at step 2 = 4+4+2 = 10 MB
naive (no reuse) = 16 MB ; saving 37.5%

Algorithm: sort by first_def; greedy interval coloring with a free-list keyed by byte-size class; output MemoryPlan{ tensor->StorageSlot }. Aliased tensors (zero-copy Reshape/Transpose views, §10 NDArray) share a slot by definition and are excluded from coloring (their storage = producer's).

8.8 Malformed inputs and edge cases — modeled response

# Condition Where caught Modeled response
a Shape mismatch at import (Add(f32[4], f32[5]) non-broadcastable) importer / infer_type Err(ShapeError{node,lhs,rhs}); abort compile, no partial module
b Untypable node (Call("unknown"), no OpDef) shape-infer fixed point + verifier Err(TypeError::Unresolved(node)); verifier fails (R1)
c Cyclic graph (importer fed a back-edge) Graph build / topo sort rejected at construction (arena forbids fwd-ref) or Err(CyclicGraph) from topo
d Illegal schedule: vectorize non-innermost / non-unit-stride tc-schedule apply, L3 Err(IllegalSchedule::NotInnermost); schedule unchanged, NUM-INVARIANT safe
e Dynamic shape on static path (Dim::Dynamic) executor selection route to tc-vm Interpreter; GraphExecutor::compile returns Err(DynamicShape)
f Divide-by-zero in const fold (Div(c, Const 0.0)) const_fold pass f32 → emit IEEE inf/nan (no panic, matches oracle); int → Err(ConstFold::DivByZero), fold skipped, op kept
g split factor not dividing extent tc-schedule, L1 emit guarded tail loop (IfThenElse); never silent truncation
h Reduce axis indexing its own store cell TIR verifier, T3 Err(IllFormedReduce)

All errors are typed (thiserror), carry the offending NodeId/AxisId, and never produce a numerically-wrong module — fail closed.
