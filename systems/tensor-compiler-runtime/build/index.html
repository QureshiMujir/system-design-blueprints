⬜ Phase 0 — Workspace, end-to-end "add" smoke through the whole pipeline §12

Objectives
  • Cargo workspace tensor-compiler/ + 9 member crates (tc-graph, tc-ir, tc-pass, tc-fuse, tc-schedule, tc-codegen, tc-runtime, tc-vm, tc-cli) wired with exact dep DAG; cargo build --workspace green.
  • Define type shells: Graph/GraphNode/GraphOp, PrimFunc/Stmt/Expr/Buffer, NDArray/Storage, stubbed PassManager / CodeGen / GraphExecutor.

  • Reference oracle harness scaffold (oracle::add) + tolerance comparator (assert_close, f32 rtol 1e-5 / atol 1e-6).
  • tcc binary skeleton with subcommands parsed (compile/run/dump/tune/check/bench); only the add smoke wired end-to-end.
  • CI (fmt → clippy -D warnings → build → test), Makefile, Dockerfile, all reproducible.

Pitfalls
  • C↔Rust ABI drift: KernelSig ndim/dtype must match emitted C signature exactly; mismatch = silent UB/segfault. Root cause: hand-kept-in-sync sig. Debug: assert KernelSig vs parsed C prototype in test; run under ASan.
  • cc not on PATH / wrong compiler: smoke hangs or errors opaquely. Resolve CC env → fallback cc; surface the full failing command + stderr.

⬜ Phase 1 — Graph IR, op registry, type/shape system, and importers §13

Objectives
  • Build tc-graph core: Graph/GraphNode/GraphOp, TensorType/Shape/Dim/DType, arena-backed NodeId.
  • Extensible op registry: each op declares arity, attrs, dtype constraints, shape-infer fn, reference-eval fn (used later as oracle hook).
  • Two importers: (a) textual graph format parser (round-trippable), (b) ONNX-subset importer mapping ONNX NodeProto → GraphOp.
  • Produce a typed-or-untyped Graph (types Option<TensorType>; full inference is Phase 2) that tcc dump --graph renders.
  • Invariant: import is total over the documented subset; unknown ops → typed error, never panic.
Deliverable

tcc dump --graph <model> parses a textual .tcg file OR a .onnx (subset) into a Graph and prints canonical textual form. tc-graph builds no_std+alloc; importers gated behind std feature for file IO.

Acceptance
  • Round-trip: parse(print(g)) == g (structural eq) for all textual fixtures; byte-identical print after one normalize pass.
  • ONNX import of a ≥6-node model (matmul+add+relu) yields the expected node count, op kinds, edges, and Const initializer bytes.
  • Unknown ONNX op or arity mismatch → GraphError with op name + node index; zero panics under fuzzed inputs (Phase 13 ties in).
  • cargo build -p tc-graph --no-default-features succeeds (no_std).

Pitfalls
  • ONNX initializer vs input overlap: a name in both initializer and input is a Const, not an Input — dedupe by name or you get a dangling free var. Debug: dump input/const name sets.
  • Endianness/dtype width decoding raw TensorProto.raw_data: assume little-endian, validate bytes.len() == shape_prod * dtype.bytes(); mismatch ⇒ silent garbage. Assert it at import.

⬜ Phase 2 — Pass infrastructure, shape inference, and type checking §14

Objectives
  • PassManager: ordered pass pipeline; analysis-result cache keyed by AnalysisId; dependency-driven invalidation on graph mutation.
  • Pass trait: distinguish AnalysisPass (read-only, cacheable) vs TransformPass (mutates, declares invalidations).
  • ShapeInference: worklist fixed-point over dataflow; per-GraphOp type relations; Dim::Static arithmetic + Dim::Dynamic symbolic unification.
  • TypeCheck: arity, dtype-equality / promotion rules, op-specific constraints (e.g. MatMul inner-dim match, Conv2d rank=4).
  • Verifier: post-condition forall n: n.ty.is_some(); structural checks (acyclicity, arg-count, valid NodeId).
  • Determinism: pass order + iteration order fixed; identical input Graph -> identical typed Graph and identical errors.
Deliverable

tc-pass exporting PassManager with a default pipeline [ShapeInference, TypeCheck, Verifier]. tcc dump graph --typed model.tg prints every node with its inferred TensorType. A typed Graph round-trips; any ill-typed input yields a single PassError with NodeId + ErrKind. Library + fixtures compile under the workspace; no codegen/runtime dependency.

Acceptance
  • Every node in a valid corpus Graph has ty = Some(_) after PassManager::run; verifier passes.
  • Fixed-point reached in ≤ 2·|nodes| worklist iterations on all valid fixtures; non-convergence is an explicit error, never a hang.
  • Each malformed fixture produces exactly one PassError with the correct NodeId and ErrKind variant (golden-matched).
  • Analysis cache hit on a re-run with no mutation: 0 re-analysis (assert via instrumented counter).
  • Shape inference on a 200-node graph completes in < 5 ms; deterministic across 100 runs (identical output bytes).

Pitfalls
  • Non-monotone update -> oscillation: re-deriving a node's type to a different shape each pass loops forever. Root cause: missing fixpoint monotonicity (type must only refine, e.g. Dynamic->Static, never flip). Debug: log per-node type history; assert refinement lattice ordering.
  • Stale cache after mutation: a transform forgets invalidates(), downstream reads dead TensorType. Symptom: typecheck passes on wrong shapes. Debug: cache entries carry a Graph-revision counter; mismatch = bug.
  • Broadcast vs dynamic-dim conflation: treating Dim::Dynamic as broadcastable 1. Root cause: ambiguous lattice. Decision: Dynamic unifies only with equal-named Dynamic or any Static (assume-compatible), never silently broadcasts.
  • Topo order assumed but graph has multi-output / shared subexprs: visiting a node before all args typed -> spurious Unresolved. Fix: worklist re-enqueues; never single-pass.
  • Reshape with -1 inferred dim: forgetting product back-solve; emit ShapeMismatch only after attempting -1 resolution against known total.
  • Error masking: first error aborts, hiding others; but multiple errors are non-deterministic to order. Decision: report the topologically-first offending node only — deterministic, single error.

⬜ Phase 3 — Graph optimization passes §15

Objectives
  • CF: evaluate fully-const subgraphs at compile time → GraphOp::Const(TensorData); reuse the Phase-10 reference op kernels (CPU eval) so folded value == runtime value.
  • CSE: hash-cons structurally-identical GraphNodes (same op + same arg NodeIds + same TensorType); collapse duplicates to one canonical NodeId.
  • DCE: prune nodes not reachable from Graph.outputs; remove dangling const/intermediate nodes after CF/CSE.
  • Simplify: pattern-rewrite canonicalization — x+0, 0+x, x*1, x*0, mul/add of consts, Reshape(Reshape(x)), Transpose(Transpose(x))=id, Relu(Relu(x)), double-negation.
  • Invariant (LOCKED): output Graph numerically identical to input on the oracle (f32 rtol 1e-5, atol 1e-6) for all sampled inputs.
Deliverable

tc-pass exposes optimize(g:&mut Graph) running CF/CSE/DCE/Simplify to fixpoint. tcc dump graph --opt model.txt prints the optimized graph; tcc check confirms optimized vs unoptimized outputs match the oracle. Per-pass node-count delta logged.

Acceptance
  • All four passes implemented, each impl Pass, registered in PassManager; output re-verifies (Phase-2 verifier: every node typed, args arity/dtype valid).
  • Numerics: optimized Graph matches unoptimized within rtol 1e-5 / atol 1e-6 on ≥50 random input draws across fixture corpus.
  • CF: a graph of Add(Const,Const)→single Const; CSE: N identical subtrees → node count drops to 1 copy + reuse; DCE: unreachable nodes count = 0 post-pass; Simplify: x+0 etc. collapsed (asserted by node match).
  • Fixpoint reached ≤8 iterations on corpus; each pass idempotent (run twice = run once, verified by node-count stability).

Pitfalls
  • CF float reproducibility: compile-time eval must use the SAME f32 rounding/accumulation order as the runtime kernel, else folded const drifts > tol. Root cause: FMA/reassoc; fix: share eval_const math with Phase-10 ref kernels; debug via per-node oracle diff.
  • CSE merging non-equal consts: 0.0/-0.0 hash equal but NaN!=NaN; bit-canonicalize payload before hashing. Symptom: silent wrong-value reuse; debug by dumping NodeKey.
  • DCE eliding aliased outputs: if an output NodeId was remapped by CSE but outputs not updated, DCE prunes the live result. Fix: apply remap to outputs/inputs before sweep.
  • Simplify infinite loop: non-terminating rewrite (e.g. a+b↔b+a both firing). Root cause: no canonical ordering; fix: commutative ops canonicalize arg order by NodeId, rules only reduce a monotone cost metric.
  • Stale TensorType after rewrite: new const/reshape node missing inferred type → verifier fail. Fix: re-run shape inference (Phase 2) or carry type from replaced node.
  • Arena dangling ids: dropping nodes without compaction leaves stale NodeId in args. Fix: single compaction map applied atomically.

⬜ Phase 4 — Operator fusion §16

Objectives
  • Dominator-based fusion analysis → partition Graph nodes into FusionGroups; each group lowers to one PrimFunc.
  • Fusion rules by op pattern-kind: Opaque < Injective < Reduce < Complex (TVM OpPatternKind model) — encode legal merges.
  • Group injective/elementwise chains + at most one Reduce (epilogue/prologue) per group; eliminate materialized intermediates.
  • Produce a materialization-count metric (#intermediate Buffers before vs after) proving reduction.
  • Invariant: fusion changes performance only, never numerics (compute/schedule separation upstream).
Deliverable

FusionPass integrated into PassManager; tcc dump --fused <model> prints the group partition + per-group PrimFunc; tcc dump --tir shows fused loop nests with no intermediate Allocate. conv→bias_add→relu fuses to a single FusionGroup/PrimFunc.

Acceptance
  • conv→bias→relu chain → exactly 1 FusionGroup (master = Conv2d); --dump fused confirms 3 members.
  • Materialization count: a 5-op elementwise chain a+b*c-relu(d)/e → intermediates drop from 4 → 0 (only group output materialized).
  • Numerics: fused PrimFunc output matches unfused per-op execution within f32 rtol 1e-5, atol 1e-6.
  • Idempotent: re-running FusionPass on a fused graph is a no-op (no group splitting/merging).
  • No Opaque op ever absorbed into a group; group count = #opaque-boundaries + #fused-regions.

⬜ Phase 5 — Layout / data-format transform and canonicalization §17

Objectives
  • Per-op data-format selection (NCHW ⟷ NHWC for conv/pool; row-major contiguous for matmul/elementwise) driven by op preference + cost.
  • Insert LayoutConvert nodes only at format boundaries (where producer-format ≠ consumer-required-format) — never per-op.
  • Cost-aware placement: minimize total convert bytes via a forward propagation + backward reconciliation, not greedy local insertion.
  • Canonicalize to contiguous/default layouts at graph outputs + at ops whose backend kernel mandates a fixed format.
  • Emit a convert-count + convert-byte metric; numerics invariant under layout (oracle re-check, rtol 1e-5).
Deliverable

Layout-optimized Graph with (a) every node carrying a resolved Layout, (b) minimal LayoutConvert insertions, (c) contiguous-canonical outputs; tcc dump --graph --show-layout model prints per-node layout + convert count; numerics unchanged vs Phase 4 graph.

Acceptance
  • Convert count on the conv-stack fixture ≤ theoretical-minimum + 0; on the mixed fixture ≤ min+1 (documented).
  • Inverse-convert pairs: 0 survive folding (asserted).
  • Numerics: layout graph output == pre-layout output, rtol 1e-5 / atol 1e-6.
  • LayoutConvert inserted only on format-mismatch edges (verifier: no convert where from==to).
  • Pass idempotent: LayoutPass(LayoutPass(g)) == LayoutPass(g) (convert count stable).
  • Runtime ≤ 5 ms on a 200-node graph.

  • Greedy local insertion explodes converts: inserting per-edge without fan-out dedup yields N converts for N consumers → root cause: missing shared-convert pass. Debug: dump convert-byte metric, diff vs theoretical min.

⬜ Phase 6 — Tensor/loop IR (TIR) and lowering §18

Objectives
  • Land tc-ir in full: PrimFunc/Stmt/Expr/Buffer/IterVar, typed-id arena, IrBuilder, verify().
  • Lower a fused GraphOp group → TensorExpr (per-element index→value λ) → default PrimFunc (row-major nested For over output axes, single Store).
  • Reduce ops (Reduce(kind), MatMul, Conv2d) lower with an inner reduction loop (IterKind::Reduce) + init Store.
  • Verifier rejects: use-before-def (VarId/BufferId), out-of-range buffer index (static), dtype mismatch across Bin/Store/Load, malformed loop bounds.
  • Invariant: lowering is schedule-free; result is numerically identical to oracle within f32 rtol 1e-5 / atol 1e-6.
Deliverable

tc-ir compiles. tcc dump tir <model> prints a PrimFunc for each fused group. lower_group produces a default PrimFunc for every group emitted by Phase 4/5; piped through Phase 0's hand-path codegen+runtime it executes and matches the oracle. verify() runs on every lowered func before codegen.

Acceptance

  • Numerical: lowered+compiled output == oracle within f32 rtol 1e-5 / atol 1e-6 across the lowering corpus (≥20 groups incl. matmul, conv, fused elementwise+reduce).
  • Fused elementwise chain allocates 0 intermediate buffers (assert buffer count == #group-outputs + #group-inputs).
  • dump tir output is deterministic (stable id numbering, byte-identical across runs).

⬜ Phase 7 — Schedule primitives I (loop structure) §19

Objectives
  • Implement Schedule { func: PrimFunc, stages: Vec<Stage> } + Stage { axes: Vec<IterVar> } over a lowered PrimFunc; AxisId/StageId typed handles into a ScheduleState.

  • Invariant: every primitive is a semantics-preserving loop transform; reduce axes keep accumulation order or stay marked IterKind::Reduce (no result change for associative-exact / within-tolerance otherwise).

Deliverable

tc-schedule crate: Schedule::new(func), all six primitives, Schedule::materialize() -> PrimFunc. tcc dump scheduled <model> prints the transformed loop nest. Round-trips a matmul PrimFunc through tile(i,j,32,32) + reorder + compute_at and re-emits a valid PrimFunc.

Acceptance

  • materialize is idempotent on an empty schedule (no primitive ⇒ byte-identical PrimFunc).
  • tile+reorder+compute_at on conv2d produces a loop nest with ≤ original total iterations and identical result.

⬜ Phase 8 — Schedule primitives II (performance: vectorize, unroll, parallel) §20

Objectives
  • vectorize(ax) → map axis to SIMD lanes; legality: axis innermost + stride-1 (contiguous) in every Buffer it indexes.
  • unroll(ax) → full (extent ≤ unroll_max, default 64) or partial (factor) loop-body replication; reduces branch/IV overhead, exposes ILP.
  • parallel(ax) → map an outer axis to the runtime thread pool over tiles; data-parallel, no cross-iteration dependence.
  • Define codegen vectorization contract: what SimdBackend must emit/honor for a vectorized axis (lane width, tail/remainder, alignment, gather rejection).
