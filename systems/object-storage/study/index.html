32. Mental Models & First Principles

MM1 — A manifest is a level of indirection that turns mutation into allocation. Predicts CopyObject is free (§13.2) and GC must be reference-counted (I10). Bug class without it: an engineer "optimizing" by writing bytes in place, breaking P2. Applies in §8.5, §16.

MM2 — Durability is a probability, not a boolean. Predicts you must compute AFR×MTTR math (§33), not just count replicas. Bug class without it: assuming RF=3 alone is "safe" without rack diversity (I6). Applies in §4, §33.

MM3 — Consistency is a per-read-path property, not a whole-system property. Predicts intra-region and cross-region reads can carry different guarantees simultaneously (I14). Bug class without it: a single doc comment claiming "the system is eventually consistent" that is wrong for half the read paths. Applies in §18, §20.

MM4 — The gateway is a stateless proxy; the metadata service is the truth. Predicts gateway crashes are free, metadata crashes are expensive (§3, P4, P14). Bug class without it: caching placement decisions in the gateway (I13 violation). Applies in §3, §14.

MM5 — Erasure coding trades repair bandwidth for storage cost. Predicts an EC cluster needs more provisioned repair bandwidth than a replicated cluster at the same node-failure rate (Rashmi et al. 2014). Bug class without it: sizing an EC cluster's network the same as a replicated one. Applies in §15, §33.

MM6 — A background worker that isn't idempotent is a data-loss bug waiting for a restart. Predicts every worker (lifecycle, GC, scrub, replication) needs a persisted cursor (I11). Bug class without it: a worker that reprocesses or skips work on crash-restart. Applies in §19, §25.

MM7 — Every state machine needs an explicit, recoverable state for every crash point. Predicts MpuState::Completing/Aborting exist precisely because a crash there is otherwise unrecoverable (§16.2). Bug class without it: designing only the happy-path states. Applies in §16, §25.

MM8 — The wire protocol is a contract with people you will never meet. Predicts you cannot silently change Sigv4 canonicalization or XML response shapes once clients exist (ADR-22, §27). Bug class without it: "cleaning up" the API surface post-launch and breaking every existing SDK integration. Applies in §17, §27.

Reference Implementations

  • MinIO (cmd/erasure-coding/, cmd/xl-storage.go). Lesson: the xl.meta layout and bitrot detection. Pitfall: do not copy the multipart-finalize race. Applied in §15, §16.
  • OpenStack Swift (swift/proxy/, swift/obj/server.py, swift/common/ring/). Lesson: ring placement, the proxy/object/account split, the auditor/replicator/reclaimer triad. Pitfall: ring-rebalance storms. Applied in §14, §23.
  • Ceph RADOS Gateway (src/rgw/). Lesson: bucket-index sharding, the lifecycle worker. Pitfall: bucket-index hot-sharding under skewed key prefixes. Applied in §13, §19.
  • Apache Ozone (hadoop-ozone/). Lesson: a separate metadata service (OM) and block service (SCM) mirroring our metadata/blob split. Pitfall: OM–SCM consistency lag. Applied in §8, §14.
  • Garage (deuxfleurs, Rust). Lesson: a minimal Rust S3-compatible store with CRDT-based metadata. Pitfall: eventual-consistency-only metadata limits strong-read use cases. Applied in §18 (contrast for our Raft-strong choice), §32.

Compaction
the LSM-tree background process merging SSTable segments (§8.4).
Compliance mode
the irreversible object-lock retention mode (§21.2, I8).

If-Match/If-None-Match/etc., RFC 7232 semantics (§22.1).

the obj-conformance fixture-driven test runner (§10.2, §28).
Content addressing
storing a fragment under a hash of its bytes (§8.3, ADR-03).
Continuation token
the opaque cursor for paginated listings (§13.2).
Degraded read
a GET served despite a missing replica/shard (§14.2, §15.5).
Delete marker
a version representing a logical delete on a versioned bucket (§18.2).
Durability
the per-bucket policy selecting replication, erasure coding, or tiering (§11.5, §6 P7).
Erasure coding (EC)
Reed-Solomon-based durability splitting data into k data + m parity shards (§15).
ETag
an opaque content-identity token, MD5-derived for single/multipart objects (§11.2).
Fragment
a content-addressed unit of stored bytes (§8.3, §11.4).
Fsck
the operator tool cross-referencing metadata against blob-node inventory (§23.2).
Gateway
the stateless S3 REST front-end (§3, §6 P4).
Hedge (hedged read)
issuing k+1 reads and using the first k, trading bandwidth for tail latency (§6 P13).
Legal hold
an independent hold preventing deletion regardless of retention (§21.2).
Lifecycle rule
a declarative (filter, action) pair evaluated daily (§11.9, §19).
LSM-tree
Log-Structured Merge-Tree, the metadata index's on-disk structure (§8.4).
Manifest
the ordered list of fragment/shard references composing an object version (§11.4).
Metadata service
the Raft-replicated authoritative index and placement decision maker (§3, §11.10).
Multipart upload (MPU)
the chunked-upload protocol for large objects (§16).
Object
one version of a (bucket, key) pair's data and headers (§11.6).
Object-lock
WORM retention enforced at the metadata layer (§21).
Orphan fragment
a fragment on disk referenced by no live manifest (§23.2, FM-11).
Placement plan
the concrete set of storage nodes holding an object's fragments/shards (§11.5).
Presigned URL
a Sigv4-signed URL granting temporary scoped access (§17.2).
Quorum
the minimum number of replica/shard acknowledgments required to commit a write (§14.2, §15.2).
RAID-adjacent term — rack diversity
placement spreading replicas/shards across failure domains (I6).
Rebalancer
the worker evening fragment distribution across blob nodes (§23.2).
Replication (cross-region)
asynchronous mirroring of writes to a remote bucket (§20).
RF (replication factor)
the count of full copies stored under Durability::Replication (§11.5).
Scrubber
the background worker verifying fragment/shard checksums on a cadence (§23.2).
Shard
one data or parity fragment of an erasure-coded object (§8.3, §15.2).
Sigv4
AWS Signature Version 4, the request-signing scheme (§17).
SSTable
an immutable, sorted, on-disk segment of the LSM-tree (§8.4).
Streaming chunked body
an aws-chunked request body verified per-chunk (§17.2).
Tiering
moving an object between hot and cold durability/cost classes (§11.9, §19.3).
Version ladder
the ordered list of versions for a (bucket, key) pair (§18.2).
VersionId
the monotonic 128-bit identifier distinguishing object versions (§11.1, I2).
WAL (Write-Ahead Log)
the durability primitive metadata mutations are logged to before being applied (§14.2, I3).
WORM
