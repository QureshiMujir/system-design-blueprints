Decisions (§9) · 24 ADRs

01

Implementation language

Chosen

Rust 2021, MSRV 1.78

Rejected

C/C++; Go; Python

When the rejected choice is right

C/C++ wins when you need to call into a legacy BLAS/MKL DSP library with no Rust bindings, or when the entire team is expert C++ and has zero Rust experience — onboarding cost exceeds safety benefit at small team sizes. Python wins for a pure-notebook research prototype run once on a laptop.

Why: Zero-cost SIMD on search hot path; explicit cache-aware layout under ownership; memory-safe concurrent multi-reader search; deterministic builds. C/C++ unsafe on concurrent path (refs hnswlib/DiskANN read, not copied); Go GC pauses wreck tail latency + weak layout control; Python interpreter voids the distance-budget meaning (plotting only).

02

Workspace shape

Chosen

7 ann-* crates (core/graph/build/optimize/search/store/cli)

Rejected

Single monolith crate; per-algorithm crates

When the rejected choice is right

A single monolith wins when the project has one author, compile-time is the bottleneck, and the crate boundary ceremony exceeds its value — e.g. a rapid prototype that won't be published to crates.io or embedded by others.

Why: Enforces dep DAG (core←graph←{build,search}←optimize); isolates SIMD/unsafe to ann-core; parallel compile; ann-optimize is the project center, kept its own crate.

03

Graph families

Chosen

HNSW + Vamana/DiskANN (RobustPrune), NSG-style repair

Rejected

IVF/clustering-first; LSH; tree (KD/ball)

When the rejected choice is right

IVF/clustering-first wins for very high-cardinality, low-recall workloads (top-100 with recall@100 ≥ 0.80 acceptable) where build time must be sub-minute and the corpus is static — no optimizer needed. LSH wins for streaming high-dimensional binary/Hamming data where graph construction itself is too slow.

Why: Project is the graph QUALITY+OPTIMIZATION layer over graph indexes; IVF is project 255's clustering path; LSH/trees not graph-navigable, no edge-pruning surface to optimize. PQ kept only as on-disk vector compression.

04

Build vs search graph form

Chosen

Mutable AdjacencyList (build) → immutable CsrGraph (search)

Rejected

Single mutable form for both; lock-free concurrent mutable graph

When the rejected choice is right

A single mutable form wins when the index must accept continuous high-rate inserts with no offline freeze window (e.g. a live streaming index with sub-second freshness SLA) — the freeze latency becomes unacceptable. Lock-free concurrent mutable structures (skip-list adjacency) win in that streaming regime.

Why: Build needs O(1) edge churn (index=VectorId); search needs contiguous cache-friendly traversal (CSR offsets+edges). Freeze boundary lets search be lock-free over immutable data.

05

Per-node neighbor container

Chosen

NeighborList = SmallVec<[_;R]> capped + distance-sorted asc

Rejected

Vec; BinaryHeap; B-tree

When the rejected choice is right

A BinaryHeap wins during construction when you perform many candidate insertions before a final selection pass and don't need sorted order until the end — the heap avoids O(R) shifts per insert. A Vec with sort-on-demand wins when R is large (≥ 256) and random reads dominate, making the shift cost of sorted insertion unacceptable.

Why: R small/known → inline SmallVec avoids per-node heap alloc; sorted-asc enables early-exit occlusion checks + cheap M_max truncation; heap wastes locality, B-tree overkill for ≤R items.

06

HNSW edge selection

Chosen

select-neighbors heuristic (Alg 4): keep e iff d(e,q)<d(e,r) ∀ selected r; keep_pruned backfill

Rejected

Naive nearest-M

When the rejected choice is right

Naive nearest-M wins when building an index over already-well-clustered data (e.g. synthetic uniform hypercube) where the diversity property is naturally present; it also wins if the build must be 2× faster and the target recall is only ≥ 0.80 (the diversity benefit is most pronounced near recall ≥ 0.95).

Why: Heuristic yields diverse, navigable neighborhood (long-range edges); naive nearest-M clusters edges → poor reachability, recall cliff.

07

Vamana pruning

Chosen

robust_prune(p,V,alpha,R), two-pass alpha=1.0 then alpha∈[1.2,1.4]

Rejected

Single-pass; alpha=1 only

When the rejected choice is right

Single-pass alpha=1 (pure RNG) wins when the data is low-dimensional (≤ 32 dims) or near-uniformly distributed so the strict relative-neighborhood criterion alone produces a navigable graph without long-range edge relaxation.

Why: Occlusion relaxation alpha≥1 adds DiskANN long-range edges; first pass seeds, second relaxes for navigability at bounded R.

08

Distance convention

Chosen

Distance(f32), smaller=closer everywhere; IP/Cosine stored negated/1−sim

Rejected

Per-metric comparator; separate max-heaps for IP

When the rejected choice is right

A per-metric comparator wins in a system that must expose raw similarity scores (not negated) to the caller without the convention-conversion confusion that arises when external APIs expect raw IP/Cosine values — the negation adds a conceptual impedance mismatch at the API boundary.

Why: One ordering rule (asc=nearest) across all heaps/lists/crates → no metric-conditional branches on hot path; kills a whole class of comparator bugs.

09

SIMD distance kernels

Chosen

Hand-written AVX2/AVX-512/NEON + runtime feature dispatch via DistanceKernel

Rejected

Compiler autovectorization; scalar-only; external SIMD crate

When the rejected choice is right

Compiler autovectorization wins on very high-dimensional vectors (dim ≥ 4096) with modern LLVM: the auto-vectorizer unrolls the reduction loop correctly when the trip count is large and known at compile time, removing the maintenance burden of hand-written intrinsics. External SIMD crate (e.g. packed_simd) wins when targeting multiple exotic ISAs (SVE, RISC-V V) not yet covered by hand-written kernels.

Why: Predictable codegen for L2/IP/Cosine; runtime dispatch ships one binary across ISAs; autovectorization unreliable for horizontal reductions. Scalar kept as differential reference.

10

Visited tracking

Chosen

VisitedSet = versioned bitset, O(1) per-query reset

Rejected

HashSet<VectorId>; clear-on-reuse bitset

When the rejected choice is right

A HashSet wins when the graph order N is very large (≥ 100M nodes) but ef is tiny (≤ 10), so only a sparse fraction of nodes are ever checked — the bitset would be 12+ MB and never fit in L3, while a small hashset stays cache-hot.

Why: Bump generation counter resets in O(1) (no realloc/clear); contiguous bits beat hash probes per node expansion; hashset allocs + cache-misses dominate at high ef.

11

Determinism

Chosen

Single seeded RNG (BuildParams.seed) for level assignment + tie-breaks

Rejected

Thread-local entropy; non-seeded rand

When the rejected choice is right

Non-seeded / thread-local entropy wins in production when you want entropy-based load spreading across parallel inserts (different seeds per shard reduce hot-node collisions) and reproducibility is provided by the corpus snapshot instead of the build process.

Why: Reproducible graphs required for differential testing vs hnswlib/DiskANN and the optimizer-guarantee gate (compare pre/post recall on fixed sample).

12

Optimizer safety gate

Chosen

Optimizer-guarantee: passes only improve/preserve recall@k at fixed ef on diagnostic sample; degree ≤ R; all nodes reachable from EP post-connect_components

Rejected

Best-effort pruning; trust-the-heuristic

When the rejected choice is right

Best-effort / trust-the-heuristic wins when the dataset is so large (≥ 100M) that a recall-harness gate per pass is prohibitively expensive and the heuristic is known-good from offline validation — the gate is replaced by offline A/B recall measurement on a held-out benchmark.

Why: Optimization must never silently regress recall or disconnect graph; gate runs RecallHarness+reachability before commit, else rollback.

13

Autotuner search

Chosen

CostModel (dist-comps≈ef·mean_out_degree·(1+hop_factor)) + Autotuner: bisection over ef, grid over (alpha,R,L)

Rejected

Bayesian optimization; random search; manual tuning

When the rejected choice is right

Bayesian optimization wins when the tuning space has many coupled parameters (≥ 5) with non-monotone interactions, e.g. a filtered ANN index where ef, R, alpha, filter-selectivity, and re-rank depth all interact — the coarse grid misses the true optimum.

Why: Recall monotone in ef → bisection finds min ef meeting RecallTarget cheaply; coarse grid over build params suffices for Pareto; Bayesian opt adds heavy dep + non-determinism for little gain.

14

On-disk vector compression

Chosen

ProductQuantizer (PQ codebooks + asymmetric distance)

Rejected

Scalar quant (i8); full-precision on disk; OPQ

When the rejected choice is right

Scalar quantization (i8) wins when vectors have a known bounded range and the precision loss is acceptable (recall@10 target ≤ 0.90) — i8 avoids codebook training, is faster to decode, and fits better into SIMD dot-product instructions (_mm256_dpbusd_epi32).

Why: PQ gives DiskANN beam-search-with-rerank memory ratio; asymmetric distance keeps query full-precision; scalar quant lower recall/byte; OPQ deferred.

15

On-disk access

Chosen

mmap_graph (mmap CSR)

Rejected

Read entire graph into RAM; custom page cache

When the rejected choice is right

Read-into-RAM wins when the graph fits comfortably in RAM and the access pattern is random/unpredictable — mmap's page-fault latency dominates in random-access workloads, while a pre-loaded Vec<u32> has zero fault cost.

Why: Billion-scale graphs exceed RAM; mmap + OS page cache for DiskANN path; full read-into-RAM kept only for small in-memory indexes.

16

Delete semantics

Chosen

Tombstones (DeleteSet bitset) + lazy relink, periodic consolidation

Rejected

In-place edge removal; immediate rebuild

When the rejected choice is right

Immediate per-delete rebuild wins in an offline batch scenario where deletes arrive in bulk at a known quiescent period (e.g. nightly) and the recall degradation from stale tombstones over hours is unacceptable — the rebuild cost is paid once, avoiding accumulating recall drift.

Why: In-place delete fragments CSR + breaks reachability mid-query; tombstone filters at search, consolidation re-optimizes affected neighborhoods offline.

17

Recall measurement

Chosen

RecallHarness holds exact brute-force KNN ground truth → recall@k

Rejected

Self-reported overlap; ANN-vs-ANN

When the rejected choice is right

ANN-vs-ANN (comparing two approximate results) wins in production monitoring where computing exact KNN on live queries is too expensive — a shadow-index comparison gives a relative quality signal sufficient for regression alerting when absolute recall is not required.

Why: Exact KNN is the only sound oracle for recall@k; used by diagnostics, autotuner gate, conformance benches.

18

Fuzzing

Chosen

cargo-fuzz (libFuzzer): build/search/optimize never panic

Rejected

Property-test only; no fuzzing

When the rejected choice is right

Property-testing only wins when the fuzz corpus is hard to generate meaningfully (e.g. the input space is constrained to semantically valid graphs) and structured property tests with proptest cover the realistic edge cases faster than random fuzzing.

Why: Untrusted vectors + degenerate graphs must never panic/UB; fuzz targets per crate boundary.

19

Differential oracle

Chosen

hnswlib + DiskANN as reference implementations

Rejected

No external oracle; single self-consistency check

When the rejected choice is right

No external oracle wins after the implementation is stable and the differential gap is proven small — the hnswlib/DiskANN build dependency becomes a maintenance burden (version pinning, C++ toolchain in CI) that outweighs the detection value once the heuristics are regression-tested in-house.

Why: Validate recall/topology against canonical impls on identical seeded inputs; catches heuristic drift.

20

Benchmarking

Chosen

criterion micro-bench + ann-benchmarks recall/latency protocol on SIFT1M/GIST1M/DEEP analogs

Rejected

std::time ad-hoc; custom harness

When the rejected choice is right

Ad-hoc std::time wins for a single-run profiling session on a dedicated benchmarking host where variance is low and the measurement overhead of criterion's sampling loop is unwanted — e.g. timing a 30-second full-corpus build where criterion's warm-up budget dominates.

Why: criterion handles variance/outliers for kernel micro-bench; ann-benchmarks methodology for recall@k-vs-QPS curves + regression gates.

21

CI

Chosen

GitHub Actions: fmt, clippy -D warnings, test, MSRV check, fuzz smoke, bench regression gate

Rejected

Local-only; no MSRV job

When the rejected choice is right

Local-only CI wins in the early solo-author phase when GitHub Actions minutes are the constraint and the author runs make ci before every commit — the push-CI cost exceeds the benefit until a second contributor joins.

Why: Enforces production bar + optimizer-guarantee on every push; MSRV job pins 1.78.

22

MSRV policy

Chosen

Pin 1.78; bump only with ADR + CI MSRV job

Rejected

Track latest stable; no policy

When the rejected choice is right

Track latest stable wins when the project has no external downstream consumers and the team wants access to the newest Rust language features immediately — the stabilization lag of a pinned MSRV blocks const-generic improvements useful in NeighborList.

Why: Stable feature surface for downstream; explicit bump audit.

23

Dependency policy

Chosen

Minimal; NO heavy linear-algebra crate in ann-core (smallvec/bitvec/memmap2 only as needed)

Rejected

ndarray/nalgebra in core; broad dep tree

When the rejected choice is right

ndarray/nalgebra in core wins when the project also needs matrix operations for PQ codebook training (k-means on sub-matrices), dimension reduction (PCA pre-processing), or learned index training — hand-writing those in SIMD is impractical, and the LA crate pays for itself.

Why: Distance kernels are hand-written SIMD; a BLAS/LA crate adds bloat, opaque codegen, audit surface for zero hot-path benefit.

Licensing

Chosen

MIT OR Apache-2.0 (dual)

Rejected

GPL; single-license

When the rejected choice is right

GPL wins when the project is a standalone tool (not a library) and the author wants copyleft to prevent proprietary forks — if annopt is only ever a CLI binary, GPL has no downstream embedding cost and ensures derivative work stays open.

Why: Permissive Rust-ecosystem norm; dual license for max downstream compatibility.

Roads not taken

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt-1: IVF / Clustering-First (Inverted File Index)

                   ┌─────────────────────────────────┐
                   │  k-means centroids (cluster map) │
                   │  [C1]  [C2]  [C3]  ...  [Ck]    │
                   └──────────────┬──────────────────┘
                                  │  query → nearest nprobe centroids
                            ┌─────┴──────┐
                            │ nprobe=8   │
                            │  C3  C7    │  ... other probed lists
                            └─────┬──────┘
                                  │  brute-force scan each centroid's inverted list
                              top-k results (with optional PQ re-rank)

Winning regime: Static corpora where build time must be sub-minute, recall targets are ≤ 0.90, and the query distribution matches the training distribution used for clustering. Very high N (≥ 100M) on machines with limited RAM — IVF can work with compressed PQ codes only in RAM. Also wins for filtered/predicate-constrained ANN where the filter dramatically reduces the cluster's candidate count.

Real system: FAISS IndexIVFPQ / IndexIVFFlat (Facebook/Meta). The dominant system for billion-scale offline workloads.

Why rejected: IVF is not a graph index; there is no edge topology to optimize, no occlusion pruning surface, no connectivity invariant. The project's subject is graph quality and topology optimization. Adding an IVF path would be a different project (project 255 — ANN Index). IVF also has a recall cliff: if the true nearest neighbor falls in a non-probed cluster (because the query distribution shifted from training), recall collapses with no gradient signal. Graph-based methods degrade more gracefully because search explores the graph topology dynamically rather than relying on a static partition.

Alt-2: LSH + Post-Filter (Locality-Sensitive Hashing)

  Hash family  h1  h2  h3  ... hL
               ↓   ↓   ↓       ↓
  Buckets:  [A B] [B C] [A C] ... [D E]

  Query q → compute h1(q)..hL(q) → collect all candidate ids from matching buckets
                                 → brute-force distance over candidates → top-k

Winning regime: High-dimensional binary/Hamming data (set membership, SimHash for near-duplicate document detection) where L2/cosine graph methods are expensive to build and maintain. Also wins for extremely high query throughput with very low precision requirements (top-100 recall ≥ 0.70) — LSH hashing is O(L) per query with no graph traversal overhead. Streaming data: no graph to rebuild, just add to the hash table.

Real system: FALCONN (C++), datasketch (Python); also FAISS IndexLSH.

Why rejected: LSH has no topology to optimize — the "structure" is a hash table, not a navigable graph. The project's distinguishing contribution is the graph quality/optimization layer: occlusion_prune, degree_rebalance, connect_components, and the Autotuner Pareto sweep. None of these concepts apply to LSH. LSH also has fundamentally worse recall/latency tradeoffs on dense f32 vectors (the primary data type here) compared to graph methods on ann-benchmarks, making it a poor choice for the target ≥ 0.95 recall workload. Included in the §9 ADR Table (ADR-03) as an explicitly rejected alternative.

Alt-3: Learned / ML Index (Neural Graph + Routing)

  Learned router (small MLP or HNSW with learned embeddings):
  
  query q → MLP(q) → "which region" → narrow graph subspace
                                     → greedy search within subspace
                                     → top-k
  
  OR: replace entry-point selection with a learned routing tree:
  
  [Root]
    ├── [Region A] → dense HNSW sub-graph
    └── [Region B] → dense HNSW sub-graph
         └── [Region C] ...

Winning regime: Known-fixed distribution queries on a static corpus where a learned routing function can dramatically reduce the search space. Google's ScaNN demonstrates that learned quantization (anisotropic hashing) beats isotropic PQ at matched recall/throughput budgets. HNSW with pre-trained embeddings that cluster the space better than raw L2 proximity — e.g. semantic embedding spaces where a learned router routes by concept, not distance.

Real system: ScaNN (anisotropic quantization component); DPR / FAISS with learned pre-processing; NMSLIB with custom distance.

Why rejected: Learned index components add a training dependency (embedding model, routing MLP, AH quantizer) outside this project's trust boundary — vectors arrive pre-computed (§1.3 non-goal: no embedding training). The routing model's quality is not measurable by RecallHarness against exact KNN without access to the model's internals. Adding a neural component would make the graph-quality optimizer's contributions unattributable — did the optimizer improve recall or the router? The project's goal is a measured, auditable, graph-topology-driven optimizer. A learned router can be added as a pre-processing stage by downstream consumers (project 46 — Embedding engine) without being part of this library's scope. The Autotuner's bisection and Pareto search is explicitly designed to be non-learned (ADR-13) for reproducibility and interpretability.
