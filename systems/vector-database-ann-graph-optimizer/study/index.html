Mental Models & First Principles

Compressed expert intuitions. Each: the insight, what it predicts in this system, the bug class that emerges without it, and the resolving section.

# Model Compressed Insight What It Predicts Bug Class Without It Resolving §
MM1 Greedy descent = monotonic gradient flow A navigable graph is one where greedy search makes strictly-decreasing-distance progress toward any target. Long-range edges serve as coarse gradients; short-range edges as fine-grain convergence. The graph quality is determined by how well this monotonic property holds across the data manifold. Whether occlusion_prune will raise or lower recall. Naive nearest-M graphs break monotonicity in dense clusters — greedy gets trapped in a local basin. Diverse heuristic edges restore the gradient at cluster boundaries. recall plateau around 0.70 regardless of ef; symptom: navigability_score low, but mean_out_degree normal §8 (P7, ADR-06)
MM2 ef is the precision/recall dial, R is the precision/memory dial ef controls search-time compute: raising it widens the beam and recovers more true neighbors without touching the graph. R controls build-time memory: raising it stores more edge candidates per node but increases both bytes and per-query dist-comps. The two dials are nearly orthogonal: fix R, sweep ef to hit your recall target. The Autotuner's bisection strategy (bisect ef first, then grid R). A system that raises R to fix a recall problem it could fix with ef wastes memory; a system that raises ef to fix a degree problem it could fix with R wastes compute. confusing graph-quality failure (bad R) with search-depth failure (bad ef) → teams over-build large R graphs when the real fix is a connectivity repair pass §11 (P12-TuneToATargetReportThePareto)
MM3 Orphan nodes cause regional recall collapse A node with no in-edges is permanently unreachable from the entry point during greedy search. Queries whose true neighbors include that orphan get a maximum possible regional recall of zero for those neighbors, but global recall may look fine if most queries don't need that region. Orphan effects are invisible in mean recall, catastrophic in tail recall. orphan_count in GraphDiagnostics is a leading indicator for p99 latency spikes and regional recall failures. After aggressive pruning, reverse_edge_repair is mandatory before measuring recall. "global recall@10 = 0.95 but specific user segment gets 0.3 recall" — textbook orphan region. Missed because mean recall passes the gate. §7 (INV-3, P6-EveryNodeReachableFromEntryPoint)
MM4 Occlusion pruning = distance-space triangle inequality The occlusion predicate d(e,r) < d(e,q) is equivalent to saying: if a node r already in the selected set is closer to candidate e than the query q is, then the edge q→e provides redundant routing — traversing q→r→e is at least as good. Dropping the edge reduces degree without sacrificing the path. Whether aggressive α values will maintain navigability. α=1 is exact RNG; α>1 relaxes the triangle constraint to allow longer edges. At very high α (→∞), no edge is ever pruned — you get back nearest-M. aggressive α=1 prunes so many edges that connectivity breaks (too many triangles eliminated); α too high retains redundant edges and wastes degree budget §6 (P7-NavigabilityOverRawNearestM, [P10])
MM5 Distance computations are the invariant cost unit Wall-clock time varies by ISA (AVX-512 vs NEON), clock speed, memory pressure, and thermal state. Distance computations per query (DistanceCounter) is machine-independent: the same algorithm on the same graph performs the same count on any hardware. The CostModel bridges the two: latency_ns ≈ dist_comps × kernel_ns where kernel_ns is the only hardware-dependent constant. The Autotuner can discover an ef setting on a developer laptop that transfers to production hardware. Comparing two graph designs via mean_dist_comps is fair across architectures; comparing via wall-clock is not. tuning on dev AVX-512 hardware, deploying to NEON ARM, finding p99 doubles — the ef was calibrated on raw wall-clock, not dist-comps §11 (P2-DistanceComputationIsTheUnitOfCost)
MM6 CSR freeze is the single-writer / multi-reader gateway The mutable AdjacencyList allows O(1) per-edge edits but requires exclusive access. The immutable CsrGraph requires no locks because it never changes. The freeze is a one-way semantic gate. Concurrent readers need no synchronization precisely because mutation is impossible after freeze — Rust's ownership model encodes this: &CsrGraph is Send + Sync, &mut Graph is neither. That any concurrent read-over-CsrGraph is race-free by construction, not by lock management. Adding a single &mut field to CsrGraph would make it non-Sync and the compiler would reject concurrent use — the property is compile-time verifiable, not runtime. race condition in C++ ANN libraries where "mostly read" graphs get a stale neighbor list during concurrent build — Rust's type system prevents this class entirely §2 (P4-OptimizedGraphImmutableSendSync, ADR-04)
MM7 Navigable small-world ≠ random graph A random graph has O(log N) diameter and O(log N) greedy convergence, but offers no cache or spatial locality. A navigable small-world graph adds spatial structure: short-range edges cover the local neighborhood, long-range edges jump across the embedding space. This bi-modal edge length distribution — like Kleinberg's 2D grid model — is what makes greedy search polylog in practice, not just in worst case. Why naive nearest-M fails even though it has O(log N) graph diameter: all edges are short-range, there are no long-range shortcuts across the embedding manifold, and greedy search must traverse many hops through the local cluster before finding the global direction. building a low-diameter graph (short max-hop-count) but high-navigability-cost (many average hops) — the diameter metric is misleading; hops-per-query is what matters §3 (P7, [P3] NSW paper)
MM8 Recall is a nonlinear function of ef near saturation At low ef, recall grows nearly linearly in ef (each additional slot in the candidate list captures a new true neighbor). As recall approaches 1.0, the marginal gain per additional ef slot shrinks dramatically — you're competing for the same small set of missed neighbors at the tail of the distribution. This super-linear cost near 1.0 recall is the Pareto knee and is the key output of the Autotuner. The shape of the recall-vs-ef curve: rapid rise, then a long flat tail. A target of recall@10=0.99 may cost 3–4× the dist-comps of 0.95. The Autotuner.pareto function's value is in making this curve explicit, not in picking one point. setting ef=32 because "that's what the docs say" and getting recall=0.88 — the docs assumed a different dataset dimensionality; without the curve you cannot predict the right ef for your corpus §11 (P12-TuneToATargetReportThePareto, ADR-13)

5.4 Specifications / Standards

  • No formal RFC/ISO standard exists for ANN vector formats or recall evaluation — state explicitly. De-facto conventions pinned below.
  • fvecs/bvecs/ivecs (SIFT/Texmex, Jégou): little-endian; per vector int32 dim then dim values (f32/u8/i32); GT in .ivecs = top-k neighbor ids/query. ann-store/CLI loaders implement exactly this. Fixtures: SIFT1M / GIST1M / DEEP-subset analogs (Phase 13).
  • HDF5 ann-benchmarks layout (pinned): datasets train/test/neighbors/distances; distance attr ∈ {euclidean, angular, dot} ↔ Metric::{L2, Cosine, InnerProduct}.
  • recall@k protocol (binding for RecallHarness):
    recall@k = (1/|Q|) · Σ_q |Approx_k(q) ∩ Exact_k(q)| / k
Exact_k(q): brute-force KNN baseline (Phase 0), tie-break by VectorId asc
Report tuple: (recall@k, mean_dist_comps, p50_us, p99_us, QPS) at fixed ef
Operating point: e.g. RecallTarget{ k:10, recall:0.95 }; Autotuner returns min-ef Pareto point
  • IEEE 754 binary32: f32 storage + distance accumulation; fixed SIMD accumulation order for tie stability; reject NaN/Inf at the ann-core trust boundary.
  • SIMD ISA refs (pinned): Intel 64 & IA-32 SDM (AVX2/FMA: VFMADD; AVX-512) + Arm NEON (FMLA, FRSQRTE). Phase 1 target: >5 GFLOP/s f32 L2 at dim 128; target_feature gating + scalar fallback contract.
  • POSIX mmap/madvise (MADV_RANDOM for traversal, MADV_WILLNEED for prefetch): mmap_graph + DiskANN sector reads (Phase 12); on-disk CsrGraph regions aligned to 4 KiB / NVMe sector for batched beam reads.
  • Index file header: magic + format version (SemVer); save_graph/mmap_graph reject incompatible versions; per-section CRC32C checksum for crash-recovery integrity on open.

Glossary · 43 terms · site-wide glossary

Approximate nearest neighbor (ANN)
Search returning vectors probably among the true k-nearest, trading exactness for sub-linear cost.
recall@k
Fraction of the true k nearest (per the exact RecallHarness oracle) that the approximate search returns. The primary quality metric.
k-NN
The exact k nearest neighbors of a query under a Metric; the recall oracle.
out-degree
Number of directed edges leaving a node; capped at R / M_max.
in-degree
Number of edges pointing to a node; low/zero in-degree ⇒ undiscoverable (orphan).
orphan node
A node with no in-edges (or unreachable from the entry point); fixed by reverse_edge_repair / connect_components.
navigable small world
A graph where greedy routing reaches any target in ~O(log N) hops; the HNSW/NSW property the optimizer preserves.
HNSW
Hierarchical Navigable Small World — a stack of Layers, sparse on top, dense on layer 0.
layer
One level of an HNSW graph; layers[0] holds all nodes.
level multiplier ml
1/ln(M); sets the geometric layer-assignment distribution L ~ floor(-ln(U)·ml).
ef_construction
Candidate-list width during build; larger ⇒ better edges, slower build.
ef / ef_search
Working-list width during search; the primary recall/latency dial.
beam width
Parallel-frontier breadth in beam_search over CsrGraph.
select-neighbors heuristic
HNSW Algorithm 4: keep candidate e only if closer to q than to all already-selected neighbors → diverse, navigable neighborhoods.
RobustPrune
Vamana edge selection: occlusion pruning with relaxation alpha, capped at R.
alpha
Occlusion-relaxation factor (≥1); alpha>1 keeps long-range edges (DiskANN two-pass build).
R (max out-degree)
Hard per-node edge cap; a load-bearing invariant (memory + DoS bound).
L
Build/search candidate-list size in the Vamana formulation.
medoid
The corpus point minimizing summed distance to all others; the Vamana entry point.
entry point
The node where every search begins; HNSW's top-layer node or the medoid.
greedy search
Best-first traversal expanding the closest unexpanded node until no improvement.
beam search
Greedy search keeping a width-ef frontier over the immutable CsrGraph.
occlusion pruning
Dropping an edge p→v when a kept neighbor p* "occludes" it (alpha·d(p*,v) ≤ d(p,v)).
relative neighborhood graph (RNG)
The pruning ideal occlusion approximates: no edge p→v if some w is closer to both.
monotonic search path
A path of strictly decreasing distance to the query; its existence underwrites greedy convergence.
connectivity / reachability
Whether every node is reachable from entry_point; enforced by connect_components.
connected component
A maximal mutually-reachable node set; the optimized graph must have exactly one (from EP).
navigability score
A sampled expected-hops-to-convergence proxy in GraphDiagnostics.
visited set
VisitedSet: a versioned bitset marking expanded nodes, reset in O(1) per query.
candidate / result heap
The min-heap of unexpanded candidates and the max-heap of the best-k-so-far in SearchContext.
tombstone
A logical delete marker (Tombstone + DeleteSet); physical removal deferred to consolidation.
consolidation
The pass that physically removes tombstoned nodes and rebuilds the CSR.
product quantization (PQ)
Vector compression into sub-space codebook codes; ProductQuantizer.
asymmetric distance
Distance between a full-precision query and a PQ-encoded vector via codebook lookups.
re-ranking
Re-scoring PQ-shortlisted candidates with full-precision distances (DiskANN).
distance computations
The true cost unit; tracked by DistanceCounter, not wall-clock alone.
recall/latency Pareto frontier
The set of non-dominated (recall, cost) operating points the Autotuner reports.
cost model
CostModel: dist-comps/query ≈ ef · mean_out_degree · (1 + hop_factor).
CSR adjacency
Compressed-sparse-row (offsets, edges) immutable graph form for cache-friendly search.
VectorStore
Row-major contiguous f32 vector storage in ann-core.
CsrGraph
The frozen, immutable, Send+Sync optimized graph searched at serving time.
GraphDiagnostics
The optimizer's measurement substrate: degree, connectivity, navigability, recall estimate.
Autotuner
Bisection over ef + grid over (alpha, R, L) producing the Pareto frontier and a recommended operating point.
