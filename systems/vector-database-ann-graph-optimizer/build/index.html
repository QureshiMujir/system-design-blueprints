Pitfalls
  • NaN in distance heap: f32 PartialOrd leaves NaN unordered → BinaryHeap corrupts, silent wrong KNN. Root cause: raw f32 compare. Fix: total_cmp + reject NaN at ingest. Debug: assert heap monotonic.
  • Self in KNN: nearest-M includes the node itself (dist 0), wasting a slot and inflating recall. Fix: oracle returns k+1, builder drops self by id. Debug: assert edge i→i count == 0.
  • Recall convention flip: max-heap vs min-heap mismatch returns farthest. Root cause: missing Reverse on candidate heap. Debug: top result distance must be the smallest.
  • VisitedSet generation wrap: u32 overflow after 4B queries reuses stale stamps → false "visited". Fix: full clear on wrap. Debug: inject low-width gen in a test.
  • IP/Cosine sign: storing raw similarity (bigger=closer) breaks the universal "smaller=closer", inverting every downstream heap. Symptom: recall 0 only for IP/Cosine. Fix: negate at the kernel boundary; test all 3 metrics in the oracle.

⬜ Phase 1 — SIMD distance kernels and the distance-computation budget §13

Objectives
  • Scalar oracle: l2_sqr / inner_product / cosine over &[f32]; bit-exact reference, never SIMD; all later kernels differential-tested against it.
  • SIMD kernels: AVX2 (8×f32), AVX-512 (16×f32, cfg-gated), NEON (4×f32); FMA accumulate; runtime is_x86_feature_detected! dispatch resolved ONCE per index, cached — no per-call branch.
  • metric_to_distance: L2 → squared L2 (skip sqrt, monotonic); InnerProduct/Cosine → negated similarity so smaller=closer holds across ALL heaps.
  • DataType: f32 primary; f16 (widen-to-f32) and i8 (PQ residual dequant) paths — callable stubs now, exact in Phase 12.
  • DistanceCounter: AtomicU64, +1 per kernel call via thread-local accumulate + batch flush; every later phase reports dist-comps/query.
  • Throughput: >2 GB/s on 128-dim L2 f32 (AVX2, single core); SIMD within fp tolerance of oracle.
Deliverable

ann-core exposes make_kernel, all three metrics × {scalar, AVX2, AVX-512, NEON}, the DistanceCounter, and a criterion suite (benches/distance.rs) printing GB/s + dist-comps. annopt bench --kernels reports chosen ISA + throughput per metric/dim. cargo test -p ann-core green on x86_64 + aarch64.

Pitfalls
  • Cosine zero-norm div-by-0 → NaN poisons heap ordering. Root: unnormalized zero/empty vector. Debug: assert finite; sentinel Distance(0.0).
  • Single SIMD accumulator → latency-bound on FMA dep chain (~4cyc), 3–4× slowdown. Root: no ILP. Debug: perf stat IPC <1 → use 4 accumulators.
  • #[target_feature] on wrong CPU → SIGILL. Root: AVX-512 fn without detection, or target-cpu=native shipped with runtime dispatch. Debug: dispatch via detected enum only; never #[inline(always)] SIMD into a scalar caller.
  • f16→f32 widen rounding drifts from oracle. Root: oracle on raw f16. Fix: oracle consumes the SAME widened f32 slice.
  • DistanceCounter atomic contention under N readers → ~30% search slowdown. Root: fetch_add per call. Fix: thread-local accumulate + batch flush.
  • L2 sqrt drift / catastrophic cancellation in Σ(a-b)² for large near-equal vectors → tiny-negative under FMA reorder. Fix: squared-L2 everywhere, clamp ≥0, relative (not absolute) tolerance.

⬜ Phase 2 — Graph representation (mutable build form + immutable CSR) §14

  • Freeze step Graph -> CsrGraph (offsets+edges; layer-0 adjacency only, the search hot path).
  • Versioned binary (de)serialization for Graph and CsrGraph; round-trip bit-identical adjacency.

Objectives

⬜ Phase 5 — Search engine (greedy/beam best-first, ef control, recall@k) §17

Objectives
  • greedy_search(g, q, ep, ef, ctx) — single-layer best-first; working list size ef; candidate min-heap, result max-heap; correct stop condition.
  • HNSW full path: descend layers top..1 at ef=1, then search-layer layer 0 at ef; return top-k.
  • beam_search(g: &CsrGraph, q, params, ctx) — beam_width expansions/iteration over CSR; identical convergence, better cache locality.
  • VisitedSet: versioned bitset, O(1) per-query reset (no realloc, no full memset).
  • SearchContext reuse: zero steady-state heap allocation across queries (heaps + visited cleared, not freed).
  • RecallHarness: recall@k vs exact KNN; report mean distance-comps + p50/p95/p99 latency.
  • Hooks: batch_search (query slice, reused ctx pool), filtered_search (predicate over VectorId).
  • Target: recall@10 ≥ 0.95 on a 1M graph at a reported ef.

ann-search compiling green. annopt search --index <g> --queries <q> --k 10 --ef <E> returns ids + distances. RecallHarness report: recall@10, mean dist-comps/query, p50/p95/p99 µs. Smoke: search the Phase 0 1k graph; full: 1M graph at recall@10 ≥ 0.95.

⬜ Phase 6 — Vamana / DiskANN builder (RobustPrune, alpha, medoid) §18

Objectives
  • Implement VamanaBuilder (ann-build): flat single-layer graph, GraphKind::Vamana { r, alpha, l } — no hierarchy, one adjacency level (layers[0]).
  • Entry point = medoid (vector minimizing summed distance to a sample), not random / level-based.
  • Per-node greedy_search collects a visited candidate pool V (every node touched, not just top-k) → fed to robust_prune.
  • robust_prune(p, V, alpha, R): occlusion rule removes v where alpha*d(p*,v) <= d(p,v); cap out-degree at R.
  • Two-pass build: pass 1 alpha=1.0 (RNG-like), pass 2 alpha ∈ [1.2,1.4] (DiskANN long-range edges).
  • Bidirectional edge add p→p* and p*→p; when |out(p*)| > R re-run robust_prune on p*.
  • Target: recall@10 within 0.01 of HNSW at equal mean distance-comps on same corpus; differential parity vs DiskANN.

  • Stale neighbor IDs after deletes: scatter into wrong index corrupts in-degree counts. Validate every neighbor < n before transpose.
  • hop_ceiling miscalibration: navigability_score saturates to 0/1 if c·log2(n) ceiling wrong; pin c per fixture, surface raw mean_hops alongside normalized score.

⬜ Phase 8 — Optimizer pruning passes (occlusion prune, rebalance, reverse edges) §20

Objectives
  • occlusion_prune(g, strat, store) — global edge re-selection sweep; drop occluded/redundant edges via PruneStrategy::{RobustPrune, HeuristicSelect, RelativeNeighborhood}.
  • degree_rebalance(g, r) — cap every over-degree node to R using the select-neighbors heuristic (keep diverse, navigable subset; not naive nearest-R truncation).
  • reverse_edge_repair(g, min_in_degree) — make orphan / low-in-degree nodes discoverable by adding reverse edges from their out-neighbors.
  • Enforce guarantee: re-run GraphDiagnostics sampled recall@k at fixed ef; reject/rollback any pass regressing recall beyond tolerance.
  • Deliverable: optimized graph with measurable improvement on mean_out_degree and/or recall/dist-comp, proven by before/after diagnostic diff.

Acceptance

⬜ Phase 10 — Incremental maintenance (insert, delete, re-optimize) §22

Objectives
  • Insert into optimized Graph (HNSW or Vamana) at amortized cost ≈ one build-time insert; recall@k drift ≤ 2 pts vs full rebuild after up to 20% churn.
  • Delete = O(1) tombstone mark + bounded lazy relink; never orphans a live node, never returns a tombstoned VectorId from search.
  • Local re-optimize: re-run pruning only over affected_set (insert/delete neighborhoods ∪ 1-hop), not the whole graph.
  • Consolidation: physically drop tombstoned nodes, remap VectorIds, rebuild CsrGraph; atomic + crash-recoverable.
Deliverable

annopt optimize --insert <vecs> | --delete <ids> | --consolidate plus the three library APIs. Acceptance
  • Insert 10k into a 100k optimized graph: recall@10 within 2.0 pts of full rebuild on the 110k set; mean insert ≤ 1.3× build-time per-node distance comps.
  • Delete 20%, then search: 0 tombstoned ids returned; 0 orphaned live nodes (reachability from entry_point covers all live).
  • Post-consolidate: connected_components == 1, orphan_count == 0, max out-degree ≤ R, IdRemap bijective over the live set.

⬜ Phase 12 — Persistence, mmap, and PQ compression (DiskANN-style rerank) §24

Objectives
  • Versioned, mmappable on-disk format for CsrGraph (offsets+edges) + VectorStore (f32 vectors) + optional PQ codes/codebooks; little-endian, fixed magic, alignment-aware.
  • mmap_graph(path) -> io::Result<MappedGraph>: zero-copy &[u32]/&[f32]/&[u8] views; search runs directly off the map, no full-vector RAM resident.
  • ProductQuantizer: train m_subspaces codebooks of ksub centroids (Lloyd k-means per subspace), encode f32 → u8 codes, asymmetric distance via per-query LUT.
  • DiskANN-style search: beam_search over PQ asymmetric distances → candidate superset, then full-precision (mmapped f32) re-rank of top-rerank_k → final top-k.
  • INVARIANT: save→mmap→search reproduces in-memory full-precision recall exactly (bit-identical results); PQ path trades bounded recall loss (≤ stated Δ) for measured memory reduction.
