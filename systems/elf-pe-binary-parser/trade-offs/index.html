Decisions (§9) · 25 ADRs

ADR-001

Language

Chosen

Rust 2021 ≥1.78

Rejected

C, C++, Go, Zig

When the rejected choice is right

C/C++ wins when embedding into a C-only codebase with no FFI budget; Zig wins in a bare-metal or WebAssembly target without std; Go wins for a quick scripting-style parser where throughput is not critical

Why: Memory safety on hostile bytes; zero-copy lifetimes; cargo fuzz/Miri; no GC; exhaustive enums

ADR-002

Parse style

Chosen

Hand-written over &[u8]

Rejected

nom, winnow, parser-gen

When the rejected choice is right

nom/winnow win when the format has complex recursive grammar and you want composable combinators with fewer test cases; parser-gen wins when the format is formally specified in a grammar

Why: Explicit control over every offset; best error messages (offset + kind) on binary; no dependency on combinator crate ABI

ADR-003

Zero-copy

Chosen

&[u8] spans; bytemuck-style reads

Rejected

Always-copy Vec<u8> fields

When the rejected choice is right

Always-copy wins when the parsed model must outlive the buffer by more than one stack frame without an OwnedImage wrapper, or when downstream mutates the data

Why: Memory ceiling ≤ 2× file size (§4); lifetime-enforced aliasing safety

ADR-004

Endianness

Chosen

Explicit read_u16/u32/u64::<LE/BE> per field

Rejected

Host-endian transmute

When the rejected choice is right

Host-endian transmute wins on a single-endian embedded target where all inputs are guaranteed same-endian and performance is constrained to nanoseconds

Why: Correctness on BE ELF (SPARC, MIPS, s390x targets); explicit reads prevent silent misparse

ADR-005

mmap

Chosen

Optional, isolated unsafe in bp-read::mmap

Rejected

Always-read into Vec<u8>

When the rejected choice is right

Always-read wins when mmap is unavailable (WASM, some embedded OSes) or when the file is on a remote/slow FS where page-fault latency exceeds sequential read cost

Why: Avoids a full read of ≥ 4 GiB files; unmaps on drop; only audited unsafe site (I9)

ADR-006

Error model

Chosen

Typed enum ParseError{offset,kind} + Result

Rejected

Panic on bad input; Option

When the rejected choice is right

Panic-on-error wins in a trusted sandbox where the caller has already validated bytes; Option wins in a deeply embedded no-alloc path where error context storage is too expensive

Why: Total parsing (P5, I1): every failure is a typed value with an offset; Option loses the offset context

ADR-007

Integer safety

Chosen

checked_add/mul/sub everywhere

Rejected

Wrapping arithmetic

When the rejected choice is right

Wrapping wins only in provably-safe arithmetic already bounded by prior validated fields — document each site explicitly

Why: I2: offset+len wrapping bypass breaks the bounds check; checked ops return Err on overflow

ADR-008

Model shape

Chosen

Concrete structs (BinaryImage, Section, …)

Rejected

Generic trait over format (ObjectFile<F>)

When the rejected choice is right

Generic traits win when you need plug-in format support at runtime (e.g., a plugin-loadable format registry), or when the compiler can exploit monomorphisation to eliminate branches

Why: Stable, greppable API for downstream (#334/#335); no associated-type complexity; trait gymnastics obscure errors

ADR-009

String tables

Chosen

Lazy bounds-checked &'a str view

Rejected

Eager String copy

When the rejected choice is right

Eager copy wins when the caller needs the string to outlive the buffer (e.g., building a long-lived index) without an OwnedImage indirection

Why: Zero-copy + lifetime safety; avoids per-symbol allocation on large .dynsym

ADR-010

CLI framework

Chosen

clap v4 derive

Rejected

Hand-rolled arg parser

When the rejected choice is right

Hand-rolled wins in a no-dep embedded context or when the binary must be <100 KB and clap is too large

Why: UX parity with readelf (subcommands, --json, --verbose); maintenance cost low; help text free

ADR-011

Logging/diagnostics

Chosen

tracing + Vec<Diag> in model

Rejected

log + stderr print

When the rejected choice is right

log + stderr wins for a simple CLI where no programmatic consumer of diagnostics exists

Why: Structured, deterministic; diagnostics embedded in model for programmatic consumers; tracing spans per phase

ADR-012

Testing strategy

Chosen

cargo test + proptest + golden differential

Rejected

Unit tests only

When the rejected choice is right

Unit-only wins for a private format with no external oracle; golden tests alone win when the output format is stable and fully specified

Why: Differential vs readelf/llvm-readobj is the correctness oracle; property tests cover the "never panic" invariant; unit tests alone miss real-world deviations

ADR-013

Fuzzing

Chosen

cargo fuzz (libFuzzer) per entry

Rejected

No fuzzing

When the rejected choice is right

AFL++ wins when targeting a target that runs in a subprocess; no-fuzz wins only for a format so simple that its grammar is a single flat struct

Why: Safety gate for hostile input (P1, I1/I2); libFuzzer's coverage guidance finds deep paths; 24h nightly catches regressions

ADR-014

Sanitizers

Chosen

Miri (UB) + ASAN on mmap path

Rejected

No sanitizers

When the rejected choice is right

No sanitizers wins in a pure-safe Rust codebase with zero unsafe — but we have mmap

Why: Miri catches UB before hardware; ASAN catches OOB in the one unsafe site (I9)

ADR-015

Corpus

Chosen

Real /usr/bin + system DLLs + compiler outputs

Rejected

Synthetic-only

When the rejected choice is right

Synthetic-only wins when real binaries are proprietary or legally restricted

Why: Real binaries expose benign deviations (§H.1) that synthetic fixtures miss; compiler corpus free

ADR-016

CI platform

Chosen

GitHub Actions (multi-job: build/fuzz/diff/release)

Rejected

Jenkins, local-only

When the rejected choice is right

Jenkins wins in an air-gapped enterprise; local-only wins for a proprietary codebase with IP concerns

Why: Free for open source; matrix (Linux/Mac/Win) covers all formats; job isolation; secrets for signing

ADR-017

Packaging

Chosen

Library crate + binary; --no-default-features strips mmap

Rejected

Binary-only

When the rejected choice is right

Binary-only wins for a standalone RE tool with no embedding requirement

Why: Embeddable beneath #334/#74/#76; --no-default-features enables WASM/embedded

ADR-018

Dependency policy

Chosen

Minimal, pinned, cargo deny

When the rejected choice is right

Permissive wins in a rapid-prototype where audit cost outweighs supply-chain risk (e.g., internal tooling with no external deployment)

ADR-019

Benchmarks

Chosen

Rejected

std::time microbenchmarks

When the rejected choice is right

std::time wins for a one-off measurement; criterion overhead is unnecessary for a non-throughput-critical tool

Why: Regression detection with confidence intervals; CI-gated throughput targets (§4, M1–M10)

ADR-020

Documentation

rustdoc + docs/adr/ + format notes

Rejected

Wiki

Wiki wins when the audience is non-Rust and the doc must be edited by non-engineers

License

Chosen

Apache-2.0

Rejected

GPL-2.0, MIT

When the rejected choice is right

GPL wins when the goal is preventing proprietary forks; MIT wins for maximum permissiveness with no patent grant

ADR-022

Model versioning

Chosen

SemVer 2.0 on bp-types::BinaryImage public API

Rejected

Implicit / no guarantee

When the rejected choice is right

Implicit versioning wins in a monorepo where all consumers are co-versioned and rebuilt atomically

Why: Downstream (#334/#335/#74/#76) depends on stable types; cargo public-api diffs gate breaks in CI (P12)

ADR-023

Reproducibility

Chosen

Deterministic dump + ordered collections + pinned toolchain + SOURCE_DATE_EPOCH

Rejected

Non-deterministic

When the rejected choice is right

Non-determinism wins only if output ordering is genuinely irrelevant and no comparison pipeline exists

Why: I3: same bytes → same dump; required for differential comparison and corpus regression

ADR-024

C-ABI binding

Chosen

cbindgen-generated header + opaque handle API

Rejected

Direct Rust FFI

When the rejected choice is right

Direct Rust-to-Rust FFI wins when all consumers are Rust; cbindgen adds build complexity

Why: Non-Rust consumers (#334 if C, tooling in Python/C++); opaque handles prevent UB from pointer misuse

ADR-025

Archive support

Chosen

ar format parsed in bp-ar crate, members re-parsed via existing pipeline

Rejected

Bundled in bp-elf

When the rejected choice is right

Bundling wins when the archive format is inseparable from the object format (e.g., a custom container)

Why: Separation of concerns; static-lib parsing is a distinct format layer above ELF/COFF; reuse all existing decoders

Alternative Architectures (Roads Not Taken)

Alternative 1 — Streaming / SAX-style event parser

file bytes → StreamParser
                │
                ├─ on_section(idx, name, flags, off, size) ─► caller callback
                ├─ on_symbol(name, value, bind, kind)       ─► caller callback
                ├─ on_reloc(offset, sym, kind, addend)      ─► caller callback
                └─ on_import(lib, name, ordinal)             ─► caller callback
    No BinaryImage built; caller accumulates what it needs.

Regime where it wins: streaming a 10 GB binary or a corpus of millions of files where building an in-memory model for each is prohibitive; or feeding a database pipeline that needs to index fields without holding the full model. Real system: readelf --wide in streaming mode; SAX XML parsers; Kafka consumer pipelines. Why rejected: downstream tools (#334, #335) need random-access queries (symbol_at(addr), section_by_name) after the parse; a streaming model cannot serve these without the caller accumulating the data anyway, rebuilding the model. The round-trip test (I8) also requires a complete model. The callback API is harder to test differentially and harder to compose.

Alternative 2 — Generic trait-object model (ObjectFile<F> where F: Format)

trait ObjectFile {
    fn sections(&self) -> Box<dyn Iterator<Item = dyn Section>>;
    fn symbols(&self) -> Box<dyn Iterator<Item = dyn Symbol>>;
    fn entry(&self) -> u64;
}
struct ElfFile<'a> { … }  impl ObjectFile for ElfFile<'a> {}
struct PeFile<'a>  { … }  impl ObjectFile for PeFile<'a>  {}

Regime where it wins: when a plugin system loads format parsers at runtime (unknown at compile time), or when the format list is open-ended (add Mach-O, WASM without recompiling the core). Real system: gimli-rs/object (uses this pattern heavily), IDA Pro's format loaders (dynamic plugins). Why rejected: trait objects incur vtable dispatch on every field access; associated types proliferate; error types become abstract (Box<dyn Error>) losing offset context; the concrete BinaryImage struct is greppable and stable — the primary SemVer contract for #334 works better on a concrete type that can be pattern-matched and doc-tested without trait gymnastics.

Alternative 3 — Lazy-everything / on-demand parser (no upfront parse)

BinaryImage::open(path) -> LazyImage   // reads only magic; no header parse
LazyImage::sections()   -> LazyResult  // reads section table on first call
LazyImage::symbols()    -> LazyResult  // reads symbol table on first call
// Each field parsed only when accessed; results cached.

Regime where it wins: a tool that needs only one field from a binary (e.g., just the build-id, just the entry point) and wants to pay zero cost for the rest; or a REPL-style interactive tool where the user inspects one field at a time. Real system: Python's pyelftools (lazy section parsing); IDA Pro's deferred analysis. Why rejected: caching per-field requires internal mutability (Mutex or OnceCell), breaking Send+Sync simplicity (I12) and making the model non-deterministic in order of initialization. The round-trip test and differential test both need the full model parsed upfront. The complexity of managing a partially-parsed state machine is higher than a single-pass full parse at the throughput targets (M2/M3).

Alternative 4 — Memory-mapped file as the primary zero-copy substrate (no &[u8] slice API)

// Parser takes `*const u8` + `usize` from mmap; all views are raw pointer arithmetic.
// No `Reader` trait; structs are `#[repr(C)]` transmutes directly from the mapping.
unsafe fn parse_elf(base: *const u8, len: usize) -> ElfImage { … }

Regime where it wins: maximum throughput on huge files where even the bounds-checked Reader trait dispatch is measurable overhead; or a kernel-space or no-alloc embedded parser where Rust's safe abstractions are unavailable. Real system: Linux kernel ELF loader (does exactly this), some commercial RE tool backends. Why rejected: violates I9 (no unsafe on the parse path); makes Miri testing difficult; repr(C) transmutes on misaligned data (e.g., a 3-byte-aligned field in a packed ELF section) cause UB on strict-alignment architectures (ARM); endianness is implicit (breaks ADR-004 for BE ELF). The safe Reader trait adds negligible overhead (bounds check = one comparison and branch) and enables Miri + fuzz without special harnesses.
