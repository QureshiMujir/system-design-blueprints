3. Architectural Overview

                ┌──────────────────────────────────────────────┐
   file/&[u8] ─►│ FORMAT DETECTOR (bp-detect)  magic: 7fELF / MZ │
                └───────────────┬───────────────┬────────────────┘

Per-box: Detector (bp-detect) — sniffs magic (\x7fELF, MZ→PE offset at 0x3C via e_lfanew), refuses ambiguous dual-magic (trust boundary #1, I10); reads ≤ 64 bytes. bp-elf/bp-pe — parse fixed headers into validated raw structs; reject impossible field combinations (wrong e_version, unknown e_class); produce arch/endian/bits metadata. bp-read — the safety core: every (offset, len) pair is checked against file size before a slice is produced; checked_add/checked_mul throughout; the sole unsafe site is mmap initialization; all other code is safe (I1/I2/I9). bp-sym — symbol tables (.symtab, .dynsym, COFF) + their string tables (via sh_link), name resolution, address-sorted index for symbol_at. bp-reloc — relocation entries decoded per arch (x86-64 RELA, AArch64, PE base relocs); addend semantics; unknown types kept with diagnostic. bp-dynamic — ELF .dynamic/DT_* walk; PE Import/Export/IAT directory; GNU symbol versioning (.gnu.version*). bp-note — ELF notes (GNU build-id, arbitrary note types), PE debug directory (CodeView RSDS → PDB GUID/path). bp-model — the canonical BinaryImage<'a> everything downstream reads; owns the RVA↔file-offset RvaMap; immutable, Send+Sync (I4/I12). bp-cli — human dump (readelf/dumpbin parity) + header round-trip check + triage report. bp-debug — locates DWARF/CodeView sections and unwind tables (full parsing deferred to #335). bp-ar — ar archive member iteration and symbol index.

8. Domain Model

8.1 Container layouts (compact)

ELF:  [Ehdr] [Phdr0..Phn] ... [section data] ... [Shdr0..Shn]
  Ehdr: e_ident(MAG0..3=7f454c46, CLASS=1/2, DATA=1/2 LE/BE) e_type e_machine
        e_entry e_phoff e_shoff e_flags e_ehsize e_phentsize e_phnum e_shentsize e_shnum e_shstrndx
  Shdr: sh_name sh_type sh_flags sh_addr sh_offset sh_size sh_link sh_info sh_addralign sh_entsize
  Phdr: p_type p_flags p_offset p_vaddr p_paddr p_filesz p_memsz p_align

PE:   [MZ DOS hdr @0 | e_lfanew@0x3C] → [PE\0\0][COFF FileHeader][OptionalHeader(PE32/PE32+)][DataDir[16]][SectionHeader[]]
  Section: Name[8] VirtualSize VirtualAddress(RVA) SizeOfRawData PointerToRawData Reloc Ln Characteristics
  DataDir: Export Import Resource Exception Cert BaseReloc Debug ... IAT DelayImport

8.2 Unified model (normative shape)

BinaryImage { fmt: Elf|Pe, arch: Arch, endian, bits: 32|64, entry: u64,
              sections: [Section], segments: [Segment], symbols: [Symbol],
              relocs: [Reloc], imports: [Import], exports: [Export],
              dynamic: [DynEntry], notes: [Note], rva_map: RvaMap, diagnostics: [Diag] }
Section { name, kind, flags(R/W/X/alloc), file_off: Span, vaddr: u64, size, align, entsize, link, info }
Symbol  { name, value: u64, size, bind(Local|Global|Weak), kind(Func|Obj|Sect|File), section_idx, defined: bool }
Reloc   { offset: u64, sym_idx, kind: u32(arch-specific), addend: i64, section }
Import  { lib, name|ordinal, iat_rva } ; Export { name|ordinal, rva, forwarder? }

8.3 RVA↔offset (the audited map)

file_off(rva) = section.file_off.start + (rva - section.vaddr)   iff section.vaddr ≤ rva < vaddr+vsize
  → gap/no section ⇒ Err(rva_unmapped)  (I4)   ; SHT_NOBITS/.bss has size but no file bytes (I11)

8.4 Worked example (ELF64 /bin/true)

7f454c46 02 01 01 → ELF64 LE; e_type=ET_DYN(PIE) e_machine=0x3e(x86-64) e_entry=0x..; walk e_shoff→Shdr[]; e_shstrndx gives section-name strtab; find .dynsym(sh_link→.dynstr), .rela.plt, .dynamic(DT_NEEDED→libc). Model: sections+symbols+imports; binparse dump mirrors readelf -a. This example exercises: I1 (every e_shoff + e_shnum*64 checked), I4 (RVA map built from PT_LOAD), I6 (strtab resolves), I7 (sh_link validated), P7 (DT_STRTAB vaddr→offset via RvaMap).

8.5 State-transition for parse dispatch

DetectState:
  initial → read(0,4) → \x7fELF → ELF_path
                       → MZ     → read_le32(0x3C) → bound-check → PE_path
                       → other  → Err(BadMagic)
  ELF_path + PE_path → both match → Err(AmbiguousFormat)   [I10]

ELF_path:
  EI_CLASS=1 → ELF32   EI_CLASS=2 → ELF64   other → Err(BadField)
  EI_DATA=1  → LE       EI_DATA=2  → BE       other → Err(BadField)
  Validated {class,data} → decode Ehdr with correct width+endian

(continued)

  Ehdr valid → checked_mul(e_phnum, e_phentsize) → bound-check(e_phoff) → Phdr[]
             → checked_mul(e_shnum, e_shentsize) → bound-check(e_shoff) → Shdr[]
  Any failure → Err(ParseError{offset, kind}) — no partial struct escapes [P5]

8.6 Malformed / failure-path examples

  • e_shoff past EOF → Err(OffsetOutOfBounds{off,filelen}) (I1).
  • e_shnum * e_shentsize overflows usize → Err(Overflow) (I2).
  • sh_link ≥ section count → Err(DanglingLink) (I7).
  • strtab index ≥ strtab size → name <malformed> + Diag (I6).
  • PE e_lfanew points outside file → Err(BadPeOffset).
  • Import directory RVA in no section → Err(RvaUnmapped) (I4).
  • 12-byte file claiming 4×10⁹ sections → Err(CountCapExceeded) (I5).
  • Both ELF magic and MZ heuristics → Err(AmbiguousFormat) (I10).
  • e_shnum == 0 with extended count in section[0].sh_size — handled as benign deviation (§H.1, W.DEVIATION).
  • .dynamic missing DT_NULL terminator — bounded scan by section size, W.DEVIATION diagnostic emitted.

Design principles (§6)

  • P1 — Parse, don't trust. Every field from the file is hostile until explicitly validated; treat the spec as describing the language of valid inputs, and reject everything outside it. Tradeoff: validation adds a branch per field — acceptable because the branch is predicted and the alternative is exploitable. Violation: one unchecked offset → OOB read / RCE in the tool. Operational implication: bp-read is the sole gate; nothing downstream slices without a checked span.
  • P2 — Bounds + overflow checks are mandatory, not optional. All offset/size arithmetic uses checked_add/checked_mul; never wrapping. Tradeoff: checked ops return Option — add one .ok_or(Err(Overflow)) per arithmetic site. Violation: offset+len integer overflow wraps on 32-bit usize, bypassing the bounds check; a 4-byte header claims 4 GiB of section data. Operational implication: overflow_guard metric is the canary.
  • P3 — Zero-copy by default, own only for fixups. Return &'a [u8] / typed views into the source buffer; never copy unless the caller needs ownership (use OwnedImage for that). Tradeoff: lifetimes couple views to the buffer scope; OwnedImage is needed for long-lived consumers. Violation: copying every field blows the ≤ 2× memory ceiling on large binaries.
  • P4 — Determinism. Same bytes ⇒ same model ⇒ same dump, always. Use ordered collections (Vec, BTreeMap, sorted indices) throughout; no HashMap iteration order in output. Tradeoff: BTreeMap has higher constant factor than HashMap — acceptable for the small tables involved. Violation: non-reproducible dump diffs prevent differential comparison and break I3.
  • P5 — Total over partial: a parse either yields a fully validated node or a typed error with offset. No half-built struct escapes the parse boundary. Tradeoff: requires validating all fields of a struct before assembling it — adds one validation pass per struct. Violation: downstream code reads uninitialized or partially-filled fields → silent wrong output.
  • P6 — Format-agnostic core, format-specific edges. All ELF-specific and PE-specific logic lives in bp-elf/bp-pe; bp-model holds only unified types. Tradeoff: requires a normalization step from format-specific to unified — adds one translation layer. Violation: PE IMAGE_ORDINAL_FLAG semantics leak into the ELF symbol path, producing wrong results on ELF inputs.
  • P7 — RVA↔offset translation is one audited function. All address arithmetic goes through RvaMap::to_offset; no ad-hoc vaddr - section.vaddr + section.file_off expressions elsewhere. Tradeoff: adds one function call per address; negligible. Violation: scattered address math → one site gets it right, three others subtly wrong → wrong import/symbol/reloc addresses.
  • P8 — Lenient read, strict report. Tolerate benign deviations real toolchains emit (§H.1), but record every deviation as a W.DEVIATION diagnostic with a stable code and rationale. Tradeoff: requires maintaining the allow-list; new deviations need review. Violation (too strict): reject real-world binaries → tool is unusable on production binaries. Violation (too lenient): silently accept corruption → downstream tools receive wrong data.
  • P9 — No unsafe on the parse path. mmap initialization in bp-read::mmap is the sole audited unsafe site; the CI grep gate enforces this. Tradeoff: occasional ergonomic friction (e.g., cannot use transmute for speed); bounded overhead from safe checked reads. Violation: unsafe slicing in a parser → Miri cannot audit it; a fuzzer input triggers UB.
  • P10 — Differential correctness. Parser output is validated field-for-field against readelf/llvm-readobj/dumpbin on a large real-world corpus; no field is "probably right". Tradeoff: requires maintaining the oracle pipeline and allow-list. Violation: a subtle endianness or shift error ships undetected and corrupts symbolization in #334.
  • P11 — Bounded work. Section/symbol/reloc/import counts are capped against what the file can physically contain (file_bytes / MIN_ENTRY_SIZE); cyclic chains use visited sets; no unbounded recursion. Tradeoff: cap checks add O(1) per table; visited sets add O(chain_length) memory. Violation: 12-byte file claims 4×10⁹ sections → OOM or OOB before any meaningful data is read.
  • P12 — Stable model API + versioned dump. Downstream projects (#334/#335/#74/#76) depend on BinaryImage; every public type is SemVer'd; breaking changes require a major bump and downstream notification. Tradeoff: requires #[non_exhaustive] on all enums and cargo public-api gating in CI. Violation: a field rename ships as a minor version → silent build break in every downstream consumer.
