⬜ Phase 0 — Skeleton, Reader, Detector, ELF+PE Headers, CLI dump §12

Objectives

Bounds-checked Reader (I1/I2), format detection (I10), ELF & PE fixed headers, BinaryImage skeleton, binparse headers. Constraint: no slice escapes unchecked from day one.

Deliverable

binparse headers <file> prints ELF/PE header + section list for real binaries; binparse detect <file> prints format/arch/bits/endian.

Acceptance
  • Parses /bin/* (ELF64 LE), a BE ELF (MIPS cross-compiler output), a PE32+ .exe/.dll; header fields byte-exact match readelf -h/dumpbin /headers on all three.
  • Every malformed Phase-0 fixture → typed Err with offset context, never panic; fuzz smoke 1M execs, 0 crashes, 0 OOB (ASAN clean).
  • Detection 100% correct on a 500-binary corpus; ambiguous inputs → Err(AmbiguousFormat).
  • CLI startup ≤ 20 ms cold (M8).
Fixtures
Fixture Purpose Expected
conformance/elf/hello64 ELF64 LE x86-64 arch=X86_64, endian=LE, sections≥10
conformance/elf/hello_be ELF32 BE MIPS endian=Big, arch correct
conformance/pe/hello.exe PE32+ x86-64 fmt=Pe, bits=64
conformance/malformed/trunc_ehdr truncated ELF header Err(Oob) at offset 0
conformance/malformed/shoff_eof e_shoff past EOF Err(Oob) at shoff
conformance/malformed/bad_lfanew e_lfanew past file Err(BadPeOffset)
conformance/differential/*.readelf.txt oracle outputs field-for-field match
Pitfalls
  • Unchecked offset+len overflow (I2): e_shoff + e_shnum*e_shentsize wraps on 32-bit usize if e_shnum is huge; use checked_mul then checked_add → Err(Overflow).
  • Host-endian read on BE ELF (ADR-004): reading a u32 at offset 0x18 with native byte order gives garbage on an x86-64 host parsing a SPARC binary; every read must pass the decoded Endian value.
  • PE e_lfanew unbounded (I1): a malformed DOS header has e_lfanew=0xFFFFFFFF; validate < file_len before seeking.
  • SHT_NOBITS data read (I11): .bss has sh_size > 0 but sh_offset points to nothing meaningful; gate Section::data by type, never read file bytes for NOBITS.
  • Extended section count (Appendix H.1): e_shnum==0 means the real count is in section[0].sh_size; forgetting this truncates the section table on large object files.

⬜ Phase 1 — Section & Segment Tables, String Tables, RVA Map §13

Objectives

Full section/segment model, ELF shstrtab/.strtab, the audited RvaMap (I4), section-data spans (lazy, NOBITS-aware I11). The RVA map is the single most load-bearing artifact in the system — every address-bearing phase depends on it.

Deliverable

binparse sections <file> outputs section table matching readelf -S field-for-field; binparse rva <file> <addr> prints file offset or error; binparse off <file> <offset> prints vaddr.

Acceptance
  • RvaMap::to_offset(vaddr) returns exact file offset for every section's vaddr on a 20-binary ELF+PE corpus; gaps return Err(RvaUnmapped) (I4 round-trip test, property: to_offset(vaddr) == file_off for every mapped address).
  • Section flags (R/W/X/alloc) match readelf -S/dumpbin /headers field-for-field.
  • NOBITS sections produce no file read (M4 memory target held).
  • rva_unmapped metric increments for gap accesses (I4 telemetry).
Fixtures
Fixture Purpose Expected
conformance/elf/sections_full full section table names+flags match readelf -S
conformance/pe/sections_pe32p PE32+ section table VirtualAddress/RVA correct
conformance/malformed/shstrndx_oob e_shstrndx ≥ shnum Err(DanglingLink)
conformance/malformed/overlap_sections overlapping file offsets W.OVERLAP diag; parse continues
conformance/malformed/rva_gap address in unmapped gap Err(RvaUnmapped)
conformance/roundtrip/rva_* round-trip tests to_offset(vaddr) correct
Pitfalls
  • e_shstrndx dangling (I7): if e_shstrndx ≥ e_shnum, section-name lookup crashes or reads garbage; validate the index before use.
  • Overlapping sections: two sections sharing a file range → ambiguous to_offset; use deterministic first-match (lowest vaddr) + emit W.OVERLAP diagnostic.
  • PE alignment mismatch (SectionAlignment > FileAlignment): virtual size rounds up to SectionAlignment; file size rounds to FileAlignment; confusing the two produces wrong RVA → file-offset mapping.
  • Zero-VirtualSize PE section: exclude from RvaMap; a vsize-0 section has no mapped range.
  • p_memsz > p_filesz (ELF BSS-like tail): the tail has virtual pages but no file bytes; only map p_filesz worth of file offset.

⬜ Phase 2 — Symbols (ELF .symtab/.dynsym, COFF) + Names §14

Objectives

Decode symbol tables + their string tables; bind/kind/section; defined-vs-undef; symbol_at(addr) for #334.

Deliverable

binparse syms mirrors readelf -s/nm; symbol_at returns nearest defined func.

Acceptance

Symbol count/names/values match nm/readelf -s on a 10-binary corpus; weak/undef flagged; COFF 8-char and strtab names both resolve; differential pass; symbol_at latency ≤ 1 µs (M6).

Fixtures

conformance/elf/syms_stripped, conformance/elf/syms_versioned, conformance/coff/obj_syms, conformance/malformed/{strtab_idx_oob,bad_st_info,sym_shndx_oob}.

Pitfalls
  • strtab index OOB (I6): st_name ≥ strtab.len() → produce name <malformed> + Diag(E.BAD_STRTAB), never crash; the symbol entry is otherwise kept.
  • SHN_ABS/SHN_COMMON/SHN_UNDEF special section indices misread as real section indices → must branch on these before indexing into the sections array.
  • COFF 8-char vs strtab names: if name[0..4] == 0x00000000, the offset is in name[4..8] LE — getting this backwards produces garbage names.
  • st_info byte split: bind = st_info >> 4; type = st_info & 0xF — off-by-one in the shift is a common mistake.
  • SHN_XINDEX: when st_shndx == 0xFFFF, the real index is in .symtab_shndx[sym_idx]; omitting this breaks large object files.

⬜ Phase 3 — Relocations (ELF REL/RELA, PE base relocs) §15

Objectives

Decode relocation tables with arch-specific kinds + addends; expose for #76 loader and #334 symbolization of references.

Deliverable

binparse relocs matches readelf -r/dumpbin /relocations.

Acceptance

Reloc count/type/offset/addend match readelf -r/dumpbin /relocations on a corpus of 12 binaries (6 x86-64/AArch64 ELF, 6 PE) with 0 field mismatches; PE base-reloc block parsing byte-exact; differential pass; relocs_n metric correct; unknown type entries present in model with raw kind; decode throughput ≤ 200 ms per 1M relocs (M11).

Fixtures

conformance/elf/rela_x64, conformance/elf/rel_arm, conformance/pe/basereloc_dll, conformance/malformed/{reloc_sym_oob, bad_block_size, reloc_into_nobits}.

Pitfalls
  • r_info split differs ELF32 vs ELF64 (I2): ELF32 sym=r_info>>8, type=r_info&0xFF; ELF64 sym=r_info>>32, type=r_info&0xFFFFFFFF — using the wrong shift silently produces wrong symbol indices.
  • PE SizeOfBlock lies: a malicious block claims 0x80000000 bytes; cap iterations by (SizeOfBlock-8)/2 and validate SizeOfBlock ≤ remaining data first (I5/I1).
  • Addend sign: RELA r_addend is a signed i64; misreading as u64 makes negative addends (common in x86-64 PLT) look like huge positive values.
  • R_X86_64_RELATIVE/R_*_IRELATIVE: no symbol index (sym_idx=0); must not index into symbol table.
  • PE ABSOLUTE (type 0): padding entries to align blocks; must be skipped, not decoded as relocations.

⬜ Phase 4 — Dynamic Linking: ELF .dynamic/DT_*, PLT-GOT, Symbol Versioning §16

Objectives

Parse ELF .dynamic (DT_*), needed libraries, soname, symbol/reloc pointers, PLT-GOT layout; parse GNU symbol versioning (.gnu.version*) so dynamic symbols resolve to their correct version.

Deliverable

binparse dynamic lists needed libs, soname, dyn entries (≈readelf -d).

Acceptance

DT_NEEDED list matches ldd/readelf -d on a corpus of 8 dynamically-linked ELF binaries (4 versioned, 4 unversioned), 0 mismatches; PLT-GOT mapping consistent with .rela.plt; binparse syms --versions output matches readelf -V (version strings + default/hidden flags) on all 4 versioned samples; absent versioning handled silently with no error.

Fixtures

conformance/elf/{dynamic_pie, needed_multi, versym_libc, verdef_default, verneed_multi}, conformance/malformed/{dt_strtab_oob, dynamic_no_null, versym_count_mismatch, verdef_aux_oob, verneed_cycle}.

Pitfalls
  • .dynamic not DT_NULL-terminated: bound scan to section size / page limit (I5); never assume termination.
  • DT_STRTAB is a vaddr, not a file offset (I4): must go through RvaMap::to_offset; using it raw produces a garbage pointer.
  • versym length ≠ dynsym count (I5/I7): validate 1:1 before joining; miscount causes an OOB index.
  • verdef/verneed aux offsets are relative to the entry start, not the section start — easy off-by-one.
  • High bit of versym = hidden flag: masking forgotten → wrong index → wrong version name.
  • VER_NDX_LOCAL (0) / VER_NDX_GLOBAL (1): special indices that do not map to verdef/verneed; treat as "no version".

⬜ Phase 5 — PE Imports / Exports / IAT / Delay-Imports §17

Objectives

Parse PE Import Directory (ILT/IAT, by-name/ordinal), Export Directory (EAT, forwarders), delay-imports.

Deliverable

binparse imports/exports output matches dumpbin /imports /exports field-for-field; forwarder entries labeled.

Acceptance

DLL+symbol lists match dumpbin /imports /exports on a corpus of 10 PE DLLs/EXEs; ordinal-vs-name discrimination correct; forwarder detection on known samples; differential pass; imports_n/exports_n metrics match dumpbin counts.

Fixtures

conformance/pe/{imports_byname, imports_ordinal, exports_fwd, delay_import}, conformance/malformed/{import_rva_oob, iat_cycle, export_name_oob}.

Pitfalls
  • All RVAs must go through RvaMap::to_offset (I4): reading an import descriptor field as a file offset (raw pointer arithmetic) is the most common PE parsing bug.
  • IMAGE_ORDINAL_FLAG (high bit of 64-bit thunk): masking forgotten → tries to treat an ordinal as a name RVA → OOB.
  • Bound imports (pre-resolved IAT): FirstThunk contains loader-patched addresses, not the original thunk; use OriginalFirstThunk (ILT) as the authoritative name source.
  • Forwarder string vs code RVA: a forwarder export has its RVA inside the export section range; comparing against [ExportDir.VirtualAddress, +Size) distinguishes them.
  • Delay import version: old-style delay imports use HMODULE* not RVAs; check the Attributes flag.

⬜ Phase 6 — Notes, Build-ID, Debug Locators (DWARF/CodeView offsets), Unwind Index §18

Objectives

ELF notes + GNU build-id; PE debug directory; locate (not parse) DWARF/CodeView sections + PDB path; ELF unwind index (.eh_frame_hdr) and PE exception table (.pdata/.xdata).

Deliverable

binparse notes/buildid/debug prints build-id, PDB path, debug-section inventory; binparse unwind <file> [<addr>] lists function ranges + unwind-record offsets.

Acceptance

Build-id matches file/readelf -n; PDB path matches dumpbin /headers; unwind function-range count matches .pdata entry count / .eh_frame_hdr fde_count; address lookup returns correct range on 5 spot checks vs llvm-objdump --unwind-info.

Fixtures

conformance/elf/{buildid_sha1, eh_frame_hdr_full}, conformance/pe/{codeview_pdb, pdata_x64}, conformance/malformed/{note_desc_oob, pdata_range_inverted, xdata_rva_oob, ehframe_trunc_fde}.

Pitfalls
  • Note 4-byte alignment: namesz and descsz are rounded up to 4-byte boundaries for the next entry; forgetting this produces misaligned reads on all subsequent notes.
  • CodeView RSDS vs older NB10 sig: some old binaries use NB10; check signature before assuming RSDS layout.
  • Debug directory with multiple entries: iterate all; don't stop at first.
  • .eh_frame is CFI bytecode — resist decoding here; only record FDE boundaries (Phase 6 scope discipline; full decode is in #335).
  • PE BeginAddr ≥ EndAddr (inverted range): reject entry + W.DEVIATION diag; do not include in unwind index.
  • Chained unwind (UNW_FLAG_CHAININFO): bounded follow with visited set (cycle guard, I5).
  • .eh_frame_hdr table_enc variants (pcrel/datarel/absptr): must apply the correct base address for each encoding.

⬜ Phase 7 — Unified Model, Queries, CLI Dump Parity, Header Round-Trip §19

Objectives

Finalize format-agnostic BinaryImage, query API (section,symbol_at,imports), full binparse dump, and header re-serialization (I8).

Deliverable

binparse dump <file> full report (all sections from phases 0–6) matching readelf -a / dumpbin /all; binparse reserialize <file> prints "OK" or byte-diff; mock #334 consumer test passes.

Acceptance
  • Header re-serialization byte-identical for all well-formed corpus binaries (I8; 0 roundtrip_mismatch events).
  • symbol_at(known_func_addr) returns correct symbol on 5 spot checks.
  • Mock #334 integration test: given a BinaryImage, resolve 3 known addresses to function names via symbol_at — all correct.
  • dump output stable across 10 runs of same binary (I3).
  • cargo public-api diff shows only intended public surface (ADR-022).
Fixtures

conformance/roundtrip/{elf64_hello, pe32p_dll, elf32_be}, conformance/{elf,pe}/dump_golden, conformance/api/mock_334_consumer.

Pitfalls
  • Lossy model drops raw reserved/padding fields needed for round-trip; keep a raw_ehdr: [u8; 64] copy in the model or record every field including reserved ones.
  • Ordering nondeterminism in dump (I3): avoid iterating a HashMap; use section/symbol index order.
  • ELF/PE flag unification mismap: ELF SHF_EXECINSTR ≠ PE MEM_EXECUTE semantically — choose unified flags that round-trip without loss for each format.
  • PE AddressOfEntryPoint is an RVA; e_entry in ELF is a vaddr — the unified entry field must be the absolute vaddr (after adding image base for PE).

⬜ Phase 8 — Hardening: Fuzzing, Miri, Bounded-Work, Malformed Corpus §20

Objectives

Make the parser unbreakable on hostile input: fuzz every entry, Miri-clean, enforce all count caps (I5/I11).

Deliverable

Green 24h fuzz (0 panics, 0 OOB, 0 UB), Miri-clean parse paths, all cap fixtures → Err not OOM, unsafe confined to mmap.

Acceptance
  • 0 panics / 0 ASAN OOB / 0 Miri UB across ≥ 1×10⁹ fuzz execs (total across all targets).
  • Every count_bomb / reloc_bomb / giant_strtab fixture → Err(CountCap) in < 1 ms (not OOM).
  • unsafe grep gate: exactly 1 site (mmap.rs) — CI blocks merge on any other.
  • Fuzz throughput ≥ 50k execs/s per target (M10).
Fixtures

fuzz/corpus/{seed_elf, seed_pe, seed_coff}, conformance/malformed/{count_bomb, reloc_bomb, cyclic_link, giant_strtab, nested_forwarder}.

Pitfalls
  • Vec::with_capacity(attacker_n) before the cap check → OOM crash treated as DoS; always cap before alloc.
  • Recursion on sh_link or forwarder chains → stack overflow on cyclic input; must be iterative with a visited set.
  • unsafe creeping in via refactor (I9): the grep gate must run on every PR, not just nightly.
  • Slow-unit timeouts (libFuzzer default 1200s): a hang looks like a green run but consumes cycles; set FUZZ_TIMEOUT=60 per exec unit.
  • Corpus license: only use system binaries and self-built compiler outputs; do not commit third-party DLLs with unclear license.

⬜ Phase 9 — Differential Conformance + Soak + Release §21

Objectives

Lock differential oracle (readelf/llvm-readobj/dumpbin) into CI; soak over a large real corpus; reproducible release.

Deliverable

Green CI across all jobs; soak report showing ≥ 99.9% parity + 0 crashes; signed crate + CLI release on crates.io + GitHub Releases; SBOM attached.

Acceptance
  • Differential parity ≥ 99.9% on a corpus of ≥ 10k real ELF + PE binaries (within documented allow-list deviations); differential_mismatch = 0 outside the allow-list.
  • Soak: 0 crashes, peak RSS ≤ 2× largest file, throughput ≥ 500 MB/s (M3).
  • Deterministic dump: running binparse dump twice on the same file produces byte-identical output (I3).
  • Soak wall-clock ≤ 10 min for 10k files on 8 parallel threads (M9).
Fixtures

conformance/differential/ (pre-captured oracle outputs for the CI corpus), conformance/soak/ (file list), conformance/allow_list.toml.

Pitfalls
  • Oracle version drift: readelf and llvm-readobj output format changes between versions; pin the oracle version in Docker and test before upgrading.
  • Locale/sort differences: readelf sorts symbols differently depending on LC_ALL; normalize to LC_ALL=C in the comparison script.
  • Benign deviations triggering false failures: maintain allow_list.toml; every new allowed deviation requires a separate review.
  • Corpus licensing: use only system binaries + self-built compiler outputs; document the corpus provenance in conformance/README.md.
  • Soak memory leak: a model holding references to a dropped buffer (lifetime violation) manifests as a use-after-free under Miri; catch in Phase 8, not here.

⬜ Phase 10 — Integrity, Overlap/Gap Analysis, Entropy & Anomaly Triage §22

Objectives

Produce a structural integrity + anomaly report for triage (packers, corruption, tampering): section overlaps/gaps, header inconsistencies, suspicious entropy, RWX sections, entry-point sanity. Report-only; never rejects a parseable file.

Deliverable

binparse triage <file> emits a ranked anomaly report (JSON + text) with rationale per flag; binparse triage --json for pipeline consumption.

Acceptance
  • Flags a known UPX-packed sample (high entropy in all sections, few sections, minimal import stub) with ≥ 2 anomaly flags; clean GCC compiler output → 0 critical flags; deterministic report across 10 runs (I3).
  • Entropy scan ≤ 150 ms for 64 MB file (M12).
  • triage is gated by --triage flag so base parse is not slowed (M2 holds).
Fixtures

conformance/triage/{upx_packed, overlay_appended, rwx_section, entry_in_data, clean_gcc, high_entropy_data}.

Pitfalls
  • Entropy false positives on compressed resources / legit crypto data → report as hint, never verdict; include rationale string.
  • Section overlap is sometimes legal (sections sharing virtual pages at alignment boundaries) → severity tiers (warn, not error).
  • Overlay misattributed: signed Windows installers append signatures after the last section; label as W.OVERLAY with note about AuthentiCode possibility.
  • Nondeterministic flag ordering (I3): use stable sort by (severity, file_offset, flag_code).

⬜ Phase 11 — Archives & Multi-Object (ar static libs, COFF objects, import libraries) §23

Objectives

Parse containers-of-objects: Unix ar archives (.a, !<arch>\n), Windows import/static libs (COFF archive), and standalone COFF/ELF relocatable objects — exposing member iteration over the same BinaryImage model.

Deliverable

binparse ar <lib.a> lists members + archive symbol index; binparse ar --member <n> parses one member as a BinaryImage.

Acceptance

Member list + symbol index match ar t / nm / dumpbin /linkermember on a corpus of 6 archives (3 GNU-format, 3 BSD/import-lib), 0 member-list mismatches; import libs resolve DLL+symbol name correctly on all import-lib samples; all member offsets within archive bounds (I1).

Fixtures

conformance/ar/{gnu_longnames, bsd_names, symdef, import_lib}, conformance/malformed/{ar_member_size_lie, bad_longname_ref, ar_member_oob}.

Pitfalls
  • Member 2-byte alignment: after each member, skip an extra byte if size is odd; missing this shifts all subsequent members by 1.
  • GNU vs BSD long names: /offset vs #1/N — confusing them produces garbage names in the other format.
  • Member offset must stay within archive (I1): a lying size field must not advance past EOF.
  • Short-import vs full COFF discrimination: check Sig1/Sig2 before treating as a full object.
  • Thin archives (!<thin>\n) reference external files by path — record as ThinRef, do not attempt to parse the external file.

⬜ Phase 12 — Public Library API, Owned/Streaming Wrappers, C-ABI Binding Seam §24

Objectives

Freeze the embeddable API the RE pipeline (#334/#335/#74/#76) builds on: borrowed BinaryImage<'a> + an OwnedImage (holds buffer/mmap), ergonomic queries, and a C-ABI seam for non-Rust consumers. Constraint: API is SemVer-stable (ADR-022) from here.

Deliverable

libbinparse.a crate + binparse.h; a C example program that opens a file and lists section names via the C ABI; Rust mock #334 integration test.

Acceptance
  • Rust mock #334 + C example both consume model correctly; cargo public-api diff shows no unintended public surface change; ABI smoke test (open+query+free) passes under ASAN across 1,000 open/query/free cycles with 0 leaks.
  • Doctests on every public type pass (≥ 8 doctests across BinaryImage/Section/Symbol/RvaMap, 0 failures).
  • OwnedImage drop + re-access under Miri: no UB across 100 construct/drop cycles.
  • FFI double-free guarded (returns BpError::AlreadyFreed) on 10/10 double-free attempts.
Fixtures

conformance/api/{borrowed_query, owned_lifetime, capi_roundtrip, ffi_double_free}, doctests on BinaryImage, Section, Symbol, RvaMap.

Pitfalls
  • Self-referential OwnedImage UB: naive struct { buf: Vec<u8>, img: BinaryImage<'self> } is illegal Rust; use ouroboros/yoke and run Miri — the lifetime fiction must be safe in practice.
  • Leaking &'a str views across FFI: the C boundary must receive a null-terminated copy or a length-prefixed copy, not a raw borrowed pointer into the Rust buffer.
  • Silent API breakage: a field reorder or added variant in a non-#[non_exhaustive] enum breaks callers; cargo public-api diff in CI catches this before merge.
  • FFI double-free: guard with a dropped/invalid flag; log BpError::AlreadyFreed to the consumer.
