In one paragraph

A small, correct, self-hosted, monolithic operating-system kernel for x86-64, written in Rust without the standard library, with C and assembly confined to the boot stub, the secondary-CPU trampoline and the context_switch/syscall_entry shims (§1). It boots from UEFI firmware (with a multiboot2 fallback for fast QEMU iteration) through 64-bit long mode to a user-space /sbin/init and an interactive shell; scheduler, memory manager, virtual filesystem, drivers and the system-call boundary live in one privileged ring-0 binary, and statically linked ELF64 programs reach it only through a numbered, versioned system-call ABI (§1). Its users are kernel engineers extending the syscall surface (§1). The defining property: it "optimizes for auditable correctness on a single trust domain, not for maximum throughput or multi-tenant isolation" (§4).

The problem, concretely

The blueprint's own worked example is a program calling write(1, "hello, world\n", 13) (§8.2). Between that line and the bytes appearing on serial, the CPU loads the kernel's entry point from model-specific registers, the entry stub swaps to per-CPU state and a kernel stack, the dispatcher indexes a table by syscall number, the handler copies 13 bytes out of user memory and writes them to file descriptor 1, and the exit stub returns with sysretq (§8.2). Being able to trace that path, naming every state transition, is the first thing the project says mastery looks like (§2).

Each step has a naive version that fails, and the blueprint names the failure:

  • A handler that uses a user pointer without copy_from_user "is a vulnerability, not a bug", because every argument is attacker-controlled until validated (§33 MM6).
  • An entry stub that touches per-CPU data before re-establishing it hits swapgs ordering bugs that corrupt per-CPU state (§33 MM3).
  • Lazily batching page-table writes across a TLB-flush boundary causes stale-mapping races (§33 MM2).
  • "Optimizing" fork by copying memory eagerly destroys the entire benefit of copy-on-write (§33 MM5).
  • Putting scheduling decisions inside the context-switch path bloats the fast path (§33 MM1).
  • Adding SMP to an unproven single-CPU base makes bugs multiply combinatorially, which is why SMP is gated behind single-CPU conformance passing in full (P1).

How it works, end to end

The blueprint's canonical diagram places user space above a single syscall crossing, with the scheduler fed by traps and timers, and memory, filesystem and driver subsystems beneath it (§3):

 user space: /sbin/init  /bin/sh  static ELF64 programs      — untrusted
     │ syscall: rax = number, rdi/rsi/rdx/r10/r8/r9 = args
 kernel (ring 0, Rust #![no_std]):
   syscall table │ IDT / trap │ LAPIC / timer │ per-CPU data (gs:base)
   scheduler: run-queues, preemption, wait queues — the only mutator of thread state
   address space (mm, VMAR) │ VFS (superblock / inode / dentry / file) │ driver core (IRQ routing, PCI, MMIO)
   physical frame allocator + kernel heap │ ramfs, ext2 (read-only) │ uart, kbd, vga, fb, rtc, pci, virtio-blk
 firmware / bootloader: UEFI (primary) or multiboot2 → our stub: long-mode entry, GDT, paging, hand-off to kmain()

Boot. Firmware and crates/bootloader sit outside the kernel's trust domain and hand off exactly once, never re-entered (§3); the boot path is "a monotonically decreasing trust handoff" (§33 MM8). Before kmain() the stub sets up long mode, the GDT and paging (§3). The kernel then uses a higher-half address space (ADR-06), the per-CPU LAPIC interrupt controller and timer (ADR-10, ADR-11), and a physical frame allocator plus kernel heap in mm (§14).

One write through the boxes. The user program loads rax=1, rdi=1, rsi=&buf, rdx=13 and executes syscall (§8.2 step 1). The syscall_entry.S stub runs swapgs, saves the user stack pointer and loads the kernel stack from per-CPU data at gs:base (§8.2 step 3, §18.2). Dispatch reads rax, indexes syscall::table and calls handlers::fs::write (§8.2 step 4). The handler calls copy_from_user(buf, 13) and writes to fd 1's inode (§8.2 step 5) through the fs::vfs layer, which resolves paths component by component (§8.5) over ramfs and a read-only ext2 image served by virtio_blk in drivers (ADR-17, ADR-18). The handler returns Ok(13), the exit stub reverses entry and runs sysretq, and the user sees rax == 13 (§8.2 steps 6–8).

Around that path. The sched scheduler owns run-queues and wait-queues and is the only mutator of thread state (§3); it runs per-CPU MLFQ-lite run-queues (ADR-12) and preempts on the timer tick, 1 kHz after a 100 Hz warm-up (§4). The IDT / trap box turns hardware events into typed Rust calls (§3). The address space (mm, VMAR) box owns each process's page tables and virtual memory regions (§3). Pipes and POSIX-shaped signals arrive in ipc (§21), and Phase 10 brings up the other CPUs with per-CPU data and TLB-shootdown IPIs (§22). Fixtures run under a harness that drives QEMU, exits through isa-debug-exit and scrapes serial output (ADR-21).

The core ideas

A thread is a saved instruction pointer plus a stack (§8.1, I5, MM1)

The scheduler is "a function that picks which saved IP runs next" (§33 MM1). Five rows of the thread state machine (§8.1):

From Event To Guard
New first enqueue Runnable run-queue accepts (I5)
Runnable scheduler picks it Running CPU available
Running timer tick, quantum expired Runnable preempt_count == 0 (I3)
Running blocking syscall / wait Blocked(reason) preempt_count == 0 (I3)
Zombie wait() by parent (freed) parent observes exit code

A thread sits on exactly one run-queue or wait-queue, never both and never neither, except while Running (I5). Context-switch cost is dominated by register save/restore and cache effects, so the switch path holds no decisions; they happen in pick_next() before the switch (§16.7). The pick must be O(1): a naive scan of 4,096 threads at about 5 ns each costs about 20 µs, far above the < 3 µs switch target, so each per-CPU run-queue keeps a bitmap of its non-empty priority bands (§35 item 10, §16.7). Phase 4 uses four bands, round-robin within a band, promotion when a thread blocks on I/O and demotion when it uses up its quantum (§16.2).

The page table must always be truthful (§8.3, I9, I12, MM2)

A virtual address is cut into fields (§8.3): bits 47–39 index the top table (PML4), 38–30 the PDPT, 29–21 the PD, 20–12 the PT, and bits 11–0 are the offset into the final frame. A walk goes PML4 → PDPT → PD → PT → frame + offset, and an entry with PRESENT clear ends the walk with a page fault (§8.3). Any entry the kernel writes must be immediately valid or explicitly not present; there is no tolerated half-written state (§33 MM2). Two invariants follow: no entry maps a freed frame (I9), and TLB entries are flushed on every unmap before the frame returns to the allocator (I12). Mapping 1 GiB takes 2 MiB of leaf page tables, about 2.008 MiB with the upper levels (§35 item 2), and a working set beyond about 6 MiB outruns a 1,536-entry L2 TLB and pays walk costs regularly (§35 item 3).

Copy-on-write moves fork's cost to first write (§17, MM5)

fork clones the parent's virtual memory regions, marks every writable user page read-only in both address spaces, reference-counts the shared frames, and gives a private copy on the first write (§17.2). That turns fork "from an O(memory) into an O(page-table) operation", moving cost from fork time to first-write time (§33 MM5). Fork-heavy pipelines are cheap; a fork followed by writing everything defeats the optimization (§33 MM5). The Phase 5 isolation proof is a write to a copy-on-write page that must be invisible in the other address space (§17.4). execve then parses the ELF64 header, maps each PT_LOAD segment with its R/W/X flags, zeroes the tail where memsz > filesz, builds a user stack with argv/envp/auxv, and iretqs to ring 3 (§8.4).

Every syscall argument is attacker-controlled (§8.2, I2, T1, T10, MM6)

A syscall is "a value-passing RPC to the most trusted process on the machine" (§33 MM6). The register layout follows System V AMD64 (§8.2, ADR-15): rax carries the number in and an i64 result out, negative meaning -errno; r10 replaces rcx because syscall clobbers rcx and r11 (§8.2). The blueprint is not consistent on argument count: §8.2 labels rdi, rsi, rdx, r10, r8, r9 as "args 1–5" and §3's diagram labels all six as arguments, while §18.2 dispatches "five usize args" in rdi rsi rdx r10 r8. User memory is copied once and then used, never re-read, which prevents time-of-check-to-time-of-use races (TOCTOU) by design (T10, §18.9). An entry without the USER bit is unreachable from ring 3 (I2), and a syscall given an unmapped pointer returns -EFAULT and never panics (§18.4), with no state change (T1). New syscalls append and none is ever renumbered (I7, P14).

Interrupts are forced calls from an adversarial caller (§15, §18, I3, I13, MM3)

On entry, rsp, cr3 and gs cannot be trusted until re-established, so every entry stub re-establishes per-CPU state before touching it (§33 MM3). The 256-entry IDT is laid out (§15.2, §22.2):

Vectors Use
0–31 CPU exceptions only (I13)
32–47 legacy PIC range, masked
48–255 IOAPIC routing and IPIs
0xFE reschedule IPI
0xFD TLB-shootdown IPI

Each CPU's TSS holds three dedicated interrupt stacks for double fault, NMI and machine check (§15.2), so a deliberate double fault runs on its own stack and prints a full trace before halting (§15.4). A thread may sleep only with its preemption count at zero, because sleeping while holding a spinlock deadlocks the CPU (I3); a spinlock around I/O deadlocks waiting for a scheduler that cannot run (§33 MM7). Locks are taken in the total order of docs/lock-order.md, checked in debug builds (I14).

One trust domain, by choice (§3, MM4, Alt-1)

Drivers implement the Driver trait and do not reach past it (P6), but that bounds blast radius "for correctness review, not for security": "a compromised driver still owns ring 0" (§33 MM4). The blueprint accepts this deliberately: pushing the VFS and drivers into user space would remove exactly the material this project exists to teach (§37 Alt-1). Related gaps are recorded rather than closed: device DMA is trusted under QEMU with the IOMMU deferred, an accepted and documented risk (T4); secure boot is deferred (T5), a gap MM8 calls deliberately accepted (§33 MM8); and the KPTI-equivalent speculative-execution mitigation is deferred (T2).

The trade-offs — where engineers disagree

Language: Rust nightly, no standard library (ADR-01)

Chosen: Rust nightly with #![no_std], for memory safety in privileged code (ADR-01, P2); §1 adds that it removes use-after-free, double-free and out-of-bounds-write classes without runtime cost. Rejected: C, C++, Zig. When the rejected choice is right: a one-off research kernel with no safety budget at all, where C avoids the toolchain tax (ADR-01).

Address space: higher-half kernel (ADR-06)

Chosen: a higher-half kernel at 0xFFFF_FFFF_8000_0000+, standard for x86-64, matching Linux/xv6 convention and supporting per-process fork and copy-on-write (ADR-06). Rejected: identity-mapped, lower-half, or a Theseus-shaped single address space. When the rejected choice is right: a single-address-space model wins for a language-safe, no-fork embedded target, as in Theseus (ADR-06).

Scheduler: per-CPU run-queues with MLFQ-lite (ADR-12)

Chosen: per-CPU run-queues, because they avoid cache-line bouncing past 8 cores (Boyd-Wickizer 2010), with an MLFQ-lite policy that suffices for Phase 0 (ADR-12). Rejected: global round-robin, a CFS clone. When the rejected choice is right: a global run-queue wins at two cores or fewer, where balancing costs more than contention (ADR-12).

Locking: spinlocks first, sleeping mutexes from Phase 5 (ADR-13)

Chosen: Spinlock with an IRQ-safe variant, and a sleeping Mutex from Phase 5; spinlocks are correct for short critical sections and sleeping locks need the scheduler online (ADR-13). Rejected: parking_lot, a kernel RWLock everywhere. When the rejected choice is right: a sleeping lock wins whenever the critical section may block on I/O (ADR-13).

Syscall path: syscall/sysret (ADR-14)

Chosen: syscall/sysret via MSR_LSTAR, the modern path on AMD and Intel x86-64 (ADR-14). Rejected: int 0x80, sysenter. When the rejected choice is right: int 0x80 wins for a 32-bit-compatibility shim, which is irrelevant here (ADR-14).

VFS shape: Linux-style objects (ADR-16)

Chosen: superblock/inode/dentry/file, because the Linux shape is well understood and namespaces are deferred complexity (ADR-16). Rejected: Plan-9-shaped namespaces from day one. When the rejected choice is right: a container-first design (ADR-16).

First on-disk filesystem: ext2, read-only (ADR-17)

Chosen: ext2, read-only: a smaller specification surface, easier to fuzz, well documented, and close to the model xv6 uses (ADR-17). Rejected: FAT32, ext4, a custom format. When the rejected choice is right: FAT32 wins when interoperating with a Windows or UEFI system-partition writer is the priority (ADR-17).

Roads not taken (§37)

A microkernel, seL4-shaped, wins for security- or safety-critical deployments needing provable blast-radius bounds per component (avionics, medical, verified enclaves); it is rejected because it would remove the monolithic material the project teaches, and the IPC-marshalling cost would roughly double the phase count for no scope gain (§37 Alt-1).

An exokernel, Aegis-shaped, wins for research systems needing per-application control of resource policy; it is rejected because one opinionated VM/scheduler abstraction is what lets the project ship one syscall ABI and one conformance suite (§37 Alt-2).

A single-address-space unikernel, Theseus-shaped, wins for embedded or cloud targets that compile one trusted application against kernel internals; it is rejected because it cannot support the fork/copy-on-write model of ADR-06 and breaks I1 and I2 (§37 Alt-3).

A multikernel, Barrelfish-shaped, wins at very high or heterogeneous core counts where shared-memory coordination is the bottleneck, which §32 puts at about 32 CPUs for this design; it is rejected because the reference rig is single-socket with at most 128 logical CPUs, where per-CPU run-queues are simpler (§37 Alt-4, §32).

What must never be false

Each line gives the rule, then how the system notices (§7 Detection column).

  • I1 — cr3 matches the current thread's address space in user mode; a debug assert on switch.
  • I2 — a page-table entry without USER is unreachable from ring 3; fixture mm/02-mprotect-rw-to-r.
  • I3 — the preemption count is zero before any voluntary sleep; a debug assert in block().
  • I4 — IRQs are disabled around unlocked per-CPU mutation; code review plus Miri on a host subset.
  • I5 — a thread is on exactly one run-queue or wait-queue, except Running; fixture sched/02-wait-queue-wakeup.
  • I6 — descriptor entries are refcounted and release the inode at zero; fixture vfs/03-bad-fd-ebadf.
  • I7 — syscall numbers are never renumbered once shipped; the ADR-14 review gate on every new syscall.
  • I8 — every unsafe block carries a SAFETY comment citing the Nomicon; a CI diff on the unsafe count.
  • I9 — no page-table entry maps a freed frame; fixture mm/00-frame-alloc-roundtrip.
  • I10 — the heap never returns memory misaligned to the Layout; the allocator conformance suite.
  • I11 — a zombie keeps its exit code until reaped by wait(); fixture proc/00-fork-exec-exit.
  • I12 — the TLB is flushed on every unmap before the frame returns; fixture mm/01-mmap-anon-fault-in.
  • I13 — vectors 0–31 are reserved for CPU exceptions; a boot-time assert.
  • I14 — locks follow the total order in docs/lock-order.md; the order checker panics in debug builds.

What breaks in production

  • FM-1 — triple fault at boot. QEMU resets silently with no serial output; the cause is a bad GDT/IDT load or wrong code-model relocations; the boot-latency fixture times out; there is no automatic recovery, so you attach -d int,cpu_reset and bisect the boot stub (FM-1).
  • FM-2 — double-fault loop. Repeated #DF entries appear in the trace ring because no IST stack was set for #DF/NMI/MCE; the 02-double-fault-recovery fixture catches it; the kernel halts, and the fix is verifying that TSS.IST1 maps a guarded stack (FM-2).
  • FM-3 — page-table corruption. Sporadic page faults at an untracked physical address, from a TLB not flushed after unmap or a double-freed frame; the mm/01 regression and the I9 debug assert detect it; the kernel panics with cr2/cr3 dumped, and you replay under -icount and diff the frame-allocator log (FM-3).
  • FM-4 — scheduler starvation. A thread gets zero timeslices for more than 5 s because the MLFQ promote/demote thresholds are miscalibrated; the sched/01 fixture and the sched_wait_ns_p99 histogram show it; ageing promotion recovers, and the band thresholds are retuned (FM-4).
  • FM-5 — deadlock between two spinlocks. A CPU spins forever in lock acquire after the lock order was violated (I14); debug builds panic in the order checker, and in release a watchdog NMI dumps every CPU's backtrace before halting (FM-5).
  • FM-7 — malformed image panics the mounter. An unchecked length field in an archive or superblock; the vfs/00 malformed variant and the fuzz corpus detect it; after the fix the parser returns FsError::Malformed, and the crashing input becomes a regression fixture (FM-7, §8.6).
  • FM-8 — virtio queue desync. Block reads return stale or zeroed data because a memory barrier is missing between the descriptor write and the doorbell; the driver/02 fixture catches it, with no automatic recovery until the barrier is inserted (FM-8).
  • FM-10 — TLB-shootdown hang. The sending CPU waits forever on the acknowledgement counter because a target CPU had interrupts disabled during the window; the smp/02 fixture and a bounded timeout detect it, and the timeout triggers a diagnostic NMI (FM-10).

Threats a reader should know (§25): T1 privilege escalation through crafted syscall arguments, answered by copy_from_user and range checks; T6 memory disclosure through an uninitialised buffer, answered by zero-init or bounded copy_to_user; T8 denial of service by fork bombs, descriptor exhaustion or busy loops, answered by per-process rlimit caps and fair MLFQ scheduling; T10 TOCTOU on user pointers, answered by copy-once-then-use; T4 a device writing outside its DMA buffer, an accepted and documented risk until the IOMMU lands.

All latency and boot rows are design targets, measured nightly by the benchmarks/ rig under both QEMU/TCG and QEMU/KVM, and a regression of more than 10% against the trailing 7-day median fails the job (§31). The memory and overhead rows are the blueprint's own arithmetic (§35).

Three places where the blueprint disagrees with itself, stated both ways:

  • §35 item 1 assumes a 10 ms default timeslice and says it is "derived from §4's tick", but §4 lists the tick as 1 kHz with a 100 Hz warm-up.
  • §35 item 7 counts "VFS mount + first read ~2 ms" inside its 25 ms boot model, while §35 item 12 adds ~5 ms of mount and ~5 ms of first read on top of the 50 ms boot ceiling.
  • §31 gates M1/M2 ("boot to init: ready") at Phase 1, and §13.4 cites M1/M2 for a banner within 250 ms on both boot paths, but init: ready is first printed in Phase 5 (§17.3).

How it compares

  • Linux is the monolithic baseline whose shape this design follows most closely. Its loadable kernel modules win whenever an operator must patch a running fleet without a reboot, a feature this design defers (§34).
  • seL4 pushes every driver and policy into user space behind capability-checked IPC and is formally verified. That wins whenever a single component's compromise must be provably bounded, as in avionics or security-critical enclaves (§34).
  • xv6 is the teaching kernel this design's shape and phase order descend from, and it skips copy-on-write entirely. That is right when clarity for a one-semester course outweighs performance; this production-shaped design reinstates copy-on-write (§34).
  • Zircon makes every kernel object a capability-addressed handle and runs drivers in user-space driver hosts. That wins when a product needs update-in-place driver isolation without seL4's formal-verification investment (§34).
  • Windows NT splits a hybrid executive and HAL, with some drivers in kernel mode and others in user mode. That wins when decades of third-party driver compatibility is the priority (§34).

Questions to test yourself

  1. Why does copy-on-write make fork() asymptotically cheaper, and under what workload does that advantage invert? — Hint: §17 and mental model MM5.
  2. Why must swapgs execute before any per-CPU access in the syscall entry stub, and what corrupts if the ordering is reversed? — Hint: the entry-stub steps in §18.2 and MM3.
  3. Name the two invariants that together prevent a TOCTOU attack on a user-supplied pointer, and the mechanism that enforces both. — Hint: I2, T10 and the failure analysis in §18.9.
  4. Why is a spinlock wrong to hold across a blocking I/O call, and which invariant would be violated if one were? — Hint: I3, ADR-13 and MM7.
  5. What is the concrete numeric relationship between the scheduler tick, the context-switch cost, and the maximum thread count before scheduling overhead exceeds 1%? — Hint: §35 item 1 and the §4 tick and context-switch rows.

If you only remember three things

A thread is a saved instruction pointer and a stack, the scheduler picks which one runs next, and that pick has to be O(1) because a scan of every thread would cost far more than the whole context-switch budget. The page table is a hardware-walked tree the kernel must keep truthful at every instant, so unmaps flush the TLB before a frame is reused and no entry ever points at freed memory. Every system-call argument and every interrupt comes from an adversary, so user memory is copied once, per-CPU state is re-established before use, and in a monolithic kernel any driver bug is a kernel bug.

Words used here

  • Ring 0 / ring 3 — the privileged kernel mode and the unprivileged user mode.
  • Long mode — the 64-bit operating mode the boot stub enters before handing off.
  • Page table / PTE / TLB — the four-level translation tree, one entry in it, and the CPU's cache of translations.
  • Frame — one fixed-size unit of physical memory handed out by the allocator.
  • Copy-on-write — sharing pages read-only after fork and copying one only when it is written.
  • ELF — the executable format the loader maps segment by segment.
  • Syscall table — the numbered, append-only dispatch table for system calls.
  • swapgs — the instruction that exchanges gs:base with the kernel's saved per-CPU base at entry.
  • TOCTOU — a time-of-check-to-time-of-use race on memory the caller can change mid-call.
  • Spinlock / preemption count — a short busy-wait lock, and the counter that forbids sleeping while one is held.
  • Run-queue / wait-queue — where a thread sits while runnable, or while blocked on an event.
  • IDT / IST — the interrupt descriptor table and the dedicated stacks for faults like double faults.
  • LAPIC / IPI — the per-CPU interrupt controller and an interrupt sent from one CPU to another.
  • TLB shootdown — telling other CPUs to drop a stale translation after an unmap.
  • VFS / inode / dentry — the filesystem-agnostic layer, its file objects, and its name-to-inode bindings.
