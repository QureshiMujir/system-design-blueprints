28 — OS Kernel

Project Number: 28

Project Name: OS Kernel

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal & Scope

Build a small, correct, self-hosted, monolithic operating-system kernel for x86_64 (aarch64 is a stretch target, formally deferred — see §38), written in Rust (#![no_std]) with C and NASM-syntax assembly restricted to the boot stub, the AP trampoline, and the context_switch/syscall_entry shims, that boots from UEFI firmware (multiboot2 fallback for fast QEMU iteration) through long-mode entry to a user-space /sbin/init and an interactive shell, verified under QEMU (q35, -cpu max) in CI and on one real UEFI x86_64 board at the Phase-12 hardware milestone. Scheduler, memory manager, VFS, drivers, and the syscall boundary live in one privileged ring-0 binary; user programs are statically linked ELF64 executables that talk to the kernel only through a numbered, versioned syscall/sysret ABI (§18).

Phase-0 deliverable (numbered modules):

  1. crates/kernel — the kernel binary (boot, arch, mm, sched, sync, trap, syscall, proc, ipc, fs, drivers, log).
  2. crates/kernel-abi — shared syscall/ABI types for kernel and user-space.
  3. crates/bootloader — UEFI stub + multiboot2 fallback.
  4. crates/userspace/libc-stub — minimal user-space runtime.
  5. crates/userspace/init, sh, coreutils — PID 1, shell, core utilities.
  6. conformance/runner — the QEMU-driving conformance harness.

System boundaries.

  • Provides: preemptive process/thread scheduling; virtual memory with demand paging and copy-on-write; a syscall ABI; a VFS with ramfs + read-only ext2; a character/ block driver core; pipes and POSIX-shaped signals; single- and multi-CPU execution.
  • Delegates: TCP/IP (a future project, final_ranking.md rank 33); cryptography (vendored, audited crate only — never hand-rolled, ADR-25); device firmware blobs; GUI toolkits.
  • Does NOT provide: networking beyond a loopback stub; a dynamic loader / shared libraries; containers or namespaces; real-time scheduling guarantees; NUMA-aware placement; a journaling filesystem.

Non-goals: POSIX conformance beyond the ABI in §8; architecture parity at Phase 0 (aarch64 is PhaseDeferred("§9"), tracked against ADR-02); a GUI; nested virtualization.

Deployment model: one bootable disk image (ESP + kernel + initramfs) run under QEMU/KVM in CI, and on one real UEFI x86_64 board for the Phase-12 hardware milestone (M-table, §31).

Target users/operators: kernel engineers extending the syscall surface; the conformance runner is the operator-facing verification tool; docs/runbooks/ is written for an on-call engineer debugging a triple-fault from a serial log.

Later phases unlock: SMP (§22), a POSIX-shaped user-space (§23), hardening and fuzzing (§24); downstream projects — Memory Allocator (rank 29), File System (rank 34), Container Runtime (rank 35), TCP/IP Stack (rank 33) — all reuse the Mapper trait, Driver trait, and syscall ABI locked here.

Recommended language: Rust 1.84+, nightly channel, #![no_std]. Rationale: memory safety removes UAF/double-free/OOB-write CVE classes in privileged code without runtime cost (P2); core/alloc compose cleanly under no_std; the reference corpus (Redox, Theseus, Zephyr, blog_os) is Rust- or C-first with mature no_std idiom to draw from. Rejected: pure C — no safety net, and the CVE history of Linux/BSD memory-safety bugs is the exact class Rust removes; Zig — the no_std kernel ecosystem is too immature to cite a stable reference implementation; C++ — RAII gains do not offset exception-model and ABI complexity inside a no_std, no-unwind kernel.

Prerequisites: x86_64 long mode, paging, the interrupt/exception model, MSRs, the local APIC, syscall/sysret; linker scripts and ELF object layout; Rust without std (core, alloc, Pin, raw pointers, Send/Sync, atomics, the Rust memory model); QEMU + gdb-multiarch debugging of a crashed kernel; enough assembly to read a 16-instruction trampoline.

Estimated timeline: Phase 0 in 2 weeks; the full system (Phases 0–12) in 7–9 months at one engineer full-time.

Deferred features (full table with anchors, building phase, and un-defer trigger: §38 Deferred Features Register): networking beyond the loopback stub PhaseDeferred("§18.8"); the aarch64 port PhaseDeferred("§9"); the AHCI driver PhaseDeferred("§20.6"); ext4 PhaseDeferred("§19.1"); dynamic linking / shared libraries PhaseDeferred("§23.1"); live kernel-module update PhaseDeferred("§20.1"); a USB stack PhaseDeferred("§20.6"); GPU/framebuffer acceleration PhaseDeferred("§20.2"); IOMMU/DMA isolation PhaseDeferred("§25"); secure-boot signing PhaseDeferred("§25").

2. Why Build This

  • Dissolves the membrane between "the language" and "the machine": after this project, a CPU instruction stream and an operating system are no longer different categories of thing to you.
  • Teaches exactly what a page fault is, when it is recoverable, and who decides (§8.3, §15).
  • Teaches how a context switch is implemented — what state it saves, what it does not, and why the omission is safe (§16, MM1).
  • Teaches how read(2) becomes a VFS call becomes a block-device read becomes a DMA-completion interrupt (§8, §19, §20).
  • Teaches how an SMP system enters a critical section without a hypervisor's help (§22).
  • Teaches why every modern kernel has a per-CPU data area, a deferred-work mechanism, and a way to run code with interrupts disabled but preemption permitted (§22, P3).
  • Teaches why memory safety is non-negotiable below the syscall line (P2, T7).
  • Cross-links: shares the Mapper/frame-allocator design with the Memory Allocator project (rank 29); shares the VFS shape with the File System project (rank 34); the syscall ABI is the substrate the Container Runtime (rank 35) namespaces later.
  • Calibration value: every subsequent systems project in the portfolio (allocator, file system, scheduler-as-a-library, container runtime, JIT, debugger, profiler) reuses a decision locked here — this is the portfolio's longest-lived asset.

What Mastery Looks Like. After building this, an engineer can:

  1. Trace a write(2) call from user-space register load through sysret return, naming every state transition (Phase 6, §18).
  2. Explain, with numbers, why copy-on-write turns fork() from an O(memory) into an O(page-table) operation (Phase 5, §17, MM5).
  3. Diagnose a triple fault from a serial/QEMU trace alone, without a debugger attached (Phase 1, §13, FM1).
  4. Defend the choice of per-CPU run-queues over a global run-queue with a cache-line- contention argument, citing the source (Phase 10, §22, Boyd-Wickizer 2010).
  5. Explain why a spinlock and a sleeping mutex are not interchangeable and name the deadlock class each one prevents or invites (Phase 10, §22, ADR-13).
  6. Redesign the system as a microkernel, an exokernel, or a multikernel and state exactly which invariant/ADR would have to change (§37).
  7. Read an unfamiliar production kernel's arch/ tree and map every file to a phase in this plan within an hour.

This diagram is canonical; every later section stays consistent with it. Box-by-box:

  • User-space. /sbin/init (PID 1), /bin/sh, and static ELF64 programs. Trust boundary: everything here is untrusted input to the kernel (T1). Concurrency boundary: one address space per process, N threads per process (§17).
  • syscall table / trap. The only crossing point of the trust boundary. Persistence boundary: none — stateless dispatch (§18).
  • IDT / trap. CPU-exception and IRQ entry; converts hardware events into typed Rust calls (§15).
  • LAPIC / timer. Per-CPU interrupt controller and preemption clock (§15, §22).
  • per-CPU data. gs:base-addressed; concurrency boundary for anything not behind an explicit lock (P3, §22).
  • scheduler. Owns run-queues and wait-queues; the only mutator of ThreadState (§8.1, §16).
  • address space (mm, VMAR). Owns page tables and virtual memory regions per process; persistence boundary: none, volatile (§14, §17).
  • VFS layer. Filesystem-agnostic dispatch; queue/channel boundary: none, synchronous calls only in Phase 0–12 (§19).
  • driver core. Owns IRQ routing and device state; isolation boundary via the Driver trait (P6, §20).
  • physical frame allocator + kernel heap. Owns all RAM not yet handed to a VMAR or a kernel object (§14).
  • ramfs, ext2 (read-only). Persistence boundary: ramfs is volatile (image reload), ext2 is read-only backing store (§19).
  • drivers (uart, kbd, vga, fb, rtc, pci, virtio-blk). External-interface boundary: MMIO/PIO to real or virtual hardware (§20).
  • firmware / bootloader. Outside the kernel's trust domain until hash-verified (T5); hands off exactly once, never re-entered (§13).

6. Design Principles

  1. Boring first. A correct, slow, single-CPU, cooperative kernel outranks a half-finished SMP kernel. Tradeoff: slower early milestones. Operational implication: SMP (§22) is gated behind single-CPU conformance passing in full. Violating it: bugs multiply combinatorially once concurrency is added on an unproven base.
  2. The unsafe budget is finite. Every unsafe block carries a one-line SAFETY comment citing the Rust Nomicon section it relies on (I8). Tradeoff: verbosity. Operational implication: cargo geiger inventories the surface every PR (§30). Violating it: unreviewable memory-safety holes re-enter the exact class Rust was chosen to remove (T7).
  3. No hidden global state. Cross-CPU data lives in static cells with explicit locking; per-CPU data lives behind gs:base through a typed wrapper. Tradeoff: more boilerplate accessors. Operational implication: every global is greppable and lock-order-checkable (I14). Violating it: silent data races (T9).
  4. The kernel is a service, not a library. User-space talks to the kernel only through documented syscall numbers (I7); the internal API is not stable ABI. Tradeoff: internal refactors are free, external ones are not. Violating it: an ABI break silently corrupts every statically linked user binary.
  5. One source of truth per fact. The page table is truth for virtual memory; the run-queue is truth for runnable threads; the VFS is truth for paths (I1, I5). Tradeoff: no caches without explicit invalidation. Violating it: two subsystems disagree about the same fact and the disagreement is undebuggable.
  6. Drivers are isolated. A driver implements the Driver trait (§11.9) and does not reach past it into kernel internals. Tradeoff: some drivers need extra plumbing to stay inside the trait. Violating it: a single driver bug corrupts unrelated kernel state (MM4).
  7. Fast path is short, slow path is correct. The syscall fast path (no scheduling, no I/O) is < 200 instructions (§4); the slow path may take as long as needed but must be re-entrant. Tradeoff: two code paths to maintain per syscall. Violating it: tail latency explodes under load (M3/M4).
  8. Panics print, then halt. A kernel panic emits a structured trace (frame walk, registers, cr2, current task) to serial, then cli; hlt (P8). Tradeoff: no automatic recovery from a kernel bug. Violating it: silent corruption propagates past the point where it was detectable.
  9. Reproducibility. Every kernel image is reproducible from a pinned toolchain and bootloader; CI verifies byte-identical rebuilds (§30). Violating it: "works on my machine" bugs become undebuggable across CI/hardware.
  10. Readable assembly. Assembly lives in *.S files, commented, preferred over inline asm! that buries register constraints. Violating it: an entry-stub bug becomes unreviewable (T2, MM3).
  11. Explicit backpressure over silent drops. Bounded queues (pipe ring, run-queue) block the producer rather than dropping data (ADR-31). Tradeoff: a slow consumer stalls a fast producer. Violating it: unbounded memory growth under load — strictly worse than a stall (T8).
  12. Every lock has a documented order. docs/lock-order.md defines a total order; a debug-only checker asserts it (I14). Violating it: deadlock (FM5).
  13. Telemetry is not optional. Every subsystem emits at least one counter or histogram to the trace ring (§27). Tradeoff: small per-event overhead. Violating it: production failures are undiagnosable (FM-class blast-radius unknown).
  14. Version the ABI, never break it silently. New syscalls append; none are ever renumbered (I7, ADR-14). Violating it: a recompiled user binary silently invokes the wrong syscall.

8 user observes rax == 13

8.3 Page-Table Walk (x86_64, 4-level)

VirtAddr bits:  63........48 47....39 38....30 29....21 20....12 11.....0
                sign-ext     PML4 idx PDPT idx PD idx    PT idx   offset
PML4[idx] -> PDPT[idx] -> PD[idx] -> PT[idx] -> Frame + offset

Each level's entry is a PageTableEntry (§11.3); a PRESENT-clear entry ends the walk with a page fault (§8.7).

8.4 ELF64 Loading Sequence (execve, §17.4)

  1. Parse ELF64 header; verify magic, class=64, machine=x86-64.
  2. Iterate PT_LOAD segments; for each, map pages with the segment's R/W/X flags.
  3. Zero the tail where memsz > filesz (BSS).
  4. Allocate a user stack; push argv, envp, auxv per the SysV ABI supplement.
  5. Set entry rip from the ELF header; iretq to ring 3.

8.5 VFS Path Grammar (EBNF)

path       = [ "/" ] , component , { "/" , component } ;
component  = 1*63( unreserved_char ) ;
unreserved_char = ? any byte except 0x00 and "/" ? ;

Resolution is iterative left-to-right lookup() on each component starting from either the root inode or cwd (relative path); ../. are ordinary components resolved by the filesystem, not the VFS layer (matches ext2/ramfs convention).

8.6 Malformed-Input Example

cpio newc header with a truncated namesize field: the parser reads past the declared archive length. Fix: bounds-check namesize/filesize against the remaining archive length before any slice indexing; on violation return FsError::Malformed (never panic) — exercised by vfs/00-cpio-roundtrip's malformed variant and by the cargo-fuzz corpus (§24.2, FM7).

11.1 Addresses, Frames, Pages

#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]

#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
#[repr(transparent)]

impl VirtAddr {
    pub const fn new(addr: u64) -> Self;      // panics if non-canonical (I2)
    pub const fn p4_index(self) -> u16;
    pub const fn p3_index(self) -> u16;
    pub const fn p2_index(self) -> u16;
    pub const fn p1_index(self) -> u16;
}

#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Frame { pub start: PhysAddr }        // owned exclusively by mm::frame

impl Frame {
    pub const SIZE: u64 = 4096;
    pub fn containing(addr: PhysAddr) -> Self;
}

#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct Page { pub start: VirtAddr }

impl Page {
    pub const SIZE: u64 = 4096;
    pub fn containing(addr: VirtAddr) -> Self;
}

Ownership: Frame/Page are Copy value types, no aliasing hazard. Mutation: immutable once constructed. Concurrency: Send/Sync (plain integers). Persistence: none. Serialization: #[repr(transparent)] matches the raw u64 on the wire (§8.3). Compatibility: stable since Phase 0, referenced by every mm type.

  1. UEFI service pointers are invalidated by ExitBootServices — never dereference them after exit (T5 adjacent).
  2. The multiboot2 header must be 8-byte aligned in the first 32 KiB; enforce in the linker script, not by convention.
  3. Forgetting to load a TSS before the first iretq crashes on the first exception — Phase 3 needs it; assert it is loaded at the end of Phase 1.
  4. Two boot paths diverging in GDT/PML4 contents is a silent, hard-to-reproduce bug — the debug probe in §13.4 exists specifically to catch this early.

13.7 Performance Concerns

Boot-time paging setup walks a handful of tables — bounded, not measured yet at this phase (measured starting M1/M2, §31). Avoid memset-style zeroing loops over more than the exact BSS range — the linker script must give exact bounds.

13.8 Edge Cases

  • OVMF reports a memory map with overlapping regions on some QEMU versions — the BootInfo parser must de-duplicate before handing regions to the frame allocator (Phase 2).
  • A multiboot2 build run under real UEFI firmware (no -kernel support) must fail loudly, not silently boot-loop.

13.9 Failure Analysis

A triple fault here (FM1) is diagnosed via QEMU -d int,cpu_reset; blast radius is total (no kernel code has executed) but detection is immediate via the fixture timeout. Recovery: bisect the boot stub against the last passing commit.

13.10 Operational Notes

docs/boot-flow.md documents both paths side-by-side; docs/memory-map.md documents the higher-half layout. Both are load-bearing references for on-call debugging (FM1 runbook, docs/runbooks/boot-triple-fault.md).

14. Phase 2 — Physical & Virtual Memory Management

14.1 Objectives

Bring the frame allocator, page-table API, kernel heap, and VMAR online so alloc works inside the kernel and a first demand-paged user mapping can fault in (ADR-06, ADR-07, ADR-08, I9, I12).

14.2 Detailed Implementation Steps

  • Implement BitmapFrameAllocator (ADR-07) keyed off the UEFI/multiboot2 memory map; reserve the kernel image, bootloader pages, framebuffer. allocate/free are O(1)-amortized via a search-hint cursor (§35 item 8 for the bitmap-size derivation).
  • Implement the Mapper trait (§11.3) over a direct-mapped physical-memory window in the higher half (never the recursive-mapping trick — ADR-09, unsafe under SMP). Walk PML4→PDPT→PD→PT (§8.3), allocating intermediate tables on demand.
  • Implement the kernel heap: Phase 2a linked-list allocator (1 MiB reserved, writable); Phase 2b slab allocator on top for fixed-size objects (Thread, Process, Inode, DirEntry) per Bonwick 1994 (ADR-08, Required Reading #4).
  • Implement the VMAR: a per-address-space red-black tree of [start, end) regions with flags and optional file backing; mmap/munmap/mprotect/brk operate on it; the page-fault handler (Phase 3) consults it to decide fault-in vs. SIGSEGV.
  • Implement copy_from_user/copy_to_user (§11) with a fault-tolerant fixup table so a bad user pointer returns EFAULT instead of panicking the kernel (T1, T10).

14.3 Deliverable

alloc::vec![1u8; 4 MiB] succeeds inside the kernel; a synthetic page fault on a MAP_ANON VMAR region faults the page in on demand.

14.4 Acceptance Criteria

  • mm/00-frame-alloc-roundtrip.toml: 100,000 allocate/free cycles, zero leaked frames (frame-table checksum stable).
  • mm/01-mmap-anon-fault-in.toml: mmap(8 KiB) + touch + munmap completes in < 40 µs median (M7).
  • Idle kernel resident memory stays < 16 MiB (M8) after this phase's structures are live.
  • mm/02-mprotect-rw-to-r.toml: a write to a downgraded region raises SIGSEGV (I2).

14.5 Conformance Fixtures

Fixture Purpose Expected Output
mm/00-frame-alloc-roundtrip.toml allocator correctness 0 leaked frames after 1e5 cycles
mm/01-mmap-anon-fault-in.toml demand paging fault-in succeeds, < 40 µs (M7)
mm/02-mprotect-rw-to-r.toml permission downgrade write → SIGSEGV
mm/03-stack-grow.toml guard-page-triggered stack growth grows once, not unbounded

14.6 Pitfalls

  1. TLB must be flushed on unmap (invlpg for single pages, full mov cr3, cr3 for bulk) — cheaper than expected on QEMU, expensive on real hardware (I12, M-table).
  2. Recursive page-table mapping is clever and wrong on the way to SMP — a direct-mapped physical window is simpler and correct under concurrent CPUs (ADR-09).
  3. The NX bit requires EFER.NXE; set it once during Phase-1 long-mode entry and assert it here (I2).

14.7 Performance Concerns

Bitmap-scan cost for the frame allocator is O(n) worst case; the search-hint cursor keeps the common case O(1) amortized (derived in §35 item 8). Huge pages (2 MiB/1 GiB) are PhaseDeferred("§14.7") — the buddy-allocator follow-up (ADR-07) is the prerequisite.

14.8 Edge Cases

  • Two threads racing mmap on overlapping ranges in the same VmarTree must be serialized by the address-space lock, not left to the red-black tree's own (non-atomic) rotation.
  • A brk() shrink below the current heap tail must unmap and free the vacated frames, not merely shrink a pointer.
  • Out-of-frames during fault-in must deliver SIGSEGV/OOM-kill semantics, not panic.

14.9 Failure Analysis

A dangling PTE (FM3) surfaces as a page fault at a physical address outside any tracked frame; detection is a debug-only assert on I9, blast radius is the faulting process (kernel panics with cr2/cr3 dump per P8 if the assert fires in a kernel context). Recovery: replay under -icount deterministic mode, diff the frame- allocator log.

14.10 Operational Notes

docs/memory-map.md is the operator reference for every region boundary; the frame allocator emits a ring-buffer log of allocate/free events consulted by docs/runbooks/oom.md.

15. Phase 3 — Interrupts, Exceptions & Timers

15.1 Objectives

Bring the IDT, TSS/IST stacks, LAPIC, and the page-fault handler online so the kernel can safely take CPU exceptions and IRQs without corrupting state (I4, I13).

15.2 Detailed Implementation Steps

  • Build a 256-entry IDT (I13): vectors 0–31 reserved for CPU exceptions; 32–47 legacy PIC range (masked); 48–255 available for IOAPIC routing and IPIs (Phase 10). Entries point at stubs in trap/entry.S that save the full register file into a TrapFrame, call the Rust handler, then iretq.
  • Allocate one TSS per CPU with three IST stacks: double-fault, NMI, machine-check (FM2); load with ltr after the GDT load (Phase 1 dependency).
  • Bring up the LAPIC (ADR-10): disable the legacy PIC (mask all lines), map LAPIC MMIO, enable via IA32_APIC_BASE, configure the spurious-interrupt vector, error vector, and timer.
  • Configure the LAPIC timer (ADR-11) in periodic mode at 100 Hz to start (raised to 1 kHz in Phase 4); calibrate against the invariant TSC (§35 item 7, ADR-30).
  • Implement the page-fault handler (§8.7): decode cr2 and the error code, consult the faulting thread's VMAR (Phase 2 dependency); fault-in/COW if the region permits, else kernel-fault→panic (P8) or user-fault→SIGSEGV (Phase 9 dependency, forward reference resolved at §21).

15.3 Deliverable

int 0x03 from the kernel triggers a debug exception the handler logs and returns from; a divide-by-zero in user-space (once Phase 6 lands) terminates only the faulting thread.

15.4 Acceptance Criteria

  • trap/00-breakpoint.toml: int 0x03 logs and resumes execution at the next instruction.
  • trap/02-double-fault-recovery.toml: a deliberately triggered #DF runs on its own IST stack and prints a full trace before halting (P8).
  • Page-fault handling latency (anon fault-in path) < 2 µs median (M9).

15.5 Conformance Fixtures

Fixture Purpose Expected Output
trap/00-breakpoint.toml #BP handling logs, resumes
trap/01-page-fault-user.toml user #PF → fault-in or SIGSEGV correct disposition per VMAR
trap/02-double-fault-recovery.toml #DF on IST stack trace printed, no triple fault

15.6 Pitfalls

  1. The #DF handler must run on its own IST stack (FM2) or the kernel triple- faults before printing anything.
  2. The CPU pushes an error code for some vectors and not others (SDM Vol. 3A Table 6-1) — the entry stub must use the correct iretq frame layout per vector.
  3. swapgs is a sharp tool (MM3): get the entry/exit pairing wrong and gs:base becomes garbage, corrupting per-CPU access into a UAF-shaped bug.

15.7 Performance Concerns

The trap-entry stub is on the fast path for every syscall and every IRQ (P7); it must stay under the same instruction budget discipline as the syscall fast path (§4). LAPIC timer calibration against TSC happens once at boot, not per-tick.

15.8 Edge Cases

  • A nested #PF while already inside the page-fault handler (recursive fault) must be detected and escalated to a kernel panic, not infinitely recurse.
  • An IRQ arriving during the entry-stub window before swapgs completes must be impossible by construction (FMASK clears IF on entry, ADR-14 dependency forward- referenced from Phase 6).

15.9 Failure Analysis

A double-fault loop (FM2) is detected by the fixture timeout and by a repeated-vector counter in the trace ring; forensic artifact is the serial trace dump with register state; long-term mitigation is the boot-time assert that IST1 is set (I13-adjacent).

15.10 Operational Notes

The trace ring buffer introduced here (sched_switch, irq_enter, irq_exit, pf_enter, pf_exit events) is the backbone of docs/runbooks/deadlock.md and every later phase's telemetry (P13, §27).

16. Phase 4 — Scheduler & Threads

16.1 Objectives

Bring cooperative then preemptive thread scheduling online with per-CPU run-queues and wait-queues (ADR-12, I5, MM1).

16.2 Detailed Implementation Steps

  • Thread::new_kernel(entry) allocates a kernel stack, builds an initial Context (§11.4) with rip = entry, links it into the per-CPU run-queue. Thread::new_user additionally references an AddressSpace (Phase 5 dependency).
  • Implement yield_now(): the context_switch.S stub saves callee-saved registers, swaps stacks, reloads the next thread's registers (P7 fast-path budget, MM1). Validate with two cooperative threads ping-ponging through yield_now() 1e6 times.
  • Wire the LAPIC timer interrupt (Phase 3 dependency) into the trap path: on return, if the current thread's time slice expired and preempt_count == 0 (I3), perform a context switch. Implement preempt_disable()/preempt_enable() for critical sections that cannot tolerate preemption.
  • Implement per-CPU MLFQ-lite run-queues (ADR-12): 4 priority bands, round-robin within a band, promote-on-IO-block, demote-on-quantum-expiry — this is the per-CPU design the Boyd-Wickizer 2010 cache-line-contention finding motivates (Required Reading, ADR-12).
  • Implement wait queues as linked lists keyed by an event token; wake_one/ wake_all (I5 — a thread transitions Blocked→Runnable only via these calls).
  • Implement the idle thread: one per CPU, runs hlt in a loop.

16.3 Deliverable

Two preemptively scheduled kernel threads print a counter at 100 Hz over serial with zero missed ticks over a 60 s window.

16.4 Acceptance Criteria

  • sched/00-coop-yield.toml: 1e6 yield_now() round trips, median context-switch latency < 3 µs on KVM (M5).
  • sched/01-preempt-fairness.toml: no thread starved (zero timeslices) for > 5 s under a 4-thread, 4-band contention fixture (FM4).
  • 60 s soak with zero missed 100 Hz ticks (jitter < 1 ms p99).

16.5 Conformance Fixtures

Fixture Purpose Expected Output
sched/00-coop-yield.toml cooperative switch correctness 1e6 round trips, no corruption
sched/01-preempt-fairness.toml MLFQ-lite fairness no thread starved > 5 s
sched/02-wait-queue-wakeup.toml wait/wake correctness woken thread state == Runnable (I5)

16.6 Pitfalls

  1. The first context switch is special — there is no "previous" thread to save; allocate a dummy current early.
  2. Forgetting to re-enable interrupts on the new thread's stack after a switch is the classic bug — diff the switch path against xv6's (Required Reading #3).
  3. Stack-canary checking needs a kernel __stack_chk_fail; ship one even if it is only exercised in debug builds.

16.7 Performance Concerns

Context-switch cost is dominated by register save/restore and cache effects, not scheduling logic (MM1) — keep the switch path itself free of any decision-making; decisions happen in pick_next() before the switch. Per-CPU run-queue bitmap lookup for non-empty bands is O(1), not O(n) over threads (§35 item 10).

16.8 Edge Cases

  • A thread that yields while preempt_count > 0 must be rejected (I3 assert), not silently deferred.
  • A wait-queue wakeup racing with the waiter's own timeout must not double-wake (I5: a thread is on exactly one queue).
  • SMP load-balancing (Phase 10 forward dependency) must not pull a thread mid-switch.

16.9 Failure Analysis

Scheduler starvation (FM4) is detected via the sched_wait_ns_p99 histogram gated in CI (§31); deadlock across scheduler-adjacent locks (FM5) is detected by the debug-only lock-order checker (I14). Both have documented runbooks.

16.10 Operational Notes

The trace ring's sched_switch events (from §15.10) are consulted for fairness debugging; docs/runbooks/deadlock.md covers the scheduler-lock deadlock class specifically.

17. Phase 5 — Processes, Address Spaces & ELF Loading

17.1 Objectives

Bring fork/execve/wait/exit online with copy-on-write address spaces and an ELF64 loader (ADR-06, I11, MM5).

17.2 Detailed Implementation Steps

  • Each Process owns an AddressSpace (§11.5); cr3 swaps on context switch only when the next thread's address space differs from the current (I1).
  • Implement the global process table: RwLock<BTreeMap<Pid, Arc<Process>>>; monotonic AtomicU64 PID allocation initially, bitmap reuse later (PhaseDeferred("§23.1") for the reuse policy).
  • Implement copy-on-write fork: clone the VMAR, mark all writable user pages read-only in both address spaces, refcount the underlying frames, fault-in a private copy on the first write (MM5 — this is what turns fork from O(memory) into O(page-table)).
  • Implement execve (§8.4): parse the ELF64 header, iterate PT_LOAD segments, build a fresh address space, map segments, zero BSS tail, allocate a user stack, push argv/envp/auxv (SysV ABI supplement), iretq to user mode.
  • Implement wait/exit: a zombie thread releases everything but its Process slot until reaped (I11); dynamic linking / shared libraries beyond static ELF64 are PhaseDeferred("§23.1").

17.3 Deliverable

A user-space /sbin/init executes, prints init: ready over serial, and forks /bin/sh.

17.4 Acceptance Criteria

  • proc/00-fork-exec-exit.toml: fork+exec+exit+wait completes with the correct exit code observed by the parent.
  • proc/01-cow-correctness.toml: a write to a COW page after fork is invisible in the other address space (isolation proof).
  • ELF execve of a 64 KiB binary completes in < 500 µs median (M13).

17.5 Conformance Fixtures

Fixture Purpose Expected Output
proc/00-fork-exec-exit.toml full lifecycle parent observes correct exit code
proc/01-cow-correctness.toml COW isolation write invisible cross-address-space
proc/02-stack-args.toml argv/envp/auxv layout child sees exact argv it was given

17.6 Pitfalls

  1. Forgetting to zero-fill BSS for PT_LOAD segments where memsz > filesz corrupts uninitialized-global assumptions in user programs.
  2. Skipping auxv breaks a future libc port silently — it is part of the ABI, lock it now (ADR-15).
  3. fork must atomically duplicate the file-descriptor table (I6) — a thread racing dup2 against fork is the canonical regression (FM6).

17.7 Performance Concerns

COW defers the fork cost to first-write time (MM5); a fork-then-immediately-write- everything workload defeats the optimization — document this tradeoff in docs/adr/ADR-06.md rather than "fixing" it by eager copy.

17.8 Edge Cases

  • execve of a non-ELF or truncated file must return ENOEXEC, never panic (mirrors §8.6's malformed-input discipline).
  • A fork when the process table is at its 1,024-process ceiling (§4) must return EAGAIN, not silently reuse a PID.
  • wait() on an already-reaped child must return ECHILD.

17.9 Failure Analysis

The fork/dup2 race (FM6) is detected by a dedicated regression fixture added after the first occurrence; forensic artifact is an FDT snapshot log taken at fork time.

17.10 Operational Notes

Process lifecycle events (fork, exec, exit, wait) are logged at INFO level with PID/PPID; docs/runbooks/ gains a process-table-exhaustion entry cross-linked to FM6.

18. Phase 6 — System-Call ABI & Dispatch

18.1 Objectives

Bring the syscall/sysret fast path online end-to-end: register load, dispatch, handler, return (ADR-14, ADR-15, P7, MM6).

18.2 Detailed Implementation Steps

  • Set IA32_LSTAR to the entry stub; configure STAR selectors and FMASK to clear IF/DF on entry (P7, §15.8 dependency).
  • Entry stub: swapgs; save user rsp into per-CPU; load kernel rsp from per-CPU; push a minimal SyscallFrame; jump to dispatch (MM3 — re-establish per-CPU state before trusting it).
  • Dispatch: read rax, index syscall::table (I7), call the Handler (§11) implementation with five usize args in SysV order (rdi rsi rdx r10 r8, §8.2).
  • Each handler in syscall/handlers/: validate pointers via copy_from_user/ copy_to_user (T1, T10, MM6 — every argument is attacker-controlled until validated); take locks in the documented order (I14); perform the operation; return value or -errno via an Errno enum mirroring POSIX values.
  • Exit stub reverses entry, then sysretq.
  • Socket/Bind/Connect handlers return -ENOSYS with a blueprint_ref log entry (PhaseDeferred("§18.8"), ADR-27 boundary — no in-kernel async reactor is built for this stub).

18.3 Deliverable

write(1, "hello, world\n", 13) from user-space prints to serial and returns 13 (§8.2 worked example).

18.4 Acceptance Criteria

  • syscall/00-write-stdout.toml: write() returns exactly 13 and the bytes appear on serial.
  • Median getpid() round trip < 1 µs on KVM, < 5 µs on TCG (M3/M4).
  • syscall/01-bad-pointer-efault.toml: a syscall given an unmapped user pointer returns -EFAULT, never panics.

18.5 Conformance Fixtures

Fixture Purpose Expected Output
syscall/00-write-stdout.toml fast-path correctness returns 13, bytes on serial
syscall/01-bad-pointer-efault.toml pointer validation -EFAULT, no panic
syscall/02-getpid-monotonic.toml PID stability same PID across calls
syscall/03-exit-status.toml exit-code propagation parent observes correct code

18.6 Pitfalls

  1. FMASK must clear IF and DF on entry — an interrupt during the entry stub before swapgs corrupts per-CPU state (MM3, T1-adjacent).
  2. swapgs executes exactly once per entry/exit; the entry path must run it before any per-CPU access.
  3. Validating a user pointer is not just a range check — the page may be unmapped and faulting must be tolerated via the copy_from_user fixup table, not a manual is_mapped() check that races (T10, MM6).

18.7 Performance Concerns

The fast path (no scheduling, no I/O) stays under 200 instructions (§4, P7); every handler that takes a lock or touches the VFS is, by definition, the slow path and is exempt from that budget but must remain re-entrant.

18.8 Edge Cases

  • A syscall number outside the defined enum range returns -ENOSYS, not undefined behavior.
  • Socket/Bind/Connect return -ENOSYS — the deferred networking stub anchor (PhaseDeferred("§18.8"), resolved in §38).
  • A signal pending at syscall-return time (Phase 9 forward dependency) must be delivered before sysretq, and an interrupted blocking syscall returns -EINTR.

18.9 Failure Analysis

A TOCTOU race on a user pointer (T10) is prevented by design (copy-once-then-use); if a future handler regresses this, the conformance fixture 01-bad-pointer-efault plus a fuzz-driven TOCTOU fixture (§24.2) catch it.

18.10 Operational Notes

docs/syscall-abi.md is the versioned public contract; every new syscall PR must update it and add a fixture in the same PR (P7, key pitfall — never ship a syscall without its fixture).

19. Phase 7 — VFS, Ramfs & ext2 (Read-Only)

19.1 Objectives

Bring the filesystem-agnostic VFS layer online with an in-memory ramfs and a read-only ext2 reader (ADR-16, ADR-17). ext4 support is PhaseDeferred("§19.1") — ext2's smaller spec surface is easier to fuzz and matches the read-only Phase-0–12 scope.

19.2 Detailed Implementation Steps

  • Implement superblock/inode/dentry/file (§11.6) mirroring Linux's shape but smaller (Required Reading #4, #5). Path resolution is iterative component-wise lookup() per the EBNF grammar (§8.5). The mount table is a flat Vec<Mount> for Phase 0–12.
  • Implement ramfs: the initramfs is a cpio newc archive shipped beside the kernel image; the bootloader passes its physical address in BootInfo; ramfs::mount parses it in place into a tree of in-memory inodes (malformed-input handling per §8.6, FM7).
  • Implement ext2 read-only: parse the superblock, block-group descriptors, inode table; read_at/readdir walk direct and indirect block pointers. No write path in Phase 0–12.
  • Implement open/read/write/lseek: open(path, flags) returns an fd in the per-process FDT (I6); read/write call the underlying inode's read_at/ write_at with the file's current offset, copying through copy_to_user/ copy_from_user (T1), advancing the atomic offset.

19.3 Deliverable

/bin/cat /etc/motd prints a baked-in message from ramfs; once Phase 8 lands, the same path works against a virtio-blk-backed ext2 image.

19.4 Acceptance Criteria

  • vfs/00-cpio-roundtrip.toml: a built initramfs round-trips through mkfs-ramfs and ramfs::mount byte-identical.
  • read(file, 4 KiB, ramfs) completes in < 5 µs median (M6).
  • vfs/03-bad-fd-ebadf.toml: an operation on a closed fd returns -EBADF, never panics.

19.5 Conformance Fixtures

Fixture Purpose Expected Output
vfs/00-cpio-roundtrip.toml archive parse correctness (+ malformed variant, §8.6) round-trips; malformed → FsError::Malformed
vfs/01-open-close-read.toml fd lifecycle correct bytes, correct offset advance
vfs/02-readdir-order.toml directory listing matches archive insertion order

  1. cpio newc requires 4-byte alignment; an off-by-one in the parser is the most common bug (§8.6, FM7).
  2. A dentry cache is a future optimization — do not add it before path resolution is proven correct (P1: boring first).
  3. readdir semantics across fork/dup/close is subtle — document and test the offset behavior explicitly (I6).

19.7 Performance Concerns

19.8 Edge Cases

  • A cpio archive with a name collision (two entries, same path) — last-wins, documented, tested.
  • ext2 indirect-block corruption must surface as FsError::Malformed, never an out-of-bounds read (T3, FM7).
  • Concurrent read+lseek on the same fd from two threads sharing it (post-fork, pre-exec) — the atomic offset (§11.6) makes this race-free but not linearizable-by-intent; documented as defined-but-surprising.

19.9 Failure Analysis

A malformed on-disk image (FM7) is caught by the fixture's malformed variant and by continuous fuzzing (§24.2, M14); recovery is a clean mount failure, never a panic.

19.10 Operational Notes

docs/driver-model.md cross-references the BlockDevice seam this phase depends on (Phase 8); mount/unmount events are logged at INFO with the filesystem name and device.

20.1 Objectives

Bring the driver-registration core and the minimum device set online: UART, PS/2 keyboard, VGA text/framebuffer, RTC, PCI enumeration, virtio-blk (P6, ADR-18, ADR-19). Live kernel-module update is PhaseDeferred("§20.1") — the Driver trait boundary here is its prerequisite, not its implementation.

  • driver/01-pci-enumerate.toml: PCI bus walk finds the expected virtio-blk device by [vendor, device] ID.
  • driver/02-virtio-block-roundtrip.toml: a written block round-trips through read_block/write_block byte-identical.

20.5 Conformance Fixtures

driver/01-pci-enumerate.toml PCI bus walk expected device found
driver/02-virtio-block-roundtrip.toml block I/O correctness round-trip byte-identical

20.6 Pitfalls

  1. PCI BAR sizing follows a non-obvious probe sequence (write all-1s, read back, compute size) — follow the OSDev reference precisely.
  2. virtio device-status bits must be set in a specific order or the device refuses the queue (FM8).
  3. A missing memory barrier between the descriptor write and the doorbell ring is the canonical virtio desync bug (FM8) — insert one even though it looks like overkill on x86's stronger memory model.

  • Hot-plug (a device appearing after boot) is out of scope for Phase 0–12 — documented as a non-goal, not silently unsupported.

20.9 Failure Analysis

21. Phase 9 — IPC: Pipes & Signals

21.1 Objectives

Bring pipes and POSIX-shaped signal delivery online, resolving the Phase-3 forward reference to user-fault SIGSEGV delivery (§8.7, ADR-31, P11).

21.2 Detailed Implementation Steps

  • Implement pipes: unidirectional bounded ring buffer (default 64 KiB, ADR-31 — a full buffer blocks the writer, an empty one blocks the reader, never drops); two file descriptors, fork duplicates them (I6), close decrements refcount, the pipe is freed when both ends close.
  • Implement signals: POSIX-shaped numbers, default actions, dispositions. sigaction(2) registers a user-space handler. Delivery is checked on the syscall- return path (§18.8 forward reference resolved): the kernel builds a signal frame on the user stack and redirects iretq; sigreturn(2) restores the original frame.
  • Wire the Phase-3 page-fault handler's SIGSEGV delivery (§8.7 step 6) through this mechanism.
  • Document EINTR semantics for a syscall interrupted by signal delivery mid-block (T11, FM11).

21.3 Deliverable

echo hello | wc -c prints 6; kill -TERM <pid> from the shell is honored by the running program.

21.4 Acceptance Criteria

  • ipc/00-pipe-byte-stream.toml: byte stream through a pipe is order-preserving and complete.
  • Pipe round trip (64 B payload) < 5 µs median on KVM (M10).
  • ipc/03-sigaction-handler.toml: a registered handler runs and sigreturn restores the exact pre-signal register state.

21.6 Pitfalls

  1. Signal delivery atop a syscall about to block is subtle — document and test EINTR semantics explicitly (T11).
  2. The signal-frame layout is part of the user ABI; a future libc port depends on it — lock it in docs/syscall-abi.md (ADR-15).
  3. A race between kill and exit on the same target is the classic bug (FM11, T11) — the process-table lock and signal-queue must agree on a happens-before order (I14).

21.7 Performance Concerns

Pipe throughput is bounded by the 64 KiB ring and the wake-up latency of the blocked end (context-switch cost, M5); larger buffers trade memory for fewer wake-ups — a documented future lever, not a Phase-0–12 default.

21.8 Edge Cases

  • A pipe write larger than the ring capacity must be split across multiple blocking writes, never truncated silently.
  • A signal delivered to a thread already inside its own handler (no SA_NODEFER) must not re-enter — matches POSIX default disposition.
  • kill() to a PID that has already been reaped returns ESRCH, not undefined behavior.

21.9 Failure Analysis

The kill/exit race (FM11, T11) is detected by a dedicated fuzz-driven race fixture added after first occurrence; forensic artifact is a user-stack dump at the fault point for signal-frame corruption cases.

21.10 Operational Notes

Signal delivery and pipe open/close events are logged at DEBUG (not INFO — high frequency); docs/syscall-abi.md gains the locked signal-frame layout section.

22. Phase 10 — SMP: AP Bringup & Per-CPU Data

22.1 Objectives

Bring multi-CPU execution online: AP bringup, per-CPU data, IRQ-safe spinlocks, and TLB-shootdown IPIs (ADR-12, Boyd-Wickizer 2010, MM7).

22.2 Detailed Implementation Steps

  • BSP starts APs via the LAPIC INIT-SIPI-SIPI sequence with the documented inter-SIPI delays; each AP runs trampoline.S (must be linked below 1 MiB, real-mode addressable), enters long mode, loads its per-CPU block, jumps into ap_main.
  • Implement per-CPU data via gs:base, set only through wrmsr of IA32_KERNEL_GS_BASE — never a direct mov (MM3). The percpu! macro expands to a typed accessor.
  • Extend the scheduler to per-CPU run-queues with load balancing at quantum boundary (§16 dependency; per-CPU avoids the cache-line-bouncing global-runqueue cost Boyd-Wickizer 2010 measured past 8 cores — Required Reading, ADR-12).
  • Implement IRQ-safe Spinlock<T> (§11.8): disables preemption on lock, saves/ restores the interrupt flag; lock order documented in docs/lock-order.md with a debug-only order checker (I14, MM7).
  • Implement IPIs: reschedule IPI (vector 0xFE), TLB-shootdown IPI (vector 0xFD). Shootdown rendezvous: sender writes a target page set, receivers invlpg each entry, sender waits on a count (I12 cross-CPU case).

22.3 Deliverable

An nproc-equivalent syscall reports the number of QEMU -smp CPUs; two user-space programs run concurrently on different cores; context-switch latency holds within 20% of the single-CPU baseline.

22.4 Acceptance Criteria

  • smp/00-ap-count.toml: reported CPU count matches -smp N exactly.
  • Cross-CPU IPI delivery < 2 µs median (M11).
  • TLB shootdown (4 CPUs, 1 page) < 10 µs median (M12).

Fixture Purpose Expected Output

smp/01-cross-cpu-pipe.toml cross-CPU IPC pipe correctness holds across cores
smp/02-tlb-shootdown.toml shootdown correctness + latency < 10 µs median (M12)

22.6 Pitfalls

  1. The trampoline must live below 1 MiB (real-mode addressable) — enforce via linker script, not convention (FM9).
  2. The INIT-SIPI-SIPI sequence has documented timing requirements (Intel SDM) — insert the exact delays, do not shortcut them.
  3. gs:base is per-CPU — never mov directly, always wrmsr of IA32_KERNEL_GS_BASE (MM3, FM9 adjacent).

22.7 Performance Concerns

Per-CPU run-queues bound cache-line contention (Boyd-Wickizer 2010); load-balancing frequency trades fairness for cross-CPU cache-line traffic — tuned, not fixed, and documented in docs/adr/ADR-12.md.

22.8 Edge Cases

  • An AP that fails to respond to SIPI within the timeout must not hang the BSP — log a warning and proceed single-CPU-reduced (FM9).
  • A TLB-shootdown sender whose target CPU has interrupts disabled during the window must time out and raise a diagnostic NMI, not hang forever (FM10).
  • Two CPUs racing to acquire the same spinlock under IRQ must preserve I3/I4 exactly.

22.9 Failure Analysis

AP bringup failure (FM9) degrades to single-CPU with a logged warning rather than halting the boot; TLB-shootdown hang (FM10) is bounded by a timeout that triggers a diagnostic NMI dumping the stuck CPU's backtrace.

22.10 Operational Notes

Per-CPU IRQ-disable duration is histogrammed (irq_disabled_ns_p99) to catch shootdown-unsafe critical sections before they cause FM10 in the field.

28. Compatibility & Versioning

  • Wire/ABI compatibility: the syscall ABI (§11.7, §18) is append-only — I7/ADR-14 forbid renumbering; docs/syscall-abi.md is the versioned public contract.
  • Storage compatibility: ramfs is volatile (no compatibility surface); ext2 is read-only against the standard on-disk format (Required Reading — ext2 spec via Required Reading #17-equivalent citation, applied §19) — no custom on-disk extensions.
  • Schema evolution: the conformance.report.json schema (§29) carries a "version" field; a breaking change bumps it and both old/new parsers coexist for one release.
  • API stability: the Mapper/Driver/FileSystem/Inode traits (§11) are internal-only — never a stability promise to anything outside the kernel binary (P4).
  • Deprecation policy: an ADR is required to remove any syscall number's behavior (never its number, I7); a deprecated syscall returns -ENOSYS for at least one release cycle before removal.
  • SemVer policy: the kernel image itself is not semver'd (it is a specification implementation, not a library); kernel-abi crate is semver'd for any user-space crate that depends on it directly.
  • Rolling-upgrade guarantees: none in Phase 0–12 (single-image deployment); the ADR-29 boundary defers orchestrated rolling upgrade to the future Container Runtime project (rank 35).

32. Scalability Analysis

  • Constant regardless of load: the syscall fast-path instruction budget (§4, P7); the per-CPU run-queue's O(1) pick (Boyd-Wickizer 2010, §35 item 10).
  • Grows with load, named Big-O: frame-allocator bitmap scan O(n) worst case, O(1) amortized via search-hint cursor (§14.7); VFS path resolution O(depth) per lookup() (§19.7); process-table lookup O(log n) via BTreeMap (§17.2).
  • Named bottlenecks, in order: (1) the single global process-table RwLock (§17.2) — write-locked on every fork/exit; (2) the frame-allocator spinlock under contention from many concurrent mmap calls; (3) the virtio-blk single request-queue depth (§20.7) capping I/O concurrency.
  • Horizontal scaling: none within one kernel instance — horizontal scale is achieved at the orchestration layer (future Container Runtime, rank 35), not by this kernel.
  • Vertical scaling: bounded by §4's ceilings (4,096 threads, 128 logical CPUs, 16 GiB reference RAM); the levers beyond those ceilings are a buddy allocator (ADR-07 follow-up) and a slab-only heap at scale (Bonwick & Adams 2001). NUMA-aware placement is out of scope for Phase 0–12 and is flagged here as a known future gap, not a registered deferral (no phase in this plan claims it).
  • Sharding/partitioning: the process table could shard by PID range under contention (documented lever, not implemented) — the Scalable Commutativity Rule (Clements et al. 2013) is the applicable analysis tool for deciding which kernel interfaces can be made to commute and thus shard.
  • Coordination overhead: TLB shootdown (§22, M12) is the dominant cross-CPU coordination cost; it scales O(CPUs) per shootdown, bounding practical CPU count well before the 128-logical-CPU architectural ceiling.
  • Practical ceiling and the lever beyond it: ~32 CPUs before per-CPU run-queue load-balancing overhead and shootdown coordination cost dominate useful work at this design's fidelity; the lever is a multikernel-style architecture (§37 Alt-4) that trades shared-memory coordination for explicit message passing.

33. Mental Models & First Principles

  • MM1 — "A thread is a saved instruction pointer plus a stack; the scheduler is a function that picks which saved IP runs next." Predicts: context-switch cost is dominated by register save/restore and cache effects, not scheduling logic. Bug without it: engineers embed scheduling decisions inside the switch path itself, bloating the fast path (violates P7). Resolving §: §16.
  • MM2 — "A page table is a hardware-walked lookup tree; the kernel's only job is to keep it truthful." Predicts: any PTE the kernel writes must be immediately valid or explicitly not-present — there is no tolerated half-written state. Bug without it: lazily batching PTE writes across a TLB-flush boundary causes stale-mapping races. Resolving §: §14, I9.
  • MM3 — "An interrupt is a forced procedure call with an adversarial caller — rsp, cr3, and gs cannot be trusted until re-established." Predicts: every asm entry stub must re-establish per-CPU state before touching it. Bug without it: swapgs ordering bugs corrupt per-CPU state (T9-adjacent). Resolving §: §15, §18, §22.
  • MM4 — "Ring 0 is a single trust domain; a bug in any driver is a bug in the kernel." Predicts: driver isolation via the Driver trait (P6) bounds blast radius for correctness review, not for security — a compromised driver still owns ring 0. Resolving §: §20, §34 (contrast with seL4).
  • MM5 — "Copy-on-write turns fork() from an O(memory) into an O(page-table) operation — cost moves from fork-time to first-write-time." Predicts: fork-heavy pipelines are cheap; a fork-then-write-everything pattern defeats the optimization. Bug without it: "optimizing" fork by eager copy destroys the entire benefit. Resolving §: §17.
  • MM6 — "A syscall is a value-passing RPC to the most trusted process on the machine — every argument is attacker-controlled until validated." Predicts: any handler skipping copy_from_user for a pointer argument is a vulnerability, not a bug. Resolving §: §18, T1.
  • MM7 — "A spinlock trades CPU cycles for latency predictability; a sleeping lock trades latency for throughput under contention." Predicts: spinlocks are correct only for short, preemption-safe critical sections; one around I/O deadlocks waiting for a scheduler that cannot run. Resolving §: §22, ADR-13.
  • MM8 — "The boot path is a monotonically decreasing trust handoff." Firmware trusts nothing; it hands off to a bootloader it will (someday) verify, which hands off to a kernel it trusts unconditionally today. Predicts: every boot-time security gap (no secure boot in Phase 0–12) is a deliberately accepted, named risk, not an oversight. Resolving §: §25, T5.

Linux — the monolithic baseline this design's shape follows most closely; its one decision made differently from this design is loadable kernel modules for live driver/feature addition, which wins whenever an operator needs to patch a running fleet without a reboot — a niche this design's PhaseDeferred("§20.1") explicitly declines to build in Phase 0–12.

xv6 — the teaching kernel this design's shape and phase ordering most directly descend from; its decision to skip copy-on-write entirely (plain-copy fork) wins whenever code clarity for a one-semester course outweighs the performance MM5 describes — this design keeps xv6's structure but reinstates COW because it is a production-shaped, not teaching-shaped, kernel.

Zircon (Fuchsia) — its decision to make every kernel object (VMO, channel, process) a capability-addressed handle, with drivers running in user-space driver hosts, wins whenever a product needs update-in-place driver isolation without a full formal-verification investment (seL4's regime) — a middle point this design's single ring-0 trust domain does not occupy.

Windows NT — its hybrid executive/HAL split, with some drivers in kernel mode and others in user mode (UMDF), wins whenever broad third-party hardware-vendor driver compatibility across decades of ABI stability is the priority over either full in-kernel simplicity (this design) or full driver isolation (seL4/Zircon).

35. Back-of-Envelope Capacity Model

  1. Scheduler-overhead-bounded thread count. At a 10 ms default timeslice and a 3 µs context-switch cost (M5), overhead stays under 1% while 10ms × 0.01 / 3µs ≈ 33 threads round-robin on one core before crossing 1% scheduling overhead (derived from §4's tick and M5).
  2. Page-table memory overhead per 1 GiB mapped. 1 GiB / 4 KiB page = 262,144 leaf PTEs → 262,144 / 512 entries-per-table × 4 KiB = 2 MiB of leaf page-table memory, plus ~0.4% for PD/PDPT/PML4 levels ≈ 2.008 MiB per 1 GiB mapped (from §4 page size and address-space size).
  3. TLB reach before a walk. A typical 64-entry L1 dTLB × 4 KiB pages covers 64 × 4 KiB = 256 KiB; a 1,536-entry L2 TLB extends reach to 1,536 × 4 KiB ≈ 6 MiB — any working set beyond 6 MiB pays L2-TLB-walk cost regularly (from §4 page size).
  4. Kernel-stack memory reserved at the 4,096-thread ceiling. 4,096 threads × 16 KiB kernel stack = 64 MiB reserved (from §4 max threads).
  5. Theoretical max syscalls/sec/core. 1 / 1 µs target latency (M3) = 1,000,000 syscalls/sec/core as a back-to-back ceiling (never sustained in practice due to scheduling and I/O interleaving) — a sanity bound, not a promise.
  6. Pipe message-rate ceiling. Round trip ≈ write syscall (1 µs) + read syscall (1 µs) + wakeup context switch (3 µs, M5) = 5 µs ⇒ 1 / 5µs = 200,000 small messages/sec through one pipe pair (from M3, M5).
  7. Boot-time sub-budget allocation. Target < 50 ms (M1): firmware handoff ~5 ms + long-mode entry ~1 ms + mm init ~2 ms + PCI/virtio probe ~10 ms + execve init ~5 ms + VFS mount + first read ~2 ms = 25 ms, leaving 25 ms slack against the 50 ms ceiling (from M1).
  8. Frame-allocator bitmap memory. At the 16 GiB reference RAM ceiling (§4) and 4 KiB frames: 16 GiB / 4 KiB = 4,194,304 frames → 4,194,304 / 8 bits = 524,288 bytes = 512 KiB bitmap (from §4 RAM ceiling and page size).
  9. Worst-case FD-table memory. 4,096 threads × 1,024 FDs (per-process soft limit) × 16 B per entry ≈ 64 MiB worst case if every thread maxed its FD table (from §4 max threads and FD limit) — a sanity check that the 1,024 default is not absurdly expensive, not a claim it will be reached.
  10. O(1) vs. O(n) scheduler-pick savings. A naive O(n) scan at the 4,096-thread ceiling, ~5 ns per node, costs 4,096 × 5 ns ≈ 20 µs per pick — far above the < 3 µs context-switch target (M5); the per-CPU bitmap-banded O(1) pick (§16.7) is what makes M5 reachable at all (from §4 max threads and M5).
  11. Per-CPU data footprint at the 128-logical-CPU ceiling. 128 CPUs × 4 KiB per-CPU block ≈ 512 KiB total per-CPU memory (from §4 max logical CPUs).
  12. Cold-restart RTO budget. Boot (M1, 50 ms) + ramfs/ext2 mount (no fsck needed, read-only/volatile, ~5 ms) + init first read (~5 ms) ≈ 60 ms RTO, matching §4's stated RTO ceiling exactly (derived from M1 plus this section's own item 7 breakdown).

36. Hard Questions (Self-Examination)

  1. Why does copy-on-write make fork() asymptotically cheaper, and under what workload does that advantage invert? (§17, MM5)
  2. Trace write(1, buf, 13) from user register load to the byte appearing on serial, naming every privilege-boundary crossing. (§8.2, §18)
  3. Why is a per-CPU run-queue chosen over a global one, and at what core count does the rejected choice (ADR-12) actually win? (§9 ADR-12, §22, §32)
  4. What exact invariant would break if the recursive page-table mapping trick were used instead of a direct-mapped physical window, and why does it only surface under SMP? (§14.6, ADR-09, I9)
  5. Why must swapgs execute before any per-CPU access in the syscall entry stub, and what corrupts if the ordering is reversed? (§18.2, MM3)
  6. Name the two invariants that together prevent a TOCTOU attack on a user-supplied pointer, and the mechanism that enforces both. (I2, T10, §18.9)
  7. Why does this design reject a microkernel architecture, and under what deployment regime would that rejection reverse? (§37 Alt-1, §34 seL4, MM4)
  8. What is the concrete numeric relationship between the scheduler tick, the context-switch cost, and the maximum thread count before scheduling overhead exceeds 1%? (§35 item 1, §4)
  9. Why is a spinlock wrong to hold across a blocking I/O call, and which invariant would be violated if one were? (I3, ADR-13, MM7)
  10. Explain why the ELF loader's zero-fill-BSS step is not optional, tracing the consequence through to a specific class of user-space bug. (§8.4, §17.6)
  11. Why does the Deferred Features Register anchor the networking stub to §18.8 rather than to a dedicated phase, and what would have to change to un-defer it? (§38, §18.8)
  12. Contrast the failure blast radius of a driver bug in this design versus in seL4 or Zircon, and name the mental model that explains the difference. (MM4, §34)
  13. Why does the frame allocator start as a bitmap rather than a buddy allocator, and at what fragmentation profile does that choice become wrong? (ADR-07, §14.7)
  14. Trace a page fault from a null-pointer dereference in user-space to the parent process observing an exit code, naming every subsystem touched. (§8.7, §21, §17)
  15. Why is the pipe implementation blocking rather than dropping under backpressure, and what principle and ADR jointly justify that choice? (P11, ADR-31, §21)
  16. What two conditions together are necessary for the TLB-shootdown hang failure mode, and which IPI mechanism is implicated? (FM10, §22)
  17. Why does this design's Comparative Architecture table show Windows NT rather than a second monolithic kernel, and what unique dimension does it contribute that Linux does not? (§34)
  18. Derive, from the System Constraints table alone, the reserved kernel-stack memory at the maximum thread ceiling, and explain why that number bounds a design decision elsewhere in the document. (§35 item 4, §4, §16)
  19. Why does ext2 win over ext4 for the first on-disk filesystem here, and under what future requirement would that ADR need revisiting? (ADR-17, §19.1)

37. Alternative Architectures (Roads Not Taken)

Alt-1 — Microkernel (seL4-shaped).

 user:  [ VFS server ] [ driver: virtio-blk ] [ driver: uart ]
              \              |                    /
               \             |                   /
                +--- capability-checked IPC ---+
                              |
                      [ microkernel: IPC,
                        scheduling, capabilities ]

Regime where it wins: security-critical or safety-critical deployments needing provable blast-radius bounds per component (avionics, medical, formally verified enclaves). Real system: seL4 (Klein et al., SOSP 2009). Rejected here because Phase 0–12's goal is teaching the full monolithic-kernel surface (§2) — pushing VFS/drivers to user-space would remove exactly the material (direct driver/VFS/scheduler interaction) this project exists to teach, and the IPC-marshaling engineering cost would roughly double the phase count for no scope gain at this project's size.

Alt-2 — Exokernel (Aegis-shaped).

 user: [ LibOS A: its own VM/scheduler ] [ LibOS B: its own VM/scheduler ]
              \                                    /
               +------ exokernel: hardware --------+
                     multiplexing only (no abstraction)

Regime where it wins: research systems needing per-application control over resource-management policy (custom pagers, custom schedulers) without kernel-imposed abstraction overhead. Real system: MIT Aegis/Exokernel (Engler, Kaashoek, O'Toole, SOSP 1995). Rejected here because a single opinionated VM/scheduler abstraction is exactly what lets Phase 0–12 ship one coherent syscall ABI and one conformance suite — an exokernel pushes that design work onto every LibOS, which this project's single user-space target does not need.

Alt-3 — Single-address-space / unikernel (Theseus-shaped).

 +-----------------------------------------------------+
 |  one address space: kernel code + all "process"      |
 |  logic as cooperatively-scheduled tasks, no fork/exec |
 +-----------------------------------------------------+

Regime where it wins: embedded or cloud-unikernel targets where a single trusted application is compiled directly against kernel internals for minimum overhead and maximum inlining/optimization opportunity. Real system: Theseus OS (Boos et al., OSDI 2020). Rejected here because it structurally cannot support the fork/COW model locked in ADR-06 — a single address space has no cross-process isolation boundary to speak of, which breaks I1/I2 and the entire process/thread teaching goal (§2).

Alt-4 — Multikernel (Barrelfish-shaped).

 CPU0: [ kernel replica | local state ]  <--messages-->
 CPU1: [ kernel replica | local state ]  <--messages-->
 CPU2: [ kernel replica | local state ]  <--messages-->
        (no shared kernel state; agreement via explicit messages)

Regime where it wins: very-high-core-count or heterogeneous-ISA systems where cache-coherent shared-memory coordination itself becomes the bottleneck (§32's named ceiling of ~32 CPUs before shootdown/load-balancing overhead dominates). Real system: Barrelfish / The Multikernel (Baumann et al., SOSP 2009). Rejected here because Phase 0–12 targets a single-socket, ≤128-logical-CPU reference rig (§4) where shared-memory SMP with per-CPU run-queues (ADR-12) is simpler to build and teach, and the message-passing agreement protocol a multikernel requires is exactly the kind of distributed-systems complexity this project defers to its distributed-systems siblings in the portfolio.

39. Glossary

  • ABI. Application Binary Interface — the syscall register/calling convention locked in §11.7, §18.
  • APIC. Advanced Programmable Interrupt Controller — per-CPU successor to the legacy 8259 PIC.
  • AUXV. Auxiliary vector — ELF-loader-supplied key/value pairs on the initial user stack (§8.4).
  • BSP. Bootstrap Processor — the first CPU to run; brings up APs (§22).
  • AP. Application Processor — any non-BSP CPU brought up via INIT-SIPI-SIPI.
  • COW. Copy-on-write — the fork() optimization deferring page copy to first write (MM5).
  • CR0/CR3/CR4. x86 control registers: CR0 holds PG/WP/PE; CR3 holds the page-table root; CR4 holds PAE/SMEP/SMAP.
  • Dentry. Directory entry — the VFS's name-to-inode binding (§11.6).
  • ELF. Executable and Linkable Format — the user-binary format loaded in §8.4.
  • FD. File descriptor — a per-process index into the FileDescriptorTable (I6).
  • FDT. File Descriptor Table — per-process, refcounted (I6).
  • Frame. A fixed-size unit of physical memory (§11.1).
  • GDT. Global Descriptor Table — segment descriptors, largely vestigial in long mode but still required for the TSS selector.
  • IDT. Interrupt Descriptor Table — 256 entries mapping vectors to handlers (§15.2).
  • IPI. Inter-Processor Interrupt — cross-CPU signaling (reschedule, TLB shootdown, §22).
  • IST. Interrupt Stack Table — per-vector dedicated stacks in the TSS (§15.2).
  • KASLR. Kernel Address-Space Layout Randomization — a Phase-12 hardening mitigation (§24).
  • LAPIC. Local APIC — one per CPU; owns the timer and IPI delivery.
  • MLFQ. Multi-Level Feedback Queue — the scheduler's priority-band model (ADR-12).
  • MMIO. Memory-Mapped I/O — devices appearing as memory regions with side effects.
  • MSR. Model-Specific Register — read/written via rdmsr/wrmsr.
  • Nomicon. The Rustonomicon — the unsafe-Rust reference cited by every SAFETY comment (I8).
  • NX. No-Execute — PTE bit 63, requires EFER.NXE (I2).
  • PCB-equivalent. This design's Thread/Process structs (§11.4, §11.5) — no single monolithic PCB, split by concern.
  • PID. Process identifier, monotonically allocated (§17.2).
  • PML4. Page-Map Level 4 — top of the four-level x86_64 page table (§8.3).
  • PTE. Page-Table Entry (§11.2).
  • Ramfs. The in-memory filesystem backing the initramfs (§19.2).
  • rlimit. Per-process resource limit (FD count, thread count) enforced per T8.
  • SAS. Single-Address-Space — the alternative model this design rejects (Alt-3, ADR-06).
  • SIPI. Startup IPI — the AP-bringup signal following INIT (§22.2).
  • Slab allocator. Fixed-size-object heap allocator (Bonwick 1994, §14.2).
  • SMAP/SMEP. Supervisor Mode Access/Execution Prevention — hardening bits set in CR4 (§24.2).
  • Spinlock. A busy-wait lock; IRQ-safe variant saves/restores rflags.IF (§11.8).
  • swapgs. The instruction that exchanges gs:base with IA32_KERNEL_GS_BASE (MM3).
  • syscall/sysret. The fast-path privilege-transition instruction pair (ADR-14).
  • TLB. Translation Lookaside Buffer — a hardware page-table-entry cache (§35 item 3).
  • TOCTOU. Time-Of-Check-To-Time-Of-Use — the pointer-validation race class prevented by copy-once semantics (T10).
  • TSC. Time-Stamp Counter — the invariant per-core cycle counter used for timing (ADR-30).
  • TSS. Task State Segment — holds the IST stacks and rsp0 (§15.2).
  • VFS. Virtual File System — the kernel's filesystem-agnostic layer (§11.6, §19).
  • VMAR. Virtual Memory Address Region — a subdivision of an address space (§14.4).
  • VMO. Virtual Memory Object — Zircon's capability-addressed memory abstraction (§34, for comparison only, not implemented here).
  • Zombie. A thread/process that has exited but not yet been reaped (I11, §8.1).
