⬜ Phase 0 — Repository Scaffold & Reproducible Build §12

Objectives

Stand up the workspace, the custom target, and a reproducible container build so every later phase has a stable make build/make run/make test contract. No kernel logic yet — this phase is infrastructure only (P9).

Deliverable

make build produces target/x86_64-allvest/debug/kernel.elf; make run boots it under QEMU to a serial "hello, kernel" banner; make test runs host-testable unit tests under x86_64-unknown-linux-gnu.

Acceptance
  • make build exits 0 and produces a non-empty kernel.elf (size > 0 bytes, ELF64 magic verified by file).
  • make run emits the banner string within 100 ms of QEMU exiting firmware, captured by fixture boot/00-banner.toml.
  • cargo clippy --workspace -- -D warnings exits 0 (ADR-32, §30).
  • Two consecutive make build runs in the Docker container produce byte-identical kernel.elf (SHA-256 match) — the reproducibility gate (P9).
Fixtures
Fixture Purpose Expected Output
boot/00-banner.toml banner reachable banner string within 100 ms
build/00-reproducible.toml byte-identical rebuild SHA-256 match across 2 builds
Pitfalls
  1. Forgetting code-model = kernel produces relocations the bootloader cannot place — builds succeed, kernel triple-faults; budget two hours to diagnose (FM1).
  2. Default panic = unwind does not work in no_std; set panic = abort in both dev and release profiles.
  3. cargo's -Z build-std is required to rebuild core for the custom target; document the flag explicitly in README.md.

⬜ Phase 1 — Boot Path & Long-Mode Entry §13

Objectives

Reach kmain and print a serial banner from both a UEFI boot and a multiboot2/BIOS boot, converging on one _start64 symbol and one BootInfo struct (ADR-03, MM8).

Deliverable

A serial-port banner under both UEFI (OVMF) and multiboot2 (qemu -kernel), each gated by its own conformance fixture.

Acceptance
  • 01-uefi-banner.toml: banner observed within 250 ms of OVMF handoff (M1/M2).
  • 02-multiboot2-banner.toml: banner observed within 250 ms under -kernel.
  • Both paths reach _start64 with identical cr3/GDT contents, asserted by a debug probe compiled into Phase-1-only builds.
Fixtures
Fixture Purpose Expected Output
boot/01-uefi-banner.toml UEFI path reaches kmain banner within 250 ms
boot/02-multiboot2-banner.toml multiboot2 path reaches kmain banner within 250 ms
Pitfalls
  1. UEFI service pointers are invalidated by ExitBootServices — never dereference them after exit (T5 adjacent).
  2. The multiboot2 header must be 8-byte aligned in the first 32 KiB; enforce in the linker script, not by convention.
  3. Forgetting to load a TSS before the first iretq crashes on the first exception — Phase 3 needs it; assert it is loaded at the end of Phase 1.
  4. Two boot paths diverging in GDT/PML4 contents is a silent, hard-to-reproduce bug — the debug probe in §13.4 exists specifically to catch this early.

⬜ Phase 2 — Physical & Virtual Memory Management §14

Objectives

Bring the frame allocator, page-table API, kernel heap, and VMAR online so alloc works inside the kernel and a first demand-paged user mapping can fault in (ADR-06, ADR-07, ADR-08, I9, I12).

Deliverable

alloc::vec![1u8; 4 MiB] succeeds inside the kernel; a synthetic page fault on a MAP_ANON VMAR region faults the page in on demand.

Acceptance
  • mm/00-frame-alloc-roundtrip.toml: 100,000 allocate/free cycles, zero leaked frames (frame-table checksum stable).
  • mm/01-mmap-anon-fault-in.toml: mmap(8 KiB) + touch + munmap completes in < 40 µs median (M7).
  • Idle kernel resident memory stays < 16 MiB (M8) after this phase's structures are live.
  • mm/02-mprotect-rw-to-r.toml: a write to a downgraded region raises SIGSEGV (I2).
Fixtures
Fixture Purpose Expected Output
mm/00-frame-alloc-roundtrip.toml allocator correctness 0 leaked frames after 1e5 cycles
mm/01-mmap-anon-fault-in.toml demand paging fault-in succeeds, < 40 µs (M7)
mm/02-mprotect-rw-to-r.toml permission downgrade write → SIGSEGV
mm/03-stack-grow.toml guard-page-triggered stack growth grows once, not unbounded
Pitfalls
  1. TLB must be flushed on unmap (invlpg for single pages, full mov cr3, cr3 for bulk) — cheaper than expected on QEMU, expensive on real hardware (I12, M-table).
  2. Recursive page-table mapping is clever and wrong on the way to SMP — a direct-mapped physical window is simpler and correct under concurrent CPUs (ADR-09).
  3. The NX bit requires EFER.NXE; set it once during Phase-1 long-mode entry and assert it here (I2).

⬜ Phase 3 — Interrupts, Exceptions & Timers §15

Objectives

Bring the IDT, TSS/IST stacks, LAPIC, and the page-fault handler online so the kernel can safely take CPU exceptions and IRQs without corrupting state (I4, I13).

Deliverable

int 0x03 from the kernel triggers a debug exception the handler logs and returns from; a divide-by-zero in user-space (once Phase 6 lands) terminates only the faulting thread.

Acceptance
  • trap/00-breakpoint.toml: int 0x03 logs and resumes execution at the next instruction.
  • trap/02-double-fault-recovery.toml: a deliberately triggered #DF runs on its own IST stack and prints a full trace before halting (P8).
  • Page-fault handling latency (anon fault-in path) < 2 µs median (M9).
Fixtures
Fixture Purpose Expected Output
trap/00-breakpoint.toml #BP handling logs, resumes
trap/01-page-fault-user.toml user #PF → fault-in or SIGSEGV correct disposition per VMAR
trap/02-double-fault-recovery.toml #DF on IST stack trace printed, no triple fault
Pitfalls
  1. The #DF handler must run on its own IST stack (FM2) or the kernel triple- faults before printing anything.
  2. The CPU pushes an error code for some vectors and not others (SDM Vol. 3A Table 6-1) — the entry stub must use the correct iretq frame layout per vector.
  3. swapgs is a sharp tool (MM3): get the entry/exit pairing wrong and gs:base becomes garbage, corrupting per-CPU access into a UAF-shaped bug.

⬜ Phase 4 — Scheduler & Threads §16

Objectives

Bring cooperative then preemptive thread scheduling online with per-CPU run-queues and wait-queues (ADR-12, I5, MM1).

Deliverable

Two preemptively scheduled kernel threads print a counter at 100 Hz over serial with zero missed ticks over a 60 s window.

Acceptance
  • sched/00-coop-yield.toml: 1e6 yield_now() round trips, median context-switch latency < 3 µs on KVM (M5).
  • sched/01-preempt-fairness.toml: no thread starved (zero timeslices) for > 5 s under a 4-thread, 4-band contention fixture (FM4).
  • 60 s soak with zero missed 100 Hz ticks (jitter < 1 ms p99).
Fixtures
Fixture Purpose Expected Output
sched/00-coop-yield.toml cooperative switch correctness 1e6 round trips, no corruption
sched/01-preempt-fairness.toml MLFQ-lite fairness no thread starved > 5 s
sched/02-wait-queue-wakeup.toml wait/wake correctness woken thread state == Runnable (I5)
Pitfalls
  1. The first context switch is special — there is no "previous" thread to save; allocate a dummy current early.
  2. Forgetting to re-enable interrupts on the new thread's stack after a switch is the classic bug — diff the switch path against xv6's (Required Reading #3).
  3. Stack-canary checking needs a kernel __stack_chk_fail; ship one even if it is only exercised in debug builds.

⬜ Phase 5 — Processes, Address Spaces & ELF Loading §17

Objectives

Bring fork/execve/wait/exit online with copy-on-write address spaces and an ELF64 loader (ADR-06, I11, MM5).

Deliverable

A user-space /sbin/init executes, prints init: ready over serial, and forks /bin/sh.

Acceptance
  • proc/00-fork-exec-exit.toml: fork+exec+exit+wait completes with the correct exit code observed by the parent.
  • proc/01-cow-correctness.toml: a write to a COW page after fork is invisible in the other address space (isolation proof).
  • ELF execve of a 64 KiB binary completes in < 500 µs median (M13).
Fixtures
Fixture Purpose Expected Output
proc/00-fork-exec-exit.toml full lifecycle parent observes correct exit code
proc/01-cow-correctness.toml COW isolation write invisible cross-address-space
proc/02-stack-args.toml argv/envp/auxv layout child sees exact argv it was given
Pitfalls
  1. Forgetting to zero-fill BSS for PT_LOAD segments where memsz > filesz corrupts uninitialized-global assumptions in user programs.
  2. Skipping auxv breaks a future libc port silently — it is part of the ABI, lock it now (ADR-15).
  3. fork must atomically duplicate the file-descriptor table (I6) — a thread racing dup2 against fork is the canonical regression (FM6).

⬜ Phase 6 — System-Call ABI & Dispatch §18

Objectives

Bring the syscall/sysret fast path online end-to-end: register load, dispatch, handler, return (ADR-14, ADR-15, P7, MM6).

Deliverable

write(1, "hello, world\n", 13) from user-space prints to serial and returns 13 (§8.2 worked example).

Acceptance
  • syscall/00-write-stdout.toml: write() returns exactly 13 and the bytes appear on serial.
  • Median getpid() round trip < 1 µs on KVM, < 5 µs on TCG (M3/M4).
  • syscall/01-bad-pointer-efault.toml: a syscall given an unmapped user pointer returns -EFAULT, never panics.
Fixtures
Fixture Purpose Expected Output
syscall/00-write-stdout.toml fast-path correctness returns 13, bytes on serial
syscall/01-bad-pointer-efault.toml pointer validation -EFAULT, no panic
syscall/02-getpid-monotonic.toml PID stability same PID across calls
syscall/03-exit-status.toml exit-code propagation parent observes correct code
Pitfalls
  1. FMASK must clear IF and DF on entry — an interrupt during the entry stub before swapgs corrupts per-CPU state (MM3, T1-adjacent).
  2. swapgs executes exactly once per entry/exit; the entry path must run it before any per-CPU access.
  3. Validating a user pointer is not just a range check — the page may be unmapped and faulting must be tolerated via the copy_from_user fixup table, not a manual is_mapped() check that races (T10, MM6).

⬜ Phase 7 — VFS, Ramfs & ext2 (Read-Only) §19

Objectives

Bring the filesystem-agnostic VFS layer online with an in-memory ramfs and a read-only ext2 reader (ADR-16, ADR-17). ext4 support is PhaseDeferred("§19.1") — ext2's smaller spec surface is easier to fuzz and matches the read-only Phase-0–12 scope.

Deliverable

/bin/cat /etc/motd prints a baked-in message from ramfs; once Phase 8 lands, the same path works against a virtio-blk-backed ext2 image.

Acceptance
  • vfs/00-cpio-roundtrip.toml: a built initramfs round-trips through mkfs-ramfs and ramfs::mount byte-identical.
  • read(file, 4 KiB, ramfs) completes in < 5 µs median (M6).
  • vfs/03-bad-fd-ebadf.toml: an operation on a closed fd returns -EBADF, never panics.
Fixtures
Fixture Purpose Expected Output
vfs/00-cpio-roundtrip.toml archive parse correctness (+ malformed variant, §8.6) round-trips; malformed → FsError::Malformed
vfs/01-open-close-read.toml fd lifecycle correct bytes, correct offset advance
vfs/02-readdir-order.toml directory listing matches archive insertion order
vfs/03-bad-fd-ebadf.toml fd-table correctness (I6) -EBADF on stale fd
Pitfalls
  1. cpio newc requires 4-byte alignment; an off-by-one in the parser is the most common bug (§8.6, FM7).
  2. A dentry cache is a future optimization — do not add it before path resolution is proven correct (P1: boring first).
  3. readdir semantics across fork/dup/close is subtle — document and test the offset behavior explicitly (I6).

⬜ Phase 8 — Driver Core & Block/Char Devices §20

Objectives

Bring the driver-registration core and the minimum device set online: UART, PS/2 keyboard, VGA text/framebuffer, RTC, PCI enumeration, virtio-blk (P6, ADR-18, ADR-19). Live kernel-module update is PhaseDeferred("§20.1") — the Driver trait boundary here is its prerequisite, not its implementation.

Deliverable

/sbin/init reads /etc/motd from a virtio-blk-backed ext2 image (Phase 7 dependency) and prints it.

Acceptance
  • driver/00-uart-loopback.toml: bytes written to UART loop back correctly under QEMU's serial loopback mode.
  • driver/01-pci-enumerate.toml: PCI bus walk finds the expected virtio-blk device by [vendor, device] ID.
  • driver/02-virtio-block-roundtrip.toml: a written block round-trips through read_block/write_block byte-identical.
Fixtures
Fixture Purpose Expected Output
driver/00-uart-loopback.toml UART correctness loopback bytes match
driver/01-pci-enumerate.toml PCI bus walk expected device found
driver/02-virtio-block-roundtrip.toml block I/O correctness round-trip byte-identical
Pitfalls
  1. PCI BAR sizing follows a non-obvious probe sequence (write all-1s, read back, compute size) — follow the OSDev reference precisely.
  2. virtio device-status bits must be set in a specific order or the device refuses the queue (FM8).
  3. A missing memory barrier between the descriptor write and the doorbell ring is the canonical virtio desync bug (FM8) — insert one even though it looks like overkill on x86's stronger memory model.

⬜ Phase 9 — IPC: Pipes & Signals §21

Objectives

Bring pipes and POSIX-shaped signal delivery online, resolving the Phase-3 forward reference to user-fault SIGSEGV delivery (§8.7, ADR-31, P11).

Deliverable

echo hello | wc -c prints 6; kill -TERM <pid> from the shell is honored by the running program.

Acceptance
  • ipc/00-pipe-byte-stream.toml: byte stream through a pipe is order-preserving and complete.
  • Pipe round trip (64 B payload) < 5 µs median on KVM (M10).
  • ipc/03-sigaction-handler.toml: a registered handler runs and sigreturn restores the exact pre-signal register state.
Fixtures
Fixture Purpose Expected Output
ipc/00-pipe-byte-stream.toml pipe correctness byte-exact, ordered
ipc/01-pipe-blocking.toml backpressure (P11, ADR-31) writer blocks on full, reader on empty
ipc/02-sigterm-default.toml default signal disposition process terminates on SIGTERM
ipc/03-sigaction-handler.toml custom handler + sigreturn register state restored exactly
Pitfalls
  1. Signal delivery atop a syscall about to block is subtle — document and test EINTR semantics explicitly (T11).
  2. The signal-frame layout is part of the user ABI; a future libc port depends on it — lock it in docs/syscall-abi.md (ADR-15).
  3. A race between kill and exit on the same target is the classic bug (FM11, T11) — the process-table lock and signal-queue must agree on a happens-before order (I14).

⬜ Phase 10 — SMP: AP Bringup & Per-CPU Data §22

Objectives

Bring multi-CPU execution online: AP bringup, per-CPU data, IRQ-safe spinlocks, and TLB-shootdown IPIs (ADR-12, Boyd-Wickizer 2010, MM7).

Deliverable

An nproc-equivalent syscall reports the number of QEMU -smp CPUs; two user-space programs run concurrently on different cores; context-switch latency holds within 20% of the single-CPU baseline.

Acceptance
  • smp/00-ap-count.toml: reported CPU count matches -smp N exactly.
  • Cross-CPU IPI delivery < 2 µs median (M11).
  • TLB shootdown (4 CPUs, 1 page) < 10 µs median (M12).
Fixtures
Fixture Purpose Expected Output
smp/00-ap-count.toml AP bringup correctness CPU count matches -smp N
smp/01-cross-cpu-pipe.toml cross-CPU IPC pipe correctness holds across cores
smp/02-tlb-shootdown.toml shootdown correctness + latency < 10 µs median (M12)
Pitfalls
  1. The trampoline must live below 1 MiB (real-mode addressable) — enforce via linker script, not convention (FM9).
  2. The INIT-SIPI-SIPI sequence has documented timing requirements (Intel SDM) — insert the exact delays, do not shortcut them.
  3. gs:base is per-CPU — never mov directly, always wrmsr of IA32_KERNEL_GS_BASE (MM3, FM9 adjacent).

⬜ Phase 11 — User-Space Runtime §23

Objectives

Ship the user-space crates that make the kernel usable: libc-stub, init, sh, coreutils. Dynamic linking / shared libraries and PID-reuse bitmap allocation are PhaseDeferred("§23.1") here.

Deliverable

A serial console session: log in, run ls /, cat /etc/motd, echo $$, sleep 1 && echo ok, exit.

Acceptance
  • user/00-shell-builtin-cd.toml: cd changes cwd observed by a subsequent pwd.
  • user/01-pipeline-cat-wc.toml: cat file | wc -c reports the exact byte count.
  • All Phase 0–10 fixtures continue to pass with user-space now exercising them end-to-end (regression gate).
Fixtures
Fixture Purpose Expected Output
user/00-shell-builtin-cd.toml shell built-in correctness pwd reflects cd
user/01-pipeline-cat-wc.toml pipeline + pipe integration exact byte count
user/02-redirect-stdin.toml redirection correctness program reads redirected file
Pitfalls
  1. The shell's fork race with signal delivery is its own subject — port xv6's pattern rather than inventing one (Required Reading #3, T11).
  2. execve argument layout determines how init's argv[0] appears in ps — lock it now, it is ABI (ADR-15).

⬜ Phase 12 — Hardening, Fuzzing & Performance Validation §24

Objectives

Close the Phase-0–12 bar: hardening mitigations, continuous fuzzing, and the full performance-target suite (§31) all passing on both QEMU and the real-hardware milestone. IOMMU/DMA isolation and secure-boot signing are PhaseDeferred("§25").

Deliverable

A documented threat model, a CVE disclosure process, a hardening writeup, and a clean 30-day continuous-fuzz run archived under fuzz/artifacts/.

Acceptance
  • Zero uncaught panics across 30 days of continuous cargo-fuzz on all three targets (M14).
  • SMEP/SMAP/NX/KASLR all confirmed enabled via a cr4/cr0/efer snapshot fixture.
  • Full M1–M14 performance table passes on both QEMU/KVM and the real-hardware board.
  • One external review recorded under audits/reviews/ with all critical/high findings closed.
Fixtures
Fixture Purpose Expected Output
hardening/00-mitigations-enabled.toml SMEP/SMAP/NX/KASLR confirmed all bits set per snapshot
hardening/01-fuzz-corpus-clean.toml 30-day fuzz gate 0 uncaught panics
perf/00-full-suite.toml M1–M14 all pass every target met on both rigs
Pitfalls
  1. unsafe growth without review defeats P2 — every PR is measured against the last cargo geiger result; growth requires a new SAFETY comment (I8).
  2. QEMU and real hardware do not always behave the same — a kernel that boots under QEMU and hangs on the reference board is a full day, not an afternoon; own the difference (documented per-board in docs/runbooks/).
  3. Do not ship a new syscall or driver without its conformance fixture in the same PR — this phase's fuzz/perf gates only cover what already has fixtures.
