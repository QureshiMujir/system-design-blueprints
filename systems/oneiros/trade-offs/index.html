Decisions (§9) · 25 ADRs

ADR-01

Language

Chosen

TypeScript 5.x control plane + Python 3.12 confined to self-hosted-model adapters

Rejected

full-stack Python; full-stack Rust; Go

When the rejected choice is right

Rust/Go win once the control plane becomes CPU-bound numerical work (e.g. self-built inference runtime) rather than I/O orchestration

Why: one control-plane language minimizes schema drift across 4 services on packages/schema; Python only where a PyTorch process boundary already exists

ADR-02

Monorepo build

Chosen

pnpm workspaces + Turborepo

Rejected

Nx; Bazel; Lerna

When the rejected choice is right

Bazel wins past ~200 packages needing hermetic cross-language builds

Why: fast incremental builds, low config overhead for a 2-language, <60-package repo

ADR-03

Dependency policy

Chosen

pinned exact versions, Changesets-driven bump PRs

Rejected

caret ranges; Renovate auto-merge

When the rejected choice is right

caret ranges win for pure internal tooling with zero safety surface

Why: a safety-critical safety-classifier dependency chain should never silently float

ADR-04

Primary storage

Chosen

Postgres 16 (Neon) for World/Character/Scene metadata + S3-compatible object storage for blobs

Rejected

MongoDB; DynamoDB; all-in-object-storage

When the rejected choice is right

DynamoDB wins for pure key-value access with no relational joins

Why: World↔Character↔Thread is relational; referential integrity matters for identity invariants (I2)

ADR-05

Wire serialization

Chosen

JSON over WebSocket envelopes

Rejected

msgpack; protobuf-everywhere; Avro

When the rejected choice is right

protobuf wins once video byte-rate metadata dominates payload size (Phase 9+, revisit)

Why: JSON keeps the Adapter contract debuggable and language-agnostic at Phase 1 scale

ADR-06

PWS consistency model

Chosen

single-writer-per-world, read-after-write for the owning session, eventually consistent replicas

Rejected

multi-writer CRDT world state; strict-serializable multi-region

When the rejected choice is right

CRDTs win if worlds were ever concurrently co-edited by multiple writers

Why: worlds are never concurrently co-edited (P1, P3); CRDTs add merge complexity with no benefit here (Brewer, CAP 2012)

ADR-07

Viewer transport

Chosen

WebSocket (metadata/text/image/audio) + HLS (video, Phase 9)

Rejected

WebRTC; gRPC-web; HTTP long-polling

When the rejected choice is right

WebRTC wins for genuinely bidirectional low-latency co-viewing (deferred)

Why: one-way generative delivery, not bidirectional live media

ADR-08

Control-plane runtime

Chosen

Node 22 LTS

Rejected

Deno; Bun

When the rejected choice is right

Bun wins for cold-start-sensitive edge functions once adapter-ecosystem parity catches up

Why: mature ecosystem parity with every frontier-provider SDK used

ADR-09

Concurrency model

Chosen

event-loop async per process, one process per adapter type, horizontal replication

Rejected

worker-threads-per-request; shared-memory concurrency

When the rejected choice is right

worker-threads win for genuinely CPU-bound in-process work

Why: all adapter work is a remote inference call, not CPU-bound

ADR-10

Logging

Chosen

structured JSON logs (pino) to a central sink

Rejected

unstructured text logs; per-service bespoke formats

When the rejected choice is right

unstructured logs are tolerable only in a single-file, pre-telemetry Phase-0 spike script

Why: cross-service correlation requires a stable schema

ADR-11

Cancellation semantics

Chosen

explicit cancel(requestId), ≥95% GPU-cost reclaim within 2 s

Rejected

fire-and-forget with after-the-fact billing reconciliation; no-cancel

When the rejected choice is right

no-cancel wins when the provider bills flat-rate reserved capacity regardless of use

Why: viewer skip-ahead is common; billed-per-call providers punish uncancelled work (I11)

ADR-12

Tracing

Chosen

OpenTelemetry, one trace per session, one span per scene

Rejected

per-request-only tracing; vendor-proprietary APM SDK

When the rejected choice is right

per-request tracing wins for a stateless API with no session concept

Why: session-level correlation is the debugging unit, not the request

ADR-13

Metrics

Chosen

Prometheus-format pull metrics, ¢/SH as a derived series

Rejected

StatsD push-only; vendor-proprietary metrics only

When the rejected choice is right

StatsD wins at extremely high per-request cardinality that scraping can't keep up with

Why: per-session cardinality is low enough for pull-based scraping

ADR-14

Image adapter strategy

Chosen

primary frontier image API + self-hosted latent-diffusion successor fallback

Rejected

single-provider only; self-hosted-only

When the rejected choice is right

self-hosted-only wins once GPU-hour cost at scale undercuts frontier per-call pricing (§32 crossover)

Why: multi-provider routing hedges price/availability risk (Rombach et al. 2022)

ADR-15

Music adapter strategy

Chosen

self-hosted MusicGen-class model primary, commercial API as upgrade path

Rejected

commercial-API-only

When the rejected choice is right

commercial-API-only wins pre-validation, before cohort size justifies GPU-ops overhead

Why: GPU-ops overhead is justified once cohort size amortizes it (Copet et al. 2023)

ADR-16

Safety classifier architecture

Chosen

dual-classifier ensemble (general + sleep-mode-specific), both must pass

Rejected

single general classifier; LLM-self-critique-only

When the rejected choice is right

a single general classifier wins for a non-sleep, non-safety-critical context outside this product

Why: sleep mode is the flagship safety promise and needs a dedicated model (Markov et al. 2023)

ADR-17

Test frameworks

Chosen

Vitest (unit) + Playwright (E2E) + custom adapter-conformance suite

Rejected

Jest; Cypress

When the rejected choice is right

Jest wins for a team already standardized on it with large existing investment

Why: fastest TS-native unit runner; Playwright's multi-browser model fits PWA player testing

ADR-18

Fuzzing

Chosen

property-based fuzzing (fast-check) of vibe input and seed deserialization

Rejected

byte-level AFL fuzzing; no fuzzing

When the rejected choice is right

AFL-style byte fuzzing wins for genuinely binary wire formats

Why: the wire format is JSON/structured, not binary

ADR-19

CI/CD

Chosen

GitHub Actions, trunk-based, PR gates on conformance + ¢/SH regression report

Rejected

Jenkins; CircleCI; GitLab CI

When the rejected choice is right

self-hosted Jenkins wins once compliance requires build infra fully inside a private network

Why: lowest operational overhead pre-compliance-era

ADR-20

Packaging

Chosen

per-service Docker images, multi-stage builds, distroless base for adapter wrappers

Rejected

bare-metal deploy; single-monolith container

When the rejected choice is right

a single-monolith container wins only for the Phase-0 throwaway demo, where isolation isn't yet needed

Why: isolation between adapter processes matters for the health/cancel contract

ADR-21

Security (encryption)

Chosen

per-user envelope encryption (JWE, RFC 7516) via KMS, least-privilege IAM per service

Rejected

application-level shared-key encryption; no encryption at rest

When the rejected choice is right

shared-key encryption wins for a single-tenant internal tool with no cross-user isolation requirement

Why: multi-tenant isolation is a hard invariant (I10, I12)

ADR-22

Release strategy

Chosen

Changesets-driven semver, minor bi-weekly, major at phase boundaries

Rejected

continuous-deploy-every-merge with no version pinning; manual quarterly releases

When the rejected choice is right

continuous-deploy-every-merge wins for an internal-only tool with no external compatibility promise

Why: the Adapter contract is externally versioned and needs compatibility guarantees

ADR-23

Time source

Chosen

monotonic clock for scheduler deadline arithmetic; wall-clock (NTP) only for user-facing timestamps

Rejected

wall-clock-only for deadlines

When the rejected choice is right

wall-clock-only is fine when deadlines are measured in minutes/hours, not milliseconds

Why: scene deadlines are sub-10-second; wall-clock skew would corrupt deadline math

ADR-24

Backpressure

Chosen

bounded per-session adapter dispatch queue (depth 3), reject new plans when full

Rejected

unbounded queue; drop-oldest

When the rejected choice is right

unbounded queueing wins in offline batch pre-generation with no latency SLO

Why: a live-streaming SLO cannot tolerate unbounded buffering

ADR-25

Licensing

Chosen

Apache 2.0 for published adapter-contract + schema packages; proprietary Composer prompts and classifier weights

Rejected

fully closed-source; fully open including prompts

When the rejected choice is right

fully-open prompts win for a research-only publication with no product moat concern

Why: the contract is a moat-neutral ecosystem play; the prompts/weights are the actual moat

Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alternative 1 — Fully Offline Batch Pre-Generation

[Batch Generator] --> [Object Store] --> [CDN] --> [Player]
        (no live Composer loop; episodes rendered overnight)

Regime where it wins: GPU cost per live call far exceeds what a subscription can bear, or latency tolerance is measured in hours. Real system embodying it: personalized-trailer batch-rendering pipelines used by large streaming services for promotional assets. Rejected because: it kills the "never told before, right now" real-time promise and reintroduces a library-like ceiling on variety — the opposite of the product's differentiation.

Alternative 2 — Fully Client-Side Generation

[Viewer Device: local Composer + local Adapters] --> local playback
        (no server round trip at all)

Regime where it wins: extreme privacy requirements, zero marginal server-side cost at scale, offline usage. Real system embodying it: emerging on-device LLM/diffusion apps using WebGPU/ONNX Runtime Web. Rejected because: Phase-1-era consumer hardware cannot run a frontier-quality multi-modal stack inside the latency budget (§4), and it forfeits the multi-provider cost-arbitrage moat (§19).

Alternative 3 — Peer-to-Peer / Federated World-Hosting

[Peer A] <--> [Peer B] <--> [Peer C]   (mesh; each hosts partial world shards)

Regime where it wins: censorship-resistant distribution, community-run infrastructure. Real system embodying it: BitTorrent-style content distribution / federated systems (ActivityPub). Rejected because: the non-bypassable safety-classification invariant (I3, P4) requires a trusted, centrally auditable gate — a federated model cannot guarantee that untrusted peers apply it.

Alternative 4 — Single-Modality-First, No Real-Time Scheduler

[Viewer] <-> [Chat Loop] -> text now; image/audio fetched async, later
        (no buffer-ahead scheduling, no scene-level modality fan-out)

Regime where it wins: a much simpler engineering bar when narrative text alone is the product. Real system embodying it: AI Dungeon's original architecture (§5 Reference Implementations). Rejected because: it forfeits the multi-modal ambient/visual sleep-aid experience that defines the product's differentiation and the sleep wedge's core value proposition.
