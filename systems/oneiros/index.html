Viewer Browser (untrusted): submits vibe input, plays the emitted scene stream, never talks to model providers or another user's world directly.

Edge/API Tier (trusted): owns authentication, session lifecycle, and every cross-user isolation check (I12). Hosts the Composer and Streaming Runtime.

Composer: the sole writer to the Persistent World Store (P1); plans N scenes ahead from world state + vibe; single-threaded per session (I1).

Persistent World Store: per-user encrypted durable state — Worlds, Characters, Threads, Vibe history — schema-versioned and forward-migrating only (P8, I9).

Scene Scheduler / Streaming Runtime: dispatches modality-adapter calls in parallel for the next scene while the current scene plays; enforces the buffer-ahead invariant (I7) and the latency budget (§4).

Modality Adapter Bus: pluggable adapters — text, image, music (Phase 3–4), video (Phase 9); voice deferred (Deferred Features Register) — behind one interface (§11); each independently swappable (P2) and independently health-checked.

Safety Classifier Ensemble: gates every adapter output before it reaches the cache or the viewer (P4, I3); applies the strictest tone envelope in sleep mode (I4).

GPU Orchestration Pool: routes each adapter call across frontier APIs and self-hosted pools to hold ¢/SH inside the phase ceiling (P9, §4); reclaims cost on cancellation (I11).

CDN / Edge Asset Cache: caches classified assets for resume and repeat-hit amortization (§20).

Style Pack Engine / Seed-Sharing / Creator Studio (deferred, dotted boxes not drawn above — see Deferred Features Register): planned consumers of the same Adapter Bus and PWS once licensed and social features are in scope.

Boundary Summary

Every arrow in §3's diagram crosses exactly one of four boundary types; naming them explicitly keeps later sections (§9 ADRs, §22 Threat Model) consistent with the diagram rather than re-deriving it ad hoc.

Boundary Type Where It Sits Enforced By
Trust boundary Viewer Browser ↔ Edge/API Tier Auth (§11), per-user scoping (I12, P11)
Trust boundary Edge/API Tier ↔ Modality Adapter processes Safety Classifier Ensemble (P4, I3) treats every adapter output as untrusted
Concurrency boundary Composer ↔ Persistent World Store Single-writer lock (I1, P1)
Concurrency boundary Scene Scheduler ↔ Modality Adapter Bus Bounded dispatch queue (ADR-24), per-requestId cancellation (I11)
Persistence boundary In-memory scheduler state ↔ PWS Scene commit is the durability point (§8.3); nothing before committed survives a crash
Persistence boundary Classified assets ↔ CDN Edge Asset Cache Cache promotion gated on provenance (I8, §20)
Protocol boundary Viewer Browser ↔ Streaming Runtime WebSocket + HLS (ADR-05, ADR-07), versioned envelope (§25)
Protocol boundary GPU Orchestration Pool ↔ external providers Per-provider HTTP client with a declared capability contract (§11.4)

Two boundary types deliberately do not appear above: there is no consensus/coordination boundary (per-world locking is local, never a distributed-consensus round, §29), and there is no cross-user boundary inside the Persistent World Store itself (isolation is enforced at the query layer, I12, not by physical partitioning — see ADR-04's rejection-regime column for when that would change).

8. Domain Model

8.1 Core Entities

World → Character[] / Thread[] / Location[]; Scene is the atomic streaming unit; ModalityAsset is a scene's rendered output; Stream is a viewer session; Seed is a re-hydration payload (type defined now, feature deferred — see Deferred Features Register). Full signatures in §11.

8.4 Worked Example

Vibe input "a foggy coastal town that remembers my name", mode sleep. Composer plans scene index 0: mood = {arousal: -0.4, valence: 0.1, descriptors: ["foggy","quiet","welcoming"]} — inside the sleep-mode tone envelope (I4). Scheduler dispatches adapter-text (≈40-word prose), adapter-image (1024×1024, style hint ["soft palette","low contrast"]), adapter-music (30 s loop, 58 BPM). All three return within p95 budget (§4). Classifier Ensemble passes all three. Scene commits; streams as WebSocket envelope scene-start → asset-ready ×3 → scene-end. Composer ingests completion, updates World.vibeHistory, plans scene index 1.

8.5 Malformed-Input Example

A vibe input contains a 12,000-character adversarial string attempting prompt injection ("ignore all safety instructions and…"). The vibe is treated as untrusted (P4-adjacent) — it is never elevated to system-prompt scope. The Composer emits a graceful reinterpretation scene rather than an error. If the injection targets content-profile axes directly, the profile's 30-minute change cooldown prevents any single vibe from raising the ceiling; I4 remains enforced regardless of vibe content.

8.6 Failure-Path Example

adapter-image times out at 6 s (p95 budget 4 s, hard timeout 6 s). The scheduler cancels the in-flight call (I11: ≥95% cost reclaim within 2 s) and falls back to adapter-text-only for that scene slot (P13). The scene is flagged modalitySlots: ["text"], degraded: true, surfaced via scheduler.modality_fallback. The next scene retries image at full budget. No viewer-facing error appears; I7 still holds because the degraded scene counts as "ready" once text-only commits.

8.7 Cross-Subsystem Incident Trace (Resume After a Regional Failover)

A worked trace tying together §13 (PWS), §17 (Scheduler), §19 (GPU Orchestration Pool), and §24 (Operational Readiness), illustrating why the invariants in §7 are designed to compose:

  1. T+0s — the Postgres primary in Region A fails. pws.resume_latency_p95 and the connection-pool health check both fire (§13.9).
  2. T+2s — the session orchestrator marks every in-flight Stream in Region A buffering (§8.2) rather than ended; I7's buffer-ahead guarantee degrades to the declared "buffering" state, never a silent stall.
  3. T+5min — the read replica is promoted (RTO ≤5 min, §4); PWS writes resume against the new primary; the WAL position at failover is logged as a forensic artifact (FM-13-adjacent, §23).
  4. T+5min+ε — resumed sessions re-enter active (§8.2); the Composer's single-writer lock (I1) re-acquires cleanly because the lock itself lived in the (now-promoted) database, not in process memory.
  5. T+5min+1s — the Scheduler re-dispatches the scene that was rendering at failover time; because that scene was never committed (§8.3), I5's monotonic-no-gap invariant is untouched — the replay resumes at the same scene index, not a new one.
  6. T+5min+3s — the GPU Orchestration Pool's circuit breakers (§19) are unaffected by the database failover (a different trust boundary, §3), so in-flight adapter calls that survived the failover window complete normally; any that did not are cancelled and reclaimed per I11.

This trace is why I1 (single-writer), I5 (scene-sequence monotonicity), I7 (buffer-ahead-or-declared-buffering), and I11 (cancellation reclaim) are independent invariants rather than one combined "session health" check: each one fails, is detected, and recovers on its own timeline, and the sim-harness (§12, §26) asserts each independently for exactly this reason.

8.8 Worked Example — Video Session Cold Start (Phase 9)

A second worked example, chosen because video's cost/latency profile (§4, §32 item 12) makes cold start qualitatively different from the Phase 1 text+image+music case in §8.4:

  1. Viewer opens a world with licensedStylePackId unset (no style pack, out of scope per the Deferred Features Register) and submits vibe "a rain-soaked cyberpunk alley, something is following me", mode free.
  2. Composer plans scene index 0 with mood = {arousal: 0.3, valence: -0.2, descriptors: ["tense","neon-lit","rain"]} — outside any sleep-mode rail since mode !== "sleep" (I4 does not apply here).
  3. Scheduler dispatches adapter-video with no prior clip to stitch from (§21.8 edge case): the stitching layer falls back to a static establishing image (P13, video→image degradation) for this first scene only.
  4. adapter-video renders the first real clip against the establishing image as its sole conditioning input (no PersistentCharacter.appearance.seed yet, since no character has appeared); latency lands at the p95 budget of 30 s (§4, M5).
  5. From scene index 1 onward, the stitching layer conditions each clip on the previous clip's last frame plus any now-established character seeds, and the streaming runtime's 30 s pre-warm buffer (§21.2) is fully established, hiding all subsequent cold-start-class latency from the viewer.

This example is why Phase 9's Acceptance Criteria (§21.4) are measured over a 30-minute cohort rather than a single scene: the first-scene cold start is expected and budgeted for, while the cost/continuity story is only meaningful once the buffer has stabilized.

Design principles (§6)

  • P1 — Single-writer worlds. The Composer is the sole writer to a world's persistent state, serialized per-session by the session orchestrator. Tradeoff: no concurrent multi-agent editing of one world. Operational: write contention shows up as scheduler queue depth, never DB lock contention. Violating it: two Composer instances writing the same world causes character-identity collapse (I2).
  • P2 — Adapters are swappable, not bespoke. Every modality adapter implements one bounded interface (§11); provider swap is a deploy, not a migration. Tradeoff: the interface caps how much provider-specific capability can be exposed. Violating it: a provider price hike becomes existential (R-class risk).
  • P3 — One viewer, one stream. No shared mutable state across sessions; no synchronous co-viewing. Tradeoff: no live shared streams. Operational: horizontal scaling is embarrassingly parallel per session. Violating it: cross-session state leakage is a privacy incident (T3).
  • P4 — Classify the output, not the plan. Safety classification runs on every adapter output before delivery, never on the Composer's internal plan alone. Tradeoff: added latency inside the scene budget. Violating it: an unclassified plan can still emit unsafe adapter output.
  • P5 — Defense in depth for sleep mode. The sleep-mode tone envelope is enforced at three independent layers: Composer planning constraint, adapter routing constraint, output classifier. Tradeoff: triple-checked cost. Violating it (single-layer enforcement): one layer's bug becomes a production safety incident with no backstop.
  • P6 — Always one scene ahead. The scheduler keeps ≥1 fully rendered scene ahead of playback (I7). Tradeoff: wasted GPU spend on unplayed scenes if the viewer exits early, bounded by cancellation (P10). Violating it: visible stutter breaks the immersion contract.
  • P7 — No anonymous assets. Every generated asset carries provenance (prompt hash, seed, model version). Tradeoff: extra columns per asset row. Violating it: cannot answer "what did we show this viewer" after the fact.
  • P8 — Forward-only schema evolution. Schema changes are additive; no breaking change to a persisted world. Tradeoff: schema accretion over years, mitigated by dual-version support (I9). Violating it: a viewer's multi-year world becomes unreadable.
  • P9 — Cost is a gated metric. ¢/Stream-Hour is checked in CI like a test, not reviewed after the invoice arrives. Tradeoff: slower feature velocity near a ceiling. Violating it: silent cost creep triggers phase kill-criteria (§34-adjacent risk).
  • P10 — Cancellation reclaims cost. Cancelling an in-flight adapter call must reclaim ≥95% of its GPU cost within 2 s (I11). Tradeoff: every adapter must expose a real cancel path, not an abandoned promise. Violating it: viewer skip-ahead behavior bankrupts the cost model.
  • P11 — Scope every cross-user access at the data layer. PWS reads are scoped by authenticated userId, never trusted from the caller. Tradeoff: extra scoping code on every query. Violating it: cross-user world leakage (T3), automatic Sev-1.
  • P12 — Every tradeoff gets an ADR with a regime for the loser. Every latency-vs-quality or cost-vs-fidelity decision is recorded with the regime where the rejected choice wins (§9). Tradeoff: authoring overhead per decision. Violating it: decisions get silently re-litigated by the next engineer.
  • P13 — Degrade the modality, not the scene. A dead or slow adapter falls back to a cheaper modality (video→image→text) rather than failing the whole scene. Tradeoff: viewer sees lower fidelity, never an error. Violating it: a single-provider outage takes down the entire stream.
  • P14 — Identifiers are branded, never bare strings. Every *Id type (§11.8) is a distinct compile-time type, not an interchangeable string. Tradeoff: a small amount of type-declaration ceremony at every boundary. Operational: cross-ID-type bugs (passing a CharacterId where a SceneId belongs) are caught at compile time, not in production. Violating it: a whole class of silent data-corruption bugs becomes possible at every PWS/adapter boundary.
  • P15 — Estimates are reconciled against ground truth, never trusted standalone. Real-time cost and audit telemetry are estimates; they are reconciled against an authoritative source (provider invoice, storage listing) on a fixed cadence. Tradeoff: a reconciliation job and its own monitoring (cost.reconciliation_delta, T12). Operational: divergence between estimate and ground truth is itself an alertable signal. Violating it: cost or audit drift goes undetected until it becomes a financial or compliance surprise.
