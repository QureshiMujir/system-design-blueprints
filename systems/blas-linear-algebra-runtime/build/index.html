⬜ Phase 0 — Skeleton: storage, views, scalar trait, machine probe, a working scalar dot §12

Objectives
  • Stand up the Cargo workspace (ADR-2) and the la-core + simd skeleton.
  • Define MatView/MatViewMut/VecView and the Scalar trait for f32/f64.
  • Implement the machine probe (Machine/Isa).
  • Ship one runnable, oracle-verified kernel (dot, scalar) end-to-end.
  • Establish the test/bench scaffolding every later phase reuses.
Deliverable
  • cargo run -p bench --bin probe prints cache sizes, ISA, vreg count, FMA-peak estimate.
  • cargo test runs dot vs oracle and the view/stride unit tests.
Acceptance
  • dot matches oracle to ‖err‖ ≤ n·u·‖x‖·‖y‖ on 10³ random vectors.
  • All view/stride operations pass Miri (no UB).
  • Probe output correct on CI x86-64 and aarch64.
Fixtures
  • numerics/dot_{small,large,mixed_sign}.json — inputs + expected + tolerance.
  • badargs/dot_neg_inc.json — invalid inc → typed error.
  • golden/probe_{x86,aarch64}.json — expected Machine per CI arch.
Pitfalls
  • isize stride overflow on huge lda → use checked math at the validation boundary.
  • Negative inc (BLAS convention: traverse from the end) → encode in VecView::nth.
  • cpuid cache-size leaves differ AMD vs Intel → fall back to sysconf.
  • Aligned alloc must be paired with aligned free → wrap exclusively in AlignedArena.

⬜ Phase 1 — Level-1 BLAS complete + SIMD reduction patterns §13

Objectives
  • Implement all Level-1 kernels for f32/f64: axpy, dot, nrm2, scal, asum, iamax, rot, rotg, copy, swap.
  • SIMD-accelerate with correct reductions and over/underflow-safe norms.
  • Lock the SIMD-reduction patterns reused by every later level.
Deliverable
  • level1 crate green against the oracle.
  • bench shows axpy/dot ≥ 80 % of STREAM bandwidth.
Acceptance
  • Every kernel within its error bound vs oracle.
  • nrm2([1e200, 1e200]) = 1.414e200, not Inf.
  • Multi-accumulator dot error bound ≤ (n/A + A)·u (A = #accumulators) documented.
Fixtures
  • numerics/nrm2_overflow.json, nrm2_underflow.json — scaling correctness.
  • numerics/iamax_ties.json — first-index tie rule.
  • numerics/axpy_alpha0.json — α=0 no-op.
  • numerics/rotg_quadrants.json — Givens sign/quadrant coverage.
Pitfalls
  • Naïve sum-of-squares over/underflows → must use the scaled algorithm.
  • Horizontal reduce ordering changes bits → fix one order (I4).
  • iamax tie-break must match BLAS (lowest index), not "first SIMD lane."
  • Forgotten scalar tail → reads past the end (fuzz len % vlen ≠ 0).

⬜ Phase 2 — Naïve Level-3 GEMM oracle + Level-2 kernels (the correctness anchor) §14

Objectives
  • Build a simple, obviously-correct triple-loop GEMM as the differential oracle (all trans/layout combos via MatView).
  • Implement the full Level-2 kernel set.
  • Speed is irrelevant here; correctness is total — this unblocks every later L3 optimization (they all diff against this).
Deliverable
  • Naïve gemm + full Level-2 green vs hand-computed cases and Netlib reference semantics.
Acceptance
  • Oracle gemm passes 5k random {shape × trans × layout × α,β} cases.
  • All Level-2 kernels within error bound.
  • trsv solves Tx=b to residual ≤ c·n·u·κ.
Fixtures
  • gemm/oracle_{NN,NT,TN,TT,CN,…}.json — every trans/layout combination.
  • level2/gemv_beta.json — β handling.
  • level2/trsv_unit_diag.json — unit-diagonal solve.
  • level2/symv_upper_lower.json — uplo coverage.
Pitfalls
  • Row/col-major identity is easy to invert → assert RowMajor C=AB equals ColMajor Cᵀ=BᵀAᵀ.
  • trsv with Unit diag must not read the diagonal (it may hold garbage).
  • Complex C (conjugate) vs T (plain transpose) confusion.
  • β handling when k=0 (result must be C := βC).

⬜ Phase 3 — The register-blocked SIMD micro-kernel (AVX2/FMA) §15

Objectives
  • Implement the mr×nr register-blocked micro-kernel for f64 (then f32) on AVX2+FMA.
  • Keep the C micro-tile in YMM accumulators; stream kc rank-1 updates; scale/axpy on exit.
  • Provide a scalar fallback kernel with identical semantics.
  • This is the performance heart — correctness plus register-pressure discipline.
Deliverable
  • microkernel::avx2 computes a single mr×nr block correctly.
  • Integrated into a temporary pack-less driver (test scaffold) and diffed against the oracle.
Acceptance
  • Matches oracle for all kc ∈ [0,256], all α,β combinations, and edge tiles (<mr, <nr).
  • No register spill (verified via disassembly / perf — no extra loads in the inner loop).
  • Tiny-shape fuzz (I3) clean under ASAN.
Fixtures
  • gemm/microkernel_kc_sweep.json — accumulation over a range of kc.
  • gemm/microkernel_edge_{partial_m,partial_n}.json — sub-tile edges.
  • gemm/microkernel_beta0_nan.json — β=0 must clear C (I5).
Pitfalls
  • Register spill from too-large mr·nr — the #1 perf cliff; verify in asm.
  • Unaligned C store (C tile carries user stride) — use unaligned store, or stage edge tiles via a temporary.
  • Too few independent accumulator chains → FMA latency not hidden.
  • β=0 must NOT load C (would read NaN, I5).
  • _mm256_fmadd_pd operand order: numerically inert but pick a consistent "c" operand.

⬜ Phase 4 — Packing + macro-kernel: the real GEMM driver §16

Objectives
  • Implement packing (Ap col-of-mr, Bp row-of-nr; padded, aligned, transpose+conj folded in).
  • Implement the macro-kernel looping the micro-kernel over a packed block.
  • Assemble the full single-block-sized GEMM — the Goto unlock: contiguous, aligned, reused operands.
Deliverable
  • level3::gemm correct for all shapes/trans/layout via pack+macro+micro; diffed against the oracle at scale.
Acceptance
  • Matches oracle (error bound) on 5k cases including non-multiple-of-block shapes.
  • Pack round-trip test: unpack(pack(X)) == X.
  • Single-thread GFLOP/s ≥ 40 % peak (pre cache-blocking) for mid sizes.
Fixtures
  • gemm/pack_roundtrip_{N,T,C}.json — pack/unpack identity per transpose mode.
  • gemm/full_driver_random.json — randomized end-to-end.
  • gemm/non_multiple_shapes.json — m,n,k not multiples of block sizes.
Pitfalls
  • Pack layout must match the micro-kernel's expected stride → test pack+kernel together (subtle).
  • Zero-padding must be real zeros (α·0 contributes 0).
  • Transpose folded into pack vs into the view — pick one and document.
  • Pack cost can dominate for small k — measure pack_ns vs compute_ns.

⬜ Phase 5 — Three-level cache blocking + block-size derivation §17

Objectives
  • Implement the full five-loop nest (§8.4) with mc,kc,nc derived from the machine probe.
  • Guarantee Bp ⊂ L3, Ap ⊂ L2, micro-tile ⊂ registers.
  • Push single-thread GEMM to ≥ 80 % peak.
Deliverable
  • gemm at ≥ 80 % peak (dgemm, large square, 1 thread) + a roofline plot.
Acceptance
  • FLOPS %-of-peak ≥ 80 % on the CI reference CPU for n ∈ {512,1024,2048,4096}.
  • Correctness unchanged (re-diff oracle).
  • Block sizes in the trace match derived values.
Fixtures
  • gemm/blocksize_derivation_{cpuA,cpuB}.json — Machine → BlockSizes expected.
  • golden/gemm_flops_baseline.json — per-size %-peak floor.
Pitfalls
  • kc too large → Ap evicts Bp from L2 (capacity/associativity) → measure misses, tune.
  • nc ignoring L3 sharing across threads → contention in P6.
  • Set-associativity conflicts (power-of-two strides) → pad panel strides.
  • TLB misses for a huge Bp → consider huge pages (deferred §24).

⬜ Phase 6 — Multithreading: loop partition, pool, scaling §18

Objectives
  • Parallelize GEMM across cores by partitioning the jc (and ic for tall-skinny) loops.
  • Use a fixed thread pool, per-thread pack buffers, and a shared-Bp strategy.
  • Target ≥ 0.85× linear scaling.
Deliverable
  • Multi-threaded gemm + a scaling curve in bench.
Acceptance
  • ≥ 0.85× linear to physical cores for large square.
  • No races (TSan clean); result deterministic per thread count (I4).
  • Partition is a disjoint cover (I11 test: ranges sum to total, no overlap).
Fixtures
  • gemm/threaded_determinism.json — identical result at 1/2/4/8 threads within bound.
  • golden/scaling_curve.json — expected scaling efficiency.
Pitfalls
  • False sharing on C-tile boundaries → align partitions to cache lines / nr.
  • Shared Bp write race if a thread re-packs → make Bp read-only-shared or per-thread.
  • Oversubscription via nested BLAS (LAPACK → threaded GEMM) → thread-count context.
  • NUMA remote Bp access (first-touch deferred — Deferred Features Register — but documented).
  • Pool startup latency on the first call.

⬜ Phase 7 — Complex arithmetic (c32/c64) across all levels §19

Objectives
  • Extend L1/L2/L3 and the micro-kernel to interleaved complex.
  • Implement correct conjugation semantics (Trans::C) and complex FMA.
Deliverable
  • All routines for c32/c64 + complex conformance suite.
Acceptance
  • Complex GEMM/factorizations vs complex oracle within bound.
  • dotc conjugates the first argument; hemm/herk Hermitian semantics correct.
  • Complex geqrf produces a unitary Q.
Fixtures
  • numerics/dotc_vs_dotu.json — conjugation correctness.
  • gemm/complex_conj_trans.json — T vs C coverage.
  • factor/herk_hermitian.json — Hermitian rank-k.
Pitfalls
  • T vs C confusion (transpose vs conjugate-transpose).
  • Complex-multiply rounding (4-mul has a different error profile than 3-mul).
  • Interleaved layout (ADR-12) → SIMD complex needs shuffle/permute for re/im.
  • Hermitian diagonal must be treated as strictly real.

⬜ Phase 8 — Derived Level-3: SYMM, SYRK, SYR2K, TRMM, TRSM §20

Objectives
  • Implement the remaining Level-3 ops as structured GEMM variants (Kågström 1998).
  • Prioritize TRSM (triangular solve, multiple RHS) — the op LAPACK leans on most.
Deliverable
  • Full Level-3 BLAS; TRSM ready for the LAPACK layer.
Acceptance
  • Each op vs oracle within bound.
  • syrk produces an exactly symmetric result (mirror tiles consistent).
  • trsm residual ≤ c·n·u·κ over all 8 case combinations.
  • FLOPS within 70–90 % of GEMM (structured ops have less reuse).
Fixtures
  • factor/trsm_{LLNN,LUNN,RLTN,…}.json — the full case matrix.
  • factor/syrk_upper_lower.json — uplo coverage.
  • factor/trmm_unit_diag.json — unit-diagonal handling.
Pitfalls
  • TRSM diagonal-block solve is sequential — block-size tradeoff (small → more GEMM, large → sequential cost).
  • syrk mirror-tile skipping must still yield a correct triangle per uplo.
  • Unit diagonal in TRSM/TRMM (never read the diagonal).
  • In-place TRSM (B overwritten) aliasing.
  • Numerics: TRSM of an ill-conditioned triangular amplifies error.

⬜ Phase 9 — LU and Cholesky factorization (blocked, right-looking) §21

Objectives
  • Implement getrf (LU, partial pivoting) and potrf (Cholesky, SPD), blocked to maximize the level-3 fraction.
  • Implement getrs/potrs solves with stability instrumentation.
Deliverable
  • getrf/potrf/getrs/potrs; solve Ax=b end-to-end (examples/solve_lu).
Acceptance
  • ‖PA−LU‖/‖A‖ ≤ c·n·u·ρ; ‖A−LLᵀ‖/‖A‖ ≤ c·n·u·κ.
  • Solve residual ‖Ax−b‖/(‖A‖‖x‖) ≤ c·n·u.
  • Indefinite input → correct info (I7).
  • Level-3 fraction > 90 % for large n (most flops in GEMM).
Fixtures
  • factor/getrf_{wellcond,illcond,singular}.json.
  • factor/potrf_{spd,indefinite}.json.
  • solve/lu_solve_residual.json.
  • Hilbert/Pascal/Wilkinson matrices (known conditioning/growth).
Pitfalls
  • Forgetting to apply pivots to BOTH the done-columns (left) and the trailing matrix (right) — the classic bug.
  • Growth-factor blow-up on pathological matrices (Wilkinson) → record, document partial-pivoting limits.
  • Cholesky sqrt of a tiny-negative pivot (rounding on near-singular SPD) → info threshold.
  • Panel width too small → memory-bound; too large → unblocked-panel cost dominates.
  • In-place factor aliasing of the pivot vector.

⬜ Phase 10 — QR (Householder) + least-squares + iterative refinement §22

Objectives
  • Implement geqrf (blocked Householder QR with WY block reflectors).
  • Implement ormqr/orgqr (apply/form Q) and gels (least-squares via QR).
  • Add optional iterative refinement to recover solve accuracy.
Deliverable
  • QR + least-squares; examples/least_squares fits an overdetermined system.
Acceptance
  • ‖QR−A‖/‖A‖ ≤ c·n·u; orthogonality ‖QᵀQ−I‖ ≤ c·n·u (I8).
  • gels residual is minimal for the system.
  • Refinement reduces residual toward u for moderately conditioned A.
  • Level-3 fraction high.
Fixtures
  • factor/geqrf_orthogonality.json.
  • solve/gels_overdetermined.json, solve/gels_underdetermined.json.
  • refine/illcond_refinement.json.
Pitfalls
  • Householder sign: choose −sign(x₁)‖x‖ to avoid cancellation.
  • Classical Gram-Schmidt loses orthogonality — never use it (I8).
  • Forming Q explicitly when only Qᵀb is needed wastes flops → use ormqr.
  • WY T build cost vs block size tradeoff.
  • Working-precision refinement has limited gain (extra-precise residual deferred).

⬜ Phase 11 — CBLAS / LAPACKE C ABI §23

Objectives
  • Provide a drop-in C ABI: cblas_?gemm, all L1/L2/L3, plus a LAPACKE subset (LAPACKE_?getrf, …).
  • Exact enum values, row/col-major handling, and an xerbla error path — linkable by existing C/Fortran code.
Deliverable
  • libla.so/.a + cblas_la.h; examples/cblas_from_c.c links and runs.
Acceptance
  • A C program calling cblas_dgemm gets identical results to the Rust facade.
  • Enum integer values match reference CBLAS exactly.
  • Bad-arg calls invoke xerbla with the correct position, no compute (I12).
  • No unwinding across the FFI boundary.
Fixtures
  • badargs/cblas_param_positions.json — each routine's bad-arg → xerbla position.
  • abi/rowmajor_colmajor_equiv.json — layout equivalence.
  • A C integration test compiled and run in CI.
Pitfalls
  • Enum-value mismatch (silent wrong op) — pin to the reference header, test.
  • Row-major LAPACKE needs a transpose-copy (LAPACK is col-major) — manage workspace.
  • Complex scalars are passed by pointer, not by value.
  • Panic across FFI = UB → catch_unwind everywhere.
  • int width: pick LP64, document; ILP64 deferred.
  • Thread-count env compatibility with OpenBLAS expectations.

⬜ Phase 12 — Performance hardening (the long pole) §24

Objectives
  • Close the gap to ≥ 80 % peak single-thread / ≥ 0.85× scaling across the full size sweep.
  • Levers: prefetch tuning, edge-case kernels, packing optimization, small-matrix path, AVX-512/NEON micro-kernels (gated).
Deliverable
  • FLOPS sweep meeting constraints across n ∈ [64, 8192]; AVX-512 path measurable on a capable CPU.
Acceptance
  • ≥ 80 % peak (dgemm) sustained across the sweep.
  • Small-matrix path beats the blocked path below threshold.
  • AVX-512 ≈ 2× AVX2 where available.
  • No correctness regression (re-diff oracle).
Fixtures
  • golden/flops_sweep_full.json — per-size %-peak floor.
  • gemm/small_matrix_path.json — small-path correctness + crossover.
  • ISA-specific golden hashes.
Pitfalls
  • Prefetch too aggressive evicts useful lines.
  • AVX-512 downclocking can make it slower than AVX2 for memory-bound sizes — measure, don't assume.
  • Small-matrix overhead (the blocking machinery) — branch early.
  • Look-ahead complexity vs gain.
  • NEON has 32 regs → a different mr×nr optimum.

⬜ Phase 13 — Conformance, differential, fuzzing, benchmarks §25

Objectives
  • Lock correctness and performance with a full conformance suite.
  • Components: differential vs oracle, numerical error-bound assertions, micro-kernel/pack fuzzing, factorization residual suite, reproducible FLOPS report.
Deliverable
  • make conformance green; make bench emits a report; make fuzz runs N iterations clean.
Acceptance
  • 100 % differential pass within bounds.
  • Fuzz clean ≥ 10⁷ iterations (extended 30-day runs deferred).
  • Determinism hashes stable; bench meets all §4 constraints.
  • Coverage of all CBLAS routines + factorizations.
Fixtures
  • Full conformance/ corpora: gemm/, level2/, factor/, numerics/, badargs/, golden/.
  • Structured matrices (Hilbert, Wilkinson, random orthogonal) with known properties.
Pitfalls
  • Tolerance too tight (false fails on legit rounding) or too loose (misses bugs) — derive from theory (Higham).
  • Fuzz corpus not exercising edge tiles (m%mr, etc.).
  • Determinism hash breaks legitimately when blocking changes — version the golden set with the numeric contract.
  • Bench noise (turbo, noisy neighbors) → pin + median.
