Query engine output shapes (five, fanning out from the box above): P2P (single least-cost path + cost), one-to-many (reachable set / distances to many targets), isochrone (a time-budget polygon, GeoJSON), matrix (a dense |S|×|T| cost matrix), alternatives (a small set of admissible near-optimal paths).

Per-box detail:

  • OSM PBF FILE — the untrusted input: a .osm.pbf extract (city to planet). A sequence of length-prefixed Blobs, each zlib-compressed protobuf (OSMHeader once, then many OSMData/PrimitiveBlock). May be truncated, oversized, or hostile. Read-only, streamed; never fully materialized when avoidable.
  • PBF PARSER — reads BlobHeader (length-prefixed), inflates the zlib blob, decodes the protobuf PrimitiveBlock: a string table plus primitive groups of dense-nodes (delta + zig-zag packed), ways (node-ref deltas + tags), relations (members + tags). Bounds-checks every length; caps allocation by declared sizes. Emits a stream of (NodeRecord | WayRecord | RelationRecord).
  • PROFILE — maps OSM tags to routing semantics: access (is this way routable for the mode?) and speed (→ travel-time weight) and turn/penalty defaults. Ships as a hardcoded car profile; the general tag→weight DSL is PhaseDeferred("Phase 1 — OSM PBF Ingest → Routing Graph"). Pure function of tags; deterministic.
  • GRAPH BUILDER — the topology compiler: identifies intersections (nodes referenced by ≥2 ways, or way endpoints), collapses interior geometry nodes of a way into a single weighted edge (preserving polyline for output), applies oneway direction, and lowers turn-restriction relations into either forbidden turns (edge-expanded) or turn-table entries. Produces node/edge id assignment.
  • CSR GRAPH (fwd + rev) — the in-memory routing graph in compressed-sparse-row form: head[n+1] offsets, edges[m] of {target, weight}; a parallel reverse CSR for backward search; coords[n] for heuristics and output. Optionally an edge-expanded form when turn costs are active. Immutable after build; the hot data structure all search scans.
  • ALT PREPROCESS — selects landmarks (avoid / farthest / planar), runs a full Dijkstra forward and backward from each landmark, stores dist(L,·) and dist(·,L) tables. Output feeds triangle-inequality lower bounds at query time.
  • CH PREPROCESS — orders nodes by importance (edge difference, deleted neighbors, etc.), contracts them lowest-first, running witness searches to decide which shortcuts are necessary, and emits the up/down graph + ranks + per-shortcut middle node. Slow (minutes–1 h), metric-bound (re-run on weight change).
  • CRP PREPROCESS — computes a metric-independent multilevel partition (inertial flow / PUNCH-style) and the overlay topology (which boundary vertices connect within each cell) — once. The CUSTOMIZE step then computes overlay arc weights for a given metric (live traffic), bottom-up, in seconds.
  • ROUTING INDEX — the versioned, immutable, memory-mappable artifact bundling every preprocessed structure plus a metadata header (OSM extract SHA, profile id, tool version, technique set). Atomically swapped on rebuild; shared read-only across query threads.
  • QUERY ENGINE — loads the index and answers queries: snap a coordinate to the nearest routable edge, then run the chosen algorithm (bidirectional Dijkstra, A*/ALT, CH with stall-on-demand + unpacking, CRP overlay search, TD-Dijkstra for a departure time, PHAST for one-to-all). Stateless per query; the index is read-only.

8. Domain Model / Protocol / Data Model

8.1 The road graph

A directed weighted graph G = (V, E). A node is an intersection (a point where routing decisions happen); an edge is a directed road segment from one intersection to the next, weighted by a metric (travel time or distance). A two-way street is two directed edges. weight: u32 is travel time in deciseconds (0.1 s units → 119 h fits in u32 minus the INF sentinel) or distance in meters, chosen per metric. u32::MAX is reserved as INF / unreachable (I16). Coordinates Coord{lat_e7, lon_e7} are fixed-point degrees × 10⁷ (i32), exact and float-free for snapping/output; floats appear only in the Haversine bound and geometry export.

Road networks have exploitable structure: near-planar, low average degree (~2–3), sparse (m ≈ 2.5n), with a natural hierarchy (few high-speed arterials carry most long routes). CH exploits the hierarchy via importance ordering; CRP exploits near-planarity via small partition cuts; A*/ALT exploit the geometric embedding.

8.2 CSR (Compressed Sparse Row) layout

The canonical adjacency layout for a static graph. Two arrays:

head:  [u32; n+1]      // head[v]..head[v+1] is v's out-edge range
edges: [Edge; m]       // Edge { target: u32, weight: u32 }   (sorted by source, then target)

Out-neighbors of v = edges[head[v] .. head[v+1]] — a contiguous slice, so neighbor iteration is a linear cache-friendly scan. head[v+1]-head[v] is v's out-degree; head[n]==m (I3). Memory: 4(n+1) + 8m bytes ≈ for 50 M nodes / 120 M edges ≈ 0.2 GB + 0.96 GB. Contrast adjacency-list-of-Vec: ~24 B overhead/node + pointer-chasing per neighbor → ~10× slower and cache-hostile (P5).

Reverse CSR (rev): the transpose, built by counting in-degrees then scattering — needed for backward search (bidirectional Dijkstra, CH/CRP backward, ALT backward tables). Built once at index time.

ASCII: node 0 has edges to {1,2}; node 1 to {2}; node 2 to {0}
head  = [0,        2,     3,    4]
edges = [(1,w),(2,w), (2,w), (0,w)]
         \__node0__/  node1  node2

8.3 Node-based vs edge-based (edge-expanded) graph

Node-based Edge-based (edge-expanded)
Node = intersection a directed road segment
Edge = road segment a turn between two segments
Turn costs not representable on edges natural: weight on the turn-edge
Turn restrictions special-cased omit the forbidden turn-edge
Size n nodes, m edges ~m nodes, ~Σ deg² turn-edges (≈2–4× blow-up)
Used when distance/time metric, no turns turn costs / restrictions active (Phase 5)

The edge-expanded graph (OSRM's representation, R1) makes turn modeling first-class: a U-turn penalty or a no-left-turn restriction is just a turn-edge weight or a missing turn-edge. CH and CRP then run on the edge-expanded graph unchanged. The cost is size; the build collapses degree-2 chains and shares turn tables to limit blow-up.

8.4 Worked example graph

Eight-node fragment (a small grid + a fast arterial), travel-time weights in deciseconds:

      (0)--30-->(1)--30-->(2)
       |         |         |
      40        15        40       arterial 6->7 is fast (weight 50 for a long span)
       v         v         v
      (3)--30-->(4)--30-->(5)
       |                   |
      40                  40
       v                   v
      (6)========50=======>(7)

Edges (directed): 0→1:30, 1→2:30, 0→3:40, 1→4:15, 2→5:40, 3→4:30, 4→5:30, 3→6:40, 5→7:40, 6→7:50. Query 0→7: candidate paths 0→3→6→7 = 40+40+50 = 130; 0→1→4→5→7 = 30+15+30+40 = 115; 0→3→4→5→7 = 40+30+30+40 = 140. Optimal = 115 via 0→1→4→5→7. This OD pair is used throughout (CH walkthrough in Phase 6/7, Dijkstra trace below).

Dijkstra from 0 (settle order, dist): 0(0) → 1(30) → 3(40) → 4(45) → 2(60) → 5(75) → 6(80) → 7(115). Predecessor of 7 = 5; backtrack 7←5←4←1←0. Cost 115 — the oracle answer (I1).

8.5 OSM PBF format

A .osm.pbf file is a sequence of blobs, each a length-prefixed pair (BlobHeader, Blob):

[ 4-byte BE length ][ BlobHeader (protobuf) ][ Blob (protobuf) ]   repeated
BlobHeader { type: "OSMHeader"|"OSMData", datasize: i32 }
Blob       { raw | zlib_data (+ raw_size) }     // payload is zlib-compressed protobuf

The first blob is OSMHeader (bbox, required features, writing program). Subsequent OSMData blobs each inflate to a PrimitiveBlock:

PrimitiveBlock {
  stringtable: [bytes]          // all strings (keys/values) interned; index 0 = ""
  primitivegroup: [PrimitiveGroup]
  granularity: i32 (default 100 nm)   lat_offset, lon_offset
}
PrimitiveGroup = oneof { dense: DenseNodes | ways: [Way] | relations: [Relation] | nodes:[Node] }

DenseNodes (the common node encoding) packs ids, lats, lons as delta-encoded zig-zag varints (each value is a delta from the previous), and tags as a flat keys_vals stream of stringtable indices terminated by 0. Way: id, delta-encoded refs (node ids), and keys/vals (stringtable indices). Relation: id, members (type, ref, role) and tags — turn restrictions live here.

Decoding requires: protobuf varint/zig-zag decode, zlib inflate, delta accumulation, granularity scaling (coord = (offset + granularity·value) / 100). Every length and count is bounds-checked; declared sizes cap allocation (P7, T1/T2).

8.6 Profile (tag → weight)

A profile maps OSM tags to routing semantics for a transport mode. Hardcoded car profile (the DSL is PhaseDeferred("Phase 1 — OSM PBF Ingest → Routing Graph")):

highway= car access default speed (km/h) notes
motorway / motorway_link yes 110 / 60 maxspeed tag overrides
trunk / primary yes 90 / 70
secondary / tertiary yes 60 / 50
residential / unclassified yes 30
service / living_street yes 10–20
footway / cycleway / path / steps no — excluded for car
construction / proposed no — excluded

Weight = length_m / speed_mps → deciseconds, rounded. oneway=yes → forward edge only; oneway=-1/reverse → backward only; oneway=no/absent → both; motorways imply oneway=yes unless tagged otherwise. access=no/private removes the way. The profile is a pure deterministic function of tags (P8); the same tags always yield the same weight.

8.7 Turn restrictions and costs

OSM models restrictions as type=restriction relations: members from (way), via (node or way(s)), to (way), tag restriction=no_left_turn | no_right_turn | no_u_turn | no_straight_on | only_left_turn | …. The graph builder lowers these onto the edge-expanded graph: a no_* restriction deletes the corresponding turn-edge; an only_* restriction deletes all other turn-edges from the from segment at the via. Turn costs (default U-turn penalty, e.g. 300 s; left-turn penalty across traffic) are weights on turn-edges. All turn weights are re-based non-negative (I2, P3). Via-way (multi-segment) restrictions require expanding the via path — handled in Phase 5.

8.8 Time-dependent travel-time functions (TTF)

For time-dependent routing an edge weight is a function f: τ ↦ travel_time of departure time-of-day τ, not a scalar. Represented as piecewise-linear, periodic with period T = 86400 s (one day):

Ttf { points: [(τ_i: u32 /*s of day*/, t_i: u32 /*travel time s*/)], period: 86400 }
// linear interpolation between consecutive breakpoints; wraps at period

FIFO / non-overtaking property (I11, P9): τ1 ≤ τ2 ⇒ τ1 + f(τ1) ≤ τ2 + f(τ2). Equivalently the arrival function a(τ) = τ + f(τ) is non-decreasing, i.e. f'(τ) ≥ -1 on every linear piece. FIFO means departing later never lets you arrive earlier — the precondition that keeps label-setting Dijkstra correct on a time-dependent graph. Probe/measured data is FIFO-repaired (lower later values to respect the bound) or rejected (NonFifoTtf).

Two query types: earliest-arrival (fix departure τ0, minimize arrival at t) via TD-Dijkstra evaluating f at each node's arrival time; profile (compute arrival as a function of all departures) via function composition (link: f∘g) and minimum (merge: pointwise min of two PWL functions). TCH shortcuts store composed TTFs and grow large → approximate TCH (PhaseDeferred("Phase 8 — Time-Dependent Routing (TD-Dijkstra + TCH)")) bounds breakpoint count with a max-error tolerance.

8.9 Algorithm cost model (why each technique is faster)

Technique Settled nodes (continental, typical) Preprocessing Exact?
Dijkstra up to n (≤ 50 M) none yes (oracle)
Bidirectional Dijkstra ~n/2 searched area none yes
A* + Haversine metric-dependent; 2–10× fewer coords only yes (admissible h)
ALT (k landmarks) 10–50× fewer k forward+backward Dijkstras yes
Arc-flags (K regions) † large prune toward target region per-region boundary trees yes
CH few hundred order + contract (min–h) yes
CRP ~1–2 k (overlay) partition+overlay once; customize s yes
Hub Labels † O(1) table lookups large label store yes

† Not implemented in this blueprint — comparative reference only; see Alternative Architectures (Roads Not Taken).

The progression is the story of the field: each technique searches a smaller fraction of the continent for the same exact answer (I1).

8.10 Bidirectional search meeting/stopping criterion

Forward search settles from s on G; backward from t on G_rev. Maintain μ = best known dist_f[v] + dist_b[v] over nodes settled (or relaxed) in both directions. Stop when min_key(Q_f) + min_key(Q_t) ≥ μ (I6). The shortest path need not pass through the first node settled in both directions; μ must be updated on every edge relaxation that touches an oppositely-reached node. Naive "stop at first common settled node" is a classic bug → suboptimal paths.

8.11 CH query mechanics

After preprocessing, each node has a rank (contraction order). The query runs bidirectional Dijkstra on the up-graph: forward from s relaxes only edges to higher-ranked nodes; backward from t (on the reverse up-graph) likewise. They meet at high-rank nodes. Stall-on-demand: before expanding a node u, if some already-settled higher-ranked neighbor w gives dist[w] + w(w,u) < dist[u], then u is reached suboptimally on the up-graph and is stalled (not expanded) — a major pruning. The result is an up-down path of shortcuts; unpacking recursively replaces each shortcut by its two constituent edges (via the stored middle node) until only original edges remain (I8).

8.12 CRP overlay query mechanics

The multilevel partition gives, per cell, an overlay of arcs between the cell's boundary vertices (precomputed shapes; weights from customization). A query runs bidirectional Dijkstra on a graph that uses: original edges inside the source and target cells, and overlay arcs at the coarsest level possible between them (climbing levels away from s/t, descending toward them). Customization (I10) guarantees each overlay arc weight equals the true in-cell shortest distance between its endpoints for the current metric, so the overlay search is exact. Path unpacking descends overlay levels back to original edges.

8.14 State / pipeline summary

PBF bytes ──parse──▶ {Node,Way,Relation} stream ──profile+builder──▶ CSR(fwd,rev)
   ──[ALT|CH|CRP] preprocess──▶ ROUTING INDEX (versioned, immutable)
   ──load(mmap)──▶ QUERY ENGINE ──{P2P|1→many|isochrone|matrix|alternatives}

Each arrow is a phase boundary with a typed artifact; the index is the durable handoff from offline to online and the unit of versioning/atomic-swap (P6, I18).

Design principles (§6)

  • P1: Exactness is not negotiable; speedups shrink the search, not the answer. CH, CRP, ALT, and bidirectional search, and A*(admissible), all return the provably optimal path — identical to the Dijkstra oracle. Tradeoff: preprocessing cost and code complexity. Operational: every technique is graded against the oracle in CI. Violation: an "optimization" that returns a 1.02× path is a bug, not a speed/quality knob — silent wrong routes erode all trust.
  • P2: The Dijkstra oracle is ground truth. Plain Dijkstra (Phase 2) is implemented first, kept forever, and is the differential reference for every later technique. Tradeoff: must keep a slow path maintained. Operational: route --validate re-runs the oracle. Violation: without an oracle, a subtle CH ordering bug ships undetected and corrupts a fraction of routes.
  • P3: Non-negative weights, always. Dijkstra/CH/CRP correctness requires weight ≥ 0. Tradeoff: cannot model "rebates"; turn bonuses must be re-based to non-negative. Operational: the profile and turn tables assert ≥ 0 at build. Violation: a single negative edge breaks the label-setting invariant → wrong distances, possibly non-termination.
  • P4: Heuristic admissibility + consistency are correctness properties. A* potentials must never overestimate (admissible) and should satisfy h(u) ≤ w(u,v)+h(v) (consistent). Tradeoff: Haversine must use the network's max speed (a loose but safe bound). Operational: potentials are unit-tested for admissibility on fixtures. Violation: an inadmissible heuristic yields fast but wrong (suboptimal) paths.
  • P5: CSR is the canonical layout; the graph is immutable after build. Forward + reverse CSR, SoA, u32 ids. Tradeoff: edits require rebuild. Operational: the index is memory-mapped and shared read-only. Violation: an adjacency-list-of-Box graph is ~10× slower and defeats every cache-locality assumption the latency targets depend on.
  • P6: Offline preprocessing is separate from online query. Ingest + build write a versioned index; the query engine only reads it. Tradeoff: a build/serve split and an index format to version. Operational: rebuilds are atomic swaps; queries never block on a build. Violation: building inside the query path reintroduces the latency the whole project exists to remove.
  • P7: Bounded, total parsers. PBF/protobuf/zlib parsing handles every byte sequence: valid → graph, invalid → typed ParseError; allocation bounded by validated counts. Tradeoff: no unwrap on input paths. Operational: fuzzers must find zero panics/OOMs. Violation: a crafted .osm.pbf panics or OOMs the build host.
  • P8: Determinism + reproducibility. Identical (OSM extract SHA + profile + tool version) ⇒ byte-identical index and byte-identical paths; ties broken by ascending NodeId. Tradeoff: must pin inputs and avoid float in cost. Operational: index header records all input SHAs; incidents reproduce from them. Violation: nondeterministic tie-breaks make "why did the route change" unbisectable.
  • P9: The FIFO property is the precondition for time-dependent correctness. Every travel-time function must satisfy τ1 ≤ τ2 ⇒ τ1+f(τ1) ≤ τ2+f(τ2) (no overtaking). Tradeoff: raw probe data must be FIFO-repaired at build. Operational: TTFs are validated at build; non-FIFO → NonFifoTtf. Violation: TD-Dijkstra silently returns wrong arrivals if a function lets a later departure arrive earlier.
  • P10: Customization is metric-independent topology + cheap weights (CRP). The partition and overlay shape are computed once; only arc weights are recomputed per metric. Tradeoff: a partition/overlay layer to maintain. Operational: live traffic updates run in seconds, not the CH rebuild hour. Violation: coupling topology to the metric forces a full re-preprocess on every traffic tick — unusable for live data.
  • P11: Partition cells are disjoint and covering. Every node belongs to exactly one cell per level; levels nest. Tradeoff: partitioner must guarantee this. Operational: asserted at build; overlay correctness depends on it. Violation: overlapping/missing cells corrupt overlay arcs → wrong or missing CRP paths.
  • P12: Unpacking yields a valid original-edge path with identical cost. A CH/CRP shortcut expands to a sequence of original edges whose summed weight equals the shortcut weight. Tradeoff: store middle nodes / edge ids. Operational: unpack is checked against the shortcut weight in tests. Violation: an unpacking bug returns a path whose geometry/cost disagrees with the reported distance.
  • P13: Bounded resource usage per query. Per-query scratch (dist, parent) is O(n) but pooled/reused; isochrone/matrix sizes are capped; PHAST sweeps are bounded. Tradeoff: pre-allocate scratch pools. Operational: concurrent queries reuse thread-local buffers; no per-query 50 M-element allocation churn. Violation: allocating O(n) per request thrashes the allocator and spikes tail latency.
  • P14: Observability of search, not just outcome. Every query can report settled-node count, relaxed-edge count, max queue size, and (for CH) unpacked-shortcut count. Tradeoff: a few counters per search. Operational: "this query was slow" is debuggable via search-space metrics. Violation: a latency regression with no search-space telemetry is undiagnosable.
