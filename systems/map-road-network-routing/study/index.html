Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does CH query in < 1 ms while CRP query takes 1–2 ms, yet CRP is still the chosen path for live traffic? (§4, Phase 7, Phase 10, ADR-12)
  2. Why is the Haversine bound divided by the network's maximum speed rather than its average speed? (Phase 3, I4, P4)
  3. Why does witness search need a hop limit, and what breaks — performance or correctness — if the limit is too tight vs too loose? (Phase 6, I7)
  4. Why is CSR immutable-after-build rather than supporting incremental edits, given that OSM data changes daily? (§8.2, P5, Phase 12)
  5. Why does the edge-expanded graph roughly double the graph size, and why is that cost accepted rather than special-casing turns per-node? (§8.3, Phase 5, ADR-13)
  6. Why must the bidirectional stopping criterion use min_key(Q_f)+min_key(Q_t) ≥ μ rather than "stop at the first node settled by both directions"? (§8.10, I6, Phase 3)
  7. Why does the FIFO property matter for time-dependent Dijkstra specifically, and what observable symptom appears when it's violated? (§8.8, I11, Phase 8)
  8. Why is Contraction Hierarchies metric-bound (full rebuild on weight change) while CRP is not, given both are "preprocessing techniques"? (Phase 6, Phase 10, MM3)
  9. Why does the ALT landmark table use both to_l and from_l rather than one direction? (Phase 4, I4)
  10. Why is u32::MAX reserved as INF rather than using a separate boolean "reachable" flag alongside the weight? (§4, I16, §11)
  11. Why does PHAST require a descending-rank sweep, and what would happen if the sweep order were reversed? (Phase 9, I20, PR9)
  12. Why is Hub Labeling faster at query time than CH, yet rejected as this project's primary technique? (Phase 10, Alternative Architectures, PR13)
  13. Why does the Comparative Architecture Table show Valhalla with higher query latency despite also being a "hierarchical" approach like CH? (Comparative Architecture Table, Alternative Architectures)
  14. Why does unpacking need to verify summed weight equals the shortcut weight, rather than trusting the contraction step that created it? (Phase 6, Phase 7, I8, P12)
  15. Why is the routing index versioned with a magic number and SHA rather than trusting file extension/location? (Phase 12, I18, T10)
  16. Why does the capacity model (item 8 vs item 9) show a six-order-of-magnitude difference in concurrent-search ceiling between plain Dijkstra and CH? (Back-of-Envelope Capacity Model, Phase 2, Phase 7)
  17. Why does the blueprint keep the Dijkstra oracle in production (route --validate) instead of removing it once CH/CRP are trusted? (P2, Phase 2, Phase 13, MM7)
  18. Why is arc-flags rejected as a primary technique here despite being real, published, and used historically, while CRP is chosen? (Alternative Architectures, ADR-12, PR6)
  19. Why does the partition quality (not raw node count) determine CRP's practical scaling ceiling? (Scalability Analysis, MM8, ADR-17)
  20. Why must turn-restriction lowering happen before CH contraction rather than after? (Phase 5, Phase 6, ADR-13)

Mental Models & First Principles

  • MM1 — A road network is a near-planar sparse graph with an emergent hierarchy; CH ordering discovers that hierarchy, it does not impose one. Predicts: order quality, not code cleverness, dominates CH speed. Bug class without it: uniform/random contraction order → shortcut explosion, blown preprocessing time and memory. Applied in Phase 6, ADR-11.
  • MM2 — A shortcut is a memoized subpath, not a new fact; CH is dynamic programming over path concatenation, exactly like compiler constant-folding. Predicts: unpacking must reproduce the exact original edges, never an approximation. Bug class without it: treating shortcuts as opaque distances and losing geometry/turn fidelity on unpack. Applied in Phase 6, Phase 7, I7/I8.
  • MM3 — Preprocessing buys a view of the graph, not a smaller graph; CRP's overlay is a materialized query plan, exactly like a database query-optimizer's plan cache. Predicts: customization cost scales with plan-rebind cost (cheap), not with graph size. Bug class without it: treating CRP as "CH but slower" and missing why it is chosen for live traffic. Applied in Phase 10, ADR-12, P10.
  • MM4 — Admissibility is a promise about the future (never overestimate to the goal); consistency is a promise about consecutive steps. Conflating them causes silent A* correctness bugs that present as performance bugs (extra re-expansions) rather than wrong answers, or vice versa. Applied in Phase 3, Phase 4, I4/I5.
  • MM5 — FIFO is what makes "time" behave like a total order for shortest-path purposes; break FIFO and Dijkstra's core exchange argument breaks with it. Predicts exactly which correctness argument fails (settled-node finality) when probe data isn't repaired. Applied in Phase 8, I11, P9.
  • MM6 — CSR is a graph frozen into a columnar database: "ALTER TABLE" (structural edit) is expensive, "SELECT" (traversal) is nearly free. Predicts that any workload requiring frequent graph edits is a poor fit for this design regardless of query speed. Applied in §8.2, Phase 0, ADR-3.
  • MM7 — The Dijkstra oracle is not a testing convenience, it is the specification; every optimization is a compiler correctness proof against it. Predicts that "the fast path disagrees with the oracle" is always a bug in the fast path, never grounds to "fix" the oracle. Applied in Phase 2, Phase 13, I1, P2.
  • MM8 — A road network's "difficulty" is measured in cut size, not node count; CRP/partition quality is the real scaling variable, not graph size. Predicts that a bigger-but-well-partitioned continent can customize/query faster than a smaller-but-badly-cut region. Applied in Scalability Analysis, ADR-17, Phase 10.

Glossary · 49 terms · site-wide glossary

Routing graph
Directed weighted graph; node = intersection, edge = directed road segment weighted by travel time or distance
CSR (Compressed Sparse Row)
Static adjacency layout: head[n+1] offsets + edges[m]; contiguous out-edge slices; cache-friendly (§8.2)
Reverse CSR
Transpose of the CSR; needed for backward (bidirectional/CH/ALT) search
Edge-expanded graph
Node = directed segment, edge = a turn; makes turn costs/restrictions first-class (§8.3)
NodeId / EdgeId / Weight
u32 newtypes; Weight in deciseconds/meters; u32::MAX = INF (I16)
Coord
Fixed-point i32 degrees ×10⁷; exact, float-free (ADR-6)
Dijkstra
Label-setting shortest-path on non-negative weights; the exact ground-truth oracle (P2)
Label-setting
A settled node's distance is final (vs label-correcting); requires weight ≥ 0
Bidirectional search
Forward from s + backward from t; correct stop when min_key(Q_f)+min_key(Q_t) ≥ μ (§8.10)
A\
Goal-directed search with key g+h; exact iff h is admissible (P4)
Admissible heuristic
h(v) ≤ true dist(v,t) — never overestimates; a correctness property (I4)
Consistent heuristic
h(u) ≤ w(u,v)+h(v) — no node re-expansion (I5)
Haversine
Great-circle distance on a sphere; ÷ max speed = admissible time bound (ADR-9)
ALT
A*, Landmarks, Triangle inequality: precomputed landmark distances → tight lower bounds (PR3)
Landmark
A node from which all distances are precomputed; selected by avoid/farthest (ADR-10)
Contraction Hierarchies (CH)
Preprocessing: order nodes by importance, contract lowest-first, add distance-preserving shortcuts (Phase 6)
Highway Hierarchies
CH's direct precursor: a coarser multilevel highway-only skeleton extraction (PR12, Alternative Architectures)
Node ordering / importance
Contraction priority = edge-difference + deleted/contracted neighbors (+ depth)
Witness search
Bounded local Dijkstra deciding whether a shortcut is necessary; soundness = CH exactness (I7)
Shortcut
An edge u→w summarizing a contracted path u→v→w, weight-preserving, with stored middle
Stall-on-demand
CH query pruning: don't expand a node reached suboptimally via a higher-rank neighbor (§8.11)
Unpacking
Recursively expand shortcuts to original edges; summed weight == shortcut weight (I8)
Rank
A node's contraction order; CH query relaxes only edges to higher ranks
CRP (Customizable Route Planning)
Metric-independent partition + overlay topology (once) + fast per-metric customization (Phase 10)
Partition / cell
Disjoint + covering + nested multilevel node grouping; cells communicate via boundary vertices (I9)
Overlay arc
A precomputed connection between a cell's boundary vertices; weight set by customization (I10)
Customization
Recomputing overlay arc weights for a metric (live traffic) in seconds, no topology rebuild
Boundary vertex
A node on a cell boundary; the interface for overlay arcs
Inertial flow
Geometry-based graph partitioner (project on a line, min-cut) tuned for road networks (ADR-17)
Arc-flags
Per-edge bit "lies on a shortest path into region r"; prunes search toward the target region — evaluated, not built (Alternative Architectures)
Hub Labeling (HL)
2-hop labels; fastest query (table merge, no search) but large labels; not cheaply customizable (PR13)
TTF (travel-time function)
Piecewise-linear periodic f(τ) = travel time vs departure time-of-day (§8.8)
FIFO / non-overtaking
τ1≤τ2 ⇒ τ1+f(τ1) ≤ τ2+f(τ2); precondition for time-dependent Dijkstra correctness (I11)
TD-Dijkstra
Time-dependent Dijkstra: relax on arrival time; earliest-arrival for a fixed departure
TCH
Time-dependent CH; shortcuts store composed TTFs (link); witness compares functions
link / merge
TTF composition (f∘g) and pointwise minimum; the algebra of profile/TCH queries
Earliest-arrival vs profile
Fixed-departure scalar arrival vs arrival as a function of all departures
PHAST
CH-based one-to-all: forward up-search then descending-rank sweep settling every node (Phase 9)
RPHAST
Restricted PHAST: sweep limited to a target subgraph (one-to-many)
Isochrone
Reachable region within a time/distance budget, polygonized (concave hull → GeoJSON)
Concave hull / alpha-shape
Non-convex boundary fitting reached nodes; the isochrone polygon shape
Distance matrix
Dense `
Alternative route
An admissible non-optimal path: bounded overhead, limited sharing, locally optimal (Phase 11)
Snap-to-road
Map a (lat,lon) to the nearest routable edge via a spatial index (grid/R-tree, I13)
Routing index
Versioned, immutable, mmap'd artifact bundling CSR + CH/CRP/ALT/TTF + header (I17/I18)
Exactness gate
CI rule: every speedup technique's cost == Dijkstra oracle on the OD sample (I1) — the spec's heart
Tile (Valhalla-style)
A fixed geographic cell of hierarchical graph data used instead of CSR+CH (Alternative Architectures)
Reduced-cost reformulation
w'(u,v)=w(u,v)-h(u)+h(v)≥0 rewriting that keeps A*'s heap logic unchanged under a consistent heuristic (Phase 3)
Deciseconds
0.1 s weight unit; integer, float-free; ~119 h fits in u32 minus the INF sentinel
