Back-of-Envelope Capacity Model

Twelve numbers, each derived from the System Constraints table (§4), formula shown:

  1. CSR edge-array bytes = m × 8 B = 120 M × 8 B = 0.96 GB (from §4 edge count × Edge{u32,u32} size).
  2. CSR head-array bytes = (n+1) × 4 B ≈ 50 M × 4 B = 0.2 GB (from §4 node count).
  3. Coords-array bytes = n × 8 B (two i32) = 50 M × 8 B = 0.4 GB (from §4 node count, ADR-6).
  4. Total warm graph-only index = edges + head + coords = 0.96 + 0.2 + 0.4 = ≈ 1.56 GB (sum of 1–3).
  5. ALT table memory = 2 · k · n · 4 B; with k=16 landmarks: 2×16×50 M×4 B = 6.4 GB (from §4's stated formula, matches M13).
  6. CH shortcut memory = m × 1.25 × 8 B (midpoint of the 1.0–1.5× ratio, M8) = 120 M × 1.25 × 8 B ≈ 1.2 GB additional.
  7. Per-query scratch (plain Dijkstra) = n × (4 B dist + 4 B parent) = 50 M × 8 B = 0.4 GB per in-flight full-graph search (worst case, before pooling).
  8. Plain-Dijkstra concurrent-search ceiling at a 16 GB scratch budget = 16 GB / 0.4 GB = ≈ 40 concurrent full searches (derived from 7; motivates why CH, not plain Dijkstra, is the production query path).
  9. CH concurrent-search ceiling at the same 16 GB budget = touched-set ≈ few hundred nodes × 8 B ≈ 2.4 KB/search ⇒ 16 GB / 2.4 KB ≈ 6.7 M concurrent CH searches (derived from the M1 few-hundred-settled-node target, contrasted with 8 — the reason pooled SearchSpace reset is O(touched), P13).
  10. Cold index load time (SSD ≈ 2 GB/s sequential) = 1.56 GB / 2 GB/s ≈ 0.78 s worst-case fully-faulted read, vs the < 100 ms M9 target achieved because mmap lazily faults only the pages a query actually touches (derived from 4).
  11. CRP customization work = cells × avg-in-cell-Dijkstra-cost, parallelized over P cores ⇒ wall time ≈ (cells × cost) / P; at thousands of cells and sub-ms per-cell Dijkstras on a 32-core host this lands in the 0.5–5 s M3 target (derived from the partition granularity implied by §4's CRP query settled-node count).
  12. Theoretical single-core CH query throughput = 1000 ms / 0.5 ms per query = 2000 qps/core; at 32 cores ≈ 64,000 qps theoretical ceiling before contention/networking overhead (derived from M1's 0.1–0.5 ms typical latency).
