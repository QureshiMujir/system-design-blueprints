Mental Models & First Principles

MM1. A build is a pure function from source content to artifact content. The expert insight: if you model a build as f(inputs) = outputs where inputs is a set of (path, sha256-hash) pairs, caching is just memoization of f, and distributed caching is just sharing that memo table. What it predicts: any non-determinism in f breaks shared memoization. Bug class without it: developers treat builds as stateful processes and use timestamps or inode numbers as cache keys, producing stale hits when content changes without mtime changes. Applied in: §6 P3 (content addressing), Phase 5 (ActionKey = sha256 of canonical inputs), Phase 7 (CAS write-once).

MM2. The ActionKey is the hash of a hash-of-hashes: a Merkle root over the action. Input digests are themselves hashes; the ActionKey hashes those hashes (plus argv, env, platform). A change anywhere in the input tree bubbles upward. What it predicts: changing a deep transitive source invalidates exactly the ActionKeys that include it, no more. Bug class without it: using file paths instead of content hashes means cache keys collide across branches when files differ but paths match. Applied in: Phase 5 (canon.rs STEP 1–6), §8.4 (ActionKey computation canonical form), Phase 11 (dirty-set propagation reuses the same digest chain).

MM3. The sandbox is a contract, not a filter. The sandbox enforces that an action can only see what it declared. Without this mental model, developers add "extra" inputs "just in case" and the cache key becomes meaningless. What it predicts: an action that reads an undeclared file will silently succeed in dev and fail in CI when the ambient file is absent. Bug class without it: undeclared #include paths that exist on developer machines but not in CI. Applied in: Phase 6 (deny-by-default SandboxSpec), §7 I3 invariant, §6 P1 (Hermeticity).

MM4. Incremental correctness is harder than correctness from scratch. A clean build has one code path; an incremental build has two that must produce identical outputs. What it predicts: every fast-path (mtime skip, dirty-set approximation) is a potential source of silent divergence. Bug class without it: adding an mtime short-circuit that skips content verification → stale incremental results undetected until a clean build is forced. Applied in: Phase 11 (mtime fast-path with content-verify fallback), §7 I8 (incremental equivalence), Phase 14 (clean-vs-incremental digest comparison test).

MM5. Toolchains are inputs, not context. The compiler version, linker, and sysroot are logically inputs to every action they influence. Failing to model them as digested ArtifactRefs makes cache keys non-portable across machines with different ambient toolchains. What it predicts: a compiler upgrade on a CI machine produces different outputs but the same cache key, delivering stale binary artifacts from the old compiler. Bug class without it: implicit $PATH-based toolchain resolution, which is invisible to the cache. Applied in: Phase 9 (Toolchain::digest() injected into ActionKey), §7 I9 invariant, §6 P9.

MM6. The cache hit rate is the build system's health metric. A falling hit rate is a canary for correctness bugs (non-determinism, volatile key material) as much as for performance regression. What it predicts: a hit rate near 0% in CI on unchanged code means ActionKey non-determinism; a hit rate near 100% but wrong outputs means a false hit (I2 violation). Bug class without it: operators focus on wall-time latency and miss systematic cache poisoning. Applied in: Phase 10 observability (§6 P10), Operational Readiness (alert: hit rate < 60% in CI), Phase 14 (fuzz: any mutation → cache miss).

MM7. Remote execution is a trust-but-verify relationship. Remote workers are semi-trusted (see Threat Model boundary). Every downloaded output must be re-verified against its declared digest before entering the local CAS. What it predicts: a compromised or buggy worker produces wrong output that passes the ActionKey check but fails the output-digest check. Bug class without it: accepting remote ActionResult at face value, allowing a malicious server to inject arbitrary artifacts into the local build. Applied in: Phase 12 (output_sync.rs sha256 verify before local CAS insert), §7 I10 invariant, Threat Model T4 and T10.

MM8. Build system design is a tradeoff between scheduling policy and cache soundness. A "suspending" scheduler (dynamic deps) maximizes parallelism; a "topological" scheduler (static deps) maximizes cache soundness. PBS chooses the topological (verifying) scheduler because soundness is non-negotiable. What it predicts: dynamic dep discovery (e.g., gcc -M header scanning) requires a restart or suspending scheduler that PBS explicitly defers. Bug class without it: adding dynamic dep discovery to a topological scheduler produces unsound incremental builds where new deps are not tracked after the first build. Applied in: Phase 8 (topological scheduler design from P1), §1.3 non-goals (no dynamic dep discovery in Phase 1–14), Phase 4 (all deps declared statically).

Glossary · 39 terms · site-wide glossary

Action
Atomic build step: { mnemonic, command: Vec<String>, inputs: Vec<ArtifactRef>, outputs: Vec<PathBuf>, env: Map, platform: Digest }. The unit of scheduling, sandboxing, caching, and remote execution in pbs-action.
Action cache
Map ActionKey -> ActionResult stored in pbs-cache. A hit means the result of a prior identical action is reused; serves I2 (cache soundness).
Action graph
DAG of Actions lowered from the target graph by pbs-graph + pbs-rules; nodes keyed by ActionKey, edges are input/output producer-consumer relationships.
ActionKey
sha256(canonicalized(argv + sorted(input digests) + sorted(env) + platform digest + toolchain digest)); the cache key. Computed by pbs-action. Identical inputs across machines produce identical keys (I1).
ActionResult
{ exit_code, output_digests: Map<PathBuf,Digest>, stdout: Digest, stderr: Digest, metadata }. Stored in the action cache; both local execution and remote execution return this type.
ArtifactRef
`{ path, digest: Digest, kind: Source
Attribute
Named, typed configuration value on a Target (e.g., srcs, deps, copts). Declared in a rule's attribute schema (RuleClass) and populated at BUILD-file evaluation time.
Bazel
Google's open-source hermetic build system (bazelbuild/bazel); primary design reference for PBS. Introduces Skyframe, action graph, sandbox, REAPI client, and remote cache.
BUILD file
Declarative package boundary file parsed by pbs-loader; contains rule invocations that instantiate Targets. Analogous to Bazel's BUILD/BUILD.bazel.
CAS (content-addressed store)
Key-value store Digest -> bytes in pbs-cache. Write-once, dedup-on-write, integrity-verified on read (I4). Also the backing store for remote execution input/output transfer in pbs-remote.
Configured target
A Target evaluated in the context of a specific Platform; distinct targets with the same label but different platforms have different TargetIds and separate action graphs.
Constraint
A typed key-value pair that characterizes a Platform (e.g., cpu=x86_64, os=linux). Toolchain resolution matches the set of constraints declared by a target's platform against registered toolchains.
Cross-compilation
Building for a target_platform different from the exec_platform on which the build runs. pbs-toolchain resolves separate exec and target toolchains per action.
Cycle detection
pbs-graph detects cycles in the target DAG via DFS; reports the full cycle path and aborts. Invariant I5: graph is always a DAG before any action is scheduled.
DAG (directed acyclic graph)
The structural requirement for both the target graph and the action graph. Enforced by pbs-graph (I5); enables safe topological scheduling.
Digest
{ hash: [u8;32], size_bytes: u64 } where hash = sha256(bytes). Universal key throughout PBS: for source files, generated artifacts, Actions, Commands, and toolchain blobs.
Dirty tracking
pbs-graph marks a configured target as dirty when any of its input digests change. Only dirty subgraphs are re-lowered and re-scheduled; clean subgraphs reuse cached results (I8).
Eviction (GC)
pbs-cache evicts CAS and action-cache entries by LRU when the store exceeds its size bound; live outputs (referenced by the current build) are pinned and exempt.
Genrule
A language-agnostic rule that runs an arbitrary shell command; inputs and outputs fully declared. Implemented in pbs-rules; the fallback rule for tools without a native rule set.
Hermetic
An action is hermetic when it observes only its declared inputs and a scrubbed, deterministic environment. Enforced by pbs-sandbox (I3, I7). A build is hermetic when all its actions are hermetic.
Incremental build
A build that reuses cached ActionResults for actions whose input digests have not changed, executing only the affected subgraph. Implemented via dirty tracking (Phase 11) and the action cache.
Label
Canonical target address //package/path:name. Parsed and interned by pbs-core into { repo, package, name }. The unique identifier for a Target before platform configuration.
Mnemonic
Short human-readable tag on an Action identifying its kind (e.g., CppCompile, RustLink, Genrule). Used in log output and build event streams; not part of the ActionKey.
Package
A directory containing a BUILD file. The unit of visibility and loading in pbs-loader. A Label's package component identifies the package that owns the target.
Platform
An immutable set of Constraint values describing an execution or target environment. Represented as its Digest in ActionKey computation. Managed by pbs-toolchain.
Provider
Typed data a rule exposes to its dependents (e.g., CcInfo { headers, link_inputs }, RustCrateInfo { rlib, crate_name }). Declared by pbs-rules; flows up the action graph at analysis time.
REAPI
Remote Execution API (bazelbuild/remote-apis). Defines gRPC services ContentAddressableStorage and Execution; the wire protocol implemented by pbs-remote for remote cache and remote execution.
Reproducible build
A build where identical inputs produce byte-identical outputs, making the output digest stable. Non-determinism in a tool violates P2 and must be treated as a build correctness bug.
Runfiles
The runtime file tree assembled for a binary or test target: the binary plus all data dependencies at declared relative paths. pbs-rules assembles a runfiles manifest; pbs-sandbox materializes it.
Rule
A named function registered in pbs-rules with an attribute schema (RuleClass); when invoked in a BUILD file it instantiates a Target. Examples: cc_library, rust_binary, genrule.
Sandbox
An isolated execution environment created by pbs-sandbox. Input root contains only declared inputs (symlink forest or namespace mount); environment is scrubbed; undeclared file reads are denied or detected.
Spawn strategy
The dispatch mechanism for an action: local-sandbox, remote-execution, or no-sandbox (test/debug only). Configured per mnemonic or globally; resolved by pbs-exec at scheduling time.
Starlark
Python-dialect configuration language (bazelbuild/starlark) used in BUILD files and .bzl extension files. pbs-loader implements a deterministic subset: no side effects, no unbounded loops, no I/O.
Symlink forest
Input-tree materialization strategy: pbs-sandbox creates a temporary directory containing symlinks pointing into the CAS or source tree for each declared input. Faster than copying; revoked after action completes.
Target
{ label, rule: RuleClass, attrs: Map, deps: Vec<Label>, toolchains: Vec<Label> }. Instantiated by pbs-loader from a BUILD file rule invocation; the node in the target graph.
TargetId(u32)
Dense interned integer identity for a configured target inside pbs-graph. Stable for the lifetime of one build graph; regenerated on graph reload. Cheaper than Label for edge storage.
Toolchain
{ lang, exec_platform, target_platform, tools: Map<String,ArtifactRef> }. Registered in pbs-toolchain; selected per action by constraint matching. Tool digests enter every ActionKey they influence (I9).
Undeclared input
A file read by an action that was not in its declared inputs set. Detected/denied by pbs-sandbox; a violation of I3 and P1. A build with undeclared inputs is not hermetic.
Visibility
A per-package policy restricting which other packages may depend on a target. Enforced during dependency resolution in pbs-graph; violation aborts analysis with a structured error.
