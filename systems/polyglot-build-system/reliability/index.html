I1Action determinism: identical ActionKey ⟹ identical ActionResult; re-executing a cached action reproduces its outputsCache correctness depends on this; a non-deterministic tool makes every cache hit potentially wrongpbs-action (key computation), pbs-rules (action generation must not embed PIDs/timestamps)Phase 14 reproducibility test: two independent executions of same key → diff output digests; divergence emits DETERMINISM_FAILURE eventaction.determinism_check: pass/fail, output_digest_before, output_digest_afterInvalidate that action's cache entry; log tool as non-deterministic; require -fdebug-prefix-map or equivalent fixRe-run action twice with identical env; sha256sum each output; objdump/strings to find embedded volatile paths
I2Cache soundness: a cache hit is served only when the recomputed ActionKey matches exactly; a hit is indistinguishable from a fresh executionA false hit delivers wrong outputs silently — the cardinal sin (P4)pbs-cache (lookup path: recompute key, compare before serving), pbs-exec (drives lookup)Any served ActionResult with output digests that fail re-verification triggers CACHE_SOUNDNESS_VIOLATION; Phase 14 fuzz: mutate one input byte → must get cache misscache.hit, cache.miss, cache.soundness_violation counterInvalidate corrupted entry; re-execute; alert operatorReplay the ActionKey computation step by step; compare input digest lists between the hit entry and the current build
I3No undeclared inputs: an action that reads a file not in its declared input set fails in the sandboxWithout this, builds depend on ambient state; incremental invalidation is unsound (P1, P5)pbs-sandbox (deny-by-default filesystem policy), pbs-action (input set completeness)Sandbox returns EACCES / EPERM on undeclared read; action fails with UndeclaredInputRead(path) errorsandbox.undeclared_read: path, action_keyBuild fails; user must add missing dep to BUILD rulestrace -e trace=openat,open the action outside the sandbox to enumerate all file reads; compare to declared inputs
I4Digest integrity: every blob in the CAS satisfies sha256(bytes) == key; a corrupted blob is detected on read and never servedServing a corrupted blob propagates silent wrong-code into the buildpbs-cache (integrity check on every cas_get; write-once semantics prevent partial overwrites)Read-time hash mismatch → CasIntegrityError(digest); entry evicted and re-fetched/re-executedcas.integrity_error: digest, cas.read_ok counterEvict corrupted entry; re-execute or re-fetch from remotesha256sum <blob-path> vs stored key; check disk health with fsck/SMART
I5Graph acyclicity: the target graph and action graph are DAGs; a cycle is reported with its path and aborts the buildA cycle makes topological ordering impossible; incremental invalidation divergespbs-graph (DFS cycle detection during dep resolution, post-lowering for action graph)CycleError { path: Vec<Label> } returned from graph build; aborts before executiongraph.cycle_detected: pathBuild aborts with cycle path; user must break the cycle in BUILD filesPrint the reported cycle path; trace which deps attribute introduced each edge
I6Output completeness: a successful action produces exactly its declared outputs; a missing or extra output is an errorAn action that silently omits an output leaves dependents with a missing input, causing a confusing downstream failurepbs-sandbox (post-execution output capture: check each declared output path exists)Missing: MissingOutput(path, action_key); extra outputs are ignored (not captured into CAS)sandbox.missing_output: path, action_keyBuild fails at that action; user must fix the rule's outs declarationRun the action command manually in the input root; verify output file names match declared names exactly
I7Hermetic environment: the action environment is a deterministic function of the Action; volatile variables are scrubbed and excluded from ActionKeyLeaking $HOME, $USER, $TMPDIR, or $RANDOM into the action makes ActionKey non-portablepbs-sandbox (env scrub list applied before spawn), pbs-action (env canonicalisation: only explicitly declared vars enter the key)Lint in pbs-action: reject env vars matching a volatile pattern list (HOME, USER, TMPDIR, TMP, TEMP, RANDOM, LANG unless declared)action.scrubbed_env_var: name per scrubbed varRemove the offending var from the env before key computation; warn the rule authorDiff the env dict between two machines; any differing var that is NOT in the scrub list is a bug
I8Incremental equivalence: an incremental build produces the same outputs as a clean build of the same final inputsIncremental correctness: if dirty tracking is wrong, incremental builds silently diverge from clean buildspbs-graph (dirty/affected set computation), pbs-exec (action cache reuse logic), Phase 11 (change detection)Phase 14 equivalence test: clean build → record all output digests; make no-op change → incremental build → compare digests; any divergence is a failurebuild.incremental_equivalence: pass/fail, actions_reused, actions_rerunInvalidate the dirty-tracking state; force a clean rebuildBisect: disable action-cache for a subset of targets to find which action produced a divergent result
I9Toolchain capture: the resolved toolchain's tool digests are part of every ActionKey it influences; no ambient toolchain leakageA compiler upgrade that is not captured in the key serves stale-compiler cache results silentlypbs-toolchain (tool ArtifactRef.digest injected into key computation), pbs-action (toolchain_digest field in key preimage)If Toolchain.tools contains an ArtifactRef with a zero/missing digest, pbs-action returns ToolchainDigestMissing error at key-computation timetoolchain.digest_missing: tool_name, action_keyFail-fast at key computation; require all toolchain tools to have resolved digests before executionCheck Toolchain.tools map; re-run pbs toolchain inspect //toolchain:cc to verify each tool's digest is populated
I10Remote/local equivalence: an action executed remotely yields the same ActionResult (and output digests) as executing it locallyIf remote results differ from local, remote cache hits produce wrong builds on local machines and vice versapbs-remote (result verification: re-hash downloaded outputs vs ActionResult.output_digests), pbs-sandbox (hermetic env identical on both sides)Output digest mismatch after remote download → RemoteLocalMismatch(action_key, expected, got); fall back to local executionremote.local_mismatch: action_key, remote.verified_ok counterDiscard remote result; execute locally; alert if mismatch is persistent (non-deterministic remote worker)Compare ActionResult.output_digests from remote vs a local execution of the same ActionKey; diff env and input roots
I11Query non-mutation: evaluating any pbs-query function or daemon status/read request never executes an action or mutates BuildGraph/ActionGraph state (P11)CI and tooling treat pbs query as side-effect-free; if it could trigger execution, external systems could not safely poll the graph without incurring build costpbs-query (Evaluator reads via RwLock read guard only), pbs-server (QueryRequest routed to a read-only handler path, never to BuildRequest dispatch)Handler-boundary test: fire concurrent QueryRequests against a graph with unresolved toolchains and assert zero pbs-exec dispatches occurquery.eval_total, query.mutating_attempt_blocked counter (should always be 0)Reject the offending query function at code review; add a regression fixture reproducing the mutation pathTrace tracing spans for query_eval; assert no action.execute span is a child of any query_eval span in the same request
I12Daemon single-writer: at most one writer holds the DaemonState RwLock at any instant; all other concurrent holders are readers (P12)Concurrent writers could interleave partial graph updates, corrupting the rdeps_index used by both dirty propagation (Phase 11) and query (Phase 13)pbs-server (state.rs: single Arc<RwLock<BuildGraph>>/Arc<RwLock<ActionGraph>>; only watcher.rs's incremental-reload task acquires a write guard)Concurrency test: spawn two simulated write paths and assert the second blocks until the first releases, via a writer-count assertion in test buildsdaemon.write_lock_hold_ms histogram; daemon.concurrent_writer_attempts counter (should always be 0 in production)Any new write-path RPC must acquire the same RwLock write guard; code-review checklist item added for pbs-server PRsAttach tokio-console to the daemon; inspect the RwLock task queue to confirm only one write-waiter is ever granted at a time
