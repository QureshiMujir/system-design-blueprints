Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. The loop-cut rule (§8.3) asserts I on entry, havocs the modified variables, and then assumes I. If the havoc set under-approximates the actual modified set, which invariant is violated first — I4, I14, or I1 — and what is the exact execution that witnesses the false Verified? (§8.3, Phase 2, I14, I1, P4)
  2. The block-equation compacted VC (§8.4) introduces one fresh predicate per block. If two blocks share a successor and that successor's block predicate is referenced from both block equations, trace exactly how structural sharing prevents the exponential blowup — and explain why naive WP applied to a binary-branch tree of depth 10 produces 2^10 copies of the postcondition instead. (Phase 4, ADR-07, I6, MM1)
  3. ADR-14 locks in the external-solver-over-SMT-LIB2 design. Under what program/theorem class does this choice incur a measurable performance penalty compared to a native FFI binding, and does that penalty threaten any §4 constraint? (ADR-14, ADR-15, §4 per-VC solver budget, Phase 6, Scalability Analysis, Bottleneck #1)
  4. The WP of wp(havoc x, Q) is ∀x. Q — a universal quantifier. After passification, havoc x becomes a fresh unconstrained version. Explain precisely why these two formulations produce the same VC validity, and under what degenerate condition they could diverge. (§8.2, Phase 3, Phase 4, I4, ADR-08)
  5. A user supplies the trigger {f(x)} on the axiom forall x :: f(x) == g(x). The matching-loop check in Phase 5 should flag this — but the check as described in §8.7 looks at self-regeneration. Construct a two-axiom system with triggers {f(x)} and {g(x)} that produces a cross-axiom matching loop the single-axiom check misses. (Phase 5, ADR-13, I10, T3, MM7)
  6. k-induction (Phase 10) requires both the base case and the inductive step. Construct a concrete transition system where the inductive step is unsat (1-inductive) but the property is false — i.e., there exists a reachable initial state that violates the property — and identify exactly which of I16/I17 this tests. (Phase 10, I16, I17, ADR-20, MM9)
  7. The spuriousness re-check (Phase 8) re-evaluates the reconstructed model against the original program path. Identify a class of program/encoding (hint: quantified postconditions with an ∃ witness that the SMT model represents only partially) where the re-check may incorrectly classify a genuine counterexample as spurious, and explain the recovery path. (Phase 8, I11, Phase 5, ADR-13)
  8. Inferred invariants from the interval domain (Phase 11) are re-checked by the deductive engine. Now suppose the transfer function for assume(x == y + 1) is non-monotone — it sometimes returns a value below the true abstract semantics. Trace the worst-case consequence through I12, the re-check, and the final verdict. Does the architecture prevent false Verified? (Phase 11, I12, P11, MM10, ADR-21)
  9. §4 states VCGen determinism is bit-identical VC for identical input. The hash-cons table uses a hasher with a fixed salt (I7). Suppose two procedures' term DAGs have the same structural shape but different variable names — their TermIds differ but their VCs have the same structure. Explain why this is not a determinism violation, and then construct a hash-collision scenario that would be. (Phase 0, Phase 4, ADR-24, I7, ADR-05)
  10. The SMT encoding emits (assert (not VC)) (check-sat). If the VC contains a division expression a / b and the div_nonzero obligation was correctly emitted in Phase 2 but the encoding of division in Phase 5 uses the SMT div function (total, defined at zero) without conditioning, is the result sound? Construct a counterexample or prove soundness. (Phase 2, Phase 5, ADR-09, I1, §8.7 division-by-zero example)
  11. ADR-22 defers IC3/PDR; the current invariant inference chain is intervals → Houdini. Identify a class of programs (beyond the §4 constraint "nonlinear arithmetic incompleteness") where Houdini converges to an empty candidate set and the deductive engine returns Unknown, and explain what IC3/PDR would do differently at that class boundary. (Phase 11, ADR-22, Deferred Features Register, MM10, P1)
  12. The modifies-conformance VC (Phase 7) checks that a method's actual assignments ⊆ declared modifies. This is a VC, not a static check. Explain what program pattern would make this VC require quantification over heap locations, and why the current simple modifies-set model (ADR-11) is sufficient for the non-heap case but insufficient for the deferred separation-logic case. (Phase 7, ADR-11, I14, P4, Deferred Features Register)
  13. Phase 8's counterexample reconstruction maps SMT model values through the DSA version map to source spans. Consider a loop whose body contains an assignment m := i conditionally (as in MaxIndex §8.1). After 3 iterations, the model has m_7 = 2, i_7 = 3. Trace the DSA-reverse to identify what source statement each version corresponds to, and explain what old(m) would mean in this context. (Phase 3, Phase 8, §8.1, §8.6, I18, ADR-17)
  14. The three engines (deductive, BMC, k-induction) share the same VIR but use it differently: the deductive engine uses the invariant-cut CFG, BMC uses the original transition relation, and k-induction also uses the raw transition. Explain why k-induction using the invariant-cut CFG would be unsound (not merely incomplete), and then explain why BMC using the cut CFG would be both unsound and produce wrong counterexamples. (Phase 9, Phase 10, Phase 11, ADR-19, ADR-20, I17, MM2)
  15. The soundness tripwire (I1, Phase 7) runs conformance/soundness/ known-buggy programs and fails the build if any is Verified. Suppose a build introduces a regression in Phase 3 (a bad DSA merge that conflates pre- and post-loop versions) that makes the passified CFG semantically wrong for programs with at least 2 loop iterations. Design the minimal soundness-corpus fixture that catches this regression, specifying the program structure, the expected Refuted obligation kind, and the model that witnesses the failure. (Phase 3, Phase 7, I1, I4, I5, ADR-08, MM5)
  16. The per-VC time budget (§4: default 10 s) maps to Unknown on expiry. Consider a procedure with 100 VCs where 80 are instantaneously unsat (trivial) and 20 each require 9 s. With incremental push/pop reuse, the solver retains learned lemmas across the 80 trivial VCs before hitting the 20 hard ones. Estimate how much incremental context reduces the 9 s solve time for the hard VCs, and identify which §4 constraint and which ADR governs this trade-off. (Phase 6, §4 per-VC solver budget, ADR-14, ADR-15, P10, Scalability Analysis, Bottleneck #1)
  17. The old(e) capture (Phase 2, I18) captures e at procedure entry. Consider a recursive procedure where the recursive call is the last statement. The old(e) in the postcondition should refer to the entry-state of the top-level invocation, not the recursive call's entry. Explain how the modular call rule (assert pre; havoc M; assume post) interacts with old semantics across recursive call sites, and identify whether this is handled correctly or deferred. (Phase 2, §8.3, I18, ADR-04, Phase 7)
  18. Widening (▽) applied at loop heads forces termination but can lose precision. The narrowing (△) phase is supposed to recover it. Construct a two-variable loop (e.g., x := x + 1; y := x * 2) where widening over the interval domain loses the relational invariant y == 2*x, and explain why narrowing cannot recover it (a fundamental limit of the interval domain). Identify which deferred feature addresses this limit. (Phase 11, ADR-21, I13, Deferred Features Register, MM10)
  19. The --dump-smt flag (Phase 5) lets a standalone Z3/CVC5 re-check any verdict. Suppose the re-check with Z3 agrees with the verifier (unsat) but the re-check with CVC5 returns unknown (not sat). Is this a soundness concern, an incompleteness gap, or a solver bug? Identify which invariant and threat entry governs the response. (Phase 5, Phase 6, ADR-14, I1, T4, I15)
  20. The Verified verdict is defined as "every VC is unsat within budget." A procedure with 5 VCs where 4 are unsat and 1 is Unknown(Timeout) returns Unknown, not Verified. Explain why this is the correct and sound behavior with reference to P1 and I15, and identify the one scenario where a legitimate user might argue this is too conservative (and how the response documents that position). (§6 P1, I15, Phase 7, §4 per-VC solver budget, MM6)
  21. The block-equation VC for a procedure with a deeply nested conditional (depth 5, 2^5 = 32 paths) has how many block predicates and how many block equations? Estimate the total VC node count and compare it to the naive WP exponential. At what depth does the naive WP exceed the 4 GB memory ceiling (§4) for a postcondition formula of 10 nodes? (Phase 4, §4 memory ceiling, ADR-07, I6, MM1, M2)
  22. The ghost/physical separation (I3) is enforced at typeck (Phase 1) and audited at lower (Phase 2). Consider a ghost variable g that is assigned from a physical variable x (legal), and then g is used in a decreases clause (legal). Now x is havoc'd by a call (legal). Does the decreases obligation correctly reflect the post-havoc x via g, or does old(g) create a soundness hole? Trace through lower/ghost.rs and I18. (Phase 1, Phase 2, I3, I18, ADR-04, §8.3)

Mental Models & First Principles

  1. MM1 — Passivity is the prerequisite for linear-size WP. Predicts: whether your WP implementation is O(n) or O(2^n) in program size. Without it: naive WP applied to assignments duplicates the postcondition across every branch → exponential term blowup → the solver times out on any non-trivial program, and you blame the solver instead of VCGen. Applied: §8.2 (WP table over passive commands), Phase 3 (passification), Phase 4 (block-equation compaction, ADR-07, I6).

  2. MM2 — A loop cut replaces infinite iteration with one universally-quantified iteration. Predicts: which programs require a user invariant and which can be handled by k-induction or bounded unrolling. Without it: you unroll the loop (BMC style) and can only verify up to the unroll bound — the deductive engine's infinite-state strength disappears. Applied: §8.3 (loop cut), Phase 2 (lower/loops.rs), Phase 9 (BMC deliberately does NOT use the cut), Phase 10 (k-induction also uses the raw transition relation).

  3. MM3 — Modular verification: the call rule is an assume/assert sandwich. Predicts: whether a verifier scales to large programs. Without it: you inline callee bodies at every call site — coupling caller proofs to callee implementations, destroying scalability, and turning any edit into a full re-proof. The sandwich (assert Pre; havoc Modifies; assume Post) is the single idea that makes deductive verification compositional. Applied: §8.3 (call translation), Phase 2 (lower/calls.rs), Phase 7 (modifies conformance, I14, P3/P4).

  4. MM4 — Frame soundness: under-havocking is a silent soundness bug. Predicts: whether a modifies bug produces a false Verified (under-havoc) or spurious Unknown/Refuted (over-havoc). Without it: a callee that modifies x but declares it doesn't allows the caller to wrongly assume x unchanged — a false Verified that is invisible until a real execution contradicts the proof. Applied: Phase 2 (lower/calls.rs, I14), Phase 7 (modifies-conformance VC), §6 P4, Consolidated Pitfall #2.

  5. MM5 — DSA versioning: each variable occurrence becomes a unique SMT constant. Predicts: whether the SMT encoding is correct and whether counterexample reconstruction succeeds. Without it: two occurrences of x in a passified formula collapse to one SMT constant — the solver conflates pre-state and post-state values, producing either a wrong VC or an uninterpretable model. Applied: Phase 3 (passify/dsa.rs, I4), Phase 8 (counterexample reconstruction via version map, I11).

  6. MM6 — Soundness = never false Verified; incompleteness = sometimes Unknown. Predicts: how to triage every verdict. Without it: engineers treat Unknown as a bug and add axioms or weaken triggers until the tool says Verified — destroying soundness to eliminate incompleteness. Applied: §4 (Soundness constraint, P1), §6 P1, Phase 6 (timeout → Unknown, I15), Phase 7 (soundness tripwire, M12).

  7. MM7 — E-matching triggers determine both completeness and termination of quantifier instantiation. Predicts: whether a quantified VC will hang (matching loop), time out (over-restrictive trigger misses a needed instance), or solve (tight, loop-free trigger). Without it: every quantified axiom (array axioms, recursive-function unfolding, user forall postconditions) becomes a probability bet. Applied: Phase 5 (encode/quant.rs, ADR-13, I10), §8.1 (trigger syntax), §8.7 (matching loop example), T3.

  8. MM8 — The trusted computing base is explicit, minimal, and documented. Predicts: what class of bugs can produce a false Verified without any detectable signal in the verifier itself. Without it: a solver soundness bug certifies incorrect programs and there is no fallback — the developer trusts a liar. Applied: §4 (TCB size constraint), §6 P5, Phase 6 (dual-solver cross-check, T4; Failure Analysis, proof-producing mode), Phase 5 (proof-mode deferred, ADR-18, Failure Analysis), Deferred Features Register (proof-producing certificates).

  9. MM9 — k-induction proves safety properties that are k-inductive; it needs the base case to exclude unreachable states. Predicts: when k-induction will return Verified vs Unknown, and why step-only is unsound. Without it: you accept an inductive-step unsat as a proof — but the step holds vacuously for unreachable states; the base case is what connects the induction to the actual initial state. Applied: Phase 10 (kinduct.rs, I17, ADR-20), Consolidated Pitfall #10.

  10. MM10 — Abstract interpretation infers sound over-approximations; the deductive engine re-checks every inferred invariant. Predicts: whether a non-monotone transfer function can cause a false Verified. Without it: you trust the inferred invariant directly — a buggy transfer function under-approximates, producing an invariant that doesn't actually hold, and the verifier certifies a false program. The defense-in-depth split (AI as hint, deductive engine as judge) means a buggy AI degrades to Unknown, not to false Verified. Applied: Phase 11 (absint/transfer.rs, I12/I13, ADR-21/22), §6 P11, Consolidated Pitfall #8.

Glossary · 55 terms · site-wide glossary

Deductive verification
proving a program meets its specification by generating + discharging logical verification conditions (this project; vs model checking).
Hoare triple
{P} c {Q}: if P holds before c, Q holds after.
Weakest precondition (WP)
the predicate transformer wp(c, Q): the weakest P such that {P} c {Q}.
Strongest postcondition (SP)
the dual transformer; used here for differential testing.
Predicate transformer
a function mapping a postcondition to a precondition (or vice-versa); WP/SP.
Verification condition (VC)
the FOL formula whose validity implies a program obligation holds.
Guarded command
assume/assert/havoc/assign/;/□; the VIR's command set (Dijkstra).
Verification IR (VIR)
the Boogie/WhyML-style guarded-command intermediate representation.
Passification
rewriting a program into assignment-free, acyclic (passive) form for WP.
DSA / SSA
dynamic/static single assignment: each variable version defined once.
Loop cutpoint
the program point where a loop's back-edge is cut by the invariant assumption.
Loop invariant
a predicate true on every loop iteration; the crux of loop verification.
Decreases / variant
a well-founded metric proving loop/recursion termination.
Frame / modifies clause
the set of locations a procedure may change; the basis of modular framing.
Modular verification
verifying a call site against the callee's contract, not its body.
Contract
a procedure's requires/ensures/modifies.
Precondition / postcondition
what a caller must establish / what the callee guarantees.
old(e)
the pre-state value of e in a postcondition (2-state assertion).
Ghost state
specification-only state that may not influence physical execution.
Block-equation encoding
the linear VC form using one fresh predicate per block (Leino).
Trusted computing base (TCB)
the components trusted to conclude Verified (VCGen + encode + solver).
Soundness
never report a false program as verified (the prime invariant).
Completeness
never fail to verify a true program; this verifier is sound but incomplete.
SMT
satisfiability modulo theories; the decision procedure backend.
SMT-LIB2
the standard SMT solver command + term language.
LIA / LRA
linear integer / real arithmetic theories.
Theory of arrays
McCarthy select/store axioms.
EUF
equality + uninterpreted functions.
Bitvector theory
fixed-width machine-integer semantics (wrapping arithmetic).
Algebraic datatypes (ADT)
constructor/selector/tester theory.
Trigger / pattern
a term guiding quantifier instantiation (E-matching).
E-matching
instantiating quantifiers by matching triggers against ground terms.
Matching loop
a trigger whose instantiation regenerates a matching term forever (a hang risk).
Counterexample
a concrete model witnessing that an obligation can fail, mapped to source.
Spurious counterexample
a model that is not a real program execution (a reconstruction bug).
Unsat core
a minimal unsatisfiable subset; here, the obligations responsible for validity/diagnostics.
Bounded model checking (BMC)
unrolling the transition relation to a bound k to find bugs ≤ k.
Transition system
(Init, Trans, Prop); the BMC/k-induction view of a program.
k-induction
proving safety by a base case (BMC to k) + an inductive step over k consecutive states.
Unique-states strengthening
requiring the k induction states distinct, to prove more properties.
Abstract interpretation
sound over-approximating analysis over a lattice of abstract values.
Lattice
a partial order with joins/meets; the abstract-domain structure.
Interval domain
abstracting a variable by [lo, hi]; the Phase-0 abstract domain.
Transfer function
the abstract semantics of a command; must be monotone for soundness.
Widening (▽)
an operator forcing fixpoint termination on infinite-height lattices.
Narrowing (△)
an operator recovering precision lost by widening.
Fixpoint
the stable solution of the abstract iteration; the inferred invariant.
Houdini
greatest-fixpoint pruning of candidate invariants to an inductive subset.
Invariant inference
automatically computing loop invariants (so the deductive engine succeeds).
CEGAR
counterexample-guided abstraction refinement (a deferred BMC/k-induction tie-in).
Hash-consing
interning structurally equal terms to one id (sharing + fast equality + determinism).
Verdict triplet
