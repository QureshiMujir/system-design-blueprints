Per-box.

  • parse — the only component touching untrusted source text. A hand-written lexer + recursive-descent parser for the annotated imperative language and the spec sublanguage (requires, ensures, invariant, decreases, modifies, reads, ghost, forall/exists with {trigger} annotations). Produces a hash-consed AST with source spans on every node (spans are the spine of counterexample reconstruction, §10/Phase 8). Everything downstream consumes validated, typed structures — never raw text.
  • typeck — assigns sorts/types (Int, Real, Bool, BitVec n, Array S T, ADTs, uninterpreted), enforces well-formedness of specs (a postcondition references only in-scope + old(...) variables; decreases is a well-founded expression; a trigger is a legal term covering the bound variables), separates ghost from physical state (ghost may not influence physical execution), and validates the modifies clause scope (a procedure may only assign variables/heap locations it declares it modifies — the frame discipline). Rejects ill-typed/ill-specified programs with located errors before any VC exists.
  • lower — desugars typed source into VIR guarded commands. The two load-bearing rules: (1) while g invariant I decreases V { B } becomes the standard cut: assert I (entry); havoc the loop-modified variables; assume I ∧ g; verify B re-establishes I and strictly decreases V; then assume I ∧ ¬g on exit — so the loop is verified once against its invariant, not unrolled. (2) call p(args) becomes assert pre[args]; havoc modifies(p); assume post[args, old] — modular: the callee's body is never inlined; correctness rests on the contract + frame. Also lowers if/;/assign/assert/assume/havoc, array read/write to select/store, ADT constructors/match, and ghost code.
  • VIR CFG — basic blocks whose statements are guarded commands (assume P, assert P, havoc x, x := e, sequencing ;, nondeterministic choice □). Loops appear as back-edges with explicit cutpoints carrying the invariant. This is the single normalized form every later pass and every engine (VCGen, BMC, k-induction) consumes.
  • passify — transforms the CFG into a form with no assignments and no cycles. Loops are cut at their cutpoints (the invariant assumption breaks the back-edge), yielding an acyclic CFG; assignments x := e become assume(x_i = e) under dynamic-single-assignment (each variable version numbered, SSA/DSA), so the resulting guarded commands are passive — pure assume/assert over immutable versioned variables. Passivity is what makes WP linear-size with sharing rather than exponential.
  • VCGen (wp/sp) — computes a verification condition per block via the weakest-precondition calculus over passive guarded commands: wp(assume P, Q) = P ⇒ Q, wp(assert P, Q) = P ∧ Q, wp(c1;c2, Q) = wp(c1, wp(c2, Q)), wp(c1 □ c2, Q) = wp(c1,Q) ∧ wp(c2,Q). A strongest-postcondition variant exists for comparison. The product is a first-order formula whose validity means "this block's assertions always hold." Naive WP duplicates Q across choices → exponential; VC compaction (the passive/block-equation form, à la Boogie/Barnett-Leino) introduces a fresh proposition per block and conjoins block equations, keeping the VC linear in program size.
  • VC compaction — converts the per-block WP into a conjunction of block verification equations using one fresh Block_b predicate per block, so shared continuations are referenced, not copied. Carries labels mapping each assert (and its conjuncts) back to a source span + obligation kind (precondition / postcondition / invariant-entry / invariant-preservation / decreases / assertion / array-bounds), feeding counterexample reconstruction.
  • encode — translates a VC (FOL over the verifier's sorts) into SMT-LIB2, choosing theories: linear integer/real arithmetic (LIA/LRA) for math integers/reals, the theory of arrays (McCarthy select/store) for arrays + the heap model, EUF for uninterpreted/recursive functions, bitvectors for machine-int semantics (overflow wraps), and algebraic datatypes for ADTs. Quantifiers are emitted with explicit triggers / patterns; the encoder enforces matching-loop avoidance (no trigger whose instantiation regenerates a matching term ad infinitum). To check validity of VC, it asserts ¬VC and checks for unsat.
  • smt — drives the decision procedure: by default an external Z3 or CVC5 child process over the SMT-LIB2 text stream (LOCK, ADR-14), with an optional embedded DPLL(T) core (cross-link #277/#278/#303) for self-containment. Uses incremental push/pop to reuse context across a procedure's many VCs, enforces a per-VC time budget (timeout → Unknown, never a false Verified — I15/P8), and extracts a model (for counterexamples) on sat and an unsat-core (for proof minimization + diagnostics) on unsat.
  • Verified / next — unsat of ¬VC means the VC is valid; advance to the next VC, then the next procedure. A procedure is Verified only when every VC is unsat within budget.
  • cex — on sat of ¬VC, the SMT model is a witness that the assertion can fail. Reconstruction maps model values back through the version numbering (DSA) and source spans to a human-readable counterexample: input/ghost valuations, the specific failing assertion (with its obligation kind), and the failing path/trace through the CFG (which branch choices and which loop iteration). This is the developer-facing output.
  • bmc — encodes the VIR as a transition system (Init, Trans, Prop) and unrolls Trans to a bound k, asserting Init ∧ Trans^0 ∧ … ∧ Trans^{k-1} ∧ ¬Prop; sat is a concrete bug trace of length ≤ k, unsat proves the property holds up to k. Complete for bug-finding within the bound; not a proof beyond it.
  • kind — k-induction: the base case (BMC to k: no violation in the first k steps) plus the inductive step (assuming the property held for k consecutive states, it holds at the (k+1)-th). If both discharge, the property holds for all reachable states — an inductive proof without a manually supplied invariant (strength permitting).
  • absint — an abstract-interpretation framework: a lattice (intervals Phase 0, with the structure to add octagons/polyhedra), monotone transfer functions per guarded command, a fixpoint iterator with widening (to force termination on loops) and narrowing (to recover precision). Its output is inferred loop invariants that feed lower so the deductive engine can discharge loops the user under-annotated; also drives Houdini (greatest-fixpoint pruning of candidate invariants).

Boundaries. Trust: only parse consumes untrusted input; the trusted computing base is VCGen + encode + the SMT solver (plus the optional proof checker shrinks it — see Deferred Features Register). Concurrency: single-threaded VCGen; VCs of distinct procedures are embarrassingly parallel (deferred parallel discharge). Persistence: none — verification is in-memory; SMT scripts + proofs stream to files. Protocol: the source language + spec sublanguage is the input contract; SMT-LIB2 is the solver contract; the CLI/library result triplet (Verified/Refuted/Unknown) is the external contract.

8. Domain Model / Source Language / Verification IR

8.1 Source + spec language (EBNF)

program     ::= { decl } ;
decl        ::= proc_decl | func_decl | type_decl | ghost_decl ;
type_decl   ::= "type" Ident [ "=" adt_def ] ;            (* uninterpreted or ADT *)
adt_def     ::= ctor { "|" ctor } ;
ctor        ::= Ident [ "(" field { "," field } ")" ] ;
field       ::= Ident ":" sort ;
func_decl   ::= "function" Ident "(" [ params ] ")" ":" sort
                { "decreases" expr } [ "=" expr ] ;        (* pure; recursive ⇒ decreases *)
proc_decl   ::= "method" Ident "(" [ params ] ")" [ "returns" "(" params ")" ]
                { contract } block ;
contract    ::= "requires" expr                            (* precondition *)
              | "ensures"  expr                            (* postcondition (may use old(.)) *)
              | "modifies" lvalue { "," lvalue }           (* frame *)
              | "reads"    lvalue { "," lvalue }           (* read frame for functions *)
              | "decreases" expr { "," expr } ;            (* termination metric *)
params      ::= param { "," param } ;
param       ::= [ "ghost" ] Ident ":" sort ;
sort        ::= "int" | "real" | "bool" | "bv" Nat
              | "array" "<" sort "," sort ">" | Ident ;     (* Ident = ADT/uninterpreted *)
block       ::= "{" { stmt } "}" ;
stmt        ::= var_decl | assign | if_stmt | while_stmt
              | "assert" expr ";" | "assume" expr ";"
              | "havoc" lvalue { "," lvalue } ";"
              | call ";" | "return" ";" | block ;
var_decl    ::= [ "ghost" ] "var" Ident ":" sort [ ":=" expr ] ";" ;
assign      ::= lvalue ":=" expr ";" ;
lvalue      ::= Ident | Ident "[" expr "]" ;               (* var or array element *)
if_stmt     ::= "if" "(" expr ")" block [ "else" block ] ;
while_stmt  ::= "while" "(" expr ")"
                { "invariant" expr } [ "decreases" expr { "," expr } ] block ;
call        ::= [ lvalue { "," lvalue } ":=" ] Ident "(" [ args ] ")" ;
expr        ::= literal | lvalue | "old" "(" expr ")"
              | expr binop expr | unop expr
              | Ident "(" [ args ] ")"                      (* function application *)
              | "(" expr ")"
              | quant Ident ":" sort [ "{" trigger { "," trigger } "}" ] "::" expr
              | expr "[" expr "]" | expr "[" expr ":=" expr "]" (* select / store *)
              | "match" expr "{" { matcharm } "}" ;
quant       ::= "forall" | "exists" ;
trigger     ::= expr ;                                      (* must cover bound var *)
binop       ::= "+" | "-" | "*" | "/" | "%" | "==" | "!=" | "<" | "<=" | ">" | ">="
              | "&&" | "||" | "==>" | "<==>" ;
unop        ::= "-" | "!" ;
literal     ::= Nat | Real | "true" | "false" | bvliteral ;

Worked source (the canonical example — binary search "find max"):

method MaxIndex(a: array<int,int>, n: int) returns (m: int)
  requires n > 0
  ensures  0 <= m < n
  ensures  forall j: int { a[j] } :: 0 <= j < n ==> a[j] <= a[m]
{
  m := 0;
  var i: int := 1;
  while (i < n)
    invariant 1 <= i <= n
    invariant 0 <= m < i
    invariant forall j: int { a[j] } :: 0 <= j < i ==> a[j] <= a[m]
    decreases n - i
  {
    if (a[i] > a[m]) { m := i; }
    i := i + 1;
  }
}

8.2 Verification IR (guarded commands)

vir_proc  ::= "proc" Ident "(" vars ")" "{" cfg "}" ;
cfg       ::= block { block } ;
block     ::= label ":" { gcmd } terminator ;
terminator::= "goto" label { label }        (* nondeterministic choice over successors *)
            | "return" ;
gcmd      ::= "assume" expr                  (* path/loop/contract assumptions *)
            | "assert" expr label_kind span  (* the obligations; carry provenance *)
            | "havoc" var { var }            (* nondeterministic re-assignment *)
            | var ":=" expr ;                (* assignment (removed by passify) *)
label_kind::= "pre" | "post" | "inv_entry" | "inv_pres" | "decreases"
            | "assert" | "bounds" | "frame" | "div_nonzero" ;

VIR semantics (predicate-transformer view — Dijkstra/Boogie):

Command Meaning wp(c, Q)
assume P proceed only on paths where P holds P ⇒ Q
assert P obligation: P must hold here; else fail P ∧ Q
havoc x x takes an arbitrary value ∀x. Q
x := e (pre-passify) assign Q[e/x]
c1 ; c2 sequence wp(c1, wp(c2, Q))
c1 □ c2 nondeterministic choice (≈ goto) wp(c1,Q) ∧ wp(c2,Q)
skip nothing Q

8.3 Loop translation (the cut) and call translation (modular frame)

while (g) invariant I decreases V { B }      ⟿     # mods = vars assigned in B
   assert I ;                                       # I holds on entry  (inv_entry)
   havoc mods ;                                      # forget loop-modified vars
   assume I ;                                         # arbitrary iteration: assume I
   ( assume g ;                                        #   enter body
     assert 0 <= V ;                                  #   variant bounded below (decreases)
     let v0 = V in B ; assert I ; assert V < v0 ;     #   body re-establishes I, V decreased
     assume false                                     #   this path is for verification only
     □                                                #   ─ or ─
     assume !g )                                       #   exit: fall through with I ∧ ¬g
x := p(args)   (callee: requires Pre, ensures Post, modifies M)   ⟿
   assert Pre[args/params] ;          # caller must establish callee precondition  (pre)
   havoc M, x ;                        # forget everything the callee may change
   assume Post[args/params, old↦pre] ;# assume the callee's postcondition (post)

8.4 VC structure + the SMT validity query

A procedure's VC is a conjunction of block verification equations (compacted):

VC(proc) ≡  ⋀_b  ( Block_b  ⟺  wp_local(b, ⋀_{s∈succ(b)} Block_s) )   ∧   Block_entry

where Block_b is a fresh proposition per block and wp_local is WP over the block's guarded commands only (continuations referenced via Block_s, not inlined — this is the linear-size encoding, P6/I6). Validity check: emit (assert (not VC)) (check-sat); unsat ⟹ Verified; sat ⟹ a model ⟹ counterexample.

8.5 Worked verification — MaxIndex obligations (sketch)

For §8.1 MaxIndex, the VCs are: (1) inv_entry — after m:=0; i:=1, the three invariants hold (1≤1≤n, 0≤0<1, vacuous ∀j. 0≤j<1 ⇒ …); (2) inv_pres — assuming the invariants + i<n, the body (if a[i]>a[m] {m:=i}; i:=i+1) re-establishes them (the interesting one: the forall extends from <i to <i+1, requiring case analysis on whether m updated); (3) decreases — 0 ≤ n−i and n−(i+1) < n−i; (4) post — on exit (i≥n ∧ invariants), 0≤m<n and the global forall j. 0≤j<n ⇒ a[j]≤a[m] (follows since the invariant forall …<i plus i≥n plus i≤n gives i=n). Each is encoded with the array axioms + a quantified VC; the {a[j]} trigger instantiates the quantifier on exactly the array reads that appear.

8.6 Counterexample example (a missing invariant)

Drop invariant 0 <= m < i. Now inv_pres of the forall can't be proved (the verifier doesn't know m is in range when reading a[m]), and post 0≤m<n fails. SMT returns sat with e.g. n=2, i=1, m=5, a=[…]. cex reconstructs: "postcondition 0 <= m < n may fail; model: on entry the loop established no bound on m; at the loop exit m=5, n=2; failing obligation kind = post at line ensures 0 <= m < n." The fix (re-add the invariant) is implied by the trace. Note this is a spec incompleteness, not a soundness bug — the verifier correctly refuses to verify.

8.7 Malformed / edge / failure-path examples

  • Ill-formed decreases (decreases a[i] where a[i] is unbounded below) → typeck rejects: a decreases term must be a known well-founded sort (Int with a proven lower bound, or a lexicographic tuple) — located error (I2).
  • old(x) for a non-modified x → sound but flagged: old(x)=x for anything outside modifies; a redundant old is a warning, not an error.
  • Frame violation — a method assigns g (a global) but omits it from modifies → the per-procedure modifies-conformance VC fails; Refuted with kind frame (I14). This is the verifier catching an unsound spec, the most important diagnostic.
  • Division by zero — a / b emits an assert b != 0 obligation (kind div_nonzero); if unprovable, Refuted. (Not UB — a checked obligation.)
  • Integer overflow on bv32 — x + 1 where x = 2^31−1 wraps to −2^31 (BV semantics); if a postcondition assumed x+1 > x, it's correctly Refuted (overflow is modeled, I9). The same code on math int verifies (x+1 > x always) — the type choice changes the verdict, as it should.
  • Matching loop — a user axiom forall x {f(x)} :: f(x) == f(g(x)) whose trigger f(x) matches f(g(x)), regenerating f(g(g(x))), … → encode flags matching_loop_risk, suggests a safer trigger or Unknown with reason (I10). Never a hang.
  • Non-terminating recursive function without decreases → typeck requires decreases on recursive functions; absent ⇒ rejected (else the EUF axiom for the function could be inconsistent).
  • Quantifier with no trigger covering the bound variable → typeck rejects (the solver couldn't instantiate it deterministically); user must supply {...} (I2).

Design principles (§6)

  • P1 — Soundness over everything — never report a false program as Verified. Every pass (lower, passify, VCGen, encode) must preserve "VC valid ⟹ program correct." A timeout, a malformed encoding, or an unsupported feature returns Unknown, never Verified. Tradeoff: we accept incompleteness (true programs may not verify) to never accept an unsound one. Violation: a dropped frame axiom or an over-eager simplification that proves a false VC valid is catastrophic and silent — the verifier becomes a confident liar (I1).
  • P2 — VCGen is deterministic and terminating. The same source yields a bit-identical VC; VCGen over the acyclic passive CFG is structurally recursive and always halts (no fixpoint in VCGen — fixpoints live only in absint, where widening guarantees termination). Tradeoff: term construction must use ordered, hash-cons-stable iteration (no HashMap iteration order into a VC). Violation: nondeterministic VCs make failures unreproducible and conformance flaky; a non-terminating VCGen hangs the tool (I7).
  • P3 — Modularity: verify against contracts, never bodies, at call sites. A call p is assert pre; havoc modifies(p); assume post — p's body is irrelevant to the caller's proof. Tradeoff: a too-weak callee contract makes a correct caller fail to verify (incompleteness, not unsoundness). Violation: inlining bodies destroys scalability and couples every caller to every callee's implementation (P-frame, §8).
  • P4 — Frame soundness: the call's havoc set must over-approximate the callee's true effects. If p actually modifies x but its modifies clause omits x, the caller wrongly assumes x unchanged across the call — unsound. The verifier therefore checks that each procedure respects its own modifies clause. Tradeoff: an over-broad modifies is sound but loses precision. Violation: under-declared frames are the classic modular-verification soundness hole (I14).
  • P5 — The trusted computing base is explicit and minimal. What we trust to conclude Verified: the VCGen, the SMT encoding, and the SMT solver. We document it, keep VCGen + encode small + reviewable, and offer an optional proof-checked mode (Deferred Features Register) that shrinks the TCB to an independent certificate checker. Tradeoff: proof production costs time + complexity. Violation: an unstated TCB lets a solver bug silently certify a false program (P-trust).
  • P6 — VCs must be compact (linear), never exponential. Naive WP duplicates the postcondition across every branch → exponential blowup. The block-equation/passive encoding (Leino) introduces one fresh predicate per block and conjoins block equations, sharing continuations. Tradeoff: the compacted VC is less directly readable. Violation: exponential VCs make any non-trivial program time out — incompleteness masquerading as a solver problem (I6).
  • P7 — Encoding is faithful to the source semantics — machine ints wrap, math ints don't. A bv32 add overflows by wrapping (encoded over the bitvector theory); a mathematical int is unbounded (LIA). Mixing them is a deliberate, typed choice in lower/encode, never an accident. Tradeoff: bitvector reasoning is more expensive than LIA. Violation: encoding a machine int as a math int hides overflow bugs (a false Verified); the reverse over-constrains (I9).
  • P8 — Quantifier instantiation is bounded and matching-loop-free. Quantified axioms (array/heap/recursive-function axioms) are emitted with explicit triggers; no trigger may match a term whose instantiation regenerates that trigger forever. Tradeoff: triggers that are too restrictive lose completeness (the solver can't instantiate a needed fact → spurious Unknown); too permissive → matching loops → timeout. Violation: a matching loop turns every VC mentioning the axiom into a non-terminating instantiation storm (I10, P8).
  • P9 — Every Refuted ships a concrete, source-level counterexample. A bare sat is unacceptable; the model is reconstructed into variable valuations, the failing obligation (with kind + span), and a path/trace. Tradeoff: reconstruction couples encode/passify to source provenance (labels must survive every pass). Violation: a counterexample-less refutation is undebuggable; a spurious counterexample (model not actually a program execution) erodes trust (I11).
  • P10 — Incrementality is core, not bolted on. Within a procedure, VCs share an SMT context via push/pop; across edits, only procedures whose VCs changed are re-verified (dependency-tracked). Tradeoff: provenance/dependency bookkeeping. Violation: re-verifying the whole program per edit makes interactive use unusable (P-incremental, Phase 11).
  • P11 — Abstract transfer functions are monotone; widening guarantees termination. The absint fixpoint is sound only if each transfer function is monotone over the lattice, and only terminates on loops because widening forces a finite ascending chain. Tradeoff: widening loses precision (recovered partly by narrowing). Violation: a non-monotone transfer can compute an under-approximation → an unsound inferred invariant → a false Verified downstream (I12/I13).
  • P12 — Separate the engine seams cleanly. parse → typeck → lower → passify → VCGen → encode → smt → cex is a pipeline of total functions over well-defined IRs; BMC/k-induction/absint are alternative consumers of VIR. The SMT backend never sees source; the parser never sees SMT. Tradeoff: more IRs to maintain. Violation: leaking SMT details into VCGen, or source into encode, ossifies the pipeline and makes a new theory or a new front end a rewrite (P-seam).
  • P13 — Determinism + reproducibility end to end. Fixed encoding order, pinned solver version + seed, no wall-clock in decisions. A verification outcome reproduces exactly across runs and machines. Tradeoff: must order every iteration explicitly. Violation: a flaky Verified/Unknown is unactionable; a bug that won't reproduce can't be fixed (I7, P2).
  • P14 — Bounded resources, graceful Unknown. Per-VC time + global memory budgets are first-class; on exhaustion the verifier returns Unknown(reason) and frees the SMT process — never crashes, never lies. Tradeoff: an under-resourced run under-reports. Violation: an OOM-killed verifier loses the run; returning Verified on timeout is the worst soundness bug (I15, P8).
  • P15 — Specifications are checked for well-formedness before use. A decreases that isn't well-founded, a postcondition referencing out-of-scope state, a trigger not covering its bound variables — all rejected at typeck, with a located error, before a VC is built. Tradeoff: stricter specs are more work to write. Violation: an ill-formed spec produces a meaningless VC — a "verified" that proves nothing (I2/I8).
