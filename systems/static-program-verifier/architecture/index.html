3. Architectural Overview

A single, strictly-ordered, non-cyclic compiler pipeline: annotated source enters at spv-cli, flows down through six transformation crates, and exits as a verdict (Verified) or a classified VError with a source-level Counterexample. No stage skips, no stage feeds backward; each lowers one IR to the next and is independently inspectable (print-ast/print-ivl/print-vc/print-smt). The only external dependency is the SMT solver, reached through one trait (SmtSolver) over SMT-LIB 2 text.

  Trust: source.spv untrusted; IRs trusted-by-construction; a buggy solver

Direction of data flow: source text -> Token -> Program -> typed AST -> IvlCmd -> VcFormula -> SmtTerm/SMT-LIB -> SmtResult -> VerifyResult. Every arrow is a total lowering of a smaller, more-explicit language; soundness is the conjunction of each arrow preserving meaning (Sec 3.8).

3.2 spv-syntax — source front end

Owns Lexer, Token, the recursive-descent Parser, and the entire surface AST (Program, Decl, Method, Function, Stmt, Expr, Spec, Type). Input: untrusted UTF-8 source bytes (the trust boundary). Output: a Program AST or ParseError{kind: ParseErrorKind} (UnexpectedToken/BadSpec/BadType). no_std + alloc — pure, allocation-only, no I/O, deterministic. Key invariant: the AST is a faithful, lossless tree of the source (spans on every node for later error mapping); the parser never silently repairs or drops a clause — malformed input is a ParseError, never a partial tree that could later verify. Spec clauses (requires/ensures/modifies/decreases), old(), assert/assume, and Quant with Triggers are first-class grammar productions, not afterthoughts. Built in Phase 0 (type shells) and fully in Phase 1.

3.3 spv-ast — name resolution, type checking, spec well-formedness

Owns Type, TypeError, and the resolved/typed AST. Input: surface Program from spv-syntax; output: the same AST with every Var/Call/Field resolved to a declaration and every Expr assigned a Type, or a precise TypeError (Undeclared, Mismatch{expected,got}, NonBoolSpec, OldOutsideEnsures, BadModifies, ArityMismatch). The TypeChecker infers/checks Int/Bool/Ref/Map/Seq/Named and enforces spec well-formedness: every requires/ensures/invariant expression is Bool; Old() appears only inside ensures (else OldOutsideEnsures); modifies entries name framable locations (else BadModifies); call/function arities match. Key invariant: every node downstream stages touch is resolved and well-typed, so spv-ivl/spv-vc never face an undeclared name or a type ambiguity and can lower without runtime type queries; an ill-formed spec is rejected here, before it could be silently treated as a tautology and let a buggy program verify. Built in Phase 2 (consuming the logical-expression semantics fixed in Phase 3).

3.4 spv-ivl — intermediate verification language + desugaring

Owns IvlCmd (Assume/Assert/Havoc/Assign/Seq/Choice), Reason{kind: VErrorKind, span}, and the Desugarer (desugar_method). Input: typed AST; output: one IvlCmd per method. The Boogie-like guarded-command core erases source control flow into nondeterminism: if -> Choice(Seq[Assume(g), then], Seq[Assume(Not g), else]); assignment/return -> Assign; assert/assume -> Assert/Assume; a method body is wrapped Seq[Assume(requires), body..., Assert(ensures)]; a Call -> Seq[Assert(callee.requires), Havoc(modifies), Assume(callee.ensures)] (modular, Sec 3.7); a While -> the invariant cut Seq[Assert(inv), Havoc(targets), Assume(inv), Choice(inductive-step, exit)] with decreases for termination (Sec 3.7, Phase 6). Key invariant — soundness of lowering: the IvlCmd must over-approximate nothing the source guarantees and under-approximate nothing it must prove — every reachable source assertion becomes a reachable Assert, and every Havoc exactly covers the frame that may change. Dropping an Assert, narrowing a Havoc, or mis-encoding a guard is a soundness bug (a buggy program would verify). Each Assert carries a Reason linking it back to a source VErrorKind + Span so spv-verify can name the failure. Built in Phases 4 (straight-line: assign/assert/assume/if), 5 (contracts/calls/framing), and 6 (loops/termination).

3.5 spv-vc — weakest-precondition VC generation + passive form

Owns VcFormula (first-order logic: True/False/And/Or/Not/Imp/Forall/Exists/Atom(Pred)), wp, and passify. Input: an IvlCmd; output: a VcFormula that is valid iff the method meets its spec. Two stages: passify(c) rewrites to dynamic single assignment (DSA) — each Var written once, fresh versions per assignment, Assign becoming an Assume of an equality, Choice arms merged with version reconciliation — so that wp(x:=e, Q)=Q[e/x] does not duplicate Q and explode (the Flanagan-Saxe passive-form trick keeps VC size near-linear instead of exponential); then wp(c, True) applies the six rules (Sec 3.1) bottom-up to the passive command. A final simplification pass (constant folding, Imp/And flattening, dead-True elimination) shrinks the formula before SMT. Key invariant — soundness of VCGen, the cardinal property: wp must compute the weakest precondition exactly — never weaker (would let buggy programs verify) — and passify must be a meaning-preserving renaming. This crate is where an off-by-one in a wp rule or a botched DSA merge most directly causes false "verified", so it is the most heavily fuzzed and differentially tested stage (Phase 13). Built in Phases 7 (wp) and 8 (DSA + simplification).

3.6 spv-smt — SMT encoding + solver interface

Owns SmtSort (Int/Bool/Uninterp(Atom)/Array(_,_)), SmtTerm, the SmtSolver trait, SmtResult (Unsat/Sat(Model)/Unknown), and Model. Input: a VcFormula; output: SmtTerms + emitted SMT-LIB 2, and the solver's SmtResult. Maps the FOL VcFormula onto sorted SMT terms — Int/Bool directly, pure functions to Uninterp, heaps/Map/Seq to Array with select/store axioms — and annotates each Forall with Triggers to control quantifier instantiation (untriggered quantifiers => Unknown/timeout/matching loops). The verifier asks for refutation: SmtSolver.check(&[NOT VC]). Key invariant — soundness of encoding: the SMT translation must be a conservative, faithful model of VcFormula semantics — every SMT-LIB axiom and sort must agree with the logical meaning, because a mis-encoded operator that makes NOT VC spuriously Unsat reports a false "verified". The SmtSolver trait is the sole boundary to the external (trusted) solver — #278 or Z3 — over SMT-LIB text; a buggy solver is an explicit soundness assumption, not this crate's fault, but Unknown is surfaced, never swallowed. Built in Phases 9 (encode/emit/trait/sorts) and 10 (backend integration, push/pop, Unknown handling).

3.7 spv-verify — driver, verdict mapping, counterexample reconstruction

Owns VerifyResult (Verified/Failed(Vec<VError>)), VError{kind: VErrorKind, span, counterexample}, VErrorKind (the eight classes: AssertionMightNotHold, PostconditionMightNotHold, PreconditionOfCallMightNotHold, LoopInvariantOnEntry, LoopInvariantNotMaintained, DivisionByZero, ModifiesViolation, MightNotTerminate), and Counterexample{bindings, at}. Input: the typed Program; orchestrates per-method desugar -> passify -> wp -> encode -> check. Verdict mapping (LOCKED): Unsat => Verified; Sat(Model) => VError; Unknown => reported as such, NEVER Verified. On Sat, it decodes the Model, reverses the DSA/skolem renaming back to source Atoms, locates the failing program point via the triggering Assert's Reason{kind, span}, classifies the VErrorKind, and renders a readable Counterexample (bindings: Vec<(Atom, Value)>, at: Span). Key invariant: the driver upholds end-to-end soundness — it must treat anything other than a clean Unsat as "not verified", so timeouts/incompleteness can never masquerade as success; and the counterexample must point at the actual failing source location, not a DSA artifact. Modular verification lives here: each method is verified solely against callee contracts (never bodies), so methods are independent verification jobs — the basis for safe parallelism (Sec 3.1 concurrency boundary). Built in Phases 0 (smoke verdict), 10 (discharge), 11 (counterexample), 12 (richer features wiring).

3.8 spv-cli — driver binary

The spv binary (std): subcommands verify, print-ast, print-ivl, print-vc, print-smt. Input: a source.spv path + flags; output: a VerifyResult rendered to stdout with a process exit code (0 = Verified, nonzero = Failed/error), or the chosen IR dump for inspection. It is the only crate doing I/O and the only std crate; all logic crates above are pure (spv-syntax is no_std + alloc). Key invariant: the CLI is a thin shell — it adds no verification logic, only argument parsing, file reading, solver process wiring, and rendering, so the trusted computing base for soundness stays in the lower crates. The print-* subcommands expose each pipeline stage's IR verbatim, making the lowering chain (Sec 3.1) auditable end to end. Built in Phase 0 and extended per phase as each IR becomes printable.

3.9 Cross-cutting properties

Property Where enforced Statement
Soundness (cardinal) spv-ivl, spv-vc, spv-smt, spv-verify A buggy program MUST NEVER report Verified. Every lowering over-/under-approximates correctly; Unknown is never Verified.
Completeness (secondary) spv-smt + spv-verify Verify all correct programs as far as SMT allows; bounded by quantifiers/Unknown/timeouts — tracked separately from soundness in Phase 13.
Determinism all crates Same source + same solver => same VerifyResult. No clocks, no RNG, no iteration-order dependence in IR construction.
Auditability spv-cli print-* Every IR (Program/IvlCmd/VcFormula/SMT-LIB) is dumpable; no hidden stage.
Trust boundary spv-syntax entry; SmtSolver exit Only source.spv is untrusted; the solver is a trusted soundness assumption reached over SMT-LIB.
Modularity spv-verify Each Call checked against callee Spec only; methods verify independently => scalable + parallelizable.

8. Domain Model — Source Language, IVL, and Verification Conditions

The verifier is a five-stage lowering: source AST (spv-syntax) → typed AST (spv-ast) → IVL guarded commands IvlCmd (spv-ivl) → passive-form IVL + VC VcFormula (spv-vc) → SMT-LIB SmtTerm (spv-smt). This section pins the meaning of each representation; later phases (## 12–## 25) implement them. Soundness is the cardinal invariant: every lowering must over-approximate the program's executions so a buggy program can never be lost (no execution dropped between stages).

8.1 Source language — EBNF

The surface syntax parsed by spv-syntax's Lexer + recursive-descent Parser into Program. ASCII; // … line comments; identifiers interned as Atom. Operator precedence (low→high): ==>, ||, &&, == != < <= > >=, + -, * / %, unary ! -. ==> is right-assoc; arithmetic left-assoc.

program     = { decl } ;
decl        = method | function | axiom ;
method      = "method" Ident "(" [ params ] ")" [ "returns" "(" params ")" ] spec ( block | ";" ) ;
function    = "function" Ident "(" [ params ] ")" ":" type spec [ "{" expr "}" ] ;
axiom       = "axiom" expr ";" ;
params      = param { "," param } ;
param       = Ident ":" type ;
spec        = { requires | ensures | modifies | decreases } ;
requires    = "requires" expr ";" ;
ensures     = "ensures"  expr ";" ;        (* may contain old(...) *)
modifies    = "modifies" expr { "," expr } ";" ;
decreases   = "decreases" expr { "," expr } ";" ;
block       = "{" { stmt } "}" ;
stmt        = vardecl | assign | ifstmt | whilestmt | callstmt
            | "assert" expr ";" | "assume" expr ";" | "return" ";" ;
vardecl     = "var" Ident ":" type [ ":=" expr ] ";" ;
assign      = lvalue ":=" expr ";" ;
callstmt    = [ lvalue { "," lvalue } ":=" ] "call" Ident "(" [ args ] ")" ";" ;
ifstmt      = "if" "(" expr ")" block [ "else" block ] ;
whilestmt   = "while" "(" expr ")" { "invariant" expr ";" } { "decreases" expr ";" } block ;
lvalue      = Ident | expr "." Ident ;     (* var or field (heap) *)
args        = expr { "," expr } ;
expr        = quant | impl ;
impl        = orexpr [ "==>" impl ] ;
orexpr      = andexpr { "||" andexpr } ;
andexpr     = cmp { "&&" cmp } ;
cmp         = add { ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) add } ;
add         = mul { ( "+" | "-" ) mul } ;
mul         = unary { ( "*" | "/" | "%" ) unary } ;
unary       = ( "!" | "-" ) unary | atom ;
atom        = literal | Ident | call_expr | "old" "(" expr ")"
            | expr "." Ident | "(" expr ")" ;
call_expr   = Ident "(" [ args ] ")" ;     (* pure-function application *)
quant       = ( "forall" | "exists" ) qvars [ trigger ] "::" expr ;
qvars       = Ident ":" type { "," Ident ":" type } ;
trigger     = "{" expr { "," expr } "}" { "{" expr { "," expr } "}" } ;
type        = "int" | "bool" | "ref" | "map" "<" type "," type ">"
            | "seq" "<" type ">" | Ident ;
literal     = Number | "true" | "false" | "null" ;

Distinction (LOCKED): callstmt (the Stmt::Call guarded command, side-effecting, contract-checked) vs call_expr (the Expr::Call pure-function application, used inside formulas). method with ; instead of a block = an abstract method (contract only, body: None) — verified by clients, not itself.

8.2 Surface AST → resolved/typed AST

spv-syntax emits the AST shells in §Core Types; spv-ast resolves Atoms to binding sites and annotates every Expr with a Type. Mapping is structural and 1:1:

8.3 Type system

Type ∈ { Int, Bool, Ref, Map(K,V), Seq(E), Named(Atom) }. No subtyping, no implicit coercion, structural equality on Type. Typing judgement Γ ⊢ e : T (Γ = params ∪ returns ∪ in-scope vars ∪ quantifier vars).

Construct Rule (telegraphic) Failure ⇒ TypeError
Var x x:T ∈ Γ ⇒ Int/Bool/… Undeclared(x)
Lit n / true,false / null Int / Bool / Ref —
e1 + e2 (- * / %) both Int ⇒ Int Mismatch{expected:Int,got}
e1 < e2 (<= > >=) both Int ⇒ Bool Mismatch{Int,got}
e1 == e2 (!=) same T ⇒ Bool Mismatch{ty(e1),ty(e2)}
e1 && e2 (||, ==>) both Bool ⇒ Bool Mismatch{Bool,got}
!e Bool ⇒ Bool; -e: Int⇒Int Mismatch
m[k] (map sel) m:Map(K,V) ∧ k:K ⇒ V Mismatch
s[i] (seq sel) s:Seq(E) ∧ i:Int ⇒ E Mismatch
e.f e:Ref, f declared field of type T ⇒ T BadModifies/Undeclared(f)
f(a…) (pure fn) f:(T1..Tn)->T, ai:Ti, count=n ⇒ T ArityMismatch / Mismatch
old(e) ty(old e)=ty(e); legal context only OldOutsideEnsures
forall/exists x:T :: body body:Bool under Γ,x:T ⇒ Bool NonBoolSpec

Statement well-typedness: Assign(lv,e) ⇒ ty(lv)=ty(e); If/While guard :Bool; Assert/Assume arg :Bool; Call(outs,m,ins) ⇒ ins match m.params, outs match m.returns (else ArityMismatch/Mismatch); return only in method body.

8.4 Spec well-formedness (spv-ast)

Beyond typing, four spec-shape checks (a malformed spec is a tool input error, never silently dropped — that would threaten soundness):

Rule Constraint Violation ⇒ TypeError
WF-1 Boolean every requires/ensures/invariant clause :Bool NonBoolSpec
WF-2 old-scope Old(e) only inside ensures (and 2-state postconds); never in requires/invariant/decreases/body OldOutsideEnsures
WF-3 modifies each modifies term is an l-value path (x or e.f over Ref); requires/ensures may only mutate names in modifies BadModifies
WF-4 decreases each decreases term :Int (or a tuple of ints, lexicographic); present on every while needing total correctness and on recursive functions Mismatch{Int,got}

8.5 IVL grammar — IvlCmd (six forms)

spv-ivl lowers the typed AST to a Boogie-like guarded-command IVL. The whole language is six constructors — the deliberate minimalism is what makes wp (§8.7) a six-rule function.

IvlCmd = "assume" Expr                       (* assume p — restrict states to p     *)
       | "assert" Expr Reason                (* assert p — proof obligation (tagged) *)
       | "havoc" Var { "," Var }             (* set vars to arbitrary values         *)
       | Var ":=" Expr                       (* assign                               *)
       | IvlCmd { ";" IvlCmd }               (* Seq — sequencing                     *)
       | IvlCmd "[]" IvlCmd ;                (* Choice — nondeterministic choice     *)

Maps to IvlCmd::{Assume(Expr), Assert(Expr,Reason), Havoc(Vec<Var>), Assign(Var,Expr), Seq(Vec<IvlCmd>), Choice(Box<IvlCmd>,Box<IvlCmd>)}. Every Assert carries Reason{kind:VErrorKind, span:Span} so that a Sat model later (## 23) names which source assertion failed. Operational semantics: assume p blocks executions where ¬p; assert p fails (is an error) on executions where ¬p; havoc forks over all values; [] forks over both branches. Verification = no execution reaches a failing assert.

8.6 Desugaring rules — source construct → IvlCmd

desugar_method(m: &Method) -> IvlCmd produces, for method m: assume(⋀requires) ; havoc returns,locals ; ⟦body⟧ ; assert(⋀ensures, PostconditionMightNotHold). The body translation ⟦·⟧ (LOCKED):

Source construct IvlCmd lowering Reason.kind of generated asserts
x := e x := e —
var x:T := e x := e (fresh Var x) —
var x:T; havoc x —
assert p assert p AssertionMightNotHold
assume p assume p —
e1 / e2, e1 % e2 precede use with assert e2 != 0 DivisionByZero
s1 ; s2 ⟦s1⟧ ; ⟦s2⟧ —
if (g) {s1} else {s2} (assume g ; ⟦s1⟧) [] (assume !g ; ⟦s2⟧) —
call o := m(a) assert ⋀m.requires[a/params] ; havoc m.modifies ; o := havoc'd ; assume ⋀m.ensures[a/params, o/returns] PreconditionOfCallMightNotHold
return assume true (control reaches method-exit assert) —
while (g) inv I dec D {body} invariant cut, see below LoopInvariantOnEntry, LoopInvariantNotMaintained, MightNotTerminate

Loop invariant cut (Phase 6, ## 18) — loops are never unrolled; an invariant I = ⋀invariants cuts the loop into three obligations spliced as one straight-line IvlCmd:

assert I                       Reason: LoopInvariantOnEntry           (I holds before loop)
havoc t1,…,tk                  (t = loop targets: vars assigned in body)
assume I                       (arbitrary iteration starting in I)
(  assume g                                                          (inductive step…)
   ⟦body⟧
   assert I                    Reason: LoopInvariantNotMaintained     (…re-establishes I)
   assert D < old(D) && D>=0   Reason: MightNotTerminate              (variant decreases)
   assume false                                                      (cut: step explores no further)
) [] (
   assume !g                                                         (exit branch continues)
)

After the cut, the continuation observes only I ∧ ¬g. assume false makes the inductive-step branch contribute nothing to the post — that branch only discharges "I preserved". The pitfall (LOCKED): a too-weak I makes the LoopInvariantNotMaintained assert fail with a counterexample to the user's invariant, not the program.

Frame / modifies (Phase 5, ## 17): havoc m.modifies scrambles exactly the contracted set; everything outside it is implicitly framed (unchanged). A callee that mutates outside its modifies is caught by ModifiesViolation asserts emitted at the call site. Modular verification ⇒ a call is checked against the callee contract, never its body — the scaling property.

8.7 Weakest-precondition calculus — wp

wp(c: &IvlCmd, post: VcFormula) -> VcFormula in spv-vc. Exactly six rules (one per IvlCmd):

c wp(c, Q) intuition
assume p p ==> Q only states satisfying p survive
assert p p ∧ Q p must hold and the rest
havoc x ∀x. Q Q must hold for all values of x
x := e Q[e/x] substitute (only in passive form; see §8.8)
c1 ; c2 wp(c1, wp(c2, Q)) right-to-left threading
c1 [] c2 wp(c1, Q) ∧ wp(c2, Q) both branches must establish Q

The method VC = wp(desugar_method(m), True). Theorem (Hoare/Dijkstra, LOCKED): {P} c {Q} holds iff P ==> wp(c,Q). Hence the program meets its spec iff the VC is valid, which holds iff ¬VC is unsatisfiable in SMT. verify therefore asks the solver to refute ¬VC: Unsat ⇒ Verified; Sat(model) ⇒ VError + Counterexample. Partial correctness omits the MightNotTerminate asserts; total correctness includes them.

8.8 Passive form (dynamic single assignment)

passify(c: &IvlCmd) -> IvlCmd (Phase 8, ## 20). Naïve wp(x:=e,Q)=Q[e/x] duplicates Q at every assignment, and [] duplicates again — wp over n assignments + m choices is O(2^m) in formula size (the exponential blowup, Flanagan–Saxe 2001). DSA fixes it: rename each variable to a fresh version x_0, x_1, … so every version is assigned exactly once; rewrite x_i := e into assume x_i == e[versions]; at a Choice join, havoc x_j to the max version, then each branch assume x_j == x_branch. With assignments now assumes of equalities, wp introduces no substitution duplication ⇒ VC size grows ~linearly.

Worked DSA on if (x>0){ y:=x } else { y:=0-x }; assert y>=0:

source IVL:  (assume x>0 ; y:=x) [] (assume !(x>0) ; y:=0-x) ; assert y>=0  [AssertionMightNotHold]

passive (DSA):                                  version map: x→x0; y on entry y0, joined y3
  ( assume x0>0  ; assume y1 == x0   )
  []
  ( assume !(x0>0) ; assume y2 == 0-x0 )
  ; assume (x0>0  ==> y3==y1) && (!(x0>0) ==> y3==y2)
  ; assert y3>=0

wp of the passive command into True (six rules, no blowup):

VC =  ( x0>0  ==> y1==x0  ==> ( (x0>0==>y3==y1)&&(!(x0>0)==>y3==y2) ==> y3>=0 ) )
   && ( !(x0>0) ==> y2==0-x0 ==> ( (x0>0==>y3==y1)&&(!(x0>0)==>y3==y2) ==> y3>=0 ) )

8.9 VcFormula (FOL) → SMT-LIB

VcFormula is sorted first-order logic: True | False | And(Vec) | Or(Vec) | Not | Imp | Forall(vars,triggers) | Exists(vars) | Atom(Pred). Pred = an atomic predicate over terms (arithmetic comparisons, equalities, uninterpreted-function applications). spv-smt maps it to SmtTerm over SmtSort ∈ { Int, Bool, Uninterp(Atom), Array(K,V) }, emitting SMT-LIB 2:

VcFormula / Type SMT-LIB
Type::Int / Bool Int / Bool
Type::Ref / Named(t) (declare-sort t 0) ⇒ Uninterp(t)
Type::Map(K,V) / Seq(E) (Array K V) / (Array Int E)
And[..] / Or[..] (and …) / (or …)
Not / Imp(a,b) (not a) / (=> a b)
Atom(eq a b) / < (= a b) / (< a b)
map/seq select m[k] (select m k)
map/seq store m[k:=v] (store m k v)
Forall(vs,trigs,b) (forall (vs…) (! b :pattern (trigs…)))
Exists(vs,b) (exists (vs…) b)
pure fn f (declare-fun f (T1..Tn) T) + defining (assert (forall … (= (f x) body))) w/ fuel if recursive

The solver call is (assert (not VC)) (check-sat) via SmtSolver::check(&[SmtTerm]) -> SmtResult. Triggers ({…}) guide quantifier instantiation; a bad/missing trigger ⇒ Unknown or a matching loop, not unsoundness. Unknown (timeout/incompleteness) is surfaced explicitly, never treated as Verified (soundness).

8.10 Fully worked example — Max

Source (spv-syntax):

method Max(a: int, b: int) returns (m: int)
  ensures m >= a;
  ensures m >= b;
  ensures m == a || m == b;
{
  if (a >= b) { m := a; } else { m := b; }
}

Typed AST (spv-ast): Γ = {a:Int, b:Int, m:Int}; all three ensures clauses type Bool (WF-1 ✓); no old() (WF-2 vacuous); empty modifies (WF-3 ✓). IVL (desugar_method):

assume true ;                                      (no requires)
havoc m ;
( (assume a>=b ; m:=a) [] (assume !(a>=b) ; m:=b) ) ;
assert (m>=a) && (m>=b) && (m==a || m==b)          Reason: PostconditionMightNotHold

Passive (DSA): m versions m1 (then-branch), m2 (else), joined m3:

( assume a>=b   ; assume m1==a )
[] ( assume !(a>=b) ; assume m2==b )
; assume (a>=b ==> m3==m1) && (!(a>=b) ==> m3==m2)
; assert (m3>=a)&&(m3>=b)&&(m3==a||m3==b)

VC (= wp(…, True), both [] branches conjoined; abbreviate the post as P(m3)):

VC =  ( a>=b   ==> m1==a ==> Join ==> P(m3) )
   && ( !(a>=b) ==> m2==b ==> Join ==> P(m3) )
   where Join = (a>=b==>m3==m1)&&(!(a>=b)==>m3==m2),  P(m)=(m>=a)&&(m>=b)&&(m==a||m==b)

SMT (spv-smt, ¬VC):

(declare-const a Int)(declare-const b Int)
(declare-const m1 Int)(declare-const m2 Int)(declare-const m3 Int)
(assert (not (and
  (=> (>= a b) (=> (= m1 a) (=> (and (=> (>= a b)(= m3 m1)) (=> (not (>= a b))(= m3 m2)))
        (and (>= m3 a)(>= m3 b)(or (= m3 a)(= m3 b))))))
  (=> (not (>= a b)) (=> (= m2 b) (=> (and (=> (>= a b)(= m3 m1)) (=> (not (>= a b))(= m3 m2)))
        (and (>= m3 a)(>= m3 b)(or (= m3 a)(= m3 b)))))))))
(check-sat)        ; => unsat   ⇒  VerifyResult::Verified

Buggy variant — drop the third ensures and write else { m := b; } as else { m := a; } (returns a always):

method MaxBug(a,b) returns (m) ensures m>=a; ensures m>=b;
{ if (a>=b){ m:=a; } else { m:=a; } }

VC negation is now Sat. SmtResult::Sat(Model{ a:=0, b:=5, m3:=0 }). spv-verify (## 23) maps m3 → m, reads Reason{kind:PostconditionMightNotHold, span:<ensures m>=b>}, and reconstructs:

VError { kind: PostconditionMightNotHold,
         span: <line: ensures m >= b>,
         counterexample: Counterexample {
           bindings: [(a,Int(0)),(b,Int(5)),(m,Int(0))], at: <method exit> } }
⇒ VerifyResult::Failed([VError])

8.11 Loop example — SumTo (invariant cut + DSA)

method SumTo(n: int) returns (s: int)
  requires n >= 0;
  ensures s == n*(n+1)/2;
{
  var i: int := 0; s := 0;
  while (i < n)
    invariant 0 <= i && i <= n;
    invariant s == i*(i+1)/2;
    decreases n - i;
  { i := i + 1; s := s + i; }
}

IVL (cut per §8.6; targets t = {i, s}; I = 0<=i && i<=n && s==i*(i+1)/2; D = n-i):

assume n>=0 ; havoc s ; i:=0 ; s:=0 ;
assert I                                   LoopInvariantOnEntry
havoc i,s ; assume I ;
( assume i<n ; i:=i+1 ; s:=s+i ;
  assert I                                 LoopInvariantNotMaintained
  assert (n-i < old(n-i)) && (n-i >= 0)    MightNotTerminate
  assume false )
[] ( assume !(i<n) ) ;
assert s == n*(n+1)/2                       PostconditionMightNotHold

After passify + wp the VC is valid (Unsat of ¬VC) ⇒ Verified. Two failure surfaces to test (Phase 13, ## 25): (1) drop invariant s == i*(i+1)/2 ⇒ the LoopInvariantNotMaintained assert is Sat (i=0,s=0 start, body gives s=1 but I can't relate it) — counterexample is to the weak invariant, not the code. (2) drop the decreases under total correctness ⇒ MightNotTerminate obligation unprovable ⇒ Sat.

8.12 Malformed inputs → diagnostics

Each well-formedness violation is rejected before VC generation (a dropped check would let a buggy program verify — the gravest failure):

Malformed source Caught by Diagnostic
ensures m + 1; (Int spec) WF-1, spv-ast TypeError::NonBoolSpec
requires old(a) > 0; WF-2 TypeError::OldOutsideEnsures
{ y := x + 1; } with x undeclared resolution TypeError::Undeclared("x")
var b: bool := 3; §8.3 TypeError::Mismatch{expected:Bool, got:Int}
m := Max(a); (Max takes 2) §8.3 Call TypeError::ArityMismatch
modifies a + b; (not an l-value) WF-3 TypeError::BadModifies
while(i<n){ i:=i+1; } no invariant desugar + VC not a type error: Assume true invariant ⇒ inductive LoopInvariantNotMaintained/post Sat ⇒ VError, not Verified
forall x:int :: x + 1 (Int body) WF-1 TypeError::NonBoolSpec
if (n) {…} (Int guard) §8.3 TypeError::Mismatch{expected:Bool, got:Int}
lex/parse garbage (method 7() spv-syntax ParseError{kind:UnexpectedToken} / BadSpec / BadType

Diagnostics ordering: ParseError (spv-syntax) precedes TypeError (spv-ast); both precede any IVL/VC work. A missing loop invariant is intentionally not a static error — it manifests as an honest VError so the user learns the invariant is too weak, consistent with the deductive-verification contract (§8.7).
