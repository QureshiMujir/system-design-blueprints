Echoes Web — the only untrusted-host surface; premium-tier client-side WebCrypto encryption happens here before upload (§13). Edge/API Gateway — trusted, hardened; owns session state, MFA gates, rate limits, the audit-log envelope; no business logic. Vault Service — the only component that ever holds plaintext, and only transiently (I1); chunks, encrypts, shards across regions. Delivery Engine — time-critical; sleeps on a heartbeat, wakes at scheduled moments, invokes Identity Service before releasing ciphertext for decryption. Identity Service — evidentiary; owns the verification ladder and produces a signed evidence packet per attempt. Object Storage — S3 + KMS multi-region, Glacier mirror, escrow-partner shards; the redundancy graph that backs the durability numbers in §4. AI Echo Trainer — isolated per-user sandbox (I8); never sees another subject's corpus. AI Echo Dialogue Service — mediated; every turn logged, rate-limited, non-dismissible-disclaimer gated (I13). Postgres + Audit Log Stream — the system of record for schedules and identity, and the tamper-evident ledger every invariant in §7 is checked against.

3.1 Data Flow — Compose Path

  1. User composes in the browser; attaches a DeliveryRule; selects a vault.
  2. Premium tier: client encrypts plaintext with a per-message DEK, wrapped by the vault's KEK (§13, P4).
  3. Ciphertext + wrapped DEK + metadata posted to the API gateway.
  4. Vault Service chunks, applies redundancy, writes multi-region S3, mirrors to Glacier and escrow storage.
  5. Delivery Engine inserts a scheduled job keyed by (messageId, scheduledAt) (I3).
  6. Audit Log Stream records the act of composition — who, when, vault, delivery-rule hash; never plaintext.

3.2 Data Flow — Delivery Path

  1. Delivery Engine wakes at scheduledAt (or when a delivery condition, e.g. death verification, is satisfied).
  2. Identity Service executes the verification ladder appropriate to the policy and elapsed time (§15, §20).
  3. On success, a signed evidence packet is produced.
  4. Vault Service unwraps the DEK (customer-managed keys require the recipient/trustee to present a key fragment; platform-managed keys unwrap automatically).
  5. Plaintext is decrypted in a single short-lived session, presented via the reading surface, and an open-event is logged.
  6. The audit chain — composition, key transitions, verification, open — is sealed.

All later sections stay consistent with this diagram; a proposal that adds a new trust boundary not shown here requires an ADR (§9) before it ships.

8. Domain Model

8.1 Message

type Message = {
  id: MessageId;                 // ULID, monotonic
  vaultId: VaultId;
  authorId: UserId;
  composedAt: ISODateTime;
  ciphertextRef: ObjectRef;      // pointer into Vault Service; never plaintext in metadata
  contentDigest: SHA256Digest;   // verifies integrity at delivery (I1, I14)
  attachments: AttachmentRef[];
  delivery: DeliveryRule;
  recipientPolicy: RecipientPolicy;
  state: MessageState;           // see §8.9 state table
  stateHistory: StateTransition[];
  keyEnvelope: KeyEnvelope;      // wrapped DEK, key class, escrow refs (I7)
  schemaVersion: SchemaVersion;  // e.g. "echoes/message@1.0"
  flags: MessageFlags;           // sensitiveContent, suicideRisk, etc.
};

8.2 DeliveryRule

type DeliveryRule =
  | { kind: "at"; at: ISODateTime; tzHint?: IANATimezone }
  | { kind: "onAge"; subjectId: SubjectId; age: number /* years */ }
  | { kind: "onAnniversary"; date: ISODate; n: number }
  | { kind: "onDeathOf"; subjectId: SubjectId; graceDays: number }
  | { kind: "onCondition"; predicateId: PredicateId }
  | { kind: "compound"; op: "all-of" | "any-of"; rules: DeliveryRule[] };  // max depth 3 (I2)

Rules are versioned, signed at compose time, evaluated by a deterministic sandboxed evaluator (I2, MM1). Time-based rules bind to the canonical TAI-rooted clock (ADR-22).

8.5 Audit Envelope

Every state transition produces an entry keyed by (vaultId, ts, eventId), hash-chained to the prior entry for the same vault (I6, per Merkle 1988 / Lamport 1978, §5). Entries never contain plaintext — only hashes and metadata sufficient for forensic reconstruction. Mirrored off-site monthly.

8.7 Worked Example — Compose a 60-Year onAge Letter

Sender composes at 2026-08-02T00:00:00Z, addresses their newborn, rule = {kind:"onAge", subjectId: <child>, age: 60}. Compose path (§3.1) writes ciphertext + Message row with state: "scheduled"; Delivery Engine cannot resolve an absolute dispatch time yet (subject's exact birth timestamp is pending Identity Service confirmation, §15) — it stores a resolved-time cache once the birth event is confirmed, so the evaluator (I2) never re-derives age from a moving "current date" at dispatch time; it re-derives once, deterministically, from the confirmed birth date, and caches the resolved instant for forensic clarity (§12.2).

8.8 Malformed-Input Example

{kind:"compound", op:"all-of", rules:[{kind:"compound", op:"any-of", rules:[{kind:"compound", op:"all-of", rules:[{kind:"at", at:"2100-01-01"}]}]}]} — nesting depth 4, exceeds the depth-3 ceiling (I2, §12.4). Evaluator rejects at compose time with RULE_DEPTH_EXCEEDED; the message never reaches scheduled.

8.9 Failure-Path Example

Recipient email bounces at dispatch time → delivering → holding (§8.6) → Identity Service invokes the fallback ladder (§15.2) → after 3 failed rungs, the message remains in holding indefinitely, an operator-visible alert fires (echoes_identity_autoresolve_attempts_total stays at 0 — I4 forbids ever auto-resolving to a lesser-verified match), and the sender's named secondary contact (if configured) is notified per the recipient policy.

Design principles (§6)

  • P1 — Delivery Is Sacred. Every change is evaluated against "does this make delivery more reliable, or less?" Tradeoff: slows shipping velocity. Violate it and VDPW regressions ship silently.
  • P2 — Default-to-Hold. Identity Service never auto-delivers to the nearest identity match. Tradeoff: some deliveries delay. Violate it and a wrong-recipient catastrophe (T6) follows.
  • P3 — Sender-Intent Immutability. A locked DeliveryRule cannot be silently altered by the platform. Tradeoff: no retroactive product pivots on stored content. Violate it and user trust collapses irrecoverably.
  • P4 — Envelope Encryption Everywhere. Every message body is encrypted with a per-message DEK wrapped by a KEK. Tradeoff: ~2 extra KMS round-trips per compose/open. Violate it and one key compromise decrypts the whole corpus instead of one message.
  • P5 — Algorithm Agility. Every ciphertext/format carries a version tag enabling non-destructive re-wrap. Tradeoff: extra metadata bytes, migration engineering. Violate it and crypto obsolescence permanently strands old ciphertext.
  • P6 — Append-Only Audit. State transitions are recorded in a hash-chained log, never mutated. Tradeoff: storage grows monotonically. Violate it and forensic reconstruction after an incident becomes impossible.
  • P7 — Idempotent Dispatch. Delivery Engine operations are keyed by (messageId, scheduledAt) and safe to retry. Tradeoff: requires a dedupe store. Violate it and a crash-restart causes double-delivery or lost delivery.
  • P8 — Quorum Before Consequential Action. Death verification and generational key reconstruction require multi-party quorum, never a single assertion. Tradeoff: slower unlock (30-day quiet period). Violate it and a false-positive delivery becomes catastrophic.
  • P9 — Isolation of the AI Echo Corpus. Each subject's training corpus/model is structurally sandboxed. Tradeoff: no shared fine-tuning economies of scale. Violate it and a privacy/dignity catastrophe follows (T8).
  • P10 — Reconstruction, Not Resurrection. AI Echo outputs are disclosed as reconstructions via a non-dismissible UI. Tradeoff: dialogue-UX friction. Violate it and the dignity- violation kill trigger fires.
  • P11 — Format Longevity Floor. Every stored format supports a 25-year backward read. Tradeoff: cannot adopt bleeding-edge formats immediately. Violate it and century-old attachments become unreadable.
  • P12 — Backpressure Over Data Loss. Under load, the Delivery Engine slows dispatch rather than drops jobs. Tradeoff: elevated dispatch jitter temporarily. Violate it and deliveries are silently missed.
  • P13 — Least-Privilege Custodianship. No single party — including Echoes itself — holds enough key material to unilaterally decrypt a generational vault. Tradeoff: quorum- reconstruction operational complexity. Violate it and a single point of catastrophic compromise exists.
  • P14 — Observability Before Optimization. Every subsystem emits invariant-mapped telemetry before performance tuning begins. Tradeoff: upfront instrumentation cost. Violate it and production incidents become undiagnosable.
