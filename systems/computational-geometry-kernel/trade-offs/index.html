Decisions (§9) · 30 ADRs

ADR-1

Implementation language

Chosen

Rust (ed. 2021, MSRV 1.74)

Rejected

C++, C, Go, Python, Java

When the rejected choice is right

C++ wins linking directly into an existing CGAL/Triangle C++ codebase with zero FFI tolerance; Python wins for one-off prototyping/scripting glue where robustness is irrelevant

Why: memory safety over pointer-dense meshes + no implicit FMA contraction; modern robust corpus is Rust

ADR-2

Predicate technique

Chosen

Shewchuk adaptive precision (staged filter→exact)

Rejected

always-f64; always-exact; epsilon-fudging

When the rejected choice is right

always-f64 wins when inputs are provably well-separated (e.g. synthetic grids with a guaranteed minimum gap); always-exact wins for a one-shot offline batch job where wall-clock time is unconstrained

Why: zero misclassification (I1) at filter-speed (Principle 5); the proven gold standard (Paper P1)

ADR-3

EFT primitives

Chosen

two_sum/fast_two_sum/split/two_product (+ FMA two_product variant)

Rejected

naive double-double libs; software bignum everywhere

When the rejected choice is right

naive double-double wins when only a fixed, small precision boost (not full adaptive exactness) is needed and a smaller dependency is valued; bignum-everywhere wins when arbitrary (not just doubled) precision is required throughout, not only at a determinant's top

Why: exact, branch-light, no_std; the building blocks of expansions (Papers P2, P3)

ADR-4

Exact fallback representation

Chosen

floating-point expansions (default) + optional rational (bignum) backend

Rejected

always rational; always interval

When the rejected choice is right

always-rational wins when the surrounding application is already rational/bignum end-to-end (e.g. an algebraic CAD kernel); always-interval wins for a reject-only certifier that never needs an exact tie-break

Why: expansions are faster and no_std; rational backend gated PhaseDeferred("§13")

ADR-5

Filter strategy

Chosen

a-priori error bound (stage A) + optional interval (stage B)

Rejected

interval-only; static analysis

When the rejected choice is right

interval-only wins on targets where directed-rounding interval ops are cheap and a-priori-bound branch history is expensive; static analysis wins when the input distribution is compile-time-known and bounds are provable offline

Why: a-priori bound is fastest common case; interval is a cheap second net

ADR-6

Degeneracy handling

Chosen

Simulation of Simplicity (symbolic perturbation)

Rejected

per-case epsilon branches; random "joggle" (qhull)

When the rejected choice is right

per-case epsilon wins for a single fixed, well-understood primitive pair where SoS machinery is overkill; joggle wins for a throwaway visualization that needs a valid answer, not the exact one

Why: one code path, consistent ties (I12); joggle changes the answer and is non-deterministic

ADR-7

Coordinate type

Chosen

f64 (binary64)

Rejected

f32; fixed-point integer; rational coords

When the rejected choice is right

f32 wins in GPU-bound rendering paths where bandwidth dominates and exactness is irrelevant; fixed-point/rational coords win when the whole pipeline is already integer-based (PCB/CAM tooling) with easy overflow bounds

Why: ecosystem standard; 53-bit mantissa; integer/rational coords are a different (valid) robustness tradeoff (Clipper2) we reject for generality

ADR-8

Kernel parameterization

Chosen

Kernel<NT> trait over number type (f64+filter | interval | rational)

Rejected

hardcoded f64

When the rejected choice is right

hardcoded f64 wins for a narrow single-purpose tool where genericity adds compile-time cost with no reuse payoff

Why: CGAL-style EPIC; swap exactness without rewriting algorithms (ADR-3 of CGAL heritage, R3)

ADR-9

Predicate/construction split

Chosen

enforced by API + types (Constructed marker)

Rejected

When the rejected choice is right

mixing freely wins only inside a throwaway prototype/script that never touches production data or feeds a downstream consumer

Why: confines rounding to constructions (Principle 2, I18)

ADR-10

Planar-subdivision structure

Chosen

DCEL canonical + quad-edge for Delaunay/Voronoi

Rejected

winged-edge; half-edge mesh only; triangle-soup

When the rejected choice is right

winged-edge wins in a legacy codebase already standardized on it; triangle-soup wins for a GPU rasterization path that never needs adjacency queries

Why: DCEL is the general standard; quad-edge is self-dual for Voronoi (Paper P9); one checker (Principle 11)

ADR-11

Mesh storage

Chosen

arena + u32 index handles

Rejected

raw pointers; Rc<RefCell>

When the rejected choice is right

raw pointers win in a performance-critical C/C++ interop layer with one trusted owner and no safety requirement; Rc<RefCell> wins for a small, non-perf-critical structure with genuine shared mutable ownership

Why: memory safety without GC; cache-packed; no UAF (the C/C++ mesh crash class)

ADR-12

Convex hull 2D

Chosen

Andrew's monotone chain

Rejected

Graham scan; Jarvis; QuickHull; Chan

When the rejected choice is right

Chan wins when h (hull size) is asymptotically known to be ≪ n and output-sensitivity dominates; QuickHull wins when average-case speed on well-distributed data matters more than worst-case guarantees

Why: simplest correct O(n log n); no angle sort; alternates kept as oracles/stretch

ADR-13

Convex hull 3D

Chosen

randomized incremental + conflict graph

Rejected

QuickHull3D; gift-wrapping

When the rejected choice is right

gift-wrapping wins for tiny point sets (low hundreds) where implementation simplicity beats asymptotic complexity

Why: O(n log n) expected; conflict-graph analysis is clean; QuickHull3D kept as oracle

ADR-14

Delaunay algorithm

Chosen

randomized incremental Bowyer–Watson + history-DAG location

Rejected

Fortune sweep; Guibas–Stolfi D&C; flip-only

When the rejected choice is right

Fortune sweep wins when the full point set is known up front and worst-case (not just expected) O(n log n) is required; Guibas–Stolfi D&C wins when the build must parallelize across cores

Why: simplest robust incremental; DAG gives O(log n) location; alternates as oracles (Papers P8, P9)

ADR-15

Point location

Chosen

history DAG (Delaunay tree) + walk fallback

Rejected

k-d-tree; bucketing; jump-and-walk only

When the rejected choice is right

k-d-tree wins for a static point set with many repeated queries and no insertions; walk-only wins for small n where DAG memory overhead isn't justified

Why: O(log n) expected; #375 supplies index-based location, not us

ADR-16

Voronoi

Chosen

Rejected

When the rejected choice is right

direct Fortune wins when only the Voronoi diagram is needed (not Delaunay) and skipping the dual saves memory

Why: reuse the robust Delaunay; duality is exact (I14)

ADR-17

Segment intersection

Chosen

Bentley–Ottmann sweep

Rejected

naive O(n²); Shamos–Hoey (detection only)

When the rejected choice is right

naive O(n²) wins for very small n (≲100 segments) where sweep machinery overhead exceeds its payoff; Shamos–Hoey wins when only a yes/no "any intersection" answer is needed

Why: output-sensitive O((n+k) log n); naive kept as oracle; S–H for the boolean fast-reject

ADR-18

Polygon boolean

Chosen

Martínez–Rueda–Feito sweep

Rejected

When the rejected choice is right

Sutherland–Hodgman wins when the clip polygon is guaranteed convex (its exact restriction); Vatti/Clipper wins when integer/fixed-point coordinates are already the pipeline's currency

Why: robust at degeneracies (vertex-on-edge); single framework for ∪∩∖⊕; G–H pitfalls rejected

ADR-19

Polygon triangulation

Chosen

Rejected

When the rejected choice is right

Why: O(n log n) guaranteed; ear is simple for holes; Seidel PhaseDeferred("§18")

38. Alternative Architectures (Roads Not Taken)

Four fundamentally different designs for the same system — not parameter tweaks.

AA1 — Pure floating-point + epsilon tolerance (no exact arithmetic).

Show the original text diagram
input coords (f64) --> raw f64 determinant --> if |det| < eps: "treat as zero"
                                              else: sign(det)

Regime where it wins: quick prototyping/visualization where occasional wrong topology is tolerable (a debug overlay, a one-off plot). Real embodying system: the naive hull/triangulation code Ericson's Real-Time Collision Detection (B9) warns against — widespread in early game-engine geometry utilities. Why rejected: silently wrong topology under near-degenerate input is exactly the categorical corruption Principle 1 exists to prevent; no fixed eps is correct across the coordinate-magnitude range in §4.

AA2 — Exact rational (GMP/bignum) arithmetic throughout, no floating filter.

Show the original text diagram
input coords --> promote to exact rational --> all predicates AND constructions exact
                                                  (no filter, no expansion staging)

Regime where it wins: algebraic/CAD kernels where construction outputs must also be exact, not just predicate signs (e.g. exact Boolean CAD modeling feeding a solver that cannot tolerate rounding at all). Real embodying system: CGAL's exact kernels instantiated with CGAL::Gmpq/Lazy_exact_nt (R3). Why rejected: 10–100×+ slower on the common non-degenerate case, no no_std embeddability, incompatible with the §4 latency/throughput ceilings this project targets.

AA3 — Fixed-point/integer coordinates + snap-rounding (Vatti/Clipper-style).

Show the original text diagram
input coords (f64) --> quantize to integer grid --> snap-round near-coincidences
                                                   --> integer predicates (cheap, exact)

Regime where it wins: pipelines already committed to integer coordinates (PCB/CAM tooling, tile-based GIS) where a small controlled coordinate perturbation is acceptable and predicate cost must be minimal. Real embodying system: Clipper2's Vatti-derived clipping (R6) and GEOS's CommonBitsRemover/snap-rounding heuristics (R5). Why rejected: snap-rounding perturbs the input to make the predicates trivial — the inverse of this project's EGC discipline (compute coordinates approximately, decide signs exactly, §2) — and does not generalize to native floating-point input without a lossy pre-quantization step.

AA4 — Interval-only filter with random re-perturbation ("joggle") on failure.

Show the original text diagram
input coords --> interval bound --> if inconclusive: jitter coords randomly --> retry

Regime where it wins: a one-shot visualization or small-n triangulation where determinism doesn't matter and implementation simplicity/speed is paramount. Real embodying system: qhull's Qz/joggle option (R4). Why rejected: non-deterministic (violates I17/Principle 4), and joggling changes the actual answer rather than certifying the original input's answer — it solves a nearby, different problem instead of the one asked.
