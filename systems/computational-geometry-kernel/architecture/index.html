Per-box detail (one paragraph per box):

  • Untrusted geometric input — coordinate triples (f64 x, y, optional z), WKT/WKB byte streams, or direct API calls passing points/segments/polygons. Adversarial: may contain NaN/Inf, enormous magnitudes, billions of vertices, or deliberately near-degenerate configurations crafted to force the slow exact path on every predicate. All inputs cross a trust boundary into IO+Validation.
  • IO + Validation (cgk-io) — parses WKT (text) and WKB (binary) per the OGC Simple Features subset; rejects NaN/Inf and out-of-range magnitudes with typed ParseError; canonicalizes polygon-ring winding (exterior CCW, holes CW per the chosen convention); bounds vertex counts against configured caps. Pure given its input; performs no geometric decisions itself (it calls no predicates) — it only normalizes representation.
  • Number layer (cgk-num) — the arithmetic substrate. Provides the IEEE-754 error-free transformations (two_sum, fast_two_sum, split, two_product) that compute the exact rounding error of a single +/×; floating-point expansions (a real represented as a non-overlapping, magnitude-sorted f64 sequence) with exact addition/multiplication; interval arithmetic with directed rounding; and an optional exact rational backend (bignum numerator/denominator). no_std, allocation-bounded, deterministic.
  • Predicate layer (cgk-predicates) — the robustness spine; double-boxed in the diagram because every algorithm's correctness reduces to it. Implements orient2d, incircle, orient3d, insphere as staged evaluators: (A) a fast f64 computation with an a-priori error bound that returns immediately when |det| > errbound; (B) an optional interval filter; (C) Shewchuk's adaptive expansion that computes successively more-precise approximations, stopping as soon as the sign is certain; (D) a full exact expansion/rational fallback. When the exact value is zero (a true degeneracy), SoS returns the sign of the first non-vanishing term of the symbolic-perturbation polynomial, so the layer above always sees a definite, consistent sign. Pure, deterministic, no_std.
  • Kernel traits (cgk-kernel) — geometric value types (Point, Vector, Segment, Triangle, Bbox) and the CGAL-style Kernel<NT> parameterization over a number type. Enforces the predicate/construction split: predicates return exact signs/booleans and never produce new coordinates; constructions (intersection point, circumcenter, centroid) produce new, necessarily inexact, f64 coordinates and are the only place rounding error enters the data. Higher layers consume predicates for all branching and constructions only for output coordinates.
  • HULL (cgk-hull) — 2D convex hull via Andrew's monotone chain (sort lexicographically, build lower then upper chain using orient2d to reject non-left-turns) and alternates (Graham, Jarvis, QuickHull, Chan); 3D convex hull via randomized incremental construction with a conflict graph. Consumes orient2d/orient3d; emits hull vertices in CCW order (2D) or a DCEL/face list (3D).
  • ARRANGE (cgk-arrange) — Bentley–Ottmann sweepline computing all pairwise segment intersections and the planar arrangement they induce. An event queue (priority queue keyed by sweep position with deterministic tie-breaking) drives a status structure (a balanced BST of segments ordered by their y along the sweep line); intersection events are discovered between newly-adjacent segments. Consumes orient2d (for segment ordering and intersection existence) and the intersection-point construction; emits intersection points and an arrangement DCEL.
  • TRIANGUL. (cgk-tri) — polygon triangulation (ear clipping; monotone decomposition + monotone-polygon triangulation) and Delaunay triangulation via randomized incremental Bowyer–Watson (insert a point, find the triangles whose circumcircle contains it = the cavity, delete them, re-triangulate the star-shaped hole), plus Lawson edge-flips and constrained Delaunay (CDT). Consumes orient2d and incircle; produces a DCEL/triangle mesh satisfying the empty-circumcircle property (Delaunay) or constrained-empty-circle (CDT).
  • BOOLEAN (cgk-boolean) — polygon set algebra (∪ ∩ ∖ ⊕) via the Martínez–Rueda–Feito sweepline: subdivide all edges at intersections, sweep computing inside/outside transition flags per edge for each operand, then select edges per the requested operation and stitch result contours. Consumes orient2d and intersection constructions; emits well-formed (non-self-intersecting, consistently wound) result polygons.
  • VORONOI (cgk-voronoi) — the Voronoi diagram, built primarily as the geometric dual of the Delaunay triangulation (Voronoi vertex = Delaunay-triangle circumcenter; Voronoi edge ⟂ Delaunay edge), with a direct Fortune sweepline as an alternate/oracle; supports nearest-site queries. Consumes incircle (via Delaunay) and the circumcenter construction; emits a Voronoi DCEL.
  • TOPOLOGY (cgk-dcel) — the doubly-connected edge list and Guibas–Stolfi quad-edge structures that represent every planar subdivision the algorithms produce, plus an invariant checker (twin/next/prev consistency, face cycles, Euler's formula V − E + F = 2). Shared by ARRANGE, TRIANGUL., BOOLEAN, VORONOI; the single source of topological truth.
  • POINT LOCATION — answers "which triangle/face contains query point q?" for incremental construction and queries, via a history DAG (Delaunay-tree of created/destroyed triangles) or a robust straight-line walk; uses orient2d for every step. Critical: a non-robust orient2d makes the walk loop forever between two triangles that each think they do not contain q.
  • OUTPUT + CHECK — serializes results to WKT/WKB and runs the invariant audit (Euler's formula, DCEL consistency, Delaunay empty-circle spot-checks, output non-self-intersection) before returning. The last line of defense: a corrupted structure is caught here rather than silently returned.
  • CLI (cgk-cli) — the cgk binary; dumps hulls/triangulations/Voronoi/arrangements, converts WKT↔WKB, evaluates a single predicate on given coordinates, and runs the differential harness (filter-vs-exact, and vs reference oracles). The operator-facing surface for validation and debugging.

8. Domain Model

8.1 The geometric predicates (exact-sign primitives)

A predicate maps points to a sign in {−1, 0, +1}. The sign — never the magnitude — is the load-bearing output. Each is the sign of a determinant.

orient2d(a, b, c) — orientation of the ordered triple; the sign of twice the signed area of triangle abc:

                 | a.x − c.x   a.y − c.y |
orient2d(a,b,c)= | b.x − c.x   b.y − c.y |  = (a.x−c.x)(b.y−c.y) − (a.y−c.y)(b.x−c.x)

Sign convention: > 0 ⇒ a,b,c is counter-clockwise (c is to the LEFT of ray a→b); < 0 ⇒ clockwise (right); = 0 ⇒ collinear. (Equivalently the cross product (b−a) × (c−a) z-component.) This single predicate underlies hull (left-turn test), triangulation (ear/visibility), sweep (segment ordering, intersection existence), and point location (which side of an edge).

incircle(a, b, c, d) — is d inside the circumcircle of a,b,c? With a,b,c in CCW order, the sign of:

            | a.x−d.x   a.y−d.y   (a.x−d.x)²+(a.y−d.y)² |
incircle =  | b.x−d.x   b.y−d.y   (b.x−d.x)²+(b.y−d.y)² |
            | c.x−d.x   c.y−d.y   (c.x−d.x)²+(c.y−d.y)² |

Sign convention (a,b,c CCW): > 0 ⇒ d is INSIDE the circumcircle; < 0 ⇒ outside; = 0 ⇒ d cocircular with a,b,c. This is the Delaunay test: a triangulation is Delaunay iff no vertex is inside any triangle's circumcircle (I3). Degree-4 polynomial in the coordinates → larger error bounds, heavier exact path than orient2d.

orient3d(a, b, c, d) — is d above/below the plane through a,b,c? The sign of the 3×3 determinant of (a−d, b−d, c−d):

             | a.x−d.x   a.y−d.y   a.z−d.z |
orient3d =   | b.x−d.x   b.y−d.y   b.z−d.z |
             | c.x−d.x   c.y−d.y   c.z−d.z |

Sign convention: > 0 ⇒ d is below the plane of a,b,c viewed so that a,b,c appears CCW (equivalently (a−d)·((b−d)×(c−d)) > 0); = 0 ⇒ coplanar. Drives 3D hull and is the engine of the lifting map.

insphere(a, b, c, d, e) — is e inside the circumsphere of a,b,c,d? The sign of the 4×4 determinant analogous to incircle, with a fifth squared-norm column. > 0 ⇒ inside (with a,b,c,d positively oriented); = 0 ⇒ cospherical. Used by 3D Delaunay (deferred; registered in §39) — the predicate itself ships in Phase 11 (§23).

The lifting map (paraboloid). Lift each 2D point p = (x, y) to 3D p↑ = (x, y, x² + y²) on the paraboloid z = x² + y². Then incircle(a,b,c,d) > 0 ⟺ orient3d(a↑, b↑, c↑, d↑) has the corresponding sign: d is inside the circumcircle of a,b,c ⟺ d↑ is below the plane through a↑,b↑,c↑. Consequence: the 2D Delaunay triangulation is the projection of the lower convex hull of the lifted points. This unifies incircle with orient3d, and Delaunay with convex hull — both implementation and testing exploit it (an independent Delaunay via 3D lower hull is a differential oracle).

8.2 Why floating point misclassifies signs (the motivating failure)

Evaluating orient2d naively as (ax−cx)*(by−cy) − (ay−cy)*(bx−cx) in f64 rounds each −, ×, and the final −. When the true value is near zero (near-collinear points) the result is dominated by catastrophic cancellation: the rounding error can exceed |true value|, so the computed sign is arbitrary. Worked failure: points a=(0.5, 0.5), b=(12, 12), c=(24, 24) are exactly collinear (true orient2d = 0); perturb c.x by one ulp and the naive f64 result may report +, −, or 0 inconsistently depending on evaluation order — and three different call sites may get three different signs for the same three points. That inconsistency, not the magnitude error, is fatal: a hull edge can be "left of" a point at one site and "right of" it at another, yielding a non-convex hull, a crash, or an infinite loop.

8.3 Floating-point error-free transformations (EFTs) — num primitives

Each EFT computes a rounded result plus the exact rounding error, both as f64. (≤2-line sketches; NOT full source.)

fast_two_sum(a, b)  [requires |a| >= |b|]:        # x = fl(a+b), y = exact error
    x = a + b ;  y = b − (x − a)                  # x + y == a + b exactly
two_sum(a, b):                                    # no magnitude assumption (Knuth)
    x = a + b ; bv = x − a ; av = x − bv
    y = (a − av) + (b − bv)                        # x + y == a + b exactly
split(a):                                         # Veltkamp split, 26+26 bits
    c = SPLITTER * a ; hi = c − (c − a) ; lo = a − hi    # SPLITTER = 2^27 + 1
two_product(a, b):                                # x = fl(a*b), y = exact error
    x = a * b
    (ahi,alo)=split(a); (bhi,blo)=split(b)
    y = alo*blo − (((x − ahi*bhi) − alo*bhi) − ahi*blo)
    # FMA variant (deliberate, allowed): y = fma(a, b, −x)

Constants (exact, const, never runtime-initialized): EPSILON = 2⁻⁵³ (binary64 unit roundoff); SPLITTER = 2²⁷ + 1 = 134_217_729.

8.4 Expansions — exact reals as non-overlapping f64 sequences

An expansion is a sequence e = [e₀, e₁, …, e_{m−1}] of f64 components, non-overlapping and increasing in magnitude, whose exact sum is the value (Priest/Shewchuk). Operations (each preserves the non-overlapping property, I15):

Op Signature (sketch) Role
grow_expansion(e, b) expansion + scalar → expansion add one f64 to an expansion
expansion_sum(e, f) expansion + expansion → expansion exact addition of two expansions
fast_expansion_sum(e, f) merge-sorted variant Shewchuk's faster, non-adjacent sum
scale_expansion(e, b) expansion × scalar → expansion exact multiply by one f64
expansion_sign(e) expansion → {−1,0,+1} sign = sign of the last (largest) nonzero term

The exact value of a determinant is built by composing two_product (for each product term) and fast_expansion_sum (to combine them). expansion_sign reads the sign off the top component in O(1). The expansion length grows with the number of bits required — bounded because input coordinates are 53-bit f64.

8.5 Staged adaptive evaluation (Shewchuk)

A predicate runs through stages, stopping at the first that certifies the sign (I1, Principle 5):

Stage Method a-priori bound Typical cost
A — fast filter naive f64 determinant det if ` det
B — interval (optional) recompute with directed-rounding intervals [lo,hi] if lo>0 or hi<0, sign known ~2× stage A
C — adaptive compute successively more expansion terms; re-test bound after each stop when remaining terms cannot flip the sign 100 ns – low µs
D — exact full expansion (or rational) determinant; expansion_sign always certain µs
SoS if exact value == 0: return sign of first nonzero perturbation term always definite adds the SoS term sequence

Error-bound constants (from P1, for f64, where ε = EPSILON):

Predicate A-bound coefficient B-bound C-bound
orient2d (3 + 16ε)·ε (2 + 12ε)·ε (9 + 64ε)·ε²
incircle (10 + 96ε)·ε (4 + 48ε)·ε (44 + 576ε)·ε²
orient3d (7 + 56ε)·ε (3 + 28ε)·ε (26 + 288ε)·ε²
insphere (16 + 224ε)·ε (5 + 72ε)·ε (71 + 1408ε)·ε²

The bound is multiplied by a permanent (a sum of absolute products from the determinant) computed in stage A; if |det| exceeds it, the f64 sign is provably correct. These constants are reproduced verbatim from Shewchuk and are themselves a conformance fixture.

8.6 Simulation of Simplicity (SoS) — degeneracy elimination

Every input point pᵢ carries a stable index i. SoS conceptually perturbs coordinate j of point i by + ε^(2^(i·d + j)) for a sufficiently small symbolic ε > 0 and dimension d, guaranteeing no determinant is ever exactly zero and ties break by a fixed, consistent rule (I12). In implementation we never compute with ε; instead, when the exact determinant is 0, we evaluate a fixed sequence of sub-determinants (minors) — the coefficients of increasing powers of ε in the expanded perturbation polynomial — and return the sign of the first nonzero one. Edelsbrunner–Mücke give the explicit term orderings for orient and incircle; we tabulate them per predicate. The result: the layer above always receives + or −, never 0, and the perturbed configuration is a consistent general-position instance, so all algorithms agree.

Worked SoS example: three coincident points or three exactly-collinear points yield orient2d = 0; SoS breaks the tie by point index (e.g., the lower-indexed point is treated as infinitesimally lower), so a hull or triangulation built on them is consistent and degenerate-free. The user-visible coordinates are unchanged; only the decisions are perturbed.

8.7 Topological structure — DCEL (doubly-connected edge list)

Represents a planar subdivision as half-edges. Each undirected edge is two oppositely-directed half-edges. A half-edge e stores: origin(e) (vertex), twin(e) (the opposite half-edge), next(e) and prev(e) (the next/prev half-edge along the face on e's left), face(e) (the incident face on e's left). Vertices store one outgoing half-edge; faces store one boundary half-edge.

Invariants (I5):

twin(twin(e)) = e            and    twin(e) != e
next(prev(e)) = e            and    prev(next(e)) = e
origin(next(e)) = dest(e)    where  dest(e) := origin(twin(e))
face(e) = face(next(e))      (all half-edges of one face form a directed cycle)

Euler's formula on a connected planar subdivision including the outer face: V − E + F = 2 (I4), where E counts undirected edges (= #half-edges / 2). For a triangulation of n points with h on the convex hull: #triangles = 2n − h − 2, #edges = 3n − h − 3. These closed forms are runtime self-checks.

Worked DCEL: a single triangle v₀v₁v₂ has 6 half-edges (3 interior CCW, 3 exterior CW around the outer face), V=3, E=3, F=2 (the triangle + outer face), and indeed 3 − 3 + 2 = 2. Storage: handles are u32 arena indices, not pointers (memory safety + cache packing).

8.8 Topological structure — quad-edge (Guibas–Stolfi)

The self-dual structure for subdivisions, ideal for Delaunay/Voronoi because primal and dual are represented simultaneously. Each edge is a record of four directed edges e[0..3]; algebraic operators:

Rot(e)   = rotate to the dual edge (90° CCW in the dual);   Rot⁴ = identity
Sym(e)   = Rot²(e) = the same edge, opposite direction
Onext(e) = next edge CCW around e's origin
Oprev(e) = Rot(Onext(Rot(e)))
Lnext, Lprev, Rnext, Rprev, Dnext … = derived from Rot/Onext

Two topological operators suffice to build any subdivision: MakeEdge() (a new isolated edge) and Splice(a, b) (the single operation that joins/splits edge rings at a vertex/face). Invariants (I13): Rot⁴ = id, Sym = Rot², and Onext rings stay consistent under Splice. The Guibas–Stolfi divide-and-conquer Delaunay (the Phase 7 / §19 alternate) is expressed entirely in MakeEdge/Splice/InCircle/CCW.

8.9 Convex hull (2D) — monotone chain semantics

Andrew's monotone chain: (1) sort points lexicographically by (x, y); (2) build the lower hull left-to-right, appending each point and popping while the last three make a non-left turn (orient2d ≤ 0); (3) build the upper hull right-to-left identically; (4) concatenate, dropping duplicate endpoints. Output: hull vertices in CCW order (I6). The collinearity policy (orient2d == 0) is explicit: default drops collinear points (strict < 0 pops), KeepCollinear keeps them (≤ 0 pops only strict right turns). Complexity O(n log n), sort-dominated; the chain construction is a single linear pass using only orient2d.

8.10 Delaunay triangulation — Bowyer–Watson semantics

Randomized incremental insertion. Maintain a triangulation (initially a big enclosing "super-triangle" or a known bounding triangle). To insert point p:

1. LOCATE the triangle t containing p (point-location DAG or walk; uses orient2d).
2. CAVITY: starting from t, find all triangles whose circumcircle CONTAINS p
   (incircle(.,.,.,p) > 0), growing across shared edges (the "Delaunay cavity").
3. The cavity boundary is a star-shaped polygon visible from p (I9).
4. DELETE the cavity triangles; RETRIANGULATE the hole by joining p to every
   cavity-boundary edge.
5. (Lawson-flip view: equivalently, insert p in its triangle, then flip every
   edge that violates incircle until none remains.)

Expected O(log n) location + O(1) amortized cavity ⇒ O(n log n) total under random insertion order (Clarkson–Shor analysis, P15). The empty-circumcircle property (I3) holds after every insert. The super-triangle's vertices are removed at the end (and any triangle touching them).

8.11 Voronoi — duality semantics

The Voronoi diagram partitions the plane into cells, one per site, where a cell is the locus of points nearest that site. It is the geometric dual of the Delaunay triangulation (I14): each Delaunay triangle ↦ one Voronoi vertex at its circumcenter; each Delaunay edge ↦ one Voronoi edge (the perpendicular bisector segment between the two adjacent circumcenters); each site ↦ one Voronoi cell (the polygon around it). Build Delaunay (Phase 7, §19), then walk the dual (Phase 8, §20). Fortune's sweepline (the Phase 8 / §20 alternate) builds Voronoi directly via a beach line of parabolic arcs with site and circle events. Nearest-site query = point-location in the Voronoi diagram (or in Delaunay + dual lookup).

8.12 Segment intersection — Bentley–Ottmann semantics

Sweep a vertical line left-to-right. Two structures:

  • Event queue — a priority queue ordered by sweep position (x, then y), holding segment endpoints (known up front) and intersection points (discovered during the sweep). Deterministic tie-breaking (left-before-right, lower-before-upper) is essential at shared x-coordinates.
  • Status structure — a balanced BST of the segments currently crossing the sweep line, ordered by their y-coordinate at the sweep x (comparisons use orient2d).

At a left endpoint: insert the segment, test it against its new neighbors for intersection. At a right endpoint: remove it, test the now-adjacent neighbors. At an intersection: swap the two segments' order, report the point, and test the newly-adjacent pairs. Complexity O((n + k) log n), k = reported intersections (I8). Degeneracies (vertical segments, overlapping collinear segments, many segments through one point) require careful event grouping (handle all events at one point together).

8.13 Polygon boolean ops — Martínez–Rueda–Feito semantics

A sweepline over the edges of both operand polygons (subject and clip). Steps: (1) subdivide every edge at intersection points (so edges only touch at endpoints); (2) sweep, and for each edge compute its inside/outside status with respect to each operand (is the region just above this edge inside the subject? inside the clip?); (3) classify each edge as belonging to the result of ∪/∩/∖/⊕ by a truth table over those flags; (4) stitch selected edges into result contours, nesting holes correctly. Output is well-formed (I7): non-self-intersecting, consistently wound. Handles all four operations in one framework; robust because all geometric decisions go through exact predicates.

8.14 Polygon triangulation semantics

  • Ear clipping O(n²): a vertex is an ear if it is convex (orient2d on its two neighbors) and its triangle contains no other polygon vertex; repeatedly clip an ear and remove it. Simple, handles simple polygons; holes need a bridge merge.
  • Monotone decomposition O(n log n): a sweepline classifies vertices (start/end/split/merge/regular), adding diagonals at split/merge vertices to cut the polygon into y-monotone pieces; each monotone piece triangulates in O(m) with a stack-based scan. Locked for large n.

8.15 Geometry I/O — WKT/WKB

OGC Simple Features text (WKT) and binary (WKB). WKT examples: POINT(30 10), LINESTRING(30 10, 10 30, 40 40), POLYGON((35 10, 45 45, 15 40, 10 20, 35 10),(20 30, 35 35, 30 20, 20 30)) (exterior ring + one hole). WKB layout: 1-byte byte-order flag (00=big, 01=little), 4-byte geometry type code, then coordinate doubles (and counts for rings/parts). Validity (OGC): rings closed, exterior CCW / holes CW (our chosen convention; canonicalized on ingest), no ring self-intersection. We implement a subset: Point, LineString, Polygon, and the Multi* collections.

8.16 Degenerate input catalogue (must be handled; SoS eliminates zeros)

Class Example Handling
Collinear points 3+ points on a line; orient2d = 0 SoS tie-break by index (I12); hull policy decides keep/drop (I6)
Coincident points duplicate coordinates SoS perturbs by index; or pre-dedup with exact equality
Cocircular points 4+ on a common circle; incircle = 0 SoS → consistent Delaunay (no flip-flop, I3)
Cospherical points 5+ on a sphere; insphere = 0 SoS (3D)
Collinear segment overlap two segments sharing a sub-segment Bentley–Ottmann overlap handling; report shared interval
Many segments through one point a pencil of segments group all events at the point; single status reorder
Vertical segments (B–O) infinite slope order by lower endpoint then orient2d; special comparator
Vertex-on-edge (boolean) a polygon vertex lying on the other's edge Martínez labeling handles; do NOT inherit Greiner–Hormann's failure here
Polygon with hole touching shell ring tangency OGC-invalid on input → ParseError; or split per policy

8.17 Malformed input catalogue (never panic; typed error)

Design principles (§6)

  • Exact Geometric Computation — branch only on exact signs. Coordinates may be approximate; every decision (predicate sign) must equal the exact-arithmetic decision. Tradeoff: a fast/exact staged evaluator instead of one f64 line. Operational: the predicate layer is the most-tested, most-instrumented code. Violation: one wrong sign → flipped triangle, non-star-shaped cavity, infinite point-location loop, self-intersecting boolean output — a categorical corruption, never a small error.
  • Predicate / construction separation (CGAL's EPIC discipline). Predicates return signs/booleans and create no coordinates; constructions create coordinates and are never the basis of a downstream branch without re-filtering. Tradeoff: two distinct API kinds. Operational: rounding error is confined to construction outputs. Violation: feeding a constructed intersection point back into a predicate as if exact → cascading inconsistency (the classic "snap a vertex, now it is on the wrong side of an edge it created").
  • Degeneracy is eliminated, not special-cased. Collinear/cocircular/coincident/overlapping inputs are made general-position by SoS symbolic perturbation; the topology layer never receives a zero. Tradeoff: SoS term orderings must be defined per predicate. Operational: one code path, not 2ⁿ degenerate branches. Violation: ad-hoc epsilon special-cases multiply combinatorially, contradict each other, and leave gaps that crash.
  • Determinism + reproducibility. Identical input → byte-identical topology and coordinates: a single seeded PRNG for randomized order (seed recorded), no wall-clock, no FMA contraction, no SIMD reassociation in num. Tradeoff: must pin the RNG seed and FP flags. Operational: any result reproduces from input + seed + version. Violation: "works on my machine" geometry bugs that cannot be bisected; non-reproducible meshes.
  • Filter first, escalate only on demand (adaptive precision). The fast f64 filter resolves >99.9% of calls; exact arithmetic runs only when the error bound cannot certify the sign. Tradeoff: code complexity of the staged evaluator. Operational: filter_hit_rate and exact_fallback_total are first-class metrics. Violation: always-exact is 10–100× slower (DoS-able); always-fast is wrong.
  • Bounded resources on untrusted input. Vertex counts capped; coordinate magnitudes range-checked; every sweep/expansion loop has a progress guarantee. Tradeoff: legitimately huge inputs must be chunked by the caller. Operational: input_rejected_total by reason. Violation: a crafted near-degenerate dataset forces exact fallback on every predicate → CPU exhaustion; or a billion-vertex polygon OOMs the host.
  • Topological invariants are checked, not assumed. DCEL twin/next/prev consistency, face cycles, and Euler's formula are validated by a checker runnable after every mutation in debug and on output. Tradeoff: checker cost in debug builds. Operational: a corrupt mesh is caught at its source, not three algorithms later. Violation: a single broken twin pointer silently produces wrong faces, areas, and adjacencies downstream.
  • No floating-point sign without a proven bound. It is forbidden to write if det > 0 on an unfiltered f64 determinant anywhere in the algorithm layer; all orientation/in-circle tests go through the predicate layer. Tradeoff: no "quick local epsilon check." Operational: a lint/grep gate forbids raw determinant comparisons outside predicates. Violation: exactly the non-robustness this whole project exists to prevent, reintroduced by a shortcut.
  • Coordinates are inputs, the tzdb-equivalent is the FP environment. Results are defined relative to a pinned floating-point environment (round-to-nearest-even, no contraction) and a pinned RNG seed; these are first-class, recorded parameters. Tradeoff: the FP environment is an explicit contract. Operational: fp_environment and rng_seed in telemetry. Violation: a build with fast-math enabled produces different topology — silently, and only on some inputs.
  • Overflow and non-finite values are typed errors, never UB. NaN/Inf rejected at IO; integer counters use checked arithmetic; expansion lengths are bounded. Tradeoff: IO and arithmetic are fallible. Operational: non_finite_rejected_total. Violation: a NaN coordinate makes every comparison false → silent corruption that bypasses every epsilon check.
  • One topological representation, derived views. DCEL is canonical for planar subdivisions; quad-edge is used where its self-dual elegance fits (Delaunay/Voronoi). Triangle-based meshes are a view, not a competing source of truth. Tradeoff: conversions at boundaries. Operational: one invariant checker to maintain. Violation: two structures drift, adjacencies disagree, faces double-count.
  • Differential validation against exact arithmetic is the oracle. Every predicate is tested filter-vs-exact on millions of random and near-degenerate inputs; every algorithm is tested against an independent exact (or O(n²) brute-force) implementation. Tradeoff: maintaining a slow exact reference. Operational: a single sign disagreement fails CI. Violation: subtle filter-constant errors ship and surface only on a customer's pathological dataset.
  • Output is well-formed by construction and verified on exit. Hulls are CCW with the requested collinearity policy; triangulations are valid planar subdivisions; boolean outputs are non-self-intersecting with consistent winding; all are audited before return. Tradeoff: an exit-time check. Operational: output_invalid_total (should be zero). Violation: a malformed polygon leaks into a downstream GIS that trusts validity → cascading failures far from the kernel.
