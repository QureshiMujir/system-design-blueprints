Per-box notes. Bind (§13) is the only place SQL-level type policy lives; it takes a snapshot of the Catalog (I10) so the rest of the pipeline sees consistent metadata. Logical IR (§14) is the lingua franca (P2): every later phase codes against LogicalPlan, never the AST. Rewriter (§15) is a fixed-point loop over pure rules (P3, I13); it must converge before Phase 4 runs. Statistics + Cost (§16) is the single subsystem every cardinality number flows through (P5); the enumerator never reads a histogram directly. DPccp (§17) and Cascades (§18) share one memo: DPccp seeds group winners for join order, Cascades explores transformation/implementation rules on top (P6). Physical Lowering (§19) picks an operator family per logical node; Physical Optimisation (§20) is the only place enforcers are inserted (P7) — property reasoning is correct-by-construction, not heuristic. EXPLAIN (§21) is a first-class output built before the executor handoff (P8), and is the point where the deferred adaptive-replanning hook attaches. Trust boundary A is upstream-parser output (an AST we do not trust to be internally consistent, §22 T10); trust boundary B is the executor's actuals callback (§21, §22 T12 for information leakage via row-count side channels).

8. Domain Model / Protocol / Data Model

8.1 SQL Grammar (EBNF fragment — the subset qp-bind accepts)

query          ::= [ with-clause ] select-stmt [ order-by ] [ limit-clause ] ;
with-clause    ::= "WITH" [ "RECURSIVE" ] cte { "," cte } ;
cte            ::= ident "AS" "(" query ")" ;
select-stmt    ::= "SELECT" select-list "FROM" from-item { join } [ where-clause ]
                    [ group-by ] [ having ]
                  | select-stmt set-op select-stmt ;
set-op         ::= ("UNION" | "INTERSECT" | "EXCEPT") [ "ALL" ] ;
select-list    ::= "*" | select-expr { "," select-expr } ;
select-expr    ::= expr [ "AS" ident ] | ident "." "*" ;
from-item      ::= table-ref | "(" query ")" [ "AS" ] ident | "LATERAL" "(" query ")" [ "AS" ] ident ;
table-ref      ::= ident [ "AS" ident ] ;
join           ::= [ join-kind ] "JOIN" from-item [ "ON" expr | "USING" "(" ident { "," ident } ")" ]
                  | "," from-item ;                          (* comma-join == inner, no predicate *)
join-kind      ::= "INNER" | "LEFT" [ "OUTER" ] | "RIGHT" [ "OUTER" ]
                  | "FULL" [ "OUTER" ] | "CROSS" ;
where-clause   ::= "WHERE" expr ;
group-by       ::= "GROUP BY" expr { "," expr } ;
having         ::= "HAVING" expr ;
order-by       ::= "ORDER BY" order-item { "," order-item } ;
order-item     ::= expr [ "ASC" | "DESC" ] [ "NULLS" ("FIRST" | "LAST") ] ;
limit-clause   ::= "LIMIT" integer [ "OFFSET" integer ] ;
expr           ::= literal | column-ref | func-call | expr binop expr | "NOT" expr
                  | expr "IS" [ "NOT" ] "NULL" | expr ["NOT"] "IN" "(" expr-list | query ")"
                  | expr ["NOT"] "BETWEEN" expr "AND" expr | expr ["NOT"] "LIKE" expr
                  | "CASE" { "WHEN" expr "THEN" expr } [ "ELSE" expr ] "END"
                  | "EXISTS" "(" query ")" | "(" query ")"                  (* scalar subquery *)
                  | window-call ;
window-call    ::= func-call "OVER" "(" [ "PARTITION BY" expr-list ] [ order-by ] ")" ;

Every production above lowers to exactly one LogicalPlan/Expr shape in §11; LATERAL and correlated scalar/EXISTS subqueries lower to LogicalPlan::Apply (§11.8), never to Join.

8.4 Worked Example

SELECT o.o_orderkey, c.c_name FROM orders o JOIN customer c ON o.o_custkey = c.c_custkey WHERE o.o_orderdate >= '2025-01-01' lowers as:

Bind:      BoundStatement{ Query(
             Project[o_orderkey,c_name](
               Filter[o_orderdate>=date](
                 Join[Equi(o_custkey=c_custkey), Inner](Scan(orders), Scan(customer))))) }
Rewrite:   Project[o_orderkey,c_name](
             Join[Equi(o_custkey=c_custkey), Inner](
               Scan(orders, pushed=[o_orderdate>=date]),
               Scan(customer)))                          -- predicate pushed to Scan(orders)
Physical:  Project(
             HashJoin(build=Scan(customer), probe=Scan(orders, filter pushed)))

8.5 Malformed-Input Example

SELECT id FROM orders o JOIN order_items i ON o.id = i.order_id where both orders and order_items have a column named id and the SELECT list says id unqualified: name resolution (§13.2 step 2) finds two matches ⇒ Diagnostic::Ambiguous { name: "id", candidates: [orders.id, order_items.id] }; bind fails closed with PlannerError::InvalidName, never guesses.

8.6 Failure-Path Example

A hypothetical buggy build of predicate_pushdown (§15.2) pushes i.discontinued = false (null-rejecting on the right) through a LeftOuter(orders, order_items) join into the join condition. LogicalPlan::validate (I1) diffs the pre-/post-rewrite row count on the negative conformance fixture rewrite/predicate_pushdown/outer_join_null_reject.json (§15.5), detects the semantic divergence, and the rewriter raises PlannerError::Internal { kind: "rewrite_violation", rule: "predicate_pushdown" } with the offending subtree attached — per P10, it never ships the unsafe plan silently.

Design principles (§6)

  • The AST is upstream and immutable (P1). qp consumes sql_ast::Statement; it never mutates it. Tradeoff: any parser bug becomes a qp-bind upstream-contract bug, not a local workaround. Violate it and the binder silently diverges from what the parser actually emits.
  • The logical algebra IR is the lingua franca (P2). Every phase past §14 codes against LogicalPlan; nothing reaches into the bound AST after lowering. Tradeoff: one more IR to maintain, in exchange for exhaustive pattern-matching (ADR-03). Violate it and rewrite rules fragment across two representations.
  • Rewrites are pure (P3). A Rule::apply never mutates its input; subtrees are Arc-shared. Tradeoff: extra Arc bookkeeping for O(1) structural sharing instead of O(n) copies. Violate it and the fixed-point loop (§15.2) cannot be trusted to terminate deterministically (I4).
  • Cost is a scalar, not a vector (P4). Cost::total() is one f64. Tradeoff: a Pareto-front cost model finds strictly-dominant plans but explodes the search space for no measured TPC-H win (ADR-07). Violate it and the enumerator's memo key space multiplies by the frontier size.
  • Statistics are estimates, and the cost model owns the error (P5). Every Cardinality carries relative_error (I8); the cost model prefers lower-variance plans within 10% of lowest cost. Violate it and the planner is confidently wrong under skew (MM2).
  • DP first, Cascades second (P6). §17 ships DPccp; §18 wraps a Cascades memo around it for transformation rules. Tradeoff: two enumeration mechanisms sharing one memo instead of one uniform Cascades search from day one (ADR-04); DPccp is exhaustively testable against the System R reference before Cascades' larger rule surface is trusted.
  • Physical lowering is property-driven, not heuristic (P7). §20 asks "what properties does this operator's output need?" and inserts enforcers where a child under-delivers. Tradeoff: more bookkeeping (required vs. delivered property sets) for plans that are correct by construction (ADR-14). Violate it and a MergeJoin can silently receive unsorted input.
  • EXPLAIN is a first-class output (P8). The formatter ships before the executor handoff (§21); no plan the planner can produce is a plan it cannot describe. Violate it and production debugging degrades to source-reading.
  • Determinism is the default (P9). Same AST + same catalog + same statistics ⇒ bit-identical physical plan (I4), enforced by hashing rendered EXPLAIN output in conformance (§26). Violate it and regression bisection becomes probabilistic.
  • No silent fallbacks (P10). An invalid rewrite raises with the rule name and offending subtree (I13); the validator runs after every rule in debug builds. Violate it and a schema-breaking rewrite ships silently to production.
  • Interesting orders are first-class DP state, not an afterthought (P11). The DP table is keyed by (RelationSet, InterestingOrder), not RelationSet alone (§17.2). Tradeoff: a larger memo for a plan that can win overall despite losing on raw cost-per-row (MM1). Violate it and the enumerator misses every merge-join opportunity that isn't also the row-count winner.
  • Statistics staleness is a first-class signal, not silence (P12). Every TableStatistics carries last_analyzed (I11); staleness beyond budget (§4) is surfaced in EXPLAIN, not hidden. Violate it and an operator cannot tell "bad plan" from "stale plan" (MM7).
  • Planning time is budgeted, not open-ended (P13). A hard wall-clock timeout (plan_timeout_ms, §4) bounds every plan() call; DPccp degrades to greedy beyond dpccp_max_relations (ADR-12). Violate it and one pathological join graph starves the host.
  • The cost model and the statistics layer are versioned together (P14). Changing cost weights without recalibrating against JCC-H, or vice versa, shifts the plan distribution unpredictably (§17.6 pitfalls). Violate it and a "small tuning change" becomes a fleet-wide plan regression.
