Decisions (§9) · 24 ADRs

ADR-01

Language & tensor runtime

Chosen

Python 3.11 + PyTorch 2.3+

Rejected

Rust + Burn; JAX + XLA

When the rejected choice is right

JAX+XLA wins for a from-scratch XLA-compiled research stack willing to drop the PyTorch model zoo entirely

Why: PyTorch is the reference dependency for every target model; autograd integration is the entire mechanism (§1)

ADR-02

Phase-0 default parallelism

Chosen

DP-only, TP=PP=1, ZeRO=0

Rejected

Ship TP/PP first

When the rejected choice is right

TP-first wins when the Phase-0 target model does not fit in single-GPU memory even at batch=1

Why: DP is the surface every later phase depends on; bit-exact DP vs. single-GPU gates the build (I1, §7)

ADR-03

GPU collective backend

Chosen

NCCL primary, Gloo CPU fallback, in-tree shim for tests

Rejected

MPI; UCX

When the rejected choice is right

UCX wins on heterogeneous fabrics mixing InfiniBand and RoCE where NCCL's topology detection under-performs

Why: NCCL is the only library that exploits NVLink/IB topology natively

ADR-04

Default pipeline schedule

Chosen

1F1B (PipeDream)

Rejected

GPipe (fill-then-drain)

When the rejected choice is right

GPipe wins when P is small and M is large enough that its simpler, stash-free schedule's bubble is already negligible

Why: GPipe bubbles (P-1)/M; 1F1B bubbles (P-1)/(M+P-1) and keeps every stage busy in steady state

ADR-05

ZeRO-3 prefetch policy

Chosen

Trace-driven (record first-pass module order)

Rejected

Fixed-depth lookahead

When the rejected choice is right

Fixed-depth wins when the model graph is static and trace-recording's first-pass overhead is unacceptable

Why: Trace-driven handles MoE/conditional graphs whose access order is stable across iterations

ADR-06

Transformer TP sharding

Chosen

Column-parallel QKV/MLP-in, row-parallel out-proj/MLP-out (Megatron)

Rejected

Column-only or row-only uniform sharding

When the rejected choice is right

Row-only-everywhere wins when inputs are already cheaply replicated and an extra all-gather beats tracking f/g pairing

Why: Minimizes all-reduce count to one per attention block + one per MLP block

ADR-07

Sequence parallelism

Chosen

On by default inside TP groups

Rejected

Off, accept replicated activations

When the rejected choice is right

Off wins when sequence length is not divisible by tp_size and padding cost exceeds the memory saving

Why: Shards non-linear activations along the sequence dim, /tp_size memory (Korthikanti 2022)

ADR-08

Activation-checkpoint granularity

Chosen

Per-transformer-block, selective recompute

Rejected

Whole-model checkpointing

When the rejected choice is right

Whole-model checkpointing wins on memory-constrained single-GPU debug runs where simplicity outweighs ~20% extra recompute

Why: Selective recompute discards only cheap-to-recompute activations

ADR-09

Gradient-accumulation trigger

Chosen

Post-backward hook fires collective once per accumulated batch

Rejected

Fire collective every micro-batch

When the rejected choice is right

Per-micro-batch firing wins only when grad_accum_steps=1, where the distinction is moot

Why: Correctness requires firing only after full accumulation (P6, §6; I3, §7)

ADR-10

Determinism mode for correctness suite

Chosen

torch.use_deterministic_algorithms(True) + fixed reduction tree

Rejected

Best-effort (non-deterministic kernels allowed)

When the rejected choice is right

Best-effort wins in throughput-critical production runs where bit-exact CI already gates correctness upstream

Why: Bit-exact loss curves require deterministic algorithms; ~20% cost is acceptable for CI

ADR-11

Wire-level transport security

Chosen

Trusted-fabric assumption, no mTLS on collectives

Rejected

mTLS on every NCCL/Gloo channel

When the rejected choice is right

mTLS wins when training traverses a shared or multi-tenant network the operator does not fully control (T1, §26)

Why: Dedicated training fabrics are operator-secured; encrypting every collective costs bandwidth

ADR-12

Per-rank inner loop

Chosen

Delegate to rank-114 single-host trainer unchanged

Rejected

Reimplement forward/backward/step

When the rejected choice is right

Reimplementation wins if rank-114's API cannot express a required distributed hook without modification

Why: Avoids duplicating tested single-host logic; keeps two projects' correctness in lock-step

ADR-13

Single-host launcher

Chosen

torch.multiprocessing.spawn

Rejected

Manual process-launch scripts

When the rejected choice is right

Manual scripts win under Slurm/Kubernetes, where multi-host launchers (§25) replace spawn

Why: Simplest, most debuggable local multi-GPU launcher

ADR-14

Inter-node collective algorithm selection

Chosen

NCCL auto-select ring/tree; override only the 30-min default timeout

Rejected

Force ring or force tree

When the rejected choice is right

Forcing tree wins on a full fat-tree IB fabric where auto-detection has been observed to mis-classify topology

Why: NCCL's topology-aware selection outperforms a fixed choice on most fabrics

ADR-15

Checkpoint format

Chosen

Sharded safetensors per rank + JSON manifest

Rejected

Pickle-based torch.save per rank

When the rejected choice is right

torch.save wins for quick local single-node debug checkpoints kept private to one machine and one process, not shared or re-sharded

Why: safetensors is mmap-friendly, zero-copy, free of pickle's deserialization CVEs

ADR-16

Default mixed precision

Chosen

bf16 default, fp16 opt-in with rank-114's loss scaler

Rejected

fp16 default

When the rejected choice is right

fp16 wins on GPU generations without native bf16 tensor-core throughput parity (pre-Ampere)

Why: bf16 has fp32's dynamic range, no loss-scaling required

ADR-17

Elastic rendezvous backend

Chosen

torch.distributed.elastic (c10d rendezvous)

Rejected

Custom rendezvous service

When the rejected choice is right

Custom rendezvous wins when the scheduler already provides a coordination primitive duplicating c10d's role

Why: Production-grade, operator-familiar, avoids a bespoke coordination service

ADR-18

Profiling instrumentation

Chosen

NVTX ranges + Kineto/torch.profiler

Rejected

Custom sampling profiler

When the rejected choice is right

Custom sampling profiler wins in CPU-only Gloo deployments where NVTX/nsys are unavailable

Why: NVTX integrates directly with nsys and existing NVIDIA tooling

ADR-19

Python/C++ extension boundary

Chosen

pybind11 for fused-kernel bindings

Rejected

Cython; raw CPython C API

When the rejected choice is right

Raw CPython C API wins when a kernel is hot enough that pybind11's per-call overhead is unacceptable

Why: Least boilerplate for the small fused-kernel surface shipped here

ADR-20

Tracing/metrics stack

Chosen

OpenTelemetry spans + Prometheus metrics

Rejected

Vendor-specific APM agent

When the rejected choice is right

A vendor APM agent wins when the operator has already standardized fleet-wide on that vendor

Why: Open standard integrates with any operator's existing observability stack

ADR-21

Python environment/reproducibility

Chosen

uv + Nix flake, pip+requirements.txt fallback

Rejected

Conda

When the rejected choice is right

Conda wins in HPC clusters whose module system already standardizes on Conda-distributed CUDA toolkits

Why: uv is fastest; Nix pins CUDA-aware toolchains reproducibly

ADR-22

License

Chosen

Apache-2.0 runtime; ELv2 reserved for a future hosted control plane

Rejected

MIT

When the rejected choice is right

MIT wins if the hosted-control-plane split is abandoned and a single permissive license is preferred

Why: Apache-2.0 carries an explicit patent grant, important given the CUDA-kernel surface

ADR-23

Automatic parallelism planner

Chosen

Deferred (manual ParallelStrategy only in-scope)

Rejected

Alpa-style cost-model auto-planner in Phase-0 scope

When the rejected choice is right

Auto-planner wins once manual (D,T,P,zero) search across a model/cluster catalog becomes the operator's bottleneck

Why: Manual strategy suffices through 3D parallelism; auto-planning is a distinct research surface (Zheng et al. 2022)

ADR-24

CPU/NVMe offload (ZeRO-Infinity)

Chosen

Deferred; ZeRO-3 pure-GPU ships first

Rejected

Ship offload alongside ZeRO-3

When the rejected choice is right

Shipping together wins when target hardware's GPU memory is so constrained pure-GPU ZeRO-3 cannot fit even the smallest model

Why: Offload is a bandwidth-modelled wrapper around a not-yet-hardened ZeRO-3; sequencing reduces risk

38. Alternative Architectures (Roads Not Taken)

1. Parameter-server architecture (DistBelief / Downpour SGD lineage).

 worker1 --push grad-->  [ parameter server ]  --pull params--> worker1
 worker2 --push grad-->  [   apply, avg     ]  --pull params--> worker2
 worker3 --push grad-->  [   broadcast      ]  --pull params--> worker3

Regime where it wins: extreme worker-count asynchrony tolerance, heterogeneous or unreliable workers (federated-like settings). Real system: the original TensorFlow parameter-server / DistBelief. Rejected because asynchronous PS updates break bit-exactness (P1, §6; I1, §7) and staleness is un-auditable at the scale this framework targets.

2. Fully automatic cost-model-driven parallelism (Alpa-style).

 model graph -> [ cost model + ILP/DP solver ] -> per-op (D,T,P) assignment -> compiled plan

Regime where it wins: heterogeneous architectures (MoE, mixed-depth) where manual strategy search is infeasible. Real system: Alpa (Zheng et al. 2022). Rejected (ADR-23, §9) because manual ParallelStrategy suffices through 3D parallelism and an auto-planner is a distinct, large research investment.

3. Fully asynchronous pipeline with weight-stashing (original PipeDream).

 stage i:  F(mb1,w0) F(mb2,w0) B(mb1,w0) F(mb3,w1) B(mb2,w0) ...  [stashed weight versions]

Regime where it wins: workloads where draining the pipeline per accumulated batch is too slow and staleness is tolerable. Real system: PipeDream (Harlap et al. 2018). Rejected because weight-version staleness is incompatible with bit-exact single-GPU equivalence (I1, §7).

4. Single flat compiler-driven mesh (GSPMD / JAX pjit).

 eager nn.Module  vs.  [ compiled graph + sharding annotations -> XLA partitioner -> SPMD ]

Regime where it wins: a compiler-first stack where the compiler, not hand-written engines, derives all communication from sharding annotations. Real system: GSPMD / JAX pjit. Rejected because the chosen substrate is eager PyTorch, not an XLA-compiled graph (ADR-01, §9), making compiler-driven sharding propagation unavailable without changing the runtime entirely.
