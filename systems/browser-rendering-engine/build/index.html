⬜ Phase 0 — Workspace, lifecycle shell, and the smoke test §12

Objectives

Stand up the Cargo workspace + nine render-* crate skeletons (§10); fix MSRV 1.78, edition 2021, deny-warnings CI posture. Define spine shells: DocumentLifecycle, DirtyBits, InvalidationKind, RenderEngine stub, Au, Rect, Canvas. Wire rengine CLI subcommand skeletons. End-to-end vertical slice: <p>hi</p> → 2-node DOM → one BlockContainer → 1-item DisplayList → solid rect rastered → PNG.

Deliverable

cargo build --workspace and cargo test --workspace green on MSRV 1.78; rengine render <(echo '<p>hi</p>') -o smoke.png emits a valid PNG with one solid rect at the block's geometry.

⬜ Phase 1 — HTML5 tokenizer and tree construction §13

Objectives

Build render-dom: a WHATWG-faithful tokenizer state machine + InsertionMode tree construction turning arbitrary bytes into a Document arena (I2). Character references (named/decimal/hex); implied end tags; foster-parenting subset; quirks detection from <!DOCTYPE>. Hard invariant (P2): zero panics on any fuzz-corpus input; bounded recursion (depth cap 512, §4.2).

Deliverable

render-dom::parse(&[u8]) -> Document; rengine dump dom <file> prints the indented tree. Structurally round-trips: serialize→reparse→identical tree shape.

Acceptance
Metric Target
html5lib tree-construction (tests1, tests6, doctype, entities subset) ≥ 95% pass
Panics on fuzz corpus (10M iters, 24h) 0
parse throughput ≥ 30 MB/s single-thread (§4)
Max stack depth before graceful cap 512, no overflow
Fixtures
Fixture Input Expected
fixtures/dom/implied.html <ul><li>a<li>b first <li> auto-closed
fixtures/dom/entities.html &amp;&#x41;&copy "&A©"
fixtures/dom/foster.html <table>x<td> "x" foster-parented before table
Malformed: <p<p<p, unterminated <!--, 100k <div> parse, no panic, recovers
Pitfalls

Reconsume vs re-emit: forgetting reconsume before switch_to drops/duplicates a char — trace (state,char), diff vs html5lib. RAWTEXT/RCDATA exit: </script end-tag match must equal the current tag name case-insensitively. Foster-parenting target: insert before the table in its parent, not append into it — off-by-one lands text inside the table.

⬜ Phase 2 — CSS tokenizer, parser, and CSSOM §14

Objectives

Implement render-css: CSS Syntax L3 (spec S2) tokenizer + parser → StyleSheet→CssRule→ StyleRule{SelectorList, Vec<Declaration>} for §15's cascade. Build the PropertyId registry (initial value + inherited flag + parse fn per property) and shorthand expansion (margin/padding/border/font). Resilience invariant (P2): invalid declarations/unknown properties are dropped silently; one bad rule never fails the whole sheet.

Deliverable

render-css parses UA + author stylesheets into a StyleSheet CSSOM; rengine dump css <file> prints the rule/selector/declaration tree. Round-trips a 200-rule author sheet without panicking.

Acceptance
Metric Target
CSS tokenizer fixtures 100% pass on supported token types
Declaration-drop correctness unknown prop/bad value dropped, sibling decls survive (100%)
Throughput ≥ 20 MB/s tokenize+parse, single thread (§4)
Fuzz 0 panics across fuzz/fuzz_targets/css.rs (24h)
Fixtures
Fixture Expected
shorthand.css margin:1px 2px → MarginTop/Bottom=60Au, MarginLeft/Right=120Au
at_rules.css @media/@import → skeleton rules, prelude captured
malformed_decl.css a:;b:1px;c → only b survives
unclosed_block.css p{color:red → recovers at EOF, decls kept
Pitfalls

Hash id-vs-unrestricted: #abc is an id-hash (selector+color); #1abc unrestricted (color only) — conflating breaks selector vs #rgb parse. !important placement: must be the last component values before ;; mid-value !important drops the whole decl. Error-recovery boundary: a bad rule must skip to its matching } honoring nested brace depth, not the first }.

⬜ Phase 3 — Selector matching and the cascade §15

Objectives

render-style cascade entry: match every StyleRule selector against DOM Elements, collect matched Declarations, order by the cascade tuple (I3) → specified values per element. Cascade tuple: (origin, !important inversion, specificity(a,b,c), source order) (§8.3). Right-to-left matching (rightmost compound first), reusing #258's matching model conceptually (ADR-14). Ship the built-in UA stylesheet.

Deliverable

rengine dump style <file> --css <author.css> emits per-element specified-value tables with the winning CascadeKey. Cascade-order test matrix passes.

Acceptance
Metric Target
12-row cascade matrix (origin×importance×specificity×order) 100% correct winner
Right-to-left matching, 6-element fixture correct match set
Matching throughput ≥ 200k (element×candidate-rule) tests/sec on 5k-element/500-rule doc
Fixtures
Fixture Input Expected
cascade_origin.css UA p{color:black} + author p{color:red} color=red
cascade_important.css author p{color:red} + user p{color:green!important} color=green
cascade_specificity.css #x{color:red} + p.c{color:blue} #x wins
malformed: bad_selector.css p::{}, >div{} rule dropped, others apply
Pitfalls

Source order across origins: a per-sheet local counter breaks cross-sheet ties — must be one global counter (I3). Specificity of :not(): contributes its argument's max specificity, not the pseudo-class itself. Bucket miss on multi-class: an element with two classes must be deduped by RuleId before emitting decls, or a rule matched via two buckets double-counts.

⬜ Phase 4 — Computed values, inheritance, and the style-sharing cache §16

Objectives

Consume §15's specified values, produce the styled tree: exactly one ComputedStyleId per Element, interned and shared via StyleCache (P6, I7). Resolve specified→computed: inherited props default to parent's computed value, non-inherited default to the initial value (spec S6). Value resolution: <length> (em/rem/%→Au), <color>→Rgba, font-size chain. Target: styled tree built, ≥40% style-sharing hit rate on a typical 5k-node page (§4).

Deliverable

Every Element carries a ComputedStyleId; rengine dump style --computed shows fully-resolved longhand values per element with Au/px both shown.

Acceptance
Metric Target
Style-sharing hit rate, 5k-node page, ≥30% identical siblings ≥ 40%
StyleCache false-share rate (I7 --verify) 0
Length resolution round-trip (Au↔px) exact on all px-multiple inputs
Cascade→computed pipeline, 5k-node page < 3 ms p50 (§4.1)
Fixtures
Fixture Input Expected
inherit_color.html parent color:red, no child override child computed color=red
share_siblings.html 100 <li> identical class, no state diff 1 ComputedStyleId, 100 refs
hover_no_share.html one <div> matches :hover-adjacent rule siblings do NOT share with it
percent_font.html font-size:150% on nested spans chained resolution matches expected Au
Pitfalls

False sharing is the gravest bug class (I7): sharing across any cascade-input difference silently corrupts unrelated elements' styles — the Bloom filter is a pre-filter, never the final gate; always verify full equality on a probable hit. Em/percentage resolution order: em must resolve against the element's own font-size chain, not the parent's, or nested 150% compounds wrong.

⬜ Phase 6 — Block layout (BFC) §18

Objectives

Implement the Block Formatting Context: width flows top-down from the containing block, height flows bottom-up from content (P3-adjacent: layout is a strict two-pass solve, applying P2 from Meyerovich & Bodik). Margin collapsing per CSS 2.2 section 8.3.1 (I6): adjoining vertical margins merge by the signed-max rule. Auto margins for centering.

Deliverable

layout_block produces correct Fragment geometry for nested block documents; rengine dump fragments --margins annotates each edge with raw and collapsed margin values.

Layout latency, 5k-node BFC-heavy page < 12 ms p95 (§4.1)
Auto-margin centering fixture exact px match
Fixtures
Fixture Input Expected

Reference-check against taffy (R-equivalent cross-check per §5, though not a dependency per ADR-21).

Deliverable

layout_flex produces correct Fragment geometry for single-line flex containers; rengine dump fragments shows each item's resolved main/cross size.

Acceptance

Fixtures
Fixture Input Expected
flex_grow_1_2.html items flex:1/flex:2 in 300px container 100px/200px split (§8.6)

⬜ Phase 9 — Positioned layout, stacking, and fragmentation §21

Objectives

Implement position: relative/absolute/fixed (spec S3/CSS Positioned Layout), containing-block determination for positioned boxes, z-index/stacking-context creation, and basic fragmentation (one LayoutBox → multiple Fragments, e.g. across explicit line breaks). sticky is best-effort (edge-case scroll-clamping is PhaseDeferred("§39")).

Deliverable

Positioned elements resolve to correct absolute coordinates; StackingContext tree is built and consumable by §22; rengine dump fragments --stacking shows the nesting.

Acceptance
Metric Target

Containing-block resolution correctness, 50-fixture corpus 100%
Stacking-context nesting matches CSS 2.2 App. E order (I8 precursor) 100% on fixture corpus
Fixtures
Fixture Input Expected
abs_pos_basic.html position:absolute;top:10px;left:20px inside relative parent offset from parent's padding edge
fixed_pos.html position:fixed offset from initial containing block (viewport), not nearest ancestor
z_index_stack.html three siblings with z-index:-1,0,1 negative-z under, zero at doc order, positive-z above

Objectives

render-paint::build_display_list(&FragmentTree) -> DisplayList (I8): walk the fragment tree once and emit DisplayItems in exact CSS 2.2 Appendix E order — backgrounds/borders → negative-z descendants → in-flow block descendants → floats → in-flow inline → positive-z descendants, recursing per nested StackingContext built in §21.

Deliverable

build_display_list produces a flat, ordered DisplayList; rengine dump display-list prints items with kind/rect/color, one line per item.

Acceptance
Metric Target
I8 band-order assertion on 200-fixture corpus 0 violations
WPT paint-order reftest subset ≥ 90% pass
Display-list build latency, 5k-node page < 4 ms p95 (§4.1)
Determinism: 3× identical build on same FragmentTree byte-identical DisplayList
Fixtures
Fixture Input Expected
paint_order_basic.html bg + border + text on one box items in bg→border→text order
neg_z_under.html z-index:-1 child of a positioned parent painted before the parent's own background is NOT correct — parent bg paints, then neg-z child, per App. E
clip_nested.html nested overflow:hidden balanced PushClip/PopClip pairs, correctly nested
Pitfalls

Confusing "paint order" with "DOM order" — floats and positioned descendants paint out of DOM order per Appendix E; a naive DFS in document order fails these fixtures silently (wrong-looking but not crashing). ⬜ Phase 11 — Compositing and software rasterization §23

GPU raster is PhaseDeferred("§39") per ADR-11.

Deliverable

composite() + the raster backend produce a valid Canvas; rengine dump layers shows the layer tree with bounds/transform/opacity; render emits a PNG.

Fixture Input Expected
layerize_opacity.html opacity:0.5 + will-change:opacity promoted to own Layer

⬜ Phase 12 — Invalidation and incremental rendering §24

Objectives

Wire render-engine's StyleInvalidator (stub since §16) and DirtyBits/InvalidationKind (stub since §12) into a working incremental pipeline: a DOM mutation scopes to the minimal DirtyBits, the FrameScheduler coalesces all mutations between frames into one lifecycle pass, and unchanged subtrees (style, fragments, display items, layers) are reused frame-to-frame (P5, I11). This is the phase that proves I11 (incremental ≡ full re-render).

Deliverable

render_frame() on a single mutated element re-runs only the dirtied phases; rengine bench --incremental reports per-mutation-class latency against §4's 16 ms floor.

Acceptance
Metric Target
Incremental frame, localized mutation (§4) < 16 ms
Composite-only frame (scroll/opacity) < 4 ms
I11 "dirty-twin" test (incremental vs full render SHA-256) 100% match, 0 divergences, across 100 mutation fixtures
Subtree reuse rate on a single-class-toggle mutation ≥ 95% of unaffected fragments reused (not rebuilt)
Fixtures
Fixture Input Expected
mutate_color.html toggle a class changing only color NEEDS_PAINT only, 0 relayouts (dirty-twin match)
mutate_width.html toggle a class changing width NEEDS_LAYOUT, downstream repaint+composite, dirty-twin match
mutate_transform.html toggle opacity on a layerized subtree NEEDS_COMPOSITE only, 0 relayouts/repaints (I9), dirty-twin match
mutate_structure.html insert a new sibling <div> correct DirtyBits scope covering the new subtree + affected sibling selectors
Pitfalls

Under-invalidation (a missed selector dependency) is the gravest bug class in the whole engine — silently stale pixels with no crash to signal it; the dirty-twin test (I11) is the only reliable detector. Over-invalidation (marking too much dirty) is merely a performance bug, never correctness — when in doubt during development, over-invalidate and tighten later.
