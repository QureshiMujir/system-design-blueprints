Decisions (§9) · 22 ADRs

ADR-01

Language

Chosen

Rust, edition 2021, MSRV 1.78

Rejected

C/C++; Go; TypeScript

When the rejected choice is right

C/C++ wins for a GPU-driver-adjacent layer needing raw pointer ABI to existing C libraries (e.g. binding to a vendor's proprietary codec)

Why: untrusted parse hot path needs memory safety; sum types for BoxKind/DisplayItem; Servo maps 1:1

ADR-02

Code organization

Chosen

Cargo workspace, nine render-* crates

Rejected

one monolith; per-type micro-crates

When the rejected choice is right

a one-person prototype where crate-split overhead exceeds any DAG-enforcement benefit

Why: crate boundary = pipeline-stage boundary = compiler-enforced DAG (P13)

ADR-03

Tree storage

Chosen

Arena<T> + typed index newtypes

Rejected

Rc<RefCell<Node>> pointer graph

When the rejected choice is right

a tree needing frequent structural sharing across independent owners (e.g. a persistent/functional data structure) favors Rc

Why: Copy indices, cache-dense, side-steps RefCell panics + cycles

ADR-04

Layout unit

Chosen

Au(i32), 1 px = 60 Au, integer math

Rejected

f32/f64 px; fixed-point 16.16

When the rejected choice is right

a physics/3D-transform-heavy renderer where sub-Au precision and matrix math dominate favors floats throughout

Why: 60=lcm(2,3,4,5,6) → exact splits, zero float drift (P4, I5)

ADR-05

Style reuse

Chosen

StyleCache shares ComputedStyle on exact-input equality

Rejected

recompute per element; cache by element identity

When the rejected choice is right

a document with almost no structural repetition (e.g. one giant unique form) gets no benefit and pure per-element compute is simpler

Why: sibling/list-item style sharing is 1 alloc not N (P6, I7)

ADR-06

Pipeline staging

Chosen

DocumentLifecycle strict DAG, forward-only

Rejected

ad-hoc "render everything"; lazy on-demand recompute

When the rejected choice is right

a batch/offline renderer with no incremental requirement can skip lifecycle bookkeeping entirely

Why: explicit precondition gate makes incremental scoping (ADR-07) tractable (P3, I1)

ADR-07

Invalidation model

Chosen

DirtyBits bitset + InvalidationKind, minimal-subtree scoping

Rejected

full reflow every mutation; observer/event graph

When the rejected choice is right

a tiny document (<100 nodes) where full-reflow cost is negligible and scoping machinery is pure overhead

Why: dirty bit encodes which phase must re-run + from where (P5)

ADR-08

HTML parser

Chosen

hand-written tokenizer + tree construction in render-dom

Rejected

html5ever dependency; regex/ad-hoc parse

When the rejected choice is right

a production engine with zero pedagogical goal should vendor html5ever — battle-tested, saves years

Why: pedagogical control of InsertionMode, foster-parenting, quirks (P1)

ADR-09

CSS parser

Chosen

hand-written CSS Syntax L3 tokenizer/parser

Rejected

cssparser/lightningcss crate

When the rejected choice is right

a project only consuming CSS (not teaching it) should vendor cssparser for correctness-by-construction

Why: owns the cascade-input modeling ADR-05 depends on

ADR-10

Layout output

Chosen

separate immutable FragmentTree; BoxTree is input-only

Rejected

mutate LayoutBox geometry in place

When the rejected choice is right

a single-pass, never-incremental renderer (e.g. print-to-PDF one-shot) gains nothing from the split and pays its allocation cost

Why: reusable box tree + throwaway fragments enable fragmentation + incremental relayout (P7)

ADR-11

Raster backend

Chosen

software RasterBackend, scanline/edge AA

Rejected

GPU backend (wgpu/Vulkan)

When the rejected choice is right

an interactive browser needing 60fps on 4K viewports must go GPU — software raster cannot hit that budget

Why: deterministic pixels for reftests, no driver dependency, portable in CI (I10)

ADR-12

Compositing

Chosen

LayerTree with layerization on transform/opacity/will-change

Rejected

paint everything flat every frame

When the rejected choice is right

a static, non-animated document renders once and never benefits from layer bookkeeping overhead

Why: composite-only changes reuse cached layer content (P9, I9)

ADR-13

Text rendering

Chosen

embedded monochrome bitmap glyphs, fixed metrics

Rejected

full shaping (HarfBuzz-style); vector outlines

When the rejected choice is right

any document with complex scripts (Arabic, Devanagari) or scalable text needs PhaseDeferred("§39") full shaping

Why: decouples layout/paint from shaping complexity; deterministic metrics

ADR-14

Selector engine

Chosen

selector-matching reused conceptually from #258, implemented inline

Rejected

vendor/depend on #258's crate

When the rejected choice is right

a project whose point is the selector engine should depend on #258 directly, not reimplement

ADR-15

Error policy

Chosen

best-effort parse, never panic; layout clamps degenerate sizes

Rejected

Result-propagate parse errors to caller

When the rejected choice is right

an internal-only tool parsing known-good, machine-generated markup can afford to fail loudly instead

Why: HTML/CSS are error-tolerant by spec; untrusted input must not crash the host (P2)

ADR-16

Determinism

Chosen

byte-identical Canvas for identical input, across runs/platforms

Rejected

allow platform float variance

When the rejected choice is right

a GPU-accelerated interactive renderer accepts driver-level nondeterminism in exchange for speed

Why: required for reftests + differential diffing (I10)

ADR-17

Concurrency

Chosen

single-threaded pipeline v1; arena design keeps parallel style/layout deferred

Rejected

thread-per-stage; rayon parallel layout from day 1

When the rejected choice is right

a page-load-latency-critical production engine (Stylo in Firefox) must parallelize restyle from the start

Why: correctness+determinism first; arena handles already enable later Send parallelism

ADR-18

Benchmarking

Chosen

criterion micro+macro benches vs §4 targets

Rejected

When the rejected choice is right

a one-off research prototype with no CI budget can skip a formal harness

Why: variance-aware regression detection

ADR-19

Fuzzing

Chosen

cargo-fuzz targets: HTML tokenizer, CSS parser, layout driver

Rejected

no fuzzing; manual edge cases only

When the rejected choice is right

a closed, trusted-input-only deployment (e.g. an internal templating tool) has lower fuzz ROI

Why: untrusted-input parsers are prime crash surface (P2)

ADR-20

Conformance harness

Chosen

WPT reftests + html5lib tree-construction, per-pixel tolerance diff

Rejected

golden-string DOM dumps only; exact-bit-match images

When the rejected choice is right

a text-only renderer with no anti-aliasing can use exact-bit-match safely and more strictly

Why: reftests are the real-world correctness standard; tolerance absorbs AA rounding

ADR-21

Dependency policy

Chosen

minimal deps: std only in the render path

Rejected

pull html5ever/cssparser/skia/wgpu/font crates

When the rejected choice is right

a production deployment optimizing for time-to-ship should take the battle-tested crates (see ADR-08/09/11/13)

Why: the pipeline is the deliverable — vendoring it defeats the pedagogical purpose

Licensing

Chosen

MIT OR Apache-2.0

Rejected

GPL; proprietary; single license

When the rejected choice is right

a project needing copyleft protection against proprietary forks should choose GPL/AGPL instead

Why: maximal reuse, matches Servo/Rust convention

38. Alternative Architectures (Roads Not Taken)

A1 — Mutable render-object tree (WebKit-classic style), rejected in favor of the immutable box/fragment split (ADR-10).

DOM --style--> RenderObject tree (mutable in place: RenderBlock/RenderInline/RenderText)
                    |  layout() mutates x/y/w/h directly on the same nodes
                    v
                 paint() walks the same mutable tree

Regime where it wins: an engine migrating incrementally from a decades-old codebase, where a clean-slate immutable rewrite is not affordable — WebKit's WebCore/rendering is the real system that embodies this. Rejected here because in-place mutation conflates persistent structure with transient per-layout geometry, which defeats both fragmentation (one box → many fragments) and cheap incremental relayout (§9, ADR-10).

A2 — GPU-first display list (WebRender model), rejected in favor of software raster (ADR-11), deferred not abandoned (§39).

FragmentTree -> DisplayList -> GPU command batching -> shader-based tile raster -> compositor

Regime where it wins: any interactive browser targeting 4K/60fps on real hardware — WebRender (Mozilla, embodied in Firefox and Servo) is the real system. Rejected for v1 because it adds a GPU-driver dependency that breaks CI portability and reftest bit-exactness (I10); this design's DisplayList (§11) is intentionally WebRender-shaped so the GPU backend is a drop-in later (PhaseDeferred, §39).

A3 — Parallel-everything from day one (Stylo/Servo model), rejected in favor of single-threaded-first (ADR-17).

DOM --parallel restyle (rayon)--> styled tree --parallel layout (BFC subtrees)--> FragmentTree

Regime where it wins: a production engine under real page-load-latency pressure, where restyle of a 50k-node page must not block the main thread — Stylo in Firefox is the real system. Rejected for v1 because correctness-first sequencing is easier to prove invariant-by-invariant (§7) before introducing data races across StyleCache/arena mutation; the arena+index design (ADR-03) already makes the later parallel retrofit structurally possible without a rewrite.

A4 — Streaming/incremental parse-and-layout fusion (progressive rendering), rejected in favor of a batch-per-frame pipeline (ADR-06).

byte stream --(parse chunk)--> partial DOM --(layout chunk immediately)--> partial paint
   (repeat as bytes arrive, before the document is fully loaded)

Regime where it wins: a real user-facing browser on a slow network, where showing partial content immediately (progressive rendering) beats waiting for the full document — every shipping browser does this. Rejected here because the engine's input contract is a complete in-memory byte slice (§1.3, no networking/fetch in scope) — there is no "arriving bytes" event to fuse against, and adding one would entangle the deferred fetch/networking non-goal into the core lifecycle (I1).
