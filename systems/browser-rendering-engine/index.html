3. Architectural Overview

3.1 The pipeline at a glance

The engine is a strict, single-direction DAG: HTML+CSS bytes enter, an RGBA framebuffer exits. render-engine drives every box through a monotone DocumentLifecycle; no stage reaches forward into its consumer's state.

   HTML bytes (untrusted)         CSS bytes (untrusted)
        |  ===== TRUST BOUNDARY: all parser input is hostile =====
        v                              v
  +-------------+              +----------------+
  | render-dom  |              |   render-css   |   PARSE (sequential, per-doc)
  | Document/   |              | StyleSheet/    |   tokenizer = state machine,
  | Node/Element|              | CssRule/Decl   |   no parallelism (linear scan)
  +------+------+              +-------+--------+
         \  DOM tree               CSSOM  /
          v                              v
        +-----------------------------------+
        | render-style : cascade()          |  origin+importance+specificity+order
        |   -> ComputedStyle (immutable)    |  StyleCache (share), StyleInvalidator
        +-----------------+-----------------+
                          | styled tree  ===== CONCURRENCY: ComputedStyle is
                          v                    frozen Send+Sync after cascade =====
        +-----------------------------------+
        | render-layout : BoxTree           |  box generation -> BFC/IFC/FFC
        |   -> layout() -> FragmentTree     |  Au integer geometry; independent
        +-----------------+-----------------+  BFC subtrees layout in parallel
                          | fragments + geometry
                          v
        +-----------------------------------+
        | render-paint : build_display_list |  CSS 2.2 App. E paint order
        |   -> DisplayList (StackingContext)|
        +-----------------+-----------------+
                          | display items
                          v
        +-----------------------------------+
        | render-compositor : layerize      |  transform/opacity/will-change
        |   -> LayerTree -> composite()     |  -> Layers; flatten to Canvas
        +-----------------+-----------------+
                          | layers
                          v
        +-----------------------------------+
        | render-raster : Canvas (RGBA)     |  scanline AA fill, glyph blit;
        |   scanline fill <- DisplayItems   |  tiles raster in parallel
        +-----------------+-----------------+
                          v
                    PNG / RGBA buffer
             ===== PERSISTENCE BOUNDARY: none at runtime;
                   the framebuffer is the ONLY durable output =====

 [ render-engine drives all of the above: DocumentLifecycle, DirtyBits,
   InvalidationKind, FrameScheduler -> one coalesced frame per advance ]

Every box in this diagram is named identically in the Repository Layout (§10), Core Schema (§11) and every phase; consistency is enforced by ADR-02's crate-per-stage boundary.

3.2 The three cross-cutting boundaries

Boundary Where Rule
Trust inputs to render-dom + render-css all bytes are hostile; parsers never panic/OOB/unbounded-recurse (P2); malformed input recovers per spec, never aborts
Concurrency layout + raster parsing is sequential (serial state machine); post-cascade ComputedStyle is immutable + Send+Sync; independent BFC subtrees layout on a work-stealing pool; raster tiles run in parallel; no shared mutable state crosses a thread
Persistence none arenas live in-process for the document's lifetime; the framebuffer (PNG via render-cli) is the sole durable artifact; no cache survives a process restart

3.3 Box-by-box responsibilities

render-dom — HTML front end. In: byte stream. Out: Document (arena of Node) + QuirksMode. Owns the ~70-state tokenizer and InsertionMode tree construction. Referenced later: §15 matches selectors against Element; §24 sets DirtyBits on mutation.

render-css — CSS front end. In: CSS byte streams. Out: StyleSheet{rules,origin}. Owns the CSS Syntax L3 tokenizer, the parser, and the PropertyId registry. Referenced later: §15 consumes SelectorList+Declaration.

render-style — the cascade engine. In: Document + matched StyleSheets. Out: one immutable ComputedStyle per element. cascade() orders declarations by origin→importance→specificity→ source order (I3); StyleCache shares styles across provably-equal inputs (I7). Referenced later: every layout box carries a ComputedStyleId.

render-layout — geometry. In: styled tree. Out: FragmentTree. Two trees: BoxTree (box generation, anonymous-box fixup) and layout(box_tree, viewport) -> FragmentTree, dispatched by FormattingContext (Block/Inline/Flex). All coordinates are Au (I5). Referenced later: §22 walks the FragmentTree; §24 reuses unchanged BFC subtrees.

render-paint — display-list builder. In: FragmentTree. Out: flat DisplayList. Emits items in CSS 2.2 Appendix E order (I8). Referenced later: §23 partitions items into Layers.

render-compositor — layer manager. In: DisplayList + StackingContext tree. Out: LayerTree. Layerization promotes transform/opacity/will-change subtrees (I9). Referenced later: §24's InvalidationKind::Composite advances only to Composited.

render-raster — software pixel backend. In: DisplayItems per layer. Out: Canvas{w,h,pixels}. Scanline/edge AA fill + mono glyph blit; the only stage using floating point. GPU raster is PhaseDeferred("§39").

render-engine — the orchestrator. Owns DocumentLifecycle (I1), DirtyBits, InvalidationKind scoping, and the FrameScheduler that coalesces invalidations into one lifecycle pass per frame.

render-cli — the rengine binary: render/dump/reftest/bench. A thin I/O shell; owns no rendering logic.

3.4 Data-flow & ownership summary

Stage Crate Produces Owned arena Immutable after
Parse HTML render-dom Document Arena<Node> mutation only via DOM API
Parse CSS render-css StyleSheet Vec<CssRule> parse complete
Cascade render-style ComputedStyle id-keyed table cascade complete (frozen, Send+Sync)

Each arena outlives only its document; nothing crosses the persistence boundary. A phase reads only *Clean upstream state, never a producer mid-mutation.

8. Domain Model — HTML, CSS, and the Render Trees

Seven coupled data models, one per pipeline stage (§3): DOM (render-dom), CSSOM (render-css), ComputedStyle/styled tree (render-style), BoxTree+FragmentTree (render-layout), DisplayList (render-paint), LayerTree (render-compositor), Canvas (render-raster).

8.1 HTML model — tokenization + tree construction

Two coupled state machines (WHATWG HTML section 13.2): the tokenizer (bytes → tokens) and tree construction (tokens → DOM), sharing state (tree construction resets tokenizer mode for <script>/<style>).

Token = DOCTYPE{name,public_id,system_id,force_quirks}
      | StartTag{name:Atom, attrs:Vec<(Atom,String)>, self_closing:bool}
      | EndTag{name:Atom} | Comment(String) | Character(char) | EOF

InsertionMode = Initial | BeforeHtml | BeforeHead | InHead | AfterHead
              | InBody | Text | InTable | InCell | AfterBody | ...
Mode Token Action → next mode
Initial DOCTYPE set QuirksMode (8.1.1), → BeforeHtml
BeforeHead <head> push head → InHead
InHead <style>/<script> switch tokenizer RAWTEXT → Text
AfterHead <body> push body → InBody
InBody </p> if no p in scope, insert implied <p></p> then close
InBody <table> → InTable

Implied end tags: auto-close {dd,dt,li,option,optgroup,p,rp,rt} before certain insertions (<li>a<li>b auto-closes the first <li>). Foster parenting: mis-nested content inside <table> relocates before the table, not inside it.

8.1.1 Quirks detection

DOCTYPE Mode
<!DOCTYPE html> NoQuirks
public id matches legacy "limited" list LimitedQuirks
missing/unknown/force_quirks Quirks

QuirksMode is carried on Document.quirks, read by render-style and render-layout.

8.2 CSS model — grammar + CSSOM

stylesheet      = { CDO | CDC | ws | at-rule | qualified-rule } ;
qualified-rule  = selector-list , declaration-block ;
declaration-block = "{" , { declaration , [ ";" ] } , "}" ;
declaration     = property , ":" , value , [ "!" , "important" ] ;
selector-list   = complex-selector , { "," , complex-selector } ;
complex-selector= compound , { combinator , compound } ;
combinator      = ">" | "+" | "~" | ws ;
compound        = [ type-sel ] , { id-sel | class-sel | attr-sel | pseudo } ;

Parse output (locked types): StyleSheet{rules:Vec<CssRule>, origin:Origin}; CssRule = Style(StyleRule)|Media|Import|FontFace; StyleRule{selectors:SelectorList, block:Vec<Declaration>}; Declaration{property:PropertyId, value:ComputedValue, important:bool}. The PropertyId registry maps each known property to {inherited, initial, applies_to}; unknown property names are dropped at parse time (8.6). Shorthand expansion (margin: 1px 2px → four longhands) happens before cascade.

8.3 The cascade — ordered tuple sort

CascadeKey = (origin_importance, specificity(a,b,c), source_order)   // descending wins (I3)
fn cascade(el, matched: &MatchedRules, parent: &ComputedStyle) -> ComputedStyle

Origin×importance precedence (highest first): Author !important > User !important > UA !important > Author normal > User normal > UA normal. Specificity (a,b,c): a=#id, b= class/attr/pseudo-class, c=type/pseudo-element, compared lexicographically. Source order: later declaration wins ties. Result = specified value per property; computed-value resolution (lengths → Au, colors → Rgba) yields ComputedStyle (§16). StyleCache shares one ComputedStyle across elements with identical (parent style, matched rules, inline) inputs (I7).

8.4 Box generation and formatting contexts

display / node Generated BoxKind
block BlockContainer
inline InlineBox

none (no box)
text node Text(TextRun)
replaced (<img>) Replaced

Anonymous-box fixup (I4): mixed block+inline children wrap consecutive inline runs in AnonymousBlock; text inside a block-only container wraps in AnonymousBlock→AnonymousInline.

Context Owns Key algorithm
Block (BFC) block-level children, vertical stacking width top-down, height bottom-up, margin collapsing (§18)
Inline (IFC) inline content, LineBoxes greedy line breaking, baseline/vertical-align (§19)
Flex (FFC) flex items, main/cross axis grow/shrink/basis, justify/align (§20)

8.5 Worked example — block + inline document

Input: <!DOCTYPE html><div class=box><p>Hello <b>world</b></p></div> with UA rules div,p{display:block} b{display:inline;font-weight:bold} and author rules .box{width:200px; margin:10px} p{color:#cc0000;font-size:16px}.

(1) DOM:          Document>html>body>div.box>p>{"Hello ", b>"world"}
(2) ComputedStyle: div: Width=12000Au(200px), MarginTop=600Au
                   p:   Color=#cc0000, FontSize=960Au(16px)
                   b:   inherits Color/FontSize, FontWeight=Bold
(3) BoxTree:       BlockContainer(div) > BlockContainer(p)[IFC] > {Text, InlineBox(b)>Text}
(4) FragmentTree:  Fragment(div) rect=600,600,12000,~1500
                     └ Fragment(p) rect=600,600,11760,~960
                        └ Line: GlyphRun("Hello ",#cc0000), GlyphRun("world",#cc0000,bold)
(5) DisplayList:   [Text{"Hello ",#cc0000}, Text{"world",#cc0000}]   // paint order I8

8.6 Worked example — flex

`<div style="display:flex;width:300px"><div style="flex:1">A</div><div style="flex:2">B</div>

</div>` → main-axis 18000 Au splits 1:2 by flex-grow → `A` gets 6000 Au (100px), `B` gets 12000 Au (200px); cross-axis default `align-items:stretch` fills both to container cross size.

8.7 Malformed input and recovery

Malformed input Recovery
<b>bold<i>both</b>still</i> (mis-nested) adoption-agency reparent; <i> reopened after </b>
<p>one<p>two (missing </p>) implied </p> before second <p> (8.1)
stray </p> with no open p insert implied empty <p></p> then close
color: ; (empty value) declaration dropped, rest of block parsed
colour: red (unknown property) declaration ignored (not in PropertyId registry)
unbalanced { in rule consume to matching } or EOF, skip rule
<table>text</table> foster-parent "text" before the table

Invariant: a dropped declaration/rule never affects sibling declarations; a recovered tag never loses already-parsed content.

8.8 Incremental frame — class toggle sequence

setAttribute(class) -> render-dom mutates Node.attrs -> notify render-style
  StyleInvalidator matches changed selectors -> DirtyBits: NEEDS_STYLE (+NEEDS_LAYOUT if a
  geometry property changed) -> render-engine FrameScheduler coalesces -> one render_frame():
  restyle(dirty subtree, StyleCache reuse) -> StyleClean
  relayout(dirty box only)                -> LayoutClean   [partial FragmentTree]
  repaint(dirty display items)            -> PaintClean
  composite (flatten LayerTree)           -> Composited    -> &Canvas

Scoping rules (locked, I9): color-only change → NEEDS_PAINT (skip relayout); width/display change → NEEDS_LAYOUT; transform/opacity on a layerized subtree → NEEDS_COMPOSITE only. Unchanged subtrees keep their cached fragments/display-items/layers frame-to-frame.
