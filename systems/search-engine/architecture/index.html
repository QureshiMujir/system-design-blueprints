Box-by-box. HTTP/gRPC frontend terminates untrusted client connections, deserializes requests, and is the only component that sees raw client bytes (trust boundary 1, §23). Coordinator is the only component aware of shard topology; it owns request fan-out and partial-failure merging (§21.3) and is stateless across requests. Shard engine is the unit of correctness: analyser and query parser are pure functions over text with no shared mutable state; indexer and searcher are the only components that touch the inverted index, and they do so through one shared trait boundary (PostingListReader, §11.5) so the searcher never branches on which storage layer served a posting. Inverted index is the immutable artifact boundary — nothing downstream mutates a posting once written (Principle P6). Aggregations/highlight run alongside the searcher as read-only observers of the same scored-document stream. Hybrid fusion adapter is the only component that crosses a service boundary to another blueprint's system (delegation, §1). Storage layer is the persistence boundary: segment files are rename-into-place atomic; the WAL is the crash-recovery source of truth for anything not yet in a segment (§18.6, I11).

Three load-bearing properties, referenced throughout: (1) the data path is one-way — documents flow down into the segment store, queries flow down into the searcher, posting lists are the immutable interface between them; (2) every backend (analyser, scorer, codec, merge policy) presents the same trait-bound interface (§11) and the searcher never branches on backend identity; (3) every cross-cutting resource (memory pool, Unicode tables, term dictionary, page cache) is owned by exactly one module and reached everywhere else only via a trait call, never a direct reach-across.

8. Domain Model / Protocol / Data Model

8.1 Query grammar (EBNF)

query          = disjunction ;
disjunction    = conjunction , { "OR" , conjunction } ;
conjunction    = factor , { [ "AND" ] , factor } ;
factor         = [ "NOT" | "+" | "-" ] , clause ;
clause         = group | term-clause | phrase-clause | field-clause | range-clause ;
group          = "(" , disjunction , ")" ;
field-clause   = ident , ":" , clause ;
term-clause    = term , [ "~" , integer ] , [ "^" , float ] ;
phrase-clause  = '"' , { term } , '"' , [ "~" , integer ] , [ "^" , float ] ;
range-clause   = ( "[" | "{" ) , (range-value | "*") , "TO" , (range-value | "*") ,
                  ( "]" | "}" ) , [ "^" , float ] ;
range-value    = integer | float | date | keyword ;
term           = unicode-word | escaped-unicode-word ;

Operator precedence: NOT > AND > OR; parentheses override. Bare juxtaposition (foo bar) is a disjunction (Lucene-compatible default, ADR-08).

8.2 Posting-list wire/storage layout

posting list:
  [block 0][block 1] ... [block N-1][tail]
each block (fixed 128 docs, except tail):
  header:    doc_count:u8 | codec_id:u8 | bit_width:u8 | flags:u8
  doc_ids:   delta-encoded, codec-compressed (§15)
  tfs:       codec-compressed
  positions: offset into separate .pos stream (only if field has positions)
  block_max_doc_id: u32
  block_max_score:  f32   (I4)
  crc32c:           u32   (I3)
tail:
  varbyte-encoded remainder, no block-max fields

8.5 Worked example — query rewrite

Input: title:"quick brown"~2 AND status:active. Lex → [FIELD(title) COLON PHRASE("quick","brown") TILDE 2 AND FIELD(status) COLON TERM(active)]. Parse → Query::Boolean{ must: [Phrase{field:title, terms:["quick","brown"], slop:2}, Term{field:status, term:"active"}], should: [], must_not: [], minimum_should_match: 1 }. Rewrite applies the title field's analyser (stemming off, lowercase on) to "quick"/"brown" and the status field's keyword analyser (exact, no stemming) to "active" — this is where P3 is enforced: if status were accidentally stemmed, "active" could rewrite to "activ" and never match a keyword-indexed "active" value.

8.6 Malformed-input example

Input: title:"unterminated phrase AND x:1. Lexer reaches EOF inside the phrase quote. Parser raises SearchError::QueryParse{ col: 38, msg: "unterminated phrase literal" }. The HTTP layer maps this to 400 Bad Request with the column echoed in the response body so a client can underline the offending character. Conformance fixture: conformance/corpora/query/malformed-001.json (§16.5).

8.7 Failure-path example

Indexing thread crashes mid-flush_block() after writing 96 of 128 doc-id deltas but before the CRC is written. On restart, segment::reader opens the .post file, encounters a block whose trailing CRC bytes are absent (Building-state temp file, never renamed into place per I1), and the previous committed segment (still Live) is used for search unaffected. The partial _tmp file is garbage-collected on next flush attempt. No corrupt bytes ever reach a Live segment because commit is a single atomic rename (§8.4 Committing → Live), not an in-place write.

Design principles (§6)

  • P1 — Correctness is the ground truth. Every codec has a scalar reference path that is the conformance baseline; SIMD-accelerated paths must be bit-identical to it. Tradeoff: the reference path is kept even after the fast path ships (double maintenance). Violate it and a "fast" decoder that is wrong on one block in a million silently corrupts rankings — worse than a slow correct one.
  • P2 — One engine, two storage layers, one trait. The immutable-segment layer and the in-memory delta layer both implement PostingListReader (§11.5); the searcher never branches on which layer served a posting. Tradeoff: the trait must be conservative enough to fit both. Violate it and real-time visibility logic leaks into the scorer, becoming untestable in isolation.
  • P3 — Analysis is the document's property, not the searcher's. A document is analysed once at index time; the query is analysed at query time with the same analyser configuration per field. Tradeoff: changing an analyser requires re-indexing. Violate it and the user's exact query never matches the document (§7 I2, §16.2).
  • P4 — The term dictionary is a finite-state transducer. FST gives O(prefix-length) lookup and 5–10× size reduction vs. a hash map (ADR-02). Tradeoff: FST construction requires sorted input, forcing a sort at flush time. Violate it (plain hash map) and term-dictionary memory blows past §4's 2.5 GB ceiling at 50 M terms.
  • P5 — Posting lists are blocks of integers, no per-document headers. Fixed BLOCK_SIZE=128 blocks (doc-id delta + tf + optional positions + block-max stat), tail block for the remainder. Tradeoff: block granularity bounds skip precision. Violate it and per-document overhead dominates at scale (§33 C1).
  • P6 — Segments are immutable. Updates are delete-tombstone + insert; GC happens at merge time. Tradeoff: deleted documents cost disk until the next merge. Violate it (in-place mutation) and concurrent readers lose the free consistent-snapshot property (I8).
  • P7 — The merge policy owns time, not the indexer. Indexer flushes; a separate module decides when to fold, on explicit triggers (size/count/age) and explicit budgets (CPU/IO/fan-in). Tradeoff: merge scheduling adds a coordination layer. Violate it and indexing throughput and read amplification couple in an untunable way (§18.4).
  • P8 — Strings are owned by the analyser. No other module decodes UTF-8 or normalizes Unicode; downstream sees TermId (interned u32) and analyser-owned byte slices. Tradeoff: every new text-touching feature must route through the analyser. Violate it and Unicode bugs (Turkish dotless-I, ZWJ sequences) surface in three different modules instead of one.
  • P9 — Determinism is the default. Same documents, same order ⇒ byte-identical segments; merge policy and scorer are deterministic given the same inputs; stochastic components (learned reranking) are seeded. Tradeoff: some optimizations (unordered parallel merge) are foreclosed. Violate it and conformance fixtures (§14.5 et al.) become flaky.
  • P10 — No silent fallbacks. A codec that cannot decode a block (bad CRC, unsupported version) raises; the caller decides. Tradeoff: no automatic "just serve something" degradation. Violate it and throughput predictability — the search-tier SLO — is destroyed by hidden slow paths.
  • P11 — Memory pool per query, one global term-dictionary cache. Per-query allocations live in a query-scoped arena freed at end-of-query; no per-posting malloc/free on the hot path. Tradeoff: arena sizing must be tuned per workload. Violate it and allocator contention becomes the dominant cost at high QPS (§17.7).
  • P12 — One shard is a unit of work; replicas are for availability, not sharding. The router treats replicas as interchangeable reads; only the primary accepts writes. Tradeoff: replica reads can lag (§21.5). Violate it (writes to any replica) and you have reinvented a conflict-resolution problem this engine explicitly does not solve.
  • P13 — Score-safety before speed. Any early-termination strategy (WAND, BMW, MaxScore) must be provably score-safe (never drops a true top-k member) before it is allowed to ship; speed gains beyond that are free upside, never a justification to relax safety. Violate it and top-k results become silently incomplete (§17.5, I6).
  • P14 — Every backend is swappable through one trait, never a call-site if. Analyser, Codec, Scorer, MergePolicy all present trait-bound interfaces (§11); the search/index hot path contains zero match backend_kind {} dispatch outside the trait impl itself. Violate it and adding a new codec requires touching every call site instead of one impl block.
  • P15 — Observability is a first-class output, not an afterthought. Every phase ships named metrics/traces before it ships an optimization (§22, §25). Violate it and a production latency regression becomes undiagnosable from the dashboard alone.
