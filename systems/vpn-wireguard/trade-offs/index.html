Decisions (§9) · 24 ADRs

ADR-01

Language

Chosen

Rust 1.78+ MSRV

Rejected

C, Go, Zig

When the rejected choice is right

Go wins when portability to a Go-fluent ops team outweighs the memory-safety gain — wireguard-go's actual, deliberate choice.

Why: Memory safety without GC pauses on the hot path (§1).

ADR-02

Workspace shape

Chosen

Cargo workspace, 16 crates

Rejected

Single monolithic crate, Bazel

When the rejected choice is right

A single crate wins for a throwaway prototype where compile-time boundary enforcement isn't worth the overhead.

Why: Crate boundaries enforce the protocol/crypto/transport separation (P1–P5) at compile time.

ADR-03

Dependency policy

Chosen

Minimal audited crates only

Rejected

Hand-rolled crypto, unaudited crates

When the rejected choice is right

Hand-rolled crypto wins only in a teaching-only context with no real key material at stake.

Why: Constant-time guarantees are a multi-year audit investment.

ADR-04

Key persistence

Chosen

Static keys on disk only; sessions never persisted

Rejected

Session-key persistence for fast reconnect

When the rejected choice is right

Session persistence wins on multi-minute-RTT satellite links where re-handshake cost dominates and reduced FS is accepted.

Why: Forward secrecy (I4) requires ephemerals to never touch disk.

ADR-05

Serialization

Chosen

Fixed-offset binary structs

Rejected

Protobuf, FlatBuffers

When the rejected choice is right

Protobuf wins for the control-plane CLI protocol if cross-language client libraries are needed.

Why: The wire format is externally fixed by the WireGuard spec.

ADR-06

Networking

Chosen

Raw UDP via tokio

Rejected

TCP, QUIC/MASQUE

When the rejected choice is right

QUIC/MASQUE wins when the deployment must traverse UDP-blocking middleboxes (§37 Alt 4).

Why: Avoids TCP-over-TCP collapse (P5).

ADR-07

Async runtime

Chosen

tokio multi-threaded

Rejected

async-std, manual epoll/io_uring

When the rejected choice is right

Raw io_uring wins past the >10 Gbps single-core tier (§38).

Why: Mature ecosystem; AsyncFd bridges raw TUN/UDP fds.

ADR-08

Concurrency model

Chosen

Per-peer mutex + hot-path atomics (P11)

Rejected

Global lock, fully lock-free

When the rejected choice is right

Fully lock-free peer state wins past ~100,000 peers/process.

Why: Global lock serializes unrelated peers; full lock-free isn't worth the complexity at ≤10,000 peers.

ADR-09

DoS mitigation

Chosen

Cookie-reply, 2-min secret rotation

Rejected

Rate-limiting-only, SYN-cookie-only

When the rejected choice is right

Rate-limiting-only wins behind a DDoS-scrubbing edge that already strips spoofed traffic.

Why: Rate-limiting can't distinguish spoofed from legitimate load; cookie binds source+ephemeral cheaply (I8).

ADR-10

Handshake pattern

Chosen

Noise_IKpsk2

Rejected

Noise XX, IK (no PSK), TLS 1.3 handshake

When the rejected choice is right

XX wins when peers don't share static keys out-of-band (first-contact/opportunistic encryption).

Why: 1-RTT + identity hiding + PSK-derived limited PQ resilience (§5 Papers, Perrin).

ADR-11

ECDH curve

Chosen

Curve25519

Rejected

NIST P-256, secp256k1

When the rejected choice is right

P-256 wins where FIPS 140-2 certification is a hard requirement.

Why: Constant-time-by-construction, no invalid-curve-point pitfalls (RFC 7748).

ADR-12

AEAD cipher

Chosen

ChaCha20-Poly1305

Rejected

AES-256-GCM

When the rejected choice is right

AES-256-GCM wins on server x86 with AES-NI (2-4x faster in software).

Why: Constant-time in software without AES-NI; uniform across ARM/embedded (RFC 8439).

ADR-13

Hash/KDF

Chosen

BLAKE2s + HKDF

Rejected

SHA-256 + HKDF, SHA-3

When the rejected choice is right

SHA-256 wins only if wire compatibility with WireGuard is not required.

Why: Spec-mandated for wire compatibility (RFC 7693, RFC 5869).

ADR-14

Crypto library

Chosen

ring + x25519-dalek

Rejected

OpenSSL FFI, pure RustCrypto only

When the rejected choice is right

OpenSSL FFI wins where FIPS-validated module status is contractually required.

Why: Audited constant-time guarantees without an unsafe FFI-to-C boundary.

ADR-15

Routing structure

Chosen

Longest-prefix binary trie

Rejected

Linear scan, hash map by exact CIDR

When the rejected choice is right

Linear scan wins under ~16 peers (single-peer embedded gateways).

Why: O(log n) lookup, natural longest-prefix semantics (P4, I13).

ADR-16

Replay window size

Chosen

2,048 bits

Rejected

64-bit (RFC 6479 minimum), 8,192-bit

When the rejected choice is right

64-bit wins on memory-constrained embedded targets.

Why: Spec-mandated; tolerates realistic reordering without excess memory.

ADR-17

Rekey schedule

Chosen

2min/2^60 msgs / 3min / 5min fixed

Rejected

Configurable rekey interval

When the rejected choice is right

A configurable interval wins in a closed single-vendor deployment tuned to one traffic pattern.

Why: Fixed constants avoid an interop-matrix explosion (P14).

ADR-18

TUN integration

Chosen

Userspace default (OS-specific)

Rejected

Kernel module only

When the rejected choice is right

Kernel-only wins when the deployment is Linux-only and performance dominates (original WireGuard's choice).

Why: Portability across Linux/macOS/Windows/BSD.

ADR-19

Kernel module

Chosen

Optional Rust-for-Linux module (§24)

Rejected

Mandatory kernel module, C kernel module

When the rejected choice is right

A C kernel module wins if Rust-for-Linux's crypto-API bindings aren't yet production-stable.

Why: Keeps the default path portable; avoids a second unsafe-C protocol implementation.

ADR-20

Config format

Chosen

wg-quick-style INI

Rejected

YAML, TOML, JSON

When the rejected choice is right

TOML wins for a greenfield deployment with no existing WireGuard config investment.

Why: Wire-compatible with existing wg/wg-quick tooling.

ADR-21

Observability

Chosen

tracing + structured logging

Rejected

log crate, syslog-only

When the rejected choice is right

Syslog-only wins on an embedded target where tracing's allocation overhead is unacceptable.

Why: Span-based tracing correlates one handshake/session across async tasks.

ADR-22

Testing strategy

Chosen

Differential + property + fuzz + conformance

Rejected

Unit-tests-only

When the rejected choice is right

Unit-tests-only wins for an isolated utility function with no protocol interaction.

Why: Protocol corner cases (P12, P13) are combinatorial.

ADR-23

CI/CD topology

Chosen

GitHub Actions matrix + interop containers

Rejected

Single-OS CI, self-hosted-only

When the rejected choice is right

Single-OS CI wins for an internal fork deployed to one Linux distribution only.

Why: Cross-platform TUN differences (§18) only surface per-OS.

ADR-24

Licensing

Chosen

Dual Apache-2.0/MIT

Rejected

GPL-2.0, proprietary

When the rejected choice is right

GPL-2.0 wins for the in-kernel module (§24) if it must link GPL-only kernel crypto APIs — the actual reason upstream WireGuard's kernel module is GPL-2.0.

Why: Permissive licensing matches the userspace-default deployment model.

Roads not taken (§37)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt 1 — IPsec/IKEv2 model (certificate-based, kernel policy database)

[App] → [Kernel SPD lookup] → [SAD (per-SA keys)] → [ESP encap] → [UDP/IP]
              ▲ policy pushed/negotiated via IKEv2 (cert or PSK auth)

Regime where it wins: multi-vendor enterprise interop requiring X.509 PKI and FIPS-certified cipher suites (Kaufman/Perlman/Speciner, §5). Real system: strongSwan / Linux native IPsec stack. Rejected here because the SPD/SAD split (MM3) creates the exact ACL-drift bug class P4 removes, and IKEv2's negotiated cipher suite reopens the downgrade-attack surface P1 closes.

Alt 2 — TLS-over-TCP/UDP overlay (OpenVPN model)

[App] → [TUN/TAP] → [TLS 1.3 record layer, negotiated cipher] → [TCP or UDP]

Regime where it wins: traversing networks that block raw UDP or shape WireGuard-looking traffic but permit generic HTTPS-shaped flows. Real system: OpenVPN. Rejected here: TCP mode reintroduces TCP-over-TCP collapse (P5); even UDP mode carries TLS's negotiation surface (P1) this design is built to avoid.

Alt 3 — Coordination-server + relay mesh (Tailscale model)

[Peer A] ←DERP relay (NAT-traversal fallback)→ [Peer B]
     ▲                                              ▲
     └──── coordination service (key distribution, ACL push) ────┘

Regime where it wins: zero-touch NAT traversal and centrally-managed ACLs across a large, frequently-changing fleet. Real system: Tailscale (built on the WireGuard data plane). Rejected here: introduces a centralized trust anchor and control-plane dependency this project's non-goals explicitly exclude (§1) in favor of self-contained, statically-configured peers (P10).

Alt 4 — QUIC/MASQUE-based tunnel

[App] → [CONNECT-IP session] → [QUIC (TLS 1.3 handshake, stream mux)] → [UDP/443]

Regime where it wins: enterprise networks that block non-QUIC UDP but explicitly permit QUIC on port 443. Real system: MASQUE-based VPN implementations (e.g., iCloud Private Relay's use of MASQUE). Rejected here: QUIC's handshake and congestion-control machinery add complexity and CPU cost that this design's 1-RTT, no-negotiation principles (P1, P6) are specifically built to avoid.
