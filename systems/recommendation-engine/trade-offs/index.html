Decisions (§9) · 24 ADRs

ADR-01

Primary candidate generator

Chosen

Implicit ALS (Hu-Koren-Volinsky 2008)

Rejected

BPR, Neural CF, item-item cosine, SLIM

When the rejected choice is right

BPR wins when pure ranking quality dominates and the squared-error popularity skew costs >2 NDCG pts (§16 ablation); item-item wins when near-zero training compute and item-cold-start coverage matter more than personalization depth

Why: Best NDCG-per-training-hour on implicit data; closed-form per-user solve parallelizes trivially (§15.2)

ADR-02

ANN index for online top-K

Chosen

HNSW (consumed library)

Rejected

IVF-PQ, flat brute-force, ScaNN, Faiss-IVF

When the rejected choice is right

IVF-PQ wins past ~100M items where HNSW's graph memory exceeds RAM budget; flat brute-force wins below ~10K items where index overhead exceeds scan cost

Why: HNSW gives sub-ms p99 at recall>0.95 for our catalog size (§4: ≤5M items, rank 64)

ADR-03

Primary ranker

Chosen

Logistic/FM ranker over RankFeatures

Rejected

Neural CF, DLRM, MMOE

When the rejected choice is right

Neural CF/DLRM win once categorical cardinality and interaction depth exceed what linear+FM terms capture, typically past 200+ categorical features (PhaseDeferred, §19)

Why: Matches team ML maturity progression and the v1 scope (§20); avoids embedding-table-sharding cost (§4)

ADR-04

Ranker progression order

Chosen

Neighborhood → ALS/BPR → FM ranker

Rejected

Skip straight to deep ranker

When the rejected choice is right

Skipping wins when the team already has deep-ranker operational experience and the catalog is large enough that linear/FM ranking is known insufficient from prior systems

Why: Each phase isolates one complexity source; team learns calibration before architecture (§13-§20)

ADR-05

Training/orchestration language

Chosen

Python 3.11

Rejected

Scala/JVM, C++, Go

When the rejected choice is right

Scala/JVM wins once distributed multi-node training is required (PhaseDeferred, §15); C++ wins past the throughput ceiling in §29

Why: Fastest iteration loop; every reference impl (§5) is Python-first (§1)

ADR-06

Serving hot-path implementation

Chosen

NumPy/BLAS-vectorized Python + compiled kernel

Rejected

Pure Python loops, Rust/C++ rewrite

When the rejected choice is right

A Rust/C++ rewrite wins once serving QPS crosses the single-process throughput ceiling documented in §29

Why: Meets the p99 budget (§4) without a second language for a single-team learning build (§1)

ADR-07

Offline rebuild cadence

Chosen

Nightly full rebuild

Rejected

Hourly, weekly, fully online

When the rejected choice is right

Hourly wins for fast-moving inventories (e.g., flash-sale e-commerce) where item relevance decays within hours

Why: Nightly catches behavioral drift the (deferred) streaming path would miss; fits a 2-hr maintenance window (§4)

ADR-08

Feedback model support

Chosen

Both implicit and explicit paths (§14, §15)

Rejected

Implicit-only, explicit-only

When the rejected choice is right

Implicit-only wins when the product has no rating UI at all and maintaining the explicit path is pure overhead

Why: Production datasets are usually implicit-dominant but ml-25m and many catalogs still carry explicit ratings worth modeling directly (P3)

ADR-09

Candidate-gen loss function

Chosen

Confidence-weighted squared error (implicit ALS)

Rejected

BPR pairwise log-loss, sampled softmax

When the rejected choice is right

BPR wins when offline NDCG@10 gain from §16's ablation exceeds 2 points on the target dataset

Why: Has the closed-form solve (§15.2); BPR retained as Phase 4 alternative for ranking-metric optimization

ADR-10

Ranker loss function

Chosen

Log-loss (calibratable)

Rejected

Squared error, hinge, pairwise

When the rejected choice is right

Pairwise loss wins when the deploy gate is purely rank-order quality and calibrated probabilities are not consumed downstream

Why: Log-loss is calibrated (I10) and composes cleanly with popularity-bias reweighting (§20)

ADR-11

Negative sampling strategy

Chosen

Popularity-corrected (^0.75 power)

Rejected

Pure uniform, pure popularity

When the rejected choice is right

Pure uniform wins when the catalog has near-uniform popularity (rare, but true for some curated catalogs)

Why: Pure uniform under-trains tail items; pure popularity over-corrects (§16.2, P6)

ADR-12

Score calibration

Chosen

Isotonic regression on validation slice

Rejected

Platt scaling, no calibration

When the rejected choice is right

Platt scaling wins with very small validation slices (<10K examples) where isotonic overfits the step function

Why: Non-parametric, beats Platt on long-tailed score distributions (I10)

ADR-13

Diversity reranking

Chosen

MMR (greedy, cosine similarity)

Rejected

DPP, no diversification

When the rejected choice is right

DPP wins once the relevance-diversity Pareto frontier from MMR plateaus in a documented A/B test

Why: Greedy, deterministic, explainable (P7); DPP deferred (§20, PhaseDeferred anchor §20)

ADR-14

Exploration policy

Chosen

Thompson sampling (Beta-Bernoulli)

Rejected

UCB1, epsilon-greedy, none

When the rejected choice is right

UCB1 wins when a deterministic, auditable exploration bonus is required for regulatory/explainability reasons

Why: Bayes-optimal under the Beta prior; empirically beats UCB on most production benchmarks (§20)

ADR-15

Primary offline metric

Chosen

NDCG@10 on chronological holdout

Rejected

MRR, Recall@K alone, MAP alone, AUC alone

When the rejected choice is right

MRR wins when only the first relevant item's position matters (e.g., a single-answer QA-style surface)

Why: Rank-aware and standard in the literature (§17); we also report Recall@50 and MAP@10 (P4)

ADR-16

Position-bias correction

Chosen

IPS with propensities from a 1% randomized slice

Rejected

EM-based correction, no correction

When the rejected choice is right

EM-based correction wins when randomized traffic is organizationally impossible to obtain

Why: IPS is unbiased when propensities are known; 1% traffic cost is acceptable (§4, §17)

ADR-17

Cold-start strategy

Chosen

Content fallback + Bayesian-shrinkage bridge

Rejected

Popularity-only, hand-coded rules, always-bandit

When the rejected choice is right

Popularity-only wins when content features are unavailable or unreliable at signup time

Why: Gives a relevant first impression and a smooth transition (§18, P5)

ADR-18

Sequential/session modeling

Chosen

Out of scope for v1 (PhaseDeferred, §8)

Rejected

Adopt SASRec/BERT4Rec as primary

When the rejected choice is right

SASRec/BERT4Rec win once the product surface is fundamentally session-based (e.g., a single continuous feed)

Why: v1 targets general recsys, not session-heavy domains; revisit at avg session length > 5 (§35)

ADR-19

Feature store

Chosen

Redis (online) + Parquet (offline)

Rejected

Feast, Tecton, Hopsworks, in-process only

When the rejected choice is right

A managed feature store wins once feature reuse spans more than this one model family across a larger ML org

Why: Simple and fast at v1 scale; managed feature stores add operational cost not yet justified (§4)

ADR-20

Training data format

Chosen

Parquet, partitioned by date, sorted by (user_id, ts)

Rejected

CSV, TFRecord, Arrow IPC

When the rejected choice is right

TFRecord wins when the downstream consumer is exclusively a TensorFlow training pipeline needing sharded reads

Why: Columnar compression, partition pruning, de facto industry standard (§11.1)

ADR-21

Model artifact format

Chosen

Tarball: factors + ranker + index + meta

Rejected

ONNX, TorchScript, MLflow, custom proto

When the rejected choice is right

ONNX wins once the ranker is a deep network that benefits from a standardized cross-runtime inference format (§19 deferred)

Why: Debuggable, language-agnostic, forces an explicit schema (§11.11)

ADR-22

Serving RPC

Chosen

gRPC with proto3 schema

Rejected

REST/JSON, GraphQL, Thrift

When the rejected choice is right

REST/JSON wins for a low-QPS internal debug/admin surface where typed codegen overhead is not worth it

Why: Typed schema, streaming support, language bindings (§21)

ADR-23

A/B traffic splitting

Chosen

Deterministic hash of user_id mod 100

Rejected

Random per-request, sticky cookie

When the rejected choice is right

Sticky cookie wins for fully anonymous, cookie-only surfaces with no stable user id at all

Why: Ensures the same user sees the same model across sessions (I11); cookie-based fails logged-out/mobile

ADR-24

Rollback mechanism

Chosen

Config flip of active_model_version, 1-min TTL

Rejected

Blue-green redeploy, process restart, kill switch

When the rejected choice is right

Blue-green redeploy wins when the rollback also needs to revert serving-code changes, not just the model artifact

Why: Fastest option; leaves both model versions warm in memory (P11, RTO in §4)

34. Alternative Architectures (Roads Not Taken)

AA1 — Pure content-based, no collaborative signal.

 [item content features]--->[similarity engine]--->[per-user profile of liked content]--->[top-N]
                                                              ^
                                                    [explicit/implicit history]

Regime where it wins: an extremely sparse or brand-new catalog where collaborative signal barely exists yet (a B2B SaaS marketplace at launch). Real system: the original Pandora Music Genome Project (hand-annotated content features driving similarity, no collaborative signal at all). Rejected here because the target domain (§1) has enough interaction volume (§4) that collaborative signal is the stronger predictor once past the cold-start window (§18), and pure content-based recommendation cannot exploit the confidence-weighted implicit signal this blueprint centers on (P3).

AA2 — Fully online, no batch training.

 [click stream]-->[online learner: per-event gradient step]-->[live factors]-->[serving]
                                                                     ^
                                                       (no nightly batch rebuild at all)

Regime where it wins: a continuously evolving catalog/user base at massive scale where nightly batch latency (§4, ADR-07) is itself unacceptable staleness. Real system: TikTok's Monolith architecture (large-scale online learning with no batch-primary training path). Rejected here because it requires the streaming-join and online-learning infrastructure this blueprint deliberately defers (PhaseDeferred("§21"), §35) — the engineering cost is not justified at the target scale in §4, and the nightly-rebuild cadence (ADR-07) is sufficient for the target staleness tolerance.

AA3 — Graph-based random-walk recommendation.

 [bipartite user-item graph]-->[random walk with restart]-->[visit-frequency ranking]-->[top-N]

Regime where it wins: when rich graph structure beyond simple interactions exists (social connections, board/collection structure) and the walk can exploit second- and third-order relationships. Real system: Pinterest's Pixie/PinnerSage (random walks over the pin-board bipartite graph). Rejected here because the domain as scoped (§1) has no social or collection graph beyond the user-item interaction matrix itself — building the graph-walk machinery would duplicate what matrix factorization already captures from the same data, at higher serving cost.

AA4 — Explicit-only regression, no implicit path.

 [explicit ratings only]-->[biased-ALS RMSE minimization]-->[predicted rating]-->[rank by predicted rating]

Regime where it wins: a domain with only explicit ratings and genuinely no implicit signal at all (a legacy movie-rating site with no click/view logging). Real system: the original Netflix Prize competition harness itself (explicit ratings only, RMSE as the sole target). Rejected as the primary path here (though retained as Phase 2, §14) because ADR-08 documents that 95%+ of production interaction data is implicit-dominant, and an explicit-only system cannot exploit the confidence-weighting mechanism (§8.2) that this blueprint's primary candidate generator (ADR-01) depends on.
