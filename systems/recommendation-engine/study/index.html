30. Mental Models & First Principles

MM1. A recommendation is a bet under uncertainty, not a fact. Every score is a point estimate with hidden variance; treating it as ground truth (rather than a posterior to be explored, §20) produces the pure-exploit collapse described in T7. Predicts: any system with no exploration term eventually narrows its own training distribution. Bug class without it: engineers "fix" a stale recommender by retraining more often, which does nothing, because the data itself has collapsed. Applied in §20 (Thompson sampling as the ranker's decision rule, not a bolt-on).

MM2. Sparsity is the whole game. Every design decision in this blueprint — CSR storage (§8.1), the ALS closed-form trick (§8.4), the co-rating floor (§13.6), the ANN index (§19) — exists because the interaction matrix is >99.7% empty (§4). Predicts: any algorithm whose cost scales with dense dimensions (n_users * n_items) is wrong for this problem by construction. Bug class without it: reaching for a dense-matrix library call that silently allocates 10GB for a 200MB problem. Applied in §8.1, §15.2.

MM3. Offline metrics measure agreement with a biased policy, not truth. Logged data only contains what a previous policy chose to show; a new policy is evaluated on a distribution shift from its own perspective. Predicts: an offline NDCG win does not guarantee an online win, and can even correlate negatively when the metric rewards agreement with the old policy's blind spots. Bug class without it: shipping on offline metrics alone and being surprised by an A/B loss. Applied in §17 (IPS/replay), P3, P10.

MM4. A trained factor is a compressed history, and compression forgets deliberately. Regularization (I5) is not noise-reduction incidental to the math; it is the explicit choice of how much individual-user idiosyncrasy to discard in favor of population-level structure. Predicts: too little regularization overfits sparse users' single ratings; too much erases genuine personalization. Bug class without it: tuning lambda by "what number felt reasonable" instead of by measured density (P9). Applied in §14.2, §15.2.

MM5. Two-stage retrieval trades recall for latency, and the trade is measured, not assumed. Candidate generation (§19) accepts a bounded recall loss (I8's 0.95 floor, not 1.0) in exchange for sub-millisecond query time; the ranker (§20) then recovers precision within the surviving candidates. Predicts: any attempt to push candidate-set size to zero-recall-loss defeats the latency purpose of having two stages at all. Bug class without it: endlessly widening the ANN candidate count "to be safe," destroying the latency budget it was built to protect. Applied in §19.6, P1, P8.

MM6. A feedback loop is a system training on its own opinions. Once a ranker's own output shapes what data it gets to learn from next (T7), the system is no longer a pure supervised learner — it is closer to a reinforcement-learning problem wearing supervised-learning clothes. Predicts: metrics can look stable while the underlying exposure distribution silently narrows. Bug class without it: monitoring aggregate CTR (which can stay flat) while catalog coverage collapses (§20.5's headcount gate exists to catch exactly this). Applied in §20, T7, P6.

MM7. Calibration and ranking are different properties of a score. A score can rank candidates correctly (high AUC) while being wildly wrong as a probability (miscalibrated) — and popularity- bias correction, cross-model comparison, and A/B deploy gates all depend on the probability being trustworthy, not just the order (I10). Predicts: a model that "looks great" on AUC can still break reranking logic that assumes calibrated inputs. Bug class without it: applying MMR's relevance-diversity tradeoff on an uncalibrated score, producing an unpredictable diversity effect. Applied in §20.2, ADR-12.

MM8. Every artifact needs a provenance trail or the system cannot explain or undo itself. TrainMeta (§11.10), trace_id (I7), and content-hashing (I12) exist together because explainability (P12), rollback (P11), and forensics (§23) are the same underlying requirement: given a served recommendation, reconstruct exactly which model, which candidates, and which score produced it. Predicts: a system without this trail cannot debug a single bad recommendation, let alone roll back a bad deploy in minutes. Bug class without it: an incident where nobody can say which model version served a given user an hour ago. Applied in §11.10, §21.2, §24.

Glossary (§36) · 55 terms · site-wide glossary

ALS (Alternating Least Squares)
matrix-factorization training method alternating closed-form solves for user factors and item factors while holding the other fixed (§8.4, §14, §15).
A/B testing
randomized online comparison of two model versions on live traffic, the deploy gate per P10 (§21).
Adjusted cosine similarity
item-item cosine computed after centering each rating by its user's mean rating, correcting for per-user rating-scale bias (§8.3).
ANN (Approximate Nearest Neighbor)
a search structure (here, HNSW) trading a small recall loss for large latency gains versus brute-force search (§19).
Bandit (multi-armed)
an online decision framework balancing exploration and exploitation; here, Thompson sampling over a Beta-Bernoulli CTR posterior (§20).
Bias term (bu, bi)
per-user and per-item additive offsets in explicit-ALS, capturing rating tendencies independent of latent factors (§8.4, §14).
Bootstrap confidence interval
a resampling-based uncertainty estimate on a metric, used throughout §17's evaluation reports (P4).
BPR (Bayesian Personalized Ranking)
a pairwise ranking loss for implicit feedback (Rendle et al. 2009), the SGD-trained alternative to ALS (§8.5, §16).
Calibration
the property that a predicted probability matches observed frequency; enforced via isotonic regression (I10, ADR-12).
Candidate generation
the first serving stage: cheaply retrieving a bounded set of plausible items before ranking (§19, P1).
Chronological split
a train/test split by timestamp rather than random assignment, preventing future-information leakage (P2, I2).
Cholesky factorization
the matrix decomposition used to solve the per-user/per-item ALS linear system, requiring the matrix be positive-definite (I5, §8.4).
Cold start
the problem of recommending to users or items with little or no interaction history (§8.7, §18).
Collaborative filtering
predicting preference from patterns across many users' behavior, without relying on item content (§8.3, §13).
Confidence weighting
the c_ui = 1 + alpha*r_ui transform converting implicit signal strength into a per-observation training weight (Hu-Koren-Volinsky 2008, §8.2).
Content-based filtering
recommending based on item attributes (text, image, category) rather than collaborative signal (§18).
Counterfactual evaluation
estimating what a different policy would have done using logged data from the deployed policy, via replay or IPS (§17, P3).
Coverage
the fraction of the catalog ever surfaced by the recommender across users (§11.11).
CSR (Compressed Sparse Row)
the sparse matrix storage layout used for the interaction matrix (§8.1, §11.3).
Diversity (intra-list)
a measure of how dissimilar the items within one recommended list are to each other, traded against relevance by MMR (§20, P7).
Explicit feedback
a directly stated preference signal, typically a star rating (§8.2).
Feedback loop
the phenomenon where a model's own served output shapes the data it is next trained on, risking self-reinforcing bias (T7, MM6).
Global mean
the average rating across the entire training set, the baseline term in explicit-ALS (§8.4, §11.4).
HNSW (Hierarchical Navigable Small World)
the graph-based ANN index algorithm used for candidate retrieval (Malkov-Yashunin 2018, §19).
Hybrid recommender
a system combining collaborative and content-based signals, as in the cold-start bridge (§18).
Implicit feedback
an indirect preference signal inferred from behavior (clicks, plays, purchases) with no negative label (§8.2).
Inverse propensity scoring (IPS)
reweighting logged data by the inverse probability of the observed action, correcting for position/selection bias (§17.2, P3, ADR-16).
Isotonic regression
a non-parametric monotonic calibration method used to map raw ranker scores to calibrated probabilities (ADR-12, I10).
Item-based collaborative filtering
CF predicting from item-item similarity rather than user-user similarity (Sarwar et al. 2001, §8.3, §13).
Jaccard similarity
set-overlap similarity metric, |A∩B|/|A∪B|, ignoring rating magnitude (§8.3).
Latent factor
a learned low-dimensional vector representing a user or item in matrix factorization (§8.4, §11.4).
MAP@k (Mean Average Precision at k)
the mean, across users, of average precision computed over the top-k recommended list (§17.2).
Matrix factorization
approximating the interaction matrix as the product of two low-rank factor matrices (§8.4).
MMR (Maximal Marginal Relevance)
a greedy diversity-reranking algorithm trading relevance for dissimilarity from already-selected items (Carbonell-Goldstein 1998, §20, ADR-13).
Model artifact
the versioned, deployable bundle of factors, ranker, index, and provenance metadata (§11.10).
NDCG@k (Normalized Discounted Cumulative Gain)
a rank-aware ranking-quality metric normalized against the ideal ordering (§17.2).
Negative sampling
drawing unobserved (or non-positive) items during training to contrast against observed positives, with popularity correction to counter bias (§16.2, ADR-11, P6).
Neighborhood method
a family of CF algorithms (user-based, item-based) predicting from similarity-weighted neighbor ratings, without learning latent factors (§8.3, §13).
Pearson correlation
mean-centered cosine similarity, correcting for user rating-scale offset (§8.3).
Popularity bias
the tendency of click-trained systems to over-recommend already-popular items, addressed via sampling correction, reranking, and exploration (P6, T7, §20).
Position bias
the confound where higher-ranked slots receive more clicks regardless of true relevance, corrected via IPS (§17, ADR-16).
Precision@k
the fraction of the top-k recommended items that are relevant (§17.2).
Propensity
the probability that a given slot/position would be examined, estimated from a randomized traffic slice for IPS correction (§17.2, ADR-16).
Rank (latent dimension)
the dimensionality of the learned factor vectors (§11.5, §4).
Ranker
the second serving stage, scoring the candidate set with a richer feature vector than any single retriever (§20, P1).
Recall@k
the fraction of all relevant items that appear in the top-k recommended list (§17.2).
Regularization
the L2 penalty term (lambda) preventing overfitting in ALS/BPR, tuned to matrix sparsity (P9, I5).
Reranking
post-processing the ranker's scored list for diversity, freshness, or business rules before the final response (§20).
RMSE (Root Mean Squared Error)
the accuracy metric for explicit-rating prediction (§17.2, §14).
Sparsity/density
the fraction of the interaction matrix that is observed; the defining property shaping every algorithmic choice in this blueprint (§4, MM2, §32 item 1).
Thompson sampling
a Bayesian exploration policy sampling from a posterior (here, Beta) to balance exploring uncertain items against exploiting known-good ones (§20, ADR-14).
Trace ID
the identifier linking a served recommendation through impression, click-join, and counterfactual replay for explainability and forensics (I7, P12).
Train/test leakage
contamination of the evaluation set with information unavailable at prediction time, most commonly from a random (non-chronological) split (P2, §13.6-adjacent).
Two-stage retrieval
the candidate-generation-then-ranking architecture pattern underlying the whole serving path (P1, §3).
User-based collaborative filtering
CF predicting from similarity between users' rating patterns (§8.3, §13). ---
