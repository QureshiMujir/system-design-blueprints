Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — Polyhedral-First Compiler

graph --> polyhedral model (iteration domains + schedule map) --> direct codegen
          (no separate heuristic tile-planner stage)

Regime where it wins: dense affine loop nests with regular access patterns — classical HPC kernels with no data-dependent control flow. Real system: Tensor Comprehensions (Vasilache et al. 2018, §5) and Tiramisu take this approach as their primary compilation strategy, not just a Phase-6 technique. Why this blueprint rejects it as the whole architecture: polyhedral model construction and scheduling scale poorly on irregular, control-flow-heavy ML graphs (attention with data-dependent masking, dynamic shapes) that dominate this project's target workloads; polyhedral techniques are retained as one tile-planner input (§18.2), not the compiler's spine.

Alt B — Interpreted / Bytecode Execution

graph --> bytecode VM --> dispatch loop interprets ops directly
          (no LLVM/PTX codegen stage at all)

Regime where it wins: rapid iteration and debugging where compile latency must be near-zero and peak throughput is secondary. Real system: ONNX Runtime's default CPU execution provider (interpreted op-kernel dispatch). Why rejected: interpretation overhead per op would violate the §4 runtime-dispatch p95 20 µs target at the scale of this project's target workloads (GEMM/conv/ attention benchmarks, §28); native codegen is required to hit the occupancy and throughput targets in §28's M6/M8.

Alt C — Single-IR-Layer Design

graph IR (with SSA-like def/use annotations bolted on)
   --> backend lowering directly
       (no distinct Tensor SSA IR stage)

Regime where it wins: a small, fixed backend set where dominance/effect tracking overhead isn't worth a second IR layer. Real system: Glow (pytorch/glow) goes straight from its single graph IR to backend lowering. Why rejected: I1 (dominance) and I3 (alias safety) need an explicit, independently-checkable SSA layer (§7); collapsing the layers would make the Phase 2 verifier (§14) inseparable from Phase 1's frontend trust-boundary logic, weakening the P7 fail-closed guarantee this project treats as non-negotiable.
