30. Mental Models & First Principles

  • MM1 — Schedule Is Not Algorithm. Numerical semantics and execution strategy are orthogonal axes; predicts a fusion/tiling bug should never change results, only speed; without it: a correctness regression gets triaged as a performance regression; applies in §18.
  • MM2 — Determinism Is a Debugging Multiplier. A deterministic pipeline turns every bug into a replayable, bisectable artifact; predicts nondeterminism compounds — one unordered iteration poisons every downstream replay; without it: "worked on retry" bugs that never get root-caused; applies in §21.
  • MM3 — Alias Safety Is a Memory-Planning Property, Not a Type-System Property. Rust's borrow checker cannot see across the arena/IR boundary; predicts a memory-safe language does not imply an alias-safe compiler; without it: silent numerical corruption mistaken for a training instability; applies in §17.
  • MM4 — Cost Models Must Be Measured, Never Assumed. A heuristic that looks correct on paper can regress real hardware; predicts any unmeasured heuristic eventually regresses a real workload; without it: a "principled" tile-size formula ships slower than the naive default; applies in §18 and §28.
  • MM5 — Fail-Closed Beats Fail-Soft in a Compiler. A compiler's job is to refuse ambiguity, not resolve it silently; predicts every "helpful" default eventually produces a silently wrong artifact; without it: a compiler that "just works" on malformed input until it produces a wrong number; applies in §15 and §16.
  • MM6 — Immutable Artifacts Turn Caching Into a Correctness Tool. Content-addressing collapses "is this the same build" into a hash comparison; predicts any artifact-store mutation bug reintroduces every caching bug this design prevents; without it: stale-artifact-served-as-fresh incidents; applies in §20 and §27.
  • MM7 — Occupancy Is a Consequence, Not a Target. Occupancy is a downstream measurement of register pressure, shared-memory use, and divergence; predicts chasing occupancy in isolation produces an "occupied" but not faster kernel; without it: block-size tuning that looks good on the occupancy dashboard while wall-clock throughput stays flat; applies in §20.
  • MM8 — A Verifier Is Cheaper Than a Postmortem. Every invariant check added before a phase ships is orders of magnitude cheaper than reconstructing the same violation from an incident; predicts skipping a verifier pass to hit a deadline always costs more later; without it: a violation surfaces phases downstream as an unrelated-looking crash; applies in §14 and §21.

5. Required Reading

Books

  • Engineering a Compiler — Cooper & Torczon (2011, 2nd ed.), ch. on SSA construction, optimization passes, dependence analysis: canonical pass-ordering and IR-mutation discipline; applied in §14 and §16.
  • Compilers: Principles, Techniques, and Tools — Aho, Lam, Sethi & Ullman (2006, 2nd ed.), ch. on parsing, dataflow analysis, code generation: classical CFG-transformation foundations; applied in §13 and §19.
  • Computer Architecture: A Quantitative Approach — Hennessy & Patterson (2017, 6th ed.), ch. on cache hierarchies, SIMD execution, memory bandwidth: the arithmetic behind tile/vector-width choices; applied in §18 and §28.
  • Programming Massively Parallel Processors — Kirk & Hwu (2016, 3rd ed.), ch. on GPU execution model, occupancy, memory coalescing: the occupancy math behind the launch-config planner; applied in §20.
  • Linkers and Loaders — John R. Levine (1999), ch. on relocation, symbol management, object formats: the ELF-emission discipline for the CPU backend; applied in §19.
  • Systems Performance — Brendan Gregg (2020, 2nd ed.), ch. on profiling, tracing, performance bottlenecks: the profiling methodology reused directly; applied in §21 and §28.
  • Designing Machine Learning Systems: An Iterative Process for Production-Ready Applications — Chip Huyen (2022, O'Reilly), ch. on inference systems and deployment architectures: the deployment-model assumptions behind the runtime executor; applied in §20 and §24.

Papers

  • "TVM: An Automated End-to-End Optimizing Compiler for Deep Learning" — Chen et al., 2018, OSDI: schedule abstraction decoupled from compute definition → shapes SchedulerPlan (§11); applied in §18.
  • "Halide: A Language and Compiler for Optimizing Parallelism, Locality, and Recomputation in Image Processing Pipelines" — Ragan-Kelley et al., 2013, PLDI: schedule/algorithm separation → the reason schedule metadata lives outside op semantics; applied in §14 and §18.
  • "MLIR: A Compiler Infrastructure for the End of Moore's Law" — Lattner et al., 2021, CGO: extensible dialect-layered IR → the Graph-IR/SSA-IR layering boundary; applied in §13 and §14.
  • "Weld: A Common Runtime for High Performance Data Analytics" — Palkar et al., 2017, CIDR: cross-library fusion through a shared IR → the fusion-planner cost model; applied in §16.
  • "Tensor Comprehensions: Framework-Agnostic High-Performance Machine Learning Abstractions" — Vasilache et al., 2018, arXiv: polyhedral scheduling of tensor ops → the tile-planner's loop-nest strategy; applied in §18.
  • "The Tensor Algebra Compiler" — Kjolstad et al., 2017, OOPSLA: sparse-iteration-space compilation → informs iteration-space/alias reasoning in the memory planner; applied in §17.
  • "Relay: A New IR for Machine Learning Frameworks" — Roesch et al., 2018, MAPL: a functional graph IR with first-class control flow → the operation-purity metadata on GraphNode; applied in §13.
  • "Ansor: Generating High-Performance Tensor Programs for Deep Learning" — Zheng et al., 2020, OSDI: search-based schedule autotuning → the exact capability this blueprint defers, PhaseDeferred("§18"); applied in §18.
  • "Polly — Performing Polyhedral Optimizations on a Low-Level Intermediate Representation" — Grosser, Größlinger & Lengauer, 2012, Parallel Processing Letters: polyhedral loop transformation on LLVM IR → informs CPU loop-nest lowering; applied in §19.

Reference Implementations

  • llvm/llvm-project — study llvm/lib/IR/, llvm/lib/Transforms/, llvm/lib/CodeGen/: pass infrastructure and IR-ownership discipline; pitfall: do not copy LLVM's mutable-in-place IR model wholesale; applied in §14 and §19.
  • apache/tvm — study src/tir/, src/relay/, src/runtime/: two-level Relay→TIR lowering; pitfall: do not adopt TVM's Python-first scheduling DSL as the primary interface; applied in §16 and §18.
  • openxla/xla — study xla/service/, xla/hlo/: HLO-level algebraic simplification and fusion heuristics; pitfall: do not port XLA's whole-program buffer-assignment pass verbatim; applied in §16 and §17.
  • llvm/llvm-project (mlir) — study mlir/lib/IR/, mlir/lib/Pass/: dialect-layered IR and nested pass-manager scoping; pitfall: do not import MLIR's ODS/TableGen op-definition machinery; applied in §13 and §14.
  • pytorch/glow — study lib/Graph/, lib/Backend/: graph-level backend abstraction boundary; pitfall: do not copy Glow's ahead-of-time-only execution model; applied in §19 and §20.
  • halide/Halide — study src/Lower.cpp, src/CodeGen_LLVM.cpp: schedule/algorithm separation enforced at the IR level; pitfall: never let scheduling directives leak into SSA op definitions; applied in §18.

RFCs / Specifications

  • ONNX IR Specification — pins down operator schemas, tensor shape/type metadata, and graph serialization used by the frontend importer; applied in §13.
  • StableHLO Specification — pins down the HLO-dialect op set and shape-inference contracts the StableHLO importer conforms to; applied in §13.
  • LLVM Language Reference Manual — pins down IR well-formedness, calling conventions, and intrinsic signatures consumed by the CPU backend; applied in §19.
  • PTX ISA Specification — pins down the instruction set, memory-space model, and synchronization primitives the CUDA backend emits against; applied in §20.
  • DWARF Debugging Information Format — pins down the debug-map encoding preserved through object emission for postmortem symbol resolution; applied in §19.
  • WebAssembly SIMD Proposal — pins down the vector-lane width and instruction subset available to the experimental WASM backend; applied in §19.

Glossary (§36) · 45 terms · site-wide glossary

SSA
Static Single Assignment; every value is defined exactly once, enabling dominance- based correctness reasoning.
Dominance
CFG property: block A dominates block B if every path to B passes through A; governs SSA use validity (I1).
Fusion
combining adjacent kernels into one executable unit to eliminate intermediate materialization.
Tiling
partitioning a computation into cache- or register-sized blocks for locality.
Vectorization
SIMD transformation mapping scalar loop iterations onto vector lanes.
Occupancy
ratio of active GPU warps to the hardware maximum on a given multiprocessor.
Warp Divergence
GPU threads within a warp taking different execution paths, serializing otherwise-parallel work.
Alias Analysis
determining whether two memory references may overlap.
Interference Graph
graph whose edges mark buffers with overlapping lifetimes, used for allocation packing.
Spill
moving a value out of a fast storage tier (register/cache) to a slower one under pressure.
Replay Log
deterministic, append-only record of every transformation applied to an IR.
Shape Inference
deducing tensor dimensions, including resolving symbolic bindings.
Lowering
transforming a higher-level IR into a lower-level, more execution-oriented one.
Canonicalization
normalizing semantically equivalent IR into one stable form.
CFG
Control Flow Graph.
CSE
Common Subexpression Elimination.
DCE
Dead Code (Op) Elimination.
NUMA
Non-Uniform Memory Access; memory latency depends on which CPU socket issues the access.
ABI
Application Binary Interface; the calling-convention and layout contract between compiled units.
PTX
NVIDIA's intermediate GPU instruction set architecture, target of the CUDA backend.
HSACO
the compiled binary object format produced by the ROCm/HIP toolchain.
IR
Intermediate Representation.
HLO
High-Level Operations, XLA's graph-level IR.
Broadcast
implicit shape expansion rule for elementwise ops on mismatched-rank tensors.
Content Addressing
identifying an artifact by the hash of its contents rather than a mutable name/path.
Arena Allocator
a bump/pool allocator that owns a batch of same-lifetime objects together.
Bank Conflict
multiple GPU threads accessing the same shared-memory bank in one cycle, serializing the access.
Register Pressure
the degree to which live values exceed available hardware registers.
Backpressure
an explicit bounded-queue rejection/slow-down signal preventing unbounded buildup.
Structured Concurrency
a concurrency discipline where every task's lifetime is scoped to its spawning context.
Crash-Only Software
components designed to recover solely via restart, never in-place repair.
BLAKE3
the cryptographic hash function used for content-addressing artifacts (ADR-27).
FlatBuffers
the zero-copy binary serialization format used for artifact bundles (ADR-05).
Sigstore
a keyless code-signing infrastructure backed by a public transparency log (ADR-17).
SBOM
Software Bill of Materials; a manifest of every dependency in a build.
Soak Test
a long-duration (72-hour) continuous workload run to surface rare/slow failures.
Differential Testing
comparing two independent implementations' outputs on the same input to detect divergence.
Property Testing
generating randomized inputs to check a general property rather than a fixed example.
Polyhedral Model
a mathematical (integer linear programming) representation of loop iteration spaces used for scheduling transformations.
Grid/Block Dimensions
the GPU kernel launch-configuration parameters controlling thread and thread-block counts.
Shared Memory
fast, on-chip, block-scoped GPU memory explicitly managed by the kernel.
HIP
AMD's CUDA-source-portable GPU programming model, target of the ROCm backend.
DWARF
a standard debugging-information format encoding source-line and symbol data.
ELF
Executable and Linkable Format, the object/executable file format on Linux targets.
Ring Buffer
a fixed-capacity circular buffer used here to bound replay-log retention.
