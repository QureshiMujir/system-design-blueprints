⬜ Phase 0 — Skeleton, Ray/Sphere Intersection, PPM Output and CI §12

Objectives

Stand up the crate workspace (§10), the Vec3/Point3/Ray/Sphere types (§11), a linear-scan scene of spheres, a pinhole camera producing one ray per pixel with no jitter, and a PPM writer. Stand up CI (ci.yml) running build + unit tests on every push. This is the tinyraytracer-style skeleton (§5 Reference Implementations) before any acceleration or shading exists.

Deliverable

A raytracer-cli binary that renders a fixed 3-sphere scene at 400×300 to output.ppm, and a green CI run on the initial commit.

Acceptance
  • cargo test passes with zero failures; cargo clippy -- -D warnings emits zero warnings.
  • Rendered image matches conformance/references/phase0_three_spheres.ppm pixel-for-pixel (bit-exact; no sampling noise exists yet at 1 ray/pixel, I9).
  • Render of a 400×300 image completes in < 200 ms on a single core (establishes the Phase 0 floor for M1 in §30).
  • Sphere intersection matches the analytic quadratic root to within 1e-5 relative error on 10 hand-computed test rays.
Fixtures
  • phase0_three_spheres.json — three spheres, flat albedo, no lighting; expected output phase0_three_spheres.ppm (bit-exact).
  • phase0_single_sphere_centered.json — degenerate single-sphere case, camera looking directly at the center; expected: a perfect circle, radius matches atan(r/d) projection to within half a pixel.
  • phase0_miss_all.json — camera facing away from all geometry; expected: solid background color, zero variance.
Pitfalls
  • Image-space y (top-down) vs. world-space y (up) confusion — flip in Camera::generate_ray, not ad hoc in the writer.
  • Forgetting t_min entirely produces self-intersection once bounces exist later; bake the field into Ray now even though it is always 0.0 in Phase 0.
  • PPM header formatting off-by-one (magic number, whitespace) silently produces a file every viewer rejects; test against a hex diff of the fixture, not visual inspection alone.

⬜ Phase 1 — Camera, Film and the Tile Scheduler §13

Objectives

Replace the one-ray-per-pixel Phase 0 camera with a Film that accumulates multiple jittered samples per pixel, and a Tile Scheduler that partitions the film and parallelizes across rayon (ADR-19, P14). Introduce the thin-lens parameter stub (full depth-of-field lands in Phase 10) and per-thread Sampler ownership (P12).

Deliverable

Multi-sample-per-pixel rendering of the Phase 0 scene at configurable spp, parallel across all cores, written to PPM, with measured near-linear core scaling.

Acceptance
  • 16 spp render of phase0_three_spheres scene is pixel-identical in expectation (RMSE < 0.5% vs. the Phase 0 bit-exact 1-spp fixture on flat-albedo regions with no antialiasing-sensitive edges) and shows measurable antialiasing at sphere silhouettes.
  • Parallel render on 8 cores completes in ≤ 1.5× the ideal 8× speedup floor (i.e., ≥ 5.3× measured speedup vs. single-core; accounts for scheduling overhead, M4 in §30).
  • Fixed seed + fixed thread count reproduces a bit-identical image across two runs (I9).
  • No data race reported by a loom-style concurrency test over the tile-to-film write path (I13).
Fixtures
  • phase1_aa_edge.json — a single sphere at 16 spp; expected: measurable per-pixel variance reduction at the silhouette vs. 1 spp, quantified as a ≥ 4× reduction in edge-pixel variance.
  • phase1_seeded_replay.json — fixed seed, 4 threads; two consecutive renders diffed bit-exact (I9).
  • phase1_tile_boundary.json — a scene sized to leave a partial tile at the image edge (e.g. 401×301 with 16×16 tiles); expected: no dropped or duplicated pixels at the boundary.
Pitfalls
  • Sharing one Sampler/RNG instance across threads produces correlated noise (visible banding) — violates P12; each thread must own a distinct, seeded-per-pixel sampler.
  • A non-atomic film write under rayon's default iterator produces silent data corruption at tile boundaries — must use atomic add or the tile-ownership guarantee, never both assumed simultaneously without a test (I13).
  • Off-by-one in partial-tile bounds computation drops or double-renders edge pixels.

⬜ Phase 2 — Triangle Meshes and glTF Loading §14

Objectives

Add Triangle (Möller & Trumbore 1997) alongside Sphere, and a glTF 2.0 mesh/material loader (RFC/Spec §5) so the renderer can load real assets (Stanford bunny, Cornell box mesh) instead of hand-coded spheres.

Deliverable

The renderer loads a glTF-exported Stanford bunny (~70k triangles) and a hand-authored Cornell box mesh, rendering both with the Phase 1 pinhole camera and flat per-primitive albedo (no BSDF yet — Phase 4).

Acceptance
  • Möller-Trumbore intersection matches an independent analytic barycentric solve to within 1e-5 relative error on 50 randomized triangle/ray pairs.
  • glTF loader round-trips the reference bunny.glb fixture: vertex count, triangle count, and bounding-box extents match the fixture's recorded metadata exactly.
  • A malformed glTF file with an out-of-bounds index produces RenderError::GltfImport, never a panic or out-of-bounds read (T6, I10-adjacent).
  • Linear-scan render of the 70k-triangle bunny at 400×300, 1 spp completes in < 30 s single-threaded (establishes the "before BVH" baseline that Phase 3's acceptance criteria quote a speedup against).
Fixtures
  • phase2_bunny.glb + phase2_bunny_expected.ppm — full-mesh render, reference image comparison at RMSE < 1% (no shading noise yet, deterministic).
  • phase2_zero_area_triangle.json — a triangle with two coincident vertices; expected: loader accepts it (not a parse error) but the primitive contributes zero surface area and is excluded from any future area-light role (§8 degenerate-input example).
  • phase2_index_out_of_bounds.glb — a corrupted index buffer; expected: RenderError::GltfImport, process exit code non-zero, no crash.
Pitfalls
  • Treating glTF's right-handed, Y-up convention inconsistently with the internal camera convention flips the scene; fix once in the loader's coordinate transform, not per-consumer.
  • Loading vertex normals but forgetting to renormalize after any scale transform produces subtly wrong shading once Phase 4 lands.
  • Triangle degenerate-check done per-ray instead of at load time wastes cycles on every intersection test for the life of the render.

⬜ Phase 3 — BVH Construction with SAH and Traversal §15

Objectives

Replace Phase 2's O(N) linear scan with a BVH (ADR-03) built via binned SAH (Wald 2007, MacDonald & Booth 1990) and traversed front-to-back with an explicit stack (ADR-04). This is the hardest data-structure phase in the arc (§1 timeline) and the single most performance consequential component in the system (§4, §30).

Deliverable

The Phase 2 bunny scene renders through the BVH with a measured traversal-time speedup over the Phase 2 linear-scan baseline, plus a passing debug-mode brute-force cross-check on 10,000 random rays.

Acceptance
  • BVH-accelerated render of the 70k-triangle bunny at 400×300, 1 spp completes in < 0.5 s single-threaded (≥ 60× speedup vs. the Phase 2 linear-scan baseline of < 30 s, M3 in §30).
  • Debug-mode cross-check against brute force reports zero hit/miss disagreements and zero distance disagreements beyond 1e-4 relative error over 10,000 random rays (I3, I4).
  • Binned-SAH build of a 1M-triangle scene completes in < 200 ms single-threaded (≤ 200 ns/ triangle, within the §4 budget).
  • The degenerate all-coincident-centroid fixture (15.5) builds a tree of depth ≤ 2 log2(N) + 8 rather than degenerating to a linked list (I10).
Fixtures
  • phase3_bunny_bvh.glb — same asset as Phase 2, reference image RMSE < 1% against the Phase 2 linear-scan render (same image, faster path) plus a recorded build-time and traversal-time metric.
  • phase3_coincident_centroids.json — N primitives with identical centroids (e.g., N stacked degenerate quads at one point); expected: bounded build depth, no build-time blowup (I10).
  • phase3_random_ray_crossvalidation.json — 10,000 uniformly sampled rays against the bunny scene; expected: BVH and linear-scan agree exactly (I3, I4).
  • phase3_single_primitive.json — a one-triangle scene; expected: a single-leaf tree, no interior nodes, correct intersection.
Pitfalls
  • Naive O(N²) SAH evaluation makes build time balloon on scenes above ~50k triangles — must use binned SAH from the start (ADR-04), not as a later optimization.
  • Forgetting the front-to-back near-child-first ordering loses the early-t_max-pruning benefit even though the tree itself is optimal — a correctness-neutral but performance-critical bug.
  • A BVH SAH build that degenerates to a linked list on coincident bounds (I10) silently turns every subsequent render O(N) again, hiding behind an otherwise-passing correctness test.
  • Off-by-one in the slab test's t_enter <= t_exit boundary condition drops legitimate grazing-angle hits.

⬜ Phase 4 — The Diffuse Path-Tracing Integrator §16

Objectives

Implement the Lambertian Bsdf (§11) and the recursive/iterative unidirectional path-tracing integrator (ADR-06) evaluating the hemispherical rendering equation (§8) by BSDF-only sampling with cosine-weighted hemisphere directions. Introduce the white-furnace conformance test (I1, P4) before any other correctness check, per P4's ordering rule.

Deliverable

A path-traced render of the Cornell-box mesh (from Phase 2's fixtures) with Lambertian-only materials, visible color bleeding between adjacent walls, and a passing white-furnace test.

Acceptance
  • White-furnace scene converges (16384 spp) to within 0.5% relative error of the source radiance L0 at every pixel (I1, the primary Phase 4 gate).
  • Cornell-box render at 256 spp shows measurable color bleeding: a floor patch adjacent to the red wall differs from a floor patch adjacent to the blue wall by ≥ 5% in the red channel (quantifies "indirect lighting bleeds color" from the domain requirement).
  • Russian-roulette-enabled render's expectation matches a fixed-max-depth-64 render (no RR) to within the Monte Carlo noise floor (≤ 1% relative, 4096 spp) on a synthetic constant-albedo scene (I8).
  • Zero NaN/Inf pixels reach the film across a 10-run seeded soak of the Cornell-box fixture (I5).
Fixtures
  • phase4_white_furnace.json + expected uniform-radiance output — the primary I1 fixture, 16384 spp reference.
  • phase4_cornell_box.json — Lambertian-only Cornell box; expected: color-bleed RMSE < 2% against a 16384-spp reference render.
  • phase4_rr_vs_full_depth.json — a constant-albedo synthetic scene compared with RR on vs. fixed-depth-64 RR off; expected: expectation match within 1% (I8).
  • phase4_black_material.json — a zero-albedo material (degenerate input from §8); expected: absorbs all light, contributes zero indirect bounce energy, no NaN.
Pitfalls
  • Cosine clamp omitted at the horizon: wi · n < 0 must return zero contribution, not a negative energy value (a P5/P1 violation).
  • Applying Russian roulette before depth ≥ 3 truncates paths before they've had a fair chance to contribute, inflating variance without a compensating benefit (P8).
  • A fixed (non-scale-aware) epsilon offset produces shadow acne at one scene scale and light leaks at another (P7, I11) — this is the single most common Phase 4 bring-up bug.
  • Reusing a single RNG/sampler instance across recursive calls instead of threading it through correctly produces correlated bounces within a single path.

⬜ Phase 5 — Stratified and Low-Discrepancy Sampling §17

Objectives

Replace Phase 1's naive per-pixel jitter with stratified sampling (Chiu, Shirley & Wang 1994) and Owen-scrambled Sobol low-discrepancy sequences (Owen 1998, Sobol 1967), reducing variance at fixed spp without changing the estimator's expectation (P3).

Deliverable

A configurable sampler (independent / stratified / Sobol) with measured variance reduction at matched spp for stratified and Sobol vs. the Phase 1 independent baseline, and a passing 1/√N convergence-rate test (I7).

Acceptance
  • Stratified sampling reduces per-pixel variance on the Cornell-box fixture by ≥ 30% at 64 spp vs. independent sampling at the same spp, with matched converged means (within 0.5%, P3).
  • Sobol/Owen-scrambled sampling reduces variance by ≥ 50% at 64 spp vs. independent sampling, matched means within 0.5%.
  • Measured variance-vs-N slope across {64, 256, 1024, 4096} spp matches the theoretical 1/N law within 10% relative error on log-log regression (I7).
  • No visible structured pattern (banding, moiré) in a 64-spp Sobol render of a smooth-gradient test scene (regression against the "PBRT sampling bugs" lesson catalogued in §33-adjacent history).
Fixtures
  • phase5_variance_comparison.json — same scene rendered with all three samplers at matched spp; expected: variance ordering independent > stratified > Sobol, means matched.
  • phase5_convergence_rate.json — the white-furnace scene at {64, 256, 1024, 4096} spp; expected: 1/N variance slope within 10% (I7).
  • phase5_pattern_check.json — a smooth radial gradient synthetic scene; expected: no visible structured artifact at 64 spp Sobol (visual + FFT-based periodicity check).
Pitfalls
  • Reusing the same Sobol dimension index across different path-vertex decisions (e.g., camera lens sample and first-bounce BSDF sample sharing a dimension) reintroduces correlation the low-discrepancy sequence was supposed to remove.
  • Per-thread RNG seeded by thread ID rather than by (pixel, sample_index) produces cross-pixel correlation invisible at low spp but visible as blocky patterns at high spp.
  • Stratification grid dimensions not matching the configured spp (e.g., requesting 100 spp with a 10×10 grid but rounding spp down silently) silently changes the requested sample count.

⬜ Phase 6 — The Microfacet BSDF System (GGX Metal and Dielectric) §18

Objectives

Implement Microfacet (GGX metal, Walter et al. 2007, Cook & Torrance 1982) and Dielectric (smooth and rough transmission) BSDFs with Heitz 2014 visible-normal importance sampling and Schlick-approximated Fresnel, extending the Phase 4 Lambertian-only material system.

Deliverable

Rough copper, brushed aluminum (metallic GGX), and frosted/clear dielectric spheres rendering with correct Fresnel reflectance at grazing angles and passing the extended white-furnace test for all three material types.

Acceptance
  • GGX-metal white-furnace test converges to within 1% relative error of source radiance across roughness values {0.05, 0.2, 0.5, 0.9} (extends I1 across the roughness range).
  • Dielectric white-furnace test (a glass sphere in a uniform environment) converges within 1.5% relative error, accounting for both reflected and transmitted paths.
  • Chi-square PDF-consistency test (I2) passes for Microfacet::sample_f/pdf at p-value > 0.01 across 4 roughness values and 4 incident angles.
  • Heitz 2014 visible-normal sampling shows ≥ 2× lower variance than Walter et al. 2007's original angular sampling on a matched-spp glossy-highlight test scene (quantifies the literature's claimed improvement, §33-adjacent history).
Fixtures
  • phase6_ggx_white_furnace.json — metal spheres at 4 roughness values inside a uniform emitter; expected converged radiance within 1% of source (I1 extension).
  • phase6_dielectric_white_furnace.json — glass sphere, same environment; expected within 1.5%.
  • phase6_pdf_chisquare.json — a fixed (ω_o, α) configuration sampled 100,000 times; expected chi-square p-value > 0.01 against the analytic pdf (I2).
  • phase6_fresnel_grazing.json — a dielectric plane viewed at increasing grazing angles; expected: reflectance approaches 1.0 monotonically per the Fresnel equations (§8).
Pitfalls
  • Using the uncorrelated (separable) Smith G instead of the height-correlated form loses energy at grazing angles on rough surfaces — a subtle deviation from Heitz 2014 that a screenshot would not catch but the white-furnace test (18.4) does.
  • Forgetting the reflection Jacobian when transforming the half-vector PDF to the incident-direction PDF silently breaks I2 while sample_f still "looks" plausible.
  • Schlick Fresnel applied to the wrong angle (using ω_i · n instead of ω_o · h) produces physically wrong grazing behavior that only shows up at extreme angles (18.5's grazing fixture).
  • GGX sampling below the roughness clamp without switching to a delta/specular path numerically degenerates (near-zero-probability samples, fireflies) instead of being treated as mirror reflection.

⬜ Phase 7 — Area and Environment Lights with Importance Sampling §19

Objectives

Implement AreaLight and EnvironmentLight (§11) with next-event-estimation (NEE) sampling and per-light importance sampling — a 2D CDF over an environment map's luminance (with the sinθ solid-angle correction) and, for area lights, uniform-area sampling transformed to solid-angle measure.

Deliverable

Cornell-box and HDRI-lit scenes with physically plausible soft shadows (area-light penumbrae) and correct glossy reflections of the environment map, at markedly reduced spp vs. Phase 4/6's BSDF-only sampling for the same noise level.

Acceptance
  • Cornell-box with an area light at 64 spp with NEE matches the Phase 4/6 BSDF-only-sampling 1024-spp reference to within 2% RMSE (quantifies the "NEE needs far fewer samples" domain claim).
  • A sphere lit solely by a uniform environment light matches its closed-form analytic answer (irradiance = π × environment radiance for a diffuse sphere under uniform lighting) to within 1% relative error (an analytic-scene acceptance gate, not just a reference-image diff).
  • Environment-map importance sampling shows ≥ 3× variance reduction vs. uniform environment sampling on a scene with a small bright sun disk in the HDRI, at matched spp.
  • AreaLight::pdf_li matches AreaLight::sample_li's implied density via chi-square test (I2) at p-value > 0.01.
Fixtures
  • phase7_area_light_nee.json — Cornell box with one area light; expected: 64-spp NEE render within 2% RMSE of the 1024-spp BSDF-only reference.
  • phase7_sphere_uniform_env_analytic.json — a diffuse sphere under uniform environment radiance; expected: matches the closed-form π · L_env answer within 1%.
  • phase7_env_importance_sun.json — an HDRI with a small bright sun disk; expected: ≥ 3× variance reduction with importance sampling vs. uniform sampling at matched spp.
  • phase7_zero_area_light.json — a light with a degenerate zero-area shape; expected: rejected at load time (RenderError::SceneParse), not a runtime division by zero.
Pitfalls
  • Forgetting the sinθ Jacobian when converting an environment map's (u, v) CDF sample to a spherical direction biases the sampling density near the poles, silently violating I2.
  • Picking lights uniformly at random becomes inefficient once many lights of very different power exist — acceptable for Phase 7's scope (ADR-12) but flagged as the upgrade path to a light-tree.
  • Double-counting emission (adding both the NEE contribution and the BSDF-sampled bounce's self-emission at the same vertex) inflates direct lighting — the temporary skip-emission rule (19.2 step 6) must be applied consistently until Phase 8's proper MIS weighting replaces it.
  • A shadow ray's t_max not set to just short of the light's distance (missing the epsilon trim) can self-intersect the light's own geometry (I11-adjacent).

⬜ Phase 8 — Multiple Importance Sampling §20

Objectives

Combine Phase 6's BSDF sampling and Phase 7's light (NEE) sampling via multiple importance sampling (Veach & Guibas 1995, ADR-13 power heuristic), replacing the Phase 7 temporary skip-emission rule with correctly weighted double-strategy estimation (I6).

Deliverable

The Cornell-box and GGX-metal/dielectric conformance scenes rendering under full MIS, with spp requirements roughly halved relative to Phase 7's NEE-only numbers for the same RMSE target, and glossy-highlight scenes (small light, low-roughness BSDF) converging cleanly for the first time in the arc.

Acceptance
  • Cornell-box with area light under MIS at 32 spp matches the Phase 7 64-spp NEE-only RMSE (≤ 2%), confirming the domain claim that "each step roughly halves required samples."
  • A glossy-highlight scene (small area light, GGX roughness 0.05) under MIS at 128 spp shows ≤ 5% RMSE against a 4096-spp reference, whereas BSDF-only sampling (Phase 6) at 128 spp exceeds 20% RMSE on the same scene (quantifies MIS's value specifically for glossy-plus-small-light configurations).
  • I6 weight-sum property test passes for 10,000 randomized (ω_o, material, light) configurations, |w_light + w_bsdf − 1| < 1e-5.
  • White-furnace test (I1) still passes under MIS for all three material types (regression check — MIS must not introduce an energy bug).
Fixtures
  • phase8_cornell_mis.json — same Cornell box as phase7_area_light_nee; expected: 32-spp MIS RMSE ≤ the 64-spp NEE-only RMSE recorded in Phase 7.
  • phase8_glossy_small_light.json — small area light, low-roughness GGX metal; expected: MIS RMSE ≤ 5% at 128 spp vs. BSDF-only's ≥ 20% at the same spp.
  • phase8_mis_weight_sum.json — 10,000 randomized configurations; expected: weight sum within 1e-5 of 1.0 (I6).
  • phase8_white_furnace_regression.json — re-run of phase6_ggx_white_furnace and phase6_dielectric_white_furnace under MIS; expected: same ≤1%/≤1.5% thresholds hold (I1 regression gate).
Pitfalls
  • Computing bsdf_pdf via a separate re-derivation instead of calling the BSDF's own pdf method (P9) is the most common way to silently violate I6 — the two must be bit-for-bit the same code path.
  • Forgetting to set w_bsdf = 1 after a specular bounce (where light sampling was skipped entirely) causes MIS to under-weight the only strategy that produced a sample.
  • Applying MIS weights to the wrong PDF (e.g., using the light-sampling PDF in solid-angle measure at the wrong reference point) reintroduces the double-counting bug Phase 7's temporary rule was covering for.
  • Balance vs. power heuristic mismatch between what's implemented and what's documented in ADR-13 makes the "power heuristic usually wins" claim untestable — keep both available for the I6 test specifically.

⬜ Phase 9 — Textures, Mipmapping and Normal Mapping §21

Objectives

Implement the Texture trait, image-texture loading, a box-filtered MipMap chain, ray differentials (RayDifferential, §11) for mip-level selection, and tangent-space normal mapping (ADR-17), replacing Phase 0–8's flat per-primitive albedo with sampled material parameters.

Deliverable

Textured, normal-mapped meshes (e.g., a textured Cornell box floor, a normal-mapped rough-metal sphere) rendering without minification aliasing at grazing/distant camera angles, using the mip chain driven by ray differentials.

Acceptance
  • A high-frequency checkerboard texture viewed at a grazing, distant angle shows ≤ 2% RMS aliasing energy (measured via a high-frequency FFT band on the rendered image) with mipmapping enabled, vs. > 15% with mipmapping disabled (nearest/level-0 only, ADR-15/16 regression contrast).
  • Normal-mapped sphere's shading normal matches an independently computed tangent-space transform to within 1e-4 for 100 randomized UV/tangent-frame configurations.
  • Geometric-normal-based ray offsetting (P7) remains correct under normal mapping: shadow rays still originate along the geometric normal, not the perturbed shading normal, verified by the I11 acne-detector fixture re-run under normal-mapped materials.
  • Mip-level selection matches the analytic footprint-derived level (computed independently from the differential) within ±1 level for 95% of sampled hit points on a test scene.
Fixtures
  • phase9_checkerboard_aliasing.json — a distant, grazing-angle checkerboard plane; expected: ≤ 2% aliasing energy with mips vs. > 15% without.
  • phase9_normal_map_tangent.json — 100 randomized tangent-frame/UV configurations; expected: ≤ 1e-4 error against an independent transform.
  • phase9_acne_regression.json — re-run of the Phase 4 shadow-acne fixture under a normal-mapped material; expected: I11 still holds (geometric-normal offsetting unaffected by shading-normal perturbation).
  • phase9_miplevel_footprint.json — a test scene with known analytic ray-differential footprints; expected: selected mip level within ±1 of the analytic level for 95% of samples.
Pitfalls
  • Bypassing the mip chain for a "quick" raw texel lookup anywhere reintroduces the exact aliasing the phase exists to eliminate (P13).
  • Conflating the perturbed shading normal with the geometric normal used for ray offsetting reintroduces self-intersection artifacts at silhouettes under bump-mapped materials (P5, I11).
  • An inconsistent tangent-frame handedness convention between the asset pipeline (glTF, ADR-22) and the normal-map decoder flips bump direction on some meshes but not others.
  • Ray-differential transfer at a specular bounce (mirror, glass) requires a different transform than a diffuse bounce; using the diffuse transform everywhere produces wrong mip selection behind mirrors/glass.

⬜ Phase 10 — Depth of Field, Tone Mapping, Progressive Preview and the Denoiser Seam §22

Objectives

Complete the camera model with thin-lens depth of field (Cook, Porter & Carpenter 1984), add the tone-mapping stage (Reinhard et al. 2002), wire the progressive-preview emitter, and define the denoiser seam trait (ADR-21) — the last phase before conformance hardening (Phase 11).

Deliverable

A Cornell-box render with visible depth-of-field blur at a configured aperture/focus distance, a tone-mapped and gamma-correct PNG/OpenEXR output, a live progressive-preview stream observable during the render, and a passthrough denoiser seam ready for a future model.

Acceptance
  • Thin-lens depth-of-field blur radius at a known defocus distance matches the analytic circle-of-confusion formula (aperture_radius × |focus_distance − object_distance| / object_distance, scaled by focal length) within 5% on a synthetic test scene with known geometry.
  • Tone-mapped output matches the extended Reinhard formula (§8) applied out-of-band to the raw film buffer within 1e-4 per channel (a pure-function regression test, P10).
  • OpenEXR output round-trips through an independent EXR reader with linear radiance values matching the film buffer within 1e-5 (no precision loss through the write path).
  • Progressive-preview snapshots never block a tile worker for more than 1 ms (measured via the §30 profiling methodology) and never emit a torn (partially-written) frame.
Fixtures
  • phase10_dof_coc.json — a scene with known object/focus distances; expected: measured blur radius within 5% of the analytic circle-of-confusion formula.
  • phase10_tonemap_regression.json — a fixed synthetic HDR film buffer; expected: tone-mapped output matches the out-of-band Reinhard computation within 1e-4.
  • phase10_exr_roundtrip.json — render, write OpenEXR, re-read via an independent library; expected: values match within 1e-5.
  • phase10_preview_nonblocking.json — a long render with preview snapshots enabled; expected: zero torn frames across 100 snapshots, worker stall < 1 ms per snapshot.
Pitfalls
  • Fusing gamma correction into the tone-mapping curve instead of keeping them as separate pure functions (P10) makes either stage impossible to swap or test independently.
  • Sampling the lens with a naive square-mapped random pair instead of a concentric-disk mapping produces non-uniform bokeh density (visible as a squarish, non-circular defocus blur).
  • Snapshotting the film for preview without a consistent read (e.g., reading sum and count from different points in time under concurrent writes) produces a preview frame with visible tearing, even though the final accumulated result remains correct.
  • Treating the denoiser seam as "done" because the trait compiles, without a passthrough regression test, risks a future real implementation silently changing radiance values in a supposedly opt-in-only path (ADR-07 bias-labelling requirement).

⬜ Phase 11 — Conformance Suite, Reference-Image Regression Gating and Performance Hardening §23

Objectives

Consolidate every prior phase's conformance fixture into a single gated conformance.yml CI job, add reference-image regression comparison with numeric tolerances, and harden performance against the §4/§30 quantified targets — the exit gate for the entire 12-phase arc.

Deliverable

A green conformance.yml and perf-regression.yml on the full fixture manifest, a completed 24-hour soak report with no detected drift, and a documented differential-comparison result against Mitsuba 3 on the shared analytic scenes — the render-farm-readiness gate (§1 deployment model).

Acceptance
  • 100% of the consolidated fixture manifest (§12.5–§22.5, ≥ 30 fixtures) passes within its recorded tolerance in conformance.yml.
  • Cornell-box-class scene at 1920×1080, 1024 spp, max depth 8, renders in < 15 minutes on a 16-core CPU (the §4 target render-time gate, M-series in §30).

Fixtures
  • phase11_manifest.json — the full consolidated fixture list with per-fixture tolerances, covering every named fixture from Phase 0 through Phase 10.
  • phase11_mitsuba_differential.json — the shared white-furnace and Cornell-box scenes exported in a Mitsuba-compatible format; expected: ≤ 3% RMSE differential.
  • phase11_soak_24h.json — a large scene configured for a 24-hour continuous render; expected: < 1% memory growth, zero NaN accumulation.
  • phase11_seeded_replay_full_config.json — the full default render configuration at fixed seed; expected: bit-exact match across two runs (I9).
Pitfalls
  • Setting per-fixture tolerances too loosely to make the suite pass defeats the entire purpose of the gate (P4) — tolerances must be derived from the fixture's own known noise floor at its configured spp, not chosen to make a broken build green.
  • A differential comparison against Mitsuba 3 that ignores legitimate RNG-sequence differences (which are not a bug) risks either false failures or, worse, a tolerance loosened so much it stops catching real bias.
  • A soak test run on a machine under variable load (shared CI runner) can show apparent memory growth that is actually OS-level noise, not a leak — run the soak on a dedicated, isolated machine.
  • Perf-regression gating without a stable baseline (e.g., comparing against a baseline recorded on different hardware) produces false positives that erode trust in the gate.
