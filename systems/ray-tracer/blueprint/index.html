1. Goal & Scope

This blueprint specifies a from-scratch, offline, physically-based ray tracer / path tracer in Rust that solves the light-transport problem by stochastic (Monte Carlo) integration of the rendering equation (Kajiya 1986) along rays traced through a scene, rather than by projecting and scan-converting geometry onto an image plane with a depth buffer. The system: (1) intersects rays against triangles and analytic spheres, accelerated by a bounding volume hierarchy (BVH) built with the surface-area heuristic (SAH); (2) evaluates a path-tracing integrator that estimates outgoing radiance at each shading point by recursively sampling BSDF and light directions, combined by multiple importance sampling (MIS, Veach & Guibas 1995); (3) supports Lambertian, microfacet GGX metal, and dielectric (transmissive) materials with importance-sampled BSDFs; (4) supports area and environment (image-based) lights with importance sampling; (5) supports texture and normal mapping with mipmapping; (6) models a thin-lens camera for depth of field; (7) accumulates radiance into a floating-point film, tone-maps, and writes PPM/PNG/OpenEXR output; and (8) renders progressively, tile-scheduled across CPU cores, with a defined seam for an external denoiser. The system trades render latency (minutes to hours) for physical accuracy and generality that a rasterizer cannot provide in a single deterministic pass.

Phase-0 deliverable — crates

  1. raytracer-math — Vec3/Point3/Normal3/Transform primitives, Interval, Aabb.
  2. raytracer-core — Ray, RayDifferential, Primitive trait, Triangle, Sphere, SurfaceInteraction, Scene.
  3. raytracer-accel — BvhNode, BvhBuildRecord, SahBucket, SAH build, traversal.
  4. raytracer-sampling — Sampler trait, RNG, stratified/Sobol sequences (stubbed Phase 0, filled Phase 5).
  5. raytracer-render — Camera, Film, Tile, RenderConfig, RenderStats.
  6. raytracer-io — PPM writer (Phase 0), PNG/OpenEXR (Phase 10), glTF loader (Phase 2).
  7. raytracer-cli — binary crate; load → build → render → write orchestration.

Boundaries

  • Provides: ray/primitive intersection, BVH acceleration, the path-tracing integrator, BSDF/light sampling and MIS, texture/normal mapping, thin-lens camera, film accumulation, tone mapping, tile scheduling, progressive preview emission, and a denoiser seam (interface only — no shipped trained model).
  • Delegates: interactive display of the progressive preview (this system writes snapshots to disk or a socket; a viewer is external); scene authoring (consumes glTF 2.0, does not author it); the trained denoiser weights themselves — PhaseDeferred("§22 Phase 10 — Depth of Field, Tone Mapping, Progressive Preview and the Denoiser Seam").
  • Does NOT provide: bidirectional path tracing, Metropolis light transport, photon mapping, participating-media/volumetric transport, subsurface scattering, hair/fur/cloth BSDFs, spectral rendering, a GPU backend — PhaseDeferred("§36 Alternative Architectures (Roads Not Taken)").

Non-goals

  • Not real-time. Target is offline batch rendering, minutes to hours per image; no frame-rate guarantee anywhere in this document.
  • Not a rasterizer. Sibling project rank 169, Software-Rasterizer, solves visibility by projecting and scan-converting triangles against a depth buffer in one deterministic pass per triangle. This project solves visibility by tracing rays through a BVH and solves the transport integral stochastically over many samples per pixel. The two share only linear-algebra and texture-sampling primitives; rasterization is not re-specified here.
  • Not a full spectral renderer. RGB only (ADR-09); Smits 1998 is cited for a future spectral upgrade path, not implemented.
  • No GPU backend in Phase 0. CPU-only across the entire 12-phase arc; a GPU wavefront path tracer is analyzed as a rejected architecture in §36, not built.

Deployment model

(a) CLI offline renderer: scene file in, image file out, single process, single machine. (b) Library: the crates above are independently embeddable (e.g., in a look-dev tool's preview pane). (c) Progressive preview: the render loop emits partial-film snapshots at a configurable cadence to a directory or local socket without blocking the render loop.

Users / operators

Technical artists validating look-dev scenes; a render-farm operator scheduling batch jobs across machines (§26); a CI job that renders conformance fixtures (§28) and gates merges on image-regression; a library consumer embedding the renderer inside a larger pipeline.

What later phases unlock

Phase 3 (BVH+SAH) unlocks million-triangle scenes. Phase 6 (microfacet BSDFs) unlocks photorealistic metal/glass. Phases 7–8 (lights + MIS) unlock efficient noise-free convergence. Phase 9 (textures) unlocks production-asset scenes. Phase 10 (DoF/tonemap/denoiser seam) unlocks presentation-quality stills. Phase 11 (conformance + perf) unlocks the render-farm deployment model.

Rust rationale and rejected languages

Rust: no garbage-collector pause inside a long-running render loop; Send + Sync trait bounds statically enforce the same/cross-thread data-race-freedom the tile-parallel renderer depends on (P6, P14); zero-cost trait-object dispatch keeps Primitive/Bsdf/Light polymorphism cheap; the crate ecosystem supplies rayon (tile parallelism), glam (SIMD vector math), and image/exr (output) without hand-rolling. Rejected: C++ — no memory-safety guarantee for the wide unsafe-pointer surface of BVH/traversal code (pbrt-v4 and Embree pay for this with a large sanitizer/fuzz surface, ADR-01). Go — GC pauses interact badly with a tight per-ray inner loop and there is no mature SIMD story. Python — the throughput requirement (millions of rays/second per core) is 2–3 orders of magnitude beyond an interpreter even with numpy vectorization at this granularity.

Prerequisites

Linear algebra (vectors, matrices, change of basis, orthonormal frames); probability (density functions, expectation, variance, change-of-variables for sampling); radiometry (radiance, irradiance, solid angle, the BRDF definition); asymptotic reasoning for the BVH; enough Rust to write trait objects and use rayon.

Timeline

Phase 0–2 (skeleton, camera/film, mesh loading): 1–2 weeks each, solo evenings/weekends pace. Phase 3 (BVH+SAH): 2 weeks — the hardest data-structure phase. Phase 4–5 (diffuse integrator, stratified sampling): 1 week each. Phase 6 (microfacet BSDFs): 2 weeks — the hardest math phase. Phase 7–8 (lights, MIS): 2 weeks combined. Phase 9 (textures): 1 week. Phase 10 (DoF/tonemap/denoiser seam): 1 week. Phase 11 (conformance + perf hardening): 2 weeks. Total: ~16–18 weeks part-time.

Deferrals

PhaseDeferred("§22 Phase 10 — Depth of Field, Tone Mapping, Progressive Preview and the Denoiser Seam") — the trained denoiser model itself; only the seam trait ships. PhaseDeferred("§36 Alternative Architectures (Roads Not Taken)") — bidirectional path tracing, Metropolis light transport, photon mapping, GPU wavefront execution.

2. Why Build This

  • Radiometry made operational: the rendering equation stops being an abstract integral once you write the estimator that evaluates it.
  • Variance-reduction techniques transfer: importance sampling, stratification, MIS, and Russian roulette reappear in option pricing, particle transport, and variational inference.
  • BVH construction is a masterclass in heuristic-driven spatial indexing, applicable to collision detection, nearest-neighbor search, and spatial databases.
  • Numerical robustness under composition: shadow acne, NaN propagation, and energy-conservation bugs teach defensive floating-point engineering.
  • The sharpest contrast case against a rasterizer (rank 169) for understanding the two fundamental visibility algorithms in computer graphics.
  • Concurrency without shared mutable state: per-tile, per-pixel independence is close to embarrassingly parallel — a clean teaching case for rayon.
  • Production relevance: pbrt, Cycles, Arnold, and RenderMan all embody the same core loop this blueprint specifies.

What Mastery Looks Like

  • Deriving and re-deriving the cosine-weighted and GGX-visible-normal sampling densities from scratch, matching Phase 6 acceptance criteria without a formula sheet.
  • Diagnosing a fireflies bug (Phase 7/Phase 8) by inspecting the offending sample's PDF rather than clamping blindly.
  • Explaining why the BVH SAH split at a given node is optimal for a specific scene without running the profiler (Phase 3).
  • Writing a white-furnace test (Phase 4) before writing the first BSDF, and trusting it over a screenshot.
  • Reading pbrt-v4's BVH aggregate or Embree's binned SAH builder (Phase 3) and naming which of their optimizations this blueprint deliberately omits, and why (§33).
  • Predicting, from the §34 capacity model, how many samples per pixel a target noise level requires before running the render.
  • Explaining the MIS balance/power-heuristic tradeoff (Phase 8) in terms of the worst-case variance bound, not just "it looks less noisy."

Scene Loader parses the custom JSON scene wrapper plus glTF 2.0 mesh/material payloads into an in-memory Scene; runs once at startup, single-threaded, and is the sole untrusted-input boundary (§24).

Geometry Store owns immutable triangle/sphere buffers post-load; every traversal thread holds a read-only reference, which is what makes tile-parallel traversal safe without locks (P6).

BVH Builder consumes the Geometry Store once and produces a flat BvhNode array via binned SAH (Wald 2007); this is the one build-time-critical, single-writer stage in the pipeline.

BVH Traverser is the read-hot inner loop invoked by every ray; it is stateless with respect to the tree and therefore trivially shared across threads.

Tile Scheduler partitions the film into fixed-size tiles and hands them to a work-stealing thread pool (rayon); it is the only component that mutates cross-thread scheduling state, via a lock-free queue.

Camera / Ray Generator maps a film-space sample (x, y, u_lens, v_lens) to a world-space Ray, applying the thin-lens transform for depth of field.

Sampler supplies the per-pixel, per-dimension quasi-random or stratified numbers consumed by the camera, BSDF, and light-sampling routines; one sampler instance is owned per thread, never shared (P12).

Integrator is the recursive/iterative path-tracing loop that turns a primary ray into a radiance estimate, combining BSDF sampling, light sampling, and MIS weighting at each vertex.

BSDF evaluation and sampling computes f, sample_f, and pdf for the material at a hit point; it is a pure function of the surface interaction and two uniform random numbers.

Light sampling produces a candidate light direction, its radiance, and its PDF for next-event estimation; it is queried once per non-specular bounce.

Texture system resolves a filtered color or normal from UV coordinates and a mip level derived from ray differentials (Phase 9); it sits behind the BSDF, never invoked directly by the integrator.

Film / Framebuffer Accumulator holds one atomic accumulation slot (sum, sum-of-squares, sample count) per pixel; it is the only cross-tile shared state, and it is written via atomic add, never locked (P14, I13).

Progressive Preview emitter reads a consistent snapshot of the film at a bounded cadence and serializes it externally without pausing the render loop.

Tone Mapper is a pure function from linear HDR radiance to a display-referred image; it never touches BSDF, light, or integrator state (P10).

Denoiser Seam is a trait boundary between the tone-mapped (or pre-tonemap, per configuration) buffer and the output writer; Phase 0–11 ships the trait and a no-op implementation only.

Output Writer serializes the final buffer to PPM (Phase 0), PNG, or OpenEXR (Phase 10), and is the sole trusted-output boundary (§24, T9).

6. Design Principles

P1. Radiance is the only currency. Every quantity the integrator touches (BSDF value, light sample, film pixel) is denominated in radiance or a radiance-like ratio; mixing in ad-hoc "brightness" scalars breaks the physical units and turns tone mapping into a guess instead of a display transform. Violating it: a scene that looks right at one exposure and wrong at another.

P2. Every sampling strategy declares its probability density. An unnormalized PDF is an energy bug that looks like an art-direction choice — a material that appears "moodier" is actually darker because sample_f and pdf disagree. Tradeoff: declaring and testing PDFs costs upfront engineering time. Operational implication: every new BSDF or light ships with a chi-square PDF-consistency test (§28) before it renders a single pixel.

P3. The integrator is unbiased by default. Every variance-reduction technique (importance sampling, MIS, stratification) must preserve the expectation; any biased mode (firefly clamping, denoising) is opt-in and labelled in the render metadata. Violating it silently produces a converged image that is provably wrong, not just noisy.

P4. Correctness is proven by convergence to a reference, never by a screenshot. A white-furnace test (I1) outranks a "looks about right" visual check; every phase's acceptance criteria (N.4) are numeric — RMSE, energy-conservation percentage — against an analytic or reference render.

P5. Geometric and shading frames are never conflated. The geometric normal governs ray-origin offsetting (self-intersection avoidance); the shading normal (possibly normal-mapped) governs BSDF evaluation. Collapsing them into one field produces light leaks at silhouettes and NaN normals under bump maps.

P6. The BVH is read-only after build. No traversal thread ever mutates node data; the concurrency safety of tile-parallel rendering follows directly from this, not from locks. Violating it — e.g., lazy refit during traversal — reintroduces the data race the type system was supposed to rule out.

P7. Every ray carries a scale-aware origin offset, never a fixed global epsilon. A single hardcoded epsilon is correct at one scene scale and wrong at every other; origin offsetting scales with local geometric error. Violating it produces shadow acne at one scale and light leaks at another.

P8. Throughput, not depth, drives Russian roulette. Termination probability is a function of the path's accumulated throughput magnitude, never depth alone below a minimum-depth floor. Violating it either wastes samples on paths that can't matter or introduces bias by cutting off high-contribution paths too early.

P9. MIS weights are computed from PDFs the estimator already had to compute. No hidden PDF re-derivation path is allowed to diverge from the sampling routine that produced the direction. Violating it is the single most common source of energy loss or gain in a path tracer.

P10. The film accumulates linear radiance; the display transform is a pure function applied once at output. No BSDF, light, or integrator code ever touches gamma or a tone curve. Violating it makes every downstream module context-dependent on a display assumption it has no business knowing about.

P11. The acceleration structure is validated against brute force, never trusted by construction. Every BVH build ships a debug-mode invariant check (I3, I4) intersecting a sample of rays against both the BVH and a linear scan. A silently wrong BVH is worse than a slow one because it corrupts every downstream measurement.

P12. Determinism is a first-class deliverable, not an accident of implementation. A fixed seed and fixed thread count must reproduce a bit-identical or documented tolerance-bounded image. Violating it makes every regression test flaky and every reported bug unreproducible.

P13. Texture and normal data are sampled through one filtered interface, never raw pixel lookups. Bypassing the mipmap/filter chain to "just read a pixel" reintroduces the aliasing a whole phase (§21) exists to eliminate.

P14. A tile is the unit of work, parallelism, and failure isolation. No cross-tile shared mutable state exists except the film's per-pixel atomic accumulation slots. Violating it — e.g., a shared per-thread light-sampling cache with cross-tile state — reintroduces the same race-condition class P6 already ruled out for the BVH.

Debugging methodology: every invariant violation is first reproduced with a seeded-replay fixture (I9) to make it deterministic, then isolated with the smallest conformance scene that still reproduces it (single-triangle white-furnace, a two-sphere Cornell-box corner), then bisected by disabling one integrator feature at a time (NEE, MIS, Russian roulette) until the violation disappears, pinpointing the offending code path. The reducing fixture is then added permanently to the §28 regression suite so the bug class cannot regress silently.

8. Domain Model

Radiometric quantities

Radiance: L(p, ω) = d²Φ / (dA cosθ dω) — flux per unit projected area per unit solid angle. Irradiance: E(p) = ∫_Ω L(p, ω) cosθ dω. Solid-angle measure in spherical coordinates: dω = sinθ dθ dφ.

The rendering equation

Hemispherical form:

L_o(p, ω_o) = L_e(p, ω_o) + ∫_{H²(n)} f(p, ω_i, ω_o) L_i(p, ω_i) cosθ_i dω_i

Area form (integrating over surface points p' visible from p):

L_o(p, ω_o) = L_e(p, ω_o) + ∫_A f(p, ω_i, ω_o) L_o(p', -ω_i) G(p, p') V(p, p') dA'
G(p, p') = (cosθ_i cosθ_i') / ‖p − p'‖²

Monte Carlo estimator

⟨F⟩ = (1/N) Σ_{k=1..N} f(X_k) / p(X_k)

Unbiased iff p(x) > 0 wherever f(x) ≠ 0. Variance:

Var[⟨F⟩] = (1/N) Var[f(X)/p(X)]

Importance sampling minimizes variance by choosing p(x) ∝ f(x); the ideal (zero-variance, unreachable in general) density is p(x) = f(x) / ∫ f.

Sampling densities used by the integrator

Cosine-weighted hemisphere (Lambertian): p(ω) = cosθ / π. GGX visible-normal sampling (Heitz 2014):

pdf_h(h) = G1(ω_o) D(h) max(0, ω_o · h) / cosθ_o
pdf_ωi(ω_i) = pdf_h(h) / (4 (ω_o · h))

MIS heuristics (Veach & Guibas 1995)

Balance heuristic: w_s(x) = p_s(x) / Σ_i p_i(x). Power heuristic (β = 2): w_s(x) = p_s(x)² / Σ_i p_i(x)².

Fresnel and the Schlick approximation

F0 = ((n1 − n2) / (n1 + n2))²
F_schlick(θ) = F0 + (1 − F0)(1 − cosθ)^5

GGX / Trowbridge-Reitz distribution and Smith masking-shadowing

D_GGX(h) = α² / (π ((n·h)²(α² − 1) + 1)²)
Λ(ω) = (−1 + sqrt(1 + α² tan²θ)) / 2
G(ω_o, ω_i) = 1 / (1 + Λ(ω_o) + Λ(ω_i))          (height-correlated Smith, Heitz 2014)

Microfacet BRDF assembly

f(ω_o, ω_i) = D(h) G(ω_o, ω_i) F(ω_o · h) / (4 cosθ_o cosθ_i)

Russian roulette

Continue with probability q (function of throughput, P8), scaling throughput by 1/q; terminate with probability 1 − q contributing zero. Unbiased iff q is chosen independent of the sample's own future contribution (a function only of accumulated past throughput) — proven in Veach 1997, chapter 10.

Thin-lens camera model

p_lens = aperture_radius · concentric_disk_sample(u)
p_focus = ray.origin + t_focus · ray.direction
ray' = Ray(origin = ray.origin + p_lens_offset,
           direction = normalize(p_focus − (ray.origin + p_lens_offset)))

Tone-mapping curve (extended Reinhard, Reinhard et al. 2002)

L_d = L (1 + L / L_white²) / (1 + L)

Ray-triangle intersection (Möller & Trumbore 1997)

E1 = v1 − v0,  E2 = v2 − v0,  T = O − v0
P = D × E2,  Q = T × E1
t = (Q · E2) / (P · E1),  u = (P · T) / (P · E1),  v = (Q · D) / (P · E1)
hit iff u ≥ 0, v ≥ 0, u + v ≤ 1, t ∈ [t_min, t_max]

Ray-sphere intersection

a = D·D,  b = 2 D·(O − C),  c = (O − C)·(O − C) − r²
discriminant = b² − 4ac;  hit iff discriminant ≥ 0, smallest positive root in [t_min, t_max]

SAH cost model and a worked split decision

cost(split) = K_T + (SA(L)/SA(N)) · N_L · K_I + (SA(R)/SA(N)) · N_R · K_I

Worked example: N = 100 triangles, SA(N) = 24 m², K_T = 1.0, K_I = 1.2. Candidate split A gives SA(L) = 10 m², N_L = 40, SA(R) = 16 m², N_R = 60 → cost = 1.0 + (10/24)(40)(1.2) + (16/24)(60)(1.2) = 1.0 + 20.0 + 48.0 = 69.0. Candidate split B gives SA(L) = 12 m², N_L = 50, SA(R) = 13 m², N_R = 50 → cost = 1.0 + (12/24)(50)(1.2) + (13/24)(50)(1.2) = 1.0 + 30.0 + 32.5 = 63.5. B wins (lower cost); the builder picks the split minimizing this cost per axis per bin (ADR-04).

Worked numeric example — two bounces

Camera ray hits a Lambertian floor (ρ = 0.8) at p0; cosine-weighted sample gives pdf = cosθ/π, so f·cosθ/pdf = ρ = 0.8 (throughput becomes 0.8). The bounce ray hits a second Lambertian wall (ρ = 0.5) at p1, emissive L_e = 0; NEE samples an area light (radiance 10, pdf_solid_angle = 2.0, cosθ_l = 0.9) giving direct contribution f · L_e_light · cosθ / pdf = (0.5/π) · 10 · 0.9 / 2.0 ≈ 0.716; scaled by the path throughput so far (0.8) contributes ≈ 0.573 to the pixel. The BSDF-sampled continuation ray from p1 carries throughput 0.8 × 0.5 = 0.4 into depth 2, where Russian roulette (depth ≥ 3 not yet reached) does not yet engage.

Degenerate-input examples

Zero-area triangle (two or more vertices coincident): surface_area() = 0; excluded from area-light sampling (division-by-zero guard), still valid for intersection but contributes zero importance weight. Degenerate BVH with all-coincident bounds: SAH cost is flat across all splits (I10); builder falls back to index-based median split to guarantee O(log N) depth. Black or singular material (albedo = 0, pdf well-defined but f = 0 everywhere): valid, absorbs all incident light, must not propagate NaN. Light with zero area: pdf_li undefined; excluded from the light list at load time with a load-time warning (T-adjacent, §24).

Failure-path example

A shadow ray from a hit point offset by a non-scale-aware epsilon on a scene with 1000× the reference scale re-intersects its own triangle at t ≈ 1e-7; the light is incorrectly reported occluded; the pixel goes black; caught by I11's acne-pattern detector in the conformance renderer, recovered by switching to relative epsilon scaled by the hit point's magnitude.

  • Sharing one Sampler/RNG instance across threads produces correlated noise (visible banding) — violates P12; each thread must own a distinct, seeded-per-pixel sampler.

13.9 Failure Analysis

13.10 Operational Notes

15. Phase 3 — BVH Construction with SAH and Traversal

15.1 Objectives

Replace Phase 2's O(N) linear scan with a BVH (ADR-03) built via binned SAH (Wald 2007, MacDonald & Booth 1990) and traversed front-to-back with an explicit stack (ADR-04). This is the hardest data-structure phase in the arc (§1 timeline) and the single most performance consequential component in the system (§4, §30).

15.2 Detailed Implementation Steps

  1. Implement Aabb slab-test intersection with the Williams et al. 2005 robust formulation (precomputed 1/direction, correct handling of zero-direction components, I11-adjacent numerical care).
  2. Implement BvhBuildRecord/SahBucket (§11) and the binned-SAH build: bin primitive centroids into 12–16 buckets per axis, evaluate the SAH cost model (§8 equation) at each bucket boundary, pick the minimum-cost split per axis, then the minimum across axes.
  3. Apply the SAH cost model exactly as derived in §8's worked example; use K_T = 1.0, K_I = 1.2 as the default traversal/intersection cost ratio (ADR-04).
  4. Guard against degenerate input (I10): if centroid bounds have zero extent on all axes (fully coincident centroids), fall back to an index-median split to guarantee O(log N) depth rather than a flat SAH tie that could pick the same split forever.
  5. Pack the built tree into the flat 32-byte BvhNode layout (§8 byte-layout table); leaves store a primitive-range offset/count, interior nodes store a left/right child index and the split axis for front-to-back ordering.
  6. Implement iterative traversal with an explicit stack, visiting the near child first per the ray's direction sign on the split axis (ADR-04), maintaining a running t_max for early pruning.
  7. Implement the debug-mode brute-force cross-check (P11, I3, I4): for a sampled batch of rays, assert the BVH's hit/miss and hit distance agree with a linear scan.
  8. Replace Scene::intersect's linear scan with the BVH traversal; retain the linear scan as a #[cfg(debug_assertions)]-gated reference path for I3/I4 checks only.

15.3 Deliverable

The Phase 2 bunny scene renders through the BVH with a measured traversal-time speedup over the Phase 2 linear-scan baseline, plus a passing debug-mode brute-force cross-check on 10,000 random rays.

15.4 Acceptance Criteria

  • BVH-accelerated render of the 70k-triangle bunny at 400×300, 1 spp completes in < 0.5 s single-threaded (≥ 60× speedup vs. the Phase 2 linear-scan baseline of < 30 s, M3 in §30).
  • Debug-mode cross-check against brute force reports zero hit/miss disagreements and zero distance disagreements beyond 1e-4 relative error over 10,000 random rays (I3, I4).
  • Binned-SAH build of a 1M-triangle scene completes in < 200 ms single-threaded (≤ 200 ns/ triangle, within the §4 budget).
  • The degenerate all-coincident-centroid fixture (15.5) builds a tree of depth ≤ 2 log2(N) + 8 rather than degenerating to a linked list (I10).

15.5 Conformance Fixtures

  • phase3_bunny_bvh.glb — same asset as Phase 2, reference image RMSE < 1% against the Phase 2 linear-scan render (same image, faster path) plus a recorded build-time and traversal-time metric.
  • phase3_coincident_centroids.json — N primitives with identical centroids (e.g., N stacked degenerate quads at one point); expected: bounded build depth, no build-time blowup (I10).
  • phase3_random_ray_crossvalidation.json — 10,000 uniformly sampled rays against the bunny scene; expected: BVH and linear-scan agree exactly (I3, I4).
  • phase3_single_primitive.json — a one-triangle scene; expected: a single-leaf tree, no interior nodes, correct intersection.

15.6 Pitfalls

  • Naive O(N²) SAH evaluation makes build time balloon on scenes above ~50k triangles — must use binned SAH from the start (ADR-04), not as a later optimization.
  • Forgetting the front-to-back near-child-first ordering loses the early-t_max-pruning benefit even though the tree itself is optimal — a correctness-neutral but performance-critical bug.
  • A BVH SAH build that degenerates to a linked list on coincident bounds (I10) silently turns every subsequent render O(N) again, hiding behind an otherwise-passing correctness test.
  • Off-by-one in the slab test's t_enter <= t_exit boundary condition drops legitimate grazing-angle hits.

15.7 Performance Concerns

BVH traversal is projected to become ~60% of total render time once shading exists (§13 Performance Notes analogy carried forward; quantified per M2–M5 in §30). Node memory layout is cache-critical: the 32-byte node (§8) is sized to fit two nodes per 64-byte cache line minus padding, minimizing cache misses during the traversal stack's inner loop.

15.8 Edge Cases

A scene with exactly one primitive must build a valid single-leaf tree without triggering the binning logic's divide-by-zero on a zero-extent centroid bounds. A ray with t_min > t_max at entry (malformed by a caller) must return no hit rather than undefined behavior.

15.9 Failure Analysis

A BVH that reports a false hit (I4 violation) is the most dangerous failure class in this phase because it corrupts shading with no visible artifact pattern until compared against a reference; the debug-mode cross-check (15.2 step 7) is the only reliable detector and is therefore run in CI on every PR touching raytracer-accel, not just locally.

15.10 Operational Notes

Build-time and node count are logged as RenderStats fields and surface on the §26 dashboard as bvh_build_time_ms and bvh_node_count; a regression in either metric beyond the §30 M-series thresholds fails the perf-regression.yml CI gate (§29).

16. Phase 4 — The Diffuse Path-Tracing Integrator

16.1 Objectives

Implement the Lambertian Bsdf (§11) and the recursive/iterative unidirectional path-tracing integrator (ADR-06) evaluating the hemispherical rendering equation (§8) by BSDF-only sampling with cosine-weighted hemisphere directions. Introduce the white-furnace conformance test (I1, P4) before any other correctness check, per P4's ordering rule.

16.2 Detailed Implementation Steps

  1. Implement Lambertian::f returning albedo / π (§8 Lambertian equation) and Lambertian:: sample_f returning a cosine-weighted direction with pdf = cosθ / π (I2: the two must agree by construction, not by coincidence).
  2. Implement the integrator's main loop: intersect via the Phase 3 BVH, evaluate self-emission, sample a bounce direction from the BSDF, recurse/iterate, accumulate f · cosθ / pdf · L_incoming (§8 Monte Carlo estimator, P2).
  3. Implement Russian roulette (P8, I8): apply only after depth ≥ 3, q a function of throughput's max channel, throughput scaled by 1/q on survival (§8 Russian roulette equation, Veach 1997 chapter 10 unbiasedness proof).
  4. Implement the origin-offset routine (P7, I11): offset the continuation ray's origin along the geometric normal by a scale-aware epsilon derived from the hit point's magnitude, not a fixed constant.
  5. Implement the white-furnace conformance scene: a diffuse sphere of albedo 1.0 inside a uniform environment emitter of radiance L0; the expected converged image is uniformly L0 everywhere (I1).
  6. Implement the NaN/Inf guard (I5) at the per-sample accumulation step; log and discard rather than propagate.
  7. Wire max_depth from RenderConfig as a hard cap independent of Russian roulette (§4 constraint: default 8, hard cap 64).

16.3 Deliverable

A path-traced render of the Cornell-box mesh (from Phase 2's fixtures) with Lambertian-only materials, visible color bleeding between adjacent walls, and a passing white-furnace test.

16.4 Acceptance Criteria

  • White-furnace scene converges (16384 spp) to within 0.5% relative error of the source radiance L0 at every pixel (I1, the primary Phase 4 gate).
  • Cornell-box render at 256 spp shows measurable color bleeding: a floor patch adjacent to the red wall differs from a floor patch adjacent to the blue wall by ≥ 5% in the red channel (quantifies "indirect lighting bleeds color" from the domain requirement).
  • Russian-roulette-enabled render's expectation matches a fixed-max-depth-64 render (no RR) to within the Monte Carlo noise floor (≤ 1% relative, 4096 spp) on a synthetic constant-albedo scene (I8).
  • Zero NaN/Inf pixels reach the film across a 10-run seeded soak of the Cornell-box fixture (I5).

16.5 Conformance Fixtures

  • phase4_white_furnace.json + expected uniform-radiance output — the primary I1 fixture, 16384 spp reference.
  • phase4_cornell_box.json — Lambertian-only Cornell box; expected: color-bleed RMSE < 2% against a 16384-spp reference render.
  • phase4_rr_vs_full_depth.json — a constant-albedo synthetic scene compared with RR on vs. fixed-depth-64 RR off; expected: expectation match within 1% (I8).
  • phase4_black_material.json — a zero-albedo material (degenerate input from §8); expected: absorbs all light, contributes zero indirect bounce energy, no NaN.

16.6 Pitfalls

  • Cosine clamp omitted at the horizon: wi · n < 0 must return zero contribution, not a negative energy value (a P5/P1 violation).
  • Applying Russian roulette before depth ≥ 3 truncates paths before they've had a fair chance to contribute, inflating variance without a compensating benefit (P8).
  • A fixed (non-scale-aware) epsilon offset produces shadow acne at one scene scale and light leaks at another (P7, I11) — this is the single most common Phase 4 bring-up bug.
  • Reusing a single RNG/sampler instance across recursive calls instead of threading it through correctly produces correlated bounces within a single path.

16.7 Performance Concerns

The integrator's cost is now BVH-traversal-dominated per §15.7's projection; Phase 4 introduces BSDF evaluation and sampling cost (~20% of total per the same projection) and Russian-roulette branch overhead, both bounded because Lambertian's f/sample_f/pdf are closed-form, O(1), branch-light.

16.8 Edge Cases

A path that never terminates via Russian roulette before max_depth must still terminate at the hard cap (64) without accumulating unbounded stack depth if implemented recursively — prefer an iterative loop with an explicit depth counter to avoid stack-overflow risk on deep paths.

16.9 Failure Analysis

An indirect-lighting-too-dark symptom (scene looks correct at direct light only, dim elsewhere) traces to either an insufficient max_depth, an RR q computed too aggressively, or a sign error in the cosine term; the debugging methodology (§7) isolates which by disabling RR first, then increasing max_depth, then inspecting per-bounce throughput in a scalar debug scene.

16.10 Operational Notes

RenderStats gains average_path_depth and rr_terminated_count, both surfaced on the §26 dashboard; the white-furnace fixture (16.5) is added to conformance.yml as a blocking gate for every subsequent phase, since every later BSDF/light addition must keep it passing (I1).

17. Phase 5 — Stratified and Low-Discrepancy Sampling

17.1 Objectives

Replace Phase 1's naive per-pixel jitter with stratified sampling (Chiu, Shirley & Wang 1994) and Owen-scrambled Sobol low-discrepancy sequences (Owen 1998, Sobol 1967), reducing variance at fixed spp without changing the estimator's expectation (P3).

17.2 Detailed Implementation Steps

  1. Implement stratified 2D sample generation: subdivide [0,1)² into an n × m grid matched to the configured spp, jitter one sample per cell.
  2. Implement the Sobol sequence generator with Owen scrambling, allocating one dimension pair per path-vertex decision (camera lens, BSDF direction, light direction) via SampleDimension (§11) so successive bounces do not reuse correlated dimensions.
  3. Extend Sampler (§11) with a Stratified and a Sobol implementation behind the existing trait; raytracer-cli selects one via RenderConfig (ADR-08).
  4. Verify the change-of-sampler is expectation-preserving (P3): render the Phase 4 Cornell-box fixture with each sampler at matched spp and compare converged means.
  5. Implement the 1/√N convergence-rate measurement harness: render the white-furnace and Cornell-box fixtures at 4×, and measure the variance ratio against the theoretical 1/N law (I7).

17.3 Deliverable

A configurable sampler (independent / stratified / Sobol) with measured variance reduction at matched spp for stratified and Sobol vs. the Phase 1 independent baseline, and a passing 1/√N convergence-rate test (I7).

17.4 Acceptance Criteria

  • Stratified sampling reduces per-pixel variance on the Cornell-box fixture by ≥ 30% at 64 spp vs. independent sampling at the same spp, with matched converged means (within 0.5%, P3).
  • Sobol/Owen-scrambled sampling reduces variance by ≥ 50% at 64 spp vs. independent sampling, matched means within 0.5%.
  • Measured variance-vs-N slope across {64, 256, 1024, 4096} spp matches the theoretical 1/N law within 10% relative error on log-log regression (I7).
  • No visible structured pattern (banding, moiré) in a 64-spp Sobol render of a smooth-gradient test scene (regression against the "PBRT sampling bugs" lesson catalogued in §33-adjacent history).

17.5 Conformance Fixtures

  • phase5_variance_comparison.json — same scene rendered with all three samplers at matched spp; expected: variance ordering independent > stratified > Sobol, means matched.
  • phase5_convergence_rate.json — the white-furnace scene at {64, 256, 1024, 4096} spp; expected: 1/N variance slope within 10% (I7).
  • phase5_pattern_check.json — a smooth radial gradient synthetic scene; expected: no visible structured artifact at 64 spp Sobol (visual + FFT-based periodicity check).

17.6 Pitfalls

  • Reusing the same Sobol dimension index across different path-vertex decisions (e.g., camera lens sample and first-bounce BSDF sample sharing a dimension) reintroduces correlation the low-discrepancy sequence was supposed to remove.
  • Per-thread RNG seeded by thread ID rather than by (pixel, sample_index) produces cross-pixel correlation invisible at low spp but visible as blocky patterns at high spp.
  • Stratification grid dimensions not matching the configured spp (e.g., requesting 100 spp with a 10×10 grid but rounding spp down silently) silently changes the requested sample count.

17.7 Performance Concerns

Sobol/Owen scrambling has higher per-sample generation cost than independent PRNG (roughly 2-3× per §30 profiling methodology); this is offset by needing fewer total samples for the same noise target, and the net effect is measured, not assumed, via the M-series targets in §30.

17.8 Edge Cases

Requesting 1 spp with stratified sampling degenerates to a single jittered sample per pixel (equivalent to Phase 1's baseline) — must not divide-by-zero on a 1×1 stratification grid.

17.9 Failure Analysis

A convergence-rate test that fails (measured slope far from 1/N) most commonly traces to a sampler bug that reintroduces correlation (17.6); the debugging methodology bisects by reverting to independent sampling and re-measuring, isolating whether the fault is in the estimator (Phase 4) or the sampler (this phase).

17.10 Operational Notes

The active sampler type is recorded in the render's metadata alongside the seed (P12, §27), so a regression bisect can distinguish a sampler-caused variance change from an integrator-caused one.

18. Phase 6 — The Microfacet BSDF System (GGX Metal and Dielectric)

18.1 Objectives

Implement Microfacet (GGX metal, Walter et al. 2007, Cook & Torrance 1982) and Dielectric (smooth and rough transmission) BSDFs with Heitz 2014 visible-normal importance sampling and Schlick-approximated Fresnel, extending the Phase 4 Lambertian-only material system.

18.2 Detailed Implementation Steps

  1. Implement the GGX normal distribution D, height-correlated Smith masking-shadowing G, and Schlick Fresnel F exactly per §8's equations (Walter et al. 2007, Heitz 2014).
  2. Implement Heitz 2014 visible-normal sampling: sample a half-vector h visible from ω_o, derive ω_i = reflect(ω_o, h), and derive the transformed PDF via the reflection Jacobian (§8 GGX sampling density) — required by I2 to match Microfacet::pdf exactly.
  3. Implement Microfacet::f assembling D · G · F / (4 cosθ_o cosθ_i) (§8 microfacet BRDF assembly equation), clamping to zero when ω_i/ω_o are on the wrong side (P5).
  4. Implement Dielectric: Fresnel-weighted stochastic choice between reflection and refraction (Snell's law), handling total internal reflection by forcing reflection when sinθ_t > 1; implement Beer's-law absorption for tinted glass as an exponential decay of throughput per unit distance traveled inside the medium.
  5. Implement roughness clamping (minimum α) to avoid numerical degeneration of GGX sampling at near-zero roughness (Burley 2012 remapping convention); below the clamp, treat the BSDF as a delta (specular) distribution and flag BsdfFlags::specular so the integrator skips NEE at that bounce (P9-adjacent specular handling).
  6. Extend the integrator's specular-bounce handling: when flags().specular, skip light sampling entirely (a specular BSDF's pdf is a delta, undefined for arbitrary directions).
  7. Extend the white-furnace conformance test (I1) to cover GGX metal and dielectric materials, not just Lambertian, since energy conservation must hold for every BSDF (P1).

18.3 Deliverable

Rough copper, brushed aluminum (metallic GGX), and frosted/clear dielectric spheres rendering with correct Fresnel reflectance at grazing angles and passing the extended white-furnace test for all three material types.

18.4 Acceptance Criteria

  • GGX-metal white-furnace test converges to within 1% relative error of source radiance across roughness values {0.05, 0.2, 0.5, 0.9} (extends I1 across the roughness range).
  • Dielectric white-furnace test (a glass sphere in a uniform environment) converges within 1.5% relative error, accounting for both reflected and transmitted paths.
  • Chi-square PDF-consistency test (I2) passes for Microfacet::sample_f/pdf at p-value > 0.01 across 4 roughness values and 4 incident angles.
  • Heitz 2014 visible-normal sampling shows ≥ 2× lower variance than Walter et al. 2007's original angular sampling on a matched-spp glossy-highlight test scene (quantifies the literature's claimed improvement, §33-adjacent history).

18.5 Conformance Fixtures

  • phase6_ggx_white_furnace.json — metal spheres at 4 roughness values inside a uniform emitter; expected converged radiance within 1% of source (I1 extension).
  • phase6_dielectric_white_furnace.json — glass sphere, same environment; expected within 1.5%.
  • phase6_pdf_chisquare.json — a fixed (ω_o, α) configuration sampled 100,000 times; expected chi-square p-value > 0.01 against the analytic pdf (I2).
  • phase6_fresnel_grazing.json — a dielectric plane viewed at increasing grazing angles; expected: reflectance approaches 1.0 monotonically per the Fresnel equations (§8).

18.6 Pitfalls

  • Using the uncorrelated (separable) Smith G instead of the height-correlated form loses energy at grazing angles on rough surfaces — a subtle deviation from Heitz 2014 that a screenshot would not catch but the white-furnace test (18.4) does.
  • Forgetting the reflection Jacobian when transforming the half-vector PDF to the incident-direction PDF silently breaks I2 while sample_f still "looks" plausible.
  • Schlick Fresnel applied to the wrong angle (using ω_i · n instead of ω_o · h) produces physically wrong grazing behavior that only shows up at extreme angles (18.5's grazing fixture).
  • GGX sampling below the roughness clamp without switching to a delta/specular path numerically degenerates (near-zero-probability samples, fireflies) instead of being treated as mirror reflection.

18.7 Performance Concerns

Microfacet evaluation and sampling involve more transcendental function calls (sqrt, tan, trigonometric terms) than Lambertian's closed form; §30's benchmark methodology isolates BSDF evaluation cost per-material-type to keep the ~20% BSDF-cost share (§15.7 projection) accurate even as material complexity grows.

18.8 Edge Cases

A roughness of exactly 0.0 must route through the specular delta path (18.2 step 5), never through the general GGX sampling code path, to avoid a divide-by-zero in D_GGX at α = 0. A dielectric with ior = 1.0 (matched to the surrounding medium) must produce zero reflectance and full transmission with no bending, a degenerate but valid configuration.

18.9 Failure Analysis

Over-bright specular highlights (radiance exceeding the light's own radiance) trace to either a missing Smith G term, a V-cavity (rather than height-correlated) G approximation, or a sampling routine lacking the visible-normals correction; the debugging methodology isolates the cause by substituting each term with its "obviously correct but slow" reference implementation one at a time.

18.10 Operational Notes

Per-material energy-conservation ratios (18.4's white-furnace metrics) are logged per conformance run and tracked over time on the §26 dashboard as bsdf_energy_ratio{material}, so a future dependency bump (e.g., a libm transcendental-function change) that silently shifts the ratio is caught by trend, not just by threshold.

19. Phase 7 — Area and Environment Lights with Importance Sampling

19.1 Objectives

Implement AreaLight and EnvironmentLight (§11) with next-event-estimation (NEE) sampling and per-light importance sampling — a 2D CDF over an environment map's luminance (with the sinθ solid-angle correction) and, for area lights, uniform-area sampling transformed to solid-angle measure.

19.2 Detailed Implementation Steps

  1. Implement AreaLight::sample_li: sample a point on the light's shape uniformly by area, convert to solid-angle measure via pdf(ω) = distance² / (cosθ_l · area) (§8, §9-equivalent light-sampling density).
  2. Implement AreaLight::pdf_li as the exact inverse of the sampling transform in step 1, so I2 holds for lights as well as BSDFs.
  3. Implement the HDR environment-map loader (image-based lighting, Cook, Porter & Carpenter 1984 distributed-sampling lineage) and EnvironmentLight::sample_li via a precomputed 2D CDF over pixel luminance weighted by sinθ for the spherical area element.
  4. Implement EnvironmentLight::pdf_li as the density implied by the same CDF, converted from image (u, v) space to solid angle via the sinθ Jacobian — the single most commonly miscomputed step in environment importance sampling.
  5. Implement the integrator's next-event-estimation step: at every non-specular bounce, sample one light (uniform light selection, ADR-12), trace a shadow ray, and add the direct-lighting contribution weighted by the light's PDF (not yet combined with BSDF sampling via MIS — that is Phase 8).
  6. Implement double-counting avoidance: skip adding self-emission on a BSDF-sampled bounce that hits an area light's shape, since NEE already accounted for direct light at every non-specular vertex (temporary rule, superseded by proper MIS weighting in Phase 8).
  7. Extend the degenerate-input handling (§8): a light with zero area is rejected at scene-load time (14.2's loader-validation pattern extended to lights).

19.3 Deliverable

Cornell-box and HDRI-lit scenes with physically plausible soft shadows (area-light penumbrae) and correct glossy reflections of the environment map, at markedly reduced spp vs. Phase 4/6's BSDF-only sampling for the same noise level.

19.4 Acceptance Criteria

  • Cornell-box with an area light at 64 spp with NEE matches the Phase 4/6 BSDF-only-sampling 1024-spp reference to within 2% RMSE (quantifies the "NEE needs far fewer samples" domain claim).
  • A sphere lit solely by a uniform environment light matches its closed-form analytic answer (irradiance = π × environment radiance for a diffuse sphere under uniform lighting) to within 1% relative error (an analytic-scene acceptance gate, not just a reference-image diff).
  • Environment-map importance sampling shows ≥ 3× variance reduction vs. uniform environment sampling on a scene with a small bright sun disk in the HDRI, at matched spp.
  • AreaLight::pdf_li matches AreaLight::sample_li's implied density via chi-square test (I2) at p-value > 0.01.

19.5 Conformance Fixtures

  • phase7_area_light_nee.json — Cornell box with one area light; expected: 64-spp NEE render within 2% RMSE of the 1024-spp BSDF-only reference.
  • phase7_sphere_uniform_env_analytic.json — a diffuse sphere under uniform environment radiance; expected: matches the closed-form π · L_env answer within 1%.
  • phase7_env_importance_sun.json — an HDRI with a small bright sun disk; expected: ≥ 3× variance reduction with importance sampling vs. uniform sampling at matched spp.
  • phase7_zero_area_light.json — a light with a degenerate zero-area shape; expected: rejected at load time (RenderError::SceneParse), not a runtime division by zero.

19.6 Pitfalls

  • Forgetting the sinθ Jacobian when converting an environment map's (u, v) CDF sample to a spherical direction biases the sampling density near the poles, silently violating I2.
  • Picking lights uniformly at random becomes inefficient once many lights of very different power exist — acceptable for Phase 7's scope (ADR-12) but flagged as the upgrade path to a light-tree.
  • Double-counting emission (adding both the NEE contribution and the BSDF-sampled bounce's self-emission at the same vertex) inflates direct lighting — the temporary skip-emission rule (19.2 step 6) must be applied consistently until Phase 8's proper MIS weighting replaces it.
  • A shadow ray's t_max not set to just short of the light's distance (missing the epsilon trim) can self-intersect the light's own geometry (I11-adjacent).

19.7 Performance Concerns

NEE adds one shadow ray per non-specular bounce (§4's "plus shadow rays" ray-count model, used again in §34's capacity model); the environment CDF sampling adds a one-time O(log(W×H)) binary search over the precomputed CDF per sample, a small constant-factor cost relative to the variance reduction achieved.

19.8 Edge Cases

An environment map with a single all-zero (black) pixel row must not produce a zero-probability CDF bucket that the sampler can still select (guard the CDF construction against exact-zero runs). A scene with only an environment light and no area lights must skip area-light selection entirely rather than dividing by a zero light count.

19.9 Failure Analysis

"Caustics never appear" is expected and documented, not a bug: NEE from a diffuse surface cannot see through a dielectric to a light behind it, and BSDF sampling from the diffuse surface rarely finds the correct specular-transmission direction; this is a known limitation of unidirectional path tracing (ADR-06) resolved only by the rejected architectures in §36, not fixed in this phase.

19.10 Operational Notes

The phase7_sphere_uniform_env_analytic fixture (19.5) is the first analytic (not reference-image) conformance test in the suite and is prioritized in conformance.yml because it catches light-sampling PDF bugs (I2) independent of any stored reference image drifting due to unrelated renderer changes.

20. Phase 8 — Multiple Importance Sampling

20.1 Objectives

Combine Phase 6's BSDF sampling and Phase 7's light (NEE) sampling via multiple importance sampling (Veach & Guibas 1995, ADR-13 power heuristic), replacing the Phase 7 temporary skip-emission rule with correctly weighted double-strategy estimation (I6).

20.2 Detailed Implementation Steps

  1. Implement mis_balance(pdf_a, pdf_b) and mis_power(pdf_a, pdf_b) (§8 MIS equations); default to the power heuristic (ADR-13), keep the balance heuristic available for the I6 weight-sum test.
  2. At each non-specular vertex, sample the light (as in Phase 7) and weight its contribution by w_light = mis(light_pdf, bsdf_pdf(ω_i)), where bsdf_pdf is the BSDF's own pdf evaluated at the light-sampled direction (P9: reusing the BSDF's existing pdf method, never a re-derivation).
  3. Also sample the BSDF (as in Phase 4/6) and, if the resulting ray hits an emissive surface, weight that contribution by w_bsdf = mis(bsdf_pdf, light_pdf(ω_i)), where light_pdf is computed by asking the hit light's pdf_li for the sampled direction.
  4. Remove the Phase 7 skip-emission special case entirely; emission is now added at every hit (specular or BSDF-sampled) weighted correctly by w_bsdf, with w_bsdf = 1 when the previous bounce was specular (a specular BSDF has no light-sampling competitor, §8 specular handling).
  5. Implement the I6 weight-sum property test: for a fixed scattering event with both strategies active, assert w_light + w_bsdf ≈ 1 for every sampled direction pair (accounting for the fact each strategy samples an independent direction — the test checks the heuristic function directly, not a single realized path).
  6. Re-run and update the Phase 4/6/7 conformance fixtures under MIS to confirm the acceptance thresholds tighten (fewer spp needed for the same RMSE).

20.3 Deliverable

The Cornell-box and GGX-metal/dielectric conformance scenes rendering under full MIS, with spp requirements roughly halved relative to Phase 7's NEE-only numbers for the same RMSE target, and glossy-highlight scenes (small light, low-roughness BSDF) converging cleanly for the first time in the arc.

20.4 Acceptance Criteria

  • Cornell-box with area light under MIS at 32 spp matches the Phase 7 64-spp NEE-only RMSE (≤ 2%), confirming the domain claim that "each step roughly halves required samples."
  • A glossy-highlight scene (small area light, GGX roughness 0.05) under MIS at 128 spp shows ≤ 5% RMSE against a 4096-spp reference, whereas BSDF-only sampling (Phase 6) at 128 spp exceeds 20% RMSE on the same scene (quantifies MIS's value specifically for glossy-plus-small-light configurations).
  • I6 weight-sum property test passes for 10,000 randomized (ω_o, material, light) configurations, |w_light + w_bsdf − 1| < 1e-5.
  • White-furnace test (I1) still passes under MIS for all three material types (regression check — MIS must not introduce an energy bug).

20.5 Conformance Fixtures

  • phase8_cornell_mis.json — same Cornell box as phase7_area_light_nee; expected: 32-spp MIS RMSE ≤ the 64-spp NEE-only RMSE recorded in Phase 7.
  • phase8_glossy_small_light.json — small area light, low-roughness GGX metal; expected: MIS RMSE ≤ 5% at 128 spp vs. BSDF-only's ≥ 20% at the same spp.
  • phase8_mis_weight_sum.json — 10,000 randomized configurations; expected: weight sum within 1e-5 of 1.0 (I6).
  • phase8_white_furnace_regression.json — re-run of phase6_ggx_white_furnace and phase6_dielectric_white_furnace under MIS; expected: same ≤1%/≤1.5% thresholds hold (I1 regression gate).

20.6 Pitfalls

  • Computing bsdf_pdf via a separate re-derivation instead of calling the BSDF's own pdf method (P9) is the most common way to silently violate I6 — the two must be bit-for-bit the same code path.
  • Forgetting to set w_bsdf = 1 after a specular bounce (where light sampling was skipped entirely) causes MIS to under-weight the only strategy that produced a sample.
  • Applying MIS weights to the wrong PDF (e.g., using the light-sampling PDF in solid-angle measure at the wrong reference point) reintroduces the double-counting bug Phase 7's temporary rule was covering for.
  • Balance vs. power heuristic mismatch between what's implemented and what's documented in ADR-13 makes the "power heuristic usually wins" claim untestable — keep both available for the I6 test specifically.

20.7 Performance Concerns

MIS roughly doubles the per-vertex PDF-evaluation cost (each strategy now evaluates the other's density) but the net effect is a large variance reduction at fixed spp, so wall-clock time to a target RMSE decreases even though per-sample cost increases slightly — measured, not assumed, against the Phase 7 baseline (20.4).

20.8 Edge Cases

A light-sampled direction that the BSDF assigns exactly zero probability (e.g., a direction below the horizon for a Lambertian BSDF) must yield w_light = 1 (the other strategy has zero weight) rather than a division by zero in the heuristic. A BSDF-sampled ray from a specular bounce that hits a light must not attempt to compute a light-sampling MIS weight since no light sample was drawn at that vertex.

20.9 Failure Analysis

A rendered image with subtle double-brightening at direct-light-visible surfaces (visible only in a difference image against a NEE-only or BSDF-only reference, not to the naked eye) traces to an I6 violation; the debugging methodology isolates it via the phase8_mis_weight_sum property test before touching the full integrator.

20.10 Operational Notes

The MIS heuristic choice (balance/power) is recorded in render metadata (§27) since it is a correctness-neutral but noise-affecting configuration choice, distinct from a seed or sampler choice but tracked the same way for regression bisection.

21.1 Objectives

Implement the Texture trait, image-texture loading, a box-filtered MipMap chain, ray differentials (RayDifferential, §11) for mip-level selection, and tangent-space normal mapping (ADR-17), replacing Phase 0–8's flat per-primitive albedo with sampled material parameters.

Propagate RayDifferential (already a Phase 0 type, unused until now) through the integrator: primary rays carry auxiliary rx/ry offset rays one pixel apart; each bounce transforms the differential per the surface's local curvature (approximate, per pbrt's reflection/refraction differential transfer).

21.3 Deliverable

Textured, normal-mapped meshes (e.g., a textured Cornell box floor, a normal-mapped rough-metal sphere) rendering without minification aliasing at grazing/distant camera angles, using the mip chain driven by ray differentials.

21.4 Acceptance Criteria

  • A high-frequency checkerboard texture viewed at a grazing, distant angle shows ≤ 2% RMS aliasing energy (measured via a high-frequency FFT band on the rendered image) with mipmapping enabled, vs. > 15% with mipmapping disabled (nearest/level-0 only, ADR-15/16 regression contrast).

21.5 Conformance Fixtures

  • phase9_normal_map_tangent.json — 100 randomized tangent-frame/UV configurations; expected: ≤ 1e-4 error against an independent transform.

21.6 Pitfalls

  • Bypassing the mip chain for a "quick" raw texel lookup anywhere reintroduces the exact aliasing the phase exists to eliminate (P13).
  • Conflating the perturbed shading normal with the geometric normal used for ray offsetting reintroduces self-intersection artifacts at silhouettes under bump-mapped materials (P5, I11).
  • An inconsistent tangent-frame handedness convention between the asset pipeline (glTF, ADR-22) and the normal-map decoder flips bump direction on some meshes but not others.
  • Ray-differential transfer at a specular bounce (mirror, glass) requires a different transform than a diffuse bounce; using the diffuse transform everywhere produces wrong mip selection behind mirrors/glass.

21.7 Performance Concerns

Mipmap memory adds ~33% over the base texture size (§34's 4/3 mip-overhead formula); the 512 MB texture-cache ceiling (§4) bounds total resident texture memory via LRU eviction of unused tiles, keeping large scenes within the memory ceiling in §4's table.

21.8 Edge Cases

A texture with non-power-of-two dimensions must still build a valid mip chain (box-filter padding to the next level, not a hard requirement of power-of-two input). A UV coordinate outside [0,1) must wrap or clamp per a per-texture addressing mode, never index out of bounds (I12).

21.9 Failure Analysis

Visible moiré or shimmering in an otherwise-correct render traces to either a missing/incorrect ray-differential transfer at a bounce (21.6) or an off-by-one in mip-level selection; the debugging methodology renders the same scene at level-0-only and at the selected mip level side by side to isolate which.

21.10 Operational Notes

Texture cache hit/miss rates and resident memory are added to RenderStats and the §26 dashboard as texture_cache_hit_rate and texture_cache_resident_bytes, since a cache-thrash regression (too many working textures for the 512 MB ceiling) manifests as a performance regression indistinguishable from a BVH regression without this metric.

22. Phase 10 — Depth of Field, Tone Mapping, Progressive Preview and the Denoiser Seam

22.1 Objectives

Complete the camera model with thin-lens depth of field (Cook, Porter & Carpenter 1984), add the tone-mapping stage (Reinhard et al. 2002), wire the progressive-preview emitter, and define the denoiser seam trait (ADR-21) — the last phase before conformance hardening (Phase 11).

22.2 Detailed Implementation Steps

  1. Implement the thin-lens CameraSample.p_lens consumption (§8 thin-lens equations): sample a point on the aperture via a concentric-disk mapping, compute the focus point along the pinhole ray at focus_distance, and re-aim the ray from the lens-offset origin through the focus point.
  2. Implement the tone-mapping stage as a pure function (P10) from the film's linear-radiance buffer to a display-referred buffer, using the extended Reinhard curve (§8 equation) with a configurable L_white.
  3. Implement the linear-to-sRGB transform as a separate, final step after tone mapping (ADR-10), never fused into the tone curve itself, so either stage can be swapped independently.
  4. Implement the progressive-preview emitter: at a configurable cadence (e.g., every N completed tiles or T seconds), snapshot the current film state (a consistent read of the atomic accumulators) and serialize it to a preview directory or socket without blocking in-flight tile workers.
  5. Define the Denoiser trait (the seam, ADR-21): takes a film snapshot (plus optional auxiliary buffers — albedo, normal — for a future guided denoiser) and returns a denoised buffer; ship a no-op passthrough implementation only, no trained model.
  6. Wire the output writer to accept PNG and OpenEXR (RFC/Spec §5) in addition to Phase 0's PPM, selected by RenderConfig/file extension.
  7. Wire a bounded backpressure mechanism (ADR-27) on the preview-snapshot cadence so a slow consumer of the preview stream cannot stall the render loop.

22.3 Deliverable

A Cornell-box render with visible depth-of-field blur at a configured aperture/focus distance, a tone-mapped and gamma-correct PNG/OpenEXR output, a live progressive-preview stream observable during the render, and a passthrough denoiser seam ready for a future model.

22.4 Acceptance Criteria

  • Thin-lens depth-of-field blur radius at a known defocus distance matches the analytic circle-of-confusion formula (aperture_radius × |focus_distance − object_distance| / object_distance, scaled by focal length) within 5% on a synthetic test scene with known geometry.
  • Tone-mapped output matches the extended Reinhard formula (§8) applied out-of-band to the raw film buffer within 1e-4 per channel (a pure-function regression test, P10).
  • OpenEXR output round-trips through an independent EXR reader with linear radiance values matching the film buffer within 1e-5 (no precision loss through the write path).
  • Progressive-preview snapshots never block a tile worker for more than 1 ms (measured via the §30 profiling methodology) and never emit a torn (partially-written) frame.

22.5 Conformance Fixtures

  • phase10_dof_coc.json — a scene with known object/focus distances; expected: measured blur radius within 5% of the analytic circle-of-confusion formula.
  • phase10_tonemap_regression.json — a fixed synthetic HDR film buffer; expected: tone-mapped output matches the out-of-band Reinhard computation within 1e-4.
  • phase10_exr_roundtrip.json — render, write OpenEXR, re-read via an independent library; expected: values match within 1e-5.
  • phase10_preview_nonblocking.json — a long render with preview snapshots enabled; expected: zero torn frames across 100 snapshots, worker stall < 1 ms per snapshot.

22.6 Pitfalls

  • Fusing gamma correction into the tone-mapping curve instead of keeping them as separate pure functions (P10) makes either stage impossible to swap or test independently.
  • Sampling the lens with a naive square-mapped random pair instead of a concentric-disk mapping produces non-uniform bokeh density (visible as a squarish, non-circular defocus blur).
  • Snapshotting the film for preview without a consistent read (e.g., reading sum and count from different points in time under concurrent writes) produces a preview frame with visible tearing, even though the final accumulated result remains correct.
  • Treating the denoiser seam as "done" because the trait compiles, without a passthrough regression test, risks a future real implementation silently changing radiance values in a supposedly opt-in-only path (ADR-07 bias-labelling requirement).

22.7 Performance Concerns

Depth-of-field sampling adds one extra 2D sample per camera ray (lens position) — negligible per-ray cost, but increases the total sample-dimension budget the sampler (Phase 5) must supply without dimension reuse (17.6's pitfall, revisited here for the camera's own dimensions).

22.8 Edge Cases

An aperture_radius of exactly 0.0 must degenerate to the Phase 1 pinhole camera exactly (no blur), not a divide-by-zero in the concentric-disk mapping. A focus_distance of 0 or negative is rejected at scene-load time as a RenderError::SceneParse.

22.9 Failure Analysis

A progressive-preview stream that appears to "freeze" while the final render continues correctly traces to the bounded backpressure mechanism (22.2 step 7) discarding snapshots when the consumer is slow, by design (ADR-27); this is documented behavior, not a bug, and is distinguished from an actual render hang by checking RenderStats::rays_traced continuing to increase.

22.10 Operational Notes

The denoiser seam's no-op passthrough is exercised in every conformance run so that a future real denoiser integration only needs to change one trait implementation, not the surrounding pipeline; the progressive-preview cadence is configurable per §26's operational runbooks.

  • phase11_seeded_replay_full_config.json — the full default render configuration at fixed seed; expected: bit-exact match across two runs (I9).

23.6 Pitfalls

  • Setting per-fixture tolerances too loosely to make the suite pass defeats the entire purpose of the gate (P4) — tolerances must be derived from the fixture's own known noise floor at its configured spp, not chosen to make a broken build green.
  • A differential comparison against Mitsuba 3 that ignores legitimate RNG-sequence differences (which are not a bug) risks either false failures or, worse, a tolerance loosened so much it stops catching real bias.
  • A soak test run on a machine under variable load (shared CI runner) can show apparent memory growth that is actually OS-level noise, not a leak — run the soak on a dedicated, isolated machine.
  • Perf-regression gating without a stable baseline (e.g., comparing against a baseline recorded on different hardware) produces false positives that erode trust in the gate.

23.7 Performance Concerns

This phase is where every prior phase's quantified acceptance criteria are re-verified together under production load (full scene complexity, full spp budget); the M-series targets in §30 are the authoritative source of truth, and this phase's job is enforcement, not redefinition.

23.8 Edge Cases

A fixture that passes in isolation but fails only when run as part of the full parallel conformance suite (resource contention, e.g., texture-cache thrashing across concurrently running fixtures) must be isolated to its own CI job rather than silently tolerated.

23.9 Failure Analysis

A newly failing fixture after an unrelated dependency bump (e.g., a libm version change altering transcendental-function rounding) is triaged by first checking whether the failure is within the fixture's documented Monte Carlo noise floor before treating it as a regression; if it exceeds the floor, the bisection follows the §7 debugging methodology.

Named metrics: rays_per_second, average_path_depth, bvh_traversal_steps_per_ray, nan_sample_count, firefly_count (clamped-mode only), per_tile_variance_estimate, convergence_rate (measured 1/N slope, I7), bvh_build_time_ms, bvh_node_count, texture_cache_hit_rate, texture_cache_resident_bytes, rr_terminated_count.

Tracing spans: one tracing span per pipeline stage (§3) — scene_load, bvh_build, tile_schedule, camera_ray_gen, bvh_traverse, integrate, bsdf_eval, light_sample, texture_eval, film_accumulate, tonemap, denoise, output_write — each tagged with tile ID and thread ID for cross-thread correlation (ADR-23).

Structured logging: JSON-formatted log lines keyed by render ID, scene hash, seed, and phase-stage span; RenderError variants log at error level with the offending file/line; invariant violations (I1–I13) log at warn or error depending on whether an auto-recovery path exists (§25).

Dashboards: a per-render dashboard plotting rays_per_second and per_tile_variance_estimate over wall-clock time; a per-fixture conformance-history dashboard plotting bsdf_energy_ratio and RMSE-vs-tolerance trends across CI runs (§18.10, §23).

Alerting philosophy: alert on invariant violations with no auto-recovery path (I3/I4 mismatches, I6 weight-sum failures) as build-blocking; alert on metrics crossing an M-series threshold (§30) as a performance regression, not a correctness failure — the two alert classes route to different on-call playbooks.

SLOs: render-time budget of < 15 minutes for the Cornell-box-class reference scene at the §4 target resolution/spp (Phase 11 gate); scene-load + BVH-build budget of < 5 s for a 1M-triangle scene (§4); checkpoint-restore RTO of < 30 s (§4).

Incident response: an SLO breach or a build-blocking invariant alert pages the on-call engineer, who first checks the relevant named runbook before ad hoc debugging.

Named runbooks (docs/runbooks/, §10): firefly-triage.md (FM-1), energy-loss-bisect.md (FM-3), bvh-degeneracy-diagnosis.md (FM-5), nondeterminism-hunt.md (FM-6).

Backup/restore of render checkpoints: the film's per-pixel accumulators (sum, sum_sq, count) are periodically serialized to a checkpoint file; restore re-hydrates the film and resumes tile scheduling from the last incomplete tile set, meeting the < 30 s RTO (§4).

Deployment topology for a render farm: a job scheduler distributes independent scenes (or independent tile ranges of one large scene) across worker machines, each running the raytracer-cli binary with a pinned toolchain (ADR-26) for cross-machine reproducibility; results are collected and merged (for split-tile-range jobs) or archived independently (for independent-scene jobs).

Canary/rollback/migration: a new renderer binary version is canaried on a subset of farm machines against the conformance.yml fixture manifest before full rollout; a canary failure blocks rollout and triggers rollback to the last known-good binary; scene-format migrations (§27) run through a documented converter before being accepted by a new binary version.

27. Compatibility & Versioning

Scene format versioning: the custom JSON scene wrapper (ADR-22) carries an explicit schema_version field; the loader rejects a schema_version newer than it understands rather than guessing at forward compatibility.

Material-parameter semantics across versions: a material parameter's meaning (e.g., roughness under the Burley 2012 remapping convention) is locked per schema_version; a future change to the remapping convention ships as a new schema_version, never a silent reinterpretation of existing scene files.

Render reproducibility guarantees and what breaks them: a fixed seed, scene, and thread count reproduce a bit-identical image (I9) under a pinned toolchain (ADR-26) with FMA contraction disabled. This guarantee breaks under: a changed thread count (changes tile scheduling order and hence floating-point summation order); enabled FMA contraction (changes rounding); a changed math-library (libm) version (changes transcendental-function rounding, FM-10-adjacent); a changed sample-ordering scheme (a sampler-dimension reassignment, §17.6).

Checkpoint format: versioned alongside the film's Pixel layout; a checkpoint written by one binary version is only guaranteed restorable by the same or a documented-compatible later version (§26 backup/restore).

API stability: the crate-level public API (§10, §11 types) follows SemVer; a Bsdf/ Light/Primitive trait signature change is a MAJOR version bump; a new optional field on RenderConfig with a documented default is a MINOR bump; a bug fix that does not change any public signature is a PATCH bump.

Migration and deprecation: a deprecated scene-format field is accepted with a load-time warning for one MAJOR version cycle before removal; a migration tool (tools/, §10) upgrades scene files between schema_versions.

Rolling-upgrade guarantees: a render farm may run mixed binary versions during a rolling upgrade only if both versions share the same MAJOR version and the same pinned toolchain/math library (ADR-26); mixed-MAJOR-version farms are not supported because I9's reproducibility guarantee does not extend across MAJOR versions.

28. Testing & Verification Strategy

Unit tests: closed-form checks per type — ray-triangle/ray-sphere intersection against independent analytic solves (§14.4, §12.4), BVH slab-test edge cases (§15.8).

Integration tests: full scene-load → build → render → write pipelines on the Phase 2/3 fixtures (bunny, Cornell box).

Property tests (proptest): a BSDF's pdf matches the empirical density of its sample_f via a chi-square test (I2, §18.4, §19.4); the white-furnace test conserves energy within a stated tolerance (I1, §16.4, §18.4); MIS weights sum to one (I6, §20.4); the BVH agrees with brute-force intersection on a random ray set (I3, I4, §15.4); the estimator's error falls as 1/√N (I7, §17.4).

Differential testing: against Mitsuba 3 on shared analytic scenes (white-furnace, Cornell box), comparing RMSE (§23.2, §23.4) — catches systematic bias invisible to internal self-consistency tests.

Fuzzing: cargo-fuzz targets on the scene-JSON and glTF parsers (T1, T6), run on a schedule (fuzz.yml) and on every PR touching raytracer-io.

Chaos / fault injection: killing a tile-worker thread mid-render and verifying the CLI surfaces a RenderError rather than writing a silently incomplete image (§13.9); simulating a slow preview consumer and verifying the bounded-backpressure path (FM-9) engages correctly.

Deterministic seeded replay: bit-exact (or tolerance-bounded per ADR-26's FMA note) comparison across two runs of the same seed/scene/thread-count (I9, §23.4, §23.5).

Soak testing: a 24-hour continuous render watching for memory growth, variance-estimate drift, or NaN accumulation (§23.2, §23.4, FM-11).

Conformance scenes with published reference images: the full manifest consolidated in Phase 11 (§23.2), covering analytic scenes (white-furnace, a sphere under uniform environment light with a closed-form answer), degenerate geometry, seeded-replay, and regression cases with numeric tolerances.

Perf-regression gating: perf-regression.yml runs the §30 benchmark suite against the M-series targets on every PR, failing on a regression beyond a configured margin.

Every property/differential/soak test above ties back to a specific invariant (I1–I13) and to the phase N.5 fixture that first introduced its scenario, so a test failure always names both "what broke" (the invariant) and "where it was first specified" (the phase fixture).

29. Build & Release Engineering

Reproducible builds: pinned Rust toolchain version (rust-toolchain.toml), Cargo.lock committed and enforced (--locked in CI), disabled FMA contraction in release profile (ADR-26) so a given source revision always produces bit-identical render output on identical hardware.

Artifact signing: release binaries are signed (e.g., via cosign or GPG) and the signature published alongside the artifact in release.yml.

SBOM: a software bill of materials is generated per release (cargo-cyclonedx or equivalent) enumerating every dependency and version, feeding the T8 supply-chain mitigation.

Release channels: stable (tagged SemVer releases), nightly (main-branch builds for early testing, not reproducibility-guaranteed against stable).

CI/CD topology: ci.yml (build/test/lint) → conformance.yml (reference-image regression gate, §28) → perf-regression.yml (benchmark gate, §30) → fuzz.yml (scheduled) → release.yml (signed artifact publishing, gated on all prior jobs passing).

Version stamping: each binary embeds its SemVer version, git commit hash, and toolchain version in RenderStats/render metadata, so a rendered image's provenance is always recoverable (ties into §27's reproducibility guarantees).

Provenance / attestation: release.yml publishes a build-provenance attestation (e.g., SLSA-style) tying the signed artifact to the exact CI run and source commit that produced it.

Dependency auditing: cargo audit runs on a schedule and on every dependency-bumping PR (T8); a new advisory blocks merge until triaged.

Math/compiler pinning that preserves render reproducibility: the pinned toolchain (rust-toolchain.toml) and disabled FMA contraction together are the two settings that most directly protect I9 and are therefore change-controlled — any bump requires a full conformance.yml re-baseline, not just a passing build.

31. Scalability Analysis

What stays constant vs. grows, with Big-O: BVH traversal is logarithmic in primitive count (O(log N) per ray under a balanced tree, ADR-04); the integrator's total cost is linear in samples × pixels × average_path_depth (§34); BVH build is O(N log N) in triangle count (Wald 2007). Film memory is constant in sample count (accumulators, not per-sample storage) and linear in pixel count. Texture memory grows with scene asset budget, bounded by the §4 cache ceiling regardless of scene size (LRU eviction).

Named bottlenecks in order: (1) BVH traversal (~60% of render time once shading exists, §15.7); (2) BSDF evaluation/sampling (~20%); (3) light sampling / shadow rays (~10%); (4) camera/accumulation/other (~10%) — the same ordering carried forward from the Phase 3 projection and re-verified in Phase 11 (§23.7).

Near-linear parallel scaling and its limits: tile-parallelism (P14) scales near-linearly up to the point where film-accumulation contention (I13's atomic writes, mitigated by one-tile- one-thread ownership) or memory-bandwidth saturation (large scenes' BVH+texture working set exceeding cache, §15.7) becomes the limiter; M4 (§30) quantifies the floor.

Scaling across machines for a render farm: independent-scene jobs scale embarrassingly across machines (§26 deployment topology); a single large scene split by tile-range across machines requires a merge step and loses the single-process film-accumulator simplicity, trading it for wall-clock reduction on a single huge render.

Practical scene-size and sample-count ceiling and the levers beyond it: the practical ceiling under the §4 memory constraints is ~40–50M triangles and 1024–4096 spp on a single 32 GB-RAM machine before either memory or the M2 render-time target is exceeded; levers beyond that ceiling are: more aggressive importance sampling (Phase 7/8, reducing spp needed for a target noise level), denoising (Phase 10 seam, trading a small bias for a large spp reduction), and adaptive/per-pixel-variance-driven sampling (an extension noted but not built in Phase 0–11, since the convergence criterion in §4 is per-tile, not fully adaptive per-pixel).

32. Mental Models & First Principles

MM1. A ray tracer is a Monte Carlo integrator with a geometry oracle — all image quality questions reduce to variance questions. Predicts: noise reduction always trades against more samples or smarter sampling, never a free lunch. Bug class without it: chasing "sharper" images by tweaking BSDF math instead of variance. Resolved in §8, §17.

MM2. Importance sampling does not make the answer better, it makes the same answer arrive sooner — every sampling change must leave the expectation untouched. Predicts: unbiasedness must be independently re-verified after any sampling change. Bug class without it: renders that look "cleaner" but are silently biased. Resolved in §20 (P3).

MM3. The BVH is a spatial index, not a scene graph — it must be validated against brute force, never trusted by construction. Predicts: periodic cross-checking catches silent correctness bugs invisible to screenshots. Bug class without it: false hits/misses corrupting shading with no visible artifact pattern. Resolved in §15 (P11).

MM4. Energy conservation is a conserved quantity, like momentum — every BSDF is a candidate suspect until the white-furnace test proves otherwise. Predicts: BSDF bugs manifest as brightness drift, not obvious visual artifacts. Bug class without it: subtle over/under- brightening across material combinations that a screenshot review misses. Resolved in §16, §18 (I1).

MM5. A path's throughput is the only memory a random walk carries forward — everything else must be re-derived at each vertex. Predicts: state that leaks across bounces (a stale reused PDF) causes correctness bugs. Bug class without it: MIS/PDF mismatches that only manifest as a weight-sum violation. Resolved in §20 (P9).

MM6. Determinism is a property of the whole pipeline — RNG, thread schedule, math library — not just the algorithm. Predicts: a "correct" renderer can still be non-reproducible. Bug class without it: flaky regression tests blamed on "noise" when the real cause is thread-order- dependent summation. Resolved in §27 (I9).

MM7. Radiometric units are conserved through every transform — texture, tone curve, and BSDF each have a defined place in the unit chain, and skipping one corrupts everything downstream. Predicts: gamma/tonemap bugs that look like material bugs. Resolved in §21, §22 (P10).

MM8. A tile is the unit of parallel failure isolation — cross-tile state is the only place data races can hide. Predicts: race bugs always trace to a violation of one-tile-one-thread ownership. Resolved in §13 (P14, I13).

34. Back-of-Envelope Capacity Model

1. Total ray count (chained from §4's target: 1920×1080 @ 1024 spp, depth 8): primary-path samples = 1,920×1,080×1,024 ≈ 2.12×10⁹; path vertices = samples × avg_depth(8) ≈ 1.70×10¹⁰; shadow rays ≈ 0.7 × path vertices (fraction of non-specular bounces) ≈ 1.19×10¹⁰; total rays ≈ 2.9×10¹⁰.

2. Render wall clock: total rays ÷ rays/sec/core (M1 = 8×10⁶) ÷ cores (16) = 2.9×10¹⁰ ÷ 8×10⁶ ÷ 16 ≈ 227 s ≈ 3.8 minutes of raw traversal time — leaves headroom under the M2 < 15-minute target for BSDF evaluation, light sampling, and film accumulation overhead.

3. BVH memory: nodes ≈ 2 × triangles; for a 1M-triangle scene, 2×10⁶ nodes × 32 bytes (§8 byte layout) = 64 MB. Triangle storage: 10⁶ triangles × (3 vertices × 12 bytes position) ≈ 36 MB positions-only, rising to ≈100 MB with normals/UVs — both well inside the §4 ≤200 bytes/triangle ceiling.

4. Film memory: 1,920×1,080 pixels × 3 channels × (4 bytes sum + 4 bytes sum_sq) = 2,073,600 × 24 bytes ≈ 49.8 MB (ADR-18 f32 accumulation).

5. Samples needed for a target noise level: variance ∝ 1/N (I7), so noise (∝ √variance) ∝ 1/√N; halving noise requires 4× the samples — from the 1024-spp/1% RMSE baseline (§4), reaching 0.5% RMSE requires ≈4096 spp.

6. Texture memory with mipmaps: a geometric series 1 + 1/4 + 1/16 + ... = 4/3 of the base resolution (§21.7); a 512 MB base-texture budget therefore costs ≈683 MB with the full mip chain resident.

7. BVH build time: n log₂ n scaling (Wald 2007); for n = 10⁶, log₂(10⁶) ≈ 20; at the M5 target of ≤150 ns/triangle amortized, total build time ≈ 150 ns × 10⁶ = 150 ms, comfortably inside the §4 < 5 s scene-load-plus-build budget (M7).

8. Traversal-step estimate per ray: log₂(triangle count) node visits × per-node cost; for 10⁶ triangles, ≈20 node visits; at ≈5 ns/node (cache-resident 32-byte nodes, §8), traversal alone costs ≈100 ns/ray, leaving ≈25 ns of the 125 ns/ray budget implied by M1 (8×10⁶ rays/s/core ⇒ 125 ns/ray) for leaf-level primitive intersection tests.

36. Alternative Architectures (Roads Not Taken)

Whitted-style recursive ray tracing (no stochastic integration)

 camera ray -> [intersect] -> shade:
                                 + local direct light (hard shadow ray)
                                 + recurse: mirror reflection ray
                                 + recurse: refraction ray
               (no hemisphere sampling, no indirect diffuse bounce)
 fixed recursion depth, deterministic, zero noise, zero soft shadows, zero GI

Winning regime: real-time-adjacent preview rendering where a fast, noise-free (but physically incomplete) image is preferable to a slow, correct, noisy one. Embodying system: the original Whitted 1980 renderer and most real-time ray-traced-reflections implementations in modern game engines. Rejected here because §1's scope requires soft shadows, global illumination, and glossy reflection — exactly what Whitted-style tracing cannot produce without becoming a different algorithm.

Bidirectional path tracing / Metropolis light transport

 camera subpath: camera -> v1 -> v2 -> ...        light subpath: light -> l1 -> l2 -> ...
                       \                                    /
                        connect every (v_i, l_j) pair, weight by MIS across ALL strategies
 MLT: mutate a high-contribution path locally instead of resampling from scratch each time

Winning regime: scenes dominated by specular-diffuse-specular light paths (caustics through glass, light through a keyhole) that unidirectional sampling from either end essentially never finds. Embodying system: Veach's own PBRT-lineage implementations and Mitsuba 3's BDPT/MLT integrators. Rejected here per ADR-06: roughly triples integrator implementation complexity (full light-subpath generation, all-pairs MIS) for a gain (§19.9's caustics) explicitly listed as an accepted non-goal in §1.

Photon mapping (two-pass, biased-but-fast)

 pass 1: trace photons from lights, store hit points in a spatial photon map
 pass 2: trace camera rays; at each hit, gather nearby stored photons, estimate radiance
         from local photon density (a density-estimation bias, converges as photon count -> inf)

Winning regime: fast preview of caustics and complex indirect lighting where a small, documented bias is acceptable in exchange for speed — historically the standard technique before MIS path tracing matured. Embodying system: Jensen's original photon-mapping renderers and many production caustics passes still layered under a primary path tracer. Rejected here per ADR-07: this blueprint's unbiased-by-default policy would require a biased mode heavily labelled and kept structurally separate, adding a second full light-transport algorithm this project's scope (§1) does not allocate time for.

GPU wavefront / megakernel path tracer

 [ray-gen kernel] -> [large in-flight ray/path-state buffer, SoA layout]
       |                          |
       v                          v
 [intersect kernel]  <-shared->  [BVH in GPU memory]
       |
       v
 [shade kernel] -> respawn rays into ray-gen queue, or terminate into film buffer
 (kernels launched per stage across the WHOLE in-flight batch, not per-tile-per-thread)

Winning regime: massively parallel throughput on GPU hardware where thousands of in-flight paths amortize kernel-launch overhead and memory-access patterns are batched by stage rather than by spatial tile. Embodying system: Blender Cycles' GPU wavefront kernels and NVIDIA OptiX-based renderers. Rejected here per §1's explicit non-goal (no GPU backend in Phase 0): the CPU tile-per-thread megakernel design (P14) is architecturally simpler and sufficient for the offline, single-machine deployment model this blueprint targets; the SoA path-state memory-access redesign a GPU wavefront architecture requires is deferred wholesale, not partially adopted.

38. Glossary

Radiance — flux per unit projected area per unit solid angle; the fundamental quantity the integrator estimates. Irradiance — flux per unit area, the hemispherical integral of incident radiance. Solid angle — the 2D angular measure dω = sinθ dθ dφ subtended on a sphere. BRDF — Bidirectional Reflectance Distribution Function, describing reflection only. BSDF — Bidirectional Scattering Distribution Function, generalizing BRDF to include transmission. BTDF — the transmission-only component of a BSDF. Rendering equation — Kajiya 1986's integral equation for outgoing radiance in terms of emission plus scattered incoming radiance. Monte Carlo estimator — an average of f(X)/p(X) over random samples X ~ p, converging to the true integral. Variance — the estimator's expected squared deviation from its mean; the quantity every noise-reduction technique targets. Importance sampling — choosing a sampling density p that matches the integrand f to reduce variance. Probability density function (PDF) — the density p(x) a sampling routine draws from. Cosine-weighted sampling — sampling hemisphere directions with density proportional to cosθ, matched to the Lambertian integrand. Low-discrepancy sequence — a deterministic sequence (Sobol, Halton) that fills sample space more uniformly than independent random draws. Stratification — subdividing the sample domain into cells and drawing one jittered sample per cell. Multiple importance sampling (MIS) — combining several sampling strategies with weights that sum to one, reducing variance below any single strategy alone. Balance heuristic — the MIS weighting w_s = p_s / Σp_i, provably within 4× of optimal. Power heuristic — the MIS weighting using squared PDFs, empirically often lower variance. Russian roulette — probabilistic path termination that preserves the estimator's expectation via inverse-probability throughput scaling. Unbiased vs. consistent — an unbiased estimator's expectation equals the true value at any sample count; a consistent estimator converges to the true value only as sample count grows to infinity. Firefly — an isolated, very-bright pixel caused by a low-probability, high-contribution sample. Shadow acne — self-intersection artifacts from insufficient ray-origin offsetting. Epsilon offsetting — nudging a ray's origin along the geometric normal to avoid self-intersection. BVH — Bounding Volume Hierarchy, the tree-structured acceleration structure this blueprint uses. Surface area heuristic (SAH) — a cost model for choosing BVH split positions based on child surface area and primitive count. Microfacet — a model treating a rough surface as a statistical distribution of microscopic mirror facets. GGX / Trowbridge-Reitz — the microfacet normal distribution function used for the rough-metal and rough-dielectric BSDFs. Smith masking-shadowing — the geometric attenuation term accounting for microfacet self-occlusion. Fresnel equations — the physical law governing reflectance/transmittance as a function of incidence angle and index of refraction. Schlick approximation — a cheap polynomial approximation to the Fresnel reflectance curve. Dielectric — a non-conducting material (glass, water) exhibiting both reflection and refraction. Conductor — a metal, whose complex index of refraction absorbs the transmitted component entirely. White furnace test — a scene with uniform environment emission used to verify a BSDF conserves energy exactly. Tone mapping — the pure-function transform from linear HDR radiance to a display-referred image. Mipmap — a precomputed pyramid of progressively lower-resolution, filtered texture levels. Ray differential — auxiliary rays tracked alongside a primary ray to estimate texture-footprint size for mip-level selection. Next-event estimation (NEE) — explicitly sampling a light source at each non-specular path vertex rather than relying solely on BSDF sampling to find it. Throughput — the accumulated product of BSDF-value-over-PDF factors along a path, scaling all future contributions. Path tracing — the recursive/iterative Monte Carlo algorithm evaluating the rendering equation by sampling scattering directions. Thin-lens camera — a camera model with a finite aperture producing depth-of-field blur. Depth of field — the range of scene depths that appear acceptably in focus under a finite-aperture camera model. Circle of confusion — the blur disk radius produced by an out-of-focus point under the thin-lens model. Tangent space — the local coordinate frame (tangent, bitangent, normal) used to interpret a tangent-space normal map. Normal mapping — perturbing the shading normal per-texel to simulate fine surface detail without added geometry. Texture filtering — resolving a texture sample by averaging over a footprint rather than a single texel, avoiding aliasing. Trilinear filtering — filtering that interpolates between two adjacent mip levels as well as within each level. Spectral rendering — representing light as a function of wavelength rather than three RGB channels. Gamma correction — the nonlinear encode/decode transform between linear light and a display-referred signal. Linear color space — a color representation proportional to physical radiance, used internally throughout this system (P10). sRGB — the standard display color space and its associated gamma-like transfer function. HDR (high dynamic range) — image data whose values exceed the [0,1] display range, requiring tone mapping before display. Tile scheduler — the component partitioning the film into work units and distributing them across threads. Film accumulator — the per-pixel running sum (and sum-of-squares) of radiance samples. Denoising — a post-process (typically biased) that trades some fidelity for reduced apparent noise at fixed sample count. Seeded replay — re-running a render with an identical seed, scene, and thread count to verify reproducibility. Chi-square test — a statistical test comparing an empirical sample distribution against an expected density, used here to validate BSDF/light PDF consistency. Soak test — a long-duration continuous render used to detect memory growth or numerical drift.
