Mental Models & First Principles

MM1 — PDF is a random-access object graph, not a sequential stream.
Insight: The file must be read back-to-front (%%EOF → startxref → xref → catalog) before any content is interpreted. Objects are materialized by offset, not by file order.
What it predicts: Opening a huge PDF should be O(xref size), not O(file size). Latency is proportional to xref parse + catalog walk, not total bytes.
Bug class without it: Sequential parsers that read from byte 0 miss linearization hints and fail on files with junk at the start; they also force full-file parse.
Applied in: §8.1 physical structure; Phase 0 tail detection; Phase 2 lazy resolve; §4.5 open latency target.

MM2 — The xref is a versioned namespace; newer always wins.
Insight: Incremental updates append new object definitions without erasing old ones. The /Prev chain is an ordered log; resolution always returns the latest definition for an (ObjId).
What it predicts: A correctly built XrefTable after merge will always surface the post-increment version of any modified object.
Bug class without it: A merge that picks an older offset over a newer one produces stale content — the classic "why does signing corrupt a PDF?" bug.
Applied in: I3; Phase 3 /Prev merge; §8.3 xref stream semantics.

MM3 — The graphics state is a stack of snapshots; q/Q balance is an invariant.
Insight: Every q saves a full copy of the rendering context. Every Q restores it. Any paint operation operates on the top of the stack. A content stream that qs without matching Q leaks its mutated state forward.
What it predicts: A cm inside a balanced q/Q pair has zero effect outside it. An unbalanced extra Q corrupts the CTM for the rest of the page.
Bug class without it: Broken content (common in practice) corrupts clip/color/CTM state indefinitely forward — produces garbage rendering with no error signal.
Applied in: I5; §6 P9; Phase 6 gstate machine; §11.3 GraphicsState.

MM4 — PDF filters are composable, not monolithic; every codec is hostile input.
Insight: A stream's content is encoded through an ordered chain of codecs (/Filter [/ASCII85Decode /FlateDecode]). Each stage is independently decodeable and independently attacker-controlled. A decompression bomb exists at exactly one stage.
What it predicts: Ratio guards must be applied per-stage, not on the final output. Any stage can be a DoS vector; each needs an independent budget.
Bug class without it: Applying a single ratio cap at the chain end allows a deep-chain attack where stage 1 expands 100× and stage 2 expands 200× for a 20,000× net ratio.
Applied in: I8; §6 P8; Phase 4 filter pipeline; §11.5 run_filter_chain.

MM5 — Font programs are embedded interpreters; their inputs are untrusted.
Insight: A /FontFile (Type1), /FontFile2 (TrueType), or /FontFile3 (CFF/OpenType) is a binary program — a charstring interpreter is a small VM. Maliciously crafted charstrings can trigger infinite loops, stack overflows, or OOB access in an unchecked interpreter.
What it predicts: CFF/Type1 interpreters need explicit op-count caps, stack-depth limits, and subroutine-call-depth limits, exactly as a sandboxed VM does.
Bug class without it: An unbounded charstring interpreter loops indefinitely on a crafted glyph, consuming CPU without triggering the content-stream op budget.
Applied in: I9; Phase 9 text/cff.rs, text/type1.rs; Threat Model (font program parsing threat).

MM6 — Determinism is a design property, not a runtime guarantee.
Insight: Identical input + identical render params must produce bit-identical pixel output. This is not automatic: floating-point rounding, thread scheduling, and global state all destroy it.
What it predicts: The coverage accumulator must be fixed-point (26.6 integer), the operation order must be deterministic (no thread nondeterminism in the pixel path), and clocks/RNG must be excluded.
Bug class without it: Non-deterministic rendering means golden-image differential tests are unreliable, archival renders are not reproducible, and "why does this PDF look different on two machines?" is unanswerable.
Applied in: §4.4 numeric/determinism; §6 P4; ADR-15 shared rasterizer; ADR-30 reproducibility.

MM7 — Actions and JavaScript are a separate attack class; refuse-by-construction beats sanitize.
Insight: The dominant class of PDF exploits (Müller et al. 2019–21, P15) are not parser bugs but action bugs: malicious PDFs execute /JS, /Launch, /OpenAction to exfiltrate data or run code. Sanitizing action content is intractable; refusing to execute it is a single policy decision.
What it predicts: A renderer that parses action objects but never dispatches them eliminates the entire class, at the cost of no interactive behavior.
Bug class without it: Any action executor (even a minimal one) introduces a sandbox-escape attack surface proportional to the completeness of the executor.
Applied in: I14; §6 P6; ADR-31; Threat Model (embedded JS/actions row); Phase 5 catalog parse.

MM8 — Text extraction and rendering are independent paths; conflating them corrupts both.
Insight: /ToUnicode maps character codes → Unicode for extraction. It has nothing to do with glyph selection or advance widths during rendering. CID→GID mapping drives rendering; /ToUnicode drives extraction.
What it predicts: A renderer that uses /ToUnicode for glyph lookup will produce wrong glyphs for any font where the CID→GID mapping differs from the Unicode mapping.
Bug class without it: CJK glyphs render incorrectly, or extraction produces wrong Unicode from fonts where /ToUnicode is provided but CID→GID follows a separate path.
Applied in: §6 P7 separation of model vs render; Phase 10 text/tounicode.rs vs text/cid.rs; §11.6 Font types.

Glossary · 52 terms · site-wide glossary

COS
Carousel Object System — PDF's underlying object model (the 9 object kinds + indirect references)
Indirect object
An object stored as N G obj … endobj, referenceable by (num,gen) via N G R
Generation number
The gen half of an object id; incremented when an object number is reused after being freed
Xref (cross-reference)
The table mapping object numbers → byte offsets (or ObjStm location), enabling random access
Trailer
Dict at the file tail giving /Root, /Size, /Prev, /Encrypt, /ID
startxref
The byte offset of the last xref section, read from the file tail
Incremental update
New objects + xref appended after %%EOF, chained via /Prev; never rewrites the original
Linearization
"Fast web view" layout placing first-page data early + hint streams; structurally a normal PDF
Object stream (ObjStm)
A stream packing many non-stream objects together (compressed once); PDF 1.5+
Xref stream
A stream object (/Type /XRef) replacing the classic table with binary entries; PDF 1.5+
Content stream
A stream of postfix operators describing a page's marks
Operator
A content-stream verb (m, l, Tj, Do, …) consuming preceding operands
Operand
A value pushed before an operator on the operand stack
CTM
Current Transformation Matrix — maps user space → device space
User space
Default coordinate system; origin bottom-left, unit 1/72 inch
Device space
Output pixel coordinate system; origin top-left after the y-flip
MediaBox / CropBox
Page media rectangle / visible-crop rectangle (in user space)
Resource dict
Per-page/XObject /Resources mapping names → fonts/xobjects/colorspaces/etc
FlateDecode
DEFLATE (RFC 1951) + zlib (RFC 1950) stream filter
Predictor
Pre-compression transform (PNG filters / TIFF differencing) improving Flate/LZW ratio
LZW
Lempel-Ziv-Welch dictionary compression (LZWDecode filter)
DCTDecode
Baseline JPEG (DCT) image filter
CCITTFax
Group 3/4 fax (MH/MR/MMR) bilevel image filter
JBIG2
Bilevel image coding filter (deferred)
JPX
JPEG 2000 (wavelet) image filter (deferred)
ASCII85
Base-85 ASCII encoding filter
Color space
Interpretation of color components (Device/CIE/Indexed/Separation/DeviceN/Pattern)
ICCBased
Color space defined by an embedded ICC profile (/N components, /Alternate)
Separation
Single-colorant color space with a tint transform to an alternate space
DeviceN
Multi-colorant color space with a tint transform
Indexed
Palette color space (base, hival, lookup)
Pattern
Tiling- or shading-based paint color space
Shading
A smooth color gradient (axial/radial/function-based), painted by sh or as a pattern
Type0 / CID
Composite (multi-byte) font / character-collection-indexed font
CMap
Maps multi-byte character codes → CIDs (or codes → Unicode for ToUnicode)
CIDToGIDMap
Maps CIDs → glyph indices in a CIDFontType2 (/Identity or a stream)
ToUnicode
A CMap mapping character codes → Unicode, for text extraction only
FontDescriptor
Dict of font metrics + flags + the embedded program reference
FontFile2
Embedded TrueType font program (/FontFile2)
Standard-14
The 14 fonts a viewer must support without embedding (Helvetica/Times/Courier/Symbol/ZapfDingbats)
Type3 charproc
A glyph defined as a content stream (Type3 font)
Form XObject
A reusable content-stream object painted with Do (with its own matrix/bbox/resources)
Image mask
A 1-bit stencil selecting where the current color is painted
SMask
A soft mask giving per-pixel alpha
Blend mode
The compositing function combining backdrop + source (Normal/Multiply/Screen/…)
Security handler
The component deriving keys + decrypting streams/strings (standard handler = RC4/AES)
RC4
The stream cipher used by older PDF encryption
AESV3
AES-256 encryption (PDF 2.0, revision 6)
/U /O /P
User-password hash / owner-password hash / permission bits in /Encrypt
AcroForm
Interactive form definition (field appearances rendered; recalc deferred)
Optional content (OCG)
Layers that can be shown/hidden
Flatness
Tolerance for approximating curves with line segments during rasterization
