⬜ Phase 0 — Repo Skeleton + Byte Lexer + Tail Detection §12

Objectives

Bootstrap workspace; byte scanner; detect %PDF-, startxref, %%EOF; emit the full PDF token grammar. No object parsing yet.

Deliverable

pdfcli stub + lexer crate that tokenizes any byte stream; cli xref prints header version, startxref offset, %%EOF position.

Acceptance
  • Tokenize the §8.1 sample → exact expected token sequence.
  • 100% of bytes accounted for (no infinite loop, pos strictly advances).
  • Fuzz fuzz_lexer 1M execs, zero panics, zero hangs (op-per-byte bound).
  • Header/tail detection correct on 20 valid + 10 junk-prefixed fixtures.
Fixtures

hello.pdf (token golden); junk_prefix.pdf (header not at 0); trailing_garbage.pdf (bytes after %%EOF); crlf.pdf / lf.pdf / cr.pdf (EOL variants); no_eof.pdf (malformed — must report, not crash).

Pitfalls
  • Treating PDF as UTF-8 → multibyte corruption; PDF is bytes (root cause: char-based scanner). Detect: non-ASCII in names. Fix: byte API only.
  • Comments inside strings consumed as comments → desync. Root cause: % handled before string context. Fix: string lexer ignores %.
  • startxref offset read as decimal with leading zeros / whitespace → parse fail. Fix: tolerant integer parse.
  • Reverse-scan for %%EOF matching an earlier occurrence in content. Fix: scan from true EOF, accept last.

⬜ Phase 1 — COS Object Parser (9 kinds + references) §13

Objectives

Recursive-descent parser: tokens → Object; all 9 kinds; reference disambiguation; nesting caps.

Deliverable

cos crate parsing standalone object syntax; cli dump --raw prints a parsed object tree from a byte range.

Acceptance
  • Round-trip parse of every object kind in §8.1/§8.10 fixtures.
  • MAX_NEST enforced (deep-array fixture → RecursionLimit, no stack overflow).
  • fuzz_cos_parser 5M execs zero panics; miri-clean on parser core.
  • Reference vs integer disambiguation correct in array [1 0 R 2 0 3 0 R].
Fixtures

all_types.pdf (one of each kind); nested_128.pdf (legal depth); nested_1000.pdf (must reject); ref_in_array.pdf; dup_keys.pdf; bad_dict_key.pdf (number as key → recover); hex_odd.pdf (odd hex digit padding).

Pitfalls
  • Greedy reference detection consuming 1 0 in [1 0] as a ref. Root: no push-back. Fix: 2-token lookahead with restore.
  • << vs <hex> confusion. Fix: peek 2nd byte after <.
  • Treating stream keyword bytes inside a dict value. Fix: stream only valid immediately after a complete dict in indirect-object context.
  • Real parse losing precision (e.g. 0.00000000000000000001). Fix: parse to f64, accept denormal flush.

⬜ Phase 2 — Classic Xref + Trailer + Lazy Resolution §14

Objectives

Parse the classic 20-byte xref table + trailer; build XrefTable; implement Document::open and lazy resolve(ObjId) with caching + cycle detection. Resolve /Length references from Phase 1.

Deliverable

Document::open on a classic-xref PDF; cli dump --obj N G resolves and prints any object; cli info prints /Size, /Root, version.

Acceptance
  • Resolve every object in hello.pdf correctly; cache hit-rate measurable.
  • Cycle fixture → CycleDetected, no infinite loop.
  • /Length-lie fixture → correct stream bytes via fixup.
  • Object-resolution p50 ≤ 50 µs (warm), ≤ 200 µs (cold, no decompress).
Fixtures

classic_xref.pdf; multi_subsection.pdf (xref 0 1 + 5 3); length_lie.pdf; self_ref_cycle.pdf (5 0 obj 5 0 R); gen_mismatch.pdf; free_list.pdf.

Pitfalls
  • 20-byte entries off-by-one EOL (\r\n vs \n vs \r ). Root: assuming \r\n. Fix: accept the 3 legal 2-char terminators; stride is fixed at 20.
  • obj header gen not matching reference. Fix: prefer exact (num,gen); fall back to num-only if unique (quirk + telemetry).
  • Caching the unresolved Ref instead of the target. Fix: cache only fully-resolved Objects; chase Ref→Ref.
  • /Length itself an indirect ref to an object after the stream. Fix: defer + resolve via xref.

⬜ Phase 3 — Xref Streams + Object Streams + /Prev + Incremental §15

Objectives

PDF 1.5+ xref streams; object streams (ObjStm); /Prev chain merge; incremental-update + hybrid-reference resolution.

Deliverable

Resolve objects from xref-stream + ObjStm PDFs; cli xref reports table source (classic/stream/hybrid) and /Prev depth.

Acceptance
  • Resolve all objects in a pure xref-stream PDF and a hybrid PDF.
  • ObjStm member resolution byte-exact vs reference dump.
  • /Prev-chain fixture: an object redefined in an increment resolves to the newest version.
  • Chain-depth cap fixture → truncation + telemetry, no hang.
Fixtures

xref_stream.pdf; objstm.pdf; hybrid_ref.pdf; incremental_update.pdf (object redefined twice); prev_chain_deep.pdf (over-cap); objstm_bad_offset.pdf (member offset OOB → drop + telemetry).

Pitfalls
  • /W field width 0 handling (default type = 1). Root: assuming all widths nonzero. Fix: honor 0-width → default value.
  • ObjStm containing a stream//Encrypt/another ObjStm (illegal) → reject member. Fix: enforce ObjStm content rules (I13).
  • Decoding an ObjStm that is itself encrypted before the security handler is ready. Fix: ordering — security handler first (I17).
  • /Prev cycle (A→B→A). Fix: visited-set of xref offsets.

⬜ Phase 4 — Filter Pipeline (Flate + Predictors, LZW, ASCII85/Hex, RunLength) §16

Objectives

Composable decode chain; FlateDecode + PNG/TIFF predictors; LZWDecode; ASCII85Decode; ASCIIHexDecode; RunLengthDecode; full /Length-vs-actual reconciliation; ratio cap.

Deliverable

Decode any stream with these filters/chains; cli dump --obj N G --decode outputs decoded bytes; content streams now decodable.

Acceptance
  • Byte-exact decode vs reference for each filter + the chain [/ASCII85Decode /FlateDecode].
  • Predictor 12 (PNG up) + 15 (PNG optimum) byte-exact.
  • Zip-bomb fixture (200:1+) → DecompressBomb, bounded memory.
  • fuzz_flate, fuzz_lzw 5M execs each, zero panics.
Fixtures

flate_basic.pdf; flate_predictor12.pdf; lzw_earlychange0.pdf; a85_chain.pdf; ahx.pdf; runlength.pdf; bomb_200x.pdf; bad_adler.pdf (warn-not-fail); raw_deflate.pdf (no zlib header quirk).

Pitfalls
  • /EarlyChange default = 1; getting it wrong shifts the whole LZW dictionary by one code. Detect: garbage after ~512 bytes. Fix: honor default + explicit.
  • PNG predictor /Colors//BitsPerComponent → bytes-per-pixel miscalc → row misalignment. Fix: bpp = ceil(colors*bpc/8).
  • Adler-32 mismatch failing the decode. Fix: warn-only (real files lie).
  • ASCII85 z inside a partial group (illegal) — reject group, not whole stream.
  • Ratio cap measured pre-predictor vs post. Fix: cap on inflate output (largest stage).

⬜ Phase 5 — Document Model (Catalog, Page Tree, Resources, Boxes) §17

Objectives

Navigate catalog → page tree with attribute inheritance; resolve resource dictionaries with scope; expose MediaBox/CropBox/Rotate per page; flat page index.

Deliverable

Document::page(i) returns a fully-resolved Page; cli info lists page count + each page's box/rotate; cli dump --page N shows resolved resources.

Acceptance
  • Page count matches reference engine on multi-level page-tree fixtures.
  • Inherited MediaBox/Rotate applied correctly (intermediate-node fixture).
  • Cyclic page tree → truncated traversal, found pages still listed.
  • /Contents array concatenation order preserved.
Fixtures

pagetree_flat.pdf; pagetree_nested.pdf (3 levels, inherited box); inherited_rotate.pdf; contents_array.pdf; cyclic_pages.pdf; missing_mediabox.pdf; count_mismatch.pdf.

Pitfalls
  • Forgetting /Contents may be an array of streams concatenated with whitespace separators. Fix: join with \n; a token must not span the boundary (insert separator).
  • Inheritance applied at wrong precedence (local must override inherited). Fix: local-first lookup.
  • /Rotate not normalized (e.g. 450, −90). Fix: ((rotate % 360)+360)%360, snap to nearest 90.
  • Treating /Pages count as authoritative for iteration. Fix: iterate /Kids, use /Count only as a check.

⬜ Phase 6 — Content Lexer + Interpreter Skeleton + Graphics State Stack §18

Objectives

Tokenize decoded content; postfix operand/operator machine; graphics-state stack (q/Q/cm); operator budget. No painting yet — establish the dispatch + gstate spine.

Deliverable

Interpreter walks a content stream, maintains a correct CTM through q/Q/cm; cli dump --page N --ops lists the operator trace with running CTM.

Acceptance
  • q/Q balance tracked; unbalanced fixture → clamp, no panic.
  • CTM after a known cm sequence matches hand-computed matrix (float tolerance 1e-9).
  • Operator budget enforced on a synthetic huge-content fixture.
  • fuzz_content 5M execs zero panics.
Fixtures

gstate_basic.pdf; unbalanced_qQ.pdf (extra Q); cm_chain.pdf (golden CTM); op_budget.pdf (loop-like huge stream); unknown_op.pdf (custom operator → ignored); bx_ex.pdf (compat section).

Pitfalls
  • Q underflow corrupting all subsequent rendering. Fix: clamp at depth 0, emit qq_underflow (I5).
  • cm order (PDF concatenates right-multiply: CTM' = cm × CTM). Getting the order wrong mirrors/skews output. Fix: lock matrix convention in matrix.rs.
  • Operands left on the stack after an operator (extra operands). Fix: clear operand stack after each operator dispatch.
  • Treating BX/EX content as normal (unknown ops inside should be silently dropped). Fix: compat flag suppresses bad_op telemetry.

⬜ Phase 7 — Path Construction + Painting + Clipping + Rasterizer Integration §19

Objectives

Path operators; fill (non-zero/even-odd); stroke (width/cap/join/dash); clipping; integrate the shared scanline AA rasterizer; DeviceGray/RGB/CMYK color. First visible pixels.

Deliverable

Render filled/stroked vector pages to a bitmap; cli render outputs PNG of rectangle/line/curve fixtures; clipping visibly applied.

Acceptance
  • Filled-rectangle fixture pixel-matches reference within SSIM ≥ 0.99.
  • Non-zero vs even-odd star fixture renders the correct hole pattern.
  • Stroke width/cap/join visually correct vs reference (SSIM ≥ 0.98 — AA tolerance).
  • Clip fixture: content outside clip absent.
Fixtures

rect_fill.pdf; star_nonzero.pdf / star_evenodd.pdf; stroke_caps_joins.pdf; dash.pdf; bezier.pdf; clip_rect.pdf; clip_nested.pdf (intersection); cmyk_fill.pdf.

Pitfalls
  • Flattening in user space before CTM → wrong tolerance at scale. Fix: flatten in device space (post-CTM).
  • Even-odd vs non-zero swapped → wrong holes. Fix: thread the rule from the paint operator.
  • Clip not intersected (replaced) across nested q. Fix: clip is intersection of all active clips (I12).
  • Miter spikes at sharp joins exceeding miter-limit → fall back to bevel. Fix: compute miter length, compare to limit×width.
  • Self-intersecting stroke outline double-covering → AA artifacts. Fix: union via winding in the coverage pass.

⬜ Phase 8 — Color Spaces (Indexed, ICCBased, Separation/DeviceN, Pattern, Shading) §20

Objectives

Full color-space model: CS/cs/SC/SCN; Indexed palettes; ICCBased (minimal); Separation/DeviceN tint transforms via PDF functions; Pattern (tiling + shading); sh operator.

Deliverable

Correct colors for all space families; cli render reproduces Indexed images, spot-color (Separation) fills, and a gradient sh page.

Acceptance
  • Indexed/Separation/DeviceN fills match reference (SSIM ≥ 0.98).
  • Axial + radial shading gradients match reference (SSIM ≥ 0.97).
  • Type 4 PostScript-calculator tint transform produces correct colors on a DeviceN fixture.
  • ICCBased falls back to alternate with correct component count.
Fixtures

indexed.pdf; separation.pdf; devicen.pdf; icc_rgb.pdf; axial_shading.pdf; radial_shading.pdf; tiling_pattern.pdf; psfunc_tint.pdf; lab_color.pdf.

Pitfalls
  • Type 4 calculator as an exec vector — must be a sandboxed numeric VM (no operators beyond the math/stack set; op-count + stack-depth caps). Fix: whitelist operators.
  • Indexed hival off-by-one (entries = hival+1). Fix: clamp index to [0,hival].
  • Shading domain/extend flags ignored → gradient clipped wrong. Fix: honor /Domain, /Extend [bool bool].
  • DeviceN with /Colorants attributes ignored (fine) but tint transform arity must match names.len().
  • Pattern color space without a base for uncolored patterns. Fix: require base for PaintType 2.

⬜ Phase 9 — Text Engine + Simple Fonts (Type1/CFF/TrueType/Type3) §21

Objectives

Text/positioning/showing operators; simple-font glyph rendering — TrueType (via #385), Type1 + CFF (in-tree charstring interpreters), Type3 (charproc content streams); encodings + /Differences + /Widths; correct glyph placement + advance.

Deliverable

Render text pages with embedded + Standard-14 fonts; cli render produces correct glyphs at correct positions; invisible text (mode 3) advances without painting.

Acceptance
  • "Hello" + multi-font fixture matches reference (SSIM ≥ 0.98).
  • Glyph advances match reference width tables (positional drift < 0.5px over a line).
  • Type1, CFF, TrueType, Type3 glyphs all render.
  • /Differences remapping correct (e.g. custom ligature code).
  • fuzz_font_cff 5M execs zero panics.
Fixtures

helvetica_std14.pdf; embedded_type1.pdf; embedded_cff.pdf; embedded_truetype.pdf; type3_font.pdf; differences.pdf; render_mode_invisible.pdf; seac_accents.pdf (Type1 composite glyphs).

Pitfalls
  • Word spacing Tw applies only to single-byte code 32, never to composite fonts. Fix: gate on simple-font + code==32.
  • Type1 eexec decryption (skip first 4 random bytes) + charstring decryption (skip lenIV=4). Fix: two-stage decrypt.
  • CFF private-dict local subrs vs global subrs bias (nominalWidthX/defaultWidthX, subr index bias 107/1131/32768). Fix: implement bias correctly.
  • Confusing glyph space (/1000 em) with text space. Fix: font matrix scale before text matrix.
  • TrueType cmap (3,1)/(1,0)/(3,0) subtable selection for symbol fonts. Fix: delegate selection to #385 with the PDF encoding hint.

⬜ Phase 10 — Composite Fonts (Type0/CID) + CMaps + ToUnicode §22

Objectives

Type0 composite fonts; CMap (Identity-H/V + embedded/predefined) code→CID; /CIDToGIDMap; /W//DW widths; /ToUnicode for text extraction; CJK/multi-byte rendering.

Deliverable

Render CJK/multi-byte text; cli render reproduces a composite-font page; cli text extracts Unicode via /ToUnicode.

Acceptance
  • Identity-H CJK fixture matches reference (SSIM ≥ 0.97).
  • Embedded-CMap fixture maps codes→CIDs correctly (byte-length disambiguation).
  • cli text output equals reference text extraction on a /ToUnicode fixture (exact string match after normalization).
  • /W width runs applied (advance drift < 0.5px/line).
Fixtures

type0_identity.pdf; type0_embedded_cmap.pdf; cidfonttype0.pdf (CFF CID); cidfonttype2.pdf (TrueType + CIDToGIDMap stream); tounicode_extract.pdf; vertical_text.pdf; mixed_1_2_byte.pdf (variable codespace).

Pitfalls
  • Variable-length codespace: a 1-byte and 2-byte range coexist; decoding must match the longest applicable codespace prefix. Fix: codespace-driven tokenizer.
  • /CIDToGIDMap /Identity vs stream confusion. Fix: name → identity, stream → 2-byte table.
  • /W array forms: [c [w1 w2 …]] (consecutive) vs [cFirst cLast w] (range). Fix: handle both syntaxes.
  • ToUnicode used for rendering (wrong) — it's extraction-only; rendering uses CID→GID. Fix: strict separation.
  • Endianness of 2-byte codes (big-endian). Fix: BE decode.

⬜ Phase 11 — Images (XObjects, Inline, Masks, SMask, DCTDecode, CCITTFax) + Form XObjects §23

Objectives

Image XObjects + inline images; image masks + soft masks + color-key masking; DCTDecode (baseline JPEG) + CCITTFax G4; form XObjects (Do) with resource scoping + recursion cap.

Deliverable

Render raster-image pages (RGB/CMYK/indexed/JPEG/fax), masked images, and form XObjects; cli render reproduces image + form pages.

Acceptance
  • RGB/Gray/Indexed image fixtures pixel-match within SSIM ≥ 0.98.
  • Baseline JPEG (DCTDecode) decode SSIM ≥ 0.97 vs reference (DCT rounding tolerance).
  • CCITT G4 fax fixture decode byte-exact (1-bit).
  • Image mask + SMask alpha correct; form XObject renders with correct matrix/clip; recursion cap stops a self-referential form.
  • fuzz_dct, fuzz_ccitt 5M execs zero panics.
Fixtures

image_rgb.pdf; image_indexed.pdf; image_cmyk_jpeg.pdf; image_gray_jpeg.pdf; fax_g4.pdf; image_mask.pdf; smask_alpha.pdf; colorkey_mask.pdf; inline_image.pdf; form_xobject.pdf; form_recursive.pdf (over-cap).

Pitfalls
  • Inline-image EI detection inside binary data → premature end. Fix: compute expected byte length from /W/H/BPC/CS (uncompressed) or scan for whitespace-EI-whitespace after filter decode.
  • CMYK JPEG inverted (Adobe APP14 transform + inverted CMYK convention). Fix: honor APP14 transform flag; invert per Adobe quirk.
  • /Decode array ignored → wrong tonal mapping (esp. inverted masks). Fix: apply /Decode per component.
  • SMask resolution differs from base image → must resample, not assume 1:1. Fix: bilinear resample SMask.
  • Form /BBox not applied as clip → overpaint. Fix: clip to BBox (transformed by /Matrix).
  • 16-bit samples (/BitsPerComponent 16) byte order (big-endian). Fix: BE unpack.

⬜ Phase 12 — Encryption (Standard Security Handler) + Transparency (Alpha + Blend) §24

Objectives

Standard security handler: RC4 40/128, AESV2 (128), AESV3 (256); /U//O//P validation; empty-user-password path; per-object decryption before decode (I17). Transparency: constant alpha (CA/ca via gs), separable blend modes. Soft-mask groups partly deferred.

Deliverable

Open + render encrypted PDFs (RC4 + AES, empty user password); cli render/text work on encrypted files; constant-alpha + blend-mode pages composite correctly.

Acceptance
  • RC4-128, AESV2, AESV3-256 fixtures decrypt + render correctly (empty user password).
  • Owner-password-only files open via empty user password (permissions enforced as policy, not as a decode gate).
  • /U validation correctly accepts/rejects passwords.
  • Blend-mode fixtures (Multiply/Screen/Overlay) SSIM ≥ 0.97 vs reference; ca/CA alpha correct.
Fixtures

rc4_40.pdf; rc4_128.pdf; aesv2.pdf; aesv3_256.pdf; owner_only.pdf; wrong_password.pdf (→ BadPassword); blend_multiply.pdf; alpha_ca.pdf; metadata_unencrypted.pdf (/EncryptMetadata false).

Pitfalls
  • Decode-before-decrypt → garbage (filters run on ciphertext). Fix: decrypt at resolve, then filter (I17).
  • /Encrypt dict and xref streams must not be decrypted. Fix: exclude them explicitly.
  • ObjStm member double-decryption (decrypt the container once; members are plaintext within). Fix: decrypt ObjStm stream, not members.
  • AES IV handling (prepended 16 bytes) + PKCS#7 unpad off-by-one. Fix: strict IV split + pad validation.
  • R6 hash algorithm 2.B iteration count is data-dependent (loop until condition). Fix: implement the exact stop condition.
  • Password padding (32-byte standard padding string) for R2–R4. Fix: use the canonical padding constant.

⬜ Phase 13 — Robustness: Xref Rebuild, Stream Recovery, Conformance Suite, Fuzzing Hardening §25

Objectives

Production hardening: scan-rebuild of broken xref; broken-stream recovery; the full conformance differential-render suite; fuzzing-driven hardening across all stages. JBIG2/JPX remain deferred safe stubs.

Deliverable

A renderer that survives a large hostile corpus without crashing; rebuilds broken files; passes the differential suite; CI fuzz gate green.

Acceptance
  • 100% of the Isartor + veraPDF + pdf.js corpora: open+render+text with zero panics, bounded memory/time.
  • ≥ 95% of valid-corpus pages within SSIM threshold vs both oracles.
  • Broken-xref fixtures render via rebuild.
  • 24h continuous fuzz (each target) with zero new crashes after triage.
Fixtures

broken_xref_offsets.pdf; no_xref.pdf (full rebuild); truncated.pdf; garbage_trailer.pdf; the entire conformance/fixtures/ tree; jbig2_stub.pdf / jpx_stub.pdf (gray fallback). Plus auto-imported fuzz-crash regression inputs.

Pitfalls
  • Rebuild picking the wrong (older) object when duplicates exist. Fix: latest-offset (highest file position) wins, mirroring incremental-update semantics.
  • Rebuild scan matching obj inside a stream's binary data. Fix: require the \d+ \d+ obj shape at a plausible boundary; validate the object parses.
  • Infinite recovery loop (rebuild → still fails → rebuild). Fix: rebuild is one-shot; if it fails, return a clear error.
  • SSIM threshold too strict → false regressions from legitimate AA differences. Fix: per-class thresholds + perceptual tolerance.
