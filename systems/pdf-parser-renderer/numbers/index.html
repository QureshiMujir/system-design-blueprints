4.4 Numeric & determinism

  • Raster fixed-point: 26.6 (64ths) for scanline coordinates; float for CTM composition then quantized.
  • DPI/scale range: 1–7200 DPI; scale 0.01×–100×; reject outside.
  • Determinism: identical input bytes + identical render params → bit-identical output bitmap (no time/random/threading nondeterminism in pixel path).
  • No panic on malformed input: every parse/decode path returns Result; the process must never abort on hostile data. Panics are bugs caught by fuzzing.

4.5 Startup / availability

  • Document open (parse xref + catalog, no page render): ≤ 5 ms for a 10 MB file; ≤ 50 ms for 200 MB with xref streams.
  • Library has no global mutable state; safe for concurrent multi-document use.
  • Render farm SLO: 99.9% of pages render without crash; ≥ 99% within p99 latency.

Back-of-Envelope Capacity Model

All numbers derived step-by-step from System Constraints (§4).

1. Page bitmap memory (Letter, 150 DPI, RGBA8)

W = 8.5 in × 150 DPI = 1275 px
H = 11 in × 150 DPI = 1650 px
Bitmap = W × H × 4 bytes = 1275 × 1650 × 4 = 8,415,000 B ≈ 8 MB per page

Check: well under the §4 ceiling of 4 × page_px × bpp = 4 × 2,103,750 × 1 = ~8 MB (Gray8 4× is a conservative ceiling for intermediate buffers).

2. Decompression bomb threshold (§4.3, 200:1 cap)

Max stream input before bomb: cap_output / ratio = 512 MB / 200 = 2.56 MB input triggers abort
A 2.6 MB Flate stream claiming 200× expansion → abort at 512 MB output (I8)

3. Object cache ceiling (§4.1, 256 MB LRU)

Average resolved object size: ~500 B (dict + children inline)
Objects cached at ceiling: 256 MB / 500 B = ~524,288 objects
A 1-million-object PDF → ~50% cache hit rate at ceiling; rest resolved on-demand

4. Glyph cache sizing (§4.1, 32 MB LRU)

Average glyph outline (Path, 20 segments): ~20 × 32 B = 640 B
Glyphs at ceiling: 32 MB / 640 B = ~52,000 glyph outlines cached
A font with 65,536 glyphs: ~80% hit rate for a typical corpus (Zipf distribution of glyph usage)

5. Render-farm FD budget (100 concurrent documents)

Per-doc FDs: 1 mmap (source file) + 1 (metrics socket) + 2 (log pipe) = 4 FDs
100 docs: 400 FDs; well under typical per-process limit of 65,536

6. Xref table memory (1 million objects)

Per-entry: ObjId(6 B) + XrefEntry(12 B) = 18 B in HashMap
HashMap overhead (~1.5×): 18 × 1.5 = 27 B/entry
1M entries: 27 MB → fits comfortably in 256 MB object-cache ceiling

7. Filter chain bandwidth (FlateDecode, 150 DPI Letter page)

Page content stream (typical text+vector): ~50 KB compressed
Inflate at 150 MB/s (M4): 50 KB / 150 MB/s = 0.33 ms
Image streams: up to 5 MB compressed; inflate: 5 MB / 150 MB/s = 33 ms
→ Inflate is rarely the bottleneck for text pages; can dominate image-heavy pages

8. Rasterizer throughput check (M10, 200 Mpix/s)

Letter page at 150 DPI: 1275 × 1650 = 2,103,750 px
Time at 200 Mpix/s: 2,103,750 / 200,000,000 = 10.5 ms
→ Rasterizer alone can fill a full Letter page in ~10 ms (consistent with M7 ≤ 8 ms for simple pages at cache-warm)

9. Glyph coverage cache per render (text-heavy, 1000 glyphs)

Rendered coverage per glyph (12pt, 150 DPI, ~16×20 px): 320 B
1000 unique (font, gid, scale-bin) combos: 320 KB → negligible vs 32 MB cache
→ Text-heavy pages fit entirely in glyph cache after first pass; subsequent pages are cache-warm

10. Parallel page render scaling (N cores)

Per-page CPU: ~8 ms (M7 text), ~25 ms (M8 mixed), ~120 ms (M9 vector)
Amdahl's law: shared state = RwLock on object cache (read-mostly → near-zero contention)
Ideal throughput: N pages/core; measured ceiling: ~0.9N (5–10% RwLock write overhead on cold-miss bursts)
At 16 cores: 16 × 0.9 = 14.4× throughput vs single-threaded for text pages
