Listener. Owns the TCP/TLS boundary and per-connection state; the trust boundary between an untrusted network peer and the broker begins here (§23 T1, T7).

Command Dispatcher. The single mutation point for per-connection subscription state and the routing point into every subsystem; concurrency boundary between one connection's command sequence and the shared topic/pattern/Streams state.

Topic Store / Pattern Index. The persistence boundary for pub/sub state is deliberately absent here — both structures hold only live-connection references (P2, P5); sharding bounds lock contention (256 buckets, §14).

Fanout Engine. The queue/channel boundary: the per-subscriber output buffer is the only queue in the pub/sub path (P3); this is where backpressure is decided.

Streams Tier. The one true persistence boundary in this design — the only state that survives a client disconnect (P5); consistency semantics are at-least-once via PEL (§7 I2).

Cluster. The distribution boundary: slot ownership, gossip membership, and the binary bus that is lossy for fanout and reliable for Streams cluster traffic (ADR-08, §9).

Operability. Not a separate subsystem bolted at the edge — every box above emits metrics/ spans/log lines into this layer (P10).

Three properties hold everywhere below: (1) the pub/sub fanout path is one-way with no broker-side queue — the queue is the per-subscriber output buffer; (2) Streams is the only surface with state outliving a connection; (3) cluster mode is a superset of single-node mode — a single-node broker is a one-node cluster with the bus disabled, served by the same dispatcher.

8. Domain Model / Protocol / Data Model

8.1 Wire grammar (RESP2/RESP3, EBNF)

frame        = simple | error | integer | bulk | array
             | null | double | boolean | map | set
             | push | bignum | verbatim ;
simple       = "+" , text , CRLF ;
error        = "-" , text , CRLF ;
integer      = ":" , ["-"] , digit+ , CRLF ;
bulk         = "$" , length , CRLF , length*OCTET , CRLF ;
array        = "*" , count , CRLF , count*frame ;
null         = "_" , CRLF ;                       (* RESP3 *)
double       = "," , float , CRLF ;                (* RESP3 *)
boolean      = "#" , ("t" | "f") , CRLF ;           (* RESP3 *)
map          = "%" , count , CRLF , count*(frame,frame) ; (* RESP3 *)
set          = "~" , count , CRLF , count*frame ;   (* RESP3 *)
push         = ">" , count , CRLF , count*frame ;   (* RESP3, subscriber deliveries *)
bignum       = "(" , ["-"] , digit+ , CRLF ;        (* RESP3 *)
verbatim     = "=" , length , CRLF , 3*OCTET , ":" , (length-4)*OCTET , CRLF ; (* RESP3 *)
inline       = token , (SP , token)* , CRLF ;       (* rejected for binary-safe payload cmds *)
length       = ["-"] , digit+ ;                     (* "-1" encodes null bulk/array *)

8.4 Malformed-input example

Client sends $18446744073709551615\r\n... (a bulk length that overflows i64 and exceeds proto-max-bulk-len). Framer rejects at the length-parse step (before allocating), emits -ERR Protocol error: invalid bulk length, increments psm_wire_parse_errors_total, and closes the connection (I11).

8.6 Streams data model

A stream is an ordered log of (StreamId, fields) entries, StreamId = (ms: u64, seq: u64) compared lexicographically (I7). A consumer group holds last_delivered: StreamId and a per-consumer PEL: {StreamId → (consumer, delivery_time, delivery_count)}. XREADGROUP … id=">" delivers entries past last_delivered and inserts them into the PEL; XACK removes; XCLAIM reassigns PEL entries idle beyond min-idle-time to a new consumer (§18).

Header is 38 bytes, little-endian, followed by a kind-typed body (§11.8).

8.8 Delivery-semantics summary

Tier Semantics Mechanism Invariant
Pub/sub (channel, pattern) At-most-once No backlog; connection-scoped subscription I1
Streams, no consumer group At-most-once per XREAD call (client tracks its own last-seen id) Client-held cursor —
Streams, consumer group At-least-once PEL + XACK/XCLAIM I2
Any tier Exactly-once Not provided I3

Design principles (§6)

  • P1 — The wire is RESP, not a parallel API. Existing RESP2/RESP3 clients connect unchanged. Tradeoff: no room for a leaner native protocol without breaking compatibility. Operational implication: every wire fixture in conformance/corpora/wire/ is a compatibility contract, not a test convenience. Violate it and every existing Redis client library breaks.
  • P2 — Pub/sub is fanout, not queueing. A PUBLISH with zero subscribers is dropped; a late-joining subscriber never sees history. Tradeoff: zero durability for the pub/sub tier in exchange for zero broker-side backlog memory. Violating it (adding a backlog "just in case") turns this into a slower, worse Streams tier.
  • P3 — Each subscriber owns its own bounded output buffer. No global queue, no broker-side spool, no priority. Tradeoff: a subscriber's own slowness cannot be smoothed by broker memory beyond its bound. Violating it removes the isolation that keeps one slow subscriber from starving others.
  • P4 — Pattern subscriptions are O(patterns), not O(channels), per publish. The pattern index is keyed by pattern; a publish walks the pattern set once regardless of subscriber count per pattern. Tradeoff: cost scales with the number of distinct patterns, which is unbounded without an index refinement (§16, Deferred Register item 1). Violating the design (indexing by channel) makes a single busy channel touch every subscriber's per-message cost.
  • P5 — The Streams tier is the only stateful surface. Pub/sub state lives in the connection; Streams state (the log, the PEL) is the only thing that survives disconnect. Tradeoff: any cross-disconnect guarantee must be built on Streams, never on pub/sub. Violating it (adding pub/sub replay) breaks I1 (§7).
  • P6 — Cluster mode shards channel space, not the broker. Channel c lives on slot CRC16(c) & 0x3FFF; a single-node broker is a one-node cluster. Tradeoff: slot ownership changes require a migration protocol (§19), not a code fork. Violating it (a special-cased single-node code path) doubles the maintenance surface.
  • P7 — The cluster bus is binary and lossy for fanout traffic. A missed bus packet for fanout is accepted loss, mirroring a missed pub/sub message to a disconnected subscriber; Streams cluster traffic uses a retried channel instead. Tradeoff: simpler bus code, at the cost of best-effort cross-node fanout. Violating it (retrying fanout) risks duplicate delivery with no dedup mechanism.
  • P8 — The broker is single-process, multi-threaded. Tokio's multi-thread runtime owns the listener and fanout; no fork-on-publish, no thread-per-connection, no embedded scripting. Tradeoff: no in-process user code (Lua/WASM deferred, §36). Violating it (a scripting escape hatch) reopens the security surface P12 closes.
  • P9 — Determinism is best-effort for pub/sub, strict for Streams. Fanout order across subscribers is undefined; per-subscriber order from one publisher is preserved; Streams entries are strictly ordered by XADD (I4, I7). Tradeoff: cross-subscriber ordering guarantees would require a broker-side sequencer, adding latency P2 rejects.
  • P10 — Operability ships with the core, never bolted on. ACL, TLS, slow-log, hotkey-log, Prometheus, OpenTelemetry land in the same Phase-0 arc (Phases 8–9, §20–§21), not a later release. Tradeoff: more Phase-0 surface area. Violating it produces a broker nobody can safely run in production.
  • P11 — Backpressure resolves by disconnection, never by blocking the publisher. The output buffer is unbounded in channel capacity but bounded in byte count; exceeding the bound disconnects the subscriber, never stalls PUBLISH. Tradeoff: a slow subscriber loses messages (already true per P2) rather than the whole broker losing throughput. Violating it (a bounded channel) turns one slow reader into a global outage.
  • P12 — Security is default-deny. A new ACL user has zero privileges; TLS and plaintext ports are separate with no in-band downgrade. Tradeoff: every new command needs an explicit ACL category. Violating it is the single most common way brokers get owned in production.
  • P13 — The client wire and the cluster bus are distinct protocols on distinct ports. Client traffic never shares a port or trust domain with inter-node traffic. Tradeoff: two listeners, two framers to maintain. Violating it lets a client-facing bug become a cluster-wide compromise vector.
