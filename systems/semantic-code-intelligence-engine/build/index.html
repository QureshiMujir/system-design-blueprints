⬜ Phase 1 — Core Types + Interning + Monikers

Objectives
  • Establish scie-core as the zero-I/O foundation crate; all other crates depend on it.
  • Implement string/path interner yielding Interned(u32)/FileId(u32); SymbolId(u32) dense arena.
  • Define Position/Range as half-open spans, well-formedness enforced at construction.
  • Define Moniker { scheme, package: PackageId, descriptor: String } (SCIP grammar), SymbolRole bitflags, SymbolKind enum, PackageId { manager, name, version }.
  • Guarantee equality/hash determinism: no pointer addresses, no map-iteration order, no thread-local leakage into these types.
Deliverable
  • scie-core compiles with cargo build -p scie-core; no I/O, no std::fs.
  • Unit tests: interner roundtrip, moniker encode/parse roundtrip, Range well-formedness panics, SymbolRole bitflag composition.
  • Exported via scie_core::prelude::* for downstream crates.

⬜ Phase 2 — Syntax Front-End

Objectives
  • Build scie-syntax as a per-language adapter layer over tree-sitter grammars; define LanguageAdapter trait as the single extension point for per-language logic.
  • Implement a TypedCursor wrapping tree-sitter's cursor; expose typed NodeKind enum.
  • Map tree-sitter node kinds to DeclCategory (declaration/definition) and RefCategory (reference/import).
  • Implement byte-offset ↔ Position mapping via a line-offset table.

⬜ Phase 4 — Scope Tree Construction

Objectives
  • Build a Scope tree (module/function/block/class nodes) for each source file from the typed CST produced by scie-syntax; insert a Binding { name: Interned, symbol: SymbolId, decl_range: Range } into the nearest enclosing scope at the point each declaration is encountered.
  • Encode shadowing: an inner binding shadows an outer binding of the same name; lookup returns the nearest.
  • Model hoisting (e.g., function declarations hoisted to enclosing function scope) where the target language requires it; encode visibility (pub/private/protected) on Binding so later resolution can enforce it.
  • Emit a per-file ScopeIndex { root: ScopeId, scopes: Arena<Scope>, bindings: Arena<Binding> } as the deliverable consumed by Phase 5.
  • Constraint: ScopeIndex is a pure derived product of the CST + Phase 3 SymbolInformation table; no mutable shared state.
Deliverable
  • ScopeIndex produced for every source file; persists as an in-memory derived value memoized in scie-incremental (Phase 11).
  • ScopeIndex::lookup(scope: ScopeId, name: Interned) -> Option<BindingId> — walks parent chain respecting shadowing.
  • ScopeIndex::scope_at(pos: Position) -> ScopeId — binary-search on sorted scope spans; returns innermost enclosing scope.
  • Snapshot-serializable (bincode) for cache persistence.

⬜ Phase 5 — Intra-File Name Resolution

Objectives
  • For every identifier reference in a file, walk the ScopeIndex scope chain to bind the name to a SymbolId; produce Occurrence { range, symbol, roles: SymbolRole }. Roles distinguish Reference vs Write (assignment LHS) vs Read; apply SymbolRole bitflags accurately.
  • Unresolvable names within the file emit ResolutionResult::Unresolved and are recorded (not silently dropped) for Phase 7 to attempt cross-file resolution.
  • Deterministic nearest-binding rule: the innermost visible Binding in scope-chain order wins; no heuristics, no fuzzy matching.
  • Constraint: this phase is purely local (one file); it produces no global state; all unresolved names are passed to Phase 7.
  • Constraint (I2): every resolved Occurrence maps to exactly one SymbolId; ambiguity recorded as ResolutionResult::Ambiguous.
Deliverable
  • IntraFileResult per file: sorted, non-overlapping Vec<Occurrence> + Vec<UnresolvedRef>.
  • LocalResolver::resolve_file(cursor, scope_index, sym_table) -> IntraFileResult — pure function, no side effects.
  • Unresolved references forwarded to Phase 7 as structured UnresolvedRef records.
  • Stats logged per file; resolution rate measurable.

⬜ Phase 6 — Occurrence Model + Per-File Document Index

Objectives
  • Assemble the canonical Document { file: FileId, lang, occurrences: Vec<Occurrence>, symbols: Vec<SymbolInformation>, scopes } — the SCIP per-document unit — by combining Phase 3 (symbols), Phase 4 (scopes), and Phase 5 (occurrences). Enforce structural invariants (I3: non-overlapping sorted occurrences; I6: stable interned ids within build).
  • Define the roundtrip serialization: encode(Document) -> Bytes / decode(Bytes) -> Document; must satisfy decode(encode(d)) == d (I8).
  • Derive a document symbol outline (for LSP textDocument/documentSymbol) from symbols using enclosing-symbol nesting; persist per-file Document to a scie-index shard so Phase 10 can assemble the full index.
  • Constraint: Document is the atomic unit for incremental invalidation; replacing a Document replaces all its occurrences atomically.
Deliverable

  • Per-file .shard files written to $INDEX_DIR; readable by scie-index merge (Phase 10).
  • Integration test: Phase 3 + 4 + 5 → DocumentBuilder → Document → encode → decode → equality.

⬜ Phase 10 — Index Serialization (SCIP/LSIF-style)

Objectives
  • Implement scie-index: encode/decode the canonical on-disk index format — versioned header + Document records (occurrences + symbols) + external-symbol table + package metadata.
  • Produce byte-deterministic output (I8) given a fixed input model.
  • Support per-shard index files and an offline merge step (multiple repos/files → single queryable index).
  • Interop target: format is a strict subset of SCIP protobuf schema (sourcegraph/scip); consumers that speak SCIP must parse the engine's output without modification.
Deliverable
  • scie-index crate compiles; encode + decode roundtrip is lossless.
  • scie-cli index subcommand produces a shard file from a set of Documents.
  • scie-cli merge combines N shard files into one.
  • scie-cli dump prints human-readable occurrence table from any shard.
  • Byte-determinism: identical Document inputs produce identical shard bytes on two separate runs.

Pitfalls
  • Corpus path normalization mismatch: reference indexer may use absolute paths; our index uses relative; moniker descriptor match may fail due to path prefix. Normalize both to repo-relative before comparison.
  • Non-deterministic map iteration leaking into monikers: if descriptor is built from HashMap iteration order, monikers differ across runs, failing stability test. Use sorted insertion or BTreeMap for descriptor construction (P6, I6).
  • Fuzz edit generates syntactically invalid file: tree-sitter parses with error nodes; incremental recompute must handle error-node occurrences consistently; do not panic. Mark such occurrences with SymbolRole::Generated or skip.
  • Merge symbol-id collision: two shards may use the same local SymbolId for different symbols; merge must remap ids through fresh interner; never alias two distinct symbols to one id (violates I2).
  • RSS measurement noise: OS page reclaim between measurements inflates or deflates RSS; take max RSS at end of indexing pass, not at query time; average over 3 runs.
  • Precision/recall denominator ambiguity: macro-generated or auto-imported names inflate Unresolved count; tag them SymbolRole::Generated and exclude from precision denominator; document exclusion in report.
  • Round-trip fidelity after merge: field ordering in protobuf-like encoding may differ; define occurrence-set equality (not byte equality) as the merge acceptance criterion; byte equality only for single-file encode/decode (I8).
