Mental Models & First Principles

The compressed insights an expert in IXP/BGP simulation holds. Each predicts a bug class. Every cited § resolves to a real heading.

MM1. A discrete-event simulator is a clock driven by a priority queue, not a loop over wall-time. Time advances to the next scheduled event; nothing happens "between" events. Predicts: deterministic, reproducible ordering from a fixed seed. Bug without it: polling or wall-clock sleeps introduce nondeterminism that breaks regression replay (P8). Applied: Phase 0–1 (event loop), ADR-05/ADR-06, §4.1 (event throughput).

MM2. Determinism is a property of total event order, and a tie-break makes it total. Two events at the same virtual time must order by a deterministic secondary key (time, seq). Predicts: identical output for identical seed+scenario. Bug without it: heap ties resolve by insertion-order luck → divergent runs flagged as determinism violations (§4.2). Applied: ADR-06 (Reverse min-heap), ADR-26 (seeded RNG), §4.1 (determinism).

MM3. A route server is the star that collapses a quadratic mesh. A bilateral full mesh is O(N²/2) sessions; an RS gives every member one O(N) session while preserving per-member policy via separate Loc-RIB views. Predicts: the N=1000 memory/convergence inflection. Bug without it: sharing one RIB across members leaks routes that policy should have hidden. Applied: Phase 6 (RS), §4.1 (session counts), §4.3 (scaling).

MM4. BGP path selection is a deterministic tie-break ladder, not a metric minimization. LOCAL_PREF → AS_PATH length → origin → MED → eBGP>iBGP → … applied in fixed order. Predicts: which route wins and why. Bug without it: treating selection as "lowest cost" produces wrong best-paths and route oscillation. Applied: Phase 4–5 (decision process), §8 (domain), I-invariants.

MM5. The RIB is three stages, not one table. Adj-RIB-In (received) → Loc-RIB (selected) → Adj-RIB-Out (advertised, post-export-policy). Predicts: where a filter applies and what a peer actually sees. Bug without it: filtering only at Loc-RIB leaks routes a peer should never receive. Applied: §8 (RIB model), Phase 5–7, §4.1 (RIB entries).

MM6. A withdrawal is as important as an announcement. Convergence is reached only when withdrawals have fully propagated; a lost withdrawal is a black hole. Predicts: PortDown→withdraw→reconverge timing. Bug without it: tracking only announcements leaves stale routes after a member leaves. Applied: Phase 9–10 (convergence/fault), §4.1 (fault recovery), MM4.

MM7. RPKI origin validation answers one question: is this (prefix, origin-AS) authorized? A ROA maps a prefix + maxLength to an authorized origin; the verdict is Valid / Invalid / NotFound. Predicts: route-origin-validation filtering behaviour. Bug without it: ignoring maxLength accepts more-specific hijacks under a valid ROA. Applied: Phase 7 (RPKI), ADR-11, §8.

MM8. The L2 fabric is a shared broadcast domain with learned, aging MAC state. Frames flood until a MAC is learned; entries age out; the table is bounded per domain. Predicts: MAC-table overflow and storm behaviour. Bug without it: unbounded MAC learning or never aging → table overflow and incorrect forwarding. Applied: Phase 2–3 (fabric), §4.1 (MAC table), §11.

MM9. Filtering is layered and order-dependent: prefix-list, AS-path, max-prefix, RPKI, IRR. Each filter can reject; max-prefix is a circuit breaker that tears the session. Predicts: which member's bad announcement is contained where. Bug without it: applying max-prefix after import wastes memory the limit was meant to bound. Applied: Phase 7 (policy), §4.1 (max-prefix breach), MM5.

MM10. Simulated time and wall-clock time are different currencies. Throughput is "events per wall-second"; latency targets are "simulated seconds to converge." Predicts: why a 1-hour simulation runs in ≤ 600 s wall-clock. Bug without it: conflating the two makes performance and correctness budgets incomparable. Applied: ADR-07 (VirtualClock), §4.1 (sim vs wall-clock targets), MM1.

Glossary · 32 terms · site-wide glossary

Adj-RIB
Per-session routing table (Adj-RIB-In / Adj-RIB-Out) held by a BGP speaker. In ixp-peering, each bilateral session has its own Adj-RIB; the route server maintains per-member Loc-RIBs serving the same role.
ARP (Address Resolution Protocol)
RFC 826 protocol mapping IP addresses to MAC addresses on a shared L2 segment. On the peering LAN, ARP requests flood to all member ports; ixp-fabric models this flooding path, and ixp-traffic resolves dst MAC via simulated ARP.
AS-path
Sequence of ASNs a BGP route has traversed. Under RFC 7947, the route server must not prepend its own ASN, so the path visible to a receiving member is identical to the path the originator sent (invariant I1).
AS-set
An IRR object enumerating the ASNs (and nested AS-sets) that a member is authorised to originate. ixp-policy expands an as-set recursively to derive the set of valid origin ASNs for IRR filtering.
Bilateral peering
A direct BGP session between two member ASes. Session count scales O(N²) with member count. Modelled in ixp-peering; compare multilateral peering.
BGP community
A 32-bit tag (u32,u32) attached to a BGP route. ixp-policy uses communities for selective announcement via the route server: announce-to-peer and do-not-announce-to-peer semantics (Phase 7).
BGP FSM
The five-state finite state machine (Idle → Connect → OpenSent → OpenConfirm → Established) governing a BGP session. Timers: ConnectRetry, Hold, Keepalive. Modelled as SessionState in ixp-peering (Phase 3).
Bogon
An IP prefix that is not legitimately routable on the public Internet (RFC 1918, documentation prefixes, unallocated space). ixp-policy's bogon filter drops announcements of such prefixes.
Broadcast domain
The set of ports that receive a broadcast or unknown-unicast frame. At an IXP the peering LAN is a single broadcast domain; modelled as PeeringLan with all member ports in scope.
LACP
Link Aggregation Control Protocol. A mechanism for bundling multiple physical ports into one logical link. ixp-fabric models LACP-like aggregation groups; traffic hashes across member ports of a LAG (Phase 9).
Loc-RIB
Local RIB; a BGP speaker's post-import, post-best-path routing table. The route server maintains one Loc-RIB per member (rib_per_member in RouteServer) so each member receives a distinct policy-filtered view (I8).
MAC aging
Automatic expiry of learned MAC-table entries after a configured inactivity interval. Prevents stale unicast forwarding state. ixp-fabric enforces aging; a port-down event triggers immediate flush (I3, I9).
MAC learning
Process by which an L2 switch records the source MAC of an ingress frame and maps it to the ingress port. Drives unicast forwarding. Keyed per broadcast domain in MacTable.
MANRS
Mutually Agreed Norms for Routing Security. A framework of routing-hygiene actions (prefix filtering, AS-path filtering, RPKI). ixp-policy's filtering primitives are aligned with MANRS recommendations.
Max-prefix
A per-session limit on the number of prefixes a peer may announce. Breach triggers session teardown (invariant I4), modelled in ixp-policy (Phase 6).
Multilateral peering
BGP sessions formed via a route server; each member holds exactly one session to the RS rather than N-1 bilateral sessions. Session count scales O(N). Modelled in ixp-routeserver; principle P6 quantifies the difference.
Next-hop preservation
RFC 7947 requirement that the route server not rewrite the BGP NEXT_HOP attribute; the receiving member sees the originating member's LAN address as next-hop (invariant I10).
NOTIFICATION
BGP error message that terminates a session immediately. ixp-peering emits a NOTIFICATION on policy violations (e.g., max-prefix breach) and transitions the FSM to Idle.
Peering LAN
The shared Ethernet segment at an IXP to which all members connect. Provides L2 connectivity and the medium over which BGP control-plane sessions are established. Modelled as PeeringLan.
Peering policy
A member's stance on which other members it will exchange routes with. Three modes: Open (peer with all), Selective (whitelist), Restrictive (blacklist/default-deny). Encoded in PeeringPolicy.
Prefix-list
An ordered set of prefix/length-range match clauses used in import or export filters. ixp-policy evaluates prefix-lists before accepting or propagating a BGP route.
ROA (Route Origin Authorisation)
A cryptographically signed object in the RPKI that states which AS is authorised to originate a given prefix. ixp-policy checks ROAs to classify routes as valid, invalid, or unknown.
Route leak
Accidental re-advertisement of a route beyond its intended scope, potentially providing unintended transit. ixp-policy and invariant I6 prevent the IXP from becoming a transit AS; I4 limits leak volume; P9 makes leaks observable.
Route server (RS)
A BGP speaker at the IXP that maintains multilateral peering sessions and distributes routes among members without inserting its own ASN. Specified in RFC 7947. Implemented in ixp-routeserver.
RPKI
Resource Public Key Infrastructure. A hierarchical PKI that binds IP prefixes to ASNs via ROAs. ixp-policy performs origin validation against an RPKI dataset; invalid routes are dropped when rpki_mode is enforced (I5).
Settlement-free peering
Exchange of traffic between two networks without monetary compensation, based on mutual benefit. The default semantic at an IXP; principle P1 prohibits transit-style re-advertisement.
Split-horizon
Rule preventing a switch port from forwarding a frame back out the port it arrived on. Applied in ixp-fabric to prevent loops on the peering LAN.
Storm control
Rate-limiting mechanism that suppresses broadcast/unknown-unicast floods when they exceed a threshold. ixp-fabric applies storm control to bound flooding overhead (Phase 11).
Traffic matrix
An N×N table of inter-member traffic rates (Mbps). TrafficMatrix drives flow generation in ixp-traffic; only member pairs with a valid route and peering relationship generate traffic (I6).
Transit
Carrying traffic for a third party between two external ASes. An IXP provides peering, not transit; routes received from one member must not be used to provide transit to another member by default (P1, I6).
Unknown unicast
A unicast frame whose destination MAC is not in the MAC table. The fabric floods such frames to all ports in the broadcast domain (I2). Containment is critical for scalability (Phase 11).
VirtualClock
The monotonic simulation clock in ixp-sim. Advances by dispatching SimEvent records in (time, seq) order. Provides determinism (P8).
