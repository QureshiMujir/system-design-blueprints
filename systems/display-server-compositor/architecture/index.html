3.2 Box Narratives

  • server (event loop). The single owner of control flow: an epoll loop over the listen socket, every client fd, the libinput fd, the DRM fd, and timer/idle sources. Per-client, it reads the recv ring + ancillary fd ring, frames messages (wire), and dispatches each request serially in arrival order (I4). Writes are buffered and flushed once per loop iteration. No protocol dispatch ever runs off this thread; only rendering/decoding may be offloaded.
  • objects. The per-client namespace: a map ObjectId → Resource. Clients allocate ids in [1, 0xFEFFFFFF]; the server allocates server-side ids from 0xFF000000 (I2). Each Resource carries its interface, negotiated version, opcode-handler table, and typed userdata. Destruction emits wl_display.delete_id so the client may recycle the id (I3). This is where every use-after-free is prevented or created.
  • protocol + shell. The object implementations. wl_display (sync/get_registry, error/delete_id), wl_registry (global/bind), wl_compositor/wl_surface (the central object — attach/damage/frame/ regions/transform/scale/commit), wl_shm pools and wl_buffer (release protocol), wl_seat and the input objects, wl_output. shell adds xdg-shell (the configure/ack lifecycle that turns a surface into a window), subcompositor, viewporter, presentation-time, linux-dmabuf, layer-shell, data-device.
  • scene. The compositor's model of what is on screen. Each wl_surface has double-buffered state: a pending set mutated by requests and a current set swapped in atomically on commit (I5). Surfaces have roles (toplevel/popup/subsurface/layer/cursor/dnd-icon) and form a tree (subsurfaces) within a scene graph (per-output, per-layer stacking). It accumulates damage (surface-local → output-local), owns the output layout (positions/transforms/scales), and answers input hit-tests via input regions.
  • alloc. The buffer boundary. wl_shm buffers are a client memfd mmap'd read-only into the compositor (CPU pixels for the software renderer or texture upload). linux-dmabuf buffers are imported as EGLImage/GBM bo for zero-copy GPU texturing and possible direct scanout. It tracks the buffer-release protocol — a buffer must be wl_buffer.released before the client may reuse it (I6) — and the negotiated format/modifier set.
  • render. Renderer + Texture traits with two backends: a GLES2 renderer (an EGL context per output/GPU, client buffers as textures via EGLImage or glTexImage2D from shm, an FBO or the GBM surface as target, glScissor to the damage region) and a software renderer (CPU coverage + alpha blend, reusing #169) for headless/no-GPU. It consumes the scene's node list + damage and produces a composited framebuffer.
  • backend. The hardware abstraction. DRM/KMS+GBM: enumerates connectors/CRTCs/encoders/planes, performs atomic modeset, allocates scanout buffers via GBM, page-flips on vblank, drives a hardware cursor plane, and (P7) assigns a fullscreen opaque surface directly to an overlay plane (direct scanout, zero compositing). headless: an in-memory framebuffer + a synthetic vblank timer (CI + golden-image readback). nested: renders into a parent X11/Wayland window for development. Emits vblank/page-flip-done, hotplug, and session-active/inactive events into the loop.
  • input. libinput (over a udev/seat-provided device fd set) produces evdev events; the seat routes them: pointer motion/button/axis with surface-local coordinates, keyboard key/modifier state via an xkbcommon keymap (shared to clients as an fd), touch, and the focus model (which surface receives keyboard input). It allocates the monotonic input serials that gate xdg-shell interactions and selection (I7). Keyboard input goes only to the focused surface — the isolation guarantee.
  • session/seat (libseat). Acquires DRM master and input-device fds without running as root, and handles VT switching (pause/resume the backend + input on session deactivate/activate). The privilege seam.
  • GPU / display hardware & input devices. The external world: the kernel DRM driver + the panel, and the evdev input devices. The compositor is a client of both.

3.3 Boundaries

  • Trust boundary: the client socket. Every request's object id, opcode, arg lengths, string/array bounds, and passed fds are attacker-controlled and validated before use (I1, I12, §26). Clients never see each other's objects, buffers, or input (the isolation contract).
  • Concurrency boundary: protocol dispatch is single-threaded (the event-loop thread); there are no locks on the object graph or scene. Only the renderer's GPU/CPU pixel work and media decode may run on a worker pool, fenced back to the loop (I11). A surface's state is only ever mutated on the loop thread.
  • Privilege boundary: DRM master + input fds are held via libseat; on VT-switch the compositor drops the GPU/input and restores on resume. No raw-root requirement.
  • Buffer boundary: client wl_shm memory is mapped read-only and its size/stride/format validated against the pool (a client shrinking a pool under us must not cause an OOB read — I8); dmabuf imports are validated against the advertised format/modifier set.

3.4 Data-flow walk — one client frame (shm, headless or DRM)

  1. Client binds wl_compositor, wl_shm, xdg_wm_base; create_surface; xdg_wm_base.get_xdg_surface + get_toplevel; commit (no buffer) → compositor sends the initial xdg_surface.configure(serial).
  2. Client ack_configure(serial), creates a wl_shm pool from a memfd, create_buffer, draws pixels, wl_surface.attach(buffer), damage, frame(cb), commit.
  3. On commit the compositor swaps pending→current SurfaceState (I5), maps/validates the buffer (I8), marks the surface mapped, and accumulates surface→output damage in the scene.
  4. The repaint scheduler, woken for the next vblank, walks the scene graph for that output, builds the damaged node list, and the renderer composites (software: blend; GLES2: textured quads scissored to damage) into the output framebuffer.
  5. The backend commits the framebuffer atomically (DRM drmModeAtomicCommit with PAGE_FLIP_EVENT; headless: schedule the synthetic vblank).
  6. On page-flip-done (vblank), the compositor sends wl_buffer.release for the now-scanned-out buffer (I6), fires the frame callback done(time) (I9) so the client may draw the next frame, and emits any wp_presentation feedback. The client, throttled by the callback, draws frame N+1.

8. Domain Model — The Wayland Protocol

8.1 The wire format

A connection is a byte stream of 32-bit-aligned, little-endian messages plus an out-of-band fd stream (ancillary SCM_RIGHTS data). Each message:

word 0:  object_id : u32                        // sender's target object
word 1:  (size : u16 << 16) | (opcode : u16)    // size = total bytes incl. 8-byte header; opcode = request/event #
words 2..: arguments, each 32-bit aligned

Argument wire encodings:

int / uint   : 1 word (i32 / u32)
fixed        : 1 word, signed 24.8 fixed point (wl_fixed_t)         // sub-pixel coords
object       : 1 word, an object_id (0 = null)
new_id       : 1 word (known interface) | (string iface + uint version + uint id) for wl_registry.bind
string       : 1 word length (incl. trailing NUL) + UTF-8 bytes, padded to 4
array        : 1 word length (bytes) + raw bytes, padded to 4
fd           : NOT in the stream — consumed in-order from the ancillary fd queue

Requests flow client→server, events server→client; both use the identical framing. The decoder must treat size, string/array lengths, and the fd count as untrusted (I1, I8, I12).

8.2 Objects, interfaces, versions

The protocol is object-oriented over the wire. An interface (e.g. wl_surface) defines numbered requests (client→server) and events (server→client) plus enums. An object is an interface instance with an id, created by a request carrying a new_id (factory pattern). Each interface has a version; wl_registry.bind negotiates it (I13). The bootstrap object is wl_display (id 1, always present).

interface wl_compositor {
  request create_surface(new_id wl_surface);
  request create_region(new_id wl_region);
}

8.3 The bootstrap handshake (sequence)

client                                  compositor
  | connect AF_UNIX wayland-0  ───────────►|
  | wl_display.get_registry(new_id=2) ───►| create wl_registry #2
  |                                        |─ global(name=1, "wl_compositor", v=6) ─►
  |                                        |─ global(name=2, "wl_shm", v=1) ────────►
  |                                        |─ global(name=3, "xdg_wm_base", v=6) ───►   (… one per global)
  | wl_display.sync(new_id=3) ───────────►| create wl_callback #3
  |                                        |─ wl_callback.done(serial) ─────────────►   (roundtrip marker)
  | wl_registry.bind(name=1, wl_compositor, v=6, new_id=4) ─►  bind global → object #4
  | wl_compositor.create_surface(new_id=5) ─►  create wl_surface #5

sync + done is the universal roundtrip primitive (flush + "you've seen everything so far").

8.4 wl_surface — the central object and its double-buffered state

A surface is a rectangle of pixels with pending vs current state (I5). Requests stage pending; commit swaps:

pending: { buffer: Option<wl_buffer>, buffer_dx/dy, damage: Region (surface coords),
           buffer_damage: Region (buffer coords), opaque_region, input_region,
           frame_callbacks: Vec<wl_callback>, transform, scale, viewport(src,dst) }
on commit:  current ← pending ; pending.damage/frame cleared ; accumulate output damage ; (sub)surface tree applied

State-transition table (role-neutral surface):

Pending op Effect at commit Invariant
attach(buf,dx,dy) current buffer ← buf; surface size from buffer×scale÷viewport I6 (release old buffer when done)
damage(x,y,w,h) union into output damage I10 (conservative)
frame(cb) queue cb; fire at present I9 (once)
set_opaque_region optimize occlusion/blend skip must be subset-safe
set_buffer_transform/scale reinterpret buffer orientation/HiDPI size recompute
commit with no buffer (xdg) triggers initial configure xdg lifecycle

8.5 Roles and xdg-shell

A bare wl_surface has no on-screen meaning until given a role: xdg_toplevel (a window), xdg_popup (a menu/tooltip, positioned by an xdg_positioner relative to a parent), wl_subsurface (a child composited with a parent), a layer-shell layer, a cursor, or a DnD icon. A surface has exactly one role for life. xdg-shell lifecycle (the configure/ack contract):

surface.commit (no buffer) → compositor: xdg_surface.configure(serial=S)
client: xdg_surface.ack_configure(S); attach buffer; commit            // now mapped & shown
compositor (resize/maximize/focus): xdg_toplevel.configure(w,h,states[]) + xdg_surface.configure(S2)
client: ack_configure(S2); attach buffer sized w×h; commit             // atomic resize, no flicker
compositor: xdg_toplevel.close()  (request to close)  |  client: xdg_toplevel.destroy()

The serial ties a configure to the client's acknowledging commit so resizes are atomic and unambiguous (I5). Worked example — interactive resize: user drags edge → compositor sends configure(new w,h, [resizing]) each frame → client renders at that size and acks → compositor maps the new buffer; never a half-resized frame.

8.6 wl_shm buffers

A client creates a pool from a sealed memfd (wl_shm.create_pool(fd, size)), then carves wl_buffers (offset, width, height, stride, format) from it (I8). The compositor mmaps the pool read-only and reads pixels (software path) or uploads them as a texture (GLES2). The buffer-release protocol (I6): the client must not touch a buffer until wl_buffer.release. Formats: ARGB8888, XRGB8888 mandatory; others advertised via wl_shm.format.

8.7 Input — seat, focus, serials

A wl_seat advertises capabilities (pointer/keyboard/touch) and vends wl_pointer/wl_keyboard/ wl_touch. Event flow + the focus/serial model:

pointer:  enter(serial, surface, sx, sy) → motion(time, sx, sy)* → button(serial, time, btn, state)
          → axis(time, axis, value) → frame()   (frame groups one logical event)
keyboard: keymap(format, fd, size) once → enter(serial, surface, keys[]) → key(serial, time, key, state)
          → modifiers(serial, depressed, latched, locked, group) → leave(serial, surface)

Keyboard enter/key go only to the focused surface (I7). Serials are monotonic and tag every input-derived event; interactive requests (xdg_toplevel.move/resize, wl_data_device.set_selection, set_cursor) must cite a recent valid serial or are rejected (I7) — this prevents a background client from, e.g., grabbing the pointer or stealing the clipboard.

8.8 Output, layout, transform, scale

A wl_output describes a monitor: geometry(x,y,phys_w,phys_h,subpixel,make,model,transform), mode(flags,w,h,refresh), scale(factor), name/description, terminated by done. The compositor owns the layout (where each output sits in a global compositor-space coordinate system) and per-output transform (rotation/flip) and scale (HiDPI integer scale; fractional via viewporter). A surface overlapping an output gets wl_surface.enter(output); clients pick buffer scale accordingly.

8.9 Subsurfaces, viewporter, presentation-time, dmabuf (extension semantics)

  • wl_subsurface: a surface composited at an offset relative to a parent; synchronized mode caches its commits until the parent commits (atomic nested update, I16); desynchronized applies immediately.
  • wp_viewporter: a src crop rect (in buffer coords) + a dst size → scaling/cropping without a new buffer (video letterboxing, fractional scale).
  • wp_presentation: feedback(surface) → presented(tv_sec, tv_nsec, refresh, seq, flags) with the actual scanout time (for A/V sync) or discarded.
  • zwp_linux_dmabuf_v1: advertises (format, modifier) pairs; the client builds a buffer from dmabuf fd(s) + plane layout + modifier; the compositor imports it as an EGLImage (zero-copy texture / direct scanout candidate, §19).

Input Correct behavior
size < 8 or not 4-aligned or > recv data wl_display.error(INVALID_METHOD) + disconnect (I1)
request to a destroyed/never-allocated object id error(INVALID_OBJECT), disconnect
opcode ≥ interface's request count (for negotiated version) error(INVALID_METHOD) (I13)
new_id already in use, or client id ≥ 0xFF000000 error(INVALID_OBJECT) (I2)

second role assigned to a surface role-specific error (e.g. xdg_wm_base.error(ROLE))

interactive resize citing a stale/forged serial ignored (I7)
client exceeds object/buffer/byte cap error(NO_MEMORY)-class + disconnect (I14)

Design principles (§6)

  • The wire decoder is the security perimeter; validate every byte before it becomes a pointer. Object ids, opcodes, lengths, string/array bounds, fd counts — all attacker-controlled, all checked before use (I1, I12). Violation: trusting a length → OOB read, a sandbox escape from one client into the compositor's address space.
  • Mechanism in the compositor, policy in the WM. The server provides surfaces, input routing, scanout; where windows go and how they're decorated is a thin, replaceable layer (the wlroots split). Violation: baking tiling/stacking into the core → an unembeddable, unforkable compositor.
  • All state application is atomic and double-buffered — at both layers. Surface state applies on commit; KMS state applies on atomic commit; never a partial frame or torn protocol state (I5). Violation: applying attach immediately → flicker/tearing and protocol races.
  • Backpressure via frame callbacks + buffer release, never busy-loops or timers. Clients animate only when told a frame was presented; buffers can't be reused until released (I6, I9). Violation: firing frame on a timer → clients render faster than refresh, wasting GPU/power and adding latency.
  • Damage-driven repaint; do nothing when nothing changed. A static screen triggers no compositing; a small change repaints only its bounding damage (I10). Violation: repaint-every-vblank → constant CPU/GPU load, no idle, mobile battery dead.
  • Schedule repaints relative to the next vblank; sample input as late as possible. The repaint clock is the display, not a fixed timer; input is read at repaint start. Violation: render-ahead / early-sample → an extra frame of latency, the difference between snappy and laggy.
  • One thread owns the object graph and scene; offload only pixels. Protocol dispatch + state mutation is single-threaded and lock-free; only render/decode may use a worker pool, fenced back (I11). Violation: touching a wl_surface from a render thread → data races on the very lifetimes Rust is here to protect.
  • unsafe is confined to the FFI seam (libdrm/gbm/EGL/libinput/xkb) and client-buffer mmap. Everywhere else is checked Rust. Violation: unsafe leaking into the object graph → unauditable use-after-free, the bug class this project exists to eliminate.
  • The wire ABI is forever; versions are negotiated, never broken. Interfaces are versioned; bind negotiates the min of client/server version; new requests/events only ever extend (I13). Violation: changing an opcode/signature → every existing client breaks; Wayland's whole value is the stable ABI.
  • Buffers are zero-copy where the hardware allows. dmabuf imports texture directly; a fullscreen opaque surface scans out from its own buffer on an overlay plane (direct scanout) (I-direct). Violation: always glReadPixels/CPU-copy → bandwidth + latency + power blown.
  • Bounded everything: objects, buffers, pool memory, recursion (subsurfaces), per-client. Every client-driven growth has a configurable cap (I14, §26). Violation: an unbounded object map → one client OOMs the compositor and takes down every other client's session.
  • Isolation by construction: no client sees another's input, buffers, or objects. Keyboard input goes only to the focused surface; there is no global input/screencopy without an explicit, privileged protocol (I7, §26). Violation: a keylogger-as-a-client — the failure X11 is infamous for.
  • Crash-only, per-client fault isolation. A malformed request → a wl_display.error + disconnect of that client; the compositor and all other clients continue (I1). Violation: a panic on bad input → the whole session dies because one app misbehaved.
  • Observability by default. Every commit, repaint, page-flip, plane assignment, focus change, and protocol error is traceable with timings; latency is measurable, not guessed. Violation: an opaque repaint loop → unprofilable judder and "feels laggy" bug reports with no data.
  • Backend/renderer/allocator are abstractions, resolved at startup. DRM vs headless vs nested; GLES2 vs software — chosen once, behind traits, so CI runs headless and dev runs nested. Violation: hard-coding DRM → no CI, no dev-on-laptop, untestable.
