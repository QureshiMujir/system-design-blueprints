Hard questions (§37)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. (§8.1 + §12) A client sends a wl_surface.attach message where the size field is 0xFF000010 (a large value). Walk through every check the wire decoder must perform before the message reaches the surface handler. What invariants does each check enforce, and what is the blast radius if any one is skipped?
  2. (§8.7 + §21) A client calls wl_data_device.set_selection(source, serial=42). The compositor's current serial counter is at 100. Should this be accepted? Why does the Wayland serial model defeat a malicious background client even if it can sniff the serial from another client's event stream?
  3. (§14 + §19) A surface moves 50 px to the right. Derive the output-space damage rectangle produced by the scene's damage accumulation. How does the buffer-age mechanism (§19) extend this to a multi-frame repaint, and what goes wrong if the age is off by one?
  4. (§17 + §23) A VT-switch-away arrives while a drmModeAtomicCommit is in flight. Trace every state transition in the DRM/KMS backend and session module that must happen, in order, without triggering a use-after-free on the in-flight framebuffer (I15). Which invariant prevents a black screen on return?
  5. (§12 + §26) The fuzz harness sends a message with object_id = 0xFF000001 (a server-side id) from the client side. What invariant fires, what error is sent, and why does the compositor continue serving other clients? Now trace the same exploit for object_id = 0.
  6. (§13 + §19) A client calls wl_shm_pool.resize(new_size) smaller than an existing wl_buffer's offset + stride × height. When must the compositor detect this? How does I8's "re-validate on every access" model prevent the OOB read, and what would happen under a "validate at create" model?
  7. (§8.4 + §20) A synchronized subsurface tree has depth 5. The client commits the leaf, then the intermediate, then the root. In what order does commit apply state to current, and why is the entire tree visible only after the root commit? What does the depth cap (I16) prevent, and how is it implemented without recursion?
  8. (§4.1 + §24) At 60 Hz the render takes 9 ms. The vblank offset is currently set to −8 ms. What happens? Now recalculate the correct offset assuming 10 ms render + 1 ms margin. How does increasing refresh to 120 Hz change the arithmetic, and what breaks at 144 Hz without re-tuning?
  9. (§17 + §19 + §22) A fullscreen opaque dmabuf surface engages direct scanout. A system notification pops up as a zwlr_layer_shell_v1 overlay surface. Trace the exact sequence of plane assignments, test_commit calls, and fall-back decisions the compositor must make to transition from direct scanout to composited output within a single atomic commit without a flash (I15).
  10. (§16 + §21) Two clients, A (keyboard-focused) and B (background), both call wl_data_device.set_selection with serial=S at the same instant (two separate socket messages). The compositor processes A first, then B. What state does the compositor hold after both? Does the serial check alone prevent B from stealing the clipboard, or is focus also required?
  11. (§3 + §32 + §33) A compositor serves 200 simultaneous clients, each animating at 60 Hz with a 1080p shm surface. Compute the total socket read bandwidth, the shm-to-GPU upload bandwidth, and the per-output composite bandwidth. Which resource saturates first? What architectural change (one from §19) eliminates the bottleneck?
  12. (§12 + §13 + §25) A client mounts an fd-exhaustion DoS: it sends wl_shm.create_pool with a fresh memfd fd 10,000 times per second. Walk through the cap enforcement path (I12, I14) and explain why this disconnects only that client, not all others. What is the worst-case fd leakage before the cap fires?
  13. (§18 + §19) The GLES2 renderer's glScissor is set to the damage rectangle. A surface partially outside the output is attached. Trace the coordinate transformations from surface-local damage to output-local framebuffer scissors, including the y-flip and any output transform. What goes wrong if any one transform is applied twice?
  14. (§20 + §28) A RepaintTrace shows sample_to_render_ns = 2.1 ms, render_ns = 6.3 ms, commit_ns = 0.4 ms, flip_latency_ns = 14.2 ms. Is the §4 target met? Identify the dominant latency contributor and the one architectural change (from §6 principles) that would most reduce it.
  15. (§8.5 + §15) A client sends xdg_toplevel.move(seat, serial=S) where S was generated by the compositor for a wl_pointer.button event 3 seconds ago. Is the compositor required to reject it? If it rejects it, what error is sent? If it accepts it, what invariant does I7 say must be checked first, and why is "recent" not formally specified?
  16. (§26 + §30 + §25) A fuzzer discovers that a specific 24-byte message causes the compositor to exit with a panic rather than sending a wl_display.error and continuing. Classify this as a security bug or correctness bug, explain the mitigation path (I1 + catch_unwind), and describe the regression fixture that must be added.
  17. (§19 + §36.C1 + §4.1) A 4K @ 60 Hz display with direct scanout disabled is running 8 fullscreen clients. Compute the GPU compositing bandwidth required and explain whether the §4 frame budget can be met. Which phase (P7 or P12) and which mechanism reduce this to zero?

34. Mental Models & First Principles

MM1. The compositor is a protocol multiplexer, not a window manager. The server demuxes N client object graphs over N sockets and is the sole KMS client; window placement is a thin policy layer (principle 2). Predicts: separating the WM from the compositor enables compositors-as-libraries (wlroots). Bug class without it: baking tiling into the server makes it un-embeddable; every fork must re-implement the full stack. Applied: §3 (architecture), §15 (P3 xdg-shell policy split), §22 (P10 layer-shell / demo WM).

MM2. Surface state is a double-buffered state machine; commit is the only clock edge. Requests stage pending state; commit atomically swaps it to current (I5). No request can cause a partial frame. Predicts: any request that "takes effect immediately" (not at commit) creates a race. Bug class without it: attaching a buffer before committing gives the compositor a dangling reference; mid-frame updates cause tearing. Applied: §8.4, §11.4, all phases (I5 is a compositional invariant).

MM3. The wire decoder is the security perimeter; every byte is attacker-controlled. Object ids, sizes, string lengths, fd counts — all forged-able. Predicts: a single missing bounds-check is a sandbox escape. Bug class without it: OOB read from a forged size; UAF from a client id in the server's namespace (I2). Applied: §8.10, §12 (P0 wire fuzz), §26 (threat model), §30 (fuzz strategy).

MM4. Backpressure is credit-based: wl_buffer.release gates reuse, frame callback gates the next draw. The compositor holds a credit (the buffer) until it is done reading it; the client holds a credit (a frame slot) until the compositor fires the callback. Predicts: missing a release starves a single-buffered client forever; firing frame before present causes over-rendering. Bug class without it: stale-buffer tearing (I6 violation); GPU/power waste from unconstrained animation. Applied: §8.4, §13 (P1), §20 (P8 scheduler), §27 (failure mode: client buffer starvation).

MM5. Damage drives the repaint clock; vblank drives the scanout clock. Nothing repaints if nothing changed; repaints are scheduled relative to the next vblank, not a fixed timer. Predicts: a static screen costs ~0 CPU/GPU; render-ahead adds exactly one frame of latency. Bug class without it: repaint-every-tick wastes 100 % idle GPU; early-sample adds a frame of input lag. Applied: §4.1 (latency budget), §14 (P2 damage), §20 (P8 scheduler), §24 (P12 hardening, I10).

MM6. Atomic KMS commit is an all-or-nothing hardware transaction. TEST_ONLY validates the plane/mode configuration without touching hardware; PAGE_FLIP_EVENT signals when the new buffer is live. Predicts: a non-atomic modeset produces tearing or a black frame; freeing a framebuffer before its PAGE_FLIP_EVENT produces scanout-of-freed-memory. Bug class without it: I15 violations — torn frames, GPU hang on freed fb. Applied: §17 (P5 DRM/KMS), §23 (P11 VT-switch re-modeset), §27 (failure mode: tearing, black screen).

MM7. The single-threaded loop is lock-free by construction. All protocol dispatch + scene mutation happens on one thread; workers receive owned pixel buffers and return them fenced. No lock needed on the object graph or scene. Predicts: sharing any Resource or Scene handle with a worker thread introduces data races invisible at compile time. Bug class without it: I11 violations — concurrent surface mutation during a worker repaint; TOCTOU on SurfaceState. Applied: §3.3 (concurrency boundary), §6 (principle 7), §11.3 (Cx design), §25 (TSan tests).

MM8. Interface versioning is forever; bind negotiates the minimum. Interfaces never remove or renumber requests/events; a client binding vN gets exactly the API it asked for. Predicts: any opcode renumbering or signature change breaks every existing binary compiled against that interface. Bug class without it: I13 violations — a v4 client sending a v5 opcode silently corrupts state. Applied: §8.2, §8.3, §12 (P0 opcode dispatch), §29 (compatibility guarantees).

MM9. Zero-copy is a hierarchy: shm → texture upload → dmabuf → direct scanout. Each step removes a buffer copy. shm requires a CPU upload per frame; dmabuf textures without copying; direct scanout skips compositing entirely. Predicts: the biggest per-frame bandwidth saving is dmabuf import; the biggest latency saving is direct scanout. Bug class without it: always-uploading-shm wastes bandwidth for GPU clients; missed direct-scanout adds composite latency on the critical path (#291, §4.1). Applied: §13 (P1), §18 (P6), §19 (P7 dmabuf+direct scanout), §32 (performance engineering).

MM10. Serial monotonicity is the isolation protocol; a stale serial is a forgery. Interactive requests (move, resize, set_selection, start_drag) must cite a recent input serial to prove they were triggered by the user, not a background client. Predicts: a background client can never grab the pointer or steal the clipboard if serials are checked. Bug class without it: I7 violations — a malicious client sends xdg_toplevel.move with a fabricated serial and hijacks window management; the classic X11 keylogger attack. Applied: §8.7, §16 (P4 serial pool), §21 (P9 data device), §26 (threat model: clipboard/DnD theft).

Required reading (§5)

5.1 Books

  • Kerrisk, The Linux Programming Interface — ch.57–61 (sockets, Unix-domain), ch.63 (epoll), sendmsg/recvmsg + SCM_RIGHTS ancillary data, memfd/mmap. Applied in §12 (P0): the socket accept loop, fd ring, and wl_shm pool mmap.
  • Drepper, What Every Programmer Should Know About Memory — cache/bandwidth for the compositing/copy paths and why damage-driven partial repaint matters. Applied in §14 (P2) and §24 (P12): damage-scissored compositing and per-frame allocation elimination.
  • Hennessy & Patterson, Computer Architecture (6e) — memory hierarchy + DMA; framing for dmabuf zero-copy and scanout bandwidth. Applied in §19 (P7): dmabuf import, the back-of-envelope scanout bandwidth model, and direct-scanout rationale.
  • Tanenbaum & Bos, Modern Operating Systems — IPC, scheduling, the privilege/session model; framing for the soft-real-time repaint loop and libseat. Applied in §23 (P11): libseat privilege model and VT-switch state machine.
  • Akeley/Segal et al., OpenGL (the Red Book) + the OpenGL ES 2.0 spec — textures, FBOs, the programmable pipeline the GLES2 renderer uses. Applied in §18 (P6): EGL context, glTexImage2D, FBO setup, glScissor damage clipping.
  • Gregory, Game Engine Architecture (3e) — the main loop, frame pacing, double/triple buffering, input latency — the same scheduling concerns as a compositor's repaint loop. Applied in §20 (P8): vblank-relative repaint scheduler, late input sampling (principle 6), and the §4.1 latency budget derivation.
  • Foley, van Dam et al., Computer Graphics: Principles and Practice — 2-D compositing, alpha blending (Porter–Duff), transforms; the software renderer's math. Applied in §13 (P1) and §14 (P2): premultiplied-alpha over operator (ADR-23), the software coverage/blend kernel.
  • Love, Linux System Programming — fd lifetime, signals, resource limits; the operational realities of a long-lived privileged daemon. Applied in §12 (P0) and §25 (P13): fd ownership tracking (I12), RLIMIT_NOFILE cap rationale, the crash-only client-disconnect model.

5.2 Papers / Specifications-as-literature

  • Høgsberg et al., "Wayland Architecture" (freedesktop docs) — the design rationale: why the compositor is the server, the request/event model, the role of xdg-shell. Applied in §8, §12 (P0), §15 (P3): the global/bind bootstrap, the object model, the xdg-shell configure/ack lifecycle.
  • Porter & Duff, "Compositing Digital Images" (SIGGRAPH 1984) — the over operator + premultiplied alpha; the algebra of every blend the renderer does. Applied in §13 (P1) and §18 (P6): the over blend in the software and GLES2 renderers (ADR-23), and in the Comparative Architecture Table's pixel-pipeline row.
  • Packard & Gettys, "The X Render Extension" (and Packard's KMS/DRM writeups) — the lineage from X to KMS planes; informs the plane-assignment + damage model. Applied in §17 (P5): the plane enumeration model and the atomic modeset rationale (ADR-7), and in the Comparative Architecture Table.
  • "Atomic Mode Setting" (kernel DRM docs / Wiens, Vetter talks) — the atomic KMS state model (properties, planes, TEST_ONLY, PAGE_FLIP_EVENT); the backend's core contract. Applied in §17 (P5): AtomicState, test_commit, PAGE_FLIP_EVENT handling (I15), and ADR-7.
  • "The DRM/GEM + dma-buf buffer sharing model" (kernel docs) — dmabuf import/export, implicit fences; the zero-copy + sync semantics. Applied in §19 (P7): zwp_linux_dmabuf_v1 implementation, eglCreateImageKHR, implicit fence handling (I6), and the Back-of-Envelope capacity model.
  • Pulkkinen / Larsson, "Weston repaint scheduling" (Collabora blog series) — the vblank-relative repaint loop + frame-callback throttling; the latency model. Applied in §20 (P8) and §24 (P12): the repaint scheduler design, the vblank-offset tuning, and the §4.1 latency budget.
  • "libinput: building a generic input stack" (Hutterer) — pointer acceleration, the seat model, tap/ click semantics; the input layer. Applied in §16 (P4): libinput context setup, seat capabilities, pointer acceleration, device hotplug handling (ADR-11).
  • "xkbcommon" design notes (Herrb/Hutterer) — keymap compilation + state; how the keymap fd is shared. Applied in §16 (P4): XkbKeymap compilation, keymap fd sharing, modifier-state tracking (ADR-12).

5.3 Reference Implementations

  • wlroots (types/, backend/{drm,libinput,headless,wayland}, render/{gles2,pixman}, util/) — the modular compositor library this project mirrors. Study; do not copy (MIT, but re-derive). Applied in §3 (architecture), §17–18 (P5–P6), §19 (P7): the backend/renderer/allocator abstraction, scene graph structure, and plane-assignment logic. Pitfall: its wl_signal listener pattern is C-idiomatic; we use Rust ownership instead.
  • Weston (libweston/, compositor/, clients/) — the reference compositor + the protocol test clients (weston-simple-shm, weston-simple-egl, the test-suite). Applied in §12–25 (P0–P13): its clients are the conformance oracle for every phase. Pitfall: heavier, more policy baked in.
  • libwayland (src/wayland-{server,client,private}.c, connection.c, wayland-scanner) — the wire format + scanner we re-implement. Applied in §12 (P0) and §8: wire semantics, the new_id-in-bind special case, fd queue decoupling. Pitfall: its object/refcount model is the exact C footgun Rust ownership replaces.
  • Smithay (src/wayland/, src/backend/, src/desktop/) — a safe-Rust compositor library; the closest model in our language. Applied in §11 (types) and §12–13 (P0–P1): how to express the object graph, Resource<I>, and SurfaceState pair in safe Rust. Pitfall: don't copy; re-derive to learn the borrow patterns.
  • Mesa (EGL platform_gbm, GLES2) + libdrm (xf86drmMode.c, atomic API) + GBM — the GPU/scanout libraries we call via FFI (the OS boundary). Applied in §17 (P5) and §18 (P6): the exact gbm_surface + EGL context + atomic-commit dance. Pitfall: driver-specific quirks (modifiers, async flips) — gate behind capability probes.
  • libinput + libudev + libseat + xkbcommon — the input/session libraries we FFI. Applied in §16 (P4) and §23 (P11): seat/focus/serial model + VT-switch privilege handoff (ADR-11/12/13). Pitfall: device hotplug + VT-switch edge cases.
  • Sway / wlr-protocols — wlr-layer-shell, the demo of a real WM on wlroots. Applied in §22 (P10): layer-shell anchor/exclusive-zone semantics and the WM-as-thin-policy split (principle 2).

Glossary (§40) · 36 terms · site-wide glossary

Compositor / display server
the process that owns the screen + input, multiplexes clients, and scans out the composited result. Here, the same process.
Client
a Wayland application connected over the socket; isolated from other clients.
Wire protocol
the byte-level message format (§8.1): object id + opcode/size header + typed args.
Object / interface / version
a protocol entity, its type, and the negotiated capability level (I13).
wl_display
the bootstrap object (id 1): get_registry, sync, error, delete_id.
wl_registry / global / bind
the discovery mechanism: the server advertises globals; the client binds one to an object (I13).
wl_surface
the central object: a rectangle of pixels with double-buffered state (I5).
Role
the meaning given to a surface (toplevel/popup/subsurface/layer/cursor/dnd-icon); exactly one.
commit
the atomic pending→current state swap (I5).
Double-buffered state
pending (staged by requests) vs current (applied at commit).
wl_buffer / wl_shm / dmabuf
pixel storage: shared-memory pool buffers or zero-copy GPU dmabuf.
Buffer release
the protocol that gates client buffer reuse (I6).
Frame callback
wl_surface.frame → done at present; the throttling primitive (I9, principle 4).
xdg-shell
the windowing protocol: toplevels, popups, the configure/ack lifecycle (§8.5).
Configure / ack_configure / serial
the atomic-resize handshake; serials gate interactions (I7).
Seat / focus / serial
the input model: a seat's devices, the focused surface, monotonic event tags (I7).
Scene graph
the retained model of on-screen surfaces: outputs → layers → nodes (ADR-30).
Damage
the region of changed pixels; drives partial repaint (I10).
Backend
the hardware abstraction: DRM/KMS, headless, nested.
DRM / KMS
the kernel display API: connectors, CRTCs, encoders, planes.
Atomic modeset / TEST_ONLY / page-flip
the tear-free state-application API (I15).
GBM
the buffer allocator bridging GL/EGL to KMS scanout.
EGL / GLES2
the GPU context + rendering API of the GLES2 renderer.
EGLImage
a dmabuf imported as a GL texture (zero-copy).
Plane (primary/overlay/cursor)
a hardware compositing layer; direct scanout + hw cursor use these.
Direct scanout
assigning a surface's buffer directly to a plane, bypassing compositing (§19).
Buffer age
frames since a reused fb was last current; drives partial repaint (§19).
Vblank / page-flip-done
the display refresh tick; the repaint clock (principle 6).
libinput / evdev / xkbcommon
the input device, event, and keymap libraries.
libseat / VT switch
the privilege/session library and the console-switch lifecycle (§23, Phase 11).
Premultiplied alpha / Porter–Duff over
the compositing color model (ADR-23).
Layer-shell
the protocol for panels/wallpapers/lock-screens (background/bottom/top/overlay).
Subsurface / synchronized
a child surface; synchronized commits apply atomically with the parent (I16).
Viewporter / presentation-time
crop/scale, and accurate scanout-timestamp protocols (§8.9).
Input-to-photon latency
sample→scanout time; the headline metric (§4).
SCM_RIGHTS
the Unix-socket mechanism for passing fds between processes (I12).
