⬜ Phase 0 — Skeleton: wire codec, object map, socket, headless backend, conformance scaffold §12

Objectives
  • Stand up the Cargo workspace (ADR-2) and the wire + objects + server + backend/headless skeleton.
  • Implement the wire codec (Message framing, all arg types, SCM_RIGHTS fd ring) and the per-client object map with id-range + version validation (I1, I2, I13).
  • Bring up the wl_display/wl_registry/wl_callback bootstrap handshake; advertise zero real globals.
  • Establish the libwayland-client differential harness + headless golden-image scaffold — the oracle.
Deliverable
  • A real libwayland (or our client) connects, runs get_registry + sync, and receives a correct global/done sequence; cargo run -p server --example run_headless boots and accepts the connection.
Acceptance
  • libwayland-client completes the bootstrap handshake byte-identically to the golden trace (I4).
  • Wire round-trip (encode∘decode) identity on a corpus of every arg type; malformed messages → typed error, never a panic (I1).
  • id-range + version violations rejected (I2, I13); Miri clean on the codec; fd ring leaks zero fds (I12).
Fixtures
  • wire/good/*.bin — one per arg type + the bootstrap sequence; wire/malformed/*.bin — short size, misaligned, OOB string/array, missing fd, bad object id.
  • traces/bootstrap.golden — the canonical handshake event order.
Pitfalls
  • size is the whole message incl. header; off-by-8 truncates every arg — assert against a hand-built message (I1).
  • SCM_RIGHTS fds arrive out-of-band and can be batched/split across recvmsg differently than messages → the fd queue must be decoupled from the byte ring (I12).
  • new_id in wl_registry.bind carries an inline interface string + version (unlike every other new_id) — special-case it.
  • Little-endian + 32-bit padding on strings/arrays — pad length includes the NUL for strings.

⬜ Phase 1 — `wl_shm` + `wl_compositor` + `wl_surface` (attach/commit), software path §13

Objectives
  • Implement wl_compositor.create_surface, the wl_surface request set, and double-buffered SurfaceState with commit as the sole swap point (I5).
  • Implement wl_shm pools + wl_buffer with the release protocol (I6) and bounds-checked access (I8).
  • Get a real weston-simple-shm client's buffer onto the headless framebuffer; verify by pixel readback.
Deliverable
  • weston-simple-shm (or examples/client_shm) attaches a buffer + commits; a PNG readback shows its pixels; wl_buffer.release is observed by the client.
Acceptance
  • Committed pixels are byte-exact (0 differing pixels) against golden/shm_single_surface.png (I5).
  • A buffer is released after the compositor finishes reading it; reuse-before-release is detectable in ≤ 1 frame (I6).
  • Oversized/short pool geometry → wl_shm.error, no OOB read (I8); ASAN clean across a corpus of ≥ 20 malformed-geometry fixtures.
Fixtures
  • golden/shm_single_surface.png; wire/good/shm_pool_create_buffer.bin; wire/malformed/shm_buffer_oob.bin (geometry exceeds pool).
Pitfalls
  • A client can wl_shm_pool.resize smaller after creating a buffer → re-validate on every access, not just at create (I8).
  • Forgetting to release starves a single-buffered client (it waits forever) — release after the last read.
  • attach(NULL) un-maps the surface — a valid, easy-to-miss case.
  • Premultiplied vs straight alpha confusion → fringing; pin premultiplied (ADR-23).

⬜ Phase 2 — Scene graph + software renderer + damage tracking §14

Objectives
  • Build the retained scene graph (Output → layers → Nodes) and the output layout (ADR-30).
  • Implement damage accumulation (surface→output) and damage-scissored compositing; idle when nothing changed (I10).
  • Composite multiple overlapping surfaces correctly (z-order, opaque-region occlusion, alpha blend).
Deliverable
  • Two overlapping shm surfaces composite with correct z-order + blending; moving the top surface repaints only the damaged union; a static scene triggers zero repaints.
Acceptance
  • Composited output matches a golden PNG for a multi-surface scene (I5/I10).
  • Damaged region is a conservative superset of changed pixels (golden diff ⊆ damage) (I10); idle-frame repaint count == 0 (I10).
  • Frame callbacks fire exactly once per committed frame after present (I9).
Fixtures
  • golden/two_surfaces_zorder.png, golden/move_damage.png + the damage rect log; traces/frame_callback_once.golden.
Pitfalls
  • Damage in surface vs buffer vs output coordinates — transform carefully; a coordinate-space slip paints the wrong region (I10).
  • Opaque-region occlusion must be conservative (treat unknown as non-opaque) or you drop pixels.
  • Firing frame callbacks before present → clients race ahead (I9, principle 4).
  • An empty damage region must short-circuit the whole repaint (I10).

⬜ Phase 3 — `xdg-shell` (windows: toplevel, popup, configure/ack) §15

Objectives
  • Implement xdg_wm_base/xdg_surface/xdg_toplevel/xdg_popup/xdg_positioner and the configure/ack lifecycle (§8.5) — turning surfaces into real windows.
  • Run a real toolkit client (foot, weston-terminal, a GTK app) mapped as a window.
Deliverable
  • foot (or weston-terminal) opens as a window, renders its content, and resizes atomically; a popup menu positions correctly relative to its parent.
Acceptance
  • The initial configure→ack→map handshake matches traces/xdg_toplevel_map.golden byte-for-byte (I4/I5); a forged/old ack_configure serial → xdg_surface.error (I7).
  • Interactive resize never shows a half-resized frame across ≥ 50 resize steps (atomic, I5); popup geometry matches the positioner spec for all 8 anchor × 8 gravity combinations (64 cases, golden/popup_positioning_*.png).
Fixtures
  • traces/xdg_toplevel_map.golden; golden/popup_positioning_*.png (anchor/gravity matrix); wire/malformed/ack_configure_stale_serial.bin.
Pitfalls
  • The first commit (no buffer) must trigger the initial configure; mapping only happens after the client acks and attaches a sized buffer — getting this order wrong = a blank or never-shown window.
  • xdg_popup grab + dismiss semantics (click-outside closes) are subtle; mis-handling leaks menus.
  • Window geometry ≠ surface size (drop shadows live outside geometry).
  • ping/pong: a client that never pongs is unresponsive → mark it, but never block the loop.

⬜ Phase 4 — Input: seat, pointer, keyboard (xkb), touch, focus, serials §16

Objectives
  • Integrate libinput/libudev; implement wl_seat + wl_pointer/wl_keyboard/wl_touch; route events with surface-local coordinates and the focus model (I7).
  • Compile + share an xkbcommon keymap as an fd; track modifier state; allocate input serials (I7).
Deliverable
  • Moving the mouse moves a cursor and delivers motion to the surface under it; typing reaches only the focused window; clicking a background window focuses it.
Acceptance
  • Keyboard events never reach an unfocused surface across 0 of N ≥ 1000 fuzzed dispatch orderings (I7) — verified by traces/kbd_focus_isolation.golden (two clients).
  • Pointer coordinates are correct in surface-local space (± 0 px after transform/scale) across all 4 output transforms; serials are monotonic and stale-serial interactions are rejected (I7).
  • The keymap fd round-trips through a real client and matches fixtures/xkb_keymap_us.txt exactly (it loads our xkb keymap).
Fixtures
  • traces/pointer_enter_motion.golden; traces/kbd_focus_isolation.golden (two clients); fixtures/xkb_keymap_us.txt.
Pitfalls
  • Surface-local coordinate conversion must apply output transform + scale + surface position + viewport; any slip mis-targets clicks.
  • The keymap fd must be sent before any key event, and shared read-only/sealed.
  • Serial reuse / non-monotonic serials break set_selection + move/resize gating (I7).
  • libinput device hotplug (add/remove) must update the seat live without dropping events.

⬜ Phase 5 — DRM/KMS + GBM + EGL backend (real screen, atomic modeset, page-flip, hw cursor) §17

Objectives
  • Implement the backend::drm path: enumerate connectors/CRTCs/encoders/planes, perform atomic modeset, allocate scanout buffers via GBM, page-flip on vblank, drive a hardware cursor plane (ADR-7, ADR-31, I15).
  • Acquire DRM master + input fds via libseat (stub VT-switch; full in P11).
Deliverable
  • The compositor lights up a real monitor on a TTY, composites the P2 scene, page-flips tear-free at the panel's refresh, and shows a hardware cursor that moves without a full repaint.
Acceptance
  • test_commit validates before every real commit; no legacy SetCrtc in steady state (I15).
  • No tearing across sustained animation; a committed fb is never freed before its flip-done (I15).
  • Cold modeset < 100 ms; startup→first frame < 500 ms (§4).
Fixtures
  • backend/drm/probe-golden.json (per test-rig GPU: connectors/planes/modes); a manual on-hardware checklist (this phase is hardware-gated; CI stays headless, ADR-22).
Pitfalls
  • Atomic property discovery differs per driver; never hard-code property ids — query by name.
  • A page-flip with no fb change, or two flips before a vblank, → -EBUSY; honor the one-flip-per-vblank rule (I15).
  • GBM format modifiers must intersect with what the plane supports, or AddFB2 fails — negotiate.
  • Forgetting PAGE_FLIP_EVENT → you never learn when to release buffers (I6) or fire frames (I9).

⬜ Phase 6 — GLES2 renderer (EGL textures, scissored damage, transforms) §18

Objectives
  • Implement the render::gles2 path: an EGL context on the GBM device, client buffers as textures (shm upload + dmabuf EGLImage stub, full in P7), an FBO/GBM-surface render target, glScissor to damage.
  • Make GLES2 the default on the DRM backend; keep software for headless/no-GPU (ADR-9/10, I10).
Deliverable
  • The full scene composites on the GPU; partial repaint scissors GPU work to the damage region; transforms (rotated output) render correctly.
Acceptance
  • GLES2 output matches the software renderer's golden PNGs within a small tolerance (anti-aliasing/rounding) for the scene corpus.
  • glScissor confines GPU work to damage (I10); a sub-ms composite for a typical desktop scene.
Fixtures
  • Reuse golden/*.png from P2 with a GLES2 tolerance; golden/output_transform_*.png (90/180/270/flip).
Pitfalls
  • EGL/GBM context-current discipline (one context per thread); losing current → silent no-op draws.
  • Texture format/swizzle for ARGB8888 vs GL's RGBA — get the channel order right or colors invert.
  • Scissor is in framebuffer (post-transform) coordinates — transform the damage region first (I10).
  • y-flip between Wayland (top-left) and GL (bottom-left) conventions.

⬜ Phase 7 — linux-dmabuf zero-copy + buffer-age partial repaint + direct scanout §19

Objectives
  • Implement zwp_linux_dmabuf_v1: advertise (format, modifier) pairs, accept dmabuf-backed buffers, import as EGLImage (zero-copy texturing) (ADR-8, principle 10).
  • Implement buffer-age partial repaint (reuse the prior fb, repaint only damage since it was last current).
  • Implement direct scanout: assign a fullscreen opaque dmabuf surface to an overlay plane, bypassing compositing (the §4 latency/power headline).
Deliverable
  • A GPU client (weston-simple-egl, a video player) shares a dmabuf that textures with no copy; a fullscreen video/game scans out directly off its own buffer; partial repaint reuses the prior frame.
Acceptance
  • dmabuf import succeeds for advertised format/modifier pairs and textures correctly (golden vs shm path).
  • Buffer-age repaint paints a strict superset of changed pixels using the correct age (I10); a stale-age bug is detectable (visible artifact in the golden).
  • Direct scanout engages for a fullscreen opaque surface (0 composite, plane flip only) and disengages cleanly when an overlay (e.g. a notification) appears (§19, Edge Cases: a plane already in use by the cursor).
Fixtures
  • golden/dmabuf_vs_shm.png; golden/buffer_age_partial.png + the age/damage log; traces/direct_scanout_engage_disengage.golden.
Pitfalls
  • Implicit sync: the imported dmabuf carries a fence; reading before it signals → torn/garbage frame. Respect the fence (I6; explicit sync deferred — Deferred Features Register).
  • Buffer age is the count of frames since that specific buffer was current; off-by-one → under-damage → visible stale regions (I10).
  • Direct-scanout format/modifier must exactly match a plane's capability; mismatch → test_commit fails → fall back, never black-screen.
  • Disengaging direct scanout (when chrome appears over the surface) must re-enable compositing in the same atomic commit — no flash.

⬜ Phase 8 — Subsurfaces, viewporter, presentation-time, frame scheduling §20

Objectives
  • Implement wl_subcompositor/wl_subsurface (synchronized + desynchronized, atomic nested commit, bounded recursion, I16); wp_viewporter (crop/scale); wp_presentation (real present timestamps).
  • Implement the vblank-relative repaint scheduler + frame-callback throttling (principle 6, I9).
Deliverable
  • A client with subsurfaces (e.g. video + decorations) updates atomically; a video letterboxes via viewporter; wp_presentation reports accurate scanout times; clients throttle to refresh.
Acceptance
  • A synchronized-subsurface tree applies as one atomic frame with its parent (I16); recursion past the cap → protocol error.
  • wp_presentation timestamps match the actual flip time within a frame; viewporter crop/scale matches a golden.
  • Clients render exactly one frame per refresh under a frame-callback loop (no overdraw) (I9, principle 4).
Fixtures
  • golden/subsurface_atomic.png; golden/viewport_crop_scale.png; traces/presentation_feedback.golden; traces/frame_throttle_60hz.golden.
Pitfalls
  • Synchronized subsurface state must cache through arbitrary parent-commit nesting and apply in tree order; getting the order wrong tears the nested update (I16).
  • A frame callback fired late (or never) stalls an animating client; fired early wastes a frame (I9).
  • Viewporter source rect in buffer coords vs destination in surface coords — mixing them mis-scales.
  • Presentation seq/refresh must be monotonic + accurate for A/V sync to work.

⬜ Phase 9 — Data device: selection (clipboard) + drag-and-drop + primary selection §21

Objectives
  • Implement wl_data_device_manager/wl_data_device/wl_data_source/wl_data_offer: copy-paste (selection), drag-and-drop, and zwp_primary_selection (middle-click paste), all serial-gated (I7).
Deliverable
  • Copy in one client, paste in another (text + a binary mime); drag a file/icon from one window to another with a visible drag icon and correct drop action.
Acceptance
  • set_selection/start_drag with a stale/forged serial is rejected 100% of the time across traces/selection_set_paste.golden (I7) — a background client cannot steal or set the clipboard.
  • The paste fd transfers bytes byte-exact for ≥ 3 mime types (text/plain, text/uri-list, image/png) per traces/dnd_copy_move.golden; DnD action negotiation (copy/move/ask) matches the spec for all 3 actions.
Fixtures
  • traces/selection_set_paste.golden; traces/dnd_copy_move.golden; wire/malformed/set_selection_stale_serial.bin.
Pitfalls
  • The clipboard fd transfer is async (the source writes when the receiver reads) — don't block the loop on it; pump it as an EventSource.
  • Selection ownership changes on focus/new source; clearing it correctly avoids leaking the old offer.
  • DnD must follow the pointer grab; releasing outside any surface cancels.
  • Serial gating is the security control here (I7) — never skip it.

⬜ Phase 10 — Layer-shell, multi-output, hotplug, HiDPI/scale, chrome (#385/#398) §22

Objectives
  • Implement zwlr_layer_shell_v1 (background/bottom/top/overlay layers — panels, wallpapers, lock screens); multi-output layout + hotplug; HiDPI integer + fractional (viewporter) scale.
  • Render cursor theme + server-side decorations + window titles via #385 (rasterizer) + #398 (shaping).
Deliverable
  • A panel + wallpaper (layer-shell) render; plugging/unplugging a monitor re-lays-out live; a HiDPI output shows crisp 2× content and correctly-scaled cursor/decorations.
Acceptance
  • Layer ordering + exclusive zones match the spec (panels reserve space); hotplug add/remove never crashes and re-lays-out within a frame or two.
  • HiDPI: a 2× client buffer maps 1:1 to physical pixels; fractional scale letterboxes via viewporter without blur beyond the resampling filter.
Fixtures
  • golden/layer_shell_panel.png; golden/hidpi_2x.png, golden/fractional_1_5x.png; traces/output_hotplug.golden.
Pitfalls
  • Exclusive zones must reduce the usable area for toplevels or panels overlap windows.
  • Hotplug mid-frame: a removed output must drop its in-flight fb/flip cleanly (I15); surfaces on it migrate.
  • Mixed-DPI multi-output: a surface spanning a 1× and a 2× output needs the larger scale; clients pick via enter.
  • Cursor scale must match the output it's on, or it's tiny/huge across a DPI boundary.

⬜ Phase 11 — Session / seat management (libseat, VT switch, multi-seat, master lease) §23

Objectives
  • Full session integration: acquire/release DRM master + input fds via libseat; handle VT-switch (deactivate→drop GPU/input, activate→restore + full re-modeset); support multi-seat and DRM lease/revoke.
Deliverable
  • Ctrl+Alt+F2 switches away (screen released to the other VT) and back (the session restores intact); a second seat drives an independent pointer; a lease hands a connector to another process.
Acceptance
  • On VT-switch-away (≤ 1 s, §4) the compositor stops touching the GPU/input (the other VT works); on return it re-modesets in < 100 ms (§4, ADR-7) and repaints without artifacts or lost clients (I15), verified by traces/vt_switch_cycle.golden.
  • No raw-root required (libseat handles privilege) across 0 UID-0 processes; input devices added/removed live update the right seat within 1 dispatch cycle.
Fixtures
  • traces/vt_switch_cycle.golden (deactivate→activate state machine); a manual on-hardware checklist (this phase is hardware-gated).
Pitfalls
  • After VT-return the GPU state is gone — you must re-modeset and fully re-damage, not assume the old fb is live (I15).
  • Input fds are revoked on deactivate; reading them after → EBADF; pause cleanly.
  • A flip in flight when deactivating must be abandoned without freeing its fb prematurely (I15).
  • Multi-seat device assignment races on hotplug — bind devices to seats deterministically.

⬜ Phase 12 — Performance hardening (latency, direct scanout, damage minimization) §24

Objectives
  • Drive input-to-photon latency to the §4 targets across renderers/backends; minimize damage; maximize direct-scanout engagement; profile + close the gaps.
Deliverable
  • Measured sample→photon ≤ 1 frame + render on the DRM backend; idle screen = 0 repaints/0 GPU; fullscreen video direct-scans-out at minimal latency/power.
Acceptance
  • §4 latency + frame-budget targets met on the test rig (bench gate); zero per-frame heap allocation in the repaint path; direct scanout engages whenever eligible.
Fixtures
  • benchmarks/*.toml scenarios (single window, many windows, fullscreen video, resize storm); bench latency/frame-time reports archived as baselines.
Pitfalls
  • Late sampling that overruns the budget drops the frame — the offset must be tuned to the measured render cost, with margin.
  • A single per-frame allocation (e.g. a Vec in the node walk) shows up as tail-latency jitter — hunt them with an alloc counter.
  • Over-aggressive damage minimization → stale pixels (correctness > perf); keep the conservative fallback (I10).

⬜ Phase 13 — Security / sandboxing + conformance / fuzz / soak / bench §25

Objectives
  • Close the security model: enforce all resource caps (I14), input isolation (I7), the read-only buffer model (I8), and model wp_security_context (sandboxed clients). Run the full conformance + fuzz + soak + bench matrix; this defines "Phase-0 done" for the future coding contract.
Deliverable
  • A green conformance run against real clients + the differential; clean extended fuzz; a leak-free soak; the bench gate met — a compositor that runs a real desktop session.
Acceptance
  • 100 % of the conformance corpus passes within bounds; every cap enforced (no client can OOM/fd-exhaust the compositor, I14); input isolation holds (I7); fuzz clean ≥ 10⁷ iterations (30-day run deferred).
  • Soak: stable RSS/fd count over hours (no leak); bench within §4.
Fixtures
  • The full conformance/ corpus: wire/{good,malformed}, golden/, traces/, weston-clients/; fuzz corpora; benchmarks/.
Pitfalls
  • A cap that disconnects too eagerly breaks legitimate heavy clients (browsers) — calibrate against real workloads (I14).
  • Fuzzers find the decoder edge you missed (the trust boundary) — every escape becomes a regression fixture.
  • Soak leaks are slow (one fd per N frames) — run long enough to see them.
