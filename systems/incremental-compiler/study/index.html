30. Mental Models & First Principles

  • MM1 — Incremental = memoize + validate + cut off. A derived query is a pure function; the cache holds its last value and its dependency fingerprints; you re-run only when a fingerprint changed. Predicts: recompute count ≈ size of the fingerprint-changing frontier, not the program. Bug without it: re-running downstream on unchanged values (batch-in-disguise). Applied: §13.
  • MM2 — Early cutoff is where the savings live. The graph's edges, not its nodes, are where you stop propagation: an unchanged fingerprint at an edge prunes an entire subtree. Predicts: trivia edits are nearly free (M3). Bug without it: a stable value that still forces dependents to recompute. Applied: §14, §13.
  • MM3 — Identity stability is a performance feature. If SymbolIds/spans renumber on unrelated edits, every downstream fingerprint flaps and incrementality collapses. Predicts: the biggest incremental wins come from not changing identities, not from faster recompute. Bug without it: "why does adding a comment recompile everything?" Applied: §16.
  • MM4 — Durability is a bet on change frequency. Tag rarely-changing inputs HIGH so validation skips their subgraphs by revision comparison alone. Predicts: std-lib validation is O(1) per edit. Bug without it: every keystroke walks the entire prelude. Applied: §13, §17.
  • MM5 — The dependency graph is the correctness boundary, not the cache. Cache invalidation is exactly graph reachability from changed inputs; a missed edge is a wrong answer, not a slow one. Predicts: correctness bugs are missed/extra edges. Bug without it: trusting timestamps/heuristics over recorded reads. Applied: §13 (P12, I5).
  • MM6 — WAL turns a crash into a bounded replay. Durability = "the log is the truth; the index is a cache of the log." Predicts: recovery time = replay of the WAL tail (M9), not a full rebuild. Bug without it: index-before-log ordering that loses data on crash. Applied: §18 (P7, I6).
  • MM7 — Determinism is what makes debugging possible. A pure, logical-revision system replays bit-exactly; a mismatch is a bug report. Predicts: nondeterminism surfaces as replay_mismatch_total, always. Bug without it: heisenbugs you can't reproduce. Applied: §21, §7 (P1, I11).
  • MM8 — Content addressing makes corruption self-detecting. If a value's name is the hash of its bytes, tampering/bit-rot is a name/content mismatch you catch on read. Predicts: zero silent corruption is achievable with one compare (I7). Bug without it: trusting bytes you can't verify. Applied: §18 (ADR-12, MM8→FM-4).
  • MM9 — Split a query along its firewall, not its function. Divide a computation where its consumers' interest changes (signature vs body, module-symbols vs one reference), so an edit invalidates the smallest consumer set. Predicts: the right query boundaries are where change frequency differs, not where the code is naturally factored. Bug without it: a coarse query that re-runs callers on irrelevant internal edits. Applied: §16 (symbols/resolve split), §17 (signature/body split).
  • MM10 — The cache is a derivative; the source is the truth. Every persisted byte is recomputable from source, so the cache is disposable and "backup" is meaningless for it. Predicts: the safe response to any cache doubt is discard-and-recompute, never repair-in-place. Bug without it: trying to salvage a corrupt cache and shipping a wrong answer (P15 violated). Applied: §24 (backup/restore), §18 (FM-4).

Required reading (§5)

Books

  • Cooper & Torczon, Engineering a Compiler (2nd ed.). Ch. 2 (scanners) and Ch. 3 (parsers) — the incremental lexer/parser structure. Applied in §14, §15.
  • Aho, Lam, Sethi, Ullman, Compilers: Principles, Techniques, and Tools (2nd ed., "Dragon"). Ch. 4 (parsing), Ch. 6 (intermediate code) — grammar factoring and IR shape. Applied in §15, §16.
  • Appel, Modern Compiler Implementation in ML. Ch. 5 (semantic analysis), Ch. 15 (functional IR) — symbol tables and lowering as functions. Applied in §16, §17.
  • Muchnick, Advanced Compiler Design and Implementation. Ch. 8 (SSA/IR), Ch. 9 (dataflow) — the dataflow framing behind demand-driven analysis. Applied in §17, §29.
  • Kleppmann, Designing Data-Intensive Applications. Ch. 3 (storage engines: LSM/WAL), Ch. 5 (replication/versioning) — the persistence and revision model. Applied in §18, §25.
  • Petrov, Database Internals. Part I (B-trees, WAL, recovery), Ch. 6 (log-structured) — cache-store index and crash recovery. Applied in §18, §23.
  • Gregg, Systems Performance (2nd ed.). Ch. 6 (CPU), Ch. 7 (memory) — the profiling methodology behind §28. Applied in §28.
  • Mara Bos, Rust Atomics and Locks. Ch. 2–4 (atomics, memory ordering, building locks) — lock-free memo reads and per-query locking. Applied in §19.
  • Grune & Jacobs, Parsing Techniques: A Practical Guide (2nd ed.). Ch. 8 (deterministic top-down), Ch. 16 (error recovery) — the recursive-descent + resync recovery model. Applied in §15.
  • Nystrom, Crafting Interpreters. Ch. 4–6 (scanning, Pratt parsing), Ch. 21 (variables/scopes) — the hand-written lexer/Pratt parser and scope handling. Applied in §14, §15, §16.

Papers

  • Reps, T. (1982), "Optimal-time incremental semantic analysis for syntax-directed editors," POPL. First optimal incremental attribute evaluation — the origin of demand-driven reanalysis. Applied in §13.
  • Pugh, W. & Teitelbaum, T. (1989), "Incremental computation via function caching," POPL. Memoization + dependency comparison as the general incremental mechanism. Applied in §12, §13.
  • Acar, U. (2005/2006), "Self-Adjusting Computation" (PhD thesis, CMU). Modifiable references + change propagation — the theory the query engine implements. Applied in §13, §30.
  • Hammer, M. et al. (2015), "Incremental Computation with Names" (Adapton), OOPSLA/PLDI. Demand-driven, name-indexed memoization with dirtying/cleaning — the exact validation model. Applied in §13, §31.
  • Mokhov, A., Mitchell, N., Peyton Jones, S. (2018), "Build Systems à la Carte," ICFP. Taxonomy (rebuilder × scheduler) placing this design (suspending scheduler + verifying-trace rebuilder). Applied in §9 (ADR-07), §31, §34.
  • Erdweg, S. et al. (2015), "A Sound and Optimal Incremental Build System with Dynamic Dependencies," OOPSLA (pluto). Dynamic dependency discovery + correct minimal rebuild. Applied in §13, §26.
  • The rustc Development Guide, "Queries: demand-driven compilation" and "Incremental compilation in detail." Red-green algorithm, fingerprints, DepNode, on-disk cache. Applied in §13, §18.
  • Salsa framework design notes (salsa-rs), "How Salsa works" / "Durability." Inputs, derived queries, revisions, durability, LRU. Applied in §12, §13, §20.
  • Bernstein, P. & Goodman, N. (1983), "Multiversion Concurrency Control — Theory and Algorithms," ACM TODS. MVCC — the model for revision-versioned memo reads under parallelism. Applied in §19.
  • O'Neil, P. et al. (1996), "The Log-Structured Merge-Tree (LSM-Tree)," Acta Informatica. Append-only segments + compaction behind cache-store. Applied in §18, §20.
  • Wagner, T. & Graham, S. (1998), "Efficient and flexible incremental parsing," ACM TOPLAS. Incremental parsing with subtree reuse and node reuse across edits — the direct basis for §15's reuse. Applied in §15.
  • Merkle, R. (1988), "A Digital Signature Based on a Conventional Encryption Function," CRYPTO '87. Merkle trees — the structure BLAKE3 and the CAS content-hashing rely on. Applied in §18 (ADR-12).

Reference Implementations

  • rust-lang/rust — compiler/rustc_query_system/ and compiler/rustc_query_impl/. Study dep_graph/ (red-green marking) and query/plumbing.rs. Lesson: fingerprints enable early cutoff. Pitfall not to copy: macro-heavy query DSL hurts compile times and readability — prefer explicit trait definitions. Applied in §13.
  • salsa-rs/salsa — src/ (runtime.rs, derived.rs, durability.rs). Lesson: durability tiers cut validation traversals for rarely-changing inputs. Pitfall: early Salsa's global runtime lock serialized queries — this design uses per-query locks (§19). Applied in §12, §13, §20.
  • dotnet/roslyn — src/Compilers/Core/Portable/ (compilation & red/green trees). Lesson: immutable green nodes + red facade with absolute positions. Pitfall: .NET GC hides tree memory cost — we account it explicitly (§14, M12). Applied in §14, §15.
  • Adapton — adapton.org reference (Rust adapton crate). Lesson: names/articulation points make memo reuse predictable. Pitfall: fully general nominal memoization has high constant overhead — we specialize to compiler queries. Applied in §13, §31.
  • rust-analyzer/rust-analyzer — crates/hir/, crates/base-db/ (salsa-based). Lesson: interned SyntaxNode/SymbolId keep spans stable across edits. Pitfall: cancellation-by-panic (Canceled) needs careful unwind safety. Applied in §16, §21.
  • facebook/buck2 & Bazel Skyframe (bazelbuild/bazel .../skyframe/). Lesson: demand-driven graph at build-action granularity scales to millions of nodes. Pitfall: coarse (file-level) nodes over-invalidate — we go query-granular. Applied in §29, §31.

Glossary (§36) · 60 terms · site-wide glossary

Adapton
nominal demand-driven incremental-computation framework (Hammer 2015); the validation model behind §13.
Artifact
a persisted derived-query value in the cache-store.
BLAKE3
Merkle-tree cryptographic hash; source of fingerprints (128-bit) and CAS keys (256-bit) (ADR-12).
CAS (Content-Addressed Store)
value store keyed by the hash of the value's bytes; makes corruption self-detecting (I7, MM8).
changed_at
the revision at which a memo entry's value last actually changed (drives dependents' re-execution).
Cold build
a build with an empty cache; O(program) (§29).
Compaction
reclaiming dead CAS segments to bound storage amplification (§20).
Cutoff (early cutoff)
stopping propagation when a re-executed query's fingerprint is unchanged (I3, P3).
DerivedQuery
a pure function of other queries; the memoized unit (§11).
Dependency edge
a recorded "query A read query B" relationship (P12, I5).
Durability
a tier (LOW/MED/HIGH) predicting an input's change frequency, letting validation skip stable subgraphs (P4).
ecl
the example compiler language, a test vehicle for the incremental substrate (§1).
ecld / eclc / ecl-lsp
the daemon, batch CLI, and language-server front doors (§1).
Fingerprint
128-bit BLAKE3 of a query's serialized value; the early-cutoff comparison key.
Firewall
a durability boundary that halts invalidation propagation (P4).
Green tree
immutable, structurally-shared, offset-free syntax tree (§14, P5).
HIR
high-level intermediate representation, the semantic lowering target (§17).
Hygiene
the property that spans/identities stay stable across unrelated edits (I9, I14).
Input query
a query whose value is set by the driver, not computed (P2).
Interner
deduplicating string/symbol store producing Interned ids (§16, P5).
Invalidation storm
a pathological cascade where early cutoff fails and O(program) work results (FM-6).
Memo entry
a cached (value, fingerprint, revisions, deps) record for one query (§8.2, §11).
MVCC
multi-version concurrency control; revision-versioned reads under parallelism (§19, paper 9).
Poison (Ty::Error)
an error value that propagates without cascading duplicate diagnostics (P15, §17).
Query key
(QueryId, key_hash) uniquely identifying a query invocation (§11).
Red tree
a lightweight cursor overlay adding absolute offsets/parents over a green tree (§15).
Red-green marking
per-revision coloring (Green=validated-clean, Red=must recompute) (§8.3, §13).
Replay
recording inputs+revisions to re-execute a session bit-identically (I11, §21).
Revision
the global monotone logical clock; every input change bumps it (I2, ADR-21).
Single-flight
guarantee a query executes at most once per revision (I8).
Span
a (file, lo, hi) byte range anchoring diagnostics; hygiene-stable (I9).
Storage amplification
bytes on disk ÷ live value bytes; held ≤ 2.5× (M10).
Subtree reuse
reusing an unedited green subtree across a reparse (§15, P3).
SymbolId
content+scope-derived stable identity for a resolved name (P6, I9).
verified_at
the revision at which a memo entry was last proven clean (§8.2).
WAL (write-ahead log)
durable log fsynced before index mutation, enabling bounded recovery (P7, I6).
Work-stealing
the scheduler model where idle workers steal tasks from busy workers' deques (§19).
Workspace
the full set of source files/modules under one session (§4).
Arena
a bump-allocated region for short-lived scratch (e.g. parser events), freed as a unit (§12, ADR-14).
Backpressure
rejecting or queuing work when a bounded resource is full, rather than growing unbounded (P10, ADR-22).
Checkpoint
a WAL record snapshotting the index root, bounding replay length on recovery (§18, M9).
Debounce
coalescing rapid edits into one revision batch to bound validation churn (§21, §4 row 27).
Demand-driven (pull)
computing a value only when it is asked for, versus eager push (§13, §34-B).
Differential testing
comparing incremental output to a from-scratch recompute to catch reuse bugs (I1, §26).
EdgeKind
whether a dependency edge reads a value or only an input's existence (§11, §13).
Existence edge
a dependency on "is this input present?" rather than its value (§13).
Group-commit
batching many WAL appends into one fsync to amortize latency (§18, M8).
Injector queue
the global task queue a work-stealing pool pulls from when a worker's deque is empty (§19).
NUMA pinning
binding worker threads and their allocations to one memory node to avoid remote-access penalty (§19, §4 row 17).
Pratt parsing
precedence-climbing expression parsing used for ecl binops (§8 grammar, §15).
Quarantine
dropping a suspect cache entry and recomputing rather than serving it (P15, FM-4).
Trivia
whitespace and comments attached to tokens but excluded from the significant-token fingerprint (§14, I14).
Single-flight
see also I8; deduplicating concurrent demands of one query into a single execution (§19).
Compaction I/O ceiling
the cap (50 MB/s, §4 row 29) on background compaction throughput protecting foreground latency (FM-8).
Poison suppression
not emitting duplicate diagnostics for items whose inputs are already Ty::Error (§17, P15).
Work-stealing deque
a per-worker double-ended queue; the owner pushes/pops one end, thieves steal the other (§19).
Firewall query
the stable caller-visible query (signature, module symbol set) hiding a volatile implementation query (P17, MM9).
Read barrier
the instrumentation that routes every query read through the dependency recorder (I5, §13).
Verifying-trace rebuilder
the Build-Systems-à-la-Carte category this engine occupies: recompute a query iff a recorded dependency changed (Mokhov 2018, paper 5; §31).
Suspending scheduler
the scheduler category (pull, on-demand) paired with the verifying-trace rebuilder in the §31 taxonomy (Mokhov 2018).
