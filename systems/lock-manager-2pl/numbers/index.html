The one defining property: the lock manager trades a bounded, quantified amount of acquire-path latency (≤100 µs p99) for correctness guarantees (conflict-serializability, no cascading aborts, no phantoms) that no faster mechanism in this design space provides without giving up one of those guarantees (see §32 Comparative Architecture Table and §35 Alternative Architectures for the tradeoff space).

33. Back-of-Envelope Capacity Model

  1. Lock-table memory at 10M concurrent row locks. LockEntry ≈ SmallVec<Holder,4> (4 × 24 bytes ≈ 96 B) + VecDeque header (≈24 B) + resource bytes (≈24 B) + struct overhead (≈40 B) ≈ 200 B/entry (§4 row 1). 10,000,000 × 200 B = 2,000,000,000 B ≈ 2 GB (§4 row 2).
  2. Bucket concurrency. shard_count = 1,024 (ADR-03) → up to 1,024 concurrent non-conflicting bucket writers before intra-bucket contention dominates.
  3. Detector snapshot duration. 1,024 buckets × ~10 µs/bucket (read-lock + iterate ~100 entries/bucket at 100K total entries) ≈ 1,024 × 10 µs ≈ 10 ms, consistent with the §4/M4 ≤100 ms target with 10× margin.
  4. Escalation memory reduction. 1,000,000 rows × 200 B = 200,000,000 B (200 MB) of row locks collapses to 1 × 200 B table lock ⇒ a 200,000,000 / 200 = 1,000,000× reduction, bounded by the 5,000-row escalation threshold (ADR-11) triggering well before 1M rows are ever held.
  5. Cross-shard probe volume, CMH worst case. N = 1,000 concurrent cross-shard waiters × E_remote = 5 average remote edges/waiter ⇒ 1,000 × 5 = 5,000 probe messages per detection cycle, versus Obermarck's N = 1,000 summaries — the ADR-19 crossover derives from N × E_remote > N whenever E_remote > 1, i.e. almost always past a handful of shards; the ~50-shard practical threshold in ADR-19 reflects the point where per-message transport overhead (not raw count) dominates.
  6. FD budget for distributed transport. 1 persistent connection/peer shard (§4 row
    1. ⇒ at a 64-shard cluster, 64 − 1 = 63 connections/node.
  7. Fast-path throughput ceiling. 5,000,000 ops/sec/core (M1) × 8 cores ≈ 40,000,000 ops/sec aggregate ceiling before cross-core cache-line contention on shared buckets reduces this below linear scaling (Amdahl-style derating, not measured as exactly linear).
  8. Contended throughput per-transaction share. 500,000 ops/sec (M2) ÷ 10 txns = 50,000 ops/sec/txn average serialized throughput through hot buckets under Zipfian s=1.0.
  9. Timeout-to-tail-latency ratio. 30,000,000 µs (30 s default timeout, ADR-14) ÷ 100 µs (p99 wait, M8) = 300,000× — the timeout is 300,000 times the nominal p99 wait, i.e. it fires only under genuine contention pathology, never steady-state tail latency.
  10. Wait-queue memory spike. WaitEntry ≈ 64 B (txn+mode+timestamps+deadline+mutex+ condvar) × 10,000 worst-case queued waiters on one hot bucket = 640,000 B (640 KB) — a bounded transient spike, not a steady-state cost.
