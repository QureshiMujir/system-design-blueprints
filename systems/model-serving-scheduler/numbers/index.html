Deployment assumptions. Linux kernel 6.x · cgroup v2 · Kubernetes optional but supported · NVMe-backed metadata nodes · RDMA optional · IPv6-compatible networking.

Horizontal scaling assumptions. Gateway tier horizontally scalable · scheduler partitions sharded by tenant/model (ADR-20) · metadata replicated via Raft (ADR-04) · telemetry aggregation decoupled (P5).

Vertical scaling assumptions. Scheduler instances scale to 64 vCPUs · high memory pressure expected from queue metadata · cache residency optimized for NUMA locality (§15.2 NUMA hints).

32. Back-of-Envelope Capacity Model

  • C1 — Placement p50 budget. 0.3ms queue-manager dequeue + 1.5ms placement-engine scoring over ≤200 sampled candidates (Sparrow-style, §15.2 step 11) + 1ms amortized WAL-append fsync = 2.8ms, inside the §4 3ms p50 ceiling.
  • C2 — Queue enqueue throughput. 50M tok/min regional target ÷ ~200 avg tokens/req = 250,000 req/min ÷ 60 = 4,167 req/s sustained average; provisioned to the 250k req/s §4 burst ceiling for a ~60x burst headroom over sustained average.
  • C3 — GPU utilization target derivation. 100% theoretical − 18% fragmentation loss (Robin-Hood-style multi-GPU split overhead, §15.6 Pitfall 1's mitigation) − 10% preemption/drain overhead (§20) = 72% sustained target, matching §4.
  • C4 — Max cluster nodes. 15ms Raft quorum write-latency budget (§4) ÷ 0.003ms marginal fan-out cost per follower at intra-region RTT (0.2–2ms, §4) = 5,000 nodes before replication lag exceeds the budget, matching §4's ceiling.
  • C5 — Max active models / lease-table budget. 25,000 models × 1.2KB average PlacementDecision + lease-table row footprint = 30MB, well inside the 32GB scheduler memory ceiling (§4), leaving headroom for queue-shard state (C8 below).
  • C6 — Startup recovery window. 25,000-model snapshot load at ~250 models/s deserialization rate (RocksDB-backed, ADR-09) ≈ 100s + WAL-tail replay ≈ 15s = 115s, inside the §4 120s ceiling.
  • C7 — Error budget. 0.05% of a 30.44-day month = 0.05% × 30.44 × 24 × 60 = 21.6 minutes/month, matching §4 exactly.
  • C8 — Concurrent-stream memory footprint. 2,000,000 max streams (§4) × ~4KB per-stream buffer (§17.2 step 5) = 8GB, within the 32GB scheduler memory ceiling (§4) alongside C5's 30MB lease-table footprint.
  • C9 — Runtime-agent memory ceiling check. 512MB budget (§4) ÷ 8 GPUs/node average (§4) = 64MB per GPU inventory record's amortized share, comfortably inside NVML-class probe overhead.
  • C10 — Max FDs vs. concurrent streams. 2,000,000 FD budget (§4) ÷ 2,000,000 max concurrent streams (§4) = 1.0 FD per stream, exactly matching the 1-FD-per-stream design assumption with zero multiplexing slack — gRPC connection multiplexing (ADR-19) is required, not optional, to avoid exhausting the FD ceiling under the max-stream scenario.
