32. Mental Models & First Principles

MM1 — An acceptor's disk state is the database; a proposer's ballot is a stateless client cache. Predicts: any code that persists proposer state or fails to persist acceptor state is wrong by construction. Bug class without it: promised-ballot violations after a restart that re-issues a ballot already promised away. Applied in §11.4/§11.5, §13.6.

MM2 — A ballot is a fencing token with a total order, not a timestamp. Predicts: two ballots from different proposers must never compare equal, and the ordering must be total, not partial. Bug class without it: duelling proposers deadlock, or a comparison tie silently lets a lower-priority proposal win. Applied in §11.1, P3.

MM3 — Quorums are set intersections, not head-counts. Predicts: any two quorums under one membership must share a member; a membership change must preserve this pairwise property, not merely the numeric majority size. Bug class without it: a reconfiguration producing two non-intersecting quorums (T7, FM8). Applied in §11.2, I6, §18.

MM4 — The leader is a cache for liveness, never an oracle for safety. Predicts: the safety proof must hold with zero leaders, one leader, or transiently many. Bug class without it: accidentally re-deriving Raft's safety-via-leader coupling without Raft's corresponding proofs. Applied in P5, §33.

MM5 — fsync-before-respond is the linearizability boundary, not a durability nicety. Predicts: any reordering of fsync versus reply reopens a crash-recover safety hole even though "everything eventually gets written to disk." Bug class without it: a crash between reply and fsync silently loses a promise the acceptor claimed to have made. Applied in I2, §14.2.

MM6 — A snapshot is a compaction of history, never a semantic change to what was agreed. Predicts: snapshot+compaction must be provably equivalent to replaying the full log; content-addressing (a hash) is how that equivalence is checked mechanically rather than trusted. Bug class without it: divergent replica state from a non-deterministic encode_state. Applied in P8, I8, §17.

MM7 — A failure detector is a probabilistic oracle whose only guarantee is eventual agreement, never point-in-time truth. Predicts: no code path may treat "not currently suspected" as proof of aliveness; the protocol must tolerate the detector being wrong at any single instant. Bug class without it: safety code (rather than only throughput code) gated on Φ. Applied in P5, §15.

MM8 — Reconfiguration is consensus on membership, not a side channel. Predicts: the same machinery (ballots, quorums) that protects data values must protect membership changes — a membership change is itself a chosen log value, never an out-of-band operation. Bug class without it: a reconfiguration protocol that bypasses quorum-intersection reasoning entirely (the precise mistake the α-parameter trick is designed to prevent). Applied in §11.11, §18.

Acceptor

ADR
Architecture Decision Record; a locked choice with rejected alternatives (§9).
Agreement
the safety property that only one value is ever chosen per slot (I1).
Α-parameter (alpha)
the reconfiguration offset controlling how many slots overlap the old and new membership (§18.1, ADR-16).
Ballot
(round, proposer_id), the totally-ordered proposal number (§11.1, P3).
Basic Paxos
the single-decree ("synod") protocol choosing one value (§13).
Batching
grouping multiple proposals into one fsync/network write (ADR-12).
BLAKE3
the hash function used for content-addressable snapshots (ADR-05, I8).
Bisection
finding the minimal seed prefix that reproduces a simulator-detected violation (§21.4).
Byzantine fault
a node that violates the protocol rather than merely crashing; out of scope here (P14).
Catch-up
a lagging learner's process for reaching current state via snapshot + log tail (§16.3).
CAP theorem
the impossibility of simultaneous Consistency, Availability, and Partition tolerance; this system is CP (§4, §31).
Chain Replication
a primary-order, quorum-free replication architecture (§36.4).
Chosen
a value with a quorum of Accepted acknowledgements, distinct from applied (§8.6, §20.9).
Chubby
Google's production Paxos-based lock service (§5, §33).
Content-addressable storage
data identified by the hash of its contents, used for snapshots (P8, I8).
Copy-on-write snapshot
a snapshot mechanism that avoids blocking the apply path (§22.2).
CRC32C
the checksum protecting each WAL record against torn writes (§8.5, I7).
Crash-recover failure
a node halts and later restarts with disk intact (FM2).
Crash-stop failure
a node halts and never returns (FM1).
Determinism canary
a test asserting the application state machine's apply is order-independent (I11, P11).
EPaxos
the leaderless, dependency-graph-ordered Paxos variant (§5, §33, §36.2).
Fencing token
a monotonically increasing value that invalidates stale holders; the mental model for a ballot (MM2).
Flexible Paxos
the observation that Phase-1 and Phase-2 quorums need only intersect pairwise, not both be majorities (§5, §31).
FLP impossibility
the proof that asynchronous consensus cannot guarantee both safety and termination (§5, §7).
fsync-before-respond
the rule that a reply must follow its WAL fsync (I2, P4).
Gap-fill
a new leader's process for completing slots a deposed leader left incomplete (§16.2).
Group commit
batching multiple WAL appends behind one fsync call (ADR-07).
Invariant (I1–I14)
a property enforced structurally or by assertion throughout the system (§7).
Jepsen
the chaos/linearizability-testing framework (§5, §28).
Joint consensus
Raft-style two-phase reconfiguration; this project's rejected default (ADR-16, §36.1).
Leader stickiness
retaining the current leader until Φ crosses the step-down threshold or a higher ballot is observed (§15.3).
Learner
the role that observes Accepted messages and determines chosen values (§11.6).
Lease read
an opt-in read path serving from local state under a bounded-clock-skew assumption (ADR-18).
Linearizability
the strongest single-object consistency model; the default read/write guarantee here (§5, §20).
Log compaction
truncating the WAL after a snapshot, retaining a small tail (§17.4, I12).
Maelstrom
the lightweight protocol-conformance workload runner (§5, §23.5).
Membership
