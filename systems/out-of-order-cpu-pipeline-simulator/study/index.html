30. Mental Models & First Principles

  • MM1 — Retirement Is Truth. Architectural state exists only at ROB commit; predicts that any "debug read" of speculative registers is fiction; the bug class avoided is trusting speculative state as ground truth; applies in §16.
  • MM2 — Determinism Is A Scheduling Discipline, Not A Language Property. Determinism comes from fixed subsystem ordering plus a monotonic clock, not from choosing Rust; predicts that a HashMap-iteration-order bug breaks determinism even in memory-safe code; bug class: replay divergence from unstated iteration-order assumptions; applies in §12.
  • MM3 — Backpressure Beats Buffering. An unbounded queue just moves a failure later and makes it bigger; predicts that "just increase the buffer" is a deferred OOM, not a fix; bug class: unbounded memory growth under burst load; applies in §12.
  • MM4 — A Wakeup Is A Broadcast, Not A Message. Reservation-station wakeup clears bits across every matching entry in one cycle, not a queued one-to-one delivery; predicts wakeup-fanout cost scales with dependent count, not issue width; bug class: assuming O(1) wakeup cost; applies in §17.
  • MM5 — Speculative State Needs Its Own Undo Log. A checkpoint is a targeted overlay, not a full-state copy; predicts checkpoint cost should scale with speculation depth, not architectural register count; bug class: full-table-copy checkpointing that stops scaling under deep speculation; applies in §15.
  • MM6 — Plausible-But-Wrong Is The Dangerous Failure Class. Renaming, ordering, and latency bugs rarely crash — they produce numbers that look fine; predicts you need differential verification (§26), not just invariant assertions, to catch this class; bug class: shipping wrong IPC numbers with a fully green test suite; applies in §26.
  • MM7 — Non-Blocking Misses Need Coalescing, Not Just Queuing. An MSHR without address-collision coalescing double-tracks the same line; predicts refill duplication under bursty access patterns; bug class: MSHR exhaustion that a bigger MSHR table would not actually fix; applies in §20.
  • MM8 — A Metric Name Is A Promise, Not A Label. Renaming a metric is a breaking API change under P12; predicts dashboards silently going dark after a "harmless" rename; bug class: an undetected regression because the dashboard stopped showing data rather than showing bad data; applies in §24.

5. Required Reading

Books

  • Computer Architecture: A Quantitative Approach — Hennessy & Patterson (2017), ch. 3 (ILP), ch. 3.9 (memory hierarchy): Tomasulo scheduling, ROB semantics, speculative execution baseline; applied in §14, §16, and §17.
  • Modern Processor Design: Fundamentals of Superscalar Processors — Shen & Lipasti (2005), ch. 5–6: dynamic scheduling, register renaming, commit semantics; applied in §15 and §16.
  • Structured Computer Organization — Tanenbaum (2013), ch. 4 (microarchitecture): pipeline design, control flow, memory systems basics; applied in §13 and §14.
  • Engineering a Compiler — Cooper & Torczon (2011), ch. 8, 12–13: SSA, dependency graphs, instruction scheduling; applied in §14 and §15.
  • Operating Systems: Three Easy Pieces — Arpaci-Dusseau & Arpaci-Dusseau (2018), ch. on concurrency/scheduling: synchronization primitives and scheduling semantics reused for sim-core's tick discipline; applied in §12.
  • Designing Data-Intensive Applications — Kleppmann (2017), ch. 11 (streams and logs): ordering guarantees, replayability, WAL-style log semantics; applied in §21 and §25.
  • Systems Performance: Enterprise and the Cloud — Gregg (2020), ch. 6 (CPUs), ch. 13 (methodology): flamegraph methodology, latency analysis, observability discipline; applied in §24 and §28.

Papers

  • "An Efficient Algorithm for Exploiting Multiple Arithmetic Units" — R. M. Tomasulo, 1967, IBM Journal of R&D: dynamic scheduling via reservation stations and register tagging → basis for sim-rs wakeup/select; applied in §17.
  • "Implementation of Precise Interrupts in Pipelined Processors" — J. E. Smith & A. R. Pleszkun, 1985, ISCA/IEEE Trans. Computers: reorder-buffer-based precise exception model → basis for sim-rob retirement authority; applied in §16.
  • "Two-Level Adaptive Training Branch Prediction" — T.-Y. Yeh & Y. N. Patt, 1991, MICRO: two-level branch history predictors → basis for the gshare/tournament predictor family; applied in §19.
  • "Combining Branch Predictors" — S. McFarling, 1993, DEC WRL Technical Report: hybrid/tournament predictor combination → basis for sim-branch's tournament mode; applied in §19.
  • "Evaluating Future Microprocessors: The SimpleScalar Tool Set" — D. Burger & T. Austin, 1997, UW-Madison TR: academic execution-driven simulator architecture, deterministic event scheduling discipline → applied in §12 and §13.
  • "Memory Ordering: A Value-Based Approach" — H. W. Cain & M. H. Lipasti, 2004, ISCA: speculative memory disambiguation and value-based ordering checks → basis for sim-lsq alias detection; applied in §20.
  • "Complexity/Performance Tradeoffs with Non-Blocking Loads" — K. I. Farkas & N. P. Jouppi, 1994, ISCA: non-blocking cache / MSHR design tradeoffs → basis for sim-cache MSHR modeling; applied in §20.
  • "Spectre Attacks: Exploiting Speculative Execution" — Kocher et al., 2019, IEEE S&P: speculative-execution side effects surviving mispredict squash → basis for the speculation-epoch threat surface; applied in §22.

Reference Implementations

  • gem5 / gem5 — study src/cpu/o3/: out-of-order CPU model decomposition (IEW stage split, extensible instruction-set backends); pitfall: excessive abstraction depth slows onboarding and profiling — do not copy the generic-ISA template layer wholesale; applied in §13 and §31.
  • MARSSx86 (marss) — study its pipeline timing model integration with a full-system functional simulator; pitfall: tight coupling between timing and functional model makes isolated timing-only testing hard — keep sim-core timing decoupled from sim-isa functional semantics; applied in §17 and §34.
  • SimpleScalar (SimpleScalar LLC / UW-Madison) — study its deterministic event-scheduling loop and sim-outorder structure; pitfall: monolithic single-file scheduler resists later multi-core extension — keep sim-core scheduling logic in its own crate boundary; applied in §12.
  • Sniper Simulator (snipersim) — study its interval-simulation approach to fast multicore design-space exploration; pitfall: interval models trade cycle accuracy for speed and cannot replace this blueprint's cycle-accurate mode for pipeline-bug hunting; applied in §29 and §34.
  • BOOM — Berkeley Out-of-Order Machine (riscv-boom) — study its ROB and issue-queue RTL structure; pitfall: RTL ROB sizing assumptions do not transfer directly to a software timing model's memory-footprint arithmetic — re-derive from §4, not from BOOM's silicon parameters; applied in §16 and §32.

RFCs / Specifications

  • ELF specification (Tool Interface Standard, ELF v1.2): object-file layout referenced by sim-trace when ingesting compiled binaries for trace extraction; applied in §13.
  • DWARF Debugging Information Format (DWARF v5): symbol/line correlation used by sim-traceviz for source-attributed pipeline visualization; applied in §21.
  • OpenTelemetry Tracing Specification (v1.x): span/trace-context model adopted verbatim by sim-stats telemetry export; applied in §21 and §24 (ADR-05).
  • Prometheus Exposition Format (text-based, v0.0.4): metrics-scrape wire format for sim-stats; applied in §24 (ADR-04).
  • TOML v1.0: configuration file format for sim-config; applied in §12 (ADR-03).
  • SemVer 2.0.0: public-trait and metric-name versioning discipline; applied in §25 (P12).

Glossary (§36) · 43 terms · site-wide glossary

ROB
Reorder buffer; enforces precise, program-order commit (I1).
RS
Reservation station; holds a dispatched uop until its dependencies clear for issue.
LSQ
Load/store queue; enforces memory ordering and store-to-load forwarding.
MSHR
Miss Status Handling Register; tracks one outstanding, non-blocking cache miss.
IPC
Instructions per cycle; the primary throughput metric reported by sim-stats.
Uop
Micro-operation; the internal execution unit below instruction granularity.
Rename Map
Architectural-to-physical register mapping table (RenameMap).
Checkpoint
A speculative-recovery snapshot (BranchCheckpoint) enabling exact rollback.
Replay Divergence
A determinism mismatch between two runs of the same input (I4).
Structural Hazard
A resource conflict, e.g. a non-pipelined divider already busy (§18).
Branch Epoch
A monotonically increasing speculation-generation identifier (EpochId).
Wakeup
Dependency-satisfaction propagation from a completing result to waiting RS entries.
Writeback
Publication of an execution result onto the bypass network / ROB entry.
Retirement
The architectural commit phase; the sole source of architectural truth (P9).
Frontend Bubble
An idle fetch/decode cycle with no forward progress.
Tail Latency
Worst-case operation latency (p99-class), tracked explicitly in §4/§28.
Backpressure
Upstream throttling triggered by downstream queue saturation (P3).
Precise Exception
An exception delivered as if instructions executed strictly in order.
Dispatch Width
Maximum uops entering the backend (ROB/RS) per cycle.
Fetch Width
Maximum instructions fetched per cycle from the instruction stream.
Tomasulo Algorithm
Dynamic scheduling via tagged reservation stations (Tomasulo, 1967).
Instruction-Level Parallelism (ILP)
Independent instructions executable concurrently.
Speculative Execution
Executing instructions before their control dependency resolves.
Register Renaming
Mapping architectural registers to physical registers to remove false dependencies (WAW/WAR).
WAW Hazard
Write-after-write false dependency, eliminated by renaming.
WAR Hazard
Write-after-read false dependency, eliminated by renaming.
RAW Hazard
Read-after-write true dependency; the only hazard renaming cannot remove.
Physical Register File
The renamed backing store of physical registers (§11).
Free List
The pool of unallocated physical registers (§11, I2).
Bypass Network
Same-cycle result forwarding path from a functional unit to a waiting RS entry.
BTB
Branch Target Buffer; caches predicted branch targets at fetch time.
RAS
Return Address Stack; predicts call/return targets.
Gshare
A global-history-indexed branch predictor (McFarling, 1993).
Tournament Predictor
A meta-predictor selecting between two component predictors per branch.
Store-to-Load Forwarding
Supplying a load's value directly from an in-flight store buffer.
Memory Disambiguation
Determining whether a load and an earlier store's addresses overlap.
Non-Blocking Cache
A cache that services further accesses while a miss is outstanding (via MSHR).
Cache Coherence
Protocol ensuring consistent views of shared memory across cores (deferred, §35).
Differential Verification
Comparing this simulator's output against a reference trace (§26).
Crash-Only Recovery
A recovery design assuming abrupt termination as the only failure mode (P6).
Snapshot Amplification
The ratio of on-disk replay-log size to raw executed-instruction count.
Age-Priority Arbitration
Resolving resource contention in favor of the oldest ROB-slot entry.
Speculation Epoch
See Branch Epoch; used interchangeably in sim-branch/sim-rob code.
