Decisions (§9) · 22 ADRs

ADR-01

Language

Chosen

Rust

Rejected

C++, Go, Java

When the rejected choice is right

Go wins when GC jitter is irrelevant and team velocity on a GC'd language dominates — not this project

Why: Ownership model eliminates the dominant replay-divergence bug class (P2); no GC pause (I3)

Roads not taken (§34)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt A — Trace-Driven Functional-Only Simulation

+-----------+     +------------------+     +--------------+
| trace in  | --> | functional-only  | --> | final arch   |
|           |     | execute (no timing)|    | state dump   |
+-----------+     +------------------+     +--------------+

Regime where it wins: pure correctness validation of a new ISA extension where cycle timing is irrelevant. Real system: SimpleScalar's sim-fast/sim-safe modes. Rejected here because §1's entire purpose is cycle-level microarchitectural research — a functional-only mode would satisfy none of the §4 timing constraints or §28 performance-engineering goals; it remains available as a debug subset of sim-isa, not as the blueprint's primary mode.

Alt B — Interval / Statistical Simulation

+-----------+     +-------------------+     +----------------+
| trace in  | --> | interval sampler   | --> | statistical IPC |
|           |     | (miss-event driven)|     | estimate        |
+-----------+     +-------------------+     +----------------+

Regime where it wins: fast multicore design-space exploration across hundreds of configurations where approximate IPC is acceptable. Real system: Sniper Simulator (§5, §31). Rejected here because §26's differential-verification strategy and §7's cycle-level invariants (I1, I5, I6) require exact per-cycle state, which interval simulation deliberately discards for speed — the two goals are mutually exclusive at the architecture level, not just a tuning knob.

Alt C — Full RTL Cycle-Level Co-Simulation

+-----------+     +-------------------+     +----------------+
| trace in  | --> | Verilator/FireSim  | --> | RTL waveform / |
|           |     | RTL simulation     |     | signoff timing  |
+-----------+     +-------------------+     +----------------+

Regime where it wins: pre-tape-out timing signoff where the model must be bit-identical to the fabricated silicon's actual logic. Real system: BOOM via the Chipyard/FireSim RTL simulation flow (§5, §31). Rejected here because RTL co-simulation runs orders of magnitude slower than a software timing model and requires a synthesizable hardware description — incompatible with §1's rapid microarchitecture-experimentation goal and the 50M instr/sec §4 throughput target.

Alt D — Full-System Execution-Driven Simulation with OS Boot

+-----------+     +-------------------+     +----------------+
| disk image| --> | full-system model  | --> | OS-interaction  |
| + trace   |     | (boots real kernel)|     | timing effects   |
+-----------+     +-------------------+     +----------------+

Regime where it wins: research questions where syscalls, page faults, and interrupt handling materially affect the timing result under study. Real systems: gem5's full-system mode and MARSSx86 (§5, §31). Rejected here because §1 explicitly excludes real kernel boot from Phase 0–9 scope — trace ingestion (§13) is deliberately decoupled from any OS-interaction model, keeping the timing core testable in isolation per the MARSSx86 pitfall noted in §5.
