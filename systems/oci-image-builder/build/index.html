⬜ Phase 0 — Skeleton §12

Objectives
  • Cargo workspace with all 12 crate stubs compiling; CI green; forge build FROM scratch + COPY hello / produces a valid OCI layout accepted by forge inspect and skopeo inspect.
  • Establish foundational types: Digest, Descriptor, MediaType in forge-digest; stub ContentStore in forge-cas; stub ImageManifest in forge-oci; stub Definition in forge-llb.
Deliverable

Workspace compiles; forge build --platform linux/amd64 -f examples/hello-world/Dockerfile . → output/ OCI layout; skopeo inspect oci:output:latest succeeds without error.

Acceptance
  • cargo build --workspace exits 0; zero clippy warnings.
  • cargo test --workspace exits 0 (unit tests: Digest::parse, validate_manifest, write/read OCI layout round-trip).
  • forge build examples/hello-world → OCI layout; skopeo inspect validates schemaVersion, config.rootfs.diff_ids non-empty.
  • forge inspect output/ prints valid JSON with schemaVersion: 2.
  • CI passes on push in < 5 min.

Fixture Purpose Expected outcome

conformance/image-spec/invalid-manifests/bad-schema-version.json schemaVersion=1 ForgeError::Validation
examples/hello-world/Dockerfile Smoke-test build OCI layout with 1 layer, diff_id non-empty
Pitfalls
  • Atomic rename across filesystems: temp/ and blobs/ must be on same filesystem for rename() to be atomic; detect and error early.
  • Missing oci-layout marker file: skopeo and other consumers require the marker; easy to omit.
  • Descriptor size field: must match exact byte count of stored blob; off-by-one from buffered writers is common.
  • Clippy on trait objects: Arc<dyn Snapshotter> requires Send + Sync; missing bounds break compilation silently in stubs.
  • JSON key ordering: serde_json default HashMap has random key order; use BTreeMap for annotations from the start.

⬜ Phase 1 — forge-digest + forge-cas §13

Objectives
  • Production-quality forge-digest: canonical JSON hashing, DigestVerifyingReader/Writer, all MediaType variants, full Descriptor fields.
  • Production-quality forge-cas: streaming ingest, atomic commit, refcount, mark-sweep GC, lease objects, integrity check.
Deliverable

forge-digest and forge-cas pass all unit tests; GC correctly removes unreferenced blobs; DigestVerifyingReader rejects tampered bytes.

Acceptance
  • cargo test -p forge-digest -p forge-cas → all pass.
  • test_verifying_reader_mismatch: flip one byte → ForgeError::DigestMismatch.
  • test_gc_removes_unreferenced: ingest 100 blobs; lease on 50; gc → 50 deleted, 50 remain.
  • test_cas_concurrent_ingest: 8 threads ingest same blob → exactly one file on disk; no races.
  • Blob path = blobs/sha256/<hex> verified by path assertion.
Fixtures
Fixture Purpose Expected
conformance/image-spec/valid-manifests/digest-test.json Known manifest + expected sha256 canonical_json_digest matches expected
fuzz/fuzz_targets/fuzz_digest.rs Arbitrary strings → Digest::parse No panic; returns Ok or Err
Pitfalls
  • Partial read buffering: DigestVerifyingReader must not assume read() returns all bytes; accumulate across multiple calls.
  • Rename atomicity on macOS APFS inside Docker bind mounts: tmp/ and blobs/ may be on different overlay layers; always use same parent dir.
  • GC root set race: concurrent ingest not yet in Lease during GC window → blob deleted mid-ingest; always create Lease before beginning ingest.
  • Refcount persistence crash safety: JSON flush not crash-safe; document WAL upgrade in Phase 9.
  • sha256 tee pattern: sha2::Sha256 context must be cloned to hash same stream for both diff_id and layer digest; use TeeReader (uncompressed) + separate hasher (compressed).

⬜ Phase 3 — forge-tar §15

Objectives
  • Deterministic layer tar: path-sorted entries, SOURCE_DATE_EPOCH normalization, gzip/zstd at fixed levels, dual-stream hashing (diff_id = uncompressed sha256, layer digest = compressed sha256), whiteout generation/detection.
Deliverable

Bit-identical tarballs for identical ChangeSets across two independent runs. LayerResult.diff_id matches independent sha256 of the uncompressed stream.

Acceptance
  • test_deterministic_layer: build same 5-entry ChangeSet twice → diff_id and descriptor.digest byte-identical.
  • test_diff_id_is_uncompressed_sha256: Compression::None parallel build → sha256 == diff_id from gzip build.
  • test_whiteout_entries_sorted_correctly: whiteout entries in lexicographic order among regular entries.
  • test_absolute_path_rejected: path /etc/passwd → ForgeError::Validation.
  • benchmarks/layer_hash.rs baseline establishes ≥ 200 MB/s for sha256+gzip.
Fixtures
Fixture Purpose Expected
conformance/image-spec/layers/alpine-layer.tar.gz Real-world OCI layer LayerReader iterates without error; no absolute paths
conformance/image-spec/layers/whiteout-layer.tar.gz Layer with .wh. entries is_whiteout detects all; opaque dir detected

Pitfalls
  • Gzip level reproducibility: pin flate2 version in Cargo.lock; same level + same input → same bytes only within a fixed flate2 version.
  • PAX extended headers for long paths: tar ustar limit is 100 bytes; use PAX for paths > 100 chars; test explicitly.
  • Mtime sub-second precision: normalize to integer seconds; strip PAX sub-second fields.
  • Sorting locale sensitivity: use byte-order sort (raw byte lexicographic), not locale-aware.
  • Two 512-byte zero block end-of-archive: always emit; missing causes reader warnings.

Definition with 10-vertex diamond DAG serializes; topo_sort returns valid linearization; cycle in 3-vertex DAG detected as ForgeError::Parse.

Acceptance
  • test_topo_sort_diamond: 4-vertex diamond → topo order respects all input edges.
  • test_cycle_detection: A→B→A → ForgeError::Parse{msg:"cycle"}.
  • test_vertex_digest_stable: compute digest; serialize Definition; deserialize; recompute → same digest.
  • test_validate_missing_input_ref: InputRef to non-existent digest → ForgeError::Validation.

Fixtures
Fixture Purpose Expected
conformance/llb/linear-chain.json 5-vertex linear Definition topo_sort returns vertices in order
conformance/llb/cycle.json Deliberate cycle ForgeError::Parse on validate
conformance/llb/diamond.json Diamond DAG Valid topo sort; all 4 vertices present
Pitfalls
  • Non-stable JSON key order breaks vertex digest: BTreeMap ordering mandatory in vertex_bytes; HashMap is non-deterministic.
  • InputRef output_index range: verify output_index < declared output count of input vertex; ExecOp has 1 output; FileOp may have multiple.

  • Vertex dedup: identical digest = same vertex; solver must dedup before scheduling.

Pitfalls

Deliverable

LinuxExecutor::exec runs RUN apt-get update inside a rootfs assembled from pulled Alpine layers and captures the resulting upper dir.

Acceptance
  • test_exec_echo (Linux only, integration): exec /bin/echo hello inside scratch rootfs → exit 0.
  • test_exec_writes_file: exec touch /out/marker → ExecResult.upper_dir/out/marker exists.
  • test_exec_nonzero: exec sh -c "exit 42" → ForgeError::Sandbox{exit_code:42}.

Fixtures
Fixture Purpose Expected
conformance/exec/echo.sh Integration: exec echo + capture output exit 0; no upper dir files
conformance/exec/write-file.sh exec writes /marker upper_dir/marker present
conformance/exec/exit-nonzero.sh exec exits 42 ForgeError::Sandbox{exit_code:42}
Pitfalls
  • newuidmap/newgidmap not installed: fail at startup with clear message; check binary existence in LinuxExecutor::new().
  • pivot_root requires a different filesystem: rootfs must be a mount point itself; ensure overlayfs mount creates a new mount point.
  • /proc in new PID namespace: child must mount new procfs after pivot_root; otherwise tools like ps fail inside RUN.
  • Leaked mount points on exec failure: use scopeguard or explicit cleanup on all error paths to unmount overlay on error.
  • setgroups deny required before uid_map write: kernel enforces; write deny to setgroups before writing gid_map in newer kernels.
  • CLONE_NEWPID and fork vs thread: must fork() before exec, not just exec from a thread; nix::unistd::fork required.

  • test_cache_invalidation_on_env_change: change ENV value → solver executes all downstream ExecOps (no hit).
  • test_prune_removes_old_entries: store 1000 entries with old timestamps; prune(max_age=1s) → all removed.
  • cargo test -p forge-cache all pass.
Fixtures
Fixture Purpose Expected
conformance/cache/env-invalidation.dockerfile Change ENV value between builds Second build re-executes downstream RUN
conformance/cache/copy-invalidation.dockerfile Change copied file content Second build re-executes COPY + downstream
conformance/cache/from-digest-invalidation.sh Update base image tag resolution Build from new base; different cache key
Pitfalls
  • Tag-to-digest resolution: FROM ubuntu:22.04 must resolve to a manifest digest at solve start; re-resolve each build to detect upstream changes; incorporate digest into SourceOp CacheKey.
  • ARG before FROM: global ARG not in any stage env; must still invalidate if value changes.

  • Prune during active build: sled supports concurrent readers; prune must not delete entries with active lookups; use sled transactions.

Fixtures
Fixture Purpose Expected
conformance/distribution-spec/run.sh OCI distribution-spec conformance suite All required tests pass

Pitfalls
  • WWW-Authenticate header parsing: realm, service, scope may have quoted strings with commas; use a proper header parser not naive split.
  • Cross-repo mount 202 fallback: registry may return 202 (not mounted) even when cross-repo mount is supported; always fall back to upload on 202.
