⬜ Phase 2 — Assignment trail and two-watched-literal BCP §14

Objectives
  • Assignment state (Trail, assigns/level/reason: VarMap, qhead); enqueue (assign+push) and propagate() -> Option<ClauseRef> (two-watched BCP to fixpoint, conflict or None); watches: LitMap<Vec<Watcher>> with cached blocker, never touched on backtrack. Outcome: a correct, allocation-stable BCP core for DPLL/CDCL.
Deliverable
  • BCP engine: given assignments enqueued, propagate() reaches fixpoint, enqueues all forced units with correct reason/level, and returns the first conflicting ClauseRef or None. Watch invariants hold after arbitrary backjump.
Acceptance
  • Chains of N unit-forcing binary clauses propagate fully in one propagate() call; trail length = N.
  • Conflict on (a)∧(¬a) returns Some(cref); no conflict returns None with trail at fixpoint.
  • Property test: every clause has ≥2 distinct watched lits or is satisfied/unit at root; verified after each propagate.
  • ≥40 M propagations/sec on a satisfiable random 3-SAT instance (n=1e4) on reference hardware.
