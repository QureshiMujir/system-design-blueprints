4. System Constraints

4.1 Resource budgets (quantified targets)

Resource Target / cap Mechanism Rationale
Clause storage ClauseArena packed u32 words; header 2 words + 1 word/literal -> ~4 bytes/literal ClauseRef(u32) handle, not pointer; bump alloc + compaction cache density; 32-bit handles halve footprint vs ptrs
Lit/Var width u32 each; nvars <= 2^31-1 sign-bit encoding 2*var+sign one word indexes LitMap sized 2*nvars
Watch lists ~2 Watcher entries/clause (binary watched-lit invariant) watches: LitMap<Vec<Watcher>>; Watcher{cref,blocker} = 8 bytes minimize touched clauses on BCP
Assignment arrays assigns/level/reason/phase = VarMap dense, O(nvars) indexed by Var, no hashing L1/L2-resident per-var state
Learnt DB capped to multiple of original clauses (default ~2-4x, dynamic) reduceDB: keep LBD-2 glue + high-activity + reasons; drop ~half bound memory + GC pressure

4.2 Throughput / latency targets

Metric Target (single core, competition CNF) Notes
Propagations/sec > 1e7 BCP hot loop; L1/L2-bound; dominates runtime
Conflicts/sec ~1e4-1e6 (instance-dependent) each conflict = analyze() + backjump + DB bump
Decisions/sec tracks conflicts pick_branch() = heap pop + phase lookup
Restart cadence Luby unit ~50-100 conflicts base; Glucose-LBD dynamic; blocking on long trail EMA fast vs slow LBD
reduceDB cadence every reduce_limit conflicts (geometric/arith growth)
Parse throughput O(formula bytes); streaming, no full-buffer slurp large .cnf files (GB)
  • Worst-case solve time is UNBOUNDED — SAT is NP-hard. Every solve()/solve_under() runs under a conflict and/or wall-clock budget; on exhaustion returns SolveResult::Unknown (never spins forever). No steady-state latency SLO: "fast" vs "impossible" differ by >10⁹×; latency is budget-bounded, not per-call bounded.

4.3 Startup / load

Zero global init (no static tables, lazy_static, warm-up). Solver::new(cnf) allocates VarMap/LitMap to nvars, builds initial watches — O(formula size). Cold-start to first decision = parse (O(bytes)) + arena fill + watch init; no I/O beyond input .cnf and optional proof file.

4.4 Capacity caps (DoS bounding)

Dimension Soft fit Hard cap Enforcement
Variables millions < 2^31 (Lit encoding) DimacsError::VarOutOfRange at parse
Clauses tens of millions configurable max (RAM-derived) reject in parse_dimacs
Single clause size normal <= nvars bounded; reject absurd sizes DimacsError
Header counts must match body mismatch tolerated or rejected per mode BadHeader / count check
  • Untrusted DIMACS bytes + declared clause sizes are the DoS surface at sat-cnf (trust boundary). All caps enforced before allocation to prevent OOM/length-overflow from a hostile header.

4.5 CPU / cache assumptions

Propagation is L1/L2-bound, pointer-chasing over watches+ClauseArena; layout is the perf lever. blocker lets BCP skip the arena load when blocker is true (avoids a miss/clause). Watched-literal invariant: clause touched only when a watched lit goes false, no update on backtrack ⇒ cheap backjump. VarMap/LitMap dense ⇒ sequential, prefetch-friendly, no hot-path hashing. Arena compaction (Phase 12) restores locality after reduceDB churn.

4.6 Platform / environment constraints

Single-threaded core; shared-clause portfolio PhaseDeferred("Deferred Features Register"); no threading/locks/atomics. No NUMA, network, IPC. FDs only: stdin/input .cnf, stdout, single append-only DRAT/LRAT proof file (sole runtime persistence boundary). No async — synchronous std. unsafe confined to the audited arena/watch-list module (ADR-20). MSRV 1.78, edition 2021, std only.

4.7 Recovery / robustness invariants

Failure Behavior Invariant
Malformed DIMACS Err(DimacsError) parsing NEVER panics on adversarial bytes
Var/clause cap exceeded Err(DimacsError) pre-allocation no OOM from hostile header
Budget / interrupt hit SolveResult::Unknown solve always terminates on budget
Internal contradiction at level 0 SolveResult::Unsat (+ proof) empty clause derivable

Availability framing: an adversarial CNF can never crash the host — at worst it times out (Unknown). Liveness is sacrificed (NP-hardness); safety/memory-safety is absolute on all input. Interrupt is cooperative (checked at decision/restart points) so solve() yields Unknown promptly with Solver state consistent (trail/arena valid for a later solve_under).

36. Back-of-Envelope Capacity Model

Numbers an expert computes before designing, derived from System Constraints (§4). Formula shown; assume a single ~3 GHz core, 64 B cache line.

  1. Clause-arena bytes = clauses × (header 2 words + avg-size lits) × 4 B. For 1e6 clauses, avg size 8: 1e6 × (2+8) × 4 ≈ 40 MB. (§4.1 clause storage.)
  2. Watch-list memory = clauses × 2 watchers × 8 B (Watcher{cref,blocker}): 1e6 × 2 × 8 ≈ 16 MB. (§4.1; MM2.)
  3. Per-var dense arrays = nvars × (assigns 1 + level 4 + reason 8 + activity 8 + phase 1) ≈ 22 B. For 1e6 vars: ≈ 22 MB. LitMap watch heads add 2·nvars pointers. (§4.1.)
  4. Total RAM @ 1e6 vars / 5e6 clauses, avg size 6: arena 5e6×(2+6)×4 ≈ 160 MB + watches 5e6×2×8 = 80 MB + per-var 22 MB ≈ ~260 MB before learnts. (§4.1, §4.4.)
  5. Learnt-DB ceiling = reduce_limit × avg-learnt-size × 4 B. At reduce_limit ≈ 2e5, avg learnt 12: 2e5 × 12 × 4 ≈ 9.6 MB steady-state (bounded, not monotone). (Scalability "Learnt-DB growth".)
  6. LitMap size cap = 2 × nvars must fit u32 ⇒ nvars < 2^31; the configured cap 2^28 ≈ 268M keeps 2·nvars ≈ 2^29 words safely under 2^31. (§4.4, ADR-4, T6.)
  7. BCP throughput vs cache: at ≥1e7 props/s and ≤1 cache miss/propagated lit (~100-cycle miss), miss-bound rate ≈ 3e9 / 100 = 3e7 misses/s — so the target needs <1 miss/prop, exactly what the blocker shortcut buys (§4.5, §32.7).
  8. VSIDS heap ops/s = decisions/s × log₂(nvars). At 1e5 decisions/s, 1e6 vars: 2e6 sift ops/s — negligible vs BCP (§32.7, I6).
  9. reduceDB cadence = one sort per reduce_limit conflicts. At 1e5 conflicts/s, reduce_limit=2e5: a sort every ~2 s over ~2e5 learnts (≈ sub-ms) — <1% runtime (Phase 7 §19.7).
  10. Proof-stream rate = ~1 Add/conflict; at 1e5 conflicts/s, avg 12 lits binary-DRAT: ≈ 1.5 MB/s ⇒ a 1-hour hard UNSAT emits ~5 GB — hence streaming + .zst + trim (§4.1, §28).
  11. Compaction pause = O(live words) at ~1 word/ns: a 40 MB arena ≈ 10 ms, fired at >20% waste (~once per ~10 reduceDB cycles) ⇒ <2% wall (§32.7).
  12. Cold start = parse at ≥150 MB/s + arena fill + watch init: a 200 MB CNF loads in ~1.3 s before the first decision (§4.3, Phase 13 §25).
