4.3 Concurrency Constraints

Constraint Value Rationale
Budget ledger concurrency Lock-free CAS or mutex-per-dataset Atomic spend; no TOCTOU between check and charge
Mechanism invocations Embarrassingly parallel across queries Each is stateless given a CSPRNG per thread
CSPRNG threading model One CSPRNG state per thread (thread-local) Avoid contention; rand::thread_rng() pattern
dp-accountant state Single-writer, multiple-reader Composition is append; reads for conversion are concurrent
dp-validate Parallelizable across mechanisms Independent test suites; rayon parallel iterator
Max parallel query threads 64 (soft) OS thread overhead dominates above this for I/O-free workloads

4.4 Correctness and Safety Constraints

Constraint Enforcement
Epsilon > 0 and finite Newtype constructor rejects at construction; I8
Delta in [0, 1) Newtype constructor; Gaussian requires delta > 0
Sensitivity >= 0, l1 >= 0, l2 >= 0 Newtype invariants; panic-free: return Err
Budget spend monotone Ledger spent field only increases; no subtraction
Accountant composition monotone compose only appends; I9
No release on budget exhaustion BudgetExhausted error; no default-zero release; I10
Clamping before aggregation dp-sensitivity enforces I6; out-of-range values clamped
No raw data in logs dp-budget and dp-accountant log only PrivacyLoss values; P10

4.5 Numerical Precision Constraints

Constraint Requirement
Float type f64 throughout; no f32 on privacy-critical paths
Snapping mechanism precision Clamp-then-round to nearest representable; see Mironov 2012 §3
Exponential mechanism Log-sum-exp for numerical stability; never raw exp() overflow
Analytic Gaussian sigma Balle-Wang bisection converges to < 1e-10 relative error
RDP order vector Orders in [1.01, 256]; at least 20 log-spaced values recommended
Privacy-loss arithmetic Use checked_add / saturating semantics; never silent overflow

4.6 Storage and Audit Constraints

Aspect Constraint
Audit log format Append-only structured records: {timestamp, dataset_id, mechanism, eps, delta, remaining}
Audit log persistence Optional; in-process Vec by default; file backend via trait object
Audit log size budget 1 M entries per dataset before rotation required
State serialization PrivacyLoss / Budget serializable to JSON or CBOR for checkpointing
No dataset persistence The engine never writes raw data; only budget and accounting state

4.7 Availability and Failure Budget

Scenario Behavior
Invalid params at construction Immediate Err(InvalidParam); no panic
Budget exhausted Err(BudgetExhausted); caller decides policy (reject, prompt)
CSPRNG entropy failure Propagate OS error; no fallback to weak RNG
Sensitivity overflow (unbounded domain) Err(SensitivityUnbounded); I10
Accountant numeric underflow/overflow Return Err(AccountingOverflow); no silent clamp
Panic policy No panics in library code; all errors are Result<T, DpError>

Back-of-Envelope Capacity Model

Every number is derived from the §4 System Constraints tables with the formula shown.

C1 — Single noise-draw throughput. §4.1: <1 µs p99/draw. Formula: 1 / 1 µs = 10⁶ draws/s per core per thread.

C2 — Histogram query cost. §4.1: 1000-bin histogram <1 ms; each bin is one draw (C1). Formula: bins × draw_cost = 1000 × 1 µs = 1 ms. Confirms parallel composition — disjoint bins are independent.

C3 — End-to-end query overhead. §4.1: dp-query <10 µs vs draw <1 µs. Formula: query = draw + sensitivity_calc + budget_spend; the ~9 µs balance is sensitivity computation + the <5 µs atomic budget charge (C4).

C4 — Budget-ledger throughput. §4.1: atomic spend <5 µs p99. Formula: 1 / 5 µs = 2×10⁵ spends/s per dataset (single CAS sequence, §4.3).

C5 — Accountant state size. §4.2: <100 KB per accountant at 100 orders. Formula: |orders| × 8 B = 100 × 8 = 800 B per composed curve; pruning bounds the total (Scalability Analysis).

C6 — RDP compose cost. §4.1: 50-order compose <20 µs (a Vec<f64> add). Formula: |orders| ops, memory-bound. 10⁴ mechanisms → 10⁴ × 20 µs = 0.2 s total accounting.

C7 — DP-SGD per-step overhead. §4.1: <100 µs/step at batch ≤256 (excl. backprop). Formula: step = 256 per-example clips + 1 Gaussian draw on the batch gradient + 1 accountant charge.

C8 — DP-SGD memory. §4.2: <512 MB at batch 256, 1M params; engine adds one noise buffer. Formula: caller_grad_buffer + 1 × (1M params × 8 B) = +8 MB over the caller's allocation.

C9 — Audit-log rotation point. §4.2/§4.6: <10 MB ledger, ~64 B/entry, structural cap 1M entries. Formula: max_RAM_entries = 10 MB / 64 B ≈ 156,000. Rotation triggers at ~156 K entries — well before the 1M structural cap. (Surfaces the real tension between the two constraints.)

C10 — Conformance-test runtime. §4.1: dp-validate 10⁴ samples <10 s/mechanism. Formula: samples × per_sample ≈ 10⁴ × 1 ms = 10 s; N mechanisms over c cores (rayon, §4.3) → N/c × 10 s wall-clock.

C11 — Parallel query throughput. §4.3: ≤64 threads; each query <10 µs (C3). Formula: 64 × 10⁵ q/s = 6.4×10⁶ queries/s aggregate (compute-bound; only the per-dataset budget mutex is shared).

C12 — RDP order-vector sizing. §4.5: orders in [1.01, 256], ≥20 log-spaced. Formula: 20–100 orders × 8 B = 160 B–800 B per curve; order count trades accounting tightness (more orders → tighter (ε,δ)) against the O(|orders|) compose cost (C6).
