3.2 Subsystem Descriptions

dp-cli — Entry point for human operators. Parses query | budget | mechanism | validate subcommands and dispatches to the corresponding library crate. Owns no business logic; translates CLI arguments to typed PrivacyParams and Bounds. Stdout: DpResult JSON or budget summary. Stderr: errors. No access to raw data in production mode.

dp-query — The analyst-facing query API. Exposes count, bounded_sum, mean, histogram, and quantile operations. Each query type implements the Query trait: computes its own Sensitivity from supplied Bounds, selects the appropriate mechanism via dp-mechanism, and requests a budget spend via dp-budget. Inbound: raw data slice + Bounds + PrivacyParams. Outbound: DpResult<T>. Does not own noise generation; delegates entirely to dp-mechanism.

dp-sensitivity — Computes and enforces global L1/L2 sensitivity. Input: a query description and Bounds. Output: a Sensitivity value certified to be >= the true global sensitivity (I2). Provides clamp(value, bounds) to enforce I6. Provides transform_stability(scale) for composing sensitivities across data transforms. No randomness; deterministic; no I/O.

dp-mechanism — Implements the Mechanism trait for Laplace, Gaussian, exponential, and report-noisy-max. Each mechanism takes (exact: T, sens: Sensitivity, params: PrivacyParams) and returns a noisy T. Noise generation is delegated to dp-sample; the mechanism layer only calibrates parameters (scale b = l1/ε for Laplace; σ from analytic-Gaussian formula for Gaussian) and calls the sampler. Advertises its own PrivacyParams to the accountant. dp-svt is a peer crate that implements the sparse vector technique on top of dp-mechanism primitives.

dp-svt — Sparse vector technique and above-threshold. Accepts a stream of queries and a threshold; answers "above" or "below" while paying ε once per query that crosses the threshold, not once per query answered. Internally uses dp-mechanism's Laplace noise. Useful for answering many queries with a single budget allocation.

dp-sample — Trusted noise source. Implements the Mironov snapping mechanism for Laplace (closes the float-DP attack) and a discrete / interval-refinement Gaussian. Uses a CSPRNG (OS entropy via getrandom). No higher-level logic; only: uniform bit generation → Laplace/Gaussian samples with no representable-value gaps. This is the trust anchor for I5; all other noise passes through here.

dp-accountant — Tracks cumulative privacy loss across releases. Four accountant modes: basic composition (εs add, δs add), advanced composition (sqrt-scaling), RDP (Renyi divergence at a vector of orders α), and zCDP/moments accountant (rho). Provides compose(mechanism_params) -> PrivacyLoss and to_eps_delta(delta_target) -> PrivacyParams. RDP is the default for Gaussian and DP-SGD; converts to tightest (ε,δ) at report time (P6). Monotonic: I9 enforced by construction.

dp-budget — Hard budget enforcer. Holds a Budget { total: PrivacyParams, spent: PrivacyLoss } per dataset/per-analyst scope. Before any release: query accountant for the cost, compare against total - spent; if it would exceed, return BudgetExhausted error (I3, I10). If allowed, atomically update spent. Maintains an append-only audit log of every charge (P10). No access to raw data; operates solely on PrivacyLoss accounting values.

dp-local — Local-DP layer. Implements randomized response with flip probability p for a binary response, and a debiased frequency estimator. Provides heavy-hitter sketches via the RAPPOR-style approach. Does not route through dp-budget (local DP's trust model is user-side); has its own PrivacyParams for the reported ε guarantee. Outbound: DpResult<T> stamped with local-DP ε.

dp-dpsgd — DP-SGD integration. Input: per-example gradient tensors (as f64 slices), a clipping norm bound, and PrivacyParams. Clips each per-example gradient to L2 norm ≤ C, sums, adds Gaussian noise calibrated to (C, ε, δ), and charges the moments accountant once per training step. Returns the noisy batch gradient + updated PrivacyLoss for the training run. Does not implement backpropagation; expects caller-supplied per-example gradients.

dp-validate — Statistical DP conformance testing. Constructs pairs of neighboring datasets; runs a mechanism many times on each; applies a hypothesis test (log-likelihood ratio or empirical CDF test) to verify the ε-bound holds. Also runs sensitivity audits (verify declared sensitivity >= empirical sensitivity). Outputs a conformance report: PASS / FAIL per mechanism + accountant cross-checks.

DpResult<T> — The post-processing-immune output type. Carries { value: T, params: PrivacyParams }. Once emitted, any deterministic or randomized function of value remains DP at the same params (I7). The params field is the provenance record for the released value.

8.2 Newtype Invariant State Machine

Epsilon(f64):
  UNVALIDATED ──[f64 > 0 && finite]──► VALID
               ──[f64 ≤ 0 || NaN || Inf]──► REJECTED (Error::InvalidEpsilon)

Delta(f64):
  UNVALIDATED ──[0.0 ≤ f64 < 1.0 && finite]──► VALID
              ──[f64 < 0 || f64 ≥ 1 || NaN]──► REJECTED (Error::InvalidDelta)

Sensitivity {l1, l2}:
  UNVALIDATED ──[l1 ≥ 0 && l2 ≥ 0 && both finite]──► VALID
              ──[l1 < 0 || l2 < 0 || Inf]──► REJECTED (Error::UnboundedSensitivity)
  VALID ──[declared < true global sens]──► UNSOUND (bug; audited by dp-validate, not caught at runtime)

8.4 Privacy Accounting Type Hierarchy

PrivacyLoss (enum)
  ├── Basic(PrivacyParams)          — (eps, delta) pair from a single mechanism
  ├── Rdp(RdpCurve)                 — Vec<(alpha: f64, rdp: f64)>
  └── Zcdp(rho: f64)               — zCDP accumulator

RdpCurve
  ├── orders: Vec<f64>              — Renyi orders α > 1
  └── losses: Vec<f64>             — D_α(M(D) || M(D')) per α

Composition path:
  RdpCurve + RdpCurve  →  element-wise sum per α  (I4, I9)
  Zcdp(ρ₁) + Zcdp(ρ₂) →  Zcdp(ρ₁ + ρ₂)
  RdpCurve → PrivacyParams via: min over α of {rdp[α] + log(1/δ)/(α-1)} (Mironov 2017 conversion)
  Zcdp(ρ) → (eps,delta): eps = ρ + 2√(ρ ln(1/δ))  (Bun-Steinke)

8.6 Sensitivity Computation Rules (Normative)

Query Neighboring relation L1 global sensitivity L2 global sensitivity
Count add/remove one record 1 1
Bounded sum ([l,u]) add/remove max(|l|, |u|) max(|l|, |u|)
Bounded mean ([l,u], n) add/remove (u-l)/n (u-l)/n
Histogram (k bins, [l,u]) add/remove 1 (parallel: max bin sens=1) 1
Quantile (via exp mech) add/remove 1/n (score sensitivity) —
  • Replace neighbor model: sensitivity may differ; user must declare which model is in use.
  • Unbounded query (no Bounds declared) → Error::UnboundedSensitivity (I10, P7).
  • Transform stability: if a map f has stability t (i.e., d(f(D),f(D')) ≤ t·d(D,D')), then sensitivity of g∘f = t · sens(g).

8.7 Mechanism Calibration Normative Rules

Mechanism Noise law Scale / sigma rule DP guarantee
Laplace Lap(b) b = l1_sens / ε pure ε-DP (δ=0)
Gaussian (classical) N(0,σ²) σ = l2_sens · √(2 ln(1.25/δ)) / ε (ε,δ)-DP; not tight
Gaussian (analytic, Balle-Wang) N(0,σ²) σ = smallest s.t. Φ(Δ/(2s) - εs/Δ) - e^ε·Φ(-Δ/(2s) - εs/Δ) ≤ δ (ε,δ)-DP; optimal σ
Exponential Categorical P(o) ∝ exp(ε·u(o)/(2·Δu)) ε-DP
Report-noisy-max Lap(1/ε) per score b = 1/ε (sensitivity 1 counts) ε-DP (cheaper than Exp for argmax)
Randomized response (local) Bernoulli(p) p = e^ε/(1+e^ε) ε-LDP; debiased estimator unbiases the aggregate

Invariant: noise scale must be computed from the sensitivity declared at call time, not any cached value (I2).

8.8 Sparse Vector Technique (SVT) Model

SVTState:
  threshold: T (noised once at construction, pays 1 use from ρ_threshold)
  above_count: u32
  above_limit: u32   (k = max above-threshold queries to answer)
  epsilon_threshold: Epsilon
  epsilon_answer: Epsilon   (charged per ABOVE answer; no charge for BELOW)

Transitions per query q_i:
  noised_q_i = q_i(D) + Lap(2/eps_threshold)
  if noised_q_i < threshold: emit ⊥ (BELOW); no budget charge for answer
  else if above_count < above_limit:
    emit true + Lap(4k/eps_answer)  (ABOVE); charge eps_answer / k to budget; above_count++
  else: terminate SVT (all k answers exhausted)

Privacy: total cost = epsilon_threshold + epsilon_answer (sequential composition of the two components); parallel composition does NOT apply here.

8.9 DP-SGD Execution Model

Per training step t:
  for each example i in minibatch B:
    g_i = ∇L(θ, x_i)                           // per-example gradient
    g_i_clipped = g_i / max(1, ‖g_i‖₂ / C)    // clip to L2 norm ≤ C
  g_sum = Σ g_i_clipped
  g_noised = (g_sum + N(0, σ²C²·I)) / |B|      // σ = noise_multiplier
  θ ← θ - η · g_noised

Accountant charge per step:
  q = |B| / N  (subsampling rate)
  Compute RDP(α) = subsampled_gaussian_rdp(α, σ, q) per order α
  Accumulate into RdpAccountant
  Privacy budget checked after each step; training halts if budget exhausted (I3, I10)

Key parameters:
  C:  gradient clipping norm (bounds L2 sensitivity per example = C)
  σ:  noise multiplier (σ·C = Gaussian std dev)
  q:  subsampling rate → amplification; ONLY claimed through RDP accountant (P9)

8.11 Worked Example — Bounded Sum Query

Setup: dataset D of salaries, n=1000, bounds [20000, 200000], total budget ε=1.0, δ=1e-6.

  1. Bounds { lower: 20000.0, upper: 200000.0 } → declared.
  2. dp-sensitivity: l1_sens = max(|20000|, |200000|) = 200000; l2_sens = 200000.
  3. LaplaceMechanism { scale: 200000 / 1.0 = 200000.0 } — Laplace noise with scale 2e5.
  4. dp-sample (snapping): compute exact sum, add Lap(2e5) via snapping mechanism (not naive float).
  5. DpResult { value: exact_sum + noise, params: PrivacyParams { epsilon: 1.0, delta: 0.0 } }.
  6. RdpAccountant.accumulate(rdp_laplace(alpha, 1.0)) for each order α.
  7. Budget.spend(cost) → remaining ε reduces; ledger entry appended.
  8. Analyst receives numeric answer + PrivacyParams stamp; raw sum never emitted.

If the analyst prefers Gaussian: delta=1e-6 → analytic Gaussian σ calibration via Balle-Wang bisection → sigma ≈ 200000 · sqrt(2 ln(1.25/1e-6)) / 1.0 ≈ 739000 (classical), or tighter analytic sigma ≈ 715000 → RdpAccountant tracks D_α for each order; accountant is charged before emitting the result.

8.12 Failure-Path Example — Budget Exhaustion Mid-Session

Setup: budget ε=0.5, δ=0. Three Laplace queries each requesting ε=0.2.

Step Cost Cumulative (basic) Budget check Outcome
Q1 ε=0.2 0.2 0.2 ≤ 0.5 → PASS CHARGED; DpResult emitted
Q2 ε=0.2 0.4 0.4 ≤ 0.5 → PASS CHARGED; DpResult emitted
Q3 ε=0.2 0.6 0.6 > 0.5 → FAIL DENIED; Err(BudgetExhausted); nothing emitted

Q3 leaves no partial state change: the budget read and the check are atomic; no noise was sampled before the check passes (fail-closed, I3, I10).

8.13 Mechanism Privacy Proof Sketches (Normative Constraints)

Each mechanism must satisfy the following normative constraints — not full proofs, but the key inequality the implementation must honor:

Laplace Mechanism

  • Output: f(D) + Lap(b), b = Δ₁/ε.
  • Proof constraint: for any D, D' neighboring, any S ⊆ ℝ: Pr[M(D) ∈ S] / Pr[M(D') ∈ S] ≤ exp(|f(D)-f(D')|/b) ≤ exp(Δ₁/b) = exp(ε).
  • Implementation check: b > 0 (ε > 0 && Δ₁ > 0); b = ∞ rejected (I8, I10).

Gaussian Mechanism (analytic)

  • Output: f(D) + N(0, σ²).
  • Proof constraint (Balle-Wang): σ is the smallest value satisfying Φ(Δ₂/(2σ) - εσ/Δ₂) - e^ε · Φ(-Δ₂/(2σ) - εσ/Δ₂) ≤ δ.
  • Implementation check: δ > 0 (pure DP impossible for Gaussian, I8); bisection tolerance ≤ 1e-10.

Exponential Mechanism

  • Output: candidate o with probability ∝ exp(ε · u(o) / (2·Δu)).
  • Proof constraint: for any neighboring D, D', any output o: Pr[M(D)=o] / Pr[M(D')=o] = exp(ε(u(D,o)-u(D',o))/(2Δu)) ≤ exp(ε).
  • Implementation check: utility differences bounded by Δu (sensitivity of u); log-sum-exp stable normalization.

Randomized Response

  • Output: true answer with prob p = e^ε/(1+e^ε); flip with prob 1-p.
  • Proof constraint: p/(1-p) = e^ε; satisfies ε-LDP.
  • Debiasing estimator: p̂_true = (p̂_obs - (1-p)) / (2p-1); unbiased, variance inflated by 1/(2p-1)².

8.15 RDP Accountant Detail

Per-mechanism RDP loss (α > 1):

Mechanism D_α(M(D) ‖ M(D'))
Gaussian N(0,σ²), Δ₂ α·Δ₂²/(2σ²)
Laplace Lap(b), Δ₁ min(α·Δ₁²/(2b²), ...) — exact formula via moment generating function
Subsampled Gaussian (rate q) ≤ (1/α-1)·log(q²·D_α/(M_q)+...) — Mironov Thm 9

Conversion RDP → (ε,δ):

  • For each order α: ε(α,δ) = rdp[α] + log(1/δ)/(α-1).
  • Return min over α { ε(α,δ) } for the target δ.
  • Implementation: sweep orders vector, return minimum; order vector should include [1.5, 2, 4, 8, 16, 32, 64] as defaults.

Composition accumulation invariant (I9):

  • After k steps: rdp_total[α] = Σᵢ rdp_i[α] for all α.
  • Monotone: adding step k+1 can only increase rdp_total[α] (δ ≥ 0 per-step contribution).

Gaussian requested with δ=0 Err(PureDpIncompatible); Gaussian requires δ>0 (I8)
Bounds [u, l] where l > u Err(InvalidBounds)

Concurrent spend on same Budget Serialized via internal mutex; second spend sees post-first state

Histogram with 0 records in a bin Count = 0; sensitivity still 1 (add/remove); noise still added to 0

8.17 Type Ownership and Lifetime Model

Key ownership rules enforced at compile time:

Relationship Ownership model Rationale
Budget and BudgetLedger Budget owns BudgetLedger exclusively Ledger is an internal implementation detail; no outside ref
RdpAccountant inside Budget Budget owns accountant; exposes borrow for read Prevents out-of-band accountant mutation

8.18 Local DP Frequency Estimation Model

Objective: estimate frequency vector f ∈ [0,1]^k from n local DP responses without accessing true answers.

Randomized Response on k categories:

  • Each user holds true answer v ∈ {1,...,k}.
  • Report true v with prob p = (e^ε/(e^ε + k - 1)); report each other value with prob (1-p)/(k-1).
  • Satisfies ε-LDP per user.
  • Aggregator receives n reports; computes empirical frequency of each category.
  • Debiased estimate: f̂_j = (p̂_j - (1-p)/(k-1)) / (p - (1-p)/(k-1)).
  • Variance per cell: O(k e^ε / (n (e^ε-1)²)).

Heavy-hitter sketch (RAPPOR-style):

  • User encodes v into a Bloom filter; applies randomized response per bit.
  • Server decodes candidates above frequency threshold from noisy counts.
  • Privacy: ε-LDP per user (bit-level RR with per-bit ε' summing to ε via basic composition across bits).

8.18 dp-validate Statistical Test Protocol

Neighboring dataset test (per mechanism M):

  1. Fix a query f and two neighboring datasets D, D' (differ by one record).
  2. Sample N=10000 outputs from M(D) → distribution P; N=10000 from M(D') → distribution Q.
  3. For each threshold t, compute empirical Pr[M(D) ≥ t] and Pr[M(D') ≥ t].
  4. Check: for all t, log(Pr[M(D) ≥ t] / Pr[M(D') ≥ t]) ≤ ε + δ_slack.
  5. δ_slack = 1/√N (statistical tolerance); fail if exceeded by more than 3σ.
  6. Also check the reverse direction (symmetry of DP).

Sensitivity audit:

  • For n=1000 random pairs (D, D') that differ by one record, compute |f(D) - f(D')|.
  • Assert: max over pairs ≤ declared_sensitivity.l1 (soundness, I2).
  • If any pair exceeds declared, emit SensitivityViolation error.

Accountant cross-check:

  • Run k=100 identical Gaussian releases; compare RDP-accountant's (ε,δ) vs advanced composition (ε,δ).
  • Assert: RDP gives ε ≤ advanced-composition ε (tightness check, P6).
  • Assert: both ≥ true composition lower bound from first-principles (correctness check, I4).
