⬜ Phase 1 — core types + privacy parameters

Objectives
  • Define foundational newtypes in dp-core: Epsilon, Delta, PrivacyParams, Sensitivity, Bounds, DpResult<T>.
  • Enforce invariants at construction: eps > 0 finite; delta in [0, 1); l1/l2 >= 0.
  • Guarded arithmetic (composition add, min/max) preserves invariants or returns DpError.
  • No I/O, no randomness, no mechanism logic in this crate.
  • DpError enum covers all failure modes used by downstream crates.
Deliverable
  • dp-core crate compiles with zero dependencies beyond std (optional serde feature).
  • All constructors enforce invariants; invalid inputs return typed errors.
  • cargo test -p dp-core passes all unit + property tests.
  • Downstream crates can import dp-core::{Epsilon, Delta, PrivacyParams, Sensitivity, Bounds, DpResult, DpError}.

Malformed cases: delta = -0.0 (must accept as Delta::ZERO), eps = f64::MIN_POSITIVE (must accept), eps = f64::INFINITY (must reject).

Pitfalls
  • Negative zero delta: -0.0 < 0.0 is false in IEEE 754; test sign+zero separately — treat as valid Delta::ZERO.
  • Epsilon addition overflow: two valid values near f64::MAX/2 sum to Inf; detect via is_infinite() → CompositionOverflow.
  • Delta addition near 1.0: 0.9 + 0.2 = 1.1 but both valid individually; must check sum < 1 before constructing.
  • l2 > l1 on Sensitivity: possible for multi-dimensional queries via scalar path; validate() warns but does not hard-reject.
  • Serde round-trip precision loss: deserializing Epsilon may introduce sub-ULP drift; re-validate after deserialization.
  • Bounds::width underflow: upper - lower near f64::MIN_POSITIVE may underflow to 0; detect and return InvalidBounds.

Pitfalls
  • Under-estimation of sum sensitivity: (upper - lower) instead of max(|lower|, upper) is wrong for asymmetric bounds — worst case is a record at the extreme. Fix: always use absolute max.
  • Mean sensitivity with data-dependent n: using actual dataset size makes sensitivity data-dependent, breaking the public-parameter requirement. Fix: require min_dataset_size as a public constant.
  • Clamping after aggregation: clamping the aggregate (sum, mean) instead of individual records does not bound sensitivity; I6 requires per-record clamping first.
  • Float rounding in sensitivity scale: c * l1 may round below the true product; add margin via c * l1 * (1.0 + 2.0 * f64::EPSILON).
  • Histogram sensitivity and parallel composition: non-disjoint bins make composition additive, not max; verify disjointness at query construction time.
  • Transform chain mis-ordering: Lipschitz before vs after AddRemove changes the result; sensitivity_after_map applies one step, chains must be applied in order.

Pitfalls
  • Using rand::distributions::Laplace directly: rand 0.8 has no Laplace distribution; naive sign * Exp(1/b) via inverse-CDF uses f64::ln on a [0,1) uniform, which has representable-value gaps — the float-DP attack fixed in Phase 5. Mark NaiveSamplerHandle test-only.

⬜ Phase 5 — Secure Noise Sampling

Objectives
  • Implement dp-sample crate: secure samplers for Laplace and Gaussian that close the Mironov 2012 floating-point attack (I5).
  • Provide the snapping mechanism for Laplace: rounds the noisy value to the nearest power-of-two multiple, preventing input reconstruction from representable-value gaps.
  • Provide a discrete Gaussian (Canonne-Kamath-Steinke NeurIPS 2020) or interval-refinement sampler that avoids float-gap leakage in Gaussian sampling.
  • Source randomness exclusively from a CSPRNG (OsRng or equivalent); no rand::thread_rng / seeded-rng in production paths.

⬜ Phase 6 — Exponential Mechanism

Objectives
  • Implement ExponentialMechanism in dp-mechanism for discrete candidate selection: samples candidate c with probability proportional to exp(eps * u(c) / (2 * sensitivity)).
  • Target non-numeric selection queries: mode, best histogram bin, decision-tree split point, top-k candidates.
  • Guarantee pure eps-DP (delta = 0) via the standard exponential mechanism proof.
  • Numerically stable selection via log-sum-exp over utilities; avoid overflow for large utilities.
  • Sensitivity is max_{c} |u(D,c) - u(D',c)| over neighboring datasets; caller must declare this.

  • ExponentialMechanism<C> compiles for generic C: Clone; sample returns DpResult<C>.

  • Log-sum-exp path verified: no inf or NaN for utilities in [-1000, 1000].

⬜ Phase 7 — Report-Noisy-Max + Randomized Response

Objectives
  • Implement ReportNoisyMax in dp-mechanism: add Laplace noise to each candidate score, return argmax index; achieves eps-DP with eps = 2 * sensitivity / scale (half the exponential mechanism cost for selection).

⬜ Phase 8 — Basic + Advanced Composition

Objectives
  • Implement dp-accountant crate: BasicComposer and AdvancedComposer structs.
  • Basic composition: k sequential (eps_i, delta_i) releases → total (sum eps_i, sum delta_i); always-valid, always-conservative.
  • Advanced composition: k-fold adaptive composition theorem (Dwork-Rothblum-Vadhan 2010); tighter bound (sqrt(2k ln(1/delta')) * eps + k*eps*(e^eps-1), k*delta + delta') for homogeneous mechanisms.
  • Sequential vs parallel composition: disjoint-partition queries compose with max(eps_i), not sum.
  • Heterogeneous mechanism composition: accumulate per-mechanism (eps_i, delta_i) tuples; apply basic or advanced depending on context.
  • Expose CompositionStrategy enum (Basic | Advanced | Parallel) so dp-budget (Phase 11) can select automatically.
  • No budget ceiling enforcement yet (Phase 11); accountant only reports cumulative cost.
Deliverable
  • dp-accountant crate compiles; BasicComposer, AdvancedComposer, ParallelComposer, Accountant exported.
  • Integration test: 10 Laplace mechanism releases each with eps=0.1, delta=0; basic total = (1.0, 0.0); advanced total < (1.0, 0.0) for suitably chosen delta_prime.
  • tighter_of_basic_and_advanced returns advanced when k > threshold.

Pitfalls
  • Advanced composition's delta_prime not subtracted from budget: delta_adv = k*delta + delta' means the caller must reserve delta' from the dataset budget before calling advanced composition; failure undercharges delta. Fix: document that delta_prime is itself a budget draw.
  • Parallel composition applied to non-disjoint partitions: overlapping partitions break the max-eps guarantee — true sensitivity doubles on the overlap; no in-engine check possible; operator error. Mitigation: a boolean assert_disjoint param that panics in debug mode.
  • Floating-point summation drift in basic composition: summing 10 000 small epsilons loses precision; use Kahan summation. Signal: total eps differs from k * eps_single by > 1e-9.
  • Advanced formula valid only for eps <= 1: the DRV tighter form assumes eps <= 1 for the simplified sqrt bound; for large eps, k*eps*(e^eps-1) grows rapidly and may exceed basic. Fix: always return min(basic, advanced).
  • Monotonicity violation on floating-point edge: sqrt-based eps_adv plus zero-eps releases can cause tiny floating-point decrease. Fix: max(previous_loss, new_loss) in Accountant::compose to enforce I9.

⬜ Phase 9 — Renyi Differential Privacy (RDP)

Objectives
  • Implement RdpAccountant in dp-accountant: track Renyi divergence D_alpha[M(D) || M(D')] at a vector of orders alpha.
  • Per-mechanism RDP: Gaussian mechanism RDP(alpha) = alpha * l2^2 / (2 * sigma^2).
  • RDP composes additively per order: RDP_total(alpha) = sum_i RDP_i(alpha).
  • Convert RDP curve to tightest (eps, delta) at release time via the optimal conversion formula (Mironov 2017, Proposition 3).
  • Implement rdp_for_gaussian, rdp_for_laplace, rdp_for_randomized_response as standalone functions in dp-accountant::rdp_formulas.
  • Primary accountant used by dp-budget (Phase 11) when Gaussian mechanisms are present; basic/advanced composition (Phase 8) is the fallback for pure-DP releases.
Deliverable
  • RdpAccountant with Gaussian, Laplace, and RR formulas compiles and passes unit tests.
  • Cross-validation: rdp_for_gaussian → to_eps_delta agrees with known (eps, delta) values from Table 1 of Mironov 2017 within 1e-6.
  • AccountantKind::Rdp integrates with Accountant unified interface.
  • Phase 10 extends RdpAccountant with zCDP and the subsampled Gaussian (moments accountant).

Pitfalls
  • Off-by-one in the conversion formula: Mironov 2017 Prop 3 uses (alpha-1) in the denominator; mistyping as alpha shifts the bound. Signal: rdp_gaussian_single fixture fails.
  • Numerical instability at large alpha: log(delta * (alpha_i-1)) for alpha=1024, delta=1e-10 produces very large negative values; subtraction with rdp[i] may cancel. Use log1p and split the expression.
  • Wrong order grid resolution: too-sparse grid (e.g. alpha=[2, 1024]) misses the optimal alpha, returns eps 20-50% larger. Fix: use the 14-point default grid; expose override for advanced users.
  • Laplace RDP formula overflow: exp((alpha-1)*l1/b) for alpha=1024, l1=1, b=0.01 = exp(102300) → inf. Use log-sum-exp: compute in log space, exponentiate once.
  • Composition with heterogeneous order grids: two mechanisms computed on different alpha grids cannot be composed element-wise. Fix: require a single global order grid at RdpAccountant::new; reject mismatched rdp_curve lengths with Err(OrderMismatch).
  • Forgetting to include delta_prime in budget when converting: the (eps, delta) returned by to_eps_delta uses the supplied delta as the conversion target, which must be drawn from the privacy budget; operator must ensure it matches the budget delta ceiling.
