I1Device state transitions Unbound → Probing → Bound → Removing → Freed monotonically; no transition skips or reverses.A skipped state (e.g. Unbound → Bound direct) bypasses resource-claim bookkeeping.ddf-core::DeviceState transition function (§11).ddf-verifier state-machine assertion per transition.ddf_device_state_transition counter, tagged from/to.Illegal transition rejected; device forced to Removing.
I2A bound Driver holds only resources declared in its own ResourceSet; no claim bypasses the resource manager.Undeclared claims defeat leak detection and conflict checking.ddf-mmio/ddf-irq/ddf-dma claim APIs (§15–§17).Static: only these APIs can construct a Resource.ddf_resource_claim_total, ddf_resource_conflict_total.Claim rejected with ResourceError::Conflict.
I3refcount(Device) ≥ 1 while any FD/IRQ/DMA mapping is pinned; drops to 0 only after every pin releases.Load-bearing for safe unplug under concurrency (P11).ddf-hotplug refcount primitive (§18).Debug-build refcount tracker; underflow assertion.ddf_device_refcount_gauge.Underflow panics in debug builds; release builds saturate and log FM-1.
I4No top-half IrqHandler::handle blocks (sleeps, blocking-allocates, takes a sleeping mutex).Bounds IRQ latency (§4); required by P7.Type-level: IrqHandler trait has no sleeping-primitive-capable methods (§11).Lint (no-sleep-in-tophalf) + runtime watchdog on handler duration.ddf_tophalf_duration_us histogram.Watchdog logs and, above threshold, disables the offending IRQ line.
I5Every DMA-streaming mapping is synced before device access and after device completion.Unsynced streaming DMA reads/writes stale cache lines.ddf-dma::sync_for_device/sync_for_cpu (§17).ddf-verifier fixture asserting sync-before-access ordering.ddf_dma_sync_total.Access without prior sync rejected at the API boundary (typestate).
I6IOMMU group membership is static after boot; no cross-group DMA translation.Cross-group translation defeats the IOMMU isolation boundary (P5).ddf-iommu::IommuGroup (§11, §17).IOMMU fault trap on mismatched group access.ddf_iommu_fault_total.Faulting device quarantined (§23 FM-4).
I7A failed probe() leaves the device Unbound with zero leaked resources.Retryable probe requires a clean rollback (§14).ddf-probe RAII rollback on Err (§14).ddf-verifier fixture: inject probe failure, assert ResourceSet empty.ddf_probe_failure_total.Automatic rollback; device eligible for the next driver match.
I8A device's parent is not freed while children exist (bottom-up teardown only).Top-down teardown frees a bus while children still reference it.ddf-core::Device::children refcount contributes to parent pin (§11).ddf-verifier teardown-order fixture.ddf_teardown_order_violation_total.Parent free deferred until children count reaches 0.
I9Power-state transitions form a total function: every (state, event) pair has a defined handler.Load-bearing for P10; an unhandled pair strands a device.ddf-pm::PmState exhaustive match (§19).Compile-time exhaustiveness check + ddf-verifier fixture enumerating all pairs.ddf_pm_unhandled_transition_total (should be permanently 0).Build fails if the match is non-exhaustive.
I10Hot-plug events for one bus are strictly ordered by sequence number; no reordering across plug/unplug on the same bus.TOCTOU races on rapid plug/unplug/replug (§22 T4).ddf-hotplug::EventQueue per-bus sequence counter (§18).ddf-verifier fixture: interleave plug/unplug, assert delivery order.ddf_hotplug_seq_gap_total.Out-of-order event dropped with FM-2 telemetry.
I11A removed Device returns ENODEV to every subsequent operation; no operation succeeds against a Freed device.Load-bearing for P4/P11.ddf-userspace and driver-call dispatch check state before dispatch (§16 Phase 8-adjacent §8.4).ddf-verifier fixture: call after removal, assert ENODEV.ddf_post_removal_call_total.Call short-circuits to ENODEV before reaching driver code.
I12MMIO regions never overlap between two live devices in the same address space.Overlapping MMIO causes silent cross-device corruption.ddf-mmio::claim range-conflict check (§15).Range-tree conflict check on every claim.ddf_mmio_conflict_total.Claim rejected with ResourceError::Overlap.
I13Descriptor-based device inputs (USB config descriptors, virtio vrings) are bounds-checked before use; no field read exceeds its declared length.The historical CVE-2016-2384 defect class (§37/§22 T1).Descriptor parsers in ddf-bus-usb/ddf-bus-virtio (§20).ddf-fuzz structure-aware fuzzer; ddf-verifier malformed-input fixtures (§8.6).ddf_descriptor_reject_total.Malformed descriptor rejected; device quarantined per P9.
I14Probe/match resolution is deterministic given identical (bus, driver-registry, load-order) inputs.Load-bearing for P2 and for conformance-fixture reproducibility.ddf-probe resolver uses BTreeMap-backed registry (P12).ddf-verifier fixture: replay identical inputs N times, assert identical output.ddf_probe_nondeterminism_total (should be permanently 0).N/A — enforced structurally via P12's deterministic containers.
