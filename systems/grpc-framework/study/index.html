Hard questions (§35)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does the framework subtract elapsed time from the deadline at every hop instead of checking the client's absolute deadline once at the leaf? (§8.7, §20.2)
  2. Under what regime would a token-bucket retry throttle still allow a retry storm, and what ADR plus failure class addresses it? (§9 ADR-12, §25 FM-3)
  3. Why is HPACK dynamic-table memory the dominant per-connection memory cost at high fan-in, and how does §34's derivation change the tuning guidance in §26?
  4. Trace a bidi-streaming call's HalfClosedRemote state through §8.3's table and explain why the server can still send after the client half-closes — cite the invariant that would be violated if it couldn't. (§8.3, §7 I2)
  5. Why does canonical encoding apply only to bytes we produce, never to bytes we accept — and which invariant would break if we rejected non-canonical input from another implementation? (§6 P6, §7 I1)
  6. A client sets no grpc-timeout at all. Walk through why this is a threat and which system constraint bounds the resulting resource exposure. (§24 T7, §4)
  7. Why does codegen cost ~200 ns of dispatch savings per RPC, and under what real-world regime does that saving not matter? (§6 P2, §9 ADR-08)
  8. Compare how Cap'n Proto's zero-copy design and this framework's decode-then-encode design handle "the hot path is deserialization" differently — which mental model explains why we didn't choose Cap'n Proto's approach? (§33, §32 MM7)
  9. Why is the retry idempotency gate a compile-time lint rather than a purely runtime check, and what failure mode does the compile-time version prevent that a runtime-only check would not? (§15 Phase 3, §7 I6, §25 FM-6)
  10. If the xDS resolver is deferred, what concretely breaks for a user running this framework inside an existing Envoy mesh today, and which ADR explains the accepted gap? (§37, §9 ADR-14)
  11. Explain why the flow-control window invariant is enforced by the wrapped h2 crate rather than hand-rolled code, tracing the decision to its ADR and the pitfall it avoids. (§7 I9, §9 ADR-04, §17.6)
  12. Using §34's derivation, at what connection count does HPACK dynamic-table memory exceed a typical 4 GB service memory ceiling, and what operational lever reduces it? (§34, §4, §26)
  13. Why does the framework treat a handler panic as a per-call Internal status rather than crashing the whole process, and which design principle does that decision serve? (§25 FM-7, §6 P9)
  14. Contrast Twirp's HTTP/1.1+JSON design against this framework's HTTP/2 choice — under what deployment regime would Twirp's approach have strictly lower operational cost? (§33, §9 ADR-06)
  15. Why must cancellation propagation be cooperative rather than preemptive, and what invariant bounds how long a misbehaving handler can violate that expectation before it's detectable? (§6 P4, §9 ADR-10, §7 I5)
  16. Derive, from §4's RTT assumptions and §34's chained arithmetic, the minimum viable top-level client deadline for a 6-hop call chain, and explain why a client deadline below that floor guarantees cascading DEADLINE_EXCEEDED failures. (§34, §25 FM-2)
  17. Why does the Deferred Features Register anchor every deferred item to a real section instead of leaving it as an unstructured TODO, and what would an unresolved anchor mean for the document's own integrity? (§37, §7 I14)
  18. Compare Apache Thrift's protocol/transport separation to this framework's own transport-agnostic principle — what did Thrift get right that we deliberately copied, and what did we do differently regarding codegen dispatch? (§33, §6 P1, §9 ADR-08)

32. Mental Models & First Principles

# Model Predicts Bug Class Without It Applied
MM1 An RPC call is a state machine, not a function call. Which operations are legal at which point in a call's lifecycle. Sending a message after trailers, or reading headers twice. §8.5, Phase 6
MM2 The wire format and the transport are orthogonal layers. Why swapping HTTP/2 for HTTP/3 shouldn't touch the codec. Conflating a transport-level error with an application-level Status. §3, Phase 5
MM3 A deadline is a budget that only shrinks. Why nested calls must subtract elapsed time, never reset it. A server ignoring elapsed time, causing downstream deadline overshoot. Phase 8, §20.2
MM4 Cancellation is advisory, not preemptive. Why handlers must poll rather than assume they'll be killed. A leaked task/resource after the client gives up. Phase 8, I5
MM5 Flow control is per-stream congestion control, reinvented. Why window size, not just bandwidth, bounds throughput on high-BDP links. Throughput collapse on a high-latency link with a small fixed window. Phase 5, §34
MM6 Retries must be idempotency-aware or they convert partial failure into double execution. Why a retry policy needs a schema-level annotation, not just a status-code list. A duplicated non-idempotent write under network flakiness. Phase 10, I6
MM7 Codegen trades a build-time dependency for a runtime dispatch guarantee. Why static dispatch beats reflection on the hot path. Runtime dispatch cost silently regressing under load. Phase 3, ADR-08
MM8 Schema evolution is a wire-compatibility contract, not a type-system feature. Why removing a field is breaking even though the type-checker doesn't complain. A field-tag reuse bug invisible until two versions interoperate. Phase 1, I10

5. Required Reading

Books

  • Kleppmann, Designing Data-Intensive Applications, O'Reilly, 2017, ch. 4 ("Encoding and Evolution"). Extract: why schema evolution rules (additive-only) are a wire-compatibility contract, not a type-system feature. Applied in §8, Phase 1 (§13).
  • Stevens, Fall, TCP/IP Illustrated, Volume 1, 2nd ed., Addison-Wesley, 2011. Extract: TCP flow control and congestion behavior that HTTP/2's per-stream flow control deliberately re-derives. Applied in §4, Phase 5 (§17).
  • Grigorik, High Performance Browser Networking, O'Reilly, 2013, ch. 12 ("HTTP/2"). Extract: multiplexing and header compression motivation. Applied in Phase 5 (§17).
  • Beyer, Jones, Petoff, Murphy (eds.), Site Reliability Engineering, O'Reilly, 2016, ch. 21–22 ("Handling Overload", "Addressing Cascading Failures"). Extract: why unlimited client retries amplify outages. Applied in Phase 10 (§22), §24 Threat Model.
  • Blandy, Orendorff, Tindall, Programming Rust, 2nd ed., O'Reilly, 2021, chs. on async/await and ownership across .await points. Applied in Phase 0 (§12), Phase 6 (§18).
  • Vitillo, Understanding Distributed Systems, 2nd ed., 2022, ch. on RPC semantics and idempotency. Applied in Phase 6 (§18), Phase 10 (§22).
  • **Nygard, Release It!, 2nd ed., Pragmatic Bookshelf, 2018**, ch. on the circuit breaker pattern. Applied in Phase 10 (§22), §25 (FM-3).

Papers

  • Birrell, Nelson. "Implementing Remote Procedure Calls." ACM TOCS, 1984. Foundational RPC semantics (marshalling, at-most-once/exactly-once framing). Applied in §2, §8, Phase 6 (§18).
  • Dean, Barroso. "The Tail at Scale." CACM 56(2), 2013. Motivates hedging as a tail-latency defense. Applied in Phase 10 (§22), §4.
  • Ousterhout et al. "The Case for RAMCloud." CACM 54(7), 2011. Motivates microsecond-scale RPC latency targets. Applied in Phase 6 (§18), §4.
  • Burrows. "The Chubby Lock Service for Loosely-Coupled Distributed Systems." OSDI, 2006. Deadline/lease-style budget reasoning. Applied in Phase 8 (§20).
  • Chandra, Toueg. "Unreliable Failure Detectors for Reliable Distributed Systems." JACM 43(2), 1996. Failure-detector theory behind health checking. Applied in Phase 11 (§23).
  • Verma et al. "Large-Scale Cluster Management at Google with Borg." EuroSys, 2015. Service discovery and load-balancing at scale. Applied in Phase 9 (§21).
  • Ongaro, Ousterhout. "In Search of an Understandable Consensus Algorithm." USENIX ATC, 2014. Consensus-based config propagation, contrasted with our DNS/ static resolver choice. Applied in §36 (Alternative Architectures).
  • Fielding. "Architectural Styles and the Design of Network-based Software Architectures." PhD dissertation, UC Irvine, 2000. REST as the RPC alternative. Applied in §33 (Comparative Architecture), §36.

Reference Implementations

  • grpc/grpc-go — internal/transport/, balancer/, resolver/. Lesson: a production plugin architecture for LB/resolver. Pitfall: don't copy its reflection-heavy codec path for our static-dispatch design. Applied in Phase 9 (§21), Phase 11 (§23, differential testing).
  • hyperium/tonic — tonic/src/transport/, tonic/src/client/, tonic/src/server/, tonic-build. Lesson: layered tower::Service interceptor model. Pitfall: codegen macro complexity balloons compile times. Applied in Phase 3 (§15), Phases 6–8 (§18–20).
  • tokio-rs/prost — src/encoding.rs. Lesson: derive-macro codec cost model. Pitfall: doesn't forward unknown fields by default in older versions. Applied in Phase 2 (§14).
  • hyperium/h2 — src/frame/, src/proto/. Lesson: correct HPACK dynamic-table + flow-control state machine. Pitfall: never hand-roll this; wrap it. Applied in Phase 5 (§17).
  • apache/thrift — lib/rs/src/. Lesson: transport/protocol separation predates gRPC by a decade. Pitfall: TCompactProtocol's varint differs subtly from protobuf's — don't conflate. Applied in Phase 2 (§14), §33.
  • capnproto/capnproto — c++/src/capnp/. Lesson: zero-copy serialization eliminates decode cost entirely. Pitfall: its schema-evolution rules are stricter than protobuf's — don't assume parity. Applied in Phase 4 (§16), §33.
  • twitchtv/twirp — twirp/. Lesson: HTTP/1.1+JSON trades multiplexing for debuggability. Pitfall: no native streaming — don't try to retrofit it. Applied in §33, §36.

Glossary (§38) · 49 terms · site-wide glossary

Varint
variable-length integer encoding, 7 data bits/byte, MSB continuation flag.
Zigzag encoding
maps signed integers to unsigned so small-magnitude negatives encode compactly.
Wire type
the 3-bit tag suffix identifying a field's on-wire shape (VARINT/FIXED64/LENGTH_DELIMITED/FIXED32).
Tag
a field's on-wire numeric identifier, distinct from its name.
LEB128
Little Endian Base 128, the general varint scheme protobuf uses.
Canonical encoding
the single deterministic byte form our own encoder always produces.
Unknown field
a decoded field whose tag isn't in the local schema, preserved for forward compatibility.
Packed encoding
a repeated primitive field encoded as one length-delimited block instead of N key-value pairs.
HPACK
the HTTP/2 header-compression algorithm (static + dynamic table + Huffman coding).
Dynamic table
HPACK's per-connection mutable header cache.
SETTINGS frame
HTTP/2's connection-parameter negotiation frame.
WINDOW_UPDATE
the flow-control credit-replenishment frame.
GOAWAY
the connection-draining signal.
RST_STREAM
the per-stream abort signal.
ALPN
TLS's application-layer protocol negotiation extension, used to agree on h2.
mTLS
mutual TLS, both peers present certificates.
SPIFFE
a workload-identity standard for cryptographic service identity.
Stream multiplexing
running many logical streams over one TCP connection.
Flow control
window-based backpressure bounding unacknowledged in-flight bytes.
BDP
bandwidth-delay product, used to size flow-control windows.
Deadline
a monotonic timestamp by which an RPC must complete.
Cancellation token
a cooperative signal a handler polls to detect client abandonment.
Idempotency level
a schema annotation declaring whether an RPC is safe to retry.
Retry throttle
a token-bucket mechanism suppressing retries under sustained failure.
Hedging
firing parallel speculative requests to bound tail latency.
Load balancer
client-side logic picking one endpoint per call.
Resolver
logic producing a service's current endpoint set.
Pick-first
an LB policy sticking with the first connectable endpoint.
xDS
the Envoy-originated dynamic configuration protocol family (deferred, §37).
Reflection service
a service exposing schema introspection at runtime.
Health checking
a service reporting per-service serving status.
Trailer
HTTP/2 headers sent after the message body, carrying gRPC status.
Metadata
the RPC's header/trailer key-value bag.
Any
a well-known type wrapping an arbitrary typed message plus a type URL.
FieldMask
a well-known type naming a subset of a message's fields.
Well-known types (WKT)
the google.protobuf canonical message set (Timestamp, Duration, Any, etc.).
Oneof
a field group where at most one member is set.
Schema evolution
the discipline of changing a schema without breaking deployed peers.
Reserved field
a tag/name explicitly barred from reuse.
Codegen
generating typed client/server code from a schema.
Intermediate representation (IR)
the language-agnostic parsed-and-resolved schema model.
Interceptor
a middleware layer wrapping call/handler invocation.
Span
one traced unit of work in a distributed trace.
Trace context
the propagated identifiers linking spans across a call chain.
OTLP
the OpenTelemetry wire protocol for exporting telemetry.
Conformance suite
the fixture corpus proving spec compliance.
Differential testing
comparing behavior against a reference implementation.
Fuzzing
feeding adversarial/random input to find crashes or invariant violations.
Soak test
a long-duration run verifying stability over time. ---
