34. Back-of-Envelope Capacity Model

  1. Per-core bandwidth = RPS × avg message size = 80,000 × 1,024 B ≈ 82 MB/s/core (from M3, §4).
  2. 16-core aggregate = 82 MB/s × 16 ≈ 1.31 GB/s, chained from (1); a 10 GbE NIC (~1.25 GB/s) is saturated near this core count — confirms the §31 NIC-bound ceiling around 16–20 cores.
  3. FD usage at max connections = 10,000 conns × 6 FD/conn = 60,000 FDs, just under the 65,536 ulimit (§4) — shows why the FD budget, not CPU, bounds max_connections first.
  4. Connection-table memory = 10,000 conns × ~2 KiB/H2Connection (§11) ≈ 20 MB — negligible against a typical multi-GB service memory ceiling.
  5. HPACK dynamic-table memory (worst case) = 10,000 conns × 64 KiB raised table size (§17.2) = 640 MB — the dominant per-connection memory driver at high fan-in, motivating a lower default table size for high-connection-count servers (§26 dashboard row).
  6. Retry amplification bound = 1 + (max_attempts − 1) × token_ratio = 1 + (3−1) × 0.1 = 1.2× steady-state traffic worst case, chained from ADR-12/I7's default token_ratio = 0.1.
  7. Minimum viable top-level deadline, 6-hop chain = 6 × (2 × 0.5 ms RTT + 1 ms local floor) = 6 × 2 ms = 12 ms, chained from §4's 0.5 ms intra-DC RTT assumption — informs the "≥ 50 ms client deadline" operational floor with margin.
  8. Streaming bandwidth = 90,000 msg/s × 1,024 B ≈ 92 MB/s/core (M8), within 12% of the unary bound (1) — confirms the 5-byte gRPC framing prefix costs < 1% of a 1 KiB message.
  9. Compression break-even = decode_cost(gzip, ~2 µs/KiB) < bandwidth_saved ÷ link_speed — favors compression only below roughly a 2 Gbps effective link speed; above that, CPU cost exceeds the bandwidth saved, informing the "compression off for loopback/intra-DC, on for cross-region" default (ADR-15).
