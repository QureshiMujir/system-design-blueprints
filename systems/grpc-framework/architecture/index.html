Five properties hold throughout and every later section stays consistent with them:

Wire codec independent of transport. grpc-codec's bytes are identical whether carried over HTTP/2 today or HTTP/3 in a deferred future phase (§37) — this is Principle P1.

Transport independent of protocol. grpc-transport-h2 knows about HTTP/2 frames and gRPC's 5-byte prefix; it never inspects protobuf field contents.

Resolver and load balancer are independent. grpc-resolver produces an endpoint set; grpc-loadbalancer picks one per call; neither depends on the other's internals.

Interceptors are layered, not chained. Each interceptor wraps a handler and decides how many times (zero, one, many) to invoke it — enabling retry-at-the-edge and circuit-breaking patterns a fixed chain cannot express (Principle P13).

Reflection/health are ordinary services. They register through the same Service trait as user code (§11); no special-cased server path exists for them.

8. Domain Model / Protocol / Data Model

8.1 Protobuf IDL Grammar (proto3 subset, EBNF)

file         = [syntax] [package] {import} {top_level_def} ;
syntax       = "syntax" "=" "\"proto3\"" ";" ;
package      = "package" full_ident ";" ;
import       = "import" ["public"] string_lit ";" ;
top_level_def= message | enum | service ;
message      = "message" ident "{" {message_body} "}" ;
message_body = field | oneof | reserved | enum | message | option ;
field        = ["repeated"] type ident "=" int_lit [field_options] ";" ;
oneof        = "oneof" ident "{" {oneof_field} "}" ;
oneof_field  = type ident "=" int_lit [field_options] ";" ;
reserved     = "reserved" (ranges | field_names) ";" ;
type         = "double"|"float"|"int32"|"int64"|"uint32"|"uint64"|"sint32"|"sint64"
             | "fixed32"|"fixed64"|"sfixed32"|"sfixed64"|"bool"|"string"|"bytes"
             | message_type | "map" "<" key_type "," type ">" ;
service      = "service" ident "{" {rpc} "}" ;
rpc          = "rpc" ident "(" ["stream"] message_type ")"
               "returns" "(" ["stream"] message_type ")" (";" | rpc_body) ;
enum         = "enum" ident "{" {enum_field} "}" ;
enum_field   = ident "=" int_lit [field_options] ";" ;

8.2 Wire Format

Wire Type Code Used For Encoding
VARINT 0 int32/int64/uint32/uint64/sint32/sint64/bool/enum LEB128, 7 data bits/byte, MSB=continuation
FIXED64 1 fixed64/sfixed64/double 8 bytes, little-endian
LENGTH_DELIMITED 2 string/bytes/embedded message/packed repeated varint(length) + length bytes
FIXED32 5 fixed32/sfixed32/float 4 bytes, little-endian

Field key = (field_number << 3) | wire_type, itself varint-encoded (ADR-03/I1).

Worked example. Encode {name: "Al" (tag 1, string), age: 30 (tag 2, int32)}:

  • key₁ = (1<<3)|2 = 0x0A; length=2; bytes 41 6C → 0A 02 41 6C.
  • key₂ = (2<<3)|0 = 0x10; value 30 varint = 1E → 10 1E.
  • Full encoding: 0A 02 41 6C 10 1E (6 bytes).

Malformed-input example. Byte stream 0A 02 41 — field 1 declares LENGTH_DELIMITED length 2 but only 1 byte remains → decoder returns CodecError::Truncated (I3), never reads past the buffer.

Failure-path example. A field key decodes to wire_type 6 (invalid) → decoder returns CodecError::InvalidWireType; the call fails Status::InvalidArgument; grpc-verifier increments codec_invalid_wiretype_total (ties to T1/T2).

8.3 HTTP/2 Framing & Stream Lifecycle

Frame Purpose Stream-scoped
DATA message bytes yes
HEADERS request/response/trailer headers yes
PRIORITY scheduling hint (deprioritized in modern HTTP/2) yes
RST_STREAM abort one stream yes
SETTINGS connection-wide parameters no
PING liveness / RTT sample no
GOAWAY connection draining no
WINDOW_UPDATE flow-control credit both
CONTINUATION HEADERS overflow continuation yes

Stream state table (I2):

Idle --(send/recv HEADERS, no END_STREAM)--> Open
Open --(send END_STREAM)--> HalfClosedLocal --(recv END_STREAM)--> Closed
Open --(recv END_STREAM)--> HalfClosedRemote --(send END_STREAM)--> Closed
{Open,HalfClosedLocal,HalfClosedRemote} --(RST_STREAM either side)--> Closed

8.4 gRPC Message Framing & Trailers

gRPC-Message := compressed-flag(1 byte) length(4 bytes, big-endian) payload(length bytes)

Multiple gRPC-Messages may share one DATA frame; one message may span several DATA frames (I3 governs boundary detection). Status is delivered in the final HEADERS frame (END_STREAM set):

grpc-status: <int code, §7.7's Code enum>
grpc-message: <percent-encoded text>
grpc-status-details-bin: <base64 google.rpc.Status, optional>

8.5 RPC Method Types & Call State Machine

Type Request Response Half-close
Unary 1 1 client closes after 1 message
Server-streaming 1 N client closes after 1 message; server streams then trailers
Client-streaming N 1 client streams then closes; server responds once
Bidi-streaming N N either side half-closes independently

Call state machine (client side, Phase 6/8):

CREATED -> HEADERS_SENT -> (MESSAGE_SENT)* -> HALF_CLOSED
        -> (MESSAGE_RECEIVED)* -> TRAILERS_RECEIVED -> COMPLETE

I12 requires exactly one COMPLETE transition per call, carrying exactly one Status.

8.6 Codegen Model

Schema IR → per-message Rust struct (#[prost(...)]-style tag/type attributes) + per service: a <Service>Client (static-dispatch methods, one per RPC) and a <Service> trait + <Service>Server wrapper (Phase 3, §15). The IR is language-agnostic (ADR-20); the Rust backend is the only implemented target (§37).

8.7 Deadline, Status, Metadata Wire Representation

grpc-timeout header: <1–8 ASCII digit int><unit> where unit ∈ {H,M,S,m,u,n} (hours…nanoseconds). Status.Code is the 17-value enum (§11). Reserved metadata keys (never settable by user code): :method, :scheme, :path, :authority, te, grpc-timeout, grpc-encoding, grpc-accept-encoding, content-type, grpc-message, grpc-status, grpc-status-details-bin.

Design principles (§6)

  • P1 — Transport-agnostic protocol. The wire codec and gRPC framing never reference HTTP/2 types. Violating breaks the deferred HTTP/3 addition (§37).
  • P2 — Codegen over reflection. Static dispatch via generated stubs; reflection is an ordinary sidecar service (Phase 11), never the default dispatch path. Violating costs ~200 ns/RPC (ADR-08) and loses compile-time method-signature safety.
  • P3 — Deadlines are a monotonically shrinking budget. Every hop subtracts its elapsed time before propagating. Violating causes downstream deadline overshoot (FM-2).
  • P4 — Cancellation is cooperative. Handlers poll a CancellationToken; the framework cannot force cooperation. Violating leaks resources after client abandonment.
  • P5 — Schema evolution over schema rigidity. Additive field changes are non-breaking by default; the framework lints unsafe changes at codegen time. Violating breaks rolling upgrades.
  • P6 — Canonical encoding on write, tolerant decoding on read. Our encoder always emits canonical byte order; our decoder accepts any valid protobuf field order. Violating either direction breaks either determinism (I1) or interop.
  • P7 — mTLS-first posture. Plaintext requires an explicit dev-only opt-in. Violating exposes credentials on the wire (T5).
  • P8 — Mandatory observability. Every call emits a span; no exceptions. Violating blinds on-call during incidents.
  • P9 — No global mutable state. Every Channel/Server/Interceptor takes explicit config. Violating causes hidden cross-test coupling.
  • P10 — Idempotency-gated retries. Retries fire only when the RPC declares idempotency_level permits it (I6). Violating duplicates side effects under partial failure.
  • P11 — Retry-storm defense is non-optional. The token-bucket throttle is always active. Violating amplifies outages (SRE ch. 21, FM-3).
  • P12 — Differential correctness against a reference implementation. grpc-go is the interop truth source for spec corner cases. Violating risks "correct per our reading, wrong per the ecosystem."
  • P13 — Layered interceptors, not a fixed chain. Each interceptor wraps a handler and controls invocation count. Violating blocks retry-at-the-edge and circuit-breaking patterns.
  • P14 — Fuzz-first trust boundary. Every externally-received byte sequence is adversarial until successfully decoded. Violating lets one malformed message crash a multi-tenant server (T1, T2).
