3. Architectural Overview

3.2 Subsystem Responsibilities

clients (append / read / subscribe) External callers: application services appending domain events, query services reading streams or projections, workers consuming persistent subscriptions. Trust boundary: outside the process; all input is untrusted. Speak gRPC (primary) or HTTP/1.1 JSON (secondary). Deliver EventId for idempotency. Carry no cluster state; reconnect to the leader on redirect.

esdb-server (gRPC/HTTP) Entry-point process per cluster node. Accepts inbound RPCs; multiplexes Append, Read, Subscribe, Project, Scavenge, Cluster admin commands. Concurrency boundary: tokio runtime, one task per streaming RPC. Routes non-owner appends to the partition owner via esdb-partition. Owns connection lifecycle, TLS termination, auth hook, and health/gossip endpoints. Persistence boundary: none — delegates to lower crates.

esdb-partition (route by StreamId hash to owner) Hash StreamId to a partition slot; map slot to owning node via cluster membership table. Appends routed to the Raft leader of the owning group. Reads may be served locally from a follower with a staleness caveat. Rebalancing: ownership transfer triggers catch-up replication before serving. No storage; pure routing + membership state.

esdb-stream (append w/ ExpectedVersion; optimistic concurrency check) Per-stream state machine: current EventNumber head, tombstone flag, EventId dedup ring buffer. Enforces ExpectedVersion atomically before issuing an append to esdb-log. Assigns gap-free EventNumbers. Returns AppendResult{next_expected_version, commit_position}. Concurrency boundary: one write lock per stream (short-held); reads are lock-free on committed data. No direct disk I/O — delegates to esdb-log.

esdb-replication (RAFT) Implements Raft over the global log. Leader accepts ReplicationEntry from esdb-stream, writes to its local log, fans out AppendEntries RPCs to followers. Advances commit_index once a quorum acknowledges. Followers apply entries in order. Leader election: randomized election timeouts, term-safe vote grant, pre-vote optional. Persistence boundary: durable via esdb-log (the Raft log IS the global event log). Safety: only the leader appends; followers redirect clients.

esdb-log: PER-STREAM log + GLOBAL ($all) log (segments + index, fsync) Dual-log storage engine. Per-stream log: fixed-size segment files, length-prefixed + CRC records, sequential append, segment roll-over at configured size. Global ($all) log: same segment format, records ordered by GlobalPosition, written after stream append. Index: (stream, EventNumber) → file offset; GlobalPosition → file offset. fsync after each commit (or group-commit window). Recovery: scan last segment, detect torn tail by CRC failure, truncate, rebuild index from log scan. This is the only layer that writes to disk (aside from snapshots and projection state).

esdb-snapshot (load = snap + tail) Snapshot store keyed by (StreamId, EventNumber). Writes opaque Snapshot{stream, version, state, position} blobs written by the application at chosen intervals. Aggregate load: find newest snapshot with version <= target; replay tail events from that version. Invalidation: snapshot is invalidated when the application's state schema version changes (stored alongside the blob). Separate storage path from the event log; not subject to scavenge. Persistence boundary: own segment or flat file per stream in a snapshots/ directory.

esdb-subscribe (catch-up + live, checkpointed) Subscription engine. Catch-up phase: reads historical events from esdb-log from the subscriber's from position, delivers in order. Transition to live: at log head, switch to live tail feed without gap (position fence). Volatile subscriptions: in-memory only, lost on crash. Persistent subscriptions: checkpoint position durably; on reconnect, resume from checkpoint. Competing consumers: partition delivery across a consumer group; ack/nack/park/retry. Backpressure: pause delivery when consumer ack window is full.

esdb-storage (scavenge: compact deleted streams) Online scavenge: reads segments, builds a ScavengePlan of live ranges (events not soft-deleted, not over maxcount, not expired), rewrites segments retaining only live events, preserves original EventNumbers and GlobalPositions in rewritten records, swaps index. Safety: the scavenge plan is committed before rewriting; a crash mid-scavenge resumes from the plan. Checksum verification pass precedes any scavenge. Also owns index persistence: flushes in-memory index to disk and rebuilds from log on startup if index file is stale or missing.

esdb-projection (idempotent read models, checkpointed) Projection engine. Each projection is a named {query, checkpoint, state, mode}. Registered over $all or a filtered stream. Handler is called with each event; must be idempotent. State is serialized and persisted; checkpoint is GlobalPosition of last processed event. At-least-once delivery from esdb-subscribe + idempotent handler = exactly-once effect. Rebuild: reset checkpoint to 0, replay from start. OneTime mode: run once then seal. Continuous mode: run forever, track live tail.

esdb-query (read stream / $all / by category / projection) Read-path façade. ReadStream(stream, from, direction, count) → ReadResult. ReadAll(from, direction, count, filter) → ReadResult over $all. Category reads: filter by StreamId prefix. Event-type reads: filter by event_type field. Projection state reads: return last-checkpointed state blob. Consistent reads: read-your-writes guarantee on the leader; followers expose a min_position staleness parameter. Paging: next cursor + is_end flag.

8. Domain Model

8.1 Entity Taxonomy

Entity Crate Key Mutable? Notes
StreamId esdb-core string (e.g. "order-1234") No category = prefix before first '-'
EventId esdb-core Uuid v4/v7 No idempotency key; globally unique
EventNumber esdb-core u64, zero-based No per-stream, gap-free
GlobalPosition esdb-core u64, monotonic No commit position in $all log
EventRecord esdb-event (stream, number, position) No immutable once committed
Snapshot esdb-snapshot (stream, version) Replaced newer snapshot supersedes older

Checkpoint esdb-projection / esdb-subscribe subscription or projection id Updated advancing; never decreasing
ReplicationEntry esdb-replication (term, position) No Raft log entry

8.2 Event Record Layout (wire + storage)

EventRecord on-disk frame (length-prefixed, inside segment):
  [frame_len: u32 LE]
  [crc32c: u32]
  [version: u8]          # envelope version
  [flags: u8]            # 0x01 = tombstone, 0x02 = snapshot
  [event_id: 16 bytes]   # UUID bytes
  [stream_len: u16 LE]   # byte length of stream id
  [stream: variable]
  [number: u64 LE]       # EventNumber
  [position: u64 LE]     # GlobalPosition (0 = not-yet-assigned in WAL)
  [event_type_len: u16 LE]
  [event_type: variable] # UTF-8 string
  [content_type: u8]     # 0=binary, 1=json, 2=avro, 3=proto
  [created_ns: u64 LE]   # Unix nanos
  [metadata_len: u32 LE]
  [metadata: variable]   # Bytes (opaque; structured e.g. causation-id, correlation-id)
  [data_len: u32 LE]
  [data: variable]       # Bytes (opaque payload)

Alignment: none required; CRC covers bytes from version through end of data. Torn write detection: frame_len read first; if segment tail < frame_len, truncate.

8.3 Index Layout

Two independent index structures per log (stream-log and global-log):

Stream index: (StreamId, EventNumber) -> (segment_id: u32, byte_offset: u64)
Global index: GlobalPosition          -> (segment_id: u32, byte_offset: u64)
Category index: category (StreamId prefix) -> sorted list of GlobalPositions
EventType index: event_type string -> sorted list of GlobalPositions

On-disk index file per segment: sorted array of fixed-size index entries.

IndexEntry (stream): [stream_hash: u64][number: u64][segment: u32][offset: u64] = 28 bytes
IndexEntry (global): [position: u64][segment: u32][offset: u64] = 16 bytes

Index rebuilt from segment scan on crash recovery (P8).

8.4 Stream State Machine

States: NonExistent | Active | Deleted (soft) | Tombstoned (hard)

Transitions:
  NonExistent  --[append, ExpectedVersion::NoStream]--> Active
  NonExistent  --[append, ExpectedVersion::Any]--> Active
  NonExistent  --[append, ExpectedVersion::Exact(n)]--> Error(WrongExpectedVersion) if n != 0
  Active       --[append, ExpectedVersion::Exact(n)]--> Active  (n == current_version)
  Active       --[append, ExpectedVersion::Exact(n)]--> Error(WrongExpectedVersion) if n != current_version
  Active       --[soft-delete cmd]--> Deleted
  Active       --[tombstone cmd]--> Tombstoned
  Deleted      --[scavenge]--> events removed, metadata retained
  Deleted      --[append]--> Error(StreamDeleted)
  Tombstoned   --[append]--> Error(StreamDeleted)
  Tombstoned   --[read]--> Error(StreamDeleted)

8.5 Optimistic Concurrency — ExpectedVersion Semantics

ExpectedVersion Accept condition Reject condition
Any always never
NoStream stream state == NonExistent stream exists (any events present)
StreamExists stream state == Active stream does not exist
Exact(n) current last EventNumber == n any other last version

Atomicity: version check and EventNumber assignment occur in a single write-lock scope within esdb-stream; no observer can see a partial batch.

8.6 Global Log and Commit Position

Prepare position: byte offset where the event was staged in the stream WAL.
Commit position:  GlobalPosition assigned when all events in a transaction reach quorum.

$all log ordering invariant (I3):
  for any two commits C1 < C2: C1.position < C2.position and C1 is visible before C2.

Position 0 is reserved; first committed event has position >= 1.

Position delta used as lag metric: head_position - checkpoint.position (P10).

8.7 Replication Log Entry

ReplicationEntry layout:
  term: u64          # Raft term when entry was created by leader
  position: u64      # GlobalPosition of this event
  stream: StreamId
  number: EventNumber
  payload_ref: u64   # byte offset in the per-stream log (avoids double-storing)

Leader appends to esdb-log, then replicates entry to followers. Follower applies by writing the entry locally. Commit index advances when match_index[i] >= entry.index for a quorum of nodes.

8.8 Snapshot State Machine

States: None | Valid | Stale (schema_version mismatch)

Transitions:
  None  --[periodic checkpoint]--> Valid(version=N, state=Bytes)
  Valid --[new snapshot at version M > N]--> superseded (retain M only)
  Valid --[schema_version bump in projection]--> Stale
  Stale --[aggregate load]--> ignored; fallback to full replay from 0

Load algorithm:

  1. Fetch newest Snapshot where version <= target_version and schema_version == current.
  2. If found: deserialize state; replay tail events [snapshot.version+1 .. target].
  3. If not found: replay from EventNumber 0.

Invariant I9: result is identical to full replay.

8.9 Subscription State Machine

States: Created | CatchingUp | Live | Paused | Terminated

Transitions:
  Created    --[subscribe(from_position)]--> CatchingUp
  CatchingUp --[reached log head]--> Live (atomic with last batch delivery)
  Live       --[new committed event]--> Live (push event to consumer)
  Live       --[consumer backpressure]--> Paused
  Paused     --[consumer ready]--> Live or CatchingUp (if gap accumulated)
  Live       --[unsubscribe / error]--> Terminated
  CatchingUp --[unsubscribe / error]--> Terminated

Catch-up/live boundary: read up to head_position in CatchingUp; atomically register live listener; flush any events that arrived during final read; transition to Live with no gap and no duplicate.

8.10 Projection State Machine

States: Idle | Running | Faulted | Stopped | Rebuilding

Transitions:
  Idle      --[start]--> Running
  Running   --[handler panic / serialization failure]--> Faulted
  Faulted   --[admin restart]--> Running
  Running   --[admin stop]--> Stopped
  Stopped   --[admin start]--> Running
  Running   --[admin rebuild]--> Rebuilding (reset checkpoint to 0)
  Rebuilding --[replayed to head]--> Running

Checkpoint write: after each batch of events; durably before acknowledging. Idempotency: handler applied to the same event at the same checkpoint position yields the same read-model mutation (I8).

8.11 Scavenge Plan and Compaction

ScavengePlan:
  scavenge_id: Uuid
  segments: Vec<(segment_id, live_bitmap: RoaringBitmap)>
  initiated_at: u64  # unix nanos
  status: Planned | Running | Complete | Aborted

Live-bitmap maps record slot indices within a segment to keep/drop. Scavenge rewrites each segment in-place to a new file with only live records; positions and EventNumbers of surviving events are preserved (I10). Deleted stream marker kept; $all positions remain monotonic (gaps become tombstone-markers in $all reads).

8.12 Partition Routing Model

partition_id = fnv1a64(stream_id.bytes) % num_partitions
owner_node   = partition_table[partition_id]

Routing table broadcast via cluster gossip. Write path: client -> any node -> route to owner -> append locally -> Raft replication within partition group. $all across partitions: merge-sort by GlobalPosition using per-partition cursors (not guaranteed globally contiguous; partitions have independent position spaces unless using a global position arbiter — ADR-23).

8.13 Worked Example — Happy-Path Append

Client:  Append("order-1234", ExpectedVersion::Exact(2), [e3, e4])
  -> esdb-server: route to owner node for "order-1234"
  -> esdb-stream: acquire write lock on "order-1234"
     read current last EventNumber = 2  (matches Exact(2))
     assign e3.number=3, e4.number=4
     write to per-stream segment: [frame(e3), frame(e4)] + fsync
  -> esdb-log: assign GlobalPosition 901 to e3, 902 to e4
  -> esdb-replication: create ReplicationEntry{term=7, position=901, ...}, {902, ...}
     replicate to 2/3 followers; advance commit_index to 902
  -> AppendResult{next_expected_version: EventNumber(4), commit_position: GlobalPosition(902)}

8.14 Failure-Path Example — Optimistic Concurrency Conflict

Concurrent writers W1 and W2 both read last version = 5:
  W1: Append("acct-99", ExpectedVersion::Exact(5), [debit])  -> accepted, assigns version 6
  W2: Append("acct-99", ExpectedVersion::Exact(5), [credit]) -> rejected
      Error: WrongExpectedVersion { stream: "acct-99", expected: Exact(5), actual: 6 }
W2 must re-read stream, reconcile, retry with ExpectedVersion::Exact(6).
No partial write from W2 is observable.  Invariant I5 holds.

8.15 Edge Cases and Invariant Stress Points

Edge Case Invariant Handling
Re-append same EventId I6 dedup map (stream -> Set<EventId>); return original AppendResult
Append 0 events I4 no-op; return current AppendResult immediately
ExpectedVersion::NoStream on existing stream I5 WrongExpectedVersion
Torn segment tail on crash P8/I4 truncate to last complete + CRC-verified frame
Follower ahead of leader (stale leader) I7 leader rejects its own appends when it sees higher term
Snapshot schema_version mismatch I9 Snapshot marked Stale; full replay forced
Scavenge on active stream I10 scavenge skips live tombstone events; positions preserved
Catch-up/live race I3 final catch-up batch under log-head latch; no duplicate delivery
EventNumber gap after crash I2 replay segment from base; reject writes with non-contiguous number
Projection handler panics I8 transaction rolled back; checkpoint not advanced; retry
Partition rebalance mid-append — old owner rejects after ownership transferred; client retries
$all read crossing partition boundary I3 merge-sort cursor; position monotonicity guaranteed per-partition
Competing consumers double-deliver — ack required before removal from pending; nack -> requeue
Stream tombstone with pending snapshot I10 snapshot deleted; tombstone written to $all; scavenge clears data frames

                event_type_field content_type created_ns metadata_field data_field

8.18 Raft State Transition (condensed)

Role transitions:
  Follower  --[election timeout, no heartbeat]--> Candidate
  Candidate --[votes received from quorum]--> Leader
  Candidate --[higher term seen]--> Follower
  Candidate --[election timeout again]--> Candidate (new term)
  Leader    --[higher term seen]--> Follower
  Leader    --[quorum unreachable]--> stays Leader until step-down timeout

Leader invariants:
  - AppendEntries sent every heartbeat_interval (< election_timeout_min)
  - Only appends with term == current_term
  - commit_index advances only when match_index[quorum] >= entry_index

8.19 Competing Consumers Protocol

Persistent subscription group G has N consumers C1..CN:
  Available event delivered to exactly one consumer (round-robin or least-pending).
  Consumer must Ack(event_id) within ack_timeout.
  On Nack(event_id, action=Retry): event re-queued after nack_sleep_ms.
  On Nack(event_id, action=Park):  event moved to parked queue; no retry.
  On timeout:                      event treated as Nack(Retry); retry_count++.
  On retry_count > max_retries:    auto-park.

Group checkpoint = min(acknowledged_position across all consumers).
Parked queue accessible via admin API; replay on demand.

State tracked per in-flight event:

Field Type Notes
event_id Uuid correlates Ack/Nack to delivery
position GlobalPosition for checkpoint advancement
consumer_id NodeId which consumer holds it
delivered_at u64 nanos timeout base
retry_count u16 park threshold

8.20 Backpressure Model

Layer 1 (transport): gRPC server-side streaming flow control; H2 window.
Layer 2 (subscription channel): bounded async channel (capacity = high_water_mark).
  Producer (catch-up reader or live pusher) blocks when channel full.
Layer 3 (consumer ack window): max_in_flight events; producer pauses at limit.

Metrics:
  subscription_lag_events: head_position - checkpoint.position
  subscription_channel_fill_ratio: len / capacity
  consumer_ack_pending: current in-flight count

Slow consumer effect: catch-up reader slows I/O read rate proportionally; live events queue in bounded channel; producer signals Paused to log reader.

8.21 Event Type Versioning

Strategy Mechanism Invariant
Up-cast projection handler maps old event_type to new shape I8: same replay result
New type new event_type emitted alongside old; handler handles both I1: old records unchanged
Schema hash in metadata schema_version key in metadata Bytes (JSON or custom) snapshot stale detection (§8.8)
Content-type negotiation content_type byte in frame (json/avro/proto) reader selects deserializer

Projection rebuild triggered on schema_version bump: reset checkpoint to 0, replay from beginning (P9, I8).

8.22 Category Stream Semantics

$category-<C> is a virtual stream containing all events from streams where
  category(stream_id) == C.
  category("order-1234") = "order"
  category("order")      = "order"   (no '-' -> whole name is category)
  category("acct-99-sub") = "acct"   (first '-' is the delimiter)

$all is a virtual stream: all events across all streams in commit order.
$et-<T> is a virtual stream: all events with event_type == T in commit order.

Virtual streams are served by index lookup (category/event-type secondary indexes),
not by storing a separate log. Phase 5 Read API builds these with server-side filter.

8.25 Position Semantics — Prepare vs Commit

Position type When assigned Durability Used by
Prepare position when event enters stream WAL buffer NOT durable alone internal staging only
Commit position (GlobalPosition) when quorum ack received quorum-durable (I7) subscriptions, projections, replication cursor, $all reads

Clients only receive GlobalPosition in AppendResult. Subscriptions and projections cursor only on committed positions. Prepare positions are internal to the log write path.

8.27 Failure Mode Interaction Matrix

Failure Invariant at Risk Detection Recovery
Torn segment write I4, I2 CRC mismatch or frame_len overrun at tail truncate to last valid frame; rebuild index from base
Index file corruption I2, I3 checksum on index file header delete index file; rebuild from segment scan on startup
Leader crash mid-replicate I7 quorum absent; new election new leader has all committed entries; uncommitted entries discarded
Double-append same EventId I6 EventId dedup map in esdb-stream return original AppendResult; no new frame written
