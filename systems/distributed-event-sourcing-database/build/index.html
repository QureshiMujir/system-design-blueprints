⬜ Phase 2 — append-only segment log + index

Objectives
  • Implement esdb-log: the durable, append-only, crash-safe log underlying both per-stream and global logs.
  • Fixed-size segment files; length-prefixed + CRC records; fsync on commit; segment roll-over at size threshold.
  • Build dual indexes: (StreamId, EventNumber) → file offset and GlobalPosition → file offset.
  • Sequential append path; sequential and random read paths.
  • Crash recovery: scan last segment, detect torn write by CRC/length mismatch, truncate tail, rebuild in-memory index from last good position.
  • Establish WAL ordering: write-then-fsync before acknowledging.
Deliverable
  • esdb-log crate compiles and passes all tests.
  • Log::append + Log::read_stream + Log::read_all callable from integration test.
  • Crash simulation test: kill process mid-write, re-open, verify no torn record visible.
  • Segment roll-over verified: writing past MAX_SEGMENT_SIZE creates new segment file.
  • Index rebuild verified: delete in-memory state, reopen, all reads return same data.

⬜ Phase 3 — stream append + optimistic concurrency

Objectives
  • Implement esdb-stream crate: the per-stream state machine governing append atomicity and versioning.
  • append(stream, expected_version, events) -> AppendResult enforces ExpectedVersion atomically.
  • Assign gap-free EventNumbers starting at 0; disallow skips or reuse.
  • WrongExpectedVersion error on version mismatch; surface stream identity in error.
  • Idempotent re-append: detect duplicate EventIds; return original AppendResult without writing.
  • Soft-delete tombstone: delete_stream(stream) appends a system event; subsequent appends to a tombstoned stream return StreamDeleted. Backed by esdb-log (Phase 2) for persistence.
Deliverable
  • esdb-stream compiles; StreamEngine::append + delete_stream + read_stream all callable.

  • Idempotency test: append the same batch twice — log contains the events once, both calls return the same AppendResult. Tombstone test: delete stream then attempt append — StreamDeleted returned, no new records in log.

⬜ Phase 4 — Global Log + Commit Positions

Objectives
  • Implement the $all global log in esdb-log: every committed event receives a unique monotonic GlobalPosition(u64).
  • Define commit/prepare position semantics: prepare = offset at which leader proposes; commit = position assigned after quorum (in later phases), single-node = same value.
  • Make GlobalPosition the universal cursor for subscriptions, projections, and replication.
  • Guarantee I3: positions strictly increasing, unique, assigned at commit time, never reused.
  • Expose global_log::append(entry) -> GlobalPosition and global_log::read_from(pos, limit) -> Vec<EventRecord>.
Deliverable
  • GlobalLog compiles, appends entries, assigns monotonic positions, fsyncs to disk, reads back in commit order.
  • Single-node integration test: append 10 000 events via esdb-stream, verify all appear in $all read with strictly increasing positions and correct EventRecord fields.
  • global_index rebuilt from segments after simulated crash (truncated last segment).

⬜ Phase 6 — Snapshots + Aggregate Load

⬜ Phase 7 — Subscriptions (Catch-Up + Live)

Objectives
  • Implement esdb-subscribe crate: catch-up from any GlobalPosition, seamless transition to live delivery, no gap or duplicate at the boundary. Two subscription kinds: Volatile (in-memory, lost on restart) and Persistent (checkpointed, resumes across restarts). Filter dimensions: single stream by StreamId, stream category (prefix match), event-type, or $all.
  • Backpressure: a slow consumer must not block the log or other subscriptions — bounded channel with configurable capacity, apply/park semantics. Produce Subscription and Checkpoint types; integrate with esdb-log's global position cursor and esdb-stream's per-stream reader.
Deliverable
  • SubscriptionManager::subscribe(req) -> SubscriptionHandle compiles and passes integration tests; catch-up replays all matching historical events then delivers live events without gap or duplicate.
  • Persistent subscriptions survive process restart and resume from the last checkpoint; competing-consumer round-robin distributes across N consumers with ack/nack/park all functioning; saturating a consumer channel pauses catch-up reads without blocking other subscriptions.

⬜ Phase 8 — Projection Engine (Read Models)

Objectives
  • Implement esdb-projection crate: register a named projection over $all or a category; an idempotent handler folds EventRecord into mutable read-model state, checkpointing position durably. At-least-once delivery from esdb-subscribe is made exactly-once-effect via handler idempotency (pure w.r.t. duplicate positions) + durable checkpoint.
  • Two modes: Continuous (runs perpetually, stays live) and OneTime (runs to current head then stops). Rebuild: reset checkpoint to 0, re-register with the Phase 7 catch-up subscription → identical final state (I8). No implementation source code in projection handlers (user-supplied closures) — the engine only manages lifecycle, state storage, and checkpointing.
Deliverable
  • ProjectionEngine::register(def) -> ProjectionHandle runs catch-up then stays live for Continuous projections; state is queryable via ProjectionEngine::read_state(name) -> Bytes at any time.
  • ProjectionEngine::rebuild(name) resets checkpoint, re-replays, and yields an identical final state; OneTime projections stop at head, mark Stopped, and return the final state.
  • Checkpoint survives crash; projection resumes from the last checkpointed position.

⬜ Phase 9 — Persistence Hardening + Scavenging

Objectives
  • Harden esdb-storage + esdb-log: crash recovery via torn-write truncation and index rebuild from log; checksum verification on every read.
  • Soft-delete streams (tombstone marker in log); scavenge (compaction) removes events from deleted, expired, or maxcount-exceeded streams.
  • Scavenge rewrites segment files, preserving EventNumber and GlobalPosition semantics for all surviving events (I10).
  • Online scavenge: runs without stopping appends or reads; uses generation markers to keep current readers on old segments until swap.
  • Deliver ScavengePlan introspection: operator can preview which events will be removed before committing.
Deliverable
  • A crashed node recovers cleanly: torn tail truncated, index rebuilt, all committed events readable.
  • Every read verifies CRC; corrupted segment returns ChecksumMismatch not silent bad data.
  • delete_stream appends tombstone; subsequent appends/reads return StreamDeleted.
  • ScavengePlanner::plan returns inspectable ScavengePlan before any mutation.
  • Executed scavenge removes targeted events; all surviving events readable at original numbers and positions.
  • Online scavenge does not block concurrent appends or reads.

⬜ Phase 10 — Raft replication of the global log

Objectives
  • Wrap every committed event as ReplicationEntry { position, term, event_record } in esdb-replication.
  • Leader appends entries to its local esdb-log then replicates via AppendEntries RPC to all followers.
  • Commit index advances when a quorum of match_index values reach or exceed the entry's index.
  • Followers apply entries in order to their own esdb-log; follower log is identical to leader post-commit.
  • Only the leader accepts client appends; followers reject or redirect (I7, P6).
  • Log matching property: if two logs share an entry at (index, term), all prior entries are identical.
Deliverable
  • 3-node cluster where every committed append via leader is durably reflected on all three nodes' esdb-log.
  • cargo test -p esdb-replication passes: single-leader commit, quorum commit with one follower lagging, append rejection on follower.
  • Metric endpoint exposes replication_lag_entries{peer=...} and commit_latency_ms histogram.

Pitfalls
  • Stale match_index after reconnect: follower was partitioned; leader's next_index is stale; fix: decrement next_index on AppendEntries failure, binary-search rollback. Signal: replication_lag_entries spike.
  • Committed entry overwritten on follower: follower has higher-term entries from a previous brief leadership; truncation in AppendEntries handler must check term, not just index. Signal: CRC mismatch on apply.
  • Leader applies before quorum: advancing last_applied before commit_index is reached; fix: strict last_applied ≤ commit_index. Signal: client sees event that is later lost on failover.
  • Unbounded in-flight AppendEntries: pipeline without back-pressure fills TCP buffers; fix: limit per-peer in-flight count to max_pipeline (default 8). Signal: memory growth on leader.
  • Clock-skew election storm: election timeouts smaller than network RTT; fix: randomise in [150 ms, 300 ms], assert heartbeat_interval < min_election_timeout / 2.
