⬜ Phase 1 — Tensor + local-training substrate §12

Objectives

Build fl_tensor (NumPy-backed Tensor + minimal reverse-mode autograd, ModelState, fixed-point quantize/dequantize to Z_R, deterministic byte codec), fl_data (shards, IID/non-IID partitioner, LocalLoader, n_u), and fl_client local training (SGD/Adam → weight-delta Δ_u or gradient). Lock the model wire layout (I15, P4) and the randomness faucet usage (P2). This is the numerics foundation everything trains on.

Deliverable

Train a small model locally on a shard; produce a Δ_u; quantize→dequantize round-trips within tolerance; ModelState serializes byte-identically across processes; pytest packages/fl_tensor packages/fl_data packages/fl_client green.

Acceptance
  • Autograd: numerical-gradient check passes (finite-difference vs backward()) with max relative error < 1e-5 on each op (fixture tensor/gradcheck.json).
  • Local training reduces toy-dataset loss by ≥ 50% over 20 epochs at lr=0.01 (sanity convergence).
  • quantize/dequantize unbiased under stochastic rounding: mean error < 1e-3 over a 10⁴-element vector; deterministic under fixed seed.
  • to_bytes→from_bytes is identity for 100% of round-trips; byte layout stable across runs/machines (I15).
  • Dirichlet(α=0.1) partition reproduces the same split for a fixed seed; Σ n_u equals the dataset size exactly.
Fixtures
Fixture Purpose Expected
tensor/gradcheck.json autograd correctness max rel-err < 1e-5
tensor/codec_roundtrip.json I15 byte-exact
tensor/quant_unbiased.json §8.3 E[error] ≈ 0
data/dirichlet_repro.json non-IID determinism identical split per seed
Pitfalls
  • Float nondeterminism (BLAS thread order, fma) breaks byte-exact model agreement; pin dtype, avoid order-dependent reductions where wire-exactness is required (I15).
  • Quantization without stochastic rounding biases the FedAvg mean (systematic drift) — keep it unbiased (§8.3).
  • Sharing one shuffle seed across clients correlates "independent" local randomness (P2).
  • Delta vs gradient confusion: mixing Δ_u (post-E-epochs) with a single gradient changes FedAvg semantics; pick one per campaign and record it.

⬜ Phase 2 — Server coordinator + round orchestration §13

Objectives

Build fl_server: client registration, cohort sampling (uniform/importance, rate q), the global-model store with monotonic version (I11), the round lifecycle FSM (SELECT→BROADCAST→LOCAL-TRAIN→COLLECT→AGGREGATE→UPDATE, P7, P14), per-round deadlines, straggler policy, and partial-participation bookkeeping. No privacy yet — aggregation is cleartext sum here; SecAgg layers on in Phase 5–7.

Deliverable

Server runs N cleartext rounds against simulated clients: selects a cohort, broadcasts the model, collects updates until a deadline, averages, bumps version; RoundReport emitted per round; pytest packages/fl_server green.

Acceptance
  • Cohort sampling hits rate q (size = round(qN)); reproducible under a fixed seed; no duplicates.
  • FSM advances only on guard satisfaction; never AGGREGATEs before the deadline/barrier (P7, I10).
  • Stale-version updates rejected (I11); survivor/dropped counts correct under injected dropout.
  • run_campaign stops at the round limit; RoundReports show monotonic version.
Fixtures
Fixture Purpose Expected
server/cohort_rate.json sampling size = round(qN), unique
server/fsm_order.json P7 states in canonical order
server/stale_reject.json I11 stale update rejected
server/dropout_counts.json straggler survivors+dropped = cohort
Pitfalls
  • Aggregating before the barrier yields a partial mean over early clients (bias toward fast clients) — enforce the deadline/barrier (P7).
  • Importance sampling without correcting weights biases the aggregate; keep FedAvg weights consistent with the sampling (I12).
  • Forgetting to pin the model version lets clients train against mixed versions → inconsistent aggregation (I11).
  • Over-provisioning without a survivor target wastes downlink; size the cohort to t + margin for SecAgg later.

⬜ Phase 3 — FedAvg aggregation §14

Objectives

Build fl_aggregate: FedAvg sample-count-weighted averaging (McMahan 2017, I12), FedProx (proximal μ), FedAdam/FedYogi server-side adaptive optimizers (Reddi 2020), convergence tracking, and the AggregationRule interface. The server now produces a principled global step from collected updates.

Deliverable

FedAvg/FedProx/FedAdam selectable; a campaign converges on a toy non-IID task; convergence curve recorded; pytest packages/fl_aggregate green.

Acceptance
  • FedAvg equals the exact sample-weighted mean (vs a centralized reference on the same data) within float tolerance (I12).
  • FedProx with μ>0 reduces client-drift variance vs μ=0 on a skewed split.
  • FedAdam converges in ≤ FedAvg rounds-to-target on the benchmark task (or matches, never diverges).
  • Weight-sum assertion Σ n_u/n = 1 holds every round.
Fixtures
Fixture Purpose Expected
aggregation/fedavg_exact.json I12 == weighted mean
aggregation/fedprox_drift.json μ effect lower drift
aggregation/fedadam_step.json §8.2 matches optimizer math
aggregation/weight_sum.json I12 Σ weights = 1
Pitfalls
  • Equal-weight averaging when shards differ in size biases toward small clients — use n_u weighting (I12).
  • FedAdam state must persist across rounds on the server; resetting it each round kills adaptivity.
  • Mixing model-averaging and delta forms inconsistently double-applies the global model.
  • Under SecAgg, the server only has summed quantities — never normalize using a single client's n_u (P1).

⬜ Phase 4 — Communication layer §15

Objectives

Build fl_transport: a Transport interface (send/recv/broadcast), in-proc channels (simulator) and gRPC/protobuf network transport, chunking for large models, compression codecs (uniform/stochastic quantization, top-k sparsification, random masking), and bandwidth/round accounting (P9, I10, I15). Communication is the FL bottleneck; this phase makes it measurable and cheap.

Deliverable

Server↔clients exchange chunked, compressed models/updates in-proc and over gRPC; identical message sequences both ways; comm stats reported; pytest packages/fl_transport green.

Acceptance
  • In-proc and gRPC deliver byte-identical message sequences for the same campaign (100% parity, fixture transport/inproc_vs_grpc.json).
  • CommStats counts bytes/rounds per client exactly (0 discrepancy vs a manual byte count, P9).
  • Top-k(k=10%) reduces uplink bytes to ≈ 0.1× baseline with accuracy loss < 1% vs uncompressed, recovered within 5 rounds by error feedback.
  • Model > 4 MiB → chunked per the §4.1 threshold; a message exceeding the configured per-message size cap → rejected (Malformed); chunk reassembly is order-independent + checksum-verified.
Fixtures
Fixture Purpose Expected
transport/inproc_vs_grpc.json parity identical sequence
transport/comm_stats.json P9 exact bytes/rounds
transport/topk_bytes.json compression bytes ≈ (1−k%)
transport/chunk_reassemble.json chunking byte-exact, any order
Pitfalls
  • Quantization in the codec must agree with the SecAgg ring Z_R (Phase 5) — diverging quantization breaks mask cancellation (P4, I6).
  • Top-k changes which coordinates each client sends; SecAgg masks the full vector, so sparsification under SecAgg needs a shared support or full-length masking (documented constraint).
  • Unbounded streaming buffers OOM under a large cohort; bound + backpressure.
  • Forgetting error feedback makes sparsification biased (dropped coordinates never sent).

⬜ Phase 5 — Pairwise masking (secure-aggregation core) §16

Objectives

Build the fl_crypto primitives (SecureRng/TranscriptRng, X25519 DH, AES-CTR/ChaCha20 PRG → Z_R^m, ring add/sub, KDF) and fl_secagg pairwise masking (Bonawitz core): per-pair seed s_{u,v}=KA(s_u^{SK},s_v^{PK}), PRG-expanded mask, and the masked input y_u whose pairwise terms cancel in the exact sum (§8.4, I1, I5, P2, P4). Single-round secure sum with no dropout yet.

Deliverable

N clients each mask a quantized vector; the server sums masked inputs and recovers the exact vector sum (no dropout); pytest packages/fl_crypto packages/fl_secagg::mask green; examples/secure_sum.py runs.

Acceptance
  • Σ_u y_u mod R == Σ_u x_u mod R for a cohort of ≥ 2 with all clients present (I1) — bit-exact vs cleartext sum over 1000 random trials.
  • DH symmetry holds for all pairs (I5); PRG output passes a chi-square goodness-of-fit test for uniformity in Z_R at p > 0.01 (fixture masking/prg_uniform.json).
  • The server's view (the y_us) is statistically independent of any individual x_u given the others: mutual information estimate < 1e-3 bits over 1000 trials (masking hides individuals) — leakage test.
  • Seeded TranscriptRng reproduces bit-identical masks across 2 runs at the same seed; prod_rng refuses a seed 100% of the time (I7).
Fixtures
Fixture Purpose Expected
masking/cancel_exact.json I1 Σ y == Σ x (mod R)
masking/dh_symmetry.json I5 seeds equal both sides
masking/prg_uniform.json PRG uniform in Z_R
masking/individual_hidden.json P3 y_u ⟂ x_u given rest
Pitfalls
  • Sign/order disagreement (u<v convention) leaves a residual ±2·PRG(s_uv) and corrupts the sum (P4, I1) — fix a single canonical ordering.
  • PRG modular bias (mapping a keystream to Z_R by truncation when R∤2^k) skews masks; use rejection sampling or a large reduction.
  • Ring too small → the true sum wraps and the aggregate is garbage (I6); size R from cohort × max-quantized.
  • Reusing a seed across rounds reuses masks → differencing attack reveals updates (P2); fresh keys per round.
  • Using numpy.random for any seed is insecure in prod (I7, P2).

⬜ Phase 6 — Dropout recovery via Shamir secret sharing §17

Objectives

Add double-masking (per-client self-mask PRG(b_u)) and t-of-n Shamir secret sharing (cross-link 379) of each client's self-mask seed b_u AND its pairwise secret key s_u^{SK}, so the server can reconstruct dropped clients' pairwise masks and surviving clients' self-masks — never both for the same client (§8.5, I2, I3, P5, P6). Shares are encrypted peer-to-peer (I16). Resolves the dropped-vs-slow ambiguity.

Deliverable

A secure sum completes correctly with injected dropout: the server recovers Σ_{u∈U} x_u after reconstructing dropped keys + surviving self-masks; pytest packages/fl_crypto::shamir packages/fl_secagg::recover green; examples/secagg_dropout.py runs.

Acceptance
  • For cohort=100, t=50: up to 49 dropouts still yield unmask == Σ_{u∈U} x_u bit-exact vs cleartext (I1, §8.10).
  • Shamir: any t+1 of n shares reconstruct 100% of trials; any ≤ t shares are statistically indistinguishable from random (I3, marginal-uniformity test, p > 0.01).
  • For every client in 100 sampled rounds the server obtains exactly one of {b_u, s_u^{SK}} — zero both-kind reconstructions (reconstruction audit, I2).
  • A "slow" client (its y_u present but declared dropped) cannot be unmasked in any of 100 injected-equivocation trials — its self-mask survives (P5).
Fixtures
Fixture Purpose Expected
sharing/shamir_threshold.json I3 any t+1 reconstruct
sharing/shamir_privacy.json I3 ≤t shares uniform
protocol/dropout_recover.json §8.5 unmask = Σ_U x_u
protocol/one_kind_per_client.json I2 exactly one of {b,sSK}
Pitfalls
  • Reconstructing both b_u and s_u^{SK} for a client unmasks it — the single most dangerous bug; enforce one-kind-per-client at the client, not just the server (I2, P5).
  • Lagrange over integers instead of mod the ring/field gives wrong reconstruction; all arithmetic in Z_R/F_p.
  • Off-by-one on the threshold (t vs t+1) silently weakens privacy or breaks reconstruction (I3, P6).
  • Sending shares unencrypted lets the server read them and reconstruct everything (I16) — encrypt peer-to-peer.
  • Pairwise key reconstruction must recompute the dangling masks only (dropped↔survivor), not survivor↔survivor (already cancelled).

⬜ Phase 7 — Secure-aggregation protocol orchestration §18

Objectives

Assemble the 4-round SecAgg protocol (R0 AdvertiseKeys → R1 ShareKeys → R2 MaskedInputCollection → R3 Unmasking + ConsistencyCheck, §8.6) end-to-end over fl_transport, with per-round survival thresholds (I4), Ed25519 signatures on keys, a consistency check so a malicious-ish server cannot equivocate about who dropped (I9, P5), and abort conditions that fail loud before any unmasking (P7, P8). Wire SecAgg into the server's COLLECT/AGGREGATE.

Deliverable

A full private FL round: cohort runs R0–R3, server obtains only the aggregate, dropout tolerated, equivocation rejected; pytest packages/fl_secagg green; fl_sim runs a SecAgg campaign with injected dropout.

Acceptance
  • For cohort=100, t=50: end-to-end round outputs Σ_{u∈U2} x_u (bit-exact vs cleartext over survivors, I1) across the full 0–49 dropout range.
  • Server view across 100 sampled rounds is simulatable from the aggregate (+ ≤t colluders' inputs) — sim-vs-view audit passes 100% of trials (I8, P3).
  • Equivocation (server tells different clients different dropout sets) → consistency check fails and aborts in 100% of 50 injected trials (I9).
  • Any round with < t+1 survivors at any of the 4 SecAgg sub-rounds → abort with no unmasking, verified across all 4 (I4, P8).
Fixtures
Fixture Purpose Expected
protocol/full_round.json I1,I8 aggregate correct, view simulatable
protocol/equivocation.json I9 abort on mismatched (U,D)
protocol/subthreshold_abort.json I4 abort, no unmask
protocol/sig_verify.json R0/R3 bad sig rejected
Pitfalls
  • Skipping the consistency check lets a server learn an individual by telling everyone except the victim that the victim dropped (it would then collect the victim's s^{SK} shares as "dropped" while the victim's y is present) — the self-mask + consistency check together prevent this (P5, I9).
  • Advancing a round on a timeout without rechecking the survival threshold can unmask a tiny set → individual leakage (I4, P8).
  • Reusing DH keys across rounds enables cross-round differencing; fresh keys each round (P2).
  • Not verifying R0 signatures lets the server inject fake public keys (man-in-the-middle on seeds) — verify (I9).
  • Consuming R2 messages before R1 routing completes desyncs share availability (I10, P7).

⬜ Phase 8 — Differential privacy §19

Objectives

Build fl_dp: per-example L2 clipping to bound sensitivity to C (I14), the Gaussian mechanism N(0,σ²C²I), DP-SGD (Abadi 2016), client-level vs example-level DP, central vs local DP, and the distributed-noise-under-mask helper so the aggregate carries central-quality noise with no trusted noiser (§8.7, P11). DP bounds what the (visible) aggregate leaks; SecAgg hides individuals — complementary (P11).

Deliverable

A DP-FedAvg campaign: clients clip + (distributed-)noise updates; the aggregate is DP; accuracy/ε tradeoff recorded; pytest packages/fl_dp green; examples/dp_fedavg.py runs.

Acceptance
  • Post-clip per-record L2 norm ≤ C for 100% of records, verified over 10⁴ sampled gradients (I14).
  • Aggregate noise distribution matches N(0,σ²C²I): sample mean within 0.01σC of 0, sample variance within 5% of σ²C² over 10³ trials — KS-test statistical check.
  • Distributed-noise-under-mask: post-unmask aggregate noise variance within 5% of the central-DP target σ²C² (not |U|× too small/large).
  • Example-level vs client-level produce the documented different sensitivities: example-level uses C per record, client-level uses C per whole Δ_u — verified by two distinct fixtures in dp/levels.json.
Fixtures
Fixture Purpose Expected
dp/clip_norm.json I14 ‖ḡ‖ ≤ C
dp/gaussian_var.json mechanism var ≈ σ²C²
dp/distributed_noise.json §8.7 post-unmask var ≈ σ²C²
dp/levels.json sensitivity example vs client correct
Pitfalls
  • Clipping after averaging (instead of per-record before summing) breaks the sensitivity bound → invalid DP (I14).
  • Continuous Gaussian noise added under modular masking can wrap/round inconsistently; use the discrete Gaussian for Z_R (P4, I6).
  • Distributed noise with the wrong per-client variance (σ²C² instead of σ²C²/|U|) over- or under-noises the aggregate.
  • Using numpy.random for noise is insecure (predictable noise defeats DP) (I7, P2).
  • Reporting "DP" with σ=0 is a no-op (ε=∞) — log loudly (§8.12).

⬜ Phase 9 — Privacy accounting §20

Objectives

Build fl_accountant: Rényi DP accounting of the (subsampled) Gaussian mechanism (Gaussian = (α, α/2σ²)-RDP), composition across rounds (additive in RDP), subsampling amplification (cohort rate q, moments accountant), (ε,δ) conversion, a privacy-budget ledger with a pre-round hard stop (I13, P10), and σ calibration to a target ε for (q,T,δ) (§8.8).

Deliverable

The accountant reports cumulative (ε,δ) per round, refuses an over-budget round, and calibrates σ for a target ε; values match a reference (Opacus RDP) within tolerance; pytest packages/fl_accountant green; fl_cli account runs offline.

Acceptance
  • RDP/(ε,δ) for a single subsampled-Gaussian step matches Opacus RDPAccountant within 1e-3 (cross-check, ADR-17).
  • Composition over T rounds is monotone increasing and matches summed RDP → converted ε.
  • calibrate_sigma returns σ achieving ≤ target ε over T rounds at rate q (verified by re-accounting).
  • can_afford returns False exactly when the next round would exceed target ε (I13).
Fixtures
Fixture Purpose Expected
accounting/rdp_single.json ADR-17 matches Opacus ±1e-3
accounting/compose_T.json composition monotone, additive
accounting/calibrate.json σ↔ε ε ≤ target
accounting/budget_stop.json I13 refuse over-budget
Pitfalls
  • Forgetting subsampling amplification massively over-estimates ε (overspends conservatively) or, if mis-signed, under-estimates (privacy breach) — use the validated subsampled bound.
  • Optimizing the α grid too coarsely gives a loose ε; too fine wastes compute — tune the grid (e.g. up to 64).
  • Counting microbatches and rounds inconsistently double- or under-counts composition.
  • Conversion picking a fixed α instead of min_α reports a looser ε than achieved.
  • Charging the budget after the round (instead of gating before) can overspend by one round (I13, P10).

⬜ Phase 10 — Robustness / poisoning defense §21

Objectives

Build fl_robust: Krum/Multi-Krum (Blanchard 2017), coordinate-wise median + trimmed mean (Yin 2018), norm bounding/clipping of updates, and simple anomaly detection — and make explicit the fundamental tension with SecAgg (the server cannot inspect individual updates, P12). Ship robust cleartext-aggregation mode + client-side norm bounding compatible with SecAgg; defer verifiable/ZK robust-under-SecAgg.

Deliverable

Robust rules defend against poisoned clients in cleartext mode; client-side norm bounding works under SecAgg; the tension guard prevents misconfiguration; pytest packages/fl_robust green; examples/robust_poisoning.py runs.

Acceptance
  • With cohort=100 and f=20 Byzantine clients (f < cohort/2), Krum/median/trimmed-mean reach within 5% of the non-Byzantine target accuracy vs FedAvg diverging by > 30% (cleartext, fixture robust/krum_defend.json).
  • Client-side norm bounding caps ‖Δ_u‖ ≤ M for 100% of updates and remains bit-exact correct under SecAgg (the masked sum of bounded updates).
  • The tension guard raises RobustSecAggConflict in 100% of 10 tested misconfigurations when a peek-requiring rule is selected with SecAgg on and no verifiable backend (P12).

Fixture Purpose Expected

⬜ Phase 13 — Conformance, testing, attack simulation, scale §24

Objectives

Lock the system with reproducible seeded runs, mask-cancellation correctness, statistical DP-noise tests, an attack-simulation suite (membership inference, gradient inversion/DLG, model inversion, sybil/poisoning), and scale analysis (cross-device vs cross-silo). Sketch the deferred extensions: async FL, log-degree-graph SecAgg (Bell 2020), and TEE/HE-based aggregation (cross-link 391).

Deliverable

Green conformance + attack-sim report: DP measurably reduces membership-inference advantage; SecAgg blocks single-update DLG; robust rules blunt poisoning (cleartext); scale numbers recorded; deferred items specified; make conf + make fuzz green.

Acceptance
  • 100% of correctness/privacy fixtures pass; seeded runs are bit-reproducible across 2 independent replay runs (tests).
  • Membership-inference attacker advantage drops from a no-DP baseline ≥ 0.15 to ≤ 0.05 at ε=3 (quantified, fixture attack/membership_inference.json).
  • DLG reconstructs a single cleartext update to < 0.01 MSE but fails (MSE > 1.0, no better than random) against a SecAgg aggregate — demonstrated.
  • Robust rules keep convergence within 5% of target accuracy under f < cohort/2 poisoners (cleartext); the SecAgg tension is reproduced in 100% of 10 peek-requiring-rule trials (unavailable under SecAgg without ZK).
  • Scale: cross-device cohort=200 sampled from pool=10⁶ completes with documented comm/round/dropout; the O(cohort²) pairwise-quadratic cost is flagged with the Bell-2020 mitigation as deferred.
