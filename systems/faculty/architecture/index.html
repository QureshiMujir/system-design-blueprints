  • Wearer's Browser — untrusted execution context; the extension and web app run wearer-controlled code, so no server-side trust decision may depend on client honesty (I13, P3).
  • Extension — captures a task selection only on an explicit gesture, tracks per-tab/per-domain scope, renders the streamed response (§17).
  • Faculty Web App — the canonical wearing surface for users without the extension installed; same Pattern Engine contract (§16).
  • Session Gateway — the sole TLS termination point (I13); validates session JWTs, enforces per-user rate limits, scrubs PII before any logging.
  • Cognitive Pattern Engine — the only component that assembles prompts; composes signed-Manifest rules, retrieved corpus chunks, retrieved memory chunks, and sanitized task text (§14).
  • Memory Layer — vector + structured store, partitioned at the database layer by tenant key, never by application-layer filtering alone (I2, I8, §15).
  • Room Real-Time Channel — WebSocket fan-out for multi-wearer Faculty Rooms, with a private per-participant side-channel (§23).
  • Faculty Store / Royalty Ledger / Stripe — marketplace listing, search, ratings, and the revenue-split ledger that must reconcile to Stripe Billing (§21, §20).
  • Author Tools API — the only path by which a third-party artifact enters the system; validates schema, runs the evaluation suite, signs, and queues borderline submissions for Trust & Safety review (§19).
  • LLM Providers — delegated inference, provider-abstracted for failover (ADR-07).
  • Object Storage / Postgres — durable storage for signed Manifests, corpus chunks, memory rows, session/Room state, and the royalty ledger.
  • Concurrency boundary — the Cognitive Pattern Engine is stateless per request; all cross-request state (memory, sessions) lives exclusively in Postgres, never in engine-worker process memory, which is what makes horizontal scale-out (§32) a capacity decision rather than a redesign.

8. Domain Model

8.1 Faculty Manifest — Canonical Envelope

The Manifest is the JSON realization of the type in §11.1, stored at manifests/{faculty_id}/{version}.json in object storage, Ed25519-signed by the platform key (ADR-05). Required fields are normative; unknown top-level fields are rejected — no silent forward compatibility on the envelope itself (ADR-19), so a materially new capability always forces a conscious major-version bump.

deprecated 90 days elapse — removed

8.3 Memory Model

Per-(user_id, faculty_id) (or (room_id, faculty_id), §23) rows of kind interaction | summary | anchor | preference (full type at §11.2). Interactions are retained verbatim only with opt-in; otherwise summarized within 24 hours (P2). Anchors are explicit, user-editable "remember this" facts. Retrieval scores memory chunks by salience × recency × cosine (§15).

8.4 Session and Room Model

A Session (§11.3) accumulates wearingSeconds — the raw input to the HW/WAU north-star metric — and carries facultyIds: FacultyId[], where length > 1 marks a stacked session (§22). A Room (§23, §11.4) is a Session variant scoped to (room_id, faculty_id) with a separate real-time transcript.

8.5 Worked Example — Wearing Munger Around a Fundraising Paragraph

  1. Wearer highlights a paragraph in Google Docs, hits Ctrl-J (P3). Extension sends {selection, domain: "docs.google.com"} to the Session Gateway over TLS (I13).
  2. Engine loads manifests/munger-multidisciplinary/1.4.0.json, verifies its Ed25519 signature (I1) and content hash (I14).
  3. Retrieval fetches top-5 corpus chunks (corpus_chunk_id: mnc-0042, mnc-0117, …) via pgvector cosine search (§15) plus top-3 memory chunks tagged with this wearer's prior "fundraising" anchor.
  4. Prompt Assembler composes: behaviour.systemPrompt + structured rules (must_invert, must_cite) + the 5 corpus chunks + the 3 memory chunks + the sanitized selection.
  5. LLM Orchestrator streams from Claude Sonnet (Manifest's llm.preferred); Behavioural Rule Enforcer checks the response for a citation anchor and an inversion — both present, no retry needed (I7).
  6. Post-processing filter confirms the response is framed as "the Munger-inspired pattern suggests…", never "Munger says…" (I12).
  7. Response streams to the side panel; wearer clicks "remember this about me" — a new anchor memory row is written, partitioned to (user_id="u_9a1", faculty_id="munger-multidisciplinary") (I2).
  8. Session's wearingSeconds accumulator increments; on session end, revenue for this wearing-second range is queued for royalty allocation (§20).

8.6 Malformed-Input Example

Submission payload includes an undeclared top-level field "authorNotes": "draft v2" and omits provenance.rightsBasis. The Manifest schema validator (Zod, §11.1) rejects the submission with MANIFEST_UNKNOWN_FIELD: authorNotes and MANIFEST_MISSING_REQUIRED: provenance.rightsBasis, both surfaced verbatim in the Author Tools CLI (faculty validate) before any network call — the submission never reaches evaluation (I3, ADR-19).

8.7 Failure-Path Example

An attacker rewrites the corpus pointer inside a previously-signed Manifest stored in object storage (bypassing the signing service). On next cold load, the Engine recomputes the content hash, finds it does not match the embedded signed hash, and refuses to load (I1, I14). The wearer sees "Faculty temporarily unavailable" with an incident id; manifest_hash_mismatch_total increments; if the same Faculty id triggers twice within 10 minutes, on-call is paged and the Faculty is auto-unlisted pending investigation (§25, §26 FM-2).

8.8 Continuity Note

The Munger Multidisciplinary, Feynman First-Principles, and Jobs Product-Critique Faculties referenced throughout this document are the three founder-curated Faculties shipped in §12 Phase 0; their corpora are public-domain or original analyses only, per the provenance policy at T5 (§25) and the rightsBasis field (§11.1).

Design principles (§6)

  • P1 — Manifest-as-Data, Never-as-Code. Author-submitted rules and prompts are compiled and interpreted as declarative data by the Pattern Engine; never executed as arbitrary code. Tradeoff: less expressive than a scripting sandbox. Operational implication: eliminates an entire class of RCE/exfiltration risk. Violating it: a sandbox escape becomes wearer-task-content exfiltration (T1).
  • P2 — Task Content Never Leaves the Vault. Raw wearer task text is never persisted beyond ephemeral session scope without explicit opt-in. Tradeoff: limits cross-session raw-text recall (mitigated by summarization, §15). Violating it: a privacy breach indistinguishable from a data-broker leak.
  • P3 — Explicit Gesture Before Capture. No ambient DOM scraping; every capture requires a discrete user action. Tradeoff: one extra interaction step. Violating it: Chrome Web Store rejection (ADR-09) and a prompt-injection surface from arbitrary page content.
  • P4 — Signed Manifests Only. Every Manifest is Ed25519-signed by the platform key before the Engine will load it. Tradeoff: every publish requires a signing round-trip. Violating it: I1/I14 fail, tampering becomes undetectable.
  • P5 — Partition at the Database, Not the Application. Cross-tenant isolation is enforced by DB-level partition keys, never solely by application-layer filters. Tradeoff: every query must carry its partition key explicitly. Violating it: I2/I8 fail — a single missed WHERE clause leaks memory across tenants.
  • P6 — Evaluation Gates Before Marketplace, Not After. A Faculty cannot list publicly until it clears its evaluation floor. Tradeoff: slows author time-to-list. Violating it: the marketplace fills with low-fidelity Faculties (R-08-class risk).
  • P7 — Behavioral Rules Compile to Guards, Not Prompts Alone. Rules produce pre-flight prompt augmentation and post-flight validators, with exactly one automatic retry on violation (I7, Madaan et al. 2023). Tradeoff: doubles worst-case latency on a violation. Violating it: silent behavioral drift the wearer cannot detect.
  • P8 — Idempotent, Replayable Session Accounting. Every wearing-second increment and royalty-allocation event is idempotent and replayable from an append-only session-event log. Tradeoff: extra storage for the event log. Violating it: reconciliation double-counts or under-counts revenue (I5).
  • P9 — Backward-Compatible Schema Evolution. Manifest/Memory/Session schemas are semver; the runtime supports the current and previous major version simultaneously for ≥ 6 months. Tradeoff: dual-path read code during the overlap window. Violating it: a schema bump breaks every in-flight wearer session (§28).
  • P10 — Royalty Arithmetic Lives in One Service. Allocation logic is centralized in the Royalty Ledger service; no other service computes revenue splits. Tradeoff: every consumer of "how much does an author earn" makes a network call. Violating it: the author dashboard and the actual Stripe transfer drift apart (I5).
  • P11 — Memory Is Portable, Not a Moat. Export and delete are first-class, documented, and complete within a bounded SLA (24 h propagation). Tradeoff: no data-lock-in retention lever. Violating it: the compounding-value story becomes coercive rather than earned (Principle 7 of the original product charter).
  • P12 — Every External Claim Is Framed as Inspiration, Not Fact. Output attributing views to a named human is transformed at the post-processing layer into "inspired-by" framing, non-overridable by author rules. Tradeoff: a small, constant post-processing cost on every response. Violating it: defamation exposure (I12, R-04-class risk).
  • P13 — Degrade Gracefully Across LLM Providers. The orchestrator's provider abstraction allows hot failover without a user-visible Manifest change. Tradeoff: must certify behavior against ≥ 2 providers per Faculty. Violating it: a single provider's rate-limit or pricing change halts the product (ADR-07).
  • P14 — Human Review Is a Backstop, Not the Primary Gate. Automated evaluation and corpus fingerprint scanning are the primary marketplace gate; the human review queue handles only flagged borderline cases within an SLA. Tradeoff: some false negatives reach a human late. Violating it: the review queue becomes an unscalable bottleneck at marketplace scale (§21).
