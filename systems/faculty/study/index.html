  20. If search relevance (M10) is benchmarked against a fixed 50-pair set, what mechanism actually catches degradation between re-benchmarking intervals, and is it sufficient at 10× the catalogue size? (§21.6, §31)
  21. Why does the token-bucket rate limiter (ADR-23) gate submissions per author rather than per Faculty, and what abuse pattern would slip through a per-Faculty-only gate? (ADR-23, §19)

33. Mental Models & First Principles

  1. MM1 — A Manifest is a contract, not a prompt. Treat it as an interface boundary with a compatibility guarantee, like a public API, never a casual prompt template. Predicts: schema changes need versioning discipline. Bug class without it: silent behavioral drift disguised as a "prompt tweak" that breaks wearer trust. Applies at §11.1, ADR-19.
  2. MM2 — Retrieval is lossy compression of the corpus, not search. Top-k retrieval always discards relevant context; recall@k is a first-class tunable, not an afterthought. Predicts: chunking strategy materially changes fidelity. Bug class without it: authors blame "the LLM" for what is actually a retrieval-recall problem. Applies at §14.2, ADR-08, ADR-22.
  3. MM3 — A partition key is a promise enforced by the database, not the application. Any isolation guarantee resting on every code path remembering to filter will eventually fail; push it to the schema/RLS layer. Bug class without it: one forgotten WHERE clause becomes a cross-tenant leak. Applies at §15.2, I2, I8.
  4. MM4 — Behavioral rules are guards around a black box, not control over it. You cannot make an LLM obey a rule by asking nicely in the prompt alone; a post-hoc validator with a bounded retry is required. Predicts: naive prompt-only rule systems degrade under adversarial input. Bug class without it: silent rule violations invisible in casual testing. Applies at §14.2, P7, I7.
  5. MM5 — Royalty is a distributed-ledger problem wearing a subscription business's clothes. Revenue-split allocation needs the rigor of a financial ledger (idempotency, reconciliation, append-only), not a dashboard computation. Bug class without it: double-pays and silent drift between the UI and actual money moved. Applies at §20, I5, P10, P8.
  6. MM6 — A Faculty Room is a convergence problem even without a CRDT. Multiple private side-channels plus one shared transcript is the same shape as shared-document convergence; sticky routing sidesteps needing an actual CRDT at this scale. Predicts: naive "broadcast to everyone" designs break under mid-session failover. Bug class without it: split-brain transcripts. Applies at §23.2, §23.8, ADR-11.
  7. MM7 — Evaluation is the load-bearing wall, not a QA afterthought. In a system whose core claim ("this Faculty thinks differently") is unfalsifiable by casual inspection, the evaluation suite is the only thing standing between the marketplace and pure marketing claims. Bug class without it: a marketplace that quietly degrades into a directory of unverified prompts. Applies at §18, P6, I4.
  8. MM8 — Every provider abstraction is a bet that behavior transfers, and it never fully does. A Faculty certified against Claude may behave differently on GPT-4o; provider-agnosticism is a spectrum, not a boolean. Predicts: silent quality regressions after a failover event. Bug class without it: assuming ADR-07's failover is quality-neutral. Applies at §14.6, ADR-07.
  9. MM9 — A rate limiter is a promise about the future, not just a counter of the past. A token bucket's refill rate encodes an assumption about sustainable throughput; tuning it wrong either starves legitimate bursts or fails to prevent abuse. Predicts: a limiter needs empirical calibration against real submission patterns, not a guessed constant. Bug class without it: an untuned limiter that either blocks power authors or lets a denial-of-wallet attack (T11/T13) through. Applies at §19.2, ADR-23, T11, T13.

Required reading (§5)

Books

  • Kleppmann, M. — Designing Data-Intensive Applications (O'Reilly, 2017). Chapters 5–7 (replication, partitioning, transactions). Extract: the partition-key discipline applied to the Memory Layer's (user_id, faculty_id) key (§15, I2).
  • Petrov, A. — Database Internals (O'Reilly, 2019). Part I (storage engines, B-trees vs LSM). Extract: why Postgres + pgvector's page layout bounds the vector-row ceiling in §4 and ADR-03.
  • Beyer, B., Jones, C., Petoff, J., Murphy, N. (eds.) — Site Reliability Engineering (Google/O'Reilly, 2016). Chapters 4 (SLOs), 6 (monitoring). Extract: the error-budget model applied to §4's availability row and §27 Operational Readiness.
  • Google SRE authors — Building Secure and Reliable Systems (O'Reilly, 2020). Chapters 3–5 (design for security, trust boundaries). Extract: the trust-boundary decomposition in §3 and the Author boundary in §25 Threat Model.
  • Akidau, T., Chernyak, S., Lax, R. — Streaming Systems (O'Reilly, 2018). Chapters 1–2 (streaming fundamentals, watermarks). Extract: the event-accounting model for wearing-seconds and Room transcripts (§16, §23).
  • Gilman, E., Barth, D. — Zero Trust Networks (O'Reilly, 2017). Chapters 1, 5. Extract: tenant-isolation posture for the Phase 12 enterprise/BYO-cloud path (§24).
  • Chen, A. — The Cold Start Problem (Harper Business, 2021). Chapters on marketplace liquidity. Extract: the author/wearer liquidity flywheel applied in §21 Faculty Store and §34 Comparative Architecture.
  • Nygard, M. — Release It! (Pragmatic Bookshelf, 2nd ed., 2018). Chapters on stability patterns (circuit breaker, bulkhead). Extract: the circuit-breaker/rate-limit discipline behind ADR-23's token-bucket submission gate and T11's denial-of-wallet mitigation (§19, §25).
  • Fowler, M. — Patterns of Enterprise Application Architecture (Addison-Wesley, 2002). Chapter on Unit of Work / optimistic offline lock. Extract: the append-only, reference-predecessor correction pattern used by RoyaltyLedgerEntry (§11.4, ADR-25, P10).

Reference Implementations

  • LangChain (github.com/langchain-ai/langchain) — study libs/core/langchain_core/runnables for composable retrieval chains. Lesson: composability of retrieve→assemble→generate stages (§14). Pitfall: its abstraction depth hides token-cost accounting — Faculty's Prompt Assembler logs cost per stage explicitly (§16.10).
  • LlamaIndex (github.com/run-llama/llama_index) — study llama_index/core/node_parser for chunking strategies. Lesson: structural vs. semantic chunking tradeoffs (ADR-22). Pitfall: naive fixed-size chunking silently truncates citation anchors.
  • pgvector (github.com/pgvector/pgvector) — study src/hnsw.c and the README's index-tuning section. Lesson: ef_search/m parameter tuning for recall vs. latency (§15, M4). Pitfall: default parameters under-recall at corpus sizes above ~500k rows.
  • Chrome Extensions Samples (github.com/GoogleChrome/chrome-extensions-samples) — study functional-samples/cookbook.sidepanel. Lesson: MV3 side-panel lifecycle and gesture-scoped activation (§17, P3). Pitfall: over-broad host_permissions trigger Web Store review rejection.
  • Stripe Connect sample apps (github.com/stripe-samples/connect-integration-visualizer, connect-marketplace) — study the platform/connected-account split-payment flow. Lesson: idempotent transfer creation keyed by session id (§20, I5). Pitfall: naive proration on mid-cycle Faculty changes causes chargeback drift (R-style risk, §26).
  • Envoy Proxy (github.com/envoyproxy/envoy) — study source/extensions/filters/http/ratelimit for token-bucket-style local/global rate limiting. Lesson: local vs. global rate-limit tradeoffs (ADR-23). Pitfall: a purely local rate limiter under-throttles behind multiple engine-worker replicas — global (shared) state is required past a single instance.
  • Kong Gateway (github.com/Kong/kong) — study kong/plugins/rate-limiting for per-consumer counter-window design. Lesson: per-consumer rate-limit key design (ADR-23). Pitfall: a naive in-memory counter under multi-node deployment undercounts without a shared backing store — informs ADR-28's shared Postgres-backed counter over per-instance memory.

Glossary (§39) · 48 terms · site-wide glossary

Anchor
an explicit "remember this about me for this Faculty" memory row, surfaced in UI and user-editable (§11.2).
Author
the creator of a Faculty, identity-verified via Stripe Connect KYC (§20), entitled to royalty under ADR-21.
Author Tools
the CLI (@faculty/cli) and Web Studio (apps/studio) through which an author drafts, validates, evaluates, and publishes a Faculty (§19).
Behavioral Rule
a structured constraint (e.g., must_invert, must_cite) compiled into a pre-flight/post-flight runtime guard, never executed as code (§11.1, P1, P7).
BYO-Cloud
a single-tenant, customer-hosted deployment topology (Helm + Terraform) sharing the SaaS codebase behind a config flag (ADR-18, §24).
Cognitive Pattern Engine
("the Engine") — the trusted-boundary runtime turning a Manifest into live behavior: retrieval, prompt assembly, rule enforcement, LLM orchestration (§14).
Cognitive Primitive
a declared atomic operation (e.g., inversion, first-principles decomposition) a Faculty performs and the evaluation suite tests for (§11.1, §18).
Corpus
the retrieval source material for a Faculty: signed, chunked, embedded documents (§11.1, ADR-22).
Corpus Fingerprint
a content hash (or SimHash/MinHash under ADR-31) used both for IP-infringement scanning (§19, T2) and duplicate-across-account rate-limit-evasion detection (T15).
Custom Corporate Faculty
a Faculty trained on an internal expert's archive, corporate_owned provenance, deployed only inside one tenant, never publicly listed (§24).
Denial-of-Wallet
an attack pattern (T11) where pathological or abusive usage inflates LLM-call cost rather than compromising data; mitigated by per-Faculty cost ledgers and rate limits (§19, ADR-23).
Ed25519
the elliptic-curve signature scheme (RFC 8032) used to sign every Manifest (ADR-05, I1, I14).
Evaluation Suite
the mandatory automated test pack (packages/eval-suite) gating marketplace listing (§18, P6, I4).
Faculty
a versioned, Manifest-defined bundle of cognitive pattern, corpus, behavioral rules, evaluation suite, and memory scope (§11.1).
Faculty Room
a multi-human shared session wearing one Faculty around a shared task, with a separate memory partition (§23).
Faculty Store
the public marketplace surface for browsing, searching, and renting Faculties (§21).
Fingerprint Scan
the IP-infringement and duplicate-corpus detection step run at submission time (§19, T2, T15).
HNSW
(Hierarchical Navigable Small World) — the approximate-nearest-neighbor graph index type used by pgvector for retrieval (ADR-06, Malkov & Yashunin 2018).
HW/WAU
Hours Wearing per Weekly Active User; the north-star metric, accumulated via Session.wearingSeconds (§11.3, §16).
Idle Network Invariant
informal name for I15: the guarantee that the extension emits zero network traffic while no Faculty is active (§17.4).
Invariant
(I#) — a system-wide correctness guarantee enforced structurally, not by convention (§7).
Manifest
the signed, versioned JSON envelope defining a Faculty (§11.1).
Memory Entry
a single row of per-(user, Faculty) or per-(room, Faculty) compounding context: interaction, summary, anchor, or preference (§11.2).
Memory Layer
the partitioned vector-plus-structured store implementing compounding context (§15).
Memory Lift
the measured relevance improvement in retrieval once a Faculty's memory crosses a usage threshold (§18.4 target: ≥ 25% by interaction 50).
Partition Key
the (user_id, faculty_id), (room_id, faculty_id), or (tenant_id, user_id, faculty_id) tuple enforced at the database layer to guarantee isolation (I2, I8, §24).
Pattern Engine
shorthand for Cognitive Pattern Engine.
Provenance
the declared rights basis (public_domain, estate_licensed, original_work, corporate_owned) of a Faculty's corpus (§11.1).
Provenance Attestation
a SLSA-style, CI-generated cryptographic record proving a build artifact came from a specific, verifiable CI run (§30, T14, I18) — distinct from Manifest Provenance (rights basis) despite the shared term.
Query-Builder Exclusion
the pattern behind I16: a structural, base-query-level filter (e.g., excluding corporate_owned Faculties) rather than a per-callsite WHERE clause (§24.2).
RAG
(Retrieval-Augmented Generation) — the retrieve-then-generate architecture underlying the Engine's corpus and memory retrieval (§14, Lewis et al. 2020, ADR-08).
Rate Limit (Token Bucket)
the per-author submission throttle (ADR-23) that refills continuously rather than resetting on a fixed window boundary, gating publish frequency (§19, I17).
Reconciler
the platform-controlled prompt that synthesizes agreements and disagreements across a Stack's independent Faculty responses (§22).
Retrieval
the top-k similarity search over corpus and memory embeddings that grounds a Faculty's response (§14.2).
Rights Basis
see Provenance.
Royalty Ledger
the append-only, reconciled record of revenue allocation to authors (§11.4, §20, I5).
Session
a scoped wearing instance accumulating wearingSeconds and an append-only event log (§11.3).
Signing Key
the Ed25519 keypair (with rotation lineage) used to sign Manifests; pluggable to an HSM/KMS for BYO-cloud tenants (§13, §24.2).
SLSA
Supply-chain Levels for Software Artifacts; the build-provenance attestation framework applied to container images and the extension bundle (§30, T14, I18).
Stack
a composition of N ≤ 4 Faculties worn simultaneously, reconciled by the Reconciler (§11.4, §22, I11).
Takedown SLA
the response-time commitment for a Trust & Safety report: 24h for Sev-1, 7 days for Sev-2 (§21, §25).
Tenant
an isolated customer boundary in the BYO-cloud deployment topology, scoped by tenant_id (§24).
Token Bucket
see Rate Limit (Token Bucket).
Trust & Safety (T&S)
the human-review backstop for borderline evaluation, impersonation, and takedown cases (P14, §21).
Vault Scope
the per-record privacy marker (user_only, user_and_platform_audit, user_and_faculty_aggregate) governing what an author may ever see (§11.2).
Wearer
a user actively wearing a Faculty around a task.
Wearing
active use of a Faculty around a browser task, the unit HW/WAU measures.
Wearing Surface
the web app's rich-text task editor plus Faculty side panel (§16).
