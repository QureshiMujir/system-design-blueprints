1. Goal & Scope

Engineering definition. A correctness-oriented, deterministic-replay simulation platform for x86 Local APIC / IOAPIC / x2APIC and ARM GICv2/GICv3 interrupt delivery semantics: interrupt state-machine modeling, priority arbitration, SMP routing, timer generation, inter-processor interrupts, and observability-first execution — not a CPU emulator, not an RTL model, not a hardware bring-up tool. The simulator is the interrupt subsystem's behavioral contract made executable, replayable, and measurable.

Target correctness bar: byte-identical replay across runs, zero tolerated divergence (§4), and conformance against documented APIC/GIC architectural behavior (§26).

Phase 0 deliverable — core crates:

  1. sim-core — runtime lifecycle orchestration
  2. sim-clock — deterministic logical clock
  3. sim-eventbus — bounded event transport
  4. sim-trace — WAL / replay serialization
  5. sim-observability — metrics, tracing, logging
  6. sim-topology — CPU/interrupt-domain graph
  7. sim-apic — Local APIC / x2APIC semantics
  8. sim-ioapic — IOAPIC redirection/routing
  9. sim-gic — ARM GICv2/GICv3 semantics
  10. sim-delivery — central arbitration/routing engine
  11. sim-priority — priority class and nesting semantics
  12. sim-timer — timer wheel / deadline facilities
  13. sim-ipi — inter-processor interrupt delivery
  14. sim-replay — deterministic replay runtime
  15. sim-config — topology/runtime configuration parsing
  16. sim-fixtures — conformance fixture corpus
  17. sim-cli — operator-facing command surface
  18. sim-conformance — differential/conformance runner
  19. sim-fuzz — fuzz targets (topology, replay, wire)
  20. sim-metrics — metrics registry
  21. sim-scheduler — domain-worker scheduling
  22. sim-storage — snapshot/trace persistence
  23. sim-wire — envelope/serialization types
  24. sim-testkit — integration test harness

System boundaries.

  • Provides: interrupt topology modeling, interrupt state machines, interrupt transport, arbitration, delivery semantics, queueing, timer generation, observability, deterministic replay, topology configuration, trace persistence.
  • Delegates: wall-clock synchronization to PTP/NTP-equivalent inputs in distributed mode (does not implement a clock-sync protocol itself); container/orchestration lifecycle to Docker/Kubernetes (not governed by any ADR in §9; host orchestration is explicitly out of scope).
  • Does NOT provide: full CPU instruction execution, full MMU behavior, device DMA execution, real networking stacks, real storage hardware, PCIe device emulation, GPU interrupt pipelines, ACPI firmware emulation, RTL synthesis, Verilog generation, electrical signal-level modeling.

Non-goals (Phase 0): full CPU ISA emulation, full VM execution, real hardware passthrough, SMT microarchitectural timing accuracy, ARM TrustZone routing, RISC-V AIA support, full Linux boot, power-management state machines, hardware waveform simulation.

Deployment model. Runtime modes: standalone CLI simulator, embedded library runtime, deterministic replay runtime, distributed simulation coordinator, visualization-enabled debug runtime. Deployment targets: developer workstation, CI validation pipeline, deterministic replay analysis node, research cluster execution, kernel validation lab.

Target operators: OS/kernel engineers, hypervisor developers, architecture researchers, low-level systems educators, hardware validation engineers, deterministic-systems researchers.

What later phases unlock: kernel interrupt-stack testing, hypervisor interrupt-injection testing, distributed deterministic replay, interrupt-scheduling experimentation, real trace ingestion, hybrid hardware/simulated validation, microkernel interrupt-policy testing, interrupt QoS research.

Recommended language: Rust 1.82+. Rationale: ownership semantics prevent lifecycle corruption in a long-lived event-driven runtime; algebraic data types map directly onto interrupt state machines (§8); trait systems allow pluggable controller models (APIC vs GIC) behind one InterruptController trait (§11); async runtimes can be selectively avoided (ADR-07) to keep replay deterministic; mature tracing/fuzzing/serialization ecosystems reduce Phase 0 risk; reproducible builds and lock-free structures are practical without a GC.

2. Why Build This

Interrupt controllers are the substrate every kernel subsystem ultimately depends on: scheduling wakeups, timer ticks, TLB shootdowns, device completions, and IPI-based coordination all resolve through the APIC/GIC delivery path. A bug here corrupts everything built above it, which is why this simulation demands the same rigor a real controller implementation would.

Historical importance. APIC and GIC architectures replaced legacy PIC designs because SMP scaling required distributed interrupt routing, prioritization became mandatory for real-time and latency-sensitive workloads, virtualization demanded programmable delivery, NUMA systems required affinity-aware routing, and performance-sensitive workloads required reduced interrupt overhead. Studying these systems exposes hardware-abstraction tradeoffs, distributed-arbitration semantics, interrupt-fairness problems, scheduler-interaction complexity, and concurrency hazards specific to low-level systems — the same hazards recur in database WAL systems, consensus engines, and network switch schedulers.

Engineering muscles developed: systems decomposition, deterministic architecture design, state machine correctness, protocol implementation discipline, lock-hierarchy design, cache-aware data structure design, event-pipeline design, trace analysis, compatibility engineering, failure containment, observability-first engineering.

Production engineering concepts exercised: bounded queues, replay logs, failure isolation, crash consistency, compatibility guarantees, scheduling fairness, tail-latency analysis, backpressure propagation, metrics-cardinality control, structured telemetry, fault injection, topology-aware scheduling.

Related systems projects: hypervisors, kernels, scheduler simulators, CPU simulators, distributed event engines, observability systems, tracing infrastructures, database WAL systems, consensus engines, network switch schedulers, runtime schedulers, hardware validation systems.

What Mastery Looks Like

  • Can explain why the priority-stack invariant (I10, §7) is necessary and not merely defensive, using the Local APIC nesting model built in Phase 3 (§15).
  • Can derive queue and memory sizing from first principles the way §32's capacity model does, rather than quoting a number from §4 without the arithmetic.
  • Can distinguish a livelock from a deadlock in an arbitration engine and name the exact invariant each violates, grounded in the Phase 6 arbitration work (§18).
  • Can design a replay format that survives schema evolution, using the append-only wire compatibility discipline built in Phase 7 (§19) and pinned by ADR-05/ADR-17 (§9).
  • Can reason about GICv2-to-GICv3 migration (flat distributor → per-CPU redistributor) as a cache-coherence-shaped problem, from the Phase 5 GIC work (§17).
  • Can diagnose an interrupt storm from queue-occupancy telemetry alone, without attaching a debugger, using the observability stack built in Phase 8 (§20).
  • Can write a fault-injection scenario that is itself deterministically replayable, from the Phase 9 chaos infrastructure (§21).

sim-cli — operator control surface; topology ingestion, runtime bootstrap, replay execution, metrics export configuration, deterministic seed injection, fixture orchestration. Trust boundary: untrusted configuration enters here; malformed topology can poison scheduler assumptions, replay mismatch can invalidate determinism guarantees.

sim-core — owns runtime lifecycle: subsystem initialization ordering, scheduler coordination, global shutdown, failure containment, resource ownership, panic-recovery boundaries. Concurrency boundary: every worker execution context originates here.

sim-clock — deterministic logical time: cycle advancement, synchronization barriers, monotonic timestamp generation. Invariant: time never regresses (I1).

sim-eventbus — bounded asynchronous event transport: queueing, dispatch ordering, backpressure enforcement, priority-aware delivery, replayable sequencing. Unbounded queues break replay determinism and starve latency analysis.

sim-trace — deterministic trace persistence: event WAL, snapshots, replay serialization, ordering guarantees. Persistence boundary: all replayable state crosses here.

sim-observability — metrics, tracing, logging, diagnostics: structured telemetry, event tracing, latency histograms, queue-depth instrumentation, anomaly reporting.

sim-topology — CPU and interrupt-domain graph: enumeration, routing maps, affinity tracking, validation.

sim-apic — x86 Local APIC: ISR/IRR/TMR management, EOI handling, vector prioritization, timer generation, x2APIC mode.

sim-ioapic — IOAPIC routing: redirection tables, masking, delivery-mode routing, trigger-mode handling.

sim-gic — ARM GICv2/GICv3: distributor state, redistributor state, SGI delivery, PPI routing, SPI arbitration.

sim-delivery — central routing engine: delivery arbitration, retry handling, routing decisions, fairness enforcement, starvation prevention. This is the protocol boundary where the InterruptEvent state machine (§8) is enforced.

sim-priority / sim-ipi / sim-timer — priority nesting and preemption eligibility; broadcast and targeted IPIs including TLB-shootdown simulation; periodic/deadline timer facilities with drift accounting.

sim-storage — persistence infrastructure: replay storage, snapshots, trace archival, compatibility-aware serialization. External interface: local disk / object storage for archived traces.

6. Design Principles

  • P1 — Determinism Over Convenience. Rule: every replayable execution must produce byte-identical traces. · Tradeoff: forbids convenient nondeterministic sources (wall clock, thread-scheduling-order reads, unseeded RNG). · Operational: every scheduler decision must be traceable to a recorded input. · Violated: replay diverges silently, turning every regression into an irreproducible one-off.

  • P2 — Bounded Resource Usage. Rule: every queue, buffer, allocator pool, and scheduler pool must have a hard capacity. · Tradeoff: rejects load instead of degrading gracefully via unbounded growth. · Operational: capacity exhaustion is a first-class, telemetered event, not a crash surprise. · Violated: unbounded allocation causes replay drift, memory amplification, and scheduler collapse under load.

  • P3 — Observability by Default. Rule: every subsystem emits metrics, structured logs, tracing spans, and causal identifiers without an opt-in flag. · Tradeoff: fixed instrumentation tax on every code path (bounded by §4's 2%/5% overhead budgets). · Operational: postmortems start from telemetry, not attached debuggers. · Violated: failures become undebuggable in production-scale runs.

  • P4 — Crash-Only Semantics. Rule: subsystems recover only through restart-and-replay, never partial in-memory repair. · Tradeoff: no "hot patch the corrupted structure and continue" path — simplicity over availability of a single process. · Operational: every recovery path is exercised by the same code path as a cold start. · Violated: ad-hoc repair logic silently diverges from the replay contract (P1).

  • P5 — Explicit Ownership. Rule: no shared mutable state without an explicit synchronization boundary and a named owner. · Tradeoff: more type/module boilerplate at each boundary. · Operational: every data race is a missing-boundary bug, not a "we forgot a lock" bug. · Violated: undetectable data races surface as nondeterministic replay divergence.

  • P6 — Replayability First. Rule: a feature that cannot be made replayable is rejected from Phase 0 scope, full stop. · Tradeoff: some realism (true wall-clock jitter, real hardware timing) is deliberately excluded. · Operational: every new feature proposal answers "how does this replay?" before "how does this perform?". · Violated: the simulator degrades into an unreproducible approximation, defeating its purpose.

  • P7 — Stable Wire Compatibility. Rule: serialization formats evolve append-only; no field renumbering, no field removal. · Tradeoff: schemas accumulate unused legacy fields over time. · Operational: old traces remain replayable against new binaries indefinitely. · Violated: a minor-version upgrade silently breaks archived trace replay (T4, §22).

  • P8 — Backpressure Everywhere. Rule: queue pressure must propagate upstream to the producer, never absorbed silently downstream. · Tradeoff: producers must handle rejection/stall, adding caller-side complexity. · Operational: a saturated queue is visible as a metric before it is visible as a failure. · Violated: silent absorption hides the true bottleneck until an unrelated subsystem overflows.

  • P9 — Isolation of Failure Domains. Rule: APIC, GIC, and replay failures must not corrupt global runtime state. · Tradeoff: each domain needs its own containment boundary and cannot freely share mutable structures. · Operational: one controller's bug is a contained, telemetered failure, not a whole-simulation crash. · Violated: a single malformed IOAPIC redirection entry can corrupt an unrelated GIC redistributor's state.

  • P10 — Metrics Cardinality Control. Rule: metric label sets must remain bounded regardless of topology size. · Tradeoff: per-vector-per-CPU granularity (65536 × 4096, §4) must be sampled, not exhaustively labeled. · Operational: a cardinality budget is enforced at the metrics registry, not left to convention. · Violated: metrics backend collapses under label explosion (T5, §22), taking observability down exactly when it is needed most.

  • P11 — Lock Ordering Discipline. Rule: a single global lock hierarchy is defined and every lock acquisition follows it. · Tradeoff: occasionally forces a less "local" code structure to respect global ordering. · Operational: lock-order violations are statically or dynamically detectable, not discovered via production deadlock. · Violated: lock inversions cause deadlocks that only manifest under specific interleavings (FM-5, §23).

  • P12 — Time Is a First-Class API. Rule: logical time is an explicit parameter/return value, never an ambient global read. · Tradeoff: every time-dependent function signature carries a LogicalTime argument. · Operational: replay can drive time deterministically because nothing reads a hidden clock. · Violated: a hidden wall-clock read reappears as an unreproducible replay divergence months later.

  • P13 — Configuration Validation Before Execution. Rule: malformed topology or config is rejected before any runtime state is constructed. · Tradeoff: startup does more upfront validation work, increasing cold-start latency slightly. · Operational: a bad topology fails fast with a structured diagnostic, not a mid-run corruption. · Violated: an invalid routing entry poisons scheduler assumptions and surfaces as an unrelated crash minutes later.

  • P14 — Immutable Event Records. Rule: an InterruptEvent becomes immutable once committed to the event log. · Tradeoff: state transitions are represented as new records, not in-place mutation, costing extra allocation. · Operational: any historical event can be inspected without holding a lock on live state. · Violated: in-place mutation of a committed record breaks the WAL-order invariant (I7) retroactively.

  • P15 — Compatibility Before Optimization. Rule: never optimize away architectural correctness (e.g., short-circuiting an arbitration step for speed). · Tradeoff: some throughput is left on the table in exchange for conformance guarantees. · Operational: every performance change ships with a conformance-fixture diff proving behavior is unchanged. · Violated: a "fast path" silently diverges from documented APIC/GIC behavior, invalidating conformance claims (§26).

Debugging methodology: the simulator is a deterministic simulator with one assertion per invariant — each row above corresponds to exactly one runtime assertion compiled into debug and conformance builds, never a comment or convention. A failing assertion identifies the violated invariant by ID directly in its panic message and structured log line, so triage starts from the invariant table, not from a stack trace alone. Conformance and fuzz runs (§26) execute with all assertions enabled; release builds keep the fatal subset (I1, I3, I4, I5, I10) and downgrade the rest to telemetry-only counters to preserve the §4 performance budget.

8. Domain Model — Interrupt Event & Delivery State Machine

struct InterruptEvent
  event_id: Uuid;
  timestamp: LogicalTime;
  source_controller: ControllerId;
  destination_cpu: CpuMask;
  vector: u32;
  priority: PriorityClass;
  trigger_mode: TriggerMode;
  delivery_mode: DeliveryMode;
  state: InterruptState;

Interrupt state machine — happy path:

IDLE -> PENDING -> DELIVERED -> ACTIVE -> EOI_PENDING -> COMPLETED

Failure transitions:

PENDING -> RETRY_PENDING     (arbitration retry, bounded by I9)
ACTIVE  -> STALLED           (handler never completes; watchdog territory, FM-5)
DELIVERED -> LOST            (queue overflow mid-flight; fatal per I4)

APIC delivery flow (sim-ioapic → sim-apic, enforced in sim-delivery):

IOAPIC pin assert -> redirection lookup -> destination resolution
  -> LAPIC IRR insertion -> priority arbitration -> CPU acceptance
  -> ISR activation -> handler completion -> EOI emission

GIC delivery flow (sim-gic, enforced in sim-delivery):

Peripheral IRQ -> Distributor enqueue -> Redistributor targeting
  -> CPU-interface arbitration -> priority masking -> active-state transition

Wire trace record header (sim-trace / sim-wire):

struct TraceRecordHeader
  magic: u32;
  version: u16;
  checksum: Sha256;
  timestamp: LogicalTime;
  sequence: u64;
  payload_type: PayloadType;
  payload_length: u32;

Delivery sequence diagram:

Device -> IOAPIC:          Assert IRQ
IOAPIC -> DeliveryEngine:  Route Interrupt
DeliveryEngine -> LAPIC:   Queue Vector
LAPIC -> CPU:              Signal Pending Interrupt
CPU -> LAPIC:              Accept Interrupt
CPU -> Handler:            Execute ISR
Handler -> LAPIC:          Send EOI
LAPIC -> DeliveryEngine:   Release Vector

Malformed input examples and expected behavior (validated at sim-config / sim-delivery boundary, P13): interrupt vector outside [0, 65536); destination CPU missing from topology (I8); priority class outside the defined PriorityClass enum range; EOI issued for an inactive vector (I5). Expected behavior in every case: reject the event, emit a structured diagnostic naming the violated invariant, preserve runtime integrity (no partial state mutation, per P13).

11. Core Schema & Types

struct InterruptVector
  vector_id: u32;
  priority_class: PriorityClass;
  trigger_mode: TriggerMode;
  delivery_mode: DeliveryMode;

Ownership: immutable after creation (P14). Mutation: none — replacement, not in-place edit. Concurrency: shared via Arc, no interior mutability. Persistence: embedded verbatim in InterruptEvent records. Serialization: Protobuf, append-only field evolution (P7/ADR-05). Compatibility: new fields default-optional; no renumbering (ADR-05).

enum InterruptState
  Idle, Pending, Delivered, Active, EoiPending, Completed, RetryPending, Failed,

Ownership: owned by the InterruptEvent it tags. Mutation: transition-only, enforced by sim-delivery per §8's state machine. Concurrency: single-writer per event (owning domain worker). Persistence: every transition is a new WAL record (I7). Serialization: Protobuf enum, append-only variants. Compatibility: unknown future variants must round-trip as Failed on old readers.

struct DeliveryDescriptor
  source_controller: ControllerId;
  destination: CpuMask;
  retry_budget: u16;
  priority: u8;

Ownership: owned by sim-delivery for the lifetime of one delivery attempt. Mutation: retry_budget decrements monotonically (I9). Concurrency: not shared across workers — cloned per attempt. Persistence: logged at each retry (I7). Serialization: Protobuf. Compatibility: append-only.

struct ReplayRecord
  sequence: u64;
  timestamp: LogicalTime;
  payload: EventPayload;

Ownership: sim-trace WAL. Mutation: none — append-only (I7). Concurrency: single WAL writer per domain, ordered by sequence. Persistence: this is the persistence layer. Serialization: TraceRecordHeader + Protobuf payload (§8). Compatibility: payload is a versioned oneof (ADR-05).

trait EventQueueHandle
  fn push(event: InterruptEvent) -> Result<(), QueueFull>;
  fn pop() -> Option<InterruptEvent>;

Ownership: one handle per bounded queue (sim-eventbus). Mutation: internal ring-buffer cursor state. Concurrency: bounded MPSC, deterministic dequeue ordering (ADR-09, I3). Persistence: transient — not itself persisted, but every push is preceded by a WAL append (I7). Serialization: n/a (in-process only).

trait LogicalClock
  fn now() -> LogicalTime;
  fn advance(delta: TickDelta);

Ownership: sim-clock, one instance per simulation run. Mutation: monotonic advance only (I1). Concurrency: read-shared, single-writer advance behind a synchronization barrier. Persistence: LogicalTime values are embedded in every record (I7). Serialization: u64 tick count. Compatibility: stable representation, never renumbered.

struct TopologyGraph
  cpus: Vec<CpuNode>;
  controllers: Vec<ControllerNode>;
  routing_table: RoutingTable;

Ownership: sim-topology; immutable snapshot once validated (I8). Mutation: only via explicit topology-diff + revalidation (§14), never in place. Concurrency: shared read-only Arc across all domain workers after load. Persistence: hashed and logged at startup (§14.10). Serialization: TOML on ingest (config-format choice, not an ADR-table entry), binary-hashed internally. Compatibility: topology-hash field guards cross-version replay mismatch (T4, §22).

trait InterruptController
  fn enqueue(event: InterruptEvent);
  fn acknowledge(vector: u32);
  fn eoi(vector: u32);
  fn snapshot() -> Snapshot;

Ownership: implemented separately by sim-apic and sim-gic behind one trait boundary. Mutation: internal ISR/IRR/TMR or distributor/redistributor state, always transition-checked (I2, I5). Concurrency: one controller instance owned per CPU/domain worker — no cross-CPU sharing. Persistence: snapshot() feeds sim-storage. Serialization: n/a at the trait level; Snapshot is Protobuf. Compatibility: trait signature is the stable seam between APIC and GIC backends.

struct SnapshotDescriptor
  snapshot_id: Uuid;
  generation: u64;
  checksum: Sha256;

Ownership: sim-storage. Mutation: none — one descriptor per generation. Concurrency: read-shared during restore. Persistence: indexes the binary snapshot blob (ADR-13). Serialization: Protobuf header + binary payload. Compatibility: generation monotonically increases; checksum enforces I11.

enum SimError
  QueueOverflow, InvalidTopology, ReplayDivergence,
  SerializationFailure, LockViolation, PriorityCorruption,

Ownership: crate-wide error taxonomy, re-exported from sim-core. Mutation: n/a (error value, not mutable state). Concurrency: Send + Sync, freely passed across worker boundaries. Persistence: fatal variants (ReplayDivergence, PriorityCorruption) are logged to the WAL before termination. Serialization: structured log field error_kind. Compatibility: append-only enum, never renumbered — old trace readers must still recognize legacy error kinds.

struct TraceRecordHeader
  magic: u32;
  version: u16;
  checksum: Sha256;
  timestamp: LogicalTime;
  sequence: u64;
  payload_type: PayloadType;
  payload_length: u32;

Ownership: sim-wire; prefixes every WAL/snapshot record. Mutation: none, write-once. Concurrency: constructed synchronously by the writing domain worker. Persistence: the on-disk framing format itself. Serialization: fixed-width binary header + varint-framed payload. Compatibility: version field gates decoder behavior; unknown payload_type values are skippable, not fatal (P7).

12. Phase 0 — Runtime Skeleton, Deterministic Clock, and Repository Bootstrap

12.1 Objectives

Establish the correctness kernel every later phase depends on: deterministic logical time, lifecycle orchestration, bounded worker scheduling, deterministic startup ordering, and structured shutdown. No interrupt semantics exist yet — this phase exists purely to make everything above it replayable (P1, P6). Constraints introduced: startup must complete under 2 sec for a 256-CPU topology (§4); shutdown under 5 sec; zero nondeterministic timestamps anywhere in the call graph.

12.2 Detailed Implementation Steps

Implement sim-core/src/runtime.rs, sim-core/src/bootstrap.rs, sim-core/src/shutdown.rs, and sim-clock/src/logical.rs. Introduce a worker registry keyed by NUMA-domain ID (ADR-08), a startup dependency graph resolved topologically before any worker runs, a monotonic tick allocator guarded by I1, and a lifecycle state machine (Uninitialized -> Bootstrapping -> Running -> Draining -> Terminated). Add startup barriers (sim-clock/src/barrier.rs) so no worker observes a tick before every peer has registered — this directly implements P12 (Time Is a First-Class API): LogicalClock::now() is never read before the barrier releases. Add panic-isolation domains per worker (I14) and deterministic RNG seeding threaded explicitly through bootstrap, never read from an ambient source (P1). Instrumentation: startup-duration histogram, tick-advancement counter, scheduler queue-depth gauge, all wired through sim-observability stubs even though later phases own their real content. Testing harness: sim-testkit/src/harness.rs gains a monotonicity property test and a 1000-run replay-reproducibility test, per Herlihy & Shavit's memory-ordering discipline (§5) applied to the tick allocator.

12.3 Deliverable

A runnable simulator shell: sim-cli boots, initializes the worker registry, advances the logical clock deterministically for N ticks with no registered controllers, and shuts down cleanly. No interrupts are modeled yet — this is pure scaffolding, but it is a real, executable binary.

12.4 Acceptance Criteria

100% deterministic replay across 1000 consecutive runs (zero divergence, I1/I3); startup under 500 ms for a 0-CPU topology and under 2 sec for a 256-CPU topology (§4); zero queue-depth growth over a 10-minute idle soak; zero nondeterministic timestamps detected by the sim-testkit clock auditor across all 1000 runs.

12.5 Conformance Fixtures

fixtures/clock/basic_tick.bin — single-domain tick-advancement trace, expected monotonically increasing sequence. fixtures/clock/regression_monotonicity.bin — replay of a historical regression where a race produced a tick regression; expected: assertion fires at the exact regressed tick. fixtures/runtime/startup_order.toml — a 12-worker dependency graph; expected startup order is the unique topological sort.

12.6 Pitfalls

Tick regression — manifestation: LogicalTime observed to decrease across two reads; root cause: concurrent tick updates without the barrier (12.2); debugging method: replay regression_monotonicity.bin under the clock auditor; signal: clock_regression_total > 0; recovery: terminate, preserve snapshot (I1). Worker startup race — manifestation: nondeterministic worker registration order across runs; root cause: unsynchronized barrier wait; debugging method: diff two runs' bootstrap logs; signal: startup_order.toml fixture produces a different order per run; recovery: fix barrier release condition, never retry blindly. Replay drift from wall-clock usage — manifestation: divergence appears only outside CI (different wall-clock jitter); root cause: a stray SystemTime::now() call bypassing P12; debugging method: grep for ambient time reads outside sim-clock; signal: divergence correlates with wall-clock time of day, not tick count; recovery: remove the read, route through LogicalClock.

12.7 Performance Concerns

Avoid allocator churn in the tick-advancement hot path — pre-allocate the tick-event pool at bootstrap. Avoid mutex contention in the scheduler registry by sharding it per NUMA domain (ADR-08). Maintain cache locality for worker metadata by packing registry entries to 64-byte cache-line boundaries (§4 cache-line assumption).

12.8 Edge Cases

Zero-worker runtime (must still boot and shut down cleanly); startup panic during barrier wait (must not deadlock peers waiting at the same barrier); scheduler starvation under a pathological dependency graph (must be detected as a cycle at bootstrap, not a hang); shutdown requested mid-tick advancement (must complete the in-flight tick before draining).

12.9 Failure Analysis

If runtime bootstrap fails: preserve the partial startup trace (for forensics), emit a structured diagnostic naming the failing dependency-graph node, and prevent partial startup state from being reused by a subsequent retry (P4 — crash-only, not patch-and-continue). Blast radius is contained to the single bootstrap attempt; no controller state exists yet to corrupt.

12.10 Operational Notes

Expose /metrics (Prometheus, ADR-12) from first boot even with no controllers registered. Metrics: runtime_startup_duration_seconds (histogram), replay_divergence_total (counter, stays zero here), worker_startup_latency_seconds (per-worker histogram). Tracing spans: bootstrap, shutdown. Structured log fields: worker_id, dependency_graph_hash, lifecycle_state. Deployment: this phase's binary is the base image layer for every later phase's Dockerfile.

13. Phase 1 — Event Bus and Queueing Infrastructure

13.1 Objectives

Build the replay-safe, bounded, priority-aware event transport that every controller crate will depend on. Introduces the queue-boundedness invariant (I4) and the backpressure principle (P8) as enforced code, not policy. No interrupt semantics yet — this phase moves opaque InterruptEvent envelopes, it does not interpret them.

13.2 Detailed Implementation Steps

Implement sim-eventbus/src/queue.rs (bounded lock-free ring buffer, per Herlihy's wait-free synchronization design, §5), sim-eventbus/src/router.rs (deterministic dequeue ordering across per-domain and priority-aware dispatch queues), and sim-eventbus/src/backpressure.rs (P8 enforcement — a saturated queue signals the producer synchronously rather than absorbing the event). Add per-domain queues sharded by NUMA node (ADR-08) and replay-sequencing queues that assign a monotonic sequence (feeding ReplayRecord, §11) at enqueue time under I3. Implement the event envelope (sim-wire/src/envelope.rs) carrying causal correlation IDs (Sigelman et al., §5) and the replay sequence number. Cache-line-pad queue head/tail indices per §4's 64-byte assumption to avoid false sharing (Mellor-Crummey & Scott, §5) — this is the direct anchor for P11's lock- ordering discipline extended to lock-free structures. Telemetry: queue-occupancy histograms, enqueue-rejection counters, queue-stall timers, wired through sim-observability stubs from Phase 0.

13.3 Deliverable

A deterministic, bounded event-transport library usable independently of any controller: producers push InterruptEvent envelopes, consumers pop them in a provably deterministic order under replay, and saturation is observable before it becomes fatal.

13.4 Acceptance Criteria

Zero dropped events under sustained load below capacity; queue overflow is always detected within one enqueue attempt (100% detection rate across fixtures/eventbus/overflow.trace); deterministic dequeue ordering verified byte-identical across 500 replay runs; sustained throughput of at least 1,000,000 events/sec on a single domain queue (10% of the §4 system-wide 10M target, since Phase 1 tests one domain in isolation).

13.5 Conformance Fixtures

fixtures/eventbus/saturation.trace — enqueue rate exceeding capacity; expected: backpressure signal fires before the Nth enqueue where N = configured capacity. fixtures/eventbus/ replay_order.trace — interleaved multi-producer enqueue sequence; expected: replayed dequeue order matches recorded order exactly (I3). fixtures/eventbus/overflow.trace — deliberate overflow; expected: queue_overflow_total increments exactly once and the queue rejects further enqueues (I4).

13.6 Pitfalls

ABA queue corruption — manifestation: a popped-then-repushed slot is read as though never popped; root cause: reused ring-buffer slot without a generation tag; debugging method: replay replay_order.trace with generation-tag assertions enabled; signal: sequence-number gaps; recovery: add a generation counter per slot. False sharing on queue indices — manifestation: throughput collapses under multi-core contention despite low logical load; root cause: head/tail indices sharing a cache line; debugging method: perf c2c cache-line contention profile; signal: cross-core cache-miss rate spike; recovery: pad indices to 64 bytes (12.7). Priority starvation — manifestation: low-priority queue never drains under sustained high-priority traffic; root cause: naive strict-priority dequeue with no fairness bound; debugging method: replay under a synthetic high-priority flood; signal: low-priority queue depth monotonically increases; recovery: bounded fairness quota, deferred formally to Phase 6 (§18) but flagged here. Replay reordering — manifestation: two runs of the same trace dequeue in different order; root cause: nondeterministic tie-breaking on equal-priority, equal-timestamp events; debugging method: diff dequeue order across two runs; signal: replay_sequence_mismatch_total > 0; recovery: make the tie-break a deterministic function of event_id, never of memory address.

13.7 Performance Concerns

Cache-line padding on queue indices (12.6); branch-prediction-friendly dequeue path (priority check before mode check, hottest branch first); lock contention avoided entirely on the common path via lock-free CAS, with a fallback slow path only under contention exceeding a tunable threshold.

13.8 Edge Cases

Queue full during shutdown drain (must still flush deterministically, not drop silently); replay attempts to reorder relative to the recorded trace (must be rejected, not silently corrected); duplicate event_id values from a misbehaving producer (must be rejected at envelope validation, not deduplicated silently).

13.9 Failure Analysis

Overflow is fatal by design (§4: "queue overflow tolerance — none"): silent event loss invalidates every replay guarantee built on top of this phase (I3, I4). Detection is synchronous at enqueue time; blast radius is contained to the overflowing domain queue, which triggers I14's panic isolation rather than a global halt, but the domain's simulation results are marked invalid for that run.

13.10 Operational Notes

Expose per-domain queue metrics: eventbus_queue_depth (gauge), eventbus_enqueue_rejected_total (counter), eventbus_dequeue_latency_seconds (histogram). Tracing spans: enqueue, dequeue, tagged with the causal correlation ID from the envelope. Rollback implication: this crate's wire format (envelope) is versioned from day one (P7) because every later phase depends on it.

14. Phase 2 — Topology Engine

14.1 Objectives

Implement the CPU and interrupt-domain topology graph that all controller and delivery logic will route against. Introduces topology referential integrity (I8) as an enforced load-time invariant and establishes the topology-hash mechanism that later guards cross-version replay (T4, §22).

14.2 Detailed Implementation Steps

Implement sim-topology/src/graph.rs (CPU graph, controller graph, routing maps, affinity masks), sim-topology/src/validation.rs (referential-integrity pass enforcing I8, disconnected-graph detection, duplicate-vector detection, invalid-routing-target detection), and sim-topology/ src/routing.rs (routing-table construction from validated graph data). Add topology hashing (stable hash of the validated graph, embedded in every TopologyGraph per §11) so replay can detect topology drift (T4), immutable topology snapshots (P14 applied to topology, not just events), and a topology-diff engine for live mutation (bounded to < 50 ms pause per §4). Parse topology from TOML (sim-config/src/parser.rs — deterministic parsing over YAML's ambiguous scalar coercion; a config-format choice orthogonal to the §9 ADR table) into the MADT-inspired CPU/interrupt-controller enumeration model (ACPI Specification's MADT, per §5) before validation runs. Validation failures produce a structured diagnostic naming the exact offending node, per P13.

14.3 Deliverable

A validated, immutable, hashed topology runtime: given a TOML topology description, the engine either produces a fully validated TopologyGraph or rejects the input with a specific diagnostic before any controller state is constructed.

14.4 Acceptance Criteria

Invalid topology rejected in 100% of fixtures/topology/invalid_cpu.toml and cyclic_route.toml cases; topology load completes under 1 second for a 4096-CPU topology (§4); topology hashing is deterministic — identical topology input produces an identical hash across 100 runs; live topology mutation pause stays under 50 ms (§4) on a 1024-CPU topology.

14.5 Conformance Fixtures

fixtures/topology/dual_socket.toml — canonical 2-socket, 64-core-per-socket topology; expected: valid load, hash stable across reloads. fixtures/topology/invalid_cpu.toml — routing entry referencing a nonexistent CPU ID; expected: rejected with topology_dangling_ref_total incrementing (I8). fixtures/topology/cyclic_route.toml — a routing cycle; expected: rejected at the disconnected/cyclic-graph validation pass.

14.6 Pitfalls

Inconsistent affinity masks after a live mutation (manifestation: a CPU removed from topology still appears in a stale routing entry's mask; root cause: diff engine not atomically swapping the routing table; recovery: apply mutations as a single atomic snapshot swap, never incremental in-place edits, per P14). Duplicate controller IDs across a merged multi-file topology (root cause: naive file concatenation without ID-namespace validation; recovery: validation pass rejects at load). Stale topology references surviving a reload (root cause: a component cached a raw pointer instead of the Arc<TopologyGraph> snapshot handle; recovery: enforce handle-only access via the type system, never raw references, per ADR-08's ownership discipline).

14.7 Performance Concerns

Graph-traversal locality: lay out CpuNode entries contiguously by NUMA domain so affinity-mask computation stays cache-resident. Immutable-snapshot copying overhead: use Arc sharing rather than deep-copying the graph on every read, deep-copying only on mutation-diff application.

14.8 Edge Cases

Zero-controller topology (must load and simulate an idle system, not error); topology mutation attempted mid-replay (must be rejected outright — replay pins one topology hash for its entire duration, T4); a topology declaring more CPUs than the §4 ceiling of 4096 (must be rejected at parse time, not truncated silently); a NUMA-aware topology whose domain-worker assignment (ADR-08) does not evenly divide the CPU count (must fall back to a documented remainder-assignment rule, not panic). Fully automatic NUMA-aware interrupt rebalancing in response to live affinity drift is PhaseDeferred("§14") and registered in §35 — Phase 2 validates and hashes static affinity masks only; it does not yet re-balance them under load.

14.9 Failure Analysis

Topology corruption invalidates every downstream delivery guarantee: a dangling routing reference that escapes validation would let sim-delivery route an interrupt to a nonexistent CPU, silently dropping it outside the queue-overflow detection path (I4) entirely. Detection must therefore be exhaustive at load time (P13), never deferred to first-use. Containment: a validation failure rejects the entire topology load; no partial topology is ever installed.

14.10 Operational Notes

Topology fingerprints (hash + CPU/controller counts) are logged at startup and exported as a topology_fingerprint structured-log field on every subsequent record for the run's duration — this is what §22's T4 mitigation (pinned topology hash in the replay manifest) consumes. Migration: a topology-format version bump requires a sim-config schema-migration pass documented in docs/adr/overview.md before old topology files can be re-validated.

15. Phase 3 — Local APIC / x2APIC Implementation

15.1 Objectives

Implement x86 Local APIC semantics: IRR/ISR/TMR management, EOI handling, vector prioritization, x2APIC mode, and the LAPIC timer. This is the first phase that models real interrupt-controller behavior rather than infrastructure, and it is the first conformance target (§26) against the Intel SDM (§5).

15.2 Detailed Implementation Steps

Implement sim-apic/src/lapic.rs (core LAPIC state machine implementing the InterruptController trait, §11), sim-apic/src/irr.rs (interrupt request register as a 256-bit vector bitmap), sim-apic/src/isr.rs (in-service register enforcing I2's vector-uniqueness invariant and I10's nesting-stack ordering), and sim-apic/src/timer.rs (periodic and one-shot LAPIC timer modes). Algorithms: highest-priority-vector selection via bitmap scan (priority-class-ordered, per the Intel SDM's arbitration description, §5), nesting-stack push/pop on interrupt entry/EOI (I10), and vector masking. x2APIC mode reuses the same state machine behind an MSR-style wider-addressing front end rather than a parallel implementation (P15 — compatibility before optimization: do not special-case x2APIC's faster MSR path at the expense of a second, divergent state machine). Instrumentation: vector-activation-latency histogram, active-vector-depth gauge, EOI-timing histogram. This is the anchor point for Understanding the Linux Kernel's APIC-handling chapters (§5) and directly informs how sim-delivery's dispatcher (§18) will call into this trait.

15.3 Deliverable

A functional LAPIC simulation: IRR/ISR/TMR state transitions are conformant with documented Intel behavior, EOI ordering is enforced, and nested interrupts (higher-priority preempting lower) resolve correctly.

15.4 Acceptance Criteria

100% pass rate against the SDM-derived conformance fixtures below; nested-interrupt depth up to 16 validated without stack corruption (I10); EOI issued for an inactive vector is rejected in 100% of fixtures/apic/eoi_order.trace mutation cases (I5); vector-activation p99 latency under 100 µs simulated (§4) at 1024 active CPUs.

15.5 Conformance Fixtures

fixtures/apic/eoi_order.trace — a sequence of activations and EOIs including one out-of-order EOI; expected: the malformed EOI is rejected, in-order ones succeed. fixtures/apic/ nested_interrupt.trace — three nested priority levels; expected: ISR stack unwinds in exact reverse-priority order (I10). fixtures/apic/timer_periodic.trace — 10,000-tick periodic timer run; expected: zero drift beyond the configured tolerance (§4 clock-drift-tolerance = 0 in deterministic mode).

15.6 Pitfalls

ISR corruption — manifestation: a vector remains marked active after its EOI; root cause: EOI handler updating the wrong bitmap index; debugging method: replay eoi_order.trace with the ISR bitmap dumped per tick; signal: interrupt_duplicate_active_total > 0 (I2); recovery: terminate (I10 is fatal by design). Vector priority inversion — manifestation: a lower-priority vector services before a pending higher-priority one; root cause: bitmap scan starting from the wrong end or a stale priority cache; debugging method: replay nested_interrupt.trace; signal: ISR stack order fixture mismatch; recovery: fix scan direction, add a regression fixture. Timer drift — manifestation: periodic timer ticks accumulate skew over a long run; root cause: timer reprogrammed from wall-clock-derived delta instead of logical-tick delta (violates P12); debugging method: replay timer_periodic.trace and compare tick deltas; signal: drift metric nonzero; recovery: reprogram strictly from LogicalClock. Invalid EOI release — manifestation: EOI for a vector never activated corrupts an unrelated vector's state; root cause: missing target validation before release; debugging method: fuzz EOI targets against sim-fuzz; signal: I5 detector fires; recovery: validate target before any state mutation (P13's discipline applied inline).

15.7 Performance Concerns

Bitmap-scan optimization: use hardware find-first-set intrinsics over the 256-bit IRR/ISR bitmaps rather than a linear priority loop. Cache locality for vector tables: keep IRR/ISR/TMR bitmaps for one LAPIC contiguous within one cache line group to minimize cross-line scans during arbitration.

15.8 Edge Cases

Spurious interrupts (vector with no corresponding IRR bit set reaching ISR — must be logged and discarded per documented spurious-vector semantics, not treated as an error); duplicate EOIs for the same vector (second EOI rejected, I5); vector wraparound at the 256-vector-per-LAPIC boundary in legacy (non-x2APIC) addressing mode (must clamp/reject, not overflow into an adjacent bitmap word).

15.9 Failure Analysis

Incorrect ISR state produces interrupt storms (a vector that never clears stays permanently "pending" and keeps re-arbitrating), starvation (a corrupted priority ordering starves a class entirely), or dead vectors (a vector stuck active blocks all future activity on that slot). Detection is via I2/I5/I10's dedicated assertions; containment is per-CPU (one corrupted LAPIC does not affect peer CPUs' LAPIC state, per P9); operator visibility is the per-vector metrics below.

15.10 Operational Notes

Expose per-vector metrics: apic_vector_active_depth (gauge, per CPU), apic_eoi_latency_seconds (histogram), apic_spurious_interrupt_total (counter). Tracing spans: irr_insert, isr_activate, eoi_emit. Compatibility: the LAPIC state-machine trait boundary (InterruptController, §11) is what lets x2APIC mode ship as an additive front end without a breaking change to sim-delivery.

16. Phase 4 — IOAPIC and External Interrupt Routing

16.1 Objectives

Implement IOAPIC redirection-table semantics: masking, delivery-mode routing, edge- and level-trigger handling, and pin-to-vector routing from external devices into the LAPIC layer built in Phase 3. Introduces the MSI-X deferral decision point for this blueprint's scope.

16.2 Detailed Implementation Steps

Implement sim-ioapic/src/redirection.rs (redirection-table entries per the Intel MultiProcessor Specification 1.4 legacy layout, §5) and sim-ioapic/src/router.rs (pin-assertion-to-vector routing, delivery-mode dispatch into sim-delivery). Add edge-trigger tracking (single-shot assertion, cleared on acceptance) and level-trigger tracking (assertion persists until the source deasserts, requiring an explicit pending-assertion state distinct from InterruptState::Pending, §8) and masking semantics that must desynchronize-safely with in-flight pending assertions (P13). The redirection-table entry format intentionally excludes an MSI-X capability table — full MSI-X table emulation is PhaseDeferred("§16") and registered in §35, since it requires PCIe device modeling explicitly out of scope (§1). Firecracker's minimal interrupt-injection path (§5) is the model for keeping this router's surface small rather than replicating QEMU's full device-model coupling (§5 pitfall).

16.3 Deliverable

Interrupt routing from external sources through the IOAPIC into the Phase 3 LAPIC layer, with correct edge/level semantics and masking.

16.4 Acceptance Criteria

Level-triggered replay correctness verified byte-identical across 200 runs of fixtures/ioapic/level_trigger.trace; routing determinism holds under edge_trigger.trace; masking correctness: a masked pin's pending assertion is held, never dropped, verified across 1000 mask/unmask cycles; routing-table lookup p99 under 10 µs simulated at 240 redirection entries (the legacy IOAPIC pin count ceiling).

16.5 Conformance Fixtures

fixtures/ioapic/level_trigger.trace — a level-triggered source asserted before the destination CPU is ready to accept; expected: assertion persists, delivered exactly once on acceptance, no duplicate delivery. fixtures/ioapic/edge_trigger.trace — back-to-back edge assertions on the same pin; expected: each is a distinct InterruptEvent, no coalescing.

16.6 Pitfalls

Stuck level-triggered interrupt (manifestation: a level source never clears even after acceptance; root cause: EOI path not deasserting the level line's pending-assertion flag; recovery: tie level deassertion explicitly to EOI completion, not to delivery). Routing loops (manifestation: a misconfigured redirection entry routes back into its own source domain; root cause: missing topology-level cycle check, I8 gap at the routing layer specifically; recovery: extend Phase 2's cyclic-route validation to cover IOAPIC redirection targets, not just CPU topology). Mask desynchronization (manifestation: an unmask operation loses a pending assertion that arrived while masked; root cause: mask/unmask not atomic with the pending-assertion flag; recovery: single compare-and-swap covering both fields).

16.7 Performance Concerns

Routing-table lookup locality: index redirection entries by pin number in a flat array, not a hash map, since the domain (0–239) is small and dense.

16.8 Edge Cases

Simultaneous assertion on multiple pins targeting the same destination CPU in the same tick (must resolve via Phase 6's arbitration, not silently coalesce); a masked pending interrupt that is unmasked exactly at shutdown (must either deliver-then-drain or explicitly document drop-on- shutdown — this blueprint chooses deliver-then-drain to preserve P6).

16.9 Failure Analysis

Incorrect masking can create unbounded storms (a level source repeatedly re-asserting into a mis-cleared pending flag re-enters the queue every tick). Detection: queue-occupancy telemetry from Phase 1 spikes correlated with a single source pin ID; containment: per-pin rate limiting is a documented mitigation surfaced in §22 (T8), not built into this phase's core path.

16.10 Operational Notes

Emit routing-decision traces: ioapic_route_total{pin, delivery_mode} (counter), ioapic_mask_ state (gauge per pin). Rollback: redirection-table format is versioned identically to the general Protobuf schema discipline (P7); an IOAPIC-only rollback does not require a topology-format bump.

17. Phase 5 — GICv2/GICv3 Simulation

17.1 Objectives

Implement ARM Generic Interrupt Controller semantics: distributor state, redistributor state, SGI delivery, PPI routing, SPI arbitration, and the GICv2→GICv3 affinity-routing shift from a flat distributor-owned CPU targeting model to a per-CPU redistributor. This is the second conformance target (§26), against the ARM GIC specifications (§5).

17.2 Detailed Implementation Steps

Implement sim-gic/src/distributor.rs (shared interrupt state for SPIs, group configuration), sim-gic/src/redistributor.rs (per-CPU state for SGIs/PPIs, introduced by GICv3 per ARM IHI 0069, §5, to eliminate the GICv2 distributor's single-shared-table bottleneck), and sim-gic/ src/priority.rs (priority masking mirroring the LAPIC arbitration model from Phase 3 behind the same InterruptController trait, §11, per P15's compatibility-over-optimization discipline — GIC and APIC share one delivery contract). Add affinity routing (GICv3's Aff0-Aff3 addressing scheme mapped onto the topology graph's CpuMask, §11), CPU-interface state, and interrupt groups (Group 0/Group 1, gating which priority-mask register applies). Mental model MM6 (§30) applies directly here: treat the redistributor as a per-CPU cache of distributor state, and design its desynchronization detection the same way a cache-coherence protocol would — a redistributor's SGI target set must never diverge from the distributor's authoritative affinity table (I13).

17.3 Deliverable

A functional GIC simulation runtime supporting both GICv2 (flat distributor-only) and GICv3 (distributor + per-CPU redistributor) behind one configuration switch, sharing the arbitration core with sim-apic.

17.4 Acceptance Criteria

GICv2 fixture compatibility: 100% pass on fixtures/gic/sgi.trace and spi_route.trace under flat-distributor mode; GICv3 redistributor correctness: affinity-routed SGI delivery verified byte-identical across 200 replay runs; distributor↔redistributor desync detector fires within one tick of an injected inconsistency (I13); SPI arbitration p99 under 100 µs simulated (§4) at 4096 CPUs.

17.5 Conformance Fixtures

fixtures/gic/sgi.trace — software-generated-interrupt broadcast to 8 target CPUs; expected: all 8 redistributors observe delivery in the same tick, order between them is defined as CPU-ID-ascending (a deterministic tie-break, not an arbitrary one). fixtures/gic/spi_route.trace — shared peripheral interrupt routed via affinity mask to a 3-CPU subset; expected: exactly those 3 CPUs' redistributors see the pending state.

17.6 Pitfalls

Redistributor desynchronization — manifestation: a redistributor's cached affinity view diverges from the distributor's authoritative table after a topology mutation; root cause: the Phase 2 topology-diff engine's atomic swap (14.6) not fanned out to per-CPU redistributor caches; debugging method: replay with I13's mask-validity check enabled every tick, not just on mutation; signal: affinity_mask_invalid_total > 0; recovery: redistributor caches must subscribe to the same atomic snapshot handle as the distributor, never a separately-timed copy. Affinity corruption — manifestation: an SGI reaches the wrong CPU set; root cause: Aff0-Aff3 decoding bug mapping an affinity level incorrectly onto the CpuMask; debugging method: replay sgi.trace with affinity-decode tracing; signal: fixture target-set mismatch; recovery: unit-test the affinity-decode function directly against ARM IHI 0069's worked examples (§5).

17.7 Performance Concerns

Affinity-routing cache pressure: per-CPU redistributor state should stay resident in that CPU's local cache/NUMA-local memory (§4 NUMA assumption), not centrally pooled — a shared-pool layout reintroduces the GICv2 distributor bottleneck GICv3 exists to remove.

17.8 Edge Cases

SGI broadcast storms (all-CPU broadcast IPI-equivalent — must be rate-limited at the same mechanism as Phase 6's IPI broadcast path, not a separate GIC-only limiter); redistributor offline transitions (a CPU hot-removed from topology mid-run — its redistributor's pending SGIs must be explicitly drained or rejected, never silently lost, per I4's spirit extended to GIC state). ARM's Locality-specific Peripheral Interrupts (LPIs) and RISC-V's IMSIC/APLIC equivalent controller family are explicitly out of Phase 5 scope: RISC-V IMSIC/APLIC support is PhaseDeferred("§17") and registered in §35.

17.9 Failure Analysis

Priority corruption in the GIC path breaks fairness guarantees identically to Phase 3's ISR corruption (15.9) — the two controllers share I10's nesting-stack invariant. Detection is via the same priority-stack assertion; containment is per-CPU-interface, isolated from the distributor's shared state where possible, but a distributor-level corruption (shared SPI table) has a larger blast radius than a single redistributor's corruption by construction.

17.10 Operational Notes

Expose distributor queue metrics: gic_distributor_pending_spi (gauge), gic_redistributor_ desync_total (counter), gic_sgi_broadcast_latency_seconds (histogram). Compatibility: the GICv2/GICv3 mode switch is a topology-level configuration flag, not a build-time feature flag, so one binary supports both without recompilation.

18. Phase 6 — Interrupt Arbitration, Priority Engine, IPI, and Timers

18.1 Objectives

Implement the delivery-arbitration engine that both sim-apic and sim-gic route through: vector priority classes, nested arbitration, fairness/starvation-bounded retry, plus IPI delivery (targeted and broadcast) and the timer-wheel facility backing periodic/deadline timers system-wide. This phase closes the loop opened by Phase 1's priority-aware dispatch queues.

18.2 Detailed Implementation Steps

Implement sim-priority/src/arbitration.rs (highest-priority-first selection across pending vectors from both APIC and GIC sources), sim-priority/src/nesting.rs (I10's active-stack tracking, shared by both controller backends), sim-delivery/src/dispatcher.rs (the central arbitration entry point diagrammed as the protocol boundary in §3), and sim-delivery/ src/retry.rs (bounded retry scheduling enforcing I9). Add sim-ipi/src/broadcast.rs (broadcast IPI, including TLB-shootdown simulation) and sim-ipi/src/shootdown.rs (targeted-IPI reschedule semantics), plus sim-timer/src/wheel.rs and sim-timer/src/deadline.rs (system-wide timer facilities feeding both periodic LAPIC timers, Phase 3, and GIC-side timer-equivalent SGIs). Algorithms: highest-priority-first arbitration (Anderson, Lazowska & Levy's scheduler-interaction analysis, §5, applies directly — interrupt arbitration is a scheduling decision), bounded starvation prevention via an aging counter per pending vector (Mellor-Crummey & Scott's fairness discipline under contention, §5), and retry scheduling capped by retry_budget (§11). Xen's event-channel model (§5) informs how a virtualized/injected interrupt is represented as just another arbitration input rather than a privileged bypass path — this is the seam where virtualized-injection support would plug in if un-deferred. VT-d interrupt remapping and nested virtualization interrupt injection are both explicitly out of scope here and are PhaseDeferred("§18"), registered in §35.

18.3 Deliverable

A priority-aware, fairness-bounded interrupt-delivery engine unifying APIC and GIC arbitration behind one dispatcher, plus functional IPI and timer facilities feeding it.

18.4 Acceptance Criteria

Starvation detector validated: no pending vector waits more than 64 arbitration rounds under sustained high-priority flood (fixtures/priority/starvation.trace); nesting correctness across 16 levels (I10); bounded retry latency — 100% of retried deliveries resolve within retry_budget attempts (I9) with zero livelocks across 500 fuzz runs; IPI broadcast to 4096 CPUs completes within the p99 delivery budget (§4).

18.5 Conformance Fixtures

fixtures/priority/starvation.trace — sustained high-priority flood against a low-priority pending vector; expected: aging counter forces eventual delivery within the 64-round bound. fixtures/priority/nesting.trace — 16-level nested preemption; expected: unwinds in exact reverse order, matching Phase 3's nested_interrupt.trace semantics extended to cross-controller arbitration.

18.6 Pitfalls

Livelock — manifestation: two equal-priority vectors perpetually retry against each other with neither completing; root cause: retry scheduling without a deterministic tie-break; debugging method: replay under the fuzz corpus targeting equal-priority collisions; signal: delivery_retry_ exhausted_total climbing without corresponding completions; recovery: deterministic tie-break by event_id, identical discipline to Phase 1's dequeue tie-break (13.6). Starvation — manifestation: a low-priority class never completes under sustained load; root cause: missing aging mechanism; debugging method: replay starvation.trace; signal: fixture's 64-round bound violated; recovery: implement the aging counter, do not simply raise the priority-check frequency. Active-stack corruption — manifestation: I10 fires under IPI-heavy load specifically; root cause: IPI delivery bypassing the shared nesting-stack update path; debugging method: replay with IPI-only fixtures against the stack assertion; recovery: route IPI delivery through the same sim-priority nesting update as regular vectors, never a shortcut path (P15).

18.7 Performance Concerns

Heap allocation in the arbitration path must be zero on the steady-state path — pre-allocate the per-CPU pending-vector scan buffer at controller construction (Phase 3/5), reused across ticks. Lock contention under domain-worker boundaries (ADR-08) is bounded by keeping arbitration CPU-local; only IPI broadcast crosses domain boundaries and is explicitly the one place a cross-domain lock-ordering rule (I6/P11) applies.

18.8 Edge Cases

Equal-priority collisions (resolved by deterministic tie-break, 18.6); retry exhaustion (I9's bound reached — must escalate to a Failed state transition per §8, never spin indefinitely); IPI broadcast targeting a CPU mask that includes a CPU mid-removal from topology (must resolve against the pre-mutation snapshot, consistent with Phase 2's atomic-swap discipline).

18.9 Failure Analysis

Arbitration bugs cause nondeterministic latency, which is functionally equivalent to a replay divergence even when I3's strict ordering holds, because two runs with identical ordering can still diverge in wall-observable timing if arbitration itself is not a pure function of state — this phase's dispatcher must therefore be side-effect-free apart from the state transitions it commits. Detection: arbitration-latency histograms (18.10) flag distributional drift across otherwise identical replay runs.

18.10 Operational Notes

Expose arbitration-latency histograms: delivery_arbitration_latency_seconds, priority_starvation_rounds (gauge, max observed per vector), ipi_broadcast_fanout_latency_ seconds. Tracing spans: arbitrate, ipi_broadcast, retry_schedule. This is the busiest tracing surface in the system per §4's 10M events/sec target — sampling policy (not exhaustive spans) is mandatory here and is the direct motivating case for P10.

19. Phase 7 — Replay, Snapshots, and Persistence

19.1 Objectives

Implement deterministic replay end to end: append-only WAL, snapshot generation/restore, replay loader, and divergence detection. This phase makes P1/P6 executable rather than aspirational — it is where "byte-identical replay" becomes a testable property against real controller state from Phases 3–6.

19.2 Detailed Implementation Steps

Implement sim-trace/src/wal.rs (append-only WAL enforcing I7's ordering invariant), sim-replay/src/replayer.rs (replay execution loop consuming the WAL and re-driving Phases 0–6's state machines tick-for-tick), sim-replay/src/divergence.rs (divergence detector comparing live execution against recorded state, implementing Altekar & Stoica's output-determinism-checking discipline, §5), and sim-storage/src/snapshot.rs / sim-storage/src/compaction.rs (periodic snapshot generation and WAL compaction after a snapshot is durable). Add per-record checksums (SHA-256, feeding I11), trace compaction (drop WAL segments covered by a durable snapshot, never the segment currently being written), and replay cursors (ReplayRecord.sequence-indexed seek support bounded by the §4 200 ms seek-latency budget). Kleppmann's log-as-source-of-truth framing (DDIA, §5) is the direct design anchor: the WAL, not any in-memory structure, is the authoritative history, and every controller's live state is a materialized view derivable by replaying it.

19.3 Deliverable

A replayable deterministic runtime: any recorded WAL segment can be replayed to reproduce byte-identical controller state, snapshots can restore a run to a known point without replaying from the beginning, and divergence is detected automatically rather than discovered by manual diffing.

19.4 Acceptance Criteria

Byte-identical replay verified across 500 runs of fixtures/replay/divergence.trace's non- divergent baseline; divergence detection latency under 100 ms (§4 derived from C8, §32) once injected; snapshot restore under 5 sec for a 4 GB resident-state snapshot (§4, C6 derivation); replay seek latency under 200 ms to an arbitrary sequence number (§4).

19.5 Conformance Fixtures

fixtures/replay/divergence.trace — a WAL with one deliberately corrupted mid-stream record; expected: divergence detector fires within the sequence range containing the corruption, not at end-of-run. fixtures/replay/snapshot_restore.trace — a snapshot taken mid-run plus the WAL tail after it; expected: restoring the snapshot and replaying the tail reproduces the same terminal state as replaying the entire WAL from scratch.

19.6 Pitfalls

Replay skew — manifestation: replay reproduces state correctly but at a different logical-time alignment than the original run; root cause: LogicalTime not itself persisted per record, only inferred; debugging method: replay snapshot_restore.trace and diff per-record timestamps; recovery: persist LogicalTime explicitly in every ReplayRecord (§11), never re-derive it. Partial WAL writes — manifestation: a crash mid-fsync leaves a torn record at the WAL tail; root cause: no per-record checksum to detect a truncated write; debugging method: WAL integrity scan on load; signal: checksum mismatch at the exact torn offset; recovery: truncate to the last fully-checksummed record, resume from there (never attempt partial-record repair, per P4). Snapshot corruption — manifestation: a restored snapshot produces immediately-invalid controller state; root cause: bit-rot or an interrupted snapshot write; debugging method: checksum verification on every snapshot load (I11); recovery: restore the previous snapshot generation, per §23 FM-4.

19.7 Performance Concerns

WAL fsync amplification: batch multiple ReplayRecords per fsync call up to the §4 500 ms durability-window ceiling, trading a bounded window of at-risk records for throughput — this is the direct mechanism behind the RPO row in §4. Snapshot copy overhead: use copy-on-write semantics for the resident-state snapshot where the OS/allocator supports it, to avoid stalling live workers during snapshot capture beyond the §4 50 ms mutation-pause budget's spirit (snapshotting is not a topology mutation but should respect a comparable pause ceiling).

19.8 Edge Cases

Crash during snapshot capture (must leave the previous snapshot generation intact and valid, never a half-written one visible to a restore attempt); replay from a WAL segment with no preceding snapshot (must replay from tick zero, which must therefore always remain available or the run is unreplayable — a documented constraint, not a silent gap); compaction racing a concurrent snapshot (explicitly forbidden by 19.2's ordering rule — compaction must never run while a snapshot capture is in flight).

19.9 Failure Analysis

Replay divergence is fatal by design (§4: zero tolerated): it means the recorded history no longer predicts live behavior, invalidating every downstream conformance and capacity claim made against that trace. Detection is via the divergence detector's continuous per-record comparison, not an end-of-run summary; blast radius is the entire replay session, which must halt immediately (I3) and preserve the divergent record for forensics rather than skip past it.

19.10 Operational Notes

Metrics: wal_fsync_latency_seconds, replay_divergence_detection_latency_seconds, snapshot_ restore_duration_seconds. Replay manifests (naming the topology hash, snapshot generation, and WAL segment range) are versioned (P7) so a manifest produced by an older binary remains loadable. Migration: a WAL-format version bump requires a documented offline migration tool, never an in-place rewrite of archived traces.

20. Phase 8 — Observability Stack

20.1 Objectives

Implement the production-grade observability pipeline every earlier phase has been emitting stub telemetry toward: metrics registry, tracing spans, structured logging, and causal correlation IDs, now with real export and cardinality enforcement (P10/I12).

20.2 Detailed Implementation Steps

Implement sim-observability/src/metrics.rs (Prometheus-compatible registry, ADR-12, enforcing I12's cardinality boundedness) and sim-observability/src/tracing.rs (OpenTelemetry span export, ADR-11, implementing Sigelman et al.'s Dapper causal-propagation model, §5). Wire every metric stubbed in Phases 0–7 into the real registry: interrupt latency, queue occupancy, replay divergence, active vectors, plus the per-phase metrics named in each phase's N.10. Add structured-JSON logging (sim-observability/src/logging.rs) carrying causal_id, controller_id, cpu_target, and vector on every interrupt-related log line, directly implementing Barham et al.'s Magpie causality-reconstruction approach (§5) — a trace can be reconstructed purely from log correlation IDs without a live debugger attached. Sampling policy for the arbitration hot path (18.10) is enforced here at the registry level, not left to each caller's discretion. Hardware performance-counter-assisted trace export (e.g. Intel PT-style hardware tracing integration) is explicitly out of scope and is PhaseDeferred("§20"), registered in §35.

20.3 Deliverable

A full observability pipeline: metrics scrapeable via Prometheus, traces exportable via OpenTelemetry, structured JSON logs mandatory on every subsystem, all within the §4 overhead budgets.

20.4 Acceptance Criteria

OpenTelemetry export verified functional against fixtures/observability/trace_export.trace; metrics-scrape overhead measured under 2% CPU at 10M events/sec (§4); logging overhead under 5% CPU at the same load; cardinality enforcement rejects any label combination exceeding the configured budget in 100% of injected high-cardinality test cases.

20.5 Conformance Fixtures

fixtures/observability/trace_export.trace — a full delivery flow from IOAPIC assertion through EOI; expected: the exported OpenTelemetry trace contains one span per state transition in §8's state machine, correctly parented by causal ID.

20.6 Pitfalls

Metrics cardinality explosion — manifestation: the metrics backend's memory grows unbounded under a large topology; root cause: a per-vector-per-CPU label combination left un-sampled (65536 × 4096, §4); debugging method: inspect the registry's live label-set size against the I12 budget; signal: metrics_cardinality_total climbing; recovery: apply the sampling policy at the registry boundary, never at each individual call site inconsistently. Trace-sampling corruption — manifestation: a sampled-out span breaks a downstream trace's parent-child chain; root cause: sampling decisions made independently per span instead of per causal-ID root; recovery: sample at the trace root and propagate the decision down the causal chain (head-based sampling, not per-span).

20.7 Performance Concerns

Histogram allocation overhead: pre-allocate histogram bucket arrays at registry initialization, never per-observation; this is the same "no heap allocation on the hot path" discipline as 18.7, applied to the observability layer itself so instrumentation never becomes the bottleneck it is measuring.

20.8 Edge Cases

Exporter backpressure (the OpenTelemetry collector or Prometheus scrape target stalls — must apply P8's backpressure discipline to telemetry itself, dropping oldest samples per ADR-21 rather than blocking the simulation, since telemetry loss is tolerable where event loss is not).

20.9 Failure Analysis

Telemetry failure must not halt the simulator (P9's failure-domain isolation extended to the observability plane): a metrics-exporter stall (FM-6, §23) degrades observability, not correctness. Detection: exporter-lag metric surfaces the stall to the operator even while the export path itself is degraded, via a redundant minimal-cardinality health-check metric that bypasses the main registry.

20.10 Operational Notes

Structured JSON logs are mandatory, not optional (P3) — no plaintext logging mode exists. Every metric name introduced across Phases 0–7 is registered here exactly once; drift between a phase's documented metric name and the registry's actual name is treated as a defect (terminology lock). Dashboards (interrupt heatmaps, queue pressure, replay divergence, topology activity) are built against this registry's stable metric names, detailed in §24.

21. Phase 9 — Fault Injection and Chaos Infrastructure

21.1 Objectives

Implement systematic, deterministically-replayable failure testing: queue-corruption injectors, latency injectors, packet-reorder injectors (for distributed replay mode), and clock-skew injectors. This is the final Phase 0-era phase — it validates that every invariant and recovery path documented in §7/§22/§23 actually fires under controlled adversarial conditions.

21.2 Detailed Implementation Steps

Implement sim-failure/src/injectors.rs (individual fault primitives: queue corruption, latency injection, reorder injection, clock skew) and sim-failure/src/scenarios.rs (composed chaos scenarios combining multiple injectors with a deterministic seed, per P1 — a chaos run must itself be replayable, or it violates P6 and is rejected). Wire sim-conformance/src/runner.rs to execute the full differential/property/fuzz suite (§26) as part of this phase's exit criteria, and sim-fuzz/src/targets.rs to register the topology-parser, replay-reader, and wire-decoder fuzz targets (ADR-15) against every invariant assertion from §7 as a fuzzing oracle. Every injected fault is tagged with a unique injection_id, threaded through the causal-ID mechanism from Phase 8 (§20) so a chaos run's failures are traceable exactly like a production failure would be — containment verification for I14 (panic isolation) is exercised here for the first time under adversarial, not merely accidental, conditions.

21.3 Deliverable

A programmable, deterministic failure-injection runtime: any invariant violation documented in §7 can be deliberately triggered, its detection/recovery path exercised, and the whole scenario replayed byte-identically for postmortem analysis.

21.4 Acceptance Criteria

Deterministic failure replay verified across 200 runs of fixtures/failure/queue_corruption.trace; containment verified: an injected panic in one domain worker (I14) leaves all peer domains' telemetry uninterrupted in 100% of runs; every §7 invariant has at least one corresponding chaos scenario exercising its detection path (14 for 14, full 1:1 coverage).

21.5 Conformance Fixtures

fixtures/failure/queue_corruption.trace — deliberate mid-flight corruption of a queued InterruptEvent's checksum; expected: I11's checksum verification rejects the record, the domain worker is isolated (I14) without affecting peers, and the scenario replays identically on rerun.

21.6 Pitfalls

Nondeterministic injection timing — manifestation: the same chaos scenario, replayed twice, injects the fault at a different logical tick; root cause: injector triggered from an ambient counter rather than an explicit seeded schedule; debugging method: diff injection_id-tagged events' timestamps across two runs; recovery: schedule every injector deterministically from the seed and the recorded tick count, never from real elapsed wall time (P1/P12 applied to the fault injector itself, which must obey the same rules as the system it tests).

21.7 Performance Concerns

Instrumentation overhead of the injector framework itself must stay within the same §4 budgets as normal telemetry (2%/5% CPU) when injectors are configured but not firing — a chaos-capable build must not be a slower build by default.

21.8 Edge Cases

Cascading retries (an injected latency fault triggers Phase 6's retry-bound logic repeatedly — must resolve via I9's cap, not compound into an unbounded retry storm); a chaos scenario that itself triggers a queue overflow (I4's fatal-overflow behavior must still apply — chaos scenarios do not get an exemption from any invariant).

21.9 Failure Analysis

Chaos runs are archived for postmortems exactly like production incidents (§23's forensics column applies identically): the injection_id, the full causal trace, and the WAL segment covering the scenario are retained together as one bundle. This closes the loop back to §2's calibration claim — an engineer who has built this phase has exercised every recovery path in the document at least once under controlled conditions, not merely read about it.

21.10 Operational Notes

All injected failures are tagged with injection_id in every metric, span, and log line they touch, so a chaos run is indistinguishable from a real incident in the observability stack except for that one field — this is deliberate: it validates that Phase 8's observability pipeline (§20) would actually surface the equivalent real failure with the same fidelity.

24. Operational Readiness

Metrics strategy. Mandatory metrics across every deployment: interrupt latency (per-phase histograms from §15/§16/§17/§18), queue occupancy (§13), active-interrupt count (§15/§17), replay drift (§19), scheduler stalls (§12/§18). All registered exactly once in §20's registry; metric-name drift between a phase's documentation and the live registry is a defect.

Tracing strategy. Every interrupt event carries a causal ID, controller ID, CPU target, and vector metadata (§8, §20) from the moment it is enqueued (§13) through EOI (§15/§17). Head-based sampling (20.6) is applied at the causal-ID root so a sampled trace is always structurally complete, never truncated mid-chain.

Dashboard design. Four canonical dashboards: interrupt heatmaps (per-CPU, per-vector activity over time), queue pressure (occupancy and rejection rates per domain), replay divergence (detection-latency and divergence-rate trend), topology activity (mutation frequency and mutation-pause duration against the §4 50 ms budget).

Backup strategy. Snapshot every 5 minutes of wall-clock deployment time (not logical time — this is an operational cadence, not a determinism-sensitive one); WAL archival hourly to NUMA-aware local storage first, then to durable object storage per §10's /legal and /docs retention policy references.

Rolling upgrade strategy. Schema-compatibility gates (P7) block a deployment from starting against traces/snapshots produced by an incompatible schema version; replay validation runs against a canary node before a version is promoted fleet-wide, per ADR-19's reproducibility discipline extended to deployment.

25. Compatibility & Versioning

Wire compatibility. Protobuf fields are append-only (ADR-05); no field renumbering, ever (P7). A new optional field must have a documented default that preserves old-trace replay semantics exactly.

Storage compatibility. Snapshot format is explicitly versioned (SnapshotDescriptor. generation, §11); WAL migration tooling is mandatory for any breaking format change and lives under /scripts (§10), never an in-place silent rewrite.

API stability. Semantic versioning across all public crate APIs (sim-core, sim-delivery, sim-topology, etc.); minimum two-release deprecation period before a breaking removal, matching the rolling-upgrade cadence in §24.

Topology compatibility. The topology-hash mechanism (§14) is itself part of the compatibility contract: a replay manifest's pinned hash is the enforcement point for T4 (§22), not a convention operators must remember to check manually.

26. Testing & Verification Strategy

Unit testing. State-machine transitions (§8, per controller); queue ordering (§13); arbitration correctness (§18) — each against the specific invariant it enforces (§7), not generic "it works" assertions.

Integration testing. APIC + IOAPIC interaction (Phases 3–4, §15/§16); GIC topology routing (Phase 5, §17); full delivery-to-EOI round trips across the dispatcher (§18).

Differential testing. Compare LAPIC/GIC behavior against QEMU's device-model output and against Linux kernel interrupt traces (both named in §5's Reference Implementations) on a curated set of scenarios where bit-exact register-level behavior is the conformance bar, per the QEMU register-fidelity lesson noted in §31.

Property testing. Core properties, each mapped to a §7 invariant: monotonic time (I1), deterministic ordering (I3), bounded queues (I4) — expressed as proptest-style generators over randomized event sequences, run continuously in CI (ADR-14).

Fuzzing. Targets registered in sim-fuzz/src/targets.rs (§21): topology parsers, replay readers, interrupt-payload decoders — every fuzz target treats each §7 invariant assertion as an oracle, per 21.2.

Chaos testing. Injected queue corruption, latency spikes, and scheduler stalls via sim- failure (§21), verifying that every §23 failure mode's detection and recovery path actually fires under adversarial conditions, not merely under accidental ones.

27. Build & Release Engineering

Reproducible builds. Pinned dependencies (ADR-03), locked Rust toolchain (rust-toolchain.toml, ADR-19), deterministic archive generation — a rebuild from the same commit hash produces a byte-identical artifact.

Artifact signing. cosign signatures on every release artifact plus release-provenance attestations, implementing ADR-17's supply-chain mitigation for T10 (§22).

SBOM generation. SPDX-format SBOM generated during CI (.github/workflows/release.yml, §10), attached to every release artifact.

Release channels. Nightly (unreviewed, latest main), beta (release-candidate, conformance-gate passed), stable (fully promoted, per ADR-19's reproducibility guarantee). Promotion from beta to stable requires the canary replay-validation pass described in §24.

28. Performance Engineering

29. Scalability Analysis

Bottlenecks. Central arbitration (§18's dispatcher is the one cross-domain synchronization point); WAL fsync pressure (§19, bounded by C7's 1.5x amplification ceiling, §32); topology-graph traversal at the 4096-CPU ceiling (§14).

Horizontal scaling. Partition by interrupt domain and by CPU cluster (§4 scaling assumptions); deterministic cross-domain event sequencing is required before partitioning, per Q15 (§33) — partition boundaries must be fixed at topology-load time (§14), not discovered dynamically.

Vertical scaling. NUMA-local queues (§13, §4), affinity-pinned domain workers (ADR-08), thread-per-domain scaling up to one worker per NUMA node × CPU domain (§4's max-concurrency row).

Metadata scaling. Compressed topology indexes and vector-bitmap compression become necessary past roughly 2048 CPUs, where the flat TopologyGraph (§11) representation's traversal cost starts competing with arbitration for cache bandwidth — this is a documented Phase-9-and-later optimization target, not a Phase 0–9 requirement.

30. Mental Models & First Principles

  • MM1 — Interrupts Are Priority Queues With Physical Deadlines. An interrupt controller is fundamentally a priority queue with real-time delivery deadlines and a bounded active set; it predicts that nesting/preemption bugs look identical to priority-queue starvation bugs; without it, engineers treat IRR/ISR as booleans instead of an ordered active set, causing silent priority inversion; applies in §15.
  • MM2 — Determinism Is a Testing Multiplier, Not a Feature. Every nondeterminism source removed eliminates an entire class of flaky-test debugging permanently; predicts teams skipping logical time pay an order of magnitude more in triage time; the bug class without it is "unreproducible" reports closed as works-for-me; applies in §12.
  • MM3 — Backpressure Is Conservation of Mass. Interrupts, like fluid, must be conserved — every enqueue needs a matching dequeue or an explicit drop signal; predicts unbounded queues eventually OOM or desync replay; without it, invisible memory growth gets diagnosed as a generic "slow leak" instead of missing backpressure; applies in §13.
  • MM4 — Priority Without Fairness Is Starvation. Strict priority ordering guarantees the top class's latency at the expense of unbounded delay for the bottom; predicts low-priority vectors starve under sustained high-priority load unless explicitly bounded; without it, low-priority driver timeouts get blamed on drivers, not the scheduler; applies in §18.
  • MM5 — Replay Is Just a Second Execution With the Same Inputs. Replay correctness reduces to "is every nondeterminism source captured as an input"; predicts any uncaptured wall-clock, RNG, or scheduling read eventually diverges; without it, replay divergence gets blamed on "flaky hardware" instead of a missing input; applies in §19.
  • MM6 — A Redistributor Is a Per-CPU Cache of Distributor State. GICv3's redistributor exists because shared per-CPU affinity state doesn't scale as one table; predicts redistributor/ distributor desync bugs look exactly like cache-coherence bugs; without it, SGI/PPI routing bugs get dismissed as GIC "flakiness"; applies in §17.
  • MM7 — EOI Is a Lock Release. EOI is structurally identical to releasing a lock guarding a vector slot; predicts EOI-ordering bugs manifest like lock-ordering bugs (double-free / use- after-release); without it, EOI bugs get debugged as APIC-specific rather than recognized as a general concurrency pattern; applies in §15.
  • MM8 — Observability Cost Is Amortized Correctness Insurance. Every metric/span/log field is a pre-paid debugging session; predicts systems skipping instrumentation pay exponentially more in postmortem time than the CPU overhead they saved; applies in §20.

32. Back-of-Envelope Capacity Model

  • C1 — Max Resident Interrupt State. 4096 CPUs × 16,384 pending/CPU = 67,108,864 events × 64 B/InterruptEvent = 4,294,967,296 B = 4.0 GB, inside the 8 GB §4 memory ceiling with room for topology/WAL buffers.
  • C2 — Vector-Table Memory. 65,536 vectors × 4096 CPUs × 3 bitmaps (IRR/ISR/TMR) × 1 bit = 65,536 × 4096 × 3 = 805,306,368 bits = 100.7 MB, negligible against the 8 GB ceiling.
  • C3 — Sustained-Throughput Headroom. 10,000,000 events/sec × 100 B/event = 1.0 GB/sec logical; × 1.5 (§4 amplification ceiling) = 1.5 GB/sec required WAL disk bandwidth, near the edge of a single NVMe device — motivates per-NUMA-node WAL sharding (ADR-08).
  • C4 — p99 Latency Budget vs. Queue Depth. 10,000,000 events/sec = 1 event / 100 ns; a fully-backed-up 16,384-deep per-CPU queue drains in 16,384 × 100 ns = 1.638 ms, ~16x over the 100 µs p99 budget (§4) — forces bounded per-priority sub-queues (ADR-09) rather than one FIFO.
  • C5 — FD Budget vs. Distributed Replay Fan-Out. 8192 FDs (§4) / 4 FDs per peer connection (socket + 2 pipes + eventfd) = 2048 max concurrent peer connections per node, bounding replay-coordinator fan-out.
  • C6 — Snapshot-Restore Bandwidth. 4,294,967,296 B (C1) / 5 s (§4 restore budget) = 858,993,459 B/sec ≈ 858 MB/sec required read bandwidth, achievable on local NVMe (> 1 GB/s) but not a 1 Gbps network link (125 MB/s) — pins snapshot storage to local NVMe.
  • C7 — Trace Write-Amplification Ceiling. 10,000,000 events/sec × 100 B logical = 1.0 GB/sec; × 1.5 (§4) = 1.5 GB/sec physical WAL write-rate ceiling, matching C3's NVMe sizing exactly.
  • C8 — Divergence Detection Blast Radius. 10,000,000 events/sec × 0.1 s (§19's 100 ms detection budget) = 1,000,000 events that could execute before an undetected divergence is caught, motivating per-N-event checksum checkpoints rather than end-of-run-only comparison.

34. Alternative Architectures (Roads Not Taken)

Alt A — Event-Sourced Actor Model

+--------+   msg   +--------+   msg   +--------+
| CPU-0  | <-----> | CPU-1  | <-----> | CPU-2  |
| actor  |         | actor  |         | actor  |
+--------+         +--------+         +--------+
    ^                                     ^
    |             mailbox queues          |
    +-------------------------------------+

Wins in the regime of highly heterogeneous device fleets needing hot-swappable per-device logic modules with independent scheduling. Embodied by Erlang/OTP-style actor schedulers. Rejected here because message-passing actor overhead conflicts with the 10M events/sec §4 throughput target, and deterministic ordering (I3) is harder to guarantee across independently scheduled actors than across the domain-sharded model actually chosen (ADR-08).

Alt B — Full Cycle-Accurate RTL/Co-Simulation

[ RTL model of APIC/GIC ] <--waveform sync--> [ Verilator/co-sim harness ]

Wins in the regime of hardware/software co-verification for actual silicon tape-out validation. Embodied by RTL+co-simulation platforms pairing Verilator-class simulators with a functional model. Rejected here because it is an explicit non-goal (§1) — RTL synthesis and electrical signal-level modeling are excluded — and it would blow the §4 startup and throughput budgets by orders of magnitude for no correctness benefit at this abstraction level.

Alt C — Centralized Single-Threaded Discrete-Event Simulator

[ global event queue ] -> [ single simulation loop ] -> [ all controller state ]

Wins in the regime of research prototypes handling a few thousand events/sec, where implementation simplicity beats throughput. Embodied by classic discrete-event simulation frameworks such as OMNeT++. Rejected here because it cannot reach the 10M events/sec §4 target or satisfy the NUMA-aware vertical-scaling assumption; the single global event queue becomes the sole bottleneck (§29).

Alt D — Full VM-Based Hardware Emulation as Primary Architecture

[ guest OS ] -> [ byte-exact APIC/GIC register emulation ] -> [ real vCPU exit/entry ]

Wins in the regime of running unmodified guest OS kernels that require byte-exact hardware register behavior. Embodied by QEMU itself. Rejected here because full CPU/VM execution is an explicit non-goal (§1); this architecture optimizes for hardware fidelity over the observability- first and deterministic-replay-first priorities that this blueprint is built around (P1, P3, §6).

36. Glossary

  • APIC — Advanced Programmable Interrupt Controller, the x86 family covering Local APIC and IOAPIC.
  • IOAPIC — External interrupt-routing controller feeding vectors into per-CPU Local APICs.
  • LAPIC — Local APIC; per-CPU interrupt controller managing IRR/ISR/TMR and the local timer.
  • x2APIC — Extended-addressing LAPIC mode using MSRs instead of memory-mapped registers.
  • GIC — ARM Generic Interrupt Controller, covering GICv2 and GICv3 in this blueprint.
  • Distributor — GIC component holding shared (SPI) interrupt state.
  • Redistributor — GICv3 per-CPU component holding SGI/PPI state, replacing GICv2's shared table.
  • CPU Interface — The per-CPU GIC component a core actually reads to accept/acknowledge an interrupt.
  • ISR — In-Service Register; tracks currently-active vectors on a LAPIC.
  • IRR — Interrupt Request Register; tracks pending, not-yet-accepted vectors.
  • TMR — Trigger Mode Register; records edge vs. level trigger mode per vector.
  • EOI — End Of Interrupt; the signal releasing a vector's active state.
  • SGI — Software Generated Interrupt (GIC), roughly analogous to an APIC-world IPI.
  • PPI — Private Peripheral Interrupt (GIC); per-CPU device interrupt.
  • SPI — Shared Peripheral Interrupt (GIC); routed via the distributor to a CPU subset.
  • Vector — The numeric identifier selecting which handler an interrupt targets.
  • Pending Interrupt — An interrupt asserted but not yet accepted by its target CPU.
  • Active Interrupt — An interrupt accepted and currently being serviced (ISR-set).
  • Nesting — A higher-priority interrupt preempting a lower-priority one already active.
  • Starvation — A pending interrupt class never receiving service under sustained higher- priority load.
  • Priority Inversion — Lower-priority work blocking higher-priority work from proceeding.
  • Backpressure — Upstream propagation of downstream queue pressure (P8).
  • Bounded Queue — A queue with a hard capacity ceiling whose overflow is a detectable event.
  • WAL — Write-Ahead Log; the append-only durable record of committed events.
  • Snapshot — A point-in-time serialized copy of resident controller state.
  • Checksum — A verifiable integrity value (SHA-256 in this blueprint) guarding I11.
  • Replay Drift — Divergence from deterministic execution during replay.
  • Replay Cursor — The current replay position within a WAL, indexed by sequence number.
  • Divergence Detector — The component comparing live replay state against recorded state (§19).
  • Causal Correlation ID — An identifier linking all telemetry for one logical interrupt flow.
  • Topology Hash — A stable hash of a validated TopologyGraph, guarding cross-version replay.
  • Affinity Mask — CPU-targeting bitmap for a routing entry or SGI destination set.
  • Redirection Entry — IOAPIC routing descriptor mapping a pin to a vector/destination.
  • Delivery Mode — The interrupt-routing semantic (e.g., fixed, lowest-priority, NMI).
  • Trigger Mode — Edge or level activation semantic for a redirection entry.
  • Interrupt Storm — Sustained, excessive interrupt generation, often from a stuck level source.
  • TLB Shootdown IPI — An inter-processor interrupt requesting a remote TLB invalidation.
  • Timer Wheel — A data structure for efficiently managing many pending timers by deadline bucket.
  • Deadline Timer — A one-shot timer firing at a specific logical-time deadline.
  • Domain Worker — A scheduling unit owning one NUMA/CPU domain's execution context (ADR-08).
  • NUMA Node — A non-uniform-memory-access domain; the unit of locality for queues and workers.
  • Fixture — A named, versioned test input/expected-output pair under /fixtures (per phase).
  • Conformance Suite — The differential/property/fixture-based test corpus validating architectural correctness (§26).
  • Fault Injection — Deliberate, deterministic introduction of a failure condition (§21).
  • Chaos Scenario — A composed, seeded sequence of fault injectors (§21).
  • MADT — Multiple APIC Description Table; ACPI structure enumerating CPUs/interrupt controllers.
  • MPS — Intel MultiProcessor Specification; legacy predecessor to ACPI-based enumeration.
  • Crash-Only Recovery — Recovering exclusively via restart-and-replay, never in-place repair (P4).
  • Cardinality (metrics) — The number of distinct label-value combinations a metric can take.
  • Span (tracing) — A single traced operation, parented by causal ID, per OpenTelemetry's model.
