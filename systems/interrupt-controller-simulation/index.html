In one paragraph

An interrupt controller takes a signal from a device or another CPU and decides which processor handles it, and in what order (§2, §36). This design is a Rust simulator of x86 APIC/IOAPIC/x2APIC and ARM GICv2/GICv3 delivery behavior: state machines, priority arbitration, routing, timers and inter-processor interrupts. It is explicitly not a CPU emulator or an RTL model (§1). Its defining promise is deterministic replay: every run can be replayed byte for byte, with zero tolerated divergence (§1, §4). It runs as a standalone CLI or embedded library, operated by kernel and hypervisor engineers, researchers and hardware-validation engineers (§1).

The problem, concretely

Interrupts sit under everything a kernel does: scheduling wakeups, timer ticks, TLB shootdowns and device completions all resolve through the delivery path, so a bug there corrupts everything above it (§2). Now try to simulate that path naively, at the scale the blueprint targets: up to 4096 CPUs and 10,000,000 events per second (§4). Five obvious shortcuts fail.

  • One plain FIFO queue per CPU. At 10,000,000 events/sec an event arrives every 100 ns. A fully backed-up 16,384-deep per-CPU queue then takes 16,384 × 100 ns = 1.638 ms to drain, about 16 times over the 100 µs p99 delivery budget (§32 C4, §4). A high-priority interrupt stuck behind that pile is late. This is why the design uses bounded per-priority sub-queues (§32 C4, ADR-09).
  • Strict priority, nothing else. The top class gets its latency, and the bottom class waits without limit. Low-priority driver timeouts then get blamed on the drivers instead of the scheduler (MM4, §18.6).
  • Let queues grow when load spikes. Unbounded queues eventually run out of memory or make replay drift apart (MM3, P2). Silent event loss would invalidate every replay guarantee, so overflow is fatal by design (§4, I4).
  • Read the wall clock or thread order for convenience. Two runs of the same input then produce different traces, and every regression becomes an irreproducible one-off (P1). The blueprint's own example is a stray ambient time read whose divergence shows up only outside CI (§12.6).
  • Release an interrupt that was never active. An end-of-interrupt (EOI) for an inactive vector can corrupt an unrelated vector's state (§15.6, I5).

The blueprint's structure answers these pressures: bounded queues with backpressure (P2, P8), logical time instead of ambient time (P12, ADR-20), bounded retries with aging (I9, §18.4), and a write-ahead log that makes every run replayable (§19.2).

How it works, end to end

Follow one external interrupt through the boxes of §3's diagram. Each box is a crate:

 sim-cli       topology load | runtime control | replay control   [untrusted config enters here]
   v
 sim-core      lifecycle | domain-worker scheduling | panic isolation
   |  uses: sim-clock (logical time), sim-eventbus (bounded queues), sim-trace (WAL),
   |        sim-observability (metrics/tracing/logging)
   v
 sim-topology  CPU graph | interrupt domains | routing tables | affinity maps
   v
 sim-apic (IRR/ISR/TMR)   sim-ioapic (redirection)   sim-gic (distributor/redistributor)
   v
 sim-delivery  arbitration | routing | retries | EOI   [InterruptEvent state machine enforced here]
   v
 sim-priority (nesting stack)   sim-ipi (broadcast, TLB shootdown)   sim-timer (wheel, deadlines)
   v
 sim-storage   trace persistence | snapshots | replay artifacts
  1. Config and topology. sim-cli takes the operator's topology file. This is the trust boundary, because a malformed topology can poison scheduler assumptions (§3, T1). sim-config parses the TOML and sim-topology validates it before any runtime state exists, rejecting dangling CPU references and cycles (§14.2, P13, I8).
  2. Runtime. sim-core owns the lifecycle and starts domain workers, one per NUMA node and CPU domain (§3, §4, ADR-08). sim-clock supplies logical time, never wall time (§3, I1).
  3. Pin assertion. A device asserts a pin. sim-ioapic looks up the redirection entry and resolves the destination (§8, §16.2). On ARM the same step is sim-gic: peripheral interrupt, distributor, redistributor targeting (§8).
  4. Transport. The event travels through sim-eventbus, a bounded queue that assigns a monotonic sequence at enqueue and tells a saturated producer synchronously (§13.2, P8). sim-wire frames it in an envelope carrying a causal correlation ID (§13.2).
  5. Arbitration. sim-delivery is the protocol boundary where state-machine transitions are enforced (§3). It calls sim-priority for highest-priority-first selection and nesting (§18.2) and sim-delivery/src/retry.rs for bounded retries (§18.2, I9).
  6. Controller state. For x86, sim-apic inserts the vector into the IRR, accepts it, activates it in the ISR, and waits for the handler's EOI (§8, §15.2). Both controllers sit behind one InterruptController trait (enqueue, acknowledge, eoi, snapshot) (§11).
  7. Recording. Every state transition is a new WAL record in sim-trace, and snapshots go through sim-storage (§11, §19.2). sim-observability emits metrics, spans and JSON logs on every path (P3, §20.2).

sim-ipi and sim-timer feed the same dispatcher, so IPIs and timer interrupts are ordinary arbitration inputs and not a shortcut path (§18.3, §18.6).

The core ideas

The event state machine and the Local APIC registers (§8, §15)

Every interrupt is an InterruptEvent that moves through states (§8):

From To Meaning
IDLE PENDING the interrupt has been asserted (§8, §36)
PENDING DELIVERED arbitration chose it
DELIVERED ACTIVE the CPU accepted it; the vector is in service
ACTIVE EOI_PENDING the handler finished and is signalling
EOI_PENDING COMPLETED the vector is released
PENDING RETRY_PENDING an arbitration retry, bounded by I9
ACTIVE STALLED the handler never completes; the watchdog's job (§8, FM-5)
DELIVERED LOST queue overflow mid-flight, fatal per I4 (§8)

The blueprint disagrees with itself on the failure states. §8 names STALLED and LOST, while §11's InterruptState enum has neither and lists a Failed variant instead, which §18.8 calls "a Failed state transition per §8" although §8 has no such state (§8, §11, §18.8).

An event is immutable once committed, so each transition creates a new record (P14, §11). Inside one Local APIC (LAPIC, the per-CPU controller, §36) three registers hold the state. The interrupt request register (IRR) is a 256-bit bitmap of pending vectors, the in-service register (ISR) holds active ones, and the trigger-mode register (TMR) records edge or level (§15.2, §36). Delivery picks the highest-priority pending vector with a bitmap scan (§15.2), using hardware find-first-set instructions instead of a linear loop (§15.7). A higher-priority vector may preempt a lower one, and the active vectors form a nesting stack that must stay strictly ordered (nesting, I10, §36).

The blueprint's nested-interrupt fixture has three nested priority levels, and the ISR stack must unwind in exact reverse-priority order (§15.5, I10). The EOI fixture mixes activations and EOIs with one out-of-order EOI: that EOI is rejected and the in-order ones succeed (§15.5). I5's recovery is to reject the EOI and keep the vector active (§7). MM7 gives the useful picture: an EOI is a lock release on a vector slot, so EOI-ordering bugs look like lock-ordering bugs (MM7). x2APIC mode reuses the same state machine behind a wider-addressing front end rather than a second implementation (§15.2, P15).

IOAPIC routing: edge versus level (§16)

The IOAPIC is the external controller that turns device pins into vectors for the per-CPU LAPICs (§36). Its redirection table maps each pin to a vector and destination, held in a flat array indexed by pin number because only 240 entries exist (§16.4, §16.7). The tricky part is the trigger mode (§16.2, §16.5):

Mode What the pin does What the design guarantees
Edge a single-shot assertion, cleared on acceptance back-to-back assertions on one pin are distinct events, never coalesced
Level the assertion persists until the source deasserts delivered exactly once on acceptance, with no duplicate delivery

Two rules keep this safe. A level line is released by EOI completion and not by delivery, because tying it to delivery produces a stuck level-triggered interrupt (§16.6). A masked pin's pending assertion is held and never dropped, so mask and unmask must be atomic with the pending flag, via one compare-and-swap covering both fields (§16.4, §16.6). A level source that re-asserts into a mis-cleared flag becomes an interrupt storm (§16.9, §36).

GIC: a distributor and per-CPU redistributors (§17)

ARM's controller splits the work differently. The distributor holds shared state for shared peripheral interrupts (SPIs). In GICv3 each CPU also has a redistributor for its private state (software-generated and private peripheral interrupts), replacing GICv2's single shared table (§17.2, §36). Both versions run behind one configuration switch, which is a topology flag and not a build flag (§17.3, §17.10). Affinity routing maps ARM's Aff0-Aff3 addresses onto the topology's CpuMask (§17.2).

MM6 is the mental model: the redistributor is a per-CPU cache of distributor state, so the bug to fear is a cache-coherence bug. A redistributor's target set must never diverge from the distributor's authoritative affinity table (MM6, I13). The fixtures are concrete. A software- generated interrupt broadcast to 8 CPUs is seen by all 8 redistributors in the same tick, with order between them defined as CPU-ID ascending (a deterministic tie-break). A shared interrupt routed to a 3-CPU subset appears only in those 3 redistributors (§17.5). An injected inconsistency must trip the desync detector within one tick (§17.4).

Bounded queues and bounded retries: nothing waits forever (§13, §18)

Every queue has a hard capacity. Enqueue checks it, and a full queue is a fatal, counted event and not a quiet drop (P2, I4, §13.9). Pressure travels upstream to the producer (P8, ADR-21). One backed-up FIFO cannot drain inside the p99 budget, which forces bounded per-priority sub-queues (§32 C4, ADR-09).

Priority alone starves the bottom class (MM4), so arbitration adds an aging counter per pending vector. The acceptance target is that no pending vector waits more than 64 arbitration rounds under a sustained high-priority flood (§18.2, §18.4). Retries are capped: DeliveryDescriptor.retry_budget only decrements, and exhausting it escalates to a failure path instead of spinning (§11, I9, §18.8); I9's recovery column adds "drop with diagnostic" (§7). Equal-priority collisions are broken deterministically by event_id and never by memory address, in both the queue and the arbiter (§13.6, §18.6). Livelock (two vectors retrying against each other forever) is therefore bounded by I9, while deadlock is a different bug, a lock-order violation (I6, FM-5).

Logical time and the write-ahead log: making replay real (§12, §19)

Time is an explicit value. LogicalClock::now() and advance(delta) are the only time source, now() is never read before a startup barrier releases (every worker registered), and random seeds are passed in explicitly (P12, ADR-20, §12.2, §11). Replay then reduces to one question: is every nondeterminism source captured as an input (MM5)?

The record of what happened is an append-only write-ahead log (WAL). The log is the authoritative history, and every controller's live state is a view derivable by replaying it (§19.2). Each record carries a header with magic, version, SHA-256 checksum, logical timestamp, sequence, payload type and payload length (§8, §11). Three checks follow from that (§19.2, §19.6, §19.5):

  1. Per-record checksums. A torn tail from a crash mid-fsync is found by checksum and the log is truncated to the last valid record, never repaired in place (I11, P4).
  2. Snapshots. Restoring a snapshot and replaying the WAL after it must reproduce the same final state as replaying the whole log from scratch.
  3. Divergence detection. The detector compares live execution against the record continuously, and a corrupted record must be caught within its sequence range, not at the end of the run (§19.9, I3).

Replay is fatal on divergence by design, and the divergent record is preserved for forensics (§19.9).

The trade-offs — where engineers disagree

Time source: a logical clock (ADR-20)

Chosen: a logical monotonic clock, for determinism (I1, P12). Rejected: wall-clock time (NTP/PTP). When the rejected choice is right: when simulated events must be correlated against real external hardware traces in hybrid hardware/simulated validation (§9, §1).

Queues: bounded ring buffers (ADR-09)

Chosen: a bounded MPSC ring buffer, for replay safety (P2, I4). Rejected: unbounded channels. When the rejected choice is right: on best-effort telemetry sampling paths, where dropping is preferable to blocking upstream (§9, ADR-21). The blueprint still rejects one shared bounded FIFO for event data, since it cannot meet the p99 budget (§32 C4).

Concurrency: domain-sharded workers (ADR-08)

Chosen: one worker per NUMA node and CPU domain, for failure isolation (P9) and NUMA locality (§4). Rejected: a global work-stealing executor. When the rejected choice is right: for highly irregular, bursty workloads where static domain partitioning under-utilizes cores (§9).

Trace storage: a custom append-only log (ADR-04)

Chosen: a custom append-only WAL, because deterministic append ordering (I7) is simpler to guarantee outside a general-purpose transactional engine. Rejected: SQLite. When the rejected choice is right: when ad-hoc queryable analysis of historical traces matters more than write-path determinism (§9).

Serialization: Protobuf (ADR-05)

Chosen: Protobuf, for tooling maturity and append-only schema evolution (P7). Rejected: FlatBuffers. When the rejected choice is right: when zero-copy random access into huge single messages dominates, for example embedding raw device-memory snapshots (§9).

Roads not taken (§34, §35)

Event-sourced actor model (§34 Alt A): one actor per CPU exchanging messages, as in Erlang/OTP. It wins for highly heterogeneous device fleets that need hot-swappable per-device logic modules. It is rejected because actor overhead conflicts with the 10M events/sec target and deterministic ordering is harder to guarantee across independently scheduled actors (I3, ADR-08).

Cycle-accurate RTL co-simulation (§34 Alt B): it wins for hardware/software co-verification before silicon tape-out. It is rejected because RTL synthesis and signal-level modeling are non-goals (§1) and it would blow the startup and throughput budgets (§4).

Single-threaded discrete-event simulator (§34 Alt C): it wins for research prototypes handling a few thousand events/sec, where simplicity beats throughput (OMNeT++ style). It is rejected because the one global queue is the sole bottleneck and cannot reach 10M events/sec (§29, §4).

Full VM-based hardware emulation (§34 Alt D): it wins when unmodified guest kernels need byte-exact register behavior (QEMU itself). It is rejected because full CPU/VM execution is a non-goal (§1) and it favors fidelity over observability and replay (P1, P3).

Deferred features (§35): MSI-X tables, VT-d remapping, nested-virtualization injection, RISC-V IMSIC/APLIC, hardware trace export and NUMA-aware rebalancing each wait for an un-defer trigger.

What must never be false

Each invariant is one runtime assertion in debug and conformance builds. A failure names the invariant by ID (§7). Release builds keep only the fatal subset (I1, I3, I4, I5, I10) and turn the rest into counters (§7).

  • I1: logical time never regresses. Noticed by a monotonic assertion and the trace-divergence detector; clock_regression_total.
  • I2: a vector cannot be active twice on one CPU. Noticed by the ISR duplication validator; interrupt_duplicate_active_total.
  • I3: replay ordering matches the recorded ordering exactly. Noticed by the sequence-mismatch comparator; replay_sequence_mismatch_total.
  • I4: no queue ever exceeds its capacity. Noticed by the capacity check on enqueue; queue_overflow_total.
  • I5: an EOI corresponds only to an active vector. Noticed by the EOI-target validator; eoi_invalid_target_total.
  • I6: no lock inversions. Noticed by a dynamic lock-order checker in debug builds; lock_order_violation_total.
  • I7: WAL append order equals event commit order. Noticed by an append-sequence assertion; wal_order_violation_total.
  • I8: routing entries reference only existing CPUs and controllers. Noticed by the referential-integrity pass at load; topology_dangling_ref_total.
  • I9: delivery retries are capped. Noticed by the retry-budget exhaustion check; delivery_retry_exhausted_total.
  • I10: the priority nesting stack stays strictly ordered. Noticed by a stack-order assertion; priority_stack_corruption_total.
  • I11: every persisted record carries a verifiable checksum. Noticed by verification on read; checksum_mismatch_total.
  • I12: metric label sets never scale with topology size. Noticed by the cardinality high-water check; metrics_cardinality_total.
  • I13: every active routing entry's CPU mask is non-empty and valid. Noticed by a mask-validity check on mutation; affinity_mask_invalid_total.
  • I14: a panic in one domain worker cannot corrupt global state. Noticed by the panic hook and domain-health check; domain_panic_total.

What breaks in production

The blueprint's own note says every failure row traces to one invariant or to a metric (§23). Each paragraph below is symptom, then root cause, then detection and recovery. §23's headers are shifted by one (its second column holds the failure's name), so these paragraphs read each cell by content.

  • FM-1: queue overflow. Enqueues are rejected and a saturation metric spikes. The producer's rate exceeded the bounded capacity (I4). Watch eventbus_queue_depth. The runtime terminates by design; an operator resizes capacity or fixes the producer, with the WAL up to the overflow point kept as evidence (§23, §13.10).
  • FM-2: replay divergence. The detector fires mid-replay because some nondeterminism source was not captured (I3). Replay stops immediately, and an operator bisects the WAL to find the divergent record (§23, §19.9).
  • FM-5: deadlock. A watchdog times out with no forward progress, from a lock-ordering violation (I6, P11). The affected domain restarts crash-only, and the operator audits acquisition order against the global hierarchy (§23).
  • FM-7: priority or ISR corruption. A validator fires (I2, I5, I10) because of a bug updating the ISR/IRR bitmaps. The simulation terminates, and the operator replays a nested_interrupt.trace-style fixture to isolate it, using the bitmap dump from the failure tick (§23, §15.6).
  • FM-8: WAL fsync stall. The fsync-latency histogram shows a tail spike, from disk contention or a durability window misconfigured. Nothing recovers automatically. The durability window bounds exposure while the operator tunes batching and checks disk saturation (§23, §19.7).
  • FM-10: GIC redistributor desync. The I13 mask-validity check fires because a redistributor cache was not updated atomically with the distributor's topology swap (§23, §17.6). The stale mutation is rejected, and a full cache rebuild from the distributor snapshot recovers it (§23).
  • FM-11: panic in a domain worker. The domain-health check fails after an unhandled panic. The isolated worker restarts and its peers continue (I14, §23). The operator reads the captured backtrace and the worker's last N events (§23).

Threats worth knowing (§22):

  • T3, a tampered WAL: hand-edited trace bytes. Answered by checksums plus signed trace manifests; the replay stops and the file is quarantined.
  • T4, replay against the wrong topology: answered by pinning the topology hash in the replay manifest and rejecting a mismatch at replay start (§14.2, §25).
  • T8, interrupt-storm amplification through a sustained IPI broadcast: answered by bounded queues (I4) and rate-limited broadcast, then shed load and isolate the domain (I14).

How it compares

  • Linux kernel irq subsystem chose live-migratable per-CPU IRQ affinity with softirq deferral over synchronous handler execution. That fits a world where thousands of device drivers must share one dispatch path, and determinism is not a goal there (§31).
  • QEMU chose exact hardware-register fidelity over an abstracted event model. That fits running an unmodified guest OS against byte-exact behavior, with real-time emulation instead of replay (§31, Alt D in §34).
  • Xen chose hypervisor-mediated event channels over direct virtual-APIC passthrough. That fits strong isolation between untrusted guests, where raw injection latency matters less (§31).
  • seL4 chose capability-mediated IRQ handler objects over global privileged IRQ dispatch. That fits a formally verified minimal trusted base, though it is not replay-oriented (§31).

Questions to test yourself

  1. Why does bounding per-CPU pending interrupts at 16,384 (§4) combined with the priority-stack invariant (I10, §7) not eliminate starvation on its own, and what closes the gap in §18? — Hint: MM4 and §18.4's aging counter.
  2. Why does the EOI-ordering invariant (I5, §7) force sim-apic (§15) and sim-delivery (§18) to share a single source of truth for active-vector state rather than each caching it locally? — Hint: §15.6's ISR-corruption pitfall and MM7.
  3. Why does the lock-ordering invariant (I6, §7) combined with ADR-08's domain-worker concurrency model (§9) make deadlock (FM-5, §23) structurally different from a livelock in the delivery-retry bound (I9, §7)? — Hint: §18.6 and §18.7.
  4. Given ADR-09's bounded-MPSC choice (§9) and the 10M events/sec target (§4), why does §13's ring-buffer design still require per-priority sub-queues rather than one shared bounded queue? — Hint: §32 C4.

If you only remember three things

An interrupt controller is a priority queue with deadlines and a bounded active set, and priority without an aging bound is starvation (MM1, MM4). Every queue, retry count and metric label set is bounded, because an unbounded structure breaks replay and hides the real bottleneck (P2, P8, P10). Determinism is the project's whole value, so time is an explicit input, the WAL is the authoritative history, and any divergence is fatal (P1, P12, MM5).

Words used here

  • LAPIC / IOAPIC: the per-CPU x86 controller, and the external one feeding it from device pins (§36).
  • IRR / ISR / TMR: the pending, in-service and trigger-mode registers of a LAPIC (§36).
  • EOI: end of interrupt, the signal that releases a vector's active state (§36).
  • GIC distributor / redistributor: ARM's shared-state component, and GICv3's per-CPU one (§36).
  • SGI / PPI / SPI: GIC software-generated, private peripheral and shared peripheral interrupts (§36).
  • IPI: an interrupt one CPU sends to others, such as a TLB-shootdown request (§36).
  • Starvation: a pending interrupt class never getting service under sustained higher-priority load (§36).
  • Backpressure: pushing queue pressure upstream to the producer (§36, P8).
  • Logical clock: simulated time advanced explicitly and never read from the wall clock (§11, ADR-20).
  • WAL: write-ahead log, the append-only durable record of committed events (§36).
  • Crash-only recovery: recovering only by restart and replay, never by in-place repair (§36, P4).
  • Topology hash: a stable hash of the validated topology that guards against replaying a trace on the wrong one (§36, T4).
  • Domain worker: the scheduling unit owning one NUMA/CPU domain's execution (§36, ADR-08).
