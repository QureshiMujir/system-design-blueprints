⬜ Phase 0 — Runtime Skeleton, Deterministic Clock, and Repository Bootstrap §12

Objectives

Establish the correctness kernel every later phase depends on: deterministic logical time, lifecycle orchestration, bounded worker scheduling, deterministic startup ordering, and structured shutdown. No interrupt semantics exist yet — this phase exists purely to make everything above it replayable (P1, P6). Constraints introduced: startup must complete under 2 sec for a 256-CPU topology (§4); shutdown under 5 sec; zero nondeterministic timestamps anywhere in the call graph.

Deliverable

A runnable simulator shell: sim-cli boots, initializes the worker registry, advances the logical clock deterministically for N ticks with no registered controllers, and shuts down cleanly. No interrupts are modeled yet — this is pure scaffolding, but it is a real, executable binary.

Acceptance

100% deterministic replay across 1000 consecutive runs (zero divergence, I1/I3); startup under 500 ms for a 0-CPU topology and under 2 sec for a 256-CPU topology (§4); zero queue-depth growth over a 10-minute idle soak; zero nondeterministic timestamps detected by the sim-testkit clock auditor across all 1000 runs.

Fixtures

fixtures/clock/basic_tick.bin — single-domain tick-advancement trace, expected monotonically increasing sequence. fixtures/clock/regression_monotonicity.bin — replay of a historical regression where a race produced a tick regression; expected: assertion fires at the exact regressed tick. fixtures/runtime/startup_order.toml — a 12-worker dependency graph; expected startup order is the unique topological sort.

Pitfalls

Tick regression — manifestation: LogicalTime observed to decrease across two reads; root cause: concurrent tick updates without the barrier (12.2); debugging method: replay regression_monotonicity.bin under the clock auditor; signal: clock_regression_total > 0; recovery: terminate, preserve snapshot (I1). Worker startup race — manifestation: nondeterministic worker registration order across runs; root cause: unsynchronized barrier wait; debugging method: diff two runs' bootstrap logs; signal: startup_order.toml fixture produces a different order per run; recovery: fix barrier release condition, never retry blindly. Replay drift from wall-clock usage — manifestation: divergence appears only outside CI (different wall-clock jitter); root cause: a stray SystemTime::now() call bypassing P12; debugging method: grep for ambient time reads outside sim-clock; signal: divergence correlates with wall-clock time of day, not tick count; recovery: remove the read, route through LogicalClock.

⬜ Phase 1 — Event Bus and Queueing Infrastructure §13

Objectives

Build the replay-safe, bounded, priority-aware event transport that every controller crate will depend on. Introduces the queue-boundedness invariant (I4) and the backpressure principle (P8) as enforced code, not policy. No interrupt semantics yet — this phase moves opaque InterruptEvent envelopes, it does not interpret them.

Deliverable

A deterministic, bounded event-transport library usable independently of any controller: producers push InterruptEvent envelopes, consumers pop them in a provably deterministic order under replay, and saturation is observable before it becomes fatal.

Acceptance

Zero dropped events under sustained load below capacity; queue overflow is always detected within one enqueue attempt (100% detection rate across fixtures/eventbus/overflow.trace); deterministic dequeue ordering verified byte-identical across 500 replay runs; sustained throughput of at least 1,000,000 events/sec on a single domain queue (10% of the §4 system-wide 10M target, since Phase 1 tests one domain in isolation).

Fixtures

fixtures/eventbus/saturation.trace — enqueue rate exceeding capacity; expected: backpressure signal fires before the Nth enqueue where N = configured capacity. fixtures/eventbus/ replay_order.trace — interleaved multi-producer enqueue sequence; expected: replayed dequeue order matches recorded order exactly (I3). fixtures/eventbus/overflow.trace — deliberate overflow; expected: queue_overflow_total increments exactly once and the queue rejects further enqueues (I4).

Pitfalls

ABA queue corruption — manifestation: a popped-then-repushed slot is read as though never popped; root cause: reused ring-buffer slot without a generation tag; debugging method: replay replay_order.trace with generation-tag assertions enabled; signal: sequence-number gaps; recovery: add a generation counter per slot. False sharing on queue indices — manifestation: throughput collapses under multi-core contention despite low logical load; root cause: head/tail indices sharing a cache line; debugging method: perf c2c cache-line contention profile; signal: cross-core cache-miss rate spike; recovery: pad indices to 64 bytes (12.7). Priority starvation — manifestation: low-priority queue never drains under sustained high-priority traffic; root cause: naive strict-priority dequeue with no fairness bound; debugging method: replay under a synthetic high-priority flood; signal: low-priority queue depth monotonically increases; recovery: bounded fairness quota, deferred formally to Phase 6 (§18) but flagged here. Replay reordering — manifestation: two runs of the same trace dequeue in different order; root cause: nondeterministic tie-breaking on equal-priority, equal-timestamp events; debugging method: diff dequeue order across two runs; signal: replay_sequence_mismatch_total > 0; recovery: make the tie-break a deterministic function of event_id, never of memory address.

⬜ Phase 2 — Topology Engine §14

Objectives

Implement the CPU and interrupt-domain topology graph that all controller and delivery logic will route against. Introduces topology referential integrity (I8) as an enforced load-time invariant and establishes the topology-hash mechanism that later guards cross-version replay (T4, §22).

Deliverable

A validated, immutable, hashed topology runtime: given a TOML topology description, the engine either produces a fully validated TopologyGraph or rejects the input with a specific diagnostic before any controller state is constructed.

Acceptance

Invalid topology rejected in 100% of fixtures/topology/invalid_cpu.toml and cyclic_route.toml cases; topology load completes under 1 second for a 4096-CPU topology (§4); topology hashing is deterministic — identical topology input produces an identical hash across 100 runs; live topology mutation pause stays under 50 ms (§4) on a 1024-CPU topology.

Fixtures

fixtures/topology/dual_socket.toml — canonical 2-socket, 64-core-per-socket topology; expected: valid load, hash stable across reloads. fixtures/topology/invalid_cpu.toml — routing entry referencing a nonexistent CPU ID; expected: rejected with topology_dangling_ref_total incrementing (I8). fixtures/topology/cyclic_route.toml — a routing cycle; expected: rejected at the disconnected/cyclic-graph validation pass.

Pitfalls

Inconsistent affinity masks after a live mutation (manifestation: a CPU removed from topology still appears in a stale routing entry's mask; root cause: diff engine not atomically swapping the routing table; recovery: apply mutations as a single atomic snapshot swap, never incremental in-place edits, per P14). Duplicate controller IDs across a merged multi-file topology (root cause: naive file concatenation without ID-namespace validation; recovery: validation pass rejects at load). Stale topology references surviving a reload (root cause: a component cached a raw pointer instead of the Arc<TopologyGraph> snapshot handle; recovery: enforce handle-only access via the type system, never raw references, per ADR-08's ownership discipline).

⬜ Phase 3 — Local APIC / x2APIC Implementation §15

Objectives

Implement x86 Local APIC semantics: IRR/ISR/TMR management, EOI handling, vector prioritization, x2APIC mode, and the LAPIC timer. This is the first phase that models real interrupt-controller behavior rather than infrastructure, and it is the first conformance target (§26) against the Intel SDM (§5).

Deliverable

A functional LAPIC simulation: IRR/ISR/TMR state transitions are conformant with documented Intel behavior, EOI ordering is enforced, and nested interrupts (higher-priority preempting lower) resolve correctly.

Acceptance

100% pass rate against the SDM-derived conformance fixtures below; nested-interrupt depth up to 16 validated without stack corruption (I10); EOI issued for an inactive vector is rejected in 100% of fixtures/apic/eoi_order.trace mutation cases (I5); vector-activation p99 latency under 100 µs simulated (§4) at 1024 active CPUs.

Fixtures

fixtures/apic/eoi_order.trace — a sequence of activations and EOIs including one out-of-order EOI; expected: the malformed EOI is rejected, in-order ones succeed. fixtures/apic/ nested_interrupt.trace — three nested priority levels; expected: ISR stack unwinds in exact reverse-priority order (I10). fixtures/apic/timer_periodic.trace — 10,000-tick periodic timer run; expected: zero drift beyond the configured tolerance (§4 clock-drift-tolerance = 0 in deterministic mode).

Pitfalls

ISR corruption — manifestation: a vector remains marked active after its EOI; root cause: EOI handler updating the wrong bitmap index; debugging method: replay eoi_order.trace with the ISR bitmap dumped per tick; signal: interrupt_duplicate_active_total > 0 (I2); recovery: terminate (I10 is fatal by design). Vector priority inversion — manifestation: a lower-priority vector services before a pending higher-priority one; root cause: bitmap scan starting from the wrong end or a stale priority cache; debugging method: replay nested_interrupt.trace; signal: ISR stack order fixture mismatch; recovery: fix scan direction, add a regression fixture. Timer drift — manifestation: periodic timer ticks accumulate skew over a long run; root cause: timer reprogrammed from wall-clock-derived delta instead of logical-tick delta (violates P12); debugging method: replay timer_periodic.trace and compare tick deltas; signal: drift metric nonzero; recovery: reprogram strictly from LogicalClock. Invalid EOI release — manifestation: EOI for a vector never activated corrupts an unrelated vector's state; root cause: missing target validation before release; debugging method: fuzz EOI targets against sim-fuzz; signal: I5 detector fires; recovery: validate target before any state mutation (P13's discipline applied inline).

⬜ Phase 4 — IOAPIC and External Interrupt Routing §16

Objectives

Implement IOAPIC redirection-table semantics: masking, delivery-mode routing, edge- and level-trigger handling, and pin-to-vector routing from external devices into the LAPIC layer built in Phase 3. Introduces the MSI-X deferral decision point for this blueprint's scope.

Deliverable

Interrupt routing from external sources through the IOAPIC into the Phase 3 LAPIC layer, with correct edge/level semantics and masking.

Acceptance

Level-triggered replay correctness verified byte-identical across 200 runs of fixtures/ioapic/level_trigger.trace; routing determinism holds under edge_trigger.trace; masking correctness: a masked pin's pending assertion is held, never dropped, verified across 1000 mask/unmask cycles; routing-table lookup p99 under 10 µs simulated at 240 redirection entries (the legacy IOAPIC pin count ceiling).

Fixtures

fixtures/ioapic/level_trigger.trace — a level-triggered source asserted before the destination CPU is ready to accept; expected: assertion persists, delivered exactly once on acceptance, no duplicate delivery. fixtures/ioapic/edge_trigger.trace — back-to-back edge assertions on the same pin; expected: each is a distinct InterruptEvent, no coalescing.

Pitfalls

Stuck level-triggered interrupt (manifestation: a level source never clears even after acceptance; root cause: EOI path not deasserting the level line's pending-assertion flag; recovery: tie level deassertion explicitly to EOI completion, not to delivery). Routing loops (manifestation: a misconfigured redirection entry routes back into its own source domain; root cause: missing topology-level cycle check, I8 gap at the routing layer specifically; recovery: extend Phase 2's cyclic-route validation to cover IOAPIC redirection targets, not just CPU topology). Mask desynchronization (manifestation: an unmask operation loses a pending assertion that arrived while masked; root cause: mask/unmask not atomic with the pending-assertion flag; recovery: single compare-and-swap covering both fields).

⬜ Phase 5 — GICv2/GICv3 Simulation §17

Objectives

Implement ARM Generic Interrupt Controller semantics: distributor state, redistributor state, SGI delivery, PPI routing, SPI arbitration, and the GICv2→GICv3 affinity-routing shift from a flat distributor-owned CPU targeting model to a per-CPU redistributor. This is the second conformance target (§26), against the ARM GIC specifications (§5).

Deliverable

A functional GIC simulation runtime supporting both GICv2 (flat distributor-only) and GICv3 (distributor + per-CPU redistributor) behind one configuration switch, sharing the arbitration core with sim-apic.

Acceptance

GICv2 fixture compatibility: 100% pass on fixtures/gic/sgi.trace and spi_route.trace under flat-distributor mode; GICv3 redistributor correctness: affinity-routed SGI delivery verified byte-identical across 200 replay runs; distributor↔redistributor desync detector fires within one tick of an injected inconsistency (I13); SPI arbitration p99 under 100 µs simulated (§4) at 4096 CPUs.

Fixtures

fixtures/gic/sgi.trace — software-generated-interrupt broadcast to 8 target CPUs; expected: all 8 redistributors observe delivery in the same tick, order between them is defined as CPU-ID-ascending (a deterministic tie-break, not an arbitrary one). fixtures/gic/spi_route.trace — shared peripheral interrupt routed via affinity mask to a 3-CPU subset; expected: exactly those 3 CPUs' redistributors see the pending state.

Pitfalls

Redistributor desynchronization — manifestation: a redistributor's cached affinity view diverges from the distributor's authoritative table after a topology mutation; root cause: the Phase 2 topology-diff engine's atomic swap (14.6) not fanned out to per-CPU redistributor caches; debugging method: replay with I13's mask-validity check enabled every tick, not just on mutation; signal: affinity_mask_invalid_total > 0; recovery: redistributor caches must subscribe to the same atomic snapshot handle as the distributor, never a separately-timed copy. Affinity corruption — manifestation: an SGI reaches the wrong CPU set; root cause: Aff0-Aff3 decoding bug mapping an affinity level incorrectly onto the CpuMask; debugging method: replay sgi.trace with affinity-decode tracing; signal: fixture target-set mismatch; recovery: unit-test the affinity-decode function directly against ARM IHI 0069's worked examples (§5).

⬜ Phase 6 — Interrupt Arbitration, Priority Engine, IPI, and Timers §18

Objectives

Implement the delivery-arbitration engine that both sim-apic and sim-gic route through: vector priority classes, nested arbitration, fairness/starvation-bounded retry, plus IPI delivery (targeted and broadcast) and the timer-wheel facility backing periodic/deadline timers system-wide. This phase closes the loop opened by Phase 1's priority-aware dispatch queues.

Deliverable

A priority-aware, fairness-bounded interrupt-delivery engine unifying APIC and GIC arbitration behind one dispatcher, plus functional IPI and timer facilities feeding it.

Acceptance

Starvation detector validated: no pending vector waits more than 64 arbitration rounds under sustained high-priority flood (fixtures/priority/starvation.trace); nesting correctness across 16 levels (I10); bounded retry latency — 100% of retried deliveries resolve within retry_budget attempts (I9) with zero livelocks across 500 fuzz runs; IPI broadcast to 4096 CPUs completes within the p99 delivery budget (§4).

Fixtures

fixtures/priority/starvation.trace — sustained high-priority flood against a low-priority pending vector; expected: aging counter forces eventual delivery within the 64-round bound. fixtures/priority/nesting.trace — 16-level nested preemption; expected: unwinds in exact reverse order, matching Phase 3's nested_interrupt.trace semantics extended to cross-controller arbitration.

Pitfalls

Livelock — manifestation: two equal-priority vectors perpetually retry against each other with neither completing; root cause: retry scheduling without a deterministic tie-break; debugging method: replay under the fuzz corpus targeting equal-priority collisions; signal: delivery_retry_ exhausted_total climbing without corresponding completions; recovery: deterministic tie-break by event_id, identical discipline to Phase 1's dequeue tie-break (13.6). Starvation — manifestation: a low-priority class never completes under sustained load; root cause: missing aging mechanism; debugging method: replay starvation.trace; signal: fixture's 64-round bound violated; recovery: implement the aging counter, do not simply raise the priority-check frequency. Active-stack corruption — manifestation: I10 fires under IPI-heavy load specifically; root cause: IPI delivery bypassing the shared nesting-stack update path; debugging method: replay with IPI-only fixtures against the stack assertion; recovery: route IPI delivery through the same sim-priority nesting update as regular vectors, never a shortcut path (P15).

⬜ Phase 7 — Replay, Snapshots, and Persistence §19

Objectives

Implement deterministic replay end to end: append-only WAL, snapshot generation/restore, replay loader, and divergence detection. This phase makes P1/P6 executable rather than aspirational — it is where "byte-identical replay" becomes a testable property against real controller state from Phases 3–6.

Deliverable

A replayable deterministic runtime: any recorded WAL segment can be replayed to reproduce byte-identical controller state, snapshots can restore a run to a known point without replaying from the beginning, and divergence is detected automatically rather than discovered by manual diffing.

Acceptance

Byte-identical replay verified across 500 runs of fixtures/replay/divergence.trace's non- divergent baseline; divergence detection latency under 100 ms (§4 derived from C8, §32) once injected; snapshot restore under 5 sec for a 4 GB resident-state snapshot (§4, C6 derivation); replay seek latency under 200 ms to an arbitrary sequence number (§4).

Fixtures

fixtures/replay/divergence.trace — a WAL with one deliberately corrupted mid-stream record; expected: divergence detector fires within the sequence range containing the corruption, not at end-of-run. fixtures/replay/snapshot_restore.trace — a snapshot taken mid-run plus the WAL tail after it; expected: restoring the snapshot and replaying the tail reproduces the same terminal state as replaying the entire WAL from scratch.

Pitfalls

Replay skew — manifestation: replay reproduces state correctly but at a different logical-time alignment than the original run; root cause: LogicalTime not itself persisted per record, only inferred; debugging method: replay snapshot_restore.trace and diff per-record timestamps; recovery: persist LogicalTime explicitly in every ReplayRecord (§11), never re-derive it. Partial WAL writes — manifestation: a crash mid-fsync leaves a torn record at the WAL tail; root cause: no per-record checksum to detect a truncated write; debugging method: WAL integrity scan on load; signal: checksum mismatch at the exact torn offset; recovery: truncate to the last fully-checksummed record, resume from there (never attempt partial-record repair, per P4). Snapshot corruption — manifestation: a restored snapshot produces immediately-invalid controller state; root cause: bit-rot or an interrupted snapshot write; debugging method: checksum verification on every snapshot load (I11); recovery: restore the previous snapshot generation, per §23 FM-4.

⬜ Phase 8 — Observability Stack §20

Objectives

Implement the production-grade observability pipeline every earlier phase has been emitting stub telemetry toward: metrics registry, tracing spans, structured logging, and causal correlation IDs, now with real export and cardinality enforcement (P10/I12).

Deliverable

A full observability pipeline: metrics scrapeable via Prometheus, traces exportable via OpenTelemetry, structured JSON logs mandatory on every subsystem, all within the §4 overhead budgets.

Acceptance

OpenTelemetry export verified functional against fixtures/observability/trace_export.trace; metrics-scrape overhead measured under 2% CPU at 10M events/sec (§4); logging overhead under 5% CPU at the same load; cardinality enforcement rejects any label combination exceeding the configured budget in 100% of injected high-cardinality test cases.

Fixtures

fixtures/observability/trace_export.trace — a full delivery flow from IOAPIC assertion through EOI; expected: the exported OpenTelemetry trace contains one span per state transition in §8's state machine, correctly parented by causal ID.

Pitfalls

Metrics cardinality explosion — manifestation: the metrics backend's memory grows unbounded under a large topology; root cause: a per-vector-per-CPU label combination left un-sampled (65536 × 4096, §4); debugging method: inspect the registry's live label-set size against the I12 budget; signal: metrics_cardinality_total climbing; recovery: apply the sampling policy at the registry boundary, never at each individual call site inconsistently. Trace-sampling corruption — manifestation: a sampled-out span breaks a downstream trace's parent-child chain; root cause: sampling decisions made independently per span instead of per causal-ID root; recovery: sample at the trace root and propagate the decision down the causal chain (head-based sampling, not per-span).

⬜ Phase 9 — Fault Injection and Chaos Infrastructure §21

Objectives

Implement systematic, deterministically-replayable failure testing: queue-corruption injectors, latency injectors, packet-reorder injectors (for distributed replay mode), and clock-skew injectors. This is the final Phase 0-era phase — it validates that every invariant and recovery path documented in §7/§22/§23 actually fires under controlled adversarial conditions.

Deliverable

A programmable, deterministic failure-injection runtime: any invariant violation documented in §7 can be deliberately triggered, its detection/recovery path exercised, and the whole scenario replayed byte-identically for postmortem analysis.

Acceptance

Deterministic failure replay verified across 200 runs of fixtures/failure/queue_corruption.trace; containment verified: an injected panic in one domain worker (I14) leaves all peer domains' telemetry uninterrupted in 100% of runs; every §7 invariant has at least one corresponding chaos scenario exercising its detection path (14 for 14, full 1:1 coverage).

Fixtures

fixtures/failure/queue_corruption.trace — deliberate mid-flight corruption of a queued InterruptEvent's checksum; expected: I11's checksum verification rejects the record, the domain worker is isolated (I14) without affecting peers, and the scenario replays identically on rerun.

Pitfalls

Nondeterministic injection timing — manifestation: the same chaos scenario, replayed twice, injects the fault at a different logical tick; root cause: injector triggered from an ambient counter rather than an explicit seeded schedule; debugging method: diff injection_id-tagged events' timestamps across two runs; recovery: schedule every injector deterministically from the seed and the recorded tick count, never from real elapsed wall time (P1/P12 applied to the fault injector itself, which must obey the same rules as the system it tests).
