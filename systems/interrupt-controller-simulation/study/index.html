30. Mental Models & First Principles

  • MM1 — Interrupts Are Priority Queues With Physical Deadlines. An interrupt controller is fundamentally a priority queue with real-time delivery deadlines and a bounded active set; it predicts that nesting/preemption bugs look identical to priority-queue starvation bugs; without it, engineers treat IRR/ISR as booleans instead of an ordered active set, causing silent priority inversion; applies in §15.
  • MM2 — Determinism Is a Testing Multiplier, Not a Feature. Every nondeterminism source removed eliminates an entire class of flaky-test debugging permanently; predicts teams skipping logical time pay an order of magnitude more in triage time; the bug class without it is "unreproducible" reports closed as works-for-me; applies in §12.
  • MM3 — Backpressure Is Conservation of Mass. Interrupts, like fluid, must be conserved — every enqueue needs a matching dequeue or an explicit drop signal; predicts unbounded queues eventually OOM or desync replay; without it, invisible memory growth gets diagnosed as a generic "slow leak" instead of missing backpressure; applies in §13.
  • MM4 — Priority Without Fairness Is Starvation. Strict priority ordering guarantees the top class's latency at the expense of unbounded delay for the bottom; predicts low-priority vectors starve under sustained high-priority load unless explicitly bounded; without it, low-priority driver timeouts get blamed on drivers, not the scheduler; applies in §18.
  • MM5 — Replay Is Just a Second Execution With the Same Inputs. Replay correctness reduces to "is every nondeterminism source captured as an input"; predicts any uncaptured wall-clock, RNG, or scheduling read eventually diverges; without it, replay divergence gets blamed on "flaky hardware" instead of a missing input; applies in §19.
  • MM6 — A Redistributor Is a Per-CPU Cache of Distributor State. GICv3's redistributor exists because shared per-CPU affinity state doesn't scale as one table; predicts redistributor/ distributor desync bugs look exactly like cache-coherence bugs; without it, SGI/PPI routing bugs get dismissed as GIC "flakiness"; applies in §17.
  • MM7 — EOI Is a Lock Release. EOI is structurally identical to releasing a lock guarding a vector slot; predicts EOI-ordering bugs manifest like lock-ordering bugs (double-free / use- after-release); without it, EOI bugs get debugged as APIC-specific rather than recognized as a general concurrency pattern; applies in §15.
  • MM8 — Observability Cost Is Amortized Correctness Insurance. Every metric/span/log field is a pre-paid debugging session; predicts systems skipping instrumentation pay exponentially more in postmortem time than the CPU overhead they saved; applies in §20.

5. Required Reading

Books

  • Intel 64 and IA-32 Architectures Software Developer's Manual, Volume 3 — Intel Corporation (2023), ch. 10–11: Local APIC architecture, x2APIC mode, interrupt priority classes; applied in §15 and §16.
  • Linux Kernel Development — Robert Love (2010), ch. 7–8: interrupt handlers, softirqs, SMP scheduling interaction; applied in §13 and §18.
  • Understanding the Linux Kernel — Daniel P. Bovet & Marco Cesati (2005), ch. 4, 18: APIC handling, interrupt dispatch, scheduler wakeups; applied in §15.
  • Systems Performance — Brendan Gregg (2020, 2nd ed.), ch. 2, 5–6: latency analysis methodology, queueing theory basics, tracing; applied in §28.
  • Designing Data-Intensive Applications — Martin Kleppmann (2017), ch. 3, 5, 11: log-structured storage, replication, stream processing; applied in §19.
  • Operating Systems: Three Easy Pieces — Remzi H. Arpaci-Dusseau & Andrea C. Arpaci-Dusseau (2018), ch. 6, 36: interrupts and traps, concurrency fundamentals; applied in §12 and §18.
  • The Art of Multiprocessor Programming — Maurice Herlihy & Nir Shavit (2012, rev. ed.), ch. 7, 10: spin-lock design, concurrent queues, memory ordering; applied in §13.
  • Arm Architecture Reference Manual for A-profile architecture — Arm Ltd (current), exception-model and GIC-integration chapters: how the CPU exception model ties into distributor/redistributor state; applied in §17.

Papers

  • "The Performance Implications of Thread Management Alternatives for Shared-Memory Multiprocessors" — Anderson, Lazowska & Levy, 1989, IEEE Transactions on Computers: scheduler-interaction cost of interrupt-driven wakeup vs. spin-based coordination → informs domain-worker scheduling; applied in §18.
  • "Dapper, a Large-Scale Distributed Systems Tracing Infrastructure" — Sigelman et al., 2010, Google Technical Report: causal span propagation architecture → causal correlation IDs on every interrupt event; applied in §20.
  • "Using Magpie for Request Extraction and Workload Modelling" — Barham, Donnelly, Isaacs & Mortier, OSDI 2004: event-causality reconstruction from low-level traces → replay-trace schema design; applied in §20.
  • "Xen and the Art of Virtualization" — Barham et al., SOSP 2003: event-channel-mediated interrupt virtualization → informs the delivery engine's injected-vs-physical event model; applied in §18.
  • "ODR: Output-Deterministic Replay for Multicore Debugging" — Altekar & Stoica, SOSP 2009: bounding nondeterminism sources to make multicore replay tractable → the divergence-detector design; applied in §19.
  • "The Tail at Scale" — Dean & Barroso, 2013, CACM: tail-latency amplification under fan-out and retry → the p99 budget and retry-bound invariant; applied in §28.
  • "Wait-Free Synchronization" — Herlihy, 1991, ACM TOPLAS: lock-free progress guarantees → the bounded ring-buffer design for the event bus; applied in §13.
  • "Algorithms for Scalable Synchronization on Shared-Memory Multiprocessors" — Mellor-Crummey & Scott, 1991, ACM TOCS: queue-based spin-lock scalability under contention → lock-ordering discipline under domain-worker contention; applied in §18.

Reference Implementations

  • torvalds/linux — study arch/x86/kernel/apic/, kernel/irq/, drivers/irqchip/: interrupt layering, affinity management, topology awareness; pitfall: do not copy the full softirq/tasklet deferral machinery wholesale — it solves a different (in-kernel execution context) problem; applied in §14 and §15.
  • qemu/qemu — study hw/intc/, hw/i386/apic_common.c: device-model abstraction boundaries between APIC state and CPU objects; pitfall: do not copy its implicit global-state coupling between APIC and vCPU objects; applied in §15.
  • xen-project/xen — study its event-channel / interrupt-virtualization paths: hypervisor-mediated injected-interrupt semantics; pitfall: do not copy the shared-info-page ABI verbatim — it assumes real hardware coupling this simulator does not have; applied in §18.
  • seL4/seL4 — study its capability-mediated IRQ-handler objects: capability-scoped interrupt delivery instead of a global privileged dispatch table; pitfall: do not copy its historically single-core-oriented IRQ model into an SMP design; applied in §18.
  • firecracker-microvm/firecracker — study its minimal virtual-interrupt injection path: minimal-surface interrupt injection with no legacy device baggage; pitfall: do not copy its VMM-specific KVM ioctl coupling into a hardware-agnostic simulator; applied in §16.

RFCs / Specifications

  • ARM IHI 0048B — GICv2 Architecture Specification — pins distributor/CPU-interface register semantics, priority masking, SGI generation; applied in §17.
  • ARM IHI 0069 — GICv3 Architecture Specification — pins the redistributor/LPI/affinity-routing model superseding the GICv2 CPU interface; applied in §17.
  • Intel MultiProcessor Specification (MPS) 1.4 — pins the legacy IOAPIC redirection-table layout and MP-table discovery predating ACPI; applied in §16.
  • ACPI Specification, MADT (Multiple APIC Description Table) — pins the CPU/interrupt-controller enumeration entry layout; applied in §14.
  • OpenTelemetry Specification — pins the span/trace-context model behind causal correlation IDs; applied in §20.
  • Protocol Buffers Encoding — pins wire tag/varint rules behind append-only schema evolution (P7); applied in §11.

Glossary (§36) · 50 terms · site-wide glossary

APIC
Advanced Programmable Interrupt Controller, the x86 family covering Local APIC and IOAPIC.
IOAPIC
External interrupt-routing controller feeding vectors into per-CPU Local APICs.
LAPIC
Local APIC; per-CPU interrupt controller managing IRR/ISR/TMR and the local timer.
x2APIC
Extended-addressing LAPIC mode using MSRs instead of memory-mapped registers.
GIC
ARM Generic Interrupt Controller, covering GICv2 and GICv3 in this blueprint.
Distributor
GIC component holding shared (SPI) interrupt state.
Redistributor
GICv3 per-CPU component holding SGI/PPI state, replacing GICv2's shared table.
CPU Interface
The per-CPU GIC component a core actually reads to accept/acknowledge an interrupt.
ISR
In-Service Register; tracks currently-active vectors on a LAPIC.
IRR
Interrupt Request Register; tracks pending, not-yet-accepted vectors.
TMR
Trigger Mode Register; records edge vs. level trigger mode per vector.
EOI
End Of Interrupt; the signal releasing a vector's active state.
SGI
Software Generated Interrupt (GIC), roughly analogous to an APIC-world IPI.
PPI
Private Peripheral Interrupt (GIC); per-CPU device interrupt.
SPI
Shared Peripheral Interrupt (GIC); routed via the distributor to a CPU subset.
Vector
The numeric identifier selecting which handler an interrupt targets.
Pending Interrupt
An interrupt asserted but not yet accepted by its target CPU.
Active Interrupt
An interrupt accepted and currently being serviced (ISR-set).
Nesting
A higher-priority interrupt preempting a lower-priority one already active.
Starvation
A pending interrupt class never receiving service under sustained higher- priority load.
Priority Inversion
Lower-priority work blocking higher-priority work from proceeding.
Backpressure
Upstream propagation of downstream queue pressure (P8).
Bounded Queue
A queue with a hard capacity ceiling whose overflow is a detectable event.
WAL
Write-Ahead Log; the append-only durable record of committed events.
Snapshot
A point-in-time serialized copy of resident controller state.
Checksum
A verifiable integrity value (SHA-256 in this blueprint) guarding I11.
Replay Drift
Divergence from deterministic execution during replay.
Replay Cursor
The current replay position within a WAL, indexed by sequence number.
Divergence Detector
The component comparing live replay state against recorded state (§19).
Causal Correlation ID
An identifier linking all telemetry for one logical interrupt flow.
Topology Hash
A stable hash of a validated TopologyGraph, guarding cross-version replay.
Affinity Mask
CPU-targeting bitmap for a routing entry or SGI destination set.
Redirection Entry
IOAPIC routing descriptor mapping a pin to a vector/destination.
Delivery Mode
The interrupt-routing semantic (e.g., fixed, lowest-priority, NMI).
Trigger Mode
Edge or level activation semantic for a redirection entry.
Interrupt Storm
Sustained, excessive interrupt generation, often from a stuck level source.
TLB Shootdown IPI
An inter-processor interrupt requesting a remote TLB invalidation.
Timer Wheel
A data structure for efficiently managing many pending timers by deadline bucket.
Deadline Timer
A one-shot timer firing at a specific logical-time deadline.
Domain Worker
A scheduling unit owning one NUMA/CPU domain's execution context (ADR-08).
NUMA Node
A non-uniform-memory-access domain; the unit of locality for queues and workers.
Fixture
A named, versioned test input/expected-output pair under /fixtures (per phase).
Conformance Suite
The differential/property/fixture-based test corpus validating architectural correctness (§26).
Fault Injection
Deliberate, deterministic introduction of a failure condition (§21).
Chaos Scenario
A composed, seeded sequence of fault injectors (§21).
MADT
Multiple APIC Description Table; ACPI structure enumerating CPUs/interrupt controllers.
MPS
Intel MultiProcessor Specification; legacy predecessor to ACPI-based enumeration.
Crash-Only Recovery
Recovering exclusively via restart-and-replay, never in-place repair (P4).
Cardinality (metrics)
The number of distinct label-value combinations a metric can take.
Span (tracing)
A single traced operation, parented by causal ID, per OpenTelemetry's model.
