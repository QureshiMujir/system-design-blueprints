Mental Models & First Principles

MM1 — The hash is the address. A chunk's name is the hash of its content, so equal content is automatically one object and corruption is detectable at read time. Predicts: dedup and bit-rot detection fall out for free. Bug class without it: trusting storage and shipping silently-corrupt restores. Applied: P1, I1, Phase 2–3.

MM2 — Make misuse impossible, not merely discouraged. Derive the nonce from the chunk id + epoch instead of asking engineers to manage nonces. Predicts: the entire class of nonce-reuse CVEs cannot occur. Bug class without it: catastrophic AEAD nonce reuse. Applied: P3, I2, Phase 3.

MM3 — One mutable pointer, everything else immutable. Only the head pointer changes; chunks, trees, manifests are append-only. Predicts: concurrency reduces to a single CAS; GC is mark-sweep. Bug class without it: lost updates and torn manifests under concurrency. Applied: P4, I6, Phase 5/8.

MM4 — Separate the consistent view from the copy. Snapshot first, then walk the snapshot. Predicts: live databases back up cleanly without quiescing the application for the whole walk. Bug class without it: torn, unrestorable database backups. Applied: P2, Phase 9.

MM5 — Advisory caches, authoritative storage. The chunk index can be wrong; the repository's content addressing is the truth. Predicts: you can lose/rebuild the index with at worst a re-upload. Bug class without it: over-engineered cache-coherence machinery and data-loss from a "missing" decrement. Applied: I5, Phase 2/6.

MM6 — Reclamation is liveness, not refcounting. Compute the live set from retained manifests and delete the complement. Predicts: a crashed GC is always safe to re-run. Bug class without it: refcount leaks and double-frees. Applied: P7, I8, Phase 6.

MM7 — Verify what you will rely on, end to end. A backup is only as good as its last successful verify. Predicts: corruption is found on a schedule, not during a 3 a.m. restore. Bug class without it: discovering an unreadable backup at the worst time. Applied: P8, Phase 7.

MM8 — Rotation and rekey are different verbs. Rotation protects future data; rekey re-encrypts past data. Predicts: the correct response to a key compromise. Bug class without it: believing rotation alone protects old backups. Applied: Phase 10, T3.

MM9 — The bound that matters is the delta, not the size. Incremental backup, GC mark, and replication scale with change, not total bytes. Predicts: the system stays usable at 100 TB with daily small deltas. Bug class without it: O(repo_size) operations that stop completing. Applied: Scalability Analysis, Phase 11.

MM10 — Bind context into the ciphertext. The aad binds chunk_ref ‖ epoch ‖ algo. Predicts: swapping or re-labelling a chunk fails authentication. Bug class without it: chunk-substitution and cross-algo downgrade attacks. Applied: I12, T5, Phase 3.

Required reading (§5)

general

  • BorgBackup Internals documentation (2015 onward). Segment format, index format, lock manager, cache layout, metadata-application ordering. Applied: Phase 1 (restore metadata order), Phase 8 (lock manager), Phase 6 (retention default).
  • restic Design document (2014 onward). Pack-file format, snapshot format, master-key wrapping, index design. Applied: Phase 4 (packs), Phase 5 (manifest), Phase 2 (chunk index).
  • Kopia Architecture documentation (2019 onward). Splitter selection, BLAKE3 + AEAD scheme, maintenance discipline, manifests-as-commit-objects. Applied: §3, Phase 5, Phase 6.
  • Tarsnap technical-details whitepaper (Percival, 2009 onward). Authenticated encryption over content-defined chunks, encrypted index, the cleanest crypto exposition in the literature. Applied: Phase 3, ADR-06/07.
  • NetApp WAFL internals (Hitz 1994, extended in NetApp TRs incl. SnapVault TR-3487). Snapshots, SnapMirror, SnapVault archival. Applied: Phase 9 (snapshots), Phase 11 (replication).
  • ZFS internals / zfs(8) command reference (Bonwick et al.). Block-pointer-as-source-of-truth, uberblock, snapshot/clone duality, scrub, zfs send. Applied: Phase 9 (ZFS driver), Phase 11 (incremental send).
  • Quinlan & Dorward, 2002. Venti: A New Approach to Archival Storage. USENIX FAST. WORM discipline, score-as-address, fragmentation, hash-collision reasoning (updated to BLAKE3 in ADR-03). Applied: §3, Phase 2.
  • Hitz, Lau, Malcolm, 1994. File System Design for an NFS File Server Appliance. USENIX. The original CoW snapshot algorithm; consistency points. Applied: Phase 9.
  • Bonwick et al., 2003. The Zettabyte File System. USENIX FAST. Copy-on-write-never-overwrite discipline. Applied: §6 P2, Phase 9.
  • Percival, 2009. Tarsnap: Online Backups for the Truly Paranoid. Crypto construction over chunks. Applied: Phase 3, ADR-06.
  • Bernstein et al., 2012. ChaCha20 and Poly1305 (RFC 7539/8439). The AEAD construction and its security argument. Applied: Phase 3, ADR-07, Appendix C.
  • Arciszewski, 2017. XChaCha20: A Variant of ChaCha for Extended Nonces (IETF draft). 192-bit nonce / HChaCha20 derivation, makes random nonces safe. Applied: Phase 3, ADR-07.
  • Biryukov, Dinu, Khovratovich, 2016. Argon2. Memory-hard KDF, parameter selection, side-channel discussion. Applied: Phase 3, ADR-10.
  • Krawczyk, 2010. Cryptographic Extraction and Key Derivation: The HKDF Scheme. CRYPTO. Extract-then-expand, info-label domain separation. Applied: Phase 3, ADR-11.
  • Bernstein, Duif, Lange, Schwabe, Yang, 2012. High-speed High-security Signatures (Ed25519). CHES/JCEN. Manifest signing. Applied: Phase 5, ADR-05.
  • Xia et al., 2016. FastCDC: A Fast and Efficient Content-Defined Chunking Approach. USENIX ATC. Gear-hash CDC, dedup alignment. Applied: Phase 2, ADR-02.
  • Cox, Murray, Noble, 2002. Pastiche: Making Backup Cheap and Easy. OSDI. Convergent-encryption discussion (which we reject). Applied: ADR-09.
  • rdiff-backup + duplicity (manuals + source). Historical incremental/rsync context and threat model. Applied: ADR-02 (comparison).
  • Apple Time Machine engineering notes. Hard-link-based backup; operator-UX lessons. Applied: Phase 1 (hard links), Operational Readiness.
  • ioctl(BTRFS_IOC_SNAP_CREATE_V2) / BTRFS_IOC_SUBVOL_CREATE_V2 kernel reference. Btrfs snapshot semantics. Applied: Phase 9.1.
  • RFC 5869 (HKDF), RFC 8032 (Ed25519), RFC 8439 (ChaCha20-Poly1305). Test vectors and normative definitions. Applied: Appendix C, Phase 3, Phase 5.
  • Linux FIFREEZE/FITHAW ioctl + PostgreSQL pg_backup_start/pg_backup_stop docs. Freeze-pause and application-coordinated quiesce. Applied: Phase 9.2.

Glossary · 57 terms · site-wide glossary

AEAD
Authenticated Encryption with Associated Data; encrypts and authenticates ciphertext plus associated data.
aad
Additional Authenticated Data; here chunk_ref ‖ epoch ‖ aead_algo, binding ciphertext to context (I12).
Append-only
written once, never modified; all objects except head/lock pointers are append-only.
Argon2id
memory-hard passphrase KDF (Biryukov 2016); passphrase → master key.
BLAKE3
fast Merkle-tree-friendly cryptographic hash; the content-addressing primitive.
Btrfs
Linux CoW file system; one snapshot driver source.
Chunk
a content-defined slice of a file, named by BLAKE3 of its plaintext.
ChunkRef
the 32-byte BLAKE3 hash of a chunk's plaintext; its repository address.
Chunk index
advisory local set of known chunk_refs; speeds dedup (I5).
CDC
Content-Defined Chunking; boundaries chosen by content so inserts shift few chunks.
Content addressing
naming an object by the hash of its contents.
CoW
Copy-on-write; enables O(1) snapshots.
Convergent encryption
deriving the key from the plaintext for cross-tenant dedup; rejected (ADR-09).
Ed25519
elliptic-curve signature scheme; manifest signing.
Epoch
per-backup value mixed into chunk key/nonce derivation.
Etag
opaque object version token; basis of optimistic concurrency.
FastCDC
a fast content-defined chunking algorithm (Xia 2016); rank 109's chunker.
Fencing
invalidating an expired lock holder so a new holder can proceed safely.
fsfreeze
FIFREEZE/FITHAW ioctls that pause writes for a consistent walk.
GC
Garbage Collection; mark-sweep over the chunk set.
GFS retention
grandfather-father-son: keep N daily/M weekly/K monthly/J yearly.
Head pointer
the mutable per-source pointer to the latest manifest id.
HKDF
HMAC-based key-derivation function (Krawczyk 2010); master → purpose keys.
Incremental backup
storing only chunks new since the parent manifest.
Journal
per-backup replayable event log enabling resume after crash (I11).
KDF
Key Derivation Function.
KeyVersion
monotonic identifier for a master-key generation.
KMS
Key Management Service; can seal the master key.
LiveWalk
fallback snapshot driver that walks the live tree (best-effort consistency).
Lock manager
TTL-fenced repo lock ensuring one writer at a time (I6).
LVM
Logical Volume Manager; thin-snapshot driver source.
Manifest
the signed Merkle-tree commit object describing a backup; the only mutable-by-replacement object.
ManifestId
32-byte BLAKE3 of a manifest body.
Mark-sweep
GC that marks the live closure then deletes the complement.
Merkle tree
hash tree of TreeNodes enabling O(log N) partial restore and incremental verify.
Multipart upload
S3 mechanism for uploading large objects in parts.
Nonce
number-used-once for AEAD; here derived, never reused (I2).
Pack file
an aggregate object bundling many chunks to cut S3 request count.
Parent pointer
a manifest's link to the previous backup of the same source.
prost
Rust protobuf codegen; manifest serializer.
Pruning
retention + GC; reclaiming unreferenced storage.
Rekey
re-encrypting past backups under a new key (protects past data).
RepoId
random per-repository identifier.
Repository
the storage backend a backup lives in (local/S3/SFTP/REST).
Retention policy
pure function from manifest list to kept set (P6).
Rotation
adding a new key version for future backups (protects future data).
RPO
Recovery Point Objective; max tolerable data-loss window.
RTO
Recovery Time Objective; max tolerable restore-to-service time.
Snapshot
a consistent point-in-time view of a source tree.
SnapshotId
BLAKE3 of (source-root, timestamp, salt).
SnapVault
NetApp's incremental-replication protocol; Phase 11's model.
TreeNode
a node (File/Directory/Symlink/Other) in the Merkle-tree encoding of the source.
TreeNodeId
32-byte BLAKE3 of a TreeNode body.
Verify
end-to-end integrity check: fetch, decrypt, re-hash, check signature (P8).
WAFL
NetApp file system that introduced CoW snapshots (1994).
XChaCha20-Poly1305
extended-nonce AEAD (Arciszewski 2017 + Bernstein 2012); default chunk encryption.
ZFS
CoW file system/volume manager; snapshot driver source and replication prior art.
