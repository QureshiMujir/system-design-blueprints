1. Goal

1.1 Precise scope

A bounded-latency real-time media pipeline built from scratch: a directed graph of typed processing nodes connected by typed ports, carrying audio and video samples from capture through processing, encoding, transport, decoding, to render, with rigorous real-time guarantees (glitch-free audio, bounded end-to-end latency, A/V lip-sync).

  • Pipeline core: a Graph of Nodes connected by Ports; sources (capture), transforms (DSP/convert/scale), sinks (render). Pull and push scheduling. Media-type negotiation (caps) between ports.
  • Buffers & frames: reference-counted Buffer with timestamped Frame metadata (PTS/DTS); typed MediaType (audio/video, format, rate, layout); pooled allocation so the RT path never calls the system allocator.
  • Audio path: capture/playback over ALSA (Linux, locked) behind a portable backend trait; sample formats S16LE / F32; channel layouts (mono/stereo/N-channel); the RT audio callback contract (no allocation, no locks, no syscalls on the audio thread); period/buffer sizing vs latency; xrun (underrun/overrun) detection + recovery; polyphase-FIR sample-rate conversion; a small DSP block set (gain, mixer, biquad).
  • Video path: capture over V4L2 (locked); pixel formats YUV420P / NV12 / RGB; VideoFrame structs; color conversion; scaling; presentation timestamps.
  • Timing/clocks/sync: media clock vs wall clock vs capture-device clock; a presentation/pipeline clock; PTS/DTS; clock-drift estimation and resampling-based drift compensation; A/V sync to a master clock (audio-master); a jitter / de-jitter buffer for transport; an explicit latency budget decomposed across stages.
  • Real-time discipline: SCHED_FIFO/SCHED_RR thread scheduling, priority assignment, priority-inheritance / inversion avoidance, mlockall to defeat page faults, lock-free SPSC ring buffers between threads, bounded queues with explicit per-media backpressure (drop-oldest / block / drop-newest), a deadline model with deadline-miss accounting.
  • Transport (later phase): RTP-style packetization, sequence numbers, timestamping, a de-jitter buffer. Network is a later phase; the local capture→render path is the core.
  • Encoded-frame boundary: codec internals (H.264-style entropy coding) are DEFERRED and wrapped behind a typed PhaseDeferred("Deferred Features Register") seam; the pipeline carries encoded frames but does not implement the entropy coder here.
  • Tooling: rtpctl pipeline launcher / inspector; offline file-driven test rig; conformance vector runner.

1.3 Explicit non-goals

  • No codec entropy coder here (DCT/CABAC/CAVLC); EncodedFrame is opaque payload + metadata. Gated PhaseDeferred("Deferred Features Register").
  • No GPU offload for convert/scale; CPU reference paths only. Gated PhaseDeferred("Deferred Features Register").
  • No backends beyond ALSA/V4L2; the backend trait seam exists, others deferred.
  • No full network media protocols (SRTP, WebRTC ICE/DTLS, congestion control); only RTP-style packetization + de-jitter. Cross-link #161.
  • No hard real-time certification; the target is soft/firm RT with bounded, measured latency and glitch-free audio on a PREEMPT_RT-capable Linux.
  • No GUI; rtpctl is CLI only. Rendering sink is a file/loopback/null sink unless a simple display sink is configured.

1.4 Deployment model

  • Host binary (Linux, std): the pipeline runs as a single multi-threaded process. Threads: an RT audio thread (SCHED_FIFO, highest prio), an RT video thread, optional transport thread, and a non-RT control/telemetry thread. mlockall(MCL_CURRENT|MCL_FUTURE) at start.
  • Backend seam: AudioBackend / VideoBackend traits decouple the graph from ALSA/V4L2; an offline FileBackend drives deterministic tests with no hardware.
  • Offline-first: every phase is verifiable through the file-driven rig (WAV / raw-YUV in, WAV / raw-YUV / trace out) so CI needs no audio/video hardware.

1.10 Recommended language + rationale

Rust 2021, std host.

Reason Detail
No GC No stop-the-world pauses on the audio thread; deterministic drop = deterministic buffer recycle.

Zero-cost FFI Thin libc/alsa-sys/v4l2 bindings; direct ioctl/mmap without overhead.

Rejected: C (no safety, weaker test ergonomics, manual refcount on buffers is error-prone); C++ (UB surface, RT-unsafe STL allocation hidden in containers); Go (GC pauses fatal on the audio thread; goroutine scheduler not RT); Python (only an external differential oracle for DSP/format checks).

2. Why Build This

2.1 Unique systems knowledge

  • The pipeline-graph architecture — typed ports, caps negotiation, pull vs push scheduling, backpressure — the canonical media-framework design (GStreamer/PipeWire) built from first principles.
  • The real-time audio callback contract — why allocation, locks, and syscalls are forbidden on the audio thread, and how to move all of that off-thread via lock-free rings and pre-allocated pools.
  • Media-clock synchronization — three clocks (media, wall, device) that must be reconciled; drift estimation; resampling as the lever for drift compensation; lip-sync to a master clock.
  • Latency budgeting — decomposing end-to-end latency (capture + queue + process + encode + network + de-jitter + decode + render) into a quantified budget and defending each term.
  • Glitch-free operation — xrun detection/recovery, deadline-miss accounting, and bounded queues as the machinery that keeps audio uninterrupted under load.
  • Lock-free SPSC rings — single-producer/single-consumer wait-free queues with correct memory ordering as the only safe RT↔non-RT data path.

2.2 Historical / architectural significance

Media frameworks evolved from monolithic players to graph-based pipelines: DirectShow (filter graphs, 1996) → GStreamer (typed pads + caps, 2001) → PipeWire (low-latency graph + RT, 2017). The graph-of-typed-nodes model is now universal in audio (JACK, CoreAudio AUGraph), video (FFmpeg filtergraph), and pro-media (NDI, SMPTE 2110). Real-time media is where OS scheduling, lock-free concurrency, signal processing, and clock synchronization all meet under an unforgiving glitch-free constraint — a uniquely integrative systems exercise.

2.3 Engineering muscles

Graph/dataflow architecture; typed-port protocol design; real-time scheduling and priority assignment; lock-free concurrency with explicit memory ordering; buffer-pool / zero-allocation hot-path design; DSP (FIR/IIR/resampling); clock synchronization and drift control; latency analysis; fault injection and recovery; deterministic offline testing of an inherently timing-sensitive system.

2.5 Calibration value

Forces mastery of correctness-and-timing-first systems work where a single allocation on the audio thread causes an audible glitch, a wrong memory ordering on a ring buffer silently drops or duplicates frames, and a few-ppm clock drift desyncs lip-sync over minutes. Builds the rare ability to reason about an entire real-time data path end-to-end — scheduling, concurrency, DSP, clocks, and latency — and to keep it glitch-free under fault injection. A permanent step-up in real-time and multimedia engineering capability.

3.2 Per-box detail

Control / telemetry thread (media-cli, media-telemetry, negotiation in media-graph). Non-RT, lowest priority. Builds the graph from a description, drives caps negotiation (an offline activity that completes before streaming starts), and owns all observability: latency-budget instrumentation, xrun/deadline-miss counters, tracing spans, metrics export. Sends control messages to RT threads only via a lock-free MPSC channel; never blocks an RT thread. The single place allowed to allocate, log, and make syscalls freely.

Pipeline graph (media-graph). A directed graph of Nodes. Each Node exposes Pads (input/output); each Pad carries a typed Port whose MediaType (caps) is negotiated with the peer pad before streaming. Links connect a source pad to a sink pad only if caps intersect to a fixed format. The graph is partitioned into segments that run under a single scheduling discipline (pull or push) and on a single thread. Concurrency boundary: segments on different RT threads communicate only through SPSC rings.

Scheduler (media-sched). Decides per segment whether nodes are pulled (sink requests buffers upstream — natural for fixed-rate render sinks) or pushed (source delivers buffers downstream as captured). Owns the bounded queues between nodes and the explicit backpressure policy per media type. Implements the deadline model: each RT iteration has a deadline (= next device period), and overruns are accounted as deadline misses. Trust/timing boundary: it must never let an unbounded queue or a blocking call enter an RT segment.

Audio source / sink (media-audio). Wraps ALSA PCM capture/playback behind the AudioBackend trait. Enforces the RT audio callback contract: inside the callback (or the RT poll loop) there is no allocation, no lock acquisition, no syscall beyond the PCM read/write, and all buffers come from a pre-allocated pool. Detects xruns (EPIPE underrun/overrun) and recovers (snd_pcm_recover/prepare) while accounting the gap. Period/buffer sizing sets the latency floor.

DSP nodes (media-dsp). Transform nodes: Gain (per-sample scale), Mixer (sum N inputs with per-input gain, clamp/saturate), Biquad (second-order IIR filter, Direct Form I/II). The Resampler (polyphase FIR) converts sample rate and, critically, accepts a fractional ratio adjustment from the drift estimator to compensate device-clock drift. All process in-place or into pooled output buffers; no allocation in process(). Advanced DSP primitives are sourced from #174.

Video source / convert / scale / sink (media-video). Wraps V4L2 capture (mmap streaming I/O) behind VideoBackend. Decodes pixel formats (YUV420P, NV12, RGB), performs color conversion (e.g. YUV↔RGB via integer matrix) and scaling (bilinear reference). VideoFrame carries plane pointers/strides + PTS. The sink writes frames to a file/null sink (display sink deferred). Video runs on its own RT thread at a lower priority than audio.

Clocks + A/V sync (media-clock, media-sync). MediaClock advances with consumed samples (audio-master). WallClock is CLOCK_MONOTONIC. DeviceClock is inferred from the soundcard's actual sample-consumption rate. The drift estimator (a PI controller) compares media vs device progress and outputs a resampler ratio that nudges audio playout to match the device, keeping the buffer level stable. The lip-sync controller maps each video frame's PTS onto the master (audio) clock and decides present/drop/repeat. The de-jitter buffer absorbs transport arrival jitter into a smooth playout schedule.

RT substrate (media-rt). The foundation: a wait-free SPSC ring buffer (the only RT↔non-RT data path), RT thread creation (SCHED_FIFO with assigned priorities), mlockall(MCL_CURRENT|MCL_FUTURE) to pin pages, and deadline-miss accounting. Provides the primitives every RT segment is built on. The concurrency-correctness center of the project.

Transport (media-transport). Optional/later. Packetizes EncodedFrames into RTP-style packets (sequence number, timestamp, marker bit), and depacketizes + reorders on ingress, feeding the de-jitter buffer. The codec that produces/consumes EncodedFrame payloads is PhaseDeferred; transport treats payloads as opaque. Cross-links #161 (WebRTC) and #223 (reliable multicast).

4.3 RT discipline contract

On any RT thread: (1) no heap allocation (all buffers pooled, pre-touched after mlockall); (2) no blocking lock — only the wait-free SPSC ring and atomics; (3) no syscall except the device read/write and clock read; (4) bounded, predictable work per iteration (no unbounded loops, no I/O, no logging — telemetry is written to a lock-free ring and drained off-thread); (5) deadline = next device period, and overrun is recorded as a deadline miss with a timestamp.

6. Design Principles

  1. Glitch-free audio is the top invariant. No xrun, no audible discontinuity, under all in-scope load. Tradeoff: conservative buffer sizing raises latency. Ops: every xrun is counted and alerts. Violation: a single allocation/lock on the audio thread → underrun → audible click; the project's core promise breaks.

  2. No allocation, no locks, no syscalls on the RT path. All buffers pooled and page-locked; only wait-free rings + atomics; only device read/write + clock read. Tradeoff: more setup, fixed pools. Violation: a hidden Vec::push or Mutex::lock introduces unbounded latency → deadline miss.

  3. Typed ports + caps negotiation before streaming. Formats are fixed at link time, not per-buffer. Tradeoff: a negotiation phase up front. Violation: per-buffer format guessing causes silent conversion bugs and reallocation in the hot path.

  4. Backpressure everywhere, explicit per media type. Every inter-node queue is bounded with a declared policy (drop-oldest / block / drop-newest). Tradeoff: must choose a policy per edge. Violation: an unbounded queue grows without limit → memory blowup or latency creep; a blocking queue on the RT path → underrun.

  5. One master clock; everything else is derived. Audio-master by default; video and transport sync to it. Tradeoff: video may drop/repeat frames to follow audio. Violation: two free-running clocks → unbounded lip-sync drift.

  6. Drift is measured and compensated by resampling, not ignored. A PI controller turns device-clock drift into a resampler ratio. Tradeoff: a control loop to tune. Violation: uncompensated ppm drift → buffer slowly empties/fills → xrun or growing latency over minutes.

  7. The RT↔non-RT boundary is a single SPSC ring. No other shared mutable state crosses threads. Tradeoff: all control/telemetry is message-passed. Violation: shared state + a lock reintroduces priority inversion and nondeterminism.

  8. Deterministic offline testing first. The FileBackend makes every behavior reproducible without hardware. Tradeoff: maintain a faithful offline substrate. Violation: timing-dependent code only testable on hardware rots and cannot be CI-gated.

  9. Latency is budgeted, not discovered. Each stage has a quantified latency term; the sum is the contract. Tradeoff: upfront accounting + instrumentation. Violation: "it feels laggy" with no decomposition → unfixable.

  10. PTS/DTS are explicit and monotonic per stream. Every frame is timestamped at capture; presentation decisions use timestamps, never arrival order. Tradeoff: timestamp bookkeeping. Violation: presenting by arrival order → jitter and A/V desync.

  11. Buffers are reference-counted and pool-recycled. Ownership is explicit; the last reader returns the buffer to its pool. Tradeoff: refcount discipline. Violation: a leaked buffer exhausts the pool → backpressure stall or (worse) an allocation.

  12. Errors are typed and total on the RT path; never panic. Malformed input or device error returns a typed result; the RT loop degrades gracefully. Tradeoff: verbose error enums. Violation: a panic on the audio thread kills the stream.

  13. Observability without RT cost. RT threads write counters/events to a lock-free telemetry ring; the non-RT thread aggregates and exports. Tradeoff: eventual (not instant) metrics. Violation: logging on the RT thread → syscalls → glitch.

  14. Pull vs push chosen deliberately per segment. Render sinks pull (rate-driven); capture sources push (event-driven); the seam is a queue. Tradeoff: two scheduling modes to maintain. Violation: pushing into a pull segment without a queue couples rates and starves/overruns.

  15. The codec is a deferred, opaque boundary. EncodedFrame carries bytes + metadata; transport never inspects it. Tradeoff: no in-arc codec. Violation: leaking codec assumptions into transport breaks the seam and the cross-link to #380/#173.

7. System Invariants

Each: statement → why → enforced where → detection → telemetry → recovery → debugging.

  1. No system allocation occurs on any RT thread after streaming starts. Why: allocation latency is unbounded → glitch. Where: media-rt pools + a debug global allocator hook that flags RT-thread allocs. Detect: alloc-on-RT-thread assertion (debug builds), latency spikes (release). Telemetry: rt_alloc_violations. Recover: none — it is a bug; degrade by reusing last buffer. Debug: allocator backtrace + RT-thread id check.

  2. No blocking lock is acquired on any RT thread. Why: priority inversion → deadline miss. Where: only SPSC rings/atomics on RT paths; loom model tests. Detect: a try-lock that would block (debug trap); contention telemetry. Telemetry: rt_lock_violations. Recover: ring-based fallback. Debug: thread-priority + lock-owner trace.

  3. Audio playout produces no xrun under in-scope load. Why: top invariant. Where: media-audio sink; buffer-level monitor. Detect: ALSA EPIPE / buffer-level < threshold. Telemetry: xrun_total, buffer_level_frames. Recover: snd_pcm_recover + account the gap + (if recurring) raise latency. Debug: buffer-level timeline vs deadline-miss log.

  4. PTS is monotonically non-decreasing per stream. Why: ordered presentation. Where: capture timestamping + a monotonicity check at sink. Detect: PTS regression. Telemetry: pts_regressions. Recover: clamp/drop the offending frame. Debug: per-stream PTS trace.

  5. A/V sync error stays within ±20 ms of the master clock. Why: lip-sync. Where: media-sync lip-sync controller. Detect: |video_pts_mapped − master_now| > bound. Telemetry: av_sync_error_ms (gauge + histogram). Recover: drop (video ahead) / repeat (video behind) frames. Debug: sync-error timeline correlated with drift estimate.

  6. Every inter-node queue is bounded; depth never exceeds capacity. Why: bounded memory + latency. Where: media-sched queues. Detect: enqueue into a full queue triggers the declared policy. Telemetry: queue_depth{edge}, queue_drops{edge,policy}. Recover: policy applied (drop/block — block only off-RT). Debug: per-edge depth + drop counters.

  7. The buffer pool is conserved: buffers_out + buffers_free == pool_size. Why: no leaks, no allocation. Where: media-core::BufferPool refcount + a conservation check. Detect: count mismatch. Telemetry: pool_free{type}, pool_leak_suspected. Recover: reclaim on drop; if exhausted, backpressure. Debug: per-buffer refcount/owner tag.

  8. The SPSC ring neither drops nor duplicates an item under correct single-producer/single-consumer use. Why: data integrity across the RT boundary. Where: media-rt ring + loom tests. Detect: sequence-number gap/dup in a checked mode. Telemetry: ring_full_events, ring_empty_events. Recover: full → backpressure; empty → underrun handling. Debug: head/tail indices + memory-ordering model test.

  9. Caps are fully fixed on every active link before the first buffer flows. Why: no per-buffer format ambiguity. Where: media-graph negotiation. Detect: an unfixed/under-specified cap at stream start. Telemetry: negotiation_failures. Recover: refuse to start the segment; report the failing link. Debug: per-pad caps intersection log.

  10. Deadline misses are counted, timestamped, and never silently absorbed. Why: visibility into RT health. Where: media-sched/media-rt deadline accounting. Detect: iteration end > deadline. Telemetry: deadline_miss_total, deadline_overrun_us histogram. Recover: continue; if sustained, raise latency / shed load. Debug: overrun distribution + the node that overran.

  11. Clock-drift compensation keeps the audio buffer level within ±1 period of its target. Why: prevents slow drift to xrun. Where: media-clock estimator → media-dsp resampler ratio. Detect: buffer level drifts beyond band. Telemetry: drift_ppm, resampler_ratio, buffer_level_error. Recover: PI controller adjusts ratio. Debug: drift estimate vs buffer-level vs ratio over time.

  12. EncodedFrame payload is opaque to transport; no codec field is interpreted. Why: the deferred-codec seam. Where: media-transport packetizer. Detect: any access to payload internals (review/type-level). Telemetry: n/a. Recover: n/a. Debug: type boundary — payload is &[u8] + metadata only.

  13. Denormal floats are disabled on audio-processing threads (FTZ/DAZ set). Why: denormals cause 10–100× slowdown → glitch. Where: RT thread init in media-dsp/media-rt. Detect: a denormal-stress test measuring per-block time. Telemetry: process_block_us p99. Recover: re-assert FTZ/DAZ. Debug: block-time spike correlated with low-amplitude tails.

  14. Video frame presentation respects PTS; late frames are dropped, early frames wait. Why: smooth video + sync. Where: media-sync/video sink. Detect: present time vs PTS-mapped-to-master. Telemetry: video_frames_dropped, video_frames_repeated. Recover: drop/repeat per policy. Debug: PTS vs present-time scatter.

8. Domain Model / Data Formats / Protocol

8.1 Core entities

MediaType (caps) ::= Audio { format, rate, channels, layout, interleaved }
                   | Video { pixel_format, width, height, framerate }
                   | Encoded { codec_id (opaque), rate_or_fps }

Frame  ::= { pts: Option<i64>, dts: Option<i64>, duration: Option<i64>,
             flags: FrameFlags, buffer: BufferRef }     // PTS/DTS in clock ticks
Buffer ::= refcounted bytes from a BufferPool (audio samples | video planes | encoded bytes)
Port   ::= { direction: In|Out, caps: NegotiatedType, queue: BoundedQueue }
Node   ::= { kind: Source|Transform|Sink, pads: [Pad], process(...) }
Graph  ::= { nodes, links, segments(scheduling+thread assignment) }

8.2 Audio sample formats + layout

Format Bits Range Notes
S16LE 16 −32768..32767 interleaved default for capture/playback
F32 32 [−1.0, 1.0] nominal internal DSP format; clamp/saturate on output
  • Interleaved: [L0 R0 L1 R1 …]. Planar: [L0 L1 …][R0 R1 …]. Internal DSP prefers planar F32; conversion nodes bridge to S16LE interleaved for the device.
  • Channel layout: mono(1), stereo(2 = L,R), up to 8 (positional). A Frame's sample count = bytes / (channels × bytes_per_sample) for interleaved.
  • PTS unit: clock ticks at the media clock's timebase (e.g. 1/48000 s for audio-master at 48 kHz, or a common 90 kHz timebase for RTP).

8.3 Video pixel formats

Format Layout Chroma Bytes/px (avg)
YUV420P (I420) 3 planes: Y, U, V 4:2:0 (U,V quarter-res) 1.5
NV12 2 planes: Y, interleaved UV 4:2:0 1.5
RGB24 1 plane: R,G,B 4:4:4 3
  • Planes/strides: each plane has a pointer + stride (row bytes ≥ width × bpp, aligned). Chroma planes in 4:2:0 are ceil(w/2) × ceil(h/2).
  • Color conversion (BT.601, integer): Y = (66R+129G+25B+128)>>8 +16, U = (−38R−74G+112B+128)>>8 +128, V = (112R−94G−18B+128)>>8 +128, and the inverse for YUV→RGB; clamp to [0,255]. BT.709 coefficients swapped in for HD.
  • PTS: per-frame presentation timestamp in the media timebase; frame duration = timebase / framerate.

8.4 The pipeline scheduling model

PULL (rate-driven sink):   sink.pull() -> upstream.pull() -> ... -> source.produce()
PUSH (event-driven source): source.push(buf) -> queue -> downstream.process(buf) -> ...
SEAM:  push-source --[bounded queue, SPSC if cross-thread]--> pull-or-process downstream
  • A segment is a maximal chain under one discipline on one thread. Audio capture (push) → DSP → resampler → sink (pull) typically splits at the queue between capture thread and playback thread.
  • The render sink defines the rate: it pulls one period worth of samples every device period. Upstream must have produced them (else underrun).

8.5 Caps negotiation (state machine)

UNNEGOTIATED --query--> peer caps --intersect--> CANDIDATE set
CANDIDATE --fixate(pick one)--> FIXED --commit--> READY (buffers may flow)
intersection == empty -> NEGOTIATION_FAILED (link rejected)
  • Each pad advertises a caps set (e.g. audio: {S16LE,F32}×{44100,48000}×{1,2}). Linking intersects source-out with sink-in; fixate picks a single concrete MediaType (preferring the source's native, then lowest-conversion-cost). A transform node may transform caps (e.g. resampler maps any-rate-in to fixed-rate-out).

8.6 Clocks and timestamps

Clock Source Role
WallClock CLOCK_MONOTONIC reference time, latency measurement
MediaClock samples consumed (audio-master) the timeline PTS are expressed against
DeviceClock actual soundcard sample rate (drifts) what playout really runs at
PresentationClock MediaClock + base offset maps PTS → "now" for presentation
  • Drift model: device_rate = nominal_rate × (1 + ε) where ε ∈ ±ppm. Over time, samples-consumed vs samples-produced diverge → buffer level changes. The estimator measures the rate of buffer-level change → ε → resampler ratio r = 1/(1+ε).
  • A/V sync (audio-master): present a video frame when presentation_clock.now() ≥ map(video_pts). If far behind, drop; if early, hold (repeat last).

8.7 De-jitter buffer (transport ingress)

arrival times jittery -> insert by seq# into reorder buffer -> release on a smooth schedule
target_depth = ceil(jitter_p99 / frame_interval)   (adaptive, bounded)
late packet (past playout point) -> discard (counted); gap -> conceal/skip

8.8 RTP-style packet (transport)

| V(2) | P | X | CC(4) | M | PT(7) | sequence number (16) | timestamp (32) | SSRC (32) | payload ... |
  • sequence number: +1 per packet, detects loss/reorder. timestamp: media-clock sample/tick of the frame (same value across packets of one frame). M (marker): last packet of a frame. Payload = a slice of an EncodedFrame (opaque).

8.9 Worked examples

Audio period math (48 kHz, stereo, S16LE, period=256): bytes/period = 256 × 2 × 2 = 1024 B; period duration = 256/48000 = 5.333 ms; with 3 periods buffered, device buffer = 768 frames = 16 ms; the sink must deliver 256 frames every 5.333 ms or underrun.

Drift over an hour: device at +100 ppm consumes 48 004.8 Hz; over 3600 s it consumes 172 817 280 frames vs 172 800 000 produced → a 17 280-frame (360 ms) surplus consumed → without compensation, the buffer empties in ~ (buffer_frames / (rate×ppm)) = 768 / (48000×1e-4) ≈ 160 s → xrun. With compensation, resampler outputs 1.0001× samples to refill.

A/V sync decision: master_now = 10.000 s; next video frame PTS maps to 9.985 s → 15 ms late, within ±20 ms → present. Next maps to 9.950 s → 50 ms late → drop and advance.

Malformed / failure-path examples:

  • Caps intersection empty (source F32-only, sink S16LE-only, no convert node) → NEGOTIATION_FAILED; link rejected at build, before streaming.
  • ALSA returns EPIPE (underrun) mid-stream → xrun counted → snd_pcm_recover → resume; if it recurs > N/min, telemetry recommends a larger period.
  • SPSC ring full when audio thread pushes a captured period → backpressure event; under drop-oldest the oldest queued period is discarded (counted) so the freshest audio plays (latency bounded over completeness).
  • Video PTS regresses (camera glitch) → pts_regressions++, frame dropped, presentation continues from the last good PTS.

31 Reproducibility pinned rust-toolchain.toml + Cargo.lock; seeded sim time floating Bit/sample-for-sample replay offline. Floating toolchain wins in a research prototype where always using the latest compiler for new optimizations outweighs the cost of occasional breakage.

  • Malformed: core/pts_regression.json (decreasing PTS → flagged), negotiation/empty.json.

1.6 Pitfalls

  • rescale overflow / rounding — i64×i64 overflows; using float loses precision and breaks determinism; compute in i128, round-half-even; signal: PTS jitter at high tick values.
  • Refcount leak / double-free — a BufferRef cloned but not dropped leaks a slot (pool exhausts); a double-return corrupts the free-list; debug with per-slot owner tags + a leak check at teardown.
  • Caps fixate non-determinism — picking from a HashSet randomizes the chosen format; use an ordered preference list; signal: flaky negotiation across runs.
  • Interleaved vs planar sample-count math — computing frames from byte length must account for layout × channels × bytes/sample; an error here mis-slices every audio buffer.

1.7 Performance Concerns

  • MediaType is Copy-small; keep it out of the heap. BufferPool free-list ops are O(1); the off-RT path may use a tiny lock, but the RT path (Phase 4+) uses a lock-free variant. rescale is a few integer ops; precompute constant ratios where possible.

1.8 Edge Cases

  • Zero-duration frame (single sample / still image) valid.
  • Empty buffer (DLC-0-like silent frame) — pool slot of size 0 disallowed; minimum slot size enforced.
  • MediaType::Encoded intersect is identity-or-empty (opaque codec_id must match).
  • Timebase with den that does not divide evenly — round-half-even resolves ties deterministically.

1.9 Failure Analysis

  • A core-type bug corrupts every layer. Detection: unit + property + differential (rescale vs Fraction). Blast radius: whole pipeline. Recovery: fix + regression vector. Forensic: failing fixture + pool owner-tag dump.

1.10 Operational Notes

  • These types are the public API surface; freeze their layout/semantics as a v1 contract (CHANGELOG). pool_free{type} becomes a top metric. Document the PTS timebase convention (audio media-clock vs 90 kHz RTP) for downstream consistency.

Phase 2 — Pipeline graph, typed ports, caps negotiation, scheduler, bounded queues, backpressure

2.1 Objectives

  • Implement media-graph (Node/Port/Pad/Graph, link-time caps negotiation, segment partitioning) and media-sched (pull/push scheduling, BoundedQueue with explicit per-edge backpressure, the deadline model). Still single-threaded / offline.

2.2 Detailed Implementation Steps

  • port.rs/node.rs: Port{dir,caps}, Pad{port,peer}, the Node trait (kind, pads, transform_caps, process). A Source produces into its out-pads; a Sink consumes from in-pads; a Transform maps in→out and may transform caps (resampler: any-rate-in → fixed-rate-out). (GStreamer pad model — §5.3 ref-impl #1; Design Principle 3)
  • negotiate.rs: link-time FSM (§8.5) — query peer caps, intersect (via media-core), fixate, commit to Fixed; empty intersection → NEGOTIATION_FAILED. Negotiation runs once, before streaming. (Invariant 9; §5.2 paper #2 GStreamer design docs)
  • graph.rs: add/link/validate (all active links Fixed — Invariant 9); partition groups nodes into Segments by scheduling discipline + target ThreadClass, inserting a queue at every cross-discipline / cross-thread seam. (ADR-12 scheduling model; Design Principle 14)
  • media-sched: pull.rs (sink requests N frames upstream recursively to the source), push.rs (source delivers; downstream processes; queue at the seam); queue.rs BoundedQueue<T> with BackpressurePolicy (Block off-RT / DropOldest / DropNewest) returning a PushResult; deadline.rs DeadlineAccount (miss if finished > deadline; histogram of overrun). (ADR-12; Invariant 6; Invariant 10; Liu §5.1 book #6)
  • Wire process() invocation: the scheduler walks a segment in topological order, passing input frames and collecting outputs. (Design Principle 4 backpressure; ADR-4 buffer strategy)
  • Observability: queue_depth{edge}, queue_drops{edge,policy}, deadline_miss_total, negotiation_failures; a per-segment span. (ADR-17 tracing; ADR-18 metrics)
  • Harness: build small graphs (source→gain→sink) offline; drive with the FileBackend; assert frame flow + queue behavior under induced overflow. (ADR-16 offline substrate; ADR-19 cargo test)

2.3 Deliverable

  • A graph that links nodes with negotiated caps, partitions into segments, and runs (offline) under pull or push with bounded queues and deadline accounting; small graphs process file input to output.

2.4 Acceptance Criteria

  • Linking incompatible pads → NEGOTIATION_FAILED at build (before any buffer flows); compatible pads fixate to the expected MediaType.
  • A 3-node graph processes a WAV through gain to output identically to a reference (Phase 5 fills real gain; here a pass-through).
  • BoundedQueue enforces capacity; each policy behaves per queue/*.json (drop-oldest keeps newest; drop-newest keeps oldest; block off-RT).
  • Deadline misses are counted on an injected slow node; never silently absorbed.

2.5 Conformance Fixtures

  • negotiation/link_ok.json, negotiation/link_fail.json — pad caps → fixed type / failure.
  • queue/drop_oldest.json, queue/drop_newest.json, queue/block.json — push sequence vs capacity → accepted/dropped trace.
  • queue/deadline_miss.json — finish times vs deadlines → miss count + overrun histogram.
  • Malformed: negotiation/unfixed_link.json (validate rejects), queue/over_capacity.json.

2.6 Pitfalls

  • Blocking backpressure on an RT segment — Block policy on an edge that lands on an RT thread stalls the audio callback → underrun; restrict Block to off-RT edges; the partitioner must flag it; signal: xruns correlated with queue-full.
  • Negotiation at buffer time instead of link time — guessing format per buffer causes per-buffer conversion + allocation; fixate once at link; signal: format flips mid-stream.
  • Topological cycle / unpartitioned graph — a cycle deadlocks the scheduler; validate must reject cycles (or require an explicit queue to break them); debug with a cycle check.
  • Drop-policy off-by-one — dropping the wrong end (oldest vs newest) changes latency-vs-completeness semantics; verify against queue/*.json.
  • Deadline measured against the wrong clock — using wall time where media time is meant inflates/deflates misses; pin each deadline to the device-period boundary.

2.7 Performance Concerns

  • Scheduler walk is O(nodes) per iteration; keep the segment node list a Vec for cache-friendly traversal. BoundedQueue ops O(1). Negotiation is one-time (no hot-path cost). Avoid per-process allocation — outputs come from pools (Phase 1).

2.8 Edge Cases

  • Single-node segment (source-only or sink-only) — degenerate but valid.
  • A transform that changes rate (resampler) splits the rate domain; the seam queue absorbs the rate difference.
  • Queue capacity 1 (tightest coupling) — push must still respect policy.
  • Zero-capacity queue disallowed (would always drop/block).

2.9 Failure Analysis

  • Graph/scheduler bugs cause stalls, format errors, or unbounded latency. Detection: negotiation + queue vectors + offline graph runs. Blast radius: whole pipeline structure. Recovery: fix negotiation/partition; regression. Forensic: per-edge depth/drop counters + segment span trace.

2.10 Operational Notes

  • rtpctl inspect renders the negotiated graph (nodes, fixed caps, segment/thread assignment, queue depths). queue_drops rising = backpressure active → a tuning signal. Document which edges are RT (no Block) vs off-RT. The Node trait is the extension API; keep it stable.

Phase 3 — Lock-free SPSC ring + RT thread model (SCHED_FIFO, mlockall, deadline accounting)

3.1 Objectives

  • Implement media-rt: a wait-free SPSC ring buffer (the sole RT↔non-RT data path), RT thread creation (SCHED_FIFO with assigned priorities), mlockall + page pre-touch, and RT deadline-miss accounting. This is the concurrency-correctness foundation.

3.2 Detailed Implementation Steps

  • spsc.rs: Spsc<T>::new(cap_pow2) → (Producer, Consumer); a ring of cap slots with separate head/tail atomics on distinct cache lines (padding to avoid false sharing). push: read tail (Relaxed by producer), compute next, compare to cached head; if full return Err(item); write slot, publish tail with Release. pop: read head, compare to tail loaded Acquire; if empty None; read slot, publish head Release. Producer/Consumer are !Sync (one thread each), Send. (Herlihy & Shavit §5.1 book #5; ADR-5 RT↔non-RT data path; Design Principle 7)
  • Memory-ordering proof: model the ring under loom (bounded threads) asserting no lost/duplicated item and no torn read across the publish (Invariant 8). (ADR-21 loom; §5.3 ref-impl #8 ringbuf/rtrb)
  • thread.rs: spawn_rt(prio, name, body) — spawn a std thread, then sched_setscheduler(0, SCHED_FIFO, {prio}) mapping RtPriority::{AudioHigh,VideoMid,TransportLow} to descending integers; if it fails (no CAP_SYS_NICE), fall back to normal scheduling and set a degraded flag (CI path). (ADR-6 RT scheduling; Liu & Layland §5.2 paper #9; §5.1 book #8 Love)
  • memlock.rs: lock_all_memory() = mlockall(MCL_CURRENT|MCL_FUTURE), then pre-touch every BufferPool page (write a byte per page) so no minor fault occurs later. (ADR-7 page locking; §4.3 RT discipline contract)
  • deadline.rs: DeadlineAccount increments deadline_miss_total and records overrun into a histogram when an RT iteration finishes past its deadline; counters are read off-thread. (Invariant 10; ADR-24 criterion jitter harness)
  • Telemetry ring: a dedicated Spsc<TelemetryEvent> the RT thread pushes counters/events into; the non-RT media-telemetry thread drains it (no logging on the RT thread — Invariant 13 support). (ADR-17 tracing; Design Principle 13)
  • Harness: a producer/consumer stress test (single each) under loom; a "no-alloc" test using a custom global allocator that panics if invoked on a thread tagged RT; a jitter harness measuring wakeup-to-work latency. (ADR-21 loom; ADR-24 RT-jitter harness)

3.3 Deliverable

  • A verified wait-free SPSC ring, RT-thread spawning with priorities (graceful degradation without privileges), page-locked memory, and deadline accounting — exercised by a stress + jitter harness.

3.4 Acceptance Criteria

  • loom proves the SPSC ring drops/duplicates nothing and has no data race under all interleavings of one producer + one consumer.
  • The no-alloc harness confirms zero allocations on a thread tagged RT during a sustained push/pop loop.
  • spawn_rt sets SCHED_FIFO where privileged; degrades cleanly (flag set, test skips RT assertion) where not.
  • mlockall succeeds (or warns) ; after lock + pre-touch, a fault-counting test shows zero minor faults during the steady-state loop.
  • Deadline misses counted on injected overrun; histogram populated.

3.5 Conformance Fixtures

  • ring/fill_drain.json — push/pop sequence vs capacity → accept/empty trace.
  • ring/wrap.json — wrap-around past capacity boundary → indices/values.
  • ring/full_empty.json — full→push rejected; empty→pop None.
  • rt/deadline.json — iteration finish vs deadline → miss count.
  • (loom is code-driven, not a JSON vector; recorded as a CI job result.)

3.6 Pitfalls

  • Wrong memory ordering on the ring — using Relaxed for the publish lets the consumer read a slot before the write is visible → torn/garbage data; producer publishes tail Release, consumer loads Acquire; debug with loom; signal: occasional corrupt frame only under load.
  • False sharing of head/tail — head and tail on the same cache line bounce between cores, tanking throughput; pad to a cache line each; signal: ring throughput far below memory bandwidth.
  • ABA / capacity that is not power-of-two — non-pow2 forces a modulo (slow) and index arithmetic bugs; require pow2 and mask; signal: indices drift after many wraps.
  • mlockall without pre-touch — MCL_FUTURE locks future pages but the first write still faults if the page was never resident; pre-touch all pool pages; signal: a latency spike on the very first buffer use.
  • Forgetting to drop RT privileges / runaway priority — a buggy RT loop at SCHED_FIFO can starve the whole machine; cap priorities below kernel threads, document rtprio ulimit, provide a watchdog.
  • Allocator on the RT thread via a hidden path — format!, Vec::push, Box, or even a String in an error path allocates; the no-alloc harness must cover error branches too.

3.7 Performance Concerns

  • The ring is the hottest cross-thread structure; target ops in the tens of nanoseconds, throughput near memory bandwidth. Batch where possible (push/pop a slice). Cache-line padding is essential. The telemetry ring must be large enough that the RT side never blocks on a full telemetry queue (drop telemetry, never the audio).

3.8 Edge Cases

  • Capacity 1 ring (tightest) — push/pop must still be wait-free and correct.
  • Producer much faster than consumer → ring stays full → producer sees Err (backpressure, not block) on the RT side.
  • Consumer much faster → ring empties → None → RT underrun handling (Phase 4).
  • Thread spawn on a system with rtprio limit 0 — degrade, do not crash.

3.9 Failure Analysis

  • A ring or ordering bug corrupts the RT↔non-RT boundary intermittently — the hardest class. Detection: loom + checked-sequence stress + ASan. Blast radius: every cross-thread frame. Recovery: fix ordering/padding; re-run loom. Forensic: head/tail snapshots, sequence-gap log, loom counterexample trace.

3.10 Operational Notes

  • Document the host RT-tuning prerequisites (/etc/security/limits.conf rtprio, CPU governor=performance, isolcpus optional) in tools/rt_tune.sh + BUILD_PLAN. deadline_miss_total and a degraded (non-RT fallback) flag are top operational signals. On a non-RT kernel, expect higher jitter; the budget (§4.1 relaxed) reflects it.

Phase 4 — Audio capture/playback (ALSA) + RT callback contract + xrun recovery

4.1 Objectives

  • Implement media-audio: the AudioBackend trait, the ALSA PCM capture/playback impl (locked), the RT audio callback/poll contract (no alloc/lock/syscall beyond read/write), period/buffer sizing vs latency, xrun (EPIPE) detection and recovery, and S16LE↔F32 / interleave↔planar conversion at the device edge.

4.2 Detailed Implementation Steps

  • backend.rs: AudioBackend trait (open_capture/open_playback/read/write/buffer_level); XrunOr<E> result. FileBackend (offline WAV) already exists from P0; this phase adds AlsaBackend behind the hardware feature. (ADR-2 audio backend; ADR-16 offline substrate)
  • alsa.rs: open PCM (snd_pcm_open), set hw params (format S16LE/F32, rate, channels, access RW_INTERLEAVED or MMAP), set period_size + periods (latency = period × periods / rate); set sw params (start threshold, avail_min). read = snd_pcm_readi; write = snd_pcm_writei. buffer_level from snd_pcm_avail/delay (drift input). (ALSA PCM spec §5.4; §5.3 ref-impl #4 PortAudio ALSA layer, #6 alsa-lib test/pcm.c)
  • callback.rs: the RT poll loop body (run via spawn_rt(AudioHigh, …)): acquire a pooled buffer, read/write exactly one period, hand the buffer across the SPSC ring to/from the graph thread; absolutely no allocation, no lock, no logging — events go to the telemetry ring. The body is the process driver for the audio segment's RT half. (Bencina §5.2 paper #5 RT rules; ADR-5 SPSC ring; Invariant 1; Invariant 2)
  • xrun.rs: on read/write returning -EPIPE (under/overrun), call recover_xrun (snd_pcm_recover then snd_pcm_prepare if needed), mark the next frame DISCONT, and push an xrun telemetry event with a timestamp; if xruns exceed a rate threshold, emit a "increase period" recommendation. (Invariant 3; ALSA PCM spec §5.4)
  • format.rs: branch-light S16LE↔F32 (/32768.0, clamp×32767, round) and interleave↔planar shuffles; these run on the conversion node (graph thread), not necessarily the device callback. (ADR-8 F32 internal format; §8.2 audio sample formats)
  • Integrate: capture push-source on the RT audio thread → SPSC ring → graph thread (DSP) → SPSC ring → playback pull-sink on the RT audio thread (loopback example). (ADR-12 push/pull model; Design Principle 2)
  • Observability: xrun_total, buffer_level_frames (gauge), period_us, frames_captured/played; a per-period span on the non-RT side only. (ADR-17 tracing; ADR-18 metrics)
  • Harness: offline first (WAV in→WAV out, deterministic); then a hardware loopback test (capture→playback) measuring round-trip latency and counting xruns over a soak. (ADR-16 FileBackend; ADR-24 RT-jitter harness)

4.3 Deliverable

  • Audio capture and playback over ALSA honoring the RT callback contract, with configurable period/buffer sizing, working xrun recovery, and format/layout conversion; an offline WAV pipeline and a hardware loopback both run.

4.4 Acceptance Criteria

  • Offline: a WAV routed capture→(passthrough)→playback equals the input sample-for-sample.
  • Hardware loopback at default latency (256×3) runs 60 min with xrun_total == 0.
  • RT contract verified: the no-alloc harness shows zero allocations on the audio thread during steady state and during an injected xrun-recovery path.
  • Format conversion S16LE↔F32 round-trips within 1 LSB (quantization) and matches an FFmpeg reference; interleave↔planar is exact.
  • buffer_level_frames tracks the device buffer and feeds the drift estimator (Phase 6).

4.5 Conformance Fixtures

  • audio/format_roundtrip.json — S16LE↔F32 sample sets → expected (±1 LSB).
  • audio/interleave.json — interleaved↔planar shuffles → exact.
  • audio/period_latency.json — (rate, period, periods) → latency ms.
  • audio/xrun_recovery.json — injected EPIPE sequence → recover + DISCONT flag + xrun count (offline-simulated via FileBackend fault hook).
  • Malformed: audio/unsupported_format.json (device refuses → typed error, no panic).

4.6 Pitfalls

  • Allocation/log/lock inside the audio callback — the classic cause of clicks; any format!, Vec, Mutex, or println! on the audio thread → underrun; route everything through pooled buffers + the telemetry ring; debug with the no-alloc harness + xrun-vs-event correlation.
  • Period/buffer sizing mismatch — avail_min/start-threshold inconsistent with period size causes early/late wakeups and xruns; follow the documented ALSA sw-param sequence; signal: periodic xruns at a fixed cadence.
  • Ignoring partial reads/writes — snd_pcm_writei may write fewer frames than requested; looping incorrectly drops samples; handle short counts; signal: pitch/gaps in output.
  • Wrong xrun recovery state — calling recover but not prepare/start leaves the PCM stuck; follow recover→prepare→(re)start; signal: stream halts after the first xrun.
  • Format/endianness assumption — assuming the device gives F32 when it gives S16LE (or wrong endianness) corrupts every sample; query and convert; signal: white noise / garbage.
  • Blocking vs non-blocking mode confusion — a blocking readi on the RT thread is acceptable only if it blocks for ≤ one period; a misconfigured large buffer blocks too long → deadline miss; size deliberately.

4.7 Performance Concerns

  • The conversion (S16↔F32, interleave↔planar) is per-sample; vectorize-friendly, branch-light; keep it off the device callback where possible. readi/writei are the only syscalls on the RT path — one per period. Buffer-level reads are cheap. Avoid copying: read directly into a pooled buffer; pass by BufferRef across the ring.

4.8 Edge Cases

  • Device opened at a rate it does not natively support → ALSA resamples or refuses; prefer to negotiate the device's native rate and resample in our resampler (Phase 5) for control.
  • Capture and playback on different devices with independent clocks → two device clocks → drift between them (Phase 6 handles).
  • Very small period (64) on a non-RT kernel → frequent xruns → telemetry recommends a larger period.
  • Mono device, stereo graph (or vice versa) → channel up/down-mix at the conversion node.

4.9 Failure Analysis

  • Audio-path bugs are immediately audible (clicks, dropouts, garbage). Detection: offline sample-exact tests + hardware soak + the no-alloc harness + xrun telemetry. Blast radius: the audio output (the core promise). Recovery: xrun recover for transient; raise latency for sustained; fix the RT-contract violation for clicks. Forensic: xrun timeline vs deadline-miss vs buffer-level.

4.10 Operational Notes

  • xrun_total is the single most important operational metric; any nonzero in production alerts. Runbook docs/runbooks/xrun.md: correlate xruns with CPU load, deadline misses, and period size; the standard mitigation is a larger period (latency↑) or RT-priority/isolcpus tuning. rtpctl inspect shows period/buffer/latency and live buffer level. The AudioBackend trait is the portability seam; non-ALSA backends are PhaseDeferred.

Phase 5 — Audio DSP nodes (gain / mixer / biquad) + polyphase resampler

5.1 Objectives

  • Implement media-dsp: Gain, Mixer, Biquad nodes and the polyphase-FIR Resampler with a fractional-ratio input (the drift-compensation hook), all RT-safe (no alloc/lock in process), planar F32, with denormals disabled. Advanced DSP primitives are sourced from #174.

5.2 Detailed Implementation Steps

  • gain.rs: Gain{gain} — out[i] = in[i] * gain; parameter smoothing (one-pole ramp toward a target) to avoid zipper noise on gain changes. (Pirkle §5.1 book #3 parameter smoothing; ADR-8 F32 internal)
  • mixer.rs: Mixer{gains} — out[i] = clamp(Σ_k in_k[i] * gains[k], -1.0, 1.0); saturate (not wrap) on overflow; N inputs → 1 output. (Design Principle 2 no alloc in process())
  • biquad.rs: BiquadCoeffs{b0,b1,b2,a1,a2} (normalized, a0=1); Biquad state z1,z2 (Direct Form II transposed for numeric stability); coefficient designers for low/high/band-pass/peak/shelf (RBJ cookbook). Per-channel state. (Smith §5.1 book #2 biquad DF-II; Lyons §5.1 book #1 filter design)
  • resampler.rs: a polyphase FIR — a windowed-sinc prototype low-pass split into phases sub-filters of taps each; a phase accumulator steps by 1/ratio per output sample; process(input, output) -> (consumed, produced); set_ratio(r) updates the step for drift compensation (Phase 6 drives it). Anti-alias cutoff at min(in,out)/2. (Smith & Gossett §5.2 paper #1 ICASSP 1984; ADR-9 resampler choice)
  • denormal.rs: set_denormals_off() sets FTZ/DAZ (x86 MXCSR) / FZ (aarch64 FPCR) on RT threads at start (Invariant 13). (Intel/AMD optimization manuals §5.2 paper #10; ADR-29)
  • All nodes implement Node::process writing into pooled output buffers; no allocation; coefficient/filter-bank memory allocated once at construction. (ADR-4 buffer strategy; Invariant 1)
  • Observability: process_block_us{node} (p50/p99 via off-RT aggregation of timestamps the RT side records), resampler_consumed/produced. (ADR-17; ADR-18)
  • Harness: reference outputs generated by scripts/gen_dsp_refs.py (numpy/scipy) for gain/biquad/resampler; differential vs FFmpeg swresample for the resampler; property tests (biquad stability: poles inside unit circle; resampler length relationship). (ADR-23 differential oracle; ADR-20 proptest)

5.3 Deliverable

  • A small DSP node set and a quality polyphase resampler, all RT-safe, matching numpy/FFmpeg references; a tone→resampler→WAV example runs offline.

5.4 Acceptance Criteria

  • Gain/Mixer/Biquad outputs match the numpy/scipy reference within a tight tolerance (e.g. ≤1e-5 RMS for F32).
  • Resampler: output length = round(input_len × ratio) (±1); SNR vs an ideal resample ≥ a threshold (e.g. ≥ 80 dB for the designed taps); matches FFmpeg swresample within tolerance.
  • No allocation in any process() (no-alloc harness); denormals confirmed off (denormal-stress block time stays flat).
  • Mixer saturates (never wraps) on overflow; gain smoothing eliminates zipper noise (spectral check).

5.5 Conformance Fixtures

  • dsp/gain.json, dsp/mixer.json — input + params → expected output (reference).
  • dsp/biquad_lp.json, dsp/biquad_peak.json — coeffs + input → output; impulse/step response.
  • dsp/resample_48_to_44.json, dsp/resample_44_to_48.json — input → output (+ SNR floor).
  • dsp/resampler_ratio_change.json — mid-stream ratio change (drift comp) → continuous output (no click).
  • Malformed: dsp/biquad_unstable.json (coeffs with poles outside unit circle → flagged), dsp/denormal_stress.json.

5.6 Pitfalls

  • Denormals not disabled — low-amplitude filter tails produce denormal floats → 10–100× slowdown → block overruns deadline → xrun; set FTZ/DAZ per RT thread; debug with the denormal-stress block-time test; signal: glitches only on quiet/decaying signals.
  • Biquad Direct Form I numeric blowup — DF-I accumulates error; use DF-II transposed; signal: filter output drifts/oscillates over long runs.
  • Resampler phase-accumulator drift — float accumulation error over millions of samples shifts the sub-filter index; use a high-precision (f64 or fixed-point) accumulator; signal: slow pitch drift.
  • Ratio change discontinuity — snapping the resampler ratio causes a click; ramp the ratio (the PI controller output is already smooth) and keep filter history continuous; verify with resampler_ratio_change.json.
  • Mixer overflow wrap — summing without clamp wraps F32→loud artifacts on the S16 conversion; saturate; signal: loud clicks on loud mixes.
  • Allocation in coefficient redesign — recomputing biquad coeffs on a parameter change must not allocate on the RT thread; precompute or compute in fixed scratch; signal: alloc-on-RT violation when tweaking a filter live.

5.7 Performance Concerns

  • The resampler is the heaviest DSP (taps × output samples MACs); keep the inner loop tight, contiguous filter banks, no bounds-check surprises (use iterators/get_unchecked only with proven bounds). Biquad is ~5 MACs/sample. Gain/mixer are trivial. Target: a full audio block (256 samples × channels) through gain→biquad→resampler well under one period. Cache: keep filter state and coeffs hot; planar layout aids vectorization.

5.8 Edge Cases

  • Ratio = 1.0 exactly (no resampling needed) → fast pass-through path.
  • Extreme ratio (e.g. 96k→8k) → strong low-pass; ensure enough taps to avoid aliasing.
  • Zero-length input block → zero output, no state change.
  • Gain = 0 (mute) / very large gain → clamp at the mixer/output.
  • Single-tap / single-phase degenerate resampler config — guard against div-by-zero.

5.9 Failure Analysis

  • DSP bugs produce wrong/glitchy audio (aliasing, instability, clicks) or RT overruns (denormals). Detection: reference + differential + property + denormal-stress. Blast radius: audio quality + RT timing. Recovery: fix math / re-enable FTZ; regression with the offending signal. Forensic: per-node block-time + the input signal that triggered it.

5.10 Operational Notes

  • process_block_us p99 per node is the RT-headroom signal; if it approaches the period budget, an xrun is imminent → shed/scale. Document the resampler taps/phases vs quality/CPU tradeoff. The resampler's set_ratio is the single integration point for clock-drift compensation (Phase 6). Advanced filters/effects come from #174; this crate keeps the minimal in-pipeline set.

Phase 6 — Clocks: media clock, presentation clock, PTS handling, drift estimation

6.1 Objectives

  • Implement media-clock: the Clock trait and the four clocks (Wall/Media/Device/Presentation), PTS assignment/handling against a timebase, and the PI drift estimator that turns device-clock drift into a resampler ratio to keep the audio buffer level stable (Invariant 11).

6.2 Detailed Implementation Steps

  • clock.rs: Clock{now, timebase}. WallClock = CLOCK_MONOTONIC (ns). MediaClock advances by samples consumed by the sink (audio-master): now = base + consumed_frames in the audio timebase. DeviceClock is inferred — from buffer_level trend and wall time, estimate the real device rate. PresentationClock = MediaClock + base_offset; map(pts) converts a PTS to a wall-relative presentation instant. (ADR-11 audio-master; Design Principle 5; §8.6 clock model)
  • PTS handling: capture stamps each frame's PTS from the MediaClock at capture (pts = frames_captured_so_far rescaled to the stream timebase); rescale (Phase 1) converts between audio (1/rate) and a common 90 kHz timebase for transport/video alignment. (Invariant 4; RFC 3550 §5.2 paper #8; §8.2 PTS unit)
  • drift.rs: DriftEstimator — a PI controller. Input: error = buffer_level_frames − target_frames (target = half the device buffer). Output: ratio = 1 + Kp*error + Ki*∫error, clamped to ±max-ppm. This ratio is fed to the resampler's set_ratio so playout speeds up/slows down imperceptibly to hold the buffer level. drift_ppm() reports (ratio−1)*1e6. (ADR-10 PI controller; Mills/PTP §5.2 paper #7; Design Principle 6; Invariant 11)
  • Tie-in: the sink reports buffer_level each period (Phase 4); the estimator updates each period; the resampler (Phase 5) applies the ratio next block. The loop runs on the graph thread, not the device callback. (ADR-9 resampler ratio hook; §4.3 RT discipline — no controller on RT thread)
  • Observability: drift_ppm, resampler_ratio, buffer_level_error, media_clock_now, wall_vs_media_skew. (ADR-18 metrics; Invariant 11)
  • Harness: offline drift simulation — the FileBackend models a device consuming at nominal×(1+ε); assert the estimator converges and the buffer level stays within ±1 period over a long run; sweep ε ∈ {−1000,…,+1000} ppm. (ADR-16 FileBackend; ADR-32 virtual clock)

6.3 Deliverable

  • A clock subsystem with a master media clock, presentation mapping, monotonic PTS, and a converging drift estimator that holds the audio buffer level stable under simulated device drift.

6.4 Acceptance Criteria

  • PTS monotonic non-decreasing per stream; rescale between timebases matches the reference.
  • Drift estimator converges: for any ε in ±1000 ppm, buffer-level error settles to within ±1 period within a bounded time, and stays there (no oscillation/instability) over a 60-min sim.
  • drift_ppm reported within a tolerance of the injected ε.
  • No xrun in the drift sim once converged; the ratio changes are smooth (no clicks — ties to Phase 5).

6.5 Conformance Fixtures

  • clock/pts_assign.json — captured frame indices → PTS (per timebase).
  • clock/rescale_pairs.json — already in core; cross-checked here for audio↔90kHz.
  • clock/drift_converge.json — injected ε sequence → buffer-level trajectory + final ratio.
  • clock/drift_sweep.json — ε sweep → convergence time + steady-state error per ε.
  • Malformed: clock/drift_step.json (sudden ε jump → controller responds, bounded overshoot), clock/pts_regression.json.

6.6 Pitfalls

  • PI gains mistuned — too aggressive → oscillation (audible pitch wobble); too soft → slow convergence, near-xrun before it catches up; tune Kp/Ki against the sweep; signal: buffer-level oscillates or drifts.
  • Integrator windup — the integral term saturates during a long error, then overshoots; clamp the integrator (anti-windup); signal: large overshoot after a sustained drift.
  • Wrong sign on the control — speeding up when the buffer is full (should slow down) diverges fast → immediate xrun; verify the sign against the buffer-level definition.
  • Mixing clock domains — comparing a wall-time delta to a media-time delta without rescale corrupts the drift estimate; keep domains explicit and rescale; signal: nonsense ppm.
  • PTS from the wrong clock — stamping PTS from wall time instead of the media clock couples PTS to scheduling jitter; stamp from the MediaClock (samples consumed); signal: jittery PTS.
  • Estimator updated on the device callback — running the controller on the RT thread risks alloc/jitter; run it on the graph thread from reported buffer levels.

6.7 Performance Concerns

  • The estimator is a few FLOPs per period — negligible. Clock reads are cheap (CLOCK_MONOTONIC via VDSO; sample counters are atomics). The cost is in the resampler applying the ratio (Phase 5). Keep clock state on the graph thread; the RT thread only reports buffer_level and consumed_frames via atomics/the telemetry ring.

6.8 Edge Cases

  • ε = 0 (no drift) → ratio stays ~1.0; controller idle.
  • Two capture/playback devices with independent clocks → two drift loops (or resample capture to the playback clock).
  • A clock that jumps (device reset) → estimator sees a step; anti-windup + clamp keep it bounded; mark DISCONT.
  • Startup transient: buffer level fills from empty → the controller must not over-correct during prime.

6.9 Failure Analysis

  • Clock/drift bugs cause slow latency creep, eventual xrun, or pitch wobble — subtle and time-delayed. Detection: drift sim/sweep + buffer-level monitoring + drift_ppm sanity. Blast radius: audio continuity + A/V sync (next phase). Recovery: re-tune gains / fix sign; regression with the ε pattern. Forensic: buffer-level + ratio + drift_ppm timelines.

6.10 Operational Notes

  • drift_ppm and buffer_level_error are key health gauges; a rising |drift_ppm| toward the clamp means the device is near tolerance limits. Runbook docs/runbooks/drift.md: distinguish device-drift (expected, compensated) from a clock fault (step/jump). The master-clock choice (audio) is documented; switching masters is a design-time decision. Cross-link #394 for the offset/skew estimation theory.

Phase 7 — A/V sync to master clock + jitter buffer

7.1 Objectives

  • Implement media-sync: the lip-sync controller that schedules video presentation against the master (audio) clock (present/drop/repeat within ±20 ms), and the adaptive, bounded de-jitter buffer that absorbs transport/arrival jitter into a smooth playout schedule.

7.2 Detailed Implementation Steps

  • avsync.rs: LipSync{bound_ms} — decide(video_pts, master_now, clock): compute err = clock.map(video_pts) − master_now; if |err| ≤ bound → Present; if video is late (err < −bound) → DropFrame (advance to the next, catching up); if early (err > +bound) → RepeatLast (hold). error_ms reports the signed error for telemetry. The audio path is never resampled for sync (audio is master); only video is dropped/repeated. (ADR-11 audio-master; Design Principle 5; Invariant 5; §4.2 ±20 ms target)
  • jitter.rs: JitterBuffer<T> — insert by sequence number into a reorder structure; target_depth = ceil(jitter_p99 / frame_interval), adapted from observed inter-arrival variance (an EWMA of jitter); pop_due(now) releases the frame whose scheduled playout ≤ now; a packet arriving after its playout point → LateDiscard (counted); buffer beyond max depth → Overflow (drop per policy). Bounded capacity. (§5.3 ref-impl #9 libwebrtc NetEq; §8.7 de-jitter buffer model; Design Principle 4)
  • Integration: video frames (captured or depacketized) enter the jitter buffer keyed by PTS/seq; the video RT thread pops due frames and asks LipSync for a decision before presenting at the sink. (ADR-12 scheduling model; Phase 8 V4L2 output path)
  • Master-clock distribution: the MediaClock (Phase 6) is shared read-only with the video thread (atomic snapshot); the video thread never writes it. (Design Principle 7 SPSC-only shared state; ADR-5)
  • Observability: av_sync_error_ms (gauge + histogram), video_frames_dropped, video_frames_repeated, jitter_buffer_depth, jitter_late_discards, jitter_overflow. (ADR-17; ADR-18; Invariant 5)
  • Harness: offline — drive audio + video with known PTS and an injected jitter/latency profile; assert sync error stays within bound and drop/repeat decisions match expectations; sweep jitter magnitude. (ADR-16 FileBackend; ADR-32 virtual clock; ADR-20 proptest)

7.3 Deliverable

  • A lip-sync controller keeping audio and video aligned to the master clock within ±20 ms, and an adaptive de-jitter buffer that smooths jittery arrivals with bounded depth — verified offline against jitter profiles.

7.4 Acceptance Criteria

  • For a synthetic A/V stream with injected video jitter (e.g. ±15 ms) and a fixed audio master, av_sync_error_ms p99 ≤ 20 ms; the correct frames are dropped/repeated per sync/*.json.
  • The jitter buffer's adaptive depth tracks the injected jitter (depth ≈ ceil(jitter_p99/interval)); late packets are discarded (counted), not presented out of time.
  • No audio is altered for sync (audio remains sample-exact; only video drop/repeat).
  • Overflow/late-discard are bounded and counted; the buffer never grows unbounded.

7.5 Conformance Fixtures

  • sync/present_drop_repeat.json — (video_pts, master_now) → decision.
  • sync/lip_sync_profile.json — A/V stream + jitter profile → sync-error trajectory + drop/repeat counts.
  • sync/jitter_depth_adapt.json — inter-arrival profile → adapted target depth.
  • sync/jitter_reorder.json — out-of-order seq# → in-order release.
  • Malformed: sync/late_packet.json (past playout → discard), sync/jitter_overflow.json, sync/pts_gap.json (missing frame → conceal/skip).

7.6 Pitfalls

  • Resampling audio for sync — stretching audio to match video is audible; audio is master, video follows; only drop/repeat video; signal: pitch artifacts when sync corrects.
  • Sync bound too tight — a ±2 ms bound forces constant drop/repeat (judder); ±20 ms (target ±10) is perceptually safe; signal: visible stutter despite small error.
  • Jitter buffer too shallow/deep — too shallow → late discards + gaps; too deep → excess latency; adapt to measured jitter_p99 with hysteresis; signal: either drops or laggy video.
  • Reorder vs duplicate — a retransmitted/duplicated packet with a seen seq# must be ignored, not re-inserted; dedup on seq#; signal: a frame presented twice.
  • Mapping PTS with the wrong clock base — using wall time instead of the presentation clock offsets the whole sync; map via PresentationClock; signal: constant sync bias.
  • Wraparound of seq# / timestamp — 16-bit seq and 32-bit RTP timestamps wrap; compare with modular arithmetic; signal: a flood of "late" discards at wrap.

7.7 Performance Concerns

  • The jitter buffer is a small ordered structure (a ring or a tiny heap keyed by playout time); ops O(log depth) or O(1) for a ring; bounded depth keeps it cache-resident. The sync decision is a couple of comparisons per frame. Video drop/repeat avoids work (drop) or repeats a buffer (no copy). The master-clock snapshot is a single atomic load on the video thread.

7.8 Edge Cases

  • Audio-only stream (no video) → lip-sync inactive; jitter buffer still smooths audio packets in the transport phase.
  • Video far ahead of audio at startup (priming) → repeat until audio catches the schedule.
  • A long gap (lost frames) → conceal by repeating the last good frame; mark DISCONT.
  • Exactly-on-the-bound error → choose Present (inclusive bound) deterministically.
  • Variable frame rate video → frame_interval per-frame from duration, not a fixed assumption.

7.9 Failure Analysis

  • Sync bugs cause visible lip-sync drift, judder, or stutter; jitter-buffer bugs cause gaps or latency. Detection: jitter-profile sims + sync-error histogram + drop/repeat counters. Blast radius: video presentation + perceived A/V quality. Recovery: re-tune bound/depth; fix clock mapping; regression with the profile. Forensic: sync-error timeline + per-frame decision log + jitter-depth trace.

7.10 Operational Notes

  • av_sync_error_ms p99 and video_frames_dropped/repeated are the A/V-quality SLO signals. Runbook docs/runbooks/av-desync.md: separate clock-drift desync (Phase 6) from jitter-buffer or scheduling causes. The de-jitter buffer adds a quantified latency term to the budget (Phase 10). Cross-link #161 (WebRTC NetEq-style adaptive buffering) for the advanced version.

Phase 8 — Video capture (V4L2) + pixel formats + color convert + scale

8.1 Objectives

  • Implement media-video: the VideoBackend trait, the V4L2 capture impl (mmap streaming, locked), VideoFrame (planes + strides + PTS), pixel-format handling (YUV420P/NV12/RGB24), color conversion (YUV↔RGB, NV12↔I420), and a bilinear scaler — all CPU reference paths (GPU PhaseDeferred).

8.2 Detailed Implementation Steps

  • backend.rs: VideoBackend trait (open_capture/dequeue/requeue). FileBackend (raw-YUV) from P0; this phase adds V4l2Backend behind the hardware feature. (ADR-3 V4L2 backend; ADR-16 offline substrate)
  • v4l2.rs: open /dev/videoN; VIDIOC_QUERYCAP; VIDIOC_S_FMT (pixel format, width, height); VIDIOC_REQBUFS (mmap); VIDIOC_QUERYBUF + mmap each buffer; VIDIOC_QBUF all; VIDIOC_STREAMON; capture loop: poll → VIDIOC_DQBUF (a filled buffer) → wrap as a VideoFrame (planes into pooled or mmap'd memory, PTS from the buffer timestamp mapped to the media clock) → consumer uses it → requeue (VIDIOC_QBUF). The video RT thread runs this via spawn_rt(VideoMid, …). (V4L2 spec §5.4; §5.3 ref-impl #7 v4l2-ctl capture.c; ADR-6 SCHED_FIFO VideoMid)
  • frame.rs: VideoFrame{mt, planes[3], pts}; PlaneRef{buf, stride, rows}. Strides may exceed width (alignment); convert/scale must honor stride. (§8.3 pixel formats; Jack §5.1 book #7 strides/planes)
  • convert.rs: BT.601/709 integer YUV↔RGB (§8.3 coefficients, clamp to [0,255]); NV12↔I420 (deinterleave/interleave the UV plane). Operate plane-by-plane respecting stride. (ITU-R BT.601/709 §5.4; §8.3 color conversion formula; ADR-23 FFmpeg swscale oracle)
  • scale.rs: bilinear scaler — for each output pixel, sample the 4 nearest input pixels with fractional weights; per-plane (chroma planes scaled at their subsampled resolution). Reference quality; GPU/SIMD PhaseDeferred. (Design Principle 15 deferred boundary; §5.3 ref-impl #5 FFmpeg swscale as oracle)
  • sink.rs: file sink (write raw frames / a simple container) and null sink; a display sink (DRM/KMS, Wayland) is PhaseDeferred("Deferred Features Register"). (Deferred Features Register)
  • Integrate: capture (push) on the video RT thread → SPSC ring → graph thread (convert/scale) → jitter buffer + lip-sync (Phase 7) → video sink. (ADR-5 SPSC ring; ADR-12 push model)
  • Observability: video_frames_captured, convert_us, scale_us, video_pts, v4l2_dqbuf_errors. (ADR-17; ADR-18)
  • Harness: offline (raw-YUV in → convert/scale → raw-YUV out) with reference outputs from FFmpeg swscale; a hardware capture smoke test (capture N frames, check format/size/PTS monotonicity). (ADR-23 differential oracle; ADR-16 FileBackend)

8.3 Deliverable

  • Video capture over V4L2 with mmap streaming, correct pixel-format handling, CPU color conversion and bilinear scaling matching FFmpeg references, and a file/null sink; offline and hardware-capture paths run.

8.4 Acceptance Criteria

  • Offline convert (YUV420P↔RGB24, NV12↔I420) matches FFmpeg swscale within a tight per-pixel tolerance (rounding).
  • Bilinear scale (e.g. 1280×720→640×360 and up) matches a reference within tolerance; strides honored (no green/garbage rows).
  • Hardware capture: N frames dequeued at the requested format/resolution; PTS monotonic; buffers requeued (no leak; steady-state REQBUFS count conserved).
  • Convert/scale process() allocation-free on the RT/graph path (output buffers pooled).

8.5 Conformance Fixtures

  • video/yuv420p_to_rgb.json, video/rgb_to_yuv420p.json — sample frames → expected (reference).
  • video/nv12_to_i420.json — plane reshuffle → exact.
  • video/scale_down.json, video/scale_up.json — input → bilinear output (+ tolerance).
  • video/stride_aligned.json — non-trivial stride → correct handling.
  • Malformed: video/odd_dimensions.json (4:2:0 with odd w/h → chroma rounding), video/unsupported_pixfmt.json (typed error).

8.6 Pitfalls

  • Ignoring stride — assuming stride == width × bpp corrupts every row when the device pads rows; always index by stride; signal: a sheared/garbled image.
  • Chroma subsampling rounding (odd dimensions) — 4:2:0 chroma is ceil(w/2)×ceil(h/2); off-by-one on odd sizes reads/writes out of bounds; round up; signal: a colored edge artifact / crash.
  • Color matrix / range mismatch — BT.601 vs 709, and full-range vs limited-range (16–235) — using the wrong one washes out or over-saturates color; pick per resolution and signal range; verify against FFmpeg; signal: tinted output.
  • V4L2 ioctl ordering — REQBUFS/QUERYBUF/QBUF/STREAMON must be in order; a missing QBUF before STREAMON starves capture; follow the documented sequence; signal: DQBUF blocks forever.
  • Forgetting to requeue (QBUF) — not returning a dequeued buffer exhausts the V4L2 queue → capture stalls; requeue after use; signal: capture halts after REQBUFS frames.
  • Mapping V4L2 timestamp to the media clock — using the raw struct timeval without rescaling to the media timebase breaks A/V sync; rescale; signal: video constantly offset from audio.

8.7 Performance Concerns

  • Color convert and scale are the heaviest CPU here (per-pixel, megapixels × fps); the reference paths are O(pixels) with tight inner loops; keep planes contiguous; SIMD/GPU are PhaseDeferred but the data layout (planar, aligned strides) is chosen to enable them later. Avoid copies: convert/scale write into pooled output frames. At 1080p60 the budget is tight on CPU — telemetry must flag if convert_us+scale_us approaches the frame interval.

8.8 Edge Cases

  • Odd width/height with 4:2:0 → chroma dimension rounding.
  • Capture format the camera does not support → enumerate (VIDIOC_ENUM_FMT) and pick a supported one or fail with a typed error.
  • Resolution change mid-stream (rare) → renegotiate caps + reallocate the pool (off-RT, before resuming).
  • A frame with V4L2_BUF_FLAG_ERROR → mark CORRUPT/DISCONT, requeue, count it.
  • Very high resolution exceeding the CPU budget → telemetry warns; downscale earlier in the graph.

8.9 Failure Analysis

  • Video bugs corrupt the image (stride/chroma/matrix) or stall capture (ioctl/requeue). Detection: offline convert/scale vs FFmpeg + hardware capture smoke + PTS monotonicity. Blast radius: video output. Recovery: fix conversion/ioctl sequence; requeue; regression. Forensic: a saved corrupt frame + the format/stride/matrix used + dqbuf error log.

8.10 Operational Notes

  • v4l2_dqbuf_errors, convert_us/scale_us p99, and capture frame-rate are the video-health signals. Document the supported pixel formats and the BT.601/709 + range policy. The VideoBackend trait and the planar/strided VideoFrame are the portability seam; the display sink and GPU convert/scale are PhaseDeferred. Cross-link #173/#380 for the codec that will consume these frames.

Phase 9 — Encoded-frame transport boundary (encode/decode behind PhaseDeferred) + RTP packetization

9.1 Objectives

  • Implement media-transport: the EncodedFrame boundary (opaque payload; the codec that produces/consumes it is PhaseDeferred), RTP-style packetization (sequence number, timestamp, marker) and depacketization + reorder feeding the de-jitter buffer (Phase 7). Establishes the network path while keeping the codec out of scope.

9.2 Detailed Implementation Steps

  • codec.rs: EncodedFrame{pts, dts, keyframe, payload: BufferRef}; CodecId opaque (Invariant 12). The encoder/decoder traits are declared but their bodies are PhaseDeferred("Deferred Features Register") → cross-link #380 (video codec), #173 (image codec). For testing, a pass-through "codec" wraps raw frames as EncodedFrame payload so the transport path is exercisable end-to-end without a real codec. (ADR-13 codec PhaseDeferred; Design Principle 15; Invariant 12)
  • rtp.rs: RtpHeader{marker, payload_type, seq, timestamp, ssrc}; packetize(frame, mtu, ssrc, pt, out) — split frame.payload into ≤MTU chunks, assign consecutive seq, the same timestamp (frame PTS rescaled to a 90 kHz / sample-rate timebase) across all chunks, set marker on the last; depacketize(pkt) parses the header and yields header + payload slice. (NAL-aware H.264 packetization per RFC 6184 is documented but deferred with the codec.) (RFC 3550 §5.4; RFC 6184 §5.4; §5.2 paper #8; ADR-14 RTP transport)
  • reorder.rs: an ingress reorder buffer keyed by seq that reassembles a frame's chunks (until the marker), detects loss (seq gaps) and reorder, and forwards complete EncodedFrames to the JitterBuffer (Phase 7). (§8.7 de-jitter buffer; §8.8 RTP packet format; Design Principle 10 PTS ordering)
  • Transport runs on its own thread (TransportLow); it is off the audio/video RT threads. Sockets (UDP) and any recv/send are here, never on the audio/video RT path. (ADR-6 TransportLow; Design Principle 2 no-syscall on RT; §5.1 book #9 Stevens UDP)
  • Observability: rtp_packets_sent/recv, rtp_loss, rtp_reorder, frames_reassembled, mtu_splits. (ADR-17; ADR-18)
  • Harness: offline loopback — packetize a stream, shuffle/drop packets per a profile, depacketize + reorder, assert the reassembled frames equal the input (modulo declared loss); fuzz the depacketizer. (ADR-22 cargo-fuzz; ADR-16 offline; ADR-19 golden vectors)

9.3 Deliverable

  • An RTP-style packetizer/depacketizer and reorder buffer carrying opaque EncodedFrames end-to-end (with a pass-through codec), feeding the de-jitter buffer; the real codec remains a PhaseDeferred seam.

9.4 Acceptance Criteria

  • Packetize→depacketize→reorder round-trips frames exactly under no loss; under an injected loss/reorder profile, complete frames reassemble and losses are detected/counted.
  • marker set only on the last packet of a frame; all packets of a frame share one timestamp; seq increments by 1.
  • The depacketizer never panics on arbitrary bytes (fuzzed); malformed packets yield typed errors.
  • EncodedFrame.payload is treated as opaque — no codec field is read by transport (type-level + review).

9.5 Conformance Fixtures

  • transport/packetize.json — frame + MTU → packets (seq/ts/marker).
  • transport/depacketize.json — packets → header fields + payload.
  • transport/reorder.json — shuffled seq# → in-order reassembly.
  • transport/loss.json — dropped seq# → loss count + (in)complete frame handling.
  • Malformed: transport/bad_header.json, transport/seq_wrap.json (16-bit wrap), transport/ts_wrap.json (32-bit wrap).

9.6 Pitfalls

  • Timestamp per-packet instead of per-frame — RTP packets of one frame must share a timestamp; incrementing per packet breaks frame grouping and sync; assign once per frame; signal: every packet treated as a new frame.
  • Marker-bit misuse — the marker denotes the last packet of a frame; setting it wrong fragments or merges frames; verify against packetize.json.
  • Seq/timestamp wraparound — 16-bit seq and 32-bit timestamp wrap; loss/reorder detection must use modular comparison; signal: a burst of false loss at wrap.
  • MTU split losing payload boundaries — splitting without tracking offsets drops bytes at chunk seams; reassemble by offset/marker; signal: corrupt frames only when fragmented.
  • Leaking codec assumptions into transport — peeking at payload bytes (e.g. NAL type) couples transport to the deferred codec; keep payload opaque; the NAL-aware path is documented as future work.
  • Doing socket I/O on an RT thread — recv/send are syscalls; keep them on the transport thread; the jitter buffer is the seam to the RT video thread.

9.7 Performance Concerns

  • Packetization is O(payload/MTU) memcpys (or zero-copy slices over the BufferRef); prefer slicing to copying. Reorder buffer is small and bounded. The transport thread is off the RT path, so its jitter is absorbed by the de-jitter buffer; only its throughput and the added latency term matter. Loss/reorder detection is O(1) per packet.

9.8 Edge Cases

  • Single-packet frame (payload ≤ MTU) → marker on the only packet.
  • Frame exactly a multiple of MTU → last chunk full, marker set.
  • Out-of-order arrival within the reorder window → reassembled; beyond the window → declared lost.
  • Duplicate packet → ignored (dedup on seq).
  • Keyframe vs delta frame (metadata only here; concealment/decoding is the deferred codec's concern).

9.9 Failure Analysis

  • Transport bugs cause corrupt/lost frames or sync errors via bad timestamps. Detection: loopback round-trip + loss/reorder profiles + depacketizer fuzz. Blast radius: the network media path (video especially). Recovery: fix grouping/wrap handling; regression. Forensic: packet trace (seq/ts/marker) + reassembly log + the loss profile.

9.10 Operational Notes

  • rtp_loss/rtp_reorder are network-health signals feeding the jitter-buffer adaptation (Phase 7). Document the timebase used for RTP timestamps (e.g. 90 kHz video / sample-rate audio) and the MTU. The codec is the single largest PhaseDeferred boundary; the pass-through codec keeps the path testable. Cross-link #161 (full WebRTC: SRTP/ICE/congestion) and #223 (reliable multicast) for the productionized transport.

Trust boundaries: (1) the RT audio/video callback (a hard-real-time context — any blocking or allocation is an availability bug), (2) device drivers (ALSA/V4L2 — untrusted timing + buffer sizes), (3) the network transport (untrusted RTP-style packets), (4) the graph configuration (operator-supplied node/link topology), (5) the build/dependency supply chain. The pipeline is a local-first media engine; the dominant threat class is availability (xruns/drops/desync), with input robustness (malformed media/packets) and supply chain secondary.

Compatibility Guarantees

  • Wire (transport): the RTP-style packet layout (seq/ts/marker/payload-type) + the chosen timebases (90 kHz video / sample-rate audio) are the on-wire contract; depacketizer tolerates loss/reorder/duplication within a documented window. Full RTP/SRTP interop is PhaseDeferred (#161).
  • Media formats: declared SampleFormat/PixelFormat/ChannelLayout sets are the supported surface; unknown formats fail negotiation cleanly (never silently mis-interpret). The codec boundary is opaque (Encoded caps match by codec_id); a real codec is deferred.
  • API stability: the Node/Port/Pad trait + the media-core types (Frame, Buffer, MediaType, Timestamp) are the frozen v1 public surface; custom nodes link against them.
  • Config/schema evolution: graph + device + transport config is versioned; additive fields only within a major; an unknown field is rejected (fail-closed) rather than ignored.
  • Semantic versioning: major = Node trait / wire / media-type break; minor = additive node/format/feature; patch = bugfix. Deferred features (real codec, full WebRTC, GPU path) are explicitly not guaranteed.
  • Rolling-upgrade: a process restart re-negotiates the graph; same config + same deps → identical negotiated topology (deterministic fixate). Mixed-version transport peers fall back to the common format set.

Scalability Analysis

  • Bottlenecks: the RT callback's per-period CPU budget (hard ceiling — overrun = xrun); per-node cost on the hot path; queue depth vs latency trade; transport ingress rate; color-convert/scale cost for high-resolution video.
  • Scaling ceilings: single-machine, local-first — the ceiling is one host's CPU + the RT period budget; higher channel count / resolution / frame rate consumes the per-period budget.
  • Horizontal scaling: out of scope here — the seam is the network transport (multiple peers); fan-out to many consumers is a transport concern (cross-link #161/#223), not the engine's.
  • Vertical scaling: SIMD DSP kernels, GPU offload for video (deferred), larger worker pool for off-RT nodes, a faster master clock source; the per-period budget is the lever.
  • Sharding/partitioning: the graph partitions into segments by scheduling discipline + thread class; adding parallelism = more off-RT worker threads for independent segments (the RT segment stays single-threaded per device).
  • Replication pressure: N/A locally; a multi-consumer transport replicates frames downstream (transport-layer cost).
  • Coordination overhead: segment seams (queues) are the coordination points; cross-thread handoff cost is the SPSC ring; minimize seams on the RT path.
  • Network fanout: transport fan-out (one source → many receivers) scales packetization + send cost linearly; deferred to the productionized transport.
  • Scheduler saturation: too many RT segments / too-short a period saturates the RT scheduler → xruns; the partitioner + period sizing bound it; off-RT work never starves the RT thread (priority).
  • Storage/metadata growth: N/A (streaming, no persistence); the bounded pools + queues are the only "storage," and they're fixed-size by construction.

Mental Models & First Principles

The compressed intuitions an expert holds about a real-time media pipeline. Each: the insight, what it predicts, the bug class you write without it, and the section/phase where this blueprint applies it.

  • MM1 — The RT thread is a time budget, not a thread. Every RT iteration is a fixed time slice (one device period); every line of code in that slice is a withdrawal from that budget. Predicts: any operation with unbounded latency — malloc, mutex, syscall, page fault, I/O — eventually busts the budget → xrun, regardless of average cost. Bug without it: calling log::debug!() inside the audio callback (hidden string allocation + write syscall) that is invisible until the machine is loaded. Applied: §4.3 (RT discipline contract), Phase 4 §4.2 (callback contract), ADR-2/ADR-5, Invariant 1/Invariant 2.
  • MM2 — A lock-free ring is a happens-before contract, not a hardware trick. The producer's Release write to tail establishes a happens-before edge with the consumer's Acquire read of tail; every earlier producer write is then visible. Predicts: weaken the publish to Relaxed and the slot content can be globally invisible when the index says "ready" → torn/garbage frame. Bug without it: publishing tail with Relaxed produces intermittent corrupt data only under load, undetectable by a single-schedule stress test. Applied: Phase 3 §3.2 (SPSC Acquire/Release ordering), §5.2 paper #5 (Herlihy/Shavit), ADR-5, Invariant 8.
  • MM3 — Caps negotiation is type-checking at link time. A media-format mismatch is a type error; discovering it at buffer-flow time (per-buffer conversion) is the runtime-vs-compile-time error distinction. Predicts: fixing caps once at link time guarantees no per-buffer format surprises or hot-path allocation; deferring it forces a guess on every buffer. Bug without it: a pipeline that guesses the format per buffer silently converts on every iteration, adding latency and allocation. Applied: §8.5 (caps negotiation FSM), Phase 2 §2.2 (negotiate.rs), Invariant 9, Design Principle 3.
  • MM4 — Clock drift is integration, not a step. A ±100 ppm device error accumulates ~100 frames per million consumed; over 60 minutes at 48 kHz that is ~17,000 frames — far more than any buffer. Predicts: uncompensated drift always eventually drains (or floods) the buffer to xrun, no matter how large the buffer — only the time-to-failure scales. Bug without it: a "works for 2 minutes then clicks" report caused by ppm drift with no compensation loop. Applied: §8.9 (drift worked example), Phase 6 §6.2 (DriftEstimator PI controller), Invariant 11, the Back-of-Envelope Capacity Model.
  • MM5 — Backpressure policy is a tradeoff, not a default. Every bounded-queue edge must declare a policy — DropOldest bounds latency at the cost of completeness; DropNewest keeps completeness at the cost of freshness; Block is safe only off-RT. Predicts: there is no universally correct choice, and the wrong one per edge changes the latency-vs-completeness contract silently. Bug without it: using Block on an RT-segment edge stalls the audio callback → underrun. Applied: §8.4 (scheduling model), Phase 2 §2.2 (queue.rs), ADR-12, Invariant 6, Design Principle 4.
  • MM6 — The buffer pool is a conservation law. acquired + free == pool_size must hold at all times; a violation is either a leak (slot never returned) or a double-return (corruption). Predicts: exhaustion without a leak signals a cycle or a long-lived consumer; exhaustion with a leak is a refcount bug — the two have different fixes. Bug without it: a BufferRef clone that escapes scope without dropping leaks a slot; the pool silently starves → backpressure stall or an illegal RT-path alloc. Applied: Phase 1 §1.2 (BufferPool conservation), Invariant 7, ADR-4.
  • MM7 — Audio is master, video is a follower. Audio glitches are perceptually instant and irreversible; video drop/repeat is nearly imperceptible within ±20 ms. Predicts: stretching audio to follow video makes a resampling artifact audible on every sync correction; dropping/repeating video to follow audio is invisible. Bug without it: A/V-sync logic that pitch-shifts audio to follow video is immediately audible. Applied: Phase 7 §7.2 (LipSync audio-master), ADR-11, Invariant 5, §4.2 (±20 ms bound).
  • MM8 — Denormals are a silent deadline killer. IEEE-754 subnormal floats trigger a 10–100× slowdown on most x86/ARM FPUs that fall back to microcode; a filter tail full of denormals at near-zero amplitude can overrun the audio block's deadline. Predicts: a biquad with slowly decaying state runs fine until the signal fades, then suddenly overruns — the spike correlates with low-amplitude input, not load. Bug without it: glitches that appear only on quiet/decaying passages and vanish under a test tone. Applied: Phase 5 §5.2 (set_denormals_off), ADR-29, Invariant 13, §5.2 paper #10 (Intel FTZ/DAZ).
  • MM9 — PTS is the contract, arrival order is the accident. Transport reorder, jitter, and retransmission make arrival order meaningless for presentation; only PTS (the media-clock anchor stamped at capture) decides when to present. Predicts: any logic keyed on arrival/dequeue order produces timing-dependent bugs that disappear in a quiescent test and reappear under jitter. Bug without it: presenting video by dequeue order rather than PTS → stutter visible even under otherwise smooth playback. Applied: §8.7 (de-jitter buffer), §8.6 (A/V sync), Phase 7 §7.2, Design Principle 10, Invariant 4.
  • MM10 — The SPSC ring is the only safe RT boundary. Every other cross-thread primitive (mutex, condvar, MPSC channel, shared atomic state) either risks priority inversion or requires a syscall (futex). Predicts: the wait-free SPSC ring is the one construction with no OS involvement and a provable memory-ordering argument, so it is the sole sanctioned RT↔non-RT data path. Bug without it: substituting a Mutex<VecDeque> for the ring on the RT path works on a lightly loaded machine and sporadically xruns on any loaded one. Applied: Phase 3 §3.2 (Spsc<T>), ADR-5, Invariant 2, Design Principle 7.

GStreamer: Made the GObject/plugin-factory choice to maximize extensibility across languages and distributions — any element can be replaced at runtime. The niche where this wins: a media server or transcoding pipeline where the set of codecs, sources, and sinks is unknown at compile time and elements must be hot-swapped. The tradeoff is the GObject overhead (vtable-heavy, allocation-prone), which makes ultra-low-latency RT harder than a bespoke design.

PipeWire: Made the RT-first design choice from the start, treating the graph quantum as the fundamental tick and using eventfd wakeups instead of thread-per-period. Wins for a modern Linux desktop where the same daemon must serve both JACK-style pro-audio clients and PulseAudio-style apps simultaneously, with a single RT graph at the session-manager level. The SPA plugin ABI is more rigorous than GStreamer's GObject but narrower in ecosystem.

JACK2: Made the shared-memory process-graph choice so multiple independent applications can participate in a single RT audio graph as first-class peers — the canonical pro-audio studio model. Wins when inter-application routing (DAW ↔ synthesizer ↔ effects) is the primary use case and all clients are trusted. Loses for a single-process embedded pipeline where the server/client split adds overhead with no benefit.

FFmpeg filtergraph: Made the demand-pull/offline choice optimizing for throughput in transcoding and file processing. Wins for a batch transcoder, a streaming media server doing real-time transcoding, or any pipeline where output rate is not constrained by a real-time device. Not designed for sub-10ms latency or a no-alloc RT callback.

WebRTC (libwebrtc): Made the browser-first, full-stack choice — integrating ICE/DTLS/SRTP/congestion-control/codec/jitter-buffer into one vertically integrated system. Wins for browser-to-browser and browser-to-server media where NAT traversal, security, and interoperability are non-negotiable. Loses for a local A/V pipeline (no network, no browser), where the ICE/DTLS overhead and the Chromium-scale dependency tree are pure cost.

Back-of-Envelope Capacity Model

The numbers an expert computes from §4 (System Constraints) before designing. Each is derived step-by-step; the §4 input is named and the formula shown.

  • C1 — Audio bytes per period (the unit of work). Input: §4.2 (rate 48,000 Hz; §4.1 default period 256 frames; §4.2 stereo; §4.2 S16LE = 2 B/sample). bytes/period = frames × channels × bytes_per_sample = 256 × 2 × 2 = 1,024 B interleaved S16LE. In the internal F32 DSP path: 256 × 2 × 4 = 2,048 B/period. This is the buffer the pool slot and the SPSC slot must hold.
  • C2 — Audio device buffer depth and latency floor. Input: §4.1 default (256 frames × 3 periods). buffered = 256 × 3 = 768 frames; latency = 768 ÷ 48,000 = 16.0 ms device buffer, plus one capture period → ~21 ms round-trip, matching the §4.1 ≤ 20 ms default target. Low-latency (§4.1 64×2): 128 ÷ 48,000 = 2.67 ms, total ≈ 4 ms (≤ 5 ms target ✓).
  • C3 — Audio throughput (sustained bandwidth). Input: §4.2 sample-rate/format ceilings. At 48 kHz stereo S16LE: 48,000 × 2 × 2 = 192 kB/s capture→pool. At the §4.2 ceiling (96 kHz × 8 ch × F32): 96,000 × 8 × 4 = 3,072 kB/s ≈ 3 MB/s internal DSP throughput — trivial for memory bandwidth, so CPU (not bandwidth) bounds audio.
  • C4 — SPSC ring sizing (minimum). Input: §4.2 "ring capacity ≥ 4× the per-period buffer count, power-of-two". Audio: 4 × 1,024 B = 4,096 B needed → next pow2 slot count is 8 → 8 × 1,024 B = 8 kB ring. Video at 1080p YUV420P: 1 frame = 1920 × 1080 × 1.5 = 3,110,400 B ≈ 2.97 MB; a 4-frame ring ≈ 12 MB.
  • C5 — Buffer-pool sizes and the mlockall budget. Input: §4.2 "fixed N pre-allocated buffers per media type; exhaustion is backpressure". Audio pool 8 × 2,048 B (F32 stereo 256) = 16 kB — fits in L1. Video pool at 1080p YUV420P: 8 × 2.97 MB = ~23.8 MB locked RAM. Full-pipeline mlockall budget ≈ 50 MB at 1080p default — the number Phase 3 must pre-touch.
  • C6 — Clock-drift accumulation rate (time-to-xrun without compensation). Input: §4.2 drift range ±1,000 ppm, C2 buffer depth. At 100 ppm: 48,000 × 1e-4 = 4.8 extra frames/s; drain_time = 768 ÷ 4.8 = 160 s. At 1,000 ppm: 768 ÷ 48 = 16 s → xrun in under a minute, which is exactly why Invariant 11's PI loop exists.
  • C7 — Drift-compensation ratio magnitude. Input: §4.2 ±1,000 ppm clamp. ratio ∈ [1 − 1e-3, 1 + 1e-3] = [0.999, 1.001]. At 1,000 ppm the resampler adds/drops 1 sample per 1,000 → per 256-frame period that is 256 × 1e-3 = 0.256 samples/period — sub-sample, hence imperceptible, confirming MM7/Phase 5's "no audible artifact" claim.
  • C8 — Video frame bandwidth (the CPU pressure point). Input: §4.2 1920×1080, 30/60 fps, pixel formats. 1080p YUV420P @ 60 fps: 3,110,400 × 60 = 186.6 MB/s. RGB24 @ 60 fps: 1920 × 1080 × 3 × 60 = 373.2 MB/s — approaching single-core memory bandwidth, so §8.7's "convert/scale must be tight" is quantitatively forced. 30 fps YUV420P: 93.3 MB/s (comfortable).
  • C9 — A/V-sync jitter-buffer depth. Input: §4.2 target_depth = ceil(jitter_p99 / frame_interval), C4 frame size. At 30 fps, frame_interval = 33.3 ms. jitter_p99 = 20 ms → ceil(20/33.3) = 1 frame. jitter_p99 = 100 ms (poor network) → ceil(100/33.3) = 3 frames = 3 × 2.97 MB ≈ 9 MB for 1080p — the bounded memory the de-jitter buffer must reserve.
  • C10 — RTP packetization overhead. Input: §8.8 (12-B RTP header), MTU 1,400-B payload. overhead = 12 ÷ (12 + 1,400) = 0.85% bandwidth — negligible. A ~100 kB 1080p keyframe splits into ceil(100,000 / 1,400) = 72 packets, all sharing one timestamp with the marker on #72 (Phase 9 §9.2).
  • C11 — File-descriptor budget. Input: §4.2 FD budget. 1 ALSA capture + 1 ALSA playback + 1 V4L2 + 4 V4L2 mmap + 2 eventfd (telemetry wakeup) + 2 UDP socket + 3 CI pipe = ~15 FDs — orders of magnitude below any ulimit; FDs are not a scaling concern.
  • C12 — Startup budget. Input: §4.2 "graph build + caps negotiation + device open < 500 ms". Caps negotiation is O(nodes × ports) = microseconds; ALSA open + hw-params ≈ 5–20 ms; V4L2 open + REQBUFS + mmap ≈ 10–30 ms; mlockall + pre-touch of C5's 50 MB at ~1 GB/s ≈ 50 ms. Total ≈ < 150 ms — well inside the 500 ms gate.

Alternative Architectures (Roads Not Taken)

Fundamentally different ways to build a real-time media pipeline for the same goal — not parameter tweaks. Each: an ASCII sketch, the regime where it wins, the real system that embodies it, and why this blueprint rejected it.

A1 — Server-client IPC graph (the JACK model). A privileged RT server owns the device; independent client processes attach to one shared RT graph over shared memory.

  ┌────────────────────────────────────────────────────────┐
  │  JACK-LIKE SERVER PROCESS  (SCHED_FIFO, mlock)         │
  │  ┌──────────┐   shm ringbuf   ┌──────────────────────┐│
  │  │  ALSA    │<═══════════════>│ RT Graph Scheduler   ││
  │  │  Driver  │                 │ (period callback)    ││
  │  └──────────┘                 └────────┬─────────────┘│
  └───────────────────────────────────────┼───────────────┘
                             shared-memory│
         ┌─────────────────┬─────────────┘
         │                 │
  ┌──────┴──────┐   ┌──────┴──────┐
  │  CLIENT A   │   │  CLIENT B   │
  │ (DSP chain) │   │ (recorder)  │
  │  own process│   │  own process│
  └─────────────┘   └─────────────┘
  • Wins: a pro-audio studio where multiple independent applications (a DAW, a synthesizer, an effects processor) must share one RT audio graph at session level, each in its own process for isolation and independent lifecycle — per-client isolation is the killer feature.
  • Real system: JACK2 (jackd) and PipeWire in JACK-compatibility mode.
  • Rejected because: this project is a single-process learning exercise where the server/client IPC machinery (shared-memory ring, IPC protocol, daemon lifecycle) adds complexity without teaching anything about the pipeline or the RT substrate itself; the in-process design is strictly simpler for the scope while preserving every RT invariant (Invariant 1/2/8).

A2 — Demand-pull transcoder (the FFmpeg filtergraph model). A non-RT thread pulls frames from the sink backward to the source at whatever rate the CPU allows; no device period governs timing.

  ┌─────────────────────────────────────────────────────┐
  │  PULL THREAD (non-RT, throughput-optimized)          │
  │                                                      │
  │  av_buffersink_get_frame()                           │
  │         │ pulls                                      │
  │         ▼                                            │
  │  [scale] ← [convert] ← [decode] ← [demux ← file]   │
  │         │                                            │
  │  write output file / forward to encoder              │
  └─────────────────────────────────────────────────────┘
  (no RT scheduling, no mlockall, no clock discipline)
  • Wins: offline transcoding (file-in → file-out), a streaming server encoding at faster-than-realtime, or any pipeline where throughput (frames/s above realtime) is the goal and there is no physical render device — per-frame allocation is fine, latency is irrelevant.
  • Real system: FFmpeg libavfilter / ffmpeg -vf.
  • Rejected because: the demand-pull model has no device period, no clock discipline, and no RT thread model, so it cannot guarantee frame delivery within a period deadline and cannot produce glitch-free audio to a real sound device — the §4.3 RT model is the only correct one when a real device is the sink.

A3 — Push-only streaming bus (no backpressure, no graph). Each stage pushes into an unbounded channel; there is no bounded queue, no policy, and no negotiation.

  ┌──────────┐      ┌──────────┐      ┌──────────┐
  │  Capture │─────>│  DSP     │─────>│  Render  │
  │  Thread  │ chan │  Thread  │ chan │  Thread  │
  └──────────┘      └──────────┘      └──────────┘
    push at       std::sync::mpsc    (no bounded
    device rate   (unbounded)         queues,
                                      no policy)
  • Wins: a simple audio-monitoring app where the pipeline is one fixed chain with uniform stage throughput, the only failure mode is lag (not xrun), and minimal code is the goal — an std::sync::mpsc push chain with no backpressure is fine when the consumer is always at least as fast as the producer.
  • Real system: many simple audio visualization tools and naive FFT-based spectrum analyzers.
  • Rejected because: unbounded channels grow without limit the moment any stage is slower than the source — exactly the memory blowup and latency creep Design Principle 4 (backpressure) and Design Principle 9 (budgeted latency) forbid; the bounded-queue seam is not optional when a slow consumer must not silently delay the render deadline.

A4 — Hardware-in-the-loop microkernel (the RTOS model). No host OS; DMA-driven ISRs move samples and frames, all memory is static, and worst-case execution time is formally proven.

  ┌────────────────────────────────────────────┐
  │  RTOS KERNEL  (e.g., FreeRTOS / Zephyr)    │
  │  ┌──────────────────────────────────────┐  │
  │  │  Audio ISR (period interrupt)        │  │
  │  │    DMA → ring → DSP task → DAC DMA   │  │
  │  └──────────────────────────────────────┘  │
  │  ┌──────────────────────────────────────┐  │
  │  │  Video task (frame interrupt)        │  │
  │  │    DMA → convert → display DMA       │  │
  │  └──────────────────────────────────────┘  │
  │  All memory static; no heap; WCET proven   │
  └────────────────────────────────────────────┘
  • Wins: an embedded media device (smart speaker, video doorbell, automotive head unit) on a microcontroller/SoC with a hard-RTOS requirement, where WCET must be formally proven and dynamic allocation is wholly prohibited — DMA-driven ISR pipelines on FreeRTOS/Zephyr are the canonical form.
  • Real system: Zephyr RTOS audio pipeline (Bluetooth LE Audio); automotive Linux with PREEMPT_RT + AUTOSAR Adaptive.
  • Rejected because: this project targets a Linux std host, where mlockall + SCHED_FIFO give a soft/firm-RT approximation; a microkernel RTOS removes std, cargo test, proptest, and the offline FileBackend — a fundamentally different environment that §1.3's non-goal "No hard real-time certification / WCET" explicitly excludes.

Glossary

  • Frame — a unit of media (audio block or video image) with PTS/DTS/duration/flags + a buffer.
  • Buffer / BufferPool / BufferRef — fixed-capacity preallocated memory + refcounted handle; the RT-safe, alloc-free memory substrate.
  • MediaType / caps — the negotiated description (audio/video/encoded × format × rate × layout); "caps" = the capability set negotiated at link time.
  • Intersect / fixate — caps negotiation: intersect two capability sets, then fixate to a single concrete MediaType.
  • PTS / DTS — presentation / decode timestamp (when to render / when to decode).
  • Timebase / Timestamp / rescale — a rational tick rate; an integer tick count; converting ticks between timebases (overflow-safe, integer).
  • Node / Port / Pad / Graph — the pipeline DAG: a processing element, its typed I/O, the link endpoint, the whole topology.
  • Source / Sink / Transform — a producer / consumer / mapping node (a transform may change caps, e.g. a resampler).
  • Segment — a group of nodes sharing a scheduling discipline + thread class; seams between segments carry a queue.
  • Scheduler (pull / push) — sink-driven recursive demand / source-driven delivery; how frames flow through a segment.
  • BoundedQueue / backpressure — a fixed-capacity edge queue; the explicit policy (Block off-RT / DropOldest / DropNewest) when full.
  • Deadline / DeadlineAccount — the time budget for processing tied to a device period; the miss histogram.
  • RT thread / SCHED_FIFO / mlockall — a real-time-priority thread; the Linux RT scheduling class; locking memory to prevent page faults.
  • Xrun (underrun/overrun) — the audio device starved (underrun) or overflowed (overrun) — a missed real-time deadline.
  • SPSC ring — single-producer/single-consumer lock-free ring buffer (the RT↔off-RT handoff).
  • ALSA / V4L2 — the Linux audio / video-capture device APIs.
  • Media clock / presentation clock / master clock — the rate reference for samples; the render-timing reference; the clock everything is synced to.
  • Drift / drift estimation — the slow rate mismatch between clocks (ppm); estimating it to drive resampling.
  • De-jitter buffer — an ingress buffer absorbing transport timing variation (trades latency for smoothness).
  • A/V sync — aligning audio + video to the master clock within the perceptual bound.
  • Resampler (polyphase) — rate conversion via polyphase filtering (also used to correct drift).
  • Biquad — a second-order IIR filter section (the DSP building block).
  • Gain / mixer — scalar amplitude scaling / multi-input summing nodes.
  • Pixel format / color convert / scale — video sample layout (e.g. YUV/RGB); colorspace conversion; resizing.
  • Keyframe / DISCONT / CORRUPT — frame flags: independently decodable / a discontinuity / damaged data.
  • RTP-style packet — the transport packet (sequence number, timestamp, marker, payload type, payload).
  • Packetize / depacketize — fragment frames into packets / reassemble packets into frames (loss/reorder-tolerant).
  • Jitter / loss / reorder profile — injected network-condition fixtures for testing transport robustness.
  • Pass-through codec — the trivial identity codec keeping the encoded-frame path testable while a real codec is deferred.
  • PhaseDeferred — an explicitly out-of-scope feature behind a documented marker (real codec, full WebRTC, GPU).
  • Backpressure policy — how a full queue responds: block (off-RT only), drop oldest, or drop newest.
  • rtpctl — the inspection/control tool (renders the negotiated graph + live metrics).
