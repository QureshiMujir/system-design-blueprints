4.3 RT discipline contract

On any RT thread: (1) no heap allocation (all buffers pooled, pre-touched after mlockall); (2) no blocking lock — only the wait-free SPSC ring and atomics; (3) no syscall except the device read/write and clock read; (4) bounded, predictable work per iteration (no unbounded loops, no I/O, no logging — telemetry is written to a lock-free ring and drained off-thread); (5) deadline = next device period, and overrun is recorded as a deadline miss with a timestamp.

Back-of-Envelope Capacity Model

The numbers an expert computes from §4 (System Constraints) before designing. Each is derived step-by-step; the §4 input is named and the formula shown.

  • C1 — Audio bytes per period (the unit of work). Input: §4.2 (rate 48,000 Hz; §4.1 default period 256 frames; §4.2 stereo; §4.2 S16LE = 2 B/sample). bytes/period = frames × channels × bytes_per_sample = 256 × 2 × 2 = 1,024 B interleaved S16LE. In the internal F32 DSP path: 256 × 2 × 4 = 2,048 B/period. This is the buffer the pool slot and the SPSC slot must hold.
  • C2 — Audio device buffer depth and latency floor. Input: §4.1 default (256 frames × 3 periods). buffered = 256 × 3 = 768 frames; latency = 768 ÷ 48,000 = 16.0 ms device buffer, plus one capture period → ~21 ms round-trip, matching the §4.1 ≤ 20 ms default target. Low-latency (§4.1 64×2): 128 ÷ 48,000 = 2.67 ms, total ≈ 4 ms (≤ 5 ms target ✓).
  • C3 — Audio throughput (sustained bandwidth). Input: §4.2 sample-rate/format ceilings. At 48 kHz stereo S16LE: 48,000 × 2 × 2 = 192 kB/s capture→pool. At the §4.2 ceiling (96 kHz × 8 ch × F32): 96,000 × 8 × 4 = 3,072 kB/s ≈ 3 MB/s internal DSP throughput — trivial for memory bandwidth, so CPU (not bandwidth) bounds audio.
  • C4 — SPSC ring sizing (minimum). Input: §4.2 "ring capacity ≥ 4× the per-period buffer count, power-of-two". Audio: 4 × 1,024 B = 4,096 B needed → next pow2 slot count is 8 → 8 × 1,024 B = 8 kB ring. Video at 1080p YUV420P: 1 frame = 1920 × 1080 × 1.5 = 3,110,400 B ≈ 2.97 MB; a 4-frame ring ≈ 12 MB.
  • C5 — Buffer-pool sizes and the mlockall budget. Input: §4.2 "fixed N pre-allocated buffers per media type; exhaustion is backpressure". Audio pool 8 × 2,048 B (F32 stereo 256) = 16 kB — fits in L1. Video pool at 1080p YUV420P: 8 × 2.97 MB = ~23.8 MB locked RAM. Full-pipeline mlockall budget ≈ 50 MB at 1080p default — the number Phase 3 must pre-touch.
  • C6 — Clock-drift accumulation rate (time-to-xrun without compensation). Input: §4.2 drift range ±1,000 ppm, C2 buffer depth. At 100 ppm: 48,000 × 1e-4 = 4.8 extra frames/s; drain_time = 768 ÷ 4.8 = 160 s. At 1,000 ppm: 768 ÷ 48 = 16 s → xrun in under a minute, which is exactly why Invariant 11's PI loop exists.
  • C7 — Drift-compensation ratio magnitude. Input: §4.2 ±1,000 ppm clamp. ratio ∈ [1 − 1e-3, 1 + 1e-3] = [0.999, 1.001]. At 1,000 ppm the resampler adds/drops 1 sample per 1,000 → per 256-frame period that is 256 × 1e-3 = 0.256 samples/period — sub-sample, hence imperceptible, confirming MM7/Phase 5's "no audible artifact" claim.
  • C8 — Video frame bandwidth (the CPU pressure point). Input: §4.2 1920×1080, 30/60 fps, pixel formats. 1080p YUV420P @ 60 fps: 3,110,400 × 60 = 186.6 MB/s. RGB24 @ 60 fps: 1920 × 1080 × 3 × 60 = 373.2 MB/s — approaching single-core memory bandwidth, so §8.7's "convert/scale must be tight" is quantitatively forced. 30 fps YUV420P: 93.3 MB/s (comfortable).
  • C9 — A/V-sync jitter-buffer depth. Input: §4.2 target_depth = ceil(jitter_p99 / frame_interval), C4 frame size. At 30 fps, frame_interval = 33.3 ms. jitter_p99 = 20 ms → ceil(20/33.3) = 1 frame. jitter_p99 = 100 ms (poor network) → ceil(100/33.3) = 3 frames = 3 × 2.97 MB ≈ 9 MB for 1080p — the bounded memory the de-jitter buffer must reserve.
  • C10 — RTP packetization overhead. Input: §8.8 (12-B RTP header), MTU 1,400-B payload. overhead = 12 ÷ (12 + 1,400) = 0.85% bandwidth — negligible. A ~100 kB 1080p keyframe splits into ceil(100,000 / 1,400) = 72 packets, all sharing one timestamp with the marker on #72 (Phase 9 §9.2).
  • C11 — File-descriptor budget. Input: §4.2 FD budget. 1 ALSA capture + 1 ALSA playback + 1 V4L2 + 4 V4L2 mmap + 2 eventfd (telemetry wakeup) + 2 UDP socket + 3 CI pipe = ~15 FDs — orders of magnitude below any ulimit; FDs are not a scaling concern.
  • C12 — Startup budget. Input: §4.2 "graph build + caps negotiation + device open < 500 ms". Caps negotiation is O(nodes × ports) = microseconds; ALSA open + hw-params ≈ 5–20 ms; V4L2 open + REQBUFS + mmap ≈ 10–30 ms; mlockall + pre-touch of C5's 50 MB at ~1 GB/s ≈ 50 ms. Total ≈ < 150 ms — well inside the 500 ms gate.
