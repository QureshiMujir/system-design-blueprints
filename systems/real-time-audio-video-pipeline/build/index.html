⬜ Phase 0 — Workspace skeleton + offline rig + governance

Objectives
  • Stand up the 13-crate Cargo workspace; CI green on the offline (hardware-free) rig.
  • Lock toolchain, lint, format, license, deterministic-build contract, and the offline FileBackend substrate.
  • Establish vector/trace JSON schemas and the empty conformance tree. No media logic yet; only seams compile.
Deliverable
  • cargo build + cargo test pass on the offline rig (no hardware feature); CI green; rtpctl offline --help runs.
Acceptance
  • All 13 crates compile; clippy -D warnings clean; rustfmt --check clean.
  • Default (no-hardware) build links no ALSA/V4L2 symbols; the hardware feature builds where libs exist.
  • Empty conformance runner exits 0 with "0 vectors"; loom job runs the empty ring model.
  • Reproducible: two clean builds produce identical crate hashes given the pinned lock.
Fixtures
  • conformance/vectors/.gitkeep per subdir; templates/vector.json validated by a schema test.
  • smoke_workspace.json — trivial vector the placeholder runner loads and skips (proves the load path).
Pitfalls
  • Hardware dep leaks into the default build — manifests as CI failing on a runner with no ALSA; root cause a non-optional alsa-sys; debug cargo tree -e features; fix the hardware feature gate.
  • Unpinned toolchain — non-reproducible builds + clippy lint drift; pin in rust-toolchain.toml and CI.
  • Workspace resolver v1 vs v2 — feature-unification surprises across crates; set resolver = "2".
  • unsafe FFI scaffolding compiled-in too early — keep alsa.rs/v4l2.rs behind the feature so the audited-unsafe surface stays empty until Phase 4/8.

⬜ Phase 1 — Core types: Frame, Buffer, BufferPool, MediaType/caps, Timestamp

Objectives
  • Implement media-core: MediaType (audio/video/encoded) + caps intersect/fixate, Frame (PTS/DTS/flags), refcounted Buffer/BufferRef, the fixed-capacity BufferPool, Timebase/Timestamp + rescale.
  • These are the normative load-bearing types every later phase consumes; no scheduling/threads yet.
Deliverable
  • media-core constructs/validates media types, negotiates caps via intersect/fixate, manages a conserved buffer pool, and rescales timestamps; unit + property tests pass.
Acceptance
  • intersect/fixate match negotiation/*.json (incl. empty-intersection → None).
  • rescale matches a reference (numpy/Fraction) over a fixture set; no overflow at i64::MAX inputs.
  • Pool conservation holds over ≥1e6 randomized acquire/drop ops; exhaustion returns None, never allocates.
  • PTS-monotonicity check flags a regression (no panic).
Fixtures
  • core/rescale.json — (ts, from_tb, to_tb) → expected ticks.
  • negotiation/intersect.json, negotiation/fixate.json — caps sets → result / None.
  • core/pool_conservation.json — acquire/drop sequence → free-count trace.
  • Malformed: core/pts_regression.json (decreasing PTS → flagged), negotiation/empty.json.
Pitfalls
  • rescale overflow / rounding — i64×i64 overflows; using float loses precision and breaks determinism; compute in i128, round-half-even; signal: PTS jitter at high tick values.
  • Refcount leak / double-free — a BufferRef cloned but not dropped leaks a slot (pool exhausts); a double-return corrupts the free-list; debug with per-slot owner tags + a leak check at teardown.
  • Caps fixate non-determinism — picking from a HashSet randomizes the chosen format; use an ordered preference list; signal: flaky negotiation across runs.
  • Interleaved vs planar sample-count math — computing frames from byte length must account for layout × channels × bytes/sample; an error here mis-slices every audio buffer.

⬜ Phase 2 — Pipeline graph, typed ports, caps negotiation, scheduler, bounded queues, backpressure

Objectives
  • Implement media-graph (Node/Port/Pad/Graph, link-time caps negotiation, segment partitioning) and media-sched (pull/push scheduling, BoundedQueue with explicit per-edge backpressure, the deadline model). Still single-threaded / offline.
Deliverable
  • A graph that links nodes with negotiated caps, partitions into segments, and runs (offline) under pull or push with bounded queues and deadline accounting; small graphs process file input to output.
Acceptance
  • Linking incompatible pads → NEGOTIATION_FAILED at build (before any buffer flows); compatible pads fixate to the expected MediaType.
  • A 3-node graph processes a WAV through gain to output identically to a reference (Phase 5 fills real gain; here a pass-through).
  • BoundedQueue enforces capacity; each policy behaves per queue/*.json (drop-oldest keeps newest; drop-newest keeps oldest; block off-RT).
  • Deadline misses are counted on an injected slow node; never silently absorbed.
Fixtures
  • negotiation/link_ok.json, negotiation/link_fail.json — pad caps → fixed type / failure.
  • queue/drop_oldest.json, queue/drop_newest.json, queue/block.json — push sequence vs capacity → accepted/dropped trace.
  • queue/deadline_miss.json — finish times vs deadlines → miss count + overrun histogram.
  • Malformed: negotiation/unfixed_link.json (validate rejects), queue/over_capacity.json.
Pitfalls
  • Blocking backpressure on an RT segment — Block policy on an edge that lands on an RT thread stalls the audio callback → underrun; restrict Block to off-RT edges; the partitioner must flag it; signal: xruns correlated with queue-full.
  • Negotiation at buffer time instead of link time — guessing format per buffer causes per-buffer conversion + allocation; fixate once at link; signal: format flips mid-stream.
  • Topological cycle / unpartitioned graph — a cycle deadlocks the scheduler; validate must reject cycles (or require an explicit queue to break them); debug with a cycle check.
  • Drop-policy off-by-one — dropping the wrong end (oldest vs newest) changes latency-vs-completeness semantics; verify against queue/*.json.
  • Deadline measured against the wrong clock — using wall time where media time is meant inflates/deflates misses; pin each deadline to the device-period boundary.

⬜ Phase 3 — Lock-free SPSC ring + RT thread model (SCHED_FIFO, mlockall, deadline accounting)

Objectives
  • Implement media-rt: a wait-free SPSC ring buffer (the sole RT↔non-RT data path), RT thread creation (SCHED_FIFO with assigned priorities), mlockall + page pre-touch, and RT deadline-miss accounting. This is the concurrency-correctness foundation.
Deliverable
  • A verified wait-free SPSC ring, RT-thread spawning with priorities (graceful degradation without privileges), page-locked memory, and deadline accounting — exercised by a stress + jitter harness.
Acceptance
  • loom proves the SPSC ring drops/duplicates nothing and has no data race under all interleavings of one producer + one consumer.
  • The no-alloc harness confirms zero allocations on a thread tagged RT during a sustained push/pop loop.
  • spawn_rt sets SCHED_FIFO where privileged; degrades cleanly (flag set, test skips RT assertion) where not.
  • mlockall succeeds (or warns) ; after lock + pre-touch, a fault-counting test shows zero minor faults during the steady-state loop.
  • Deadline misses counted on injected overrun; histogram populated.
Fixtures
  • ring/fill_drain.json — push/pop sequence vs capacity → accept/empty trace.
  • ring/wrap.json — wrap-around past capacity boundary → indices/values.
  • ring/full_empty.json — full→push rejected; empty→pop None.
  • rt/deadline.json — iteration finish vs deadline → miss count.
  • (loom is code-driven, not a JSON vector; recorded as a CI job result.)
Pitfalls
  • Wrong memory ordering on the ring — using Relaxed for the publish lets the consumer read a slot before the write is visible → torn/garbage data; producer publishes tail Release, consumer loads Acquire; debug with loom; signal: occasional corrupt frame only under load.
  • False sharing of head/tail — head and tail on the same cache line bounce between cores, tanking throughput; pad to a cache line each; signal: ring throughput far below memory bandwidth.
  • ABA / capacity that is not power-of-two — non-pow2 forces a modulo (slow) and index arithmetic bugs; require pow2 and mask; signal: indices drift after many wraps.
  • mlockall without pre-touch — MCL_FUTURE locks future pages but the first write still faults if the page was never resident; pre-touch all pool pages; signal: a latency spike on the very first buffer use.
  • Forgetting to drop RT privileges / runaway priority — a buggy RT loop at SCHED_FIFO can starve the whole machine; cap priorities below kernel threads, document rtprio ulimit, provide a watchdog.
  • Allocator on the RT thread via a hidden path — format!, Vec::push, Box, or even a String in an error path allocates; the no-alloc harness must cover error branches too.

⬜ Phase 4 — Audio capture/playback (ALSA) + RT callback contract + xrun recovery

Objectives
  • Implement media-audio: the AudioBackend trait, the ALSA PCM capture/playback impl (locked), the RT audio callback/poll contract (no alloc/lock/syscall beyond read/write), period/buffer sizing vs latency, xrun (EPIPE) detection and recovery, and S16LE↔F32 / interleave↔planar conversion at the device edge.
Deliverable
  • Audio capture and playback over ALSA honoring the RT callback contract, with configurable period/buffer sizing, working xrun recovery, and format/layout conversion; an offline WAV pipeline and a hardware loopback both run.
Acceptance
  • Offline: a WAV routed capture→(passthrough)→playback equals the input sample-for-sample.
  • Hardware loopback at default latency (256×3) runs 60 min with xrun_total == 0.
  • RT contract verified: the no-alloc harness shows zero allocations on the audio thread during steady state and during an injected xrun-recovery path.
  • Format conversion S16LE↔F32 round-trips within 1 LSB (quantization) and matches an FFmpeg reference; interleave↔planar is exact.
  • buffer_level_frames tracks the device buffer and feeds the drift estimator (Phase 6).
Fixtures
  • audio/format_roundtrip.json — S16LE↔F32 sample sets → expected (±1 LSB).
  • audio/interleave.json — interleaved↔planar shuffles → exact.
  • audio/period_latency.json — (rate, period, periods) → latency ms.
  • audio/xrun_recovery.json — injected EPIPE sequence → recover + DISCONT flag + xrun count (offline-simulated via FileBackend fault hook).
  • Malformed: audio/unsupported_format.json (device refuses → typed error, no panic).
Pitfalls
  • Allocation/log/lock inside the audio callback — the classic cause of clicks; any format!, Vec, Mutex, or println! on the audio thread → underrun; route everything through pooled buffers + the telemetry ring; debug with the no-alloc harness + xrun-vs-event correlation.
  • Period/buffer sizing mismatch — avail_min/start-threshold inconsistent with period size causes early/late wakeups and xruns; follow the documented ALSA sw-param sequence; signal: periodic xruns at a fixed cadence.
  • Ignoring partial reads/writes — snd_pcm_writei may write fewer frames than requested; looping incorrectly drops samples; handle short counts; signal: pitch/gaps in output.
  • Wrong xrun recovery state — calling recover but not prepare/start leaves the PCM stuck; follow recover→prepare→(re)start; signal: stream halts after the first xrun.
  • Format/endianness assumption — assuming the device gives F32 when it gives S16LE (or wrong endianness) corrupts every sample; query and convert; signal: white noise / garbage.
  • Blocking vs non-blocking mode confusion — a blocking readi on the RT thread is acceptable only if it blocks for ≤ one period; a misconfigured large buffer blocks too long → deadline miss; size deliberately.

⬜ Phase 5 — Audio DSP nodes (gain / mixer / biquad) + polyphase resampler

Objectives
  • Implement media-dsp: Gain, Mixer, Biquad nodes and the polyphase-FIR Resampler with a fractional-ratio input (the drift-compensation hook), all RT-safe (no alloc/lock in process), planar F32, with denormals disabled. Advanced DSP primitives are sourced from #174.
Deliverable
  • A small DSP node set and a quality polyphase resampler, all RT-safe, matching numpy/FFmpeg references; a tone→resampler→WAV example runs offline.
Acceptance
  • Gain/Mixer/Biquad outputs match the numpy/scipy reference within a tight tolerance (e.g. ≤1e-5 RMS for F32).
  • Resampler: output length = round(input_len × ratio) (±1); SNR vs an ideal resample ≥ a threshold (e.g. ≥ 80 dB for the designed taps); matches FFmpeg swresample within tolerance.
  • No allocation in any process() (no-alloc harness); denormals confirmed off (denormal-stress block time stays flat).
  • Mixer saturates (never wraps) on overflow; gain smoothing eliminates zipper noise (spectral check).
Fixtures
  • dsp/gain.json, dsp/mixer.json — input + params → expected output (reference).
  • dsp/biquad_lp.json, dsp/biquad_peak.json — coeffs + input → output; impulse/step response.
  • dsp/resample_48_to_44.json, dsp/resample_44_to_48.json — input → output (+ SNR floor).
  • dsp/resampler_ratio_change.json — mid-stream ratio change (drift comp) → continuous output (no click).
  • Malformed: dsp/biquad_unstable.json (coeffs with poles outside unit circle → flagged), dsp/denormal_stress.json.
Pitfalls
  • Denormals not disabled — low-amplitude filter tails produce denormal floats → 10–100× slowdown → block overruns deadline → xrun; set FTZ/DAZ per RT thread; debug with the denormal-stress block-time test; signal: glitches only on quiet/decaying signals.
  • Biquad Direct Form I numeric blowup — DF-I accumulates error; use DF-II transposed; signal: filter output drifts/oscillates over long runs.
  • Resampler phase-accumulator drift — float accumulation error over millions of samples shifts the sub-filter index; use a high-precision (f64 or fixed-point) accumulator; signal: slow pitch drift.
  • Ratio change discontinuity — snapping the resampler ratio causes a click; ramp the ratio (the PI controller output is already smooth) and keep filter history continuous; verify with resampler_ratio_change.json.
  • Mixer overflow wrap — summing without clamp wraps F32→loud artifacts on the S16 conversion; saturate; signal: loud clicks on loud mixes.
  • Allocation in coefficient redesign — recomputing biquad coeffs on a parameter change must not allocate on the RT thread; precompute or compute in fixed scratch; signal: alloc-on-RT violation when tweaking a filter live.

⬜ Phase 6 — Clocks: media clock, presentation clock, PTS handling, drift estimation

Objectives
  • Implement media-clock: the Clock trait and the four clocks (Wall/Media/Device/Presentation), PTS assignment/handling against a timebase, and the PI drift estimator that turns device-clock drift into a resampler ratio to keep the audio buffer level stable (Invariant 11).
Deliverable
  • A clock subsystem with a master media clock, presentation mapping, monotonic PTS, and a converging drift estimator that holds the audio buffer level stable under simulated device drift.
Acceptance
  • PTS monotonic non-decreasing per stream; rescale between timebases matches the reference.
  • Drift estimator converges: for any ε in ±1000 ppm, buffer-level error settles to within ±1 period within a bounded time, and stays there (no oscillation/instability) over a 60-min sim.
  • drift_ppm reported within a tolerance of the injected ε.
  • No xrun in the drift sim once converged; the ratio changes are smooth (no clicks — ties to Phase 5).
Fixtures
  • clock/pts_assign.json — captured frame indices → PTS (per timebase).
  • clock/rescale_pairs.json — already in core; cross-checked here for audio↔90kHz.
  • clock/drift_converge.json — injected ε sequence → buffer-level trajectory + final ratio.
  • clock/drift_sweep.json — ε sweep → convergence time + steady-state error per ε.
  • Malformed: clock/drift_step.json (sudden ε jump → controller responds, bounded overshoot), clock/pts_regression.json.
Pitfalls
  • PI gains mistuned — too aggressive → oscillation (audible pitch wobble); too soft → slow convergence, near-xrun before it catches up; tune Kp/Ki against the sweep; signal: buffer-level oscillates or drifts.
  • Integrator windup — the integral term saturates during a long error, then overshoots; clamp the integrator (anti-windup); signal: large overshoot after a sustained drift.
  • Wrong sign on the control — speeding up when the buffer is full (should slow down) diverges fast → immediate xrun; verify the sign against the buffer-level definition.
  • Mixing clock domains — comparing a wall-time delta to a media-time delta without rescale corrupts the drift estimate; keep domains explicit and rescale; signal: nonsense ppm.
  • PTS from the wrong clock — stamping PTS from wall time instead of the media clock couples PTS to scheduling jitter; stamp from the MediaClock (samples consumed); signal: jittery PTS.
  • Estimator updated on the device callback — running the controller on the RT thread risks alloc/jitter; run it on the graph thread from reported buffer levels.

⬜ Phase 7 — A/V sync to master clock + jitter buffer

Objectives
  • Implement media-sync: the lip-sync controller that schedules video presentation against the master (audio) clock (present/drop/repeat within ±20 ms), and the adaptive, bounded de-jitter buffer that absorbs transport/arrival jitter into a smooth playout schedule.
Deliverable
  • A lip-sync controller keeping audio and video aligned to the master clock within ±20 ms, and an adaptive de-jitter buffer that smooths jittery arrivals with bounded depth — verified offline against jitter profiles.
Acceptance
  • For a synthetic A/V stream with injected video jitter (e.g. ±15 ms) and a fixed audio master, av_sync_error_ms p99 ≤ 20 ms; the correct frames are dropped/repeated per sync/*.json.
  • The jitter buffer's adaptive depth tracks the injected jitter (depth ≈ ceil(jitter_p99/interval)); late packets are discarded (counted), not presented out of time.
  • No audio is altered for sync (audio remains sample-exact; only video drop/repeat).
  • Overflow/late-discard are bounded and counted; the buffer never grows unbounded.
Fixtures
  • sync/present_drop_repeat.json — (video_pts, master_now) → decision.
  • sync/lip_sync_profile.json — A/V stream + jitter profile → sync-error trajectory + drop/repeat counts.
  • sync/jitter_depth_adapt.json — inter-arrival profile → adapted target depth.
  • sync/jitter_reorder.json — out-of-order seq# → in-order release.
  • Malformed: sync/late_packet.json (past playout → discard), sync/jitter_overflow.json, sync/pts_gap.json (missing frame → conceal/skip).
Pitfalls
  • Resampling audio for sync — stretching audio to match video is audible; audio is master, video follows; only drop/repeat video; signal: pitch artifacts when sync corrects.
  • Sync bound too tight — a ±2 ms bound forces constant drop/repeat (judder); ±20 ms (target ±10) is perceptually safe; signal: visible stutter despite small error.
  • Jitter buffer too shallow/deep — too shallow → late discards + gaps; too deep → excess latency; adapt to measured jitter_p99 with hysteresis; signal: either drops or laggy video.
  • Reorder vs duplicate — a retransmitted/duplicated packet with a seen seq# must be ignored, not re-inserted; dedup on seq#; signal: a frame presented twice.
  • Mapping PTS with the wrong clock base — using wall time instead of the presentation clock offsets the whole sync; map via PresentationClock; signal: constant sync bias.
  • Wraparound of seq# / timestamp — 16-bit seq and 32-bit RTP timestamps wrap; compare with modular arithmetic; signal: a flood of "late" discards at wrap.

⬜ Phase 8 — Video capture (V4L2) + pixel formats + color convert + scale

Objectives
  • Implement media-video: the VideoBackend trait, the V4L2 capture impl (mmap streaming, locked), VideoFrame (planes + strides + PTS), pixel-format handling (YUV420P/NV12/RGB24), color conversion (YUV↔RGB, NV12↔I420), and a bilinear scaler — all CPU reference paths (GPU PhaseDeferred).
Deliverable
  • Video capture over V4L2 with mmap streaming, correct pixel-format handling, CPU color conversion and bilinear scaling matching FFmpeg references, and a file/null sink; offline and hardware-capture paths run.
Acceptance
  • Offline convert (YUV420P↔RGB24, NV12↔I420) matches FFmpeg swscale within a tight per-pixel tolerance (rounding).
  • Bilinear scale (e.g. 1280×720→640×360 and up) matches a reference within tolerance; strides honored (no green/garbage rows).
  • Hardware capture: N frames dequeued at the requested format/resolution; PTS monotonic; buffers requeued (no leak; steady-state REQBUFS count conserved).
  • Convert/scale process() allocation-free on the RT/graph path (output buffers pooled).
Fixtures
  • video/yuv420p_to_rgb.json, video/rgb_to_yuv420p.json — sample frames → expected (reference).
  • video/nv12_to_i420.json — plane reshuffle → exact.
  • video/scale_down.json, video/scale_up.json — input → bilinear output (+ tolerance).
  • video/stride_aligned.json — non-trivial stride → correct handling.
  • Malformed: video/odd_dimensions.json (4:2:0 with odd w/h → chroma rounding), video/unsupported_pixfmt.json (typed error).
Pitfalls
  • Ignoring stride — assuming stride == width × bpp corrupts every row when the device pads rows; always index by stride; signal: a sheared/garbled image.
  • Chroma subsampling rounding (odd dimensions) — 4:2:0 chroma is ceil(w/2)×ceil(h/2); off-by-one on odd sizes reads/writes out of bounds; round up; signal: a colored edge artifact / crash.
  • Color matrix / range mismatch — BT.601 vs 709, and full-range vs limited-range (16–235) — using the wrong one washes out or over-saturates color; pick per resolution and signal range; verify against FFmpeg; signal: tinted output.
  • V4L2 ioctl ordering — REQBUFS/QUERYBUF/QBUF/STREAMON must be in order; a missing QBUF before STREAMON starves capture; follow the documented sequence; signal: DQBUF blocks forever.
  • Forgetting to requeue (QBUF) — not returning a dequeued buffer exhausts the V4L2 queue → capture stalls; requeue after use; signal: capture halts after REQBUFS frames.
  • Mapping V4L2 timestamp to the media clock — using the raw struct timeval without rescaling to the media timebase breaks A/V sync; rescale; signal: video constantly offset from audio.

⬜ Phase 9 — Encoded-frame transport boundary (encode/decode behind PhaseDeferred) + RTP packetization

Objectives
  • Implement media-transport: the EncodedFrame boundary (opaque payload; the codec that produces/consumes it is PhaseDeferred), RTP-style packetization (sequence number, timestamp, marker) and depacketization + reorder feeding the de-jitter buffer (Phase 7). Establishes the network path while keeping the codec out of scope.
Deliverable
  • An RTP-style packetizer/depacketizer and reorder buffer carrying opaque EncodedFrames end-to-end (with a pass-through codec), feeding the de-jitter buffer; the real codec remains a PhaseDeferred seam.
Acceptance
  • Packetize→depacketize→reorder round-trips frames exactly under no loss; under an injected loss/reorder profile, complete frames reassemble and losses are detected/counted.
  • marker set only on the last packet of a frame; all packets of a frame share one timestamp; seq increments by 1.
  • The depacketizer never panics on arbitrary bytes (fuzzed); malformed packets yield typed errors.
  • EncodedFrame.payload is treated as opaque — no codec field is read by transport (type-level + review).
Fixtures
  • transport/packetize.json — frame + MTU → packets (seq/ts/marker).
  • transport/depacketize.json — packets → header fields + payload.
  • transport/reorder.json — shuffled seq# → in-order reassembly.
  • transport/loss.json — dropped seq# → loss count + (in)complete frame handling.
  • Malformed: transport/bad_header.json, transport/seq_wrap.json (16-bit wrap), transport/ts_wrap.json (32-bit wrap).
Pitfalls
  • Timestamp per-packet instead of per-frame — RTP packets of one frame must share a timestamp; incrementing per packet breaks frame grouping and sync; assign once per frame; signal: every packet treated as a new frame.
  • Marker-bit misuse — the marker denotes the last packet of a frame; setting it wrong fragments or merges frames; verify against packetize.json.
  • Seq/timestamp wraparound — 16-bit seq and 32-bit timestamp wrap; loss/reorder detection must use modular comparison; signal: a burst of false loss at wrap.
  • MTU split losing payload boundaries — splitting without tracking offsets drops bytes at chunk seams; reassemble by offset/marker; signal: corrupt frames only when fragmented.
  • Leaking codec assumptions into transport — peeking at payload bytes (e.g. NAL type) couples transport to the deferred codec; keep payload opaque; the NAL-aware path is documented as future work.
  • Doing socket I/O on an RT thread — recv/send are syscalls; keep them on the transport thread; the jitter buffer is the seam to the RT video thread.
