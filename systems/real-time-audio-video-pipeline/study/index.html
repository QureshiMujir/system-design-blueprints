Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why is mlockall with pre-touch insufficient on its own to guarantee zero page faults, and what additional constraint must hold at runtime? (Synthesizes §4.3 RT contract + Phase 3 §3.2 pool pre-touch + Design Principle 2 no-alloc rule — even with mlockall, a new Box allocation on an RT thread faults a fresh page.)
  2. Trace the exact path by which a 200 ppm device clock drift causes an audible xrun at the 160-second mark, naming every component involved and the metric that would have warned you. (Synthesizes §8.9 drift example + Phase 6 §6.2 DriftEstimator + Invariant 11 + §4.2 drift ceiling + Back-of-Envelope Capacity Model C6.)
  3. Why does using Relaxed ordering on the SPSC tail publish cause a data race but not a deadlock, and what exact interleaving produces a torn read? (Synthesizes Phase 3 §3.2 memory ordering + §5.2 paper #5 Herlihy/Shavit + Invariant 8 — the Consumer reads the tail increment before the slot write is globally visible.)
  4. A caps negotiation succeeds between a resampler node (any-rate-in → 48 kHz-out) and a downstream biquad node (48 kHz-only).   6. You observe that process_block_us{biquad} p99 spikes to 50× normal exactly when the input signal fades to silence. What is the root cause, how do you confirm it, and what two code paths fix it? (Synthesizes Phase 5 §5.2 denormals + Invariant 13 + §5.1 book #10 Intel FTZ/DAZ + §5.6 pitfalls.)

  10. If buffer_level_frames is read on the audio RT thread and passed to the drift estimator, why is that a design violation even if the read is a single atomic load?   11. Compare the latency budget decomposition for a local capture→render path at 256-frame periods against a transport path with 20 ms jitter_p99. How does the de-jitter buffer interact with each stage's latency term? (Synthesizes §4.1 latency targets + Phase 7 §7.2 jitter depth formula + Back-of-Envelope Capacity Model C2 and C9 + Phase 10 telemetry.)

(Synthesizes Phase 3 §3.2 thread.rs + Phase 5 §5.2 denormal.rs + Invariant 13 — FTZ/DAZ is per-CPU-context, set in the thread that will run the biquad.)
  13. A BoundedQueue with DropOldest policy is on the edge between the audio DSP segment and the video sync segment. Mental Models & First Principles

The compressed intuitions an expert holds about a real-time media pipeline. Each: the insight, what it predicts, the bug class you write without it, and the section/phase where this blueprint applies it.

  • MM1 — The RT thread is a time budget, not a thread. Every RT iteration is a fixed time slice (one device period); every line of code in that slice is a withdrawal from that budget. Predicts: any operation with unbounded latency — malloc, mutex, syscall, page fault, I/O — eventually busts the budget → xrun, regardless of average cost. Bug without it: calling log::debug!() inside the audio callback (hidden string allocation + write syscall) that is invisible until the machine is loaded. Applied: §4.3 (RT discipline contract), Phase 4 §4.2 (callback contract), ADR-2/ADR-5, Invariant 1/Invariant 2.
  • MM2 — A lock-free ring is a happens-before contract, not a hardware trick. The producer's Release write to tail establishes a happens-before edge with the consumer's Acquire read of tail; every earlier producer write is then visible. Predicts: weaken the publish to Relaxed and the slot content can be globally invisible when the index says "ready" → torn/garbage frame. Bug without it: publishing tail with Relaxed produces intermittent corrupt data only under load, undetectable by a single-schedule stress test. Applied: Phase 3 §3.2 (SPSC Acquire/Release ordering), §5.2 paper #5 (Herlihy/Shavit), ADR-5, Invariant 8.
  • MM3 — Caps negotiation is type-checking at link time. A media-format mismatch is a type error; discovering it at buffer-flow time (per-buffer conversion) is the runtime-vs-compile-time error distinction. Predicts: fixing caps once at link time guarantees no per-buffer format surprises or hot-path allocation; deferring it forces a guess on every buffer. Bug without it: a pipeline that guesses the format per buffer silently converts on every iteration, adding latency and allocation. Applied: §8.5 (caps negotiation FSM), Phase 2 §2.2 (negotiate.rs), Invariant 9, Design Principle 3.
  • MM4 — Clock drift is integration, not a step. A ±100 ppm device error accumulates ~100 frames per million consumed; over 60 minutes at 48 kHz that is ~17,000 frames — far more than any buffer. Predicts: uncompensated drift always eventually drains (or floods) the buffer to xrun, no matter how large the buffer — only the time-to-failure scales. Bug without it: a "works for 2 minutes then clicks" report caused by ppm drift with no compensation loop. Applied: §8.9 (drift worked example), Phase 6 §6.2 (DriftEstimator PI controller), Invariant 11, the Back-of-Envelope Capacity Model.
  • MM5 — Backpressure policy is a tradeoff, not a default. Every bounded-queue edge must declare a policy — DropOldest bounds latency at the cost of completeness; DropNewest keeps completeness at the cost of freshness; Block is safe only off-RT. Predicts: there is no universally correct choice, and the wrong one per edge changes the latency-vs-completeness contract silently. Bug without it: using Block on an RT-segment edge stalls the audio callback → underrun. Applied: §8.4 (scheduling model), Phase 2 §2.2 (queue.rs), ADR-12, Invariant 6, Design Principle 4.
  • MM6 — The buffer pool is a conservation law. acquired + free == pool_size must hold at all times; a violation is either a leak (slot never returned) or a double-return (corruption). Predicts: exhaustion without a leak signals a cycle or a long-lived consumer; exhaustion with a leak is a refcount bug — the two have different fixes. Bug without it: a BufferRef clone that escapes scope without dropping leaks a slot; the pool silently starves → backpressure stall or an illegal RT-path alloc. Applied: Phase 1 §1.2 (BufferPool conservation), Invariant 7, ADR-4.
  • MM7 — Audio is master, video is a follower. Audio glitches are perceptually instant and irreversible; video drop/repeat is nearly imperceptible within ±20 ms. Predicts: stretching audio to follow video makes a resampling artifact audible on every sync correction; dropping/repeating video to follow audio is invisible. Bug without it: A/V-sync logic that pitch-shifts audio to follow video is immediately audible. Applied: Phase 7 §7.2 (LipSync audio-master), ADR-11, Invariant 5, §4.2 (±20 ms bound).
  • MM8 — Denormals are a silent deadline killer. IEEE-754 subnormal floats trigger a 10–100× slowdown on most x86/ARM FPUs that fall back to microcode; a filter tail full of denormals at near-zero amplitude can overrun the audio block's deadline. Predicts: a biquad with slowly decaying state runs fine until the signal fades, then suddenly overruns — the spike correlates with low-amplitude input, not load. Bug without it: glitches that appear only on quiet/decaying passages and vanish under a test tone. Applied: Phase 5 §5.2 (set_denormals_off), ADR-29, Invariant 13, §5.2 paper #10 (Intel FTZ/DAZ).
  • MM9 — PTS is the contract, arrival order is the accident. Transport reorder, jitter, and retransmission make arrival order meaningless for presentation; only PTS (the media-clock anchor stamped at capture) decides when to present. Predicts: any logic keyed on arrival/dequeue order produces timing-dependent bugs that disappear in a quiescent test and reappear under jitter. Bug without it: presenting video by dequeue order rather than PTS → stutter visible even under otherwise smooth playback. Applied: §8.7 (de-jitter buffer), §8.6 (A/V sync), Phase 7 §7.2, Design Principle 10, Invariant 4.
  • MM10 — The SPSC ring is the only safe RT boundary. Every other cross-thread primitive (mutex, condvar, MPSC channel, shared atomic state) either risks priority inversion or requires a syscall (futex). Predicts: the wait-free SPSC ring is the one construction with no OS involvement and a provable memory-ordering argument, so it is the sole sanctioned RT↔non-RT data path. Bug without it: substituting a Mutex<VecDeque> for the ring on the RT path works on a lightly loaded machine and sporadically xruns on any loaded one. Applied: Phase 3 §3.2 (Spsc<T>), ADR-5, Invariant 2, Design Principle 7.

Glossary · 32 terms · site-wide glossary

Frame
a unit of media (audio block or video image) with PTS/DTS/duration/flags + a buffer.
Buffer / BufferPool / BufferRef
fixed-capacity preallocated memory + refcounted handle; the RT-safe, alloc-free memory substrate.
MediaType / caps
the negotiated description (audio/video/encoded × format × rate × layout); "caps" = the capability set negotiated at link time.
Intersect / fixate
caps negotiation: intersect two capability sets, then fixate to a single concrete MediaType.
PTS / DTS
presentation / decode timestamp (when to render / when to decode).
Timebase / Timestamp / rescale
a rational tick rate; an integer tick count; converting ticks between timebases (overflow-safe, integer).
Node / Port / Pad / Graph
the pipeline DAG: a processing element, its typed I/O, the link endpoint, the whole topology.
Source / Sink / Transform
a producer / consumer / mapping node (a transform may change caps, e.g. a resampler).
Segment
a group of nodes sharing a scheduling discipline + thread class; seams between segments carry a queue.
Scheduler (pull / push)
sink-driven recursive demand / source-driven delivery; how frames flow through a segment.
BoundedQueue / backpressure
a fixed-capacity edge queue; the explicit policy (Block off-RT / DropOldest / DropNewest) when full.
Deadline / DeadlineAccount
the time budget for processing tied to a device period; the miss histogram.
RT thread / SCHED_FIFO / mlockall
a real-time-priority thread; the Linux RT scheduling class; locking memory to prevent page faults.
Xrun (underrun/overrun)
the audio device starved (underrun) or overflowed (overrun) — a missed real-time deadline.
SPSC ring
single-producer/single-consumer lock-free ring buffer (the RT↔off-RT handoff).
ALSA / V4L2
the Linux audio / video-capture device APIs.
Media clock / presentation clock / master clock
the rate reference for samples; the render-timing reference; the clock everything is synced to.
Drift / drift estimation
the slow rate mismatch between clocks (ppm); estimating it to drive resampling.
De-jitter buffer
an ingress buffer absorbing transport timing variation (trades latency for smoothness).
A/V sync
aligning audio + video to the master clock within the perceptual bound.
Resampler (polyphase)
rate conversion via polyphase filtering (also used to correct drift).
Biquad
a second-order IIR filter section (the DSP building block).
Gain / mixer
scalar amplitude scaling / multi-input summing nodes.
Pixel format / color convert / scale
video sample layout (e.g. YUV/RGB); colorspace conversion; resizing.
Keyframe / DISCONT / CORRUPT
frame flags: independently decodable / a discontinuity / damaged data.
RTP-style packet
the transport packet (sequence number, timestamp, marker, payload type, payload).
Packetize / depacketize
fragment frames into packets / reassemble packets into frames (loss/reorder-tolerant).
Jitter / loss / reorder profile
injected network-condition fixtures for testing transport robustness.
Pass-through codec
the trivial identity codec keeping the encoded-frame path testable while a real codec is deferred.
PhaseDeferred
an explicitly out-of-scope feature behind a documented marker (real codec, full WebRTC, GPU).
Backpressure policy
how a full queue responds: block (off-RT only), drop oldest, or drop newest.
rtpctl
the inspection/control tool (renders the negotiated graph + live metrics).
