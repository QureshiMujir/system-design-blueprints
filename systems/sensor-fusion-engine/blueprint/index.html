285 — Sensor Fusion Engine

Goal: A from-scratch, real-time, no_std-capable multi-sensor state-estimation engine that fuses IMU, GPS/GNSS, wheel odometry, barometer, and optional visual/LiDAR odometry into one consistent pose/velocity/orientation estimate via complementary, KF, EKF, ESKF (core), and UKF back-ends, with quaternion attitude, rigorous frame management, time synchronization, calibration, outlier rejection, and filter-consistency monitoring.

Project Number: 285

Project Name: Sensor Fusion Engine

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

1. Goal

1.1 What is built (precise terms)

  • Recursive Bayesian state estimator producing a unified 6-DOF pose + 3-DOF velocity + orientation estimate at IMU rate, corrected by aiding sensors.
  • State: position p (3), velocity v (3), attitude quaternion q (4 stored / 3 error-DOF), gyro bias b_g (3), accel bias b_a (3). Nominal state 16 scalars; error-state 15-DOF (core).
  • Filter back-ends: complementary filter (attitude baseline), linear KF, EKF, ESKF (recommended core), UKF (alternative). One Filter trait, swappable at construction.
  • Sensors fused: IMU (accel+gyro+mag), GPS/GNSS (position, velocity, optionally heading), wheel odometry (body-frame velocity / displacement), barometer (altitude), optional visual/LiDAR odometry (relative pose). ZUPT (zero-velocity update) for stationary detection.
  • Attitude: Hamilton quaternions throughout (locked, §8.6). Frames: body b, ECEF e, geodetic llh, local-tangent ned and enu (NED chosen as default navigation frame, §8.7).
  • Time handling: monotonic core clock; per-sensor timestamping; out-of-order + delayed-measurement buffer; latency compensation; interpolation/extrapolation.
  • Calibration: gyro/accel bias+scale+misalignment, magnetometer hard/soft-iron, sensor-to-body extrinsics (lever arms + rotation), time-offset estimation.
  • Health: innovation (Mahalanobis) gating, NIS/NEES consistency monitoring, adaptive noise, divergence detection, SPD-covariance enforcement.

1.2 System boundaries

  • In: estimation math, filter cores, sensor/measurement models, buffering/sync, calibration math, replay + evaluation, real-time runner.
  • Out (hard boundaries): sensor hardware drivers / HAL (mock + dataset only), feature tracking / front-end VIO, map building, path planning, actuation/control.

1.3 Explicit non-goals

  • Not a full SLAM / VIO system — front-end (feature detection/tracking, loop closure, mapping) is out → cross-link #288 SLAM.
  • Not a controller — no PID / trajectory tracking / actuation → cross-link #289 PID / Autonomous Control.
  • Not a physics simulator → cross-link #171 Physics Engine (used only to generate synthetic ground-truth trajectories for tests).
  • No GPU compute, no learned estimators, no factor-graph batch optimizer (filter-only; sliding-window MSCKF deferred).
  • No hardware time-sync protocols (PTP/PPS) implemented — modeled as time-offset parameters only.

1.4 Deployment model

  • Primary artifact: embeddable library (no_std + alloc-free hot loop core). Core crates compile for thumbv7em-none-eabihf (Cortex-M4F) and host.
  • Secondary artifact: real-time runner sfctl (std) — ingests live/replayed sensor streams, emits estimates + telemetry.
  • Integration surface: Filter trait + measurement-submission API; no global state; one estimator instance per fused body.

1.5 Target users

  • Robotics / drone / autonomous-vehicle / embedded navigation engineers integrating INS/GNSS, dead-reckoning, attitude/heading reference systems (AHRS).

1.6 Phase-0 deliverable (numbered crate list)

  1. sf-linalg — fixed-size matrices/vectors, Cholesky/LU/QR, no_std.
  2. sf-math — quaternion, rotation, SO(3)/SE(3), frames/transforms.
  3. sf-state — state vector, covariance, error-state.
  4. sf-sensor — sensor traits, measurement types, timestamps, buffer.
  5. sf-filter — KF/EKF/UKF/ESKF cores + Filter trait.
  6. sf-imu — strapdown mechanization.
  7. sf-gate — outlier rejection + NIS/NEES consistency.
  8. sf-sync — time sync, interpolation, delayed/out-of-order.
  9. sf-calib — calibration routines.
  10. sf-replay — dataset replay + evaluation (RMSE/ATE).
  11. sf-cli — sfctl demo/runner.
  12. sf-bench — benchmarks.

1.7 What later phases unlock

  • Phase 1–3: math + types substrate. Phase 4–8: filter family. Phase 9–11: robustness, sync, calibration. Phase 12: dataset conformance + real-time budget proof.

1.8 Deferred features (gated)

1.9 Timeline

1.10 Recommended language + rationale

  • Rust 2021, no_std core. Rationale: deterministic destruction + no GC → bounded hot-loop latency; const generics → stack-allocated fixed-size matrices with compile-time dimension checks (catches frame/dimension mismatch at build time); ownership → no aliasing of covariance during update; #![no_std] + #![forbid(unsafe_code)] in math/filter cores → portable to MCUs; strong float-determinism control (no implicit FMA contraction unless opted in).

1.11 Prerequisites

  • Linear algebra (matrix factorizations, PD matrices, conditioning).
  • Probability / estimation theory (Gaussian, Bayes, MMSE, ML).
  • Rigid-body kinematics (frames, DCM, angular velocity).
  • Quaternion algebra (Hamilton product, exp/log, SO(3) tangent).
  • Real-time systems (scheduling, jitter, bounded allocation) — see #185, #186.

  • Error-state KF lineage (Solà 2017) is the de-facto attitude-estimation core in production INS.

  • Translating continuous-time stochastic models to discrete filters; defending every Jacobian; keeping a numerical system stable for hours; designing for replay/determinism; building observability into a math kernel.

2.4 Production engineering concepts exercised

  • Bounded-allocation hot loops, deterministic replay, structured telemetry of internal estimator health, fault injection, conformance datasets, semver of binary log formats.

2.6 Calibration value

  • After this, an engineer can reason about why an estimator diverges (observability vs numerics vs modeling), not just tune Q/R by trial — a permanent capability lift.

2.7 What Mastery Looks Like

  • Derive any Jacobian from first principles (no copy-paste from refs): finite-diff verify, defend the linearization regime — built in Phase 6 (EKF Jacobians) and Phase 7 (ESKF reset Jacobian).
  • Diagnose filter inconsistency from NIS/NEES telemetry alone: distinguish underscaled Q, wrong R, unmodeled bias, observability collapse, or missing reset Jacobian — built in Phase 9.
  • Read Allan-variance plots and extract noise PSDs that go into Q; know when bias instability dominates vs angle random walk — built in Phase 11.
  • Reason about manifold geometry: why filtering the 4-vector quaternion directly ranks-deficient the covariance, and why right-perturbation ESKF avoids it — built in Phase 7 (§8.2, §8.5).
  • Design a latency/OOSM compensation strategy: choose buffer-replay vs Larsen approximation given delay horizon and real-time budget — built in Phase 10.
  • Evaluate observability: rank the Gramian, identify unobservable yaw/scale under planar motion, apply FEJ to prevent spurious information gain — built in Phase 9 (§21.2).
  • Write a deterministic replay + conformance harness: bit-exact replay, ATE/RPE evaluation, CI-gated thresholds — built in Phase 12.

3.2 Per-box detail (one paragraph each)

  • Sensor drivers (external). Out of scope as hardware; represented by traits + mock/dataset producers. Emit raw, device-unit, device-frame samples tagged with a device timestamp. No filtering here. Interface: SensorSource::poll() -> Option<RawSample>. Trust boundary: all input is untrusted (malformed/spoofed handled downstream).

  • sf-sensor ingest. Converts raw → canonical Measurement (SI units, documented frame, covariance R). Normalizes units, applies static calibration corrections, attaches a core Timestamp. Runs on the non-RT ingest path; may allocate at setup but not per-sample in steady state (fixed-capacity pools). External interface: submit(Measurement).

  • sf-sync MeasurementBuffer. Fixed-capacity ring buffer ordered by timestamp. Absorbs out-of-order arrival and bounded delay; supports interpolation (between IMU samples) and latency compensation (re-apply a delayed measurement at its true time via state cloning / OOSM logic). Concurrency boundary: SPSC/MPSC queue from ingest threads → drained by RT core. Backpressure: full buffer drops oldest non-applied with a counted telemetry event.

  • sf-imu strapdown predict. The RT predict step. Integrates gyro to propagate attitude (quaternion exp map), rotates specific force to nav frame, subtracts gravity, integrates to velocity then position. Computes discrete F, Q. Bounded compute, no heap. Runs at IMU rate (100–1000 Hz) on the RT thread. This is the only step allowed to run without an aiding measurement.

  • sf-filter core. Houses Filter trait + KF/EKF/ESKF/UKF. Owns the predict/update math (covariance propagation, Kalman gain, Joseph update, ESKF inject/reset, UKF sigma transform). Stateless w.r.t. sensors — receives (F,Q) from sf-imu and (h,H,R,z) from sensor models. Concurrency: single-writer to state/covariance on the RT thread.

  • sf-state store. Authoritative StateVector + Covariance + ErrorState. Enforces invariants: quaternion normalized, P symmetric PD. Only the RT thread mutates; readers get an atomically-published snapshot (double-buffer) for the Estimate API. Serializable for logging/replay.

  • sf-gate (outlier + consistency). Before applying any update, computes innovation y and S, evaluates Mahalanobis d² = yᵀ S⁻¹ y against a χ² threshold; accepts/rejects/defers. Tracks NIS (per update) and NEES (vs ground truth in test), runs divergence detection, drives adaptive R/Q. Emits health telemetry. Can veto a measurement entirely.

  • Estimate API / output. Publishes the current best estimate: position/velocity in nav frame, attitude quaternion (+ Euler convenience), bias estimates, full or marginal covariance, and health flags (gated count, NIS status, divergence flag). Lock-free read snapshot for control consumers (#289).

  • sf-replay logging/replay. Captures the full input stream + estimator outputs to a versioned binary log; replays bit-deterministically; computes RMSE / ATE / RPE against ground truth. The backbone of regression and conformance testing.

  • sf-calib. Offline (batch) and limited online calibration of IMU intrinsics, magnetometer iron, sensor-to-body extrinsics, and per-sensor time offset. Feeds parameters into ingest + models; not in the RT hot loop except online bias states (which live in the filter state itself).

3.3 Data flows / boundaries summary

  • RT boundary: predict + (gated) update + state publish. Hard real-time, bounded compute, no heap.
  • Non-RT boundary: ingest, normalization, buffering, calibration, logging.
  • Trust boundary: every measurement crosses from untrusted → validated at sf-gate before touching covariance.
  • Persistence boundary: only sf-replay persists (logs); core holds no disk state.

6. Design Principles

  1. Covariance stays SPD, always. Every update uses Joseph form + explicit symmetrization; failure ⇒ negative variance ⇒ NaN gain ⇒ divergence. Enforced at write boundary of sf-state; violation is a hard fault with telemetry.

    • Tradeoff: Joseph costs ~2× a naive (I−KH)P. Operational: cheaper than recovering a diverged filter in the field.

  2. Quaternion stays normalized. |q|=1 within tol after every injection. Drift ⇒ implicit scaling of attitude ⇒ biased rotation. Enforced in sf-math/sf-state. Violation breaks the rotation group assumption.

  3. Error-state over full-state for attitude. Attitude lives on SO(3); a 3-DOF error in the tangent space (MEKF/ESKF) avoids quaternion-norm constraint singularities and keeps P minimal-dimension. Violating it (filtering the 4-vector directly) creates a rank-deficient covariance.

  4. Innovation gating before every update. No measurement touches P before passing the χ² gate. Skipping ⇒ one spoofed/outlier sample can collapse covariance. Enforced in sf-gate.

  5. Frame conventions explicit and single-sourced. Every quantity carries (or is documented with) a Frame. One module defines NED/ENU/ECEF/body; no ad-hoc conversions. Mixing NED/ENU or Hamilton/JPL silently flips signs → catastrophic, hard-to-find errors.

  6. Bounded compute in the hot loop. Predict + update are O(n²)/O(n³) with fixed n; no allocation, no unbounded iteration. Violation ⇒ deadline miss ⇒ dropped IMU samples ⇒ attitude drift.

  7. Determinism over convenience. Given (init, stream, params, target, flags) → identical output. No wall-clock, no RNG in core, no FMA contraction unless globally fixed. Enables replay-based debugging and conformance.

  8. Numerical stability over micro-optimization. Prefer Cholesky/square-root forms and conditioning checks over the fastest algebraic shortcut. A faster but ill-conditioned update is worthless after an hour.

  9. Observability monitored, not assumed. Track which states are observable given current sensor set; apply FEJ where needed; flag observability collapse (e.g. yaw unobservable when stationary without mag/GNSS heading).

  10. Consistency is measured. NIS per update and NEES in Monte-Carlo tests must lie within χ² bounds; a "confident but wrong" filter is the worst failure. Drives adaptive noise and alerts.

  11. Time is monotonic at the core. The filter advances only forward in time; all reordering/delay handled in sf-sync before the core. Non-monotonic time ⇒ negative dt ⇒ unstable propagation.

  12. Models are explicit and testable in isolation. Each sensor model (h,H,R) is a unit, validated by finite-difference Jacobian checks and against analytic truth.

  13. Type-level dimension safety. Matrix dimensions are const-generic; mismatched multiplies fail at compile time, not runtime.

  14. Fail loud, contain locally. A bad sensor degrades that channel (reject + flag), never silently corrupts the shared state.

  15. Replayability first. Every input and decision is loggable; nothing in the core is observable only via a debugger.

8. Domain Model / Math

8.1 State vector (nominal)

x = [ p (3), v (3), q (4, body→nav, Hamilton), b_g (3), b_a (3) ], dim 16. Frame: p,v in nav (NED); q maps body→nav; biases in body.

8.2 Error-state (15-DOF)

δx = [ δp (3), δv (3), δθ (3), δb_g (3), δb_a (3) ]. Attitude error is a 3-vector rotation in the tangent space; nominal/error relation (right perturbation): q = q_nom ⊗ δq, δq ≈ [1, ½ δθ]ᵀ. (Convention locked: right/local error, Hamilton.)

8.3 Process model (IMU strapdown mechanization)

Inputs: gyro ω_m, accel a_m (specific force). Corrected: ω = ω_m − b_g − n_g, a = a_m − b_a − n_a. Continuous nominal kinematics (nav = NED, g = local gravity vector):

ṗ = v
v̇ = R(q) a + g
q̇ = ½ q ⊗ [0, ω]
ḃ_g = n_bg   (random walk)
ḃ_a = n_ba   (random walk)

R(q) = body→nav DCM. Discretization over Δt (median IMU dt): attitude via exp map q_{k+1}=q_k ⊗ Exp(ω Δt); velocity/position via first/second-order integration (trapezoidal; optional coning/sculling correction).

Continuous error-state dynamics δẋ = F_c δx + G w, with (standard ESKF blocks, right perturbation):

δṗ = δv
δv̇ = −R(q)[a]_× δθ − R(q) δb_a − R(q) n_a
δθ̇ = −[ω]_× δθ − δb_g − n_g
δḃ_g = n_bg
δḃ_a = n_ba

[·]_× = skew. Discrete F = exp(F_c Δt) ≈ I + F_c Δt + ½(F_c Δt)²; discrete Q via Van Loan or trapezoidal of G Q_c Gᵀ.

Process-noise PSDs (continuous): gyro σ_g², accel σ_a², gyro-bias RW σ_bg², accel-bias RW σ_ba² (from datasheet noise density + bias instability).

8.5 KF / EKF / ESKF / UKF equations

Linear KF (predict/update):

predict:  x⁻ = F x⁺ ;            P⁻ = F P⁺ Fᵀ + Q
update :  y = z − H x⁻ ;          S = H P⁻ Hᵀ + R
          K = P⁻ Hᵀ S⁻¹
          x⁺ = x⁻ + K y
          P⁺ = (I − K H) P⁻ (I − K H)ᵀ + K R Kᵀ      (Joseph form)

S⁻¹ via Cholesky solve (never explicit inverse).

EKF: h(x) nonlinear; H = ∂h/∂x|_{x⁻}, F = ∂f/∂x; predict via nonlinear f, covariance via Jacobian F. Jacobians verified by central finite differences (tol 1e-5 f64).

ESKF (recommended core): split nominal x (integrated full-precision) and error δx (filtered, mean 0 between resets).

predict: nominal integrated (no covariance growth from nominal);
         δx⁻ = F δx⁺ (mean stays 0) ; P⁻ = F P⁺ Fᵀ + Q
update : y = z − h(x_nom) ; S = H P⁻ Hᵀ + R ; K = P⁻ Hᵀ S⁻¹
         δx⁺ = K y ; P⁺ Joseph
inject : x_nom ← x_nom ⊞ δx⁺   (⊞: p,v additive; q ← q ⊗ Exp(δθ); biases additive)
reset  : δx ← 0 ; P ← J P Jᵀ  (J = reset Jacobian ≈ I − ½[δθ]_× on attitude block)

ESKF advantages: error stays small (linearization valid), attitude minimal (3-DOF), no quaternion-norm constraint in P.

UKF (alternative back-end): unscented transform; 2n+1 sigma points (n=error-dim or augmented), weights:

λ = α²(n+κ) − n
χ₀ = x̄ ; χ_i = x̄ ± (√((n+λ)P))_i      (columns of matrix sqrt, Cholesky)
W_m^0 = λ/(n+λ) ; W_c^0 = λ/(n+λ)+(1−α²+β) ; W_{m/c}^i = 1/(2(n+λ))

Propagate sigmas through f/h; recombine mean/covariance; cross-covariance P_xz; K = P_xz S⁻¹. On manifolds: sigma points generated in tangent space, mapped through Exp, recombined via iterative mean (or simple for small spread). Square-root UKF preferred for conditioning.

Complementary filter (baseline): fuse high-pass gyro integration with low-pass accel/mag attitude: q_{k+1} = q_k ⊗ Exp((ω + k_p e) Δt), e = error between measured and predicted gravity/mag direction (Mahony) — no covariance, O(1), used as a sanity baseline and fallback.

8.6 Quaternion algebra (Hamilton — LOCKED)

  • Storage q = [w, x, y, z], scalar-first, Hamilton product (i j = k). JPL convention is not used anywhere (single-sourced in sf-math).
  • q maps body→nav (active rotation of a body vector into nav frame).
  • Exp: R³→S³, Exp(φ) = [cos(‖φ‖/2), sin(‖φ‖/2) φ/‖φ‖]; small-angle ≈ [1, ½φ].
  • Log: S³→R³ inverse; Rotvec = Log × 2 mapping to SO(3) tangent.
  • R(q) ∈ SO(3); derivative w.r.t right error: R(q⊗Exp(δθ)) ≈ R(q)(I+[δθ]_×).
  • Renormalize after each injection; sign-fix w≥0 to avoid double cover ambiguity in logs.

8.7 Frames & transforms (LOCKED defaults)

  • Navigation frame: local NED (North-East-Down) tangent at a fixed reference origin. (ENU adapter provided; one flag at construction; never mixed at runtime.)
  • Frames: body (b), nav (NED, n), ECEF (e), geodetic LLH. Conversions: LLH↔ECEF (WGS-84), ECEF↔NED (rotation by ref lat/lon), body↔nav via R(q).
  • Lever arm l: sensor offset from IMU/body origin, body frame. GPS measures p_body + R(q) l_gps.
  • Gravity: g_ned = [0,0,+9.81…] (down positive) using a latitude-dependent gravity model.

8.8 Worked numeric example (1-D vertical, baro+IMU)

State [p_D, v_D, b_a]. IMU a_m=0, true g=9.81. Init P=diag(1,1,0.01). Baro z=0 m, R=0.04. Predict Δt=0.01: v_D⁻=v_D+(a_m−b_a−g+g)Δt (gravity cancels in down channel when at rest) → demonstrates that a stationary vehicle should show ~0 velocity; nonzero residual reveals b_a (Invariant I12 test). Update: y=z−p_D, S=P_pp+R, K=P_pp/S, Joseph P⁺. After ~50 updates b_a observable through baro+gravity coupling only weakly → illustrates partial observability (§9).

  • Initialization/alignment: coarse attitude from accel (roll/pitch) + mag/GPS-course (yaw); set initial P (§8.10: Uninit→Aligning transition).
  • Integrate gating hook (still pass-through until Phase 9 — P4: gate before every update).
  • End-to-end harness on synthetic INS/GNSS trajectory with ground truth (ADR-17: differential testing; ADR-18: dataset replay).

18.3 Deliverable

  • EKF fusing IMU + GPS (+baro, +mag heading) producing bounded-error global pose; sfctl can run a synthetic INS/GNSS scenario.

18.4 Acceptance Criteria

  • On synthetic INS/GNSS (circle/figure-8, GPS@5Hz σ=1.5 m): horizontal position RMSE < 1.0 m, velocity RMSE < 0.2 m/s, attitude RMSE < 1°, after convergence. All H finite-diff errors < 1e-5. Covariance SPD throughout. NIS within 95% χ² (consistent EKF on synthetic-Gaussian case).

18.5 Conformance Fixtures

  • tests/ekf_jac.rs: per-sensor H vs finite diff. synthetic/circle.spec,figure8.spec with GPS dropouts; degenerate: GPS-only-Z (vertical) update; heading update at high pitch. Regression: golden RMSE in conformance/synthetic/expected/.

18.6 Pitfalls

  • Wrong H attitude column sign (lever arm) → attitude-correlated position bias. Manifestation: bias grows with turn rate. Detect: finite-diff; turn-heavy fixture. Recovery: re-derive, test.
  • Linearization error under large innovation (e.g. GPS jump after outage) → inconsistent update. Detect: NIS spike. Recovery: gate (Phase 9), iterate (IEKF) if needed.
  • Yaw observability with position-only GPS at low dynamics → yaw drifts. Detect: yaw variance not shrinking. Recovery: add heading/mag or rely on acceleration excitation (§9).
  • Mag heading vs true/magnetic north (declination) → constant yaw offset. Detect: yaw bias vs GPS course. Recovery: apply declination model.
  • Baro datum drift (weather) → slow altitude bias. Detect: baro-GPS-alt residual trend. Recovery: estimate baro bias state or fuse loosely.

18.7 Performance Concerns

  • Per-sensor update O(15²·m + m³). GPS pos/vel m=3 each — batch into m=6 when synchronous to amortize. DCM reuse. Avoid recomputing F per measurement (predict already did).

18.8 Edge Cases

  • GPS reports valid-but-wrong (multipath) before gating exists → documents the need for Phase 9. Simultaneous GPS pos+vel+heading at same ts (stacked update). Heading wrap (±π) in innovation — wrap to [−π,π].

18.9 Failure Analysis

  • Jacobian errors are the dominant EKF failure. Detection: mandatory finite-diff gate in CI. Containment: per-model isolation. Forensic: log H, innovation, S per update.

18.10 Operational Notes

  • Telemetry: per-sensor innovation mean/std, accepted/rejected counts, yaw variance. Declination + nav-frame origin are versioned config. Document alignment procedure in runbook.

19. Phase 7 — Error-State KF (Nominal/Error Split, Injection, Reset) — Recommended Core

19.1 Objectives

  • sf-filter::Eskf: the recommended production core. Nominal state integrated full-precision; 15-DOF error filtered; inject + reset with reset-Jacobian. Same models as EKF but error-state-correct.

19.2 Detailed Implementation Steps

  • eskf.rs: predict integrates nominal (no covariance contribution from nominal), propagates error covariance P⁻=FP⁺Fᵀ+Q; error mean held at 0 between updates (Solà 2017 §5; ADR-7: ESKF core; P3: error-state over full-state).
  • Update: y=z−h(x_nom), S, K, δx⁺=Ky, Joseph P⁺ (Kalman 1960; Simon ch.6; P1: SPD always; I9).
  • Inject: x_nom ⊞ δx (q←q⊗Exp(δθ) + renormalize; p,v,b additive); then reset: δx←0, P←J P Jᵀ with J=blkdiag(I, I, I−½[δθ]_×, I, I) (attitude block; Solà 2017 §6; Lefferts et al. 1982; I1: quat norm; P3).
  • Differential test: ESKF vs EKF on identical data → near-identical estimates, ESKF more consistent under large attitude error (ADR-17: differential testing).
  • Confirm error stays small (validity of single linearization) (Crassidis & Junkins ch.7).

19.3 Deliverable

  • ESKF fusing IMU+GPS(+baro,mag,odo,ZUPT) — the default Filter for sfctl.

19.4 Acceptance Criteria

  • Matches EKF within 1e-3 on benign data; on aggressive attitude maneuvers, ESKF attitude RMSE ≤ EKF and NEES closer to dof. Reset keeps P SPD and consistent (NEES within bounds over Monte-Carlo, Phase 9). Inject keeps |q|=1. Same RMSE thresholds as Phase 6, met or better.

19.5 Conformance Fixtures

  • tests/eskf_consistency.rs: NEES vs ground truth over 100 Monte-Carlo runs within 95% χ²(15). synthetic/figure8.spec with high yaw rate; compare ESKF vs EKF attitude error. Degenerate: large initial attitude error (30°) — ESKF converges, EKF may not.

19.6 Pitfalls

  • Missing reset Jacobian → covariance inconsistent with relinearization → optimistic P → divergence. Manifestation: NEES below dof then blow-up. Detect: Monte-Carlo NEES. Recovery: apply J P Jᵀ.
  • Injecting into wrong sign/side (left vs right perturbation) → attitude correction inverted. Detect: differential vs EKF. Recovery: lock right-perturbation convention (§8.2).
  • Error mean not reset to 0 → double counting. Detect: error norm grows unbounded. Recovery: reset after inject.
  • Bias states uncorrected because H bias columns zero → biases never observed. Detect: bias estimate flat under excitation. Recovery: verify H includes R(q) bias coupling.

19.7 Performance Concerns

  • Same as EKF; reset adds one 3×3 J block multiply on attitude sub-block (cheap). Nominal integration is full-precision but identical cost to EKF predict. Net: ESKF ≈ EKF cost.

19.8 Edge Cases

  • Very small δθ (reset J≈I) — small-angle branch. Long run without updates (error covariance large but mean 0). Simultaneous multi-sensor update then single reset.

19.9 Failure Analysis

  • The reset step is the classic ESKF bug site (often omitted). Detection: NEES consistency soak. Forensic: log δx pre-inject, P pre/post reset.

19.10 Operational Notes

  • Default core; document why (Principle 3). Expose error-state norm + reset count as telemetry. ESKF is the reference for differential tests of UKF (Phase 8) and the conformance baseline (Phase 12).

20. Phase 8 — Unscented KF (Sigma Points, Unscented Transform) — Alternative Back-End

20.1 Objectives

  • sf-filter::Ukf: derivative-free back-end via unscented transform; manifold-aware sigma handling for attitude; square-root form for conditioning. Validate against EKF/ESKF.

20.2 Detailed Implementation Steps

  • ukf.rs: parameters α,β,κ; λ=α²(n+κ)−n; sigma generation via Cholesky of (n+λ)P (matrix sqrt); weights W_m,W_c (§8.5) (Julier & Uhlmann 1997/2004; ADR-8: UKF back-end).
  • Manifold handling: generate error-state sigma points in tangent space, map to nominal via ⊞ (Exp on attitude), propagate through nonlinear f/h, recombine: attitude mean via iterative boxminus averaging (or single-step for small spread), covariance from weighted boxminus outer products (Solà 2017 Appendix C; P3: error-state attitude).
  • Predict: propagate sigmas through mechanization; recombine x⁻,P⁻+Q (Titterton & Weston ch.3 mechanization reused).
  • Update: propagate sigmas through h; compute S, cross-cov P_xz, K=P_xz S⁻¹, δx⁺, inject+reset like ESKF (I1: quat norm; I3: SPD; I9: S PD).
  • Square-root UKF (Van der Merwe & Wan 2001) to keep P factorized (Cholesky update/downdate) — optional feature for conditioning (P8: numerical stability).
  • Differential test: UKF vs ESKF on identical data (ADR-17; I7: determinism).

20.3 Deliverable

  • Working UKF back-end selectable via Filter trait; matches ESKF/EKF on benign data, more robust on strong nonlinearity.

20.4 Acceptance Criteria

  • UKF vs ESKF estimate difference < 1e-2 on benign data; on highly nonlinear measurement (e.g. heading near singularity) UKF NIS more consistent than EKF. 2n+1 sigma propagation within budget (≤600 µs M4F, m=3). Covariance SPD (square-root form never produces non-PD). Manifold mean converges (iterative averaging < 5 iters).

20.5 Conformance Fixtures

  • tests/ukf_vs_ekf.rs: identical input, compare estimates + NIS. Degenerate: α tuning extremes (very small spread → numerical; large → overshoot). Strong-nonlinearity fixture (large attitude uncertainty). Deferred: MSCKF visual-inertial sigma handling → PhaseDeferred("FINAL_BLUEPRINT §8.5").

20.6 Pitfalls

  • Naive Euclidean sigma mean on quaternion → invalid/denormalized mean attitude. Manifestation: attitude bias. Detect: |q| of recombined mean. Recovery: tangent-space (Exp/Log) averaging.
  • Matrix sqrt non-PD when P ill-conditioned → sigma generation fails. Detect: Cholesky fail. Recovery: square-root UKF / regularize.
  • Weight W_c^0 negative (with λ<0) can yield non-PD recombined covariance. Detect: SPD probe. Recovery: square-root form or scaled UKF.
  • Sigma count cost 2n+1 predicts per step — 31 mechanizations at n=15. Detect: cycle budget. Recovery: reuse DCM/structure, or restrict UKF to update-only with EKF predict.

20.7 Performance Concerns

  • UKF ≈ (2n+1)× propagation cost of EKF predict; dominant cost. SIMD opportunity (batch sigma propagation) — deferred (Performance Engineering). Square-root form trades flops for stability. Choose UKF only where nonlinearity demands it.

20.8 Edge Cases

  • Very high state dimension (augmented for process noise) inflates sigma count. Near-π attitude uncertainty (sigma points wrap). κ choice when n>3.

20.9 Failure Analysis

  • Manifold-mean and negative-weight bugs are UKF-specific. Detection: differential vs ESKF + SPD probe. Forensic: log sigma set + recombined moments.

20.10 Operational Notes

  • Document when to prefer UKF (strong nonlinearity, hard-to-derive Jacobians) vs ESKF (cheaper, production default). Expose sigma-recombination iteration count + matrix-sqrt failures as telemetry.

21. Phase 9 — Outlier Rejection + Consistency Monitoring + Adaptive Noise

21.1 Objectives

  • sf-gate: Mahalanobis χ² innovation gating before every update; NIS (online) + NEES (test) consistency monitoring; divergence detection; adaptive R/Q; optional FEJ for observability consistency.

21.2 Detailed Implementation Steps

  • mahalanobis.rs: d²=yᵀS⁻¹y (Cholesky solve, ADR-29); compare to χ² threshold (per dof, configurable confidence, e.g. 0.99). Return GateResult{accepted,d2,threshold,dof} (Bar-Shalom et al. ch.5; P4: gate before every update; I5: every accepted meas passed χ² gate).
  • nis.rs: rolling-window NIS average; expected ≈dof; bounds from χ²(dof·N)/N; nis_in_bounds (I10) (Bar-Shalom et al. ch.5; P10: consistency measured).
  • nees.rs: test-only NEES using ground truth (x−x̂)ᵀP⁻¹(x−x̂); Monte-Carlo average within χ² bounds — primary ESKF/UKF consistency check (Bar-Shalom et al. ch.5; ADR-26: seeded RNG for deterministic MC).
  • adaptive.rs: innovation-based R scaling (e.g. covariance-matching) and Q inflation when NIS persistently high; bounded scaling to avoid runaway (P10: consistency measured; §8.10: Degraded state).
  • divergence.rs: detect sustained NIS > bound, covariance collapse (trace below floor) or inflation (above ceiling); transition state machine (Running→Degraded→Reinit) (§8.10; P14: fail loud, contain locally).
  • FEJ (optional): evaluate Jacobians at first-estimate for unobservable directions to prevent spurious information gain (Huang et al. 2010–2014; ADR-30; P9: observability monitored; §8.11 stationary-no-heading case).

21.3 Deliverable

  • Gating + consistency layer wired into all filters; outliers rejected; health flags + adaptive noise active.

21.4 Acceptance Criteria

  • Injected outliers (10× σ GPS spikes) rejected with false-accept rate < 1% at 0.99 gate; false-reject of valid measurements < 1%. NIS within 95% χ² bounds on consistent sims. NEES within χ²(15) 95% bounds over 100 MC runs (ESKF). Divergence detector fires within N=20 windows of induced divergence. Adaptive noise restores consistency on mild model mismatch without oscillation.

21.5 Conformance Fixtures

  • tests/chi2.rs: known innovation distributions → expected accept rate. nees_mc.rs: 100-run Monte-Carlo NEES. Fixtures: outlier_burst.spec, slow_bias_drift.spec, cov_collapse.spec. Degenerate: all measurements outliers (filter holds), zero outliers (no false reject).

21.6 Pitfalls

  • Gate too tight rejects valid measurements after legitimate state jump → filter starves, diverges. Manifestation: rising covariance + high reject rate. Detect: reject-rate telemetry. Recovery: looser gate or innovation-adaptive threshold.
  • Gate too loose admits outliers → covariance collapse. Detect: NIS low then attitude error high. Recovery: tighten; cross-check with NEES.
  • Adaptive Q runaway (positive feedback) → covariance inflation → everything passes gate. Detect: trace ceiling. Recovery: bound adaptation, hysteresis.
  • Observability collapse undetected: yaw unobservable (stationary, no heading) → P_yaw may artificially shrink from linearization. Detect: observability Gramian rank / yaw variance floor. Recovery: FEJ + hold yaw variance.
  • Single-measurement gating vs joint (correlated GPS pos+vel) — gating components separately misses joint outliers. Detect: joint NIS. Recovery: gate stacked measurement jointly.

21.7 Performance Concerns

  • Gating reuses S Cholesky already computed for the update → near-free. NEES is test-only (no runtime cost). Rolling windows are O(1) ring updates. FEJ adds bookkeeping (store first estimates) but no extra flops.

21.8 Edge Cases

  • S not invertible (skip + flag). Innovation NaN (reject). Window not yet full (warm-up: don't alarm). Step change in true state (maneuver) vs outlier — distinguished by persistence.

21.9 Failure Analysis

  • A mis-tuned gate is a top field failure (either starvation or collapse). Detection: paired reject-rate + NIS dashboards. Containment: per-sensor gates; degrade not crash. Forensic: log every gate decision with d², threshold, dof.

21.10 Operational Notes

  • Metrics: gated_total, accepted_total, nis, nees(test), diverged, adaptive_scale. Alert on sustained reject-rate or NIS breach. Runbook divergence.md references state machine. Gate thresholds are versioned config.

22. Phase 10 — Time Sync, Out-of-Order + Delayed Measurements, Latency Compensation, Interpolation

22.1 Objectives

  • sf-sync: robust handling of multi-rate, out-of-order, and delayed measurements; latency compensation via state cloning / OOSM; IMU interpolation; per-sensor time-offset application.

22.2 Detailed Implementation Steps

  • buffer.rs: extend ring to hold IMU + aiding measurements with timestamps; maintain a short state history (snapshots at IMU epochs) for OOSM (ADR-10: heapless ring; P6: bounded compute; I4: monotonic time).
  • interp.rs: linear/SLERP interpolation of IMU between epochs to evaluate a measurement at its exact timestamp (ADR-5: Hamilton quaternion SLERP; §8.6).
  • oosm.rs: out-of-sequence measurement handling — when a delayed measurement with ts<now arrives: (a) buffer-replay (rewind to ts, apply, re-propagate to now) using stored history (ethzasl_msf OOSM pattern, ref-impl §5.2), or (b) Larsen/Alspach delayed-update approximation when full rewind is too costly. Choose buffer-replay for ≤ N-step delay, approximation beyond (P11: time monotonic at core; I4).
  • latency.rs: apply known per-sensor processing latency (constant offset) and estimated time offset (from sf-calib) (Phase 11 time_offset.rs; §8.4 timing).
  • Bound history depth = max supported delay × IMU rate; backpressure beyond (I11: no heap on RT path).
  • Determinism: reordering yields identical result to in-order arrival (tested) (I7; ADR-24: reproducibility; ADR-18: replay format).

22.3 Deliverable

  • Sync layer that makes the filter order-invariant and delay-tolerant up to a bounded horizon.

22.4 Acceptance Criteria

  • Shuffled + delayed measurement stream produces estimate identical (within 1e-9) to in-order processing, up to max delay. GPS with 100 ms latency, compensated, reduces position RMSE vs naive (no compensation) by ≥30% on dynamic trajectory. History/buffer never exceeds memory ceiling. Deterministic replay hash stable under reordering.

22.5 Conformance Fixtures

  • tests/ooo.rs: random permutation of timestamps. tests/delay.rs: fixed + variable latency. Fixtures: delayed_gps.spec, multirate.spec. Degenerate: delay exceeding history (fallback to approximation + flag), simultaneous identical timestamps, time going backward at ingest (rejected by I4 at core, reordered in sync).

22.6 Pitfalls

  • Applying delayed measurement at now instead of ts → correlated error, especially under acceleration. Manifestation: position lag/overshoot. Detect: compare vs ground truth on dynamic segment. Recovery: timestamp-correct OOSM.
  • History too shallow for actual delay → silent approximation error. Detect: delay vs history-depth telemetry. Recovery: size history to max delay; flag overflow.
  • Interpolation across a state reset (attitude) using linear instead of SLERP → wrong attitude at meas time. Detect: attitude residual. Recovery: SLERP on quaternion.
  • Time offset sign (t_true=t_device±offset) wrong → systematic lead/lag. Detect: cross-correlation of innovation with motion. Recovery: estimate + lock sign (Phase 11).
  • Non-determinism from re-propagation order → replay hash drift. Detect: determinism CI. Recovery: canonical replay order.

22.7 Performance Concerns

  • OOSM rewind cost = delay-depth predict re-runs; bound it. Buffer-replay is the expensive path — amortize by limiting frequency of large delays; approximation for the tail. History snapshots cost memory (bounded). Interpolation cheap.

22.8 Edge Cases

  • Out-of-order IMU samples (should not happen; reject + flag). Measurement older than entire history (drop + count). Clock jumps (NTP step) at ingest — detect discontinuity, optionally reset reference. Duplicate measurement (idempotent or dropped).

22.9 Failure Analysis

  • Subtle: delay errors look like model error and get mis-tuned. Detection: A/B compensation on/off on same dataset. Forensic: log meas ts, arrival ts, applied ts.

22.10 Operational Notes

  • Metrics: reordered_total, delayed_total, oosm_rewind_depth, history_overflow_total, time_offset_applied. Clock-skew runbook. Time offsets are versioned per-sensor config. Document max supported delay as an SLO-equivalent.

23. Phase 11 — Calibration (IMU Intrinsics, Mag Iron, Extrinsics, Time Offset)

23.1 Objectives

  • sf-calib: offline + limited online calibration — gyro/accel bias+scale+misalignment, magnetometer hard/soft-iron, sensor-to-body extrinsics (lever arm + rotation), and per-sensor time offset. Allan variance for noise PSDs.

23.2 Detailed Implementation Steps

  • imu_intrinsic.rs: estimate accel bias/scale/misalignment from multi-orientation static data (6-position tumble; gravity magnitude constraint); gyro bias from static; scale/misalignment from rate-table or known rotations. Solve via QR least-squares (sf-linalg, ADR-29; Farrell ch.10; I6: bias bounds) (kalibr ref-impl §5.3 as design reference — not copied).
  • allan.rs: Allan variance from long static log → angle/velocity random walk (σ_g,σ_a) + bias instability (σ_bg,σ_ba) → feeds Q (Phase 5 noise.rs) (Titterton & Weston ch.12; scripts/allan_variance.py).
  • mag_iron.rs: ellipsoid fit of magnetometer samples (hard-iron offset + soft-iron matrix) → maps measured field to sphere; declination application (§8.4 mag model; I8: frame consistency).
  • extrinsics.rs: estimate lever arm + body↔sensor rotation (GPS antenna offset; camera/LiDAR pose) from motion (rotation-induced velocity coupling) — batch (Farrell ch.11 lever arm; kalibr ref-impl pattern; §8.4 GPS lever-arm H).
  • time_offset.rs: estimate per-sensor time offset by cross-correlating sensor-derived motion with IMU (or as a filter state online) (ADR-28: external Timestamp; Phase 10 latency.rs consumes output).
  • Online subset: gyro/accel bias already estimated as filter states (§8.1 state vector); calibration provides priors + offline refinement (P9: observability monitored).

23.3 Deliverable

  • Calibration toolset producing a versioned parameter set consumed by ingest + models + process noise.

23.4 Acceptance Criteria

  • Accel calibration residual (gravity magnitude across orientations) < 0.01 m/s². Gyro bias estimate within 0.01 °/s of injected truth (synthetic). Mag ellipsoid fit RMS < 2% of field magnitude; corrected samples lie on a sphere. Lever-arm estimate within 2 cm on synthetic. Time-offset estimate within 1 ms. Allan variance recovers injected PSDs within 10%.

23.5 Conformance Fixtures

  • tests/mag_ellipsoid.rs: synthetic distorted field → recover hard/soft-iron. allan.rs: synthetic noise with known PSD. Fixtures: tumble6.spec, mag_sphere.spec, lever_arm.spec, time_offset.spec. Degenerate: insufficient excitation (rank-deficient extrinsics → flag), magnetic anomaly during mag cal (reject), pure-rotation-only data for lever arm.

23.6 Pitfalls

  • Insufficient motion excitation → unobservable extrinsics/scale → garbage estimates. Manifestation: huge parameter covariance. Detect: observability/rank check. Recovery: require excitation; flag low-rank.
  • Mag calibration under disturbance (nearby metal) → wrong soft-iron. Detect: residual + field-magnitude variance. Recovery: collect in clean environment; reject anomalies.
  • Declination vs calibration conflation → yaw offset absorbed into soft-iron. Detect: yaw vs GPS course post-cal. Recovery: separate declination model.
  • Online bias vs offline bias double-correction → over-subtraction. Detect: stationary residual after applying both. Recovery: single source of truth; offline sets prior only.
  • Time-offset/lever-arm aliasing (both produce motion-correlated error). Detect: joint estimation observability. Recovery: estimate jointly or fix one.

23.7 Performance Concerns

  • Offline (not RT). QR/ellipsoid fits are batch, O(N) in samples. Online bias states add to filter dim (15→ unchanged; biases already in state). Extrinsics as online states grow P (O(n²)) — only if enabled.

23.8 Edge Cases

  • Temperature-dependent bias (out of scope; note as deferred). Near-singular ellipsoid (planar mag data). Antenna offset near IMU origin (lever arm ≈ 0, weakly observable).

23.9 Failure Analysis

  • Bad calibration silently biases the whole filter. Detection: post-cal stationary + course-vs-yaw checks. Forensic: store calibration residuals + covariance with the parameter set.

23.10 Operational Notes

  • Parameter sets are versioned + checksummed; sfctl records the param-set version in every log (compatibility). Re-cal runbook. Online extrinsic/time-offset estimation gated behind config (default off for bounded dim). Temperature compensation PhaseDeferred("FINAL_BLUEPRINT §11").

24. Phase 12 — Replay Harness + Dataset Conformance + Benchmarks + Real-Time Budget

24.1 Objectives

  • sf-replay + sf-bench + sf-cli: deterministic binary log format; EuRoC/KITTI-style loaders; RMSE/ATE/RPE evaluation; criterion benchmarks; MCU cycle-budget verification; conformance gate in CI.

24.2 Detailed Implementation Steps

  • log_format.rs: versioned little-endian binary (header: magic, version, scalar type, state layout, param-set version; records: IMU, aiding, snapshots). Encode/decode no_std-friendly (ADR-27: custom LE binary; ADR-18: dataset replay; I7: determinism; P15: replayability first).
  • euroc.rs,kitti.rs: dataset loaders → Measurement stream + ground truth; checksum-verified (Shin 2005 loosely-coupled protocol; §5.3 ref-impls OpenVINS/EKF2 as comparison).
  • eval.rs,ate.rs,rpe.rs: Absolute Trajectory Error (after SE(3) alignment), Relative Pose Error, position/velocity/attitude RMSE (SE(3) from sf-math §8.7).
  • sf-cli: sfctl run --filter eskf --dataset euroc/MH_01 --out log.bin; sfctl eval --log log.bin --gt gt.csv; sfctl replay --log log.bin (deterministic re-run) (ADR-9: crossbeam SPSC ingest; ADR-12: tracing telemetry).
  • sf-bench/benches: predict, per-sensor update, UKF, end-to-end; criterion thresholds (ADR-19); MCU path measures cycles via DWT (feature bench) — validates §4 compute budgets.
  • CI conformance.yml: run datasets, assert RMSE/ATE under thresholds; bench.yml: assert no perf regression; determinism.yml: replay hash equality (ADR-20: CI matrix; I7; P7: determinism over convenience).

24.3 Deliverable

  • End-to-end: ingest a standard dataset, produce + evaluate a trajectory, replay it bit-deterministically, and prove the real-time budget.

24.4 Acceptance Criteria

  • EuRoC (loosely coupled equivalent) ATE within target band (document per sequence; e.g. < a few % of trajectory length for the aided cases). Replay hash identical across two runs (I7) and across CI runs (same target/flags). Predict ≤ 50 µs M4F / ≤ 5 µs x86; GPS EKF update ≤ 120 µs M4F (verified by sf-bench). Memory within §4 ceiling. All prior-phase fixtures pass as regression.

24.5 Conformance Fixtures

  • conformance/euroc/*.spec + expected/*.json (golden RMSE/ATE with tolerance). kitti/seq00.spec. synthetic/* regression. Degenerate: GPS-denied stretch (dead-reckon ATE bound), sensor dropout, corrupted log (decode error handled). Replay-equality fixture across reordered input (links Phase 10).

24.6 Pitfalls

  • Dataset frame/units mismatch (EuRoC body frame, gravity-aligned) → large ATE from convention error, not algorithm. Manifestation: constant rotation offset. Detect: ATE after alignment vs before. Recovery: documented per-dataset adapter.
  • ATE alignment masking drift (Umeyama alignment hides bias). Detect: also report RPE (drift rate). Recovery: report both ATE + RPE.
  • Nondeterministic eval (float reduction order) → flaky conformance. Detect: determinism CI. Recovery: fixed reduction order, pinned flags.
  • Benchmark variance on shared CI → false regressions. Detect: criterion confidence intervals. Recovery: statistical thresholds, dedicated runner or relative gates.
  • Log-format drift breaks old logs. Detect: round-trip + version test. Recovery: versioned format + migration (Compatibility Guarantees).

24.7 Performance Concerns

  • Replay must be faster than real time for CI throughput. Log encode I/O batched. Benchmarks isolate hot kernels (predict/update) from I/O. MCU cycle counts via DWT cycle counter.

24.8 Edge Cases

  • Truncated/corrupted log (graceful decode error). Dataset with missing ground truth (skip ATE, still replay). Very long sequence (memory of history bounded; streaming eval). Mixed scalar type log on f32 build (reject with clear error).

24.9 Failure Analysis

  • Conformance regression blocks release. Detection: CI thresholds. Containment: per-sequence gates; bisect via deterministic replay. Forensic: store failing log + diff vs golden.

24.10 Operational Notes

  • Logs carry version + param-set + filter type → reproducible postmortems. sfctl replay is the primary incident-debugging tool. Benchmark baselines stored in benchmarks/baselines/. Conformance thresholds versioned with the spec.

Mental Models & First Principles

# Model Expert insight What it predicts Bug class without it Applied in
MM1 Covariance is belief, not error P encodes what the filter claims to know; NIS checks if it matches reality. Filter consistency; NIS/NEES within χ² bounds. Overconfident P (underscaled Q): filter ignores valid measurements → slow divergence. §7 System Invariants (I10); Phase 9 (§21.2 NIS)
MM2 Error-state lives in the tangent space Attitude error δθ is a 3-vector in the Lie algebra; the nominal quaternion is the base point. Filtering happens in flat space; the manifold is only used at inject/reset. Linearization stays valid as long as δθ is small; reset returns error to zero. Filtering the full 4-vector creates a rank-deficient P and the norm constraint conflicts with the Kalman update. §8.2; Phase 7 (§19.2); ADR-5, ADR-7
MM3 Observability governs what the filter can learn A state is observable only if there exists a measurement sequence that produces non-zero Fisher information about it. Unobservable states (e.g. yaw without heading sensor) have bounded information; P in that direction should not shrink. Without FEJ, linearization drift manufactures spurious information → artificially confident yaw → catastrophic yaw bias. Phase 9 (§21.2 FEJ); §8.11 stationary case; ADR-30
MM4 Innovation is the signal; S is the noise The innovation y = z - h(x⁻) carries all new information. Its covariance S = HPHᵀ + R is the expected uncertainty. Mahalanobis distance normalizes the signal by the noise. A consistent filter's d² ~ χ²(dof). Persistent d² >> dof means model mismatch or outlier, not "large innovation". Gating without Mahalanobis (e.g. absolute threshold) rejects valid large-variance measurements and accepts normalized outliers. §8.5 update equations; Phase 9 (§21.2 mahalanobis.rs); I5, I10
MM5 Joseph form is insurance against numerical drift The standard (I-KH)P is algebraically equivalent to Joseph form but accumulates rounding error; Joseph form is SPD-preserving by construction. Over thousands of updates, standard form yields negative variances (NaN gain); Joseph does not. One non-Joseph update in 10⁴ steps causes an almost-undetectable slow drift toward non-PD covariance, then sudden filter death. Phase 4 (§16.2 joseph.rs); I3; P1
MM6 Time is a measurement, not a given Every sensor reading carries a timestamp that may be wrong, delayed, or out of order. The filter must treat the timestamp as input, not ground truth. Delayed/reordered measurements must be applied at their true time, not arrival time, to avoid correlated errors. Applying a GPS fix at arrival time (100 ms late) during acceleration introduces a position error that correlates with vehicle velocity — unmodeled and ungated. Phase 10 (§22.2 oosm.rs, latency.rs); I4; P11
MM7 Cholesky is both the gate and the guard Cholesky factorization of P and S serves double duty: it computes the matrix square root for UKF sigma points and signals non-PD before the update damages the state. A failing Cholesky on P or S is an early warning, not a catastrophic failure — the correct response is regularize and skip, not propagate NaN. Using explicit matrix inverse skips the PD check and produces NaN gain on the first ill-conditioned cycle. Phase 1 (§1.2 chol.rs); I3, I9; ADR-29; P8
MM8 Gravity is the reference; bias is what you estimate In the ESKF, gravity cancels exactly in the vertical channel at rest — any residual velocity is caused by accel bias. This makes a stationary vehicle a bias calibration fixture. Stationary velocity residual reveals b_a; gyro bias appears in attitude drift when turning. Without this understanding, engineers misattribute stationary drift to noise and inflate Q instead of estimating bias, destroying observability. §8.8 worked example; Phase 5 (§5.2 stationary test); I12

Why rejected: Requires access to raw GNSS pseudoranges (not available from NMEA/UBX NAV-PVT, the documented interface in §5.4); adds per-satellite states (4–12 clock/bias states) growing n to ~27+; satellite geometry and ionospheric modeling increase implementation complexity by an order of magnitude. Explicitly deferred per §1.3 ("loosely coupled" is the documented coupling level).

Lever arm Vector offset of a sensor from the IMU/body origin (body frame).
FEJ First-Estimates Jacobians: evaluate Jacobians at first estimate to preserve observability/consistency.
ZUPT Zero-velocity update: pseudo-measurement v=0 when stationary.
Sigma points Deterministic samples of a distribution used by the unscented transform.
Unscented transform Propagate sigma points through nonlinearity, recombine to get mean/covariance.
ESKF Error-State Kalman Filter: filter a small error state about an integrated nominal state.
MEKF Multiplicative EKF: attitude error applied multiplicatively (quaternion).
Joseph form Numerically stable covariance update (I−KH)P(I−KH)ᵀ+KRKᵀ.
SPD Symmetric Positive-Definite (required of all covariances).
Quaternion (Hamilton) Scalar-first unit quaternion, i j=k; used for attitude (body→nav).
Exp/Log map Maps between SO(3) tangent (R³) and rotation group (quaternion/DCM).
DCM Direction Cosine Matrix; rotation matrix R(q).
NED / ENU North-East-Down / East-North-Up local tangent navigation frames.
ECEF Earth-Centered Earth-Fixed Cartesian frame.
LLH Latitude/Longitude/Height geodetic coordinates (WGS-84).
OOSM Out-Of-Sequence Measurement: a measurement arriving after later-timestamped data.
Latency compensation Applying a delayed measurement at its true timestamp (via rewind/clone).
Complementary filter Frequency-domain blend of gyro (high-pass) and accel/mag (low-pass) for attitude.
Allan variance Time-domain stability analysis yielding noise PSDs + bias instability.
Hard/soft iron Magnetometer offset (hard) and scale/skew (soft) distortions.
Declination Angle between magnetic and true north.
Coning/sculling High-rate attitude/velocity integration corrections for rotating/vibrating motion.

Measurement noise R Covariance of sensor measurement noise.
