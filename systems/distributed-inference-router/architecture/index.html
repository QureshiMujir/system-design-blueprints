3. Architectural Overview

3.1 Canonical Architecture Diagram

    clients (HTTP/1.1, HTTP/2, gRPC, streaming)
            |
      [infr-ingress] parse request; resolve model/adapter; compute prefix_hash
            |  Request
      [infr-queue] admission: SLO deadline, priority, bounded queue -> admit / shed / backpressure   <->   [infr-sched] fairness, autoscale signals
            |  admitted Request
      [infr-route] policy: least-load + prefix-cache-aware (PrefixTree longest match) + adapter-aware   <->   [infr-registry]+[infr-health] (model->replicas, LoadState, PrefixTree)
            |  RoutingDecision (BackendId + reason)
      [infr-dispatch] conn pool -> backend; stream tokens back; retry / hedge / timeout / circuit-break
            |  token stream
        back to client          [infr-telemetry] taps every stage

3.2 infr-ingress

  • Responsibilities: accept TCP connections; negotiate HTTP/1.1 upgrade or HTTP/2 ALPN; parse OpenAI-compatible /v1/chat/completions and /v1/completions JSON bodies; resolve model → ModelId, optional adapter → AdapterId; compute prefix_hash (SHA-256 of canonicalized prompt tokens); emit a Request struct; relay SSE (data: <token>\n\n) or chunked transfer back to client byte-for-byte preserving order; execute graceful drain on SIGTERM.
  • Concurrency boundary: one tokio::task per client stream; H2 multiplexes N streams over one TCP connection; backpressure via H2 flow-control windows propagates to upstream client.
  • Protocol boundary: external (client-facing) vs internal (infr-queue channel); no backend protocol here.
  • Failure modes: malformed JSON → 400; unknown model → 404; upstream queue full → 429 with Retry-After; graceful drain timeout → 503.

3.3 infr-queue

  • Responsibilities: per-ModelId bounded VecDeque<Lease>; admit requests by priority (Priority enum: high/normal/low/batch); enforce SLO deadline (Slo.deadline) — shed if wall-clock would exceed deadline before dispatch; emit backpressure signal to infr-ingress when queue at high-water mark; interact with infr-sched for fairness quotas.
  • Async queue/channel: tokio mpsc channel from ingress → queue; semaphore-based bounded admission; tokio::time::sleep_until(deadline) for SLO expiry.
  • Bounded-queue invariant: queue capacity = max_queue_depth per model (config); on saturation, shed lowest-priority first (oldest-deadline-first within same priority); never allocate unbounded.
  • Concurrency boundary: queue actor runs in its own tokio task; registry/health read is read-only shared Arc<RwLock<RegistryState>>.
  • Failure modes: queue full + high-priority request → shed lowest priority to make room; all priorities full → 503; SLO deadline already expired on dequeue → drop + increment requests_expired_total.

3.4 infr-sched

  • Responsibilities: observe queue depths across all models; emit autoscale signals (ScaleSignal { model, direction: Up|Down, reason }) to a broadcast channel consumed by an external HPA/KEDA bridge; enforce per-model and per-tenant quota (token/minute, request/minute); coordinate disaggregated prefill/decode: on prefill completion, emit a decode-continuation Request to the decode-replica queue with affinity to the correct decode backend.
  • Disaggregated prefill/decode: prefill replicas handle prompt evaluation; decode replicas handle token generation; sched tracks PrefillLease → DecodeLease handoff; invariant: decode continuation is only dispatched after prefill KV-cache is confirmed transferred.
  • Async queue/channel: sched subscribes to infr-health's LoadEvent broadcast; publishes to autoscale_tx: broadcast::Sender<ScaleSignal>.
  • Failure modes: prefill backend fails mid-transfer → abort decode lease; emit InferError::PrefillFailed; retry policy configurable.

3.5 infr-registry + infr-health

  • infr-registry responsibilities: authoritative map ModelId → Vec<Replica>; adapter inventory AdapterId → Vec<BackendId>; capacity descriptors (GPU memory, max_batch); config reload (SIGHUP → atomic Arc swap of RegistryState); exposes read-only handle to infr-route.
  • infr-health responsibilities: periodic heartbeat probes (HTTP GET /health); scrape queue-depth + kv-util from backend metrics endpoints; compute EWMA of ttft_ms per replica; run ejection state machine (Healthy → Degraded → Ejected); publish LoadEvent to broadcast channel; update LoadState in RegistryState via write lock.
  • Ejection state machine: consecutive_failures >= threshold → Ejected; periodic re-probe in Ejected state; re-admit to Degraded on first success; Degraded → Healthy after recovery_probes successes.
  • Health invariant: infr-route reads only replicas with Health::Healthy | Health::Degraded (Degraded used only when no Healthy alternative); Health::Ejected replicas are never returned by route().
  • Persistence boundary: no persistent storage; state is in-memory; re-bootstraps from config on restart.

3.6 infr-route

  • Responsibilities: given admitted Request + current RegistryState, select BackendId and record RouteReason; policy chain (in order): 1) filter by ModelId + Health; 2) filter by AdapterId if request.adapter.is_some(); 3) PrefixTree longest-prefix match on prefix_hash (prefix-cache-aware); 4) least-load on kv_util * w_kv + ewma_ttft * w_ttft + queue_depth * w_q; 5) consistent hashing for session affinity; 6) fallback: lowest queue_depth.
  • PrefixTree: radix tree keyed by token-prefix byte sequences; leaf = BTreeSet<BackendId> with recency timestamp; updated by infr-health when backends report cache hits; eviction: LRU per prefix entry; thread-safe via RwLock<PrefixTree> (write only on health events, read on every route call — low contention).
  • Decision auditability: every call returns RoutingDecision { backend: BackendId, reason: RouteReason } — RouteReason ∈ {PrefixHit, LeastLoad, AdapterResident, Affinity, Fallback}; logged and counted in infr-telemetry.
  • Failure modes: no healthy replica for model → InferError::NoHealthyReplica; prefix match found but replica now Ejected → fall through to least-load; all replicas at max kv_util → InferError::Overloaded → shed at queue.

3.7 infr-dispatch

  • Responsibilities: maintain per-BackendId HTTP/2 connection pool (hyper client, max pool_size streams); forward Request to chosen BackendId as HTTP POST; stream response tokens back through a tokio::sync::mpsc::Sender<Bytes>; implement retry (on retriable errors + request.idempotent), hedging (second replica after hedge_delay_ms if idempotent), timeout (Slo.ttft_ms for first token, Slo.tpot_ms per token), circuit breaker per backend.
  • Circuit breaker: per-backend AtomicU32 failure counter; >= cb_threshold → Open; Open → reject immediately with InferError::CircuitOpen; half-open probe after cb_reset_ms.
  • At-most-once invariant: non-idempotent requests sent to exactly one backend; hedging disabled; retry only on connection errors before first byte sent.
  • Order invariant: SSE/chunked bytes forwarded in arrival order; no reordering in relay buffer.
  • Lease invariant: Lease acquired before dispatch, released (and backend accounting decremented) on completion, error, or timeout.
  • Failure modes: backend 5xx → retry if budget; backend timeout → retry or hedge; all retries exhausted → InferError::BackendExhausted; circuit open → InferError::CircuitOpen → queue may re-route to alternate backend.

3.8 infr-telemetry

  • Responsibilities: tap every stage via tracing::Span and metrics crate (Prometheus-compatible); emit per-route histograms for TTFT, TPOT, queue wait, dispatch latency; counters for cache-hit/miss, shed requests, retry count, circuit-open events; gauges for queue depth, kv_util per backend, inflight requests; export via /metrics HTTP endpoint (Prometheus scrape); structured JSON logs via tracing-subscriber; OpenTelemetry trace export (OTLP/gRPC).
  • Instrumentation points: ingress parse, queue admit/shed, route decision (+ RouteReason), dispatch start/first-byte/last-byte, retry, hedge, circuit-breaker transition.
  • No side effects on hot path: all metric updates are atomic increments or histogram observations; tracing spans are sampled; never blocks the routing hot path.

3.9 Data Flow Summary

Request path (per request):
  1. TCP accept → HTTP parse → Request{id, model, adapter, prefix_hash, slo, priority} (infr-ingress)
  2. mpsc send → infr-queue: priority enqueue; SLO deadline check
  3. sched signal: quota gate; disaggregated-prefill routing hint
  4. dequeue → infr-route: PrefixTree match + load score → RoutingDecision
  5. Lease acquire (infr-core) → infr-dispatch: H2 forward → backend
  6. Token stream: backend → dispatch relay buffer → ingress SSE writer → client
  7. Lease release; telemetry record TTFT/TPOT/route-reason

Control path (continuous background tasks):
  - infr-health: probe loop (every health_interval_ms) → update LoadState + PrefixTree → broadcast LoadEvent
  - infr-sched: observe LoadEvents → emit ScaleSignal → external HPA
  - infr-registry: SIGHUP → reload config → Arc::swap(RegistryState)

3.10 Trust + Persistence Boundaries

Boundary Description
External trust Clients are untrusted; request size limits enforced at infr-ingress
Internal trust Backend replicas are trusted (same cluster); no mTLS required by default (hook exists)
Persistence None: all state in-memory; restart = re-bootstrap from config + health probes

8.4 Replica Health State Machine

  [Healthy] ──consecutive_failures(≥3)──► [Degraded]
  [Healthy] ──kv_util > 0.95──► [Degraded]
  [Degraded] ──probe_success + load_ok──► [Healthy]
  [Degraded] ──consecutive_failures(≥5)──► [Ejected]
  [Ejected] ──slow_start_probe_success──► [Degraded]  (not directly Healthy)
  [Ejected] ──manual_force_healthy──► [Healthy]
Health Routing Eligibility Probe Interval Recovery Path
Healthy Full weight 500 ms —
Degraded Reduced weight (50%) 200 ms 2 consecutive successes → Healthy
Ejected None (invariant: never dispatched) 5 s slow-start probe success → Degraded
  • Health invariant: RoutingDecision.backend is NEVER a BackendId whose Replica.health = Ejected.
  • EWMA decay: ewma_new = α * sample + (1-α) * ewma_old; α=0.2 default; configurable per model.

8.5 PrefixTree (Radix Cache) Model

Purpose: route requests whose prompt shares a long prefix with tokens already materialized in a backend's KV cache → reduces TTFT and compute cost.

  • PrefixTree structure:
  • root
    • ├── [hash_A] → {BackendId(1), BackendId(3)} recency: T-10s
    • │ ├── [hash_A+B] → {BackendId(1)} recency: T-2s
    • │ └── [hash_A+C] → {BackendId(3)} recency: T-5s
    • └── [hash_D] → {BackendId(2)} recency: T-1s

Key operations:

  • longest_match(prefix_hash) -> Option<(depth, Set<BackendId>)> — walk radix tree; return deepest node whose BackendId set intersects Healthy replicas.
  • insert(prefix_hash, backend_id, timestamp) — called on COMPLETED; adds leaf; evicts LRU nodes beyond capacity.
  • evict(backend_id) — called on Ejected; removes all tree nodes referencing that backend.
  • invalidate_stale(ttl: Duration) — background task; removes nodes older than TTL.

PrefixHash computation:

prefix_hash = SHA-256( canonical_token_bytes )[0..16]
canonical_token_bytes = little-endian u32 array of first min(512, N) token ids

Routing with prefix cache:

  1. longest_match(request.prefix_hash) → candidates.
  2. Intersect candidates with Healthy replicas for request.model + request.adapter.
  3. If intersect non-empty: pick lowest LoadState.kv_util among matches → RouteReason::prefix_hit.
  4. If empty (cold start or all matched backends degraded/ejected): fall through to least_load.

Edge cases:

  • Hash collision: two distinct prompts produce same prefix_hash → harmless; backend may not have the exact prefix but will re-compute; routed with RouteReason::prefix_hit but actual cache miss is acceptable.
  • All matching backends ejected: invariant forces fallback; prefix_hit reason NOT emitted; fallback emitted.
  • Tree race: concurrent insert + evict on same node → protected by per-tree RwLock; writers hold write lock; readers share read lock; stale reads tolerated (eventual consistency acceptable for cache hints).

8.6 Admission Control & Queue Model

Queue per (ModelId, Priority) pair:

Queue key: (ModelId, Priority)
Queue capacity: config.queue_max[model] * priority_weight[p]
  e.g., model="llama3-70b", capacity=1000 total
        Critical=200, High=300, Normal=400, Low=80, BestEffort=20

Admission algorithm (sequential checks, first failure → shed):

  1. Deadline check: now + estimated_queue_wait > slo.deadline → shed 504.
  2. Capacity check: queue.len() >= queue_max → shed 429 (backpressure).
  3. Token budget check: request.prompt_tokens + request.max_tokens > model.max_context → reject 400.
  4. Replica availability check: at least one Healthy replica for model+adapter → admit; else hold for replica_wait_timeout then shed.

Queue drain:

  • Dequeue order: priority-descending, then FIFO within priority tier.
  • Dequeue rate governed by infr-sched fairness policy (token budgets per tenant/model).
  • SLO scan: background task every 50 ms evicts expired entries (deadline < now) → shed 504 without dispatching.

Backpressure propagation:

  • HTTP/1.1: return 429 with Retry-After header.
  • HTTP/2: send RST_STREAM or 429 response.
  • gRPC: RESOURCE_EXHAUSTED status.
  • Internal: infr-ingress checks queue fullness before accepting TCP read; applies TCP backpressure by pausing reads on saturated connections.

Bounded-queue invariant: queue.len() is bounded by queue_max; no dynamic growth; admission is rejected before exceeding bound.

8.7 Routing Policy Engine — Decision Procedure

Candidate set (computed once per request): replicas serving req.model, filtered to Health == Healthy, further filtered to replicas holding req.adapter when an adapter is requested. An empty candidate set short-circuits to RouteReason::Fallback with an error — no tier below is consulted.

Decision tiers, evaluated in strict priority order against the candidate set — the first tier that yields a non-empty eligible subset wins and the search stops:

Tier Name Eligible subset (within candidates) Winner selection RouteReason on match
1 Session affinity Candidates equal to the backend bound in affinity_store for req.session_id, if that backend is not overloaded The bound backend itself Affinity
2 Prefix-cache aware Candidates ∩ tree.longest_match(req.prefix_hash) backend set min by score_load (table below) over the intersection PrefixHit
3 Adapter-resident Candidates already holding req.adapter loaded (skips adapter swap-in cost) min by score_load over that subset AdapterResident
4 Least-load (default) Full candidate set min by score_load over all candidates LeastLoad

score_load weighted-sum components (default weights, per-model configurable via infr-cli config reload, no restart required):

Component Default weight Contribution
load.queue_depth w_q = 0.4 pending requests at replica
load.kv_util w_kv = 0.3 KV-cache occupancy fraction
load.ewma_ttft_ms w_t = 0.2 smoothed time-to-first-token
load.inflight w_i = 0.1 dispatched, awaiting first token

score_load(r) = w_q·queue_depth + w_kv·kv_util + w_t·ewma_ttft_ms + w_i·inflight; lower score wins each tier's min.

8.8 Dispatch & Streaming Protocol Model

Connection pool per BackendId:

  • Multiplexed HTTP/2 streams; max concurrent streams bounded by backend's max_concurrent_streams advertisement.
  • Pool size: min_idle=2, max_size=config.backend_max_conns (default 32).
  • Acquire timeout: 50 ms; on timeout → circuit-breaker check → fallback to least-loaded alternative.

Request forwarding wire format:

POST /v1/completions  (OpenAI-compatible) or /generate (vLLM native)
Headers: X-Request-Id, X-Upstream-Deadline, X-Prefix-Hash, X-Router-Lease
Body: JSON { model, prompt, max_tokens, stream, ... }

Streaming relay invariants:

  • Order invariant: bytes forwarded to client in exact order received from backend; no reordering, no buffering beyond flow control.
  • SSE relay: each data: ... chunk forwarded immediately on receipt; [DONE] forwarded then connection closed.
  • Chunked-transfer relay: chunk boundaries preserved; no re-chunking.
  • On backend mid-stream disconnect: if request.idempotent → attempt hedge/retry on new backend from token 0 (no partial replay); else → send SSE data: {"error":"upstream_disconnect"} then close.

Retry policy:

Attempt Delay Condition
1 (initial) 0 —
2 50 ms jitter 5xx, connect_err, timeout; only if idempotent=true or retryable_error
3 200 ms jitter same; new backend selected
4+ rejected retries_exhausted → FAILED

Hedging (speculative execution):

  • Enabled only if request.idempotent=true AND p99_ttft > slo.ttft_ms * 0.8 (configurable threshold).
  • Hedge fires after hedge_delay = ewma_ttft_ms * 1.5 ms on a second backend.
  • First response wins; second request cancelled via HTTP/2 RST_STREAM.
  • At-most-once invariant: hedging is ONLY permitted for idempotent requests.

Circuit breaker per BackendId:

States: Closed → Open → HalfOpen
Closed  : normal dispatch; trip on consecutive_failures >= threshold (default 5)
Open    : all requests to backend fail-fast; timeout = 10s
HalfOpen: allow 1 probe request; success → Closed; failure → Open (reset timer)

8.9 Disaggregated Prefill/Decode Coordination

Applies when backend fleet supports disaggregation (e.g., DistServe-style split prefill/decode nodes).

Model:

  • PrefillReplica: optimized for high-throughput prompt ingestion (large batch, high MFU).
  • DecodeReplica: optimized for low-latency token streaming (smaller batch, KV cache resident).
  • KV cache transfer: prefill node sends KV blocks to decode node over RDMA/NVLink or TCP fallback.

Routing for disaggregated requests — applies only when model.disaggregated_mode is set; unified (non-disaggregated) models skip this table entirely and use the standard §8.7 decision procedure:

Step Action On failure
1 Select prefill_backend from PrefillReplicas via the §8.7 decision procedure (reason: LeastLoad) No prefill candidate → route_failed
2 Select decode_backend from DecodeReplicas via the §8.7 decision procedure (reason: KvAffinity) No decode candidate → route_failed
3 Dispatch prompt to prefill_backend; receive opaque KV-transfer-token Prefill fails → retry on a new prefill_backend (idempotent step)
4 Forward (prompt_ref, kv_token) to decode_backend; stream tokens to client Decode fails post-transfer → route_failed (KV blocks are not re-transferable without cost)

Coordination invariants:

  • Lease covers BOTH prefill and decode phases; released only after decode completes.
  • KV transfer token is opaque to infr-route; treated as bytes forwarded to decode backend.
  • infr-sched emits autoscale signals independently for prefill pool and decode pool.

8.10 Autoscaling Signal Model

infr-sched emits AutoscaleSignal events consumed by external orchestrators (Kubernetes HPA, Ray autoscaler):

AutoscaleSignal {
  model          : ModelId
  replica_class  : ReplicaClass   -- {Prefill, Decode, Combined}
  current_count  : u32
  desired_count  : u32
  reason         : ScaleReason    -- {queue_depth, slo_miss_rate, kv_util, idle}
  timestamp      : Instant
}

Scale-out triggers:

Metric Threshold Action
avg_queue_depth > 10 for 30 s scale_out by ceil(queue_depth / target_queue_depth)
slo_miss_rate (TTFT) > 5% over 60 s scale_out by 1
avg_kv_util > 0.85 for 60 s scale_out by 1
p99_ttft_ms > slo.ttft_ms * 1.2 scale_out by 1

Scale-in triggers:

Metric Threshold Action
avg_queue_depth < 2 for 300 s scale_in by 1 (keep min_replicas)
avg_kv_util < 0.3 for 300 s scale_in by 1
No traffic 600 s scale_in to min_replicas

Cooldown: 120 s between consecutive scale actions per model (prevents thrash).

BackendConfig { addr: SocketAddr, model: ModelId, adapters: Vec<AdapterId>, max_conns: u32 }

Reload invariants:

  • Config is validated before applying; invalid config → reload rejected, old config retained.
  • New backends added: registered in infr-registry, health probed before routing eligible.
  • Removed backends: drained (no new requests), existing Leases allowed to complete, then removed.
  • Weight changes: applied immediately to next routing decision; in-flight requests unaffected.
  • Queue-max reduction: new arrivals bounded by new max; existing queue not truncated.

Example A — Normal streaming request (cold prefix)

T=0ms  client POST /v1/completions {model="llama3-70b", stream=true}

T=45ms infr-ingress: begin SSE relay to client
T=800ms last token; SSE [DONE]; Lease released; PrefixTree.insert(ab12.., Backend 2)

Example D — Backend ejection mid-stream

Backend 3 returns 500 on 5 consecutive requests → Health: Healthy→Degraded
After 5 more failures → Health: Degraded→Ejected
infr-route: Backend 3 removed from candidate set (Health invariant enforced)

Circuit breaker: Open for Backend 3, 10s timeout

Example F — Disaggregated prefill/decode

Request dispatched to PrefillReplica(id=10)

Example G — Hedge firing

Request idempotent=true, slo.ttft_ms=100
ewma_ttft_ms for Backend 4 = 80ms; hedge_delay = 80*1.5 = 120ms
Primary dispatch → Backend 4 at T=0
At T=120ms: no first token yet; hedge fires → Backend 5
Backend 5 returns first token at T=135ms (Backend 4 still pending)
Backend 5 wins; Backend 4 RST_STREAM sent
Client receives tokens from Backend 5
