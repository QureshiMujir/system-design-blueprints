⬜ Phase 0 — Skeleton — crates, core types, reverse proxy that forwards one request to one static backend and relays the response (no routing logic) §12

Objectives
  • Establish full Cargo workspace with all 11 spine crates (infr-core, infr-ingress, infr-registry, infr-health, infr-route, infr-queue, infr-dispatch, infr-sched, infr-telemetry, infr-cli, infr-bench); each crate compiles.
  • Define every canonical core type in infr-core exactly as per spine: RequestId(Ulid), Request, BackendId(u32), Replica, LoadState, RoutingDecision, Slo, Priority, Lease, InferError; all with #[derive(Debug, Clone, PartialEq, Eq)] and serde.
  • Implement minimal working path: single static backend in config → infr-ingress accepts one HTTP request → infr-dispatch forwards it → streams response back to client → exits cleanly.
  • Constraint: no routing policy logic, no health checks, no queuing, no telemetry aggregation — just plumbing.
  • MSRV 1.78, edition 2021, #![forbid(unsafe_code)] in all crates except where FFI is explicitly noted.
Deliverable

  • cargo run -p infr-cli -- serve starts, listens on :8080, forwards all requests to $INFR_BACKEND_ADDR.
  • Any HTTP/1.1 POST reaches the backend verbatim; response (including chunked streaming) relayed byte-for-byte.
  • cargo test --workspace passes; 3 integration tests green.
  • Operators can confirm behavior via INFR_LISTEN_ADDR, INFR_BACKEND_ADDR env vars + server log line at startup.

Pitfalls
  • Hyper body consumption double-read — reading body for logging then forwarding: body stream is consumed on first read. Root cause: hyper::body::Incoming is single-pass. Debug: response body empty at client. Fix: axum::body::to_bytes then re-wrap in http_body_util::Full; signal via ingress_body_buffer_bytes counter.
  • MSRV breakage from transitive deps — ulid or hyper-util may require newer Rust. Root cause: Cargo.lock resolves latest patch. Debug: cargo +1.78.0 check. Fix: pin transitive deps to MSRV-compatible versions in workspace Cargo.toml.
  • Chunked transfer encoding double-wrap — axum re-encodes already-chunked backend response. Root cause: setting Transfer-Encoding: chunked header while also using axum::body::Body stream. Debug: garbled client response. Fix: strip TE header before relay; let hyper handle framing.
  • SIGTERM vs SIGINT race on shutdown — axum::serve::with_graceful_shutdown waits for all connections; if backend is slow the router hangs. Debug: process stuck at shutdown. Fix: add shutdown deadline (5 s default, INFR_SHUTDOWN_TIMEOUT_MS); force-close after.
  • Ulid monotonicity skew under test parallelism — concurrent test threads calling Ulid::new() at the same millisecond can produce same Ulid. Root cause: monotonic counter resets per thread. Fix: use ulid::Generator with mutex per test thread; assert uniqueness in test.
  • Response header forwarding stripping content-length — axum strips content-length when body is stream. Root cause: mismatched framing. Debug: client sees content-length: 0. Fix: preserve original header only when body is fully buffered; else omit and let chunked flow.

Pitfalls
  • gRPC trailer frames dropped — gRPC uses HTTP/2 HEADERS frame with END_STREAM as trailers; hyper/axum may not relay trailers. Root cause: http::Response body does not expose trailers. Debug: grpc client sees unknown error. Fix: use hyper::body::Body::trailers() explicitly; wrap in axum::body::Body::new.
  • SSE flush starvation — TCP Nagle delays small SSE frames. Root cause: write() coalesces < 512-byte frames. Debug: high perceived TTFT despite fast backend. Fix: set TCP_NODELAY on accepted sockets; axum::body::Body writer flushes on each frame.
  • Prefix hash collision across models — same prompt bytes with different model → same PrefixHash; Phase 1 FNV-64 does not include ModelId. Root cause: hash input omits model. Fix in Phase 1: hash = fnv64(model_id_bytes ++ prompt_prefix_bytes).
  • Content-Length mismatch on stream — backend sends Content-Length: N but streams tokens; relay forwards header; client may cut off early. Root cause: content-length inaccurate for streaming. Fix: strip Content-Length header when stream=true.
  • H2 WINDOW_UPDATE deadlock — large request body + slow backend; client's h2 flow control window exhausted, blocks. Root cause: h2 default window 65 535 bytes. Fix: increase via hyper_util::server::conn::auto::Builder → http2_initial_connection_window_size(1<<20).
  • Timeout tower layer position — if Timeout wraps only handler (not connection), a slow client sending body can consume connection indefinitely. Root cause: tower::timeout::Timeout starts after body fully received. Fix: set axum::serve tcp_keepalive + http1_header_read_timeout on hyper builder.
  • In-flight counter leak on panic — InFlightGuard drop not called if handler panics without catch-unwind. Root cause: tokio task panic unwinds before guard drop in some configurations. Fix: CatchPanic layer must be outermost tower layer; verify guard drop in panic test.

Debug: panic in route crate at models_index[model_id]. Fix: validate() checks all refs; ConfigError::UnknownModel.
  • Adapter ID collision across models — two models use same AdapterId string for different LoRA weights; adapter_index maps both to same entry. Root cause: AdapterId is global, not scoped to model. Fix: scope adapter index as HashMap<(ModelId, AdapterId), Vec<BackendId>>; document in ADR.
  • SIGHUP lost during reload — rapid successive SIGHUPs; second signal arrives while first reload still in progress. Root cause: tokio signal stream buffers at most one pending signal. Fix: reload task drains signal stream, coalesces, runs latest config only; AtomicBool::compare_exchange guards re-entrant reload.
