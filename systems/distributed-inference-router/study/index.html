Hard Questions (Self-Examination)

HQ1 — When does increasing max_queue_depth make P99 latency worse, not better? When queue depth exceeds the product of backend throughput and SLO deadline, admitted requests at the back of the queue will always miss their SLO. A deeper queue does not add capacity — it adds latency for requests that will be shed at dispatch anyway (I8 violation). The correct lever is admission control at queue entry (§3.3 infr-queue, Phase 6), not queue depth. Synthesis: §4 System Constraints (SLO bounds) × Failure Modes & Recovery (queue saturation failure class) × Phase 6.

HQ2 — A backend's kv_util probe reads 0.20 (20%) occupied, but P99 TTFT is spiking to 5s. What are the three most likely causes and which infr- crate owns each?* (1) Probe staleness: health probe interval is 5s, backend loaded up between probes; infr-health (Phase 3). (2) KV-cache fragmentation: 20% utilization is global but contiguous blocks for the request's sequence length are unavailable; not detectable by the scalar probe — requires per-sequence block-map exposure from the backend (future work, §Deferred Features Register). (3) Adapter mismatch: request is routed to a backend that is loading the adapter on-demand (cold LoRA load), blocking prefill; infr-registry adapter inventory (Phase 9). Synthesis: §3.5 infr-health × §3.3 infr-registry × Failure Modes & Recovery TTFT spike.

HQ3 — Explain why the PrefixTree must be rebuilt from health probes rather than maintained as durable state. The PrefixTree maps prefix_hash → BackendId set, representing which backends have that prefix hot in their KV cache. KV caches are volatile (evicted on memory pressure, lost on backend restart). A durable PrefixTree would route to a backend whose KV cache no longer holds the prefix, causing a cold-start penalty indistinguishable from a cache miss. The PrefixTree is soft state: if it disagrees with backend reality, the router makes a suboptimal routing decision (not a correctness failure, I6). Rebuilding from health probes (which report kv_util and active prefixes) keeps the tree consistent with actual cache state. Synthesis: I6 (PrefixTree consistency) × §8.5 PrefixTree model × §Scalability Analysis horizontal scaling.

HQ4 — The circuit breaker for BackendId B is in Open state. A new request arrives for a model only served by B. What happens at each layer of the stack? (1) infr-route policy chain: B is filtered from candidates (circuit breaker Open); no candidates remain. (2) infr-queue: request is held if queue not full, awaiting candidate availability. (3) infr-sched: if no HalfOpen probe has been sent in base_ejection_time, schedules a probe for the next eligible request. (4) infr-dispatch: if probe succeeds → Closed; if fails → extends Open with base_ejection_time × ejection_count. (5) If no candidates available and queue deadline exceeded: 503 returned + autoscale signal emitted. Synthesis: Phase 8 circuit-breaker FSM × Phase 6 admission × Phase 11 autoscale signal × Failure Modes (all-backends-ejected failure class).

HQ5 — How does the consistent hashing ring for session affinity interact with the PrefixTree, and which wins when they conflict? Consistent hashing maps prefix_hash → BackendId for session affinity (same prefix → same backend → KV cache hit). The PrefixTree does a longest-match lookup to find which backend has the deepest cached prefix. When they agree, routing is optimal. When they conflict (consistent hash says B1, PrefixTree says B2 has deeper prefix match), the policy is: PrefixTree wins if match_depth > affinity_threshold (configurable). Rationale: a deeper KV-cache hit reduces GPU compute more than affinity preserves — the marginal cost of breaking affinity is a cold miss on a shorter prefix. Synthesis: Phase 4 §16.2 AffinityTable × Phase 5 PrefixTree design × ADR-08 (ULID) × ADR-16 (PrefixHash).

HQ6 — Under what conditions does hedging increase total backend load rather than decrease user-visible P99? Hedging sends a second request speculatively; if both complete, one is wasted. At high backend utilization (kv_util > 0.80), the second dispatch occupies a KV-cache block that could serve a new request, causing higher queue wait for subsequent requests. The HedgePolicy must gate on: idempotent: true AND backend_utilization < hedge_util_threshold (default 0.60). Above the threshold, hedging trades global throughput for individual P99 — a losing trade under overload. Synthesis: Phase 8 §20.2 HedgePolicy × P8 (Tail at Scale) × §4 System Constraints (kv_util targets) × Failure Modes & Recovery.

HQ7 — Why must the Lease watchdog fire on deadline + grace, not just deadline? The lease deadline is the SLO deadline for the request. If the backend is still generating tokens at the deadline, the response is degraded but may still be useful (partial streaming). The grace period allows in-flight streaming to complete delivery before the lease is force-released. Force-releasing at exactly deadline would cancel an in-flight response at the exact moment the first token might arrive. The grace period must be bounded (e.g., 2× estimated TBT) to prevent lease leaks when backends hang silently. Synthesis: I5 (Lease invariant) × §3.7 infr-dispatch × Phase 7 streaming relay × MM1.

HQ8 — A tenant's quota is exhausted mid-stream. What happens to their active streams? The quota gate (infr-sched quota.rs) applies at admission (queue entry). Active streams that have already passed admission are not cancelled mid-stream — doing so would violate I10 (stream order invariant) and produce a corrupted partial response. The correct behavior: active streams complete; quota enforcement prevents new requests from being admitted. This means a tenant can temporarily exceed quota if many requests entered before quota exhaustion. Mitigation: quota accounting should track admitted-but-incomplete requests as consumed quota, not just completed ones. Synthesis: Phase 11 §23.2 quota.rs × I10 (stream order) × Phase 6 admission × MM3.

HQ9 — If the infr-sched fairness loop runs at 100ms epochs and a high-priority request arrives 99ms into an epoch, what is the maximum admission delay? Up to 100ms (one full epoch) in the worst case, plus queue service time. For latency-sensitive requests (e.g., interactive chat with 200ms TTFT SLO), a 100ms scheduling epoch is 50% of the SLO budget. Mitigation: priority-bypass path — requests with Priority::Critical skip the fairness epoch and are admitted directly to the per-model priority queue without waiting for the next epoch. Synthesis: Phase 11 §23.2 fairness.rs × I8 (SLO deadline admission) × §4 System Constraints (TTFT ≤200ms) × §Scalability Analysis scheduler saturation.

HQ10 — How does the registry single-writer invariant (I1) prevent a torn read, and what is the consequence of violating it? I1 mandates that only infr-registry's writer task may mutate the registry state. The reader sees a complete Arc snapshot via ArcSwap — either the old state or the new state, never a partially-updated state. If two writers race (violating I1), they could produce an intermediate state where a replica is present in the BackendId list but its AdapterInventory has not yet been updated. A router reading this intermediate state routes an adapter request to a backend that doesn't serve the adapter, causing a 4xx or silent wrong-model response. Synthesis: I1 × MM8 × Phase 2, §3.5 infr-registry × ADR-14 (RwLock choice).

HQ11 — Describe the sequence of events that leads from a KV-cache eviction storm on backend B to a 503 cascade, naming each infr- crate involved.* (1) B's KV cache is under memory pressure; evicts cached prefixes to free blocks. (2) infr-health (Phase 3) probes B; kv_util returns >0.95 → Health::Degraded. (3) infr-registry updates B's LoadState; PrefixTree removes B's entries (Phase 5). (4) infr-route redirects all prefix-matched requests to other backends. (5) Those backends now receive elevated load; their KV caches also begin evicting. (6) A cascading health degradation across the fleet; infr-health marks all as Degraded. (7) infr-route finds no Healthy candidates; returns 503. (8) infr-sched emits autoscale signal (scale out). (9) New backends take 5–10 minutes to warm up; cascade persists until warm. Synthesis: Failure Modes & Recovery (KV eviction storm) × Phase 3 × Phase 5 × Phase 8 × Phase 11 × MM2.

HQ12 — What is the correct behavior when the disaggregated prefill backend completes but the decode backend is unavailable for KV handoff? The prefill result (KV blocks) are generated but cannot be transferred to a decode backend. Options: (1) Hold the KV blocks on the prefill backend and retry decode assignment (bounded by SLO deadline); (2) Fall back to unified prefill+decode on the prefill backend if it supports it; (3) Fail the request with 503 and release KV blocks. The correct choice per §22.4: retry decode assignment for up to kv_handoff_timeout (10ms); if no decode backend available, fall back to unified mode on the prefill backend. Synthesis: Phase 10 §22.2 KV handoff × §22.4 acceptance criteria × P5 (Splitwise) × Failure Modes & Recovery disaggregated coordination failure.

HQ13 — Why does telemetry cardinality at (model_id, adapter_id, backend_id, route_reason) explode and what is the principled mitigation? At 1k models × 10 adapters × 500 backends × 6 route_reason variants = 30M label combinations. Prometheus TSDB stores one time series per label set; 30M active series would consume ~30 GB of RAM in the scraper. Principled mitigation: aggregate at the router level. Expose per-model and per-adapter metrics (not per-backend) on the /metrics endpoint. Expose per-backend metrics only on a debug /metrics/debug endpoint not scraped by production Prometheus. Retain route_reason as a label on the router-level series (1k × 10 × 6 = 60k series — manageable). Synthesis: §Scalability Analysis (telemetry cardinality) × Phase 13 §25.4 telemetry × §4 System Constraints × P9 (FIFO Queues cardinality note).

HQ14 — Under a network partition where the router cannot reach any health probes for 30 seconds, what routing decisions does the system make and why? infr-health stops receiving probe responses; it does not immediately mark backends Unhealthy — it applies a health-probe timeout threshold (e.g., 3 consecutive missed probes = Degraded, 5 = Unknown). During the partition, the router continues routing based on stale health state (last known LoadState). Backends in Closed circuit breaker state receive traffic; if they are genuinely down, dispatch will fail (timeout → circuit breaker transition to Open). After partition heals, health probes recover and state is updated. The key invariant: stale health state causes suboptimal routing, not correctness failure (I6 analogy for health). Synthesis: Phase 3 §3.5 infr-health × Phase 8 circuit-breaker FSM × Failure Modes & Recovery health probe partition × MM4.

HQ15 — How does the EWMA smoothing factor for load state affect routing stability versus responsiveness? EWMA: load_ema = α × current_load + (1-α) × load_ema. High α (→1.0): responsive to spikes but noisy — a single bursty second causes routing changes that may reverse immediately, producing oscillation. Low α (→0.0): smooth but slow — a backend that becomes overloaded is still sent traffic for many seconds while EMA catches up. The correct α depends on the probe interval: for 1 Hz probes, α=0.3 gives a ~3-probe settling time (3s responsiveness). For 10 Hz probes, α=0.1 gives the same settling time. The wrong α causes either thundering-herd (high α, many routers simultaneously route away from a backend) or delayed-overload (low α). Synthesis: Phase 2, §3.5 infr-registry LoadState × §8.5 PrefixTree model × §Scalability Analysis replication pressure.

HQ16 — What prevents the admit-from-queue fairness loop from starving low-priority requests indefinitely? The fairness loop (infr-sched fairness.rs) uses weighted fair queuing: each priority tier receives a quota of admits per epoch proportional to its weight, not a strict priority ordering. A Critical request does not prevent a Normal request from being admitted if the Critical quota for this epoch is already filled. Additionally, requests carry a maximum queue age (derived from SLO deadline): if a Normal request has been queued beyond its age limit, it is shed (429) rather than starved indefinitely, which prevents unbounded queue age growth. Synthesis: Phase 11 §23.2 fairness.rs × Phase 6 §3.3 infr-queue shed policy × I4 (bounded-queue) × I8 (SLO deadline admission).

HQ17 — Name three observable signals that distinguish "router is overloaded" from "backend fleet is overloaded." (1) router_queue_depth_p99 > 0 and backend_kv_util_p50 < 0.50: router is queuing requests while backends are underutilized — router admission or routing logic is the bottleneck, not backend capacity. (2) lease_acquire_latency_us_p99 > 1000 with low backend latency: Lease contention inside infr-dispatch is the bottleneck (router-side). (3) dispatch_retry_rate > 5% with all backends Healthy: router is dispatching and backends are rejecting (429/503) — backend admission is the bottleneck, not router. Synthesis: Phase 13 §25.4 telemetry × §Performance Engineering (M1–M10) × Failure Modes & Recovery × MM1.

Mental Models & First Principles

MM1 — The Router Is a Lease Manager, Not a Proxy Compressed insight: Every in-flight request is a lease on one backend slot. The router's core invariant is not "forward packets" but "every lease is eventually released exactly once." Prediction: any latency spike that cannot be explained by network or GPU time is a lease acquisition bottleneck — measure lease_acquire_latency_us, not just end-to-end P99. Bug class: Lease leak (I5 violation) manifests as monotonically growing inflight_gauge diverging from actual backend load; backend appears overloaded while queue is empty. Resolving §: §3.7 infr-dispatch (Lease), §7 Invariants (I5), Phase 3.

MM2 — KV-Cache Hit Is a Routing Constraint, Not an Optimization Compressed insight: When prefix-cache hit rate drops below 50%, the router degrades to a load-balancer — this is a qualitative regime change, not a gradual degradation. The PrefixTree is the tightest feedback loop between prompt structure and infrastructure cost. Prediction: a workload with high prefix diversity (random prompts, no system-prompt sharing) will show near-zero KV hit rate and make all PrefixTree logic irrelevant; detect by measuring prefix_match_depth_p50 == 0. Bug class: Eviction storm — when backends are ejected, their PrefixTree entries become stale, causing cold cache routing until the tree is rebuilt; the 5xx storm from ejection can trigger more evictions. Resolving §: Phase 5, §8.5 PrefixTree model, I6, §Scalability Analysis.

MM3 — Admission Control Is the System's Pressure Regulator Compressed insight: A queue with no admission ceiling is an amplifier, not a buffer. Under overload, every request that enters the queue adds latency to all subsequent requests; the correct response is to shed at the boundary (429) and let callers retry with backoff. Prediction: removing the queue_max limit will cause mean latency to grow faster than throughput — the queue depth grows unboundedly while P99 collapses. Bug class: SLO-unaware queuing — admitting a request whose remaining SLO deadline is shorter than the current queue wait (I8 violation) wastes a backend slot that could serve a newer request. Resolving §: Phase 6, §3.3 infr-queue, I4, I8, P1, P6.

MM4 — Circuit Breakers Are State Machines, Not Thresholds Compressed insight: A circuit breaker that only checks "error rate > X" in the last N requests is a reactive threshold. The FSM (Closed → Open → HalfOpen → Closed/Open) provides memory: it prevents a flapping backend from generating repeated error storms during HalfOpen probing. Prediction: a backend that intermittently recovers will cause threshold-only breakers to oscillate; the HalfOpen probe-single-request gate prevents this. Bug class: HalfOpen deadlock — if the probe request itself times out (no response), the breaker must transition back to Open, not stay HalfOpen indefinitely; timer-driven HalfOpen expiry required. Resolving §: Phase 8, §7.10 circuit-breaker FSM, ADR-04 (Envoy outlier detection reference), R4.

MM5 — Hedging Is an At-Most-Once Constraint, Not a Retry Compressed insight: Hedging dispatches a second request speculatively before the first times out; this is fundamentally different from retry (which fires after failure). The at-most-once invariant (I3) means hedging is only legal for idempotent: true requests. The hedge budget (P2) constrains how many requests can have a simultaneous second dispatch. Prediction: mis-applying hedging to non-idempotent requests (e.g., stateful generation with tool calls) causes double-execution; guarded by idempotent: bool check at HedgePolicy gate. Bug class: Double-billing — a hedged request that both replicas complete causes two inference costs but one API charge; cancel the slow replica's connection immediately on first response. Resolving §: Phase 8 §20.2 HedgePolicy, P2 (at-most-once), I3, ADR-15.

MM6 — The Router Must Never Directly Scale Compressed insight: The router emits autoscaling signals (queue depth, TTFT P99, KV utilization) but must never call Kubernetes APIs directly. This preserves separation of concerns: the router observes, the autoscaler decides, the scheduler executes. Prediction: a router that directly patches HPA replicas will race with the Kubernetes control plane under topology changes, causing oscillation. Bug class: Signal amplification — emitting autoscale signals at per-request granularity (rather than per-model debounced) floods the autoscaler with redundant events; debounce to 1 Hz per model. Resolving §: Phase 11 §23.2 batch_hint.rs, P13 (autoscaling signal design), ADR-23, §Operational Readiness.

MM7 — Streaming Relay Correctness Is Flow-Control, Not Forwarding Compressed insight: Token streaming relay is not memcpy — it must respect H2 flow-control windows (I10), release capacity after each DATA frame, and handle mid-stream backend failure by either closing the stream or inserting an error frame. Prediction: a relay that buffers entire responses before forwarding converts streaming latency into batch latency; TTFT collapses to total-generation-time. Bug class: H2 flow-control deadlock — if the router does not release the H2 receive window after forwarding each DATA frame, the backend stalls waiting for window credit while the client is waiting for tokens. Resolving §: Phase 7, §3.7 infr-dispatch streaming relay, I10, B7 (Computer Networking flow-control).

MM8 — Wait-Free Reads Require Epoch-Based Snapshot Discipline Compressed insight: ArcSwap enables wait-free reads on the routing table (registry snapshot) by having writers publish a new Arc without blocking readers holding the old one. But epoch discipline is required: a writer must not free old state until all readers that could be holding it have advanced their epoch. Prediction: using ArcSwap correctly means routing decisions never block on registry updates — measure registry_lock_contention_us should be zero in steady state. Bug class: Torn read — if the registry is updated in two steps (replica added, then adapter map updated) without atomic snapshot replacement, a reader can see a replica without its adapter inventory, causing dispatch to a backend that doesn't serve the requested adapter. Resolving §: Phase 2, §3.5 infr-registry, I1 (single-writer registry), ADR-14.

Glossary · 51 terms · site-wide glossary

Admission control
Gate before queue entry; rejects or backpressures requests when queue is full or SLO deadline already expired at arrival. Implemented in infr-queue.
AdapterId
Opaque newtype (String) identifying a LoRA/PEFT fine-tune adapter loaded onto one or more replicas. Distinct from ModelId (base weights).
At-most-once
Dispatch invariant: non-idempotent Request reaches exactly one backend; hedging forbidden unless idempotent: true. Prevents double-charging or duplicate state mutation.
Autoscaling signal
Scalar or event emitted by infr-sched to an external HPA/cluster-autoscaler; carries queue depth, TTFT p99, and KV utilization. Does not directly scale; only advises.
BackendId
Newtype (u32); stable identifier for a Replica within the registry. Reused on restart if address is same; new id on re-registration after eviction.
Backpressure
Flow-control mechanism: when infr-queue is saturated, infr-ingress pauses token reading on the TCP/HTTP/2 stream rather than allocating more memory.
Batching hint
Advisory from infr-sched to a backend suggesting it combine N queued requests in one forward pass (continuous batching); backend may ignore.
Bounded-queue invariant
All queues in infr-queue have a fixed max capacity; saturation triggers shedding or backpressure, never heap growth. Prevents OOM under spike load.
Circuit breaker
State machine in infr-dispatch with states Closed/Open/Half-Open; trips on consecutive errors or latency breach; prevents request storms to a failing backend.
Consistent hashing
Hash ring mapping ModelId + session_key -> BackendId; minimizes remapping when replicas are added/removed; one policy in infr-route.
Continuous batching
LLM serving technique (Orca, 2022) where the forward pass is executed continuously and new requests join mid-batch at iteration boundaries, maximizing GPU utilization without fixed batch windows.
Decision auditability
Every RoutingDecision carries a RouteReason variant; logged to infr-telemetry enabling post-hoc analysis of routing choices per request.
Decode phase
Second phase of LLM inference; autoregressive per-token generation using KV cache built in prefill; typically memory-bandwidth-bound, lower compute intensity.
Disaggregation
Architecture (DistServe/Splitwise) separating prefill and decode onto different GPU pools; router must coordinate handoff of KV-cache state between prefill-replica and decode-replica.
EWMA load
Exponentially-weighted moving average of a metric (e.g., TTFT, queue depth); infr-health computes with configurable half-life; dampens transient spikes in routing decisions.
Ejection
Outlier-ejection: replica transitions Health::Ejected after consecutive errors or latency outlier detection; no requests routed to it until recovery timer expires.
Fairness
Policy in infr-sched ensuring no tenant/model starves; implemented via weighted fair queuing or token-bucket per tenant.
Graceful drain
infr-ingress shutdown mode: stop accepting new connections, wait for inflight requests to complete up to drain timeout, then close; preserves streaming clients.
Hedging
Speculative retry: send duplicate request to second backend after hedge delay; only legal when Request.idempotent == true; cancel slower response on first completion.
Health
Enum { Healthy, Degraded, Ejected } per Replica; drives routing eligibility. Degraded still routes but with penalty weight; Ejected is fully excluded.
Health invariant
Requests are never dispatched to Health::Ejected replicas; enforced in infr-route before issuing RoutingDecision.
Idempotency
Request.idempotent: bool; when true, hedging and safe retry allowed; when false, at-most-once enforced. Caller asserts; router does not verify semantics.
InferError
Enum of error variants: Timeout, BackendUnavailable, ModelNotLoaded, AdapterNotLoaded, StreamBroken, RateLimited, InternalError, QueueFull.
infr-core
Root crate exporting all shared types; no I/O, no async; all other crates depend on it. Zero transitive deps outside std + serde + ulid.
KV cache
Key-value attention cache (PagedAttention, vLLM); backends store KV tensors per request; kv_util: f32 in LoadState tracks utilization 0.0–1.0.
Lease
{ request: RequestId, backend: BackendId, deadline: Instant }; held from routing decision until response complete or timeout; freeing updates backend accounting atomically.
Lease invariant
Each admitted request holds exactly one Lease at a time; issuing a second Lease for the same request is a bug; enforced in infr-dispatch.
LoadState
Snapshot of backend load: { queue_depth, kv_util, running_batch, ewma_ttft_ms, inflight }; scraped by infr-health and stored in registry.
LoRA adapter
Low-Rank Adaptation fine-tune weights layered on top of base model; must be loaded on target replica; AdapterId routes to adapter-resident replicas.
ModelId
Newtype (String) identifying base model weights (e.g., "llama3-70b"); foreign key into registry's model->replica map.
Order invariant
Byte order of token stream from backend is preserved to client exactly; infr-dispatch relay must not reorder, merge, or buffer chunks out of order.
Outlier ejection
Detection algorithm comparing a replica's p99 TTFT to fleet mean; if deviation exceeds threshold, transitions replica to Health::Ejected for a penalty interval.
PagedAttention
vLLM memory management (Kwon 2023) dividing KV cache into fixed-size pages; enables fine-grained sharing and eviction; kv_util reflects page pool saturation.
Prefill phase
First LLM inference phase: processes all prompt tokens in one (often parallel) forward pass; compute-bound; produces KV cache; TTFT directly depends on it.
Prefix cache / RadixAttention
SGLang (Zheng 2024) radix-tree structure reusing KV cache segments for shared prompt prefixes across requests; PrefixTree in infr-route maps prefix hashes to backends holding the cache.
PrefixHash
u64 rolling hash of prompt token prefix; computed in infr-ingress; used by infr-route for longest-prefix match against PrefixTree.
PrefixTree
Radix tree token-prefix -> Set<BackendId> with recency metadata; maintained by infr-registry updated on dispatch outcomes; drives prefix-cache-aware routing.
Priority
Enum { RealTime, High, Normal, Batch }; determines queue ordering and SLO enforcement strictness in infr-queue.
RequestId
Newtype (Ulid); monotonic, sortable, globally unique; used as correlation key in logs, traces, and lease tracking.
Replica
Active backend instance: { id: BackendId, model: ModelId, adapters: HashSet<AdapterId>, load: LoadState, health: Health, addr: SocketAddr }.
RouteReason
Enum { LeastLoad, PrefixHit, AdapterResident, SessionAffinity, ConsistentHash, Fallback, Hedged }; attached to every RoutingDecision for auditability.
RoutingDecision
{ backend: BackendId, reason: RouteReason }; output of infr-route policy engine; input to infr-dispatch.
Session affinity
Routing policy binding a client session key (e.g., X-Session-Id) to a consistent backend for KV cache reuse; degrades gracefully to least-load on backend failure.
Shedding
Active request rejection (HTTP 429 / gRPC RESOURCE_EXHAUSTED) when queue is full or deadline already expired; preferred over silent OOM or unbounded latency.
SLO
{ ttft_ms: u32, tpot_ms: u32, deadline: Instant }; per-request service-level objective; infr-queue ages requests and sheds if deadline expires in queue.
SSE
Server-Sent Events; HTTP/1.1 streaming token delivery format; infr-ingress emits data: {token}\n\n chunks from the backend relay.
TTFT
Time-To-First-Token: latency from request receipt to first token byte delivered to client; primary LLM latency SLO metric; tracked as EWMA per backend.
TPOT
Time-Per-Output-Token: inter-token latency during decode phase; secondary SLO metric; computed per request in infr-telemetry.
Tenant
Logical isolation unit for fairness/quota enforcement in infr-sched; identified by header or API key prefix; quota tracked as token-bucket.
vLLM
Open-source LLM inference engine (PagedAttention); primary reference backend implementation; exposes /v1/completions HTTP API compatible with OpenAI spec.
Weighted fair queuing
Scheduling algorithm in infr-sched allocating dispatch slots proportionally to tenant weights; prevents single tenant monopolizing capacity.
