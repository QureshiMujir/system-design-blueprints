Hard questions (§33)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. How does the system avoid exponential blowup when IFDS context-sensitivity meets recursive call chains, and what caps the exploded supergraph? (§17, §7 I8)

  3. What guarantees a WAL replay reconstructs a bit-identical finding set after a worker crash mid-propagation? (§19, §21, §7 I2/I4)
  4. How is field-sensitivity bounded so deeply nested access paths cannot stall the fixpoint solver, and what precision is lost by that bound? (§8, §9 ADR-19, §7 I8)
  5. What happens to in-flight taint facts when a rule hot-reload changes sanitizer semantics mid-analysis? (§18, §7 I7)
  6. Why is call-graph construction (CHA+RTA) a separate phase from points-to analysis instead of a unified pass? (§15, §16, §9 ADR-16/ADR-17)
  7. How does the scheduler distinguish a slow worker from a dead one without triggering a false-positive shard reassignment? (§20, §23 FM-12)
  8. What concrete mechanism prevents split-brain shard ownership under a network partition? (§20, §7 I12, §22 T9)
  9. How does the 8GB memory ceiling constrain the maximum single-shard repository size, and what is the exact derivation? (§4, §32 C1/C10)
  10. Why does the system choose IFDS/IDE over a general abstract-interpretation fixpoint framework? (§9 ADR-18, §30 MM2)
  11. What prevents a malicious rule file from becoming a code-execution vector inside the rule engine? (§18, §22 T6)
  12. How is deterministic replay preserved across a distributed cluster where worker scheduling order can legitimately vary run to run? (§20, §7 I4/I11)
  13. What is the precision cost of Steensgaard mode in IDE quick-check, and where does that surface as downstream false positives? (§16, §9 ADR-17, §31)
  14. How does snapshot compaction avoid write amplification exceeding the 2.5x storage ceiling? (§19, §32 C6)
  15. Why is SARIF chosen over a custom finding format, and what compatibility guarantee does that impose going forward? (§9 ADR-22, §25)

  17. How do access-path k-limiting and heap-region collapsing interact — could over-aggressive collapsing hide a real taint flow? (§16, §18, §9 ADR-19/ADR-24)
  18. What is the minimum cluster width required to analyze a repository at the 15M-LOC/8GB ceiling, and how is it derived? (§4, §32 C10, §29)

30. Mental Models & First Principles

MM1 — Taint is a lattice fact, not a boolean. Predicts: multiple taint kinds compose without separate analysis passes. Bug class without it: conflating Tainted(SQL-context) with Tainted(XSS-context) causes false sanitization across sink kinds. Resolving: §8, §18.

MM2 — IFDS reduces distributive dataflow to graph reachability. (Reps-Horwitz-Sagiv 1995.) Predicts: polynomial complexity bound O(E·D³) instead of naive exponential fixpoint. Bug class without it: a hand-rolled interprocedural fixpoint without summary edges blows up exponentially on deep call chains. Resolving: §5, §17.

MM3 — Points-to precision is a dial, not a switch. (Andersen vs Steensgaard.) Predicts a tunable precision/speed tradeoff exists and should be exposed, not hardcoded. Bug class without it: hardcoding Andersen-only causes OOM on 15M-LOC repos; hardcoding Steensgaard-only causes a false-positive storm at sinks. Resolving: §16, §9 ADR-17.

MM4 — Context sensitivity without call-string bounding diverges. Predicts unbounded call strings on recursive programs blow the exploded graph. Bug class without it: infinite exploded-graph growth on mutually recursive functions. Resolving: §17, §7 I8.

MM5 — A sanitizer is a lattice transformer, not a boolean flag. Predicts partial sanitization (SQL-safe but not HTML-safe) is representable. Bug class without it: a single "sanitized" bit causes false negatives across sink kinds that weren't the sanitizer's target. Resolving: §8, §18.

MM6 — Field-sensitivity is bounded by access-path k-limiting. Predicts a termination guarantee at the cost of merging deep field chains. Bug class without it: unbounded access paths hang the fixpoint on deeply nested structs. Resolving: §9 ADR-19, §16.

MM7 — Crash-only design turns recovery into replay, not repair. Predicts workers can be killed with SIGKILL safely. Bug class without it: ad-hoc cleanup-on-panic code paths introduce the exact state corruption crash-only design exists to prevent. Resolving: §6 P3, §23.

MM8 — Finding identity must survive code churn or CI drowns in noise. Predicts stable hashing keyed on structural path, not line number. Bug class without it: line-number-keyed IDs make every PR look like all-new-plus-all-resolved findings. Resolving: §21, §25.

Reference Implementations

  • Soot + Heros (soot-oss/soot, secure-software-engineering/heros). Study: soot/toolkits/scalar, Heros's IFDSSolver. Lesson: generic IFDS solver architecture reused across analyses. Pitfall: exponential context blowup without summary-edge caching. Applied in §5 / Phase 5 (§17).
  • WALA (wala/WALA). Study: com.ibm.wala.ipa.callgraph, com.ibm.wala.dataflow.IFDS. Lesson: pluggable call-graph construction policies (0-CFA/1-CFA). Pitfall: pointer-analysis precision/scalability tradeoff surfaces as a configuration, not a fixed choice. Applied in §5 / Phase 3–4 (§15–§16).
  • SVF (SVF-tools/SVF). Study: lib/SVF-FE, lib/MSSA. Lesson: sparse value-flow graph (SVFG) avoids re-deriving points-to facts per use. Pitfall: field-sensitivity explosion on template-heavy C++ codebases without region collapsing. Applied in §5 / Phase 4 (§16), ADR-24.
  • CodeQL (github/codeql). Study: javascript/ql/lib/semmle/javascript/security, Python TaintTracking library. Lesson: declarative source/sink/sanitizer config classes. Pitfall: query timeout on deeply recursive predicates without memoization. Applied in §5 / Phase 6 (§18), §31.
  • Facebook Pysa (facebook/pyre-check, dir source/interprocedural_analyses/taint). Study: taint model generators, cross-file summary caching. Lesson: interprocedural summaries make incremental re-analysis tractable. Pitfall: false negatives from unmodeled decorators/dynamic dispatch. Applied in §5 / Phase 7 (§19), §31.
  • DOOP (plast-lab/doop). Study: logic/analyses Datalog rule sets, Souffle backend. Lesson: expressing points-to analysis declaratively simplifies extension. Pitfall: recursive Datalog rules blow up without careful indexing; poor fit for incremental re-analysis. Applied in §5 / §34 AA-4.
  • Joern (joernio/joern). Study: Code Property Graph construction, overflowdb storage. Lesson: one unified graph (AST+CFG+PDG) supports both call-graph and taint queries without separate representations. Pitfall: property-graph query latency degrades on repositories above a few million LOC without indexing discipline. Applied in §5 / §8, Phase 4 (§16).

Glossary (§36) · 55 terms · site-wide glossary

CFG
Control Flow Graph
SSA
Single Static Assignment
IFDS
Interprocedural Finite Distributive Subset (Reps-Horwitz-Sagiv graph-reachability dataflow)
IDE
Interprocedural Distributive Environment (value-valued extension of IFDS)
Exploded Supergraph
IFDS/IDE graph whose nodes are (CFG node, dataflow fact) pairs
PathEdge
IFDS worklist edge from a procedure entry fact to a reachable node fact
SummaryEdge
Cached IFDS edge summarizing a procedure's net effect entry-to-exit
Access Path
Base variable plus a bounded chain of field/index selectors
k-limiting
Bounding access-path depth to guarantee fixpoint termination
Points-to Set
Set of heap regions a pointer/reference may refer to
Andersen Analysis
Inclusion-based points-to analysis via constraint-graph worklist solve
Steensgaard Analysis
Unification-based points-to analysis via union-find
Heap Region
Abstract heap-location grouping (allocation-site or type-based)
CHA
Class Hierarchy Analysis — conservative call-graph construction from type hierarchy
RTA
Rapid Type Analysis — call-graph refinement using instantiated-type sets
Call Graph
Graph of caller-to-callee edges across the whole program
Devirtualization
Resolving a virtual/dynamic dispatch call site to concrete targets
Context-sensitivity
Distinguishing dataflow facts by calling context (e.g. call string)
Field-sensitivity
Distinguishing dataflow facts by accessed struct/object field
Flow-sensitivity
Distinguishing dataflow facts by program point (vs whole-function summary)
Path-sensitivity
Distinguishing dataflow facts by branch-condition history
Taint Kind
Classification of untrusted data (e.g. UserInput, NetworkResponse)
Taint State
Lattice value: Untainted, Tainted(kind), Sanitized(kind, sanitizer), Unknown
Source
Program point introducing untrusted data
Sink
Security-sensitive operation that must not receive unsanitized taint
Sanitizer
Lattice transformer that neutralizes taint for a specific context
Rule DSL
Declarative language configuring sources/sinks/sanitizers
Finding
A reported source-to-sink flow with severity and path trace
Deduplication
Collapsing findings sharing the same structural path hash
SARIF
Static Analysis Results Interchange Format (OASIS 2.1.0)
WAL
Write-Ahead Log
Replay Epoch
Deterministic execution generation counter
Snapshot
Compacted, checksummed persisted graph/cache state
Merkle Verification
Hash-tree integrity check of a snapshot before replay
Shard
Unit of distributed work assignment (module-partitioned)
Lease
Time-bounded exclusive ownership grant over a shard
Work Stealing
Load-balancing scheme where idle workers pull queued work
Backpressure
Admission control tied to memory/queue quotas
Crash-only Design
Components may terminate abruptly; recovery is always replay, not repair
Fixpoint
A dataflow state that stops changing under repeated application of flow functions
Lattice
Partially ordered set with join/meet used to model dataflow facts
Monotone Framework
Dataflow framework where flow functions are monotone over the lattice
Soundiness
Best-effort soundness stance accepting documented unsoundness for scalability
Distributive Problem
Dataflow problem whose flow functions distribute over set union (IFDS precondition)
Structural Hash
Hash of a finding's structural path, stable across line-number churn
Provenance Metadata
Build-time record of toolchain/commit/dependency identity
SBOM
Software Bill of Materials
Split-brain
Two nodes simultaneously believing they own the same resource
Fencing
Forcibly revoking a stale owner's access to a resource
Object-sensitivity
Context abstraction keyed on the allocation site of the receiver object
Code Property Graph
Unified AST+CFG+PDG graph representation (Yamaguchi et al. 2014)
mTLS
Mutual TLS — both peers authenticate each other's certificate
Epoch Budget
Bound on propagation rounds preventing non-terminating oscillation
Region Collapsing
Merging heap regions to bound points-to set growth
Thin Slicing
Restricting a program slice to direct data-dependence chains (Tripp et al. 2009)
