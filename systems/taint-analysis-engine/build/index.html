⬜ Phase 0 — Repository Bootstrap & Deterministic Build Infrastructure §12

Objectives

Establish a reproducible repository structure, CI/CD, deterministic builds, tracing scaffolding, fixture harness, and replay-safe execution primitives — the correctness kernel every later phase depends on.

Deliverable

Reproducible Cargo workspace; deterministic test harness; CI pipeline (ci.yml); trace-enabled empty binary (crates/cli).

Acceptance
  • Byte-identical release builds across 2 independent CI runs of the same commit.
  • All CI checks (lint, test, SBOM) pass.
  • Replay IDs deterministic: 100/100 identical session-ID hash given identical seed input, validated against fixtures/bootstrap/replay-order.jsonl.
Fixtures
  • fixtures/bootstrap/minimal-project/ — smallest buildable workspace.
  • fixtures/bootstrap/replay-order.jsonl — 100-run replay-ID determinism corpus.
Pitfalls
  • Nondeterministic timestamps embedded in build artifacts.
  • Unstable hash-map iteration order leaking into serialized output.
  • Trace-span cardinality explosion at startup (T5).

⬜ Phase 1 — Frontend: Parsing, AST Normalization & Symbol Resolution §13

Objectives

Implement resilient multi-language parser frontends (tree-sitter, ADR-10) and a normalized, canonical AST with symbol resolution, per Aho/Lam/Sethi/Ullman parsing theory (§5).

Deliverable

Multi-file AST generation with deterministic serialization; parser epoch versioning (I14) live.

Acceptance
  • Parse a 1M-LOC fixture corpus without crash or unbounded recursion (T1).
  • AST hash stable across 10 repeated parses of the same input (I1-adjacent determinism).
  • Malformed-unicode fixture downgrades to Unknown trust rather than panicking.
Fixtures
  • fixtures/parser/malformed-unicode.src
  • fixtures/parser/incomplete-class.src
  • fixtures/parser/recursive-template.src
Pitfalls
  • Parser ambiguity silently resolved instead of downgraded (violates P11).
  • AST node explosion on generated/templated code.
  • Invalid byte offsets from incremental tree-sitter edits.

⬜ Phase 2 — CFG Construction & SSA Lowering §14

Objectives

Lower canonical AST into control-flow graphs and Cytron-et-al. (1991) minimal-phi SSA form, validated against I1.

Deliverable

Validated SSA IR exportable to Protobuf (ADR-03).

Acceptance
  • Zero SSA validation failures (I1) across a 500-function fixture corpus.
  • Irreducible-CFG fixture resolved via node splitting, not rejected.
Fixtures
  • fixtures/ssa/irreducible-cfg.ir
  • fixtures/ssa/nested-exception.ir
  • fixtures/ssa/recursive-fn.ir
Pitfalls
  • Malformed dominance trees on irreducible loops.
  • Phi-node explosion on wide switch/match statements.

⬜ Phase 3 — Call-Graph Construction (CHA/RTA + Interprocedural Edges) §15

Objectives

Build the interprocedural call graph via Class Hierarchy Analysis refined by Rapid Type Analysis (ADR-16; Dean/Grove/Chambers 1995, Bacon/Sweeney 1996 — §5), resolving virtual dispatch with fail-closed confidence tagging (P11).

Deliverable

Sealed, queryable call graph (crates/callgraph-engine) with Exact/Devirtualized/Unknown confidence per edge.

Acceptance
  • Call-graph edge count within 1.3x of an RTA-reference oracle on the fixture corpus.
  • Reflection/dynamic-dispatch fixture flagged Unknown, never silently dropped (P11).
Fixtures
  • fixtures/callgraph/polymorphic-dispatch.ir
  • fixtures/callgraph/reflection-call.ir
Pitfalls
  • Over-approximation inflating edge count beyond usable precision.
  • Missed dynamic-dispatch targets silently narrowing coverage instead of flagging Unknown.

⬜ Phase 4 — Points-To / Alias Analysis (Andersen & Steensgaard Engines) §16

Objectives

Implement dual points-to engines — Andersen inclusion-based (Andersen 1994 thesis, §5) for precision and Steensgaard unification-based (Steensgaard 1996 POPL, §5) for speed — selectable per analysis profile (ADR-17).

Deliverable

Queryable, immutable points-to store keyed by AccessPath (crates/pointsto-engine).

Acceptance
  • Andersen mode converges on a 1M-LOC fixture in ≤90s (M4, §28).
  • Steensgaard mode converges on the same fixture in ≤9s (M5, §28).
  • Alias-correctness fixture passes under both engines with matching alias-pair verdicts.
Fixtures
  • fixtures/pointsto/recursive-alias-chain.ir
  • fixtures/pointsto/andersen-vs-steensgaard.diff
Pitfalls
  • Constraint-graph amplification from naive inclusion propagation.
  • Alias over-approximation cascading into sink false positives downstream (Phase 5, §17).

⬜ Phase 5 — IFDS/IDE Dataflow Solver & Taint Lattice §17

Objectives

Implement a Heros-style IFDS solver (Reps-Horwitz-Sagiv 1995) generalized to IDE (Sagiv-Reps- Horwitz 1996) over the taint lattice (§8), with the exploded supergraph and PathEdge/SummaryEdge worklist (§11).

Deliverable

Working IFDS/IDE taint engine (crates/taint-runtime) with deterministic replay support (I4).

Acceptance
  • Deterministic findings across 100 replay runs — bit-identical output hash (I4).
  • SQL-injection, XSS, SSRF, and command-injection fixtures all resolve the expected verdict.
Fixtures
  • fixtures/taint/sql-injection.case
  • fixtures/taint/xss.case
  • fixtures/taint/ssrf.case
  • fixtures/taint/command-injection.case
Pitfalls
  • Propagation oscillation from a non-monotone lattice violation.
  • Sanitizer under-modeling causing false negatives (P9 violation).

⬜ Phase 6 — Source/Sink/Sanitizer Rule Engine & Access-Path Abstraction §18

Objectives

Implement the declarative rule DSL for sources/sinks/sanitizers (ADR-20) and access-path k-limiting (ADR-19, I8), citing Tripp et al. 2009 TAJ (§5) for the abstraction design.

Deliverable

Rule engine (crates/rule-engine) with declarative DSL parser and hot-reload.

Acceptance
  • Rule reload completes without dropping in-flight propagation facts.
  • A depth-10 nested access-path fixture merges correctly at k=5 (default) without producing an unbounded solve (I8).
Fixtures
  • fixtures/rules/rule-reload.case
  • fixtures/rules/access-path-depth10.case
Pitfalls
  • Rule-loader race conditions during hot-reload (I7 violation risk).
  • Over-aggressive k-limiting merging semantically distinct fields (§30 MM6).

⬜ Phase 7 — Incremental Analysis, Persistent Cache & WAL §19

Objectives

Enable incremental invalidation and a persistent graph/points-to cache backed by RocksDB (ADR-04) and an append-only WAL (ADR-15), per Kleppmann/Petrov (§5).

Deliverable

Incremental analysis across repository changes (crates/storage-engine) — unaffected modules skip re-analysis.

Acceptance
  • Unchanged modules correctly skipped on a repeated-run fixture (0 re-analysis of untouched files).
  • WAL replay recovery completes within 60s (M9, §4/§28).
Fixtures
  • fixtures/incremental/stale-cache-replay.case
  • fixtures/incremental/corrupted-wal.case
Pitfalls
  • Dependency-fingerprint drift causing false cache hits.
  • Stale snapshots surviving a schema migration (I7).

⬜ Phase 8 — Distributed Execution & Sharded Scheduling §20

Objectives

Scale analysis across worker clusters via lease-based shard coordination (ADR-21), surviving worker loss without corrupting global state (P3).

Deliverable

Horizontally scalable cluster execution (crates/scheduler) with lease-fenced shard ownership.

Acceptance
  • Cluster survives a simulated worker loss without duplicate or corrupted shard output (network-partition fixture).
  • Lease collision rate is 0 across a 512-worker simulated fixture (I12).
Fixtures
  • fixtures/distributed/network-partition.case
  • fixtures/distributed/delayed-heartbeat.case
Pitfalls
  • Split-brain scheduling from lease-expiry races (T9).
  • Duplicate shard ownership under coordinator failover.

⬜ Phase 9 — Findings Pipeline, SARIF Export & Deduplication §21

Objectives

Implement normalized finding generation, structural-hash deduplication (P12), and SARIF 2.1.0 export (ADR-22) consumable by CI systems.

Deliverable

SARIF-compliant reports (crates/sarif-exporter) consumable by standard CI security-scanning tooling.

Acceptance
  • SARIF output validates against the SARIF 2.1.0 JSON schema with 0 validation errors.
  • Duplicate-findings fixture collapses to 1 finding per distinct structural path.
Fixtures
  • fixtures/findings/duplicate-findings.case
  • fixtures/findings/malformed-sink-trace.case
Pitfalls
  • Unstable finding hashes from line-number-keyed IDs (P12 violation).
  • Trace truncation losing the sanitizer-application step from the rendered path.
