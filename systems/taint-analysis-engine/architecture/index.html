Client Interfaces — untrusted boundary; protocol normalization, request admission, configuration validation, artifact upload, result streaming; isolates external consumers from internal IR evolution (§25).

Analysis Orchestrator — trusted core; owns deterministic scheduling, replay IDs (I11), cancellation propagation, memory quotas (§4), work stealing, concurrency budgeting.

Frontend Pipeline — transforms source programs into normalized SSA-backed IR; parsing recovery, AST canonicalization, symbol resolution, CFG generation, dominance analysis, SSA insertion (Phases 1–2, §13–§14).

Persistence Layer — persistence boundary; stores replay logs, incremental caches, graph snapshots, findings metadata, deterministic execution manifests; crash-recovery guarantees (Phase 7, §19).

Interprocedural Graph Core — concurrency boundary; canonical call graph, points-to graph, heap-region model. All taint propagation traverses these graphs; immutable after sealing (I3, I10).

Taint Propagation Engine — executes IFDS/IDE fixpoint propagation with configurable taint semantics; field sensitivity via access paths, heap abstractions, taint kinds, sanitizer effects, context windows (Phase 5, §17).

Result Processing — normalizes findings, deduplication, severity mapping, sink aggregation, export formatting (Phase 9, §21).

Observability Platform — distributed traces, propagation counters, queue-depth metrics, scheduler diagnostics, heap-pressure visibility, replay correlation (§24).

8. Domain Model / Protocol / Data Model

Core entity chain:

Source -> Propagation Edge (Access Path) -> Sanitizer -> Sink

IR node types (canonical, reused §11, Phase 2 §14, Appendix A):

AssignNode · BranchNode · PhiNode · CallNode · ReturnNode · HeapLoadNode · HeapStoreNode · LiteralNode.

Access-path grammar (EBNF; bounded by I8 to depth k, default k=5, ADR-19):

access_path   ::= base field_chain
base          ::= identifier | "this"
field_chain   ::= ( "." field | "[" index "]" )*
field         ::= identifier
index         ::= identifier | integer | "*"        (* "*" = any-index summary *)

Taint states (lattice, IDE-valued per Sagiv-Reps-Horwitz 1996; ⊥ = Untainted, ⊤ = merged Unknown):

State Meaning
Untainted safe
Tainted(UserInput) attacker-controlled
Sanitized(SQL) escaped for SQL context only
Sanitized(HTML) escaped for HTML context only
Unknown analysis uncertainty (fail-closed, P11)

Propagation sequence (Phase-by-phase, §12–§21):

Parser -> AST -> CFG -> SSA -> CallGraph -> PointsTo -> IFDS/IDE Fixpoint -> Findings -> SARIF

Worked example (SQL injection):

user_input = request.get("id")           // AssignNode, source: HttpRequestParam
query = "SELECT * FROM t WHERE id=" + user_input   // AssignNode, access path: query
execute(query)                            // CallNode, sink: SqlExecute

Detected flow (PathEdge chain through the exploded supergraph, §17):

request.get(HttpRequestParam) --Assign--> query --Call(execute)--> SqlExecute[sink]

State-transition table (sanitizer effect application, Phase 6, §18):

Input State Sanitizer Applied Output State
Tainted(UserInput) SQL_ESCAPE Sanitized(SQL)
Tainted(UserInput) HTML_ESCAPE Sanitized(HTML)
Tainted(UserInput) NONE Tainted(UserInput)
Sanitized(SQL) HTML_ESCAPE (SQL context sink) Sanitized(SQL) (unaffected — not a SQL sink)

Malformed-input example: unresolved dynamic dispatch on execute (reflection) — analysis emits Tainted(UserInput) at Unknown confidence rather than dropping the edge (P11, T1).

Failure-path example: corrupted AST span on query assignment (parser bomb, T1) — parser epoch (I14) rejects the file, emits a parser_epoch_mismatch_total telemetry event, and the file is quarantined from the shard rather than crashing the worker (FM-5).

Second worked example (reflected XSS, exercising field-sensitive access paths, ADR-19):

resp.headers["X-User"] = request.get("name")      // HeapStoreNode, access path: resp.headers["X-User"]
render_template(resp)                              // CallNode, sink: HttpResponseWrite

Detected flow: request.get(HttpRequestParam) propagates via HeapStoreNode into access path resp.headers["*"] (index summarized under I8 k-limiting) then reaches HttpResponseWrite unsanitized — verdict Tainted(UserInput), distinct sink class from the SQL example, same AccessPath machinery (§11).

Access-path wire layout (Protobuf, ADR-03; forward-compatible per I7):

Field Wire Type Notes
base_node_id fixed64 NodeId of the access-path root
field_tokens repeated string bounded to k entries (I8); overflow merges to "*"
depth uint32 redundant with len(field_tokens), kept for O(1) k-limit checks
taint_state enum TaintState discriminant (§11)
schema_version uint32 I7 versioning; unknown versions trigger compatibility mode

Design principles (§6)

  • P1 — Determinism over throughput. Every analysis run must be replayable from identical inputs. Tradeoff: forgoes nondeterministic work-stealing gains for reproducibility. Operational implication: replay IDs (I11) gate every release. Violate it and CI findings diffs become unauditable noise.
  • P2 — Bounded resource usage. No unbounded queues or recursive traversals. Tradeoff: precision loss via access-path k-limiting (I8, ADR-19). Violate it and a single adversarial repo OOMs the cluster (T7).
  • P3 — Crash-only worker semantics. Workers may terminate abruptly without corrupting global state. Tradeoff: no graceful-shutdown code paths to maintain. Violate it and ad-hoc cleanup introduces the exact corruption crash-only design exists to avoid (§30 MM7).
  • P4 — Immutable graph sealing. Graph mutation prohibited after publication (I3, I10). Tradeoff: incremental updates require new graph generations, not in-place edits. Violate it and concurrent readers observe torn graph state.
  • P5 — Observability by default. Every propagation stage emits metrics and traces. Tradeoff: telemetry cardinality must be actively capped (T5). Violate it and failures are undiagnosable in production.
  • P6 — Explicit ownership. Shared mutable state minimized; graphs are Arc-shared immutable structures. Tradeoff: some structural-sharing overhead vs raw pointers. Violate it and data races reappear despite Rust's borrow checker (unsafe escape hatches).
  • P7 — Replayability first. Reconstructable execution traces mandatory (I4, I11). Tradeoff: WAL write volume scales with propagation event count. Violate it and post-incident forensics is impossible (§23).
  • P8 — Versioned schemas everywhere. Storage and wire evolution must remain compatible (I7, §25). Tradeoff: every schema change carries a migration cost. Violate it and rolling upgrades break mid-fleet.
  • P9 — No hidden sanitizers. Sanitizer effects require explicit declaration in the rule catalog (§18). Tradeoff: unmodeled third-party sanitizers cause false positives until catalogued. Violate it and silent under-sanitization produces false negatives (a security bug in a security tool).
  • P10 — Backpressure everywhere. Queue admission tied to memory quotas (§4). Tradeoff: admission control adds latency under load. Violate it and unbounded queue growth causes FM-4.
  • P11 — Fail closed on parser ambiguity. Ambiguous semantics produce warnings and downgraded trust, never silent best-guess resolution. Tradeoff: more Unknown-taint findings requiring triage. Violate it and a missed dynamic dispatch target becomes a silent false negative.
  • P12 — Stable finding identity. Findings maintain deterministic IDs across runs, keyed on structural path, not line number (§30 MM8). Tradeoff: ID computation requires structural hashing, not a simple counter. Violate it and every CI run looks like all-new findings.
  • P13 — Precision is a dial, not a switch. Points-to and context-sensitivity are configurable per analysis profile (ADR-17). Tradeoff: more configuration surface to test. Violate it and the engine either can't scale (Andersen-only) or can't triage precisely (Steensgaard-only).
  • P14 — Sealed interprocedural summaries over re-derivation. Function summaries are computed once and cached (summary edges, §17), never re-derived per call site. Tradeoff: summary cache invalidation complexity (§19). Violate it and analysis time grows with call-site count instead of function count.
