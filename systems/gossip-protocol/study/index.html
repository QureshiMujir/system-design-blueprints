Mental Models & First Principles

  • MM1 — The view is a CRDT-ish lattice keyed by (incarnation, status-strength). Predicts: every merge is a join on that lattice, so order-of-arrival cannot matter for the final state. Bug class without it: order-dependent merges that diverge under reordering. Applied: Phase 3, I1/I2.
  • MM2 — Incarnation is the only thing that lets a node speak about itself with authority. Predicts: a node can always overrule a stale suspicion by bumping. Bug class without it: a falsely-convicted node that can never recover. Applied: Phase 3 self-refute, I3.
  • MM3 — Failure detection is a statistical bet, not a fact. Predicts: tuning timeouts trades false positives against detection latency along a fixed curve; you cannot have both. Bug class without it: chasing a "zero false positives, instant detection" impossibility. Applied: Phase 4/5, M2/M3.
  • MM4 — Local health is a confession, not an accusation. Predicts: a node that keeps failing probes should suspect itself of being the problem and slow down. Bug class without it: a degraded node convicting the whole cluster (the Lifeguard motivation). Applied: Phase 5, P7, I8.
  • MM5 — Dissemination and detection are separable concerns sharing one packet. Predicts: piggybacking gossip on probes is free bandwidth; the two layers can be reasoned about independently. Bug class without it: conflating "is P alive?" with "what does P know?" and coupling their failure modes. Applied: Phase 4 piggyback, §3.
  • MM6 — Determinism is a property you architect for, not test for. Predicts: one HashMap or one Instant::now() in the core silently destroys reproducibility forever. Bug class without it: Heisenbugs that vanish under the debugger. Applied: P1/P11, I4/I5, Phase 11.
  • MM7 — Anti-entropy is the floor under probabilistic dissemination. Predicts: even if every gossip packet is lost, one reconciliation round closes the gap; dissemination tuning becomes a latency knob, not a correctness one. Bug class without it: a cluster that converges "usually" and silently diverges under loss. Applied: Phase 7, MM3 complement.
  • MM8 — A spanning tree is a flooding graph with the redundant edges turned lazy. Predicts: Plumtree's eager tree + lazy repair gives flooding's reliability at a tree's bandwidth. Bug class without it: either a fragile tree (no repair) or a wasteful flood. Applied: Phase 9, MM5.
  • MM9 — The reclaim window is a clock that resists rebirth. Predicts: a fast crash-restart inside the window must be treated as the same node, not a new one. Bug class without it: a reborn node with a stale incarnation confusing every peer. Applied: Phase 3, I7, I12.
  • MM10 — The outbox makes the protocol a function, not a process. Predicts: (state, input) → (state', outbox) is referentially transparent, so the simulator can drive it exactly like the real transport. Bug class without it: hidden side effects that the simulator cannot observe or replay. Applied: P3, Phase 11.

Required reading (§5)

general

  • Kleppmann, Designing Data-Intensive Applications (2017), Chapter 9 "Consistency and Consensus". The cleanest English-language summary of weak guarantees and gossip dissemination — applied in §2 framing and Phase 3 merge.
  • Cachin, Guerraoui, Rodrigues, Introduction to Reliable and Secure Distributed Programming (2nd ed., 2011). Failure-detector abstractions and the eventually-perfect detector — applied in Phase 4/5 (SWIM/Lifeguard) and Phase 6 (accrual).
  • Tanenbaum & van Steen, Distributed Systems (3rd ed., 2017), epidemic-protocols chapter. Anti-entropy vs rumour-mongering taxonomy — applied in Phase 7 and the Disseminator design.
  • Steen & Tanenbaum on naming and structured overlays (same volume). Partial-view overlay membership — applied in Phase 8 (HyParView).
  • The Rust Programming Language (Klabnik & Nichols) and Rust for Rustaceans (Gjengset). Type-state, trait objects, Send/Sync boundaries — applied in §11 type design and the no-runtime core (P1).
  • Database Internals (Petrov, 2019), the anti-entropy and gossip chapters. Merkle-tree reconciliation and read-repair lineage — applied in Phase 7.
  • Demers et al., Epidemic Algorithms for Replicated Database Maintenance, PODC 1987. Push/pull/push-pull, convergence analysis, infective/susceptible/removed terminology — applied throughout the Disseminator and concretely in Phase 4's piggyback dissemination; the source of P9.
  • Das, Gupta, Motivala, SWIM, DSN 2002. Probe / ack / indirect-probe-via-k-peers, alive/suspect/dead — the Phase 4 baseline; ADR-07.
  • Dadgar, Currey, Phillips, Lifeguard: Local Health Awareness for More Accurate Failure Detection, DSN 2018 workshop + HashiCorp blog. Dogpile suspicion, NACK-driven local health, health-scaled timeout — Phase 5; ADR-07.
  • Hayashibara, Défago, Yared, Katayama, The Phi Accrual Failure Detector, SRDS 2004. Continuously-valued suspicion from inter-arrival distribution — Phase 6; ADR-08.
  • Leitão, Pereira, Rodrigues, HyParView, DSN 2007. Active/passive partial views, ForwardJoin, Shuffle — Phase 8; ADR-11.
  • Leitão, Pereira, Rodrigues, Epidemic Broadcast Trees (Plumtree), SRDS 2007. Eager push + lazy gossip, Graft/Prune — Phase 9; ADR-12.
  • van Renesse, Minsky, Hayden, A Gossip-Style Failure Detection Service, Middleware 1998. The original decoupled gossip failure detector; the lineage to SWIM — §2 and Phase 4 context.
  • Birman, The Promise, and Limitations, of Gossip Protocols, SIGOPS OSR 2007. The failure-mode survey — Threat Model and Failure Modes back-matter.
  • hashicorp/memberlist (MPL-2.0). The most readable production SWIM; state.go (state machine), net_transport.go (transport), security.go (encryption) — mirrored in module naming across Phases 1, 3, 4.
  • hashicorp/serf (MPL-2.0). Sits on memberlist; adds user-event broadcast, operator CLI, convergence detection — informs Phase 9 and Phase 10.
  • apache/cassandra o.a.c.gms.Gossiper (Apache-2.0). The most-deployed gossip on earth; read as counter-example for dead-node reclaim and heartbeat piggyback — Phase 3, Phase 4.
  • akka/akka cluster module (Apache-2.0). Vector-clock-style version vectors — contrasted with incarnation merge in ADR; Phase 3.
  • basho/riak_core gossip (Apache-2.0). Membership-as-substrate integration with a ring KV store — the rank-38 cross-project pattern, informing the Delegate/AntiEntropy contract of §11.5 that rank-38 consumes.
  • etcd-io/raft and lni/dragonboat. The tickable-core + deterministic-test pattern — Phase 11 simulator architecture (shared with rank 39).

Glossary · 58 terms · site-wide glossary

Active view
The set of peers HyParView currently has connections to; probes and broadcasts use it.
AEAD
Authenticated Encryption with Associated Data.
Alive
Status: peer is reachable and responding.
Anti-entropy
Periodic full-state reconciliation between peers.
Ack
A probe acknowledgement confirming reachability.
Bandwidth-delay product
The amount of in-flight data a path holds; the floor for the broadcast LRU history size.
BTreeMap/BTreeSet
Ordered collections used in the core for deterministic iteration (P11, I5).
Conformance bucket
A named group of fixtures with a single Pass/Fail/Deferred outcome.
Dead
Status: peer is permanently unreachable from this node's perspective.
Delegate
The application-supplied callback interface (on_join, on_failed, local_state, …).
Detection latency
Time from a true failure to the cluster declaring the node Dead.
Dogpile
Lifeguard refinement: suspicion timeout shrinks as independent peers confirm.
Eager push
Plumtree's tree-formed push of a broadcast event.
Endpoint
A routable v4/v6 socket address plus bind port.
Envelope
The AEAD wrapper around every UDP datagram.
Epidemic algorithm
A dissemination class spreading information via random pairwise exchanges.
EventId
A 16-byte random identifier for a broadcast user event.
False positive (Dead)
Declaring a live node Dead; bounded by M2.
Fanout
The number of eager peers a full-view node pushes a broadcast to (default 5).
ForwardJoin
HyParView's TTL-bounded join propagation message.
Frame
The outer protobuf oneof carrying any message variant.
Graft
Plumtree control message: switch a lazy peer to eager.
HyParView
Hybrid Partial View; a partial-view membership protocol.
Ihave
Plumtree control message: a list of recently-seen event ids.
Incarnation
Per-node monotonic counter; the refute-only authority signal.
Indirect probe
A probe forwarded via k random peers; the SWIM trick.
In-flight probe
A sent probe awaiting an ack or timeout; bounded by max_in_flight_probes.
Keyring
The list of installed AEAD keys with a rotation index.
Lazy gossip
Plumtree's gossip-formed repair of missed events.
Leaf
A Merkle-tree leaf carrying one membership-or-state entry.
Lifeguard
A SWIM refinement scaling suspicion by local health.
Local health
A node's self-assessment, decremented on probe failure / NACK.
Membership
The cluster's view of which nodes are present and their statuses.
Merge rule
The deterministic function combining inbound state into the local view.
Merkle diff
Reconciliation by hashing a sorted set in a tree and exchanging hashes top-down.
MTU
Maximum transmission unit; the UDP packet budget (mtu_bytes, default 1400).
NACK
A relay's negative acknowledgement: "I tried to reach the target and could not."
NodeId
A UUIDv4 cluster-unique node identifier.
Nonce
The 96-bit per-packet uniqueness value in the AEAD envelope.
Outbox
The struct the core fills with outbound messages, events, persist ops, and observ events.
Passive view
HyParView's larger pool of known-but-not-active peers.
Phi accrual
Hayashibara's continuously-valued failure detector.
Piggyback
Membership deltas carried on probes/acks; the dissemination path.
Plumtree
Epidemic Broadcast Tree (eager push + lazy gossip).
Probe
The basic SWIM "are you alive?" message.
Prune
Plumtree control message: switch an eager peer to lazy.
Push / Pull / Push-Pull
The three Demers dissemination modes.
Reclaim window
The period a Dead node is retained before GC (dead_node_reclaim_timeout).
Refute
A node's self-published incarnation bump in response to a Suspect or Dead.
Self-refute
The merge path that bumps the local incarnation above an observed suspicion.
Shuffle
HyParView's periodic exchange of passive-view subsets.
Status strength
The total order Alive > Suspect > Leaving > Dead used in merge tie-breaks.
Suspect
Status: peer has missed probes; in the suspicion timeout window.
SWIM
Scalable Weakly-consistent Infection-style Process Group Membership.
Tick
The logical-time advance entry point (tick(elapsed)).
TTL
Time-to-live; ForwardJoin and Ihave messages carry one.
UserEvent
An application-level message broadcast via Plumtree.
View
The per-node membership map plus local state and local health.
