⬜ Phase 0 — Repo skeleton, governance, conformance scaffold §12

Objectives
  • Land every governance, build, and conformance artefact so the project "could be open-sourced today" before any protocol line ships.
  • Establish the Cargo workspace, CI pipeline, all 25 ADRs (§9), runbook skeletons, and two conformance fixtures that exercise the runner's wiring without depending on any later phase.
  • Constraint introduced: every crate compiles as a stub only — no protocol logic, no tokio dependency in gossip/gossip-membership (P1 boundary asserted from commit one).
Deliverable

The full repository tree of §10 minus protocol logic; 25 ADR files; the two scaffold conformance fixtures; green CI on Linux x86_64 and macOS aarch64.

Acceptance

make test and make lint return 0 on a fresh checkout; cargo doc --no-deps builds with zero warnings; CI is green on first push. Exit gate: a reviewer clones the repo, runs make test && make lint && make conformance, and gets three zero exit codes with the conformance report showing both scaffold buckets Pass.

Pitfalls

Do not start writing protocol code in Phase 0 — the point is to make every later phase trivial to ship. Do not put the tokio runtime in the protocol crate's Cargo.toml; that contamination is forever (P1). Do not skip the legal/brand/governance packs — retrofitting SPDX headers across eight crates later is a full-day tax.

⬜ Phase 1 — Transport: UDP, TCP, AEAD envelope, keyring §13

Objectives
  • Build the byte-level transport before any protocol logic: a dual-stack (IPv4+IPv6) UDP socket, a short-lived TCP listener (TLS 1.3 when enabled), the AEAD envelope, the rotating keyring, per-peer rate limiting, and the length-delimited framing layer.
  • Constraint introduced: encryption is on by default (P8) — cleartext on the gossip port is a configuration error, never the default path.
Deliverable

gossip-transport crate with envelope, keyring, UDP, TCP, framing, rate-limit; three transport conformance fixtures.

Acceptance

cargo test -p gossip-transport exercises seal+open across all keyring states; the rotation test passes; loss-injection passes; IPv4 and IPv6 round-trip integration tests pass. Exit gate: conformance/transport.report.json Pass (M-trans); keyring rotation demonstrated online without quiescing the cluster.

Fixtures
Fixture Purpose Expected
transport/seal-open-roundtrip.json 1024 random plaintexts all round-trip byte-identical
transport/wrong-key.json ciphertext sealed with K1, keyring has only K2 open rejected (UnknownKeyId)
transport/torn-packet.json ciphertext truncated by 1, 2, 16 bytes all rejected
keyring_rotation.rs install K2, switch primary, remove K1 K1 packets decrypt before removal, rejected after
loss_injection.rs drop 10% UDP framing handles cleanly, no panic
IPv4/IPv6 integration dual-stack round-trip both succeed
Pitfalls

Do not let the nonce counter wrap within a process lifetime (impossible at realistic rates; assert + exit-on-wrap). Do not allow remove to succeed for the primary id (force a primary swap first). Do not assume path MTU is 1500 — some clouds drop to 1400 or below; expose mtu_bytes and document cloud defaults. Do not coalesce UDP packets above the MTU; let the SWIM piggyback selector decide the budget (I14).

Acceptance

⬜ Phase 4 — SWIM probe loop and indirect probe §16

Objectives
  • Implement the core SWIM failure detector: periodic probe of a random peer, ack correlation by sequence number, indirect probe via k relays, suspicion entry, and piggyback dissemination.
Deliverable

swim.rs, indirect.rs, the SWIM conformance bucket.

Acceptance

swim_basic converges within 4 * probe_interval; 50%-loss test produces zero false-positive Dead; crash-to-Dead < 2 s at 99.5% (M3). Exit gate: conformance/swim.report.json Pass (M-swim); M3 detection-latency microbench within target.

⬜ Phase 7 — Anti-entropy via Merkle diff §19

Objectives
  • Implement periodic full-state reconciliation: a TCP round exchanging Merkle root hashes, walking the tree level-by-level on divergence, merging differing leaves for both membership and application user state.
Deliverable

sync.rs, diff.rs, the anti-entropy conformance bucket.

Acceptance

The three fixtures pass; cold-join converges within one interval to a byte-identical view; converged 1000-node bandwidth ≤ 1 KiB/node/round (M5, §4 BoE #6). Exit gate: conformance/anti-entropy.report.json Pass (M-ae).

Fixtures
Fixture Purpose Expected

anti-entropy/diverged-after-loss-converges-in-one-round.json 1% loss divergence converges in one round

Do not hold the membership lock for the whole round — snapshot first (I13). Do not assume the peer's tree uses the same sort order — specify the leaf comparator in the proto and assert on both sides. Do not race a round with a join handshake — serialise per-peer with a per-peer lock.

⬜ Phase 9 — Plumtree broadcast layer §21

Objectives
  • Implement user-event broadcast on top of membership: the eager path forms a spanning tree; the lazy path repairs missing messages via gossip.
Deliverable

plumtree.rs, repair.rs, history.rs, the broadcast conformance bucket.

Acceptance

The three fixtures pass; 1000-node propagation reaches 99% within O(log N) * probe_interval; 5%-loss repair reaches 100% within 2 * lazy_push_interval; flooding uses 5× the bandwidth. Exit gate: conformance/broadcast.report.json Pass (M-bcast).

Do not let the LRU history shrink below the cluster's bandwidth-delay product — a too-small history readmits duplicates (I9). Do not let pending_grafts grow unbounded — prune on delivery and TTL expiry (I11). Do not race on_user_event and on_ihave — the single-threaded step is the contract (P3).

⬜ Phase 11 — Deterministic simulator §23

Objectives
  • Land the simulator — the deliverable that proves correctness. A single-threaded discrete-event scheduler runs N nodes in logical time, injects faults, and asserts invariants across thousands of seeds.
Deliverable

gossip-sim crate, nine scenarios, the invariant suite, report.json.

Acceptance

The nine scenarios pass against a 100-node cluster; the 1024-seed proptest completes in < 30 min wall-clock with zero invariant violations (M7, M8). Exit gate: gossip-sim/report.json Pass.

Deliverable

gossip-jepsen crate, three scenarios, jepsen.yml, the triage runbook.

Acceptance

The three scenarios run end-to-end against a 9-node Compose cluster with all assertions passing; the nightly CI workflow uploads histories. Exit gate: gossip-jepsen/report.json Pass or Deferred (opt-in surface); M9 60-minute partition+kill Pass.

Fixtures
Fixture Purpose Expected

Pitfalls
