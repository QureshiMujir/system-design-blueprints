4. System Constraints

Reference hardware: a single node is a 4-vCPU / 8 GiB cloud instance; the reference cluster is 1,000 such nodes on a 10 Gbps regional network with ~0.5 ms intra-region RTT. All targets below gate Sealed (failing them on reference hardware blocks the release).

Back-of-Envelope Capacity Model

All numbers derived step-by-step from the §4 System Constraints table.

  1. Membership memory at 1,000 nodes. ~1 KiB/peer (NodeState: 16 B id + ~28 B endpoint + 8 B incarnation + 1 B status + 16 B timestamp + ≤512 B meta + map overhead). 1,000 × 1 KiB ≈ 1 MiB core, with BTreeMap overhead and Dead-in-reclaim entries pushing toward the §4 8-MiB ceiling. ✓ within ceiling.
  2. Steady-state probe bandwidth. 1 probe/s × (1,400 B probe + 1,400 B ack) = 2.8 KB/s/node worst-case full MTU; typical probes are far smaller (piggyback ≤ 4 × ~80 B ≈ 320 B), so ~0.8 KB/s/node typical. ✓ under the 5 KB/s/node §4 target.
  3. Indirect-probe amplification. On a timeout, indirect_probe_count = 3 relays each get one probe: 3 × 1,400 B = 4.2 KB burst, but only on the fraction of probes that time out (target ≪ 1% in a healthy cluster), so amortized < 0.1 KB/s/node. ✓
  4. Detection latency. probe_timeout (0.5 s) + 2 × probe_timeout indirect (1.0 s) + suspicion_min (5 s, dogpiled down) ≈ 1.5 s to Suspect + dogpile-shortened confirmation. Process-kill to Dead converges under the §4 < 2 s (99.5%) target once dogpile shortens the window with confirmations. ✓
  5. Convergence after join. O(log N) × probe_interval = log2(1,000) ≈ 10 rounds × 1 s = 10 s for piggyback alone, but the join push-pull seeds the full view in 1 round-trip (< 1 s). ✓ meets M1 via push-pull, not piggyback.
  6. Anti-entropy in-sync round. One root-hash exchange: 32 B hash × 2 directions + framing ≈ 100 B/round, well under the §4 1 KiB/node/round target. ✓
  7. Anti-entropy divergent round. For d divergent leaves over a binary tree of depth log2(1,000) ≈ 10: d × 10 levels × 32 B ≈ 320·d B. At d = 10 divergent nodes, ~3.2 KB — under the 4 MiB anti_entropy_max_bytes cap by three orders of magnitude. ✓
  8. Broadcast propagation. Tree depth O(log N) = 10 rounds; at probe_interval pacing for lazy repair, 99% delivery within 4 × probe_interval = 4 s (M6) is met because eager push is faster than probe-paced (sub-second per hop). ✓
  9. FD budget. 2 UDP sockets (v4/v6) + ≤ 64 short-lived TCP streams = 66 FDs, under the §4 64-TCP budget if we cap concurrent anti-entropy/join streams; enforce a TCP-stream semaphore. ✓ (cap enforced)
  10. HyParView memory at 10,000 nodes. (active 5 + passive 30) × ~1 KiB = 35 KiB, far under the §4 256-KiB partial-view ceiling. ✓
  11. Nonce-cache memory. 1M entries × 12 B nonce ≈ 12 MB for replay defence; sits outside the 8-MiB membership ceiling (it is a transport structure) but is itself bounded by keyring_history-scaled LRU. Budget separately.
  12. step() CPU budget. At p99 ≤ 250 µs/packet (§4) and 1 probe/s + ~1 ack/s + piggyback merges, a node handles ~10 packets/s typical: 10 × 250 µs = 2.5 ms/s ≈ 0.25% of one core. ✓ leaves ample headroom for broadcast bursts.
