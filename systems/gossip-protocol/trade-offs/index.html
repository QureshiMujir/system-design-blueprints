Implementation language

Chosen

Rejected

Alternative Architectures (Roads Not Taken)

A1 — Centralized membership registry.

   nodes ----heartbeat---->  [ registry / etcd ]  <----watch---- nodes

A strongly-consistent registry (etcd/ZooKeeper) holds the authoritative member list; nodes heartbeat in and watch for changes. Wins when the cluster is small (< ~100 nodes), strong consistency of the member list is required, and an operator already runs etcd. Embodied by Kubernetes node membership via the API server. Rejected because it introduces a coordination dependency and a scaling bottleneck the gossip substrate exists precisely to avoid; the rank-39 Raft project would then depend on the very thing this project supplies to it.

A2 — Pure flooding broadcast with no failure detector.

   on event: send to ALL peers; dedup by id; no probes

Every node floods every event to every neighbour; membership is implicit in who you can reach. Wins for tiny clusters (< 10 nodes) where tree maintenance overhead exceeds flooding's waste and failure detection can be left to the application. Embodied by early Scuttlebutt-style designs and small Redis Cluster bus deployments. Rejected because bandwidth is O(N) edges per event (BoE #8 shows 5× Plumtree) and the absence of a first-class detector pushes the hardest problem onto every consumer.

A3 — Vector-clock / version-vector membership (Akka style).

   each node carries a version vector; merge = element-wise max

Membership changes carry causal version vectors; merges reconstruct causal order. Wins where consumers must reason about the causal order of membership changes, not just the latest state. Embodied by Akka Cluster. Rejected because the vector grows O(N), the incarnation scheme (one u64 + status) captures everything our consumers need (latest-wins with refute), and the simpler shape is far easier to simulate exhaustively (P2, MM1).

A4 — QUIC-multiplexed transport replacing UDP+TCP.

   all gossip over one QUIC connection per peer (streams for probe/sync/broadcast)

A single QUIC connection per peer multiplexes probe, sync, and broadcast streams, eliminating the UDP/TCP split and head-of-line blocking. Wins for high-latency WAN links where connection setup and 0-RTT resumption dominate, and where per-stream flow control matters. Embodied by modern HTTP/3-era service meshes. Rejected for the Phase-0 drop because UDP+TCP matches SWIM/memberlist exactly (operator familiarity), QUIC adds a heavyweight dependency and a non-deterministic congestion controller that complicates the simulator; it is tracked as a stretch goal in the Deferred Features Register.
