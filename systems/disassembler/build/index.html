⬜ Phase 0 — Skeleton, Cursor, x86-64 Integer Decode, Linear Sweep, Intel Printer, CLI

Objectives

Bounds-checked Cursor (I1), a Decoder for the common integer x86-64 subset (mov/add/sub/push/pop/lea/cmp/test/jmp/jcc/call/ret + ModRM/SIB/disp/imm/REX), linear sweep, Intel printer, disasm sweep over a #333 .text. Constraint: never panic on any byte from day one.

Deliverable

disasm sweep <elf-or-pe> prints an Intel listing of .text for real binaries; recognizable function prologues.

Acceptance
  • Decodes a hand-assembled fixture exactly (mnemonics+operands+lengths).
  • On gcc -O0 .text, ≥ 95% of instructions match objdump -d (integer subset).
  • Fuzz smoke (1M execs) → 0 panics (I2).
  • Σ lengths = region for the clean fixture (I4).
Fixtures

conformance/x64/{prologue,arith,branches,lea_rip}, malformed/{trunc_imm,reserved_modrm}, differential/*.objdump.txt.

Pitfalls
  • ModRM mod=00,rm=101 = RIP-relative (not [rbp]) in 64-bit → wrong operand if treated as 32-bit [disp32].
  • REX.W vs default 32-bit operand size confusion.
  • SIB base=101 + mod=00 = disp32 no base → special case.
  • Sign-extension of i8/i32 disp/imm to i64 (I5).
  • Prefix vs opcode ambiguity (0x66 as operand-size vs mandatory prefix).

⬜ Phase 1 — Full ModRM/SIB/Displacement/Immediate + Operand-Size/Address-Size Matrix

Objectives

Complete the integer operand decoder across all addressing forms and operand/address-size combinations (16/32/64), making operand bytes exact for the whole integer ISA.

Deliverable

disasm prints exact memory operands ([rip+0x...], [rax+rcx*4+0x10], [rsp+disp8]) matching objdump.

Acceptance

Operand strings match objdump on a broad integer corpus (≥ 99%); SIB/RIP-relative exact; differential pass.

Fixtures

conformance/x64/{sib_all,rip_rel,opsize16,addrsize,seg_override}, roundtrip/operand_*.

Pitfalls
  • scale=0 vs index=100 (none) SIB special.
  • 16-bit addressing legacy forms ([bx+si]) — rare in 64-bit but must not misdecode.
  • Default operand size in 64-bit for push/pop/call (forced 64).
  • immediate vs displacement confusion in group ops.

⬜ Phase 2 — Length-Only Fast Path + Resync Strategy

Objectives

A length(bytes) path that determines instruction size without full decode (for sweep speed, patching, and robust resync), plus a principled resync after (bad).

Deliverable

disasm len <file> byte-accounts a region; sweep uses length for skipping; resync recovers after data.

Acceptance

Σ lengths = region on clean code (I4); length matches full-decode length for all fixtures; resync recovers within ≤ 15 bytes after inline data; length-path throughput ≥ 150 MB/s (M2-adjacent, faster than full decode since no operand materialization).

Fixtures

conformance/x64/length_*, malformed/inline_data_desync, roundtrip/length_eq_decode.

Pitfalls
  • Length path diverging from decode path → two sources of truth; share code.
  • Resync heuristic bias → prefer simple byte-advance.
  • Prefixes counted twice in length.
  • Forgetting the 15-byte cap in the length walk lets a malformed prefix run report an unbounded length, corrupting downstream byte accounting (T7).

⬜ Phase 3 — Recursive Descent + Worklist + Function Discovery

Objectives

Follow control flow from known entries (image entry + #333 function symbols), decoding only reachable code; build the instruction set per function; guarantee termination (I6).

Deliverable

disasm rd <file> disassembles reachable code per function; lists discovered functions.

Acceptance

On gcc/clang binaries, recovered functions ⊇ symbol functions; terminates on all fixtures incl. self-loops (I6); fewer desync artifacts than sweep on data-interleaved code; worklist drains to empty within a bounded number of iterations proportional to reachable instruction count (M5-scale parallelism across seeds).

Fixtures

conformance/cfg/{rd_reachable,self_loop,overlap,switch_stub}, malformed/rd_cycle.

Pitfalls
  • Missing indirect targets → unreachable real code (under-approximation) → combine with symbols + sweep gap-fill.
  • Decoding data as code when following a bad target → bound + validate.
  • Non-termination on crafted CFG → visited set (I6).
  • Tail calls (jmp func) misclassified as intra-function.
  • Recursion implemented as actual call recursion instead of an iterative worklist risks a native stack overflow on deep/cyclic CFGs (T4, FM-7) — the worklist must be a heap-allocated queue, never the Rust call stack.

⬜ Phase 4 — Basic Blocks + Control-Flow Graph

Objectives

Partition decoded instructions into basic blocks and build a CFG with typed edges; sound w.r.t. decode (I7). Constraint: a block ends exactly at a control-flow terminator or a leader boundary.

Deliverable

disasm cfg <file> [--func name] emits the CFG (text + Graphviz .dot).

Acceptance

Block/edge counts consistent with instruction flow; every edge has a decoded terminator (I7); .dot renders; matches manual CFG on fixtures.

Fixtures

conformance/cfg/{if_else,loop,switch,nested,tailcall} + golden block/edge sets.

Pitfalls
  • Fall-through after call is a real edge (call returns) but after jmp/ret is not → flow-class drives it.
  • Targets mid-instruction (overlap) → block split at unaligned address; record + flag.
  • noreturn calls (exit/abort) leave a dead fall-through → mark via #333 symbol hints.
  • Phantom edges from misclassified indirect (I7).

⬜ Phase 5 — Jump-Table / Switch Recovery + Indirect-Branch Heuristics

Objectives

Resolve common compiler jump tables so indirect jmp targets become concrete edges, improving CFG completeness (the hardest accuracy problem in disassembly).

Deliverable

disasm cfg resolves switch tables into concrete edges; reports resolved vs unresolved indirects.

Acceptance

Recovers clang/gcc switch tables on fixtures; bounded by the guard compare; 0 fabricated targets (unresolved stay IndirectEdge).

Fixtures

conformance/cfg/{switch_jumptable_gcc,switch_clang,sparse_switch,unresolved_indirect}.

Pitfalls
  • Reading the table from the wrong section → garbage targets; require RVA→offset via #333 (I8/I9).
  • Unbounded table (no guard found) → do NOT guess; leave indirect (principle 7).
  • Relative vs absolute table entries (offsets from base).
  • PIC jump tables (entries are deltas).

⬜ Phase 6 — Symbolization (#333 join: symbols, relocs, PLT/IAT, call graph)

Objectives

Turn target addresses into names using #333's symbols/relocations only (I9): direct calls→function names, PLT/IAT→imported APIs, data refs→symbol names, build a call graph.

Deliverable

disasm listing shows call printf@plt, lea rax, [rip+x] # &message; disasm callgraph emits the call graph.

Acceptance

Symbolized names match objdump on direct calls + PLT/IAT; unknown targets show raw address (no fabrication, I9); call graph nodes ⊇ symbol functions.

Fixtures

conformance/x64/{plt_call,iat_call,rip_data_ref}, cfg/callgraph_*.

Pitfalls
  • PLT stub vs real function confusion → resolve through .rela.plt.
  • Local vs global symbol preference; nearest-symbol-below for offsets.
  • Fabricating names for unknown addresses (I9 violation) → raw addr only.
  • Thunk/ICF-merged functions (identical-code folding) share an address.

⬜ Phase 7 — SSE/AVX (VEX) Subset + Floating/Vector Operands

Objectives

Decode a practically-useful SSE/AVX subset (movaps/movups/addps/mulps/xorps, common VEX-encoded AVX) so real .text (which is full of SIMD) disassembles without large (bad) gaps.

Deliverable

disasm decodes common SSE/AVX in real binaries; SIMD-heavy functions no longer desync.

Acceptance

≥ 99% instruction coverage on gcc -O2 -mavx2 .text (combined with integer); decoded SSE/AVX matches objdump; unknown SIMD → (bad) not misdecode (I12).

Fixtures

conformance/x64/{sse_mov,avx_vex2,avx_vex3,three_byte_op}.

Pitfalls
  • Mandatory prefix as opcode selector (not a real prefix) → wrong opcode if treated as group3.
  • VEX vvvv inversion (1's complement) → wrong source reg.
  • VEX.L (128 vs 256) → XMM vs YMM.
  • EVEX (AVX-512) out of scope → (bad), not partial decode.

⬜ Phase 8 — AT&T Syntax + Re-encoder Round-Trip (I10)

Objectives

Add AT&T output (operand order, sigils, suffixes) for objdump parity, and a re-encoder for the decidable subset to prove decode fidelity via round-trip (I10).

Deliverable

disasm sweep --att matches objdump -d (AT&T default); disasm roundtrip reports re-encode fidelity.

Acceptance

AT&T listing matches objdump on the corpus; round-trip byte-identical for the supported subset (I10); mismatches enumerated; roundtrip_fail = 0 on the canonical-subset conformance suite (M12-adjacent release gate).

Fixtures

conformance/x64/att_*, roundtrip/reencode_*, differential/*.objdump-att.txt.

Pitfalls
  • AT&T operand reversal + suffix rules (ambiguous sizes need suffix).
  • Encoding ambiguity (multiple byte sequences decode same) → round-trip only for canonical forms.
  • RIP-relative AT&T syntax (x(%rip)).
  • Implicit operands shown differently across syntaxes.
  • Redundant REX bytes (W=R=X=B=0) are legal but meaningless; the re-encoder drops them, so naive byte-for-byte comparison against the original must first classify the input as canonical or non-canonical (Q9).

⬜ Phase 9 — AArch64 Secondary Decoder (fixed-width)

Objectives

Validate the Decoder trait as a real multi-arch seam by adding a useful AArch64 (A64) subset: fixed 32-bit instructions decoded by field extraction. Schedule-permitting; proves the architecture generalizes beyond x86-64.

Deliverable

disasm sweep <arm64-elf> decodes A64 .text; CFG + symbolization work via the shared pipeline.

Acceptance

A64 subset matches objdump/llvm-mc on AArch64 fixtures; CFG/symbolization identical code path to x86-64 (seam validated); ≥90% coverage on the common-subset mnemonic list (Appendix D.8 row "AArch64 A64 integer/branch/ldst").

Fixtures

conformance/arm64/{movz_movk,ldr_str,branches,adrp_add}, differential/*.arm64.objdump.txt.

Pitfalls
  • Field-extraction off-by-bit (immediate shift/extend encodings, e.g. bitmask immediates) — notoriously fiddly.
  • PC-relative adrp page arithmetic.
  • Condition codes mapping vs x86 Cc.
  • Endianness (A64 is fixed LE for instructions).

⬜ Phase 10 — Hardening: Fuzzing, Miri, Anti-Disassembly Resilience

Objectives

Guarantee the never-panic invariant (I2) and characterize behavior on adversarial/obfuscated code: fuzz decode/sweep/rd, Miri-clean, detect (not necessarily defeat) anti-disassembly.

Deliverable

Green fuzz (24h, 0 crashes), Miri-clean, an anti-disasm diagnostic report.

Acceptance

0 panics/OOB across 1e9 fuzz execs minimum, scaling to the full 24h/M10 campaign volume (I2); Miri no-UB; recursive descent terminates on all crafted CFGs (I6); anti-disasm patterns flagged, not crashed-on.

Fixtures

fuzz/corpus/*, malformed/{overlap_trap,jmp_into_insn,prefix_bomb,max_len_chain}.

Pitfalls
  • Prefix bomb (long redundant prefix runs) → cap at 15-byte max length.
  • with_capacity(attacker) in CFG building → cap vs region.
  • Recursion in rd as actual call recursion → iterative worklist (I6).
  • Slow units hiding hangs → fuzz timeouts.

⬜ Phase 11 — Differential Conformance, Soak, Release

Objectives

Lock the differential oracle (objdump + llvm-mc) into CI, soak over large real .text, ship a reproducible signed release.

Deliverable

Green CI (build+clippy+test+miri+fuzz-smoke+differential); soak report; signed release; coverage dashboard.

Acceptance

≥ 99.9% instruction parity vs oracles on 10k+ real functions (within documented gaps, M12); soak flat memory; deterministic listing (I3).

Fixtures

differential/* (oracle outputs across arch/opt levels), full conformance/**.

Pitfalls
  • Oracle disagreements (objdump vs llvm-mc differ on edge encodings) → record + pick a documented reference.
  • Oracle version drift → pin versions.
  • Coverage gaps (unimplemented opcodes) counted honestly, not hidden.
  • Syntax differences normalized before compare.
