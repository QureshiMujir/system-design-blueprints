3. Architectural Overview

The system is a privilege-separated process model split by a single hard line: the trust boundary. Everything above it is the TCB (the browser/broker process, written in safe Rust); everything below it is fully untrusted (renderer, GPU, network, utility children). The diagram below is canonical; the rest of the document elaborates each box.

+-------------------------------------------------------------------------------+
|                  Browser (broker) process   [TCB · Privileged]                |
|  sbx-browser: ProcessHost registry · RouteId IPC router                       |
|  sbx-site: SiteInstance/BrowsingInstance · site = scheme+eTLD+1 -> process     |
|  sbx-broker: File/Socket/Resource brokers · PolicyEngine (CapabilitySet)      |
|  sbx-launcher + sbx-zygote (fork server)   sbx-crash (SIGCHLD watch · restart) |
+-------------------------------------------------------------------------------+
      |              |               |                |                |
IPC: sbx-ipc (UNIX domain socket · SCM_RIGHTS handle passing · sbx-shm shared memory) | spawn + sandbox
      |              |               |                |                |
======|==============|===============|================|================|=========  TRUST BOUNDARY
      v              v               v                v                v
+-------------+ +-----------+ +-------------+ +-------------+
| Renderer    | | GPU       | | Network     | | Utility     |     (sandboxed children)
| (untrusted) | | process   | | process     | | process     |
| sbx-renderer| | relaxed   | | net caps    | | minimal caps|
| seccomp-bpf | | sandbox   | | sandbox     | | sandbox     |
| +namespaces | |           | |             | |             |
+-------------+ +-----------+ +-------------+ +-------------+
      \___ brokered file/socket/shm requests (validated vs CapabilitySet) ___/
sbx-sandbox (seccomp-bpf · user/pid/net/mnt/ipc/uts ns · pivot_root · no_new_privs · cap drop)
applies confinement to each child; a renderer compromise is contained to its CapabilitySet.

3.1 The three boundaries

Boundary Where Rule Consequence
Trust boundary (the line above) between browser/broker and every child child input is adversarial; the TCB validates everything; nothing the child says is trusted the single most important invariant in the doc — every OS access by a child is denied by seccomp OR brokered + validated vs CapabilitySet; defense in depth = TWO independent layers, a bug in one must not yield escape
Concurrency boundary OS process / address space each process = its own address space (no shared mutable memory except explicit sbx-shm regions); a child cannot reach into TCB memory browser runs an event loop + one IPC thread per child; children run their own loops; sole cross-process channels = sbx-ipc pipes + sbx-shm buffers + SCM_RIGHTS handle passes
Persistence boundary runtime state vs disk no durable runtime state required; the process graph + route table + CapabilitySets live in TCB memory and are rebuilt on restart only sbx-crash writes to disk (Minidump-style artifacts + crash log); a renderer cannot persist anything outside its brokered caps

Trust boundary detail (the load-bearing line). Threat = a renderer whose memory is fully controlled by an attacker (arbitrary code execution inside the renderer is assumed, not a failure). Containment, not prevention, is the goal. A compromised renderer holds exactly its CapabilitySet; it cannot widen it because (1) seccomp-bpf blocks the syscalls that would open new resources directly, and (2) every brokered request is re-validated by the PolicyEngine against the recorded CapabilitySet for that ProcessId — the renderer's own claims are ignored. Escape requires defeating both layers simultaneously.

Concurrency model. Browser = single-threaded event loop owning the ProcessHost registry + router, plus a dedicated blocking IPC reader thread per child (each thread owns one MessagePipe, demultiplexes by RouteId, hands parsed Messages to the loop via a channel). No child shares an address space with the TCB or with another child. sbx-shm regions are the only shared-memory channel and are sealed (memfd seals) + mapped read-only on the consumer side wherever the producer is untrusted. SIGCHLD is handled by sbx-crash on a self-pipe to keep async-signal-safety.

Persistence model. Runtime requires zero on-disk state: the site→process map, route table, and per-process CapabilitySets are reconstructible. The only writers to disk are sbx-crash (Minidump artifact + structured crash report) and observability sinks (metrics/traces in Phase 12). Children write nothing to disk except through a FileBroker grant.

3.2 The boxes (one per crate)

sbx-core — OS-free shared vocabulary. Defines ProcessId, ProcessType (Browser/Renderer/Gpu/Network/Utility/Storage), ProcessRole (Privileged for the browser, Sandboxed for children), SiteId, BrowsingInstanceId, HandleId, RouteId, Capability/CapabilitySet, SbxError. Inputs: none (pure types). Outputs: the type alphabet every other crate speaks. Security invariant: CapabilitySet is the only representation of a principal's authority — least-privilege grants are expressed here as Capability variants (OpenFile{path_glob,mode}, ConnectSocket{host,port}, SharedMemory{max_bytes}, …), nothing implicit. Referenced by every phase; the capability model is fleshed out in Phase 8 (## 20).

sbx-ipc — the Mojo-like typed IPC layer over UNIX domain sockets. Defines MessagePipe (bidirectional UDS pair via pair() → socketpair), Message{MessageHeader{route,kind,req_id,num_handles}, payload, handles}, Handle (owned OS fd), Interface/Endpoint<T> typed binding, request/response + async. Inputs: a connected UDS + typed interface contracts. Outputs: framed messages + duplicated fds. Security invariant: the TCB never trusts wire bytes — every inbound Message is bounds-checked, num_handles is reconciled with the actual SCM_RIGHTS ancillary data, and a malformed frame returns an error rather than panicking. Built in Phase 1 (## 13, framing/typed binding) and extended in Phase 2 (## 14, handle passing); fuzzed in Phase 13 (## 25).

sbx-shm — shared memory for bulk/zero-copy transfer. Defines SharedBuffer (memfd-backed, carries a Handle), Mapping (mmap region, Prot::ReadOnly/ReadWrite), ShmRing (SPSC ring over a SharedBuffer), seal flags. Inputs: a size + protection request. Outputs: a sealed memfd Handle passable over sbx-ipc. Security invariant: buffers from an untrusted producer are mapped read-only on the TCB side and sealed (F_SEAL_SHRINK|GROW|WRITE as applicable) so a renderer cannot shrink/grow/race a region the broker is reading — no TOCTOU on shared length. Used wherever IPC payloads exceed the small-message path; introduced in Phase 2 (## 14).

sbx-sandbox — the OS confinement engine and the heart of containment. Defines the Sandbox trait + LinuxSandbox (primary), SeccompFilter (compiles SyscallRule[] → a classic-BPF program over seccomp_data), SyscallPolicy with Disposition (Allow/Errno/Trap/KillProcess/Log) + arg filters, Namespaces (USER|PID|NET|MNT|IPC|UTS clone flags), Policy{namespaces, seccomp, rlimits, root (pivot_root target), drop_caps, no_new_privs}. Inputs: a Policy per ProcessType. Outputs: a confined process. Security invariants: (1) the BPF program checks arch first, rejecting anything but the expected AUDIT_ARCH_* to block the x32/ia32 ABI bypass; (2) the filter is installed only after PR_SET_NO_NEW_PRIVS; (3) deny-by-default — unknown syscalls map to Errno/KillProcess, never Allow. macOS (Seatbelt) + Windows (job/restricted-token/AppContainer) backends are PhaseDeferred stubs. Built across Phase 4 (## 16, namespaces + fs) and Phase 5 (## 17, seccomp-bpf).

sbx-zygote — the pre-forked template for fast renderer spawn. Defines Zygote (fork-server socket + base sandbox policy), ForkRequest{process_type, policy, channel}, ForkServer (services requests by fork() + seal). Inputs: a ForkRequest over its control socket. Outputs: a new sandboxed child sharing COW pages with the template. Security invariant: the zygote pre-applies the common sandbox before any untrusted work, and each forked child seals/tightens its seccomp policy to the per-ProcessType profile before running renderer code — the template never executes untrusted input, and a forked child cannot weaken the filter (seccomp is monotonic). Built in Phase 6 (## 18); consumed by sbx-launcher via use_zygote.

sbx-broker — the capability-validating resource gateway. Defines FileBroker/SocketBroker/ResourceBroker, the Broker trait, BrokerRequest{from, op}, BrokerResponse (Handle/Denied/Error), and the PolicyEngine (maps ProcessId → CapabilitySet, validates each BrokerOp). Inputs: a BrokerRequest arriving over sbx-ipc from a child that cannot perform the operation itself (NET namespace removes sockets; pivot_root + seccomp remove file opens). Outputs: a brokered fd returned via SCM_RIGHTS, or a denial. Security invariant: deny-by-default + the broker opens, never the renderer — the renderer sends a request, the broker validates it against the recorded CapabilitySet (path glob, host/port, byte cap), opens the resource itself, and passes only the resulting fd; a renderer never gains the ability to name resources outside its grant. This is layer two of defense in depth; built in Phase 7 (## 19), policy profiles in Phase 8 (## 20).

sbx-launcher — process spawning + lifecycle. Defines LaunchOptions{process_type, policy, use_zygote}, ChildProcess{pid, channel}, ProcessLauncher, ProcessHandle. Inputs: LaunchOptions. Outputs: a running, sandboxed child with a connected MessagePipe and a completed handshake. Responsibilities: build the child command/args/env, create the IPC channel, route through the zygote or do a direct clone/exec, run the handshake, then monitor/reap via SIGCHLD with restart hooks. Security invariant: the IPC channel + sandbox Policy are wired before the child runs untrusted work — there is no window in which a child is alive but unconfined. Built in Phase 3 (## 15, no sandbox yet), then composed with sbx-sandbox + sbx-zygote in Phases 4–6.

sbx-site — site-isolation policy. Defines SiteInstance{id, site, browsing_instance}, BrowsingInstance, ProcessReusePolicy (ProcessPerSiteInstance / ReuseExistingForSite / LimitReached), SiteIsolationPolicy (eTLD+1 derivation via public-suffix list, site_for(url), site→process map). Inputs: a navigation URL. Outputs: a SiteId and a process-assignment decision. Security invariant: the principal is the SiteInstance — site = scheme + registrable domain (eTLD+1); cross-site documents land in separate processes, so a renderer compromise cannot read another site's data even via Spectre-class side channels. SiteInstances within one BrowsingInstance may script each other and so share a process. Built in Phase 9 (## 21); consumed by the orchestrator's assignment logic.

sbx-browser — the orchestrator and TCB entry point. Defines BrowserProcess (owns ProcessHost, launcher, brokers, site policy, crash handler, router), ProcessHost (registry of all child hosts keyed by ProcessId), RenderProcessHost{pid, site_instance, routes}. Inputs: navigations + inbound child IPC. Outputs: process spawn/assignment decisions + routed messages. Responsibilities: map navigation → SiteInstance → process (new or reused per ProcessReusePolicy), multiplex many frames over one pipe via RouteId, own every child's lifetime. Security invariant: it is the sole privileged actor — all broker validation, site assignment, and routing happen here; a RouteId is bound to one RenderProcessHost, so a child cannot inject messages on a route it does not own. Wired end-to-end in Phase 10 (## 22).

sbx-renderer — the minimal untrusted child (a stand-in, not a web engine; real rendering is #260/#305). Defines RendererProcess (sandboxed; talks to broker; hosts RenderFrames; has a test crash hook) and RenderFrame{route, url}. Inputs: a navigation + brokered resources. Outputs: broker requests + IPC responses; deliberately, nothing it isn't granted. Security invariant: it runs fully sealed (seccomp + all namespaces + pivot_root + dropped caps + no_new_privs) and can reach the OS only through the broker — it is the device under test for the Phase 13 (## 25) red-team harness, which forces it to attempt forbidden syscalls/files/sockets and asserts each is denied or kills it.

sbx-crash — crash handling + recovery. Defines CrashHandler (SIGCHLD/exit/IPC-disconnect watcher → Minidump + RestartPolicy + sad-tab signal), Minidump (minimal artifact: pid, signal, register-ish snapshot, maps), RestartPolicy (Never / Restart{max,window_secs} / ReloadTab). Inputs: child-death signals. Outputs: a crash artifact + a recovery action. Security invariant: blast radius is one child — a renderer crash is observed (never trusted to self-report cleanly) and isolated; the browser and sibling renderers are unaffected and the user sees a "sad tab." Crash artifact writes are the only runtime disk persistence. Built in Phase 11 (## 23).

sbx-cli — the sbx operator binary. Subcommands: run, spawn, policy, ipc-ping, sandbox-test, crash-test, sites, attack (the red-team harness). Inputs: operator commands. Outputs: an end-to-end driver of the whole stack for demos, conformance, and the security gate. Security note: attack is the executable form of the trust boundary — it must prove that forbidden operations are denied/killed, anchoring the Phase 13 (## 25) "done" gate. Depends on all crates above.

8. Domain Model — Processes, IPC Protocol, Sandbox Policy, and the Site Model

Five coupled sub-models meeting at the trust boundary: above = browser/broker = TCB; below = fully untrusted sandboxed children. Every cross-boundary fact (Message, brokered FD, process assignment) is named here once; phases reuse it.

8.1 Process taxonomy

ProcessType Role Trust Network ns Default CapabilitySet Sandbox tightness
Browser Privileged TCB host net n/a (is the broker) none — it IS the authority
Renderer Sandboxed hostile NET ns (no net) {} empty → all via broker strictest: full ns + tight seccomp
Gpu Sandboxed semi NET ns {GpuChannel, SharedMemory} relaxed: needs ioctl/DRM nodes
Network Sandboxed semi host net {ConnectSocket{*}} relaxed: socket/connect/sendto allowed
Utility Sandboxed minimal NET ns per-task narrow grant strict, task-scoped
Storage Sandboxed minimal NET ns {OpenFile{<profile>/**}} strict + path-glob limited

Principal = SiteInstance (§8.6), not URL/tab. One RenderProcessHost ↔ one child ↔ one SiteInstance (subject to ProcessReusePolicy).

8.2 Process lifecycle state machine

Spawning → Handshaking → Sandboxed → Live → {Crashed | Exited} → Reaped

From Event To TCB action / invariant
— launch(LaunchOptions) Spawning clone/exec or zygote ForkRequest; allocate ProcessId, socketpair → MessagePipe
Spawning child applied sandbox + self-check ok Handshaking child sealed (INV-1/10) BEFORE this edge; sends ready Message
Spawning sandbox-apply fail / no ready within T_handshake(=500ms) Crashed fail closed (INV-5): never run unconfined; SpawnFailed
Handshaking handshake Message validated (proto ver, type echo) Sandboxed confirm sealed=true; bind Endpoint<T> routes
Sandboxed first route bound, broker reachable Live serve traffic; only state that runs untrusted work
Live SIGCHLD w/ signal | IPC EOF/disconnect Crashed sbx-crash: capture Minidump, sad-tab (INV-7)
Live clean exit(0) Exited normal teardown
Crashed/Exited waitpid reaped + routes torn down Reaped free ProcessId (no reuse — anti-ABA), apply RestartPolicy

Sandbox seal is a precondition of Handshaking, never a later edge → no window where a Live/handshaking child is unconfined.

8.3 IPC wire format

Transport = one MessagePipe per child = a socketpair(AF_UNIX, SOCK_SEQPACKET, 0) (SEQPACKET → message boundaries preserved, no stream re-framing ambiguity; datagram cap respected, large payloads go via sbx-shm). Each Message = one sendmsg; handles ride the ancillary control buffer via SCM_RIGHTS.

Wire layout (little-endian, header fixed 24 bytes):

 byte 0          4          8                 16                22   24
 +----+----+----+----+----+----+----+----+----+----+----+----+----+----+
 | route (u32)  | kind(u16)| req_id (u64, correlation)         | nh |pad|   <- MessageHeader (24B)
 +----+----+----+----+----+----+----+----+----+----+----+----+----+----+
 | payload[payload_len] (CBOR/postcard-encoded args)                   |   <- Message.payload
 +---------------------------------------------------------------------+
   ancillary (separate cmsg, NOT in payload):
   cmsg_level=SOL_SOCKET  cmsg_type=SCM_RIGHTS  data=[fd_0 .. fd_{nh-1}]  <- Message.handles
  • route: RouteId — demux key WITHIN this pipe (§8.7); validated owned-by-sender (INV-14).
  • kind: MsgKind — Request | Response | Event | ControlReady | ControlBye.
  • req_id: u64 — correlation. Request allocates monotonic id; matching Response echoes it. Event ⇒ req_id=0. One id ↔ ≤1 in-flight response (INV-13: dup/unknown id rejected → no request smuggling).
  • num_handles (nh): u16 — count of FDs in the ancillary cmsg. Decode invariant (INV-9): nh MUST equal the FD count actually delivered by the kernel in the cmsg; mismatch → reject frame, close any received FDs, SbxError::Ipc. Hard cap nh ≤ 8; payload_len ≤ 64 KiB (overflow → shm).

Framing/bounds: header parsed first; reject if payload_len > cap or nh > cap or trailing bytes ≠ payload_len. No raw payload pointer is treated as a trusted struct — always deserialized through a schema (INV-3).

Interface/Endpoint<T>: a typed contract over one route. Endpoint<T: Interface> = sugar that (de)serializes T's methods to Messages; Mojo-like. pair() -> (MessagePipe, MessagePipe) = the socketpair primitive.

8.4 Sandbox policy model

Dispositions (Disposition):

Variant seccomp ret Meaning
Allow SECCOMP_RET_ALLOW syscall proceeds
Errno(e) SECCOMP_RET_ERRNO|e fail w/ errno, no kill (graceful, e.g. EPERM)
Trap SECCOMP_RET_TRAP SIGSYS → handler (log/emulate)
KillProcess SECCOMP_RET_KILL_PROCESS whole process dies (the default for forbidden)
Log SECCOMP_RET_LOG allow + audit (dev only)

seccomp_data (filter input, read-only):

struct seccomp_data { int nr; __u32 arch; __u64 instruction_pointer; __u64 args[6]; }

Filter shape (cBPF): insn[0] loads arch; if arch != AUDIT_ARCH_X86_64 → KILL_PROCESS (blocks x32/ia32 ABI bypass, INV-2) BEFORE any nr dispatch. Installed only after PR_SET_NO_NEW_PRIVS=1 (else seccomp()→EINVAL). Default tail = KillProcess ⇒ deny by default.

Namespaces clone flags (renderer): CLONE_NEWUSER | CLONE_NEWPID | CLONE_NEWNET | CLONE_NEWNS | CLONE_NEWIPC | CLONE_NEWUTS. USER first (unprivileged → fake root → enables the rest); NET = no network (forces brokering); NS+pivot_root = minimal read-mostly rootfs.

Baseline renderer SyscallPolicy (pseudo-DSL excerpt):

arch  != AUDIT_ARCH_X86_64           => KillProcess     # INV-2 guard, insn 0
read, write, recvmsg, sendmsg        => Allow           # talk to broker/parent only
mmap(prot) if !(prot & PROT_EXEC)    => Allow           # W^X: executable maps denied
mprotect(prot) if !(prot & PROT_EXEC)=> Allow
futex, nanosleep, sched_yield, brk   => Allow
exit, exit_group, rt_sigreturn       => Allow
close, fstat, lseek, ppoll, epoll_*  => Allow
clone(flags) if flags & CLONE_THREAD => Allow           # threads ok
clone(flags) otherwise               => Errno(EPERM)    # no new process
open, openat, creat                  => KillProcess     # no direct FS — broker only
socket, connect, bind, sendto        => KillProcess     # no direct net — NET ns + kill
execve, execveat, ptrace, mount      => KillProcess
fork, vfork, clone(NEWUSER)          => KillProcess     # no sandbox unshare
*  (unlisted)                        => KillProcess     # deny by default

Two independent layers (defense in depth): (1) seccomp syscall filter, (2) broker CapabilitySet check. A bug in either alone must not yield escape. Forbidden actions are killed at the syscall layer; legitimate resource needs are routed to the broker (FD-passing), never to a direct syscall.

8.5 Capability model

Capability variants (least-privilege grants):

Variant Authorizes Validated against op
OpenFile{path_glob, mode: AccessMode} open files matching glob, ≤ mode canonicalized path re-matched vs glob (INV-4)
ConnectSocket{host, port} TCP connect to host:port exact host+port match
SharedMemory{max_bytes} map a SharedBuffer ≤ max_bytes requested len ≤ max_bytes
ReadClipboard read clipboard contents presence check
GpuChannel obtain the GPU IPC channel presence check

CapabilitySet = the per-process set; assigned at launch from the ProcessType profile + navigation context. Immutable for the child's lifetime (INV-11): no in-process grant/revoke; widening authority = a new process.

Grant/validate flow:

launch: BrowserProcess derives CapabilitySet(process_type, site) -> PolicyEngine.bind(pid -> caps)
runtime: child -> BrokerRequest{from=pid, op=OpenFile{"/p"}}  --IPC-->  Broker.service
         PolicyEngine.validate(op, caps): canonicalize path, find matching Capability
           match  -> open()/connect()/memfd -> BrokerResponse::Handle(fd via SCM_RIGHTS)  # FD-only, INV-12
           none   -> BrokerResponse::Denied("no cap for /p")                              # deny by default

Returned FDs never carry a path/name back (INV-12): the renderer gets bearer authority (a Handle), not a namespace it can enumerate.

8.6 Site model

site = scheme + eTLD+1 (registrable domain), eTLD computed via the public-suffix list (PSL). SiteIsolationPolicy::site_for(url) -> SiteId.

URL scheme host eTLD (PSL) eTLD+1 SiteId
https://a.example.com/x https a.example.com com example.com https://example.com
https://b.example.com/y https b.example.com com example.com https://example.com ← same site
https://foo.github.io/ https foo.github.io github.io (PSL!) foo.github.io https://foo.github.io ← isolated from bar.github.io
http://example.com http example.com com example.com http://example.com ← scheme differs → distinct

SiteInstance = a SiteId within a BrowsingInstance. BrowsingInstance = a set of SiteInstances that may script each other (window.opener-reachable) ⇒ same-instance same-site documents may share a process. Cross-BrowsingInstance never shares (INV-8 candidates isolated).

Process assignment (ProcessReusePolicy): ProcessPerSiteInstance (default) → one renderer per SiteInstance. ReuseExistingForSite → if a live host already serves this SiteId in the same BrowsingInstance, reuse it. LimitReached → at the process-count cap, coalesce same-site tabs onto one host.

Reuse example: tab1→https://example.com, tab2 (same BrowsingInstance)→https://b.example.com. Both map to SiteId https://example.com ⇒ same RenderProcessHost reused (one process, two RouteIds). tab3→https://foo.github.io ⇒ distinct SiteId ⇒ new sandboxed renderer.

8.7 RouteId multiplexing

One MessagePipe per child carries many logical frames; RouteId demuxes (one per RenderFrame). RouteId is namespaced per pipe — same numeric value on two pipes is unrelated, and never crosses the process boundary (INV-14: a route is owned by exactly one host). Browser router dispatches inbound Message by (pid, route).

8.8 End-to-end worked example — navigate https://a.example

1. NAV     BrowserProcess receives navigate(tab=7, url="https://a.example")
2. SITE    SiteIsolationPolicy.site_for -> SiteId("https://a.example")   # eTLD+1 = a.example via PSL
3. ASSIGN  ProcessReusePolicy=ProcessPerSiteInstance, no live host for site
           -> new SiteInstance{ id, site, browsing_instance } ; new RenderProcessHost{ pid?, site_instance, routes:[r0] }
4. SPAWN   ProcessLauncher.launch(LaunchOptions{ Renderer, policy=renderer_profile, use_zygote=true })
           -> ForkRequest to Zygote (COW fork, fast) ; child SEALS sandbox (ns+pivot_root+caps+no_new_privs+seccomp)
           -> child self-check ok -> Handshaking -> ready Message -> Sandboxed -> Live   (states §8.2)
5. BIND    browser binds Endpoint<FrameHost> on route r0 ; sends Navigate{route:r0, url}
6. BROKER  renderer needs /usr/share/fonts/x.ttf -> BrokerRequest{from=pid, op=OpenFile{"/usr/share/fonts/*.ttf", Read}}
           PolicyEngine: renderer CapabilitySet has OpenFile{"/usr/share/fonts/**",Read} -> canonicalize -> match
           -> open(O_RDONLY) -> BrokerResponse::Handle(fd) via SCM_RIGHTS   # FD-only
7. ATTACK  compromised renderer calls open("/etc/shadow") DIRECTLY (not broker)
           -> seccomp baseline: open => KillProcess -> SIGKILL ; SIGCHLD -> Crashed -> Minidump -> sad tab
           browser + every other renderer UNAFFECTED (blast radius = this child's CapabilitySet only)

8.9 Malicious / edge cases — required outcomes

Stimulus Layer Outcome
renderer issues open()/socket() directly seccomp SECCOMP_RET_KILL_PROCESS → SIGKILL → sad tab
BrokerRequest for path/host outside CapabilitySet broker PolicyEngine BrokerResponse::Denied(reason), logged; surge → mark host suspect → terminate (INV-4)
Message with num_handles=3 but cmsg carries 1 FD sbx-ipc decode reject frame, close stray FDs, SbxError::Ipc; no OOB (INV-9)
payload_len > 64 KiB or trailing-byte mismatch sbx-ipc decode reject; never allocate attacker-chosen huge buffer
duplicate/unknown req_id on a Response sbx-ipc correlation drop, no smuggling (INV-13)
inbound route not owned by sending host sbx-browser router reject, SbxError::Ipc (INV-14)
clone(CLONE_NEWUSER) from renderer (re-sandbox/escape try) seccomp KillProcess
x32-ABI syscall to dodge the filter seccomp insn 0 arch mismatch → KillProcess (INV-2)
renderer crashes (segfault / forced via test hook) sbx-crash SIGCHLD/IPC-EOF → Crashed → Minidump + sad tab; RestartPolicy applied; browser + peers isolated (INV-7)
renderer tries to grow a sealed SharedBuffer sbx-shm seals ftruncate→EPERM (F_SEAL_GROW/SHRINK set before share, INV-15)

Every row resolves to deny / kill / reject / isolate — never to silent escalation. The two layers (§8.4) ensure a single-layer bug still leaves the other intact.
