Pitfalls
  • fd inheritance leak: child inherits ALL parent fds across fork; the other socketpair end + unrelated fds leak in. Root cause: no O_CLOEXEC/no explicit close. Fix: SOCK_CLOEXEC on socketpair, close peer end in each process, dup2 only the kept fd. Debug: ls -l /proc/<child>/fd.
  • fork in multithreaded process: async-signal-unsafe between fork and exec (allocator/locks). Root cause: tokio/threads spawned pre-fork. Fix: keep smoke path single-threaded; only async-signal-safe calls (dup2,execv,_exit) post-fork.

  • execv self-path: re-exec via /proc/self/exe not argv[0] (cwd-relative argv0 breaks); guard infinite re-exec with the --child arg.

⬜ Phase 1 — IPC core (typed message pipe over UNIX domain sockets) §13

Objectives
  • MessagePipe: bidirectional UDS channel; pair() (socketpair, parent/child) + named-socket connect (late joiners) — same MessagePipe type either way.
  • Wire format: length-prefixed Message{MessageHeader, payload}, bounds-checked on every decode; one frame = one message; never partial-deliver.
  • Correlation: monotonic req_id (u64); request -> response match; out-of-order + concurrent in-flight; async + blocking send/recv.
  • Typed layer: Interface (method -> MsgKind) bound to Endpoint<T>; compile-time-ish contract over the raw byte pipe.
  • Robust disconnect/error semantics: SbxError::Ipc on EOF/ECONNRESET/oversize/short-read; broker never panics on malformed input.
Deliverable

sbx ipc-ping spawns/links two MessagePipe ends; sends N typed Requests, receives matched Responses. cargo test -p sbx-ipc green. Echo + concurrency tests pass. MAX_MESSAGE, header size, LE byte order documented in wire.rs.

Acceptance
  • Echo: 10k round-trips, every Response.req_id == Request.req_id, payloads byte-identical, zero loss/reorder corruption.
  • Concurrency: 64 in-flight requests across 8 tasks on one pipe -> all correlate correctly; no req_id collision (assert unique).
  • Framing: payload_len of 0, 1, MAX_MESSAGE, MAX_MESSAGE+1 -> last is rejected Err(Ipc), process survives.
  • Malformed/attack: truncated frame, len=u32::MAX, num_handles>0, garbage header bytes -> all return Err(Ipc), never panic, never OOM, never hang (recv has read timeout/EOF path).
  • Disconnect: peer drop mid-frame -> recv() -> Err(Ipc) within one poll cycle; pending calls resolve to Err(Ipc).

Pitfalls
  • SOCK_STREAM vs SEQPACKET boundary loss: stream coalesces/splits writes -> a length prefix is mandatory regardless; relying on one read() == one message corrupts under load. Debug: strace -e recvmsg, check returned byte counts != frame size.
  • Partial read assumed complete: read() may return < requested without EOF; treat short read as "loop, not done." Root cause: ignoring read return. Debug: inject 1-byte-at-a-time socket.
  • Attacker-controlled len -> OOM: Vec::with_capacity(len) before bounds-check lets a peer request 4 GiB. Always check len <= MAX_MESSAGE first. Debug: fuzz len field, watch RSS.
  • req_id reuse/wrap: trusting peer-supplied req_id to index pending; a malicious peer forges ids to complete the wrong oneshot. Only the local side owns its pending map; ignore unknown ids. Debug: assert id in map before complete.
  • Blocking recv deadlock: request/response both blocking on one thread -> self-deadlock. Async demux or separate recv thread required. Debug: both peers stuck in recvmsg.
  • Endianness drift: native-endian encode breaks cross-arch; lock little-endian. Debug: golden header_golden.bin mismatch on BE.

⬜ Phase 2 — Handle and shared-memory passing (SCM_RIGHTS, memfd) §14

Objectives
  • Pass owned OS FDs peer↔peer via sendmsg/recvmsg SCM_RIGHTS cmsg; receiver gets a duplicated fd in its own table (capability transfer, not path transfer).
  • Handle: single-owner, close-on-drop, non-Clone, move-only; reject double-close/leak; track open count for tests.
  • Wire-bind handle count: MessageHeader.num_handles MUST equal received cmsg fd count; mismatch → SbxError::BadHandle, close strays.
  • sbx-shm: memfd_create-backed SharedBuffer; Mapping ro/rw via mmap; F_SEAL_* to freeze size/writes; ShmRing SPSC for large zero-copy bulk.
  • Deliverable: send an fd + a shm region across the boundary; peer reads/writes; throughput + ownership tests pass.
Deliverable

sbx ipc-ping --pass-fd <path> (extends Phase 1): browser opens a file, sends the FD + a 64 MiB sealed SharedBuffer to the child; child reads via the brokered FD, mmaps the buffer, verifies a CRC the parent wrote, echoes a CRC of its own write-back through a ShmRing. Exit 0 iff CRCs match and fd-table accounting is clean.

Acceptance
  • Round-trip a real FD: child reads exactly the parent's file bytes via the passed fd; the path is never sent on the wire (assert payload contains no path string).
  • num_handles mismatch (inject extra/missing fd) → SbxError::BadHandle, zero fd leak (verify via /proc/self/fd count pre/post).
  • Sealed SharedBuffer: receiver write attempt on a F_SEAL_WRITE region → SIGBUS/EPERM; size cannot grow/shrink post-seal.
  • Handle double-close impossible: dropping a moved-from Handle is a no-op; into_raw_fd disarms Drop (no spurious close).
  • ShmRing 1 GiB streamed, zero-copy: throughput ≥ 5 GB/s single-core; zero data corruption vs memcpy baseline.

Pitfalls
  • fd leak on the error path: parse fails after kernel installed fds → must close every received fd before returning. Root cause: kernel installs cmsg fds regardless of app validation. Debug: watch /proc/<pid>/fd count climb under fuzzing.
  • Missing MSG_CMSG_CLOEXEC: received fds inherited across a later exec → sandbox-escape vector (untrusted child keeps a privileged fd). Always set it; verify FD_CLOEXEC on recv.
  • SIGPIPE on peer death: sendmsg to a dead child raises SIGPIPE, killing the broker. Use MSG_NOSIGNAL (and/or signal(SIGPIPE, SIG_IGN) at startup).
  • memfd without MFD_ALLOW_SEALING: later F_ADD_SEALS → EINVAL. The flag must be set at memfd_create, not retrofittable.
  • Handle accidental Clone/Copy: would double-own one fd → double-close, then close of an unrelated reused fd → data corruption in TCB. Enforce move-only at compile time; no derive.
  • Ring without acquire/release fences: consumer reads stale data or torn slices across the trust boundary. Root cause: relaxed atomics reorder data vs index publish. Debug: TSan + cross-core stress.
  • Partial sendmsg of payload: large payloads short-write while ancillary already delivered → desync. Keep handle-bearing messages small; assert full byte count or fail.

⬜ Phase 3 — Process launcher and lifecycle §15

Objectives
  • ProcessLauncher::launch(LaunchOptions) -> Result<ChildProcess, SbxError>: typed spawn via re-exec of /proc/self/exe with role arg/env; one socketpair MessagePipe per child.
  • Child-side entry: detect --child/SBX_PROCESS_TYPE, dup2 inherited channel fd to a fixed slot, reconstruct MessagePipe, run role main.
  • Handshake (handshake.rs): exchange identity (pid, ProcessType, proto version) + initial Endpoint; reject version mismatch → SbxError::SpawnFailed.
  • ChildProcess{pid,channel} + ProcessHandle (cloneable supervisory token: pid, type, exit-status cell, restart hook).
  • Single global reaper: SIGCHLD handler → self-pipe → waitpid(WNOHANG) loop drains all exits; no per-child blocking thread.
  • Restart hooks present (on_exit(FnMut(ExitInfo))) but inert this phase; deterministic teardown (kill+reap all children on launcher drop).
Deliverable
  • sbx spawn --type renderer launches one typed child, handshakes, prints OK pid=<n> type=Renderer proto=<v>; child idles until Shutdown, exits 0, parent reaps.
  • ProcessLauncher launches N children of mixed types concurrently; all handshake; killing one (kill -9) is detected by the reaper, ExitInfo{Signaled(9)} recorded, others unaffected.
  • Integration test lifecycle: spawn → talk (Hello/HelloAck) → graceful exit → reap; and spawn → external kill → reap. Launcher Drop kills+reaps all survivors (no orphans/zombies).

Pitfalls
  • SIGCHLD coalescing: multiple children die between handler invocations → kernel delivers ONE SIGCHLD (signals don't queue). Fix: handler is a wakeup; reaper loops waitpid(WNOHANG) until 0/ECHILD. Symptom if wrong: zombies despite handler firing (debug: ps -o stat,pid | grep Z). Self-pipe full (storm of exits): handler write would block (illegal in handler) — pipe nonblocking, handler ignores EAGAIN (one byte already pending ⇒ reaper drains regardless).
  • Handshake recv on a non-handshake fd: child reconstructs pipe from the WRONG fd if SBX_CHANNEL_FD drifts from the dup2 target. Root cause: magic-number mismatch. Fix: single const CHANNEL_FD: RawFd = 3; assert in both launch and child_entry. Debug: child recv blocks forever; check lsof -p.
  • CLOEXEC self-deadlock: forget to clear CLOEXEC on FD 3 → execv closes the channel → child's first recv = EBADF. Fix: dup2(peer,3) yields a non-CLOEXEC fd (dup2 clears it); never fcntl it back. Debug: child immediate EBADF on recv.
  • Reaper steals the handshake waitpid: a global waitpid(-1) reaper can reap a child before the parent handshake completes, racing the recv/exit-status read. Root cause: reaper + handshake both touch the same child. Fix: handshake uses only the pipe (never waitpid); reaper records exit but handshake distinguishes EOF-on-pipe (SpawnFailed) from HelloAck.
  • PID reuse aliasing: OS pid reused after reap; a stale HashMap<pid_t,ProcessId> entry misattributes a new child's exit. Root cause: not removing the map entry on reap. Fix: erase pid→ProcessId atomically when exit is filled. Debug: on_exit fires on wrong ProcessHandle.
  • fork() in a multithreaded launcher: tracing background thread or future spawner makes post-fork pre-exec code async-signal-unsafe (alloc/lock in child). Fix: between fork and execv call ONLY dup2/setenv-via-pre-built-array/execv/_exit; build env array before fork. (Carried from Phase 0; re-asserted as TCB rule.)

⬜ Phase 4 — Linux sandbox part 1: namespaces and filesystem confinement §16

Objectives
  • Implement Sandbox::apply(&Policy) for LinuxSandbox: unprivileged USER ns → uid/gid maps → PID/NET/MNT/IPC/UTS ns → pivot_root minimal RO rootfs → rlimits → no_new_privs → drop all caps.
  • No real root, no CAP_SYS_ADMIN, no setuid helper — USER ns is the privilege source. unshare(CLONE_NEWUSER) first, then nest other namespaces.
  • Defense layer 1 of 2 (seccomp = layer 2): renderer has zero network, zero foreign PID visibility, RO rootfs, empty cap set, NOFILE/AS/NPROC capped. Strict ORDER is security-critical — wrong order = silent escape or EPERM; fail-closed everywhere.
Deliverable
  • LinuxSandbox::apply fully wired into sbx-launcher (Phase 3 clone/exec path runs it pre-exec).
  • sbx sandbox-test subcommand spawns a child that calls apply, then self-reports: visible PIDs, cap set, network reachability, rootfs writability → asserts the locked invariants.
  • Child in fully namespaced, rootless, network-less, capability-empty, RO-rootfs environment.

⬜ Phase 6 — The zygote (pre-forked, pre-sandboxed renderer template) §18

Objectives
  • Cheap renderer spawn: COW fork() from a warm zygote vs clone+exec (Phase 3) — eliminate per-spawn loader/relocation cost.
  • Base-then-seal sandbox: zygote pre-applies the intersection-safe base (namespaces from Phase 4, no_new_privs); each fork tightens to the final per-type seccomp (Phase 5) before untrusted code — never loosens.
  • COW page sharing: warmed RX text/.rodata shared across all renderers — measurable RSS savings (shared vs PSS).
  • Single-fork() invariant: zygote stays single-threaded so child is in a consistent address space (no held locks / orphaned threads post-fork).
  • Targets met: spawn latency + sealed-sandbox correctness proven by the two Phase deliverable tests.
Deliverable

sbx run boots a zygote; sbx spawn --zygote --type renderer forks N renderers from it. Each is correctly sandboxed (sealed seccomp + base ns). cargo test -p sbx-zygote passes a spawn-latency test and a sandbox-sealed test. sbx reports per-spawn latency + shared/PSS RSS.

Acceptance

Pitfalls
  • Self-defeating harness — probe kills the reporter: a SIGSYS(KILL) on the renderer's main thread takes the IPC reporter with it → harness sees disconnect, can't distinguish "contained" from "harness bug". Root cause: probe + reporter share a process. Fix: probe in a forked grandchild, reporter waitpids + relays WTERMSIG. Debug: if every case reports "disconnect", the fork split is missing.
  • False-green: sandbox not actually applied: harness runs the payload unsandboxed (forgot policy/use_zygote) → forbidden syscalls "succeed" but harness mislabels expectation, or worse passes. Root cause: launch path bypassed Sandbox::apply. Fix: assert post-seal state (no_new_privs==1, caps empty, seccomp mode==2) before probing; abort if unsealed. Debug: grep Seccomp /proc/<pid>/status must be 2.
  • Fuzzer can't reach the parser: target wraps Message::decode but a length pre-check rejects all inputs first → 100% coverage of the guard, 0% of the decoder → false "0 crashes". Root cause: fuzz harness mis-models the wire boundary. Fix: feed bytes at the exact recv boundary; track coverage, gate on decoder-region hit. Debug: cargo fuzz coverage shows cold decode arms.
  • Errno-vs-Kill ambiguity: a syscall returning ENOSYS could mean "seccomp Errno" OR "kernel lacks it" → conformance test passes for the wrong reason. Fix: pin disposition per nr in expected_dispositions.csv; for KILL rules assert SIGSYS, not errno. Debug: compare against seccomp audit log (SECCOMP_RET_LOG).
  • Benchmark measures the wrong thing: spawn bench includes process teardown / first-touch page faults → p50 inflated, gate flaps (timing window too wide). Fix: time fork→seal→handshake only; warm zygote; pin CPU, disable turbo, drop caches between cold runs. Debug: variance > 20% ⇒ machine noise, not regression.
  • Fuzz FD/mem leak masked by short runs: a per-message FD leak in the broker only OOMs after 10⁶ inputs; a 30 s fuzz misses it. Fix: dedicated long-soak job asserts /proc/<broker>/fd + RSS flat over ≥ 10⁷ iters (plot fd-count slope; nonzero ⇒ leak). TOCTOU in attack timing: traversal probe races broker canonicalization, intermittent pass. Fix: deterministic fixture (pre-created symlink), repeat N×, require all-deny (flaky-only-under-load ⇒ revisit P7 openat2 RESOLVE_BENEATH).
