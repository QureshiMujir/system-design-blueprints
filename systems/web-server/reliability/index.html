I4A written response's body length never disagrees with its own Content-Length header.Framing correctness for the next request on a reused keep-alive connection.response.rs::serialise.httpserver-net byte-count assertion.response_length_mismatch_total.Abort the response, close the connection — framing cannot be repaired mid-stream.
I5max_requests_per_connection (§4) bounds every keep-alive loop.Unbounded connection lifetime starves the accept queue (P6).connection.rs loop counter.fixtures/conn/keep-alive-cap.txt.conn_closed_total{reason="request_cap"}.Server sends Connection: close on the capped response.

I8A handler panic never crashes any connection task other than its own.One bad handler must not take the listener down.dispatcher.rs catch_unwind boundary around Handler::handle.fixtures/handler/panicking-handler.txt.handler_panic_total{handler}.Convert to 500, close only this connection.

I13The keep-alive idle timer runs only while awaiting the first byte of a new request, never mid-request.A slow-but-valid request body must not be killed by the idle timer (distinct from I10/body cap).connection.rs timer reset points.fixtures/conn/slow-body-not-killed.txt.conn_idle_timeout_total vs. conn_body_timeout_total (disjoint counters).Idle timeout closes silently; body timeout returns 408.
