Boxes. listener.rs is the sole owner of the bound socket and the only place accept() is called; it is the queue-admission point (ADR-21) and the concurrency boundary — everything past it runs inside one Tokio task per connection with no shared mutable state except Arc<Router> and Arc<HandlerRegistry> (read-only after startup). connection.rs owns the per-connection byte buffer, the keep-alive timer, and the request-count cap (I5); it is the trust boundary for framing — nothing downstream re-validates framing. dispatcher.rs is a pure wiring layer with one side effect: the catch_unwind boundary (I8) that turns a handler panic into a 500 instead of a task crash. httpserver-proto is intentionally I/O-free and async-free — it is a pure function &[u8] -> Result<Request, ProtoError> and Response -> Vec<u8>, which is what makes it fuzzable (ADR-13) and unit-testable without a runtime. httpserver-router is a total function with no I/O — RouteResult covers Match/MethodNotAllowed/NotFound exhaustively (I3). static_files.rs is the only component that touches the filesystem — a read-only persistence boundary, no writes, no app-level database. tracing_setup.rs/metrics.rs are the external interface for operators — a Prometheus scrape target and a structured-log/trace sink — added in Phase 9 but instrumented from Phase 0 onward (P8). h2_bridge.rs (Phase 8) is a protocol boundary: it terminates HTTP/2 framing and HPACK, then feeds the same Request/Response types into the same dispatcher, so routing and handlers are version-agnostic (P11).

8. Domain Model — Request/Response Lifecycle & Connection State

Core entities and relationships. A Connection owns exactly one TCP socket and cycles through zero-or-more Request/Response pairs before closing. Each Request resolves through exactly one RouteResult (Match/MethodNotAllowed/NotFound) against the shared, read-only Router. A Match names exactly one Handler in the shared, read-only HandlerRegistry, which produces exactly one Response. No entity here is shared mutable state across connections — Router and HandlerRegistry are built once at startup and never mutated after listen() returns, which is what makes them safely Arc-shared without locking (P2, ADR-07).

Connection 1───* RequestCycle
RequestCycle  1───1 Request ──resolve()──> RouteResult
RouteResult   ── Match{handler, params} ──> HandlerRegistry.get(handler) ──> Handler
Handler       ── handle(Request, Params) ──> Response
RequestCycle  1───1 Response ──serialise()──> bytes on the wire

Connection state machine (connection.rs, enforced by I5/I6/I13):

State Entry Condition Exit Condition Notes
Accepted listener.rs accept() returns a socket under the accept semaphore (ADR-21). Immediately transitions to AwaitingRequest. Registered in the shutdown JoinSet (I6) at this instant.
AwaitingRequest Prior response fully written, or fresh connection. First byte read, or idle timeout fires. Idle timer (I13) armed only in this state.
Reading First byte of a new request observed. parse_request returns Complete, or body-read timeout fires. Buffer growth bounded by I10; body timer (I13) armed here, not the idle timer.
Dispatching Parse complete. Handler returns (or panics, caught by I8). No I/O; pure CPU + handler-defined I/O (e.g., Phase 6 filesystem read).
Writing Response serialised. All response bytes written to the socket. HEAD strips body per I7 before this state is entered.
Closing Request cap hit (I5), Connection: close requested, idle/body timeout, or shutdown signal. Socket closed, fd released (I1), task removed from JoinSet. Terminal state — no transition back to AwaitingRequest.

Request/Response field ownership (elaborated fully as signatures in §11): Request owns its method, path, query, version, headers, and body once parsing completes — no borrow outlives the function call that produced it, so a Request can be moved into the dispatcher without lifetime parameters leaking into Handler::handle's signature. Response is handler-authored and core-serialised: handlers never write directly to the socket (P1's boundary discipline extended to the write side).

Router/Handler binding is name-based, not type-based. A Match carries a handler: String name, resolved against HandlerRegistry at dispatch time, not a function pointer baked into the trie at build time. This is a deliberate indirection (P11-adjacent): it lets Phase 9's hot-reload of handler configuration (not code — Rust has no safe hot code reload) swap which named handler serves a route without rebuilding the trie.

Why no ORM-style entity persistence appears here. This domain model has no durable-storage entities (ADR-04) — Connection, Request, Response, and RouteResult are all request-scoped and vanish when the connection closes. The only persistence boundary in the entire system is the read-only static-file tree touched by static_files.rs (Phase 6), which is not part of this request/response domain model — it is treated as an external data source a handler queries, no different in kind from a hypothetical downstream database a future handler might call.
