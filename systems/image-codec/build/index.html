⬜ Phase 0 — Skeleton, Bit I/O, Image Buffer, CI §12

Objectives

Stand up the repo skeleton (§10), the CI pipeline (ADR-25), and the correctness kernel: BitReader/BitWriter (both bit orders), ImageBuffer, DecodeLimits, CodecError. No format-specific parsing yet — this phase proves the shared plumbing every later phase depends on.

Deliverable

pip install -e . succeeds; pytest passes a bit-exact round-trip test of BitWriter→BitReader for both bit orders over a 10,000-bit random sequence; imgcodec identify anything.bin runs without crashing.

Acceptance
  • 100% of BitWriter→BitReader round-trip tests pass for both bit orders, 1,000 randomized sequences, 0 bit mismatches.
  • CI green on a clean checkout in ≤ 3 minutes wall-clock (lint+unit+property stages).
  • DecodeLimits.check() rejects width=0/height=0 in 100% of 20 unit-test cases covering zero/negative/overflow dimensions.
Fixtures
  • conformance/fixtures/bitio/random_msb_10000.bin — random MSB-first bitstream; expected: identical round-trip.
  • conformance/fixtures/bitio/random_lsb_10000.bin — random LSB-first bitstream; expected: identical round-trip.
  • conformance/fixtures/limits/zero_width.json — {width:0,height:100}; expected: CodecError.Malformed.
  • conformance/fixtures/limits/overflow_dims.json — {width:4294967295,height:4294967295}; expected: CodecError.AllocationTooLarge.
Pitfalls
  • Mixing bit orders in one shared BitReader across formats: garbage from byte 0; root cause a "clever" shared reader; debug via a type-level BitOrder mismatch assertion; recovery: separate instantiation per format (P10).
  • Off-by-one in limit accounting: reads one bit past a byte boundary; debug via boundary-value tests (7, 8, 9 bits); recovery: fix modulo arithmetic, keep boundary tests permanently in the fixture set.
  • Checked-multiply omission in DecodeLimits: Python ints don't overflow but a downstream NumPy int32 cast can wrap; debug by tracing the first NumPy array construction; recovery: validate against max_pixels/max_buffer_size in pure-Python space before any NumPy call (I2).

⬜ Phase 1 — PNG Chunk Parser with CRC Validation §13

Objectives

Parse the PNG container: signature, chunk stream, IHDR, CRC-32 validation (I4) — no DEFLATE yet.

Deliverable

A hand-crafted minimal PNG (IHDR + empty IDAT + IEND) parses to correct header fields; imgcodec identify reports them.

Acceptance
  • 100% CRC-mismatch detection over 50 corpus files with a single bit flipped in random chunk data (conformance/fixtures/png/crc_flip_*.png).
  • Chunk-length-exceeds-file-size rejected in 100% of 10 crafted fixtures, 0 OOB reads.
  • IHDR parse round-trips all 5 legal color-type × bit-depth combinations from RFC 2083's table with 0 misclassifications.
Fixtures
  • conformance/fixtures/png/minimal_valid.png — hand-crafted; expected: IHDR fields match a known dict.
  • conformance/fixtures/png/crc_flip_idat.png — one bit flipped in IDAT; expected: CodecError.ChecksumMismatch in strict mode.
  • conformance/fixtures/png/truncated_length.png — chunk length exceeds remaining bytes; expected: CodecError.Malformed("chunk_length").
  • conformance/fixtures/png/idat_before_ihdr.png — reordered chunks; expected: CodecError.Malformed("chunk_order").
Pitfalls
  • Chunk-length endianness confusion (big-endian read as host-endian): absurd length value; recovery: struct.unpack(">I", ...) explicitly, never host-endian.
  • CRC computed over data only, omitting the 4-byte type prefix: every CRC check fails on genuinely valid files; debug against RFC 1952's reference vectors; recovery: include chunk_type bytes in the CRC input.
  • Trusting length before bounds-checking against remaining bytes: Python silently returns a short slice past EOF instead of raising; recovery: explicitly compare length to len(remaining) first (I2, I3).

⬜ Phase 2 — DEFLATE Decode Then Encode §14

Objectives

Implement RFC 1951 DEFLATE — inflate first (own implementation, the conformance path, ADR-11), then deflate — plus the zlib-binding fast path.

Deliverable

inflate(deflate(data)) == data for the full conformance/fixtures/deflate/ corpus, both backends; a hand-crafted stream exercising all three block types decodes correctly.

Acceptance
  • 100% round-trip byte-identity over a 200-file corpus spanning 0 bytes to 10 MiB, both backends (own, zlib).
  • Own-backend inflate throughput ≥ 1 MP/s-equivalent (§4); zlib-backend ≥ 15 MP/s-equivalent (§4).
  • bomb_10kb_to_2gb.bin aborts within max_decode_seconds (2.0 s) and raises AllocationTooLarge, 100% of 20 runs.
Fixtures
  • conformance/fixtures/deflate/stored_block.bin — single stored block; expected: byte-identical round trip.
  • conformance/fixtures/deflate/fixed_huffman.bin — single fixed-Huffman block; expected: byte-identical round trip.
  • conformance/fixtures/deflate/dynamic_huffman.bin — multi-block dynamic-Huffman; expected: byte-identical round trip.
  • conformance/fixtures/deflate/bomb_10kb_to_2gb.bin — crafted high-ratio stream; expected: AllocationTooLarge before full expansion.
  • conformance/fixtures/deflate/truncated_mid_block.bin — cut mid-Huffman-code; expected: CodecError.UnexpectedEof.
Pitfalls
  • Conflating LSB-first bit reads with byte-level multi-bit fields (stored-block LEN is byte-order-normal): silently wrong LEN; recovery: separate "bit-level LSB" reads from "byte-level" reads explicitly.
  • Over-subscribed dynamic Huffman table accepted by a lenient decoder: garbage output instead of a clean reject; recovery: I5's construction-time Kraft-inequality check.
  • Back-reference distance exceeding bytes produced so far: reads uninitialized window memory; recovery: reject if distance > total_output_so_far.
  • Length > distance overlap mishandled as an error instead of the defined repeat behavior: spurious rejects on legal streams; recovery: implement "read what you just wrote" explicitly.
  • Adler-32 (zlib wrapper) vs. CRC-32 (PNG chunks) confusion: validating the wrong checksum; recovery: keep the two checksum implementations in separate modules.

⬜ Phase 3 — PNG Filters and Lossless Round-Trip §15

Objectives

Integrate Phase 2's inflate into the PNG pipeline; implement all five scanline filters' inverse (decode) and forward (encode) forms; reach the first true lossless round trip (I1, P2).

Deliverable

A grayscale and an RGB PNG (no palette, no interlace yet) round-trip byte-identically through encode→decode.

Acceptance
  • 100% byte-identical round trip over conformance/fixtures/png/roundtrip_*.png (20 files, mixed dimensions including 1×1, 1×N, N×1, odd widths).
  • Filter-selection heuristic reduces post-DEFLATE size by ≥15% vs. always-filter-0 on the natural-photograph corpus.
  • Zero row-order violations (I10) across the fixture corpus, asserted in CI.
Fixtures
  • conformance/fixtures/png/roundtrip_1x1.png, roundtrip_1xN.png, roundtrip_Nx1.png — degenerate-dimension round trips; expected: byte-identical.
  • conformance/fixtures/png/filter_byte_invalid.png — filter byte value 5 (illegal); expected: CodecError.Malformed("filter_type").
  • conformance/fixtures/png/all_five_filters.png — each scanline uses a different filter type; expected: correct unfilter per row.
Pitfalls
  • Assuming the "left neighbor" is always 1 byte back: for RGBA8 it's 4 bytes (bpp=4), for 16-bit RGBA it's 8; wrong bpp scrambles color channels while dimensions look correct; debug via a single-pixel-wide test image; recovery: compute bpp from PixelFormat, never hardcode 1.
  • Forgetting the filter-type byte in scanline byte length (1 + ceil(width×bpp_bits/8)): desyncs every row after the first; recovery: a 2-row test image where desync is immediately visible.
  • Treating Average's division as signed instead of floor on a non-negative sum before mod-256 subtraction: recovery: compute in the unsigned/masked domain per the PNG specification's wording.
  • Reading the filtered prior row instead of the reconstructed prior row for Up/Average/Paeth: cascading corruption after row 1; recovery: I10 enforces reconstructed-row use.

⬜ Phase 4 — PNG Color Types, Bit Depths, Adam7 §16

Objectives

Cover all five PNG color types (§8.14) and all five bit depths; implement Adam7 interlacing (decode + encode, ADR-14) per §8.10's pass geometry.

Deliverable

An 8-bit indexed PNG, a 16-bit grayscale PNG, and an Adam7-interlaced RGB PNG all decode to correct, expected pixel data and round-trip losslessly.

Acceptance
  • 100% byte-identical round trip across all 10 color-type × representative-bit-depth combinations in conformance/fixtures/png/colortype_*.png.
  • Adam7 round trip byte-identical for 5 image sizes including two smaller than an 8×8 macro-cell (I9's degenerate case).
  • Palette-index-out-of-range fixture rejected in 100% of 10 crafted cases (I13).
Fixtures
  • conformance/fixtures/png/colortype_palette_8bit.png, colortype_gray_16bit.png, colortype_rgba_1bit.png (synthetic 1-bit RGBA is illegal per RFC 2083 and used as a rejection fixture) — expected: valid ones round-trip, the illegal combination raises Malformed("colortype_depth").
  • conformance/fixtures/png/adam7_5x5.png, adam7_3x3.png — smaller than one macro-cell; expected: correct degenerate pass geometry (I9), byte-identical round trip.
  • conformance/fixtures/png/palette_index_oob.png — index 200 with a 100-entry palette; expected: CodecError.Malformed("palette_index").
  • conformance/fixtures/png/trns_short.png — tRNS shorter than palette; expected: missing entries treated as opaque (255), not an error.
Pitfalls
  • Sub-byte unpacking off-by-one in bit position: manifests as a diagonal-streak corruption pattern; debug via a 1-bit test image with a known checkerboard; recovery: verify against RFC 2083's explicit bit-packing diagram.
  • Adam7 pass dimension arithmetic at small sizes producing negative or zero-but-mishandled pass buffers: manifests as an index error or a silently dropped pass; debug via the adam7_3x3.png fixture; recovery: ceil division per §8.10, clamp to 0, and still sum-check (I9).
  • tRNS array shorter than the palette treated as an error instead of "missing = opaque": manifests as spurious rejects on legal files; recovery: pad reads with 255 up to palette length (documented pitfall, §12.6 of the original salvaged material).
  • 16-bit sample byte order assumed little-endian: manifests as channel values off by a factor of 256; recovery: struct.unpack(">H", ...) explicitly.

⬜ Phase 5 — Colour Transform and Chroma Subsampling §17

Objectives

Begin the JPEG pipeline's pixel-domain half: RGB↔YCbCr color transform (§8.1) and chroma subsampling (4:4:4/4:2:2/4:2:0, ADR-06), independent of DCT/entropy coding.

Deliverable

A standalone color-transform module that converts a synthetic RGB test image to YCbCr and back within the documented fixed-point tolerance, and correctly subsamples/upsamples all three chroma factors.

Acceptance
  • Fixed-point RGB→YCbCr→RGB round trip within ≤1 gray level per channel RMS error over a 10,000-pixel synthetic gradient (P11's precision contract measured concretely).
  • 4:2:0 subsampling reduces chroma-plane byte count to exactly 25% of 4:4:4's, verified arithmetically (ties §34).
  • Bilinear upsample visually and numerically smoother than nearest on a conformance/fixtures/color/edge_step.png synthetic step-edge (measured via a discrete second-derivative check, not "looks smoother").
Fixtures
  • conformance/fixtures/color/known_triples.json — 20 hand-computed RGB→YCbCr pairs; expected: exact fixed-point match.
  • conformance/fixtures/color/gradient_10000px.png — synthetic RGB gradient; expected: round-trip RMS ≤1 gray level.
  • conformance/fixtures/color/edge_step.png — a hard chroma edge; expected: bilinear upsample reduces ringing vs. nearest, quantified by the second-derivative metric.
Pitfalls
  • Off-by-one chroma upsampling at odd image dimensions: a 4:2:0 image with odd width/height has a chroma plane whose dimensions are ceil(width/2), not floor; using floor silently drops the last column/row of chroma data; debug via an odd-dimension fixture; recovery: always ceil chroma-plane dimensions on encode, and replicate the last sample on decode upsample.
  • Using the wrong color-transform matrix (BT.601 vs. BT.709 vs. JFIF's specific rounding constants) inconsistently between encode and decode: manifests as a color-cast round-trip error; recovery: lock to the JFIF constants in §8.1 everywhere, document the choice in ADR-06's rationale.
  • Nearest-neighbor upsampling used silently where bilinear was assumed: manifests as blocky chroma edges the caller didn't expect; recovery: make the upsample strategy an explicit, logged parameter, never a silent default drift.
  • Clamping applied after the fixed-point shift instead of before: manifests as wraparound artifacts near pure black/white; recovery: clamp post-shift, pre-cast-to-uint8, exactly per §8.1's inverse formula order.

⬜ Phase 6 — DCT and Quantization §18

Objectives

Implement the forward and inverse 8×8 DCT (§8.2), separable into row/column 1-D passes (P4), plus quantization/dequantization and the quality-to-scale mapping (§8.3, ADR-05).

Deliverable

A forward-DCT→quantize→dequantize→inverse-DCT round trip on a synthetic 8×8 block matches the worked example in §8.17 within the stated reconstruction-error bound; the fast and reference IDCT agree within tolerance across a 10,000-block corpus.

Acceptance
  • Fast IDCT vs. reference IDCT: max per-sample deviation ≤ 2, RMS ≤ 0.5, over 10,000 randomized quantized blocks (I6's neighbor: precision, not just range).
  • Quality-to-scale monotonicity (I14) holds for all 100 integer quality values, 0 violations.
  • DCT/IDCT round trip (forward then inverse, no quantization) recovers the original block within ≤1 gray level RMS over the same 10,000-block corpus (isolates transform error from quantization error).
Fixtures
  • conformance/fixtures/dct/worked_example_block.json — the §8.17 worked 8×8 block, expected coefficients and reconstruction error at quality 50.
  • conformance/fixtures/dct/random_blocks_10000.npy — randomized synthetic blocks; expected: fast/reference IDCT agreement within tolerance.
  • conformance/fixtures/dct/quality_monotonicity.json — all 100 quality values' derived Q tables; expected: monotonic non-increasing scale.
  • conformance/fixtures/dct/coefficient_overflow.json — a crafted coefficient exceeding category range at quality 1; expected: clamped + jpeg.encode.coefficient_clamped counter increments (I6).
Pitfalls
  • Integer overflow in the IDCT's intermediate precision: a 32-bit accumulator can still overflow if intermediate products aren't bounded (e.g., chaining fixed-point multiplies without intermediate rescale); debug via the coefficient-overflow fixture at extreme quantization; recovery: rescale after each butterfly stage per the AAN paper's documented bit-growth analysis.
  • Color banding from quantization-table rounding: visible at low quality on smooth gradients; root cause: round() vs. floor() inconsistency between encode and the standard's definition; debug via the edge_step-style gradient fixture reused from Phase 5; recovery: lock to round-half-to-even or the standard's exact rounding rule, applied identically encode-side and in any reference comparison.
  • Mixing float64 reference results into the production fixed-point path "just to double check": silently changes production precision; recovery: keep the reference path fully isolated (a separate function, never imported into the hot path).
  • Forgetting the level shift (−128 before DCT, +128 after IDCT): manifests as a globally too-bright or too-dark reconstruction; recovery: unit test a mid-gray (128) flat block, which should DCT to a single nonzero DC and IDCT back to exactly 128.

⬜ Phase 7 — Zigzag, Run-Length, and Huffman Entropy Coding §19

Objectives

Implement zigzag reordering (§8.4), DC differential coding (§8.5), the AC run-length/EOB symbol structure (§8.6), and canonical Huffman construction (§8.7, P5) for JPEG's MSB-first entropy stream.

Deliverable

A known small JPEG's entropy-coded data decodes to the correct zigzag-ordered coefficient blocks, matching a hand-verified expected sequence; the encoder reproduces the same bitstream (modulo standard-vs-optimal table choice) for the same input.

Acceptance
  • 100% correct decode of conformance/fixtures/jpeg/known_block_sequence.bin against a hand-verified expected coefficient sequence.
  • Canonical Huffman round trip (encode table → decode table → identical code assignment) for all four standard tables, 0 mismatches.
  • Fast-table decode throughput ≥ 3× the full-dict-lookup fallback path, measured on a 10 MB entropy-data corpus (feeds the JPEG decode M-target, §30).
Fixtures
  • conformance/fixtures/jpeg/known_block_sequence.bin — a small hand-verified entropy segment; expected: exact coefficient sequence.
  • conformance/fixtures/jpeg/oversubscribed_huffman.bin — a Huffman table with lengths summing past capacity; expected: CodecError.Malformed("huffman_table") (I5).
  • conformance/fixtures/jpeg/dc_predictor_reset.bin — entropy data spanning two restart intervals; expected: DC predictor resets to 0 at each RST marker for all components (I8).
  • conformance/fixtures/jpeg/zrl_run_overflow.bin — a crafted run exceeding 63 total AC positions via repeated ZRL; expected: CodecError.Malformed("zigzag_overflow").
Pitfalls
  • An over-subscribed Huffman table accepted by a lenient decoder: the classic silent-corruption bug in this phase; debug via the oversubscribed_huffman.bin fixture; recovery: I5's Kraft-inequality check at table-build time, shared with Phase 2's DEFLATE tables.
  • Missing DC predictor reset on restart, or resetting only the current component instead of all components (I8): manifests as DC drift/banding a few restart intervals in; debug via dc_predictor_reset.bin; recovery: zero the full predictor vector, not a single scalar.
  • Special-casing 0x00/0xF0 after, rather than before, the general run/category decode: manifests as EOB/ZRL misinterpreted as a run=0/run=15 category-0 symbol, corrupting the rest of the block; recovery: check the two reserved byte values first, unconditionally.
  • Confusing JPEG's MSB-first bit order with DEFLATE's LSB-first when reusing the shared HuffmanTable/BitReader types: recovery: P10's separate-instance rule, enforced by a constructor-level BitOrder requirement (no default).

⬜ Phase 8 — The Full Baseline JPEG Encoder and Decoder §20

Objectives

Assemble Phases 5–7 into a complete baseline (SOF0) JPEG decoder and encoder: marker parsing (§8.13), JFIF/EXIF containers, DQT/DHT/SOF/SOS handling, the full decode state machine (§8.15), and a quality-parameterized encoder.

Deliverable

A real-world baseline JPEG decodes to an ImageBuffer visually and numerically consistent with a reference decoder; the encoder produces a valid, standard-conformant baseline JPEG at a requested quality that a reference decoder (Pillow/libjpeg-turbo) also decodes correctly.

Acceptance
  • Decode: PSNR ≥ 34 dB and SSIM ≥ 0.94 (§4) when comparing this decoder's output to libjpeg-turbo's decode of the same file, over conformance/fixtures/jpeg/photo_corpus/ (30 images).
  • Encode: at quality 75, file size within 5% of libjpeg-turbo's output size on the same corpus, and this decoder's round-trip decode of its own encoded output meets the same PSNR/SSIM bar.
  • Decode throughput ≥ 9 MP/s single-core (§4, M-table §30); encode throughput ≥ 6 MP/s single-core.
  • Zero crashes over the photo_corpus × {4:4:4, 4:2:2, 4:2:0} × {quality 1, 50, 75, 100} matrix (120 combinations).
Fixtures
  • conformance/fixtures/jpeg/photo_corpus/*.jpg — 30 natural photographs; expected: PSNR/SSIM thresholds above vs. libjpeg-turbo.
  • conformance/fixtures/jpeg/grayscale_1component.jpg — single-component (no chroma) baseline JPEG; expected: color-transform stage skipped entirely, correct decode.
  • conformance/fixtures/jpeg/exif_orientation_6.jpg — EXIF orientation tag 6 (90° rotation); expected: orientation exposed in metadata, pixels unrotated unless requested.
  • conformance/fixtures/jpeg/progressive_rejected.jpg — a SOF2 (progressive) file fed to a baseline-only build config; expected: CodecError.UnsupportedFeature("progressive") (superseded once Phase 9 lands).
Pitfalls
  • EXIF orientation silently ignored: many real-world phone-camera JPEGs are stored "sideways" relative to the orientation tag; a decoder that reads pixels without checking or exposing the tag produces a plausible-looking but rotated image the caller didn't ask for; recovery: expose orientation on ImageBuffer.metadata always, apply only on explicit request (ADR-15, P13).
  • The Adobe APP14 marker gotcha: an Adobe-produced JPEG's color-transform interpretation depends on APP14's transform field; assuming YCbCr unconditionally for 3-component frames misreads a small but real subset of files; recovery: check APP14 when present, default YCbCr when absent (Phase 5).
  • Mixing up the four standard Huffman tables (DC-luma, AC-luma, DC-chroma, AC-chroma): produces garbage decode that "almost" works (looks like static); recovery: bind table selection strictly by (component_class, table_class), verified in known_block_sequence.bin (Phase 7).
  • MCU geometry hardcoded for 4:2:0 only, breaking on 4:2:2/4:4:4 inputs: recovery: derive MCU block layout from SubsampleFactor generically, tested against all three factors in the acceptance matrix.

⬜ Phase 9 — Progressive JPEG and Restart Markers §21

Objectives

Extend the baseline decoder/encoder (Phase 8) to progressive JPEG (SOF2): spectral selection and successive approximation scans; implement restart-marker emission on encode (decode support already required by I8 since Phase 7).

Deliverable

A real-world progressive JPEG (multiple SOS scans, spectral selection and successive approximation both present) decodes to the same pixel output as libjpeg-turbo's decode within the §4 tolerance; an encoder-produced progressive JPEG with restart markers round-trips through both this decoder and a reference decoder.

Acceptance
  • Progressive decode matches baseline-equivalent PSNR/SSIM thresholds (§20.4) on a 10-file progressive corpus.
  • Restart-marker round trip: DC drift (banding) absent across 5 restart-interval settings (1, 4, 16, 64 MCUs, and "none"), verified by I8's reset-count metric matching the expected reset count exactly.
  • Zero crashes over a progressive-scan-structure fuzz corpus of 500 crafted files (pathological Ss/Se/Ah/Al combinations), feeding forward into Phase 10's fuller campaign.
Fixtures
  • conformance/fixtures/jpeg/progressive_corpus/*.jpg — 10 real-world progressive JPEGs; expected: PSNR/SSIM thresholds match baseline-equivalent bar.
  • conformance/fixtures/jpeg/restart_interval_16.jpg — encoded with restart_interval=16; expected: exact reset-count match, no banding.
  • conformance/fixtures/jpeg/progressive_bad_spectral_range.jpg — a crafted scan with Ss > Se; expected: CodecError.Malformed("spectral_selection").
  • conformance/fixtures/jpeg/progressive_resource_exhaustion.jpg — a pathological scan count (thousands of tiny scans); expected: rejected under DecodeLimits, not an unbounded-time decode (ties T-class resource exhaustion, §24).
Pitfalls
  • Running IDCT after every scan instead of only the last scan touching a block: manifests as visibly wrong intermediate images treated as final (a correctness bug, not just an efficiency one, if the caller reads the buffer mid-decode); recovery: track a per-block "scans remaining" count derived from the frame's declared scan structure.
  • Successive-approximation bit-position bookkeeping errors (Ah/Al off by one): manifests as a subtly wrong final image (each refinement scan shifts by the wrong bit position); recovery: unit test against the worked spectral-selection/successive-approximation example in ITU-T T.81's informative annex.
  • Restart markers not resetting AC end-of-band run state (progressive AC scans carry their own inter-block run state distinct from DC's per-component predictor): recovery: reset both DC predictors and the AC run-state accumulator at every RST (extends I8).
  • Unbounded scan count from a malicious/pathological file: each SOS is cheap individually but thousands of them can still exhaust decode time; recovery: cap total scan count via DecodeLimits (feeds T12's resource-exhaustion mitigation).

⬜ Phase 10 — Decoder Hardening, Limits, and the Fuzzing Campaign §22

Objectives

Make every prior phase's decoder safe against adversarial input as a first-class deliverable: enforce DecodeLimits everywhere, close every gap the invariants (§7) describe, and stand up the Atheris fuzzing campaign (ADR-24).

Deliverable

Both decoders survive a 1,000,000-iteration Atheris campaign per harness with zero crashes and zero timeouts beyond the declared max_decode_seconds; the CLI rejects a path-traversal probe corpus.

Acceptance
  • Zero crashes, zero hangs beyond max_decode_seconds (2.0 s), over 1,000,000 Atheris iterations per harness (4 harnesses, §22.2).
  • 100% of conformance/fixtures/*/malformed_* and */bomb_* fixtures across all prior phases rejected with the correct CodecError variant (regression-locking every prior phase's hardening claim in one gate).
  • Fault-injection: truncation at every byte offset of a 50-file representative corpus produces either a clean error or a truncated=True partial result, 0 unhandled exceptions (ties I7, §28).
  • Path-traversal probe corpus (20 crafted --output paths) 100% rejected.
Fixtures
  • fuzz/corpus/png_seed/*, fuzz/corpus/jpeg_seed/* — seed corpora derived from every prior phase's conformance fixtures, used as Atheris's starting corpus.
  • conformance/fixtures/hardening/truncate_matrix/ — every representative file truncated at every byte offset (generated, not hand-authored); expected: clean error or partial result, per I7.
  • conformance/fixtures/hardening/path_traversal_probes.json — 20 crafted output-path strings (../../etc/passwd, absolute paths, symlink-adjacent names); expected: CodecError.Malformed("output_path").
  • conformance/fixtures/hardening/exif_gps_present.jpg — EXIF with GPS tags; expected: gps_present=True, stripped on default re-encode.
Pitfalls
  • A fuzz harness that catches too broadly (e.g., a bare except Exception: pass inside the harness itself) silently hides real crashes; recovery: the harness re-raises anything that isn't a documented CodecError subclass, so Atheris sees the real crash.
  • Timeout-as-hang vs. timeout-as-slow-but-correct ambiguity: a very large but legitimate image can look like a hang under a naive timer; recovery: the max_decode_seconds bound is checked against the declared image size's expected decode time (scaled from the M-table), not a flat constant, avoiding false-positive "hangs" on large legitimate inputs while still catching true bombs.
  • Path-traversal checks applied only to the literal string, missing symlink-based traversal: recovery: resolve the real path (os.path.realpath) and check it remains within the configured output directory, not just a string-prefix check.
  • Stripping EXIF metadata by default breaking a caller that genuinely wanted round-trip metadata preservation: recovery: make retention an explicit, documented opt-in (ADR-15) rather than a silent behavior change mid-project.

⬜ Phase 11 — Quality-Metrics Harness, Conformance Suite, and Perf Hardening §23

Objectives

Ship the PSNR/SSIM/bpp measurement harness (imgcodec.metrics) as a first-class module (P12), assemble the full conformance suite (spec vectors + differential + regression), and close out performance work against the M-table (§30).

Deliverable

conformance/run.py executes the full suite (spec vectors, differential, fuzz-regression fixtures, invariant assertions) in one command with a pass/fail summary; imgcodec measure a.png b.png prints a QualityReport; the M-table's throughput targets are gated in CI.

Acceptance
  • conformance/run.py reports 100% pass on the full fixture corpus (all prior phases' fixtures combined, ≥ 400 files) with 0 skipped-without-reason entries.

Pitfalls
  • A quality-harness bug (e.g., an off-by-one in the SSIM windowing) silently produces plausible-but-wrong numbers that then get trusted as ground truth for every other acceptance criterion in this document; recovery: validate the harness itself against Wang et al. 2004's published reference SSIM values on a known test pair before trusting any downstream number (P12).
  • Conformance suite "passing" because a fixture was silently skipped (e.g., a missing test-vector file treated as a soft skip instead of a hard failure); recovery: conformance/run.py treats a missing fixture as a failure, never a skip, unless explicitly marked xfail with a tracked reason.
  • Perf-regression gate flaky due to CI-runner noise (shared-tenancy variance): recovery: run each benchmark 5× and gate on the median, not a single sample, per §30's methodology.
  • Differential testing against a reference decoder's own known bugs (treating a reference-decoder quirk as ground truth): recovery: P3's conformance-outranks-reference-agreement principle — spec-vector failures always outrank differential disagreement.
