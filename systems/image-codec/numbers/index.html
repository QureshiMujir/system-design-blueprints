34. Back-of-Envelope Capacity Model

  1. Raw vs. compressed size, 1920×1080 RGB24. Raw = 1920×1080×3 = 6,220,800 bytes (≈ 6.22 MB). At the JPEG q75 target ratio (10:1–15:1, §4), compressed ≈ 6,220,800 ÷ 12 (midpoint) ≈ 518,400 bytes. Bits per pixel = (518,400 × 8) ÷ (1920×1080) ≈ 2.0 bpp, versus 24 bpp raw.

  2. Block count and DCT multiply count, 1920×1080, 4:2:0. Luma blocks = ceil(1920/8) × ceil(1080/8) = 240 × 135 = 32,400. Chroma planes (each halved both axes) = ceil(960/8) × ceil(540/8) = 120 × 68 = 8,160 per plane × 2 planes = 16,320. Total blocks ≈ 48,720. Naive separable DCT: 1024 mults/block × 48,720 ≈ 49.9M multiplies. AAN (M10): 176 mults/block × 48,720 ≈ 8.57M multiplies — a 5.8× reduction, matching M10 exactly.

  3. Decoder memory, 1920×1080 RGBA8. Decoded buffer = 1920×1080×4 = 8,294,400 bytes (≈8.3 MB). JPEG working set adds ≈3 YCbCr planes (≈0.75×buffer, accounting for 4:2:0 chroma) + a float64 DCT staging copy (≈2×buffer) + a dequantized-coefficient array (≈1×buffer) ≈ 8.3 MB × (1 + 0.75 + 2 + 1) = 8.3 MB × 4.75 ≈ 39.4 MB, i.e. ≈4.75× the decoded buffer — within the §4/M8 6× ceiling with headroom.

  4. Decompression-bomb ratio and the resulting hard limit. DEFLATE's back-reference model (length ≤258, distance ≥1) can in principle repeat a pattern to compression ratios exceeding 1000:1. For the 8,294,400-byte declared image above, I11's bomb_ratio_multiple=4 caps allowed decompressed bytes at 4 × 8,294,400 ≈ 33.2 MB regardless of input compactness — the mechanism enforcing §4's ≤3× declared-size allocation bound (set below the 4× inflate-check ceiling so the allocator's own cap fires first).

  5. Chroma-subsampling data saving, 4:2:0 vs. 4:4:4. 4:4:4 chroma bytes, 1920×1080 = 2 planes × 1920×1080 = 4,147,200. 4:2:0 chroma bytes = 2 planes × (960×540) = 1,036,800. Fraction = 1,036,800 ÷ 4,147,200 = 0.25 exactly — matching §17.4's acceptance criterion precisely.

  6. PSNR from a measured MSE at quality 75. Assume a corpus-measured MSE ≈ 8.0 (gray-level² units): PSNR = 10 log10(255² ÷ 8.0) = 10 log10(65,025 ÷ 8.0) = 10 log10(8,128.1) ≈ 10 × 3.910 = 39.1 dB — comfortably above the §4 34 dB floor, showing the floor has real headroom for a worse-than-typical corpus image.

  7. Adam7 per-pass pixel counts summing to the total, 16×16 image. Pass 1: 2×2=4. Pass 2: 2×2=4. Pass 3: 4×2=8. Pass 4: 4×4=16. Pass 5: 8×4=32. Pass 6: 8×8=64. Pass 7: 16×8=128. Sum = 4+4+8+16+32+64+128 = 256 = 16×16 exactly, verifying I9 arithmetically.

  8. Startup table-construction cost. 4 standard Huffman tables × ≤256 symbols ≈ 1,024 canonical-code assignments, plus building each table's 256-entry fast_lookup ≈ 1,024 more operations ≈ 2,048 total operations at import. Even at a pessimistic 25,000 ops/ms Python rate, this is <1 ms — well inside the <50 ms M12/§4 startup budget, leaving the remainder for module import and NumPy initialization.
