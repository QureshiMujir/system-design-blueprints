⬜ Phase 1 — abc-digest: Streaming SHA-256, Verify-on-Write/Read, Negotiation §13

Objectives
  • Production-quality streaming hash in abc-digest; SHA-256 primary, SHA-512 + BLAKE3 pluggable.
  • VerifyingWriter and VerifyingReader adapters: hash-while-streaming, assert at finalize.
  • Digest function negotiation: select function from ServerCapabilities; default SHA-256.
  • Hex encoding/decoding: lowercase, validated length per function.
  • Throughput benchmark: ≥ 2 GB/s for SHA-256 streaming on 4-core machine.
Deliverable
  • abc-digest fully implemented; all tests pass.
  • abc-cas::put() uses VerifyingWriter; DigestMismatch returned for corrupt upload.
  • Benchmark reports ≥ 2 GB/s SHA-256 throughput.
  • cargo test -p abc-digest passes all unit + integration tests.
Acceptance
  • SHA-256 vectors: empty, "abc", 1 MB random bytes — all match reference digests.
  • VerifyingWriter: corrupt last byte → DigestMismatch; truncated data → SizeMismatch.
  • VerifyingReader: same cases as writer.
  • Benchmark: p50 throughput ≥ 2 GB/s on CI machine (c5.2xlarge or equiv).
  • abc-cas::put() with wrong digest returns AbcError::DigestMismatch and leaves no file at addressable path.

⬜ Phase 3 — abc-store: Memory LRU Tier, Metadata Index, Tier Promotion/Demotion §15

Objectives
  • MemoryTier: bounded in-memory LRU with configurable byte ceiling.
  • MetadataIndex (BlobMeta): tracks size, atime, refcount, compressor, tier for every blob.
  • TieredStore: routes put/get across memory → disk (→ remote stub); on get miss, promote from disk to memory.
  • Crash-safe index: persist BlobMeta to disk (bincode file) on background flush; reload on startup.
  • Demotion: when memory tier > high_watermark, evict LRU entries to disk.
Deliverable
  • TieredStore passes tiered integration tests: put small blob → found in memory; put large blob → disk only; get disk blob → promoted to memory; memory full → LRU eviction to disk.
  • MetadataIndex survives crash: restart + reload; blobs still accessible.
  • usage_bytes() = memory_bytes + disk_bytes; exposed in metrics.
Acceptance
  • Memory tier evicts to disk when current_bytes > max_bytes; no panic, no data loss.
  • Index reload: put 1000 blobs, kill process, restart, get all 1000 → all found.
  • Tier promotion: 100 get calls on disk-only blobs → all promoted to memory within 100 calls.
  • touch() updates atime; LRU order is correct (most-recently used stays, least-recently used evicted first).
  • usage_bytes() within 1% of true value (AtomicU64 may have brief races).

Fixture Purpose

  • DashMap + LRU list inconsistency → DashMap shard lock and Mutex<LinkedList> are separate; get() acquires map shard lock then LRU lock → consistent lock order: always map-then-LRU to avoid deadlock.

⬜ Phase 4 — abc-grpc ByteStream: Resumable Write/Read, Backpressure, QueryWriteStatus §16

Objectives
  • Implement google.bytestream.ByteStream gRPC service in abc-grpc/src/bytestream.rs.
  • Write (client-streaming): parse upload resource name, stream chunks to abc-cas via temp write, support resumption via QueryWriteStatus, enforce committed_size monotonicity.
  • Read (server-streaming): parse blob resource name, stream blob in configurable chunks with read_offset + read_limit.
  • QueryWriteStatus: return committed_size and complete for an in-progress upload UUID.
  • Backpressure: limit concurrent in-flight write streams; drop new connections when at capacity.
Deliverable
  • abcd serve accepts ByteStream Write (full + resumable) and Read from a gRPC client.
  • bazel build with --remote_cache=grpc://localhost:8980 (empty AC) successfully uploads blobs.
  • QueryWriteStatus returns correct committed_size for in-progress uploads.
  • Concurrent 8-stream write test: all 8 complete without corruption.
Acceptance
  • Upload 10 MB blob: Write RPC streams 20×512 KB chunks; WriteResponse.committed_size = 10485760.
  • Resume: interrupt write at 5 MB; QueryWriteStatus returns committed_size=5242880; re-send from offset 5242880; upload completes.
  • Read: Read with read_offset=1024, read_limit=2048 returns exactly 2048 bytes starting at byte 1024.
  • committed_size must equal digest.size_bytes exactly on completion.
  • Corrupt upload: DigestMismatch error returned; blob absent from CAS.
  • Backpressure: 256 concurrent Write RPCs → 240 queued, 16 active; no panic; queued return in order.

Fixture Purpose

  • Resource name in second message not first → per REAPI spec, resource_name is in every WriteRequest; only validate on first message; ignore on subsequent (or assert consistent).

⬜ Phase 10 — abc-gc: LRU Eviction, Size Watermarks, AC→CAS Mark-Sweep, Refcounting §22

Objectives
  • Production GC in abc-gc: LRU size-watermark eviction loop + AC→CAS reachability mark-sweep.
  • Watermark: evict when usage > high; stop at low; never evict blob with refcount > 0.
  • Reachability: mark all CAS blobs reachable from live AC entries; sweep unreferenced blobs.
  • Atomic eviction: unlink() only after refcount == 0; no torn reads.
  • Background sweeper task: triggered by timer + manual abc gc command.
Deliverable
  • GcSweeper background task runs; abc gc command triggers immediate sweep.
  • After GC: usage ≤ low_watermark; all live AC entries' output blobs still present.
  • Refcount guard: upload in progress not evicted.
  • abc stats shows current usage, watermarks, last GC timestamp.
Acceptance
  • Fill to 110% of high watermark → GC runs → usage drops to ≤ low_watermark within 30 s.
  • AC-referenced blob survival: 1000 AC entries; GC runs; all referenced output blobs still present.
  • In-flight upload: refcount = 1 blob → GC skips it; refcount drops to 0 after commit → GC may evict on next cycle.
  • evict_lru_until() returns freed bytes ≥ (usage_before - low_watermark).
  • Mark-sweep: 10 orphan CAS blobs (no AC reference) → all evicted; 10 live AC-referenced blobs → none evicted.
Fixtures
Fixture Purpose
gc_overfull.json Cache at 120% high_watermark; 20 AC entries; expect GC evicts unreferenced only
gc_refcount_guard.json Upload session active; GC runs; expect upload blob not evicted
gc_mark_sweep.json 10 orphan blobs, 10 AC-ref blobs; expect orphans swept, AC-ref survive
Pitfalls
  • GC evicts blob between contains() and get() → race window; mitigate: incref() before returning from get(); decref() when caller drops reader.
  • Mark-sweep misses blob referenced by AC entry added after mark phase → mark-sweep runs while UpdateActionResult is executing; mitigation: hold AC read-lock during mark phase.
  • atime clock skew → LRU order depends on SystemTime; on VM with clock drift, LRU may misjudge recency; use monotonic counter as atime alternative.
  • Freed bytes double-count → usage_bytes AtomicU64 decremented on delete(); GC also tracks freed; ensure only one path decrements.
  • High == Low watermark → degenerate; validate high > low in config; else GC would loop infinitely.
