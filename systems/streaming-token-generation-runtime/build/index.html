⬜ Phase 0 — Repo Skeleton, Core Types, Executor/Tokenizer Traits, Mock Executor, Single-Sequence Greedy Decode Loop, In-Process Streaming

Objectives

Stand up the workspace; define stg-types (IDs, GenerationRequest, SamplingParams, StreamEvent, ModelExecutor/Tokenizer traits); ship a deterministic mock executor (synthetic logits) + a real tokenizer; implement a single-sequence greedy decode loop (max_num_seqs=1, full-row KV stub) that streams tokens through an in-process channel and stops on EOS/max_tokens.

Deliverable

stgrt run --prompt "hello" --max-tokens 32 runs greedily against the mock executor, prints each streamed token delta + Done{reason}; cargo test green; Miri clean on KV-stub scalar paths.

Acceptance
  • Greedy output equals reference greedy decode of the mock executor's logits (exact, differential).
  • Stops correctly on EOS and on max_tokens (both fixtures).
  • Stream emits monotonic pos 0..n with no gaps (I1).
  • Exactly one terminal Done event (I12).
Fixtures
  • requests/greedy_basic.json, requests/stop_eos.json, requests/stop_maxlen.json. golden_streams/p0_greedy.txt. Malformed: requests/prompt_too_long.json (PromptTooLong), requests/bad_param.json (InvalidParam).
Pitfalls
  • Detokenize-after-each-token re-decodes whole sequence → O(n²) text growth. Root: calling full decode per token. Debug: detok time grows with position. Recover: incremental detok (proper fix §2); here document the stub limit.
  • TTFT measured from wrong point → misleading metric. Root: timer started after prefill. Debug: TTFT≈0. Recover: start at request receipt, stop at first delta emit.
  • Mock executor nondeterministic (uses RNG/time) → replay impossible later. Root: impure logits. Debug: two runs differ. Recover: logits a pure fn of (position, history).
  • EOS token id mismatch between tokenizer + executor → never stops or stops early. Root: vocab disagreement. Debug: runs to max_tokens always. Recover: assert tokenizer.eos_id consistent with executor vocab.

⬜ Phase 1 — Admission + Validation + Bounded Queue, Request Lifecycle State Machine, Multi-Request (still single-seq batch)

Objectives

Build the front of the pipeline: stg-admit (tokenize → validate → assign deadline → bounded per-class FIFO queue with backpressure), the full request lifecycle state machine (§8.1), and a scheduler that pulls from the queue and runs requests one at a time (batching lands §5). Establish the first backpressure point.

Deliverable

Multiple requests submitted concurrently are queued, validated, and processed FIFO-within-class one at a time; queue-full yields 429; lifecycle states visible in traces.

Acceptance
  • Validator rejects 6 malformed requests with correct RequestError/HTTP code.
  • Queue-full backpressure: 1025th request (cap 1024) rejected with 429 + Retry-After.
  • FIFO-within-class order deterministic across runs (I13).
  • Lifecycle transitions match §8.1 for all fixtures (no illegal transitions).
Fixtures
  • requests/valid_batch_10.json, requests/queue_overflow.json, requests/invalid_*.json (6 variants). golden_streams/p1_fifo_order.txt. State-machine fixture: conformance/requests/lifecycle_transitions.json.
Pitfalls
  • Tokenization cost unbounded (huge prompt) → admission itself a DoS vector. Root: tokenize before length check. Debug: CPU spike on giant payload. Recover: cap raw byte length before tokenizing; stream-tokenize with early abort.
  • Queue unbounded → memory blow-up under load spike. Root: no cap. Debug: RSS grows with arrivals. Recover: bounded queue + reject (principle 6/12).
  • Priority inversion / starvation of Bulk class. Root: Interactive always wins. Debug: Bulk requests never scheduled. Recover: weighted fairness / aging (fuller policy §10).
  • Illegal state transition (e.g., Finished→Running) silently corrupts. Root: missing guard. Debug: state assert. Recover: explicit transition table + assert.

⬜ Phase 2 — Tokenizer Integration + Incremental Detokenization (partial UTF-8 / multi-token glyphs), Streaming Correctness

Objectives

Solve the deceptively-hard streaming problem: incremental detokenization that never emits a broken UTF-8 code point or a partial multi-token glyph (I3), while staying O(1) per token (no full-sequence re-decode). Wire the real Tokenizer (BPE/byte-level) and a DetokState that buffers across token boundaries.

Deliverable

A sequence generating multi-byte CJK / emoji / combining-character text streams correct incremental UTF-8; concatenated deltas equal the full decode; no mojibake mid-stream.

Acceptance
  • For every detok fixture, concat(deltas) == tokenizer.decode(all_tokens) (exact, the I3 oracle).
  • No delta ever contains invalid UTF-8 (invalid_utf8_emitted == 0).
  • Detok ≤ 5 µs/token p99 (incremental, no re-decode).
  • Truncation mid-glyph handled deterministically (golden fixture).
Fixtures
  • detok/ascii.json, detok/cjk.json, detok/emoji_4byte.json, detok/combining_marks.json, detok/byte_fallback.json, detok/truncated_midglyph.json. golden_streams/p2_detok_*.txt.
Pitfalls
  • Emitting a half code point → client renders U+FFFD garbage. Root: decoding without checking completeness. Debug: invalid-UTF-8 counter > 0; visual mojibake. Recover: buffer trailing bytes until valid (I3).
  • O(n²) re-decode (decode whole prefix each token). Root: stateless decode. Debug: detok time grows with position. Recover: stateful incremental decode with byte buffer.
  • Stop string spans tokens but detok already emitted past it → over-emit beyond stop. Root: stop check after emit. Debug: text past stop string visible. Recover: stop-match buffer reserves potential-stop suffix before emitting (cross-link §6).
  • Combining characters / graphemes split → cursor/rendering glitches (acceptable per policy, but document). Root: code-point not grapheme boundary. Debug: grapheme fixture. Recover: optional grapheme-cluster buffering (UAX #29).
  • Tokenizer leading-space / SentencePiece ▁ handling → spurious/ missing spaces. Root: special-prefix semantics. Debug: spacing diff vs oracle. Recover: respect tokenizer's decode conventions.

⬜ Phase 3 — Paged KV-Cache: Fixed-Size Block Allocator, Block Tables, Slot Mapping, Free-List, Utilization Accounting

Objectives

Replace the full-row KV stub with the project's heart: a paged KV allocator (stg-kv) — fixed-size blocks, per-sequence block tables, a free-list, slot mapping for the executor, and exact utilization/fragmentation accounting. Enforce no-overcommit (I4), valid block tables (I5/I11), and conserve-on-free (I8).

Deliverable

A sequence's KV is paged into blocks; block table grows/shrinks correctly; the executor reads/writes via slot mapping; pool utilization + fragmentation reported; freeing a sequence returns exactly its blocks (balance == 0).

Acceptance
  • Output identical to the full-row KV stub (differential — paging is transparent to results).
  • Σ live blocks ≤ capacity always (I4); alloc past capacity → PoolFull/NeedPreemption.
  • Per-seq alloc/free balance == 0 over lifetime (I8); no leak across 10k seq churn.
  • Internal fragmentation ≤ block_size/seq_len bound; external ≈ 0; total ≤ 4% on realistic length mix.
Fixtures
  • requests/paged_basic.json (long enough to span many blocks), requests/many_short.json (churn), requests/pool_exhaust.json (hit PoolFull). golden_streams/p3_paged.txt (== p0 greedy). KV ledger fixture: conformance/requests/kv_balance.json.
Pitfalls
  • Block leak on early termination (cancel/error path doesn't free) → capacity bleeds. Root: free only on normal finish. Debug: kv_block_leak > 0 under churn. Recover: RAII / free on every terminal transition (I8).
  • Block table off-by-one at block boundary → reads stale/wrong KV → wrong tokens. Root: allocating a block one token early/late. Debug: output diverges at multiples of block_size; kv_append_gap. Recover: allocate when pos % block_size == 0 after append (I11).
  • Slot mapping wrong offset → executor writes K,V to wrong slot → cross-token bleed within seq. Root: offset math. Debug: differential at block edges. Recover: offset = pos % block_size; unit-test the mapping.
  • Fragmentation undercounted → false "plenty of memory" while OOMing. Root: counting only used blocks, not partial waste. Debug: util says 50% but allocs fail. Recover: account internal waste explicitly.
  • Pool capacity miscomputed from kv_layout → device OOM at runtime. Root: wrong dtype/shape bytes. Debug: executor OOM on first big batch. Recover: capacity = device_kv_bytes / block_bytes; assert against executor.

⬜ Phase 4 — Scheduler Step Loop: Prefill/Decode Separation, Chunked Prefill, Batch Descriptor + Slot Mapping, Budget Enforcement

Objectives

Build the real step loop (stg-sched/step.rs): one step = one ModelExecutor.forward over a batch that mixes prefill chunks + decodes, under max_num_seqs / max_num_batched_tokens budgets (I10). Separate prefill from decode; implement chunked prefill (principle 11) so a long prompt cannot freeze the batch. Still few sequences (full continuous add/evict is §5).

Deliverable

Several sequences run through a single step loop with mixed prefill/decode batches; long prompts are chunk-prefilled; per-step budgets enforced; step metrics emitted.

Acceptance
  • Multi-seq results identical to running each seq alone (differential — batching transparent to output, I7).
  • Σtokens_in_step ≤ max_num_batched_tokens and seqs ≤ max_num_seqs every step (I10).
  • Chunked prefill: a 4096-token prompt does not raise other seqs' inter-token gap beyond TPOT budget.
  • Scheduler step overhead ≤ 0.5 ms p99 (excluding executor).
Fixtures
  • requests/mixed_prefill_decode.json, requests/long_prompt_chunked.json, requests/budget_overflow.json. golden_streams/p4_mixed.txt. logits_traces/p4_*.json (mock executor outputs for replay).
Pitfalls
  • Monolithic prefill of a huge prompt → one giant step freezes all decodes → TPOT cliff. Root: no chunking. Debug: periodic ITL spikes correlated with new long prompts. Recover: chunked prefill (principle 11).
  • Decodes starved by prefill → running seqs stall. Root: prefill scheduled before decode. Debug: n_decode drops when prefills present. Recover: decode-first ordering (§8.5 rule 3).
  • Batch order vs logits row order mismatch → tokens assigned to wrong seqs → cross-seq corruption. Root: descriptor/logits index drift. Debug: differential per seq. Recover: canonical batch order; assert logits row count == seqs (I2 fail-closed).
  • Budget off-by-one → executor over-allocated → OOM. Root: counting prefill tokens wrong. Debug: step_token_count > budget. Recover: assert pre-forward (I10).
  • Slot mapping for prefill chunk spans block boundary → partial-block write bug. Root: chunk not aligned to block. Debug: KV diff at chunk edges. Recover: map each token's slot independently; don't assume contiguity.

⬜ Phase 5 — Continuous (In-Flight) Batching: Add/Evict Sequences Mid-Batch, KV-Aware Batch Composition, Free-On-Finish

Objectives

The defining feature: continuous batching — sequences join the running batch the moment they're admitted and leave the instant they finish, every step, without waiting for batch-mates (principle 1). Wire KV availability into batch composition: only add a Waiting seq if its prefill KV can be allocated; free a finished seq's KV the same step (I8) for immediate reuse.

Deliverable

Under a stream of arrivals with varied lengths, the batch continuously fills as sequences finish; GPU (mock) stays busy; short requests do not wait for long ones; KV freed-and-reused within a step.

Acceptance
  • Continuous-batching throughput ≥ 5× a static-batching baseline on a mixed-length trace (the core win).
  • A short request's TTFT is unaffected by a concurrent long request (no head-of-line blocking, principle 1).
  • Results identical to single-seq runs (differential, I7) — composition does not change outputs.
  • KV freed within ≤1 step of finish (I8); utilization stays high without leak.
Fixtures
  • traces/mixed_lengths.json (short+long interleaved), traces/burst_arrivals.json, requests/static_vs_continuous.json. golden_streams/p5_continuous.txt. logits_traces/p5_*.json.
Pitfalls
  • Waiting for batch to fill before forward (accidental static batching) → idle device + TTFT spikes. Root: gating forward on batch size. Debug: low batch_occupancy early; TTFT high. Recover: forward every step regardless of fill (continuous).
  • Finished seq's KV not reclaimed same step → capacity lags churn → false KV pressure. Root: reclaim deferred. Debug: utilization high while seqs finished. Recover: reclaim at step start (rule 1).
  • Adding a seq mid-batch without KV check → over-allocate → OOM. Root: admit-then-alloc. Debug: kv_alloc_fail spikes. Recover: alloc-gated admission (rule 2/5).
  • Long sequence monopolizes a slot forever → fairness starvation. Root: no max-seq-len / no preemption. Debug: same seq present 1000s of steps. Recover: max_tokens cap + preemption (§8).
  • Batch-composition nondeterminism (set iteration order) → replay divergence. Root: HashSet iteration. Debug: replay diff. Recover: deterministic ordering (admit_seq order, I7/I13).

⬜ Phase 6 — Sampling Pipeline: Logit Processors (penalties, bias, min-p), Top-k / Top-p / Temperature, Stop Conditions, Deterministic Seeding

Objectives

Implement the full sampling pipeline (stg-sample, §8.6): ordered logit processors (logit_bias, repetition/presence/frequency penalty), temperature, top-k, top-p (nucleus), min-p, then a per-request-seeded multinomial draw (I14), then stop logic (EOS, stop strings across token boundaries, max_tokens). Deterministic under fixed seed (principle 7).

Deliverable

Requests with temperature/top-k/top-p/min-p/penalties/logit-bias/stop-strings produce correct, reproducible (seeded) token streams; stop strings spanning tokens are caught exactly.

Acceptance
  • Greedy (T=0) matches argmax exactly; sampled output reproducible bit-for-bit under fixed seed across 100 runs (I7/I14).
  • Top-k/top-p/min-p distributions match the reference oracle (HF) under fixed seed (exact token sequence).
  • Stop string spanning two tokens detected; no text emitted past the stop (cross-link §2 I3).
  • max_tokens honored exactly (length finish).
Fixtures
  • sampling/greedy.json, sampling/topk40.json, sampling/topp95.json, sampling/minp.json, sampling/penalties.json, sampling/logit_bias.json, sampling/stop_multitoken.json, sampling/seed_repro.json. golden_streams/p6_*.txt (seed→tokens golden vs HF oracle).
Pitfalls
  • Shared/global RNG → non-reproducible sampling + cross-seq interference. Root: thread_rng. Debug: replay diff; rng_shared_state. Recover: per-seq SeqRng seeded from request (I14).
  • Processor order wrong (e.g., temperature before penalties) → different distribution than the spec/oracle. Root: order drift. Debug: differential per processor. Recover: fixed order (§8.6).
  • Top-p sort over full vocab every token → expensive. Root: naive sort of 32k–128k logits. Debug: sampler time dominates step. Recover: top-k pre-filter then top-p on the survivors; partial select.
  • Stop string emitted before detection → over-emit. Root: emit before stop-match. Debug: text past stop visible. Recover: reserve potential-stop suffix in detok buffer (§2/§6 coupling).
  • Penalty applied to prompt tokens unintentionally → distorted output. Root: history includes prompt when it shouldn't (or should — policy). Debug: differential vs oracle with/without prompt. Recover: configurable; match oracle semantics.
  • Float nondeterminism in softmax across runs → seed repro fails. Root: non-deterministic reduction. Debug: tiny logit diffs. Recover: deterministic reduction order; fixed dtype.

⬜ Phase 7 — Streaming Transports: SSE + HTTP Chunked + gRPC Server-Streaming + WebSocket, Cancellation, Heartbeats, Per-Seq Backpressure

Objectives

Expose the runtime to real clients (stg-server): SSE (text/event-stream), raw HTTP chunked, gRPC server-streaming, WebSocket — all emitting StreamEvents incrementally. Implement cancellation (client disconnect → CancelToken → KV freed next step, I8), heartbeats (keep-alive), and per-sequence backpressure (a slow client throttles only its own seq, principle 6).

Deliverable

A real curl -N SSE client and a gRPC client both receive incremental tokens; disconnecting the client frees KV within a step; a deliberately-slow client does not stall other clients' streams.

Acceptance
  • SSE/gRPC/WS each stream tokens incrementally; concatenated payload == full completion (I3 end-to-end).
  • Client disconnect → KV freed ≤ 1 step (I8); kv_block_leak stays 0 under disconnect churn.
  • Slow-client isolation: a client reading at 1 token/s does not raise other clients' TPOT (principle 6) — verified under load.
  • Exactly one terminal event per stream (I12); [DONE] sentinel sent on SSE.
Fixtures
  • requests/sse_stream.json, requests/grpc_stream.json, requests/ws_stream.json, requests/cancel_midstream.json, requests/slow_client.json. golden_streams/p7_sse_frames.txt (frame-level). SSE frame fuzz corpus seed.
Pitfalls
  • Unbounded stream channel → slow client buffers entire response in memory → OOM + head-of-line blocking. Root: unbounded mpsc. Debug: RSS grows with slow clients; others' TPOT spikes. Recover: bounded channel + per-seq throttle (principle 6).
  • Disconnect not detected → KV leaks for abandoned streams. Root: no drop/poll-cancel wiring. Debug: kv_block_leak>0 with client churn; capacity bleeds. Recover: CancellationToken on connection drop → free next step (I8).
  • Cancellation races the step (free while executor reading the block) → use-after-free. Root: freeing mid-forward. Debug: kv_double_free/corruption. Recover: free only at step boundary (single-writer, I2), never mid-forward.
  • Two terminal events (Done then Error, or duplicate Done) → client contract break. Root: finalize called twice. Debug: stream_double_terminal. Recover: terminal-once flag (I12).
  • Proxy buffers SSE (no incremental delivery) → client sees nothing until end. Root: missing X-Accel-Buffering: no / flush. Debug: client gets one big chunk. Recover: disable proxy buffering; flush per event; heartbeats.
  • gRPC backpressure ignored → same OOM as SSE. Root: unbounded send. Debug: memory. Recover: bounded send + flow control.

⬜ Phase 8 — Preemption Under Memory Pressure: Swap-Out vs Recompute, Victim Selection, Restore, No-Thrash Policy

Objectives

Make the runtime survive KV exhaustion gracefully (principle 15): when the pool is full and a running/admitting seq needs a block, preempt a victim — either swap its KV blocks to host/NVMe (SwapStore) and restore later, or recompute (drop blocks, re-prefill on resume). Implement victim selection, restore, and a no-thrash policy. Conserve blocks across preemption (I8).

Deliverable

Under deliberate over-subscription, the runtime preempts victims (swap or recompute), continues making progress, restores preempted seqs, and avoids thrash — no process OOM, no wrong output.

Acceptance
  • Over-subscribed workload completes all requests correctly (differential, I7) with preemption, no OOM (I4).
  • Preempted-then-restored seq produces identical output to a never-preempted run (I7) — swap/recompute is transparent.
  • Block conservation across preempt/restore: alloc==free balance holds (I8); no leak/double-free.
  • Thrash bounded: preemption rate < a configured ceiling under steady over-subscription; near-done seqs not preempted.
Fixtures
  • requests/oversubscribe_swap.json, requests/oversubscribe_recompute.json, requests/preempt_restore_identity.json, requests/thrash_attempt.json. golden_streams/p8_preempt.txt (== non-preempted). logits_traces/p8_*.json.
Pitfalls
  • Preemption thrash (preempt A to run B, then preempt B to run A) → progress collapses. Root: victim policy ignores progress / no hysteresis. Debug: preemptions high, tokens/s low, same seqs cycling. Recover: protect near-done seqs; hysteresis; reject-over-preempt (principle 15).
  • Swap I/O blows the step budget → TPOT cliff for the whole batch. Root: synchronous large swap mid-step. Debug: ITL spike correlated with swaps. Recover: bound swap per step; prefer recompute for short seqs; async swap with backpressure.
  • Recompute loses sampled-token state (re-prefills prompt but forgets generated tokens) → wrong continuation. Root: recompute only the prompt, not prompt+generated. Debug: output diverges after restore. Recover: recompute over prompt+already-generated tokens (they're part of the context now).
  • Double-free on swap-out (free device blocks but swap copy also "freed") → corruption. Root: ownership ambiguity between pool and swap store. Debug: kv_double_free. Recover: clear ownership transfer; device blocks freed only after swap-out confirmed (I8).
  • Victim selection nondeterministic → replay divergence. Root: set iteration / time-based. Debug: replay diff. Recover: deterministic victim order (priority, admit_seq) (I7).

⬜ Phase 9 — Prefix Caching / Copy-on-Write Shared Prefixes (KV Reuse Across Requests)

Objectives

Add prefix caching: when multiple requests share a prompt prefix (system prompt, few-shot examples, chat history), share the same KV blocks via copy-on-write + reference counts (I6) — prefill the shared prefix once, reuse it across requests. Massive TTFT + memory win for templated/chat workloads. Cross-link #117.

Deliverable

Two requests sharing a long system prompt prefill the shared prefix once; the second request's TTFT drops dramatically; their KV blocks are shared (ref_count=2) until divergence, then COW-split; outputs are independent and correct.

Acceptance
  • Second request with a shared prefix has TTFT ≥ 50% lower than cold (prefix reuse) on a templated fixture.
  • COW correctness: two seqs sharing a prefix then diverging produce identical outputs to two independent runs (I7) — no cross-seq bleed (I9).
  • ref_count always equals the number of referencing seqs (I6); no premature free, no leak (I8).
  • Memory: N requests sharing a prefix use ~1 copy of the prefix KV (not N).
Fixtures
  • requests/shared_system_prompt.json (N reqs, same prefix), requests/diverge_after_prefix.json, requests/partial_block_share.json (divergence mid-block → COW). golden_streams/p9_prefix.txt. KV: conformance/requests/refcount_audit.json.
Pitfalls
  • COW miss → cross-request bleed (one seq writes into a shared block, corrupting another) → wrong output + security boundary breach. Root: writing a shared block without copying. Debug: kv_isolation_violation (I9); differential. Recover: copy on first write when ref_count>1 (I6).
  • Ref-count leak (decrement missed on terminal) → shared block never freed → capacity bleeds. Root: free path doesn't decrement shared refs. Debug: kv_refcount_mismatch; util high. Recover: decrement on every terminal; audit ledger (I6/I8).
  • Hash collision in prefix cache → adopt wrong KV → garbage output. Root: weak/short hash, no token verification. Debug: differential mismatch on cache hit. Recover: verify actual tokens match on hit (not just hash); strong hash.
  • Stale cached prefix (model/params differ) → wrong KV reused. Root: cache keyed only on tokens, not model/dtype. Debug: cross-model contamination. Recover: key on (model, dtype, tokens).
  • Partial-block divergence mishandled (two seqs share a half-full block then both write) → both think they own the tail. Root: block-granular COW ignores intra-block. Debug: tail-token corruption. Recover: COW the partial block on divergence; only fully-identical blocks shared.

⬜ Phase 10 — Admission Control + SLO-Aware Scheduling + Backpressure (TTFT vs TPOT, Goodput, Fairness)

Objectives

Close the control loop on quality of service: KV-aware admission control (admit only if the request can be served without thrash, principle 15), SLO-aware scheduling (balance prefill (TTFT) vs decode (TPOT) per deadline class, principle 10), fairness across classes, and end-to-end backpressure. Optimize goodput (deadline-meeting requests), not raw throughput.

Deliverable

Under heavy mixed load, Interactive requests meet TTFT/TPOT SLOs while Bulk fills spare capacity; admission rejects (429) before the system thrashes; goodput stays high; fairness maintained.

Acceptance
  • Goodput ≥ 99% (deadline-meeting) for Interactive class under target load (the primary SLO).
  • TTFT/TPOT per-class SLOs met (§4 targets) under load; Interactive protected from Bulk.
  • Admission rejects gracefully (429 + Retry-After) before preemption thrash (principle 15) — no thrash under overload.
  • Bulk class makes progress (no starvation) when capacity allows; fairness verified.
Fixtures
  • traces/mixed_slo_classes.json (Interactive+Batch+Bulk), traces/overload_reject.json, traces/fairness.json. golden_streams/p10_slo.txt. Load profiles in benchmarks/load/.
Pitfalls
  • Admit past capacity → preemption cascade → everyone's SLO blown. Root: admission ignores KV pressure. Debug: preemption_rate + deadline_misses spike together. Recover: KV-aware admission; reject-over-preempt (principle 15).
  • Prefill starves decode under TTFT pressure → running seqs' TPOT blown. Root: over-allocating budget to prefill. Debug: n_decode drops, TPOT rises. Recover: reserve decode budget first (decode-first, §8.5).
  • Bulk starvation → low-priority requests never served. Root: strict priority. Debug: Bulk goodput ≈ 0. Recover: weighted fairness / aging.
  • Deadline thrash (admit then can't meet, repeatedly) → wasted work. Root: optimistic admission. Debug: high deadline_misses post-admit. Recover: admit only if deadline projectable; fail fast on unmeetable.
  • Goodput optimized as throughput → tail requests sacrificed. Root: maximizing tokens/s. Debug: high tokens/s but low Interactive goodput. Recover: goodput-under-SLO objective (principle 10).

⬜ Phase 11 — Speculative Decoding Hook: Draft / N-gram / Tree-Verify, Acceptance Accounting (optional accelerator)

Objectives

Add an optional speculative-decoding accelerator (stg-spec) behind a trait: a cheap draft (small draft model, n-gram, or Medusa-style heads) proposes K tokens; the target executor verifies them in one forward; accepted tokens advance the sequence, the first rejected token is resampled. Must preserve the target distribution (correctness over speed) and account acceptance. Cross-link #117.

Deliverable

With a draft enabled, sequences generate multiple tokens per target forward when the draft agrees; output distribution is provably identical to non-speculative sampling (under fixed seed); acceptance rate + speedup reported; disabling the hook restores plain decode.

Acceptance
  • Output distribution identical to non-speculative target sampling under fixed seed (the spec-decode correctness gate, I7) — not just "close".
  • Tokens-per-target-forward > 1 on a fixture where the draft agrees (measured speedup); adaptive fallback when acceptance < threshold.
  • KV correctness: accepted tokens' KV appended, rejected drafts' KV discarded cleanly (I8 balance holds).
  • Disabling spec-decode yields byte-identical output to Phase 6 sampling (transparency).
Fixtures
  • requests/spec_ngram.json, requests/spec_draft_model.json, requests/spec_low_acceptance.json (fallback), requests/spec_distribution_equiv.json (correctness). golden_streams/p11_spec.txt (== non-spec under seed). logits_traces/p11_*.json.
Pitfalls
  • Acceptance rule wrong → distribution drift (faster but subtly different outputs). Root: incorrect accept/resample math. Debug: distribution-equivalence differential fails (I7). Recover: implement Leviathan/Chen rejection sampling exactly; the gate is identical, not similar.
  • Rejected-draft KV not discarded → stale KV corrupts continuation. Root: appending draft KV before acceptance. Debug: output diverges after a rejection; kv_append_gap. Recover: append only accepted tokens' KV (I8/I11).
  • Negative speedup (draft cost > savings) on low-agreement workloads. Root: drafting when acceptance is low. Debug: tokens_per_forward < 1; tokens/s drops with spec on. Recover: adaptive K; disable below acceptance threshold.
  • Draft model KV mismanaged (separate KV pool for draft leaks). Root: two KV systems. Debug: leak in draft pool. Recover: account draft KV separately; free on each step.
  • Nondeterministic acceptance under seed → replay diff. Root: shared RNG between draft + verify. Debug: replay mismatch. Recover: deterministic per-seq RNG threading (I14).

⬜ Phase 12 — Observability + Deterministic Replay: Metrics, Tracing, Structured Logs, Request/Logits Trace Capture + Replay Gate

Objectives

Lock observability + the determinism gate: the full serving-metric vocabulary (TTFT/TPOT/goodput/KV-util/preemption) via Prometheus, per-request/step tracing spans, structured logs, and a deterministic replay harness (I7) that captures a request trace + the executor's logits + per-request seeds and re-runs them to byte-identical output token streams.

Deliverable

A live Prometheus endpoint with the full metric set; tracing spans queryable per request; a captured production-style trace replays to byte-identical token streams; replay diffs surface any nondeterminism.

Acceptance
  • 100% deterministic replay across the conformance trace set (I7) — identical token streams + finish reasons across 100 runs.
  • All Operational Readiness metrics emitted + scrapeable; TTFT/TPOT histograms accurate vs measured ground truth.
  • Tracing spans totally ordered by (step_seq, seq_id, token_pos) (I15); no gaps.
  • Replay overhead off the hot path (capture ≤ small % overhead, replay offline).
Fixtures
  • conformance/logits_traces/* (per-request captured logits), conformance/requests/replay_set.json, golden_streams/p12_replay.txt. Replay manifest cross-checks token streams + finish reasons.
Pitfalls
  • Replay diverges from live (hidden nondeterminism). Root: wall-clock/RNG/HashSet-iteration/thread-order leaked into a decision. Debug: bisect decision inputs; replay diff. Recover: purge impure inputs (I7); deterministic ordering everywhere.
  • Executor nondeterminism not captured → replay can't reproduce. Root: capturing requests but not logits. Debug: same inputs, different tokens. Recover: capture executor logits in the trace (the executor is the black box).
  • Metric cardinality explosion (per-seq labels) → Prometheus melts. Root: high-cardinality labels. Debug: TSDB memory blowup. Recover: bounded label sets; per-seq detail in traces/logs, not metrics.
  • Capture overhead on hot path → TPOT regression in prod. Root: synchronous trace write per token. Debug: TPOT rises with capture on. Recover: async/sampled capture; ring buffer.
  • Clock-based TTFT/TPOT skew under load → misleading percentiles. Root: coarse timer / measurement contention. Debug: implausible percentiles. Recover: monotonic clock, lock-free histograms.

⬜ Phase 13 — Soak, Chaos / Fault Injection, Differential vs Reference, Fuzzing, Full Conformance + Performance Gate (production-readiness)

Objectives

Production-readiness gate: long soak (no KV/FD/mem leak, no thrash), chaos/fault injection (executor stalls, client floods, swap failures, mid-stream cancels), differential vs a reference generator, fuzzing (request JSON, token stream, detok bytes, SSE frames), full conformance, and the TTFT/TPOT/goodput performance gate. Mark the distributed seam for Phase 13-deferred work (see Deferred Features Register).

Deliverable

make conformance + make replay + make soak + make chaos + make fuzz-smoke + make bench all green; metrics endpoint live; the runtime survives chaos with correct containment; performance gate passes.

Acceptance
  • Soak (≥ 4 h mixed load): zero KV/FD/mem leak; preemption_rate < ceiling; TTFT/TPOT/goodput stable within SLO.
  • Differential vs HF: identical token sequences across the seeded sampling suite (§6 correctness).
  • Fuzz smoke (5 min/target): no panic/UB; no invalid UTF-8 emitted (I3); no I1/I8 violation; corpus retained.
  • Chaos: every injected fault contained (no OOM, no corruption, correct degradation); KV always reclaimed (I8).
  • Performance gate: TTFT/TPOT/goodput within target; no > 10% regression vs committed baseline.
Fixtures
  • conformance/requests/* (valid + malformed + negative), logits_traces/*, golden_streams/*, detok/*, sampling/*. benchmarks/traces/* (ShareGPT-like). fuzz/corpus/*. Chaos scenario manifests.
Pitfalls
  • Slow KV leak only visible in soak (per-request tiny leak). Root: a rare terminal path skips free. Debug: kv_blocks_allocated trends up over hours. Recover: per-seq balance audit on every terminal (I8); soak as the detector.
  • FD leak from abandoned connections / swap files. Root: handles not dropped on disconnect/error. Debug: lsof count climbs. Recover: RAII handles; close on terminal.
  • Chaos uncovers cancellation race (disconnect during forward → use-after-free). Root: freeing mid-step. Debug: kv_double_free under chaos. Recover: free only at step boundary (I2).
  • Bench flakiness on shared CI hosts → false regressions. Root: noisy neighbors. Debug: high variance. Recover: pinned-core load-gen host, relative thresholds, multiple runs.
  • Fuzz finds a malformed request that panics admission. Root: an unvalidated field. Debug: minimized crash input. Recover: extend validator; add to corpus.
