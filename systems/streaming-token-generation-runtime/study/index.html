Mental Models & First Principles

  1. MM1 — Iteration-level scheduling eliminates the HOL-blocking tax of static batching. Predicts: throughput vs static batching given a mixed-length arrival trace. Without it: short sequences wait behind long ones, the device idles between request-level completions, and observed throughput is 10–24× below capacity (Yu et al. OSDI 2022). Applied: §5, §8.5, Phase 5.

  2. MM2 — The KV cache is a virtual memory system; paging reduces external fragmentation to zero. Predicts: maximum concurrent sequences for a given device memory budget. Without it: contiguous per-sequence KV reserves worst-case length upfront, wasting 60–80% of device memory and collapsing concurrency to a fraction of what paging allows. Applied: §3, §8.3, Phase 3.

  3. MM3 — Reference counting is the only correct ownership protocol for shared KV blocks. Predicts: whether a shared block is freed prematurely (ref_count undercount) or leaked (overcount). Without it: a COW copy is skipped on one code path, one sequence silently writes into another's KV, producing wrong tokens and a security boundary breach (I6, I9). Applied: §9.2, §3.2, Phase 9.

  4. MM4 — Goodput under SLO and raw throughput are orthogonal objectives; optimizing one can degrade the other. Predicts: whether a scheduling policy that maximizes tokens/s will also meet per-request deadlines. Without it: the scheduler packs the batch to maximize device utilization, starving latency-sensitive sequences, and TTFT/TPOT SLOs are violated even as aggregate throughput looks healthy (Zhong et al. OSDI 2024, §10 principle P10). Applied: §10, Phase 10.

  5. MM5 — A token boundary is not a code-point boundary; a code-point boundary is not a grapheme boundary. Predicts: whether incremental detokenization will produce valid UTF-8 at every emit boundary. Without it: a byte-level BPE token that encodes part of a multi-byte code point is emitted as a raw byte sequence, producing client-visible mojibake that cannot be un-rendered (I3). Applied: §2.2, Phase 2.

  6. MM6 — Backpressure must be per-sequence, not per-batch; one slow consumer must not stall all others. Predicts: whether a slow or disconnected client raises TPOT for unrelated sequences. Without it: a single bounded channel shared by all streams, or an unbounded per-sequence channel, turns one client's network congestion into head-of-line blocking across the entire batch (principle P6, I12). Applied: §7.2, Phase 7.

  7. MM7 — Speculative decoding preserves the target distribution only when the accept/reject rule is mathematically exact. Predicts: whether sampled output with speculative decoding is statistically identical to plain sampling from the target. Without it: an approximate acceptance heuristic shifts the distribution, producing subtly different text that passes visual inspection but fails a fixed-seed differential test (Leviathan et al. ICML 2023; Chen et al. 2023). Applied: §11.2, Phase 11.

  8. MM8 — Determinism requires that every decision input be explicit; wall-clock, hash-map iteration order, and thread-completion racing are hidden nondeterminism sources. Predicts: whether a captured trace replays to byte-identical output. Without it: a single HashMap iteration in batch composition or a wall-clock tie-break in victim selection makes a production incident unreproducible and regression testing meaningless (I7). Applied: §8.5, §12.2, Phase 12.

  9. MM9 — Chunked prefill bounds the worst-case TPOT; monolithic prefill of a long prompt is a denial-of-service against all running decode sequences. Predicts: p99 TPOT under a workload with large prompt arrivals. Without it: a 32k-token prompt occupies the entire max_num_batched_tokens budget for one step, freezing every other sequence's token stream for hundreds of milliseconds (Agrawal et al. 2023/2024, principle P11). Applied: §4.2, §8.5, Phase 4.

  10. MM10 — Conservative admission (reject before thrash) yields higher goodput than optimistic admission followed by preemption cascades. Predicts: steady-state goodput under over-subscription. Without it: admitting a sequence whose working set cannot fit causes a victim to be preempted, which frees blocks for the new arrival but forces re-prefill of the victim, consuming capacity that harms both and lowering overall goodput (principle P15, §8.6). Applied: §10.2, Phase 8, Phase 10.

Glossary · 42 terms · site-wide glossary

STGRT
Streaming Token Generation Runtime — the serving control plane built here.
Autoregressive decoding
Generating one token at a time, each conditioned on all previous tokens.
Prefill
Processing the full prompt to populate the KV cache before generation begins.
Decode
Generating one new token per forward pass (the steady-state of generation).
Chunked prefill
Splitting a long prompt's prefill into chunks interleaved with ongoing decodes.
Continuous (in-flight) batching
Iteration-level scheduling: sequences join/leave the batch every decode step.
Static batching
Request-level batching: a batch runs to completion before the next forms (the slow baseline).
Step / iteration
One ModelExecutor.forward call over a batch; the scheduler's unit of work.
KV cache
Cached key/value tensors per layer/head/position; avoids recomputing attention over the prefix.
PagedAttention
KV cache stored in fixed-size blocks with a per-sequence block table (OS-paging analogue).
KV block
A fixed-size unit of KV memory holding block_size tokens' K,V across all layers/heads.
Block table
Per-sequence map from logical block index to physical BlockId.
Slot mapping
Per-step map of (seq, new token) → (physical block, offset) for the executor's K,V writes.
Copy-on-write (COW)
Shared KV blocks (ref_count>1) are copied on first divergent write — enables prefix sharing.
Prefix caching
Reusing KV blocks of a shared prompt prefix across requests (content-addressed).
Reference count
Number of sequences sharing a KV block; gates free + COW.
Fragmentation
Wasted KV memory; paging makes external≈0 and internal ≤ one partial block per seq.
Preemption
Evicting a running sequence's KV under memory pressure (swap or recompute).
Swap
Moving a preempted sequence's KV blocks to host/NVMe and restoring later.
Recompute
Dropping a preempted sequence's KV and re-prefilling (prompt+generated) on resume.
TTFT
Time To First Token — admission to first streamed delta.
TPOT / ITL
Time Per Output Token / Inter-Token Latency — latency between successive tokens.
Goodput
Fraction of requests meeting their deadline/SLO (the headline objective, not raw throughput).
max_num_seqs
Hard cap on concurrent sequences in the batch.
max_num_batched_tokens
Hard cap on tokens processed per step (prefill + decode).
Admission control
Deciding whether to admit/queue/reject a request based on capacity + SLO.
Backpressure
Bounded queues/channels; a full consumer throttles its producer.
Head-of-line blocking
One slow item stalling all behind it; avoided by per-seq isolation.
Logit processor
A transform applied to logits before sampling (penalty, bias, etc.).
Top-k / Top-p / Min-p
Truncated-sampling strategies (k-highest / nucleus / probability-floor).
Temperature
Logit scaling controlling randomness; T=0 ⇒ greedy.
Repetition/presence/frequency penalty
Down-weighting already-seen tokens.
Stop string
A substring that, when generated, terminates the sequence.
Finish reason
Why generation ended: stop / length / eos / cancel / error.
Incremental detokenization
Decoding tokens to text deltas without re-decoding the whole sequence; buffers partial glyphs.
Speculative decoding
A cheap draft proposes tokens; the target verifies them in one forward (accept/reject).
Acceptance rate
Fraction of speculatively-drafted tokens accepted (the speed-up driver).
ModelExecutor
The pluggable forward-pass backend (the only box STGRT does not implement).
SSE
Server-Sent Events — text/event-stream incremental HTTP streaming.
Cancellation token
Signal set on client disconnect; frees the sequence's KV at the next step boundary.
Deterministic replay
Re-feeding captured requests + logits + seeds yields identical output token streams.
Single-writer scheduler
One task owns batch + KV mutation, preventing torn state.
