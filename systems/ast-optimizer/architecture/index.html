Typed AST (input): the sole external, untrusted entry point (T1, §24) — the resolver never trusts NodeId uniqueness or well-scopedness from upstream and re-validates both (I2). Resolver & Annotator: single-threaded per module, pure function of the input AST; its output (side tables keyed on NodeId, P5) is the only state every later pass reads. Pass Manager: owns the concurrency boundary — one manager instance per module, run on an independent worker thread by the driver (§23), never shares mutable e-graph or annotation state across threads. The ten classical passes: pure Rewriter/Visitor implementations, each declaring its reads/writes/invalidates set (ADR-04, I11) so the manager can schedule safely. Equality Saturation Engine: the one component with genuinely different data-flow shape (a DAG of equivalence classes, not a tree) — bounded by fuel (I7) so it cannot dominate wall-clock time. Verifier: the trust boundary's closing gate — no optimized output is emitted to the CLI or conformance report until the interpreter agrees with the pre-optimization program (I1). Output: two persistence artifacts — the optimized AST/CLI output, and the JSON conformance report (external interface #2) consumed by CI. IR-lowering boundary: intentionally a hard stop; this project publishes a LowerToIR-shaped contract (§11) but never implements it.

8. Domain Model

8.1 Locked Input AST Grammar

The EBNF below is the locked Phase-0 surface. Phase-1+ extensions require an ADR.

Module    ::= Decl*
Decl      ::= "let" Ident "=" Expr
            | "let" "rec" Ident Param+ "=" Expr
            | "type" Ident TypeParam* "=" AdtBody
Expr      ::= Lit
            | Ident
            | "fn" Param+ "->" Expr
            | Expr Expr                            (* application *)
            | "let" Ident "=" Expr "in" Expr
            | "if" Expr "then" Expr "else" Expr
            | "match" Expr "with" Arm+
            | "{" Field* "}"                        (* record *)
            | Expr "." Ident                        (* projection *)
            | "{" Expr "with" Ident "=" Expr "}"     (* row update *)
            | "(" Expr ":" Type ")"                  (* ascription *)
            | "loop" Block                           (* explicit loop, for LICM *)
            | "while" Expr Block                     (* sugar over loop *)
Param     ::= Ident (":" Type)?
Field     ::= Ident "=" Expr
Arm       ::= "|" Pat "->" Expr
Pat       ::= "_" | Ident | Lit | Ident Pat* | "{" PatField* "}"
Lit       ::= Int | Float | Bool | String | Unit

Every node carries a Span and a NodeId (I2). Annotations hang off NodeId in side tables (P5), never on the node.

8.2 Pass Pipeline as a State-Transition Table

State Produced By Reads Invariant Established
Parsed external front end — well-scoped, typed (upstream contract)

Folded / Propagated Phase 3 (§15) Annotated I1, I9 (type-consistent folds)
DCE'd / CSE'd Phase 4 (§16) prior state I1, I3 (purity-gated)
Inlined / Peepholed Phase 5 (§17) prior state I1, I4 (fuel), I10 (alpha-safe)
PartialEval'd / Beta-Eta'd Phase 6 (§18) prior state I1, I4, I10
LICM'd / TailAnnotated Phase 7 (§19) prior state I1, I3
Saturated Phase 8 (§20) any prior state (post-manager) I1, I7, I14
Verified Phase 10 (§22) Saturated (or any manager output) I1 (final gate)
Emitted Phase 11 driver (§23) Verified — terminal

A module can enter the manager's fixpoint at Annotated and cycle through the middle rows multiple times (I6) before reaching Saturated/Verified; the table lists the canonical forward order, not a single-pass requirement.

Purity lattice (annotation domain, P3/I3):

Constant-propagation lattice (Wegman & Zadeck 1991 SCCP, specialized to a tree walk rather than a CFG):

Show the original text diagram
         Top            (could be anything — join of ≥2 disagreeing constants)
        /   \
  Const(v1) Const(v2) ...    (one class per distinct literal value)
        \   /
        Bottom          (unreachable / not yet computed)

Join (⊔): Bottom ⊔ x = x; Const(v) ⊔ Const(v) = Const(v); Const(v1) ⊔ Const(v2) = Top (v1 ≠ v2); Top ⊔ x = Top. Monotonicity across worklist iterations is what makes the propagator (§15) terminate in at most |nodes| steps before reaching a fixpoint (Kildall 1973).

8.4 Worked Example (fold → propagate → DCE → CSE trace)

Source: let x = 1 in let y = x + 2 in let _ = pure_call() in y + y

Step Fact / Rewrite Applied Resulting Fragment
0 (Annotated) pure_call marked Purity::Unknown (no callee body visible) unchanged
1 (Propagate, §15) x ↦ Const(1) reaches its one use let y = 1 + 2 in let _ = pure_call() in y + y
2 (Fold, §15) 1 + 2 → 3 (type-directed, P2) let y = 3 in let _ = pure_call() in y + y
3 (Propagate, §15) y ↦ Const(3) reaches both uses let _ = pure_call() in 3 + 3
4 (Fold, §15) 3 + 3 → 6 let _ = pure_call() in 6
5 (DCE, §16) binding for _ is kept — pure_call's purity is Unknown, I3 forbids deletion unchanged (I3 guard fires)
6 (CSE, §16) no duplicate pure subterms remain unchanged — fixpoint reached in 4 manager iterations

Final verified output: let _ = pure_call() in 6, and interp on both the original and the final form agree for every generated environment (I1).

8.5 Malformed-Input Example

Input: an Expr::Var { name, .. } whose Symbol has no reaching Decl/Param/Arm binder — a well-scopedness violation that should never reach the optimizer given the upstream contract (§1), but which the resolver (§13) defensively rejects rather than assumes away. Detected by I5 (WellFormedCheck) immediately after annotation, before any pass runs; the manager refuses to schedule and returns ManagerReport::RejectedInput { reason: DanglingVar(node_id) } rather than silently treating the variable as Unknown-typed garbage — the alternative (silent acceptance) is precisely the P2 violation class illustrated by folding 1 / 0-shaped inputs without a type check.

8.6 Failure-Path Example

During Phase 8 saturation (§20) on an adversarial fixture containing 40 nested applications of add-comm/add-assoc, the e-graph reaches the 50,000-e-node ceiling (I7) before reaching the iteration limit. Runner::stop_reason reports NodeLimit; the engine extracts from the graph as it stands (still sound, per I7's recovery clause) rather than continuing unboundedly. SaturationReport.iterations and .stopped_reason are logged (saturate.stopped_reason{node_limit} telemetry, §26), and the conformance report (§28) marks the case Pass (partial-saturation) rather than Fail, because I1 — not saturation completeness — is the correctness contract.
