Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. If two events are scheduled at (time=T, seq=N) and (time=T, seq=N+1) and the first event's handler schedules a third at time T (same virtual ns), what seq does the third event get, and what does this guarantee about the execution order of all three? (§8.6, §6 P2, §7 I4, Phase 0)
  2. An operator claims that increasing the MSI-X coalescing parameter from N=16 to N=64 reduces host CPU load. How would you design an offload-on vs offload-off experiment to measure this claim, and what does the cycles-saved ledger need to model for interrupt-coalescing savings to be non-zero? (§4, §8.7, §7 I11, Phase 1, Phase 11)
  3. A TCAM table with entries A (prio=10, mask=0xF0) and B (prio=10, mask=0xFF) both match packet P. Under the current tie-break rule (§8.3, I8), which fires? What must the config loader do if two entries at equal priority are provably both matchable by some packet? (§8.3, §7 I8, ADR-011, Phase 3)
  4. The checksum offload engine passes a differential test against scapy for IPv4/TCP packets. A new test adds an IPv6 packet with a UDP pseudo-header. Why might the engine fail this test even though it passed the IPv4 case, and what RFC sections govern the difference? (§8.5, §7 I6, Phase 4, MM3)
  5. TSO produces 45 segments from a 64 KB send. The cycles-saved ledger records TSO savings. The TX checksum engine also runs on each segment. How do you ensure that checksum cycle savings are not double-counted between TSO and the checksum engine? (§6 P4, §7 I11, Phase 4, Phase 5, MM4)
  6. A VXLAN-encapsulated packet arrives at the RX pipeline. The outer UDP checksum is zero (disabled). The inner TCP checksum is valid. The flow-steering rule matches on the inner 5-tuple. Trace the exact sequence of parse → decap → inner-parse → steer events and identify which invariants are checked at each step. (§8.5, §7 I5 I15 I16, Phase 6, ADR-018)
  7. The verifier statically checks that all jumps are forward-only and all field accesses are in-range. A bytecode program passes the verifier but still triggers step_cap_hit at runtime. What does this imply about the verifier's completeness, and why is the runtime cap not redundant with the static check? (§8.9, §7 I10, Phase 8, Phase 9, ADR-019)
  8. The offload-on run records 41,580 host cycles saved for a 64 KB TCP send. The offload-off control run records 38,000 host cycles "spent" by the host for the same workload. The difference is 3,580 cycles. What are three plausible root causes for this discrepancy, and which telemetry counters isolate each? (§4, §7 I11, Phase 5, Phase 11, MM4)
  9. An embedded core program uses AddCycles(n) to self-report its modeled cost. A second engine (e.g. checksum) runs after the core program completes and also charges cycles for work done on the same packet. How does the CpuSavingsModel prevent double-counting here, and what invariant guarantees this? (§8.9, §7 I9 I11, Phase 8, Phase 11, P4)
  10. The LRO engine receives segments A, B, C in order, coalesces them, then receives D which is out-of-order (seq(D) != seq(C) + len(C)). What must the engine do with D, and how does this interact with the byte-conservation invariant (I5) for the coalesced A+B+C segment already emitted? (§8.5, §7 I5 I7, Phase 5, MM6)
  11. The sim runs on x86-64 and produces event trace T1. It runs on aarch64 and produces T2. T1 != T2 at event #4,200,017. The config, seed, and workload are identical. List in priority order the five most likely root causes for this cross-platform divergence, and identify which §4 / §6 constraints are violated. (§7 I1, §6 P1, Phase 12, ADR-006, ADR-010)
  12. A parameter sweep runs 500 independent sim instances across 50 machines. One instance produces a negative value in the cycles-saved ledger for the checksum engine. Explain why this can occur in an otherwise-correct sim, what invariant it violates, and how the ledger's clamp-and-log recovery interacts with the offload-on/off comparison harness. (§7 I11, §6 P4, Phase 11, ADR-027, MM4)
  13. A runtime reconfig event installs a new ternary table entry at (time=5000 ns, seq=99). Packet P is currently in PipelineStage(pkt, 1) with its own event at (time=5001 ns, seq=98). Does the reconfig apply to P? Justify with the event-ordering rules and state whether this is correct by design or a race. (§8.6, §7 I1 I4, Phase 9, ADR-004, P2)
  14. The RSS engine uses Toeplitz hashing with a 40-byte key. A study changes the indirection table size from 128 to 256 entries without changing the key. For a 5-tuple that previously hashed to queue 3, what queue does it now map to, and does this change violate I15? What must the config versioning system do when the indirection table changes? (§8.5, §7 I15, Phase 4, ADR-030, MM5)
  15. The soak test runs for 1 hour of virtual time on a mixed workload. Memory usage grows by 40 MB over the run. List the three most likely unbounded data structures in the codebase, how each should be bounded, and what §4 constraint each violates if left unbounded. (§4, §7 I9 I12, Phase 12, ADR-003, P9)
  16. An RDMA WRITE to a remote MR completes without host involvement on the receive side. The cycles-saved ledger attributes host-bypass savings. The offload-off control must model what the host would have done. Describe exactly what work the host performs in the offload-off model for an RDMA WRITE, and which §Phase 10 accounting fields capture this. (§6 P4 P12, §7 I11, Phase 10, Phase 11, MM4)
  17. The QoS scheduler uses WFQ with weights w1=2, w2=1 for two classes. Class 1 is idle for 100 µs of virtual time. Then both classes burst simultaneously. What does the WFQ virtual-finish-time formula predict about the initial service order, and does the deficit carry-forward from class 1's idle period change the answer? (§8.5, Phase 7, ADR-004, MM8)
  18. The fuzz corpus contains an input that causes the parser to emit a HeaderStack with an Esp header immediately after an Eth header (no IP/UDP tunnel), then the tunnel engine's decap path is invoked on it. Trace the exact path and identify which guard — and which invariant — prevents a panic or silent corruption. (§8.2, §7 I5, Phase 2, Phase 6, Phase 12, P9)
  19. A config sets gso_size = 1448 and line_rate = 400 GbE. From the §4 capacity model, compute the maximum TSO input-packet rate (large sends) the sim must handle to saturate the modeled 400 GbE wire, and explain why sim-pps does not need to match this number. (§4, Phase 5, MM3, MM1)
  20. The calendar-queue alternative for the event heap is deferred to PhaseDeferred("§11.10"). State the exact profiling condition (from §4 and ADR-003) that must be observed before un-deferring it, and explain why switching from a binary heap to a calendar queue does NOT change any simulation outputs — only simulator performance. (§4, ADR-003, Phase 11, §7 I1, MM1)

Mental Models & First Principles

  1. MM1 — A discrete-event simulation is a pure function: (config, seed, workload) -> outputs. Predicts: any observable difference between two runs means a hidden input changed. Without it: you chase "flaky" behaviour that is actually deterministic-but-uncontrolled nondeterminism (wall-clock reads, OS RNG draws, thread scheduling). Applied: §6 P1, §7 I1, Phase 0, Phase 12.

  2. MM2 — Virtual time is a total order on causality, not a measurement of real duration. Predicts: event A scheduled before event B at the same timestamp will always fire first, even if real dispatch order varies. Without it: you conflate modeled latency (a parameter) with observed simulator latency (wall-clock), and mis-interpret the telemetry. Applied: §6 P2, §8.6, Phase 0, Phase 11.

  3. MM3 — Every offload is a (functional transform, cycle cost) pair; conflating them produces either correct-but-valueless or fast-but-wrong engines. Predicts: a checksum offload that produces wrong bytes but records plausible cycle savings will pass a cost audit and fail a correctness audit; each must be gated separately. Without it: you ship offload engines that pass the cost model but silently corrupt packets or vice versa. Applied: §6 P3, §8.5, Phase 4, Phase 5.

  4. MM4 — The offload-value ledger is conserved: cycles attributed to an offload must equal cycles the host would have spent in the offload-off control run. Predicts: any cycles-saved number that cannot be reproduced by diffing an offload-on vs offload-off pair is an assertion, not a measurement. Without it: you produce marketing numbers — a "50% host-CPU reduction" with no falsifiable control. Applied: §6 P4, §7 I11, Phase 5, Phase 11.

  5. MM5 — RSS Toeplitz hashing is a pure function of (headers, 40-byte key, indirection table): the same packet always maps to the same queue. Predicts: any per-run variation in RSS queue assignment means either the key changed or a non-deterministic hash was used. Without it: you write a load-balancer that appears to work but produces irreproducible per-queue counters, breaking differential analysis. Applied: §6 P7, §7 I15, §8.5, Phase 4, Phase 12.

  6. MM6 — TSO and LRO/GRO are inverses: TSO(payload) produces N segments whose concatenated payloads reconstruct the original; LRO(segments) must reconstruct the same payload. Predicts: any TSO/LRO implementation that fails this round-trip test has a seq-number, IP-ID, or flag-propagation bug. Without it: you write a TSO that produces segments that look correct per-segment but whose reassembly reveals a missing or doubled byte range. Applied: §6 P6, §7 I5 I7, Phase 5, Phase 12.

  7. MM7 — Bounded programs are the only safe programs in a single-threaded simulator: a program that can loop forever is a denial-of-service against the entire model. Predicts: any bytecode loader that does not statically verify forward-only jumps AND enforce a runtime step cap will eventually hang on adversarial input. Without it: a malformed offload program silently stalls the sim — there is no watchdog that distinguishes "long computation" from "infinite loop" without a cap. Applied: §6 P9 P10, §7 I10, Phase 8, Phase 9.

  8. MM8 — Interrupt coalescing trades latency for throughput: batching N completions into one interrupt reduces host wakes but adds up to coalesce_ns delivery delay. Predicts: coalescing N=1 is equivalent to per-packet interrupts (no saving); coalescing at large N reduces interrupt count but can add multi-microsecond latency to the last packet in a batch. The timer flush (T ns) bounds the worst-case delay. Without it: you tune for maximum throughput and wonder why tail latency spikes on small bursts. Applied: §4, §8.7, Phase 1, Phase 11.

  9. MM9 — TCAM is a priority-ordered parallel lookup: the result is the entry with the lowest index whose (value & mask) matches the key, and ties in priority are a configuration error, not a runtime choice. Predicts: any ternary table that defers tie-breaking to lookup time will produce non-deterministic matches. Without it: you write an ACL engine that returns different rules for the same packet depending on insertion order or hash layout. Applied: §6 P7, §8.3, §7 I8, Phase 3.

  10. MM10 — Byte conservation is an invariant, not a hope: at every stage boundary, bytes_in == bytes_out unless an offload has an explicit, accounted reason to differ (TSO multiplies, LRO coalesces, encap/decap adds/removes header bytes). Predicts: silent corruption introduced at any stage will manifest as a bytes_out != bytes_in anomaly if you instrument every boundary. Without it: you write a tunnel encap that forgets to update the outer IP total_len and the error only surfaces when a real decap peer rejects the packet. Applied: §6 P5, §7 I5, §8.5, Phase 2, Phase 6.

Required reading (§5)

Books

  • Banks, Carson, Nelson, Nicol, Discrete-Event System Simulation, 5e — Ch. 3 (event-scheduling / event-list algorithm), Ch. 4 (simulation examples), Ch. 7 (random-number generation). The canonical DES engine + reproducible RNG. Extract: future-event-list management, tie-breaking, verification/validation discipline. → applied in §8.6, Phase 0.
  • Peterson & Davie, Computer Networks: A Systems Approach, 6e — Ch. 2 (framing, error detection, Internet checksum), Ch. 3 (switching, VLANs), Ch. 5 (TCP, segmentation). Header layouts + checksum semantics the offloads must reproduce. → applied in §8.1, Phase 2, Phase 4.
  • Stevens, TCP/IP Illustrated, Vol. 1, 2e — TCP segmentation, sequence/ACK, IP fragmentation vs TSO, pseudo-header checksum. Ground truth for TSO/LRO seq semantics. → applied in §8.5, Phase 5.
  • Drepper, What Every Programmer Should Know About Memory (2007) — DMA, cache effects; informs the DMA + host-ring cost model (sim realism, not gates). → applied in §8.7, Phase 1.
  • Hennessy & Patterson, Computer Architecture: A Quantitative Approach, 6e — Appendix on interconnects + the cost-modeling discipline behind cycles-saved accounting. → applied in §4, Phase 5, Phase 11.
  • Fall & Stevens, TCP/IP Illustrated, Vol. 2 (selectively) — driver/queue interaction informing the descriptor-ring + interrupt model. → applied in §8.7, Phase 1.
  • Klabnik & Nichols, The Rust Programming Language — ownership, enum + pattern matching exhaustiveness, Ord/BinaryHeap, Send/Sync (why the core stays single-threaded). → applied in §11, Phase 0, Phase 8.
  • The P4_16 Language Specification (P4.org) — parser state machine, table + action model, match kinds (exact/lpm/ternary), deparser. The pipeline's normative shape (a subset of which we implement). → applied in §8.2, §8.3, Phase 2, Phase 3.

Glossary · 49 terms · site-wide glossary

SmartNIC / DPU
A NIC with programmable pipeline + offload engines + embedded cores that offloads host CPU work.
Discrete-event simulation (DES)
Simulation advancing virtual time event-to-event via a future-event list, not in fixed ticks.
VirtualClock
The monotone u64-nanosecond clock; the only time source (I2).
Event / EventKind
A scheduled (time, seq, kind) unit on the heap; the unit of simulation progress.
Future-event list / event heap
The BinaryHeap<Event> ordered by (time, seq) giving a total order (I1/I4).
Seq (tie-break)
Strictly increasing per-event counter that breaks same-time ties deterministically (I4).
Match-action pipeline
P4 model: parser → tables (match) → actions → deparser.
Parser / deparser
Walks bytes into a HeaderStack / re-serializes modified headers (P4 subset).
HeaderStack
Ordered parsed headers + offsets for a packet.
Exact / LPM / Ternary (TCAM) table
Match kinds: full-key hash / longest-prefix / value+mask-with-priority (I8).
Action
A pipeline primitive: set-field, fwd, drop, count, encap, decap, to-core, mark, mirror.
Offload engine
A unit that performs host work on the NIC, returning (disposition, cycle cost).
Checksum offload
RX verify / TX compute of Internet + pseudo-header checksums; incremental on edits.
TSO / GSO
Transmit/Generic Segmentation Offload: split a large TCP buffer into MSS segments.
LRO / GRO
Large/Generic Receive Offload: coalesce in-order same-flow segments (inverse of TSO).
MSS
Maximum Segment Size (TCP payload per segment); TSO's gso_size.
RSS
Receive Side Scaling: Toeplitz hash → indirection table → queue (I15).
Toeplitz hash
The RSS hash function over a 40-byte key and a packet tuple (NDIS spec).
Indirection table
RSS map from hash bucket to receive queue.
n-tuple flow steering
Steer a packet to a queue/core by matching header tuple fields.
Tunnel (VXLAN/Geneve/GRE)
Encapsulation of an inner packet inside outer headers (overlay networking).
Encap / decap
Push outer headers / pop them (inverse; round-trip I16).
VNI
VXLAN/Geneve 24-bit Virtual Network Identifier (tenant).
IPsec ESP
Encapsulating Security Payload: encrypt + authenticate (RFC 4303); cost modeled, correctness borrowed (#87/#88).
Token bucket
Rate limiter: tokens refill at rate r, capped at burst b; conform → pass.
QoS scheduler
Egress ordering across traffic classes: strict-priority / DRR / WFQ.
DRR / WFQ
Deficit Round Robin / Weighted Fair Queueing scheduling disciplines.
Embedded DPU core
A run-to-completion programmable core executing offload bytecode.
Offload program / bytecode
Bounded match-action instructions (Insn) run per packet on a core (no loops, I10).
Verifier
Static check that a program is bounded, in-range, loop-free before load (I10).
Spillback
Counted drop/re-queue when embedded cores saturate (never silent, I9/I11).
Run-to-completion
A core finishes one packet's program before taking the next (no preemption).
VirtQueue (split/packed)
Virtio descriptor ring layout: split (avail/used) or packed (single ring + flags).
Descriptor
A (addr, len, flags, next) ring entry describing a host buffer.
Doorbell
Host notification that kicks the NIC to process a queue.
DMA engine
Models host↔NIC transfer as latency + bandwidth + bounded in-flight (I12).
MSI-X / interrupt coalescing
Message-signaled interrupts; batch N completions or T ns per interrupt.
VirtioNetHdr
virtio-net per-packet header carrying GSO type/size + checksum hints.
RDMA / RoCEv2
Remote Direct Memory Access over UDP/IPv4; host-bypass data path.
Queue Pair (QP) / CQ / MR
RDMA send+recv queues / completion queue / registered memory region.
PFC
Priority Flow Control: per-class pause for lossless fabrics.
Host-cycles-saved
Modeled host CPU cycles an offload removes; the central analytical output (I11).
Offload-on vs offload-off
The control comparison that defines offload value (principle 12).
Sim-pps
Simulator throughput (simulated packets/s) — a SIM metric, distinct from modeled device pps.
Modeled line rate
The device speed the model represents (100/200/400 GbE).
Determinism / replay
Same (config, seed, workload) → bit-identical run; the simulator's core guarantee (I1).
Byte conservation
Payload bytes preserved through the pipeline except intentional rewrites (I5).
Round-trip (TSO/LRO, encap/decap)
An offload and its inverse recover the original (I7, I16).
Differential testing
Validating an offload's output against an independent reference (scapy/kernel/NDIS).
