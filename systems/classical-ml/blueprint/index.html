372 — Classical ML (decision trees, gradient boosting, SVM, k-means, PCA)

Goal: Implement, from scratch in Rust, a classical (non-deep) machine-learning library with a sklearn-style fit/predict/transform estimator API. The named algorithm families are the spine: decision trees (CART), gradient boosting (GBDT), SVM (SMO), k-means (++ / mini-batch), PCA (SVD/eigen) — plus the supporting ML infrastructure (dataset, metrics, cross-validation, preprocessing, pipelines). Crates: ml-core / metrics / modelselection / preprocess / linear / trees / ensemble / svm / cluster / decomp / pipeline / cabi / bench / conformance. It is a classical-ML estimator library modeling sklearn (API + algorithm set), XGBoost/LightGBM (gradient boosting), and libsvm (SVM/SMO) — not an autograd/deep framework (#112/#114), not a linear-algebra runtime (#349, a dependency), not a feature store (#122), not a recommender (#123). Correctness is validated by differential tests against sklearn golden fixtures (within tolerance), by ML invariants (impurity-decrease ≥ 0, inertia monotone, KKT at SVM convergence, orthonormal PCA components), by deterministic-seed reproducibility, and by no-train/test-leakage assertions; performance by training-time / prediction-latency benchmarks vs n_samples × n_features.

1. Goal

1.1 Engineering Definition

From-scratch classical-ML library: data layer (Dataset, dense/sparse feature matrix) → estimator traits (Estimator/Predictor/Transformer) → metrics + model selection → preprocessing + pipelines → linear/logistic → CART → ensembles (RF, GBDT, histogram) → SVM (SMO) → k-means → PCA, behind one sklearn-shaped API. IEEE-754 f32/f64 via #349 for matrix ops; sparse features via #350.

1.2 System Boundaries

  • In scope: supervised (clf+reg) + unsupervised (cluster+dim-reduction) estimators; CART (Gini/entropy/MSE/MAE, CCP pruning, importance); bagging RF + stage-wise GBDT (shrinkage/subsample/reg + histogram binning); SVM soft-margin dual + SMO + kernels (linear/RBF/poly); k-means (Lloyd + ++ + mini-batch); PCA (covariance-eigen or data-SVD + whitening); metrics; train/test split + k-fold CV + grid/random search; preprocessing (scale/one-hot/impute, fit-on-train); pipelines; model persistence; C ABI.
  • Out of scope (non-goals): deep learning/autograd/compute-graphs → #112/#114; RL → #119; dense BLAS/SVD/eigensolvers → #349 (dependency); sparse kernels → #350 (dependency); feature store → #122; recommender/matrix-factorization → #123; GPU → PhaseDeferred("§20"); distributed training → #115 / PhaseDeferred("§33"); kernel approx (Nyström/RFF) → PhaseDeferred("§24.2"); AutoML/Hyperband → PhaseDeferred("§13"); online learning → PhaseDeferred("§12").

1.3 Deployment Model

Shipped as (a) Rust library crate (ml facade), (b) cdylib/staticlib C ABI (cml_*) for C/C++/Python-ctypes callers, (c) CLI mlc (fit/predict/cross-validate/bench/conformance over CSV/NPZ/libsvm). Single process, in-memory datasets, shared-memory threads (no service, no persistence beyond model files).

1.4 Target Users

Engineers who want to understand why a boosted tree beats a single tree, what SMO solves, why PCA components are covariance eigenvectors, how sklearn's API decomposes; downstream projects (#123 recommender reuses metrics/modelselection; #122 feeds Dataset).

1.9 Recommended Language & Rationale

Rust. (a) reuse #349 (BLAS/SVD/eigen → PCA, SVM Gram, normal equations) + #350 (sparse features); (b) ownership makes the fit-before-predict / no-train-test-aliasing state machine compile-checkable; (c) zero-cost hot loops (tree-split, histogram-accumulate), no GC; (d) extern "C" clean estimator ABI; (e) Send+Sync → free data-parallel bagging/CV. Rejected: Python (sklearn's language — our reference API/oracle, but defeats "from scratch"; its hot loops are Cython/C anyway); C++ (XGBoost/LightGBM/libsvm — studied, rejected: ABI instability, weaker ownership/test tooling); Julia (calls LAPACK, defeats "from scratch"); Go (weaker numeric generics/SIMD).

Helpful: #349 (matrix ops), #350 (sparse), #112 (deep-learning contrast).

2. Why Build This

2.1 Unique Knowledge Taught

  • Greedy recursive partitioning. CART splits on the max-impurity-decrease threshold; sorted-feature scan O(n log n)/feature; why trees overfit and how pruning/depth/min-samples regularize.
  • Boosting as gradient descent in function space. GBDT fits each tree to the negative gradient of a loss (pseudo-residuals); shrinkage = LR; why a forest (variance reduction, parallel) differs fundamentally from boosting (bias reduction, sequential).
  • The histogram trick. Pre-binning turns split finding from O(n) sorted-scan to O(bins) accumulate — the XGBoost/LightGBM 10–50× speedup.
  • Constrained optimization by SMO. Soft-margin SVM dual = box-constrained QP with one equality; SMO solves it analytically two multipliers at a time; KKT = convergence oracle.
  • EM-flavored clustering & spectral structure. k-means = coord-descent on inertia (assign/update); PCA = eigenvectors of covariance / right-singular-vectors of centered data.
  • The estimator contract. Why fit/predict/transform, why preprocessing must fit on train only (leakage), why a pipeline is the only leak-safe unit for cross-validation.

2.2 Why It Matters

Classical ML is still the tabular-data workhorse (GBDT wins most Kaggle tabular); sklearn (2007) defined the estimator API the ecosystem copies; libsvm (2001) + XGBoost (2016) are among the most-cited ML systems. This stack underlies most production tabular pipelines — plus the API discipline (fit/predict/transform, no leakage, reproducibility) that makes them trustworthy.

2.3 Engineering Muscles

Numerical optimization (SGD, coord-descent, QP/SMO); cache-aware recursive structures (trees, histograms); information-theoretic split criteria; reproducible randomness; differential testing vs a mature reference (sklearn); leak-free data discipline; data-parallel map-reduce; composable API (pipelines).

2.4 Production Concepts Exercised

Seed reproducibility; train/serve-skew avoidance (same preprocessing path); CV methodology; versioned model serialization; feature importance/explainability; hyperparameter search; numerical-tolerance differential conformance; prediction-latency budgets.

2.6 Calibration Value

Read sklearn/XGBoost/LightGBM/libsvm source and explain every split criterion, gradient, kernel, binning decision — and reason about why a model overfits, leaks, or fails to reproduce, not just call .fit().

2.7 What Mastery Looks Like

  • Greedy-split algebra (§16–§17): derive the impurity-decrease formula for Gini/entropy/MSE from first principles, hand-trace a 3-sample split, explain why ties at the lowest feature index preserve determinism, and read a tree's SoA node array as a control-flow graph.
  • Variance vs. bias decomposition in ensembles (§18–§19): explain why bagging (random forest) targets variance reduction with parallel trees while boosting (GBDT) targets bias reduction with sequential trees — and predict which dominates on a given bias-variance profile without running code.
  • Histogram speedup derivation (§20): derive the complexity gap O(n·p) vs O(B·p) per node, explain histogram subtraction, and identify the regime (n, B) where the speedup disappears (n ≈ B).
  • SMO convergence as constrained optimization (§21): reconstruct the dual from the primal soft-margin SVM using KKT, derive the two-multiplier analytic step, identify the three KKT zones (α=0, 0<α<C, α=C), and explain why the Keerthi two-threshold selection accelerates convergence vs Platt's original.
  • Leakage and pipeline discipline (§14): construct the exact leakage experiment (full-fit vs fold-fit CV gap), explain why the Pipeline is the enforcement seam, and diagnose a production train/serve skew from feature statistics alone.
  • PCA as spectral geometry (§23): connect the SVD of centered data to the eigendecomposition of the covariance matrix, explain why SVD is numerically preferred when condition(XᵀX)=condition(X)², and state when the covariance route is cheaper.
  • Numerical tolerance as a contract (§4, §30): set a defensible per-estimator rtol given float accumulation order, explain why bit-reproducibility across thread counts is not promised, and write the fixture that proves the tolerance is achieved.

3.2 Box Narratives

  • Public API / ml facade. Re-exports typed estimators; contract fit(&mut,&Dataset), predict(&self,&FeatureMatrix), transform. Thin — validates shapes/dtype/fit-before-predict; no learning logic; selects f32/f64.
  • cabi ABI. #[repr(C)] opaque handles (CmlEstimator*); marshals row-major double*+dims → FeatureMatrix view, writes predictions to caller buffers, never panics across boundary (catch → code); hyperparams via flat CmlParams.
  • ml-core. The vocabulary. Dataset{X,y}; FeatureMatrix dense (#349 MatView) or sparse (#350 CSR); the three traits = the estimator algebra; Rng seed-derived/explicit (no global RNG → I1); FitState enforces fit-before-predict. No algorithms.
  • metrics. Pure fns over (y_true,y_pred)/(y_true,y_score). Classification: confusion-derived acc/P/R/F1 (micro/macro/weighted), ROC-AUC (rank), log-loss. Regression: RMSE/MAE/R²/MAPE. Pairwise distances (reused by k-means/SVM-RBF). Stateless.
  • modelselection. train_test_split (stratified/seeded); KFold/StratifiedKFold → reproducible index folds (I7); cross_validate clones the estimator per fold (no cross-fold leakage); GridSearchCV/RandomizedSearchCV wrap CV over a grid. Operates on unfitted clones.
  • preprocess. Transformers that fit on train only (I3): StandardScaler (mean/std), MinMaxScaler, OneHotEncoder (train categories; unseen → zero/error), SimpleImputer. transform applies; inverse_transform where defined.
  • linear. Linear/ridge/lasso + logistic. Solvers: closed-form normal-eq/Cholesky via #349 (small p), SGD/coordinate-descent (large n, L1). Logistic = SGD on log-loss+sigmoid. Simplest baseline + harness oracle.
  • trees / CART. Greedy recursive binary splitting. split_finding scans sorted thresholds for max impurity decrease (Gini/entropy clf, MSE/MAE reg); stopping (max_depth, min_samples_split/leaf, min_impurity_decrease); CCP pruning; feature_importances_ from weighted decrease. Ensemble substrate.
  • ensemble. Random forest = bootstrap (bagging) trees + per-split feature subsample, vote/mean — variance reduction, parallel. GBDT = stage-wise regression trees on the negative gradient of a loss (log-loss/MSE), shrinkage η, row/col subsample, L1/L2 leaf reg — bias reduction, sequential. Histogram split finder pre-bins → split finding O(bins) not O(n), the speedup.
  • svm. Soft-margin SVM. Kernel/Gram (linear/RBF/poly; linear via #349); dual box-QP solved by SMO: pick two violating multipliers, optimize analytically under equality+box, repeat until KKT ≤ tol. SVs = nonzero multipliers. SVC (hinge) / SVR (ε-insensitive).
  • cluster. k-means. k-means++ seed (spread-out) → Lloyd assign/update minimizing inertia (WCSS) → converge on stable centers. Mini-batch for large n; n_init restarts keep min inertia.
  • decomp. PCA. Center → covariance-eigen OR (preferred, stabler) SVD of centered data, both via #349. Components = top-k right-singular-vectors (orthonormal, variance-sorted); transform projects; whiten ÷ singular values; explained_variance_ratio_.
  • pipeline. Composes [Transformer*, Estimator] into one estimator. fit chains fit_transform then fit; predict chains transform then predict. The only leak-safe CV unit (preprocessing re-fit per fold).
  • bench. Train-time vs n×p; predict latency; GBDT histogram speedup A/B; SMO iters-to-KKT; k-means iters; PCA SVD cost. Robust (warmup, median-of-k).
  • conformance. Naïve oracle, the sklearn differential harness (offline golden fixtures), ML-invariant asserts, fuzzing (shapes/NaN/constant features).

3.3 Boundaries

  • Trust boundary: C ABI (untrusted dims/pointers/hyperparams → validated) + untrusted data (NaN/Inf/constant columns/huge cardinality → handled, never UB).
  • Concurrency boundary: bagging trees, CV folds, per-feature split finding are independent tasks → data-parallel by construction (disjoint work, shared read-only X).
  • Numerical boundary: FP reductions in impurity/gradient/Gram depend on order; match sklearn within tol, not bit-for-bit (assert tolerance — ADR-15).
  • Leakage boundary: preprocessing stats derive only from train rows; CV re-fits preprocessing per fold; pipeline is the enforcement seam (I3).
  • Fit/predict boundary: FitState forbids predict before fit (I2).

3.4 Data-flow walk — one GridSearchCV.fit over a pipeline

  1. Build Pipeline([StandardScaler, GradientBoostingClassifier]) + param grid + StratifiedKFold(k=5, seed).
  2. GridSearchCV enumerates the grid; per combo clones a fresh unfitted pipeline.
  3. cross_validate gets k reproducible stratified folds (I7) from the seeded RNG.
  4. Per fold: split X,y train/val by index (no held-out copy leaking in).
  5. Clone; fit on train → StandardScaler learns mean/std on train only (I3); GBDT fits.
  6. predict/predict_proba on val; metrics scores; never touches train stats wrong.
  7. Mean ± std per combo; best selected; refit on full data.
  8. Optional CvTrace (fold scores, fit_ms, predict_ms, n_estimators, best_params).

4.1 Worked complexity derivation

n rows × p features:

  • Sorted-scan split: presort each feature (O(n log n)); one L→R scan updating left/right class counts → O(1)/threshold → O(p·n log n) per level, ×depth per tree (presort amortizes the log).
  • Histogram split: pre-bin each feature into B bins once (O(n·p)); per node accumulate per-bin grad/hess (O(n·p)), scan B thresholds (O(p·B)) → O(n·p + p·B) per node, scan independent of n → ≥5× win at large n (B≈256 ≪ n).
  • GBDT: M trees × per-tree; grad/hess O(n)/stage. Shrinkage η trades trees for accuracy.
  • SMO: each step O(n) (two cached kernel rows); convergence empirical, bounded by max_iter; max-KKT-violation pair selection accelerates.
  • k-means: Lloyd iter O(n·k·p) assign + O(n·p) update; ×n_init restarts.
  • PCA: center O(n·p); SVD O(min(n,p)·n·p) (#349) — dominant. Constants come from #349 GEMM/SVD + cache behavior.

6. Design Principles

  1. Correctness before speed; sklearn is the oracle. Validate every estimator vs sklearn golden fixtures ≤tol before optimizing. Violation: tuning before a green differential → plausible-looking wrong models.
  2. The estimator contract is sacred: fit/predict/transform, fit-before-predict. One trait algebra; models interchangeable in pipelines/CV. Violation: per-model APIs → no composition, no generic CV.
  3. No train/test leakage — preprocessing fits on train only, re-fit per CV fold. The pipeline enforces it. Violation: full-data scaling → optimistic CV, prod train/serve skew.
  4. Deterministic given a seed (and thread count). All randomness from an explicit seeded Rng; no global RNG. Violation: irreproducible CV/bagging/k-means++ → untestable, unscientific.
  5. A split must never increase impurity; record the decrease. The greedy invariant + importance provenance. Violation: a sign/accounting bug → worse-than-parent splits, silently bad trees.
  6. GBDT fits the negative gradient of an explicit loss. Loss → grad(+hess) is a pluggable tested contract; trees fit pseudo-residuals. Violation: conflating loss/gradient → divergence or wrong objective.
  7. SVM convergence is KKT, not iteration count. SMO stops at max KKT violation ≤ tol; max_iter is a safety bound. Violation: stopping on iterations → wrong support vectors.
  8. k-means inertia is non-increasing per iteration. Assign + update cannot raise WCSS; convergence provable. Violation: an update that raises inertia → oscillation, no guarantee.
  9. PCA components orthonormal and variance-sorted. Via SVD/eigen of centered data (#349); sign fixed. Violation: unsorted/non-orthonormal → wrong projection, irreproducible signs.
  10. Numerical behavior is a tolerance contract, not bit-equality. Promise per-estimator rtol/atol vs sklearn; reductions order-deterministic per config. Violation: promising bits → broken by any order change.
  11. Reuse #349/#350; never reimplement linear algebra. PCA SVD, SVM Gram, normal equations, SpMV go through the deps. Violation: a private matmul → numerical drift + duplicated maintenance.
  12. Bounded memory; stream, don't materialize ensembles. O(n·p) data + O(n)/pass, not O(trees·n·p). Violation: per-tree copies → OOM on large forests.
  13. Validate hyperparameters and data at the boundary. n_estimators<1, C≤0, NaN labels, empty dataset → typed error pre-compute. Violation: trusting inputs → panics, OOB, nonsense.
  14. Observability by default. Every fit can emit fold scores, iters-to-converge, split/leaf counts, KKT curve, inertia history, EVR. Violation: opaque training → un-debuggable non-convergence.

8. Domain Model — Classical ML

8.1 Data & Estimator Algebra

Dataset = {X: FeatureMatrix (n×p), y: Target}. Target = Continuous (reg), Discrete (clf, label-encoded), or None (unsupervised). FeatureMatrix = Dense(#349 MatView, row-major) or Sparse(#350 CSR). The three traits:

Estimator : fit(&mut self, &Dataset) -> Result<&mut Self>
Predictor : predict(&self, &FeatureMatrix) -> Array (+ predict_proba for classifiers)
Transformer : transform(&self, &FeatureMatrix) -> FeatureMatrix (+ fit_transform, inverse_transform)

Every model implements Estimator + one of {Predictor, Transformer}. clone() yields a fresh unfitted copy (for CV). Hyperparameters are constructor fields; fitted state lives behind FitState.

8.2 The Algorithm Taxonomy

Family Type Learns Loss/Objective Output
Linear / Logistic sup. weights w,b squared / log-loss (+L1/L2) wᵀx+b / σ(wᵀx+b)
CART tree sup. binary split tree impurity (Gini/entropy/MSE/MAE) leaf value / class
Random forest sup. bag of trees per-tree impurity mean / majority vote
GBDT sup. additive trees any differentiable loss (grad+hess) Σ η·tree(x)
SVM sup. dual multipliers α, b soft-margin dual (box QP) sign(Σ αᵢ yᵢ K(xᵢ,x)+b)
k-means unsup. k centroids inertia (WCSS) nearest-centroid assignment
PCA unsup. top-k components V max variance / min reconstruction projection XᵥV

8.3 Impurity & Split Criteria (classification + regression)

Gini(node) = 1 − Σ_c p_c² (p_c = class-c fraction)
Entropy(node) = − Σ_c p_c log p_c
MSE(node) = (1/n) Σ (yᵢ − ȳ)² (variance; regression)
MAE(node) = (1/n) Σ |yᵢ − median|
Decrease = Impurity(parent) − (n_L/n)·Impurity(L) − (n_R/n)·Impurity(R) ≥ 0 (I4)

Split finding: per feature, sort (or presorted index / histogram bins), scan midpoints between distinct values, keep incremental left/right class-counts or sum/sum-sq, pick max-Decrease (feature, threshold). Ties → lowest feature index then threshold (deterministic, matches sklearn).

8.4 GBDT Objective (second-order, XGBoost-style)

Obj = Σ_i L(yᵢ, ŷᵢ) + Σ_t Ω(f_t), Ω(f) = γ·T + ½λ‖w‖² (T leaves, w leaf weights)
At stage m, 2nd-order Taylor: gᵢ = ∂L/∂ŷ, hᵢ = ∂²L/∂ŷ² at ŷ^(m−1)
Optimal leaf weight (leaf j, instance set Iⱼ): w*ⱼ = − (Σ_{i∈Iⱼ} gᵢ) / (Σ_{i∈Iⱼ} hᵢ + λ)
Split gain: ½ [ G_L²/(H_L+λ) + G_R²/(H_R+λ) − (G_L+G_R)²/(H_L+H_R+λ) ] − γ
Update: ŷ^(m) = ŷ^(m−1) + η · f_m(x) (η = learning_rate / shrinkage)

First-order (Friedman) GBM = special case hᵢ=1 (fit trees to −gradient by MSE). Losses: regression ½(y−ŷ)² (g=ŷ−y,h=1); binary log-loss (g=σ(ŷ)−y, h=σ(1−σ)); multiclass = K OvR boosters.

8.5 SVM Dual & SMO (state machine)

Primal (soft-margin): min ½‖w‖² + C Σ ξᵢ s.t. yᵢ(wᵀφ(xᵢ)+b) ≥ 1−ξᵢ, ξᵢ≥0
Dual: max Σ αᵢ − ½ Σ_{i,j} αᵢαⱼ yᵢyⱼ K(xᵢ,xⱼ) s.t. 0 ≤ αᵢ ≤ C, Σ αᵢyᵢ = 0
SMO step: select pair (i,j) maximizing KKT violation (Keerthi two-threshold);
          optimize αᵢ,αⱼ analytically along the equality line, clip to the box;
          update b, error cache; repeat until max KKT violation ≤ tol (I6).
KKT: αᵢ=0 ⇒ yᵢf(xᵢ)≥1 ; 0<αᵢ<C ⇒ yᵢf(xᵢ)=1 ; αᵢ=C ⇒ yᵢf(xᵢ)≤1.

Kernels: linear xᵀz; RBF exp(−γ‖x−z‖²); poly (γ xᵀz + r)^d. Support vectors = {i : αᵢ>0}.

8.6 k-means & PCA (compact)

k-means++ seed: c₁ random; cⱼ ∝ D(x)² (distance to nearest chosen center).
Lloyd: assign xᵢ → argmin_k ‖xᵢ−μ_k‖² ; update μ_k = mean(assigned) ; repeat (inertia ↓, I10).
inertia = Σ_i ‖xᵢ − μ_{a(i)}‖² . n_init restarts → keep min inertia.

PCA: X̄ = X − mean ; SVD: X̄ = U Σ Vᵀ ; components = Vᵀ[:k] ; scores = X̄·V[:, :k]
explained_variance_k = σ_k²/(n−1) ; whiten: scores_k / σ_k·√(n−1).
(covariance route: eig(X̄ᵀX̄/(n−1)) → same V, less stable; SVD preferred — ADR-21.)

8.7 Worked split example (3 samples, 1 feature, binary)

For x=[1,2,3], y=[0,0,1]: Parent Gini = 1−(2/3)²−(1/3)² = 0.444. At threshold 1.5: L={y=0} Gini 0, R={0,1} Gini 0.5 → weighted (1/3·0 + 2/3·0.5)=0.333 → decrease 0.111. At threshold 2.5: L={0,0} Gini 0, R={1} Gini 0 → weighted 0 → decrease 0.444 (best) — split lands at 2.5, matching §8.3's Decrease formula.

11. Core Schema and Core Types

Normative signatures. Lightweight only — no algorithm bodies (CRITICAL RULE 10).

11.1 Dataset & feature matrix

pub struct Dataset { x: FeatureMatrix, y: Target }
pub enum FeatureMatrix { Dense(DenseMat /* #349 row-major n×p */), Sparse(CsrMat /* #350 */) }
pub enum Target { Continuous(Array1<f64>), Discrete(Array1<i32>), None }
impl FeatureMatrix { fn n(&self)->usize; fn p(&self)->usize; fn row(&self, i)->RowView;
                     fn col(&self, j)->ColView; fn select_rows(&self, &[usize])->FeatureMatrix; }

Dataset owns its data; RowView/ColView borrow; select_rows index-based (CV/bagging, no held-out copy); &FeatureMatrix is Sync (read-only task sharing).

11.2 The three traits (the estimator algebra)

pub trait Estimator: Clone {                 // Clone ⇒ fresh UNFITTED copy (CV)
    fn fit(&mut self, d: &Dataset) -> Result<&mut Self, MlError>;
    fn get_params(&self) -> Params;  fn set_params(&mut self, p: Params) -> Result<(),MlError>;
}
pub trait Predictor: Estimator { fn predict(&self, x: &FeatureMatrix) -> Result<Array1<f64>, MlError>; }
pub trait Classifier: Predictor { fn predict_proba(&self, x:&FeatureMatrix)->Result<Array2<f64>,MlError>;
                                   fn classes(&self)->&[i32]; }
pub trait Transformer: Estimator {
    fn transform(&self, x:&FeatureMatrix) -> Result<FeatureMatrix, MlError>;
    fn fit_transform(&mut self, d:&Dataset) -> Result<FeatureMatrix, MlError>;  // default: fit(d) then transform(d.x)
    fn inverse_transform(&self, x:&FeatureMatrix) -> Result<FeatureMatrix, MlError>;  // default: NoInverse
}

fit is &mut self (stores state); predict/transform are &self (immutable post-fit); a fitted estimator is Sync for parallel predict.

11.3 Fit-state guard & RNG

pub enum FitState<S> { Unfitted, Fitted(S) }   // S = per-model fitted params
impl<S> FitState<S> { fn get(&self)->Result<&S,MlError>{ /* Err(NotFitted) if Unfitted (I2) */ } }
pub struct Rng { state: u64 }                    // SplitMix64 seed → Xoshiro256** stream (I1)
impl Rng { fn seeded(seed: u64)->Self; fn next_u64(&mut self)->u64; fn uniform(&mut self)->f64;
           fn shuffle<T>(&mut self, &mut [T]); fn sample_indices(&mut self, n, k, replace)->Vec<usize>; }

Rng threaded explicitly through fit; sub-tasks get split/jumped child streams (deterministic per task index). No global RNG (ADR-6).

11.4 Tree representation (SoA flat array, ADR-8)

pub struct Tree { nodes: Vec<Node>, n_classes: usize }
pub struct Node { feature: i32 /*-1=leaf*/, threshold: f64, left: i32, right: i32,
                  impurity: f64, n_samples: u32, value: LeafValue, default_left: bool /*NaN route*/ }
pub enum LeafValue { ClassCounts(SmallVec<f64>), Regression(f64), GbdtWeight(f64) }
impl Tree { fn predict_row(&self, x:RowView)->&LeafValue;  fn n_leaves(&self)->usize; fn max_depth(&self)->usize; }

Tree owns its node array; children by index (cache-local, serializable). Predict = branch-light index walk.

11.5 Criterion & splitter contracts

pub trait Criterion {                          // classification or regression impurity
    fn node_impurity(&self, stats:&NodeStats)->f64;
    fn children_impurity(&self, l:&NodeStats, r:&NodeStats)->(f64,f64);
    fn proxy_improvement(&self, l:&NodeStats, r:&NodeStats)->f64;  // for fast comparison
}
pub struct Split { feature: usize, threshold: f64, improvement: f64, pos: usize /*sorted split idx*/ }
pub trait Splitter { fn best_split(&mut self, node:&NodeSamples, crit:&dyn Criterion,
                                   rng:&mut Rng, max_features:usize) -> Option<Split>; }

improvement is ≥ 0 by I4; None ⇒ make a leaf. Exact (sorted) and Histogram splitters implement Splitter.

11.6 GBDT loss & histogram

pub trait Loss {                               // ADR-10 (grad + hess)
    fn init_raw(&self, y:&Array1<f64>)->f64;   // initial constant prediction
    fn grad_hess(&self, y:&[f64], raw:&[f64], g:&mut [f64], h:&mut [f64]);   // I5
    fn name(&self)->&'static str;
} // impls: SquaredError, LogLoss(binary), MultinomialDeviance(K boosters), Huber, Quantile
pub struct Histogram { grad_sum: Vec<f64>, hess_sum: Vec<f64>, count: Vec<u32>, n_bins: usize }
pub struct Binner { thresholds: Vec<Vec<f64>> /*per-feature bin edges*/, n_bins: usize }
impl Binner { fn fit(d:&FeatureMatrix, n_bins:usize)->Self; fn transform(&self, x:RowView)->Vec<u8>; }

grad_hess is the pluggable, finite-diff-tested boosting contract (I5). Histograms are subtracted (parent − sibling) to halve accumulation.

15.1 Objectives

  • linear::normal_eq — solve (XᵀX+λI)w = Xᵀy via #349 Cholesky/potrf (ridge λ; OLS λ=0); bias by ones-column or centering. [ADR-3; Strang ch.4 least-squares; ridge λI regularization = Tikhonov; Higham ch.10 Cholesky stability]

  • predict = X·w+b (GEMV #349); clf thresholds proba 0.5 (binary)/argmax (multiclass). [ADR-3; I2 FitState guard]
  • Convergence: gradient-norm/loss-change tol + max_iter. [I6 pattern: tol-based stop, max_iter safety; P7]

15.3 Deliverable

  • linear crate: linear/ridge/lasso/logistic green vs sklearn fixtures; examples fit a regression + a classification dataset.

15.4 Acceptance Criteria

  • Normal-equation OLS/ridge = sklearn within rtol=1e-5 (closed-form → tight).
  • SGD logistic reaches sklearn accuracy ≤tol; loss is monotonically decreasing (modulo mini-batch noise).
  • Lasso recovers the same sparse support as sklearn on a fixture.
  • predict_proba rows sum to 1; calibrated vs sklearn ≤tol.

15.5 Conformance Fixtures

  • linear/{ols_normal_eq,ridge,lasso_path,logistic_binary,logistic_multiclass}, sgd_loss_curve (monotone-descent), predict_proba_sums_to_one.

15.6 Pitfalls

  • Not centering/standardizing for ridge/lasso (scale-dependent penalty) → wrong coefficients; document the convention.
  • SGD LR too high → diverge; too low → no convergence in max_iter.
  • Ill-conditioned XᵀX (collinear) → Cholesky fails; fall back to QR/ridge (#349).
  • Lasso not converging on correlated features → cyclic vs random coordinate order.
  • Sigmoid overflow on large logits → stable log1p(exp) form.

15.7 Performance Concerns

  • Normal-eq O(n·p²+p³) (small p); SGD O(epochs·n·p) (large n).
  • X·w/XᵀX = GEMV/SYRK in #349 (near-peak); sparse X = #350 SpMV.
  • Mini-batch size trades gradient noise vs throughput.

15.8 Edge Cases

  • p > n (underdetermined → ridge/lasso required); constant feature; perfectly separable data (logistic weights →∞ without regularization).
  • Single feature; zero-variance target (R² undefined).

15.9 Failure Analysis

  • Non-convergence → wrong weights → loss-curve telemetry + NotConverged flag; runbook non-convergence.md.
  • Ill-conditioning → unstable solve → #349 residual checks + ridge fallback.
  • Blast: linear models are baselines and GBDT's init_raw reference.

  • FitTrace: n_iter, final loss, converged, coefficient sparsity (lasso).
  • Solver selection (normal_eq vs sgd) auto by (n,p) with override.

17.1 Objectives

18.1 Objectives

  • RandomForestClassifier/Regressor: bootstrap-sampled (bagging) CART trees with per-split feature subsample, predictions aggregated (vote/mean).

19. Phase 7 — Gradient boosting (GBDT: gradients, shrinkage, subsampling, regularization)

19.1 Objectives

  • GradientBoosting{Classifier,Regressor}: stage-wise regression trees on the negative gradient of a configurable loss; shrinkage (learning rate); row/column subsampling; L1/L2 leaf regularization.
  • Second-order objective (grad+hess, XGBoost-style, ADR-10); first-order (Friedman) = the hess=1 special case.
  • The gradient-boosting core — ensemble story heart.

19.2 Detailed Implementation Steps

  • ensemble::loss — Loss trait (§11.6): SquaredError (g=ŷ−y,h=1), LogLoss (g=σ(ŷ)−y, h=σ(1−σ)), MultinomialDeviance (K boosters, softmax), Huber, Quantile. grad_hess finite-diff-tested (I5). [Friedman 2001 §4 loss functions; Chen & Guestrin 2016 §2 second-order Taylor; Murphy ch.10.5 loss-function taxonomy; I5]
  • ensemble::gbdt — init_raw (loss-optimal constant); per stage: g,h at current raw; fit regression tree to −g (or second-order gain §8.4); leaf w*=−Σg/(Σh+λ) (ADR-10); raw += η·tree. [Friedman 2001 §4 Algorithm 1; Chen & Guestrin 2016 §3 regularized objective; ADR-10; §8.4 second-order objective]
  • ensemble::leaf_weight — regularized Newton leaf value, not the MSE mean. [Chen & Guestrin 2016 Eq.(5) optimal leaf weight; ADR-10; §8.4 formula w*ⱼ]
  • Subsample: rows (stochastic GB, seeded), columns per tree/split (I1). [Friedman 2001 §5 stochastic gradient boosting; ADR-6; I1]
  • Regularize: λ (L2 leaf weights), γ (min split gain), min_child_weight (min Σh/leaf). [Chen & Guestrin 2016 §3.1 regularization term Ω(f); §8.4 split gain formula]
  • Early stop: monitor validation loss; stop after n_iter_no_change with no improvement. [Géron ch.7 early stopping; I6 pattern: tol-based convergence]
  • predict: clf = sigmoid/softmax of Σ η·tree; reg = init + Σ η·tree. [I5; §8.4 update equation]
  • Leaf-wise growth, GOSS/EFB, monotonic constraints, categorical-native splits → PhaseDeferred("§19.2"). [Ke et al. 2017; ADR-11]

19.3 Deliverable

  • GradientBoosting{Classifier,Regressor} green vs sklearn GradientBoosting*; examples/boosting_titanic.

19.4 Acceptance Criteria

  • Regression/classification match sklearn GradientBoosting* ≤tol (rtol≈1e-3; boosting accumulates float order differences).
  • grad_hess matches finite-diff gradient/hessian within 1e-5 (I5).
  • Training loss is non-increasing on train (no early stop) — the boosting guarantee.
  • Shrinkage η<1 improves generalization vs η=1 on a fixture.

19.5 Conformance Fixtures

  • ensemble/: gbdt_{reg_squared,clf_logloss,multiclass}, loss_grad_hess_finite_diff (I5), gbdt_train_loss_monotone, gbdt_shrinkage_effect.

19.6 Pitfalls

  • Conflating loss value with its gradient (I5) → boosting fits the wrong objective; the finite-diff test guards it.
  • Forgetting the learning rate in the update → overfits in few stages.
  • Multiclass = K independent boosters with a shared softmax — easy to get the per-class gradient wrong.
  • Leaf weight must use the regularized Newton step (−Σg/(Σh+λ)), not the plain mean, for second-order GBDT.
  • Row subsample without a per-stage seed → irreproducible (I1).
  • Early stopping on the training loss (always decreases) instead of validation → never stops.

19.7 Performance Concerns

  • Sequential across stages (Amdahl) — trees can't be parallelized across stages; parallelize within a tree's split finding (P8 histograms help most here).
  • Gradients/hessians are O(n) per stage; reuse buffers (no per-stage alloc, principle 12).
  • The per-stage tree fit dominates; histogram binning (P8) is the speedup.

19.8 Edge Cases

  • n_estimators very large + small η (slow, accurate); subsample=1 (deterministic GB).
  • Perfectly fit training data (residuals →0, gradients →0, trees become trivial).
  • Single class present (degenerate log-loss); constant target (regression init = mean, no trees needed).

19.9 Failure Analysis

  • Diverging training loss → wrong gradient/leaf-weight → loss-monotone fixture + grad finite-diff.
  • Reproducibility break → subsample seeding → determinism fixture.
  • Blast: GBDT is the flagship model; P8 optimizes it.

19.10 Operational Notes

  • FitTrace: per-stage train/val loss, n_trees, learning_rate, early-stop iteration.
  • staged_predict for monitoring loss vs n_estimators (sklearn-compatible).

20. Phase 8 — Histogram-based GBDT split finding (the speedup)

20.1 Objectives

  • Histogram split finding: pre-bin features once, accumulate per-bin grad/hess per node, scan B thresholds instead of n sorted values.
  • Histogram subtraction (parent − sibling) to halve accumulation.
  • The ≥5× speedup at large n (the XGBoost/LightGBM hist win).

20.2 Detailed Implementation Steps

  • ensemble::binner — fit: per-feature n_bins quantile (or uniform) edges; transform maps each value → u8/u16 bin once (O(n·p), reused across stages/trees). [Ke et al. 2017 §3.1 histogram algorithm; Chen & Guestrin 2016 §3.3 approximate split; ADR-9; §4.1 O(n·p+p·B) complexity]
  • ensemble::histogram — per node/feature: accumulate (grad_sum,hess_sum,count) into B bins in one O(n_node) pass; split scan O(B) via second-order gain (§8.4). [Chen & Guestrin 2016 §3.3; §8.4 split gain formula; ADR-10 grad+hess]
  • Subtraction: compute smaller child directly, derive the sibling parent − child (halves cost). [Ke et al. 2017 §3.1 histogram subtraction trick; §20.7 O(B) vs O(n) cost]
  • ensemble::gbdt Histogram splitter variant (selectable tree_method = exact | hist). [ADR-9; §19.2 GBDT substrate]
  • Sparsity-aware default direction for missing (NaN bin; learn default_left, I13). [Chen & Guestrin 2016 §3.4 sparsity-aware algorithm; I13; ADR-25]
  • Pool/reuse histogram buffers across nodes (principle 12). [P12 bounded memory; §24.2 perf hardening; ADR-22]

20.3 Deliverable

  • Histogram GBDT green vs the exact-split GBDT (within tol) and sklearn HistGradientBoosting*; bench shows the speedup.

20.4 Acceptance Criteria

  • Histogram GBDT matches exact GBDT predictions ≤tol (binning is an approximation → small, doc gap).
  • ≥ 5× faster than exact split finding at n ≥ 10⁵ (§4 target).
  • Matches sklearn HistGradientBoosting* ≤tol.
  • Histogram subtraction yields identical sibling histograms to direct accumulation.

20.5 Conformance Fixtures

  • ensemble/: hist_vs_exact_gap (binning bound), hist_subtraction_identity, hist_vs_sklearn_hgbt; golden/hist_speedup_n1e5 (speedup floor).

20.6 Pitfalls

  • Bin edges from train only — re-binning per node defeats the speedup; bin once.
  • Subtraction into the wrong (larger) child → recompute the small child, subtract for the large.
  • u8 overflow for n_bins>256 → use u16; document the limit.
  • Bin accumulation order differs from sorted scan → exact↔hist tolerance gap (expected).
  • NaN bin handled in the gain scan (default direction).

20.7 Performance Concerns

  • Win: scan O(B) not O(n) → n-independent scan; accumulation O(n) but cache-friendly (sequential bin writes).
  • Pooled/reused histogram buffers (no per-node alloc); SoA (g,h,count) locality.
  • u8 bins shrink X 8× (accumulation bandwidth win).

20.8 Edge Cases

  • Feature with < n_bins distinct values (fewer bins); all-same feature (one bin, no split).
  • Extreme outliers (quantile binning handles; uniform binning wastes bins).
  • Very large n_bins (memory vs accuracy tradeoff).

20.9 Failure Analysis

  • Wrong bin edges → systematically wrong splits → exact-vs-hist gap fixture catches large divergence.
  • Subtraction bug → wrong sibling histogram → subtraction-identity fixture.
  • Blast: only the histogram tree path; exact path unaffected (selectable).

20.10 Operational Notes

  • FitTrace: tree_method, n_bins, accumulation-vs-scan time, speedup factor.
  • docs/performance/histogram-speedup.md documents the A/B and the binning approximation.

21. Phase 9 — SVM (kernels + soft-margin dual + SMO)

21.1 Objectives

  • SVC/SVR: the soft-margin dual box-constrained QP solved by SMO (Sequential Minimal Optimization).
  • Kernels: linear (via #349 Gram), RBF, polynomial, sigmoid; bounded LRU kernel cache (ADR-13).
  • KKT conditions as the convergence oracle (I6); support-vector identification.

21.2 Detailed Implementation Steps

  • svm::kernel — Kernel::eval linear/RBF/poly/sigmoid (§8.5); linear Gram via #349 GEMM. [Cortes & Vapnik 1995 §2 kernel trick; ADR-3 #349 GEMM for linear; §8.5 kernel formulas]
  • svm::gram_cache — bounded LRU row cache (libsvm-style, ADR-13); kernel rows on demand, O(cache) not O(n²). [ADR-13; libsvm svm.cpp kernel-cache design; §33 O(n²) memory ceiling; §26 resource-exhaustion threat]
  • svm::smo — Platt/Keerthi: keep α, error/grad cache, b; loop {select max-KKT-violating pair; optimize the two multipliers analytically along the equality line, clip to [0,C]; update b + grad cache} until max KKT ≤ tol (I6) or max_iter. [Platt 1998 §2 analytic subproblem; Keerthi et al. 2001 §3 two-threshold selection; ADR-12; I6; Boyd & Vandenberghe ch.5 KKT]
  • svm::working_set — two-threshold (b_up/b_low) selection (Keerthi); shrinking (drop bounded multipliers) optional. [Keerthi et al. 2001 §2 KKT zones; libsvm Solver::select_working_set; ADR-12]
  • svm::svc — sign(Σ αᵢyᵢK(xᵢ,x)+b); predict_proba via Platt → PhaseDeferred("§21.2"), default raw decision. [Cortes & Vapnik 1995 §2; §8.5 decision function; §1.7 Platt calibration deferred]
  • svm::svr — ε-insensitive regression dual (two multipliers/sample). [ESL ch.12.3.2 SVR ε-insensitive loss; dual with α,α* per sample]
  • SvmModel stores only support vectors (αᵢ>0). [ADR-13; §11.7 SvmModel type; §33 O(n_sv·n) predict cost]

21.3 Deliverable

  • SVC/SVR with all kernels green vs sklearn (libsvm) ≤tol; examples/svm_moons.

21.4 Acceptance Criteria

  • Decision values / predictions match sklearn (libsvm) within rtol=1e-3 (same SMO tol).
  • At convergence, max KKT violation ≤ tol for all multipliers (I6 assert).
  • Support-vector set = sklearn (the αᵢ>0 indices) on a fixture.
  • RBF gamma / linear / poly all match; Gram-cache result == full-Gram result.

21.5 Conformance Fixtures

  • svm/: svc_{linear,rbf,poly}, svr_eps, kkt_satisfied_at_convergence (I6), support_vectors_match, gram_cache_equiv_fullgram.

21.6 Pitfalls

  • SMO not converging on overlapping classes → working-set quality matters; verify KKT, not iterations (principle 7, I6).
  • Two-multiplier step denominator (η=K_ii+K_jj−2K_ij) ≤ 0 → degenerate case, clip to bound.
  • Kernel-cache thrash at large n → tune budget; document O(n²) ceiling.
  • RBF gamma convention (sklearn scale/auto) — match it.
  • b from free SVs (0<α<C) — averaging vs single, match libsvm.
  • Forgetting Σαᵢyᵢ=0 → wrong dual (the joint two-multiplier update preserves it).

21.7 Performance Concerns

  • Each SMO step O(n) (two kernel rows + grad update); cache amortizes recomputation.
  • Gram O(n²) if materialized → cache + on-demand at large n.
  • Linear kernel = #349 GEMM; RBF distances reuse metrics::pairwise.
  • Convergence is the cost wildcard (empirical); shrinking accelerates.

21.8 Edge Cases

  • C→∞ (hard margin, non-separable → no convergence); tiny C (under-fit); gamma too large (RBF overfits, every point an SV).
  • All one class; duplicate points (degenerate η); n=1; linearly separable (few SVs).

21.9 Failure Analysis

  • Non-convergence → return best-so-far + NotConverged{n_iter, violation} flag (not an error, I6); runbook svm-nonconvergence.md.
  • Wrong KKT check → premature stop → KKT-satisfied fixture.
  • Blast: SVM is self-contained (own crate); reuses metrics::pairwise + #349.

  • Components match sklearn up to sign (sign-fixed → exact); ‖VᵀV−I‖ ≤ c·n·u (orthonormal, I9).
  • explained_variance_ratio_ = sklearn within rtol=1e-5, sorted descending (I9).
  • transform scores + inverse_transform reconstruction match ≤tol.
  • Whitened components have unit variance.

23.5 Conformance Fixtures

  • decomp/: pca_digits_components (sign-fixed + EVR), pca_orthonormal (I9, ‖VᵀV−I‖), pca_transform_inverse, pca_whiten.

23.6 Pitfalls

  • Not centering → wrong components (PCA is on centered data).
  • Singular-vector sign ambiguity → non-reproducible signs; fix the convention (I9).
  • Covariance-eigen on ill-conditioned XᵀX squares the condition number → prefer SVD (ADR-15).
  • n_components > min(n,p) → error; support both integer count and variance fraction (0<f<1).
  • Explained-variance uses (n−1) not n — match sklearn.

23.7 Performance Concerns

  • SVD O(min(n,p)·n·p) dominates; for n≫p use the covariance XᵀX (p×p) eigen route (cheaper).
  • transform = one GEMM (#349, near-peak).
  • Randomized/truncated SVD for k≪p → PhaseDeferred.

23.8 Edge Cases

  • Constant column (zero singular value, dropped component); n_components=p (full, lossless); single feature.

23.9 Failure Analysis

  • Non-orthonormal / unsorted components → wrong projection → I9 assert + sklearn diff.
  • Numerical instability via covariance route → SVD-vs-eigen agreement fixture; prefer SVD.
  • Blast: PCA is a self-contained transformer; the heaviest #349 user (validates the dependency).

33. Scalability Analysis

  • Sample scaling (n): trees O(n log n) sorted → histogram O(n) accum + O(B) scan = lever; GBDT serial across stages (Amdahl) → parallelize within-tree; SVM dual O(n²) memory (hard ceiling → kernel approx §24.2); k-means O(n·k·p) → mini-batch; PCA O(min(n,p)·n·p).
  • Feature scaling (p): split finding O(p)/node → feature/column subsampling (RF/GBDT) reduces it; sparse (#350) for high p; normal-eq O(p³) → SGD for large p.
  • Parallelism: RF/CV/grid trivially parallel (≥0.85× linear to cores); within-tree split finding parallel across features; GBDT stages serial.
  • Memory: O(n·p) data shared read-only across tasks (no per-tree/fold copy); forest O(trees·nodes); Gram O(n²) capped by cache budget.
  • Does NOT scale (by design): multi-node/distributed (→ #115, §33); GPU (§20); SVM beyond ~10⁵ samples without kernel approx (§24.2).
  • Coordination: none (no metadata service); pure in-process compute; CV/grid is local map-reduce.

34. Mental Models & First Principles

MM1. A decision tree is a partition machine, not a function approximator. Each split partitions the input space axis-aligned; the prediction is a constant per partition cell. This predicts: trees cannot extrapolate (predict outside training range), they staircase smooth functions, and more splits = finer but more fragile partition. Bug class without it: tuning max_depth to fit a smooth curve instead of regularizing the partition count — mistaking depth for capacity. Applied in §16 (CART builder stopping criteria) and §17 (CCP pruning reduces the number of cells).

MM2. Boosting is gradient descent in function space. Each stage adds a weak model f_m that descends the loss in the space of functions (not parameter vectors). This predicts: the loss must be differentiable, shrinkage = step size, and overfitting = too many steps without regularization. Bug class without it: fitting trees to raw residuals (y−ŷ) without realizing that only equals the negative gradient for squared loss — wrong objective for log-loss or Huber. Applied in §19 (loss.grad_hess, leaf weight derivation) and §8.4 (GBDT second-order objective).

MM3. The estimator contract is a state machine: Unfitted → Fitted. fit transitions the state; predict is valid only in Fitted. Clone always yields Unfitted. This predicts: CV must clone before each fold; a fitted model passed to GridSearchCV must be cloneable to Unfitted. Bug class without it: sharing a fitted estimator across folds (fold 2 starts from fold 1's weights → leakage, I3 violation). Applied in §12 (FitState guard, I2) and §13 (cross_validate clones per fold).

MM4. Preprocessing statistics are data; test set is future data. The scaler's mean and std are learned from training samples. Using test statistics to learn them = the scaler has seen future data. This predicts: any transformer must be fit on train only; the pipeline is the enforcement seam. Bug class without it: fitting StandardScaler on the full dataset before CV — optimistic CV scores that don't reproduce in production (the canonical leakage bug). Applied in §14 (Pipeline fit/transform chain, I3) and §13 (cross_validate wraps a pipeline, not a loose estimator).

MM5. SMO is constrained coordinate descent: one hyperplane constraint, two variables free. The dual has one linear equality (Σαᵢyᵢ=0) so optimizing one α forces the partner; two variables at a time are the minimum that preserve the constraint. This predicts: pair selection quality = convergence speed; degenerate η (K_ii+K_jj−2K_ij≤0) means the two points are effectively identical → no progress. Bug class without it: selecting a singleton variable and trying to clamp it while satisfying the equality — infeasible; must always select a pair. Applied in §21 (smo::working_set two-threshold, I6 KKT stopping) and §8.5 (SMO state machine).

MM6. Inertia is a non-increasing Lyapunov function for k-means. The assign step minimizes inertia over assignments (holding centers fixed); the update step minimizes over centers (holding assignments fixed). Each step can only decrease or hold inertia. This predicts: convergence in finite steps (finite number of partitions); oscillation is impossible in exact arithmetic. Bug class without it: a center-update bug that raises inertia (divide by wrong count) — the monotone assert (I10) catches it but you don't know where to look. Applied in §22 (Lloyd loop, I10 assert) and §8.6 (inertia formula).

MM7. SVD of centered data squares the condition number for covariance. If κ(X̄)=c, then κ(X̄ᵀX̄)=c². For ill-conditioned data, the covariance eigendecomposition loses half the significant digits. This predicts: prefer the SVD path for PCA (ADR-15); the covariance path is only cheaper when n≫p. Bug class without it: choosing the covariance-eigen route for high-p, low-rank data and getting numerically noisy components that fail the orthonormality assert (I9). Applied in §23 (decomp::svd_path vs eigen_path, ADR-15) and §23.7 (regime analysis).

MM8. Histogram binning trades approximation for O(B) scan independence of n. The bin edges are fixed at fit time; all subsequent split scans are O(B) per feature per node regardless of n. This predicts: the speedup is ≈n/B (capped by accumulation O(n)) and disappears when B≈n. Bug class without it: rebinning per node (O(n log n) again) or binning on the full dataset including test (a form of leakage). Applied in §20 (Binner fit on train, histogram accumulation, §4 ≥5× target) and §8.4 (split gain formula over bins).

MM9. Bias-variance decomposition determines which ensemble to use. A high-bias model needs boosting (reduce bias sequentially); a high-variance model needs bagging (reduce variance in parallel). This predicts: a shallow decision tree is high-bias/low-variance → RF barely helps; a deep tree is low-bias/high-variance → RF reduces variance strongly; GBDT helps both but can overfit (high variance in later stages if η is too high). Bug class without it: applying RF to a model family that is already high-bias, expecting accuracy gains that won't materialize. Applied in §18 (RF variance reduction, §2.1) and §19 (GBDT bias reduction).

MM10. The leakage boundary is at the fit call, not the split. The question is not "is test data in the matrix?" but "were the statistics computed using test rows?" A full-data StandardScaler and a per-fold one produce the same fitted object format; the difference is only which rows entered fit. This predicts: splitting the data without a pipeline is insufficient — you must also ensure every transformer's fit receives only the training partition. Bug class without it: manually splitting X and y then calling scaler.fit_transform(X_train) in a loop, but accidentally passing X instead of X_train in one fold. Applied in §14 (Pipeline enforces per-fold re-fit, I3) and §25 (leakage fixture measures the score gap).

36. Back-of-Envelope Capacity Model

System Constraints (from §4): dense f64 baseline; n up to 10⁶, p up to 10⁴ dense; fits in RAM; x86-64 with AVX2.

C1. Feature matrix memory (dense, f64) Formula: mem = n × p × 8 bytes At n=10⁶, p=10³: 10⁶ × 10³ × 8 = 8 GB — just within a 16 GB server; p=10⁴ → 80 GB (needs batching or sparse). At n=10⁵, p=10³: 10⁵ × 10³ × 8 = 800 MB — comfortable for training.

C2. Sorted split-finding time per tree (exact) Formula: T_exact = depth × p × n × C_compare; C_compare ≈ 3 ns (branch + increment + compare). At depth=10, p=100, n=10⁵: 10 × 100 × 10⁵ × 3ns = 3 s/tree — slow; histogram needed. At depth=10, p=100, n=10³: 10 × 100 × 10³ × 3ns = 3 ms/tree — fine.

C3. Histogram split-finding time per tree Formula: T_hist = depth × (p × n × C_accum + p × B × C_scan); C_accum ≈ 1 ns/sample (sequential write), C_scan ≈ 0.5 ns/bin. At depth=10, p=100, n=10⁵, B=256: 10 × (100 × 10⁵ × 1ns + 100 × 256 × 0.5ns) ≈ 100ms/tree. Speedup vs C2: 3s/100ms = 30× (exceeds the ≥5× §4 target at this n).

C4. GBDT training time (M stages) Formula: T_gbdt = M × T_hist + M × n × C_grad; C_grad ≈ 5 ns/sample (sigmoid + grad). At M=100, n=10⁵: 100 × 100ms + 100 × 10⁵ × 5ns = 10s + 0.05s ≈ 10s — feasible. At M=1000, n=10⁶: 1000 × 1s + 1000 × 10⁶ × 5ns ≈ 1000s + 5s ≈ 17 min — large run.

C5. Gram matrix memory (SVM, dense) Formula: mem_gram = n² × 8 bytes At n=10⁴: 10⁸ × 8 = 800 MB — borderline; n=3×10⁴ → 7.2 GB (hard ceiling → kernel cache). Cache budget (ADR-13): 200 MB → n_cached = 200MB / (n × 8B) = 200MB / 80kB = 2500 rows at n=10⁴.

C6. SVM predict time (n_sv support vectors) Formula: T_predict_per_row = n_sv × C_kernel; C_kernel(RBF) ≈ 2p flops ≈ 5 ns at p=100 with SIMD. At n_sv=1000, p=100: 1000 × 5ns = 5 µs/row — acceptable for offline; tight for 10⁴ rows/s online. At n_sv=10⁴, p=100: 10⁴ × 5ns = 50 µs/row — SVM predict bottleneck; use linear kernel or kernel approx §24.2.

C7. k-means assign time per iteration Formula: T_assign = n × k × p × C_dist / (GEMM_efficiency); GEMM: ‖x−μ‖²=‖x‖²−2Xμᵀ+‖μ‖²; throughput ≈ peak GEMM / (n×k×p) flops. At n=10⁵, k=100, p=50: 10⁵ × 100 × 50 × 2 flops = 10⁹ flops; AVX2 GEMM at 30 GFLOPS → 33 ms/iter. 300 iters × 33 ms = 10 s total — feasible.

C8. PCA SVD time Formula: T_svd = O(min(n,p) × n × p) flops; at n=10⁵, p=100, min=100: 100 × 10⁵ × 100 = 10⁹ flops; AVX2 → 33 ms — fast. At n=10³, p=10⁴, min=10³: 10³ × 10³ × 10⁴ = 10¹⁰ flops → 333 ms; covariance route p×p eigen cheaper: 10⁴ × 10³ × 10⁴ + 10¹²... no, use SVD thin (n×p) path via #349 truncated.

C9. Random forest parallel scaling Formula: T_rf = n_estimators × T_tree / n_jobs (trivially parallel, I11). At n_estimators=100, T_tree=100ms, n_jobs=8: 100 × 100ms / 8 = 1.25s — 8× speedup = linear (§4 ≥0.85× target, reached). Memory: 100 trees × 10-depth × 2^10 nodes × ~100 bytes/node = 10 MB — small.

C10. Tree predict latency Formula: T_predict_per_row = depth × C_branch; C_branch ≈ 3 ns (index lookup + compare + branch, SoA cache-friendly). At depth=20: 20 × 3ns = 60 ns/row — well under §4 target of 1 µs/row. 10⁶ rows → 60 ms.

C11. Histogram buffer memory Formula: mem_hist = n_features × n_bins × 3 × 8 bytes (grad_sum, hess_sum, count as f64). At p=1000, B=256: 1000 × 256 × 3 × 8 = 6 MB per node; with two-node look-ahead: 12 MB — small. Pool reuse means this is a fixed allocation for the duration of training (principle 12, P12).

C12. Cross-validation wall time (grid search) Formula: T_cv = |grid| × k_folds × T_fit_single At |grid|=50, k=5, T_fit=10s: 50 × 5 × 10 = 2500s ≈ 42 min — need parallelism or randomized search. At n_jobs=8: 2500/8 = 312s ≈ 5 min — tolerable; use RandomizedSearchCV to subsample the grid.

38. Alternative Architectures (Roads Not Taken)

Alt-1. Probabilistic Gradient Boosting (Bayesian optimization of the ensemble)

Input x ──► [GP surrogate] ──► acquisition fn ──► next tree ──► update posterior
                ▲                                                        │
                └──────────────── observation of y ──────────────────────┘

Regime where it wins: When the number of training samples is small (n < 1000) and the cost of each tree-fit is low relative to the value of uncertainty quantification. Bayesian boosting produces calibrated prediction intervals without Platt scaling — useful in drug discovery (small datasets, high consequence).

Real system: NGBoost (Duan et al., ICML 2020) — natural gradient boosting for probabilistic predictions; each stage fits a parametric distribution (Normal, Laplace) to the data using natural gradients.

Why rejected: (a) Sequential by design with no histogram speedup path — O(n²) GP overhead per stage; (b) the natural gradient requires inverting the Fisher information matrix per stage, breaking the O(n·p) per-stage cost model; (c) probabilistic calibration is deferred to §21.2 (Platt scaling) as a post-hoc step; (d) does not reduce to sklearn's GradientBoosting* as the differential oracle.

Alt-2. Kernel SVM via Random Fourier Features (Nyström / RFF approximation)

Input x ──► [D random Fourier features z(x)] ──► linear SVM (linear time)
                (z sampled from ω ~ p(ω) s.t. k(x,y) = E[z(x)ᵀz(y)])

Regime where it wins: n > 10⁵ where the O(n²) Gram memory ceiling makes exact SVM infeasible. RFF approximates the RBF kernel with D features (D ~ 1000–10000) and trains a linear SVM in O(n·D) — compatible with SGD and GPU acceleration. Used by Rahimi & Recht (NeurIPS 2007) and sklearn.kernel_approximation.RBFSampler.

Real system: sklearn.kernel_approximation + LinearSVC — the standard production recipe for large-n kernel classification.

Why rejected: The §4 target (n ≤ ~10⁵ for SVM) means exact SMO fits. The approximation introduces a hyperparameter D (number of random features) that changes the algorithm's convergence behavior and complicates the differential oracle. Kernel approximation is explicitly deferred to PhaseDeferred("§24.2") for the large-n extension.

Alt-3. Incremental / Online Learning (SGD on all models)

Streaming data ──► mini-batch gradient step ──► running model (no full re-fit)
     x_t                  w_{t+1} = w_t − η∇L(w_t; x_t)

Regime where it wins: When data arrives faster than a full re-fit can run (high-frequency sensor data, click streams), when the data distribution drifts and the model must adapt without retraining from scratch, or when the dataset is too large to hold in memory (n > available RAM / p).

Real system: sklearn.linear_model.SGDClassifier.partial_fit — the partial_fit API for online linear models; river (formerly creme) — pure online ML library; Vowpal Wabbit — large-scale online learning.

Why rejected: Every estimator in this project has a batch fit contract (I2: FitState = Fitted after fit). Incremental learning requires a different state machine (intermediate states, forgetting schedules) that breaks the sklearn clone/CV contract. Correctness validation via differential testing against sklearn becomes impossible (sklearn's online models produce different parameter trajectories). Deferred to PhaseDeferred("§12").

Alt-4. Oblique Trees (multivariate linear splits)

Node: split on sign(w · x − b) instead of x_j < t
Each node = a linear separator in feature space (not axis-aligned)

Regime where it wins: When the decision boundary is diagonal in feature space and many axis-aligned splits are needed to approximate it (e.g., two correlated features define a boundary). An oblique split achieves in one node what CART needs O(depth) nodes to approximate — fewer nodes, better calibration.

Real system: OC1 (Murthy et al. 1994, JAIR); sklearn's ExtraTreesClassifier with a random-feature-combination variant; MOC (Minimum Oblique Complexity trees).

Why rejected: (a) Oblique split finding is NP-hard to optimize exactly; heuristics (random direction, hill-climbing) introduce non-determinism that breaks the sklearn structural differential (I1); (b) feature importances become ill-defined (each node mixes features); (c) the XGBoost/LightGBM/sklearn ecosystems all use axis-aligned CART as the substrate — the differential oracle assumes axis-aligned; (d) axis-aligned trees compose cleanly into RF and GBDT; oblique splits require a redesigned ensemble.
