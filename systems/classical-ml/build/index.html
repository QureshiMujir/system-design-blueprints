⬜ Phase 0 — Skeleton: Dataset, estimator traits, RNG, label encoder, a naïve baseline + oracle §12

Objectives
  • Stand up the Cargo workspace (ADR-2) with ml-core + conformance skeletons; wire #349/#350 deps.
  • Define Dataset, FeatureMatrix (dense + sparse view), Target, the three traits, FitState, seeded Rng, LabelEncoder.
  • Ship one oracle-verified estimator end-to-end (DummyClassifier/MeanRegressor) to prove the harness.
  • Establish sklearn fixture-generation + differential scaffolding every later phase reuses.
Deliverable
  • cargo run -p mlc -- fit --model dummy data.csv fits and predicts a trivial baseline.
  • cargo test runs trait/fitstate/rng/labelencoder unit tests + the dummy estimator vs oracle.
Acceptance
  • DummyClassifier predicts the training majority; MeanRegressor predicts the mean — both match a hand-computed oracle exactly.
  • Rng produces identical streams for identical seeds across reruns (I1 golden test).
  • predict before fit returns NotFitted (I2); unseen label returns UnknownLabel (I15).
  • Dense and sparse FeatureMatrix round-trip select_rows correctly; Miri clean.
Fixtures
  • modelselection/rng_stream_seed{1,2} (RNG per seed); ml-core/labelencoder_bijection (round-trip+unseen), dummy_{clf,reg}; sklearn_golden/_manifest (inventory+version).
Pitfalls
  • Global/implicit RNG anywhere → non-reproducibility (I1); ban it, thread Rng explicitly.
  • select_rows copying held-out data into a "train" matrix → latent leakage; keep it index-based.
  • Sparse vs dense FeatureMatrix divergent semantics (e.g. implicit zeros) → unify via the trait.
  • Label encoding silently mapping unseen → 0 (sklearn-incompatible & dangerous); error instead (I15).

⬜ Phase 1 — Metrics + model selection (CV, splits, search) §13

Objectives
  • the full metric set (classification + regression) and pairwise distances.
  • train_test_split, KFold/StratifiedKFold, cross_validate, GridSearchCV/RandomizedSearchCV.
  • Lock the reproducible-fold (I7/I8) and estimator-cloning (no-leakage-across-folds) discipline reused everywhere.
Deliverable
  • metrics + modelselection green vs sklearn golden fixtures.
  • cross_validate runs a dummy estimator over 5 folds with reproducible scores.
Acceptance
  • Every metric = sklearn within rtol=1e-6 on golden fixtures (these are pure functions → tight tolerance).
  • KFold folds are a disjoint full cover (I7); StratifiedKFold ratios within ±1 sample/class (I8).
  • Identical seed ⇒ identical folds and search trajectory (I1).
  • GridSearchCV selects the same best params as sklearn on a small grid.
Fixtures
  • metrics/{accuracy,f1_macro,roc_auc_binary,roc_auc_multiclass,logloss,rmse,r2}; modelselection/{kfold_indices,stratified_ratios,grid_search_iris} (last = best params + CV scores).
Pitfalls
  • AUC tie-handling (equal scores) — averaged-rank method to match sklearn.
  • macro/micro/weighted F1 confusion — implement and label all three.
  • Stratified split with rare classes (< k) — handle (some folds lack a class).
  • cross_validate sharing fitted state across folds → leakage; always clone (I11).
  • R² for constant y_true (variance 0) → define as sklearn (0/NaN, documented).

⬜ Phase 2 — Preprocessing + pipelines (the no-leakage seam) §14

Objectives
  • StandardScaler/MinMaxScaler/OneHotEncoder/SimpleImputer as Transformers that fit statistics on train only (I3).
  • Pipeline composing [Transformer*, Estimator] into one leak-safe estimator usable inside CV.
  • Establish the leakage-detection fixture (full-fit vs fold-fit score gap).
Deliverable
  • preprocess + pipeline green; a Pipeline([StandardScaler, DummyClassifier]) fits/predicts and cross-validates leak-free.
Acceptance
  • Each transformer = sklearn within rtol=1e-6 on golden fixtures.
  • Leakage fixture: CV score with in-fold scaling differs from (wrong) full-data scaling → gap proves I3 enforcement.
  • Pipeline fit→predict equals manual chained transform+predict.
  • OneHot unseen-category and Imputer NaN handling match policy.
Fixtures
  • preprocess/{standard_scaler,minmax,onehot,imputer_mean,imputer_median}, leakage_demo (fold-fit vs full-fit CV, I3); pipeline/pipeline_transform_predict.
Pitfalls
  • Fitting the scaler on the whole dataset before CV → canonical leakage bug; the pipeline + per-fold re-fit prevents it (I3).
  • std=0 constant column → divide-by-zero; guard (σ→1).
  • OneHot column ordering must be deterministic (sorted categories) for reproducibility + serialization.
  • Imputer median on even counts — match sklearn's interpolation.
  • ColumnTransformer column-index drift after one-hot expansion (track output column provenance).

⬜ Phase 3 — Linear & logistic regression baseline (SGD + normal equations via #349) §15

Objectives
  • Linear/ridge/lasso + logistic regression — the first real learners.
  • Two solvers: closed-form normal-eq/Cholesky via #349 (small p), SGD/coordinate-descent (large n, L1).
  • Simplest fit/predict models + a second oracle ("does training descend?").
Deliverable
  • linear crate: linear/ridge/lasso/logistic green vs sklearn fixtures; examples fit a regression + a classification dataset.
Acceptance
  • Normal-equation OLS/ridge = sklearn within rtol=1e-5 (closed-form → tight).
  • SGD logistic reaches sklearn accuracy ≤tol; loss is monotonically decreasing (modulo mini-batch noise).
  • Lasso recovers the same sparse support as sklearn on a fixture.
  • predict_proba rows sum to 1; calibrated vs sklearn ≤tol.
Fixtures
  • linear/{ols_normal_eq,ridge,lasso_path,logistic_binary,logistic_multiclass}, sgd_loss_curve (monotone-descent), predict_proba_sums_to_one.
Pitfalls
  • Not centering/standardizing for ridge/lasso (scale-dependent penalty) → wrong coefficients; document the convention.
  • SGD LR too high → diverge; too low → no convergence in max_iter.
  • Ill-conditioned XᵀX (collinear) → Cholesky fails; fall back to QR/ridge (#349).
  • Lasso not converging on correlated features → cyclic vs random coordinate order.
  • Sigmoid overflow on large logits → stable log1p(exp) form.

⬜ Phase 4 — Decision tree classifier (CART: Gini/entropy, exact split finding) §16

Objectives
  • DecisionTreeClassifier: greedy recursive binary CART with Gini/entropy, exact sorted-scan split finding, stopping criteria.
  • Flat SoA tree (ADR-8); deterministic tie-breaking matching sklearn.
  • The substrate every ensemble reuses.
Deliverable
  • DecisionTreeClassifier green vs sklearn on iris/synthetic; examples/iris_tree trains + visualizes.
Acceptance
  • Identical tree structure (split features + thresholds) to sklearn on fixtures with the same tie rule and random_state.
  • Every accepted split has improvement ≥ min_impurity_decrease ≥ 0 (I4).
  • Predict accuracy = sklearn ≤tol; proba rows sum to 1.
  • Deterministic given seed (I1) when max_features < p.
Fixtures
  • trees/: clf_gini_iris, clf_entropy_synthetic (structure+predictions), split_tie_lowest_index (tie rule), stopping_min_samples_leaf.
Pitfalls
  • Tie-rule divergence from sklearn → trees differ → pin the exact rule (lowest index/threshold), test.
  • Threshold = midpoint of distinct sorted values (not the value) — off-by-one misplaces points.
  • min_samples_leaf checked on both children before accepting a split.
  • Float equality in "distinct values" (tolerance/strict <) → spurious equal-value splits.
  • Presort once, pass sorted indices down (re-sorting per node wastes O(n log n)).

⬜ Phase 5 — Decision tree regressor + cost-complexity pruning + feature importance §17

Objectives
  • DecisionTreeRegressor: MSE/MAE criteria, mean/median leaf values.
  • CCP pruning (ccp_alpha) and feature_importances_.
  • Complete the CART substrate (classification + regression, pruned, explainable).
Deliverable
  • DecisionTreeRegressor + CCP pruning + feature_importances_ green vs sklearn.
Acceptance
  • Regression tree structure + predictions match sklearn ≤tol.
  • CCP pruning path (α thresholds + subtree sizes) = sklearn's cost_complexity_pruning_path.
  • feature_importances_ = sklearn within rtol=1e-5; sums to 1.
  • MAE leaves use the median (not mean).
Fixtures
  • trees/: reg_mse_synthetic, reg_mae, ccp_pruning_path (α thresholds + node counts), feature_importances.
Pitfalls
  • MAE median expensive per split (vs MSE O(1) incremental variance) → MAE slower by design.
  • Naïve sum-of-squares variance loses precision → Welford / careful sum-sq (Higham).
  • CCP α_eff off-by-one in |leaves|−1 → wrong pruning sequence.
  • Importance weights by node sample fraction, not raw decrease.
  • Pruning operates on the fully-grown tree, bottom-up.

⬜ Phase 6 — Random forest (bagging + feature subsampling) §18

Objectives
  • RandomForestClassifier/Regressor: bootstrap-sampled (bagging) CART trees with per-split feature subsample, predictions aggregated (vote/mean).
  • Parallelize tree fitting (the trivially-parallel win) with a thread pool / n_jobs.
  • Add out-of-bag (OOB) error estimation.
Deliverable
  • RandomForest{Classifier,Regressor} green vs sklearn; parallel scaling curve; OOB score.
Acceptance
  • Predictions match sklearn ≤tol (RF is randomized → match the distribution/accuracy, and exact structure with identical seed + tie rule).
  • Parallel fit is deterministic per (seed, n_jobs) (I1/I11) and ≥ 0.85× linear scaling.
  • OOB score approximates held-out test accuracy.
  • TSan clean (no races on shared X / output).
Fixtures
  • ensemble/: rf_clf_iris, rf_reg_synthetic (accuracy + seeded structure), rf_oob_score; golden/rf_parallel_determinism (identical n_jobs∈{1,2,4}).
Pitfalls
  • Bootstrap RNG not per-tree-deterministic → irreproducible forest; use per-tree child streams (I1).
  • Parallel fit sharing a mutable buffer → race; each tree owns its partition/output (I11).
  • max_features default differs (sqrt(p) classification, p/3 or p regression) — match sklearn.
  • OOB requires tracking which samples each tree saw — bookkeeping bug → wrong OOB.
  • Aggregating class labels vs probabilities — sklearn averages proba (soft vote).

⬜ Phase 7 — Gradient boosting (GBDT: gradients, shrinkage, subsampling, regularization) §19

Objectives
  • GradientBoosting{Classifier,Regressor}: stage-wise regression trees on the negative gradient of a configurable loss; shrinkage (learning rate); row/column subsampling; L1/L2 leaf regularization.
  • Second-order objective (grad+hess, XGBoost-style, ADR-10); first-order (Friedman) = the hess=1 special case.
  • The gradient-boosting core — ensemble story heart.
Deliverable
  • GradientBoosting{Classifier,Regressor} green vs sklearn GradientBoosting*; examples/boosting_titanic.
Acceptance
  • Regression/classification match sklearn GradientBoosting* ≤tol (rtol≈1e-3; boosting accumulates float order differences).
  • grad_hess matches finite-diff gradient/hessian within 1e-5 (I5).
  • Training loss is non-increasing on train (no early stop) — the boosting guarantee.
  • Shrinkage η<1 improves generalization vs η=1 on a fixture.
Fixtures
  • ensemble/: gbdt_{reg_squared,clf_logloss,multiclass}, loss_grad_hess_finite_diff (I5), gbdt_train_loss_monotone, gbdt_shrinkage_effect.
Pitfalls
  • Conflating loss value with its gradient (I5) → boosting fits the wrong objective; the finite-diff test guards it.
  • Forgetting the learning rate in the update → overfits in few stages.
  • Multiclass = K independent boosters with a shared softmax — easy to get the per-class gradient wrong.
  • Leaf weight must use the regularized Newton step (−Σg/(Σh+λ)), not the plain mean, for second-order GBDT.
  • Row subsample without a per-stage seed → irreproducible (I1).
  • Early stopping on the training loss (always decreases) instead of validation → never stops.

⬜ Phase 8 — Histogram-based GBDT split finding (the speedup) §20

Objectives
  • Histogram split finding: pre-bin features once, accumulate per-bin grad/hess per node, scan B thresholds instead of n sorted values.
  • Histogram subtraction (parent − sibling) to halve accumulation.
  • The ≥5× speedup at large n (the XGBoost/LightGBM hist win).
Deliverable
  • Histogram GBDT green vs the exact-split GBDT (within tol) and sklearn HistGradientBoosting*; bench shows the speedup.
Acceptance
  • Histogram GBDT matches exact GBDT predictions ≤tol (binning is an approximation → small, doc gap).
  • ≥ 5× faster than exact split finding at n ≥ 10⁵ (§4 target).
  • Matches sklearn HistGradientBoosting* ≤tol.
  • Histogram subtraction yields identical sibling histograms to direct accumulation.
Fixtures
  • ensemble/: hist_vs_exact_gap (binning bound), hist_subtraction_identity, hist_vs_sklearn_hgbt; golden/hist_speedup_n1e5 (speedup floor).
Pitfalls
  • Bin edges from train only — re-binning per node defeats the speedup; bin once.
  • Subtraction into the wrong (larger) child → recompute the small child, subtract for the large.
  • u8 overflow for n_bins>256 → use u16; document the limit.
  • Bin accumulation order differs from sorted scan → exact↔hist tolerance gap (expected).
  • NaN bin handled in the gain scan (default direction).

⬜ Phase 9 — SVM (kernels + soft-margin dual + SMO) §21

Objectives
  • SVC/SVR: the soft-margin dual box-constrained QP solved by SMO (Sequential Minimal Optimization).
  • Kernels: linear (via #349 Gram), RBF, polynomial, sigmoid; bounded LRU kernel cache (ADR-13).
  • KKT conditions as the convergence oracle (I6); support-vector identification.
Deliverable
  • SVC/SVR with all kernels green vs sklearn (libsvm) ≤tol; examples/svm_moons.
Acceptance
  • Decision values / predictions match sklearn (libsvm) within rtol=1e-3 (same SMO tol).
  • At convergence, max KKT violation ≤ tol for all multipliers (I6 assert).
  • Support-vector set = sklearn (the αᵢ>0 indices) on a fixture.
  • RBF gamma / linear / poly all match; Gram-cache result == full-Gram result.
Fixtures
  • svm/: svc_{linear,rbf,poly}, svr_eps, kkt_satisfied_at_convergence (I6), support_vectors_match, gram_cache_equiv_fullgram.
Pitfalls
  • SMO not converging on overlapping classes → working-set quality matters; verify KKT, not iterations (principle 7, I6).
  • Two-multiplier step denominator (η=K_ii+K_jj−2K_ij) ≤ 0 → degenerate case, clip to bound.
  • Kernel-cache thrash at large n → tune budget; document O(n²) ceiling.
  • RBF gamma convention (sklearn scale/auto) — match it.
  • b from free SVs (0<α<C) — averaging vs single, match libsvm.
  • Forgetting Σαᵢyᵢ=0 → wrong dual (the joint two-multiplier update preserves it).

⬜ Phase 10 — k-means (++ seeding + Lloyd + mini-batch) §22

Objectives
  • KMeans: k-means++ seeding, Lloyd's assign/update loop, inertia objective, multi-restart.
  • Mini-batch variant for large n (Sculley 2010).
  • Enforce inertia monotonicity (I10) and reproducibility (I1).
Deliverable
  • KMeans (full + mini-batch) green vs sklearn; examples/kmeans_blobs.
Acceptance
  • Final inertia and cluster assignments match sklearn ≤tol (same random_state, n_init).
  • Inertia is non-increasing every iteration (I10 assert).
  • k-means++ seeding is reproducible per seed (I1).
  • Mini-batch converges to near-full-batch inertia (doc gap).
Fixtures
  • cluster/: kmeans_blobs (centers+inertia+labels), kmeanspp_seeding (reproducible init), inertia_monotone (I10), empty_cluster_reinit.
Pitfalls
  • Inertia increasing across an iteration (I10) → assign/update bug; assert and fail.
  • Empty cluster (no points) → undefined mean; reinitialize (no divide-by-zero).
  • k-means++ unseeded → irreproducible (I1).
  • Expanded ‖x−μ‖² (GEMM, fast) can go slightly negative from rounding → clamp at 0.
  • n_init keeping the last (not minimum) inertia → suboptimal.

⬜ Phase 11 — PCA + dimensionality reduction (SVD/eigen via #349, whitening) §23

Objectives
  • PCA: center → SVD of the centered data (preferred) or covariance eigendecomposition, both via #349.
  • Components orthonormal, variance-sorted, sign-fixed (I9); transform/inverse_transform; whitening; explained-variance.
  • The dimensionality-reduction transformer; the cleanest reuse of #349.
Deliverable
  • PCA green vs sklearn (components up to sign, scores, EVR); examples/pca_digits.
Acceptance
  • Components match sklearn up to sign (sign-fixed → exact); ‖VᵀV−I‖ ≤ c·n·u (orthonormal, I9).
  • explained_variance_ratio_ = sklearn within rtol=1e-5, sorted descending (I9).
  • transform scores + inverse_transform reconstruction match ≤tol.
  • Whitened components have unit variance.
Fixtures
  • decomp/: pca_digits_components (sign-fixed + EVR), pca_orthonormal (I9, ‖VᵀV−I‖), pca_transform_inverse, pca_whiten.
Pitfalls
  • Not centering → wrong components (PCA is on centered data).
  • Singular-vector sign ambiguity → non-reproducible signs; fix the convention (I9).
  • Covariance-eigen on ill-conditioned XᵀX squares the condition number → prefer SVD (ADR-15).
  • n_components > min(n,p) → error; support both integer count and variance fraction (0<f<1).
  • Explained-variance uses (n−1) not n — match sklearn.

⬜ Phase 12 — Serialization + C ABI + performance hardening §24

Objectives
  • versioned model serialization (round-trip, I14) for every estimator.
  • Provide the extern "C" estimator ABI (cml_fit/predict/transform, opaque handles).
  • Performance-harden the hot loops (tree predict, histogram accumulation, k-means assign, Gram cache).
Deliverable
  • libcml.so/.a + cml.h; examples/cml_from_c.c links, fits, predicts; all models serialize/deserialize.
Acceptance
  • load(save(model)).predict == model.predict ≤tol for every estimator (I14).
  • A C program calling cml_fit/cml_predict gets identical results to the Rust facade.
  • No unwinding across FFI (catch_unwind test); bad args → negative code, no compute (I12).
  • Hot-loop benchmarks meet §4 latency/throughput targets; zero steady-state alloc (alloc-counter test).
Fixtures
  • serialization/roundtrip_<model> (per-model save/load, I14); cabi/c_integration (compiled C test), cabi/bad_param_codes; golden/no_alloc_in_hot_loop.
Pitfalls
  • Schema drift between versions → IncompatibleVersion on load; never silently mis-parse (I14).
  • Panic across FFI = UB → catch_unwind everywhere (mirrors #349 P11).
  • Opaque handle type confusion (fit a classifier, call regressor predict) → tag the handle with model type.
  • Float serialization (exact bit round-trip) — use a canonical encoding, not lossy text.
  • CmlParams union growing → version it; additive only.

⬜ Phase 13 — Conformance, differential (vs sklearn), fuzzing, benchmarks §25

Objectives
  • Lock correctness with a full differential suite vs sklearn golden fixtures + ML-invariant assertions.
  • Fuzz the fit paths (shapes/NaN/constant features); benchmark train-time/latency/scaling reproducibly.
  • Define "Phase-0 done" for the future coding contract.
Deliverable
  • make conformance green; make bench emits a report; make fuzz runs N iterations clean.
Acceptance
  • 100% differential pass within documented per-estimator tolerances vs sklearn.
  • All ML invariants (I1–I15) asserted and green.
  • Fuzz clean ≥ 10⁷ iterations per target (30-day canaries deferred).
  • Determinism hashes stable; bench meets all §4 constraints (histogram ≥5×, scaling ≥0.85×, latencies).
Fixtures
  • Full conformance/ corpora (trees/ ensemble/ svm/ cluster/ decomp/ linear/ metrics/ modelselection/ preprocess/); sklearn_golden/ (version manifest; iris/blobs/moons/digits/synthetic); golden/ determinism hashes.
Pitfalls
  • Tolerance too tight (false fails on legit float-order differences, esp. GBDT/SVM) or too loose (misses bugs) — derive per-estimator from theory + sklearn's own variability.
  • sklearn version drift changing golden outputs → pin the version, regenerate deliberately, version the fixtures.
  • Fuzz not hitting edge shapes (constant columns, single sample, NaN) — seed the corpus with them.
  • Determinism hash breaks legitimately on a numeric-behavior change → version the golden set with the contract (ADR-30).
  • Bench noise (turbo, neighbors) → pin governor, median-of-k.
