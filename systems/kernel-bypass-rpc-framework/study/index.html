Hard questions

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why are flow control and congestion control two separate loops with one shared admission gate rather than a single window, and give the distinct failure each prevents? (§principle 5 + I3 + I8 + MM2)
  2. A peer sends msg_size = 4 GiB in a single REQ header. Trace exactly where this is rejected, why the check must precede buffer allocation, and what telemetry fires. (§8.8 + §Phase 3 §15.6 + I3 + MM8)
  3. Explain why a retransmitted packet must carry the same pkt_seq (only setting the RETX flag), and what corrupts at the receiver if pkt_seq is incremented instead. (§Phase 4 §16.6 + I6 + §8.7 + MM4)
  4. Derive the credit window needed to fill a 100 Gb/s × 2 µs path, then explain why kSessionCredits=32 is safe per-session but the per-peer-pair aggregate can still overshoot. (§Back-of-Envelope C2 + §19.6 + §4)
  5. Why does the design tie an MsgBuffer's lifetime to the op's completion rather than the application's intent, and which two mechanisms (compile-time + runtime) jointly enforce it? (§principle 3 + I2 + §Phase 8 §20.6 + MM3)
  6. An RTO floor of 50 µs is used even though RTO is nominally "5× RTT" and the in-DC RTT is 2 µs. Compute the nominal value, explain why the floor overrides it, and what storm a 10 µs RTO would cause. (§Back-of-Envelope C6 + §Phase 4 §16.6 + I9 + MM5)
  7. UD verbs and UDP give no delivery guarantee, yet the framework claims exactly-once RPC delivery. Reconcile these — name every layer that contributes and the invariant each upholds. (§Phase 6 §18.6 + §Phase 4 + I1 + I4 + I6)
  8. Why can a credit-only sender (no pacing) cause loss on a shallow switch buffer that a paced sender at the same window avoids? Quantify the burst delay. (§principle 12 + §Back-of-Envelope C7 + §Phase 7 + MM6)
  9. Linear scaling depends on flow steering, not locks. Explain what breaks the instant a flow lands on the wrong core, which counter detects it, and why a mutex "fix" would defeat the whole design. (§principle 1 + I7 + §Phase 5 §17.6 + §Phase 10 §22.4 + MM7)
  10. A reassembly bug only reproduces under live load, never under a debugger. What determinism property is missing, how does the loopback transport provide it, and what would a replay-diff reveal? (§principle 8 + I13 + §Phase 4 §16.2 + §Phase 12 §24.6 + MM9)
  11. Why is a slow inline handler a thread-wide latency cliff rather than a single-RPC slowdown, and what is the exact mechanism (and the fix) that keeps rx_burst flowing? (§principle 15 + §Phase 10 §22.2 + MM10 + §Failure Modes HOL blocking)
  12. The framework rejects one-sided RDMA (FaRM-style) as its primitive. Explain the design tension — for what workload would one-sided win, and why does request/response RPC choose UD instead? (ADR-005 + §Comparative Architecture + §Alternative Architectures A3)
  13. Trace a duplicate REQ arriving after its RPC completed: what stops the handler from running twice, what is sent back, and how does this interact with the slot state machine? (§8.7 + I4 + I12 + §Phase 4 §16.2)
  14. Why is the large-response path receiver-paced via RFR rather than sender-pushed, and how does this give natural backpressure that complements credits? (§8.6 + §Phase 3 §15.2 + §principle 5)
  15. Compute the per-packet time budget to sustain 75 Gb/s of large-message traffic, and explain why this makes per-packet syscalls impossible and tx_burst batching mandatory. (§Back-of-Envelope C3 + §principle 2 + MM1)
  16. An incast of 16 senders hits one receiver core rated for 5 Mrps. Compute the offered load, name the two control loops that must throttle it, and describe the collapse if both are off. (§Back-of-Envelope C9 + I3 + I8 + §Phase 7 §19.4)
  17. Why does memory registration happen once at pool setup rather than per RPC? Quantify the per-RPC registration cost at 5 Mrps to show why the alternative is infeasible. (§Back-of-Envelope C8 + §Phase 8 §20.2 + §Phase 6 §18.6)
  18. Explain why wire_ver mismatch must reject a packet rather than attempt a best-effort parse, and how this makes mixed-version peers fail closed instead of misbehaving. (I14 + §8.8 + §Compatibility & Versioning + ADR-033)
  19. A large transfer runs concurrently with small RPCs on the same thread. Why doesn't it head-of-line-block them, and what is the exact ownership protocol for the session's credits during a backgrounded transfer? (§principle 10 + §Phase 10 §22.2 + I3 + §Failure Modes HOL blocking)
  20. Why does Karn's algorithm forbid sampling RTT from a retransmitted packet, and what does SRTT do without it after a loss event? (§Phase 4 §16.6 + RFC 6298 + I9 + MM5)
  21. The dispatch table is an array indexed by req_type, not a hashmap. Justify this from the latency budget and explain what the IDL codegen must guarantee about req_type ranges across services. (§Back-of-Envelope C1 + §12.7 + §Phase 9 §21.8)
  22. Why is observability built as per-thread counters aggregated on scrape rather than shared atomics, and what scaling pathology would shared counters reintroduce? (§principle 1 + §Phase 11 §23.6 + I7 + §Performance Engineering)
  23. Snap runs transport as a separate upgradable service; krpc runs it as an embedded library. Explain the latency-vs-upgradability tradeoff and the regime where each wins. (§Comparative Architecture + §Alternative Architectures A2 + ADR-029)

Mental Models & First Principles

The compressed intuitions an expert holds about kernel-bypass RPC. Each: the insight, what it predicts, the bug class you write without it, and where this blueprint applies it.

  • MM1 — On the µs data path, the kernel is not a service, it is a tax. Sockets bundle sessions, reliability, flow/congestion control, copies, and scheduling behind a syscall; kernel-bypass means you re-own every one of those in userspace and pay only for what you use. Predicts: removing the syscall + copy + stack traversal collapses RPC latency from tens of µs to single-digit µs — the eRPC result — and that the remaining cost is cache misses and branch mispredicts, not "the network". Bug without it: treating a syscall or a memcpy on the hot path as free, then wondering why p99 is 10× the median. Applied: §principle 2 (poll, never block), §principle 3 (zero-copy), §Phase 5 (no per-packet syscall), §Back-of-Envelope C1/C2.
  • MM2 — Flow control and congestion control answer different questions and must be two loops. Credits answer "can the receiver's buffers hold more?"; congestion control answers "can the network carry more?". They share an admission gate (min(credits, cc_window)) but never share state. Predicts: collapse them into one window and you either overrun a slow receiver (CC said the net was fine) or congest the net (credits said the receiver was fine). Bug without it: a single window that is correct for neither failure, oscillating between receiver-drop and incast collapse. Applied: §principle 5, I3, I8, §Phase 2, §Phase 7, §Comparative Architecture.
  • MM3 — A registered DMA buffer is co-owned by software and the NIC; freeing it is a two-party release. The app may consider an MsgBuffer done, but if the NIC still has an outstanding descriptor pointing at it, the memory is live. Predicts: tie the buffer's lifetime to the op's completion (not the app's intent) and use-after-free is impossible; decouple them and you corrupt whatever gets allocated into that slab next. Bug without it: the canonical kernel-bypass UAF — a reused buffer DMAed into mid-flight, surfacing as garbage payloads far from the real bug. Applied: §principle 3, I2, ADR-001, §Phase 8 (§20.6), §Threat Model (Memory row).
  • MM4 — Reliability over an unreliable datagram is your problem, and a retransmit must be a no-op if it wasn't lost. UD verbs and UDP give no delivery or ordering guarantee; the engine supplies seq numbers, RTO, dedup, and ordering. A correct retransmit is byte-identical and re-applying it changes nothing. Predicts: increment a pkt_seq on retransmit and you corrupt the receiver's window; re-run a handler on a duplicate REQ and you double-apply a non-idempotent op. Bug without it: reassembly corruption under loss, or a KV INCR applied twice. Applied: §principle 6, I4, I6, I9, §Phase 4, §Phase 6 (§18.6 "UD as reliable").
  • MM5 — An over-eager RTO doesn't just waste bandwidth; it manufactures the congestion it was reacting to. Fire the timer below the real RTT and you retransmit packets that were merely in flight, adding load exactly when the path is busy, feeding spurious losses into CC, which cuts rate, which the next spurious RTO undoes. Predicts: an RTO floor near or below SRTT produces a retransmit storm + a sawtoothing CC rate with zero real loss. Bug without it: a "loss event" cascade triggered purely by a misconfigured timer (the classic RTO-too-low incident). Applied: §principle 12, I9, RFC 6298/Jacobson 1988, §Phase 4 (§16.6), §19.6 (RTO/CC storm).
  • MM6 — Credits and pacing are different smoothers: one bounds how much is outstanding, the other how fast it leaves. A full credit window released as a line-rate burst overruns a shallow switch buffer even when the average rate is safe; pacing spaces packets to the CC-chosen rate. Predicts: a credit-only sender causes loss/RTT spikes on shallow buffers that a paced sender at the same window avoids. Bug without it: bursting to the window each RTT and blaming the fabric for the resulting drops. Applied: §principle 5/§principle 12, §Phase 7 (pacer.rs, §19.6 "pacing too coarse"), §Back-of-Envelope C7.
  • MM7 — Sharding turns "scaling" from a coordination problem into a steering problem. If a session lives on exactly one core and the NIC steers its flow to that core, there is no shared mutable state, no lock, and no cache-line bounce — so throughput is linear in cores. Predicts: the moment a packet lands on the wrong core you either take a lock (killing the µs budget) or a data race (corruption); correctness now hinges on flow steering (RSS/flow rules), not mutexes. Bug without it: a "thread-safe" session behind a lock that contends under load and erases the per-core win. Applied: §principle 1, I7, ADR-007, §Phase 5 (steering), §Phase 10 (§22.4), §Alternative Architectures A2.
  • MM8 — Untrusted peer packets drive the state machine, so every wire field is an attack surface until validated. msg_size, num_pkts, CR amounts, SM seqs, and wire_ver all arrive from a peer; act on them before bounding them and a single packet can OOM you, inflate credits, or double-allocate a session. Predicts: validate msg_size ≤ kMaxMsgSize before allocating the reassembly buffer and the reassembly-bomb is a dropped packet; clamp CR ≤ consumed and a forged CR cannot overrun the receiver. Bug without it: a reassembly-buffer DoS or a credit-inflation overrun from one crafted header. Applied: §principle 7, I3, I11, §8.8, §Threat Model (Reassembly/Flow-control rows), §Phase 3 (§15.6), §Phase 12 (fuzz).
  • MM9 — Determinism over a stochastic transport is engineered, not given: seed every randomness source and order every event. Loss, reorder, and duplication look nondeterministic, but a model of them is reproducible iff the loss RNG, reorder window, and event ordering are all seeded and total-ordered. Predicts: one unseeded RNG or a wall-clock dependency makes a reassembly/RTO bug irreproducible; seed them all and a captured trace replays bit-identically. Bug without it: a heisenbug in the reliability path that vanishes under a debugger. Applied: §principle 8, I13, ADR-003/ADR-021, §Phase 4 (loss injection), §Phase 12 (replay gate).
  • MM10 — Run-to-completion is the lowest-latency scheduler, but it makes one slow handler everyone's problem. Running a handler inline on the Rpc thread costs zero context switches — the µs win — but a handler that blocks for 1 ms stalls rx_burst and every other RPC on that core until it returns. Predicts: an inline blocking handler turns into a thread-wide latency cliff (loop-iteration time spikes); the fix is explicit worker offload, not a faster handler. Bug without it: a "fast" service whose tail latency is hostage to its slowest handler. Applied: §principle 15, §Phase 10 (§22.2 handler execution, §22.6), §Failure Modes (HOL blocking), §Alternative Architectures A1.

Required reading (§5)

Books

  • Peterson & Davie, Computer Networks: A Systems Approach, 5e/6e — Ch. 2 (framing, error detection), Ch. 5 (UDP, reliable transport, sliding window), Ch. 6 (congestion control: AIMD, RED/ECN). Extract: windowing, RTT estimation, ECN, why TCP-like CC behaves under loss. → applied in §Phase 2 (credits/windowing), §Phase 4 (reliability), §Phase 7 (CC/ECN).
  • RDMA Aware Programming User Manual (Mellanox/NVIDIA) — QP, CQ, MR, lkey/rkey, UD vs RC, post_send/post_recv, completion semantics. The verbs model Phase 6 mirrors.
  • Kurose & Ross, Computer Networking: A Top-Down Approach — transport-layer chapter: reliable data transfer (rdt 3.0), pipelining, Go-Back-N vs selective repeat. Reliability design baseline (§Phase 4).
  • Klabnik & Nichols, The Rust Programming Language — ownership, lifetimes, Send/Sync, unsafe/FFI. Registered-buffer lifetime safety (ADR-001, I2). → applied in §Phase 0 (types/Send/Sync), §Phase 8 (buffer-lifetime contract), §Phase 10 (!Sync sharding).
  • Drepper, "What Every Programmer Should Know About Memory" (2007) — cache lines, NUMA, DMA, hugepages. Hot-loop + buffer-pool locality. → applied in §Phase 8 (hugepage/NUMA pool), §Phase 5 (NUMA-local rings), §Performance Engineering (cache analysis).
  • Hennessy & Patterson, Computer Architecture, 6e — memory hierarchy + interconnect appendix; PCIe/DMA cost intuition for the transport model. → applied in §Phase 6 (verbs cost model), §Performance Engineering (cache/DMA analysis).
  • Varghese, Network Algorithmics — timing wheels (Ch. on timers), efficient packet processing, avoiding per-packet allocation. Timing wheel (§Phase 4/7).
  • Bertsekas & Gallager, Data Networks, 2e — flow control, windowing, queueing; Little's law for credit sizing (§Phase 2).

Glossary · 54 terms · site-wide glossary

Kernel bypass
Networking that avoids the kernel stack on the data path (userspace polling + DMA), eliminating syscalls/copies for µs latency.
RPC
Remote Procedure Call — a request to a remote handler that returns a response; here unary request/response.
Nexus
Process-wide object owning the transport, the req_type→handler registry, and background threads.
Rpc
Per-thread object owning that thread's sessions, rings, buffer slice, timers, and CC state (the sharding unit).
Session
A client↔server endpoint pair with credits, a slot table, sequence numbers, and CC state.
Slot
One of kSessionReqs (8) concurrent-RPC entries in a session, holding buffers + continuation.
MsgBuffer
Registered, headroom-bearing, scatter-gather buffer; zero-copy; app-owned until the RPC completes.
Headroom
Reserved space at a buffer's front for Pkthdr (and Eth/IP/UDP) so app data is not copied.
Pkthdr
The fixed-offset ≤1-cache-line wire header (req_type, req_num, msg_size, pkt_num/num_pkts, flags, sessions, pkt_seq).
ReqType
The 0..255 dispatch key mapping a packet to a registered handler.
req_num
Per-session monotonically increasing request id; matches request↔response (exactly-once).
pkt_seq
Per-session packet sequence number used for reliability/ordering.
Small / large path
Single-packet (≤MTU) vs multi-packet (fragmented) message paths.
Fragmentation / reassembly
Splitting a large message into MTU packets / rebuilding the original bytes in order.
RFR (request-for-response)
A packet by which the receiver pulls the next response packet (receiver-paced large responses).
CR (credit return)
A packet (or piggyback) returning consumed flow-control credits.
Credit / flow control
A per-session window bounding in-flight bytes/packets so the receiver's buffers can't overrun.
Congestion control (CC)
A control loop bounding in-flight bytes to avoid network congestion (Timely/DCQCN/window).
Timely
RTT-gradient congestion control (rate from the delay derivative); eRPC's default.
DCQCN
ECN-mark-driven rate control (RoCEv2).
ECN
Explicit Congestion Notification — a marked bit signaling queue buildup before loss.
Rate pacing
Spacing a flow's packets to the CC-chosen rate (here via a timing wheel) to avoid bursts.
Timing wheel
An O(1) hierarchical timer structure holding RTO + pacing deadlines.
RTO
Retransmission Timeout — the deadline after which an unacked packet is retransmitted.
SRTT / RTTVAR
Smoothed round-trip time / its variance; inputs to the RTO (RFC 6298).
Karn's algorithm
Don't sample RTT from a retransmitted packet (avoids ambiguity).
Idempotent retransmit
A re-sent packet is byte-identical and re-applying it is a no-op (no double effect).
Exactly-once (RPC layer)
Each request yields one response + one handler run despite retransmits/duplicates.
Dedup window
Per-session set of recently served req_nums (+ cached responses) suppressing duplicate handler runs.
Out-of-order buffering
Holding ahead-of-sequence packets until earlier ones arrive.
Transport
The pluggable datapath behind trait Transport (loopback / DPDK-UDP / RDMA-UD).
Loopback transport
In-process rings with seeded loss/reorder/dup injection — the deterministic test substrate.
DPDK
Userspace poll-mode networking framework; the model for the UDP backend (via #321).
rx_burst / tx_burst
Batched receive/transmit of multiple packets per call (amortizes per-packet cost).
RSS / flow steering
NIC mechanism routing a flow's packets to a specific queue/core (here, the session's owning thread).
RDMA / verbs
Remote Direct Memory Access; libibverbs API (QP, CQ, MR, post_send/recv, poll_cq).
UD (unreliable datagram)
A connectionless RDMA transport scaling to many peers with one QP; unreliable + unordered.
QP / CQ
Queue Pair (send/recv work queues) / Completion Queue (verbs completions).
MR / lkey / rkey
Memory Region registration; local key (this host) / remote key (peer's RDMA access).
Memory registration
Pinning + registering a buffer with the NIC/HCA so it can DMA to/from it.
Zero-copy
No data-path copy: TX DMAs from the app buffer; RX delivers the buffer to the handler.
Scatter-gather (SG)
A message spanning multiple buffers, transferred without a contiguous copy.
Hugepage
A large (2 MiB/1 GiB) memory page reducing TLB misses for the buffer pool.
Run-to-completion
Running a handler inline on the Rpc thread (no context switch) — lowest latency.
Handler offload
Moving a slow handler to a worker thread so it doesn't block the event loop.
Background thread
A Nexus thread absorbing large transfers / session management off the foreground fast path.
Incast
Many senders → one receiver, the canonical congestion-collapse scenario.
IDL
Interface Definition Language — the .svc DSL defining services/methods/messages.
Codegen
Build-time generation of typed Client stubs + Server skeletons + zero-copy (de)serialization.
Continuation (ContFunc)
The callback fired when an RPC completes (with the response or an error).
Tag
An opaque app-supplied token correlating a request with its continuation.
run_event_loop
The poll engine: rx_burst → classify → advance sessions → fire timers → run continuations.
Deterministic replay
Re-feeding a captured (seeded) packet trace yields identical RPC outcomes.
Crash-only / session-scoped
No mid-RPC durability; a peer crash surfaces as a session-scoped error; the app owns durability.
