Each card is one row of the blueprint's decision table: what was locked in, what was rejected, and — the column that matters most — the situation in which the rejected choice is the right one.

Decisions (§9) · 33 ADRs

001

Language

Chosen

Rust 1.78+ (ed. 2021)

Rejected

C++ (eRPC), Go, Java

When the rejected choice is right

C++ wins when forking/extending eRPC itself or another C++ datacenter stack where reusing its battle-tested transport + matching the team's language outweighs Rust's safety; Go/Java win for a control-plane RPC where developer velocity matters and the p99 budget is milliseconds, not microseconds (GC jitter is then negligible).

Why: Registered-buffer lifetime safety (I2); Send/Sync for sharding (I7); no GC µs tail; trait-based pluggability.

002

Transport abstraction

Chosen

trait Transport (loopback/UDP/RDMA)

Rejected

hard-coded DPDK

When the rejected choice is right

Hard-coded DPDK wins when the framework will only ever run on one DPDK NIC fleet and the trait's dynamic dispatch per burst is measurable overhead — monomorphizing to the single backend removes a vtable hop on the hot path.

Why: Pluggable datapath; CI runs on loopback without a NIC (§8 principle).

003

Default test transport

Chosen

in-process loopback w/ seeded loss/reorder

Rejected

UDP-only

When the rejected choice is right

UDP-only testing wins when the only behavior that matters is real NIC/PCIe timing (a hardware-bring-up or driver-bug investigation) and in-memory loopback's timing model is too idealized to reproduce the fault.

Why: Deterministic replay (I-determinism); no hardware in CI.

004

UDP datapath

Chosen

DPDK-style burst API via #321

Rejected

raw sockets, AF_XDP direct

When the rejected choice is right

AF_XDP wins when partial kernel bypass is required — the deployment cannot grant a NIC exclusively to userspace (shared host, no VFIO/hugepage privileges) and AF_XDP's kernel-cooperative zero-copy path is the only option; raw sockets win for a debugging build where portability beats latency.

Why: Kernel-bypass; cross-link #321; burst RX/TX for batching.

005

RDMA datapath

Chosen

UD-verbs model (libibverbs semantics)

Rejected

RC verbs, one-sided only

When the rejected choice is right

RC verbs win when the peer fan-out is small and fixed and the app wants the hardware to provide reliability + ordering (fewer software retransmits); one-sided READ/WRITE wins for a remote-memory KV (FaRM/HERD-style) where bypassing the remote CPU entirely is the goal, not request/response.

Why: UD = scalable connectionless datagrams (eRPC choice); RC deferred.

006

Async model

Chosen

poll-loop run_event_loop (no reactor)

Rejected

Tokio, async/await runtime

When the rejected choice is right

Tokio/async runtime wins when the workload is I/O-bound with thousands of mostly-idle connections (not a busy-polled core) — there a reactor that parks threads saves CPU and the executor's scheduling cost is dwarfed by network wait.

Why: Run-to-completion polling; no executor jitter on µs path (§principle 2).

007

Concurrency model

Chosen

one Rpc per thread, share-nothing

Rejected

thread-pool over shared sessions

When the rejected choice is right

Shared-session thread-pool wins when sessions are few but each is bursty and load is highly skewed — a work-stealing pool over shared sessions balances load better than pinning a hot session to one starved core (the Caladan/Shenango argument for core reallocation).

Why: Linear scaling; no hot-path locks (I7, §principle 1).

008

Cross-thread comms

Chosen

crossbeam MPSC/SPSC queues (bg threads)

Rejected

shared Mutex<Session>

When the rejected choice is right

Mutex<Session> wins for a low-throughput control path (rare SM/admin RPCs) where a mutex's simplicity and obvious correctness beat the cognitive cost of a lock-free protocol that almost never contends.

Why: Lock-free handoff to large-xfer/SM threads; no shared session state.

009

Buffer pool

Chosen

hugepage-backed, registered, slab allocator

Rejected

malloc per message

When the rejected choice is right

malloc-per-message wins in a prototype or a small-message-only deployment where registration/zero-copy is irrelevant, hugepages aren't provisioned, and the allocator's flexibility (any size) beats a fixed slab's fragmentation risk.

Why: Zero-copy + registration cost amortized; NUMA-local (§Phase 8).

010

Memory registration

Chosen

lkey/rkey model (verbs-style)

Rejected

none (copy)

When the rejected choice is right

Copy (no registration) wins when messages are tiny (≤ a cache line) so a memcpy is cheaper than the registration bookkeeping, or on a transport (pure in-process loopback) where DMA does not exist and registration is pure overhead.

Why: Required for RDMA DMA + zero-copy UDP; modeled on loopback.

011

Timers

Chosen

hierarchical timing wheel

Rejected

per-timer heap / OS timers

When the rejected choice is right

A per-timer min-heap wins when outstanding timers are few and their deadlines span a huge dynamic range (sparse, long-horizon timers) — the heap's O(log n) is fine at low n and it wastes no memory on empty wheel slots.

Why: O(1) RTO + pacing at packet rate (Varghese).

012

Reliability

Chosen

per-packet seq + RTO + selective retx

Rejected

TCP offload, Go-Back-N

When the rejected choice is right

TCP offload wins when a smart NIC provides reliable transport in hardware and the app is content with TCP semantics (then reimplementing reliability is wasted work); Go-Back-N wins on a near-lossless link where its trivial receiver (no reorder buffer) beats selective-repeat's bookkeeping.

Why: Selective repeat minimizes retransmit on loss (§Phase 4).

013

Flow control

Chosen

credit window per session

Rejected

TCP-style cwnd only

When the rejected choice is right

A single cwnd (no separate credits) wins when the receiver's buffers are effectively unbounded (huge RAM, small messages) so receiver-overrun is impossible and the second control loop is needless complexity — the network is then the only constraint.

Why: Bounds receiver buffers explicitly (I3); decoupled from CC.

014

Congestion control

Chosen

trait CongestionControl: Timely/DCQCN/window

Rejected

single hard-coded scheme

When the rejected choice is right

A single hard-coded scheme wins for an appliance that ships one transport on one known fabric forever (e.g. DCQCN on a fixed RoCE cluster) where the vtable indirection and multi-scheme test matrix are pure cost.

Why: Pluggable; Timely default (eRPC), DCQCN for RoCE (§Phase 7).

015

Wire format

Chosen

fixed Pkthdr, little-endian, versioned

Rejected

protobuf-framed header

When the rejected choice is right

A protobuf-framed (self-describing) header wins when wire flexibility/extensibility matters more than per-packet parse cost — a control protocol or a slow-path management channel where fields come and go and µs parsing is irrelevant.

Why: ≤1 cache line, fixed-offset parse on every packet (§principle 11).

016

IDL

Chosen

custom .svc DSL + build-script codegen

Rejected

gRPC .proto direct, flatbuffers

When the rejected choice is right

gRPC .proto wins when cross-language/cross-org interop and an existing protobuf ecosystem dominate (the schema must be consumable by many languages); flatbuffers wins when you want zero-copy and an established, audited format and can accept its layout rules (the smf approach).

Why: Zero-copy into MsgBuffer; Rust-native stubs (§Phase 9, x-link #178).

017

Serialization

Chosen

zero-copy field layout + headroom

Rejected

serde/JSON on hot path

When the rejected choice is right

serde/JSON wins off the hot path — config, control-plane RPCs, and debug tooling — where human-readability and ecosystem breadth beat the copy/alloc cost that is irrelevant when latency is not µs.

Why: No alloc/copy on µs path; serde only for control/IDL meta.

018

Build

Chosen

Cargo workspace, multi-crate

Rejected

Bazel

When the rejected choice is right

Bazel wins when krpc is one component of a large polyglot monorepo with remote build caching and hermetic cross-language builds already standardized on Bazel — the org-wide caching beats Cargo's per-crate model.

Why: Native, reproducible (Cargo.lock); build-script codegen.

019

Logging

Chosen

tracing (structured, off hot path)

Rejected

log + stdout

When the rejected choice is right

log + stdout wins for a tiny tool or example where structured spans are overkill and a plain line log is the fastest thing to read while debugging.

Why: Spans per RPC/session; hot path uses counters not logs.

020

Metrics

Chosen

metrics facade + Prometheus; HDR histograms

Rejected

bespoke

When the rejected choice is right

A bespoke metrics path wins when integrating into a host that already has its own telemetry pipeline (a proprietary collector) and the metrics/Prometheus facade would be a redundant second system.

Why: Latency histos + counters (§Phase 11).

021

Tracing/replay

Chosen

seeded loopback + packet-trace capture/replay

Rejected

none

When the rejected choice is right

No replay harness wins only for a throwaway spike where the reliability/CC state machine is not under test — any shipped transport needs deterministic replay, so "none" is acceptable solely pre-Phase-4.

Why: Determinism gate; reliability/CC reproducibility (§8 principle).

022

Testing

Chosen

cargo test, proptest, insta

Rejected

unit-only

When the rejected choice is right

Unit-only testing wins in the earliest Phase-0 bring-up before invariants are formalized, when a fast example-based smoke test gives quicker feedback than authoring property generators.

Why: Property tests for invariants (I1/I3/I6); snapshot wire layouts.

023

Concurrency testing

Chosen

loom (Rpc/bg-thread handoff)

Rejected

stress-only

When the rejected choice is right

Stress-only testing wins when the concurrency surface is too large for loom's exhaustive model to terminate (many threads/long sequences) — randomized stress + sanitizers then cover more real interleavings than a model that can't finish.

Why: Interleavings for I7 / queue handoff.

024

UB checking

Chosen

Miri (header parse, buffer paths)

Rejected

none

When the rejected choice is right

No Miri wins for a fully-safe crate with #![forbid(unsafe_code)] and no FFI — Miri's slowdown buys nothing when there is no unsafe to validate (relevant only to the pure-logic crates here).

Why: Catch unsafe buffer/FFI mistakes (I2).

025

Fuzzing

AFL raw

When the rejected choice is right

AFL/AFL++ wins for deep stateful targets where its mutation feedback and persistent-mode harnesses outperform libFuzzer, or when fuzzing a non-Rust component over a binary harness.

Why: libFuzzer; corpus from conformance; no-panic on malformed (§Threat).

Ad-hoc timers win for a one-off back-of-envelope measurement during exploration, where standing up a criterion harness costs more than the answer is worth.

tc/netem wins when validating against the real kernel/NIC path end-to-end (the UDP backend on hardware), where injecting loss below our transport tests the whole stack as deployed, not just the engine.

When the rejected choice is right

Implicit (unversioned) wins for a single-binary deployment where client and server are always built and rolled together from one commit, so there is never a mixed-version pair on the wire and the version fields are dead weight.

Alternative Architectures (Roads Not Taken)

Fundamentally different ways to build µs RPC for the same goal. Each: ASCII sketch, the regime where it wins, the real system embodying it, why this blueprint rejected it.

A1 — Thread-pool over shared sessions (a reactor, not run-to-completion sharding). A pool of worker threads pulls work from shared session queues behind locks; any thread can serve any session.

        ┌───────────────── shared session table (locked) ─────────────────┐
        │  S0   S1   S2   S3   ...                                          │
        └────▲─────▲─────▲─────▲───────────────────────────────────────────┘
             │     │     │     │   (work-steal; any worker, any session)
        ┌────┴──┐ ┌┴───┐ ┌┴───┐ ┌┴────┐
        │ wkr 0 │ │wkr1│ │wkr2│ │ wkr3 │   ← threads contend on the table
        └───────┘ └────┘ └────┘ └──────┘
  • Wins: highly skewed load where one session is briefly hot — work-stealing rebalances across idle cores, and a reactor that parks idle threads saves CPU when most connections are idle. This is the Caladan/Shenango argument for fast core reallocation under bursty load.
  • Real system: classic reactor RPC frameworks and async runtimes (Tokio/tonic, Netty-style servers); Seastar offers the opposite (shard-per-core), and Caladan/Shenango (Fried et al.) embody the dynamic-core-reallocation side.
  • Rejected because: the shared table needs a lock or lock-free protocol on the hot path, reintroducing contention and cache-line bouncing that erase the µs budget (MM7, §principle 1, I7). krpc chooses strict per-thread sharding (ADR-007) with offload only for genuinely slow handlers (§Phase 10), accepting that a hot session is pinned to one core.

A2 — Transport as a separate userspace service (microkernel/IPC model). A dedicated transport process owns the NIC; applications talk to it over shared memory / a local ring, and the transport can be upgraded independently.

   ┌──────────┐  shared-mem ring   ┌─────────────────────────────┐   ┌─────┐
   │ app proc │ ─────────────────▶ │ TRANSPORT SERVICE (own NIC) │ ─▶│ NIC │
   │ (RPC API)│ ◀───────────────── │ sessions, reliability, CC   │ ◀─│     │
   └──────────┘   completions      └─────────────────────────────┘   └─────┘
  • Wins: fleet-scale operation where transport must evolve (new CC, new NIC, security patches) without recompiling or redeploying every application, and where one transport process can multiplex many apps and enforce fleet-wide policy.
  • Real system: Google Snap / Pony Express (Marty et al., SOSP 2019) — userspace networking as an upgradable microkernel-style service.
  • Rejected because: the app↔transport IPC hop (even shared-memory) adds latency and a copy/handoff that an embedded library avoids, and krpc's goal is the lowest possible single-RPC latency (ADR-029, §Comparative Architecture). The independent-upgradability win does not justify the per-RPC cost for an embedded datacenter service; Snap's model is right at Google's scale, not for a library.

A3 — One-sided RDMA remote-memory access (no server-side handler at all). Instead of request/response handler invocation, expose memory and let clients READ/WRITE it directly with RDMA one-sided verbs, bypassing the remote CPU.

   client                                    server (CPU idle for reads)
     │  RDMA READ (rkey, addr, len) ─────────────▶ [registered memory region]
     │ ◀──────────── data via HCA DMA ───────────  (no handler runs)
     │  RDMA WRITE (rkey, addr, data) ───────────▶ [region mutated directly]
  • Wins: a distributed in-memory store whose dominant operation is "read a remote object", where remote CPUs are the bottleneck and bypassing them entirely (the HCA serves the read) maximizes throughput per server core.
  • Real system: FaRM (Dragojević et al., NSDI 2014) and HERD (Kalia et al., SIGCOMM 2014) build KV/transactional stores on one-sided RDMA.
  • Rejected because: the deliverable is RPC — invoking a typed handler that runs arbitrary logic — not remote-memory access; one-sided ops cannot run a handler, enforce application invariants server-side, or carry the session/credit/CC machinery this framework is built to teach (ADR-005, §1, §Comparative Architecture). UD request/response is chosen precisely because it preserves the handler-invocation model while still scaling to many peers.
