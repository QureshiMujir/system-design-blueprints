smtp_recv: the untrusted-input trust boundary — every byte from an unauthenticated remote MTA is parsed here before anything else touches it; owns the EHLO/MAIL/RCPT/DATA state machine (§8, P1, I1). smtp_submit: identical wire protocol, but SASL-authenticated (port 587, RFC 6409) — the trust boundary moves from "any TCP peer" to "any authenticated user," so relay policy differs (ADR-14). anti_abuse pipeline: a milter-style ordered chain — SPF, then DKIM, then DMARC alignment, then greylist/rate-limit — each stage can defer (4xx), reject (5xx), or annotate and continue; order is fixed because DMARC alignment needs both SPF and DKIM results (§8, I11). local_delivery: LMTP-like; runs Sieve (Phase 10) before the message ever touches Maildir, checks quota (P10), and is the only writer path into a user's Maildir for inbound mail. mailbox_store: the persistence boundary — Maildir owns durability via atomic rename (P2, I3); SQLite owns the queryable index (UIDs, MODSEQ) that Maildir's filesystem layout cannot answer efficiently (§8). imap_server: the read/write access boundary for MUAs; sessions subscribe to per-mailbox change notification for IDLE (I9); POP3 access is out of scope for Phase 0-12 (PhaseDeferred("§38")). outbound_queue: the persistence + concurrency boundary for anything not locally deliverable — four durable directories (active/deferred/hold/bounce) mirror Postfix's queue model (ADR-10); a crash must never lose a queued message (I4). smtp_outbound: the client-side SMTP state machine — resolves MX (delegated to the operator's resolver, §1), opportunistically STARTTLS, signs DKIM on egress (Phase 8) before sending. bounce_processor: generates RFC 3464 DSNs on permanent (5xx) failure or retry-budget exhaustion; verifies SPF before bouncing to avoid backscatter (T7, FM-7).

8. Domain Model / Protocol / Data Model

8.1 SMTP command grammar (section 4.1 of RFC 5321, EBNF excerpt)

command     = ehlo / helo / mail / rcpt / data / rset / vrfy / noop / quit
            / starttls / auth ;
ehlo        = "EHLO" SP domain CRLF ;
mail        = "MAIL FROM:" reverse-path [SP mail-params] CRLF ;
rcpt        = "RCPT TO:" forward-path [SP rcpt-params] CRLF ;
mail-params = esmtp-param *(SP esmtp-param) ;
esmtp-param = esmtp-keyword ["=" esmtp-value] ;   (* SIZE, BODY=8BITMIME, AUTH *)
data        = "DATA" CRLF ;
reverse-path= "<" [mailbox] ">" ;
forward-path= "<" mailbox ">" ;
mailbox     = local-part "@" domain ;

8.2 SMTP session state machine

From Event To Guard
Connected EHLO/HELO valid Greeted domain syntactically valid
Greeted STARTTLS (if advertised) TlsNegotiating → Greeted (TLS) not already TLS
Greeted AUTH (if required for submission) Authenticated(user) SASL exchange succeeds (I1)
Greeted/Authenticated MAIL FROM valid MailFrom reverse-path parses (P2)
MailFrom RCPT TO valid, relay-permitted RcptTo (accumulates) I13 relay-policy check
RcptTo DATA InData ≥1 accepted RCPT
InData <CRLF>.<CRLF> terminator Greeted (message queued) I2 durable write before 250
any RSET Greeted —
any QUIT Closed —

Worked example (accept path):

S: 220 mail.example.com ESMTP ready
C: EHLO sender.example.org
S: 250-mail.example.com Hello
S: 250-PIPELINING
S: 250-SIZE 10485760
S: 250-STARTTLS
S: 250 AUTH PLAIN LOGIN SCRAM-SHA-256
C: MAIL FROM:<alice@example.org> SIZE=1024
S: 250 OK
C: RCPT TO:<bob@example.com>
S: 250 OK
C: DATA
S: 354 End data with <CR><LF>.<CR><LF>
C: From: alice@example.org
C: To: bob@example.com
C: Subject: hi
C:
C: Hello!
C: .
S: 250 2.0.0 OK: queued as 1a2b3c

Malformed-input example: RCPT TO:<bob@example.com (missing closing >) → parser rejects at grammar level (§8.1), server replies 501 5.5.4 syntax error in parameters, session remains in MailFrom (I1) — no partial RCPT is accumulated.

Failure-path example: client disconnects mid-InData after 40% of body bytes → em-smtp-server discards the partial buffer (never reaches I2's durable-write gate), no tmp/ file is ever created, no bounce is generated (nothing was accepted) — see FM-4.

8.3 RFC 5322 message + MIME model

Message  := Headers CRLF Body
Headers  := 1*(Field-Name ":" [FWS] Field-Body CRLF *( WSP Field-Body CRLF ))
Body     := *OCTET                          ; opaque unless MIME
MIME     := Content-Type ";" boundary=B
            "--"B CRLF Part *( "--"B CRLF Part ) "--"B"--"
Part     := Headers CRLF Body

Header folding: a continuation line begins with SPACE/TAB (section 2.2.3 of RFC 5322); encoded-words (RFC 2047) decode non-ASCII header text: =?UTF-8?Q?...?=. Malformed-input example: an unterminated MIME boundary — the parser closes the last part at end-of-message and flags mime_truncated=true rather than erroring (permissive "trustworthy" parsing per section 1.2 of RFC 5322 tolerance guidance), consistent with P3 (parser never panics on malformed input).

8.4 Maildir storage model

  • Mailbox/
    • tmp/<uniq>.host (in-progress write; not yet visible)
    • new/<uniq>.host:2, (delivered, unread)
    • cur/<uniq>.host:2,S (seen; trailing flags: S=Seen R=Replied
  • T=Trashed F=Flagged D=Draft)

<uniq> = <epoch-sec>.M<µs>P<pid>.<hostname> (I3). Write path: create in tmp/, write body, fsync, rename(2) into new/ (P4, I2) — POSIX guarantees rename is atomic within one filesystem. A crash before rename leaves an inert tmp/ file, cleaned after 36h (Maildir convention, FM-1).

8.5 IMAP command grammar (excerpt, sections 6/7 of RFC 9051)

command      = tag SP (login / select / fetch / store / search / idle) CRLF ;
select       = "SELECT" SP mailbox ;
fetch        = "FETCH" SP sequence-set SP fetch-att ;
fetch-att    = "UID" / "FLAGS" / "BODY" ["[" section "]"] / "ENVELOPE" ;
store        = "STORE" SP sequence-set SP store-att-flags ;
search       = "SEARCH" SP search-key *(SP search-key) ;
idle         = "IDLE" ;                      (* RFC 2177 *)

8.6 IMAP session state machine

From Event To
NotAuthenticated LOGIN/AUTHENTICATE success Authenticated
Authenticated SELECT/EXAMINE Selected(mailbox)
Selected CLOSE/UNSELECT Authenticated
Selected IDLE IdleSelected (untagged pushes until DONE)
any LOGOUT Closed

Worked example:

* OK IMAP4rev2 Server ready
A001 LOGIN alice secret
A001 OK LOGIN completed
A002 SELECT INBOX
* 23 EXISTS
* OK [UIDVALIDITY 1] UIDs valid
* OK [UIDNEXT 24] Predicted next UID
A002 OK [READ-WRITE] SELECT completed
A003 FETCH 1:23 (UID FLAGS)
* 1 FETCH (UID 1 FLAGS (\Seen))
A003 OK FETCH completed

Malformed-input example: FETCH abc (UID) (non-numeric sequence-set) → A004 BAD invalid sequence set per section 7.1 of RFC 9051, session state unchanged (I1 analogue for IMAP).

Failure-path example: server crashes mid-STORE; on restart, MODSEQ (I8) is recomputed from the last durable Maildir flag-rename, so the client's next FETCH CHANGEDSINCE sees a consistent (possibly slightly stale, never corrupt) view — see FM-2.

8.7 Anti-abuse pipeline data model

VerifyResult { spf: SpfResult, dkim: Vec<DkimResult>, dmarc: DmarcVerdict }
SpfResult    ∈ {Pass, Fail, SoftFail, Neutral, None, TempError, PermError}
DkimResult   { selector, domain, valid: bool, canon: (Header, Body) }
DmarcVerdict { policy: {None, Quarantine, Reject}, aligned: bool }

Worked example: a message forwarded through a mailing list — original DKIM signature valid=false (headers modified by list software adding List-Id:), but SPF Pass for the forwarder's IP is not aligned with the original From: domain, so DMARC alignment fails on both checks; policy Quarantine → message delivered to the recipient's Spam mailbox, not rejected (I10, Phase 9 N.8).

Design principles (§6)

  • P1 — SMTP is push, IMAP is pull; they share storage, never state. Rule: no in-process shared mutable session state crosses the SMTP/IMAP boundary — only the Maildir + SQLite index (§3) is shared. Tradeoff: an extra persistence round-trip for cross-protocol notification (IDLE wake-up, I9). Operational implication: either subsystem restarts independently. Violated: a shared-memory shortcut couples restart/crash domains and reintroduces the coupling Postfix/Dovecot's split avoids (§2).
  • P2 — Illegal protocol states are unrepresentable in the type system. Rule: SmtpState/ImapState enums encode exactly the legal transitions (§8, §11); no boolean flags simulate a state machine. Tradeoff: more enum variants to plumb through match arms. Operational implication: a compiler error, not a runtime bug, when a phase is unhandled. Violated: boolean-flag state (as in historical sendmail) admits combinations the protocol forbids — the exact CVE-2019-19515 class of bug.
  • P3 — The untrusted-input parser never holds privilege. Rule: em-msgparse and the SMTP command parser run before authentication and before any privileged file write (§3 trust boundary). Tradeoff: two-phase parse (syntax, then semantic) costs one extra pass. Operational implication: a parser crash cannot escalate. Violated: parsing with privilege already granted is the 1988 Morris Worm's exact shape (§2).
  • P4 — Maildir writes are atomic via tmp/ → new/ rename; nothing else is durable. Rule: every delivery path writes to tmp/, fsyncs, then rename(2)s (§8, I3). Tradeoff: one extra fsync per message vs. an in-place write. Operational implication: crash recovery is "GC orphaned tmp/ files," not "replay a WAL." Violated: in-place mailbox mutation (mbox-style) corrupts under a concurrent writer or a mid-write crash.
  • P5 — SASL mechanism negotiation is pluggable, not hardcoded. Rule: em-sasl exposes one SaslMechanism trait; PLAIN/LOGIN/CRAM-MD5/ SCRAM-SHA-256/OAUTHBEARER are implementations, not special-cased branches (§11, ADR-06/07). Tradeoff: one more trait-object indirection per auth attempt. Operational implication: adding GSSAPI later is additive, not a rewrite. Violated: hardcoded mechanism dispatch blocks OAuth-only providers (Gmail/Microsoft) without a rewrite.
  • P6 — SPF, DKIM, and DMARC are evaluated in a fixed order because DMARC depends on both. Rule: SPF → DKIM → DMARC-alignment, never reordered (§8, I11). Tradeoff: DMARC's per-message cost includes both upstream checks even when one alone would suffice for a coarse decision. Operational implication: alignment failures are always attributable to a specific upstream check in logs. Violated: evaluating DMARC before its inputs exist yields a meaningless verdict.
  • P7 — The outbound queue never drops a message; it defers, bounces, or holds. Rule: every outbound message is in exactly one of active/deferred/hold/bounce at all times (§8, I4); exponential backoff caps at 5 days (§4) before a bounce is generated. Tradeoff: disk usage for long-deferred mail. Operational implication: mailq-equivalent introspection always accounts for 100% of accepted mail. Violated: dropping on transient failure silently loses mail — the "black hole" failure mode §2 explicitly rejects.
  • P8 — DKIM signs on egress with Ed25519 by default, RSA-2048 for compatibility. Rule: signing key type is per-domain configurable but Ed25519 is the shipped default (ADR-08, RFC 8463). Tradeoff: some older receivers lack Ed25519 verification support (rare in 2026). Operational implication: signing latency is ~500 µs vs. RSA's ~5 ms (§4, M5). Violated: RSA-only signing costs 10× CPU at volume (§31).
  • P9 — Sieve execution is sandboxed with a hard iteration/redirect cap. Rule: the Sieve VM (§8, Phase 10) enforces a Received:-header count cap (50) and a bytecode step budget per message. Tradeoff: pathological but legitimate scripts (long forwarding chains) may hit the cap. Operational implication: a runaway script cannot become a mail-loop DoS (T8). Violated: unbounded redirect execution is a documented incident class (T8, FM-9).
  • P10 — Per-user quota is enforced at the write path, not the read path. Rule: local_delivery and IMAP COPY/APPEND check quota before the Maildir write commits (§11, I6). Tradeoff: an extra index lookup per write. Operational implication: quota cannot be bypassed via IMAP-side copy operations (a documented pitfall, §22 Phase 12 N.6). Violated: read-path-only enforcement lets COPY multiply messages past quota.
  • P11 — TLS is opportunistic on 25, mandatory on 587/993. Rule: STARTTLS is advertised but not required for relay-to-relay SMTP (interop with the installed base); submission (587) and IMAP-over-TLS (993) require it (§4, ADR-03, RFC 8314). Tradeoff: unauthenticated relay SMTP can still be plaintext if the peer refuses STARTTLS. Operational implication: TLS posture is auditable per-port. Violated: mandatory TLS on 25 breaks interop with legacy MTAs still on the public Internet.
  • P12 — Every conformance fixture is a named, versioned file, never an inline ad hoc string. Rule: N.5 fixtures live under conformance/ fixtures/ with a stable name (§10). Tradeoff: more repository surface area. Operational implication: a regression always has a reproducible, diffable fixture (§29 Testing & Verification Strategy). Violated: inline test strings can't be shared across differential runs against Postfix/Dovecot (§5 Reference Implementations).
  • P13 — The DNS resolver is a pluggable dependency, never embedded. Rule: em-dns wraps the operator's resolver via a trait (§11); this project never runs its own authoritative or recursive resolver (§1). Tradeoff: an extra network hop per MX/TXT lookup vs. an embedded zone cache. Operational implication: DNS outages are a separately operable failure domain (FM-6). Violated: embedding DNS duplicates Authoritative-DNS (#162) and couples two independently-scaled systems.
