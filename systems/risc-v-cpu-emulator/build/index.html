⬜ Phase 0 — Repository Foundation and Correctness-Kernel Scaffolding §12

Objectives
  • Establish a deterministic, reproducible build environment for the 16-crate workspace.
  • Lock lint/dependency/audit policy before any ISA code lands (ADR-03, ADR-19).
  • Stand up CI gates: lint, unit, fuzz-smoke — full topology finalized in §27.
  • Produce the operational scaffolding (docs/adr/, docs/runbooks/, templates/) later phases fill in.
  • Introduce the correctness-kernel pattern (§7's closing paragraph) reused by every later phase.
Deliverable

A compiling, structured 16-crate workspace; green CI on lint+unit stages; a reproducible container image; the assert_invariant! macro available to every downstream crate.

Acceptance
  • Clean build on Linux x86_64 and ARM64 in < 90 s cold, < 20 s incremental.
  • Byte-identical Cargo.lock hash across 3 consecutive CI reruns.
  • Zero clippy::all warnings across all 16 crates.
  • SBOM (legal/THIRD_PARTY_LICENSES.md) generated and non-empty.
Fixtures
  • fixtures/build/reproducible_hash.txt — expected SHA256 of the release archive; regression case for build drift.
  • fixtures/build/container_boot.txt — expected container-image boot log prefix; malformed case: missing Docker daemon.
  • fixtures/build/toolchain_pin.txt — expected rustc --version output; regression case for silent toolchain drift.
Pitfalls
  • Dependency drift. Manifestation: non-reproducible build hashes. Root cause: an unpinned transitive dependency resolving differently across CI runs. Debugging method: diff Cargo.lock across runs. Signal: fixtures/build/reproducible_hash.txt mismatch. Recovery: freeze via cargo-deny lockfile policy (ADR-03).
  • Toolchain mismatch. Manifestation: ABI-level instability across contributor machines. Root cause: missing rust-toolchain.toml pin. Debugging method: compare rustc --version --verbose. Signal: link-time symbol mismatch. Recovery: enforce the pinned toolchain in CI and a pre-commit hook.
  • Silent lint suppression. Manifestation: an #[allow(clippy::...)] creeps into a hot-path module unreviewed. Root cause: no CI check for new allow-attributes. Debugging method: grep diff for #[allow(. Signal: warning count creeping despite deny(warnings). Recovery: require ADR sign-off for any new allow-attribute.

⬜ Phase 1 — ISA Definitions and Decode Engine §13

Objectives
  • Implement the canonical RV64GC opcode/CSR metadata tables (rvemu-isa) as the single source of truth (P13).
  • Build the decode engine (rvemu-decode) covering RV64I/M/A/F/D + Zicsr/Zifencei + compressed (RVC).
  • Guarantee deterministic instruction parsing: identical bytes always decode to an identical DecodedInstruction (§11).
Deliverable

A standalone rvemu-decode crate turning a u32/u16 fetch word into a DecodedInstruction (§11) for the full RV64GC + compressed encoding space, with zero heap allocation on the decode path.

Acceptance
  • Passes all official RISC-V decode vectors from riscv-tests (100% of the RV64GC subset, ~1,200 vectors).
  • Zero panics across 24 CPU-hours of decode_target.rs fuzzing.
  • Decode throughput > 200 MIPS on the criterion decode benchmark (§4).
  • Illegal-instruction detection: 100% on the decode_illegal.bin corpus, zero false accepts.
Fixtures
  • fixtures/decode/rv64i_base.bin — canonical RV64I vectors; expected: exact DecodedInstruction match.
  • fixtures/decode/compressed_rvc.bin — RVC vectors; expected: correct expansion to base-format equivalent.
  • fixtures/decode/malformed_opcode.bin — deliberately invalid encodings; expected: IllegalInstruction outcome, never a panic.
  • fixtures/decode/replay_decode_trace.bin — regression case pinning a previously fixed sign-extension bug.
Pitfalls
  • Bitfield sign errors. Manifestation: wrong result on negative immediates. Root cause: incorrect sign extension in immediate assembly. Debugging method: differential-compare against Spike's insns/ reference. Signal: rv64i_base fixture mismatch on B/S-type instructions. Recovery: fix the extension mask, re-run the full vector suite.
  • Decode-table drift. Manifestation: two opcode entries silently disagree after a manual edit. Root cause: hand-duplicated opcode row bypassing the P13 single-source generator. Debugging method: diff the generated table against a schema checksum. Signal: codegen checksum mismatch in CI. Recovery: regenerate from schema; forbid direct edits to generated files.
  • Compressed-instruction ambiguity. Manifestation: one RVC opcode maps to two different base instructions depending on an ignored field. Root cause: incomplete CR/CI disambiguation. Debugging method: cross-check against the Unprivileged ISA sec. 16 compressed table. Signal: compressed_rvc fixture divergence. Recovery: add the missing discriminant field.

⬜ Phase 2 — Core Interpreter Runtime §14

Objectives
  • Execute the full RV64I/M/A/F/D instruction set through rvemu-core's execution loop.
  • Implement register-file, arithmetic, branch, and memory-op semantics with retirement accounting (I1).
  • Implement synchronous trap propagation for illegal instructions and misaligned access (I12).
Deliverable

A runnable single-hart interpreter executing RV64I/M/A/F/D user-mode binaries end to end, with retirement counters and a differential-testing hook against Spike.

Acceptance
  • Passes 100% of the rv64ui-*/rv64um-* riscv-tests suites.
  • Zero divergence against Spike across a 10-million-instruction differential run (rvemu-testkit).
  • Interpreter throughput within the 25–80 MIPS budget (§4) on the criterion interpreter benchmark.
  • No undefined architectural-state transition across the full riscv-tests corpus.
Fixtures
  • fixtures/core/rv64ui_add.bin — base arithmetic; expected: bit-identical register file vs. Spike.
  • fixtures/core/rv64ui_branch.bin — branch/jump semantics; expected: correct PC sequence.
  • fixtures/core/rv64ui_loadstore.bin — memory ops; expected: correct byte/half/word/double semantics.
  • fixtures/core/x0_write.bin — I11 regression case; expected: x0 reads zero after any write.
  • fixtures/core/pc_misalign.bin — I12 regression case; expected: InstructionAddressMisaligned trap.
Pitfalls
  • x0 mutation. Manifestation: silently corrupted downstream computation. Root cause: a handler writes regs[0] directly instead of through the write chokepoint. Debugging method: x0_write.bin plus a runtime assertion on every register write. Signal: assertion fires in debug build. Recovery: route all writes through one function (I11).
  • PC misalignment tolerated. Manifestation: the guest continues from a misaligned address instead of trapping. Root cause: missing alignment check before fetch dispatch. Debugging method: pc_misalign.bin. Signal: conformance fixture failure. Recovery: enforce I12 at the fetch chokepoint.
  • Overflow-semantics mismatch. Manifestation: differential divergence from Spike on signed overflow. Root cause: two's-complement wraparound at the wrong operand width. Debugging method: differential trace isolates the exact instruction. Signal: rvemu-testkit divergence report. Recovery: fix the operand-width mask, re-run rv64um-*.

⬜ Phase 3 — Memory Subsystem and Bus §15

Objectives
  • Build the guest physical RAM model (rvemu-memory) with page-granular allocation and dirty tracking.
  • Implement MMIO routing and address-space isolation via rvemu-bus (I10).
  • Enforce region-ownership validation ahead of any host-memory touch.
Deliverable

A working guest-RAM subsystem plus MMIO routing layer: any guest physical address resolves deterministically to a RAM range or a registered device, with no unmapped gaps silently returning zero.

Acceptance
  • Address-decode correctness across 100% of registered regions in mmio_overlap.json's topology.
  • Zero overlapping regions accepted at registration time (hard rejection, not a runtime check).
  • Faults generated deterministically: 100% reproducibility across repeated ram_alignment.bin runs.
  • Dirty-bitmap growth stays within the §4-adjacent ceiling under the stress fixture.
Fixtures
  • fixtures/memory/ram_alignment.bin — width-correct access matrix; expected: correct trap on misalignment where required.
  • fixtures/memory/mmio_overlap.json — deliberately overlapping topology; expected: registration-time rejection.
  • fixtures/memory/dirty_bitmap_stress.bin — sustained write pattern; regression case for unbounded dirty-tracking growth.
  • fixtures/memory/out_of_range_access.bin — access beyond the mapped range; expected: deterministic bus fault.
Pitfalls
  • Region overlap. Manifestation: undefined device-routing behavior. Root cause: registration-time validation gap. Debugging method: dump the region table, check pairwise interval overlap. Signal: mmio_overlap.json failure. Recovery: reject overlapping registration at boot (I10).
  • Unbounded dirty tracking. Manifestation: snapshot serialization time grows unboundedly. Root cause: the dirty bitmap is never compacted between snapshot cycles. Debugging method: dirty_bitmap_stress.bin plus allocation-pressure trend. Signal: memory.dirty_page_growth exceeding budget. Recovery: compact the bitmap on every successful snapshot commit (P8).
  • Torn partial write. Manifestation: a multi-byte MMIO write straddling a boundary hits the wrong device for its tail bytes. Root cause: router splitting logic assumes width-aligned regions. Debugging method: boundary-crossing write fixture. Signal: differential mismatch. Recovery: reject boundary-crossing accesses as a bus fault (P9).

⬜ Phase 4 — ELF Loader and User-Mode Execution §16

Objectives
  • Parse ELF64 binaries and validate RISC-V machine/class fields (rvemu-loader).
  • Initialize ABI state: stack, argv/envp, entry point.
  • Execute real user-mode programs end to end through the Phase 2 interpreter.
Deliverable

Runnable user-mode ELF execution: a statically linked RV64GC binary runs to completion under the interpreter with correct argv/envp and exit-code propagation.

Acceptance
  • hello_static.elf runs to completion, exits with code 0, in under 50 ms wall time.
  • 100% of segment-permission violations in overlapping_segments.elf rejected at load time.
  • malformed_header.elf rejected with a typed loader error (P14), zero panics.
  • Stack alignment bit-exact against the RVABI convention on every test binary.
Fixtures
  • fixtures/loader/hello_static.elf — canonical static binary; expected: exit code 0, correct stdout.
  • fixtures/loader/malformed_header.elf — corrupted ELF magic/class; expected: typed rejection, no panic.
  • fixtures/loader/overlapping_segments.elf — overlapping PT_LOAD segments; expected: load-time rejection.
  • fixtures/loader/zero_size_segment.elf — zero-length PT_LOAD; expected: skip without fault.
Pitfalls
  • Incorrect stack alignment. Manifestation: ABI-incompatible crashes in libc-linked binaries. Root cause: misalignment computation after variable-length argv/envp. Debugging method: diff the constructed stack layout against a known-good readelf/objdump trace. Signal: failure specific to libc-linked fixtures. Recovery: recompute padding per RVABI, pin a byte-layout fixture.
  • Segment permission drift. Manifestation: a segment ends up executable and writable simultaneously. Root cause: PT_LOAD flag-translation bug. Debugging method: diff segment permissions against the program header. Signal: overlapping_segments.elf-adjacent fixture catch. Recovery: fix the flag-translation table, add a W^X assertion at map time.
  • Relocation misassumption. Manifestation: a dynamically-linked binary loads but jumps unrelocated. Root cause: Phase 4 scope is static binaries only. Debugging method: check e_type == ET_DYN before load. Signal: unexpected trap immediately after entry. Recovery: reject ET_DYN explicitly with a typed error.

⬜ Phase 5 — Privileged Architecture and MMU §17

Objectives
  • Implement Sv39 virtual-memory translation (rvemu-mmu) and supervisor-mode execution.
  • Add full CSR privilege-check semantics and trap delegation (medeleg/sedeleg).
  • Support the U/S/M privilege-mode transitions defined in §8's domain model.
Deliverable

Supervisor-mode execution: a guest kernel stub enables Sv39, takes a page fault, and resumes correctly under the interpreter — the prerequisite for any multi-process guest workload and for Phase 7's boot.

Acceptance
  • Passes 100% of the rv64si-*/rv64mi-* privileged riscv-tests vectors.
  • Deterministic page-fault behavior: identical cause/tval/epc across 100 repeated page_fault.bin runs.
  • Correct TLB invalidation: zero stale-translation hits across satp_switch.bin's mode-switch sequence.
  • p95 translation latency under the 250 ns §4 budget on the sv39_walk.bin benchmark.
Fixtures
  • fixtures/mmu/sv39_walk.bin — canonical three-level walk; expected: correct PA + permission bits.
  • fixtures/mmu/page_fault.bin — invalid leaf PTE; expected: deterministic page-fault trap (I7).
  • fixtures/mmu/satp_switch.bin — Bare→Sv39 transition; expected: correct TLB flush on switch.
  • fixtures/mmu/invalid_pte.bin — malformed PTE bit patterns; expected: rejection before any host-memory touch (I7).
  • fixtures/mmu/pmp_violation.bin — access outside a configured PMP region; expected: distinct PMP-fault telemetry.
Pitfalls
  • TLB staleness. Manifestation: silent wrong-answer execution after a page-table update without an sfence.vma. Root cause: a gap in the TLB-invalidation path. Debugging method: differential trace against Spike immediately after a satp/PTE update. Signal: satp_switch.bin divergence with no fault raised — the dangerous case. Recovery: audit every page-table-touching path for a required shootdown per I8.
  • Incorrect privilege checks. Manifestation: an S-mode guest reads/writes an M-mode-only CSR without trapping. Root cause: the privilege-check table missing an entry for a newly added CSR. Debugging method: cross-reference the CSR map against the privileged spec's access-mode column. Signal: rv64mi-* fixture failure. Recovery: regenerate the check table from the same single-source schema as csr_table.rs (P13).
  • PMP-before-translation ordering bug. Manifestation: an access that should be blocked by PMP proceeds to a successful walk. Root cause: pmp.rs invoked after, not before, the walk. Debugging method: pmp_violation.bin with a valid mapping but a violating PMP entry. Signal: fixture expects a PMP fault but observes success. Recovery: reorder per the spec's mandated sequence.

⬜ Phase 6 — Interrupts and Device Framework §18

Objectives
  • Implement interrupt routing and the CLINT/PLIC/UART device triad.
  • Guarantee deterministic, replay-compatible device behavior (P1/P5) ahead of Phase 7's boot work.
Deliverable

An interrupt-capable runtime: CLINT timer interrupts and UART character IO function correctly and deterministically under a single hart, with PLIC priority arbitration ready for Phase 7's boot path.

Acceptance
  • Timer interrupts fire within the p99 20 µs injection-latency budget (§4) on timer_irq.bin.
  • UART echo functional on uart_echo.bin with zero dropped characters across 10,000 iterations.
  • Correct privilege-mode delivery: 100% of nested_irq.bin cases deliver to the correct mode per delegation state (§17.2).
  • Zero lost interrupts across a 1-million-injection stress run.
Fixtures
  • fixtures/devices/timer_irq.bin — CLINT timer-compare sequence; expected: interrupt fires exactly at mtimecmp crossing.
  • fixtures/devices/uart_echo.bin — UART TX/RX loopback; expected: byte-identical echo, no drops.
  • fixtures/devices/nested_irq.bin — interrupt arriving mid-trap-handler; expected: correct nesting per delegation rules.
  • fixtures/devices/malformed_plic_claim.bin — out-of-range PLIC claim ID; expected: typed rejection, no panic.
Pitfalls
  • Lost interrupts. Manifestation: a pending interrupt never delivered. Root cause: incorrect pending-bit clear ordering racing a new assertion in the same retirement window. Debugging method: replay-trace diff isolating the exact retirement index. Signal: timer_irq.bin stress-fixture failure. Recovery: serialize pending-bit mutation through I2's commit-order discipline.
  • Timer drift. Manifestation: replay divergence around timer-interrupt-adjacent instructions. Root cause: mtime derived from host wall clock instead of the virtual clock (violating ADR-21). Debugging method: check whether mtime reads correlate with retirement count or Instant::now(). Signal: non-reproducible timer_irq.bin runs. Recovery: route all time reads through the virtual clock (P1).
  • PLIC claim/complete mismatch. Manifestation: an interrupt source appears permanently masked after one claim. Root cause: the complete-side pending-bit re-arm is missing. Debugging method: fixture-driven claim/complete trace. Signal: nested_irq.bin regression on repeated interrupts. Recovery: fix the re-arm step in the claim/complete state machine.

⬜ Phase 7 — Linux Boot Support §19

Objectives
  • Boot an unmodified BusyBox-based Linux kernel to an interactive shell.
  • Support initramfs loading, minimal SBI calls, and VirtIO-blk root-filesystem access.
Deliverable

Linux boots to an interactive BusyBox shell over the emulated UART console, with the root filesystem served from a VirtIO-blk-backed image.

Acceptance
  • BusyBox Linux boots to shell under the 15 s §4 budget on linux_boot.trace, single hart.
  • Stable shell interaction: 100 consecutive commands execute without a device-driven divergence.
  • Deterministic boot logs: byte-identical linux_boot.trace across 10 repeated boots (P1 gate).
  • Zero DTB-consistency mismatches between the constructed device tree and the region table.
Fixtures
  • fixtures/boot/linux_boot.trace — canonical boot replay trace; expected: byte-identical across reruns.
  • fixtures/boot/busybox_rootfs.img — minimal VirtIO-blk-backed root filesystem image.
  • fixtures/boot/malformed_initramfs.img — corrupted initramfs; expected: typed boot-failure error, not a hang.
  • fixtures/boot/dtb_mismatch.bin — inconsistent DTB vs. region table; expected: boot-time rejection.
Pitfalls
  • DTB mismatch. Manifestation: kernel panic during early boot, before console is live. Root cause: the constructed DTB disagrees with the actual region table — e.g. a stale UART base address. Debugging method: the early-boot ring buffer captures the pre-panic sequence without console output. Signal: dtb_mismatch.bin, or an unexpected panic offset in linux_boot.trace. Recovery: generate the DTB directly from the region table, never from a hand-maintained template.
  • SBI incompatibility. Manifestation: kernel timer init hangs or panics. Root cause: the minimal SBI shim is missing a call the target kernel build expects. Debugging method: trace every SBI ecall and argument state; compare against the kernel's probe sequence. Signal: boot hangs immediately after the SBI probe, before CLINT ticks appear. Recovery: extend the SBI shim's supported-extension bitmap.
  • VirtIO virtqueue misalignment. Manifestation: root-filesystem reads intermittently corrupted. Root cause: descriptor-ring alignment not matching the VirtIO sec. 2.6 layout requirement. Debugging method: dump ring state at the point of a corrupted read. Signal: small reads succeed, multi-descriptor reads fail. Recovery: fix ring alignment/wrap-around arithmetic per spec.

⬜ Phase 8 — Deterministic Replay and Snapshotting §20

Objectives
  • Implement the replay WAL and snapshot subsystem (rvemu-trace) to full production strength.
  • Guarantee bit-identical replay (P1/P5) and validated snapshot restore (I6).
Deliverable

A fully replayable execution environment: any recorded run replays to bit-identical architectural state, and any quiesced snapshot restores and resumes within the §4 RTO budgets.

Acceptance
  • Bit-identical replay: zero divergence across 1,000 replay runs of replay_boot.trace (§19's boot sequence).
  • Snapshot restore functional: snapshot_restore.bin restores and resumes within the 30 s §4 RTO budget.
  • Divergence detection: 100% of injected single-instruction perturbations detected within 1 instruction.
  • WAL write-amplification measured and documented within the 512 MB budget under a full boot-length run.
Fixtures
  • fixtures/replay/replay_boot.trace — full boot-sequence WAL; expected: bit-identical replay across 1,000 runs.
  • fixtures/replay/snapshot_restore.bin — a mid-boot quiesced snapshot; expected: successful restore.
  • fixtures/replay/partial_wal_corruption.bin — a truncated WAL segment; expected: typed corruption error, rollback to last valid sequence (I3).
  • fixtures/replay/interrupted_snapshot_write.bin — a snapshot write interrupted mid-serialization; expected: rejected on next restore attempt via checksum mismatch, never silently accepted.
Pitfalls
  • Non-deterministic timers. Manifestation: replay drift around CLINT-driven interrupts. Root cause: a residual host-wall-clock read outside §18.6's virtual-clock discipline. Debugging method: grep for Instant/SystemTime usage outside timer_wheel.rs. Signal: divergence localized to timer-adjacent retirement indices. Recovery: eliminate the wall-clock read, re-validate ADR-21.
  • Missing device events. Manifestation: silent divergence with no error raised — the most dangerous failure mode here. Root cause: a device mutates state without emitting a ReplayEvent. Debugging method: audit every MmioDevice::write call site against WAL-emission coverage. Signal: replay produces a plausible but subtly wrong final state. Recovery: enforce WAL emission at the rvemu-bus dispatch chokepoint (§15.2), not per-device self-reporting.
  • Interrupted snapshot write. Manifestation: a snapshot file that looks complete but is truncated. Root cause: process crash mid-serialization before the content-hash footer is written. Debugging method: check SnapshotHeader.content_hash (§11) validity before trusting any body byte. Signal: interrupted_snapshot_write.bin; checksum mismatch on restore. Recovery: atomic-rename into place only after the hash is verified.

⬜ Phase 9 — Debugging, GDB, and Observability §21

Objectives
  • Implement GDB remote serial protocol support (rvemu-gdb) for interactive kernel/userspace debugging.
  • Complete the operational observability stack: metrics export, structured span hierarchy, crash-dump generation.
Deliverable

A production debugging environment: a RISC-V-aware GDB attaches over TCP, sets breakpoints/watchpoints, single-steps, and inspects registers/memory, while an operator observes the same session through Prometheus metrics and correlated structured traces.

Acceptance
  • GDB attach functional: 100% of gdb_breakpoint.trace's scripted session completes without protocol error.
  • Watchpoint reliability: zero missed hits across 10,000 triggering accesses in watchpoint_access.trace.
  • Trace correlation complete: 100% of breakpoint hits resolve to a valid ReplayEvent.sequence_id.
  • Metrics exporter exposes every counter named in §12.10–§20.10 (cross-section completeness check).
Fixtures
  • fixtures/gdb/gdb_breakpoint.trace — scripted attach/breakpoint/continue session; expected: exact GDB packet sequence match.
  • fixtures/gdb/watchpoint_access.trace — memory-access watchpoint trigger sequence; expected: zero missed hits.
  • fixtures/gdb/malformed_rsp_packet.bin — corrupted RSP packet; expected: typed protocol-error response, connection stays alive.
  • fixtures/gdb/concurrent_attach.trace — a second debugger attaching mid-session; expected: deterministic rejection, not a race.
Pitfalls
  • Breakpoint re-entry. Manifestation: an infinite trap loop from a breakpoint set on the trap-vector entry instruction. Root cause: the breakpoint-hit trap and the original trap share the dispatch chokepoint without a re-entry guard. Debugging method: trace the retirement sequence around the loop for a repeating PC with no forward progress. Signal: gdb_breakpoint.trace hangs instead of completing. Recovery: add a one-shot re-entry guard keyed on PC + breakpoint ID.
  • Trace amplification. Manifestation: disk exhaustion once full observability (§21.2) turns every placeholder span real. Root cause: sampling rate (P4) not re-tuned after this phase. Debugging method: check trace.commit_wal_record volume against §4's FD/storage budgets. Signal: disk-usage alert on the trace filesystem. Recovery: apply P4's sampling policy uniformly, not just to the highest-volume span.
  • Concurrent debugger-attach race. Manifestation: two GDB sessions both believe they hold the single debug lock. Root cause: the accept loop is missing single-session enforcement. Debugging method: concurrent_attach.trace. Signal: the second session's packets interleave with the first's. Recovery: enforce single-session ownership at the socket-accept chokepoint.
