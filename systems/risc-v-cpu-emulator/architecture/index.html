rvemu-cli — sole operator boundary; parses config/argv (least-trusted input alongside guest binaries), wires topology, drives replay/snapshot/bench subcommands. No ISA semantics live here; it stays stateless apart from resolved configuration, so it can be re-invoked idempotently in CI.

rvemu-runtime — the concurrency boundary. Owns hart scheduling, CLINT-driven timer dispatch, trap routing, cooperative cancellation, and replay orchestration; defines the global lock-ordering hierarchy (I5) that every other subsystem must respect when it needs cross-hart or cross-device state.

rvemu-core (with rvemu-decode/rvemu-isa) — the execution kernel. Owns register file, CSR file, privilege-mode state, trap generation, decode dispatch, and monotonic retirement accounting (I1). This is the only subsystem allowed to mutate architectural state directly.

rvemu-mmu — owns every guest-visible address-translation invariant: Sv39 walk, TLB, PMP checks, translation-fault generation. A translation crossing this boundary without a validated PTE is a correctness bug, not a performance one (I7).

rvemu-devices — virtual peripherals (UART/CLINT/PLIC/VirtIO). Devices talk to each other and to RAM only through rvemu-bus; direct device-to-device or device-to-RAM coupling is the isolation invariant (I10) this subsystem exists to enforce.

rvemu-trace — the persistence boundary. Every subsystem's structured logs, spans, metrics, and replay events flow through here before they leave the process; nothing bypasses it for telemetry (P7).

rvemu-bus — the protocol boundary between the CPU-side subsystems and memory/devices: address decode, MMIO dispatch, DMA arbitration, device registration. Prevents any subsystem from addressing physical memory except through a validated region lookup.

rvemu-memory — the trust boundary around guest RAM: allocation, dirty-page tracking for snapshotting, and access instrumentation. Guest-controlled addresses are validated here before any host-memory touch.

rvemu-loader — the external-IO boundary for guest images: ELF64 parsing, segment mapping, ABI/stack construction. It is the last place untrusted binary input is validated before it becomes executable guest state.

rvemu-gdb and the rvemu-testkit/rvemu-fuzz/rvemu-bench/rvemu-conformance cluster are external interfaces: a GDB remote-serial-protocol socket into the trap router, and a family of harnesses driving the runtime from outside without becoming part of its concurrency boundary.

8. Domain Model — Hart, Trap & Replay Protocol

Hart State Model (owned exclusively by rvemu-core, per P3):

HartState
  regs               : [u64; 32]        (x0 hardwired zero, I11)
  pc                 : u64
  csr                : CsrFile
  privilege          : PrivilegeMode    (U | S | M)
  pending_interrupts : InterruptBitmap
  trap_state         : TrapState
  mmu_ctx            : MmuContext
  retired            : u64               (monotonic, I1)

Privilege modes:

Mode Encoding Description
U 0b00 User — unprivileged application execution.
S 0b01 Supervisor — kernel-mode execution under Sv39 translation.
M 0b11 Machine — highest privilege, owns SBI shim and boot ROM.

Trap flow (synchronous exception or asynchronous interrupt, both funnel through the same path, enforcing I4):

Instruction Execute
    |
    +--> exception or pending interrupt taken?
            |
            +--> save {cause, tval, epc, previous_mode}   (I4: atomic)
            +--> apply delegation (medeleg/sedeleg)
            +--> update CSRs (deterministic sub-order, I2)
            +--> switch privilege mode
            +--> jump to trap vector (mtvec/stvec)

Sv39 translation walk (three-level, enforced by rvemu-mmu, I7/I8):

VA[38:0] --VPN[2]--> PTE (level 2) --VPN[1]--> PTE (level 1) --VPN[0]--> PTE (level 0) --> PA

Replay event record (append-only, versioned per P6, serialized by rvemu-trace):

ReplayEvent
  schema_version    : u16
  sequence_id       : u64            (WAL ordering key, I3)
  hart_id           : u8
  instruction_pc    : u64
  opcode            : u32
  register_deltas   : Vec<RegDelta>
  memory_deltas     : Vec<MemDelta>
  csr_deltas        : Vec<CsrDelta>
  interrupt_state   : InterruptBitmap
  timestamp_ns      : u64            (monotonic per hart, I9)

Device MMIO request (routed exclusively through rvemu-bus, I10):

MmioRequest
  address     : u64
  width       : AccessWidth  (Byte | Half | Word | Double)
  operation   : MmioOp       (Read | Write)
  value       : u64

ELF loading sequence (rvemu-loader, validated before any guest state exists):

parse ELF64 header
  -> validate machine=EM_RISCV, class=ELFCLASS64
  -> map PT_LOAD segments (permission-checked, I7-adjacent MMU setup)
  -> initialize user stack (argv/envp per RVABI)
  -> set entry PC
  -> hand off to rvemu-core execution loop

Failure path example — malformed page table (illustrates I7 end to end):

TLB miss
  -> walk page table
  -> invalid leaf PTE encountered
  -> raise page fault (synchronous exception)
  -> enter trap handler (per trap-flow diagram above)
  -> emit fault telemetry (mmu.invalid_pte_blocked, I7)
