Pretrained LM + tokenizer: external artifact, consumed read-only; establishes the trust boundary — this project never mutates or trains the tokenizer (§1 boundary).

SFT Trainer: converts a base LM into an instruction-following policy via causal-LM loss on demonstration data; its checkpoint is the shared warm-start for every downstream model.

Reference policy π_ref: a frozen copy of the SFT checkpoint; persists unchanged for the lifetime of a PPO run, defining the KL-penalty anchor (I3).

Policy π_θ: the trainable actor, with an attached value head for PPO's critic; the only model updated by gradient steps during Phase 4–5, 7–8, 10.

Reward model r_φ: base LM plus scalar head, trained on preference pairs via the Bradley-Terry objective (§8); frozen during PPO, providing the scalar reward signal.

Generation Engine: batched autoregressive sampling with KV-cache reuse; produces rollouts and computes both policy and reference log-probabilities in the same forward pass batch (ADR-11).

Rollout Buffer: the queue/record store connecting generation to the PPO update; schema fixed in §8 (rollout record layout); concurrency boundary between generation (producer) and PPO (consumer) workers (I5).

PPO + GAE + KL Update: the online RL optimizer; consumes rollouts, computes GAE advantages, applies the clipped surrogate objective plus token-level KL penalty (§8 domain model).

Reward-Hacking Diagnostics: continuous monitor comparing proxy reward trend against KL budget and judge win-rate; the trust boundary between "reward went up" and "policy got better."

DPO/IPO/ORPO/KTO Loss Family: an alternate, rollout-free update path consuming the same preference-pair schema as the reward model, swappable via a single loss-function interface (ADR-14).

Eval Harness: the single source of truth for cross-run comparison; every reported number (reward, KL, win-rate, hacking score) is produced by this component, never ad hoc.

RLAIF/Constitutional Judge Loop: replaces or augments human preference labels with AI-critique-derived labels (Bai et al. 2022), feeding the same preference-pair schema.

Checkpoint Store: persistence boundary for every trainable model; layout fixed in §8; consumed by eval, by resume-from-checkpoint, and by the scale-out hooks.

ZeRO/DeepSpeed Scale-Out Hooks: the sole integration point with distributed-training infrastructure; everything upstream is written to be shard-agnostic (P9).

8. Domain Model

Preference-pair schema (canonical input to RM, PPO's reward source via I9, and the DPO family):

PreferencePair {
  pair_id: UUID
  prompt: string
  chosen: string
  rejected: string
  chosen_score: float | null      # optional scalar label (KTO unpaired path derives from this)
  rejected_score: float | null
  source: enum { HUMAN, RLAIF, SYNTHETIC }
  dataset_split: enum { TRAIN, VAL, TEST }
  schema_version: uint16
}

Reward-model objective (Bradley-Terry pairwise loss, Christiano et al. 2017 framing):

L_RM(φ) = − E₍x,yw,yl₎~D [ log σ( r_φ(x, yw) − r_φ(x, yl) ) ]

where x is the prompt, yw the chosen (winning) response, yl the rejected response, r_φ the scalar reward head, σ the logistic sigmoid.

PPO objective with KL penalty and GAE (Schulman et al. 2017; Schulman et al. 2015):

Per-token reward with KL penalty (Ouyang et al. 2022 formulation):

R_t = r_φ(x, y) · 𝟙[t = T] − β · KL(π_θ(·|s_t) ‖ π_ref(·|s_t))

GAE recursion:

δ_t = R_t + γ·V(s_{t+1}) − V(s_t)

A_t^GAE = Σ_{l=0}^{∞} (γλ)^l · δ_{t+l}

Clipped surrogate objective:

L_CLIP(θ) = E_t[ min( ρ_t(θ)·A_t, clip(ρ_t(θ), 1−ε, 1+ε)·A_t ) ], ρ_t(θ) = π_θ(a_t|s_t) / π_θ_old(a_t|s_t)

Total PPO loss: L(θ) = −L_CLIP(θ) + c1·L_VF(θ) − c2·H[π_θ] , where L_VF is the value-function MSE loss and H is the entropy bonus.

DPO/IPO/ORPO/KTO loss family comparison:

Loss Reference model required Data shape Loss form (summary) Failure mode if misapplied
DPO (Rafailov 2023) yes, frozen π_ref paired (chosen, rejected) −log σ(β·[log π_θ(yw|x)/π_ref(yw|x) − log π_θ(yl|x)/π_ref(yl|x)]) implicit reward unbounded, can overfit to length (Singhal 2023)
IPO (Azar 2023) yes, frozen π_ref paired squared-error form bounding the implicit reward, avoids DPO's saturation mis-set τ hyperparameter flattens gradient signal
ORPO (Hong 2024) no paired odds-ratio penalty added directly to SFT cross-entropy loss no reference model means no KL anchor — cannot bound drift (I3 does not apply)
KTO (Ethayarajh 2024) yes, frozen π_ref unpaired (single response + binary label) prospect-theory-weighted log-odds loss requires desirable/undesirable class balance or biases toward majority class

Rollout record layout (buffer entry produced by generation, consumed by PPO, §15/§16):

RolloutRecord {
  batch_id: UUID
  prompt_ids: int32[]
  response_ids: int32[]
  logprobs_policy_old: float32[]      # π_θ_old(a_t|s_t) at generation time
  logprobs_ref: float32[]             # π_ref(a_t|s_t), same tokenization (I8)
  value_estimates: float32[]          # V(s_t) from policy's value head
  reward_scalar: float32              # r_φ(x, y), terminal reward
  kl_per_token: float32[]
  generation_step: uint64
  generation_timestamp: timestamp
}

Checkpoint layout (self-describing per P10/I10):

checkpoint_dir/
  config.yaml            # full run config, hyperparameters
  model.safetensors       # policy (+ value head) weights
  optimizer_state.pt      # Adam moments (or ZeRO-sharded shards, Phase 11)
  rng_state.pt            # torch/numpy/python RNG state (P13)
  step_counter.json       # {"global_step": N, "epoch": E}
  manifest.json           # schema_version, checksum of model.safetensors

Worked numeric example — GAE for a 3-token rollout, γ=0.99, λ=0.95, β=0.1: rewards R = [0.0, 0.0, 2.0] (terminal reward only, per the R_t formula above), values V = [0.4, 0.5, 0.3, 0.0] (V(s_3)=0 terminal). Deltas: δ_0 = 0 + 0.99·0.5 − 0.4 = 0.095; δ_1 = 0 + 0.99·0.3 − 0.5 = −0.203; δ_2 = 2.0 + 0.99·0.0 − 0.3 = 1.700. Advantages (backward recursion): A_2 = δ_2 = 1.700; A_1 = δ_1 + (γλ)·A_2 = −0.203 + 0.9405·1.700 = 1.395; A_0 = δ_0 + (γλ)·A_1 = 0.095 + 0.9405·1.395 = 1.407. This hand-computed trace is the exact fixture used by conformance/fixtures/gae_3token.json (§16, Phase 4 conformance).

Training-loop state-transition table:

State Trigger Next State Notes
IDLE run start LOADING_CHECKPOINTS loads SFT/reward/reference per §8 checkpoint layout
LOADING_CHECKPOINTS all 3–4 models loaded, I1/I2 verified GENERATING verifies invariants before any step
GENERATING rollout batch requested ROLLOUT_COMPLETE produces RolloutRecords (I5)
ROLLOUT_COMPLETE buffer write validated (I5) PPO_UPDATING consumer takes exclusive batch (I4)
PPO_UPDATING 4 epochs complete or early-stop (I3 breach) DIAGNOSTICS reward-hacking check (§17)
DIAGNOSTICS pass CHECKPOINTING periodic per config cadence
DIAGNOSTICS fail (KL/hacking alarm) HALTED requires manual intervention (FM-4)
CHECKPOINTING write complete, manifest validated (I10) GENERATING loop continues
HALTED operator intervention LOADING_CHECKPOINTS resume path, RTO ≤10 min (§4)

Malformed-input examples: (a) PreferencePair with chosen == rejected text — rejected by I7 at dataset load, logged with pair_id. (b) RolloutRecord with mismatched prompt_ids length vs logprobs_policy_old length — rejected by buffer schema validation (I5), generation batch re-requested. (c) Checkpoint directory missing manifest.json — refused at load (I10), operator must re-run the checkpoint-repair tool (§26).

Failure-path example: generation produces a rollout batch; PPO update begins; mid-epoch the KL tracker crosses the 20-nat alarm threshold (I3); the loop transitions PPO_UPDATING → HALTED without completing remaining epochs; the partially-applied optimizer step is rolled back via the pre-step optimizer-state snapshot (retained per epoch); operator is alerted via kl_cumulative telemetry breach (FM-4 details the full recovery runbook).
