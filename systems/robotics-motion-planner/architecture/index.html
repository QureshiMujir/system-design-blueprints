3.2 One paragraph per box

  • mp-planner — top-level orchestrator. Owns the PlanRequest, selects the global planner by PlannerCfg, runs collision-checked search, then smoothing then time parameterization, and packages PlanResult. Stateless across requests except for caches; deterministic given the request's seed. Boundary between user intent and algorithm choice.
  • mp-space (C-space) — defines the configuration space (SE(2), SE(3), R^n joint). Provides sample (seeded), interpolate, distance (metric), and validate (bounds). Every planner is generic over this trait; it is the abstraction that lets one planner serve a car, a drone, and an arm. Hot path: distance and interpolate called millions of times.
  • mp-collision (checker) — answers "is configuration q (or motion q1->q2) in collision?". Broad phase culls pairs via BVH/uniform grid; narrow phase resolves convex pairs via GJK (distance/intersection) and EPA (penetration). Motion validation discretizes an edge at resolution ε and checks each sub-state. The dominant cost in planning; designed for batching and early-out.
  • mp-env (world model) — owns the environment representation: OccupancyGrid (binary/probabilistic cells), Costmap (layered inflation + cost), and Esdf (signed distance to nearest obstacle, with gradient). Provides cost and clearance queries to planners and smoothers. Loaded from map files; treated as untrusted input.
  • Global planner — mp-graph — discrete search on a grid/graph: Dijkstra, A* (admissible heuristic), weighted/greedy A* (bounded suboptimality), and D* Lite (incremental repair on edge-cost changes). Resolution-complete; optimal on the discretization.
  • Global planner — mp-sampling — probabilistic planners: PRM/lazy-PRM (multi-query blueprint), RRT/RRT-Connect (single-query feasible), RRT*/Informed RRT* (asymptotically optimal). Avoids explicit C-obstacle construction; scales to high DOF.
  • Global planner — mp-steer — kinodynamic/non-holonomic: Dubins and Reeds-Shepp closed-form steering, discrete state lattices, and Hybrid A* (continuous-state A* with analytic expansions). Produces paths a curvature-constrained vehicle can actually follow.
  • mp-opt (smooth) — post-processes a feasible path: shortcutting (replace sub-paths with valid straight/steering connections) and CHOMP-style covariant gradient descent on an ESDF obstacle cost plus a smoothness term. Reduces path length/jerk while preserving collision-freedom.
  • mp-time (parameterize) — converts a geometric path to a time-stamped Trajectory honoring velocity/acceleration (and optionally jerk) limits: trapezoidal and S-curve profiles, and TOPP-lite path-velocity optimization. Output is what a controller consumes.
  • mp-local (DWA loop) — the only real-time component. Each tick, samples a dynamic window of feasible (v, ω) (or joint velocities), forward-simulates, scores against goal/clearance/velocity, and emits the best command. Watches for trajectory invalidation and raises a replan trigger. Bounded ≤ 20 ms.
  • replan trigger — bridges real-time and offline: when the local planner detects the global trajectory is blocked or stale, it requests a new global plan (full or D* Lite incremental) without stalling the control loop.

3.3 Boundaries

  • Concurrency boundary: offline global planning (ms–s, may run on a worker thread/process) vs the real-time local loop (≤ 20 ms, dedicated thread, pre-allocated). Communication via a lock-free single-slot channel carrying the latest trajectory.
  • Trust boundary: map files and robot models are untrusted (§ Threat Model); all parsing is bounds-checked and resource-capped.
  • Determinism boundary: every stochastic step draws from a single seeded RNG threaded through PlanRequest; same seed + same inputs -> byte-identical path.

8. Domain Model

8.1 Configuration space (C-space)

Space DOF State Metric Notes
SE(2) 3 (x, y, θ) weighted: √(dx²+dy² + w_θ·angdiff(θ)²) mobile robots; θ wraps in [-π, π)
SE(3) 6 (x, y, z, quaternion) √(pos² + w_r·quat_geodesic²) drones / free-flying bodies
R^n (joint) n (6–7) (q₁..qₙ) with limits weighted Euclidean (per-joint weights) manipulators; respects joint bounds
R² (point) 2 (x, y) Euclidean holonomic mobile / 2-D demos

angdiff(a,b) = shortest signed angular difference, in (-π, π]. Quaternion geodesic = 2·acos(|q1·q2|).

8.2 Metrics

  • Euclidean (R^n), weighted SE(2), SE(3) (position + rotation geodesic), joint-weighted.
  • All metrics: non-negative, symmetric, identity-of-indiscernibles, triangle inequality (#7.9).
  • Pseudo-metrics (e.g. Dubins length as cost-to-go) are allowed as costs but flagged non-metric for optimizing planners.

8.3 Samplers

Sampler Use Note
Uniform default; uniform over bounded C-space needs valid bounds
Gaussian bias near obstacles (one sample free, one near it) improves narrow-passage hit rate
Bridge both endpoints in collision, midpoint free -> sample midpoint targets narrow passages
Halton / low-discrepancy deterministic quasi-random; better dispersion great for PRM coverage
Informed (ellipsoid) RRT*: sample inside the prolate hyperspheroid defined by c_best shrinks as solution improves

All samplers draw from the single seeded RNG (#7.5).

8.4 Steering functions (worked geometry)

SteeringFn::steer(from, to) -> Option<Path> produces a feasible primitive.

  • Straight: linear interpolation in the metric; holonomic.
  • Dubins: 6 word types {LSL, RSR, LSR, RSL, RLR, LRL}, each a sequence of {Left arc (radius R=1/κ_max), Straight, Right arc}. Shortest forward-only path between two SE(2) poses. Closed-form: transform to into from's frame, compute each word's length, pick the minimum feasible.
  • Reeds-Shepp: 48 word patterns allowing reversals (segments may be backward). Superset of Dubins; used when the vehicle can reverse. Closed-form per the 1990 classification.

Worked Dubins example

Start pose (0, 0, 0) (heading +x), goal (4, 0, π) (heading -x), turning radius R = 1.

  • Candidate LSL: left turn, straight, left turn. Compute the two tangent circles (left of start, left of goal), the connecting tangent, arc angles.
  • Candidate RSR symmetric.
  • For this symmetric "U-turn", the minimal word is typically RSL/LSR or an LRL/RLR depending on separation. With separation 4 and R=1, the straight-segment words dominate; the engine evaluates all 6 and returns the shortest with total length L = arc₁·R + straight + arc₂·R. Expected ~ (π/2)·1 + 2 + (π/2)·1 ≈ 5.14 m (illustrative). Conformance fixture pins exact lengths to 1e-6.

8.5 Environment representations

Representation Cells/structure Query Use
OccupancyGrid row-major bytes; free/occupied/unknown is_occupied(cell) discrete planners, collision broad phase
Costmap layered: static + inflation + (dynamic) cost(cell) ∈ [0,254], 255 = lethal weighted A*, DWA scoring
Esdf per-cell signed distance to nearest obstacle + gradient distance(p), gradient(p) CHOMP smoothing, clearance cost

ESDF built from the occupancy grid via a 2-pass exact Euclidean distance transform (Felzenszwalb-Huttenlocher) on free and obstacle sets; sign = inside/outside.

8.6 Collision model

  • Shapes: sphere, AABB, OBB, capsule, convex polytope, triangle mesh (as BVH of triangles).
  • Broad phase: BVH (AABB tree) over robot links + obstacles; or uniform spatial hash for grids. Produces candidate pairs.
  • Narrow phase: GJK (boolean intersection + distance for convex pairs), EPA (penetration depth/normal when overlapping), SAT (boxes), sphere/capsule analytic tests.
  • Motion (edge) validation: discretize edge at ε, check each sub-state; optionally adaptive subdivision (check midpoint, recurse) for early-out.

8.7 Graph / tree representations

  • Graph (PRM, grid): nodes = states/cells; edges with cost; adjacency via Vec/CSR; near-neighbors via kd-tree.
  • Tree (RRT family): each node has a parent index + cumulative cost; near-neighbors via kd-tree (rebuilt/incremental).
  • Search frontier: binary heap keyed by f = g + h (A*) or g (Dijkstra), keys via ordered-float.

ASCII: RRT tree growth (5 iterations, 2-D)

 start S                        q_rand x
   *                               .
   |\                              ^ steer (step η)
   | \                             |
   *  *                            * q_new  (added if motion S-region valid)
  /|                               
 * *      after k iters:    S---*---*---*===> toward goal G
                                  \         (nearest node extended toward q_rand)
                                   *--*

Tree extension: sample q_rand; find nearest tree node q_near; q_new = steer(q_near, q_rand, η); if motion(q_near, q_new) collision-free, add q_new with parent q_near. RRT-Connect grows two trees and tries to connect greedily.

8.8 Trajectory representation

  • Geometric path: ordered Vec<State> (waypoints) + optional segment type (straight / Dubins word / RS word).
  • Smoothed path: same, fewer/optimized waypoints, possibly spline-fitted.
  • Trajectory: Vec<TrajPoint { t: f64, state: State, vel: Vec, acc: Vec }> — monotone time stamps; honors v/a limits.

8.9 State-transition contract (tree extension)

Declarative contract for one extend step shared by RRT/RRT-Connect/RRT* (Phase 6, Phase 7); no control flow, just the input/output/state-change per step:

Step Operation Result
1. Nearest q_near = tree.nearest(q_rand) kd-tree query (§8.7)
2. Steer q_new = steer(q_near, q_rand, η) bounded step / feasible primitive (§11.5 SteeringFn)
3. Validate checker.motion_valid(q_near, q_new) at resolution ε boolean edge-validity verdict (#7.1, #7.8)
4a. Outcome — valid insert q_new, parent = q_near, cost = cost(q_near) + dist(q_near, q_new) tree grows; extension result = Advanced(q_new)
4b. Outcome — invalid discard q_new; tree unchanged extension result = Trapped

8.10 Malformed / degenerate cases

Case Handling
Start in collision validate at boundary -> StartInCollision error (no search)
Goal in collision GoalInCollision error
Start == goal trivial 1-state path returned
No path exists (sealed region) planners hit sample/expansion cap -> NoPath
Narrow passage (low-probability connection) Gaussian/bridge sampling + higher cap; may still NoPath (probabilistic)
Unbounded C-space (missing bounds) InvalidSpace error (samplers need bounds)
Degenerate geometry (zero-area triangle) narrow phase guards with EPS_GEOM; skip or treat as no-collision
Empty environment every motion valid; straight-line/A* trivial
Disconnected costmap D* Lite reports unreachable; NoPath

Design principles (§6)

  • P1 — Collision-checking is the bottleneck — minimize, batch, lazy-evaluate. 90%+ of planning time is collision queries. Implication: cache broad-phase culls, validate edges lazily (only when an edge enters the candidate solution), early-out narrow phase. Violation: per-edge eager full-robot checks make even simple plans seconds-slow; profiling shows >95% in narrow phase.
  • P2 — State completeness guarantees are stated, never assumed. Each planner declares its guarantee: resolution-complete (A*/Hybrid A*), probabilistically complete (RRT/PRM), asymptotically optimal (RRT*/Informed RRT*). Tradeoff: stronger guarantees cost time. Violation: callers expecting optimality from RRT ship suboptimal paths and blame the planner.
  • P3 — Anytime + incremental over restart. Long-running planners return the best-so-far at any deadline; replanning repairs (D* Lite) rather than recomputes. Tradeoff: bookkeeping overhead. Violation: replanning-from-scratch in a dynamic map blows the local loop budget.
  • P4 — Determinism given the RNG seed. Same inputs + seed -> identical path bytes. One seeded rand_chacha RNG threaded through the request; no thread-local entropy, no HashMap iteration order in hot paths (use BTreeMap/sorted). Violation: irreproducible bugs; differential tests flap; CI cannot gate.
  • P5 — Separation of planner / steering / collision / environment / metric. Each is a trait; planners are generic over all four. Tradeoff: more generics, more monomorphization. Violation: a car-specific RRT cannot serve an arm; collision logic leaks into search and becomes untestable.
  • P6 — Path validity is non-negotiable. A returned path is collision-free at resolution ε on every edge, or the result is NoPath/error — never a "probably fine" path. Implication: final validation pass before returning. Violation: robot collides; trust destroyed; safety incident.
  • P7 — Metrics must be true distance metrics where planners assume it. Symmetry/triangle-inequality matter for RRT* near-radius and PRM connection. SE(2) uses a weighted position+angle metric; document weights. Violation: rewiring picks wrong parents; cost no longer monotone.
  • P8 — Admissible heuristics for optimal search. A* heuristic never overestimates (Euclidean/octile for grids; never inflate unless weighted-A* with declared bound). Violation: A* returns suboptimal paths while claiming optimality; invariant #7.6 trips.
  • P9 — Bounded real-time local loop. mp-local pre-allocates, never allocates in steady state, and has a hard per-tick deadline; if it would overrun it returns the last safe command. Tradeoff: fixed sample budget. Violation: a tick overruns, the controller starves, the robot lurches.
  • P10 — Resource caps everywhere. Sample counts, tree size, ESDF memory, search expansions all have configurable hard caps; exceeding a cap is a graceful ResourceExhausted, not an OOM. Violation: an adversarial map balloons the tree and OOM-kills the process (§ Threat Model).
  • P11 — Configuration validity is checked at the boundary. Start/goal validated against bounds + collision before search starts; invalid -> typed error, not silent failure. Violation: planner loops forever from an in-collision start.
  • P12 — No hidden global state. Planners, RNG, caches are owned by the request/engine instance; multiple plans can run concurrently in separate instances. Violation: two threads share an RNG -> nondeterminism + data race (compile error in Rust, but discipline still required for caches).
  • P13 — Float discipline. Use f64 in planning math; define tolerances as named constants (EPS_GEOM, EPS_ANGLE); never == on floats; ordered-float for keys. Violation: GJK never terminates; degenerate triangles crash EPA.
  • P14 — Observability is first-class. Every planner emits structured stats (samples, checks, expansions, time, final cost, anytime curve). Implication: stats struct is part of the API. Violation: production "planner is slow" reports are undebuggable.
