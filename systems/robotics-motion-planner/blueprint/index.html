287 — Robotics Motion Planner

Project Number: 287

Project Name: Robotics Motion Planner

Owner: Mujir Qureshi

Document: FINAL_BLUEPRINT.md

Status: specification — locked

Goal: Implement, from scratch in Rust, a deterministic motion/path-planning library and engine — configuration-space modeling (SE(2)/SE(3)/joint space), collision checking (BVH + GJK/EPA), environment/costmap/ESDF representation, graph search (A*, Dijkstra, D* Lite), sampling-based planners (PRM, RRT, RRT-Connect, RRT*, Informed RRT*), kinodynamic/nonholonomic planning (Dubins/Reeds-Shepp steering, state lattices, Hybrid A*), trajectory smoothing/optimization (shortcutting, CHOMP-style), time parameterization (trapezoidal/S-curve, TOPP-lite), and a reactive local planner (Dynamic Window Approach) with replanning. Plans for mobile robots (workspace, nonholonomic) and manipulators (joint space). Embeddable library + mpctl offline CLI + optional ≤20 ms real-time local loop. It is a planner, not a SLAM stack (#288), not a controller (#289); perception is out of scope.

1. Goal

Goal: A from-scratch Rust library that, given a robot model, an environment, a start and goal in configuration space, and a planner choice, returns a collision-free, constraint-feasible, time-parameterized trajectory — deterministically given an RNG seed — plus a bounded-latency reactive local loop for dynamic re-planning, exposed through the mpctl CLI.

1.1 Engineering definition (what is built)

Pipeline: PlanRequest (robot + env + start + goal + planner cfg) -> global path -> smoothed path -> time-parameterized Trajectory -> (optional) reactive local tracking + replan.

1.4 Deployment model

  • Embeddable Rust library: mp-space/mp-geom/mp-collision/mp-env/mp-graph/mp-sampling/mp-steer/mp-opt/mp-time/mp-local/mp-planner link into AV/drone/mobile/manipulator stacks. Core crates are no_std + alloc-capable where feasible (geometry, steering, graph); mp-collision/mp-env may require alloc. mp-local is the only crate on the real-time path.
  • mpctl offline planner CLI (std): subcommands plan, smooth, time, local, bench, viz, validate.
  • Optional real-time local-planner loop: mp-local DWA runs at ≥ 20–50 Hz with a ≤ 20 ms per-tick budget; replanning is triggered when the global trajectory is invalidated.

2. Why Build This

2.1 Unique knowledge taught

Concept What you learn
Configuration space (C-space) reduce robot+obstacle geometry to a point in an abstract space; obstacles map to C-obstacles
Sampling-based planning escape the curse of dimensionality without explicit C-obstacle construction
Asymptotic optimality why RRT is not optimal and RRT*/Informed RRT* converge to the optimum as samples -> infinity
Kinodynamic constraints plan respecting curvature/velocity/accel limits; non-holonomic steering (Dubins/Reeds-Shepp)
Anytime / incremental search D* Lite repairs a plan in changed regions instead of replanning from scratch
Collision checking as the bottleneck 90%+ of planning time is collision queries; design around it
Signed distance fields ESDF turns clearance into a differentiable cost for gradient-based smoothing (CHOMP)
Time parameterization converting a geometric path into a dynamically feasible, time-stamped trajectory

2.2 Historical / architectural significance

  • 1957 Dubins / 1990 Reeds-Shepp: shortest paths for curvature-constrained vehicles (forward-only / with reversal).
  • 1968 A*: admissible-heuristic optimal graph search — foundation of grid planners.
  • 1996 PRM (Kavraki): probabilistic blueprint — first practical high-DOF multi-query planner.
  • 1998 RRT (LaValle): rapidly-exploring random tree — single-query, incremental, kinodynamic-friendly.
  • 2000 RRT-Connect (Kuffner): bidirectional greedy connect — fast feasible solutions.
  • 2002 D Lite (Koenig & Likhachev)*: incremental replanning for changing environments.
  • 2008 Hybrid A (Dolgov/Thrun, DARPA Urban Challenge)*: continuous-state lattice search for cars.
  • 2009 CHOMP (Ratliff): covariant gradient trajectory optimization on a cost field.
  • 2011 RRT (Karaman & Frazzoli)*: provably asymptotically optimal sampling.
  • 2014–15 Informed RRT / BIT (Gammell)**: ellipsoidal informed sampling; batch heuristic search.
  • Ecosystems: OMPL (planner library), MoveIt (manipulators), ROS2 nav2 (mobile, Smac/DWB), SBPL (lattice).

2.3 Engineering muscles

Generic trait design over abstract state spaces; spatial data structures (kd-tree, BVH); numerically robust geometry (GJK/EPA tolerances); priority-queue search at scale; reproducible RNG; real-time loop budgeting; differential testing against a mature reference; property-based testing of geometric invariants.

2.5 Calibration value

After this project an engineer can reason about completeness vs optimality, choose a planner for a given C-space dimension and query pattern, profile and minimize collision checking, and ship a deterministic, replayable, real-time-capable planning stack — the calibration baseline for autonomy work.

2.6 What Mastery Looks Like

What Mastery Looks Like — finishing this blueprint means you can:

  • Choose the right planner (A*, PRM, RRT, RRT*, Hybrid A*, DWA) for a given C-space dimension, query pattern, and completeness/optimality requirement, and defend the tradeoff quantitatively (Phase 4–Phase 8)
  • Specify a numerically-robust collision checker (GJK/EPA/BVH) that sustains ≥ 1e5 full-robot checks/s and never crashes on adversarial geometry (Phase 2)
  • Derive a signed distance field from an occupancy grid, reason about gradient correctness, and formulate a covariant smoothing gradient from it (Phase 3, Phase 9)
  • Establish asymptotic optimality from the near-radius condition r_n = γ·(log n / n)^(1/d) and instrument the convergence curve to verify the invariant holds (Phase 7)
  • Specify a kinodynamic planner for curvature-constrained vehicles (Dubins/Reeds-Shepp closed-form, Hybrid A* search) where every emitted path satisfies κ ≤ κ_max by construction (Phase 8)
  • Specify a hard-real-time reactive local loop (≤ 20 ms, zero allocation in steady state) that fails safe on overrun and replans without stalling the control thread (Phase 11)
  • Construct a determinism harness that byte-compares plan results across runs/platforms and CI-gates any reproducibility regression (Phase 12)

3.2 One paragraph per box

  • mp-planner — top-level orchestrator. Owns the PlanRequest, selects the global planner by PlannerCfg, runs collision-checked search, then smoothing then time parameterization, and packages PlanResult. Stateless across requests except for caches; deterministic given the request's seed. Boundary between user intent and algorithm choice.
  • mp-space (C-space) — defines the configuration space (SE(2), SE(3), R^n joint). Provides sample (seeded), interpolate, distance (metric), and validate (bounds). Every planner is generic over this trait; it is the abstraction that lets one planner serve a car, a drone, and an arm. Hot path: distance and interpolate called millions of times.
  • mp-collision (checker) — answers "is configuration q (or motion q1->q2) in collision?". Broad phase culls pairs via BVH/uniform grid; narrow phase resolves convex pairs via GJK (distance/intersection) and EPA (penetration). Motion validation discretizes an edge at resolution ε and checks each sub-state. The dominant cost in planning; designed for batching and early-out.
  • mp-env (world model) — owns the environment representation: OccupancyGrid (binary/probabilistic cells), Costmap (layered inflation + cost), and Esdf (signed distance to nearest obstacle, with gradient). Provides cost and clearance queries to planners and smoothers. Loaded from map files; treated as untrusted input.
  • Global planner — mp-graph — discrete search on a grid/graph: Dijkstra, A* (admissible heuristic), weighted/greedy A* (bounded suboptimality), and D* Lite (incremental repair on edge-cost changes). Resolution-complete; optimal on the discretization.
  • Global planner — mp-sampling — probabilistic planners: PRM/lazy-PRM (multi-query blueprint), RRT/RRT-Connect (single-query feasible), RRT*/Informed RRT* (asymptotically optimal). Avoids explicit C-obstacle construction; scales to high DOF.
  • Global planner — mp-steer — kinodynamic/non-holonomic: Dubins and Reeds-Shepp closed-form steering, discrete state lattices, and Hybrid A* (continuous-state A* with analytic expansions). Produces paths a curvature-constrained vehicle can actually follow.
  • mp-opt (smooth) — post-processes a feasible path: shortcutting (replace sub-paths with valid straight/steering connections) and CHOMP-style covariant gradient descent on an ESDF obstacle cost plus a smoothness term. Reduces path length/jerk while preserving collision-freedom.
  • mp-time (parameterize) — converts a geometric path to a time-stamped Trajectory honoring velocity/acceleration (and optionally jerk) limits: trapezoidal and S-curve profiles, and TOPP-lite path-velocity optimization. Output is what a controller consumes.
  • mp-local (DWA loop) — the only real-time component. Each tick, samples a dynamic window of feasible (v, ω) (or joint velocities), forward-simulates, scores against goal/clearance/velocity, and emits the best command. Watches for trajectory invalidation and raises a replan trigger. Bounded ≤ 20 ms.
  • replan trigger — bridges real-time and offline: when the local planner detects the global trajectory is blocked or stale, it requests a new global plan (full or D* Lite incremental) without stalling the control loop.

3.3 Boundaries

  • Concurrency boundary: offline global planning (ms–s, may run on a worker thread/process) vs the real-time local loop (≤ 20 ms, dedicated thread, pre-allocated). Communication via a lock-free single-slot channel carrying the latest trajectory.
  • Trust boundary: map files and robot models are untrusted (§ Threat Model); all parsing is bounds-checked and resource-capped.
  • Determinism boundary: every stochastic step draws from a single seeded RNG threaded through PlanRequest; same seed + same inputs -> byte-identical path.

6. Design Principles

  1. P1 — Collision-checking is the bottleneck — minimize, batch, lazy-evaluate. 90%+ of planning time is collision queries. Implication: cache broad-phase culls, validate edges lazily (only when an edge enters the candidate solution), early-out narrow phase. Violation: per-edge eager full-robot checks make even simple plans seconds-slow; profiling shows >95% in narrow phase.

  2. P2 — State completeness guarantees are stated, never assumed. Each planner declares its guarantee: resolution-complete (A*/Hybrid A*), probabilistically complete (RRT/PRM), asymptotically optimal (RRT*/Informed RRT*). Tradeoff: stronger guarantees cost time. Violation: callers expecting optimality from RRT ship suboptimal paths and blame the planner.

  3. P3 — Anytime + incremental over restart. Long-running planners return the best-so-far at any deadline; replanning repairs (D* Lite) rather than recomputes. Tradeoff: bookkeeping overhead. Violation: replanning-from-scratch in a dynamic map blows the local loop budget.

  4. P4 — Determinism given the RNG seed. Same inputs + seed -> identical path bytes. One seeded rand_chacha RNG threaded through the request; no thread-local entropy, no HashMap iteration order in hot paths (use BTreeMap/sorted). Violation: irreproducible bugs; differential tests flap; CI cannot gate.

  5. P5 — Separation of planner / steering / collision / environment / metric. Each is a trait; planners are generic over all four. Tradeoff: more generics, more monomorphization. Violation: a car-specific RRT cannot serve an arm; collision logic leaks into search and becomes untestable.

  6. P6 — Path validity is non-negotiable. A returned path is collision-free at resolution ε on every edge, or the result is NoPath/error — never a "probably fine" path. Implication: final validation pass before returning. Violation: robot collides; trust destroyed; safety incident.

  7. P7 — Metrics must be true distance metrics where planners assume it. Symmetry/triangle-inequality matter for RRT* near-radius and PRM connection. SE(2) uses a weighted position+angle metric; document weights. Violation: rewiring picks wrong parents; cost no longer monotone.

  8. P8 — Admissible heuristics for optimal search. A* heuristic never overestimates (Euclidean/octile for grids; never inflate unless weighted-A* with declared bound). Violation: A* returns suboptimal paths while claiming optimality; invariant #7.6 trips.

  9. P9 — Bounded real-time local loop. mp-local pre-allocates, never allocates in steady state, and has a hard per-tick deadline; if it would overrun it returns the last safe command. Tradeoff: fixed sample budget. Violation: a tick overruns, the controller starves, the robot lurches.

  10. P10 — Resource caps everywhere. Sample counts, tree size, ESDF memory, search expansions all have configurable hard caps; exceeding a cap is a graceful ResourceExhausted, not an OOM. Violation: an adversarial map balloons the tree and OOM-kills the process (§ Threat Model).

  11. P11 — Configuration validity is checked at the boundary. Start/goal validated against bounds + collision before search starts; invalid -> typed error, not silent failure. Violation: planner loops forever from an in-collision start.

  12. P12 — No hidden global state. Planners, RNG, caches are owned by the request/engine instance; multiple plans can run concurrently in separate instances. Violation: two threads share an RNG -> nondeterminism + data race (compile error in Rust, but discipline still required for caches).

  13. P13 — Float discipline. Use f64 in planning math; define tolerances as named constants (EPS_GEOM, EPS_ANGLE); never == on floats; ordered-float for keys. Violation: GJK never terminates; degenerate triangles crash EPA.

  14. P14 — Observability is first-class. Every planner emits structured stats (samples, checks, expansions, time, final cost, anytime curve). Implication: stats struct is part of the API. Violation: production "planner is slow" reports are undebuggable.

7. System Invariants

Format per invariant: statement / why / enforced / detection / telemetry / recovery / debugging.

7.1 I1 — Returned path is collision-free at resolution ε

  • Statement: every edge of a returned path, discretized at ε, contains no in-collision state.
  • Why: the robot will physically follow it; a collision is a safety failure (Principle 6).
  • Enforced: final validate_path pass in mp-planner before constructing PlanResult::Solved.
  • Detection: re-validation in mp-bench; property test asserts on every generated solution.
  • Telemetry: path_validation_failures counter (must stay 0); logs offending edge + state.
  • Recovery: discard path, return NoPath or retry with finer ε; never emit the path.
  • Debugging: dump the failing motion to a fixture; replay narrow-phase on the exact pair.

7.2 I2 — Path connects start to goal within tolerance

  • Statement: first state ≈ start, last state ≈ goal (within goal_tol in the metric).
  • Why: a path to the wrong place is useless.
  • Enforced: planners terminate only on goal-region membership; checked again at packaging.
  • Detection: assertion in PlanResult constructor; differential test vs OMPL endpoints.
  • Telemetry: goal_distance_residual gauge.
  • Recovery: if residual > tol, continue planning or report NoPath.
  • Debugging: inspect goal-region predicate + tolerance config.

7.3 I3 — Kinodynamic / non-holonomic constraints satisfied

  • Statement: curvature ≤ κ_max, |v| ≤ v_max, |a| ≤ a_max on every edge for constrained spaces.
  • Why: a car cannot turn sharper than κ_max; violating it is unexecutable (#289 cannot track it).
  • Enforced: steering functions (mp-steer) only emit feasible primitives; mp-time clamps to limits.
  • Detection: post-hoc constraint check in validation; property test on Dubins/RS outputs.
  • Telemetry: constraint_violations{type} counter.
  • Recovery: reject the primitive; choose a feasible alternative; fail to NoPath if none.
  • Debugging: log the violating segment's curvature/velocity profile.

7.4 I4 — RRT* cost is monotonically non-increasing (anytime)

  • Statement: across iterations, the best solution cost never increases.
  • Why: anytime contract — interrupt at any time and the latest is the best.
  • Enforced: rewiring only accepts strictly-improving parents; best-cost tracked monotonically.
  • Detection: assertion each iteration; anytime-curve fixture must be non-increasing.
  • Telemetry: best_cost time series (the anytime curve).
  • Recovery: revert a rewire that would increase cost (bug guard).
  • Debugging: dump the rewiring decision (old vs new parent cost).

7.5 I5 — Deterministic given seed

  • Statement: identical (RobotModel, Environment, start, goal, cfg, seed) -> identical PlanResult bytes.
  • Why: replay, regression, differential testing, audit.
  • Enforced: single seeded RNG; sorted iteration; fixed float mode; no wall-clock in logic.
  • Detection: determinism harness runs each scenario twice, byte-compares.
  • Telemetry: determinism_mismatch counter (must be 0).
  • Recovery: none at runtime; it is a build-blocking CI failure.
  • Debugging: bisect with a per-step RNG draw log to find the first divergence.

7.6 I6 — Heuristic admissibility (A* optimality)

  • Statement: A* heuristic h(n) ≤ true cost-to-go for all n (unless weighted-A* with declared ε).
  • Why: admissibility is necessary for A* optimality on the discretization.
  • Enforced: heuristic functions documented + unit-tested as lower bounds on representative graphs.
  • Detection: property test compares h against Dijkstra ground-truth cost-to-go.
  • Telemetry: heuristic_inflation (max observed h/true ratio; ≤ 1.0 admissible).
  • Recovery: fall back to Dijkstra (h=0) if a heuristic is flagged inadmissible.
  • Debugging: log nodes where h exceeded true cost.

7.7 I7 — Local loop meets its deadline

  • Statement: each mp-local tick completes within the configured budget (≤ 20 ms).
  • Why: the controller (#289) consumes commands at a fixed rate; an overrun starves it.
  • Enforced: bounded sample count; pre-allocated buffers; soft-deadline check returns best-so-far.
  • Detection: per-tick duration histogram; alert on p99 > budget.
  • Telemetry: local_tick_us histogram; local_deadline_overruns counter.
  • Recovery: emit last safe command (e.g. decelerate/stop) on overrun; raise replan.
  • Debugging: flamegraph the slow tick; check for allocation or unbounded scoring.

7.8 I8 — Tree/graph contains no invalid edges

  • Statement: every edge stored in a tree/blueprint has been (or will be, for lazy) validated; no in-collision edge contributes to a returned path.
  • Why: an invalid edge can leak into the solution and break #7.1.
  • Enforced: eager checkers validate on insert; lazy checkers validate on extraction and remove invalid edges.
  • Detection: invariant sweep over the structure in tests; differential vs OMPL.
  • Telemetry: lazy_edge_invalidations counter.
  • Recovery: remove invalid edge, re-search; never return it.
  • Debugging: replay the edge through narrow phase.

7.9 I9 — Metric obeys triangle inequality where required

  • Statement: distance(a,c) ≤ distance(a,b) + distance(b,c) for metrics used by RRT*/PRM.
  • Why: rewiring and near-neighbor correctness depend on it.
  • Enforced: metric implementations documented; property test on random triples.
  • Telemetry: metric_triangle_violations (must be 0).
  • Recovery: forbid non-metric pseudo-distances in optimizing planners (type/feature gate).
  • Debugging: log violating triple + metric weights.

7.10 I10 — Every resource cap fails graceful, never OOM

  • Statement: exceeding any configured cap (samples, tree nodes, expansions, ESDF bytes) returns PlanError::ResourceExhausted, never an abort/OOM (Principle 10).
  • Why: untrusted maps/models must not crash or exhaust the host (§ Threat Model).
  • Enforced: caps checked before each growth step / allocation in mp-sampling/mp-graph/mp-env; allocation bounded by cap.
  • Detection: fuzz the parsers/planners with adversarial inputs; assert no OOM, only typed errors.
  • Telemetry: resource_exhausted_total{what}, tree_nodes, esdf_bytes gauges.
  • Recovery: return the capped/typed result; caller may raise the cap deliberately.
  • Debugging: log which cap tripped, the configured limit, and the input hash.

7.11 I11 — Start and goal validated at the boundary before search

  • Statement: start and goal are bounds-checked and collision-checked before any planner loop runs; invalid -> typed error, not a hang (Principle 11).
  • Why: a planner that loops forever from an in-collision start is a liveness failure.
  • Enforced: validate(start)/validate(goal) + in_collision gate in mp-planner before solve.
  • Detection: integration tests inject in-collision / out-of-bounds endpoints; expect StartInCollision/GoalOutOfBounds.
  • Telemetry: boundary_validation_rejections{kind} counter.
  • Recovery: none at runtime (input error); surface the typed error to the caller.
  • Debugging: dump the offending endpoint + bounds + collision verdict.

7.12 I12 — Zero heap allocation in the local-loop steady state

  • Statement: after warm-up, an mp-local tick performs no heap allocation; all buffers are pre-allocated to the configured caps (Principle 9).
  • Why: a steady-state allocation can stall a tick past its deadline (I7) and starve the controller (#289).
  • Enforced: pre-allocated arenas/buffers; allocation forbidden on the tick path; checked by an allocator counter in tests.
  • Detection: dhat/custom allocator counter asserts 0 allocations across N steady-state ticks.
  • Telemetry: local_loop_allocations counter (must be 0 in steady state).
  • Recovery: if an allocation is detected in CI, the build is blocked; at runtime the soft-deadline guard (I7) returns the last safe command.
  • Debugging: attribute the allocation via allocator backtrace; bisect the offending tick input.

8.2 Metrics

  • Euclidean (R^n), weighted SE(2), SE(3) (position + rotation geodesic), joint-weighted.
  • All metrics: non-negative, symmetric, identity-of-indiscernibles, triangle inequality (#7.9).
  • Pseudo-metrics (e.g. Dubins length as cost-to-go) are allowed as costs but flagged non-metric for optimizing planners.

All samplers draw from the single seeded RNG (#7.5).

8.4 Steering functions (worked geometry)

SteeringFn::steer(from, to) -> Option<Path> produces a feasible primitive.

  • Straight: linear interpolation in the metric; holonomic.
  • Dubins: 6 word types {LSL, RSR, LSR, RSL, RLR, LRL}, each a sequence of {Left arc (radius R=1/κ_max), Straight, Right arc}. Shortest forward-only path between two SE(2) poses. Closed-form: transform to into from's frame, compute each word's length, pick the minimum feasible.
  • Reeds-Shepp: 48 word patterns allowing reversals (segments may be backward). Superset of Dubins; used when the vehicle can reverse. Closed-form per the 1990 classification.

Worked Dubins example

Start pose (0, 0, 0) (heading +x), goal (4, 0, π) (heading -x), turning radius R = 1.

  • Candidate LSL: left turn, straight, left turn. Compute the two tangent circles (left of start, left of goal), the connecting tangent, arc angles.
  • Candidate RSR symmetric.
  • For this symmetric "U-turn", the minimal word is typically RSL/LSR or an LRL/RLR depending on separation. With separation 4 and R=1, the straight-segment words dominate; the engine evaluates all 6 and returns the shortest with total length L = arc₁·R + straight + arc₂·R. Expected ~ (π/2)·1 + 2 + (π/2)·1 ≈ 5.14 m (illustrative). Conformance fixture pins exact lengths to 1e-6.

8.6 Collision model

  • Shapes: sphere, AABB, OBB, capsule, convex polytope, triangle mesh (as BVH of triangles).
  • Broad phase: BVH (AABB tree) over robot links + obstacles; or uniform spatial hash for grids. Produces candidate pairs.
  • Narrow phase: GJK (boolean intersection + distance for convex pairs), EPA (penetration depth/normal when overlapping), SAT (boxes), sphere/capsule analytic tests.
  • Motion (edge) validation: discretize edge at ε, check each sub-state; optionally adaptive subdivision (check midpoint, recurse) for early-out.

8.7 Graph / tree representations

  • Graph (PRM, grid): nodes = states/cells; edges with cost; adjacency via Vec/CSR; near-neighbors via kd-tree.
  • Tree (RRT family): each node has a parent index + cumulative cost; near-neighbors via kd-tree (rebuilt/incremental).
  • Search frontier: binary heap keyed by f = g + h (A*) or g (Dijkstra), keys via ordered-float.

ASCII: RRT tree growth (5 iterations, 2-D)

 start S                        q_rand x
   *                               .
   |\                              ^ steer (step η)
   | \                             |
   *  *                            * q_new  (added if motion S-region valid)
  /|                               
 * *      after k iters:    S---*---*---*===> toward goal G

Tree extension: sample q_rand; find nearest tree node q_near; q_new = steer(q_near, q_rand, η); if motion(q_near, q_new) collision-free, add q_new with parent q_near. RRT-Connect grows two trees and tries to connect greedily.

8.8 Trajectory representation

  • Geometric path: ordered Vec<State> (waypoints) + optional segment type (straight / Dubins word / RS word).
  • Smoothed path: same, fewer/optimized waypoints, possibly spline-fitted.
  • Trajectory: Vec<TrajPoint { t: f64, state: State, vel: Vec, acc: Vec }> — monotone time stamps; honors v/a limits.

11.1 State and StateSpace

// mp-space
pub enum State {
    R2 { x: f64, y: f64 },
    Se2 { x: f64, y: f64, theta: f64 },     // theta in [-PI, PI)
    Se3 { pos: [f64; 3], rot: UnitQuaternion },
    Joint(SmallVec<[f64; 8]>),               // n joint values
}

pub trait StateSpace {
    type S;                                   // associated state type
    fn dim(&self) -> usize;
    fn sample(&self, rng: &mut ChaChaRng) -> Self::S;          // uniform in bounds
    fn interpolate(&self, a: &Self::S, b: &Self::S, t: f64) -> Self::S; // t in [0,1]
    fn distance(&self, a: &Self::S, b: &Self::S) -> f64;       // metric (#7.9)
    fn validate(&self, s: &Self::S) -> bool;                   // within bounds
    fn enforce_bounds(&self, s: &mut Self::S);                 // clamp/wrap
}

Ownership: spaces are immutable, Send + Sync, shared by Arc. Mutation: none (config in constructor). Concurrency: read-only across planner threads. Serialization: serde (bounds, weights). Compatibility: adding a state variant is breaking -> semver major.

Phase 1 — State space / C-space + metrics + samplers

1.1 Objectives

Implement mp-space: SE(2), SE(3), R^n joint, R² spaces with correct metrics, bounds, interpolation, and the sampler family, all deterministic under a seeded RNG. This is the abstraction every planner builds on.

1.2 Detailed Implementation Steps

  • Implement State variants + StateSpace for each space: Se2Space, Se3Space, JointSpace { lo, hi, weights }, R2Space. (LaValle 2006 Ch. 4; P5)
  • distance: weighted SE(2) (w_θ configurable), SE(3) (position + quaternion geodesic 2·acos(|q1·q2|)), joint-weighted Euclidean. (P7, P13; LaValle 2006 §5.1)
  • interpolate: linear for translation; slerp for quaternions; angle interpolation with wrap for SE(2) θ.
  • enforce_bounds: clamp joints to [lo,hi]; wrap θ to [-π,π); normalize quaternions.
  • Samplers: Uniform, Gaussian (sample_near), Bridge, Halton (low-discrepancy sequence), InformedEllipsoid (transform unit-ball samples by the rotation/scale from c_best, c_min, focii). (LaValle 2006 Ch. 5; P4, ADR-6)
  • RNG: ChaChaRng seeded from PlanRequest.seed; one instance threaded through; no thread-local randomness.
  • Property tests: metric axioms (symmetry, triangle inequality #7.9), interpolate(a,b,0)=a, interpolate(a,b,1)=b, enforce_bounds idempotent. (P7, I9)

1.3 Deliverable

mp-space exposes all spaces + samplers; mpctl can sample N states from a space with a fixed seed and dump them; same seed -> identical dump.

1.4 Acceptance Criteria

  • Metric property tests pass for all spaces (1e6 random triples, 0 triangle violations).
  • Determinism: 2 runs of 1e5 samples byte-identical (#7.5).
  • SE(3) interpolation stays on the unit sphere (‖q‖ = 1 ± 1e-9).
  • Halton dispersion measurably lower than uniform on a 2-D coverage metric (documented).

1.5 Conformance Fixtures

  • conformance/space/se2_distance.json — pose pairs + expected weighted distances (1e-9 tol).
  • conformance/space/se3_slerp.json — quaternion interpolation checkpoints.
  • conformance/space/sampler_seed.json — first 100 uniform/Halton samples for seed 42.
  • Degenerate: antipodal quaternions (slerp ambiguity) -> documented shortest-arc choice.

1.6 Pitfalls

  • Angle wrap-around: naive θ subtraction gives 359° instead of 1°. Use angdiff. Detection: SE(2) distance > π for nearby headings.
  • Quaternion double-cover: q and -q are the same rotation; slerp must pick the short arc (flip if dot < 0). Detection: interpolation takes the long way.
  • Metric weight mis-scaling: meters vs radians not comparable; w_θ couples them. Detection: planner ignores rotation or over-rotates.
  • Halton dimension drift: wrong prime base per dimension ruins dispersion. Pin base table.
  • Joint-limit at boundary: sampling exactly at hi then collision-checking; ensure inclusive bounds + tolerance.

1.7 Performance Concerns

distance/interpolate are the hottest functions (called per near-neighbor and per motion step). Keep them allocation-free, branch-light, #[inline]. SE(3) acos is costly — consider clamping argument to [-1,1] and using a fast path for near-identical quaternions. SIMD candidate for joint-space distance.

1.8 Edge Cases

Zero-DOF space (reject); degenerate bounds (lo == hi); NaN in input state (reject via validate); near-antipodal quaternions; sampler called with std=0 (returns center).

1.9 Failure Analysis

A wrong metric silently degrades every downstream planner (suboptimal/no convergence). Detection = metric property tests + planner success-rate regression. Blast radius = all planners. Recovery = fix metric, rerun conformance. Forensic = dump offending state pairs.

1.10 Operational Notes

Expose space type + weights in PlannerStats so operators see what C-space a plan ran in. Log sampler kind + seed at plan start. Determinism counter wired (#7.5).

Phase 2 — Collision checking (geometry, broad+narrow phase, BVH, GJK/EPA)

2.1 Objectives

Implement mp-geom (shapes, transforms, FK) and mp-collision (broad-phase BVH, narrow-phase GJK/EPA/SAT, motion validation). This subsystem dominates runtime; design for speed and numerical robustness.

2.2 Detailed Implementation Steps

  • mp-geom: Isometry (SE(2)/SE(3) transform), shapes (Sphere, Aabb, Obb, Capsule, ConvexPolytope, TriMesh), support functions for GJK. (Ericson 2004 Ch. 4; P13)
  • RobotModel: links with collision geometry, joints (revolute/prismatic) with limits, FK to place link shapes given a State (joint or SE(2)/SE(3)). URDF/SRDF-subset parser (roxmltree), allowed-collision matrix (ACM).
  • Broad phase: build BVH (AABB tree, SAH-lite) over obstacles; refit/rebuild per env update; query candidate pairs vs robot link AABBs. Optional uniform spatial hash for grid worlds.
  • Narrow phase: GJK (Minkowski-difference support, simplex evolution, distance + boolean), EPA (expanding polytope for penetration depth/normal), SAT for box-box, analytic sphere/capsule tests. Tolerances EPS_GEOM, max-iteration caps. (Gilbert-Johnson-Keerthi 1988; ADR-7)
  • Motion validation: motion_valid(a,b,eps) — uniform discretization at ε or recursive midpoint subdivision with early-out; counts checks. (P6, I1; ADR-7)
  • Self-collision: check link pairs not in the ACM.
  • Property tests: GJK distance ≥ 0; GJK boolean agrees with distance==0; EPA normal points out of penetration; separating-axis equivalence with GJK on boxes. (P13, I1; Ericson 2004 Ch. 5)

2.3 Deliverable

mp-collision answers config + motion + clearance queries for a robot in an environment; mpctl validate reports collision status of a state; benchmark reports checks/s.

2.4 Acceptance Criteria

  • ≥ 1e5 full-robot checks/s and ≥ 1e6 sphere/AABB checks/s on a single core (§4).
  • GJK terminates within iteration cap on 1e6 random convex pairs (0 non-terminations).
  • Differential: collision verdicts match a reference (FCL-derived fixtures) within tolerance on the conformance set.
  • Motion validation never misses a collision present at ε (tested on adversarial thin walls).

2.5 Conformance Fixtures

  • conformance/collision/gjk_pairs.json — convex pairs + expected distance/penetration (1e-6).
  • conformance/collision/motion_thinwall.json — edge crossing a wall thinner than a coarse step; must report collision at proper ε.
  • conformance/collision/self_collision_arm.json — 7-DOF poses with/without self-collision + ACM.
  • Degenerate: coincident shapes, zero-radius sphere, zero-area triangle, deeply nested penetration.

2.6 Pitfalls

  • GJK cycling on degenerate simplices: floating error makes the simplex oscillate. Mitigation: robust simplex reduction + iteration cap + restart. Detection: iteration-cap-hit counter > 0.
  • Tunneling: a coarse ε steps through a thin obstacle. Mitigation: ε ≤ smallest obstacle thickness / 2, or continuous collision detection (conservative advancement) for fast motions. Detection: thin-wall fixture fails.
  • EPA on shallow penetration: unstable normal near touching. Mitigation: clamp, fall back to GJK distance sign.
  • BVH staleness: env changes but BVH not refit -> stale candidate pairs. Mitigation: version the env; invalidate BVH on change.
  • ACM omissions: missing allowed pair -> false self-collision deadlocks planning. Detection: 100% self-collision on a valid home pose.
  • Mesh winding: inconsistent triangle winding flips inside/outside. Validate on load.

2.7 Performance Concerns

Collision is the bottleneck (Principle 1). Optimize: contiguous BVH node layout (cache locality), early-out on first collision in motion validation, batch broad-phase queries, avoid per-query allocation (reuse simplex/stack buffers), SIMD support-function dot products. Track narrow-phase fraction of total time; aim < 90% with broad-phase culling effective.

2.8 Edge Cases

2.9 Failure Analysis

A missed collision -> invariant #7.1 broken -> potential safety incident. Detection = re-validation + thin-wall fixtures + property tests. Blast radius = every plan using this checker. Containment = block release on conformance failure. Forensic = serialize the exact (shapes, transforms) pair for offline replay.

Phase 3 — Environment model (occupancy grid, costmap, ESDF)

3.1 Objectives

Implement mp-env: OccupancyGrid import + semantics, layered Costmap with inflation, and exact Esdf (signed distance + gradient) for clearance cost and CHOMP. Treat maps as untrusted input.

3.2 Detailed Implementation Steps

  • OccupancyGrid: row-major Vec<u8>, resolution, origin; import from PGM/PNG and nav_msgs/OccupancyGrid semantics ([0,100] occupancy, -1 unknown -> configurable treatment). Bounds-checked indexing. (Thrun, Burgard, Fox 2005 Ch. 6; ADR-14)
  • Costmap: base grid + layers (StaticLayer, InflationLayer, optional DynamicLayer); inflation = exponential decay of cost out to inflation_radius (cost 254 lethal -> decaying). Composite cost = max/last-write per layer.
  • Esdf: exact Euclidean distance transform (Felzenszwalb-Huttenlocher, separable 1-D lower-envelope per axis) over the obstacle set and the free set; signed = +outside / -inside. Compute gradient via central differences. Support 2-D and 3-D; tile/cap memory (§4). (ADR-10, P13)
  • Queries: occupied(p), cost(p) (bilinear/nearest), distance(p), gradient(p) (trilinear in 3-D). (P1, P10; ADR-10)
  • Import validation: dimensions sane, non-empty, resolution > 0, values in range; reject otherwise (InvalidMap). (P10, P11; ADR-21)
  • Property tests: ESDF distance ≥ 0 outside, monotone away from obstacles; EDT equals brute-force on small grids; gradient points away from nearest obstacle.

  • EDT matches brute-force exact distance on 100 random ≤ 64×64 grids (0 mismatches).
  • ESDF build ≤ O(n) per axis; 1000×1000 grid built in < 100 ms.
  • Inflation produces lethal cost within inflation_radius of every obstacle.
  • Memory for a tiled 1000³ ESDF stays under the configured cap (§4).

  • conformance/env/edt_small.json — grid + expected exact distances.
  • conformance/env/inflation.json — obstacle + expected inflated cost ring.
  • datasets/scenarios/{empty_2d,random_2d,narrow_passage_2d,maze_2d}/ — maps used across phases.
  • Degenerate: all-free (distance = +inf clamped), all-occupied (distance = 0 / negative inside), single-cell map.

3.6 Pitfalls

  • Off-by-one in EDT: distances shifted by half a cell. Mitigation: pin cell-center convention; brute-force cross-check.
  • Unknown-cell semantics: treating unknown as free invites collisions; as occupied blocks valid space. Make it explicit + configurable; default = lethal for safety.
  • ESDF sign errors inside obstacles: needed for CHOMP gradients to push out. Test inside points have negative distance + outward gradient.
  • Memory blow-up in 3-D: a dense 1000³ f32 ESDF is 4 GB. Mitigation: tiling + cap + on-demand build.
  • Coordinate/origin mismatch: world-to-grid transform errors place obstacles wrong. Pin origin + resolution; round-trip test.

3.7 Performance Concerns

ESDF build is a one-time cost amortized over many queries; cache to binary for fixtures. Query path (CHOMP/DWA) must be allocation-free with trilinear interpolation; keep dist/grad in contiguous arrays for locality. Inflation recompute on dynamic updates should be incremental (only changed region).

3.8 Edge Cases

Point outside grid bounds (clamp + report unknown); fractional coordinates at exact cell boundaries; negative resolution/origin (reject); extremely sparse obstacles (distance saturates).

3.9 Failure Analysis

A wrong ESDF silently corrupts smoothing (CHOMP pushes into obstacles) and DWA clearance. Detection = EDT brute-force cross-check + smoother re-validation (#7.1). Blast radius = mp-opt, mp-local. Recovery = rebuild ESDF; gate on conformance. Forensic = dump the grid + ESDF slice as an image.

Phase 4 — Graph search (A*, Dijkstra, weighted/greedy) + D* Lite incremental replanning

4.1 Objectives

Implement mp-graph: Dijkstra, A* (admissible heuristics), weighted-A*/greedy (bounded suboptimality), and D* Lite (incremental replanning on edge-cost changes). Resolution-complete, optimal on the discretization.

4.2 Detailed Implementation Steps

  • Grid graph over Costmap: 4/8-connected (2-D) or 6/26-connected (3-D); edge cost = distance × cell-cost factor; lethal cells impassable. (Hart, Nilsson, Raphael 1968; P8)
  • Binary-heap frontier keyed by f = g + h (A*) / g (Dijkstra); ordered-float keys; closed set via visited array; deterministic tie-break (by node index).
  • Heuristics: Euclidean, octile (8-connected), Manhattan (4-connected); all admissible (#7.6); weighted-A* multiplies h by ε (declared bound). (P8, I6; Hart, Nilsson, Raphael 1968)
  • Path reconstruction via parent pointers; post-condition validation (#7.1, #7.2).
  • D* Lite: maintain g and rhs values, a priority queue keyed by [min(g,rhs)+h+k_m, min(g,rhs)]; update_vertex, compute_shortest_path; on edge-cost change, update affected vertices and re-plan incrementally; key modifier k_m for moving start. (Koenig & Likhachev 2002; P3)
  • Stats: expansions, frontier max size, path cost, time. (P14, ADR-16)
  • Property tests: A* cost == Dijkstra cost (admissible h); D* Lite result == fresh A* after each change; heuristic ≤ Dijkstra cost-to-go (#7.6).

4.3 Deliverable

mp-graph plans optimal grid paths and incrementally repairs them; mpctl plan --planner astar|dijkstra|dstar works on 2-D scenarios; D* Lite demo replans after injecting an obstacle.

4.4 Acceptance Criteria

  • A* path cost == Dijkstra on all grid fixtures (optimality, #7.6).
  • Weighted-A* (ε=1.5) returns cost ≤ ε × optimal, with fewer expansions than A*.
  • D* Lite after K obstacle insertions yields the same path as K fresh A* runs (0 mismatches), with fewer total expansions.
  • 1000×1000 grid A* p50 ≤ 50 ms (§4).

4.5 Conformance Fixtures

  • conformance/astar/maze_2d_optimal.json — maze + expected optimal cost/path.
  • conformance/astar/weighted_bound.json — weighted-A* cost ≤ ε·optimal.
  • conformance/dstar/replan_sequence.json — sequence of obstacle edits + expected repaired paths.
  • Degenerate: start==goal; unreachable goal (NoPath); single open cell; fully blocked map.

4.6 Pitfalls

  • Inadmissible heuristic: octile used on 4-connected grid overestimates -> suboptimal. Match heuristic to connectivity (#7.6).
  • Tie-break nondeterminism: heap ties resolved by insertion order vary run-to-run. Mitigation: deterministic secondary key (node index) (#7.5).
  • D Lite key staleness*: forgetting to update k_m on start move corrupts ordering. Symptom: replanned path wrong/looping.
  • Closed-set re-expansion with inconsistent h: weighted-A* may re-expand; bound expansions or accept suboptimality.
  • Float cost accumulation: summing many small costs drifts; use stable accumulation; compare with tolerance.

4.7 Performance Concerns

Heap operations dominate; use an indexed binary heap with decrease-key, or lazy deletion (push duplicates, skip stale). Visited/g arrays sized to the grid (contiguous, cache-friendly). For D* Lite, only affected vertices re-enter the queue — measure expansions saved vs fresh A*. Avoid hashing node coords; use packed integer indices.

4.8 Edge Cases

Grid with isolated free pockets; diagonal corner-cutting (forbid passing between two diagonal obstacles); cost overflow (cap at 254); start/goal on a lethal cell (StartInCollision/GoalInCollision).

4.9 Failure Analysis

Suboptimal/incorrect A* path -> robot takes a bad or invalid route. Detection = differential vs Dijkstra + path re-validation. Blast radius = all grid-based plans + Hybrid A* (Phase 8) which reuses the frontier. Recovery = fall back to Dijkstra (h=0). Forensic = dump expansion order + heuristic values.

4.10 Operational Notes

Emit astar_expansions, frontier_peak, dstar_incremental_expansions, path_cost. Runbook docs/runbooks/no-path.md covers unreachable-goal triage. D* Lite replan latency tracked separately for the dynamic-replan SLO.

Phase 5 — PRM (blueprint construction + query, lazy PRM)

5.1 Objectives

Implement mp-sampling PRM and lazy PRM: build a probabilistic blueprint over C-space for multi-query planning, then answer start->goal queries via graph search on the blueprint. Probabilistically complete.

5.2 Detailed Implementation Steps

  • Blueprint construction: sample N valid configs (sampler from Phase 1); add each as a node if collision-free; connect to k-nearest (or within radius r) neighbors via mp-steer straight (or Dubins/RS) edges, validating each edge (eager PRM) or deferring (lazy PRM). (Kavraki et al. 1996; P2, I8)
  • kd-tree for near-neighbor queries (build over node states); k-nearest and radius queries. (ADR-8, P1)
  • Query: connect start and goal to the blueprint (k-nearest valid connections), run A*/Dijkstra (mp-graph) over the blueprint graph.
  • Lazy PRM: skip edge collision checks at build; during query search, validate edges along the candidate path on demand; on invalid edge, remove it and re-search (#7.8). (Kavraki et al. 1996; I8, P1)
  • Blueprint reuse: persist/serialize the blueprint for repeated queries in a static environment.
  • Connection strategies: k-PRM (fixed k), PRM* (k or r scaled by log(n) for asymptotic optimality).
  • Property tests: every blueprint edge collision-free (eager) or validated-before-use (lazy) (#7.8); query path collision-free (#7.1). (I8, I1; P6)

5.3 Deliverable

mp-sampling::Prm builds a blueprint and answers queries; mpctl plan --planner prm|lazy_prm; blueprint can be saved/loaded; multi-query demo reuses one blueprint for several start/goal pairs.

5.4 Acceptance Criteria

  • Success rate ≥ 99% on random_2d (n ≥ 2000), ≥ 95% on narrow_passage_2d with Gaussian/bridge sampling (§4).
  • Lazy PRM does fewer collision checks than eager PRM for a single query (measured).
  • Multi-query: second query on a saved blueprint is ≥ 10× faster than the first (amortized build).
  • All returned paths collision-free (re-validated, #7.1).

5.5 Conformance Fixtures

  • conformance/prm/random_2d_success.json — seed + expected success + cost band.
  • conformance/prm/narrow_passage.json — bridge-sampling success-rate target.
  • conformance/prm/lazy_edge_invalidation.json — case where a lazy edge is invalidated and re-searched.
  • Degenerate: disconnected blueprint (NoPath); start/goal unconnectable to blueprint; n=0.

5.6 Pitfalls

  • k too small: blueprint disconnected -> false NoPath. Mitigation: PRM* scaling k ~ e·(1+1/d)·log(n).
  • Narrow-passage starvation: uniform sampling rarely hits thin corridors. Mitigation: Gaussian/bridge sampling; report success rate per scenario.
  • kd-tree degeneracy: clustered samples unbalance the tree. Mitigation: periodic rebuild / median split.
  • Lazy re-search thrash: many invalid edges cause repeated re-search. Mitigation: cache validated edges; bound re-search iterations.
  • Self-edges / duplicate edges: pollute the graph. De-dup on insert.

5.7 Performance Concerns

Build is dominated by edge collision checks (Principle 1) — lazy PRM defers them. kd-tree near-neighbor query is the second cost; keep it allocation-free. Blueprint stored as CSR adjacency for cache-friendly search. For multi-query, the blueprint is built once; query cost is just connection + graph search.

5.8 Edge Cases

Goal region (not point) — connect to multiple blueprint nodes; sampler exhausts attempts finding valid nodes (cap -> ResourceExhausted); environment changed since blueprint built (stale blueprint -> rebuild or use lazy validation).

5.9 Failure Analysis

A stale blueprint in a changed environment returns invalid edges. Detection = lazy validation (#7.8) + final re-validation. Blast radius = multi-query users. Recovery = rebuild blueprint on env version change. Forensic = blueprint node/edge dump + env hash.

5.10 Operational Notes

Emit blueprint_nodes, blueprint_edges, prm_collision_checks, lazy_edge_invalidations, query_search_time. Record blueprint hash + env hash in stats. Runbook for "PRM returns NoPath but path exists" (raise n, switch sampler).

Phase 6 — RRT / RRT-Connect (single + bidirectional)

6.1 Objectives

Implement single-tree RRT and bidirectional RRT-Connect: incremental single-query planners that grow trees by sampling and steering toward random configs. Probabilistically complete; fast feasible solutions.

6.2 Detailed Implementation Steps

  • RRT: loop — sample q_rand (with goal bias p_goal); q_near = tree.nearest(q_rand) (kd-tree); q_new = steer_bounded(q_near, q_rand, η); if motion_valid, add with parent; if q_new in goal region, terminate. Cap on iterations/nodes. (LaValle 1998; P4, ADR-6)
  • RRT-Connect: two trees (from start, from goal); each iteration extend one tree toward a random sample, then connect the other tree greedily toward the new node (repeated extend until reached or blocked); swap trees; on connection, splice both branches into one path. (Kuffner & LaValle 2000; P4)
  • Goal biasing: with probability p_goal sample the goal directly.
  • kd-tree: incremental insert; periodic rebuild if unbalanced. (ADR-8, P1)
  • Path extraction: walk parent pointers from goal to start (and mirror for the goal tree).
  • Property tests: every tree edge collision-free (#7.8); returned path collision-free (#7.1) and connects start->goal (#7.2); determinism under seed (#7.5). (I8, I1; P6)

6.3 Deliverable

mp-sampling::{Rrt, RrtConnect}; mpctl plan --planner rrt|rrt_connect; tree growth visualizable (mpctl viz --tree).

6.4 Acceptance Criteria

  • RRT-Connect success rate ≥ 99% on random_2d, ≥ 90% on narrow_passage_2d (§4).
  • RRT-Connect faster (fewer samples to first solution) than single RRT on the same scenarios (measured).
  • 7-DOF arm arm_shelf_7dof: feasible solution p50 ≤ 1 s (§4).
  • All paths collision-free + connect endpoints (#7.1, #7.2); deterministic per seed.

6.5 Conformance Fixtures

  • conformance/rrt/random_2d_success.json — seed -> success + node count band.
  • conformance/rrt/connect_bidirectional.json — connection point + path validity.
  • conformance/rrt/arm_7dof.json — joint-space feasibility + self-collision-free.
  • Degenerate: start in goal region (trivial); goal unreachable (cap -> NoPath); η too large (overshoots) / too small (slow).

6.6 Pitfalls

  • Step size η mis-tuned: too large overshoots obstacles (relies on motion_valid catching it); too small explores slowly. Tune relative to obstacle scale.
  • Goal bias too high: degenerates to greedy, gets stuck at local obstacles. Typical p_goal ≈ 0.05.
  • kd-tree staleness: nearest query wrong after many inserts without rebalancing -> poor extension. Periodic rebuild.
  • Connect overshoot: greedy connect must stop at first invalid motion, not skip. Off-by-one splices an invalid edge (#7.8).
  • Tree-swap bug: forgetting to swap trees biases growth to one side; slower connection.

6.7 Performance Concerns

Dominated by motion_valid (Principle 1) and nearest-neighbor queries. kd-tree query is O(log n) amortized but degrades when unbalanced. Pre-allocate node storage (Vec with capacity = node cap) to avoid reallocation. Avoid per-iteration heap allocation in steering. Bidirectional halves expected tree size to connection.

6.8 Edge Cases

Goal exactly on start; very long narrow corridor (RRT struggles; RRT-Connect better); high-dimensional joint space (nearest-neighbor cost grows); η larger than corridor width (always blocked).

6.9 Failure Analysis

RRT-Connect splicing an unvalidated connection edge -> invalid path (#7.1/#7.8). Detection = re-validation + property test. Blast radius = all RRT-family users. Recovery = revalidate connect motion before splice; if invalid, continue. Forensic = dump both tree branches + connection motion.

6.10 Operational Notes

Emit rrt_nodes, rrt_iterations, rrt_collision_checks, time_to_first_solution, goal_bias. Tree-size + seed in stats. Runbook for "RRT slow / no solution" (lower η, raise cap, switch to RRT-Connect, change sampler).

Phase 7 — RRT* / Informed RRT* (rewiring, asymptotic optimality)

7.1 Objectives

Implement RRT* (asymptotically optimal via rewiring) and Informed RRT* (ellipsoidal informed sampling once a solution exists). Anytime: best cost monotonically non-increasing (#7.4).

7.2 Detailed Implementation Steps

  • RRT* extension: after adding q_new, find near set within radius r_n = γ·(log n / n)^(1/d) (or k-nearest, PRM*-style); choose the parent in the near set minimizing cost(parent) + dist(parent, q_new) among collision-free connections; then rewire near nodes through q_new if it lowers their cost. (Karaman & Frazzoli 2011; I9, P7)
  • Cost tracking: cumulative cost from root per node; propagate cost changes to descendants after rewiring (or store and lazily update).
  • Anytime: keep best solution found; report best_cost each iteration; never increase (#7.4). (P3, I4; Karaman & Frazzoli 2011)
  • Informed RRT*: once c_best exists, sample only within the prolate hyperspheroid (focii = start, goal; transverse diameter = c_best; conjugate = √(c_best² − c_min²)); shrinks as c_best improves -> faster convergence. (Gammell et al. 2014; ADR-6)
  • Near-radius decay: ensure r_n shrinks correctly with n (asymptotic-optimality condition). (Karaman & Frazzoli 2011; P7, I9)
  • Property tests: best_cost non-increasing (#7.4); rewiring never creates a cycle; cost(child) == cost(parent)+edge after rewire; informed samples lie inside the ellipsoid.

7.3 Deliverable

mp-sampling::{RrtStar, InformedRrtStar}; mpctl plan --planner rrt_star|informed_rrt_star --time-budget; anytime curve exported (mp-bench anytime harness).

7.4 Acceptance Criteria

  • Path cost within 5% of reference optimal after 1e4 samples on narrow_passage_2d (§4).
  • best_cost non-increasing across iterations on every run (#7.4; 0 violations).
  • Informed RRT* reaches a given cost threshold in fewer samples than plain RRT* (measured, documented).
  • All anytime intermediate paths collision-free (#7.1).

7.5 Conformance Fixtures

  • conformance/rrt_star/anytime_curve.json — seed -> monotone non-increasing cost series.
  • conformance/rrt_star/optimal_gap.json — cost vs reference optimal after N samples.
  • conformance/rrt_star/informed_ellipsoid.json — sampled points all inside ellipsoid for given c_best.
  • Degenerate: c_best == c_min (ellipsoid collapses to the straight line); first solution == optimal (no improvement needed).

7.6 Pitfalls

  • Wrong near-radius: r_n not decaying -> loses asymptotic optimality or O(n²) cost. Verify the γ·(log n/n)^(1/d) formula and d (C-space dimension).
  • Rewiring cost-propagation bug: descendants keep stale cost -> non-monotone best_cost (#7.4). Mitigation: propagate or lazily recompute; test.
  • Ellipsoid transform error: informed samples leak outside (rotation/scale wrong) -> wasted samples. Test membership.
  • Metric non-triangle-inequality: breaks rewiring correctness (#7.9). Forbid pseudo-metrics here.
  • Floating cost ties: equal-cost parents chosen nondeterministically. Deterministic tie-break (#7.5).

7.7 Performance Concerns

Near-neighbor queries (radius search) scale with node count; kd-tree radius query is the hot path beyond collision checks. Rewiring adds collision checks per near node — batch and early-out. Informed sampling reduces effective sampling volume -> fewer wasted collision checks as c_best shrinks. Cost-propagation must be O(affected subtree), not O(n).

7.8 Edge Cases

Very small near-radius at low n (few rewires early); high d (near set large, expensive); solution found immediately (informed ellipsoid tiny); disconnected goal (degrades to RRT exploration, NoPath at cap).

7.9 Failure Analysis

Non-monotone best_cost -> anytime contract broken; a consumer interrupting mid-plan gets a worse path. Detection = anytime-curve fixture + per-iteration assertion (#7.4). Blast radius = optimizing-planner users. Recovery = guard rewires that would increase cost. Forensic = dump rewiring decisions + cost series.

7.10 Operational Notes

Emit best_cost time series (the anytime curve), rewire_count, near_set_size, informed_sample_fraction. Anytime curve rendered by mpctl viz. Stats note convergence rate for capacity planning.

Phase 8 — Kinodynamic / nonholonomic (Dubins/Reeds-Shepp steering, state lattice, Hybrid A*)

8.1 Objectives

Implement mp-steer: Dubins and Reeds-Shepp closed-form steering, discrete state lattices, and Hybrid A* (continuous-state A* with analytic expansions) for curvature-constrained vehicles. Constraints (#7.3) satisfied by construction.

8.2 Detailed Implementation Steps

  • Dubins: all 6 word types {LSL, RSR, LSR, RSL, RLR, LRL}; transform goal into start frame; closed-form arc/straight lengths per word; return shortest feasible; expose path discretization at ε for collision checking. (Dubins 1957; I3, P7)
  • Reeds-Shepp: 48-word classification (forward + reverse segments); compute lengths per the 1990 tables; choose shortest; tag segment directions (for cost: reverse penalty). (Reeds & Shepp 1990; I3, P13)
  • SteeringFn impls plug into RRT family (replace straight-line steering) and PRM edges for non-holonomic robots.
  • State lattice: precompute a set of feasible motion primitives (control set) from each heading bin; expand discrete (x, y, θ-bin) states with these primitives; edge cost = primitive length (+ penalties).
  • Hybrid A*: continuous (x, y, θ) state bucketed into a discrete grid for the closed set; expand with steering primitives (forward/reverse × steer-left/straight/right); heuristic = max(non-holonomic-without-obstacles via Dubins/RS lookup, holonomic-with-obstacles via 2-D Dijkstra on the grid); analytic expansion: periodically try a direct Dubins/RS shot to goal and accept if collision-free; reconstruct continuous path. (Dolgov, Thrun et al. 2008; P8, ADR-8)
  • Property tests: Dubins/RS paths respect κ_max (#7.3); Dubins length ≤ RS length (RS is a superset allowing reversal, so RS ≤ Dubins actually — verify direction); Hybrid A* path collision-free + curvature-feasible. (I3, P7; Dubins 1957)

8.3 Deliverable

mp-steer::{Dubins, ReedsShepp, StateLattice, HybridAStar}; mpctl plan --planner hybrid_astar on parking_lot; Dubins/RS path demos; non-holonomic RRT via plugged steering.

8.4 Acceptance Criteria

  • Dubins/RS lengths match closed-form reference to 1e-6 on conformance fixtures.
  • Every steered path satisfies κ ≤ κ_max (#7.3; 0 violations).
  • Hybrid A* finds a feasible parking path on parking_lot (with reversal) p50 ≤ 500 ms; path curvature-feasible + collision-free.
  • Analytic-expansion shortcut reduces expansions vs lattice-only (measured).

8.5 Conformance Fixtures

  • conformance/dubins/lengths.json — pose pairs + exact word + length (1e-6).
  • conformance/reeds_shepp/lengths.json — pose pairs + exact word + length (1e-6).
  • conformance/hybrid_astar/parking.json — scenario + feasible path with reversal.
  • Degenerate: identical start/goal pose (length 0); goal within turning radius (tight-turn words RLR/LRL); straight-line case (single S segment).

8.6 Pitfalls

  • Frame-transform error in Dubins/RS: forgetting to rotate into the start frame yields wrong words. Test against reference.
  • Wrong word selection: picking a non-minimal word. Enumerate all, pick min feasible; test exhaustively.
  • κ_max units: radius vs curvature confusion (R = 1/κ). Pin convention.
  • Hybrid A discretization too coarse*: misses narrow gaps or claims false collision; too fine explodes the closed set. Tune θ-bins + cell size.
  • Analytic-expansion frequency: too frequent wastes collision checks; too rare loses the speedup. Tune attempt interval.
  • Reverse-segment cost: not penalizing reversal yields jerky back-and-forth paths. Add reverse penalty.

8.7 Performance Concerns

Dubins/RS are closed-form (microseconds) but called millions of times in lattice/Hybrid A* — keep allocation-free. The Hybrid A* heuristic precompute (holonomic-with-obstacles Dijkstra) is a one-time grid cost; the non-holonomic heuristic uses a precomputed Dubins/RS lookup table. Closed-set hashing of (x,y,θ-bin) must be fast + deterministic (packed integer key). Analytic expansion collision-checks a full Dubins/RS shot — early-out.

8.8 Edge Cases

Goal heading opposite start at zero distance (U-turn, RLR/LRL); turning radius larger than free space (no feasible turn -> NoPath); reverse-only feasible (RS required, Dubins fails); θ exactly on a bin boundary (deterministic bin assignment).

8.9 Failure Analysis

A curvature-violating path (#7.3) cannot be tracked by the controller (#289) -> the robot deviates or stalls. Detection = post-hoc curvature check + conformance lengths. Blast radius = all non-holonomic plans. Recovery = reject primitive; fail to NoPath. Forensic = dump the violating segment's curvature profile.

Phase 9 — Trajectory smoothing + optimization (shortcutting, CHOMP-style gradient)

9.1 Objectives

Implement mp-opt: shortcutting (replace sub-paths with valid shorter connections) and CHOMP-style covariant gradient descent on an ESDF obstacle cost plus a smoothness term. Reduce length/jerk while preserving collision-freedom (#7.1).

9.2 Detailed Implementation Steps

  • Shortcutting: repeatedly pick two random (or all adjacent) waypoints; attempt a direct (straight or steering) connection; if motion_valid, replace the intervening sub-path; iterate until no improvement or budget. Partial shortcutting (interpolate a fraction) for non-holonomic paths. (P1, I1; P6)
  • CHOMP: represent the trajectory as discretized waypoints ξ; objective = smoothness (sum of squared accelerations, via a finite-difference matrix A) + obstacle cost (sum of ESDF-based cost weighted by velocity); covariant gradient update ξ ← ξ − (1/η)·A⁻¹·∇U; keep endpoints fixed; iterate to convergence or budget. (Ratliff et al. 2009; ADR-10)
  • Obstacle cost from mp-env::Esdf: cost(d) = high inside, decaying to 0 beyond a margin; gradient = −c'(d)·∇d (pushes away from obstacles). (Ratliff et al. 2009; P6, I1)
  • Collision safety: after each smoothing pass, re-validate the path at ε; reject steps that introduce collisions (line-search / reject-and-shrink).
  • Joint-space + workspace variants: CHOMP on joint trajectory using FK to map workspace ESDF gradients to joint gradients via Jacobian (manipulator). (Ratliff et al. 2009; P5, ADR-3)
  • Property tests: smoothed path collision-free (#7.1); cost (length/smoothness) ≤ input cost; endpoints unchanged.

9.3 Deliverable

mp-opt::{Shortcutter, ChompOptimizer}; mpctl smooth --method shortcut|chomp; before/after path length + smoothness reported and visualized.

9.4 Acceptance Criteria

  • Shortcutting reduces path length on maze_2d by a measurable margin (e.g. ≥ 15%) while staying collision-free.
  • CHOMP reduces a jerk/smoothness metric vs the raw path; final path collision-free (#7.1).
  • No smoothing pass ever increases collision count (rejected if it would).
  • Determinism: same seed + path -> same smoothed output (#7.5).

9.5 Conformance Fixtures

  • conformance/opt/shortcut_maze.json — raw path + expected length-reduction band + validity.
  • conformance/opt/chomp_clearance.json — path near an obstacle + expected increased clearance.
  • conformance/opt/chomp_arm.json — 7-DOF joint trajectory smoothing, self-collision-free.
  • Degenerate: already-optimal straight path (no change); path hugging an obstacle (CHOMP pushes out); infeasible smoothing (reject, return input).

9.6 Pitfalls

  • Shortcut through a thin obstacle: relies on motion_valid ε; a coarse ε tunnels. Mitigation: ε tied to obstacle scale (Phase 2).
  • CHOMP step too large: overshoots into obstacles. Mitigation: line-search / Armijo; reject-and-shrink; trust region.
  • ESDF gradient sign error: pushes into obstacles (Phase 3 sign bug). Detection: clearance decreases after CHOMP.
  • Endpoint drift: failing to pin start/goal moves them. Mitigation: fix boundary rows in the update.
  • Non-holonomic shortcutting: straight-line shortcut violates curvature (#7.3). Use steering connections, not straight lines, for car/drone paths.
  • Singular A matrix: finite-difference matrix ill-conditioned at short trajectories. Regularize.

9.7 Performance Concerns

CHOMP's per-iteration cost is dominated by ESDF queries (one per waypoint per iteration) — keep them allocation-free and cache-local (Phase 3). The A⁻¹ multiply is fixed-size per trajectory (precompute factorization). Shortcutting cost is dominated by motion_valid on candidate connections. Bound iterations; expose a time budget (anytime smoothing).

9.8 Edge Cases

Two-waypoint path (nothing to shortcut); trajectory shorter than the finite-difference stencil (skip CHOMP); ESDF undefined region (clamp); manipulator near a kinematic singularity (Jacobian ill-conditioned — regularize).

9.9 Failure Analysis

A smoothing pass that silently introduces a collision breaks #7.1 with high blast radius (the planner "found a path" that hits an obstacle). Detection = mandatory re-validation after every pass + conformance. Recovery = reject the pass, return the last valid path. Forensic = dump the pre/post path + the offending waypoint + ESDF slice.

9.10 Operational Notes

Emit shortcut_iterations, length_reduction_pct, chomp_iterations, min_clearance_before/after, smoothing_rejections. Budget + method in stats. Runbook for "smoothed path hits obstacle" (check ESDF sign, reduce step, tighten ε).

Phase 10 — Time parameterization (trapezoidal/S-curve velocity profiles, TOPP-lite, dynamic limits)

10.1 Objectives

Implement mp-time: convert a geometric path into a time-stamped Trajectory honoring velocity/acceleration (and optionally jerk) limits via trapezoidal and S-curve profiles, plus a TOPP-lite path-velocity optimizer. Constraints (#7.3) enforced.

10.2 Detailed Implementation Steps

  • Trapezoidal profile: per segment (or path arclength), accelerate at a_max to v_max, cruise, decelerate; handle short segments where v_max is never reached (triangular profile); compute timestamps + velocities + accelerations. (Lynch & Park 2017 Ch. 9; I3)
  • S-curve (jerk-limited): 7-phase profile (jerk up / const accel / jerk down / cruise / jerk down / const decel / jerk up); honors j_max; smoother for actuators. (Lynch & Park 2017 Ch. 9; I3, P13)
  • Multi-DOF synchronization: scale per-joint profiles to a common duration (slowest joint governs) so all joints start/stop together.
  • TOPP-lite: parameterize path by arclength s; compute the maximum-velocity profile v(s) subject to velocity + acceleration limits (forward-backward pass on the (s, ṡ) phase plane); a lightweight subset of TOPP-RA (no full reachability sets). (Pham & Stasse 2018; I3, ADR-3)
  • Dynamic limits: per-segment v_max/a_max may vary (e.g. tighter on high-curvature segments) — DynamicLimits carries per-DOF arrays.
  • Continuity: ensure velocity continuity at waypoints (zero or matched velocity); C¹ (trapezoidal) or C² (S-curve).
  • Property tests: |v| ≤ v_max, |a| ≤ a_max (and |jerk| ≤ j_max for S-curve) everywhere (#7.3); timestamps strictly increasing; endpoints at rest (or specified). (I3, P7; Lynch & Park 2017 Ch. 9)

10.3 Deliverable

mp-time::{TrapezoidalProfile, SCurveProfile, ToppLite}; mpctl time --profile trapezoidal|scurve|topp; velocity/acceleration profiles plotted; trajectory duration reported.

10.4 Acceptance Criteria

  • All profiles respect v/a (and jerk for S-curve) limits everywhere (#7.3; 0 violations across fixtures).
  • Trapezoidal handles triangular (short-segment) case correctly (no overshoot of v_max).
  • Multi-DOF trajectories synchronized (all DOF reach waypoints at the same time).
  • TOPP-lite yields a faster (≤ duration) trajectory than naive trapezoidal on a curvy path while respecting limits.

10.5 Conformance Fixtures

  • conformance/time/trapezoidal_triangular.json — short segment, expected triangular profile.
  • conformance/time/scurve_jerk.json — jerk-limited profile, |jerk| ≤ j_max checkpoints.
  • conformance/time/topp_curvy.json — curvy path + expected duration band, limit-respecting.
  • Degenerate: zero-length path (duration 0); single waypoint; v_max = 0 (invalid -> error); already at goal.

10.6 Pitfalls

  • Short-segment overshoot: applying full trapezoidal when the segment is too short to reach v_max overshoots. Mitigation: triangular fallback; test.
  • Multi-DOF desync: per-joint profiles with different durations cause uncoordinated motion. Mitigation: time-scale to slowest joint.
  • Jerk discontinuity: trapezoidal has step accelerations (infinite jerk) — fine for some actuators, not others. Document; offer S-curve.
  • TOPP phase-plane numerical issues: forward/backward pass instability near switching points. Mitigation: careful discretization + clamping.
  • Curvature-coupled limits ignored: cornering too fast violates lateral accel. Mitigation: per-segment a_max from curvature.

10.7 Performance Concerns

Time parameterization is O(path length) and cheap relative to planning; not on the hot path. TOPP-lite's forward-backward pass is O(n) in path samples. Keep allocation-free; precompute arclength. For real-time re-timing in the local loop, cache the profile and only re-time the changed suffix.

10.8 Edge Cases

Path with repeated waypoints (zero-length segment -> skip); non-monotone arclength (degenerate path); limits so tight the trajectory is extremely long (warn); jerk limit with too-short segment (cannot complete 7 phases -> degrade to S-curve sub-case).

10.9 Failure Analysis

A trajectory violating a/v limits (#7.3) cannot be tracked -> the controller saturates and the robot deviates. Detection = post-hoc limit check + conformance. Blast radius = every executed trajectory. Recovery = re-time with correct limits; clamp. Forensic = dump the (s, ṡ) profile + the violating sample.

10.10 Operational Notes

Emit trajectory_duration, max_velocity_used, max_accel_used, time_param_method. Limits recorded in stats. Runbook for "robot can't track trajectory" (check limits match the robot, switch to S-curve, enable curvature-coupled a_max).

Phase 11 — Local reactive planner (DWA) + replanning in dynamic environments + anytime

11.1 Objectives

Implement mp-local: the Dynamic Window Approach reactive planner running in a bounded ≤ 20 ms loop, plus the replanning trigger that bridges to the global planner when the trajectory is invalidated. The only real-time component (#7.7).

11.2 Detailed Implementation Steps

  • Dynamic window: from current (v, ω) and accel limits over Δt, compute the reachable velocity window; intersect with admissible velocities (those allowing a stop before the nearest obstacle). (Fox, Burgard, Thrun 1997; I7, P9)
  • Sampling: discretize the window into a grid of (v, ω) candidates (or joint-velocity candidates for arms).
  • Forward simulation: roll each candidate forward Δt (or a short horizon) to a predicted trajectory.
  • Scoring: weighted sum of (heading-to-goal, clearance-from-obstacles via ESDF/costmap, velocity/progress); pick the max-scoring admissible candidate; emit LocalCmd. (Fox, Burgard, Thrun 1997; ADR-10)
  • Bounded loop: fixed candidate count; pre-allocated buffers; soft-deadline check returns best-so-far before the budget (#7.7); no allocation in steady state. (P9, I7; ADR-12)
  • Replanning trigger: detect when the global trajectory is blocked (predicted collision) or stale (robot drifted / goal moved); raise ReplanReason; request a global replan (full or D* Lite incremental from Phase 4) on a worker thread; swap in the new trajectory via a lock-free single-slot channel. (P3, ADR-11; I7)
  • Anytime integration: while replanning, keep tracking the last safe trajectory or decelerate; never block the loop.
  • Property tests: emitted command admissible (can stop before nearest obstacle); loop never exceeds budget in steady state (#7.7); replan does not stall the loop.

11.3 Deliverable

mp-local::Dwa; mpctl local runs a closed-loop simulation tracking a global trajectory through a dynamic scenario with moving obstacles + replanning; loop timing histogram exported.

11.4 Acceptance Criteria

  • Loop tick p99 ≤ 20 ms @ ≥ 20 Hz on corridor_dynamic (#4, #7.7); 0 allocations in steady state (verified via allocator counter).
  • DWA reaches the goal without collision in the dynamic scenario (Monte-Carlo over seeds, success ≥ 95%).
  • Emitted commands always admissible (can stop before obstacle); 0 admissibility violations.
  • Replan latency within the dynamic-replan SLO; loop never blocks on replan.

11.5 Conformance Fixtures

  • conformance/local/corridor_dynamic.json — moving obstacles + expected goal-reach + collision-free.
  • conformance/local/admissibility.json — states where only braking is admissible.
  • conformance/local/replan_trigger.json — blocked trajectory -> replan requested + new trajectory accepted.
  • Degenerate: no admissible velocity (must brake/stop); goal reached (zero command); obstacle directly ahead (emergency stop).

11.6 Pitfalls

  • Local minimum trap: DWA stuck in a U-shaped obstacle (greedy heading score). Mitigation: replan globally when progress stalls; detect via low progress over a window.
  • Allocation in the hot loop: a Vec::push reallocates -> a tick overruns (#7.7). Mitigation: pre-allocate; allocator counter in tests.
  • Replan thrash: oscillating between two global plans every tick. Mitigation: hysteresis / cooldown on replan; commit to a plan for N ticks.
  • Stale trajectory tracking: tracking a trajectory after the robot drifted -> wrong commands. Mitigation: stale detection + replan.
  • Scoring-weight mis-tuning: too much heading weight -> ignores clearance (collisions); too much clearance -> never reaches goal. Tune + document.
  • Δt / horizon mismatch: forward-sim horizon shorter than stopping distance -> chooses inadmissible velocity. Mitigation: horizon ≥ stopping distance.

11.7 Performance Concerns

The hot loop budget (≤ 20 ms) governs candidate count × horizon steps × per-step ESDF/costmap query cost. Pre-allocate all buffers; keep ESDF queries cache-local (Phase 3); SIMD the candidate scoring. The replan runs off the hot thread; the lock-free channel must be wait-free on the read side. Measure per-tick p99 and tail latency explicitly.

11.8 Edge Cases

All candidates inadmissible (full stop); robot already at goal (zero command); sudden obstacle inside the dynamic window (emergency brake); replan returns NoPath (stop + alert); clock jitter in the loop (use a monotonic clock; skip-and-catch-up policy).

11.9 Failure Analysis

A loop overrun (#7.7) starves the controller (#289) -> the robot continues on a stale command and may collide. Detection = per-tick duration histogram + overrun counter + alert. Containment = emit a safe (braking) command on overrun. Recovery = reduce candidate count; investigate allocation/scoring. Forensic = flamegraph the slow tick + record the input state.

11.10 Operational Notes

Emit local_tick_us histogram, local_deadline_overruns, replan_requests, replan_reason, dwa_chosen_score, min_clearance. Loop runs on a dedicated thread under a real-time-ish scheduler (#185). Runbook for "robot oscillates / stuck" (replan thrash cooldown, retune weights). Deployment note: the local loop is the safety-critical path — it must fail safe (stop), never fail open.

Phase 12 — Benchmarks (OMPL.app-style scenarios), conformance, determinism, visualization

12.1 Objectives

Implement mp-bench: a benchmark harness over OMPL.app-style scenarios, the determinism harness, the anytime-curve recorder, differential testing vs OMPL, and visualization, with CI perf gates. Lock the production bar.

12.2 Detailed Implementation Steps

  • Scenario format: serde JSON describing map/robot/start/goal/planner/seed/budget; loader in mp-bench::scenario. (ADR-15, P14)
  • Benchmark runner: run each (scenario × planner × seed) M times; record success rate, path cost, planning time (p50/p95/p99), collision checks, nodes/expansions; aggregate to a report.
  • Determinism harness: run each scenario twice, byte-compare PlanResult (#7.5); fail on mismatch. (I5, P4; ADR-23)
  • Anytime harness: record best_cost vs time/samples for optimizing planners; assert non-increasing (#7.4); export curves. (I4, P3; ADR-22)
  • Differential testing: run the same SE(2)/SE(3) rigid-body problems through OMPL (via the tools/ompl_diff harness) and compare success + cost bands (not exact, since RNG differs — compare distributions/optimality gaps). (P2, P6; ADR-22)
  • Visualization: mpctl viz renders maps, costmaps, ESDF, trees/blueprints, paths, anytime curves to SVG/PNG (headless, CI-renderable).
  • CI perf gate (bench.yml): compare against committed baselines in benchmarks/results/; fail if regression beyond tolerance.
  • Soak: long-running planner over many seeds to catch rare nondeterminism / leaks.

12.3 Deliverable

mp-bench produces a full benchmark report across all planners + scenarios; mpctl bench runs it; determinism + anytime + differential checks gate CI; mpctl viz renders all artifacts.

12.4 Acceptance Criteria

  • All §4 targets met on their scenarios (success rates, planning times, loop budget) and encoded as gates.
  • Determinism: 0 mismatches across the full scenario set, 2 runs each (#7.5).
  • Anytime: 0 non-increasing-cost violations (#7.4).
  • Differential vs OMPL: success-rate and optimality-gap within documented tolerance on the rigid-body set.
  • Perf gate green against committed baselines; regressions fail CI.

12.5 Conformance Fixtures

  • benchmarks/scenarios/ — full suite (empty/random/narrow/maze 2-D, SE(3) apartment, 7-DOF arm shelf, parking lot, dynamic corridor).
  • benchmarks/results/baseline.json — committed baseline numbers (the gate).
  • conformance/differential/ompl_*.json — OMPL cross-check inputs/expected bands.
  • Regression: prior-release report archived; new report diffed.

12.6 Pitfalls

  • Benchmark variance: single-run timings are noisy. Mitigation: M runs + statistics (criterion); report p50/p95/p99, not single samples.
  • Nondeterminism slipping through: rare seed-dependent divergence. Mitigation: soak over many seeds; per-step RNG-draw logging for bisection.
  • Differential false alarms: OMPL uses a different RNG -> exact-cost compare fails. Mitigation: compare distributions/optimality gaps, not exact paths.
  • Stale baselines: hardware change shifts numbers. Mitigation: pin bench env (Docker, ADR 26); re-baseline deliberately with sign-off.
  • Viz nondeterminism: floating layout varies. Mitigation: fixed seeds + rounded coordinates for diffable SVG.

12.7 Performance Concerns

The benchmark harness itself must not perturb measurements (warm-up runs, isolated process, pinned CPU). ESDF/blueprint builds amortized across runs where valid. Report tail latency (p99) as the gate, since planning latency distributions are heavy-tailed.

12.8 Edge Cases

A planner that never succeeds on a scenario (record success=0, not a crash); a scenario with no solution (expected NoPath); extremely long anytime run (cap by time budget); OMPL unavailable in CI (skip differential with a recorded waiver, not a silent pass).

12.9 Failure Analysis

A perf regression or determinism break is caught here before release; the gate is the last line of defense. Detection = CI gate. Blast radius = blocked release (intended). Recovery = revert/fix the offending change. Forensic = the benchmark report diff + determinism mismatch log.

12.10 Operational Notes

Emit the full benchmark report as a CI artifact; publish anytime curves + flamegraphs to docs/performance/. The benchmark dashboard tracks success/cost/latency trends across releases. Re-baselining is a reviewed, logged event (BLUEPRINT_LOG.md).

Mental Models & First Principles

  1. MM1 — C-space is the only space where planning is tractable. Predicts: whether a planner can serve both a car and an arm without rewriting. Without it: you hard-code SE(2) into search logic, write a separate planner for every robot morphology, and collision logic leaks into the planner (violates P5). Applied: §8.1 / §11.1 / Phase 1 where StateSpace is the universal abstraction every planner is generic over.

  2. MM2 — Collision checking is a first-order bottleneck; everything else is second-order. Predicts: where 90%+ of planning CPU goes, and which optimizations yield linear speedup. Without it: you optimize the wrong layer (heuristic computation, kd-tree queries) while narrow-phase GJK still dominates; your planner is 10× slower than it needs to be (P1). Applied: §8.6 / Phase 2 (BVH early-out, batch broad phase) / Phase 7 (lazy near-set validation).

  3. MM3 — Probabilistic completeness is an asymptotic statement, not a convergence-rate guarantee. Predicts: why PRM fails on a narrow passage at n = 200 but succeeds at n = 5000; why raising n costs quadratically in edge checks. Without it: you declare the planner broken when it is merely under-sampled, or you over-provision n and blow memory/time budgets (P2, I1). Applied: §4 (success-rate targets with explicit n) / Phase 5 / Phase 6.

  4. MM4 — Asymptotic optimality requires a shrinking near-radius; fixed-k RRT is not optimal. Predicts: whether r_n = γ·(log n / n)^(1/d) is necessary and what γ must be for the given C-space dimension d. Without it: you ship RRT*-labeled code with a fixed k-nearest neighbor that converges to a suboptimal path and does not satisfy the Karaman & Frazzoli 2011 conditions (I4, P7). Applied: Phase 7 (near-radius decay, dimension-aware γ) / §7.4.

  5. MM5 — A signed distance field turns clearance into a differentiable cost; without the sign, gradient ascent pushes into, not away from, obstacles. Predicts: whether CHOMP's gradient step reduces or increases collision. Without it: an unsigned distance field has zero gradient inside obstacles, making the optimizer unable to escape; the smoothed path can be worse than the input (P6, I1). Applied: §8.5 / Phase 3 (ESDF sign convention + gradient direction) / Phase 9 (CHOMP obstacle cost).

  6. MM6 — Admissible heuristics are necessary, not sufficient, for A-optimal paths.* Predicts: when octile distance overestimates on 4-connected grids (inadmissible) vs 8-connected grids (tight admissible bound). Without it: you use octile on a 4-connected grid and produce suboptimal paths while believing them optimal; invariant §7.6 silently breaks (P8, I6). Applied: Phase 4 (heuristic-to-connectivity matching, Dijkstra ground-truth property test).

  7. MM7 — The dynamic window restricts to velocities that allow a safe stop; without the admissibility filter the local planner is a crash generator. Predicts: which (v, ω) pairs are reachable and stoppable given current accel limits and nearest obstacle distance. Without it: the DWA scores and selects velocities the robot cannot brake from before hitting an obstacle — the scoring objective wins over physical safety (P9, I7, I3). Applied: Phase 11 (admissibility filter before scoring) / §7.7.

  8. MM8 — Determinism is a protocol property, not an implementation detail; any thread-local entropy or unordered iteration breaks it globally. Predicts: which data structures and API patterns violate replay (HashMap iteration, thread_rng, wall-clock timestamps in search). Without it: bugs are irreproducible; differential tests flap; the CI gate has false negatives; the audit trail is broken (P4, I5). Applied: §3.3 (determinism boundary) / Phase 0 (ordered-float, BTreeMap) / Phase 12 (byte-compare harness).

  9. MM9 — Kinodynamic constraints must be satisfied by the steering function, not checked after the fact.   10. MM10 — Incremental replanning repairs only the changed subgraph; full replanning from scratch does not scale with environment dynamism. Predicts: when D* Lite's incremental-expansion count is sublinear in map size vs a fresh A* sweep. Without it: a dynamic environment with frequent small changes forces full A* replans that blow the local-loop budget, and the reactive planner starves (P3, I7). Applied: §8.7 / Phase 4 (D* Lite k_m + rhs logic) / Phase 11 (replan trigger selects D* Lite incremental vs full).

Back-of-Envelope Capacity Model

  1. Collision-check throughput ceiling (§4: ≥ 1e5 full-robot checks/s, single core). Budget per check: 1e9 cycles/s ÷ 1e5 = 10 000 ns = 10 µs per full-robot check. A GJK iteration costs ~50–200 ns; a 7-DOF robot has 7 link pairs after broad-phase culling to ~3; 3 GJK calls × 300 ns = 900 ns narrow-phase + BVH traversal ~500 ns ≈ 1.4 µs per check -> headroom exists. Design consequence: the 10 µs budget allows ~7 GJK calls per check; any link-count or mesh-complexity increase must be profiled against this ceiling (Phase 2, ADR-7).

  2. RRT sample budget for 5% optimality gap* (§4: cost within 5% of optimal after 1e4 samples). At 1e5 checks/s, 1e4 samples × (1 steer + ~5 near-set checks) = 6e4 collision checks → 0.6 s. With RRT* near-radius checks O(log n) ≈ 14 per sample at n = 1e4: 1e4 × 14 checks = 1.4e5 checks → 1.4 s on single core. Design consequence: the §4 1 s p50 arm budget (§4: "p50 ≤ 1 s, p99 ≤ 10 s") is tight; the near-set check batch must be aggressively early-outed and the kd-tree radius query must be O(log n) (Phase 7, ADR-8).

  3. A grid-search ceiling* (§4: p50 ≤ 50 ms on a 1000×1000 grid). 1e6 cells; a full Dijkstra expands all 1e6 cells; at ~50 ns per expansion (heap pop + 8-neighbor relaxation + visited check) = 50 ms. A* with octile heuristic on a typical free map expands ~10–20% of cells → 5–10 ms p50. Design consequence: the 50 ms budget is achieved by A* heuristic pruning alone; D* Lite incremental repairs only the changed subgraph (≪ 1e5 cells typically) → order-of-magnitude faster replanning (Phase 4).

  4. ESDF memory for a 1000×1000×1000 grid (§4: ≤ 512 MB for a tiled 1000³ ESDF). 1e9 cells × 4 B (f32 distance) = 4 GB dense, and +12 B/cell gradient (f32×3) = 16 GB with gradient → both far exceed the cap, so a monolithic 3-D ESDF is impossible. Tiling at 128³ = 2.1e6 cells/tile → 8.4 MB dist + 25 MB gradient = 33 MB/tile; covering 1000³ needs ~512 tiles (~17 GB if all resident). Lazy load/evict keeps the working set ≤ 512 MB ÷ 33 MB ≈ 15 tiles resident (≈ 61 tiles if gradient is recomputed on demand and only dist is cached). Design consequence: ESDF must be tiled with on-demand load/evict and an LRU resident set; monolithic 3-D allocation is forbidden (Phase 3, ADR-10).

  5. Local-loop candidate-scoring budget (§4: ≤ 20 ms tick, ≥ 20 Hz). At 20 ms budget: assume 100 (v, ω) candidates × 5 forward-sim steps × 1 ESDF query/step = 500 ESDF queries per tick. At 200 ns/ESDF query (trilinear interpolation, cache-hot) = 100 µs for scoring; remaining ~19.9 ms for window computation, replan check, channel read. Design consequence: up to ~2000 candidates fit in the 20 ms budget at 200 ns/query; any allocation that evicts ESDF pages from cache pushes query cost to ~2 µs and the budget to 4 ms for scoring, leaving no headroom (Phase 11, ADR-12).

  6. PRM blueprint storage ceiling (§4: PRM default 2000–5000 nodes). At n = 5000 nodes, k = 15 neighbors per node: 5000 × 15 × (4 B index + 8 B cost) = 900 KB adjacency list. kd-tree over 5000 × 3-D states: ~200 KB. Total blueprint ≈ 1.1 MB — negligible. Design consequence: blueprint memory is not the bottleneck; the bottleneck is edge-validation cost at build time: 5000 × 15 edges × 10 µs/check = 750 ms build for eager PRM → lazy PRM defers to query time, making multi-query cost ~1 edge validation per query-path edge (Phase 5).

  7. ESDF build time (§4: 1000×1000 grid built in < 100 ms, §3.4 acceptance). Felzenszwalb-Huttenlocher EDT is O(n) per dimension (2 passes/axis). 2-D 1000²: 2 axes × 1e6 cells × ~5 ns/op = 10 ms. Dense 3-D 1000³: 3 axes × 1e9 × 5 ns = 15 s — confirms a monolithic 3-D build is infeasible. A 128³ tile = 3 axes × 2.1e6 × 5 ns ≈ 31 ms/tile, so tiles build independently and incrementally within budget. Design consequence: 2-D ESDF meets the 100 ms target trivially; 3-D requires tiled incremental build, only dirty tiles recomputed on map edits (Phase 3, ADR-10).

  8. Dubins/RS call frequency in Hybrid A* (§4 mobile 2-D p99 ≤ 500 ms; §8.4 parking p50 ≤ 500 ms acceptance). Hybrid A* at a 500 ms budget, ~50 µs/expansion (collision + steering): 500 ms ÷ 50 µs = 10 000 expansions. Dubins closed-form evaluation: ~1 µs for all 6 words; analytic expansion attempt every 10 expansions → 1000 attempts × 1 µs = 1 ms overhead. Design consequence: Dubins/RS must be allocation-free and sub-microsecond to stay negligible relative to collision cost; the analytic-expansion frequency is a tuning knob, not a bottleneck (Phase 8, ADR-7).

  9. Trajectory waypoint density for TOPP-lite (§4: global planning budget includes time parameterization). A 10 m path at ε = 0.01 m = 1000 waypoints. TOPP-lite forward-backward pass: 2 × 1000 operations at ~10 ns/op = 20 µs. Design consequence: time parameterization is never the planning bottleneck at typical path lengths; even 1e5 waypoints → 2 ms, well within budget. The allocation cost of the waypoint buffer matters more than compute (Phase 10).

  10. Memory ceiling for the local loop (§4: ≤ 16 MB pre-allocated). 100 candidates × 5 steps × TrajPoint (t + state + vel + acc ≈ 80 B for SE(2)) = 40 KB scoring buffer. kd-tree for local map: not needed (ESDF lookup). Pre-allocated local costmap window (e.g. 50×50 cells at 1 B): 2.5 KB. Total working set ≪ 16 MB; budget is dominated by a cached ESDF tile slice. Design consequence: zero allocation in steady state is achievable; the 16 MB cap is sized to fit the local ESDF tile slice (a 2-D window of the active 3-D tile) plus all scoring buffers in the local loop's pre-allocated arena (Phase 11, ADR-12).

Alternative Architectures (Roads Not Taken)

Alt-A: Optimization-First Trajectory Planning (Direct Collocation / CHOMP as Primary Planner)

PlanRequest
    |
    v
  Initial guess (straight-line or RRT seed)
    |
    v
+---------------------------------------------------+
|  Direct Collocation / CHOMP SQP                   |
|  minimize: sum(smoothness) + sum(obstacle cost)   |
|  subject to: kinematic constraints, joint limits  |

+---------------------------------------------------+
    |         (iterate until convergence)
    v
  Trajectory (time-stamped, limit-respecting)
    |
    v

Wins when: the C-space is low-dimensional (≤ 6 DOF), an initial feasible guess is always available (e.g. from a previous plan or a straight-line heuristic), and the application demands dynamically optimal, smooth trajectories with certified constraint satisfaction rather than probabilistic completeness. Also wins when contact constraints or torque limits must enter the primary objective.

Embodied by: Drake (Toyota Research/MIT) — MultibodyPlant + direct transcription via MathematicalProgram; uses SNOPT/IPOPT/OSQP for the NLP inner loop.

Why rejected here: requires a feasible initial trajectory to converge (cannot guarantee finding one in obstacle-cluttered environments from scratch); local optimality means the solver can get stuck near the initial guess, missing the global path entirely in narrow-passage problems; computation time for a full SQP pass is O(N³) in waypoint count — incompatible with the §4 arm p99 ≤ 10 s target on complex scenes. CHOMP-style gradient descent is retained in mp-opt as a post-processor (Phase 9) where a feasible path already exists.

Alt-B: Lattice / Search-First Planning with Precomputed Motion Primitives

            |
            v
+------------------------------------------+
|  State lattice graph                      |
|  nodes: (x, y, θ, v) discretized         |

+------------------------------------------+
            |

            |

  Path = sequence of primitives

Wins when: the robot's feasible action set is finite and enumerable (fixed steering angles, fixed gear states, fixed velocities), real-time replanning with hard suboptimality bounds is required (ε-suboptimal at any interruption), and the environment is known enough that offline primitive precomputation is worthwhile. Also wins when anytime behavior with a monotone cost guarantee is the primary SLO.

Embodied by: SBPL (Likhachev) — ARA*/AD* search over a precomputed motion primitive graph; used in the DARPA Urban Challenge and Ackermann-steered robot navigation.

Why rejected here: primitive precomputation requires enumerating the robot's discrete control set — infeasible for a continuous joint-space manipulator or a drone with unconstrained SE(3) controls; lattice discretization errors mean paths must be re-smoothed anyway (Phase 9); the library targets multiple robot morphologies (§1.4) where no single primitive set applies. Hybrid A* (Phase 8) captures the lattice-inspired continuous-state search without committing to a fully discrete primitive graph.

Alt-C: Purely Reactive Potential-Field / DWA-Only Stack (No Global Planner)

PlanRequest

    |

  No global path; track gradient field in real time

Wins when: the environment is open and convex (few local minima), replanning latency must be strictly bounded by a single tick (no global search at all), and path quality (optimality, length) is irrelevant compared to real-time obstacle avoidance — e.g. close-range collision avoidance in a cluttered warehouse where the robot simply needs to not hit things and a human guides the high-level goal.

Embodied by: Classic ROS base_local_planner DWA-only mode; early Braitenberg vehicle reactive architectures; potential-field navigators in early NASA planetary rovers.

Why rejected here: potential fields trap the robot in local minima (U-shaped obstacles, narrow corridors) with no escape mechanism; the stack specification explicitly requires planning feasible paths in narrow_passage_2d and maze_2d scenarios (§4) where pure reactive methods provably fail; the global-plan + local-tracking architecture (§3.1) is retained, and DWA lives only in mp-local as the reactive tracker, not as the primary planner.
