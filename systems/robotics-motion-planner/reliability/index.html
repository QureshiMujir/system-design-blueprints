7. System Invariants

Format per invariant: statement / why / enforced / detection / telemetry / recovery / debugging.

7.1 I1 — Returned path is collision-free at resolution ε

  • Statement: every edge of a returned path, discretized at ε, contains no in-collision state.
  • Why: the robot will physically follow it; a collision is a safety failure (Principle 6).
  • Enforced: final validate_path pass in mp-planner before constructing PlanResult::Solved.
  • Detection: re-validation in mp-bench; property test asserts on every generated solution.
  • Telemetry: path_validation_failures counter (must stay 0); logs offending edge + state.
  • Recovery: discard path, return NoPath or retry with finer ε; never emit the path.
  • Debugging: dump the failing motion to a fixture; replay narrow-phase on the exact pair.

7.2 I2 — Path connects start to goal within tolerance

  • Statement: first state ≈ start, last state ≈ goal (within goal_tol in the metric).
  • Why: a path to the wrong place is useless.
  • Enforced: planners terminate only on goal-region membership; checked again at packaging.
  • Detection: assertion in PlanResult constructor; differential test vs OMPL endpoints.
  • Telemetry: goal_distance_residual gauge.
  • Recovery: if residual > tol, continue planning or report NoPath.
  • Debugging: inspect goal-region predicate + tolerance config.

7.3 I3 — Kinodynamic / non-holonomic constraints satisfied

  • Statement: curvature ≤ κ_max, |v| ≤ v_max, |a| ≤ a_max on every edge for constrained spaces.
  • Why: a car cannot turn sharper than κ_max; violating it is unexecutable (#289 cannot track it).
  • Enforced: steering functions (mp-steer) only emit feasible primitives; mp-time clamps to limits.
  • Detection: post-hoc constraint check in validation; property test on Dubins/RS outputs.
  • Telemetry: constraint_violations{type} counter.
  • Recovery: reject the primitive; choose a feasible alternative; fail to NoPath if none.
  • Debugging: log the violating segment's curvature/velocity profile.

7.4 I4 — RRT* cost is monotonically non-increasing (anytime)

  • Statement: across iterations, the best solution cost never increases.
  • Why: anytime contract — interrupt at any time and the latest is the best.
  • Enforced: rewiring only accepts strictly-improving parents; best-cost tracked monotonically.
  • Detection: assertion each iteration; anytime-curve fixture must be non-increasing.
  • Telemetry: best_cost time series (the anytime curve).
  • Recovery: revert a rewire that would increase cost (bug guard).
  • Debugging: dump the rewiring decision (old vs new parent cost).

7.5 I5 — Deterministic given seed

  • Statement: identical (RobotModel, Environment, start, goal, cfg, seed) -> identical PlanResult bytes.
  • Why: replay, regression, differential testing, audit.
  • Enforced: single seeded RNG; sorted iteration; fixed float mode; no wall-clock in logic.
  • Detection: determinism harness runs each scenario twice, byte-compares.
  • Telemetry: determinism_mismatch counter (must be 0).
  • Recovery: none at runtime; it is a build-blocking CI failure.
  • Debugging: bisect with a per-step RNG draw log to find the first divergence.

7.6 I6 — Heuristic admissibility (A* optimality)

  • Statement: A* heuristic h(n) ≤ true cost-to-go for all n (unless weighted-A* with declared ε).
  • Why: admissibility is necessary for A* optimality on the discretization.
  • Enforced: heuristic functions documented + unit-tested as lower bounds on representative graphs.
  • Detection: property test compares h against Dijkstra ground-truth cost-to-go.
  • Telemetry: heuristic_inflation (max observed h/true ratio; ≤ 1.0 admissible).
  • Recovery: fall back to Dijkstra (h=0) if a heuristic is flagged inadmissible.
  • Debugging: log nodes where h exceeded true cost.

7.7 I7 — Local loop meets its deadline

  • Statement: each mp-local tick completes within the configured budget (≤ 20 ms).
  • Why: the controller (#289) consumes commands at a fixed rate; an overrun starves it.
  • Enforced: bounded sample count; pre-allocated buffers; soft-deadline check returns best-so-far.
  • Detection: per-tick duration histogram; alert on p99 > budget.
  • Telemetry: local_tick_us histogram; local_deadline_overruns counter.
  • Recovery: emit last safe command (e.g. decelerate/stop) on overrun; raise replan.
  • Debugging: flamegraph the slow tick; check for allocation or unbounded scoring.

7.8 I8 — Tree/graph contains no invalid edges

  • Statement: every edge stored in a tree/blueprint has been (or will be, for lazy) validated; no in-collision edge contributes to a returned path.
  • Why: an invalid edge can leak into the solution and break #7.1.
  • Enforced: eager checkers validate on insert; lazy checkers validate on extraction and remove invalid edges.
  • Detection: invariant sweep over the structure in tests; differential vs OMPL.
  • Telemetry: lazy_edge_invalidations counter.
  • Recovery: remove invalid edge, re-search; never return it.
  • Debugging: replay the edge through narrow phase.

7.9 I9 — Metric obeys triangle inequality where required

  • Statement: distance(a,c) ≤ distance(a,b) + distance(b,c) for metrics used by RRT*/PRM.
  • Why: rewiring and near-neighbor correctness depend on it.
  • Enforced: metric implementations documented; property test on random triples.
  • Telemetry: metric_triangle_violations (must be 0).
  • Recovery: forbid non-metric pseudo-distances in optimizing planners (type/feature gate).
  • Debugging: log violating triple + metric weights.

7.10 I10 — Every resource cap fails graceful, never OOM

  • Statement: exceeding any configured cap (samples, tree nodes, expansions, ESDF bytes) returns PlanError::ResourceExhausted, never an abort/OOM (Principle 10).
  • Why: untrusted maps/models must not crash or exhaust the host (§ Threat Model).
  • Enforced: caps checked before each growth step / allocation in mp-sampling/mp-graph/mp-env; allocation bounded by cap.
  • Detection: fuzz the parsers/planners with adversarial inputs; assert no OOM, only typed errors.
  • Telemetry: resource_exhausted_total{what}, tree_nodes, esdf_bytes gauges.
  • Recovery: return the capped/typed result; caller may raise the cap deliberately.
  • Debugging: log which cap tripped, the configured limit, and the input hash.

7.11 I11 — Start and goal validated at the boundary before search

  • Statement: start and goal are bounds-checked and collision-checked before any planner loop runs; invalid -> typed error, not a hang (Principle 11).
  • Why: a planner that loops forever from an in-collision start is a liveness failure.
  • Enforced: validate(start)/validate(goal) + in_collision gate in mp-planner before solve.
  • Detection: integration tests inject in-collision / out-of-bounds endpoints; expect StartInCollision/GoalOutOfBounds.
  • Telemetry: boundary_validation_rejections{kind} counter.
  • Recovery: none at runtime (input error); surface the typed error to the caller.
  • Debugging: dump the offending endpoint + bounds + collision verdict.

7.12 I12 — Zero heap allocation in the local-loop steady state

  • Statement: after warm-up, an mp-local tick performs no heap allocation; all buffers are pre-allocated to the configured caps (Principle 9).
  • Why: a steady-state allocation can stall a tick past its deadline (I7) and starve the controller (#289).
  • Enforced: pre-allocated arenas/buffers; allocation forbidden on the tick path; checked by an allocator counter in tests.
  • Detection: dhat/custom allocator counter asserts 0 allocations across N steady-state ticks.
  • Telemetry: local_loop_allocations counter (must be 0 in steady state).
  • Recovery: if an allocation is detected in CI, the build is blocked; at runtime the soft-deadline guard (I7) returns the last safe command.
  • Debugging: attribute the allocation via allocator backtrace; bisect the offending tick input.
