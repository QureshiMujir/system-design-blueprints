Mental Models & First Principles

The compressed insights an expert holds; each predicts behavior, names the bug class you write without it, and the section/phase where this blueprint applies it.

  • MM1 — The optimizer is two stacked optimization problems, not one. Plan cost (which equivalent graph) is minimized first; schedule makespan (when/where on resources) second. Predicts: the cheapest plan need not have the shortest makespan. Bug class without it: folding cost and schedule into one objective, so a makespan regression looks like a cost-model bug and is "fixed" in the wrong stage. Applied: P2 (logical/physical/schedule separation), Phase 6, Phase 7.
  • MM2 — A fingerprint is one identity serving three masters. The BLAKE3 structural hash is the CSE key, the cache key, and the replay key. Predicts: any drift/collision in canonicalization simultaneously breaks dedup, cache, and replay. Bug class: keying the cache on a hash that omits an output-determining input → silent wrong reuse. Applied: Phase 2, Phase 8, Phase 11; I5, I13.
  • MM3 — Greedy rewriting is hostage to phase ordering; saturation escapes it. An e-graph represents all rewrite orders at once, so extraction is unbiased by application order. Predicts: greedy can get stuck below the optimum that a different rule order would reach. Bug class: chasing a "missing optimization" that is really an ordering artifact. Applied: Phase 4 (greedy), Phase 6 (saturation); Tate 2009.
  • MM4 — Pruning is only as sound as the monotonicity you can prove. DP/B&B may prune a partial plan only on cost dimensions where a subplan's cost ≤ any containing plan's. Predicts: pruning on a non-monotone dim (wall under caching) silently discards the optimum. Bug class: a "fast but occasionally worse" optimizer. Applied: Phase 5, Phase 6; I8, P6.
  • MM5 — Determinism is a property you engineer, not one you get. Hash-map iteration, wall clock, thread order, and raw FP compares each inject nondeterminism that survives until a plan-diff goes noisy or a replay diverges. Predicts: where reproducibility breaks first. Bug class: irreproducible production incidents. Applied: Phase 11; P3, I15.
  • MM6 — Every search must have a budget, and the budget must degrade, not crash. A bounded search turns a pathological DAG into a flagged-suboptimal result rather than an OOM/hang. Predicts: the DOS surface of the planner. Bug class: an unbounded e-graph or memo table that takes down the process. Applied: Phase 6, Phase 9, Phase 13; P4, I18.
  • MM7 — The type system is the trust boundary. ValidatedDag is constructible only via validate(); downstream code assumes acyclicity by type, not by convention. Predicts: an unvalidated graph reaching the optimizer loops forever. Bug class: re-validation scattered everywhere, or its absence. Applied: Phase 1; P14, I1.
  • MM8 — Content addressing turns "recompute" into "reuse" for free. The same hash that dedupes a subgraph keys the result cache, so incremental re-planning is just diffing fingerprints and reusing the clean prefix. Predicts: re-plan cost scales with change size, not graph size. Bug class: re-optimizing the whole graph on a one-node edit. Applied: Phase 2, Phase 8; P5.
  • MM9 — Crash-only beats repair. Append-only logs + atomic-rename cache + truncate-torn-tail recovery mean kill -9 is always safe and there is never a repair tool to get wrong. Predicts: which failure leaves state corrupt (none, if the discipline holds). Bug class: an in-place mutation that a mid-write crash corrupts. Applied: Phase 8, Phase 11; P12, I14.

Glossary · 49 terms · site-wide glossary

DAG
Directed acyclic graph of tasks (nodes) and typed data edges; the workflow's logical form.
Task
A unit of computation; an opaque op with typed in/out ports and a resource profile.
Port
A typed input/output slot on a node; edges connect a producer port to a consumer port.
Artifact
The typed value flowing on an edge; single-producer, content-addressable by digest.
IR (IR0–IR4)
Intermediate representations: parsed (0), validated (1), canonical (2), optimized (3), scheduled (4).
ValidatedDag
A newtype produced only by validate(); the type-enforced trust boundary.
Canonicalization
Deterministic rewriting to stable IDs, sorted edges, and structural fingerprints.
Fingerprint (Fp)
BLAKE3 structural hash of a node/subgraph; identity for CSE, cache, and replay.
Topological order
A linear order respecting all edges; exists iff the graph is acyclic.
Critical path
The longest-duration path to a sink; sets scheduling priority and the makespan lower bound.
Dominator
Node D dominates N if every path to N passes through D; bounds region-scoped rewrites.
Reachability
Whether one node's output can influence another (transitive closure over edges).
Liveness
The interval an artifact must be retained (producer to last consumer); drives memory and DCE.
Rewrite rule
A validity-preserving transformation: pattern + guard + builder + proof tag.
Pattern matcher
Finds subgraphs matching a rule's pattern, binding pattern variables to nodes.
Operator fusion
Combining adjacent pure single-consumer tasks into one (fewer scheduling units).
DCE
Dead-task elimination: removing pure tasks with no live path to a sink.
CSE
Common-subgraph elimination: merging structurally-identical pure subgraphs (by fingerprint).
Constant folding
Replacing a pure task over constants with the precomputed constant result.
Predicate pushdown
Moving a filter toward the source to shrink intermediate artifacts.
Cost model
Estimates per-node/per-plan cost (cpu/wall/mem/io) from statistics; yields a scalar objective.
Cardinality / selectivity
Estimated output size / fraction-passing; flows through map/reduce/filter.
Monotonicity
A cost dimension where a subplan's cost ≤ any containing plan's; required for sound pruning.
Objective
The weighted scalar minimized by search (default wall-dominant).
Memo table
Best-known plan per subgraph fingerprint; the DP/Cascades group abstraction.
Dynamic programming (search)
Bottom-up optimal selection over enumerated per-node alternatives (System R).
Branch-and-bound
Search pruning partial plans whose cost lower bound exceeds the best-so-far.
E-graph
Equivalence graph: e-classes of equivalent subgraphs, e-nodes with e-class children.
Equivalence saturation
Applying rewrites non-destructively to a fix-point/budget, avoiding phase-ordering.
Extraction
Selecting the min-cost representative per e-class to materialize a concrete plan.
List scheduling
Greedy schedule popping highest-priority (critical-path) ready tasks onto resources.
HEFT
Heterogeneous-earliest-finish-time list scheduling for heterogeneous resources.
Bin-packing
Placing tasks onto resource pools to fit capacities and minimize makespan.
Makespan
The wall-clock completion time of the whole schedule (max task end).
Resource pool
A capacity bucket (cpu/mem/io/concurrency) tasks are placed onto.
Backpressure
Bounding outstanding work via tokens so a slow consumer can't cause unbounded buffering.
Token
A unit of admission credit; submit requires one; bounded outstanding (I12).
Content addressing
Naming data by the hash of its content; powers cache keys and dedup.
Memoization
Reusing a stored result for a repeated computation, keyed by fingerprint.
Incremental re-planning
Re-optimizing only the changed (dirty) region of a workflow, reusing the rest.
Dirty set
Changed nodes plus their transitive successors; the region needing re-planning.
ExecPlan
The serialized physical plan handed to the executor; versioned, round-trippable.
Executor
The external component that runs tasks; we define the interface, not the runtime.
Replay log
Append-only crash-consistent record of plan inputs + chosen plan for reproduction.
Determinism
Same inputs (+ seed) → byte-identical plan; prerequisite for diff/replay.
Sharded planning
Partitioning a large DAG across planner shards with a stitching coordinator.
Boundary artifact
A cut edge between shards; its size/cost is exchanged during distributed planning.
Suboptimal flag
Marks a plan returned after a budget breach (correct but not proven optimal).
Proof obligation
The semantic-equivalence guarantee a rewrite rule must satisfy (gated by differential tests).
