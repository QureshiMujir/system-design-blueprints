Failure Modes & Recovery

Taxonomy by subsystem. Each: symptoms, root causes, detection, automatic recovery, manual recovery, operator actions, forensic artifacts, long-term mitigation.

F1 — Frontend/validation failure

  • Symptoms: workflows rejected; parser panic (bug).
  • Root causes: malformed input; grammar/recovery bug.
  • Detection: typed errors; parse.panic (should be 0); fuzzing.
  • Automatic: typed Result; request-boundary catch_unwind → INVALID_ARGUMENT.
  • Manual: inspect diagnostic; fix the .wdl or the grammar.
  • Operator: check validate.errors{kind}; common kinds indicate a workflow-author issue vs a bug.
  • Forensic: input hash → replay; diagnostic with span.
  • Long-term: fuzz corpus seed for any panic.

F2 — Incorrect optimization (semantic divergence)

  • Symptoms: optimized plan produces different results than unoptimized (the worst failure).
  • Root causes: buggy rewrite rule, bad CSE/cache (omitted fingerprint input), wrong analysis (dominators/reachability), unsound cost pruning.
  • Detection: differential testing (CI + production sampling); rewrite.semantic_div, cache.key_result_skew, search.equiv_violation.
  • Automatic: per-rule kill switch (config); global cache-disable; mode=greedy fallback (no e-graph).
  • Manual: bisect with replay log (re-run captured plans with the rule/cache off); delta-debug the failing DAG.
  • Operator: flip the rule/cache flag; alarm fires on any divergence.
  • Forensic: rule trace, e-graph dump, minimized DAG, the two result digests.
  • Long-term: minimized DAG → permanent differential fixture; tighten the rule's proof obligation.

F3 — Suboptimal plan (correct but slow)

  • Symptoms: plan executes correctly but with poor makespan/cost; SLO miss on execution side.
  • Root causes: budget breach (search stopped early), mis-calibrated cost model, bad partition (sharded), wrong critical path.
  • Detection: search.suboptimal, cost.estimate_error, sched.makespan_ratio, dist.cut_ratio.
  • Automatic: none (correctness preserved); flagged suboptimal=true.
  • Manual: raise budgets, recalibrate stats, re-partition; compare via plan-diff.
  • Operator: watch suboptimal rate and estimate-error; tune budgets/weights (config).
  • Forensic: stats_snapshot, search stats, the chosen-vs-alternatives in explain.
  • Long-term: feed estimate errors to recalibration; the deferred learned model (§5.5 Required Reading).

F4 — Scheduling infeasibility/violation

  • Symptoms: plan rejected (Infeasible) or executor reports input-missing/oversubscription.
  • Root causes: task larger than any pool; scheduler precedence/capacity bug; stale pool config.
  • Detection: post-schedule validation (I9/I10, mandatory); executor errors.
  • Automatic: validation fails the plan before emission (fail closed).
  • Manual: fix pool config (sync with executor); fix the workflow's resource request.
  • Operator: check sched.infeasible, sched.capacity_violation.
  • Forensic: schedule table, the violating pair, pool config.
  • Long-term: feasibility pre-check; pool-config drift alert.

F5 — Backpressure failure / OOM

  • Symptoms: planner/service memory climbs unbounded; OOM kill.
  • Root causes: token leak, unbounded planning pool, e-graph budget not enforced.
  • Detection: exec.tokens_outstanding, svc.queue_depth, RSS alerts, mem.budget_exceeded.
  • Automatic: hard budget abort (Principle 4); token gate (I12); LB routes around a dead instance.
  • Manual: restart the instance; tune budgets/pool size.
  • Operator: scale out; lower max-in-flight.
  • Forensic: token ledger, heap profile, the offending DAG.
  • Long-term: RAII token guards; budget guards in every loop; slow-executor alert.

F6 — Persistence corruption / loss

  • Symptoms: cache returns corrupt/missing; replay log torn; cache/log unreadable.
  • Root causes: crash mid-write, disk failure, bit rot.
  • Detection: CRC/digest verify on read; replay.torn_tail, cache.corrupt.
  • Automatic: truncate torn tail (log); treat corrupt cache entry as miss (recompute); atomic rename prevents torn cache files.
  • Manual: restore log+blobs from backup; rebuild cache by recompute.
  • Operator: run restore-test; check storage health.
  • Forensic: the corrupt segment/entry, CRC mismatch logs.
  • Long-term: scrub job (periodic digest verification); the cache is regenerable so loss costs recompute, not correctness.

F7 — Determinism/replay divergence

  • Symptoms: replay produces a different plan; plan-diff noisy.
  • Root causes: hidden nondeterminism (hash iteration, wall clock, FP), rule-set drift, incomplete snapshot.
  • Detection: replay-audit job; determinism tests; replay.divergence{stage}.
  • Automatic: none (plans still correct); divergence flagged.
  • Manual: bisect to the divergent stage; fix the nondeterminism source.
  • Operator: monitor replay.audit_pass_ratio.
  • Forensic: the diverging stage, both plan dumps, the record.
  • Long-term: ban plan-affecting HashMap iteration (lint); the audit job is the standing guard.

F8 — Distributed coordination failure

  • Symptoms: large-DAG plan times out; shard crash; boundary oscillation.
  • Root causes: coordinator crash, shard crash, partition imbalance, non-converging boundary estimates.
  • Detection: heartbeats, dist.shard_crash, dist.boundary_rounds at cap, dist.coordination_fraction.
  • Automatic: shard reassignment (idempotent re-plan); coordinator restart re-partitions from content-addressed DAG.
  • Manual: reduce shard count; improve partition; cap rounds.
  • Operator: scale shards; watch coordination fraction.
  • Forensic: per-shard spans, boundary-round logs, partition sizes.
  • Long-term: hierarchical coordinator if it bottlenecks; damped boundary estimates.

F9 — Service availability

  • Symptoms: requests fail/time out; instance down.
  • Root causes: OOM, crash, overload, deploy gone wrong.
  • Detection: health checks, error-rate/latency SLO alerts.
  • Automatic: LB removes unhealthy instances; backpressure sheds load; stateless restart.
  • Manual: rollback deploy; scale out.
  • Operator: incident runbook; canary check.
  • Forensic: instance logs, the in-flight request set (by id).
  • Long-term: capacity planning; canary + rolling upgrade discipline.

F10 — Cache / incremental staleness

  • Symptoms: a re-plan reuses an outdated result or schedule though an input changed; results are uncorrupted but stale (distinct from F2's rule bug and F6's corruption).
  • Root causes: a too-narrow dirty set (a transitively-affected node not re-planned), a fingerprint that omits an output-determining input, or a cache entry served after its inputs changed (Phase 8 §8.6).
  • Detection: differential of incremental vs full re-plan (must match), incremental.divergence, cache.key_result_skew (I13); production differential sampling.
  • Automatic: dirty set = changed nodes ∪ all reachable successors (never narrower); pure-only caching; global cache-disable flag.
  • Manual: invalidate the offending key/namespace; widen the fingerprint to cover the missed input; recompute.
  • Operator: watch incremental.reused_ratio vs expected; flip cache-disable on suspicion.
  • Forensic: the dirty set, the key + both results, the producing plans (replay log).
  • Long-term: make incremental-vs-full equivalence a standing property test (Phase 8 §8.4); add the missed input shape to the differential corpus.
