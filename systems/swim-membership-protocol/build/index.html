⬜ Phase 0 — Repo Skeleton, Core Types, Conflict Resolution

Objectives

Lay down the module, the membership state (Member, MembershipList, ring), and the conflict-resolution function (§8.3) — the correctness kernel — with no networking yet.

Deliverable

A membership list that correctly resolves any sequence of alive/suspect/dead/leave updates to the same converged state regardless of order (modulo precedence) — verified in-memory.

Acceptance
  • Every precedence-table cell (§8.3) has a passing test.
  • Applying a set of updates in any permutation yields the same final state (order-independence property).
  • Self-suspect/self-dead triggers RefuteSelf with a strictly higher incarnation (I1/P5).
  • Ring visits every member once before repeating (I8 coverage test).
Fixtures

resolve/alive-beats-lower-inc, resolve/suspect-beats-alive-equal-inc, resolve/dead-terminal, resolve/self-refute, resolve/order-independence, ring/full-coverage.

Pitfalls
  • Wrong precedence at equal incarnation (Suspect must beat Alive; Dead beats both) → flapping or missed deaths. Table-drive + exhaustively test.
  • Letting a peer advance our own incarnation → I1 breach, identity chaos. Only RefuteSelf advances selfInc.
  • Ring with replacement → some node never probed for long → unbounded detection time. Use a permutation (I8).
  • Mutating the list without the lock → torn view. All mutations through Merge under the lock (I13).

⬜ Phase 1 — Transport + Codec (UDP/TCP, Bounded Datagrams)

Objectives

A pluggable Transport (real UDP/TCP + a simulated one for tests) and a compact codec that packs messages + piggyback updates under the MTU (I6).

Deliverable

Two processes exchange encoded messages over UDP and a TCP stream; datagrams never exceed MTU; the simulated transport drives the same code in-memory.

Acceptance
  • Round-trip encode/decode for every message type + piggyback.
  • No datagram exceeds the configured MTU (I6 guard test); leftover piggyback deferred, not fragmented.
  • Codec fuzz survives 5 min (no panic/UB on malformed datagrams).
  • Simulated transport is byte-identical to real for the same inputs.
Fixtures

codec/roundtrip-all-types, codec/piggyback-mtu-budget, codec/leftover-deferred, codec/malformed-reject, transport/sim-equiv-real.

Pitfalls
  • Relying on IP fragmentation → one lost fragment drops the whole probe + its piggyback. Stay under MTU (P8/I6).
  • Unbounded piggyback packing → oversize datagram. Budget by remaining bytes.
  • Codec panic on malformed input → remote DoS (a crafted datagram crashes the daemon). Total decode + fuzz.
  • Endianness / version drift in the wire format → interop breakage. Fix byte order + version the format.

⬜ Phase 2 — Failure Detector: Direct Ping/Ack + Protocol Period

Objectives

The core failure-detector loop: every period T′, probe one round-robin target; on ack it's alive, on timeout escalate (Phase 3). Constant per-node load (P1).

Deliverable

A node probes peers once per period and marks a non-responding peer as a candidate for suspicion (full suspicion in Phase 4); ack traffic is one ping + one ack per period.

Acceptance
  • Per-node UDP load is constant per period regardless of N (measured in sim: 1 ping + 1 ack, plus piggyback) (P1).
  • Every member is probed once per ring cycle (I8).
  • A crashed node (sim: stops acking) is detected as non-responsive within ~1 period of being targeted.
  • Period uses monotonic time; no wall-clock dependence (P3).
Fixtures

fd/constant-load, fd/ring-coverage, fd/detect-nonresponsive, fd/ack-matching, fd/monotonic-period.

Pitfalls
  • Probing all peers per period → O(N) load, defeats SWIM. Exactly one target/period (P1).
  • Ack/seq mismatch → false timeouts. Match acks to pings by seq; expire correctly.
  • Wall-clock period → skew/NTP-step breaks timing. Monotonic clock (P3/ADR-28).
  • Blocking the period loop on a slow probe → cascading delays. Probe asynchronously; the period ticks independently.

⬜ Phase 3 — Indirect Probing (ping-req via k Relays)

Objectives

The SWIM completeness mechanism: when a direct probe times out, ask k relays to probe the target, distinguishing "target dead" from "the direct path is lossy." Reduces false positives without per-node load growth.

Deliverable

A target reachable via some path stays Alive even if the direct probe was lost; only a target unreachable directly and via all k relays proceeds to suspicion.

Acceptance
  • Sim with selective loss on the direct A→C path (but B→C, D→C fine): C is not suspected (indirect ack saves it).
  • Sim with C truly crashed: direct + all indirect probes fail ⇒ C suspected.
  • Per-node load still bounded: + up to k ping-reqs only on the (rarer) direct-timeout path.
  • Differential vs memberlist on the same loss scenario (same suspicion outcome).
Fixtures

indirect/lossy-direct-path-saved, indirect/true-crash-suspected, indirect/k-relays-load, indirect/relay-forwards-ack, indirect/vs-memberlist.

Pitfalls
  • k too small → false positives under loss; too large → load spikes on timeout. Tune (default 3).
  • Relay pings target with relay's own identity confusion → ack routed wrong. Carry the original requester; relay forwards.
  • Not bounding indirect within the period → detection latency drifts. Budget direct + indirect within T′.
  • Choosing the suspected/self as a relay → wasted probe. Exclude target + self.

⬜ Phase 4 — Suspicion Subprotocol + Incarnation Refutation

Objectives

Turn detection into safe state changes: Alive→Suspect on probe failure, Suspect→Dead on timeout, and self-refutation via incarnation numbers (§8.5, P4/P5).

Deliverable

The full failure-decision pipeline: transient loss → Suspect → refuted back to Alive; genuine crash → Suspect → Dead everywhere; a falsely-suspected live node refutes itself within a period.

Acceptance
  • I3: a node reaches Dead only via timeout or explicit Leave/Confirm, never one failed probe.
  • I4 (sim): a crashed node is marked Dead by every live node within bounded periods.
  • I5 (sim): a transiently-lossy live node is never permanently Dead (self-refute heals it).
  • I9: suspicion timers fire once and are cancelled on refute/leave (no timer leaks).
Fixtures

suspect/transient-then-refute, suspect/crash-to-dead, suspect/self-refute-fast, suspect/timeout-scales-logn, suspect/timer-no-leak, suspect/no-direct-to-dead.

Pitfalls
  • Suspicion timeout too short → false positives under load (a busy node can't refute in time). Scale with log N + Lifeguard (Phase 7).
  • Not cancelling the timer on refute → a refuted node later wrongly declared Dead (I9 breach). Cancel atomically with the state change.
  • Refuting with an equal (not higher) incarnation → the rumor isn't overridden (precedence: Alive needs inc > Suspect's). Bump strictly above.
  • Removing a Dead node before the update disseminates → peers re-learn it as Alive (resurrection). Retire after dissemination window.

⬜ Phase 5 — Infection-Style Dissemination (Piggyback Gossip)

Objectives

Spread membership updates epidemically by piggybacking them on probe traffic, retransmitting each λ·log N times freshest-first, achieving O(log N) convergence with bounded bandwidth (P6/I7).

Deliverable

A single membership change (join/suspect/dead/leave) reaches the whole cluster in O(log N) periods without any standalone flood; bandwidth per change is bounded.

Acceptance
  • Sim: an update converges to all N nodes within O(log N) periods (measured curve).
  • I7: no update transmitted more than λ·log(N+1) times.
  • Bandwidth per change is bounded and independent of how the change occurred.
  • Freshest-first ordering verified (a newer update overtakes an older queued one).
Fixtures

gossip/converge-logn, gossip/retransmit-cap, gossip/freshest-first, gossip/piggyback-only, gossip/bandwidth-bounded.

Pitfalls
  • Unbounded retransmission → bandwidth blowup + stale news lingering. Cap at λ·log N (I7).
  • FIFO instead of freshest-first → fresh critical news (a death) stuck behind stale updates. Order by recency.
  • Dissemination only on probe traffic → slow convergence in idle clusters. Add the periodic gossip tick.
  • Re-queuing an update on every reception → never retires, infinite gossip. Count transmissions, not receptions.

⬜ Phase 6 — Anti-Entropy (TCP Push-Pull Full-State Sync)

Objectives

Backstop lossy gossip with periodic full-state reconciliation: a node opens TCP to a random peer, both exchange entire membership lists, and reconcile by incarnation — guaranteeing eventual convergence (P7/I10).

Deliverable

Any update lost by gossip is swept in within one anti-entropy interval; two nodes that diverged (e.g. across a brief partition) reconverge on the next sync.

Acceptance
  • Sim: drop all gossip for an update; it still converges within one anti-entropy interval (I4 via backstop).
  • I10: syncing two identical states changes nothing (idempotent).
  • Diverged states (post-partition) reconcile to the incarnation-wise newest per node.
  • Push-pull handles an N=1000 list over TCP without datagram limits.
Fixtures

antientropy/sweeps-lost-update, antientropy/idempotent, antientropy/post-partition-reconcile, antientropy/large-list-tcp, antientropy/on-join-bootstrap.

Pitfalls
  • Anti-entropy too frequent → O(N) TCP syncs dominate; too rare → slow convergence backstop. Tune interval.
  • Non-idempotent merge → sync oscillation. Merge must be a pure function of incarnations (I10).
  • Syncing only push (not pull) → one-directional, the peer doesn't learn our updates. Always bidirectional.
  • Blocking the protocol on a slow TCP sync → period jitter. Run anti-entropy in its own goroutine.

⬜ Phase 7 — Membership Lifecycle: Join, Leave, Lifeguard

Objectives

Complete the lifecycle: join via seed nodes (bootstrap a view), graceful Leave (no suspicion cycle), and the Lifeguard accuracy extensions (local health multiplier, adaptive timeouts, buddy system).

Deliverable

A node joins an existing cluster and gets a full view within a few periods; a node leaving disappears cleanly without a suspicion cycle; an overloaded node stops generating false positives (LHM dilates its judgments).

Acceptance
  • Join: a new node has a near-complete view within a few periods (push-pull + gossip).
  • I12: a graceful Leave never triggers a Suspect state on peers.
  • I11: a node with high missed-ack-to-self raises LHM and dilates timers (measured); LHM clamped.
  • Sim: under one-sided overload, the overloaded node's false-positive generation drops vs Lifeguard-off.
Fixtures

join/seed-bootstrap, join/view-complete-fast, leave/no-suspect-cycle, lifeguard/lhm-raises-on-misses, lifeguard/adaptive-timeout, lifeguard/buddy-fast-refute, lifeguard/fewer-false-positives.

Pitfalls
  • Join without push-pull → slow, partial initial view. Always TCP-sync with seeds on join.
  • Leave that relies on detection → wasted detection+suspicion latency + a false-positive-looking event. Explicit Leave broadcast (P13).
  • LHM unclamped → runaway dilation (a node stops detecting anything). Clamp [0,max].
  • LHM raised by peer failures (not self) → blames the wrong side. Raise only on signals about our own health (missed acks to us, nacks).
  • Buddy list stale → suspicions routed to dead neighbors. Refresh from the live set.

⬜ Phase 8 — Wire Hardening: Security, Compression, Labels

Objectives

Make the protocol safe on a real network: authenticated (and optionally encrypted) datagrams via a keyring, compression for large syncs, and message labels to prevent cross-cluster contamination.

Deliverable

A cluster that ignores forged/foreign/unauthenticated datagrams and resists trivial spoofing; large syncs are compressed; two clusters on one LAN stay separate.

Acceptance
  • A datagram with a bad/missing HMAC is dropped (auth test).
  • Encrypted mode round-trips; plaintext rejected when encryption required.
  • A foreign-label message is dropped (no cross-cluster merge).
  • Compression reduces large push-pull size measurably with no semantic change.
Fixtures

security/hmac-reject-forged, security/aead-roundtrip, security/keyring-multi-key, security/label-mismatch-drop, security/compression-roundtrip, security/replay-bounded.

Pitfalls
  • No datagram auth → any host can declare any node Dead (spoofed suspicion/dead). HMAC every message (Threat T1).
  • Single key, no ring → re-keying requires full cluster downtime. Keyring with multiple valid keys.
  • Compressing then forgetting to bound decompressed size → decompression bomb DoS. Cap decompressed bytes.
  • No cluster label → a stray node from cluster B poisons cluster A's membership. Label + drop mismatches.

⬜ Phase 9 — Observability, Convergence Measurement, Simulation Harness

Objectives

Make liveness fully observable and the protocol testable at scale: metrics + events for every transition, a convergence/detection measurement harness, and the deterministic network simulator that all earlier phases lean on.

Deliverable

Dashboards + a simulator that reproduces any membership scenario deterministically and measures convergence/detection/false-positive quantitatively.

Acceptance
  • Every state transition emits a metric + event (coverage audit).
  • Sim reproduces a scenario bit-identically under a fixed seed (I14).
  • Measured convergence is O(log N) and detection time is size-independent (matches the SWIM analysis) on the scenario suite.
  • False-positive rate under modeled loss (sim/false-positive-rate fixture, §4) stays ≤1% at 10% packet loss with indirect probing + Lifeguard on, versus an order-of-magnitude higher rate with both off (M3).
Fixtures

sim/deterministic-replay, sim/convergence-logn-curve, sim/detection-size-independent, sim/false-positive-rate, sim/partition-heal, sim/mass-failure.

Pitfalls
  • Non-deterministic sim → unreproducible test failures. Seed all randomness (I14).
  • High-cardinality metrics (per-peer labels) → Prometheus blowup. Aggregate; per-state counts, not per-node.
  • Measuring convergence with wall-clock → flaky. Measure in protocol periods (logical).
  • Simulator that diverges from real transport behavior → green sim, broken prod. Keep the sim a faithful Transport (Phase 1 equivalence test).

⬜ Phase 10 — Conformance, Interop, and Scale Validation

Objectives

Lock correctness with a conformance suite, best-effort wire-interop against the reference (memberlist), and scale validation in simulation; produce the conformance report that gates Done.

Deliverable

make sim + make conformance green; documented convergence/detection/load curves matching the SWIM analysis; interop demonstrated on core messages.

Acceptance
  • All conformance buckets (resolve, fd, indirect, suspicion, gossip, anti-entropy, lifecycle, security) Pass.
  • Per-node load constant across N=100/500/1000 (P1 evidence).
  • Convergence scales as O(log N); detection time size-independent.
  • I4/I5 hold under partition-heal and mass-failure chaos.
  • Core-message interop with memberlist succeeds.
Fixtures

conf/all-buckets-pass, scale/constant-load-100-500-1000, scale/convergence-logn, chaos/partition-heal-completeness, chaos/mass-failure, interop/memberlist-core-messages.

Pitfalls
  • Validating only small clusters → scaling bugs hide. Run to ~1k in sim.
  • Interop drift → claiming memberlist compatibility without testing it. Capture real datagrams.
  • Flaky chaos tests (timing) → measure in logical periods, assert convergence not fixed sleeps.
  • Declaring Done on phase-0 label → the owner's bar is the full runnable protocol; ensure the core algorithm runs end-to-end (no stubs on the detection/suspicion/dissemination path).

⬜ Phase 11 — WAN / Multi-Datacenter Gossip Tiers

Objectives

Extend single-LAN SWIM to spanning datacenters: a fast LAN tier per DC plus a slow WAN tier connecting DCs, with latency-aware timing and probe selection. Fulfils the WAN multi-DC deferral (this phase; see the Deferred Features Register).

Deliverable

A cluster spanning ≥2 DCs where intra-DC failure detection stays fast and accurate while cross-DC membership converges over the slower, lossier WAN without false-positive DC evictions.

Acceptance
  • Intra-DC detection/convergence unchanged from single-LAN targets (M1/M2/M6 hold per DC).
  • A transient WAN partition does not falsely mark a remote DC's nodes Dead (heals on reconnect via WAN anti-entropy).
  • WAN bandwidth bounded (only gateway/DC-level state crosses, not full per-node lists).
  • Vivaldi coordinates reduce cross-DC false positives vs latency-blind timing (sim comparison).
Fixtures

wan/two-dc-converge, wan/transient-partition-no-evict, wan/bandwidth-bounded, wan/vivaldi-fewer-fp, wan/relaxed-suspicion.

Pitfalls
  • Using LAN timing on WAN links → high-latency links look like failures → DC-wide false positives. Relaxed per-tier timing.
  • Gossiping full per-node lists across DCs → WAN bandwidth blowup. Cross only DC/gateway-level state.
  • One WAN member per DC (SPOF) → losing it isolates the DC at the WAN tier. ≥2 WAN members per DC.
  • Vivaldi coordinate drift → bad latency estimates → wrong timeouts. Clamp + periodically re-anchor coordinates.

⬜ Phase 12 — Serf-Style User Events and Queries

Objectives

Layer an application event bus on the membership substrate: best-effort broadcast user events and request/response queries over the same gossip, ordered + deduped by a Lamport clock. Fulfils the Serf-style events deferral (this phase; see the Deferred Features Register).

Deliverable

Applications can broadcast events and run cluster-wide queries over the existing gossip — no new transport — with ordering, dedup, and bounded fanout.

Acceptance
  • A broadcast event reaches all live nodes (O(log N) periods) and is delivered exactly once per node (dedup) under no-loss; best-effort under loss.
  • Queries collect responses from live nodes within the timeout; late responses dropped.
  • Lamport ordering is monotonic; out-of-order/duplicate events filtered.
  • Event/query payloads never exceed MTU (I6); fanout bounded (I7).
Fixtures

events/broadcast-reaches-all, events/dedup-once, events/lamport-order, query/collect-responses, query/timeout-drops-late, events/payload-mtu-bound.

Pitfalls
  • Confusing Lamport time (events) with incarnation (liveness) → ordering/refutation bugs. Keep the two clocks separate and distinctly purposed.
  • No dedup window → an event delivered many times as it re-infects. Track recent Lamport times per name.
  • Unbounded event payloads → fragmentation (I6 breach). Cap payload; large blobs go out-of-band (app's job).
  • Treating events as reliable → app assumes delivery that loss can break. Document best-effort (P9).
