4. System Constraints

Dimension Phase 0 target Notes
Per-node message load O(1) per protocol period, independent of N the core scalability claim: ~ (1 ping + 1 ack) + k·(ping-req) on failure
Protocol period T′ ~1 s (configurable) one probe target per period
Direct probe timeout < T′ (e.g. 0.5·RTT-based) sub-period
Indirect relays k 3 (configurable) completeness vs load
Suspicion timeout ~ (suspicion_mult · log(N+1)) · T′ scales with size for accuracy
Dissemination retransmits λ·log(N+1), λ≈3–4 per update before retirement
Convergence latency O(log N) periods to full infection epidemic spread
Detection time (expected) ~ T′·(1/(1−e^-1)) for first failed probe + suspicion bounded, size-independent for detection itself
UDP datagram size ≤ path MTU (≈1400 B safe) no fragmentation
Memberlist memory O(N) entries × small record ~ tens of bytes/node + meta
False-positive rate ≤ 1% under ≤10% packet loss with indirect probing (k=3) + Lifeguard on (target; M3 gate) accuracy knob
Anti-entropy interval ~ 30 s (configurable) TCP full sync backstop
Join time ≤ a few periods to a usable view; full state via TCP sync on join fast usable + eventual complete
Clock dependence none (logical incarnations, not timestamps) partition/skew resilient
CPU < 1% of one core steady-state per node (≈2 small datagrams/s encode+decode) not a bottleneck
Scale (Phase 0) validated to ~1k nodes in simulation 10k+ later

The defining property: per-node load is constant in N (a node probes one target per period regardless of cluster size). Detection load does not grow; only state memory (O(N)) and convergence latency (O(log N)) do.
