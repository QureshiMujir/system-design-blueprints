278 — SMT Solver from Scratch

Goal: Implement, from scratch in Rust, a lazy DPLL(T) SMT solver — an SMT-LIB 2.6 front end over a hash-consed, sort-checked Term DAG, a Tseitin encoder driving a reused project-277 CDCL SAT core, the online theory-solver protocol (theory propagation, conflict explanations), theory solvers for EUF (congruence closure with explanations), linear real/integer arithmetic (exact-rational Simplex + branch-and-bound), and fixed-width bit-vectors (bit-blasting), Nelson-Oppen combination, model generation (get-value), and unsat cores. It reports sat/unsat/unknown. It is the theory layer atop the #277 SAT engine — not a model checker (#279) or a higher-order theorem prover (#280).

1. Goal

Goal: Build, from scratch in Rust, a sound lazy DPLL(T) SMT solver over EUF + LIA/LRA + fixed-width bit-vectors, combined by Nelson-Oppen, behind an SMT-LIB 2.6 front end — emitting sat+model / unsat+core / unknown.

1.1 Precise engineering definition

A decision procedure for the quantifier-free fragments of first-order logic modulo a fixed set of background theories. Pipeline:

Stage Crate Function
Parse SMT-LIB 2.6 script, maintain command/assertion stack smt-parse parse_script, CommandContext
Hash-cons typed Term DAG, sort-check smt-types TermBank.intern
Tseitin-encode Boolean skeleton, drive CDCL smt-sat tseitin, SatCore, AtomMap
Orchestrate DPLL(T) + Nelson-Oppen combination smt-core check_sat, TheoryManager
Decide T-consistency per theory smt-theory CongruenceClosure, Simplex, BitBlaster
Build model, evaluate get-value, extract unsat core smt-model ModelBuilder, evaluate, UnsatCore
  • Lazy SMT: the SAT core decides truth assignments to theory atoms (abstracted as BoolVars); after each unit-prop fixpoint the relevant theory solver checks assigned theory literals for T-consistency. T-conflict → add negated conflict clause (theory lemma) + backjump. T-propagation → theory-implied atom fed back to SAT core as implied literal.
  • Sound by construction: exact BigRational / BigInt arithmetic everywhere — never floating point. Bit-vectors via eager bit-blasting to the same SAT core.
  • Result contract: CheckResult::{Sat, Unsat, Unknown}; Sat→get-model/get-value; Unsat→get-unsat-core; Unknown only for PhaseDeferred features.

1.2 Supported logics

QF_UF, QF_LRA, QF_LIA, QF_BV, QF_UFLIA, QF_AUFLIA (subset) — via Logic enum. Unsupported logic → ParseError::UnsupportedLogic / Logic::Unsupported.

2. Why Build This

2.1 The unique knowledge this teaches

SMT is the deepest glue layer in automated reasoning: a SAT core deciding Boolean structure wired to exact-arithmetic decision procedures over a shared, hash-consed term DAG. Building one from scratch forces mastery of six interlocking subsystems:

Subsystem The hard idea you cannot fake Where (phase / crate)
Lazy SMT / DPLL(T) SAT decides truth of theory atoms; theory checks T-consistency only on assigned literals; T-conflict → theory lemma → backjump; T-propagation → implied literal fed back to SAT Ph4 / smt-core
SAT↔theory protocol the online assert_lit/check/explain/push/pop contract synchronized to the SAT trail Ph4 / TheorySolver
Congruence closure + explanations union-find of terms + congruence rule over the e-graph, with a proof forest that reconstructs why a==b (NCA on the proof tree) Ph5 / CongruenceClosure
Exact-arithmetic Simplex general-form tableau with per-variable Bound, pivot to feasibility, minimal infeasible-bound conflict set — BigRational, never f64 Ph6 / Simplex
Bit-blasting width-w BvTerm → w BoolVars; structural ripple/adder/comparator clause encodings feeding the shared SatCore Ph8 / BitBlaster
Theory combination Nelson-Oppen purification + interface-equality exchange between EUF and arith; non-convex LIA needs case splits Ph9 / TheoryManager

The non-obvious lesson: the value is in the protocol and the explanations, not the individual procedures. Most engineers can write congruence closure; few can make it produce a minimal reason set that the SAT core can turn into a sound learned clause.

2.2 Why SMT matters — historically and architecturally

  • Workhorse oracle. SMT is the engine under program verification (ESC/Java, Dafny, Boogie, Viper), symbolic execution (KLEE, angr, SAGE), bounded model checking, type-system constraint solving (Liquid/refinement types), compiler superoptimization, and scheduling/planning.
  • Lineage. Z3 (de Moura & Bjørner), cvc5/CVC4 (Barrett et al), Yices2 (Dutertre), MathSAT — all are DPLL(T) lazy solvers. The framework is Nieuwenhuis–Oliveras–Tinelli 2006 (DPLL(T)); the arithmetic core is Dutertre–de Moura 2006; combination is Nelson–Oppen 1979.
  • Architectural payload. SMT is where a propositional engine meets first-order theories. Understanding that seam — atom abstraction, the equality-sharing bus, convexity — is understanding how the last 25 years of formal-methods tooling is actually wired.

2.6 What Mastery Looks Like

A developer has mastered this project when they can:

  • Ph4 — DPLL(T) loop: Explain exactly why check(final_check=false) can omit a conflict that check(final_check=true) must catch, and trace the push/pop depth invariant after a backjump from level 5 to level 2.
  • Ph5 — EUF explanations: Given a proof forest, manually execute explain_eq(a,d) (NCA walk) for a chain a—b—c—d produced by congruence steps, naming each asserted equality each edge represents.
  • Ph6 — Exact Simplex: Derive the infeasible-row conflict set for a three-constraint system and show why replacing BigRational with f64 on any pivot can flip feasible↔infeasible.
  • Ph7 — B&B/Gomory: State why the Gomory cut derived from a fractional basic row is valid for all integer feasibles, and trace depth-capped behavior on a formula where no branch closes under budget.
  • Ph8 — Bit-blasting: Trace the clause encoding for a 4-bit bvadd ripple-carry, identifying exactly which clauses fire for inputs 7 + 1 mod 16 = 8.
  • Ph9 — Nelson-Oppen: Purify f(x + 1) = y (mixed EUF + arith), enumerate the interface variables, and trace two rounds of the equality-sharing bus.
  • Ph13 — Differential testing: Given a DISAGREE from Z3/cvc5, reproduce the minimal .smt2 repro using delta-debugging and identify which theory's explain produced the unsound clause.

3.2 Box Responsibilities

smt-types — Term DAG + Sorts. Owns TermBank (arena + HashMap<TermKind, TermRef>), Term, TermRef(u32), Sort, SortRef(u32), Symbol(u32) interner, Value, Logic. Key invariant: hash-consing => structural equality == handle equality. Referenced by: every phase.

smt-parse — Parser + CommandContext. Owns SExpr, Command, Parser, CommandContext, ParseError. Key invariant: the trust boundary — all size/nesting/sort checks happen here. Referenced by: Phase 1 (§13); Phase 12 (§24) push/pop scoping.

smt-sat — Tseitin + reused SatCore + AtomMap. SatCore is the reused project-277 CDCL engine (NOT re-derived). tseitin() introduces a fresh BoolVar per non-atomic subformula; theory atoms become leaf BoolVars in AtomMap. Key invariant: AtomMap is a bijection. Referenced by: Phase 3 (§15); Phase 4 (§16)'s DPLL(T) loop.

smt-core — DPLL(T) loop + TheoryManager. Owns TheorySolver (trait), TheoryConflict, TheoryPropagation, TheoryManager, CheckResult, check_sat(). Key invariant: TheorySolver push/pop depth tracks the SAT trail exactly. Referenced by: Phase 4 (§16); all theory phases.

Nelson-Oppen equality bus (in smt-core / TheoryManager). Purifies mixed terms; theories exchange entailed interface equalities to fixpoint. Key invariant: share only equalities over interface variables; UNSAT if any theory rejects. Referenced by: Phase 9 (§21).

smt-theory::euf — CongruenceClosure. Union-find with proof forest + e-graph of App nodes; merge, are_equal, explain_eq. Key invariant: classes closed under congruence; explanations are minimal asserted-literal subsets. Referenced by: Phase 5 (§17); feeds N-O bus (§21).

smt-theory::arith — Simplex + branch-and-bound. General-form Tableau over BigRational, basic/nonbasic vars, Bound per var. Exact BigRational — never floating point (soundness). LIA = LRA + B&B. Referenced by: Phases 6–7 (§18–19).

smt-theory::bv — BitBlaster. Maps each width-w BvTerm bit to a BoolVar; lowers each BvOp to structural clauses emitted into the shared SatCore (eager bit-blasting). Referenced by: Phase 8 (§20).

smt-model — ModelBuilder + evaluate + UnsatCore. On Sat: per-theory model contributions combined; evaluate(t, model) -> Value. On Unsat: UnsatCore extracts the subset of named assertions in the final conflict. Referenced by: Phases 10–11 (§22–23).

4.2 Time / decidability

  • Worst case unbounded. QF fragments are NP-hard+ (QF_BV NP-complete; QF_LIA NP-complete). With quantifiers SMT is undecidable → e-matching stub may not terminate.
  • Resource budget (--timeout, --max-mem, --max-conflicts) → on exhaustion check_sat returns CheckResult::Unknown, never a wrong sat/unsat.
  • Budget checked at safe points: SAT decision boundary, theory check entry, branch-and-bound node, Nelson-Oppen round.

4.3 Arithmetic soundness

LRA/LIA use BigRational exact arithmetic — never f32/f64. Floating point would make Simplex feasibility/conflict unsound. Cost: rational num/den grow with pivot chains; bounded by problem, not unbounded precision drift. GCD-normalize after pivots, never approximate.

4.4 Adversarial input limits (DoS surface = untrusted SMT-LIB text at smt-parse)

Limit Default cap Enforcement
Max paren nesting 10_000 Parser depth counter → ParseError::UnbalancedParens
Max term DAG nesting 100_000 iterative (no recursive drop/print) → bounded stack
Max asserted formulas 10_000_000 CommandContext counter
Max BvVec width 4_096 sort check → ParseError::SortMismatch/reject
Max symbol length / count 1 MB / 10M interner cap
  • Term construction is iterative (explicit worklists) — no native recursion on attacker-controlled depth ⇒ no stack overflow.

4.5 Concurrency, persistence, platform

  • Single-threaded core. Theory solvers share the SAT trail synchronously; no locks, no async.
  • No persistence at runtime. stdin/stdout REPL only; optional proof/core export to file (Phase 11).
  • Zero global init. Every arena/interner/solver lives in CommandContext; constructing it is the only startup cost.

4.6 Recovery & availability

  • Parsing never panics on malformed/hostile input → every failure is a typed ParseError.
  • Solving honors the budget → exhaustion yields Unknown, not a panic and not a crash.
  • No unwrap/panic! on input-derived paths; debug_assert! only for internal invariants.
  • Availability guarantee: adversarial SMT-LIB can never crash, hang unboundedly, or corrupt the host — it can only time out (Unknown) or return a typed error.

4.7 Determinism

Same input + same flags ⇒ identical output and identical model/core. No wall-clock or RNG in the search. Timeout-induced Unknown is the only nondeterministic outcome.

6. Design Principles

6.1 Soundness over speed

Never report Sat for an unsatisfiable formula, never Unsat for a satisfiable one. Unknown is the only legal escape hatch. Every TheorySolver::check and assert_lit must be refutation-sound. Violation: arith check skips a feasibility pivot under time pressure → reports Sat on an infeasible bound set → the model fails its own evaluate check.

6.2 Exact arithmetic only

Simplex tableau, Bound, all coefficients use BigRational. No f64 anywhere in the theory path. Floats lose soundness: a pivot that computes 1/3 in f64 rounds; a tableau row that should be =0 reads 1e-16. Tradeoff: BigRational is ~10–50× slower than i64; mitigate with small-value fast paths that are still exact, never with floats.

6.3 The Term DAG is canonical

TermBank.intern hash-conses every TermKind; equal structure → identical TermRef(u32). Structural equality is TermRef equality. Violation: arith builds an atom term without interning → two TermRefs denote the same atom → AtomMap maps them to two BoolVars → SAT decides them independently → unsound or nonterminating.

6.4 Theories explain themselves

Every TheoryConflict.core and every TheoryPropagation must come with a reason set via explain/explain_eq: the minimal asserted literals entailing the result. If the reason set is wrong, CDCL learns falsehoods. Violation: CC returns explain_eq(a,b)=[] for a derived equality → the learned lemma is empty → SAT core treats the formula as trivially unsat.

6.5 The SAT core is reused, not reinvented

smt-sat::SatCore is the project-277 CDCL engine used as-is. This project's novelty is the theory layer (smt-core, smt-theory), not CDCL internals. Violation: hand-rolling a second conflict analyzer in smt-core → divergent learned-clause semantics → wrong backjump levels → unsound results or loops.

6.6 Backtrack in lockstep

Theory push/pop must mirror the SAT trail's decision levels exactly. Theory state (CC union-find, Simplex tableau/bounds, BitBlaster) is trailed/undoable per level. Violation: Simplex forgets to undo a Bound on pop → a stale bound survives backjump → phantom conflict → Unsat on a sat formula.

6.7 Lazy by default, eager where it wins

Default strategy is lazy DPLL(T): theories see only the literals the SAT core assigns. Exception: bit-vectors are eager — BitBlaster lowers all BvOp to SAT clauses up front. Violation: lazily wrapping BV as a theory with weak propagation → exponential SAT decisions, timeout → Unknown where eager would solve in ms.

6.8 Combination is equality-sharing (Nelson-Oppen)

Disjoint, stably-infinite theories combine via purification + entailed interface equality exchange until fixpoint. Non-convex theories (LIA) force case splits. Violation: arith fails to propagate x = y to EUF → a UF congruence f(x)≠f(y) stays satisfiable → Sat on an unsat QF_UFLIA formula.

6.9 Bounded resources → unknown

The solver must never OOM or hang. On exceeding a configured budget, check_sat returns CheckResult::Unknown cleanly. Violation: unbounded LIA branch-and-bound → infinite branching → hang, no answer.

6.10 Models are checkable

A Sat result's ModelBuilder must satisfy every asserted formula under evaluate. The model checker is run in debug/CI builds as a self-test. Violation: EUF emits a UF graph inconsistent with an asserted disequality → evaluate yields false → fuzzer flags an invalid model.

6.11 Unsat cores are subsets of asserted formulas

UnsatCore(Vec<TermRef>) is a subset of the named asserted formulas that participated in the final SAT+theory conflict. Violation: a core that drops a needed assertion → re-checking the core returns Sat → core is unsound and useless.

6.12 Determinism on a fixed seed

Same input + options + seed ⇒ byte-identical output and decision trace. No HashMap iteration order, wall-clock, or thread scheduling may affect results. Violation: pending-merge queue drains in HashMap order → CC explanation set varies run-to-run → a fuzz failure won't reproduce.

6.13 Single-threaded synchronous core

The DPLL(T) loop and all TheorySolvers share one trail synchronously on one thread. Violation: spawning a theory check on another thread mutating the shared trail → data race / inconsistent partial model → nondeterministic unsoundness.

6.14 Fail closed on untrusted input

smt-parse treats SMT-LIB text and unbounded term size/nesting as hostile: every error is a typed ParseError, never a panic, never UB. Violation: unchecked deep nesting → stack overflow panic on adversarial input → DoS.

6.15 One canonical representation per fact

Each datum lives in exactly one place: truth of a theory atom lives in SatCore+AtomMap, not duplicated in a theory; sort of a term lives in Term.sort; the assertion stack lives in CommandContext. Violation: a theory caches a literal's polarity, the SAT core flips it on backjump → theory acts on a stale truth value → unsound conflict.

7. System Invariants

Invariants are global truths the solver maintains across every command, decision, propagation, and backtrack. Violations are bugs, not error conditions. All checkers gated behind cfg(debug_assertions) or --invariant-check to keep the hot loop clean.

7.1 INV-CANON — hash-consing canonicity

field value
statement bank.intern(k1)==bank.intern(k2) iff k1 structurally-equal k2. No two live TermRef share a TermKind.
why DAG sharing; TermRef used as HashMap/union-find key; congruence closure & AtomMap correctness depend on pointer identity == semantic identity.
enforced smt-types TermBank::intern — HashMap<TermKind, TermRef> lookup before alloc.
detection debug: rebuild reverse map, assert no two TermRef map to equal TermKind. Periodic audit_canon().
telemetry counters: intern_hits, intern_misses, bank_len.
recovery none possible if violated — abort with arena dump.

7.2 INV-SORT — every Term is well-sorted before assertion

field value
statement For every TermRef reachable from an Assert, Term.sort is the unique correct SortRef per SMT-LIB typing rules.
why downstream theories assume sort-correctness; unsound otherwise.
enforced smt-types constructor smart-builders check sort at intern time; smt-parse raises ParseError::SortMismatch/ArityMismatch before emitting Command::Assert.
detection debug check_well_sorted(t) post-order walk recomputes sort, asserts == stored.
recovery reject the command, keep prior context intact.

7.3 INV-ATOMMAP — AtomMap is a bijection BoolVar ↔ theory atom (TermRef)

field value
statement Total & injective both directions over theory atoms. Tseitin-internal vars are NOT in the atom direction.
why DPLL(T) glue: SAT trail literal ⇒ unambiguous theory atom to assert_lit. A non-injective map double-asserts/mis-explains.
enforced smt-sat AtomMap::atom_var(t) — memoized: first sighting allocs a BoolVar, reuse thereafter.
detection debug: assert_eq!(map.var_of(map.atom_of(v)), v) round-trip over all entries.
recovery n/a (build-time structure); abort if round-trip fails.

7.4 INV-TRAIL — theory state consistent with SAT trail at every push/pop boundary

field value
statement After every backjump/decision, the set of literals asserted into each theory == the set of theory literals currently on the SAT trail (same prefix). Theory scope-stack depth == count of push − pop issued by the orchestrator.
why DPLL(T) soundness: a theory must reason over exactly the current partial assignment.
enforced smt-core DPLL(T) loop pairs each SAT-trail level with TheorySolver::push/pop; on backjump to level k, pops theory to k before resuming.
detection debug: assert_eq!(theory.scope_depth, trail.decision_level).
recovery n/a — abort.

7.5 INV-CONFLICT — every TheoryConflict.core is a currently-asserted, T-inconsistent literal set

field value
statement core ⊆ {currently-asserted theory literals} and ⋀ core is T-unsatisfiable. The negation is a valid theory lemma.
why if core contained a non-asserted or T-satisfiable literal set, the SAT core learns a false clause ⇒ unsound.
enforced each theory builds core only from assert_lit inputs.
detection debug: assert every l ∈ core is on the theory's asserted list; re-check ⋀core in a fresh theory instance.
recovery a too-large but valid core is sound (just weaker); only non-asserted/T-sat cores are bugs ⇒ abort.

7.6 INV-EXPLAIN — every TheoryPropagation has a valid explanation entailing it

field value
statement explain(lit) returns reason literals R ⊆ {currently-asserted} such that ⋀R ⊨_T (lit==polarity). R does not contain lit itself.
why the propagation enters the SAT trail with R as its antecedent clause for CDCL analyze; an invalid R corrupts conflict analysis ⇒ unsound.
enforced EUF explain_eq = proof-forest NCA path; Simplex derived-bound explanation = the row's tight bounds.
detection debug: re-derive — assert a fresh theory fed only R propagates the same lit/polarity.
recovery n/a; abort on invalid explanation.

7.7 INV-CC — congruence closure is congruence-closed at every check() fixpoint

field value
statement At return from CongruenceClosure::check, for all App(f,a₁..aₙ), App(f,b₁..bₙ) in the e-graph: if ∀i are_equal(aᵢ,bᵢ) then are_equal(f(a),f(b)). Pending-merge queue is empty.
why EUF soundness: an un-propagated congruence = a missed equality ⇒ wrong sat.
enforced smt-theory::euf merge loop drains the pending queue until no new merge.
detection debug audit_cc(): brute-force all App pairs with f equal & args pairwise-equal ⇒ assert same class.
recovery n/a; abort.

7.8 INV-TABLEAU — Simplex tableau is a valid rephrasing; exact rationals only

field value
statement (a) Rows always express basic = Σ coeff·nonbasic, equivalent to originally-asserted linear atoms. (b) Every coefficient is BigRational; NO f32/f64. (c) Each Bound reflects exactly the asserted bound literals.
why (a) soundness of feasibility/conflict; (b) float rounding ⇒ unsound sat/unsat; (c) bounds drive conflict cores.
enforced Simplex::pivot performs exact BigRational row ops; assert_bound is the only bound mutator.
detection debug: after each pivot, recompute the original constraint values ⇒ assert residual == 0 exactly. CI grep gate: deny f64 in arith.
recovery rational bit-blowup is performance not soundness; abort only on residual ≠ 0.

7.9 INV-MODEL — a returned model satisfies every asserted formula

field value
statement On CheckResult::Sat, for every top-level asserted TermRef a, evaluate(a, model) == Value::Bool(true). Shared interface vars agree across theories.
why a sat answer is only meaningful with a witnessing model; cross-theory disagreement on a shared var ⇒ a false sat.
enforced smt-model ModelBuilder collects per-theory assignments; N-O guarantees interface-var agreement.
detection ALWAYS-ON: before printing sat, run evaluate on each assertion; any non-true ⇒ downgrade to unknown + log.
recovery downgrade sat→unknown; never emit an unvalidated model.

7.10 INV-CORE — an unsat core is a subset of named assertions whose conjunction is unsat

field value
statement UnsatCore(v) ⇒ v ⊆ {named assertions in current context} and ⋀v is unsat.
why consumers require subset + unsat; a non-subset or sat core is wrong.
enforced smt-model UnsatCore extraction intersects with tracked named-assertion set.
detection ALWAYS-ON: re-solve ⋀v in a fresh solver ⇒ must return unsat.
recovery if recheck returns sat/unknown ⇒ bug; if non-minimal ⇒ acceptable.

7.11 INV-NO-TERM — Nelson-Oppen terminates and reports unsat iff some theory is inconsistent

field value
statement (a) Termination: equality-sharing fixpoint exchanges only equalities over the FINITE set of shared variables; each exchanged equality strictly merges classes ⇒ at most #shared−1 merges per theory ⇒ loop halts. (b) Soundness/completeness: combined result is unsat iff some component theory reports inconsistent under the shared equalities.
why purification + equality exchange is the combination correctness contract.
enforced TheoryManager equality-sharing bus: purify mixed terms; loop until fixpoint; LIA non-convexity ⇒ case splits.
detection debug: assert each bus round produces ≥1 new merge or terminates; iteration counter ≤ shared².
recovery iteration counter exceeding shared² ⇒ invariant breach ⇒ abort.

7.12 INV-INCR — push/pop restores exact theory + SAT trail state

field value
statement After pop(k), every mutable structure (union-find roots, Bound stacks, blasted-var scope, learned clauses above level k, AtomMap additions above level k) is indistinguishable from a solver that never executed the popped scope.
why incremental soundness: a post-pop check-sat must be equivalent to a from-scratch solve over the retained assertions.
enforced smt-core::incremental scope stack; each theory must implement push/pop pairing undo; TermBank is global (no pop needed: hash-cons is additive); SAT clause DB prunes learned clauses above pop level.
detection property prop_pushpop_idempotent: (push; assert φ; pop) followed by check-sat must agree with baseline; soak test 10k iterations; if diverge → INV-INCR violated.
recovery n/a — abort on detection; invariant dump triggers.

8.3 The Term DAG + hash-consing

TermBank = arena (Vec<Term>) + HashMap<TermKind, TermRef> for de-duplication. intern(kind) -> TermRef: compute sort, look up kind; hit → return existing TermRef; miss → push, insert, return fresh. Maximal structural sharing: identical subterms share one node.

Why canonicity is load-bearing:

  • TermRef identity ⇒ syntactic equality in O(1) — no recursive walk.
  • Memory bounded by distinct subterms; deeply nested SMT-LIB collapses. Target: ≥2M intern/sec, ≤40 B/node amortized.
  • AtomMap keyed by TermRef: each theory atom maps to exactly one BoolVar.

TermKind variants partition into: Boolean-structural (Not,And,Or,Implies,Ite over Bool) → Tseitin-encoded; theory atoms (Eq,Distinct, Arith comparisons, Bv predicates) → leaves handed to TheorySolvers; theory terms (App,Var,IntLit,RealLit,BvLit,Arith arithmetic, Bv ops) → interpreted inside theory solvers; quantifiers (Forall,Exists) → stub.

8.4 The DPLL(T) protocol (state machine)

Lazy SMT: SatCore (reused project-277 CDCL) decides a Boolean assignment over theory atoms (abstracted as BoolVar via AtomMap); the TheoryManager checks T-consistency of the assigned theory literals.

   set-logic / assert ...           check_sat(ctx)  [smt-core: DPLL(T) loop]
            |                                |
   tseitin(skeleton) ──▶ SatCore (CNF) , AtomMap (BoolVar<->atom TermRef)
            |
            v
   ┌──────────────────────────── DPLL(T) main loop ────────────────────────────┐
   │  (1) SatCore: BCP/unit-prop to fixpoint over current decision level        │
   │        ├─ propositional conflict ─▶ analyze/learn/backjump (project-277)   │
   │        └─ fixpoint reached, partial assignment A of theory literals        │
   │  (2) for each literal newly assigned in A:                                 │
   │        TheorySolver::assert_lit(atom, polarity)                            │
   │          └─ Err(TheoryConflict{core}) ─▶ goto (5)                          │
   │  (3) TheoryManager::check(final_check=false)  (+ Nelson-Oppen eq bus)      │
   │        ├─ Ok(props: Vec<TheoryPropagation>) ─▶ feed each as implied lit    │
   │        │      to SatCore (reason = explain(lit)); goto (1)                 │
   │        └─ Err(TheoryConflict{core}) ─▶ goto (5)                            │
   │  (4) all vars assigned & no props:  check(final_check=true)                │
   │        ├─ Ok([]) ─▶  SAT  (build model; ready for get-value/get-model)     │

Invariants: Soundness of lemmas (every TheoryConflict.core is jointly T-inconsistent); Trail synchrony (push/pop mirror SatCore decision levels); Termination (each learned theory lemma is new over finitely many atoms).

8.5 Worked example 1 — QF_UF (unsat)

(set-logic QF_UF)
(declare-sort U 0) (declare-fun a () U) (declare-fun b () U) (declare-fun c () U)
(declare-fun f (U) U)
(assert (= a b)) (assert (= b c)) (assert (not (= (f a) (f c))))
(check-sat)
Atom (TermRef) BoolVar Asserted polarity
Eq(a,b) p₁ true
Eq(b,c) p₂ true
Eq(f(a),f(c)) p₃ false

SatCore picks p₁=T, p₂=T, p₃=F. EUF CongruenceClosure:

assert_lit(Eq(a,b),T):  merge(a,b)      classes: {a,b} {c} {f(a)} {f(c)}
assert_lit(Eq(b,c),T):  merge(b,c)      classes: {a,b,c} {f(a)} {f(c)}
   congruence:  f(a),f(c) with a~c  =>  pending merge(f(a),f(c))
                                        classes: {a,b,c} {f(a),f(c)}
assert_lit(Eq(f(a),f(c)),F):           are_equal(f(a),f(c)) == true  -> CONFLICT

explain_eq(f(a),f(c)) walks the proof forest: f(a)=f(c) ⇐ congruence ⇐ a=c ⇐ {a=b, b=c}. Conflict core = { Eq(a,b), Eq(b,c), ¬Eq(f(a),f(c)) }. Theory lemma ¬p₁ ∨ ¬p₂ ∨ p₃ added; at decision level 0 ⇒ unsat.

8.6 Worked example 2 — QF_LRA (unsat)

(set-logic QF_LRA)
(declare-fun x () Real) (declare-fun y () Real)
(assert (<= (+ x y) 2)) (assert (>= x 1)) (assert (>= y 2))
(check-sat)

Simplex general form: introduce slack s = x + y (a basic var).

Var lo hi role
s = x+y — 2 basic
x 1 — nonbasic
y 2 — nonbasic

x=1, y=2 ⇒ s = 3. But hi(s)=2 ⇒ s violates upper bound. Every nonbasic in its row is at its lower bound and cannot decrease ⇒ no pivot restores feasibility ⇒ infeasible row. Conflict: { x≥1, y≥2, x+y≤2 }. Theory lemma negates these ⇒ unsat. Arithmetic is exact BigRational for soundness.

8.7 Worked example 3 — QF_LIA branch-and-bound (mini)

(set-logic QF_LIA)
(declare-fun x () Int)
(assert (<= (* 2 x) 3)) (assert (>= (* 2 x) 1))
(check-sat)

LRA-relaxation: feasible, e.g. x = 0.5. Integrality check: x is Int but q = 1/2 ∉ ℤ ⇒ branch: x ≤ 0 OR x ≥ 1.

  • Branch x≤0: combined with 2x≥1 ⇒ infeasible ⇒ prune.
  • Branch x≥1: with 2x≤3 ⇒ x=1, integral ⇒ sat, model x=1.

Eager wins for a purely QF_BV solver where all constraints are bit-level Boolean and no arithmetic/EUF is needed.
ADR-06 SAT core Reuse the project-277 CDCL SatCore Embed external solver (MiniSat/CaDiCaL via FFI); re-derive CDCL here This project's novelty is the theory layer — reuse #277. External FFI breaks tight theory-propagation callbacks. External FFI (CaDiCaL) wins if you need state-of-the-art CDCL heuristics (chronological backtracking, VSIDS improvements) without maintaining the SAT core yourself.
ADR-07 Theory-solver interface TheorySolver trait: assert_lit / check / explain / push / pop / model Per-theory bespoke APIs; callback closures One uniform contract lets TheoryManager drive any enabled theory generically; explain mandatory for theory-lemma generation. Bespoke APIs win when theory solvers have wildly different state models and the trait abstraction adds overhead (e.g., a lean QF_BV-only engine).
ADR-08 EUF algorithm Congruence closure: union-find + e-graph + proof forest for explain_eq Ackermann expansion to pure SAT; naive O(n²) re-scan CC is incremental and produces minimal explanations via NCA on the proof forest. Ackermann expansion wins for very small, static EUF problems where the clause explosion is bounded and simplicity is paramount.
ADR-09 Arithmetic engine Exact-rational Simplex (BigRational tableau, general form, bound per var) Fourier-Motzkin elimination; floating-point Simplex; interval/CAD Float Simplex is UNSOUND for a decision procedure. FM blows up exponentially. Exact Simplex gives minimal infeasible bound sets. Floating-point Simplex wins in a non-decision setting (LP optimization without soundness requirement) where speed dominates correctness.
ADR-10 LIA integrality strategy Branch-and-bound over the LRA Simplex + basic Gomory cuts, bounded depth Omega test; pure cutting planes; ILP solver dependency Reuses the LRA Simplex directly; cuts accelerate; bounded depth yields Unknown rather than non-termination. Omega test wins when the formula has a known small quantifier-free Presburger structure and you need guaranteed termination without depth caps.
ADR-11 Bit-vectors Eager bit-blasting into the shared SatCore Lazy bit-vector theory solver; word-level decision procedure Bit-blasting is robust, complete, and reuses the CDCL core. Lazy BV wins for very wide (> 1024-bit) vectors where bit-blasting is infeasible and word-level reasoning (e.g., bitwuzla's approach) can prune earlier.
ADR-12 Theory combination Nelson-Oppen: purification + interface-equality sharing Model-based combination (MBTC); Shostak combination; monolithic super-theory N-O is the textbook disjoint-theory method matching EUF+arith. MBTC wins when you need to combine many theories efficiently and model-based split avoids the exponential case-split of non-convex N-O.
ADR-13 Non-convex theories Explicit case-splitting for LIA in N-O Assume convexity (unsound for LIA); arrangement enumeration only LIA is non-convex — N-O must split; convex fast path retained for EUF/LRA. Arrangement enumeration wins when the number of shared integer vars is very small (e.g., 1–2), making exhaustive enumeration cheaper than CDCL-driven case splits.
ADR-14 Big-number library num-bigint + num-rational (BigInt, BigRational) Vendored from-scratch bignum; GMP via FFI; i128 only Battle-tested, pure-Rust, no unsafe FFI, deterministic across platforms. GMP via FFI wins when Simplex performance on very large instances is the bottleneck and you accept the native build dep and unsafe boundary.
ADR-15 Model construction Per-theory ModelBuilder contributions + combined-model consistency check Single global assignment map; re-solve to extract model Each theory owns its variable assignments; UF rendered as a finite function graph. Re-solve-to-extract wins if theories do not maintain internal assignments (e.g., a black-box theory oracle) and model extraction is rare.
ADR-16 get-value evaluation evaluate(t, model) walks the Term DAG against the constructed model Cache values during solving; symbolic substitution Post-solve DAG walk is simple and exact for arbitrary queried terms. Caching during solving wins when get-value is called on millions of terms and the model is hot in cache at solve time.
ADR-17 Unsat-core method Assumption-based: track named assertions, return the subset in the final conflict Proof-based extraction (replay full resolution proof); deletion-based minimization only Assumption tracking is low-overhead and standard (SMT-LIB :named). Full proof replay wins when a client needs certifiable UNSAT proofs (e.g., hardware verification) and the extra overhead is acceptable.
ADR-18 Incremental solving Scoped push/pop: theory push/pop, Simplex warm-start, e-graph compaction Re-solve from scratch each check-sat; full-state snapshots SMT-LIB clients issue many incremental check-sats; warm-start preserves state. From-scratch wins when incremental state corruption risk (F-INCR-LEAK) outweighs the speedup — e.g., during debugging or for short-lived sessions.
ADR-19 Term-DAG memory mgmt Mark-sweep GC of TermBank triggered on pop / high-water mark Never free (leak); per-pop immediate free; Rc auto-drop Long incremental sessions accumulate dead terms; explicit GC over the arena reclaims without per-term refcount overhead. Never-free wins for short-lived single-check sessions where GC overhead exceeds reclamation benefit.
ADR-20 Fuzzing cargo-fuzz (libFuzzer) + a structured Term generator; model-validation oracle No fuzzing; AFL standalone; property tests only Untrusted SMT-LIB text at the trust boundary — fuzz the parser and the solver. AFL wins when you have an existing AFL infrastructure and libFuzzer integration is blocked.
ADR-21 Differential oracle Differential testing vs Z3 and cvc5 on shared benchmarks Self-consistency only; single reference solver Two independent oracles catch soundness bugs a single reference would miss. Single oracle wins when only one reference solver is available or licensed in your environment.
ADR-22 Benchmarking criterion micro-benches + SMT-COMP benchmark buckets per logic Ad-hoc time; wall-clock only; no perf gates criterion gives statistical regression detection; SMT-COMP buckets are the canonical real-world workload. Ad-hoc timing wins for rapid iteration during early development before performance baselines matter.
ADR-23 Dependency policy Minimal: num-bigint, num-rational, plus dev-only criterion/cargo-fuzz Liberal crate use; pull in an SMT/SAT framework crate Small audited dependency surface for a correctness-critical tool. Liberal crate use wins when developer productivity and ecosystem integration outweigh the security review burden.
ADR-24 MSRV / toolchain Rust 1.78, edition 2021, pinned in rust-toolchain.toml; CI matrix MSRV + stable Track nightly; no MSRV guarantee Stable reproducible builds. Nightly wins when you need unstable features (e.g., #[may_dangle]) for the arena design and can accept breakage risk.

Minimal CI (just build+test) wins when the CI infrastructure cost exceeds the bug-catch benefit for a solo project with frequent experimental iterations.

11.1 Identity, ownership, mutation, concurrency

Concern Rule
Identity TermRef/SortRef/Symbol are u32 newtype handles, NOT pointers — index into arena vectors. Copy, Eq, Hash by raw value.
Structural identity Hash-consing guarantees a == b (handle eq) IFF structurally equal.
Ownership Every Term/Sort owned by TermBank; handles are non-owning.
Mutation TermBank append-only between GCs; interning never rewrites existing slots.
Concurrency Single-threaded; handles are !Send by convention.
Serialization None for handles. Round-trips happen through SMT-LIB text via the parser/printer.
Compatibility Adding TermKind/Sort/Logic variants is source-breaking (intentional — forces phase coverage).

Mental Models & First Principles

# Model What it predicts Bug class without it Resolving §
MM1 Hash-consed identity = structural equality — two TermRefs are equal iff r1.0 == r2.0. No deep-compare anywhere. Any call to structural equality beyond == on TermRef is redundant at best, wrong at worst. Non-canonical references cause CC to miss equal terms. CC maintains two distinct roots for the same subterm → merged e-classes diverge → explain_eq gaps → unsound unsat claim. §8 Domain Model; §11 (TermBank); §7 INV-CANON; Ph2
MM2 DPLL(T) is DPLL + a T-oracle — the SAT core controls the Boolean structure; theories speak only via Propagation/T-conflict returns. Neither theory solver nor DPLL(T) loop may set a BoolVar directly. Every theory deduction must carry a reason set in the DPLL(T) trail. If a theory skips the Propagation channel the proof system has a gap. Theory solver writes BoolVar directly; SAT trail misses the reason → conflict analysis produces a clause without that literal → wrong unsat-core; possibly infinite loop. §3; §8 (DPLL(T) state machine); Ph4, Ph5; §7 INV-CONFLICT
MM3 Nelson-Oppen requires stably-infinite, disjoint theories — only then can equality propagation between theories be sound and complete. Finite-domain theories (BV) must stay eager. Any non-stably-infinite theory combined lazily will miss satisfying models that require a finite-domain witness. BV ↔ LRA lazy combination via N-O interface equalities → incomplete → unknown on decidable formula, or spurious sat. §3; §8 (DPLL(T) state machine); Ph9 (N-O combination); §9 ADR-12
MM4 Soundness before completeness before speed — every heuristic (f64 pivot scoring, VSIDS) must be a guide only; exact arithmetic (BigRational) decides. A float scoring heuristic for which variable to pivot is fine; using f64 to test feasibility at a bound is not. f64 feasibility check at a Simplex bound → rounding → false Unsat or false Sat for a lattice point — soundness failure. §4 SC-5; §7 INV-TABLEAU; Ph6, Ph7; Failure Modes & Recovery F-FLOAT
MM5 Learned clauses are valid theory lemmas — every clause added to the SAT core via add_clause must be a valid consequence of the already-asserted trail prefix. If a theory lemma is added that is not entailed by the current trail, the SAT core will use it in future conflict analysis and block valid branches. Bad theory lemma (reason set does not entail propagated literal) → DPLL(T) closes a satisfying branch → Unsat for a Sat instance. §7 INV-EXPLAIN; Ph4; Failure Modes & Recovery F-BADEXPL
MM6 Incremental solving is a stack of consistent states — push is a checkpoint; pop is an exact undo of every structure modified between the two calls. Any mutable structure (union-find, Simplex bound stack, blasted-var scope, learned clauses above the level) must undo cleanly, or residual state corrupts the post-pop check. Union-find merges not undone after pop → stale equalities survive → sat/unsat disagrees with from-scratch solve. §7 INV-INCR; Ph12 (incremental hardening); Failure Modes & Recovery F-INCR-LEAK
MM7 Congruence closure runs to fixpoint — a single merge(a,b) triggers merge(f(a),f(b)) which may trigger further merges; the pending-merge queue must drain entirely before CC is "closed". Premature return from merge leaves the closure in a non-fixed-point state, making explain_eq incomplete and theory propagation unsound. merge returns before pending queue drains → are_equal(f(a),f(b)) returns false even though a=b was asserted → missed T-propagation. §3; §7 INV-CC; Ph5; Failure Modes & Recovery F-CC-NT
MM8 Unsat-core correctness is a separate obligation — Unsat is correct if the conjunction is unsatisfiable; the core is correct only if it is a subset that is itself unsatisfiable and is a subset of the named assertions. These are different invariants. Re-checking the core independently (re-solve) is the only reliable test. Trusting the core without re-checking can produce cores containing spurious named assertions. Core includes an assertion not in the original named set → user mis-attributes the unsatisfiability → debugging entirely in the wrong place. §7 INV-CORE; Ph11; Failure Modes & Recovery F-BADEXPL

Applying the models in practice: MM1–MM8 form a diagnostic decision tree. When a result is suspect, ask in order: (1) is every interned term canonical? (MM1); (2) are all theory deductions through the propagation channel? (MM2); (3) did N-O get the theory classification right? (MM3); (4) is the feasibility test exact? (MM4); (5) is every learned clause valid? (MM5); (6) did every pop undo cleanly? (MM6); (7) did CC reach fixpoint? (MM7); (8) was the unsat-core re-checked? (MM8). This ordering covers ~95% of historical SMT solver soundness bugs documented in public postmortems (see Failure Modes & Recovery, F-FLOAT, F-INCR-LEAK, F-CC-CANON).

Cross-model interactions: MM1 (hash-cons) underpins MM7 (CC fixpoint) because congruence is detected via TermRef equality; if two TermRefs for the same term exist, congruence is never detected. MM2 (DPLL(T) channel) underpins MM5 (learned clauses) because the propagation channel is where the reason set is recorded. MM6 (incremental stack) underpins MM4 (exact arithmetic) at the Simplex level because warm-start carries the exact BigRational basis across a pop, and an imprecise carry-over would corrupt the next check_sat. Understanding these dependencies allows triaging S0 bugs without exhaustive state inspection.

Onboarding shortcut: A new contributor should internalize MM1 and MM2 in Phase 2–4 before touching MM3–MM8 in later phases. MM1 requires no context beyond §8; MM2 requires tracing one DPLL(T) loop iteration in §8's state-machine diagram and the §11 TheorySolver trait. Both can be verified against the Phase 4 unit tests before any theory code is written.

Alternative Architectures (Roads Not Taken)

Alt-1: Eager Pre-processing + Bounded Model Checking

  SMT-LIB input
       |
  Preprocessor (rewriting, simplification, AIG/BDD reduction)
       |
  Bit-blast ALL theories eagerly → fixed SAT instance
       |
  Monolithic CDCL SAT solver
       |
  verdict (no theory callbacks, no learned T-lemmas)

Regime where it wins: Hardware model checking / bounded model checking; formulas with heavy bit-level structure; tool-chains where the verifier needs a fixed-size SAT instance for downstream analysis (e.g., FPGA timing tools). Real systems: CBMC (C Bounded Model Checker), many HW model checkers (Cadence JasperGold pre-processing path).

Why rejected: (a) Exponential clause blow-up for wide arithmetic — multiplier = O(W²) clauses; (b) no incremental support without rebuilding the entire SAT instance; (c) EUF/LRA theories don't reduce cleanly to BV without expensive, soundness-critical encodings; (d) soundness of the encoding is a separate proof obligation per theory. ADR-11 explicitly limits bit-blasting to QF_BV.

Alt-2: Quantifier Elimination (QE) + BDD

  SMT-LIB input (linear arithmetic)
       |
  Quantifier elimination (Presburger for LIA, Fourier-Motzkin for LRA)
  → quantifier-free equivalent
       |
  BDD or simple CNF SAT
       |
  verdict

Regime where it wins: Small-variable quantified arithmetic that must produce witnesses or certificates; synthesis and optimization formulas; cases where QE gives a polynomial bound in the theory. Real systems: QEPCAD (quantifier elimination over reals), Omega test (Presburger arithmetic), LattE Integrale.

Why rejected: (a) QE for LIA is doubly exponential in the number of variables; (b) our scope explicitly excludes quantifiers (INV-NO-TERM) — QE is moot; (c) BDD explosion on Boolean structure: BDD size is not bounded by formula size; (d) no incremental model. The QE/BDD approach is irrelevant for the quantifier-free logics targeted here.

Alt-3: Abstract Interpretation / Interval Domain

  SMT-LIB assertions
       |
  Abstract domain analysis (intervals, octagons, convex polyhedra)
       |
  Fixed-point computation (widening / narrowing)
       |
  verdict: SAFE (no false sat) | UNKNOWN (may have false unsat)

Regime where it wins: Program analysis / invariant inference where soundness = no missed errors (over-approximate safe set); does not need to find a concrete model; fast on large codebases with thousands of variables. Real systems: Astrée (Airbus certified), Polyspace, Frama-C EVA, Infer.

Why rejected: (a) Abstract interpretation is not refutation-complete — it cannot prove sat; (b) false unsat (spurious alarm) violates our correctness contract (§7 INV-MODEL); (c) no concrete model production for SAT answers; (d) it is useful as a preprocessor (propagate bounds before Simplex), not as the decision engine. We use lightweight interval propagation during bound assertion, but the Simplex tableau decides.

Alt-4: Portfolio / Parallel SMT

  SMT-LIB input ─┬─► smtsolve config A (VSIDS, seed 1) ─┐
                 ├─► smtsolve config B (phase saving, seed 2) ├─► first-to-answer → result
                 ├─► Z3 subprocess                           │
                 └─► cvc5 subprocess                         ┘

Regime where it wins: Competition settings (PAR-2 score optimization); industrial timeout budgets where diverse strategies cover different hard classes; cloud environments with many cheap cores. Real systems: SMT-COMP portfolio solvers, ppSAT (parallel SAT), the VeriT+Z3 portfolio.

Why rejected (for the core): (a) Primary value of this project is deep understanding of a single DPLL(T) implementation — a portfolio is an orchestrator, not a solver; (b) subprocess management adds infrastructure complexity outside the education target; (c) no Clone-able CommandContext until Phase 12; (d) shared-clause exchange requires a thread-safe clause database (out of scope). Deferred as a stretch wrapper in Phase 13 (ADR-21).
