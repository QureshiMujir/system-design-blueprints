Decisions (§9) · 26 ADRs

ADR-01

Implementation language

Chosen

Rust, edition 2021, MSRV 1.78, std

Rejected

C/C++; Python; Haskell; OCaml

When the rejected choice is right

C++ wins if the team has a mature solver codebase and requires tight C library integration; Python wins for rapid prototype/scripting of test oracles only.

Why: Enums model TermKind/Sort with exhaustive match; ownership disciplines the shared hash-cons/union-find aliasing; no GC pauses in SAT+theory inner loop.

ADR-02

Project structure

Chosen

Cargo workspace, seven crates

Rejected

Single monolithic crate; per-theory separate crates

When the rejected choice is right

Monolithic crate wins when build times are paramount (zero workspace overhead) and the team's discipline prevents layering violations.

Why: Crate boundaries = compile-time layering: theory solvers cannot reach into parser internals; parallel cargo builds.

ADR-03

Term representation

Chosen

Hash-consed TermBank arena, handles TermRef(u32)

Rejected

Rc<Term> reference-counted tree; Box owned tree

When the rejected choice is right

Rc<Term> wins when terms are rarely shared and simplicity of ownership matters more than memory and equality speed.

Why: Maximal structural sharing; O(1) term equality via TermRef compare; u32 handles halve memory vs 64-bit pointers.

ADR-04

Sort system

Chosen

Explicit Sort enum + SortRef, eager well-sortedness check at intern()

Rejected

Untyped terms; lazy/deferred sort checking

When the rejected choice is right

Lazy checking wins if you need to represent ill-typed intermediate terms (e.g., rewriting passes that temporarily violate sorts).

Why: Reject ill-sorted terms at parse/build time before any solving.

ADR-05

SMT solving approach

Chosen

Lazy DPLL(T): Boolean skeleton + online theory solvers

Rejected

Eager (bit-blast/encode everything to SAT); pure tableau/sequent

When the rejected choice is right

Eager wins for a purely QF_BV solver where all constraints are bit-level Boolean and no arithmetic/EUF is needed.

Why: Lazy scales across EUF+LIA+BV where eager encoding of EUF/LIA blows up.

ADR-06

SAT core

Chosen

Reuse the project-277 CDCL SatCore

Rejected

Embed external solver (MiniSat/CaDiCaL via FFI); re-derive CDCL here

When the rejected choice is right

External FFI (CaDiCaL) wins if you need state-of-the-art CDCL heuristics (chronological backtracking, VSIDS improvements) without maintaining the SAT core yourself.

Why: This project's novelty is the theory layer — reuse #277. External FFI breaks tight theory-propagation callbacks.

ADR-07

Theory-solver interface

Chosen

TheorySolver trait: assert_lit / check / explain / push / pop / model

Rejected

Per-theory bespoke APIs; callback closures

When the rejected choice is right

Bespoke APIs win when theory solvers have wildly different state models and the trait abstraction adds overhead (e.g., a lean QF_BV-only engine).

Why: One uniform contract lets TheoryManager drive any enabled theory generically; explain mandatory for theory-lemma generation.

ADR-08

EUF algorithm

Chosen

Congruence closure: union-find + e-graph + proof forest for explain_eq

Rejected

Ackermann expansion to pure SAT; naive O(n²) re-scan

When the rejected choice is right

Ackermann expansion wins for very small, static EUF problems where the clause explosion is bounded and simplicity is paramount.

Why: CC is incremental and produces minimal explanations via NCA on the proof forest.

ADR-09

Arithmetic engine

Chosen

Exact-rational Simplex (BigRational tableau, general form, bound per var)

Rejected

Fourier-Motzkin elimination; floating-point Simplex; interval/CAD

When the rejected choice is right

Floating-point Simplex wins in a non-decision setting (LP optimization without soundness requirement) where speed dominates correctness.

Why: Float Simplex is UNSOUND for a decision procedure. FM blows up exponentially. Exact Simplex gives minimal infeasible bound sets.

ADR-10

LIA integrality strategy

Chosen

Branch-and-bound over the LRA Simplex + basic Gomory cuts, bounded depth

Rejected

Omega test; pure cutting planes; ILP solver dependency

When the rejected choice is right

Omega test wins when the formula has a known small quantifier-free Presburger structure and you need guaranteed termination without depth caps.

Why: Reuses the LRA Simplex directly; cuts accelerate; bounded depth yields Unknown rather than non-termination.

ADR-11

Bit-vectors

Chosen

Eager bit-blasting into the shared SatCore

Rejected

Lazy bit-vector theory solver; word-level decision procedure

When the rejected choice is right

Lazy BV wins for very wide (> 1024-bit) vectors where bit-blasting is infeasible and word-level reasoning (e.g., bitwuzla's approach) can prune earlier.

Why: Bit-blasting is robust, complete, and reuses the CDCL core.

ADR-12

Theory combination

Chosen

Nelson-Oppen: purification + interface-equality sharing

Rejected

Model-based combination (MBTC); Shostak combination; monolithic super-theory

When the rejected choice is right

MBTC wins when you need to combine many theories efficiently and model-based split avoids the exponential case-split of non-convex N-O.

Why: N-O is the textbook disjoint-theory method matching EUF+arith.

ADR-13

Non-convex theories

Chosen

Explicit case-splitting for LIA in N-O

Rejected

Assume convexity (unsound for LIA); arrangement enumeration only

When the rejected choice is right

Arrangement enumeration wins when the number of shared integer vars is very small (e.g., 1–2), making exhaustive enumeration cheaper than CDCL-driven case splits.

Why: LIA is non-convex — N-O must split; convex fast path retained for EUF/LRA.

ADR-14

Big-number library

Chosen

num-bigint + num-rational (BigInt, BigRational)

Rejected

Vendored from-scratch bignum; GMP via FFI; i128 only

When the rejected choice is right

GMP via FFI wins when Simplex performance on very large instances is the bottleneck and you accept the native build dep and unsafe boundary.

Why: Battle-tested, pure-Rust, no unsafe FFI, deterministic across platforms.

ADR-15

Model construction

Chosen

Per-theory ModelBuilder contributions + combined-model consistency check

Rejected

Single global assignment map; re-solve to extract model

When the rejected choice is right

Re-solve-to-extract wins if theories do not maintain internal assignments (e.g., a black-box theory oracle) and model extraction is rare.

Why: Each theory owns its variable assignments; UF rendered as a finite function graph.

ADR-16

get-value evaluation

Chosen

evaluate(t, model) walks the Term DAG against the constructed model

Rejected

Cache values during solving; symbolic substitution

When the rejected choice is right

Caching during solving wins when get-value is called on millions of terms and the model is hot in cache at solve time.

Why: Post-solve DAG walk is simple and exact for arbitrary queried terms.

ADR-17

Unsat-core method

Chosen

Assumption-based: track named assertions, return the subset in the final conflict

Rejected

Proof-based extraction (replay full resolution proof); deletion-based minimization only

When the rejected choice is right

Full proof replay wins when a client needs certifiable UNSAT proofs (e.g., hardware verification) and the extra overhead is acceptable.

Why: Assumption tracking is low-overhead and standard (SMT-LIB :named).

ADR-18

Incremental solving

Chosen

Scoped push/pop: theory push/pop, Simplex warm-start, e-graph compaction

Rejected

Re-solve from scratch each check-sat; full-state snapshots

When the rejected choice is right

From-scratch wins when incremental state corruption risk (F-INCR-LEAK) outweighs the speedup — e.g., during debugging or for short-lived sessions.

Why: SMT-LIB clients issue many incremental check-sats; warm-start preserves state.

ADR-19

Term-DAG memory mgmt

Chosen

Mark-sweep GC of TermBank triggered on pop / high-water mark

Rejected

Never free (leak); per-pop immediate free; Rc auto-drop

When the rejected choice is right

Never-free wins for short-lived single-check sessions where GC overhead exceeds reclamation benefit.

Why: Long incremental sessions accumulate dead terms; explicit GC over the arena reclaims without per-term refcount overhead.

ADR-20

Fuzzing

Chosen

cargo-fuzz (libFuzzer) + a structured Term generator; model-validation oracle

Rejected

No fuzzing; AFL standalone; property tests only

When the rejected choice is right

AFL wins when you have an existing AFL infrastructure and libFuzzer integration is blocked.

Why: Untrusted SMT-LIB text at the trust boundary — fuzz the parser and the solver.

ADR-21

Differential oracle

Chosen

Differential testing vs Z3 and cvc5 on shared benchmarks

Rejected

Self-consistency only; single reference solver

When the rejected choice is right

Single oracle wins when only one reference solver is available or licensed in your environment.

Why: Two independent oracles catch soundness bugs a single reference would miss.

ADR-22

Benchmarking

Chosen

criterion micro-benches + SMT-COMP benchmark buckets per logic

Rejected

Ad-hoc time; wall-clock only; no perf gates

When the rejected choice is right

Ad-hoc timing wins for rapid iteration during early development before performance baselines matter.

Why: criterion gives statistical regression detection; SMT-COMP buckets are the canonical real-world workload.

ADR-23

Dependency policy

Chosen

Minimal: num-bigint, num-rational, plus dev-only criterion/cargo-fuzz

Rejected

Liberal crate use; pull in an SMT/SAT framework crate

When the rejected choice is right

Liberal crate use wins when developer productivity and ecosystem integration outweigh the security review burden.

Why: Small audited dependency surface for a correctness-critical tool.

ADR-24

MSRV / toolchain

Chosen

Rust 1.78, edition 2021, pinned in rust-toolchain.toml; CI matrix MSRV + stable

Rejected

Track nightly; no MSRV guarantee

When the rejected choice is right

Nightly wins when you need unstable features (e.g., #[may_dangle]) for the arena design and can accept breakage risk.

Why: Stable reproducible builds.

ADR-25

CI

Chosen

GitHub Actions: fmt + clippy -D warnings + test + MSRV + SMT-COMP smoke + fuzz-build

Rejected

No CI; manual testing

When the rejected choice is right

Minimal CI (just build+test) wins when the CI infrastructure cost exceeds the bug-catch benefit for a solo project with frequent experimental iterations.

Why: Gate every merge on formatting, lints, conformance smoke, and that fuzz targets compile.

Licensing

Roads not taken

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Alt-1: Eager Pre-processing + Bounded Model Checking

  SMT-LIB input
       |
  Preprocessor (rewriting, simplification, AIG/BDD reduction)
       |
  Bit-blast ALL theories eagerly → fixed SAT instance
       |
  Monolithic CDCL SAT solver
       |
  verdict (no theory callbacks, no learned T-lemmas)

Regime where it wins: Hardware model checking / bounded model checking; formulas with heavy bit-level structure; tool-chains where the verifier needs a fixed-size SAT instance for downstream analysis (e.g., FPGA timing tools). Real systems: CBMC (C Bounded Model Checker), many HW model checkers (Cadence JasperGold pre-processing path).

Why rejected: (a) Exponential clause blow-up for wide arithmetic — multiplier = O(W²) clauses; (b) no incremental support without rebuilding the entire SAT instance; (c) EUF/LRA theories don't reduce cleanly to BV without expensive, soundness-critical encodings; (d) soundness of the encoding is a separate proof obligation per theory. ADR-11 explicitly limits bit-blasting to QF_BV.

Alt-2: Quantifier Elimination (QE) + BDD

  SMT-LIB input (linear arithmetic)
       |
  Quantifier elimination (Presburger for LIA, Fourier-Motzkin for LRA)
  → quantifier-free equivalent
       |
  BDD or simple CNF SAT
       |
  verdict

Regime where it wins: Small-variable quantified arithmetic that must produce witnesses or certificates; synthesis and optimization formulas; cases where QE gives a polynomial bound in the theory. Real systems: QEPCAD (quantifier elimination over reals), Omega test (Presburger arithmetic), LattE Integrale.

Why rejected: (a) QE for LIA is doubly exponential in the number of variables; (b) our scope explicitly excludes quantifiers (INV-NO-TERM) — QE is moot; (c) BDD explosion on Boolean structure: BDD size is not bounded by formula size; (d) no incremental model. The QE/BDD approach is irrelevant for the quantifier-free logics targeted here.

Alt-3: Abstract Interpretation / Interval Domain

  SMT-LIB assertions
       |
  Abstract domain analysis (intervals, octagons, convex polyhedra)
       |
  Fixed-point computation (widening / narrowing)
       |
  verdict: SAFE (no false sat) | UNKNOWN (may have false unsat)

Regime where it wins: Program analysis / invariant inference where soundness = no missed errors (over-approximate safe set); does not need to find a concrete model; fast on large codebases with thousands of variables. Real systems: Astrée (Airbus certified), Polyspace, Frama-C EVA, Infer.

Why rejected: (a) Abstract interpretation is not refutation-complete — it cannot prove sat; (b) false unsat (spurious alarm) violates our correctness contract (§7 INV-MODEL); (c) no concrete model production for SAT answers; (d) it is useful as a preprocessor (propagate bounds before Simplex), not as the decision engine. We use lightweight interval propagation during bound assertion, but the Simplex tableau decides.

Alt-4: Portfolio / Parallel SMT

  SMT-LIB input ─┬─► smtsolve config A (VSIDS, seed 1) ─┐
                 ├─► smtsolve config B (phase saving, seed 2) ├─► first-to-answer → result
                 ├─► Z3 subprocess                           │
                 └─► cvc5 subprocess                         ┘

Regime where it wins: Competition settings (PAR-2 score optimization); industrial timeout budgets where diverse strategies cover different hard classes; cloud environments with many cheap cores. Real systems: SMT-COMP portfolio solvers, ppSAT (parallel SAT), the VeriT+Z3 portfolio.

Why rejected (for the core): (a) Primary value of this project is deep understanding of a single DPLL(T) implementation — a portfolio is an orchestrator, not a solver; (b) subprocess management adds infrastructure complexity outside the education target; (c) no Clone-able CommandContext until Phase 12; (d) shared-clause exchange requires a thread-safe clause database (out of scope). Deferred as a stretch wrapper in Phase 13 (ADR-21).
