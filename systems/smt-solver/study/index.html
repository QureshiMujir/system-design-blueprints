Mental Models & First Principles

# Model What it predicts Bug class without it Resolving §
MM1 Hash-consed identity = structural equality — two TermRefs are equal iff r1.0 == r2.0. No deep-compare anywhere. Any call to structural equality beyond == on TermRef is redundant at best, wrong at worst. Non-canonical references cause CC to miss equal terms. CC maintains two distinct roots for the same subterm → merged e-classes diverge → explain_eq gaps → unsound unsat claim. §8 Domain Model; §11 (TermBank); §7 INV-CANON; Ph2
MM2 DPLL(T) is DPLL + a T-oracle — the SAT core controls the Boolean structure; theories speak only via Propagation/T-conflict returns. Neither theory solver nor DPLL(T) loop may set a BoolVar directly. Every theory deduction must carry a reason set in the DPLL(T) trail. If a theory skips the Propagation channel the proof system has a gap. Theory solver writes BoolVar directly; SAT trail misses the reason → conflict analysis produces a clause without that literal → wrong unsat-core; possibly infinite loop. §3; §8 (DPLL(T) state machine); Ph4, Ph5; §7 INV-CONFLICT
MM3 Nelson-Oppen requires stably-infinite, disjoint theories — only then can equality propagation between theories be sound and complete. Finite-domain theories (BV) must stay eager. Any non-stably-infinite theory combined lazily will miss satisfying models that require a finite-domain witness. BV ↔ LRA lazy combination via N-O interface equalities → incomplete → unknown on decidable formula, or spurious sat. §3; §8 (DPLL(T) state machine); Ph9 (N-O combination); §9 ADR-12
MM4 Soundness before completeness before speed — every heuristic (f64 pivot scoring, VSIDS) must be a guide only; exact arithmetic (BigRational) decides. A float scoring heuristic for which variable to pivot is fine; using f64 to test feasibility at a bound is not. f64 feasibility check at a Simplex bound → rounding → false Unsat or false Sat for a lattice point — soundness failure. §4 SC-5; §7 INV-TABLEAU; Ph6, Ph7; Failure Modes & Recovery F-FLOAT
MM5 Learned clauses are valid theory lemmas — every clause added to the SAT core via add_clause must be a valid consequence of the already-asserted trail prefix. If a theory lemma is added that is not entailed by the current trail, the SAT core will use it in future conflict analysis and block valid branches. Bad theory lemma (reason set does not entail propagated literal) → DPLL(T) closes a satisfying branch → Unsat for a Sat instance. §7 INV-EXPLAIN; Ph4; Failure Modes & Recovery F-BADEXPL
MM6 Incremental solving is a stack of consistent states — push is a checkpoint; pop is an exact undo of every structure modified between the two calls. Any mutable structure (union-find, Simplex bound stack, blasted-var scope, learned clauses above the level) must undo cleanly, or residual state corrupts the post-pop check. Union-find merges not undone after pop → stale equalities survive → sat/unsat disagrees with from-scratch solve. §7 INV-INCR; Ph12 (incremental hardening); Failure Modes & Recovery F-INCR-LEAK
MM7 Congruence closure runs to fixpoint — a single merge(a,b) triggers merge(f(a),f(b)) which may trigger further merges; the pending-merge queue must drain entirely before CC is "closed". Premature return from merge leaves the closure in a non-fixed-point state, making explain_eq incomplete and theory propagation unsound. merge returns before pending queue drains → are_equal(f(a),f(b)) returns false even though a=b was asserted → missed T-propagation. §3; §7 INV-CC; Ph5; Failure Modes & Recovery F-CC-NT
MM8 Unsat-core correctness is a separate obligation — Unsat is correct if the conjunction is unsatisfiable; the core is correct only if it is a subset that is itself unsatisfiable and is a subset of the named assertions. These are different invariants. Re-checking the core independently (re-solve) is the only reliable test. Trusting the core without re-checking can produce cores containing spurious named assertions. Core includes an assertion not in the original named set → user mis-attributes the unsatisfiability → debugging entirely in the wrong place. §7 INV-CORE; Ph11; Failure Modes & Recovery F-BADEXPL

Applying the models in practice: MM1–MM8 form a diagnostic decision tree. When a result is suspect, ask in order: (1) is every interned term canonical? (MM1); (2) are all theory deductions through the propagation channel? (MM2); (3) did N-O get the theory classification right? (MM3); (4) is the feasibility test exact? (MM4); (5) is every learned clause valid? (MM5); (6) did every pop undo cleanly? (MM6); (7) did CC reach fixpoint? (MM7); (8) was the unsat-core re-checked? (MM8). This ordering covers ~95% of historical SMT solver soundness bugs documented in public postmortems (see Failure Modes & Recovery, F-FLOAT, F-INCR-LEAK, F-CC-CANON).

Cross-model interactions: MM1 (hash-cons) underpins MM7 (CC fixpoint) because congruence is detected via TermRef equality; if two TermRefs for the same term exist, congruence is never detected. MM2 (DPLL(T) channel) underpins MM5 (learned clauses) because the propagation channel is where the reason set is recorded. MM6 (incremental stack) underpins MM4 (exact arithmetic) at the Simplex level because warm-start carries the exact BigRational basis across a pop, and an imprecise carry-over would corrupt the next check_sat. Understanding these dependencies allows triaging S0 bugs without exhaustive state inspection.

Onboarding shortcut: A new contributor should internalize MM1 and MM2 in Phase 2–4 before touching MM3–MM8 in later phases. MM1 requires no context beyond §8; MM2 requires tracing one DPLL(T) loop iteration in §8's state-machine diagram and the §11 TheorySolver trait. Both can be verified against the Phase 4 unit tests before any theory code is written.

Glossary · 47 terms · site-wide glossary

ADR
Architecture Decision Record — immutable record of a design decision with rationale and rejected alternatives
AtomMap
Bijection between BoolVar (SAT variable) and a theory atom (TermRef of Bool sort)
BigRational
Exact arbitrary-precision rational number; num_rational::Ratio<BigInt>; the only numeric type in Simplex tableau cells
BitBlaster
Module in smt-theory/bv that lowers TermRef-level BV expressions to SAT clauses
BoolVar
Opaque u32 SAT-level variable handle, allocated by smt-sat (#277)
B&B
Branch-and-bound — the integer-feasibility search layered on top of Simplex for LIA
CDCL
Conflict-Driven Clause Learning — the modern DPLL algorithm in smt-sat (#277)
CommandContext
Top-level session state machine: holds TermBank, AtomMap, CommandResult, scope stack
CongruenceClosure (CC)
Algorithm maintaining the set of equalities implied by asserting a=b under function symbols
DPLL(T)
Davis-Putnam-Logemann-Loveland modulo Theory — lazy architecture pairing CDCL with theory solvers
EUF
Equality with Uninterpreted Functions — the theory of congruence closure
explain_eq
Method returning a set of asserted equality literals that entails a given equality; used for conflict minimization
final_check
TheorySolver call on a complete Boolean assignment; must either approve or produce a T-conflict
Gomory cut
Valid inequality derived from a fractional Simplex solution to cut off non-integer optima in LIA
Hash-consed DAG
Term representation sharing all structurally identical subterms; TermRef identity = structural equality
INV-
System invariant (see §7): CANON, SORT, CC, EXPLAIN, TRAIL, CONFLICT, ATOMMAP, TABLEAU, MODEL, CORE, INCR, NO-TERM
LIA
Linear Integer Arithmetic — the theory of linear constraints over the integers
LRA
Linear Real Arithmetic — the theory of linear constraints over the reals (rationals in practice)
Logic
One of the SMT-LIB 2.6 logics: QF_UF, QF_LRA, QF_LIA, QF_BV, QF_UFLIA, QF_AUFLIA; parsed from set-logic
MSRV
Minimum Supported Rust Version: 1.78
Nelson-Oppen (N-O)
Algorithm for combining two stably-infinite, disjoint theories via interface-equality sharing
Propagation
A theory-deduced literal (not a SAT decision) with a reason set; returned by TheorySolver::check
QF_
Quantifier-Free logic; logics with names prefixed QF_ exclude universal/existential quantifiers
Simplex
The dual Simplex method (Bland's rule for cycling prevention) over a BigRational tableau
SMT-LIB 2.6
The standard input language and command set for SMT solvers
SortRef
Opaque u32 handle for an interned Sort; allocated by TermBank
Symbol
Interned identifier string; u32 handle from a global symbol table
T-conflict
A theory-discovered unsatisfiable subset of currently asserted theory literals
TermBank
Arena allocator + hash-consing table for the global term DAG
TermRef
Opaque u32 handle into TermBank; identity implies structural equality
Tseitin encoding
Linear-time CNF transformation introducing one fresh BoolVar per non-atomic connective
UnsatCore
A named subset of assertions whose conjunction is unsatisfiable
VSIDS
Variable State Independent Decaying Sum — the decision heuristic in smt-sat (#277)
warm-start
Resuming Simplex from the previous basis after a push/pop delta, rather than re-initializing; correctness (not just performance) because the old basis is valid for the retained constraints
purification
Preprocessing step in Nelson-Oppen: replace mixed-theory terms with fresh variables to make each sub-formula belong to exactly one theory
Bland's rule
Pivot-selection rule for Simplex that selects the lowest-index eligible variable; prevents cycling at the cost of slower convergence
e-graph
The equality graph maintained by CongruenceClosure, consisting of equivalence classes of TermRefs linked by asserted and derived equalities
proof forest
The forest of parent-pointers in CongruenceClosure used to reconstruct the chain of equalities that justifies explain_eq(a,b)
NCA
Nearest Common Ancestor — the tree algorithm used in the proof forest to find the shortest explanation path between two equal TermRefs
stably-infinite
A theory is stably-infinite if every satisfiable formula over a finite domain has a model over an infinite domain; required by Nelson-Oppen for completeness
interface variable
In Nelson-Oppen combination, a variable shared between two theories (appears in atoms of both); equality sharing propagates over these
model validation
The always-on check after returning sat: evaluate(assert_i, model) == Value::Bool(true) for all i; failure downgrades to Unknown
SLSA
Supply-chain Levels for Software Artifacts — the attestation framework used to sign release binaries via GitHub OIDC
SolveStats
Snapshot of all performance and diagnostic counters after check_sat; returned by last_stats(ctx); never logged by the library
PAR-2
Penalised Average Runtime (×2): SMT-COMP metric where a timeout counts as 2× the time limit; used to compare solver portfolios fairly across hard/easy splits
2WL
Two-Watched-Literals — the watched-literal propagation scheme in smt-sat's clause database; enables O(1) amortized unit propagation per assigned literal
theory atom
A ground literal of non-Boolean sort appearing in a Boolean position (e.g., (= x y), (<= x 3), (= (f x) a)); allocated a BoolVar in AtomMap when first encountered
