4. System Constraints

Reference hardware: 16-core x86_64, 3.5 GHz, 32 MB shared L3, single-socket NUMA-free. The one defining property: hygiene correctness dominates throughput — every constraint below is a ceiling enforced to keep worst-case compile time bounded, never a target chased at the expense of I1–I14.

34. Back-of-Envelope Capacity Model

  1. Max sandbox instances = FD budget ÷ FDs-per-store = 4,096 ÷ 16 = 256 — matches §4's concurrency ceiling exactly.
  2. Max sustained warm procedural-macro rate = 1 ÷ M7(p50) = 1 ÷ 200 µs = 5,000 invocations/sec/core; × 16 reference cores (§4) = 80,000/sec ceiling before the sandbox itself becomes the bottleneck.
  3. Expansion bookkeeping memory per macro-heavy unit ≈ tokens/invocation (empirically ~40) × invocations (iteration-cap-bounded, 1,024) × bytes/token (Token + ScopeSet overhead ≈ 64 B) = 40 × 1,024 × 64 ≈ 2.6 MB — negligible against the 2 GiB ceiling (§4), implying the ceiling is dominated by AST size, not expansion bookkeeping (HQ15, §35).
  4. Worst-case fixpoint wall-clock = iteration cap × per-iteration cost. Per-iteration cost ≈ M5(p50) ÷ 1,000-invocation batch = 200 ms ÷ 1,000 = 200 µs/invocation; 1,024 × 200 µs ≈ 205 ms worst-case bound per unit before the cap trips — consistent with the M5/M9 budgets (§30).
  5. 100,000-line corpus token estimate ≈ 12 tokens/line (Rust-like density) × 100,000 = 1.2 M tokens; at lexer throughput 200,000 tokens/sec (§4) → 6 s lex time, leaving ~9 s of the 15 s M9 p50 budget for parse + expand + resolve.
  6. Differential-Racket corpus runtime ≈ corpus size (~500 fixtures) × avg per-fixture time (~1.2 s incl. Racket process startup) ≈ 600 s ≈ 10 minutes — the exact ceiling asserted in §23.4/M9's Phase-11 gate.
  7. FD headroom check = 256 stores × 16 FDs = 4,096 = exactly the §4 ulimit ceiling, leaving zero headroom for the host process's own FDs; production configs reserve 512 FDs for the host, so the effective sandbox ceiling becomes (4,096 − 512) ÷ 16 = 224 (operationally tighter than the nominal 256, per §21/ADR-28).
  8. 30-day fuzz canary statistical basis ≈ 2,000 exec/sec (typical cargo-fuzz throughput for a mid-size grammar) × 86,400 s/day × 30 days ≈ 5.18 billion executions — the basis for treating "0 panics" as meaningful evidence rather than coincidence (T10, M12, §23.2).
