  2. What specifically breaks if the resolver were allowed to see raw scope IDs directly instead of only the subset-check contract? — §19 (Phase 7), I8 (§7).

32. Mental Models & First Principles

  • MM1 — An identifier's identity is (name, scope-set), not name alone. Predicts two lexically identical tokens can refer to different bindings. Bug class without it: naive text-substitution capture. Applies §8 (Domain Model), §17 (Phase 5).
  • MM2 — Hygiene is a construction property of expansion, not a post-hoc check. Predicts you cannot bolt hygiene onto an expander after the fact — it must thread through every substitution step. Bug class without it: teams that try to "add hygiene later" end up rewriting the expander from scratch. Applies §17, ADR-02 (§9).
  • MM3 — A macro system has (at least) two phases: pattern/definition-time and expansion-time, and confusing them is the C-preprocessor's original sin. Predicts any design sharing one evaluation context between "the macro body" and "the expanded code" reintroduces capture. Bug class: token-paste bugs. Applies §8, §15 (Phase 3).
  • MM4 — Expansion is a fixpoint computation, and every fixpoint needs a convergence argument. Predicts that without an explicit termination bound (I4), some legal- looking macro will hang the compiler. Bug class: unbounded recursive-macro DoS. Applies §18 (Phase 6), I4 (§7).
  • MM5 — A sandbox boundary is only as strong as its narrowest capability leak. Predicts one ambient capability (clock, env var) left enabled defeats the entire sandbox's determinism guarantee. Bug class: "deterministic except on Tuesdays" bugs. Applies §21 (Phase 9), T2/T8 (§24).
  • MM6 — The resolver, not the expander, owns meaning. Predicts that keeping scope sets out of the type checker/codegen keeps phase separation clean and lets multiple front ends share one resolver contract. Bug class: a type checker accidentally depending on macro-internal scope IDs. Applies §19 (Phase 7), I8 (§7).
  • MM7 — A differential oracle only proves what its corpus covers. Predicts passing 100% of a differential suite is necessary, not sufficient, for hygiene correctness. Bug class: false confidence from a narrow corpus. Applies §23 (Phase 11).
  • MM8 — Determinism is a build property, not a runtime property. Predicts a system can pass every test yet be non-reproducible across machines if any nondeterministic source (hash-iteration order, wall clock) leaks in. Bug class: works-in-CI, fails-in- release builds. Applies §18 (Phase 6), P9/I2 (§6/§7).

5. Required Reading

Books

  • Dybvig, R. K. — The Scheme Programming Language, 4th ed. (MIT Press, 2009), Ch. 8 "Syntactic Extension". Extract: syntax-rules semantics, pattern variables, ellipsis quantifiers. Applied §15 (Phase 3).
  • Graham, P. — On Lisp (Prentice Hall, 1993), Ch. 7–19. Extract: variable-capture examples, anaphoric macros as deliberate capture (the exception that proves I1's rule). Applied §17 (Phase 5), §36 (AA3).
  • Hoyte, D. — Let Over Lambda (2008), Ch. 3–4. Extract: manual gensym hygiene discipline that automated hygiene replaces. Applied §17, MM2 (§32).
  • Queinnec, C. — Lisp in Small Pieces (Cambridge University Press, 1996), Ch. 12 "Macros". Extract: macro expansion modeled as an explicit compiler pass, hygienic vs non-hygienic expanders compared directly. Applied §8 (Domain Model), §18 (Phase 6).
  • Blandy, J.; Orendorff, J.; Tindall, L. — Programming Rust, 2nd ed. (O'Reilly, 2021), Ch. 20 "Macros". Extract: macro_rules! fragment specifiers, procedural macro crate types. Applied §15, §21 (Phase 9).
  • Butterick, M. — Beautiful Racket (2019, beautifulracket.com). Extract: reader/expander pipeline separation, macros as a language-construction tool. Applied §3, §22 (Phase 10).

Papers

  • Kohlbecker, Friedman, Felleisen, Duba — "Hygienic Macro Expansion" — LFP 1986. Foundational alpha-renaming algorithm. Applied §17, §36 (AA1).
  • Clinger, Rees — "Macros That Work" — POPL 1991. Syntactic closures. Applied §8, §17.
  • Dybvig, Hieb, Bruggeman — "Syntactic Abstraction in Scheme" — Lisp and Symbolic Computation, 1993. syntax-case and explicit renaming. Applied §36 (AA2), §17.
  • Flatt, M. — "Binding as Sets of Scopes" — POPL 2016. Current state of the art; Racket's and (since 2017) Rust's mechanism. Applied §17, §8.
  • Bawden, Rees — "Syntactic Closures" — LFP 1988. Precursor to Clinger-Rees. Applied §17.
  • Adams, M. D. — "Towards the Essence of Hygiene" — POPL 2015. High-level hygiene framing. Applied §17, MM1/MM2 (§32).
  • Tobin-Hochstadt, St-Amour, Culpepper, Flatt, Felleisen — "Languages as Libraries" — PLDI 2011. Racket's embedded-DSL framework. Applied §22 (Phase 10), §33.
  • Herman, D.; Wand, M. — "A Theory of Hygienic Macro Expansion" — Higher-Order and Symbolic Computation, 2008. Formal grounding for identifier identity. Applied §7 (I1, I3).
  • Culpepper, R.; Felleisen, M. — "Fortifying Macros" — ICFP 2010. Contracts on macro syntax (syntax-parse classes). Applied §15, §37 (deferred syntax-classes).
  • Flatt, Culpepper, Darais, Findler — "Macros That Work Together" — JFP 2012. Compile-time bindings, partial expansion, definition contexts. Applied §22 (Phase 10).

Reference Implementations

  • Racket — racket/racket, dir racket/src/expander/syntax/. Lesson: a production set-of-scopes implementation with binding tables. Pitfall to avoid: its multi-phase module-instantiation machinery is far beyond this project's scope — do not copy it wholesale. Applied §17.
  • rustc — rust-lang/rust, dirs compiler/rustc_expand/, compiler/rustc_resolve/. Lesson: hygiene via opaque SyntaxContext/ExpnId marks, a mechanism related to but distinct from pure set-of-scopes. Pitfall: rustc's resolver is coupled to whole-language name resolution — keep this project's resolver (§19) decoupled. Applied §19, §36 (AA discussion via HQ18).
  • Chez Scheme — cisco/ChezScheme, file s/syntax.ss. Lesson: syntax-case as explicit renaming. Pitfall: wrap composition is subtle without decades of hardening. Applied §36 (AA2).
  • Guile — gnu/guile, psyntax.pp. Lesson: a portable syntax-case used to bootstrap hygiene in a new Lisp. Pitfall: naive wrap composition is slow. Applied §36 (AA2).
  • dtolnay/syn + dtolnay/proc-macro2. Lesson: the de facto Rust procedural-macro-parsing/TokenStream boundary shape. Pitfall: syn's permissive parsing accepts more than rustc's real grammar — a "works with syn, rejected by rustc" bug class. Applied §21 (Phase 9).
  • SBCL — sbcl/sbcl, dir src/code/. Lesson: an unhygienic-by-default macro system that pushes hygiene onto the author via gensym. Pitfall: assuming manual gensym scales past small macros — this project's entire value proposition is eliminating that manual burden. Applied §36 (AA3).

RFCs / Specifications

  • R7RS-small (2013), Section 4.3 "Macros". syntax-rules normative surface. Applied §15.
  • R6RS (2007), Section 11.19 "Macro transformers" + non-normative syntax-case appendix. Applied §17.
  • The Rust Reference — "Macros" chapter (doc.rust-lang.org/reference/macros.html). Normative description of macro_rules! and procedural macros. Applied §15, §21.
  • rust-lang/rfcs — the "macros" label collection. Non-normative but historically load-bearing for macro_rules! hygiene tightening and procedural-macro stabilization. Applied §27 (Compatibility & Versioning).

Glossary (§38) · 39 terms · site-wide glossary

Alpha-renaming
the pre-1991 hygiene algorithm; rename every macro-introduced identifier to a fresh name (§36 AA1).
AllowedCaps
the sandbox capability manifest struct; all fields default false (§11, I11).
Ambiguous resolution
two or more equally-specific candidate bindings for one identifier use; a compile error, never a silent pick (I5, P10).
Bincode
the binary serialization format used across the sandbox TokenStream boundary (ADR-14).
Binding
a (name, scopes, kind, id) record the resolver matches identifier uses against (§11).
Capability manifest
the per-macro declaration of which sandbox capabilities (clock, network, random, …) it requires (P13, ADR-24).
Def-site (definition site)
the lexical position where a macro is defined; immutable across import/re-export (I6, P8).
Depth cap
the ceiling (64, §4) on macro-invocation nesting depth (I4).
Differential oracle
Racket's expander used as the correctness truth source (I12, ADR-10).
Ellipsis quantifier
the */+/? repetition operator in a pattern or template (§8.1 EBNF).
Expansion
replacing a MacroInvocation with its matched/substituted template (§16-17).
Fixpoint driver
the component iterating expansion until no invocations remain or a cap trips (§18, §11).
Fragment kind
a classifier for what a metavariable matches (expr, ident, pat, …, ADR-06).
Fresh scope
a ScopeId not previously allocated in the current compilation unit (I2).
Hermeticity
the property that identical (macro, input, seed) yields identical output across processes/machines (I7).
Hygiene
the property that macro-introduced identifiers never collide with caller identifiers of the same surface name (I1).
Identity (identifier)
the pair (surface name, scope set); two tokens are the same identifier iff both match (I1, MM1).
Intro scope
the scope attached to tokens from the macro's own definition during one expansion step (§8.3).
Invocation site
the source position where a macro is called.
Iteration cap
the ceiling (1,024, §4) on total fixpoint iterations per unit (I4).
MacroArm
one pattern => template rule inside a pattern macro's definition (§11).
MacroDef
the AST item representing a macro's definition, pattern or procedural (§11).
MacroInvocation
the AST node representing a macro call site, holding its unexpanded TokenStream (§11).
MacroTransformer
the shared trait pattern and procedural macros both implement (P2, §11).
Metavariable (metavar)
a pattern variable bound to part of the invocation's input ($x:expr).
Most-specific binding
among subset-matching candidates, the one with the largest scope set; the resolver's selection rule (§19.2).
Pattern macro
a macro defined by patterns and templates (declarative, §15-16).
Procedural macro
a macro defined by a sandboxed function mapping TokenStream to TokenStream (§21).
Re-export
exposing a macro defined in one module through another module's namespace, preserving def-site (§22, I6).
Resolver
the pass mapping identifier uses to bindings; the sole scope-set consumer (§19, I8).
Sandbox
the wasmtime-backed restricted execution environment for procedural macros (§21).
Scope set
the set of ScopeIds attached to a token, used for identity (§11).
Set-of-scopes
Flatt's 2016 hygiene algorithm; this project's locked choice (ADR-02).
Store pool
the bounded, reused set of wasmtime::Store instances behind the sandbox (§21.2, ADR-28).
Subset check
the resolver's test that a binding's scope set is a subset of a use's scope set (§19.2).
TokenStream
the input/output type of procedural macros and the raw payload of a MacroInvocation (§11).
Template
the right-hand side of a macro arm; substituted with bindings on match (§16).
Use-site scope
the scope attached to tokens from the caller during one expansion step (§8.3).
Wrap
the explicit-renaming representation used by syntax-case systems (§36 AA2).
