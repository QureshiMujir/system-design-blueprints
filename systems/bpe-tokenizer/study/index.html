32. Mental Models & First Principles

  1. MM1 — A pre-token is a merge arena, not a string. Once bytes enter the BPE loop they are arena-indexed nodes, never re-touched as &str. Predicts: any bug report mentioning "codepoint boundary" inside the merge loop is a category error. Bug class without it: accidental UTF-8 re-validation inside the hot path. Applied at §8.4, §14.
  2. MM2 — Rank is time. A merge's rank is literally "when training minted this token" — lower rank = earlier = higher encode priority. Predicts: two tokenizers with the same vocab but different training-corpus order can have different ranks and thus different encodes even on identical vocab contents. Bug class without it: assuming vocab-set equality implies encode-equality. Applied at §8.4, §9 (ADR-05).
  3. MM3 — The trie is a trust boundary, not a feature. Everything before SpecialTrie::scan is untrusted; everything after is tokenizer-internal. Predicts: any special-token bug report is either "the trie let something through it shouldn't" or "the trie ate bytes it shouldn't have" — never a BPE bug. Bug class without it: prompt-injection via regex-augmented specials (rejected at ADR-09). Applied at §3, §19, §24 (T3).
  4. MM4 — Determinism is a wire-compatibility guarantee, not a nicety. P9/I8's append-only MergeTable means "same input, same output, forever" is a promise to every downstream consumer who persisted an id. Predicts: any proposal to "just re-tie-break ties differently" is a breaking change requiring a major version bump. Bug class without it: silent train/serve skew after a library upgrade. Applied at §7 (I7–I9), §27.
  5. MM5 — Sharding beats locking when the update is commutative-ish. The pair-count delta (§15.2) is fold-associative across shards; a lock would serialize what sharding parallelizes. Predicts: any "just add a mutex" PR to the trainer is a regression, not a fix. Bug class without it: lock-contention collapse under high core counts. Applied at §9 (ADR-07), §15.
  6. MM6 — The byte level is the only level with no escape hatch. Every other segmentation (pre-tokenizer, special tokens, merges) can fail closed to "just bytes." Predicts: any "impossible to tokenize" bug report is a bug, not an expected outcome — P1 guarantees total coverage. Bug class without it: an unk-token reintroduction disguised as an edge case. Applied at §2, §8.1.
  7. MM7 — A format reader that panics is a format the ecosystem cannot trust with adversarial input. P13/I12's fail-closed discipline is what lets bpe-cli sit at a trust boundary (loading vocabs from arbitrary sources) safely. Predicts: any reader PR with an .unwrap() on file-derived data is a security regression, not a style nit. Applied at §9 (ADR-19), §24 (T1, T2).
  8. MM8 — Streaming is a two-pass discipline, not a single loop with a smaller buffer. Pass 1 (dedup) and Pass 2 (train) are separable because the trainer only needs (bytes, count), not corpus order (§8.2). Predicts: any attempt to "stream training directly" without the dedup pass re-derives an O(corpus_size)-working-set trainer, defeating the point. Applied at §21.

5. Required Reading

Books

  • Jurafsky & Martin, Speech and Language Processing, 3rd ed. draft, Ch. 2 (Regular Expressions, Text Normalization, Edit Distance). The BPE-training-algorithm sketch and its place among tokenization strategies. Applied in §8 (Domain Model) and Phase 0 (§12).
  • Cormen, Leiserson, Rivest, Stein, Introduction to Algorithms, Ch. 6 (Heapsort/Priority Queues) and Ch. 11 (Hash Tables). Binary-heap amortized cost and hash-table load-factor analysis. Applied in Phase 2 (§14, the pair priority queue) and Phase 3 (§15, sharded pair-count map).
  • Sedgewick & Wayne, Algorithms, 4th ed., Section 5.2 (Tries). R-way trie construction and longest-prefix-match traversal. Applied in Phase 7 (§19, SpecialTrie).
  • Gjengset, Rust for Rustaceans, Ch. 4 (Error Handling) and Ch. 9 (Unsafe Code). API design for fallible parsers and the discipline for confining unsafe to documented call sites. Applied in §11 (Core Schema & Types) and Phase 2 (§14, the arena).
  • Blandy, Orendorff & Tindall, Programming Rust, 2nd ed., Ch. 19 (Concurrency). Data-parallel rayon patterns and the shared-mutable-state pitfalls they avoid. Applied in Phase 3 (§15, sharded reduce).
  • Kleppmann, Designing Data-Intensive Applications, Ch. 3 (Storage and Retrieval, SSTables/external sort). External merge-sort over corpora larger than RAM. Applied in Phase 9 (§21, the streaming trainer).
  • Korpela, Unicode Explained, Ch. 7 (Character Properties) and Ch. 10 (Encodings). Unicode general-category classes and UTF-8 byte-structure. Applied in Phase 1 (§13, the GPT-2 regex) and Phase 8 (§20, the DFA splitter).

Papers

  • Sennrich, Haddow, Birch, 2016. "Neural Machine Translation of Rare Words with Subword Units." ACL. The algorithm this system implements. Applied in §8.2 (training) and Phase 3 (§15).
  • Gage, 1994. "A New Algorithm for Data Compression." C Users Journal. Original BPE. Applied in §8.2 (the pair-count → merge core loop).
  • Radford, Wu, Child, Luan, Amodei, Sutskever, 2019. "Language Models are Unsupervised Multitask Learners" (GPT-2). Section 2.2's byte-level commitment. Applied in §8.1 (byte alphabet) and Phase 1 (§13, the GPT-2 regex).
  • Kudo & Richardson, 2018. "SentencePiece: A Simple and Language Independent Subword Tokenizer and Detokenizer for Neural Text Processing." EMNLP. The no-pre-tokenization counter-argument. Applied in §36 (Alternative Architectures).
  • Kudo, 2018. "Subword Regularization: Improving Neural Network Translation Models with Multiple Subword Candidates." ACL. Unigram-LM regularization, the bar BPE-dropout must clear. Applied in Phase 10 (§22).
  • Provilkov, Emelianenko, Voita, 2019. "BPE-Dropout: Simple and Effective Subword Regularization." The regularizer this system implements at encode time. Applied in Phase 10 (§22).
  • Wu et al., 2016. "Google's Neural Machine Translation System: Bridging the Gap between Human and Machine Translation." WordPiece, the greedy-longest-match alternative. Applied in §9 (ADR-03) and §36 (Alternative Architectures).
  • Bostrom & Durrett, 2020. "Byte Pair Encoding is Suboptimal for Language Model Pretraining." The standing critique of BPE vs. unigram for LM pretraining. Applied in §35 (Hard Questions, Q12).
  • Mielke, Alyafeai, et al., 2021. "Between Words and Characters: A Brief History of Open-Vocabulary Modeling and Tokenization in NLP." The survey lineage. Applied in §2 (Why Build This) and §5 traceability generally.

Reference Implementations

  • OpenAI tiktoken (github.com/openai/tiktoken). src/lib.rs (encode loop), src/ tiktoken/load.rs (the .tiktoken format), tiktoken/_educational.py (byte-display mapping). Lesson: a tight Rust core with a thin Python surface. Pitfall not to copy: its encode loop assumes a trusted, pre-validated merge table and panics on a malformed one — we return Result instead (ADR-19). Applied in Phase 5 (§17) and Phase 2 (§14).
  • HuggingFace tokenizers (github.com/huggingface/tokenizers). tokenizers/src/models/ bpe/ (model), .../bpe/trainer.rs (training loop), .../tokenizer/serialization.rs (tokenizer.json). Lesson: pre-tokenizers, normalizers, post-processors as traits. Pitfall: its trait object graph makes the encode hot path allocate per stage — our arena avoids this. Applied in Phase 6 (§18) and Phase 3 (§15).
  • Karpathy minbpe (github.com/karpathy/minbpe). Three files of readable Python; the clearest correctness reference in the literature. Pitfall: it is O(n²) and single-threaded by design (teaching artifact) — never copy its performance profile, only its correctness. Applied in Phase 0 (§12) and Phase 3 (§15, the parity test).
  • Google SentencePiece (github.com/google/sentencepiece). The C++ no-pre-tokenization, unigram-capable reference. Lesson: a single self-contained normalization + segmentation model. Pitfall: its own on-disk protobuf format is a third format we deliberately do not add (ADR-08). Applied in §36 (Alternative Architectures).
  • fastBPE (github.com/glample/fastBPE). fastBPE.hpp's learnbpe/getvocab. Lesson: the parallel pair-count-and-merge training loop this system's Phase 3 adapts. Pitfall: its in-place std::vector mutation under OpenMP is not memory-safe under rayon's work-stealing model without the sharding discipline of §8.2 — we shard instead of locking. Applied in Phase 3 (§15).

RFCs / Specifications

  • Unicode Standard Annex #29 — Unicode Text Segmentation. Grapheme/word/sentence boundary reference. Applied in Phase 1 (§13, the Uax29Pretokenizer alternative).
  • Unicode Standard Annex #15 — Unicode Normalization Forms. NFC/NFD/NFKC/NFKD. Applied in §9 (ADR-13, NFC-off-by-default).
  • RFC 4648 — The Base16, Base32, and Base64 Data Encodings. The exact base64 flavor .tiktoken uses (standard, padded). Applied in Phase 5 (§17.1).

Glossary (§38) · 38 terms · site-wide glossary

Alphabet
the closed set of 256 byte values, ids 0..256, that every input decomposes into before any merge (§8.1).
AllowedSpecial
the caller-supplied policy (Default/All/Set/None) governing which special tokens may be matched in a given encode call (§8.5).
Arena
the pre-allocated backing store (Vec<Node>) for the intrusive doubly-linked pre-token structure, avoiding per-merge heap allocation (§11.6).
BPE (Byte-Pair Encoding)
the algorithm that iteratively replaces the most frequent adjacent symbol pair with a new symbol (Gage 1994; Sennrich et al. 2016).
BPE-dropout
Provilkov et al.'s regularization technique: skip a candidate merge with probability p during encode (§22).
Byte-level BPE
BPE applied over the 256-byte alphabet rather than characters, closing the unk-token gap (Radford et al., GPT-2).
Corpus
the training text, consumed as a stream (CorpusInput) rather than fully materialized (§11.7, §21).
DFA splitter
the hand-rolled finite-automaton pre-tokenizer implementing the GPT-2 pattern at higher throughput than fancy-regex (§20).
Dedup table
the deduplicated (pre-token bytes, count) structure training operates over instead of raw corpus order (§8.2, §21.1).
Determinism
the guarantee that a fixed merge table and input bytes always produce the same output, across machines/threads/versions (I7, P3).
Display mapping
the GPT-2-style remap of non-printable byte values to U+0100+ codepoints for human-legible vocab inspection, distinct from the underlying identity byte map (§8.1).
Encode
the process of turning &str/&[u8] input into a Vec<TokenId> (§8.4, §11.6).
EncoderScratch
the thread-local arena + priority queue + byte buffer reused across encode calls to avoid allocation (§11.6, P11).
Fixture
a named, versioned test input/expected-output pair in conformance/corpora/ (§12.5 et seq.).
fancy-regex
the Rust regex engine with lookaround support, used for the default GPT-2 pre-tokenizer (ADR-04).
Fuzz target
a cargo-fuzz harness exercising one invariant under adversarial mutation (§23.2).
GPT-2 pattern
the specific regex 's|'t|'re|'ve|'m|'ll|'d| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+ (§8.3).
Lazy invalidation
the priority-queue technique of leaving stale entries in place and checking validity only at pop time (§14.2, I6).
Merge
a (left, right) -> merged_id rule with a rank, produced by training (§8.2, §11.3).
MergeTable
the append-only, rank-ordered collection of all learned merges (§11.3, P9).
Pair-count map
the sharded (TokenId, TokenId) -> u64 frequency structure driving merge selection during training (§8.2, §15.2).
Parity test
a differential test asserting byte-identical output between this system and a reference implementation (minbpe, tiktoken, HF tokenizers) (§15, §17, §18).
Pre-token
a contiguous byte span the pre-tokenizer regex yields, inside which BPE may freely merge (§8.3, P2).
Pretokenizer
the trait abstracting the pre-tokenization strategy (GPT-2/Llama3/ Whitespace/UAX29/DFA) (§11.5).
Priority queue
the binary heap ordering candidate merges by (rank, insert_seq) for the encode-time greedy loop (§14.2, ADR-05).
Rank
a merge's position in training emission order; lower rank = higher encode priority (§8.2, I8).
Reduce (sharded)
folding per-shard pair-count deltas into the global PairCounts before the next top() read, never concurrently with it (§15.2, P10).
Round-trip
decode(encode(s)) == s for valid UTF-8 s; the system's core correctness contract (I10).
Shard
a partition of the deduplicated corpus (or the pair-count map) processed independently by one rayon task (§15.2, ADR-07).
SpecialToken
a literal byte sequence matched at the input boundary, bypassing BPE entirely (§8.5, §11.4).
SpecialTrie
the R-way byte-trie performing longest-prefix-match special-token scanning (§11.8, §19.1).
Streaming training
the two-pass (dedup, then train) discipline enabling corpora larger than RAM (§21, MM8).
Tie-break
the deterministic lexicographic rule ((left_id, right_id) ascending) resolving equal-count pairs during training (I9, §16.1).
TokenId
the u32 newtype identifying a byte or a learned merge (§11.1).
.tiktoken format
OpenAI's line-oriented on-disk vocabulary format: base64(bytes) rank per line (§17, §26.7).
tokenizer.json format
HuggingFace's JSON on-disk schema for a BPE model plus pre-tokenizer/decoder/added-tokens metadata (§18.1).
Vocab
the id↔bytes bidirectional mapping plus the special-token registry (§11.2).
Wire compatibility
the guarantee that a serialized vocab decodes identically forever, independent of library version (§27, P9).
