Seven properties, referenced throughout: (1) Bytes are ground truth — text is decoded once into &[u8] at the boundary; ids 0..256 are the byte alphabet, ids >=256 are learned merges (§8.1, I1). (2) The pre-tokenizer is a regex, not a tokenizer — its only job is to bound where BPE may not merge across (§8.3, P2). (3) The BPE merge is greedy, deterministic, priority-driven — lowest-rank pair wins, ties break left-most (§8.4, I6). (4) Special tokens bypass BPE entirely — matched by trie before pre-tokenization, never after (§8.5, P6, I5). (5) Training and encoding share the merge table, not the code — a trained tokenizer is a pure value (§11.2–§11.3, P7). (6) The encode hot path is allocation-free per pre-token — the EncoderScratch arena amortizes to one allocation per program run (P11, M3). (7) The trust boundary is at the SpecialTrie — everything past it is untrusted bytes; everything before Optional-kind special matching is where prompt-injection defenses live (T3, §19.3).

8. Domain Model

8.1 Byte-level alphabet

The alphabet is TokenId(0)..TokenId(256), identity-mapped to byte values (I1). Display-only, the on-disk formats render bytes 0–32/127–160/173 via a "printable-ish" remap to U+0100+ (the GPT-2 convention, tiktoken/HF-compatible) so bpe inspect output is human-legible; the identity mapping underneath never changes. PRINTABLE_BYTES = the 188 byte values 33–126, 161–172, 174–255 that map to themselves.

8.2 Training: pair-count → merge

State table (per training epoch):

Step Input state Operation Output state
1 raw corpus stream pre-tokenize (§8.3), dedup to (bytes, count) ShardedCorpus
2 ShardedCorpus per-shard adjacent-pair count (rayon fan-out) per-shard PairCounts
3 per-shard PairCounts reduce: pick global top pair, tie-break by I9 (pair, count)
4 (pair, count) if count < min_pair_count: stop; else mint TokenId, MergeTable::push new merge, rank r
5 new merge apply in place across all shards; emit ±count deltas for neighbor pairs updated ShardedCorpus, PairCounts
6 updated state repeat from step 3 until vocab.len() == target_vocab trained Vocab + MergeTable

Worked example (toy corpus "aaab" x3, "abab" x2, min_pair_count=2): byte ids a=97,b=98. Pair counts: (97,97)→3, (97,98)→5, (98,97)→2. Merge 1: (97,98)→TokenId(256) ("ab"), rank 0 (highest count 5). Re-scan: "aaab"→[97,256,... ] becomes [97,97,256] per token; "abab"→[256,256]. New pair counts: (97,97)→3 (unchanged, no a,a pair touched), (97,256)→3, (256,256)→2. Merge 2 (tie between (97,97)@3 and (97,256)@3, I9 tie-break picks lexicographically smaller (97,97)): mint TokenId(257) ("aa"), rank 1. Training halts at target_vocab or when the max remaining count < min_pair_count.

Malformed-input example: a pre-token whose byte sequence is not valid UTF-8 at a chunk boundary (a corpus reader split mid-codepoint) is handled by re-validating at the &str boundary per §8.3 — the trainer operates on &[u8] post-pre-tokenization and never requires codepoint alignment past that point, so a split multi-byte sequence degrades to two shorter pre-tokens rather than corrupting state (I12's discipline applied to the trainer, not only the readers).

Failure-path example: if counts.top() returns a pair whose count was already decremented to zero in a prior shard's delta but not yet reduced (a race in delta application order), the sharded-reduce-then-apply ordering in step 5→3 (never concurrent) makes this unreachable by construction — deltas are folded into the global PairCounts before the next top() call, per ADR-07's "no lock across a task boundary, but reduce before the next read" discipline.

8.3 Pre-tokenization regex

GPT-2 pattern: 's|'t|'re|'ve|'m|'ll|'d| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+ (EBNF-equivalent below). The pre-tokenizer trait contract: yields (start, end) byte offsets into input that partition it — every byte in exactly one pre-token, in order (P2).

pretoken     ::= contraction | word | number | punct-run | ws-trailing | ws-run
contraction  ::= "'s" | "'t" | "'re" | "'ve" | "'m" | "'ll" | "'d"
word         ::= [" "]? letter+          ; letter = \p{L}
number       ::= [" "]? digit+           ; digit  = \p{N}
punct-run    ::= [" "]? (not-space-letter-digit)+
ws-trailing  ::= space+                  ; lookahead: not followed by non-space
ws-run       ::= space+

8.4 Encode via merge application

Inside one pre-token: build a doubly-linked list of byte-level TokenIds in an arena; seed a priority queue with every adjacent pair that has a MergeTable entry, ordered (rank, insert_seq); pop the lowest-rank valid entry, fuse the pair, push newly adjacent candidate pairs, repeat until the queue is empty (I6). State per merge step:

Field Meaning
rank merge's position in training emission order (lower = higher priority)
left_node / right_node arena indices of the two nodes being fused
insert_seq monotonic counter breaking rank ties deterministically, left-to-right
live false once a node has been fused away; queue entries referencing it are stale

8.5 Vocab & special tokens

Vocab = {bytes: Vec<Vec<u8>>, by_bytes: HashMap<Vec<u8>, TokenId>, specials: BTreeMap<TokenId, SpecialToken>}. A SpecialToken is {id, bytes, kind} where kind ∈ {Regular, Optional}. Regular specials (e.g. <|endoftext|>) are always matched by SpecialTrie::scan; Optional specials are matched only when the caller's AllowedSpecial set includes them — the default caller posture for untrusted text is AllowedSpecial::Default with Error on an unexpected literal special-token sequence (the prompt-injection defense, T3).

Design principles (§6)

  • P1 — Byte-level invariant. The alphabet is the 256 byte values; every input maps to &[u8]; no unk token exists. Tradeoff: merges may cross UTF-8 boundaries. Violating it (e.g. char-level fallback) reintroduces unk and breaks I1.
  • P2 — Pre-tokenizer bounds, never tokenizes. The regex only prevents cross-run merges; it never assigns ids. Violating it (letting the regex assign ids) collapses the pre-tokenizer and BPE stage into one, breaking format compatibility (§17–§18).
  • P3 — Determinism guarantee. Same merge table + same bytes ⇒ same Vec<TokenId>, on every machine, thread count, and version, except the seeded encode_with_dropout. Enforced by I7.
  • P4 — Streaming-corpus support. Training working-set is O(vocab_size + active_pretokens), never O(corpus_size). Violating it caps trainable corpus size at RAM (breaks §4's 100 GB target).
  • P5 — Format compatibility, exactly two. .tiktoken and tokenizer.json, both emitted and loaded from one Tokenizer value (ADR-08). A third format is scope creep and an interoperability trap.
  • P6 — Special-token isolation. Specials are matched by trie before pre-tokenization, never inside the regex. Violating it chops literal special-token bytes into regex runs and BPE merges them wrongly (§19.5's regex-augmentation trap).
  • P7 — Training/encode symmetry. The value that trains is the value that encodes; no separate "trained model" object with divergent state. Violating it risks train/serve skew.
  • P8 — Regex-engine choice is an ADR, not an accident. fancy-regex for lookaround (ADR-04); the DFA (Phase 8) is a documented, feature-flagged optimization of the same contract, never a silent behavior change.
  • P9 — Vocabulary stability (append-only). A (pair, rank) once in the table never moves; wire compatibility is a determinism guarantee across versions (I8).
  • P10 — Memory-safe parallelism via sharding, never locking across a task boundary. The pair-count map is sharded by pair_hash % N; no lock is held across a rayon task boundary (ADR-07). Violating it (a global mutex) makes the lock the bottleneck.
  • P11 — No-allocation hot path. One call to encode allocates exactly the output Vec<TokenId>; all intermediate state is arena-backed and thread-local (M3). Profile-guided via dhat (Phase 2 gate).
  • P12 — Locale-neutral. No behavior depends on OS locale; no to_lowercase/ to_uppercase; explicit Unicode flags only. Violating it makes tokenization machine-dependent, a determinism (I7) breach.
  • P13 — Fail closed on malformed on-disk state. A reader returns a typed Error, never panics, on a malformed .tiktoken/tokenizer.json line (I12). Violating it turns a corrupt file into a process crash instead of an operator-visible error.
