Four properties recur throughout this document. First, repair is three separate mechanisms, not one (P2, §6): read repair fixes divergence on the keys clients are actually touching; hinted handoff buffers writes for a transiently-down replica; active anti-entropy (Merkle gossip) reconciles ranges nobody is reading or hinting about. Dropping any one creates a distinct persistent-divergence class (§24, Failure Modes). Second, the conflict resolver is pluggable, not baked-in (I9, §7): LWW+HLC is the default; siblings and CRDT merge are consumers of the same Resolver trait (§11.7), not special cases. Third, the network protocol is fingerprint-first, payload-second (§13.2): a Merkle root is 32 bytes; fingerprints are gossiped every cycle and only leaf payloads are shipped once divergence is localized — the Back-of-Envelope Capacity Model (§33) quantifies this. Fourth, the Disagreement Event Log is the system's observability surface: every repair trigger, every located divergent leaf, every resolver decision emits a telemetry event (I11, §7) that both operators and the adaptive scheduler (§14.4) consume.

8. Domain Model / Protocol / Data Model

8.1 Wire protocol (ae-net)

Messages are length-prefixed CBOR (RFC 8949) over Tokio TCP (ADR-16); QUIC is deferred (ADR-20, §20). Every message begins with a 4-byte big-endian length prefix, then the CBOR payload. Three message families:

FingerprintExchange   { range_id: RangeId, root_hash: Hash256, depth: u8,
                         leaf_count: u32, generation: u64 }
SubtreeQuery          { range_id: RangeId, node_index: u32 }
SubtreeReply          { range_id: RangeId, node_index: u32, hash: Hash256 }
IbltExchange          { range_id: RangeId, cell_count: u32, hash_count: u8,
                         seed: u64, cells: Vec<CellWire> }
HintReplayBatch       { batch_id: u64, hints: Vec<HintWire> }
HintReplayAck         { batch_id: u64, delivered: u32, failed: u32 }

Field types reuse ae-core's canonical types (RangeId, Hash256, Hint → HintWire); no protocol-local type shadows a core type under a different name (the terminology-lock discipline this document holds throughout).

8.2 Repair-task state machine

Queued ────────► InFlight ───────────► Applying ───────────► Done
  │                  │  timeout/error         │  resolver error

  │                  │  retries exhausted

Transitions: Queued → InFlight on scheduler dispatch (respecting I12/I13); InFlight → Applying on successful fingerprint/IBLT exchange; Applying → Done on successful resolver + write-back; InFlight/Applying → Failed on RPC error or resolver panic; Failed → Retrying up to max_retries (default 3, exponential backoff 1s/2s/4s); Retrying → Abandoned past max_retries, logged and re-queued at Background priority on the next gossip cycle rather than dropped outright (active anti-entropy is the backstop, P2).

8.3 Worked example — convergence trace

Replica A holds key1 → ("old", Hlc{physical:100, logical:0, node:1}). Replica B holds key1 → ("new", Hlc{physical:100, logical:1, node:1}). Gossip cycle fires: A sends FingerprintExchange{root_hash: R_a} to B; roots differ; recursive SubtreeQuery/ SubtreeReply descends to the single divergent leaf containing key1; both sides fetch the leaf's entries; LwwResolver::resolve([("old", ts=100.0.1), ("new", ts=100.1.1)]) returns Single(("new", ts=100.1.1)) (I3's lexicographic order: logical 1 > 0); the write-back applies ("new", ...) to A. Both replicas' Merkle roots for that range now match (I1).

8.4 Malformed-input example

A SubtreeQuery arrives with node_index exceeding the local tree's 2^depth - 1 bound (e.g. the peer's tree has a stale, pre-split depth). The receiver rejects with a RangeGenerationMismatch error (checked against the generation field of the last exchanged FingerprintExchange, §8.1) rather than indexing out of bounds; the gossip scheduler treats this as Failed → Retrying, and on repeated mismatch escalates to a full-range re-fingerprint (bypassing the stale cached tree).

8.5 Failure-path example

Mid-IbltExchange, the peer disconnects (TCP RST). The in-flight repair task transitions InFlight → Failed (detection: RPC future resolves to Err(Error::PeerUnreachable)); ae_repair_ranges_total{outcome="peer_unreachable"} increments; the task retries with backoff; if the peer remains unreachable past 3 retries the range moves to Abandoned and is re-queued at Background priority — active anti-entropy will pick it up again next cycle rather than starve it indefinitely (P11).

Design principles (§6)

  • P1 — Eventual consistency is contractually correct only if the repair protocols converge. Rule: "eventual" without a bounded-convergence proof is a marketing word. Tradeoff: proving convergence requires the property-test infrastructure of §27, which is nontrivial engineering effort up front. Operational implication: every release gates on the convergence property suite, not just unit tests. Violating it: the system silently accumulates divergence with no detection.
  • P2 — Three reconciliation mechanisms, not one. Rule: read repair, hinted handoff, and active anti-entropy are complementary and all three must be present (§3). Tradeoff: more surface area to build and operate than a single mechanism. Operational implication: dashboards must track all three independently (§25). Violating it: skipping any one creates a distinct persistent-divergence class (§24, FM-1..FM-3).
  • P3 — Merkle trees are the bandwidth-optimal full-range primitive at moderate divergence. Rule: for d divergent keys of N total, Merkle costs O(d log N) fingerprints plus O(d) payload. Tradeoff: IBLT beats Merkle when d is small (sub-thousand) and loses when d is large or unbounded (§19.3). Operational implication: the fallback threshold (ADR-14) must be tuned per workload. Violating it: using IBLT unconditionally causes decode failures under high divergence with no recovery path.
  • P4 — Gossip-driven scheduling beats centralized scheduling for fault tolerance. Rule: each node decides locally which peer to reconcile with this cycle (§14.1). Tradeoff: harder to reason about global repair progress than a central scheduler. Operational implication: convergence proofs rely on Karp-Schenker-Shenker (§6 Papers) not on operator intervention. Violating it: a central scheduler is a single point of failure and a single point of policy.
  • P5 — Hinted handoff is bounded, never unbounded. Rule: hints spill to disk, then drop with telemetry past a hard cap (ADR-09, ADR-10). Tradeoff: dropped hints rely on active anti-entropy to converge, delaying full correction. Operational implication: the drop counter (ae_hint_drops_total) must alert. Violating it: an unbounded queue for a permanently-down replica exhausts disk (I4, §7).
  • P6 — Synchronous read repair adds latency; default off for high-throughput paths. Rule: the added cost is one replica round-trip plus a write-back (§16.4). Tradeoff: asynchronous (probabilistic) repair converges slower per-key but never blocks the read path. Operational implication: the default is asynchronous at a 10% sample rate (ADR-11); synchronous is opt-in per request. Violating it: p99 latency explodes on any workload with frequent divergence.
  • P7 — Conflict resolution requires a total order; LWW+HLC is the pragmatic default. Rule: plain wall-clock LWW lets clock skew pick the winner instead of causality (§18.1). Tradeoff: HLC requires a monotone, persisted clock (blueprint #95). Operational implication: HLC state must survive process restart (I7, §7). Violating it: a slow-clock node loses every conflict regardless of causal order.
  • P8 — Siblings are correct but unfriendly; expose as opt-in. Rule: applications that need custom merge can request the sibling list (§18.2). Tradeoff: default callers never see siblings and get LWW; opt-in callers own the merge complexity. Operational implication: sibling-count histograms (ae_sibling_count) must be monitored per keyspace. Violating it: forcing siblings on all callers pushes merge complexity onto applications that do not need it.
  • P9 — CRDTs eliminate conflict resolution at the cost of API constraints. Rule: blueprint #55's CRDT types plug into the Resolver trait (§11.7). Tradeoff: only CRDT-expressible state benefits; arbitrary application state falls back to LWW/siblings. Operational implication: adopting CRDTs is a per-keyspace migration, not a global default. Violating it: forcing CRDTs everywhere constrains the data model unnecessarily.
  • P10 — Set reconciliation via IBLT trades CPU for bandwidth. Rule: constructing and decoding an IBLT costs more CPU than a Merkle build, but wire cost is O(d) not O(d log N) (Minsky-Trachtenberg-Zippel 2003; Eppstein et al. 2011). Tradeoff: bandwidth-constrained links (cross-DC, mobile) prefer IBLT; CPU-constrained nodes prefer Merkle. Operational implication: the d_expected cell-count parameter is per-range tunable (§19.3). Violating it: fixed cell budgets either waste bandwidth or fail to decode.
  • P11 — Repair is never "finished." Rule: there is no terminal "repaired" state; the gossip scheduler runs forever (§14). Tradeoff: metrics must track rate of reconciliation, not a binary done/not-done. Operational implication: operator runbooks must never promise "repair complete," only "converged as of gossip round N." Violating it: an operator who believes repair "finishes" will miss ongoing cold-range drift.
  • P12 — Conformance is the contract. Rule: the conformance suite (§27) gates every release; property tests for convergence, Merkle correctness, hint durability, resolver determinism, and IBLT decoding are merge gates, plus a 30-day Jepsen-style soak. Tradeoff: slower release cadence than "ship and monitor." Operational implication: a red conformance bucket blocks release regardless of urgency. Violating it: undetected regressions ship to production reconciliation logic — the worst possible place for a silent bug.
  • P13 — Repair-induced load amplification is a footgun. Rule: a scheduler that accelerates repair under high divergence can cause the very partition it was meant to heal (Datastax's 2015 incident, cited in §24 FM-5). Tradeoff: the token bucket (ADR-06 successor at §14.3) caps throughput even when divergence is severe, extending wall-clock convergence time. Operational implication: the 25 MB/s per-(peer,range) default (§4) is non-negotiable without an explicit override. Violating it: repair traffic amplifies the incident it is trying to fix.
  • P14 — Observability is built-in, not bolted-on. Rule: every reconciliation event (repair start, divergent-leaf located, hint dropped, sibling created, conflict resolved) emits a Prometheus metric and a structured log line (§21.2). Tradeoff: instrumentation overhead on the hot path (bounded, measured in §29). Operational implication: the operator runbooks (§21.3) exist from Phase 9, not "written after production breaks." Violating it: an operator debugging a stuck repair at 3 a.m. with no telemetry.
