Decisions (§9) · 24 ADRs

ADR-01

Workspace language

Chosen

Rust 1.78+ (edition 2021)

Rejected

Go, C++, Java/JVM, Zig

When the rejected choice is right

Go wins when team Rust experience is near-zero and time-to-first-prototype dominates over long-run latency guarantees

Why: Memory safety without GC pause; mature async + fuzz tooling (§1)

ADR-02

no_std core crates

Chosen

ae-core, ae-merkle, ae-iblt are no_std + optional alloc

Rejected

Full std everywhere

When the rejected choice is right

std-everywhere wins when there is no embedded/WASM target and the extra crate-boundary discipline has no payoff

Why: Embedded/WASM consumers need it; std-bound crates wrap with async + storage

ADR-03

Async runtime

Chosen

Tokio

Rejected

smol, async-std

When the rejected choice is right

smol wins in a minimal single-purpose binary where Tokio's feature surface is pure overhead

Why: Ecosystem dominance; select! + bounded mpsc are load-bearing (§14, §17)

ADR-04

Merkle hash function

Chosen

BLAKE3

Rejected

SHA-256, SHA-512, KangarooTwelve

When the rejected choice is right

SHA-256 wins when FIPS-140 certification is a hard compliance requirement and BLAKE3 lacks an approved module

Why: Faster at relevant input sizes; built-in tree mode; 256-bit digest fits fingerprint size (§13.1)

ADR-05

Hint persistence

Chosen

RocksDB

Rejected

sled, LMDB

When the rejected choice is right

sled wins for a pure-Rust dependency constraint where RocksDB's C++ toolchain is unacceptable and the data-loss class is mitigated elsewhere

Why: Bounded log compaction; column-family-per-target gives efficient drain (§15.2); sled rejected for issue #1124 data-loss class; LMDB rejected for mmap fragility under power-loss

ADR-06

Gossip cycle period

Chosen

1 s intra-DC default

Rejected

100 ms, 10 s

When the rejected choice is right

100 ms wins on small clusters (N < 50) where sub-second convergence is required and bandwidth is not the bottleneck

Why: Karp-Schenker-Shenker (§5) gives O(log N)-round convergence; 1 Hz × N=1000 ≈ 10 s to disseminate cluster-wide

ADR-07

Merkle leaf granularity

Chosen

16-bit prefix (65,536 leaves) default

Rejected

8-bit, 24-bit prefix

When the rejected choice is right

24-bit wins on ranges > 100 M keys where leaf-level payload amplification would otherwise dominate

Why: ~16 keys/leaf at 1 M-key range balances tree depth vs. leaf payload size (§13.1)

ADR-08

Repair concurrency limit

Chosen

4 ranges/node default

Rejected

1, unbounded

When the rejected choice is right

Unbounded wins only inside the deterministic simulator (§10) where there is no real network/CPU contention to amplify

Why: Balances load amplification (P13) against wall-clock repair time

ADR-09

Hint queue cap

Chosen

4 GiB total default

Rejected

512 MiB, unbounded

When the rejected choice is right

512 MiB wins on memory-constrained edge deployments where active anti-entropy is cheap to lean on more heavily

Why: A 24 h-down replica at 1 KB/hint, 1 K writes/s ≈ 86 GB uncapped; 4 GiB bounds worst case and forces active-anti-entropy handoff

ADR-10

Hint TTL

Chosen

24 h default

Rejected

1 h, 7 days

When the rejected choice is right

1 h wins on high-write-rate keyspaces where hints are almost always stale well before 24 h

Why: Matches Cassandra's default; older hints are usually superseded (§15.4)

ADR-11

Read-repair sampling rate

Chosen

10% async default

Rejected

1%, 100%

When the rejected choice is right

100% wins only as a short-lived, operator-triggered manual repair window (ADR-11 note, §17.5) — the standing production default stays 10%

Why: Cassandra's default; balances coverage vs. added load (P6)

ADR-12

LWW timestamp source

Chosen

HLC (blueprint #95)

Rejected

plain wall-clock, pure vector clock

When the rejected choice is right

Pure vector clocks win when the application wants explicit sibling exposure instead of a forced total order (→ ADR-13's Siblings path)

Why: Plain wall-clock is broken under skew (P7); pure vector clocks lack a total order for LWW

ADR-13

Sibling exposure

Chosen

Opt-in per keyspace (SiblingsResolver)

Rejected

Always-on (Riak-style global allow_mult)

When the rejected choice is right

Always-on wins for a store whose entire API contract is "you always resolve conflicts yourself" (pure Riak deployment model)

Why: Default callers should not see merge complexity they did not ask for (P8)

ADR-14

IBLT cell count

Chosen

c × d_expected, c ≈ 1.5

Rejected

c = 1.0, c = 3.0

When the rejected choice is right

c = 3.0 wins when decode-failure probability must be near-zero and bandwidth is not the binding constraint

Why: Eppstein 2011 §4's safe over-provisioning for the 3-hash variant (§19.1)

ADR-15

IBLT fallback

Chosen

Fall back to Merkle on Exhausted

Rejected

No fallback (hard fail)

When the rejected choice is right

No fallback wins only in a context where d_expected is provably an upper bound (e.g. bounded write-rate + bounded outage window)

Why: Bounds worst-case correctness; accept O(d log N) cost on fallback (§19.4)

ADR-16

Wire serialization

Chosen

CBOR (RFC 8949, ciborium)

Rejected

Protobuf

When the rejected choice is right

Protobuf wins when cross-language (non-Rust) clients must interoperate with the wire protocol directly

Why: CBOR is compact, schema-less, has mature Rust support; Protobuf rejected for schema-evolution overhead (§8.1)

ADR-17

Constant-time cell-hash comparison

Chosen

subtle crate for IBLT check-hash equality

Rejected

plain ==

When the rejected choice is right

Plain == wins wherever the comparison is provably not on any security-relevant path and the subtle dependency is unwanted

Why: Defensive discipline carried over from cryptographic blueprints; IBLT decode is not security-sensitive but consistency of practice matters

ADR-18

Licensing

Chosen

Apache-2.0 + MIT dual

Rejected

GPL-family, proprietary

When the rejected choice is right

GPL wins when the deploying organization requires copyleft to prevent proprietary forks

Why: Standard Rust ecosystem dual-licence convention

ADR-19

Metrics format

Chosen

Prometheus exposition

Rejected

StatsD, OpenTelemetry-only

When the rejected choice is right

OpenTelemetry-only wins in an org that has already standardized entirely on OTLP pipelines with no Prometheus scraper

Why: Industry default; prometheus crate stable; §27's conformance suite parses /metrics directly

ADR-20

Cross-DC transport

Chosen

TCP now, QUIC deferred

Rejected

QUIC from day one

When the rejected choice is right

QUIC from day one wins when the initial deployment target is already WAN-heavy with many short-lived cross-DC connections

Why: Amortized handshake cost matters most at scale; TCP is simpler to ship first (§20; PhaseDeferred("§20"))

ADR-21

Streaming/dataflow convergence

Chosen

Deferred; polled gossip is Phase 0–10

Rejected

Differential-dataflow (Naiad-style) incremental convergence

When the rejected choice is right

Naiad-style dataflow wins at very large N where polling overhead itself becomes the bottleneck (§30)

Why: Polled gossip is simpler to reason about and test first (§35.3)

ADR-22

Byzantine tolerance

Chosen

Out of scope; honest-but-down assumption

Rejected

Signed Merkle proofs (BFT)

When the rejected choice is right

Signed proofs win the instant replicas cross an untrusted trust boundary (multi-tenant, federated deployment)

Why: Complexity not justified absent a multi-tenant trust boundary (§23.1); Project #94 owns BFT

ADR-23

ML-driven repair scheduling

Chosen

Deferred

Rejected

Static/adaptive-formula scheduling (§14.4)

When the rejected choice is right

ML scheduling wins once historical ae_repair_ranges_total time series exist at sufficient volume to train on (§35.4)

Why: No divergence-prediction dataset exists yet; formula-based adaptive throttling is provably correct today

ADR-24

Formal verification of Merkle localisation

Chosen

Deferred; property-tested only (§27)

Rejected

Machine-checked Coq proof

When the rejected choice is right

Coq proof wins when the deployment is safety-critical enough that a property-test gap is unacceptable (§27 note)

Why: Property testing is cheaper and catches the practical bug classes; formal proof is a stretch investment

Roads not taken (§35)

Whole architectures the blueprint considered and rejected, each with the regime where it would win.

Pure-CRDT convergence (no Merkle/IBLT at all)

Replica A ──merge(CRDT)──► Replica B ──merge(CRDT)──► Replica C
     ▲                                                     │
     └─────────────────── gossip full CRDT state ──────────┘

Regime where it wins: applications whose entire data model is CRDT-expressible (counters, sets, sequences) and where full-state gossip bandwidth is cheap relative to divergence rate. Real embodying system: Riak with allow_mult effectively always true, or a pure Automerge-backed document store. Rejected because: forces every application data model into a CRDT shape; most production KV workloads (arbitrary blobs) do not fit, which is exactly why this design makes CRDTs opt-in (P9) rather than foundational.

Consensus-based replication (no anti-entropy needed)

Client ──► Raft Leader ──replicate(log)──► Follower, Follower
                (linearizable; no divergence possible by construction)

Regime where it wins: strict-consistency requirements, moderate write throughput, and a willingness to pay coordination latency and reduced partition-availability. Real embodying system: CockroachDB, etcd (both Raft-based). Rejected because: it sacrifices the availability-under-partition property that eventual consistency exists to provide (P1's entire premise); this is explicitly Projects #91/#92's surface, not this one's.

Differential-dataflow streaming convergence (no polled gossip)

Change stream ──► [incremental dataflow operator: continuously-updated diff] ──► Repair
   (continuous, event-driven — no fixed-cycle poll)

Regime where it wins: very large N where gossip-cycle polling overhead itself becomes the dominant cost (§30's bottleneck 1) rather than the actual divergence-detection work. Real embodying system: Naiad / Differential Dataflow, and Materialize's incremental view-maintenance engine built on the same model. Rejected because: significant operational-complexity increase and immature fit for a per-node embedded library at this project's current scale target; deferred as ADR-21 rather than abandoned — it is the named lever beyond the polled-gossip ceiling (§30).

Chain replication (no quorum, no divergence by construction)

Write ──► Head ──► Mid ──► Tail ──► Ack           Read ──► Tail
   (strict order; a chain failure blocks writes until reconfigured)

Regime where it wins: workloads that tolerate primary-side write serialization and want zero read-repair complexity by eliminating divergence structurally. Real embodying system: van Renesse & Schneider's original Chain Replication design, used in systems like FAWN-KV. Rejected because: a mid-chain node failure blocks writes until the chain reconfigures, trading the availability-under-partition guarantee this project prioritizes (P1) for strict ordering — the opposite trade from this project's mission.
