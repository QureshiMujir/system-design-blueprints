  3. A 4-stage TypeScript→JS→bundle→minify pipeline produces a map where a minified frame resolves to the wrong TypeScript line by exactly +1. (§19 Phase 7, §26.2–26.3, §7.9 INV-8)
  4. Given that compose is claimed to be associative, write the property test that would catch a failure.   5. The by-original index in SourceMapConsumer is more expensive to build than the by-generated index, yet many workloads never call generated_position_for. Explain why this matters only at the API boundary, not inside smap-codec, and write the exact conversion a smap-edit column-tracker must perform for a line containing "hello 🎉 world".   10. Describe the "carry-checkpoint" approach to lazy per-line decode. Why can't you simply jump to a ; offset and decode from there without the checkpoint?   12. A fuzz run discovers a crash in decode_vlq on the 8-byte input \x67\x67\x67\x67\x67\x67\x67\x67 ("gggggggg"). 33. Mental Models & First Principles

Expert compressed insights: what each predicts, the bug class without it, where this blueprint applies it.

ID Mental Model Expert Insight Predicts Bug Class Without It Resolving §
MM1 VLQ is sign-magnitude, not two's complement The sign is stored in the LSB of the pre-grouped value; continuation is bit 5 of each group. These are two orthogonal bit fields on two different levels. Which bit patterns encode -1 vs +1; maximum magnitude for N groups -1 decodes as a large positive; i32::MAX+1 silently wraps; off-by-everything on negative deltas §8.1, §13 (Phase 1)
MM2 The mappings decoder is a running-delta state machine with asymmetric reset Five delta accumulators. prev_gen_col resets to 0 at every ;. The other four carry across ;. This is not a symmetric reset — it is a precise invariant. Why every line's first segment has a column relative to 0, but an original-line relative to the last segment of the previous generated line Carrying gen_column across lines (columns explode) or resetting prev_source on ; (every line starts at source 0) — both produce wrong but parse-valid maps §6.3, §8.3, §15 (Phase 3)
MM3 Composition is a fold of partial functions over a shared domain compose(A, B) = for each point in B's domain, look it up in A, yield A's value if it exists, else yield a "hole" (1-field segment). remap = left-fold compose. The algebra is a partial-function composition, not a join. Why unmapped intermediate positions must produce 1-field (generated-only) segments, not be dropped; why compose is associative Dropping unmapped-mid segments (removes generated columns); snapping to nearest (fabricates origins); losing associativity (fold order changes result) §6.5–6.6, §19 (Phase 7)
MM4 Binary search for nearest is a GLB/LUB question, not an equality question Source map queries almost never hit an exact segment; the goal is "greatest segment ≤ query" (GLB) or "least segment ≥ query" (LUB). These are classical lower/upper-bound problems on a sorted array. Which standard partition_point variant to use; why a hash map gives wrong answers; why the chosen bias must be consistent throughout compose Using == (no match → wrong segment or panic); returning the insertion point rather than the predecessor; swapping GLB/LUB in compose vs query §6.8, §8.8, §18 (Phase 6)
MM5 0-based inside, 1-based at the boundary — one seam, nowhere else The entire codec/model/consumer operates in 0-based coordinates. The only place that converts is the CLI/API surface. One conversion seam means one place to audit and one place to test. Where every +1 / -1 on a line/column field is a bug Stray +1 inside the codec shifts every downstream column; a missing -1 in the consumer shifts every query result; "everything is one line off in the UI but tests pass" §6.4, §7.7 (INV-6), §14 (Phase 2)
MM6 Index-map offset is a "first-line-only column shift" The section offset.column applies only to the section's first generated line. Subsequent lines of the section carry their natural gen_column (relative to 0). This is a spec rule, not a convention. Why a 2-line section whose offset is (5, 7) has column 7 + seg_col on gen line 0 but just seg_col on gen line 1 Applying offset.column to all lines (shifts every non-first line sideways by the section offset) §6.14, §8 (Domain Model), §20 (Phase 8)
MM7 A source map is the inverse function of a multi-stage transformation A minified JS file is the image of a composition of partial functions (tsc → bundle → minify). The source map is a representation of the preimage function: given a point in the image, recover the corresponding point in the domain. Composition = chaining the preimage functions. Why there must be exactly one composed map for a pipeline; why stage order in remap is deepest-first; why a 1-field segment means "no preimage at this point" Reversing the chain order in remap; treating composition as map metadata merging rather than function chaining §2.2, §6.5, §7.9 (INV-8)
MM8 The trust boundary is at every decode entry point The library never fetches sources or URLs. Every byte of map JSON, VLQ, and sourceMappingURL is attacker-controlled. The library's job is to return a typed error for any malformed input, never panic, and never allocate without a cap. Why size caps must precede allocation; why unwrap in a decode path is a DoS Panic on truncated VLQ (DoS in a build server); OOM on a billion-segment map; path traversal via sourceRoot if library resolved paths §4.4, §6.2, §25 (Threat Model)

Glossary (§39) · 39 terms · site-wide glossary

Source Map v3
the "Source Map Revision 3 Proposal" / TC39 source-map spec; the JSON envelope (version:3 + file/sourceRoot/sources/sourcesContent/names/mappings/ignoreList) modeled by smap-model::SourceMap. The only version this toolkit emits; from_json rejects others via JsonError::BadVersion.
VLQ
Variable-Length Quantity; signed integer encoded in a variable number of Base64 VLQ groups. Used for every field in the mappings string. Sign-bit + magnitude, not two's complement. Owned by smap-vlq.
Base64 VLQ
one VLQ group serialized as one char of the 64-char alphabet A-Za-z0-9+/ (smap-vlq::B64). Each group carries 5 payload bits + the continuation bit. Reverse table maps char → 6-bit value; unknown char → VlqError::InvalidBase64Char.
continuation bit
bit 5 (value 32) of each Base64 VLQ group; 1 = another group follows, 0 = last group. Encoder sets it while value remains after shifting right 5; decoder loops until clear, accumulating into i64 (VlqError::Overflow on >32 magnitude bits).
sign bit
the least-significant bit of the value (before splitting into 5-bit groups), 1 = negative. Distinct from the continuation bit. encode_vlq folds sign in as (v<<1)|sign; decode_vlq extracts it from the final accumulated quantity.
mappings string
the encoded VLQ blob (SourceMap::mappings). Grammar: mappings = group (";" group)* ; group = [segment ("," segment)*] ; segment = field{1}|field{4}|field{5}. Encoded/decoded by smap-codec encode_mappings/decode_mappings.
segment
one mapping entry on a generated line; smap-model::Segment{ gen_column, source:Option<u32>, orig_line, orig_column, name:Option<u32> }. In the wire format a tuple of 1, 4, or 5 VLQ fields (1 = generated-only/unmapped; 4 = mapped no name; 5 = mapped + name). Field count validated; bad count → CodecError::BadFieldCount.
field
one VLQ-encoded integer inside a segment; positionally typed (1=gen col, 2=source, 3=orig line, 4=orig col, 5=name). Each holds a relative delta, not an absolute.
generated position
location in the output (post-transform) file; smap-model::Position{ line, column }, 0-based. The query key for original_position_for.
original position
location in a source input file; carried by OriginalLocation{ source, line, column, name }. The result of original_position_for, the query key for generated_position_for.
generated line/column
the generated position axes. gen_column is Segment field 1; the generated line is implicit = outer DecodedMap index (incremented per ";").
original line/column
Segment's orig_line/orig_column (fields 3/4); index into a source file's text. 0-based internally.
source index
Segment::source (field 2); index into SourceMap::sources / sourcesContent. Interned by SourceMapBuilder::add_source (returns u32); out-of-range → CodecError::SourceIndexOob.
name index
Segment::name (field 5); index into SourceMap::names. Interned by add_name. None ⇒ segment has no field 5.
sources
SourceMap::sources: Vec<Option<String>>; input file paths/URLs, resolved against sourceRoot. None ⇒ anonymous source. Indexed by source index.
sourcesContent
SourceMap::sources_content: Vec<Option<String>>; optional inline copy of each source's text, parallel to sources. Served by source_content_for; embedding governed by Phase 10 policy.
sourceRoot
SourceMap::source_root: Option<String>; prefix prepended to each sources entry to form the resolved URL. Normalization is an API/boundary concern, never inside the codec.
sourceMappingURL
the //# sourceMappingURL=<url> (or legacy //@) trailer comment linking output code to its map. Parsed/emitted by smap-json; extract_source_mapping_url → SourceMapRef.
inline / data: URL map
a sourceMappingURL of form data:application/json;base64,<b64> embedding the whole map. extract_source_mapping_url decodes it to SourceMapRef::Inline(SourceMap) vs SourceMapRef::Url(String).
XSSI prefix
the )]}' cross-site-script-inclusion guard some tools prepend to map JSON. from_json strips a leading )]}'(+optional newline) before parsing; to_json does not emit it by default.
ignoreList
SourceMap::ignore_list: Vec<u32> (serialized as ignoreList, legacy x_google_ignoreList); source indexes of vendored/third-party files devtools should skip when stepping. Populated per Phase 10.
DecodedMap
smap-model::DecodedMap(Vec<Vec<Segment>>); the in-memory dual of the mappings string. Outer index = generated line (0-based), inner Vec = that line's segments in column order. Decoder/encoder pivot type.
SourceMap
the v3 JSON-shaped struct (smap-model); the canonical artifact built by smap-builder/smap-edit, (de)serialized by smap-json, queried by smap-consumer, produced by compose/flatten.
index map / sectioned map
smap-index::IndexedSourceMap{ version, file, sections:[Section] }; a map composed of offset-placed sub-maps instead of a single mappings. Built from concatenated chunk outputs (e.g. one section per bundled module).
section offset
Section{ offset:Position, map:SourceMap }; the generated position at which a sub-map begins. flatten adds offset.line to every section line and offset.column only to the section's first generated line.
composition / chaining
smap-compose::compose(orig_to_mid, mid_to_gen, mid_names): for each segment in mid_to_gen, look its intermediate original position up in orig_to_mid; map gen → the found deepest source/line/col(+name); unmapped intermediate ⇒ emit a 1-field segment. Associative.
remap
smap-compose::remap(chain:&[SourceMap]); folds compose left-to-right over a chain (orig → … → gen) into one SourceMap. Errors surface as CodecError.
flatten
IndexedSourceMap::flatten() -> SourceMap; merges all sections into one flat map applying section offset arithmetic; requires sorted, non-overlapping sections.
bias
smap-consumer::Bias; tie/gap policy for binary search when the query has no exact segment. GreatestLowerBound (default) vs LeastUpperBound.
greatest-lower-bound
GLB; pick the segment with the greatest generated position <= the query. Default bias for original_position_for.
least-upper-bound
LUB; pick the segment with the least generated position >= the query.
SourceMapGenerator
the producer contract realized by smap-builder::SourceMapBuilder: add_source/add_name interning, set_source_content, add_mapping, then into_sourcemap (sorts by (gen_line, gen_column), dedups, encodes mappings). Mirrors Mozilla SourceMapGenerator / gen-mapping.
SourceMapConsumer
the query contract (smap-consumer::SourceMapConsumer): builds sorted by-generated + by-original indexes; original_position_for, generated_position_for, source_content_for, all_generated_positions_for. Mirrors Mozilla SourceMapConsumer / trace-mapping.
MagicString
smap-edit::MagicString; a source editor over an original buffer (overwrite/append/prepend/remove/move/indent) that emits transformed code (to_string) + a correct map (generate_map) via interval bookkeeping + column tracking, without re-parsing. Modeled on Rich Harris's magic-string.
gen-mapping
@jridgewell/gen-mapping; reference modern generator the SourceMapBuilder API mirrors (interning, sort-on-finalize).
trace-mapping
@jridgewell/trace-mapping; reference modern consumer the SourceMapConsumer index + bias search mirror.
relative delta
each numeric field stores the difference from the prior segment's same field, not an absolute. Reset rules (the #1 bug source): gen_column resets to 0 at every ";"; source index, original line/column, name index carry across lines. EncoderState/DecoderState hold prev_* accumulators.
0-based vs 1-based
lines and columns are 0-based everywhere inside the map and codec. Most tools present 1-based lines to users; the ±1 conversion happens only at the API/CLI boundary, never inside smap-codec/smap-consumer.
byte vs UTF-16 column
columns in Source Map v3 count UTF-16 code units (JS string semantics), not bytes or Unicode scalars. Rust String is UTF-8, so smap-edit/builder must convert byte offsets ↔ UTF-16 column counts at the boundary; an unconverted byte column mismaps any non-ASCII line. ---
