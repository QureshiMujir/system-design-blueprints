⬜ Phase 1 — Base64 VLQ codec §13

Objectives
  • Encode signed i64 → Base64 VLQ; decode Base64 bytes → i64, advancing a caller-held cursor.
  • 5-bit groups low→high; bit 5 (value 32) = continuation; LSB of value = sign (1 = negative).
  • Total function: never panic on arbitrary &[u8]; all errors via Result<_, VlqError>.
  • Range: encode any i32-fitting source delta; decode rejects values outside [i32::MIN, i32::MAX] (Overflow).
  • Non-goal: mappings grammar (Phase 2/3), JSON (Phase 4). This crate knows only single integers.
Deliverable

smap-vlq crate: encode_vlq, decode_vlq, B64, VlqError exported. cargo test -p smap-vlq green incl. proptest round-trip + fuzz-byte non-panic. Builds under --no-default-features (no_std target e.g. thumbv7em-none-eabi).

Acceptance
ID Check Target
A1 round-trip decode(encode(v)) == v ∀ v ∈ i32 proptest 100k cases pass
A2 known vectors (table 1.5) exact byte match
A3 decode on arbitrary &[u8] ≤ 16B never panic; only Ok/Err (proptest 1M)
A4 pos advance == chars consumed byte-exact
A5 overflow input (7+ cont groups) Err(Overflow), no UB
A6 encode 0 "A", 1 char

Pitfalls
  • Sign as two's complement — root cause: treating MSB/native sign instead of LSB magnitude flag → -1 decodes wrong. Debug: assert encode(-1)=="D".
  • -i32::MIN overflow in encode — (-value) as u64 on i64 holding i32::MIN is safe only because widened to i64 first; do not narrow before negate. Debug: unit-test i32::MIN.
  • shift overflow / silent truncation — accumulating >6 groups shifts past 32 bits; without the shift>37 && cont guard a huge map decodes garbage instead of Overflow. Debug: feed "ggggggggggg".
  • Reverse-table off-by-one for +// — easy to misplace; +=62, /=63. Debug: B64_REV[b'+']==62.
  • Empty output — forgetting the do-while shape drops value 0 (loop body never runs). Debug: encode(0)=="A".
  • Signed-byte index i8 negative — using b as usize after sign-extend; index by raw u8. Debug: bytes ≥128 must hit -1 lane, not panic.

⬜ Phase 2 — Data model and the mappings-string grammar §14

Objectives
  • Lock smap-model: Position, Segment, DecodedMap, SourceMap, OriginalLocation + index newtypes — exact layout, 0-based internal convention.
  • Specify (NOT yet encode/decode — that is Phase 3) the mappings string grammar as canonical EBNF + relative-delta semantics + per-field reset rules.
  • Encode invariants in code: field-count {1,4,5}, index-range bounds, per-line gen_column ascending sort, version == 3.
  • Provide invariant-checking constructors (Segment::with_*, DecodedMap::from_lines) that reject malformed shapes at construction, not at encode time.
  • Establish the 0-based ↔ 1-based boundary contract: conversion lives only at API/CLI edge, never inside model/codec.
Deliverable

smap-model crate compiles (no_std + alloc); all five core types + newtypes + ModelError present with constructors and validate()/validate_against(). A documented grammar.md (EBNF + reset-rule table) ships in the crate. Unit-test suite covers shape construction + malformed rejection. cargo test -p smap-model green.

Acceptance
  • Segment::with_name on a None-source builder path is a compile error or returns ModelError::FieldCount — name-without-source impossible to construct.
  • DecodedMap::validate() returns Err(UnsortedColumn) for any inner Vec with a descending gen_column; Ok otherwise.
  • SourceMap::v3() yields version==3; constructing with any other version is unrepresentable (no public setter).
  • Round-trip a hand-built 3-line DecodedMap (shapes 1,4,5 present) through validate() → Ok, with iter_segments count == sum of inner lens.
  • EBNF in grammar.md parses the canonical example AAAA; / AAgBC examples by hand-trace (documented, not executed here).

⬜ Phase 3 — Mappings codec (encode/decode state machine) §15

Objectives
  • encode_mappings(&DecodedMap) -> String: walk lines, emit ; per line boundary, , between segments, 1/4/5 VLQ fields as running deltas.
  • decode_mappings(&str) -> Result<DecodedMap, CodecError>: split on ; → generated lines; per ,-segment read 1/4/5 fields, fold into running state, validate.
  • Enforce reset rules: gen_column delta resets to 0 per ;; source/orig_line/orig_column/name carry ACROSS lines.
  • Tolerant decode of real-world maps: trailing ;/,, empty groups, leading ;.
  • Round-trip stable: decode→encode→decode fixpoint over fixtures + fuzz. Never panic.
Deliverable

smap-codec crate: encode_mappings + decode_mappings + CodecError, no_std, zero panics on arbitrary &str. cargo test -p smap-codec green; property test decode→encode→decode fixpoint passes; round-trips every Phase-3 fixture byte-identically after one normalization pass.

Acceptance
  • Encode of hand-authored DecodedMap matches golden mappings string byte-for-byte.
  • Decode of all valid fixtures yields expected Vec<Vec<Segment>> (assert exact Segment fields).
  • Idempotence: encode(decode(encode(decode(s)))) == encode(decode(s)) for all fixtures + 10k fuzz inputs.
  • Every malformed fixture returns the documented CodecError variant (not panic, not wrong variant).
  • cargo +nightly miri test -p smap-codec clean (no UB in cursor arithmetic).

⬜ Phase 4 — v3 JSON serialization, sourceMappingURL, and inline maps §16

Objectives

  • from_json → parse v3 JSON, strip XSSI )]}' line + optional UTF-8 BOM, validate version==3, read all fields, zero-copy borrow sources/names where the parser allows.
  • to_json → emit canonical, deterministic v3 envelope (stable key order, valid JSON string escaping, version:3 always first).
  • extract_source_mapping_url → find trailing //# sourceMappingURL= / //@ comment; decode data:application/json;base64, inline → SourceMapRef::Inline; else SourceMapRef::Url.

Acceptance

⬜ Phase 5 — The generator/builder API (SourceMapGenerator) §17

Objectives
  • SourceMapBuilder: stateful accumulator → spec-valid SourceMap (version 3).
  • add_source/add_name: dedup interning → stable first-seen indices; add_source returns u32 source index, add_name returns u32 name index.
  • set_source_content(source, content): index-aligned with sources (sparse → None fill).

⬜ Phase 6 — The consumer/query API (SourceMapConsumer) §18

Objectives
  • Build smap-consumer: SourceMapConsumer over a decoded map, answering position queries the way browsers/error reporters do.
  • new decodes "mappings" once, builds two sorted indexes: by-generated (gen_line, gen_col), by-original (source, orig_line, orig_col).
  • original_position_for(gen, Bias) → Option<OriginalLocation> via binary search; generated_position_for(source, orig, Bias) → Option<Position>; source_content_for(source); all_generated_positions_for.
  • Bias::GreatestLowerBound (default) / LeastUpperBound. Match reference source-map / trace-mapping query results on a shared corpus.
  • NON-GOAL: editing/composing maps (Phases 7/9); decode internals (Phase 3, reused via decode_mappings).
Deliverable

smap-consumer crate: SourceMapConsumer::new + four query methods compiling no_std+alloc; smap query original-for <line> <col> / generated-for CLI paths resolve through it; query-correctness + bias test matrix green.

Acceptance
  • new decodes once: ≤1 decode_mappings call; query methods allocate zero Vec (except all_generated_positions_for).
  • original_position_for / generated_position_for match reference source-map output on the shared corpus: byte-identical (source,line,col,name) for 100% of probe points (both biases).
  • GLB query just past last segment on a line returns that segment; LUB returns next; cross-line GLB does not leak onto prior line.
  • Binary search: O(log n) per query, verified by op-count assertion on a 1M-segment map (≤21 comparisons).

⬜ Phase 8 — Index (sectioned) maps §20

Objectives
  • Model IndexedSourceMap{ version:3, file, sections:[Section{offset:Position, map:SourceMap}] } per v3 sectioned spec; Section.map is a regular (non-index) v3 map.
  • Construct from an ordered list of (offset, SourceMap) chunks; one chunk = one emitted output region (e.g. concatenated module).
  • Invariants: sections sorted ascending by offset (line, then column); non-overlapping; no nested index map in a section.
  • flatten() -> SourceMap: shift each section's generated positions by its offset, merge sources/sourcesContent/names with index remapping, re-encode mappings.
  • Lossless: flatten output ≡ a flat map built directly from the same inputs (segment sets equal after sort/dedup).
Deliverable
