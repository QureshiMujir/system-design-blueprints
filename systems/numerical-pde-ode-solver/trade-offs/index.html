Decisions (§9) · 30 ADRs

1

Language

Chosen

Rust (2021)

Rejected

C++, Python, Julia, Fortran

When the rejected choice is right

C++ wins when linking an existing solver ecosystem (PETSc/Trilinos/deal.II are C++); Julia wins for research where DifferentialEquations.jl's autodiff + composable types beat hand-written kernels; Fortran wins for legacy BLAS/LAPACK-dominated codes

Why: Memory control + safety on stencil/SpMV/assembly kernels; matches portfolio

2

Scalar

Chosen

f64, generic where cheap

Rejected

f32-only, arbitrary precision

When the rejected choice is right

f32 wins on GPU/memory-bandwidth-bound SpMV where 2× bandwidth halves runtime and accuracy permits (mixed-precision iterative refinement); arbitrary precision wins for ill-conditioned systems (κ ≳ 1e14) where f64 round-off (§Phase 12, order floor) destroys the answer

Why: Standard numerical precision

3

Dense matrices

Chosen

row-major Vec<f64> + dims

Rejected

nested Vec

When the rejected choice is right

Nested Vec<Vec<f64>> wins only for jagged/ragged data kept out of any hot loop — irrelevant here, so genuinely dominated; choose flat

Why: Cache locality

4

Local dense (elements)

Chosen

nalgebra (small)

Rejected

hand-roll all

When the rejected choice is right

Hand-rolling wins for fixed 3×3/6×6 P1/P2 element matrices where const-generic unrolled code avoids nalgebra's generic dispatch and the dependency entirely (a leaf embedded build)

Why: Element matrices are tiny; reuse vetted code

5

Global linear algebra

Chosen

hand-written (CSR + Krylov)

Rejected

nalgebra-sparse, suitesparse

When the rejected choice is right

SuiteSparse (UMFPACK/CHOLMOD) wins in production: a battle-tested sparse-direct factorization beats hand-written Krylov for repeated solves with the same matrix and many RHS, or for indefinite systems where Krylov stalls

Why: "From scratch" is the point

6

Sparse format

Chosen

CSR (CSC for transpose)

Rejected

dense, LIL only

When the rejected choice is right

Dense wins below ~n=500 where BLAS-3 cache reuse beats sparse indirection; LIL/DOK win during incremental assembly with unknown structure (we instead batch via COO, ADR 7)

Why: Standard, SpMV-efficient (P3)

7

Assembly

Chosen

COO triplets → CSR

Rejected

direct CSR insert

When the rejected choice is right

Direct CSR insert wins when the sparsity pattern is known and fixed up front (structured FD grid) and assembly is on the hot path — skipping the COO sort/compress pass

Why: Simple, correct scatter-add

8

Iterative solvers

Chosen

CG/MINRES/GMRES/BiCGSTAB

Rejected

only direct

When the rejected choice is right

Direct wins for small/medium systems (n ≲ 1e4), for many RHS sharing one matrix (factor once), and for highly indefinite/ill-conditioned operators where Krylov convergence is unreliable

Why: Scales to large sparse (P4)

9

Preconditioners

Chosen

Jacobi/SSOR/ILU(0)

Rejected

multigrid (deferred)

When the rejected choice is right

Multigrid/AMG wins decisively for elliptic operators at large N: it gives mesh-independent (O(N)) convergence where ILU(0) iterations grow as κ~h⁻² (§Scalability Analysis) — the reason it is the standard for production Poisson

Why: Cheap, effective baseline

10

Direct solvers

Chosen

dense LU/Cholesky/QR + Thomas

Rejected

sparse direct (deferred)

When the rejected choice is right

Sparse direct (SuperLU/MUMPS) wins for 2-D problems up to ~1e5 unknowns where fill-in is tolerable and a single exact factorization beats iterating, especially with many RHS

Why: Small/local + tridiagonal fast path

11

ODE explicit

Chosen

Euler/RK4/RK45 (Dormand–Prince)

Rejected

only fixed-step

When the rejected choice is right

Fixed-step wins for real-time/embedded control loops needing deterministic per-step cost, for symplectic integrators where adaptivity breaks energy conservation, and for method-of-lines where the CFL-limited Δt is already near-constant

Why: Adaptive accuracy (I10)

12

ODE implicit

Chosen

BE/CN/BDF + Newton

Rejected

only explicit

When the rejected choice is right

Explicit-only wins for non-stiff/hyperbolic problems (wave, advection) where the CFL step is acceptable and a linear solve per step is pure overhead — explicit RK is then far cheaper

Why: Stiff systems (P2)

13

Step control

Chosen

PI controller

Rejected

basic doubling/halving

When the rejected choice is right

Doubling/halving wins for its simplicity when step-size history is unavailable (first step, after a reject) or when the integrand is so smooth that controller tuning is irrelevant

Why: Smoother, fewer rejects

14

FD grids

Chosen

structured uniform + stretched

Rejected

only uniform

When the rejected choice is right

Uniform-only wins for spectral/FFT-based Poisson solves (constant spacing is required for the FFT) and for simple MMS verification where stretching adds no value

Why: Boundary-layer resolution

15

FEM elements

Chosen

P1 + P2 Lagrange

Rejected

only P1; higher order

When the rejected choice is right

P1-only wins for non-smooth solutions (shocks, kinks) where high-order gains nothing and adds oscillation; P3+/spectral elements win for very smooth solutions on coarse meshes where exponential convergence pays off (Dedalus regime)

Why: Order vs complexity balance

16

Quadrature

Chosen

Gauss (degree-matched)

Rejected

Newton–Cotes

When the rejected choice is right

Newton–Cotes (trapezoid/Simpson) wins for tabulated data at fixed equispaced points, and lumped (nodal) quadrature wins deliberately for explicit transient FEM where a diagonal mass matrix avoids a solve per step (I9)

Why: Exactness for polynomials (P6)

17

Mesh

Chosen

1-D seg + 2-D triangles

Rejected

quads, 3-D tets (deferred)

When the rejected choice is right

Quads/hexes win for structured/boundary-aligned domains (better accuracy per DOF, tensor-product quadrature); 3-D tets win the moment the problem is genuinely 3-D (§Phase 9 defer trigger)

Why: Simplest 2-D FEM

BC handling

Chosen

Rejected

When the rejected choice is right

Naive row-zero (set row to identity) wins when the solver is a general nonsymmetric direct solve that does not exploit symmetry — it is simpler and the SPD loss costs nothing there

Why: Preserve SPD (I6)

Alternative Architectures (Roads Not Taken)

Fundamentally different architectures for the same goal. Each: ASCII sketch, the regime where it wins, the real system that embodies it, why this blueprint rejected it.

ALT-1 — Method of lines with an external ODE suite (chosen pattern, externalized).

   PDE + BCs                          this design owns
       |                              the integrator;
   [ spatial discretize ]            ALT-1 delegates it
       |  semi-discrete  u' = L u + b
       v
   [ EXTERNAL ODE library: CVODE / ARKODE ]  <-- owns step control, BDF, Newton-Krylov
       |
       v
   solution field over time

Regime where it wins: problems where temporal stiffness is the hard part (chemical kinetics, large stiff MOL systems) and a battle-tested adaptive BDF/Newton-Krylov integrator beats a hand-written one. Real system: SUNDIALS (CVODE/ARKODE/IDA, LLNL) used as the time integrator behind a user's spatial discretization. Why rejected: the integrator's order control, step adaptivity, and Newton stage solve (§Phase 5, §Phase 6) are precisely the learning targets; delegating them to a library would hide the mechanism this blueprint exists to teach.

ALT-2 — Fully-implicit monolithic Newton–Krylov in space-time.

   F(U) = 0   over all unknowns at once (no operator-split)
       |
   [ SNES outer Newton ]
       |  forms/applies J (often matrix-free)
       v
   [ KSP inner Krylov (GMRES) + PC preconditioner ]
       |
       v
   converged U  (steady or one large implicit step)

Regime where it wins: strongly coupled nonlinear/multiphysics problems where operator splitting loses accuracy or stability, and where a single global Newton with a good preconditioner converges robustly. Real system: PETSc SNES + TS (Argonne). Why rejected: the monolithic Jacobian assembly, matrix-free SNES, and field-split preconditioning are a large engineering surface beyond a from-scratch teaching solver; this design uses operator-split MOL (§8.8) and per-step Newton (§Phase 6) instead, which is simpler and exposes each piece.

ALT-3 — Spectral / FFT-based methods on smooth periodic domains.

   periodic smooth field u(x)
       |
   [ FFT to spectral coefficients ]   derivative = multiply by ik
       |
   [ solve in spectral space ]        (diagonal for constant-coeff)
       |
   [ inverse FFT ]
       v
   solution  (exponential / spectral accuracy)

Regime where it wins: smooth solutions on periodic or simple geometries, where spectral methods give exponential (faster-than-any-power-of-h) convergence and the FFT makes constant-coefficient operators diagonal and O(N log N). Real systems: Dedalus and Chebfun. Why rejected: spectral accuracy demands smoothness and simple geometry, and it does not handle the unstructured meshes, general BCs, and non-smooth/shock solutions (Burgers, §Phase 11) that FD/FEM target here; it is named as a deferred method class (§Deferred Features Register).

ALT-4 — Matrix-free operator application instead of assembled CSR.

   ALT-4 (matrix-free)            this design (assembled CSR)
   x --> [ apply_op(x) ] --> y    x --> [ SpMV(CSR, x) ] --> y
         (recompute stencil/        (stored nnz streamed
          element action on the fly)  from memory)
   Krylov only ever needs y = A x in both cases (MM5)

Regime where it wins: very large or high-order problems where storing nnz is the memory bottleneck, or where the operator changes every step (nonlinear/time-varying) so storing it buys nothing — recomputing the action is cheaper than assembling. Real system: PETSc matrix-free (MatShell) operators and high-order matrix-free FEM (e.g. libCEED). Why rejected: at this design's target scale the assembled CSR fits comfortably in RAM (§Back-of-Envelope Capacity Model item 3: ~88 MB) and a stored operator is faster to apply and simpler to precondition (ILU(0) needs the entries); matrix-free is the right call only past the memory ceiling this design does not reach.
