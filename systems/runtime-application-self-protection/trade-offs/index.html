Decisions (§9) · 28 ADRs

ADR-001

Implementation language

Chosen

Rust 2021, MSRV 1.78

Rejected

JVM agent (Java/Kotlin), .NET CLR profiler, Node.js native addon, Go plugin

When the rejected choice is right

JVM agent wins when the target application is pure JVM and bytecode weaving (via Java Instrumentation API) provides richer hook coverage than C-ABI FFI; Go plugin wins when instrumenting a Go HTTP service where CGO overhead is acceptable and the team lacks Rust expertise

Why: Zero-cost abstractions; memory safety on untrusted inputs; no GC pauses inline; precise FFI for hook ABI; catch_unwind for host-safety

ADR-002

Build system

Chosen

Cargo workspace (rasp-core, …, rasp-bench, 10 crates)

Rejected

Bazel, Buck2, CMake

When the rejected choice is right

Bazel/Buck2 win in a monorepo where RASP shares build graph with non-Rust services (e.g., C++ adapters, Python bindings) and hermetic cross-language caching is required

Why: Cargo is Rust standard; workspace unifies builds; no polyglot toolchain needed

ADR-003

Dependency policy

Chosen

cargo deny allowlist; no unsafe in dependencies without audit; SemVer pinned in Cargo.lock

Rejected

Unpinned deps, vendoring everything

When the rejected choice is right

Full vendoring wins in air-gapped environments where no external network access is available at build time, or when regulatory compliance mandates an immutable, audited source snapshot

Why: Reproducibility + supply-chain safety; cargo deny blocks unknown licenses/advisories

ADR-004

Async runtime

Chosen

Tokio 1.x (task-local context, JoinSet, channels)

Rejected

async-std, smol, bare futures

When the rejected choice is right

async-std wins for embedded targets or environments where Tokio's work-stealing scheduler is prohibited by RTOS constraints; bare futures win in no_std environments where any runtime is too heavy

Why: Tokio is ecosystem-dominant; task-local! macro for context propagation; good catch_unwind integration

ADR-005

Concurrency primitives

Chosen

std::thread_local! (sync), tokio::task_local! (async), parking_lot::RwLock for Policy

Rejected

std::sync::RwLock, crossbeam channels

When the rejected choice is right

std::sync::RwLock wins when linking to a no_std-compatible target where parking_lot is unavailable; crossbeam channels win when bounded backpressure between producers and consumers is needed (telemetry pipeline redesign)

Why: parking_lot lower overhead; task-local avoids context leakage; RCU-style policy swap

ADR-006

Policy hot-reload

Chosen

arc-swap crate (lock-free Arc swap)

Rejected

Mutex swap, reload-via-signal, full restart

When the rejected choice is right

Mutex swap wins at very low concurrency (single-threaded CLI tool, test harness) where lock contention does not arise; full restart wins under strict immutable-infrastructure policy where dynamic state change is prohibited

Why: Zero-reader-delay on policy update; consistent read-once per hook invocation

ADR-007

SinkArgs serialization (adapter→core)

Chosen

MessagePack (rmp-serde)

Rejected

JSON, Protobuf, FlatBuffers, Cap'n Proto

When the rejected choice is right

Protobuf wins when RASP must interoperate with non-Rust adapters across a service mesh where schema evolution and cross-language code generation justify the IDL overhead; FlatBuffers wins for zero-copy access when SinkArgs are very large (e.g., full HTTP body)

Why: Compact binary; no schema IDL; fast decode in Rust; smaller inline overhead vs JSON

ADR-008

AttackEvent serialization (internal→SIEM)

Chosen

JSON (serde_json) for internal storage; CEF string for SIEM export

Rejected

OTLP, NDJSON, Avro

When the rejected choice is right

OTLP wins when the organization runs an OpenTelemetry Collector pipeline where all telemetry (traces, metrics, logs) is unified; Avro wins in high-throughput event-streaming systems (Kafka) where schema registry and columnar compaction matter

Why: JSON: human-readable audit log; CEF: SIEM interoperability standard; no extra schema registry

ADR-009

SQLi detection algorithm

Chosen

libinjection-inspired tokenizer (pure Rust, rasp-detect)

Rejected

PCRE/regex, full SQL parser (sqlparser-rs), ML model

When the rejected choice is right

Full SQL parser (sqlparser-rs) wins in an offline pre-execution analysis mode (batch audit, DAST scanner) where latency is not inline; ML model wins when the corpus is domain-specific (proprietary query patterns) and a labeled training set is maintained

Why: Tokenizer matches libinjection accuracy benchmark; no regex-ReDoS; full parser too heavy inline; ML non-deterministic

ADR-010

SSRF detection

Chosen

URL-parse + IP-range deny-list (no DNS resolution inline)

Rejected

DNS-resolve + compare, network egress hook

When the rejected choice is right

DNS-resolve + compare wins when DNS rebind attacks are the primary concern and a dedicated fast resolver (local DoH) can be queried within SLA; network egress hook wins in kernel-bypass or eBPF-enforced environments where syscall interception is already in place

Why: DNS inline = latency + TOCTOU; URL-level detection catches most SSRF patterns; egress hook = runtime-specific

ADR-011

Taint tracking granularity

Chosen

Byte-range tags on string values; no per-character shadow memory

Rejected

DFT (dynamic flow tracking) shadow memory, LLVM DataFlowSanitizer

When the rejected choice is right

DFT shadow memory wins for security research and offline program analysis (not inline production RASP) where completeness is valued over performance; LLVM DataFlowSanitizer wins for native binaries compiled under your control where sanitizer passes are applied at compile time

Why: Shadow memory requires full instrumentation; byte-range is sufficient for HTTP injection detection; bounded cost

ADR-012

TaintMap data structure

Chosen

HashMap<ValueId, TaintedValue> (std HashMap, per-request)

Rejected

persistent trie, reference-counted taint DAG, global taint store

When the rejected choice is right

Persistent trie wins when taint must survive request boundaries (e.g., cross-request session-tainting for stored-XSS detection); ref-counted DAG wins when provenance chains must be retained for forensic reconstruction of multi-hop propagation

Why: Per-request map: isolated, cheap to clear; DAG = complex reclamation; global = contention

ADR-013

Telemetry channel

Chosen

tokio::sync::mpsc unbounded-ish with explicit capacity cap; drop on full

Rejected

crossbeam-channel, flume, blocking send

When the rejected choice is right

Blocking send wins when the RASP operates in an audit-only mode where no event must be dropped (regulated financial services, PCI-DSS audit log completeness); crossbeam-channel wins in synchronous (non-Tokio) runtimes where tokio::sync is unavailable

Why: Non-blocking send preserves host-safety invariant; drop-with-metric preferred over backpressure

ADR-014

Metrics format

Chosen

Prometheus exposition (metrics crate + metrics-exporter-prometheus)

Rejected

StatsD, OTLP metrics, custom binary

When the rejected choice is right

StatsD wins in environments where all metrics are push-based and no Prometheus scraper is deployed; OTLP wins when all telemetry flows through an OpenTelemetry Collector with a unified backend (Grafana Cloud, Honeycomb)

Why: Prometheus: pull-model; widely supported; metrics facade allows backend swap

ADR-015

Tracing

Chosen

tracing crate with tracing-subscriber; per-hook span (disabled by default, enable via env)

Rejected

log crate only, OpenTelemetry SDK

When the rejected choice is right

OpenTelemetry SDK wins when distributed tracing context (W3C TraceContext propagation) must flow from RASP spans into the application's existing APM pipeline (Jaeger, Zipkin, Datadog APM) without a bridging layer

Why: tracing structured + low overhead when disabled; spans enable per-request latency profiling

ADR-016

Fuzzing

Chosen

cargo-fuzz (libFuzzer) for all parser inputs (SQL tokenizer, URL parser, msgpack decode, XML scanner)

Rejected

AFL++, honggfuzz, property-testing only

When the rejected choice is right

AFL++ wins when coverage feedback is needed across language boundaries (C adapter + Rust core) in a single fuzzing harness; honggfuzz wins when hardware performance counters (perf_event_open) are required for branch-coverage feedback on Linux

Why: cargo-fuzz integrates natively; sanitizer support; OSS-Fuzz compatible

ADR-017

Testing strategy

Chosen

Unit (each crate), integration (rasp-bench attack corpus + benign corpus), property (proptest), fuzz

Rejected

Manual testing only, snapshot tests only

When the rejected choice is right

Snapshot tests win for CLI output and human-readable report formats where exact formatting must not drift; property-testing alone wins during early prototyping when an attack corpus is not yet curated

Why: Attack corpus covers OWASP test cases; benign corpus measures FP rate; proptest for taint invariants

ADR-018

Benchmark harness

Chosen

criterion microbenchmarks per analyzer; rasp-bench end-to-end throughput; overhead budget <5% p95

Rejected

Custom timing loops, iai-callgrind only

When the rejected choice is right

iai-callgrind wins for deterministic, noise-free instruction-count benchmarks in CI environments where wall-clock variance is high (shared cloud runners); custom loops win in embedded targets where criterion's statistical infrastructure is too heavy

Why: criterion statistical soundness; end-to-end captures real app overhead; wall-clock + perf-counter modes

ADR-019

CI/CD pipeline

Chosen

GitHub Actions: cargo test, cargo clippy --deny warnings, cargo deny, cargo fuzz (short runs), bench regression gate

Rejected

Jenkins, CircleCI, self-hosted only

When the rejected choice is right

Self-hosted runners win when benchmark reproducibility requires dedicated hardware (bare-metal, pinned CPU frequency) to avoid cloud-runner variance; Jenkins wins in enterprises with existing pipeline infrastructure and compliance controls on build environments

Why: GH Actions: zero infra; bench gate catches overhead regressions per PR

ADR-020

Hook ABI target (primary)

Chosen

C ABI (extern "C") with stable struct layout for adapter FFI

Rejected

Rust ABI (unstable), WASM component model, RPC

When the rejected choice is right

WASM component model wins when RASP must run in a sandboxed plugin host (e.g., Envoy WASM extension, Spin serverless) where native shared libraries are disallowed; RPC (gRPC/Unix socket) wins when the hook path can tolerate >1 ms latency and process isolation is a security requirement

Why: C ABI: stable across compiler versions; required for JVM JNI, CPython C-ext, Node N-API adapters

ADR-021

Error handling model

Chosen

Result<T, RaspError> throughout; catch_unwind at hook boundary; no unwrap/expect in hot paths

Rejected

anyhow for all error types, panic-based, thiserror only

When the rejected choice is right

anyhow wins in application-layer (CLI, integration test harness) code where error context richness matters more than typed matching; panic-based wins in pure library code during rapid prototyping before the error taxonomy is stable

Why: thiserror for typed errors; catch_unwind at boundary enforces host-safety invariant

ADR-022

Logging

Chosen

tracing::error!/warn!/info! structured; JSON log format via tracing-subscriber JSON layer

Rejected

println!, env_logger, syslog direct

When the rejected choice is right

Syslog direct wins in environments where the RASP is deployed as an OS service (systemd unit) and all logs must flow through the kernel syslog facility for auditability; env_logger wins for extremely minimal builds where compile-time log level filtering is sufficient

Why: JSON: machine-parseable; tracing: correlated to request span; no stdout in library crates

ADR-023

Config format

Chosen

TOML (Policy, Rules, ALLOW_LIST, DENY_LIST, limits) parsed via toml crate

Rejected

YAML (ambiguous), JSON (no comments), custom DSL

When the rejected choice is right

YAML wins when the RASP is managed by a Kubernetes operator where configuration is rendered from Helm charts that already produce YAML; JSON wins when policy is machine-generated by an API and human readability is not required

Why: TOML: unambiguous; Rust-ecosystem standard; comments supported

ADR-024

Packaging / distribution

Chosen

Shared library (.so/.dylib) + static library (libRASP.a) + rasp-cli binary

Rejected

Docker-only, kernel module, LD_PRELOAD only

When the rejected choice is right

Kernel module wins when the deployment target is a controlled Linux server where eBPF is unavailable and kernel-level syscall interception (via ptrace or LSM hooks) is the only approved interception mechanism; LD_PRELOAD wins for intercepting glibc syscall wrappers in unmodified binaries without source access

Why: Shared lib: runtime-adapter loads via dlopen; static: link-time embedding; CLI: ops tooling

ADR-025

Reproducible builds

Chosen

cargo with locked Cargo.lock; SOURCE_DATE_EPOCH pinned; Docker base image SHA-pinned

Rejected

Best-effort builds, floating base images

When the rejected choice is right

Floating base images win in rapid prototyping/development where always-latest security patches in the base image are more valuable than bit-for-bit reproducibility; best-effort builds win in ephemeral CI jobs where artifacts are not published externally

Why: Reproducible: auditability + supply-chain; SHA-pinned base images prevent upstream injection

ADR-026

Security tooling

Chosen

cargo audit (RUSTSEC advisory check); cargo deny (license + ban); clippy::undocumented_unsafe_blocks lint

Rejected

Manual review only, Snyk

When the rejected choice is right

Snyk wins when the organization already has a Snyk enterprise license covering multi-language monorepos (Rust + JS + Python) and unified SCA dashboards are required; manual review wins for third-party audits where tool-assisted review must be supplemented by human expert judgment

Why: cargo audit in CI catches known CVEs; undocumented unsafe blocks fail CI

ADR-027

Docs

Chosen

rustdoc for API docs; ADR table in blueprint; per-crate ARCHITECTURE.md; mdbook for operator guide

Rejected

Confluence, Notion, wiki-only

When the rejected choice is right

Confluence/Notion win in large enterprises where documentation discovery, search, and access control are managed centrally and developers cannot host static sites; wiki-only wins for internal tools where the audience is small and co-located with the codebase

Why: rustdoc co-located with code; mdbook for human-readable operator runbook; no external wiki drift

ADR-028

Licensing

Chosen

Apache-2.0 OR MIT (dual) for library crates; Apache-2.0 for CLI/bench

Rejected

GPL (incompatible with commercial embedding), proprietary

When the rejected choice is right

GPL wins when the project is a standalone security tool (not embedded in apps) and copyleft is desired to ensure improvements flow back to the community; proprietary licensing wins when the RASP is the organization's core commercial product and source disclosure is prohibited

Why: Dual license: embedded in commercial apps without copyleft; Apache patent clause protection

Alternative Architectures (Roads Not Taken)

Alt-A — Network WAF (edge pattern matching).

client --HTTP--> [ WAF: regex rules on request ] --(pass)--> app

Wins when: you need language-agnostic protection with zero app changes and a fast first line of defence (CDN/edge). Embodied by: ModSecurity + OWASP CRS, Cloudflare WAF. Rejected (as core) because: the WAF cannot see the assembled query, deserialized objects, or ORM-built SQL, so it trades precision for placement (MM1); kept as a complementary outer layer, not the detection core.

Alt-B — Static analysis (SAST) at build time.

source --> [ taint analysis: source->sink paths ] --> findings (pre-deploy)

Wins when: you want to eliminate vulnerability classes before deployment with no runtime overhead. Embodied by: CodeQL, Semgrep, commercial SAST. Rejected because: SAST has no runtime values (is this request's input actually attacker-controlled?), over-reports on infeasible paths, and cannot cover dynamically-loaded or reflective code; it is a build-time complement, not a runtime protector.

Alt-C — Kernel-level syscall interception (eBPF/uprobe).

app --syscalls--> [ eBPF programs at exec/connect/openat ] --> allow/deny

Wins when: you want one language-agnostic sensor below the runtime with no in-process code. Embodied by: Falco, Tetragon. Rejected (deferred) because: the kernel sees execve/connect but not which SQL string or which deserialized class — it lacks application-level semantics (MM1); captured as a future enhancement in the Deferred Features Register.

Alt-D — IAST (passive, test-time instrumentation).

QA traffic --> [ instrumented app reports taint paths ] --> findings (no blocking)

Wins when: you want to surface vulnerabilities during testing/CI without any production enforcement risk. Embodied by: Contrast Assess, Seeker. Rejected (deferred) as the primary mode because: IAST observes but does not protect production; this blueprint's purpose is inline enforcement (monitor/block), with IAST-style passive export kept in the Deferred Features Register.
