  3. What guarantees a panic inside a taint propagator cannot crash the host request? (MM3 + §4.3 + §13)
  4. Why does thread_local! break request context under tokio, and what replaces it? (MM7 + §14 + §11)
  5. Trace one tainted HTTP parameter from source annotation to a blocked SQL sink, naming each crate and latency budget. (§3 + §4.1 + §16 + §19)
  6. How does the engine stay within a 5% overhead budget when most arguments are untainted? (MM6 + Capacity C1 + §22)

  8. Why must monitor mode be observationally pure, and what operational failure follows if it is not? (MM5 + §21 + §4.3)
  9. How are double-encoded payloads defeated, and at what stage of the pipeline? (MM9 + §23 + §17)
  10. What does the hook abi_version protect against, and what is the failure mode of a mismatch? (MM10 + §4.1 + Compatibility & Versioning)
  11. Why is full SQL/edge pattern matching rejected as the core detection model despite WAF ubiquity? (Comparative Architecture + Alternative Architectures + MM1)
  12. How is the ≤ 0.01% benign false-positive budget connected to whether block mode is deployable? (Capacity C9 + §4.3 + §21)

Mental Models & First Principles

The compressed insights an expert in runtime application self-protection holds. Each predicts a bug class. Every cited § resolves to a real heading.

MM1. A RASP sees intent at the sink; a WAF sees bytes at the edge. Detection runs inside the process at the moment the dangerous operation executes, with the fully-assembled query/command and its data provenance in hand. Predicts: far lower false positives than pattern-matching the raw request. Bug without it: building a RASP that re-matches request patterns like a WAF — you inherit the WAF's blindness to post-decode, post-deserialize, and ORM-built payloads. Applied: §8 (sink interception), §19 (SQLi at sink), Comparative Architecture Table.

MM2. Taint is a provenance label that flows with data, not a scan you run. A TaintedValue carries byte-range tags from source (HTTP input) through string operations to sink. Predicts: you can answer "did attacker-controlled bytes reach this exact position?" Bug without it: re-scanning whole strings for "bad patterns" at the sink — O(n) per call and semantically blind to provenance. Applied: §16 (taint core), §8.7 (TaintMap Data Model), P-taint principles.

MM3. A security tool that crashes the app is worse than the attack it stops. Every hook path is wrapped in catch_unwind and defaults fail-open in brownfield deployments. Predicts: the 0% RASP-induced crash invariant (§4.3). Bug without it: a panic in a taint propagator takes down the host request — you have built an availability vulnerability. Applied: §4.3 (host-safety budget), §13 (hook trampolines), §21 (fail-open vs fail-closed).

MM4. Injection = tainted data reaching a syntactic keyword position. SQLi is not "input contains a quote"; it is "attacker bytes altered the parse tree of the query." Predicts: high SQLi precision via tokenize-and-diff (libinjection-style). Bug without it: alerting on the mere presence of taint or of metacharacters → false positives on legitimate quoted data. Applied: §17 (SQLi tokenization), §18 (command/path), §8 domain model.

MM5. Monitor mode must be observationally pure. In monitor mode the engine may compute, score, and log, but must never alter app control flow or output. Predicts: safe staged rollout (monitor → block). Bug without it: a "monitor" mode that occasionally blocks or mutates → operators lose trust and disable the agent. Applied: §21 (monitor vs block), P-policy principles, I-invariants.

MM6. Overhead is a budget spent per sink call — protect the fast path. Untainted arguments must take an inline fast exit before any analyzer runs. Predicts: the ≤ 5% request overhead target (§4.1). Bug without it: running full detection on every argument regardless of taint → linear blow-up and missed SLA. Applied: §4.1 (overhead budget), §22 (performance), §16 (untainted fast path).

MM7. Context propagation across async boundaries needs task-local, not thread-local. Under tokio::spawn a request hops threads; thread_local! silently loses the RequestContext. Predicts: correct per-request isolation in async runtimes. Bug without it: cross-request taint leaks where request A's taint is checked against request B's sink. Applied: §14 (execution context engine), §11 Core Schema (RequestContext).

MM8. Bound everything an attacker can inflate. TaintMap bytes, entries, tags-per-value, telemetry channel depth, and hook stack depth all have hard caps with conservative-fallback modes. Predicts: resilience to taint-explosion DoS. Bug without it: an attacker sends input that fans out into millions of taint tags → OOM or unbounded latency. Applied: §4.1 (limits table), §16 (OverBudget mode), §20 (correlation/dedup).

MM9. Evasion is a normalization problem: decode before you match. URL/hex/unicode/double-encoding and SQL comment/whitespace tricks must be canonicalized before analysis. Predicts: anti-bypass robustness (§23). Bug without it: matching raw %2527 instead of the decoded ' → trivial bypass. Applied: §23 (evasion resistance), §17/§18 (normalization steps).

MM10. The hook ABI is a versioned contract between agent and runtime. abi_version is checked at rasp_init; a mismatch must refuse to load, not run with undefined behaviour. Predicts: safe upgrades across agent/runtime skew. Bug without it: a new agent against an old runtime adapter reads misaligned HookEvent structs → memory corruption. Applied: §4.1 (abi_version), §13 (hook ABI), Compatibility & Versioning.

Glossary · 52 terms · site-wide glossary

RASP
Runtime Application Self-Protection — security instrumentation embedded inside the running application process; intercepts dangerous operations at their call sites with full semantic context unavailable to network-edge defenses.
Sink
A dangerous operation site where untrusted data produces harm if injected: SQL exec, OS command exec, file open, outbound HTTP, deserialization, LDAP query, XML parse. Represented as SinkType enum variant.
Source
Origin of untrusted input entering the trust boundary: HttpParam, HttpHeader, HttpBody, HttpPath, Cookie — enumerated in TaintSource.
Taint tracking
Data-flow analysis at runtime: each byte of untrusted input is tagged at ingress (TaintTag { source, byte_range }); tags propagate through string operations; checked at every sink.
TaintedValue
Value paired with its set of TaintTags — TaintedValue { value, tags: Vec<TaintTag> }. Propagation preserves tags through concat, slice, format.
TaintTag
Minimal provenance record: { source: TaintSource, byte_range: Range<usize> } — records which bytes of the final value originated from which HTTP field.
Taint propagation
Rule set by which tags flow through string operations (concat → union, slice → sub-range, format → mapped tags); cost-bounded to keep overhead within budget.
Taint soundness (bounded)
Invariant: no taint drop within the configured operation budget; operations exceeding budget are conservatively treated as fully tainted; untracked ops documented.
Hook
A call intercept registered at a sink call site; the protected runtime invokes rasp_hook_entry(event) / rasp_hook_exit(result) at each instrumented site.
Hook ABI
The C-compatible function signature boundary between the instrumented runtime (any language) and the Rust RASP engine — defined in rasp-hook; enables language-agnostic adapters.
Trampoline
Low-level thunk that redirects control from the original sink implementation to the RASP hook entry point, then conditionally returns to the original; must be async-signal-safe.
Instrumentation adapter
Per-runtime shim (JVM agent, .NET profiler, Node.js monkey-patch) that installs trampolines and emits HookEvents into the RASP engine via the hook ABI; specified but out-of-core.
HookEvent
Payload passed from adapter to engine: { sink: SinkType, args: SinkArgs, context_id: ContextId, phase: Entry|Exit, timestamp }.
RequestContext
Per-request store: { id, http: HttpInfo, taint_map: TaintMap, call_stack, started } — isolated per thread or async task; never shared across concurrent requests.
Context isolation
Invariant: RequestContext is scoped strictly to one logical request; no taint or correlation data leaks across concurrent requests/tasks regardless of concurrency model.
Inline guard
The composed pipeline rasp-protect executes inline in every request at every sink: hook → context → taint → detect → policy → action; must complete within overhead budget.
Monitor mode
Policy.mode == Monitor — guard observes and emits telemetry for every detection but NEVER alters app behavior; no blocking, no error injection. Monitor purity invariant.
Block mode
Policy.mode == Block — guard aborts the sink operation and returns a safe error to the app on Action::Block; the app continues without executing the dangerous operation.
Monitor purity
Invariant: in Monitor mode zero side effects on the app's observable behavior — no aborted ops, no injected exceptions, no altered return values.
Block determinism
Invariant: given identical (sink args, RequestContext, Policy), the Allow/Block decision and attached evidence are identical — no stochastic or time-dependent branching.
Fail-open
Policy.fail_mode == Open — on RASP internal error, allow the operation to proceed and log the fault; prioritizes availability over security.
Fail-closed
Policy.fail_mode == Closed — on RASP internal error, block the operation and log the fault; prioritizes security over availability.
Host-safety invariant
A RASP fault NEVER crashes or hangs the protected app — every hook path is bounded; panics are caught at the hook boundary; errors fall back to fail_mode, never propagate into host.
Overhead budget
Inline added latency constraint — p95 added latency ≤ configured threshold (default 5%); analyzers short-circuit on untainted args; taint propagation is cost-bounded.
Detection
Result of a successful attack analysis: { rule_id, sink, severity, confidence, evidence, taint_path } — produced by rasp-detect, consumed by rasp-policy.
Action
Policy enforcement outcome: Allow | Block | Monitor; Block triggers sink abort; Monitor allows but emits event; Allow is silent pass-through.
Rule
Named detection + enforcement spec: { id, sink, kind: Signature|Semantic, action } — keyed by rule_id in Policy.rules.
Policy
Top-level config: { mode, rules: Vec<Rule>, waivers: Vec<Waiver>, fail_mode }; hot-reloadable without restart; transitions must not drop in-flight requests.
Virtual patching
Rule targeting a known CVE in a dependency; blocks known-bad inputs without modifying the vulnerable library; identified by CVE-id waiver or rule condition.
Waiver
Scoped allow-list entry: exempts a (rule_id, context_matcher) pair from blocking; must carry expiry, owner, and justification fields.
SQLi (SQL injection)
Attack class: untrusted input inserted into a SQL query alters its structure/semantics; detected by tokenizing the query and identifying injected structural tokens not present in the template.
Command injection
Attack class: untrusted input inserted into an OS command exec alters the command; detected by argument-level parsing to find shell metacharacters or injected tokens.
Path traversal
Attack class: untrusted input in a file path contains ../ sequences or absolute paths that escape the intended root; detected by normalizing the resolved path against an allowlist.
SSRF
Server-Side Request Forgery — attacker-controlled URL in an outbound HTTP call targets internal infrastructure; detected via URL allowlist + private-IP/loopback check on resolved host.
Deserialization gadget
A class chain in a runtime's class hierarchy that produces harmful side effects when an attacker-controlled serialized blob is deserialized; detected by class-name and magic-byte signature matching before full deserialization.
XXE
XML eXternal Entity injection — malicious XML declares external entities; parser is redirected to local files or internal services; detected by scanning the raw XML prolog for ENTITY / SYSTEM / PUBLIC declarations.
LDAP injection
Untrusted input inserted into an LDAP filter alters its structure; detected by filter-syntax tokenization looking for injected operators or wildcard abuse.
NoSQL injection
Untrusted input inserted into a NoSQL query object (JSON/BSON) alters query semantics; detected by type checks (unexpected $operator keys) and structural analysis.
Signature rule
Detection rule matching fixed patterns — byte sequences, token sets, regex; fast but bypassed by novel encodings; complemented by semantic rules.
Semantic rule
Detection rule performing structural/syntactic analysis of the sink argument (tokenize SQL, parse URL, normalize path) — higher precision than signatures, more CPU cost.
False positive (FP)
RASP blocks or flags a benign operation; degrades availability and erodes operator trust; minimized by taint-gating (only analyze tainted args) and semantic precision.
False negative (FN)
RASP misses a real attack; leads to exploitation; managed by rule coverage, taint soundness, and periodic red-team corpus regression.
SIEM/CEF
Security Information and Event Management / Common Event Format — standardized attack event schema emitted by rasp-telemetry to security monitoring infrastructure.
IAST
Interactive Application Security Testing — contrast to RASP: IAST instruments for vulnerability discovery during testing, not production protection; RASP is a production enforcement layer.
WAF
Web Application Firewall (project 338) — network-edge defense; sees only HTTP bytes, lacks execution context, higher FP rate than RASP for injection; complementary layer.
OpenRASP
Baidu open-source RASP reference implementation (Java); hook model and policy semantics are a primary reference for this project's architecture.
ContextId
Opaque identifier correlating a HookEvent to its RequestContext; generated at request ingress; propagated via thread-local or async task-local storage.
SinkArgs
Tagged union of arguments passed to a sink, typed per SinkType; carries the raw data subjected to taint check and attack analysis.
TaintMap
Per-request map from value identity to Vec<TaintTag>; bounded capacity; evicts on overflow with conservative full-taint fallback.
Cost budget (taint)
Per-request operation counter for taint propagation; when exceeded, remaining values are conservatively marked fully tainted and a metric is emitted.
Attack event
Structured record emitted on detection/block: includes rule_id, sink, severity, confidence, evidence, taint_path, request_id, timestamp; exported via CEF/JSON.
Severity
Critical | High | Medium | Low — assigned per rule; used by rasp-policy to prioritize blocking and by rasp-telemetry for alert routing.
