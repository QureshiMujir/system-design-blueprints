3. Architectural Overview

3.1 Canonical Architecture Diagram

protected application (instrumented runtime)  --hook ABI call at each dangerous sink-->
        |
  [rasp-hook] sink entry/exit interception (SQL exec, command exec, file open, outbound HTTP, deserialize)
        |  HookEvent (sink_type, args, context_id)
  [rasp-context] resolve per-request context (thread/async-local), HTTP request, call stack, correlation id
        |
  [rasp-taint] are sink args tainted? source (HTTP input) -> propagation -> sink reached?
        |  TaintedValue + taint path
  [rasp-detect] per-sink analyzer: SQLi (query tokenize + injected-syntax), cmd-injection, path-traversal,
        |        SSRF (URL allowlist), deserialization (gadget), XXE, LDAP/NoSQL -> Detection?
  [rasp-policy] Detection -> Action (Block / Monitor) by mode + rule + waiver (fail-open / fail-closed)
        |
  [rasp-protect] enforce: Block => abort the sink op + safe error to app; Allow => proceed
        |
  [rasp-telemetry] emit attack event (SIEM/CEF), metrics (overhead, blocks), audit log

3.2 Subsystem Descriptions

Protected Application / Instrumented Runtime

  • The host process; can be JVM, Node.js, .NET CLR, Python CPython, or native Rust.
  • Per-runtime adapter (out-of-core) weaves hook calls at each sink: SQL driver execute(), Runtime.exec(), Files.open(), HttpClient.send(), ObjectInputStream.readObject(), JNDI lookup, DocumentBuilder.parse().
  • The adapter calls the hook ABI (rasp_hook_sink_entry, rasp_hook_sink_exit) via FFI/JNI/N-API.
  • Trust boundary: adapter code is trusted; sink args are untrusted payloads from user input.
  • Protocol boundary: hook ABI is a C-stable FFI boundary; extern "C" function signatures; versioned with a u32 abi_version handshake at rasp_init.

rasp-hook

  • Receives HookEvent at each sink; owns the call dispatch loop.
  • Maintains SinkRegistry: mapping SinkType → Vec<HookFn>; allows multiple interceptors per sink (e.g., audit + detect).
  • Enforces re-entrancy guard: if RASP itself calls a sink (e.g., telemetry writes a file), the inner call is passed through without re-intercepting.
  • Concurrency boundary: hook calls arrive from multiple threads/tasks; all state access goes through rasp-context (thread/task-local) — no shared mutable state in rasp-hook itself.
  • Trampoline: saves minimal register state, calls Rust hook fn, restores; bounded unsafe block, audited.
  • Failure mode: on any panic inside hook, catch_unwind catches; falls back to Policy.fail_mode; never propagates panic to host.

rasp-context

  • Owns RequestContext: id: CorrelationId, http: HttpInfo, taint_map: TaintMap, call_stack: Vec<Frame>, started: Instant.
  • Storage: thread_local! for synchronous/blocking apps; tokio::task_local! for async; adapter selects at init.
  • rasp_context_begin(http_info) called by adapter at request entry; rasp_context_end() at response exit.
  • Context isolation invariant: each request gets a fresh RequestContext; no fields shared across concurrent requests; TaintMap is per-context, not global.
  • HttpInfo captures: method, URL, headers (raw Vec<(String,String)>), body snapshot (up to max_body_capture bytes), remote IP.
  • call_stack: lightweight Vec<Frame> pushed/popped at hook entry/exit; used by rasp-detect for stack-context signals (e.g., call depth, framework frame detection).
  • Persistence boundary: RequestContext is in-process memory only; not persisted; telemetry extracts fields before drop.

rasp-taint

  • Consumes HttpInfo from rasp-context; annotates each HTTP field as a TaintedValue with TaintSource + TaintTag { source, byte_range }.
  • TaintMap: HashMap<ValueId, TaintedValue>; ValueId is a u64 handle assigned at source annotation.
  • Propagation policy: concat(a_tainted, b_clean) → tainted(merged_tags); slice(tainted, range) → tainted(adjusted_byte_range); format! with tainted arg → tainted output; propagation is field-level, not byte-level (bounded cost).
  • Taint soundness invariant: within configured ops set, propagation never silently drops taint; untracked ops (e.g., regex match, crypto hash) are documented as taint sinks that clear taint.
  • Overhead invariant: TaintMap lookup is O(1); propagation at string ops is O(tags) where tags ≤ MAX_TAGS_PER_VALUE (default 16); exceeds budget → mark TaintedValue::OverBudget → conservative (treat as tainted).
  • Sink-time check: given SinkArgs, resolves each arg's ValueId in TaintMap; returns Option<TaintedValue>.

rasp-detect

  • Per-sink analyzer dispatched by SinkType; receives (TaintedValue, SinkArgs, &RequestContext).
  • Short-circuit rule: if arg is not tainted, skip all analyzers → O(1) fast path; this is the primary overhead budget mechanism.
  • Analyzers:
    • SqliAnalyzer: tokenise query (libinjection algorithm port); detect injected syntax tokens (UNION, comment, stacked query, boolean blind); produce Detection { rule_id, confidence, evidence: TokenDiff }.
    • CmdInjectionAnalyzer: shell metacharacter scan (`; | && || $() `` etc.); argument boundary violation detection.
    • PathTraversalAnalyzer: normalize path; detect ../, null bytes, symlink bypass patterns; compare resolved path against allowed roots.
    • SsrfAnalyzer: parse URL; check against AllowedHostsPolicy; detect DNS rebinding patterns, loopback/link-local, internal RFC-1918 ranges, metadata endpoints (169.254.169.254).
    • DeserializationAnalyzer: check type name / class descriptor against gadget chain blocklist (ysoserial gadgets); detect java.lang.Runtime, ProcessBuilder, reflection chains.
    • XxeAnalyzer: scan DOCTYPE / ENTITY declarations; detect external entity references, SYSTEM/PUBLIC identifiers pointing to file:// or http://.
    • LdapInjectionAnalyzer: detect unescaped LDAP filter metacharacters (* ( ) \ NUL); NoSQL injection: detect $where, $gt, operator injection in JSON/BSON.
  • Each analyzer returns Option<Detection>; multiple analyzers can fire; highest-severity wins for policy dispatch, all are logged.
  • False-positive discipline: analyzers have configurable confidence_threshold; detections below threshold are downgraded to Monitor regardless of policy.

rasp-policy

  • Evaluates Vec<Detection> against Policy { mode: Monitor|Block, rules: Vec<Rule>, waivers: Vec<Waiver>, fail_mode: Open|Closed }.
  • Rule { id, sink, kind, action }: kind: Signature|Semantic; action: Allow|Block|Monitor.
  • Waiver: exempts specific (source_ip, rule_id, path) triple from blocking; time-bounded; signed.
  • fail_mode: Open → on RASP internal error, return Action::Allow; Closed → return Action::Block.
  • Decision is deterministic: same (Detection, Policy) → same Action; reproducible for audit.
  • Arc<Policy>: hot-reloaded atomically via ArcSwap; no lock on hot path; reload triggered by SIGHUP or file-watcher event.
  • Virtual patching: Rule with kind: Semantic and inline match expression applied before sink; deployed without redeploying app.

rasp-protect

  • The inline guard: called synchronously in the hook path; orchestrates the rasp-hook → rasp-context → rasp-taint → rasp-detect → rasp-policy → action pipeline.
  • Block path: returns Err(RaspError::Blocked { detection }) to the adapter; adapter translates to a safe application error (e.g., SQL driver throws SecurityException); the dangerous operation is NOT executed.
  • Allow path: returns Ok(()) to adapter; sink proceeds normally; overhead is the RASP check cost only.
  • Monitor path: returns Ok(()) but enqueues detection event to rasp-telemetry; no blocking; no app behavior change.
  • Monitor purity invariant: in Monitor mode, no call to Block path, no alteration of SinkArgs, no side effect on app execution.
  • Host-safety invariant: catch_unwind wraps entire protect path; on panic → fall back to fail_mode; never propagate panic to host stack.
  • Execution budget: configurable max_hook_duration_us (default 500µs); if exceeded, self-interrupts and falls back to fail_mode.

rasp-telemetry

  • Receives DetectionEvent via a bounded async channel (flume::bounded(4096)); non-blocking send from hot path (if channel full → drop event + increment events_dropped counter).
  • SIEM/CEF export: formats Detection as CEF:0 or JSON; writes to stdout/file/TCP socket; batched with configurable flush interval.
  • Prometheus metrics: rasp_hook_duration_us (histogram), rasp_detections_total (counter, labels: sink, rule, action), rasp_blocks_total, rasp_events_dropped_total, rasp_taint_map_size (gauge).
  • OpenTelemetry spans: each hook invocation creates a child span under the request trace; exports to OTLP collector.
  • Audit log: every Block decision logged with: correlation_id, sink, rule_id, action, evidence, taint_path, timestamp, request_url, source_ip; append-only, structured JSON.
  • Async queue boundary: telemetry consumer runs in a dedicated task/thread; decoupled from request path; backpressure via bounded channel.

3.3 Data Flow Summary

HTTP request arrives
    → adapter calls rasp_context_begin(HttpInfo)
    → rasp-taint annotates HTTP fields as TaintedValue, stores in RequestContext.taint_map
    → app processes request; calls SQL driver.execute(query_string)
    → adapter intercepts; calls rasp_hook_sink_entry(HookEvent{SqlQuery, args:[query_string], context_id})
    → rasp-protect dispatches:
        rasp-context: resolve RequestContext by context_id
        rasp-taint: lookup query_string ValueId → TaintedValue{tags:[HttpParam("q")]}
        rasp-detect: SqliAnalyzer(tainted_query) → Detection{SQLi, HIGH, evidence}
        rasp-policy: Detection + Policy → Action::Block
    → rasp-protect returns Err(Blocked) to adapter
    → adapter throws SecurityException (SQL never executes)
    → rasp-telemetry: DetectionEvent enqueued → CEF log + metrics
    → adapter calls rasp_context_end(); RequestContext dropped

8. Domain Model — Runtime Taint-Propagation & Sink-Interception

8.1 Entity Catalogue

Entity Crate Cardinality Lifetime
RequestContext rasp-context 1 per request request boundary
TaintMap rasp-taint 1 per request same as RequestContext
TaintedValue rasp-taint 0..N per request per propagation op
HookEvent rasp-hook 1 per sink invocation inline; stack-allocated
Detection rasp-detect 0..M per sink invocation emitted to rasp-protect

8.2 Core Type Definitions (normative)

SinkType :: SqlQuery | Exec | FileOpen | HttpRequest
          | Deserialize | LdapQuery | XmlParse | NoSqlQuery

TaintSource :: HttpParam | HttpHeader | HttpBody | HttpPath | Cookie

TaintTag   :: { source: TaintSource, byte_range: Range<usize>, generation: u32 }

TaintedValue :: { value: Bytes, tags: Vec<TaintTag> }

TaintMap   :: HashMap<ValueId, TaintedValue>   // keyed by intern handle

HookEvent  :: { sink: SinkType, args: SinkArgs, context_id: ContextId,
                phase: Entry | Exit, timestamp: MonotonicNs }

RequestContext :: { id: ContextId, http: HttpInfo, taint_map: TaintMap,
                   call_stack: SmallVec<[FrameInfo;8]>, started: MonotonicNs }

Detection  :: { rule_id: RuleId, sink: SinkType, severity: Severity,
               confidence: f32, evidence: Bytes, taint_path: TaintPath }

Action     :: Allow | Block | Monitor

Rule       :: { id: RuleId, sink: SinkType, kind: Signature | Semantic,
               action: Action, priority: u16 }

Policy     :: { mode: Monitor | Block, rules: Vec<Rule>,
               waivers: Vec<Waiver>, fail_mode: Open | Closed }

RaspError  :: HookAbiError | ContextMissing | TaintOverflow
            | DetectorPanic | PolicyLoadFail | TelemetryDrop

8.3 State Machine — Request Lifecycle

States: Idle → Active → Completing → Done

         request-start hook
  Idle ─────────────────────────────────────────────► Active
         (allocate RequestContext, seed taint from HTTP headers/params/body)

         sink invocation (0..N)
  Active ─────────────────────────────────────────────► Active
         (HookEvent → taint-check → detect → policy → Allow/Block)
         ↓ Block
         Active ──────────────────────────────────────► Active
                (abort op; inject safe error to app; emit AttackEvent)

         request-end hook (or thread reclamation)
  Active ─────────────────────────────────────────────► Completing
         (flush pending telemetry, reclaim TaintMap)

  Completing ──────────────────────────────────────────► Done
         (context slot released; correlation-id archived)

  Any state ──── RASP internal panic ──────────────────► Active (fail_mode)
         (host-safety invariant: catch_unwind + log; never propagate)

Invariant: RequestContext allocated exactly once per request entry; NEVER shared across concurrent requests. Context slot must be released at Done to prevent leak.

8.4 State Machine — Taint Propagation

States per TaintedValue: Clean | Tainted(tags) | Overflowed | Dropped

  Clean ──── source-tagged at HTTP ingress ────────────► Tainted(tags)
  Tainted ── string-concat / format / slice ───────────► Tainted(merged_tags)
  Tainted ── untracked op (regex-replace, etc.) ────────► Dropped (documented gap)
  Tainted ── tag-set exceeds TAINT_TAG_LIMIT ───────────► Overflowed
  Overflowed ─────────────────────────────────────────────► treat as fully-tainted (sound)
  Dropped ────────────────────────────────────────────────► treat as clean (FN risk; documented)
  • TAINT_TAG_LIMIT default: 64 tags per value; configurable, not unbounded.
  • Overflowed → conservative: assume all bytes tainted from all sources.
  • Propagation budget: max PROPAGATION_OPS (default 4096) per request; on breach → Overflowed on remaining ops.

8.6 Per-Sink Analyzer State Machines

8.6.1 SQLi Analyzer

Input: (query_string: &str, tainted_ranges: &[Range<usize>])

States:
  Tokenize → [tokens]
  Inject_Check(token_at_tainted_range) →
      Keyword-in-taint? → Detection(SqlInjection, High)
      Quote-break? → Detection(SqlInjection, High)
      No injection syntax? → Allow
  Error (tokenize fails) → Detection(Suspicious, Medium) [conservative]
  • Tokenizer: libinjection-style; pure Rust re-implementation in rasp-detect.
  • Tainted ranges mapped to token boundaries; injection flagged if tainted region contains SQL keyword or structural token (', --, ;, UNION, OR 1=1 patterns).
  • Parameterized queries (args passed as typed bind params, not string-interpolated): no taint in query string → Allow immediately.

8.6.2 Command Injection Analyzer

Input: (cmd: &OsStr | &[OsStr], tainted_ranges)

States:
  Shell-invoked (sh -c "...") → parse shell metachar in tainted range
      Metachar { |, ;, &, $(), ``, >, < } in taint → Detection(CmdInjection, Critical)
  Execve-style (argv[]) → tainted argv element is whole field
      User-controlled argv[0] → Detection(CmdInjection, Critical)
      User-controlled arg with path-sep → Detection(PathTraversal, High)
  No taint in cmd/args → Allow

8.6.3 Path Traversal Analyzer

Input: (path: &Path, tainted_ranges)

States:
  Normalize(path) → canonical
  Tainted segment contains "../" or "%2e%2e" → Detection(PathTraversal, High)
  Canonical path outside ALLOWED_ROOT_SET → Detection(PathTraversal, High)
  Symlink target outside ALLOWED_ROOT_SET → Detection(PathTraversal, Medium)
  No escape → Allow
  • ALLOWED_ROOT_SET configured in Policy; default empty = alert on any traversal attempt.

8.6.4 SSRF Analyzer

Input: (url: &str, tainted_ranges)

States:
  Parse URL → scheme + host + port
  Host in DENY_LIST (169.254.0.0/16, 10.0.0.0/8, 127.0.0.0/8, ::1, metadata endpoints) → Detection(SSRF, Critical)
  Tainted host not in ALLOW_LIST → Detection(SSRF, High)
  Tainted scheme (file://, gopher://, dict://) → Detection(SSRF, Critical)
  Parse error on tainted input → Detection(SSRF, Medium)
  Allow → proceed
  • DNS resolution NOT performed inline (overhead + TOCTOU); alert at URL-parse level.
  • ALLOW_LIST required for Block mode; Monitor mode logs all outbound to tainted hosts.

8.6.5 Deserialization Analyzer

Input: (format: SerFormat, payload: &[u8], tainted: bool)

States:
  tainted=false → Allow (payload not from HTTP input)
  format=Java|PHP|Python-pickle → Detection(DeserGadget, Critical) [always deny tainted]
  format=JSON|CBOR → structural scan: class-name fields gadget-list → Detection if found
  format=XML → delegate to XmlParse analyzer (XXE check)
  Unknown format → Detection(Suspicious, Medium)
  • Gadget list: known ysoserial chains, Commons-Collections payloads (hex/class-name signatures).
  • JSON deserialization: only flag @class, _type, __type__ with known gadget class names.

8.6.6 XXE Analyzer

Input: (xml_bytes: &[u8], tainted: bool)

States:
  tainted=false → quick DOCTYPE scan (defense-in-depth)
  DOCTYPE present + SYSTEM/PUBLIC entity → Detection(XXE, High)
  External entity ref (http://, file://, jar://) → Detection(XXE, Critical)
  Parameter entity (%name;) in tainted input → Detection(XXE, High)
  Well-formed, no external entity → Allow

8.6.7 LDAP/NoSQL Injection Analyzer

Input: (query: &str | Value, tainted_ranges)

LDAP:
  Tainted region contains metachar { (, ), *, \, NUL } → Detection(LdapInjection, High)

NoSQL (MongoDB-style):
  Tainted string contains "$" operator prefix → Detection(NoSqlInjection, High)
  Tainted value parsed as JSON object (not scalar) → Detection(NoSqlInjection, High)

8.7 TaintMap Data Model

TaintMap layout (per-request, heap-allocated, owned by RequestContext):

  key: ValueId (u64 intern handle, assigned at source-tag time)
  value: TaintedValue { value: Bytes, tags: Vec<TaintTag> }

  TaintTag: { source: TaintSource, byte_range: Range<usize>, generation: u32 }
    generation: incremented each propagation step; aids forensic taint-path reconstruction

  TaintPath (for Detection evidence):
    Vec<TaintStep { op: TaintOp, src_id: ValueId, dst_id: ValueId, generation: u32 }>
    TaintOp :: Concat | Slice | Format | HttpIngress | PropagateOpaque
  • Map cleared atomically at request-end; no cross-request sharing.
  • ValueId collision probability negligible (u64 counter per context, not global hash).
  • Memory limit: TAINT_MAP_MAX_BYTES (default 4 MiB per request); on breach → oldest entries evicted + metric fired; Detection(TaintOverflow, Low) emitted.

8.8 Policy Evaluation Model

Input:  Detection + RequestContext + Policy
Output: Action (Block | Monitor | Allow)

Evaluation order:
  1. Waiver match (exact route + rule_id + ip range) → Allow (waiver wins)
  2. Policy.mode == Monitor → Monitor (no block regardless of rule action)
  3. Rule lookup by (sink, rule_id, priority desc):
       first matching rule with action=Block → Block
       first matching rule with action=Allow → Allow
       no match → Policy.fail_mode: Closed→Block, Open→Allow
  4. Result annotated with matched rule_id + waiver_id (or "default")

State transition of a Detection through Policy:

Detection ──── waiver? ──Yes──► Allow (waiver_id tagged)
     │ No
     ▼
  mode=Monitor? ──Yes──► Monitor (emit; no block)
     │ No (Block mode)
     ▼
  rule match? ──Yes──► rule.action (Block or Allow per rule)
     │ No match
     ▼
  fail_mode: Open → Allow; Closed → Block
  • virtual_patch: a Rule with kind=Signature targeting a known CVE pattern; allows per-pattern disable without app redeploy.
  • Waiver fields: { route_pattern, rule_id, expires_at, requester, ticket_id } — all waivers are time-bounded and audited.

8.9 HookEvent Protocol / Wire Format

HookEvent (in-process; no serialization — direct struct pass across FFI boundary):

C ABI layout (for runtime-adapter FFI):
  struct RaspHookEvent {
    sink_type:   u32,         // SinkType discriminant
    context_id:  u64,         // ContextId
    phase:       u8,          // 0=Entry, 1=Exit
    _pad:        [u8; 3],
    timestamp_ns: u64,
    args_ptr:    *const u8,   // SinkArgs serialized as msgpack in adapter-allocated buffer
    args_len:    usize,
  }

SinkArgs variants (msgpack schema per SinkType):
  SqlQuery:    { query: str, params: [Value] }
  Exec:        { program: bytes, argv: [bytes], env: [(bytes,bytes)] }
  FileOpen:    { path: bytes, flags: u32 }
  HttpRequest: { method: str, url: str, headers: [(str,str)], body: bytes }
  Deserialize: { format: u8, payload: bytes }
  LdapQuery:   { filter: str, base_dn: str }
  XmlParse:    { fragment: bytes }
  • args_ptr buffer owned by the adapter; must remain valid for duration of hook call.
  • RASP never writes back through args_ptr; read-only borrow.
  • context_id resolved in rasp-context via thread-local or task-local lookup.

8.10 AttackEvent Wire Format (Telemetry / SIEM)

AttackEvent (JSON internal; CEF on emission):

{
  "event_id":    "<uuid-v7>",
  "timestamp":   "<rfc3339>",
  "context_id":  "<u64-hex>",
  "request":     { "method", "path", "remote_ip", "correlation_id" },
  "sink":        "<SinkType>",
  "rule_id":     "<str>",
  "severity":    "critical|high|medium|low|info",
  "confidence":  0.0..1.0,
  "action":      "block|monitor|allow",
  "evidence":    "<base64-truncated-512B>",
  "taint_path":  [{ "op", "src_id", "dst_id", "generation" }],
  "waiver_id":   "<str|null>",
  "overhead_ns": "<u64>"
}

CEF mapping:
  CEF:0|RASP|rasp-engine|1.0|<rule_id>|<rule_id>|<sev-int>|
    src=<remote_ip> request=<path> act=<action> cs1=<evidence-hash> cs2=<taint_path_len>
  • evidence truncated to 512 bytes before telemetry; full evidence stored in local audit ring (rasp-telemetry in-process ring buffer, 65536 entries).
  • overhead_ns = wall-clock from hook entry to policy decision (excludes telemetry emit).

8.11 Context Isolation — Concurrency Model

Thread model:
  thread_local!(static RASP_CTX: RefCell<Option<RequestContext>>)
  set on request-start hook; cleared on request-end hook.

Async model (tokio):
  task_local!(static RASP_CTX: Arc<Mutex<RequestContext>>)
  spawned task inherits parent's context_id for correlation but NOT its TaintMap.
  Child task sees its own TaintMap (child_of parent, tagged with parent_id for tracing).

Cross-task taint propagation:
  Values passed across task boundaries via channel → taint tags embedded in a
  TaintCarrier wrapper; rasp-context extracts tags on recv side.
  Values passed via Arc<T> (shared read) → tainted at read site if origin tainted.
  No automatic cross-task taint; explicit TaintCarrier required (documented gap).
  • Invariant: RequestContext.taint_map never accessible from a different request's thread.
  • Mutex in async model: uncontended fast path (single writer per request task); contention metric tracked.

8.12 Failure-Path Examples

Example A — SQLi Block Path

HTTP GET /items?id=1' OR '1'='1
  → HttpParam("id") → TaintedValue { value: "1' OR '1'='1", tags: [HttpParam, 0..15] }

App calls: db.query("SELECT * FROM items WHERE id = " + user_input)
  → rasp-hook fires: HookEvent { sink: SqlQuery, args: { query: "SELECT...1' OR '1'='1" } }
  → rasp-context: resolves ctx for this thread
  → rasp-taint: range [27..42] of query string is tainted (tag: HttpParam)
  → rasp-detect: tokenize → " OR '1'='1" contains keyword OR + quote-break → Detection(SQLi, Critical, conf=0.97)
  → rasp-policy: mode=Block, rule R-001 matches → Action::Block

8.13 Edge-Case Catalogue

Edge Case Behavior Invariant
Context missing at sink (async task with no TaintCarrier) ContextMissing → apply fail_mode host-safety
Taint tag count exceeds TAINT_TAG_LIMIT Mark Overflowed; treat as fully tainted taint soundness
Propagation op count exceeds PROPAGATION_OPS Remaining ops → Overflowed overhead budget
Regex-replace on tainted string (untracked) Taint Dropped; logged as gap documented FN
Parameterized SQL (no string interpolation) No taint in query string → Allow; no FP block determinism
Waiver expired (expires_at in past) Treat as no waiver; re-evaluate rule policy correctness
Telemetry channel full Drop event; increment rasp_telemetry_drops host-safety
Double request-start hook (bug in adapter) Second call replaces context; first context reclaimed; log warning context isolation
Block in Monitor mode Impossible by invariant (Monitor purity); if triggered → bug + panic in debug, log in release monitor purity
SinkArgs msgpack decode failure Detection(Suspicious, Medium); fall to policy host-safety
