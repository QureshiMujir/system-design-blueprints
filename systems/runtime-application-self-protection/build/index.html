Pitfalls
  1. ReDoS in lexer: naive regex-based lexer → crafted query causes exponential backtracking. Fix: hand-written DFA; no regex. Verify with regexplode or equivalent.
  2. Fingerprint false negatives via encoding: hex_encode, char() bypass structural analysis; fingerprint must include encoded-form patterns. Mitigation: pre-decode 0x... hex literals before fingerprinting.
  3. Parameterized false negative: app concatenates unsanitized input even with ? markers in other positions (mixed query). paramcheck only fires when ALL tainted bytes map to bind markers; partial match does not suppress analysis.
  4. Confidence threshold drift: setting threshold too high (0.95) → low-confidence real attacks pass in Block mode. Operator must tune; default 0.85 is calibrated on OWASP corpus. Monitor-first deployment recommended to calibrate before enabling Block.
  5. Binary column data misidentified: app stores binary (e.g., image bytes) in a column; SqlArgs::query includes that literal in the generated SQL. Lexer emits Error token; confidence < 0.3; no block. Edge: if binary data happens to contain SQL keywords — conservative but low confidence, does not block.
  6. Unicode SQL keywords (MySQL ＳＥＬＥＣＴ): full-width characters not in lexer keyword set → Ident token → missed keyword detection. Mitigation: normalize full-width ASCII before lexing; document as known gap.
  7. Comment-in-keyword obfuscation (SEL/**/ECT): lexer must recognize SEL as partial ident, not keyword — syntax diff approach catches this because redaction changes token structure. Structural analysis alone may miss; rely on multi-strategy scoring.
