Hard questions (§33)

Self-examination questions from the blueprint; each points at the section where the answer lives.

  1. Why does CRT-accelerated decryption require a mandatory re-encryption check, and what exact arithmetic relationship connects a single-bit fault in m1 to full private-key recovery? (§16, §22 T3, Boneh-DeMillo-Lipton 1997)

  3. Why is blinding necessary even though the Montgomery ladder is already constant-time over the exponent — what attack does blinding close that the ladder alone does not? (§19, §6 P5, Brumley & Boneh 2003)

  8. Why must the Manger and Bleichenbacher countermeasures produce a fixed-length, ciphertext-deterministic fake output rather than merely "an error" — what channel remains open if the fake output were randomized per call? (§18, §22 T4/T5)

  11. Why is RsaPrivateKey Clone but not Copy, and how does that interact with the zeroization invariant under Rust's move semantics? (§11, §7 I8)
  12. Why is safe-prime generation offered as a config option even though it is strictly slower and, per this design's own Threat Model, closes no attack beyond probable-prime generation with FIPS 186-5's rejection rules? (§6 P8, §15, §22)
  13. Trace a fault-injection attack from a single flipped bit in mod_exp_ct(c, dP, p) through to the point the algorithm-level defense intercepts it — name every invariant and phase subsection involved. (§16, §7 I6, §23 FM-2)
  14. Why does this design defer HSM/PKCS#11 integration rather than build it into Phase 9's public API — and what does the Alternative Architectures section say about the regime where HSM-backed signing wins outright? (§34, §35, §21)

30. Mental Models & First Principles

MM1 — A private exponent is a secret schedule, not a secret number. The ladder consumes d's bits one at a time; the sequence of operations, not merely the stored value, is what a side channel observes. Predicts: any implementation that branches on individual bits of d leaks it bit-by-bit even if d is never printed or logged. Bug class without it: "I never log the key, so I'm safe" — misses that the exponentiation's own control flow is the leak. Applies in §14 (the ladder), §7 I5.

MM2 — Padding is the security proof's hypothesis, not decoration. OAEP/PSS's security proofs (Bellare-Rogaway 1996; the OAEP IND-CCA2 reduction, Katz & Lindell) assume the exact byte layout; moving one byte invalidates the proof even if the scheme "still round-trips" in functional tests. Predicts: a padding variant can pass every round-trip test yet be completely broken (Manger, Bleichenbacher). Bug class without it: treating padding as a serialization format rather than the mechanism that makes RSA IND-CCA2-secure. Applies in §17, §18, §8.3.

MM3 — CRT trades an arithmetic invariant for a fault-injection surface. Splitting a computation across p and q creates exactly one recombination point where corrupting either half alone produces a consistent-looking but wrong result — unlike a random error in the non-CRT path, which just produces obviously wrong output. Predicts: any optimization that "splits work" across independently-computed halves is exactly where to look for new fault-injection surfaces. Applies in §16, §22 T3, Boneh-DeMillo-Lipton (1997).

MM4 — A constant-time function is a claim about a sampled input distribution, not a universal property. dudect only tests the distributions fed to it; a function constant-time over "random exponent vs. random exponent" may still leak on an edge case (all-zero, all-ones, exactly n−1) never sampled. Predicts: constant-time bugs cluster at the boundaries of the value space. Applies in §14, §19's fixture design (§19.4/§19.8).

MM5 — An oracle doesn't need to say "yes" to leak — silence and timing are also outputs. Bleichenbacher/Manger show that any observable difference in an otherwise-silent failure path (timing, error type, downstream connection behavior) is itself the oracle. Predicts: "we don't return the padding error to the caller" is insufficient if the caller's own behavior still differs by branch. Applies in §18, §22 T4/T5.

MM6 — Key generation is a rejection sampler, not a formula. RSA keygen is "generate candidate, test, reject, repeat" — its running time is a random variable, and its rare rejection events (Fermat-close primes, Wiener-small d) are the security boundary, not an afterthought. Predicts: any keygen "simplification" that skips a rejection check silently narrows the guaranteed security margin. Applies in §15, §32 #7.

MM7 — Zeroize is a race against the optimizer, not just against the OS. A compiler may legally elide a memory write it can prove is dead; clearing a secret buffer requires either a volatile write or a crate (zeroize) that defeats dead-store elimination — "I overwrote it in source" is not the same claim as "it is cleared in the compiled binary." Applies in §11, §7 I8, §23 FM-9.

MM8 — Multi-prime and CRT are the same idea at different arity, but the fault surface grows with arity. Two-prime CRT has one recombination point; k-prime multi-prime RSA (RFC 8017 App. A.1.4) has k−1 recombination points, each an independent fault-injection surface — exactly why this project defers multi-prime (§35) despite its throughput appeal. Applies in §16, §34, §35.

Required reading (§5)

Books

  • Menezes, van Oorschot, Vanstone — Handbook of Applied Cryptography (CRC Press, 1996), Ch. 8 (Public-Key Encryption), Ch. 11 (Digital Signatures) — extract: RSA primitive definitions, security notions, key-generation constraints. Applied in §8, §15, §16.
  • Katz & Lindell — Introduction to Modern Cryptography, 3rd ed. (CRC Press, 2020), Ch. 12 (Number Theory), Ch. 13 (RSA) — extract: the RSA assumption, formal IND-CCA2 reasoning for OAEP. Applied in §8, §18.
  • Boneh & Shoup — A Graduate Course in Applied Cryptography (2023, free online), Ch. 10 & 13 — extract: padding-scheme security proofs, PSS existential unforgeability. Applied in §17.
  • Knuth — The Art of Computer Programming, Vol. 2: Seminumerical Algorithms, 3rd ed., Ch. 4.3 (Multiple-Precision Arithmetic), Ch. 4.5 (Rational Arithmetic / GCD) — extract: schoolbook multiplication, long division, extended-Euclid. Applied in §13, §14.
  • Cohen — A Course in Computational Algebraic Number Theory (Springer GTM 138), Ch. 1 (fast arithmetic), Ch. 8 (primality testing) — extract: Miller-Rabin and Lucas test implementation detail. Applied in §15.
  • Ferguson, Schneier, Kohno — Cryptography Engineering (Wiley, 2010), Ch. 4 (hash functions), Ch. 12 (implementation pitfalls) — extract: why "textbook RSA" fails, side-channel implementation discipline. Applied in §16, §19.
  • Aumasson — Serious Cryptography, 2nd ed. (No Starch Press, 2024), Ch. 9 (RSA) — extract: practitioner pitfalls, key-size guidance. Applied in §4, §15.

Papers

  • Rivest, Shamir, Adleman (1978) — A Method for Obtaining Digital Signatures and Public-Key Cryptosystems, CACM 21(2) — the foundational construction. Applied in §8, §16.
  • Bleichenbacher (1998) — Chosen Ciphertext Attacks Against Protocols Based on the RSA Encryption Standard PKCS #1, CRYPTO 1998 — the padding-oracle attack. Applied in §18, §22.
  • Manger (2001) — A Chosen Ciphertext Attack on RSA Optimal Asymmetric Encryption Padding (OAEP) as Standardized in PKCS #1 v2.0, CRYPTO 2001 — the OAEP oracle attack. Applied in §18, §22.
  • Boneh, DeMillo, Lipton (1997) — On the Importance of Checking Cryptographic Protocols for Faults, EUROCRYPT 1997 — the CRT fault-injection attack. Applied in §16, §22.
  • Bellare & Rogaway (1996) — The Exact Security of Digital Signatures: How to Sign with RSA and Rabin, EUROCRYPT 1996 — the PSS construction and its proof. Applied in §17.
  • Kocher (1996) — Timing Attacks on Implementations of Diffie-Hellman, RSA, DSS, and Other Systems, CRYPTO 1996 — the first practical timing attack. Applied in §14, §19, §22.
  • Brumley & Boneh (2003) — Remote Timing Attacks are Practical, USENIX Security 2003 — the OpenSSL RSA timing attack over a network. Applied in §19, §22.
  • Coppersmith (1997) — Small Solutions to Polynomial Equations, and Low Exponent RSA Vulnerabilities, J. Cryptology 10(4) — lattice attacks on small-exponent/partial-key RSA. Applied in §15, §22.
  • Boneh (1999) — Twenty Years of Attacks on the RSA Cryptosystem, AMS Notices 46(2) — the attack survey. Applied in §8, §22, §34.
  • Heninger, Durumeric, Wustrow, Halderman (2012) — Mining Your Ps and Qs: Detection of Widespread Weak Keys in Network Devices, USENIX Security 2012 — shared-prime disasters from weak RNGs. Applied in §15, §22.

Reference Implementations

  • OpenSSL crypto/rsa/ + crypto/bn/ — the canonical C reference; study the primitive split (rsa_ossl.c) and the bignum montgomery path (bn_mont.c). Pitfall: do not copy its historical non-constant-time division fallback. Applied in §13, §16.
  • BoringSSL crypto/fipsmodule/rsa/ + crypto/fipsmodule/bn/montgomery.c — the constant-time-hardened fork; study its blinding call sites. Applied in §14, §19.
  • RustCrypto rsa (github.com/RustCrypto/RSA) — a safe-Rust reference; study its key types and encoding module layout as a reference, not a copy source. Applied in §16, §17, §18.
  • GNU GMP mpn layer — the fastest reference bignum kernel; study its Montgomery reduction for the algorithmic shape (not the assembly). Applied in §13.
  • mbedTLS library/rsa.c + library/bignum.c — the embedded/constrained-target reference; study its blinding and OAEP decode paths. Applied in §18.
  • Project Wycheproof (github.com/google/wycheproof) testvectors/rsa_*.json — the negative-test corpus that catches lazy verifiers. Applied in §21, every phase's N.5.

Glossary (§36) · 42 terms · site-wide glossary

ACVP
Automated Cryptographic Validation Protocol; NIST's automated successor to CAVP.
Barrett reduction
a modular-reduction technique using a precomputed reciprocal; rejected here in favor of Montgomery reduction (ADR-04) for the repeated-modulus RSA hot path.
Bleichenbacher attack
the 1998 chosen-ciphertext attack against PKCS#1 v1.5 decryption oracles; closed here by I10.
Blinding
randomizing a private-key operation's input with a fresh factor r to remove correlation between secret-dependent timing and the operation's true input; mandatory here (I7).
CAVP
Cryptographic Algorithm Validation Program; NIST's test-vector validation suite.
Carmichael function λ(n)
the smallest exponent m such that a^m ≡ 1 (mod n) for all a coprime to n; used in place of Euler's totient for the tighter FIPS-186-5-mandated d.
Chinese Remainder Theorem (CRT)
the number-theoretic result allowing computation mod p and mod q independently, then recombination mod n = p·q; the basis of §16's speedup.
Ciphertext
the encrypted representative c, always < n (I14).
Constant-time
an implementation property where timing/memory-access pattern is independent of secret data (I5, I9, I10); verified statistically via dudect.
Coppersmith's attack
lattice-based attacks recovering RSA parameters from partial information or exploiting small exponents; motivates ADR-08 and I3/I4.
CRT parameters (dP, dQ, qInv)
the precomputed values enabling CRT-accelerated private-key operations (§8.2, §11).
Decoy
the fixed-length, ciphertext-deterministic fake plaintext returned on decode failure (I9, I10), indistinguishable from a real result to the caller.
DER
Distinguished Encoding Rules; the canonical binary form of ASN.1, used by PKCS#1/8.
dudect
a statistical framework for detecting timing side channels via Welch's t-test.
EME (Encoding Method for Encryption)
RFC 8017's term for an encryption padding scheme (OAEP, PKCS1-v1.5).
EMSA (Encoding Method for Signatures with Appendix)
RFC 8017's term for a signature padding scheme (PSS, PKCS1-v1.5).
Euler's totient φ(n)
count of integers below n coprime to n; φ(n) = (p−1)(q−1) for RSA moduli.
Fault-injection attack
deliberately corrupting a computation (voltage glitch, etc.) to extract secret information from the faulty output; closed for CRT decryption by I6.
Fermat factoring
factoring n by searching near √n when p and q are close; closed by I4.
F4 (65537)
the fixed public exponent this project uses for keygen (ADR-08, P9).
I2OSP / OS2IP
Integer-to-Octet-String / Octet-String-to-Integer primitives (RFC 8017 §4), the byte↔integer boundary between wire formats and BigUint.
IND-CCA2
indistinguishability under adaptive chosen-ciphertext attack; the security notion OAEP is designed to satisfy.
JWK (JSON Web Key)
RFC 7517's JSON key-interchange format.
Lucas test
a probabilistic primality test complementary to Miller-Rabin, guarding specifically against certain adversarial pseudoprimes (P8, §15).
Manger attack
the 2001 chosen-ciphertext attack against OAEP decryption oracles; closed here by I9.
MGF1
Mask Generation Function 1 (RFC 8017 Appendix B.2.1); the shared hash-based masking primitive underlying both OAEP and PSS.
Miller-Rabin test
the probabilistic primality test used in key generation, iterated per FIPS 186-5 Table A.1 (P7, I12).
Modulus (n)
the product of two (or, deferred, more) primes; the public part of an RSA key together with e.
Montgomery multiplication
a division-free modular-multiplication algorithm operating in a transformed representation (aR mod n); the basis of mod_exp_ct/mod_exp_pub (§14).
OAEP (Optimal Asymmetric Encryption Padding)
the RSA encryption padding scheme this project defaults to (ADR-11), providing IND-CCA2 security under the RSA assumption.
Padding oracle
any observable channel (error type, timing) that reveals whether a decryption's padding was valid, enabling chosen-ciphertext attacks (Bleichenbacher, Manger).
PEM
Privacy-Enhanced Mail textual (base64) encoding of DER data (RFC 7468).
PKCS#1
RFC 8017, the primary RSA specification this project implements; also the name of its raw-key DER encoding (§20).
PKCS#8
RFC 5958's generic private-key DER container, wrapping PKCS#1 with an algorithm identifier.
PSS (Probabilistic Signature Scheme)
the RSA signature padding scheme this project defaults to (ADR-10), with a provable existential-unforgeability reduction (Bellare-Rogaway 1996).
RSAEP / RSADP / RSASP1 / RSAVP1
RFC 8017's four primitive operations: encrypt, decrypt, sign, verify (§16).
Safe prime
a prime p such that (p−1)/2 is also prime; an optional, slower keygen mode (P8) offered for compliance regimes.
Salt (PSS)
the random value included in PSS's hashed pre-image, giving the scheme its probabilistic (non-deterministic) signatures (§17, Hard Question 17).
Timing attack
recovering secret information by measuring operation latency; the class Kocher (1996) and Brumley-Boneh (2003) demonstrate against naive RSA implementations.
Wiener's attack
a continued-fraction attack recovering d when it is too small relative to n; closed by I3.
Wycheproof
Google's project providing a large corpus of cryptographic test vectors, including deliberately malformed/adversarial cases, used throughout this project's conformance suite (§26).
Zeroize
overwriting secret memory on drop in a way that survives compiler dead-store elimination (MM7, I8, ADR-22). ---
